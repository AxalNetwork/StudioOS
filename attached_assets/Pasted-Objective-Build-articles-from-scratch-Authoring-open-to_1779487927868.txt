Objective
  Build /articles from scratch. Authoring open to founders,
  investors, mentors, coaches, and partners with sufficient trust
  score. Submissions go through admin approval. Approved articles
  publish to /articles, filterable by sector + author role.
  Articles appear on the author's public profile under an
  "Articles" tab.

Schema (new)
  cloudflare-worker/sql/migrations/00xx_articles.sql:

    CREATE TABLE articles (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      slug TEXT UNIQUE NOT NULL,
      author_user_id INTEGER NOT NULL,
      author_role TEXT NOT NULL,         -- 'founder','investor',
                                         -- 'mentor','coach','partner','admin'
      title TEXT NOT NULL,
      subtitle TEXT,
      category TEXT NOT NULL,            -- sector taxonomy
      sub_category TEXT,
      tags_json TEXT,
      body_markdown TEXT NOT NULL,
      body_html_cached TEXT,
      cover_image_r2_key TEXT,
      excerpt TEXT,
      reading_minutes INTEGER,
      status TEXT NOT NULL,              -- 'draft','submitted',
                                         -- 'in_review','changes_requested',
                                         -- 'approved','published',
                                         -- 'rejected','retracted','unpublished'
      submitted_at DATETIME,
      reviewed_at DATETIME,
      reviewed_by_admin_id INTEGER,
      published_at DATETIME,
      rejection_reason TEXT,
      view_count INTEGER DEFAULT 0,
      version INTEGER DEFAULT 1
    );
    CREATE INDEX idx_articles_status_published ON articles(status, published_at DESC);
    CREATE INDEX idx_articles_author ON articles(author_user_id, status);
    CREATE INDEX idx_articles_category ON articles(category, status);

    CREATE TABLE article_revisions (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      article_id INTEGER NOT NULL,
      version INTEGER NOT NULL,
      body_markdown TEXT NOT NULL,
      title TEXT NOT NULL,
      snapshot_at DATETIME DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE article_review_comments (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      article_id INTEGER NOT NULL,
      admin_id INTEGER NOT NULL,
      body TEXT NOT NULL,
      inline_anchor TEXT,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
    );

Trust gate (server-side)
  An author may create + submit if any of:
    users.role = 'admin'
    OR users.role IN ('founder','investor','mentor','coach','partner')
       AND users.trust_score >= 60
       AND users.email_verified = 1
       AND users.account_age_days >= 14
       AND NOT users.abuse_flagged
  trust_score is computed by the existing trust service if present;
  else derive at read time per the rules in earlier prompt LE.

Notifications
  Each state transition fires a notification (email + in-app) via
  cloudflare-worker/src/services/notifications/send.ts:
    submitted              → author + all admins
    in_review              → author
    changes_requested      → author, with admin's notes
    approved               → author
    published              → author
    rejected               → author, with reason
    unpublished            → author
  Iteration loop: when status='changes_requested', the author can
  edit + re-submit, which transitions back to 'submitted'.
  article_revisions row inserted on every submit.

    /api/articles/by-author/:user_id. Empty state honest:
    "No published articles yet."

Anti-abuse
  - Trust gate enforced server-side; never trust the client.
  - Rate limit: 3 submissions / week / author.
  - Submissions auto-scanned by the existing PII redact checker;
    block submit if private data of OTHER users is detected.
  - On publish, cache the rendered article through Cloudflare
    Cache API for 60-day TTL.
  - Markdown rendered through the existing sanitiser (no inline
    HTML, no scripts, no data: URLs).

Acceptance
  - Authorised user creates draft + submits.
  - Admin sees it in the queue, can leave inline comments, request
    changes, or approve + publish.
  - Author gets notification at every state transition.
  - Published article visible at /articles and on the author's
    profile Articles tab.
  - Front page surfaces the latest 3.
  - Category filters work.
  - Rejection lets the author iterate without losing prior content.
  - Drift smoke test (api.js ↔ worker) still passes.
