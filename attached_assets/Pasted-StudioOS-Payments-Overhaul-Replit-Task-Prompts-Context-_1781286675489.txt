StudioOS Payments Overhaul — Replit Task Prompts
Context
You want every paid action in StudioOS — subscriptions, incorporation, compliance fees, mentorship/coaching, à la carte feature unlocks — to run through a single Axal-branded payment terminal. Stripe stays as the processor, but no user ever sees checkout.stripe.com or the Stripe Customer Portal. Add a unified Settings → Billing dashboard, a universal referral system that pays commission on any sold SKU, an admin promo-code panel, and Axal-branded invoice emails.
Today the repo already has Stripe wired deeply (3 subscription tiers, Connect payouts for expert bookings + refer-earn, webhooks, Gmail email service). What's missing is: (a) embedded card UI, (b) a generalized product catalog, (c) checkout for incorporation / sessions / à la carte, (d) a generic promo code system, (e) referral attribution that works across all products, and (f) branded invoice delivery. This plan is a sequence of Replit task prompts that build this incrementally on top of the existing infrastructure.
Architectural decisions to lock in up-front
1. Card capture → Stripe Elements + PaymentIntents. Keeps PCI at SAQ A (Stripe.js iframes inputs) and gives full Axal-branded UI. Not embedded Checkout (Stripe branding leaks).
2. Promo codes → native Stripe Coupons + Promotion Codes, mirrored in D1 for admin lookup. Survives proration, refunds, multi-currency.
3. Catalog → Stripe Products + Prices is source of truth, D1 caches. Replaces today's hardcoded STRIPE_PRICE_* env vars in billing.ts.
4. Customer Portal → internal /settings/billing that calls Stripe REST from the Worker. Secret key never reaches the SPA.
5. Referral attribution → metadata.referral_code on every PaymentIntent, plus a D1 attribution table with 30-day window. Connect destination charges keep Axal as merchant of record.
6. Invoicing → Stripe generates the PDF, we re-send via existing Gmail service with Axal HTML wrapper. Disable Stripe's customer emails.
Cross-cutting risks / gotchas
* PCI: Elements only; never log raw PANs; CSP whitelists js.stripe.com + *.stripe.network.
* 3DS / SCA: PaymentIntent confirmation must handle requires_action via stripe.confirmCardPayment().
* Webhook idempotency: every new event handler inserts into a webhook_events(stripe_event_id PRIMARY KEY) ledger before processing. Reuse the existing entrypoint at cloudflare-worker/src/routes/billing.ts /stripe/webhook.
* Taxes/VAT: enable Stripe Tax (automatic_tax: { enabled: true }) on every PaymentIntent + Subscription.
* Refund policy: incorporation = no refund after filing; sessions = 24h cancel window; subs = prorated. Encoded in admin refund tool.
* Connect payouts: referral commissions and expert payouts must use separate transfers post-charge (not transfer_data at charge time) to allow clawback on refund.
Reuse map
* stripeCall<T>() in cloudflare-worker/src/routes/billing.ts — idempotency-keyed Stripe REST wrapper, use everywhere.
* cloudflare-worker/src/services/email.ts — Gmail OAuth2 sender for invoice emails (reuse buildEmailHTML() pattern).
* cloudflare-worker/src/services/referralPayouts.ts — Connect transfer mechanics.
* cloudflare-worker/src/routes/admin_billing.ts — TOTP step-up + audit pattern for admin promo/refund endpoints.
* cloudflare-worker/src/services/wellbeing/bookings.ts — booking + Connect destination charge reference.
* Settings → Billing tab scaffolding already exists in frontend/src/pages/SettingsPage.jsx (FounderBillingPanel, InvestorBillingPanel).
* Admin tab pattern in frontend/src/pages/AdminPage.jsx — add Promo Codes alongside existing 9 tabs.
