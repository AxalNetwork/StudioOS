Google Calendar OAuth fix
  Likely cause of the current failure (verify in Worker logs):
    a. redirect_uri sent at /authorize doesn't match the registered
       URI exactly (trailing slash, http vs https, subdomain drift).
    b. The state parameter isn't being verified server-side so
       Google falls back to an error path.
    c. The token endpoint POST is sending Content-Type:
       application/json instead of application/x-www-form-urlencoded.

  cloudflare-worker/src/routes/calendar.ts:
    GET /google/start
      → builds authorize URL with:
         response_type=code
         client_id=env.GOOGLE_CLIENT_ID
         redirect_uri=https://axal.vc/api/calendar/google/callback
         scope=https://www.googleapis.com/auth/calendar.events
               https://www.googleapis.com/auth/calendar.readonly
               openid email profile
         access_type=offline   prompt=consent
         state=<HMAC(user_id, nonce, env.JWT_SECRET)>
      → returns { redirect_url }
    GET /google/callback?code=&state=
      → verify state HMAC; exchange code at
         POST https://oauth2.googleapis.com/token
         body: application/x-www-form-urlencoded
         { code, client_id, client_secret, redirect_uri, grant_type:
           'authorization_code' }
      → persist refresh_token (encrypted), access_token, expires_at,
         scope, remote_account_id into calendar_google_tokens.
      → 302 redirect back to /calendar?connected=google

  Token refresh: separate helper that runs on every calendar read
  request, refreshing 5 minutes before expiry.

Outlook / Microsoft 365 OAuth (new)
  cloudflare-worker/src/routes/calendar.ts:
    GET /outlook/start
      → https://login.microsoftonline.com/common/oauth2/v2.0/authorize
         client_id=env.MS_CLIENT_ID
         response_type=code
         redirect_uri=https://axal.vc/api/calendar/outlook/callback
         response_mode=query
         scope=offline_access Calendars.ReadWrite User.Read
         state=<HMAC>
    GET /outlook/callback
      → exchange at
         POST https://login.microsoftonline.com/common/oauth2/v2.0/token
         body application/x-www-form-urlencoded
         { client_id, scope, code, redirect_uri,
           grant_type: 'authorization_code',
           client_secret: env.MS_CLIENT_SECRET }
      → persist into calendar_outlook_tokens (same shape as Google).

  Microsoft Graph wrapper:
    cloudflare-worker/src/services/calendar/outlook.ts
      listEvents(user, range)
      createEvent(user, event)
      deleteEvent(user, event_id)
