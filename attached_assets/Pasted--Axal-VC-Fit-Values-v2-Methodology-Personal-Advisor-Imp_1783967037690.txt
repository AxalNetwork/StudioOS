# Axal VC Fit & Values v2 — Methodology + Personal Advisor Implementation Plan

## Context

Axal VC wants a decision-grade "Fit & Values" assessment inside the Personal Advisor — a three-layer model (Values = what someone optimizes for; Archetypes = how they operate; Skills = what they can reliably execute), kept separate in measurement and combined in a weighted 6-outcome decision rubric, with behavioral evidence and validation rather than self-report alone. Uses: founder evaluation, operator/advisor matching, team design, hiring, portfolio support, culture alignment. Priority: structure-first (schema → routes → question model → scoring interfaces → screens → MVP bank → results), calibration tooling later.

**Critical discovery**: StudioOS already ships **Axal Fit v1** end-to-end — spec `attached_assets/axal_fit_methodology.md`; engine `cloudflare-worker/src/services/axalFit.ts` (5 Axal values, 4 per-persona rubrics, bands ≥85/≥70/≥55, 7 red flags, deterministic); fit banks (`fit.<persona>.<key>` IDs, 0–5 scale) delivered one-per-turn by the Personal Advisor chat (`components/advisor/PersonalAdvisor.jsx`, embedded in Dashboard/Exploring/Advisory pages); writeRouter fan-out to `axal_values`/`user_skills`/`user_values`; results in `ProfileFitSection.jsx` + admin Best-Fit Console. **So this build is Fit v2: an additive, versioned upgrade — not a parallel system, and nothing v1 stores or serves may break.**

## Decisions made (flag at review if you disagree — each is a one-constant change)

1. **6th value = `ambition`** ("Compounding Ambition"). v1's five (integrity, stewardship, curiosity, resilience, collaboration) stay untouched; `ownership` was rejected because v1 `integrity` already covers owning outcomes/blame-shifting. Verified zero-DDL: `axal_values.value_key` has no CHECK constraint; v1 `AXAL_VALUES` const + its test stay at 5, v2 owns `FIT_V2_VALUES = [...AXAL_VALUES, 'ambition']`.
2. **Dual-mode delivery from day one**: new staged `/fit` assessment flow AND the conversational advisor both serve v2 core items through the same write pipeline. Conversational adds ~30 `importance:'low'` items per persona (they trail all onboarding questions; progress-ring denominators bounded by profiling module floors). Alternative (staged-only first) noted in PR description.
3. Defaults: route `/fit`; roles include `exploring`; full ~95-item bank authored in this PR with `mvp_core` flags (your spec explicitly requires both full + MVP banks); single PR on `claude/axal-vc-fit-methodology-r63hu2`; no FastAPI mirror (advisor is worker-only by design).

## Methodology v2 (authored into `design/AXAL_VC_FIT_V2_METHODOLOGY.md`)

### Layer 1 — Values (6 = 5 v1 + ambition): what they optimize for
integrity · stewardship · curiosity · resilience · collaboration · **ambition** (plays long games at high standards; durable advantage over quick optics). Each: definition, 4–5 items (likert + forced-choice + tradeoff + 1 behavioral-evidence), behavioral indicators, positive/negative signals, per-context manifestations (founder/investor/operator/advisor/team). Red-flag probes keep v1 keys/thresholds (`at_or_below: 1`).

### Layer 2 — Archetypes (6 = 4 v1 traits + scout + steward): how they operate
builder · visionary · connector · operator · **scout** (finds signal early, cross-domain synthesis; risk: novelty-chasing) · **steward** (protects quality/trust/downside; risk: veto energy). Scored as preference (no "good" answers), forced-choice/SJT items, nearest-centroid over 6-dim trait space → primary + secondary + margin. v1 4-trait classifier untouched (`archetypeScoring.ts` filters to its own trait list — verified).

### Layer 3 — Skills (10 priority skills): what they can execute
fundraising & capital narrative, market research, analytical judgment, product thinking, sales & relationship building, hiring, execution management, communication, diligence, strategic synthesis. Seeded as `fitv2_*` rows in the existing `skills` catalog (display_order 901+ so v1 `resolveCategorySkillId` mappings are untouched), mapped to the 8 radar axes as domains. Two tracks per skill: claimed proficiency (likert + recency) and evidence strength (SJT/evidence probe); capability capped at "unvalidated" band without evidence.

### Scoring (pure, deterministic, no LLM — v1 principles preserved)
- **Culture score** (0–100): 100 − weighted L1 distance of the 6-value vector from `AXAL_VALUES_BASELINE` (integrity/stewardship double-weighted).
- **Role score** (0–100): 0.6·Σw·skill/5 + 0.4·Σw·rubric/5, normalized over *answered* weights (v1 `scoreRubric` pattern) per role template.
- **Confidence** (0–1): coverage (0.4 values + 0.3 skills + 0.2 archetypes + 0.1 validation) × consistency (1 − 1.5·contradictions/pairs, floor 0) × evidence factor (0.4 + 0.6·evidence quality — self-report-only can't exceed the cap).
- **Contradictions**: 16 validation items form reverse-keyed pairs (`validation_pair`); fire at |a − (5−b)| ≥ 2; reduce confidence, surface in review.
- **Red flags**: v1 7 keys reused; option-level `flag` on SJT choices; caps below.
- Role Fit and Culture Fit always reported separately; missing-data gates per layer.

### Decision rubric (6 outcomes, thresholds in one exported `FIT_V2_THRESHOLDS` const)
| Outcome | Criteria (ordered gates) |
|---|---|
| insufficient_evidence | confidence < 0.35 OR values coverage < 3/6 OR skills coverage < 0.4 (runs first) |
| misaligned | culture < 40 OR ethics-class flag (weak_ethics / integrity contradiction) |
| (caps) | 1 non-ethics flag → best = conditional_fit; ≥2 flags → best = low_fit |
| high_fit | culture ≥ 75 ∧ role ≥ 75 ∧ confidence ≥ 0.6 ∧ 0 contradictions |
| specialist_fit | role ≥ 75 ∧ 40 ≤ culture < 60, OR top-2 weighted skills ≥ 4.5 with breadth < 2.5 ∧ culture ≥ 60 |
| conditional_fit | culture ≥ 60 ∧ role ≥ 55 (gaps enumerated), or high_fit-but-confidence < 0.6 |
| low_fit | everything else |

Each outcome carries definition, evidence conditions, strengths/risks, next action, recommended environment, what-to-validate-next (authored in doc + served in results payload). Reviewer override always possible, recorded with reason.

### Question bank (~95 + context/role add-ons; `mvp_core` subset ~50)
30 values (5×6) · 24 archetypes (4×6) · 24 skills (2–3×10) · 16 validation (pairs, social-desirability catches, confidence checks) · ~3 context · ~8 role add-ons per role. Kinds: likert, forced_choice, sjt, tradeoff, rank_order, multi_select, behavioral_evidence, confidence_check. Every item: id, module, stage, kind, ui hint, options with per-option dimension loads, signal notes (strong/weak/contradiction) for reviewers, follow-up prompts, chat-degrade `input_kind`. Six role templates: founder, investor, operator (→`partner` id prefix), advisor, internal_hire, portfolio_talent (last two staged-only, not in conversational `bankFor`).
