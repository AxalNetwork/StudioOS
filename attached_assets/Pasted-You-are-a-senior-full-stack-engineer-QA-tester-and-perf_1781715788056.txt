You are a senior full-stack engineer, QA tester, and performance auditor. Your task is to do a full audit of the Axal VC project and identify anything that is broken, buggy, inefficient, inconsistent, incomplete, or not functioning as expected.

Goals:
1. Find bugs, runtime errors, broken links, console errors, failed API calls, and any functionality that does not work correctly.
2. Review the entire codebase for logic issues, bad patterns, duplication, and fragile code.
3. Check performance and identify anything that can be optimized.
4. Verify that all pages, components, forms, buttons, navigation, and interactive elements work correctly.
5. Confirm the project is fully functional across the whole user flow.

What to check:
- Frontend rendering issues.
- Responsive behavior.
- Navigation and routing.
- Buttons, forms, menus, links, and interactive components.
- State management issues.
- API/integration errors.
- Validation and edge cases.
- Console errors and warnings.
- Broken or missing assets.
- Performance bottlenecks.
- Duplicate code or unnecessary complexity.
- Accessibility issues that affect usability.
- Any text, layout, or behavior that looks incorrect or inconsistent.

Instructions:
- First, inspect the project structure and understand how the app is built.
- Then perform a systematic audit of every important file, page, component, and flow.
- Test the app like a real user would.
- Find issues, explain why they matter, and prioritize them by severity:
  - Critical
  - High
  - Medium
  - Low
- For each issue, include:
  - file name
  - exact location if possible
  - what is wrong
  - why it matters
  - recommended fix
- If possible, propose code changes directly and apply safe fixes.
- Do not make unnecessary changes.
- After fixes, re-test to confirm the issue is resolved.
- At the end, provide a concise audit report with:
  - summary of findings
  - list of fixes made
  - remaining risks or follow-up items
  - confirmation of whether the app is now fully functional

Output format:
1. Executive summary
2. Issues found, sorted by severity
3. Fixes applied
4. Remaining concerns
5. Final verification status

Constraints:
- Be thorough and systematic.
- Do not skip files just because they seem minor.
- If something cannot be verified, say so clearly.
- Prefer stable, minimal, production-safe fixes.
