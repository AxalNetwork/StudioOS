Part 1 — Data model for templates

Create `src/templates.ts` with:

```ts
export type Audience =
  | 'customer'
  | 'investor'
  | 'partner'
  | 'advisor'
  | 'mentor'
  | 'cofounder';

export type AssetType =
  | 'landing'
  | 'deck'
  | 'memo'
  | 'doc'
  | 'email_plus_landing';

export interface TemplateConfig {
  id: string;              // machine id, e.g. "capital-ready-kit"
  label: string;           // human label, e.g. "Capital Ready Kit"
  audience: Audience;      // who this template is primarily for
  assetType: AssetType;    // landing vs deck vs memo vs doc etc.
  primaryGoal: string;     // normalized goal, e.g. "request_intro", "start_pilot", "join_waitlist"
  defaultCtaLabel: string; // e.g. "Request intro", "Start pilot"
  defaultSlug: string;     // e.g. "capital-story"
  recommended?: boolean;   // whether we show this as a recommended template for that audience
  notes?: string;          // free-form notes about usage
}
```

Then export an array:

```ts
export const TEMPLATES: TemplateConfig[] = [ /* fill in */ ];
```

Part 2 — Representing the 4-step Brand Kit & Landing flow

Create `src/flow.ts` that encodes the wizard steps and how they use the template mapping.

We already have a separate `Project` model in the main app; here, just model the shape we need:

```ts
export interface ProjectSummary {
  id: string;
  name: string;
  sector: string;
  oneLiner: string;
  // any other fields we need to seed copy, e.g. problem/solution/whyNow if useful
}

export type PageGoal =
  | 'join_waitlist'
  | 'request_intro'
  | 'start_pilot'
  | 'book_call'
  | 'apply'
  | 'offer_guidance';
```

Define a minimal representation of state for the wizard:

```ts
export interface BrandKitState {
  step: 1 | 2 | 3 | 4;

  // Step 1
  projectId?: string;
  audience?: Audience;
  goal?: PageGoal;

  // Step 2
  selectedTemplateId?: string;

  // Step 3
  // these are the fields the UI will bind to:
  brandName?: string;
  headline?: string;
  subheadline?: string;
  primaryColor?: string;
  accentColor?: string;
  typography?: string;
  ctaLabel?: string;

  // Step 4
  publicUrl?: string;
  privatePreviewUrl?: string;
}
```

Implement pure helper functions for each step (no I/O, no network):

```ts
// Step 1 — given a project and (optionally) a preferred audience,
// propose a default goal.
export function suggestAudienceAndGoal(
  project: ProjectSummary,
  preferredAudience?: Audience
): { audience: Audience; goal: PageGoal };

// Step 2 — given an audience, recommend templates sorted by relevance.
export function getRecommendedTemplatesForAudience(
  audience: Audience
): TemplateConfig[];

// Step 3 — given project, template, and current state,
// generate initial suggestions for brand/copy fields.
export function generateInitialBrandKit(
  project: ProjectSummary,
  template: TemplateConfig,
  goal: PageGoal
): Pick<
  BrandKitState,
  'brandName' | 'headline' | 'subheadline' | 'ctaLabel'
>;
```

For `generateInitialBrandKit`, you can stub simple rules like:

- brandName := project.name
- headline := templated string using project.oneLiner and audience/goal
- subheadline := “{problem/solution style text}” for now
- ctaLabel := template.defaultCtaLabel

I’ll later replace the internals with calls to my own AI/copy layer — I mostly need the wiring and placeholders.

In comments, document the 4-step flow:

```ts
/**
 * Brand Kit & Landing — 4-step flow
 *
 * Step 1 — Pick project & audience
 *   - User selects a ProjectSummary (we already know startup details).
 *   - We use suggestAudienceAndGoal(...) to prefill audience + goal.
 *
 * Step 2 — Pick a template
 *   - We show getRecommendedTemplatesForAudience(audience).
 *   - When user selects one, we store selectedTemplateId.
 *
 * Step 3 — Tune your landing page
 *   - We call generateInitialBrandKit(project, template, goal)
 *     to seed brandName, headline, subheadline, ctaLabel, and
 *     we’ll also hook in color/typography suggestions from elsewhere.
 *   - User edits these fields; we keep them in BrandKitState.
 *
 * Step 4 — Share your page
 *   - The main app will publish the landing page using BrandKitState
 *     and the chosen template, then fill publicUrl + privatePreviewUrl.
 *   - This library doesn’t call any APIs; it just provides structure.
 */
```
