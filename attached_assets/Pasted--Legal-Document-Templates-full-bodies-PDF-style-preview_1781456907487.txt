# Legal Document Templates — full bodies, PDF-style preview, PDF export

## Context

The Admin → Contracts → Templates surface (`AdminTemplates.jsx`) lets admins
edit ~84 legal templates stored in D1 (`legal_templates`). 21 of them are
either empty `v1` placeholders or `v1 · stub` catalog entries with no body.
Two adjacent quality problems compound this:

1. **The live preview doesn't look like the document the lawyer will sign.**
   The right pane renders raw `<pre>` text — no paper chrome, no header/footer,
   no margins, nothing to convey "this is a real deed/agreement." The actual
   PDF generated by `cloudflare-worker/src/services/pdf.ts` *does* have all
   that styling, but the editor preview can't see it.
2. **There's no way to download a draft PDF from the editor.** PDF rendering
   only fires inside the e-sign envelope flow, after a signer signs. Lawyers
   reviewing templates can't see a "real PDF" of an unsigned template.

This plan does three things in one PR:

- **A.** Author substantive v1 bodies for the 21 listed templates, with a
  canonical merge-field schema rich enough to pull legal name, company info,
  dates, cap-table percentages, and co-founder equity splits from the user
  panel.
- **B.** Replace the right-pane preview with a `PaperPreview` component that
  renders the body inside a paper-like card with AXAL VC header, tamper hash
  footer, and PDF-matched typography.
- **C.** Add a `Download PDF` button per template that hits a new admin
  worker route returning `application/pdf`, rendered via a refactored
  `renderTemplatePreviewPdf` that reuses the existing pdf-lib pipeline.

The deliverable for this turn is the **Replit prompt** at the bottom — the
user will run it in Replit, not in this Claude Code session.

## Recommended approach (summary)

### A. Template bodies + merge-field schema

- Author all 21 bodies as `.md` files under `cloudflare-worker/src/templates/legal/`
  (the home the seed generator already special-cases — path B in
  `scripts/gen-legal-templates-seed.py`). Use deterministic filenames; keep
  the database slug literal (spaced slugs like `MSA + Equity-for-Services`
  stay as-is — they're join keys against `esign_envelopes.document_type`).
- New `cloudflare-worker/src/services/mergeFieldsSchema.ts` exporting
  `MERGE_FIELDS_SCHEMA` — a typed `Record<string, { description, example,
  source }>` keyed by dotted path. This is the contract bodies are written
  against.
- New migration `cloudflare-worker/sql/migrations/086_seed_legal_templates_full.sql`
  using `INSERT ... ON CONFLICT(slug) DO UPDATE SET body_md=excluded.body_md,
  ..., is_stub=0` **gated with `WHERE legal_templates.is_stub = 1`** so admin
  edits to non-stub rows are never clobbered. Do NOT rewrite migration 085.
- The D1 resolver `buildUserMergeContext(env, opts)` that pulls live user/
  project/cap-table data is **deferred to a follow-up PR**. This PR ships
  `PLACEHOLDER_MERGE_CONTEXT` derived from `MERGE_FIELDS_SCHEMA.example`
  values so the preview shows real prose flow today.

### B. PDF-style live preview

- New component `frontend/src/components/PaperPreview.jsx`. Do NOT extend
  `DocumentBody` — it's reused by the e-sign signing page where paper chrome
  would be wrong.
- Single continuous paper column (Apple Pages style), not multi-page CSS.
  Pagination accuracy is a stretch goal not worth the complexity.
- `max-w-[8.5in]`, white background, `shadow-lg`, ~54px horizontal padding,
  ~72px top/bottom padding (mirrors `pdf.ts` `MARGIN_X`/`MARGIN_TOP` in CSS
  pixels at 72 DPI).
- Header strip: `AXAL VC` in `text-violet-600`, `Envelope: PREVIEW…` right-
  aligned, 0.5px gray rule below. Footer: 0.5px rule, `SHA-256: <hash>…` left,
  `Page 1 of 1` right, all `text-[7–8px] text-gray-400`.
- Body slot uses `font-family: ui-sans-serif, Helvetica`, `text-[10.5px]
  leading-[14px]` to mirror pdf.ts `BODY_FONT_SIZE`/`BODY_LINE_HEIGHT`. Title
  in `text-[16px] font-bold` above.
- Wire in `AdminTemplates.jsx` — replace the right-pane block at lines 358–367
  with `<PaperPreview title body envelopeUuidPlaceholder bodySha256Placeholder />`.
- Add a small **Resolve merge fields** toggle in the sticky pane header.
  When on (default), body is run through a tiny `frontend/src/lib/mergeFields.js`
  `resolveWithBrackets(body)` that turns `{{company.legal_name}}` into
  `[COMPANY LEGAL NAME]`. When off, literal `{{tokens}}` are shown — useful
  for QA-ing token wiring.

### C. Per-template PDF export

- Refactor `cloudflare-worker/src/services/pdf.ts`:
  - Extract a shared internal `paginateBody({ doc, font, boldFont, title,
    body, reserveTailHeight })` that returns `{ pages, lastY }` — used by
    both renderers.
  - Add `export async function renderTemplatePreviewPdf(opts: { title,
    body, envelopeUuid?, bodySha256?, watermark? })`. Same wrap/header/
    footer as `renderAgreementPdf`, no signature block. Default
    `envelopeUuid = 'PREVIEW-NOT-YET-SENT'`, `bodySha256` to a fresh
    `sha256Hex(body)`, and ALWAYS render a 45° low-opacity `PREVIEW`
    watermark so previews can never be confused with signed envelopes.
  - Refactor `renderAgreementPdf` to call `paginateBody` too — pure code
    move, no behavior change.
- New route in `cloudflare-worker/src/routes/admin_contracts.ts` next to the
  other store routes:
  `GET /api/admin/contracts/templates/store/:slug/preview.pdf?resolve=brackets|raw`
  → `requireAdmin(c)`, loads the row via `storeGetTemplate`, applies
  `resolveWithBrackets(body)` unless `resolve=raw`, calls
  `renderTemplatePreviewPdf`, returns `application/pdf` with
  `Content-Disposition: inline; filename="{slug}-v{version}-preview.pdf"`.
- Frontend trigger: new `api.adminTemplateStorePreviewPdfBlob(slug)` in
  `frontend/src/lib/api.js` (mirror `adminFormPreviewBlob` at line ~943 —
  uses `credentials: 'include'` + auth header). In `TemplateEditorModal`
  add a `Download PDF` button to the footer's right cluster (left of
  `Cancel`), disabled when `isNew` or `saving`, with `Loader2` spinner
  while in-flight. Synthetic `<a download>` click on the blob URL — do
  NOT use `window.open` (Bearer token from localStorage won't attach).
