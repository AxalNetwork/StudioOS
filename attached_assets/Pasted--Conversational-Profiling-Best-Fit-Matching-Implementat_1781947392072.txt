# Conversational Profiling + Best-Fit Matching — Implementation Plan

## Context

Replit already built Skills Profile, Personal Values Assessment, Play & Discover,
and Assessment Studio for Axal VC — but each is a separate page, and adding more
surfaces is increasing UX complexity. We will **consolidate** assessment into a
single human-feeling conversation inside the existing **Personal Advisor**, then
surface the results on **every user's Dashboard** (skills spider, values graph,
range of potential matches) and give **admin (Guillaume)** a full best-fit report
when a user books a consultation. A small **paywall** gates the full user-facing
report, but the backend always computes it so admin matching/spin-out assessment
works regardless. Separately, the **onboarding chatbot's Cloudflare Worker AI
connection is broken** and must be fixed.

The platform already has nearly all the substrate, so this is an **integration +
methodology + surfacing** build, not a rewrite.

**Decisions (confirmed):** build the whole feature now; add the 5 Axal values
(Integrity, Stewardship, Curiosity, Resilience, Collaboration) as a NEW behavioral
layer feeding the admin scorecard while keeping the existing 15 value dimensions
for the user-facing "where you lean" graph; consolidate the standalone `/skills`
and `/values` pages into the Advisor + Dashboard (Play & Discover stays as the
optional gamified deep-dive).

## Workstream 1 — Data model + Axal Fit scoring engine

**Migration `cloudflare-worker/sql/migrations/115_axal_fit.sql`** (+ `schema.sql` mirror), idempotent:
- `axal_values(user_id, value_key, score REAL, confidence REAL, updated_at, PRIMARY KEY(user_id,value_key))` — the 5 Axal values (integrity/stewardship/curiosity/resilience/collaboration), mirrors `user_values`.
- `axal_fit_scores(id, user_id, persona, total_score REAL, band TEXT, rubric_json, red_flags_json, signal_quality REAL, narrative_fit TEXT, computed_at)` — weighted-rubric result; latest row per (user,persona) is current.
- `admin_consultation_bookings(id, uid, user_id, admin_id, requested_at, slot_at, status, topic, notes, report_id, created_at)`.
- `axal_fit_reports(id, uid, user_id, persona, report_json, computed_by, created_at)` — persisted admin best-fit snapshots.

**Service `cloudflare-worker/src/services/axalFit.ts`** — encodes the methodology:
- `RUBRICS`: per-persona weighted categories from the spec (Founder, Partner, Mentor/Coach, Investor), weights normalized to 100.
- `AXAL_VALUES`: the 5 behavioral values.
- `computeFit(env, userId, persona)` → loads scored answers (rubric category scores 1–5, value scores), computes `total_score` 0–100 (Σ weight×score/5), `band` via thresholds (85+ strong_yes / 70–84 yes_caution / 55–69 hold / <55 no), `red_flags` (overconfidence, blame-shifting, inconsistency, ego, weak ethics — from flagged answers), `signal_quality` (confidence/coverage), `narrative_fit`.
- Reuse `assessmentScoring.ts` for the skill/value vectors + archetype; `axalFit` only adds the rubric + 5 values + decision rule.

Remove the standalone pages from `sidebarConfig.js` (replace with a single "Your Profile" entry pointing at the dashboard/advisor).

- **Admin UI**: a dedicated `frontend/src/pages/AdminBestFitPage.jsx` (already scaffolded) — a consultation-request queue on the left, the full best-fit report on the right (skills radar, Axal values, fit scorecard+band, range of matches with reasons, gaps-to-fill, spin-out assessment), plus per-request status controls. Routed at `/admin/best-fit` (admin-guarded), reusing `play/SkillRadar.jsx`. Remaining wiring: lazy import + `<Route>` in `App.jsx`, a sidebar entry, and the `api.adminConsultations`/`adminBestFitReport`/`adminConsultationStatus` methods (each with its worker mount).

## Workstream 6 — Axal Fit methodology + Replit prompts doc  ← ONLY REMAINING WORKSTREAM

> WS0–WS5 + the venture-risk engine are implemented, green, committed on
> `claude/beautiful-dirac-xh904d`, and in draft **PR #92**. WS6 is the last piece.

**New file `attached_assets/axal_fit_methodology.md`** — the canonical methodology,
authored to mirror the as-built engine *exactly* (every weight/threshold/value/flag
cross-checked against code so the doc can't drift). Pure documentation — no code
touched. Sections:

1. **Overview & philosophy** — hybrid model: structured self-rated scorecard →
   human consultation review as the second pass; Axal ideology (30-day spin-out
   engine, high-throughput, stewardship). Source: `banks/fit.ts` header, `CLAUDE.md`.
2. **Conversational delivery** — one 0–5 `scale` question per turn inside the
   Personal Advisor (human tone, "no wrong answers"), not a survey grid; each
   tagged with a `measures` map; IDs `fit.<persona>.<key>`. Source: `banks/fit.ts`,
   `questionBank.ts` (`FitMeasures`, `input_kind:'scale'`).
3. **The four persona rubrics** (weighted categories) — reproduce exactly from
   `axalFit.ts RUBRICS`, each with its `look_for` + the conversational prompt:
   - Founder (8): vision_clarity 15, execution_ability 20, domain_insight 15,
     coachability 15, resilience 15, communication 10, team_dynamics 10, values_fit 10.
   - Investor (6): thesis_fit 20, capital_quality 15, governance_style 15,
     reputation 20, decision_quality 15, values_fit 15.
   - Partner (6): strategic_alignment 20, trustworthiness 20, network_quality 15,
     execution_support 15, collaboration_style 15, reputation 15.
   - Mentor/Coach (6, shared): domain_expertise 25, teaching_ability 20, listening 15,
     founder_empathy 15, reliability 15, values_alignment 10.
   Note weights are relative, normalized by Σweight at score time.
4. **The 5 Axal behavioral values** (asked of every persona) — integrity,
   stewardship, curiosity, resilience, collaboration; the probe + exact question
   wording. Source: `AXAL_VALUES`, `VALUE_SPECS`.
5. **Skills radar (8 axes) + values lean (5 founder spectrums)** — the SKILL_SPECS
   + LEAN_SPECS that populate the dashboard radar + "where you lean" graph. Source:
   `SKILL_SPECS`, `LEAN_SPECS`.
6. **Red flags** (7: overconfidence, blame_shifting, inconsistent_stories,
   poor_follow_through, ego_over_collaboration, transactional, weak_ethics) — how
   they're probed via `red_flag:{key,at_or_below}` on specific questions
   (integrity→blame_shifting, coachability→overconfidence, collaboration→ego).
   Source: `RED_FLAGS`, `banks/fit.ts`.
7. **Scoring & decision rule** — total = Σ(weight×score/5) over *answered*
   categories ÷ Σ(answered weights) × 100; bands **≥85 Strong yes / 70–84 Yes,
   with caution / 55–69 Hold–more diligence / <55 No**; signal_quality =
   0.6×coverage + 0.4×mean value-confidence; final hybrid rule (score + signal
   quality + red flags + human review). Source: `bandFromScore`, `BAND_LABEL`,
   `scoreRubric`, `computeFit`.
8. **From fit → matching & spin-out** — how the vectors feed the range of matches
   (cofounder/investor/partner/mentor) and the admin report's 10-layer venture-risk
   spin-out assessment. Source: `services/bestFit.ts`, `services/ventureRisk.ts`.
9. **Replit Agent build prompts** (the original ask) — sequenced copy-paste prompts,
   one per workstream (chatbot fix → data+scoring → advisor delivery → dashboard →
   matching → admin report+booking → this doc), each prefixed with the `CLAUDE.md`
   guardrails: worker route in `cloudflare-worker/src/routes/` first; add an
   `api.js` method only with a matching worker mount (else `npm run test:drift`
   fails); numbered idempotent migration in `sql/migrations/` + `schema.sql` mirror;
   never touch `wrangler.toml` main; D1 canonical, FastAPI dev-only.

**Verification**: pure doc — `npm run test:drift` stays green (no code touched);
manually diff every rubric weight / band threshold / value / red-flag in the doc
against `axalFit.ts` + `banks/fit.ts`. Commit on `claude/beautiful-dirac-xh904d`,
push; draft PR #92 updates automatically.
