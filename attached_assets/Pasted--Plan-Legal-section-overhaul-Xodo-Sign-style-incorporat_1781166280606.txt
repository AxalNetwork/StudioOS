# Plan: Legal section overhaul — Xodo-Sign-style incorporation flow + template management

## Context

Today the StudioOS Admin Console has a **Contracts** tab (`ContractsPanel`, `frontend/src/pages/AdminPage.jsx:1710-1890`) with sub-tabs *All / Pending / Signed / Voided / Pairwise / Partner / Templates*. The **Incorporate Your Company** wizard (`frontend/src/pages/IncorporatePage.jsx`, backend `cloudflare-worker/src/routes/legal.ts:98-260`) collects company details across four steps and currently deep-links Delaware C-Corp users to Stripe Atlas; UK/SG/EE/LLC just generate the doc set. There is **no Stripe checkout in this flow**, no company-name availability check, no pre-filled e-sign packet, and signed PDFs are single-page envelopes generated by `cloudflare-worker/src/services/pdf.ts` (`renderAgreementPdf`).

Existing infrastructure we will reuse:

- **eSign + audit**: `cloudflare-worker/src/routes/esign.ts` — `esign_envelopes`, `esign_recipients`, `esign_audit_events`. Signed PDFs stored at `esign/signed/{uuid}.pdf` in R2 `FILES` bucket. **This is the spine of the new Xodo-style flow** — we don't replace it; we extend it.
- **PDF library**: `pdf-lib` 1.17.1 (already in `cloudflare-worker/package.json`). Use for all 8 pages — no Browser binding needed for assembly.
- **R2 bindings**: `FILES` (`studioos-files`), already used for KYC docs at `kyc/{user_id}/{uuid}.{ext}` and signed PDFs at `esign/signed/{uuid}.pdf`.
- **Stripe helper**: `stripeCall()` in `cloudflare-worker/src/routes/billing.ts:46-73`.
- **Markdown templates** already live at `cloudflare-worker/src/templates/legal/*.md` with `{{merge_field}}` substitution.
- **Plain-text templates** in `backend/app/api/routes/legal.py:45-831` (21 templates) — these will be migrated to the markdown store.
- **AGREEMENT_OPTIONS dropdown** at `frontend/src/pages/AdminPage.jsx:66-93` already lists the agreements the user mentioned; the gap is **content for each item in the Templates grid**, not the dropdown.
- **KYC capture**: `frontend/src/pages/KYCPage.jsx` and `cloudflare-worker/src/routes/kyc.ts` already collect `id_document_base64` — this feeds Page 7 of the generated PDF.
- **Audit trail source**: `esign_audit_events` already records every recipient action — this feeds Page 8.
- **Browser binding**: `BROWSER` is already in `wrangler.toml:317-318` for PDF analytics export. We'll add SOS scraping calls on top of it.

Architecture decisions (confirmed):

1. **Stripe**: new Price per jurisdiction (DE C-Corp, DE LLC, UK Ltd, SG Pte, EE OÜ) created up-front in Stripe dashboard, IDs stored as Worker secrets. Checkout session is created in step 4 of the wizard; on `checkout.session.completed` webhook the incorporation pipeline kicks off.
2. **Name availability**: per-jurisdiction scrapers running on the `BROWSER` binding (Delaware SOS, Companies House UK, ACRA SG, Estonia e-Business Register), one adapter per jurisdiction in `cloudflare-worker/src/services/name_check/`.
3. **8-page PDF**: fully programmatic with `pdf-lib`. Hardcoded layouts (IRS form geometry) for SS-4, 8821, Statement of Faxed EIN, Confirmation of Information; dynamic generation for Cert of Formation, KYC ID, Audit Trail.
4. **Security**: Cloudflare Access policies in front of `/api/legal/document/{id}/download` and KYC-doc read routes, layered on top of existing `requireAuth` middleware.

The user wants this delivered as **a set of Replit task prompts** — each section below is ready to paste into Replit as one self-contained task.

## Replit Task 4 — Company name availability check via Cloudflare Browser binding

**Goal:** Inline live check of company-name availability on the Confirm step of the incorporate wizard, querying the relevant jurisdiction's official register.

**Files:**

- `frontend/src/pages/IncorporatePage.jsx` — in `ConfirmStep` (line 233-315): wire the company-name input to debounced (500ms) calls to `api.legalNameCheck()`. Show a green check / red conflict pill below the input. Disable the "Submit" button while a check is in flight or if `available === false`. Add a "Skip check, I'll verify manually" link for resilience when SOS sites are down.
- Update `frontend/src/lib/api.js` with `legalNameCheck({ jurisdiction_id, name })`.

**Acceptance:**
- Typing a name like "Stripe Inc." against DE shows red within ~3 seconds.
- A nonsense string shows green.
- KV cache hit returns in <100ms on repeat queries.
- If `BROWSER` is unavailable (preview env), the route returns `{ available: null, source: 'unavailable' }` and the UI falls back to a "could not check — proceed with manual verification" message.

## Replit Task 7 — 8-page combined PDF assembler

**Goal:** Single function that produces the full packet PDF in the exact order described.

**File:** `cloudflare-worker/src/services/pdf/incorporation_packet.ts` exporting `renderIncorporationPacket({ founder, company, jurisdiction, kycDoc, auditEvents }): Promise<Uint8Array>`.

**Page order (matches user's spec):**
1. **Certificate of Formation** — dynamically rendered from `jurisdiction` template (Delaware uses `cert_of_formation_de.ts`; other jurisdictions get jurisdiction-appropriate equivalent). Pulls company name, registered agent, incorporator block.
2. **Form SS-4 Instructions** — `services/forms/ss4_instructions.ts` (Task 3).
3. **Form SS-4** — `services/forms/ss4_form.ts`, pre-filled with company name, responsible-party founder, address from KYC, principal activity from project metadata.
4. **Statement and Acknowledgement of Faxed EIN Filing (Third Party Designees)** — `services/forms/statement_faxed_ein.ts` with `[Full Legal Name]`, `[Company]`, `[Date]` substituted.
5. **Form 8821** — `services/forms/form_8821.ts` filled with taxpayer name, designee (Axal VC GP LLC), date.
6. **Confirmation of Information Provided** — `services/forms/confirmation_of_info.ts` with the three placeholders substituted.
7. **KYC ID page** — embed the founder's `id_document_base64` from KYC (`users.kyc_data.id_document_base64`). If image, draw on a single-page canvas with caption ("Identification document provided during KYC on {date}"); if PDF, merge with `PDFDocument.copyPages`.
8. **Audit Trail** — table of every row in `esign_audit_events` for this envelope (timestamp, signer email, action, IP, user-agent), followed by a hash footer (envelope UUID + SHA-256 of the entire concatenated PDF body + completion timestamp) — re-using the tamper-evident pattern from `cloudflare-worker/src/services/pdf.ts:renderAgreementPdf`.

**Implementation notes:**
- Use `PDFDocument.create()`, build each page, then concatenate with `PDFDocument.copyPages`.
- Cache the static pages (SS-4 instructions, blank 8821) as `Uint8Array` constants generated once at module load — keeps invocation fast on Workers.
- Total file should stay <5 MB to fit comfortably in the email attachment limit (use JPEG-2000 quality 60 for the KYC image if it's a photo).

**Acceptance:**
- Unit test in `cloudflare-worker/tests/pdf/incorporation_packet.test.ts` that runs the assembler with fixture data and asserts: 8 pages, expected text on each page, audit-trail hash matches body.

## Replit Task 9 — Cloudflare Access policies on sensitive R2 read endpoints

**Goal:** Layer Cloudflare Access in front of the routes that serve KYC IDs, signed PDFs, and Certificates of Formation. Existing `requireAuth` middleware stays — Access is additive.

**Endpoints to gate:**
- `GET /api/legal/document/:envelope_uid/download` (signed packet)
- `GET /api/kyc/document/:uid` (raw KYC image)
- `GET /api/legal/incorporations/:uid/certificate` (Cert of Formation only)

**Setup (manual in Cloudflare dashboard, scripted via Terraform optional):**
- Create an Access Application: `Sensitive Legal Docs`, hostname `axal.vc`, path patterns matching the three endpoints above.
- Identity provider: Google Workspace (already used for admin auth in Gmail OAuth path).
- Policy: `Allow` if user email is in `studioos-admins` Access Group OR if the requesting user is the document's signer (use Service Auth token issued by the worker after `requireAuth` succeeds, with email claim).

**Worker changes:**
- `cloudflare-worker/src/middleware/access.ts` (new): validates the `CF-Access-Jwt-Assertion` header against the Access app's certs (cache certs in KV `TOKENS:cf_access_certs` for 1h). If header missing in production, return 403.
- Apply the new middleware after `requireAuth` on the three endpoints above.
- Bypass the middleware in preview/dev environments (`env.ENV !== 'production'`).

**Acceptance:**
- Unauthenticated access to a signed-packet URL returns the Cloudflare Access login page in prod.
- After Google sign-in, an authorized admin reaches the PDF.
- A non-admin, non-signer is denied.
