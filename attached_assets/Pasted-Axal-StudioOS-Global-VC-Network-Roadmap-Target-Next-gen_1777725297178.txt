EPIC 5 — Anti-cheat for Diligence & Scoring Engine
Problem stated: users can hack the scoring engine. Goal: scores LPs see are tamper-proof, but founders still get a sandbox to self-test.
5.1 Server-authoritative scoring
Move all scoring math out of the frontend. Frontend submits raw inputs only; worker calculates score in services/scoring.ts.
Reject any request body that contains score, tier, or score_breakdown as input fields (defense-in-depth).
Sign every score record with HMAC-SHA256 over (project_id, score, version, timestamp). Store the signature in score_snapshots.integrity_hash. On read, recompute and compare; mismatch → flag in error_logs, hide from LP view.
5.2 Two-track scoring: Sandbox vs Score-of-Record
New column: score_snapshots.is_sandbox INTEGER DEFAULT 0.
Sandbox runs are unlimited, do not appear in LP views, do not trigger TIER_1 BUILD promotion. They DO appear in the founder's own portal under "Practice runs".
Score-of-Record runs are rate-limited (1 official run per 7 days per project; admin override available), require all required fields filled, and are the only ones surfaced to partners/LPs and the Pipeline board.
Frontend UX: a clear toggle "Practice mode" vs "Submit official run". Submitting official locks the inputs from edit for 7 days.
5.3 Anomaly detection
New worker job score_anomaly_check runs after every official score. Heuristics:
Inputs change >50% across two runs within 14 days → flag
Identical text strings in qualitative fields across multiple projects → flag (template farming)
Score jumps >25 pts between successive practice runs → flag
Flags surface in admin MonitoringPage and require admin sign-off before LPs see the score.
5.4 Audit trail
Every score read by a partner/LP is logged in activity_logs with the score's integrity_hash. If a founder later disputes a score, admin can replay the exact inputs and recompute.

EPIC 8 — Personality typology for the Axal network
Goal: A repeatable, defensible personality framework specifically for venture capital so partners can find compatible co-investors, advisors, and operators. Eventually publishable as a reference book.
8.1 Working name: Axal Capital Archetypes (ACA-12)
Built on two axes plus a third modifier:
Axis 1 — Conviction stance: Convictor (concentrated, high-conviction bets) ↔ Indexer (portfolio breadth, optionality)
Axis 2 — Engagement depth: Operator-investor (rolls up sleeves) ↔ Capital allocator (board + capital, hands-off)
Modifier — Discovery posture: Thesis-led (top-down) vs Founder-led (bottom-up)
That yields 8 quadrant archetypes; add 4 specialty roles (Scout, Architect-Academic, Steward-LP, Catalyst-Operator) → 12 total.
Working archetype names (rename for marketability):
The Conviction Hunter — concentrated, thesis-led, hands-off
The Builder-Backer — concentrated, thesis-led, operator
The Founder Whisperer — concentrated, founder-led, operator
The Quiet Backer — concentrated, founder-led, hands-off
The Portfolio Architect — diversified, thesis-led, hands-off
The Sector Operator — diversified, thesis-led, operator
The Network Multiplier — diversified, founder-led, operator
The Index Allocator — diversified, founder-led, hands-off
The Scout — specialty: deal-flow generator, sub-$100k checks
The Architect-Academic — specialty: research-rooted, deep-tech
The Steward-LP — specialty: institutional capital, governance-first
The Catalyst-Operator — specialty: portfolio CXO, fractional
8.2 Methodology
Quiz: 24 forced-choice questions (2 per axis-position), Likert 1–5. ~6 minutes.
AI inference: passive — the onboarding chat + activity patterns (which deals they engage with, voting behavior, hold times on liquidity listings) feed a Workers-AI classifier that suggests an archetype with confidence. User can accept/override.
Recompute quarterly — archetypes drift as users mature.

  source TEXT,  -- quiz | ai_inferred | manual
  confidence REAL,
  computed_at INTEGER NOT NULL,
  history_json TEXT,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
8.4 Match scoring between users
Cosine similarity over (axis1, axis2, modifier) vector → compatibility_score.
Surface in PartnersPage and LiquidityPage ("This buyer is a Founder Whisperer — strong fit with your Builder-Backer profile").
Privacy: archetype is opt-in to display. Stored regardless for internal matchmaking but never wire-returned without consent.
8.5 Book-readiness deliverables
Each archetype gets a 1-page profile in docs/archetypes/{slug}.md: signature behaviors, famous examples (with their public consent or pure analogy), failure modes, ideal co-investor pairings.
Quarterly aggregate report: distribution of archetypes across the network, anonymized.
