Objective
  The frontend calls 24 entire feature areas that have no Worker
  implementation. Result: silent 404s across Calendar, Customer
  Discovery, Roadmap, Financials, Marketplace, Mentors, Compliance,
  Wellbeing, and many more. Build minimum-viable handlers for each,
  scoped by the existing auth + IDOR rules.

Implementation rules for every new file
  - Hono router pattern matching the existing routes/* style.
  - `requireAuth(c)` on every handler unless explicitly public (only
    `public.ts` and `calendar.ts` callback need to allow no-auth).
  - IDOR guard: founders see only their own resources via
    user.founder_id; admin/partner/investor see all per the existing
    pattern in projects.ts.
  - Use the existing getSQL(c.env) helper; close with sql.end() in a
    finally.
  - Add CREATE TABLE IF NOT EXISTS for any new tables under
    cloudflare-worker/sql/schema.sql AND a single migration file
    cloudflare-worker/sql/migrations/00xx_unmounted_routes.sql.
    Tables to add if not already present:
      calendar_events, calendar_google_tokens, ic_meetings,
      founder_checkins, compliance_events, wellbeing_checkins,
      wellbeing_resources, marketplace_categories, marketplace_inquiries,
      marketplace_providers, mentor_slots, mentor_bookings,
      financial_models, captable_holders, captable_securities,
      captable_scenarios, companies, cofounder_preferences,
      cofounder_matches, comarketing_pitches, comarketing_campaigns,
      engagements, founder_risk_pulls, insights_signals,
      watchlist_items, journal_entries, needs, quotes,
      references_records, service_offerings, partner_oh_slots.
  - Reuse existing helpers wherever a similar table already exists.

Mount everything in cloudflare-worker/src/index.ts in alphabetical order.
