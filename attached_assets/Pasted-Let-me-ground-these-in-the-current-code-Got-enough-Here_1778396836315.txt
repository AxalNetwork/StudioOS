## Replit Prompt T — Anti-cheat for Diligence & Scoring Engine

```
Objective
  Founders self-report TAM, SAM, MRR, ARR, user counts, runway, etc.
  These feed scoreMarket / scoreTraction / scoreFinancials. Today nothing
  stops a founder from typing $5B TAM and $1M MRR to game the score.
  Make the scoring engine require evidence and use external signals.
  Score numbers without evidence; flag, deweight, or refuse anything that
  smells fake.

Approach
  Layer 1 — Evidence-required inputs
    Every "high-leverage" numeric input must be backed by either:
      a) An auto-pulled external value (Stripe / Plaid / GA / GitHub /
         Crunchbase / SEC EDGAR), OR
      b) A founder-uploaded artefact (bank statement PDF, Stripe export,
         board deck, signed customer LOI, traffic export) hashed and
         stored in R2 (encrypted per Prompt B).
    Without evidence, the input is accepted but scored as 0 for that band.

    Mandatory evidence fields:
      mrr_usd, arr_usd, monthly_revenue_usd, cash_in_bank_usd,
      monthly_burn_usd, total_users, paying_customers,
      tam_usd (must cite ≥1 public source URL), sam_usd, traction_growth.

  Layer 2 — Cross-source reconciliation
    Whenever a connected integration exists, the platform value beats the
    founder-typed value:
      - Stripe connected      → MRR/ARR pulled from Stripe charges
      - Plaid connected       → cash_in_bank, monthly_burn
      - Google Analytics      → DAU/WAU/MAU
      - GitHub                → engineering activity
      - Crunchbase            → funding history
    Discrepancy > 20% between typed and source → flag for admin review,
    score uses the source value, founder shown a banner: "We're using your
    Stripe MRR ($X) instead of your typed value ($Y)."

  Layer 3 — Plausibility checks
    Server-side rules that always run:
      - tam_usd ≤ 100x sam_usd                  else flag tam_implausible
      - mrr_usd × 12 ≈ arr_usd  (±5%)            else flag arr_mrr_inconsistent
      - monthly_revenue_usd ≥ mrr_usd            else flag revenue_lt_mrr
      - paying_customers × min_acv ≤ arr_usd    else flag arr_customer_math
      - growth_mom_pct ≤ 100                    else flag growth_implausible
      - cash_in_bank_usd ≥ 0
      - any % field in [0,100]
      - monthly_burn_usd ≥ founder_salary_usd / 12  (if founder_salary set)
    Each failed rule pushes a row into score_flags with reason + severity.

  Layer 4 — Behavioural signals
    Track edit-volatility per field per project:
      - >5 edits to MRR in 7 days → suspicious
      - flipping the same field up/down repeatedly → suspicious
    Save into score_flags(kind='volatility').

  Layer 5 — Attestation + signature
    Before computing the score, founder must check a box:
      "I attest these figures are accurate. I understand Axal verifies via
       Stripe/Plaid and that fraudulent submission can void the engagement."
    The attestation is signed (TOTP step-up if available) and the input
    snapshot HMAC'd. Stored in score_attestations(project_id, snapshot_id,
    signed_by, signed_at, totp_used, hmac).

  Layer 6 — Score effects of evidence
    The existing total_score is computed as today, but multiplied by an
    evidence_confidence factor:
        evidence_confidence =
          0.4 + 0.6 × (verified_inputs_count / total_high_leverage_inputs)
    No evidence → max 40% of score.
    Full Stripe + Plaid + GA + Crunchbase → 100%.
    Display "Evidence confidence: 73%" next to the score with a tooltip
    listing what's verified and what isn't.

  Layer 7 — Admin / DD overlap
    Every score_flag with severity ≥ 'med' creates a dd_findings row
    (Prompt D) under the relevant DD section. Founders cannot see these
    flags in the score UI; admins/partners/investors can.

Schema
  CREATE TABLE IF NOT EXISTS score_evidence (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    field TEXT NOT NULL,                  -- e.g. 'mrr_usd'
    source TEXT NOT NULL,                 -- 'stripe','plaid','ga','founder_upload','manual'
    value REAL,
    file_key TEXT,                        -- R2 key for upload
    file_sha256 TEXT,
    fetched_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    verified INTEGER DEFAULT 0
  );
  CREATE TABLE IF NOT EXISTS score_flags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    snapshot_id INTEGER,
    kind TEXT NOT NULL,                   -- 'rule','volatility','discrepancy','no_evidence'
    field TEXT,
    reason TEXT,
    severity TEXT NOT NULL,               -- 'info','low','med','high'
    payload_json TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );
  CREATE TABLE IF NOT EXISTS score_attestations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    snapshot_id INTEGER NOT NULL,
    signed_by INTEGER NOT NULL,
    signed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    totp_used INTEGER DEFAULT 0,
    hmac_signature TEXT NOT NULL
  );

Worker (cloudflare-worker/src/routes/scoring.ts +
        cloudflare-worker/src/services/scoring.ts +
        cloudflare-worker/src/services/scoreIntegrity.ts)
  - On POST /scoring/score:
      1. Pull verified values from connected integrations (precedence rules)
      2. Run plausibility rules; insert score_flags
      3. Compute evidence_confidence
      4. Multiply final score
      5. Require attestation row (return 428 Precondition Required if
         missing)
      6. Persist snapshot with integrity_hash already implemented
      7. Mirror med+ flags to dd_findings

Frontend
  Scoring page:
    - Each input shows a small badge: "Verified via Stripe", "Founder upload
      pending", or "No evidence".
    - "Upload evidence" buttons next to inputs without verified source.
    - Top of page: connect-integration suggestions ("Connect Stripe to
      verify MRR automatically").
    - "Run Score" disabled until attestation checkbox checked.
    - Confidence ring + breakdown next to the score.
    - When the platform overrides a typed value, show:
        "Your typed MRR was $A. We used the Stripe value of $B."
  Admin dashboard for flags:
    - /admin/score-flags lists all flags grouped by project, with link into
      the matching DD case.

Acceptance
  - Founder typing $5B TAM with no source URL gets a 'no_evidence' flag and
    the TAM band scores 0.
  - Stripe-connected founder cannot inflate MRR — UI shows the Stripe value.
  - Typed numbers that fail plausibility rules block score finalisation
    until corrected.
  - Attestation required; no score without it.
  - Med+ flags appear in the corresponding DD case under FINANCIAL or
    MARKET section automatically.
  - Existing snapshots remain valid (integrity_hash unchanged).
```
