Use this prompt in Replit:

> Analyze this entire codebase and act like a senior product engineer, staff security engineer, and technical architect. First, identify the **major feature improvements** that would most increase product value, usability, reliability, performance, and scalability. Then perform a **security review** covering auth, authorization, secrets handling, input validation, data exposure, dependency risk, unsafe file or network access, workflow/config risks, and deployment security. After that, convert everything into a prioritized implementation plan with concrete tasks. Group tasks by epic, label each as feature, security, infra, or refactor, assign severity/priority, estimate impact vs effort, identify dependencies, and break large work into small executable tasks Replit can complete one by one. Show quick wins first, then major projects, and end with the top 10 next tasks.[1][2][3]

A stronger version for better output:

> Perform a full product, architecture, and security audit of this repo without making changes yet. Infer the stack from the codebase. Deliver:
> 1. A concise summary of what the app does.
> 2. The top major feature improvements that would materially improve the product.
> 3. The top security and privacy risks, with exploitability and business impact.
> 4. A prioritized roadmap split into epics and tasks.
> 5. For each task: title, why it matters, files likely affected, implementation steps, risk level, impact, effort, and whether Replit can do it autonomously.
> 6. A recommended execution order for the next 2 weeks.
> Focus on actionable findings, avoid generic advice, and prefer repo-specific recommendations over boilerplate. If something is uncertain, say what evidence would confirm it.[2][4][5]

If you want it to immediately turn findings into an actionable backlog:

> Review this codebase for major feature opportunities, security issues, and technical debt. Then create a backlog I can execute in Replit. Organize the backlog into: Quick wins, High-impact features, Security fixes, Reliability improvements, and Nice-to-have ideas. For each item, include a short description, acceptance criteria, priority, estimated complexity, and the exact first step. Make the recommendations specific to this repository, not generic SaaS advice.[6][7][8]

Best short version:

> Audit this repo for major feature improvements and security risks, then turn the findings into a prioritized task list with epics, acceptance criteria, and recommended execution order.[3][1]

If you want, I can make a version specifically for a **SaaS app**, **marketing site**, or **API/backend** repo.
