# Git LFS Migration — StudioOS

_Branch: `claude/eager-lovelace-pf7lZ` · Generated 2026-06-06_

## Context

StudioOS already has substantial Git LFS scaffolding from a prior audit
(`MIGRATION_LFS_AUDIT.md`, baseline 2026-05-21): `.gitattributes`
patterns, a `scripts/lfs-size-gate.mjs` pre-commit hook, a
`.github/workflows/lfs-budget.yml` budget cron, and matching guidance in
`CONTRIBUTING.md`. **No LFS objects have actually been created yet** —
the audit's "first LFS commit" remained an operator task that was never
done.

Between the prior audit and today, **547 new PNGs** landed in
`attached_assets/`; **54 of them are >500KB (48.8 MB total)** — exactly
what the size-gate hook is designed to catch. The hook isn't enforced in
CI, only locally, so the drift slipped through.

This plan does **three** things:

1. **Patch the obvious gaps** that allowed the post-audit drift: enforce
   the size-gate in CI, broaden `.gitattributes` to cover Office and
   ML/data formats that don't yet match a rule, ignore `dist-deploy/`
   and `backend/app.db`.
2. **Close the prior audit's open follow-ups** that are safe to act on
   without rewriting history: drop `users/1/activity.md` (PII), document
   the operator handoff for the first LFS object.
3. **Surface — but do not execute without confirmation** — the one
   history-rewriting option that would actually shrink the pack: a
   targeted `git lfs migrate import` of the 54 post-audit large
   screenshots, scoped to commits made since the audit baseline.

Goal: a clean, durable LFS posture that prevents the next round of
drift, without surprising collaborators with a force-push.

### A5 — Add a `--against=<ref>` mode to the size-gate, then enforce in CI

The 547-PNG / 48.8 MB drift since the prior audit is direct evidence
the local-only hook isn't enough.

**Problem with the existing script:** the default mode reads `git diff
--cached`, which is empty in CI; the `--all` mode walks `git ls-files`,
which would flag every grandfathered pre-audit screenshot
(~280 PNGs >500 KB intentionally left in place). Neither mode is
appropriate for CI.

**Fix:** add an `--against=<ref>` mode that lists files added/modified
relative to a base ref (the PR's merge target) and runs the existing
checks against just those files:

```js
function listAgainst(ref) {
  const out = tryShOrEmpty(
    `git diff ${JSON.stringify(ref)}...HEAD --name-only --diff-filter=AM`
  );
  return out ? out.split("\n").filter(Boolean) : [];
}

// in main(), before the existing branching:
const againstArg = [...args].find((a) => a.startsWith("--against="));
const files = againstArg
  ? listAgainst(againstArg.slice("--against=".length))
  : args.has("--all")
  ? listAll()
  : listStagedAdditions();
```

Then add a `lfs-gate` job to `.github/workflows/ci.yml` after the
`drift` job:

```yaml
  lfs-gate:
    name: lfs size gate
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v6
        with:
          # Full history so the diff range works on a PR build.
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: '20'
      - name: Run LFS size gate (against PR base)
        run: |
          base="origin/${{ github.base_ref || 'main' }}"
          git fetch --no-tags --depth=1 origin "${{ github.base_ref || 'main' }}"
          node scripts/lfs-size-gate.mjs --against="$base"
```

`--all` mode stays available for ad-hoc local audits; the CI gate uses
`--against=...` so it only fires on files the PR actually touches.

|---|---|---|
| A1 (new patterns) | Future commits route DOCX/etc. through LFS; needs `git lfs install` on every contributor's machine. | Already documented in `CONTRIBUTING.md`. New patterns only affect new files. Revert: `git revert` the commit. |
| A2 (dist-deploy/) | Someone might be relying on the committed worker bundle for audit/inspection. | Grep confirmed no CI/script depends on it. If a reviewer objects, drop `dist-deploy/` from `.gitignore`; bundle re-appears on next build. |
| A3 (app.db) | None — file is 0 B and Replit-dev-only. | Reversible: `touch backend/app.db && git add -f backend/app.db`. |
| A4 (activity.md) | The file is **deleted** from tree, not just untracked. | Reversible: the backend export script regenerates it. PII removal is the goal, so re-adding is undesirable. |
| A5 (CI gate) | New PRs fail until contributors install `git-lfs` locally. | Hook output points at remediation: `git lfs track "*.pdf"` + re-add. Lower friction than letting bytes pile up. |
| B (history rewrite) | Force-push, collaborators must re-fetch the branch. | Only run with explicit user say-so. Scoped to the dev branch — `main` unaffected. |
