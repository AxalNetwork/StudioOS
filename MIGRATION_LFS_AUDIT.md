## Decision rule

| Destination | When | Rationale |
|---|---|---|
| **LFS** | Versioned *source* artifact that belongs with the codebase: design masters, ML weights, fixture archives, deck-template PSDs that author KB. | We have 250 GB / 250 GB Team allotment idle. Git stays fast; checkouts only fetch pointers; designers and ML engineers get history. |
| **R2** | Runtime-served traffic: user uploads, signed contracts, deck exports, KYC docs, backups. | Zero egress; lifecycle rules; encryption-at-rest via cryptoBox; not source-controlled by intent. |
| **GitHub Releases** | Public point-in-time artifacts: quarterly Investor Signals PDFs, public DD summaries, sector reports. | Uncapped release-asset bandwidth; immutable per tag; doesn't bloat the repo. |
| **Worker bundle** | Tiny atomic assets that ship with the worker: favicons, OG fallback PNG, validation regex JSON, deck templates < 50 KB. | Atomicity with deploys; cold-start latency is the bottleneck, not bytes. |
| **Leave in place** | Anything already in tree that doesn't trip the size gate, or build outputs that GitHub Pages already serves. | No history rewrites. Existing blobs stay until they are rotated by normal turnover. |

History is **NOT** rewritten. `BFG` and `git filter-repo` are explicitly out of scope. New and re-added files only.

### Categories targeted for LFS going forward

These extensions are auto-tracked by `.gitattributes` so *new* commits route through LFS:

- **Design sources**: `*.psd`, `*.psb`, `*.ai`, `*.xd`, `*.fig`, `*.sketch`
- **ML weights / model artifacts**: `*.onnx`, `*.safetensors`, `*.pt`, `*.pth`, `*.gguf`
- **Tabular fixtures**: `*.parquet`
- **Archives**: `*.zip`, `*.tar.gz`, `*.tgz`
- **Video**: `*.mp4`, `*.webm`, `*.mov`
- **Audio masters**: `*.wav`, `*.flac`

PDFs and PNGs are **not** auto-tracked by extension because that would route every small inline diagram and every existing in-tree screenshot through LFS pointers (and the repo already has hundreds). Instead, the pre-commit hook size-gates them: any **new** PDF or PNG > 500 KB must be `git lfs track`'d before commit or the hook rejects the push.

### Categories that stay on R2 (NOT in this audit's scope; documented for clarity)

- User-uploaded pitch decks, founder docs, NDAs
- Signed legal documents (incorporation, 83(b), waterfall outputs)
- KYC documents
- DD reports (already AES-GCM via `cryptoBox.encryptBytes`)
- Backup snapshots, DR drill outputs
- Generated deck PDF exports

R2 retains the zero-egress advantage for serve traffic; LFS bandwidth is precious (250 GB/month) and must be reserved for source artifacts that engineers actually pull on clone.

### Categories that go to GitHub Releases

- Quarterly Investor Signals PDFs (public)
- Public DD summary briefs (founder-redacted)
- Sector reports (public)
- Annual transparency report / threat model snapshots

GitHub Releases are tagged, immutable, and have uncapped public-asset bandwidth. They are reachable from the marketing site without consuming LFS budget. Workflow for publishing lives in `CONTRIBUTING.md → "Publishing public artifacts"`.

## First LFS commit (operator action)

To validate the LFS panel and prove the wiring end-to-end, an operator (outside the main-agent sandbox; main-agent bash is git-restricted) needs to run, once, on a workstation or in the Replit Shell tab:

```bash
git lfs install                          # one-time, per machine
mkdir -p design/logo
cp /path/to/axal-logo-master.ai design/logo/axal-logo-master.ai
git add .gitattributes design/logo/axal-logo-master.ai
git commit -m "chore(lfs): track logo master via LFS"
bash scripts/git-sync.sh                 # or the blue Sync button
```

After the push, GitHub → Repo Settings → Git LFS panel should show one
object and a few hundred KB of storage used. That confirms `.gitattributes`
is doing its job and the budget workflow has a non-zero baseline.

## What the daily budget workflow does

`.github/workflows/lfs-budget.yml` runs at 09:00 UTC daily:

1. Queries `GET /repos/{owner}/{repo}` for `size` and the GraphQL endpoint
   for the current month's LFS bandwidth.
2. Computes projected month-end usage = `current_usage / day_of_month * days_in_month`.
3. If `projected > 0.80 * 250 GB`, posts to `SLACK_OPS_WEBHOOK_URL` with
   current, projected, and the top contributors (resolved from `git lfs ls-files --size`).
4. Always writes a one-line summary to the workflow log so a clean day
   leaves a green tick.

The threshold is 80% (200 GB / month). Tune via the `BUDGET_THRESHOLD_PCT`
workflow input.
