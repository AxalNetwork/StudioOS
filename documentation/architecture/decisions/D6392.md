## D6392 — Preserve recorded Signals consent when a profile save omits it (#6392)

The existing profile upsert keeps contribution at its database value on a
conflict when the request omits contribute_to_signals. The SQL CASE and
bound presence flag make this atomic with the update, so an omitted field
cannot reapply a stale value read before another opt-out. A new profile
retains the existing default of 1; explicit false/true still write 0/1.
The activity detail labels an omitted contribution unchanged instead of
claiming that the save opted in. No other full-replacement profile field is
changed; #6287 retains that work and #6131 retains onboarding scope.

The owner explicitly assigned this narrow route repair to s38. Tests run
PUT/GET and the opt-out endpoint over canonical SQLite schema, checking
stored and returned consent, new-profile default and explicit changes.
No schema, permission, frontend or production data operation is added.
