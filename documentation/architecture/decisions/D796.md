## D796 — The Admin sidebar's "Settings" row becomes "Licences", on both Admin shells

- **Status:** decided by S1 for the owner, 2026-10-20 (#2229; part of D795, #2228, item D-a). Built by S08.
- **Basis:** `origin/main` at `8902ea2c56`. Paths are relative to `frontend/src/` unless they say otherwise.
- **The owner:** rename "Settings" in the Admin's left sidebar to "Licences". The spelling is British, the owner's answer, matching the Super Admin's "Licences" row.

### What changes

1. **The plain Admin shell** (`sidebarConfig.js`, `SIDEBAR_GROUPS.admin`): the row that read "Settings" reads **"Licences"**, with the `BadgeCheck` icon. It still opens `/admin/my-licence`, the administrator's own read of their licence.
2. **The branch shell** (`SIDEBAR_GROUPS.branch_admin`): the row that read "Settings" and opened `/branch/settings` now reads **"Licences"** and opens `/admin/my-licence`, which on a branch reads the branch's licence copy. Its `match` is `['/admin/my-licence', '/branch/settings']`, so it stays lit on Branch settings.
3. **My Licence links Branch settings.** `MyLicencePage.jsx` draws a "Branch settings →" card (`BranchSettingsLink`) under its header, only on a branch (`branchOfUser`), opening `/branch/settings`. Off a branch there is no such page, and nothing is drawn. The page's frame is named "Licences"; its title, "My licence", stays until D800's canvas page replaces it.
4. **The map, the rail and the overview.**
   - `lib/adminPlacement.js`: `ADMIN_ROWS` ends in `'Licences'`, and My Licence's placement is `admin('Licences', 'embedded')`.
   - The Studio overview's card is titled "Licences" and opens the shell's Licences row (`studioCardTarget`); its test id stays `admin-studio-settings`.
   - `lib/railOptions/admin.js`: S39's section is `'Licences'`.
5. **The not-deployed bar's link** reads "Your licence →" (it read "Licence summary in Settings →").

The Super Admin shell's own "Settings" row (`/account`) is the HQ shell's personal settings and is unchanged.

### The rail page key

`/admin/my-licence` (and its alias `/branch/settings`) answer **`Admin · Licences`** (`lib/railPages.js`), not `Admin · Settings`.

- **Runs already logged keep the old value.** `ai_usage_logs.rail_page` rows written before this change say `Admin · Settings`; nothing rewrites them. A reader that groups by page should treat the two as the same page. No code reads the old key literally: a search of `frontend/src`, `cloudflare-worker/src` and the tests found it only in the page map and the matrix, both changed here.
- **The canvas names the board, so the canvas changes with it.** The page key is the canvas's board name, and D768's parity test and D764's model matrix both read it. The owner chose (2026-10-20, in the session) to rename the board and keep its models:
  - `design/incoming/airail-every-page-data/canvas.json`: the Admin profile's `"Settings"` board is `"Licences"`.
  - `scripts/build-rail-matrix.mjs` gains `keepKind`: an override in `scripts/lib/railMatrixOverrides.json` may keep an on-canvas board on the kind it had, with its `why`. `Admin · Licences` keeps `plan`, the kind it had as Settings; the canvas's `Licences` kind (`legal`) is the Super Admin's ledger of every licence, a different page.
  - `cloudflare-worker/src/services/ai/railMatrix.json` is regenerated (`node scripts/build-rail-matrix.mjs`). Its one change is the row's `pageKey`; the kind, route task and models are as before. This is the only file under `cloudflare-worker/` the change touches, and it is generated data, not Worker code.
