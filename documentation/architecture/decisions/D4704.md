## D4704 — One definition of an advisor's money report (#4704, slice 1)

- **Status:** slice 1 built 2026-11-09 by S02 for #4704 (Practice audit 6/6). Later slices are listed at the end.
- **Number:** D4704 is this issue's number (D4106).
- **Code:**
  - `cloudflare-worker/src/services/practiceReporting.ts` (new);
  - the earnings route in `routes/advisors_money.ts`.
- **Test:** `cloudflare-worker/test/practice_reporting_4704.test.ts`.

### 1. The defect

The Practice money pages read three endpoints:

- the earnings overview (`GET /api/advisors/me/earnings`);
- the ledger and its export (`GET /me/ledger`);
- the annual summary (`GET /me/tax-summary`).

D4702 put the ledger and the annual summary on one aggregate. The overview still ran its own query and grouped by the
stored `billing_state`. The ledger derives a line's state from its amount first.

So one booking could be counted two ways at once. A priced session whose stored state still read `unpriced` was
"unpriced" (no cents) in the overview and "billed" in the ledger beside it. The write route allows this: an amount sent
with an explicit `billing_state: 'unpriced'` keeps both. That broke #4704's acceptance line "no overview/detail/export
pair uses different definitions for the same metric".

### 2. The rule

`services/practiceReporting.ts` is now the one definition. `ledgerAggregate` moved there unchanged from
`routes/advisors_money.ts`, which re-exports it.

**The population.** Every booking created in the half-open window, except a cancelled or missed session that was never
collected. That one owes nothing and is counted apart. Totals are counted in the database, so no row cap applies.

**The state of a line:**

| State | When |
| --- | --- |
| `unpriced` | `amount_cents IS NULL` |
| `collected` | priced, and stored `collected` |
| `written_off` | priced, and stored `written_off` |
| `billed` | any other priced line, including one still stored as `unpriced` |

**The cut** is the one stamped when the line was priced; only a line priced before 241 is derived.

**What reads it.** The overview is `earningsOf(ledgerAggregate(all time))`. It keeps its response shape (`billed_cents`,
`collected_cents`, `written_off_cents`, `outstanding_cents`, `unpriced_count`, `by_state`, `take_rate`, `settlement`)
and adds `population`. Following #4704's request for explicit metadata, `population` gives:

- the definition's name;
- the period;
- the session count;
- the void sessions left out;
- `complete: true`.

### 3. What the test pins

- **The overview and the ledger agree on every state.** The fixture includes a priced row stored `unpriced`, a cancelled
  and uncollected row, and a missed but collected row. The states add up to the ledger's gross.
  - **Run against the code before this change, it fails.**
- **The annual summary for a year equals the ledger over that year**, including at the boundary instants.
- **One client past `LEDGER_CLIENT_CAP` changes no total:**
  - the listed rows plus `clients_other` reconcile to the totals;
  - the overview counts everyone;
  - the ledger says its client list is incomplete.

**Mutation-checked.** Each of these makes a test fail:

- the overview's original query;
- capping the client query without its overflow probe;
- the overview summing only the listed clients.

### 4. What the user sees

**Earnings is unchanged** except for a priced line stored as `unpriced`. It now shows under Billed with its amount,
where it already showed in the ledger. No figure moves for a booking whose stored state already matched its amount.
