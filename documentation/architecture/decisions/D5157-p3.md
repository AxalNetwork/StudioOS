### What a comparison is

A named set of companies, or of funds, kept with a Research Project. Every column has the same attributes, each value is read from the directory with its source and as-of date, and nothing is scored, ranked or summed.

### Built

1. **The store.**
   - `research_project_subjects` is a project's companies and funds: what "Add to research" keeps. Each row names a company directory (migration 228) or fund directory (378) row by its uid, with the name the directory gave it when it was added. The directories are rebuilt by import, so the uid is a reference, not a foreign key.
   - `research_project_comparisons` holds the title and the kind (`company` or `fund`).
   - `research_project_comparison_members` holds the columns in order. Its two composite foreign keys, `(comparison_id, kind)` and `(subject_id, kind)`, hold one kind per comparison in the schema itself, so a fund can never be a column of a company comparison.
   - Removing a subject from the project removes it from its comparisons (CASCADE). Deleting a comparison keeps its subjects.
   - No value is copied from the directory. A comparison never keeps a stale figure.
2. **Worker routes** (`routes/research_project_comparisons.ts`, mounted at `/api/research/projects` beside parts 1 and 2 through the #4105 registry). Every route reads the project through part 1's `checkProjectOwner`, so another member's project is a 404.
   - `GET /:uid/comparisons` returns:
     - the project's subjects, each `listed`, `removed` (no longer in the directory), `withdrawn` (its fund list was taken down for its terms, D597) or `unreadable`;
     - the comparisons, with each listed column's values: `{ status: 'recorded', value, source: { name, url }, as_of }`, or `{ status: 'not_recorded', reason }`;
     - the attributes per kind and the limits.
   - One directory read runs per kind. A failed read marks that kind `unreadable`; it never makes a row look absent or a value look missing.
   - `POST /:uid/subjects { kind, uids }` adds up to 25 companies or funds (an existing one is kept). Every uid must be in the company directory, or among the funds the fund directory serves. Otherwise it is 404 `not_in_directory` and nothing is added.
   - `DELETE /:uid/subjects/:kind/:uid` removes one.
   - `POST /:uid/comparisons { kind, uids, title? }` makes a comparison of 1 to 6 of them and adds any that are not yet subjects. The title defaults to the names, cut at a name.
   - `PATCH /:uid/comparisons/:cuid { title }` renames a comparison, and `DELETE /:uid/comparisons/:cuid` deletes it.
   - `POST /:uid/comparisons/:cuid/members { uid }` adds a column of the comparison's kind. A seventh is 409 `comparison_full`, refused before anything is written.
   - `DELETE /:uid/comparisons/:cuid/members/:uid` removes a column.
   - An archived project is read-only (409 `project_archived`), as in parts 1 and 2. A failed directory read during a write is 503 `directory_unreadable`.
   - Every write leaves a receipt: `research_project_subject_added`, `_removed`, `research_project_comparison_created`, `_updated`, `_deleted`, `_member_added` and `_member_removed`.
   - All SQL is bound. A list of uids is one bound JSON array read through `json_each`, and a uid must match the directories' character set.
3. **Client:** `frontend/src/lib/api/researchProjectComparisons.js` (`researchProjectComparisonsApi`), in the generated index.
4. **The Comparisons tab** (`/research/projects/:uid/comparisons`, `ProjectComparisons.jsx`). The tab is now a link, with a badge counting comparisons. The badge is absent, never 0, while the read is not ok.
   - **Companies and funds in this project.** Each entry links to its profile and says if it left the directory or how many comparisons it is in. Remove is confirmed in the row and says which comparisons it also leaves. Ticking entries of one kind and pressing Compare N makes a comparison. Ticking the other kind starts a new selection.
   - **Each comparison** is a card titled with its name and "as of each source's date · no composite score", with Add company or Add fund, Rename and Delete (asked once, in the card).
     - Its table has row headers and one column per company or fund. Each value shows its source and date, and links to the source where one is recorded. Not recorded is italic and gives its reason. Unreadable is said as Unreadable.
     - A column that left the directory says so under its name and shows no values.
     - On a phone each column is a card of attribute and value.
   - **Add company / Add fund** offers the project's own entries of that kind first, then a directory search.
   - Loading, "No comparisons yet" and Unavailable with Retry are separate states.
5. **The project bar's Compare** opens the Comparisons tab.
6. **Add to research and Compare** (`AddToResearch.jsx`, the shared `Sheet`; a bottom sheet on a phone).
   - The panel names what will be added. You pick one of your active projects, or start one with the New research form. Then Add to project keeps them there, or Create comparison opens a comparison of them (with an optional title).
   - The outcome is said in the panel with a link into the project. A failure says why and that nothing was added.
   - An unreadable project list is Unavailable with Retry and offers no button.
   - Where it appears:
     - **Companies** (`CompanyDirectoryZone.jsx`): a checkbox and Add to research on each row; a selection kept across pages and filters; and a bar with "N selected", Clear, Add to research and Compare N, enabled from two.
     - **Company profile**: Add to research and Compare (`ResearchActions.jsx`).
     - **Fund directory**: Add to my research on each row.
     - **Fund profile**: Add to my research and Compare.
   - These controls are drawn only in a shell whose Research row has My Research, the founder's, which an admin browses as (`canAddToResearch`).

### Departures from the canvas

- **No "Research status" or "Sources" row.** The canvas's comparison draws both per column, and the directory draws them as columns. No store records a company's research status ("Researching", "Profile saved") or a source count tied to a project. So they are not rows, and the directory gains no such columns. Each value names its own source instead.
- **The attributes are what the directories record.**
  - Companies: Country, Sector, Founded, Employees, Last round, Total funding and Revenue. The canvas says "Headquarters", and the company directory records a country.
  - Funds: Headquarters, Stated focus, Fund, Fund size (only in a known currency), Vintage, Notable LPs and EIF / EIFO.
  - The fund canvas's Stage and Cheque have no store (D535) and are not rows.
- **A comparison is one kind.** The canvas never mixes companies and funds in one table. Here the schema holds it.
- **At most six columns.** The canvas draws three. Six keeps the table readable on a laptop, and the Worker refuses more.
- **The company profile keeps "Run competitor analysis" as its violet primary.** The canvas makes Add to research the profile's primary. That button already held the place (D534), so Add to research and Compare sit beside it as secondary buttons. On the fund profile, "Add to my funds" stays violet for the same reason.
- **The fund directory has no selection or Compare bar.** RS-05 A draws only the row action, so Compare for funds is on the fund profile and in the project's Comparisons tab.
- **Market rows are not added.** RS-03's market card draws Compare and Add to research, but #5157 names Companies and Funds. A market has no directory uid a project could keep yet.
- **The context rail's "Comparison set"** is part of the context rail slice, still open.
