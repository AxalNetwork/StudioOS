## D8078 — Venture namespaces: `ventures/<slug>/` folders, a `venture:` label each, and no cross-venture write (#8078)

- **Status:** built by S20 on 2026-11-22 for #8078 (audit section 16), after #8075 (#8098) and #5569 (#7541/#7654).
- **Owner decision (2026-11-21, on #8078):**
  - **Q1 A:** venture code lives in folders `ventures/<slug>/` of this repository, protected by path rulesets.
  - **Q2 A:** only the owner creates a namespace, by adding it to the root `ventures.json` in a privileged PR.
  - No migration is needed, because Q1 is not B.

**The list.** The root `ventures.json` is `{ "version": 1, "ventures": [{ slug, name, company_id }] }`. It starts
empty: no venture exists yet, and adding one is the owner's.
- **Checks** (`validateVentures()` in `scripts/lib/workIntent.mjs`): a slug is lowercase, starts with a letter, is
  2 to 40 characters, and has no leading, trailing or double hyphen. Slugs are unique, each company has at most one
  venture, and unknown fields are refused.
- **Company link:** `company_id` maps a venture to the company that `scope_tasks` and `agent_task_runs` already
  carry.

**Branches.** `parseBranch()` reads two shapes:

| Shape | Kind | Use |
| --- | --- | --- |
| `agent/<slot or agent>/<issue>-<slug>` | platform | every task today |
| `agent/<slot or agent>/<venture>/<issue>-<slug>` | venture | work inside one venture |

- **Malformed names:** a venture segment that is not a slug is `other`, never platform.
- **Ownership:** `ventureBranchViolations()` gives the ownership check (#8075) its rule. A venture branch changes
  only `ventures/<its slug>/`. A platform branch changes no venture folder. A venture that `ventures.json` does not
  declare owns nothing.
- **Not wired yet:** `scripts/ci/ownership-check.mjs` is #8075's file and is not in this issue's list, so this PR
  does not call it. That one call is the follow-up. The checker's existing task regex reads only the platform shape.

**Labels.** Each venture gets a `venture:<slug>` label. The labels are generated into a marked block of
`.github/labels.yml` by `node scripts/lib/workIntent.mjs --venture-labels`, and `--check` exits 1 when the block
and `ventures.json` disagree. The test runs that check and fails if a `venture:` label appears outside the block.
labels-sync reads the file with `yq`, so the marker comments change nothing there.

**The publisher.** `planAgentPublish()` (D5569-p2) gets one more check, `ventureScopeViolations()`. It runs after
`protected_path` and before `allowed_paths`:
- a venture company's agent may write only inside its own `ventures/<slug>/`. Anything else, another venture's
  folder or a platform path, is refused `venture_scope_violation` with the paths, and is not retryable;
- any other company's agent may write no venture folder;
- the namespaces come in as an observation (`ventures`). If the intent touches `ventures/` and none were supplied,
  the plan refuses `invalid_observation` (field `ventures`, retryable). An intent that touches no venture path, from
  a company that is not a venture, plans exactly as before.

The repository check (`repository_mismatch`) already pins the target. With Q1 A every venture is in this
repository, so no extra repository rule is needed.

**Not in this PR:**
- the path rulesets on `ventures/<slug>/` (a repository setting for an admin);
- a venture's `README.md` once it exists;
- the ownership-check call above;
- adding `ventures.json` to the privileged path list (`merge-control/src/lib/classify.mjs`, D8067), which makes
  Q2's "privileged PR" automatic. That file belongs to D8067; until then the owner's review of the change is the
  gate;
- the publisher's caller supplying `ventures`. The broker stays disabled (#5569), so nothing calls it yet.

**Rollback.** Revert the PR. `ventures.json` is empty and the label block holds no entries, so nothing on GitHub or
in D1 changes.
