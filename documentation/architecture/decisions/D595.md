## D595 — Research markets: US public companies from SEC EDGAR on the Public tab

**The Public tab of `/research/markets` lists SEC EDGAR's public companies
beside the signal companies, each row labelled by its source.** Slot S10,
issue #1230, 2026-10-06. From the owner's answers 1A (free, open sources
first, EDGAR among them) and 3A (public = the listed companies, plus EDGAR)
on #1083, which D537 records. Migration 404.

### The importer

`scripts/import-sec-edgar.mjs` reads EDGAR's public company list,
`https://www.sec.gov/files/company_tickers_exchange.json`, and writes
migration 404. It never writes to a database. The rules live in
`scripts/lib/secEdgarCompanies.mjs`:

- **What a row carries is what EDGAR records:** the CIK (ten digits,
  zero-padded, as EDGAR writes it), the registrant name, the ticker and the
  exchange. EDGAR lists a company once per ticker, so a CIK with several
  share classes appears several times. The first listing is the row's
  ticker and exchange; the others go in `other_listings`, in EDGAR's order.
- **Nothing is invented.** An exchange EDGAR leaves null stays null and
  reads "Not recorded". EDGAR records no country, sector, market cap or
  headcount, so none is stored.
- **No personal data.** The file names registrants only, with no officers
  or addresses, and the importer asks for nothing else.
- **A listing that fails a check is skipped and counted, never repaired:**
  no valid CIK, no name, a ticker outside `[A-Z0-9.-]`, or a control
  character. A file whose `fields` are not EDGAR's four throws, so a format
  change can never put a name in the ticker column.
- **Every row cites its source:** `source_name` `SEC EDGAR`, `source_url`,
  `licence` (US government work, not subject to copyright in the United
  States, 17 U.S.C. § 105), and `as_of`, the date the file was read.
- **The User-Agent** the SEC requires names the project's public contact in
  `SECURITY.md` (`security@axal.vc`), never a person. A test holds it to
  that file.
- Rows go in `INSERT OR IGNORE` batches of 100, keyed on CIK, so each
  statement stays well under D1's statement limit and applying the file
  twice leaves the same rows.

### The table

`research_public_companies` (migration 404) is a table of its own, not
rows mixed into `signal_companies`. The 21 signal companies carry bands their
source sets; EDGAR's rows carry none, and one table for both would make a
null band read as "unknown" for a company whose source never had the column.

### The route

`GET /api/research/listed-companies` reads both stores and returns one list,
paged on the Worker:

- The signal companies come first, in the chosen order, then EDGAR's rows,
  by name. EDGAR records no market cap, so a cap sort orders them by name.
  The EDGAR page is two literal SQL statements (ascending, descending): no
  order clause is built from the request.
- Each item has `source` (`signal_companies` or `sec_edgar`). An EDGAR item
  has `symbol`, `name`, `exchange`, `cik`, `other_listings`, `source_url`,
  `licence` and `as_of`, and no band, country or sector key.
- `sources` gives each store's matched total. For EDGAR it also gives the
  whole store's size, its date, URL and licence, and
  `also_signal_companies`: how many of its tickers are also a signal
  company's symbol. Those companies appear once per source, and the page
  says how many.
- `source=signal_companies|sec_edgar` narrows the list to one store. A
  `sector` or `country` filter leaves EDGAR out, because EDGAR records
  neither.
- A failed read of either store is a 503 `listed_companies_unreadable`, never
  a zero. An empty EDGAR store is a zero read from the store.
- `offset` may now reach 200,000, since EDGAR lists about ten thousand
  companies.

### The page

The Public tab asks the Worker for 50 rows at a time, with Previous and Next.
It prints the total and each source's count from the API, a Source column
that links each EDGAR row to the file, and a source line under the table:
EDGAR, its count, the date it was read, its licence and URL, and the overlap.
EDGAR rows read "Not recorded" for country, market cap and employees. The
page writes no count of its own.

Government stays "Not recorded". The reason now names EDGAR too: no source,
EDGAR included, records who owns a company (D537, answer 3A).

### Not done here

The rows themselves. This environment's network policy refuses
`www.sec.gov`, so the committed migration 404 was written by the importer
from an empty file: the table, and no rows. Before 404 merges, someone
with access to sec.gov runs `node scripts/import-sec-edgar.mjs` on this
branch and commits the file it writes. Once 404 is applied it is never
rewritten, and a later refresh is a new migration with its own number from
an issue.
