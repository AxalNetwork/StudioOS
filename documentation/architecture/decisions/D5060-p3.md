- **Status:** built 2026-11-13 by S10. The PR says `Part of #5060`: the Contracts filters (addendum boards CT-17 to

- **Builds on:** D5060 (the registry reads), D5060 part 2 (the history read), D5059 (program entitlements), D4819
  (the Licences v2 ledger). Boards: L36, L37 and L37B of `design/incoming/Licences and Contracts v2 Addendum Page.dc.html`.
- **No migration.** One Worker string changes (below).

### 1. The family chips (L36)

`/admin/licences` gains the six family chips: All, Operator / territory, Founder, Investor, Operating Partner and
Advisor. The choice is in the URL (`?family=`).

- **Operator / territory** is the existing operator ledger, unchanged: counts, Needs HQ, requests, coverage and the
  renewal pipeline (boards L01, L02).
- **All and the four user families** are the registry (`licences/RegistryLedger.jsx`), read from
  `/api/admin/licence-registry` with the family, the search and the holder as server filters. Its table has L36's ten
  columns: Licence ref, Holder, Type, Scope / territory, Package / plan, Status, Renewal, Agreement, Programs and
  Attention. Each chip shows its family's count over the whole registry when the read has it.
- **Holder filter.** Clicking a holder narrows the registry to that holder (`?holder=user:<id>` or `entity:<id>`),
  shown as a removable "Holder:" chip.

**Where this departs from the canvas.** L36 draws All selected. Here the bare address opens on Operator / territory,
because the registry read does not carry what HQ works from on that ledger every day: Needs HQ, request counts,
coverage and the renewal pipeline. Opening on All would hide them behind a click. All is one click away and is a
link (`/admin/licences?family=all`). The owner can reverse this with one constant (`DEFAULT_FAMILY` in
`licenceRegistryModel.js`):

- **A** (built): keep Operator / territory as the default.
- **B**: open on All, as the canvas draws, and reach the operator ledger through its chip.

### 2. No franchise field on a user row

The Worker sends a user row with no `territory` key (D5060 §1). Its Scope / territory cell is drawn empty and heard
as "Not applicable", never "Not recorded" (L36's note). Its Programs cell opens the licence, because the ledger read
does not expand entitlements (D5059). The Worker's reason for that was stale ("#5059 derives them", written before
#5059 merged); it now says the ledger does not expand them and the detail reads them.

### 3. The user licence detail (L37, L37B)

A user row opens `/admin/licences/registry/user/:uid` (`licences/UserLicenceDetail.jsx`, route module
`routes/adminLicenceRegistry.jsx`).

- **Address.** Three segments under Licences, as Program access's `/admin/licences/programs/licence/:uid` has. Two
  segments (`/admin/licences/user/:uid`) would share a shape with `/admin/licences/:uid/:section`, and the route
  guard (`admin_route_reachability.test.mjs`) refuses an ambiguous door.
- **Sections:** Overview, Programs, Agreement, Billing and History, in the URL as `?section=`. The territory tabs
  (Terms, Access, Operations) are not reused.
- **Overview:** holder, type, status and since when, renewal, the account (or Not recorded), the programs in force
  (key entitlements), and attention.
- **Programs:** D5059's table (`ProgramsTable`), read-only. Grant changes stay on Program access, which this section
  links to.
- **Agreement:** the primary (executed before awaiting signature), then amendments and history, then the related
  package and program agreements. Each row opens the same canonical record in Contracts
  (`/admin/contracts/agreements/doc/:uid`): for a user licence agreement that is its envelope uuid (D5060 §3), which
  the Contracts read resolves.
- **Billing** is drawn only when the licence has commercial terms. None is recorded on a user licence today, so it is
  left out, not drawn empty (L37B).
- **History:** the lifecycle events (D5060 part 2), newest first.
- **States.** A section the database lacks is Not recorded with the Worker's reason; a section that fails to read is
  Unreadable, and the rest of the licence still answers. An operator licence's uid here goes to its own page; an
  unknown uid says so.
