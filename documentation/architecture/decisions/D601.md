## D601 — The formation packet and the state filing are recorded by an Axal admin, by hand

**After an incorporation is paid, an Axal admin moves the order on in HQ in two
recorded steps: "Packet ready", with the packet attached, then "Filed with the
state", with the date.** Slot S08, issue #998, 2026-10-06, from the owner's
answers 1A and 2A on #998. Migration 411.

### What the owner chose

- **1A:** an Axal admin, by hand. There is no vendor and no new dependency.
  The e-sign assembler (#1001) can later replace the "Packet ready" step
  without changing the screens.
- **2A:** the deck share sheet keeps what #1074 shipped. Changing the expiry
  withdraws the link that is on screen. No change here.

### Before this

D367 found that after payment the Worker moved an order to
`packet_processing` and built nothing. Nothing ever set `packet_ready` or
`filed`, so every screen said the packet had not been built.

### The two steps (`routes/admin_incorporations.ts`, `/api/admin/incorporations`, `requireAdmin`)

- **`POST /:id/packet-ready { document_id }`**
  - Moves `paid` or `packet_processing` to `packet_ready`.
  - The document must belong to the order's own project.
  - Stores `packet_document_id`, `packet_ready_by` and `packet_ready_at`.
- **`POST /:id/filed { filed_on }`**
  - Moves `packet_ready` to `filed`.
  - The date must be a real calendar date. It cannot be in the future or
    before the day the order was paid.
  - Stores `filed_on`, `filed_by` and `filed_recorded_at`.
- **Each step is one conditional UPDATE.** The status it moves from is part of
  the WHERE clause. A second press, or two admins pressing at once, changes
  the row once, and the other call gets 409.
- **Each step is recorded through `logAdminAction`** as
  `incorporation_packet_ready` or `incorporation_filed`, with the acting
  admin.
- **`GET /`** lists the paid orders, each with its project's documents to
  choose the packet from.

Nothing here assembles a packet or files with a state. It records what the
admin did.

### What the founder sees

- **`GET /legal/incorporate/orders` and `/incorporate/status`** now return
  `packet_document_id` and `filed_on`.
- **The Lab Incorporate tracker:**
  - a filed order is "Submitted to {state}", with "Filed {date}";
  - a ready packet is still only "Documents prepared".
- **The status badge** has "Filed with the state".
- **The success page** says what was recorded. It no longer claims a packet
  link "has been emailed to you", because nothing emails one.
- **`PAID_STATUSES` includes `filed`**, so a filed order still counts as paid.
  The co-founder agreement's order check reads that one list.
- **Payment-status polling stops at payment.** The packet now waits on an
  admin for days, and before this the poll would have timed out into a false
  "something went wrong" after five minutes.

### Refunds

`packet_ready` joins `packet_processing` and `filed` in the statuses that stop
a refund (`admin_billing.ts`).

### HQ

The Spin-Out Lab page gets a "Formation orders" tab
(`AdminFormationOrders.jsx`). It offers each order only its next step:
- no document is preselected;
- no date is filled in;
- a project with no documents says so instead of offering the step.
