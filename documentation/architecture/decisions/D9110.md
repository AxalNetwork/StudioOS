## D9110 — Pipeline: the shared opportunity sheet opens from every zone, and See all lists the feed (#9110)

- **Status:** built 2026-11-27 for #9110 (slot S16), part of #5128 (redesign wave, gap g26). Canvas `Pipeline v2` (D4838), board PP-6 "Shared opportunity sheet" (frames PP08, PP08m) and board PP-0 frame PP02 / PP02m (Recent movement).
- **Builds on:** D4838 part 8 (#5934, `OpportunitySheet.jsx`), D4838 part 9 (#5943, Recent movement from the feed), D5942 (`GET /api/partner/pipeline/activity`, `cloudflare-worker/src/routes/partner_pipeline.ts`), D1317 (`frontend/src/ui/Sheet.jsx`). No Worker change and no new client method: every read was already mounted.

### What was there

`OpportunitySheet` opened in one place, Leads' Draft proposal. Proposals, Negotiations and Retainers each held an opportunity's id in their own sheet, and Recent movement named one on each row, but none of them could open the joined view. D4838 part 8 listed this as "Not yet opened from a zone". D4838 part 9 listed two items as Not built: "A link from a movement row to its opportunity sheet" and "A 'See all' for the feed".

### The decision

1. **Open opportunity in every zone sheet.** Each zone sheet draws **Open opportunity** beside its ×: `ProposalSheet` in `ProposalsZone.jsx`, `NegotiationTermsSheet.jsx` (through `Sheet`'s `headerActions`) and `RetainerSheet` in `RetainersZone.jsx`. The action closes the zone sheet and opens `OpportunitySheet` with the id that zone holds. Proposals passes `{ quoteId }`. Negotiations passes `{ quoteId }` and opens on Terms. Retainers passes `{ engagementId }`. The join is by id, never by name, so the header and stage tracker are the same as when the opportunity is opened from Leads. Only one sheet is open at a time. Closing the opportunity sheet returns focus to the zone row that opened the zone sheet. Retainers closes its sheet the way × does, so the `?engagement=` focus parameter goes with it, and `backToStudio` is unchanged. The zones have no refresh counter, so none is passed as `refreshKey`.
2. **Recent movement rows open the sheet.** `activityRows` now carries `needId` (the event's `opportunity.need_id`). A row with a need is a 44px button that opens `OpportunitySheet` with `{ needId }` on its Activity tab. A row without one stays plain text, because there is nothing to open. The root still asks for and shows `MOVEMENT_SHOWN` (8) events.
3. **See all is a sheet on `/pipeline`.** See all appears under Recent movement only when the feed answered with rows. It opens an **All movement** sheet (`ui/Sheet.jsx`, `phone="full"`, 560 wide). That sheet reads `partnerPipelineActivityApi.list({ limit: FEED_ALL_LIMIT })`, where `FEED_ALL_LIMIT = 200` is the Worker's `LIST_PAGE_MAX`, and draws the rows with the same `activityRows` words. A row there closes All movement and opens that opportunity's sheet.
4. **Its states.**
   - Loading: a pulse skeleton.
   - An answered empty read: "Nothing has moved yet.", followed by the root's own population sentence (`MOVEMENT_NONE`, shared).
   - A failed read: "Unreadable. The lifecycle feed could not be read; this is not evidence that nothing moved." with **Try again**.
   - A full page: "Showing the latest 200 events." The feed has no cursor, so the sheet does not claim the list is complete. `allMovementView` decides this from the Worker's raw item count (`items.length === FEED_ALL_LIMIT`), not from the drawn rows, because `activityRows` leaves out a kind it has no words for.
5. **No new address.** There is no `/pipeline/activity` route. A new address would need a zone in `shellConfig` and a route line, and the canvas draws neither.

This closes D4838 part 8's "Not yet opened from a zone" and D4838 part 9's two Not-built items.
