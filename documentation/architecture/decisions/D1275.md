### 1. The list (PRM1, PRM1m)

**The four tiles:**
- **Active codes:** the active count, of all, with each other state counted. Those counts come from the list read and follow its search and Applies to; when either narrows the list, the tile says "under these filters".
- **From the usage read's last 30 days (D1274):**
  - redemptions;
  - the discount given, each currency on its own;
  - codes ending within 14 days, by name.
- **A tile whose read failed** says "Not recorded" and why, never 0. A 0 the Worker counted is drawn as 0. No redemptions in the window reads "None given".

**The chips, filters and sort:**
- **Chips:** All and the six states (Active, Paused, Ended, Expired, At its cap, Switched off), each with its count.
- **Search, Applies to and Sort:**
  - Search covers the code or the name, from two characters, as the Worker searches.
  - Applies to is Plans, Chosen products or Every product.
  - Sort is newest, oldest, code or most redeemed.
- **In the address:** `?state=&applies=&q=&sort=&page=`, written by `filterSearch`. A drawer's address keeps them, and closing the drawer returns to the same list.

**Each row:**
- the code, opening its drawer, with its name;
- the discount, in major units;
- what it applies to: plan names with the interval, product names, or "Every product". A product list the Worker could not read says "Product list unreadable", never "Every product".
- the duration;
- Redeemed, StudioOS's count, "37 of 200" or "21, no cap". A count the row does not carry is "Not recorded".
- the end, with "in N days" inside 14;
- the state;
- the day it was made.

**The row menu by state (PRM1m):**

| State | Menu |
|---|---|
| Active | Open, Copy code, Pause…, End now…, Replace with a new code…, Copy as a new code |
| Paused, or switched off before part 2 | the same, with Resume… in place of Pause… |
| Expired, At its cap | Open, Copy code, End now…, Replace…, Copy as a new code |
| **Ended** | **Open and Copy as a new code only. It never resumes: Stripe deleted its coupon.** |

**The pager:** 25 to a page. The canvas's Discount filter is not drawn: the list read takes no discount filter.

### 2. The drawer (PRM2)

`/admin/platform/promo-codes/:id` opens a lightbox over the list. It reads the code itself from the new `GET /api/admin/promos/:id` (§6), so a code on another page of the list, or a shared link, opens too.

**Overview:**
- **Facts:** discount, applies to, duration, limit (cap, once per member, first purchase only), the end in UTC, and the note.
- **What a member pays:** each price in scope, before and after, from the catalogue.
- **Redeemed:** StudioOS's count beside **Stripe's own count** (D1274's `stripe.times_redeemed`, which also counts subscriptions). It says "Not read" with why when Stripe is not configured or could not be read.
- **"What can change.":** the canvas's line on what HQ can still change.
- **Banners:** a paused code shows when it was paused and its reason. An ended one shows the day, its reason and what replaced it, and that it can never be resumed or reused.

**Redemptions:** the newest hundred StudioOS recorded: when, member, bought, paid, saved and source. A field a redemption from before migration 631 does not carry says "Not recorded". The tab's count is Stripe's when read.

**History:** read when its tab opens. Created, Changed, Paused, Resumed and Ended, with who and when and the terms a creation set. D1274 keeps a reason's text out of this read on purpose, so the history shows none; the code's latest reason is shown on Overview.

**Actions:** the drawer offers the same changes as the row menu, plus Edit name and note…. An ended code offers Copy as a new code alone.

Each tab is its own read: one failing says so with Try again and never blanks the others.

### 3. New code in five steps (PRM3, PRM4)

`promoWizard.js` holds the rules; `PromoDialogs.CodeWizard` draws them.

1. **Applies to:**
   - **Plans:** each plan any live catalogue product sells, keyed as the Worker's `planKeyOf` keys it. Monthly, yearly or both: monthly by default (#2381 question 3), and for the whole code, because the Worker stores one interval list per code.
   - **One-time products:** live products that sell no plan.
   - **Every plan and product.**
   - A token pack or an archived product is never offered.
   - If the catalogue (`api.adminCatalogList`) cannot be read, the step says so, and only Every plan and product can be chosen.
2. **Discount:**
   - **Percent:** 1 to 100. At 100%, the step says the purchase is free and a one-time product unlocks at once.
   - **An amount in major units:** "10" or "10.50", sent in minor units, with the currency picked from USD, EUR or GBP.
   - **What a member pays,** before and after. An amount off is drawn only against prices in its own currency.
3. **Duration:** first payment only, for N months (1 to 36), or every payment. The step is skipped when only one-time products are in scope: a one-time purchase is discounted once.
4. **Limits and dates:**
   - total redemptions (blank for no cap);
   - once per member; first purchase only;
   - the day it ends, sent as 23:59:59 UTC and never in the past;
   - the code: 3 to 64 letters, digits, `_` or `-`, uppercased, with Generate;
   - the name and the note.
5. **Review:** the terms and what a member pays. Create code sends one `POST /api/admin/promos`.

Each step says what it is missing before Next. The Worker checks everything again.

### 4. Edit and replace (PRM5)

- **Edit name and note** changes those two alone (`PATCH /:id`). The dialog says Stripe keeps the terms fixed and members see no change.
- **Replace** walks the five steps from the old code's terms, never its code: the old code is refused as already taken. A reason is required.
  - It sends `POST /:id/replace` (D1272), which makes the new code and then ends the old one.
  - **If Stripe made the new code but would not end the old one** (502, `old_ended: false`), the dialog says the new code was created, the old one could not be ended, and both work at checkout. It is never reported as a clean replace.
- **Copy as a new code** starts the five steps from a code's terms, with a new code to type.

### 5. Pause, resume and end (PRM6)

Each opens an in-page dialog that says what it does in Stripe, for members and in the record. Never `window.confirm`.

- **Pause** needs a reason (`PATCH {action: 'pause', reason}`).
- **Resume** takes an optional one, and says how many redemptions are left by StudioOS's count.
- **End now:**
  - needs a reason, and the code typed to confirm;
  - sends `DELETE /:id {reason}`, which deletes the coupon and records the end;
  - an ended code opened here says it has already ended.
- **After each change,** the list and the drawer are read again, and the page says what happened ("Paused LAUNCH20.").

Every write needs TOTP and a recent step-up; `request()` asks for the code (StepUpModal), and each dialog says so.

### 6. Worker first: two changes

- **`GET /api/admin/promos/:id`** (`requireSuperAdmin`) answers `{ promo }` in the list's own shape (`rowToView`), or 404 `not_found`. The drawer needs one code that may not be on the list's page.
- **`applies=plans` filters** now that part 3 records plan scope. D1272 refused it with `applies_not_recorded` until then.
  - `plans` keeps a code HQ chose plans for.
  - `products` keeps a code that names products and no plan. A plan code's resolved products no longer count it as "products".
  - `all` keeps a code that names neither.
  - Every value is bound; `LIST_FROM` stays one fragment, as `sql-prepare-baseline.json` records.
