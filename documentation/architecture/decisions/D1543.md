### 1. The elements, from records, with no model

`services/decks/ventureElements.ts` answers each element of the picker that S1 keyed to `ventureElements`, plus the Team grid:

| Element | Read from | Block(s) |
| --- | --- | --- |
| `team_grid` | `cap_table_holders` rows with a `founder_role` (names and roles), and `sources.ts`'s `team.founders` | a `table`: Name, Role |
| `team_bios` | the same founders, and the team adapter's `team.skills` and `team.archetypes` | a `text` list, bound to `team.founders` |
| `use_of_funds` | `recordSources.ts`'s `use_of_funds_sections` (the recorded split) | a `table`, one bound cell per section above 0% |
| `round_terms` | `round_terms` (pre-money, post-money, dilution) and `round` (`raise.round_terms`, the instrument) | one `metric` per figure and a `text` for the instrument, each bound |
| `cap_table` | `raise.cap_table` and a count and a sum over `cap_table_holders` | a `table`: a header row and one Total row |
| `logo_wall` | migration 732's `deck_logos`, joined to the venture's kept `deck_images` | one `image` per permitted logo (`tag: 'logo'`, `logo_key`) |
| `interview_quote` | `quoteRetrieval.pickQuote` (D1556) | a `text` "“…” — <role>", with its `session_uid` |

Every block names its `element`, so `shareInclude.blockKept` judges it by `ELEMENT_GATES`. Every figure is a D896 binding with the Source and grade of `sources.ts`'s one mapping: `readSources` gains an `only` option, so an element reads just the adapters it needs, through the same code. Each answer carries `bindings` (key, label, value, unit, source, grade, date, record, snapshot) and `model: null`. **No model runs**: the service and the route import nothing from the AI router or the catalogue, and the test fails if they do.

**Team bios are record-only in v0.** The canvas draws "Team bios [Model A]", and the issue says that model comes from the rail's Venture records group (#3754). Writing bios with a model is a proposal like any other generated text, so it belongs with the several-area run (#3764); here a bio is the founder's name and role and the team's recorded skills and archetypes. This is a reading for the owner to confirm.

### 2. The gates are Worker refusals

A gate that does not pass answers `refuse(c, 409, { code, message })`: `error` is the code and `message` is the canvas's own line (dk-boards §3, pd9r). `deckV2Adapter.through()` now carries a refusal's `code` with its `reason`, so the surface can draw that line. The codes (`GATE_CODES`):

- `no_consent`: the picked line is not quotable under D1556's clause (recorded consent, consent to quote, the final transcript, the interviewee's own line, this venture). Line: "Only quotes from sessions with recorded consent can be used."
- `no_permission`: a logo whose customer has not given permission. Line: "[Customer name] hasn't given permission to show their logo." When logos are asked for by key, one unpermitted logo refuses the wall; unasked, the wall holds the permitted ones and is refused only when none is.
- `totals_only`: a holder-level view of the cap table (`detail=holders`). Line: "Totals only · never shown in shared links unless you include it".
- `not_included`: the cap-table summary was not included (`include=cap_table`). It is off by default, in the element read and in the one-click list. Same line.
- `subject_to_counsel`: round terms asked for without their label (`final=1`) while any term is not graded Reviewed. Line: "Proposed, subject to counsel" (`compliance.ROUND_TERMS_LABEL`). Otherwise the terms are placed with `label` and `proposed: true`, and D1546's `slideFootnotes` draws "Round terms: Proposed, subject to counsel." under the card in every format, because each figure is bound to a round-terms slot. `Reviewed` is counsel's approval (D1520); once every term carries it, the label is null and `final=1` passes.
- `quotes_not_switched_on`: D1556's index is not bound (`env.DECK_QUOTES`, owner decision L). The manual pick reads through `quoteRetrieval.ts`, so it stays off with D1556's own reason, "Quote retrieval is not switched on yet.", until the owner approves the `axal-deck-quotes` index.
- `pick_required`: a quote is the founder's manual pick, so the one-click list never places one.
- `not_recorded`: nothing recorded for the element. The line names the module that fills it. A slide with no data says so; it never draws a 0.
- `unreadable`: 503 when the records could not be read.

### 3. The logos store (migration 732)

`deck_logos` holds one customer logo per row for the venture: `logo_key` (`logo_` and 24 hex digits, the reference a block carries), `customer_name`, `image_uid` (a kept `deck_images` upload of the same venture), `permitted`, `permission_reference`, `permitted_by` and `permitted_at`. A CHECK makes `permitted = 1` impossible without a reference and a date, so the store itself refuses a bare permission. An unpermitted row can be stored while the founder asks, but it is never placed (`no_permission`) and never sent.

Routes: `GET`/`POST /api/decks/:id/logos`, `PATCH`/`DELETE /api/decks/:id/logos/:key`. A write needs write access to the venture, and a support session is refused. No reply carries a user id or an email.

### 4. Share links

`shareInclude.shareGatesFor` now reads the permitted `logo_key`s from `deck_logos` at share time, beside the quote consents. Before 732 it read an empty set. Withdrawing a permission therefore takes the logo off every link at once. Nothing else in the share path changed. The cap table already needed `include.cap_table` (off by default, `DEFAULT_SHARE_INCLUDE`), and then sends only its header and Total rows (D1507). A quote still needs its session among the consented ones. Every share read (`decks.ts`'s `/share/:token`, and `deck_grants.ts`) goes through `shareSlides` with these gates.

### 4a. Saves refuse them too

`services/decks/saveGates.ts` (`saveGateRefusal`) runs on both paths that persist a founder's cards: `PUT /api/decks/:id` (`routes/decks.ts`, after the cards are sanitized, before the image copy and the insert) and the working copy's `PATCH /api/decks/:id/cards/:uid` (`routes/deck_draft.ts`). It refuses with 409 and the same codes and lines:
- `no_permission`: a block carrying a `logo_key` that is not a permitted `deck_logos` row of the venture (a key never recorded included);
- `no_consent`: an `interview_quote` block whose `session_uid` is not a session with a quotable line, under `quotableLines`' own clause. The test holds the two clauses equal.

Nothing is written when a save is refused. A save with no such block reads nothing, and a gate whose store cannot be read does not pass. The module imports nothing at run time, so `routes/decks.ts` takes on no new module graph. Server-built cards (autofill, apply-method, the proposals' keep) carry no gated block; restore copies a version that was already saved.

### 5. Routes

`routes/deck_venture_elements.ts`, mounted at `/api/decks` beside `deck_typed_values.ts`, before `decks`:

- `GET /:id/venture-elements[?include=cap_table]`: every element at once, each `{ available: true, … }` or `{ available: false, code, line }`. The one-click run fills [Team], [Use of funds] and [Round] from it and leaves out each gated item whose gate does not pass, with no placeholder.
- `GET /:id/venture-elements/:element` with `include`, `detail`, `final`, `logos` and `segment`: one element, or its refusal.
- The logo routes in §3.

Reads are open to whoever may read the deck (`projectOwned`, as the other deck reads). Every statement is a bound literal.
