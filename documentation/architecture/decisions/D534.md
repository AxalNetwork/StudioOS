## D534 — the company directory is searched, filtered, sorted and paged on the server, and a company reads its evidence and peers

**The Worker half of GitHub issue 1079, slot S07.** The two company-directory
routes are rebuilt on a new service, `services/researchCompanyDirectory.ts`,
with their tests. The directory and company pages wait for the owner to
approve the Claude Design canvas (`needs-design`), so this decision covers the
routes only. No migration: no query here needs an index that 300 rows would
notice, so migration 377 is not used.

**What was true on main (`3ca9d291`).**
- `GET /api/research/company-directory` took `q`, `country` and `sector`. It
  returned up to 1,000 rows with no offset and no total.
- `GET /api/research/company-directory/:uid` returned the ten identity fields
  and nothing else. Nothing called it.
- Nothing read the 24 columns that migration 375 declares (D531), or migration
  370's four `company_*` tables.

**The list.** `GET /api/research/company-directory` keeps every field it
returned before, and adds:

- `q`: a case-insensitive substring of the name or the website. `%`, `_` and
  `\` match themselves (`LIKE … ESCAPE '\'`), and every value is bound.
- `country` (exact, as before), and `sector` through the route's alias map, as
  before. `MarketSectorProfile` (#1080) calls it with `sector`.
- `founded_from` and `founded_to`, inclusive.
- `has=funding|revenue|headcount`, comma-separated. The metric must be
  recorded (`funding_total`, `revenue`, `employee_count`).
- `sort`: `name` (the default), `founded` or `funding`, with `-` for
  descending. A company without the value sorts after every company that has
  it, in either direction.
- `limit` (25 by default, 100 at most), `offset`, and `total`, which counts
  every match.

A bad value is a coded 400 that names the field. It is never a silent default.

**Funding is ranked within one currency, never across.** Rows are ordered by
currency first. On 4 October every recorded `funding_total` is USD (16 rows),
so this changes nothing today, and it keeps a second currency from being
ranked against the first. **Revenue is not a sort**, because production's 27
recorded revenues are in five currencies (USD 19, EUR 5, AUD, CHF and CZK one
each). Those counts are aggregates only; no row was read.

**The company.** `GET /api/research/company-directory/:uid` returns:

- `item`: the same ten identity fields as before.
- `metrics`: funding total, last round, valuation, revenue, headcount and
  market share. Each one has its value, currency, source name, source URL
  and as-of date. A metric with no record reads `status: 'not_recorded'`,
  `reason: 'Not recorded'`, and is never a zero. The as-of date is the
  metric's own (`revenue_as_of`, `employee_as_of`, `valuation_as_of`,
  `market_share_as_of`, `last_funding_date`), or else `metrics_updated_at`.
- `financials`, `employment`, `sources` and `funding_rounds`: what migration
  370's tables hold for the company. Each has its own `status`. A failed read
  is `unreadable` on that table alone, and is never shown as a company with
  no rows.
- `peers`: up to eight other companies in the same sector (compared trimmed
  and case-insensitively). Companies in the same country come first, then
  the rest by name. A company with no sector reads
  `peers.status: 'not_recorded'` with the reason.

A failed read of the company itself is a 503 `Unreadable`, and so is a failed
read of the list. Neither is ever an empty answer.

**The key, checked.** Migration 370's tables carry an INTEGER `company_id` and
no foreign key. It is `research_company_directory.id`. On production every
row matches one: 19 of 19 financials, 40 of 40 employment rows and 300 of 300
sources; `company_funding_rounds` is empty. That was counted on 4 October
without reading a row. The response names the key in `evidence_key`.

**One line outside this issue's files.** `MarketSectorProfile.jsx` (#1080's
page) drew its "Open company directory (N matched)" from the length of the
list it got back. With the list now paged, that would read 25 for a sector
with 251 companies. It now asks for `limit: 24`, the 24 it draws, and reads
`total` through `lib/companyDirectoryPage.js`. Nothing else on that page
changed.

**Not built here, waiting on the canvas:** the directory page (search box,
filters, sort, the "1–25 of 300" count, pages, and the loading, empty and
Unreadable states); the company page; removing `companyDirectory.json`; the
competitor-analysis button; the GTM lookup; and a way into the saved
analyses. The existing `api.research.companyDirectory(params)` already passes
any query parameter, so the new filters need no new client method yet. The
`lib/api/researchCompanies.js` module will come with the page that calls it.
