## D5608 — Trace test dependencies and wall time by commit (#5608)

Part of #5600. Test files are the unit of evidence. The suite runner appends an opt-in `NODE_OPTIONS=--import` preload when `TEST_TRACE_DIR` is set. Node 22.23.4 ran the preload and both existing loader entry points, `_deck-loader.mjs` and `_ts-loader.mjs`, with the test-file context present. An ordinary PR run leaves the preload off.

The trace records repo-relative file reads, directory and glob roots, resolved modules, successful and unsuccessful existence probes, SQLite opens, executable names, wall milliseconds and the exit code. It drops outside-repository paths and `node_modules` and never records environment variables, arguments, file contents or SQL. Direct Node children carry the test path even with an explicit child environment. A non-Node subprocess or unsupported observation marks the test opaque. An opaque trace is still usable as timing evidence and cannot prove that its dependency list is complete.

The merger reads each shard directory independently, unions dependencies across processes and gets wall time and exit code from the test-file processes. Both outputs are ordered deterministically. A child-only trace is opaque and its test is listed as untraced. Counts for recorded, opaque, untraced and invalid records are printed at merge time. A test with no trace is unknown.

The CI integration follows #5601. It is to upload a single `test-deps-<sha>` artifact per full merge-group or push run for 30 days. A push that reuses a successful exact-SHA merge-group suite has no new traces and uses that merge-group artifact. The artifact job is advisory and outside the required gate. Coverage, opaque count for a full run, and three paired frontend and Worker shard timings are pending. #5609 and #5610 consume the artifacts after validation.

### The CI wiring (published 2026-11-16, #5608)

`.github/workflows/ci.yml` now carries the integration described above.

- **`suite`.** The existing `test-drift-parts.mjs` step keeps its run line.
  - It gets `TEST_TRACE_DIR` as step `env:`, set to `$RUNNER_TEMP/test-traces` on `merge_group` and on a push to `main`, and empty otherwise. Empty leaves the tracer inert.
  - A pull request run never traces. Neither does a push to a `bench/runners-*` branch: `runner-benchmark.yml` mirrors the suite steps byte for byte (`runner_lanes_5611`), so its push is excluded by ref.
  - Each part uploads `test-traces-<part>` with `if: always()`, so a failed part still reports. It keeps them 3 days, and the upload uses `continue-on-error`.
- **`test-deps`** is a new job, named "test deps".
  - It runs after `suite` on `merge_group` and a `main` push, when the suite ran.
  - It downloads every `test-traces-*` artifact and runs `merge-test-deps.mjs` with the commit SHA.
  - It uploads `test-deps-<sha>` (`test-deps.json` and `test-timings.json`) for 30 days.
  - Neither `landing` nor `gate` needs it, so a failed merge loses only the artifact.
  - It runs in the queue, which `merge_queue_ci_4107` names as its one advisory exception. A push that `verified` skips has no traces of its own, so the queue run on the same SHA is the one that makes the artifact.
- **Effect on the suite plan.** The `plan` job already reads the newest `test-deps-*` artifact on `main` (`download-test-timings.sh`). Until now it found none and used equal weights. Once this lands, the next run's parts are packed by measured wall time.
- **Tests.** `test_tracer_5608.test.mjs` pins the wiring:
  - the trace env applies only on the queue and `main`, and the run line is unchanged;
  - the upload runs on `always()`, with its name and path;
  - `test-deps` needs `suite`, carries the event condition, the merge command, the artifact name, both files and 30 days;
  - no job needs `test-deps`.

  `copilot_setup_steps` now ignores artifact uploads, as it ignored downloads. `ci_suite_parts_4130.test.mjs` is unchanged.

Overhead: the previous holder measured +1.9% (frontend) and +2.9% (Worker) wall time, from local paired runs. That is under the 5% limit. Hosted medians and the coverage proof can only be recorded after this lands:
- a `merge_group` run whose `test-deps-<sha>` covers at least 99% of test files;
- that run's opaque count.

Both go on #5608 and here.
