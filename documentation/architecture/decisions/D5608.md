## D5608 — Trace test dependencies and wall time by commit (#5608)

Part of #5600. Test files are the unit of evidence. The suite runner appends an opt-in `NODE_OPTIONS=--import` preload when `TEST_TRACE_DIR` is set. Node 22.23.4 ran the preload and both existing loader entry points, `_deck-loader.mjs` and `_ts-loader.mjs`, with the test-file context present. An ordinary PR run leaves the preload off.

The trace records repo-relative file reads, directory and glob roots, resolved modules, successful and unsuccessful existence probes, SQLite opens, executable names, wall milliseconds and the exit code. It drops outside-repository paths and `node_modules` and never records environment variables, arguments, file contents or SQL. Direct Node children carry the test path even with an explicit child environment. A non-Node subprocess or unsupported observation marks the test opaque. An opaque trace is still usable as timing evidence and cannot prove that its dependency list is complete.

The merger reads each shard directory independently, unions dependencies across processes and gets wall time and exit code from the test-file processes. Both outputs are ordered deterministically. A child-only trace is opaque and its test is listed as untraced. Counts for recorded, opaque, untraced and invalid records are printed at merge time. A test with no trace is unknown.

The CI integration follows #5601. It is to upload a single `test-deps-<sha>` artifact per full merge-group or push run for 30 days. A push that reuses a successful exact-SHA merge-group suite has no new traces and uses that merge-group artifact. The artifact job is advisory and outside the required gate. Coverage, opaque count for a full run, and three paired frontend and Worker shard timings are pending. #5609 and #5610 consume the artifacts after validation.
