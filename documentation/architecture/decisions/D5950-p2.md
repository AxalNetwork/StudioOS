## D5950 part 2 — Revenue per subsidiary and AI margin per licence join the read model (#5950)

- **Status:** built. It finishes the Worker half of slice 6 of #5038.
- **Builds on:** D5950 (the read model and its envelope), D5947 (branch reports carry a measured gross, its state,
  source and as-of time), D5948 (AI holds and usage rows carry their licence, `licenceAiPeriod`), D762 (`tokenMargin`),
  D5039 (`?period=YYYY-Qn`).
- **No migration.** Both metrics read stores #5947 and #5948 built.

### What changed

The two metrics D5950 left `not_available`, with `pending_issue` 5947 and 5948, now read their stores
(`cloudflare-worker/src/services/revenueReadModel.ts`). They use the same envelope as the other four. No metric is
`not_available` now. The state stays in the vocabulary for a store a later slice adds.

The rest of `GET /api/admin/revenue/summary` is unchanged. That includes `temporal`, `quarter`, `current_period`,
`period_requested`, `read_at` and the top-level `revenue_per_subsidiary_*` and `token_pl_per_subsidiary_*` sentences
the built page reads. The page will move to `metrics` in the frontend half of slice 6.

### `revenue_per_subsidiary`

| Field | Value |
| --- | --- |
| source | `subsidiary_usage_reports` for the requested `YYYY-Qn`: each branch's report, per stream |
| values | `by_licence`: one line per licence that is not terminated, plus any licence that reported without being one. Each line lists its streams with `gross_cents`, `currency`, `is_estimate`, `state`, `reason`, `source`, `source_as_of` and `reported_at` |
| currencies | the currencies of the streams that carry a figure |
| last reconciled | always null. HQ reconciles nothing against a branch report. Each stream's `source_as_of` is when the branch read its ledger, which is not a reconciliation |
| incomplete rows | `not_reported` licences, plus streams whose figure is missing or partial, counted by state (`incomplete`, `not_recorded`, `unreadable`, `no_state` for a row from a build before D5947, `estimated`) |
| coverage | `unknown`: migration `202611161359_5947_usage_report_source` began storing state and source, and the database does not hold when it was applied |

Rules:

- **A figure is only what the branch measured.** A stream whose state is `not_recorded`, `not_available` or
  `unreadable` reads null, whatever number is stored. A stream with no figure has a null `currency`, so an unknown
  amount never carries a currency.
- **`not_available` is not a gap.** It marks a stream the branch has no store for, by design (D5947: licence fees and
  token margin on a branch). Every other stream with no figure is counted.
- **Nothing is totalled.** No sum is made across streams, licences or currencies.
- **States.** The metric is `not_recorded` when no branch reported the period (`values` null). It is also
  `not_recorded` when reports arrived but no stream carries a figure. That is every branch today, because branch
  ledgers are empty by design (D5947). In that case `values` still lists each licence's streams with the branch's own
  reason, so the page can say why per licence. The metric is `incomplete` when figures are shown and gaps are counted,
  and `complete` when there is no gap. A failed read makes it `unreadable`.

### `ai_margin_per_licence`

| Field | Value |
| --- | --- |
| source | D5948's `licenceAiPeriod` over this Worker's database: settled member holds by `licence_uid`, with `tokenMargin`'s arithmetic |
| values | `unit: 'microusd'`, `by_licence` (runs, runs not recorded, included, billed, cost, margin), `unattributed_runs`, `pre_migration_runs` |
| currencies | `['USD']`. Provider cost is USD by its own name, and top-up spend is micro-USD |
| last reconciled | always null. Holds are settled by the Worker and nothing reconciles them against the provider's invoice |
| incomplete rows | `unattributed`, `not_recorded` (runs with no usage row to cost them) and `pre_migration` (left out when the start row cannot be read, never 0) |
| coverage | `ai_licence_attribution_start.started_at` against the quarter. SQLite's `datetime('now')` form is read as UTC |

Rules:

- **No zero for an uncosted licence.** `licenceAiPeriod` reports billed and cost as 0 for a licence none of whose runs
  has a usage row (its `COALESCE`). The metric reads them as null, as it already does for margin.
- **HQ.** HQ's own runs name no licence (U1). A branch's runs are on the branch's database, and its report to HQ
  carries no AI figure (D5947: `token_margin` is `not_available`). So at HQ this metric is `not_recorded`, with the
  unattributed runs counted and the reason saying where the branch figures are. It is never a zero per licence.
  Bringing per-licence AI figures to HQ needs the branch report to carry them. That is a later slice of #5038, not
  this one.
- **States.** `unreadable` on a failed read, such as before migration `202611150131`. `not_recorded` when attribution
  began after the period, or when no run in the period names a licence. `incomplete` when there is any gap, or when
  coverage is partial or unknown. `complete` otherwise.

### Both

- **`?period`.** Both metrics read the requested quarter, and a bad period is still 400 before anything is read.
- **One failure at a time.** Each metric catches its own failure, so one unreadable store leaves the others answering.
- **No Stripe call.** Every read is D1.
- **Super Admin only.** Both metrics stay behind the route's `requireSuperAdmin`.
- **No new interpolated SQL.** The two new statements bind every value, and the `sql-prepare` baseline is unchanged.

### Tests

`cloudflare-worker/test/revenue_read_model_5950.test.ts` covers each metric with:

- an empty store;
- a store with only unmeasured or unattributed rows;
- a partial store;
- a complete store;
- a period before coverage (AI);
- an unknown start (AI);
- a failed read.

`admin_revenue_period_5039.test.ts` checks both metrics through the route. They follow `?period`, make no network
call, and leave the fields the built page reads unchanged.
