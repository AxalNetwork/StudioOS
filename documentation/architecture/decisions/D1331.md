### 1. The reads

Each card reads on its own, so one failed read costs that card only (`McpServicesPage.jsx`'s `useRead`). The reads are:

| Read | Decision | Card |
|---|---|---|
| `GET /api/connectors/assistants` | D666 | the endpoint's state and who can call (a 404 is the MCP server switched off) |
| `GET /api/developer/keys` | D841 | the keys line and the callers (a 404 is keys switched off) |
| `GET /api/developer/limits` | D849 | Limits |
| `GET /api/connectors` and `/available` | D751, D753 | Services, named from the catalogue |
| `GET /api/connectors/health` | D848 | each service's health pill and its last ten checks |

- **`connectorsApi.health`** is added to `lib/api/connectors.js` for D848's existing route. It is a client for a route already mounted, so there is no drift.
- **The tool list waits.** D846's tool read has not landed, so Card 3, the tools, stays `BuilderSection`'s `Wait` ("Not read here yet"). Nothing here draws a tool, a price or a limit the Worker did not send.

### 2. The pages (`frontend/src/pages/account/builder/`)

- **`mcpServicesModel.js`** holds the rules as pure functions:
  - **who reads** (`audienceOf`):
    - a Founder, or a profile with an admitted Spin-Out Lab project, owns companies the tools reach;
    - an Investor, Advisor, Operating Partner or Admin owns none, and reads "Your profile owns none, so an assistant or key could connect but reach nothing.";
    - an Explorer reads "Connectors open once your profile is set.";
    - a Super Admin also gets the line to HQ › Integration keys;
  - **the endpoint and keys** (`keysSummary`);
  - **an assistant row** (`assistantRow`): "Unrecognised assistant" for a missing name, and "No call recorded" for a missing last call, never a guessed date;
  - **D848's health words** (`healthPill`) and the ten-check strip (`checkStrip`);
  - **the services rows** (`serviceRows`), in Connectors' own state words, and `filterServices` for MCPX2's search and filters;
  - **the limits** (`limitRows`), from D849's read only;
  - **`NOT_YOURS`**: the words for a drawer address that is not this member's.
- **`McpServicesPage.jsx`** draws the cards:
  - MCPX1 for a Founder, MCPX6 for a profile that owns nothing, and MCPX7 for an Explorer and a Super Admin;
  - MCPX8–MCPX10: empty, loading, error with Try again, and switched off;
  - **Revoke** opens an in-page dialog (`RevokeDialog`), never `window.confirm`.
  - Connecting, disconnecting and every key action stay on their own pages: this page links to them.
- **The drawers** follow D1317. A drawer's address opens it as the shared `Sheet` over the page, 560px, with the page still drawn under it. Closing goes back to `/account/builder`.
  - **MCPX3, `/account/builder/services/[key]`:** the connection, its permissions, its companies and its health checks.
  - **MCPX5, `/account/builder/assistants/[id]`:** where the assistant signs in from, what it may do, its companies, and its last call or "No call recorded".
  - An address that is not this member's says so (`NOT_YOURS`).
- **`BuilderSection.jsx`:**
  - MCP and services is `McpServicesPage`, with the tools' `Wait` in Card 3's place;
  - the service and assistant drawers are the page's own, and the section's `Sheet` stays for keys;
  - the waits D1331 replaces (limits, services and the two drawers) are gone from `WAITS`;
  - the tools' wait now says what it will draw.
- **The phone (MCPX12):** D1315's tabs, with the cards in one column.
