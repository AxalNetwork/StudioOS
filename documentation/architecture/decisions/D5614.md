## D5614 — A shrink-only test clock inventory and guard (#5614)

A new real-clock dependency in a test fails test:guards. The scanner follows
package.json's frontend, Worker, meeting-bot and retention globs, plus adjacent
underscore helpers. Existing Acorn/acorn-jsx dependencies parse syntax; Node's
stripTypeScriptTypes strip mode preserves TS offsets and comments. Strings,
regex literals and comments are not code, while template expressions are.
No TypeScript compiler API or new dependency is needed.

Date.now, an argless Date constructor, and a bare Date function call count as
real reads unless the file actually enables mock.timers for Date. Bare Date
function calls always read now, even with arguments. Awaited fixed setTimeout
sleeps count unless setTimeout is mocked. Numeric expressions and const numeric
delays count, including node:timers/promises aliases. A deadline-bounded polling
loop is allowed. The file-wide mock exemption follows the issue's specified
rule; it does not claim every read happened after the mock was enabled.

A same-line line comment may opt out with exactly clock-ok: relative, deadline,
unique-id or duration. Any other reason fails, and an opt-out on a different
line or inside string data grants nothing. This is a static tripwire, not proof
that every possible indirect clock dependency is frozen.

The sorted inventory contains 943 rule/file pairs: 482 date and 461 sleep;
20 pairs are in underscore helpers. It records the actual first parsed scan,
not a target count extrapolated from the issue's earlier regex estimate.
An unlisted finding names file, line and rule. An entry with a removed or clean
file fails. Migration work in #5504 removes entries here and keeps no second list.

### Bootstrap order

Main has no test-clock allowlist yet. The issue explicitly requires:
"fail if that list cannot be read". A PR adding both a seed and its guard would
therefore fail its own no-growth check, correctly. There is no first-run bypass.

1. The seed PR adds this decision and the starting inventory only. Review it
   and merge it to main first. It does not activate the new guard.
2. The implementation PR adds the guard, fixture tests and its test:guards
   command. After the seed merge its existing exceptions match origin/main.

Both are part of #5614 until the implementation lands. The owner merges;
this agent never pushes to main or merges either PR.

### CI ratchet

In CI, every event except a push to refs/heads/main fetches origin main at
depth one into the local origin/main tracking ref, then reads its allowlist.
Fetch/read failure fails closed. The explicit tracking ref handles Actions'
shallow checkouts; it never updates remote main. The forced local refspec is
needed when the depth-one fetch cannot establish fast-forward ancestry.
Any current entry absent from the fetched main list fails. Local runs enforce
findings/stale entries; main pushes enforce those same rules and are exempt
only from the cross-base no-growth comparison.

### Validation

Fixtures prove each rule, real mocks versus mock text, comments/strings,
explicit dates, four opt-outs and invalid reasons, stale/missing entries,
growth versus shrink, and both PR and merge_group event predicates. A real
local bare Git repository and a depth-one checkout prove fetching the list and
failing when it is deleted on main. Mutation outcomes, guard-chain/build/drift
results and the hosted bootstrap limitation are recorded in the PR.
No change to github-alerts.yml, ci.yml, shifted-time execution or production.
