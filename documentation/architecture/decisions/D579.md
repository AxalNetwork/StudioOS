## D579 — The company's EIN: stored encrypted, read by its founders and admins only

**A Lab startup's EIN is stored, encrypted at rest. Only the startup's
founder, its company editors and Axal admins read it, and an admin reads only
the last four digits.** Slot S08, issue #1206, 2026-10-06, from the owner's
answer "A" on #1206. Migration 397.

### What the owner chose

The owner answered "A", read as A for both questions:
- **1A:** store it.
- **2A:** the founder, company editors and admins read it. Investors don't,
  even in the data room.

2A is the narrower reading. If B was meant, investors under an active NDA
can be added later without changing the store.

### The store (migration 397)

**`company_eins`** has one row per project.
- **Its own table.** It is not on `users`, which is at D1's column cap, and
  not in `incorporation_meta`, which the browser writes.
- **The number** is AES-256-GCM through `services/columnCipher.ts`, the same
  cipher `integrations/secrets.ts` wraps. That module fixes its table to
  `integrations`, so this store calls the cipher directly with its own AAD,
  `company_eins:ein_enc:<project_id>`. A ciphertext copied onto another
  project's row does not decrypt.
- **The CHECKs** hold the cipher's `v1.` prefix (so no plaintext) and a
  four-digit `ein_last4`.

### Who reads and writes (`routes/company_ein.ts`, `/api/company-ein/:projectId`)

- **A founder.** That is the owning founder, or an accepted owner or
  co-founder member (`canAccessProject` with `write`, so not an advisor). A
  founder reads the masked number. With `?full=1`, a founder gets the
  number itself, for their own edit field. A founder also writes it.
- **An admin** reads the masked number only, even with `full=1`, and writes
  it. The write is recorded through `logAdminAction` as
  `company_ein_recorded`, with the project and never the number.
- **Anyone else gets 404**, as for a startup that doesn't exist. That
  includes another founder, an advisor member, a partner and an investor.
- **The shape is `NN-NNNNNNN`.** A refusal answers `ein_invalid` and never
  echoes what was sent.

### Where the number goes

No response, log, activity row, audit row or console line carries the
number, apart from the founder's `full` read.

### The milestone

**Storing a valid EIN marks `ein_received`** for the startup's owning
founder (`services/einMilestone.ts`). It does so whoever stores it, because
the startup is that account's Lab sprint. It follows `POST /milestone`'s
rules:
- the cohort gate and a frozen sprint record nothing;
- an inactive Lab records nothing;
- credits are paid only by the call that recorded it (D541).

`ein_received` doesn't graduate anyone, so no certificate is issued.

### The page

On the Lab Incorporate page:
- **The Company EIN card** shows the last four, or Not recorded, or
  Unreadable. It offers Add EIN or Edit. The edit field reads the full number
  when it opens and drops it when it closes.
- **The investor preview's EIN tile** used to print "Pending" once paid,
  although nothing would ever record a number. It now says Not shared when one
  is stored (2A) and Not recorded when none is. It never shows the number.

### Not built

- An HQ screen for the EIN. An admin writes through the same route.
- Investor access (2B).
- Any change to `LegalCapitalPage.jsx`'s own `ein_received` mark, from
  `subsidiaries.ein`.
