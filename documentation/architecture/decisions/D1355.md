### Rules and implementation

The [in] rules supply blue, black and white versions. Keep the original shapes, proportions, colours and registration mark; no rotation, cropping, arbitrary recolouring or brand lockup/endorsement. This PR uses the provided blue and white PNGs byte-for-byte. The archived blue is **#2867B2**; it is not recoloured to a newer palette. The supplied sign-in button’s own blue is **#0077B5** and its wording is **Sign in with LinkedIn**.

[Logo size guidance](https://brand.linkedin.com/linkedin-logo) gives a 21px screen minimum measured by the [in] part, no enlargement beyond native resolution, and separation from neighbouring graphics/text. Its clear-space diagram concerns the full wordmark (not used here). The standalone bug page gives no numeric clear-space measure. **Our compact-UI rule is a conservative 28px SVG viewport with at least 8px reserved padding**, proportionally increased at larger sizes. The supplied blue bug itself is above 23px high after aspect-fit, exceeding 21px. This 8px rule is an implementation choice, not a number attributed to LinkedIn.

`BrandIcon` enforces this for every direct or dynamic LinkedIn key, even callers asking for 12–18px or `currentColor`; inline minimum dimensions also defeat incidental `w-3`/`h-3` styling. Light surfaces use the supplied blue; dark surfaces the supplied white. Blue-backed referral controls explicitly use white in both themes. The footer’s permanently white icon backing explicitly uses blue in both themes. No CSS tint/filter changes pixel colours. The bordered share anchor is at least 46px so its 44px mark frame fits within both borders. Connector-card headers reserve 46px for every provider so titles stay aligned beside the larger approved LinkedIn mark.

Actual OAuth entry points on the connector page and existing connector sheet use the official default/hover/active sign-in images and their existing handlers. An opening sign-in disables interaction and shows progress outside the unchanged artwork. Opening is derived from the actual sign-in view, including an expired connection whose band still says Reconnect. Another in-flight operation disables sign-in with the caller’s explicit “Please wait…” reason (the shared button invents no reason for a generic disabled state) and does not announce that LinkedIn is opening. Reconnect keeps a visible caption and accessible context; unavailable connectors keep their original disabled status control instead of pretending sign-in can start. LinkedIn has no environment/PAT choices in the current catalogue. Refer & Earn is now a Connections.csv import (#3568), and Settings’ connected-account/PDF import is not sign-in; their import wording and behaviour stay truthful. Login currently offers no LinkedIn OAuth button, so this task adds no new authentication capability.
