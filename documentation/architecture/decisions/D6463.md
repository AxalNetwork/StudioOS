## D6463 — The Actions-queue alert ignores queued runs created before a cutoff (#6463)

Part of #5600 (plan key A4). `[alert] the Actions queue is backed up` (#5719) has been open since 2026-11-11. About 207 runs from that day are stuck as queued, and GitHub refuses to cancel or delete them. The alert opens at 40 queued runs or a 45-minute oldest age, and clears only under half of both (`QUEUE_CLEAR_RATIO`). Those runs are three days old, so it could never clear, and while it is open AGENTS.md holds branch updates and bulk re-runs.

### The rule

- **The variable.** `QUEUE_ALERT_IGNORE_BEFORE` is a repository variable holding an ISO date (`2026-11-12`) or date-time (`2026-11-12T06:00:00Z`). It reaches the `queue` job through `.github/workflows/github-alerts.yml`.
- **Unset or blank.** Nothing is ignored, and the job reads exactly the pages it read before.
- **Invalid.** A value that is not a real calendar date (`2026-11-31`, `yesterday`, a timestamp) fails the job with an error annotation and ignores nothing.
- **What is left out.** A queued run created before the cutoff is left out of both the count and the oldest-age figure (`queueAfterCutoff`, `scripts/lib/githubAlerts.mjs`).
- **What always counts.** A run is ignored only when it was read and its `created_at` is before the cutoff. A run created at or after the cutoff counts. So does a run with an unreadable date, and a run beyond the API's 1,000-run window that the reader never reached.
- **Unread runs.** While runs remain unread, the oldest age is the oldest run read, old or not. Unread runs are older than every run read (the API lists newest first), so the age is never younger than the truth.
- **Pages read.** With the cutoff set, the job reads every page in that window (at most 10 calls), so each run it leaves out was seen.
- **Where the exclusion shows.** While the queue issue is open, its body carries one line: `Ignored: N queued run(s) created before <cutoff> (QUEUE_ALERT_IGNORE_BEFORE, #6463).` Each run replaces it, and it sits above the health marker. The Slack text adds "(N queued before <cutoff> ignored)".
  - `safeHealthFacts` admits the two new facts: `ignored`, a non-negative integer, and `cutoff`, in the exact ISO form `parseQueueCutoff` writes.
