## D7909 part 4 — Validate the reusable planner before repinning its caller (#7909)

GitHub rejected the capacity planner before scheduling a job because a job-level
environment entry used the unavailable runner context. Local actionlint 1.7.12,
downloaded from the official release and checked against its published checksum,
reproduced that exact context-availability error in the prepared source.

The plan-file path is now evaluated only in the submit step, where runner.temp
is available. It still names the exact directory used by the artifact download.
Metadata mode does not consume the plan file and needs no path override. Existing
audience, original-run/artifact identity, digest, source, permission and default-off
checks are retained; no candidate code gains the trusted OIDC capability.

The corrected reusable definition is committed before the ordinary CI caller is
repinned to that exact full revision. The existing source-consistency test checks
that the literal pin contains this actual definition. An old pin cannot silently
leave CI invoking the rejected workflow. Actionlint validates the planner, caller
and executor together; restoring the job-level runner reference reproduces failure.

This is local source preparation only. It neither schedules work nor clears the
newer executor intake, lifecycle, native, operator, review or #5719 gates. Ordinary
hosted execution and required-check consumers remain in place. AGENT_ENGINE=off.
