### 2. The rail

- **The page key.** Both routes carry the AIRail under `<Profile> · Articles`. That is the key D1409's Worker files every article run under (`articlePage`).
- **The routes are off the canvas.** `railPages.js` gives `/articles/draft` the key in `SHARED` (`off`), with `/articles/edit` as its alias. `/articles` itself is the public feed and has no rail.
- **`WorkerRail workspace="Articles"`** holds the member's switch for the page. D1409's `assist_off` refusal now has a toggle a member can reach.
- **The rail-route census** (`frontend/test/_railRoutes.mjs`) reads `authOnly(…)` as every member profile. Before this, a rail on an `authOnly` route could not be counted. The `/spinout-lab/apply` row in `NO_RAIL_ROUTES` now names the three profiles that have no key there.
- **No `railOptions` rows.** Those lists cover canvas boards, and this page is off the canvas. Each press sends its own option (`railPressHeaders`).

**The addendum's wording is kept:**
- the button is **Ask**, never "Fill";
- each action reads "Holds up to $x · you pay what it uses";
- a proposal reads "Charged $x of $y held · the rest is released";
- a charge the server could not read says so, and is never shown as $0;
- the AIRail holds no actions;
- blank Search title and Search description fields carry an **Ask** trigger, which opens the panel on `draft:article-seo`.

**Nothing writes the article but the page's own save:**
- Insert, Replace, Use and Use both decide the proposal (`POST /api/ai/rail/proposals/:uid/decide`), then change the draft. The autosave writes it.
- A rewrite whose selection changed since the run goes below the selection instead of replacing other text.
- The image sheet places one picked image and discards the others when the member picks or closes.
  - A cover is copied from the pick (`/cover` with `{ image }`), so the pick's own file is discarded too and nothing is left orphaned in R2.
  - A body image is accepted, and placed as Markdown.
