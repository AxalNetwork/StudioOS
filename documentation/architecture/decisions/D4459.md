## D4459 — No-call run costs and live task-update responses (#4459)

Part of #3968. Addresses S1’s post-merge review of #4444.

A NULL usage reference on an E3 attempt means no model call and no charge,
including refused, admitted and running attempts. The per-attempt aggregate
now contributes zero for that case. It no longer marks the whole task’s
all-attempt total unknown: a paid attempt of 50 plus a refused attempt is 50.
A real usage row with a NULL/negative charge, or a non-NULL reference whose
usage row is absent, remains unknown. Guard-inclusive charges, selected-task
batching, run identity, concurrent-attempt checks and unreadable states stay.

`workItemRoutes` defaults to `recordedWorkRuns`, the same default as the board.
Labels, milestone, review and draft-accept responses all use that reader via
the existing card helper. The injectable reader remains available for callers.
No route, scope or permission changes.

`work_runs_4459.test.ts` exercises actual migrated SQLite and the real engine
mount: charged/refused/running attempts, genuinely unknown charges, and the
labels/milestone/review responses compared to GET /tasks/:uid. The stranger’s
write still answers 404. Existing run and W7 suites remain in verification.
No schema or production changes were applied; no deployment performed.
