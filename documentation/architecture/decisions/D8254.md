## D8254 — Grow Markets: link growth partners to a market (#8254)

- **Status:** built 2026-11-22. Follows D6120, whose evidence line read "Partners are not linked to a market yet".
- **Migration:** `202611222056_8254_partner_markets.sql` — `growth_partner_markets (partner_id, market_id, created_by, created_at)`, primary key `(partner_id, market_id)`, both foreign keys `ON DELETE CASCADE`, and an index on `market_id`. Additive.

### What this decides

1. **A partner can work several markets, so the link is a table, not a column.** A link is a plan, not history: it goes with the partner or the market, and nothing else is removed with it. Removing a partner is still refused when it has revenue or deals (D6112, D6114).
2. **The partner form sets it.** The partner's Edit form has a `Markets this partner works` field (checkboxes over the venture's markets, current links ticked). `updatePartner` and `addPartner` take `markets` (market uids): the list replaces the set, an empty list unlinks everything, and a body without `markets` changes nothing. A uid that is not this venture's market is a 400 before anything is written. The Add partner form on the list does not ask for markets; link them from the partner's Edit.
3. **Permissions are the partner write gate's:** a reader of the venture is refused (403), and another venture's partner is a 404.
4. **The market record lists them** (`parts.market.partners`: uid, name, type, stage, each linking to its partner record), with an empty state and a link to Partnerships when none is linked. The read joins on the partner's venture, so a stray row never lists another venture's partner. A failed read is `partners: null` with `partners_state: 'unreadable'` and reads Unavailable, never an empty list.
5. **The evidence strip** under Partners now reads "Partners linked to Portugal: 2", or Not recorded when none.
6. **History:** the link change is part of "Partner updated" (D8252 records the market's own field changes; a partner's links are not a market field).

### Rollback

Revert the commit. The table stays (migrations are never undone) and older code ignores it; links already set are kept.
