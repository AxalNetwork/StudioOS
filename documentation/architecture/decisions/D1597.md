## D1597 — Advisor › Expertise › Visibility: requests per booking link and opens of your writing

- **Status:** built by S09 from S1's specification on #3870, under the profiles canvas #3700 (board PH11).
- **Owner question H, answered 2026-11-01:** (b), do not count profile views. Migration 751 is released.
- **Builds on:**
  - `advisor_booking_links` (migration 240) and `advisor_bookings.booking_link_id` (migration 394);
  - `articles.views`, a counter of opens here on Axal;
  - the partner's Visibility (`GET /api/partner/offers/visibility`), whose honesty this follows.
- **Migration:** none.

### The question

The canvas draws Advisor › Expertise › Visibility with figures, and the zone had no store: it rendered `NoStoreYet`. What can it show that the product actually records?

### What was decided

**One read, `GET /api/advisors/me/visibility?days=30`** (`routes/advisors.ts`, logic in `services/advisorVisibility.ts`).
- **Gate:** `requireAuth`, role `advisor`, then `requireMyAdvisor`. Every read binds the caller's advisor id; the writing read binds the caller's user id, as `/me/thinking` does.
- **Window:** `days` is 1–370, 30 when absent or not a number. The window runs from now minus `days` to now.

**`surfaces`.**
- There is one row per booking link the advisor owns (`key` `link:<uid>`, `name` `/b/<slug>`, `audience`, `is_active`), plus `no_link`.
- `requests` counts the bookings created in the window on this advisor; `by_status` groups them by the statuses the route writes (`pending`, `confirmed`, `completed`, `cancelled`, `no_show`), listing only the statuses present.
- A booking with no link, or whose link is not one of this advisor's, counts under `no_link` and nowhere else. Its note says the booking names no link.
- A link with no booking in the window reads 0. That zero is real, because its read succeeded.

**`writing`.** `published` counts the advisor's published pieces, and `opens` sums their `articles.views`. That figure is lifetime, not windowed, and the note says so. `requests` is null, because a booking does not record which piece led to it.

**`views` and `engagements` are always null,** each with its sentence.
- No profile view is recorded anywhere in the product. The owner chose not to start counting one (H = b), because a raw counter with no bot or repeat handling would read as measured when it is not.
- No advisor engagement records the link or piece it came through (migration 238).

**A failed read is never a zero.**
- `surfaces` and `writing` are read apart. One that fails is null, and the top-level `unreadable` is true, so the null block is the one that failed. The other block still answers.
- This deliberately does not copy `/me/thinking`'s old empty-shelf fallback.

**Nothing is added up across stores.** Opens and booking requests are never one reach figure, and no rate is computed over rows that name no surface.

**The client** is `api.getMyAdvisorVisibility(days)`, beside `listMyAdvisorBookingLinks`. S1 mounts `pages/advisor/expertise/VisibilityZone.jsx` in place of `NoStoreYet` and draws "Not recorded" for `views` and `engagements`.

### Verified

- `cloudflare-worker/test/advisor_visibility_d1597.test.ts` passes 7 tests on the migrated schema. It covers:
  - only the caller's links and bookings, with another advisor's on the same days never counted;
  - the window and the clamp;
  - `no_link`;
  - writing that counts only the caller's published pieces;
  - `views` and `engagements` null with their sentences;
  - a failed bookings or links read, and a failed articles read, each null and unreadable while the other block reads;
  - a founder, partner or Explorer refused, and an advisor with no profile refused.
- Five mutations each turned a test red:
  1. count another advisor's booking;
  2. drop the window;
  3. return 0 for views;
  4. add opens into requests;
  5. swallow a failed read into an empty list.
