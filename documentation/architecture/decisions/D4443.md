### Follow-up #4463 — first-event errors and main-account isolation

An OpenAI stream enters the uncertain-cost window as soon as the Responses
request resolves after successful HTTP headers, before iterating SSE events.
The SDK can throw on the first `event: error` without yielding it. Such errors,
including `insufficient_quota`, `billing_hard_limit_reached` and
`billing_not_active`, retain the attempt's worst-case reservation with
`cost_known: false`; they do not establish that the accepted stream was free.
A pre-stream HTTP quota refusal still settles at known zero, while an abort
before headers remains uncertain.

Real-SDK intercepted-response tests cover these boundaries through the durable
ledger, plus Anthropic's first-event SSE `APIError`. Constructor-option tests
pin that neither main API-key nor federation clients receive account 2 or 3
workspace IDs; federation keeps its own workspace configuration. No account
settings, review-chain order, SDK version, or production application changes.
