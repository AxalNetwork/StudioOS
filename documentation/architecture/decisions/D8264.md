## D8264 — Keep the recovery command result consistent (#8264)

The command entry point keeps an output-only contract for its backup and restore
paths. Restore runs its existing handler and exits before backup argument parsing.
Both successful paths return `None`. Handler failures propagate to the existing
command error handling.

The tracker remains open through the confirming default-branch scan. Evidence is
in the protected [Code Scanning alert](https://github.com/AxalNetwork/StudioOS/security/code-scanning/7449).

The existing synthetic recovery suite now checks restore arguments, one handler
invocation, early exit, error propagation, and the normal backup receipt. All 27
Python tests pass, together with the standard Worker runner wrapper. Three
mutations fail the regression tests, covering helper-return forwarding,
fallthrough into backup, and omitted restore invocation. No live services were
contacted during this validation.
