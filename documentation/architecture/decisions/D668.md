### The consent page
- **The redirect host is always shown, in a box above the scopes and larger than the client's name.** RFC 7591 lets any client register any name, so the name is never trusted alone. A request without a host reads "Not recorded"; the name never stands in for it.
- **The scopes are fixed:** "Read your Validate context" and "Submit interviews for your review", then "It cannot change a module, delete anything, or see other companies."
- **The companies are ticks,** from the request, which lists only the companies the founder can write to. Approve is off until one is ticked, and sends exactly the ticked ids the request offered; a tick for anything else is dropped.
- **States:** the Worker's 404 is "Not available yet" (the flag is off); 410 is an expired request and 409 a used one, both "Start again from your assistant"; an empty company list explains itself; any other failure is unreadable, never "expired". None of these can approve.
- **Signed out** goes to `/login?next=` with this page's path and query.
- **Redirects:** only an absolute `https:` URL is followed (or `http:` on localhost, for a developer's client). Anything else is refused.

### The AI assistants group
- **One server URL,** `https://axal.vc/api/mcp`, on every card, with a copy button.
- **The steps are the vendors',** read from their help pages on 2026-10-09, and each card links its page:
  - ChatGPT: OpenAI's developer mode article. Full MCP with write actions is in beta on Business, Enterprise and Edu; Pro connects read and fetch tools only.
  - Claude: Anthropic's custom connectors article. In beta on Free, Pro, Max, Team and Enterprise; on Team and Enterprise an owner adds it first.
  - Gemini: Google's custom apps help. A personal account with Gemini Spark access and Keep Activity on; country and language limits. Enterprise adds servers through its admin.
  - Grok: xAI's connectors docs. Paid plans.
  - Another MCP client: the MCP specification. It must register itself and use OAuth.
- **The grants list** shows each grant's client and host, its companies, when it was connected and last used ("Never used", never a date it was not). **Revoke asks first,** then the row is gone. On a phone each grant is a card, because a table scrolled the page sideways at 390.

### Record a session and the review step
- **"From an AI assistant"** gives three steps (connect, run it there, review here), links to the AI assistants group, and offers "Copy a starter prompt" naming the company and nothing about the interviewee. StudioOS never sends the prompt anywhere.
- **The consent line** says the interviewee's consent must cover the assistant processing the interview.
- **A session an assistant submitted** carries "From <name>" and opens on the review step.
- **Each placement is labelled** "Proposed by <name> (<host>)" or "Proposed by StudioOS". A missing host is said.

### Part 2: wired to D667 (#1497)
#1497 merged, and #1506 mounted the review step, so this part wires what reads D667's fields:
- **Each placement is labelled by its source,** from the review read's `source` and `submitted_via_name` (D667): "Proposed by StudioOS", or "Proposed by ChatGPT (the name the assistant gave itself)". The read carries no redirect host (it lives on the grant, #1496), so the label says the name is self-declared rather than inventing a host; `placementSource` shows "(host)" once a read carries `submitted_via_host`. Only a row whose `source` is `assistant` is credited to one; a row from before migration 447 is StudioOS's own.
- **The compare view heads each run by who proposed it:** "ChatGPT (assistant)" against "StudioOS · <model>". It used to read "Model not recorded" for an assistant's run, which has no model.
- **The review lists the latest run of each source.** It used to list only the latest run, so once StudioOS structured an assistant's transcript to compare, the assistant's pending proposals could no longer be accepted. With StudioOS's runs only, nothing changes.
- **The session page** carries "From <name>" beside the breadcrumb, and a session an assistant submitted shows its review step above its transcript. There is no session list in the SPA yet (`interviewSessionsApi.list` has no caller), so the badge is on the page itself.
