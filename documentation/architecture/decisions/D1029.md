## D1029 — Cap table part 14: the old pages retired, their addresses redirected, their links retargeted

- **Status:** built by S23 for #2866 (part 14 of #2432), 2026-10-26.
- **Split:** D1015 §6, from S21's integration in #2852.
- **Builds on:** parts 7 to 11 (D1022 to D1026), all on `main`. Nothing is deleted before the tool is live (#2432, "Retire the old pages").
- **Migration:** none.

Paths are relative to `frontend/src/` unless they say otherwise.

### 1. The redirects

`pages/raise/captable/CapTableMovedRedirect.jsx` forwards each old address into the tool. App.jsx mounts it on four routes, unguarded: the guard is the destination's.

| Old address | Lands on |
| --- | --- |
| `/raise/capital/cap-table` | `/raise/cap-table?moved=cap-table` |
| `/build/captable` | `/raise/cap-table`, with no chain through the old page |
| `/raise/cap-table/variants` | `/raise/cap-table/scenarios?moved=variants` |
| `/raise/cap-table/variants/:variant` | `/raise/cap-table/scenarios/:variant` (a variant's uid is its scenario id) |

Each keeps its query and its hash.
- **`?project=` becomes `?project_id=`**, the tool's word.
- **A `?project_id=` already there wins**, so an address never names two ventures.

All four are on `REDIRECT_ROUTES` (`cloudflare-worker/src/services/redirectRoutes.ts`) for #2319's 90-day count. None is `keep`: no email or external link carries them, and every in-app link is retargeted (§3).

`cyclePaths.js`'s `STATIC_CHILDREN` is empty now. The variants page was the last static child, and its addresses are cycle paths that redirect.
