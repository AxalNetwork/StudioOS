## D6909 — Request a mark: evidence on a request, and HQ's queue across companies (#6909)

- **Status:** Worker part built 2026-11-16 (`Part of #6909`). The PRM20–PRM24 boards are not built yet (see "Not built here").
- **Builds on:**
  - D6205: `portfolio_mark_requests`, with `open | resolved | declined`, the decline note and `resolved_mark_uid`;
  - D6228: owner answer A, "evidence (a file or a link), optional";
  - D6868, which files this issue.

### The problem

#6909 lists two backend items the boards need and D6205 does not have:
- **Evidence on a request.** PRM21's Prepare step lets the investor attach a file or a link. The store had no place for either.
- **HQ's queue across companies, oldest first.** PRM23 puts the queue above the register. `GET /api/mark-requests` lists newest first, for one company or all, and does not carry the company's current mark that Record a mark is prefilled from.

### What is built

**Store.** Migration `202611161239_6909_mark_request_evidence.sql` adds to `portfolio_mark_requests`:
- `evidence_url`: an http or https link, at most 2,000 characters, by CHECK;
- `evidence_file_key`: under `mark-request-evidence/`, by CHECK;
- `evidence_file_name`, `evidence_file_size` and `evidence_file_mime`.

Two triggers guard the evidence:
- **One kind, all or nothing.** A request carries a link or a file, never both, and a file's four columns are all set or all empty.
- **Frozen.** Evidence is written with the request and never changed. Answering a request (D6205's `PATCH`) leaves it as it was.

**Worker.** `routes/mark_requests.ts`:

| Method | Who | Rule |
| --- | --- | --- |
| `POST /` | an investor, as in D6205 | **Accepts JSON** as before, now with an optional `evidence_url`. **Or a multipart form** with `project_uid`, `kind`, `reason` and an optional `evidence_file`. **The file:** PDF, PNG, JPEG or WebP (else 415), not empty, at most 10 MB (else 413). It is stored at `mark-request-evidence/<project_id>/<request uid>.<ext>`. **Checks:** a link and a file together are refused (400 `one_evidence`), and a link that is not http or https, or carries credentials, is 400 `bad_evidence_url`. **Order:** every check, the held check and the open-request check run before the file is stored. If the insert then fails, the stored file is deleted again. **No file store:** 503 `storage_unavailable`, which says to send a link instead. |
| `GET /queue` | admin | Every open request across companies, oldest first (`created_at`, then id), at most 500. Each row carries who asked and `latest_mark`: the company's latest mark by `as_of_date` (uid, as-of date, FMV, basis), or `null` when there is none, never an invented one. |
| `GET /:uid/evidence` | the investor who asked, or an admin | Streams the stored file as an attachment, with its own type, `nosniff` and `no-store`. Anyone else reads 404, as for an unknown uid, so a uid confirms nothing. A request with no file is 404 `no_evidence_file`. A file the store cannot return is 404 `evidence_unreadable`, never an empty file. |

Every request read (`POST`, `GET /`, `PATCH`, `/queue`) carries `evidence`:
- `{ kind: 'link', url }` for a link;
- `{ kind: 'file', name, size_bytes, mime, href }` for a file;
- `null` when there is no evidence.

The storage key is never handed out.

**Client.** `frontend/src/lib/api/markRequests.js`:
- `create` takes `evidenceUrl` or `evidenceFile`, and sends a file as FormData;
- `queue()` reads the queue;
- `downloadEvidence(uid)` downloads the file.

The existing callers are unchanged.

### Choices made here

- **Evidence counts to no storage area.** One file per request, at most 10 MB, is sent to HQ. It is not part of the investor's own library, so it is not added to D1169's storage areas, and `assertStorageRoom` is not called. If the owner wants it counted, the change is one `assertStorageRoom({ userId })` call and one area in `storageUsage.ts`.
- **The queue is its own route, not a `?order=` on `GET /`.** `GET /` keeps D6205's newest-first contract for the investor list and the position sheet. The queue adds the latest mark, which only HQ needs.

### Tests

`cloudflare-worker/test/mark_request_evidence_6909.test.ts` covers:
- the link rule;
- a link stored and read back;
- a file stored, read back and opened by the asker and HQ only;
- each refusal storing nothing;
- the open-request check running before the upload;
- a failed insert leaving no file;
- the store's shape and frozen triggers;
- the queue's order, latest mark and admin-only rule.

**Mutation checks**, each of which turns a named case red:
- "not both" dropped;
- the queue ordered newest first;
- the requester check on the file dropped;
- the orphan delete dropped.

D6205's suite (`mark_requests_d6205.test.ts`) passes unchanged.
