### 1. A pull read, not a heartbeat

HQ already reaches each branch over its service binding, with one read path that reports a
branch's three states the same everywhere (`branchRead`, D153: ok, unreadable, not deployed).
The branch already keeps the revision its copy holds and whether the copy is complete
(`branch_licence.hq_revision`, `copy_state`, migration `202611071927`). So the read needs no new
store, no branch cron and no new HQ ingest route: the branch's existing `health()` answer now carries
those two fields.

A heartbeat would add a scheduled write on every branch, an authenticated HQ endpoint to receive it
and a table to keep it. It would only say what the branch held when it last beat. A pull read says
what it holds when the operator asks.

#5786 (open as PR #6313) reads the same `health()` for its scoped Platform view, so the new fields
reach that view too, with nothing further to build.

### 2. Two facts, side by side

`sync.branch_revision` stays what it was: the branch's answer to HQ's last push. A branch on an
older build that answered `{ applied: true }` was recorded as holding what HQ sent (D4686).
`sync.branch_report` is the separate read:

| `state` | When | `revision` |
|---|---|---|
| `reported` | the branch answered with its copy's revision | that revision, or null with "holds no numbered copy" |
| `older_build` | the branch answered without the field (a build before D5925) | null; "redeploy the branch to read it" |
| `unreadable` | the call failed or timed out, or the registry could not be read | null, with the reason |
| `not_deployed` | no deployment row, or no binding on HQ | null |

`applied_at` is when the branch wrote its copy, and `reported_at` is the branch's own `as_of` for
this answer. A branch that cannot be reached never shows the last pushed revision.

### 3. Not in this change

The licence page's sync strip still draws `branch_revision` only. Drawing `branch_report` beside it
(L15, Sources, partial success L18, History's outcome) is the frontend's next step. The data and its
SPA contract keys are in place.
