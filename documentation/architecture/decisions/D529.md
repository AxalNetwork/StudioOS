## D529 — `docs/` is not committed: CI builds it, and the deploy carries the old-bundle window in the Actions cache

**`docs/` leaves git. Every job that reads it builds it from `frontend/src`
first, `scripts/check-docs-fresh.mjs` is retired, and the production deploy
keeps the old-bundle window by restoring the previous deploy's `docs/assets`
and retention ledger from an `actions/cache` entry before it builds, and saving
them after it ships.** Issue #1065, slot S03; the owner chose option B on
#1057. No migration, no route, no `api.js` change.

**Why.** Every PR that touched `frontend/src` committed its own build of
`docs/`, so after each merge the other open PRs collided in `docs/`: on
3 October twelve did at once, all in `docs/` only. A stale committed build also
turned checks red that had nothing to do with the PR (#970's "open graph
metadata"). The deploy already rebuilt `docs/` from source, so the committed
copy was only ever a second, drifting copy of what the source says.

**What changed.**
- **Untracked.** `git rm -r --cached docs/`, and `/docs/` in `.gitignore`. The
  Worker's `[assets]` directory is still `./docs`; the static security headers
  still come from `frontend/public/_headers`, built to `docs/_headers`.
- **The old-bundle window.** A tab opened before a deploy asks for the previous
  build's hashed chunks. `scripts/build-frontend.mjs` keeps the last three
  builds' assets in `docs/assets` (D252, `scripts/lib/assetRetention.mjs`), but
  only if the previous ones are on disk when it runs, and that used to be the
  committed tree. Now `cloudflare-worker-deploy.yml`:
  1. restores `docs/assets` and `docs/.asset-retention.json` from the newest
     `spa-assets-` cache entry (`actions/cache/restore`, `restore-keys`);
  2. builds with `--seed-restored-tree` (renamed from `--seed-committed-tree`:
     it seeds what was restored, and the ledger decides the window);
  3. deploys; and only after that step succeeds,
  4. saves the same two paths under `spa-assets-<run_id>-<run_attempt>`.

  The branch-redeploy job restores the entry HQ's deploy just saved and builds
  over it, so a branch serves the same window; it never saves.
- **Why `actions/cache`.** It needs no credential and no API call: the restore
  and save are two pinned steps in the same workflow, and the newest entry is
  found by key prefix. An Actions artifact from an earlier run can only be
  fetched through the REST API with a token, and it expires on its own
  schedule; an R2 prefix would need a bucket, a binding the build cannot use,
  and an API token in the workflow. The cost is eviction: an entry unused for
  seven days, or pushed out by the 10 GB repository limit, is gone. That case
  is handled, not avoided — see below.
- **An empty store still ships.** With nothing restored, the deploy builds,
  deploys and saves as usual. The build log prints `retention restarted` (from
  `retentionStart` in `scripts/lib/assetRetention.mjs`), and a step emits a
  workflow warning saying a tab opened before that deploy may need a reload.
- **Build before reading.** `ci.yml`'s full-suite job runs the root
  `npm run build` before `npm run test:drift`, and its "open graph metadata"
  job installs the frontend and builds before its three checks, so they check
  the PR's own build instead of a committed one. The PR preview and branch
  provisioning already built `docs/` themselves; the post-deploy smoke reads
  the live hosts only. `check-reload-loop` and `check-workspace-frames` run by
  hand after a build and already said so.
- **Retired.** `scripts/check-docs-fresh.mjs` (and its place in
  `test:guards`), and `scripts/lib/buildStamp.mjs` with its test, which existed
  only to classify the stamp that check read. The build still writes
  `docs/.build-source`, which says which `frontend/src` a `docs/` on disk was
  built from, and `docs/.assetsignore` still keeps it off both hosts.
- **The words.** `CLAUDE.md` fact 4 and the `docs/` row of the file map,
  `AGENTS.md`'s test bullet, `documentation/operations/DEPLOY.md` §2.1 (and its
  pre-deploy commands), `PRODUCTION.md`, `CODEBASE_MAP.md`,
  `.github/copilot-instructions.md`, `CONTRIBUTING.md` and the PR template.

**Sequencing.** This PR deletes `docs/` from the index. Any open PR that
changed `docs/` conflicts once with a modify/delete; it resolves by merging
`main` and running `git rm -r --cached docs/` (the files stay on disk, ignored).

**Not built.** No store of the shells: the deploy restores assets and the
ledger, not the prerendered HTML, because the ledger already names each
build's files and the seed flag keeps what was restored. Nothing re-seeds the
cache if it is evicted; the next deploy restarts the window and says so.

**Verified.**
- `scripts/lib/assetRetention.test.mjs` gains five tests: with a saved
  previous build restored (three builds in the ledger), the kept set is this
  build and the two before it, the fourth ages out, and the ledger carries the
  window forward; a restored tree with no ledger is kept whole as one previous
  build; an empty store starts over and says "retention restarted"; a ledger
  with no files on disk is still a restart; and the deploy job restores before
  it builds and saves only after the deploy step, naming both paths, under a
  per-run key with the `spa-assets-` restore prefix. The D252 flag tests are
  re-aimed at `--seed-restored-tree`.
- Mutation-checked both ways, seven mutants, all caught: never restarting,
  always restarting, keying the restart on the ledger instead of the files,
  ignoring the flag, saving before the deploy, saving without the ledger, and
  a two-build window.
- End to end on this machine: a build's `docs/assets` and ledger copied aside,
  `docs/` deleted, the two restored, and a source change rebuilt with
  `--seed-restored-tree`. The old entry chunk `index-CclwSGqM.js` was still on
  disk beside the new `index-DodNQH4B.js` (661 fresh, 379 retained, 1040 in
  all). With nothing restored, the build printed `retention restarted` and
  still built.
- `npm run test:drift` exits 0 after the root build, read from a redirected
  log: frontend 4276, worker 5098 (3 skipped), retention 121 (123 before, plus
  five new, less the seven retired `buildStamp` tests).
- After the merge, S1 confirms the deploy, then that an asset hash from the
  build before it still answers 200 on axal.vc.
