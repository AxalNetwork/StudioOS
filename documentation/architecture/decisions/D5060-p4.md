## D5060 part 4 — Contracts: the Licence family, Licence type and Holder filters (#5060)

- **Status:** built 2026-11-14 by S10. This closes #5060.
- **Builds on:**
  - D5050 part 2, which built CT-17 to CT-20 and left these three filters to #5060;
  - D5060 (the registry, and each agreement context's `licence_family`, `licence_type` and `holder`).
- **Board:** CT-17 of `design/incoming/Licences and Contracts v2 Addendum Page.dc.html`.
- **No Worker change, no migration.** `GET /api/admin/contracts` already accepts and matches `licence_family`, `licence_type` and `holder` (`agreementFilters` and `matchesAgreementFilters` in `services/contractAgreementSources.ts`). It already returns the four user licence agreement types and their holder. What was missing was the frontend.

### 1. Three filters in the canvas's order

`AgreementFilterRow` draws CT-17's ten filters in order. The three new ones sit between Axal VC package and Template:

1. Agreement type
2. Legal state
3. Licence / territory
4. Program
5. Axal VC package
6. **Licence family**
7. **Licence type**
8. **Holder**
9. Template
10. Signed date

The canvas's "Signed / effective" stays "Signed date": effective date is not a filter (D5050 part 2).

- **Licence family:** Operator / territory, or User licence (`LICENCE_FAMILIES`).
- **Licence type:** the seven `LICENCE_TYPES`, from Territory to Advisor.
- **Holder:** the holders named on the page of agreements just read, by name.
  - Only those rows are known, so the panel says "The holders on this page of agreements".
  - Any row's **Only {holder}** button filters to that holder.
  - A page naming no holder says so.

Each value is the Worker's own. A set filter reads its value in words on its button and in a removable chip. A holder no row named reads "Member #42" or "Entity 7", never the raw `user:42`. Clear all clears all three.

### 2. The address

`ContractsDesk` keeps the three in the URL with the territory and signed-date filters (the D5050 part 2 line), so a filtered list survives a reload or a shared link. This is one line in an S24-owned file (#4811), beside #5050's.
