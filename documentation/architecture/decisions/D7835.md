### A context is its own record

A context is an owner-private record for competitor research and holds no link to a study: no column references a Research Project, a study or a study segment. Its only foreign key is its owner. A study's scope belongs to #7719 and nothing here writes it. A prefill of a context from a study segment is not built; if it is wanted later, it copies named fields through #7719's read and stores the origin as text, with no foreign key. A context is never part of a study report or a reviewer's read (#7727, #7728). A schema test pins this.

### Store

- `research_competitive_contexts`: uid, owner, a name (1 to 120 characters, so a member can tell saved contexts apart), and the fields below. NULL means not written, never `''`. `version` starts at 1 and each update adds one.
- `research_competitive_context_versions`: each saved version, copied whole as JSON in the same batch as the write. A trigger refuses any update, so a run (#7837) can name the exact version it used. Deleting a context deletes its versions with it, because the record is owner-private.
- A member keeps at most 100 contexts (`CONTEXTS_PER_OWNER_MAX`).

### Fields

| Field | Limit | Note |
|---|---|---|
| `product` | 200 | #7719's `product` and limit. The member's own product. |
| `directory_record_uid` | 64 | A company directory record instead of `product`. Both together are refused (`product_or_record`). |
| `buyer` | 200 | #7719's segment `buyer` and limit. |
| `customer_segment` | 200 | Named as #7828's attribute. |
| `customer_problem`, `use_case` | 1000 each | `use_case` is #7828's attribute name. |
| `customer_countries` | 60 codes | #7719's name and limit; see below. |
| `business_model` | 500 | #7719's name and limit. |
| `delivery_model` | 500 | Named as #7828's attribute. |
| `purpose` | 1000 | Why the research is being done. |
| `market_slug` | 64 | A tracked market: a slug the market directory holds. |
| `criteria` | the 12 attributes | An ordered list from #7828's `COMPANY_FACT_ATTRIBUTES`, each once. |

Over a limit is a refusal (`<field>_too_long`), never a truncation, as in #7719.

### Customer geography

The geography of a context is customer geography: where the buyers are. The field is `customer_countries`, never a plain "geography" or "country", and it is never where listed companies are based. It holds two-letter codes on the taxonomy's country list (`research_countries`), starts empty, and is set only by its own field. Nothing fills it from a company-location filter or from a directory record's country.

### Access

- Signed in; every route reads the context by uid and the caller's id, so another account's context is a 404 identical to one that does not exist.
- A support session reads as the member and cannot write (403 `support_read_only`).
- A write names the version it read. A stale one is 409 `context_changed` with `current_version`, and changes nothing. A delete names its version too (`?version=N`).
- A directory record is read through the served rows (`readCompanyByUid`) and only for a caller `admitsCompanies` admits. A record that is absent, withdrawn or excluded, and any record for a caller the rule does not admit, gets one refusal, 404 `directory_record_not_available`, which never names the record. A read gives the record's name only while both still hold; otherwise it returns the uid the member wrote with `state: 'not_available'`. An edit that keeps the same record is not refused because it has since stopped being served.
- Each write leaves an `activity_logs` receipt (`logAdminAction`) with the context uid and the changed field names, never the text typed.
