## D8920 — The future-clock report accepts the frontend's two opt-in skips by exact name and reason (#8920)

**Date:** 2026-11-27. **Status:** Built. Extends D5663's TAP classifier.

### Why

The nightly future-clock report (run 45987090967, job 140473244489) was the
first nightly in which the report job ran at all. It failed with
`tests_not_executed:frontend-1-of-2` and `tests_not_executed:frontend-2-of-2`,
although both frontend part jobs finished green. D5663's `inspectTap`
(`scripts/lib/futureClockEvidence.mjs`) treats a part as not executed when its
TAP has a cancelled test, a todo test, or a skip other than the three bare
Worker skips. The frontend parts had not been checked before.

A local run of both frontend parts, with the Date-only clock shifted 7 days
ahead (`scripts/future-clock.mjs`, no libfaketime), reported `# cancelled 0`
and `# todo 0` in each part. Each part had exactly one skip:

- `frontend/test/d1_backup_stream_d7142.test.mjs`: the 600+ MiB memory proof.
  It runs only with `D7142_LARGE=1`, and it skips with the reason
  `set D7142_LARGE=1 to write and read a 600+ MiB export`.
- `frontend/test/runner_executor_isolation_7905.test.mjs`: the ACL behaviour
  test. It runs only as root with `setfacl` and `setpriv`, and it skips with
  the reason `needs root, setfacl and setpriv to switch to the candidate UID`.
  An Actions runner job does not run as root.

Both skips are deterministic environment opt-ins, like the Wrangler ones. No
test skips because of a missing build, and none was cancelled by a timeout
under the moved clock. Run against Node's real TAP for those two files, the old
classifier returned `tests_not_executed`, matching the nightly, and the new one
returns `complete_green`.

### What changes

- The allowlist is now `OPTIONAL_SKIPS`, a map from each exact top-level test
  name to its exact skip directive. An empty string means a bare `# SKIP`, so
  the three Worker entries behave as before.
- The two frontend tests above are added, each with the reason its source
  prints. A skip is accepted only if both the name and the reason match exactly.
- These are still refused: any other reason (including the bare marker for a
  frontend entry), a reason on a Worker entry, a near-name, a duplicate marker,
  a skipped subtest, any todo, any cancellation, and zero executed tests.

### Tests

`frontend/test/health_alert_repair_5663.test.mjs` adds three tests:

- the accept and refuse cases above;
- a check that each test file still declares that name and reason, so a
  renamed test or a changed reason fails here, not on the next nightly;
- real Node TAP output for the two markers, which must read as `complete_green`.

### Not changed

- No workflow changes.
- A frontend test that crashes at file level prints its `not ok N - <file>`
  line out of order. `inspectTap` then reads the whole part as `tap_incomplete`,
  not `assertion_failure`. A local run showed this, but it is outside #8920.
