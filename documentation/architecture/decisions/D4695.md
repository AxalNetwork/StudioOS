## D4695 — Practice bookings and engagements are decided on the server, at the write (#4695)

This is package 3 of 6 of the `/practice` audit. It covers scheduling rules,
booking reservation, engagement transitions and renewal history.

### The failure

- `POST /api/advisors/slots/:id/book` checked only `is_cancelled`. A slot an
  advisor **blocked** (`blocked_reason`) was still listed and still bookable.
- None of the advisor's availability rules (`advisor_availability_rules`,
  migration 240) were enforced: minimum notice, weekly paid cap, blackout
  windows and buffers were stored and shown but never applied.
- Capacity was read, then the row was inserted, then capacity was read again
  and the loser's row was **cancelled** (`capacity_race`). That row stayed in
  the table, which is `UNIQUE (slot_id, founder_user_id)`, so the loser could
  never book that slot again, even when a seat freed. A client who cancelled
  and came back hit the same wall.
- A block counted bookings, then wrote unconditionally: a booking landing in
  between was blocked out from under its holder.
- `/advance` wrote the lane without conditioning on the lane it read. A signed
  engagement could move back to *drafting* (leaving an `active` outcome on an
  unsigned row) and then be ended through `/advance`, outside the renewal
  rate.
- `/renewal` added a cycle every time it ran, so a retry after a timeout counted
  a term twice, and nothing recorded when or why a term was decided.

### The booking path

One door: a booking-link booking and a direct slot booking both end in
`/slots/:id/book` (`/:uid/book` forwards to it).

1. **The rules** (`services/advisorBookingRules.ts`, pure) give the refusal and
   its code: `slot_blocked`, `min_notice`, `blackout`, `buffer`, `weekly_cap`,
   each a 409.
   - A rule that is not set (NULL) is no rule. A weekly cap of **0** accepts no
     paid session.
   - **Paid** means a priced type that is neither included nor a free intro.
   - **Blackouts and the week are read in the advisor's timezone** (Monday 00:00
     to Monday 00:00 there), not UTC. An unknown or missing zone reads as UTC.
   - A buffer compares the gap to the advisor's other *booked* slots; a gap equal
     to the buffer is allowed.
2. **The reservation is one INSERT** that decides what can change between the
   reads and the write: the slot is still open (not cancelled, not blocked),
   a seat is left, the type and link are still bookable, the once-per-client
   rule, and the weekly paid cap. The refusal is then explained from the state
   as it now is.
3. **A cancelled booking is taken over, not left to block.** The table's
   `UNIQUE (slot_id, founder_user_id)` cannot be dropped without rebuilding the
   table, so the INSERT is `ON CONFLICT ... DO UPDATE ... WHERE status =
   'cancelled'`: a client who cancelled books the slot again on the same row.
   A client who loses a capacity contention now leaves **no row at all**.
4. **Blocking is one UPDATE** that refuses a slot holding a seat, and counts
   from the row count. Blocked slots are not in the public slot list.
5. **Slots are stored as UTC instants.** `POST /me/slots` refuses a string that
   is not a date and stores the canonical instant, so the week, notice and
   buffer rules compare like with like. Older rows are read as they are.

Booking *transitions* (confirm, cancel, complete, no-show) already update with
`AND status = ?` and answer 409 when no row changed (D4703). This change does
not alter them and pins the stale-confirm-after-cancel case with a test,
including a cancel that lands between the read and the write.

### The engagement path

- **A state graph, on the server** (`ENGAGEMENT_GRAPH` in `routes/advisors.ts`):
  an unsigned engagement moves between *drafting* and *proposed*, is signed, or
  is abandoned; a signed one only flips between *signed* and *renewal_due*; it
  never returns to an unsigned lane and ends only through `/renewal`; *ended* is
  terminal. The board's `laneMoves` mirrors it, and a test derives the Worker's
  list from the source.
- **The lane write names the lane it read** (`WHERE id = ? AND lane = ?`), and
  `expected_lane` lets a screen name the lane it showed. A moved row is a 409
  `lane_changed`. The same advance twice is one change (the retry finds the lane
  already there).
- **Ending never leaves an `active` outcome:** a row that carries an outcome and
  is ended through `/advance` reads `ended`.
- **A renewal decides one term.** `expected_cycles` (required, from 1) is the
  cycle count the caller read. The UPDATE is conditional on it, and an event is
  written in the same batch.
- **Replay is idempotent.** The same decision on a decided term answers 200 with
  `replayed: true` and changes nothing; a different decision is a 409
  `term_decided`; a term that moved on is a 409 `cycles_changed`. Two unique
  indexes on the events table are the second line.
- **History:** `advisor_engagement_events` (migration
  `202611071547_advisor_engagement_events.sql`) is append-only: `signed`,
  `renewed`, `ended`, each with the cycles before and after and the note.
  `GET /me/engagements/:id/events` reads it. Engagements decided before the
  table existed have no events; nothing is backfilled.

### What the screens do

`EngagementsZone` sends the lane and cycle count it showed, and reloads when the
Worker says the row moved. The earlier `capacity_race` cancel reason is no
longer written; the practice model keeps it in the system-cancel set so old rows
still read as withdrawn, never as a decline.

### Not done, and why

- **No table rebuild** to replace `UNIQUE (slot_id, founder_user_id)` with a
  partial index. Taking over the cancelled row gives the behaviour without
  rewriting a table that carries money columns.
- **No backfill** of renewal events for decisions made before this change.
- **The weekly-cap count in the INSERT compares stored strings.** Slots created
  from now on are canonical UTC instants; older rows saved with an offset can
  be a few hours off at a week's edge in that one count. The route's own check
  compares real instants.
- **Not verified here:** an authenticated run against production data, and the
  time zones other than the ones in the tests. Tests use synthetic advisors.

### Tests

`cloudflare-worker/test/advisor_lifecycle_4695.test.ts` (13) and
`frontend/test/advisor_lifecycle_4695.test.mjs` (2). `advisor_engagements_scope`,
`network_standing_d976`, `advisor_practice_pr1` and `advisor_practice_pr4`
changed only where they pinned the old shape (the renewal call names its term,
the fixture has migration 240, `capacity_race` is no longer written, the block
is decided by its UPDATE). 24 Worker and 6 frontend mutations were each caught;
one more (the route's early "blocked" answer) is equivalent, because the INSERT
guard returns the same 409.
