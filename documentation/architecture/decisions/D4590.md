## D4590 — Interview suggestions are edited in typed fields, never JSON (#4590)

A founder correcting an interview suggestion on a Validate module ("From your
interviews", `SuggestionRow` in `frontend/src/pages/cycles/ValidateSections.jsx`)
now edits labelled fields for the suggestion's kind. The editor used to show
`JSON.stringify(payload)` in a textarea and `JSON.parse` the result, so a
missing quote mark could stop an accept.

The fields come from the Worker's own rules. `frontend/src/pages/cycles/suggestionForms.js`
lists, per placement kind, the fields, limits and allowed values that
`PLACEMENT_KINDS[kind].parse` (`services/interviewStructuring.ts`, with
`FINDING_KINDS` in `services/interviewFindings.ts`) applies to an edit on
`POST /placements/:id/accept`. The form checks the same rules first and says
what is wrong in plain words, next to the field. The Worker still checks every
edit (422 `invalid_edit`, nothing accepted), so the form never decides validity
on its own. `cloudflare-worker/test/suggestion_forms_d4590.test.ts` runs every
form's output through `parse` and fails when a kind, a value list, a limit or a
module name drifts. There is one difference, and it is deliberate: the Worker
silently drops a competitor context longer than 200 characters, while the form
refuses it, so an edit is never lost without a word.

What is not typed. The hypothesis or theme a suggestion points at
(`hypothesis_id`, `pain_group_id`) is carried over unchanged and named
("Accepting writes to Experiments and evidence · hypothesis H1 · …").
Choosing a different one is not a correction of what was heard. The server
still adds `build_candidate` to a prototype ask.

The accept path is unchanged. The row calls the same `onAccept(id, payload)` →
`interviewSessionsApi.accept` as before. No route, permission check or
provenance write is added or moved, so #4627's acceptance and provenance
contract applies to it as it stands.

What the row shows and keeps:

- **The source stays readable.** The suggestion's own line, its quote and its
  "Heard in" reference remain above the form, marked "As suggested". The form
  is "Your version".
- **Rejected edits.** A draft that breaks a rule sends nothing.
- **Failed accepts.** When the accept itself is refused, the draft stays open
  and the suggestion stays pending.
- **Cancel** restores the suggestion's values.
- **While saving,** every button is disabled.
- **An empty optional field** is left out of the payload, because the Worker
  refuses an empty string where it accepts an absent field.
- **An amount** is typed in units and sent in cents. A currency or period
  without an amount is refused, as the Worker refuses it.
- **A need-to-have demand signal** shows no amount, because the Worker drops it
  (D690).
- **A kind this file does not know** has no Edit. The row says it can only be
  accepted as suggested or discarded, so nothing is dropped silently.
- **A stored choice the list does not have** is drawn as itself, marked
  "not a listed value". It is never shown as a different choice.
