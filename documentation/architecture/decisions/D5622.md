## D5622 — Bound CI repair eligibility and verify the repair App (#5622)

Eligibility requires a PR-only digest at an identified head, a quiet
period of 30 minutes since the last push, fewer than two attempts for
the PR and failure fingerprint, positive daily budget, and an off kill
switch. The breaker opens when any of the three CI incident issues is
open or the observed infra-failure count reaches the configured limit.
Missing alert or threshold evidence stops repair. The daily cap and
infra sampling window and threshold need configuration before activation.
The Worker must recheck eligibility and reserve attempt and budget under
the issue lease before it dispatches. The pure policy reserves nothing.

GitHub documents that an installation token with Actions write can
dispatch a workflow. Its commit mutation accepts the branch's expected
head OID, and the Actions documentation distinguishes App tokens from
the workflow token that suppresses recursive events. These are API
contracts. The installed Merge Control App still needs to exercise them.
[Dispatch API](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event),
[commit mutation](https://docs.github.com/en/graphql/reference/commits#createcommitonbranch),
[workflow triggers](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).

In an isolated fixture, use the actual App to dispatch on the default
branch and capture the run ID. The fixture workflow should upload one
inert artifact with empty repository token permissions and checkout
credentials disabled. Test an expected-head mismatch after moving the
fixture branch, then commit against its current SHA and verify a PR CI
run starts at the new SHA. Record the App ID, run, artifact and resulting
commit in this decision when observed.

The executor and patch guard follow #5618, #5619, #5620 and #5604.
Owner decisions #5605 rows 2 and 7, the restricted environment, App
permissions and spend limits must be settled before activation.
