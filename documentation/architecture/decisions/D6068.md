### 1. The tally is the module read's, and it runs no check

`parts.narrative.claims` is the newest version's tally of the claims the last check stored:
`{ state: 'ok', version, backed, total, checked_at, mismatch_sections }`, or `{ state: 'unreadable', version, reason }` on its own, or `null` with no version. Reading the module never runs a check: `GET /narrative/:version/claims` and `POST …/check` stay the only places one runs (D912). So the tile shows what the last check found, and Home is no slower.

### 2. The section mapping is `sectionOfField`, reused

The per-section mapping was already `sectionOfField` in `services/narrative/claims.ts`, which the Claims tab uses. The tally calls it on each Mismatch's field (the part before `#`). No new read or table.

The route hands `sectionOfField` to `narrativeHome` (`sectionOf`), and `claimTally.ts` imports nothing of `claims.ts`, for two reasons. `claims.ts` imports `raiseCycle.ts` at load, so a static import from the tally closes an import cycle and leaves `raiseCycle.ts`'s constants uninitialised (it failed exactly so in the test runner). And any import of it, even a dynamic one, gives `raiseCycle.ts` a path through `store.ts` and `raiseWriters.ts` to the deck routes and on to Stripe and Mercury code, which the fund modules' import guards forbid (`fund_modules_no_stripe_d707`, `fund_admin_overview_d714`, both of which reach `raiseCycle.ts` through `cycleActivity.ts`).

### 3. What counts

- **Backed** is the `backed` state; **total** every claim stored for the version. The tile reads "n of m".
- **Nothing checked** (`total` 0) is a dash with "Nothing checked yet in vN". An unreadable store is a dash with "The claims could not be read." A part with no tally (an older Worker) keeps D909's sentence. The tile never shows 0 for unknown; "0 of 5" is a checked zero.
- **An open Mismatch** is any claim in the `mismatch` state. A Mismatch kept with a note stays a Mismatch (D900 §10: neither figure is presumed right), so its section keeps the dot.

### 4. The dot is the newest version's only

The tally is for the newest version, so Story draws the Mismatch dot only when it shows that version. On any other version, or when the module read fails, no section claims a Mismatch, and the dot falls back to Written or Stale. Empty still wins: a section whose words are cleared in the draft shows Empty. Mismatch wins over Stale. Story reads the module read again when it reloads after Save version.

Story reads the module read itself (`StoryTab.jsx`), not through `NarrativeTool.jsx`, so this change stays clear of #5074's edits there.
