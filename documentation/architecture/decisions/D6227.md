## D6227 — One joined activity read for a portfolio company (#6227)

- **Status:** built. Worker route, client module and the company workspace's Activity tab.
- **Builds on:** D4817 part 6 (PF-06e, the Activity tab), D4636 parts 2 to 4 (who reads `/api/positions*`), D1058 (asks and waivers in `reporting_events`), D1059 (sent and corrected reports), D4642 (support history), #5847 (a failed query is not an empty list).

### What it decides

**One read joins the company's history.** `GET /api/positions/:projectUid/activity` returns one company's activity, newest first. It reads six sources:

| Source | Rows | Store |
|---|---|---|
| `investments` | each round | `portfolio_positions` |
| `marks` | each valuation mark | `portfolio_marks` |
| `distributions` | each realisation | `portfolio_distributions` |
| `reports` | each report revision the caller received as an investor: revision 1 "received", later ones "corrected" | `portfolio_updates` × `update_recipients` |
| `requests` | the caller's own asks and waivers | `reporting_events` (`asked`, `waived`; `actor_user_id` is the caller, on a duty the caller holds) |
| `support` | each entry's promised, delivered and withdrawn dates, and each recorded amendment | `portfolio_support_entries`, `portfolio_support_entry_events` (`amended`) |

Each row is `{ id, kind, at, date, label, source, link, amount? }`. `id` is `<kind>:<uid>`, so it is unique. `link` names the workspace tab that holds the record (Financials, Reports or Support), so the timeline sends a reader to the record without new addresses.

**The route lives in its own file.** It is `cloudflare-worker/src/routes/position_activity.ts`, exporting `mount` at `/api/positions` with `before: [positions]`. Three open pieces of work touch `positions.ts` (#5847, PR #5854 and proposal 7), so the only change there is `export` on `positionScope` and its type. The route is mounted inside the same STUDIO_PREFIXES gate, and no `/:projectUid` handler can shadow it.

**Scope is the detail read's, step for step.** Admission uses `positionScope`:
- 403 with neither the licence nor a fund;
- 404 for no such company;
- 403 for a company outside the caller's scope.

A company reached only as GP of record reads its funds' rounds, marks and distributions (and the firm-level marks), as `GET /api/positions/:uid` does. The test asserts the two routes give the same status for the same caller and company.

Reports and requests are the caller's own by construction. Support is read under the ledger's own scope (`supportBookIds`, which needs `canViewLpData`). A caller outside that scope, such as a GP of record without the investor licence, gets the support source as `not_in_scope` with its reason, never as an empty list.

**Never another investor.** No row carries a user id, a recorder, an actor or a name. Another holder's asks and waivers are never read, and neither is a report sent only to another investor. A support entry is the firm's record about the company. It is shown as the Support tab and Value-add already show it: its summary, without who recorded or amended it.

**A failed source is reported (#5847).** Each source's query is caught on its own. A failure is answered in `sources[]` as `{ source, state: 'failed', reason }`, and `partial` is true. The other sources' rows still come back. The raw database error is never returned. A source that answered is `{ state: 'ok', count }`.

**Pages are stable.** The order is `at` descending, then `id` descending, which is a total order. `?limit=` takes 1 to 200 (50 by default). `?before=` takes the previous page's `page.next_cursor`, base64url of `at` and `id`. A cursor that does not decode to that shape is a 400. A page's `total` counts only the sources that answered. Per-company volumes are small, so each source runs its own bound query and the merge happens in the Worker.

### The client and the tab

- `frontend/src/lib/api/positionActivity.js` exports `positionActivityApi.companyActivity(uid, { limit, before })`.
- The Activity tab (`CompanyActivity` in `CompanyPanels.jsx`) draws one timeline from this read. It keeps the All, Financial, Reports and Support switch, which now narrows the one timeline by source group.
- A failed source is named in its group with its own Retry. That Retry reads the joined feed again, because one read now carries every source. A whole-read failure says Unreadable, with Retry. When a failed source leaves a group empty, the group reads "Nothing is recorded in the sources that answered", not "no activity".
- Older pages are read on request ("Show older activity") from the cursor.
- The tab no longer reads `GET /api/positions/:uid`, the reporting read or the support ledger for Activity. The model's per-source `financialEventsOf`, `reportEventsOf` and `supportEventsOf` are removed, and `activityOf` and `activityRow` replace them.

### Not in it

- A chase written by the old `portfolio_update_chases` path without a `reporting_events` row. Asks since D1058 write both.
- Health snapshots, saved views and request-a-mark. These are separate D4817 items.
- Who recorded a mark or a support entry. The rows never name a person.

### Tests

- `cloudflare-worker/test/position_activity_d6227.test.ts` (real schema, real routers) covers:
  - the mount;
  - ordering across all six sources;
  - paging by cursor with no repeat or gap, including a tie on one date, and a forged cursor answered 400;
  - scoping: another holder's ask, waiver and report are absent, and no name or user id is returned;
  - admission equal to `GET /api/positions/:uid`;
  - one failed source reported as failed while the others answer.

  The mutations checked, each failing with the mutation and passing without it, are: oldest first; an inclusive cursor; no id tie-break; the `actor_user_id` filter dropped; the recipients filter dropped; the visibility check skipped; a failed query answered as `ok`; one source dropped.
- `frontend/test/portfolio_company_d4817.test.mjs` test 6 covers populated with an older page, empty, and one source failed with its Retry. Tests 1 and 3 are re-aimed at the joined read. Its header lists five mutations.
