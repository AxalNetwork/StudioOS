## D5057 — One licence identity for the operator and user licence families (#5057)

- **Status:** built by S21, 2026-11-09 (#5057, user licences 1/4 under #5047). PR: see the issue.
- **Number:** D5057 is this issue's number (D4106). Migration: `202611090932_shared_licences.sql`.
- **Files:** the migration; `cloudflare-worker/src/routes/admin_licences_ledger.ts` (the create route's reference
  clash now spans both families); `routes/admin_licence_agreements.ts` (`licence_identity: 'shared_licence'`);
  `services/programAgreements.ts` (header); `cloudflare-worker/test/shared_licences_d5057.test.ts`; two lines of
  `test/licence_program_agreements_d5048.test.ts` (below); `cloudflare-worker/sql/README.md`.

### 1. What was decided

`licences` is the registry of every Axal VC licence. A row says which **family** (`operator` or `user`) and
**type** it is, who holds it (`holder_type` `entity` or `user`, `holder_id`), its status and dates
(`starts_on`, `ends_on`, `renews_on`), a `revision`, where it came from (`origin`) and who and when.

| Family | Types |
| --- | --- |
| operator | `territory` (the subsidiary/franchise licence), `white_label`, `master_franchise` |
| user | `founder`, `investor`, `operating_partner`, `advisor` |

- **Administrator is not a family.** It stays a binding (`licence_admins`). The family and type CHECKs refuse it.
- **The family is the type's**, held by a CHECK; an operator licence is held by an entity (CHECK).
- **No user licence is a territory.** Only an operator `territory` or `white_label` licence may point at a
  `territory_licences` row (CHECK on `territory_licence_id`). Founder, Investor, Operating Partner and Advisor
  licences are rows of their own, with no territory row.
- **The identity is frozen** (uid, ref, family, holder, territory row, origin, created_at; trigger), every change
  to type, status or dates moves `revision` by exactly one (trigger), and no row is deleted (trigger).
- **Status is a shape, not a list** (`[a-z_]`, 1–40). For an operator licence the territory row's own CHECK closes
  it; the user-licence lifecycle is #5058's to define, and a closed list here would cost it a table rebuild.
- `user_licence_details` is **not** created: nothing needs user-licence-specific columns yet (#5058 adds them when
  it does).

### 2. The mapping: the territory licence's own uid, and an explicit pointer

A territory licence's shared row takes **the territory licence's own `uid` and `licence_ref`**, and names it in
`licences.territory_licence_id` (UNIQUE, so one-to-one both ways). A trigger (`licences_territory_identity`)
refuses a mapping under any other uid or ref.

Why this rather than a new uid with a `territory_licences.licence_uid` column or a mapping table:

- `territory_licences` takes **no ALTER**, and every route, URL and row that names a territory uid keeps working,
  because that uid *is* the shared uid.
- `licence_program_agreements.licence_uid` (D5048) already holds territory uids. D5048 §2 planned to repoint it
  "with one UPDATE", but its own freeze trigger refuses any change of `licence_uid` and any update that does not
  move `revision` by one, so a rewrite would have bumped the revision of every agreement (executed ones included)
  and written a history line for nothing. With the same uid, every existing agreement **already** names its shared
  licence, and no row is rewritten.
- A separate mapping table would add a join to every read for a relation that is one-to-one and fixed at birth.

### 3. The migration

1. `CREATE TABLE licences` with the CHECKs above, two indexes and four triggers.
2. **The backfill:** one row per `territory_licences` row (`origin = 'backfill_d5057'`), skipped when the licence
   already has one, so the file applies twice with no change. `kind` gives the type (`subsidiary` → `territory`,
   `white_label` → `white_label`); `holder_id` is the territory row's `entity_id`, or `territory_licence:<uid>`
   when the licence names its party only by legal name (no `entities` row): the party that territory licence
   names, rather than an invented entity id. `ends_on` stays NULL (a territory licence records no end date).
3. **New territory licences:** `territory_licences_shared_identity` (AFTER INSERT) writes the shared row
   (`origin = 'territory_licence'`) **in the same statement** as the insert, whatever path inserts it (the HQ
   create route, a seed, a fixture), so the one-to-one mapping cannot be skipped by a new insert path. The create
   route keeps its one statement; its reference check now also refuses a reference a user licence holds (409),
   which the shared row's UNIQUE `licence_ref` would otherwise refuse as a 500.
4. **Status and dates follow the territory row:** `territory_licences_shared_mirror` (AFTER UPDATE OF status,
   starts_on, renews_on, kind) writes them, and the type, onto the shared row in the same statement, moving its
   revision by one. SQLite's change count excludes trigger rows, so every revision-guarded lifecycle write
   (D4678) still reads `changes = 1`.
5. **Agreements anchor on the shared uid:** `licence_program_agreements_shared_licence` (BEFORE INSERT) refuses
   an agreement whose `licence_uid` names no `licences` row. Every writer today passes a territory uid, which has
   its shared row, so no reader or writer changes; a user licence can anchor an agreement too.

**Not copied:** no commercial or territory field (fees, shares, currency, term, entity names, signatory, kind,
territories, seats). `territory_licences` stays authoritative for all of them, and the shared row's status and
dates are written only by the territory row's own writes.

### 4. What is not done here

- No lifecycle, pricing, contract or invoice behaviour changes; no route reads `licences` yet except the create
  route's reference check.
- No user-licence routes, lifecycle, details or UI (#5058, #5059, #5060).
- `licence_contracts`, `licence_fee_invoices`, `licence_terms`, `licence_events` and `program_grants` keep their
  territory keys. Since the territory uid is the shared uid, the `licence_uid` they hold already names a shared
  licence; moving their integer `licence_id` keys is a later issue's.
- The shared row records no `updated_by_user_id` for a territory write: the trigger cannot know the actor, and
  `licence_events` already records it.

### 5. D5048's test

Two lines of `licence_program_agreements_d5048.test.ts` change, neither weakened: test 2's second licence
(`lic_other`) is now inserted as a territory licence, because an agreement must name a shared licence; test 7
asserts `licence_identity: 'shared_licence'`, the value D5048 §2 said #5057 would replace.

### 6. Tests

`cloudflare-worker/test/shared_licences_d5057.test.ts`:

1. the migration on a database holding three territory licences (one white-label, one terminated, two without an
   entity row) writes exactly one shared row each, with the territory uid and ref; a second application changes
   nothing; every row of `territory_licences`, its territories, seats and events, `licence_contracts`,
   `licence_fee_invoices`, `licence_terms`, `licence_program_agreements`, its events and `program_grants` is
   unchanged; no commercial column exists on `licences`;
2. the four user licences and a master franchise are rows of their own; a user licence as a territory, an
   administrator family or type, a family disagreeing with its type, an operator licence held by a user, an unknown
   holder type, a shared reference and a territory mapped under another uid or ref are each refused;
3. the identity is frozen, the revision moves by exactly one, nothing deletes;
4. `POST /api/admin/licences` writes the shared row with the territory licence; a reference a user licence holds is
   a 409; a status and renewal change is followed on the shared row while the territory write still changes one
   row; a commercial edit does not touch it;
5. a program schedule sent from Program access names the shared licence and reaches its territory row through it;
   the agreements read answers `shared_licence`; an agreement naming a user licence is accepted and one naming no
   shared licence is refused.

Each guarded line was reverted in turn (the backfill's skip, each CHECK, each trigger, the holder fallback and the
route's clash query) and a test failed for each.
