## D647 — Contracts access and reliable reads

Issue #1441, S18 (direct owner request), 2026-10-08. Part of #1441.
No migration. This first slice implements the independently authorized Worker
reads and access bridge while the new canvas data and publication definition
are pending. It does not claim the standalone redesign is finished.

### Reads

The four-source union keeps its existing offset and total contract. Validated
limit (1–500), offset (0–1,000,000), search (200 characters), sort and direction
now refuse malformed inputs with 400. Sorting precedes paging, missing values
stay last in both directions, and source/id/uid break ties. Supported sorts:
created_at, signed_at, title, recipient, days_to_sign. Filters include status,
party_role, provider, project_id, template and signed_recent=true. Viewed remains
awaiting signature; rejected remains void. Recent signatures exclude future
dates. Invalid or backwards signing dates are unknown, rather than zero days.
The date metric uses the existing created_at measurement, not a newly recorded
send event. The union is still loaded and filtered in memory; these are not
snapshot pages. A failed source read returns 503 without an invented count.
Other legacy loadAllContracts consumers retain their existing best-effort mode.

E-sign company and project fields now join deal→project. GET /recipients and
/deal-options provide minimal, counted, paged picker rows, with bound literal
searches. Recipients are active accounts; plain admins see non-admins and their
own account, while canonical Super Admins can see all active accounts. These
reads expose no signing tokens, credentials or provider configuration.

GET /templates/store/:slug/fields derives deduplicated input keys from the
actual stored body, classifying existing automatic merge keys separately.
Inactive, stub, blank and missing templates return 404. Publication is explicitly
not_recorded: active is not asserted to mean published. The published-only
wizard and send-version check await the owner/S1 definition on #1441.

### Access bridge

Both admin shells route to /admin/contracts. /admin?tab=legal redirects before
mounting the console and displays a moved notice. Existing template and agreement
components are reused; no new screen layout is invented. The document-type
registry is gated on canonical Super Admin authority in the Worker and hidden
from plain admins in the shared page. Existing publish reason, step-up and
revision checks remain in force.

### Continuation after the first slice merged

The dead Incorporation tab and its empty promise are removed. One quiet link
opens the existing Programs › Spin-Out Lab page and tells the admin to open
its Formation orders tab; that page has no addressable sub-tabs today, so the
link does not claim an unsupported deep link. Empty agreement and template-usage
messages name the existing New envelope action instead of a nonexistent Profiles
tab. The guided wizard/publication definition and canvas-dependent redesign
remain pending; these changes reuse the existing panel layout.

The reused agreement list now renders the existing console Unreadable state
with Try again when its read fails, rather than the empty message. Retrying
shows loading, and a successful read clears the failure. Render tests cover
loading, successful empty, failed and recovered reads.
