## D5356 — Continue learning opens the lesson the learner left, at its saved position (#5356)

- **Status:** part 1 built (this PR). Part 2, whether exam choices and exercise drafts are held on the server, is the owner's question and is not built here.
- **Builds on:** D4646, D4648 (per-kind bounds on `GET /me`), D4650 ("Next for you").
- **Why:** #4646's criterion "Continue opens the appropriate lesson and resume position" was left unmet. `GET /me` course rows named no lesson, so Continue opened the course page.

### The rule, in one place

`services/learningResume.ts` gives each in-progress course one resume lesson:

1. The learner's most recently updated lesson row in that course that is `started`, not completed.
2. Otherwise, the first required lesson, in outline order (module position, then lesson position), that the learner has not completed.
3. Otherwise, none: the row keeps its course link.

A lesson is a candidate only while all of these hold:

- it still exists in that course;
- the course is published;
- for a video or reading, the item it opens is published.

So a removed or unpublished lesson is never named, and the link is never dead. The next rule answers, or the course page does.

The saved position is the learner's own item row for the lesson's video or reading. D4646 writes the position there. When none is recorded, it is null.

**One rule for two surfaces.** `GET /me` and "Next for you" (`learningNext.ts`, rule `continue_course`) both call `resumeLessons`. They cannot point to different lessons for the same course.

Before this change, "Next for you" named the first required lesson not completed. It now names the last started lesson first. Its reason text, `<n> of <m> required lessons complete.`, is unchanged.

### Bounds and privacy

There are two fixed statements, each `LIMIT 2000` across every in-progress course of the caller. Every user id they bind is the session's own: the course rows, the lesson rows and the position. So another learner's rows are never read, and a test seeds a peer to check this. They sit beside D4648 part 2's per-kind bounds on `GET /me`, which are unchanged.

### Frontend

- **Lesson link.** `meRowHref` sends a course row that has a resume lesson to `/learning/courses/<slug>/<lesson>`. That is the same lesson page "Next for you" opens. A row without one keeps `/learning/courses/<slug>`.
- **Position.** The lesson page's own item read carries the saved position. The player's existing resume (`resumeAt` → "Resume from 04:12") starts there, so no position travels in the URL.
- **Wording.** Continue learning, on desktop and on the phone row, says "Resume <lesson> at 04:12". When no position is recorded, it says "Resume <lesson>" with no time.

### Changed fixture

`learning_next_4650.test.ts` seeded reading lessons that pointed at an item that did not exist. A lesson is now resumable only while its reading is published, so the fixture creates that reading. The test's assertions are unchanged.
