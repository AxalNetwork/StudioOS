## D641 — AI usage reads: spend by model, the last 30 days, task labels and the rate card

**Issue:** #1434, part of #1430 (the Usage page). **Built by:** S07. **Migration:**
none. The day series reads a range on `created_at`, which the existing
`(user_id, created_at)` index serves, so migration 431 was not needed.

Worker only. S09 builds the screens.

### What was true

- **No split by model and no daily series.** `GET /api/ai/me/spend` returned
  today, the month, the last run, `by_task` and `by_surface`.
- **No route served the prices.** `GET /api/ai/pricing` gives the rail its
  routing table and the per-token prices, but nothing listed the audio rate or
  said which model is kept only for past runs.
- **Task classes had no readable names.** They were bare identifiers
  (`TaskClass` in `services/aiRouter.ts`).

### What is true now

**`GET /api/ai/me/spend` adds three things:**
- **`by_model`**: this month per model, dearest first, each with:
  - `calls` and `spend_usd`;
  - `prompt_tokens` and `completion_tokens`, each summed only over the rows
    where D401 counts that direction: a live call (not cached, not refused)
    whose recorded figure is positive. This is the rule `last_run` already
    used.
  - `uncounted_calls`: the calls whose zero in either direction is not a
    count. That covers cached answers and refusals (no model ran), streamed
    replies (no completion side is read) and transcriptions (billed by the
    minute). Their calls and cost are in the totals; their tokens are in
    neither sum.
  - `cached_calls` and `fallback_calls`.
- **`days`**: the last 30 UTC days, oldest first, today last, each
  `{ day, calls, spend_usd }`. A day with no run is a recorded 0.
- **`label`** on every `by_task[]` entry and on `last_run`, from
  `TASK_LABELS` in `services/aiCatalog.ts`. It is typed
  `Record<TaskClass, string>`, so a new task class without a label does not
  compile. A row whose task the router no longer has gets `label: null`, never
  a guessed one.

**A failed read is not an empty list.** When either new read fails, it is
`by_model: null, by_model_recorded: false` or `days: null, days_recorded:
false`. When the totals themselves are unreadable, neither runs and both stay
unrecorded. A caller with no runs gets a recorded empty `by_model` and thirty
recorded zero days.

**`GET /api/ai/rates`** (any signed-in member) is the rate card, under
`models`, one row per model in either of the router's price tables:
- `{ id, name, in_per_1m_usd, out_per_1m_usd }` for a token model;
- `{ id, name, per_audio_minute_usd }` for an audio model;
- `retired: true` on a model kept only so past runs keep their cost
  (`@cf/meta/llama-3.1-8b-instruct`, deprecated 2026-05-30).

The figures are read from `PRICE_USD_PER_1M_TOKENS` and
`PRICE_USD_PER_AUDIO_MINUTE` on every request, never copied. The names are in
`MODEL_NAMES` and the retired set in `RETIRED_MODELS`, both in `aiCatalog.ts`.

**One price is 0 by fact, not by omission.** The embedding model's output price
is 0 because an embedding produces no output tokens. Every token model has an
input price above 0, every model that produces output has an output price above
0, and every audio model has a minute price above 0.

### Verified

**`cloudflare-worker/test/ai_usage_reads_d641.test.ts`**, on node:sqlite with
a fixed clock and a seeded log:
- **`by_model`** is pinned field by field. A cached row, a refusal (with a
  recorded completion figure), a streamed row and a transcription each count as
  uncounted, never as 0 tokens. Last month, tomorrow, another user and an
  unattributed call are excluded.
- **`days`:**
  - it has 30 entries, today last;
  - a day with no run reads 0, and a day in the previous month is in the
    window;
  - the 31st day back and tomorrow are out;
  - `lastDays` crosses month and year ends.
- **Labels:**
  - every `ROUTE` task has one, and none uses the words the voice rule bars;
  - `by_task` and `last_run` carry them;
  - a removed task and an inherited property name get `null`.
- **Failures:** a failed per-model or per-day read is `null` with
  `recorded: false`, and so is a log that cannot be read at all.
- **The rate card:**
  - it lists every model in `ROUTE` and in each `fallbackChain` and
    `alternates`, none of them retired;
  - every priced model appears once, with the table's own figures, and follows
    an edit to the table;
  - no price is 0 except the embedding output, and every model has a readable
    name;
  - the route serves the card to a member and nothing without a session.

Every new assertion is mutation-checked. 32 mutants were run and 30 caught. Four
more survived a first pass and were closed by strengthening the fixture: a
refusal with a non-zero completion, and a second fallback call so cached and
fallback counts differ. The two survivors are equivalent: they remove the
bounds on the day query. The thirty day keys alone decide which days appear,
so the bounds only let the index serve the read.
