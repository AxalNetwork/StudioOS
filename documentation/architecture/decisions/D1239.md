## D1239 — Deal flow part 3: personal thesis fit and saved views (#3252)

Built for S28, 2026-10-26. Part of #2423. Migration 619 adds saved settings;
fit is computed on read and has no score table or recompute writer.

### Personal fit

`services/thesisFit.ts` compares four criteria: sector, company stage, recorded
market region and the deal's recorded minimum cheque against the caller's structured
`investor_profiles` preferences. Free-text thesis prose is not interpreted.
The result is a personal comparison, not one of SCORING's eleven scopes, an
Overall, or a change to any venture score.

Each comparable criterion has equal weight. The score is the rounded percentage
of comparable criteria that match. Missing/unset criteria do not count as a
mismatch; if none can be compared the score is null. All four absent thesis
preferences read `not_set` / **Set your thesis**, never zero. An observed mismatch
on every comparable criterion can correctly produce zero.

Confidence is recorded comparison coverage out of the four criteria, not a
prediction of investment success. High starts at 0.70, Medium at 0.45, otherwise
Low. Each criterion carries its state, fixed reason and source. Excluded sectors
and stages override positive preferences. Sector and stage compare normalized
recorded labels; no company lifecycle/funding-stage equivalence is invented.

SCORING #2428 cites Grow's `markets` as Geographic facts. This reader uses their
validated `geography_ref` country links and `research_countries.region`, for
served, entering and considering markets. It never parses `projects.hq` or an
address. Research's Latin America maps to LATAM, Asia/Oceania to APAC and Middle
East to MENA; the other existing regions keep their labels. These are the
recorded Research classifications, not a country-risk score or an inferred HQ.
An unmapped market prevents a negative region conclusion, while a recorded match
can still establish a match. No recorded geography remains **Not recorded**.

The ticket criterion reads `deals.minimum_check` in recorded USD and tests
whether that cheque floor exceeds the thesis's maximum ticket. A floor below the
investor's preferred minimum is not a mismatch: they can write a larger cheque.
A thesis minimum alone cannot constrain a floor, so a missing maximum, minimum
check or comparable currency is **Not recorded**. This is minimum-cheque
compatibility, not an allocation or promised participation. The whole round's
`target_raise`/`amount` is never treated as the ask of one investor. No exchange
rate or unrecorded allocation is supplied.

`GET /api/deals/fit?ids=` accepts up to fifty IDs. It uses the existing
`userReadableDealIds` invited-or-committed rule and Professional gate. A saved
view, seat relationship, shared company link or room membership never opens a
deal. Unknown, deleted and unauthorized IDs have the same unavailable projection.
Authorized rows keep their fit even when another requested row is unavailable or
one source row is malformed. Geographic facts are fetched in one bound query for
the whole batch; a query failure marks that fit block Unreadable. The caller's
own thesis is used, including for seats.
A malformed thesis/store read is **Unreadable**, never an empty preference list.

### Saved views

Migration `619_deal_saved_views.sql` holds opaque uid, author, firm-account owner,
nullable company, name, sharing/default flags, bounded JSON spec, version and
write nonce. It stores settings only; the spec is never executed as SQL or used
as an access grant. It may retain filters, columns, scope, presentation, sort and
personal weights; it never changes a score.

`routes/deal_views.ts` provides `GET/POST /api/deals/views` and
`PATCH/DELETE /api/deals/views/:uid`. They are investor-only, Professional,
no-store reads/writes, with no staff or support-session bypass. Shared views
require the existing active Institutional firm-seat account. A seat's primary
account and accepted, unrevoked seat row establish the firm; a company link
alone does not. The primary's verified company selection narrows the scope.
Multiple companies require an explicit verified choice, and forged headers
refuse. An older account without a company can still share with its own seats;
a null company never means all firms.

The optional `context=unbound` query selects the account’s original null-company
settings explicitly, even after one or more company links are added. It is
supported by all four saved-view methods and overrides the default company
header only for that null scope. No settings are copied between companies.
`context=archived` lists only the caller’s own settings whose company is no
longer linked to the same firm account. It supports read and versioned deletion
for cleanup, never creation, edits or sharing. Another author’s rows stay private,
and a revoked seat cannot enter either context. Linked companies still require
the verified company header when more than one is present.

Only the author edits/deletes. A shared row is read-only for a colleague, whose
default remains personal. A former seat cannot keep reading/writing that firm's
settings. Shared reads also recheck the author’s active, accepted, unrevoked seat;
a departed member’s shared views disappear from the firm list. Writes recheck
accepted/unrevoked membership inside the batch.

Create/edit, clearing the author's previous default, setting the new default and
recording an identifier-only audit share one D1 batch. Unique indexes enforce
one default per author/firm/company, including null-company contexts. Edits and
deletes require the version the client rendered. Replacing a default advances
the previous default’s version too; untouched non-defaults keep theirs. A version
CAS refuses stale
edits; a fresh server read never substitutes for that version. Later statements
require this operation's write nonce,
so a refused update cannot clear a default or leave a false audit. Delete and its
audit are atomic. A failed audit rolls back the entire operation. Names, filter
text, weights and financial figures never go into audit details or errors.

The client is `frontend/src/lib/api/dealViews.js`, re-exported once from api.js.
The route is mounted before the existing deal router. Its middleware is confined
to fit/views paths, preserving the existing deal handlers' policies. Page
integration/layout belongs to the Deal flow frontend parts; this task supplies
their API contract.

### Validation and UNVERIFIED live checks

Real SQLite tests apply migration 619 whole and twice, then cover allowed and
refused seats/firms, private/shared reads, author-only writes, revoked/lapsed
seats, forged/ambiguous companies, per-user defaults, stale versions, audit
rollback, in-flight revocation and spec limits. Fit tests cover all four inputs,
measured zero, missing/unset/unreadable states, currency, exclusions, personal
theses, protected/deleted IDs and independent row failures. Client tests cover
request methods, encoding and bodies. Mutation and full-gate results are in the PR.

After merge/deployment, the owner's live check remains **UNVERIFIED**: a colleague
reads a firm view but no private view; another firm sees neither; revoked seats
lose access; defaults are personal; fit reflects the signed-in investor's current
thesis and recorded facts. No production member content, bank/provider API or AI
was used for these tests.
