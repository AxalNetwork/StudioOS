## D5503 — Current-schema integration fixtures use isolated cached copies (#5503)

The first adoption batch uses `_schema_once.mjs`'s full baseline plus every
applicable migration. `openSchema` copies the existing cached file into a private
fixture directory and opens a handle with the caller's SQLite options. Closing
removes only that copy; a process-exit fallback cleans up older callers that did
not close their memory-only handles. SQL errors are never swallowed while
creating the cache or opening its copies. No production schema is changed.

### Local evidence

All databases and identities are disposable and synthetic. Four original suites
passed 64/64 before conversion (12.61 s). An initial full in-memory load passed
68/68 (26.52 s); private file copies passed 68/68 (15.12 s), including four new
cases. Test counts differ, and concurrent full-suite work adds machine load;
these observations are not a capacity promise or identical-workload speed claim.

A separate ten-copy measurement under that load recorded a cold schema build of
21.17 s, a warm key lookup of 98.71 ms,
mean private-copy open/close of 98.03 ms and mean full
in-memory load/close of 1093.42 ms. The cache avoids
repeating migrations; file copies avoid replaying every table/row per case.

`cached_route_fixtures_5503.test.ts` verifies post-baseline application once,
overlapping baseline/migration failure, missing objects, cross-process row
isolation, option preservation, close ownership and process teardown. Existing
`schema_once_d4133.test.ts` retains full schema/row equality and cold-build race
coverage. The new canonical audit case fails against the old inline fixture;
removing migration application or swallowing overlap also fails. Every new
assertion is inverted and restored. Existing route business assertions remain.

This batch does not declare every partial fixture in the repository migrated.
The shrink-only clock inventory and date behavior belong to #5504; no time
policy, published schema or production data is changed here.
