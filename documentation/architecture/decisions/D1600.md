- **Boards:** pd2b (Build · live progress, the failed rows' retry), pd2c (the return banner), pd9n (Areas finish one by one, "Busy, retrying").
- **Basis:** `origin/main` at `bef8cc00e2`, with #3753 (D1502, the run runtime) on it.
- **Migration:** `752_deck_area_batches_seen.sql`, as the issue wrote it: `seen_at`, `notified_at` and `parent_batch_uid` on `deck_area_batches`, and the `(deck_id, state, seen_at)` index. 752 was still free on main.

### 1. Retry only the failed areas

`POST /api/decks/areas/batches/:uid/retry-failed`, in `routes/deck_batches.ts` beside resume and cancel, with the work in `services/decks/batchFollowUp.ts`.

- **Who.** Only the member who started the run. Anyone else, a co-founder included, gets 404 `run_not_found`, the same answer a stranger gets from resume, because the run's quote is its starter's.
- **The key.** `Idempotency-Key` is required: 8 to 64 letters, digits or `. _ : -` (the characters #3753's start takes). Otherwise 400 `invalid_idempotency_key`.
- **What is retried.** A run's family is its first run and every retry of it. `parent_batch_uid` always names the first run, so a retry of a retry links to the first run too. A line of the plan (its card, area, element, kind and task) is failed when its newest step in the family that ran failed. A stopped step never ran, so a cancelled retry leaves its lines failed. The retry copies those lines, with the model, the request and the rail option each had, into a new run. `{ areas }` narrows it to the failed ones among those areas. Lines that succeeded are never in it.
- **The answers:**
  - 200 `{ batch_uid, retried: [area_id], quote: { microusd } }`. The new run is admitted through `admitDeckRun`, so resume, cancel and the stream work on it unchanged.
  - 409 `nothing_to_retry` when no line is failed.
  - 402 `hold_exhausted` with `{ quote: { microusd }, hold_remaining_microusd }` when the retry's quote is more than what the family has not charged of the first run's quote. Nothing is held or run; the page asks for a new quote through the start route.
  - 400 `invalid_areas` for a body that is not `{ areas: [string, …] }`.
  - The same key again answers the first answer, read back from the run it made, and charges nothing, even after that run ended.
- **The quote** is the sum of the retried lines' quotes. Each line was priced by `quoteRun` when the first run was admitted.
- **The limit is enforced twice.** The route compares before admitting. `D1GenRuntime.admit` takes `parentBatchUid` and writes the run only while its quote fits the family's remainder, in the same insert that checks the deck is free. Two retries racing therefore never both spend the same remainder; the loser's hold is given back.
- **Rate.** Retrying starts a run, so its path joins the `deck_generate` bucket (`DECK_GENERATE`).

### 2. "Busy, retrying" (pd9n)

- **The event.** `DeckGenRoom.retrying` streams `area_retrying { area_id, attempt, next_at }` (with the step's card, element and seq, and the running charged-of-held) before each automatic retry of a busy model. It also keeps D1502's `area_busy`, for its readers.
- **The limit.** A step makes at most `MAX_AREA_RETRIES` (3) automatic retries in all, counted across D1503's same-tier fallback. After that it fails `model_busy` and its area reports `area_failed`, which the route above retries. Each model still gets at most `MAX_BUSY_RETRIES` (2).
- **Busy.** A 503 now counts as busy, beside 429 and 3040, as the issue says.
- **Image steps.** A `deck_image` step runs D1505's image pipeline (`pipelineStep`, merged on main while this was built), which has its own redraw and does not pass through this backoff loop, so it emits no `area_retrying`. A failed image area is still retried by the route above.
- **The charge.** A retry runs under the step's one record ref and the parent hold, so the step is charged once, when it lands: what its usage rows say, clamped to its line.

### 3. "Finished while you were away"

- **The notice.** A run that ends `done` while no stream takes its `batch_done` writes one in-app notice (`noticeBuildDone`). "No stream takes it" means no attached stream accepted the write, so a closed tab whose stream errors counts as away.
  - The `notified_at` claim comes before the send, so two drivers or a restarted room send it once.
  - It goes to the member who started the run: type `deck_build_done`, category `fundraising` (not critical, so quiet hours and digests apply), in-app only.
  - Its title is "Your deck build finished" and its body "Its proposals are ready to review." The payload is `{ batch_uid }` and nothing else. No figure, card text or venture metric is in it.
  - The link is `/raise/pitch?project_id=<project_id>&proposal=<batch_uid>`, as S1 ruled.
- **The banner.** `GET /api/decks/:id/batches?state=done&unseen=1` answers `{ batches: [{ batch_uid, finished_at, cards_waiting }] }`.
  - It lists finished (`done`) runs whose `seen_at` is null, newest first, at most 5.
  - It is for the deck's writers (`projectOwned` with write); anyone else gets 404 `deck_not_found`. Any other filter is 400 `unsupported_filter`.
- **Seen.** `POST /api/decks/areas/batches/:uid/seen` sets `seen_at` once and answers `{ ok: true }`. Repeating it changes nothing. It is for the deck's writers; anyone else gets 404.

### 4. The client and the adapter

- **The client.** `frontend/src/lib/api/deckBatches.js` gains `retryFailed(uid, { areas }, idempotencyKey)`, `unseenBatches(deckId)` and `markSeen(uid)`. The module already existed (#3753) and is already in the generated API index; `node scripts/build-api-index.mjs` found it current.
- **The adapter.** In `deckV2Adapter.js`, only the bodies of `retryFailed`, `unseenBatches` and `markSeen` are swapped to `through(…)`. Each has a D1511 contract: `deckRetryFailed`, `deckUnseenBatches` and `deckMarkSeen`.

### 5. Departures

- **"Not a new hold."** The issue asks the retry to charge against the remaining parent hold, not a new one. But D1502's run settles its parent hold when it ends, and the rest of that hold is released then, so no hold is left to charge by the time an area can be retried.
  - What is built instead: the retry takes its own keyed hold for exactly its quote, and is admitted only while that quote fits what the family has not charged of the first run's quote.
  - So the family's total charge never passes the first run's quote, which is the property the issue asks for.
  - Keeping the first hold open until every failed area was retried would hold the member's allowance indefinitely, and the five-minute rule would release it anyway.
- **The quote is not re-priced.** It is the sum of the stored line quotes, which `quoteRun` priced at admission. Re-running `quoteRun` would need each area's original request shape, which the step keeps only as its executor input.
- **`cards_waiting`.** It counts the cards that hold a proposal from the run: a step that ended `done` and wrote a result. Accepting or dismissing a proposal is #3764's, not on main, so nothing yet marks one decided.
- **A failed or stopped run sends no notice.** The issue names `batch_done`; the notice says the build finished, so it goes only for `done`.
- **Retry access is 404, not 403.** Cancel answers 403 `not_your_run` to another reader, but the issue asks for 404 on retry.

### 6. Tests

**`cloudflare-worker/test/deck_batch_retry_d1600.test.ts`** has 10 tests. They follow the issue's table, plus the access rules:
1. 6 areas, 4 done and 2 failed: Retry makes 2 `run()` calls, and the charge equals the 2 areas' quote.
2. The same Idempotency-Key twice, and again after the child ran: one child run and one charge.
3. A hold set in the fixture leaves 800 against a 2,000 quote: 402 with both figures, and nothing held or run. The runtime refuses on its own too.
4. No failed area: 409. A bad key, a bad body, a non-failed subset, and the rate bucket's path.
5. A stopped retry leaves its areas failed, and a retry of a retry links to the first run (4b).
6. `batch_done` with a stream attached: no notice.
7. `batch_done` detached: exactly one notice, with no digit in its title or body and only the run's uid in its payload.
8. Seen, then the banner: the run is gone. Newest five only.
9. Another founder's run: 404 on retry, seen and the banner. A co-founder reads the banner but cannot retry.
10. `area_retrying` 1, 2 and 3 on 503s, then `area_failed` `model_busy`; a step busy twice then answering is charged its line once.
