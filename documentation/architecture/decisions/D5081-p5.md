### What was wrong

Raise's header drew Overview, Evidence, **Calls** and the seven modules as one flat row of peers, so Calls appeared both as a Raise tab and as Capital relationships' Calls tab, at the same address. The row named no stage, and the compact select repeated the same flat list. Fundraising readiness' header still offered Raise's global Build your deck, which D6049 kept for this issue to replace.

### The decision

1. **One desktop list under four stage headings** (RA-12): Prepare (Evidence, Fundraising readiness) · Build the story (Investor narrative, Pitch) · Prepare diligence (Data room, Cap table, Use of funds) · Run the raise (Capital relationships). Overview leads with no heading. The headings are headings, not routes: no address is added or changed. `RAISE_STAGES` and `cycleTabGroups` in `cycleModel.js` hold the rule; a module the read sends that no stage names is drawn after the stages under no heading, so a new module is never dropped, and a stage none of whose modules came back is left out rather than drawn empty. Every other cycle is one group with no heading and draws as before.
2. **The compact select is the only navigation below 1024px**, with the same stages as optgroups. The list is `hidden … lg:flex` and the select's label `lg:hidden`: each is `display: none` where the other shows, so only one is ever in the accessibility tree (RA-12: "hidden, not visually hidden"). This split was already D661's; part 5 pins it.
3. **Calls lives inside Capital relationships.** Raise's history entry (D1221) is removed from `CYCLES.raise`, so Calls is no longer a peer tab. It is Capital relationships' Calls tab, as it already was, at `/raise/capital-relationships/calls`; `/raise/calls` (retired D2319) still opens it and a sent call keeps `/raise/capital-relationships/calls/:uid`. Commitments is the tool's tab; Closing stays the address under the tool, opened from Commitments (D1213).
4. **Fundraising readiness' header action is its own** (RA-14): Fix next priority, opening the workflow of the first priority the page lists (`nextPriorityAction` over `priorities`). It is handed through D6049's `homes` entry as `action`; CycleRoute uses a home's `action` when it names one, with no new import. None while the read is not here or failed, and none when no assessed area needs attention, so the header never offers a fix the read does not name and never falls back to Build your deck.

### What the board draws that no read backs (reconciled against main)

Not built here, and nothing is made up in their place:

- **The list in the workspace sidebar** (RA-12 draws it nested under Raise in the left rail). The sidebar is the shared workspace shell (`workspaces/shellConfig.js`), whose Raise row lists zones for every role; moving the module list there is a shell change beyond Raise. The stages are drawn in the Raise header instead, which is where the module navigation already lives.
- **Folding Capital relationships' Overview into Pipeline** (RA-22 A, deferred by part 2) and **Cap table's four tabs** (RA-20, deferred by part 3). RA-12 asks for "one desktop Raise nav plus each tool's own tabs" and does not change a tool's tabs; each of those tabs has its own read, so they stay.
- **Closing as a visible tab.** Closing is an address under the tool (D1213); a tab with no round in closing would be empty, and Commitments already opens it.

### What #5081 still holds

- **Investor narrative owns its Home**, with **Save version** as its header action (RA-14's table). Its module page still draws the tool's Home tabs over the generic layer, and Save version belongs to the narrative editor's working version; both need their own part.
