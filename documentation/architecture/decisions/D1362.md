## D1362 — Record a Session: one Start for a call, and a call that reports back soon after it ends

- **Status:** decided by the owner on 2026-10-28; built by S21. The owner asked: "replace by a button that initiates both the zoom/google/teams meeting opening and then bot joining the session, then importing the call transcript. So at the bottom of record a session, just Cancel and 'Start'". The same message reported: "I started the call, then ended the session, but it never reported back to the interview session I created."
- **Migration:** none.
- **Builds on:**
  - D1346: create the meeting, and whether Eadwyn AI can join;
  - D1358: a meeting is captured by the platform, never by this browser;
  - D1359: Teams;
  - D1360: Eadwyn AI joins by default.

### 1. Why the owner's call did not report back

What production showed on 2026-10-28 for session 13, a Zoom call:

- **No bot run.** The dialog said "Eadwyn AI can't join calls yet on Axal": the availability read (`botAvailability`) answered no for Zoom. The owner confirmed `MEETING_BOT_ZOOM_CLIENT_ID` and `MEETING_BOT_ZOOM_CLIENT_SECRET` are set on the `studioos` Worker. `botConfigured` also needs:
  - `MEETING_BOT_SECRET`, at least 32 characters;
  - the bot container and `APP_URL`, which `wrangler.toml` declares;
  - the member to be a Super Admin while `MEETING_BOT = "canary"`.

  Which of these failed at that read is not known from here.
- **The call was saved for import, and the import never ran.** `channel_events` holds no Zoom event at all: Zoom's Event Subscription has never reached `https://axal.vc/api/channels/zoom/webhook`. Without its `recording.transcript_completed`, the only path was `sweepZoom`. That sweep looks at a call one day after the call should have ended. It cannot look earlier, because before Zoom has made the recording, the recordings read answers 404, and the import would settle the call as "no transcript".

### 2. One Start

For a meeting (Zoom, Google Meet or Teams), the dialog's footer is **Cancel** and **Start**. "Create the meeting for me", "Open the meeting", the disabled "Send Eadwyn AI" button and "Save for import after the call" are gone.

`callStartPlan` (`frontend/src/pages/founder/recordSetup.js`) decides, before the press, what Start will do:

| Plan | When | Start |
| --- | --- | --- |
| `import` | Zoom or Google Meet on the member's connected account | saves the call for import (`saveZoomCall` or `attachCalendarMeet`). The Worker also sends Eadwyn AI when it can join (D1360), so both the bot's recording and the provider's transcript are on the way. |
| `bot` | no import is possible (Teams, or no connection) and Eadwyn AI can join | opens the session and sends Eadwyn AI |
| `none` | neither | Start is off, with the reason (connect the account, or Teams cannot be captured) |

- **No link pasted:** Start creates the meeting first, on the member's own account (`instantMeeting`). Its link fills the field.
- **The meeting opens in a new tab.** The tab is opened inside the press, before anything is awaited, so the browser lets it through. It is pointed at the meeting once the call is saved (`meetingHref`: a parsed https URL on the provider's own host), and closed again if Start is refused.
- **`callStartNote`** says in one sentence what Start will do, including when Eadwyn AI cannot join that provider here.

### 3. Reporting back without the webhook

`sweepZoomEarly` (`services/channels/zoom.ts`) runs with the five-minute channel sweep. It looks at each Zoom call that started in the last twelve hours, is still waiting, and was last looked at more than five minutes ago. For each, it asks Zoom for the meeting's latest recording.

- **Queues the import only when:**
  - a recording is ready: a transcript, or the audio D870 transcribes;
  - and it started within the call's slot (`withinCallSlot`).
- **Settles nothing when** there is no recording yet, or Zoom is still processing it. A call is never marked "no transcript" early; that stays `sweepZoom`'s decision, a day later.
- **Cost:** at most ten calls per sweep, and one Zoom read per call.

The webhook is still the fastest path, and the owner should still set it up (§4).

### 4. Owner setup, outside the code

- **For Eadwyn AI on Zoom:**
  - the Zoom client ID and secret are set;
  - check that `MEETING_BOT_SECRET` is set, at least 32 characters;
  - while `MEETING_BOT = "canary"`, only Super Admins get the bot.
- **For Zoom's own transcript, at once:**
  - in the Zoom app's Event Subscription, set the endpoint to `https://axal.vc/api/channels/zoom/webhook`;
  - subscribe to `meeting.ended`, `recording.completed` and `recording.transcript_completed`;
  - make its Secret Token equal `ZOOM_WEBHOOK_SECRET_TOKEN`.
- **In the member's Zoom account:** turn on cloud recording with audio transcripts. Without them Zoom makes no transcript to import.
