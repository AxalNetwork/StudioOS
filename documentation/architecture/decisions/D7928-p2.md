**Decision date:** 2026-11-27. **Part of:** D7928 (`D7928.md`), which built the importer while bls.gov was
unreachable and listed what had to be checked before the owner enables `bls-ce`. This part records that check and
the changes it led to. The source stays **disabled**: enabling it is the owner's call.

### The file (confirmed)

`ceTableUrl` was right: `https://www.bls.gov/cex/tables/calendar-year/mean-item-share-average-standard-error/cu-area-type-<year>.xlsx`
exists for 2023, 2024 and 2025 (HTTP 200, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
23–25 KB each, far inside the 2 MB cap). `Last-Modified`: 2023 and 2024 both 2025-12-19, 2025 is 2026-10-29. 2025 is
the latest year published, so `LAST_YEAR` stays 2025. Each workbook has one sheet, `Table 1721`, at
`xl/worksheets/sheet1.xml` (about 150 KB), shared strings, a styles part, no formulas and no inline strings.

### The layout (what was guessed, what is true)

| D7928 assumed | The real table (2023, 2024, 2025) |
| --- | --- |
| Header `All consumer units` in one row, after column A | True: row 3, column B, written `All\nconsumer\nunits` (the label compare collapses the line breaks). |
| Item label in column A, then `Mean`, `Share`, `SE`, `CV(%)` rows | Label, then `Mean`, `Share`, `SE`, **`RSE`**. BLS calls the CV the relative standard error (`SE / mean × 100`). The total and a few non-spending rows have no `Share`. |
| The nine item labels | All nine exact: `Average annual expenditures`, `Food`, `Housing`, `Apparel and services`, `Transportation`, `Healthcare`, `Entertainment`, `Education`, `Personal insurance and pensions`, each printed once. |
| From 2023 a suppressed cell is **blank** | No value cell is blank. A withheld value is a **footnote marker** in the cell (`c/`, `d/`), and its meaning is printed in a legend under the table. |
| — | The letters **change meaning between years**. 2023: `b` a TAXSIM note, `c` suppressed (RSE ≥ 25 percent), `d` too small to display. 2024 and 2025: `b` RSE ≥ 25 percent, **published, "use with caution"**, `c` too small to display. |
| — | From 2024 the caution letter is not in the cell's text: the cell holds the number and its **number format** prints `b/` after it (`# \b\/;-# \b\/` and three siblings in `xl/styles.xml`). |

So D7928's reader would have read the real files **wrongly but quietly**: it found no `CV(%)` row, so every CV was
counted `not_published` and each batch stored 18 of 27 rows as a success. It would also have counted every `c/` as
unknown text and ignored the caution format.

### What changed

- `CE_STATS.cv.row` is `RSE`. The metric keys (`ce_<item>_cv`) and units stay; the mean's limitations now say
  "relative standard error (coefficient of variation)".
- **Fail closed on structure:** an item that is found but lacks any of its `Mean`, `SE` and `RSE` rows fails the batch
  `provider_payload`, so a renamed statistic row can no longer pass as "not published".
- **The legend decides:** `footnotes()` reads the column-A legend lines (`<letter> <text>`) and classes each letter as
  `suppressed`, `too_small`, `caution` or `other` by what it says; a letter printed twice fails the batch. A marker
  cell counts `suppressed` or `too_small` (a new counter); a marker the legend does not explain, a blank value cell or
  other text counts `unknown_cell`. None stores a row.
- **Caution flags:** `cellMarks()` reads `xl/styles.xml` and gives each cell style the footnote letter its number
  format prints. A number whose letter the legend calls caution is stored with
  `BLS flags this estimate: its relative standard error is 25 percent or more; use it with caution.` appended to its
  own row's limitations, and counted in the report's new `caution`; a number with any other letter stores no row
  (`unknown_cell`). A style index outside the styles part fails the batch.
- `User-Agent` as above. Styles part capped at 1 MB inflated.
- Migration `202611271256_7928_bls_ce_verified_terms.sql` (text only, with its forward fix, which keeps the source
  disabled): the source's usage note now states the read terms and the robot policy instead of "not read", its
  edition names Table 1721, and the nine CV definitions name the `RSE` row. `enabled` and `export_allowed` are not
  touched.
- The tests' invented workbooks now have the real shape: the multi-line header, an `Income before taxes` block, `Share`
  rows, `RSE` rows, `c/` and `d/` markers, a styled caution number, a styles part and the legend. No BLS value is in
  them. New cases: the same marker read two ways under a 2023-style and a 2024-style legend; an unexplained marker or
  format letter; the guessed `CV(%)` layout, a missing `SE` row, a duplicated legend letter and an out-of-range style
  each failing the batch; the User-Agent sent.

### Dry run against the real files (no D1 write)

A throwaway script fed each downloaded workbook's bytes to `workbookGrid` and `ceRows` (the importer's own reader) for
all nine items. The workbooks were kept outside the repository and are not committed.

| Year | Cells seen | Rows read | Skipped | Before this change |
| --- | --- | --- | --- | --- |
| 2023 | 27 | 27 | 0 | 18 (9 CVs "not published") |
| 2024 | 27 | 27 | 0 | 18 |
| 2025 | 27 | 27 | 0 | 18 |

Seven values were compared by hand with the sheet (2025 total mean and SE; 2025 housing, entertainment and education
mean, SE and RSE; 2023 food mean, SE and RSE): all equal. Each RSE equals SE / mean × 100 to the published rounding.
The legend read from each file: 2023 `{a: other, b: other, c: suppressed, d: too_small}` with 53 `c/` and 5 `d/`
cells; 2024 and 2025 `{a: other, b: caution, c: too_small}` with 11 `c/` cells and 11 (2024) and 40 (2025) numbers
in a `b/` format. None of those markers falls on the nine national all-consumer-unit categories.
