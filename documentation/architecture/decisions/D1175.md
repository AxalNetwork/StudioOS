## D1175 — Use-of-funds model v1 and scenario stores

Issue #3102, part 2 of #2455. S18 · Codex.

### Built

- Pure `services/useOfFunds/plan.ts`, with versioned assumptions as data:
  integer-cent allocation, hire payroll from its start month, remainder spread
  evenly over the target, spend/burn, timed cash receipts, cash out, a bounded
  runway forecast and milestone affordability. Every derived block is labelled
  Modelled with its input snapshot. This never supplies runway today or actual
  milestone completion, and never calls Eadwyn or Mercury.
- Migration 606: scenarios, five fixed nullable allocation lines and milestones
  with nullable cost (Not costed), scoped OKR links and #2431 provenance.
- Founder-scoped, bound, atomic one-time copy of the old base split, section
  milestones and OKR costs. A replay/concurrent call preserves founder edits;
  unreadable legacy data refuses the entire copy without erasing the source.
- A Base writer for #3103 that atomically retains the deck inputs in
  `projects.use_of_funds`, `funding_needed` and
  `use_of_funds_meta.runway_months`. No new project runway column is needed.

### Limits and verification

Missing values and unread lists stay Not recorded; explicit zero stays zero.
An uncosted milestone is never funded. Raise timing must be supplied; the model
does not put a target raise into cash today. An unexhausted model reports only
the supplied horizon's lower bound. Historical source labels are not guessed.

No route/page changes in this part; #3103 mounts these services and adds its
write audit. Existing legacy writers continue to serve the current page until
that cutover; it must route Base changes through the dual writer. Scenario
comparison and UI are #3103–#3105. New stores/services alone do not activate them.

milestone review, and subsequent route/page integration. No production data was
