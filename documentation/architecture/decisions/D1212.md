### 1. Where it lives

| Address | What opens |
|---|---|
| `/calendar/connected` | The connected calendars (CAL9) over the view it came from, else over Month. |
| `/calendar/connected/google` | Google's panel (CAL10). Closing it returns to the list. |

- Both routes sit beside the other calendar addresses in `App.jsx`, with the same guard.
- The code:
  - `pages/CalendarConnected.jsx`, the panels and dialogs;
  - `pages/calendarConnectedModel.js`, the rules, which are pure;
  - `lib/api/calendarConnections.js`, D1209's routes.
- **The rail** (CAL1) is now a summary: one line per calendar, with Manage. The old cards are gone, and with them the page's three `window.confirm` calls.

### 2. What is read

- **Google and Outlook:** `GET /api/calendar/google/status` and `/microsoft/status`.
  - The page reads each once and passes it down, so the push control, Meet on create and these rows all read the same answer.
  - **`failed` is persisted.** It comes from D1209's `sync_error`, so a cold load after an overnight failure now reads "Last copy failed". Before this part, only a sync the reader had just run could reach that state.
  - **`sync_error_read: false`** is said in words, never shown as a clean sync.
- **Calendly and Zoom:** the member's connections (`GET /api/connectors`), one row each.
  - An unread list reads "Could not be read", never "Not connected".
  - **A row's own `last_error` text is never drawn.** It is a provider's words and can carry an address. The state is "Last copy failed", and the row points to its connector page.
- **Subscribe:** `GET /api/calendar/subscription`, which says whether a link is on and never returns the link.

### 3. The connected calendars (CAL9, CAL21d)

- **Four rows,** in the canvas's order, each with its brand tile, sentence, pill and actions:
  - **Google:** Copy now and Manage, which opens the panel.
  - **Outlook:** Copy now and Disconnect…, which opens the dialog in §5.
  - **Calendly:** "Manage on the connector page ↗".
  - **Zoom:** "Open its connector page ↗".
  - Connect and Reconnect start the provider's own sign-in. Try again re-reads.
- **The six states:** Checking, Not set up on Axal yet, Not connected, Connected, Last copy failed · time · Reconnect, Could not be read.
- **What each option does:** Copy, Copy one item and Subscribe, in the canvas's words.
- **No count of copies is drawn.** No status read carries one, so the canvas's "12 copied, 1 failed" is not shown. Copy now reports the counts its own response gives.

### 4. Google's panel (CAL10)

- **The account:** the member's own Google account. It is the one email on these pages.
- **What Axal VC can do:**
  - add and update the copies: Always;
  - read the calendar: Allowed or Not allowed, from the stored scope;
  - Meet transcripts: from `meet_transcripts`;
  - the Google files: a link to `/account/connectors/google_workspace`.
- **The old Gmail grant,** when the scope still holds it, shows the canvas's amber note. Remove Gmail access opens a dialog that says what happens, then continues into Google's consent.
- **Disconnect Google** opens the dialog in §5.

### 5. The disconnect dialog (CAL10d)

One dialog for Google and Outlook.

- **The choice:** "Keep the copies already in your calendar" is the default. "Remove the copies first" sends `?remove_copies=1`.
- **A refused copy** (502 `copies_not_removed`) says so, and nothing is disconnected.
- **A refused Google revocation** says so and offers Disconnect locally (`POST /google/force-disconnect`). That button warns the member to check their Google Account's access list.
- **The count of copies is not read,** so the canvas's "Remove the [12] copies first" names none.

### 6. Subscribe (CAL11)

The header's Subscribe opens it. It replaces the `cal-wait-feed` line, whose wait is retired.

- **Make a link** is `POST /subscription`. The link comes back this once.
- **The link is shown hidden** (`…/feed/••••••••.ics`). Copy copies the real link. If the browser refuses the clipboard, the link is shown in a field the member can select.
- **A link that is already on** says when it was made and when it was last followed. It cannot be shown again, so making a new link is the only way to copy one.
- **Make a new link** replaces the old one, which stops at once. **Turn off** is `DELETE`.
- **The note:** "Anyone with this link can read your calendar. Do not share it." It shows only what the member is part of (D1209: Mine only).
- **Download .ics** is the existing one-off file. Its window is 7 days back and 180 days ahead, so "the next 6 months" holds.

### 7. The phone (CAL21)

- **Agenda is the default:** bare `/calendar` on a phone is the Agenda with the one-week strip over it.
  - Each day of the strip is a tab with its kind markers, and a label that gives its count, or none when the list was not read.
  - Choosing a day sets `?date=`.
  - Month is `/calendar?view=month`, and draws dots only.
- **The item** (D1211's drawer) and **the connected calendars** open full screen. Every dialog stays a bottom sheet.
- **A6m's bar stays** (D700). Its Today and This week sections are the Agenda now, so they are not drawn twice.
- **Targets:** buttons and radios are 44px tall below `md`, and the strip's days are 60px.

### 8. Departures

- **The counts** "12 copied, 1 failed" and "[12] copies" are not drawn: no read carries them (§3, §5).
- **The phone's item crumb** reads the item's title, not "‹ Calendar". It is the Lightbox's own back bar.
- **Calendly's and Zoom's connect flows** stay on their connector pages, as the canvas links them.
- **The Integrations page's Google disconnect** still drops the Calendar mappings (D1209 §5). It is outside this part's files.
