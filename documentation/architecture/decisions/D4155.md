### 4. Rules carried from the brief

- People by name, never email.

- "Not recorded" is never 0.

### 5. K4 — Default templates (#4191, S24, 2026-11-02)

| Decision | Why |
|---|---|
| **`GET /api/decks/admin/recommend-overrides` answers `{ overrides, defaults }`.** `defaults` holds one row per canvas sector (B2B software, Fintech, Health, Climate, Consumer, Deep tech) and stage (`pre_seed`, `seed`, `series_a`, `series_b`): `{ sector, stage, method_id, source }`, where `source` is `sector` or `stage_default`. | They come from `engineDefault`, the one function `recommendMethod` uses after an override, so the grid and the engine cannot disagree. The defaults stay the engine's pick when a cell has an override: Reset says what it returns to. |
| **Each override names who set it as `updated_by: { uid, name }`**, or null when that account is gone. Never an email. | The brief's rule. |
| **`PUT` and `DELETE` need `reason`, ten characters or more, else 400 `reason_required`, and nothing is written.** `DELETE` reads it from the JSON body, never the query string. | A query string lands in access logs; a reason should not. |
| **Each write is one admin audit row** (`logAdminAction`): `deck_default_template_set` with `before: { method_id, engine_default }` and `after: { method_id }`, or `deck_default_template_reset` with `before: { method_id }` and `after: { method_id: null, engine_default }`, each with the sector, stage and reason. | It reaches H7's governance feed through `admin_audit_log`. |
| **Writes stay the Super Admin's on HQ; any admin reads** (D905). | Unchanged. |
| **`PitchNotes.jsx` no longer reads or writes overrides.** The Super Admin's aside there now links to HQ › Decks › Default templates. `overrideRows` left `pitchStudioModel.js` with it. | One place changes a default template. |
| **HD4b, the change sheet:** a template select, the chosen template's name, "best for" and slide titles (`GET /api/decks/methods`), a reason, Save (armed by a template other than the cell's own and a reason) and, on a changed cell, Reset to default (armed by a reason). Client: `api.deckSetRecommendOverride` and the new `api.deckResetRecommendOverride`. | The canvas's HD4b. |

**For the owner.** The engine's sector rules match by pattern (`deeptech`, `biotech`, `hardware`, `robotics`), so the canvas's "Deep tech", written with a space, matches none of them: its row reads the stage defaults (`yc_seed`, `sequoia_classic`, `series_a_growth`, `series_b_diligence`), not the deep-tech picks. K4 shows what the engine does and changes no rule. Widening the pattern would change which template new deep-tech decks start on, so it is the owner's call.

### 6. K5 — HQ stage norms (#4192, S12, 2026-11-02)

| Decision | Why |
|---|---|
| **A sibling table, `hq_stage_norms`** (migration `202611022230_hq_stage_norms.sql`, additive), not a scope column on 746's `stage_norms`. Each row: stage, metric, a range (`range_low`, `range_high`, `range_unit`), source, `last_reviewed` (a day), status (`active` or `retired`), and who retired it, when and why. | 746's `project_id` is NOT NULL and its rows carry a founder's free-text value and a sample size; an HQ norm is a range with a review date. A scope column would have meant rebuilding 746. The table's CHECKs refuse a row with no source, a range with no bound or low above high, and a retired row with no reason. |
| **`/api/admin/deck-stage-norms`, self-mounting, `requireHqAdmin`:** `GET ?stage=&status=` (active first, then retired); `POST /` adds; `PUT /:uid` edits (an edit is a review: `last_reviewed` moves to today unless one is given); `POST /:uid/retire`; `GET /projects/:id` reads one venture's own norms, read-only. | The issue's routes. A plain HQ Admin and the Super Admin both curate; a branch admin is refused. |
| **`source` is required** (400 `source_missing`), and so is a reason of ten to 500 characters on every write (400 `reason_required`). Each write is one admin audit row (`deck_stage_norm_added`, `_edited`, `_retired`) with the reason and the norm's fields before and after. | No source, no citation (D1589). |
| **A retired norm is kept**, with `retired_by: { uid, name }`, `retired_reason` and `retired_at`, cannot be edited (409 `norm_retired`) and is never cited. The critic reads the norms on each run, so retiring stops citations at once. | HD5b: "The critic stops citing it at once." |
| **What the critic cites (`citableStageNorms`, in `stageNorms.ts`):** the venture's own norms first (`citableNorms`, D1589), then HQ's active norms for the stage. An HQ citation reads "Net revenue retention: typically 100–120% (source; Axal HQ norm, reviewed 2026-11-02)". `CRITIC_SYSTEM` now says to quote the norm, its range and its source beside the card's figure, and never to rate, score or grade the company. The answer's `benchmark` keeps its shape (a list of citation lines). | The issue's order, and its rule that the critic never rates the company. |
| **`hqStageNorms.ts` and the admin route import nothing from `stageNorms.ts`.** HQ's service restates the four stage ids (`HQ_STAGES`, held equal to D1589's by a test). | `stageNorms.ts` reaches the deck sources and, through them, `mercurySpend`; no admin route may reach member bank data (D752's guard). |
| **HQ never writes a venture's norms.** `deck_stage_norms.ts` now refuses an admin's `POST`, `PUT` and `DELETE` with 403 `hq_read_only`; an admin still reads them there, and HQ › Decks reads them through `GET /projects/:id`, each setter by uid and name. | The canvas: "The founders set these… HQ cannot change them." Before K5, `projectOwned` let any admin write them. |
| **Page stages map to stored stages:** Pre-seed, Seed, Series A and Series B+ are `pre_seed`, `seed`, `series_a` and `series_b_plus` (`NORM_STAGE_OF`). | D1589's stage ids, so HQ's norms and a venture's meet in one critic read. |
| **Frontend:** `BUILD.K5.live`; client `lib/api/hqDeckStageNorms.js` (`hqDeckStageNormsApi`); HD5's stage chips, table, Add and Edit form (metric, low, high, unit, source, reason), Retire with a reason, and a venture's norms by id, read-only. | The issue's wiring. The canvas opens the venture panel "from the deck critic"; until the critic links it, HQ opens it by the venture's id. |

Tests: `cloudflare-worker/test/hq_stage_norms_4192.test.ts`, `frontend/test/hq_decks_norms_4192.test.mjs`, `frontend/test/hq_decks_d4155.test.mjs`.
