## D6312 — Three coordinator skills: coordinator-audit, land-canvas, design-brief (#6312)

- **Status:** added 2026-11-14 by S01, after the coordinator audit of that day was run as a one-off script.
- **Where:** `.claude/skills/` (`coordinator-audit/`, `land-canvas/`, `design-brief/`), `scripts/coordinator.mjs`, `scripts/land-canvas.mjs`, and the pure half `scripts/lib/coordinator.mjs` with `coordinator.test.mjs` (run by `npm run test:retention`).

### Why

The 2026-11-14 audit triaged 217 issues, posted 207 notes, changed 88 label sets, closed 6 issues and filed 435 tasks. Three things went wrong or nearly did, and each is now a rule in code:

1. **Issues edited during the run.** 17 issues changed between the snapshot and the writes. Label changes were skipped for them, but notes were still posted. `apply` now re-reads each issue just before changing it and skips the issue entirely, note included, when it was closed, retitled, edited, relabelled or commented on by anyone else since the snapshot. The skipped list goes to the next triage.
2. **Unverified notes.** Only closes and new tasks had a second, adversarial check. Now every finding is checked: a note the verifier cannot support is not posted, a label change it refuses is not made, and a finding nobody verified changes nothing.
3. **Restarts.** The container restarted twice. Writes now carry `<!-- coordinator-audit:v1 run=<id> kind=<note|file|children> … -->`, and a write whose marker is already on GitHub is not repeated, even when the local ledger is gone.

### Rules the code enforces

- One `state:` label; `needs-decision` and `needs-design` only with `state:blocked`; slots `S01` to `S37` only, with lower-case `slot:s38`/`slot:s39` folded away when an issue moves (`planLabels`).
- A new build task goes to the least-loaded slot, never `S01`, `S18` or `S32`; design briefs and owner decisions go to `S01` (`slotPicker`, `proposalLabels`).
- A close happens only when the verifier said `safe_to_close`; `close_superseded` closes as not planned (`planFromFindings`).
- The weekly delta re-reads issues created since the last pass, issues named by a PR merged since, and issues with activity after their last audit note (`deltaSelect`).
- A canvas file is landed only when its SHA-256 matches the digest on the issue, or the owner confirmed the revision (`compareDigests`). Only digests written by the owner, a member or a collaborator count, and two that disagree stop the landing (`parseDigests`). A boards file gets the repo's `· Boards` name and is never edited (`landedName`).
- A close always comes with its note; a finding for an issue outside its chunk, or a second finding for the same issue, is dropped; a parent that is not an open issue gets no comment.
- Moving to any state but `state:blocked` drops `needs-design` and `needs-decision`; no issue is left without a state label; nothing is moved into S18 or S32, only coordinator work into S01, and an active claim is not moved.

### Limits

- `coordinator-audit` and `design-brief` read and write GitHub issues only. `land-canvas` also pushes one branch and opens one draft PR that adds design files and docs only. No skill merges, approves, force-pushes, edits `main` or dispatches workflows.
- The GitHub token, when set, goes to curl through a private config file, never on the command line, so an error message cannot carry it.
- `design-brief` writes a prompt; the canvas is drawn in Claude Design by the owner, and approved by the owner.
- The workflow's verifier is an agent, not proof. The note says which main sha it was checked against.
