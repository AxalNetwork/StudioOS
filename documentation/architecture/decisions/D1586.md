## D1586 — Data-room proof links behind a shared figure (#3833)

**Deck v2 F7, slot S05 · 2026-11-02.** Worker only. No migration. Builds on D902 (what a link includes, the NDA gate), D1565 (one link per investor, #3812), D1602 (data-room deck sources, #3881) and the data room's grants and tiers (D691, D1103).

### What it is

A figure on a shared deck that is bound to a data-room file (a D1602 citation, `dataroom:<file uid>:v<content revision>:p<page>`) can be proved: the investor the link was made for opens the cited file, at the cited page, from the link. Nothing else on a deck can be proved.

### `include.evidence`

`shareInclude.ts` gains a seventh switch, `evidence`, **off by default**. Every link made before today reads it as off. The link writer (`createDeckLink`) accepts it like the other six, as a boolean.

With it on, **and the link requiring the NDA**, a binding the link sends goes out as `{ grade, as_of, proof_ref }`, where `proof_ref` is its data-room citation. Only a binding on a `dataroom.*` slot whose `record_ref` is a well-formed citation carries one. A link without the NDA reports `included.evidence: false` and sends no `proof_ref`, whatever it stores: proof sits behind the NDA.

A chart series' binding and a table cell's binding now go out as every other binding does (grade and date, plus `proof_ref` under the same rule). Before this they left the Worker whole, which would have sent a citation with evidence off.

### `GET /api/decks/share/:token/proof/:ref`

`routes/deck_proof.ts`, mounted ahead of `decks` (#4105). Each check refuses before the next is read:

1. **The link and its evidence.** A valid token, live, bound to this browser when forwarding is off (`bindShareViewer`, `shareLinkLive`), with `evidence` on. Off, or a link with no NDA: `404 no_evidence`.
2. **The NDA.** The share read's own gate (`ndaGate`): the signed-in reader accepted the NDA on this link. Otherwise `403 nda_required`, with the gate's answer. A signed-out reader gets the same answer with `signed_in: false`. The ref is not read yet.
3. **Email → account → grant.** The link is an investor's own: a D1565 link to a prospect, whose email is the signed-in account's (case-insensitive, the same match the room's commitment check makes, `investorCommitted`). The account must be verified, active and not being deleted. A link to a typed name names no account. Otherwise `403 not_the_investor`. That account holds an active, unexpired grant on the deck's venture (`activeGrant`), or `403 no_grant`. An admin is refused (`403 support_read_required`), as on the room's own download.
4. **The ref.** A citation that a figure **this link sends** carries (`sharedProofRefs`, the same rules as `shareSlides` with this link's include and the venture's consents). The file must still be tagged as a deck source, at that content revision (D1602's `sourceFile`). Anything else is `404 not_found`, which does not say why.
5. **The file's tier.** The data room's own rules, unchanged: `tierAdmits` with the investor's commitment and the grant's folder scope (a hidden file is `404`, as the room answers); a file marked `nda` needs the founder's NDA (`projectNdaActive`), logged `blocked` and `403 file_nda_required` without it.

The answer is the room's own download: a two-minute signed URL (`mintDownloadToken`, audience `data_room:<project uid>`), the file's name and the page (`null` for `p0`, unpaged). The room's activity log records it as a `download`, so the founder sees it as any other. A proof uses no view of the link.

### Private evidence is never resolvable

A bank figure, a quote and every other record have no proof. Three rules, each tested on its own with the cited file sitting in the room as a live deck source:

- only a `dataroom:` citation on a `dataroom.*` slot is a ref (`DATAROOM_REF`, `proofRefOf`);
- only a figure the link sends proves anything, so a field `shareSlides` cuts (a bank key or bank slot, an internal score, a quote without consent, an interview quote whose session recorded none, a figure with figures off) cannot be proved even when it cites the room;
- the file's tier and NDA are checked again here, never inherited from the share.

### What this does not build

- **No frontend.** The share viewer draws no provenance badge or source chip on a figure (plan §0 row 10, pd24: "Badges show only in the editor; investors never see them"). pd35 has no evidence column and PD20 was removed, so the toggle and any proof control wait for an owner decision. `frontend/src/pages/raise/pitch/shareModel.js` keeps its six switches; the Worker's default for the seventh is off.
- **No second tier or owner lookup.** The route reuses D1602's `sourceFile` and the data room's `activeGrant`, `tierAdmits`, `grantFolderScope`, `investorCommitted`, `projectNdaActive` and `logAccess`.
- **The deal page's grants (D1587)** cut every binding, so `evidence` has no effect there.
