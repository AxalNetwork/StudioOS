### What a phone draws now

- **Access (RAD33B).** Below the phone width (`PHONE_QUERY`, under 1024px) each grant is a card in place of the 880px table, and the List/Matrix switch is not drawn. A card reads: the investor (a 44px button that opens their sheet), the address when it differs, "Since … · until … · folders", the grant's state when not Active, an end date within 14 days, then labelled lines: **Can open** n of N files, **Not open to them** (N − n), **NDA** (Signed, Waiting for signatures, Not sent), **Committed**, and **Last event** among the room's last fifty. Then **File by file** and **Revoke** (owner only, not on a revoked grant), each 44px. Search and the three filters stay, 44px tall.
- **The drill-down.** File by file, or the name, opens the investor's sheet (D1107's DR7i). On a phone it adds every file of the room, its folder, and `grantOn`'s rule for this grant: "Can open", or the first rule that shuts them out. This is the matrix's column for that investor, from the same function (`grantFiles` in `accessModel.js`), so the two never disagree. Revoke, Change and Send the NDA are 44px there.
- **View table.** Under the cards, a real button with `aria-expanded` and `aria-controls` opens the file × investor matrix, which scrolls inside its own box. It is the only table on Access at phone width.
- **Files (DR22b).** One card per file: a 44px Select and the name as a 44px link to the file's sheet, then Folder, Gate (with NDA), Until, Links issued and Who can open it now, in the table's column order. Links issued with no count reads Not recorded, never 0. The table is behind View table. The tree's rows, New folder, Upload and the bulk bar are 44px.
- **Desktop is unchanged.** Every change is behind the `phone` flag `DataRoomTabPage` already computes; Files now receives it too.

### Departures from RAD33B

- **"Shared · not opened yet" and "opened 3 Nov" are not drawn.** The canvas marks them ◇ #6072; the founder's read has no opened value per grant (#6072 built only the share notice, D6072). The card shows the last event among the room's last fifty instead, as the desktop table does.
- **Cancel share is not drawn.** It is for a pending share to an address with no account (owner question 1, option A). On #6072 the owner kept existing accounts only (D6072), so no pending share exists, and every card is a grant with Revoke, in `accessModel.js`'s words.
- **Counts and the NDA are on the founder's card.** RAD33B draws neither; the issue asks for open and blocked counts and the NDA state, and the desktop table (DR6, DR26) already carries both, so the card carries them from the same rows.
- **Share stays in the card's header**, not at the foot of the list, as on desktop.
