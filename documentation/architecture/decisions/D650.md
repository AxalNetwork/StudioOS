## D650 — Personal connectors project into enabled companies

**Issue:** #1462, part of #1461. **Migration:** 435.

`/api/connectors` is the canonical Worker mount. `/api/integrations` is an alias
to the same router while its callers move. The registry describes each tool in
plain words: category, verified state, pulls, sends, feeds and permissions.
Google Calendar and Microsoft 365 read their existing calendar token stores;
there is no second calendar connection.

A new integration is enabled for the verified active company. Migration 435
backfills existing integrations to companies their owner was linked to at
migration time. A later company membership does not silently enable an old
connection. `PUT /:uid/companies` replaces the enabled set atomically and
records the actor. Reads of another teammate's connection reveal only the
teammate's name, within a verified shared company.

The Worker gates manual sync and push for project-writing providers on enabled company links. Project writes
from Stripe, HubSpot and Salesforce additionally check the destination
project against the enabled set, including cron, webhook and auto-push paths.
An unreadable link fails closed. The generic settings store sync frequency and
send mode in `config_json`; scheduled sync respects the frequency, and auto
push respects the send mode. Logs are searchable and paged. Connector requests
store the member's tool and intended use; only the Super Admin lists them.
Suggestions follow measured gaps in module stores, rather than a model or a
fabricated count.

The OAuth callback checks the provider's reported grants against the
registry's requested scopes before saving a connection. Known overreach is
logged, refused and revoked where the provider exposes a revocation endpoint.
Some providers do not return a grant list, and a private app key cannot be
revoked by this Worker; the code does not label the requested scopes as a
measured grant.

Credentials and personal records remain owned by the connecting user. Calendly
events, Carta cap-table rows, and calendar tokens remain keyed by user and
continue syncing when that user has several companies or no enabled company.
Disabling a company stops future writes into its projects; it does not disconnect
the user's personal account or share its records with teammates. DocuSign
reconciliation also matches the originating user (`created_by`), even when
two users connect the same external account or send to each other.

**Verified:** migration backfill and route tests use SQLite; Worker types,
the root build and `test:drift` are the release gates.
