### 1. The scope is broad, so the allowlist lives on the server

Intuit has no report-only scope. `com.intuit.quickbooks.accounting` reads and
writes the whole ledger (D5832 §2). The Worker therefore holds the limit itself:

- `REPORT_PATHS` names exactly `reports/ProfitAndLoss` and `reports/BalanceSheet`.
  No other report, no `query`, and no transaction, invoice, payment or payroll
  path can be built. An unknown name, including `constructor` or a path
  fragment, is refused before any request.
- Every request is a GET with no body and `redirect: 'error'`. A guard test
  fails if either file names another HTTP method or writes to the console.
- The realm id must be numeric, so it cannot carry a path or a query. It comes
  only from the connection, never from the request.
- Sandbox (`sandbox-quickbooks.api.intuit.com`) and production
  (`quickbooks.api.intuit.com`) have separate hosts. The connection's recorded
  environment picks one; the request cannot.

The query sends:

- `start_date` and `end_date`. A balance sheet is read with both set to its
  as-of date.
- `accounting_method=Cash|Accrual`. With basis `unknown` it is left out, so the
  company's default applies and the report header records which one was used.
- `minorversion=75`.

### 2. A connection binds one realm to one venture

`integrations` keeps one connection per member and provider
(`UNIQUE(user_id, provider_key)`). The QuickBooks connection carries:

- `external_account_id`: the realm the founder chose at consent;
- `config_json.project_id`: the venture it serves;
- `config_json.environment`: `sandbox` or `production`.

A sync is refused before anything is fetched in these cases:

| Case | Refusal |
|---|---|
| The connection is not the caller's own active one | `connection_not_found` |
| The connection has no realm | `realm_not_bound` |
| The connection's venture is not the requested venture | `realm_not_bound_to_venture` |
| The connection's environment is neither sandbox nor production | `environment_not_bound` |
| The caller cannot write to the venture | `project_not_found` |

Two realms can feed one venture, for example the founder's realm and a
cofounder's. They stay apart because the D5833 key includes `entity_key`
(the realm), and each connection's snapshots carry its own `integration_id`.

### 3. Failures, limits and recovery

| From Intuit | Code | Written |
|---|---|---|
| 401 | `quickbooks_unauthorized` | nothing for that statement |
| 403 | `quickbooks_scope_denied` | nothing for that statement |
| 429 | `quickbooks_rate_limited`, with `retry_after_s` from `Retry-After` (capped at 3600; null when absent) | nothing for that statement |
| 5xx | `quickbooks_unavailable` | nothing for that statement |
| other non-200 | `quickbooks_refused` | nothing for that statement |
| a `Fault` body | `quickbooks_fault` | nothing for that statement |
| not JSON | `report_invalid` | nothing for that statement |
| over 2,000,000 bytes, declared or read | `report_too_large` | nothing for that statement |
| a report of the other kind | `report_mismatch` | nothing for that statement |

- **Pagination:** reports are single documents, so there is nothing to page. One
  sync reads at most `MAX_STATEMENTS` (6) statements.
- **Rate limits:** about 500 requests a minute per company (third-party figure,
  D5832 §2). A pilot sync makes two or three requests. A 429 stops the sync and
  hands back the wait. The sync never retries on its own.
- **Recovery:** each statement is written atomically on its own (D5833). An
  interrupted sync keeps the statements it already wrote and answers
  `incomplete`. It names the statement that failed and why.
- **Last complete sync:** `last_synced_at` moves only when every requested
  statement completed.
- **Retries:** a retry finds the written statements `unchanged` and writes only
  the rest, so nothing is duplicated. A report Intuit has corrected appends the
  next revision.
- **Logs:** `last_error` holds the code alone. Neither file logs, and no refusal
  carries a response body, a figure or a realm id.
- **Disconnect:** a disconnected connection cannot sync. Its revisions and the
  founder's pins on them stay readable (D5833 pins point at revisions, not at
  connections).

### 4. What part 2 adds, and what stays with the owner

**Part 2:**

  binding above;

  race;

- create the production app keys and register the exact redirect URI;
- complete Intuit's app assessment;

  a live report.
