## D5205 — The Worker's calendar registry is the one list of Calendar sources (#5205)

Part 5 of 7 of the 2026-11-09 Calendar audit (of #3723). P1. No migration, no new route.

The live `/calendar` read 32 kinds in its rail while its header named six sources and said "Nothing else is
aggregated here", its explainer was titled "One agenda, six sources" and said a connected calendar's events "are
not read back in", and its "Not read here yet" card said cohort dates, deal closings and interview calls were not
read, beside those very items. The Worker already had one registry
(`cloudflare-worker/src/services/calendar/registry.ts`, D1484); the frontend kept copies of it beside it, and the
copies drifted.

### What the frontend mirrored, and what became of each

| Mirror | Where | Now |
| --- | --- | --- |
| `KINDS`: each kind's id, label and module | `CalendarPage.jsx` | **Deleted.** `calendarViews.js` builds `KINDS` from the registry's `SOURCES` (`kindsOf`). |
| `KIND_LABEL` | `CalendarPage.jsx` | **Deleted.** Derived from `KINDS`. |
| `PUSHABLE_KINDS` | `CalendarPage.jsx` | **Deleted.** The registry's `pushable` flag. The push route's own set is still held to the registry by `calendar_registry_d1484.test.ts` and to the page by `calendar_page_c1.test.mjs`. |
| `FAMILIES`: eight canvas families (Events, Meetings, Sessions, Deadlines, Learning, Grow, From other calendars, AI agents) | `calendarViews.js` | **Deleted.** The registry's ten families, in its order, with its names (`familiesOf`). The sources panel (CAL4) already used these, so the Kinds filter and the panel now group alike. |
| `FAMILY_LABELS` | Worker `prefs.ts` | **Moved** into `registry.ts` (re-exported from `prefs.ts`), so the page imports the whole registry with no database code behind it. |
| `WAITS`: two sentences about cohort dates, deal closings and interview calls | `calendarViews.js` | **Retired.** All three have been read since D1484. A wait now names the kinds it waits for, and `waitsOf` drops any the registry reads; the card is not drawn when none is left, which is today. |
| The header sentence and the explainer | `CalendarPage.jsx`, `lib/explainers.js` | **Rewritten** in words that name no subset and no count: the rail lists every source. |

The page imports `registry.ts` itself, the way `licenceTermsForm.js` and `redirectBeacon.js` import Worker
modules. The SPA and the Worker ship in the same `wrangler deploy` (CLAUDE.md, fact 4), so the page's list and the
Worker's cannot belong to different builds. Reading `GET /api/calendar/sources` at run time for labels instead
would have needed a fallback list for the moment before it answers, and that fallback would be a mirror again.
The route still serves the member's own settings (shown, colour) and the panel still reads it for those.

### What the frontend still keeps, and the test that holds it

Each of these is presentation the registry has no word for. `frontend/test/calendar_registry_truth_5205.test.mjs`
fails when one names a kind or family the registry does not have:

- `CHIP_LABEL`: the canvas's shorter chip word for four kinds (Advisor, Calendly, Compliance, Milestone). A key
  that repeats the registry's label also fails, so the map cannot grow into a second label list.
- `EXPLORER_KINDS`: what an Explorer's calendar reads (D1210, CAL14). It was "the Events and From other calendars
  families"; the registry files "Your event" under Tasks, so the rule is now the same six kinds, named.
- Each kind's mark in `calendarPage.css`: one light and one dark hue per registry kind, and no dot rule for a kind
  the registry lacks.
- `COLOURS` in `calendarSourcesModel.js` equals the Worker's palette; `AGENT_FAMILY` and `EXTERNAL_KINDS` match the
  registry's families.

### Behaviour that moved with the families

- The Kinds filter groups by the registry's ten families, not the canvas's eight. Advisor sessions, office hours
  and expert sessions sit under Meetings; round closes and NDA expiries under Raise; the task stores under Tasks.
- "Hide deadlines" hides the registry's Deadlines family: compliance deadlines, cohort dates and deal closings. It
  no longer hides round closes, NDA expiries or task due dates, which the registry does not call deadlines.
- The rail's "N kinds in M families" counts the registry's kinds and families for the viewer's profile.
- The source-coverage line ("31 of 32 sources answered") is unchanged: it is the Worker's `coverage` (D5204).

### Not in scope

The staff scope view (`calendarScope/calendarScopeModel.js`, D4154) groups items into its own types for a
different board; it holds no claim about which sources are read, and is left as it is.
