## D4106 — Migration and decision numbers that cannot collide (#4106)

- **Status:** built by S09, 2026-11-02 (#4106, part of #4101; claimed from slot S21 at the owner's request).
- **Number:** D4106 is this issue's number. This decision is the first one numbered by the rule it sets.

### 1. What applies and orders migrations today

| Piece | Where | What it does |
| --- | --- | --- |
| Ledger runner | `scripts/migrate-d1.mjs:258` lists the files; `:501` plans; `:527` applies (`npm run d1:migrate:remote`, `package.json:26`) | reads `cloudflare-worker/sql/migrations/*.sql`, compares with the `schema_migrations` ledger, and applies each pending file once, by file name |

| Decision ids | `scripts/check-decision-ids.mjs` | `DECISIONS.md` holds D1–D525, and from D526 each decision is a file; every number is unique |

The ledger is keyed by **file name**, so the runner never needed unique numbers: two `764_` files would both apply. What collided was the address. Seven prefixes exist twice on main (11, 68, 118, 228, 229, 230 and 259), and decision numbers were handed out by issues and then raced.

### 2. Migrations: named by their UTC minute (option a)

A new migration is `YYYYMMDDHHMM_<slug>.sql`, for example `202611021015_add_widgets.sql`: twelve digits, the UTC minute it was written, then a lower-case slug.

- **Why digits only, not the issue's `20261102T1015Z_` example.** About a hundred call sites (guards and test fixtures) select migrations with `/^\d+_.*\.sql$/`. A `T` after the digits fails that filter, so those call sites would silently skip the new files: a fixture would build a schema without them, and a guard would check nothing. Twelve digits keep every filter reading them.
- **Order.** `migrationNumber` of a stamped file is its twelve digits, which are larger than every numbered file. So stamped files sort after `1`–`799`, by minute, with the full name breaking a same-minute tie. Nothing in the runner changed.
- **Applied once.** The ledger keys on the file name, so a stamped file applies on the first deploy and is skipped after that. `collision_free_ids_d4106.test.ts` proves this with the runner's own `planActions`/`applyPlan` on a SQLite copy, never production.
- **Bootstrap.** A stamped file is far above `BASELINE_CUTOFF` (219), so a bootstrap never marks it. It is always applied.
- **The ceiling.** A numbered file may still take a number up to `NUMBERED_CEILING` (799), so the PRs already open when this lands still pass. Anything above 799 is refused, and new work uses the stamp.
- **The check.** `scripts/check-sql-migrations.mjs` (in `test:guards`) refuses:
  - a name that is neither numbered nor a valid stamp;
  - a numbered file above 799;
  - two files sharing a number or a stamp, naming both files.

  The seven historical pairs are listed in `LEGACY_DUPLICATES` and are never extended. A test holds that list to exactly the pairs on main.

Option (b), a reservation file on main, was not taken: that one file would itself conflict between parallel PRs.

### 3. Decisions: numbered by their issue

- **From D4000 up, a decision's number is its issue's number.** The decision for issue #4102 is D4102. That is unique by construction, so nothing is reserved and no two PRs can pick the same one.
- **The heading cites the issue:** `## D4106 — <title> (#4106)`. `check-decision-ids` refuses a file from D4000 up whose first line does not cite its own number as an issue. The check stays offline: it reads the citation and does not call the GitHub API.
- **Existing decisions keep their numbers.** Numbers below D4000 are the ones issues handed out before this rule, up to D1614 today, plus any still reserved in an open issue's body.
- **Gap note:** the range from the highest of those to D3999 is a gap that no one fills.

### 4. What two parallel PRs now do

PR A (issue #4120) adds `202611021015_add_widgets.sql` and `D4120.md`. PR B (issue #4121), written from the same main, adds `202611021022_add_gadgets.sql` and `D4121.md`. Neither PR coordinates with the other, and their union passes both checks, which a test asserts. They can only meet if both stamps fall in the same minute, and then the check names both files.
