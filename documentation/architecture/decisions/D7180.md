### Worker

- **Per-metric provenance.** `presentMetrics(row, citations)` in `services/researchCompanyDirectory.ts` gives each headline metric its own `publisher`, `url`, `confidence` and `observed_on`. A field citation (`company_sources.field_name`, matched by `METRIC_FIELDS`) is the metric's own publisher: the most confident, then the most recently published. Without one the metric names the directory record's shared `metrics_source_*` and says so (`provenance: 'directory_record'`, `confidence_basis`). `observed_on` comes only from the metric's own column (`last_funding_date` as announced, `revenue_as_of`, `employee_as_of`, `valuation_as_of`, `market_share_as_of`) and is `null` when it is blank. Funding total has no such column, so it is always `null`. The update date is `updated_on` (`metrics_updated_at`), kept apart. `as_of` stays for older readers and equals `observed_on`: it no longer falls back to the update date. A failed citations read leaves every metric on the record's source; the response's `sources.status` says the read failed.
- **Peers carry their rule.** `peers.rule` names the sector label and country the query matched on, and its order (same country first when recorded, then by name) and limit, so the page prints the Worker's rule rather than its own.
- **One evidence collection on its own.** `GET /api/research/company-directory/:uid?part=funding_rounds|employment|financials|sources` reads that collection only (`getCompanyPart`). An unknown part is a 400 with `field: 'part'`; a failed read is Unreadable on its own. The auth line is unchanged.
- **A subject on the analysis is D7175's.** #7175 (merged first, migration `202611180051_7175_competitor_subject_and_verified_website.sql`) added `competitor_analyses.subject_uid`, the subject card and the `company=<uid>&name=` link. This build drafted the same column and setup card; on merging main it dropped both and the profile's "Set up competitor analysis →" links through D7175's `analysisHref`, so there is one subject column and one setup path.
