## D4160 — Axal's skills are reviewed by a second admin, pass their golden cases, and retire with a replacement (#4160)

- **Status:** built by Claude Code for slot S29, 2026-11-02. Not deployed and not checked live.
- **Part of:** #4137 (HQ › AI agents), task H2 (Worker). Boards SA3, SA4, SA4b, SA9e and SA9f.
- **Migration:** `202611022140_hq_skill_lifecycle.sql` (D4106's stamped name).

### 1. States without a table rebuild

The states are draft → in review → published → retired.

`agent_skills.status` keeps its three values (migration 759's CHECK). "In review" is a draft with an open request in `agent_skill_reviews` on its current text. `lifecycleStatus` derives it.

### 2. A draft is named by its hash

`draftHash` is SHA-256 of the draft's parts, in a fixed order: name, purpose, steps, tools, output, tags and roles.

An approval and an eval result count only for the hash they were given on. Editing the draft after either makes a new hash, so publishing needs them again. No revision counter is written on every edit, and `PATCH /api/teams/skills/:uid` is unchanged.

### 3. Review

`POST /api/admin/ai-agents/skills/:uid/review` asks a named Super Admin to review.

The draft's author is never its reviewer or approver. The author is whoever asked, or whoever last wrote the draft (`updated_by`):
- naming yourself is 422 `reviewer_is_author`, and a CHECK in the table also refuses it;
- the author approving is 403 `self_approval`;
- another admin who was not named is 403 `not_reviewer`.

`request-changes` needs a comment. A review left open on an older text is withdrawn when a new one is asked for.

### 4. Golden cases

Cases are stored per skill (`agent_skill_cases`), in #3953's shape:
- the inputs are made-up records keyed by the read they stand in for;
- the expectation is the output kind plus phrases the output must include, must say are "not recorded", and must not include.

An email address anywhere in a case is refused (400 `case_has_email`). A case is never edited in place, because its results belong to its text; a changed case is a new one, and the old one is marked removed.

### 5. Eval runs

`POST /:uid/evals` runs every live case on each model through `aiRouter.run()`:
- the task is `module_chat`;
- the run is `pinned` to the model;
- it is charged to the Super Admin who pressed Re-run, which is HQ;
- the surface is `/hq/ai-agents`.

The models are the ones asked for, else every model agents may run on today (`agentModels`, not plan-locked), at most 5. H4's per-area allow-list replaces this when it lands.

Each result (pass, fail or not run, with the reason) is stored per case, model and draft hash.

### 6. The publish gate

`publishRefusal` applies to Axal skills only. `services/agents/skillPublish.ts`'s `publishDraft` calls it, and that one function is now behind both `POST /api/teams/skills/:uid/publish` and the bulk publish. It refuses in two ways:
- **409 `needs_approval`:** no approval on the current hash.
- **409 `golden_cases_failing` `{ pass, total }`:** fewer than 9 of every 10 runs pass.

How the bar counts:
- It counts every live case on every model run for this draft.
- A missing result is "not run", which is not a pass.
- No case or no result is below the bar.

A company's skill is published as before.

### 7. Write-capable tools

`checkDraft`, which every save and import goes through, refuses a tool that is not read-only: 400 `tool_not_read_only` with `{ tool }`.

`isReadOnlyTool` accepts an action of `read`, or one that starts `read_`, `list_`, `get_` or `search_`. The starter library's tools are all `<source>.read`.

This applies to company skills too. Agents only propose (D1496), and no skill may request a tool that changes records.

### 8. Retire

`POST /:uid/retire { replacement_uid, reason }` needs a published Axal skill other than itself (422 `replacement_required` or `replacement_invalid`) and a reason. It answers with the live agents pinned to the skill.

After retiring:
- pinned agents keep their version until their team moves;
- the skill leaves the library for new assignments (D1612's `skill_retired`);
- `agent_skill_retirements` keeps the replacement, the reason and the count.

`PATCH /api/teams/skills/:uid { status: 'retired' }` now refuses an Axal skill (409 `replacement_required`), so the replacement cannot be skipped.

### 9. Bulk

`POST /bulk { action: publish | retire | evals, uids, reason }` takes up to 50 skills. Each item is done or refused on its own, with its code.

### 10. Audit

Every change writes `logAdminAction` with the reason, and the state before and after. The actions are cases set, review requested, approved, changes requested, evals run, published and retired.

The admin is the row's `admin_user_id`, whom H5's read names. Until H5's table lands, this is `services/adminAudit.ts`, as the issue says.
