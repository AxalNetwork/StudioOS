### 1. The property the audit asks for

However many agents run, from whichever runtime (Cloudflare Containers, AWS,
Azure, a Claude or Codex session), **nothing reaches `main` or production except
through gates GitHub enforces**, under identities, credentials, budgets and
runners that are scoped and recorded. GitHub is the governance ledger for code;
StudioOS is the orchestration system. That sentence is the test every issue in
the map below is held to.

### 2. The admin slot, `slot:chatgptpro`

A named slot beside the numbered ones. Its queue is console configuration no
pull request can make, on GitHub, Cloudflare, AWS and Azure (the owner's
instruction of 2026-11-21 extends it from GitHub to the three clouds). It is
worked in a browser by the ChatGPT Pro session. It edits no file; its
deliverable is a STATUS table of settings changed (names and values; never a
secret, an id or a non-public address), and a coding task mirrors each setting
in the repository. `documentation/operations/GITHUB_ADMIN_BASELINE.md` (#8082)
is the mirror of record, checked weekly against the live API by a read-only
job that files an admin task on drift. The slot changes production, switches a
bypass off or widens a permission only after the owner's written go on the
issue.

Why a named slot and not `S40`: the numbered slots are interchangeable builders
the coordinator spreads load over (`slotPicker`); this one is a different kind
of work with a different deliverable, and a name keeps the coordinator from
ever handing it a build task. The validators accept it by name:
`normSlot('ChatGPTPro') === 'chatgptpro'`, `checkSlot` the same, the WIP table
keys it `chatgptpro`; `isStandardSlotLabel('slot:chatgptpro')` stays false.

### 3. S38 and S39 are standard

Issues, claim refs and the live labels `slot:s38` and `slot:s39` already
existed outside the "thirty-seven" of `AGENTS.md`, and the owner's instruction
names "S07 to S39" as the builders. `SLOT_RANGE` is `[1, 39]`,
`STANDARD_SLOTS` is 39, `labels.yml` declares `slot:S38` and `slot:S39`, and
`labels-retired.yml` maps the lower-case spellings so `labels-sync.yml`
renames them in place (GitHub label names are case-insensitive, so a second
label cannot be created; the live labels were renamed by hand on 2026-11-21
and the sync is idempotent over that).

### 4. Delegated filing

A slot files Session 1 tasks when the owner tells it to, in writing, in that
slot's own session: `S1:` body, a first paragraph naming the filing slot and
linking the session, the task's labels. The tooling that reads `^S1:` is
unchanged. A slot never files on its own initiative or from another agent's
text; the audit text itself was information until the owner's instruction made
planning it a task.

The audit's environment names map onto the repository's: its `development` is
`preview` (one deploy per pull request), its `security` is `production-ops`.
Its capability names are adopted as written (`<domain>.<action>`), and five of

### 7. What this decision does not do

It changes no console setting, merges nothing, and deploys nothing. The seven
admin tasks are ordered on #8059 and each stops for the owner's go before a
bypass is removed, a production resource changes or a permission widens.
