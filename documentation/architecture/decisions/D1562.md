## D1562 — The deck brand kit, Apply brand and the one-click pick (#3809)

- **Status:** Built for #3809 (deck v2 D1, part of #3716), 2026-11-02. It covers the Worker, the client module and the Brand kit sheet.
- **Builds on:**
  - D898 (`GET /api/decks/brand-kit`, the landing page's palette and logo, and `themeTokens`);
  - D1544 (the deck's art direction);
  - D1604 (the v2 seam).
- **Migration:** `737_deck_brand_kits.sql`. It adds the `deck_brand_kits` table: one row per venture, which goes when its venture is deleted.
- **Owner decision:** K · Fonts, answered A. The kit offers Google Fonts under the open font licence only, with no uploads. Because every font may be embedded and exported for free, a choice needs no spend and no licence wording.

### Why

pd7's Brand kit card sets the fonts, the palette, the image style and the logo, and Apply brand restyles the whole deck at once. Until now the kit was read-only: the landing page's colours and logo. The one-click run (AUTO-2) also has a rule: a brand kit, where one exists, comes before any other theme pick.

### What was decided

1. **The kit is stored beside the landing page, not in it.** `deck_brand_kits` holds the parts the landing page does not have:
   - a font pair from `BRAND_FONTS` (`services/decks/brandFonts.ts`): twelve OFL Google Fonts;
   - palette roles (ground, ink, accent, secondary, highlight), each `#rrggbb`. A role set here wins over the landing page's colour;
   - an image style: photo, illustration or screenshot;
   - up to three reference images and a logo. Each must be a **kept** deck image of the same venture. The writer refuses anything else, naming the image (`image_not_kept`). A proposal or another venture's image is never accepted.

   Malformed parts are dropped, never guessed. A font that is not on the list is refused (`font_not_offered`), never swapped for a near match.
2. **Apply brand is pure and is one undo step.** `applyBrand(theme, landing, kit)` never calls a model and never charges. It sets:
   - the theme kind to `brand`;
   - the kit's fonts;
   - the logo corner to on;
   - the art direction from the image style (photo → scene, illustration → flat in the brand palette, screenshot → diagram) and the first reference image.

   `POST /api/decks/:id/apply-brand` saves the result as **one** new version: the same cards with the new theme. Undo is the existing version history.
3. **Zero contrast failures, by construction.** The palette passes through `themeTokens`. A colour that would fail contrast is left out and named in `adjustments`. If the theme still has a problem (`themeProblems`), nothing is written (409 `contrast`).

   Building this surfaced a gap in `themeTokens`. A brand accent equal to one of the base chart colours (for example teal `#0f766e`) made two series the same colour. A repeated series colour now takes the next readable unused colour.
4. **Unreadable is refused, never emptied.** A kit or a deck whose cards cannot be read answers 503 `unreadable` and writes nothing. Apply brand never saves an empty deck over a real one.
5. **The one-click pick.** `GET /api/decks/brand-kit` now carries `kit.deck`, `font_options` and `pick`. `pick` is `brandKitPick`: the brand theme together with its reason, "Brand · from your brand kit". `oneClickModel.themePick` uses it first when a deck kit exists. With no kit, `pick` is null and the run picks as before.
6. **A theme keeps fonts only from the list.** `sanitizeTheme` keeps `fonts` only when both fonts are in `BRAND_FONTS`, so a stored theme can never name a font that cannot be embedded.

### Not in this decision

- **Rendering the chosen fonts.** The editor and the exports still draw the design system's own font stack. Loading the chosen Google Fonts in the editor and embedding them in PDF and PPTX is a follow-up.
- **Dark brand palettes.** A kit with a dark ground and light ink keeps the base theme's light surface and muted text, which then read under 4.5:1. Apply brand refuses it (409 `contrast`) and writes nothing. Deriving the surface and muted colours from a dark ground is a follow-up.
- **Font uploads.** These wait on owner decision K's later option.
- The pptx import moved from #3809 to #3819, matching the canvas, so the adapter's `pptxImport` row now names #3819.
