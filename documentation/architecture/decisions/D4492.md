## D4492 — Distribution prospects and recorded marketing permissions (#4492)

Part of #3722. This uses the venture's existing customer `contacts`, seven
contact statuses, replies and tasks. Contact creation reuses the canonical
prepared insert from `contacts.ts`; contact, consent and actor audit are kept
in one D1 batch. Campaigns remain D4447's `grow_campaigns`, linked by their
recorded UTM tag, never a second campaign store. Nothing sends.

Marketing permissions are separate from interview-recording `channel_consents`
and Axal's platform-wide `email_suppressions`. A recorded basis is opted_in,
wrote_first or none, per contact and channel. Positive bases require a short
proof; the session supplies recorded_by and the server supplies recorded_at.
No source, import or existing contact implicitly grants marketing permission.

Venture suppression addresses are normalised and HMAC-indexed using the
existing `columnCipher.indexHmac` key, domain-separated by venture. The table,
list, audit and errors contain no plaintext address. Reasons are fixed codes;
the list identifies a suppression by its id and recorded date, not an email.
Read/modify gates match Grow's existing canAccessProject rules. Other-venture
contact ids are not found; advisors read but do not write. Emails are returned
only by an individual prospect read, never cards or import results.

An HMAC-derived key tag on each suppression detects a changed key without
storing the address or the secret. A mismatch makes reachability unreadable;
key rotation must never silently make old suppressions appear absent.

Quiet hours have no invented current default: absent settings are Not recorded.
Saved windows are HH:MM in the recipient's zone. There is no recipient-zone
store or sending engine here, so this does not claim quiet hours are enforced
or that one-click opt-out is already implemented. The UI states that future
outreach must include it. Owner channel decision D and counsel review remain
outside this storage task; no non-email sending is enabled.

Venture-wide summary counts come from explicit consent and the venture's
suppression hashes. Segment membership is not stored for contacts: a requested
segment is validated in the venture, but its reachability is Not recorded,
never substituted with the venture-wide count. Contact job titles, sequence
steps and avatar images also have no canonical field here and stay unrecorded.

CSV imports use the existing parser, at most 1,000 logical data rows and 1 MB.
The consent_basis column is required; invalid rows return only their number,
a fixed field and sentence, never cell text. Accepted rows are saved in bounded
atomic batches with their consent and audit. No invite or mail service runs.

DS7/MK7 use seven columns, real counts, safe source chips, empty/loading states
and an individual Sheet. The components and consent summary are independent
of #4484's tab shell and #4487's wizard. Their integration awaits that handoff;
this task does not edit another slot's in-progress shell or wizard files.


### Completed shell and wizard integration

After #4505, #4511 and #4513 merged, the Prospects route mounts the existing
pipeline and sheets in the shared Distribution frame. ProspectsPage reads the
existing Grow form-options write permission; false, malformed and failed reads
keep all prospect writes disabled. The Worker's venture/write gates still
apply. The wizard's `?import=1` door opens the existing consent-aware CSV sheet
for writers. Add, import, status and consent completion refresh pipeline counts.
No new contact store, sending path or migration is added by the integration.

NewCampaignPage owns one consent-summary reading for the selected venture and
segment. Audience displays that reading and Schedule derives reachability from
the same reading. A changed scope immediately hides the preceding scope's
result, while the next request loads. Imported-list membership is not recorded
in the wizard, so an imported audience also remains unknown. An unavailable segment remains Not
recorded in both steps, without substituting the venture-wide total.

Mounted tests cover founder/read-only access, failed or malformed permission
reads, source filters, private detail emails, the three consent choices, import
refreshes and the actual Audience/Schedule flow. Deliberately removing the tab,
granting writes against the server permission, dropping the summary or its
segment, or hard-coding the review label must fail those checks.
