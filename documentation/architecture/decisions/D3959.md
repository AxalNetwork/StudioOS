### 2. The rules the pages keep

The Worker enforces each of these again; the pages refuse early with the same sentence.

- **A webinar** is planned at its own time, so the sheet asks for no date and says "Add and register". Reschedule is never offered for one. A full webinar reads "This webinar is full.".
- **An exam** only reserves the time. The sheet says it never starts the exam.
- **A study block** needs a name.
- **The time and duration:** a duration is 5 to 480 minutes, and a time that has passed is refused. "Until" must come after the start.
- **Done is automatic** when Learning records it, and a row says "Done · recorded by Learning". Mark done is not offered again on a done item.
- **A registration only opens.** A webinar the member is registered for, but has not planned, opens on its page and offers nothing else.
- **Remove asks first.** It removes the plan item and its repeats, and says that progress in Learning and a webinar registration stay.
- **Goals have no percent.** A goal is one item's, and reads "In progress" or "Done", never "0%" before the first item.
- **A read that fails** says so with Try again, never as an empty plan.
- **People** never appear: nothing here names anyone.

### 3. Choices a reviewer should check

- **The picker** lists courses and videos from the catalog, plus upcoming webinars, exercises and exams from their own reads. The catalog names a course by its slug, so the course's uid is read from the course when it is picked.
- **One client file:** every client call is in `pages/learning/planReads.js`, the folder's rule (`learning_ui_d562`).
- **Repeat:** a weekly repeat uses the start's weekday. The sheet does not offer a weekday choice; the Worker stores weekdays in UTC, and a local choice could land on the day before or after.
- **Unchanged:** the Calendar's note that a page-only entry "cannot be copied" still shows on Learning entries. It predates this part, and a guard (`calendar_page_c1`) pins it.
