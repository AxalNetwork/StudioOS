## D4809 — Investor cohort access: the NDA is sent explicitly, and every step to active access is recorded and recoverable (#4809)

- **Status:** Built for #4809, 2026-11-07. Worker and frontend.
- **Builds on:** D959 (investor cohort access, the NDA gate, O-NDA B) and D963 (the Programs page for it).
- **Migration:** `202611071835_investor_cohort_nda_delivery.sql` adds `nda_delivery` and `nda_delivery_at` to `investor_cohort_access`.

### The decision: explicit send (option 2)

- **Give access creates the grant and sends nothing.**
- **Each grant offers one NDA action**, chosen by `ndaAction`:
  - **Send NDA**, when nothing has been sent;
  - **Send NDA again**, after a failed delivery, a decline or a void;
  - **Void and resend**, while a delivered NDA is out.
- **Why explicit.** The send already existed as its own route (`POST /:uid/nda`). The template's wording is HQ's, and it can be missing or unfillable. An explicit action keeps each send visible and recoverable on its own grant. Folding it into Give would make one write depend on another.
- **The copy says so.** "Access given. No NDA has been sent yet: send it from the grant's Send NDA." The published-template line no longer claims each grant sends it automatically.

### What the grant says (`NDA_STATES`, `ndaStateOf`, `NDA_STATE_SQL`)

| NDA state | When | What HQ does |
|---|---|---|
| `not_sent` | never sent | Send NDA |
| `delivery_failed` | the last send could not create the envelope, or its email did not go | Send NDA again |
| `declined` | the investor declined the envelope | Send NDA again |
| `voided` | the envelope was voided | Send NDA again |
| `sent` | out for signature, email delivered | wait, or Void and resend |
| `signed` | the envelope completed | nothing: access opens |

Access stays `waits_for_nda` until `signed`. `active` also needs a verified investor and a grant that has not ended, as before.

### Rules

1. **A failed send is recorded on the same grant.**
   - Before this change, the route returned 502 and recorded nothing.
   - Now the grant takes `nda_delivery = 'failed'` and the admin audit records `investor_cohort.nda_send_failed`.
   - An envelope whose email did not go counts as a failed delivery, not as `sent`.
2. **Never two envelopes out.** Sending again over a still-open envelope (a failed delivery, or Void and resend) first voids it through `esign.voidEnvelopeForResend`. That helper follows the sender's void rule:
   - one batch;
   - only while nobody has started signing (otherwise 409 `signature_in_progress`, and nothing changes);
   - the envelope's own audit gets `envelope_voided`.

   The admin audit records `investor_cohort.nda_voided`.
3. **A delivered NDA is replaced only on purpose.** A plain send is 409 `already_sent`. Void and resend sends `{ void_previous: true }`.
4. **The signature is recorded with its history.** The completion hook writes `nda_signed_at` and an `activity_logs` row, `investor_cohort.nda_signed`, in one batch. The row is written only when the completion changed the grant.
5. **Programs › Activity lists the two new admin steps.** `INVESTOR_ACCESS_ACTIONS` gains `nda_send_failed` and `nda_voided`. The grant view carries `nda.sent_at`, `nda.signed_at`, `nda.delivery` and `nda.delivery_at`.
