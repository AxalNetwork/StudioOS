## D784 — The StudioOS MCP server answers at https://axal.vc/mcp, not under /api

- **Status:** asked by the owner on 2026-10-20 and decided by S1 on #2204. Built by S1.
- **Amends:** D665, D666 and D668, which named `https://axal.vc/api/mcp`.

### What the owner asked

> In Connectors, these slugs should be https://axal.vc/mcp and not https://axal.vc/api/mcp, for ChatGPT, Claude, Gemini, Grok..etc. The very reason MCP exist is, it works differently, so if we're using MCP using API pipeline. There's no point, resolve that..

### What was there

- **The address said `/api`, but the protocol already ran outside the API pipeline.** The Worker's `fetch` sends every MCP path to `routeMcp` (`cloudflare-worker/src/mcp/oauth.ts`) before the Hono `/api` app, so none of the REST middleware ever touched it. Only the URL, `MCP_PATH = '/api/mcp'`, put the server under `/api`.
- **Connectors gave every assistant that URL** (`frontend/src/pages/account/assistantSetup.js`, `MCP_SERVER_URL`).
- **Production had never logged an MCP tool call.** `activity_logs` held no `mcp_tool_call` row on 2026-10-20, so moving the URL disconnected no one.

### What was decided

1. **The canonical resource is `https://axal.vc/mcp`** (`MCP_PATH = '/mcp'`). The protected-resource metadata (RFC 9728) names it, at `/.well-known/oauth-protected-resource/mcp`, and an unauthenticated call's `WWW-Authenticate` points there.
2. **`/api/mcp`, and every path under it, answers 308 to the same path under `/mcp`,** query included (`LEGACY_MCP_PATH`).
   - 308 keeps the method and the body, so a client's POST arrives as sent.
   - A token is bound to the resource it was issued for (`@cloudflare/workers-oauth-provider`'s audience check). A token issued for `/api/mcp` is therefore not honoured at `/mcp`. None was in use. A client set up with the old URL reconnects with the new one.
3. **The SPA's consent API stays at `/api/mcp/consent/*`.** It is the SPA's own signed-in REST call, answered by the Hono app. It is never redirected: `isMcpPath` excludes it.
4. **The authorization server's endpoints stay at `/api/oauth/*`.** Clients read them from `/.well-known/oauth-authorization-server` and never type them. They sit outside the MCP resource, because the provider treats every path under `apiRoute` as needing a token.
5. **`wrangler.toml`'s two `run_worker_first` lists gain `/mcp` and `/mcp/*`,** so the assets binding's SPA fallback never answers them with `index.html`. This is not a route: no path-scoped apex route was added (CLAUDE.md fact 4).
6. **Connectors, the MCP README, `ROUTE_MAP.md` and `GOTCHAS.md` name `https://axal.vc/mcp`.** D665, D666 and D668 carry a pointer to this file.

### Not changed

- The tools, the grants, the scopes, the consent flow, the rate limits and `MCP_SERVER_ENABLED`. With the flag off, `/mcp` and `/api/mcp` both answer 404.
- The `/api/oauth/*` paths and the SPA's `/connect/assistant` page.

### Verified

- **`mcp_server_d666.test.ts`:**
  - discovery names `https://axal.vc/mcp`;
  - an unauthenticated call at `/mcp` is the provider's 401, pointing at `/.well-known/oauth-protected-resource/mcp`;
  - `/api/mcp` and `/api/mcp/sse?x=1` answer 308 to `/mcp` and `/mcp/sse?x=1` for GET, POST and DELETE;
  - `/mcpx` is not an MCP path, and `/api/mcp/consent/*` is never redirected;
  - with the flag off, `/mcp` and `/api/mcp` answer 404;
  - both `run_worker_first` lists hold `/mcp` and `/mcp/*`, and no route names `/mcp`.
- **`mcp_authorization_d669.test.ts`** runs against `/mcp`.
- **`assistant_connect_d668.test.mjs`** pins `MCP_SERVER_URL` to `https://axal.vc/mcp`.
- **`npm run test:drift`** gives EXIT=0.
