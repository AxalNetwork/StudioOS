## D6465 — The decisions index is generated, and a README can declare that it takes no per-file rows (#6465)

**Context.** `documentation/architecture/decisions/README.md` was the most
touched file in the repository: 52 of the last 396 commits on `main` (13%)
added one row to its table. `.gitattributes` merges every `README.md` with
git's `union` driver, but GitHub's server-side merge (the PR page and the merge
queue) does not apply it, so two PRs that each appended a row conflicted there
while merging cleanly on a local machine. Three open PRs (#6359, #5821, #5806)
were dirty only on READMEs like that. The hand-written table also listed 76 of
the folder's 1,591 decision files.

**Decision.**

1. A README may declare, in its own text, `<!-- index: generated -->` or
   `<!-- index: none -->`. `scripts/check-folder-docs.mjs` (rule 6) reads the
   marker from every tracked README, so marking another README later edits only
   that README, never a shared list in the script.
2. `index: generated`: the README holds the `<!-- files:begin -->` …
   `<!-- files:end -->` block of #4104, and the list is generated into it:
   source files by their header comment as before, and the folder's Markdown
   files (not the README) by their first heading. It is never committed
   (D5612): `--write` fills it in the working tree, `--clean` empties it, and
   the existing check fails a commit whose block holds a list. The list sorts
   numerically, so D999 comes before D1000.
3. `index: none`: the README describes the folder and its rule and holds no
   per-file rows.
4. For either marker the check fails a table row, outside the block, whose
   first cell names one of the folder's files in backticks. A marker without a
   block (`generated`) or with both markers fails. An unmarked README is
   checked exactly as before.
5. `decisions/README.md` carries `index: generated`, an empty block, and no
   hand-written rows. Adding a decision now adds its file and nothing else.
6. `AGENTS.md`'s "add one row per new file or folder" says such a README takes
   no row. `.gitattributes` no longer claims that union protects against
   GitHub's merge, and the dead `docs/.build-source merge=union` line (with its
   comment) is gone: `docs/` has not been committed since D529.

**Not built.** Other READMEs are not marked here (#6470, #6472, #5976), and no
guard yet refuses an append to a hand-written table (#6466). Decision
numbering and `scripts/check-decision-ids.mjs` are unchanged.

**Verified.** `scripts/lib/folderFiles.test.mjs`: a fixture decision file
appears in the generated list with no README change; the real guard, run in a
throwaway git repository, fails a list committed between the markers and a
per-file row in an `index: none` README, and passes an unmarked README's rows;
two fixture branches that each add a decision merge cleanly with
`git merge-tree` and merge attributes off, while the same branches appending
rows the old way conflict. Each assertion was mutation-checked.
