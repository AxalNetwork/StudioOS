## D4362 — An admin customises the Studio they switch to, saved as theirs (#4362)

- **Status:** built by Claude Code for slot S26, 2026-11-04. Not deployed and not checked live.
- **Supersedes:** D1419 SM11, which said an administrator is never offered Customise. The owner decided this on 2026-11-03, so the owner, a super admin, can arrange each Studio they switch to.
- **Migration:** none. **No Worker change.**
- **Code:** `frontend/src/pages/studio/useStudioLayout.js`, and the four homes (`FounderStudioHome.jsx`, `InvestorStudioHome.jsx`, `AdvisorStudioHome.jsx`, `PartnerStudioHome.jsx`).

### 1. What an admin can do now

- In the Founder, Investor, Advisor or Partner view, an admin sees Customise. They can arrange, add, resize and remove modules and press Done, and the layout is kept after a reload.
- The layout is the admin's own: one row per (admin, profile) in `studio_layouts`, never a member's. Each view has its own layout.
- Reset deletes only that view's row of the admin's.
- **The Admin Studio is unchanged.** In the Admin view, `/studio` is D598's Admin Studio, which has no modules and does not use this hook.

### 2. The Worker already did this

`/api/studio` (D1421, `routes/studio_layout.ts`) resolves an admin's profile through `studioProfile(user, ?profile=)` on every route. `GET /layout`, `PUT /layout` and `POST /layout/reset` all key the row by `(user_id, profile)`, and an admin who names no Studio gets a 400 `invalid_profile`. The hook already sent `profile` on every read, save and reset for an admin; only the page withheld Customise.

`cloudflare-worker/test/studio_layout_admin_d4362.test.ts` covers the two cases D1421's test left out:
- an admin's save and reset, per Studio, including a second save that updates from its revision;
- a member's own saved row, untouched by any of them.

### 3. Arranging unlocks nothing

- `readOnly` and the admin preview are now separate things. `canCustomise` no longer depends on who is looking: an admin gets Customise unless a page passes `readOnly`, and no Studio home does.
- What an admin may read is still each home's `withheld` (Investor, Advisor, Partner) and the Founder home's own reads. So a tile that said "Withheld in administrator preview" still says so, in edit mode and after Done.
- The catalogue and plan locks are the Worker's, for an admin as for a member: a module the admin's plan locks is refused with 402.
- Eadwyn's layout proposals (D1420) stay off for an admin (`403 read_only_preview`); Customise is the admin's way to arrange.

### 4. Tests

- `studio_admin_customise_d4362.test.mjs`:
  - Customise is offered for an admin in all four profiles, and `readOnly` still turns it off;
  - the homes no longer pass the preview as `readOnly`, and the three previews keep `withheld`.
- `studio_canvas_d1419.test.mjs` (updated): the mounted admin sends `investor` on the reads, the save and the reset; arranges with the tiles still withheld; and saves `[{ key, size }]` with `profile`. A `readOnly` Studio still reads "Default layout" with no Customise.
