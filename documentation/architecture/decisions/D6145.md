## D6145 — Deal flow: assign and change a deal's owner (#6145)

- **Status:** Built for #6145, 2026-11-16. Worker and frontend.
- **Builds on:** D1238 (an investor firm's own deal flow, migration 618), D1241 (the peek), D4632 (a flow row's version guard), D5900 (the deal card).
- **No migration.** `deal_flow_entries.owner_user_id` is already nullable, and `deal_flow_events` already has the kind `owner`.

### What was decided

1. **Who a deal can be given to is a read of its own.** `GET /api/deals/flow/owners` (`routes/deal_flow.ts`, `services/dealFlow.ts` `flowOwners`) is scoped the way the flow is.
   - In a firm's flow it lists the caller first (`you: true`), then the firm's active investor seats: `user_company_links` for that company, `role = 'investor'`, `is_active = 1`.
   - With no firm it lists the caller alone, with `can_unassign: false`.
   - It is the same query `validOwner` checks a change against (`SEATS`), so the page offers only people the Worker accepts. It sends ids and names only, never an email.
2. **Unassigned is an explicit `null` on a change, in a firm's flow only.** Before this, `validOwner` turned `null` into the caller's own id, so a deal could never be unassigned.
   - `PATCH /api/deals/flow/:dealId { owner_user_id: null }` now clears the owner.
   - `POST /api/deals/flow` keeps its default: no owner, or `null`, is the caller. A deal added without an owner is still the adder's.
   - With no firm, a clear is refused (`invalid_owner`, "Only you can own a deal in your own flow."). A solo investor owns every deal in their own flow.
   - **Why null, not a separate flag or route:** the column is nullable, and the PATCH already treats a missing key as "leave it". A missing key and `null` were already two things on the wire. Only `null` changed meaning, and no client sent it on a PATCH: the frontend had no owner control.
3. **The change is recorded in the flow's events, as it already was.** `updateFlow` writes a `deal_flow_events` row of kind `owner` with the actor for every owner change, a clear included (D1238). The row does not say who the new owner is, because `from_stage` and `to_stage` hold stages. Recording the names would need a column, and that is out of this issue's size.
4. **The page.**
   - The peek's Owner row is a picker (`OwnerControls.OwnerPicker`). It offers "Me · name", each colleague, and Unassigned. A current owner the read no longer lists stays shown, disabled, so the picker never misnames them.
   - A refusal stays under the picker in the Worker's words, and the row keeps its owner.
   - When the owners cannot be read, the page shows the current owner and says Unreadable, with Try again. It never shows an empty picker.
   - With no firm, the peek shows the investor's name and no picker.
   - "Assign to me" sits on the board's card (`DealCard`, beside Move to…) and in the table's Owner cell. It shows on rows in the flow that someone else owns, or that no one owns. It is hidden with no firm and while the owners read is not answered.
   - Every change leaves a toast with Undo, which gives the deal back to the owner it had before. The row is replaced with the Worker's answer, so the board, the table and the Owner filter (Mine, Unassigned) follow it without a reload.
   - Every target is 44px on a phone (`max-sm:min-h-[44px]`).
5. **The board and the table reach "Assign to me" through a context (`FlowOwnerContext`), not a new prop.** #5901 (PR #6874) is redrawing `FlowTable.jsx`. A context leaves its rows, signatures and call sites alone, so each of the two files changes by one import and one line. `FlowBoard.jsx` is not changed: the card it draws is `DealCard`.
6. **"Where `can_move` is true."** A flow row carries no `can_move`. That field belongs to the Studio lens's rounds (D1242). Every row in the investor's own flow is theirs to move, and the Worker refuses a change from an admin's investor preview (D5915). So "in the flow" is the rule here. A refusal from the preview shows in the toast.

### Not done here

- The events do not name the new owner (see 3).
- No notification is sent to a colleague who is given a deal.
