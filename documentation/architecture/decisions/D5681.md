## D5681 — Operator triage and slot work orders for reproduced section defects (#5681)

The first two cases are Learning discovery list rendering and Help Center guide placement. Each has a fixed source file and regression test. The operator reproduces an ordinary UI regression in a controlled fixture and selects its case. A render error alone, CI output alone, a Slack message, or a customer report cannot authorize a task. New cases require a reviewed code change.

### Run a preview

Use Node 22.13 or newer with built-in SQLite. From the repository root:

```sh
node scripts/section-triage.mjs scripts/lib/section-triage-example.json
node --test scripts/lib/section-triage.test.mjs
```

The example is permanently excluded from live writes. The default command previews the public title, body, labels and fixed test locally. It needs no GitHub credentials or database.

### File or reconcile a verified defect

An operator with permission to write StudioOS issues supplies a six-field JSON record using the example's schema. Use the persistent episode UUID from private triage, its cumulative count, the observed main commit, and source `operator-reproduced`. Check whether the same defect is already tracked. Keep Slack references and private observations in the private incident record.

Use one persistent `SECTION_TRIAGE_LEDGER` SQLite path shared by all invocations on the operator host. Back it up with operational state; all writers must use the same file. Run under a named, authenticated `gh` user. Map section keys to actual owners in trusted operator configuration, for example `SECTION_TRIAGE_OWNERS='{"all-learning":{"login":"approved-login","slot":"S12"}}'` with the team's verified values. The tool checks repository assignability and that the slot label exists. A missing mapping files an unassigned bug for S01. The repository API helper is shared with `scripts/claim.mjs`.

```sh
node scripts/section-triage.mjs evidence.json --apply
node scripts/section-triage.mjs evidence.json --apply --work-order
```

A durable intent precedes issue creation. On repeat events the same issue is returned. Count updates post at powers of two above the initial count. Missing, late or duplicate observations never decrease a published threshold. An ambiguous creation returns the episode marker on retry and blocks further creation. Locate the original (open or closed) issue by the marker and original author, then run `--apply --link-issue NUMBER`. If acceptance cannot be established, leave the intent pending for operator reconciliation. An uncertain milestone is checked against its original comment receipt; the tool does not retransmit an ambiguous POST. A definite rate-limit or validation rejection releases the unsuccessful attempt; retry after the provider's delay. Labels, existing assignees, comments, descriptions and human issue state are preserved on recurrence. Closed issues still require operational recovery verification.

### Hand a fix to the current slot protocol

`--work-order` returns a local S01 proposal for the verified sole assignee, with the fixed test and source path. It defers to current claims, task labels and open cross-referenced PRs. S01 also checks current drafts and branches before dispatch, because a PR without an issue reference cannot appear in its timeline. The slot follows the atomic claim protocol in AGENTS.md.

For **first filing only**, S01 authenticated as the repository's coordination owner can explicitly place a reviewed ordinary defect in the existing queue:

```sh
node scripts/section-triage.mjs evidence.json --apply --queue-for-slot
```

This adds the existing slot and ready labels, verified assignee and an S1 work order together at creation. An existing open task for the same fixed case or an incomplete lookup defers to S01. An existing linked issue requires S01 review to promote. The slot owner polls its usual ready queue, takes the atomic claim, reproduces the defect, changes the branch, and opens one draft PR with the regression test. CI and owner review govern release. The triage tool does not invoke a coding agent, dispatch a workflow, create a branch or PR, merge, deploy, or assert recovery. To stop new work, omit the queue flag or disable the operator invocation. Existing slot tasks are managed through their usual owner and state protocol.

The upstream authenticated event receiver, verified test-failure attestation, a durable production operator ledger, live assignee configuration, automatic dispatch and a deployed health receipt are separate rollout work. No workflow subscribes this CLI to untrusted input. Security, permission, credentials, financial, contract, and migration defects stay in their restricted workflows.
