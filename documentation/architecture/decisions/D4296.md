## D4296 — The Influencer section: a sidebar row by membership, six tabs, and every figure honest (#4296)

- **Status:** D4289 P7, 2026-11-03. Part of #4289. Frontend only: every read it uses is on `main` (P1, P2, P4, P5, P6).
- **Migration:** none.
- **Boards:** IN0–IN6 and IN12's -p and -d frames, `design/incoming/Influencer Page.dc.html`, notes in `design/incoming/Influencer · Boards.dc.html`.

### 1. The row and the routes

- **The row follows the membership, not a role.** `INFLUENCER_ROW` (the megaphone) and `withInfluencerRow(groups, role, active)` sit beside `withDiligenceRow` in `frontend/src/sidebarConfig.js`. `getSidebarGroups` in `App.jsx` applies it for every shell from `/api/auth/me`'s `influencer_active` (`influencerActiveOf`): last in the shell's first group, under the profile's own rows, never twice. `label` is first in the literal, so `scripts/build-profile-routing.mjs` does not count it as a static row.
- **Six addresses**, one per tab (`frontend/src/routes/influencer.jsx`): `/influencer` (Overview), `/influencer/links`, `/influencer/offers`, `/influencer/earnings`, `/influencer/audience` and `/influencer/resources`. Each is `authOnly`, and the page draws the section only while `member` (the same `influencer_active`) is true and `GET /api/influencer/me` returns an active membership. Anyone else reads "This is for Axal influencers", and nothing else is read for them.
- **Layout.** `/influencer` is in `SHARED_FULL_BLEED` and `/influencer/` in `SHARED_FULL_BLEED_PREFIXES`; the trailing slash keeps `/influencers`, the public program page (P8), off the rule. The page draws the viewer's Eadwyn rail (`WorkerRail` in a `RailFrame`, the shell role's accent) under the key `<Profile> · Influencer` (`railPages.js`, off-canvas: the AIRail canvas draws no Influencer board).

### 2. Honest values

- **A Count** is a number or "Fewer than 5" (`{ fewer_than: 5 }`); a small group draws no bar and no number.
- **A figure nothing stores** reads Not recorded, with its source on hover. **A failed read** reads Unreadable with Try again, in its own block, and the rest of the page still draws. Neither is drawn as 0.
- **Both analytics shapes are drawn:** `main`'s, where visits, paid members, revenue, bonuses, channels, retention and visit → paid are `not_recorded`, and the wired one (#4295, branch `…-4295-analytics-wire`), where they carry figures.
- **Money is per currency**, one line each, never summed: the KPI tiles, the earnings tiles, the weekly commission (one chart and one table per currency), an offer's discount given, and the payout history.
- **Eadwyn's line** is the analytics reply's `line`, drawn as it is. Nothing in the frontend writes a sentence about the figures.
- **No referred member is named.** No read returns one; the views copy named fields only, and the test feeds stray names, emails and ids into every reply to prove none is drawn.

### 4. Deviations from the boards

- **The per-invoice ledger** (IN4) is drawn as the commission per week and per currency (`commission.series`). The only invoice-line read on `main` (`GET /api/network/commissions/me`) returns whole commission rows, and this page draws no field a read was not made to show.
- **No week-on-week deltas** ("+18%"): the reply carries one range, not a previous one.
- **The brand kit's downloads are off** ("HQ has not published this file yet"), and the board's private events are not drawn: no store holds either.
- **The QR code** (IN2) is a PNG only (`qrcode`, already a dependency); the board's SVG download is not drawn.
- **Accent.** The viewer's role accent (founder violet, investor indigo, advisor emerald, operating partner amber), as `workspaces/shellConfig.js` names them; no new colour.
