## D4538 part 7 — Compare with Axal and Extend, built to the Extension Compare canvas (#4538, #5964)

Part 2 (`D4538-p2.md`) built the two Worker routes an extension needs: `POST /api/teams/skills/:uid/extend` and `GET /api/teams/skills/:uid/base`. They had no frontend caller. This part builds the screen and the action to the Skill Library v2 Extension Compare canvas (D5963, boards SK-17 to SK-25 and SK-H). It changes no Worker code, no migration and no route.

### What is built

- **Client methods** (`frontend/src/lib/api/teamAgents.js`): `extendSkill(uid, { company, reason, version?, name? })` and `skillBase(uid)`, one per mounted route. Behind `agentsAdapter.js`, `skillBase` reads the Worker's 404 as "There is no such skill". `extendSkill` keeps each refusal's code, so the dialog can tie it to its field.
- **The page** (`SkillComparePage.jsx`) is at `/account/companies/:uid/settings/team/skills/:skillUid/base`, its own page per owner Q1 option A, admitted to the same profiles as the company's Team. It reads the extension's card, its lineage, and the company's name from the Team library read. It draws:
  - the header: "Based on Axal [name] vN", your version and its state, and a Retired or Suspended by Axal chip;
  - the reason;
  - the banner. When the Worker's `base_update_available` is true it reads "Axal published v5. Your extension is based on v3. 2 parts conflict." with the conflict count. Otherwise it reads "Up to date with Axal vN", or for a retired base "No further Axal versions";
  - for writers whose draft differs from the published version, the line "Your unpublished draft edits are not in this comparison";
  - the comparison;
  - the history.
- **The comparison** (`SkillExtension.jsx`, rules in `extensionCompareModel.js`):
  - On desktop it is a real table, with the parts as row headers and a caption naming the order. On a phone it becomes one card per part.
  - Conflicting parts come first, then the fixed order.
  - Each row's marker is the Worker's own `fields[]` flag (`conflict`, `company_changed`, `base_changed`), never a second comparison. Every marker is a word plus a glyph.
  - Only the + / − lines inside a list part are computed in the browser, as a longest common subsequence. Kept runs are folded, and screen readers hear "Added:" or "Removed:".
  - A tool new in Axal's newest version reads "New in Axal vN — not available to this extension": an extension's tools narrow and never widen.
  - There are three columns only while an update is available.
- **Who acts.**
  - **Editors** (the card's `can_write`) see "Edit my draft" (the skill's page) and, when Axal has a newer version, "Extend Axal vN again…". While that version is suspended the button is `aria-disabled` and describes its reason, "Axal has paused vN, so it cannot be extended right now." A retired base shows no Extend again.
  - **Members** read the page with the line "Only your company's editors can change this skill."
  - **HQ admins** read it under "Viewing as Axal HQ — read only" (owner Q2 option A), because HQ moderates company skills and never writes one.
  - **Rebase** is drawn disabled with "Not built yet · #5965".
- **The Extend dialog** (SK-21) runs on the shared `Sheet`. It is opened from SK-10 as "Extend for [company]…" on a published Axal skill, for the company's editors, and from the compare page as Extend again.
  - It asks for a reason (required, with a 300-character counter), a name (starts as Axal's; sent only when changed) and a version (every published version, newest first).
  - The reason is checked before anything is sent.
  - Each Worker refusal is drawn tied to its field. `fork_reason_invalid` goes on the reason field. `name_missing` and `slug_taken` go on the name field. `version_not_published` and `version_invalid` go on the version field. `base_retired`, `base_suspended` and `not_editor` go on the dialog. A refusal with any other code shows the Worker's own message.
  - On 201 the dialog opens the new draft. Nothing is attached to an agent.
- **SK-10's line.** An extension's skill page reads "Based on Axal vN · Compare with Axal" only when its card's `based_on` is set (`fromWorkerSkill` now keeps `based_on`).
- **States** follow Platform States (D5129):
  - The Worker's `lineage: null` reads "This skill is not based on an Axal skill. There is nothing to compare it with."
  - `lineage.base === null` reads "Axal's version could not be read. So there is no comparison and no update signal. This is not 'up to date'." The header and history still show, and the Axal name is not guessed.
  - A failed read reads "The comparison could not be read. Nothing below is a guess." with Try again.
  - The Worker's 404 reads "There is no such skill".
  - A null `based_on_version` in history reads "Not recorded", never "v0".

### Not built here

- **Rebase** (#5965): no route exists, so it is drawn disabled, never as a working control.
- **Who published each company version, and when**: the Worker does not return it, so the history reads "Published by, when: Not recorded".
- **Eadwyn's proposals on this page** (a version summary, a way forward per conflict, a reason from the skill's purpose): no route serves them, and nothing is invented in their place.
- **"Edit my draft"** opens the skill's page (SK-10). The page has no inline editor yet, so there is nowhere to land the canvas's "Accept into my draft".
