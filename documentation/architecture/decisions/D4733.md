## D4733 — Team › AI agents › skills: four integration gaps closed (#4733)

- **Status:** built 2026-11-07.
- **Builds on:** D1612 (skills, A1 #3951 and A2 #3956), D1496 (team agents), #3885 (Team settings), #4045.
- **Migration:** none.

### What was wrong, and what changed

1. **A skill page never listed its agents.** `GET /api/teams/skills/:uid/agents` matched `team_agents`' `GET /:scope/:id/agents` first (with `scope = 'skills'`), whose `loadScope` returns null for any scope but company or project, so it answered 404 without ever reaching `team_skills`. `team_agents` now calls `next()` for a scope that is not `company` or `project`, so the order of the two mounts no longer matters. `team_agent_skills_d1612.test.ts` mounts the routers in `index.ts`'s order, so it fails without the fix.
2. **Every attempt in the New skill sheet was refused.** `createSkill`, `updateSkill`, `publishSkill` and `importSkill` were `off()` stubs. They now call `POST /api/teams/skills`, `PATCH /api/teams/skills/:uid` and `POST /api/teams/skills/:uid/publish`. An import is `POST /api/teams/skills` with `skill_md`; there is no import route and none was invented. The adapter maps the sheet's body to the Worker's (`description` → `purpose`, `taxonomy[].skill_slug` → `tags[].slug`). Skills are a company's: a project scope is refused in the sheet's words and sends nothing.
3. **Roles.** v2 has no role picker ("any skill can go to any agent"), but `checkDraft` requires at least one role. `POST /skills` now holds a skill written with no `roles` (a body without the key, or a SKILL.md without a roles line) to every agent role. An explicit empty list on a JSON body is still `roles_missing`.
4. **Data sharing per role showed "Not recorded" for every agent.** `agentDto` now carries `reads_line`, built from the role's effective rule book `works_in` ("Works in Studio, Distribution"); `null` when the book cannot be read. The card shows "Not recorded" only for an absent or null line.
5. **"AI agent" and "Add an agent" did nothing while the roles read was pending or failed.** The sheet needs that read, so `agentOff` and the Agents card now include it: the control is disabled with "Reading the roles…", "The roles could not be read." or the refusal's own words.

### Rules kept

Copy says "Ask", never "Fill". Unknown shows "Not recorded", never 0. Refusals use `skillRefusalWords`, never `e.message`. No client method without a mounted Worker route.
