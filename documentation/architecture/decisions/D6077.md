## D6077 — Capital relationships: search, filter and sort in Pipeline's board and list (#6077)

- **Status:** Built, 2026-11-14 (frontend and one Worker read; no migration).
- **Builds on:** D5377 (the tabs' filters in the address), D5073 (the pipeline's view and open investor in the address, picks by stable id), D1192 (Pipeline), D691 decision 10 (Fit).

### What was missing

The pipeline could be searched, filtered and sorted only on the generic Cycle table under Overview (`services/raiseCycle.ts` `capitalRecords`: Stage, Fit, Path, Source; Last contact, Recently updated, Next step due, Name), which #5081 removes. The canvas (`design/incoming/Capital Relationships Page.dc.html`, `pipeBar` on CRL2 and CRL3) draws the bar on Pipeline itself, above both views.

`GET /api/contacts/raise-prospects`, Pipeline's read, was `SELECT * FROM raise_prospects`: stage, warm path, next step and due, updated, but not Fit, Source or last contact, which the Cycle table derives.

### The Worker read

- `prospectSignals(env, projectId)` in `services/raiseCycle.ts` returns, per prospect id, `fit` (`fits`, `outside`, `unclear`, `not_recorded`), `via_call` and `last_contact`, from the Cycle table's own `loadProspects` and `prospectFunds`: Fit only from a fund the directory still serves (`SERVED_FUNDS`), else "not recorded"; `via_call` only while `ROUND_CALLS_ENABLED` is on; last contact only from the prospect's own venture's stored contact. Nothing is derived a second way. Every query is bound.
- The route adds them to each item on a **one-venture read** (`?project_id=`), for the venture the owner-scoped rows came from, so the scoping is the route's unchanged `ownedProjectScope`. The response carries `signals`: `ok`; `not_read` for a read across ventures (enriching each venture would cost several D1 queries per venture); `unreadable` when the derivation fails, in which case the prospects are still returned without the three fields. It also carries `round_calls`, so Source is offered only when the Cycle table offered it.

### The bar

`frontend/src/pages/raise/caprel/CapRelPipeline.jsx` draws `PipelineBar` above the Board and the List; `capRelPipelineFilters.js` holds the pure rules.

- **Search investors** reads the name, firm and warm path (the Cycle table's `has(q, name, firm, warm_path)`). **Stage**: the five stages and Passed. **Fit**: Fits, Outside its focus, Unclear, Fit not recorded. **Warm path**: has one, or none (blank is none). **Source**: Responded to a round call, or not through a call; shown only while round calls are on. **Next step**: overdue (due before today), due in the next 7 days, has a next step, no next step set. **Sort**: Next step due (the default; none last), Last contact (newest first; none last), Recently updated, Name.
- **Both views show the same investors.** The filters narrow the loaded read; each board column is in the sort's order; the List is given only the shown rows.
- **In the address** (D5377): the keys `q`, `stage`, `fit`, `path`, `source`, `next`, `sort` join `passed` in `PIPELINE_FILTERS`. A value the bar does not offer reads as its default; a default stays out of the address; a filter or sort change pushes an entry, so Back restores the set before, and a search keystroke replaces it. Pipeline's venture-switch clear already drops every `PIPELINE_FILTERS` key.
- **No match** says "No investor matches these filters", how many are in the pipeline, and offers Clear filters, which keeps the sort and the Passed column. A count line says "Showing N of M investors" while a filter applies.
- **Not read is not "no match".** With `signals` other than `ok`, the Fit and Source filters are disabled and not applied, the Last contact sort is disabled, and the count line says they are unreadable or were not read.
- **Bulk Move acts only on picked rows still shown.** D5073's pick pruning now runs against the shown rows, so a row a filter hides is unpicked, and the bulk Move takes picked rows from the shown list only.
- **Targets.** Every control is a native input, select or button with a label, at least 44px tall below 1024px (`min-h-11`, `lg:` smaller), and so in the tab order; the Board/List toggle gets the same height. On a phone the board's one-column picker follows the Stage filter.

### Departures from the canvas

- The chips are native selects (the canvas draws `Stage ▾` tags), so each is keyboard- and screen-reader-operable with no custom menu.
- Source has two values (through a call, or not), because a call response is the only source the platform records for a prospect; it is hidden while round calls are off, as the Cycle table hid it.
- The canvas's List columns for Fit, Warm path and Last contact are not added here; the issue scoped the bar.
- No "Drag a card to move it": the board moves through Move to… as before.
