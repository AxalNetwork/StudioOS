## D5364 — Block cards preserve their exact session range (#5364)

**Decision.** A `sessions:block` proposal carries its original `from` and `until` instants through the Ask-to-Sessions address. The Block form displays those instants as date and time fields in the advisor's configured timezone and submits the same exact instants when they are unchanged. If the advisor edits the fields, the edited wall times are converted back to UTC before the existing Worker route receives them.

The form's times are optional only for a hand-entered block. Leaving both empty keeps the established whole-day contract: `from` and `until` are UTC midnights and `until` is the day after the last blocked day. Supplying only one time is refused rather than widened or guessed. Old date-only handoff URLs remain readable as whole-day blocks.

**Order and reporting.** D1596's mutation order is unchanged: Block writes first; only a successful write decides the proposal. Booked slots remain untouched and their skipped count remains visible. No Worker change is needed because `POST /api/advisors/me/slots/block` already accepts arbitrary ISO instants.

**Reusable seam.** `sessionsBlockHandoff.js` owns validation, address transport, zoned display parts and wall-time conversion so the Sessions redesign tracked by #4832 can reuse the same range semantics instead of reimplementing them.

**Checks.** `frontend/test/ask_block_accept_4737.test.mjs` covers an exact afternoon, a hand-entered date-only block, an exact midnight-to-midnight card, mutation order, skipped-card behaviour and invalid handoffs.
