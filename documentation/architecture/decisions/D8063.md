### Decisions

1. **A `main` branch rule, not "protected branches".** The issue asked for
   protected branches, but `scripts/verify-production-environment.mjs` requires
   `custom_branch_policies` with exactly one branch rule named `main`, and a
   protected-branches policy would admit any protected branch. The baseline
   therefore expects `custom` and `main (branch)`.
2. **The thin-space names are kept.** `production` and `staging` are stored
   with a trailing U+2009. Renaming would make a new environment and lose the
   deployment history, so they were kept, and the baseline expects
   `name_exact` `false` for both (the check keys them by the trimmed name).
   `production-ops` and `preview` have exact names.
3. **Inventories are not baseline rows yet.** On 2026-11-21 the four changed
   environments held no secret and no variable, `landing-bot` held
   `LANDING_BOT_APP_ID` and `LANDING_BOT_APP_PRIVATE_KEY`, and the repository
   held its existing secrets, none moved or read. The cutover the STATUS lists
   as outstanding changes the four empty inventories, and later requests on
   #8063 (a preview token on 2026-11-26; the `production-backup` and
   `production-monitoring` moves of D8754) already do. So only `landing-bot`'s
   names are a row; the others stay to be recorded until a STATUS reports
   them after the cutover.
4. **`environments.names` stays to be recorded.** The STATUS names the
   environments it changed and mentions `scan-remediation` (unchanged) and the
   `pr-preview` name the current preview jobs use, but does not list every
   environment.
5. **`production-backup` and `production-monitoring` are #8754's rows.** The
   owner confirmed on 2026-11-26 that both exist with their own secrets and
   deploy from `main` only; no record gives the policy mode, the reviewer count
   or the names, so their rows stay to be recorded.
6. **Administrator bypass is not a row.** The check does not read it; it is
   recorded here.
