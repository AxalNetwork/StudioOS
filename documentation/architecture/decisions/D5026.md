## Decision contract

Opening a view writes nothing. Creating a draft freezes the chosen published version and server recommendation; the form asks term dates and reason. Offering, declining, expiring and superseding are separate reasoned decisions on an unaccepted offer. The server's recent-authentication/write bar, permission, date, grantability and revision checks remain authoritative. An ungrantable bundle is refused (owner option A), never silently omitted.

Acceptance first reads the exact server consequences: frozen version/composition/dates, country snapshot/model, recommended/accepted price, grant conflicts, legal strategy/gate and effects on grants/branch delivery. Changing price or override reason invalidates the review. Only a conflict-free, hashed offered revision reaches the second acceptance step. A reason is required; the submitted body preserves the reviewed price, `review_hash`, `expected_revision` and one operation key. Nothing sends/signs an agreement; a commercial grant is not represented as in force.

Before transmission, the exact operation is retained in memory and, when available, this browser's sessionStorage scoped to actor and licence. A network/server failure remains Outcome unknown and blocks starting another operation. A deliberate retry sends identical inputs/key, including after remount/reload. A confirmed response clears the pending operation; a definite 4xx refusal discards the stale review and asks for a fresh read. No automatic retry or success toast on an unknown response. Browser storage is not an authority; the Worker revalidates every request. A blocked storage API still permits the current page's in-memory retry.
