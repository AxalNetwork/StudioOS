## D9186 — The edge error handler answers 413 and constraint failures, and logs which route failed (#9186)

- **Status:** built by S05 on #9186, 2026-11-27.
- **Chosen by:** the coordinator audit of 2026-11-27 (RL-05, RL-10, RL-12), as filed.

### The problem

`app.onError` in `cloudflare-worker/src/index.ts` mapped only the auth messages. Anything else was a 500:

- Hono's `bodyLimit` with no `onError` throws `HTTPException(413)`, so an oversized body on the public Meta data-deletion callback and on two formation routes answered 500.
- A D1 UNIQUE or FOREIGN KEY failure is the caller's conflict, not a crash, and still answered 500. The Telegram consent PUT hit one for every unknown user id.
- The `edge_unhandled` log line named only the error class, so hundreds of them in a run named no handler.

### What was decided

1. The handler's last branch is `edgeFallback` (`cloudflare-worker/src/util/edgeError.ts`). The branches above it stay as they were, so another task that edits `app.onError` merges around one line.
   - An `HTTPException` is its own answer: `err.getResponse()`.
   - `UNIQUE constraint failed` answers 409 `already_exists`.
   - `FOREIGN KEY constraint failed` answers 409 `related_record_conflict`. It is 409, not 404, because the same failure also comes from deleting a row others still reference. A route that knows the id is unknown checks first and answers 404 itself, as the consent PUT now does.
   - Anything else is the generic 500, as before.
   Refusal bodies are fixed sentences. No SQL text, table or column name reaches them.
2. `reportPrivateError` takes an optional `where`: the method and the matched route pattern (`c.req.routePath`), never the request path, so no id is logged. `edgeFallback` also passes a fixed D1 class as `code`: `sqlite_constraint_unique`, `_foreignkey`, `_notnull`, `_check`, `sqlite_no_such_table`, `_column`, `sqlite_busy` or `d1_error`. The message is still never logged.
3. Every `bodyLimit(` in `cloudflare-worker/src/routes/` passes `onError` and answers `refuse(c, 413, …)`. `cloudflare-worker/test/edge_errors_9186.test.ts` fails on a new one that does not.
4. `PUT /api/admin/telegram/consent/:user_id` checks the user exists and answers 404 `user_not_found`.
