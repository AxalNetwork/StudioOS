## D715 — Mercury on Connectors: entity connections for admins, a member's own connection that says what it is for

Issue: #1780 (S20; PR 1a built by S02 at the owner's request). This file grows with each PR: PR 1a writes the model, PR 1b the API module and the connections read's accounts, PR 2a the entity sheet without its canvas, PR 2b its canvas, PR 3 the member's sheet.

### Why

When D710 (#1775) and D713 (#1778) are both on `main`, the Worker serves two Mercury rows, and Connectors draws both wrong:

- **The entity row** (`connection_source: 'mercury_entity_connections'`, an admin on HQ) opens the per-user key form. The Worker refuses that form with 409 `entity_connection_only`, and nothing reads `/api/admin/mercury`.
- **The personal row** (a founder's or a partner's) prints "Nothing · Mercury only pulls in" beside "only sends out". It offers Sync now on a connection that never syncs, and company ticks that gate nothing. It says nothing about what the connection is for, or what it never does.

### What was decided (S1, on #1780)

1. **The Worker's row picks the sheet, never the browser's role.** The entity row opens the entity sheet; the personal row opens the member's. "View as" and a support session change what the browser believes, not what the Worker serves.
2. **The entity connections are not "Yours".** One Mercury card sits in a "Fund administration" group on both tabs and on a phone, and in Discover it is badged "Entity connections". Build's "Connect a tool" leaves the entity row out.
3. **No entity read until the sheet opens.** Each read writes an audit row, so the card draws from the catalogue alone, and a sign-in return naming `mercury` opens nothing.
4. **The entity sheet** draws one row per entity: Holdings, Management, GP, Fund. Each row carries its state, the organization Mercury names, and its accounts as kind and "ending NNNN". It also carries the last sync and the error in words. It never shows a balance, a transaction, a Mercury account id or a token beyond the Super Admin's preview.
5. **The Super Admin** gets Connect, Replace, Disconnect and Sync now. **An Admin** gets Sync now and one sentence. **An admin on a branch** reads that HQ manages the accounts, and no read is made.
6. **Connect and Replace** take a Read Only token and a ticked box, sent as `confirm_read_only: true`. There is no webhook field and no settings field.
7. **Disconnect** takes a reason of at least ten characters.
8. **A member's own Mercury** says what StudioOS uses it for, what it never does, where it lands and how it reads, in place of the generic groups.
9. **The personal row** reads "Reads on request", "Read on request" and "You", and its own attention words.
10. **A "mercury" search** with no row says Mercury is not offered to this profile, and offers no request.
    - *Amended by D752 (#1886):* the sentence names each role's use; an investor on a branch reads that Mercury is on HQ only.

### PR 1a: `frontend/src/pages/account/mercuryModel.js`

The words and rows of decisions 4 to 10, as pure functions. It has no React and no fetch, and imports nothing from `connectorsModel.js`, which will import it. It keeps its own copy of `codeWord`'s `/^[a-z0-9_]+$/` test.

- **`entityRow(key, connection)`** reads only `status`, `mercury_org_name`, `org_name_differs`, `last_synced_at`, `last_error`, `token_preview` and `accounts` (kind, last four, nickname, `registered`).
  - A balance or a Mercury account id in the input never reaches the output.
  - `last_synced_at` is returned raw, for `agoLabel`.
  - `token_preview` is passed on; the sheet decides who sees it (decision 5).
  - A connection whose read carries no accounts gets `accounts: null` with "Not recorded", never an empty list.
- **`entityRows(read)`** orders `GET /connections`'s `entities` as Holdings, Management, GP, Fund. The names come from `AXAL_ENTITIES`.
- **Error words** cover the codes D710's client writes to `last_error`: `unauthorized`, `rate_limited` and `timeout` (`services/mercury/client.ts`). Any other code is printed only if it passes the code test; a sentence is never printed. #1798 merged before this PR, so the rate-limit and timeout words are here rather than in PR 1b.

**Not in PR 1a:**
- the member's use words (venture revenue, practice income, partner deals), which are keyed by #1778's `routes/mercury_personal.ts`. That file is not on `main`, and keys are never guessed;
- the API module, which comes in PR 1b (below).

### PR 1b: the API module, and accounts on the connections read

- **`cloudflare-worker/src/routes/admin_mercury.ts`:** `GET /connections` gives each connection `accounts: [{ kind, last_four, nickname, registered }]`, read from `mercury_accounts` under the same audit row.
  - The query selects only those four columns, so no balance (`current_cents`, `available_cents`) and no `mercury_account_id` can be serialized.
  - An entity with no connection stays `null`.
  - Nothing else in the file changes.
- **`frontend/src/lib/api/adminMercury.js`** exports `adminMercuryApi`, with one method per route #1775 mounts under `/api/admin/mercury`: `connections`, `connect`, `disconnect`, `sync`, `accounts`, `transactions`, `matches`, `proposeMatch`, `confirmMatch` and `rejectMatch`.
  - `connect` always sends `{ api_token, confirm_read_only: true }`, with no webhook or settings field.
  - It has one line in `api.js`'s module block (D527).
  - #1779's console imports it rather than adding its own.

### PR 2a: the entity sheet, without its canvas

No canvas covers the entity sheet yet, so PR 2a draws it only from parts that already exist: the Connectors sheet's `Sheet`, `Group`, `Row` and `Banner`, the Account center's buttons and fields, and the words in `mercuryModel.js`. The canvas PR lays it out, and adds the Fund administration group, Discover's "Entity connections" badge and Yours' search change.

- **`frontend/src/pages/account/MercurySheet.jsx`** draws the four entity groups (Holdings, Management, GP, Fund). Each group shows the state, the organization, the accounts as "ending NNNN", the last sync, the error in words and the Fund's note, with the audit sentence at the foot.
  - `MercuryEntityConnections` makes the one audited `GET /connections` read when it mounts, and again after an act. #1779's Banking tab draws it rather than a second copy of these controls.
  - The Super Admin gets Connect, Replace, Disconnect, Sync now and the token preview.
  - Any other admin gets Sync now and `ADMIN_ONLY`, with no write control and no preview, even when a response carries one.
  - A branch admin gets `BRANCH_MANAGED`, and the sheet makes no read.
  - Connect needs the Read Only box ticked. The token is cleared after every answer, and the help link is the registry's `docs_url`.
  - Disconnect needs a reason of at least ten characters.
  - A refusal is the Worker's own sentence. Sync now's 429 adds "Try again in N minutes."
  - Bank text is drawn as text. No balance, transaction or Mercury account id is drawn.
- **`connectorsModel.js`:** `isEntityRow(p)` is `connection_source === 'mercury_entity_connections'`.
  - `cardAction` gives `entity` (the card's Open).
  - `toolGroups` and `toolDeepLink` leave the row out, so Build never shows it.
  - A sign-in return naming `mercury` opens nothing.
- **`ConnectorSheet.jsx`:** `openingView` gives `entity`, and `ConnectorPanel` hands that row to `MercuryEntityPanel` before any flow can fetch.
- **`AccountConnectors.jsx`** follows decision 10. A search that names Mercury when no Mercury row is served shows `NOT_OFFERED` (or `BRANCH_MANAGED` for a branch admin), with no "Request it." A sign-in return naming `mercury` opens no sheet.
- **Test:** `frontend/test/mercury_entity_sheet_d715.test.mjs`.

### PR 3: a member's own Mercury, before #1778's PR B

The personal row is `key: 'mercury'` with `connection_source: 'integrations'` (`isPersonalMercury` in `connectorsModel.js`). It stays in `ConnectorPanel`, so Connectors and Build's lightbox draw the same sheet. No canvas covers it yet, so it uses the sheet's own `Group` and `Row`.

- **`MercurySheet.jsx`** adds `MercuryUsesGroups`, `MercuryLandsGroup` and `MercuryReadsGroup` (decision 8). `ConnectorPanel` draws them in the `pre`, `pro` and `detail` views instead of what a syncing connector shows:
  - instead of `UsesGroups`, "What StudioOS uses it for" and "What it never does";
  - instead of "It will serve" and the company ticks, "Where it lands";
  - instead of the Sync group, "How it reads".
- **What each group shows:**
  - **The uses group** reads "Not recorded" with its reason until #1778's PR B. The uses a profile allows come from `GET /api/mercury/personal/status`, and their keys are named in `routes/mercury_personal.ts`, which is not on `main`. They are never guessed. The never rows are fixed.
  - **"Where it lands"** reads the viewer's role from `useAuth()`. A founder gets "Only the venture you import into", and a partner "Only your own invoices, payouts and settlements". Any other role reads "Not recorded". `writesProjectData` does not list `mercury`, so there are no company ticks.
  - **Now fed by** is drawn for a founder only.
- **The rest of the sheet:**
  - **Needs attention** shows decision 9's attention words and `MEMBER_REPLACE`. It never says "sync" and never prints `last_error`.
  - **The disconnect note** is `MEMBER_DISCONNECT_NOTE`.
- **The key view:**
  - There is no Advanced toggle for `mercury`, so there is no webhook or settings field.
  - The connect body is exactly `{ provider_key, display_name, api_key, config: { confirm_read_only: true } }`. A stored config is never sent from a field the member cannot see.
  - A refusal stays on the key form, with only the Worker's sentence and the token cleared. It no longer goes to the generic "refused access" view.
- **Decision 9, in `connectorsModel.js`, for the personal row only:**
  - `doesLabel` is "Reads on request", `lastSyncLabel` is "Read on request", and `disconnectNote` is the member's note.
  - `attentionReason` uses `personalAttention`.
  - `toolRow`'s failing row offers Reconnect, never Try again. `toolBanner` uses `personalToolBanner`.
  - `yoursFeedsLabel` falls back to "Your own payments".
  - `AccountConnectors.jsx` draws "You" under Companies.
- **Tests:**
  - New: `frontend/test/mercury_personal_sheet_d715.test.mjs`.
  - `connector_sheet_mercury_d713.test.mjs` drops its `ui.click('Advanced')` and its `connector-config` line, because the toggle is gone. It now asserts that neither the toggle nor either field is drawn.
- **Waited on #1778's PR B (done in PR 3b):** the use words, keyed as `routes/mercury_personal.ts` names them, and `status()` in `frontend/src/lib/api/mercuryPersonal.js`.

### PR 3b: the uses group, read from the status route

#1778's PR B (#1843) mounted `GET /api/mercury/personal/status`. It returns `connected`, `connection` and `uses`: one row for each key `routes/mercury_personal.ts:12-16` names (`venture_revenue`, `practice_income`, `partner_deals`), each with `available` and a `reason` (`purpose_not_allowed` or `hq_only`).

- **`frontend/src/lib/api/mercuryPersonal.js`** (new) exports `mercuryPersonalApi.status()`, with its line in `api.js`. #1778's PR C adds the match and import calls to the same file (decision 11).
- **`mercuryModel.js`:**
  - `USE_WORDS` holds decision 8's three sentences, keyed exactly as the Worker's `PersonalUse` type names them. A test reads that type from `services/mercuryPersonal.ts` and compares the keys.
  - `usesRows(status)` keeps each use whose `available` is `true` and that the model has words for, in the route's order. With none left, it returns a reason (`USE_REASONS`): "matched on HQ only" when a held use is withheld off HQ, else that the profile lists none.
- **`MercuryUsesGroups`** (`MercurySheet.jsx`) makes one status read when it mounts.
  - It draws a row per use.
  - With none left it reads "Not recorded" with its reason.
  - A failed read reads "Unreadable" with Retry, never "none", and "What it never does" still draws.
  - `USES_NOT_READ` is gone.
- **Doors:** not yet. The screens where each use happens (the revenue import, the invoice match, payouts and settlements) come with #1778's PR C, which is not on `main`, so the use rows link nothing. The canvas PR adds the doors.

### Canvas PR (#1780, closes it): the hub's group, the badge, the search, the doors

Built from S1's brief on #1779 (2026-10-18 20:48Z, parts A to C), because no "Fund Administration · Admin" export is under `design/` (S1, 2026-10-19). Every part is one the Connectors page already draws, and no new layout is invented. The owner reviews it on the PR preview; an export that lands first wins on layout and copy.

- **The "Fund administration" group** (`FundAdminSection`, `AccountConnectors.jsx`) holds one Mercury card (`data-testid="fund-admin-mercury"`), on Yours, on Discover and on a phone, beside Channels. It is drawn only when the catalogue holds the entity row, which the Worker serves to an admin on HQ alone. The card opens Mercury's page (D753 F5, #1991), whose mount is the one audited read. The group reads nothing.
- **The badge.** On Discover, the entity card is badged "Entity connections" (`FUND_ADMIN_GROUP.badge`). It comes from the entity row the catalogue serves, so drawing it reads nothing.
- **The search.** On Yours, `anyMatch` counts the entity row, because the group draws it on both tabs. A search for "mercury" never says "No connector called".
- **The doors** (`USE_DOORS`, `mercuryModel.js`). Each use row links the screen where it happens, on #1778's screens (#1848):

  | Use | Door |
  | --- | --- |
  | `venture_revenue` | the revenue ledger's Import from Mercury (`/spinout-lab/revenue`) |
  | `practice_income` | the invoice match on the partner's Needs board (`/partner/needs`) |
  | `partner_deals` | payouts and settlements in Earnings (`/partner/earnings`) |
  | `capital_attestation` | its Proof of funds door, unchanged |

  `raise_receipts` and `venture_spend` have no door yet: their panels are on their own pages, and this sheet does not link them.
- **The sheets.** The entity sheet and the member's sheet already draw every row and sentence the brief names. Mercury's page (#1991) mounts the entity body, and the member's groups are one set of components for the page and Build's lightbox.
