### Tables

`research_source_record_links`: one row per (source key, provider record id), the decision standing now — kind,
decision, ground, target type and id (plus the target's source key for a staged target), reason code, a private note
of at most 280 characters, who and when, a `revision` counted per change, and the promotion mark (`promoted_uid`,
`promoted_at`) that only `markPromoted` sets. `research_source_link_history`: one row per decision or promotion mark,
written in the same `DB.batch`, holding ids, codes, the actor and the time and no note; `BEFORE UPDATE` and
`BEFORE DELETE` triggers abort, as `612_closings.sql`'s events. Because of the triggers the release-window
classifier calls the migration manual; its forward fix
(`sql/forward-fixes/202611271037_7746_research_source_record_links.fix.sql`, D8532) re-creates the two triggers, and a
Worker rollback needs nothing else since the previous Worker names neither table. Kinds, decisions, grounds, target types and reason codes
are exported lists checked in the service, not CHECKs, so the Companies plan adds a kind or target without a rebuild.
No organisation column. A staged record with no link row is unresolved.

### Rules

- **Kinds:** manager, vehicle, accelerator, resource, company, funding_round, individual (`KINDS`). `KIND_DECISIONS`:
  the first four take any decision; a company, a funding round and an individual only `retain_private` or `reject`.
- **Link:** to a served catalogue uid (`SERVED_FUNDS`, so a row of a 'not allowed' list is refused as
  `target_not_served`), or to another staged record of the same kind that carries `create`. No self-link, no chain: a
  record others link to must stay a `create` of their kind. A retired uid is refused as `target_uid_retired` naming the
  uid it moved to. A promoted record's decision stands (`record_promoted`).
- **Grounds:** `name_key`, `manager_fund_number`, `website_host`, `retired_uid` must be borne out by the record's
  candidates for that target; `operator_verified` is a person's check and needs a reason code.
- **Candidates**, never applied: served rows by D7326's rule (name key; manager plus recorded fund number, optionally
  with "fund" between; bare host), a retired uid in `research_fund_directory_uid_moves`, and other staged records in
  any source with the same name key or host. Only the cells of the columns whose role is `name` or `website` are read
  (SQL `json_each` over the stored body), never prose. Served rows and moves are read once per request.
- **Shared website:** a host used by more than one staged record or more than one served row, or on/under a hosting or
  social platform in `PLATFORM_HOSTS`. Marked on the record and on the candidate. It is never the only ground for a
  link (`shared_website_ground`), and a list naming such a record, as an entry or a staged target, is refused whole.
- **Outcome, derived, never stored:** created = `create` with a promotion mark; linked = `link` whose target resolves
  to a served catalogue row (directly, or through a promoted `create`); retained privately; rejected; unresolved =
  everything else, split into `no_decision` and `awaiting_promotion`.

### Writes

One decision or a list of at most 500. A list is previewed (writes nothing, answers a digest over the list as checked
and each named record's revision and current version id) and applied naming that digest: refused as `preview_stale` if
a named record changed, refused whole on an unknown or duplicate key, a kind or decision not allowed, a shared-website
record, or a list over the bound. Entries already standing are not written: the same list twice writes nothing,
history included. Each write is one batch — history rows from one bound JSON value, the link rows upserted from that
batch's history rows, one audit row with the batch id and counts — and the history insert carries a fence on the
whole state the request read (the newest history id and the store's record count and newest id), so a decision or a
record landing in between writes nothing (`state_changed`).

### Routes (all on `/api/research-source-imports`, gate `researchImportGate` imported from #7745)

| Route | Gate | Does |
|---|---|---|
| `GET /mappings` | `requireSuperAdmin` | Staged records, 100 a page; filters `source`, `kind`, `decision`, `outcome`, `flag`, `offset` (codes and a source key only; no search). Rows: ids, kind, decision, outcome, flag codes, candidate count, a label from the name-role column. |
| `GET /mappings/report` | `requireSuperAdmin` | Summary (counts only, the one part that may be quoted): per source and kind the five outcomes and the two unresolved sub-counts, summing to the staged total; per source the staged records, stored versions, columns and cells against the newest manifest naming it (the store's `countRecord`, `rulesFor` and the run's own cell counts). Then per-record lines, 1,000 a page. Worded as records, never funds. |
| `POST /mappings/record` | `requireSuperAdmin` | One record in full: stored cells, versions, supplied flags, decision with note, candidates, history. Writes one audit row `{record_id}`. |
| `POST /mappings/decide` | write bar | One decision. |
| `POST /mappings/bulk/preview` | `requireSuperAdmin` | Checks a list, writes nothing, answers the digest. |
| `POST /mappings/bulk/apply` | write bar | Applies a previewed list in one batch. |

Every route refuses a support session with 403 `support_session_refused`. Ids, notes and lists travel in bodies,
never in a path or a query. No refusal, log line or audit row carries a field value or a note.
