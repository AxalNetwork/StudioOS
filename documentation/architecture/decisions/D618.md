## D618 — A journal edit after the outcome is recorded, and nothing is locked

**When a decision-journal entry already has an outcome, a later change to a graded field stamps `edited_after_outcome_at`. The entry stays editable.** Issue #1315. Migration 415.

**What counts.** The stamp is set on `PUT /api/journal/:uid` only when `outcome_recorded_at` is already set and one of these differs from the stored value: thesis, key risks, expected outcome, decision, conviction, expected multiple, expected timeline. A change to tags alone does not count. A value sent unchanged does not count. An edit before the outcome leaves the column NULL.

**What it does not do.** It does not lock the thesis, and it does not keep the previous text. The column is the time of the latest graded edit after the outcome. A later tags-only save leaves that time where it is. Nothing is backfilled.

**Reads.** `GET /api/journal/:uid` and the list return `edited_after_outcome_at`, null when there has been no such edit. The mark on the page is not this change. Its design is requested on #1165 (area 8, item 6).
