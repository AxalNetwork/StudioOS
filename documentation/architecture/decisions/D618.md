## D618 — Decision journal: record when a thesis is edited after its outcome

**Issue:** #1315 · S16, found by #1165's audit (area 8, the watchlist journal). **Migration 415.**

### What was true on `main`

The decision journal permitted an investment thesis, conviction, or expected outcome to be edited via `PUT /api/journal/:uid` even after the final outcome was formally recorded via `POST /api/journal/:uid/outcome`. Only `updated_at` was bumped, leaving no audit record that an entry was rewritten post-hoc.

### What was decided

1. **Schema (Migration 415):**
   - Adds column `edited_after_outcome_at TEXT DEFAULT NULL` to `decision_journal_entries`.
   - Default is `NULL`. An entry edited after its outcome before migration 415 reads `NULL`, meaning "not recorded", not "never edited".

2. **What counts as an edit:**
   - When an entry already has `outcome_recorded_at` set, modifying any of the seven core thesis/decision fields stamps `edited_after_outcome_at` with the current UTC timestamp:
     - `thesis`
     - `key_risks`
     - `expected_outcome`
     - `decision`
     - `conviction`
     - `expected_multiple`
     - `expected_timeline_months`
   - Modifying `tags` alone does not stamp `edited_after_outcome_at`.
   - Submitting unchanged values does not stamp `edited_after_outcome_at`.
   - Edits made prior to outcome recording leave `edited_after_outcome_at` as `NULL`.

3. **No locking:**
   - Entries remain editable rather than hard-locked. This preserves operational flexibility while recording when the latest post-outcome edit happened for the future "Edited after the outcome" UI mark requested in #1165.

4. **API exposure:**
   - Returned by `GET /api/journal/:uid` and in each item of `GET /api/journal`.

### Verified

- `cloudflare-worker/test/journal_edited_after_outcome_d618.test.ts` asserts:
  - Edits before outcome leave `edited_after_outcome_at` as `null`.
  - Edits to core fields after outcome stamp `edited_after_outcome_at`.
  - Tags-only edits and unchanged values do not stamp `edited_after_outcome_at`.
  - Both single and list read endpoints return `edited_after_outcome_at`.
- All migration and declaration guards pass cleanly: `check-sql-migrations.mjs`, `check-migration-declarations.mjs`, `check-schema-pair-drift.mjs`.
- `node scripts/check-decision-ids.mjs` passes.
