## D4625 — Record a session opens the interview it was asked for, and never falls into the new-person flow by accident (#4625)

- **Status:** Built for #4625, 2026-11-07. Frontend only.
- **Builds on:**
  - D685 (the Record a session lightbox);
  - `GET /api/progress/discovery/:projectId`, which answers `{ project_id, interviews }`.
- **No migration, no Worker change.** The Worker's ownership checks are untouched.

### What was decided

1. **The envelope is decoded once.**
   - `RecordMount` treated the answer as a bare array, so a real answer never matched and the lightbox opened as if no interview was requested.
   - `interviewListOf` (`lib/discoveryEvidence.js`) accepts the envelope or a bare list and returns `null` for anything else. `interviewsOf` reuses it.
2. **A requested interview has four outcomes, never silently another.**
   - none requested: the intentional new-person flow, with no read;
   - found: the lightbox opens on it, Who is pre-filled, and Start attaches the session to that interview;
   - not in this venture's list (missing, or outside the caller's scope): a fixed message with Close and an explicit "Record someone new";
   - unreadable (the read failed, or the answer was not a list): a fixed message with Try again. There is no way into the new-person flow from here.
3. **No stale answer lands.** A result is kept with the venture and interview it was read for, and a read that outlives its effect is dropped.
4. **Test seams.** `RecordMount` takes an optional `read` and `lightboxProps` so a mounted test can use the real envelope and see the interview id Start submits.
