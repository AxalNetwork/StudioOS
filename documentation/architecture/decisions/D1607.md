### 1. The sync (`services/posthog/raise.ts`)

`POST /api/cycles/raise/posthog/sync` lands every metric tracked in Fundraising readiness, Investor narrative or Pitch deck as today's fact. It is pressed by the member whose PostHog serves the venture.

`posthogFigure(env, project, role)` is the latest read value among the metrics the founder said measure that role. It is never guessed from an insight's name, and it is null when no metric has a value.

### 2. Traction proof (`raiseCycle.ts`, `computeReadiness`)

- **Read lines.** Two lines join the traction reads, each only when PostHog gave a value:
  - "Active users · From PostHog" (1,240 · Weekly active users · as of 2026-10-30);
  - "Retention · From PostHog" (22% · Week-4 retention · as of …).
- **Marked Shown.** Each line's mark is a new value, `Shown`, with the note "Shown beside the score; it does not change it."
- **The score.** `traction` is computed before the lines and never reads them, so the score and its evidence are unchanged. A test holds this.

### 3. The consistency check

- **The figure.** `active_users` joins `FIGURES` ("Active users", a count).
  - It is read only beside its words: "1,240 weekly active users", or "MAU of 3,000". A bare "1,240 users" is not read.
  - `narrative/claims.ts` gives it no pinned record kind (`[]`), as `raise` has none.
- **Compared.** `checkInputs` reads `metrics.active_users` from `posthogFigure`, with the source "From PostHog · <insight> · as of <date>". A stated count more than 2% away is a mismatch that names both sources. That covers the narrative check, the version list and the mismatch sentences.
- **Never scored.** Readiness' narrative score compares only `NARRATIVE_CHECK_FIGURES`, which is unchanged at four, so a PostHog mismatch never lowers readiness (decision E).
