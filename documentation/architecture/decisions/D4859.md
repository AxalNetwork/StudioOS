## D4859 — HQ · Platform's summary reads its panels together, each with its own deadline (#4859)

- **Status:** Built, 2026-11-07 (Worker only). No migration, no new route, no response change.
- **Builds on:** D202 (the Platform consoles), the panel-isolated blocks of `GET /api/admin/platform/summary` (`{ available: false, reason }`, `countOf`). Related: #4858 (the read contract), #4854 (health and detected incidents), which build on these readers.

### What changed

- `GET /api/admin/platform/summary` read eleven panels one after another inside the route: integrations, scheduled jobs, the dead-letter backlog, incidents, Telegram, X, switches, integration keys, GitHub sync, the payments catalogue and promo codes. Each already failed on its own, so nothing but the code ordered them.
- Each panel is now a reader in `cloudflare-worker/src/services/platformSummary.ts`. `readPlatformSummary` runs the eleven with one `Promise.all`; the list is fixed, so the concurrency is bounded by construction. Readers that made two or three independent reads (integration keys, GitHub sync, payments) make them together too.
- Every reader goes through `settle(read, fallback, deadlineMs)`. A reader that throws becomes its own block's "could not be read" state; one that does not answer within `READER_DEADLINE_MS` (8 s) becomes "did not answer in time", which the reason says is not the same as none. The fallback keeps the block's shape: `github_sync` and `payments_catalog` keep their composite keys, the payments publishable key reads `configured: null`, and Telegram and X keep `token_configured` and `client_configured`.
- The route is now `requireSuperAdmin`, then the summary plus the derived-unavailable blocks. It went from 950 to 534 lines; the constants it exported (`INCIDENT_WINDOW_DAYS`, `PROMO_LIST_LIMIT`, `STRIPE_WEBHOOK_PATH`, `WEBHOOK_WINDOW_HOURS`) are re-exported from the service, so no importer changes.

### Kept

- The response is the same, key for key. No key material, chat id, Stripe or GitHub call, and no schema is created by reading. An unreadable count is never sent as zero.

### Measured

With a D1 double that answers every query after 15 ms, the old serial order took **232 ms** and the concurrent readers **48 ms** (`platform_summary_readers_4859.test.ts`, which prints both). With every reader held at 80 ms, the eleven finish in under 240 ms, so they are not serial.

### Tests

`cloudflare-worker/test/platform_summary_readers_4859.test.ts`: each reader directly, and against a broken database; the response shape; a throwing reader leaves every other block unchanged; a hanging reader is cut at its deadline in its own shape; the composite fallbacks keep their keys; the concurrency bound; `settle` itself. The source-reading tests that looked for the incident window, the channel states and the Telegram and X imports in the route now read the service.
