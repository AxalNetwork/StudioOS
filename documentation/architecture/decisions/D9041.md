## D9041 — /api/users: the admin user-create route is retired, and the list and read gates are pinned (#9041)

- **Status:** built by S03 on #9041, 2026-11-27.
- **Chosen by:** the issue's scope, filed from the S1 coordinator audit of 2026-11-27 under #4570.

### The problem

`cloudflare-worker/src/routes/users.ts` had three routes and no test of its own.

- `POST /api/users` let an admin create an account. It wrote no `logAdminAction` or `activity_logs` record, which breaks the AGENTS.md rule for a write made on someone else's behalf. Its client method `createUser` had no caller in `frontend/src`, `scripts` or any test.
- `GET /api/users/:id` let any admin read any user's row, another admin's and the Super Admin's included, with the linked `founders` and `partners` rows read as `SELECT *`. AGENTS.md: "Another admin's data belongs to the Super Admin." The auth ledger listed it as `unreviewed`.
- `GET /api/users`, the admin list behind the deal transfers tab, the event invite modal and the closing zone, was covered only by the generic authorization sweep.

### What was decided

- **The create route is retired, not audited.** Nothing calls it, and accounts are made by sign-up and invitations, which have their own audit. `POST /api/users` now answers 404, and `createUser` is removed from `frontend/src/lib/api.js` in the same change, as the API drift check requires. A removal from a frozen hub needs no edit to `scripts/hub-freeze.json`.
- **One record, three readers.**
  - A member reads their own record. Any other record gets 403.
  - An admin reads their own record and any non-admin's.
  - Another admin's record, the Super Admin's included (both carry `role = 'admin'`), gets 403 `super_admin_required` unless the caller is the Super Admin (`isSuperAdmin`, which is never true on a branch Worker).
  - The role check runs after the row is read, so an admin probing an unused id still gets 404.
- **Named columns.** The linked founder row returns `id, uid, name, email, company, linkedin_url, domain_expertise, experience_years, bio, created_at`, and the partner row returns `id, uid, name, company, email, specialization, status, created_at`. The CRM contact id, the referral code and the directory decision fields no longer leave the Worker on this read.
- **Refusal bodies follow D278.** The route's 400, 403 and 404 answers carry a code in `error` and a sentence in `detail`.
- **The list is unchanged.** It stays admin only, and `?role=` filters on the stored role.
- The ledger entry `GET /api/users/:id` in `scripts/baselines/auth-inventory/%2Fapi%2Fusers.json` is now `verified` by the test below.

### Not changed

The Replit-dev FastAPI keeps its own users routes (CLAUDE.md fact 3). They are never deployed.
