## D5915 — Consequential deal actions in Investor preview (#5915)

The owner chose B on #5915, implementing the policy left open in D4815.
A Super Admin previewing Investor can browse deals and use notes under their
existing access. Passing, changing the flow, answering an invitation, committing
or withdrawing, voting, starting deal signing, and changing closing or transfer
records require returning to HQ.

The shell sends `X-Axal-Preview-Shell: investor` on API mutations from the
active tab's Investor preview. The Worker verifies the authenticated Super
Admin, excludes support sessions, and refuses the guarded actions before they
write with HTTP 403 and `investor_preview_read_only`. The same response opens
the Return to HQ dialog, which uses the shell's existing exit action.
Returning to HQ does not submit the blocked action again.

The header narrows permissions for a request. It confers no authorization and
does not persist preview on the server. A separate HQ request keeps its existing
authorization. Reads, note-only flow changes, comparison-note drafts and saves
keep their existing checks. Recipient signing links already sent by email
continue to use their existing token-based authorization.
