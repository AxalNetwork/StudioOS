## D6326 — Eight development skills for building sessions (#6326)

- **Status:** added 2026-11-14 by S01, stacked on D6312's three coordinator skills.
- **Where:** `.claude/skills/` (`red-ci-triage/`, `verify-before-push/`, `task-lifecycle/`, `add-worker-endpoint/`, `build-screen-to-canvas/`, `mutation-check/`, `land-pr/`, `schema-change/`), one helper per skill under `scripts/`, and each helper's pure half with its test under `scripts/lib/` (run by `npm run test:retention`).

### Why these eight

They come from a scan of recent PRs, CI failure digests and STATUS comments on 2026-11-14, not from a list of ideas:

- **`red-ci-triage`:** twelve recent digests named only a shard such as `suite (frontend-2-of-2)`, never the failing test. The helper reads the failed jobs' logs and prints each failing test with its local reproduce command, the digest's verdict, and the open `[alert]` issues with what each forbids (D5398, D5604, D5619). It compares with main as the PR's run saw it, so a repair that has since landed is never read as the PR's own failure.
- **`verify-before-push`:** STATUS comments on #5815, #6078 and #5881 report the full local run outliving the session. The helper plans the checks for the files changed and runs them one part at a time.
- **`task-lifecycle`:** six STATUS posts in one day repeated the claim fallback, and the reaper flagged fifteen expired claims. The skill is AGENTS.md's task protocol as steps; the helper reads an issue's claim, labels and last STATUS and says what the next step is.
- **`add-worker-endpoint`:** CI failures on #5770, #5802 and #5792 were house rules for routes (self-mounting routers, the hub freeze, refusal sentences, date comparisons in gates).
- **`build-screen-to-canvas`:** the build half of AGENTS.md § Missing UI, after `land-canvas`.
- **`mutation-check`:** AGENTS.md § House rules requires it; every STATUS reported it in a different shape. The helper applies a list of mutations, always restores the files, and prints one report format.
- **`land-pr`:** AGENTS.md task-protocol step 5, as a checklist that stops at the first unmet condition.
- **`schema-change`:** D4106 and D5398's naming rule, the immutability gate and the declaration checks, in order.

### Rules

- A skill is a way to follow `AGENTS.md` and `CLAUDE.md`; those files win when they disagree.
- No helper script writes to GitHub or the repository's history: they read with GET requests and print. `mutation-check` edits files in the working tree and restores every one, also on error.
- `land-pr` never queues a PR itself. It reports whether step 5's conditions hold for the exact head SHA; when one does not, the owner lands.
- Every command, flag, path and check a skill names was checked against main by a second agent before this landed; 51 problems were found that way and fixed.

### Limits

- The skills were verified by reading and by dry runs against live PRs and issues, not by a building session using each one end to end. The first sessions to use them should report what does not match.
- `scripts/claim.mjs reap` stops at 100 pages of refs; noted during review, not changed here.
