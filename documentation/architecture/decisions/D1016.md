## D1016 — Cap table part 1: "Model a round" and the Capital tabs keep the venture, a delete opens a dialog, a missing amount reads "Not recorded", and the CSV goes through the shared client (#2853)

- **Status:** built by S19's task (#2853, part 1 of #2432, D1015 §6), 2026-10-24.
- **Migration:** none.
- **Basis:** stacked on D1015 (#2852), whose Scenarios tab "Model a round" now opens.
- **Why:** the old simulator (`/raise/capital/cap-table`, `CapTablePage.jsx`) stays until part 14, so its faults still reach founders. S21's map (`documentation/audits/CAP_TABLE_MAP_2026-10-24.md` §1) lists five that are still open. Each is fixed here.

### 1. What changed

| Fault | Before | Now |
|---|---|---|
| "Model a round" on a holder record (`services/records/raise.ts`) | linked `/raise/cap-table/variants` with no venture, so the page said "Open variants from a startup's cap table" | links `/raise/cap-table/scenarios?project_id=<id>`, D1015's tab that lists the variants, on this venture |
| The Capital tabs (`CapitalWorkspacePage.jsx`) | navigated to the bare path, so the venture was dropped | each tab keeps `?project=` and `?project_id=`, and nothing else (`tabHref`) |
| Deleting a scenario or a variant (`CapTablePage.jsx`) | a browser `confirm()` | an in-page dialog (`Lightbox`) that says what is deleted; nothing is deleted until it is confirmed; a failure is said in the dialog, which stays open |
| A missing amount (`fmtMoney`) | printed "0" | reads "Not recorded". `fmtMoney` now carries the `$`, so the page never prints "$Not recorded"; a real zero is still "$0" |
| The CSV download | a hand-built `fetch` with the bearer only (no cookie, no company header) and an `alert` on failure | `api.downloadCapTableCsv`, sent with `request()`'s headers and the cookie; a refusal is said in the page |

### 2. What the dialog says, and why the two differ

The issue asked for a dialog that says what is deleted "and that the main cap table does not change". That is true of a variant, and the variant dialog says it.

It is not true of a scenario that is not a variant. That row is a saved cap table itself: `DELETE /api/captable/scenarios/:uid` removes the row, and the project has no other copy. So that dialog says the cap table is deleted for everyone who can open it, and that its variants stay. Saying "the main cap table does not change" there would be false.
