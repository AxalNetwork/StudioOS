### 1. The registry read

`GET /api/admin/licence-registry` lists one page of `licences`, every family. It is Super Admin only, as the
licence ledger, its agreements and the program grants already are.

- **Filters:** `family` is `all`, `operator`, `founder`, `investor`, `operating_partner` or `advisor` (the issue's
  six). `holder` is `user:<id>` or `entity:<id>`. There are also `status` and `q` (ref, entity, brand, account name
  or email). The page uses a keyset cursor on `licence_ref`, which is unique. `total` counts every match, and
  `counts` gives each family over the whole registry. An unknown value is a 400 that names the filter.
- **Each row:**
  - ref, holder (type, id, name), type and its label, status, revision, and starts/ends;
  - `renewal`: `renews_on`, else `ends_on`, with which one it is;
  - `agreement`: the primary agreement's legal state and canonical id;
  - `packages`: package agreements that are not voided or superseded;
  - `programs`;
  - `attention`.
- **Territory is an operator row's alone.** The `territory` block (countries, kind, brand, legal entity) is on
  operator rows. A user row has no `territory` key at all, and the test checks that no franchise field name occurs
  anywhere in a user row.
- **Attention codes:** `suspended`; `renewal_due` (within 30 days) or `renewal_overdue`, for a licence in force;
  `agreement_not_executed`, for a licence in force whose primary agreement is not executed; `agreement_unreadable`.

### 2. The detail read, shaped by the family

`GET /api/admin/licence-registry/:uid` answers `layout: 'operator'` or `layout: 'user'`.

- **User:**
  - `overview`: holder, type, status, dates, renewal, attention, and the account (id, name, email, role, active).
    `entitlements` is Not recorded, naming #5059.
  - `programs`: Not recorded, naming #5059. Eligible, granted and in-force programs, their source licence and
    their blockers are #5059's to derive. This read does not guess them from a role.
  - `agreement`: the primary, every version (amendments and history), and the related package and program
    agreements on this licence.
  - `billing`: Not recorded, because no commercial term is stored on a user licence.
  - `history`: Not recorded, naming #5058. The lifecycle history is #5058's `user_licence_events` (PR #5390), which
    main does not have yet, and `check-sqlite-tables` refuses a query of a table nothing creates. Reading it is a
    one-query follow-up once #5058 merges.
- **Operator:** the overview, the territory block, packages, program grants, the master licence agreement's
  versions and the related agreements. `operator_detail` points at the existing territory licence read
  (`/api/admin/licences/:uid`), so terms, fees, seats, events and blockers are not read twice. A master franchise
  licence has no territory row, so its agreement and grants are Not recorded with that reason.

### 3. Where a user licence agreement lives: its envelope

No store held a Founder, Investor, Operating Partner or Advisor licence agreement.

- **What was done.** Contracts already sends any library template through e-sign, and the envelope records its
  template (`document_type`) and its account (`user_id`). So an envelope of one of the four templates **is** that
  user licence agreement:
  - its holder is the envelope's account;
  - its licence is that account's user licence of the template's type in `licences`;
  - its canonical id is the envelope uuid.
- **Why not a column or a table.** Adding a kind to `licence_program_agreements` would mean rebuilding a table
  that has freeze and revision triggers, an events table and executed rows. A new table would hold a second copy
  of what the envelope already is.
- **Legal state:**
  - a completed envelope is executed, unless a later completed one of the same template for the same account
    replaced it, which makes it superseded (history);
  - void or rejected is voided;
  - otherwise it is awaiting signature.

  An amendment out for signature does not displace the executed version as the primary agreement.
- **When the licence cannot be named,** `licence_uid` is null and `licence_reason` says why: the envelope names no
  account, the account holds no licence of that type, or it holds more than one. #5058's unique index makes the
  last case impossible once it lands.

### 4. Contracts: each agreement once, with its licence

`loadLicenceAgreementContexts` (D5050) adds the user licence agreements. Like every other version with an
envelope, each one rides on its envelope's `esign` row, so no envelope is listed twice. Every context now carries
`licence_family`, `licence_type`, `licence_type_label`, `holder` and `licence_reason`:

- from `licences` for package, program and master agreements (one bound `json_each` lookup);
- from the envelope's account for user licence agreements.

**New agreement types:** `founder_licence`, `investor_licence`, `operating_partner_licence` and
`advisor_licence`.

**New filters on `GET /api/admin/contracts`:**

- `licence_family` (`operator` or `user`);
- `licence_type` (the seven types);
- `holder` (`user:<id>` or `entity:<id>`);
- `territory` (an ISO-2 country).

The existing `agreement_status`, `program` and `package` filters still apply. An unknown value is a 400 that
names the field.

**The same id from both sides.** The registry row, the registry detail and the Contracts row name the same
`agreement_uid`:

- for a master licence agreement, the `licence_contracts` uid;
- for a user licence agreement, the envelope uuid.

### 5. Templates

`GET /api/admin/licence-registry/templates` names the four slugs and says whether HQ has authored each in the
Contracts library (`legal_templates`): `founder_licence_agreement`, `investor_licence_agreement`,
`operating_partner_licence_agreement` and `advisor_licence_agreement`.

- **Contracts owns the text.** No body is seeded. A slug HQ has not authored reads "not authored", and nothing is
  invented in its place.

### 6. Honesty

- A store this database lacks is Not recorded, with a reason. A database without `licences` answers
  `available: false`, with `items: null` and `total: null`, never an empty list.
- A store that fails to read is Unreadable for that section, and attention says so. It never reads as "none on
  file".
- Every statement is literal SQL with bound values. Lists go through `json_each(?)`, and no value is spliced into
  query text.
