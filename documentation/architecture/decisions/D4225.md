### 1. Eighty skills, ten or more in each area

There are 68 new skills in `cloudflare-worker/src/services/agents/skills/`, so the library holds 80. Each uses #3951's SKILL.md format unchanged, with one golden case in `cases/`. A skill's **area** and **level** come from its first taxonomy tag: the tag's `category_slug` in migration 090, and the tag's level. That is the rule D4160's library read already uses.

The issue asks for at least six per area. Ten each means SK0 has no thin area.

The rules of D1612 hold for every new skill:
- **Reads only.** Every tool is a `<source>.read` the catalogue grants.
- **A step proposes and never acts.** No step begins with Send, Publish, Post, Approve, Pay, Sign, File or Share.
- **A missing figure is "Not recorded".** It is never estimated.
- **Made-up records.** Every case's records are invented, with no email address.

**No skill carries a value.** The frontmatter has exactly its seven keys, and values belong to agents (#4116).

### 2. Embedded, because the Worker reads no file

The Worker cannot list or read a folder at run time, and wrangler's Text module rule covers only the legal templates. So `scripts/build-skill-library.mjs` writes `services/agents/skillLibrary.generated.ts`, which holds every SKILL.md and case as data.

The files stay the source, and the module is never edited by hand. `agent_skill_library_d1612.test.ts` fails while the module is stale.

### 3. The seed creates drafts; H2 publishes

`POST /api/admin/ai-agents/skills/library/seed { reason }` is Super Admin only. It runs each library entry through **the store's own checks**: `checkDraft` (the roles, the 1–12 tags, read-only tools) and `checkCase` (the shape, no email). An entry that fails is reported as `refused` and is not written.

Each passing skill not yet in the store becomes an Axal draft. Its tags, roles and golden cases are written in one batch. **Nothing is inserted as published.** Each draft then goes through D4160 like any draft Axal writes by hand:
1. a second admin reviews the draft's hash;
2. the golden cases run per model against the 9-of-10 bar;
3. it is published.

**Running the seed twice duplicates nothing.**
- A skill already in the store is `present`. The match is on its slug, and the insert is `ON CONFLICT DO NOTHING`.
- A draft that lost a library case gets it back (`cases_added`), matched on the case name `<slug>: golden case`.
- A published or retired skill is never touched: changing it is a new draft through D4160.

A seed that created or added something writes one `ai_admin_audit` row (`skills.library_seed`, area `skills`) with the reason and the slugs. A seed that changed nothing writes none.

`GET /api/admin/ai-agents/skills/library` lists each library skill with:
- its name, area and level;
- its case count;
- its check result;
- its status in the store, if it is there.

That is the list SK1 shows under "From Axal" before the seed.
