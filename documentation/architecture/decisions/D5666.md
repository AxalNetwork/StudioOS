## D5666 — Observational session attribution and routing (#5666)

The adapter consumes metadata v1 and emits presentation policy v1 for #5665.
It never reviews code, classifies a failure, repairs, reruns, dispatches, merges,
marks ready, bypasses checks, or mutates GitHub issues/claims. Its only writes
are atomic local metadata decisions/checkpoints. The caller serializes by PR;
SQLite commits the immutable decision and latest routing state together, so a
restart/replay cannot lose the state after accepting the decision.

Ownership uses verified claim refs and the linked work issue's slot labels.
Case aliases normalize, but released/expired refs, missing or competing labels,
conflicting linked claims and missing evidence remain explicit. An expired ref
is still held under the slot protocol, never automatically released. A missing
claim falls back to the GitHub author/requested reviewer; ambiguous evidence
uses visibly marked S01 triage. Holder comparison uses a digest rather than
retaining free-form agent/session text in presentation state. Slack identities
are never inferred from display names, branch names or slot spelling. Mentions
require both trusted policy opt-in and an explicit reviewed mapping; defaults
produce none. Review requests also retain safe GitHub reviewer logins.

The existing D5619 CI digest supplies verdict/fingerprint/failure identity.
The adapter requires the trusted source/author, exact run/attempt/current head,
current required-check evidence and integration identity. Unknown/mixed causes
remain named. Two different failures in one shard follow the digest fingerprint,
not a new shard-name classifier. Forks with no trusted digest are unknown.
Advisory checks cannot become author action through naming or labels.

Required contexts are read from ruleset 25309597. The 12 November read-only
snapshot contained `test:drift (full suite)`, `worker (typecheck)`,
`frontend (build)`, `api ↔ worker drift`, `applied migrations unchanged`, and
`scan`, each integration 15368. Production policy hard-codes none of those
names or their count. Fixtures remove the old required context, keep the new
shadow context advisory, then promote it only in the supplied live ruleset.

One PR subject key survives draft/ready, reviews, changes requested, head changes,
checks, queue changes, merge and close-unmerged. Approval never proves merge or
deploy. Stale review commits, stale heads, old run IDs/attempts and earlier
observations are activity only. A successful shard cannot recover a CI action;
recovery requires a verified complete current required-check snapshot. A newer
green watermark prevents historical failures from reopening recovery.

Inherited/common infrastructure failures point to the existing verified health
issue and make no new author action/root/mention. The D5663 producer owns that
incident and recovery. Ten affected PRs retain correlation to one episode.
Queue observations keep the exact group SHA and known membership. An unmapped
group invents neither PR nor owner. An advisory overlap is not a conflict;
conflict action requires verified merge-tree/GitHub-mergeable evidence matching
the current PR head and base. Existing queue/health action policy is untouched.

Validation covers full lifecycle and persistent root identity, ten inherited
PRs, same-shard fingerprints, mixed/unknown/fork evidence, missing/expired/
competing ownership, explicit mentions, live check-name cutover, stale heads/
attempts/reviews and atomic SQLite rollback/replay. Source/sender fixtures are
versioned and independent of unmerged #5639. Integration uses only fake Slack
transport and metadata. Build/drift/mutation results belong in STATUS. The owner closed the
publication pause in #5657; #5668's approved destination/access canary remains outstanding.
No live routing, deployment, delivery or canary is claimed.

A current authoritative requested-reviewer snapshot can create the review action
without inventing a review decision. Unchanged targets/head/owner do not repeat
that material request. Production callers must supply the verified digest
contract through the approved source boundary; arbitrary notification labels
are never evidence. Live source/policy/publisher wiring remains an explicit
rollout gate under #5668.

The v1 policy carries controlled next-step/cause fields and a validated GitHub
fallback login into presentation. These remain metadata, not a Slack identity or
an operational command; mentions still require a separate explicit mapping.
