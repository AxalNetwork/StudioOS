### 1. The narrative it binds

The build reads the venture's **latest saved narrative version**: the highest `narrative_version_meta.version` for the project.

- **Its words** are the `raise.narrative.<section>` and `raise.positioning.<kind>` slots of that version, read through the narrative store (`readNarrative`, #3772's lists).
- **The binding.** The version it saves records the number in `pitch_decks.narrative_version`. Two triggers bind `(project_id, narrative_version)` to a `narrative_version_meta` row of the same venture, so a deck built from narrative vN names `narrative_version_meta:vN`. A deck not built from the narrative keeps null.
- **No narrative saved** is `version: null` with its reason ("No narrative version is saved yet…"), never v0. The build then writes from the records and the card titles.

### 2. No figure reaches a model

Each sentence of the narrative that names a figure is dropped before anything is planned (`figureFree`, on `numberIn`, which also catches number words). The outline reports how many sentences were dropped per slot.

What is left reaches the text areas only as the cards' notes, which `planAreas` writes from. A figure on a card comes only from a records element, bound to its record, or from a chart built from records.

The route test reads every step input of the run and finds no "$" and no "1.5M" from the narrative.

### 3. The stage's cards, cut to the ones with proof

The stage is the one asked, else the audience's, else the venture's, else seed (`deckStage`, D1522). Its arc (`planFor`) orders the cards. `cutUnproven` keeps a card only when its records prove it.

A card left out says why: **"<Title> not evidenced"**. A pre-seed venture with no interviews gets "Problem not evidenced", both as the left-out card's line and as a warning. A deck as generated therefore never holds a required card with no evidence.

### 4. `grid_plan`

`grid_plan` is a **code job**. It runs no model and costs nothing. Its output schema is `GRID_PLAN_SCHEMA`: per card, `{ card, uid, title, structure, areas: [{ id, element }] }`, checked by the tests with D1511's validator.

- **The structure** is a fixed choice per catalogue card from the 17 structures. For example, Traction is `split_7_5` with a chart and words, and The round is `title_body` with `round_terms`.
- **A chart or a records element** (`team_grid`, `round_terms`, `use_of_funds`, `cap_table`) is planned only where the records can fill it. Otherwise the area writes words.
- **A retry.** An area the run's own gate refuses all the same is re-planned once as words. No area is left empty.

Each area's **model** is resolved per element when the run is planned (`elementModelFor`, D1503, with HQ's locks, D1549), through #3721's per-job table. This is the issue's "rail route through #3721's per-job plan and #3754's resolution": `grid_plan` itself has no model to route, so it has no row in `modelUseCases.ts`.

### 5. The theme and the template

`pickTheme` picks:

1. **Brand** first, when the venture has a brand kit.
2. Otherwise **by stage**:

| Stage | Theme |
| --- | --- |
| pre-seed | Sand |
| seed | Neutral light |
| Series A | Ocean |
| Series B+ | Neutral dark |

A climate, energy or agriculture **sector** takes Forest. Each pick carries its sentence, for example "Picked Ocean because it suits a Series A deck for Series A funds."

The template is `pickTemplate` over HQ's gallery (D1535), with its own "Picked … because …". Both are recorded on the built version's `theme_json` (`kind`, `reason`, `template_id`). The founder changes the theme in the editor like any other.

### 6. One build, one run, one hold

- **`POST /api/decks/narrative/outline`** runs nothing and holds nothing. It answers the cards, the grid plan, the cards left out, the picks, and the **quote** of every area as #3764's areas quote under class `deck_build`. Card uids are fixed (`nb-<card>`), so the outline's `quote_uid` holds for the build unless something changed.
- **`POST /api/decks/narrative/build`** needs an `Idempotency-Key`.
  1. It saves the planned v2 cards as a **new version that is not current**. The founder's deck stays as it was until they accept and save.
  2. It admits **one** `deck_build` run over every area through `admitDeckRun`, under one hold.
  3. It writes one proposal per area through `insertProposals`, which is shared with `deck_areas.ts`. Progress is #3753's run events; Accept and Discard are #3764's area routes on the built version.
- **The same key twice** is the same build: no second version, no second hold, one charge. A second press that races the first is 409 `build_in_flight`, and its version is removed.
- **Seeds.** The run's seeds are keyed by venture (`-project_id`), because the version does not exist yet when the outline is priced.

### 7. The zero-edit gate

`scripts/eval-elements.mjs --benchmark` is the gate #3770 measures. It now builds each sample venture's deck with this build's cut: the seed arc keeps only the cards with recorded proof.

It also counts a slot the venture has no row for as not recorded, as the live build does, since it reads every slot. Before this, the sparse venture drew metric placeholders for three slots its fixture never listed.

All three ventures now pass with 0 placeholders and 0 overflow (`DECK_BENCHMARK.md`, 2026-11-03). The sparse venture failed with 7 placeholders on 2026-11-01. Text areas cannot overflow: each is written to at most its area's capacity (`textCapacity`, `DENSITY_MAX`).
