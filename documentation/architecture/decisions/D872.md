## D872 — Upload a call recording into Record a Session

- **Status:** decided by S1 for the owner, 2026-10-22 (#2519; part of #2516). Built by S08.
- **Basis:** `origin/main` at `d1c9bbedee`. Worker paths are relative to `cloudflare-worker/`.
- **Migration:** none.

Any call can reach Validate, whatever tool ran it: a Zoom local recording, a Meet recording from Drive, Teams, or a phone recorder. The founder picks the file and attests that everyone recorded agreed. Axal transcribes the file with Workers AI into a session, through the recorder's own routes and pipeline. This task ships the contract and the client library; the page waits on M9's canvas.

### 1. The client library: `frontend/src/lib/recordingUpload.js`

1. **The attestation comes first.** `uploadRecording` refuses before the file is read and before any request is sent unless it has `{ agreed: true, method }`. The method is `verbal`, `written` or `pre_agreed` ("out loud, in writing, or beforehand").
2. **The file is decoded on the founder's device.**
   - An `OfflineAudioContext` at 16 kHz decodes and resamples it; the channels are averaged to mono.
   - A file the browser cannot decode gets one plain message (`MESSAGES.undecodable`): export the call as MP3, M4A, MP4 or WAV, and try again.
   - The library refuses a file with no sound, and one longer than 3 hours.
3. **It cuts the recording into parts of 120 seconds.** Each part is a WAV: 16-bit PCM behind a canonical 44-byte header, 3,840,044 bytes, under the chunk route's 5 MB limit. A 45-minute call is 23 parts.
   - **Why WAV, not the recorder's WebM.** MediaRecorder re-encodes in real time, so a 45-minute call would take 45 minutes. PCM is written as fast as it is read.
   - The chunk route already accepted `audio/wav`.
4. **The upload is resumable.**
   - The session is opened with a `client_key` hashed from the file's name, size and last change, so the name never travels.
   - A second open with the same file answers the same session (the routes' replay).
   - The library reads which parts the Worker holds (`GET /sessions/:id`) and sends only the rest. A part sent twice is stored once (`putChunk` by `seq`).
   - Then it calls `/finish` with `auto: false`: transcribe only. Summarise and Structure stay the founder's press (D765).
5. **It uses the existing API.** It calls `interviewSessionsApi`'s `open`, `get`, `uploadChunk` and `finish`, so no new method was added to the API client.

### 2. The session: `submitted_via 'upload'`

- **Opening.** `POST /sessions` (a picked interview, or a new interviewee) and `POST /interviews/:id/sessions` take `{ source: 'upload', attestation, duration_ms }` on an audio channel (`in_person`, `video`, `phone`).
- **Checked before anything is written** (`planUpload`):
  - `attestation_required` (400), with the sentence;
  - `duration_required` (400);
  - `upload_too_long` (413);
  - `upload_needs_audio_channel` (400);
  - `invalid_source` (400).
- **The attestation is the session's recording consent.** That is `consent_status 'given'` with its method and time (`consent_method`, `consent_at`), as a member's word is on a forwarded recording (D754 way B).
  - `channel_consents` is not used: its `provider` CHECK admits only `whatsapp` and `telegram`, and this task has no migration.
  - The `interview_session_created` activity line records `source: 'upload'` and `attested: <method>`.
- **What the session is when it opens:**
  - `stopped` (`started_at` = `stopped_at` = now);
  - `active_ms` set to the declared length;
  - no live model;
  - never refused for a recording live elsewhere, since it records nothing live.
- **Its interview.**
  - The interview is marked held.
  - A picked interview may already be held: an upload is often of a call that happened.
  - The free tier's interview cap applies when a new interviewee is named, as for any setup.
- **The chunk route, for an upload session only.**
  - It takes only the uploader's format (`isUploadWav`: canonical header, 16 kHz, mono, 16-bit PCM). Anything else is `upload_format` (415).
  - The audio held, which is the bytes less one 44-byte header per part, may not pass 3 hours. Past that the route answers `upload_too_long` (413).
  - A repeated `seq` is a duplicate and is not counted again.
- **The sweeper leaves an interrupted upload alone.** It is `stopped`, not a never-started draft (`sessionSweeper.ts`), so it waits for its remaining parts or for the founder to delete it.

### 3. Limits and cost

- **3 hours per upload** (`MAX_UPLOAD_MS`). Measured on the router's own prices (`PRICE_USD_PER_AUDIO_MINUTE`):
  - 180 minutes on whisper-large-v3-turbo (the default, $0.00051293 a minute) is about $0.09;
  - on nova-3 ($0.00520003) it is about $0.94.
  - In the browser, three hours at 16 kHz is about 690 MB of decoded samples (32-bit floats). A phone may refuse sooner, with the undecodable message.
- **AI tokens.**
  - Each part is held and charged when it is transcribed, through `aiRouter` and the ledger, as every recorder chunk is.
  - The member's daily and monthly caps apply.
  - A refusal fails the run with a sentence and keeps every part. The founder's Retry (`/process`) resumes from the parts not yet transcribed, so no part is charged twice.
- **Charged on the true length.**
  - Every chunk was held and charged on `audioMinutesFromBytes`, a 32 kbps guess. On 16-bit PCM that guess is about 8× too high: a two-minute part would be charged 17 minutes.
  - `chunkAudioMinutes(chunk, session)` (`services/interviewProcessing.ts`) charges an upload's WAV part its exact length: bytes less the header, at 32,000 bytes a second, rounded up to whole minutes. That is two minutes for a full part. The route enforces the format, which is what makes the bytes exact.
  - The charge, the run's hold and every receipt line read it (the job, the voice-note path and the manual transcribe route). Any other chunk keeps the guess.
- **Speakers.** As the recorder's:
  - nova-3 diarizes: "Me", the interviewee, or "Speaker ?";
  - Whisper returns no speakers, so its passages read "Speaker ?".
  - The founder renames a passage's speaker on the existing segment route. Numbered speakers are M1's, and apply here when it lands.

### 4. Not built here

- **The page.** It waits on M9's canvas: the file picker, the attestation's three choices, progress and the refusals' sentences. The library exposes `ATTESTATIONS`, `ATTESTATION_SENTENCE` and `MESSAGES` for it.
- **Native transcripts.** Zoom's VTT and Meet's transcript entries (D684) stay first. This is the path for a call with no native transcript, or from a tool Axal does not connect.

### 5. Tests

**`cloudflare-worker/test/recording_upload_d872.test.ts`** (new, 6). It runs on D657's session fixture. The frontend's own `uploadRecording` drives the real routes through an adapter.

1. The upload source:
   - a `stopped` session with consent, method and time from the attestation, no live model and its length;
   - the activity line;
   - a held interview accepted;
   - not refused while another recording is live;
   - a new interviewee's interview marked held;
   - a replayed `client_key` answering the same session.
2. Refused before anything is written:
   - a missing, unagreed or wrong-method attestation (with the sentence), including for a new interviewee;
   - a missing or over-cap length, a text channel, an unknown source;
   - another member.
3. An upload's parts:
   - WebM, 44.1 kHz, stereo, 8-bit or header-only WAV are refused;
   - a repeat is stored once;
   - the cap refuses a part that would pass 3 hours, but not one that fits or a repeat.
4. A 45-minute recording:
   - 23 parts, one session of 23 transcribed segments on one timeline, one transcription per part;
   - a receipt of 45 minutes, where the guess would have charged 17 for each two-minute part;
   - a retry transcribes nothing again.
5. An interrupted upload:
   - it resumes on the same session, sends only the missing parts, and stores each `seq` once;
   - it is processed once.
6. With no AI tokens:
   - the run is refused, nothing runs, and the parts stay;
   - after a top-up, Retry transcribes each part once.

**`frontend/test/recordingUpload.test.mjs`** (new, 7):

- part sizes, `seq` and start times;
- the WAV header, byte for byte, and clipping;
- the attestation checked before the file is read or any request sent;

**Mutation check.** 22 mutations were tried, removing or changing one guard each, across the routes, the minutes, the format check and the library. All 22 were caught.
