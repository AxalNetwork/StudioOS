- **Status:** built (this PR), Part of #3724. Not deployed.
- **Number:** D5309 is this issue's number (D4106).
- **Closes:** D3724 §gaps 8, 9, 10 and 11.
- **Builds on:** #3935 / D1478 (the single drawn cover, `services/coverDraws.ts`), D1487/D1488 (the

  quote's uid as the run's idempotency key), #4201 (the company logo's R2 upload, the shape this one

- **Canvas:** `design/incoming/My Events · Boards.dc.html`, board NE2. Approved; no new design.

### 1. What was missing

An event carried one field about its cover: `cover_url`, a link. Nothing recorded what the image
shows, so no event cover could be read aloud (§gap 11). Nothing could be uploaded at all — the
adapter's `uploadCover` answered "not switched on yet" (§gap 8). A draw made one image, so choosing
meant paying four times in sequence (§gap 9), and the prompt never carried the venture's own colours
(§gap 10).

### 2. The migration

`cloudflare-worker/sql/migrations/202611110745_5309_event_cover_upload.sql` adds four columns to
`events`:

| Column | What it holds |
| --- | --- |
| `cover_alt` | what the image shows, the member's own words, at most 200 characters |
| `cover_source` | `'uploaded'` or `'generated'`; NULL on every row that predates this migration |
| `cover_focal_json` | `{"x":0..1,"y":0..1}` — the point every crop keeps in frame |
| `cover_crops_json` | `{"card":{x,y,w,h},"social":{…},"square":{…}}`, in fractions of the stored image |

NULL means **not recorded** everywhere. An event whose cover predates the migration has no recorded
source and says so; it is never drawn as "uploaded", and `cover_alt` is never `''` — an empty
description would read as "this image needs none", which no event cover's does. Unparseable stored
JSON reads as not recorded too, never as a default frame (`shapeEvent`).

### 3. Three crops, one stored image (§gap 8)

**The departure from the gap's wording, and why.** §gap 8 says "with the three crops". This stores
**one** image and records the three crops as rectangles in fractions of it, rather than storing three
cropped files.

- A Worker cannot crop pixels: there is no image library in the runtime, so three stored crops would
  have to be cropped in the browser and uploaded as three files — three times the bytes, and a
  re-crop would cost a whole new upload.
- A rectangle plus the focal point is everything a card needs to frame the image it already serves,
  and it is what the gap also names ("focal point").
- So `POST /api/events/:id/cover/upload` takes one multipart press — `file`, `alt`, `focal`,
  `crops` — and `coverUploadAsk` checks all of it before a byte is stored.

**What the route checks, and in which order.** Each refusal stores nothing:

| Refusal | When |
| --- | --- |
| `multipart_required` | the body is not `multipart/form-data` |
| `file_required` | no file part, or an empty one |
| `file_too_large` (413) | over 8 MB |
| `unreadable_image` | the bytes are neither a PNG nor a JPEG |
| `too_small` | under 1200 × 675, read from the image's own header |
| `alt_required` / `alt_too_long` | no alt text, or over 200 characters |
| `bad_focal` | not a point inside the image |
| `bad_crops` | a missing key, a rectangle outside the image, or one at the wrong shape |
| `storage_unavailable` / `storage_failed` (503) | R2 is unbound, or the put failed |

**The bytes decide, not the browser.** `imageSize` reads a PNG's IHDR and a JPEG's first
start-of-frame. The `Content-Type` of the form part and the dimensions the editor measured decide
nothing a refusal depends on — the editor's own check (`checkCoverFile`) only saves the member a
round trip.

**Shapes are checked where the image is known.** `cropsAsk(raw, imageRatio)` checks each crop's
aspect within 6% against the real image; the later Save carries the crops the upload already answered
and no image, so it uses `rectsAsk`, which checks the rectangles and not their aspects. Re-checking
them against a guessed aspect would refuse every crop of an image that is not 16:9.

**The upload writes nothing.** Like #3935's draw, it answers a URL, the alt text, the focal point and
the crops with `saved: false`; the member's own Save (`PATCH /api/events/:id`) writes them. Both the
drawn and the uploaded cover are served by the one existing route, `GET /:id/cover/:filename`, under
the one existing gate: `cover-<uuid>` names a draw and `upload-<uuid>` an upload, and each pattern
reads only its own files.

**It is a member upload, so it is guarded** (D1170, D1169 §2). `storeCoverUpload` calls
`assertStorageRoom` before a byte lands and refuses with the one `storage_full` Response every member
upload answers with; a member whose plan is full stores nothing. This is the one way an uploaded cover
differs from the drawn one beside it, which is generated and is named in `storage_room_d1170`'s
`NOT_MEMBER_UPLOADS` rather than guarded. Nothing is noted as landed: no table records a cover's
size, so these bytes are not in a measured D1169 area and `noteStorageLanded` would announce a
crossing of a total they are not in.

**The dev bootstrap carries the four columns too.** `services/eventsSchema.ts` is the shape-only
mirror dev and preview D1 run instead of migrations (D191's pair), so the columns are in its
`CREATE TABLE` and in its `runSchemaBootstrap` ALTERs; `check-schema-pair-drift` reports no drift
and the baseline ledger takes no new line.

### 4. Four variants per press (§gap 9)

`POST /:id/cover/variants/quote` prices four draws and their checks in **one** figure, and the
member's balance covers the whole figure or nothing runs. `POST /:id/cover/variants` draws them on
that quote's uid, which is also the Idempotency-Key: each variant's run carries
`event-cover-variant:<user>:<quote_uid>:<index>`, so the same press retried replays and charges
nothing again (#3846). A stale or absent quote is `409 quote_stale` and runs nothing.

**Three of four drawn is three.** A variant that refuses is named in `refused` and the rest still
stand; the step reads "3 of 4 drawn" and why the fourth did not. All four refusing is the first
refusal's own status and sentence, so the member reads a reason rather than an empty grid. A balance
that runs out part-way, a paused rail or a locked plan stops the press rather than refusing three
more times.

**Regenerate** is a fresh quote for the same prompt. **More like this one** is a fresh quote for the
prompt plus the chosen variant's own alt text — Eadwyn's own words about that image, the only words a
variant carries.

### 5. Brand colours (§gap 10)

The prompt takes the venture's deck brand kit palette (`deckBrandKitFor`, D1562), by the event's
`project_id`, in the kit's key order: ground, ink, accent, secondary, highlight. `deckBrandKitFor`
answers a sanitized kit, where a role it holds is a lowercase `#rrggbb` and nothing else, so nothing
a kit's row carries can reach the prompt as words. An event that names no venture, or a venture with
no kit, carries no colours and the quote says `brand_colours_recorded: false`; the step reads "No
brand colours are recorded for this venture" rather than inventing a palette.

### 6. The seam, switched on

`frontend/src/pages/events/recommendationsAdapter.js` — the one seam D3724 put between My events and
its routes — now answers through the live routes:

| Adapter | Route |
| --- | --- |
| `uploadCover(id, { file, alt, focal, crops })` | `POST /api/events/:id/cover/upload` |
| `variantsQuote(id, prompt)` | `POST /api/events/:id/cover/variants/quote` |
| `drawVariants(id, prompt, quoteUid)` | `POST /api/events/:id/cover/variants` |

The client methods are `frontend/src/lib/api/eventCovers.js` (its own module, D527), each with a
mounted Worker route. `uploadCover` with no file, and `drawVariants` with no quote uid, send nothing:
neither is a refusal the Worker should be asked for.

The cover step (`EventCoverStep.jsx`) chooses the focal point with two sliders and derives all three
crops from it (`cropsFromFocal`), requires alt text before the press is enabled, and mounts
`EventCoverVariants.jsx` beside #3935's single-draw press. A drawn or chosen cover also records
`cover_source` and keeps Eadwyn's own alt text.
