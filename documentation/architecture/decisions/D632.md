## D632 — Draft variants are edited in place, and a colleague seat's link is shown once

**A cap table's draft variant is renamed and edited in place, and the main cap table stays one per company. A colleague seat's invite link is shown to the inviter once, in the invite reply, and never again. The colleague reads who invited them and what the seat gives before anything changes.** Issue #1390, for the Ops canvas's area 6 (#1165): screens `ct-variants`, `st-invite`, `st-accept`. No migration: every store already existed.

### V1 — draft variants (`ct-variants`)

**What was true.**
- `PUT /api/captable/scenarios/:uid` already renamed a scenario and re-simulated new inputs. For a variant (`is_variant = 1`) it skipped the one-per-project clash check.
- No screen called it. A variant could be created and deleted from the Compare panel, but not changed.

**The page.** `/raise/cap-table/variants/:variant` (`CapTableVariantsPage.jsx`) is a new address, because nothing served variants. It is guarded like `/raise/capital/cap-table` (admin, founder).
- The tabs list the project's variants, read from `GET /captable/scenarios/by-project/:id/compare`.
- "Main cap table" is a link back to `/raise/capital/cap-table`. The page never writes the main table:
  - saving is `updateCapTableScenario(uid, { name, inputs })`, with no `project_id`;
  - "New variant" is `POST …/variants`, which always inserts a variant.
- The editor covers the name, founders, option pool, SAFEs, rounds and exit value. Fields this page does not edit ride along unchanged: a SAFE's basis, instrument and note terms, and a round's pool top-up.
- A blank field is left out, never sent as zero. A value that is not a number is refused on the page, as a sentence. The route's own validation errors are shown as the route words them.
- **Not recorded.** The canvas draws Vesting beside each founder and Granted beside the pool. A variant's inputs hold neither, so each reads "Not recorded" with its reason. An exit value never set reads "Exit value: none has been set for this variant."
- **Unreadable.** A failed read says "Variants could not be read just now." with Try again. It never shows an empty tab row.
- The Compare panel on the cap table page links each draft to its editor.
- **Not built:** the canvas's "Variant read" rail, an Eadwyn note. The issue's list does not include it, and it would need its own note store.

**Writes.** Variant create, every scenario edit and every delete now write `activity_logs`: the hashed actor, the user, the project, the scenario uid and `is_variant`. A rename also carries `renamed_from`. A failed log line warns, but never undoes the write.

### S1 — the inviter (`st-invite`)

**Where it lives.** Nothing serves the canvas route `/firm/seats`. Seats were already managed in Settings › Billing (`InvestorSeatsCard`, Institutional only), so the screen is built there as `ColleagueSeatsPanel.jsx`. No new address.

**The link, once.** D611 had `GET /api/investor-seats` return each pending seat's `invite_link`. D632 supersedes that one line:
- the list's query no longer selects `invite_token`;
- each seat carries `state` (`invited`, `accepted` or `revoked`), and the reply carries `used` beside `cap`;
- `POST /invite` is the only reply with the link, and the panel shows it from that reply alone. Reloading the page or the list never brings it back.

The panel's note says "Copy this link now. It is shown once, because no email is sent." D611's mail path is kept: when Gmail is configured and the mail went out, the note says so instead. Either way, the link is shown once.

**The list.** Each seat shows its email, its state, the date it was invited, and either its accepted date or "Accepted: this seat has not been accepted yet." Every seat that is not revoked shows Revoke. A revoked seat does not count against the plan. Search and a State filter narrow the list.

**Unreadable.** A failed read says "Seats could not be read just now." with Try again. It shows no zero quota and no empty list, and invites are disabled until the seats are known.

### S2 — the colleague (`st-accept`)

**Where it lives.** The canvas route `/invite/[token]` is the events RSVP page (`InviteRsvpPage`). The seat accept page has been at `/investor-seats/accept?token=…` since D611, and the invite link points there, so it stays there.

**A read before anything changes.** `POST /api/investor-seats/invitation { token }` is new and read-only. The token is a body field, so it stays out of request logs. It returns:
- `state`: `open`, `revoked`, `accepted`, `wrong_account` or `plan_lapsed`;
- the inviter's name and firm. The firm comes from `investor_profiles.firm_name`, and `firm_readable` is false when that read fails;
- `yours`, whether this account is the one that accepted;
- `invited_email` for a wrong account only, masked as `ab***@domain`.

**The page.**
- **Signed out:** sign in, then come back. Nothing is read.
- **Signed in:** it reads the invitation first. An open invitation shows:
  - who invited them, and at which firm;
  - "Firm: the inviter has not recorded a firm name." when there is none, and a separate sentence when the firm could not be read;
  - what the seat gives;
  - for anyone not already an investor, "Accepting turns your account into an investor account."
- **Nothing is accepted until they press Accept.** D611 accepted automatically for an investor; that no longer happens.
- **Other states.** Wrong account (with Switch account, which signs out and comes back), revoked, already accepted (yours, with Open workspace, or someone else's), and plan lapsed each have their sentence and no Accept. A link with no token says the invitation has no seat attached. A failed read says "This invitation could not be read just now." with Try again.
- **Phone.** The layout is the 390-wide one: a 16px gutter, top-aligned, with full-width buttons.

**The token outlives acceptance.** Accepting no longer clears `invite_token`. `accepted_at` is what keeps a link single-use, and keeping the token lets the same link read "already accepted" rather than "not valid".

**Writes and refusals.** Invite, accept and revoke write `activity_logs` with the hashed actor and the seat id. They never record the colleague's address. Every refusal the seat routes give now carries a `message` sentence.
