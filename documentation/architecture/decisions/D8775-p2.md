## D8775 part 2 — Build › first feature: promotion on one row, team owners, an agent builder with a reviewer, a dated test against a deliverable, and the Pitch offer (#8775)

Part of #8775. Part 1 is `D8775.md` (the canvas, BLV00 to BLV40). This part builds the canvas's ◇ backend and the forms it reaches, to option A of Q1, Q2 and Q3, which the owner has not answered (S1 on #8775: build to option A). Every name and address in the tests is made up.

### What is built

- **One promotion, one row (BLV02, BLV02B).** `POST /api/cycles/build/must-haves` with `feature_id` makes that Solution design feature the must-have on its own `mvp_features` row. Its pain theme, hypothesis and the hypothesis's `success_bar` are kept; a title or hypothesis is replaced only when the body names one. `roadmap` (`now`, `next` or `later`) adds the linked roadmap item (`feature_id` set) in the same batch, under the roadmap's free-tier cap. A feature that is already a must-have answers 409, so nothing is made twice. Add must-have offers **From Solution design** (the features not yet must-haves, after "A new one"); choosing one hides the title and hypothesis boxes and offers **Also on the roadmap**. The feature record's action keeps its key `mark-must-have`, is now the form **Make it a must-have** (owner, due, also on the roadmap) and runs the same promotion.
- **What is carried is shown.** The feature record has a side section *Carried into its must-have*, and the must-have record *Carried from the feature*: pain theme, hypothesis and success bar. The four canvas facts on each record are unchanged.
- **Owners (Q1 A, BLV04, BLV05).** `services/buildOwners.ts`: an owner or reviewer is on the project's Team as #3994 lists it (accepted `project_members`, the founder-owner) or a member of its company. It is used by Add must-have, Make it a must-have, Add item, the must-have and item PATCHes, Add a session and their record forms. A changed owner is checked; one already stored stays. Risks keep company members (their own route, outside this path). An empty list says why ("No one can own it yet: an owner is on this project's team or in its company…"), the Worker's read adds a link to `/projects/<id>/settings/team`, and the must-have still saves without an owner.
- **Builder and reviewer (Q2 A, BLV05B).** Migration `202611270215_8775_build_feature_path.sql` adds `mvp_features.reviewer_user_id` and `builder_agent_id`. A must-have's builder is a person (the owner) or one of the project's own *active* agents, and an agent is refused unless a person reviews (400). The must-have record has *Who builds it* with the action *Builder and reviewer*; its foot says the agent only drafts.
- **Returned is not tested (BLV08, BLV09).** The same migration adds `mvp_test_sessions.deliverable_url`, an https address with no credentials or port. Add a session takes it, and a done session must be dated. The must-have record's *Proof* section says **Returned** (an address, no kept finding: "Returned is not tested"), **Tested** (a done session kept a finding) or **Not yet**, with the last tested date. `testedMark` and Progress are unchanged: an address never counts.
- **Offered to Pitch, accepted by the founder (Q3 A, BLV11).** `raiseEvidenceSources.ts` has the kind `prototype-test-result`: a must-have's done session that is dated, kept a finding and links an https deliverable. It is labelled *recorded*, dated by the session, and offered through Raise › Evidence › Waiting for review like every kind. The address is not in the offer. Accept or Dismiss stays the founder's.

Writing one outside that flow is a design choice for the plan's owner, so Progress (`buildProgressModel.js`) still follows plan items only.
- **An app link per must-have** whose live check feeds Live and In progress. `lovable_app_links` keeps one link per Prototype / MVP. Splitting it touches the Lovable dialog, which #8773 is changing.
- **The `build.prototype_test` deck source slot** (D896). The evidence kind is offered and accepted in Raise; placing it in the deck as its own source needs the deck-source slot list changed, which is the deck's own work.
- **Frontend only:** the overview's primary action and trail (BLV01), the Lovable "where the work is" strip (BLV06, which is #8773's dialog), the phone path (BLV20–BLV25) and dark frames. Browser verification is S21's (#8795, #8777).
