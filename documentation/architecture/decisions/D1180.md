## D1180 — Use of funds part 7: retire the old capital model (#3107)

- **Status:** built in slot S26 (claimed by the S25 session at the owner's request), 2026-10-27. Part 7 of #2455; #2297 row 66 is Retire by the owner's word.
- **Basis:** `origin/main` at `32fe9c4382`. Part 5 (D1178, Forecast on the model's store) is live; CAPTABLE (D1015) and CAPREL (D1188) shipped.
- **Migration:** none (§3).
- **Worker:** no route changes. One `FORWARD_REDIRECTS` entry in `services/redirectRoutes.ts`, and a comment in `routes/financials.ts`.
- **Deleted:** `frontend/src/pages/FinancialsPage.jsx`, `frontend/test/use_of_funds_fixes_d1174.test.mjs` (four tests, all of the page), and the Capital workspace's Financial Model tab.

### 1. What is retired

- **`FinancialsPage.jsx`.** The model is Use of funds › Runway › Forecast, on the same store (`GET`/`PUT /api/financials/:id`, through `lib/api/useOfFunds.js`). Nothing in the app imports the page now.
- **The client methods only it called:** `api.getFinancialModel`, `api.saveFinancialModel`, and `api.recomputeFinancialModel`, which nothing called before either. `downloadFinancialModelXlsx` stays: Forecast's export uses it.
- **Its explainer** (`explainers.financials`).
- **The workspace's Financial Model tab.** `CapitalWorkspacePage.jsx` draws Raise Pipeline only.
- **`/raise/capital`'s editor return** in `founderToolNavigation.js` (module Use of funds). It was the model tab's way back, and the tab is gone.

### 2. Where the old doors go

- **`/raise/capital?mode=workspace`** lands where `/raise/capital/model` already does (D1178): `/raise/use-of-funds/runway/forecast`. The model was the workspace's default tab.
  - The query and hash are kept, `?project=` becomes `?project_id=`, and `?moved=capital-model` shows Forecast's notice once.
  - **It counts itself.** `/raise/capital` is also the Capital page, so the address bar cannot count it. It is a `FORWARD_REDIRECTS` entry, and `UseOfFundsMovedRedirect` sends its key when given `count`. `/raise/capital/model` and `/build/financials` stay address-bar redirects, so they send nothing of their own and are never counted twice.
- **The Capital page's two cap-table editor links** ("Open editor" and "Open cap-table editor") pointed at `?mode=workspace`, whose cap-table tab D1029 retired. They go to `/raise/cap-table?project_id=…`.
- **The advisor's three financial questions** (runway, burn, MRR) targeted `/raise/capital/model`, which only forwards. They target `/raise/use-of-funds/runway/forecast`.

### 3. What stays

- **`/api/financials` and `financial_models`** are Forecast's store, as the issue says.
- **`capital_recompute_json` is not dropped.**
  - No Worker route reads it.
  - D1174 kept it as legacy storage, and its Worker test (`financial_integrity_2462.test.ts`) pins that the legacy value survives a save.
  - `routes/financials.ts`' schema guard still declares the column.
  - The dev FastAPI reads it.
  - #3107 names no migration.

  Dropping it would also mean changing the guard and that pin. It is left for a decision of its own, if the owner wants the space back.
- **`CapitalWorkspacePage.jsx` is not deleted.** Its Raise Pipeline tab has not moved: `/raise/capital/pipeline` still mounts it, and Capital relationships part 6 (#3128, D1194) is the part that forwards that address. S1's release note says to retire nothing a live page still imports. #3128 says the file "goes with Use of funds part 7", and this part cannot delete it before #3128 lands. **Whichever lands second deletes it.** If #3128 merges first, its forward leaves the file unmounted.
- **`AdvisorFilledBanner.jsx`** is no longer mounted anywhere (FinancialsPage drew it). It is a general component, not the model's, so it stays.
- **`lib/railPages.js`'s `/raise/capital` alias** stays: the Capital page is live.
