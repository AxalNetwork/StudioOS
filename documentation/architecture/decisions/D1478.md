### Why

The owner asked for every Cloudflare-hosted model to be connected to the modules where it fits, and to no module where it does not. Most of the facts already lived in code: the catalogue, `moduleModels.ts`, the rail matrix and the router's tasks. What was missing was a module-by-module view of them, kept from drifting, and a fresh read of Cloudflare's pages. A hand-written table would go stale with the next model.

### Part B: the picks the run reads (built 2026-10-31)

- **`image`, an option kind only.** `deck:image` and `draft:logo` take kind `image` and name the job they run (`task: 'deck_image'`, `'brand_logo'`), which is the row's `routeTask`. `RAIL_KINDS` stays at 14, and the generator refuses `image` on a page row. Their list is `optionKinds.image` in `scripts/lib/railMatrixOverrides.json`: FLUX.1 Schnell (Default), FLUX.2 Klein 4B, Klein 9B, FLUX.2 Dev, Lucid Origin and Phoenix 1.0, the last three under All models (#3745).
- **The image jobs take those six as `alternates`.** A draw run with an option of kind `image` uses, in order:
  1. the caller's model, when the option offers it, it is one of the route's alternates and `isOffered` passes; otherwise 400 `model_not_offered`;
  2. the member's stored pick for the option, under the same test;
  3. the route's default, FLUX.1 Schnell.

  The quote takes the same branch, so the hold prices the model that runs. **No fallback chain:** a failed image is not redrawn on another model. With `AI_PARTNER_MODELS` off, the FLUX.2 and Leonardo models are not offered, so a stale pick reads as none and Schnell runs.
- **Transcription options list what transcribes.** An option with handler `transcribe` lists `transcribeModels` (Whisper Large v3 Turbo, Nova-3, Whisper), the `transcribe` task's alternates. `withModuleModels` adds no chat model to it. A `transcribe` run with such an option reads its pick by the same three steps; a session's own `final_model`, which the caller passes, still wins.
- **The deck says which model drew.** S1's deck v2 task A1 (on #3721, 2026-10-31):
  - the image quote names the model the run will use (`q.model` from `quoteRun`), not FLUX.1 Schnell by fixed id;
  - a generated image's `model_label` comes from `IMAGE_MODEL_LABELS` (`services/aiImages.ts`, re-exported by `services/decks/images.ts`) for any draw model;
  - the row keeps `usage.model`, the model that ran.
- **Deck autofill runs `rail_write`.** "Fill from project" is text-only work on `form:deck`, a write option, so `services/decks/autofill.ts` runs and records the write task instead of `rail_vision` (the use-case plan's item 6 in §4.2).

### The model-coverage check (2026-11-01, #3939, task 5)

`scripts/check-model-coverage.mjs` reads the job table (`services/ai/modelUseCases.ts`, task 0), the catalogue, `railMatrix.json`, the deck's `ELEMENT_GROUPS` and the source trees. It fails when:
- a current catalogue id is in no row of the model table, or in two;
- a job, or one step of a chain, has no Default or two;
- a Default is outside its kind's list;
- a deprecated id is named in code outside `catalogue.ts`, `aiCatalog.ts` and the router's price list (comments are history, not uses);
- a model that is not text-to-image sits under Draw, or a text model under Listen;
- a deck element group names no job id.

It sits beside this decision's coverage test, not in its place. It joins `test:guards` once tasks 0–4 merge, because it must pass on `main`. On `main` today its rules find exactly the plan's known items: §4.2 item 9 (Record a Session's Listen row lists `llama-3.3-70b`, on two pages), §4.3's live persona call, and `railMatrixOverrides.json`'s "Gemma 3 12B". This task deletes that last entry rather than re-pointing it. A canvas that still names Gemma 3 12B then fails the matrix build ("no id for the canvas model"), instead of silently drawing a different model.
