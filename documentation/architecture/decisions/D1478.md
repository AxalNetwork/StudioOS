## D1478 — The Workers AI coverage matrix is generated, and image and transcription picks are the ones the run reads

- **Status:** built by the S12 session for slot S22 at the owner's request (#3721, 2026-10-31): Part A in #3859 (with the fix in #3865), Part B in the PR after them. Not deployed.
- **Builds on:** D760 (the catalogue), D764 (the rail matrix), D1369 (#3626: each offered model's operation and modules), D903 (deck images) and D763 (the guard). It changes none of them.
- **Migration:** none. D1479, D1480 and migration 706 are unused and released.

### Why

The owner asked for every Cloudflare-hosted model to be connected to the modules where it fits, and to no module where it does not. Most of the facts already lived in code: the catalogue, `moduleModels.ts`, the rail matrix and the router's tasks. What was missing was a module-by-module view of them, kept from drifting, and a fresh read of Cloudflare's pages. A hand-written table would go stale with the next model.

### What was decided

1. **The catalogue was re-read on 2026-10-31**, through the Cloudflare docs connector. `developers.cloudflare.com` does not resolve from the sandbox, the same as for D760.
   - The pricing page says it was updated on 2026-10-20 (D760 read the 2026-10-15 version).
   - 66 priced rows were compared figure for figure, both price and neurons, and none had moved.
   - Two rows are new, both announced on 2026-10-19:
     - `@cf/deepseek-ai/deepseek-v4.1-flash-1017`: GA, paid plans only, $0.300 in / $0.006 cached / $1.200 out per 1M tokens, a 1,048,576-token context, vision, reasoning (`reasoning_effort`) and function calling. It is offered, with a `moduleModels.ts` row for reason, plan and numbers work, like V4 Flash.
     - `@cf/cloudflare/clairic`: an extraction model at $0.100 per 1M input tokens with a 65,536-token context. Its page and the changelog call it a **preview** ("an early checkpoint"), so it is held as `beta` and offered nowhere until it leaves preview.
   - The counts are now 94 rows, 70 priced and 61 offered with the partner gate open (53 with it shut).
   - The two new pricing rows are kept verbatim in `cloudflare-worker/test/fixtures/workers_ai_pricing_rows_2026-10-31.md`, beside S1's copy of the 2026-10-15 page, so the neuron test still checks every row against a printed source.
   - **Not changed here:** context windows the catalogue leaves null although a model page states one (for example GLM-5.3, R1 Distill, Mistral Small 3.1 and Llama 4 Scout). The plan on #3721 corrects them in its text-jobs PR, together with the quote's fit check.
2. **The matrix is generated.** `cloudflare-worker/src/services/ai/coverage.ts` builds it from:
   - the catalogue;
   - `MODEL_CONNECTIONS`;
   - `railMatrix.json` and `moduleConnections`;
   - the router's `ROUTE`, reached from `FIXED_JOBS` (38 call sites, each cited by the file that calls the task);
   - Record a Session's `STT_MODELS`.

   `renderCoverage()` produces `documentation/architecture/AI_MODEL_COVERAGE.md`, and a test fails when the committed file differs.
3. **Four cell states.**
   - **Wired:** a page's default model, a fixed job's model or fallback, or a session's default.
   - **Offered:** a member can pick it there, but no job runs it by default.
   - **Gap:** it fits the module and nothing connects it; the plan on #3721 carries it.
   - **n/a:** it does not fit (one reason per operation), or the model is not offered (beta, deprecated, unpriced or partner gate).
4. **Fourteen columns.** Validate, Record a Session, Build, Raise, Grow, Network, Research, Calendar, Articles, Email, Studio / Eadwyn, Admin consoles, Moderation and safety, and the Investor, Advisor and Partner workspaces.
   - A page belongs to exactly one column. Admin keys come first, so `Admin · Home` is an admin page.
   - `FITS` says where each operation fits. Image generation never fits Validate, Record a Session, Network, Research, Email or Calendar, and a test pins that.
5. **The file names what is wrong.**
   - "Picks the run never reads" lists every option whose list holds models its run cannot use:
     - `deck:image` and `draft:logo` list three image readers, while their runs are `deck_image` and `brand_logo` on FLUX.1 Schnell;
     - every `transcribe:*` option lists Flux and the 70B, while its run is `transcribe`.
   - "Connected outside its fit" lists every wired or offered cell outside its operation. Today that is only Moondream on Grow, through `draft:logo`.
   - Part B emptied both sections.
6. **Pitch deck v2's models (#3716)** are printed with a price per run from `billedMicro` at `AI_MARKUP`, never hand arithmetic:
   - writing: Llama 3.3 70B;
   - images: FLUX.1 Schnell;
   - vision: Gemma 4 26B;
   - design check: GPT-OSS 120B;
   - embeddings: BGE Base EN v1.5;
   - safety: Llama Guard 3 8B.

### Citations are files, not lines (2026-10-31, after the merge)

Part A first cited each fixed job by file and line, and the test failed when that line stopped naming the task. Within the hour, PRs merged beside it moved `routes/ai.ts`'s `workspace_explain` call by five lines, and main went red on an edit that changed nothing about models. A file citation, with a test that the file still calls the task, finds a moved or removed call without failing on every unrelated edit above it.

The same merge window brought #3745, which keeps at most three suggested models per row and puts the rest in `more`. The matrix reads `more` as offered, so a model moved there keeps its cell.

### Part B: the picks the run reads (built 2026-10-31)

- **`image`, an option kind only.** `deck:image` and `draft:logo` take kind `image` and name the job they run (`task: 'deck_image'`, `'brand_logo'`), which is the row's `routeTask`. `RAIL_KINDS` stays at 14, and the generator refuses `image` on a page row. Their list is `optionKinds.image` in `scripts/lib/railMatrixOverrides.json`: FLUX.1 Schnell (Default), FLUX.2 Klein 4B, Klein 9B, FLUX.2 Dev, Lucid Origin and Phoenix 1.0, the last three under All models (#3745).
- **The image jobs take those six as `alternates`.** A draw run with an option of kind `image` uses, in order:
  1. the caller's model, when the option offers it, it is one of the route's alternates and `isOffered` passes; otherwise 400 `model_not_offered`;
  2. the member's stored pick for the option, under the same test;
  3. the route's default, FLUX.1 Schnell.

  The quote takes the same branch, so the hold prices the model that runs. **No fallback chain:** a failed image is not redrawn on another model. With `AI_PARTNER_MODELS` off, the FLUX.2 and Leonardo models are not offered, so a stale pick reads as none and Schnell runs.
- **Transcription options list what transcribes.** An option with handler `transcribe` lists `transcribeModels` (Whisper Large v3 Turbo, Nova-3, Whisper), the `transcribe` task's alternates. `withModuleModels` adds no chat model to it. A `transcribe` run with such an option reads its pick by the same three steps; a session's own `final_model`, which the caller passes, still wins.
- **The deck says which model drew.** S1's deck v2 task A1 (on #3721, 2026-10-31):
  - the image quote names the model the run will use (`q.model` from `quoteRun`), not FLUX.1 Schnell by fixed id;
  - a generated image's `model_label` comes from `IMAGE_MODEL_LABELS` (`services/decks/images.ts`) for any draw model;
  - the row keeps `usage.model`, the model that ran.
- **Deck autofill runs `rail_write`.** "Fill from project" is text-only work on `form:deck`, a write option, so `services/decks/autofill.ts` runs and records the write task instead of `rail_vision` (the use-case plan's item 6 in §4.2).
- **Plan gating** waits for owner question A: until then the offer is the catalogue and the partner switch.
- The coverage file's "Picks the run never reads" and "Connected outside its fit" are now empty, and its test holds them empty.
