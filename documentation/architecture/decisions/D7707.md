## D7707 — A market-intelligence row says what it measures, and each source run leaves a record (#7707)

- **Status:** built 2026-11-19. Filed from the owner's Research › Markets audit of 2026-11-19 (2B), under #3701.
- **Builds on:** D538 (no stub row is stored or read; `liveRowSql()`), D106 (the market-intelligence block is HQ's), #4568 and D5343 (runtime `ADD COLUMN` asks first).
- **Additive only.** Which rows are stored, their `ts`, `metric_key`, `metric_value` and `geo`, and so every index value, stay as they were. Storing an unchanged observation once, linking a revision and fetching only when a cadence is due are #7711; counts and freshness on pages are #7708 and #7710.

### What was wrong (checked on main)

- `services/market_intel/sources/_live.ts` wrote the fetch time as `ts` in both builders, and `ts` was the only date a row carried: a World Bank figure for 2025 fetched today read as an observation made today.
- The macro connectors (World Bank, OECD, Eurostat) kept the bare value and dropped the provider's period and publication date.
- Nothing recorded what a source run did, beyond console lines and the daily counter in `market_intel_quota`.
- The comment above the six-hourly block in `index.ts` said connectors were idempotent on `(source_key, sector, ts)` and that the quota ledger stopped duplicate writes. Neither was true: every run appends its rows again.

### The decision

**Migration `202611191833_7707_market_intel_row_dates_runs.sql`.** Six nullable columns on `market_intel_rows`:

| Column | What it holds |
|---|---|
| `observed_period` | the period measured, in the format below; null when the response does not state one |
| `observed_period_end` | the last day measured, `YYYY-MM-DD` |
| `published_at` | the provider's own last-updated date; never the fetch time; null when the provider sends none |
| `retrieved_at` | when the row was fetched (the same instant as `ts`) |
| `coverage_area` | macro rows: `World`, `OECD aggregate`, `EU27` |
| `scope` | `sector` (a per-sector signal) or `context` (one macro figure replicated across sectors); `CHECK`ed |

No backfill. A row written before D7707 keeps them null, meaning "not recorded", and its retrieval time is its `ts`: `retrievedAtSql()` in `liveRows.ts` reads `COALESCE(retrieved_at, ts)`.

And a table, `market_intel_source_runs`: source key, started, finished, outcome, reason, rows seen, rows inserted, rows unchanged (null until #7711) and error class.

**Period format.** `YYYY`, `YYYY-Qn`, `YYYY-MM`, or `YYYY-MM-DD/YYYY-MM-DD` for a queried window (a single day is `D/D`). `observed_period_end` is the last day measured. `normalisePeriod` in `_live.ts` reads `2025`, `2025Q3` / `2025-Q3`, `2025M07` / `2025-07` and `2025-07-04`; anything else is null, never a guess.

| Source | Period | `published_at` | Scope, coverage |
|---|---|---|---|
| World Bank | the observation's `date` | the header's `lastupdated` | context, World |
| OECD | the observation key's position on the `TIME_PERIOD` dimension of the response's own structure | null: the API returns none | context, OECD aggregate |
| Eurostat | the `time` index of the same flat key as the value stored (value keys are sparse, so the last value is not necessarily the last year listed) | the response's `updated` | context, EU27 |
| Crossref, OpenAlex | the window queried, 30 days back to the retrieval day. Neither is sent an end bound, so the end is the day it was asked | null | sector |
| arXiv | the `submittedDate` window queried, to the day | null | sector |

The other six connectors that use the builders (BLS, FRED, Hacker News, GitHub, SEC EDGAR, USPTO) compile unchanged: the new `CommonRow` and `PerSectorResult` fields are optional. Their rows carry `retrieved_at` and `scope` from the builder and a null period.

**What the macro figures are.** The World Bank series is gross capital formation (`NE.GDI.TOTL.ZS`, % of GDP, divisor 50). OECD (`DSD_MSTI@DF_MSTI`, `PT_B1GQ`) and Eurostat (`rd_e_gerdtot`, `PC_GDP`) are R&D spending as a share of GDP (divisor 6), stored under the key `capital`. The series code, its name and the divisor go in `payload_json` and in a comment beside each divisor. The key stays `capital`, so no index value changes; whether R&D intensity belongs under capital is #7708's to weigh.

**The run record.** `runSources` writes one `market_intel_source_runs` row for each source whose `MI_FLAG_<KEY>` is `live`; a source that is off writes none. Outcomes: `fetched`, `failed`, `out_of_quota`, `nothing_to_cite` (a draft whose `fetchLive` answers with stub rows), `no_live_client`. `reason` is the D538 skip reason. `error_class` is one of `http_<status>`, `timeout`, `unreadable_response`, `empty`, `other` (`classifyRunError`), enforced by a `CHECK`; no provider text and no request URL is stored. A failed write of the run row is logged and ingestion carries on. In development (`MI_STUB_ROWS = "on"`) a failed or out-of-quota run that a stub filled in for is recorded as `failed` or `out_of_quota` with the stub rows it inserted; production stores no stub (D538).

**`liveRows.ts`.** `retrievedAtSql()` / `retrievedAt()`, and `observationKeySql()` / `distinctObservationsSql()` / `countDistinctObservations()`: one observation is source, sector, geo, metric and the period, or the UTC day of `ts` where no period is recorded. A World Bank year read every six hours is one observation. For #7708.

**`schema.ts`.** The runtime `CREATE TABLE` declares the same columns as the migration, and `market_intel_source_runs` as there. Every statement, the five `ADD COLUMN`s it already had included, now runs through `runSchemaBootstrap` one at a time (a failure is warned and the rest run, as before), so `schema.ts` leaves `scripts/runtime-ddl-baseline.json`: the guard counts it as asking first.

**`GET /api/admin/market-intel/health`** (`routes/admin_market_intel_health.ts`), `requireHqAdmin`, read-only, mounted ahead of the admin hub. Per source: its flag, cadence and status; its last five runs with outcome, reason and error class; live rows held; the newest period measured; the newest retrieval. A source with no run on record has `runs: []` and says so; one whose stored rows record no period says so. Every read of `market_intel_rows` carries `${liveRowSql()}` (`market_intel_live_rows_d538.test.ts` sweeps for it). A read that fails answers 503 `market_intel_health_unreadable`, never zeros. No auth-inventory entry: the route is gated and names no record. No client method: no page reads it yet.

**`index.ts`.** Only the comment above the six-hourly block changes, to say what the code does: every run appends rows, and nothing prevents a repeat.
