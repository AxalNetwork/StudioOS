## D764 — The model matrix ships in the Worker: every page names the Workers AI models that fit its work

- **Status:** decided by the owner in #1874's plan (D720 §5 and §6; the plan's D727), filed by S1 as #2089 (task A5 of D720). This file was written by the task's first PR.
- **Basis:** `origin/main` at `2f3685ce`, with #2085's canvas data. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D720 (the decision), D761 (the shapes), D762 (the quote a resolved chain feeds). **Waits for:** D760 (the catalogue and billed prices), D768 (`useRailOption`, PR 3 only).

### 1. The decision

The rail's suggestions are the Worker's, not the browser's. `services/ai/railMatrix.json` has one row per canvas page. The row gives the page's kind of work, its router task `rail_<kind>`, and the models that fit that work, default first. The file is generated from the owner's canvas tables by `scripts/build-rail-matrix.mjs`, and a test fails when the committed file is not the script's output.

### 3. Rules the generator and the test both hold

- Every model is one the pricing file prices. D760's catalogue replaces that file when it lands.
- Every model fits its kind: a vision page's models read images, and a speech page transcribes first.
- The `research` and `search` kinds read `axal-search`, a 768-dimension index, so their embedding is `@cf/baai/bge-base-en-v1.5`. The canvas's BGE-M3 and Qwen3 Embedding collapse into it on those kinds. The `match` and `multi` kinds rank a set they have already fetched, so they keep BGE-M3.
- `models[0]` is the only card with the role "Default". Where the canvas's first role was another word (Transcribe, Match, Search, Index), that word becomes Default.
- Every paid-only default has a non-paid alternative of the same shape. A `rail_<kind>` task's primary is its kind's first model a free plan can run, and its fallback chain holds only such models.
- Roles and lines never say advice, advise, advisor, recommend or fiduciary.

### 4. Open for the owner

- **`rail_search` has only Kimi K2.6 to answer with,** which needs a paid plan. The canvas pairs the index with no other answer model. On a free plan, a search page's answer is refused until a non-paid answer model is added to the canvas's `search` kind.
- **The 1,802 option rows** D720 §5 describes were lost with the planning session's scratchpad. PR 3 builds option rows from the options the code registers through D768's `useRailOption`.
