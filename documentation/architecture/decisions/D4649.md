## D4649 — Copy to Stream: one copy per click, and an unreadable copy table said as such (#4649)

- **Status:** built by S27, 2026-11-09 (#4649, Learning audit package 4 of 5, parent #3726). Not merged, deployed or live verified.
- **Code:**
  - `cloudflare-worker/src/services/learningStream.ts`: `copyStates` answers `null` when the copies cannot be read; `CopyState` gains `unreadable`;
  - `cloudflare-worker/src/routes/admin_learning.ts`: `GET /items` sends `stream_copy: { state: 'unreadable' }` on each uploaded file then;
  - `frontend/src/pages/learning/LearningStudio.jsx`: `onCopyToStream` is single-flight per file;
  - `frontend/src/pages/learning/videoUpload.js`: `streamCopyOf` reads `starting` and `unreadable`; `stillOnStorage` answers `'unreadable'`;
  - `frontend/src/pages/learning/StudioContentTable.jsx`: the row's "Starting copy…" and "Copy state unreadable", and the banner's unreadable form.
- **Migration:** none.
- **Tests:** `frontend/test/learning_studio_copy_pending_4649.test.mjs` (a mounted Studio over a synthetic Worker) and one case in `cloudflare-worker/test/learning_stream_copy_4179.test.ts`.

### 1. One copy per click

#4742 wired Copy to Stream, but the row moved to "Copying…" only once the POST answered, so a second click in that window started a second POST. The route refuses that second one with 409 `already_copied`, and the row then read "Copy failed" for a copy that was in fact running.

Now `onCopyToStream` keeps the uids whose POST is in flight in a ref and returns at once for one already there. Before the POST it sets the row to `{ state: 'copying', starting: true }`, which draws "Starting copy…" with no button. The route's answer then replaces it: `copying` on a 202, or `failed` with the route's own words. "Try again" goes through the same path.

### 2. A copy table that cannot be read

`copyStates` used to catch a failed read of `learning_stream_videos` and answer an empty map. `GET /items` then sent `{ state: 'none' }` for every uploaded file. The Studio offered Copy to Stream for files that might already be copying or verified, and the banner counted all of them.

Now the read answers `null`, and `GET /items` sends `{ state: 'unreadable' }` on each `r2` item. The Studio draws, per row, "Copy state unreadable", with no button. The banner reads "Whether uploaded videos still play from storage could not be read. This is not a claim that none do." with Try again, which re-reads the lists. It never shows a count, and never "0".

### 3. Unchanged

The copy route, its refusals, verification (ready with a duration above 0), the 30-day retention of the original and the sweep are D4179's and are untouched. No Stream setting, spend limit, retention value or production asset changes.
