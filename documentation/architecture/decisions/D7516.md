## D7516 — Expertise Overview: the Next step, the four-dimension status strip and the admin preview (#7516)

- **Status:** built 2026-11-18. Boards EX-01 (the Next step card and the status strip), EX-03 (the admin preview with no advisor selected) and the full-width Next step of EX-04b, from the Expertise v2 canvas (D4823, `design/incoming/Expertise v2 Page.dc.html`). Split from #4828 by the owner's answer (A) of 2026-11-18; #4823 is the overview's tracker. Frontend only.
- **Builds on:** D4823 (the canvas), D4828 (the board's per-section states, `states: 'platform'`), D5129 (`StateChip`, `DataState`), D4697 (each read retries on its own), D4689 (counts over the whole list), D4670 (`needs_reconfirmation`), D4830 (a board's `lead`).
- **No migration, no Worker route, no client method.** Every figure is a read the Expertise board already makes.

### What was built

1. **`NextActionCard` (EX-01, EX-04b).** One step leads, two more at most follow under "Also worth doing", each with one link. The steps, in order, and the read each comes from:
   - no profile (`GET /api/advisors/me` answers null): **Create your Expertise profile**, and nothing else, since every other area waits on it;
   - a claim whose confirmation no longer counts (`/me/proof`, a consent in `needs_reconfirmation`, D4670): **Ask {attester} to reconfirm “{claim}”**;
   - a piece with changes requested (`/me/thinking`): **Review editor feedback on “{title}”**, to its editor;
   - profile fields a match reads that are empty (`MATCH_FIELDS`, the Profile meter's own list): **Fill in N profile fields a match reads**;
   - services with no price (`/me/services` `counts.unpriced`): **Add a price to …**;
   - no claim, or every claim self-stated with none awaiting (`/me/proof` `counts`): **Add a claim …** or **Ask someone to confirm …**;
   - an active session type no live booking link sells (`/me/visibility` `unlinked_services`, D4827): **Give “{name}” a booking link**;
   - no service at all: **Add a service**.

   A step is chosen only once every read has answered (a skeleton until then), so the lead never changes under the reader. A read that failed offers none of its steps, and the card says which reads it could not use with the Partial chip. A record that supports no step draws no card (D4823 EX-16: "none when state supports none"). On a phone the step is a column: the area and title, then a 48px full-width button; the reason is hidden there, as EX-04b draws it.
2. **`ExpertiseStatus`, four dimensions (EX-01, #4823's acceptance "distinguishes completion, publication, verification and availability").**
   - **Completion** (`/me`): Complete or Incomplete, "n of 7 fields", the missing ones named. No profile is "No profile yet", never "0 of 7".
   - **Publication** (`/me`, `/me/services` `publication_counts.published`, `/me/thinking` `counts.published`): Profile listed or not, "N services published · N articles published", proof private, and Preview public profile ↗ (`/advisors/:uid`).
   - **Verification** (`/me/proof` `counts`): confirmed and awaiting, self-stated, and "needs reconfirmation" only when the whole list came back (`page.next_offset` null); a page of a longer list leaves it out rather than undercount.
   - **Availability** (`/me/visibility`): live booking links of the total when the whole list came back, else the total; the session types no live link sells.

   Each cell is loading (the skeleton and the word), Refused (the licence, #5363), Unavailable or Partial with #5129's `StateChip`, and a failed cell has Retry, which reads only that cell's failed sources again (D4697).
3. **The admin preview (EX-03).** For an administrator browsing as Advisor, not in a support session (`isAdvisorPreview`: `useViewMode()`'s `isAdmin`, the account's own role, the same rule as `App.jsx`'s `advisorRolePreview`), one state replaces the sections: "Select an advisor to view their Expertise", Impersonate an advisor (leaves the preview and opens All accounts, `/admin/accounts/all`, whose View As starts a support session recorded with its reason) and Exit preview, then a data-free outline of the four dimensions, "Layout only · no data". An advisor never sees it.
4. **How it is mounted.** The Expertise board names `lead: ExpertiseOverview` (`workspaces/boards/advisorExpertise.js`). `BucketBoard` now hands a lead the board's source states as well as its sections (`sources={byKey}`) inside a `Suspense` that shows the sections meanwhile, so the overview reads nothing twice; the Practice lead ignores the new prop. The lead is `lazy`, because it imports Profile's field list, so the shell every first visit fetches is unchanged.

### Departures from the canvas

- **Five cells became four dimensions.** EX-01 draws "Your Expertise" as five cells, one per zone. The issue and #4823 ask for the four dimensions, and the five zone sections already sit below with their counts, so the strip is the four.
- **"Next step", not "Recommended next step".** The phone board's label is used on every width.
- **"Ask again in Proof" links to Proof** instead of asking in place: the ask flow is Proof's (`ProofZone.jsx`, open in #7191).
- **The header (Edit profile, Preview public profile ↗), the Build → Prove → Publish → Engage → Learn line, "What's public" and the Eadwyn card** are not built here; Preview public profile is the Publication cell's action. They stay with #4823.
- **EX-03's one banner.** The canvas draws one banner, "Viewing as Advisor · No advisor selected", in place of the shell's layers. The shell's Preview strip (`App.jsx`) and the `AdvisorPreviewNotice` line (`AdvisorBucketRoutes.jsx`, open in #6765) stay; the preview state carries Impersonate and Exit itself.
- **Reads still run in the preview.** The board's sources are read before the lead decides; for an administrator `/me` answers null and the list reads have no advisor of theirs to read, and none of it is shown. No advisor's record is read.
- **Dark.** The canvas draws no dark board; every light surface carries its `dark:` pair.
