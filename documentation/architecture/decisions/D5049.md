### 1. Contracts owns the templates

The fourteen slugs in the issue are a catalog in code (`AGREEMENT_TEMPLATES`): each slug is bound to its package
or program and to the kinds it may draft (a package template drafts `package_master` or `package_addendum` for its
package; a program template drafts `program_licence` or `program_addendum` for its program). The **text** is a
row HQ authors in the Contracts library (`legal_templates`), versioned there as every template is. A slug HQ has
not authored reads `authored: false` on `GET /templates` and a draft from it is refused (`missing_template`);
a library row the library restricts (D4811) is refused with the library's own sentence. A program schedule is
never drafted from a template: it is built from its grant's terms and sent from Program access (D1120, D4805),
and written to the same canonical table there (D5048).

### 2. The merge schema is namespaced

`agreementMergeValues` fills only namespaced keys: `licence.*` and `terms.*` (the master agreement's own values,
D803), `entity.*` (legal name, brand, registered address), `signer.*` (name, title, email), `program.*`,
`grant.*` (each term as the schedule prints it, plus the grant's state and terms revision), `package.*` (key,
name, version) and `agreement.*`. No flat key is produced, so a template still using one (`{{brand_name}}`)
leaves it standing; the readiness names it under `non_namespaced_fields` and the send is refused. A value
nobody recorded is null and the field stays visible (`renderContract`, D110), never blanked.

### 3. The send, reusing D4671

1. **Draft** (`POST /licences/:uid/drafts`): the template's **current** version and the values as they stand
   are rendered once and stored on the version: `title`, `body_md`, `body_sha256`, `template_version`,
   `merge_values_json`, `unresolved_fields_json`, `counsel_review`. Status `ready` when nothing is unresolved and
   a signer is on file, else `draft`. A draft or ready version of the same slot is superseded by it (kept as
   history); a version out for signature is not, and the draft is refused until it is voided.
2. **Preview** (`GET /:uid/preview`) answers the stored body and hash, and whether the body still hashes to it.
3. **Send** (`POST /:uid/send`, naming the revision read): refused unless the stored body still hashes to
   `body_sha256` and carries no `{{field}}` (D4671's two checks), and a signer is on file; then the **stored**
   body goes to `createAndSendEnvelope` as a rendered body (D416), the same e-sign infrastructure as every other
   legal document. The envelope that comes back must carry the same hash, or nothing is linked (an envelope
   already pending for that signer and document, built from other text). The link is one guarded statement
   (`revision`, `status in (draft, ready)`, no envelope yet) with its history line, through `runDecision`.
4. **A send that loses** (another send, a void, a new draft won first) links nothing and voids the envelope it
   made, so that envelope can execute nothing.
5. **Completion** (`onAgreementEnvelopeCompleted`): the version naming the envelope becomes executed with its
   signed copy's hash and date, superseding the slot's earlier executed version in the same batch. A version
   voided or superseded meanwhile records that it was signed and keeps its status.
6. **Never rebuilt.** Nothing after the draft reads live data: a later template version or a changed licence
   reaches only a new draft (test 3). The migration's trigger freezes the title, body, values, unresolved list and
   counsel marking once sent, beside D5048's freeze of the template, version and hash.

**A send racing a signature cannot replace the executed document:** a draft is refused while a version is out;
a void is one statement that loses when a signer has begun signing (test 5); an executed version is superseded
only by the execution of its replacement (test 6); its signed hash and date are set once (D5048's trigger).

### 4. Readiness

`readinessOf` (on every draft, preview and refused send) names: a missing template; missing entity fields;
missing signatory fields (including no licence administrator to send to); missing package, program, grant and
licence terms; every unresolved field; the ad hoc flat keys among them; and whether counsel review is required.

### 5. Owner questions

1. **Counsel review.** Every package and program template is marked "counsel review required" in the
   readiness, and the marking does not block a send (the licence contract's rule, D803). Should it block?
   - **A.** Informational, as now, until counsel signs off each template; then drop the marking per slug. *(My pick.)*
   - **B.** Block the send (add the slugs to `COUNSEL_REVIEW_SLUGS`, which D4811 refuses).
2. **Library rows for the catalog.** The fourteen slugs are not seeded into `legal_templates`; Contracts lists
   them only once HQ authors them.
   - **A.** Leave them unseeded; `GET /api/admin/licence-agreements/templates` shows which are missing. *(My pick.)*
   - **B.** Seed empty stub rows so the library lists them as stubs to fill (needs a category for them: today's
     four are gp, fund, portfolio, compliance).
3. **Package values.** No package store exists until #5021. A draft may name `package_version` (and a
   `package_offer_uid`), which fill `package.version`; any other package term reads "Not recorded", so a template
   using one cannot be sent before #5021.
   - **A.** Keep that: HQ names the version on the draft, other package terms wait on #5021. *(Built; my pick.)*
   - **B.** Refuse package drafts entirely until #5021's store exists.
