### What a period freezes now

The overview chart (IF0) and quarterly history (IF5) plot only what an issued
period froze. Before this, most bars were hatched, because the snapshots lacked
most figures. Each issue path now freezes the following.

**A GP's own issue** (`POST /api/funds/:id/report-periods` with `issue: true`)
freezes the manager's page as before. It adds these to `totals`, each as
`<key>_cents` and `<key>_reason`, with a null amount always carrying a reason:

- `called`: every capital-call line of the fund's LPs dated on or before the
  period end. It uses `amount_cents`, else the dollar amount in cents.
- `collected`: every capital-call receipt of the fund received on or before the
  period end.
- `nav`: the pack's own working, `fundFigures(...).nav`, for the period. It
  stays Not recorded, with the pack's reason, until books, valuations and the
  Fund's bank account allow it.
- Deployed stays `invested_cents`, the positions' invested amount. The owner
  confirmed on #6801 that Deployed is not `vc_funds.deployed_capital`.

It also adds a top-level `sector_mix`.

**The reporting queue's pack** (`lp_quarterly_report/1`) already carried
`totals.called_to_date`, `totals.receipts_to_date` and `fund_figures.nav`. It
now also carries:

- `totals.deployed`, a line `{ cents }` or `{ cents: null, reason }`;
- `sector_mix`.

The schema name is unchanged, because the change only adds keys.

**`sector_mix`** is `{ basis, items: [{ sector, invested_cents, position_count }] }`:

- It is the positions' invested amount, grouped by the sector recorded on each
  company (`projects.sector`, trimmed).
- A company with no sector is its own row with `sector: null`, always last. It
  is never dropped, so the rows sum to deployed.
- A fund with no positions has `items: []`, and deployed is null with "No
  positions are attributed to this fund."

### Frozen at issue

The figures are worked when the period is issued, or when the pack is built,
and stored in the row. Money recorded later moves the next period, never this
one. A failed read refuses the issue as Unreadable.

Periods issued before this change keep what they hold. Their snapshot has none
of the new keys, and the read returns none, never a zero. There is no backfill
unless the owner asks for one.

The issued-period read (`GET /api/funds/:id/report-periods/:periodId`) passes the
new keys through when they are present. It checks each figure as it checks
committed and invested: a non-cent amount, or a null without a reason, is
Unreadable. A malformed sector row is Unreadable too.

### For the frontend (#6801's `fundOverviewModel.js`)

`periodFigures` hard-codes called, collected and NAV as absent for an
`issue_snapshot`, and deployed as absent for a `report_pack`. To plot the new
figures, it reads them like this:

- In an `issue_snapshot`, called, collected and NAV through the same
  `own('called' | 'collected' | 'nav', …)` helper it already uses for
  committed. The fallback reason applies only when the key is absent.
- In a `report_pack`, deployed as `line(t.deployed, …)`.
- In both shapes, `snapshot.sector_mix` for the IF5 sector chart.

That change belongs to #6801, which is still open, or to a follow-up. This
issue does not edit that file.
