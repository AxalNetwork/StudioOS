## D4623 part 2 — The multi-licence Studio and Lab, finished: investor figures for a held licence, a desktop Account anchor, a historical match average and Apply in the Lab block (#4623)

- **Status:** Part 2 of #4623, the final part. Built 2026-11-12 by slot S25 on part 1 (D4623, PR #5198) and #4474 (D4474, PR #5152), in the order of S1's notes of 2026-11-09 23:26Z and 23:50Z.
- **No migration. No new route. No new `/api/*` client method:** `GET /api/dashboard` takes one new query parameter, and `api.getDashboard` one new argument.
- **No licence switcher and no active-licence toggle.** Nothing here chooses a licence for the member. The block page asks for the Investor block's own figures because that block is the Investor licence's.

### What was decided

1. **`GET /api/dashboard?licence=investor` computes the investor figures for a held Investor licence that is not the primary one** (`cloudflare-worker/src/routes/dashboard.ts`).
   - Before, every figure came from `users.role`. D4474 recorded the effect as "Not recorded". Reading the route showed it was worse: the figures were computed with the primary licence's lens. A Founder-primary member's Investor block counted their own projects as "Deals in flow". An Advisor-primary member's counted the whole tier 1/2 marketplace, without the investor's findability filter (D702) or the Trust Center mask.
   - With the parameter, the role the route computes with (`viewRole`) is `investor`. The member then gets exactly what a primary investor gets: the eligible total and its masked preview, the match average, the recommended syndicates, and `role_view: 'investor'`. `user.role` in the payload stays the member's own.
   - The lens is the caller's own licence only, read from `user.licences` (`holdsLicence`, hydrated by `requireAuth`, D4472/D5058):
     - a member who does not hold Investor is refused with 403 `licence_not_held`, never served another licence's figures;
     - an admin is refused too, because an admin is never on a block page (D4474) and keeps the admin payload;
     - any other value is refused with 400 `invalid_licence`.
   - For a primary investor the parameter changes nothing, and with no parameter the payload is unchanged for everyone. `Dashboard.jsx`, the single-licence Studio and the path for an admin preview and an impersonation, still calls `api.getDashboard(fresh)`.
   - A figure that is truly missing is still null: no match score gives `ai_score_avg: null`, and a failed deal read gives `total: null` with `source_status.deals: 'unreadable'` (D4620). The home draws both as Not recorded or Could not be read, never 0.
   - The cache key gains a `:investor` segment only for the lensed payload of a non-primary holder. Every other key is unchanged, so the founder payload and the investor payload of one member never share an L1 or KV entry.
   - `MultiLicenceStudio` asks with `api.getDashboard(false, 'investor')`. It reads the summary only when Investor is held, as before.
2. **The desktop Account button carries `data-tour="account-menu"`** (`App.jsx`, `UserDropdown`), so the tour's Account step points at it on desktop instead of explaining from the centre. The founder's phone band already carried it, and only one of the two headers is ever mounted (D699).
   - The anchored copy said "Your initials open the Account menu". The desktop button shows the member's name, not initials, so the copy is now "This button opens the Account menu", which is true of both. The page-level copy ("under your name at the top right") is unchanged.
3. **The quick stats' "Avg AI match" says it is historical** (`investorStudioParts.jsx`). It averages the same `match_scores` rows the score module labels Historical (D4623 §6), so a recorded average reads "Historical · 75", in the same words the score rows use. The label and test ids are kept.
   - A member with no score reads Not recorded. The reason no longer says "yet", because nothing calculates a new score: "No historical match score is recorded for you. The matching engine that wrote them is retired."
   - A failed read still reads "Could not be read" and is not marked historical. The deal-flow total is not historical and is not marked.
4. **The Lab block tells `SpinoutLabPage` it is not the investor view** (`MultiLicenceSpinoutLab.jsx`, `SpinoutLabPage.jsx`).
   - `SpinoutLabPage` takes an optional `investorView`. Left undefined, the page keeps today's rule, `user.role === 'investor'`. That covers a single-licence member, an admin preview, an impersonation and the route's own `<SpinoutLabPage />`.
   - The Lab block passes `investorView={false}`. The block is drawn for Founder, Advisor and Operating Partner, and Investor has its own block. So an Investor-primary member who also holds one of those gets the Apply call to action in the Lab block. The LP section is no longer drawn there a second time. The page is not forked.
5. **The multi-licence blocks were verified**, in tests and in a browser:
   - a block's thrown error, or its summary read failing, leaves the other blocks drawn;
   - single-licence, admin-preview and impersonation sessions keep today's pages.

### Departures, and why

- **D4474 said the non-primary Investor figures read Not recorded.** They were computed with the wrong lens (see 1). The fix is the same either way: compute them with the investor lens.
- **The tour copy changed** (see 2). Pointing the Account step at the desktop button made its "initials" wording untrue there.

### Not decided here, and UNVERIFIED

- **Apply for an Advisor or Operating Partner who does not hold Founder.** `POST /api/spinout-lab/apply` accepts only a Founder holder or an exploring account (`holdsLicence(user, 'founder') || user.role === 'exploring'`). An Investor-primary member who also holds Advisor, as S1 asked, now gets Apply in the Lab block. Their submission is refused there, as it is today for a single-licence Advisor, who also sees Apply. Whether Advisor and Operating Partner should be offered Apply at all is a separate question, and it is unchanged here.
- **The block page's tour has no `role`.** `MultiLicenceStudio`'s `<ProductTour>` passes none, so its Studio step uses the founder's purpose line for every member, an Advisor-primary member with Investor included. It was seen in the browser check and left for a follow-up: choosing one licence's line for a page of several is a copy decision.
- **The Investor block's Usage & quota tile** reads "Quota data is available only to the signed-in investor account" for a non-primary Investor (seen in the browser check). It is `InvestorQuotaBars`' own rule, not this route's, and is left as it is.
