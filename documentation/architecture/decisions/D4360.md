### 1. One banner, no second gate

The frame is D1463's `AccessPill`, which reads "Read only · HQ access" for the Super Admin and "Read only · Studio admin access" for an admin (`ui/reasonGate.js` `accessWord`). Portfolio and Incorporate are not among D1463's gated records (the narrative, the cap table, the data room and Capital relationships), so there is no `ReasonGate` on either page. A test fails if one of the three pages imports it.

### 2. Portfolio (PF7's admin frame)

- **When.** An admin (`profile` `admin`) or HQ (`hq`) opens a company or project in which they hold no seat (`hqReadOnly(profile, member)`):
  - a company: no row of theirs in its members;
  - a project: no `my_role` in its members read (an owner always has one, so Make it a company is never offered to a locked viewer).
- **What it draws.** The access pill beside the page's badges, and "Read only. Its members make the changes here." followed by the admin line "Switching company does not narrow what you see as an admin. Your studio's reach comes from its licence.", which stays.
- **What it hides on a company:** Company settings, New project, + Add project, Edit in Legal and the document uploads. The member actions (Make active, Rename, Invite, Transfer, Archive, Restore, Leave) already needed a seat.
- **What it hides on a project:** Project settings, Edit, Make it a company and Or move it under an existing company. The last two are hidden even when the Worker answers `can_manage` for an admin.
- **While loading.** An admin's writes stay hidden until the members read says they hold a seat. The pill is drawn once it does not.
- **Unchanged.** A member, and an admin with a seat, see no pill and keep every write.

### 3. Incorporate (INC5g)

- **Where.** The member's `/api/legal/incorporate/*` routes are owner-scoped, so HQ reads an order through its own list of paid orders (`GET /api/admin/incorporations`, D601, `requireAdmin`).
- **The address.** `/incorporate?order=<id>`, linked as "Open in Incorporate" from each row in Lab › Formation. It applies only when the viewer is an admin and the id is digits; anyone else gets the member's flow unchanged.
- **What it draws:**
  - the access pill;
  - the order's status timeline (Submitted, Packet ready, Filed);
  - "Read only. “Pay and submit” is hidden while HQ reads this order." with the admin line.
- **No writes.** "Pay and submit" is not drawn. `IncorporationTimeline` gains `readOnly`, which hides Add EIN and the bank step.
- **States:** Reading…; "This order could not be read." with Try again; an order not in HQ's list reads "This order is not among the paid formation orders HQ can read."
- **Back.** "‹ Formation orders" returns to `/admin/programs/spinout-lab/formation`.
