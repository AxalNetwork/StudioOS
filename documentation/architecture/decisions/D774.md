## D774 — The Admin's boards draw the new rail: a rail on every board but the Spin-Out Lab's, and one frame for `/admin`'s tabs

- **Status:** decided by S1 for the owner, 2026-10-19 (#2100; rollout M4 of D720 §11, #1874). PR 1 (#2140) wrote §1; the last PR wrote §2 and §3, and closes the issue.
- **The boards:** the canvas's `Admin` profile (`design/incoming/airail-every-page-data/canvas.json`), numbered S1–S39 in the canvas's own order. Frontend paths are relative to `frontend/src/`.

### 1. The missing rails and the inventory (PR 1, #2140)

1. **The inventory is `lib/railOptions/admin.js`.**
   - **`ADMIN_BOARDS`:** one row per board, giving its route, its files, and the file that mounts its rail.
   - **`ADMIN_OPTIONS`:** empty. No control on the 39 boards runs a model.
   - **`ADMIN_QUIET_CONTROLS`:** the controls that run no model, each with why:
     - Due diligence's "Generate report", which the Worker assembles from the case's recorded sections;
     - the DD NDA upload;
     - the network-profile photo upload.
2. **`pages/admin/AdminBoardFrame.jsx` is the rail on the fourteen boards that have a page of their own and drew none:** S3, S4, S8–S11, S15–S18, S22, S23, S31 and S39.
   - It is a `RailFrame` with a `WorkerRail` named for the board.
   - The rail takes the viewer's tier: HQ's for a Super Admin, the admin's otherwise.
   - A viewer outside the admin tier gets none. That is Due diligence's partners, investors and advisors, who are listed in `NO_RAIL_ROUTES`.

### 2. `/admin`'s tabs (shared frame from D775 §8, #2183)

1. **One frame for the whole of `pages/AdminPage.jsx`.**
   - #2183 added the shared `AdminBoardFrame`; D774 keeps it, rather than adding another wrapper.
   - `tabBoard(tab, role)` reads the board from D768's `pageFor('/admin', role, { search: '?tab=<tab>' })` and names the rail by its module.
2. **The one frame serves both profiles:**
   - the Admin's S2 Users, S6 Identity checks, S7 Entity profiles, S28 Wellbeing experts, S29 Advisors and partners and S30 Directory;
   - the Super Admin's H11 Users, H22 Personas, H23 Advisors and partners, H24 Directory, H27 Integration keys, H28 GitHub sync, H29 Payments catalogue and H30 Promo codes.
3. **Off-canvas tabs draw the page alone.** Billing, Bank accounts and a tab the viewer's profile has no board for get no rail, as decided in D775 §8.
4. **A host that locks the console to one section (`section`) gets the page alone.** It composes the console under a page, and a rail, of its own.
5. **H21 Assessment Studio draws this profile's existing frame.** Its route is S22 Assessment runs', which the canvas lists first. `railOptions/superAdmin.js` lists that frame as H21's rail, and the eight tabs above with `host: 'pages/AdminPage.jsx'`.
6. **The rail's crumbs and a run's page key come from the shell's provider (`ui/railCrumbs.js`), which reads the URL.**
   - On a bare `/admin` with no `?tab=`, the rail's name is Users, because that is the tab drawn.
   - The provider's key is `Admin console` until a tab is picked, because a pick writes `?tab=`.

### 3. The Spin-Out Lab stays rail-less (D317)

1. **S12 Spin-Out applications, S13 Spin-Out moderation and S20 Spin-Out Lab draw no rail.** D317 keeps Eadwyn out of the Lab, and `workspace_frame_contract.test.mjs` guards it.
2. **`NO_RAIL_ROUTES` lists `/admin/spinout-lab`, `/admin/spinout-lab/preview` and `/admin/spinout-moderation` with that reason.** The boards keep their page keys, so canvas parity holds.
3. **`/admin`'s Spin-Out Lab tab draws the page alone.** The shared `tabBoard` returns null, preserving D775 §8's exclusion.
4. **`admin.js` gives each of these boards `noRail` with the reason.**
5. **A rail there would be a new task for the owner.**
