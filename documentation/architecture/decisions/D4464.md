## D4464 — Network book filters and relationship summary (#4464)

Carries items 1–2 of the #3701 specification's D1429, which was never recorded on main. This change adds Worker reads and client methods only; the Network canvas and Research collection filter are separate work. No migration is needed.

`GET /api/contacts/book` accepts `source=linkedin_csv|csv|typed` and `follow_up=open`. Owner-bound EXISTS predicates constrain both rows and totals, alongside search and pagination. A source is provenance in `contact_sources`, not the contact's legacy source column. Unknown or empty filter values answer 400 `invalid_filter`.

`GET /api/relationships/summary` refuses support sessions and returns the caller's effective sharing, distinct teammates sharing eligible relationships through a current common team, and introduction counts. Team visibility follows `whoKnows`, including per-team withdrawals overriding a global share. Pending introductions are counted on the caller's side; made introductions count either participant once, using `made_at` in the last 90 days.

Numeric fields retain the specified response shape. Companion `recording` metadata is keyed by dotted field path, with `{ recorded: true }` for readable values. A failed read yields null for its fields and `{ recorded: false, reason }`; other readable fields remain available. The response is HTTP 503 with `error: relationships_unreadable` when any group fails. Database internals are never returned. No failed statement becomes zero.

The existing contacts client's `book(q, page)` gains an optional third filter argument; `relationshipsApi.summary()` calls the mounted authenticated route. Tests cover source provenance, open versus completed/foreign tasks, combined filters, totals and pagination, invalid values, membership/sharing withdrawals, caller-only requests, support refusal and failed reads.
