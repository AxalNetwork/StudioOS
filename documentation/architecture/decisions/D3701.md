## D3701 — Research v2: a Research Project from question to brief, evidence first (#3701)

- **Status:** canvas landed 2026-11-07 (`design/incoming/Research v2 Page.dc.html`, `design/incoming/Research v2 · Boards.dc.html`, boards RS01 to RS12 and spec boards RSA to RSC), drawn from the canonical V2 prompt in #3701 (comment 6707874262). It supersedes the earlier Research canvas for the same tracker. Not built.
- **Builds on:** `research.ts` (documents, ask sessions and answers, brief notes, market readings, drafts, company, fund and market directories), `research_collections.ts` (D549), migrations 213–230.
- **Migration:** needed for the Research Project object if built; none for the frontend-only parts.

### What the canvas decides

- **Navigation:** Overview · My Research · Markets (Geographies inside) · Companies · Funds · Library · Ask. Diligence and Benchmarking open from a company or fund.
- **Every page** has one breadcrumb, one title, one purpose line, one violet primary action and optionally Ask Eadwyn.
- **Research Project** (proposed): question → evidence → Ask sessions → findings → comparisons → brief, persisting across Markets, Companies, Funds, Library and Ask.
- **Findings** are labelled Source fact, Eadwyn interpretation (dashed, Accept / Edit / Discard) or Your conclusion. Each numbered citation opens its exact passage with document, date, freshness and availability. Conflicting sources are flagged.
- **Missing values** read Not recorded, never zero; no chart is drawn without a time series; no composite score.
- **Library** separates Index state from Answerable in Ask.
- **Ask:** answer first, then sources with passages, follow-ups, Save finding / Add to brief. History is All / Saved answers / Archived. Seven response states are kept apart.
- **Research context rail** (project, coverage, open questions, findings, comparison set, follow-ups); AI settings collapsed; billing in Account › Usage.

### Existing vs proposed (checked 2026-11-07)

- `research_documents.index_state` is pending · indexed · unsupported · failed; Indexing, Partially indexed and Unavailable are proposed.
- No sharing (own uploads only), so “shared but not answerable” is proposed.
- Ask `reason` is answered · no_source · model_unavailable; Search unavailable, Insufficient evidence and Source no longer available are proposed.
- Research Project, finding kinds, the sectioned brief, the structured run (no authoritative cost quote exists: it reads “Cost quote unavailable”) and Send to module (no receiving endpoints) are proposed and tagged on the boards.

### Built (part 1, 2026-11-08)

Part of #3701: Library (RS-06, RS-10C) and Ask's response states (RS-07C), from data the platform already records. No Worker route, no migration, no API method.

1. **One state module.** `frontend/src/pages/research/researchStates.js` names three things once:
   - the index state (Indexed, Partly indexed, Queued, Unsupported, Failed);
   - answerability (Answerable, Partly answerable, Not answerable, with the reason);
   - Ask's response states.

   An index state it does not know reads Not recorded. Library, and Ask's "What Ask can reach" table, both draw from it.
2. **Library (RS-06):**
   - The heading is "Evidence Library" with the canvas's purpose line.
   - Index state and "Answerable in Ask" are separate columns. The index-state pill used to say "Answerable", so the two read as one fact.
   - Answerability reads only the Worker's `in_ask`. A client's indexed document therefore reads "Indexed" beside "Not answerable · Indexed in their library, not yours."
   - A Failed row gives its recorded reason under the name and offers **Retry**, which is the existing re-index.
   - An Unsupported row gives its reason and says to replace the file. It offers no Retry, because reading it again reads nothing again.
   - The amber row tint is gone. The canvas keeps amber for contradictions.
3. **Phone (RS-10C):** below the `sm` breakpoint the rows are cards. Each card shows both pills, the type and the date added, the reason, and a full-width 44px Retry on a failed row.
4. **Ask response states (RS-07C):** each exchange carries its own state pill: Answered, No relevant source found (with Add evidence), Search temporarily unavailable (Ask again), Model unavailable (Try again), or Source no longer available.
   - **Source no longer available** is derived, not stored. It applies when an answer cites a document the library read no longer lists, and it is said only when that read succeeded. The answer stays as written.
   - **No answerable documents** is the zero-source page Ask already had (RS-07B). It applies to a row only when the row records `indexed_documents = 0`.
   - The amber tint on every non-answer is gone. Amber is the canvas's colour for Insufficient evidence.

**Departures from the canvas:**
- **Search temporarily unavailable is built, not proposed.** It is `retrieval_unavailable`, which D4605 added before this canvas was drawn. The canvas's RS-A board and the "Existing vs proposed" list above call it proposed, and that is stale. Its retry keeps the existing "Ask again" label.
- **Insufficient evidence is still not drawn.** The Worker has no such outcome, so the state is defined, marked `proposed`, and never assigned.
- **Library columns:**
  - Owner and Updated are not columns. Every owned row is "You", and a client's document already carries its "From …" mark.
  - Kind and Source year stay as columns, because the canvas's Type column is the file type and the store records the document's kind.
  - The canvas's "…" menu is not built. Open, Edit, Re-index and Remove stay inline.
- **Library header and filters:**
  - The violet Upload document and Ask Eadwyn header buttons are not built. Upload stays in the page's upload card.
  - The filters stay the zone's existing chips, not the canvas's four dropdowns kept in the URL.

### Built (part 3, 2026-11-09)

Part of #3701: Ask (RS-07), with one Worker change. No migration, no new route, no API method.

1. **Worker first: a citation keeps its passage.** `citationOf` (`routes/research.ts`) now stores `passage`, the first 600 characters (`CITATION_PASSAGE_CHARS`) of the text the model was given for that citation, and `passage_truncated`.
   - It goes into the answer's citations JSON (migration 221), so `POST /api/research/ask` and the session history both return it.
   - The answer and its citations are read only by their owner, about the owner's own document.
   - An answer recorded before this change has no passage, and the page says "Passage not recorded for this answer." rather than inventing one.
2. **Heading:** "Ask Eadwyn", with the canvas's purpose line and the existing "answers only from documents you have added" line kept.
3. **Composer:** labelled "What do you want to know?".
4. **Sources used · N:** under each exchange that has citations, each source shows:
   - its number, title and passage number, linked to the document;
   - its page;
   - **Available** or **No longer available**, from a library read that succeeded and never when that read failed;
   - the passage as a quote.
5. **Copy with citations**, on an answered exchange: the answer, then each numbered source with its page and passage as recorded. A browser that refuses clipboard access gets a message.
6. **History tabs:** This session · All · Saved answers · Archived. They set the same view the toolbar chips set. Archived is the discarded disposition (D549).
7. **Evidence scope**, collapsed: "Ask only uses documents in your Library that you're allowed to use." The "What Ask can reach" table sits inside it.

### Built (part 4, 2026-11-09)

Part of #3701: RS-11's "You're out of AI tokens", which needed one Worker fix first. No migration, no new route, no API method.

1. **Worker: a refused run is not a model failure.** Before this, `POST /api/research/ask` treated every run that produced no answer as `model_unavailable`. That includes runs the router refused before starting them: out of AI tokens, a spend limit, a review hold, the org kill switch, or the guard.
   - It stored those as an answer reading "The model didn't respond", which sent the reader to try again rather than to Add tokens.
   - Now a refused run is answered by `refuseRun` (D766), the same 402 in the budget's own words that every other press gets. Nothing is stored, and nothing was charged.
   - A model that ran and failed is still `model_unavailable`, with its passages, as before.
   - Retrieval's embedding is a system call (`userId 0`) and is not charged to the member. A member with no tokens left still retrieves, and only the answer is refused.
2. **Ask:** a 402 draws RS-11's amber card: "You're out of AI tokens", the budget's sentence, "Your history stays readable, and nothing was charged", and **Add tokens**. The button opens the Add tokens sheet (`openAddTokens`, D1288) over the page, from "Research › Ask". Any other failure keeps its own message.
3. **Founder desk:** the same card under the question, with Add tokens (from "Research"). It is a secondary button, so the header keeps its one violet primary.

**Departures from the canvas:** none for this state. The rest of RS-11 is either already built or proposed:
- **Already built:**
  - No evidence and Ask unavailable (part 1, D4605);
  - Indexing queued, Indexing failed and Source unavailable (part 1);
  - the Unreadable block (part 2);
  - Not recorded throughout.
- **Proposed:**
  - No research projects;
  - Upload in progress, because the upload is one request with no progress events;
  - Partial index and Shared source not answerable, which the canvas itself marks as proposed;
  - Cost quote unavailable, which belongs to the structured run;
  - Permission denied;
  - Empty search and Filters with zero results, which belong to the directory zones and come with RS-03 to RS-05.
