## D8771 part 3 — Pitch › export: the export history, the states around an export, and what is announced (#8771)

- **Status:** built 2026-11-27 (#8771, slot S12), on top of part 2 (`D8771-p2.md`, #8804). Canvas: `design/incoming/Pitch Export Disclosure Page.dc.html`, boards PTX05, PTX06, PTX07 and PTX11.
- **Owner answers used:** option A for Q1, Q2 and Q4, as part 2 built them (owner, 2026-11-27: "option A is accepted for every open question"). Q3 was answered **no**: exported files are not stored, Download again works only while the dialog is open, and exporting the same version again with the same settings is a new export. This part builds to that answer: no history row offers a stored file.

### Built

- **Export history (PTX07).** `ExportHistory` in `ExportDisclosure.jsx`, folded under "Export history (n)" in the dialog. It lists the rows `GET /api/decks/:id/exports` already returns (the venture's newest 50): when (UTC), version, format, copy, speaker notes, Sources appendix, fingerprint (first six and last four characters), who, and the file.
  - A row from before part 2 recorded the settings says Not recorded for the copy and both settings, in italics with a hollow circle, never "Not included" (`historyRows`).
  - The File column says "File not kept" (Q3, no). Only the row whose fingerprint matches the file this dialog just made offers Download again, which saves those same bytes again.
  - The line under it counts the rows and explains Not recorded when an older row is listed (`historyFoot`).
- **History states (PTX06).** An unreadable history says "The export history could not be read. Exporting still works." with Try again, which reads it again. It never reads as "No export recorded yet". A confirmed empty history keeps the last-export line's "No export recorded yet." and draws no empty table.
- **Exporting (PTX06).** While an export runs, the copy picker, format, version, both settings and the acknowledgment are disabled, and a status line says "Exporting PowerPoint of v7. The settings and version are locked until it ends."
- **Completed export (PTX05).** The panel's first line is now a heading that takes focus when the export finishes (PTX11). Once the ledger read returns the row with the file's fingerprint, the panel adds "Recorded Thu 26 Nov, 14:20 UTC · by …" (`recordedLine`).
- **Failure (PTX06, PTX11).** Focus moves to Try again. The settings are kept, as part 2 built.
- **Announcement (PTX11).** Changing the copy or either setting says, politely and off-screen, what goes into the file: "Investor copy. Speaker notes not included. Sources appendix included, page 13." (`copyAnnouncement`). Nothing is said when the dialog opens. The visible copy line is no longer a live region, so it is not announced twice.
- **Phone (PTX11).** Under 640 px the preview folds under one 48 px line that opens it, such as "13 slides · 16:9 · notes not included" (`foldLine`). From 640 px it is always open.

`ExportDialog.jsx` changed only in these places: the imports; the header comment; the announcement and failure-focus effects; `disabled={busy}` on the copy picker, format buttons, version select, both checkboxes and the acknowledgment; the exporting status line; the history's place under the last-export lines (the old "could not be read" text moved into `ExportHistory`); the `ref` on Try again; and the `recorded` prop on the completed panel.

### Not built, and why

- **The investor-link preview link (PTX05, PTX08).** `main` still has no route that previews an investor link's recipient view of a version. The cross-check across Present and the link preview stays with S21's browser verification (#8795, #8777).
- **The real-app fixture check (PTX09 ◇).** Opening the fixture in PowerPoint, Keynote, Google Slides and a PDF reader needs a person in those apps. Until one records results against a fingerprint, they are Not recorded.
- **Read-only (PTX06).** The dialog has no read-only mode to show. Who may export is decided where Export is offered and by the Worker's own check, and this part does not change that.
- **The preview's slide-list stop in the focus order (PTX11 stop 7).** The preview has no thumbnail strip, so there is no "one stop, arrows move between slides". The rest of the tab order follows the dialog's DOM order.
- **Export another copy (PTX05 footer).** After a finished export, the dialog's controls stay usable for another export, so no separate button was added.
- **Storing the writer's report on the ledger row.** As part 2 said, the acceptance does not need it.
