## D584 — The 83(b) deadline is computed in one place, and does not roll until counsel says so

**The 83(b) filing deadline is the 30th calendar day after the grant,
computed by one pure function, `electionDeadline` in
`services/section83b.ts`.** It does not move off a Saturday, a Sunday or a
holiday. Whether it should is a question for counsel, and nothing changes
until the owner posts counsel's answer on #1211. Slot S08, issue #1211,
2026-10-06, from the owner's answer on #1009 ("The 83(b) weekend roll";
D361). No migration.

### What is true

- `POST /api/legal/83b/trackers` (`routes/legal_83b.ts`) stores
  `deadline_date`. Before this change it was `addDaysISO(grantDate, 30)`,
  written in the route. It is now `electionDeadline(grantDate)`, which
  returns the same date.
- `ELECTION_WINDOW_DAYS = 30` names the window.
- `tracker83bDto` still derives `days_left` and `overdue` from the stored
  `deadline_date`, so no stored row and no response changes.
- `LAB_JURISDICTIONS` still says "Filed within the 30-day IRS window", which
  stays true.

### The question for counsel, still open

When the 30th day is a Saturday, Sunday or legal holiday, is a filing on the
next business day timely for an 83(b) election (the IRC §7503 question)? And
which holidays count?

**Until counsel answers, the earlier date stays.** It is never later than
the real deadline, so a founder who files by it is never late.

### If counsel says the date rolls (not built)

1. `deadline_date` stays the 30th day. The DTO adds the rolled date, computed
   at read time by a function beside `electionDeadline`, so no stored row
   changes.
2. `days_left` and `overdue` follow the rolled date.
3. The 83(b) page shows the 30th day and, when it moves, the date it moves
   to, in counsel's wording.
4. The dev-only FastAPI mirror is not ported.

This file will then quote counsel's answer.

### Verified

- **`cloudflare-worker/test/section83b_deadline_d584.test.ts` (3 tests).**
  - It covers grant dates whose 30th day is a weekday, a Saturday, a Sunday,
    Christmas Day, and a date across a year end and across February in both a
    leap and a non-leap year. Each one is the 30th day, unrolled.
  - The route stores `electionDeadline`'s date and computes no deadline of
    its own.
- **`legal_83b.test.ts`.** A new test shows a tracker whose 30th day is a
  Saturday is stored as that Saturday. The existing create test still reads
  grant plus 30.
- **Mutations:** 7 of 7 caught. They were a 31-day window, rolling Saturday
  and Sunday, rolling Sunday only, rolling Christmas, a wrong base date, the
  route computing its own deadline, and the route moving the Saturday case.
