### 1. The rules (part 1, `services/ai/guard.ts`)

Pure code, with no `env`, binding or D1, tested on fixtures in `test/ai_guard_d763.test.mjs`.

1. **Every text is checked in full, slice by slice.** `sliceForGuard` cuts at most `GUARD_SLICE_CHARS` (2,000) characters per slice:
   - after the last paragraph break (a blank line) inside the slice;
   - else after the last sentence end (`.`, `!` or `?`, any closing quote or bracket, then whitespace), so "3.14" or "e.g.x" is not a cut;
   - else at 2,000.

   The slices join back to the text exactly, and an empty text has none. A 5,000-character text with no breaks is three slices, so three guard calls.
2. **The verdict.** `parseVerdict` reads Llama Guard's answer:
   - `safe` alone;
   - or `unsafe`, then one line of S-codes (`S1`, `S1,S10`), read in order and once each; a code it does not know is dropped.

   Anything else is `unreadable`: empty, prose, extra lines, or a code without `unsafe`. `unreadable` is a failure of the guard and **never counts as safe**.
3. **The category policy** is one table, `GUARD_CATEGORIES`, Llama Guard 3's own numbering:

   | Codes | Action |
   | --- | --- |
   | S1 violent crimes, S2 non-violent crimes, S3 sex-related crimes, S4 child sexual exploitation, S5 defamation, S8 intellectual property, S9 indiscriminate weapons, S10 hate, S11 suicide and self-harm, S12 sexual content, S13 elections, S14 code interpreter abuse | block |
   | S6 specialised advice, S7 privacy | log, do not block: legal, cap-table and diligence drafts legitimately trip them |

   `decide` turns one slice's verdict into `pass`, `log`, `block` or `fail`. An `unsafe` with no code we know blocks. `combine` joins a run's slices: any `fail` fails, else any `block` blocks, else any `log` logs.
4. **The copy** (`GUARD_COPY`, `refusalFor`) is in Eadwyn's voice, in the first person, and never names a category or a code.
   - Input refused: "I can't help with that request. If you put what you need another way, I'll try again."
   - Output withheld: "I wrote something I can't show you, so I've held it back. Try asking another way."
   - Guard unavailable: "I can't check this right now, so I haven't run it. Try again in a minute."
   - S11, on either side: "It sounds like things might be heavy right now. I'm not the right help for this, but you don't have to carry it alone." A founder or an admin also gets the link to `/wellbeing` ("Open Wellbeing"). Everyone else gets the same words without it, because the page refuses them (`frontend/src/App.jsx`, the `/wellbeing` route's guard).

### 2. The hooks in `run()` (part 2)

In `services/aiRouter.ts`. Tested on a stubbed `env.AI` and the real budget tables in `test/ai_guard_d763.test.mjs`.

1. **Which runs.** Every run but two: the guard's own (`task: 'safety'`), and a system embedding (`userId <= 0`, `embed`). A system run of any other task is checked too; it has no hold, so the guard's cost goes to the KV spend buckets as the run's does.
2. **The input check** runs after the hold is taken and before the model is called, so a budget refusal is answered before `guard_unavailable` can be.
   - It checks the text the member typed or supplied for the run, in full. The caller says which text that is with `RunOptions.guardText`. Without it, the guard checks every message the run sends except the system prompt, or `text`.
   - A handler that puts rows gathered from the member's own store into the prompt (Eadwyn's connector data, a conversation's earlier turns) passes only the member's words, so those rows are not checked again.
   - A transcription has no text input to check.
   - A cached task looks in the cache only after the input has passed. So a cached answer never skips the input check, and what the cache holds was checked on its output before it was written.
3. **The output check** covers every text output, in full, before it is returned, streamed or stored. An embedding has no text output.
   - **Streamed runs** (`releaseChecked`): the Worker gathers the model's text and releases it one checked slice at a time, as Workers AI's own `data: {"response": …}` events. Unchecked text never reaches the reader, so "withheld" is true. A refused slice ends the stream with one `data: {"refusal": …, "message": …}` event and `[DONE]`.
   - The Worker reads ahead of the reader by up to a slice, to check it. So a run whose reader stops early is settled on what the model produced and the Worker read, not only on what was released (this narrows D762 §3's "what they were sent").
   - **The member's own material** (`guardOutput: 'mark'`, and every transcription): an unsafe verdict marks the text (`guard.output: 'marked'`) and is logged, and the text is kept. Any run that later uses it is checked again on its input. A guard that cannot read it also keeps the text.
   - **Images:** the text prompt, and any text output. **A text guard cannot read an image**, so the image itself is not checked.
4. **Fails closed.** Three refusals join `RefusalReason`:

   | What happens | Refusal | What is charged |
   | --- | --- | --- |
   | The guard can't be reached, throws, or answers `unreadable` | `guard_unavailable`. On the input side nothing runs and the hold is released; on the output side the output is withheld | Every guard call that completed, and the model if it ran |
   | The input is unsafe | `guard_blocked` | The guard |
   | The output is unsafe | `guard_blocked_output`: the output is withheld | The guard and the model, which both ran |

   A slice is checked by one call with a 16-token answer and the chat class's 8 s limit. Slices are checked four at a time, and a side stops at the first batch that blocks or fails.
5. **One hold.** The guard runs inside the run's own reservation and settles there; it never takes a hold of its own.
   - The quote (`guardQuoteMicro`) adds the guard on every input slice, and on every output slice the run's maximum output allows. Each slice is bounded by its characters plus 1,024 template tokens in and 64 tokens out. An output token is taken as at most eight characters, and a transcript as at most 2,000 characters a minute. Two consecutive slices always cover a full window, so at most `2 × ⌈chars / 2,000⌉ + 1` slices are quoted.
   - The hold settles at the model's cost plus every guard call's. A hold that charged nothing for a run that did not answer is a refund.
   - Each guard call is its own `ai_usage_logs` row (`task 'safety'`, its verdict in `safety_score`, its share in `charged_microusd`, the run's `reservation_uid`). Its `guard_for` is the run's own row, on the same page, option, record and surface. The run's row records the model's share.
6. **The routes.** Three call the guard once, through `run()`, and their answers to a block keep their shape (`error: 'safety_block'`, 422, each route's own message), mapped from `guard_blocked`. Their clients do not change.
   - `routes/advisor.ts` `/explain` (`guardText`: the topic);
   - `routes/ai.ts` `/workspace/explain` (`guardText`: the coverage lines);
   - `routes/eadwyn.ts` `/conversations/:uid/ask` (`guardText`: the question and the attached file's text).

   The fourth, `/advisor/answer`, stores the member's typed value without calling a model, so `run()` never sees it. It keeps `classifyInput`, which now checks in full, slice by slice, under the category policy, and **fails closed**. A guard that cannot answer stops the write with 503 `guard_unavailable` and the guard's words, rather than calling the value unsafe.

   A withheld output or an unavailable guard answers with the guard's words (`error`), and a `link` on S11 for a founder or an admin.
7. **`loadGuardrailCounters`** gains `guard`: per page (`rail_page`) and for today, the guard's checks (safe, unsafe, unreadable) and what they caused (blocked inputs, withheld outputs, guard unavailable). The guard's rows are `task = 'safety'` rows with a verdict, so `verdicts` counts them too.
8. **`GUARD_CATALOGUE`** (`services/ai/guard.ts`) is `{ every_run: true }`, for `GET /api/ai/catalogue`'s `guard`. That route is D760's (#2017), which has not landed; it serves this constant. So the rail's guard sentence (D769) cannot ship before the code that makes it true.
