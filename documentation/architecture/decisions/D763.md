### 1. The rules (part 1, `services/ai/guard.ts`)

Pure code, with no `env`, binding or D1, tested on fixtures in `test/ai_guard_d763.test.mjs`.

1. **Every text is checked in full, slice by slice.** `sliceForGuard` cuts at most `GUARD_SLICE_CHARS` (2,000) characters per slice:
   - after the last paragraph break (a blank line) inside the slice;
   - else after the last sentence end (`.`, `!` or `?`, any closing quote or bracket, then whitespace), so "3.14" or "e.g.x" is not a cut;
   - else at 2,000.

   The slices join back to the text exactly, and an empty text has none. A 5,000-character text with no breaks is three slices, so three guard calls.
2. **The verdict.** `parseVerdict` reads Llama Guard's answer:
   - `safe` alone;
   - or `unsafe`, then one line of S-codes (`S1`, `S1,S10`), read in order and once each; a code it does not know is dropped.

   Anything else is `unreadable`: empty, prose, extra lines, or a code without `unsafe`. `unreadable` is a failure of the guard and **never counts as safe**.
3. **The category policy** is one table, `GUARD_CATEGORIES`, Llama Guard 3's own numbering:

   | Codes | Action |
   | --- | --- |
   | S1 violent crimes, S2 non-violent crimes, S3 sex-related crimes, S4 child sexual exploitation, S5 defamation, S8 intellectual property, S9 indiscriminate weapons, S10 hate, S11 suicide and self-harm, S12 sexual content, S13 elections, S14 code interpreter abuse | block |
   | S6 specialised advice, S7 privacy | log, do not block: legal, cap-table and diligence drafts legitimately trip them |

   `decide` turns one slice's verdict into `pass`, `log`, `block` or `fail`. An `unsafe` with no code we know blocks. `combine` joins a run's slices: any `fail` fails, else any `block` blocks, else any `log` logs.
4. **The copy** (`GUARD_COPY`, `refusalFor`) is in Eadwyn's voice, in the first person, and never names a category or a code.
   - Input refused: "I can't help with that request. If you put what you need another way, I'll try again."
   - Output withheld: "I wrote something I can't show you, so I've held it back. Try asking another way."
   - Guard unavailable: "I can't check this right now, so I haven't run it. Try again in a minute."
   - S11, on either side: "It sounds like things might be heavy right now. I'm not the right help for this, but you don't have to carry it alone." A founder or an admin also gets the link to `/wellbeing` ("Open Wellbeing"). Everyone else gets the same words without it, because the page refuses them (`frontend/src/App.jsx`, the `/wellbeing` route's guard).

### 2. The hooks in `run()` (part 2)

To be written by part 2's PR. It hooks these rules into `services/aiRouter.ts` `run()`:
- the input check after the reservation;
- the output check before anything is returned, streamed or stored, with a stream released one checked slice at a time;
- the three refusals `guard_unavailable`, `guard_blocked` and `guard_blocked_output`, all failing closed;
- the guard held and charged inside the run's own hold, with `guard_for`;
- the four routes' own `classifyInput` calls removed;
- `loadGuardrailCounters` per page;
- `GET /api/ai/catalogue`'s `guard: { every_run: true }`.

**A text guard cannot read an image.** For an image run, the guard checks the text prompt and any text output. The image itself is not checked.
