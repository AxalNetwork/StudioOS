## D630 — Deal rooms: join and leave with the quota, the Invitations, Transfers and References tabs, and closing a syndicate

**Issue:** #1388, part of #1165 (the Ops canvas, area 6). **Built by:** S07.
**No migration:** every store already existed.

The Ops canvas (`design/canvases/integrated/ops-data.js`) draws six screens.
Each is built into the page that already serves its address:

| Board | Screen | Built into |
|---|---|---|
| D1 | `dr-pipeline` | `/deals` (investor): a Deal rooms panel under the bucket board (`components/deals/DealRoomsPanel.jsx`) |
| D2 | `dr-header` | `/deals/:dealId`: Join or Leave, the quota and the join note, for an investor (`DealRoomPage.jsx`) |
| D3 | `dr-invites` | the deal room's Invitations tab, admin (`DealInvitationsTab.jsx`) |
| D4 | `dr-transfers` | the deal room's Transfers tab, admin and partner, with "Record a transfer" (`DealTransfersTab.jsx`) |
| M5 | `sp-references` | the deal room's References tab, admin and investor (`DealReferencesTab.jsx`) |
| F3 | `sy-close` | the company's syndicates on Overview, each closed from its drawer (`DealSyndicates.jsx`) |

No new address. The canvas's `/deals/[deal]/invitations` and its siblings are
tabs of `/deals/:dealId`, which is how the deal room already draws its other
four. The words each screen uses are in `components/deals/dealRoomCopy.js`.

### Worker changes (first, in the same PR)

- **`GET /api/deals/dealroom/quota`**, registered before `/:id`. It returns:
  - `used` and `cap`, or `unlimited` with `cap: null` when the plan has no cap;
  - `full`;
  - `tier`, `upgrade_to`, and `upgrade_cap` (the next plan's cap from
    `INVESTOR_QUOTAS`, or null when it is unlimited);
  - `member_deal_ids`.

  The cap and the count are the join's own (`dealroomCap`, `dealroomsUsed`,
  moved out of the join), so a quota that reads full is a join that is
  refused. The count covers every firm, because that is what the join counts.
  The member list is narrowed by the active firm, the same way the deal list's
  `is_member` is.
- **Every write records its actor in `activity_logs`**
  (`services/dealRoomAudit.ts`), with the deal or syndicate in
  `entity_type`/`entity_id`. The writes are:
  - join;
  - leave, only when a membership was removed;
  - recording a transfer;
  - inviting an investor;
  - each reference write (schedule, edit, consent, delete);
  - closing a syndicate.

  None of these is an admin-only action, so they do not use `logAdminAction`,
  which also writes the admin audit log.
- **`GET /api/networkfx/syndicates?project_id=`.** `syndicates.deal_id` holds a
  **project** id: the create form on the Network page offers projects, and
  `GET /syndicates/:id` reads the id back from `projects`. The filter is named
  for what the column holds.
- **Closing a syndicate refuses in sentences:**
  - `syndicate_not_found` (404);
  - `syndicate_close_forbidden` (403), for anyone but its creator or an admin;
  - `syndicate_already_closed` (409).

  Funded closes like Open.

### Where the build departs from the canvas, and why

- **The quota counts every firm; Join/Leave is per firm.** An investor in two
  firms who joined a room under the other one sees Join here, and that join
  answers `already_member`. This is the deal list's existing reading, kept.
- **"Email requested", not "Email sent".** `deal_invitations.email_opt_in`
  records that an email was asked for. The send goes through `notify`, and its
  result is not stored on the invitation.
- **The firm is not a form field.** The Worker takes it from the company
  switcher (D467) and refuses with `transfer_firm_required` when the recorder
  is in several firms and none is chosen. The refusal reads "No firm given".
- **The open-conditions refusal says "commit room", not "Conditions tab".**
  The deal room has no Conditions tab. IC conditions are resolved in the
  commit room (`/deals/commit`).
- **References offer no upload, transcribe or summarise.** The Worker stubs all
  three with 501, so each row reads "Not available yet" three times.
  - An edit may set Scheduled or Cancelled only. Recorded, Transcribed and
    Summarised would claim a recording that cannot exist yet, though a row
    already in one of them keeps it.
  - Consent is recorded with "Record consent" (`POST /references/:id/consent`).
  - `components/ReferenceChecksPanel.jsx`, which drew the stubbed controls,
    was never mounted and is left as it was.
- **No AI rail on these screens.** `dr-pipeline` and `dr-invites` draw an
  Eadwyn rail, but no surface for either is allow-listed. A band whose run
  could only fail is not drawn.
- **Search and filters.** The pipeline panel searches company and sector. The
  tabs list every row: a deal room's invitations, wires and references are a
  short list.

### States

Each screen draws four states:
- loading;
- empty, with the canvas's sentence;
- "Not recorded", with its reason beside it rather than behind a hover;
- "Unreadable", with "Try again".

A failed read never renders a zero or an empty list. Lists stack to one column
below `md`, which is the 390-wide layout.
