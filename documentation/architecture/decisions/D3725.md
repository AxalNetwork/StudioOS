## D3725 — The Eventbrite syndication adapter, built against a mock and switched off until the owner's app exists (#3725)

- **Status:** built. Switched off. The live check waits on the owner adding Axal's Eventbrite organisation and
  app (#1008).
- **Owner's answer (2026-11-16, option B):** build the Eventbrite adapter now against a mocked Eventbrite API,
  kept switched off until the owner adds the organisation and app. The only step left for the owner is the
  account step.
- **The switch.**
  - The adapter is a row in `SYNDICATION_CHANNELS` with `enabled(env)`, which is true only when both
    `EVENTBRITE_CLIENT_ID` and `EVENTBRITE_CLIENT_SECRET` are set.
  - `syndicationChannel(key, env)` answers null while it is false. The HQ screen then reads "Not available
    yet", connect is refused 409 `adapter_not_ready`, and a queued listing fails with "This channel has no
    adapter yet, so nothing was sent." That is exactly what happened before the adapter existed.
  - Adding the two secrets is the whole switch. Removing them switches it off again.
- **What a listing is (Eventbrite v3):**
  - It connects by OAuth to the one organisation the signing-in account owns. More than one organisation
    stops the connect rather than guessing which.
  - It creates an event under that organisation (`POST /v3/organizations/:org/events/`), then calls
    Eventbrite's own `POST /v3/events/:id/publish/`. That is an HTTP endpoint on Eventbrite, not Axal's
    publishing, so D1319's walk stays green.
  - Edits go through `POST /v3/events/:id/`, and cancel and unpublish through `POST /v3/events/:id/cancel/`.
  - Name and description are HTML-escaped. Times are UTC without milliseconds. A missing end becomes start
    plus one hour, with a preview warning. An address is described in the text; no Eventbrite venue is
    created.
- **Axal stays the only ticket ledger** (owner decision E). The listing is externally ticketed
  (`is_externally_ticketed`, `external_ticketing.external_url` = the event's Axal link), and the description
  ends "Register on Axal: <link>". `imports_registrations` is false: no attendee is ever read.
- **`verified_on` stays null.** The request shapes follow Eventbrite's v3 documentation and are tested against
  a mock only. Two things must be checked live before the date is set:
  - that the account can create externally ticketed events (`is_externally_ticketed` may be limited to
    partners);
  - that Eventbrite passes OAuth's `state` back.

  If external ticketing is refused, the fallback is a free ticket class whose description sends people to
  Axal. That needs the owner's word, because Eventbrite would then hold registrations.
- **Two code changes around it:**
  - `ChannelError` moved to `channelError.ts` and is re-exported unchanged, so the adapter imports it without
    an import cycle.
  - A test's registered fake now replaces a real row, so tests that fake `eventbrite` still do.
- **Guard:** `cloudflare-worker/test/eventbrite_syndication_3725.test.ts`, with `fetch` mocked:
  - switched off without both secrets;
  - the authorize URL and the code exchange, and a refusal when there is more than one organisation;
  - create, then Eventbrite's publish, externally ticketed with escaping and UTC;
  - update and cancel by id, with an unreadable id never reaching the network;
  - a 429 with `Retry-After`, and no token in any error;
  - preview warnings;
  - end to end through the job: switched off sends nothing; switched on posts once, and a repeat posts nothing
    more.

  `event_syndication_d1490.test.ts`'s "Part A ships no adapter" line now pins that the only real adapter is
  Eventbrite, unverified and switched off. Mutation-checked: removing the switch, ticketing on Eventbrite,
  and dropping the id check each fail a test.
