## D4559 — Platform capacity from Worker-native reads first; missing is never zero (#4559)

- **Status:** part 1 built (inventory, metric dictionary, read-only capacity route); part 2 built (daily snapshots, trend and projection, stored alert episodes); part 3 built (signals from #4592, #4593 and #4558). Account analytics and the screen wait (see below).
- **Context:** #4559 asks for platform health, capacity and cost signals across the Cloudflare services, extending existing monitoring and not duplicating #3851's agent ledger. The account-level metrics need the GraphQL Analytics API and a token whose scope is unverified.
- **Decision:**
  1. The inventory and metric dictionary live in `documentation/operations/PLATFORM_OBSERVABILITY.md`, built from `wrangler.toml` and the code that reads it.
  2. The first slice reads only through bindings the Worker already holds: D1's `meta.size_after` (bytes) and `Queue.metrics()`. It is `GET /api/admin/platform/capacity` on HQ · Platform, Super Admin only, no account API, no token, no personal data.
  3. A source that does not answer is `unavailable` with a reason, `value: null` and level `unknown`; the overall level is never `ok` while one is unknown. An empty queue is `none_waiting`, not an age of zero.
  4. D1 thresholds default to 5 GB (review) and 7.5 GB (migration assessment) against a 10 GB limit, decimal bytes, overridable by whole-byte deploy variables that must keep warning < critical ≤ limit. These are policy triggers, not Cloudflare limits.
  5. No screen is invented: no canvas covers it (`AGENTS.md` § Missing UI).
- **Consequences:** HQ can read capacity today without a new secret or vendor. Request, query-latency, Workflow and R2 metrics stay listed as unavailable until the owner confirms an analytics token scope. Alert deduplication needs stored levels, which the next slice (a daily snapshot) adds.
- **Part 2 decision (daily history and alerts):**
  6. A daily snapshot (04:11 UTC, HQ only) keeps one row per deployment metric per day in `platform_capacity_snapshots`; an unreadable day is NULL with `unavailable`, never 0. Only the capacity read's fixed keys are stored, so no tenant usage reaches it.
  7. The D1 projection is a straight line through measured days only. It names a month, never a day; it states its window, points used and R²; its confidence is at most `medium`; with under seven measured days, no growth, or a limit over five years out it names no month.
  8. Alerts are stored episodes (`platform_capacity_alerts`), at most one open per metric by a partial unique index. A raised level changes the open episode's severity in place; a measured ok clears it; an unreadable source holds it and never clears it. A source measured in the last 48 hours that stops answering opens an `unavailable` episode. Hysteresis is fed the open episode's severity.
  9. Notices go in-app to active HQ Super Admins, deduplicated per episode and stage; a mute (1–168 hours, reason required, write bar, audited) stops notices, not tracking or clearing.
- **Part 3 decision (signals other issues record):**
  10. Signals are read where their issue already writes them, through bindings only: the agent sweep's `agent_sweep_*` and `agent_repair_*` rows in `system_metrics` (#4592, #4593) and the restore drill's marker in `BACKUPS` (#4558, through `readRestoreDrill`). No table, store, vendor, migration or outbound call is added. Each signal states its source, window, sampling, unit, scope and `last_success_at`.
  11. A newest sweep batch older than 20 minutes (four 5-minute sweeps) is `unavailable`, with the time it was written. A source that throws, hangs or never recorded is `unavailable`, never 0.
  12. The sweep records `eligible` 0 when it stops before discovery (halt, engine off or paused, manual autonomy). Its batch now carries a `scanned` label, and the eligible count and age are trusted only from `scanned: true`; otherwise they are `not_running`. The admission counts are the sweep's own, and a real 0.
  13. Two availabilities: `not_running` (the subsystem is off here: level `ok`; it holds an open episode, opens none and never clears one) and `not_verified` (a failed or absent restore drill: `critical`, never an age).
  14. A repair age is reported only while a repair is still owed after the sweep, or the sweep hit its 20-run cap; a sweep that settled everything it found owes nothing.
  15. Thresholds: eligible-work and repair ages 1 h / 6 h (proposed); the last verified restore warns at 32 days (the Security page's existing rule) and is critical at 64 days (proposed).
  16. #4572, #4568, #4571 and #4556 shipped no record the Worker can read (a contract, a build-time ratchet, a GitHub Actions log line, and an uncalled gateway path). They are listed in `not_read_here` with their reasons, not invented. #4591 and #4594 are open and not read.
