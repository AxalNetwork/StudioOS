## D4598 — Pitch: the check before sending reads the version that is sent, and a viewer's events land on their own link (#4598)

- **Status:** Built for #4598, 2026-11-07. Part 1 of the package: the preflight gate and the attribution of view, timing, click and reaction events. The rest is listed under "Not done".
- **Builds on:** D1370 (#3661, the preflight and its gate), D1573 (#3820, per-card analytics), D1500 (card uids), D1545 (hidden cards and button clicks), D902 (the share dialog).
- **No migration. No new route.**

### What was decided

1. **The gate before Share and Export checks the saved version (`PitchEditor.jsx`).**
   - Share and Export send the saved version. Before, the gate checked the working deck, so unsaved edits that fixed a defect cleared a saved version that still had it ("Checked with your unsaved edits. The link and the export carry the saved version until you save one.").
   - With no unsaved edits, the working deck is the saved one, and the one check serves both, as before.
   - With unsaved edits, the gate runs a second `usePreflight` on the saved version's own cards and theme. The panel ("Check before you send") keeps checking what is on screen. The second run borrows the first's dismissed set (`dismissedFrom`), so one version has one set and is read once.
   - The gate says which version it read: "v3 · the saved version that will be sent". With edits it adds: "You have unsaved edits. This check read the saved version, not your edits: the link and the export carry the saved version. Save a new version to send your edits, then check again."
   - With edits, the gate offers **Save a new version…** (it closes the gate and opens the save dialog) and drops Show me, because a finding's card place belongs to the saved version, not to the cards on screen. Saving is the founder's own step. The next Share or Export then checks the new version.
   - The check is bound to the version it read: a result for another state reads "Out of date" and runs again, as the hook already did (`currentResult`).
2. **Export's version picker (`ExportDialog.jsx`).** The gate hands the dialog the version it read. If the founder picks another version, the dialog says "v2 was not checked. The check before you export read v3." It does not block: the picker is the founder's choice, and the sentence is the visible difference.
3. **A viewer's events name only their own link's visit (`deck_share_actions.ts`, `decks.ts`).**
   - A view id sent with a heartbeat, a click, a feedback form, a sign-up, an NDA signing or the deal pack is accepted only if that view belongs to this link and this deck (`ownView`; the heartbeat checks the same).
   - A view id from another link or deck changes nothing of that view: no read seconds, no seconds per card, no signals. The event itself is kept on this link, under no view.
   - A heartbeat that names another link's view answers `{ ok: false }` and writes nothing.
4. **A reaction is filed on the card the link sent at that place (`/share/:token/feedback`).** The place is read against `linkSentCards`, the list the reader and the click route already use: the link's variant order, less hidden cards and what the link leaves out. Before, it indexed the version's stored cards, so a reaction on a tailored link, or on a deck with a hidden card, landed on another card.
5. **Time per slide still holds.** A link with it off stores the visit count only, as before.

### Not done in this part

- **The effective content the link will send.** The gate runs before the share dialog, where a variant and what the link includes are chosen. So it reads the saved version, not the link's variant or its appendix choice. Checking the link's effective content needs the choice made first.
- **A check inside the Export and Share dialogs** when the picker or the variant changes. The dialog says the version was not checked; it does not run a check.
