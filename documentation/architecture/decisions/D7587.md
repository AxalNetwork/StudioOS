## D7587 — Customer research Email and recording Start recovery (#7587)

The owner's mobile report exposed two separate failures. Read-only Workers
telemetry showed mail context returning 404, and recording Start failing with
the platform's cross-request promise lifetime error. No live interview content
or credentials are part of the reproduction or public evidence.

The investor, advisor and exploring role safety nets cached pending D1 work by
binding. A later request could therefore await a promise whose creating
request had ended. These bootstraps now cache only completed readiness by
binding. Each request that encounters an unready binding runs its own existing
idempotent safety net; there is no pending I/O shared across requests. Existing
schema/rebuild logic, success-only readiness and binding separation remain.
Concurrent cold requests can repeat the safety-net statements until readiness
is recorded; this change adds no DDL, migration or configuration flag. Atomic
users-table rebuild behavior remains in its existing helper. The column guards
being repaired in #7554 are a separate change, not ported here.

The authenticated HQ Super Admin may now request the mail pack for an
interview whose Customer research record the existing record gate admits.
Ordinary admins remain restricted to assigned cases, and a branch cannot gain
HQ elevation. The exception is interview-only. Admin company items and live
blocks remain excluded; raw transcripts remain excluded from the pack. No
interviewee address is guessed, no Network address-sharing gate is bypassed,
and the mailbox and send confirmation rules are unchanged.

A recording Start failure with an opaque generic server sentence now explains
how to recover. Its existing refusal card offers Back to session, which reads
that same session rather than creating another or automatically retrying an
uncertain write. Known consent and active-session refusals retain their own
words and destination. The failed attempt releases its microphone without
removing queued audio or claiming that all recording data was saved.

Regression coverage includes real workerd requests after an abandoned
bootstrap for all three safety nets; completed readiness reused only for the
same binding; the mounted mail route over migrated synthetic SQLite, including
ordinary-admin, JWT-spoof and branch denial; and recorder/navigation tests for
microphone release, retained local audio, explicit recovery and no automatic
retry. No production record is changed and no live recording is started by
verification. Merge/deployment and an owner check of the reported sessions are
still required before claiming the production errors are resolved.
