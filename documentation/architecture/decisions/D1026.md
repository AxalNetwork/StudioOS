### 2. Access (CT13, CT16a), `AccessTab.jsx`

**Who sees what** is drawn from `GET /api/captable/access/:id/grants`. Each row has:
- the person or holder, their relationship and their level;
- who granted it, since when, and when they last viewed it;
- for a grant from a signed side letter, the line "Rights: from a signed side letter · [level] level".

One line under the table says what the venture's own rules give without a grant (D1019 §3): the owner, co-founders, advisors and studio admins.

**The owner changes it, each change in a dialog:**
- **A level:** five choices, with the Worker's own sentence for each (`levels` on the grants read). "Save level" stays disabled until the level is different.
- **Share with a holder:** a holder the saved model names, so a level's view can find the holder (`holder_ref`).
- **Revoke:** the grant stays on file.

**Levels:** the five, in the Worker's words, plus None's "Sees nothing."

**Share links**, from D1019's links read:
- each with its label, level, expiry, views ("3 of 25") and last view;
- Revoke, in a dialog.

**New link** asks for:
- a level: Summary, Investor or Full;
- a label;
- an expiry, 1 to 2,160 hours;
- a view limit, 1 to 500;
- for Investor and Full, the attestation "The holders named here agreed to their positions being shared." Create link stays disabled without it.

What the level shows is the Worker's sentence. The link is shown once, as its full address, and never listed again.

**Access log:** newest first, with "Show older" (D1019's `before` cursor) and "No IP address is kept." A support open carries its reason.

**A co-founder reads all of it and changes nothing.** The grants read says `can_change: false`, so no control is drawn, and one line says why: "You are a co-founder: you read who sees what, and only the owner changes it."

A refusal (403) says so where the block would be, never "nobody".

### 3. Import and export (CT14), `ImportExportTab.jsx`

**From Carta**, from `GET /api/captable/live?project_id=` (D1020 §3), in one of three states:
- not connected, with Connect Carta;
- connected but not this venture's record, or the record for another venture. "Make Carta this venture's record" opens a dialog that says the rows move, then sends `PUT /api/captable/carta/venture`.
- the record, read only, with the last sync, and a line when the last sync reported a problem.

**From a spreadsheet** (`capTableImport.js`):
- **The template** downloads with the columns already named: Holder, Type, Class, Shares, Amount, Price per share, Date.
- **A file:** CSV with quoted fields, a byte-order mark and CRLF, up to 500 rows (the Worker's cap). It is read in the browser and only sent when the founder presses Propose.
- **The column map:** guessed from the words people use, and editable.
- **The preview** checks each row against D1017's record:
  - **Red, left out:** no holder; a type that cannot be read; shares or an amount missing; a fraction of a share; a class not on the record; a grant outside a pool, or shares inside one; a date that is not `YYYY-MM-DD` or "3 Jan 2025". An ambiguous date such as `1/2/2025` is never guessed. An exercise, a transfer or a cancellation needs more than one row says, so it is left out too.
  - **Amber, proposed:** a row that changes a holder's recorded shares in a class, with the count on record.
  - **Left out, not counted twice:** a row that matches the record exactly. This departs from the canvas sample, which counted such a row; accepting it would double the holding.
  - Filters: All rows, Errors and Changes.
- **"Propose [n] rows"** opens a dialog, then sends the rows that propose to `POST /api/captable/record/:id/proposals/import` (§5). **Imports land as proposals, never on the record**: each waits for the owner's Accept.

**From Mercury** draws D840's part, the one Overview draws (`MercuryRaiseFeed`), from the module read's `parts.mercury`. Only the owner's own read carries it, so anyone else reads one line saying so.

**Export:**
- **Cap table (CSV):** D1020's register export.
- **Cap table and history (spreadsheet):** §5.
- **The snapshot to the data room:** D1020's, in a dialog that says it is filed under NDA and seen by nobody until shared.

Each export is audited on the Worker, and its refusal is said where the row is.

### 4. The reads for everyone but the founders (CT17, CT18), `SharedCapTable.jsx`

**`/cap-tables/:projectId`** (Admin, Advisor, Operating Partner) reads `GET /api/captable/access/:id`. The page draws the `via` and `level` the Worker answers, never a role it guessed:
- **An Advisor (CT17a):** the Summary unless the founder granted another level: the split by group and the number of rounds, naming nobody.
- **An Operating Partner (CT17b):** the level granted, with "Shared with you at [level] level. You can read it; you cannot change it." Scenarios stay the founder's, and a line says so.
- **An Admin (CT18a, b):** the group summary and "Open for support…". The dialog asks for a reason, 10 to 500 characters, that the founder sees, then `POST /api/captable/access/:id/support` opens the full table read only, under the lavender line "You are viewing this cap table as a studio admin, for: '[reason]'. The founder sees why, and each correction." A correction is part 2's correction, with its own reason.
- **The Super Admin (CT18c):** the full table read only, and the access log across companies (`GET /api/captable/access/log`). Opening for support is not offered.
- **Anyone the founder has not shared it with:** the Worker's sentence, "The founder has not shared the cap table with you."

**`/share/captable/venture/:token`** is the venture link D1019 §6 left for this part. It is public and shows the view at the link's level. A spent, expired or invalid link says so in the Worker's words. The route sits before the older `/share/captable/:token`.

**The views share one drawing** (`SharedViewBody`, from `sharedView` in `capTableAccess.js`), so a link and a grant at the same level show the same thing:
- Summary: the split and the rounds;
- Investor and Full: the positions after the last round, and the rounds with their price;
- Own position: the holder's own rows, instruments and the split;
- no model saved: the Worker's sentence, never an empty table.

A missing percentage is "Not recorded", never 0%.

**Not here:** the links that open `/cap-tables/:projectId` from the Advisor's Practice, the Partner's Delivery, the Admin's Accounts and HQ's Support pages. Part 14 (#2866) retargets every link #2432 lists. D1019's proposal to narrow the old routes' admin path waits for that move too.

### 5. Two Worker routes this part needed (`routes/captable.ts`, `services/capTableRecord.ts`)

**`POST /api/captable/record/:projectId/proposals/import`** takes `{ file_ref, rows }`:
- **Who:** anyone who may propose (the record's write gate and the Raise + Grow plan). An admin's import carries a reason.
- **`file_ref`** is the file's SHA-256, so one file's rows are proposed once: each row's `origin_ref` is `<file_ref>:<row>`, held by D1017's unique index. A file imported again is 409 `already_imported`.
- **Every row is checked before any is written.** One that fails refuses the import with its row number ("Row 2: …"), and nothing lands. Rows are `origin: 'import'` and `source: 'document'`.
- **One audit row** for the import: `captable.import.proposed`.

**`GET /api/captable/record/:projectId/export.csv`**, behind the record's read gate:
- the record's issuances (every status, a void with its reason, an admin's reason), then the history, newest first;
- a missing value is an empty cell, and a formula is neutralised (`csvCell`, D1020's);
- one audit row, `cap_table_record_exported`, written before the file is answered: no audit row, no export (D1020 §4).
