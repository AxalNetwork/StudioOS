## D8421 — Stage evidence from job records, and what the records say about capacity (#8421)

The CI capacity pool gets a calculator for what a stage actually did: `scripts/ci/capacity-stage-evidence.mjs`.
It reads provider job records and reports running jobs, machines, waits and completions, and it judges a stage
against explicit limits. It reads only. It changes no limit, workflow, coordinator or executor file, and it
approves no machine, spend or activation.

Running it on real hosted CI records found an error in D8333, which this change corrects.

### 1. What it measures

A record is one job attempt in the GitHub jobs API shape. The same shape describes a hosted job and a pool
executor job.

| Measure | Meaning |
| --- | --- |
| Running | A job counts only while it held a runner. A job cancelled while it waited has start and end stamps and no runner; it is counted as never run. |
| Peak and sustained | The peak is one instant. Sustained is the highest number of jobs that stayed running, without a break, for a whole window (30 minutes unless set). |
| Offered | What would have been running had every job started when it was created. It is a floor: cancelled waits have no duration and are left out. |
| Registrations, machines, jobs on one machine | Counted apart. Each runner name is its own machine unless the caller supplies the mapping, which is right for hosted runners only. |
| Overlap | How long at least two machines were busy together, and how many machines stayed busy for the window. |
| Waits, completions, attempts | Creation to start; completions in whole clock hours; attempts after the first and outcomes. |

### 2. The stage verdict

A stage file states its limits; a missing or inconsistent one is refused. Three capacities stay separate:
configured slots, approved running jobs, and demonstrated running jobs.

| Verdict | When |
| --- | --- |
| `stop` | The peak passed the approved number; a machine ran more jobs than its recorded slots, or several with no slots recorded; retained reservations grew; cleanup left residue; API budget use passed its limit. |
| `below_target` | The target was never reached. |
| `burst_only` | The target was reached and did not hold for the window. |
| `incomplete` | It held, and a limit was missed (p95 wait, failed attempts, machines busy for the window) or a required fact was not recorded. |
| `demonstrated` | It held for the window inside every limit, with every required fact recorded. |

Four facts cannot come from job records: API budget used, whether retained reservations grew, whether cleanup
left residue, and whether a cost figure was recorded. The verdict never assumes one. Demonstrated capacity is
the sustained level, capped at the approved number, and zero for any other verdict.

### 4. Correction to D8333

D8333 §2 reported 147 suite shards running at once and 142 minutes at 60 or more. Both were wrong. The first
measurement counted 281 suite jobs that were cancelled while still waiting (198 in the merge queue, 83 on pull
requests) as if they had run; their "durations" were their waits. The true peak is 60, with 4 minutes at 60.
D8333's table, its demand paragraph and the model's `MEASURED` record are corrected in place, and every figure
there now comes from this tool. The enforced limits and the ten findings are unchanged. The Worker shard
median moves from 25.4 to 26.0 minutes, so finding 7 (the 25-minute external lease) stands.

### 6. New findings

11. **The hosted ceiling is the bottleneck today.** Evidence in section 3. It sets the value of the pool: slots
    beyond 60, not a replacement for them. Owner: operator, to confirm the plan limit. Informs every stage.
12. **Two external parts a request is the limit that binds the first useful stage.** `maxExternalWorkerShards`
    above 2 is refused (`ciCapacityPolicy.ts`), so eight requests move 16 jobs, plus one included. The eligible
    work is 30 at its half-hour level and 60 at its peak. Raising the bound to the shard count under reviewed
    configuration lets 48 slots carry the merge queue's Worker shards with no change to the request count.
    Owner S39. Blocks a useful result after the pilot.
13. **The deployment package is cut from a superseded revision.** S37's archive and manifest name `8c11fb864c34`.
    Since then `merge-control/src` changed in 17 files (+1,117, −64) and `scripts/ci` in 14 (+1,011, −47), and
    `documentation/operations/runner-image-8008/qualification-progress.json` still names `8c11`. The package
    and the progress record need recutting from the revision chosen for the pilot. Owners S37 and S31. Blocks
    the pilot.
14. **A per-minute API limit may bind before the hourly budget.** At 15 calls a request every 15 seconds, 15
    active requests make 900 calls a minute. GitHub documents a secondary limit on requests per minute; its
    figure could not be read from this session. Owner S39, with finding 3. Blocks expansion.
