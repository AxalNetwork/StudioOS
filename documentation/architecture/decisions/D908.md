### 1. The decision

**One sentence has one home.** A section's words live where the deck already keeps them, so the deck and the narrative never disagree:

| Section | Its words live in | Longest |
| --- | --- | --- |
| Problem | the version's deck row `problem.framing` | 600 |
| Solution | `narrative_sections.body` | 4000 |
| Why now | `narrative_version_meta.why_now` | 2000 |
| Market | deck row `market.assumptions` | 600 |
| Traction | deck row `traction.takeaway` | 600 |
| Business model | `narrative_sections.body` | 4000 |
| Competition | deck row `competitive.whitespace` | 600 |
| Team | `narrative_sections.body` | 4000 |
| The ask | deck row `ask.title` | 300 |
| Closing line | deck row `deal.closingLine` | 600 |

`narrative_sections` holds one row per (venture, version, section): its place, its audience note, its provenance, and the words only of a section the deck has no key for.

**Version 0 is the live deck.**
- It is read-only here. A write answers 409: "Version 0 is the live deck's wording. Change it in the deck, or in a saved version."
- It has no section rows, and it reads the core positioning.

**Positioning.** The venture has a core (`version` NULL). A version may adjust any field with its own row, and a field it does not adjust reads the core.
- Kinds: `one_liner` (200), `elevator` (1200), `line`, `category`, `wedge`, `for_whom` and `instead_of` (300 each).
- `line` holds up to 20 entries by `position`. Every other kind holds one, at position 0.
- Clearing a version's field (`text: null`) falls back to the core.

**Bindings** carry D896's five fields: `source_key`, `record_ref`, `as_of`, `grade` and `snapshot_hash`.
- `grade` is one of `Measured`, `Reviewed`, `Sourced` or `Stated`; "Not recorded" is never stored as a grade.
- `snapshot_hash` is 24 hex characters.
- A section holds at most 20 bindings, and each write replaces that section's set.
- **S15, please confirm these names against D896.**

**Eadwyn's wording carries no number.** A write whose source is `eadwyn` and whose words hold a digit answers 400: "Eadwyn's wording carries no number. Insert the figure as a bound figure instead."

**Provenance** follows #2431's contract:
- `source_kind`: `eadwyn`, `connector`, `module`, or NULL for typed by hand;
- `source_label`: `connector`, `document`, `recorded`, `signed` or `typed`, and NULL for an Eadwyn value;
- `prior_value`, `undone_at`, `undone_by`.

New words typed by hand clear the source. A change of note or place alone keeps it.

**A store that failed is unreadable, never empty.** Each part of a read is `{ state: 'ok', … }` or `{ state: 'unreadable' }`. A route that cannot read at all answers 503 with `code: 'unreadable'`.

**Saving a version based on another** (`start_from: 'version'`) copies that version's section rows, bindings and positioning overrides. Fills that were undone are not copied.

### 2. Routes

All of these live in `routes/cycle_raise.ts`, behind `scope()` (`?project=`, `canWrite`: the venture's founder (`ownsVenture`) or an admin).

| Route | Answers |
| --- | --- |
| `GET /api/cycles/raise/narrative/:version` | `{ version, meta, sections: {state, items}, positioning, bindings: {state, items} }`; another venture's version answers 404 |
| `PUT /narrative/:version/sections/:section` | body `{ body?, audience_note?, position?, source?, bindings? }`, at least one of them; an unknown section answers 404 with the `sections` list |
| `GET /narrative/positioning?version=` | `{ version, core, overrides, effective }` |
| `PUT /narrative/positioning?version=` | `{ kind, position?, text, source? }`; no `version` writes the core |
| `GET /narrative/compare?a=&b=` | per section and positioning field, `not_recorded`, `same` (ignoring whitespace) or `changed` |

**Logging.** Every write logs one `logCycleWrite` row with cycle `raise` and module `investor-narrative`:
- the actions are `narrative_section_saved`, `narrative_positioning_saved` and `narrative_positioning_cleared`;
- the summary names the version, the section or field, and what changed;
- it never holds the words, a figure or an investor's name.

A write to a section stored in the deck or the meta runs that version's check again (`runCheck`).
