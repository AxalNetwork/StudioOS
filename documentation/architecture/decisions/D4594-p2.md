### 1. The inference stub

The #4566 preflight passes a hosted run only if the observation says `inference: "stub"`. Workers AI (`AI`) is the
account's binding, so configuration cannot isolate it (`scripts/lib/previewIsolation.mjs`). Until now no hosted stub
existed: the local harness (D4594 §2) replaced `env.AI` inside the test.

**The seam is `callWorkersAI`.** It is the one function in the router that reaches Workers AI, and Llama Guard's check
goes through it too. With the stub on, it is handed a fixed binding in place of `env.AI`. Everything above it runs as
in production:

- the hold;
- the guard's verdict handling;
- the usage row;
- settlement and the charge;
- the proposal.

This is the same depth the local harness stubs at, so a hosted result and a local one are comparable.

**The switch fails closed.** It follows `skillEngineOf`'s pattern (D4555). The stub is on only when all three hold:

- `ENVIRONMENT` is exactly `preview`;
- `STUDIOOS_ENV` does not say production;
- `AGENT_INFERENCE_STUB` is exactly `deterministic`.

Anything else is off. `wrangler.toml` declares the variable in no environment. The Stage A workflow sets it on its own
throwaway Worker only. The test also holds `[vars]` and `[env.production.vars]` to `ENVIRONMENT = "production"`.

**The answers are fixed, and they say they are synthetic.**

- The guard model answers `safe` with zero usage.
- Every other model answers `STUB_ANSWER` ("[synthetic inference stub · D4594] …") with 40 tokens in and 10 out, so
  every run's charge is the same.

**What a stubbed result proves, and what it doesn't.** It is REAL HOSTED ORCHESTRATION with STUBBED INFERENCE. It
is not provider readiness; that is #4556's separate, approved substage.

### 2. The throwaway run (next PR)

`.github/workflows/agent-stage-a.yml`, dispatch only, like `schema-rehearsal.yml` (#5226). One step holds the
Cloudflare secrets, and a script does the run. Its `finally` deletes everything it created, pass or fail.

1. **Create:**
   - a D1 database;
   - the agent queue and its DLQ;
   - the job queue and its DLQ, if the Worker's consumers need them;
   - the KV namespaces;
   - the R2 buckets.

   Every name is suffixed `-s4594-<run>`.
2. **Configure.** Write a flat config derived from `[env.preview]`, with the same `parseToml` and swap approach as
   `branchConfig.mjs`:
   - every critical identity is replaced by the one just created;
   - the Worker is named `studioos-s4594-<run>`, on `workers_dev`;
   - there are no routes, no `[[services]]`, no crons and no browser;
   - Durable Objects are owned by the throwaway script;
   - `AGENT_ENGINE = "on"`, `AGENT_AUTONOMY = "manual"` and `AGENT_INFERENCE_STUB = "deterministic"`, on this Worker
     only.
3. **Migrate.** Build the schema through `migrate-d1.mjs --rehearsal`, as #4591 did.
4. **Seed.** Apply `agentSyntheticFixtures.mjs`: one tenant, one agent, one task, synthetic money, and
   `synthetic.invalid` addresses only.
5. **Preflight.** Take the observation with read-only `wrangler` list commands, then run `preflight()` on the generated
   config. Anything but `isolated` stops the run before any agent step.
6. **Deploy and drive.**
   - A per-run `JWT_SECRET` is generated and set as a secret. The driver signs the synthetic sponsor's token with it,
     which is the Worker's normal bearer path. No endpoint is added and no bypass exists.
   - **Workflow path:** start, then a proposal, then the sponsor accepts, then the run reaches `done`.
   - **Manual sponsor run.**
   - Then, per S1's note from #4555: once more with `AGENT_SKILL_RUNTIME = "cloudflare_sdk"` on an agent with a pinned
     skill, then once with it unset.
7. **Reconcile.** Read back D1:
   - one usage row, one proposal and one settled hold per logical run;
   - settled equals charged;
   - no pending hold and no live slot.
8. **Report.** Publish the counts and verdicts only, labelled `HOSTED PLATFORM WITH STUB`, with:
   - the commit;
   - the resource names;
   - the observation window;
   - the sample counts;
   - each step's latency where measured.

   Anything not measured is "Not recorded". No prompt or answer text is published beyond `STUB_ANSWER`.
9. **Tear down.** Delete the Worker, the D1 database, the queues, the KV namespaces and the R2 buckets.

### 3. Ceilings (owner decision 2 = A)

| Ceiling | Value |
|---|---|
| Lifecycles | One per path: Workflow, and manual sponsor run (plus the two #4555 skill-runtime runs on the Workflow path) |
| Inference | The stub; $0 model spend |
| Wall clock | 60 minutes, then stop and tear down |
| D1 writes | At most 1,000, read from the database's own `rows_written` |

A ceiling that cannot be read stops the run. Unavailable telemetry is never a pass.

Production stays at `AGENT_ENGINE=off` and `AGENT_AUTONOMY=manual`. Hosted Stage B and Stage C are not part of this.
