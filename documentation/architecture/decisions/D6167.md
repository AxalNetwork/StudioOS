## D6167 — Staff read the deal page's Evidence as an investor does; only the founder is sent to Raise (#6167)

**The bug.** The deal page gives an Admin and an Operating Partner the Evidence tab (`dealPageModel.js`, `STAFF`). `GET /api/deals/:id/evidence` refused anyone without the investor licence with `403 investor_only`. `refusalOf` turned that into the founder's line, "You read your evidence in Raise › Evidence", with a link. Staff were told to open a founder page that is not theirs. An Admin who also held the investor licence fared no better: they got 404, because they have no invitation on the deal.

**The call: option A, from D4631.** The issue asked for option A or B. D4631's audience table already settles it:
- **Staff are an audience on every deal read.** The `staff` audience (the platform admin, or a holder of the partner licence) is admitted to every deal read; refusing them is the outlier.
- **The NDA rule for the evidence pack is set.** The venture's NDA binds everyone but the admin and the venture's founder, and D4631 lists the investor's evidence pack (`evidenceNda`) among the readers that follow it.

So the tab stays, and staff read the evidence. This matches the scorecard, which admits staff.

**What staff read.** The projection an investor reads (`sharedView`), never the founder's own pack:
- only what the founder shared beyond Private;
- one investor's money and bank lines withheld, exactly as for an investor;
- files read through every grant's folders, not as a committed investor;
- before the NDA, coverage only.

The admin is NDA-exempt, so the admin reads the after-NDA projection. An Operating Partner is an outside member (#2460), so the venture's NDA binds them: they see coverage until it is signed with them.

**Logged with the staff role.** Each staff open writes `open_evidence_staff` to `data_room_access_log`, not `open_evidence`. The founder's "who opened" list (D1266) reads only `open_evidence` under the heading "investor". Counting the studio there would tell the founder an investor looked.

**Who gets which answer** (`routes/deals.ts`, from `loadDealForRead`'s audience):

| Audience | Answer |
| --- | --- |
| `staff` | 200 from `staffEvidence`, with `reader: 'staff'` |
| `owner` (the venture's founder) | `403 investor_only`. Still pointed to Raise › Evidence. |
| `investor` | `investorEvidence`, unchanged and still logged as `open_evidence` |
| anyone else admitted without the investor licence | `403 evidence_closed`. Never the founder's sentence. |
| `none` | refused by `loadDealForRead`, as before |

**Frontend.**
- **`refusalOf(error, role)`.** For an Admin or an Operating Partner a 403 is always `closed`, with its own sentence, so staff never get the founder's line even from an older Worker. The founder keeps the pointer.
- **`EvidenceSummary`.** It takes the deal page's `role`. A staff read carries one line above the block: "You are reading what an investor on this deal reads, as staff. Each open is logged."
