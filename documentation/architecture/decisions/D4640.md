### What was left, and what this decides

1. **The question travels in the address.** Opening a result (Enter on the selection, or a plain left click) first replaces the home's history entry with `/help?q=<query>`, then opens `/help/<area>/<guide>?q=<query>`. So browser Back returns to the same results, and the guide knows what was asked. A click with a modifier or a middle click is left to the browser (`isPlainClick`), and the link's own `href` already carries `?q=`. The query is trimmed to one line of at most 200 characters (`cleanQuery`) and always encoded. It is the reader's own words and nothing else.
2. **The guide offers the question back.** With `?q=`, the guide shows "Results for “…”" above the breadcrumb (a link to `/help?q=`), prefills its search with the question, and its related guides keep `?q=`. The guide's search is drawn at every width: above the guide below 1024px (new; HC13C draws no search on the phone guide, so this departs from the canvas) and in the right column from 1024px, as before. Submitting it opens the home's results, which is how a reader changes topic.
3. **Get help, before "Did this answer it?".** After the guide's content and related guides, a card says how to get help with this guide: Open a ticket (the HC7 sheet, prefilled with "From the guide: /help/<anchor>" and, when the guide was reached by search, "Searched for: “…”", both editable before Submit), Message the team only when `canUseCustomerChat` says the Worker serves this member, a private security report (the sheet's security form, never a ticket), and the status line with the status page. It repeats the public-tracker warning. Signed out: sign in to open a ticket, or the private advisory. Signed-out account recovery keeps its own "Still can’t get in?" (HC9) and draws no second block. On this page lists it as "Get help". The after-No ticket carries the search too. No record, note, company or account detail is copied into either ticket.
4. **Nothing found** adds Message the team (same eligibility) and the status page beside its ticket.
5. **Results sit directly under the phone search** (HC13B). While a query is typed the phone home does not draw Popular, Guides and Contact, nor the tickets card or the admin answers; the results (or nothing found) follow the search, then Still stuck?. Clearing the search brings them all back. Need help? stays on screen throughout, so a ticket is one tap away.
6. **The search says what it reads.** Under the results and under nothing found: "Searches guide titles and text. Release notes are not searched." with a link to What's new for a viewer who can read it (signed out, What's new is not a public guide, so only the first sentence is shown). Release notes are a Markdown file the guide fetches when opened (`/CHANGELOG-user.md`), and the index is built from the guide manifest; fetching that file into the index on every search was not chosen, because it would make the result set depend on a network read the count line cannot vouch for. The audit's alternative (scope stated, the notes one click away) is what is built.
7. **Focus and keyboard.** A guide opened from inside Help moves focus to its title (`tabIndex=-1`, no ring), so a screen reader announces the new page; a guide loaded from outside keeps the browser's own start. The search's clear button returns focus to the field. The phone search no longer draws the browser's own clear cross beside Help's.
8. **A guide on its own page no longer scrolls sideways.** The guide wrapper took back the shell's padding with `-mx-4 md:-mx-6` unconditionally; where the page renders without that padding (as it did in the local build checked below) the guide sat flush to the left edge at 390px and the page scrolled 24px sideways at 1440px. The negative margins now apply only inside the shell's main column (`[data-app-main]`).
