- **Code:** `.github/workflows/queue-stalled.yml` (new: `workflow_run` on CI), `.github/workflows/github-alerts.yml`

### Why

The rule of D7125 works; the check almost never ran. From 2026-11-20 to 11-25 the `*/15` schedule gave 22
`queue-stalled` jobs in six days (GitHub drops and delays scheduled runs under load), four of them crashed
with `ERR_MODULE_NOT_FOUND` (11-22 23:50Z to 11-24 01:47Z, fixed by #8374), and a replay found about five
cross-chain episodes where the alert should have opened and none did. A crashed check closed nothing and
said nothing.

### What changed

1. **On completion.** `queue-stalled.yml` runs the `queue-stalled` job when a `CI` run completes, if that
   run's event is `merge_group`, its head repository is this one, and its conclusion is neither `cancelled`
   nor `skipped` (queue rebuilds cancel many candidates; those carry no evidence). The `*/15` job in
   `github-alerts.yml` stays as the fallback and for `workflow_dispatch`.
2. **Bursts collapse.** Both jobs share the concurrency group `github-alerts-queue-stalled` with
   `cancel-in-progress: false`: one check runs, one waits, and each newer arrival replaces the waiting one.
   A chain of 30 failed candidates costs at most two checks in a row, and the last reads the newest runs.
   The replaced runs end `cancelled`, which the workflow-failure reporter (D6387) ignores. Every other CI
   completion (each `pull_request` and `push` run) starts a run whose one job is skipped: no runner.
3. **WF-4 widened for one entry.** `TRUSTED_WORKFLOW_RUN` now records the event each entry accepts:
   `pr-preview-deploy.yml` → `pull_request` (D7146), `queue-stalled.yml` → `merge_group`. Every other WF-4
   rule holds for both: `workflow_run` on completion is the only trigger, `permissions: {}` at the top, no
   `ref:` checkout (GitHub checks out main for `workflow_run`), no artifact download, the same-repository
   check. The job reads nothing from the event but its event, repository and conclusion, all in `if:`;
   the script lists queue runs through the API as the scheduled job does. Its token is the scheduled job's:
   `contents`, `actions`, `checks`, `pull-requests` read and `issues: write`. D6477 left widening WF-4 to
   the owner; answer A on #7125 named `workflow_run` on `ci.yml`.
   `main-red` keeps polling: its trigger would be `push` runs, which WF-4 still refuses.
4. **The check watches itself.** The check step is `id: check` with a 4-minute step timeout (job 7). After
   it, with `if: always()` on `main` only:
   - `actions/cache/restore` brings back `queue-stall-checker.json` (key prefix `queue-stall-checker-v1-`,
     the newest wins; the shared concurrency group serializes writers);
   - `scripts/queue-stall-checker.mjs` adds the check step's outcome. `success` resets the count;
     `failure`, `cancelled` (a step timeout) and `skipped` (an earlier step failed) add one. The count is
     written before any GitHub call. At the second failure in a row it opens
     **`[alert] merge queue stall check failing`**, listing the failed runs; the next successful check
     comments and closes it. Slack hears the open and the close, best effort; the issue is the record;
   - `actions/cache/save` stores the count under this run's key.
   The watchdog imports only `node:` modules and `lib/queueStallChecker.mjs`, which imports nothing, so
   what broke the check's import graph (the D8314 shape) cannot break it; a test walks its closure.

### The title

`[alert] merge queue stall check failing`, not `[alert] merge queue stalled`. Land-pr gate 7
(`scripts/lib/landPr.mjs`), the feeder breaker (`scripts/landing-bot/rules.mjs`) and the ejection handler
match that title exactly and stop admitting work while it is open. A crashed check means the stall state is
unknown, and D7125 never turns unknown into a transition; four crashed checks would otherwise have paused all
landing for a day on a fault in the monitor, not the queue. The distinct title tells the channel and leaves
the gates alone. The owner may choose otherwise (question on #7125): **B** reuse the stall title (fail
closed), or **C** keep this title and add it to gate 7 and the breakers.
