### 1. The object

- **Keying.** One object per tenant, company and asset: `idFromName(leaseKey(scope, assetId))`, where the key is
  `wgl:v1:t<tenant>:c<company>:a<asset>`. The project is not in the key: an asset has one lease object whichever
  project the caller reaches it through. Asset ids are `[A-Za-z0-9_.:-]{1,80}`.
- **Tenant binding.** The object refuses `wrong_tenant` when the request's key is not the key of the request's own
  tenant, company and asset; when the platform's name for the object (`state.id.name`, where present) is not that
  key; and when it is not the key the object stored on its first call. The service refuses `wrong_tenant` before
  that, when the caller's scope is not the resource's (D5579's rule: a company-wide caller covers its projects).
- **Units.** `whole`, `section` or `segment`, each with an id. `whole` conflicts with every unit; a section
  conflicts with itself and with a segment that names it as `sectionId`; a segment conflicts with itself. Disjoint
  sections, and segments of other sections, do not conflict.
- **Fencing.** One counter per asset, `fence`, the last fence issued. Every grant takes `fence + 1`, so fences are
  strictly increasing for every unit of the asset. Expiry, release and restarts never lower it.
- **Persistence.** The whole state (bound key, counter, live leases, expired-but-not-yet-audited leases) is one
  storage value, read on every call and written back before the call answers (the D5618 rule: persist the counter
  and the holder before responding). A new instance over the same storage, after an eviction, crash or deploy,
  honours every unexpired lease and continues the counter. Calls are serialised (`serial`, as `AiGovernor` does), so
  concurrent acquires of one unit have exactly one winner.
- **TTL.** 5 s to 5 min (`LEASE_TTL_MIN_MS`, `LEASE_TTL_MAX_MS`); anything else is `invalid_ttl`.
- **Expiry.** Checked lazily on every call, and by a storage alarm set to the earliest expiry. Leases the alarm
  expires are kept until the next call hands them to the service, which audits them.
- **Answers.** `granted {fence, expiresAt}`, `renewed`, `released`, `valid` (a fence check), `busy {heldBy, unit,
  expiresAt}` (`heldBy` is ids only: a user id or an agent run id), or `refused {code}`: `flag_off`, `no_binding`,
  `wrong_tenant`, `invalid_request`, `invalid_ttl`, `not_holder`, `expired`, `unknown_fence`, `stale_fence`,
  `no_capability`.
- **Renew and release.** Only the holder, only while the lease is live. A renew or release of a fence that was
  issued and is gone is `expired`; of a fence never issued, `unknown_fence`.

### 2. The service (`workGraphLeases.ts`)

`acquireLease`, `renewLease`, `releaseLease` and `assertFence`. Each checks, in order: the request shape, the flag,
the tenant, the binding; then calls the object once and audits the outcome.

### 3. A lease is not authorization

A lease says only that nobody else is working on that unit now. `acquireLease` takes no capability and grants
nothing; every result carries `authorizes: false`. `assertFence`, the check a write path makes just before it lands,
needs **both**: a live fence on exactly that unit held by that holder, and a `WriteCapability` the caller's own
authorization check produced for the same scope and holder. Without the capability it is refused
`no_capability` (audited, the object is not called). Optimistic concurrency (part 1's compare-and-swap head) stays
the default and the only thing that keeps a write correct; a lease only saves wasted work. Capability
authorization stays independent of coordination reservations, as the issue requires.

### 4. Audit and cost

`work_graph_lease_events`: one row per outcome (`acquire`, `renew`, `release`, `expire`, `busy`, `check`,
`refuse`), with tenant, company, project, asset, unit, fence, holder ids, expiry, refusal code and cost. Ids only,
no content. Append-only by trigger. A call whose request cannot be read as a scope and asset is refused without a
row. If the audit write fails, the lease is not undone; the result says `audited: false`.

Every result carries `cost: { doCalls, storageReads, storageWrites, alarmWrites, d1Statements }`. A first acquire
costs one object call, one storage read, one write, one alarm write and one audit statement; a busy answer or a fence
check writes nothing to storage. The audit row carries the object call and storage counts too, so spend can be read
from the table.

### 6. Wiring and the hub freeze

- `wrangler.toml`: the `WORK_GRAPH_LEASE` binding and the `v8-work-graph-lease` migration (`new_sqlite_classes =
  ["WorkGraphLease"]`) in the top-level, `[env.production]` and `[env.preview]` tables, and `WORK_GRAPH_LEASES =
  "off"` in all three `vars`. `services/topology.ts` lists the binding (a branch gets its own class).
- `index.ts` re-exports the class, because the Workers runtime finds a Durable Object class only among the entry's
  module exports. That is a new name in a frozen hub (D5615), and `HUBS.md` gives a new Durable Object no other
  home, so `scripts/hub-freeze.json` gains exactly that one name, `import ./durable-objects/work-graph-lease`.
- The eighth class made `cloudflare-worker/src/durable-objects/` heavy enough for `scripts/check-folder-docs.mjs`,
  so the folder is listed in its `DOCUMENTED` map and gets a `README.md` (one row per class).
- **Order.** `node scripts/check-decision-ids.mjs` fails this file until part 1's `D5581.md` (PR #5822) is on
  `main`, because a part file needs its parent (D5615). Part 1 lands first; nothing else here depends on it.
- **Deploy.** The `v8-work-graph-lease` migration tag creates the class's namespace on the next deploy of each
  environment. The D1 migration applies with the deploy's migration step. Nothing is reachable until the owner
  sets `WORK_GRAPH_LEASES = "on"`.

### 7. Rollback

Set the flag off (the default): every call is refused before the object is reached. To remove the class, drop
the binding and add a `deleted_classes = ["WorkGraphLease"]` migration tag (the `v8` tag stays: migrations are
append-only). Dropping `work_graph_lease_events` loses only the lease audit; no other table is read or written.
