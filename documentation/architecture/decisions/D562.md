## D562 — The Learning center's screens: "Learning" replaces "Articles" in the user menu, every Learning route is drawn, and a temporary coming-soon gate

**The user menu's "Articles" is now "Learning", and every Learning route the
canvas draws has a page.** Three of the home's tabs (Articles, Publications
and Events) are live through client methods that already existed. Everything
else is a presentational component that takes the planned API shape as props
and waits for its store. A temporary gate shows every profile except the
admin and the Super Admin "Coming soon" everywhere but Articles. Slot S01,
issue #1163 (epic #1157), 2026-10-06. The canvas is
`design/incoming/Learning.dc.html`, which is committed on the S1 branch and is
not part of this change. No migration, no Worker change and no client method.

**What was true on main.**
- The user dropdown in `App.jsx` linked "Articles" to `/articles/draft`.
- No `/learning` route existed, and no Learning store or client existed
  either. #1158 to #1162 are building them.

### The menu

- "Learning" (`/learning`) takes the slot "Articles" held, between Events and
  the Help Center.
- The article routes are unchanged: `/articles`, `/articles/:slug`,
  `/articles/draft`, `/articles/edit/:id` and the `/news` and `/articles/mine`

  - `CommandPalette.jsx`'s article results open `/articles/:slug`.

### The coming-soon gate (temporary)

**The reason, in the owner's words (2026-10-06):** "Build everything for
Learning, but put a temporary coming soon for Founder, Investor, Partner, and
Advisor profiles except articles please. As the content is not there yet."

**The gate.** It is one function in one module, `learningComingSoon(user,
activeRole)` in `pages/learning/learningAccess.js`, behind one constant,
`LEARNING_COMING_SOON = true`.
- **Gated:** every profile that is not an admin, which means founder,
  investor, partner, advisor, exploring and any role added later.
- **Not gated:** the admin and the Super Admin, so they can author and check
  content. The Super Admin is an elevation on the admin role
  (`lib/shellRole.js`), so the one admin check covers both. It is the check
  `RoleGuard` and every `guard(['admin'], …)` make.
- **The role it asks about is the one being browsed** (`lib/activeRole.js`).
  An admin using "View as Founder" sees what a founder sees.

**What a gated profile sees.**
- **On `/learning`,** Articles is the default tab and works exactly as built:
  the list, the reader links and "Write an article". Every other tab shows one
  coming-soon card: "Courses, videos, webinars and more are coming soon.
  Articles are open now." The three sections (Continue learning, My programs
  and Upcoming webinars) are replaced by one card, not three.
- **On every other Learning route, the same card is shown in place, not a
  redirect.** A shared link to a course says what is going on where it lands,
  and a redirect to the home would look like a broken link. The card links to
  the open Articles tab. The studio and programs routes are guarded to the
  admin, so a gated profile never reaches them.

**How to lift it.** Set `LEARNING_COMING_SOON` to `false` in
`learningAccess.js`. That is the whole change, and every profile then gets the
full Learning center. Afterwards, delete the gate, its callers' coming-soon
branches and `ComingSoonCard`, and record the lift in a decision. Lift it
once #1158 has merged and HQ has published content. The test file reads the
lifted gate through the function's third parameter.

### The home, `/learning`

The header carries "Write an article" (`/articles/draft`). Under it are the
sections, then the tabs, a search box and the tab's panel.
- **Articles:** `articles.list` → `GET /api/articles` (`publicArticleShape`).
  Each row shows the title, the subtitle, the author, their role, the date and
  `read_minutes`. The reading time is drawn only when it is a positive number.
  The row opens `/articles/:slug`, and the list pages through the route's own
  `total`.
- **Publications:** `publications.publicList` → `GET
  /api/market-intel-public/publications`, which sends the slug, title,
  subtitle, section and date. The search filters it here, because the route
  takes no query. Each row opens `/insights/public/:slug`. The PDF is "not
  recorded" (see GAPS).
- **Events:** `eventsPublic.list` → `GET /api/public/events` (`shapeEvent`,
  upcoming by default). Each row shows the start in the event's own time
  zone, the type and the place, and has an "Add to calendar" link to the
  existing `.ics` route.
- **All** merges the three, newest first, each row labelled by its kind. A
  source still loading or unreadable is named above the rows, never counted
  as empty.
- **Courses, Videos, Webinars, Exercises and Exams, and the three sections,**
  show "Not recorded" and one plain line: "The course catalogue is not live
  yet." No row is drawn.
- A reply in the wrong shape is a failed read, so the page shows "Unreadable"
  rather than "nothing published". `learningReads.js` is the only file in the
  folder that touches the client.
- An admin also gets links to My learning and Programs, and the Super Admin
  to the Learning studio, because the sidebar entries are #1164's.

2. **Every route is built now.** The owner widened the scope on 2026-10-06.
   Each deep page renders its component as "Not recorded" until its store
   merges.
3. **Publications have no PDF download** (see GAPS). Each row opens the
   publication's public page.
4. **The canvas's filters (Topic, Level, Length, Format, Sort) are not

5. **The canvas's "Draft · only you" row is not drawn.** The Articles tab is
   the published list. A member's drafts stay in `/articles/draft`.

   webinar scheduler, exercise editor and exam builder. They are forms over

8. **`:slug` for webinars, exercises and exams,** as the canvas and the brief

9. **"Exploring" is not admitted to `/learning`,** because it takes the

### GAPS

- **A member cannot download a publication's PDF.** The public list carries
  no file. A PDF is rendered by `POST /api/admin/publications/:id/render`,
  which is admin-only, and shared as a 24-hour token link. Closing this needs
  a Worker route.
- **A failed publications read looks empty.** `market_intel_public.ts`
  catches its own query failure and answers `{ publications: [] }`, so the
  tab can show "Unreadable" only when the HTTP request itself fails. The
  Worker is out of scope here, so this is left for its owner.
- **Two lists are bounded by their routes:**
  - the events feed sends no total, so the tab shows the next 20 and links
    `/events`;
  - the public article list is edge-cached for 5 minutes, so a new article
    can take that long to appear.
- **No planned store holds a transcript, course resources or a certificate.**
  Each is drawn "Not recorded".
- **A lesson's length is not a lessons column** in #1158. Only video items
  carry `duration_seconds`, so readings and exercises read "Length not
  recorded" unless the course route sends a length per lesson. A module totals
  only when every lesson has one.
- **Fields no issue spells out:**
  - a webinar's `registered_count` (#1161);
  - an exercise reviewer's name (#1160 stores `reviewer_id`);
  - the shape of `options_json` (the component takes strings or `{ key,
    label }`);
  - a checklist submission (drawn as text).

  Each is drawn "not recorded" if it is absent.
- **No standalone video route.** The epic lists `/learning/videos/:uid`, and
  the canvas and this stage do not. The Videos tab and a webinar's recording
  link need one, or the recording opens as a course lesson.
- **A linked video needs an embed URL.** `LessonPlayer` takes `{ src, embed
  }`, and turning a stored YouTube or Vimeo link into an embed URL is the
  wiring's job.
- **An old stub.** `/academy` (`AcademyLessonPage.jsx`) is an older
  "Academy LMS" placeholder for search results. It is untouched here, and
  folding it into Learning is a separate call.
