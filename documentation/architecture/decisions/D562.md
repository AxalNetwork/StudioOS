**The user menu's "Articles" is now "Learning", and every Learning route the
canvas draws has a page.** Slot S01, issue #1163 (epic #1157), 2026-10-06,
in three stages:

- **Stage 1** drew every screen. Articles, Publications and Events were live
  through client methods that already existed. Everything else was a
  presentational component that takes the planned shape as props.
- **Stage 2** wired those components to D557's store (#1158, merged as
  #1179). It covers the catalog behind All, Courses and Videos, a course, a
  lesson, a standalone video or reading, and My learning. It also builds the
  Super Admin's studio, which authors videos, readings and courses.

  exercises and exams (#1160), D560's webinars (#1161) and D561's video
  upload and playback (#1162). Every view now reads. The studio also authors
  exercises, exams and webinars, and uploads a video's file.

"Coming soon" everywhere but Articles. The canvas is
`design/incoming/Learning.dc.html`, which is committed on the S1 branch and is
not part of this change. There is no migration, no Worker change and no new
client method. Stages 2 and 3 call only the methods that `lib/api/learning.js`
and `lib/api/adminLearning.js` already declare. Stage 3 changes one of them:
`uploadVideoPart` takes a deadline sized to its part and a cancel signal.

### The coming-soon gate (temporary)

**The reason, in the owner's words (2026-10-06):** "Build everything for
Learning, but put a temporary coming soon for Founder, Investor, Partner, and
Advisor profiles except articles please. As the content is not there yet."

**The gate.** It is one function in one module, `learningComingSoon(user,
activeRole)` in `pages/learning/learningAccess.js`, behind one constant,
`LEARNING_COMING_SOON = true`.
- **Gated:** every profile that is not an admin, which means founder,
  investor, partner, advisor, exploring and any role added later.
- **Not gated:** the admin and the Super Admin, so they can author and check
  content. The Super Admin is an elevation on the admin role
  (`lib/shellRole.js`), so the one admin check covers both. It is the check
  `RoleGuard` and every `guard(['admin'], …)` make.
- **The role it asks about is the one being browsed** (`lib/activeRole.js`).
  An admin using "View as Founder" sees what a founder sees.

**What a gated profile sees.**
- **On `/learning`,** Articles is the default tab and works exactly as built:
  the list, the reader links and "Write an article". Every other tab shows one
  coming-soon card: "Courses, videos, webinars and more are coming soon.
  Articles are open now." The three sections (Continue learning, My programs
  and Upcoming webinars) are replaced by one card, not three.
- **On every other Learning route, the same card is shown in place, not a
  redirect.** A shared link to a course says what is going on where it lands,
  and a redirect to the home would look like a broken link. The card links to
  the open Articles tab. The studio and programs routes are guarded to the
  admin, so a gated profile never reaches them.

**Stages 2 and 3 keep the gate exactly as it was.**
- `LearningPage.jsx` applies it before any view mounts, so a gated profile
  makes no Learning read at all: no catalog, course, `/me`, program, exercise,
  exam or webinar.
- On the home, the catalog is read only for an open live tab. `/me`, My
  programs and the upcoming webinars are read only for a profile the gate
  admits, and the past webinars only while their tab is open.
- An admin browsing as a held profile ("View as") on an admin route sees the
  card there, beside that tier's rail.

**How to lift it.**
1. Set `LEARNING_COMING_SOON` to `false` in `learningAccess.js`. That is the
   whole change: every profile then gets the full Learning center.
2. Afterwards, delete the gate, its callers' coming-soon branches and
   `ComingSoonCard`, and record the lift in a decision.

#1158 has merged, so lift it once HQ has published content. The tests read
the lifted gate through the function's third parameter.

### The home, `/learning`

The header carries "Write an article" (`/articles/draft`). Under it are the
sections, then the tabs, a search box and the tab's panel.

**All, Courses and Videos read D557's catalog**: `learningApi.catalog` →
`GET /api/learning/catalog`.
- **All** shows every kind, the newest 24 (`limit=24`). Each card is
  labelled by its kind, and a Super Admin's draft is marked "Draft".
- **Courses and Videos** show one kind (`kind=course` or `kind=video`), 24 at
  a time through the route's `offset`, against the route's own total
  ("1–24 of 30").
- **Each source's state is kept.** The route answers `sources[kind]` for
  each kind. A source it could not read is named above the rows in the
  route's own sentence, for example "The event store could not be read, so
  this is not a claim that there are no upcoming events." It is never shown
  as empty. A read that fails as a whole is "Unreadable".
- **Where each card opens:**
  - a course: `/learning/courses/:slug`;
  - a video: `/learning/videos/:uid`;
  - a reading: `/learning/items/:uid`;
  - an article, a publication or an event: its existing page.

**Articles, Publications and Events keep the routes stage 1 built them on.**
Each of those routes sends more per row than the catalog does, such as an
article's subtitle and total, and an event's own time zone and place.
- **Articles:** `articles.list` → `GET /api/articles` (`publicArticleShape`).
  Each row shows the title, the subtitle, the author, their role, the date and
  `read_minutes`. The reading time is drawn only when it is a positive number.
  The row opens `/articles/:slug`, and the list pages through the route's own
  `total`.
- **Publications:** `publications.publicList` → `GET
  /api/market-intel-public/publications`, which sends the slug, title,
  subtitle, section and date. The search filters it here, because the route
  takes no query. Each row opens `/insights/public/:slug`. The PDF is "not
  recorded" (see GAPS).
- **Events:** `eventsPublic.list` → `GET /api/public/events` (`shapeEvent`,
  upcoming by default). Each row shows the start in the event's own time
  zone, the type and the place, and has an "Add to calendar" link to the
  existing `.ics` route.

**Continue learning** reads `learningApi.me` → `GET /api/learning/me`.
- It lists the first three things in progress that have somewhere to open.
- Each shows the route's percent with a bar, or "Started" when the route
  sends no percent.

**Stage 3 fills the rest of the home:**
- **Webinars** reads D560's two lists, `learningApi.webinars('upcoming')` and
  `('past')`: upcoming and live first, then past with recordings. The search
  filters them here, because the route takes no query.
- **Upcoming webinars** shows the next three from the same upcoming read,
  each with "Register →" to its page, and "All webinars". The home reads the
  upcoming list once for both.
- **My programs** reads D558: each program the member is in, with "n of m
  complete", and the programs open to join (`MyPrograms.jsx`).
- **Exercises and Exams** stay "Not recorded". D559 serves one at a time and
  lists neither, so each tab says so: "Exercises open from the courses and
  programs that hold them. No route lists them on their own yet."
  (`UNLISTED` in `learningModel.js`). No row is drawn.

**How the reads behave:**
- Each tab reads only while it is open.
- A tab switch never draws the last tab's reply (`catalogFor`).
- A reply in the wrong shape is a failed read, so the page shows
  "Unreadable" rather than "nothing published".
- Five files in the folder touch the client: `learningReads.js` and
  `studioActions.js`, and since stage 3 `programReads.js`,
  `assessmentReads.js` and `webinarReads.js`. Each Learning client is
  imported from its own module, as research's pages import theirs.

An admin also gets links to My learning and Programs, and the Super Admin
to the Learning studio, because the sidebar entries are #1164's.

### The learner's pages (stage 2)

**A course** (`/learning/courses/:slug`) reads `learningApi.course(slug)`,
which answers `{ course, modules, progress }`.
- **The outline.** `CourseOutline` draws the modules and lessons in their
  stored order, with a tick on each lesson the member has completed.
- **Progress.** The route measures progress over required lessons, and the
  line says so: "50% · 1 of 2 required lessons". A course with no required
  lesson says "No lesson is required, so there is no percentage." and draws
  no bar.
- **Start or Continue** opens the first lesson not yet completed.
- **Resources** are the course's `{title, url}` list, each opening in a new
  tab. Only an https link is linked. An empty list reads "No resources".
- **Certificate** reads "Not recorded", because no store issues one.
- **Lesson lengths.** The route sends none, so the outline says once "Lesson
  lengths are not recorded." rather than "Length not recorded" on every row.
- **A 404** reads "No such course".

**A lesson** (`/learning/courses/:slug/:lesson`) finds itself in the course
read. What it shows depends on its kind:
- **A video or reading lesson** reads its item, `learningApi.item(ref_uid)`,
  and plays it in `LessonPlayer`. Around it are the module, "lesson 3 of 8",
  previous and next across modules, and the outline with this lesson marked.
- **A webinar lesson** opens its event, `/events/:slug`. D557's `checkRef`
  makes a webinar lesson's `ref_uid` an event slug (departure 12).
- **An exercise or exam lesson** (stage 3) opens the exercise or exam it
  names, with the course along as `?course=<slug>`, so that page says "Part
  of <course> · <module>" and leads back. The outline's link for the lesson
  carries the same.
- **An item that is not published** reads "Not available".

**"Mark complete"** calls `learningApi.recordProgress`:
- **On a lesson,** it takes three calls:
  1. it records the lesson as completed;
  2. it reads the course again;
  3. it writes the course's own row: `completed` at 100%, `started`
     otherwise, carrying the route's percent when the route sends one.

  The route records only the subject it is given. Without the course write, a
  course would never appear on My learning or in Continue learning.
- **On a standalone item,** it records the item as completed.
- **A refusal** is shown under the button, in the route's words.

**How a video plays** (`videoPlayback` in `learningModel.js`). D557 stores a
video as a link on its allow-list. Each platform's link becomes its own embed
form, played in an iframe with `strict-origin-when-cross-origin`:
- YouTube (`watch?v=`, `youtu.be/`, `/embed/`, `/shorts/`, `/live/`) becomes
  `www.youtube-nocookie.com/embed/<id>`;
- Vimeo becomes `player.vimeo.com/video/<id>`;
- Cloudflare Stream (`<customer>.cloudflarestream.com/<id>`,
  `videodelivery.net/<id>`) becomes that id's `iframe` player.

Some videos are not played:
- a link that names no video the page can embed shows the reason and "Open
  the video", which opens in a new tab;
- a link that is not https is not played;
- an upload (`video_source = 'r2'`) plays in the browser's own player from
  the item's `video_stream_url` (stage 3, D561), and only from its own stream
  route. An upload whose read sent no address is "Not recorded", and a file
  that fails to load is "Unreadable", with a retry.

**Transcript and text.** A video shows its transcript when it has one, and
"No transcript is recorded for this video." when it does not. A reading's
body renders as Markdown.

**A standalone video or reading** opens at two addresses, both added in
stage 2 with the learner guard and the gate:
- `/learning/videos/:uid`, the epic's address;
- `/learning/items/:uid`, the catalog's own href for an item.

A 404 reads "No such video or reading".

**My learning** (`/learning/me`) reads `learningApi.me`.
- It lists courses in progress with their percent, courses completed, and
  videos watched, each opening its page.
- Exercises and exam results stay "Not recorded": D559 lists neither across
  exercises or exams, and each one's own page shows the member's. Certificates
  are not recorded.

### The studio, `/learning/studio` (stage 2)

The Super Admin authors here through `adminLearningApi`
(`routes/admin_learning.ts`, every route `requireSuperAdmin`).

**The content table** reads `listItems` and `listCourses`.
- It lists every row, drafts and archived included, the newest edit first.
- Each title opens its editor.
- The programs column is "Not recorded": no list route says which programs
  hold a row, and D558 keeps that on each program.
- A list that fails is named on its own line. If every list fails, they show
  as one unreadable table.
- Since stage 3 it merges exercises and exams (`withAssessmentRows`), and the
  webinars are listed under it (`WebinarStudioList`).

**What is open lives in the URL:** `?item=<uid>`, `?course=<uid>` or
`?new=video|reading|course`, and since stage 3 `?exercise=<uid>`,
`?exam=<uid>`, `?webinar=<uid>` and `?new=exercise|exam|webinar`. A link to
one course's builder can be shared, and "All content" goes back to the table.

**The item editor** creates and edits a video (a link, or since stage 3 an
uploaded file) or a reading (Markdown text).
- **Its fields:** title, summary, the link or the text, transcript, length,
  thumbnail, topic, level and visibility.
- **The length** is typed as minutes or as `12:05`, and is sent as whole
  seconds. A length the page cannot read is refused before anything is sent.
- **A video and a reading send different fields.** A video sends its link
  and transcript, a reading its text, and neither touches the other's fields.
- **A video's file** is uploaded since stage 3 (see "Stage 3" below).

**Publish, unpublish and archive** follow the stored status:
- publish is offered for anything not published;
- unpublish, for anything not a draft;
- archive, for anything not archived.

**Archive asks first:** "Archive this video? Members lose it at once; it
stays here, and can be published again."

**The course builder** holds the course's fields (title, slug, summary,
cover, estimated minutes, level and visibility) and its resources, then its
modules and lessons.
- **Modules** can be added, renamed, deleted and moved up or down. A delete
  asks first.
- **Lessons** can be added, edited, deleted and moved up or down within their
  module. A delete asks first.
- **Up and down** send the complete new order, as the reorder routes
  require. Each button is disabled at its end.
- **A lesson's kind** is set when it is added and never changed, because
  `PATCH /lessons/:uid` takes none:
  - a video or reading lesson picks an item of that kind, leaving archived
    ones out;
  - a webinar lesson names an event by its slug;
  - an exercise or exam lesson (stage 3) picks one from the studio's lists,
    leaving archived ones out. A required one keeps the course below 100%
    until #1249 records it, and the builder says so.
- **Every write answers with the whole course tree,** which replaces what is
  drawn. The order on screen is therefore always the order stored.

**Every refusal is shown in the route's own words,** beside what was being
changed. `request()` throws with the route's `message`, and the studio shows
it as it came. Examples:
- "A video needs its link before it is published."
- "A course needs at least one lesson before it is published."
- "Another course already has that slug."
- "Remove the module’s lessons first."

A refusal or a notice belongs to the editor it was made in (`sayingAt`), so
opening another item never shows the last one's error.

### Stage 3: programs, exercises and exams, webinars, and a video's file

Each part was built against its own store and then mounted here. Each one
reads and writes through its own module, and none adds a client method.

**Programs (D558, #1159),** through `programReads.js`.
- **My programs,** on the home: each program the member is in, with its
  region, "n of m complete" with a bar, and what it holds, in order. Each row
  shows the member's own status, and links only what is published. Progress
  counts published content only, and nothing started reads "None of 4
  complete yet", never 0%. A program whose own read fails says so on its row.
  "Open to join" lists the open programs the member is not in, each with Join
  and the route's refusal beside it.
- **The assigned admin's** `/learning/programs` and
  `/learning/programs/:program` are read-only: each enrolled member against
  the program's content, and one member's record at `?learner=<uid>`. A 403
  is the route's own sentence, never "could not be read". No email is drawn.
- **The Super Admin's** `/learning/studio/programs` creates a program
  (`?new=program`). `/learning/studio/programs/:program` edits its fields and
  status, its content (the whole ordered list each time), its admins (found
  through the console's user search, admins only) and its members. Every
  removal asks first.

**Exercises and exams (D559, #1160),** through `assessmentReads.js`. D559
names them by uid, which the route's `:slug` carries.
- **An exercise** takes a text answer or a checklist. It shows its status,
  the reviewer's feedback and the earlier answers. An accepted exercise takes
  no new answer.
- **An exam** starts or resumes an attempt against the attempt's own
  deadline, one question per screen, and submits option indexes. When the
  time runs out, the page submits what is chosen once, inside the route's
  30-second grace. Correct answers show only when the route reveals them on
  an exam set to show them. Attempts left is the route's own count.
- **The studio** authors both, and publishes, unpublishes and archives them:
  - the exercise editor takes the title, the instructions, a text or
    checklist answer and the visibility;
  - the exam builder takes the pass mark, time limit, attempts, shuffle,
    reveal, and questions with their correct options, fixed once someone has
    started it.

  The Super Admin accepts a submission or marks it "Needs work"; an exam's
  attempts show scores only. Every refusal is in the route's words.

**Webinars (D560, #1161),** through `webinarReads.js`.
- **The webinar page** shows the seats as the route counts them
  (`capacity: null` is "no seat limit", never 0). It has Register and Cancel
  registration, with the route's refusals in its own words, the join link
  only when the route sends it, "Add to calendar", and the recording or the
  route's reason.
- **Times** are in the viewer's locale and zone, with the webinar's own zone
  beside them when it differs. A page left open reads again as the join
  window opens, at the start and at the end.
- **The studio** schedules a webinar:
  - the date and start are read on the chosen zone's clock, and a time that
    zone skips is refused before sending;
  - a length is asked for, from which the end is worked out.

  It also publishes, unpublishes and cancels (after a confirmation), attaches
  the recording, and records attendance by name: Attended, Did not attend,
  or Not recorded, which is never counted as absent.

**A video's file (D561, #1162),** through `videoUpload.js` and `uploadVideo`
in `studioActions.js`.
- **The upload.** A saved video takes an MP4 or WebM file of at most 2 GB,
  the route's limits, and the field says them. A file outside them is refused
  before a byte is sent. The file goes up through D561's start, parts (with
  progress per part) and complete, and is aborted on Cancel or on any failure
  after the start.
- **A part's deadline follows its size:** what a 1 Mbit/s line needs, and
  never less than the long deadline, 180 s (`uploadVideoPart`). The default
  30 s would cut a 10 MB part off below about 2.7 Mbit/s. A size that is not
  a number gets the long deadline.
- **Cancel stops the part on its way,** through an `AbortSignal`, rather than
  waiting for it, and leaving the editor does the same. Either reads
  "Cancelled".
- **After an upload** the editor shows the item as stored and clears the
  form's link. It hands the stored item to the studio's list (`onUploaded`),
  so reopening the item never draws the old link, and a save never puts it
  back over the file. A saved link replaces the file; an empty link leaves
  it.
- **Playback** is described under "How a video plays" above.

**What mounting them changed.**
- `LearningPage.jsx` wires every view. `ViewBody`, the held "New program"
  button and the not-live lines are gone. The gate is still the one test
  before a view mounts.
- **Stale lines went:**
  - the visibility hint said program-only content stays hidden "until
    programs are live". It now says it reaches a member enrolled in a
    published program that holds it, as `enrolledSql` checks;
  - the programs column said "Programs are not live yet.";
  - every "not live yet" line on a surface that now reads.
- Five files call the client (see the home).

### What the routes do not return (stage 2)

Each of these is drawn "Not recorded" or left out, never invented.

  lesson lengths are not recorded.
- **A catalog event's time zone and place.** The catalog's event row carries
  only `event_type` and `starts_at`. All shows the start in the reader's own
  zone. The Events tab, on `GET /api/public/events`, keeps the event's own.

### GAPS

- **A member cannot download a publication's PDF.** The public list carries
  no file. A PDF is rendered by `POST /api/admin/publications/:id/render`,
  which is admin-only, and shared as a 24-hour token link. Closing this needs
  a Worker route.
- **A failed publications read looks empty.** `market_intel_public.ts`
  catches its own query failure and answers `{ publications: [] }`, so the
  tab can show "Unreadable" only when the HTTP request itself fails. The
  Worker is out of scope here, so this is left for its owner.
- **Two lists are bounded by their routes:**
  - the events feed sends no total, so the tab shows the next 20 and links
    `/events`;
  - the public article list is edge-cached for 5 minutes, so a new article
    can take that long to appear.
- **Progress is written only by "Mark complete".** The player does not report
  a video's position (`position_seconds`) or a partial percent. An embedded
  player's events would need each platform's own API.
- **A course's row is brought up to date only by this page.** If a lesson
  were completed anywhere else, the course row would catch up the next time a
  lesson is marked complete here. No other page writes progress today.
- **My learning lists no readings.** The canvas draws courses and videos
  watched, so a completed standalone reading appears nowhere on it. `GET /me`
  sends the row, so adding a part for it needs no Worker change.
- **An exercise's reviewer.** D559 stores `reviewer_id` and no name, so the
  feedback card says "Reviewer not recorded".
- **An exercise or exam lesson is never marked complete.** Nothing records
  it, so a course with a required one never reaches 100%; the course builder
  says so. #1249 records it on acceptance or a pass.
- **A replaced upload can stream the old file for an hour.** The stream
  address does not change and is cacheable for an hour. #1250 versions it.
- **A draft webinar is refused as "cancelled"** (D560's `memberWebinar`), a
  sentence only the Super Admin can meet; the page never offers Register on a
  draft. #1252.
- **An exam's choices are not saved before submit,** so a resumed attempt
  starts blank, and the page says so. A browser clock more than 30 seconds
  off the server's can have the automatic submit refused as "time limit
  passed".
- **The assigned admin's review of exercises and exams is not mounted.** D559
  admits them to `/review/*`; the program page shows each member's status and
  best score, and the review lists stay the Super Admin's, in the studio.
- **An old stub.** `/academy` (`AcademyLessonPage.jsx`) is an older
  "Academy LMS" placeholder for search results. It is untouched here, and
  folding it into Learning is a separate call.
