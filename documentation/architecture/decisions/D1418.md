### 2. Every module has a group, a purpose and an Open link

- **`STUDIO_GROUPS`**, in the order the module map draws them:

  | Profile | Groups |
  |---|---|
  | founder | Studio, Validate, Build, Raise, Grow |
  | investor | Investor |
  | advisor | Advisor |
  | partner | Operating partner |

  Every module's `group` is one of its profile's keys.
- **`purpose`:** one line, in the canvas's words, of at most 80 characters. Where the canvas has no caption (the advisor's and partner's modules), the line is taken from what each block shows on main.
- **`href`:** the tile's Open link, or `null` when the module acts on the page itself. Eadwyn's questions is `null`, because its "Answer now" goes to the chat on the page. Lab tools opens `/spinout-lab`.

### 3. The founder catalogue: 3 Studio modules plus 27 cycle modules

- **The Studio group:** Company progress, Eadwyn's questions and Lab tools.
- **Holding progress and What this adds up to are not offered:** owner question B, S1's pick (b). They have no store.
- **The 27 cycle modules are derived, never retyped:**
  - **The lists:** they come from the four cycles' own Worker lists, in their order: `MODULES` in `services/cycleValidate.ts`, `BUILD_MODULES` in `routes/cycle_build.ts`, `MODULES` in `services/raiseCycle.ts` and `GROW_MODULES` in `services/growCycle.ts`.
  - **Key:** `<cycle>_<slug with "-" as "_">`, for example `build_prototype_mvp`.
  - **Title:** the list's `name`.
  - **Group:** the cycle.
  - **Size:** `1/3`.
  - **href:** `/<cycle>/<slug>`.
  - **Reads:** `/api/cycles/<cycle>/overview`.
  - **Purpose:** from `CYCLE_PURPOSE`, the canvas's lines keyed `<cycle>/<slug>`.
- **No cycle module is plan-locked.** None of those reads is under a paywall prefix, so `lockOf` answers `null`. The lock stays derived.

### 4. Grow is founder-only

`/grow/:slug` admits only `admin` and `founder` (`App.jsx`), not a Spin-Out Lab member.
- **The Grow rows carry `founder_role_only`.**
- **`catalogueOf(profile, user)`** leaves them out unless the member's own role is `founder` or `admin`. A Lab member's founder Studio is 23 modules, not 30.

**The Worker does not refuse a Lab member there itself.** `cycle_grow.ts`'s overview admits any member `canAccessProject` lets read the venture, by project and not by role, so the SPA route is the only gate. The catalogue follows the route.

### 7. `GET /api/studio/modules`

```
{ profile,
  groups:  [{ key, label }],      // STUDIO_GROUPS[profile] in order; a group with no module offered is left out
  modules: [{ key, title, group, purpose, href, default_size, in_default, cohort_only, locked_by_plan, plan }] }
```

- **Order:** the registry's: by group, then each list's own order.
- **`in_default`:** true exactly for the profile's defaults. It feeds the module map's "Recommended for you", among modules not placed.
- **The refusals are unchanged:** 401, 403 `no_studio_profile`, 403 `profile_not_allowed`, 400 `invalid_profile`.
