### What the browser does

- **Reads the chosen file** (`importRun.js` `readPackage`): its SHA-256 and size, then the file against its own
  manifest: per source the record count, the cells (`expected_records × columns`, the store's own count), every
  column named, no repeated record or column, every value one the store can keep, and the list digest (sorted
  `id:row hash` lines, the store's `membershipDigest`). A file that fails stops before any request with a fixed
  sentence. Each stated row hash is **declared, not checked**: no package hash recipe is registered (D7742 Q1,
  `HASH_RECIPES` empty), and the page says so. The file digest is sent as declared (D7745).
- **The file's shape**, until the package's key-only schema is posted (D7742 Q1): one JSON object
  `{ manifest: { sources: [...] }, records: [...] }` whose manifest source is the store's (`source_key`, `columns`,
  `expected_records`, `expected_cells`, `digest`, optional `excluded_person_records`) and whose record is the
  store's input (`source_key`, `provider_record_id`, `stated_row_hash`, `cells`, optional `captured_at`), plus an
  optional `about_person: true`. Only `readPackage`/`checkPackage` know the shape, so a different one is a change
  to that one function.
- **#7739 Q3 B before upload.** The operator sets each column's class (fact, prose, contact) once per source; a
  contact column (a personal profile link included) is withheld: left out of every request and only counted. A
  record marked `about_person` is checked with its source and left out of every request. The manifest the Worker
  receives describes what is sent (its records, cells and list digest) and carries `excluded_person_records`.
- **Preview** calls only `POST /preview` (pages of at most 500 entries) and writes nothing. The same file again
  reads "Every record unchanged" and offers no Apply.
- **Apply.** One run key per plan, held in memory, so a resend after a 429 answers the same run. Chunks are cut in
  file order within the bound the Worker gives (50 records, 600,000 bytes); the same file always gives the same
  chunks. One request starts at most every 1.1 s (the Worker allows 60 a minute per user). A 429 waits (its
  `retry_after`, else 61 s) and sends the same request again; a lapsed step-up is a wait for "Confirm and continue";
  neither is a failure.
- **Resume** comes from the Worker's run record for the file's digest: `GET /runs` finds the open run whose declared
  file digest is this file's, `GET /runs/:uid` names the chunks it holds, and only the rest are sent (a partial run
  is resumed first). Nothing but the Worker's run id is kept between visits, and it is kept only by the Worker.
- **Read-back.** After the last chunk the run is sealed against the expected list, then read back with
  `GET /runs/:uid` (every page). **Complete** only when the Worker says complete, every source's recomputed list
  digest matches, every record sent is a member once and none is refused, and stored + withheld + blank cells equal
  the cells sent, with the withheld cells equal to the contact cells left out here.
- **States, in D7170's words** (`resultLabel` from `sheetsSyncModel.js`, not edited): Complete · counts verified;
  Partial (Apply again sends only what is missing); Failed · nothing written, only when the run holds no member,
  and the run is then closed so it blocks nothing; Outcome uncertain · reconciliation pending, when a request's
  answer never came (no status, a timeout or a 5xx) or the seal or read-back did not answer, with Reconcile (read
  the held chunks, send the rest and any the Worker lists as uncertain, seal, read back). An open run for another
  file blocks a new one and links to it.

### Private data

- No record field value is drawn: counts, record ids, digests, states and reason codes only. The file and its
  records live in memory while the Sheet is open and are dropped when it closes; no storage write, no address, no
  query carries anything from it (the only path parameter is the Worker's run id, the only query a page offset).
- Every problem is an `ImportProblem` whose message is a fixed sentence naming at most a source, a record index and
  a column (and, for a count mismatch, the two counts). A JSON parse error, a decoder error and any transport error
  are replaced before they are thrown, shown or reported; a Worker refusal is read by its code alone and its body is
  never printed. Anything unexpected is reported as `reportError('researchSourceImports:run', <fixed sentence>)`.
