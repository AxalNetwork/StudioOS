## D1589 — Stage norms: the only benchmarks a deck critic may cite

- **Status:** built by S15 from S1's specification on #3836 (deck builder v2, Phase F, F10; plan on #3716).
- **Owner decision S:** A now, C later (2026-11-01). The rows are founder-entered. Axal's own anonymised ventures come in a follow-up issue.
- **Builds on:**
  - D217's `research_benchmarks`, whose CHECK (no peer figure without its source and sample size) this copies;
  - D896's deck routes and their `projectOwned` gate.
- **Feeds:** the stage plan (#3774, A23) and the investor critic (#3804, C9).
- **Migration:** `746_stage_norms.sql`.

### The question

The stage plan and the critic warn when a deck lacks the proof its stage needs, for example "Seed deck with no traction slide". A warning that also compares the venture with other companies at its stage ("seed rounds show 15% month-on-month growth") is a claim about those companies, and it needs a base. Nothing at HEAD held one. Without one, the one-click run could cite an invented norm, or a model could. A deck shipped with zero edits must never carry an unsourced norm.

### What was decided

**The table** (`stage_norms`, migration 746). Each row belongs to one venture (`project_id`). It holds:
- `stage`: `pre_seed`, `seed`, `series_a` or `series_b_plus`;
- `investor_type`: one of the deck audiences, or NULL for every audience;
- `metric` and `value`, both text, so the unit travels with the value;
- `source` and `sample_size`;
- an optional `as_of`;
- `entered_by`;
- `origin`: `founder` now, and `axal_anonymised` reserved for option C so that follow-up adds a writer, not a table rebuild.

**A norm without a source is refused, by every writer:**
- The table's CHECKs refuse an empty source, a missing source and a sample size below 1.
- The route refuses them first with a sentence: 400 `source_missing` or `sample_size_missing`.
- An edit that clears either is refused the same way, and the row is unchanged.

**What a critic may cite** (`services/decks/stageNorms.ts`, callable without a route, so the one-click run and the critic read the same rows):
- `citableNorms(env, projectId, stage, investorType)` returns the venture's rows for that stage whose investor type matches or is empty. With none, it answers `{ available: false, reason: 'No stage benchmark recorded' }`. That is the line #3804 shows, and the critic then makes no benchmark claim.
- `citableBenchmark(b)` accepts a founder-entered benchmark from elsewhere only with its source and sample size. Otherwise the answer is the same block.
- Each norm carries `citation`: the figure with its base, for example "Month-on-month revenue growth: 15% MoM (Synthetic seed survey 2026, 42 companies, as of 2026-06-30)".
- An `as_of` not entered is `{ available: false, reason: 'Not recorded' }`, never a date and never 0.

**The routes** (`routes/deck_stage_norms.ts`, mounted at `/api/decks` before `decks`, so `GET /:id` cannot answer `/stage-norms`):

| Method, path | Gate | Answer |
|---|---|---|
| `GET /api/decks/stage-norms?project_id=&stage=` | `projectOwned` | `{ project_id, stages: { <stage>: { label, norms } } }`, where `norms` is a block |
| `POST /api/decks/stage-norms` | `projectOwned`, `write: true` | 201 `{ norm }` |
| `PUT /api/decks/stage-norms/:uid` | `projectOwned`, `write: true` | `{ norm }`: read, merged, checked, written |
| `DELETE /api/decks/stage-norms/:uid` | `projectOwned`, `write: true` | `{ deleted: true }` |

- The founder and accepted cofounders write. An advisor and an admin read.
- Someone who cannot read the venture gets a 404 for its rows, the same as for a uid that does not exist.

**No client or screen.** The specification asks for none: the critic and the stage plan cite these rows through their own routes (#3774, #3804), and no board draws a norm editor yet.
