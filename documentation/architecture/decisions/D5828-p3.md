## D5828 part 3 — Typeform: `needs_remap` carries field ids and status, never titles (#5828)

- **Status:** built 2026-11-24, part of #5828. Parts 1 and 2 are `D5828.md` and `D5828-p2.md`, which this file does not edit. Where they disagree, this file is later.
- **Owner answer (2026-11-24):** the no-field-titles rule also covers `needs_remap` in `GET /api/typeform/sync`. Only field ids go back to the client, even for the member whose connection holds the binding.
- **Code:** `services/typeform/importer.ts` (`typeformFormStatus` no longer selects or returns `field_title`), and the header of `routes/typeform.ts`.

### What changes

Part 2 listed each field needing a remap as `{ field_id, title, status }`. From this part it is `{ field_id, status }`. The run's own `needs_remap`, the list `POST /api/typeform/sync` answers, was already ids only and is unchanged.

`typeform_field_mappings.field_title` is still stored and still updated on a rename. It stays in the Worker: no route returns it. No migration.

### Test

`typeform_import_5828.test.ts` now compares the whole status list exactly and asserts that neither stored title appears anywhere in the serialized status.
