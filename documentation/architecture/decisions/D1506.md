## D1506 — Untrusted input framing and upload hardening (deck v2 A13, #3757)

- **Status:** built by S09, 2026-11-01 (#3757). Not deployed or live verified.
- **Spec:** the issue as revised by S1 on 2026-11-01 (#3757, comment 6550916682): Worker-only, the untrusted inputs widened to data-room documents, connector rows and the editor instruction.
- **Migration:** 718, `718_deck_images_sha256.sql`.
- **Builds on:** D897 (New deck), D899 (card tools), D903 (deck images), D1601 (connected tools as deck sources), D658/D859 (transcript framing), and #3655 (`browserRun.renderUrl`).

### 1. One frame for untrusted text (`services/ai/untrusted.ts`)

`untrustedBlock(kind, data)` wraps text written outside our code between `BEGIN_<KIND>_<nonce>` and `END_<KIND>_<nonce>`. The nonce is fresh for each block, so a fake closing line inside the data carries the wrong nonce and stays data. Every system prompt that reads a frame carries `UNTRUSTED_RULE`: a frame is read, never obeyed, and no link or email address is copied out of it.

| Kind | Where it is framed on `main` |
|---|---|
| `card_text` | Card tools (`assist.ts` `textMessage`, `chartMessage`'s heading). Imported DOCX text and PPTX speaker notes reach a model this way. |
| `editor_instruction` | Card tools' Ask (`assist.ts`), the instruction the editor sends. |
| `founder_note` | New deck's outline and build messages (`newDeck.ts`). |
| `record_fact` | New deck's facts from typed and recorded slots; Fill from project's records (`autofill.ts`); a headline's labels. |
| `connector_row` | New deck's facts whose `source` is `Connector` (PostHog, HubSpot, Linear, D1601). |
| `data_room_document` | New deck's facts whose `source` is `Document`. |
| `web_page` | Competitor positioning from a fetched page (`competitorAnalysis.ts`). |
| `transcript` | Interview and conversation transcripts (`interviewStructuring.transcriptData`). Its frame is the `BEGIN_TRANSCRIPT_…` it always had. |
| `deck_import` | Declared for the routes still to come. |

The routes for #3773 (`POST /api/decks/:id/areas/instruct`) and #3881 (data-room deck sources) are not on `main` yet. Whichever of them lands second calls `untrustedBlock('editor_instruction' | 'data_room_document', …)` before any model sees the text, as the issue asks.

### 2. The output is checked, not trusted

Framing lowers the odds of an injection working; it does not prove the output safe. So:

- Each answer must parse into its schema, through the callers' existing parsers (`outlineFromModel`, `wordingFromModel`, `chartBlock`, `batchFillParse`).
- `strangersIn(output, records)` names every link or email address that no record holds. Each caller drops what it names:
  - `wordingFromModel` drops the words, as it drops a number;
  - `outlineFromModel` falls back to the catalogue's words;
  - `wordingProblem` refuses the wording unless the founder's own text held the link or address;
  - `batchFillParse` drops the value.
- Bare domains are recognised for the common TLDs only. `http(s)://` and `www.` links are always recognised.

### 3. The figure guard in every script

- **Digits:** `numberIn` matches `\p{Nd}` (so `٣٠٠`, `३` and `３` as well as `3`), the Arabic and full-width percent signs, and Chinese and Japanese numerals (`一`, "one", is left alone, as English "one" is).
- **Number words:** they apply per language. English words always apply. A language's own words apply only to text in that language, because many are English words too (Italian *due*, German *elf*).
- **Translations:** a translation press checks the target language's words: a translation that names a figure where the founder's text named none is not placed.
- **Card tools:** the digit comparison in `wordingProblem` uses `\p{Nd}` too.
- **Known gap:** German compound numerals (*zweihundert*) are not caught.

### 4. Uploads (`services/decks/imageBytes.ts`, `routes/deck_images.ts`)

- **Size:** width and height are read from the header (PNG IHDR, the JPEG frame header, WebP VP8, VP8L and VP8X), never from the client. An unreadable header answers 415 `image_unreadable`. Over 50 MP answers 413 `image_too_large`.
- **Metadata:** stripped byte by byte, without a decoder:
  - **JPEG:** APP1 (EXIF, XMP), APP13 (IPTC), comments and the other application segments go. JFIF, the ICC profile and Adobe's colour transform stay.
  - **PNG:** tEXt, zTXt, iTXt, eXIf and tIME go.
  - **WebP:** the EXIF and XMP chunks go, with their VP8X flags, and the RIFF size is rewritten.
  - **Other files:** a file whose structure cannot be walked is stored as it was.
- **One row per picture:** the stripped bytes are hashed, and migration 718 adds `sha256` with a partial `UNIQUE(project_id, sha256)`.
  - A picture the venture already holds answers 200 with `duplicate: true` and that row.
  - A discarded copy gives up its hash, so the new one is stored.
  - A drawn image is stripped and hashed too. If the same drawn picture arrives twice, the second copy is stored without a hash.

### 5. External images and the export browser

- **Import:** `POST /api/decks/:id/images/import` copies an external image into R2 through `imageFetch.ts`, so a deck reads our copy.
  - It uses `webFetch.isSafePublicUrl`: https only, no credentials in the URL, and a public host at every redirect hop (at most three, each re-checked).
  - It has an eight-second deadline and cuts the body at the 5 MB cap.
  - The row's `source` is `upload` (543's CHECK).
- **Export:** `renderUrl` passes Browser Run's `allowRequestPattern` on every render opened by URL. Allowed: the page's own origin, `fonts.googleapis.com`, `fonts.gstatic.com`, `data:` and `blob:`.
  - An external image still in an old deck is no longer requested by an export. Copying it in fixes that.

### 6. Not built here

- Rewriting an existing deck's external image URLs on save. The editor can call `/images/import`; that is a frontend change for the pd boards.
- The #3773 and #3881 routes themselves.
- Anything tracked in the private advisories.

### 7. Verified

- **`cloudflare-worker/test/untrusted_framing_d1506.test.ts`:** 33 cases, all passing.
  - **Framing:** 23 fixtures: 4 DOCX, 4 PPTX notes, 3 transcripts, 3 web pages, 3 founder notes, 3 record facts, 1 data-room document, 1 connector row and 1 editor instruction. Each carries an injection with a fake closing delimiter, and each must sit only inside a frame of its kind.
  - **Output:** answers that obey the injection never reach the deck.
  - **Figure guard:** `٣٠٠` and `３` are refused, and number words apply per language.
  - **Images:** JPEG, PNG and WebP metadata is stripped; size comes from the header; 50 MP is refused; a repeat upload is answered from the existing row.
  - **Import and export:** `/images/import` refuses http, private hosts and a redirect to the metadata address; the export allow-list is passed.
- **Mutations:** 21, each turning a test red.
  - Skipping `untrustedBlock()` for each kind: `card_text`, `transcript`, `web_page`, `founder_note`, `record_fact`, `connector_row`, `data_room_document`, `editor_instruction`.
  - Dropping `strangersIn` from wording, assist and autofill.
  - `\d` in place of `\p{Nd}`; the translation check.
  - Keeping JPEG APP1, PNG tEXt or WebP EXIF.
  - The 50 MP check; storing raw bytes; the dedupe; the redirect-hop check; the export allow-list.
- **Existing suites, unchanged and green:** `deck_new_d897`, `deck_assist_d899`, `deck_images_d903`, `decks.autofill`, `interview_structuring_d658`, `conversation_items_d859`, `deck_export_*` and the pitch export tests.
