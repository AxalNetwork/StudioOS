## D1370 — Pitch preflight: deterministic checks that block an export only over lost content

- **Status:** asked for by the owner (#3661). Part one was built by S33 in #3670 and merged on 2026-10-29. Its draft decision text was filed by S1 under this number.
- **Builds on:** D898 (the deck block model and its 12 × 6 grid), D901 (the offline HTML export), D903 (worst-case contrast over a background image), D896 (refresh rows) and D900, which is a different thing: the evidence Check in `checkModel.js`.
- **Migration:** none. No Worker change.

### What was decided

1. **Deterministic only.**
   - Preflight gives no score and no "investor ready" verdict.
   - It rewrites nothing and corrects no figure.
   - It reads only, with no fetch and no write.
2. **No false passes.** A check it cannot run honestly reads "Not measured", never Passed (`CHECK_STATE.unmeasured`). Clipping, rendered font size and image upscale come from a real measurement of the card drawn at 1920 × 1080 (`preflightMeasure.js`). Without one, those checks read "Not measured".
3. **Blocking means the export would lose content.** Only four findings block an export:
   - an off-grid block, or two overlapping blocks;
   - more than 24 blocks on a card;
   - measured clipping;
   - an image block with no image.

   Everything else is a warning the founder may dismiss: text density, font size, contrast, upscale, alt text, theme consistency, placeholders and sources. Dismissing a warning never clears a blocking finding (`exportGate`).
4. **A result belongs to one version.** `deckKey` ties it to that version, and `currentResult` hides it after an edit.
5. **The thresholds are constants in `frontend/src/pages/raise/pitch/preflightModel.js`:**

   | Constant | Value |
   |---|---|
   | `MIN_FONT_PX` | 24 (about 18 pt at export size) |
   | `CONTRAST_BODY` | 4.5 : 1 |
   | `CONTRAST_LARGE` | 3 : 1, for headings |
   | `CARD_WORDS_MAX` | 110 words |
   | `UPSCALE_MAX` | 1.5 × |
   | `STALE_DAYS` | 120 days, for a stale source |

   Changing one is a change to this decision.
6. **Each finding is a specific fix.** It names its card and block (`{ id, check, severity, card, block, title, detail, fix, dismissible }`), so a later UI can open the affected item.
