## D675 — The public stats endpoint returns the figures the new site prints

Issue: #1549. Part of #1546 (D673).

### What changed

`GET /api/public/stats` (`cloudflare-worker/src/routes/public.ts`) keeps its four Task #18 fields (`partners`, `funds`, `deals_scored`, `spinouts`) and adds three:

| Field | Counts |
| --- | --- |
| `users` | Accounts with `is_active = 1`, the rule every other user count in the Worker uses |
| `companies` | Ventures (`projects`) with `deleted_at IS NULL` |
| `members_verified` | The rows `/directory` lists |

- **`members_verified` and the directory read share one predicate,** the exported `DIRECTORY_LISTED_WHERE` (`status = 'active' AND directory_listed = 1`), so the figure and the list can never disagree.
- **The caching and failure behaviour are unchanged:**
  - a 30-second per-isolate copy and a 5-minute KV copy;
  - a failed count answers 0 for that field and never fails the response.

### What is not served, and why

- **Countries, LPs & funds, operators & advisors:** the public directory lists partners only. It has no country column and no member type, so there is nothing to count.
- **What the pages do:** each page draws only the figures this endpoint returns, plus the module count below. The Directory and Resources pages show the listed-members figure.

### Revised 2026-10-12 (owner): Active funds, and the module count

The owner asked where the Active funds figure was, and for the total modules, counted independently.

- **Active funds counted only `status = 'active'`.** Production's one fund, Fund I, is `fundraising`, so the figure was 0 and the hero hid it. `funds` now counts every fund still open or investing: `OPEN_FUND_WHERE`, `status IN ('fundraising', 'active')`. A closed or wound-down fund does not count. The label reads "Active fund" when the count is 1.
- **The module count replaces the canvas's "Tools in the platform".** The first version served no tool count, because no single registry lists the tools. The count is now derived from the three registries that serve modules, in `frontend/src/lib/siteModules.js`, and nothing is typed:
  1. every zone the four workspace shells register (`shellConfig.js`, each guard-tested to open in `App.jsx`), except a zone the code renders with no store behind it on that licence (`noStoreCopy.js`: the advisor's profile-views zone);
  2. every founder cycle module (`pages/cycles/modules.js`, held equal to the Worker's own lists);
  3. every Spin-Out Lab tool the Platform page lists (`PLATFORM_LAYERS`).
- **Each route counts once.** On 2026-10-12 that is 74 zones and 26 cycle modules, with `/raise/data-room` in both, plus 12 Lab tools: **111 modules**. The home hero draws it first, and the Platform section reads "A sample of the 111 modules inside".
