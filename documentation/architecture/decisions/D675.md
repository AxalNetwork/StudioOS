## D675 — The public stats endpoint returns the figures the new site prints

Issue: #1549. Part of #1546 (D673).

### What changed

`GET /api/public/stats` (`cloudflare-worker/src/routes/public.ts`) keeps its four Task #18 fields (`partners`, `funds`, `deals_scored`, `spinouts`) and adds three:

| Field | Counts |
| --- | --- |
| `users` | Accounts with `is_active = 1`, the rule every other user count in the Worker uses |
| `companies` | Ventures (`projects`) with `deleted_at IS NULL` |
| `members_verified` | The rows `/directory` lists |

- **`members_verified` and the directory read share one predicate,** the exported `DIRECTORY_LISTED_WHERE` (`status = 'active' AND directory_listed = 1`), so the figure and the list can never disagree.
- **The caching and failure behaviour are unchanged:**
  - a 30-second per-isolate copy and a 5-minute KV copy;
  - a failed count answers 0 for that field and never fails the response.

### What is not served, and why

- **Countries, LPs & funds, operators & advisors:** the public directory lists partners only. It has no country column and no member type, so there is nothing to count.
- **A tool count ("Tools in the platform"):** the app keeps no single registry of its tools, and a hand-kept number would be invented.
- **What the pages do:** each page draws only the figures this endpoint returns. The home hero now shows Users, Companies and Active funds. The Directory and Resources pages show the listed-members figure.

### Guards

`cloudflare-worker/test/public_stats_site_d675.test.ts` runs the real queries on SQLite. It pins:
- each field's definition;
- the directory figure equal to the directory list's length;
- one failing count leaving the others intact.

Four mutants were killed:
- inactive users counted;
- deleted ventures counted;
- unlisted partners counted;
- the directory list drifting from the figure.
