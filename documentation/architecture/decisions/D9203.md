## D9203 — Indexes for the three reads that scanned whole tables (#9203)

- **Status:** built by S27 on #9203, 2026-11-27.
- **Chosen by:** the coordinator audit of 2026-11-27 (PR-11), as scoped on the issue.

### The problem

Three hot reads filtered on columns no index leads with, so SQLite planned a `SCAN` of the whole table:

| Read | Statement | Why it scanned |
|---|---|---|
| `services/agents/skillRubric.ts` `monthSpend` | `ai_usage_logs WHERE surface = ? AND created_at >= ?` | no `ai_usage_logs` index starts with `surface`; the table gains a row per AI call |
| `services/agents/runActivity.ts` `heldFor` | `ai_budget_reservations WHERE execution_id = ?` | no index on `execution_id` |
| `services/fundLedger.ts` `postLedgerEntry` | three subqueries `fund_ledger_lines WHERE entry_id = fund_ledger_entries.id` | the only index, `idx_fund_ledger_lines_entry`, is `(fund_id, entry_id, account_id)` |

### The decision

- `cloudflare-worker/sql/migrations/202611272339_9203_ai_usage_surface_and_reservation_execution_indexes.sql` adds `idx_ai_usage_logs_surface_created ON ai_usage_logs(surface, created_at)` and `idx_ai_reservations_execution ON ai_budget_reservations(execution_id)`, both partial on `IS NOT NULL` (an equality on the column implies it), both `IF NOT EXISTS`. Additive only; rollback is `DROP INDEX`.
- The posting `UPDATE` names `fund_id = fund_ledger_entries.fund_id` in each subquery, so the existing index serves them. No new index. The `(fund_id, entry_id)` foreign key on `fund_ledger_lines` means it selects the same rows, so the totals do not change.

### How it is held

`cloudflare-worker/test/scan_indexes_9203.test.ts` captures each statement from the code as it builds it and runs `EXPLAIN QUERY PLAN` on the migrated schema: each must `SEARCH` its table through the named index, never `SCAN` it, and the posting `UPDATE` must search the lines index three times. It fails on the schema and code before this change. `fund_ledger_d628.test.ts` still posts the same totals.
