## D4623 part 3 — Apply in the Spin-Out Lab only for a Founder holder or an exploring account (#4623)

- **Status:** Part 3 of #4623, a follow-up to part 2 (D4623-p2, PR #5739). Owner decision of 2026-11-13.
- **No migration. No new route. No new `/api/*` client method.** `POST /api/spinout-lab/apply` is unchanged.

### The question

Part 2 left one thing unverified. The multi-licence Lab block passes `investorView={false}`, so an Investor-primary member who also held Advisor or Operating Partner was offered Apply in the Lab block. `POST /api/spinout-lab/apply` accepts only a Founder holder or an exploring account (`holdsLicence(user, 'founder') || user.role === 'exploring'`), so their submission was refused. A single-licence Advisor or Operating Partner was offered the same refused Apply.

### What was decided

**Owner's answer (2026-11-13): Apply shows only for Founder holders and exploring accounts.** The UI now follows the server's rule. The server is unchanged.

1. **The multi-licence Lab block** (`MultiLicenceSpinoutLab.jsx`) passes `canApply={held.includes('founder')}` beside `investorView={false}`. It reads the licences the block page was drawn for, the same source as the blocks. An exploring account never reaches the block page (`multiLicenceSet`), so Founder is the whole test there.
   - Investor-primary with Founder: Apply, no LP section. Unchanged from part 2.
   - Investor-primary with Advisor or Operating Partner, without Founder: the Lab block without Apply, and without the LP section. The Lab block is not the investor view.
2. **`SpinoutLabPage` takes an optional `canApply`.** Left undefined, the page reads the same rule from the session's held licences (`resolveHeldLicences({ user })`, the source of the block page's licences) and `user.role === 'exploring'`. It never reads a role display string.
   - **This changes the single-licence page.** A single-licence Advisor or Operating Partner was offered Apply, and the server refused it. They are no longer offered it. The change is the same rule in the same place, so it was made here rather than reported.
   - A single-licence Founder and an exploring account are unchanged.
   - An admin preview never reaches the overview: an admin gets the workspace preview first. An impersonation reads the impersonated member's licences, as the server does for that member.
3. **"No Apply" means every Apply on the signed-in overview.** Before, the Apply section (`ApplyCtaSection`) was the only one gated, but the overview also carries Apply in the hero and in the closing apply band (`LabIntro`). `LabIntro` takes `canApply`, which defaults to true. With false:
   - the hero drops its Apply button and keeps "Download the programme brief";
   - the apply band ("How to apply") is not drawn;
   - the Apply section is not drawn. The application status card is still drawn, so a member with an application still sees its status.
   The public marketing page passes nothing and is unchanged.
4. **No line stands in place of Apply.** No canvas or design defines one, so Apply is just left out.

### Departures, and why

- **The LP view's hero.** When the page draws the LP section (`investorView`, which is still `user.role === 'investor'` when undefined), the viewer is also refused by the apply endpoint. So the hero's Apply button and the apply band are now left out there too. The route sends a single-licence investor to `SpinoutLabInvestorPage`, so this view is rarely drawn.

### Tests

`frontend/test/multi_licence_pages_3704.test.mjs`, reading what React drew. The checks look at the Apply section (`apply-cta-sub`), every link to `/spinout-lab/apply`, the apply band and the LP section:

- Investor-primary with Advisor, and with Operating Partner, without Founder: no Apply anywhere, no apply band, no LP section, and the Investor block is drawn beside it;
- Investor-primary with Founder: the Apply section, and three Apply links (hero, section, band);
- the block page hands the Lab page `canApply` equal to "Founder held" for five licence sets. A single licence hands nothing;
- the bare `SpinoutLabPage`:
  - an investor gets the LP section and no Apply;
  - a Founder and an exploring account get Apply;
  - an Advisor and an Operating Partner get neither;
- an Investor-only member draws no Apply link.

**Mutation check:** each guarded expression was broken by hand, the file run (it failed), and the line restored (it passed):

- the block's `canApply` forced true, then forced false;
- the Apply section, the hero button and the apply band each left ungated;
- the exploring clause dropped;
- the default rule reading `advisor`, and the default ignoring the session;
- the Lab block made the investor view.
