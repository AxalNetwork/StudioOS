## D6250 part 2 — The issued fund report, printed on several pages (#6250)

#8154 shipped the reader and its print stylesheet but left the multi-page print unverified. This part prints it in Chromium and keeps that check in CI.

**What was checked.** `frontend/tests/e2e/report_print_6250.spec.js` uses the built SPA with an invented LP and a long issued period: 14 letter paragraphs (one with a 120-character unbroken URL), 10 developments, 4 outlook paragraphs, 6 subsequent events and the ten report-pack figure rows. It runs in light and dark themes:

- **Print media.** Only the reader is drawn. The sidebar, top bar, Worker rail and Report actions row are not, and no ancestor of the reader clips it or takes it out of flow. The reader fills the page width and none of its elements overflows its box. All text is `rgb(0, 0, 0)`, every background is white, no card keeps a border or shadow, and the page's colour scheme is not dark.
- **Letter and A4 PDFs** (`page.pdf`, 0.5 in margins, backgrounds on), read back with pdfjs. The report runs to more than two pages: 7 on Letter and 6 on A4. Page 1 opens with the masthead (fund, period and dates, issue stamp, issuer, both correction links). Every paragraph, event, figure label and amount reaches the PDF. Every text run lies inside the margins. No development or subsequent event is split across pages. No section heading ends a page. The letter's closing line sits on the same page as its last event. The "Figures as issued" column prints whole on the last page. No app chrome text is printed.

**Two discrepancies were found and fixed** in the print block of `frontend/src/pages/fundPage.css`:

1. **Dark theme margins.** In the dark theme, `html.dark`'s `color-scheme: dark` painted the page margins near-black whenever backgrounds printed. The text and cards were already black on white. The print block now sets `color-scheme: light` on the reader's `html`.
2. **Split figures column.** The figures column split across pages: its heading and first row stayed at the bottom of one page and the rest moved to the next. It is short, so it now carries `break-inside: avoid` and prints whole after the letter.

**Left as found.** The printed title, which is the browser's print header and the default PDF file name, is the app's generic document title. No page in the app sets a per-page title, so this part does not add one. In a report-pack period, a figure row with no recorded amount shows "Not recorded" without its recorded reason. That happens on screen as well, because `issuedFundRows` keeps only `why || note`, so it is not a print discrepancy and is outside this part.

**CI.** The `visual` job of `.github/workflows/ci.yml` runs the spec after its public-journey step, on the `docs/` that job builds and with its pinned Chromium, using `--retries=0 --trace off`. The `visual` job's digest pin in `frontend/test/ci_capacity_pilot_7909.test.mjs` moves to the new digest, as it did for #8537 and #7808. Locally: run `npm run build` at the root, then `cd frontend && npx --no-install playwright test -c playwright.config.js tests/e2e/report_print_6250.spec.js --trace off`.
