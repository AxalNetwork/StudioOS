## D9257 — The commits a merged-in pull request brings are exempt from the identity chain's one-slot rule (#9257)

**Date:** 2026-11-28. **Status:** Built. The owner chose option B on 2026-11-28.

### Context

`scripts/ci/agent-provenance.mjs` (D8068, #8068) requires that a pull request's commits name one slot and one task. In #8606, a commit GitHub writes by merging another pull request into the branch (listed by `--pr-merges`) became exempt. AGENTS.md § "Identity trailers" says that pull request's "own commits were checked on its own branch". But only the merge commit was exempt. The merged pull request's own commits were still checked against this branch's slot and task.

On 2026-11-28, several pull requests were merged into agent branches. `provenance` then failed on PRs #9230, #9235 and #9241, with "the range names 3 slots" and similar errors, even though every commit carried a valid chain.

### Decision

`mergedInCommits` marks the commits a listed pull-request merge brought into the range, and `checkCommit` exempts them (`prMergedIn`). The report prints them as `brought by a pull request merged into this branch, exempt`.

- **Which commits count.** For each merge on the `--pr-merges` list, they are the commits in the range reachable from its second and later parents, minus those reachable from its first parent. The first parent is the branch's own line.
- **The branch's own commits are still judged.** A commit reachable from both sides is still checked, for example one the other branch was cut from. So is any commit after the merge. Only commits inside `base..head` are walked.
- **Nothing changes without the list.** The list comes from GitHub's API in the workflow, not from the branch. With no `--pr-merges` list, nothing new is exempt, and a merge the branch authored itself is judged as before.

The workflow runs main's copy of the script, so the three pull requests above pass on their first run after this change lands.
