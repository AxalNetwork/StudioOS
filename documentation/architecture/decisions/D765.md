## D765 — One run path for every rail option: the Worker enforces the page's switch, and every member run carries its page, option and record

- **Status:** S07, 2026-10-19 (#2090; task A6 of D720's plan, #1874 §6 and §7). PR 1 writes §1–§5. PR 2 (no run without a press) adds §6, with the owner's two rulings of 2026-10-19 (stop the automatic digests; Stop transcribes only until D770).
- **Basis:** `origin/main` at `215bf9ae`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D762 (migration 493's `rail_page`, `rail_option` and `record_ref`) and D763 (the guard inside `run()`). It reads migration 465's `ai_rail_preferences` as it is today; D764 PR 2 (#2089) re-keys its rows by D720's page keys, and D768 gives the browser those keys.

### 1. `RunOptions.rail` and the switch in `run()`

- `RunOptions.rail = { page, option?, record? }` (`services/aiRouter.ts`, `RailContext`). `run()` copies it into `railPage`, `railOption` and `recordRef`, so the log row records the member (`user_id`), the charge (D762) and where it was spent.
- When `rail` is set, `run()` reads the member's mode row for the page: `ai_rail_preferences` with `section` = the page, trimmed and lower-cased, and `task = ''`. `mode = 'manual'` is off, and the run is refused **`assist_off`**, "AI assistance is off on this page."
  - The check comes first, before the cache, the hold and the guard, and writes **no usage row**: nothing ran, and nothing is held or charged.
  - No row is on (D720 §6: AI is on by default). The browser's own default stays off until D769 PR 2 flips it, so today the Worker refuses only a page the member explicitly turned off.
  - A database without migration 465's table has no switch to read, so it is on. Any other read failure refuses `misconfigured` ("could not be checked") rather than guess, again with no hold and no row.
- **Saving is untouched.** A transcription (`route.isAudio`) is never refused by the switch: transcribing a member's own recording is saving. Summarising and placing are assistance and obey it.
- A call without `rail` is a system call and is not switched.

### 2. Recording the page

- `rail_page` takes the rail's keys as they are: letters, digits, spaces, `&`, `·` and `/_.:-`, at most 160 characters (`railPageKey`). The workspaces ("Perks & Products") and D720's page keys ("Founder · Validate") need the spaces, `&` and `·`.
- `rail_option` and `record_ref` keep D762's stricter rule (`railKey`).

### 3. Every member call passes rail context

- The browser sends the page in `X-Rail-Page`, and the open option in `X-Rail-Option`, URI-encoded, from `frontend/src/lib/railPage.js`. `WorkerRail` sets the page to its `workspace` (the key the switch is stored under) while it is mounted, and `request()` and `rawRequestHeaders()` merge the headers. D768 replaces the workspace with its page keys.
- A route builds `rail` with `railFor(c, fallback, record?)` (`util/railContext.ts`): the request's page and option where they are valid keys, else the route's own. So a run from a client that sends nothing still carries context and still obeys the switch.
- Every member call of `run()` passes it: `/api/ai/workspace/explain`, `/api/eadwyn`, the advisor's explain, tool pick and dictation, Validate's propose and recording transcription, `/api/research/ask` and the drafts alias, Brand's fills, onboarding chat, and the services those routes call (interview structuring, asking and summarising, chunk transcription, deck review, competitor analysis, citations, the advisor reranker, Grow's update draft and HQ's publication draft). A service takes the press's `rail` where its route has one, and otherwise names its own page.
- `test/rail_run_path_d765.test.ts` lists every call of `run()` outside the router, by the name each file imports it under, and fails on a call with no `rail`. System callers are an explicit allow-list, each with its reason: the legacy advisor guard's `safety` check, and `paraphraseForSnippet`, which has no caller.

### 4. The answer

- A route that runs a press answers `assist_off` with **403** `{ error: 'assist_off', message: 'AI assistance is off on this page.' }` (`refuseAssistOff`). Validate's structuring, asking and summary answers carry the same words (`refusedBody`, 403 in `refusedStatus`).
- A helper that already degrades to a non-AI answer on any refusal keeps doing so: Brand's heuristic copy, the deck's heuristic sections, the reranker's order, onboarding's "Save & continue".

### 5. What this changes for Validate's Manual mode

- Until now, Manual (the `''` row's `'manual'`) only stopped Validate's automatic runs: the founder's Summarise and Structure buttons, and the recorder's own summary after Stop, still ran (D757, `validate_engine_d757.test.ts`).
- D720 §6 makes that row the page's AI switch, and this PR enforces it in `run()`. Under Manual those buttons now answer 403 `assist_off`, and the recorder's summary is refused with the same sentence. Transcription still runs. The D757 test is updated to say so.
- The browser's switch is still labelled "Eadwyn | Manual" until D769 draws "Turn off AI assistance on this page".

### 6. No member run starts without a press (PR 2)

**No GET calls a model.**
- `GET /api/advisor/next-question` and `POST /api/advisor/start` (which the page calls on mount) take the bank's order. Only `POST /api/advisor/next-question`, the "drill in" press, lets the reranker run (`pickNextQuestion`'s `rerank`, false unless a press passes true).
- `GET /api/networkfx/syndicates/:id/recommendations` is `POST` now (D720 §9). The page already called it from a button.
- `GET /api/monitoring/anomalies`, which the page loads and polls every minute, answers with the heuristic summary. The Workers AI summary is `POST /api/monitoring/anomalies`, the admin's "Summarise with AI".
- Two GETs reach a model and stay, each named with its reason in `test/rail_no_run_without_press_d765.test.ts`: `GET /api/search`'s semantic mode embeds the query to look it up (retrieval, no page calls it), and `GET …/sessions/:id/live` is the recorder's live transcription, opened by the member's Start (saving).

**No interview is summarised or placed on its own** (the owner: "stop them"), with two exceptions.
- An imported call, consent given after a call, a pasted chat or typed notes and an AI assistant's submission are stored and transcribed as before, and queue nothing. The founder presses Summarise or Structure.
- **The owner's two exceptions (2026-10-19):** a channel chat's final text (`chat_text_added`, from D757 #2068, and the quiet-chat sweep's `chat_quiet`) and a consented voice note (`voice_note_added`, D754 and D756 #2083) still queue the engine on their own. `sweepQuietChats` keeps its cron line, and `enqueueSessionStructure` stays for it. `test/rail_no_run_without_press_d765.test.ts` holds the list to exactly these three triggers.
- The `session_structure` job also runs what a press queues (D770).

**Stop and Retry transcribe only** (the owner: until D770's Stop sheet lands).
- `POST …/sessions/:id/finish` summarises and places only on an explicit `auto: true`; absent is transcribe only. The browser sends `auto: false` and no longer reads the page's mode (`RecordLivePage.jsx`, `activeRecording.js`, `interviewSessions.finish`).
- `recoverSession` keeps the stored choice and reads a row that never recorded one as transcribe only (`COALESCE(processing_auto, 0)`). A retry whose transcript is already in resumes at the summary only when the member chose it; otherwise there is nothing left to run.
- The sweeper's resume of a stale run carries the same stored choice, so it only finishes what a press started.

**A job no member started is a system call.**
- The `ai-workers/` jobs (deal scoring, traction review, valuation and buyer matching, LPA drafting, equity) called the deprecated 8B through `env.AI` directly, with no log row. They go through `ai-workers/systemRun.ts` now: the router's new `system_job` route (`llama-3.1-8b-instruct-fp8`), `userId 0`, so each is logged at cost and charged to no member.

**Still outside `run()`, for D766:** `persona-router.ts` (`POST /api/personas/classify`), `pipeline.ts` and `networkfx.ts` `llmText` (both on POST now), `legalcap.ts`, `admin_x.ts` (LLaVA on uploads), Brand's `aiLogo`, and the embeddings in `vectorize.ts` and `market_intel`.
