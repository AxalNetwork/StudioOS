### Still open: editing key results on the item

The canvas (BLR01B) draws key results on the item sheet as "Not recorded · read only by the roadmap editor today". The requires-engineering note says only that PATCH accepts `key_results`. No board draws an editor.

The stored shape is a list of `{ text, target, current, unit }`. `current` is also written by the `/execution` editor and by the Google and Notion feeds, so a plain text field would overwrite progress. The owner's call:

- **A.** Draw, then build, a key-results list editor on the item. Each row has text, target and unit. `current` is shown but never written by the form, and the PATCH merges by row. This needs a canvas board for the editor and a list field in the record forms.
- **B.** Let the item edit only each key result's text, as a list of lines. Target, current and unit stay with the feeds, and new lines start with no target.
- **C.** Keep key results read only on the item and say where they are set. This partly reverses Q2 A for key results.

Pick: **A**. Q2 A puts key results on the item. Only a row editor that never writes `current` keeps the feeds' progress true. It needs one canvas board before it can be built.
