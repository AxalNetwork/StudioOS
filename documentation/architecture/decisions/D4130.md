## D4130 — The full suite runs in parallel parts, and main does not re-run what the queue verified (#4130)

**Context.** On main at c8c362cd17 (2026-11-02) the `test:drift (full suite)`
job took 74 minutes on one runner. Every other CI job finished in under 3
minutes. Of those 74 minutes, the guards, types and lint took under 2; the
rest was the frontend (1,247 files) and worker (1,207 files) test suites. The
job ran on every push to every pull request, drafts included, and again on
main after each merge. The PR preview Worker was built and deployed on every
push to a draft too. The owner asked for faster checks and less consumption,
without giving up code quality or security.

**Decision.**

1. **The suite runs as parts, in parallel.** `scripts/test-drift-parts.mjs`
   derives the parts from `package.json`'s `test:drift`:
   - `test:frontend` as 2 shards and `test:worker` as 6, each the same
     command with node's own `--test-shard=i/N` after `--test`, so every test
     file runs in exactly one shard;
   - `rest`: every other step of `test:drift`, in order (meeting bot,
     retention, guards, types, lint, dark mode).

   `ci.yml`'s `suite` matrix runs one part per job, `fail-fast: false`, so a
   red part does not hide another. The required check keeps its name,
   `test:drift (full suite)`. It is now a job that `needs` the parts, runs on
   `always()` (a skipped required check reports as passed), and passes only
   when every part passed. The ruleset and the merge queue are unchanged.
   Locally, `npm run test:drift` is still the whole suite.
2. **Main does not re-run a commit the queue already passed.** The merge
   queue merges the very commit it tested. On a push to main, the `verified`
   job looks for a successful `merge_group` run of `ci.yml` on that exact
   SHA. It looks four times, 20 seconds apart, because the queue run can
   still be closing when the push starts. Only when it finds one are the parts
   skipped, and the gate names that run. When the queue is off, nothing is
   found, or the lookup fails, the full suite runs. Main still finishes a run
   for every commit (D1279).
3. **Drafts get no preview.** `pr-preview.yml` deploys on `ready_for_review`
   and on every push after, never for a draft. Cleanup on close runs for every
   PR. The `login-e2e` job follows its preview, so it runs once the PR is ready,
   before any merge.
4. **npm is cached** in the parts, keyed on the three lockfiles.

**What checks it.**
- `frontend/test/ci_suite_parts_4130.test.mjs`:
  - the parts' union is exactly `test:drift`, with no step dropped, added or
    run twice;
  - each shard is the unchanged command plus the flag, for every i from 1
    to N;
  - the matrix lists exactly the parts.
- `frontend/test/merge_queue_ci_4107.test.mjs`:
  - the aggregator is the only required check allowed `if: always()`;
  - it has exactly two ways to pass;
  - it trusts a queue run only on a push;
  - the lookup reads only `merge_group` runs of `ci.yml` on `github.sha`;
  - a job a required check needs must run in the queue.
- `frontend/test/copilot_setup_steps.test.mjs` mirrors the `suite` job.
- `frontend/test/pr_preview.test.mjs` pins the draft rule and the cleanup.

All 14 mutations of the workflows and the parts script were caught by these
tests.

**Not done, and why.**
- **Skipping tests on docs-only pull requests.** 246 test files read
  `documentation/` or `design/`: decisions, the route map, the folder
  READMEs. A "docs-only" change can break them, so skipping would weaken the
  gate.
- **The Claude review on drafts.** `CLAUDE_REVIEW_DRAFTS=false` (repository
  variable) turns it off without code. That is the owner's setting.

**Found on the way.**
- **The worker suite's cost is mostly schema setup.** 178 worker test files
  each build a database from `schema_baseline.sql` plus 409 migrations, about
  5 to 10 seconds per file. Building it once per run and copying it into each
  test would cut most of the worker suite's time. It touches 178 files, so it
  is its own task.
- **Main's `.github/workflows/README.md` listed `gitleaks.yml` twice.** A union
  merge kept both versions, and `check-folder-docs` failed on main. The older
  row is removed.

**Cost.** The runner-minutes per run stay about the same: each part repeats
the install and the SPA build, about a minute. What changes is the wall time
to a result, and the runs and deploys no longer made: main's second run of a
queue-verified commit, and the preview for every draft push.
