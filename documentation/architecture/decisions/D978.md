## D978 — People and one person: the network as one table with its search, filters, sort and pages in the address, the bulk add to the deck roster and the CSV, and a person drawer that composes three reads with Pause and the directory switch asked in the page (#2764)

- **Status:** decided and built by S14, 2026-10-25 (#2764, part 6 of Advisors & Partners, #2369).
- **Canvas:** `design/incoming/Advisors Partners Page.dc.html`: AP3 (People), AP4 (the person), AP9c (Pause), AP13b–c (the phone).
- **Basis:** D972's page (#2742), D973's people reads (`routes/admin_network_reads.ts`), D976's standing and writes (`routes/admin_network.ts`, `services/networkStanding.ts`, migration 552), D974's roster (`/api/admin/network-profiles`), D980's card dialog.
- **Migration:** none. **Worker:** no change. Every read and write here already exists.

### 1. People (AP3)

`/admin/advisors-partners/people` is a tab of D972's header. It reads `GET /api/admin/network/people` and nothing else (no Overview read).

- **The address is the state.** `q`, each filter (kind, skill, sector, lab_host, profile_check, kyc, on_deck, firm_attached, active_deal), `sort` and `page` are search params; defaults are left out. A link to a filtered list opens that list. The read is asked `limit=25&offset=(page-1)*25`.
- **The columns:** name with headline, kind, firm, skills, stage, profile check, KYC, Lab host, sessions in 90 days, rating, terms (an advisor's rate, a partner's first active deal), deck and last active. Each is its block's words: a value, "Not recorded" with the block's reason (in the title and to a screen reader), or "Unreadable". None is ever a zero. A partner with no firm reads "No firm", flagged.
- **States.** The read's 503 (a filter whose source failed) is the list Unreadable with Try again. A list answered with `available: false` draws its rows under a line saying some people could not be read and the total is unknown; the page line then reads "1–25 of an unknown total". An empty network says "No advisors or partners yet." with doors to Partner invitations and the Deck roster; a search that finds no one says "No one matches ‘q’." with Clear the search.
- **A phone** (below `lg`, `usePhoneWidth`) draws cards, not the table.
- **Picking rows** opens a bar with the count, Add to deck roster, Export and Clear. Picks survive paging.
- **Add to deck roster** opens a dialog that first reads the roster (shown, hidden and archived) and lists each picked person as "Will be added", or "Skipped" with why: a deck-only name is already on the roster, and a member whose account a card already links is skipped. Each card is created hidden (`is_active: false`) and linked to the account, so the next deck built does not change until someone shows them on Deck roster. A failed roster read adds nothing.
- **Export CSV** pages through the same search and filters at 100 a call and hands over one file. A page answered with `available: false` refuses the export, because the file would be incomplete. Every cell is the table's words, so a missing value reads "Not recorded" in the file too; a field opening with `= + - @` is prefixed with `'`.

### 2. One person (AP4)

`/admin/advisors-partners/people/:ref` opens over People (a centred lightbox on a desktop, a full-screen page below `lg`). Closing goes back to People with the list's search kept.

Three reads, each its own block, so one failing never blanks the others:

1. D973's `GET /people/:ref` — the person, profile, work, terms and history. A 404 says no one has that reference; a 503 is Unreadable with Try again.
2. D976's `GET /people/:userId` — stage, pause, directory, payout and agreement. Skipped for a deck-only name. D976's blocks have their own shape (`{available: true, …fields}`, `{recorded: false, reason}`, `{available: false, reason}`), read by `standingCell`. If it fails, the standing says so and Pause and Hide are not offered.
3. The roster list — whether a card is linked to their account. If none is, "Add to deck roster" opens D980's card dialog filled in from the person (name, kind, headline as role, the account-linked firm as company, the account link), hidden.

Sections: Profile, Standing (profile check, KYC and Lab host, each linking to where it is decided; the advisor directory listing; the pause and its reason), Work, Terms (payout and agreement from D976, since D973's are not recorded), Deck, History.

### 3. Pause and the directory switch (AP9c)

Each opens an in-page dialog that says what it changes before anything is written; there is no browser pop-up.

- **Pause** needs a reason (up to 1,000 characters). For an advisor: new bookings stop and they are hidden from the advisor directory and Spin-Out Lab office hours; bookings already made stay. For a partner: the stage reads Paused and nothing else changes. The result says the write's `effects`.
- **Resume** needs a reason too.
- **Hide from / Show in the advisor directory** is offered only for an advisor with an advisor profile and a listing D976 read. It says it is not a pause.
- A refusal (`reason_required`, `already_paused`, `ended`, `not_paused`, `not_an_advisor`, `already_hidden`, `not_hidden`) is a sentence in the dialog.

### 4. Rulings

- **Stage is shown, not filtered.** D973's list answers every stage as "Not recorded" with its reason, and refuses a `stage` filter with 400. The column shows the reason; a stage filter waits for the Worker to put D976's stage into the people read (a follow-up, not this part).
- **A member's deck column is D973's "Not recorded".** The drawer reads the roster's `linked_user` instead, which is where the link lives.
- **No per-member record route exists.** The drawer's account door is `/admin/accounts/all`.
