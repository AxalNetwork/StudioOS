### 2. What is read, and from where

| Read | Used for |
|---|---|
| `GET /api/admin/catalog/products`: every product in the D1 mirror with its prices, the account's mode, the audience labels | The tab count, the Active products tile, the grouped table |
| `GET /api/admin/stripe/config`: the masked publishable key, `configured`, the account's mode (from the secret key's prefix) | The Stripe tile, Account, Publishable key |
| `GET /api/admin/stripe/webhook`: Stripe's endpoints, `is_ours`, `missing_events` against `required_events`, `our_url` | Needs you, the Webhook block |
| `GET /api/admin/platform/summary` → `payments_catalog` (`requireSuperAdmin`): the publishable key's own mode, the mirror's counts and last write, webhook deliveries in 24 hours | Keys match, Last sync, the webhook tile, Deliveries, Catalogue mirror |

- **Each read answers alone,** and a failed one marks only its blocks:
  - a failed config read says "This is not a claim that Stripe is off.";
  - a failed webhook read says "Could not be read. Stripe did not answer.", never "Loading" for ever;
  - a failed catalogue says "We could not load the catalogue. The rest of Payments still works."
- **Keys match is two reads:** the account's mode from the config read and the key's own mode from the summary. Either missing is "The key's mode was not checked", never a match. A mismatch is a Needs-you card and an amber line on Stripe connection.
- **`required_events` is what the handler acts on** since #2393, so a missing event is drawn as missing, and an endpoint of ours that is disabled, or none at all, is a Needs-you card.
- **Prices in the canvas's words:** "20.00 USD / month"; a price charged every 3 months says so (checkout would sell it as monthly); amounts in different currencies are never added.
- **The page never shows or takes a secret key.**
