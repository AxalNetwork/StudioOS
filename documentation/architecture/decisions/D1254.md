## D1254 — Venture scorecard Worker integrity, visibility and status boundaries

Issue #3277, part 1 of #2428. Slot S04, session s31. No migration.

## Behavior

The request boundary already reserves `ai_adjustment` (issue #2442);
both scoring engines now also ignore that field for direct callers. Complete
new results retain the legacy adjustment column as zero. Missing official
inputs still return no score, with their reason; historical snapshots stay intact.

An official, practice or intake score never promotes, rejects or advances a
venture or a deal. Intake keeps the project's initial status and idea stage
and creates an applied deal independently of the score. This is an application,
not a raising decision. A person's separate status action remains authoritative.
Tier classifications remain score metadata, not instructions to change status.
The intake audit records the snapshot reference and outcome, not score figures.

Investor Screening is filtered through the same readable-deal predicate as the
deal reader before the queue limit and before selecting any snapshot. It uses the centralized verified
bulk read (the batched equivalent of `getVerifiedLatestSnapshot`), including
approval, signature and `logScoreRead` auditing. Unrelated deals are absent;
flagged, rejected, unsigned and tampered snapshots supply no investor score.
Admin review details remain admin-only. Venture risk already restricts investor
single-project reads to readable deals; its matrix and writes remain internal.
Those gates and verified, audited reads are retained and regression-tested.

Issue #3277 explicitly requests investor Screening through the deal relationship;
this enables that read where the previous route refused investors. Every row
and score/empty count is computed after filtering; flags are unavailable to
investors, and the remaining metadata is static rubric/unavailable wording.
Tests pin the full scored projection and response keys with 201 unrelated
newer deals, plus an unrelated investor's zero counts. The current canonical
deal reader permits an invitation or any commitment, including historical
deals/withdrawn commitments. The pre-limit SQL and canonical bulk recheck agree
on those cases; this task does not invent a new deal-access policy. Trust's
shared-open-deal predicate is intentionally stricter and remains separate.

Risk already omits unscored layers from its numeric mean, reports covered and
total layers, preserves a recorded zero, and returns null with a reason when
nothing is scored. Trust batches already return null/Not recorded when there
are no obligations. This change retains those fixes rather than manufacturing
new zero or perfect scores. Investor trust reads now require a counterpart on
a shared open deal; an intro alone is insufficient. Self/admin rules and the
other roles' existing intro rule remain. One unauthorized target refuses a
whole batch; counterparties receive no obligation detail.

`scoreAccess.ts` carries the shared trust predicate; the routes consume it.
No new endpoint, client method, model scope, weight, scorecard, protected trait,
identity/KYC input, migration, or production write is introduced here.
