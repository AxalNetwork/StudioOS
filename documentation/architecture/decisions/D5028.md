## D5028 — Revenue tells the truth about promo-ceiling enforcement, and keeps five facts apart (#5028)

#5028 (slot S12, taken at the owner's request, P0). `/admin/revenue` told the operator "Nothing at checkout checks a code against it yet: a branch can issue past its ceiling and no payment is refused because of it". That was true until D4855. D4855 (`services/promoRedemption.ts`) reserves a discount against the active ceiling in one conditional write and refuses one that exceeds what is left. The page contradicted production.

### Decision

1. **The editor says what D4855 built** (`CEILING_ENFORCEMENT`, replacing `CEILING_NOT_ENFORCED`), one sentence each:
   - a ceiling HQ set and the branch holds is enforced at checkout, atomically (the branch refuses a discount above what is left; two checkouts cannot both take the last of it);
   - a branch with no ceiling for the current quarter allows discounts until HQ sets one, which is the owner's option B and neither 0 nor unlimited;
   - a ceiling the branch holds but cannot read refuses the discount;
   - saving stores it at HQ and pushes it to the branch: two facts, and the push can fail alone; a ceiling the branch has not received is not enforced;
   - the branch counts what it gives, but HQ does not receive that figure automatically: Issued and Remaining are what the branch reported, and Not recorded until it does.
2. **Five facts per ceiling, never derived from one another** (`ceilingFacts(row, currentPeriod)`): saved at HQ; pushed to the branch (`pushed_at` not older than the last save, so a re-save whose push failed reads "The latest figure was not pushed", not "pushed"); enforced by the branch (only a ceiling for the current quarter that the branch has received; an earlier figure is what the branch enforces when the latest save did not reach it; another quarter's ceiling governs no checkout now); issued reported to HQ or "Not reported to HQ"; remaining known only when an issued figure was reported. A reported issued figure of 0 is a figure; an absent one is not, and no remaining is shown for it even if one is supplied.
3. The note under the list now says the branch counts and enforces the ceiling itself while HQ's copy stays Not recorded until a report arrives.

### Checked, not changed

Nothing writes HQ's `licence_promo_ceilings.issued_cents` (D266 retired the pull, and `branchOps.applyPromoCeiling` leaves it alone), so the limitation the issue asks to keep explicit is real. No Worker change was needed: the list already returns `pushed_at`, `updated_at`, `issued_available` and a null `remaining_cents` for an unreported issued figure.

`revenue_ceiling_enforcement_5028` (5): the stale claim is absent from the page's code, the copy and the rendered editor, and fails if it returns; the copy states each D4855 point; the five facts in every combination; no remaining without an issued figure; the table's wiring and no remaining worked out from the ceiling.
