## D4356 — Incorporate's "Open a bank account" step, with Mercury (#4356)

- **Status:** built by slot S21 on 2026-11-04. Closes #4356.
- **Migration:** none. No new route: the step reads `GET /api/mercury/personal/status`, which already exists and now also names `open_account_url`.
- **Supersedes:** D1414 §2, Q7 ("no bank link"). The owner has chosen Mercury as the bank partner.

### What was decided

**The boards it borrows from.** No board draws this step by itself, so it is assembled from two that do:
- **INC3b**, the status timeline, whose last stop is "bank". The bank is a row after Filed (and after the EIN row), drawn only once the order is Filed.
- **INC4**, Done, whose next steps are bank, cap table and 83(b). The bank is the first card in that grid.

**What it says and links to.**
- The step is titled "Open a bank account" and names Mercury as Axal's bank partner.
- **Open a Mercury account ↗** opens in a new tab (`noopener noreferrer`). It goes to the status read's `open_account_url`: the owner's referral link when one is configured, else Mercury's public site (`https://mercury.com/`). When no address was read (a failed read, or one that is not https), no Open link is drawn, never a guessed one.
- **Connect Mercury** goes to the existing connector page, `/account/connectors/mercury`. It reads "Reconnect Mercury" when the connection needs attention.

**The referral link is Worker config, not code.** It is the Worker variable `MERCURY_REFERRAL_URL` (a `[vars]` entry or a secret, set by the owner; the owner's link is never in the diff). `mercuryOpenAccountUrl` in `routes/mercury_personal.ts` uses it only when it is an `https:` address on `mercury.com` or a subdomain with no user or password (`isMercuryHttps`, the check D840's sign-in already uses). Anything else falls back to the public site, so a mistyped value can never send a founder off-site.

**Why the Worker, not a `VITE_` build value.** D715's guard (`mercury_entity_sheet_d715.test.mjs`) keeps every Mercury host out of frontend source: Mercury links come from the Worker (the registry's `docs_url`), never from the bundle. The first cut of this PR named the public site and the host check in `incorporateModel.js` and failed that guard on CI; the link now comes from the status read, and the frontend checks only that it is https.

**When it is done.** `bankStepOf` reads the founder's own connection (`GET /api/mercury/personal/status`):
- connected, and the connection is `active`: **done**, with a tick and no actions;
- connected, but in any other state: **attention** ("Reconnect Mercury");
- not connected: **to do** (Open, plus "Already have a Mercury account? Connect it");
- a failed read: "could not be read". This is never done, and never claims that nothing is connected.

Opening an account at Mercury is never taken as done by itself: Axal cannot see it until it is connected.

### Where it lives
