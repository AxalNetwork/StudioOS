### 1. A sentence for every pack refusal (CRP5)

`POST /api/orders/intent` answered only D790's first-purchase rule with a sentence. Every other pack refusal was a 400 with the code alone. Now each answers `{ error, message }`, keeping its code and its status:

| Code | Status | Message |
|---|---|---|
| `token_pack_alone` | 400 | A token pack is bought on its own, one at a time. Take the other items out of this order and try again. |
| `promo_not_for_token_packs` | 400 | Promo codes don't apply to token packs. Offers show on the pack. |
| `token_pack_not_on_sale` | 400 | This pack isn't on sale now. Choose another pack. |
| `token_pack_first_purchase_only` | 409 | This pack is for your first token purchase, and you have bought tokens before. Choose another pack. (D790's, unchanged) |
| `token_pack_daily_limit` | 400 | You've reached today's limit of {`ordersPerDay`} pack orders. Try again tomorrow. |
| `token_balance_ceiling` | 400 | This pack would take your balance over {`balanceCeilingMicrousd`, as dollars}. |
| `token_packs_on_hold` | 400 | Buying tokens is paused on this account while a payment is reviewed. Contact support. |

- **The figures are `TOKEN_PACK_LIMITS`',** read into the sentence, never typed twice (5 and $1,000 today).
- **The table is typed against `TokenPackRefusal`.** A new refusal with no sentence fails the type check, and the test reads every `return { error: … }` in `tokenPackQuote` and fails on any code without an entry.
- **No sentence names a code, a Stripe code or a bank's words, or says "credits".**
- Auto-reload (D794) still records the code as its outcome, and its own sentences are unchanged.

### 2. Pack parity (D755 §4)

- **A pack's price or size is read from the pack store** (`ai_token_packs`, through `/api/public/plans-and-packs` and the pack reads), and never typed.
- **The test reads every source file** in `cloudflare-worker/src` and `frontend/src`, with comments removed. It fails on:
  - a price typed as text: "$25 of tokens", "a $10 pack";
  - a pack field set to a figure: `credit_microusd`, `bonus_microusd`, `face_cents` or `faceCents` with a non-zero number.
- **Not a pack's figure:**
  - the rate ("$1 of tokens buys $1 of AI use", §1);
  - a field set to 0 (no bonus);
  - `TOKEN_PACK_LIMITS`' bounds (`minFaceCents`);
  - a comment showing a label's format.
- On `main` today the scan finds none. The test also pins its own reach, both ways.

### 3. `add_tokens_opened` (CRP9)

- `POST /api/ai-budget/add-tokens-opened` with `{ from }` (signed in, the caller's own) writes one `activity_logs` row: `action = 'add_tokens_opened'`, `details = {"from": …}`, `actor = 'member'`. HQ › AI usage (D791) can read where members reach for tokens.
- **`from` must be one of the entry points** in `ADD_TOKENS_FROM`, else 400 `invalid_from`:
  - `models`, `rail`, `assist`, `billing`, `usage`, `ai_tokens`;
  - `refused_run`, `build`, `narrative`, `pitch_deck`, `session_digest`, `phone`.
- **The row holds `from` and nothing else:** no prompt, no page text, no figure. Anything else in the body is ignored.
- **One row per member, per entry point, per ten minutes,** so a sheet opened again and again is one row. The insert is one bound `INSERT … SELECT … WHERE NOT EXISTS`, and the answer is `{ recorded }`.
- **Nothing calls it yet.** D1288's `openAddTokens` calls it through `aiBudgetApi.addTokensOpened(from)`.
