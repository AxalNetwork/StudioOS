### 1. A sentence for every pack refusal (CRP5)

`TOKEN_PACK_REFUSALS` sits beside the codes in `aiCredits.ts`. It gives each `TokenPackRefusal` its status and the sentence the checkout sheet shows. `POST /api/orders/intent` answers every refusal as `{ error, message }` from it (`packRefusalBody`). Each code keeps its name.

| Code | Status | Sentence |
|---|---|---|
| `token_pack_alone` | 400 | A token pack is bought on its own, one at a time. Remove the other items and try again. |
| `promo_not_for_token_packs` | 400 | Promo codes don’t apply to token packs. Remove the code to buy this pack. |
| `token_pack_not_on_sale` | 400 | This pack is no longer on sale at this price. Choose a pack from the list. |
| `token_pack_first_purchase_only` | 409 | This pack is for your first token purchase, and you have bought tokens before. Choose another pack. (D790's, unchanged) |
| `token_pack_daily_limit` | 400 | You’ve reached today’s limit of **5** pack orders. Try again tomorrow. |
| `token_balance_ceiling` | 400 | This pack would take your balance over **$1,000**. |
| `token_packs_on_hold` | 400 | Buying tokens is paused on this account while a payment is reviewed. Contact support. |

- **The canvas's words.** The daily limit, ceiling, hold and first-purchase sentences are the canvas's (`design/incoming/Add Tokens Page.dc.html`). The other three are written in the same voice.
- **The figures are read, never typed.** The bold figures come from `TOKEN_PACK_LIMITS` (`ordersPerDay`, `balanceCeilingMicrousd`), so a change of limit changes the sentence.
- **Statuses are kept.** Every status stays what it was (400, and 409 for first-purchase-only). The SPA keys on the code, and auto-reload (D794) reads `tokenPackQuote`'s codes, not the route.
- **No refusal carries anything from the member's account.** It never includes a Stripe code, the member's balance or their order count.

### 2. Pack parity (D755 §4)

A pack's price and size live only in the pack store: `ai_token_packs`, which the Super Admin writes through HQ › AI allowances › Token packs, or the environment's fallback price.

`pack_refusals_d1289.test.ts` reads every source file in `frontend/src` and `cloudflare-worker/src`, with comments taken out. It fails on any of four shapes:
- a "$N of tokens" label typed with its amount;
- a pack field (`face_cents`, `bonus_microusd`, `credit_microusd` and their kin) given a non-zero number;
- a list of pack sizes;
- a "$N pack".

It finds none today. A second test holds the rules to what they are for. They catch each shape, and they leave alone:
- the "$1 of tokens buys $1 of AI use" rate line;
- a doc comment describing a label;
- a zero bonus;
- the limits;
- page-size lists.

### 4. `add_tokens_opened` (CRP9)

**`POST /api/ai-budget/add-tokens/opened`** takes `{ from }`, for HQ › AI usage (D791).
- **The row:** one `activity_logs` row, `add_tokens_opened`, through a bound insert. Its details hold `{"from": …}` and **nothing else**. A prompt, an amount or any other field in the body is never stored.
- **Where it was opened:** `from` is one of the entry points CRP9 and D1285 list (`ADD_TOKENS_FROM`):
  - rail, assist, billing, usage, ai_tokens, pricing;
  - phone, build, narrative, pitch_deck, digest, refused_run.

  Anything else is 400 `invalid_from`.
- **Answers:**
  - an account that is signed in: `{ ok: true, recorded: true }`;
  - a support session: `{ ok: true, recorded: false }`, and it writes nothing;
  - no session: 401.
- **The client** is `aiBudgetApi.addTokensOpened(from)`, for D1288's `openAddTokens` to call. D1288 is not built yet, so no page calls it.
