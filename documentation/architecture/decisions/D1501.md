## D1501 — A deck version's working copy on the Worker, card by card, with If-Match

- **Status:** Built by S17 (#3751, deck v2 A9, part of #3716; 2026-11-01), from S1's revision on #3751.
- **Builds on:**
  - D1500 (#3750): a card's stable `uid`;
  - #3748 (N3): the atomic, stale-base save;
  - D898: the slide model and its save rules.
- **Migration:** 715 (`715_pitch_deck_cards.sql`).

### Why

A paid generation or an insert lived only in the browser until the founder pressed Save, so a closed tab lost a charged result. The save also had no revision check of its own: two tabs could only find out at the database.

### What was decided

1. **A working copy, card by card.** `pitch_deck_cards (deck_id, card_uid, ord, json, rev, updated_at)` is keyed by the version the card was edited from and the card's own uid. It deletes with its version (`ON DELETE CASCADE`).
   - A card's working copy is written as soon as it changes (`PATCH /api/decks/:id/cards/:uid`).
   - It is read whole (`GET /api/decks/:id/draft`) for #3767's "Restore unsaved changes from [14:32]?", which reads `updated_at`.
   - It is thrown away with `DELETE /api/decks/:id/draft`.
   - A deck holds at most 60 cards, so a draft does too.
2. **If-Match on a card is required, and it is one statement.**
   - `If-Match: 0` creates the card's first copy, and only if none exists.
   - `If-Match: n` replaces revision n, and the revision becomes n + 1.
   - Each is a single conditional `INSERT … WHERE NOT EXISTS` or `UPDATE … WHERE rev = n`. So of two tabs writing the same card, exactly one wins, and the other gets 409 `card_rev_conflict` with the server's copy: the conflict board's "Their version".
   - A PATCH without the header is 428 `if_match_required`, so a client can never write blind.
   - Quoted and weak forms (`"3"`, `W/"3"`) read as the number.
3. **A working copy obeys the save's rules.** It is checked with `modelProblems` and kept through `sanitizeSlides`, exactly as a save is.
   - So it can always become a version.
   - Whatever the card references (a generated image's `image_id`, a figure's `binding`, an inserted proposal's blocks) stays referenced.
   - A card the save would refuse is refused here with the same sentence (`SLIDE_MODEL`).
4. **If-Match on the save; one 409 body.** `PUT /api/decks/:id` reads `If-Match: <version>`, since a deck's `rev` is its version number.
   - **A stale one** (another version, or a version no longer current) is refused before anything is read or written.
   - **The body** is `versionConflictBody`: `{ error: 'deck_version_conflict', current: { id, version }, rev, server, message }`. `server` is the current version, as `GET /:id` answers it.
   - **#3748's stale base answers this same body.** Its `current` is unchanged; `rev`, `server` and `code` are added. `SaveDialog` shows `message`, a plain sentence.
   - **Without the header,** the save works exactly as before and still writes one version.
5. **The draft never leaves the editor.** Nothing but `routes/deck_draft.ts` reads `pitch_deck_cards`: no share link, export, print page or reader. "Save as version" stays the one explicit `PUT`.
6. **Who.** The deck's readers read its draft, and its writers change it (`projectOwned`, the rule `GET` and `PUT /:id` use).
7. **The client and the seam.**
   - The client is `frontend/src/lib/api/deckDraft.js` (`deckDraftApi`), with one line in `api.js` (D527).
   - In `deckV2Adapter.js`, `saveCard` and `discardDraft` are swapped to `through(...)`. A new `draft` row reads `GET …/draft`, unavailable on a 404 like the others. All three are `SWAPPED`, and the seam test pins them.
   - No header or banner UI is drawn here. The autosave loop, IndexedDB replay and the offline, conflict and restore banners are #3767's (A4c).

### Verified

**`cloudflare-worker/test/deck_draft_d1501.test.ts`** (5 tests, migration 715 applied twice on the full schema):
- the round trip, with the revision climbing by one per write;
- a stale card revision gets 409 with the server copy and writes nothing; no header is 428; two first saves of one card produce one winner;
- a stale deck `If-Match` gets 409 with the server copy and writes no version, and #3748's stale base answers the same body;
- a working copy keeps its image and binding, and refuses an overlapping block;
- a share link reads only the saved version, and no other source file names the table;
- another member can neither read nor write the draft;
- deleting the version deletes its copy.

**The seam:** `pitch_v2_adapter_d1604.test.mjs` adds the swap.

**Mutations, each caught:**
- the card UPDATE without `rev = ?`;
- `PUT /:id` ignoring `If-Match`;
- a share reader naming `pitch_deck_cards`.
