## D8774 part 3 — Build › Connect a tool: Scope, Review and Result for a stop or disconnect, the last read on the GitHub row, and the Super Admin preview (#8774)

- **Status:** built 2026-11-27 on `main` after #8813 (D8774-p2). The owner accepted option A for Q1 to Q3 on 2026-11-27. This part needs no Worker change, route, column or migration.

### Built

**BLS07: Scope → Review → Result** (`ConnectToolSheet.jsx` `StopSteps`; words in `connectorsModel.js` `disconnectReview` and `disconnectResult`)

- **Scope.** A connected row's Disconnect first asks "What do you want to stop?", with two radios. "Stop using {tool} for {company}" comes first and is selected (Q1 A). "Disconnect {tool} from your account" is second. Each option carries part 2's note, then "Either way, items already in Build stay." The step offers Cancel and Review; nothing destructive is on it. A row with no scoped stop to offer (no venture, or the tool does not serve the venture's company) opens straight on Review of the account-wide disconnect.
- **Review.** A heading and label/value rows. Focus moves to the heading, never to the destructive button.
  - Scoped stop: Stops, Stays (the companies that keep the tool), Repositories (GitHub's chosen repositories, let go for this venture by part 2's `releasedConfig`) and Who (you, by name).
  - Account-wide: Ends for (every company it serves), Stops, Stays, Deleted (the stored credentials) and Who.
  - Back returns to Scope. The destructive button is "Stop using for {company}" or "Disconnect from your account".
- **Result.** A `role="status"` region (polite) after the write returns: "✓ {tool} no longer serves {company}", "Done at HH:MM UTC.", the companies it stays connected for, and "{venture} keeps what it already has". After a disconnect: "{tool} is disconnected from your account … Data already in StudioOS stays." It is worded from the connection as it was before the write, then the list is read again. "Back to Connect a tool" closes it.
- **Writes and refusals.** The writes are part 2's: `PUT /:uid/companies` without the company, and `DELETE /:uid`. A refusal stays on Review, in the row's alert as before.

**BLS04, BLS05, BLS10: the last read on the GitHub row.** When the viewer's GitHub is connected and the venture is in a company, the sheet reads Operating systems' module read (`cyclesApi.module('build', id, 'operating-systems')`, `parts.tools.code`). That is the read part 2 gave `binding.last_good_read` and `stale`. The sheet takes the system whose owner is the viewer ("You"), which is the connection the row draws.

- Under the scope ladder the row says "Last successful read of {venture}: {at} · {source}", "◷ Stale · N h" when stale, or "none yet".
- While the read is loading it claims nothing.
- When the read fails it says "Last successful read: Unreadable. The sync history could not be read; this is not a claim that none happened." and offers Try again.

**BLS10: Super Admin preview.** A Super Admin browsing the founder shell outside a support session (`isFounderPreview`, as #8261) sees a banner: "⚠ Super Admin preview of {founder}’s view. The tools listed are your own connections, and anything you do here, linking included, is written as you, {name}." The link dialog adds "Axal admins may move a venture. This link is written as you, {name}, not as the founder." Outside preview neither line appears.

**Phone (BLS11).** The sheet is already the cycle route's page below 1024px (D703). The new steps' buttons and radios are 44px tall below the `sm` breakpoint.

### Departures

- **Counts.** BLS07's Stays names counts (issues, pull requests, releases, contributors). The connections list carries no per-venture counts, so Review names what stays without counting it.
- **Repository names.** The Review lists the repositories from the connection's own config. The viewer is its owner, so these are names they may see.
- **Last read on other tools.** It is on the GitHub row only. Only GitHub records which venture it reads (part 2), so other tools have no per-venture read to show.
- **The extra read.** The last read costs one more read: Operating systems' module read, which also reads its rows. A dedicated per-venture read would be lighter and would need a new route.
- **Phone.** No dedicated bottom sheets or step eyebrows (BLS11 A–F). The steps sit inline in the existing page-mode sheet.
- **Preview wording.** The preview banner says the listed tools are the Super Admin's own connections. That is what the connections read returns. The canvas's banner says only that linking is written as them.
