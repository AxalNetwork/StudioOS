### The row

AX4 drew `All · Published · Drafts · Essays`. "Drafts" collected six states that are not drafts, and "Essays" named a kind no article records, so that chip was always disabled. EX-11 draws `All · Needs you · With editors · Published`, which asks whose move it is. Each chip is a set of the shelf's own states. Every row a chip shows therefore says on its own pill why it is there:

| Chip | States |
| --- | --- |
| All | every piece, including one in a state this page has no words for |
| Needs you | Draft, Changes requested |
| With editors | Submitted, In review, Approved with no `publish_at` |
| Published | Published |

**Scheduled and Not accepted are under All only.** A Scheduled piece goes public by itself, so it is nobody's move. A Not accepted piece is closed until the writer decides to revise it, and calling it "Needs you" would turn a closed piece into a task. EX-11's own sample agrees. Its *Needs you 2* and *With editors 2* are exactly the drawn rows in those sets (Changes requested and Draft; Submitted and In review). Its Scheduled and Not accepted rows are in neither.

**Approved with no time set is With editors.** Its audience line already reads "An editor publishes it". With a `publish_at` it is Scheduled (D484), and the Worker splits the two the same way `articleQueue.ts` does (`publish_at IS NULL`).

### The figures are the whole shelf's

The canvas puts a count on every chip. The shelf is read 100 pieces at a time (#4689), so a count over the loaded rows would understate. `GET /api/advisors/me/thinking` now returns `total`, `needs_you` and `with_editors` beside `published`, all counted over the whole shelf in the query that already counts it. A missing figure is dropped from its chip and never guessed. A zero is dropped as well, which is `zoneFilterBuilder`'s existing rule. No migration and no new route.

### The row's behaviour

- **A labelled group.** `ZoneToolbar` takes `filterLabel`. The chips sit in `role="group"` named "Article state", the canvas's own label.
- **Pressed state, not radio.** EX-11 draws `role="radio"`. Every other zone toolbar uses native buttons with `aria-pressed`, and the same component serves them all, so this row keeps that convention. Tab, Enter and Space reach each chip. Building a roving-tabindex radiogroup for one zone would give this row different keyboard behaviour from every other toolbar.
- **44px below `md`.** `ZoneToolbar` takes `tap`, which adds `min-h-[44px] md:min-h-0`. It is opt-in, so each zone gets the larger target when its own canvas is built, rather than every toolbar changing at once.
- **Not by colour alone.** The pressed chip is bold as well as tinted, and every pill names its state in words. The neutral and accent chips already have `dark:` pairs.
