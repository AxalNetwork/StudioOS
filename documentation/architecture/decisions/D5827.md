## D5827 — Typeform: read-only sign-in in the member's data center, and one chosen form per venture (#5827)

**Decided.** Typeform is the `typeform` connector, `oauth2`, with the scopes
`forms:read`, `responses:read` and `offline`. Each venture binds at most one
form, chosen explicitly, through one member's own connection switched on for
the venture's company.

**Who owns what.**

- **The developer app.** The owner registers it in Typeform's developer
  portal, in the approved pilot account. Its client id and secret live only
  in the Worker's environment (`TYPEFORM_CLIENT_ID`, `TYPEFORM_CLIENT_SECRET`)
  or HQ › Integration keys, which stores the secret encrypted.
- **Rotation.** To rotate, set the new secret in either place. The env pair
  wins over the stored pair (`providerOauthKeys.ts`, D227). The old secret
  stops working once Typeform rotates it.
- **Callbacks.** The app's callbacks are exact, one per environment:
  `<OAUTH_CALLBACK_BASE_URL>/api/integrations/oauth/typeform/callback`. HQ ›
  Integration keys shows each environment's URL, and only HTTPS is used.
- **Availability.** `ready` is false until `TYPEFORM_APP_APPROVED=1`. The owner
  sets it only after registering the app and completing one callback in the
  pilot environment. Until then the catalogue says Typeform is not set up and
  no sign-in state is written.

**Data center routing.**

- The member chooses US (default) or EU when signing in (`?region=eu` on the
  start). The choice is written into the signed, single-use state
  (`typeform_region`).
- `connect` reads it from the state, never from the callback's query. It is
  stored inside the encrypted credentials.
- Every token-bearing request is built in `typeformOAuth.ts` from that
  region's origin (`https://api.typeform.com` or `https://api.eu.typeform.com`)
  and a fixed path. The token and refresh exchanges also go to that region.
- A form id must match `^[A-Za-z0-9]{1,64}$` before it enters a path.
- An EU token is never sent to the US origin, and the reverse.

**Grants.**

- The state is bound to the member and to `typeform`, and is used once.
  Denied consent, a replayed state and another member's state connect
  nothing.
- A grant without a refresh token is refused. Without one, background sync
  could not outlive the access token.
- A grant reporting any scope beyond the three is refused (`scope_overreach`).
- Typeform rotates the refresh token on each use. A refresh therefore runs
  behind `refreshLease.ts`'s lease and re-reads the stored credentials inside
  it, and the rotated token is written back. A concurrent caller gets
  `typeform_busy` instead of spending the same refresh token twice.
- A refresh that returns no new refresh token keeps the old one.

**The form.**

- `GET /api/typeform/forms?project=&page=` lists 50 forms a page for a writer.
  An empty account is an empty page, not an error.
- `GET /forms/:id/fields` returns each field's stable `id`, `ref` and `type`,
  with nested group fields, and never their titles.
- `PUT /form` with `{ project, form_id | null }` reads that exact form with the
  member's grant before binding it.
  - The binding stores the field identities only.
  - A teammate's binding is never replaced, and a mismatched answer binds
    nothing.
- `POST /form/check` repeats the read and marks the binding
  `lost` with its reason: `grant_revoked` (401, or a refused refresh),
  `scope_missing` (403) or `form_deleted` (404). Each is its own code, never an
  empty list.
- A support session is refused before any Typeform request.
- The browser receives the capability, the status and the field identities,
  and never a token.
- Logs name outcomes only. Neither the activity log nor `console.warn` carries
  a form title, a field title or a response.

**Disconnect.** It deletes the connection and the venture bindings, and the
`integration_id` foreign key cascades as a backstop. UNVERIFIED: Typeform
documents no token revocation endpoint, so the grant ends at Typeform when the
member removes the app from their Typeform account. The connector page and
this decision say so. The owner confirms or corrects this at registration.

**Owner-only, not done here.**

- Confirm the UNVERIFIED facts against the live app:
  - refresh rotation;
  - no revocation endpoint;
  - the EU origin;
  - whether the token answer reports `scope`.
- Then set `TYPEFORM_APP_APPROVED=1`.

**Verified.**

- `cloudflare-worker/test/typeform_5827.test.ts` (11 tests, against a fake
  serving both data centers) covers:
  - the consent shape and readiness behind the flag;
  - US and EU sign-in, where a forged callback `region` is ignored;
  - denied consent, stale and foreign state, and offline-less and broader
    grants;
  - pagination and field identities, and an empty account;
  - malformed, unknown and mismatched forms;
  - two members and two ventures;
  - the three lost reasons;
  - one refresh under concurrency, with the rotated token kept and none sent
    twice;
  - a support session, a stranger and an unswitched company;
  - disconnect, with no token or title in logs, and reconnect.
- These mutations each fail a test:
  - reading the region from the callback query;
  - not storing the rotated refresh token;
  - dropping the form-id check.
