## D615 — Contract document types: saving a draft for a published type no longer changes the live type; publishing does (migration 416)

**Issue:** #1313, found by #1165's audit (area 7, registry publish). **Migration 416.**

### What was decided

1. **A pending draft beside live values.** Migration **416** adds `draft_title`, `draft_layer`, `draft_party_roles_json`, `draft_required_fields_json`, `draft_updated_at`, and `draft_updated_by` columns to `contract_doc_type_registry`. Additive only.
2. **Saving a draft never changes live published values.** When saving a draft on a published document type (`upsertDraft`), the pending changes are recorded into the `draft_*` columns. The live columns (`title`, `layer`, `party_roles_json`, `required_fields_json`) and `status` ('published') remain untouched. On a type that is only a draft, saving continues to update the live draft fields.
3. **Publishing promotes the draft.** Calling `publishType` moves the pending draft values into the live columns, clears the `draft_*` columns (`NULL`), records `published_at`, `published_by`, and `publish_reason`, and preserves the Super Admin step-up requirement and audit event `registry.type.publish`.
4. **Registry reads return both.** `listRegistryRows` returns both live values and any pending `draft` object. Both `/api/admin/contracts/registry` (hub) and `/api/admin/contracts/registry/doc-types` expose the live fields alongside pending `draft` specifications.

### Verified

- `cloudflare-worker/test/contract_doc_type_drafts_d615.test.ts` exercises:
  - Draft save on a published type leaves live values and status untouched, populating the `draft` fields.
  - Draft save on a draft-only type updates live draft fields directly as before.
  - Publishing promotes pending draft values to live columns, clears `draft_*`, and records audit metadata.
  - Hub and doc-types registry reads return live values and the pending draft object side by side.
