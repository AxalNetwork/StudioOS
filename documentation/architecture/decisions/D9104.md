### 1. What the confirm reads, and what it never does

Opening the confirm calls `narrativeOutline({ projectId })` with no `run`, so only
`POST /api/decks/narrative/outline` is sent: nothing runs, nothing is held and nothing is charged. It also reads
`GET /api/decks/by-project/:pid` for the next deck number and the version that stays current. The build is never
called from the narrative pages; the price is "held when you confirm in the studio, charged for what runs".

### 2. How the adapter's answer is read

`narrativeOutline` never throws (`through` in `deckV2Adapter.js`). `buildDeckModel.outlineState` maps it:

| Answer | State |
|---|---|
| none yet | loading: skeletons, "Reading the price…", Continue off |
| `available: true`, `narrative.version` set, cards | ready; a `narrative.reason` is a warning above the outline |
| `available: true`, `narrative.version: null` | empty, "Save a version first."; when the reason says the store could not be read, unreadable |
| `available: true`, no cards | empty: no card can be planned from the records yet |
| `unreadable`, `status: 403` | refused (RAN27d) |
| `available: false` with no `unreadable` | refused: this is the non-writer 404 that `through` turns into "Coming later"; the confirm never says "Coming later" |
| any other `unreadable` | RAN27c's sentence, "No price is shown and nothing was charged.", Try again |
