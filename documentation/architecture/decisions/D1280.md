## D1280 — Spin-Out Lab › Settings: the branch Admin's grant terms read from `GET /api/licence/mine/programs`

- **Status:** built for S05 by S13's session at the owner's request, 2026-10-26 (#3338, part of #2374).
- **Basis:** D971 (Lab Settings, #2756) left a branch Admin's grant terms waiting on #2775. #2775 (D984) shipped `GET /api/licence/mine/programs`, which `ProgramsTab` (D988) already reads.
- **Migration:** none. **Worker:** no change; the read is on `main`.

### 1. What an Admin sees

"From your studio's grant" on `/admin/programs/spinout-lab/settings` now reads the caller's own licence through `licenceProgramsApi.mine()`. It no longer prints a line saying the read is still being added. It takes the `spinout-lab` row and draws one of these states:

| The read says | The block draws |
|---|---|
| A grant (in force, granted, paused or ended) | `Grant: <word> · <line>`, then the period and the Lab's cohort terms (capacity, cohorts a year, HQ approval). |
| No grant (`not_recorded`, `switched_off`, or no row) | "Your studio does not hold Spin-Out Lab (<word>). Ask HQ for it on Licences › Programs." The link reads **Request it on Licences › Programs**. |
| `linked: false` | The read's own reason: on HQ-held accounts, HQ runs every program. |
| `programs: null` (a branch HQ has not sent its copy) | The read's reason. This is not the same as no grant. |
| A failed read, or an answer without `linked` or the list | **Unreadable** with Try again. It is never drawn as no grant. |

- **Same words as the Programs tab:**
  - the state word and its line are `statusOf`'s;
  - the period is `periodOf`'s;
  - each term row is `termRows`'s.

  So a term nobody set reads "Not recorded" with "HQ has not entered this term.", never Off or 0. The other terms (money, playbook, brand, reporting and the schedule) are on Licences › Programs, which the block links to.
- **The Super Admin branch is unchanged.** It reads HQ's grid (`programGrantsApi.grid()`). An Admin still never reads it, and the D971 test still pins that.
