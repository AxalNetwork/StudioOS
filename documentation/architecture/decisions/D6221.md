### Sources, all existing

- `GET /api/funds`: the picker; `relationship` and `can_manage` say who the
  caller is to the fund. A GP of record and an admin read `carried_interest`.
- `GET /api/funds/lp-portal` (`funds[<id>].carried_interest`): an LP's carry,
  read only for an LP, because the list leaves an LP's terms out (D4636).
- `POST /api/fund-sim/funds/:fund_id/waterfall/simulate` (mounted at
  `/api/fund-sim` in `index.ts`; handler `routes/fund_simulator.ts`).
- `GET|POST /api/fund-sim/funds/:fund_id/scenarios?kind=waterfall` and
  `DELETE /api/fund-sim/scenarios/:uid`: the scenario store. No new store.

### What the build decides

- The page draws in the frame with no tab current: crumb Account ›
  Portfolio › Exit Waterfall, one h1, document title "Exit Waterfall ·
  Portfolio · Axal VC", the Portfolio rail.
- Every result carries "Model · provisional · not a distribution".
- Carry reads "From the fund’s terms" (or "· your LP record"); when neither
  read holds one it reads "Not recorded · using 20% as an assumption", and
  when the LP record fails, Unreadable with its own Retry and the same
  labelled assumption. Hurdle 8%, years 5 and catch-up on are
  "Assumption · not recorded on the fund". Carry is editable; its chip keeps
  naming the source of the starting value.
- The exit value starts empty. The page asks the engine at $0 for the
  fund's recorded committed and invested totals, which give the 1× / 2× /
  3× invested chips, and draws no split until a value is typed or chosen.
- The engine's 0 for the multiple (nothing invested) and for the annualised
  return (nothing invested, nothing to LPs, or 0 years) reads "Not
  computable: <reason>". A computed zero stays 0.
- A failed model run keeps the inputs and the last result, greyed and
  labelled "Not current", with Try again; that result cannot be saved.
- Save scenario is shown only when `can_manage` is true. Name required,
  120 characters at most; a refusal (402, 403, 404, 400) or a failure keeps
  the sheet, the name and the inputs, with its sentence. After a save the
  list is read again and the new scenario is the loaded one.
- Load replaces the inputs; a change after it reads "Changed since loaded"
  with what moved and Save as new. There is no rename or overwrite.
- Compare two shows each scenario as saved (nothing is re-run), marks inputs
  that differ, and keeps different holding periods as two figures.
- Delete asks first; Cancel sends nothing.
- An LP sees no Save and no scenario list, and no per-LP row: the simulate
  answer carries every LP's name and no row says which is theirs, so the LP
  card reads "Your row: not recorded" (owner answer A needs the Worker's
  scoped answer; hiding rows in the browser is not a control).
- Export CSV writes `exit-waterfall-lps.csv` and `exit-waterfall-tiers.csv`
  from the rows on screen, each starting "Model, not a distribution". Print
  is the browser's dialog with a print banner; nothing is stored.
- Phone (below 1024px): one column, the four terms in a "Terms and
  assumptions" sheet, tables as labelled stacked rows, 44px targets.
