## D4819 part 16 — History as an attributable timeline (L16) (#4819)

Built for #5926, after parts 1 to 3 in `D4819.md`. The part number is the board number (L16), as in part 12.

This is frontend only. `routes/admin_licences_history.ts` (`GET /:uid/events`) is read as it is, with no Worker change and no migration. It touches `LicenceHistory.jsx` and `licenceHistoryModel.js`; `lib/api/adminLicenceHistory.js` is unchanged.

**What was built.**

- **The entry.** Each entry is two columns, as the canvas draws them.
  - **The left column** holds:
    - the title;
    - the time, written as `3 Nov 2026 · 14:32 UTC`;
    - the actor.
  - **The right column** holds:
    - each changed field as before → after, with the before value struck through;
    - `Reason:`;
    - `Branch:`.
  - **Screen readers** hear "Before: …, after: …".
- **The title is in operator words.** Every event kind the Worker writes has a title in `EVENT_TITLES`:
  - `created`: Licence drafted;
  - `activated`, `suspended`, `reinstated`, `renewed`, `terminated`: Licence activated, Licence suspended, and so on;
  - `territory_changed`: Territory changed;
  - `seats_changed`: Seats changed;
  - `terms_changed`: Terms amended;
  - `contract_instantiated`: Agreement drafted;
  - `contract_sent`: Agreement sent for signature;
  - `program_changed`: Program access changed.

  A kind with no title reads "Licence record changed", and its key appears only as a muted second line. The raw key is never the primary text.
- **Who.** Who the entry names depends on what the row records:
  - a known account: its name;
  - an account since deleted: Unknown account;
  - a row the compliance ladder wrote (`detail.automatic`): System;
  - any other row with no actor: Not recorded. It used to read System. That claimed an automatic step the row does not record. A studio's schedule signature is one such row, because `programSchedule.ts` writes `actor_user_id` NULL.
- **Reason.** The reason is the row's `note`, or failing that `detail.reason`. When neither is recorded, it reads Not recorded.
- **The branch outcome** comes from the push record the writer kept with the row (`outcome`, D4707). When that push did not land, it adds what the licence's `sync` says now.
  - **`partial`:** "HQ done · branch pending: the push to the branch did not land". It adds one of:
    - "Still pending now (revision N)", with the failure sentence;
    - "The branch has since accepted revision N".
  - **`committed`:** "No failed push recorded". The row does not tell apart a push the branch accepted, a licence with no branch, and a write that never pushes, so the line claims no more than that.
  - **`created`:** "No branch change", because drafting never pushes.
  - **No outcome:** Not recorded.
- **Load older** pages over the read's own `next_before` cursor and appends the older page below. It disappears when there is no cursor.
- **Failed reads.** A failed first read is Unreadable, with the sentence "This is not a claim that nothing happened" and Try again. It is never "Nothing recorded yet". A failed older page keeps the entries already shown, and its Try again asks for the same cursor.

**What the history read returns for each event kind.** This was checked against every writer of `licence_events` on main:

| Event | Before → after | Reason | Push outcome |
|---|---|---|---|
| `activated`, `renewed` | recorded | none written | recorded (`pushOutcome`) |
| `suspended`, set by an admin | recorded | the note | recorded |
| `suspended`, set by the compliance ladder | **not recorded** | the note | **not recorded** (raw insert) |
| `reinstated`, from the lifecycle route | recorded | none written | recorded |
| `reinstated`, from a notice (`admin_licences_notices.ts`) | **not recorded** | the note | `committed` by default |
| `territory_changed`, `seats_changed` | recorded | none written | recorded |
| `terms_changed`, from `PATCH /:uid/terms`, entity details and pricing apply | recorded | the reason | recorded |
| `terms_changed`, from exclusivity and exclusivity review | recorded | the reason | `committed` by default |
| `terms_changed`, from `PUT /:uid/terms` (`licence_terms`) | **not recorded** | the reason | `committed` by default |
| `terms_changed`, from adding an administrator (`admin_licences_admins.ts`) | **not recorded** | none written | **not recorded** (raw insert) |
| `terminated` | recorded | the note | `committed` |
| `created`, `contract_instantiated`, `contract_sent` | **not recorded** | none written | `committed` by default |
| `program_changed` (grants, schedules, requests, deal types) | **not recorded** in `before_json` and `after_json` (deal types keep theirs in `detail`) | the reason or note | **not recorded** (raw inserts) |

The kinds marked not recorded read Change: Not recorded on the timeline. Making them structured needs each writer to pass its before and after values to `logEvent`. That is Worker work and is not part of this slice.

**Still needed for the canvas's wording** ("France has not acknowledged revision 143"): a row does not carry the revision its push sent, and HQ does not read a branch's own copy (Backend required, above). So the per-row line says what the push record says, and only the current `sync` names a revision.

**Tests.** `frontend/test/licence_history_timeline_5926.test.mjs` has five tests:
- operator titles, with the raw key never the primary text;
- who, when, before → after and the reason, with Not recorded for each that is missing;
- the branch line's four states and `sync`'s "now";
- Load older over the cursor;
- Unreadable with Try again, for the first page and for an older one.

Fourteen mutants were tried and all fourteen were killed:
- a known kind printing its raw key;
- an unknown kind titled with its key;
- a missing actor read as System;
- `detail.reason` ignored;
- the raw stamp printed;
- `partial` read as no failure;
- `committed` read as Not recorded;
- the `sync` "now" dropped;
- `created` claimed as pushed;
- Load older sent without its cursor;
- the second page replacing the first;
- a first failure drawn as empty;
- Try again removed;
- an older failure clearing the rows.

`licence_navigation_d4707.test.mjs` has four assertions changed to the new wording, none weakened:

- "by Sue" became "Sue";
- the before → after text now includes its screen-reader labels;
- a row with no actor now reads Not recorded rather than System, and a new assertion covers System for an automatic row.
