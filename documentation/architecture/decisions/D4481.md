## D4481 — Learning home actions in place and the read-only strip (#4481)

Implements #4481, part of #3726, against the approved LR1, LR1e, LR18b and LR20a frames in `design/incoming/Learning Stream Page.dc.html`. The owner approved the narrow `LearningHome.jsx` edits shared with #4477. Video-library filtering and result logic remain with that task. This is frontend only: no route, client method, migration, binding or secret is added.

### Home actions and honest states

- Desktop and phone webinar rows use the existing `webinarReads.registerForWebinar(uid)`. That wrapper makes one registration write and rereads the webinar for current registration and seats. The shared action updates that row in the existing upcoming read, shows Registering… while pending and then Registered. A synchronous ref guard rejects another click on that pending UID before React renders its disabled state.
- A refusal displays the route's structured `error.data.message` in that row. An internal or transport `Error.message` is never product copy; without a route sentence, the fallback says the action could not be confirmed.
- Known capacity/counts retain their meaning, including Full and No seat limit. An absent seat figure reads Seats not recorded, never zero.
- Existing program self-enrolment is retained through `enrolSelf`, with a synchronous pending guard, a secondary Join button and Open to join pill. Success rereads the member's enrolled/open program lists. Progress is counted only from returned contents/completion; missing completion remains Not recorded.
- An empty course record says No course in progress. Browse courses selects the existing Courses tab. The phone's full-width 44px primary opens the first in-progress course in the route's existing newest-first order, skipping videos; it browses courses only once an empty course record is known. A pending/unreadable record does not become a false empty state. A recorded course with no usable link says Course link not recorded, rather than claiming there is no course in progress.
- The desktop home stacks at tablet width; phone uses a 16px gutter, its tabs before the home sections, one Continue row and at most three New this week rows. Registration uses the same action state on both layouts. Article authoring stays available below the phone sections, or in the hero for an article-only gated profile.

The existing progress read does not send module/lesson labels or lesson totals. This change uses its recorded course title, link and percent; it invents none of the design's sample counts or next-lesson names.

### Assigned admin

The status strip uses the actual program name, lock icon and existing amber theme tokens. A missing name is Program not recorded. The page lede states that nothing can be changed. Both assigned-admin program views have no AI rail; the Learning home keeps its existing no-rail pin. No sidebar entry is added.

The program route already sends each content row's `kind` (D954). Only a recorded video uses Watched / Not watched; readings and unknown item kinds keep their generic progress labels. Exam absence reads Not sat, and webinar absence Not registered. All existing tones and the Not recorded cell remain. The matrix and member record render no email and expose no write controls.
