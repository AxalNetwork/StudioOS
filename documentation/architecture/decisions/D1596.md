## D1596 — Advisor · Sessions: Block proposals from the advisor's own Axal calendar (`sessions:block`)

- **Status:** the Worker part, built for slot S26 by S13's session at the owner's request, 2026-10-31 (#3869, part of the profiles canvas #3700). S1 builds the screens. Not deployed, and not verified live.
- **Canvas:** the profiles canvas (#3700), boards PH21 and PH22b: Advisor › Practice › Sessions with Ask open. Asking for a free afternoon answers with **Block** cards marked "From your calendar", each with Accept, Edit and Discard. Nothing is blocked until the advisor presses Block.
- **Basis:** `origin/main` at `000f72aa`, which carries D1478 Part B (#3873).
- **Migration:** none.

### 1. What was decided

**`POST /api/ai/rail/run` gains a second handler, `sessions:block`.** It is matched as `/^sessions:block$/` before the `form:` path. #3864 (S11) adds `studio:layout` to the same file, and both share the one dispatch on `option`.

```
POST /api/ai/rail/run
  { page: 'Advisor · Practice · Sessions', option: 'sessions:block', input?: { days?: 1..60 } }
  → text/event-stream:
      meta { model: null, hold_microusd: 0 }
      done { proposals[{ uid, kind, from, until, open_slots, source }], dropped[],
             usage_log_id: null, charged_microusd: null }
        or { proposals: [], dropped[], reason: 'nothing_to_propose', usage_log_id: null, charged_microusd: null }
```

`days` defaults to 14. A value that is not a whole number from 1 to 60 reads as 14.

**Refused before any read of the advisor's records:**

| Case | Answer |
|---|---|
| Another page | `404 unknown_page` |
| An Explorer | `403 no_profile` |
| A support session | `403 support_session_refused` |
| No advisor profile (a founder, an admin) | `403 no_profile`, by `requireMyAdvisor`'s rule: the advisor profile whose user is the caller |

**No model, no hold, no charge.** The handler never calls `run()` or `quoteRun`, so the panel's cost line reads "No charge".

### 2. What it reads

Only the caller's own records, for the window from now to now plus `days` (`services/sessionsBlock.ts`):

- **Open slots:** the advisor's slots in the window that are not cancelled, not blocked (`blocked_reason` empty), and held by no booking. A booking holds a slot when its status is `pending`, `confirmed` or `completed`, as in `takenForSlot`.
- **Booked slots:** read only to keep a "free" afternoon free of bookings.
- **Four calendar readers**, read-only, with no provider call:
  - `hostedEvents`: events the advisor hosts;
  - `ticketEvents`: events they hold a place at;
  - `interviewCallEvents`: their interview calls;
  - `cohortDateEvents`: their cohort assignments' dates.

**Two rules on calendar items:**
- **An all-day item never clashes.** A cohort deadline is all-day; only timed items count.
- **A reader that fails is named, never treated as empty.** It goes into `dropped` as `{ why: 'source_unreadable', source }`. The calendar is never claimed to be empty because a source could not be read.

### 3. What it proposes

At most 10 proposals, clashes first. Each payload is `{ kind, from, until, open_slots, source }`, with ISO times, which the block route compares as it does today.

- **`clash`:** a run of contiguous open slots (each starting where the last ended) that overlaps a timed item. `from` and `until` span the run.
  - The source names the item's kind: "Clashes with an event you host", "…an event you hold a place at", "…an interview call" or "…a cohort session".
  - A zero-length item, an event with no recorded end, is an instant inside the slot.
- **`free_afternoon`:** up to three afternoons, 12:00–18:00 in the advisor's own time zone (`advisors.timezone`), so the advisor can keep them free. An afternoon qualifies when:
  - it holds open slots that lie wholly inside it;
  - it holds no booking;
  - it holds no timed calendar item.

  With no valid time zone recorded, this kind is skipped and `dropped` says `{ why: 'no_time_zone' }`.
- **Never a `reason`.** A block's reason is the advisor's own words, and the addendum allows no trigger on a reason. A blocked slot's reason is never read out.

### 4. What it writes

Only `ai_rail_proposals` rows, through `proposeRail`: `kind: 'proposal'`, `rail_option: 'sessions:block'`, `record_ref: 'advisor:<id>'`, `model: null`, `usage_log_id: null`. It never writes `advisor_office_hour_slots`.

With nothing to propose, no row is written.

**Accepting uses the existing routes.** On Accept, the client:
1. puts `from` and `until` into the page's Block form;
2. lets the advisor press Block (`POST /api/advisors/me/slots/block`, the advisor's own reason);
3. then calls `railProposalsApi.decide(uid, 'accept')`.

A slot booked in the meantime is skipped by the writer and reported as `skipped_booked`, as today.

### 5. Registration

- **`frontend/src/lib/railOptions/advisor.js`** adds `ADVISOR_ASK_CHIPS`, a new export beside `ADVISOR_RAIL_OPTIONS`: `{ page: 'Sessions', key: 'sessions:block', label: 'Find a free afternoon', kind: 'plan', handler: 'none', noModel: true }`. Its source is the Sessions board's Block call (`api.blockMyAdvisorSlotRange(`), the write an Accept leads to.
  - **Why a separate list.** The chip runs no model, so it is not a rail option. `ADVISOR_RAIL_OPTIONS` and its D773 and D779 tests cover model-running controls and how each board wires them. The chip is S1's to draw in the Ask panel.
- **The generator:** `scripts/build-rail-matrix.mjs` reads the new list. It writes a `noModel` option as a row with `models: []`, `more: []`, `routeTask: 'none'` and `noModel: true`, and checks the row's page, key, label and uniqueness as for any option. Any other `handler: 'none'` option still gets no row, and a `noModel` option with another handler is refused.
- **The matrix read:** `railMatrix.ts` adds no module models to that row. So `GET /api/ai/rail?page=Advisor · Practice · Sessions` lists the option with no model choice.
- **It is a chip in the Ask panel, not a rail action.** The AIRail holds only model choice and consumption.
- **Coverage:** `railMatrix.json` was regenerated with `node scripts/build-rail-matrix.mjs` (`--check` passes). `AI_MODEL_COVERAGE.md` re-renders unchanged through `renderCoverage()` (D1478), because a no-model row connects no model to any module.

### 8. Verified

**`cloudflare-worker/test/advisor_sessions_block_d1596.test.ts`, 7 tests** on the migrated schema with synthetic rows. The runner and the quoter are stubs that count their calls, and every test ends with both at zero.
- **Refused before any read:** another page (404); an Explorer, even one holding an advisor row; a founder; an admin with no advisor profile (403 `no_profile`); a support session. No proposal row is written.
- **One clash and one free afternoon:**
  - the clash is a run of two open slots under an event the advisor hosts, bounded by a blocked slot before it and a booked slot after it;
  - the free afternoon is 12:00–18:00 on a day whose all-day cohort deadline does not count;
  - an afternoon with a booking is skipped.

  The meta is `{ model: null, hold_microusd: 0 }`, and `usage_log_id` and `charged_microusd` are null. The slot table is byte-for-byte unchanged. Each row is `advisor:201`, `kind: 'proposal'`, with no model and no `reason`. A blocked slot's reason is never read out.
- **Another advisor:** their slot, and their event over this advisor's afternoon, never reach this advisor's proposals. Their own run sees only their own slot.
- **A failing reader:** with the interview-call table gone, the run still answers and names `interview_calls` in `dropped`. With no time zone, free afternoons are skipped with `no_time_zone`.
- **Nothing to propose:** `nothing_to_propose`, with no row written, both when only an all-day deadline is in the way and for an advisor with no open slot.
- **The window:** `days: 1` reads nothing, and an out-of-range or fractional value reads as 14.
- **Registration:** `railOptionsOn('Advisor · Practice · Sessions')` lists `sessions:block`, "Find a free afternoon", with no models.

**`rail_matrix_d764`** now also holds each no-model chip: it has a row with `handler` and `routeTask` both `none` and nothing to pick, and the row count includes it. Every other `handler: 'none'` option still has no row.
