### 2. Who Ask serves

`askServes` (`ui/askPanelModel.js`) returns true only when all of these hold:
- the page has a rail page key;
- no support session is active (`lib/supportSession.js`);
- the viewer is not an Explorer;
- the viewer's licence is the page's own (the rail's `role`). Staff ask on the staff consoles only.

The last rule is S1's note on #3706 (2026-11-01): an HQ admin previewing a founder's or an investor's page is reading someone else's record, so gets no Ask. The Worker refuses a support session and an Explorer too, in D1442.

### 3. Where it sits

`WorkerRail` mounts the panel; no host changes.
- **1024px and up** (#4260, #4263): a portalled, `position: fixed` `.ead-ask-dock` at the document's level, placed from the rail's measured box (`askDock`, `ui/askPanelModel.js`). It runs from the scroll area's top, under the header, to the footer's top or the window's foot, whichever is higher, so it passes neither. It sits at the column's seam where the column took the panel's width (1440px and up, `data-ask-room`), or against the column's outer edge over the content (1024 to 1439px, or a host whose track does not widen), and never left of the scroll area. `WorkerRail` places it on scroll, on resize and on the rail's resize, as inline style rather than React state, so scrolling re-renders nothing. The page stays usable: it is `role="complementary"`, not modal.
  - **Why it left the rail.** It was first drawn inside the rail's own `<aside>`. There its box was the rail's: 18px under the header and 28px above the foot inside `RailFrame`'s padding, as short as a collapsed spine, and styled by every host rule written for the rail's children (`.inw-rail section` boxed it, `.a6-rail>div` pushed it down). The container query that placed it was unmet in the owner's collapsed rail.
- **640–1023px:** portalled over the content, under the header.
- **Below 640px:** a bottom sheet at 92% with a scrim, `role="dialog"`, `aria-modal`, 44px controls.
- Escape and × close it, as do a route change and a D1317 detail sheet opening. Opening Ask closes D698's phone panel and the reverse, so one Eadwyn surface shows at a time.
- **Not yet:** the content narrowing beside the panel from 1440px (AK12). About 28 hosts draw their own rail column, and each must read the wider track. That is #3992.

### 11. #4737: four integration gaps closed (S13, 2026-11-07)

S1's audit of the week's frontend found four places where the panel and the rest of the app disagreed. Each is fixed; the decisions are these.

1. **A Block card is accepted on the Sessions page, in D1596 §4's order.** Accept used to call `decide(uid, 'accept')` and mark the card Accepted, and no slot was blocked.
   - Accept on a `sessions:block` card now sends the advisor to `/practice/sessions?block=<uid>&from=<day>&until=<day>` and closes the panel. The card's Edit link goes to the same address. Neither decides anything (`ui/sessionsBlockHandoff.js`).
   - `SessionsZone` reads the address, opens its Block form filled with the dates, and takes the keys out of the address. The proposal is decided (`railProposalsApi.decide(uid, 'accept')`) only after `POST /api/advisors/me/slots/block` succeeds. Cancelling leaves the card waiting in Ask. If the decide fails after a successful block, the page says the block stands and the card is still waiting; it never shows the Worker's message.
   - "Accept all" never holds a Block card. Accepting one means pressing Block, so it is taken one at a time. `decide` itself also refuses to accept one.
   - **The form blocks whole days.** Its inputs are dates and it sends `<date>T00:00:00.000Z`, so a card for 12:00 to 18:00 fills one day, and Block closes that day's open hours, not only the afternoon. The form says so when it was filled from a card. A booked hour is still skipped. If afternoons should be blockable, the form needs times: a separate decision.
2. **"N waiting" counts what the panel lists.** `waiting` counted every proposed row on the page, including form Fill rows (`form:*`) and module rows, while the panel lists cards only for run chips (`RUN_CHIPS`). It now counts only rows whose `rail_option` is a run chip, so every counted row is a card the opened panel shows, and a page with only form rows draws no pill.
   - **Not done:** listing every open row in the panel, with Fill rows opening `FillModule`'s own panel, or having `FillModule` claim the header slot as `DeckAsk` does. A form's and a module's rows are acted on in the form or module that holds them (§8), and the count should say only what the panel can show.
3. **Ask is reachable on a phone where only the fallback carries it.** The rail's fallback Ask is in the column, hidden below 1024px, and the floating button opens a sheet (or a founder's Eadwyn panel) that drew only the rail's body. While Ask serves the page and no header carries it (and the rail is not a deck's), both now lead with a `PageAsk`. Opening the Ask panel closes the sheet, as it already closes the founder's panel. The alternative, retiring D405's button for a phone Ask button, is not taken: the button is still how a phone reaches the rail's model choice and spend.
4. **This file.** §3 describes the portalled fixed dock (#4260, #4263), §4 notes the Block card, §5 lists `quote` and `waiting` as through, and §10 notes the sheet's Ask. The decision test now fails when §5 lists a method as off that `ASK_OFF_METHODS` lacks, and when the dock's old in-rail class name appears under `frontend/src` or in this file. `AskPanel.jsx`'s header comment and the `ui/README.md` row are corrected.
