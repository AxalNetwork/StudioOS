### 1. The read

`GET /api/admin/users` keeps its address, its gate (`requireAdmin`) and its two answers:
- **With no `envelope`,** it answers the page as a flat array. Every picker that calls it with `q` and `limit` reads that.
- **With `envelope=1`,** it answers D128's whole-table `total` and `by_role`, which the console's tiles read, plus what is new below.

**Filters.** Each takes one value or a comma list. Within a filter a list means any of its values; across filters, all of them must hold.

| Filter | Values | What it reads |
|---|---|---|
| `profile` | founder, investor, advisor, partner, exploring, admin | `users.role` |
| `sub` | lp, tester, none | an approved `lp_applications` row; an `active` `product_testers` row; neither |
| `status` | active, deactivated | `users.is_active` (§3) |
| `email` | verified, unverified | `users.email_verified` |
| `identity` | not_started, pending, needs_info, approved, rejected, expired | `users.kyc_status`. No value reads as not started, its default. `pending` is the canvas's "Waiting". |
| `limited` | on, off | `users.access_level = 'limited'` |
| `plan` | plan names | `users.subscription_tier`, free when unset |
| `country` | up to 20 names | `users.country`, matched whatever its case |
| `joined` | 7d, 30d | `users.created_at` |
| `joined_from`, `joined_to` | YYYY-MM-DD | `users.created_at`. These cannot be combined with `joined`. |
| `active` | 7d, 30d, over_30d, never | `last_active_at`, else `last_active` |
| `persona` | segment keys | the primary `user_personas` row |
| `program` | lab, mentor, testing | `users.spinout_lab_active`; an active `advisor_cohort_assignments` row; an active product tester |
| `trust` | under_50, 50_79, 80_up, not_recorded | the trust score (§2) |

**Search.** `q` reaches name, email and account uid. As D128 made it, one character is refused.

**Sorts.** The default is `joined_desc`. The others:
- `joined_asc`;
- `active_desc` and `active_asc`;
- `name_asc`;
- `completeness_asc`;
- `trust_asc`.

A value nothing records sorts last either way, never as the smallest value.

**Paging.** `limit` defaults to 100, as today, and is at most 200. `offset` pages on. The envelope's `next_offset` is null on the last page, so a caller pages until it is null and reaches every row.

**Refusals.**
- **A value outside a filter's set** is a 400 naming the filter (`invalid_<filter>`), never ignored.
- **A filter or sort that needs a store this database cannot read** is a 503 `filter_unreadable`, never "none match".

### 2. The columns

Each row keeps today's fields: `id`, `uid`, `email`, `name`, `role`, `is_active`, `email_verified`, `kyc_status`, `access_level` and `created_at`. It adds:
- `last_active_at`, `country`, `subscription_tier` and `profile_completion_pct`;
- `persona`;
- `sub_accounts: { lp, tester }` and `programs: { lab, mentor, testing }`;
- `trust: { score, open, reason }`.

**Nothing recorded is null, never 0.** That covers a completeness never computed, an activity never logged, and a column or store this database lacks. The envelope's `unreadable` names each missing column or store, so the page can say "Trust scores could not be read" (ACC3) instead of drawing a dash as a fact.

**The trust score.** It is `trustScoreOf`'s rule: the share of required legal obligations that are satisfied or waived, rounded. `open` is how many required obligations are left.
- **Where no obligation is required, the score is null,** with the canvas's sentence "Not recorded: no obligation applies yet".
- **This is not what the member sees.** `trustScoreOf` calls that case 100 in the member's own Trust Center. The list follows the canvas. **The owner may want one answer for both.**

### 3. Totals over the filtered set, and the rule for deactivated accounts

**The envelope's totals:**
- **`matched`** counts every row the filters keep, across every page. `from` and `to` place the page within it ("1–25 of 61").
- **`matched_by_role`** splits `matched` by profile.
- **`status_split`** counts active and deactivated under every filter but the status one, so the Status filter can say what each choice would show.
- **`total` and `by_role`** stay counts over the whole table.
- **`narrowed`** says whether anything filtered, searched or sorted.

**The rule for deactivated accounts** is `DEACTIVATED_RULE` in `services/accountsList.ts`, for D1301's overview read to import:
- **What it is:** an account is deactivated when `users.is_active = 0`, and only then.
- **In the list:** a deactivated account is shown, marked by `is_active: 0`, unless `status=active` asks otherwise.
- **In every count:** active and deactivated are said apart, never folded together.
- **In the overview:** it counts active accounts and puts the deactivated beside them, which is what `studioGlance.hqAccounts` already does (`is_active = 1` and `is_active = 0`).

### 4. Another studio's accounts

A studio is its own Worker over its own D1 (D106), so `users` holds this deployment's accounts only. A `scope` naming another studio is refused before any read, as Insights refuses it (D893):
- **A plain Admin, or any admin on a branch:** 403 `hq_only`, with "This view is for HQ. You see the accounts you manage."
- **HQ's Super Admin:** 400 `scope_unavailable`. HQ does not fan a list of names and emails out of a subsidiary. A subsidiary's accounts are listed on its own console.
- **The deployment's own scope** (`hq`, or the branch's code) reads as normal.

### 5. Bound, and logged without people

**Bound.** The WHERE clause is built from fixed fragments with `?` placeholders. Every value the caller sent travels in `bind`, after its filter's allow-list has passed. Nothing is interpolated into the query text, and `check-sql-prepare`'s baseline is unchanged.

**Logged without people.** A failed read logs the error's name only, and answers 500 `accounts_unreadable`: "That is not the same as no accounts." No name or email is logged or returned in an error.

### 6. The client

`api.adminListUsers` passes every filter, the sort and the scope through. A list is joined with commas, and empty values are dropped. Called without them, it asks exactly what it asked before, so every current caller is unchanged:
- the console;
- `BranchAccounts`;
- the KYC, Perks, Lab, Deck and Token pack pickers.

The boards that draw the filters are D1304–D1307.
