## D617 — Article review comments: only the author or a Super Admin deletes one, and the delete is logged

**Issue:** #1314 · S16, found by #1165's audit (area 7, comment deletion). **No migration.**

### What was true on `main`

`DELETE /api/admin/articles/comments/:cid` (`cloudflare-worker/src/routes/admin_articles.ts`) checked only `requireAdmin`, hard-deleted the row, and always returned `{ ok: true }`, even for an ID that did not exist. Because authors view review comments on their submissions (`routes/articles.ts`), an unlogged silent deletion by any administrator removed critical feedback without accountability.

### What was decided

1. **Authorization gate:** Deletion is restricted to the comment's author (`author_id === admin.id`) or a Super Admin (`isSuperAdmin(admin)`). Any other administrator receives a `403` status with `{ error: 'not_your_comment' }`.
2. **Existence check:** An unknown or invalid comment ID receives a `404` status with `{ error: 'comment_not_found' }`, never a silent `{ ok: true }`.
3. **Audit logging:** Successful deletions are logged through `logAdminAction` with action `article_comment_deleted`, capturing `article_id` and `comment_id`. In accordance with privacy and audit rules, the comment's textual body is never written into the audit log payload.

### Verified

`cloudflare-worker/test/article_review_comments_delete_d617.test.ts` asserts:
- The comment author deletes their own comment (200, row removed, audit logged).
- A Super Admin deletes a comment authored by another administrator (200, row removed, audit logged).
- Another administrator is refused (403 `not_your_comment`, row preserved, no audit log).
- An unknown comment ID is refused (404 `comment_not_found`, no audit log).
- Audit details omit the comment text across all delete operations.

All assertions verified against mutations. `node scripts/check-decision-ids.mjs` passes.
