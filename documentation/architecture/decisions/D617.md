## D617 — Only the author or a Super Admin deletes a review comment, and the delete is logged

**Deleting an article review comment is the author's, or a Super Admin's, and the delete is written to the audit log.** Issue #1314. No migration.

**Who.** `DELETE /api/admin/articles/comments/:cid` allows the comment's `author_id`, or a Super Admin. Anyone else gets 403 `not_your_comment`, and the row stays. An unknown id, including one that is not a positive number, gets 404 `comment_not_found`. It no longer answers `{ok: true}` for a comment that was never there.

**The log.** Each delete that happens is `logAdminAction` as `article_comment_deleted`, with `article_id` and `comment_id` only. The comment's text is not in the row. The author and a Super Admin are both logged. A refused delete writes nothing.

Resolving a comment stays the non-destructive path, and this change does not add a Delete control to the review page. That design is requested on #1165 (area 7, item 4). D623, which limits who may edit the text, is a separate rule.
