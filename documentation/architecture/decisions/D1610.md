### 2. W2: `next_steps`

`{ state: 'ok' | 'empty' | 'unreadable', items: [{ item_key, label, text, module_slug, href, gain_points }] }`, from `loadReadiness`.

- **The gain.** `gain_points` is `overallReadiness` with that item at 10, minus `overallReadiness` now. An unscored item at 10 joins the mean. An item already at 10, or one whose gain is not above 0, is not a step.
- **Team is never a step:** a person assesses it. Its score still counts in the overall score.
- **Order:** gain, largest first, then the readiness card's order. At most three (`NEXT_STEPS_MAX`).
- **`text`:** the score's `missing` words. Without them, "Not scored yet" for an unscored item, or "Scored n of 10".
- **`href` and `module_slug`:**

  | Item | `module_slug` | `href` |
  |---|---|---|
  | Investor narrative, Pitch deck, Data room, Cap table, Use of funds | its Raise module | its module page |
  | Traction proof | `fundraising-readiness` | `TOOL_HREF.metrics` (`/build/kpi`) |
  | Product-market fit | `fundraising-readiness` | the Fundraising readiness page |

  Every `href` carries `?project=`.
- **Empty.** No item scored gives `state: 'empty'` with one item: `readiness`, "No readiness item is scored yet", linked to Score readiness (`&add=1`), with `gain_points: null`. An unknown gain is never 0.
- **Unreadable.** A thrown read gives `{ state: 'unreadable', items: [] }`. The rest of the overview still renders.
- **Staff** get the same items. The page drops the links (RO14).

### 3. W3: `connectors`

`[{ key, label, fact, as_of, state: 'connected' | 'not_connected' | 'unreadable' }]`: the three tools Raise reads.

| Key | Connected when | `fact` | `as_of` |
|---|---|---|---|
| `mercury` (D840) | an active `mercury` integration | "16.5 months of runway · cash and net burn", from `mercuryRunway`; "No runway read yet" without a fact | the fact's `as_of` |
| `github` (D1264) | an active `github` integration | "Contributors to n repositories"; "No repository read yet" | `MAX(github_contributors.updated_at)` for the venture |
| `google` (D1094) | an active `google_workspace` integration | "n chosen files for Raise" (Pitch deck, Data room, Capital relationships, not stopped); "No file chosen for Raise yet" | `MAX(google_workspace_files.last_synced_at)` |

- **Whose connection counts.** The integration's member must be active and be the venture's founder or an accepted member. This is the join `mercuryFacts` and `teamReadiness` use. Another founder's connection, or an inactive one, is `not_connected`.
- **`as_of`** is the stored timestamp as written, only when it has a timestamp's form. Otherwise it is `null`: never a date the Worker made up, and never 0.
- **Facts are counts.** The runway is the one exception, and the figure row already shows it. A fact never holds a login, repository, file name, counterparty or amount, and staff read the same.
- **Failures.** Each row fails on its own (`unreadable`). When no row can be read, as when the connections themselves are unreadable, the list as a whole is `{ state: 'unreadable' }`. The overview still renders.
- **Bound SQL only:** each statement is written in full, with nothing interpolated.
- **Notion is not here.** No Raise read uses it. The issue's "Mercury, Google, Notion" defers to S1's list, which this extends with Google because Raise does read Google (D1094).
