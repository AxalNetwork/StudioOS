### 3. The capability table

The columns are:
- **MCP:** the vendor's own MCP server (third-party servers do not count);
- **Read scopes:** least privilege;
- **Write:** flagged for the owner's approval;
- **Review:** what must be approved before members can connect;
- **Limits:** the rate limit and how a limit is signalled, for #2469's `classifyError`;
- **Push:** webhooks or events, and how they are signed.

#### 3.2 Notion: planned in #2405

- **MCP: yes.**
  - Hosted server: `https://mcp.notion.com/mcp` (Streamable HTTP), with `/sse` as a fallback.
  - Auth: OAuth 2.0 with PKCE, dynamic client registration, and Client ID Metadata Documents.
  - Tools confirmed on the official page: `notion-search`, `notion-fetch`, `notion-create-pages`, `notion-update-page`, `notion-move-pages`, `notion-duplicate-page`, `notion-create-database`, `notion-create-comment`, `notion-get-users`, `notion-create-view`, `notion-get-async-task`.
  - The older local server, `makenotion/notion-mcp-server`, is no longer maintained ([R]).
  - Sources: [S] https://developers.notion.com/guides/mcp/build-mcp-client, https://developers.notion.com/guides/mcp/mcp-supported-tools; [R] https://raw.githubusercontent.com/makenotion/notion-mcp-server/main/README.md
- **API:** REST.
- **Read scopes:**
  - Notion has no OAuth scopes. An integration's capabilities decide access, each per shared page or database.
  - Least privilege is: Read content only, plus Read comments if needed, plus user information without email.
  - [S] https://developers.notion.com/reference/capabilities, https://developers.notion.com/guides/get-started/authorization
- **Write (flagged):** Update content, Insert content, Insert comments.
- **The hosted MCP server has no read-only endpoint.** Its grant reaches what the member can reach, so read-only rests on our tool allowlist. That is #2415's decision 6, unchanged.
- **Review:** none to connect through OAuth. A security review applies only to a Marketplace listing. [S] https://developers.notion.com/guides/get-started/public-connections
- **Limits:**
  - 180 requests/min per connection (600 on Business and Enterprise), plus a workspace-wide limit.
  - A limit is signalled by 429 `rate_limited` with `Retry-After`.
  - [S] https://developers.notion.com/reference/request-limits
- **Push:**
  - Webhooks are signed with `X-Notion-Signature: sha256=<hex>`, an HMAC of the raw body keyed with the subscription's `verification_token`.
  - Events are signals only; the content is fetched afterwards.
  - [S] https://developers.notion.com/reference/webhooks
- **Cost:** the API on free plans is UNVERIFIED (only a 2021 announcement says so). Non-interactive MCP tokens need Business or Enterprise. [S] https://developers.notion.com/guides/mcp/get-started-with-mcp
- **Pattern: B**, as #2405 plans.

#### 3.3 GitHub: on `main`

- **MCP: yes.**
  - Remote server: `https://api.githubcopilot.com/mcp/` (Streamable HTTP).
    - Auth: OAuth 2.1 with PKCE, or a personal access token.
    - Read-only mode: append `/readonly` or send `X-MCP-Readonly`.
    - Toolsets each have their own address: `/mcp/x/{toolset}`.
  - Local server: `ghcr.io/github/github-mcp-server`, stdio, personal access token only.
  - Tools include `get_file_contents`, `list_commits`, `list_releases`, `issue_read`, `list_issues`, `search_issues`, `pull_request_read` and `list_pull_requests`, with write tools beside them.
  - A GitHub App as the server's auth: not documented.
  - Sources: [R] https://raw.githubusercontent.com/github/github-mcp-server/main/README.md, https://raw.githubusercontent.com/github/github-mcp-server/main/docs/remote-server.md
- **API:** REST and GraphQL.
- **Read scopes:**
  - **A GitHub App's fine-grained read permissions,** with the repositories the installer chooses. This is what `main` uses.
  - An OAuth App has **no read-only scope for private repositories**: `repo` is read and write.
  - [R] https://raw.githubusercontent.com/github/docs/main/content/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps.md; [S] https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app
- **Write (flagged):** Contents, Issues or Pull requests set to write; `repo`, `public_repo`, `workflow`.
- **Review:** none. A public GitHub App needs no review, and the Marketplace is optional. [R] https://raw.githubusercontent.com/github/docs/main/content/apps/creating-github-apps/registering-a-github-app/making-a-github-app-public-or-private.md
- **Limits:**
  - REST:
    - 5,000/h per user token;
    - for an installation, 5,000/h scaling to 12,500;
    - secondary limits of 100 concurrent requests and 900 points/min;
    - signalled by 403 or 429.
  - GraphQL: 5,000 points/h.
  - [S] https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api; [R] https://raw.githubusercontent.com/github/docs/main/content/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api.md
- **Push:** webhooks signed with `X-Hub-Signature-256: sha256=<hex>` over the raw body. [S] https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries
- **Cost:** free. Whether the remote MCP server needs a Copilot licence is UNVERIFIED.
- **Pattern: C stays.**
  - The MCP server cannot authenticate as a GitHub App.
  - So it would ask for a user grant whose private-repository scope also writes.
  - The App's per-repository read-only grant is stronger than any allowlist.
  - #2469 moves this adapter onto the contract. Nothing new.

- **MCP: yes, generally available since 2026-02-17,** but not open to Axal as it stands.
  - Endpoint: `https://mcp.slack.com/mcp` (HTTP), with a user OAuth token.
  - **Who may use it:** "Only apps published in the Slack Marketplace and internal apps can use MCP at this time; unlisted apps are prohibited." Workspace admins approve MCP clients.
  - The search scopes (`search:read.*`) are for select partners.
  - Tool names: UNVERIFIED (seen only in third-party catalogues).
  - Sources: [S] https://docs.slack.dev/ai/slack-mcp-server/, https://docs.slack.dev/changelog/2026/02/17/slack-mcp/, https://docs.slack.dev/apis/web-api/real-time-search-api/
- **API:** Web API and Events API.
- **Read scopes:**
  - Bot token: `channels:read`, `channels:history`, `users:read`. The bot must be invited to each channel.
  - Add `groups:history` and `im:history` only if needed.
  - [S] https://docs.slack.dev/reference/scopes/channels.history/
- **Write (flagged):** `chat:write`. The existing `incoming-webhook` posts too.
- **Review and limits, the deciding fact:** for a commercially distributed app **not** in the Marketplace, `conversations.history` and `conversations.replies` drop to 1 request/min and at most 15 objects.
  - This applies to new installs since 2025-05-29 and to existing installs since 2026-03-03.
  - Marketplace and internal apps are exempt.
  - Marketplace review is manual. It is "enhanced" for `*:history` and `search:read.*`, and it excludes MCP-only apps.
  - The install threshold is 5 or 10 workspaces: the pages disagree. UNVERIFIED.
  - [S] https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps/, https://docs.slack.dev/slack-marketplace/slack-marketplace-app-guidelines-and-requirements/
- **Other limits:** tiered (Tier 1 = 1+/min up to Tier 4 = 100+/min), `chat.postMessage` about 1/s per channel, and 429 with `Retry-After`. [S] https://docs.slack.dev/apis/web-api/rate-limits/
- **Push:** Events API, signed with `X-Slack-Signature`, `v0=` plus an HMAC-SHA256 of `v0:{timestamp}:{raw body}`. [S] https://docs.slack.dev/authentication/verifying-requests-from-slack/
- **Cost:** free workspaces show only the last 90 days. [S] https://slack.com/help/articles/115002422943-Usage-limits-for-free-workspaces
- **Pattern:**
  - **C for the notifications on `main`.**
  - Reading Slack is **blocked on the owner's decision to list Axal in the Slack Marketplace (§5, question 1).**
    - Without a listing, both patterns are closed or impractical: B is prohibited, and C is limited to 1 request/min.
    - With a listing, B becomes the better reader: the server enforces the member's own access.

#### 3.5 Linear: new

- **Write (flagged):**
  - `write`, `issues:create`, `comments:create` and `timeSchedule:write`.
  - `admin` must never be asked for.
  - Creating a webhook needs a workspace admin.
- **Review:** none for OAuth. The Integration Directory listing is optional. [S] https://linear.app/docs/integration-directory

  - OAuth: 5,000 requests/h per user and 2,000,000 complexity points/h.

  - Signalled by `X-RateLimit-*` and `X-Complexity` headers.
  - [S] https://linear.app/developers/rate-limiting
- **Push:** webhooks signed with `Linear-Signature`, a hex HMAC-SHA256 of the raw body. The payload timestamp is rejected after 60 s. [S] https://linear.app/developers/webhooks
- **Cost:** UNVERIFIED (the pricing page lists "API and webhook access" under an unclear tier). Admin approval of third-party apps is on paid plans. [S] https://linear.app/pricing
- **Pattern: B, read-only.**
  - It fits #2468's client exactly: OAuth 2.1, dynamic registration, Streamable HTTP.
  - **Read-only is enforced by Linear on two sides,** the `/readonly` endpoint and the `read` grant. Our allowlist is a third guard, not the only one.
  - It is the lowest-risk new connector on this list.
  - **Workflows:**
    - Build: the roadmap and issues, beside GitHub's.
    - Validate: feedback issues.

#### 3.6 Discord: new, conditional

- **MCP: no** for Discord's data. Discord publishes only a documentation server, `docs.discord.com/mcp`, which reads developer docs. [S] https://docs.discord.com/developers/change-log
- **API:** REST, the Gateway (WebSocket), and HTTP interactions.
- **Read scopes:**
  - The OAuth2 `bot` scope, with a permissions integer of View Channel and Read Message History. The bit values are UNVERIFIED.
  - **`MESSAGE_CONTENT` is a privileged intent.** Without it, message text is empty except in DMs, mentions and the app's own messages.
  - [S] https://docs.discord.com/developers/topics/oauth2, https://docs.discord.com/developers/events/gateway
- **Write (flagged):** Send Messages; `applications.commands.permissions.update`.
- **Review:**
  - App verification is required to grow past 100 servers.
  - Privileged intents are a portal switch under 10,000 users, and need an application at 10,000.
  - The effective date of that change is UNVERIFIED.
  - [S] https://support-dev.discord.com/hc/en-us/articles/23926564536471-How-Do-I-Get-My-App-Verified, https://support-dev.discord.com/hc/en-us/articles/40281523410967-Changes-to-Privileged-Intent-Access-for-Discord-Apps
- **Limits:**
  - 50 requests/s global per bot, plus per-route buckets.
  - Signalled by 429 with `retry_after` and `X-RateLimit-Scope`.
  - Invalid requests are capped at 10,000 per 10 minutes per IP.
  - [S] https://docs.discord.com/developers/topics/rate-limits
- **Push:**
  - Message events come only over the Gateway, a long-lived WebSocket. A Worker would need a Durable Object to hold it. That design cost is UNVERIFIED for Axal's plan.
  - Interactions are signed with Ed25519 (`X-Signature-Ed25519` over timestamp plus body).
  - [S] https://docs.discord.com/developers/interactions/receiving-and-responding
- **Cost:** UNVERIFIED (no official statement found).
- **Pattern: C.** Build it only if the owner names a use (§5, question 3), for example community feedback into Validate or Research.
  - Reading message text needs the privileged intent.
  - Reading live needs a Gateway connection.
  - Both make this the costliest reader on the list.

#### 3.9 Cloudflare: new

- **MCP: yes, several servers.**
  - Transport is Streamable HTTP at `/mcp`. The old `/sse` addresses are aliases that no longer serve SSE.
  - Auth is OAuth, with **optional scopes**: the member can grant fewer scopes at consent.
  - **The Cloudflare API server,** `https://mcp.cloudflare.com/mcp`, covers over 2,500 endpoints in "Code Mode".
    - Its tools are `search()`, `execute()` and `docs()`.
    - `execute()` runs generated code against any endpoint the grant allows.
  - **Product servers** include:
    - `builds.mcp.cloudflare.com`
    - `observability.mcp.cloudflare.com`
    - `dns-analytics.mcp.cloudflare.com`
    - `bindings.mcp.cloudflare.com`
    - `logs.mcp.cloudflare.com`
    - `auditlogs.mcp.cloudflare.com`
    - `docs.mcp.cloudflare.com`
  - Whether a third-party client registers dynamically is UNVERIFIED.
  - Sources: [R] https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/, https://developers.cloudflare.com/changelog/post/2026-07-28-cloudflare-mcp-servers-mcp-2026-07-28/, https://developers.cloudflare.com/changelog/post/2026-08-22-wrangler-mcp-optional-oauth-scopes/
- **API:** REST at `https://api.cloudflare.com/client/v4`, and GraphQL Analytics.
- **Read scopes:**
  - Read permission groups: `Account Analytics Read`, `Zone Read`, `DNS Read`, `Workers Scripts Read`, `Logs Read`.
  - Cloudflare OAuth clients use the Authorization Code flow, and their scope names are the permission names.
  - [R] https://developers.cloudflare.com/fundamentals/api/reference/permissions/, https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/
- **Write (flagged):** every Edit or Write group, for example `Workers Scripts Write`, `DNS Write`, `Zone Write`, `Cache Purge` and `API Tokens Write`.
- **Review:** none for API tokens. For a third-party OAuth client: UNVERIFIED.
- **Limits:**
  - 1,200 requests per 5 minutes per user or account token. Going over is a 429 and blocks the token for 5 minutes.
  - GraphQL: 300 queries per 5 minutes.
  - [R] https://developers.cloudflare.com/fundamentals/api/reference/limits/, https://developers.cloudflare.com/analytics/graphql-api/limits/
- **Push:**
  - There are no resource-change webhooks.
  - Notification webhooks carry a shared secret in `cf-webhook-auth`. **Not an HMAC:** compare it in constant time.
  - [R] https://developers.cloudflare.com/notifications/get-started/configure-webhooks/
- **Cost:** the API itself is free: UNVERIFIED. Some products are plan-gated.
- **Pattern: B, on the product servers only.**
  - Use `builds` and `observability` for Build (is the founder's app deployed and healthy), and `dns-analytics` if the owner wants domains.
  - Request read scopes only.
  - **Never `mcp.cloudflare.com`'s `execute()`.** It runs arbitrary generated code against the member's account; our allowlist cannot see what it will call, and its read-only-ness would rest on the grant alone.
  - **Overlap with Vercel (#2408)** for "what is running": each founder uses one host or the other.

#### 3.10 Stripe: on `main`

- **MCP: yes.**
  - Endpoint: `https://mcp.stripe.com` (HTTP).
  - Auth: OAuth (per-environment consent) or agent API keys.
    - **After 2026-11-30** the MCP server refuses full secret keys and restricted keys without the Agent tag.
    - Connected-account access works only with an agent key.
  - Some `stripe_api_write` actions need a human confirmation that expires in 24 h.
  - Tools include `stripe_api_write`, `stripe_analytics` and `stripe_reports`. The Treasury tools are in preview.
  - Sources: [R] https://docs.stripe.com/mcp, https://docs.stripe.com/data/analyze-with-ai, https://docs.stripe.com/treasury/agents
- **API:** REST.
- **Read scopes:**
  - Restricted keys set Read per resource, for example `Data > Metrics: Read` and `Reporting: Read`. `main` uses Connect `read_only`.
  - The scope names of Connect OAuth are UNVERIFIED in this pass.
  - [R] https://docs.stripe.com/keys/restricted-api-keys
- **Write (flagged):**
  - any resource set to Write;
  - Payouts, Currency Conversions, Outbound Payments and Transfers, Recipient Configuration.
- **Review:** none for restricted keys or MCP OAuth. Publishing a Stripe App takes about 4 business days of review. [R] https://docs.stripe.com/stripe-apps/publish-app
- **Limits:**
  - **100 requests/s per account in live mode and 25/s in sandbox,** plus 25/s per endpoint and 20/s for Search.
  - Signalled by 429.
  - [R] https://docs.stripe.com/rate-limits
- **Push:**
  - `Stripe-Signature: t=…,v1=…`, an HMAC-SHA256 of `{t}.{raw body}` with the endpoint's secret.
  - Ignore any scheme other than `v1`.
  - [R] https://docs.stripe.com/webhooks
- **Cost:** only transaction fees: UNVERIFIED. Sigma, for SQL runs, is paid.
- **Pattern: C stays.**
  - The MCP server's surface is write-heavy, and its connected-account access needs an agent key, which Axal would have to hold per member.
  - The Connect `read_only` grant is narrower.
