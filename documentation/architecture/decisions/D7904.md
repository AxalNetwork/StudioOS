## D7904 — Admit directly on the target without OIDC exposure (#7904)

Remove the hosted preflight job instead of putting it in the external pickup
path. The one target job checks out the immutable main workflow revision from
GitHub's reserved `github.workflow_sha`, then independently resolves the current
receipt, catalog and GitHub provenance before any candidate checkout. It checks
again before installs and execution. No caller branch/ref becomes control code.
The source remains the admitted candidate, not current main.

Routing uses a fixed main-definition mapping for the three existing profiles:
standard hosted Ubuntu, or the approved group and exact AND labels for Linux
x64 / Mac ARM64. Workflow input never becomes an arbitrary label, group, image
or larger-runner selector. Catalog admission and actual runtime/isolation checks
must agree with that selection; unknown input cannot admit candidate code.
The existing native Node and Python pins and execution budgets are retained.

There is no preflight OIDC job left, so this executor grants no `id-token`
permission at all. Both workflow and job tokens have only Contents and Actions
read access. Candidate install scripts cannot use the job environment to mint
OIDC tokens. This does not implement the still-unconfigured coordinator transport.
A future authenticated transport must be separately reviewed without restoring
OIDC minting access to candidate installation or tests. Unconfigured authority
continues to deny before candidate checkout.

Admission and result observation accept only the actual `runner-executor.yml`.
The nonexistent dispatch wrapper and caller/callee identity allowance are
removed. The shard/event contract remains the six Worker shards on push and
merge_group, aligned with D7903. No live dispatch, caller cutover, required-check
change or self-hosted enablement is performed; D7905's boundary proof is required.
