## D5567 — Workspace broker grants, provider eligibility and encrypted object boundary (#5567)

**Status:** local, host-independent security foundation. Unmounted and disabled; no token issuer, object route, publisher or Container is activated by this change. Depends on D5565. Hosted isolation and production activation remain unproved and separately gated.

### Trust model

An agent task can contain a hostile repository, install script, shell command, package binary, prompt injection, archive, generated output or PR description. Those are data. None may choose tenant/sponsor/roles, mint its own grant, modify image allowlists, supply security evidence, read a raw R2 key, change region, use a cloud control-plane credential or publish an integration. BYOC is an independent trust zone, not a tenant inside Axal's trusted control plane.

The existing Worker remains the only privileged broker. Its normal authentication/role/company/project/task checks resolve the persistent sponsor and run; D5565 structural validation alone grants no authority. Security evidence comes from an owner-controlled verifier/registry and current platform policy, **never** from booleans supplied by an executor or browser. Unknown policy, quota, image or containment denies admission.

`workspaceSecurity.ts` is the unmounted service seam. Its atomic store must be backed by the scoped DO transaction boundary; the process-local memory implementation exists only in tests. D1 remains authoritative for memberships, roles, existing task/run ownership, permission revisions, human decisions and artifact references. Runtime integration must mirror and fence revocation in the DO before acknowledging it and re-check current D1 authorization at every issue/redemption. This patch does not pretend that those route/store adapters already exist.

### Grant and revocation contract

The broker imports a nonextractable HMAC-SHA256 root key of at least 256 bits. It derives a distinct signing key per tenant/run/generation/audience and issues a 1–60 second, nonce-bound grant containing the exact company/project/agent/task/run/attempt/generation, member, authorization revision and immutable spec hash. No provider/account-wide credential or key material is serialized. Audiences are separate bootstrap, heartbeat, completion, artifact upload/read and integration publication. Object and target-region bindings are mandatory for object/publisher audiences.

A grant is consumed once atomically, even under concurrent redemption. Signature, canonical encoding, expiry, exact target/audience, current image/provider policy, live sponsor/revision, run generation and issued nonce identity are checked before acceptance. Revoking a run clears its issued grants; advancing a generation preserves all other immutable scope/image/budget fields and invalidates old grants. The existing runtime, not a runner callback, owns those control operations. Exact completion replay belongs to D5565's idempotent completion/manifest contract using a fresh valid request grant; replaying a spent grant never repeats an effect.

Publication additionally requires the current existing human approval to cover that exact object/run; a previously issued publication token cannot outlive revoked approval. No second task engine, permission database, model router, usage ledger or billing hold is introduced. D4557's v1 compute grants and deterministic host boundary are unchanged.

### Image, containment and network gate

Every selected image must match a digest with verified signature, provenance, SBOM and a passing vulnerability outcome; revoked or unknown evidence denies admission. The selected provider must attest non-root execution, immutable system image, ephemeral scratch, resource enforcement, no privileged mode/host socket, private/metadata denial and a connection-time network fence. Hostile coding workloads additionally require verified microVM/gVisor-class isolation; a plain Linux container is insufficient evidence. D5565's actual resource, residency, shell, cancellation, checkpoint and capacity capabilities still apply.

For deny policy, the actual provider must disable outbound connectivity. For allowlist policy, hostname checks alone are insufficient: connect-time enforcement must cover private/reserved IPs, DNS rebinding, redirects, localhost and metadata; HTTP-only interception does not establish raw socket coverage. The URL preflight rejects non-HTTPS, credentials, alternate ports, literals, local/metadata names and unlisted domains. Only a provider with verified enforcement is eligible. No network call to a metadata endpoint is made by these tests.

Cloudflare is the first candidate (#5566), not a presumed blanket security guarantee. Current Container configuration/API can express digest-pinned named images, explicit Internet denial and resource sizes; unsupported residency/readonly-filesystem/isolation guarantees must remain unknown/ineligible until the pilot proves them. Azure/GCP/AWS (#5571) and BYOC (#5572) remain disabled until their own IAM, network, image, runtime and regional evidence is registered. A provider's self-report cannot enable itself.

### Server-mediated R2 and keyed lifecycle

A grant names an opaque object reference. The broker resolves its current metadata and checks tenant/company/project/run/generation, sink, expiry, key ID and target region. Naming a tenant prefix is not authorization and no raw R2 credential/key reaches a coding container. A cross-region read/restore needs both the spec's allowed region, verified provider enforcement and an explicit server-owned approval on that object. The caller cannot turn a different region into the original region by editing its request.

Sensitive snapshots/logs are sealed with AES-256-GCM using a tenant-scoped key provider. Authenticated additional data binds the immutable object/ref/scope/run/generation/sink/original-region/key/expiry metadata. Swapping ciphertext between objects or tenants fails authentication. Nonces are generated by WebCrypto; payloads are bounded. A retired/revoked/unavailable key or expired record fails closed; key retention/deletion follows the object's approved lifecycle. Extending immutable authenticated metadata requires a newly sealed object, not silently editing history. Raw prompts, file contents, grants, credentials and ciphertext are absent from audit events.

Actual R2 storage, immutable manifest/hash verification, bounded archive extraction and checkpoint lifecycle remain #5568's integration. The service returns a sealed envelope or decrypted bytes only to the trusted broker after grant validation; it adds no public object endpoint or direct object redemption from a runner.

All fixtures use synthetic identities, keys and objects. These are LOCAL SECURITY CONTRACT tests, not a claim that a hosted sandbox or untrusted runner is safe. Five targeted mutations break replay, current sponsor revision, image provenance, emergency halt and tenant object ownership; the real service journeys must then fail.

### Rollout and rollback

1. Review D5565/D5567 and the local contract/refusal matrix. Preserve the off/unmounted state.
2. #5566 supplies the separate coding host and local/preview lifecycle; #5568/#5569 supply actual storage/publishing adapters. Add normal authenticated routes only when those stores and authorization revisions are real. Wire existing emergency halt and permission revocation before admission.
3. Publish/admit an image only after real SBOM/vulnerability/provenance/signature evidence. Until then, image eligibility is false; no fabricated passing scan or digest is permitted.
4. Hosted preview requires #4566 isolation preflight, explicit resource/time/storage/spend ceilings and cleanup authority, then #5573's real attack/recovery evidence. Production flags, secrets, bindings, vendor activation and autonomy require separate owner authorization.

Rollback denies new admission and revokes outstanding short-lived grants, stops/reconciles actual executions through the host, and preserves immutable refs and existing usage/audit history. No migration, binding, key provisioning, deployment or production content access occurs here. Exploitable findings in an existing system belong in a private advisory; this change publishes only synthetic tests of the new unmounted boundary.

### Operational control tickets

Status/cancel/cleanup have distinct audiences. A currently authorized, same-scope operator can receive a one-use control ticket with its own member/revision attribution even after new admission is off, the original sponsor is revoked or an image is withdrawn. That ticket cannot bootstrap work, read artifacts or publish. Normal execution/artifact grants keep the full live image/provider/sponsor gate. The trusted DO deadline cleanup remains available independently of a runner ticket, so disabling admission cannot strand a live machine. The main bridge must obtain the operator from normal authenticated server context, never a caller-supplied identity. Non-root and no-new-privilege execution and an immutable OCI image are independent required provider facts; a read-only root filesystem is not silently inferred from an image digest.
