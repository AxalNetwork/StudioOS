## D6029 — Build's navigation and module copy, to BD23 (#6029)

Part of #4846 (Build v2). Board BD23 (component frame BU23) in `design/incoming/Build v2 · Boards.dc.html` and `Build v2 Page.dc.html`. This part builds everything that does not wait on #5078; the issue stays open for the single Tools entry.

### What BD23 draws

- Before (the 8 November audit): the global sidebar, then cycle navigation, then Overview and Tools tabs, then six module tabs, then a module select. Tools reads as both a Build view and a part of Operating systems.
- After: the sidebar shows **Build › Overview · Plan · Progress · Tools**, then the six modules. The sidebar is the one module switcher, with no module tabs or select inside a page. Tools is one page, and Operating systems links to it.
- Each module's subtitle is a founder outcome, not a description of its records.
- Each module has one dominant action, for the empty state and for the in-progress state.

### The rule

- **The sidebar.** The founder sidebar's Build row carries `children`, which is `BUILD_SIDEBAR_CHILDREN` in `sidebarConfig.js`: Overview, Plan, Progress and Tools, then the label Modules, then the six modules.
  - `SidebarNav` draws them under the row while the row's page or one of its children is open. It does not draw them in the collapsed rail or while the sidebar is being searched.
  - A child's page lights the Build row. Overview (`/build` itself) is matched only exactly, so Grow's `/build/team` and Validate's `/build/marketplace` do not open Build.
  - `SidebarChildren` lights one child at a time. It tries, in order, the address with its hash (Tools, `/build/operating-systems#tools`), then the page itself, then the longest child path that contains a record's page.
- **The Build header.** `CycleHeader` draws no desktop tab row for Build. Below 1024px, where the sidebar is a sheet, the module picker stays. It lists Overview, Plan, Progress, Tools and the six modules, from `cycleTabs`.
  - Build's `lead` is `BUILD_DESTINATIONS` (Plan, Progress). `cycleTabs` now accepts a list of lead pages; Raise's Evidence is a single lead and is unchanged.
  - The Build overview's line no longer says "the tabs above move between modules".
  - The Plan page marks Progress as current on `/build/plan/progress`.
- **Module copy.** `BUILD_OUTCOMES` (`pages/cycles/buildNav.js`) holds BD23's six lines, word for word. `CycleModulePage` and the phone module bar show them in place of "Records below; the tabs above move between modules." and in place of the card's caption.
- **Dominant actions.** BD23's empty and in-progress actions were built by D5076 (#5076) and are unchanged here.
- **Addresses.** No address changed. Plan and Progress keep `?project_id=` through `cycleTabs`, and the phone tabs keep it through D4602's `BuildPhoneNav`.

### Departures from the canvas

- **Tools** still opens Operating systems' Tools section (`/build/operating-systems#tools`). Making it one page is #5078.
- **"Work board ↗"**, the external link BD23 draws under the Build block, is not drawn. No page in Build is that board.
- **The tab counts** BD23 draws on Plan and Progress (3, 7) are not drawn. The sidebar has no read that holds them.
- **Inside a phone module page** there are no Plan or Progress tabs, as the canvas draws it. They are one step away in the menu sheet's Build block, and the phone Build overview keeps its Overview · Plan · Progress tabs (D4602).
- **A collapsed or closed desktop sidebar** shows no Build children. The Build row still opens the overview, whose cards open every module.
