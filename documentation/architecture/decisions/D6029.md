### 2. The sidebar lists Build's pages

`frontend/src/lib/railPages.js` is the Eadwyn rail's page list, not the sidebar, so the issue's pre-filing check that the sidebar already listed the modules was wrong. The sidebar's Build row (`sidebarConfig.js`) was one flat row. As the issue allows ("if it does not, add them there in the same PR"), it now carries the pages:

- **`BUILD_SUBPAGES`:**
  - Overview `/build`, Plan `/build/plan` and Progress `/build/plan/progress`, each lit on its exact path only;
  - a "Modules" heading;
  - the six modules, each lit on its subtree too, in `MODULES.build` order.
- **The row's `match`** gains `/build/plan` and the six module paths, so the Build row lights on them. Grow's Build-prefixed addresses (`/build/team`, `/build/brand`) stay Grow's.
- **`SidebarNav`** draws a row's `children` as an indented list (`SubpageList`) under the row only when all of these hold:
  - the row is the current row;
  - the sidebar is expanded, not the icon rail;
  - no search is typed.
- **On the current page:** the matching sub-page carries `aria-current="page"`.
- **Old addresses keep working:** no route changed, and every sub-page is an address that already answers. The query and hash are untouched, because the sidebar links carry neither (as every sidebar row already behaves). The header's links and select keep the venture's `?project_id=` as before.

### 3. The Build header drops its desktop tabs only when the sidebar lists the pages

- **The context:** `lib/sidebarSubpages.js` holds `SidebarSubpagesContext`, the rows whose pages the sidebar lists right now.
- **Who provides it:** `SidebarSubpagesProvider` in `ui/SidebarNav.jsx` sets it from the sidebar groups, through `visibleSubpageRoots`. `App.jsx` renders the provider and imports it from `./ui/SidebarNav`, a module it already imports, because its import list is frozen (D5615). While the sidebar is closed, collapsed to icons, or not on desktop, it lists nothing.
- **How `CycleHeader` uses it:**
  - it reads `useSidebarListsSubpages('/build')`;
  - while the sidebar lists Build, the desktop module tabs are not drawn (`hidden`, not `lg:flex`), and the overview's subtitle drops "the tabs above move between modules";
  - in every other case the tabs stay as before.
- **What this keeps working:**
  - an admin, a partner or anyone else whose sidebar has no Build list keeps the tabs;
  - so does a founder who closed or collapsed the sidebar;
  - so does every test that renders without the provider.
- **Tablet and phone** keep the module select (`lg:hidden`), unchanged.
- **Plan and Progress:**
  - on desktop, they are one step away in the sidebar from every Build page;
  - on phone, D4602's `BuildPhoneNav` already draws Overview · Plan · Progress, and this PR does not rebuild it.
