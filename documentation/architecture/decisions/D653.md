## D653 — Private founder round calls behind counsel and rollout gates

Issue #1465. Migration **436** owns `round_calls`,
`round_call_recipients` and `round_call_questions`. This is a founder’s
round invitation, separate from GP `capital_calls`.

The Worker domain mounts at `/api/round-calls`. Operational requests refuse
unless `ROUND_CALLS_ENABLED` is exactly `true`; unset, base production,
explicit production and preview configurations stay off. Availability is an
authenticated metadata read so the Raise button can say **Coming soon**.
Owner/counsel approval of the general-solicitation question (#1008) is required
before production enablement.

Drafts use real Raise planner and owned cap-table scenario data; linked decks
are exact recorded versions with a server-computed content hash. Mutable slide bytes are checked at approval, send and response; changed content is unreadable and responses are refused. Materials are references, with no copied files.
Data-room paths appear only with an active grant and the granting founder’s
active pairwise NDA; the existing reader/download routes recheck those gates.

The founder must own the venture; a selected company is verified through
membership before scope is applied. Every investor read/response requires the
active investor role, approved KYC and recipient entitlement. Thesis matches
use recorded stage, sector, keyword fit, exclusions and overlapping cheque
range. Founder projections hide matched names, email and ids until a real
response; opening alone reveals nothing.

Send requires a server-held counsel reference bound to the current terms hash
and draft revision. An independent HQ Super Admin, with no founder or company affiliation to the venture, records actual external counsel
approval after fresh strong-factor authentication. No client boolean approves
terms. Draft/audience edits clear approval; optimistic revisions prevent stale
edits/approval/send claims. Seven evidence readiness items may be acknowledged
as missing; the counsel gate cannot be acknowledged away. Extending a sent call
also clears its prior terms approval and enters awaiting_counsel, pausing responses. Renewed approval resumes the call without another invitation. Expired sent calls may be extended through the same approval gate.

The state claim commits before notifications. Outcomes count actual in-app
notification ids and record non-delivery. No email delivery is inferred.
Commitments are indicative intentions in cents, not payments or issuance.
Responses, their questions, actor audit and idempotent contact/Raise round/
prospect updates execute in one D1 batch through `contacts.ts`. Existing signed/
wired pipeline amounts are preserved. Closed calls refuse edits and responses; expired calls refuse responses. Closed reads do not update opens. Response nonces condition every atomic side effect, including audit and source-update replies. Service methods recheck actor ownership and current investor verification. New foreign keys cascade recipients/questions and project deletion clears the call domain.

B1 from #1466 uses merged migration 437’s existing update asks/replies.
A capital ask stores the latest currently open venture call uid when enabled;
when disabled it stores no link. The update reader projects a link only for the
actual owning author or entitled verified investor, and never for its network
audience. Eligible replies (maximum 2,000 characters) atomically become source
update replies, native call questions and pipeline entries. Other update replies
stay on the source ask; the founder’s call page lists them with a source link.

The canvas is `design/incoming/Cycle Action.dc.html`, action=call:
Round, Materials, Audience, Preview, Send; readiness/nodataroom/nomatch/counsel;
private page and closed states. Phone sheets use the full width; desktop sheets
are 480px. The app shell retains navigation. One deliberate departure: the
investor reads the selected deck’s recorded text content here; slide visuals
remain in the editor, without its sample-template fallbacks or a public share URL.

Tests exercise pure policy, mounted requests over canonical SQLite, atomic
writes and rendered React views. Behavioral mutants import isolated modified
copies; the same assertions must fail on mutants and pass after restoration.
CI builds the root SPA before the complete drift suite. Validation results
were confirmed on merged head e03b82407: full drift and all GitHub workflows passed. A follow-up replaces the rendered-test helper’s dynamic label regex with literal HTML index walks, preserving the existing behavioral mutation/restoration checks (Semgrep alert 6273).

No remote migration, production write, deployment or feature enablement.
Migration 442/readiness tables belong to #1476 and are not dependencies.
