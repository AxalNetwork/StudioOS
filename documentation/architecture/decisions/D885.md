## D885 — The interview channels' secrets in HQ › Integration keys

- **Status:** decided by S1 for the owner, 2026-10-22 (#2561; part of #2500). Built by S09.
- **Basis:** `origin/main` at `79ce1f55ba`. Worker paths are relative to `cloudflare-worker/src/`.
- **Migration:** none.
- **Why:** the owner's request, "I don't see WhatsApp here https://axal.vc/admin/integration-keys". The channels' secrets could be set only with `wrangler secret put`.

### 1. The list: `GET /api/admin/integration-keys` carries `channels`

Three rows (`routes/admin_integration_keys.ts`, `CHANNEL_SPECS`):

| Key | What | Worker secrets | Generate | Var (a PR) |
| --- | --- | --- | --- | --- |
| `whatsapp` | WhatsApp, members' own numbers (way A) | `WHATSAPP_APP_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_EMBEDDED_SIGNUP_CONFIG_ID` | `WHATSAPP_VERIFY_TOKEN` | none |
| `whatsapp_axal` | WhatsApp through Axal's number (way B) | `WHATSAPP_AXAL_ACCESS_TOKEN`, `WHATSAPP_AXAL_PHONE_NUMBER_ID`, `WHATSAPP_AXAL_WABA_ID` | none | `WHATSAPP_AXAL_DISPLAY_NUMBER` |
| `telegram_channel` | The Telegram interview bot, labelled apart from the news bot (the managed `telegram` row) | `TELEGRAM_CHANNEL_BOT_TOKEN`, `TELEGRAM_CHANNEL_BOT_USERNAME`, `TELEGRAM_CHANNEL_WEBHOOK_SECRET` | `TELEGRAM_CHANNEL_WEBHOOK_SECRET` | none |

Each row gives:
- **`secrets`:** each name with `set` (a non-blank string in `env`) and whether it can be generated. Never a value, a length or a preview.
- **`vars`:** the public var's name and `set`, with `changed_by: 'pr'`.
- **`webhook_url`:** the address to register, from `PUBLIC_BASE_URL` (else `APP_URL`). It is NULL without an https base. Both WhatsApp rows share `/api/channels/whatsapp/webhook`; Telegram's is `/api/channels/telegram/webhook`.
- **`register_webhook_href`:** `/admin/telegram` for the interview bot, where Axal registers the webhook itself. NULL for WhatsApp, which the owner registers in Meta's dashboard.
- **`rollout`:** `WHATSAPP_CHANNEL` or `TELEGRAM_CHANNEL`, its value as the Worker reads it (`channelRollout`: `off`, `canary` or `on`), and `changed_by: 'pr'`. It is read-only here.
- **`guide_href`:** the runbook (`WHATSAPP.md`, `TELEGRAM.md`, added to `SETUP_GUIDES`).
- **`configured`:** the Worker's own check, never a second copy of it. For way A and Telegram it is `providerAvailable`; for way B it is `axalNumberReady`, which also needs the display number.
  - Setting way A's four secrets is therefore exactly what ends WhatsApp's `503 not_configured`.

### 2. The writes, Super Admin only, behind `requireSuperAdminWriteBar`

D223's bar applies: a TOTP session, a recent step-up, the holder, and never on a branch.

- **`PUT /api/admin/integration-keys/channels/:channel`** takes `{ <SECRET_NAME>: value, ... }`.
  - **Allowlist:** only that channel's own secret names. Any other name, another channel's or an unrelated Worker secret's (`CLOUDFLARE_API_TOKEN`, `SLACK_CLIENT_SECRET`), refuses the whole request with `400 unknown_secret_name`, before anything is written. So this route cannot overwrite an unrelated secret.
  - **Values:** trimmed and non-empty, at most 4096 characters, with no line break. `TELEGRAM_CHANNEL_WEBHOOK_SECRET` must match `TELEGRAM_SECRET_RE`, the Worker's own check.
  - **Writing:** the secrets are written through the existing Cloudflare push (`setSecret`), one at a time.
  - **A refusal part-way** answers which were set and which failed (`set`, `failed_at`). Nothing is rolled back, because deleting a secret this request had just replaced would remove a value that may have worked before.
- **`POST .../channels/:channel/rotate`** takes `{ name, value }`, or `{ name, generate: true }` for the two tokens Axal can choose.
  - A generated value is 32 random bytes in base64url (43 characters). That is Telegram's secret alphabet, and Meta accepts any string as a verify token.
  - It is returned once, to the caller, in `generated_value`, to copy into Meta's or Telegram's dashboard. It is in no audit row and no later read.
- **`DELETE .../channels/:channel`** deletes every one of that channel's secrets.
  - Each delete is idempotent, so a retry finishes a partial removal.
  - The PR-set var is kept, and the answer says so (`vars_kept`).
- **Audit:** every write is audited once (`logAdminAction`: `channel_key_set`, `channel_key_rotate`, `channel_key_delete`). The row holds the channel, the secret names, the outcome, Cloudflare's status and, for a rotate, whether the value was generated. It never holds a value.
- **The webhook registration for Telegram** stays on `/admin/telegram`; the card links to it.

### 3. The console

`frontend/src/pages/admin/consoles/ChannelKeysSection.jsx` adds a "Channels" group under the existing cards, in the same look:
- each secret's Set or Not set, and the var's state with "set in wrangler.toml by a PR";
- the webhook URL with Copy;
- the rollout line;
- the runbook link, which is shown only when it is a repository document.

For the holder only, it adds:
- **Set secrets:** one password field per secret name; an empty field is not sent.
- **Rotate,** on a set secret.
- **Generate,** with the token shown once with Copy.
- **Remove.**

The client is `frontend/src/lib/api/channelKeys.js` (D527). The words are in `frontend/src/lib/channelKeys.js`.

### Tests

- **`cloudflare-worker/test/integration_keys_channels_d885.test.ts`** (new, 9 tests), through the real router on the D227 fixture, with every Cloudflare call recorded:

  - **A save:** only the typed names are written, trimmed; one audit row, with names only.
  - **Refusals:** 13, none reaching Cloudflare or the audit:
    - another channel's name;
    - an unrelated secret's name;
    - the var;
    - an empty body, a blank value, a line break, an over-long value;
    - Telegram's alphabet;
    - an unknown channel;
    - rotating `CLOUDFLARE_API_TOKEN`;
    - generating a secret that is not generated;
    - deleting an unknown channel.
  - **The write bar:** a plain admin, a branch and the holder without a fresh step-up are refused all three writes; a plain admin is refused the list, which needs no step-up.
  - **Generate:** the format; written once; in no audit row and no later read; a new token each time; a pasted value never echoed.
  - **A Cloudflare refusal part-way, and a missing Cloudflare token:** reported with `set` and `failed_at`, or a 503.
  - **Remove:** only that channel's secrets, the var kept, a partial failure reported.
  - **Names:** every secret name is one the Worker checks, and no two channels share one.
- **Mutation check:** 24 mutations of the route, the words and the section, all caught. Two survived the first pass (the write bar swapped for `requireSuperAdmin` on a save and on a remove), and the stale step-up case now catches them.
