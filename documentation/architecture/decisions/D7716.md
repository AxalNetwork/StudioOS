## D7716 — Market observations say what they count, and one query and one export carry the same provenance (#7716)

**Decision date:** 2026-11-22. **Scope:** one additive migration, the shared writer's optional fields, a new service and
router, the market-data CSV handler and a client module. No screen (#7718), importer (#7717) or schedule.

### What an observation says

Migration `202611220337_7716_market_observation_fields.sql` adds nullable columns to `research_market_observations`:
`statistical_unit`, `scale`, `currency`, `price_basis`, `industry_scheme`, `industry_code`, `size_band`, `series_id`,
`supporting_passage`, `applicability_note` and `limitations`. They carry no CHECK, because SQLite cannot widen a CHECK
without rebuilding the table. The allowed values are exported lists in `services/researchObservations.ts`, and
`services/marketObservations/write.ts` refuses a batch with a value outside them (`provider_payload`, nothing written):

| Field | Allowed |
| --- | --- |
| `statistical_unit` | `STATISTICAL_UNITS`: enterprise, establishment, legal_unit, household, consumer_unit, person |
| `industry_scheme` | `INDUSTRY_SCHEMES`: isic_rev4, nace_rev2, naics_2022 |
| `scale` | units, thousands, millions, billions, trillions. The value is stored as published, never rescaled. |
| `price_basis` | current_prices, constant_prices, ppp_current, ppp_constant, not_applicable |
| `size_band` | micro (fewer than 10 persons employed), small (10–49), medium (50–249), large (250 or more), sme (fewer than 250), all_sizes, following the EU SME definition |
| `currency` | three capital letters (an ISO 4217 code) |
| `industry_code` | letters, digits, dots and hyphens, up to 16; only together with a scheme |
| `series_id`, `supporting_passage`, `applicability_note`, `limitations` | text up to 120, 500, 500 and 1,000 characters |

`STATISTICAL_UNITS` and `INDUSTRY_SCHEMES` were exported first by #7719 (`routes/research_studies.ts`, D7719). D7719
said whichever of the two issues merged second imports the first's constant. This one imports them, so there is one
list. #7865 (native company classifications) was still open when this was written.

There is no new identifier: a row's `id` is one vintage, and a revision is a new row naming its predecessor in
`supersedes_observation_id`. `geography_type` is unchanged. A published aggregate is a `region` row whose code is one of
`REGION_CODES`: `WLD`, `EU27_2020`, `OECD`. New indexes cover metric with period, industry code, and
`supersedes_observation_id`. Geography with metric and period was already indexed by migration 767.

### Which sources may be exported

`research_market_sources.export_allowed` is nullable, and unset reads as not exportable. It is set for `world-bank`
only. World Bank Open Data is published under the World Bank's Terms of Use for Datasets, which license it under
Creative Commons Attribution 4.0 (https://www.worldbank.org/en/about/legal/terms-of-use-for-datasets): reuse and
redistribution are allowed with attribution. Its rows were already exported with attribution (D7318). The other
registered sources (IMF WEO, WIPO GII, OECD, Eurostat, UNCTAD) stay unset until their terms are confirmed for this
delivery channel.

### The metric catalogue

`research_market_metrics` (metric key, source, label, one-sentence definition, unit; key `(source_id, metric_key)`) is
seeded for the ten World Bank metrics on main (`WORLD_BANK_METRICS`). A later importer adds its own rows in its own
migration.

### The query

`routes/research_observations.ts` mounts itself at `/api/research`, and every handler calls `requireAuth`:

- `GET /observations` filters in SQL by metric, geography, industry code, size band, period range and status. Its
  `total` comes from the same WHERE. The WHERE is assembled only from the fixed fragments in `FRAGMENTS`, with every
  value bound; the interpolated constants are recorded in `scripts/baselines/sql-prepare/`. Current rows (those no
  later row supersedes) are the default, and `vintages=all` returns every vintage. Each item says whether it is
  exportable and how many days old it is.
- `GET /observations/:id` returns the observation and its source and usage note. Its three dates are labelled: Period
  measured, Published (null when the provider gives none) and Retrieved. Its revision chain runs oldest first, with
  each link marked older, this or newer.
- `GET /observations/metrics` returns the catalogue.
- `GET /observations/export.csv` returns the rows the list returns for the same filters, up to `EXPORT_ROW_CAP`
  (5,000).

**Geography.** `research_countries` holds two-letter codes and the store holds three-letter ones. `ISO2_TO_ISO3` maps
them, and a test asserts that every seeded code is mapped. A request may use either form. An unknown code is refused
with `unknown_geography`, not answered as empty. The table holds ISO 3166-1 countries and `XK`; a three-letter code
outside it and outside `REGION_CODES` is refused too.

**Period.** A period is one of three forms: `YYYY`, `YYYY-Qn` or `YYYY-MM`. A range compares within one form only
(`o.period GLOB` that form), and mixing forms is refused with `mixed_period_forms`.

**States.** When a metric and a geography are both asked for, `coverage.state` is one of five values, each distinct:

- `not_covered`: no enabled source lists the metric in the catalogue.
- `no_observation`: the metric is covered but there is no current row.
- `source_failing`: the newest row's source recorded an error on its last attempt. The last valid row is returned
  with its age.
- `stale`: the source last succeeded longer ago than its refresh policy allows.
- `current`: none of the above.

The Worker's clock measures age. The allowance per policy is `REFRESH_ALLOWANCE_DAYS`: monthly 45 days, quarterly
120, april_october 214, annual 400. An unknown policy, or a source that never succeeded, reads as stale, never fresh.

### One export

Both `GET /api/research/observations/export.csv` and `GET /api/research/market-data/export.csv` call
`exportObservations` and `observationsCsv`. That handler is the only change to `routes/research_market_data.ts`. The
market-data export keeps its `country` filter and every vintage, as it exported before.

- **Header.** The 19 provenance columns of the export on main, in their order, then the eleven D7716 fields.
- **Cells.** Every cell goes through `csvSafe`, so a cell a spreadsheet would run as a formula is written as text.
  Lines end in CRLF (`services/csv.ts`).
- **Sources not exportable.** Their rows are left out and counted by source in `X-Export-Omitted`. `X-Export-Rows`
  gives the rows written.
- **Cap.** Past `EXPORT_ROW_CAP` the export is refused with 413 `export_too_large` and a sentence, never a short file.

### Not done here

Importers for the new fields (#7717), the screens (#7718), and terms for sources other than the World Bank.

### Rollback

Revert the PR. The added columns, indexes and table stay and are unused. The market-data export returns to its earlier
format, which had all values quoted, LF line ends and no new columns.
