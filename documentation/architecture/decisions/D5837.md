### 1. A ledger fact is a choice, never a collection

Every other evidence kind is collected from a module's rows and proposed to the
founder. A ledger fact is not. It exists only once the founder has chosen all of
these:

- the revision (`snapshot_uid`);
- the line (`source_key`);
- the amount, date, currency and basis the revision states;
- the claim (`claim_id`).

That choice is a row in `raise_ledger_selections`. The hourly builder never proposes
one (`buildCandidates` skips the kind).

The choice is checked against the revision, not taken from the request:

| Check | Refusal |
|---|---|
| The revision is on this venture, and the claim is too | `not_found` (404) |
| A later revision exists (a stale revision) | `superseded` (409) |
| The founder's own active connection imported it | `source_unavailable` (409) |
| The line is the statement's own cash, income or net-income total (D5833 `SUPPORT`) and holds an amount | `unsupported_line` (400) |
| The amount (exact, parsed at the revision's precision), currency, basis and date (the returned period's as-of or end) are the revision's | `mismatch` (409) |
| The amount fits the currency's minor units exactly | `unsupported_amount` (400) |

Nothing is corrected for the founder.

### 2. What the pin writes, in one batch

1. **The selection,** with its own copy of the fact: revision, line label, exact
   amount and minor units, currency, basis, period and date.
2. **A `raise_evidence_items` row** of kind `ledger-fact`:
   - source `connector`, provider `quickbooks` or `xero`, strength measured;
   - the value in the currency's minor units (`cents`);
   - **pinned and Private.** The values are rebuilt by code from the revision.
3. **Its fingerprint,** built by the same adapter code that reads the selection back
   (`ledgerCandidate`), so a later read agrees with the pin.
4. **The founder's link to the claim** (`how = 'founder'`), with the claim reset to be
   checked again.
5. **A D5833 pin** on the revision.
6. **Provenance** (`fill_provenance`, task `raise:ledger-evidence`) and an activity row.

A NOT NULL provenance row is the batch's guard: if any gated write wrote nothing,
the whole choice rolls back.

The item's area follows the claim's surface:

| Claim surface | Area |
|---|---|
| Narrative, deck | Investor narrative and Pitch deck |
| Use of funds | Use of funds |
| Capital model | Capital model |
| Readiness, cap table | Fundraising readiness |

### 3. Member authority, at every read

**Who may choose.** Only the venture's founder, by D1263's evidence gate
(`raiseEvidenceContext`), and only through their own active connection to the
provider that imported the revision.

**Who reads the routes.** Every route is the founder's. A co-founder member, an
admin, an advisor, an investor and a stranger are refused: an unknown or foreign
venture is `404 not_found`, and an admin is `403 forbidden`.

**The source query checks again on every read.** The adapter's `ledger` query admits
a selection only while all of these hold:

- it is current;
- its revision and line still exist with the same minor units;
- the revision's connection is active and belongs to the founder who chose it;
- that founder is an active user who still owns the venture.

That query is what every shared read uses (`currentShared`, bound to the founder who
accepted the item, never the reader). So a revoked connection or a deleted revision
leaves every shared view at once.

**A generic `project_metrics.source` string is not provenance.** A KPI row whose
source says `quickbooks` or `connector:xero` stays Typed with no provider, and makes
no ledger fact. Only `raise_ledger_selections`, joined to the revision and its
connection, makes one.

### 4. Sharing: the existing rules, one line and its context

Sharing beyond Private is the existing evidence sharing (`setSharing`), with the
existing rules. The investor view, the staff view, the deal summary, the data-room
evidence read and a pack link or PDF all read `sharedView`. For a ledger item it adds
`ledger`:

- the figure, the line's label, the report, basis, currency and period;
- the revision number and the provider;
- the exact amount, only when shared After NDA. A Summary share gives the context
  without the figure.

Never another line, the report, the snapshot uid, the source key or the connection.
A ledger item with no current selection is not shown.

**Kept out of the pilot:**

- the scoring pack (`evidencePack`);
- Eadwyn's pack draft (`packFacts`);
- the investor's AI deal-summary draft (`dealSummarySources`).

None of them reads a ledger fact, so no model scores, drafts from or trains on one,
and nothing sends one to an investor automatically.

An admin's evidence read and the narrative claims an admin reads list no ledger item
at all, as they list no bank or quote item. The item cannot carry `private_reason`:
its CHECK allows only `bank` and `quote`, and widening it needs a table rebuild. So
the kind is excluded by name.

### 5. Corrections, withdrawal, unlink, revoked access and deletion

**A correction.** D5833 appends a revision that supersedes the pinned one. The
adapter row then carries `superseded_by`, so the item's fingerprint changes:

- the founder's evidence read says `changed`;
- the ledger read says `corrected` and names the new revision and that line's new
  amount;
- every shared view drops the item;
- `setSharing` with `confirm_current` is refused for a ledger item, so a superseded
  figure is never re-shared in place;
- a new claim link is refused (`changed`).

**Re-review** (`POST /selections/:uid/review`). The founder confirms the figure again
on the latest revision of the same statement: same provider, entity, report and
window, same figure. It writes:

- a new selection (`replaces_id`) and a new Private item;
- the old selection becomes `replaced`;
- the old item is unpinned and Private, with its claim links moved to the new item;
- each affected claim is reset to be checked again.

The founder shares the new item again explicitly. Re-review of an uncorrected figure
is `not_changed`.

**Withdrawal** (`POST /selections/:uid/withdraw`). The selection becomes `withdrawn`.
The item is unpinned and Private, its claim links are removed and those claims are
reset. It cannot be re-pinned: the source no longer offers it.

**Unlink.** The existing claim unlink works unchanged.

**Revoked access.** The connection is no longer active. Shared views drop the item,
and nothing new can be chosen through it. The founder reads `access_revoked`, and the
item keeps its value for the founder. A restored grant restores the same, unchanged
fact.

**Deletion, under the existing retention policy:**

- A venture's hard delete cascades the selections, as it does the snapshots and items
  (D8530 inventory: `raise_ledger_selections`, `cascade`).
- A deleted revision sets `snapshot_id` to NULL. The selection keeps its copy of the
  fact, so the founder still reads the pinned value, with source `deleted`.
- The fact columns cannot be updated (trigger `trg_raise_ledger_selection_fact_fixed`).

### 6. How a second source type plugs in (Search Console, #5842)

The write paths here are general. Only the fact check and the source query are
ledger-specific. A second founder-chosen source, such as a Search Console aggregate,
plugs in like this:

1. **An evidence rule and a dataset** in `raiseEvidenceSources.ts`. The rule takes one
   area per row (`Material.areas`). The dataset's query admits a row only while the
   choice is current and its source still stands through the chooser's own
   connection. Add it to the owner-bound set (`BANK_DATASETS`) if it reads a member's
   connection. Add a `ledgerMaterial`-style fixed projection of the row, so the pin
   and the read fingerprint alike. Add an exported candidate builder
   (`ledgerCandidate` calls the shared `ruleCandidates`).
2. **Its own selections table and service:** the confirmed-fact check (the aggregate,
   window, revision, units and coverage) and the claim. The rest stays the same:
   - the batch (`writes`, `closeItem`): selection, Private pinned item, provenance
     guard, claim link and activity;
   - re-review (new selection, new Private item, old one closed, links moved);
   - withdrawal.

   These can be lifted into a shared helper when the second source lands. They are
   kept in this file until then, so #5842's preview/recheck work does not have to
   edit them.
3. **Context and exclusions for the shared reads.** In `raiseEvidence.ts`, add its
   kind to:
   - the excluded-kind checks: `buildCandidates`, the `confirm_current` refusal,
     `evidencePack`, and the admin and narrative reads;
   - its own context map beside `ledgerContexts`, which `sharedView` attaches by kind.

   Model readers filter the kind as they filter `ledger-fact`.

### 7. Not in this change

- **The screens.** Picking the line and the claim in Raise › Use of Funds or
  Evidence, and showing `ledger` in the investor view, wait on a canvas: #5836's Raise
  ledger is `needs-design`. The API answers everything such a screen needs: options,
  selections with their source state and the correction, pin, review and withdraw.
- **Automatic backing.** A pinned ledger figure does not decide a figure claim's state
  automatically (`MEASURES`). A P&L total is reported for its own period, not the
  claim's. The founder's link records which claim it backs, and the claim is checked
  again on their next read.
- **Live data.** The provider choice and a live pilot (#5832, #5834 or #5835, #5838).

Rollback: revert the Worker. The table is additive and an older Worker never reads it.
