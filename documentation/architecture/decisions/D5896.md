## D5896 — HQ's Axal VC package catalogue, read only, with version history (L29) (#5896)

- **Status:** built 2026-11-15 by S05. Part 1 (a) of #5026.
- **Canvas:** board L29 of `design/incoming/Licences and Contracts v2 Addendum Page.dc.html` ("Axal VC packages").
- **No migration, no Worker change.** The reads are D5022's (`routes/admin_licence_packages.ts`, Super Admin on HQ only).

### 1. Where it lives

- **Address:** `/admin/licences/packages`, a route module (`routes/adminLicencePackages.jsx`) under `guard(['admin'])` and `hqOnly`, like the other Licences routes. `packages` is a literal segment, so React Router ranks it above `/admin/licences/:uid`; the test matches both addresses against every declared route.
- **Door:** the Licences strip's third item, "Axal VC packages" (`App.jsx` and `lib/hqStrips.js`, which the strip's highlight reads). The rail treats the address as an alias of Licences (`lib/railPages.js`).
- **Client:** `lib/api/licencePackages.js`, reads only: `catalogue()` (`?all=1`), `versions(key)`, `version(key, n)`.

### 2. What the table lists

The catalogue read with `?all=1` returns every version of every key. The table lists, per key:
- the **Active** version;
- any **Draft** above it (L29's "Venture Building v2 Draft" row);
- for a key with neither, its **newest** version, so a retired package does not disappear.

Rows are ordered Active, Draft, Retired, then by name and version.

**Status is the store's own word.** The seed's v1 versions are `draft` on main, so they read Draft, not Active. L29's footnote says its sample shows them after Publish.

**Programs** is the count of the version's items, read per row from `GET /:key/versions/:version`. A failed detail makes only that row's Programs cell Unreadable.

**Money** is in the version's own currency through `lib/money.js`. A null or unformattable figure reads Not recorded, never 0. The guidance range needs both ends.

**Effective:** an active or retired version reads its own dates (`effective_from`, and `effective_to` when set). A draft reads "Not in force" whatever date it carries.

**Program names.** An item carries only its `program_key`, and no frontend client reads the program registry's names, so programs are listed by key. Adding a name read is not this task.

### 3. Standalone sum and Bundle saving

The catalogue read does not return them. They are computed per licence, at its market (`services/packagePricing.ts`, `/api/admin/licences/:uid/package-pricing`).

**The columns stay, and each cell reads Not recorded**, with one line under the table: "Priced per licence, at its market: the catalogue does not hold it." This is the issue's first option. L29 draws the columns, and leaving them out would hide that the figure exists elsewhere. Nothing in the browser sums program prices.

### 4. Version history

The history card shows the chosen package: the first row's, or the one whose name was clicked. It reads `GET /:key/versions` and lists every version newest first, whatever order the read sent. Each version's programs come from its own detail read.

The columns are Version, Status, Programs, Effective and Created. L29's "By" is left out: `created_by` is `user:<id>`, not a name.

### 5. States

- **Catalogue:**
  - a failed read is Unreadable with Try again, and never an empty catalogue;
  - an empty read is None: "No Axal VC package exists yet".
- **History:** a failed read is its own Unreadable, and the table stays.
