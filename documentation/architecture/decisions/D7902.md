## D7902 — Reconcile expired queued Mac children (#7902)

The legacy workflow-level busy check may find a child whose pickup lease expired
and whose parent has already moved on. One such child must not permanently make
every later invocation report a busy Mac.

Before cancellation, independently read the exact workflow run and bind its
repository, workflow, dispatch event, main ref, attempt, fixed shard and parsed
parent/source tuple. Read the parent and bind its own repository, CI path,
attempt, source and permitted event/ref. Require an expired, valid creation time
and complete job metadata showing no assigned runner, started job or test step.
Recheck the run's immutable identity and queued state immediately before posting
the cancellation to that exact ID. Running, assigned, malformed, foreign or
unreadable work is never cancellation authority.

Reconcile at most one expired child in each busy check, then take the hosted path
with a distinct cleanup reason. A cancellation request is not a terminal receipt;
pending/refused cancellation stays explicit. Do not immediately dispatch another
Mac job into uncertain cleanup, follow response URLs, or turn an old result into
a new run's success. Existing owned-child failure/cancellation behavior remains.

The API boundary exposes only fixed operation categories, integer HTTP statuses,
and timeout/unavailable categories. It never reads an error response body into
public diagnostics or emits arbitrary exception messages, credentials or URLs.
Diagnostics are bounded and only attached after actual errors, preserving the
historical successful result shape.

Self-hosted execution remains blocked by #7905's verified isolation requirement.
The legacy lane must be paused before operational orphan cleanup can unblock
another unisolated dispatch. Repository-variable access was denied here; a
separate Actions workflow pause was verified (`disabled_manually`) before requesting
cancellation of the exact independently verified orphan. A successful cancellation
POST is not claimed as terminal confirmation. Owner confirmation of the
runner-group/label/workflow restriction and a secure live exercise remain outside
the deterministic code tests. No host/group permission or provider change is
made by this decision. Actual operational evidence and validation are in STATUS;
no synthetic fixture is a live runner proof.
