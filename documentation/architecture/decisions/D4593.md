## D4593 — An exhausted agent message is acknowledged only after its run and task are repaired (#4593)

- **Status:** built by S27, 2026-11-07 (#4593, audit R2-06, follow-up to D1528 and #3851).
- **Number:** D4593 is this issue's number. Migration: none.
- **Invariant (from the issue):** every acknowledged exhausted agent message has either a verified terminal lifecycle with consistent task state, or an independently durable, idempotent repair obligation with a named retry owner. A mirror row alone is neither.
- **Not authorized and not done:** production replay, enqueue, schema change, deployment, provider enablement, agent-autonomy change. Hosted fault injection: NOT RUN (needs #4566 isolation and owner approval).

### The defect
`agentDlqConsumer` caught a failure of the run update or the task reopen, logged it, and then handed the whole batch to the generic mirror. The mirror acknowledges after its own insert, so a failed repair was acknowledged. The audit's injected reproduction left the run `admitted` with the message mirrored and acknowledged. The same shape, run `failed` but task still `in_progress`, was reached by a failure between the two statements, and nothing reopened such a task: the ready scan only looks at `open` tasks.

### State and acknowledgement table
`repairExhaustedRun` reads D1 and decides; every row is idempotent.

| run | task | does | result |
|---|---|---|---|
| gone | — | nothing to repair | settled |
| `admitted` | any | run → `failed` `queue_exhausted`, read back, then the rows below | — |
| `failed` `queue_exhausted` | a newer attempt or a live run exists | nothing: the newer lifecycle is not ours | settled |
| `failed` `queue_exhausted` | `in_progress` | task → `open`, only from `in_progress` | repaired |
| `failed` `queue_exhausted` | `open`, `done`, `blocked`, gone | nothing: reopened, completed or cancelled already | settled |
| any other status or refusal | any | nothing: it moved on without us | settled |
| database error, timeout, unknown commit outcome | | read back; still undone → throws | retry |

An unknown commit outcome is never assumed either way: after a failed statement the repair re-reads the run or the task, and a redelivery reaches the same end.

### Acknowledgement, per message
- A message whose repair is `repaired` or `settled`, or that is not an agent run at all, is mirrored and acknowledged.
- A message whose repair failed is `retry`d (30 s) and not mirrored, so one message's successful mirror can no longer acknowledge another's failed repair. The mirror receives only the settled messages.
- The DLQ consumer retries 3 times and then the platform drops the message. The third delivery (`DLQ_FINAL_ATTEMPT`) is therefore mirrored and acknowledged with its repair still owed, and the owner is the sweep, which finds the obligation from D1 and not from the queue:
  - a run still `admitted`: the existing five-minute resend step sends it again (unchanged);
  - a run `failed` `queue_exhausted` whose task is `in_progress`: the new `sweepStrandedRuns` reopens the task (at most 20 a sweep, the same five-minute cadence, before the halt and engine checks, because it changes state only).
- Neither path admits, starts, refunds or charges anything; there is no new table, ledger or queue.

### Telemetry (#3851 / #4559)
`system_metrics`, labels carry an outcome code only: `agent_dlq_repair_outcome` (`repaired`, `settled`, `not_a_run`, `retry`, `deferred_to_sweep`), `agent_repair_pending`, `agent_repair_repaired`, `agent_repair_ambiguous`, `agent_repair_oldest_age_seconds`. No run, task, tenant, prompt or figure.

### Tests
`cloudflare-worker/test/agent_dlq_repair_d4593.test.ts` (6 tests, real handler, real migrated schema): lifecycle failure then successful mirror is retried and not mirrored; failure between the run and the task update; repeat delivery; unknown commit outcome both ways; per-message acknowledgement; newer attempt, cancelled/completed task, other refusal, deleted run; last delivery and the sweep; metrics. Nine mutations, including restoring the premature acknowledgement, are caught.

### Rollback
Revert the commit. No data changed shape; runs the sweep repaired stay repaired.
