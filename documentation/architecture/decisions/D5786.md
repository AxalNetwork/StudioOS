## D5786 — Platform readings scoped to one subsidiary, for the HQ scope switcher (#5786)

The read that #5757's scope switcher waits on (U1, split from #4860). D4860 part 5 kept the switcher out because every Platform reading was HQ-wide, and a switcher over those reads would only relabel them. This adds a reading scoped to one subsidiary. It does not touch the HQ-wide reads, and it builds no switcher.

### The contract

Both routes are on the existing Platform router (`routes/admin_platform.ts`), and the service is `services/platformScope.ts`.

| Route | Gate | Answers |
|---|---|---|
| `GET /api/admin/platform/scopes` | `requireSuperAdmin`, `private, no-store` | every subsidiary HQ can scope to: `{ registry_available, registry_reason?, scopes: [{ kind: 'subsidiary', code, licence_uid, registry_status, bound }] }` |
| `GET /api/admin/platform/scopes/:code` | `requireSuperAdmin`, `private, no-store` | that subsidiary's reading: `{ scope, observed_at, state, detected, unknown, signals: { live_health, stored_check, traffic }, unavailable, hq_only }` |

- **HQ-wide stays where it was.** The switcher's "HQ-wide" position reads `/summary`, `/admin/deployments` and `/monitoring/analytics/traffic-by-branch` unchanged. A scoped reading has its own route, so no existing caller gets a new shape.
- **Scope identity.** A subsidiary is a branch, and its key is its code. That code is `licence_deployments.code`, the branch's `BRANCH_CODE`, its `BRANCH_<CODE>` binding and Analytics Engine's `blob6`. `licence_uid` is its licence (D150). Nothing else is taken as a scope.
- **Access.** Super Admin only, like the three HQ-wide reads beside it. One branch's health and traffic belong to that branch, and only the Super Admin supervises every branch (D161). On a branch, `requireSuperAdmin` answers "HQ only".
- **Refusals.** Each is refused before anything is read:

  | Request | Status | Body `code` |
  |---|---|---|
  | No session | 401 | — |
  | A plain Admin | 403 | — |
  | `hq`, or a code that fails `BRANCH_CODE_RE` | 400 | `invalid_scope` |
  | A valid code that is neither in the registry nor bound | 404 | `unknown_scope` |
- **Each signal block** carries `availability` (`ready`, `unavailable` or `not_deployed`), `observed_at`, `source`, and a `reason` whenever it is not ready.

### The inventory: each overview signal, for a subsidiary

| Overview signal (#5757 consumes it) | HQ-wide source | For a subsidiary | Key |
|---|---|---|---|
| Branches: live health | `/admin/deployments`, fanning out to every branch | **Attributable**: `live_health` is a one-branch `health` read (`branchRead`, D153) | the branch's binding |
| Branches: last stored check | `/summary` `branch_health` | **Attributable**: `stored_check` | `licence_deployments.code` |
| Telemetry: traffic | `/monitoring/analytics/traffic-by-branch` | **Attributable**: `traffic` is the branch's own row of the same split | AE `blob6` |
| Telemetry probe | `/summary` `telemetry` | **HQ-only**: one reading of whether Analytics Engine answers at all | — |
| Scheduled jobs, repeated failures | `/summary` `jobs`, `cron_streaks` | **Unavailable**: a branch fires its own triggers into its own `cron_run_history`, and no branch read returns that to HQ | — |
| Dead letters | `/summary` `monitoring.dlq` | **Unavailable**: a branch drains its own queue into its own tables, and no branch read returns that to HQ | — |
| Stripe webhook, Integrations, Broadcast, HQ overrides, Integration keys, Payments catalogue, Promo codes, GitHub sync, Meeting bot starts, Published incidents | `/summary` | **HQ-only**: these read HQ's own deployment and stores | — |

The route owners were coordinated through the code: Platform's own reads, Deployments' fan-out (`services/branches.ts`) and Monitoring's traffic split (`services/analyticsReports.ts`). Each of those is called as it is, with no new query.

### Rules, as built

- **An HQ-wide reading never stands in.** Only the three attributable signals judge a subsidiary. The unavailable and HQ-only signals are named in `unavailable` and `hq_only`, with their reasons, and are not read at all. A test holds the service to calling none of the summary's readers.
- **The state** comes from `healthStateOf`, the summary's rule (D4854): critical > degraded > unknown > healthy.
  - The branch rules are D5370's:
    - a live answer whose database fails is medium;
    - a stored check that said not ok is medium;
    - one incident per branch;
    - a stored check older than `BRANCH_CHECK_STALE_HOURS` is a low note that does not lower the state.
  - Traffic is read only for whether it is available. No threshold judges it, because none was ever set.
- **Unknown, never Healthy.** Any attributable signal that did not answer is an `unknown` entry with its reason, so a scope without a usable reading cannot read healthy. A branch that is not live in the registry is unknown with its registry status, not healthy.
- **Traffic gives four different answers:**
  - **its own row:** the branch's figures;
  - **Analytics Engine answered with no row for this branch:** a true zero;
  - **the read failed:** unavailable, with a null count;
  - **the branch is missing from a full 50-row page:** unavailable, because its count is not known.
- **No infrastructure identifiers.** The read selects `licence_uid`, `code`, `status` and the stored check, and nothing else. A test holds the body free of worker, database and host names.

### Backend required for the remainder

#5757 cannot scope two signals without a new branch read: scheduled jobs and dead letters. Each would need a branch RPC method returning that branch's own `cron_run_history` grades and dead-letter count, and a branch redeploy to expose it. That is not built here. Until it is, #5757 shows both as unavailable for a subsidiary, with the reason this read gives.

### Tests

- `cloudflare-worker/test/platform_scope_5786.test.ts` has 14 tests, on synthetic fixtures only:
  - **HQ-wide:** `/summary` keeps its keys and carries no scope.
  - **Two subsidiaries** (`fr` healthy, `de` with a failing database): each is read from its own binding, registry row and traffic row, and neither borrows HQ's figures.
  - **A missing observation** (`es`: registered, unbound, never checked, traffic unread): Unknown, with every reason given.
  - **Traffic's four answers.**
  - **Refused scopes:** 401, 403, 400 and 404, and nothing is read for a refused scope.
  - **The signal groups:** the unavailable and HQ-only groups do not overlap the scoped signals.
  - **The mounted routes:** with no Analytics Engine credentials in the harness, traffic reads unavailable, never zero.
- **Mutation-checked.** Seven mutants, all killed:
  - borrowing another branch's traffic row;
  - a full page read as zero;
  - a failed traffic read as zero;
  - traffic's unknown dropped;
  - the state always healthy;
  - the code allow-list removed;
  - `/scopes` ungated.
