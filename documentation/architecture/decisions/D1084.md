## D1084 — Lovable part 5: "Built in Lovable? Sync it to GitHub", and a founder-set "Synced with Lovable" mark on a repository (#2949)

- **Status:** S11, 2026-10-26 (#2949, part 5 of #2398, the GitHub path (a)). Moved from S08 on the owner's instruction after S1 released it to `state:ready`.
- **Basis:** `origin/main` at `937a62c`.

### 1. The idea

A Lovable project synced to GitHub is an ordinary repository: the founder picks it in the GitHub connector, and D782's feeds run unchanged. This part says so where the founder looks, and lets the founder mark a picked repository "Synced with Lovable". Only the founder sets the mark; no sync ever guesses it.

### 2. The mark (`integrations/providers/github/lovableMark.ts`)

- **Where it lives:** the GitHub connection's `config_json`, as `synced_with: { "<owner/repo>": "lovable" }`.
- **How it is set:** through the existing `PATCH /api/connectors/:uid/config`, with `{ synced_with: { "<owner/repo>": "lovable" | null } }`. `null` clears.
- **Who sets it:** only the connection's owner. `loadRow` matches the owner's `user_id`, so another member reaches no connection and gets 404.
- **The check:** GitHub's `validateConfig` runs `checkSyncedWith`:
  - a repository not picked is refused as `repository_not_chosen`;
  - a value other than `lovable` or `null`, a non-object, or an empty patch is refused as `invalid_synced_with`;
  - the route answers 400 `invalid_config`, and nothing is saved.
- **The stored map:** the result is the whole map, so the route's shallow merge replaces it.
- **A repository no longer picked** carries no mark (`syncedWithOf`).
- **No sync sets or clears it.** `syncGithub` never writes `config_json`, and the test runs a sync with and without the mark and compares `config_json` byte for byte.
- **The read:** `GET /:uid/repositories` adds `synced_with` only when at least one mark is set. Absent means none. D655's and D782's exact-shape suites therefore pass unedited.
