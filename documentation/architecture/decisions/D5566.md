## D5566 — Disabled Cloudflare coding workspace candidate (#5566)

**Status:** partial implementation for review. No provider resource, image publication, production binding or flag was changed. The candidate cannot execute through StudioOS until the real authorized broker bridge is implemented and the preview prerequisites below are approved and verified.

### Architecture and current API

This separate image/Worker implements D5565's ExecutorAdapter; it does not amend #4557's deterministic v1 scope, share the meeting-bot container, create a task dispatcher, or introduce a usage ledger. AgentTaskWorkflow/Queue remains the intended caller and sole lifecycle/accounting authority. This change intentionally does not wire an unproven executor into it.

Current Cloudflare Container documentation and installed Wrangler 4.156.1/Workers types 5.20261102.1 were checked on 12 November 2026. The candidate uses the supported durable_object scheduling policy, SQLite-backed Durable Objects, named coding image, Container.start and Container.exec. It requires the managed registry's immutable digest to match the server WorkspaceSpec and the configured image. Public HTTP is always 404. No shell or unauthenticated upload endpoint exists.

Documented size classes are not account capacity. A read-only account inventory on 12 November 2026 found no coding/workspace application. The API has no per-start region selector: an allowed region in a spec is not residency enforcement. Provider facts must contain separately proven account capacity and region/network enforcement; unknown facts refuse admission. No quota, successful hosted execution or hostile-code isolation is claimed.

### Deliberately narrow admission

Both flags are off, preview has max_instances = 1, and the required broker service is absent. That absence returns a typed refusal. Even an enabled, authorized candidate admits only reviewed synthetic coding_trusted jobs, deny-network policy, at most 1 vCPU, 1024 MiB RAM, 1024 decimal MB disk and 600 seconds. Coding_untrusted, checkpoint restoration and network allowlists are refused by this pilot. No privileged mode, host socket, D1, broad R2, GitHub, image-signing or provider secret is available to the guest. The idle image has no listener; work enters through a private, ticket-authorized exec pipe.

The image is digest-pinned, root-owned program files run as node, and setpriv enables no_new_privs. Disposable scratch is not published automatically. The real local Docker fixture additionally enforces a read-only root, bounded tmpfs, dropped capabilities, process/memory/CPU limits and network-none. These Docker controls are local evidence, not proof that every Cloudflare equivalent is configured. Hostile jobs remain ineligible until the security gate has current hosted isolation evidence.

### Lifecycle and publication fences

Tenant/run/attempt/generation deterministically name one DO. A CAS-persisted provisioning record and hard deadline alarm precede start; duplicate create returns the persisted execution instead of starting another VM. Exact SHA, approved bundle and command arrays are passed through bounded stdin. The guest returns bounded unsigned changed files only. The trusted controller independently validates identity, paths, duplicate paths, canonical encoding and hashes. Destroy acknowledgement precedes broker acceptance. Current grant, run generation, role, budget, object scope and cancellation checks belong in that broker; the missing bridge must not be replaced with a permissive stub.

Finished requires the trusted broker's verified signature metadata. Ambiguous artifact acceptance remains unknown. Cancel fences late guest output, and disabling admission does not disable scoped stop/cleanup. Missing execution handles, start/quota failures, hard deadline and no-activity eviction cannot create a replacement VM blindly. Unconfirmed destroy remains unknown, never counts as a cleaned slot and leaves a future cleanup alarm. Only spec/status/artifact refs are durable; guest bytes/logs/checkouts stay out of DO storage. The existing D1/R2 ownership and encryption bridge is still required for real tasks.

### Evidence and limits

The real local Docker fixture passed ten cases: exact source SHA; scoped edit and Node tests; broker-side Ed25519 manifest with tampered tenant rejected; fresh second-tenant checkout and scratch; non-root/no_new_privs/no capabilities/no cloud credential; no reachable localhost/metadata endpoint under network-none; traversal, malformed Git bundle and symlink refusal; compressed disk exhaustion; forced stop; wall timeout. Inventory after teardown found zero fixture containers. Signing occurs outside the guest with an ephemeral synthetic key. No GitHub push or hosted job occurs.

Controller tests exercise actual controller/adapter code with fake provider I/O, persisted restart, duplicate create, quota/provision failure, revoked/wrong-audience/wrong-tenant access, off-flag cancellation, timeout, unknown cleanup, late output, content hashes/scope and missing signatures. Deliberate default-off, internet, cancellation, stop-ack and scope mutations must fail those journeys. This is fault injection, not a provider proof.

The PR image workflow builds the actual image, runs the local fixture, and uses digest-pinned Trivy to emit CycloneDX SBOM, vulnerability and provenance evidence. High/critical/unknown findings or an unavailable vulnerability inventory refuse the image. There is no publication/signing/deploy job or cloud credential. A candidate SBOM/provenance record does not satisfy the trusted published-image signature gate. Hosted tenant/R2 separation, image pull failure, provider crash/quota, egress/residency, role revocation, idle-member zero-container inventory and preview teardown must be demonstrated after integration.

The actual local scanner completed and generated both SBOM and provenance; the candidate was **denied** (high/critical/unknown findings), not cleared. No exception or ignored finding was added. A current Alpine alternative could not be built because this managed environment's destination policy denies its package CDN; it was not substituted with an untested Dockerfile or used to bypass policy. The checked-in candidate is the image actually exercised locally and remains disabled. Rebuild on an approved, supported patched base and rerun the same gate before any publication or hosted job. The evidence workflow therefore cannot be green for this current image under its required vulnerability threshold.
