## D4634 — Deals on a phone reach every match; an explicit address wins over a saved default (#4634)

Package 4 of 5 of the Deals follow-up. Frontend only; no Worker change, no migration.

**What was wrong, checked against current `main`.**
- **Phone table:** the phone cards drew `rows.slice(0, 25)` with no pager, so the 26th match and every one after it could not be reached. They also had no Add to my deal flow, which the desktop table's Stage cell offers for a round that is not on the member's deals.
- **Phone board:** the stage tabs were always the four active stages. A Passed filter showed a Passed column on the desktop board and nothing on the phone.
- **Saved defaults:** a saved default view applied whenever the address named no filter, sort or column setting. `view` and `scope` were not counted as settings, so `/deals?view=table` or `/deals?scope=new` was redirected to the default's own view and scope.

**What changed.**
- **One page model.** `PhoneCards` takes the same `page` and `onPage` as `FlowTable` and draws the same `pageOf(rows, page)`. It shows the same "x–y of n" count and has previous and next controls at least 44px tall. Phone and desktop now describe one dataset and one page.
- **Add on the phone.** A phone card for a round outside the member's flow has Add to my deal flow. It opens the same dialog as the desktop table, and the same call completes it.
- **One stage set.** `PhoneBoard` takes `showPassed` from the same filter as `FlowBoard`, so Passed is a tab when it is asked for. A tab the filter removes falls back to the first stage instead of leaving an empty page.
- **The address is authoritative** (`flowModel.defaultHref`). When the address names no other setting, the default fills in only what the address does not name. An explicit `view` or `scope` is kept, and the default's filters, sort and columns still apply. The bare `/deals` root still opens on the default. The resulting address carries `v=<uid>`, so a refresh or a back/forward reaches the page with the default already resolved and nothing is applied again.

**Tests** (`deal_flow_board_d1240`, 4 new):
- 30 rounds with mixed active and passed stages, 18 of them outside the flow: the phone and desktop tables page through all 27 matching rows with the same count.
- A phone card outside the flow adds the round through the dialog.
- A Passed filter gives the phone board a Passed tab with the passed deal.
- `/deals?view=table`, `/deals?scope=new` and `/deals?view=table&scope=all` keep their choices under a conflicting default board, while the bare root takes the default.
- Mutations caught: the phone back to the first page only; no Add on the phone; the phone board ignoring Passed; the default overriding an explicit view.

**Not done here.** Weighting and comparison state in the shared `DealFlow.jsx` and `flowModel.js` are package 5's (#4635), which follows in the same slot.
