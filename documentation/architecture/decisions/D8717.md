## D8717 — Pricing keeps the billing interval in its address, so Back restores the quoted cadence (#8717)

- **Status:** built. Slot S16. Follows #4651 (the forward handoff, `D4651.md`) and audit #8689.
- **Why:** on axal.vc (26 November 2026), Pricing → Advisors → Yearly → Get Advisor Pro showed the yearly quote on
  registration, and browser Back returned Pricing to **Monthly** with Advisors still selected. The audience lived in
  `?for=`; the interval lived only in `PricingBody`'s `useState('monthly')`, so the page Back mounted started again on
  the default. Reproduced at 390 px too.

### What changed

- **The interval is in the address, beside the audience:** `/pricing?for=<audience>&interval=monthly|yearly`. It is
  the same parameter and the same two words the signup return (`next`) and D1053's checkout ask already use, so one
  vocabulary covers all three. `billingFromSearch` (`lib/pricingModel.js`) reads it; `searchWithBilling` writes it
  and keeps every other parameter (`for`, a pending checkout ask).
- **Monthly / Yearly navigate with `replace`.** A press rewrites the current Pricing entry; it adds none, so Back from
  registration lands on Pricing in the state that produced the quote, and one more Back leaves Pricing.
- **Defaults (documented here and in the route map's Pricing row):**
  - no `interval`, or a value other than `yearly` (`?interval=weekly`, `YEARLY`, empty): **Monthly**. A new visit and
    a bare deep link (`/pricing?for=advisor`) are Monthly, as before;
  - `?interval=yearly` deep link: **Yearly**; a reload keeps whatever the address says;
  - opening the page never writes `interval`: the address changes only when someone presses Monthly or Yearly (or a
    checkout ask is spent, below);
  - a deliberate Monthly writes `interval=monthly`, so it persists through signup, Back and Forward exactly as Yearly
    does;
  - switching audience keeps the interval (it always did, as state); it is still one entry.
- **The member's checkout return (D1053, #4651).** Back from sign-in, Pricing still drops `checkout` and `seen` from
  the address so Back does not reopen the sheet. `interval` now **stays** when the sheet opens on it (it is the page's
  billing now; this is what `setBilling(iv)` did in state), and **leaves** with an ask that opened nothing (a plan no
  longer sold, a yearly price no longer held, a malformed interval), so the page shows the Monthly default as before.
  `checkout_sheet_d1048.test.mjs`'s D1053 case is updated to that: the ask leaves, `?interval=yearly` stays.

### What did not change

No price, no catalogue wording, no copy, no layout and no checkout safeguard: `planCards`, the signup address
(`planIntent.js`), the `seen` price-change notice and the signed-in gate are untouched. No Worker change, no new
route. The issue's Claude Design prompt asks for annotated boards (focus on return, monthly equivalent versus annual
commitment); this fix adds no screen or visual, so nothing was designed. Focus after Back is the browser's own
restoration of a fresh page, as before; if the owner wants focus placed on the billing switch after Back, that is a
design call for those boards.
