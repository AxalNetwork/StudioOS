## D5569 part 4 — Privileged candidate staging for the draft publisher (#5569)

D5569 part 3 left one adapter unbuilt: the privileged step that turns an
approved publish intent into the Git candidate `executeAgentPublication`
verifies. This part adds it as `stageAgentCandidate` in
`cloudflare-worker/src/services/agents/agentCandidateStaging.ts`. It is
unmounted. No route, queue consumer, Env binding or flag calls it, and it
adds no migration, secret or App.

### What it takes and returns

The caller passes the approved `PublishIntent`, one UTF-8 file body per
added or modified path, the write App's commit identity, a commit time the
server fixes for this intent, and the enable value. Only `on` enables the
adapter, as in parts 2 and 3. The caller also passes a repository-scoped
transport and a clock. The transport holds the short-lived installation
credential and prefixes the fixed API origin and `/repos/<owner>/<name>`.
It also rejects redirects and bounds request time. The adapter never sees a
token and can only address the repository the transport was scoped to. It
has no D1 handle. Part 3's reservation, WorkIntent and receipt rows remain
`executeAgentPublication`'s responsibility.

On success it returns `candidate_sha`, `tree_sha`, `base_sha` and
`patch_digest`. The caller passes `candidate_sha` to
`executeAgentPublication` and the preflight's `candidate_sha`. That
function re-verifies everything below before it creates
`agent/<task>/<attempt>`.

### How the candidate is built

1. **Exact bytes.** Each added or modified path has exactly one canonical
   base64 body of at most 1 MiB, with at most 8 MiB per intent. A removed
   path has no body, and no undeclared path is accepted. A body that has a
   NUL byte or is not valid UTF-8 is refused (`unsupported_content`)
   because GitHub renders binary changes without content. The diff digest
   would then not bind the bytes.
2. **Verified base.** The target ref must still point at `base_sha`
   (otherwise `base_moved`, with no write). The base commit and each tree on
   a changed path are read without recursion. Each tree's listed entries
   must hash to the SHA GitHub reported, and the listing must not be
   truncated. This check also proves that the adapter's tree serialization
   matches Git's.
3. **Exact operations.** An added path must be absent. A modified or
   removed path must be a regular file (`100644`/`100755`), and a
   modification must change the blob. A symlink, a submodule, a file used as
   a directory, a directory replaced by a file or an unchanged file is
   `candidate_conflict` and names the path. A modified file keeps its mode,
   an added file is `100644`, and a directory emptied by removals
   disappears.
4. **Computed locally first.** The blob, tree and commit SHAs are computed
   before any write. The commit has exactly one parent, `base_sha`. Its
   author and committer are the broker's identity at the fixed time
   (`+0000`). Its message is built only from trusted fields: task, attempt,
   agent, run UUID, intent digest and patch digest. The agent's summary and
   log never enter it.
5. **Duplicate attempts write nothing.** If the expected commit already
   exists, the adapter returns it with `replayed: true` and zero writes.
   Otherwise it creates the blobs, then one tree with `base_tree`, then the
   commit through the Git Data API. Every returned SHA must equal the
   computed one, or staging stops with `candidate_mismatch` before the next
   object. Concurrent duplicates write identical objects and agree on one
   SHA.
6. **Ambiguous writes are re-read.** A write with no answer, an unreadable
   answer or a 5xx is followed by a read of the expected SHA. A found object
   lets staging continue. A missing object or an unanswered read returns
   `staging_unknown` (retryable). A re-run computes the same SHAs, so it
   either finds the candidate or completes it. No ref exists to reconcile.
7. **What the broker will check.** The base-to-candidate comparison must
   show one commit and exactly the declared paths and operations. The
   SHA-256 of GitHub's diff must equal the intent's `patch_digest`, or the
   adapter refuses with `patch_digest_mismatch`. Unreferenced objects from a
   refused run cause no harm and are garbage collected.

The adapter never writes `/git/refs` or `/pulls`. Only part 3 creates the
branch, and only after it re-reads the installation, WorkIntent, checks
and base.

### Refusals

`publisher_disabled`, `invalid_intent`, `invalid_content` (field and paths)
and `unsupported_content` apply to the input. `repository_mismatch` means
the transport is scoped elsewhere. `base_unknown` and `base_moved` concern
the base. `candidate_conflict`, `candidate_mismatch` and
`patch_digest_mismatch` concern the candidate. Provider responses map as
follows: `github_unauthorized` (401), `github_forbidden` (403 that is not a
rate limit), `github_rate_limited` (429 or a 403 limit, with part 2's
`classifyGithubResponse` retry time), `github_rejected` (404 on a write,
409, 422) and `github_unavailable` (a 5xx, timeout or unreadable read,
retryable). `staging_unknown` is described above.

### Review points and open owner decisions

- **Diff digest format.** Part 3 binds `patch_digest` to GitHub's rendered
  base-to-candidate diff. This part keeps that binding unchanged. A
  workspace that hashes its own `git diff` output may not match GitHub's
  rendering byte for byte. The refusal is fail-safe. Isolated live
  acceptance must confirm the format, or a later part must define the
  digest over a canonical patch both sides render.
- **GitHub-side commit signing.** If GitHub signs or rewrites a commit
  created by the App, the returned SHA differs from the computed one and
  staging refuses. Live acceptance should confirm that an explicit author
  and committer produce an unsigned, byte-exact commit.
- **Commit time.** The caller fixes `committed_at_s`. The reservation's
  creation time is the natural source. The consumer chooses it when it is
  wired.
- **Still undecided and not chosen here:** where persisted allowed paths
  live, the activation flag's Env binding, and whether people or a policy
  mark drafts ready. The adapter enforces no path policy beyond part 2's
  intent validation. Part 2's planner and part 3's executor still apply
  scope before any ref is written.

### Later gates

Authenticated WorkGraph and GitHub preflight readers. Wiring through the
existing AgentTaskWorkflow/Queue or WorkGraph outbox, with dispatch rate
limits and abandoned-reservation reconciliation. A concrete transport built
on the broker's installation token. The owner's App installation and
decisions above, and isolated live acceptance. Rollback: nothing calls the
module, so removing it and its test changes no data.

### Verification

`cloudflare-worker/test/agent_candidate_staging_5569.test.ts` runs against a
synthetic Git server that hashes objects with its own implementation. That
server applies `base_tree` by flattening and rebuilding the tree. The
expected tree, commit and base SHAs were computed with `git write-tree` and
`git commit-tree`, not by the code under test. The tests cover the exact
candidate, duplicate and concurrent attempts, a disabled or misdirected
call, base movement, every path and operation mismatch, tampered or
truncated base trees, mismatched returned SHAs, lost writes found and not
found, 401/403/429/404/409/422/5xx classification, the comparison and
digest, and an end-to-end run. In that run `executeAgentPublication`
accepts the staged candidate and only then writes `/git/refs` and
`/pulls`. No network or credential is used.

All 11 staging tests and the 34 existing publisher, broker and
installation tests pass with zero skips. Mutation check
(`agent_candidate_staging_5569.test.ts`): 31 mutations, 31 caught,
0 equivalent.
