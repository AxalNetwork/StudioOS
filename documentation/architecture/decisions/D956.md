### 1. Migration 562: `draft`, and the registry's keys

- **The state check** gains `draft`.
- **The key check** becomes the registry's slug rule: at most 60 lower-case letters, digits and hyphens. Migration 553 allowed only the nine keys, and a program a proposal adds has its own key. Whether the program exists is the registry's (`programs`), and the routes read it.
- **`proposal_uid`** is the proposal a draft was opened for. A unique index allows one draft per proposal.
- **The rebuild.** SQLite cannot widen a CHECK, so the table is rebuilt as 553 rebuilt `licence_events`:
  - every row is copied with its id, and D982's index is recreated;
  - no trigger or foreign key names `program_grants`;
  - its history lives in `licence_events`, which the rebuild does not touch.
- **The backfill.** Each proposal already approved for one studio gets its draft, dated and attributed as its decision was, and one history event.
  - A studio with no licence row gets no draft.
  - The file can be applied twice and adds nothing the second time. A second application restores `proposal_uid` from the proposal, because the copy cannot read it from 553's table.

### 2. The draft

- **The approval opens it.** `decide` (`services/programProposals.ts`) does it for an approval "for this studio only", in the same batch as the registry row and the decision (`openDraftStatements`, `services/programGrants.ts`).
  - A catalogue approval opens none.
  - If the studio's licence row is gone, there is no draft and the approval still lands. The audit row's `draft_grant` says which happened.
- **A draft is HQ's:**
  - nothing runs on it;
  - the studio reads "Not granted" (§4);
  - D984's copy to the branch leaves it out (`programCopy`).
- **D982's grant write is its one way out:** `POST /api/admin/program-grants/licences/:uid/:program`, `draft` → `granted`, in place, keeping its proposal.
  - It needs no readiness or "can be granted" check, because HQ already approved the program for that studio.
  - A frozen licence still refuses it.
  - Pause, resume and end are refused on a draft (409 `wrong_state`). A terms change is refused too (409 `not_granted`, "This grant is a draft"). So is sending its schedule for signature (D1120's `schedule/send`, 409 `wrong_state`): it is sent once HQ grants it.
- **A program D955 added has the terms every program has.** Those are dates, ends with the licence, fee, currency, playbook, brand, reporting and the schedule rule, and none of the nine's own (`termsFor`). Its grant terms are #2376's.
- **Without a draft it is not granted** (422 `not_grantable`), because it has no defaults to grant from. Once its grant has ended, it may be granted again (`regranted`).

**The licence-history shape picked:** one generic event, D982's `program_changed` (D982 §4), and no new event type.
- Opening a draft writes `{ action: 'draft_opened', program_key, proposal_uid, changed: [state null → draft] }`, with a note saying the approval opened it. The backfill adds `backfilled: true`.
- Granting it writes D982's `granted`, with `from_draft: true`, `proposal_uid` and `state draft → granted` first in `changed`.

### 3. Offer to studios: `PUT /api/admin/programs/:key/grantable`

- **The request:** `{ grantable, reason }`, under `requireSuperAdminWriteBar`, with a reason of at least 10 characters.
- **The flag:** it writes D982's switch, `program_grant_defaults.grantable`. There is no second flag.
- **Switching it on** (`offerRefusal`, `services/programGrantStates.ts`) needs, in order:

  | Refusal | When |
  | --- | --- |
  | 409 `runs_at_hq` | Product testing |
  | 409 `not_built` | the registry says `not_built` (Investor cohort access) |
  | 409 `not_published` | no published playbook (part 1). AI-native Venture's draft says "When HQ publishes it, you can request it." (`dc:458`) |
  | 409 `not_grantable` | D982's readiness. It still holds AI-native Venture as not ready, so a published playbook alone does not switch it on |

- **One rule for both pages.** D982's own `PUT /defaults/:program` applies the same rule when it switches the flag on, after its own 422 for the locked three. Otherwise the rule could be skipped by using the other page.
- **Switching it off** leaves every grant as it is. The answer counts the grants that stand (`grants_kept: { granted, paused }`).
- **Other answers:**
  - a program D955 added is 409 `not_offerable`: only the nine carry defaults;
  - asking for the value the switch already has is 400 `no_change`.
- **Audit:** each write is `program.grant.offer` in the admin audit. Every program's Activity lists it, and D982's `program_grant_defaults_changed` too (`services/programActivity.ts`).

### 4. What each viewer reads: `grant`

The catalogue's rows (`GET /api/admin/programs`) and `GET /api/admin/programs/:key` carry `grant`. `/:key` also carries `grantable`, D982's switch, which is false for a program D955 added. `services/programGrantStates.ts` decides who reads what:

| Viewer | Reads |
| --- | --- |
| a Super Admin | `granted_to`, with `granted_count` (the licences holding it `granted`; paused and draft are not), or `hq_only` for a program HQ cannot grant |
| an Admin bound to a licence whose studio is deployed (`DEPLOYED_STATUSES`) | the licence's state: `granted` (with `in_force`), `requested` (with `since`), `paused`, `ended`, `not_granted`, `runs_at_hq`, `not_offered` |
| a licence administrator on HQ whose studio is not deployed | the held mode, until #2376's owner decision 1 is answered |
| an admin bound to no licence | the held mode: `hq_held`, `not_offered`, `runs_at_hq` |
| anyone on a branch | the licence's state, from D984's dated copy and the branch's own open requests to HQ |

- **The order of the licence's words:**
  1. Product testing reads `runs_at_hq`.
  2. A `granted` or `paused` row reads as it is.
  3. An open `program_grant` request reads `requested`. Requests are read from HQ's lane for the licence, and from its branch's lane by deployment code. `since` is the oldest open request.
  4. An ended grant reads `ended`.
  5. A draft reads `not_granted`.
  6. Otherwise the program reads `not_granted` if HQ offers it, else `not_offered`.
- **`nothing_granted`** is true when a viewer reading a licence's state holds no `granted` row (PG16a), and false for every other viewer. The catalogue also carries `grants: { viewer, held_because }`.
- **A failed read is unreadable, never a state.** Every row's `grant` reads `{ available: false, unreadable: true, reason }`, and the rest of the catalogue still answers.
- **On a branch with no copy yet**, the reason says HQ has not sent it, never `not_granted`.
- **HQ's fan-out.** The view of a branch that HQ fans out names no viewer, so it carries no `grant`.
