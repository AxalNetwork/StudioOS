## D5973 — CI scorecard: one classified row per merge-group candidate (#5973)

Part of #5506 ("Merge-queue timeouts under heavy load", box 1). D5603's daily scorecard reports aggregates only, so a candidate GitHub removed at its deadline could not be told from one that failed or was superseded. The scorecard now also writes one row per `merge_group` head SHA in the window to the `ci-scorecard-candidates` artifact (`$RUNNER_TEMP/ci-scorecard-candidates.json`, kept 30 days) and adds one Markdown row counting them per outcome. It is still read-only against GitHub apart from D5603's one comment, and adds no required check.

**A row.** Request time is the earliest `created_at` of the candidate's queue workflow runs (`ci.yml`, `gitleaks.yml`, `migration-immutability.yml`: the workflows that report a required check). First runner start is the earliest `started_at` of any non-skipped job. The last required check is the required job that completed last, with its wait (`created_at` to `started_at`) and runtime (`started_at` to `completed_at`); it is null unless every required check was sampled and completed. Queue entry and removal come from the PR's timeline entry that contains the request time; `removalEvent` is the event that ended it (`removed_from_merge_queue`, `merged` or `closed`) and `removalReason` is a `reason` string if GitHub put one on the event. The REST timeline records none today ([#5444's removal, event 35711750617](https://api.github.com/repos/AxalNetwork/StudioOS/issues/5444/timeline) carries no reason), so the column is null rather than invented. Reading the reason from GraphQL would need a POST, which D5603's single-writer guard forbids outside the comment.

**One outcome, first match wins, never guessed.**

1. `merged`: the PR timeline's `merged` event names this SHA (`commit_id`). A queue merge fast-forwards main to the candidate (#5423 merged as `95f95145`, its merge_group head).
2. `failed-check`: a required job concluded `failure` or `timed_out`, or a queue run did, at or before the removal (at any time, if no removal was read). #4107's test keeps every other job skipped in the queue, so a failed queue run is a failed required check.
3. `deadline-expired`: GitHub recorded a timeout reason; or every required check was sampled, the removal came between the deadline and `DEADLINE_SLACK_MIN` (15) minutes after it, and a required check was still pending at the removal. The deadline is `check_response_timeout_minutes` from `GET rules/branches/main` (90 today); if that read fails, no expiry is confirmed from run data.
4. `cancelled-or-superseded`: a queue run was cancelled; or every required check was sampled, none failed, a removal was read, and the PR merged as another commit or the removal came before the deadline. This is #5444's shape: entered 17:39:22, candidate `c6db2e00` requested 17:51:13, removed 17:51:16 and the PR merged 8 s later as `8f1dbd0c`, which has no queue run; the candidate's checks passed 100 min later.
5. `missing-evidence`: anything else, with the gap named (`required jobs not sampled`, `no queue removal or merge recorded`, `deadline unread`). A removal past the deadline with no job sample is missing evidence, not an expiry.

**Required checks.** The names come from `REQUIRED`, moved from `frontend/test/merge_queue_ci_4107.test.mjs` to `scripts/lib/requiredChecks.mjs`, which that test and `ciScorecard.mjs` both import: a script must not import a test file, and one list means a ruleset change is made once.

**Requests.** The cap rises from 150 to 200 (`BUDGET` in `ciScorecard.mjs`, tested), because a candidate needs its three queue workflows' jobs, not only `ci.yml`'s. Merge-group head SHAs are sampled first, up to 32 evenly spaced, all three runs of a SHA together; then 12 runs each of pull_request, push and other events. Jobs stop at 145 requests, PR timelines at 185, and the comment's ten pages and one write still fit (196). One request reads main's rules. At 200 sequential GETs a day this is a fifth of the documented 1,000 per hour for `GITHUB_TOKEN`. A SHA whose jobs the budget did not reach reads as missing evidence.
