## D711 — Every legal document draws one HTML paper in Axal's type, printed to PDF by Browser Run on Letter or A4, with a Word export and a record of every file

Status: Decided. Date: 2026-10-17. Slot: S10. Issue: #1776. Decided by S1 under the owner's standing rule. PR 1 (the Worker: steps 1–12 and 16, #1811) starts this record; PR 2 (the screens: steps 13–15) completes it.

**Reference.** The approved Claude Design canvas "Legal Documents · Templates" (https://claude.ai/artifact/VfkEZzQ8npTgCiQuKJu1MA, boards R1, R2, L0–L5). The reference is now `design/incoming/Legal Documents · Templates.dc.html` (#1850), decoded from that link. The export wins on look; the issue wins on data and behaviour.

Before this decision legal documents printed in two looks, and neither was Axal's:
- pdf-lib drew Helvetica on Letter only.
- The admin preview drew the browser's serif.
- Headings, bullets and bold were stripped.
- Names lost letters ("Łukasz" printed "?ukasz").
- Signed copies printed the signer's IP.
- Each signature overwrote the last signed copy, and no table said which file went where.

### Decisions

1. **One paper, owned by the Worker.**
   - `services/legalPaperBlocks.ts` reads a body into typed blocks of plain text.
   - `services/legalPaper.ts` builds the model from those blocks and from `legalDocFormat.ts` (kind, Axal party, preamble, execution block), then draws one HTML document.
   - Browser Run prints that HTML. The pdf-lib fallback (`pdf.ts`) and the Word export (`legalDocx.ts`) draw the same model.
2. **The brand faces, in the repo** (`templates/legal/paper/`, inlined as `data:` URIs; no render fetches anything):

   | Face | Role |
   | --- | --- |
   | Public Sans 400, 400 italic, 700 | body, preamble, execution text |
   | Bricolage Grotesque 800 | title and article headings |
   | Space Grotesk 700 | the lockup's "AXAL VC" only |
   | Roboto Mono 400, 700 | figures, audit line, hashes |

   - All seven faces total 108,252 bytes.
   - All four families are SIL OFL 1.1. The canvas gives Roboto Mono as Apache 2.0, but the v3.001 file shipped here names the OFL in its own `name` table and licence file.
   - Subset ranges: Basic Latin, Latin-1, Latin Extended-A, U+0218–021B, General Punctuation, ← →, ≤ ≥ ≠.
   - **Glyphs that fall back:** Public Sans and Roboto Mono have no ← or →, so those two arrows fall back to the browser's sans in those faces. Every other character in the ranges is present in every face. `paper/README.md` holds each file's source and `pyftsubset` command.
3. **Browser Run prints through `quickAction`; pdf-lib is only the fallback.**
   - `services/browserRun.ts` calls `env.BROWSER.quickAction('pdf', { html, pdfOptions, gotoOptions })` and never `BROWSER.fetch`. It accepts only an `ok` answer that starts `%PDF-` and is at most 10 MB, within 20 s.
   - On any other outcome `renderLegalPdf` draws the fallback and logs a reason code: `browser_unbound`, `browser_error`, `browser_timeout`, `browser_status`, `not_pdf` or `pdf_too_large`.
   - Every file says which renderer made it: the registry row, `X-Axal-Renderer`, or the JSON `renderer`.
4. **Letter or A4, dark or light cover.**
   - The defaults are Letter and dark.
   - The sender picks per envelope; `esign_envelopes.page_size` and `cover` store the choice, so every copy matches.
   - Previews take both as parameters. Word always uses the light cover. Margins are 0.75 in.
5. **A Word export with no new dependency, for templates only.**
   - `buildLegalDocx` writes eight XML parts, packed by `util/zip.ts`.
   - It names the faces and embeds none.
   - It has no external relationship, macro or image.
6. **A file registry.**
   - Append-only `legal_document_files` (migration 475) gets one row per file kept or handed out, holding ids, hashes, sizes and codes only.
   - Previews are never stored and get no row.
7. **Each signature keeps its own file, and each signer downloads their own.**
   - Copies are stored at `esign/signed/<uuid>/<file uid>.pdf` and never overwritten.
   - The signed UPDATE and the `signed_copy` row land in one batch: the row is inserted only while the recipient reads `signed`. If the batch throws, the claim rolls back and the route answers `signed_pdf_failed`.
   - `signed_r2_key` points at the newest copy, for the sender and admins.
   - **The multi-signer finding:** `esign_recipients` keeps no signature image. So every recipient gets a block, but only the current signer's block carries an image; earlier signers show their signed line under a blank By line. Drawing every image needs each one stored, a separate change that S1 files after this merges.
8. **The footer prints the real version, or none.**
   - `esign_envelopes.template_version` records the version when the sender knows it: the contract send passes `prepared.template.version`; `/api/legal/esign/send` passes none.
   - With no version, the footer prints the title alone, never "v1".
9. **The signer reads the paper they sign** (`GET /sign/:token/paper`), with their name in the preamble. PR 2 draws it on the signing page and falls back to today's text.
10. **No wait for the canvas's last pass.** Every colour, size and space is a named token in `PAPER_TOKENS` (`legalPaperCss.ts`). The final `.dc.html` changes those tokens, and tests read token names, not values.
11. **A page's state comes from stored state** (`paperStateFor`):

    | Page | State |
    | --- | --- |
    | a copy made for an envelope | Issued |
    | a preview whose version and body hash match `legal_template_publications` | Specimen |
    | a preview of an older version | Superseded by v<N> |
    | anything else | Draft |

    Only an issued copy prints the audit line (SHA-256 prefix and envelope id); the others print "assigned when issued".
12. **The long instruments get a cover and contents.**
    - `COVER_SLUGS` holds `lpa_amended_restated`, `ppm` and `compliance_manual_code_of_ethics`. #1781 adds the Subscription Booklet with its kind.
    - A cover slug prints in two passes: pass 1 is the body with each article heading linking to its own id; the pages of its link annotations are the contents numbers. Pass 2 is the cover and contents, numbered i, ii, …; pdf-lib merges the two.
13. **One signature page, and no IP or email on paper.**
    - The body ends "[Signature page follows]".
    - The execution block takes its own page, with up to three parties side by side. On a multi-recipient envelope, the counter-signer (`AXAL_COUNTERSIGNER_EMAIL`, default `legal@axal.vc`) signs the Axal block, and every other recipient gets a counterparty block, in `ORDER BY id`. So the 3-Way NDA prints Founder, Investor and Axal.
    - Every signed copy ends with a certificate of completion.
14. **A redraw carries the paper, not the faces.**
    - `POST /templates/render` with `fonts: 'omit'` answers the paper without faces (a short paper is under 40 KB).
    - `GET /templates/paper-fonts` answers the faces once per `paper_sha256`.
    - Every other render carries the faces inline.

### The screens (PR 2)

- **One frame, no script.** `PaperFrame({ html, title })` in `components/PaperPreview.jsx` is `<iframe sandbox="allow-same-origin" srcDoc={html}>`, with no `allow-scripts`. The parent reads the same-origin frame's height on load and sizes it. Every screen that shows a paper uses it.
- **The live preview.** `PaperPreview` posts to `/templates/render` through `contractsApi.renderPaper({ …, fonts: 'omit' })` 500 ms after the last edit, and fetches `/templates/paper-fonts` once per `paper_sha256`. `withPaperFonts` fills the paper's empty `<style id="paper-fonts">` with that CSS, and refuses CSS holding a `<`. It keeps the last paper that drew while it redraws, and says when a draw fails. Its own drawing, its `resolveWithBrackets` and its import of the JS mirror are gone, and so is any `dangerouslySetInnerHTML`.
- **The template editor.** Letter/A4 and Dark/Light selects drive the preview and Download PDF (`adminTemplateStorePreviewPdfBlob` with `page` and `cover`). Download Word (`data-testid="template-download-docx"`, `adminTemplateStoreDocxBlob`) sits beside Download PDF. Both blob helpers stay outside the typed drift surface.
- **The envelope wizard.** `envelopeBody(…)` is exported and carries `page_size` and `cover`, so changing either clears the preview. The Provider step has two `aria-pressed` pairs for the paper, and the summary names both.
- **The agreement.** Under Signed PDF, `contractsApi.files(uid)` lists each recorded file: its kind, "Signer N", renderer, size, date, a 12-character hash prefix, and "not stored" when its object is gone.
- **The signer.** `SignerPaper({ paper, envelope })` on `ESignPage` draws the paper from `api.esignPaperByToken` (unauthenticated, like `esignFetchByToken`). While it loads it shows the text; if the read fails, the text with "The formatted page did not load. This is the same text." The phone screens (L12) are #1782's.

### How the print was checked

The PR preview Worker has no bindings (its comment says `/api/*` is a 404), so Browser Run could not be exercised there. Instead the paper was printed by the pre-installed Chromium through Playwright's `page.pdf`, the engine Browser Run drives, with the same `pdfOptions`:

- **Margin boxes held.**
  - The lockup, CONFIDENTIAL and the header rule printed on every page.
  - The footer's title with its version, "Page X of Y" and the audit line printed on every page.
  - A face used only in a margin box is never loaded, so the paper carries an invisible `lockup-font-warm` run that loads Space Grotesk for the wordmark. Without it the wordmark printed blank.
- **Fonts.** `pdffonts`-style inspection listed all four faces as embedded subsets, Public Sans Bold among them.
- **Breaks held.**
  - The execution block started its own page.
  - The diagonal repeated on every page.
  - A dark A4 cover filled its page edge to edge.
- **Contents numbers held.** A PPM-sized body's contents printed 1, 2 and 4 for its three articles, and the front matter i and ii.
- **Still to confirm.** The owner checks a `browser_run` file on axal.vc after merge (the issue's owner steps).
