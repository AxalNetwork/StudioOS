## D661 — The cycle overviews and module pages in the SPA, from the shared cycle read

Issue #1474, 2026-10-09, part of #1469 (D656). No migration. S07.

### What this part builds

S1's order on #1474: build the components now and mount nothing. Each cycle is
wired as its read merges:
- Validate first: #1472 (D659);
- then Build: #1475 (D662);
- then Raise: #1476 (D663);
- then Grow: #1477 (D664).

The pieces, all in `frontend/src/pages/cycles/`:
- **`CycleOverview`** draws `Cycle Overview.dc.html`'s `variant=full`, `new`
  and `states`:
  - the cycle's question and outcome, and its primary action;
  - four headline figures with sparklines;
  - one chart card per module, in the read's order.

  There is no module list, no status pill and no Pro strip. This answers the
  owner's question of why each overview showed its modules twice: the tabs
  are navigation, and the cards are the modules.
- **`CycleModulePage`** draws `module=0…6`:
  - the tabs (a module menu on a phone);
  - the module's chart at full size, with its caption and its one next action;
  - the records as a working table: search, filters, sort, pages and Add;
  - a link to the module's own tool where it has one, rather than a second
    copy of it;
  - then the module's further parts.
- **The five card states:**
  - `empty` shows its line and the action that starts it;
  - `too_little` draws no line;
  - `not_recorded` shows its reason;
  - `unreadable` names its source and offers a retry for that card only.

  A card still being read draws the canvas's grey bars. A state the page does
  not know, and an `ok` card with nothing it can draw, read as unreadable,
  never as fine.
- **The charts are SVG components,** one per helper in the canvas. They use
  no chart library and no HTML strings: the canvas injected its charts as raw
  HTML, and these are elements, so a label from a read is always text.

### The shape D656 left open

D656 names `Card.series` and `records.cols`/`rows` but does not give their
shape. The page consumes them, so this decision gives it. The four read tasks
build to it.

**`Card.series` is a list of chart specs, drawn top to bottom.** Each spec
names its `kind` and carries that kind's data. Any spec may also carry
`legend: [{ label, tone }]`.

| kind | data |
| --- | --- |
| `hbar` | `items: [{ label, value, tone? }]`, `more?` |
| `vbars` | `values: number[]`, `labels?: [{ at, label }]` |
| `vstack` | `rows: number[][]`, `tones: string[]`, `labels?` |
| `funnel` | `steps: [{ label, value }]` |
| `stack` | `rows: [{ label, parts: number[] }]`, `tones`, `bare?` (one unlabelled bar) |
| `line` | `values: (number\|null)[]`, `target?`, `target_label?`, `plan?: number[]`, `mark?` (an index), `mark_label?`, `labels?` |
| `timeline` | `steps: [{ label, date, done }]` |
| `tiles` | `items: [{ label, state: 'connected'\|'failing'\|'not_connected' }]` |
| `dots` | `values: boolean[]`, `label?` |
| `rows` | `items: [{ label, value, tone? }]` |
| `progress` | `items: [{ label, pct }]` |
| `big` | `value: string`, `label` |
| `heat` | `rows: [{ label, cells: number[] (0–1) }]`, `axis?` |
| `bands` | `items: [{ label, value, source? }]` (total, serviceable, obtainable) |

- **Tones are names, never colours:** `v1`, `v2`, `v3`, `grey`, `ok`, `warn`,
  `bad`, `muted`.
- **A null value is drawn as "Not recorded",** or left undrawn inside a chart.
  It is never drawn as 0.
- **A line breaks at a missing point.** A spec with fewer than three real
  points is not drawn, as D656's `too_little` rule requires.
- **A spec of an unknown kind is skipped.** If nothing in the series can be
  drawn, the card reads as unreadable.

**The records:**
- `cols: [{ key, label }]`;
- `rows: [{ id, cells: { [key]: Cell } }]`, where a Cell is a string, a
  number, null, or `{ text, tone?, href? }`. Null is "Not recorded".
- optional `filters: [{ key, label, options: [{ value, label }] }]`,
  `sorts: [{ key, label }]` and `add: { text, href }`.

The page sends the read's own query: `q`, `filter=key:value,…`, `sort` and
`page`. It filters nothing in the browser, so the count is always the store's
count. An unknown `total` is shown as "N shown · total not recorded".

**Links are in-app only.** Every `href` a read carries (a card's `next`, a
cell, Add, a module's tool) must be a path on this app. Anything else is drawn
as text (`safeHref`).

**The figures:**
- `unit` is `usd`, `pct`, `score`, `of` (a pair: `[11, 18]` is "11 of 18"),
  `count`, `days` or `months`.
- `delta_30d` is written as "▲ 4 in 30 days". The page does not colour it
  good or bad, because the read does not say which direction is good.

### What waits

As each cycle's read merges:
- add `lib/api/cycles.js`, re-exported from `api.js`;
- mount `/:cycle` and `/:cycle/:slug`;
- redirect the cycle's old module URLs (for example `/validate/interviews` →
  `/validate/customer-research`);
- point the header button at the cycle's action (#1473, #1463, #1465, #1466),
  or at its current page until that action lands;
- update `workspaces/shellConfig.js` and remove the desks' duplicate module
  lists.

Until a cycle's read lands, its current page stays. When the last cycle
switches over, move `Cycle Overview`, `pro-cycles.js` and both boards to
`design/canvases/integrated/`.

### Validate is wired (Part of #1474, 2026-10-09)

**`/validate` and `/validate/:module` draw the cycle pages** from #1487's read
(D659), for a founder. `?mode=workspace` and every other role keep the editor.

**The page adapts; the Worker is not changed.** Validate's read merged with its
own shapes: module data in `series`, labels in `cols` and plain objects in
`rows`. S1 decided on #1474 that the page maps them:
- `pages/cycles/adapters/validate.js` holds one function per module slug, each
  drawing the canvas's chart for that card;
- `adapters/index.js` passes a read already in this decision's shape through,
  so Build (#1475) and Raise (#1476), told to return it, need no adapter;
- figures written in words ("interviews", "of 7") become `count` and the
  `of` pair, so "3 of 7" keeps its denominator.

`cloudflare-worker/test/cycle_adapters_d661.test.ts` runs the Worker's real
output through the adapter, on real SQLite with every module seeded. Every
`ok` card must draw, and every column must have a value source. Twelve
mutants are killed.

**The working tools stay, linked.** No canvas yet draws a module's Add form,
a record's edit view, or Validate's curation (S02 found the gap on #1474).
This decision already gives a module page "a link to the module's own tool
where it has one", so:

| Module | Tool | Add |
| --- | --- | --- |
| Problem discovery | `/validate/pain-map` | — |
| Customer research | `/validate/interviews` | Record a session (opens the interview form) |
| Ideal customer profile | — | — |
| Market intelligence | `/build/competitors` | — |
| Demand and urgency signals | — | — |
| Experiments and evidence | `/validate/hypotheses` (and the verdict) | — |

An Add button with nothing behind it is not drawn. The Validate desk's two
AI fill bands sit on the modules they fill (pain tags on Problem discovery,
hypotheses on Experiments). The A2 desk is no longer mounted; its file and
tests are retired with the other desks once every cycle is wired.

**The venture stays chosen.** The page picks the venture from `?project_id=`,
or from the read's own `?project=` (each card's `next.href`), else the
founder's first. The tabs and each card's title link carry `?project_id=`, so
a founder with two ventures does not fall back to the first by changing tab.

### Raise is wired (Part of #1474, 2026-10-09)

**`/raise` and `/raise/:module` draw the cycle pages** from #1501's read
(D663), for a founder. `?mode=workspace` and other roles keep today's pages.

**No adapter.** Raise's read was built to this decision's shape: chart specs
in `series`, `{ key, label }` columns, `{ id, cells }` rows, and its own `add`
links to the tools. It passes through `adapters/index.js` unchanged, and
`cycle_adapters_d661.test.ts` asserts exactly that on the real read, with the
cap table, use of funds and pipeline seeded.

**The tools keep their routes.** Every Raise tool route (`/raise/pitch`,
`/raise/data-room`, `/raise/capital/*`) is static and wins over
`/raise/:module`. The Data room module's slug is the data room's own path, so
its tab opens the working tool, which is this decision's rule for a module
that has one. The other module pages link their tools: positioning, the
deck, the cap table, the financial model and the investor pipeline. The
primary action is D653's Call for Capital (`/round-calls`), which says it is
not available while `ROUND_CALLS_ENABLED` is off.
