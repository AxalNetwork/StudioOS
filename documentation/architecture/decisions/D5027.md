## D5027 — Revenue renders the token margin the Worker already computes (#5027)

#5027 (slot S11, taken at the owner's request, P0). `/admin/revenue` showed Token margin as Not recorded and a test pinned the Margin stat to `value={null}`, while `routes/admin_revenue.ts` has computed the D762 token P&L: `topup_spend_microusd`, `topup_cost_microusd`, `tokens_given_microusd`, `included_in_plans_microusd`, `margin_microusd`, `member_runs`, `runs_not_recorded`, `billed_available`.

### Decision

`tokenMarginView(token)` turns the `token_cost` payload into the page's display strings, and `TokenPnl` draws six tiles in the Token P&L zone: top-up spend, top-up cost, tokens given, included in plans, token margin, and the coverage line (member runs settled, runs before migration 493, admin-licence runs left out). The stream table's Token margin row shows the margin and the cost. Every figure is the Worker's: the page works out none of it.

- **Two failure domains.** The cost (`available`, the usage log) and the margin (`billed_available`, the charge ledger) fail apart. An unreadable ledger leaves the cost on screen with the server's `billed_reason`; an unreadable usage log shows nothing as a number.
- **Unknown is Not recorded, never 0.** When every member run this quarter predates migration 493 the Worker returns `margin_microusd: null`. The page then draws the margin and the top-up spend and cost (which come from the charge join) as Not recorded, not `$0.00`; tokens given and included in plans, which do not need the join, stay. A missing field is `null`, not a defaulted number.
- **Real values draw as themselves.** A zero margin is `$0.00`, a negative one is `-$1.25` toned as a loss, and sub-cent amounts are not rounded away (`formatMicro`, exact, in `lib/money.js`).
- **Included-plan usage is its own figure.** It is shown beside the spend and is never added into it or the margin: the plan's price already pays for it. Admin-licence usage stays excluded, as D762 defines it.
- **Stale copy removed.** "no price is recorded to subtract the cost from" and "the cost of a call is recorded, the price charged for it is not" are gone (the latter row left the rail). The per-branch margin is still Not recorded, now for its real reason: AI spend is not tied to a licence (U1). The old assertions that pinned the margin to `null` were updated.

### Verified

`revenue_token_margin_5027` (8): positive, zero, negative and sub-cent margins; every run predating 493; `billed_available=false` with the cost kept; an unreadable usage log; included-plan usage not in the spend; missing fields not defaulted; the stale sentences absent; no arithmetic on the margin in the browser. Mutation checked: the margin pinned to null; a null margin drawn as a number; the cost hidden when the margin is unreadable; the spend drawn as zero when all runs predate 493; included-plan usage added to the spend; the stale sentence put back. The Worker side is `admin_revenue.test.ts` (unchanged).
