`GET /api/fund-admin/ask?prompt=<key>&fund=<id>` uses the same HQ Admin,
support-session and branch gates as the console. The overview's read audit
must succeed before figures. Only a fund in that administered scope can be
read in detail. The pure service under services/ai takes plain snapshots;
the route owns bindings, authorization and existing reads. There is no model,
quote, usage charge or financial write. Existing read audits still occur.

Every answer carries its source as-of date, exact recorded facts and one
existing-screen link, plus the canvas's prepares/explains/navigates sentence.
Unreadable sources or truncated ledgers never become zero or no-overdue
claims. No recorded fund is Not recorded. With multiple funds, detail tasks
ask for a fund instead of guessing one. Dates and amounts are not invented.

The Calls tab consumes `new=1` only after a fund and an allowed preview act
are known, opens its existing dialog once, and removes the flag. The dialog
is keyed by fund so a new fund cannot inherit another fund's typed amount.
The existing Issue flow and Super Admin gate remain in place.
