## D6472 — The test READMEs list no files, and per-part paragraphs live in their decision files (#6472)

- **Status:** built. Part of #5600 (plan key B5). Builds on D6465 (the
  `<!-- index: none -->` marker) and D5615 (a later part writes its own
  `D<n>-p<k>.md`).
- **Why:** GitHub's merge ignores the README `union` rule, so every appended
  README row or paragraph is a conflict on the PR page. After the decisions
  and scripts indexes, the most-edited READMEs in the last 396 commits were
  `frontend/test/README.md` (24 commits; the folder holds 1,874 files, the
  table had 63 rows), `cloudflare-worker/test/README.md` (17, prose appended
  at the end), `frontend/src/pages/admin/contracts/README.md` (16),
  `frontend/tests/visual/README.md` (11) and
  `frontend/src/pages/portfolio/README.md` (four latent pairs, each appending
  a "D4817 part N" paragraph).

### What changed

1. **The five READMEs carry `<!-- index: none -->`.** Each now says what the
   folder is for, how to run it and the rule for adding to it, and keeps its
   conventions. None names a file in a row, a list item or a paragraph of its
   own.
2. **What a row said about a file is in that file's header comment.** Every
   table row, list item and paragraph of the three test READMEs that described
   one test, spec, seed or helper was added to that file's leading comment,
   labelled `From <README> (moved by #6472):`, after whatever the header already
   said. A paragraph that described several files (the D1528 agent-engine
   world, D1604's editor suites, D781's whole-app render) went to each file it
   names; a decision paragraph that named no file went to the suites it means
   (D1123's Lab suites, D1174's use-of-funds and financial-integrity suites,
   D1231's KYB suite, D1456's three suites). The per-file bullets of the
   portfolio README went to those components' and stylesheets' headers the same
   way. Only comments changed in those files: no test code, no source code.
   `fixture.json` takes no comment, and `__screenshots__/` and `fonts/` are
   folders, so the visual README's prose says what they hold.
3. **A per-part paragraph is in its decision file.** Each `D<n> part <k>` (or
   `D<n> (#n) …`) paragraph of the portfolio and contracts READMEs was appended,
   unchanged, to its decision as a short list headed `Moved here from <README>
   by #6472 (D6472)`: `D<n>-p<k>.md` where that file exists (D4817 parts 1 to
   10, D4811 part 21, D5050 part 2, D6907 part 2), otherwise `D<n>.md` (D647,
   D713, D717, D758, D4563, D4811 part 1, D6208, D6221, D6222, D6227, D6867,
   D6888). D4811 parts 2 to 20 were recorded as sections of `D4811.md`, which
   cannot grow by 19 paragraphs under D6466, so each got its own new
   `D4811-p<k>.md`, headed `## D4811 part <k> — … (#4811)`, pointing at its
   `D4811.md` section and holding the paragraph. Every append stays within
   D6466's ten lines and adds no heading. The two READMEs keep one stable
   sentence that points to the decisions folder.
4. **The guard.** `scripts/check-folder-docs.mjs` rule 6 already failed a table
   row naming a file in a marked README (D6465). For an `index: none` README it
   now also fails a list item or a paragraph that opens with one of the
   folder's files (`perFileNotes` in `scripts/lib/folderFiles.mjs`) and a
   paragraph or item that opens with a decision and its part, issue or colon
   (`partNotes`: `D4817 part 9 …`, `D4811 (#4811) part 7:`, `D717: …`), naming
   the header comment or the `D<n>-p<k>.md` to write instead. A file or a
   decision named inside a sentence, or on a wrapped line, is not one, so a rule
   can still point at a helper. `index: generated` READMEs (`scripts/`, #6470)
   are held to rows only, as before.
5. `AGENTS.md`'s README rule names the new failure.

### Verified

- `scripts/lib/readmeNotes.test.mjs`: the five READMEs are marked and pass;
  copied into a throwaway repository, each folder gains a fixture file and

  list item and a part note fail with the file or decision to use; two branches
  that each add a test and a part file merge cleanly with `git merge-tree` and
  merge attributes off, and the same branches appending a row and a part
  paragraph to the README conflict. `perFileNotes` and `partNotes` are tested
  against wrapped lines, fenced code and mentions inside sentences.
- A relocation audit (run for the PR, output in its description) re-read the
  five READMEs on the base and found every moved row, item and paragraph at its
  new path, and every base line either kept in its README or inside a moved
  paragraph.
