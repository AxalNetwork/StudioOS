### 1. The slide model (`services/decks/slideModel.ts`)

**What a card carries.** A card keeps its fielded shape: `title`, `fields`, `spec_id`, `method_id`, and so on. It gains:

| Key | What it holds |
| --- | --- |
| `layout` | one of the twelve layouts (PD8) |
| `notes` | the speaker notes, at most 4,000 characters |
| `background` | `{ color, image_url }`: this card's background (PD8) |
| `blocks` | what sits on the card's grid (PD8b), at most 24 |
| `binding` | a binding for the whole card, as D896 already reads |

A field keeps its own `binding` too.

**The grid.** Every card is a 12 × 6 grid. A block is `{ id, kind, grid: { c1, c2, r1, r2 }, binding?, … }`:
- the range is inclusive: columns 1–12, rows 1–6, `c1 ≤ c2`, `r1 ≤ r2`;
- no two blocks on a card share a cell.

**Block kinds**, from PD8c, plus the metric tile from PD1:

| Kind | Its own fields |
| --- | --- |
| `text` | `style` (heading, paragraph, list) and `text` |
| `chart` | `chart_type`, `series`, `range` (3m, 6m, 12m, all), `previous`, `labels` |
| `graphic` | `graphic`, `ratio` (1x1 or 2x2) |
| `image` | `image_url`, `alt`, `tag` (illustration, photo, screenshot, logo) |
| `video` | `provider`, `video_id`, `url`, `poster_url`, `ratio` (16:9 or 9:16), `title` |
| `audio` | `url`, `label` |
| `link` | `url`, `label` (the Link button) |
| `metric` | `label`, `value`, `binding` |

- **Chart series.** Each series is a bound one (`binding`) or a typed one (`points`: up to 60 `{x, y}`, PD9's Typed series).
- **Chart types (PD9b):** line, columns, stacked, percent_bar, ranked_bars, funnel, cohort_heatmap, timeline, metric_tiles, comparison_table, waterfall, nested_bars.
- **Metric tiles.** A tile with no figure stores `value: null`, which every reader shows as "Not recorded". It is never 0.
- **Links.** Every image, audio, link and poster URL passes `sanitizeImageUrl`: https only, never a private or loopback host.
- **Video links** are read without a fetch. Only `youtube.com` (watch, shorts, embed), `youtu.be` and `vimeo.com/<id>` are accepted, each rewritten to its canonical URL. A host that merely starts with `youtube.com` is refused.

**The twelve layouts** are presets of the grid, each a list of blocks: Title, Statement, Two columns, Metric tiles, Chart + text, Timeline, Team grid, Quote, Comparison table, Image + text, Full-bleed image, Appendix table. Choosing one fills the grid; the stored card keeps both the layout id and its blocks, so a layout can change without losing what was placed.

**Bindings** are D896's five fields, kept by `sources.ts`'s `sanitizeBinding` (#2731), the one rule for a card, a field, a block and a chart series: `source_key`, `record_ref`, `as_of`, `grade` (Measured, Reviewed, Sourced, Stated) and `snapshot_hash` (24 hex characters). `bindingsOf` in `sources.ts` now also reads each chart series, at `block:<j>:series:<k>`, so `POST /api/decks/:id/refresh` compares a chart's series as it compares a tile.

### 2. Two entry points, on purpose

- **`sanitizeModel`** copies what is valid and drops the rest. Every path into `sanitizeSlides` uses it: generate, apply-method, autofill, restore, the export and the save. A version saved before D898 (fielded slides, no layout, no blocks) therefore still opens unchanged, and a stored card with an unsound block opens without that block.
- **`modelProblems`** runs first on `PUT /api/decks/:id`. A save the model cannot keep whole answers 400 with `code: 'SLIDE_MODEL'`, the first sentence as `error` and every one as `problems`, and writes no version. A save is refused rather than trimmed, so no block is lost without the founder being told.

  The sentences name the card and block:
  - an unknown layout;
  - notes that are too long;
  - more than 24 blocks;
  - an unknown kind;
  - a range off the grid;
  - an overlap;
  - a video that is not YouTube or Vimeo;
  - a link that is not https on a public host;
  - a binding that is not a source.

### 3. What a version records about itself (migration 539)

| Column | Holds | Before D898 |
| --- | --- | --- |
| `audience` | PD3's audience: angel, pre_seed_fund, seed_fund, series_a_fund, strategic, grant, other | NULL, "Not recorded" |
| `round_ref` | the `raise_rounds.uid` it was written for; a save names only a round of the same venture | NULL |
| `theme_json` | PD8's theme: `{ kind: brand / neutral_light / neutral_dark, background }` | NULL, the brand kit |
| `content_hash` | SHA-256 of the slides and theme as stored | NULL |

`created_by` was already stored, and is now returned as `by: { id, name }`.

**Inheritance.** Each of these is the version's own, and a save that does not name one keeps the version's value:
- a restore keeps the restored version's audience, round and theme;
- a kept "Fill from project" proposal keeps those of the version it was proposed over.

**Reads.** `GET /api/decks/:id` and `GET /api/decks/by-project/:pid` return `audience`, `round: { uid, name }`, `theme`, `content_hash` and `by`.
- Names are read in a separate lookup. A lookup that fails leaves a name null; the version itself still reads.
- **Where 539 has not run**, `ensureDeckVersionColumns` (`services/decks/deckVersionColumns.ts`, which imports nothing) adds the four columns.
  - Both runtime creators of `pitch_decks` await it: `routes/decks.ts`'s `ensureSchema` and the advisor's deck-draft seed in `services/advisor/writeRouter.ts`.
  - Whichever bootstrap runs first, the columns exist (`check-schema-pair-drift`).
  - That seed rewrites a version's slides in place, so it also clears that version's `content_hash`, which no longer holds.

**Studio.** PD2's versions table (`PitchStudio.jsx`) shows Audience, Round and By. A version from before 539 shows "Not recorded" for each.

**Logging.** Every save, restore and keep still writes its one `raise.pitch-deck` activity row (D691 decision 12): "Deck saved", "Deck version restored" or "Deck proposal kept". It never carries a figure or a block's words.

### 4. What leaves the venture

**The share link and the print export.** `GET /api/decks/share/:token` (the investor's read) and `GET /api/decks/print-export/:token` (the headless PDF) answer through `publicDeckOf`:
- they carry the cards, their blocks and the theme, because the cards render on it;
- they drop each card's `notes`, and the version's `audience`, `round`, `by` and `content_hash`.

**Speaker notes in an export.** Notes reach a file only when the founder asks: D901's HTML export takes `notes: true`. Until this model, `sanitizeSlides` dropped `notes`, so that option always printed "No notes on this card."

### 5b. The bound charts (group C: PD9, PD9b, PD9c)

**The series (`services/decks/chartSeries.ts`).** A chart plots dated series from stores StudioOS keeps over time. Nothing is typed into the deck: "To chart a new figure, record it in its module first."

| Series | From | One point per |
| --- | --- | --- |
| MRR, ARR, Churn, Paying customers, monthly | `project_metrics`, Stripe's snapshots | month, the newest snapshot of that month |
| Typed MRR, Typed ARR, Typed Churn, Typed Paying customers | `project_metrics`, the founder's typed snapshots | month |
| Interviews per week | `discovery_interviews`, held ones | week (Monday), first week to last |

- **Stripe's and the founder's typed snapshots are two series**, never blended, so each keeps its own Source and grade: Connector · Measured against Typed · Stated.
- **A month with no snapshot is left out**, never a 0. A week with no interview between the first and the last is a real 0, because the count was taken.
- **Interviews** are Measured only when every interview was recorded, else Sourced, as D896 grades the count.
- **A series' binding** is D896's five fields:
  - `source_key` is the series key (`grow.mrr.monthly`, never a slot key);
  - `record_ref` is the newest row behind it;
  - `as_of` is its last point's day;
  - `grade` comes from `sourceAndGrade`;
  - `snapshot_hash` covers every point.

**The reads (`routes/deck_sources.ts`, mounted before `decks`):**
- **`GET /api/decks/chart-series?project_id=`**, owner-checked like every deck read, answers:
  - every series with its points, Source, grade and binding fields; `not_recorded` with no points, or `unreadable`;
  - `types`: how many of the series each of the twelve chart types can draw, and the reason for a type with none:

| Type | Needs |
| --- | --- |
| Line, Columns, Waterfall | a series with two or more points |
| Stacked columns, 100% bar | two series in one unit |
| Metric tiles | one recorded figure |
| Ranked bars, Funnel, Cohort heatmap, Timeline, Comparison table, Nested bars | data no dated series gives yet (categories, stages, churn by month joined, milestones, Research's companies, market sizes), each with its sentence |

- **`POST /api/decks/:id/refresh`** reads each bound chart series from its own store and compares it by its snapshot, so a new month marks the card stale. It still writes nothing.

**The editor (`ChartTools.jsx`, `chartModel.js`).** `PitchEditor.jsx` only wires these in.
- **A chart block is drawn from its bound series** through `ui/Charts.jsx`, with each series' source chip always on: its Source, module, as of and grade, and the Typed marker on a typed series.
  - It draws its points up to the binding's `as_of`, so a saved version never shows a later month (Keep as of).
  - It draws them in its range: 3, 6 or 12 months back from today's month, or since the first record.
  - A missing month is blank on a line and left out of a stacked column, never drawn as 0.
  - Types map to the shared charts: a line or several, columns or grouped columns, stacked columns, a 100% bar of the last values, waterfall moves as diverging columns, and metric tiles.
  - Some states are drawn in words: a chart whose series the catalogue does not plot (part 5's Eadwyn charts over slots) shows its labels and says so; a range with no point says so.
- **PD9c, the chart toolbar.** Selecting a chart swaps Eadwyn's bar for Change type, Series, Range, Data, Labels and Remove.
  - Change type opens the twelve types on the chart; a type the chosen series cannot fill is greyed with the reason.
  - Remove opens the remove dialog, as every block's does.
- **PD9, the Data popover.** Each series shows its source and cadence, the range, the previous period, its as of and grade, and the newest value.
  - When the store has moved past the binding, it reads "Changed since [day]", with Refresh and "Keep as of [day]".
  - Refresh moves the binding, and the chip with it, to the newest snapshot.
- **PD9b, the chart library**, a centred lightbox opened from Chart library under the card or from Series on a selected chart:
  - the twelve types, each with "Fits [n] of your series" or its reason, greyed when nothing fits;
  - the charts already in the deck, to reuse;
  - only recorded series, and only those in the same unit as the ones already chosen;
  - the range;
  - the previous period, dotted, for a single line only;
  - Label the last value;
  - the source chip, always on;
  - a preview on the card's colours.
- **Insert chart** places the chart at the first free 8 × 4 range, else 6 × 3, else says the card has no room. From a selected chart, the same button reads Apply.
- **Every change waits for Save**, which lists it and writes one version with the new bindings.

### 5c. Versions and compare (group D: PD15)

**Where.** On the studio's Decks tab (`/raise/pitch`), every version but the current one has Compare in the versions table (PD2). It draws that version beside the current one (`VersionCompare.jsx`, with its rules in `compareModel.js`). On a phone the table stays a list, with no compare, as the canvas draws it.

- **The columns:** the older version on the left, the current one on the right. Each card shows its number and title, from its own title or its first heading block.
- **What changed** is read card by card, by position. A card is changed when its stored shape differs (fields, blocks, bindings, notes, layout or background), or when only one version has a card at that position. Changed cards are outlined, and the count reads "[n] changed", or "No card changed".
- **Each version is read on its own** (`GET /api/decks/:id`). A failed read says so with Try again and blanks nothing else.
- **"Restore vN"** opens a dialog first:
  - "v[next] is saved with vN's cards, notes, theme, audience and round, and becomes the working deck."
  - "v[current] stays in Versions. Its shared links keep showing v[current], as it was when they were made."
  - "Nothing is deleted."

  Confirming calls the existing `POST /api/decks/:id/restore`, which saves that copy as a new version. The studio then reads its versions again. A refused restore shows its sentence in the dialog and changes nothing.
- **An admin compares, with no Restore**, as everywhere in the studio.

### 8. Amendment for #3658 (S22, 2026-10-29): the deck design system

S33's ruling on #3658 for the owner, 2026-10-29: extend D898 rather than take a new number, and keep main's ids as the v1 contract. "Gamma-like" names the quality target the owner gave, not a claim of parity.

**8.1 The contract (v1).** The layout ids are `slideModel.ts` `LAYOUT_IDS` (PD8's twelve), the block kinds `BLOCK_KINDS`, and the theme kinds `THEME_KINDS` (`brand`, `neutral_light`, `neutral_dark`). None is renamed or duplicated. What is added is optional and validated: a deck saved before it reads the same, and a reader that does not know it draws what it drew before. #3659 (story and composition) and #3660 (visuals) consume this; neither edits `slideModel.ts`.

**8.2 Tokens** (`services/decks/designSystem.ts`, `DESIGN_SYSTEM_VERSION` 1):
- **The slide:** 1920 × 1080. The 12 × 6 grid sits inside 112px side margins, 96px top and 88px bottom, with a 24px gutter (`boxOf`).
- **Type** (`TYPE_SCALE`): display 104, heading 64, subheading 40, paragraph 32, list 30, metric 72, metric label 24 and caption 22. Nothing is set under 22px. Families: Space Grotesk for display, Inter for body, Roboto Mono for figures.
- **Colour roles:** ground, surface, ink, muted, hairline, accent, accent ink, positive and negative, with a six-colour chart palette, per theme.
  - `themeProblems` holds every theme to 4.5:1 for body text and 3:1 for the accent and chart marks (WCAG AA), with six distinct chart colours.
  - The three themes pass.
- **Image treatment:** corner radius and the default background overlay, per theme.
- **Brand kits** (`themeTokens('brand', kit)`): the kit's background, ink, accent and secondary replace the brand theme's, each only where it stays legible.
  - A colour left out is named in `adjustments`, so the founder is told.
  - The neutral themes ignore the kit.

**8.3 Budgets and fit.**
- **Where the budgets come from:** each layout's text budget is its range's lines at its style's size and leading, times the characters a line holds. An average glyph is taken as 0.52em.
- **Density caps:** whatever the space, a paragraph holds at most 280 characters, a heading 70, display 90 and a list 320.
- **Charts and tiles:** a chart reads at most six series and twenty-four points. A metric tile needs two rows for its label, figure and source line, and its figure fits its width.
- **`LAYOUT_NEEDS`:** says what each layout needs from a card's records, and where it falls back:

| Layout | Needs | Falls back to |
|---|---|---|
| metric_tiles | two figures | statement |
| chart_text | one bound series | metric_tiles |
| timeline | three ordered steps (dated objectives, or allocation lines) | two_columns |
| team_grid | two people and two photos they agreed to share | two_columns |
| comparison_table | two recorded rows | two_columns |
| image_text, full_bleed_image | one image | two_columns, statement |

- **`ROLE_LAYOUTS`:** gives each card role its layouts, best first. **`chooseLayout(role, evidence)`** picks the first one the card's evidence meets. The evidence is always counted by code, never by a model. A quote layout is chosen only when a recorded customer quote is part of the evidence.
- **`fitProblems(slides)`:** names, per block, text that overflows its own range, a figure too long or a tile too short, too many chart series or points, and too many diagram steps for their width. A renderer that keeps these sizes cannot overflow a block that passes.

**8.4 The diagram** (`services/decks/diagramModel.ts`):
- **Shape:** an optional, versioned `diagram` on a `graphic` block: `{ v: 1, type: timeline | flow | cycle | matrix, items: [{ label, detail?, date?, binding? }], axes? }`.
- **Rules:** labels are text the founder edits, with at most eight steps. A timeline item's date is a day or a month. An item placed by a record keeps its D896 binding. A matrix has two named axes and four items.
- **Saving:** `modelProblems` refuses an unsound one with a sentence, and `sanitizeModel` drops it. A graphic without one reads as before.
- **Not a picture:** a diagram is an editable element, never a picture of one. A figure stays a metric or a chart.
