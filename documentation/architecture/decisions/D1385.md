### 1. The record (`integrations/mcpProviders.ts`)

`MCP_PROVIDERS.posthog`:
- **Server:** `https://mcp.posthog.com/mcp`; every endpoint must sit on `posthog.com`.
- **Scopes:** the six read scopes the plan names (`organization:read`, `insight:read`, `query:read`, `experiment:read`, `survey:read`, `feature_flag:read`).
  - PostHog's identity scopes (`openid`, `profile`, `email`) ride every authorize, so they are accepted too.
  - Any other scope in a grant, a write scope above all, is refused with `scope_refused` and revoked.
- **Tools:** the 19 read tools in #2409's table.
  - No `*-actors` person list, no `execute-sql` (decision I), no `exec`, no write tool.
  - `write_tools` is empty.
- **Fixed headers:** `x-posthog-read-only: true` and `x-posthog-mcp-mode: tools`. Read-only mode makes PostHog drop its write tools; tools mode registers each tool by name, so the allowlist is what is offered.
- **CIMD:** `https://axal.vc/api/integrations/mcp/posthog/client.json`, served by D1080's route.
  - The document declares PostHog's scope ceiling as `com.posthog.scopes`, through a new optional record field, `cimd_fields`.
  - A provider's field can never replace one of the document's own fields.

### 2. A connection's own header (`integrations/mcpClient.ts`)

- **The rule:** a record may name headers a connection sets for itself (`connection_headers`, each name with its own pattern). PostHog names one, `x-posthog-project-id`, digits only.
- **The session refuses, before any request:**
  - a connection header the record does not name;
  - one off its pattern;
  - one standing in for a fixed header, so read-only mode stays the record's.
- **Before this,** any safe header was accepted. No caller passed one, so nothing else changes.

### 3. The reads (`services/posthog/reads.ts`)

- **One session path.** It is the only file that opens a PostHog session, and every allowlisted tool has its typed read.
- **One project.** `posthogReadsFor(env, row, { projectId })` pins the venture's linked project with the connection header. Without one, only the organisation and project lists are meaningful.
- **Checked before sending.**
  - An id is letters, digits, `-` and `_`; a project id is digits.
  - A query read sends its own kind only: `TrendsQuery`, `FunnelsQuery`, `RetentionQuery` or `LifecycleQuery`.
  - Anything carrying HogQL or a free query string is `bad_query`.
  - The web overview takes a date or a relative window only.
- **No person leaves the file.** `scrub` drops these at any depth before anything is returned:
  - `distinct_id` and `session_id`;
  - person, persons and actor fields;
  - emails and IP addresses.

  A survey response keeps its answers and its time, never who gave them.

### 4. "Your PostHog projects" (`routes/posthog.ts`, migration 657)

- **`posthog_project_links`** holds one row per venture (`project_id` UNIQUE). It goes with its connection (cascade on `integration_id`).
- **`GET /api/connectors/:uid/posthog-projects`** returns:
  - the ventures in the companies this connection is switched on for, that the member may write;
  - each venture's linked project, or the teammate whose PostHog serves it;
  - the member's PostHog projects (`projects-get`). A failed PostHog read blanks only the choices.
- **`PUT /api/connectors/:uid/posthog-projects`** links one venture to a project, or unlinks it with `posthog_project_id: null`. The project must be one the member's own PostHog lists.
  - A venture already linked through a teammate's PostHog is `venture_served`: named, never taken over or unlinked by someone else.
- **Who:** the connection's own member only. A support session is refused, as Notion's routes refuse one.
- **Logged:** the ids only, in `activity_logs`. Never a project name or anything PostHog sent.
- **The SPA:** `PosthogProjectsSection.jsx` on `/account/connectors/posthog`.
  - One row per venture, with its project, the serving teammate, or Choose project.
  - Choose and Unlink each open an in-page dialog that says what changes; a refusal stays in the dialog.
  - Unreadable with Try again; a failed project list blanks only the choices.
  - The client is `lib/api/posthog.js`, one line in `api.js`.

### 6. Departures from the issue

- **The CIMD is not a file under `frontend/public/`.** D1080's Worker route already serves every record's document at the URL the record names, and `mcp_providers.test.ts` holds the record to it. A static file would be a second copy of the same document.
- **`?tools=` is not sent.** The record's resource is matched exactly, and tools mode with the client's allowlist already limits what is offered and called.
- **PostHog's organisation header is not sent.** Pinning the project is enough, and the session refuses that header (it is not on the record).
