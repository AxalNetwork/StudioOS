### Recorded-data limits and canvas departures

- The current stores couple the selected metric and its non-null target on a
  `metric_targets` row. A separate selected-metric-without-target state cannot
  be invented. Focus and target setup open the existing Focus workflow.
- The setup list shows five checkable facts, including the first KPI. It does
  not pretend to know analytics-connection readiness. Connection/KPI health
  presentation remains with #4864; assistant/queue presentation with #4868.
- No channel-decline trend or cross-source change feed is invented from the
  sample. The canvas marks these as needing backend rules. Saved proposals,
  offers, existing failed reads and recorded customer activity are usable now.
- No sample freshness threshold or “On track” pacing is copied. Focus shows
  recorded source/as-of and an actual target comparison, including zero.
- The existing app shell/rail and cycle navigation placement are retained;
  the canonical labels sit in the current header navigation, and Reporting
  is separate. This does not redraw the sidebar or the Distribution subpages.
- An absent/failed part says it could not be read. The empty attention wording
  is limited to the records actually read and does not claim every provider
  is healthy or every source refreshed today.

Verification uses real SQLite for state selection, project isolation, restricted
Mercury visibility, zero values, and source failure; frontend regressions hold
the taxonomy, primary-action gates and honest evidence. Browser journeys cover
sparse/active, retry, Share's existing lightbox and read-only behavior at
1440px and 390px. No production records or provider credentials are used.
