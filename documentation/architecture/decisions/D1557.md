### 1. The route

`POST /api/decks/:id/critic/quote` and `POST /api/decks/:id/critic` take `{ investor_type?, stage? }`, mounted in `routes/deck_critic.ts`.

The answer is ordered for action (deal-breakers first, then by card). It carries:
- `findings`, each with key, source (`rule` or `critic`), severity, code, the card's uid and place, a message and an action;
- the persona and the stage;
- `benchmark`;
- `critic`, the state of the model run: `ok`, `off` or `refused`, with a code and a sentence;
- `cost`.

Only the deck's founders may call it, because the run is charged to them. Nothing is written but one `raise.pitch-deck` activity row naming the version and the count.

### 2. Severities and rule findings

The severities are **deal-breaker**, **will be asked** and **polish**.

The rule findings are free, need no model, and are always answered, even with AI off:

| Finding | Severity | Where it comes from |
|---|---|---|
| A required card missing ("Seed deck with no traction slide") | deal-breaker | A23's `missing_card` |
| A required card with no recorded proof | will be asked | A23's `missing_proof` |
| **A market card with no recorded source** ("Market size has no source") | will be asked | the plan's `market` row; it replaces that card's missing-proof finding |
| **Every "Not backed" figure**, on its card | will be asked | `raise_claims` for this version, unless a founder's note applies |

An unchecked proof is not a finding: the run cannot say the proof is missing.

### 3. The critic's own findings

One run under `deck:critic`, registered in `railOptions/founder.js` as a `reason` option, so its models are the reasoning models. The prompt includes:
- a persona per investor type (`PERSONAS`: angel, pre-seed fund, seed fund, Series A, strategic, grant, other);
- the cards' words and their figures as untrusted data;
- what the rules already found.

A finding is shown only when:
- its severity is known;
- it names a card of the deck;
- it is at most 240 characters;
- it states no number that is not on that card or in a cited benchmark.

The answer counts the rest in `dropped`.

### 4. The family rule

The critic never shares a model family with the writer (dk-auto AUTO-5). This is applied in three steps:
1. **The writer** is the model the deck's build run would use for this founder now: Body's element model when picked (D1503), else the build option's own resolution. It is read by quoting that run, so nothing runs and nothing is held.
2. **The critic** is the first of its option's models whose family (`familyOf`, the `@cf/<org>/` segment, or `anthropic`) differs from the writer's (`criticModelFor`). It is passed to `run()` as the caller's model.
3. **The answer** is checked again (`otherFamily`). A fallback that reached the writer's family is not shown: `same_family`, charged for the run.

When the rule cannot be applied, there is no critic run:
- a writer that cannot be read: `writer_unknown`;
- no candidate of another family: `no_other_family`.

The rule findings still show in both cases.

### 5. Benchmarks (owner decision S)

A finding may cite a stage norm only when the venture recorded one for that stage and investor type (`citableNorms`, D1589). The answer's `benchmark` is then the norms' citation lines.

Otherwise the answer says "No stage benchmark recorded", and the run is told to cite none. A benchmark read that fails says so, and is never shown as none.

### 6. The frontend

The only surface is the Check claims sheet (pd25), with no new panel. `CriticSection.jsx` is mounted in `CheckPanel.jsx`. It shows:
- **Read as an investor**, with the quote's hold;
- the findings grouped by severity, each with **Go to card ›**;
- the benchmark line;
- why the critic did not run, when it did not.

An admin reads the sheet without the section, because the run is the founder's to pay for. The client is `frontend/src/lib/api/deckCritic.js`, re-exported in `api.js`.

New deck's missing-proof strips (pd23) already draw A23's warnings through the live `stagePlan` adapter, and those are the critic's rule findings. A new deck has no version to critique, so New deck is unchanged.

Critic chips on The Grid are out of scope: no board draws them.
