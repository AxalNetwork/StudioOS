- **Canvas:** "Pitch Deck Studio", boards PD16 (present mode), PD17 (export dialog), PD25 (errors) and PD26 frame 2 (the phone viewer).
- **Basis:** `origin/main` at `b0422fef`.
- **Migration:** 537, `deck_exports`.
- **Integration:** D895 (#2674) is now merged. HTML export and the ledger reuse its deck-specific access check; founders export, admins only read, and advisors cannot read deck data.

### 1. Present mode, `/raise/pitch/present`

- **The address** takes `?deck=<id>` (a version is a `pitch_decks` row) or, with only `?project_id=`, the venture's current version. The guard is the studio's, `labRoles(['admin', 'founder'])`.
- **It reads one thing,** `GET /api/decks/:id`, and writes nothing. So a read-only viewer presents too (PD21 draws Present for them).
- **The presenter view (PD16 A):** the current card, the next card, the notes, a timer (`00:04:12`), the count (`5 / 12`) and "Esc to exit".
- **The audience view (PD16 B):** the card full-bleed, "Show sources" off by default, and progress dots.
- **Keys:** ← → (also Page Up / Page Down, Space, Home, End). Esc goes back to the studio. Neither end is passed.
- **On a phone (PD26 frame 2):** the viewer alone, one card, swiping (40 px or more across, more across than down), sources on, dots, and "Swipe for the next card · 5 of 12".
- **A card shows what the version holds.** An unfilled template field and an empty figure read "Not recorded", never the sample and never 0. A card with nothing on it says "Nothing on this card yet."
- **Notes.** Slide JSON has no `notes` until part 4's slide model (#2676). Until then a card with no notes says "No notes on this card." The page reads `notes` as soon as a slide carries it.
- **Sources.** No card records a source yet (the source chips are part 2). So "Show sources" puts "Source: Not recorded" under each figure, rather than leaving the toggle with nothing to do or inventing a source.
- **The Present button** is on PD2's current-deck card, beside Open.

### 2. The export dialog (PD17, PD25)

- **It opens from Export** on the current-deck card. Export is hidden for a read-only viewer.
- **Formats:**
  - **PDF:** today's `BROWSER` print path, `POST /api/decks/:id/export {format:'pdf'}`.
  - **PowerPoint:** today's export, which embeds one screenshot per card. The dialog says "One picture per card", not the canvas's "editable text and charts", because that is what the file is.
  - **HTML:** new (§3).
  - **Google Slides:** drawn but unavailable, with the reason. It is part 10.
- **The options:**
  - **A version picker,** over the venture's versions.
  - **"Include speaker notes" and "Include a Sources appendix",** which apply to the HTML file. The PDF and PowerPoint routes are part 1's to change, so for those formats the dialog greys both options and says that those files carry the cards only, for now.
- **Before the write,** the dialog says what it changes: "This makes a file of v4 and records the export in this venture's history: the format, the version and the file's fingerprint. Nothing is shared."
- **The last recorded export** is shown, from `GET /api/decks/:id/exports`.
- **A failure reads as PD25 does.** For example: "The PDF could not be produced. Try again in a moment. Nothing was shared."
  - This includes a missing `BROWSER` binding. The old editor falls back to drawing the PDF in the browser, but that file would not be recorded, so the studio does not do it.
  - When the ledger cannot be written, the Worker's own sentence is shown: "The export could not be recorded, so no file was made. Try again in a moment. Nothing was shared."

### 3. The HTML file (`services/decks/offlineHtml.ts`)

- **One self-contained file of the version.** It opens offline and asks for nothing:
  - The fonts are inline. These are three of the legal paper's faces: Public Sans 400 and 700, and Space Grotesk 700.
  - Every image is a `data:` URI, or a line saying "This image could not be included in the file."
  - The file's Content-Security-Policy is `default-src 'none'` (images and fonts `data:` only), so a browser would refuse any request the markup tried to make.
- **The route fetches each slide image once.** It runs every image through `sanitizeImageUrl` and then `boundedDownload`:
  - 10 s per image;
  - 2 MB per image, 12 MB in all;
  - at most 40 distinct images.
  - An image is kept only when its own first bytes are PNG, JPEG, GIF or WebP. SVG is refused, because it can carry script.
- **No script but keyboard navigation.** The file has one script, `NAV_SCRIPT`, and the CSP admits it by its SHA-256. Its keys follow the canvas ("use ← → keys", Esc):
  - → / Page Down / Space: the next card;
  - ← / Page Up: the previous card;
  - Home and End;
  - Esc: switch between one card and all of them.
  - Without the script, or in print, every card shows, one per page.
- **The options.** Notes go under each card, with "No notes on this card." where a card has none. The Sources appendix is a last card. It says the version does not record where its figures come from, and names the cards whose fields were written with AI help, which the fields do record.
- **Brand comes from the venture owner's plan, not the exporter's** (bug 9, as part 1's `deckOwnerBrand`). A missing owner counts as the free plan, which carries the footer.
- **The same version and options give the same bytes,** so the ledger's hash names one file.
- **`services/decks/render.ts` was not this file.** It loaded Tailwind from a CDN, and its `renderDeckHTML` had no caller. That function is removed. Its slide types stay, because `pptx.ts` and `decks.ts` use them.

### 4. The ledger (migration 537, `routes/deck_exports.ts`)

- **`deck_exports` columns:**
  - `deck_id`, `version`;
  - `format`: `pdf`, `pptx`, `html` or `google_slides`;
  - `content_hash`: the SHA-256 of the exact bytes handed out, lowercase hex. It may be NULL only for Google Slides, which hands out no bytes;
  - `external_ref`, `created_by`, `created_at`.
- **Every export writes one row before the file is handed out.** When the row cannot be written, there is no file (503 `export_not_recorded`).
- **HTML export** (`POST /api/decks/:id/export/html`) writes its ledger row and one `raise.pitch-deck` `logCycleWrite` row in one batch: `deck_exported`, "Deck exported as HTML". That row names no figure (D691 decision 12).
- **PDF and PowerPoint** remain answered by `decks.ts`. A middleware in `deck_exports.ts`, mounted before `decks.ts`, does the recording:
  - it hashes the file that route answers and writes its ledger row;
  - it sets `X-Content-SHA256` on the response;
  - when the row cannot be written, it holds the file back.
  - Their audit row is D895's fix 11 (`auditDeckWrite(… 'deck_exported' …)` in #2689), so the middleware writes none, and no export gets two.
- **Audit failure boundaries:** HTML audit and ledger writes are atomic. PDF/PowerPoint keep D895's existing route-attempt audit if the downstream ledger middleware withholds the file; the response still contains no file.
- **`GET /api/decks/:id/exports`** lists every export of the deck's venture, newest first (50), with who exported.
- **Access follows D895:** HTML export uses the same exported deck-specific `projectOwned` as PDF/PowerPoint, with `write`. Admins cannot export; they may read the ledger. Advisors cannot export or read the ledger. The export regression uses a real venture-owner founder and checks refusals across all three formats.

### 5. Later export consolidation

- `{format: 'html'}` joins `POST /api/decks/:id/export`.
- The middleware becomes one ledger call inside that route.
- The PDF and PowerPoint options (notes, Sources appendix) are passed to the print template.
- `ventureBrand` gives way to part 1's `deckOwnerBrand`.
