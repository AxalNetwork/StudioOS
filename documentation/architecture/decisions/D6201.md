## D6201 — Failed Portfolio sub-queries are unavailable (#6201)

The analytics distributions read and compliance definition/submission reads reject thrown, unsuccessful and malformed D1 replies with HTTP 503 and the route-owned `{ available: false, reason, detail }` response. A successful empty query keeps its existing success response. The #5847 detail/support changes and #6207 dated basis fields are preserved.

Portfolio retains that explicit failure reason in its unreadable read state. Financial figures render Unavailable with the reason; reporting stays unreadable and offers no chase population. A failed read is never a zero distribution or a claim that a company has not submitted.

The three actual route reads are exercised over SQLite with failure injection at each read (throw, unsuccessful reply, missing results and a missing reply). Model regressions cover dependent figures, reporting and chase rows. Removing each guard and corrupting the reason/metric/reporting/chase handling fails the focused regressions. Full drift and guards must pass on the final head before publication; historical validation is not current-head evidence.

The existing D1057 quarterly-compliance fixture creates the baseline KPI-definition table too. An empty required set is then a successful empty query, rather than an absent-table error concealed by the previous catch-empty fallback. Its reporting-period assertions are unchanged. The full run exposed this compatibility fixture failure, and the isolated before/after proof passes only with the table present.
