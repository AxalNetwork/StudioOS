## D4086 — A round records its securities exemption; publishing a deck reads it from the round (#4086)

- **Status:** built by Claude Code for slot S26, 2026-11-02. Not deployed and not checked live.
- **Issues:** #4086 and #4087, filed twice with the same body by S25 at the owner's request. One PR closes both.
- **Follows:** D1564 (#3811, PR #4072), deck builder v2 D3. Owner decision E = B stands: a 506(b) round never publishes.
- **Migration:** `202611022116_raise_rounds_exemption.sql` (D4106's stamped name).

### 1. Why

D1564 had no column to read, so the founder stated the exemption when publishing and the link kept it (`include_json.publish`). The 506(b) refusal therefore held only against what was said at publish time, not against the round. This decision moves the exemption onto the round, where it is recorded once, as the founder's own statement, and every link reads it.

### 2. The column

`raise_rounds.exemption`: nullable, **no default**, CHECK one of `506b`, `506c`, `reg_cf`, `reg_s` or `other`.
- NULL means not recorded, and reads "Not recorded" everywhere. Nothing is defaulted and nothing is backfilled: rounds on file stay NULL until the founder sets one.
- The list is the issue's proposal for counsel to confirm. Adding an exemption is a migration that widens the CHECK and one line in each of `ROUND_EXEMPTIONS` (Worker `services/decks/publish.ts`, frontend `capRelTabsModel.js`).
- `routes/contacts.ts`' schema self-heal adds the same column, with the same CHECK, on a database that predates the migration, like the round's other late columns.

### 3. Who may publish

Publishing reads the deck's round (`pitch_decks.round_ref`, a `raise_rounds.uid` of the same venture) and ignores any `exemption` the request sends. `roundRefusal`, in order:

| The deck's round | Answer |
| --- | --- |
| none | 409 `round_not_linked` — "Choose the round this deck is for, then record its exemption in Raise." |
| exemption not recorded | 409 `exemption_not_recorded` — "Record this round's exemption in Raise first." |
| 506(b) | 409 `exemption_506b` (D1564's sentence) |
| Reg CF, Reg S or other | 409 `exemption_not_publishable` — "Only a Rule 506(c) round can be published as a page." |
| 506(c) | may publish |
| could not be read | 503 `round_unreadable` |

**Only 506(c) publishes.** The issue names only the 506(b) refusal. But a published deck page is general solicitation, and of the five only Rule 506(c) allows that outright:
- Regulation Crowdfunding confines offering communications to the funding portal (Rule 204 allows only a tombstone notice off it).
- Regulation S forbids directed selling efforts in the United States.
- "Other" says nothing either way.

The safer reading refuses all four until counsel says otherwise. Widening it is a one-line change to `PUBLISHABLE` and `roundRefusal`, and this is an open question for counsel on #4086.

A deck with no round is refused rather than allowed: without a round there is no exemption to read.

### 4. Existing links and a changed round

- **Links published under D1564.** A link published before its round recorded an exemption keeps working: the issue asks that it keep working "but is re-checked against the round once the round records one".
- **The read-time check.** Every reader of a published link checks the round each time through `linkStands`:
  - the share read;
  - the email gate;
  - `/embed/:token`;
  - the preview card;
  - the founder's own publish read.

  A link stands while the round has none recorded, and then only while it says 506(c). A round that cannot be read leaves the link as it was, logged, so a database blip neither opens nor closes it.
- **Recording a different exemption.** When the round write records anything but 506(c) over a different value, it also takes the publish key off every published link of a deck written for that round (`unpublishRoundLinks`):
  - Pitch deck's Activity logs `deck_link_unpublished` (a count, no names);
  - the venture's founders get an in-app notice;
  - the round write answers `unpublished_links`.

  Recording 506(c), or clearing the exemption, unpublishes nothing.
- **An unpublished link.** As with D1564's Unpublish, the link itself keeps opening as the private investor link it was, with its cap, expiry, forwarding and NDA. It is no longer a page: no email gate, no embed, no preview card.

### 5. Where the founder records it

- **Raise › Capital relationships › Commitments › Round settings** (`RoundSettingsDialog`). It gains a "Securities exemption" select: Not recorded, plus the five.
  - The help line says only a 506(c) round's deck can be published as a page.
  - Choosing a value that would take links down shows the warning before Save round. Nothing is written until Save round.
  - The round write already keeps a field the body leaves out, so a client that does not send `exemption` changes nothing.
- **ShareDialog's `PublishPanel`.** The per-link exemption picker is removed. The panel shows the round's name and recorded exemption read-only.
  - When the round blocks a page, the panel shows the Worker's reason verbatim and a link to Round settings (`/raise/capital-relationships/commitments?project_id=…`), and Publish is off.
  - The request sends no exemption.

### 6. Limits

- Round settings edits the venture's active round only (the route's rule since D1193). A deck written for a closed round whose exemption was never recorded cannot be published until that is fixed by hand. The refusal says to record it in Raise, and Raise has no editor for a closed round's fields. This is an owner question.
- The notice goes to the venture's founders: the users whose `founder_id` is the project's. When none can be read, it goes to the person who saved.
