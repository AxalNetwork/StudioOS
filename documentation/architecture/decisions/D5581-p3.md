### 1. Where the bytes live: the existing `FILES` bucket

`FILES` (`studioos-files`, `studioos-files-preview` on preview) is the Worker's general private file store. It
already holds many domains under their own prefixes (`kyc/`, `esign/signed/`, `data-room/`, `deck-images/`,
`learning/videos/`, `governance/`, `agent-compute/`; D5579 §2), and every read goes through a Worker route that
re-checks auth. WorkGraph takes one more prefix there, `wg/v1/t<tenant>/c<company>/sha256/<digest>`, so no binding
is added and `check-wrangler-binding-parity` has nothing new to pair. The single-purpose buckets were not
suitable: `PUBLICATIONS` is HMAC-download exports, `BACKUPS` is object-locked for 365 days (WorkGraph must be able
to delete after retention), and `COMPANY_LOGOS` holds one logo per company.

One caveat to record: `INCIDENT_RESPONSE.md` lists dashboard versioning on `studioos-files` (7 years of previous
versions), but R2 has no object versioning. Checked on 2026-11-14: R2's bucket features are locks, lifecycle rules,
event notifications, CORS, storage classes and access logs, and the bucket's settings carry no versioning field. So
the bucket keeps no previous version. A WorkGraph object the Worker deletes is gone once the delete succeeds, which
is why §5's retention and hold checks run before any delete. A bucket lock rule covering the `wg/` prefix would
refuse that delete instead; none is known, and the operator can check with `wrangler r2 bucket lock list
studioos-files`. The runbook's recovery claim for this bucket is #6428's to correct.

**Jurisdiction.** `wrangler.toml` declares `FILES` with no `jurisdiction`, and the branch registry's
`residency.r2_jurisdiction` (`scripts/lib/branchConfig.mjs`, `eu` or `fedramp`) is not rendered into any Worker
var. So the bucket guarantees no residency, and `WORK_GRAPH_BLOB_DEPS.jurisdiction` is `null`. A residency of null
asks for nothing; any other residency must be an R2 jurisdiction equal to the bucket's. On HQ today every `eu` or
`fedramp` request is refused (`residency_mismatch`) rather than stored somewhere it was not promised.

### 2. Blobs (`workGraphBlobs.ts`)

- **`putVerified`.** Hashes the bytes, then heads the digest's key. An object whose size and R2 SHA-256 checksum
  match is reused (no write). Otherwise the bytes are put with R2's `sha256` option, so R2 itself refuses a body
  that does not hash to the digest (a torn upload never lands), and the returned object's size and checksum are
  checked again. The blob is recorded in `work_graph_blobs` in one batch with its audit row. A corrupt object at the
  key is replaced with the verified bytes.
- **Custom metadata** carries `wg`, `digest`, `size`, `tenant`, `company`, `access`, and a `preview` (at most 200
  characters) only for `public` and `internal`. A confidential or restricted put with a preview is refused
  (`preview_forbidden`). A restricted put that reuses an object still carrying a preview rewrites it without one.
  `readRevisionMetadata` returns a preview only while the asset's current class allows it. No D1 column holds
  content or a preview.
- **`verifyBlob`.** A head: size, R2's checksum, the metadata digest. Objects up to 8 MiB, and any object with no R2
  checksum, are also read back and re-hashed; a larger object with no checksum is `digest_mismatch`
  (`unverifiable`). Absent is `missing_bytes`.
- **Limits.** 100 MiB per put (held in Worker memory; multipart has no caller yet) and 100 GiB of live bytes per
  tenant, read before the write and held again inside the ledger insert, so two concurrent puts cannot both pass;
  the loser's new object is deleted.
- **Offline.** `setRevisionOffline` (a person; audited) flags a revision `offline`: its bytes are refused
  (`offline`), its metadata stays readable with no preview, and it cannot become a head. Clearing it restores both.

### 3. The head swap (`advanceHead`)

Before the CAS batch, after part 1's checks:

1. **Fence.** When `WORK_GRAPH_LEASES` is `on` and the caller brings `fence: { value, unit, capability }`, part 2's
   `assertFence` runs with the actor as holder. `no_capability` stays itself; every other lease refusal (a released
   or expired fence, another holder's fence, another unit) is `stale_fence`, with the lease's own code in `ids`.
   With leases off, or with no fence, nothing changes: optimistic concurrency alone, as in part 1. A lease still
   never authorizes.
2. **Integrity.** Only for WorkGraph-held bytes (`r2_object` / `FILES` / `wg/v1/…`): the residency must fit the
   bucket, the key must be this asset's tenant, company and digest, and `verifyBlob` must pass. Otherwise
   `residency_mismatch` or `bytes_unverified`. Bytes a domain holds (a D1 row, Git, an e-sign envelope, another R2
   prefix such as `deck-images/`) are pointed at, never copied, and are verified by their domain's own service when
   its adapter computes the digest (D5579 §1, §5 step 2); the swap does not re-read them.
3. **Inside the CAS.** The UPDATE also requires no live row in `work_graph_revision_flags`, so a revision reconcile
   flagged between the read and the write still cannot become the head. A refused swap reads the flags to say why
   (`offline`, `residency_mismatch` or `bytes_unverified`).

Each of these refusals is an `advance_refused` row in `work_graph_events`, like part 1's own. `createRevision` also
refuses a WorkGraph key that is not the asset's own tenant, company and digest (`malformed`, `blob_key`).

**Cost.** Part 1's statement counts are unchanged for every call that touches no bytes and no lease (the flag check
is part of the existing UPDATE). `Cost` gains two optional counters that appear only when used: `r2ClassB` (heads
and gets) and `doCalls`; the lease audit's statement and batch are added to `d1Statements` and `d1Batches`. A first
head move of WorkGraph-held bytes costs 6 statements in 1 batch plus 2 R2 reads.

### 4. Tenant limits

`WORK_GRAPH_LIMITS` gains `maxAssetsPerTenant` (10,000) and `maxVersionsPerTenant` (250,000), held inside the
asset and revision inserts as part 1's per-asset cap is, so they hold under concurrency. A refusal is `tenant_limit`
with the limit's name, and a `limit_refused` row in `work_graph_integrity_events` (part 1's event table has a fixed
action list, and its migration is applied). Bytes per tenant are in §2. Every call takes an override.

### 5. Reconciliation (`workGraphReconcile.ts`)

`reconcileWorkGraph(env, ctx, { scope, graceMs, retentionMs, limit, cursors, dryRun })` acts on one company; only a
company-wide caller of that company may run it. It is bounded (`limit` rows of each kind, at most 500, with
cursors) and writes all its findings in one batch. A dry run reports and writes nothing. Nothing schedules it yet:
every cron job is a dynamic import inside `index.ts`'s `scheduled()`, a frozen hub file (D5615), and
self-registering cron tasks are a listed follow-up of #5615 (`HUBS.md`). A scheduled caller must also walk the
companies that hold WorkGraph assets, which is that wiring's job.

| Case | What it does |
|---|---|
| Half-uploaded R2 | A live revision of WorkGraph-held bytes older than the grace period (default 24 h) that fails `verifyBlob` is flagged `bytes_missing`; the swap never advances it. Verified bytes later clear the flag (`bytes_restored`). |
| Orphan blob | An object under the company's prefix that no revision names, older than the grace period, is deleted and its ledger row marked `deleted_at`, unless a company hold is in force (`deletion_blocked`). |
| Deleted asset | A tombstoned revision's bytes are deleted once its tombstone is older than the retention period (default 30 days; there is still no retention policy, D5579 §5 step 5), unless the same bytes belong to a live or a newer-tombstoned revision (`shared`, content-addressing) or a revision, asset or company hold covers them (`held`). Its revisions get `bytes_deleted`, which a trigger makes permanent: the deletion tombstone. |
| Crashed DO, expired lease | The object expires its own leases and never reuses a fence (part 2). Reconcile only audits a grant whose expiry (after renewals) passed with no release or expiry row, once (`lease_expiry_observed`). It never calls the object. |
| Cross-region | A revision whose residency the bucket cannot hold is flagged `residency_mismatch`. |
| Stuck effects | Claimed effects whose claim lapsed are counted; the next drain takes them over. |

**Holds.** `placeHold` / `releaseHold` (a person; audited) put a legal hold over a company or one asset in
`work_graph_holds`. Part 1's per-revision `legal_hold` still blocks tombstoning; these block byte deletion,
including orphans, which have no revision to hold.

### 6. The bounded effect outbox (`workGraphEffects.ts`)

The existing queues were not reused. `JOB_QUEUE` and `AGENT_QUEUE` deliver at least once and are consumed in
`index.ts`'s `queue()` (a frozen hub), with no per-tenant cap and no key per effect. `program_outbox` (D4805) is the
program notices' outbox, with a `kind = 'notice'` row per member and no tenant. So `work_graph_effects` is a D1
outbox:

- **Bounded.** At most 1,000 pending or claimed effects per tenant, held inside the insert (`queue_full`). A drain
  takes at most 50.
- **Idempotent.** One row per (tenant, company, idempotency key). The same key and payload replay; another payload
  is `idempotency_conflict`. A payload holds ids, numbers and flags only (200 characters per value, 2,000 in all).
- **Exactly-once effects, not exactly-once delivery.** A delivery claims the row with a fresh token and a two-minute
  lapse, so two deliveries never run one effect together, and a dead worker's claim is taken over. A handler's D1
  statements commit in the same batch as the `applied` mark, and that batch aborts unless this delivery still holds
  the claim (the audit row's NOT NULL `outcome` is fed by `changes()`). `applied` and `dead` are terminal by trigger.
  An effect outside D1 receives the key and must be conditional on it.
- **Retries.** A failure backs off 30 s, doubling to at most 1 h. After 5 attempts the effect is `dead` (the
  dead-letter state) with its error code, kept for a person. Every outcome is audited.

Wiring a head move to enqueue its re-render effects (`impact.outputs`) is left to the route that exposes the
service, so part 1's head-move batch stays as it is.

### 7. Audit and cost

`work_graph_integrity_events`: puts, reuses, refusals, reads, reconcile findings, deletions, holds, offline changes,
tenant-limit refusals and effect outcomes, with tenant, company, asset, revision, digest, effect, actor (person,
agent run, or `system`), refusal code and the call's D1 statements and R2 Class A and B operations. Ids and digests
only. Append-only by trigger. Every blob, reconcile and effect result carries
`cost: { d1Statements, d1Batches, r2ClassA, r2ClassB }`.

### 9. Rollback

Every service is unreachable without a route. To undo the head-swap checks, revert the `workGraphRevisions.ts`
change: the flag condition and the byte check go with it, and part 1's behaviour returns. Dropping the five new
tables loses only WorkGraph's byte ledger, flags, holds, integrity audit and effects; the objects under `wg/v1/` stay
in `FILES` until deleted by prefix. No domain table or domain prefix is read or written.
