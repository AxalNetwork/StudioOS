## One text per document

Issue #1863 (S13), decided by S1 on 2026-10-18 under the owner's standing rule.
Two PRs: PR 1 is `Part of #1863`; PR 2 moves partner onboarding to its row and
closes the issue. No migration, no data change, no legal text written.

### Decisions

1. **The library row is the document.** A bundled file under
   `services/legalTemplates.ts` is the fallback for its row when the row has
   no body, never a second text. No bundled file is deleted:
   `legal_template_fund_name_d705.test.ts` pins the nine imports, and a
   signed document names its version. This settles D706's "one document has
   two texts" rows.
2. **One spelling-to-row map, beside the routing table.**
   `services/legalDocTypes.ts` holds `LIBRARY_SLUG_FOR` and
   `librarySlugFor(docType)`. Any other value maps to itself. The send and the
   usage fold both use it; `RAW_TO_CATALOG` is gone.

   | Spelling | Library row |
   | --- | --- |
   | `investor_nda_v1` | `investor_nda_axal` |
   | `mentor_nda_v1` | `mentor_nda_axal` |
   | `mentor_disclaimer_v1` | `mentor_engagement_disclaimer` |
   | `partner_msa_v1` | `partner_services` |
   | `nda_3way_founder_investor_axal_v1` | `nda_3way_founder_investor_axal` |
   | `nda_3way_v1` | `nda_3way_founder_investor_axal` |
   | `founder_nda_axal` | `founder_nda_v1` |

3. **What is still sent as the bundled file.** `BUNDLED_SENT_DIRECTLY` lists
   each bundled key a sender still sends as its file, `{ key, title, sender }`.
   - PR 1 holds one entry: `partner_msa_v1`, "Partner Master Services
     Agreement" (L8's name), sent by `routes/partner_onboarding.ts`. PR 2
     empties it.
   - `GET /templates/outside` and `/templates/outside/:key/thumbnail.png`
     list exactly these entries, replacing D717's `key !== doc_type`. The item
     shape stays `{ key, title, doc_type, counted_under: { slug, title } }`.
     An empty list answers `{ items: [] }`, and every other key's thumbnail
     answers 404 without calling `BROWSER` or `FILES`.
4. **The send resolves the row by slug.**
   - `templateBodyFor` returns the bundled body for a `BUNDLED_SENT_DIRECTLY`
     key. Otherwise it reads the store under `librarySlugFor(docType)`, then
     that slug's bundled file.
   - `createAndSendEnvelope` computes `documentType` once and uses it
     everywhere: the envelope records, prints and dedupes under the row's
     slug. The DocuSign call passes it too.
   - The one-pending-send key matches either spelling
     (`x.document_type IN (?, ?)`), so a send pending under an old spelling
     still dedupes. `envelope_created` adds `requested_as` when the spelling
     differs.
5. **The direct renders read the row.**
   - **3-way NDA** (`services/trustEnvelope.ts`): the body is
     `templateBodyFor(env, 'nda_3way_founder_investor_axal')` merged with the
     same six values. A token left throws `unfilled_fields` before any INSERT,
     and the envelope records `nda_3way_founder_investor_axal`.
     `POST /api/trust/intro/request` answers that throw 409
     `template_fields_unfilled` ("The NDA is not ready to send yet: Axal VC
     still has to complete it. Nothing was sent."); any other throw keeps its
     500.
   - **The completion hook** activates the pairwise NDA for `nda_3way_v1` or
     `nda_3way_founder_investor_axal` (`isThreeWayNdaType`). Only the row
     whose `nda_envelope_uuid` is that envelope changes, so a single-signer
     3-way NDA from `/legal/send` touches none.
   - **Deck-share NDA** (`routes/deck_share_actions.ts`):
     - `deckShareNdaBody` returns the merged `investor_nda_axal` row. The
       free-text fallback is deleted.
     - A null body or a throw answers 503 `template_unreadable`; a token
       left answers 409 `template_fields_unfilled`. Neither writes a
       `documents` row or a conversion.
     - The row, the response and `/context` name `investor_nda_axal`.
     - The merge also fills `investor_name` and `investor_email` with the
       viewer, who is the investor signing. Production's row names those
       fields (see "Production").
6. **Partner onboarding sends the Partner Services row, never a blank field**
   (PR 2): `documentType: 'partner_services'` with `refuseUnfilled: true`; a
   field left answers 409 `template_fields_unfilled` and writes nothing but a
   `partner_envelope_refused` audit row naming the fields.
7. **Usage counts each issued document once, under the row it was sent from.**
   - `loadTemplateUsage(sql, strict, keys)`: the store route passes its own
     slugs, so every row reads its real count. The legacy `GET /templates`
     keeps `TEMPLATES`' keys.
   - `catalogDocTypeForRaw` tries the exact value, its lowercase, then
     `librarySlugFor` of each. A spaced slug such as `Subscription Booklet &
     LPA` now matches its row.
   - Partner deals are labelled and counted as `partner_services`, titled
     "Partner Services Agreement — <deal type in words> — <email>".
   - A pairwise NDA or partner deal row carries `envelope_uuid`, and is skipped
     when that envelope is in the same union, so one document is one use.
   - `/templates/:doc_type/usage` uses the same fold and skip
     (`usageRowsFor`), so the drill-down equals the chip.
8. **No free text on these paths.** `renderLegalTemplate(` and
   `getLegalTemplateBody(` are called only by `services/legalTemplates.ts`,
   `templateBodyFor` and the outside thumbnail.
9. **Each PR body shows what each signer will now receive** (below).
10. **Not changed:** which document a partner deal should send for its type;
    the obligation keys; deck-share acceptances in usage; `tos_v1`,
    `privacy_v1`, `founder_nda_v1` and `accreditation_v1`; the store rows, the
    migrations and the bodies.

- **The replay's expectation did not hold.** On a replay of the repo's
  migrations, the 3-way and investor rows equal their bundled files.
- **In production each row is its bundled file plus a header block.** The
  header holds the title, the "Subject to legal review. This template is a
  working draft" banner, a version line and the parties lines. Since D705 the
  bundled `_v2` files carry none of it.
- **So PR 1 changes what these signers receive** by that header and nothing
  else. The owner's call on it is recorded on #1863.
- **Fields.** The header's merge fields are `effective_date` and the parties'
  names and emails: `investor_*`, `mentor_*`, `partner_*`, and the 3-way's
  six.
  - The 3-way and deck-share senders fill theirs.
  - A `/send` of a mentor spelling asks the sender for `mentor_name` and
    `mentor_email`, as a send of `mentor_nda_axal` does today.
- **PR 2's gate passes on production.** Production's `partner_services` row
  needs only `partner_name`, `partner_email` and `effective_date`, all of
  which partner onboarding fills. The three fields the repo's
  `partner_services_v1.md` holds are not in it.
