## D4158 — HQ › AI agents › Roster: persona status, identity and team defaults; values never writable (#4158)

- **Status:** built by S12 (slot S03, taken at the owner's request), 2026-11-02. H1 of #4137 (D4137 §3). Builds on #4117 (the persona catalogue, D4117, merged through #4148) and H5's admin audit (D4163, #4205).
- **Migration:** `202611022304_ai_persona_settings.sql`.

### 1. What HQ may change, and where it is kept

The personas stay code (`services/agents/personas.ts`, D4117): a persona's values, risk and natural fit are computed there and never stored. **`ai_persona_settings`** holds only what a Super Admin may change, one row per persona that has been changed. A persona with no row is offered, wears its catalogue identity, and has no team defaults.

| Field | Who sees it | Rule |
|---|---|---|
| `status`: `offered`, `hidden`, `retired` | the Add-agent gallery, every team | see §2 |
| `name`, `tagline`, `story`, `goal`, `avatar` | every agent card and the gallery, at once | an override laid over the catalogue's words. A rename needs `trademark_checked: true` and a name no other persona shows. Setting the catalogue's own words back clears the override. |
| `default_model_id`, `start_cap_microusd`, `max_cap_microusd` | the gallery (`defaults`) and the team routes | the model must be offered, both caps above zero and at most the platform ceiling, and the start no higher than the maximum |

**Values, risk and natural fit are never writable.** A body that names `values`, `top_values`, `risk` or `natural_fit` is 400 `values_fixed`, before anything else in it is read. Any other unknown field is 400 `invalid_field`, so `personality` and `gender` are not writable either.

### 2. Hidden and retired

- **Hidden:** the persona leaves `GET /api/teams/personas`, and `POST /api/teams/:scope/:id/agents` refuses it with 409 `persona_unavailable`. Teams that already have it keep it, running.
- **Retired:** the same as hidden, and in the same batch as the change every live agent wearing it is paused with `paused_reason = 'persona_retired'`, each with a `paused` event naming the admin. Every run path refuses a paused agent (`agentRun.ts`, `engine.ts`, `loop.ts`, `duties.ts`), so it stops running at once. Pausing withdraws nothing (only removing an agent does), so its open proposals stay decidable.
- **A team cannot resume a retired persona's agent:** `PATCH /api/teams/agents/:uid { status: 'active' }` is 409 `persona_retired` while the persona stays retired.
- **Offered again:** nothing resumes on its own. The team resumes its agent when it chooses, and the resume gate no longer applies. This build chose that over an automatic resume, so that no agent starts spending again without a person on its team deciding.
- The team page says why (`teamModel.js` `pauseWords`): "Axal VC HQ retired this agent. Its open proposals can still be decided."

### 3. Team defaults

The gallery carries each persona's `defaults` (`model`, `start_cap_usd`, `max_cap_usd`, each `null` until HQ sets it), for the Add-agent sheet.

The **maximum holds on the team routes**: adding an agent above it is 422 `cap_above_max`, and so is raising an agent's cap above it. Lowering a cap is always allowed, even for an agent that was above the maximum before HQ set one.

The platform ceiling is `PLATFORM_CAP_MAX_MICROUSD`, the team routes' own `CAP_MAX_MICROUSD` (now imported from the one definition). H4 (#4162) brings the platform maximum and tightens this check when it lands (S1's comment on #4158).

### 4. Reason and audit

- Every write takes a `reason` of 10 to 500 characters, trimmed: 400 `reason_required` or `reason_too_long` otherwise.
- Each change writes one `ai_admin_audit` row (`area = 'roster'`, `subject = 'persona:<key>'`) in the same `DB.batch` as the change, so the two land together or not at all. The row carries the admin, the reason, and the before and after.
- The actions are `persona.offer`, `persona.hide`, `persona.retire`, `persona.rename`, `persona.identity` and `persona.defaults`. One PATCH that changes the status and the identity together writes one row for each.
- A body that changes nothing is 400 `no_change` and writes no row.

### 5. Reads

- **`GET /roster`:** the 16 personas, each with its status, defaults and 30-day usage, and the counts by status.
- **`GET /roster/:key`:** the same row, plus:
  - the teams using it (company › project, by name; removed agents left out);
  - its five most-used skills (runs in 30 days whose agent links the skill);
  - its history (its audit rows, newest first, the admin by name).

**Usage (30 days):**
- `teams`: distinct teams with a live agent wearing it.
- `runs`: runs started.
- `spend_usd`: the sum of charges. It is null when any charge is unrecorded, never a smaller sum, and null when there is none.
- `accepted_pct`: accepted or edited, over decided.
- `failed_pct`: failed, step-lost or halted, over ended.

A count that was read is a count, so a measured 0 is 0. A rate with nothing to rate, or a store that cannot be read, is `null` ("Not recorded"), never 0. No answer carries an email.
