### 2. The one new read

`GET /api/founder/validate/meetings` (`routes/founder_validate_meetings.ts`, `services/channels/callsList.ts`) answers `{ calls, uploads, audio, retention }`:

- **calls:** each Zoom and Meet call as D874's `listMeetings` lists it for the MCP server, plus `transcript_source` (D870: `native`, `whisper` or null).
- **uploads:** each recording the member uploaded (`submitted_via 'upload'`).
- **audio:** for each of those sessions, whether its audio is held, when and why it was removed, and `expires_at`: D877's rule, the newest chunk plus the member's retention, null for "until I delete it".
- **retention:** the member's own setting (`retentionFor`).

Tenancy:
- only the caller's own refs and sessions;
- only on an interview in a company the caller may still write (`canWrite`);
- a company they have lost drops out.

No provider is called. No join link, meeting id or passcode is returned.

**`listMeetings` moved** from `mcp/tools/meetings.ts` to `services/channels/meetingList.ts`, unchanged. Importing the MCP tool module from a route loads `mcp/server.ts`, whose registry reads the tool list before it exists (an import cycle). The tool imports the list from its new home.

### 3. Readings of the canvas, named

- **No "Transcribe with Axal" press.** D870 runs Whisper on its own whenever Zoom saved audio and no transcript (owner question 1 on #2517, built to A). A call that reaches `no_transcript` therefore has nothing Axal can transcribe. MC3's next steps are:
  - "Upload the recording", for `no_transcript` and `failed`;
  - "Try the import again" (`POST /interviews/:id/meetings/:ref/import`), for `failed`.

  While Whisper runs, the call reads "Transcribed by Axal" once it is in.
- **Attach to interview is for Meet calls only.** The Worker attaches a Zoom link only to a video recording that is running (`session_required`). A Zoom row says where to attach it instead: start a video session in Record a session.
- **Attached calls are not in Upcoming.** D875's read lists only calls not yet attached; an attached call is under Calls with its timeline. The canvas drew both in one list.
- **Times.** Only the scheduled time of a call is stored. Ended, Transcript ready and Imported carry no time rather than an invented one.
- **"Sign-in expired".** The setup read cannot see an expired Google sign-in. The Worker's 409 on the upcoming read (`google_reconnect`, `google_not_connected`) draws the Reconnect board.
- **The summary** is shown above the proposals, as the session holds it. It is not a proposal: keeping or editing it stays on the session page (D757), as it does for every session.
- **Rename speaker** renames every passage by that speaker in the call: one `PATCH` per passage on the existing route. "Me" is never renamed, and an unnamed passage is "Speaker ?" (D872).
- **The estimate before an upload** is read from the file's own length on the device, priced at the default model's rate (D872 §3). The Worker charges the true length.
- **The meeting bot's live join** (#2581, #2582) is not on this page: it is not deployed yet.
