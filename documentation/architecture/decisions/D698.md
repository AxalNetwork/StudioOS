### PR 1 — the preferences store, on the Worker

**Why.** The rail's two choices lived in one browser. The model pick was `worker_rail_model:<workspace>:<task>` (`ui/railModelChoice.js`), and the assist mode `assist_mode:<workspace>` (`hooks/useAssistMode.js`). A founder who turned Eadwyn on at a desk found it off on a phone. No table or route held either.

**Migration 465, `ai_rail_preferences`.** One row per member, rail section and router task.

| Column | Holds |
| --- | --- |
| `id`, `uid` | Row id, and an opaque id from `crypto.randomUUID()` |
| `user_id` | The member. `ON DELETE CASCADE` from `users` |
| `section` | The rail's `workspace`, trimmed and lower-cased, as the browser keys already are |
| `task` | A router task for a model row, `''` for the section's mode row |
| `model` | The picked router model id, task rows only |
| `mode` | `'eadwyn'` or `'manual'`, the `''` row only |
| `created_at`, `updated_at` | When the row was written and last changed |

- `UNIQUE (user_id, section, task)` is also the read's index.
- A `CHECK` keeps a mode off a task row and a model off the mode row.
- A row is kept until the member changes it, and goes with the account.
- It is a display preference, like `worker_rail_collapsed`, not a venture write, so no `activity_logs` row is written.

**The routes** (`routes/ai.ts`, under `/api/ai`). Each calls `requireAuth` first, reads and writes the caller's own rows, and takes no user id from the body or the query. Every refusal goes through `refuse()`, and every value is bound.

| Route | Body | Does | Refuses |
| --- | --- | --- | --- |
| `GET /rail-preferences` | none | `{ ok, modes: { <section>: mode }, models: { <section>: { <task>: <id> } } }` | 401 signed out |
| `PUT /rail-preferences/:section` | `{ mode: 'eadwyn' \| 'manual' \| null }` | Upserts the `(section, '')` row; null deletes it | 400 `invalid_section`, 400 `invalid_mode`, 409 `too_many_preferences` |
| `PUT /rail-preferences/:section/:task` | `{ model: <id> \| null }` | Upserts the `(section, task)` row; null deletes it | 400 `invalid_section`, 400 `task_not_pickable` (not a `ROUTE` key with non-empty `alternates`; `safety` has none), 400 `model_not_offered` (writes nothing), 409 `too_many_preferences` |

- **The section** is decoded, trimmed and lower-cased, then must be 1 to 60 characters of letters, digits, spaces, `&`, `·`, `_` or `-`. Every `workspace` the app passes fits, such as "perks & products", and so does every assist-mode key, such as `deck_review`. A path segment such as `../x` is refused.
- **The cap** is 200 rows per member. The count and the write are one statement: the insert runs only while the member holds fewer than 200 rows or already holds the key. Two PUTs at once cannot pass the cap, and an update to an existing key always lands.
- **The router keeps its own check at run time** (`aiRouter.ts`), because a stored pick goes stale when a task's `alternates` change.

**The client.** `frontend/src/lib/api/railPrefs.js` exports `railPrefsApi = { read, setMode(section, mode), setModel(section, task, model) }`, each path written out with `encodeURIComponent`, re-exported by one line in `api.js`. PR 2 wires it into `railModelChoice.js` and `useAssistMode.js` (below).

#### What a card is

`jobsFor(section, module)` returns the module's own jobs where it has them (`MODULE_JOBS`), else the section's (`SECTION_JOBS`), else `DEFAULT_JOBS` (`workspace_explain`, the zone drafts). Names match without regard to case.

| Module | Its jobs |
| --- | --- |

#### The safety finding

The canvas's first sentence, "Llama Guard 3 8B checks every run.", is false, and so is any narrower claim that the guard screens what a member types to Eadwyn. The rail names no guard.

- **The four call sites.** Llama Guard is the router's `safety` task, and only `classifyInput` (`services/advisor/guardrails.ts`) runs it. Four routes call that: `routes/advisor.ts:970` (Studio's profile answers), `routes/advisor.ts:2139` (Studio's explain), `routes/ai.ts:430` (`/api/ai/workspace/explain`, whose client method nothing in the app calls) and `routes/eadwyn.ts:377` (the conversation composer, unmounted since 2026-10-10).
- **Unscreened runs.** Fill proposals, zone drafts (`POST /api/research/drafts`), transcription, interview structuring and Research's answers.
- **Unscreened typed paths.** With no profile question open, Studio sends each message to `POST /api/advisor/tool/auto`, which runs the model with no guard; the onboarding chat (`routes/profiling.ts`) has none.
- **Fail-open.** A guard run that fails lets the text through: `classifyInput` returns `blocked: false` when the router fails and when it throws.
- **What would bring the sentence back:** the guard running on every router call, and failing closed.

#### Usage

- Money is `microMoney`. A cap of 0 draws no bar.
- A failed read is Unreadable with a retry, never $0.00 (D400), and so is a read whose `held_for_review` is not an array (`budgetReadable`, `pages/account/usageModel.js`).
- **Runs paused.** While `held_for_review` lists a hold, the box draws, as an alert, "Runs paused" and "A run cost more than it held. New runs wait while HQ checks the charge." (`AccountUsage.jsx`). Every new run is refused until HQ settles the hold (`reserveAiBudget`).
- **Add tokens** links to `/checkout?ai_topup=1` when the top-up is configured, reads "Top-up not configured" when it is not, and is Unreadable with a retry when the top-up cannot be read (`AiBudgetUsage.jsx`'s checks).

#### The preferences sync (decision 11)

- `syncRailPrefs()` (`ui/railModelChoice.js`) reads `/api/ai/rail-preferences` once per page load. It writes each returned pick into its localStorage key, and each mode into `useAssistMode`'s store through `seedAssistModes(map)`, which notifies the switch. A server row wins.
- A local value with no server row is written up once.
- `writeRailModel` and the mode setter write both. A `model_not_offered` refusal clears the local pick, and `FillProposals.jsx`'s existing `writeRailModel(…, null)` now also clears the server row.
- `readRailModel` stays synchronous, so `FillProposals.jsx` does not change.
- Signed out, or when the read fails, the local values stand and nothing is drawn as an error.
