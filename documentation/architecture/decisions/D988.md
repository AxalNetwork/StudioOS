### 1. The tab (GR7)

`/admin/my-licence/programs` (`pages/subsidiary/licence/ProgramsTab.jsx`, its model in `lib/studioPrograms.js`) shows the following, top to bottom.

- **The rule.** "HQ decides which programs your studio runs, and on what terms. You can ask for a change from this tab or under Requests."
- **Four tiles.**
  - **Programs granted:** the programs in force, granted or paused, "of [n] HQ offers". An offer is a program with a grant row, or one HQ grants and has not granted yet. A switched-off program, one not ready, and Product testing are not offers.
  - **Requests with HQ:** open program requests only, with the first one and its date.
  - **Ending in 90 days:** held grants whose effective end falls in the next 90 days.
  - **Program fees a year:** the recorded fees of held grants, summed per currency.
    - A grant with no fee is counted and named ("1 grant has no fee recorded"), never added as zero.
    - With no fee recorded at all, the tile reads "Not recorded".
- **The nine programs.** Each row shows the program and its purpose, then Status, Your terms, Period, Schedule and Action.
  - **Status** is D984's word.
    - A program the studio asked for reads "Requested · Waiting for HQ since [date]".
    - A granted program that is not in force says what it waits on.
    - A paused one shows HQ's note.
    - **A program with no grant row is "Not recorded", never "Not granted"** (D981 §3).
  - **Schedule** is D1120's state: Signed [date], Sent, not signed, or Not sent.
  - **Action** depends on the program:
    - **A held program:** "Open program ›" goes to its page under Programs. It also has View all terms, Request a change and Request to end.
    - **A program HQ offers that the studio does not hold:** "Request it".
    - **A program the studio asked for:** "View request".
    - **Runs at HQ, and a program HQ does not offer:** no action and no link.
- **Partner deal types you may offer** (D986). Each type is shown ✓ or "· locked".
  - When HQ has not set them, the card shows the Worker's "Not recorded" sentence instead, never "every type".
- **On a phone (GR15a)**, the table becomes a card per program, with the same status and actions.

### 2. The terms (GR8, GR15c)

"View all terms" opens an in-page dialog. On a phone it takes the whole screen, with "Request a change" at the foot.

- **The rows.** It lists every term the program carries: Period, Capacity, Cohorts, Approval, Money, Credits, Playbook, Brand, Reporting, Contract, and the note to the studio.
- **A term HQ has not entered** reads "Not recorded · HQ has not entered this term" (GR13 E). It is never a zero or a default.
- **Where each term is stated.** The canvas draws "Schedule P-3 §n" chips, but D1120's schedule has no numbered sections. It prints every term under one "Terms" heading, as the terms stood the day HQ sent it.
  - So each term's chip names the program schedule and its state: "Program schedule · signed", "Program schedule · sent", or "No schedule sent yet".
  - An unentered term has no chip, because no schedule states it.
  - The Contract row says that the schedule states the terms as they stood the day HQ sent it.
- **History.** The canvas's "History of this grant" needs HQ's ledger, which the studio's read does not carry: `licence_events` is not pushed to a branch (D107).
  - The dialog shows instead what the grant itself records: when it was ended, paused, signed and last set.
  - It says that each change, with HQ's reason, is on HQ's record.

### 3. Asking HQ (GR9, GR9b)

"Request a program" (`ProgramRequestSheet.jsx`) is the right-hand sheet of D804, full screen on a phone. It opens from:
- "Request it";
- Request a change and Request to end;
- the terms dialog;
- GR11 B's button;
- the Requests tab's new sixth button (§4).

The sheet works like this.
- **Program.** It lists only programs HQ offers.
- **What you ask for.** The asks follow what the studio holds:
  - Grant, for one it does not hold or that has ended;
  - Change a term, or End, for one it holds.
  This matches D983's checks at HQ's door.
- **Which term.** The terms D982 gives that program, by the schedule's names. The currency rides the fee.
- **As it stands.** Read only, from the grant. **It is never sent:** HQ fills it from its own store, and the Worker refuses `current`.
- **The reason** is required, with a counter out of 2000, as the Worker requires.
- **The foot** gives HQ's response time from `response_hours`: "HQ answers within 3 days."
- **At the limit (GR9b).** With `open_max` requests open (twenty, counting every kind, as the Worker counts), the sheet says "You have 20 open requests with HQ, the most allowed. Wait for an answer before you send another." and Send is disabled.
- **A refusal**, such as `program_request_open` or `program_not_offered`, is shown in the Worker's own words.
- **Nothing changes until HQ answers.** The tab says so once the request is sent.

### 4. The insets

- **Requests tab** (`RequestsTab.jsx`): a sixth button, "Request a program", opens the same sheet over D984's read.
  - "Your requests" names program requests as "Program · Learning", "Program change · Perks · Credits a quarter" or "End program · Perks".
- **Summary tab** (`LicenceSummary.jsx`): a Programs card, "[n] granted · [n] with HQ · Open Programs ›".
  - If the read fails, it says "Programs unreadable" with the reason.

### 5. The states

- **GR11 B.** Linked, but nothing held and nothing asked: "HQ has not granted any program to [studio] yet. See what HQ offers below, or request one." with Request a program. The table stays below it.
- **GR11 C.** An account no licence binds: "Your account is not linked to a licence. On HQ-held accounts, HQ runs every program." with Open Programs and Contact HQ.
  - The Licences page draws this on its Programs tab when `/licence/mine` answers 404, and the tab draws it when D984 answers `linked: false`.
- **GR12b.** While reading, the tiles say "Reading…" and the table is a skeleton.
- **A failed read** says "That is not the same as none" with Try again. The tiles read "Unreadable". Each read fails alone: the deal types and the requests still render.
  - A failed requests read says that a program asked for may not show as Requested.
- **GR13 C.** On a branch's copy, the tab says "As of [time] UTC, [day]. This is HQ's copy of your grants. It updates when HQ changes them."
  - A copy not sent yet shows the Worker's reason. On HQ there is no stamp, because the read is the store.
- **GR14 B.** A member is refused by the admin-only notice D940 already draws: "This page is for studio admins. If you run a studio, ask HQ for admin access." with Go to your home.
- **GR14 C.** A Super Admin with no licence: "You are viewing as an Admin. HQ is not a studio, so it holds no grants." with Open Program grants.
