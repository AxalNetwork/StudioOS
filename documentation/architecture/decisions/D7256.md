## D7256 — Private error context stays out of replies and diagnostic logs (#7256)

The 2026-11-18 JavaScript CodeQL run 44235984068 reports two stack-trace data
flows at the visual server's manifest and Worker-response forwarding. That
server is a loopback-only synthetic harness, not the production server. Its
catch already returns a constant reply. The findings are retained for hosted
scan verification rather than being dismissed based on that fact alone.

Production equivalents were checked at the Worker's application error handler,
the shared route error mapper and the refusal-body builder. The application
handler already returns a generic 500, but logged the original exception.
The route mapper deliberately accepts validation sentences; native runtime
errors and messages carrying private diagnostic shapes must not use that path.
Owner/admin provider diagnostics also need the privacy boundary.

`errorPrivacy.ts` distinguishes runtime exceptions and private diagnostic
context from intentional validation sentences. Those failures receive the
same generic 500 detail. Authentication and domain-validation contracts,
thrown Responses, malformed-JSON 400 replies, and existing storage/constraint refusal handling remain.
This does not migrate every legacy validation throw to a new error class.

The application handler, route mapper, refusal builder, import-row failure
builder and visual catch record a bounded event and error-kind classification.
A small fixed provider-code vocabulary preserves actionable classifications.
Exception names outside the known runtime classes, messages, stacks, causes,
paths and request contents are not copied into these log records. This amends
D278's raw-diagnostic logging: protection of the log destination alone is not
a reason to retain potentially sensitive exception contents.

Member refusals still contain only the platform's sentence and code. Owner and
admin upstream diagnostics remain clipped and useful when ordinary; private
diagnostic context is replaced with a constant withheld notice. The original
exception never becomes the public message, detail or error code.

Tests exercise real Hono responses, all supported audiences, structured
observability, native exception kinds, and retained auth/validation behavior.
All inputs are synthetic. No live member record, credential, production write,
scan suppression or alert dismissal is involved.

The current protected open-alert inventory could not be read in this
environment. These changes do not establish that the two hosted findings have
cleared, or that every current alert is resolved. Code scanning, required CI
and main-branch reconciliation remain completion gates; keep the batch and
alert trackers open until confirmed.

Local validation: 325 related auth/refusal tests and the final 17-test focused
privacy/refusal run pass. Twelve negative variants are rejected in a private
source copy, followed by a clean restored run. The root build and Worker and
frontend typechecks pass; these local results do not replace hosted scans.
