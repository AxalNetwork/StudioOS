## D4596 — The working copy is the complete document, and recovery survives close/reopen on desktop and phone (#4596)

- **Status:** built by S27, 2026-11-07 (#4596, Pitch audit 2/5, follow-up to D1515/#3767).
- **Number:** D4596 is this issue's number. Migration: `202611071430_pitch_draft_document.sql` (one additive table).
- **Scope:** draft/autosave recovery. Explicit Save version already persisted the complete document and is unchanged.

### The defect
The autosave tracked cards only. A removal, a reorder, a theme-only edit or an audience-only edit never became "unsent": it escaped the dirty state, the 1.5 s send, the device copy and the navigation warning. A successful card sync deleted the device copy while those changes were still unsent. Restore, discard and conflict controls were drawn only in the desktop layout, so on a phone saving could wait on a decision nobody could see. "Copy mine" used the card as it was when the conflict first appeared. A failed browser-storage write still produced "saved on this device".

### The fix
- **Worker.** `pitch_deck_draft_doc` (deck_id, rev, order, theme, audience) and `PUT /api/decks/:id/draft-doc { order, theme, audience }` with `If-Match` (0 for the first). `order` is the complete list of the card uids the working copy keeps; the cards it omits are deleted in the same batch, gated on this write being the document's current revision. A stale revision is 409 `doc_rev_conflict` with the server state and writes nothing. Theme and audience are checked as a save checks them. `GET /draft` carries `doc` (null before the first save); `DELETE /draft` discards it.
- **Client.** `createAutosave` takes `saveDoc` and keeps a document revision beside the card revisions. A document differing from what the Worker holds is "unsent" (counts in `pending()`, the save chip, autosave, and the `beforeunload` warning). Cards are sent first, then the document. The device copy is deleted only when the cards and the document revision are acknowledged, and is rewritten if an edit landed during the delete. A removed card's revision is dropped, so undoing then redoing it is sent as a new card. A document-revision conflict between tabs is last-writer-wins on the revision the Worker names (a card conflict still asks).
- **Restore.** `restoreOffer`/`mergeDraft` apply the document: removals, order, theme and audience come back, including an empty deck.
- **Conflict.** `resolve('copy')` returns `{ theirs, mine }` where `mine` is the card as it is now.
- **Honest lines.** `idbStore.put` reports whether the browser took the write. A refusal sets `device: 'failed'`; the offline line then reads "NOT saved on this device" and a separate line says so while online. The in-memory work keeps being sent.
- **Phone.** The restore question, the sync line and the conflict view render above the phone editor as on desktop. While restore or a conflict waits, the sync line says saving is paused. A conflict on a card the person removed locally is still shown.
