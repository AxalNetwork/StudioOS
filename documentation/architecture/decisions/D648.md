## D648 — The Admin Console is a shell; each tool is its own console

**Issue:** #1448, groundwork for #1439 (the admin reorganisation). **Built by:**
S07. **Migration:** none. **Canvas:** none; nothing changes in how a console
looks.

### What was true

- **One component held all fourteen consoles.** `pages/AdminPage.jsx` was about
  6,100 lines; only `LegalPanel` (and a few test hooks) were exported.
- **Every tab loaded everything first.** Before any tab rendered, the page read
  the users list, the trust scores, every partner profile and the pending KYC
  queue, and showed "Loading admin console..." until all four answered. The
  profiles read and the KYC read each write an audit row, so opening Promo
  codes wrote two audit rows about profiles and KYC.
- **HQ · Accounts mounted the whole page** (`section="users"`) to show the
  Users table, and made the same four reads.
- **A failed read looked like an empty list** in Partner Profiles, KYC,
  Personas, Directory, Wellbeing, Promo codes, Payments, Integration keys and
  GitHub Sync (and Users and Billing).

### What is true now

- **One file per console** under `pages/admin/consoles/`: Users, Partner
  Profiles, KYC, Legal, Personas, Directory, Integration keys, GitHub Sync,
  Promo codes, Payments, Billing and Wellbeing. Spin-Out Lab and Advisors &
  Partners were already their own components (`pages/admin/AdminSpinoutLab.jsx`,
  `AdminNetworkProfiles.jsx`) and are mounted as they were. The code moved
  unchanged; the pieces more than one console draws (`ROLE_BADGES`, `Field`,
  `KV`, `fmtDate`) are in `consoles/shared.jsx`.
- **Each console reads only its own data.** Users reads the users list and
  trust scores; Partner Profiles reads the profiles; KYC reads its queue.
  Opening any other tab reads none of the three.
- **`AdminPage.jsx` is a thin shell** (about 220 lines): the header, the section
  dropdown and the one console it mounts. The `?tab=` links, the `section`
  prop and the `admin-tab-*` test ids work as before, because #1439 retires the
  dropdown later, from the canvases. It re-exports `LegalPanel` so the
  Contracts page (#1441) is untouched.
- **HQ · Accounts mounts `UsersConsole` alone.**
- **Every console has a real "Unreadable" state.** `ConsoleUnreadable` says
  "… could not be read. This is not a sign that there are none." with Try
  again, in place of the empty list a failed read used to draw.

### The one behaviour that moved

The dropdown's "N pending" badges on Partner Profiles and KYC came from the
shell's up-front reads. With those reads gone, each badge is reported by its
console once that console has been opened in the session (`onPendingCount`).
Reading both lists on every tab just to draw two badges is exactly the cost
this split removes; #1439 decides where pending counts live in the new
navigation.

### Verified

**`frontend/test/admin_consoles_d648.test.mjs`**, rendered with effects on a
minimal DOM and with the `api` client's methods replaced by recorders:
- **Each console on its own** (Users, Partner Profiles, KYC, Personas,
  Directory, Integration keys, GitHub Sync, Promo codes, Payments, Wellbeing):
  - loading: its read in flight, and no result claimed;
  - empty: the read answers with nothing, and the console says so;
  - unreadable: the read fails, and the console says so with Try again, never
    the empty list.
  - Payments' failed render is pinned from source, because a failed read also
    raises a toast that Payments draws as an object, the crash #1437 (PR
    #1443) fixes. Billing reads disputes on a click, so it is pinned from
    source too.
- **The shell**, at `?tab=` for each console: that console's reads are made,
  and none of the four reads every tab used to make first.
- **HQ · Accounts** mounts `UsersConsole`, not `AdminPage`.

**The existing admin tests** pass with only their paths changed: the ones
that read `AdminPage.jsx` as source now read the shell and every console
through `frontend/test/_adminConsoles.mjs`; the four imports point at the new
files; four regexes that pin an import path now expect `../../../`.
`admin_route_reachability.test.mjs` credits a console's links to the page that
mounts it through a `COMPOSED` table, checked against that page's own imports.

Mutation-checked: 21 mutants, 20 caught. The survivor drops the failed flag
from the Users console's first read; the search effect re-reads the list on
mount and reports the same failure, so it is equivalent.
