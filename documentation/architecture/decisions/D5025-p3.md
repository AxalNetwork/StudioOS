## D5025 part 3 — The change review lists each ending program's open items (#5025)

Part 3 of #5025, built for issue #8830, on top of D5025 (part 1) and D5025-p2
(part 2). Parts 1 and 2 answered the open cohorts, claims and workflows of an
ending program as `not_recorded`, because no shared read named them. This part
gives the change review a real answer. It reopens that part of #5025's scope,
so #5025's release condition that only #5026 remained did not hold until this
part.

It is read only. Nothing here grants, ends, pauses or rewrites a grant, a
cohort seat, a claim or a workflow, and no migration is added.

### What the review answers

For a downgrade or change, `GET /api/admin/licences/:uid/package-offers/:offer/change-review`
now answers `ending_dependents` as:

- `programs`: one entry per ending program, in the order `programs.ending`
  lists them, each one of:
  - `read`: `source` (the table read), `open_means` (the sentence below),
    `count` (every open item), `items` (each item's `ref` and `user_id`, the
    first 100 in id order) and `truncated` when there are more;
  - `not_recorded` with a `reason`: no source is mapped for the program, the
    licence has no holder account, or the program's store does not exist in
    this database;
  - `unreadable` with a `reason`: the store failed to read. That is not the
    same as no open items.
- `holders`: the accounts read and the scope sentence, or null before any
  store was read.
- `status`: `read` when every ending program was read, `not_read` when none
  was, `partial` otherwise. `read_only` is always true.

An upgrade or renewal still answers `ending_dependents: null`.

### Holders

A package term is held by a territory licence. On HQ the accounts of a
territory licence are its `licence_admins`, principal and delegates, and
those are the accounts whose items are read. A deployed branch's own members
live in the branch's database, which this HQ read does not reach; the
response says so in `holders.scope`. A licence with no administrator reads
every mapped program as `not_recorded` (no holder), not as 0.

### What open means, per source

D5059-p1's table names activity evidence for a holder review (a previous perk
claim, a referral submission beyond draft). Evidence of past activity is not
an open item, so this part defines open per source as work still running or
still owed:

| Program key | Source | Open |
| --- | --- | --- |
| `spinout-lab` | `cohort_applicants` | A cohort seat pending, waitlisted, approved or activated, in a cycle that is not completed |
| `learning` | `learning_enrollments` | An active enrolment in a learning program that is not archived |
| `investor-cohorts` | `investor_cohort_access` | A grant not ended whose end day is today or later |
| `mentor-cohorts` | `advisor_cohort_assignments` | An active assignment, not unassigned, in a cycle that is not completed |
| `perks` | `perk_claims` | An issued claim, not redeemed or revoked, with no expiry or one still ahead |
| `refer-and-earn` | `referral_submissions` | Submitted and not yet rewarded, rejected or closed (`submitted` through `reward_eligible`); a draft is the referrer's own and is not open |
| `referral-partners` | `referral_partner_terms` | Terms in approval or signature (`submitted`, `approved`, `sent`, `signed`), or `active` with no end day before today; the influencer segment is the influencer program's |
| `influencer` | `influencers` | A membership active or paused |
| `product-testing` | `product_testers` | A tester applied, active or paused |

The identifier is the row's `uid` where the store has one, else its id.
Timestamps are compared through `datetime()` and days through `date()`.

### Unmapped programs

AI-native Venture has no store of its own (D5059-p1 answers it
`evidence_not_mapped`), and a program added through the registry has none
here either. Each reads `not_recorded` with the reason that no store is
mapped, never an empty list or 0.

### Not in this part

- The operator screen that shows these items: #5026, with its canvas.
- Reading a deployed branch's own members' items.
- Any action on an open item. HQ decides on each one before it accepts the
  offer through D5024's route.
