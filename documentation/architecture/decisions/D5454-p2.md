### What is decided

- **A digest is a discovery reader.** The investor brief in each aggregator is the only draft in either file that reads `deals`. It is a count posted to a channel, so it uses the `discovery` mode of the existing guard (`D5454.md` §3), not a new rule: `hiddenDealIds(env, 'discovery')`, bound as `d.id NOT IN (SELECT CAST(value AS INTEGER) FROM json_each(?))`, the same fragment `routes/deals.ts` uses for its funnel and pass counts.
- **What is counted.** A legacy deal with no preparation (`legacy_visible_unreviewed`, owner answer Q1=A), an unreleased `legacy_attach` and a published release are counted. A private preparation, a preparation with unknown metadata, and a withdrawn or archived release are not. A never-released draft owns no `deals` row (CHECK `dp_private_owns_no_deal`), so the guard is the second layer for it, as everywhere else.
- **Failure.** A database that has not applied the migration hides nothing, which is the guard's own rule (`isMissingPreparationTable`: no preparation can exist there). Any other guard failure, including a hidden set over `HIDDEN_SET_MAX`, makes the figure **unreadable** (D301's `{ ok: false }`, printed as "Unreadable" and stored as `null`), never an unfiltered count. The brief's other figures still draft.
- **Transactional reads are untouched.** No by-id read is in either file.
