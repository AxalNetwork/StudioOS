## D5985 — Section draft-fix gate: a pure eligibility check with a budget and a stop switch (#5985)

Part of #5681 (third bullet). Before any automatic draft PR can exist, the rule
that decides eligibility is code with tests: `scripts/lib/sectionDraftGate.mjs`,
tested in `scripts/lib/sectionDraftGate.test.mjs` (run by `npm run test:retention`,
which globs `scripts/lib/*.test.mjs`). The gate is pure. It reads only the
observation it is handed. It makes no GitHub call, starts no workflow, creates no
branch or PR and calls no agent. Gathering the observation and dispatching a
draft are #5986's, which must call this gate and act only on a yes.

### The call

`eligible(input)` returns `{ eligible: true, job }` or `{ eligible: false, reason }`,
both frozen. The input has a fixed shape and no free-text field:

| Field | Meaning |
| --- | --- |
| `stop` | The stop switch. Only an explicit `false` lets a call through. |
| `issue` | The GitHub issue the triage CLI (D5681) filed, a positive integer. |
| `case` | A key of `cases` in `scripts/section-triage.mjs`. |
| `baseCommit` | The 40-character lowercase commit the draft would branch from. |
| `event` | `kind`, `actor` (a GitHub login), `origin` of the event asking for a draft. |
| `evidence` | `source` and `reproduced`. |
| `classification` | What the defect is. |
| `touches` | The excluded areas (below) a fix would reach; empty for an eligible defect. |
| `triage` | `criteriaMet`, `duplicate`, `ownerVerified`. |
| `work` | `claim`, `openPr`, `inFlight` for the issue. |
| `budget` | `attempts` and `branches` and `prs` for the issue, and `concurrentDrafts` overall. |

A yes needs all of: the stop switch off; the case in the allowlist; an
`operator-reproduced` event from an `operator` origin; evidence from
`operator-reproduced` with `reproduced: true`; classification
`ordinary-ui-regression` with nothing in `touches`; the triage criteria met,
not a duplicate, a verified owner; no claim, open PR or in-flight work; and
every budget below its limit.

### Rules, in order

The first rule that fails names the refusal. Each code is fixed (`REASONS`).

| # | Rule | Code |
| --- | --- | --- |
| 1 | Stop switch on, missing or not exactly `false` (or no input) | `stopped` |
| 2 | A key named like free text (`text`, `body`, `title`, `report`, `comment`, `message`, `description`, `summary`, `url`) at any level | `excluded-untrusted-text` |
| 3 | Any other unknown key | `unexpected-field` |
| 4 | A missing field or a wrong type (a missing or non-object group — `event`, `evidence`, `triage`, `work`, `budget` — is refused this way before rule 2): issue not a positive integer, base commit not 40 lowercase hex, actor not a login, a flag not a boolean, a count not a non-negative integer | `invalid-input` |
| 5 | Event origin `automation`, or an actor ending in `[bot]` | `self-generated-event` |
| 6 | Event kind `mention` | `excluded-mention` |
| 7 | Event kind `report` (report text) | `excluded-untrusted-text` |
| 8 | Any other event kind or origin | `untrusted-event` |
| 9 | Case not in `cases` | `case-not-allowlisted` |
| 10 | Classification, or an entry of `touches`, is `security` | `excluded-security-finding` |
|  | … `permissions` | `excluded-permissions` |
|  | … `financial-record` or `legal-record` | `excluded-financial-legal-record` |
|  | … `production-credentials` | `excluded-production-credentials` |
|  | … `data-migration` | `excluded-data-migration` |
|  | … `deploy` | `excluded-deploy` |
| 11 | `touches` holds anything else | `invalid-input` |
| 12 | Classification is not `ordinary-ui-regression` | `not-ordinary-defect` |
| 13 | Evidence source is not `operator-reproduced` | `evidence-untrusted` |
| 14 | Evidence not reproduced | `not-reproduced` |
| 15 | Triage criteria not met | `triage-criteria-unmet` |
| 16 | A duplicate incident | `duplicate-incident` |
| 17 | No verified owner | `no-eligible-owner` |
| 18 | The issue has a claim | `existing-claim` |
| 19 | The issue has an open PR | `open-pr` |
| 20 | The issue has other in-flight work | `in-flight-work` |
| 21 | `branches` ≥ `MAX_BRANCHES_PER_ISSUE` | `branch-exists` |
| 22 | `prs` ≥ `MAX_PRS_PER_ISSUE` | `pr-exists` |
| 23 | `attempts` ≥ `MAX_ATTEMPTS_PER_ISSUE` | `attempt-budget-exhausted` |
| 24 | `concurrentDrafts` ≥ `MAX_CONCURRENT_DRAFTS` | `concurrency-budget-exhausted` |

Rules 2, 6, 7 and 10 are #5681's excluded inputs: untrusted report text, a
mention, a security finding, permissions, financial or legal records,
production credentials, data migrations and deploys. Rule 5 is "no
self-generated events".

### Budget — for owner review

These are a first proposal. They are named constants in the module and the
owner may change them.

| Constant | Value | Counts |
| --- | --- | --- |
| `MAX_ATTEMPTS_PER_ISSUE` | 2 | Draft attempts the automation has started for the issue, ever. |
| `MAX_CONCURRENT_DRAFTS` | 1 | Automatic drafts open or in progress across the repository. |
| `MAX_BRANCHES_PER_ISSUE` | 1 | The automation's branches that exist for the issue. |
| `MAX_PRS_PER_ISSUE` | 1 | PRs the automation has opened for the issue, in any state. |

So a second attempt is possible only when the first failed before it opened a
PR and its branch is gone, and there is never more than one branch and one PR
per issue.

### The job

A yes carries exactly five fields: `issue`, `caseKey`, `sourcePath`,
`testPath`, `baseCommit` (`JOB_FIELDS`). The source and test paths come from the
allowlist, never from the input. No free text passes through.

### The allowlist

The allowlist is `cases`, exported from `scripts/section-triage.mjs` (its
entries are now frozen; the triage CLI only reads them, so its behaviour is
unchanged). The gate reads it, it does not copy it. A new case is a reviewed
change to that map, and it reaches the gate and the triage CLI together.

### The stop switch

`stop` must be exactly `false` for any call to pass. Anything else, including
a missing field, refuses every input with `stopped`, before any other rule.
The dispatcher (#5986) decides where the operator's switch lives; whatever it
reads must fail to "stopped".
