## D4833 — Practice Delivery as an artifact and an immutable version workspace (#4833)

- **Status:** built by slot S07, 2026-11-09 (#4833, Practice UX 5/6, P1). Part of #4833: the parts that need a backend field are listed under "Not built".
- **Canvas:** `design/incoming/Practice v2 Page.dc.html`, PX-06 A to D (D4874).
- **Migration:** none. **Worker:** unchanged; every write uses a mounted route.
- **Builds on:** D571 (the zone and its by-client view), D4684 (a sent version keeps its recipient), D4712 (a revision is never empty; reviews stand alone), D4714, D4702.

### What the advisor sees

- **Cards, not rows.** Each work product is a card: title, client, "Latest v3 · Sent Nov 6", its receipts ("Opened Nov 6 · Accepted Nov 7", "Not opened in 4 days", or for a draft whose earlier version went out, "v1 opened Oct 28"), a status pill and **Open**.
- **The status is the latest version's,** from that version's own stamps: Draft (no `sent_at`), Sent, Opened (`opened_at`), Accepted (`signed_off_at`). The endpoint's folded `state` (opened if any version was opened) still feeds the nudge and the four receipt tiles; it would call the canvas's "Pricing model v2" Opened while its v2 is unsent.
- **Filters:** Draft · Sent · Opened · Accepted · All, with counts, in the canvas's order. **Ready is left out**, not drawn disabled: no Ready state is stored (D4874), and the page says so under the chips. **Draft is recorded:** it is a latest version with no `sent_at`, which the store writes on every send.
- **Group by client** is a toggle beside the cards, not a chip, and `?view=by_client` (D571's `/practice/deliverables`) still opens on it. The old `?view=unopened` opens on Sent.
- **Detail sheet** (the shared `Sheet`, D1317): the eyebrow names the client and engagement; the latest version card shows its change note, its document link and its receipt line; then **Version history · immutable**, every version with its own recipient and its own opened and accepted stamps. Nothing in the history is a control.
- **Recipient states,** from the version row: a recipient the engagement no longer names says the version "stays with" that person (D4684); a recipient whose account no longer reads back says it is no longer active on Axal; a send with no recipient on the row says "Recipient not recorded".
- **Add version** is a dialog: change note and document link, both required (`attachmentBody`, D4712), saved as the next version, not sent. There is no one-click empty version.
- **Send** opens a confirmation, "Send v2 to Northstar?", naming the recipient (the engagement's client account now, which is who the Worker records, D4684), the document and its host, the change note, and that the version cannot be edited after sending. Nothing is sent until it is confirmed. The by-client group's Send uses the same confirmation.
- **Post-session reviews** keep their own section outside `ZoneBody` (D4712), now titled as the canvas titles it, so they render with no work product and when the work-product read fails.

### Departures from the canvas

- **No Practice v2 shell.** #4829's shell had not merged, so this is the Delivery zone inside the current advisor shell.
- **Ready** is not offered (D4874).
- **Document or URL** is a web link only: versions store `link_url` and there is no file upload.
- **Optional summary** is not offered: a version stores one note (`summary`, used as the change note) and no second text field. A field the store would drop is not drawn.
- **The four receipt tiles, the nudge and the "Follow-ups from sessions" statement stay** below the cards. The v2 canvas moves health figures to the Overview cockpit, which is not built yet; removing them here would lose working figures.
- **Dark mode and 390px** use the existing tokens and the shared `Sheet`/`Lightbox`, which become a full-screen page below 640px.

### Not built (backend required)

- A Ready state (D4874).
- A version summary separate from the change note, and document upload.
