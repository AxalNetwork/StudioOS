## D5621 — Select the PR suite and validate a full run at head (#5621)

The plan keeps the existing full matrix for push, merge queue and manual
dispatch. A fork, missing selection or unknown event also gets the full
matrix. A same-repository PR with a usable selection runs the rest part
and selected tests. Hash the head SHA and take one residue out of 20 for a
full audit, so a rerun at the same head makes the same choice. A full tier
returns a null parts list, which tells the planner to use its full matrix.

A successful full dispatch must belong to the repository's CI workflow,
the current PR head and the successful landing gate from the same
attempt. The tested base must be an ancestor of the current main tip
with fewer than 10 commits of lag and at most 120 minutes of lag. A
matching main tip has zero lag. The commit cap is provisional pending
the hosted rehearsal. The validator expects a trusted adapter to obtain
the base actually tested by the run, bind it to the run attempt, and
verify the full suite. A dispatch SHA alone identifies the branch tip.
Until the workflow provides base evidence that the adapter can verify,
there is no operator command or change to admission.

GitHub documents that `GITHUB_TOKEN` writes for the `labeled` event do
not start a workflow and that an explicit `workflow_dispatch` is an
exception. A dispatch runs at the last commit on the supplied branch
or tag. [Triggering a workflow](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow),
[dispatch event reference](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch).

The hosted test still needs to compare the PR head with the dispatch
run and its landing gate, then observe ruleset behavior when thin and
full Actions checks share the name. GitHub documents check/status
name collisions and checks on test-merge commits. Neither observation
identifies which of two same-named Actions checks StudioOS admits.
[Required checks troubleshooting](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks).

The workflow and queue rehearsal follow #5610, #5606, #5500 and #5501,
using the planner and landing procedure from #5609 and #5607. The
release proof continues to require its own exact-event evidence.
