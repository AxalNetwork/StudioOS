## D766 — Every AI call goes through the router: the direct env.AI.run calls move into run(), so each is guarded, metered and charged to the member who pressed

- **Status:** filed by S1 for the owner (2026-10-19) as #2094, task A7 of D720 (#1874, §7 and §9). Three PRs. PR 2 (the system calls) is built first, because PR 1 needs D765 PR 1 (#2090) for rail context and #2090 is not on `main` yet.
- **Basis:** `origin/main` at `4f7816e81c`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D761 (the router's shapes; PR 2's vision content parts carry the images), D762 (each run's charge), D763 (the guard inside `run()`), D552 (every router call names its page).

### 1. The decision

No Worker file calls `env.AI.run` outside the router and the guard. A member's press is held, guarded and charged to that member (PR 1); a system call runs as `userId 0`, logged at cost and charged to no member (PR 2); a test keeps it so (PR 3), with the live transcription WebSocket as its one listed exception.

### 2. PR 2, as built — the system calls

| Call | Task | Model | Page (D552) |
| --- | --- | --- | --- |
| `routes/monitoring.ts`, the last hour's summary (`GET /monitoring/anomalies`) | `ops_summary` | Llama 3.1 8B Instruct FP8 (unchanged) | `/monitoring` |
| `routes/admin_x.ts`, the image screen on upload | `image_screen` | Llama 4 Scout 17B | `/admin/x` |
| `routes/admin_x.ts`, the drafted alt text | `image_alt_text` | Llama 4 Scout 17B | `/admin/x` |
| `services/vectorize.ts` `embedText` (upserts, the hourly re-embed, query embeddings) | `embed` | BGE Base EN v1.5 (unchanged) | `/admin/platform` |

- **Each runs with `userId: 0`.** It takes no hold and charges nobody (`charged_microusd` 0, no reservation), writes its usage row with its task, model and page, counts against the organisation cap and obeys its kill switch. `ops_summary` and the image tasks are guarded (D763); `embed` for user 0 is not, as before.
- **The vision model.** `llava-1.5-7b-hf` is not in Cloudflare's 2026-10-15 pricing (`design/incoming/airail-every-page-data/cloudflare-pricing-2026-10-15.md`), so both image calls move to **Llama 4 Scout 17B** (`@cf/meta/llama-4-scout-17b-16e-instruct`): a vision model in D761's list, priced at $0.27 in and $0.85 out per M tokens (a new row in `PRICE_USD_PER_1M_TOKENS`, from that table), and with no license prompt to send first. Llama 3.2 11B Vision is cheaper but needs a one-time "agree" request per account; Gemma 4 26B thinks by default, which an 8-token yes/no budget cannot afford.
- **The images** go as D761 PR 2's content parts: the stored or uploaded bytes become a base64 data URI. The router sends at most 4 MB, so an upload between 4 and 5 MB (X's own limit) is refused as `too_large_to_screen` (413) instead of being stored unscreened. Every other failure of the screen still passes through, as before, so a flaky model cannot lock admins out.
- **The embedding** keeps BGE Base EN v1.5 for the 768-dimension `axal-search` index; the router's `embed` task is that model, and `embedText` refuses a vector from any other (`searchIndexAccepts`). Embeddings are now cached by the router for 30 days.
- **Labels and pages.** `services/aiCatalog.ts` names the three tasks and Scout for the Usage page; `services/aiSurfaces.ts` adds `monitoring`, `adminX` and `searchIndex`, listed in `D552.md`.
