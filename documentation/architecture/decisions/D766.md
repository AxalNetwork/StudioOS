## D766 — Every AI call goes through the router: the direct env.AI.run calls move into run(), so each is guarded, metered and charged to the member who pressed

- **Status:** filed by S1 for the owner (2026-10-19) as #2094, task A7 of D720 (#1874, §7 and §9). Three PRs. PR 2 (the system calls) was built first, because PR 1 needs D765 PR 1 (#2090) for rail context. PR 2 merged as #2137; PR 1 followed once #2132 (D765 PR 1) was on `main`.
- **Basis:** `origin/main` at `4f7816e81c`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D761 (the router's shapes; PR 2's vision content parts carry the images), D762 (each run's charge), D763 (the guard inside `run()`), D552 (every router call names its page).

### 1. The decision

No Worker file calls `env.AI.run` outside the router and the guard. A member's press is held, guarded and charged to that member (PR 1); a system call runs as `userId 0`, logged at cost and charged to no member (PR 2); a test keeps it so (PR 3), with the live transcription WebSocket as its one listed exception.

### 2. PR 2, as built — the system calls

| Call | Task | Model | Page (D552) |
| --- | --- | --- | --- |
| `routes/monitoring.ts`, the last hour's summary (`GET /monitoring/anomalies`) | `ops_summary` | Llama 3.1 8B Instruct FP8 (unchanged) | `/monitoring` |
| `routes/admin_x.ts`, the image screen on upload | `image_screen` | Llama 4 Scout 17B | `/admin/x` |
| `routes/admin_x.ts`, the drafted alt text | `image_alt_text` | Llama 4 Scout 17B | `/admin/x` |
| `services/vectorize.ts` `embedText` (upserts, the hourly re-embed, query embeddings) | `embed` | BGE Base EN v1.5 (unchanged) | `/admin/platform` |

- **Each runs with `userId: 0`.** It takes no hold and charges nobody (`charged_microusd` 0, no reservation), writes its usage row with its task, model and page, counts against the organisation cap and obeys its kill switch. `ops_summary` and the image tasks are guarded (D763); `embed` for user 0 is not, as before.
- **The vision model.** `llava-1.5-7b-hf` is not in Cloudflare's 2026-10-15 pricing (`design/incoming/airail-every-page-data/cloudflare-pricing-2026-10-15.md`), so both image calls move to **Llama 4 Scout 17B** (`@cf/meta/llama-4-scout-17b-16e-instruct`): a vision model in D761's list, priced at about $0.27 in and $0.85 out per M tokens (its row in `PRICE_USD_PER_1M_TOKENS` is D760's catalogue price, $0.269995 and $0.850003), and with no license prompt to send first. Llama 3.2 11B Vision is cheaper but needs a one-time "agree" request per account; Gemma 4 26B thinks by default, which an 8-token yes/no budget cannot afford.
- **The images** go as D761 PR 2's content parts: the stored or uploaded bytes become a base64 data URI. The router sends at most 4 MB, so an upload between 4 and 5 MB (X's own limit) is refused as `too_large_to_screen` (413) instead of being stored unscreened. Every other failure of the screen still passes through, as before, so a flaky model cannot lock admins out.
- **The embedding** keeps BGE Base EN v1.5 for the 768-dimension `axal-search` index; the router's `embed` task is that model, and `embedText` refuses a vector from any other (`searchIndexAccepts`). Embeddings are now cached by the router for 30 days.
- **Labels and pages.** `services/aiCatalog.ts` names the three tasks and Scout for the Usage page; `services/aiSurfaces.ts` adds `monitoring`, `adminX` and `searchIndex`, listed in `D552.md`.

### 3. PR 1, as built — the member presses

| Press | Task | Page (D552) | Option | Record |
| --- | --- | --- | --- | --- |
| `POST /legalcap/legal/generate`, the document's suggestions | `rail_legal` | `/legal-capital` | `draft:legal/<type>` | `deal:<id>` |
| `POST /legalcap/diligence/review`, the risk summary | `rail_reason` | `/legal-capital` | `review:diligence/<type>` | `deal:<id>` |
| `POST /legalcap/spinout/equity-allocate`, the proposed split | `rail_numbers` | `/legal-capital` | `propose:spinout/equity` | `deal:<id>` |
| `POST /pipeline/decision-gate/review`, the recommendation | `rail_reason` | `/pipeline` | `review:decision-gate` | `deal:<id>` |
| the syndicate's recommendations | `rail_match` | `/network-effects` | `recommend:syndicate` | `syndicate:<id>` |
| `POST /networkfx/marketplace/match` | `rail_match` | `/network-effects` | `match:marketplace` | none |

- **Each is the pressing member's run.** It is held, guarded and charged to them, and logged with D765's page (the browser's `X-Rail-Page`, else the route's own path), option and record. The task is the `rail_<kind>` of the work, D764's per-kind route, as D767's deck runs use Raise › Pitch deck's row. The page key differs by profile (D768), so one route cannot name a single matrix row. The old calls ran Llama 3.1 8B directly; the rail tasks run the models D764 routes each kind to.
- **How a refused run is answered** (`util/railContext.ts` `refuseRun`):
  - the switch: 403 `assist_off`, in its words (D765);
  - a budget stop: 402, in the budget's words (`budgetRefusalMessage`);
  - the guard's block: 422, in the guard's words;
  - a guard or an allowance that could not be read: 503.

  A model that could not be reached is not a refusal. The press keeps the non-AI path it already had: the rule-based gate, the heuristic diligence score, the template-only document, the top-rated match.
- **The guard** reads what the run sends. The marketplace match passes the member's need as `guardText`: the profiles in its prompt are other members' own words, already on the platform (D763's rule for rows read from the store).
- **No AI output written without the member's accept (D720 §9).**
  - **The equity split.** Asked without an allocation, the route returns the AI's split as a proposal (`proposal: true`) and writes nothing. The Spin-out wizard shows it, marked "not saved until you press Save Allocation"; Save posts it back as `allocation`, which writes it (`proposed: true` records that it began as the AI's). The wizard no longer reloads after the AI press, which would have drawn the saved split over the proposal.
  - **The legal document's suggestions** are kept beside the document (`content.suggestions`), never appended to its text as before. The document is the template the member filled.
  - **The decision gate** is already a recommendation: the gate opens `pending`, and a person records the final decision.
  - **The diligence summary** is the review the member pressed for, stored as its `ai_summary` beside the heuristic score.
- **The syndicate read.** `GET /networkfx/syndicates/:id/recommendations` still answers a GET. D765 PR 2 (#2145) turns it into a POST, and this PR leaves the verb to it so the two do not collide. Until #2145 merges, that read is a charged member run.
- **Pages.** `services/aiSurfaces.ts` adds `legalCapital`, `pipeline` and `networkEffects`, listed in `D552.md`.

### 4. PR 3, as built — no direct calls, and the test that keeps it so

- **`cloudflare-worker/test/ai_no_direct_calls_d766.test.ts`** reads every Worker source file, comments stripped, and fails on a model call made outside the router:
  - `.AI.run(` on the binding;
  - `<name>.run(` where `<name>` was taken from the binding (`const ai = env.AI`, `const ai = (env as …).AI`).

  It allows two files, each with its reason:
  - `services/aiRouter.ts`: every run, and the Llama Guard check inside it (D763);
  - `services/liveTranscription.ts`: a live WebSocket session, held in blocks and settled on its minutes by its own path (D658).

  An allowed file that stops calling the binding must leave the list. Document conversion (`toMarkdown`, `services/deckExtract.ts`) is not a model call on `run` and is not counted.
- **Two direct calls were outside the issue's table.**
  - **Build › Brand's logo** (`POST /brand/logo`, `routes/brand.ts` `aiLogo`) called FLUX.1 Schnell directly. It is now the member's `brand_logo` run: a new task class on FLUX.1 Schnell, drawn through D761's image shape (`draw`) on `/build/brand`, with the page `build` and the option `draw:brand/logo`. It is held, guarded and charged at the catalogue's image rate (`IMAGE_PRICED_MODELS`). The data URL carries the image's own type. A refused run is answered by `refuseRun`, and a model that cannot be reached still draws the inline SVG.
  - **`services/advisor/aiClient.ts`** called the binding directly in `runAdvisorTurn`, which had no caller. The file is deleted. Its daily advisor turn cap was never enforced, so `GOTCHAS.md`, `middleware/rateLimit.ts` and `types.ts` no longer say it is. `topology_d209` asserts the file stays gone.
- **The task count** is thirty-one (`AssistRail.jsx`, `aiSpend.ts`, `worker_rail_honesty_d400`). `ai_router_prices` accepts a model priced in the image view.
