## D6232 — Fund overview: the labels say what they show, the dead ends say what is true, and the chosen fund carries into the zones (#6232)

`/funds` (`InvestorFundLanding.jsx`) said several things wrongly. This fixes them ahead of the Fund redesign (#5994), and changes no Worker route.

### Corrections

| Was | Now |
|---|---|
| Fund accounting's "Contributed" showed `called_cents` | It reads Called. A separate Collected line reads `collected_cents`, the dated receipts of the fund rollup (D550). The summary strip also gains Collected beside Called. |
| — | When no receipt is recorded, Collected reads Not recorded, and the card says why: `capital_reason` from the rollup, else "No dated capital-call receipts are recorded." A recorded zero is still $0. |
| An LP with no recorded commitment printed $0: `commitment_amount` is `REAL NOT NULL DEFAULT 0`, so an unset row holds 0 | A commitment of 0 or none reads Not recorded (`lpCommitmentText`). Legacy LP amounts are USD dollars, so the conversion goes through `majorToMinor`. |
| The column "KYC / LPA" showed only the LPA | It is headed LPA. `GET /funds/:id/lps` returns no KYC state; the LPs zone shows KYC. |
| "Distribution execution remains in the detailed fund-administration tool" | That tool is `/admin/fund-admin`, admin-only. Now: "Distributed is what has been recorded on this fund. No GP page runs a distribution yet: Axal staff run one from the fund-administration console." |
| "Create a fund record in fund administration…" | The only page that creates a fund is that admin console. The empty state now says no fund names you as its GP yet, that Axal staff set one up, and what appears once one does. |
| Zone links dropped the chosen fund | See below. |
| `funds/lps`'s Comms log was disabled with "no LP correspondence is stored", false since D553 (migration 387) | It is a page handler that scrolls to the comms-log card on the same page (`id="comms-log"`). |

### The chosen fund

- The landing reads `?fund=` on load and writes it back when the switcher changes, replacing the history entry.
- Each card arrow and the call-ledger handoff open `<zone>?fund=<id>`. Each zone reads that parameter through `useManagedFund` (D371). A fund the reader cannot operate is ignored there, as before.
- The zone row (`ZoneNav`) takes an optional `carry` (`{ fund: id }`). `zoneSearch` starts from the venture (`projectSearch`) and adds only what `carry` names, so every other caller's links are unchanged.

### Files outside the issue's scope

- **`ZoneNav.jsx`:** the `carry` prop. Without it the zone row could not carry the fund.
- **`InvestorFundLPs.jsx`:** the Comms log handler and the card's anchor.

No other open PR touches either file.
