### The score rule, and the check behind it

The canvas draws numbers ("Team 78 · High", "▲4"). D1240 says a score is drawn as a band and confidence, never a number. #5900 says the score is announced only with values the Worker sends. So the rule follows from what the scoring read sends.

**The check (2026-11-14, `main`):** `POST /api/venture-scores/batch` (`cloudflare-worker/src/routes/venture_scores.ts`) answers each readable deal with `{ deal_id, project_id, locked: false, scopes: stripView(stored) }`, or `{ locked: true, reason }`, or `{ unreadable: true }`. `stripView` (`services/ventureScoring/access.ts`) maps each scope to `{ scope, state, band, confidence_word }`. It sends no value and no change. The route's header says the same: "state, band and confidence per scope". The test reads both files and fails if `stripView` gains a field.

**What holds:** bands plus confidence (D1240). The card, table and peek draw the Strong, Fair or Weak band and the High, Medium or Low confidence word. Risk reads Low, Medium or High risk on the same bands. A screen reader hears "Team: Strong, high confidence". Nothing reads a figure, and a missing score is never 0.

**Change is not drawn.** No investor read sends a per-scope change: the batch has none, and `GET /api/venture-scores/deal/:dealId` (`investorView`) sends no change field either. That read does send `value` when the investor has signed the NDA (`masked: false`), which bears on option C below.

### The owner's open choice

- **A.** Bands only, everywhere: Deal flow, Screening, Compare and the deal page. This keeps D1240, and it is **what is built**. Redraw the canvas's labels as Strong, Fair or Weak plus confidence.
- **B.** Numbers with band and confidence, as the canvas draws them. This needs a Worker change: the batch read must return the value (and a change, if "▲4" is wanted) to investors who may read the scorecard. That rule must also be squared with the NDA mask in `investorView`.
- **C.** The number only on the deal's Scorecard tab, behind the NDA rule that `GET /api/venture-scores/deal/:dealId` already applies. Bands on the lists and in Compare.

**Recommendation: A.** It is the rule on `main` (D1240). It needs no Worker change. It draws only what the batch sends. It also avoids a list that shows numbers for some deals and bands for others, which is what the NDA mask would cause under B. If the owner picks B, the Worker change comes first, as its own issue. Under C, `ScopeScore` stays as built for every list, and only the Scorecard tab would draw the value.

### The shared score (`ScopeScore`)

Its input is `flowModel.scopeCell(scores, key)` and the scope's label. Each absence is its own family, with its own word, a mark with no text, and its own style. That way no two absences look alike, and none of them reads as 0:

| Family | When | Word | Mark |
|---|---|---|---|
| value | `state: 'scored'` with a band | the band, `· High` (or a dot in compact cells) | none; low confidence is lighter, with a hollow dot |
| missing | the batch has no row for the scope (`not_read`, or absent) | Not scored | dashed bar, italic |
| not recorded | a row with too little recorded (`not_enough`) | Not enough recorded | solid bar |
| not expected yet | `not_expected` at the venture's stage | Not expected yet | dotted ring, faded |
| unreadable | the scope's read failed, or the whole batch (then "—", said "Unreadable") | Unreadable | red ring with "!" |
| locked | the founder has not shared the scorecard (`locked: true`) | Locked | lock |
| not shared | the batch left the deal out (the investor may not read it) | Not shared | dashed square, dashed underline |

### The three status families

Each family has its own shape, and the three are never the same pill:

- **Company:** a square, upper-case tag marked CO. No list read carries the company's stage, so the tag says **Not recorded** with that reason. `GET /api/deals/flow` and `GET /api/deals` select only the venture's name and sector from `projects`, though `projects.stage` and `projects.hq` exist.
- **My process:** a round violet pill with a dot, holding the firm's own stage from the flow (D1238).
- **Transaction:** a flat tag with a teal rule on the left, holding the round's status (`deals.status`, D1236: In intake, Screened, Raising, Funded, Not raising).

### The card's states (DE01b)

`dealCardModel.cardStates` reads each state from data the page already holds:

- **Normal:** none of the states below.
- **Low confidence:** the batch scored at least one scope, and every scored scope is Low.
- **Missing:** the scores were read, and a scope chosen for the card is not scored.
- **Locked:** the batch item is `locked`.
- **Stale:** on the board (not passed), and amber or red on the product's one stage SLA. That is `lib/dealFlow.js` `slaBand` with the Standard preset, 14 days or more of `days_in_stage`, the same rule the Deals zone filter's Stale uses. An unrecorded stage start is never stale. #6377 (D4815 part 3) leaves the stale count out of Needs your attention because no read records a threshold. If the owner wants no threshold either, the Stale flag is the only part to drop.
- **Passed:** the flow's `stage` is `passed`. A passed card is never also stale.
- **Unassigned:** a flow row with no `owner`.

A card can be in more than one state, for example stale and unassigned.

**Move to… stays on every card at every width.** It is a menu, so the keyboard and the phone move a card without dragging. On a phone, cards are never draggable, and Open, Move to… and Compare are 44px targets below 640px.
