## D1433 — Stripe mode safety and checkout readiness

Part 1 of #3703, assigned to S20. This change does not switch the account to live mode or enable any new price. S08 owns the separate D1434 cutover, and S12 owns the member and HQ screens.

### Mode-stamped catalogue

Migration 691 adds nullable `stripe_products.livemode`. S1 verified the historical mirror was sandbox data, so only rows present at migration time are backfilled to 0. Later missing stamps remain NULL. Sync and expanded-price fetches store Stripe's explicit mode; a price fetch must match both its price and product to the configured key's mode. D1 selectors and public plans/packs exclude the other mode and NULL. KV catalogue entries use `cache:catalog:live:test` or `cache:catalog:live:live`; the former unscoped key is never read.

A normal catalogue read can refresh an empty or mismatched mirror once per ten-minute window per binding/mode, including failed attempts. Checkout and public readiness reads do not trigger that refresh. An unsuccessful refresh does not make stale data sellable.

### Checkout contract

`stripeReadiness.ts` provides the shared key/mode and per-interval plan rule. The six refusal reasons are `secret_key_missing`, `publishable_key_missing`, `publishable_key_unknown`, `key_mode_mismatch`, `webhook_secret_missing`, and `price_missing`. Quote/start and the three legacy plan checkout paths return 409 `checkout_not_ready`, with `reason` at the top level of the JSON response, before any Stripe request. The plan sentence is “This plan can't be bought just now. Nothing was charged.” Pack orders check the same key readiness before cart pricing can reach Stripe; existing pack price validation remains in force.

Every sellable plan appears in the public plans read, even if its mirror price is absent. Its `checkout.monthly` and `checkout.yearly` are `ready` or `not_ready`, with no private reason. The six sellable entries remain the plan catalogue's source of truth. HQ checks add `sellable_plan_unpriced`, `pack_not_ready` and signing-secret readiness. HQ route wiring in `routes/catalog.ts` supplies the stored pack lines and configured signing-secret flag. Both existing portals return to `/account/billing`.

### Authenticated event receipts

The webhook verifies the signature and its integer timestamp (at most 300 seconds past or future) before touching D1. A valid event needs an id, type, explicit boolean mode and data object. Migration 691 records its id/type/mode/received time in `stripe_webhook_events`. Completed receipts return 200 without dispatch or another processing claim. An event for another mode is recorded and acknowledged without dispatch.

Two additional nullable receipt columns, `processing_uid` and `processing_until`, support an atomic five-minute claim across concurrent Worker instances. A competing delivery receives 409 for Stripe to retry. An abandoned claim can expire; a failed handler releases its own claim and returns 503. `handled_at` is set only after the handlers return successfully, with a compare-and-set on the claim owner. Existing handler-specific idempotency remains necessary for a crash after a side effect but before the completion write; this ledger does not promise transactional exactly-once execution across Stripe and D1. The existing expert Connect mirror remains best effort.

Migration 691 also declares `stripe_mode_cutovers` for D1434 with the S1-specified fields. This PR adds no cutover endpoint, performs no reset, and settles none of the owner's cutover, yearly-pricing, portal-change or tax choices.

### Validation

Tests use synthetic users, in-memory SQLite and mocked Stripe only. They exercise historical/unknown stamps, mode filtering/cache separation, bounded refresh, all six checkout refusals before provider access, ready checkout paths, legacy and pack guards, public/HQ projections, duplicate/concurrent/retry webhook delivery, timestamp boundaries and portal returns. Existing billing fixtures explicitly identify their test mode and signing/public-key configuration. Mutation checks and CI results are recorded in the PR.
