## D787 — A member reads their own AI cost per day and per model: tokens in and out, the other units, cost and charged

- **Status:** decided by the owner through S1 on #2212, 2026-10-20. Part of D785 (#2210), D-d and D-e. Built by S12.
- **Basis:** `origin/main` at `84f6e33b63`. Worker paths are relative to `cloudflare-worker/src/`.
- **Read by:** D789 (the member's cost page), which calls `aiBudgetApi.cost` and `aiBudgetApi.costCsv` (`frontend/src/lib/api/aiBudget.js`).

### 1. What was there

Every AI run is a row in `ai_usage_logs`: migrations 040, 319 and 493. The member's reads were `GET /api/ai-budget/me`, `/history` and `/runs` (D776, grouped by page, option or record), and D641's `GET /api/ai/me/spend`. None gave tokens per model per day.

### 2. The read

**`GET /api/ai-budget/cost?range=mtd|30d|prev_month&group=model|page|option`** (`routes/ai_budget.ts`, `services/aiCost.ts`).
- **Whose rows.** The signed-in member's own rows only. It takes no user id and no company.
- **The range.** UTC days, as `created_at` is:
  - `mtd`: the first of the month to today (the default);
  - `30d`: the 30 days ending today;
  - `prev_month`: the whole of last month.

  `range.from` and `range.to` are its first and last day, inclusive. The query bounds `created_at` with the end exclusive.
- **What it answers:**
  - `totals`;
  - `days`: every day in the range, a day with no runs as an empty `by_model`;
  - `models`, largest cost first, each with its catalogue `name` (`MODEL_NAMES`, then the D760 catalogue);
  - `groups`, by `group`, `model` by default;
  - `truncated`.
- **The CSV.** **`GET /api/ai-budget/cost.csv`** is the same query as CSV, one row per day and model with a run.

### 3. How a row counts

- **A refused row** (`refusal` set) counts in `totals.refused` and in nothing else.
- **Every other row is a run under its own `model`.** A Llama Guard row (D763, `guard_for` set) carries the guard model there, so it counts, and shows, as that model.
- **Tokens** are `prompt_tokens` and `completion_tokens`.
- **`units`** sums the units in `units_json` (D762) that are not tokens: audio minutes, characters, images and the rest.
- **`cost_usd`** is `est_cost_usd`, what the run cost Cloudflare. It is summed in whole micro-USD and given to six decimals, so a sum never drifts.
- **`charged_microusd`** is what the member paid, an integer.
  - A NULL charge (a row from before migration 493, or a run held for a D640 review) is never read as 0. It is counted in `not_recorded`.
  - A bucket whose every row is NULL reads `null`.
  - `not_recorded` is beside the issue's fields, so the page can say why a figure is missing.
- **`groups`:**
  - `group=page` keys by `rail_page`.
  - `group=option` keys by `rail_option` within its page, with `page` beside it. The label comes from the D764 matrix's option row where there is one.

### 4. Size and index

- **At most `MAX_COST_RUNS` (10,000) runs are read,** newest first. Beyond that, `truncated: true`.
- **No new index.** `WHERE user_id = ? AND created_at >= ? AND created_at < ?` is answered by `idx_ai_usage_user_created` (migration 040). The test holds the query plan to it.

### 5. Tests

`cloudflare-worker/test/ai_cost_d787.test.ts`: 9 cases on real SQLite.
- two models across three days;
- another member's rows;
- a refused run;
- a guard run;
- the UTC range bounds;
- the CSV against the JSON;
- the page and option groups, and a charge not recorded;
- the 10,000-run cap;
- the query's refusals and the index.

**Mutations.** 13 were each applied, run and caught:
- days with no runs dropped;
- token units counted in `units`;
- the `user_id` condition dropped;
- a refused row counted as a run;
- the end bound made inclusive;
- a NULL charge read as 0;
- the CSV's name column dropped;
- guard rows filtered out;
- `30d` made 31 days;
- the 10,000 slice removed;
- `truncated` set at exactly the cap;
- the oldest runs read first.

A larger `LIMIT` alone changes nothing a member sees, since the read is sliced to the cap.
