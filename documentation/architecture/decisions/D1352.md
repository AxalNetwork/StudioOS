### 1. The page claims no API

Axal VC confirms who the member is (Sign in with LinkedIn, OpenID Connect, D1350) and imports the `Connections.csv` the member downloads and uploads (D1351). It reads nothing else from LinkedIn.

- **The tagline:** "Sign in with LinkedIn, then import your connections from LinkedIn's data download."
- **The tools** on `/account/connectors/linkedin` are `read_identity` and `import_connections`. The import's code call is `parseConnectionsCsv(`, the server-side parser, so the D753 check that every tool names real code holds.
- **Can:** confirm who you are; import the connections file you upload.
- **Cannot:** read your LinkedIn messages; post on LinkedIn for you; see your connections without your file.
- Part 5 (#3569) adds a line only when API access is live. The test strips comments from the Worker's LinkedIn page block and fails if it says "API" anywhere else; the section's can and cannot lists are held word for word.

### 2. The section, when LinkedIn is connected

`LinkedInSection` reads `GET /api/linkedin/status` itself. An unreadable status says so; it never draws a disconnected page.

1. **Granted.** The scopes LinkedIn granted, in words (`openid` "Sign in", `profile` "Your name and photo", `email` "Your email address"); a scope Axal does not know is shown as LinkedIn names it.
2. **Download your data.** A link to LinkedIn's own download page.
3. **Upload and preview.** `POST /api/contacts/import/linkedin-csv?preview=1` writes nothing. The preview shows new, already in your Network, possible duplicates, repeated in the file, and could not be read, with a sample. A failed preview shows the Worker's sentence and leaves Import off.
4. **Import.** Enabled only after a preview. It commits the same file.
5. **Review.** The pending suggestions (`GET /api/contacts/import/reviews`), each with Merge, Keep both and Dismiss. **Merge is offered only between two rows of the member's own book** (`can_merge`, D1351 §5): a prospect is never merged into it.

The last import is one line: "Last import, 20 Oct 2026: 12 added, 3 matched, 1 skipped, 0 not read." A count the job did not record says "not recorded", never 0. A running or failed import says so.

### 3. Disconnect says what it deletes and keeps

- **`GET /api/linkedin/status`** now carries `imported: { linkedin_only, kept }`:
  - `linkedin_only`: rows a LinkedIn source created and no other source has touched;
  - `kept`: rows LinkedIn touched that also came from somewhere else.
- **The Disconnect dialog** shows "Also delete the 12 contacts imported only from LinkedIn" and "3 contacts also came from somewhere else, so they stay", before it is pressed. Unchecked by default. When either count is unreadable, it says so and draws no number.
- **`POST /api/linkedin/disconnect`** `{ delete_imported }` answers `kept_imported` beside `deleted_imported`. Without `delete_imported` it is `null`, and the page says only "Your contacts stay in your Network".
- The disconnect note on the connectors list now reads: "Sign in with LinkedIn is unlinked. Contacts you imported stay in your Network unless you also delete them below."

### 4. Your contacts, on Network › Relationships

No route listed `network_connections` for display, so this part adds one, Worker first:

**`GET /api/contacts/book?q=&page=`**: the member's own book, 50 a page, ordered by name.
- **Every statement binds the caller's id**, in the row read, the count and each subquery. Another member's rows are never read.
- **Each row:** id, name, email, company, title, LinkedIn URL, connected on, created, `sources` (distinct, sorted), `notes` (count) and `open_tasks` (follow-ups not done).
- **Search:** `q` matches name or company, case-insensitive. `%`, `_` and `\` are taken literally (`ESCAPE '\'`).
- Answers `{ total, page, page_size, contacts }`.

`NetworkContacts` draws it with search, pagination and one chip per kind of source: "From LinkedIn" (any LinkedIn source), "From a spreadsheet", "Added by hand" (`typed`, or no source). Each row opens its notes and follow-ups (D1351's `/book/:id/notes` and `/tasks`). It is lazy-mounted under the relationship requests, so the workspace's first paint is unchanged. Phone and dark mode are drawn.
