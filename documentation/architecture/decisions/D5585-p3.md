### 1. Adapters for the integrations the Worker already has

Each adapter implements part 2's `lookup` and `send`, keyed on the effect's idempotency key. Part 2's handler still runs
every check first (tenant, digest, head, audience, takedown, tombstone), so an adapter is only called for a release
that may be delivered.

| Target | Wraps | Publish | Lookup | Retract (the provider's own call) |
|---|---|---|---|---|
| `github_pr` (ref `owner/repo#N`) | `githubSync.ts` and the mirror's `GITHUB_ACCESS_TOKEN`, `GITHUB_REPO_OWNER`, `GITHUB_REPO_NAME` | a comment on the PR with the manifest uid, digest, audience and piece count, marked `<!-- axal-release key=… -->` and `<!-- axal-release-manifest … -->`; sent once (`retry: false`) | reads every comment page (100 a page, at most 10) for the key's marker | deletes each comment of the manifest (`DELETE /issues/comments/{id}`; a 404 is already gone) |
| `stream` (ref a 32-hex Stream uid) | the `STREAM` binding (`learningStream.ts`) | writes `studioos_release_key`, `_manifest` and `_digest` into the video's `meta`, keeping its other meta, with `requireSignedURLs: true` | the video's `meta` holds the key | removes those three fields; the video, its own meta and signed playback stay |

**Rules every adapter keeps.**

- **Credentials.** An adapter reads its existing binding. When it is absent it refuses with `target_not_configured`
  and calls nothing.
- **Refs.** A ref the credentials cannot reach is `ref_out_of_scope`: the GitHub token reaches the mirror's repository
  only. A ref not of the target's shape is `malformed_ref`. Neither makes a call.
- **Absence must be proven.** A lookup says `absent` only after reading everything. A PR with more than 1,000 comments
  is `lookup_incomplete`, so nothing is posted on a guess.
- **An unknown outcome is never resent.** No answer, a 5xx or a thrown binding call is `provider_unavailable`. The
  outbox retries it, and the next attempt's lookup finds a write that landed. A 401 or 403 is
  `provider_unauthorized`. Any other 4xx is `provider_rejected`.
- **Ids only.** No adapter sends content or source locators. The PR comment names the manifest, its digest, the
  audience and how many pieces it pins.
- **Retraction is done when nothing of the manifest is left.** A retraction's lookup is `confirmed` once no comment
  (or no Stream record) of that manifest remains. So a delete whose answer was lost is reconciled, not repeated. A
  later release's record on the same video is not touched.
- **Signed playback is never turned off.** Publishing to Stream records the release on the video. Who may play the
  video is still decided by the Worker, token by token. Public, unsigned playback would be a new exposure, so it is not
  done here.

Every refusal is thrown as part 2's `DeliveryRetry` with its code. The outbox records the code, backs off, and after
its attempts dead-letters the effect for a person to read. Nothing is silently dropped.

### 2. Targets with no integration refuse with `target_not_configured`

| Target | What exists on main | Why there is no adapter |
|---|---|---|
| `signed_document` | the native e-sign flow (`createAndSendEnvelope`, `voidEnvelopeForResend` in `routes/esign.ts`) | an envelope needs a sender, a recipient's name and email, and a rendered body. A release effect carries ids only (part 2), and nothing on the issue says who signs a release. Wiring it needs that owner decision. |
| `website_cdn` | Vercel is read-only by rule (D1096: no deployment, rollback or domain write); `CLOUDFLARE_API_TOKEN` is scoped to Workers Scripts only, not cache purge; the `PUBLICATIONS` bucket is private, with downloads through the Worker | there is no website or CDN publish integration to wrap |
| `external_distribution` | founder publishing (`publishCore.ts`), which by its own rule sends nothing automatically, only on the founder's confirm; event syndication (`services/eventSyndication/`), whose provider integrations are pending | wrapping either would turn a person's confirm into a drain's send |

These adapters refuse on every call, call nothing, and dead-letter after the outbox's attempts.

*Later parts:* `signed_document` is built in D5585-p4. `website_cdn` (a site record in `FILES`) and
`external_distribution` (over injected channels, none registered on main) are built in D5585-p6.

### 3. The drain: `drainReleaseEffects(env, opts)`

- **Off by default.** It runs only when `WORK_GRAPH_RELEASE_DELIVERY` is exactly `preview`. Unset, or any other value,
  it returns `{ ok: false, code: 'release_delivery_off' }` without reading D1 or calling a provider.
- **The handler map.** It merges part 2's release handlers over the caller's `opts.handlers`, so a caller cannot
  replace a release kind's checks. It hands the merged map to `drainEffects`.
- **Only kinds it can handle.** It passes `kinds: Object.keys(map)` to `drainEffects`, which now claims only those
  kinds. An effect of another kind stays pending. Without that filter, a drain that holds only release handlers would
  dead-letter every other kind as `no_handler`. A `drainEffects` call without `kinds` behaves as before.
- **Cost.** The result carries the outbox's D1 cost and the provider requests the adapters made, in total and by
  target. Part 2's delivery rows still carry each delivery's D1 statements and adapter calls.

`opts.adapters` replaces the real adapters (tests).

### 4. How it would be scheduled, after the owner approves

Nothing calls the drain today. Once the owner approves delivery:

1. Set `WORK_GRAPH_RELEASE_DELIVERY = "preview"` on a branch environment first, then in `[env.production.vars]`.
2. Call `drainReleaseEffects(env, { limit: 25 })` from the Worker's `scheduled` handler on an existing cron, inside
   `ctx.waitUntil`, after the other WorkGraph sweeps. A lapsed claim is safe: the outbox re-claims it and the lookup
   reconciles.
3. Optionally, a Super Admin's "Deliver now" on the release route calls the same function for one effect id through
   `deliverEffect`.
4. Turning the flag off stops delivery at the next tick. Queued effects wait, pending, and nothing is lost.

### 6. Rollback

Nothing calls the drain, so reverting the new service is enough. The two GitHub helpers and the `kinds` option have no
other caller. Leaving `WORK_GRAPH_RELEASE_DELIVERY` unset turns the drain off without a revert. If the owner had
enabled it, posted release comments can be deleted on GitHub by hand, and Stream `meta` keeps only the three
`studioos_release_*` fields.
