## D943 — One Lab decision path, confirmed excess places and frozen admin writes

Issue #2748, part of #2374. Worker only; no migration or new binding.

Both application decision routes use `decideCohortApplication` in
`admin_cohort.ts`. The legacy route translates accepted/refused to the cycle
statuses and requires the same internal reason. It resolves the newest assigned
cohort, refuses an application with no cohort with a clear 400, and rejects a
free-text cohort override. Neither route admits or activates a founder early:
the existing scheduler remains responsible for activation at the cohort's 1st
at 00:00 America/New_York, using the stored cycle start instant.

Approval counts approved and activated applicants in that cycle. A new place
past the configured maximum requires `confirm_over_places: true`; other truthy
values do not count. Re-deciding an already approved applicant uses no new
place. Rejection and waitlisting remain possible when the cohort is full.
An unreadable settings store returns 503 with a reason and saves no decision.

The guarded update checks capacity in the same SQLite statement that consumes
the place, and compares the applicant's previously read status. Concurrent
approvals cannot both take the last place; a competing decision returns 409.
The decision, mandatory cycle audit (including the explicit confirmation and
admin actor), and legacy status mirror commit in one D1 batch. Failure of any
statement rolls the batch back. Notifications follow a successful batch and
retain the shared decision-email ledger. The internal reason stays separate
from the optional applicant-facing note.

After authentication, the branch licence freeze now also gates grace,
week overrides, size settings, force-proceed and all host decisions. Existing
decide/interview/cancel gates remain. The shared gate keeps its established HQ,
active-branch and unreadable-licence semantics; reads are unchanged.

Mounted real-SQLite tests cover both decision doors, no early activation,
missing cohorts, role changes, terminal states, full and zero-place cohorts,
strict confirmation, concurrent approvals, atomic audit failure, and every
affected write on suspended and active branches. Key guards are mutation
checked. This changes no screen or route placement, so ROUTE_MAP is unchanged.
Production was not written or deployed by this task; the owner verifies deploy.
