## D4678 — Licence lifecycle and administrator state hold under concurrency (#4678)

- **Status:** built by S13 on #4678 (Licences audit 2/7).
- **Builds on:** D139 (the state machine in prose), D134 and D4472 (appointment), D145 (termination deprovisions), D135 (the compliance ladder).
- **Migration:** `202611071540_licence_revision.sql`.

### The question

The lifecycle routes validated a status they had read and then updated by id. Two requests that read the same row both passed, and the later write won, so a stale reinstate, activate, renew or suspend could overwrite a completed termination and leave an active licence whose territory was already released. Suspend and reinstate also reached `active` without the prerequisites activation checks. Appointment and detachment had the same flaw: an account could be promoted on a licence terminated a moment earlier, and a detach could leave an admin with no binding.

### What was decided

**One state machine, one compare-and-swap.** `services/licenceTransitions.ts` holds the table of statuses each verb starts from. A move is `UPDATE … WHERE id = ? AND status = ? AND revision = ?` with `revision = revision + 1`, in a batch whose later statements carry `appliedGuard` (the licence is at the new revision and the new status), and exactly one changed row is a success. The status is in the guard because another request can leave the same revision number behind. A stale move answers 409 `licence_changed` with the current status and revision. `?expected_revision=N` lets a caller state the revision it decided on.

**Terminated is terminal.** No verb starts from it, and a trigger refuses any UPDATE that takes a terminated row to another status. A termination releases the territory in the same batch, only if the termination applied, so it can no longer release the territory of a licence that is active again.

**Every way into `active` meets the prerequisites.** `activate` and `reinstate` (and the notice review that reinstates) re-check territory, seats, terms and the renewal date, in the blocker list and again in the UPDATE. `suspend` starts only from `active`, so a draft cannot be suspended and then reinstated into an active licence. Territory, seat and terms edits bump the revision, so an activation decided before an edit loses to it, and the compliance sweep bumps it when it suspends.

**Administrators.** A `terminated` licence takes no appointment (409 `licence_cannot_administer`). The binding, the role write and both audit rows carry one predicate inside the batch (the licence can still administer users and the account is not bound to another licence), and a trigger refuses a binding on a terminated licence. The retained-primary path (`grantLicence`) takes the same predicate on its role write. A detach states "the account is not an admin" in the DELETE itself, so a promotion that wins the race leaves a bound admin.

### What was not done

- `terminated` has no recovery workflow; none is specified.
- The brand-kit write and the D797 terms schedule do not bump the revision. Neither is an activation prerequisite that a race could change after the check except the brand kit's colours, which a white-label activation reads; a bump there is a follow-up if it proves to matter.
- Draft and pending licences may have an administrator appointed, as before. Only a terminated licence cannot.

### Tests

`licence_concurrency_4678.test.ts` interleaves a second request after the first one's read, for every verb, for appointment (plain and retained-primary paths), for detach, and for the sweep, and checks the table, the trigger and the guard directly. The existing lifecycle fixtures gained the `revision` column and, where they reinstate, a complete licence.
