## D692 — Each cycle's phone root has its One Next Thing: every overview read returns a focus, a meter and an index, in one shape

Status: Decided. Date: 2026-10-17. Slot: S12 (moved from S19 at the owner's instruction). Issue: #1701. Decided by S1 under the owner's standing rule. PR 1a started this record, PR 1b adds Validate's parts, and PR 2 completes it.

Part of D689 (#1654). On 2026-10-14 the owner asked to "implement mobile versions, artifacts" and to "Build any missing back end and wire everything". The canvases arrived with #1653.

On a phone, each cycle opens on One Next Thing (`Cycle Overview.dc.html`, CO:26, CO:280-282; the phone boards are in `Cycle Overviews · Mobile.dc.html`). It is:
- a focus;
- an optional meter;
- a Then line;
- "Everything else in <cycle>".

Before this, only Validate's overview returned those parts. With this record all four overview reads return them, so D703 (#1665) can draw the four roots without adding Worker code.

| PR | Holds |
| --- | --- |
| 1a | `services/cycleFocus.ts` (the shapes and helpers); Build's whole read; Raise's whole read; Grow's `first_kpi`, card rule and index; this record; the D685, D686 and D688 pointers |
| 1b | Validate's rules, meter `display` and gated index, in `services/validateFocus.ts` (after D690's last edit of `cycle_validate.ts`, #1692) |
| 2 | Grow's `tell_customers` and its Then, and `first_kpi`'s custom-KPI check (after #1697's migration 462) |

### Decisions

1. **One shape for all four cycles, sent by the Worker.** Each overview read returns:
   - `focus`: `{ rule, eyebrow, headline, why, cta: { label, href } | null, then }`;
   - `meter`: `{ key, label, count, target, target_reason, display }`. `display` is the value text the canvas draws ("7 of 9", "$900k of $1.5M"), so the browser never formats a figure;
   - `index`: `[{ key, title, detail, value, href }]`. `value: null` draws Not recorded. `''` draws nothing at the right. `"Unreadable"` says its source could not be read. Any other string is the value.

   Each part is null when it cannot be read (`part()`), and a failed part never fails the read.
2. **A review waiting outranks recording another interview.** Validate's rule 2 stays above the canvas's new default (PR 1b).
3. **A focus that asks for a write goes only to someone who can write.**
   - Each cycle's write gate:
     - Validate: `canWrite`.
     - Build: `canWrite`, Build's write gate.
     - Raise: every reader already passes `canWrite`.
     - Grow: `canAccessProject(…, { write: true })`. It admits partners, as Grow's writes do, and refuses an advisor member.
   - Anyone else gets the card rule, which only repeats a `next` their own cards already carry.
   - Two first steps keep their own gates, because every reader's cards already carry them: #1652's `first_feature` and Validate's rule 1.
4. **The focus is computed, never templated.** Every number is a stored value. A missing value drops its clause, never prints a bracket, and never prints 0 for nothing recorded. A counted zero is a real 0.
5. **"Nothing recorded" is read from the stores, not from a flag** (#1652's rule).
   - **Build** keeps #1652's own test: every card is empty, or Operating systems is `not_recorded` with no company and no weekly review.
   - **Raise:** nothing in any of these stores:
     - `readiness_items`;
     - a saved narrative version (`spinout_deck_overrides.version > 0`);
     - `pitch_decks`;
     - `data_room_files`;
     - a base `cap_table_scenarios` row;
     - an allocation in `projects.use_of_funds`;
     - `raise_prospects`.
   - **Grow:** nothing in any of these stores:
     - `product_feedback`, at any date;
     - `growth_channels`;
     - a recurring `revenue_entries` row;
     - a `project_metrics` snapshot;
     - an open role;
     - `growth_partners`;
     - `markets`;
     - a `compliance_events` row of any source;
     - a done checklist item (a Spin-Out Lab milestone counts);
     - with a company, a `company_people` row.

     #1697's `custom_kpis` joins this list in PR 2, because migration 462 is not on `main`.
   - **Seeded obligations count.** A `compliance_events` row seeded at incorporation (`source = 'auto'`) is a Grow record, as D699.md records for 'Active'. Leaving them out is a low-priority owner question on #1008. If the owner chooses that, D699's 'Active' check and `first_kpi` change together.
   - A card that is empty only for its range still counts as a record, for example a deck nobody has opened or feedback older than 90 days.
6. **Raise's call focus follows the round-calls flag, and rests while a call is open.**
   - With `ROUND_CALLS_ENABLED` off, a phone never pushes an action whose sheet says "Coming soon".
   - With a call open, the next thing is the investors, so the card rule leads.
   - Its Then reads "due or overdue this week", not the canvas's "due this week". `followUps` counts every overdue follow-up as well as those due within seven days, so the canvas's words would call an overdue investor due.
7. **Grow's "Tell the customers" focus opens Product improvement, not Share an update** (PR 2). An update reaches investors, the team and the network, never a customer (`updateShare.ts`). The CTA is "Open Product improvement".
8. **No href points at a route that does not exist yet.**
   - Build's CTA is `/build/connect?project_id=N`, Raise's `/raise/call?project_id=N`, and Grow's KPI CTA `/grow/focus?project_id=N`.
   - The history rows link `/build/tools`, `/raise/calls` and `/grow/updates`. Each is a `HistoryRedirect` that keeps the query.
   - Validate's review href keeps `/validate/interviews/<id>` until D704, and its Verdict row links `/validate/verdict` (PR 1b).
9. **The index is the canvas's rows, with stored values or Not recorded.** The tables below are the spec. There are three departures:
   - **Fundraising readiness** reads "Readiness score" with "<n> of 100" from the `readiness_score` figure. No ready threshold exists for "[5] of [7]" (D686.md §6), and inventing one would print a claim no store makes.
   - **The Calls row** is left out while round calls are off, so Raise's index has seven rows then.
   - **Durable company-building** prints "Compliance, next 90 days". The 90 is the card's fixed range, not a stored value.
10. **"Then" belongs to each cycle's established rule only.** The first-step focuses and the card rule carry none, and a Then whose value is missing is dropped whole. Validate's rule 1 keeps its Then (PR 1b).
11. **Validate's index moves to the Worker in one change** (PR 1b). `index` becomes the row list, and the `{ interviews_total, booked }` object goes.

The epic's decisions that bind this one:
- **D-f:** the Verdict row only for `canReadDecision` (PR 1b).
- **D-k:** a leading "Then " is stripped, the why says "the pain themes", and a row beside Not recorded keeps a neutral detail.
- **D-p:** Raise's and Grow's first steps, and Raise's call focus only with the flag on.
- **D-s:** copy that promises a behaviour must be true.
- **D-u:** each part rides on its overview's own gate, and no route is added.
- **D-b:** rule 2's href flips in D704.
- **D-m:** shared files are edited in named parts.

The why's count and target come from the meter, read once in the overview handler and passed to `focusOf`, so the why and the meter never disagree. A reader who cannot write gets the card rule or no focus: today's "Record a session." fallback is gone.

**The card rule** (`cardFocus`) takes the first card whose `next.href` is in the app:
- `eyebrow`: "<Cycle> · Next";
- `headline`: `sentence(next.text)`;
- `why`: the card's caption, or its reason;
- `cta`: `{ next.text, next.href }`;
- `then`: null.

With no such card, the focus is null.

- **The readiness row** shows the score out of 100 (decision 9).
