## D692 — Each cycle's phone root has its One Next Thing: every overview read returns a focus, a meter and an index, in one shape

Status: Decided. Date: 2026-10-17. Slot: S12 (moved from S19 at the owner's instruction). Issue: #1701. Decided by S1 under the owner's standing rule. PR 1 started this record and PR 2 completes it.

Part of D689 (#1654). On 2026-10-14 the owner asked to "implement mobile versions, artifacts" and to "Build any missing back end and wire everything". The canvases arrived with #1653. On a phone, each cycle opens on One Next Thing: a focus, an optional meter, a Then line and "Everything else in <cycle>" (`Cycle Overview.dc.html`, CO:26, CO:280-282; the phone boards in `Cycle Overviews · Mobile.dc.html`). Before this, only Validate's overview returned those parts. Now all four overview reads return them, so D703 (#1665) can draw the four roots without adding Worker code.

| PR | Holds |
| --- | --- |
| 1 | `services/cycleFocus.ts` (the shapes and helpers), Validate's rules and gated index, Raise's whole read, Grow's `first_kpi`, card rule and index, this record, and the D685 and D686 pointers |
| 2 | Build (`buildPhone`, after #1652's Worker PR), Grow's `tell_customers` and its Then and `first_kpi`'s custom-KPI check (after #1696's migration 462), and the D688 pointer |

### Decisions

1. **One shape for all four cycles, sent by the Worker.** Each overview read returns:
   - `focus`: `{ rule, eyebrow, headline, why, cta: { label, href } | null, then }`;
   - `meter`: `{ key, label, count, target, target_reason, display }`. `display` is the value text the canvas draws ("14 of 20", "$900k of $1.5M"), so the browser never formats a figure;
   - `index`: `[{ key, title, detail, value, href }]`. `value: null` draws Not recorded, `''` draws nothing at the right, `"Unreadable"` says its source could not be read, and any other string is the value.

   Each part is null when it cannot be read (`part()`), and a failed part never fails the read.
2. **A review waiting outranks recording another interview.** Validate's rule 2 stays above the canvas's new default.
3. **A focus that asks for a write goes only to someone who can write.**
   - The write gates are: Validate `canWrite`; Build `canWrite`; Raise, where every reader already passes `canWrite`; Grow `canAccessProject(…, { write: true })`, which admits partners as Grow's writes do and refuses an advisor member.
   - Anyone else gets the card rule, which only repeats a `next` their own cards already carry. Validate's "Record a session." fallback for readers is gone: with no card `next`, a reader's focus is null.
4. **The focus is computed, never templated.** Every number is a stored value. A missing value drops its clause, never prints a bracket, and never prints 0 for nothing recorded. A counted zero is a real 0.
5. **"Nothing recorded" is read from the stores, not from a flag** (#1652 decision 1).
   - **Raise:** no `readiness_items`, no saved narrative version (`spinout_deck_overrides.version > 0`), no `pitch_decks`, no `data_room_files`, no base `cap_table_scenarios`, no allocation in `projects.use_of_funds`, and no `raise_prospects`.
   - **Grow:** no `product_feedback` at any date, no `growth_channels`, no recurring `revenue_entries` row, no `project_metrics` snapshot, no open role, no `growth_partners`, no `markets`, no `compliance_events` row of any source, nothing done on the checklist (a Spin-Out Lab milestone counts), and, with a company, no `company_people` row. #1696's `custom_kpis` joins this list in PR 2 (migration 462 is not on `main`).
   - **Seeded obligations count.** A `compliance_events` row seeded at incorporation (`source = 'auto'`) is a Grow record, as D699.md records for 'Active'. Leaving them out is a low-priority owner question on #1008.
   - A card that is empty only for its range still counts as a record, for example a deck nobody has opened or feedback older than 90 days.
6. **Raise's call focus follows the round-calls flag, and rests while a call is open.**
   - With `ROUND_CALLS_ENABLED` off, a phone never pushes an action whose sheet says "Coming soon".
   - With a call open, the next thing is the investors, so the card rule leads.
   - Its Then reads "due or overdue this week", not the canvas's "due this week". `followUps` counts every overdue follow-up beside those due within seven days, so the canvas's words would call an overdue investor due.
7. **Grow's "Tell the customers" focus opens Product improvement, not Share an update** (PR 2). An update reaches investors, the team and the network, never a customer (`updateShare.ts`). The CTA is "Open Product improvement".
8. **No href points at a route that does not exist yet.**
   - The review href keeps `/validate/interviews/<id>` until D704.
   - Grow's KPI CTA is `/grow/focus?project_id=N`.
   - The Verdict row links `/validate/verdict`.
   - The history rows link `/raise/calls` and `/grow/updates`, each a `HistoryRedirect`. Build's `/build/tools` row comes in PR 2.
9. **The index is the canvas's rows, with stored values or Not recorded.** The tables below are the spec. There are three departures:
   - **Fundraising readiness** reads "Readiness score" with "<n> of 100" from the `readiness_score` figure. No ready threshold exists for "[5] of [7]" (D686.md §6), and inventing one would print a claim no store makes.
   - **The Calls row** is left out while round calls are off, so Raise's index has seven rows then.
   - **Durable company-building** prints "Compliance, next 90 days". The 90 is the card's fixed range, not a stored value.
10. **"Then" belongs to each cycle's established rule only.** Validate's rule 1 keeps its Then. The other first-step focuses and the card rule carry none. A Then whose value is missing is dropped whole.
11. **Validate's index moved to the Worker in one change.** `index` is the row list; the `{ interviews_total, booked }` object is gone, and there is no Interviews row. The phone card on `main` no longer reads `index.interviews_total` (#1655's part, landed through D694 PR 1), and until D703 reads the rows it takes "booked" from the Customer research funnel, which gives the same number.

The epic's decisions that bind this one: D-f (the Verdict row only for `canReadDecision`), D-k ("Then " stripped; "the pain themes"; a neutral detail beside Not recorded), D-p (Raise's and Grow's first steps; Raise's call focus only with the flag on), D-s (copy that promises a behaviour is true), D-u (each part rides on its overview's own gate; no route added), D-b (rule 2's href flips in D704) and D-m (shared files in named parts).

**The card rule** (`cardFocus`) takes the first card whose `next.href` is in the app. Its fields are:
- `eyebrow`: "<Cycle> · Next";
- `headline`: `sentence(next.text)`;
- `why`: the card's caption, or its reason;
- `cta`: `{ next.text, next.href }`;
- `then`: null.

With no such card, the focus is null.

### Departures from the canvas

- **Grow's CTA** is "Open Product improvement", not "Share an update" (decision 7; PR 2).
- **Raise's Then** says "due or overdue this week" (decision 6).
- **The readiness row** shows the score out of 100 (decision 9).
- **The Calls row** is absent while round calls are off (decision 9).
- **"Unreadable"** is a fourth index value the canvas does not draw (decision 1).
- **The Then rules** (decision 10): Validate's `next_interview` Then skips Customer research's `next`.
- **"Interviews this month: <n>."** is Validate's why when no target is set.
- **"1 customer"** is the plural for one customer (PR 2).
- **Build's systems clause** is dropped when that figure is not `ok` (PR 2).
- **No "Record a session." fallback** for a reader who cannot write.
