### 2. What is read, and from where

| Read | Used for |
|---|---|
| `GET /api/profiling/admin/list` (`requireAdmin`): every profile, newest first by `created_at`, no limit; `email, persona, legal_entity_name, founder_track, company_established, partnership_goal, agreement_type, admin_status, user_name`. Each read writes an audit row (D625) | The tab counts, the queue, the status chips, the categories chart, every profile |
| `GET /api/admin/studio/glance`, the `partner_profiles` lane: count and the oldest one's age | The Waiting tile: the same figure as Approvals lane 7 |
| `GET /api/profiling/admin/:email` (logged, D612) | The review, on Review or Open |

- **The list carries no date, no source, no account and no identity check.** So the queue is oldest first by reversing the newest-first list, and no row shows its age. Source, Account, Identity check and the per-row age wait for part 1.
- **No Draft state yet.** A row Eadwyn opened with only a name is `pending` like any other, so Waiting counts drafts. The page says so under the queue.
- **Counts are whole:** the list has no limit, so the chips and the chart count every profile.
- **A status the Worker should not have stored** (`profiling.ts` saves any unknown value as verified today; part 3) is drawn as "Not recorded", never as one of the three words, and counted apart under All.
- **A failed list read** says "We could not load partner profiles. This is not a sign that there are none." with Try again. **A failed record read** says "This profile could not be read." in the page; the browser `alert` is gone from this path.
