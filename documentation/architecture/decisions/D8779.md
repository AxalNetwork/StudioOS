## D8779 — The test-clock allowlist grows only against the tree's own base (#8779)

**Context.** D5614 forbids growth of `scripts/test-clock-allowlist.txt` by comparing the tree with `origin/main`
fetched at the moment the guard runs. A pull request's checkout is GitHub's merge commit, built on the main of when
the merge ref was last computed. When main removes a line after that (a fixed clock read, its entry deleted), the
tree still holds the line and the comparison reports growth the pull request never made. #8763 and #8766 failed
`suite (rest)` this way on stale merge refs.

**Decision.** In a `pull_request` run whose `HEAD` has two parents (GitHub's merge commit), and in a `merge_group`
run, the guard reads the allowlist at `HEAD`'s first parent, the base the tree was built from, fetching that commit at
depth one if the checkout lacks it. Parents come from the raw commit object, since a shallow checkout hides them
from `git log`. Any other event, a single-parent checkout, or a base that cannot be read keeps D5614's comparison
with the fetched `origin/main`, which still fails closed. A line the change adds is growth against either list.

**Rollback.** Revert `readBaseAllowlist` and its call in `scripts/check-test-clock.mjs`; the guard is D5614's again.

**Verified.** `frontend/test/test_clock_guard_5614.test.mjs` builds a depth-one clone of a merge commit whose main
has since shrunk: the main comparison reports the removed line, the base comparison passes, an added line still
fails, and `workflow_dispatch` and a single-parent head fall back to main. Mutation check: 6 mutations, 6 caught.
