### Built

Successful member-seat, host-event and admin-event cancellation starts removal
of the connected calendar copies StudioOS created. A ticket source is its
registration id, not the event id. Event cancellation includes every recorded
ticket copy for that event and its hosted copies, preserving other events,
users and kinds. Before provider work, cleanup persists a job through the existing
CF/D1 queue. At most two copies start immediately in Worker `waitUntil` (awaited
in a local request). Scan jobs dispatch at most five copy jobs and one continuation;
each copy job refreshes/deletes only its own user/provider mapping. Failed copies
retry independently through the existing queue and dead-letter handling, so one
refused provider does not prevent later attendees' cleanup. Delivery rechecks
that the source is still cancelled, preserving a newly active registration.
Duplicate delivery after successful removal makes no provider request. An uncertain
CF send falls back to D1 for this idempotent job only; duplicate acceptance is
safe and the generic producer keeps its no-dual-write policy for other jobs.
If neither transport can persist work, no immediate deletion starts; mappings
stay available for the existing stale-copy sync retry. Exact deliveries use the
mapping primary key; ticket/event scans use existing source and event indexes.
SQLite EXPLAIN controls check these plans without inventing a migration/index. Failed provider deletes retain their mapping
and a fixed error code for the existing stale-copy retry. The old generic cancel
hook ignored a false provider response and discarded the mapping; it now checks
the result. Logs hold outcomes, never provider response text. A manual calendar
compose/import has no tracked editable external id and is outside this cleanup.

The desktop next-event card draws `is_speaker` as You're presenting and a known
`comp_source` as Free seat with its source. Unknown historical sources remain
Source not recorded. The Join control requires the existing confirmed/paid seat
and link entitlement, waits until 15 minutes before start, and stays quiet for
cancelled/ended events or missing time/link. The page clock re-evaluates the
boundary. Authorised calendar-feed join links retain their existing policy;
this patch does not claim a new server-side time-access restriction.

Suggestions include the caller's actual registration eligibility, computed with
the same registration rule as the write. Explorers see the approved Popular
with new members copy; an ineligible suggestion replaces Register with Not open
to Explorers and its selected-profiles explanation. Unknown eligibility does
not offer Register. A failed suggestion read says Unreadable with Retry while
other page blocks remain readable. Existing registration gates are unchanged.

Published Hosting rows and Hosting soon use Check in on the event's own day,
through the existing check-in route. `eventTime.js` shares UTC parsing and
zone-day rules with the host header. Events' account-menu row is Current across
My events and child paths, on desktop and the phone account sheet.

The missing docs part is restored to D1030 §6; `design/EVENT_SYSTEM.md` §10 and
the page README now describe the actual surface and its limits.
