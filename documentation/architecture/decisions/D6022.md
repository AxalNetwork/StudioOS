- **Status:** built 2026-11-15 by S04. Filed under #4846 (Build v2).

  writer (`facts.can_set_target`) and only while no date is recorded. The phone

### 1. Set, Change, Clear

A writer sees **Set** while no date is recorded and **Change** once one is.
Change opens the same form on the recorded date and adds **Clear date**, which
sends `{ mvp_target_date: null }` (the route takes null). Each write re-reads
the module on success and keeps the form open on a refusal, showing the
Worker's own sentence (`Use a valid YYYY-MM-DD date`, `Forbidden`) as written.
A reader sees the date and no control. Clearing asks no confirmation: it is
one field, Set restores it, and the route logs the change.

### 2. `#mvp-target-date`

`mvpTable.js` names the anchor (`MVP_TARGET_ANCHOR`) and the link
(`mvpTargetHref(search)`). Arriving on Prototype / MVP with that hash opens the
form for a writer and focuses the date input, so the links that end there
(the overview figure below; Build's focus and attention once #6027 lands)
reach the control. A reader arriving on the hash gets the page as usual.

### 3. The overview figure

`FigureTile` takes `setLink = { href, text }`. While the figure has no value
and is not unreadable, its line becomes that link in place of "nothing
recorded yet". `CycleOverview` passes it for Build's `days_to_mvp` only, and
never on a read-only overview, so a reader is not sent to a control they do
not have. The overview re-reads its figure when it is opened again, so a saved
date shows there on return.
