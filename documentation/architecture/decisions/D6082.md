## D6082 — Edit and remove a Use of funds milestone (#6082)

- **Status:** Built, 2026-11-14 (frontend only).
- **Builds on:** D1177 (the Milestones and hires tab, UF5/UF6), D5069 (a milestone write carries the scenario's revision; `409 changed_since_open` and Review latest), D5375 (the Edit hire dialog this one is built like).

### What was wrong

`useOfFundsApi.updateMilestone` and `deleteMilestone`, and their Worker handlers (`PATCH` and `DELETE /cycles/raise/use-of-funds/milestones/:id`), existed, but no screen called them. A founder could add a milestone and then neither correct nor remove it.

### What it does now

- **Edit per row.** The Milestones table has an Edit button on every row when `viewer.can_write` is true. The Worker sets `can_write` false for a support session and for a reader (`services/useOfFunds/read.ts`), so neither sees the button or the extra column.
- **Edit milestone dialog** (`EditMilestoneDialog`, `UseOfFundsParts.jsx`). It has name, section, by and cost fields, with Save and Remove. A milestone is part of its scenario, so the scenario's revision (`base.revision`) goes with both: in the PATCH body, and as `?expected_revision=` on the DELETE, which has no body. On success the dialog closes, the notice says what happened and the plan is read again, so History shows the change.
- **Cost.** A recorded cost opens in major units. Emptying the field sends `cost_cents: null`, and the milestone stays Not costed, never 0. A cost that cannot be read keeps Save disabled. The month accepts `YYYY-MM` or a stored `YYYY-MM-DD`, the same as the Worker's `due()`.
- **Stale.** A 409 keeps the dialog open, says why and offers Review latest. `isStale` now also treats `scenario_changed`, the Worker's answer when another save lands between its revision check and the write, as stale, so that race gets the same Review latest as `changed_since_open`. Before this, the Edit split and Add milestone dialogs showed the sentence with no Review latest in that case.

### Tests

`frontend/test/use_of_funds_tool_d1177.test.mjs`, the five `D6082` tests: the save body, the reload and the notice; the emptied cost; the removal's query revision; both 409 codes; no Edit for a reader. Nine mutations, nine caught: the `can_write` gate, empty cost to 0, a dropped body revision, a dropped query revision, `scenario_changed` not stale, no reload, the dialog closed on error, the cost not prefilled, and an unreadable cost saved.
