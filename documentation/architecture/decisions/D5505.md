## D5505 — Run independent guards to completion (#5505)

S19 completes S18's preserved guard-runner work after the owner's transfer on
21 November 2026. The ordered catalog approach is retained: commands, arguments,
loaders, flags, preflight membership and prerequisite IDs live in
`scripts/guard-commands.json`. The full entry point is `npm run test:guards`.
Every command from the pre-migration package is retained in relative order;
a regression contract permits additions without pinning a total.

### Execution and prerequisites

The runner spawns argument arrays without a shell. Generation is its first
recorded prerequisite. It replaces the old npm pre-hook, which would abort
before independent guards could report. A failed prerequisite blocks only its
dependents. Other guards continue. Any failed, blocked, interrupted or not-run
guard makes the result nonzero. Signals interrupt the child process group,
record the interrupted guard and remaining not-run entries, and return the
signal's conventional nonzero exit code. Configuration or report-write failures
also fail the command. No guard is quarantined or disabled.

The CI rest part continues its independent package commands, remembers its
first failure status and runs the guards even after an earlier command fails.
The direct-test retry policy remains unchanged. If the part's initial generation
fails, the rest part still invokes the guard runner so it can record generation
and independent source-only checks; it preserves the initial failure exit code
and does not start tests that require the failed generation.

### Readers and local preflight

Guard wiring tests, the schema-change tool and red-CI triage read the catalog.
The schema tool derives ordering and Node flags from it; its list only selects
the schema checks. Red-CI triage still reads legacy chain logs and additionally
recognizes the runner's per-guard status lines. Required loader/argument
assertions remain in the individual guard tests.

`npm run test:guards:preflight` selects generation, decision headings, migration
identities, runtime DDL, auth inventory and undefined symbols, including their
prerequisite closure. It is advisory and needs the locked root/frontend/Worker
dependencies, but no built SPA. A Node 22 local run passed in 50.1 seconds on
21 November (36.4 seconds runtime DDL and 10.6 seconds undefined symbols).
These are measurements, not timeouts. Full guards still require the root SPA
build. A voluntary hook may invoke preflight; the task installs none.

### Result contract

The ignored local JSON files are `guard-results.json` (full) and
`preflight-results.json` (subset). Version 1 includes `scope: guards`, mode,
completion, aggregate exit code, interruption and ordered results. Each result
has stable ID, canonical argument array, source file, status, original exit
code/signal, blocked prerequisite IDs and elapsed milliseconds. It contains no
captured child output, assertion values, stack traces or environment contents.
The CLI removes old results before execution; consumers also clear stale records
before invoking the producer. The full output is the only evidence eligible
for the CI guard integration in D5502 part 2.

No production service, D1 data, permissions, deployment or required gate is
changed. The new PR remains draft at the owner's request.
