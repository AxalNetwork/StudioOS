### 1. What the run will write

The rail's run is not built here. Its row is fixed now, so the route below and the second PR agree. It is one `ai_rail_proposals` row (D780), with:

| Field | Value |
|---|---|
| `rail_option` | `draft:publish` (`PUBLISH_RAIL_OPTION` in `routes/publish.ts`) |
| `kind` | `draft` |
| `rail_page` | `Founder · Grow…`, the Grow page the run was asked from, e.g. `Founder · Grow · Product improvement` |
| `payload` | `{ project, module, text, source_refs, source: 'eadwyn' }` |

- `project` is the venture's numeric id, as `rail_run.ts` already writes it.
- `module` is one of `PUBLISH_MODULES`.

A run writes that row and nothing else. No draft and no send is written until the founder presses Use this draft.

### 2. Use this draft: `POST /api/publish/drafts/from-proposal/:proposalUid`

The route is inside `handle()`, so it has the same auth, refusals and sentences as part 1. It runs in this order:

1. **The proposal.** `getRail` loads the caller's own proposal. Another member's proposal, another option or another kind answers 404 `not_found`. A proposal no longer `proposed` (kept, discarded or withdrawn) answers 409 `wrong_state`. A module outside `PUBLISH_MODULES`, or a `project` that is not a number, answers 400 `invalid`.
2. **Who.** `canPublish` runs on `payload.project`. It refuses a co-founder, an admin, a partner, an advisor, an investor and a support session, as part 1 does.
3. **The draft.** One `publish_drafts` row is written:
   - `origin = 'eadwyn'`, with `rail_proposal_uid` set;
   - the founder is the author;
   - the payload's text (up to 20,000 characters) and `source_refs` (up to 50);
   - `team_only_included = 0`, whatever the payload says. Eadwyn never ticks team-only figures in. The founder does, and part 1's check blocks them until then.
4. **Once.** The insert is guarded by `WHERE NOT EXISTS (SELECT 1 FROM publish_drafts WHERE rail_proposal_uid = ?)`, and `changes` is checked. Two presses at once make one draft, and the second answers 409 `wrong_state`.
5. **The decision.** `decideRail(…, 'accept')` marks the proposal kept.

**Never:** the route does not preview, confirm or write `publish_sends`. A test reads the route's source to hold that.

**Discard** is D780's existing `POST /api/ai/rail/proposals/:uid/decide` with `discard`. It needs no new route, and it writes no draft.

**The client:** `publishApi.draftFromProposal(proposalUid)` in `frontend/src/lib/api/publish.js`. Nothing calls it yet: the lavender card is the second PR's.
