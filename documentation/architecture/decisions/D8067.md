## D8067 — The privileged PR class: one path list for T2, the landing bot, CODEOWNERS, a label and the ruleset (#8067)

- **Status:** built. Part of #8059. Feeds #8060 (the console ruleset) and #8082.
- **Why:** a privileged change was defined twice. Merge Control's `SENSITIVE` regex rated a path T2, and the landing bot's `PROTECTED` list said which paths no bot writes. CODEOWNERS named a third, older set. The two code lists had drifted: `.gitattributes` was protected from bots but not T2, and `scripts/**` was T2 but protected from bots only through the T2 check. A ruleset (#8060) would have needed a fourth copy.

### The list

- **Where it lives:** `merge-control/src/lib/classify.mjs` `PRIVILEGED_PATHS`, one gitignore-style glob per entry, each with its reason. `scripts/lib/privilegedPaths.mjs` re-exports it.
- **Why not in `scripts/lib`, as the issue first proposed:**
  - `classify.mjs` must stay import-free: the Merge Control Worker bundles it, and `policy_check_5620` and `control.test.ts` hold it to no imports and no reference to the product Worker's source (D5618, D5620);
  - every landing-bot workflow already checks out `merge-control/src/lib`, and none checks out `scripts/lib`.
  So the list sits in the one file every consumer already reads.
- **Globs, not regexes:**
  - `**` crosses folders and `*` stays inside one name;
  - a name also covers everything under a folder of that name, so `**/scripts` covers `frontend/scripts/x.mjs` and a file named `scripts`, as the old `SENSITIVE` did;
  - CODEOWNERS takes each glob as written, anchored at the root unless it starts with `**`;
  - the ruleset adds `<name>/**` for each name, because fnmatch does not treat a name as a folder.
- **Case:** matching in the classifier ignores case, as `SENSITIVE` did; CODEOWNERS and the ruleset match case. A mixed-case variant of a privileged name is still T2 and still protected from bots; only the owner request and the ruleset could miss it.

### The consumers

- **T2:** `pathPolicy` rates a path T2 when `isPrivileged(path)` or `SENSITIVE_NAME` (auth, billing and the other sensitive names) matches. `SENSITIVE_NAME` stays separate: it rates names, which CODEOWNERS and a ruleset cannot express.
- **The landing bot:** `rules.mjs` `PROTECTED` is the list's compiled regexes. `pathGuard` still also refuses anything T2.
- **The label:** `scripts/merge-policy.mjs` adds `privileged`, the changed privileged files, to its JSON. The `landing policy` workflow's `label` job sets `pr:privileged` when that list is non-empty, and clears the label only when the classification names none. An unreadable classification counts as privileged.
  - The job has only `pull-requests: write`, checks out nothing and runs no repository code; the policy job keeps its read-only token and its trusted-base checkout.
  - A fork's pull request is skipped, because its token cannot write labels.
  - `.github/labels.yml` declares the label, so `labels-sync.yml` creates it on merge.
- **CODEOWNERS:** a generated block between `# privileged:begin` and `# privileged:end`, last in the file, so it wins over `*`. `node scripts/check-privileged-paths.mjs --write` writes it; `--check` and `privileged_paths_8067` fail on drift. The rest of the file is unchanged.
- **The ruleset (#8060, #8082):** `node scripts/check-privileged-paths.mjs` prints the file-path condition; `--json` prints it alone.

### What changes for whom

- **Coverage:** the test pins the old `SENSITIVE` and `PROTECTED` and checks them against all 20,706 tracked files plus edge cases: no path either covered is lost.
- **T2:** of today's tracked files, only `.gitattributes` becomes T2 that was not; it was already protected from bots. D6679's T0/T1/T2 measurement is unaffected beyond that one file.
- **The landing bot:** it now also refuses `scripts/**` outside `scripts/ci/`, `attached_assets/`, the Worker middleware and every `package*.json`. All of these were already refused through the T2 check, so no bot write that passed before is refused now.
- **People:** CODEOWNERS already gave every path to the owner through `*`, so no new review request appears. The block makes the privileged set explicit, so a later CODEOWNERS change for the rest of the tree cannot drop it.

### Rollback

Revert the PR. The `pr:privileged` label stays on GitHub (labels-sync never deletes a label) and on the pull requests that carry it, until it is removed by hand.
