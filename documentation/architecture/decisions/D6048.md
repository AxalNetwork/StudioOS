## D6048 — Raise evidence: first-use setup, the admin viewer's empty state and the Home in RA-15's order (#6048)

- **Status:** built 2026-11-14. Raise v2 build 4 of 5, under D4863 (`design/incoming/Raise v2 Page.dc.html`, `design/incoming/Raise v2 · Boards.dc.html`). Boards built: RA-15 (A Home, B Founder empty, C Admin viewer empty) and RA-26a (Evidence at 390). RA-26b and RA-26c are #5075's; RA-26d is Capital relationships'.
- **Mints no route, changes no Worker.** `GET /api/cycles/raise/evidence` already returns every block the decision needs (items, proposals, claims, the claim check and `permissions.can_decide`).

### What changed

- **First use.** `viewModel(read).empty` (`evidenceView.js`) is true when items, proposals and claims were each read and each is empty, and the claim check did not fail. In that case `EvidenceMain` (`EvidenceView.jsx`) draws first use **instead of** the dashboard: no tiles, no claim filters, no coverage, no investor cards. Before this, VR13's empty card sat inside the full dashboard, so every tile read 0.
  - A founder (RA-15b): "Build your evidence base", with three setup actions: Connect a source (`/build/connect`), Record a session (`/validate/record`) and Open Validate records (`/validate`), then the hand-off to Fundraising readiness.
  - An admin viewer (RA-15c): "This venture has no visible evidence yet. Nothing is recorded that you can see. Founders add evidence from their own workspace." It has no actions, and VR12's admin banner stays above it.
  - How the page knows: `permissions.can_decide` on the read, the same signal as `model.canDecide`, which already hides every founder control (VR12). No new signal.
  - A block that could not be read is never taken for none. Unreadable items, proposals or claims, or a failed claim check, keep the dashboard with that block's Unreadable and Try again. Something waiting for review keeps the dashboard too, so its Accept stays in reach. VR15's note about a source that could not be read still draws on first use.
- **Home, in RA-15's order.** Figures (the six tiles) come first, then Needs you (the claims card, sorted Needs you first, now full width), then the evidence library (pinned evidence) beside the right column: Waiting for review, What investors see, Coverage by area, Investor opens. A page-level hand-off to `/raise/fundraising-readiness` closes the page. The per-area links in `SURFACES` and `AREA_HREF` are unchanged.
- **One action per claim (RA-15 Needs you, RA-26a).** `claimAction` names it: Review for a mismatch, Add evidence for Not backed, Back it for the founder's figure, Re-check for a record that changed or went stale. A backed, current claim has no action, and neither does an admin. Each opens the claim's drawer (VR2), where the change is made. Below `sm`, each claim is its own card and its action fills the width as a 44px target (`TAP_L`, `TAP_S`, `TAP_P` in `EvidenceParts.jsx`). From `sm` up, the list and the 36px buttons are as before.
- Forbidden (VR16), error (VR15 Crop B) and loading (VR14) are unchanged.
