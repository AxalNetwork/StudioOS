## D7145 — Restrict production release and operations credentials to main (#7145)

Cloudflare release and migration jobs declare the GitHub environment `production`. Backups, drills, probes and provisioning jobs declare `production-ops`, keeping their deployment records out of the release history. GitHub must restrict each environment to the single branch `main`. The two environments use different account-owned Cloudflare API tokens under the existing secret name. Both configure an empty reviewer list and a zero-minute timer. The release checks its environment's live branch policy before using its Cloudflare credential. D5501 candidate admission remains credential-free.

The live environment listing on 2026-11-17 exposed trailing U+2009 whitespace in the existing production name and no `production-ops` entry. GitHub's fixed `/repos/AxalNetwork/StudioOS/environments/production` endpoint resolves to the existing production environment, ID `21311264734`. The owner configures that environment's policies and secrets, preserves its history and creates `production-ops` before the workflow cutover. The preflight identifies production through the fixed endpoint and verifies its main-only branch policy.

The inventory records each workflow, job, trigger, intended rights and environment. CI checks the workflow definitions against it. The disabled compute-preview deploy continues to require its separate reviewer-protected environment and requires a preview-only identity. The two `pr-preview.yml` jobs temporarily use the repository secret until #7146.

The owner cutover includes resolution of the subsidiary and throwaway Worker publishing paths before they are used, verification of live branch policies and token scope, and revocation of the legacy token.
