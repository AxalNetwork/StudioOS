## D8747 — Keep the test-mode commerce fixture imports explicit (#8747)

This grouped change covers trackers #8747 and #8748. The fixture uses one
unittest import style and loads the optional HTTP module explicitly for its
availability check. The existing stand-in continues to cover environments
without that module.

The existing ten commerce tests pass with normal site packages and with
`python3 -S`, which excludes site packages and exercises the stand-in. The
standard frontend test wrapper passes. Test-mode key refusals, allowed test
keys, and the absence of network requests retain their existing coverage.

The trackers require a confirming default-branch scan after landing. Finding
evidence stays in the protected Code Scanning records.
