## D6249 — The report period read returns the frozen figures and the issuer's name (#6249)

Issue #6249, filed from the 2026-11-14 coordinator audit under #5994. `GET /api/funds/:id/report-periods/:periodId` (`readFundPeriod` in `cloudflare-worker/src/services/fundReports.ts`) returned the narrative, the dates, `issued_at` and `issued_by` as a user id. The period page could show prose but no numbers and no person. This read now adds three fields to an **issued** period. A draft reads exactly as D631 left it, and access does not change: `fundPageAccess` still lets an LP read only the issued periods of a fund they are an LP of.

### `figures` and `figures_reason`

The figures come from one of three sources, tried in order:

1. **The issued pack.** A period issued through the reporting queue (D712) has one issued `lp_quarterly_report` row in `fund_report_drafts` for its `fund_id` and `report_period_id`. These are the same rows `/lp-portal` reads. The read returns that row's `figures_json` with its `statements` list removed, plus `source: 'report_pack'`. The pack must carry `schema: 'lp_quarterly_report/1'`. The query also filters on `fund_id`, which `/lp-portal`'s query does not.
2. **The whitelisted snapshot.** A period the GP issued directly (D631) has no pack. Its `snapshot_json` is the whole of `readFundPage(env, fund, true)`, which is the manager's page: its period list includes drafts and it has `can_manage: true`. So the read does not pass the snapshot through. It copies four fields one by one: `totals.committed_cents`, `totals.invested_cents` and the reason for each. The result is `{ source: 'issue_snapshot', currency: 'USD', totals }`. The snapshot holds no NAV, so it cannot supply one.
3. **Nothing frozen.** When `snapshot_json` is null, the read returns `figures: null` with `figures_reason: 'Not recorded: no figures were frozen when this period was issued.'`

**Unreadable, not empty.** `/lp-portal` turns a failed pack query into "no figures" (`.catch(() => ({ results: [] }))`). This read does not copy that behaviour. Each of these cases throws, and the route answers 503 `fund_report_unreadable`:

- the pack query fails;
- more than one issued pack exists for the period;
- the pack JSON is corrupt or has an unknown schema;
- the snapshot cannot be parsed, is not an object, or is not in USD;
- a snapshot total is not null or a non-negative whole number of cents;
- a null total has no reason.

A snapshot shaped like a pack whose pack row is missing fails the totals check, so it is also Unreadable. None of these cases reads as zeros.

### `issued_by_name` and `issued_by_name_reason`

This is the issuer's display name only: `effectiveDisplayName` (D4616), meaning the profile's display name, else the account name. The read selects only `name` and `display_name`, so no email or other account field can leak. When the name is missing, the reason says why:

- no issuer was recorded;
- the issuing account no longer exists;
- the account has no name.

A queue-issued period shows the Super Admin who issued the pack, because that account is the period's `issued_by`.

### `corrected_by_period_id`

This is the latest issued period of the same fund whose `_receipt.corrects_period_id` names this period. Periods are ordered by `issued_at` and then `id`, newest first. A draft correction does not count, so an LP never learns a draft's id. The lookup reads `json_extract` only where `json_valid(notes)`, so one period with corrupt notes cannot make every other issued period in the fund Unreadable. That corrupt period's own read stays Unreadable. A correction of a correction names the correction it replaces, not the first original, so the field points one step along the chain.

### Frontend

`readablePeriod` in `frontend/src/hooks/useFundReport.js` accepts the new fields. A draft, which has none of them, stays readable. A malformed field makes the period unreadable: an unknown `figures.source`, a null `figures` with no reason, a name that is not a string, or a correcting id that is not a positive integer. Open PR #6331 changes the Fund Reporting pages but not this file, so the edit adds one clause and a helper.

### Tests

`cloudflare-worker/test/fund_report_period_figures_6249.test.ts` covers:

- a GP and an LP reading the snapshot totals;
- an admin and an LP reading a queue pack without its statements;
- a pack for another fund staying out;
- the failed, corrupt and unknown-shape cases above;
- the legacy Not recorded reasons;
- a corrected original, read by an admin, the GP and an LP.

`frontend/test/fund_report_period_fields_6249.test.mjs` covers the validator. The D631 Worker fixture now also applies migration 476, because an issued read looks up its pack.
