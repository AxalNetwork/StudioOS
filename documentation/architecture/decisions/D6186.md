## D6186 — The deal page's Documents tab for the founder, an Admin and an Operating Partner (#6186)

Part of #4815. One Documents design for every role. The investor's tab has
been DL8 since D1153. Everyone else got the legacy `DocumentsTab` in
`DealRoomPage.jsx`, whose rows could not be opened and were drawn in the
pre-redesign style.

### Decision

1. **The tab is `pages/deal/DealDocumentsStaff.jsx`.** It uses the frame's
   cards (`CARD`, `EYE`, `SUB`, `H3`). Its rules and words are in
   `dealDocumentsModel.js`. The viewer comes from `dealAudienceModel.js`
   `viewerOf`, and a Super Admin reads as an Admin. The legacy
   `DocumentsTab` is removed.
2. **The founder** (their own deal) sees:
   - **Their data room**, from the owner's own read (`GET /api/data-room/:projectUid`, the deal's `profile_uid`):
     - files, folders, open grants, and how many times the room was opened this week;
     - a link to Raise › Data room;
     - a link to its Activity tab, which names who opened what. The room belongs to the venture, so the deal's room is its project's room. No deal-scoped read is needed or added.
   - **Access requests** (`GET /api/data-room/:projectUid/requests`):
     - how many wait;
     - a link to Data room › Requests, where they decide them.
   - **Deal paper**: the envelopes they are party to (`GET /api/legal/esign?deal_id=`, scoped by `esignEnvelopeScope`).
   - **Documents**: the venture's documents list.
3. **An Admin** sees every envelope on the deal and the documents list. A
   plain line says the founder's data room opens to staff only through an
   audited support read (`POST /api/data-room/:projectUid/support-read`), and
   that the founder is told. The tab reads nothing from the room.
4. **An Operating Partner** sees the envelopes they are party to and the
   documents list. The list is behind the venture's NDA, as it is for an
   investor (D4631), and the tab says so. A line says the data room is not
   open to them (DL15: Never).
5. **No document row without a reason.** No route serves a `documents` row's
   text: `legal.ts` `safeDoc` redacts it on purpose (Security #8), and
   LegalPage's viewer shows "No file content available". This PR adds no
   route that would undo that. Instead, `GET /api/deals/:id/documents` now
   returns `in_paper` (a boolean: the row was sent through e-sign) and no
   other new field; the envelope id is not named. Each row then says:
   - when `in_paper` is true, "Sent through e-sign. Open it from Deal paper.";
   - otherwise, that it is a record without a file and there is nothing to open.
6. **Four states for every read**: reading, Unreadable with Try again (with
   its own "That is not a claim that…" line), empty in words, and the rows.
   No read shows an empty state after a failure.

### Departures

The canvases draw only the investor's Documents board (DL8 and its access
states in `Deal page · Boards`). These views are built in DL8's card language.
The PR lists that as a departure, until a board draws them.
