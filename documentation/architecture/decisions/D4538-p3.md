## D4538 part 3 — HQ's company-skill moderation queue shows an extension's lineage (#4538)

Part 2 (`D4538-p2.md`) recorded an extension's lineage (`based_on_skill_uid`, `based_on_version`, `fork_reason` on `agent_skills`) and listed "No HQ lineage view" among its departures: HQ's moderation queue did not show it. This part closes that gap. The owner chose it on 2026-11-13.

### What is built

**Worker (`routes/admin_company_skills.ts`).** Both moderation reads, `GET /api/admin/ai-agents/company-skills` (the queue) and `GET …/:uid` (the detail), carry `based_on` on every company skill:

- a standalone skill reads `based_on: null`;
- an extension reads `{ skill_uid, version, name, base_readable: true }`. `name` is the HQ skill's name **at the published version the extension was built on**, not its current name. A rename in a later HQ version does not change what the queue says the company forked;
- an extension whose base cannot be read reads `{ skill_uid, version, name: null, base_readable: false }`. "Cannot be read" covers three cases: no HQ row with that uid, no published version with that number, or a uid that is not an HQ skill. It is never `null`, which would pass the extension off as standalone (Honesty).

The base is read by one bound query per extension: `agent_skills` joined to `agent_skill_versions` on `based_on_version`, within `scope = 'hq'`. This is the same scope rule as `team_skills.ts` `baseOf`, so a lineage column can never name another company's skill. A standalone skill runs no query. A query that throws reads as unreadable.

The detail also carries `fork_reason`: the company's reason, on an extension, and `null` on a standalone skill. HQ moderates company-authored text, and the detail already shows the company's SKILL.md, so the reason belongs beside it. The queue row does not carry it, because the row stays compact.

The gate (`requireSuperAdmin`, 403 otherwise), the moderation actions and the rest of the response shape are unchanged. No table is written. The read adds no migration: the columns are part 2's.

**Frontend (`pages/hq/aiAgents/HqAiAgentsPage.jsx`, `aiAgentsModel.js`).** `lineageLine(based_on)` gives one line:

- "Based on <HQ name> v<n>" on an extension;
- "Base not readable" when the Worker says `base_readable: false`, or when the name or version is missing;
- nothing on a standalone skill.

A small `Lineage` component shows it under the skill's name in the queue row and under the heading in the detail. The detail adds "Why the company extended it: …" on an extension. The screen is not restructured: there is no new column, tab or control, and both lines use the page's existing `MUTED` class, which already has its `dark:` variant.

### Tests

- `cloudflare-worker/test/hq_queue_lineage_4538.test.ts`, 3 tests on the node:sqlite D1 fixture:
  - an extension's lineage in the queue and the detail, named at its base version after HQ renamed the skill in version 2;
  - `fork_reason` on the extension and `null` on a standalone skill;
  - a standalone skill reads `null`;
  - a missing HQ row, a missing version and a company skill's uid are each flagged unreadable, in both reads;
  - a plain admin, a company editor and a member get 403 on both reads, with nothing of the lineage in the refusal.
- `cloudflare-worker/test/company_skill_moderation_d4161.test.ts`: its exact queue row now includes `based_on: null`.
- `frontend/test/hq_queue_lineage_4538.test.mjs`: the line's three states, and that the queue row and the detail both render it.

Seventeen mutations each fail a suite, and both suites pass unmutated. Twelve are of the route:
- the name nulled;
- the join on the current version instead of the base version;
- the `scope = 'hq'` guard dropped;
- `base_readable` forced true;
- an unreadable base returned as `null`;
- the standalone guard dropped;
- `based_on` dropped from the queue and, separately, from the detail;
- `fork_reason` nulled, and given to a standalone skill;
- either read's `requireSuperAdmin` removed.

Five are of the screen:
- `base_readable` ignored;
- a standalone skill shown as unreadable;
- the version dropped from the line;
- the line removed from the row and, separately, from the detail.

### Departures

- **The name is the version's, not the HQ skill's current name.** The issue asked for "the HQ base skill's name". The version's name is what the company copied, so the queue shows that one.
- **`base_readable` is also `false` when the version row is missing** while the HQ row exists. The company cannot have been built on a version HQ cannot show.
- **No link to the HQ skill.** The line is text. A link to HQ's skill detail would be a layout change, and no canvas covers one.
