## D865 — Telegram speech admission and shared translation

Issue #2511, part of #2508. S20 · Codex · 2026-10-23.

### Decision

Use the merged D857 translation service (#2502, #2536, migration 527) for
Telegram, as for WhatsApp. No second translator or new migration is needed.
Keep the **5 MiB inclusive cap** and **`TELEGRAM_VIDEO_NOTES = false`**.
Direct MP4-with-video input and a 5–20 MiB single-request path remain
**UNVERIFIED**. This is S1's permitted conservative outcome on #2511,
not a claim that either speech model rejects those inputs.

The owner's preferred 20 MB option was conditional on measured support and
cost. That condition has not been satisfied, so this PR changes neither the
recorder's chunk rule nor the channel rollout switch.

### Telegram through D857

An assigned chat's typed text becomes a final transcript segment under
D684/D756. Voice notes, audio files and audio documents wait for the
contact's own YES. The existing queued follow-up re-checks consent before
`getFile`, fetches admitted audio, and uses the recorder's metered
`transcribeVoiceNote` stage. Original-language text is appended once.

Both paths enqueue the existing Validate engine. Its structuring stage calls
`translateSession` before reading the transcript. This follows the existing
manual/automatic processing preference and chat quiet window; it does not
add model work to the webhook. A consent withdrawal still blocks processing.

D857 detects each final segment, records `source_lang`, and stores the
translation encrypted beside the original. The target is the founder's
working-language setting, then account locale, then English. A segment
already in that language is marked `same`, with no translation model call or
AI-token hold. A refused/failed translation leaves the original usable,
marks translation pending, and uses D857's bounded retries.

Telegram's `from.language_code` is an **app preference**, not detection.
The adapter deliberately does not forward or persist it as a segment's
language. D857's script/word detection and metered ambiguous-language
fallback remain authoritative. Tests supply a conflicting app language and
verify French text and Spanish speech produce `fr` and `es`, never that
preference. No new hint field or contact-language fact is introduced.

Speech-to-text and translation use `aiRouter`, which reserves AI tokens
before a model run and settles/releases through the existing ledger.
Translations retain their reservation reference; a replay adds no hold.
The existing per-connection daily voice cap still applies. Refused media
never reaches a model or takes an AI-token hold.

### Why the admission rules stay conservative

- `telegram.ts` refuses a declared oversize note before `getFile`, checks
  Telegram's reported size before the download, and bounds the streamed body
  at the recorder's 5 MiB cap, including when either size is absent.
- `routes/channels.ts`, `ingestChannelAudio` and `putChunk` independently
  enforce the same recorder bound. Raising Telegram's constant alone would
  download a note the shared intake refuses.
- The current router constructs a numeric audio array in memory. A 20 MiB
  input expanded to eight-byte numeric elements can occupy about 160 MiB
  before other allocations. This is an allocation estimate, not a measured
  peak; changing the recorder limit alone is not a safe large-note design.
- A round video normalises to `video/mp4`. Even if its switch is enabled,
  the shared audio MIME rule refuses that type before download. Enabling it
  requires measured direct-container support plus a compatible intake, or
  extraction of its audio track elsewhere into an admitted audio file.

`voiceFailures.ts` continues giving the founder the specific refusal sentence
on the waiting note. The Telegram connector and its frontend fallback explain that a round video's
audio track can instead be sent as an audio file up to 5 MB. No video is
silently treated as an empty transcript.

### Provider evidence and remaining measurement

Official sources re-read on 2026-10-23:

- [Whisper Large v3 Turbo](https://developers.cloudflare.com/workers-ai/models/whisper-large-v3-turbo/)
  documents speech recognition/translation, audio input, and per-minute pricing.
- [Nova-3](https://developers.cloudflare.com/workers-ai/models/nova-3/)
  documents audio input and different HTTP/WebSocket prices.
- [Cloudflare's chunking tutorial](https://developers.cloudflare.com/workers-ai/guides/tutorials/build-a-workers-ai-whisper-with-chunking/)
  splits large audio to stay within memory and execution limits.

Those documents do not measure Telegram MP4-with-video or Axal's 20 MiB
intake. Preview authentication succeeded in this continuation, but no live
media/cost experiment was completed: an isolated metered preview media
harness and generated valid MP4/large-audio controls are still required.
No live model call, deployment or production data access was made for this work.
Do not mistake provider list prices or the fixture's ledger amounts for
measured live cost. The router's catalogue remains the charging authority.

Owner follow-up, **preview only**: use generated media with Whisper Turbo
and Nova-3, through an isolated metered harness. Test a sub-5 MiB MP4 with
both audio and video tracks, a silent-video control, and audio at 5 MiB,
5 MiB + 1 byte and 20 MiB. Record model, bytes, duration, outcome, latency,
peak memory and actual usage/cost as counts only. Distinguish Axal's refusal
from a provider refusal. Keep the controls outside the recorder's normal
chunk intake; never raise its cap for an experiment. No customer media,
transcript, token or meeting/chat identity belongs in logs or reports.

### Verification

`telegram_speech_translation_d865.test.ts` uses real SQLite with stubbed
Telegram and Workers AI. It covers the inclusive cap at every boundary,
round video both off and a hypothetical enabled switch (still MIME-refused),
voice/audio/audio-document metering, held notes and withdrawal before fetch,
daily/budget refusals, French text and Spanish-note translation through the
shared structuring entry, language preference mismatch, encrypted translation,
source preservation, free same-language text, translation refusal/retry and
reservation settlement. Deliberate isolated mutations exercise the refusal,
consent, cap, translation, encryption, ledger-link and connector-copy checks.
These prove integration and accounting, not live speech capability.
