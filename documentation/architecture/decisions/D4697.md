## D4697 — Expertise › Proof reads its consents once, and an overview draws each section when it answers (#4697)

- **Status:** Built for #4697, 2026-11-07. It covers the Worker and the bucket boards (frontend).
- **Builds on:**
  - migration 204 (proof consents);
  - #4689 (the paged proof list);
  - D403 (bucket boards read each zone's own endpoint).
- **No migration.**

### What was decided

1. **One consent read per page, not one per claim.**
   - `GET /api/advisors/me/proof` read each item's consents in its own statement. A 200-claim page cost 201 round trips.
   - It now reads them in one statement and groups them in memory:
     - the ids are one bound JSON array (`json_each(?)`), not an interpolated `IN` list, which `check-sql-prepare` refuses;
     - the statement joins `advisor_proof_items` on `advisor_id = ?`, so it can only read the caller's own items;
     - each item keeps its consents oldest first, as before.
2. **Each section draws when its own source answers.**
   - `useBucketSources` waited for `Promise.allSettled`, so the slowest source held every section on its skeleton. On `/expertise` that source was Proof, because of the per-claim reads above.
   - Each source now publishes its state as soon as it settles.
3. **No stale answer lands.**
   - Every read carries the run it started in and its own attempt number.
   - The run changes when the board changes or unmounts, and the attempt number changes on a retry.
   - An answer from an earlier board, or from a retry that was superseded, is dropped.
4. **A failed section retries on its own.**
   - Each source's state carries `retry()`, and `BucketBoard` draws "Try again" on that section only. The other sections are left as they are.
   - A failure reads as one fixed sentence (`SOURCE_UNREADABLE`, "This section could not be read."), never the raw error text.
   - The section still says why nothing is drawn, so an unreadable store never looks like an empty one.

5. **The shared paged-list helper prints a fixed sentence.**
   - `usePagedList` (`pages/advisor/expertise/pages.js`, used by Services, Proof, Thinking and Visibility) printed the thrown error's text when a read failed: `e?.message || errorText`, and the same for "Show more".
   - A thrown message can carry a driver or SQL fragment. The helper now prints `errorText` for a first page and `moreErrorText` for "Show more", and sends the thrown error to `reportError` (`expertise:list`, `expertise:list-more`), so nothing is hidden from the logs.
   - Visibility passes its own `moreErrorText`: "The next links could not be read. Try again."
   - Looking a refusal code up in the kit (`refusalText`, from #4670) waits until #4670 is on `main`; this branch does not depend on it.

### Measured, not assumed

Both measurements come from synthetic fixtures. The tests that take them print the figures; they are not pass/fail thresholds.

| What | Before | After |
| --- | --- | --- |
| Consent reads for a proof page of 1, 50 and 200 claims (`advisor_proof_batch_4697.test.ts`) | 1, 50, 200 | 1, 1, 1 |
| `GET /me/proof`, 200 claims, median of 5, over the in-memory D1 shim | 12.5 ms | 9.3 ms |
| Time until Profile draws while Proof takes 150 ms (`bucket_sources_4697.test.mjs`) | 158.4 ms | 5.1 ms |

The shim has no network, so the middle row shows only the work removed. In production each removed statement is a D1 round trip.

### Not in this decision

- The other boards' sources are not changed. Every board gets the per-section publishing and retry, because they share `useBucketSources`.
