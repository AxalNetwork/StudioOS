## D704 — /validate/interviews, /validate/pain-map and /validate/hypotheses stop being pages and redirect to their modules

Issue #1666, part of D689 (#1654). On 2026-10-14 the owner asked to remove the Interviews, Pain map and Hypotheses pages, with Interviews moving to Customer research, Pain map to Problem discovery and Hypotheses to Experiments and evidence. #1659 (D697), #1658 (D696) and #1702 (D693) move what the pages do, on D690's reads (#1690, #1691, #1692). This decision removes the pages and everything that still names them, and keeps the verdict history growing once they are gone.

It ships as two PRs.
- **PR 1** is the Worker's part, touching no page: the spend alias, the review href and the history write.
- **PR 2** changes the surface value, adds the redirects and does the removal.

This first version records the decisions and what PR 1 has shipped so far. PR 2 amends it.

### Decisions

1. **The three addresses redirect, keeping the query and the hash (D-b).** The rest of the query is always kept.

   | Address | Lands on |
   |---|---|
   | `/validate/interviews` | `/validate/customer-research` |
   | `/validate/interviews?new=record` | `/validate/record`, with `new` dropped |
   | `/validate/interviews?new=notes` or `?new=upload` | `/validate/customer-research?log=notes` or `?log=upload`, #1659's opener |
   | `/validate/interviews?new=<anything else>` | `/validate/customer-research`, with `new` dropped |
   | `/validate/pain-map` | `/validate/problem-discovery` |
   | `/validate/hypotheses` | `/validate/experiments` |

   `/validate/interviews/:id` keeps #1658's redirect. `/validate/verdict` stays #1704's static line rendering the Verdict module.

   The table is `validateZoneTarget(zone, search, hash)` in `frontend/src/pages/cycles/validateRedirects.js`, which is pure and returns `{ pathname, search, hash }`, or null for a slug that is not one of the three. Only the Interviews page ever read `?new=`, so Pain map and Hypotheses pass it on untouched. PR 2 mounts it through `ValidateZoneRedirect` in `App.jsx`; until then nothing calls it.
2. **`/validate` stops branching.** Every admitted role gets the cycle page, and `founderValidateLanding` goes.
3. **The Validate bucket stays, with no zones.** Its prefix still drives full bleed and `bucketForPath`. `zoneForPath` answers an empty bucket's root with `null`, never `undefined` (`shellConfig.js`, shipped ahead of PR 2). Validate keeps its four zones until PR 2 empties them.
4. **The old canvas is retired in place,** as D670 retired Signals. `Pages · Founder Validate.dc.html` stays in `design/canvases/integrated/`. Its ROUTE_MAP row is graded RETIRED, and its four routes join the founder's `excluded` list in both profile guards.
5. **Every link goes straight to the module.**
   - The three tool links and the `FOUNDER_TOOLS` row go.
   - The founders door's Validate chapter lists `MODULES.validate`.
   - The Lab's link opens the interview's record.
6. **Nothing the four zones did is lost.** This decision rebuilds none of the verdict zone's parts; the census below names each one's home.
7. **The history keeps growing without the board page.** The Experiments and evidence read records verdict changes with `buildBoard`'s helpers and writer. It records every live claim before search, filters and paging, and before it loads the history. It writes only on a change, logs no activity row, and never fails the read.
8. **The Worker names the modules, and the spend history follows them.**
   - `AI_SURFACE.validateInterviews` becomes `'/validate/customer-research'` in PR 2; its key stays.
   - A frozen `AI_SURFACE_ALIASES` maps each old path to its module. The per-page spend read and `/account/usage`'s By page breakdown count an old path's rows under that module, the caller's own rows only.
   - No row is rewritten, and a read of an old path itself counts only that path.
9. **The review focus opens the interview's record (D-g):** `/validate/customer-research/${interview_id}?session=${session_id}`.
10. **The old decision routes go (D-f).** `founder_validate.ts`'s decision GET and POST are removed with both client methods. #1702 and #1704's Verdict module answers instead.
11. **Fill keys stay.** `validate/pain-map` and `validate/hypotheses` are identifiers, not routes, and renaming them would orphan stored proposals.
12. **Dead code goes (D616).** `FounderValidateWorkspace.jsx` goes, and so does every file or export only it imports, found by grep when PR 2 starts. What #1659 moved, imports or calls stays.
13. **One guard keeps the old paths out of the code.** A test reads every source file through `_codeOnly.mjs` and fails on any of the three paths outside the redirect code and the alias map.
14. **Removal is last, in two PRs**, as above.

### The spend alias (PR 1, step 1)

`cloudflare-worker/src/services/aiSurfaces.ts` exports a frozen `AI_SURFACE_ALIASES`:

| Old page path | Counts under |
|---|---|
| `/validate/interviews` | `/validate/customer-research` |
| `/validate/pain-map` | `/validate/problem-discovery` |
| `/validate/hypotheses` | `/validate/experiments` |

- **Read by the two spend reads only.** The router never reads it: it records the path it is given, so a run on an old page keeps its own path until PR 2 moves the value.
- **The per-page read** (`loadMyAiSpendForSurface`): the month sum and the last run match `u.surface IN (?, ?)`. Both values are bound: the asked surface and the old path that aliases to it (`surfaceAlsoCounts`), or the asked surface twice when none does.
  - The unattributed sum and the caller scope (`aiUsageSelfScope`) are unchanged.
  - No `${…}` is added to a `DB.prepare` template.
- **The By page breakdown** (`loadMyAiSpend`'s `by_surface`): the query is unchanged. Each row's surface folds through `surfaceCountsAs` in JS, calls and spend are summed, and the entries are re-sorted by spend. The month's total is unchanged.
- **A read of an old path itself** still counts that path's rows only.
- **The value change is PR 2's** (decision 8). There it lands with the redirects and D552.md's pointer, so the Interviews page keeps counting its own runs while it still exists, and `ai_surface_d552.test.ts` finds the new value in D552.md in the same PR.

### The verdict history, written by the Experiments read (PR 1, step 3)

Decision 7, in `services/cycleValidate.ts`:
- `claimsOf` also returns each claim's `verdict` and `lane`, which it already computed for its status. The MCP context and the row builder pick their fields by name, so neither changes.
- `experimentRecords` no longer loads the history in its first `Promise.all`. Right after it builds the open claims, it calls `recordVerdictChanges` with `{ hypothesis_id, verdict, lane }` for every open claim. That is before the search, filters and paging, so a filtered, searched or later-page read records every live claim, and a Retired read still records the open ones.
- The write is caught with `.catch(() => 0)`, as `founder_validate.ts` does, so a failed write never fails the read. Only then does it load the history, so the read's own write is in its views.
- The writer writes only on a change and logs no activity row. Its rows are for the read's scoped `project_id` only, under the module read's own gate (`canReadBoard`).
- #1691's filters, `statusOf` and `verdictHistory.ts` are as they merged.

**#1691's tests.** Three of `validate_lists_d690.test.ts`'s cases seeded a history whose last observation disagreed with the claims' evidence, and pinned a read that wrote nothing.
- "Recently moved" and "Changed this month" now end each claim's seeded history on what the read computes (no evidence: `unproven`, lane `none`), so the read adds no row. Each keeps its meaning: a lane change 13 days ago, a verdict change on the first of the month, a lane-only change, and a first observation.
- The stats case asserts a non-null `history_since` after the first read, in place of null.
