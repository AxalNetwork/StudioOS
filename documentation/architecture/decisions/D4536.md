## D4536 — Skill analytics start with a metric dictionary and the catalogue's coverage, served on the HQ library read (#4536)

#4536 is Session 08 of #4528, taken by slot S17. S1 set the scope of this first step:
- the metric dictionary;
- the catalogue and coverage reads, extending the existing HQ library response rather than adding an endpoint.

It is Worker only. There is no migration and no UI; any dashboard waits for #4956's canvases.

### What is decided

- **One response, one more block.** `GET /api/admin/ai-agents/skills` returns `coverage`, computed by `services/agents/skillCoverage.ts` from two aggregate reads. The library's fixed query count holds: the test that reads 180 skills still reads the same number of queries as one skill.
- **Coverage is the whole catalogue, whatever the page.** The one figure that needs each draft's evidence, `drafts.without_current_evaluation`, is computed only on the unpaged read. A paged read says it is not available.
- **Published coverage reads the current published version** (`roles_json`, `taxonomy_json`), because that is what an attach pins and a run uses. Draft completeness reads the draft tables. The two are never mixed.
- **Company skills are counted, not read.** HQ sees counts by scope and status. A company skill's slug, roles and tags are not selected into the response. This is the D4161 moderation boundary: HQ may know a company skill exists, and never reads its content through analytics.
- **Adoption is not usage.** Pins are reported under `adoption`. `executions` is `{ available: false }` until #4667 gives a reliable run status, because a usage-log row is not proof that a skill ran.
- **An area is `thin` below 3 published skills by primary tag.** The threshold is returned as `thin_below`, so the screen never hard-codes it.
- **Overlap is not guessed.** It is `{ available: false }` until a method is chosen. When it lands, its results are suggestions, never duplicates.
- **#3851 is not reused.** Its acceptance board measures agent proposals, not skills. A test reads both changed files and fails if either reaches for it.

The dictionary is `documentation/architecture/SKILL_ANALYTICS_METRICS.md`: source, grouping, window, denominator, availability and scope for each metric, and what each deferred metric waits on (#4667, #4535, #4534).

### Not in this step

- Execution, success, latency and charge metrics (#4667).
- Published-version evaluation metrics beyond the existing compare report (#4533's release evidence).
- Workflow metrics (#4535).
- Filters, which apply once there are usage measures to filter.
- Company-level analytics routes.
- Any UI.
