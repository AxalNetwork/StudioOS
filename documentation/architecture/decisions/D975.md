## D975 — Deck roster kinds, Archive confirmation and hidden photos

Issue #2761, part of Advisors & Partners #2369. Stacked on D972's integration
(#2742); no migration and no Worker or API contract change.

`AdminNetworkProfiles.jsx`, embedded at `/admin/advisors-partners/deck`, now:

- Defaults a new editor to Advisor and offers Advisor, Partner and Investor.
  A stored `mentor` reads and edits as Advisor, matching the deck's alias.
  Merely opening the list does not rewrite it; saving an edited row sends
  `advisor`. The Advisors tile counts both stored kinds; Mentors has no tile.
- Opens Archive in the shared `Lightbox`, with the person's name, Cancel and
  Archive. Nothing is written before confirmation. The dialog prevents repeated
  submits, stays open on failure with a retry message, and closes and refreshes
  after a successful DELETE. Lightbox supplies modal semantics, focus handling,
  Escape and backdrop dismissal; dismissal is blocked during the write.
- Draws initials for a hidden profile in both its row and editor. The existing
  public photo proxy serves active profiles only, so hidden rows never request
  it. A shown photo that fails also falls back to initials.

### Canvas and current store

AP8's three kinds and AP9b's named confirmation are followed. AP9b says the
person leaves this list and can be restored from Archived. That would be false
of the current DELETE: it sets `is_active = 0`, retains the row and photo, and
GET still lists it. The dialog therefore says the next deck leaves the person
out, the record and photo are kept, and the profile currently stays in the list
and can be restored with Show on deck. It does not claim to change an already
built deck. A separate Archived state and the admin photo reader belong to
D974 (#2760), which is not available on this branch; adoption of that contract
must update the dialog and photo source together when it lands. No guessed
route or private storage key is used here.

### Validation

Mounted React controls use a stubbed fetch and React DOM props, including the
unreadable list, failed archive, cancellation, duplicate submission and retry.
The existing save regression and D972 integration tests run alongside them.
Key regressions are checked with source mutations and then the restored code.
No tests are skipped. The frontend build and full drift suite are attempted;
Linux CI is the build reference because the local macOS filesystem has existing
case-insensitive helper/component import collisions outside this change.
