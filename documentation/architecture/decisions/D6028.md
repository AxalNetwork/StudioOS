## D6028 — Build Overview V2, page: `/build` built to BD1 and BD2 (#6028)

**Source.** The approved Build v2 canvas (D4846, landed in #5858):
`design/incoming/Build v2 Page.dc.html`, boards BD1 (`BU01`, desktop 1440)
and BD2 (`BU02`, phone 390), with BD14 B (`BU14t`, tablet 768) and C (`BU14d`,
dark) for the same page. The data is D6027's read, `GET
/api/cycles/build/overview`, as it is on `main`: `focus`, `figures[].module`,
`attention`, `plan`, `cards` and `index`. No Worker change and no new client
method: `cyclesApi.overview('build', …)` already reads it. No sample venture,
name, date or count is copied from the canvas.

**Where it is mounted.** `frontend/src/pages/cycles/BuildOverview.jsx`, lazy,
as `def.Overview` in `defs/build.jsx` (the hook Grow's overview uses), so
`CycleOverview.jsx` stays as it is for Validate and Raise. `CycleRoute.jsx`
passes the overview hook five more props (`phone`, `projectId`, `openAction`,
`onChanged`, `onRetryCard`); Grow ignores them. Below 1024px the page draws
the phone root (`PhoneCycleRoot.jsx`, D703) for Build with two new optional
props: `after` (drawn between the next action and the index: Needs
attention) and `planLine` (the Build Plan row's line, which then carries the
plan's counts). `/build?new=1` (Create your startup) and the no-venture state
stay in `CycleRoute`, untouched. The pure parts are
`buildOverviewModel.js`.

**What each part draws.**

| Part | From | States |
| --- | --- | --- |
| Next (the one primary) | `focus`, through the phone's `phoneFocus` | Worker focus; `unavailable` has no button |
| Status strip | `figures[]` with `module` | value; Not recorded (never 0); "<module> could not be read" |
| Needs attention | `attention` | ready (empty says "Nothing needs attention in the records that were read"); partial (each failed source its own row with Try again); unreadable |
| Build Plan preview | `plan` | ready (counts, first three waiting, Paused); not recorded; restricted; unreadable |
| Modules | `cards` and `index` | one sentence and one link each; empty and Not recorded say their reason; unreadable retries that card alone (`retryCard`, D4601) |

**One dominant action.** The Next card's button is the only primary on the
page. Needs attention rows, the plan link and module links are secondary.

**Read only.** The read carries no write flag of its own. Its plan preview
does: `plan.state === 'restricted'` is D1065's gate (the venture's founders
or an admin), the same people `canWrite` lets write, so a restricted plan
marks a reader who cannot write. That reader gets a Read only line, no header
Ask, the record link on each attention row (the Worker already sends
`action: null`), each module's page in place of its next step, and the focus
button as "Open" without `?add=1`.

**States are local, for now.** #5129's shared state component is not on
`main`. The page's words for Not recorded, a failed read and Read only are
one local component, `BuildState` in `BuildOverview.jsx`, written so #5129's
component replaces it in one place. A failed read keeps the house word
("could not be read" with Try again); the whole overview failing uses
`Unreadable` from `frontend/src/ui/Honesty.jsx`.

**The header's Connect a tool.** BD1 says "the header CTA is gone". This
issue removes it on `/build` only: `BuildOverview` draws `CycleHeader` with no
action. `defs/build.jsx`'s `action` stays, because module pages draw it in
their Sources region (D5077) and `/build/connect` still opens over the page.
A Connect a tool the Worker's focus names (D6027 rule 6, Operating systems'
first connection) is the Next button and still opens the sheet over the page.

**Owner question (not blocking).** Who owns the overview header between this
issue and #5077 (whose first criterion is the header too)?

- **A (built).** This issue removes the header action on `/build`; #5077
  owns the shared header (`CycleHeader`) everywhere else.
- **B.** #5077 owns the header on every page, `/build` included, and this
  page follows whatever it ships.
