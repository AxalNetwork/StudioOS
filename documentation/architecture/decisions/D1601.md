### 1. Why

The owner asked for a one-click deck built from the platform's data and its connectors. Three connected tools hold the numbers a Traction, Business model or Product card needs: PostHog (activation, retention, weekly active users), HubSpot (open deals, pipeline value, customers) and Linear (work shipped, velocity). None was in `DECK_SOURCES`.

### 2. Three adapters (`services/decks/sources.ts`)

`DECK_SOURCES` goes from 17 adapters to 20, and from the founder's view the slot count grows by exactly 8.

| Adapter | Area | Slots | Reads |
|---|---|---|---|
| `product` | Grow | `grow.activation_rate` (percent), `grow.retention_w4` (percent), `grow.wau` (count) | The facts #2409's PostHog feeds store for the venture's linked project (`services/posthog/deckFacts.ts`). |
| `pipeline` | Grow | `grow.open_deals` (count), `grow.pipeline_value` (usd), `grow.crm_customers` (count) | Live CRM search totals through the founder's own HubSpot (`services/decks/hubspotCounts.ts`). |
| `shipping` | Build | `build.shipped_90d` (count), `build.cycle_velocity` (count per week, 4-week mean) | Completed issues through the founder's own Linear (`linearReadsFor(...).listCompleted`). |

**The rules, as every adapter keeps them:**
- **Origin:** a read value is `origin: 'connector'`, so Source **Connector** and grade **Measured**. It carries `record_ref` and `as_of`; a live count is dated the day it was read.
- **Missing values:** a tool with nothing stored is `not_recorded`, never 0.
- **Deadline:** each adapter reads under one deadline, `CONNECTOR_DEADLINE_MS` (3 s, `withDeadline`). A failure or the deadline makes that adapter's slots `unreadable`, and the others still answer. The deadline's signal also aborts HubSpot's requests.
- **Not connected or off:** a connection that is missing, inactive, or not switched on for the venture's company (`projectEnabled`) is `not_recorded`, not `unreadable`, and is never called.
- **Founder only:** HubSpot and Linear are the founder's own, as Mercury is (D840).
  - For any other reader those five slots are `withheld`: left out of the count, not called missing.
  - The gate is the one `mercuryFor` already applies (the founder, in the venture's company, outside a support session). A withheld Mercury in the context means a withheld HubSpot and Linear, so no route changes.
- **Counts only:** no contact, deal name, owner, issue title, assignee or email is read into an item, logged or returned.
- **Links:** each slot's `href` is the tool's connector page (`/account/connectors/<key>`), where it is connected and switched on.

### 3. PostHog (`services/posthog/deckFacts.ts`)

- **The link:** `posthogDeckLink` reads the venture's row in `posthog_project_links`, through an active PostHog connection switched on for its company.
- **The facts:**
  - `posthogDeckFacts` returns the stored facts, and `productReads` maps them onto the slots. A fact with no value leaves its slot not recorded.
  - **No feed stores a fact yet.** `POSTHOG_FEEDS` is empty until #3731's parts land, so today every product slot and the `grow.wau.weekly` series read `not_recorded`.
  - When the store lands, these two functions read it and nothing else changes.
- **Not founder-only:** these are the venture's stored facts, not a live read of a member's account, so `product` is not withheld.

### 4. HubSpot (`services/decks/hubspotCounts.ts`)

Each read is a CRM search (`POST /crm/v3/objects/{deals|companies}/search`) that asks for **one** property. The list is never left out, because HubSpot then answers with its defaults, a deal's name among them.

| Slot | Request | Read |
|---|---|---|
| Open deals | deals, `hs_is_closed EQ false`, `properties: ['hs_object_id']`, `limit: 1` | `total` |
| Customers | companies, `lifecyclestage EQ customer`, `properties: ['hs_object_id']`, `limit: 1` | `total` |
| Pipeline value | deals, `hs_is_closed EQ false`, `properties: ['amount']`, 200 per page, paged by `after` | the sum of `amount`; a deal with none adds nothing |

- **Scopes:** the provider already asks for `crm.objects.deals.read` and `crm.objects.companies.read`; nothing new is needed.
- **Failures:** a failed request throws with its status only, never HubSpot's body.
- **Paging:** at most 50 pages, HubSpot's 10,000-result search ceiling.

### 5. Linear (`services/linear/reads.ts`, `listCompleted`)

- **The new read:**
  - `listCompleted({ days, cursor })` calls `list_issues` with `state: 'completed'`, `updatedAt: '-P90D'`, `includeArchived: true` and `limit: 50`.
  - It keeps each issue's id and completion date, nothing else.
  - It reports the next page's cursor, and `done` when the answer says it was the last page or came back short with no cursor.
- **The counts:** `shippingCounts` reads up to `SHIPPING_PAGES` (10) pages.
  - **Shipped:** issues completed in the last 90 days.
  - **Velocity:** issues completed in the last 28 days, divided by 4, to one decimal.
- **The cap:** past ten pages, or on a full page that names no next one, the count is a floor and `record_ref` ends `:capped`. The card reads "500+".
- **No Linear connections yet:** until #3733 lists Linear, no member has one, so both slots read `not_recorded`.

### 6. Series (`services/decks/chartSeries.ts`)

`grow.wau.weekly` (count, weekly, module "Connectors › PostHog") is added to `CHART_SERIES`. It reads `not_recorded` until the feeds store it, and never as a run of zeros.

### 7. Departures from the issue

- **The PostHog adapter reads through `deckFacts.ts`, and that file answers "no facts" today.** The issue's first test case ("a fixture fact is recorded") is held on `productReads`, the mapping the adapter applies, because no fact table exists yet to seed.
- **`SourceCtx.connectors`** (an optional `fetcher` and `deadlineMs`) lets a test inject its fakes. Production never sets it.
- **`freshness.ts`'s `PROVIDER_ADAPTERS` is unchanged.** It lists any member's connection, while HubSpot and Linear here are the founder's own. Adding them there is #3877's call.

### 8. Tests

- The route: a cofounder gets the five slots withheld and out of the count; the founder's list has all eight new slots, none a 0.
- The source tree: counts only, bound SQL, and Linear through `reads.ts`.
