## D700 — The account menu's pages on a phone, and `/account` as an index of its sections

Issue #1662, part of D689 (#1654). The owner asked on 2026-10-14 for "mobile versions" of every screen. The canvases are `Account Menu · Mobile.dc.html` (AM) and `Account Mobile Page.dc.html` (AMP), boards A1m–A10m: the ten pages the account sheet opens on a phone. Session 1 decided every open point on the issue. This file records them.

**Status: first version, PR 1 of 2.** PR 1 builds A1m–A3m (the `/account` index, Usage and Connectors), the address rules, the plan name and the shared row parts. PR 2 builds A4m–A10m, moves the two canvases to `design/canvases/integrated/`, and amends this file.

### The rules that bind every page

- **One phone breakpoint, 1024px (D-l).** A page asks `usePhoneWidth()` (`ui/phone/usePhoneWidth.js`, D699), the one hook over `PHONE_QUERY`. Each page switches inside its rail frame, so one tree mounts and one set of reads runs. At 1024px and up every page is as it was.
- **The shell is D699's (D-h).** `PhoneBar` draws "‹ Back", which returns to the previous page, and falls back by role with no history. This task draws the bar's content and the body, and does not change `PhoneBar`.
- **Member routes win (D-j).** Events is `/my/events` and Plans & Pricing is `/plans-and-pricing`. AM:24 names the public `/events` and `/pricing`, which get no account layout.
- **Copy that promises a behaviour must be true (D-s).** Titles, subs, section titles and row labels are AMP's, byte for byte, except the departures below. A value with no store reads "Not recorded" with its reason, never 0.
- **No migration, no Worker change and no new `/api/*` client method (D-r, decision 8).** Every value comes from a route and client method that exist today.
- **Each page draws the canvas's sections first, then keeps what it has today** (decision 9). Nothing a page does now is dropped on a phone.

### A1m: `/account` on a phone is an index, and each section is its own page

Below 1024px, bare `/account` draws the A1m bar, the trust strip and the profile completeness banner (D433), and these rows. It draws no section pane.

| Section | Row | Description | Opens |
|---|---|---|---|
| Settings | Profile and identity | Personal details, identity, company profile | `/account/profile` |
| | Notifications | Each type, in-app, email and push | `/account/notifications` |
| | Sign-in and security | Password, authenticator app, SMS | `/account/security-privacy` |
| | Billing and orders | the plan line (below) | `/account/billing` |
| | Following | "\<n\> people and companies" ("1 person or company") | `/account/following` |
| Developer (admins only) | API and search indexes | Feature flags, account fields and the search indexes | `/account/developer` |
| More | Onboarding, Appearance, Activity Log | none | `/account/onboarding`, `/account/appearance`, `/account/activity` |

- **Developer** shows only to admins, the one role `SECTIONS` admits.
- **More** keeps the three sections the canvas does not draw, as the desktop column keeps them.
- **Usage and Connectors are not repeated.** They are A2m and A3m. A founder reaches them from the account sheet (D699), and every other role from the user menu.
- **Following** counts `users` plus `projects` from `api.followsMine()` (`GET /api/follows/mine`). At 500 the read has stopped (`LIMIT 500` in `follows.ts`), so the row reads "500+ people and companies". While the read loads or fails it reads "People and companies you follow", with no number.
- **Each section page** draws `PhoneBar` with the section's label as its title and no sub, then the section's cards as they stack today. Usage and Connectors carry their A2m and A3m bars instead.

The frame is `AccountPhoneFrame` in `AccountCenter.jsx`. `SettingsPage.jsx` hands it the role's sections, the index and a pane renderer, so the frame reads nothing and a test can draw each view. The index is `AccountPhoneIndex`, its rows `accountIndexGroups`.

**D607's phone select gives way to the index (decision 14).** `AccountSectionNav` is the `lg` column alone. Its "Section ▾" row over a native `<select>`, and the `current` and `option` helpers only it used, are gone. `decisions/D607.md` points here.

### The `/account` addresses (decision 7)

Two pure functions in `accountPhone.js` decide the address. `PATH_TO_SECTION` moved there from `SettingsPage.jsx` unchanged, so the map and the rules are tested together.

- `accountViewFor({ pathname, hash, phone })` returns `'index'` or a section id.
  - `/account/<alias>` and `/settings/<alias>` resolve through `PATH_TO_SECTION`. The `/settings` prefix keeps resolving for its one hop.
  - A bare `/account#security-recovery-codes` opens Sign-in and security, so recovery and anchor links keep working.
  - Otherwise a bare `/account` is the index on a phone and the profile pane on desktop.
- `accountPathFor({ section, phone })` returns the path. The profile pane is `/account/profile` on a phone, because bare `/account` is the index. On desktop it is still `/account`, never `/account/account`.

`SettingsPage` reads the view from the address on every path or hash change. It used to read it once, at mount. `/account` and `/account/:section` render the same component, so React kept the page mounted when the path moved and the pane did not follow. The URL effect writes the canonical path with `accountPathFor`, keeping the query and the hash. On a phone, `/account#security-recovery-codes` becomes `/account/security-privacy#security-recovery-codes`.

A section click, an index row, the completeness banner's jump and Roles & access's jump all open a section through its address. On a phone the section is pushed, so Back returns to the index. On desktop it replaces, as the column always has. A section the role cannot open sends the reader back to bare `/account`: the profile pane on desktop, the index on a phone.

### The plan name (decision 11)

- The A1m Billing row reads `TIER_PLANS`' name, price and period for a paid founder tier ("Validate + Build · $20 / month"), and "Free" on the free tier.
- Other roles read `planSummary`'s plan and tier ("Investor · Professional"), with no price. A role with no plan reads "No subscription plan applies", the Billing pane's words.
- While the status read loads or fails it reads "Your plan, orders and invoices".
- `planSummary` takes the founder tier names from `TIER_PLANS` too, so the Billing pane agrees: "Founder workspace · Validate + Build", not "Growth". **This is the one desktop-visible change.**

Other surfaces still say "Growth" or "Studio", and are left for Session 1:
- the connector tier labels, `TIER_LABEL` (`connectorsModel.js:44`) and `UPGRADE_TIER` (:694), pinned by `connect_tool_d686.test.mjs:141`;
- the Perks tier pill, which capitalises the tier id (`tierName`, `PerksPage.jsx:83`).

### A2m: Usage

The bar replaces the desktop's heading. The sections draw from the section's five reads, which are unchanged.

- **AI allowance**, from `allowanceView` over `/ai-budget/me`. The state lines (`STATE_COPY`) come first, so a paused or used-up allowance still says so. Then Today and This month as "\<used\> of \<cap\>" with the reset line and a 7px bar, Held by runs in progress, and Top-up balance, with AMP's descriptions. "Add tokens" links `/checkout?ai_topup=1` only when the top-up is available; otherwise the section ends on today's unavailable or unreadable line.
- **Models this month:** one row per `modelRows` entry, "\<n\> runs · \<in\> in · \<out\> out", with its estimated cost. The note is AMP's, byte for byte.
- **Storage:** "All your files", described by the five `STORAGE_AREAS` labels and valued "\<total\> · \<files\>". A missing total reads Not recorded with its reason. "Files with no size recorded" shows its count when there are any. The note is the desktop footer's two sentences.
- **Kept below:** Last 30 days, Where it went, Rates and Last run. Rates is now its own `RatesCard`; the desktop's `ModelsCard` draws it as before.

### A3m: Connectors

The bar replaces the desktop's heading and its Yours/Discover tabs.

- **Yours:** one row per connection, led by its `BrandIcon`. The description is "\<feeds\> · \<last sync\>", with the reason first when the row needs attention. The pill is its status. The section's action is the count line, with ‹ › when there is more than one page. A row opens its sheet.
- **Suggested for you:** the active company's suggestions, as Discover builds them, each with its card's pill or corner action. A failed suggestions read keeps today's reason. "Browse connectors" scrolls to Discover, in place.
- **Kept below:** Discover (with the search, filter, sort and Add menu), Customer conversations (D684), AI assistants (D668) and the request form. The API-keys card that `SettingsPage`'s `ConnectorsTab` adds stays under them. Because Discover is always drawn on a phone, its Community card makes its own channel read on arrival, as the desktop's Discover tab does when it opens.

### The departures (decision 10)

PR 1's departures are listed here; PR 2 adds the others.

- **Account:**
  - A1m adds a More section.
  - Developer's description is reworded: the canvas's "Shown when developer mode is on" names a switch that does not exist. The admin role is the switch.
- **Usage:**
  - Models rows read "\<n\> runs · \<in\> in · \<out\> out". A direction the log did not count reads "Not counted", as the desktop does.
  - No row reads "min transcribed": a transcription records no token count and no minutes.
  - No row reads "Safety check on every run": the guard runs on only four routes. Llama Guard's row is the log's runs, like any model's.
  - "All your files" is described by the five `STORAGE_AREAS` labels, because those are what it counts.
  - "Files with no size recorded" shows its count, and is left out when there are none.
  - Storage's note is the desktop footer's two sentences. The canvas's "No plan sets a storage limit." is the second.
- **Eadwyn:** every bar passes `PhoneBar` an `eadwynLabel` equal to its title, a section page its section's label. `PhoneBar` takes no such prop yet. #1661's PR 2 adds it, and #1660's `EadwynButton` draws only while `useEadwynPanel().available` is true. Until both merge, no bar draws a button, and no file here draws one of its own. `SettingsPage` keeps its `RailFrame` and `WorkerRail` mounted on a phone: the phone view replaces the heading and body inside the frame.

### What no store holds

- **An exact Following count past 500.** The read drops deleted projects and users it cannot find after its `LIMIT 500`, not before. So in a rare case a member with more than 500 follows, some of them deleted, sees a number below 500 with no "+". Only a Worker count would fix that, and this task adds none.
- **A developer-mode switch.**
- **Minutes transcribed per model.**
