## D718 — CodeQL and Semgrep upload to code scanning again, so Copilot Autofix has alerts to fix

Issue: none; S1, on 2026-10-17, while moving the AI review off GitHub Code Quality (`documentation/operations/CLAUDE_REVIEW.md`). This reverses the upload half of D672.

### Why

- **D672's reason no longer holds.** D672 stopped both uploads because the repository was private: code scanning there needs GitHub Code Security, which was off, so every upload was refused. On 2026-10-17 the repository is public (`visibility: public` on the repository API), and code scanning on a public repository is free.
- **Copilot Autofix needs the alerts.** The owner asked about Copilot Autofix ("Suggest fixes for CodeQL alerts using AI"). It proposes fixes only for alerts in the Security tab, and with `upload: never` this repository sent none, so the setting did nothing. For a public repository the classic Autofix, one suggested fix that a person reviews and applies, needs no Copilot licence and uses no AI credits. The agentic variant ("Assign to Copilot") does spend AI credits; nothing here turns it on.
- **The job-summary report stays.** The agents that fix findings cannot read the code-scanning API, which answers 403 to their token. Each run's summary is still where they see the findings.

### What was decided

- **`codeql.yml`:** `analyze` drops `upload: never`, so it uploads under its existing category `/language:<lang>`. It still writes its SARIF to `codeql-results/`, and the "Report findings" step still lists the findings.
- **`semgrep.yml`:** the `Upload SARIF` step is back, between the strip and the report, pinned to the same `github/codeql-action` commit as CodeQL's actions.
  - It has no `category`, as before D672, so it replaces the alert set the old uploads left open instead of starting a second one.
  - It takes the default `if: success()`, like the strip and the report (D170). An upload replaces the tool's alert set, so the resultless SARIF a crashed scan leaves would close every open alert as "fixed".
- **Findings still never fail either job.** A red check still means only that a scanner could not run, or that an upload was refused.

### What did not change

- `scripts/sarif-summary.py` and its rules, from D672.
- The suppressed-results strip, from GOTCHAS: the uploaded SARIF must match the count Semgrep printed.
- CodeQL's default setup stays off. This workflow is the advanced setup, and the two must not run side by side.

### If an upload is refused again

If the repository goes private again, or code scanning is turned off, every upload is refused and both jobs go red on every pull request, as on 2026-10-10. Then either turn Code Security on, or put D672 back: `upload: never` in `codeql.yml`, and no upload step in `semgrep.yml`. The report step works either way.

### Guards

- `frontend/test/code_scanning_upload_d718.test.mjs`, renamed from `code_scanning_no_upload_d672.test.mjs`, pins:
  - CodeQL no longer says `upload: never`, and still writes `codeql-results`;
  - Semgrep uploads `semgrep.sarif` after the strip and before the report, SHA-pinned, with no `if:` and no `category`;
  - both workflows still report.

  Its tests of the script on fixtures are unchanged.
- `frontend/test/semgrep_workflow.test.mjs` adds the upload to the steps that must take the default `if:`.
- Five mutants, each killed:

  - `if: always()` on the upload;

  - a `category` added;
  - the action unpinned.
