## D9193 — Unknown URLs and the bare /authors answer as not-found pages, not real ones (#9193)

**Decision date:** 2026-11-28. **Scope:** `frontend/src/pages/NotFoundPage.jsx`, one registry flag in
`frontend/src/lib/ogRegistry.js` and the two build scripts that read it. No route, `wrangler.toml`,
`run_worker_first` or `[assets]` change. Part of #6976.

### What changed

- **The catch-all 404 owns the head while it is shown.** An unknown path is not in `run_worker_first`, so the
  assets binding answers it with the SPA fallback (`docs/index.html`, the prerendered home page) and the URL
  kept the home title, the home canonical and no robots directive. `NotFoundPage` now calls
  `applyNotFoundMeta(pathname)` in a passive effect beside its existing `useLayoutEffect`: it applies the
  registry tags through `applyPageMeta` (`lib/seo.js`, unchanged) with the title "Page not found" and
  `robots: noindex`, then takes the canonical link out of the head. Its cleanup puts the canonical back and
  restores everything else, so the next page starts from the shell's head. The effect is passive, like
  `usePageMeta`'s, so the page being left restores its head before the 404 writes its own.
- **The bare /authors is no longer prerendered.** Of the two options in the issue, this one: the registry
  entry keeps `prefix: true` (each `/authors/:userId` page still inherits its card and copy) and gains
  `prerender: false`; `prerenderedRoutes()` filters those out, and `scripts/prerender-og.mjs` and
  `scripts/validate-og-tags.mjs` iterate it, so the build writes no `docs/authors/index.html`. A redirect to
  /articles was not taken: the prerendered file would still have answered crawlers with "Authors" before the
  client redirected. Per-author pages are unaffected — `/authors/*` is in `run_worker_first` and the Worker
  answers them; the bare `/authors` now falls to the SPA fallback and draws the 404 above with `noindex`.

### Not done

The optional item (no canonical in the shell for paths other than `/`): `docs/index.html` is the prerendered
home page itself — `prerender-og.mjs` writes `/`'s canonical into it — and `not_found_handling =
"single-page-application"` always serves that file, so the fallback cannot carry a different head without a
second fallback the assets binding does not offer. The client-side removal above covers it for browsers.

### Guard

`frontend/test/soft_404_9193.test.mjs` mounts the whole App at an unknown path under the home head and reads
the title, robots and canonical while the 404 is shown and after unmount; asserts that no `prefix` registry
entry is prerendered at a path no `<Route path>` in `App.jsx` or `frontend/src/routes/*.jsx` declares; and runs
the real prerender to check `authors/index.html` is not written.
