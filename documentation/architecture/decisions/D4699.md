### 1. Sessions: a stable order and a cursor

`GET /admin/security/sessions` ordered by `last_seen_at`, which moves on every request. The same rows came back in a different order on each read, and rows past the 200-row page could not be reached.

Now:
- The list is ordered newest sign-in first, by `id`, which never changes.
- It answers `cursor: { before_id }` while more rows are held. `?before_id=<id>` continues strictly below that id.
- A cursor out of shape is a 400 naming `before_id`, never the first page.
- `total` is the whole window on every page.

### 2. The ledger: a stable order

The merged feed sorted only on each row's parsed time. Rows at the same instant, from two stores or one store within a second, came back in whatever order the stores answered. They now fall back to their key, so the same rows come back in the same order on every read and every page. D4803's cursor and `trimToSecond` are unchanged.

### 3. The page: only the newest answer lands

Each of the page's three reads (overview, sessions, ledger) is numbered, and an answer that is not the newest is dropped. Two cases this covers:
- a slow read for an earlier filter, answering after the current one, used to replace it;
- a slow first read used to replace a Retry's.

Load older (events) and Load older sessions append only to the list they were asked for: a page that answers after the list changed is dropped. A sessions page appends once (a row already shown is not repeated), and it keeps what this page has already marked (`appended_to`).

### 4. After an act

D4801 re-reads nothing behind an act, so the dialog's result can be read and an act that signs the operator out does not trip a 401. That stays true for the sessions list.

Now, after an act that leaves the operator signed in, the overview's counts and the ledger are read again, softly: what is drawn stays until the new answer arrives, and a failed soft read keeps it. The acts that qualify are revoke, revoke selected, end a support session, and sign out another account.

Never after:
- emergency re-authentication;
- signing out the operator's own account;
- a sign-out whose own account is not known.

### Not in this package

- **The new filter and timestamp layout** waits for the #4802 canvas, as S1 directed.
- **A page that lies entirely within one second:** D4803 already says so with `page_split_second`. Reaching the rest of that second needs a compound cursor across five stores, which is left for package 6 (#4708).
