### What the founder does

On the `/raise` Overview, *Share outside Axal* opens the Raise status sheet: "a one-page summary of the Overview".

- **Output** is Link (a label, an expiry of 1 to 90 days and a view limit of 1 to 100) or PDF (a label only).
- **On the page** lists the stage, the five materials, investor counts by stage, readiness by area, the next three steps and the connected tools. It marks one row as left out: *Investor names and commitment amounts — Left out; counts by stage only* (Q3 A).
- *Create status page* returns the address to copy; *Download PDF* records the copy and the browser draws the A4 page. Nothing is sent.
- Both are listed on Raise › Evidence › Shared links as *Raise status*, counted in materials. A link is revoked there; when the raise has changed since it was made the row says *Changed since sent* and offers *Make a new status page* (`/raise`).
- Only the venture's founders see the button and make the page; a staff or support reader of the Overview is read only and gets no header actions.

### What the page carries

Frozen when it is made: "This shows the raise as of that day; it does not update." Built by `services/raiseStatusPage.ts` from the Overview's own reads.

- **Stage.** `raiseJourney` (D6045) with names off and no action, the stages before it listed as done.
- **Materials.** Investor narrative, Pitch, Data room, Cap table and Use of funds, in state words only:
  - a card that is `ok` reads *Saved* (narrative, use of funds) or *Recorded* (data room, cap table);
  - `empty` reads *Not started*, `too_little` *Partial*, `not_recorded` *Not recorded*;
  - Pitch reads its D6045 state label (*No deck* to *Shared*).

  No caption, figure or row of a card is copied. The data room is its summary card, the one non-owners read (D1102).
- **Investors · counts by stage.** In pipeline (everyone not passed, as `pipelineCounts`), Active conversations (contacted, meeting, diligence), In diligence and Committed, from `capitalSummary`, whose SQL selects no name, contact, note or amount.
- **Readiness by area.** The seven areas exactly as the readiness snapshot (`readinessBody`).
- **Next steps.** The Overview's three, as label and line; no score gain and no link.
- **Connected tools.** Each tool's state (*Connected*, *Not connected*, *Unavailable*) and, when connected, the day it was read. Never the fact it read: no runway, no count.

### Nothing half-filled

When any part cannot be read (the stage, the Pitch state, a material card, the pipeline counts, readiness, the next steps or the connectors list), nothing is made: 503 `status_unreadable`, "Part of the raise could not be read, so no status page was made. Nothing left Axal." One connector that cannot be read is not a failure; it is that tool's read state, *Unavailable*.

### Store, reads and writes

- `POST /api/cycles/raise/status/share-links` `{ label, expires_in_days?, view_limit? }` → 201 `{ uid, output: 'status', path: '/share/status/<token>', … }`. A row in `raise_evidence_share_links` with `output = 'status'`; the token is stored only as its digest.
- `POST /api/cycles/raise/status/pdf-copies` `{ label }` → 201 `{ uid, kind: 'pdf', output: 'status', status }`. A row in `raise_share_pdf_copies`.
- `GET /api/share/status/:token` (`routes/status_share_public.ts`): no sign-in, on the pack's rules and per-IP bucket (`EVIDENCE_SHARE_READ`). `openPackLink(…, 'status')` filters on `output`, so no pack or snapshot token opens it and a status token opens no other page.
- `GET /evidence/share-links` compares a live status link's hash with the page as it would be made now.
- Activity: `raise_status_shared`, `raise_status_pdf_copied`.
- Frontend:
  - `pages/cycles/evidence/ShareStatus.jsx` (`ShareStatusButton`, `ShareStatusSheet`, `OnThePage`) in the Overview header (`defs/raise.jsx` `overviewMore`, which `CycleRoute.jsx` draws as the header's `more`);
  - `pages/share/RaiseStatusPage.jsx` at `/share/status/:token` (public);
  - `statusPageModel.js` for the words and the A4 model, drawn by `lib/raiseSharePdf.js` `downloadStatusPdf`.

### Where this departs from the canvas

- **Connected tools are the Overview's three.** RA-31 draws four sample tools (Mercury, PostHog, GitHub, Google Workspace) with *Fresh* and *Stale*. The page carries the tools the Overview's `connectors` read (Mercury, GitHub, Google) and their recorded state and read day. It invents no freshness rule.
- **Materials say what the card records.** The canvas pairs a state with a second word (*Ready · Saved · checked*). The page carries one state word per material from the card's recorded state; it does not grade one.
