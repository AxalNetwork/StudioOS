## D895 — Truthful pitch-deck Worker data and scoped writes

Issue: #2674, part of #2434. Slot S28.

Deck routes keep admin reads but reject admin writes and advisor reads/writes,
including an accepted advisor membership. Local deck checks normalize legacy
role casing, matching the shared gate; the Lab ownership fallback cannot restore
an admin/advisor deck write. The pitch module's link writers and
record action metadata use the same narrower write policy. Other modules keep
their existing policy; the shared project-content middleware is unchanged.
Accepted cofounders retain their existing access.

Static `/api/decks/methods` and `/brand` reads precede the deck-id route. The
methods read exposes all thirteen existing templates. Existing tier gates stay.

Generated Ask slides and template fills use the latest recorded model runway,
otherwise the latest stored Mercury runway fact. A model is recorded only after
`updated_by` is populated, matching autofill; seeded/unsaved model rows are excluded. Raw Mercury facts are read only for the
owning founder after the route verifies active-company scope, outside support
sessions, from that founder’s active connection. Cofounders may use saved venture
model values but cannot copy another member’s raw bank facts into a new deck. Missing runway is “Not
recorded”; a measured zero remains zero. An AI response cannot replace the
recorded Ask, including alternate/case-varied Ask titles. Generation keeps one canonical
slot per title and pads by title rather than reusing an unmatched AI slide. Whole-month display is shared across generated and template Ask
fields; the stored measurement retains its precision. Coverage counts record-sourced required fields, excluding AI fills.
A review without a numeric returned score (a number or nonblank numeric string) has `overall_score: null`, shown as
“Score not returned”; returned zero remains a score. There is no invented
`fix_first` fallback.

The founder-deck path suppresses internal readiness score fields in both new
versions and historical reads/exports. The canonical Lab assembler retains its
score by default. The public founder-deck payload removes the internal Axal
score card after applying canonical deck overrides. Unreadable/non-array card
data becomes an empty card list while unrelated baked fields remain available;
malformed entries are dropped without mutating the Lab source fields.

Exports resolve the venture owner and use that owner's plan and watermark.
The current brand kit is the newest non-archived landing page, including voice
and dark-logo fields. The owner approved aligning the paired legacy PUT with
that read in this chat. Saves update the same newest live row. With no live row,
a new page uses an available home path and preserves archived pages; the existing
five-page limit still applies. The owner also approved matching legacy Publish
and Preview selectors. They use the page shown by the current read, while
explicit per-page actions retain their ID-based targeting. Missing ownership gets conservative free-tier branding.

Signed-in NDA acceptance additionally records and activates the canonical
founder/viewer pairwise NDA using the signed acceptance document's UID. The
viewer identity comes from authentication. This does not grant data-room access:
that remains a separate founder action. A failure to establish the pairwise NDA
returns an error rather than a successful conversion. Incomplete pairwise writes
remove only the new unfinished acceptance and its pending link; an already active
agreement is retained if a later read fails. Link verification checks that the
active pair actually references this acceptance, not a previous agreement.

Each successful Save, Keep, restore, generation, template/fill proposal, Discard,
export and first editor withdrawal writes one actor-scoped `raise.pitch-deck`
activity row. Export failures and repeated withdrawals add no completed-write
row. Summaries contain no financial figures. Share creation retains its existing
single activity writer.

Unknown engagement counts and unreadable conversion aggregates return null;
measured zero remains zero. The API represents an unlimited view cap as null,
including historical unlimited sentinel values. The owner approved replacing the
storage sentinel with SQL NULL on #2674 (comment 6383505109). The existing column
is NOT NULL, so the data-preserving rebuild must ship with its assigned migration.
S1's migration number is still pending; this partial change retains compatible
storage and does not alter an applied migration or silently rebuild a live table.

Regression tests use synthetic users and the real migrated SQLite schema, cover
both denied and admitted roles, stored-data provenance, missing versus zero,
owner/exporter branding, canonical NDA state and successful/failed audit writes.
The existing reviewer score tile changes only its missing-score copy; new studio
boards remain with their separate implementation tasks.
