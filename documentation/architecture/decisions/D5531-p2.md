### Trust and acquisition

Both Gitleaks callers and each CodeQL matrix job obtain `install-scanner.mjs`, `scanner-acquisition.mjs` and `scanner-tools.json` from a validated 40-character trusted commit: the PR base, merge-group base, or the exact main push/scheduled commit. They never execute the checkout's installer or fall back to PR files when trusted files are missing. Node 22 loads the reviewed JSON pins with the installer module.

Exact checksum/version/platform cache keys restore compressed archives only. The existing foundation copies and rehashes the archive in a fresh private directory before extraction/use. There are no prefix restore keys. Only successful trusted-main push acquisition saves an archive; PRs and queue events cannot publish it to main's cache. Gitleaks adds only its verified private binary directory to the job PATH. CodeQL init receives the verified local bundle path through its `tools` input.

The reviewed versions remain Gitleaks 8.21.2 and CodeQL 2.27.3; this PR does not opportunistically upgrade them. The current pinned CodeQL action `33d7b85da1a04171e211befe2c739303b9a4c066` lists 2.27.4 as its default and 2.27.3 as its prior bundle in [its own defaults](https://github.com/github/codeql-action/blob/33d7b85da1a04171e211befe2c739303b9a4c066/src/defaults.json), re-read during this pickup. Both JavaScript/TypeScript and Python retain the same action SHA and query/configuration policy.

- Exhausted acquisition fails its existing required check and names the scanner/version; no failure is relabelled as a clean scan and no `continue-on-error` is introduced.
