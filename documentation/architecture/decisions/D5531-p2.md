### Trusted inputs

Both Gitleaks jobs and the CodeQL analysis matrix select the PR base SHA,
merge-group base SHA, or current main SHA on a main push/schedule. They verify
the SHA shape and copy the installer, acquisition module and pins with `git show`
into a runner-temporary directory before executing them. No PR-head fallback,
workspace script fallback, cache-supplied script or client-selected URL/version
is accepted. Node 22 is set up before acquisition; no dependency install or PR
application code precedes the scanner in `fast`.

Exact-key caches contain pinned compressed archives. Only a main push with a
successful acquisition can save a cache. Restored bytes are still verified by
the trusted installer before extraction or use. Gitleaks uses its job-private
binary through `GITHUB_PATH`, and both original range calculations and finding
arguments stay unchanged. The original required `scan` context and the shadow
`fast` verdict remain in force until #5606's owner cutover.

The pinned CodeQL init action takes `steps.acquire_tools.outputs.archive` as
its local `tools` input. Upstream `src/setup-codeql.ts` at
`9b3254085494b55a0f7c4c2b3d2d52cc712ce370` handles a local path before remote
or toolcache selection. Both JavaScript/TypeScript and Python retain their
original build mode, queries, config, SARIF upload policy and 60-minute job bound.
An exhausted or integrity-refused acquisition fails before initialization.
