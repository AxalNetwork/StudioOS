## D4856 — Platform summaries describe the population they summarize (#4856)

### Decision

HQ › Platform's catalogue and storage figures each say which rows they count,
and no figure pairs a numerator from one population with a denominator from
another. Platform audit 3/7.

**What was wrong on main (1ee5b2c41c), checked in code**

1. `getCatalog()` reads `WHERE livemode = <stamp>`, the stamp of the key
   (`stripeMode(env)`: live 1, test 0, no key none). `readCatalogMirrorSummary()`
   read every `stripe_products` row with no mode predicate. A mirror holding
   test rows beside live ones made Platform's "N active of M" larger than the
   catalogue checkout sells from. Confirmed.
2. `readPlatformStorage()` summed bytes over every owner, while
   `members_with_files` skipped the admin (staff) plan, so "X across Y members
   with files" held staff bytes in X and no staff in Y. Confirmed. A second,
   smaller mix, found while fixing it: `totals.members` was `plans.size`, which
   counts staff, beside `members_with_files`, which does not.

**Catalogue**

- `catalogModeStamp(mode)` and `catalogRowScope(livemode, mode)` in
  `services/catalog.ts` are the one rule. `getCatalog` binds the stamp in SQL;
  the summary classifies each row with `catalogRowScope`. A test holds the two to
  the same rows, for live and test keys.
- A row is `current` (its stamp equals the key's), `other` (the other mode's
  stamp, or no key at all), or `unknown` (null, or any value but 0 and 1).
  Unknown is never folded into either.
- The reply gains `stripe_mode`, `other_mode: { mode, products }`,
  `unknown_mode: { products }` and `sync_state: 'not_recorded'`.
  `products`, `prices`, `complete` and `unreadable_price_rows` now describe
  current-mode rows only; a price list that does not parse under another mode's
  product does not make the catalogue incomplete.
- Freshness: `last_written_at` is the latest write to a current-mode row, or
  null, drawn "Not recorded" (it was "never written"). Nothing stores whether a
  sync is running or has failed (`CATALOG_SYNC_BASIS` already says so), so the
  page says "Sync: Not recorded" rather than "fresh".
- The mode comes from the Stripe secret key, as the storefront's does; the
  panel's publishable-key row is a separate, existing line.

**Storage**

- `GET /api/admin/platform/storage` gains `populations`: `members`, `staff`,
  `unattributed` and `total`, each with files, measured bytes and unknown-size
  files (accounts and accounts with files on the first three). Staff are the
  admin plan, the rule `members_with_files` used. Unattributed are owner ids
  that are no account. `total` is the sum of the three, and a test asserts it
  equals `totals`.
- `totals` is the whole platform only. `totals.members` and
  `totals.members_with_files` are removed; their callers (the Platform storage
  page and its model) read `populations`.
- If the plans cannot be read, `populations` is null with
  `populations_reason`; no split is guessed and nothing reads 0.
- Unknown-size files are reported per population, never added as 0 bytes; the
  byte totals stay a floor (`measured_is_floor`) while any exist.
- The page: the Total stored tile says "members 100 MB · staff 900 MB"; the
  Members tile says "of N members · X stored · staff not counted"; a new
  "Who holds the bytes" table lists each population with its total last.

**Departures and limits**

- A file whose owner is NULL is skipped by every area's `owners` query
  (`user_id IS NOT NULL`), so it is in no population and not in the total.
  Counting it would change thirteen queries; the reply's `populations_note`
  says so. Left open.
- The Admin v2 canvases for Platform are in PR #4877 (design only); this render
  change is modest and in the existing page's style, and may touch the same
  files.
- No migration: `livemode` exists (691) and the summary reads it.

  `getCatalog` in both modes; row-by-row agreement; other and unknown apart; no
  key; unreadable lists counted for current rows only.
- `storage_populations_4856.test.ts` (3): 100 MB member + 900 MB staff = 1 GB;

- `platform_populations_4856.test.mjs` (4) and additions to

  `platform_consoles_d213.test.ts`, `catalog_summary_4703.test.ts`,
  `storage_room_d1170.test.ts`, `storage_tiers_d1172.test.ts` (fixtures now carry
  `livemode`, the key, and `populations`).

  plans-unreadable defaulted to zero, copy drawn as a literal or 0); 26 caught.
  Three first survived: an equivalent condition (removed), a literal "Live"
  and a "Not recorded" fallback (tests added).
