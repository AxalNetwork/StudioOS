### What was decided

1. **The tab is a choice by gid, never a fallback.** `findTab` refuses `tab_missing` (409) when the linked gid is not in the workbook, for export, import, both previews and reconcile, and leaves the link as it was. `GET /funds/sheet/tabs` lists every tab by gid with its filled rows and whether row 1 carries Axal's headers. `PATCH /funds/sheet/link` needs `sheet_gid` or `create_tab` (`tab_required` otherwise); a gid in the pasted URL is not a choice. `create_tab` adds an empty tab (`tab_exists` if the name is taken). The status read checks the tab every time and answers `tab_state` (present, missing, or unknown when Google did not answer).
2. **Export writes first, then clears only the rows past the new end, then reads back.** The old order (clear `A:K`, then a separate write) could leave the tab empty. Google applies a values write whole or not at all, so a refused write (4xx) is `failed` with the tab unchanged. The run counts the rows read back by uid against `COUNT(*)` of the owner's funds: Complete only when every fund is on the sheet and nothing is left below; Partial otherwise; `uncertain` when nothing could be read back.
3. **Every fund is exported.** `listOwnerFunds` pages 500 at a time with no cap. 501 funds write 501 rows.
4. **Import is planned before anything is written, by the sheet's own row numbers.** `planImport` is pure; the preview and the run both call it. A blank row is listed as blank and keeps its number. A new fund's identifier goes to the mapped uid column on its own row (`uid_cell`), not to column A. A tab with no uid column cannot create (its rows are Resolve), and one with no Fund or uid header is `header_missing` (422).
5. **Only mapped and ticked fields update, and only when they changed.** The fund record always moves; Thesis is ticked by default; Notes and Pass reasons are private and move only when ticked on that run, in either direction (D7035 option A, pending the owner). A column missing from the sheet leaves Axal's value. An unchanged row is Unchanged and is not written. An update writes only its changed columns (`CASE WHEN ? THEN ? ELSE col END`, no SQL built from input).
6. **Resolve rows.** A value Axal does not record (stage fit "maybe", a cheque that is not a number) makes the row Resolve until the run chooses `keep_axal` (the other fields still update) or `skip`. A uid that is not the owner's, or that repeats an earlier row, is Resolve and is never imported. Unresolved rows are not imported.
7. **A run record per run.** `research_fund_sheet_runs` holds direction, status (`running`, `complete`, `partial`, `failed`, `uncertain`), counts, the pending identifier cells and when it was verified. `idempotency_key` is unique per owner and required (`idempotency_key_required`); the same key answers the first run (`replayed: true`) and writes nothing.
8. **Import writes Axal in one D1 batch together with its run state.** When there are new funds, that batch sets the run to `uncertain` with the cells awaiting identifiers, so a Worker that stops after the batch still leaves a correct record. The identifiers are then written and read back; all present is Complete. A timeout or refusal there answers 200 with status `uncertain`, not a 502 a retry would repeat. While an import is `uncertain`, a new import is refused with `reconcile_required` (409, naming the run).
9. **Reconcile.** `POST /funds/sheet/runs/:runUid/reconcile` reads the pending cells (`write: false`, "Check the sheet") or also writes the empty ones (`write: true`) and reads back. All matching is Complete; any still empty stays `uncertain`; a cell holding something else is left alone and the run ends Partial, which reopens import.
10. **Counts per run in status.** `GET /funds/sheet/status` adds `last_runs` (latest export and import with counts and status), `open_run` and `workbook_title`. The two clocks stay for older readers.
11. **Frontend.** `SheetsSyncCard` moves out of `FundsZone.jsx` into its own file. The actions are named Export Axal funds to Sheets and Import from Sheets. Each opens the shared `Sheet` (a bottom sheet on a phone) and goes Scope → Review → Result; the export needs a confirmation tick before its primary. One primary per card state (connect, choose a tab, reconcile, export). Disabled actions are `aria-disabled` with their reason beside them. Focus goes to each step's heading, and back to the card heading from a result. Each result has its live-region sentence (`announcement` in `sheetsSyncModel.js`); a run's idempotency key is made when its review opens.

### Departures from the canvas

- The canvas draws a 500-of-501 export with "Write the remaining fund". Paging makes that case not arise; a Partial export offers "Export again", which rewrites the whole managed range.
- The cleared-cells line names the cells (up to 20) rather than describing their contents ("Total", a formula, a date).
- The run log drawn under Outcome uncertain is not kept; the run's counts, pending cells and detail sentence are.
- The "Open sharing in Google" link on a Failed export is not drawn.
