## D5616 — Advisory PR overlap and textual conflicts (#5616)

The pure `prOverlap.mjs` classifies paths, joins overlapping PR pairs and new
migration stamps, groups connected pairs and suggests ready/fewer-files/lower-PR
order. README union merges are ignored. A shared path never implies a textual
conflict: the verdict comes only from `git merge-tree --write-tree` on validated
40-digit SHAs, never from PR code. Renamed paths include their previous name.
Names are escaped for Markdown, HTML and mentions.

The CLI bounds API requests (300), remaining quota (stop below 100), PR pages
(10), files (30 pages/3,000), comment pages (30) and merge checks (30). Missing
files, changed heads during fetch, request failures and exhausted limits produce
an explicitly partial report. Only this reporter's marker comments are edited;
unchanged bodies cause zero writes. Existing comments are cleared when their PR
stops overlapping. No labels, reviews, checks or merges are written. The parent
#5600 uses the overlap marker, distinct from other reporters. Concurrency is
serialized by the hourly workflow. A finding never fails the workflow.

Verify-first evidence, 2026-11-11:

- The [issue-comment API](https://docs.github.com/en/rest/issues/comments#create-an-issue-comment)
  accepts Issues write for issues and Pull requests write for PRs. The scheduled
  job grants both, with Contents read for git; top-level permissions are empty.
- The [PR-files endpoint](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files)
  is limited to 3,000 files. Reaching the local limit marks the report partial.
- A real `--filter=blob:none --bare --single-branch` clone fetched
  `refs/pull/5563/head`, `5553/head` and `5523/head`. Its remote is a promisor
  with filter `blob:none`. Merge-tree lazy-fetched needed blobs and returned
  exit 0 for #5563/#5553 and exit 1 for #5563/#5523.
- The live read-only scan reported #5563/#5553 clean, #5563/#5523 conflicting,
  and #5553/#5523 conflicting. #5562 merged at 19:07:45Z and is excluded.
- Unit fixtures prove an unchanged second run writes zero comments and an
  existing comment receives one PATCH, no POST. The owner dispatches the first
  publishing workflow after merge; the live verification here is dry-run only.
