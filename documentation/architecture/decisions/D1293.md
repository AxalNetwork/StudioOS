### 1. Migration 636

| Column | Meaning |
|---|---|
| `articles.featured_at`, `featured_by` | When a Super Admin featured the article, and who. Both NULL: not featured. |
| `article_review_comments.parent_id` | The thread this comment answers. NULL starts a thread. One level only. |
| `article_review_comments.resolved_by` | The admin who resolved the thread. NULL while open, and for older threads. |

- **Grep first (D689 D-t):** none of the five columns exists in an earlier migration or in `schema_baseline.sql`.

- **`ensureNewsSchema`** names the columns in its `CREATE TABLE`, so a database it creates matches the migrations. It does not `ALTER` them in, so it can never collide with 636.

### 2. Routes

**`routes/admin_articles.ts`** (`requireAdmin` on every route):

| Route | What |
|---|---|
| `GET /api/admin/articles/:id` | Adds `rendered_html` (`renderMarkdown` of the current markdown) beside `body_markdown`; each revision's `saved_by_name`; each comment's `parent_id`, `resolved_by`, `resolved_by_name`, `edited_at`. `body_html` stays what was rendered at publish. |
| `GET /api/admin/articles/:id/revisions/:rev` | One revision's stored text (title, subtitle, markdown) and its saver's name. 404 `revision_not_found`; 400 on a bad number. |
| `POST /api/admin/articles/:id/feature` `{ featured }` | Super Admin only (403 `super_admin_only`). A published article only (409 `invalid_status`). At most `FEATURED_MAX` = 3 (409 `featured_full`). The count is inside the UPDATE's own WHERE, so a race for the last place features one article. Featuring a featured article, or unfeaturing one that is not, answers `changed: false` and writes nothing. Audit `article.feature` / `article.unfeature`, with the article id only. |
| `POST /api/admin/articles/:id/unpublish` `{ reason }` | A reason under eight characters is refused (400 `reason_too_short`), as request-changes and reject refuse one. Clears `featured_at`/`featured_by`. The status flip is conditional (`AND status = 'published'`), so of two admins racing, the loser gets 409 and sends no notice. The author gets `author_unpublished` with the reason. Audit `article.unpublish` holds `article_id` and `was_featured`, never the reason. |
| `POST /api/admin/articles/:id/comments` | Takes an optional `parent_id`: a thread's first comment on this same article (404 `comment_not_found` otherwise). A reply takes no anchor. |
| `PUT /api/admin/articles/comments/:cid` | Resolving sets `resolved_by`; reopening clears it with the time. A text change stamps `edited_at`. A reply cannot be resolved on its own (400 `reply_not_resolvable`): the thread is. |
| `DELETE /api/admin/articles/comments/:cid` | A thread's replies go with it, in the statement itself, not only by the foreign key. |

**`routes/articles.ts`:**

| Route | What |
|---|---|
| `GET /api/articles?featured=1` | Orders by `featured_at` first, most recently featured first, then by publish date. The `"featured"` tag no longer counts. Each item carries `featured: true \| false`. |
| `POST /api/articles/:id/comments/:cid/replies` `{ body }` | The article's author only (403 `not_your_article`, also for an admin, who replies through the admin route). The comment must be a thread's first comment on this article, written by someone else (404 `comment_not_found`). Empty text is refused. The comment's admin gets an in-app notice, "The author replied to your comment", linking `/admin/articles/<id>`, without the reply's text. |
| `GET /api/articles/draft/:id` | The author's comments carry `parent_id` and `edited_at`. |

**`services/articleNotify.ts`:**
- `author_unpublished`: "Your article was unpublished", with the reason. It replaces the borrowed `author_changes_requested`.
- `notifyCommentReply`, for the reply notice above.

**Client (`frontend/src/lib/api.js`, the existing `articles` and `adminArticles` blocks):**
