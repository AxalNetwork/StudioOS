## D4479 — Learning exercise answers capped at 2,000 characters (#4479)

The LR10 design's 2,000-character limit was confirmed by S1 on 2026-11-04 in
#4479, part of #3726. The Worker exports EXERCISE_ANSWER_MAX_CHARS and counts
Unicode code points in the trimmed text it stores. At 2,001 it returns 400
bad_answer with “An answer is at most 2,000 characters.” Text exercise reads
carry answer_max_chars; checklist reads do not invent a text limit.

S1 confirmed that no stored answer exceeded this limit: production held no
Learning items when the task was specified (D3726's 2026-11-04 update). This
change performs no production read or migration and deletes no answer.

The counter counts Unicode code points and formats both figures as en-GB.
It is absent when the read supplies no max. Checklists keep their N of M done
line. The owner explicitly chose literal native textarea maxLength=2000 in
this chat, rather than a 4,000-unit native safety ceiling with code-point
input enforcement. Native maxLength counts UTF-16 units, so its limit is
intentionally stricter for astral characters; the displayed counter and
Worker limit still count each emoji code point once.

The exercise's header submits the existing form by id. Submit is used for
new/submitted answers, Resubmit for Needs work, and a disabled Resubmit with
“Accepted. There is nothing to resubmit.” for Accepted. Status and feedback
use only sent dates and reviewer names; absent review dates say Not recorded.
A rejected submission displays the parsed route refusal, never a raw thrown
network error. Earlier answers remain in the history.

The exercise page carries no AIRail, Ask or Eadwyn panel. Its own-answer
trigger inset is deliberately not built. The sidebar remains in Account;
there is no new Learning licence or workspace switcher. The exam portion of
the shared container belongs to S19's #4476/#4498 and is preserved for that
integration. Only the exercise portion is changed here.

The existing theme tokens cover new surfaces. The status column comes first
on stacked layouts, the answer box is 110px, mobile gutters are 16px, and
interactive targets are at least 44px. Long submitted answers wrap inside
the grid instead of widening the page.

Verification covers mounted Worker 2,000/2,001 ASCII and emoji boundaries,
text/checklist read metadata, the pure counter, all status/action states,
missing dates, checklist preservation, and a mounted header/form/refusal
flow. Restoring the old 50,000 cap makes the 2,001 test fail. Local synthetic
browser checks cover phone/tablet/desktop light and dark states, native input
limits, overflow and the actual header submission; no production provider is
contacted.
