## D9151 — Google Sheets Connect: the state is bound to the browser that started it, and the account must still be active (#9151)

**Decision date:** 2026-11-27. **Scope:** `POST /api/research/funds/sheet/connect` and
`GET /api/research/funds/sheet/callback` (`routes/research.ts`), three helpers in `services/fundSheets.ts`, the
callback test in `cloudflare-worker/test/authz_research_d4570.test.ts`, and the callback's ledger note. No migration, no
other OAuth provider, no screen.

### Why

The review of #4570 slice 10 (D4570-p10 § Hardening) recorded two gaps in the callback. Neither was exploitable, since
reaching the state takes the Super Admin's own ten-minute Connect link.

- The signed, single-use state named who started Connect, but nothing tied it to the browser that started it. Any
  browser bringing back a valid state landed a token on the Super Admin's connection, for whichever Google account
  finished consent. The class is login CSRF.
- The callback read the state's user without `is_active`, so a Super Admin disabled after Connect could still land a
  token for up to ten minutes.

### What changed

- **Connect sets a binding cookie.** It is `studioos_sheets_state=<the state's nonce>`: HttpOnly, Secure,
  SameSite=Lax, `Path=/api/research/funds/sheet`, `Max-Age` equal to the state's ten minutes.
  - It carries the session cookie's Domain (`authCookieDomainAttr`): on HQ that is `.axal.vc`, on a branch, localhost
    or preview it is host-only.
  - The Domain matters because Connect answers on the host the SPA runs on, while Google returns to the registered
    callback host (`app.axal.vc`). This is the same reason as Google sign-in's state cookie (D722).
  - The SPA calls `/api` on its own host with `credentials: 'include'`, so the browser keeps the cookie.
- **The callback refuses an unbound state**, before the state is spent:
  - A state with no binding cookie, with another state's nonce, or with the nonce under another cookie's name redirects
    with `reason=invalid_state`. It exchanges no code and stores no token.
  - The state stays unspent, so a stray attempt does not use up the Super Admin's own.
  - Every value under the cookie's name is tried, because a host-only cookie can sit beside the Domain one. Each is
    compared in constant time.
- **The callback refuses an inactive account.** A state whose user is no longer active redirects with
  `reason=forbidden`, the refusal a non-Super Admin's state already gets.
- **Every callback answer clears the binding cookie**, with the Domain and without it, so a state is tried at most once
  in this browser too.
- **Unchanged:**
  - the state is HMAC-signed, stored, single-use and ten minutes long;
  - only a Super Admin's state lands a token;
  - every refusal is a redirect to `/research/funds?sheets=error&reason=…` with no secret.

### Why a cookie, not PKCE

PKCE proves that the party exchanging the code is the one that asked for it. Here that party is the Worker, which
would hold the verifier itself, so PKCE alone would not tell one browser from another. The cookie does, and it is the
pattern Google sign-in (D722) and Mercury's OAuth (`routes/mercury_oauth.ts`) already use. PKCE can still be added as a
separate code-interception defence. Nothing here needs it, and it would need a column on `oauth_state_tokens`.

### Tests

`authz_research_d4570.test.ts`, the Sheets callback test, now also proves:
- Connect sets the cookie with the issued state's nonce and the attributes above.
- Each existing refusal is still refused when it brings a matching cookie: no, unsigned, forged, never-issued or
  expired state, an admin who is not the Super Admin, a founder.
- The Super Admin's valid state is refused with no cookie, with another state's cookie, with a wrong-length value, and
  with the nonce under another name. It is still unspent afterwards.
- A Super Admin disabled after Connect lands nothing.
- The rightful state, back with its cookie beside another cookie, lands one token, clears the cookie, and is spent.

Mutation check: 8 mutations, 8 caught.
- In the callback: the binding check removed; the check moved after the state is spent; the inactive account allowed;
  the cookie no longer cleared.
- In the cookie helpers: any cookie value accepted; any cookie name accepted (it survived the first run and is caught
  since the "another cookie's name" case was added); the clearing cookie keeping its Max-Age.
- In Connect: no binding cookie set.

The length comparison in `sheetsStateBound` was not mutated: without it, a longer value still differs from the nonce
in its extra characters, so it would be refused either way.

### Rollback

Revert the PR. Connect and the callback go back to the state alone. The cookie expires on its own within ten minutes.
