## D4815 part 15 — Deals v2 DX15: the deal page on a phone at 390px (#4815, #5908)

- **Status:** built 2026-11-18. Canvas section DX15, board DE15 (`design/incoming/Deals v2 Page.dc.html`, `design/incoming/Deals v2 · Boards.dc.html`). Frontend only: no Worker route, migration or API module changed.
- **Numbering:** the section's own number, as part 4 is DX4 and part 10 DX10.
- **Builds on:** part 4 (#5903: the frame, the strip, the sequence, the one next action at a phone's foot, the eight tabs) and part 41 (#5904: the Overview).
- **Files:** `frontend/src/pages/deal/DealFrame.jsx`, `DealOverview.jsx`, `DealInsightTabs.jsx` (Market's competitors), and one class in `frontend/src/pages/DealRoomPage.jsx` (the page's foot padding).

### What is built, to DE15's acceptance

- **Compact header.** Part 4's header already wraps to a phone: the venture as the one `h1`, the company-stage chip, the investor's progress chip, the actions. The compact round is the strip under it.
- **The strip, two by two.** Round, Committed, Minimum and Closes, as DE15 draws them, with Instrument as a full-width last row (DE15 draws four; part 4 keeps all five). Each cell draws only its inner edges, so no line is doubled. From `md` up it is part 4's five-across strip, unchanged.
- **Progress as a vertical stepper.** On a phone (`PHONE_QUERY`, below 1024px) the eight steps are one bordered list, a row per step: a mark (a tick when done, the step's number otherwise, dashed for an IC step with no record) and the step's word; the current row is lit and carries `aria-current="step"`. Each row is at least 44px. The rows draw no action.
- **A sticky primary action.** The Worker's one `next_action` stays in the foot bar (part 4), now padded for the device's safe area. The page's foot padding now follows the bar's own width rule (below 1024px, was below 768px), so from 768px to 1023px the bar no longer covers the page's last lines.
- **Tabs scroll sideways.** The eight tabs keep one row that scrolls, with snap points; the lit tab is scrolled into view by the row alone (`scrollLeft`, never `scrollIntoView`, which would move the page).
- **Scorecard.** The Scorecard tab already is the compact strip with expandable rows on a phone (part 51, `Scorecard.jsx`: Scope, Score, Value and a disclosure that opens the scope's evidence); this part does not touch it.
- **No desktop table in a narrow scroll container.** Market's competitors were a 520px table scrolled sideways inside the card. Below `md` each competitor is a card (name, why it matters, Price, Depth, Not recorded where empty); from `md` up the table, with no minimum width. No other table on the deal page's tabs scrolls sideways.
- **44px targets.** The frame's buttons (`BTN_P`, `BTN_S`, used across the deal tabs) are 44px tall below `md`, 34px above. The Overview's links that stand on their own line (Open scorecard, Open the shared evidence, N more in Notes, Full terms) are 44px targets below `md`; a link inside a sentence stays inline.

### Departures from the canvas

- **Order.** DE15 draws the stepper under the tabs; the build keeps part 4's order (strip, progress, tabs), so progress reads the same on every tab and at every width.
- **Instrument stays**, as a fifth, full-width row (part 4's departure, kept).
- **Five steps in DE15, eight here.** DE15 shows the first five of the sequence; the build draws all eight, as the stage read names them.
- **The top bar** (menu, title, Ask Eadwyn) is the workspace shell's phone bar, not this page's.
- **Dark.** DE15 has no dark board; the stepper follows DE16b with the tokens' dark pairs.
