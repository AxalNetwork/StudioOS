### What changed

`GET /api/admin/revenue/summary` gains `metrics`. It holds one envelope per metric, built by
`cloudflare-worker/src/services/revenueReadModel.ts`, one function per metric. Every other field of the reply is
unchanged, including `temporal`, `quarter`, `current_period`, `period_requested`, `read_at`, `subscriptions` and
`subscriptions_reason`. `temporal.metrics` is `period`.

Each envelope carries the fields #5950 asks for:

| #5950 asks for | Field |
| --- | --- |
| source | `source`: the store and rows read |
| period | `period`: the requested `YYYY-Qn`. Every metric here follows `?period`, and a bad period is still 400 |
| currency | `currencies`: the ISO codes of the buckets. Each figure sits in its own currency's bucket, and no total is added across them |
| last reconciled | `last_reconciled_at` (null when none) and `last_reconciled_basis`, which says what "reconciled" means for this store |
| incomplete or unreported rows | `incomplete_rows` and `incomplete_detail` |
| pre-migration coverage gap | `coverage`: `state` (`covered`, `partial`, `none`, `unknown`), `recorded_from` and `recorded_by` (the `financial_event_coverage` row, or the migration that began recording) |

Each envelope also carries `key`, `label`, `state`, `reason`, `pending_issue` and `values`. The states:

| State | Meaning |
| --- | --- |
| `complete` | every row read for the period is there and whole |
| `incomplete` | figures are shown, and `incomplete_rows` and `coverage` say what they leave out |
| `not_recorded` | the store exists and holds nothing for this period |
| `not_available` | no store records this yet; `pending_issue` names the slice that will |
| `unreadable` | the store could not be read; `values` is null |

A figure the store does not hold is null, never 0. A failed read makes only that metric `unreadable`. There is no
Stripe call on this path.

Notes on the rules:

- **Undated rows.** A ledger row with no `occurred_at` cannot be placed in a period. It is counted as incomplete in
  every period rather than dropped.
- **Disputes.** A dispute opened withdraws `refund_cents`, and a dispute won reinstates `gross_cents` (D5299). They
  are reported as `dispute_withdrawn_cents` and `dispute_reinstated_cents`, apart from refunds and from each other.
- **Promo figures.** A promo figure is shown only for `reported` and `stale` rows, as on `/promo-ceilings`. A mismatch,
  a missing report or an unreadable report reads null.
- **Two SQL fragments.** `SUBSCRIPTION_LEDGER_ROWS` and `REFUND_DISPUTE_ROWS` are literal module constants with no
  input in them, interpolated into `DB.prepare`. They are recorded in `scripts/baselines/sql-prepare/` (three
  sites). Every value is still bound with `?`.
- **Reused results.** The subscription and invoice readers already run for the summary, so the read model takes their
  results and does not read those stores twice.
