## D6253 — A GP's read-only fund performance detail (#6253)

Investor Fund Detail Pages (D6244, owner answers D6244-p2), boards I12,
I13 and I19C: keep the cross-fund summaries and select one fund's detail.
The Worker owns permission: `GET /api/funds` supplies `can_manage`, using
`requireFundGp`'s institutional-tier, GP-of-record and active-company scope.
Only literal `true` enables the existing quarterly-history and positions
reads. Failed or unknown access enables neither. Company changes remount the reader and discard old permissions and results.
Refresh creates a new read generation, ignores late responses and preserves
the shell, selected fund and filter. It rechecks the audience before either
detail request executes. Show detail focuses and scrolls to the selected
section. A filter that hides the selected fund explains that state instead
of silently selecting another fund.

| Value | Read | Store / meaning |
| --- | --- | --- |
| Fund summaries | `/api/fund-performance` | Existing called-capital performance service; unchanged |
| Detail audience | `/api/funds` | `can_manage`, from the Worker's operating scope |
| Quarter-end figures and basis | `/api/fund-performance/:id/history?step=quarter` | Existing point-in-time calls, distributions and dated marks |
| Latest mark, date, source, cost | `/api/fund-performance/:id/positions` | Existing attributed positions and dated valuation read |

Reuse `admin/fundAdmin/performanceModel.js` for quarter chart series,
money, dates, position rows and quarter-old stale flags. No new calculation,
endpoint or write. A zero mark remains zero. A missing mark is Not recorded
with the returned reason; invested cost is never its replacement. History
and positions load and retry independently. Failed reads say Unavailable;
an empty history repeats the Worker's reason. Truncation is explicitly Partial.

### Canvas departures

- I12: the detail's chart has labelled quarter cards as its text alternative,
  and positions use labelled cards; both reflow at 390px without horizontal
  scrolling. No mark or attribution controls are added to this read-only page.
- I12 calls/distribution lists and I12B's IRR cash-flow explanation are beyond
  #6253's history/positions scope; the existing summaries and quarter figures
  retain their basis. No extra cash-flow API is invented.
- I13 LP history is approved but the only mounted quarterly-history route
  still requires `requireFundGp`. LPs retain their allowed summaries and a
  visible explanation, with no refused GP calls. Opening an LP history route
  remains the owning backend task.
- I13B's blanket Institutional lock is superseded by D6245: an LP can read
  summaries without that tier. Detail admission follows server permission.
- I19C: cards are also used at desktop widths to keep one labelled responsive
  text equivalent of the chart. Light and dark use existing shared primitives.

Regression coverage: `fund_performance_detail_6253.test.mjs` covers positive
and negative admission, response identity, missing/zero marks, staleness,
isolated failures, loading, empty, partial and unknown-access states.
Its mounted Refresh regression holds the permission read unresolved, verifies
that no old GP permission is reused, then verifies both detail reads refresh
when permitted and the selected fund is preserved.
