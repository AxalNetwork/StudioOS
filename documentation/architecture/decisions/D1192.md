### 1. The Worker: two changes to the one writer

The issue requires that every prospect write goes through `services/raiseWriters.ts`. Two writes it needs did not exist there, so they are added.

- **A committed investor's status.**
  - `updateProspect` (`PATCH /api/cycles/raise/prospects/:id`) now takes `commit_status`: `soft`, `signed` or `wired`.
  - A status is refused on any stage but Committed (400).
  - A stage moved away from Committed clears it.
  - `null` stores "Status not recorded", which the commitments read never counts (D1190).
  - The log line says `status`, never the investor's name.
- **Import.**
  - `importProspects` (`POST /api/cycles/raise/prospects/import`, `{ rows }`) takes at most 50 rows.
  - Each row goes through `createProspect`, the same path Add investor uses, and each created row is logged.
  - Every row that is not added is returned with its row number and why: a stage outside the pipeline's, no name or valid email, or already in the pipeline.
  - `contacts.ts`' older import and PUT stay for the old pipeline page, but this tool never calls them.
- **Clients:** `cyclesWrite.raise.prospectsImport` and `cyclesWrite.raise.prospectNextStep` (the existing `PUT …/next-step`).

### 2. Pipeline (CRL2, CRL3)

`CapRelPipeline.jsx` replaces D1188's table on the Pipeline tab.

- **The read** is the venture's prospects (`GET /api/contacts/raise-prospects?project_id=`, the pipeline's own read). The module read gives display cells, not stages or statuses, so it cannot drive a board.
- **The board:**
  - five columns, Identified to Committed, with the most recently changed card first;
  - Passed collapsed at the right;
  - every card has a "Move to…" control, so a move never needs a mouse;
  - a committed card shows its status and amount, or "Status not recorded" and "Amount not recorded", never $0;
  - an investor on a stage the board does not draw is counted under the board and listed in the list, never dropped.
- **The list:** every investor as a row, with a checkbox. The picked rows move together.
- **On a phone (CRL18):** the board shows one stage at a time, chosen from a select. The lightbox is the Lightbox shell's full screen.
- **States:**
  - empty, with Add investor and Import;
  - loading skeletons;
  - "Your investors" Unreadable with Try again, which says it is not a claim of none.

### 3. The dialogs (CRL5, CRL6), every one in-page, saying what it changes

| Dialog | Writes through |
|---|---|
| Move (one card or the picked rows) | `PATCH /prospects/:id`. Moving onto Committed asks "What did they commit?": Soft, Signed, Wired or Status not recorded, and only Signed and Wired count. Several investors are written one by one, and any that fail are named. |
| Status (a committed card) | `PATCH /prospects/:id` `{ commit_status }` |
| Next step | `PUT /prospects/:id/next-step` |
| Log a step | the record's `log` action (`logProspectEvent`) |
| Add feedback | the record's `add-feedback` action |
| Add investor | `POST /prospects`. A duplicate email is answered inline ("Already in the pipeline") and the dialog stays open. |
| Import | `POST /prospects/import`, 50 rows a request. The file or pasted CSV is mapped by its header (name or email; firm, amount, stage, notes), and the preview names the mapped and ignored columns. Every data row is sent, even one with no name, so the writer reports it rather than it vanishing. The skipped rows come back numbered as in the file. A chunk that fails to send is reported row by row. |

Eadwyn does none of these. Nothing here sets an amount, a status or a Fit for the founder.

### 4. The investor lightbox (CRL4) and Overview (CRL1, CRL13)

- **The lightbox:**
  - It opens from a card or a row.
  - It draws the investor's record read (`cyclesApi.record('raise', …, 'capital-relationships', id)`): its facts and its sections (timeline, feedback, materials, and whatever else the record carries), read only.
  - Its buttons open the dialogs above, and "Open the full record" goes to the record page.
  - A failed record read says so, and the dialogs still work.
- **Overview's blocks** sit above the module page's own round card and tables. Each answers alone:
  - **The round at a glance:** D1190's commitments read, with the counted total against the target and the share.
    - What is listed but not counted is named.
    - With no round, its reason shows.
    - A total that did not come back reads "Not recorded", never $0.
    - A partial read says a source is missing.
  - **Needs you:** overdue follow-ups, follow-ups due today, conversations with no next step, and committed investors with no status (not counted).
  - **The pipeline by stage**, with "Against 30 days ago: not recorded".
  - **Follow-ups**, in due order, with the overdue marked.
- **The moved notice (CRL13):** "The investor pipeline is now Capital relationships › Pipeline." for `?moved=pipeline`, and "Investor match is now Capital relationships › Match." for `?moved=match`, in the canvas's words. It is read from the address and can be dismissed.
- **Dark (CRL19):** every new colour has its `dark:` pair.

### 5. Not built here, and why

- **Against 30 days ago, the next meetings, recent activity, and fit across the pipeline (CRL1).** No read returns a stage history, upcoming investor meetings across the venture, or one timeline. One block says "Not read here yet" with where each comes from (Calendar, Activity, Match).
- **The directory search in Add investor (CRL5).** Picking a fund from the directory is Match's read (D1190), which part 5 draws. Add takes a name, firm and email, and catches a duplicate inline.
- **An editable column map in Import.** The header is mapped automatically and the preview shows the map.
- **Profiles and no permission (CRL16, CRL17):**
  - the co-founder's menus;
  - the studio admin's summary and the reason asked first;
  - HQ's summary;
  - the Explorer's and another venture's refusals.

  These are the access part's. Today the module's own gate refuses them as before.
