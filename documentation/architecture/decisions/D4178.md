## D4178 — The Stream lesson player: Stream's own player, a caption read for timed cues, and chapters that seek (#4178)

- **Status:** built by Claude Code for slot S14, 2026-11-03. Not deployed and not checked live.
- **Part of:** #3726 (D3726), task L3. Built on L1 (#4176, D4176).
- **Migration:** none.

### 1. Stream's own player, so the page can time and seek it

A ready Stream video now plays in `@cloudflare/stream-react` (pinned exactly, 1.9.3) instead of a bare iframe.
- **Source:** the player takes the signed token and the customer code, read from the `iframe_url` the item read minted after `canSeeLearning` (`streamSourceOf`). An address on any other host gives no player source. `videoPlayback` already refuses such a host before this point.
- **Why:** the package gives `currentTime` and seeking through its SDK. The page uses them to mark the current chapter and cue, to seek on a click, and to resume.
- **Controls:** speed, quality, the captions menu and picture-in-picture are the player's own.
- **Script:** the package loads Cloudflare's player script from `embed.cloudflarestream.com`. The SPA's HTML carries no Content-Security-Policy (`frontend/public/_headers`), so nothing is widened.

**Resume:** the player starts at `progress.position_seconds`, through the existing `resumeAt` rule. Both the Stream player and the uploaded-file player write through one `usePositionWriter`: at most one write every 15 s while playing, and one on pause or end. The 15 s throttle is D3726's.

**A plain embed is text only.** YouTube and Vimeo cannot be seeked from the page, so their chapters and transcript are text, never buttons that do nothing.

### 2. A caption read, because nothing gave the page a caption's timing

The issue asks the player to parse the ready caption's VTT into cues. L1 (D4176) sends only each caption's language and label. Stream's Workers binding has no caption read either: it can generate, upload, delete and list captions, but not fetch one.

So this task adds one member route, `GET /api/learning/items/:uid/captions/:lang` → `{ language, vtt }`:
- **Placement:** it sits in `routes/learning.ts`, beside the item read.
- **Order of checks:**
  1. it asks `canSeeLearning` first;
  2. then it reads only a caption the store records as ready, for the item's ready Stream video;
  3. only then does it fetch the file from Stream's API with `STREAM_API_TOKEN`, the token L1's tus route already uses.
- **Refusals:**
  - 503 `stream_captions_unavailable` without the binding or the token;
  - 502 `caption_unreadable` for anything that is not WebVTT;
  - 404 for an item the member cannot see, or a caption that is not ready.
- **The answer:** private and never stored. It is JSON rather than `text/vtt` because the site's one request helper reads JSON.
- **The token:** never sent or logged.

**Owner step:** the route works once `STREAM_API_TOKEN` is set (PRODUCTION.md §4). Until then the transcript is the plain text.

### 3. Cues, tolerantly

`parseVtt` reads a WebVTT file into `[{ start, end, text }]`:
- **Not cues:** NOTE, STYLE and REGION blocks are skipped.
- **Malformed cues are skipped and the rest kept:** a missing or unreadable timing line, an end before its start, or empty text.
- **Text:** tags and the common entities are stripped.
- **Input forms:** a BOM and CRLF line ends are read.
- **Not WebVTT:** a file without the header has no cues.

The transcript then shows:
- **with cues:** the cues, the current one marked; a click seeks;
- **with no cues:** the plain transcript, with D3726's line "No caption cues, so the plain transcript is shown.";
- **when the captions cannot be read:** "The captions could not be read, so the plain transcript is shown." A failure is never an empty transcript;
- **with neither:** "No transcript is recorded for this video."

### 4. Chapters, layout and the hover preview

- **Chapters** come from the item's `chapters` (`chaptersOf`: time order, whole seconds, titled only). The current one is marked, and a click seeks.
- **Layout:** on a wide screen the chapters sit beside the player; on a tablet or phone (lr20b, lr21) they stack below it. The transcript is always below.
- **Retired line:** D3726's empty-chapters line, "Chapters arrive with the Stream videos (#4176)", is retired now that they have. None recorded reads "No chapters".
- **Hover preview (lr7):** the library's rows do not carry a preview. A video card that the pointer rests on for 400 ms reads the item once (`readItemPreview`, kept 30 minutes, inside the signature's hour). It shows the signed `preview_url` only when Stream has one on its own hosts. The preview is decoration: hidden from assistive technology, never triggered by touch, and nothing is drawn without one. Signing a preview for every row of the list was not done, because it would mint a token per row on every list read.
