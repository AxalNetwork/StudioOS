## D1135 — Company membership and venture fixes

Issue #3015, part of #2422. No migration.

- `POST /api/company/:uid/leave` removes only the authenticated member's link.
  An atomic delete refuses the last primary admin with 409 and a reason.
  Company Settings keeps its in-page confirmation, calls this route, and removes
  the membership from the switcher. Leaving the active company clears both the
  selected row and `active_company_id`; leaving another preserves the selection.
- Create and rename trim names, refuse empty names and names over 200 characters,
  and refuse case-insensitive ASCII clashes among the caller's memberships.
  Rename excludes its own row. Unrelated companies may share a name.
- `exploring` accounts cannot create companies (403 with a code and sentence).
  Their switcher hides Add a new company.
- The free venture cap counts only non-trashed projects, regardless of status.
  `POST /api/projects/:id/restore` is founder-owner only, within 30 days, and
  checks plan space atomically with restoration. Active rows restore idempotently.
  The existing administrator restoration path remains separate.
- Email-mode project invitations call the existing transactional sender once,
  after persisting the hashed token, using that invitation's accept link.
  An atomic reservation refuses unexpired pending duplicates and caps email
  invitations at 10 per inviter and 20 per venture per hour, across managers.
  Mail uses fixed copy without inviter-controlled names or text, and the existing
  sender checks transactional suppression. The response reports `email_sent` honestly; link-mode never sends mail.
  No new delivery store or automatic retry is introduced. A failed delivery still
  returns the existing one-time link for the inviter to share.

Verification uses real Worker routers against node:sqlite and synthetic accounts,
with outbound mail stubbed. Frontend tests exercise membership state, persistence,
Explorer visibility and failed writes. Mutation checks remove the protections and
verify the tests fail, then restore production sources.
