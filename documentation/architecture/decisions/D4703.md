## D4703 — Practice integrations and platform controls converge on one state, part 1 (#4703)

### Decision

Repeated or concurrent operations, and a privileged setting written alongside
its record, end in one intended state. Part 1 fixes the paths where the
recorded state could go wrong. Part 2 (below) makes health and summaries
complete.

**Practice (advisor bookings)**

1. **A cancelled or missed session is not payable.**
   - The cancellation-fee policy is that there is none.
     `BOOKING_PAYABLE_STATUSES` is `pending`, `confirmed` and `completed`.
   - `POST /bookings/:id/pay` refuses a `cancelled` or `no_show` booking with
     a 409 before any other check, so the answer is the same whether
     charging is on or off.
   - A fee would be a new, named entry in that list.
2. **A cancel or confirm writes only from the status it read.**
   - `transition()`'s UPDATE is `WHERE id = ? AND status = ?`.
   - When two presses race, the second changes nothing and answers 409.
3. **Bulk slot cancellation cleans up calendars the way a single cancel
   does.**
   - `DELETE /me/slots/:id` cancels with `RETURNING id`.
   - Each booking it cancelled gets the same deferred
     `onAxalSessionCancelled` a single cancel gets (`deferCalendarCancel`).
   - Before, the status changed and every external copy stayed in the
     attendees' calendars.
4. **A pending booking's calendar copy is tentative.**
   - It goes out with `ics_status: 'TENTATIVE'`.
   - Confirming pushes it again as `CONFIRMED`.
   - The Google and Microsoft payloads now say `confirmed` / `busy` outright,
     so the PATCH turns a tentative copy firm.
5. **Payout onboarding makes one provider account.**
   - The Stripe account create carries
     `Idempotency-Key: connect:advisory:<local row uid>`, so two starts at once
     get the same account.
   - The local attach is `WHERE provider_account_id IS NULL`. An account
     attached first stands, and the later start onboards into it.

**Platform**

6. **The take rate is whole basis points, or it is refused.**
   - `parseTakeRateBps` accepts a JSON integer or a string of digits.
   - Missing, null, blank, `0x10`, `1e3` and `12.5` are 400s. The old parse
     turned null and blank into 0 and wrote 0%.
   - The write now needs the super-admin write bar: a TOTP session and a
     recent step-up, the same as the switch write.
7. **A switch release names the activation it ends.**
   - Migration `202611062212_platform_switch_revision` adds `revision`, which
     each throw raises by one.
   - A release must send the current `revision`.
   - A release from an older tab answers 409 `stale_revision` and leaves the
     newer throw standing.
   - The console reads `operator.revision`, and `hqSetPlatformSwitch` sends it.
8. **A switch or take-rate change never lands without its audit row.**
   - The change and its `admin_audit_log` row are one `DB.batch`
     (`adminAuditStatement`).
   - The switch's row is `WHERE changes() > 0`, so a no-op records nothing.
   - A failed audit fails the change, with a 503, and nothing changes.
   - The hashed-actor `activity_logs` row stays best-effort.

### Part 2 (#4703, second PR)

9. **A failed scheduled sub-task stays visible as failed.**
   - `scheduled()` catches each sub-task so the next one runs, which left the
     tick `completed` over a failure.
   - All 64 sub-task catches now report through `taskFailed(<task>)`.
   - The history row is `partial`, with `error` naming the failed tasks.
   - `partial` is in `FAILED_STATUSES`, so HQ's trigger state reads `failed`.
     The Cron tab colours it red.
   - A guard test fails if a sub-task logs its failure with a bare
     `console.error` again.
10. **The plan allowance is figured on what the member pays.**
    - `chargeOf` took the list price, so a coupon-discounted member got the
      undiscounted allowance.
    - The subscription's coupons now come off first: percentages, then fixed
      amounts in the charge's currency.
    - A discount the event names only by id cannot be read. That charge is
      unreadable and leaves the known amount in place; it is never treated as
      the list price.
    - Amounts are ordered by the event's `created`. Migration
      `202611070805_member_subscription_amount_event_order` adds
      `event_created`, so a late older event cannot overwrite a newer amount.
11. **Partner office hours get fixes 2–4.** `partner_office_hours.ts` copies
    the booking flow, so it now has:
    - conditional transitions;
    - per-booking calendar cleanup on slot cancel;
    - a tentative copy until the partner confirms, with a firm push on
      confirm.

### Part 3 (#4703, third PR)

12. **A charge on a cancelled or missed booking is recorded as owed back.**
    - `markSessionCharged` still marks the booking `collected`, because the
      money was collected.
    - It also writes one `advisory_refunds_due` row per booking, keyed so a
      redelivery writes no second row. The table comes from migration
      `202611070915_advisory_refunds_due`.
    - `GET /api/admin/platform/advisory-refunds-due` (super admin) lists the
      rows, open first. It shows booking uids and amounts only.
    - Nothing refunds automatically: moving money back stays an operator's
      act.
    - The billing states and alert kinds are CHECK-constrained, so a separate
      table avoids rebuilding either.
13. **Failed calendar deletes are retried.**
    - `retryFailedCalendarDeletes` runs hourly (minute 17) as a named cron
      sub-task.
    - It takes the 20 oldest sources stamped `calendar_delete_failed` and runs
      the same `onAxalSessionCancelled`.
    - A success drops the mapping. A failure re-stamps it, which moves it to
      the back of the queue.
14. **The remaining platform writes take the write bar.**
    - The write bar is a TOTP session plus a recent step-up.
    - It now covers:
      - every AI-policy write: models, locks, caps, tools, pause and resume;
      - the three credit-rule writes;
      - the four token-pack writes.
    - A resume clears only the pause the page read (`AND paused_at = ?`), the
      same rule as the switch release in part 1.
    - Catalog `/sync` keeps plain super-admin, as D1009 decided: it is a
      repair that reads Stripe, not a mutation.
15. **The summaries say what they are.**
    - The catalog mirror summary adds:
      - `prices.active_under_inactive_products` (active prices nobody can
        buy);
      - `complete` (every price list parsed);
      - `read_at`.
    - The storage summary adds `read_at` and `measured_is_floor`: true when an
      area was unreadable or a file's size is unknown, so the totals are a
      minimum.
