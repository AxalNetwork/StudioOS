## D672 — CodeQL and Semgrep scan without uploading to code scanning

Issue: #1542. Resolves #1008 item 7.

### Why

The owner made the repository private on purpose (2026-10-11: "Because the repo is private").
- Code scanning on a private repository needs GitHub Code Security, which is not on.
- From 2026-10-10 19:03Z, every SARIF upload was refused: "Code Security must be enabled for this repository to use code scanning".
- The code-scanning API answered 403 to every request.
- So `analyze (javascript-typescript)`, `analyze (python)` and Semgrep's `Scan` went red on every PR and every push to `main`, with no repository change.
- Nothing recorded their findings (first seen on #1541).

### What was decided

Keep both scanners running, and stop uploading. Each run lists its findings in its own job summary.

- **`codeql.yml`:**
  - `analyze` runs with `upload: never` and writes its SARIF to `codeql-results/`;
  - a "Report findings" step lists the findings.
- **`semgrep.yml`:** the `Upload SARIF` step is now "Report findings". The order is still scan, then strip the suppressed results, then report.
- **`scripts/sarif-summary.py`:**
  - it counts results by rule and level, and skips any result the scanner marked suppressed. A non-empty `suppressions` array means suppressed; an empty one means "known not suppressed", the same rule `strip-suppressed-sarif.py` encodes;
  - it lists the first 50 locations;
  - it fails only when there is no readable SARIF, because a report built from nothing would read as a clean scan.

### What did not change

- **Findings still never fail either job.** A red check still means only that the scanner could not run.
- **The report step keeps D170's rule: no `if: always()`.** A crashed semgrep still writes a resultless SARIF that cannot be told apart from a clean scan. The upload is gone, but a report built from that file would still read "0 findings" after a scan that never ran.

### What is lost, and how to get it back

- **What is lost:**
  - the Security tab's alert history and dismissals;
  - GitHub's per-PR annotations of new alerts.
- **What replaces it:** each run's summary lists every finding. A reviewer comparing counts between `main` and a PR sees what the PR adds.
- **To restore the uploads:**
  1. Turn Code Security on.
  2. In `codeql.yml`, delete `upload: never` and the report step.
  3. In `semgrep.yml`, put back the `github/codeql-action/upload-sarif` step after the strip. The report step can stay.

### Guards

- `frontend/test/code_scanning_no_upload_d672.test.mjs` pins that neither workflow uploads, and that each reports. It also runs the script on fixtures: suppressed results are skipped, an empty suppressions array is counted, and a missing SARIF fails.
- `frontend/test/semgrep_workflow.test.mjs` now follows the report step in place of the upload.
- All five mutants were killed:
  - an upload put back in Semgrep;
  - `upload: never` dropped from CodeQL;
  - suppressed results counted;
  - a missing file passing;
  - `if: always()` on the report step.
