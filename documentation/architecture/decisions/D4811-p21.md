## D4811 part 21 — Unlink a related document (#4811)

### Built (part 21) — 2026-11-12

D4811 (#4811) part 21 removes one related-document link from a governance record's Related tab (board CT-11; CT-92 "High-risk actions"). Part 8 recorded "There is no unlink yet. Removing a link is destructive and would need Scope → Review → Result." This part builds it, so that departure no longer holds. There is no migration.

1. **The route.** `POST /api/admin/governance/documents/:uid/related/:id/unlink { reason }` → `{ unlinked: { id, kind }, banner }`. It has the same access as linking:
   - the governing record must be one this admin may open. A confidential record is the Super Admin's alone, so anyone else gets 404 `document_not_found`, as for a record that does not exist;
   - a link whose dependant this admin may not open (a confidential record, for anyone but the Super Admin) answers 404 `relation_not_found`, exactly as a link that does not exist. That check comes before the reason check, so a missing reason does not tell the two apart;
   - a link is reached through its governing record only.
2. **The reason.** It must be 10 to 500 characters, with whitespace folded (422 `reason_required`). Part 6 (Mark executed, Archive) and part 13 (Publish) ask for the same reason. Unlink asks for no typed word and no step-up, because a link is a reference and can be made again. Every refusal ends "Nothing was removed."
3. **What is removed.** Only the `governance_relations` row, by bound `DELETE … WHERE id = ? AND governing_uid = ?`. Its review state goes with it: the flag, the reviewer, the date and the review note. Nothing is rewritten in either document, its versions or the template.
4. **What stays.**
   - The `activity_logs` rows for the link's creation and its reviews stay. The Activity tab still shows them, and it now also reads `governance_relation_unlinked` ("Unlinked a record / template / agreement it governed").
   - `governance_relation_dismissals` rows stay. A dismissal belongs to an admin, a record and a version, not to one link, and `bannerOf` recomputes the banner from the links that remain. Removing the last flagged link ends the banner.
   - The same document can be linked again later.
5. **The audit row** (`governance_relation_unlinked`) records:
   - both ends: `uid`, and the dependant's `kind` and `ref`;
   - the relation id;
   - the governing record's latest version (`version`) and the link's `flag_version` and `reviewed_version`;
   - the reason.

   It records no title and no review-note text.
6. **The page.** Each row of "Governed by this record" that the viewer may open has **Unlink…**. A restricted row has none. **Unlink…** opens `UnlinkRelation.jsx`, which has three steps:
   - **Scope:** the link, its review state, and the reason. Continue stays disabled until the reason is valid.
   - **Review:** the reference is removed and only the reference; both documents are unchanged; the review state that goes with it, and that the Activity tab keeps the history; what is recorded.
   - **Result:** success, which re-reads the list, or the Worker's refusal as sent, with "Back to the form".

   The API method is `adminGovernanceApi.unlinkRelated(uid, id, reason)`.

**Where this departs:**
- **Unlink is offered only from the governing record's side,** in "Governed by this record". The "Records that govern this one" list and the template and agreement workspaces' `GoverningList` offer none. To remove a link from there, open the governing record.
- **The link row is deleted, not kept as a soft delete.** A soft delete needs a migration and a filter on every relation read. The history is in the audit log. The cost is that a review note, which the audit rows never carried, is lost with the link. The Review step says this before anything is sent.
- **This is a part file** (`D4811-p21.md`, D5615), not a section appended to `D4811.md`: AGENTS.md says a later part never edits `D<n>.md`.
