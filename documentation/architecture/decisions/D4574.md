### H6 — the Studio page's charted and Product testing panels

**The cost.** `/studio` renders `pages/Dashboard.jsx`, which `App.jsx` already loads lazily. Its static closure carried two panels that do not need to arrive with it:

- the skills radar: `components/profile/ProfileFitSection.jsx` (on every member's Studio home) imported `components/play/SkillRadar.jsx`, so recharts' `CategoricalChart` (251 KiB raw) was in the page's closure for every role;
- the Product testing section: `Dashboard.jsx` imported `pages/testing/member/ProductTestingStudio.jsx` statically, the Admin's branch included, which never draws it.

**What changed.** Two wrappers, each `React.lazy` + `Suspense` with the same props as the panel it wraps, and a skeleton in the repo's existing pattern (`animate-pulse` on `bg-axal-ground`, as `RenewalBanner` and `PhoneHeader` do):

- `components/play/SkillRadarLazy.jsx`: holds the radar's own box (`width: 100%`, the radar's `height`), so nothing shifts when the chart arrives. `ProfileFitSection.jsx` imports it under the same local name, `SkillRadar`.
- `pages/testing/member/ProductTestingStudioLazy.jsx`: a card-shaped skeleton. `Dashboard.jsx` imports it under the same local name, `ProductTestingStudio`, so its five mounts (founder, investor, advisor, partner, Lab member) and the Admin branch read exactly as before.

`SkillRadar.jsx` and `ProductTestingStudio.jsx` keep their exports; `SkillParts.jsx`, `ExploringDashboard.jsx` and the tests still import them directly.

**Chunk-load failure.** A lazy chunk that fails throws in the route tree, where `RouteErrorBoundary` and `main.jsx`'s `vite:preloadError` handler reload once onto the current shell (`lib/chunkLoadError.js`), the same recovery as every lazy route in `App.jsx`. No new handler.

**Measured** (same fixture, clean build of `676787915` before and of this change after; KiB, one decimal; brotli is the script's estimate of what an edge serves):

| | Before | After |
|---|---:|---:|
| Shell critical path, brotli | 494.6 | 494.7 |
| Shell files / `modulepreload`s | 85 / 81 | 85 / 81 |
| `Dashboard.js` beyond the shell, brotli (chunks) | 227.9 (67) | 143.1 (60) |
| `Dashboard.js` beyond the shell, raw | 938.1 | 610.7 |
| `CategoricalChart.js` (recharts) in that closure | yes, 65.5 brotli | no |
| Radar, fetched only when a radar draws: `SkillRadar.js` + recharts, brotli | in the page | 74.9 |
| Product testing, fetched when a member home mounts it, brotli | in the page | 13.0 |

The chunk the build named `ProductTestingStudio.js` before (228.7 KiB raw) mostly held `ProfileFitSection`, which Rolldown had placed there as a module shared by `Dashboard` and `ExploringDashboard`; after, `ProfileFitSection.js` (222.7 KiB raw) is its own chunk and stays in the page's closure, because every member home draws it. So the page itself sheds recharts (about 75 KiB brotli) and the testing section (about 13 KiB brotli), about 85 KiB brotli in all.

**What the number means.** The Admin's Studio and a member whose assessment has no radar yet never fetch recharts; a member with a radar fetches it after the page has drawn, behind a box of the right size, rather than before anything draws. The Product testing section is fetched after the page draws for every member. Total bytes for a member who sees both panels are about the same; what moves is when they are fetched.

**Not measured.** Lab Web Vitals and long tasks for `/studio`: `scripts/perf/vitals-local.mjs` covers the anonymous pages only, and a signed-in page needs a session and API answers the local fixture does not provide. No p50/p95 is claimed.

**Verified.** `frontend/test/dashboard_lazy_panels_d4574.test.mjs` mounts each wrapper (skeleton first, then the real panel, the props reaching it; an Admin still draws nothing and is not read), guards that the imports are dynamic and that `Dashboard.jsx` and `ProfileFitSection.jsx` reach the panels only through the wrappers, and pins the `/studio` route and its guard.

### H5 — the cycle steps under CycleRoute

**The cost.** `pages/cycles/CycleRoute.jsx` draws every cycle's overview, module pages, records and tool tabs for `/validate`, `/build`, `/raise` and `/grow`, and it imported every step statically. The build made it one `CycleRoute.js` chunk of 1,160 KiB raw, and every cycle page, plus the pages that import from it (`RaiseEvidence`, `VisibilityPage`, `PreviewPage`, `VenturePage`), fetched all of it.

**What changed.** `pages/cycles/lazyStep.jsx` adds `lazyStep(load, name, { fallback })`: a component that takes the step's props, fetches the step's module the first time it draws (`React.lazy`), and holds its place with `StepLoading` (`animate-pulse` on `bg-axal-ground`), or with nothing for a slot the page sizes itself (the tool tab bars and the Build plan door). CycleRoute declares 27 steps with it, each under its old local name, so every render site, route and deep link reads as before:

- Raise tools: Narrative (`NarrativeHome`, `NarrativeTabBar`, `NarrativeTabPage`), Cap table, Data room (and `DataRoomUpload`), Use of funds and Capital relationships (each `…HomeNav` and `…TabPage`);
- Build: `BuildPlan`, `BuildPlanDoor`, `VerdictRecordWithPlan`; Grow: `ReportingDesk`, `UpdatesHistory`; Validate: the interview record (`InterviewReviewPage`);
- Distribution tabs: Overview, Channels, Prospects, Campaigns, Results, New campaign, Ads, Calendar and `CalendarWeek`.

**What stays static, on purpose.** Hooks and model functions a render reads synchronously cannot wait for a chunk: `InboxTab` (it carries `useInboxUnread`), `NarrativeAdmin` (`narrativeFormAccess`), every `…Model.js`. `DataRoomMovedRedirect` stays static so an old file address redirects without a skeleton. `NewsletterTab` (a 47-line "Not offered yet" panel) gains nothing. No module read here has an import-time side effect; each was checked.

**Chunk-load failure.** A step whose chunk fails to load throws in the route tree, where `RouteErrorBoundary` and `main.jsx`'s `vite:preloadError` handler reload once onto the current shell (`lib/chunkLoadError.js`), as for every lazy route in `App.jsx`. A named export that is missing throws an error, never a blank.

Splitting costs something: a visitor who opens every step fetches about 50 KiB brotli more in all, in more requests, than the one chunk did. The shell moved too: Rolldown now gives five small modules the shell already held their own chunks (`partner`, `FillMark`, `AskProposal`, `dataRoomRead`, `useAiBudget`), so the critical path is 90 files and 86 `modulepreload`s (was 85 and 81) and 495.8 KiB brotli (was 494.6); the entry chunk is unchanged. Both stay inside `scripts/check-bundle-budget.mjs` (95 files, 500 KiB), which is not moved.

**Not measured.** Lab Web Vitals and long tasks for the cycle pages: they are signed-in, and `scripts/perf/vitals-local.mjs` covers the anonymous pages only. No p50/p95 is claimed.

**Tests.** `frontend/test/cycle_route_lazy_steps_d4574.test.mjs` mounts `lazyStep` (skeleton, or nothing, then the step with its props; a failed chunk reaches the error boundary as a chunk error; a missing export is an error), guards that each step is a dynamic import of a module that still exports it and that none is imported statically again, and pins the cycle routes, deep links and render sites. The suites that mount CycleRoute and settle it with a fixed number of ticks import `frontend/test/_cycleSteps.mjs` first, which loads every module CycleRoute names through `lazyStep` (read from its source), so they see each step as a browser does once its chunk has arrived; without it 55 of their assertions saw the skeleton instead. Their assertions are unchanged.

### H4 — four static imports that put page code in the shell

#4574's next step as S1 set it on 2026-11-09, taken by S17. The shell had grown to the edge of its budget: **90 files, 85 `modulepreload`s, 502.9 KiB brotli** against `check-bundle-budget`'s 504.0 KiB. A per-module breakdown of the entry and `api.js` chunks (a throwaway Rollup plugin over the same build), and the shortest static import chain from `index.html` to each heavy module, found four imports that pulled page-only code onto every page:

| Chain into the shell | What it carried (rendered, before minification) | Change |
|---|---|---|
| `App` → `DataRoomMoved` → `ui/index.js` (the barrel) | `Charts.jsx` 47.8 KiB, `FillSheet.jsx` 24.7 KiB, every other primitive, and the chunks they import | `useMovedNotice` imported from `ui/AdminPageHeader` directly. No other shell module imports the barrel. |
| `App` → `UseOfFundsMovedRedirect` → `scenariosForecastModel` → `useOfFundsModel` | 28.0 KiB of forecast models, for a legacy redirect | A lazy route element (`lazy()`, inside the routes' existing `Suspense`). An old address costs one extra chunk on its rare hit. |
| `App` → `SidebarNav` → `CompanySwitcher` → `portfolioAdapter` → `agentsAdapter` | `assessmentMeta.js` 36.1, `teamModel.js` 23.9, `skillsModel.js` 16.9 KiB, and Team's API modules | `projectAgents()`, already async and the only user of `listAgents`, imports `agentsAdapter` when called. |
| `App` → `RecordingPill` → `RecordingView` | the whole recording view (35.8 KiB) for `clock` and `useDarkTheme` | Both moved to `pages/founder/recordingClock.js`; `RecordingView` re-exports them, so its importers and tests are unchanged. |

**Measured** on the #4573 fixture, each build from an empty `docs/` (`rm -rf docs && npm run build && node scripts/perf/bundle-baseline.mjs`), main at `e795d72b60` against this change:

| | Before | After |
|---|---:|---:|
| Critical path files (entry, `modulepreload`s, CSS) | 90 (1, 85, 4) | **26** (1, 24, 1) |
| Critical path brotli / gzip / raw | 502.9 / 611.3 / 2,315.0 KiB | **380.1** / 470.6 / 1,920.8 KiB |

**Not done here, on purpose.**
- The checkout and pack sheets (38.7 and 32.4 KiB rendered) also sit in the shell and render only when opened. They are payment UI, and lazy-loading them changes when their code arrives and how a failed load reads, so they get their own PR.
- `api.js` (394 KiB raw) is unchanged. Taking domain modules out of it changes how every page reaches the API and is the larger refactor #4573 names; it is not part of this PR.
- The budget in `scripts/check-bundle-budget.mjs` (504.0 KiB) is not lowered. At 380.1 KiB the shell is still above #4573's proposed target B (≤ 350 KiB after H4 and H5); moving the gate is the owner's call.

**Contracts unchanged.** No route, guard, redirect target, API method, Worker file or data shape changes. The moved helpers keep their behaviour and their old exports.

**Tests.** `frontend/test/shell_h4_d4574.test.mjs` pins each of the four imports out of the shell path and the moved helpers' behaviour and re-exports. Mutation checked: each of the four imports restored fails its assertion. `portfolio_preview_route_4849.test.mjs` settles each route with a fixed number of ticks, and the ui barrel and the recording view now load on the first route that needs them instead of at start-up, so it failed one test until it loads those two modules first, as H5's `_cycleSteps.mjs` does for the cycle steps; its assertions are unchanged.
