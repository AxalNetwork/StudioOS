- **Status:** filed by S1 as #2517 (M1 of #2516) at the owner's request, 2026-10-22. Migration 529.
- **Basis:** `origin/main` at `3704a16a62`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:**
  - D684 and D757 (the Zoom import and the engine);
  - D657 and D685 (the recorder's chunks, the router's speech-to-text, the session's language);
  - D844 (the AI token ledger's holds).

### 1. What changes

**The trigger.**
- `recording.completed` joins `recording.transcript_completed` in the webhook. Both are claimed once, find the call by its meeting id in `interview_channel_refs` (never the payload's host or account), and queue the same `meeting_import` job.
- The daily sweep already re-asks a quiet call, and now also finds a call whose recordings exist but whose transcript does not.
- The runbook's §1 step 4 adds the event, and the account setting that saves an audio-only file.

**The source** (`services/channels/meetingAudio.ts` `chooseRecordingSource`), in order:
1. the native TRANSCRIPT VTT (else Zoom's CC file, as today), when the call's language is English or unknown;
2. otherwise the audio-only (M4A) recording;
3. otherwise, for a call set to another language with no audio, the VTT after all;
4. otherwise nothing, with the reason.

A file Zoom is still processing makes the call wait, so a transcript on its way is never pre-empted. A video MP4 alone is not the audio path; the issue names the audio-only file.

**The language.**
- `interview_channel_refs.call_lang`: NULL is auto.
- `setCallLanguage` is in `meetings.ts`. It reaches a restarted call's instances, and only the member's own call.
- Every instance a restarted call makes copies the call's language.
- No route sets the language yet. M9's screens (#2525) carry the control, since `routes/` is not this task's file.

**The record (migration 529):**
- `transcript_source`: `native` or `whisper`. NULL before an import and on older rows, so an old row never reads as native.
- `call_lang`.
- `stt_reservation_uid`. The issue names it a reservation, but it holds the audio run's key (§4).

**The plain words.** `MEETING_ERRORS` gains:
- `stt_consent_missing`;
- `stt_budget`: "…no AI tokens left…" (D793's word);
- `stt_paused` and `stt_failed`;
- `zoom_audio_unreadable` and `zoom_audio_too_large`.

`meetingView` reports `transcript_source` and `call_lang`.

### 2. The audio path, step by step

1. **Consent first.** The call's session must have consent `given` (#1470's rule, as the processing job enforces). Otherwise the call is `no_transcript` with `stt_consent_missing`, and **the file is never fetched**.
2. **Fetch once.** The M4A is fetched with the member's own token, only to Zoom's host. Zoom's signed redirect is followed without the token, as the VTT already is. It is counted as it arrives, and refused over `MAX_AUDIO_BYTES` (80 MB).
3. **Cut it.** `demuxM4a` reads the audio track's samples from its sample tables (`stts`, `stsc`, `stsz`, `stco` or `co64`), wherever the index (`moov`) sits and beside a video track. `remuxChunk` then writes each run of whole samples as a complete M4A that copies the source's codec description (`stsd`) byte for byte.
4. **Store the chunks.** They are recorder chunks: `putChunk` writes them to R2 under the call's session, with the run key in their metadata. They are purged with the session, and M8 sets their retention. A run that stopped half-way finishes the set: `putChunk` keeps a stored chunk.
5. **Transcribe them.** `STT_CHUNKS_PER_RUN` (3) chunks per run go through the recorder's own `transcribeChunk`: the router, Whisper Large v3 Turbo, and the founder's language when set. Each is staged in `interview_chunk_transcripts`. While chunks remain, the call is `transcript_ready` and the next `meeting_import` run is queued.
6. **Import.** With every chunk staged, the segments go on one timeline, each chunk's segments offset by the chunk's start. They pass through D684's `importMeetingRef`, so a restarted call, the mirror onto the call, the engine and the retry route all behave as they do for a VTT. The call is `imported` with `transcript_source = 'whisper'`.

### 3. Workers AI's limits, and how a 60-minute M4A fits them

The measurements come from Cloudflare's documentation, read 2026-10-22 through the documentation search, and are cited by page. This environment cannot call Workers AI, so the first live call confirms them.

| Model | Input | Output | Price (`/workers-ai/platform/pricing/`) |
| --- | --- | --- | --- |
| `@cf/openai/whisper-large-v3-turbo` | `audio` (base64 or bytes), `language`, `vad_filter`, `initial_prompt`, … (`/workers-ai/models/whisper-large-v3-turbo/`). **No input size limit is documented.** | `text`, `transcription_info`, `segments`, `vtt` | $0.0005 per audio minute (46.63 neurons) |
| `@cf/deepgram/nova-3` | `audio: { body, contentType }`, `diarize`, `language` | words with a `speaker` | $0.0052 per audio minute over HTTP (472.73 neurons) |

**What was ruled out:**
- **Cutting by bytes.** Cloudflare's own chunking guide (`/workers-ai/guides/tutorials/build-a-workers-ai-whisper-with-chunking/`) splits a file into 1 MB slices. That works for MP3, whose frames resynchronise, but not for MP4: a byte slice of an M4A has no index.
- **Media Transformations' audio mode.** It extracts M4A with `time` and `duration` (`/stream/transform-videos/`), but its documented limits are a 100 MB input and **a 10-minute input duration**, so it cannot take a 60-minute call.
- **Zoom's per-participant audio files.** They need an account setting, are UNVERIFIED, and are not needed for this.

**What was chosen:**
- **Remux in the Worker.** Sample tables are read and whole samples rewritten, in pure TypeScript with no dependency.
- **Bounded chunks.** Each chunk is at most `MAX_CHUNK_BYTES` (5 MB, the recorder's own per-chunk bound, the size the router already sends Workers AI) and at most `CHUNK_MAX_MS` (10 minutes). A 60-minute call is six requests, with five cuts that may split a word. Nothing larger than the recorder's bound goes to a model.
- **Cost per minute** is the ledger's own price for Whisper Large v3 Turbo: $0.0005 per audio minute at cost, billed at the licence's multiplier like every other run. A 60-minute call costs about $0.03 at cost.

**UNVERIFIED until the first live call:**
- that Workers AI's Whisper decodes a remuxed AAC M4A;
- Zoom's audio-only bitrate, and so how much audio 80 MB holds;
- that `recording.completed` lists the transcript file as still processing when one is coming. If it does not, an English call can be transcribed by Whisper before its VTT arrives; that call's text is then Whisper's, charged once.

### 4. Charging once

A Zoom event is claimed once per event and instance uuid (`claimEvent`). Both events for one instance queue one job under one idempotency key. Each chunk is transcribed only while it is unstaged.

So:
- **A duplicate event** charges nothing.
- **A second event for the same instance** charges nothing.
- **A retry after a failure** charges only the chunks left.
- **An imported call** is never transcribed again.

The tests hold each case (`zoom_whisper_fallback_d870.test.ts`, cases 7 and 8).

**Where D844 comes in.** Every request is held, settled or released on the AI token ledger by the router's own hold, and receipts are recorded per chunk and for the call. The issue asks for D844's `meteredCall`, keyed per ref and chunk. The router's hold takes no idempotency key today (`aiRouter.ts`, `reserveAiBudget` without `opts`), and threading one through means changing `aiRouter.ts` and `interviewProcessing.ts`, which this task does not own.

**The window that remains** is the recorder's own: a Worker that stops after the model answers but before the chunk is staged would charge that chunk again on its retry. The follow-up that closes it is a `holdKey` option on `aiRouter.run`, passed by `transcribeChunk` as `meeting:<run key>:<seq>`. Then `stt_reservation_uid` is the run part of every chunk's hold key, which is why it is minted once per call.

### 5. Speakers

- Whisper gives no speakers, so every passage reads "Speaker ?", the house label until the founder assigns it.
- Nova-3 diarizes (`sttFormats.ts`), but each chunk is diarized on its own, so its speaker 0 in one chunk need not be speaker 0 in the next. It also costs ten times Whisper. It is not used here.
- Matching the founder's turns by Zoom display name needs participant data that the audio-only file does not carry.

Both are left to the founder's assignment, and to M4's speaker work if it takes them on.

### 6. Failures, in the member's words

| Case | Ref | Retry |
| --- | --- | --- |
| No consent recorded | `no_transcript`, `stt_consent_missing`; nothing fetched | After recording consent |
| No AI tokens, or AI paused | `failed`, `stt_budget` or `stt_paused`; the chunks are kept | The route transcribes only what is left |
| The model failed | `failed`, `stt_failed` | The queue does not retry it; the member does |
| Not an AAC M4A, or a malformed index | `no_transcript`, `zoom_audio_unreadable` | — |
| Over 80 MB | `no_transcript`, `zoom_audio_too_large` | — (M3's upload takes the part they need) |

### 7. Security and privacy

- **Tenancy is the ref's.** A payload's download link, host or account is never read, and the download goes only to Zoom's host with the member's own token (case 10).
- **Audio and text are customer content.** They are stored under the session in R2 and D1, purged with it, never logged (case 11), and never put in a fixture: the test's audio is synthetic bytes.
- **SQL** is bound only, with no raw interpolation added.
