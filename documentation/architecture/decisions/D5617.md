## D5617 — Atomic task claims and label normalization (#5617)

Claims use an independently created `refs/heads/claim/<issue>`. The commit has
main's tree, one parent, and validated JSON metadata (version, issue, slot,
agent, session, creation time and TTL; 24 hours by default). Only ref creation
wins. An existing ref, including an expired one, returns exit 3 and its holder.
The reaper does not seize work or delete refs. The holder releases on hand-back
or DONE; an owner may explicitly resolve abandoned claims.

Renewal creates a child of the currently held commit and updates without force.
Concurrent renewals cannot overwrite each other. Identity and expiry are checked
before renewal; expired claims must be released and acquired again. Release
checks identity; GitHub ref deletion has no compare-and-swap API, so sessions
must not concurrently release and renew their own claim. This is a cooperative
lock, not a fenced server lease (#5618). HTTP 403 returns exit 4 and requires the
existing label-plus-STATUS fallback to be explicitly recorded.

Standard labels cover S01–S37. Explicitly assigned later slots (including this
session's s39) are preserved; synchronization deletes no labels. Case-only
spellings are renamed before creation because GitHub label names ignore case.
Retired non-case aliases move on open and closed issues, including pull requests.
`state:done` maps to `state:review`: issue closure remains the source of completion,
and open issues carrying a stray done label need review. The owner can delete
emptied retired labels after one sync run; this PR does not dispatch a main-only
workflow before its changes are merged.
