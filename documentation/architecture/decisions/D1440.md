### Why

A shared link previews as whatever its HTML head says. Fixed public pages have their own prerendered cards. Every other path gets the SPA shell's **home** card: record links, token links, signed-in pages and the pages being retired. Before the injector (D1439), the private-link card (Part D) and the retirement tasks change any of that, there has to be one table that says, for each route group, who can open it, whether it is meant to be shared, and which card it should show. That table is `../SOCIAL_CARDS_MAP.md`.

### What was decided

1. **The map is the record.** `SOCIAL_CARDS_MAP.md` has one row per route group, with these columns: route, access, shareable, card, title source, image source. It names the keys as they stand after #3913 (#3705) put the family keys in the registry. A change to a card, a new public prefix or a retired route updates its row in the same PR.
2. **Record links get record cards; a miss looks like a private record.** Public records (events, articles, public insights, jobs, authors, public profiles, startups, directory-listed partners) are D1439's. A missing record and a non-public one return the same section card, byte for byte.
3. **Token links get the private card, not the record.** This is Part D, after owner question B. Signed-in and admin pages keep the home card, which leaks nothing, unless the owner picks B (b).
