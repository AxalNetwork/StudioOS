## D5039 part 3 — Complete the Revenue cockpit controls and recorded statement workflows (#5039)

The remaining owner checklist on #5039 (comment 6754371204) uses the approved
Revenue v2 RV01–RV15 canvas. It preserves the existing shell, reconciled trend
ownership, invoice-backed executive figures and canonical refund review flow.

The Stream control filters the stream table only and says so beside it. Other
sections retain their explicit temporal and subsidiary scope. Summary and
period-statement reads discard superseded responses when the period changes.

Statements gain a nullable `due_on` UTC calendar date. Existing statements have
no inferred terms. Only a known, past due date on an issued claim with a known
positive outstanding balance establishes Overdue; missing dates remain unknown.
The due day itself is not overdue. Overdue sorts before Disputed, and its
outstanding still participates in its own currency's open-claim total.

Disputes and due dates now use reason → review → confirmation → recent
authentication → receipt. Both require Super Admin, the revision read and an
actor-scoped idempotency key. Clearing a value also requires a reason. Disputes
replace the disputed total without changing paid, cannot exceed owed less paid,
and cannot modify a settled or void claim. The retired PATCH refuses all writes.

The guarded statement update and action receipt commit in one D1 batch. A
receipt insert failure rolls back the update. Replays return the stored answer;
changed requests cannot reuse a key. The new migration preserves existing
action IDs, request hashes, keys and response bodies while extending its action
constraint. History reads actual `subsidiary_statement_actions`, scoped to one
opened statement, 25 rows at a time. Older changes without receipts are not
fabricated into a timeline.

Promotion push acceptance proves only acceptance. An explicit Check branch
reads the same `readCeiling` calculation used by checkout through the registered
service binding, under the existing two-second deadline. HQ checks branch
identity, current period, source time, currency and amounts against its saved
ceiling. It distinguishes verified, mismatch, no ceiling, no deployment,
another period and unreadable. The UI labels a read as a dated snapshot and
resets it when the expected ceiling changes; it does not automatically fan out
across branches. No-ceiling at HQ alone makes no claim about branch checkout.

The unused direct `RefundForm` is removed. Executive invoice figures remain
backed by `licence_invoices`, separated by native currency, with Not recorded
or Unreadable states when the source cannot substantiate a number.

Validation evidence and outstanding independent review are recorded in the PR.
Browser evidence uses synthetic finance records; it is not production financial
or deployment acceptance. The existing Eadwyn rail belongs to #5130 and is not
redrawn by this part.
