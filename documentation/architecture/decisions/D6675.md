## D6675 — Verify queue invalidation and release supersession before routing a repair (#6675)

A failed merge-group run can lose its temporary ref while it is running.
The liveness step records the candidate, ref and attempt only on a successful
absence check. The failure reporter corroborates that evidence with GitHub's
attempt and ref records and compares the producer inputs with the verified main
base. A failing producer outside the liveness check still reaches issue triage.

Production releases emit a candidate- and stage-bound supersession signal at
initial admission, the production lock, the final ownership check and the
branch rollout lock. A different failed step or incomplete evidence leaves the
attempt actionable. This changes reporting only. The release and landing gates
still enforce their original results.

The reporter retains links and separate queue invalidation and producer-failure
rates in the reporting job summary. It keeps the existing repair deduplication
key. Existing issues keep their labels and occurrence history.
