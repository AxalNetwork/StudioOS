## D5218 part 2 — Mount previews in New Deck and Gallery (#5218)

New Deck now mounts the existing registry Thumbnail through DeckTemplatePreview.
Only cards near the viewport render their deck trees. Each choice keeps the
method's count, category, audience guidance, recommendation and plan lock.
Locked choices can be selected and previewed; their Use action stays disabled.
The Worker remains the authority for usage permissions.

Choosing a template replaces the unused editable outline with that method's
ordered structure and representative slides directly beneath the chooser.
On phones, the chooser is a horizontal card strip; desktop keeps the grid. Preview all slides opens the
same renderer in the existing Lightbox. Returning to Blank or a saved version
restores the outline. Blank has an intentional empty-deck illustration.
The Use confirmation now dispatches its template action, rather than falling
through to the outline-generation dialog.

Gallery and Yours represent stored block/field decks rather than registry
methods (D1535 Q5). Their real cards therefore render through PresentCard,
the existing presentation renderer. Saved-version tiles read the exact
version and draw its first slide through that renderer too. They never fall
back to fictional content. Failed or empty reads say Preview unavailable.
Registry samples retain the visible Fictional sample caption.

Stored preview reads start near the viewport. A chooser-local promise cache
shares the tile and selected preview read, removes rejected requests, and
dies with the page; it never shares a member's saved deck across sessions.
Full-slide lists mount only when opened and still load off-screen slides on
intersection. PresentCard is imported lazily. No API, Worker, schema or plan
policy changes are needed.

The approved Pitch Studio canvas retains its existing tokens, cards and
Lightbox. This issue's explicit visual-chooser and template-structure
requirements extend Start from in place; the broader PS-02 page redesign is
outside this change. Registry methods and stored templates keep their own
structures rather than guessing a mapping between the catalogues.

Verification covers the built SPA at 1440px and 390px: rendered covers,
saved content, explicit failures, plan gating, recommendation, shared reads,
deferred off-screen trees, template structure and the confirmed apply-method
request. No production data or provider credentials are used. Browser images
are run artifacts, not committed visual baselines.
