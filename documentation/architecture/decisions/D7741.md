## D7741 — Research imports: private payload files stay out of git, and a tracked one fails the build (#7741)

- **Status:** built 2026-11-19. Filed from the owner's Research → Funds audit of the same date, under #3701. P0.
- **Why now.** The four-source package exists on the owner's device and holds contact data. This lands before any other Research import work (#7742 onward), so no branch of that work can commit it by accident.
- **No migration, no Worker route, no client method, no `package.json` edit.**

### The decision

1. **The ignore block is the prevention.** `.gitignore` gains one block, headed `# D7741 (#7741)`:
   - `*.private.*`: a file marked private by name, at any depth. No tracked file matched it when this landed.
   - `private-payloads/`: a folder of that name, at any depth.
   - The import-package JSON: `*import-package*.json`, `*import_package*.json`.
   - The four-source capture archive, whose name does not contain `.private`: `*four-source*`, `*four_source*`, `*4-source*`, `*4_source*`, and a capture archive by extension, `*capture*.zip`, `.tar`, `.tar.gz`, `.tgz`, `.7z`.
2. **The check runs after a commit exists.** `cloudflare-worker/test/private_payload_guard_7741.test.mjs` runs in the Worker suite (`test:worker` already globs `cloudflare-worker/test/*.test.mjs`, so every CI `worker-*` part picks it up). It holds:
   - a pure matcher over the same patterns, tested on invented path lists only. It matches case-insensitively, so it is stricter than git on Linux, where ignore rules are case-sensitive (a clone on macOS ignores case by default);
   - `PRIVATE_PAYLOAD_CONTENT_MARKERS`, an exported list of byte strings read from each tracked file's first 4,096 bytes. It is empty here; #7742 adds the package format's marker, so a renamed payload is caught by its first bytes. With the list empty, no tracked file is read;
   - a test that the `.gitignore` block and the matcher's list are the same lines, so the two cannot drift;
   - `git check-ignore --no-index -v` on one invented sample name per pattern, each reported ignored by its own `.gitignore` line;
   - the live run: `git ls-files -z` through the matcher. A match fails the test with one fixed sentence and the paths, one per line, and never a byte of any file.
3. **Never "passed because it could not look".** Inside a git checkout, a `git` that cannot list files (a broken `.git`, a failed spawn) fails the test with git's reason. The test skips, and says so, only where there is no `.git` at or above the repository root at all, as in an exported source tree.
4. **No fixture.** No file named like a private payload is committed, as a fixture or otherwise. Every sample is a string in memory; the broken-checkout case writes a `.git` file into a temporary directory and removes it.

### What this does not do

- **A tripped check is an incident, not a follow-up commit.** Every pushed branch of this repository is public, and the check only runs once a commit exists. A tracked payload means the data has already left: open a private GitHub Security Advisory under `SECURITY.md`, and the owner purges it from history. A commit that deletes the file does not undo the exposure.
- **A renamed file passes the name check.** Until #7742 adds the format marker, a payload saved under an unrelated name is caught by nothing here.
- **The payload is never copied into a checkout.** Not into `private-payloads/`, not under a `.private.` name: the ignore rules are a net, not a place to keep it. #7739 decides the one supported route by which a payload reaches production.
- **The secret scanner does not cover this.** `.gitleaks.toml` looks for credentials only, and allow-lists `attached_assets/` whole. Contact data is not a credential, so a payload passes it.
- **The ignore rules do not reach a forced add.** `git add -f` commits an ignored file; only the check then catches it.
- **The exact names are not known.** Neither the delivered import-package JSON nor the capture archive is named in this repository or in #7741, #7742, #7739, #7325 or #7585, so the patterns cover the shape described. Owner question below.
