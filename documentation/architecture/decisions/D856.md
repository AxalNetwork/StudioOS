### 3. The setup lock (`integrations/mcpClient.ts`)

- **The record.** `setup_tools` is empty unless `setup_issue` is set. A setup tool is never also a read or a write tool. `mcp_client_d847.test.ts` §1 holds every record to both.
- **The session.** A listed setup tool is offered (`setup_offered`) only after the record's checks: it must be on `setup_tools`, have a valid `x-mcp-header`, and match its pin when there is one.
  - Unlike a read tool, it is not refused for `readOnlyHint: false`, since it writes by nature.
  - It is refused when annotated `destructiveHint: true`. Annotations still only narrow.
- **The ticket.** `mintMcpSetupTicket(provider, tools)` mints a frozen ticket.
  - It names the provider and one step's setup tools, and nothing else is mintable: a read tool, a write tool or a name off the record throws.
  - The client alone knows which tickets are live (a `WeakMap`), so a copied or hand-built object is not a ticket.
  - `callTool(name, args, ticket)` spends that tool's use of the ticket. Another provider's ticket, another step's, or a spent one is refused before any request.
- **Who mints.** `routes/channels.ts` is the only minter, and only after `{ confirm: true }`. §2 of the D847 test holds the source to that.
- **What is unchanged.**
  - The write lock: a write tool is refused with or without a ticket.
  - #2400's publish ticket stays a separate design.
  - Mercury, Notion and custom servers list no setup tool, so nothing changes for them.

**The template.**
- Its words are D754's notice (`consent.ts` `NOTICES[1]`), with the founder's first name and the venture as `{{1}}` and `{{2}}`.
- It links the notice page, so it needs `PUBLIC_BASE_URL`. Without it the step refuses (`notice_link_missing`), as every notice sender does.

**The connection.** Step 6 writes the row through `whatsapp.ts`'s `storeWhatsAppConnection`, the tail of `completeEmbeddedSignup` moved out unchanged:
- one `integrations` row `whatsapp`, `auth_type 'oauth2'`;
- the number id as `external_account_id`, and the masked number and WABA id in config;
- the Meta sign-in's access token, encrypted against the row's own uid.

So the webhook's tenancy, consent, threads and voice notes treat it exactly as Embedded Signup's row. Embedded Signup's own path is untouched: the same code runs for it, and its tests pass unchanged.

**Resumable.**
- Progress lives in the founder's sign-in row, as `config_json.setup`: the WABA and number ids, the masked number, when each step finished, and the last failure's code.
- The read (`readWhatsAppSetup`) never calls Meta. It shows a failed step's code until the step is pressed again.
- A finished step answers done without calling Meta.
- Picking another number of the same account clears only register and connect. The account's subscription and template carry over.
- A step whose earlier steps are not done answers `step_blocked`.

**Refusals, in our words** (`WA_SETUP_SENTENCES`):
- A 403 from Meta, or `business_admin` not true, is `not_business_admin`.
- A 401 is `sign_in_again`.
- A tool Meta does not offer is `tool_not_offered`.
- A timeout is `meta_unreachable`; a 429 is `meta_busy`.
- Anything else from Meta is `meta_refused`. Meta's text is never returned or logged.

### 5. The routes (`routes/channels.ts`)

- `GET /api/channels/whatsapp/setup`: `{ signed_in, number_masked, steps[] }`. Each step has its state (`done`, `todo` or `blocked`), its code, our sentence, and the confirm line of a step that changes an account.
- `POST /api/channels/whatsapp/setup/:step`, body `{ confirm?: true, phone_number_id? }`:
  - A step that changes an account without `confirm: true` (exactly `true`) answers 400 `confirm_required`, with the confirm line, and calls nothing.
  - Only after that is the step's ticket minted.

**In order, before anything is read:**
1. `WHATSAPP_MCP_SETUP` must be exactly `"on"`, or both answer 404.
2. A venture (`canHoldValidateSource`), or 404.
3. WhatsApp's platform secrets and its rollout (`channelOpenTo`), or 503 `not_available`.
4. A paid plan (`userMeetsTier(user, 'growth')`, Q2 A), or 402 `tier_required`.
5. An active member.
6. A POST from a support session is refused (403 `support_session_refused`), as the generic sign-in refuses one.

`POST /whatsapp/connect` (Embedded Signup) is untouched, and answers with the flag off.
