## D1500 — Deck v2 A8: document model v2 (card uids, model version, rich text, chrome) (#3750)

- **Status:** built by S15 on `agent/claude-s15/3750-deck-model-v2`. Not merged, deployed or live verified.
- **Builds on:** D898 (the slide model and the editor), D899 (card tools), D903 (images), D905 (notes), D1604 (the v2 studio and its adapter seam).
- **Migration:** 714 (`714_deck_card_uids.sql`), additive. `card_uid` on `deck_images`, `deck_notes` and `deck_view_slides`; `slide_reactions_by_uid` on `deck_share_feedback`.

### 1. Card uids

Every card has a stable `uid` (at most 40 characters). `assignCardUids` (in `services/decks/slideModel.ts`) runs on every read (`rowToDeck`) and every save. It keeps a sound uid that is not already taken, and otherwise gives `c<n>` from the card's place, with `-2` added if that is taken. So a read is deterministic, and a deck saved before v2 gets the same uids on every read until its next save stores them.

A store that names a card now keeps its uid next to its index:
- an image (generate and upload);
- a note;
- an assist press (`:card` is an index or a uid);
- a view's dwell slide (the heartbeat names only unnamed rows);
- a reader's reactions (`slide_reactions_by_uid`).

`cardRefOf` resolves a card by uid first and by index second. A result that comes back after the cards were reordered lands on the card it was asked for. Each uid write is a follow-up `UPDATE` after the existing insert, so a database without 714 still saves.

In the editor, a copied or new card gets a fresh uid (`withNewUid`), and `replaceCard` places a result by uid. `AreaResults` follows its card by uid, and `CardsStrip` keys rows by uid.

### 2. Model version

`MODEL_VERSION = 2`. `PUT /api/decks/:id` without `model_version: 2` answers 409 `upgrade_required`, with the sentence "This editor and the server read decks differently. Reload the page, then save again. Nothing was saved." It writes nothing. `api.deckUpdate` sends the version, and every deck read returns it. A tab left open on an older editor cannot overwrite uids it does not know.

### 3. Rich text, theme and card fields

- **`block.paras`** is `[{ runs: [{ text, b?, i?, u?, accent?, href? }] }]`:
  - an `href` is kept only when it is https on a public host (the slide-image rule);
  - at most 3 accent runs, and each must have a contrast of at least 4.5 against the card's background (or white), or the save names the problem;
  - `block.text` stays the plain copy, so every v1 reader still works.

  The editor draws paras read-only (`RichText`). Editing them is a later slot.
- **The theme** may carry:
  - `chrome` { `page_number`, `footer_text`, `logo_corner`, `confidential` }, drawn on the stage by `CardChrome`;
  - `voice`;
  - `art_direction`;
  - `lang`;
  - `dir`.

  Each is stored only when set.
- **A card** may carry `hidden`, `section` and `decor` (at most 16 items).
- **Caps:** a card over 256 KB is refused with "the card is larger than 256 KB. Remove an image or some text, then save." Twelve areas stays the cap from D898.

### 4. Departures from the issue

- Reactions are keyed by uid in a new `slide_reactions_by_uid` column, not a `card_uid` column on the feedback row: one feedback row holds reactions for many cards.
- `decor` is a minimal list (kind and grid place). Its drawing waits for the decor slot.
- Content hashes change once for a deck saved before v2, when uids are first stored.
- The Hide and Move to section menu items stay behind the D1604 adapter. The fields are stored and round-trip, but the menu does not write them yet.

### 5. Tests

- `cloudflare-worker/test/deck_model_v2_d1500.test.ts`: the 409, uid keep, assign and dedupe, a reorder with a note by uid, rich text, the caps, and the theme and card fields round-trip.
- `frontend/test/pitch_model_v2_d1500.test.mjs`: uid placement, the strip key, `AreaResults` following its card, the version on save, and chrome.

Each test was mutation-checked: dropping the version check, preferring the index, removing the accent cap, the https rule or the bytes cap, placing by position, `key={i}`, and reading the `card` prop all turn it red.
