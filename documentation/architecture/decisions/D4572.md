### R2-07: the halt and revocation contract, as the code holds it today

1. **New admissions stop** at the first admission after the halt key (or the breaker, or `AGENT_ENGINE` off or `paused`) is visible to the reading location. A read error is a halt, so it never admits. KV is eventually consistent: a halt written in one location can read as absent elsewhere until it propagates. This contract states no propagation bound. Measuring one needs hosted, multi-location evidence (#4594, after #4566).
2. **An admitted run** continues only to its next step boundary. Every step's `gate` reads the halt key and the engine var, and a run ended from outside (`scope_moved`) stops at its next step. `paused` stops admissions only, by design (D1528): an admitted run carries on to its proposal.
3. **Revalidated immediately before an effect:**
   - the sponsor's access is checked in the run step's context (`buildContext`);
   - every MCP read is checked by `agentMcpRefusal`, twice: before any call, and again just before each call;
   - the model call's hold goes through `meteredCall`, which refuses before calling.

   A refusal has zero calls and zero holds (test 4b).
4. **What cannot be cancelled:** a provider request already in flight inside a step is not cancelled by a halt. Its known usage is settled and its output is kept as a proposal a person decides; nothing discards it silently (6b). The run then ends at the next step.
5. **A person's decision** taken while halted still lands, because it is the person's act. Nothing new is admitted after it (6d).
6. **Resume** is a person clearing the halt key or breaker (D1528). No older grant is replayed: every call re-reads the agent's current grants and status. A policy-version fence (a run carrying the grant version it was admitted under, refused when it changes) is not built. It is the proposal for the owner below.

### Update 2026-11-07: a host's trailing root dot

A fully qualified name may end in the DNS root's dot (`localhost.`, `axal.vc.`). Before this fix, `customUrlRefusal` (a member's MCP server) and `imageUrlRefusal` (an outside image) compared names exactly. A trailing dot therefore passed the private-name rule and the own-host rule. The DNS public-address check that runs next still refused any private target.

Both guards now drop trailing dots before the name rules. A name that is only dots is `bad_url`. The own host, given with a dot or a port, is normalised the same way. The test is `host_root_dot_4572`.

**The name-only guards now resolve too.** Each server-side fetch of a member-given URL resolves the host over DNS-over-HTTPS (`dohResolver`). It refuses unless every address is public (`guardHost`). Redirects are followed by hand, and each hop is checked the same way.

The shared pieces are in `services/webFetch.ts`:
- `publicHostRefusal`: the name rules (`isSafePublicUrl`, which now ignores the root's trailing dot), then DNS;
- `publicFetch`: at most 5 hops, and the runtime never follows a redirect;
- `publicResolver`, with `__setPublicResolverForTest` so tests can answer DNS.

| Fetch | Before | Now |
| --- | --- | --- |
| `fetchPage` (competitor pages and the app-link check) | Name check, then `redirect: 'follow'`: a redirect went unchecked | `publicFetch` |
| `decks/imageFetch` (copying an image in from a link) | Name check at each hop | Name check and DNS at each hop |
| IMAP and SMTP | `checkSettings` read the name only | The host is resolved before each socket opens. A host that doesn't resolve is `unreachable`; a private one is `refused` |
| The Studio watermark | Name check | Resolved at save. 400 `watermark_url must be on a public host`. Defence in depth: the export browser loads only its own origin, the font hosts, `data:` and `blob:` |

The deck image sanitizers (`autofill`'s `sanitizePublicHttpsUrl`, `routes/decks.ts`' `sanitizeImageUrl`) still check names only. The server fetches those URLs only through `deck_exports.fetchImages`, which already uses the DNS-checked `imageSafety.fetchExternalImage`. Anywhere else, the URL is only loaded by a viewer's own browser.

The test is `public_fetch_resolver_4572`. Five suites that stub `fetch` now also answer DNS through the hook: D898 watermark, D778 competitors, the app links, D1340 mail accounts and D1506 upload hardening.
