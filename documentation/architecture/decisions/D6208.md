## D6208 — Portfolio Overview filters and sort, Export on Overview and Performance (#6208)

Builds on D4817 parts 1 and 3 (#5311): the Portfolio v2 canvas (`design/incoming/Portfolio v2 Page.dc.html`), boards PF-01 (Overview), PF-03 (Performance), PF-09 (States, "Export failure") and PF-10c (phone filters). Frontend only. No route, Worker or schema change: sector and stage are already on each `/api/positions` row (`project.sector`, `project.stage`), and Reporting is the obligation `kpi-compliance` already answers per company.

**What is built.**
- **Overview filters** (`InvestorPortfolioCanvas.jsx`, `CompanyTable`). Sector, Stage, Health and Reporting selects, in the canvas's order, then a Sort select. `filterRows` in `portfolioModel.js` takes `sector`, `stage` and `reporting` beside `query` and `health`.
  - Sector and Stage offer only the values the book carries (`filterOptionsOf`), title-cased. A row that records none is reachable through its own "Not recorded" choice (`NONE`), not hidden.
  - **Reporting is the row's real field.** It is `reportingFor`'s state for the measured period: Not received, Due, Received, Not recorded (the company is not in the reporting population) or Unreadable (the reporting read failed). It is the same word the Reporting column shows. The select offers only the states present, in that order. No other reporting field exists on the row, and none is invented.
  - **Sort**: health (the table's own order, then invested), invested (largest first), multiple (highest first) and last update (newest first). A row with nothing recorded for the key sorts last, never as a zero (`sortRows`).
  - **The caption states the filters in force**: "2 of 4 companies · filtered by Sector: Robotics, Reporting: Received · sorted by multiple, highest first · values gross" (`tableCaptionOf`, `filterWordsOf`). With no filter it is the canvas's caption, unchanged. While a filter narrows, a line above the table gives the count and Clear filters.
  - An empty result keeps the existing row, "No company matches these filters."
  - The filter and sort state moved from the table to the page, because Export writes exactly the rows the table shows.
- **Export** (`PortfolioExport.jsx`, in the header beside Ask, as PF-01's header draws "Export ▾"). It writes only through `exportView` (`lib/csvExport.js`): no new CSV code. The model's builders decide what each file holds.
  - **Overview** (`companyExportOf`): the rows shown, in the order shown. The columns are Company, Sector, Stage, Invested, Latest FMV, Mark date, Ownership, MOIC, Reporting, Period, Health, Last update, Basis and As of. Basis and As of come from the performance read: "Gross of fees and carry", plus its `as_of` date or "Latest recorded marks". If that read failed, As of is written as Unreadable.
  - **Performance** offers a menu of two choices.
    - Quarter-end series (`quarterExportOf`): every quarter-end in the window, in order. A gap is written as Not recorded or Unreadable in every figure cell, with the reason in a Note column. It is never written as 0 or left blank. A measured $0 distributed stays $0.
    - Vintage cohorts (`cohortExportOf`): one row per vintage, as the table shows it. Its As of is "Latest recorded marks", because cohort carrying values are the positions read's latest marks, not the performance read's as-of.
  - **Disabled with its reason** when there is nothing to write: a source still loading, positions or the series unreadable, an empty book, no cohort, or filters that match nothing. The reason is the button's `title` and is also linked by `aria-describedby` to text a screen reader reads. A header-only file is never written.
  - **A refused file** (no `createObjectURL`, or the browser throws) shows PF-09's "Export failed. Nothing was downloaded." as an alert with Try again. Try again writes what the page holds now.
  - **The series moved up.** QuarterEndSeries reads each quarter-end in its own child component. It now hands its series up (`onSeries`), and the page uses a series only if it was read for the current window.
- **Phone** (`portfolio.css`, ≤600px): the filters become a two-column grid. Search and Open Positions take the full width, and every control is at least 44px. The Export menu opens left-aligned and no wider than the screen, with 44px choices.

**Checked against `main`.** PF-09's "Export failure" is one cell of the States board PF-09 (`STATES` in the page file). The canvas's PF-12 lists "Exports · Existing CSV paths · #4647 owns completeness"; this change uses the existing client-side path (`exportView`). It exports the loaded rows, so the Overview file is the page's book, not a server-side report.

**Tests.** `frontend/test/portfolio_export_filters_6208.test.mjs` (7 tests). It mounts both pages against a stubbed `fetch` and reads the written file back from its Blob.
- Mutation-checked, each one both ways: 19 mutations, 19 caught.
- The mutations covered: sector, Not recorded and reporting filters ignored; missing sort keys sorted first; sort reversed; caption without filters; export of every row instead of the rows shown; a missing figure written blank; basis and as-of dropped; a quarter gap written as 0; export over loading quarter-ends; the filtered-empty and failed-cohort reasons removed; the button never disabled; a refused file reading as written; the menu staying open; the phone grid removed; the export ignoring the sort; the cohort export unwired.
- One mutation was found equivalent and is not counted: treating a missing sort key as 0. With non-negative figures, a 0 already sorts last in a descending sort. The test of missing-first ordering is what holds the rule.
