## D6629 — The investor's deal summary PDF: gated at download, stamped for the reader, recorded (#6629)

- **Status:** Worker and client built 2026-11-18 (Part of #6629, under #4815). The deal header's More menu item is S33's, by the owner's answer A on #6629 (2026-11-16); #6632, which owned that menu, has merged.
- **Routes:** `GET /api/deals/:id/summary` (may this investor download it now, and the stamp) and `GET /api/deals/:id/summary/pdf` (the file), in `routes/deal_summary.ts`, mounted ahead of the deal-context router. The content is `services/dealSummary.ts`. No new table, no migration.

### Who gets the file

Every request is gated again; nothing the availability read said is trusted when the file is asked for. In order:

1. Signed in, not a support session, holding the Investor licence (`deal_context`'s `context`).
2. The firm the deal is read for (`X-Company-Id`, or the only firm), and the deal visible to this investor for that firm (`visibleDeal`: invited or committed there, venture not deleted). An invitation held for another firm opens nothing: that is the cross-firm case, answered 404 like any deal not open to the caller.
3. A paid Investor plan. A Free reader of `GET /api/deals/:id` gets the Free projection (D4631 part 4), and this file holds more than that, so Free is refused with the plan upsell (402).
4. An active NDA with the venture (`hasActiveVentureNda`, the rule the data room, the evidence read and the deal read share).

No staff or founder path: the summary is the investor's copy of their own view.

### What it holds, and from where

- **Key figures:** Round, Instrument, Committed, Minimum, Closes, from the deal row as `GET /api/deals/:id` reads it for a member (`serializeDeal`). Committed is the round's confirmed total across all investors, said as such, as the deal page's strip says it. It names no investor and gives no one investor's amount.
- **Terms:** Valuation cap, Carry, Management fee.
- **Your stage:** `stageRead`, the stage and next action `GET /api/deals/:id/stage` returns. It moved out of the route handler into a function so the two cannot drift.
- **Scorecard:** each scope's band and confidence word, only while the founder shares the scorecard with investors. The masked view is printed even after the NDA: values and inputs stay on the page, where they are read live and logged. The download writes a `venture_score_read` row with `surface: deal_summary_pdf` when bands were printed.
- **Evidence shared with you:** `investorEvidenceView`, the investor evidence read (`investorEvidence`) by the same audience, NDA and sharing rules, without its `open_evidence` row. A figure only where the founder shared it after the NDA; otherwise the reason it is withheld.
- **Never:** another investor's name or amount, any firm's notes (no note is read), evidence outside the caller's access, an email address.

A block whose read fails prints "Unreadable" with its reason and the others still print. A figure the deal does not hold is "Not recorded" with why, never 0. Without the deal row nothing is made.

### Stamp and date

The top line and every page's foot say `Prepared <date> for <name>, <firm>`: the signed-in investor's name and the chosen firm's name (`company_profiles`). An investor with no firm link is stamped with their name alone. The date is the day the file was made, and the file says it is a copy that does not update.

### The record

Each file sent writes one `data_room_access_log` row: the venture, no file id, the investor, `download_deal_summary`, the time. It is the row an evidence open writes, under its own action. It is written before the file leaves; when it cannot be written the request answers 503 and no file is sent. The availability read writes nothing.
