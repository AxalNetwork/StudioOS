### The six invariants

Each checker is `(observations) → { name, ok, checked, violations }`. Two rules apply to all of them:

- An unreadable observation set fails.
- A check that was never exercised fails (`not_exercised`), never passes.

1. `checkTenantIsolation`. Zero cross-tenant access to files, cache, refs, logs or credentials, and every one of the
   five must have been probed. Files are probed with `uploadFence` on another venture's run, refs with an `artifact.read`
   grant naming another venture's object, and credentials by redeeming another venture's grant against the probing
   venture's own run. **The real contracts refuse all three.** Cache and logs are refused by the mock sandbox's tenant
   prefix (`workspaceArtifactPrefix`); each access event records which enforcer refused it (`contract` or `mock`).
2. `checkNoUnreviewedDeploy`. Every deploy follows an approved review of an opened PR. Every task first attempts a deploy
   before review, and the D5567 publish gate must refuse it.
3. `checkNoDoubleEffect`. At most one charge per idempotency key and one PR per run key, and none for a cancelled run.
4. `checkCheckpointsKept`. A recovery restores the newest checkpoint acknowledged before it, and never an unacknowledged
   one.
5. `checkNoStrandedCompute`. Every execution the provider created is stopped and cleaned by the end of the
   reconciliation window (60 s on the virtual clock). The executions are observed at the provider, not by the driver, so
   an orphan the control plane lost is still counted.
6. `checkPolicyNeverExecutes`. A revoked sponsor's run never leases, and a run whose allowed regions the provider cannot
   enforce is never created. Each venture gets one probe of each.

### Faults

Each fault has its own test showing that the invariants hold, or that the runs fail closed.

| Fault | Injected as | Expected result |
| --- | --- | --- |
| Provider 429/5xx | The first two creates are refused as `provider_rate_limited` and `provider_unavailable`. | Retried with backoff; one physical create; counted as a quota incident and in retry amplification. |
| Unknown create outcome | The create happens, but the answer is `create_outcome_unknown`. | The retry reuses the same idempotency key and reconciles to the same execution; no second one. |
| Lost callback | The completion response is lost and the runner replays it. | The replay is a `duplicate`; no second charge or PR. |
| Queue redelivery | The task message is delivered again after the run ends. | Registration and create are idempotent and the lease is `lease_unavailable`; no new effect. |
| Expired grant | The bootstrap grant is redeemed after its 5 s lifetime. | `grant_expired`; the run fails closed, its execution is stopped and cleaned, and nothing executes. |
| Image unavailable | Every create is refused as `image_unavailable`. | Not retried; fails closed with no execution created. |
| Forced termination | The provider kills the execution after its checkpoint. | Reaped after three missed beats; the old execution is stopped and cleaned before generation 2 restores the newest acknowledged checkpoint. |
| Missed heartbeat | The runner goes silent while its execution keeps running. | As above, and the old runner's late completion is refused as `stale_generation`. |
| Partial upload | The first checkpoint arrives truncated. | The hash mismatch is rejected and never acknowledged; the full retry is acknowledged. |
| Cancellation racing completion | Cancel and complete are sent together, in both orders. | Exactly one wins; a cancelled run has no charge, PR or deploy. |
| Integration conflict | The approved merge conflicts. | No deploy and no second PR. |

When every task carries a terminal fault (expired grant, image unavailable), no task reaches isolation probes or
deploy. Those two checks then report `not_exercised`, so the report fails rather than claiming them. The tests pin this.

### The report

`buildReport` records:

- the evidence class and sample size;
- the full config and seed;
- the commit;
- queue, start, run and checkpoint-restore p50 and p95;
- success % (deployed after review), the outcome breakdown and retry amplification (create attempts per logical create);
- provider quota incidents and PR and Git-operation counts;
- the fault counts (injected and triggered);
- the six verdicts.

The harness only ever emits `local_mocked`:

- `evidenceClassFor` throws for any other class, and for any source that is not the in-process mock.
- `validateReport` flags a mock relabelled `hosted_stubbed`, `real_cloud` or `production`, any capacity-proof claim, and
  any measured timing claim.
- Cost per completed task, egress and Git clone cache hit % are `{ measured: false, value: null }`, never 0.
- The CLI has no evidence-class option; an unknown flag exits 2.
- Every timing is a synthetic virtual-clock value from the seed, labelled `virtual_clock_synthetic`.

Observations and reports hold synthetic ids, counts, codes and outcomes only, and no grant material.

### What this proves, and what it does not

**It proves,** locally and against the real contract code, that the D5565/D5567 contracts plus a correct broker sequence
keep the six invariants under each listed fault, for 2 to 10 synthetic ventures and up to 1,000 tasks at a set
concurrency. It also proves that the checkers catch each violation: 24 deliberate mutations were each killed.

**It does not prove** any hosted, cloud or production property:

- no container isolation, image provenance or region placement;
- no quota, capacity, throughput, latency or cost figure;
- no real GitHub PR or merge.

The provider, cache and log isolation, region enforcement and publisher are mocks or synthetic evidence. In particular,
the image evidence is a fixture: the real candidate image failed its vulnerability gate in #5694.
