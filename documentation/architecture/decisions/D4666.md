## D4666 — The estimate a member approves is the operation that runs (#4666)

Package 6 of 6 of the Email audit (finding 11). No migration.

**The problem.** The composer estimated the base request once and reused that estimate for everything after it. Regenerate reused it when the request had not changed, even if the sources, the live blocks, the model or the price had. Shorter called the revision with no estimate at all, although a revision's prompt also carries the draft and the instruction. Nothing tied the number on screen to the run, and the run did not check a ceiling.

**The contract.**
- **An operation is the exact prompt.** `operationFingerprint` hashes the task, the token ceiling and every message the model will be given: the recipient, purpose, tone, length, the ticked sources with their text, the live blocks and, for a revision, the exact subject and body being revised and the instruction. A change to any of them is a different operation.
- **A quote is signed, not stored** (`services/mail/draftQuote.ts`). `estimate: true` answers `{ hold_microusd, model, kind, quote, expires_at }`; the quote holds the member, the fingerprint, the model, the maximum hold and a 10-minute expiry, HMAC-signed with the Worker's secret. A client cannot raise its maximum, move it to another member or another operation.
- **A run must bring it** (`routes/mail_drafts.ts`). Before the router reserves anything, the Worker prices the operation as it stands now and accepts the quote only if it is the member's, unexpired, for this fingerprint and model, and covers the hold the router would reserve now. Otherwise the answer is `409 estimate_required` with the reason (`missing`, `invalid`, `expired`, `changed`, `repriced`) and a fresh estimate, and no model is called, no budget is reserved and nothing is stored. Because the hold is checked against the accepted maximum, the router's charge cannot exceed it.
- **Revising the member's text.** `POST /drafts/:uid/revise` takes an optional `base: { subject, body }`: the text in the member's editor. The estimate and the run then name that text, not an older saved draft behind it. Absent, it is the saved draft. (Durable edits and version integrity stay with #4660.)
- **Other callers.** The MCP tool `mail_draft` runs `runDraft` directly and is unchanged. Only the HTTP routes the composer uses require a quote.

**The page.** One hook reads the estimate for the operation on screen and derives the gate from that operation at render time (`estimateGate.js`, `useOperationEstimate.js`).
- The moment the request or the editor text changes, the old answer is no answer, and a late answer for another operation is ignored.
- Draft and Regenerate share the request's estimate. Shorter has its own, of the text in the editor, read after a short pause.
- Each button is shut while its own estimate is loading, unreadable or expired, with a retry. A missing or zero price is unreadable, never free.
- A press sends the quote of its own estimate. A refused run swaps in the fresh estimate, says why, and runs nothing; the member presses again.
- Both surfaces use it: the Email composer (`ComposeSheet`) and the record's Ask (`EmailDraftIntent`).

**Tests.** `mail_drafts_d1341` (4 new): no quote, forged quote, another recipient setting, other sources, another member and moved source contents each start no run and store nothing; Shorter's estimate differs from the draft's and cannot be swapped; the instruction and the member's base text are part of the operation; the quote verifies only when it is the member's, unexpired, unforged, for this model and no cheaper than the hold. `email_estimate_binding_4666` (6 new): the gate, the mounted composer (Shorter waits for and names the edited text, a late answer is ignored, a refused run takes the fresh estimate, a failed estimate shuts the buttons with a retry). Mutations caught: the approval check skipped, the fingerprint not compared, the maximum not enforced, an answer for another operation accepted, Shorter pressable without its estimate.

**Not done here.**
- Durable edits and version navigation (#4660): the estimate names the editor's text, but moving between versions does not yet re-key to a stored snapshot beyond that.
- A live charged run: nothing here ran a real model.
- The router itself has no per-run ceiling input; the ceiling is enforced by refusing before the run when the hold it would reserve exceeds the accepted maximum.
