## D5084 — Revenue's Eadwyn suggestions are its own finance tasks, with nothing to pick a model with (#5084)

- **Status:** built 2026-11-09 (#5084). No route and no migration. The generated `railMatrix.json` gains eight rows.
- **Number:** D5084 is the issue's number (D4106).
- **Builds on:** D5039 part 1 (#5111), D1596 (no-model Ask chips), D1443 (the Ask panel's "Suggested for this page"), D4313 (every rail option names a job), D775 (Super Admin boards H12–H17).
- **Defers to:** #5130, the shell-wide rail: where model choice, pricing and token detail move, and the rail's structure. No separate panel is built here (S1, 2026-11-09).

### What part 1 already did

#5111 shipped most of #5084: margin-first AI economics with one coverage state (RV07, RV07b), the promotion state badges and the no-ceiling row (RV10), and one temporal-label pattern. What was left was the Revenue rail's default suggestions.

### What changed

Before this change, HQ › Revenue (`Super Admin · Revenue`, H12–H17) registered no rail option, so the Ask panel suggested nothing finance-related. It now has its own Ask chips, `SUPER_ADMIN_ASK_CHIPS` in `frontend/src/lib/railOptions/superAdmin.js`:

| Board | Chips, in order |
|---|---|
| `Super Admin · Revenue` (`/admin/revenue`) | Summarise the selected period · Explain incomplete sources · Show overdue receivables · Review open disputes · Compare subsidiary reporting · Explain the AI margin |
| `… · Disputes` (`#disputes`) | Review open disputes |
| `… · Statements` (`#statements`) | Show overdue receivables |

- **Each chip is `handler: 'none'` and `noModel: true`.** It puts its question in the Ask composer, and Ask Eadwyn answers it, so `RAIL_OPTION_JOBS` maps all six keys to ST1. The chip itself runs nothing in the panel and offers no model to pick. That keeps model choice and pricing off Revenue's working rail without restructuring the rail, which is #5130's job.
- **The chips are their own list.** `SUPER_ADMIN_RAIL_OPTIONS` stays the list of controls that run a model. `rail_revenue_super_admin_d775`'s "Revenue offers no option" still holds.
- **The list is registered in `scripts/build-rail-matrix.mjs`'s `OPTION_LISTS`.** `GET /api/ai/rail?page=` serves the chips as the page's `options`, and `AskPanel` draws them through `panelChips`.
- **Overview, Refunds and Promotions get no chip.** None of the six is theirs.

### Not done here

- **Moving model configuration behind an "AI settings" action** is the rail's structure, which is #5130. That issue is waiting on its canvas.
- **What Eadwyn can read when it answers a chip** is the Ask conversation's existing page context. This change adds no new data source to it.
