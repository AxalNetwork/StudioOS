## D8199 — Literal manifest diagnostic assertions (#8199)

### Decision

Compare the manifest validator's expected filenames, refusal codes, listed paths
and success count as literal text. Preserve the validator, its policy, all
existing fixtures and every process exit-status assertion.

The focused suite now rejects near-miss expected refusal codes and exercises
filenames and privileged paths containing a literal `+`. The positive refusal
control uses the same invalid manifest and actual validator as the negative
controls, so a missing or broken validator cannot satisfy those checks.

### Validation and handoff

The existing focused suite passes 13 tests before the change and 14 afterward,
with no skips. Four bounded mutations fail by assertion: restoring either old
pattern comparison, omitting the literal diagnostic check, and prefixing the
reported success count with an extra zero. Each mutation is restored before
review. Validation uses the repository's existing pinned YAML parser; no
manifest or dependency declaration changes.

This change coordinates #8199, #8200, #8221 and #8222. Keep all four trackers
open through required review, hosted checks, landing and confirming main
verification. Local tests do not establish a protected finding's disposition.
Detailed evidence remains in the protected records. Full application build and
drift results are not claimed for this scoped change.

### Rollback

Revert this test and decision change if required. The production validator and
agent manifests are unchanged.
