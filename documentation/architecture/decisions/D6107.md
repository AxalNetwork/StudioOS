### 1. The role (migration and `services/posthog/metrics.ts`)

- `ROLES` gains `visits` ("Visits"), between `sessions` and `other`. Its unit is a count.
- The role list is also a SQL `CHECK` on `posthog_tracked_metrics.role` (755). SQLite cannot widen a `CHECK` in place, so the migration rebuilds the table, as 754, 553, 331 and 266 do:
  - every column, default, foreign key, the `UNIQUE` and the unit `CHECK` are 755's, verbatim;
  - every row is copied with its id;
  - the one index is recreated.
- No table references this one, and it has no trigger, so nothing else is re-run.
- The SPA's role chips (`fromPosthogModel.js`, `ROLE_CHIPS`) gain Visits, so the founder can pick it in Track a metric.

### 2. The stage (`services/posthog/visits.ts`, `services/growCycle.ts`)

`visitStage` reads what a section sync landed. It never calls PostHog. In order:

| Case | The stage |
|---|---|
| The viewer is not on the venture's team | Not recorded: PostHog figures are for the venture's team only |
| No PostHog link, or its connection is not active | Not recorded: PostHog is not connected for this venture |
| Linked, but no metric tracked as Visits | Not recorded: no PostHog metric is tracked as Visits |
| Tracked, no figure read yet | Not recorded: the Visits metric has no PostHog figure yet (or "PostHog is disconnected" when the metric's connection is not the venture's link) |
| Read | the latest figure among the venture's Visits metrics, `source: "From PostHog · <insight>"`, `as_of`, `apart: true` |
| The PostHog stores cannot be read | `state: 'unreadable'`, "Unreadable: PostHog figures could not be read". The rest of the card still loads. |

- **Its own sourced value (#3731).** The figure is never merged with sign-ups or any other store. `apart: true` tells the page to list it with its source and date. It is never the funnel's first bar, so sign-ups are never drawn as a share of a PostHog count from another window.
- **Any module.** A Visits metric may be tracked in any PostHog module; the stage reads it wherever it is, and that section's sync lands its figure.

### 3. The viewer (`routes/cycle_grow.ts`)

- `Ctx` gains one optional boolean, `team`. It is not a user object; absent means "not the team".
- Only the two card reads set it: `GET /overview` and `GET /modules/:slug` pass `isTeamViewer(env, user, project)`, the rule decision C already uses. The CSV export builds no card, so it does not set it.
- No route, gate or refusal code is added.

### 4. The page (`pages/cycles/adapters/grow.js`)

- A step marked `apart` with a value is listed as a row, for example "1,240 · From PostHog · Site visits, as of 2026-11-13".
- The funnel starts at the first recorded step that is not apart.
- A step with no value still shows the Worker's own reason, as before.

### 5. Departures and defaults

- **Per-channel visits stay out.** #2409 named "visitors by UTM source per channel" as an F landing. A tracked insight is one venture-wide number, so a channel record's own funnel (`records/grow.ts`) still reads "Not recorded". Its reason changes from "No page-visit store" to "No per-channel visit count", since a venture-wide store now exists.
- **No `distribution` PostHog module.** `POSTHOG_MODULES` is unchanged. A Visits metric is tracked in one of the existing modules, usually Revenue and traction, where it is also a `posthog-<uid>` KPI row (D1609).
- **Several Visits metrics.** The stage shows the one read most recently. None is summed.
- **Range.** The card's range stays "This month". The Visits figure carries its own as-of date and is whatever window the founder's insight measures.
- **#5841 (Search Console)** is clicks for Results. It does not claim this stage.
- **The rebuild's drop and rename.** The schema preflight flags both, as it does for 754. They are the rebuild, not a contract step: the table keeps its name and every column, and the Worker one version back writes only roles the wider `CHECK` still accepts.
- **`services/posthog/` joins `DOCUMENTED`** in `scripts/check-folder-docs.mjs`. `visits.ts` is the folder's eighth source file, the size at which the check asks for it. Its README already explained the folder; it gains a line for `visits.ts`.
