### What a comparison means

Only figures actually stated in a version's wording or Why now are compared to the metric side. Project columns are not a deck binding and never supply purported deck statements. The deck side reads “Not compared” until #2434 binds a deck to a narrative version.

`checkInputs.compared` counts actual finite statement/metric comparisons. The narrative readiness input exposes the same `compared_count`; with none, its missing-input reason and read say “Not enough recorded”. D890 / #2448 and READINESS #2433 own the readiness score policy. This part supplies comparison coverage, not a new scoring formula.

A card, version list or record with no comparisons says “Nothing compared yet”. A record compares current stated and metric values; a missing saved mismatch row does not imply agreement, and a stale mismatch does not overrule a current agreement. Version listing reads shared metrics once for the venture, rather than once per version. No read writes or repairs historical rows.

### Deck use and copied versions

Saving a version no longer records the newest pitch deck as a purported consumer. Existing historical `deck_version` values are retained but do not establish a binding: the list and record say “No deck reads this version.”

Starting from a version and Duplicate copy Why now and Check against along with wording. An explicit replacement or null supplied by the founder takes precedence. The source version remains unchanged, and each save/duplicate uses the existing writer and writes exactly one `raise.investor-narrative` cycle activity row, without financial figures or investor names.
