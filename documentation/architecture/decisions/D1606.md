### 1. The sync (`services/posthog/build.ts`)

`POST /api/cycles/build/posthog/sync` is pressed by the member whose PostHog serves the venture.

| What it reads | Lands as |
|---|---|
| Every metric tracked in Prototype / MVP or Product roadmap | a `metric` fact for today |
| Each feature flag (at most 10) | a `flag_state` fact for today: key, active, rollout and the linked must-have. A day's fact is kept, so the rollout's history is kept. |

### 2. What waits for Accept

- **"Link flag <key> to a must-have?"** (`flag_link`):
  - proposed for each flag not yet linked;
  - Accept needs the founder's must-have, which must be one of this venture's. It is never guessed from names;
  - the accepted proposal is the link, and a linked flag is not proposed again.
- **"Mark <must-have> Done?"** (`flag_shipped`):
  - proposed when a linked flag's current run of daily facts, active at 100%, began at least 14 days ago. An inactive day or a lower rollout restarts the run;
  - a must-have already Done is never proposed;
  - Accept moves the must-have to Done with the same statement and log line `PATCH /api/cycles/build/features/:id` writes. Migration 441's trigger dates it.

### 3. Reads

- **Prototype / MVP.** `GET /api/cycles/build/posthog?module=prototype_mvp` adds the venture's must-haves (for the link) and each linked flag's latest chip.
- **Product roadmap.** In a roadmap item's Moves column, a `posthog-<uid>` KPI reads "Weekly active users 1,240 · From PostHog, as of <date>", or "<name> · Not recorded". It never shows the key.
- **Operating systems.** `module=operating_systems` adds the Tools line:
  - the linked project, its region and last sync;
  - each sync's section and counts, newest first, from `activity_logs`;
  - "PostHog is disconnected" when it is.
  - No `project_core_systems` row is written.

### 4. The SPA (`pages/cycles/BuildPosthog.jsx`)

Each module gets one `posthog` line in `buildParts.jsx`, after its other connectors:
- **`PrototypePosthog`** draws the flag chips ("Flag 25% · active", or "rollout not recorded", never an invented 0). It also draws Link, with the must-have select (off until one is chosen), and Mark Done, which says how long the flag has been at 100%.
- **`RoadmapPosthog`** draws the tracked metrics.
- **`OperatingPosthog`** draws the Tools line and the sync lines, and nothing when the venture has no PostHog link.

`FromPosthog` now passes its read (`ctx.data`) to `renderProposal`.
