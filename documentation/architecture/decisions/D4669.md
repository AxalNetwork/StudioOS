## D4669 — Session containment: an ended session ends everywhere, and emergency acts say what they reached (#4669)

- **Status:** Part built, 2026-11-07. Waiting on the owner: review of the audit findings in the private advisory process (SECURITY.md), and the cross-branch scope question below. Production behaviour is **unverified**: nothing here was checked against the live deployment.
- **Builds on:** D481 (HQ · Security's session list and acts), D165 (sign one account out), D248 (support-session expiry and ceiling), D120 and D122 (branch support sessions), D104 (branch cookie names), T6 (request protection).
- **Stays out of:** what counts as an active session in lists and counts, security-event identity, partial reads and backup evidence (#4691); the data-subject request lifecycle (#4675); the per-route authorization matrix (#4570).

### What is built

1. **Ending a session ends it on every request path.**
   - A support-session token, HQ's or a branch's, names its support-session record. Every request re-reads that record, so ending the session refuses the token from its next request. Before, ending closed the record and the token lived on until its own expiry.
   - An HQ support session also stands only while the operator who opened it is an active administrator whose own sessions were not signed out after it was opened. Signing the operator out ends the support sessions they hold.
   - A support session whose record cannot be written is not opened, and no token is handed out. On a branch the same holds for the session row.
   - The realtime upgrade now asks the same question the HTTP path asks (`sessionStanding` in `auth.ts`): the account's sign-out floor, the session row, the support-session record.
   - Every Worker mint path issues a token bound to a row that can end it. The one that did not (the deck-share sign-up) now writes its session row; the realtime probe presents the caller's own session instead of minting one.
   - Sign-out revokes every session the request presents, read the way authentication reads them, including a branch's own cookie, and its answer says whether a session was ended.
2. **Safe failure.** A session or support-session store that cannot be read is a refusal, never a pass. Ending a support session, and HQ's sign-out acts, report a failed write as a failure (503, nothing changed) instead of a success or a generic error.
3. **Request protection follows the authentication source.** The exemption for Bearer-authenticated requests applies only when the Bearer is the credential that authenticates the request, by the same precedence authentication uses.
4. **Emergency-action scope is stated.** Every session act on `/admin/security` writes this deployment's database. A branch is its own deployment, with its own accounts and sessions, and is not reached. Each act's answer now carries `scope` and, for sign-outs, `outcomes`: one row per deployment, this one with its result and each bound branch as `not_reached` (`services/emergencyScope.ts`). The page says so beside the acts and under each result, and the sign-everyone-out control reads "this deployment", not "all tenants".

### Waiting on the owner

- **Cross-branch emergency actions.** Whether HQ should be able to sign accounts out, or end support sessions, on branch deployments too, and with what per-branch outcome. Options are in the issue's STATUS comment. Nothing here builds it; the answer states the scope as it is.
- **Owner review** of the findings, through the private advisory process.

### Residual, stated

- A token minted before this change carries no binding and is held to the account's sign-out floor and its own expiry: at most thirty minutes for a support session, a day for an ordinary one.

### Tests

- ended, extended, mismatched and unrecorded support sessions; the operator signed out, deactivated or demoted;

- the realtime upgrade under revocation, sign-out, ended support and an unreadable store;
- request protection with empty, undecodable, foreign and matching Bearers;
- sign-out on a branch and under a support Bearer;
- branch support sessions ended, and refused when their row cannot be written;
- per-deployment outcomes and failed sign-outs;
- a scan that every mint path binds its token.

`frontend/test/hq_security_scope_d4669.test.mjs` covers the scope sentence and the per-deployment outcome lines.
