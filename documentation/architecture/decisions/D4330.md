### 1. The three drafts

| Board | Press | Route | Who may press | It reads |
| --- | --- | --- | --- | --- |
| RI3 | "Draft from this record" | `POST /api/relationships/drafts/ask-reason` `{ teammate, ref, record? }` | the asker | the teammate's shared row, if the caller can see it now; and the record the asker is on, if they name one |
| RI4 | "Draft with Eadwyn" | `POST /api/relationships/intro-requests/:uid/drafts/intro` | the teammate, once they have accepted | the request: who asked, the person, the reason, and the context note the teammate may forward |
| RI6 | "Draft a follow-up" | `POST /api/relationships/intro-requests/:uid/drafts/follow-up` | either person on a made introduction | the request, the date it was made, and the latest recorded outcome ("Not recorded" until there is one) |

RI3 answers `{ text }`, the reason, which goes into the request's `note`. RI4 and RI6 answer `{ subject, body }`, which the member opens in the Email composer (#3547).

**A draft makes nothing.** An introduction is made only when the teammate sends the intro from their own mailbox (D4329 §1).

### 2. A quoted proposal, metered like every Eadwyn run

- **The quote comes first.** `estimate: true` answers `{ estimate: { hold_microusd, model } }`. That is the router's own quote (`quoteRun`), so it runs nothing, holds nothing and writes no usage row.
- **The run is the router's `mail_draft` task (D1341).** It is held, guarded and charged in the pressing member's AI tokens, and logged with surface `/network/introductions` and page `Founder · Network · Introductions`.
  - **On refusal:** a short balance is 402 in the top-up sentence, and a switched-off page is 403.
  - **On a bad answer:** an answer that is not a draft is 503 `draft_unreadable`.
- **Nothing is stored and nothing is sent.** The reply is `{ draft: { kind, proposal: true, … } }`, and the member copies the words where they want them.
- **Spend.** No model is wired here. The drafts use the model and the price that Eadwyn's email drafts already have (`mail_draft` in `ROUTE`). Each press is quoted before it runs, so its cost shows first.

### 3. What a prompt may carry (the access rule)

"Each draft reads only what its caller may already see under D1356's rule." Each prompt is built from:

- **RI3:** `visibleRelationship`, which is the same one statement an introduction request checks: my team, the teammate's membership of it, and their share effective now.
  - **A hidden relationship is 404** before any quote or run. That covers a teammate who did not share, another team's member, and an API-only row.
  - **The record** goes through `personRecord`, the mail context pack's read, which applies each module's own gate. A record the asker cannot read is the same 404.
- **RI4 and RI6:** `requestOf`, which names the caller in its `WHERE` clause. A request between other members is 404 "Not found.".
- **Never a contact detail.** The shared projection has no email, phone, notes or URL column, and the prompts never read `network_connections`.
- **Every line is scrubbed** before it reaches the model, covering the request's notes and the record's own text. Anything that looks like an email, a link or a phone number is withheld: seven digits or more, where an ISO date is not one.

### 4. Checks

`relationship_drafts_d4330.test.ts` runs on the real migrated schema with synthetic people. `env.AI` is the guard stub, which records every prompt, and `fetch` throws. It covers:

- **Hidden relationships are refused.** A hidden relationship is 404 for both the quote and the run, before and after sharing, and no prompt is written.
- **The quote runs nothing,** and the run is the asker's, charged and logged against `/network/introductions`.
- **The prompts:**
  - RI3's prompt carries the shared row and the record;
  - every prompt is checked against the books' and records' emails, phones, URLs and notes.
- **The drafts:**
  - RI4 is the accepted teammate's alone, and leaves the request accepted;
  - RI6 is either person's once the introduction is made, and reads the recorded outcome;
  - a short balance is 402, an unusable answer is 503, and a support session is 403.
- **Nothing is stored or sent:** no `mail_drafts` row and no `mail_sent` row is written.

**Mutations: 6, all caught.**
1. RI3 reads the contact without the access statement.
2. The estimate press runs the model.
3. The scrub is skipped on the record's text.
4. RI4 reads the request for either side.
5. RI6 accepts a request that was only accepted, not made.
6. The scrub is skipped on the request's lines.
