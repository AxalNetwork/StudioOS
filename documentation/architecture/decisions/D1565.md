## D1565 — One link per investor, and tailored variants

- **Status:** built by S04 from S1's revised specification on #3812 (deck builder v2, Phase D, D4; final canvas PD-8 · pd35).
- **Builds on:**
  - D691 and migration 463's per-prospect links (`pitch_deck_share_tokens.prospect_id` and `investor_label`);
  - D902's one link writer (`createDeckLink`), its NDA gate and what a link includes;
  - D1111's Withdraw (`revoked_at`);
  - D1604's studio adapter (`deckV2Adapter.js`).
- **Migration:** `738_deck_variants_and_investor_links.sql`.

### The question

pd35 draws "Share, one link per investor": one row per investor with the frozen version or a tailored variant, the NDA status, expiry, view cap, a recipient watermark, the analytics so far, and Withdraw. The links already existed, one per prospect. What was missing:
- a per-investor read;
- the variant a link opens;
- the watermark;
- the NDA status with its date.

S1's revision says to build this on the existing links, not as a second store.

### What was decided

**Migration 738**
- `deck_variants`: one tailored order of a frozen version (`pitch_decks` row). It holds the investor's stated thesis (`sectors`, `anti_sectors`, `stages`, as entered), the slide order, and the emphasis plan.
- Two new columns on `pitch_deck_share_tokens`:
  - `variant_id`;
  - `watermark_text`.

**A variant never holds a figure the master lacks.**
- It holds no cards of its own, only an order of the master's.
- `cleanOrder` refuses a card the master does not have, or a card listed twice. A card the order leaves out is kept, at the end.
- `checkVariantFigures` compares every figure in the variant against the master, and the route refuses a mismatch (422 `figure_not_in_master`).

**`tailor_match` and `tailor_plan`** (`services/decks/variants.ts`, pure, no model)
- `tailorMatch` sets the venture's sector and stage against the stated thesis. An anti-thesis sector is a **conflict chip**: "Their thesis excludes [sector]". A sector that is not recorded reads "Not recorded".
- `tailorPlan` orders the cards:
  - the title first;
  - then the cards that speak to the thesis, marked `lead`;
  - then the rest, in the master's order.
- Free-text thesis prose is never parsed.

**The recipient watermark** is written by the one link writer (`createDeckLink`) on every link, as "Prepared for [investor] · [fund]": the prospect and their firm, or the name typed. It moves here from #3809. The opened deck (`GET /api/decks/share/:token`) returns it as `watermark`, and a link made with a variant opens the master's own cards in the variant's order.

**The routes** (`routes/deck_investor_links.ts`, mounted at `/api/decks` before `decks`; gate `projectOwned`, writes with `write: true`, the studio plan for a link):

| Route | Answer |
|---|---|
| `GET /:id/investor-links` | `{ deck_id, version, links }`. Each row carries: `investor { label, fund, prospect_id }`, `version { variant }`, `nda` (`accepted` with `accepted_at`, `not_accepted`, or `not_required`), `expires_at` (null for Never), `view_cap { limit, used }` (`limit` null for No cap), `watermark`, `status` (`live`, `withdrawn`, `expired` or `used_up`), `withdrawn_at`, and `analytics { views, last_viewed_at, read_seconds }` |
| `POST /:id/investor-links` | D902's body plus `variant_uid?`; 201 `{ link, share_path }` |
| `POST /:id/investor-links/:shareId/withdraw` | `{ ok, link }`, through `revokeShareLink`. The link no longer opens, and its views and NDA signatures stay readable. |
| `GET /:id/variants` | `{ variants }`, each with `tailor_match` |
| `POST /:id/variants` | `{ name, prospect_id?, thesis, slide_order? }`; 201 `{ variant }`. With no order, `tailor_plan` decides it. |

**The screens**
- `frontend/src/lib/api/deckInvestorLinks.js` (`deckInvestorLinksApi`) is re-exported by one line in `api.js` (D527).
- `deckV2Adapter.js` swaps `investorLinks`, and adds `withdrawInvestorLink`, to `through(() => deckInvestorLinksApi.…)`. Both are in the adapter's new `WIRED` set.
- `ShareDialog.jsx` (Share ▾ › Share link…) draws `InvestorLinksTable.jsx` above the new-link form:
  - one row per investor, with Withdraw behind "Withdraw this link? … Analytics so far are kept.";
  - "Views on your links could not be read." with Try again (pd9c);
  - the new-link form previews the recipient watermark.
