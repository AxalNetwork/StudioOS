## D4705 — Studio Pipeline keyboard entry and creation recovery (#4705)

### Independent studio work

The studio board now exposes each startup name as a native button, preserving
card drag/drop and the existing detail sheet's non-drag stage actions. Vote
buttons have full accessible names, the comment has a label, and the local
Field primitive associates each label by wrapping its control.

Creation uses the existing shared Sheet at its supported 560px width. Focus
entry, trapping, Escape and return to the opener come from that primitive.
Failed creation and voting use fixed public copy and preserve the form/comment
and anonymity choice; their failures are announced as alerts. No raw server
message is rendered at either affected catch. No API or authorization changes.

### Evidence and limits

Mounted tests exercise the actual board and creation form. Chromium also
checks the real DOM at 1440px and 390px using
`frontend/tests/e2e/pipeline_4705.html`, an isolated Vite fixture with synthetic
API answers. The fixture is test-only and is not a production entry point.
The browser spec checks label-click focus, keyboard opening, failure recovery,
Tab containment, Escape, return focus and the existing stage-action buttons.
Run Vite and, from `frontend/`, run:

```sh
npx playwright test pipeline_accessibility_4705.spec.js --project=chromium
```

A measured **synthetic client-call baseline** from the mounted board:

| Cards | Board list calls | Current-account calls | Vote calls | Detail calls before opening |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 1 | 1 | 0 |
| 20 | 1 | 1 | 20 | 0 |

These are stubbed API method invocations, not HTTP traffic, D1 query counts or
production latency. They identify the per-card vote read but do not justify a
new bulk endpoint or a performance budget. No optimization was made.
