## D5609 — Measured-duration suite plans (#5609)

The full suite keeps its scripts, isolation and concurrency. `SHARDS` in
`scripts/test-drift-parts.mjs` is the only count source. Each suite is expanded
with Node's `fs.globSync`, packed longest first into the lightest part, with
path ties and part-index ties deterministic. Unknown files weigh that suite's
p90; without measurements all files weigh one. Both matrices consume names
from one generated plan, uploaded separately from job outputs. A missing plan,
wrong part names, or a missing, extra or repeated file fails before execution.
Commands are reconstructed from current package scripts, never trusted from
artifact command text. Rest retains `test:drift` order.

`plan` uses the suite's verified condition. Gate requires plan and suite success,
or the existing exact-commit queue verification on a push. Future-clock uses the
same generator and omits rest from its names. Its clock proof stays unchanged.

Verify-first evidence:

- Node 22.23.4: the focused fixture compares `globSync` results to actual
  `node --test` expansion; both execute every fixture exactly once.
- [GitHub output limits](https://github.com/github/docs/blob/031381abe29946cf44184fa9e1face7be85b4951/data/reusables/actions/output-limitations.md):
  1 MB/job and 50 MB/workflow, approximated as UTF-16. Names are under 1 KiB;
  file lists travel in the suite-plan artifact.
- [Cross-run artifacts](https://docs.github.com/en/actions/tutorials/store-and-share-data)
  require authentication and a run identifier. The jobs use `actions: read`
  and the REST artifact ID to download the newest unexpired main `test-deps-*`
  archive. No matching artifact/API access means equal weights. Malformed JSON
  fails plan generation. Only `test-timings.json` is extracted.
