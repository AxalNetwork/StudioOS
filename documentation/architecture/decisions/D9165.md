## D9165 — The Stripe webhook fulfilment test seeds production's schema and runs in CI (#9165)

**What was wrong.** `cloudflare-worker/test/billing_webhook_fulfilment.test.mjs`
boots the real Worker with wrangler `unstable_dev` against a local D1 and
replays Stripe events: no double grant on a replayed checkout, out-of-order
subscription events, a delete scoped to one subscription, and the founder-tier
and investor pipes. Both tests are skipped unless `RUN_BILLING_WEBHOOK_TEST` is
set, and nothing set it. While nothing ran them, the seed broke. It applied
`schema_baseline.sql` and then 011, 027, 103, 097 and 691 again, though the
baseline already holds the first four. The first `ALTER` failed with
"duplicate column name" (D1 reports "too many columns": `users` is at D1's
100-column limit). The boot also read the root `wrangler.toml`, whose
`[assets]` directory `docs/` is no longer committed (D529).

**What was decided.**

- The seed is the schema production has, nothing more. That is
  `schema_baseline.sql` plus every migration above `BASELINE_CUTOFF`, the set
  `scripts/migrate-d1.mjs --bootstrap` and a later plain run apply. It is built
  once per checkout by `cloudflare-worker/test/_schema_once.mjs` (D4133). The
  test writes that build out as one SQL file (tables, their rows through
  sqlite's `quote()`, then indexes, views and triggers, with foreign keys
  deferred) and runs one `wrangler d1 execute --file`. It does not spawn
  wrangler once for each of the ~800 migrations. It seeds once per file, and
  each test copies the seeded state.
- The boot points the assets binding at an empty directory of its own, so the
  test does not depend on a frontend build.
- With the variable set, a missing wrangler fails the test instead of skipping
  it.
- The replay invariant also sends the same event id twice and expects the
  receipt's `duplicate: true`. It then sends a new id for the same user, which
  the `user_id` upsert must absorb.
- `.github/workflows/billing-webhook-contracts.yml` sets
  `RUN_BILLING_WEBHOOK_TEST=1` and runs the file. It runs on ready pull requests
  that touch `routes/billing*.ts`, `services/stripe*.ts`,
  `services/planSubscription.ts`, `services/financialEvents.ts`, the billing
  webhook tests or `_schema_once.mjs`. Drafts skip it (#6461).
  `cloudflare-worker/test/billing_webhook_ci_9165.test.mjs` (in `test:worker`)
  fails if no workflow step sets the variable and runs the file on those pull
  requests, or if the test stops gating on that variable name.

**Not built.** No nightly run. A schema change that breaks the seed without
touching those paths shows up on the next billing pull request, not the next
morning. #8512 (one delivery proved end to end against Stripe) stays open.

**Verified.** Both tests pass locally with the variable set (about 110 s with
the schema cached, plus about 90 s for a cold schema build). Mutations:
removing the MI Pro checkout's `ON CONFLICT(user_id)` upsert fails the test
(503 on the second checkout). So does dropping the receipt's duplicate return
together with the claim's `handled_at IS NULL`. Making the workflow set the
variable to `0`, dropping its `routes/billing*.ts` path, or renaming the gate
in the test fails the guard.
