## D4668 — Published-skill evaluations continue past the first 20 skills (#4668)

Part of #4531 (programme #4528). Coverage reporting #4536 and HQ's progress view #4537 read the metadata this adds; the deterministic CI wiring is #4532.

### The defect

`evaluatePublished` selected `agent_skills … ORDER BY id LIMIT 20` with no cursor, so every global press re-ran skills 1–20 and never reached a 21st. The bound is intended; the traversal was missing. `skill_eval_campaigns_d4668.test.ts` reproduces it: two global presses over 25 synthetic skills both run 1–20.

### The choice: an explicit, bounded manifest

A global evaluation is a **campaign** (migration `202611062149_skill_eval_campaigns.sql`). Its manifest is written when it starts: every eligible published Axal skill (`scope = 'hq'`, `status = 'published'`, `current_version >= 1`) at the version it had then, in id order. Each press runs the next ≤ 20 pending skills through the same per-skill evaluation the single-skill press uses (`evaluateSkill` in `services/agents/skillEval.ts`): no second engine, `runCase` through `run()` charged to the admin who pressed, the same `pass | fail | not_run` meanings, the same regression rule and its once-per-skill/version/case/model notice. A cursor alone was rejected: it cannot say how much remains, nor hold a version fixed across presses. With a manifest, `pending` is a known count.

### Semantics

- **Versions.** A skill runs only at the version in the manifest. If it was republished since the start it is skipped as `version_changed`, never evaluated at a version the campaign did not start with.
- **Eligibility, rechecked at its turn.** Retired, unpublished, non-Axal or suspended (`skillRunRefusal`) → skipped `not_eligible`. Its version unreadable → skipped `version_unreadable`. Skipped skills are listed with the reason, never run and never counted as passes.
- **Added skills.** A skill published after the start is not in the campaign; the next campaign takes it.
- **Case suite.** A skill's live cases (its starter case and HQ's) are read when its turn comes, and the response names each case run (`evaluated[].cases`). The case-suite semantics beyond that stay #4533's.
- **Models.** Fixed at the start (`models_json`). A press that names models on a campaign is refused 400 `models_fixed`. A model withdrawn since the start refuses the press 409 `models_unavailable`, until the campaign is cancelled and a new one started.
- **Idempotency.** Each skill, version, case and model is one item (`agent_skill_eval_campaign_items`, unique), written in the same D1 batch as its result row. A resumed press skips the items it finds, so finished work is neither run nor charged twice. A retry that is meant to run again is a new campaign: an explicit new attempt.
- **Interruptions.** A press that throws part-way leaves the skill it reached pending and releases its lease; the next press runs only the missing units. A 15-minute lease (`CAMPAIGN_LEASE_MS`) refuses a second press 409 `campaign_busy` while one runs.
- **Terminal states.** `complete` when nothing is pending, including an empty catalogue and an exact multiple of 20. `cancelled` is final: a press is refused 409 `campaign_cancelled` with the progress. A cancel between skills stops the batch at the next skill. Cancelling a complete campaign is refused 409 `campaign_complete`.
- **Authorization.** Every press, read and cancel is Super Admin only (`requireSuperAdmin`), checked each time; start, press and cancel each write the admin audit row.

### What did not change

`SKILLS_PER_RUN = 20`; the single-skill press (`uid`) and its response; the board; the regression notices and their deduplication; publication thresholds (`PASS_BAR`). The global response keeps `{ skills, results, regressions }` and adds `evaluated` and `campaign`.
