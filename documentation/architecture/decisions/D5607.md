## D5607 — Advisory landing policy for pull requests (#5607)

Part of #5600. `landing policy` is a non-required, read-only check. It checks out the event's base SHA, fetches the PR head without checking it out, and verifies that the fetched SHA matches the event. The base's classifier inspects the merge-base diff. Missing trusted code, a moved head, and ambiguous or unreadable diffs report T2. This includes the PR that first introduces the classifier. The summary names the base and head SHAs and the value of `LANDING_AUTO`. #5620 owns the later enforced check.

### Tiers

The highest tier wins across changed and previous paths. T0 covers documentation, added test files and leaf components, icons or styles. T1 covers ordinary routes, services and pages. All unmatched paths are T2.

T2 explicitly protects `cloudflare-worker/sql/**`, `cloudflare-worker/src/middleware/**`, `**/.github/**`, `**/scripts/**`, `**/merge-control/**`, `**/attached_assets/**`, `**/package*.json`, lockfiles, `**/wrangler*.toml`, `AGENTS.md`, `CLAUDE.md` and `CODEOWNERS`. The case-insensitive path-name rule also covers auth, sessions, permissions, tenancy, billing, money, payments, Stripe, entitlements, pricing, subscriptions, cap tables, fund fees, remittances, valuations, sign-in, MFA, OAuth, access control and legal templates. A revert touching a protected path remains T2.

Existing test edits and fixtures default to T2. The check identifies deleted and renamed tests, added skip/todo/only markers, net decreases in test or assertion calls, edits to shard counts, baselines, ledgers and timeouts, and introduced links or submodules. These are conservative diff heuristics and do not attest that tests or semantics are unchanged.

### GitHub behavior and owner activation

- GitHub does not merge drafts. Agents mark the PR ready before requesting auto-merge. The API behavior of attempting to enable auto-merge while still draft was not exercised in a live repository. [GitHub draft pull requests](https://docs.github.com/en/pull-requests/reference/pull-requests#draft-pull-requests)
- The public branch rules reported `SQUASH` for the merge queue. GitHub CLI v2.103.3 warns that the queue chooses the strategy when `--squash` is explicit, and passes `--match-head-commit` as the expected head SHA to the auto-merge mutation. [CLI queue behavior](https://github.com/cli/cli/blob/v2.103.3/pkg/cmd/pr/merge/merge.go) · [CLI mutation](https://github.com/cli/cli/blob/v2.103.3/pkg/cmd/pr/merge/http.go)
- GitHub disables auto-merge when a push comes from a user without write access. A write-authorized push can leave it enabled. Agents disable auto-merge and dequeue before pushing to keep the decision bound to the reviewed SHA. [GitHub auto-merge behavior](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/automatically-merging-a-pull-request)
- `ready_for_review` is explicitly in `pr-preview.yml` and `claude-review.yml`. It is outside the default `pull_request` activity types used by `ci.yml`. [GitHub workflow events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request)

The owner activates this after #5605 rows 3 and 6 and verified queue admission under #5500. The agent verifies the required checks, queue rule, tier, switch and exact head. It also checks that the PR does not alter the reporting workflow itself before relying on a check produced by a `pull_request` workflow. T2 needs the owner. This decision changes neither settings nor check requirements.
