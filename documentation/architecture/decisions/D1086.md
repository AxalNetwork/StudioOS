### 1. What a founder picks (`notion_sources`)

One row per venture, module and Notion id: a `page`, a `page_tree` (a page and the pages directly under it) or a `database`. The founder picks it on the Notion connector page. The kinds a module takes, and the fields a database may map to, are one entry per module in `services/notion/modules.ts` (`NOTION_MODULES`), following #2405's module map:

| Module | Section | Takes | Lands as |
|---|---|---|---|
| Customer research | validate | page, page tree, database | proposal `interview` |
| Market intelligence | validate | page tree | fact (title and link) |
| Product roadmap | build | database | fact |
| Prototype / MVP | build | database | fact |
| Solution design | build | page, page tree | proposal `design_note` |
| Capital relationships | raise | database | proposal `prospect` |
| Data room | raise | page, page tree | proposal `data_room_snapshot` |
| Distribution | grow | database | fact |
| Product improvement | grow | database | fact (with a default source) |

A choice field's values are the store's own, never a new list: `roadmap_okrs.kanban_status` (now, next, later, done), `progress.ts` `MVP_STATUSES`, `contacts.ts` `RAISE_STAGES`, and the Grow stores of migration 443. A test reads each of those files and holds the lists to them.

`status = 'removed'` is Stop using: Axal VC never reads the source again. The rows already read stay in their module, and pending proposals from it are deleted. `last_result` and `last_counts_json` are the last founder-pressed sync's outcome, as counts only.

### 2. The field map

`{ fields: { <field>: { property, values? } }, default_source? }`. It is checked twice:

- against the module (`cleanFieldMap`): a field the module lacks, a property name missing or over 200 characters, values on a non-choice field or onto a value outside the store's list, a required field left unmapped, or a default source outside the list are each refused with a code and the field. Nothing is dropped. A page or page tree is never mapped (`map_not_supported`).
- against the database's own schema (`checkAgainstSchema`), when a source is saved or remapped and on every preview: a property the database does not have is refused (`unknown_property`).

`mapRow` maps one row. A required field that is empty skips the row (`empty_required`). So does a date or number that is not one (`bad_value`). A choice outside the map is left empty, never forced onto a value. A skipped row is named by its reason and field, never by its text.

### 3. The sync (`services/notion/sync.ts`)

`syncSection` runs when the founder presses Sync from Notion. There is no schedule. It reads only that section's active sources of the venture, for the caller's own connection.

- **The budget.** Twenty Notion requests per press (`REQUEST_BUDGET`). A spent budget stores a cursor in KV (`RATE_LIMITS`, key `notion:sync:<integration>:<project>:<section>`, TTL 900 s, at least the 60 s KV allows). The cursor holds the source, its next page of rows or next child, and the sources already done. The press answers `partial: true, more: true`, and the next press resumes there. A finished sync deletes the cursor.
- **Facts, through the ledger.** Each fact lands through its module's writer (`registerFactWriter`) with a `connector_fed_items` row of kind `notion_fact`. The external id is `notion:<project>:<module>:<notion id>`.
  - A known, linked row is updated.
  - A row the founder deleted keeps its ledger row with no `local_id`, so it stays deleted (`kept_deleted`). A row deleted outside Notion's Delete is found by the writer's `alive` and unlinked the same way.
  - For `roadmap_okrs` and `mvp_features`, a row is written only when `integrations/fedOwnership.ts` says this connection owns it (`ledgerOwnerOf`). One owner per row: a row GitHub or another connection fed is left alone (`owned_elsewhere`).
- **Proposals, by fingerprint.** A proposal is an item that creates a person record, is shared outside the team, or turns free text into a structured record. It waits in `notion_proposals` for Accept.
  - Its fingerprint is the SHA-256 of what it says now.
  - The same fingerprint leaves the row alone, whatever its status, so a dismissed one stays dismissed.
  - A changed fingerprint puts it back to `pending` with `changed = 1` ("Changed in Notion").
  - Accept runs the kind's acceptor (`registerAcceptor`) and records where it landed. With no acceptor registered, Accept answers 409 `not_ready`.
- **Outcomes.**
  - A source Notion will not open is `unreadable` with its `NotionReadError` code, and the other sources still sync.
  - Skipped rows make a source `partial`, with each reason, field and count.
  - Logs hold the section, counts and outcomes only.

### 4. Routes (`routes/notion.ts`)

`/api/connectors/notion` (mounted ahead of the integrations router):

| Route | What it does |
|---|---|
| `GET /search?project&q` | Titles, kinds, ids and links of what the founder shared. `q` ≤ 100 characters. |
| `GET /sources?project` | The caller's active sources. `connected: false` with no Notion. |
| `POST /sources` | `{ project, module, kind, notion_id, field_map?, default_source? }`. Notion is asked what the id is: the title, the link and the schema come from Notion, never from the browser. Upserts on the unique key; a removed source comes back active. |
| `GET /sources/:uid/schema` | The database's properties, the module's fields, its default sources. |
| `PATCH /sources/:uid` | `{ field_map }`, checked against the module and the schema. |
| `DELETE /sources/:uid` | Stop using. |
| `GET /sources/:uid/preview?map=` | The first five rows as they would land, and every skipped row by number. `map` ≤ 8000 characters. `stored: false`: it writes nothing. |

`/api/cycles` (mounted ahead of the section routers):

| Route | What it does |
|---|---|
| `GET /:section/notion?project&module` | Anyone who can read the venture. Sources, the facts with their values from the writer's `view`, how many rows stay deleted, pending and dismissed proposals, `connected`, `can_sync` and `writer_ready`. |
| `POST /:section/notion/sync` | `{ project }`. |
| `POST /:section/notion/proposals/:id/accept`, `/dismiss` | `{ project }`. |
| `DELETE /:section/notion/facts/:ledgerId?project` | The row goes through its writer's `remove`. The ledger keeps the item with no row. |

**Who may.** Every write, search, preview and sync passes three checks:

- **the owner:** the caller's own active Notion row; nobody else's is read.
- **the venture:** write access, and never an admin acting for one.
- **the company:** a venture with a company, with this Notion switched on for that company (`projectEnabled`).

A support session (an impersonated JWT) is refused with 403 `support_session_refused`. Each refusal is a code and a sentence, and never echoes a title, a value or a property name.

### 5. The SPA

- **The Sources section** (`pages/account/NotionSourcesSection.jsx`), in Your connection's provider slot on `/account/connectors/notion`, as GitHub's Repositories:
  - "Pages you shared · N pages · M ventures", with Name, Kind, Venture, Module, Last read and Stop using;
  - Stop using asks first in an in-page dialog;
  - a phone draws a stacked list;
  - the states: loading, "Share pages with Axal VC" when empty, and Unreadable with Try again.
- **Add a source,** in two steps.
  1. A venture, a module and a search. A result the module cannot take is not offered, and a page is saved at once.
  2. For a database, Map properties: a property for each field, or "Don't use"; a property named as the field is preselected, nothing else is guessed; for a choice field, which Notion value means each of the store's values. Preview shows five rows, and each skipped property says how many rows and which ("The Date property has 3 rows that are not dates. They will be skipped." / "Rows 4, 9 and 13 …"). Use this mapping saves it.
- **From Notion** (`pages/cycles/FromNotion.jsx`), shared by every module Notion feeds:
  - the source line "“Roadmap 2027” · From Notion, as of 2026-10-21", with Open in Notion, Choose from Notion and Sync from Notion;
  - a fact module's rows, with Delete asked first ("It stays deleted when you sync again." / "“Roadmap 2027” in Notion is not changed.") and the footer ("2 rows you deleted stay deleted. The “—” under Progress means …");
  - a proposal module's items, with Accept, Dismiss and "Changed in Notion";
  - the states: loading; empty; not connected; partly synced ("Partly synced: 4 of 6 rows read.", with the rows not read and Sync again); unreadable ("We could not read “Roadmap 2027”.", the rows read kept below, Choose again); a spent budget; and a read that failed, with Try again;
  - on a phone, collapsed to "Roadmap 2027 · 6 rows · as of …".

  Only the person whose Notion it is sees Sync, Delete, Accept and Dismiss. Anyone else who can open the venture reads.
- The client is `lib/api/notion.js` (`notionApi`), one line in `api.js`.
