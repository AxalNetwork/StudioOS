### What a Research Project is

One stored object that keeps a question together with its evidence (Library documents, directly or through D549 collections), its Ask sessions and answers, and later its findings, comparisons and sectioned brief. It belongs to one member and is never shared in this issue.

### Built (part 1, 2026-11-09)

1. **Worker first: the store.**
   - `research_projects` holds the owner, title, question, objective, scope, exclusions, status and timestamps.
   - Status is `in_progress`, `complete` or `archived`. `archived_at` is set exactly when the status is `archived`, and a CHECK holds the pair together, so an archive date is never inferred.
   - Four link tables name rows the owner already has: `research_project_documents`, `research_project_collections`, `research_project_sessions` and `research_project_answers`. Deleting the document, collection, session or answer removes its link (CASCADE), never the project.
2. **Worker routes** (`routes/research_projects.ts`, mounted at `/api/research/projects` through the #4105 registry):
   - `GET /` lists the caller's projects (`?status=active|archived|all`) with counts of their links and the number archived. Evidence is counted once per document, whichever route it came by.
   - `POST /` creates a project. The question is required; the title defaults to the question, cut at a word.
   - `GET /:uid` reads one: the project, its evidence with the Library's own index state and `in_ask`, where each source came from, passages used, its collections, sessions and answers.
   - `PATCH /:uid` edits the text fields (null clears an optional one) and sets `in_progress` or `complete`.
   - `POST /:uid/archive` and `POST /:uid/restore`. An archived project is read-only (409 `project_archived`) until restored.
   - `POST` and `DELETE /:uid/{documents,collections,sessions,answers}` attach and detach. Only the caller's own row may be linked; another owner's is a 404, like a row that does not exist.
   - Every write leaves an audit receipt (`research_project_*`).
3. **Client:** `frontend/src/lib/api/researchProjects.js`, in the generated index.
4. **My Research** (`/research/projects`), the first zone of the founder shell's Research row:
   - project cards, newest touched first, under Active and Archived;
   - the New research form (question first, optional title, objective, scope and exclusions);
   - RS-11's empty state, "No research yet", with New research;
   - an unreadable list says so with Retry, never as an empty list;
   - Restore on an archived card.
5. **The workspace** (`/research/projects/:uid`, `/research/projects/:uid/evidence`):
   - the project bar: title, status, Saved, the number of sources, Archive (or Restore);
   - five tabs, of which Overview and Evidence are built;
   - **Overview:** objective, question, scope and exclusions with Edit (unwritten fields read Not recorded); Progress as "N of M evidence sources answerable in Ask"; the Ask history kept with the project; Most recent findings reads Not recorded with its reason;
   - **Evidence:** per source its origin, year, kind, owner, index state and In Ask as two pills, passages used, and the failure reason with Open Library. Add evidence picks Library documents and collections. Remove takes a source out of the project only;
   - **Archive** runs through Scope → Review → Result in the page, using Security's `ActionDialog` (D4801): what stays, then the confirmation, then the result.
6. **RS-01 Overview:** Recent research projects reads the store (the newest three active projects). New research opens My Research's form, carrying any question already typed.

### Departures from the canvas

- **Key questions are not stored,** so the Overview draws no "2 of 5 key questions answered" and no progress bar on the cards. Progress shows the one fraction the store does hold: answerable evidence.
- **Findings, Comparisons and Brief tabs are not links.** Their stores come in later parts; the tabs say so on hover.
- **The project bar's Compare and Produce brief are not built.** Add evidence is the one violet primary until the brief exists.
- **Project type ("Market", "Funds · Global") is not stored.** The canvas draws it in the bar and on cards; it is not in the issue's field list, and no form on the canvas sets it.
- **Evidence columns:** the canvas's Date is the document's date. The Library records a source year, so the column is Year. Publisher is not recorded per document and is not a column; Owner is always "You", because sharing is out of scope.
- **Passages used** counts the citations of the project's Ask answers (linked one by one, or in a linked session) that name the document. A citation stored before citations carried `document_uid` is counted as unattributed and said so under the table, not dropped and not guessed.
- **Removing a source is immediate,** not Scope → Review → Result: it only unlinks, the document stays in the Library, and adding it back is one press. Archive, which changes what the project is, goes through the three steps.
- **Start research still asks Ask.** Creating a project from the desk is New research; folding the question box into project creation waits for the Ask part, which links sessions to a project.
- **My Research is in the founder shell only,** the shell the canvas draws. Its routes admit the founder and an admin; the investor, advisor and partner shells would each need the zone first (`route_role_zone_contract.test.mjs`).
