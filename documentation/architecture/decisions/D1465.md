## D1465 — Read with a reason, the Worker: end a narrative read early, and the venture before the reason (#4020, migration 761)

- **Status:** built by the S33 session in slot S05, 2026-11-01. Part of #3713. Closes #4020: the Worker part, and the page line once S21's `ReasonGate` (D1463) reached `main`.
- **Basis:** `origin/main` at `6bf4aea666`; S1's specification on #3713 ("Worker gaps" G1 and G2), which put this part in D1463 with migration 701. S21 moved it here: D1463 is the frontend, 701 was out of sequence (`main` is at 759, and #4019 holds 760), and D1465 was free.
- **Migration:** 761 (`761_narrative_read_end.sql`), additive: `narrative_read_reasons.ended_at TEXT`. Not idempotent (SQLite has no `ADD COLUMN IF NOT EXISTS`): the ledger applies it once, and the baseline runner marks it without executing it.

### G1: an admin ends their narrative read early (RR05, RR07)

- `DELETE /api/cycles/raise/narrative/reads/mine?project=` (an admin only), a literal path registered before `/narrative/:version`:
  - in one `batch`: `ended_at = datetime('now')` on the caller's live row, and a `narrative_read_ended` activity row that carries no reason words ("An admin ended their narrative read", or "HQ ended their narrative read");
  - answers `200 { read }`, with `ended_at`;
  - refuses 403 `admins_only` for anyone else, 404 `no_open_read` when nothing of theirs is live, and 503 `read_log_unreadable` when the log cannot be read or written; then nothing ends.
- `activeReason` admits a read only while it is unexpired **and** `ended_at IS NULL`, so the next narrative read after an end answers 403 `read_reason_required`. Another admin's live read is untouched.
- The founder's list (`GET /narrative/reads`) keeps the row, with `ended_at`; the page shows "Ended early" from it.

### G2: the venture before the reason

`GET /narrative/reads` adds `venture: { id, name, logo_url, founder_name }`:
- `name` and `logo_url` come from `projects`;
- `founder_name` comes from `users` only when exactly one active founder user holds the venture's `founder_id`, else null, so the page draws no founder line rather than a guess;
- it uses bound SQL only and reads no narrative content, so it stays outside `narrativeScope`.

### The client

`narrativeEndRead(projectId)` in `frontend/src/lib/api/narrative.js` (the drift guard needs the client and the route together). `NarrativeAdminGate` (`frontend/src/pages/raise/narrative/NarrativeAdmin.jsx`) passes `onEnd` to D1463's `AccessBanner`: End access now asks first (RR05), calls `narrativeEndRead`, then re-reads, so the gate returns for a new reason. A refused end keeps the read open under the banner's "could not be ended" line. `frontend/test/narrative_admin_d914.test.mjs` holds both.
