## D4120 — SkillEnergy: a skill's coded energy image, and one table of area tokens (#4120)

Issue #4120 (Roster R4, part of #4116), slot S13, 2026-11-02. No migration and
no Worker change.

**Context.** The owner asked for coded visuals for skill cards, not generated
images. The SkillEnergy canvas (Claude Design, published 2026-11-02, linked from
#4120's S1 comment) draws them as live SVG from one generator,
`skillEnergy({ slug, area, level, size, theme })`, in three styles. The owner
picked **style B, radiating rays** (2026-11-02): the rays point at the area's
angle on the 8-axis radar, so the direction still reads at 48 px.

### What was decided

1. **The generator is ported, not redrawn.** `frontend/src/ui/skillEnergyModel.js`
   is the canvas's style-B branch, line for line: the FNV-1a hash of the slug
   seeds a mulberry32 generator; the ray count, opacity, width, layers and glow
   follow the level (EN6's density curve); strokes are scaled per pixel so 48,
   96 and 160 px stay crisp. `skillEnergySvg` returns the same bytes the canvas
   returns, and the test holds every EN2 cell (8 areas × 5 levels × light and
   dark) to the canvas's own output by hash.
2. **Two departures, both for determinism.** Only style B is kept. The canvas
   numbered its element ids per call, so two renders of one input differed;
   here the ids take the theme and a caller's suffix (`useId` in the
   component), so the same input always gives the same SVG and two copies on
   one page never share a clip or gradient id.
3. **One table of area tokens.** `frontend/src/lib/skillAreas.js` holds EN6's 8
   areas (radar slug, angle, hue family, light and dark hex, stroke rhythm) and
   the 5 levels. It is in `SKILL_AXIS_ORDER`, or it throws at load. Three
   things read it, so an area is one colour everywhere:
   - **SkillEnergy** (`frontend/src/ui/SkillEnergy.jsx`);
   - **the area chips** on Team › Skills: the category filter row and each
     skill's taxonomy chips carry the area's dot (`AreaDot`);
   - **the SkillRadar's axis labels**, each in its area's token
     (`AreaTick`). Every token is at least 4.5:1 on its background (light on
     #ffffff, dark on #111827), so a token can colour text.
4. **Theme.** The tokens reach an element as CSS variables (`areaVars`) beside
   literal `dark:` classes, so the app's `.dark` class switches them.
   SkillEnergy's default `theme="auto"` draws the light and the dark picture
   and shows one by the same class; `theme="light"` or `"dark"` draws one.
5. **Decorative.** `aria-hidden`, `focusable="false"`, no text, title or
   description inside: the card carries the skill's name, area and level.
   Still by default; `motion` adds EN5's 6 s drift, which stops under
   `prefers-reduced-motion`.
6. **Where it shows.** The SK1 skill card draws its skill's image at 96 px,
   from the skill's slug and its first taxonomy tag that has both an area and a
   level (`energyOf`). A skill with no such tag draws no image, never a
   made-up area.

### Not built here

- **The SK0 area tile and the 48 px chip of EN4.** Team › Skills has no area
  tile or skill chip yet. They take `<SkillEnergy size={160} />` and
  `size={48}` when their screens land (#4116, #3952).
- **The canvas's agent values.** S1 noted the canvas shows the older 8-value
  list; SkillEnergy draws no values, so nothing here uses either list.
- **The canvas file in `design/incoming/`.** S21 does the intake.

### Verified

`frontend/test/skill_energy_d4120.test.mjs`, 11 tests:
- **Tokens:** the radar's order, 45° apart; 8 distinct hue families, at least
  15° apart in OKLCH hue in both themes; 8 distinct stroke rhythms; every token
  at least 4.5:1 on its background.
- **Generator:** deterministic; each of slug, area and level changes the
  picture; EN3's six Finance skills are six pictures; every EN2 cell hashes to
  the canvas's (`frontend/test/fixtures/skill_energy_en2.mjs`).
- **Direction and density:** the longest ray points within 25° of the area's
  angle at all three sizes, and each level draws more than the one below.
- **Decorative:** `aria-hidden`, no text, still by default, and motion off
  under reduced motion.
- **Component:** both themes, no shared ids within one image or across two
  copies, one theme when asked, an unknown size at 96.
- **Wiring:** the card's image from its tag, and none without one; the chip
  dot; the radar label's tokens.

`agent_skills_d1612.test.mjs` still passes unchanged.
