## D5570 — Workspace placement, cost quotes and compute admission leases, pure and unmounted (#5570)

**Status:** part 1 of #5570: pure modules only. There is no D1 table, route, mount, Durable Object binding, `wrangler.toml` change or account change. The owner set this split on #5570 (2026-11-13). Pure modules come first. The Durable Object binding and the reserve/settle wiring through the existing holds follow in part 2. Both modules build on the merged D5565 contract (`WorkspaceSpec`, `ExecutorCapabilities` and `executorEligibility` in `workspaceSpec.ts`) and define no second spec.

### Placement (`cloudflare-worker/src/services/agents/workspacePlacement.ts`)

`judgeCandidate` checks one provider in #5570's mandatory order. The first stage that fails gives the reason code:

| # | Stage | Reason | What it reads |
| - | ----- | ------ | ------------- |
| 1 | Consent | `consent` | The provider is in the spec's `allowed_providers` **and** in the tenant's standing consent |
| 2 | Residency | `residency` | The spec's `allowed_regions`, the tenant's residency regions and the provider's `enforced_regions` share a region |
| 3 | Security capability | `security` (`cancel`, `network_policy`, `shell`, `hostile_code_isolation`) | Interrupt, the enforced network mode, shell, untrusted-code isolation |
| 4 | Image and runtime | `image_runtime` (`image_digest`, `workload_class`, `checkpoint_restore`) | Digest pulls, the workload class, checkpoint restore when the spec resumes one |
| 5 | Workload needs | `workload` (`cpu`, `memory`, `disk`, `duration`) | The spec's cpu, memory_mb, disk_mb and max_duration_s against the provider's maxima |
| 6 | Health, then quota | `health`, `quota_unverified`, `quota_exhausted` | Only `healthy` places. Capacity that was never read, or a missing `concurrency_max`, is unverified, not free |

After stage 6, D5565's `executorEligibility` must also accept the candidate over the resident regions. The contract stays the authority, and this filter only orders its checks. Last comes the budget: a known quote above the spec's `max_cost_microusd` is `over_budget`.

`WorkspaceSpec` has no GPU request, so no candidate is judged on GPU. Adding one is a contract change (D5565). It is not in scope here.

**Ranking.** Cloudflare comes first whenever it is eligible. The rest are ranked by known expected cost (lower first), then latency (lower first), then cache locality, then free capacity in the region (more first). An unknown value always sorts after a known one.

**Outcome.**
- `place` carries the provider, the region, the quote and the reserve.
- `queue` is returned only when at least one candidate is held back by health or quota alone. Those can clear.
- Any other outcome is `refuse` (422 `no_eligible_provider`), with every candidate's reason.
- A halted tenant policy (the kill switch) refuses with 503 `placement_halted`.

There is no automatic fallback outside the providers and regions that both the spec and the tenant allow. If Cloudflare is out of quota and nothing else is allowed, the task waits. It does not move to a provider or region that would change residency or customer policy.

**Cost model.** A quote has six categories: compute (vCPU-seconds plus GiB-seconds), boot, storage (disk GiB-seconds), image pull (cold or cached), egress and idle allocation. Each line is integer micro-USD, rounded up because it is an upper bound, or `unavailable`.

The figures come from a broker-owned `RateCard` per provider. A `null` rate makes its line `unavailable`. A missing card, or a card for another provider, makes every line `unavailable` (source `none`). Egress is a known 0 under a `deny` network policy. Under an allowlist it is `unavailable`, because the spec carries no egress bound. One unavailable line makes the total `unavailable`.

An unknown is never written as 0. The reserve is the known total, or the spec's `max_cost_microusd` (`reserve_basis: 'spec_ceiling'`) when the total is unavailable. The spec's ceiling and resources are the quota and the upper bound; there is no second place for them.

`dryRunQuote` runs the same judgement and returns every candidate's per-category quote and the upper bound. It reserves nothing.

### Admission (`cloudflare-worker/src/services/agents/workspaceAdmission.ts`)

`createAdmissionControl({ store, clock, limits, observe })` takes four injected parts:
- `store`: one transactional store. Part 2 backs it with a Durable Object's storage transaction. Tests use a serialized memory store. No read-then-insert happens outside a transaction.
- `clock`: the time source. A clock that runs backwards is refused with `clock_regressed`.
- `limits`: the caps listed below.
- `observe`: reads the provider's actual state, outside any transaction.

**Keyed by the engine's run uid.** This follows the #7074 coordination note on #5570. `admitInScope` (`agents/engine.ts`) stays the one gate that decides whether a run exists. A lease is enqueued only for a run it admitted, under that run's uid. A retry with the same terms is idempotent. Different terms for the same uid are refused with `run_contract_changed`.

**Limits.**
- Per tenant: running runs and waiting runs (`tenant_queue_full`).
- Total waiting runs (`admission_queue_full`).
- Per provider and per `provider:region`. A provider or pair with no entry admits nothing.
- A halted control enqueues and admits nothing (`admission_halted`). Live leases can still renew, release and reconcile.

**Fair scheduling.** Each pick goes to the tenant holding the fewest slots, then to the earliest-queued run.

**Fencing.** Each admission bumps the run's generation. `renew`, `release` and `cancel` refuse a stale generation, and the reconcile write re-checks the generation and state it read.

**Reconcile before freeing a slot.** An expired lease becomes `reconciling` and **keeps its slot**. An admitted run that is cancelled does the same: the cancel is ambiguous until the provider confirms it. `reconcile()` reads the provider for each reconciling run, then applies what it read:
- `gone`: settles once and frees the slot.
- `running`: takes a fresh lease, unless a cancel is pending.
- `unknown`, or a reader that throws (a brownout): keeps holding.

If a late callback settles the run while the provider is being read, the reconcile write skips that run. A waiting run that is cancelled is `withdrawn` with no bill, because nothing ran.

**One logical bill.** Each lease is settled once. A repeated release, or a release after reconcile, returns the same bill with `first: false`, so part 2 settles its hold exactly once. Missing metrics charge the reserve and record `measured: false`. They are never charged as 0.

**Lane budget.** `computeReservation(agent_id)` sums the compute reserve of an agent's live leases; waiting runs hold none. Part 2 adds that sum beside `live * per_run_microusd` in `laneBudget` (`agents/capacity.ts`). Then a sub-agent lane cannot fit under the cap on tokens and overshoot it on compute. `engine.ts` and `capacity.ts` are not changed here.

**Planning.** `planning(registered_agents)` reports registered agents and simultaneous executions as separate numbers. Registered agents hold no capacity. A thousand registered agents is not a thousand containers. It also reports the simultaneous limit: each provider's cap, bounded by the sum of its regional caps. An unread agent count is `unavailable`, not 0.

### Tests

`cloudflare-worker/test/workspace_placement_5570.test.ts` has 15 tests. They use synthetic tenants, providers and rate cards, an injected clock and an injected provider-state reader, with no `setTimeout`. They cover:
- Cloudflare preferred and the ranking.
- Every stage's reason in the mandatory order.
- Fallback only to an allowed, consented, resident provider; otherwise queue or refuse.
- Unknown cost as `unavailable`, and the dry run.
- Concurrent claims plus a Worker restart over the same store.
- Provider and regional caps, fair scheduling and bounded waiting.
- Stale lease, brownout and lost callback, settled once.
- Missing metrics and a reconcile that races a callback.
- Ambiguous and waiting cancels.
- The lane-budget reservation, planning, halt and clock regression.

The mutation check (`node scripts/mutation-check.mjs run`) ran 26 mutations and the tests caught all 26, with 0 equivalent.
