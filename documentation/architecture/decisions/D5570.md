## D5570 — Workspace placement and admission leases, pure and unmounted (#5570)

**Status:** part 1 of #5570, the pure modules. Unmounted and disabled; no D1, route, binding, deployment or account change. Built on the merged D5565 contract (`workspaceSpec.ts`, `runnerProtocol.ts`). The owner chose this split on #5570 (2026-11-13): pure modules first; the Durable Object binding and the reserve/settle wiring through the existing holds follow in a second PR.

### Placement (`services/agents/workspacePlacement.ts`)

`placeWorkspace(spec, policy, candidates)` checks every candidate in #5570's order, and the first failed check is that candidate's reason:

1. **Consent.** The provider must be in the spec's `allowed_providers` **and** in the tenant's standing consent. Both are mandatory.
2. **Residency.** Only regions the spec, the tenant's residency policy and the provider all accept. A region outside them is never a fallback.
3. **Security, image/runtime and workload needs.** The merged D5565 `executorEligibility`, restricted to the resident regions. A missing capability is refused, never downgraded.
4. **Health, then quota.** Only a `healthy` provider places. Capacity that was never read is `quota_unverified`, not free.
5. **Budget.** A known quote over `max_cost_microusd` is `over_budget`.

Among the eligible candidates, Cloudflare comes first. The rest rank by known cost, then latency, then cache locality, then free capacity, and an unknown always sorts after a known.

The outcome is `place`, `queue` or `refuse`:
- `place` carries the reserve: the known quote, or the spec's ceiling when the quote is unavailable.
- `queue` happens only when a candidate that passed consent, residency and capability is held back by health or quota, which can clear.
- Anything else is `refuse` with each candidate's reason. A halted policy (the kill switch) refuses everything with `placement_halted`.

**Cost.** A quote has six lines: compute, boot, storage, image pull, egress and idle. Each is integer micro-USD or `unavailable`. One unavailable or malformed line makes the total `unavailable`. A missing figure is never read as 0.

### Admission (`services/agents/workspaceAdmission.ts`)

`createAdmissionControl({ store, clock, limits })` runs over one transactional store. A Durable Object's storage transaction is the intended host (part 2), and tests use a serializing memory store. There is no read-then-insert outside a transaction.

- **Limits.** Per-tenant running, per-tenant waiting, and per `provider:region` running. A pair with no limit admits nothing.
- **Fairness.** Each pick goes to the tenant holding the fewest slots, then to the earliest-queued run, so one tenant's backlog cannot starve another's single task.
- **Fencing.** Each admission bumps the run's generation. `renew`, `release` and `reconcile` refuse a stale generation.
- **Reconcile before freeing.** An expired lease moves to `reconciling` and **keeps its slot**. `reconcile` applies the provider's actual state:
  - `running` takes a fresh lease;
  - `gone` settles and frees the slot;
  - `unknown` keeps holding it.

  A lost callback or an ambiguous cancel therefore cannot oversubscribe.
- **Bill once.** Settlement is recorded once per admitted generation. A repeated release returns the same bill. Missing metrics charge the reserve and record `measured: false`, never 0.
- **Halt.** A halted control enqueues nothing and admits nothing.
- **Occupancy.** It reports executions holding capacity separately from registered agents. A thousand registered agents is not a thousand containers.

### Not in this part

The Durable Object class and its binding, the hand-off from `place` to the existing holds and settlement, metrics, alert thresholds, and the quota UI. No new task engine and no new AI usage ledger; part 2 wires the existing ones.

### Tests

`cloudflare-worker/test/workspace_placement_5570.test.ts` has nine tests on synthetic tenants and quotes, with an injected clock. They cover:
- Cloudflare preferred over a cheaper allowed provider.
- Fallback only to a consented, allowlisted provider in a resident region; otherwise queue.
- Refusal with each reason when nothing can ever run the spec; brownout queues.
- Unavailable cost ranks last and reserves the ceiling.
- Concurrent enqueue/admit and a restart that cannot oversubscribe.
- Fair scheduling and a full tenant queue.
- An expired lease held through `unknown` and freed only by `gone`.
- A stale generation refused, a repeated release billed once, and missing metrics charging the reserve.
- Halt, bad limits and a regressed clock refused.

Ten source mutations each fail a test: no Cloudflare preference, no tenant consent, no residency filter, unknown cost as 0, never queue, an expired lease freeing its slot, FIFO instead of fair, missing metrics billed as 0, a non-idempotent repeat release, and no generation fence.

### Rollback

Delete the two modules and the test. Nothing imports them.
