## D4708 — HQ Security: the Worker's reads in their own modules, and one shared contract (#4708)

- **Status:** part 1 of #4708 (HQ Security audit 6/6), a behaviour-preserving refactor. Not deployed.
- **Scope:** `/admin/security` and the Worker router behind it, `cloudflare-worker/src/routes/admin_security.ts`
  (mounted at `/api/admin/security` in `index.ts`, before the catch-all `/api/admin`; unchanged).
- **Builds on:** D4691 (one availability rule per part), D4699 and D4803 (the ledger's cursor and filters),
  D4800 (Security v2), D5247 (source freshness).

### What changed

The router was one 2,117-line file holding both the routing and the two large reads. The reads moved, as
written, into `cloudflare-worker/src/services/adminSecurity/`; the router (now about 790 lines) keeps every
route, every gate, every request parse and every act.

| Module | Owns |
| --- | --- |
| `routes/admin_security.ts` | The ten routes, each opening with its gate. `/overview` and `/governance` call the modules below; the session, support-session, force re-auth, branch sign-out and data-subject handlers are unchanged in place. It still exports `parseFeedQuery`, `trimToSecond`, `FEED_OUTCOMES`, `FEED_SOURCES` and `FeedQuery`. |
| `services/adminSecurity/overview.ts` | `loadSecurityOverview(env)`: the `/overview` payload, store by store, with `sources[]`. |
| `services/adminSecurity/aiSafety.ts` | `aiSafetyBlock`, the not-counted list, the window, and `GUARDRAILS_POINTER` for `/governance`. |
| `services/adminSecurity/governanceFeed.ts` | `loadGovernance(env, filter, query, now)` and `feedFilterOf`: the five stores' statements, the merge, the page and the reply. |
| `services/adminSecurity/feedQuery.ts` | `parseFeedQuery`, `storesFor`, the binds, `trimToSecond`. |
| `services/adminSecurity/feedFormat.ts` | Row wording shared by the feed and the Data access zone. |
| `services/adminSecurity/dataAccess.ts` | `loadDataAccess`: the Data access zone's two halves. |
| `services/adminSecurity/contract.ts` | The Worker's import of the shared contract, and its type-level check. |

No route path, method, gate, status code, response key, response text, audit write or statement changed.
The statements are the same literals in the same order; the reads run in the same order.

### The shared contract

`frontend/src/lib/securityContract.js` (typed by `securityContract.d.ts`) names, once, what both sides
already used: the availability shape (`absent`, `isUnavailable`), the account and support session status
words, the ledger's outcome list, a session revoke's per-row outcomes, a deployment's and a whole act's
outcomes, a data-subject close's statuses, and the page's words for what a write answered.

It is a plain module under `frontend/src/lib/` because that is how this repo already shares code between the
SPA and the Worker (`money.js` and its `.d.ts`, D5029; `ogRegistry.js`): the Worker imports it by relative
path. `cloudflare-worker/src/contracts/` was considered and not used: it holds JSON Schemas of deck replies
for `test:drift`, which the Worker never loads, and a status vocabulary is not a reply schema.

The Worker reads availability and the outcome list from it (`overview.ts`, `dataAccess.ts`, `feedQuery.ts`,
the router), and the Security page's AI Safety model reads `isUnavailable` from it. Where a service still
declares its own union (`sessionStatus.ts`, `userSessions.ts`, `emergencyScope.ts`, `dsrRequests.ts`),
`contract.ts`'s `CONTRACT_HOLDS` fails the Worker typecheck if the two drift. Those services were not edited:
the session and support-session code is under review in #4669 and this part does not touch it.

### Proof the behaviour is unchanged

- `cloudflare-worker/test/admin_security_routes_d4708.test.ts` pins the router's route table (method, path,
  order) and each handler's opening gate to what `main` had, and the mount in `index.ts`. Dropping a route,
  renaming one or swapping a write gate for the read gate each fails it.
- `cloudflare-worker/test/admin_security_contract_d4708.test.ts` pins the contract's values to its types, to
  the services' runtime lists and to the page's models.
- Every existing Worker and frontend test that reads this router or the Security page passes unchanged in what
  it asserts. Tests that read the router's source text now read the desk's files together
  (`cloudflare-worker/test/_admin_security_source.mjs`), so each pin follows the code it pinned.
