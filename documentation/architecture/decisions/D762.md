## D762 — Members pay the billed price, each run records its charge beside its cost, and HQ's token margin counts top-up spend only

- **Status:** decided by the owner in #1874's plan (§3 and §4; the plan's D725), filed by S1 as #2019 (task A3 of D720). This file was written by the task's first PR.
- **Basis:** `origin/main` at `a1a8837`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D629 and D640 (the allowance, the top-up balance, the hold and the review), D755 (the token ledger, migration 486) and D760 (the catalogue and the pricing module, #2017).
- **Read by:** D763 (the guard writes `guard_for`), D764 (the matrix passes the quote its chain), D765 (the run path writes the rail fields) and D776 (the HQ screens read the margin).

### 1. The decision

A member pays the billed price for an AI run. While `AI_BILLING` is unset that is Cloudflare's cost; once the owner sets `AI_BILLING = "charged"` it is cost × `AI_MARKUP` (D760's one constant, 1.25). The admin licence always pays cost. A run is paid from the member's allowance first, then their tokens, through D629's hold.

**Every run records its charge beside its cost.** `est_cost_usd` stays what the run cost Cloudflare. It is what the organisation cap, the KV spend buckets and the kill switch count, because Cloudflare's bill is what they protect. `charged_microusd` is what the member paid.

**HQ's token margin counts token spend only.** Allowance draws are already paid for by the plan's price.

Setting `AI_BILLING = "charged"` is the owner's (#1008, owner step 4), after the pricing copy is confirmed. This task ships with it unset, so nothing a member pays changes.

### 3. The log row (migration 493)

Seven nullable columns on `ai_usage_logs`, and one index on `(user_id, rail_page, created_at)`. Additive only; nothing is backfilled. `ensureLogSchema`'s CREATE carries the same columns (D158). A dev or test table made before 493 gains them the first time an INSERT names one it lacks (`addLogColumns493`), so a run there is still logged.

- **`charged_microusd`** is the amount the run's hold settled at.
  - It is 0 when nothing was charged: a refusal, a cached answer, a failed run, or a run with no hold (a system run).
  - It is NULL while a run that cost more than its hold waits for a Super Admin's decision (D640), because what it will be charged is not known yet. Every row from before 493 is NULL too, and the reads show it as "Not recorded".
- **`reservation_uid`** names the `ai_budget_reservations` hold that paid for the run. D755's ledger rows already carry the same uid (D755.md:181).
- **`rail_page`, `rail_option` and `record_ref`** are written when `RunOptions` carries `railPage`, `railOption` and `recordRef`. D765's run path passes them. Each is kept only if it is 1–160 characters of letters, digits and `/_.:-`; anything else is NULL.
- **`guard_for`** is the row a guard run checked. D763 writes it.
- **`units_json`** is the units the run was settled on, as the Worker measured them: the answering attempt's D761 `units` (#2018, PR 1: `tokens_in`, `tokens_cached`, `tokens_out`, `audio_minutes`), with `tokens_in` and `tokens_out` set to the counts the run was settled on. For a stream those are the counts read when it ended.

### 4. A streamed run

A streamed run used to settle its hold at once, on its prompt tokens only, and record `completion_tokens: 0`, because the router never saw the output. Now `meterStream` passes the provider's stream through unchanged and settles when it ends:
- on the provider's final usage, where a chunk carries `completion_tokens` above 0;
- otherwise on the output the Worker counted from the `response` deltas it passed on;
- never on 0 output.

A reader who stops early is settled on what they were sent. The settlement runs once, before the stream closes, so the Worker is still serving the response while it writes. A settlement that fails is logged, never thrown at the reader. A stream still open after five minutes finds its hold already released by D629's expiry, so it is charged nothing rather than twice.

### 5. The budget reads

- **`seedSpend`** seeds a new day's or month's allowance spend from the log. It reads `charged_microusd` where one is recorded, and `est_cost_usd` on an older row.
- **`month_reserved_microusd`** ("Held by runs in progress") also counts the allowance part of a hold still in review from an earlier month. That hold was added to its own month's spend row, never this one's, so this month's spend is unchanged. An earlier month's *pending* hold is not counted: it expires and returns on its own.

D755's ledger triggers and the reservation columns they read are untouched.

### 6. HQ Revenue's token line

`GET /api/admin/revenue/summary`'s `token_cost` keeps the quarter's cost, and gains the margin, all in micro-USD:
- **`topup_spend_microusd`:** the top-up part of every hold settled in the quarter (`actual_topup_microusd`);
- **`topup_cost_microusd`:** that spend's share of Cloudflare's cost (each run's cost × its top-up share of the hold);
- **`tokens_given_microusd`:** D755's bonus and adjustment entries, "Tokens given" (D755.md:345). They come off the margin and are never revenue;
- **`included_in_plans_microusd`:** allowance draws, at member prices, shown apart;
- **`margin_microusd`:** spend less its cost share, less tokens given.

Admin-licence runs are left out of all of it. A hold settled before migration 493 names no log row, so its cost share is unknown. It is counted in `runs_not_recorded` and left out of the margin. When every run in the quarter predates 493, the margin is null ("Not recorded"), never 0. If the holds or the ledger cannot be read, only the margin is marked unknown (`billed_available: false` with its reason); the cost still reads.

While `AI_BILLING` is unset, members pay cost, so token spend equals its cost share and the margin is minus the tokens given.

### 7. What this reverses in D629

D629.md:15 calls the micro-USD unit "an explicit precision extension to the cents convention, not a new price surcharge". That stays true while `AI_BILLING` is unset. Once the owner sets it to `charged`, members pay cost × `AI_MARKUP`, which is a surcharge on Cloudflare's price, and D629's sentence no longer holds for AI runs.
