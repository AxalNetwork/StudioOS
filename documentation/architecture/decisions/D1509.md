## D1509 — The Grid behind flags: `grid_generate`, one flag per element and per model, the beta cohort, and the dry run

- **Status:** Built by the S14 session (#3760, deck v2 A16, part of #3716; 2026-11-01).
- **Builds on:** D760 (the one catalogue, `isOffered`), D764 (`GET /api/ai/rail`), D1503 (#3754: element models, `resolveElementModel`, `elementModelFor`), D897 (New deck's routes), D1604 (#3885: the editor chrome, `deckV2Adapter`, the one-click run) and D1316 (the per-user `feature_flags` column, which members no longer write).
- **Migration:** **723** (`cloudflare-worker/sql/migrations/723_feature_flags.sql`).
- **Owner decision:** none. Each rollout step and exporting the production backup are the owner's, and are out of scope here.

### Why

The Grid ships first to HQ and an opt-in beta. HQ must also be able to switch off one model or one element for everyone without a deploy, and a model switched off must leave every chip within a minute. Before that ships, the owner needs a dry run over an exported backup that lists every place where a deck would draw differently.

### What was decided

1. **One table, three scopes.** Migration 723 adds `feature_flags(key, scope, scope_id, enabled, updated_by, updated_at)`. The spec's column `on` is `enabled`, because ON is an SQL keyword.
   - **Scopes and precedence.** A scope is `global`, `role` (`admin` is HQ) or `user`. The narrowest row wins: user, then role, then global.
   - **No row means on.** A flag is a switch HQ turns off, so the deploy changes nothing until someone writes a row.
   - **Keys.** A key is `grid_generate`, `element:<id>` (`elementModels.ELEMENTS`) or `model:<id>` (`catalogue.ts`; there is no second list).
2. **The 60 s cache** (`services/featureFlags.ts`).
   - All rows are read in one query and kept in KV (`TOKENS`, `feature_flags:v1`) for 60 s.
   - A write through `PUT /api/admin/feature-flags` deletes that key, so the write applies at once in its own isolate and within a minute everywhere.
   - A table that cannot be read (not migrated yet) reads as no rows: every flag stays at its default, the read is never a refusal, and nothing is cached.
3. **The beta cohort** starts on the per-user column `user_settings.feature_flags`. It is set by HQ; members cannot write it since D1316.
   - It answers only the beta keys, `grid_generate` and `element:*`, and only until a `user` row is written for that member.
   - It never turns on a model that is switched off: a model is off for a reason (cost, quality, a provider's hold).
4. **A model flag that is off.** The flag sets `CatalogueSwitches.MODELS_OFF`, so `catalogue.isOffered` refuses the model everywhere the catalogue is asked:
   - `GET /api/ai/rail`: `models`, `more` and every option's lists;
   - `GET /api/decks/:id/element-models`: every element's and group's `suggested`, `more` and `resolved`, which feed S1's AIRail groups (`deckRailGroups.js`) and the lightbox's read-only chip;
   - the run itself: `aiRouter.chooseModels`'s draw, speech and rail resolutions, and the route default, which gives way to the next model in its chain;
   - both pick routes, which answer 400 `model_not_offered`.

   A stored pick of a switched-off model is **kept, never cleared**: `resolveElementModel` skips it as `switched_off`. Both replies' `notice` reads aird5's "<Model C> is unavailable. Using <Model B>.", and the pick runs again when the flag comes back.
5. **An element flag that is off.**
   - **Element-models reply.** The element reads `switched_on: false`, `reason: "Not switched on yet."`, with no models and no `resolved`. It also leaves its group's `elements`.
   - **Generation side.** `elementModelFor` throws `ElementOffError`:
     - a pick for that element answers 404 `not_switched_on`;
     - an image run answers 404 `not_switched_on`, which the adapter's `through` reports as "Not switched on yet." (never empty, never $0.00);
     - for New deck's build words (Body), the element is **cut from the plan before the quote**: the quote answers `ai: false`, `reason: not_switched_on`, and the build runs on the records only. No model is called and nothing is held, every card keeps its title, and no area is left empty.
   - **Lightbox.** The element picker greys a switched-off element with the same sentence and the arrows skip it.
6. **`grid_generate`** decides whether the one press (the one-click run, AUTO-1) can run at all.
   - **Refused press.** While it is off, `POST /api/decks/new/quote` and `POST /api/decks/generate` with `one_click: true` answer 404 `not_switched_on` before anything is read or run.
   - **Context.** `GET /api/decks/new/context` carries `grid_generate`, so `OneClickBuild` greys Build with "Not switched on yet." before it is pressed.
   - **New deck.** Its own build sends no `one_click` and is not the one press.
   - **When it is on.** The run uses only the models and elements that are switched on (4 and 5).
   - **Area generation.** It is not on main (#3764 owns its route); when that route lands it reads the same flag.
7. **`grid_v2_editor` and `?editor=v1`: option (b), dropped.** The simplified chrome is the only editor (D1604), and v1 features sit behind ⋯ (plan §0). Neither the flag nor the parameter exists on main, and a test fails if either appears in `frontend/src` or the Worker. Legacy `fields` cards still convert through a proposal (`editorModel.withFieldBlocks`).
8. **The dry run** (`scripts/deck-dry-run.mjs <backup.sql>`).
   - **Input.** It reads an owner-exported `wrangler d1 export` dump into an in-memory SQLite. Nothing is written to disk and the database is dropped on exit.
   - **What it compares.** For every card of every current version (or every version, with `--all-versions`), it compares what Present draws today (`presentExportModel.cardOf`) with what The Grid draws:
     - a fields card goes through the editor's conversion;
     - every block is checked against `placementProblem` and `deckReflow.textCapacity` at the deck's aspect.
   - **Explained differences.** `converted`, and `placeholder` (a "Not recorded" line the conversion leaves out).
   - **Unexplained differences.** Words lost, words added, a conversion refused, an overlap, a block off the grid, or text over its capacity. Any of these makes the exit code 1.
   - **Report.** It names deck ids, versions, card numbers, kinds and counts. It never quotes a word of a deck.
   - **Sample result.** On the three sample ventures (full, sparse, conflicting) plus a legacy fields deck, it lists zero unexplained differences.

### Routes

- `GET /api/admin/feature-flags` (admin): every row, the keys a row may name, and `cache_s`.
- `PUT /api/admin/feature-flags` (admin) `{ key, scope, scope_id?, enabled: true | false | null }`. `null` deletes the row, which returns the flag to its default. Refusals, each before any write: 400 `invalid_key`, `invalid_scope`, `invalid_scope_id` (a user is their numeric id, never an email) or `invalid_enabled`.
