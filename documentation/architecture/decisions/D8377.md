## D8377 — The D190 test file builds each schema variant once (#8377)

- **Status:** built 2026-11-23. Found while driving #8377 and #8374 to green.
- **Scope:** tests only. No Worker code changes.

### Cause

`suite (worker-3-of-6)` hit its 50-minute limit five times on 2026-11-23, after 18:00 UTC:
- #8162's merge-queue run;
- #8374 and #8377, each twice;
- `agent/codex-s39/8345-hosted-readers`.

Each time it was cancelled with 3,382 tests passed and none failed. In other runs over the same hours the shard passed in 21–41 minutes.

The time is in `sub_cutoff_restores_d190.test.ts`. `freshDb()` built the whole schema from scratch for every test, about twenty times: the baseline, then each migration above the cutoff, statement by statement. Only five variants exist, because a test skips none, 278, 4680, both, or 287. Each build took about 36 s on a passing CI runner and 61 s on the slower runners that timed out, so this one file decided whether the shard finished.

### What changes

- `freshDb(skip)` builds each variant once per run, with the same error-tolerant, statement-by-statement steps as before. It builds into a private directory under the checkout's schema cache (`node_modules/.cache/studioos-schema`, D4133), removed when the process exits.
- Each test then gets its own in-memory copy, rows included, through `loadSchemaFile`. A test that writes to or alters its database changes only its copy.
- `_schema_once.mjs` splits `loadSchema(db, opts)` into `loadSchemaFile(db, path)`, so a test that builds its own variant reuses the same copy steps. `loadSchema` behaves as before.

The shared `schemaPath` build was not reused: it applies each migration whole and stops at an error. The variants that skip 278 or 287 rely on the runner's statement-by-statement tolerance.

### Measured

On the same machine, the whole file takes 876 s before and 336 s after (−62%), with 16 of 16 passing both ways. Five builds remain, at about 60 s each; every other test drops from about 60 s to about 1 s.

### Rollback

Revert the PR. The file builds per test again.

### Tests

The file's own 16 assertions are unchanged and pass. `schema_once_d4133.test.ts` passes 4 of 4, which covers `loadSchema` through the split. `check-test-clock` and `check-unused-imports` pass.
