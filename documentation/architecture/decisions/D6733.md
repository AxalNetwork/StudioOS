## D6733 — Retry sync: a Worker route that re-sends a licence's copy on demand (#6733)

Built for #6733, the follow-up the owner asked for on #5924 (part of #4819). D5924 drew **Retry sync** on Licences › Operations (board L15) disabled, because no Worker route re-sent a licence copy on demand. This adds the route and wires the button. No migration. `admin_deployments.ts` and `admin_licences.ts` are not touched (#5925, PR #6380, is changing them).

### The route

`POST /api/admin/licences/:uid/sync/retry`, in its own file, `cloudflare-worker/src/routes/admin_licence_sync_retry.ts`, which mounts itself at `/api/admin/licences` ahead of the licence ledger (`before: [adminLicences]`), as `admin_licence_pricing_apply.ts` does. The file is named `admin_licence_…`, not `admin_licences_…`: every `admin_licences_*.ts` must be mounted by hand from `admin_licences.ts` (`cloudflare-worker/test/_licenceRoutes.mjs`), and that file is out of bounds here.

| Answer | When |
|---|---|
| `200 { ok: true, pushed, sync }` | The attempt ran. `pushed` is `pushLicenceToBranch`'s result (`ok`, `revision`, `failure_code`), `sync` is `syncSummary` after it, the same shape as `sync` on `GET /api/admin/licences/:uid`. |
| `409 nothing_pending` | No `licence_push_pending` row: no copy is owed. Nothing is sent and no revision is spent. |
| `409 retry_in_flight` | An attempt on this licence started less than `SYNC_RETRY_LEASE_SECONDS` (120) ago. |
| `503 sync_unreadable` | The queue could not be read. Nothing is sent. |
| `404 not_found` | No such licence. |

A push the branch does not accept is a **200**, not an error (D111): the attempt ran and is recorded, and the branch's failure travels on `pushed.failure_code`.

### Recorded exactly as a cron attempt

The send is `pushLicenceToBranch(env, licence.id, at)`, the call `retryPendingLicencePushes` makes on HQ's ten-minute tick (D272). It reads the licence fresh, allocates a new revision, and `recordPushOutcome` writes the outcome. A copy that lands deletes the pending row and records `branch_revision` and `last_success_at`. A copy that fails adds one to `attempts`, sets `last_attempt_at` to this attempt and records its `failure_code` and `revision`. The cron takes a row only when `last_attempt_at` is 60 minutes old (`LICENCE_PUSH_RETRY_WINDOW_MINUTES`), so its window counts from the manual retry. The Worker test proves this: the cron tries nothing at 59 minutes after the retry and sends it at 60.

### One manual retry at a time: refused, not coalesced

Before sending, one statement claims the row:

```sql
UPDATE licence_push_pending SET last_attempt_at = ?
 WHERE licence_id = ? AND datetime(last_attempt_at) <= datetime(?)   -- now − 120 s
RETURNING licence_id
```

A second press inside the lease changes no row and is refused with `retry_in_flight`, so two clicks never send two copies. Refusing is simpler than coalescing: coalescing would have to hold the second request open on the first one's answer, and Workers have no shared memory between requests to do that. The page re-reads the licence after every answer anyway, so the second operator sees how the first attempt ended.

The stamp is the time the attempt records anyway, so `recordPushOutcome` writes the same value. The stamp also keeps the cron off the row while the push runs, because the cron only takes rows an hour old.

Two edges, both safe:

- **A cron run already holding the row.** If the cron read the row before the claim, both may send. Each push carries its own revision, and `recordPushOutcome` never lets an older answer overwrite a newer one (#4686), so the outcome is the same as two cron ticks.
- **A failure that never learnt its branch** (`licence_unreadable`, `deployment_unreadable`). `recordPushOutcome` leaves such a row's `last_attempt_at` as it was. After a manual retry it holds the claim's stamp, so the cron waits an hour from the retry rather than trying on its next tick. That is the same window every other failure gets.

### Gate and audit

`requireSuperAdmin` is the gate used by every licence ledger route and by the transitions that push (`activate`, `suspend`, `PUT /:uid/seats`). It is not `requireSuperAdminWriteBar`, the money writes' bar, because a retry changes no term. The narrower `requireHqAdmin` would hand a plain admin a write on another tenant's licence.

The retry is logged through `logAdminAction` as `licence_sync_retried`, written to `activity_logs` (`user_id` = who pressed it) and `admin_audit_log` (D159). The details hold `licence_uid`, `licence_ref`, `attempted_at` (the attempt's time, the same value the pending row records), `revision`, `accepted` and `failure_code`. This is the log the licence domain, brand-kit and fee routes already use. It is not `licence_events`, for two reasons. That table's `CHECK` admits a fixed list of events, and widening it takes a full table rebuild (migrations 266, 331). And a retry changes nothing on the licence itself.

### The page

- **`frontend/src/lib/api/licenceSync.js`** (new): `licenceSyncApi.retry(uid)`.
- **`licenceDeploymentModel.js`**:
  - `RETRY_SYNC_REASON` is gone. In its place:
    - `RETRY_SYNC_NOTE`: "Sends the owed copy now. HQ also re-sends it by itself, at most once an hour after the last attempt."
    - `RETRY_SYNC_NOTHING_OWED`: "No copy is queued, so there is nothing to re-send."
  - `noticeForSyncRetry(body)` gives the outcome:
    - "Sent. The branch accepted revision N."
    - "Sent, and not accepted: <the failure code's sentence> (code X) The attempt is recorded. HQ tries again by itself not before <time>."
    - The code's sentence comes from `syncFailureSentence`, never `pushed.reason`, which can carry raw error text.
  - `noticeForSyncRetryError(e)` gives the refusals' notices.
- **`licences/LicenceSyncStrip.jsx`**:
  - Retry sync is enabled on L15 (state `pending`) when the strip is given `licenceUid`.
  - On out of sync (no copy queued), Retry sync stays disabled with `RETRY_SYNC_NOTHING_OWED` beside it, because the route would answer `nothing_pending`.
  - While the request runs, it reads "Sending…" and Read again is disabled.
  - The answer shows under the card (`OutcomeNotice`, `licence-sync-retry-outcome`). The strip then re-reads the licence. The notice survives the card turning to L14 "Synced with HQ".
- **`licences/LicenceDetail.jsx`**: one prop added to the existing strip call, `licenceUid={d.uid}`.

### Defaults chosen without an owner question

1. Refuse, not coalesce, a second retry, with a 120-second lease (above).
2. Super Admin, the plain gate (above).
3. `activity_logs` and `admin_audit_log` through `logAdminAction`, not `licence_events` (above).
4. A failed push answers 200 with the failure on `pushed` (D111), not 502.

### Ledger action integration

The pending-copy route keeps the ledger's `not_issued` refusal for draft licences and its status response field. The newer named lifecycle action handling remains in LicenceDetail, including termination and partial-outcome retry. The strip also accepts legacy retry callbacks when no licence uid is supplied, and honours the ledger's busy state; a named licence keeps its per-card outcome and re-read.
