## D6381 — Bound unused-import usage blanking to the import clause (#6381)

The unused-import guard on main 6d7712c6d1 reported twelve live bindings in
`workflow_channel_delivery_6370.test.mjs`. Its usage preparation matched from
an `import` through a module literal at the end of a line. A JSON import with
`with { type: 'json' }` could not end that match, so it consumed real uses up
to an import inside a later generated-worker template. Side-effect imports
could cause the same overrun.

Match only the supported import clause (named, default, namespace, or a
default plus named/namespace clause) and its quoted module literal. Stop at
the module literal without requiring the line to end there. When attributes
follow, match their own braces using the existing bracket/string scanner and
blank them too, so attribute text cannot hide a dead `type` or `json` binding.
Side-effect imports declare no bindings and need no blanking. The existing
length/newline preservation and declaration/usage
asymmetry for embedded templates remain intact.

Do not remove live bindings from the workflow regression, exempt that file,
weaken the guard, or change the guard chain. The new regressions cover the
real unchanged workflow file, attributed default/named imports, a side-effect
import, preserved offsets/newlines and genuine dead named/local bindings.

This is the single main-red repair for #6381. Feature branches inherit it
through main, without porting the fix or rerunning inherited failures. It
changes local/CI static analysis only: no production runtime, Slack delivery,
workflow configuration or repository settings change. Validation outcomes
and the exact candidate are recorded in the repair PR.
