### 1. What Overview draws now

The four blocks D1195 left as "Not read here yet" are drawn, and their waits (`WAITS.weekly`, `profiles`, `mail`, `needs`) are retired.

| Block | Where it reads | How it is drawn |
|---|---|---|
| Applications and picks per week | `overview.weekly` | Two lines: Applications in violet, Picks in sky. A week the read marks `recorded: false` keeps null figures and is the dashed "Not recorded: no program was open" hairline, never a 0. A measured quiet week is a 0. The current week is a hollow point, "to date". If no week is recorded, the block says Not recorded and draws no chart and no toggle. |
| Who applies, by profile | `overview.by_profile.pool` and `.applicants` | Grouped bars in the canvas order (Founders, Investors, Advisors, Operating Partners, Explorers); "Other profiles" only when someone is in it, which is how an admin in the pool shows. Each sub-block answers alone: an unreadable pool leaves its bars out and says so (TST14a). |
| Can Mail reach them? | `overview.mail_reach` | Per open program, the four steps Picked → Agreed to email → Program emails on → Reachable. Counts only, never an address. |
| Needs you | the programme list | See §2. |

- **View as table:** each chart block has the canvas's Chart/Table toggle, labelled "View as table", and the table holds the chart's own figures. In the weekly table an unrecorded week reads "Not recorded" in both columns.
- **Four states per block:** reading (a skeleton); figures; empty (no program ever opened, an empty pool, no open program); and Unreadable, with the reason and Try again, which reads the overview again.
  - A failed overview costs its three blocks only. The tiles, places bars, chips and Needs you still answer.
  - A block the read marks `available: false` shows the Worker's reason. Its figures are never drawn, even if some were sent.
- **The rail's line** is drawn as a note under the blocks, in the canvas's words: "Eadwyn reads the programs and applicants on this page. Nothing changes until you act." It is followed by READS and NEVER.
- **Dark (TST11):** every new colour has its `dark:` pair. Violet becomes violet-400 (#a78bfa), as the canvas says.
- **Phone (TST16a):** the phone keeps the tiles, the weekly chart, the places bars, Needs you and the rail note. By profile, Mail reach and the status chips are left out below `sm`.

### 2. Needs you

Needs you is built from the programme list alone. A missing or unreadable date never makes a row. Each row says what it is and links to where it is acted on:

| Row | Rule | Link |
|---|---|---|
| "[Product] · [Firm] · waiting for review N days" | a partner's program in `submitted`, aged from `updated_at` (when it was sent); HQ's own never waits for HQ | Review |
| "[Product] · approved N days ago, not open" | `approved`; `updated_at` is the approval, since an approved program cannot be edited | Open in Programs |
| "[Product] · testing started [day], still Open" | `open` with `testing_starts` today or earlier | Move to testing in Programs |
| "[Product] · testing ended [day], still Testing" | `testing` with `testing_ends` before today | Close in Programs |
| "[Product] · N applicants, none picked yet" | `open` with applicants and nobody picked | View applicants (the program's Applicants) |

**Departures, for review:**
- **The canvas's actions with an ellipsis ("Open…", "Move to testing…") are links here, not dialogs.** Those dialogs belong to D815's console on Programs. A second copy on Overview would be a second write path for one action. The link text names where the action is taken.
- **The canvas's "N of its M applicants wait for a decision"** needs a per-program count of undecided applications, and the programme list carries only `applicant_count` and `picked_count`. The row is therefore "none picked yet", the issue's own wording.
- **The canvas's withdrawal request row** ("asked Support to withdraw") has no read. It is left out, and the block's foot says that withdrawal requests are not read here yet.

### 3. The tab counts

`ProductTestingHqPage` makes two reads (`useTestingReads`) and passes them to the Overview, so the tiles and the tab counts draw from the same answers and the programme list is read once.

| Tab | Count |
|---|---|
| Review | the amber dot with how many partner programs wait (`HeaderTab`'s `flag`); a measured 0 when none |
| Programs | every program |
| Applicants | the applicants on open programs: the Places tile's figure, as the canvas pairs them (48 and 48) |
| Tester pool | the active testers |

While a read is still answering, its tab draws the loading bar. A failed read draws "—" with why, never 0. Every tab, not only Overview, now makes these two reads. D1195's Applicants test says so.
