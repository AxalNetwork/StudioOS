## D6097 — Add to roadmap from a feedback record and its theme (#6097)

- **Status:** built 2026-11-14 for #6097.
- **Number:** D6097 is this issue's number (D4106).
- **Code:** `cloudflare-worker/src/services/records/grow.ts` (Product improvement's
  `add-to-roadmap` action, `addToRoadmapHref`, the Theme row's control and empty sentence),
  `frontend/src/pages/cycles/forms.js` (`buildItem.fromQuery`, `feedbackThemeOf`).
- **Tests:** `cloudflare-worker/test/cycle_records_grow_d691.test.ts` (the two `D6097` tests),
  `frontend/test/feedback_to_roadmap_d6097.test.mjs`.

### Why

Feedback reached a roadmap item only when the item already existed (Edit's Roadmap item) or
was made in Build with Answers feedback theme chosen. A founder reading a theme in Grow could
not turn it into a roadmap item from there.

### What changed

- **The action.** A feedback record with a theme declares **Add to roadmap**, a `link` action to
  `/build/product-roadmap/new?project_id=<venture>&feedback_theme=<theme>`, the theme
  URL-encoded. The Theme section's row carries the same action, so the control sits beside the
  theme as well as in the record's actions. The form it opens is Build's **Add item** (key
  `item`), Product roadmap's only Add form.
- **The prefill.** `buildItem.fromQuery` reads `feedback_theme`, trimmed, and chooses it under
  Answers feedback theme. A value no stored theme can be (blank, longer than 80 characters,
  which is `setFeedbackTheme`'s limit, or holding a control character) chooses nothing, and
  None stays chosen. Opened from Build itself the form is unchanged.
- **The link.** Nothing new writes it. Saving Add item posts `feedback_theme` to
  `POST /api/cycles/build/roadmap`, whose `feedbackLink` (`services/buildCreates.ts`, D690)
  links the theme's rows. That statement links only rows that are **open and have no roadmap
  item yet**: a planned or shipped row, and a row already linked to another item, keep what
  they had. So "the feedback rows of that theme show the roadmap item" holds for those open,
  unlinked rows only; the record that opened the form shows the item only when it is one of
  them.
- **The record's next.** An Open or Planned theme row was already the record's `next`
  (`nextFor` in `cycle_records.ts`), with no action. It now names Add to roadmap.
- **No theme.** A row with no theme has no Add to roadmap: a roadmap item answers a theme, and
  `feedbackLink` keys on it. The Theme section says why, "No theme yet. Add to roadmap needs a
  theme.", beside its Change theme. This is how other record actions hide: the action is not
  declared, and a POST to it answers 404.
- **Read-only viewers.** An advisor (or anyone the write gate refuses) gets no record actions and
  no row actions from the record route, so neither control is drawn, and a POST is a 403. Their
  `next` names the theme with no action, as before.

### Left as it is

- **A theme past Build's list.** Build's form-options list at most 100 themes. A theme beyond
  that is still sent from the query, but no chip shows it chosen. Ventures do not have that
  many themes today; widening the read is its own change.
- **A per-theme control on the Product improvement page.** `CycleModulePage.jsx` draws no
  per-theme control (its rows are feedback items, not themes), so none was added there.
- **Linking rows that are not open, or relinking.** `feedbackLink` is unchanged; changing which
  rows a new item takes is a decision about Build's create, not this link.
