## D5664 — Independent metadata event capture and reconciliation (#5664)

A separate Worker accepts approved GitHub App webhook deliveries. The proposed
Worker is inactive and has no installation ID or credentials. It uses raw-byte
HMAC verification, installation/repository/event allowlists and a bounded body.
Only allowlisted metadata enters a durable Queue before HTTP 202. Invalid
canonical extras cannot be persisted. No logs, titles, diffs, comment bodies,
finding contents or arbitrary URLs enter the ledger. Security events require
a separate installation, secret, endpoint and restricted partition; they have
no public fallback. Unsupported approved event kinds retain safe identity and
an explicit coverage gap.

Version 1 keeps repository/delivery/source identity, occurrence and observation
time, raw/canonical state, run/attempt/job/workflow/check/PR IDs, label snapshots,
environment, visibility and provider identity. A PR's head, observed run head,
check's tested SHA, proposed merge candidate and landed main SHA are separate;
unknown relationships stay null. Runs with no mapped PR and many mapped PRs
are both retained. A per-repository/visibility SQLite ledger atomically appends
semantic history and delivery receipts. Delivery ID collisions are errors;
semantic duplicates link additional deliveries without replacing history.
The notifier consumes read-only history; Merge Control credentials are never
shared. #5639 is unmerged and optional, via a read-only metadata source contract.

The independent schedule reconciles all Actions workflows rather than a name
allowlist. It overlaps its durable cursor, rechecks pending attempts, enumerates
all attempts and jobs/steps, splits >1,000-result time slices and refuses to
advance an incomplete window. Dense same-second caps, changed/missing pages,
revoked permissions, rate exhaustion and interruptions create explicit gaps.
REST cannot reconstruct every intermediate transition or destroyed group;
GitHub does not automatically redeliver failed webhooks. Authorized retained
replay is an operator action owned with #5668, not a new GitHub write capability.

The dated coverage matrix contains 41 committed workflow files at 8ef2ebd1e7,
50 registered workflows (nine paths absent from this checkout) and provider IDs.
The issue's count of 40 is its older snapshot, not a coverage limit. Webhook
normalization covers work/reviews/issues/claims, all run/job/check triggers,
merge/ref/release/deployment and restricted security metadata. Recurring REST
adapters for work/delivery/external checks and restricted scopes remain explicit
unsupported gaps pending the approved installation and scope evidence; the
current scheduled adapter implements Actions. This is a partial delivery of
#5664; exhaustive per-family recurring recovery remains outstanding. It must
not be presented as complete coverage or enabled before that is reviewed.

Validation includes >1,000 synthetic results, dropped/duplicate/reversed events,
immutable two-attempt history, restart after acknowledgement, canonical injection,
new workflow/provider, fork, orphan/multi-PR run, disabled security scope, queue
interruption and real Workers SQLite/RPC persistence with partition isolation.
The installed workerd supports November 8; local runtime tests use that date.
The proposal targets November 12, so target-date runtime validation remains a
rollout gate. Packaging dry-run passes without provisioning or deployment.

build/drift and mutation results belong in STATUS. #5657 still pauses pushes.
