## D8963 — SEC EDGAR registrants: the first company-register source outside Europe (#8963)

### Decision

#8963 carries #7316's 50-country goal: add official company-register sources
outside Europe, one per PR, each with its terms-review record. This PR adds the
first, **SEC EDGAR operating-company registrants (United States)**, as a fourth
register in `scripts/import-register-companies.mjs`, the offline compiler that
brought in BRREG, PRH and RIK ([D7316 part 2](D7316-p2.md)). Every rule of that
compiler applies unchanged: pinned primary-record hashes, the mandatory
quality-hold ledger, shared-domain and shared-name holds across the whole
ledger, deduplication against every existing directory row, the original
worldwide gate reported separately, and SQL emitted only for the exact objects
the compiler admitted.

This PR loads no rows. Production D1 and R2 were not read or written. The
directory gains no SEC rows until the terms review below is completed and the
owner runs the compile and application described at the end.

### Why EDGAR

`research_company_directory.website` is `NOT NULL` (migration 228), and the
D7316 register route admits only a homepage that the register itself records.
So a usable register must publish a website for each entity, with terms that
allow reuse. Most non-European registers considered publish no website field:
ASIC (Australia), ACRA (Singapore), Corporations Canada, the Japanese
corporate-number register, the Brazilian CNPJ file and the Indian MCA master
data. Two registers that do record websites were set aside because their reuse
terms could not be established from this session: the New Zealand NZBN (the
search index shows a restrictive Companies Office bulk-data agreement and no
open licence for the API) and Japan's gBizINFO (API-specific terms on top of
the site terms, and the search index shows neither text). EDGAR's registrant record carries a `website`
field, a native industry code (SIC), the state of incorporation and the filing
history, which is the evidence the D7316 gates need. Its data is published by a
U.S. federal agency.

EDGAR is the SEC's registrant register (the CIK), not a state incorporation
register; the United States has no national one. A row says that the SEC
records an operating company incorporated in a U.S. state, and nothing more.
How often the `website` field is filled was not measured, because no real data
was read. That yield is unknown until the owner's compile, and this PR makes no
claim about it.

### Terms-review record

`REGISTER_TERMS_REVIEWS` in the compiler holds one record per register. A
register's rows produce SQL only when its record is `reviewed`, carries the
same licence identifier as the register's manifests, has HTTPS licence and terms
links, a review date and a decision reference (`termsReviewProblem`). BRREG, PRH
and RIK are recorded as reviewed on 2026-11-19 under D7316 part 2, with the
links that record cites.

| Field | SEC EDGAR |
| --- | --- |
| state | **pending** |
| licence identifier carried by manifests | `US-SEC-public-information` |
| terms to read | `https://www.sec.gov/privacy` (SEC website policy), plus EDGAR's access and fair-use terms for automated download |
| reviewed on | not reviewed |
| why pending | The session network policy refused `www.sec.gov` and `data.sec.gov` (`CONNECT tunnel failed, response 403`) on 2026-11-27. The block was not worked around. The search index did not show the policy text. |

The expected basis is that EDGAR data is public information from a federal
agency. That is an expectation, not a quoted term, so it is not recorded as
reviewed. In line with D7810, no `research_company_publishers` row is seeded for
EDGAR until its terms have been read. The reviewed record, with the quoted
reuse sentence and the access conditions, goes in a later part of this decision
(`D8963-p2.md`), together with a migration adding its
`research_company_publishers` reference.

### Admission rules for EDGAR

The adapter reads one native registrant record per line, the shape of
`data.sec.gov/submissions/CIK##########.json`. The projection keeps only
`cik`, `entityType`, `name`, `sic`, `sicDescription`, `stateOfIncorporation`,
`website` and `filings.recent.form` / `filings.recent.filingDate`. It drops
addresses, phone numbers, EIN, former names and every other field. EDGAR also
registers individuals, so the owner's projection should keep only records whose
`entityType` is `operating`; the compiler rejects the others in any case.

| Gate | Rule |
| --- | --- |
| identity | CIK of 1–10 digits, not all zeros; stored zero-padded to 10 digits; uid `us-sec:<cik>` |
| entity kind | `entityType` is exactly `operating`; people, funds and other filers are held |
| jurisdiction | `stateOfIncorporation` is one of the 50 states or DC. Foreign codes and territories are held, because a territory is its own ISO country. Kept as `incorporation_state`; EDGAR records no legal form, so `legal_form` is null |
| filing history | `form` and `filingDate` are arrays of equal length |
| current reporting | a 10-K, 10-Q, 10-KT or 10-QT (or an amendment of one) filed no earlier than two calendar years before the as-of year |
| termination | a Form 15 (15-12B, 15-12G, 15-15D, or an amendment) on or after the latest periodic report holds the company; an undated or future Form 15 always holds it |
| activity | SIC code and description are both present. SIC 60, 61, 62, 65 and 67 (banks, credit, brokers, real estate, holding and investment offices, blank checks) are held, mirroring the NACE 64/66/68/701 holds. Insurance stays admissible, as NACE 65 does |
| website | the D7316 `sourceWebsite` rules: one usable HTTP(S) host, with social, aggregator and private hosts rejected |
| founding year | never set: EDGAR records no formation date |

The country is `United States` in `North America`, using the existing
`research_countries` row when present, and the register's own country and
region otherwise. (The fallback region was hard-coded to `Europe`; it is now per
register.) Field evidence keeps `source_type='official_registry'`,
`confidence='medium'` and `verified_at=NULL`. Financial, employee and valuation
fields stay null.

### How rows reach the directory, and where this PR stops

1. A runner allowed to reach `www.sec.gov` reads the terms and records them as
   `D8963-p2.md`. That PR flips `REGISTER_TERMS_REVIEWS.SEC` to `reviewed` and
   adds the `research_company_publishers` reference migration.
2. The owner downloads EDGAR's bulk `submissions.zip` under its fair-access
   terms, writes the projection JSONL and a source manifest (registry `SEC`,
   hosts `data.sec.gov` or `www.sec.gov`, licence `US-SEC-public-information`,
   byte hash of the projection), selects candidates and refreshes the
   existing-identity snapshot and quality-hold ledger.
3. The owner runs the D7316 part 2 command with the SEC manifest in
   `--source-manifests`. While the terms record is pending, the CLI performs a
   **dry run**: it writes the report and audit, writes no SQL and no statements
   file, and exits 2 with `sql_withheld_for_terms_review: ["SEC"]`. Once the
   record is reviewed, it writes the insert-only proposal as for the other
   registers.
4. Application follows the reviewed path of D7316 part 2: rehearse on a local
   copy, apply in bounded batches, then run aggregate post-flight checks. Only
   aggregates go into issues and PRs.

This PR covers step 3's dry run on synthetic fixtures only.

### Not done here

- The worldwide acceptance is still unmet: this adds one country to the
  register route (Norway, Finland, Estonia and now the United States). The 50
  countries need further sources, one PR each.
- `research_record_identifiers.scheme` (D7825) has no EDGAR scheme yet, so a
  `us-sec:` uid reads "Not recorded" for its native identifier until a
  migration adds one.
- Nothing in the Worker or the frontend changes. A `us-sec:` row is served like
  any other register row.

### Verification

`cloudflare-worker/test/research_companies_sec_d8963.test.mjs` runs on
synthetic EDGAR-shaped records (invented names on `example.com` hosts). It
covers admission and provenance, every gate in the table, candidate pinning,
manifest hosts, shared-domain and quality holds, deduplication against an
existing row, the terms gate (alone and through both SQL helpers), and the
CLI dry run. Eleven mutations of the compiler were each caught and then reverted
byte for byte. These mutants marked the terms reviewed, removed the SQL gate,
the entity-kind check, the passive-SIC holds, the same-day and undated Form 15
holds, the dry-run branch, the territory exclusion, the licence-match check,
the recency window or the per-register region. The 16 tests of
`research_companies_registers_d7316.test.mjs` pass unchanged.
