### 1. The read

`GET /api/cycles/build/plan/states?project=&scope=&limit=&offset=` sits beside D1068's handoffs and links, behind the same gate (`scoped(false, …)`):

- the venture's founders, an admin (read-only) and a partner of the venture's company read it;
- anyone else gets 404 `not_this_project`, and no session gets 401.

It returns every accepted (or edited) plan item that landed in a row, oldest first, in pages:

- 200 by default and at most 500;
- a bad page is 400 `invalid_page`;
- each answer carries `{ states, total, limit, offset }`.

Each state names `plan_item_uid`, `kind`, `landed_table` and `landed_id`, and carries `built`, `live` and `tested` where they apply to the kind.

Each landed table is joined on its own literal predicate and on the item's own venture, so an item never reads another venture's row. Every statement is bound.

A stage is one of three things, and only a source's own report makes it one:

- **done**: `{ reported: true, done: true, at, source, value }`. `at` is the day it changed when the table stores one. Otherwise it is null with `at_reason`, never a guessed day.
- **not done yet**: `{ reported: true, done: false, source, value }`.
- **not reported**: `{ reported: false, reason }`. Progress shows "Not recorded" with that reason, never "Not yet".

A landed row that is no longer on the venture reports each stage as not reported: "The row it landed in is no longer on this venture".

### 3. Departures from the issue, and why

- **A deploy's Live.** The issue reads Live from "a deploy" off a connector feed. No connector feeds deploys: GitHub's feed carries issues, pull requests and releases (D1068), and Vercel is a hand-off, not a feed. So:
  - a feature's or must-have's Live is Not recorded, "No connector reports a deploy here";
  - a roadmap item's Live is the GitHub release that shipped it, the one source that says a thing went out.
- **No day, no column.** Formation steps, experiments and a roadmap item moved to Done by hand store no day they changed. Per the issue's rule, no column is added. The stage is done with "Day not recorded" and the reason under it (`at_reason`, drawn as the cell's note).
- **A test's Tested** comes from the experiment the item landed in, not from a link to a separate test: D1068 links nothing to a test.

### 4. The frontend

- **`progressRows(plan, handoffs, links, states)`** fills Built, Live and Tested through `laterStage`:
  - a done stage reads its day, or "Day not recorded" with the reason as a note;
  - Tested and Live lead with their value (the result, or the release's name);
  - a not-done stage reads "Not yet";
  - a stage not reported reads "Not recorded" with the Worker's reason;
  - a failed read reads "Not recorded · Built, live and tested could not be read", with an Unreadable block saying it is not a claim that nothing was built.
- **`readAllStates`** reads every page (500 each, at most ten pages). One failed page fails the read; it never gives a short list.
- **The lead** says "None is built or live yet." only when a source reports those stages. When none does, it keeps "Built and live are not recorded here yet."
- **Built per week** (`builtPerWeek`, `weekLine`) draws twelve Monday weeks (UTC), this one to date and drawn lighter, from each Built day:
  - a built item with no day is in no week, and the line counts it apart;
  - so is one built before the twelve weeks;
  - when no source reports any Built, the chart stays D1070's dashed not-recorded line, never a row of zeros.
