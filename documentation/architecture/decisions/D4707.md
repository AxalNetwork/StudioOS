## D4707 — Licence navigation in the URL, accessible reasons, attributable paginated history (#4707)

This decision covers the behaviour half of #4707: navigation, accessibility
and history. The domain split of `AdminLicences.jsx` and
`admin_licences.ts`, with shared typed contracts, and a phone browser test
come next, on top of the tests this change adds.

### Navigation lives in the URL

`/admin/licences?licence=<uid>&tab=<key>&kind=<all|subsidiary|white_label>`

- A link reopens the same licence on the same tab.
- Choosing a licence or a tab pushes a history entry, so Back steps through
  what was opened.
- The tab keys and their order are in `pages/admin/licenceNavModel.js`. A
  test checks that each key opens the page step it names.
- A tab the licence does not have falls back to the first tab. For example,
  `brand` on a subsidiary opens Entity.

### A filter never leaves a hidden row selected

- The editor gets `reconcileSelection(wanted, visibleRows)`. That is the
  licence the URL names when the filter shows it, and otherwise the first
  visible row, or none. The URL is then replaced to match, so it never names
  a row the editor is not showing.
- Opening a licence the filter hides widens the filter to All rather than
  editing an invisible row. That covers a coverage cell, a link from another
  licence, and a licence just created.

### Accessible interaction

- **The tab bar** is a `tablist`:
  - each tab has `aria-selected` and roving `tabIndex`;
  - Arrow keys, Home and End move between tabs;
  - the panel is a labelled `tabpanel`;
  - on a narrow screen the row scrolls sideways instead of wrapping.
- **Pressed and current state.** The kind filter and the kind picker carry
  `aria-pressed`. The selected licence row carries `aria-current`. The three
  create fields are labelled.
- **Reasons use a dialog.** The six `window.prompt` calls are replaced by
  `LicenceReasonDialog`: demote an administrator, accept a notice response,
  reject one, suspend a licence, and terminate one.
  - It is built on `ui/Lightbox`, so it is a labelled modal dialog that traps
    focus, closes on Escape and returns focus to the button that opened it.
  - The field is labelled, and its rule is stated before anything is refused.
    The demote reason needs at least 10 characters, matching the Worker.
  - Confirm stays disabled until the reason meets that rule.

### History names who did what, and pages instead of stopping at a cap

**Migration `202611062240_licence_event_changes.sql`** adds three columns to
`licence_events`:

| Column | What it holds |
| --- | --- |
| `before_json` | The values the write replaced, read in the same request. |
| `after_json` | The values the write left. |
| `outcome` | `committed`, or `partial` when HQ's write landed but the push to the licence's branch did not. |

**Which writes record them:** territories, seats, terms, activate, suspend,
reinstate, renew and terminate.

**When the row is written.** `licence_events` cannot be updated (migration
269's triggers). So a write that pushes to the branch now logs its event
after the push, when the outcome is already known. The test fixture installs
those triggers, which proves the write path never needs an `UPDATE`.

**`GET /api/admin/licences/:uid/events?before=<id>&limit=<n>`** returns the
history newest first, a page at a time:

- Paging uses the row `id`, at most 100 rows a page.
- `next_before` gives the next page, and is null once the history runs out.
  Nothing is cut silently.
- Each row carries:
  - `actor`: `known` with the account's name, `unknown` when the account no
    longer exists, or `none` for a system writer;
  - `change`: `{ recorded: false }` for rows from before this migration,
    `{ recorded: true, readable: false }` for stored JSON that cannot be
    parsed, and otherwise `before` and `after`;
  - `outcome`, which is null when it was not recorded.

**The History tab** (`LicenceHistory.jsx`) shows, for each row:

- who did it;
- a table of the fields that changed, before and after;
- how the write ended.

It also keeps "Not recorded", "Unreadable" and "Nothing recorded yet" as
separate states, and offers **Load older** until the history runs out. The
licence detail payload keeps its own `events` field unchanged for other
readers.

**Tests that read the code as text** now read every file of the page or the routes, through two helpers:

- `frontend/test/_licencePage.mjs` for the page, root first;
- `cloudflare-worker/test/_licenceRoutes.mjs` for the routes, in mount order, so "the first X in the source" means what it did before.

The few tests that named one file or an import depth were pointed at the file that now holds the code. The SQL-prepare baseline moves the five existing `placeholders` sites to their new files, and changes nothing else.

### Shared typed contracts

The values both sides must agree on, and the shapes of the licence answers,
are written once on each side and held together by a test.

**The Worker: `services/licenceContracts.ts`.** It names:

- the licence statuses and kinds, which must equal the CHECK lists in
  migrations 187 and 279;
- the seat types;
- a history row's outcomes and actor states;
- the history page's default size (50) and maximum (100);
- the response types of the history page and of every write that pushes to
  the branch: the transitions, suspend, renew, territories, seats and terms.

The routes build each of those answers with `satisfies` against its type.
`npm run test:types` therefore fails when a route returns a status outside the
list or a misspelled field. Both were mutation-checked and caught.

**The SPA: `lib/licenceContracts.js`.** The SPA's `.js` is not type-checked,
so this file mirrors the values and describes the shapes as JSDoc types. It
also lists each answer's fields. The history client and the History tab take
their page size and outcomes from it.

**The test that holds them together:**
`cloudflare-worker/test/licence_contracts_4707.test.ts` checks that:

- the SPA's constants equal the Worker's;
- the statuses and kinds equal the migrations' CHECK lists;
- the SPA has a status tone for every status, a seat for every seat type and
  a filter for every kind;
- the SPA's field lists equal the keys the routes actually return.

Each of these was mutation-checked: dropping a seat, adding a field to a
route, dropping a status tone, or changing the page maximum makes it fail.
