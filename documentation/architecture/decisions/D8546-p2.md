## D8546 part 2 — Problem discovery's Proposed grouping cards, on the part 1 routes (#8546)

Built under #9020, after #6006 and #8546 closed. D8546 built the Worker contract and left the cards undrawn: "The proposal cards in the rail, their Edit and Discard controls, the producer … Not done here." This part draws the cards from boards V17 (desktop) and V29 (phone) of the Validate v2 Discovery and ICP canvas (D5995), plus V30 (dark). It adds no route, no migration and no Worker change. The producer is still not built, so on production the list stays empty until something calls `proposeGrouping`.

### What is built

- **Client.** `frontend/src/lib/api/painGroupingProposals.js` (`painGroupingProposalsApi`) has `list`, `edit`, `discard` and `accept`. Each one calls a route that D8546 mounted at `/api/progress/pain-grouping-proposals` and passes both the venture id and the proposal id. `api.js` is not edited; the generated index re-exports the module.
- **Cards.** `frontend/src/pages/cycles/ProposedGroupings.jsx` draws them, and `defs/validate.jsx` mounts it on Problem discovery under `PainThemesSection`. Each pending proposal gets one card:
  - the eyebrow "Proposed grouping", plus "Edited" once a writer has changed it;
  - the headline, "N quotes → new theme “…”" or "N quotes → add to “…”";
  - each quote with the interviewees who said it, and a "No consent to quote" mark on each interview that did not agree;
  - Discard, Edit and Accept.
- **Edit.** Edit keeps or drops quotes, and changes the title when the target is a new theme. A theme that already exists keeps its own title. It sends one PATCH with every interview behind each kept quote. If you drop every quote, or empty the title, nothing is sent and the card says why. The Worker keeps the original proposal beside the edit.
- **Accept.** Accept is one POST, and while it is in flight a second press sends nothing. The list is then read again, and so is the module (`ctx.reload`), so the themes list shows the new or extended theme.
- **Discard.** Discard is one POST. The list is read again, and the module is not, because no theme changes.
- **Refusals.** `stale_source`, `stale_target`, `stale_grouping`, `already_decided` and `proposal_not_found` each get their own sentence, and each reads the list again. `accept_failed` (503) says that nothing was saved, and the card stays. Any other failure gets one generic sentence. The Worker's raw message is never shown.
- **States.** While the list loads, the section says it is reading the groupings. With none waiting, it says that no proposed groupings are waiting, never "0 waiting". A failed read says **Unavailable** and offers Try again (D5129).
- **Readers.** Only a writer (`parts.can_write`) gets the section. Anyone else gets no section and no read, and the Worker would refuse them anyway (403).
