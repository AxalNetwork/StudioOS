- **Canvas:** the owner's "Data room" boards DR1–DR5, DR15 and DR19–DR23, in `design/incoming/Data Room · Boards.dc.html`.
- **Basis:** `origin/main` at `ef4477147c`, with part 2's worker (D1103, migration 594) merged.
- **Migration:** none. No worker file changes: `data_room.ts` belongs to parts 3 and 4, which are open, so the page composes reads that already exist.

### 1. What is built

- **Home (DR1)**, under the tool's tab row on the module page: the room's counts as chips; **Needs you** (files no investor can open now, access ending within fourteen days, investors who need an NDA, grants whose folders could not be read); **Who has access**; **What was added**. The module page's coverage and records stay below it.
- **Files (DR2)** at `/raise/data-room/files`: the folder tree, search, and the table with a checkbox per file. Selecting files brings the bulk bar: Move, Set gate, End access, Match to checklist, Remove and Clear. New folder and the folder lightbox (the NDA switch with `apply_to_contents`, rename, delete) sit beside the tree.
- **The file lightbox (DR3)** at `/raise/data-room/file/:id`: the file's gate and who can open it now, links issued (Downloaded or Blocked only; a link not opened is not counted), versions with Make current, what it answers, the founder's own download, Replace, and each write through its dialog. Closing it returns to Files.
- **Upload (DR4)** at `/raise/data-room/new`, in place of the generic Add form: a queue in states (Waiting, Sending, In the room, Refused), and for all files the folder, the gate (NDA on by default, D1101 §5 answer 9), an end date and what it answers.
- **The dialogs (DR5, DR15, DR19–DR23):** every write says what it changes before it is sent — who gains and who loses the file, by name, for a move or a gate change; what an end date ends; that a removal cannot be undone.

### 3. What it reads and writes

| Use | Through |
|---|---|
| The room | `GET /api/data-room/:projectUid`, the venture's uid from the founder's own list (D1101 §2) |
| Versions, Make current, the founder's download | D1103's `dataRoomApi.versions`, `makeCurrent`, `download`, `downloadVersion` |
| What a file answers | the module record, `cyclesApi.record('raise', projectId, 'data-room', id)` |
| Replace | the record action `replace` (multipart), as the module page does |
| Upload | `cyclesWrite.formOptions` for the uid and the answer choices, then `api.dataRoomUploadFile` (`POST /api/data-room/:projectUid/files`) per file |
| Move, gate, end, rename, folders, remove | the existing `data_room.ts` routes through `api.dataRoomUpdateFile`, `dataRoomDeleteFile` and the folder methods |

No client method is added, so `check-api-drift` has nothing new to match.

### 4. Who may do what

- Only the owner sets a gate, ends access or removes a file (D1103). A co-founder sees those controls absent, not disabled, and a co-founder's upload sends no gate: the file takes its folder's.

### 5. Said, not drawn, and why

- **Trash:** there is no Trash store yet (D1101 §5 answer 8 is not built). Remove says the file is deleted and cannot be brought back.
- **Storage left:** not recorded. Upload says so and states the 20 MB cap, which is refused before a file is sent.
- **Files from Google Drive or Notion (DR4c):** wait for part 4's file sources (D1105).
- **Access requests on Home, and the last ninety days:** wait for parts 3 and 4 (D1104, D1105). Each block says so where it would be.
- **Upload progress:** the browser reports no percentage for one request, so each file shows a state.
- **A folder with subfolders** cannot be deleted from here: what happens to the subtree depends on the database's foreign-key setting, so the dialog refuses it and says to empty the folder first. Deleting a folder names the investors whose only scoped folder it is.
