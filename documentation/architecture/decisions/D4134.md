## D4134 — Lists every deck swap extends are derived or kept in key order (#4134)

**Context.** On 2026-11-02, fourteen open pull requests conflicted with main
again within hours of a full resolution pass. Most of the conflicts were on
three lists that every deck v2 swap extended at the same place:

- `SWAPPED` in `frontend/src/pages/raise/pitch/deckV2Adapter.js`, a literal
  array each swap appended to, mirrored by a second literal in
  `frontend/test/pitch_v2_adapter_d1604.test.mjs`, plus the adapter's
  `lib/api` imports, appended at the end;
- `CONTRACTS` in `cloudflare-worker/src/contracts/index.ts`, appended in
  decision order;
- the Worker's total mount count in
  `cloudflare-worker/test/route_registry_4105.test.ts`, a number every new
  router bumped (390, then 392).

Any two branches touching one of these conflicted, whatever they did
otherwise. D4102, D4103, D4104 and D4105 removed the same kind of shared list
from the route map, the routing projections, the folder READMEs and
`index.ts`.

**Decision.**

1. **`SWAPPED` is derived.** `off(name)` records the rows still off; the
   export is every `SURFACES` key that is not. The test reads each method's
   body: a swapped row answers through `through(() => deck<X>Api.…)` and ends
   on its own `SURFACES.<name>.issue`, an off row is exactly
   `off('<name>')`, and the two together are every method. A swap is now a
   one-line change to its own method.
2. **The adapter's imports are in file-name order**, one per client, each
   used by a swapped row, so two swaps add lines at different places.
3. **`CONTRACTS` is in key order**, one row per line. The decision that added
   a row is in its issue and in `git log -L`.
4. **No test pins a total.** The registry test derives the mount count from
   the `app.route(` lines in `index.ts` plus the registry's planned mounts, and
   fails a router mounted twice on the same path. The deck-router and votes
   slice checks no longer pin the hand-written line beside them.
5. **A swap's own test goes in its own file**, never appended to
   `pitch_v2_adapter_d1604.test.mjs`. AGENTS.md carries the rule.

**Consequences.** A deck swap PR touches its method's line, one import line,
one contract row and its own test file, each at its own sorted place, so two
swaps that land together merge cleanly unless they swap the same method. The
guards fail a row out of order, a method neither swapped nor off, an unused
or unsorted import, and a duplicate mount. The open PRs that already append
to these lists still conflict once, against this change; their resolution
is to keep the sorted order.
