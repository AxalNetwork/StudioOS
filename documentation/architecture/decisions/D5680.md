## D5680 — Restricted operational security triage without public disclosure (#5680)

The existing typed security_events ledger remains authoritative. The new
HQ Super Admin reader selects only bounded-window kind/outcome counts; it
never reads subjects, networks, detail, evidence or customer content. Unknown
or failed reads stay unavailable. The ledger records signin/step-up/gate/
recovery, not every security domain; no unsupported producer is invented.

Domain ownership is explicit for authentication, isolation, privilege, keys,
payments, investor/fund, contracts, signatures and PII. Presentation is denied
unless a trusted server authorization callback verifies domain, tenant scope,
team, private recipient, no Slack Connect and the exact registered private
case. Product role/profile is not a notification grant. Routine refusal and
step-up produce no alert. Scanner failure is not a finding. Recovery requires
verified healthy evidence. Private payload contains fixed labels and an opaque
case reference; input text, IDs, URLs, tokens, parameters and diagnostic fields
are never copied. No public issue/comment/fix-dispatch writer is imported.

A separately approved generic operational impact contains neither security
labels nor case/domain/finding existence. Sensitive existence, absent grants,
unknown tenant and external channels are withheld. Publisher success is only
a validated durable pending intent, never an inferred Slack receipt. Exceptions
and uncertain publisher results remain unavailable/ambiguous.

The restricted-transport-5680 adapter rechecks live private/internal audience
and membership before every send using the existing transport. It is an
explicit integration port, not a replacement transport or enabled route.

The #5667 restricted publisher/private case system must supply real grants,
permission-checked drill-down and durable intent keys. This patch has no public
HTTP export or scheduled reader and does not wire recording/refusal paths.
All tests use synthetic cases. No actual findings or private ledger records
were queried or published. Live private-recipient/access/retention and source
integration remain required before activation.
