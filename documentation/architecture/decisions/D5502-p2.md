## D5502 part 2 — Integrate per-guard failure evidence (#5502)

D5505 supplies the full guard-run result that D5502 initially lacked. The shard
runner ingests it after `npm run test:guards`, on success as well as failure,
and retains its original process exit status. Failed queue guards emit their
stable IDs through the existing bounded `ci-failure-id` annotations.

Each guard becomes a report in the existing run/attempt/SHA-bound
`ci-failures-<part>-attempt-<attempt>` artifact. Identity includes kind, source
file, guard ID and canonical argument array, so a flag change is not confused
with the same check at the tested base. Passed/failed guards provide exact-ID
coverage; blocked, interrupted and not-run guards provide unknown evidence.
The collector already reads and sanitizes these envelopes. Guard IDs, paths,
arguments and exit metadata are validated again; no raw diagnostic output is
published. Reproduction includes the SPA build and `--guard <id>`.

Independent guards are compared only with the exact tested base, using the
same inherited/independent/unknown rules as tests. A malformed, missing, stale,
preflight-only or exit-inconsistent report supplies no full coverage. Partial
execution cannot prove that a guard passed. Older base runs with no guard
artifacts remain unknown; there is no nearest-ancestor substitution.

The existing bounded archive handling, three-day retention, escaped summary,
trusted-base digest, request budgets, test retry policy and required gate
remain in force. D5505 and D5502's guard integration ship together in a new
reviewable draft; #7992 is already merged and is not rewritten.
