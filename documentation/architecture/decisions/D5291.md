## D5291 — TikTok read-only connector (#5291)

The first release connects one Axal-managed TikTok app and requests only
`user.info.basic`, `user.info.stats` and `video.list`. The connector stays
unavailable until the owner completes app approval in #1008 and enables it.
Grow records, scheduled reads and draft uploads belong to later parts of #2401.

Provider behavior recorded in #2401 is provisional until verified against the
official documentation. App approval and production connection verification
are separate from local tests using a fake provider.

Provider evidence checked on 2026-11-10:

- [Login Kit for Web](https://developers.tiktok.com/docs/en/login-kit-web) documents
  the v2 web authorization flow.
- [Token lifecycle](https://developers.tiktok.com/docs/en/oauth-user-access-token-management)
  documents 2-hour access and 180-day refresh tokens and refresh-token rotation.
  Use the response's expiry fields rather than the durations in the planning issue.
- [Revocation](https://developers.tiktok.com/docs/en/oauth-revoke-a-user-access-token)
  uses a form-encoded POST with the app credentials and access token.
- [Webhook verification](https://developers.tiktok.com/docs/en/webhooks-verification)
  signs the timestamp, a dot, and the raw request body with HMAC-SHA256 using
  the client secret. [Event documentation](https://developers.tiktok.com/docs/en/webhooks-events)
  identifies the disconnected user by `user_openid`.
