## D1263 — Founder-decided Raise evidence candidates

Part of #2430, part 2 (#3286), S18. Migration 628 and the existing Raise router
provide the evidence pack's local source builder and founder decisions. The
D1261 page stays unchanged; wiring its drawers belongs to the other parts.

`raiseEvidenceSources.ts` contains 33 EVIDENCE_RULES covering the parent pack:
receipts/runway/team, interview themes and consent, experiments and verdicts,
KPIs and delivery, mapped spending and planned costs, legal/document proof,
cap and capital relationships, and saved model assumptions. They read existing
local stores only. They make no provider or model request. Source labels come
from code and recorded provenance. Strength is separate from SCORING grades;
this implementation creates no grade mapping and no claim-check formula.
Typed-only material remains anecdotal and linking never promotes it to Backed.

The source date is its receipt, interview, snapshot, filing, publication or
recorded action date. Sync-only contributors/IP steps, completed formation
steps without completion dates, experiments without result dates and typed
commitments without a commitment date keep a null observation date and reason.
A bank statement retains its actual month, without inventing a day. The owner’s
90-day metric/connector and 12-month interview/document windows are computed
from those dates, including an indeterminate month spanning the cutoff.

`raiseEvidence.ts` preserves its D891 readers and adds buildCandidates,
acceptItem, dismissItem, setSharing and linkClaim. A small per-project refresh
lease/cache accompanies the three requested evidence/claim/link tables. Open
rebuilds only after the last attempt is over an hour old, including partial
outcomes; Look again forces one. A failed source cannot create activity noise
on every open. Source reads run concurrently with independent failure states,
and a decision rereads only the rule’s dataset. A refresh writes at most 500 changed candidates in batches of 50 and
reports partial coverage rather than disguising unreadable sources as zero.
Decided source identities are retained and never proposed again, including
unpinned items. No cron or connector sync is added.

Candidate rows use AUTOFILL's source columns already declared in migration
581. Their payload contains metadata, hashes and references, without bank
values, names, notes, quote text or file keys. The founder read rehydrates
current values. Generic rail decisions refuse these two routed options so they
cannot bypass the dedicated evidence/provenance writer. Migration 628 adds a
unique candidate identity and project-composite foreign keys for claim links.

Accept requires the displayed source hash and rereads the source; a changed
source waits for a fresh decision. Sharing requires the displayed item version;
confirming changed material is explicit. Bank-derived evidence and consented
quotes start Private; other items start After NDA. Unpin and make-private work
even after a source disappears. Bank values are withheld when the authenticated
founder’s current connection cannot substantiate them. No balance, account,
line, counterparty, investor name or quote text is projected into these APIs.
The new routes refuse support sessions. Founders and active Lab owners decide;
admins in the current company read metadata only, with bank/quote items omitted.
HQ Super Admin retains its established cross-company metadata read.

Every decision batches the target write, fill provenance and canonical cycle
activity together. The operation nonce and NOT NULL provenance target abort a
losing/no-op decision before it can leave an audit. Fresh SQL predicates repeat
founder identity, company, account activity and undeleted venture. Provenance
uses the established D1066 citation_json source/prior-value envelope; code
candidates have no invented model or usage run. Eadwyn links require a real
pending proposal for the exact venture/claim/item/hash and an actor-owned usage
record. Ordinary manual links cannot claim computed or Eadwyn provenance.
Duplicate links and missing unlinks return 409/404; a losing version update
returns 409 rather than reporting an outage. Link/sharing changes invalidate the claim's cached check; #3287 owns rechecking.

The seven required routes are mounted under `/api/cycles/raise/evidence`, with
an API domain and alphabetical re-export. GET blocks fail independently;
metadata/pinned items/candidates/claims/coverage report unreadable separately.
There is no new investor read, public endpoint, export, binding or secret.
#3288 owns investor projection, NDA gates and SCORING evidencePack consumers.

Verification uses synthetic rows in the actual baseline plus all numbered
migrations, and exercises every rule's date/label, founder/company/support gates,
privacy defaults, one-hour/forced refresh, permanent dismissal, current snapshot
acceptance, versioned sharing/links, provenance/audit rollback, generic-route
bypass prevention and independent unreadable blocks. A client test executes all
seven methods against an intercepted request boundary. Final validation results
and mutation evidence are recorded in the PR.
