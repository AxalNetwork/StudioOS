## D7821 — Stored, explainable company activity classification (#7821)

The native classification, a reviewed code crosswalk and a materialized mapping are separate stores. Native evidence retains scheme/version, code, native label, language, source and register order. A mapping is one of `mapped`, `no_label`, `not_yet_considered`, `outside_tracked_markets`, or `pinned_unmapped_by_hand`, with the deciding method (`rule`, `code`, `manual`), proof, rules version and date.

Precedence is an explicit company-label override, then the first crosswalk-placed native code in register order, then a reviewed label rule. Crosswalk matching is restricted to the same scheme and version; exact codes precede the longest applicable prefix. Unknown codes are unreviewed, never automatically outside. The separate reviewed outside-label list adds no COMPANY_SECTOR_RULES keys. Conflicting normalized override keys are reported rather than merged; exact keys win. Fund and country overrides retain exact matching. The old pure mapping functions, whole return shape, COUNTRY_ALIASES and Node type-stripping compatibility remain intact; researchTaxonomy.ts gains no runtime import.

Neither #7716 nor #7719 is merged on this base. The single exported INDUSTRY_SCHEMES list therefore lives in researchCompanyClassification.ts; notes on both issues link it. Whichever merges second imports the first landed constant, in researchCompanyClassification.ts rather than researchTaxonomy.ts. This change does not introduce a third list.

UK SIC native backfill retains every comma-separated code and order from Companies House sic_codes. Its sector column is an Axal crosswalk label; no native label is invented. The seed generator imports the reviewed SIC_SECTORS table instead of copying its dictionary. The reviewed asset supplies classification-owned activity codes/titles and review metadata. Normalized industry uses UK SIC's own code and title; it is not an Axal market name and does not assert an unreviewed NACE/ISIC parent equivalence. The crosswalk can explicitly record another normalized parent scheme/version when reviewed. Every existing reviewed SIC code retains its prior market target; no differences were found on fixtures. A foreign key rejects a crosswalk target outside the market catalogue.

The admin-only self-mounted route provides resumable pages over every physical company row, including held rows, not a served-directory view. Counts by state, deciding method and evidence scheme describe the processed page. A company with several evidence schemes is counted once in each; a company without evidence is in `none`. Repeating the same recompute leaves identical rows and dates intact. Missing or old rules versions read `needs_recompute`. An override records reason and authenticated author in the same atomic batch as its audit, invalidates materialized mappings, and advances a revision. Recompute writes only while its read revision is current, preventing a concurrent override from publishing stale mappings as fresh. Resumed pages must carry the returned rules version, so an override between pages also forces a restart.

A directory count by tracked market is a catalogue count, never a market's size.

These are test proportions, not coverage claims about production.

Operator steps (after reviewed migrations land): use an authenticated admin session to POST JSON `{"after":"","limit":100}` to `/api/admin/research-company-mapping/recompute`. Repeat using the returned `after` AND `rules_version` until `done:true`; resumed pages require both. A 409 `recompute_rules_changed` means restart at an empty cursor. POST `{"raw_value":"the exact company label","target":"a-market-slug","reason":"approved classification reason"}` to `/api/admin/research-company-mapping/overrides`; an empty target explicitly pins unmapped. The authenticated author is always used. After an override, recompute from the start. These steps were exercised only against synthetic fixtures; they do not authorize a production run.
