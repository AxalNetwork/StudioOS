## D7129 — Check meeting-bot preview readiness before waiting or building (#7129)

Run #63 built a meeting-bot image before discovering that the preview signing secret, origin and route approval were missing. Run #62 stopped earlier when another commit became the tip of main.

The first check reads the origin, route approval and a boolean indicating whether GitHub has a signing secret. A configuration error reports the affected setting names in the log and failure receipt. A successful settings check produces no deployment receipt. After the six checks admit the exact main commit, the signing preflight validates the actual key before dependency installation and image build. Normal promotion still requires a signed receipt for that revision with confirmed cleanup, followed by a fresh candidate check.

The three candidate checks identify their stages in the existing supersession notice. Incident triage recognizes a newer main commit only when the notice matches the workflow run, attempt, SHA and failed stage, and GitHub records production promotion as skipped. A superseded candidate can already have reached preview. The release owner can dispatch from the current main after verifying the setup in [the production runbook](../PRODUCTION.md#owner-only-first-deployment). Hosted activation remains with #5675.
