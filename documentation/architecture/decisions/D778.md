## D778 — Founder options fill the open form and wait for the founder's Save

Task #2103 (D720 §9). Implemented in bounded parts, each naming its inventoried
option keys. D777's never-fill registry and D765's run path are on main. The
owner released the design dependency: keep the existing UI and AIRail canvas.

### Part 1 — Distribution's three brand text options

| Page | Option | Handler |
| --- | --- | --- |
| Founder · Grow · Distribution | `form:landing` | Fill the open landing form |
| Founder · Grow · Distribution | `form:palette` | Fill the open palette fields |
| Founder · Grow · Distribution | `draft:taglines` | Offer candidates; choosing one edits the form |

The mounted brand routes run through the existing router, which checks the
page's switch, guards the model output, meters usage and charges the pressing
member. Their fallback page and option now match D771's inventory. The existing
non-AI heuristic fallback remains available when a run cannot answer; it saves
nothing either.

Each UI handler captures the mounted rail's page and sends its own option with
the request itself. With no mounted page it uses the inventoried fallback.
Keeping the mounted page preserves its existing Manual switch. It does not
wait for the busy-state render to update the rail. The three existing API
methods accept these optional headers; they add no method or route. Other
callers retain the default request behavior. D771's rail hooks remain intact.

A response updates only the project/template form from which the run started.
Switching projects or templates invalidates it, including switching away and
back. Landing copy and palette values remain local draft state. Tagline
candidates are local too; selecting one still saves nothing. The existing Save
handler remains the only way these fills write a landing record. The handlers
copy their existing allowed fields rather than merging arbitrary response keys;
legal identity, payment and other never-fill fields are not added to the form.

`draft:logo`, uploads and recordings are outside this part. Later placement
parts depend on the shared proposals store from #2105. This PR is Part of #2103,
not its closure. No migration is needed. No layout or style changes are made,
so there is no departure from the existing desktop or phone canvas.
