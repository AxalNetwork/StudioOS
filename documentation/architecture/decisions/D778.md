## D778 — Founder options fill the open form and wait for the founder's Save

Task #2103 (D720 §9). Implemented in bounded parts, each naming its inventoried
option keys. D777's never-fill registry and D765's run path are on main. The
owner released the design dependency: keep the existing UI and AIRail canvas.

### Part 1 — Distribution's three brand text options

| Page | Option | Handler |
| --- | --- | --- |
| Founder · Grow · Distribution | `form:landing` | Fill the open landing form |
| Founder · Grow · Distribution | `form:palette` | Fill the open palette fields |
| Founder · Grow · Distribution | `draft:taglines` | Offer candidates; choosing one edits the form |

The mounted brand routes run through the existing router, which checks the
page's switch, guards the model output, meters usage and charges the pressing
member. Their fallback page and option now match D771's inventory. The existing
non-AI heuristic fallback remains available when a run cannot answer; it saves
nothing either.

Each UI handler captures the mounted rail's page and sends its own option with
the request itself. With no mounted page it uses the inventoried fallback.
Keeping the mounted page preserves its existing Manual switch. It does not
wait for the busy-state render to update the rail. The three existing API
methods accept these optional headers; they add no method or route. Other
callers retain the default request behavior. D771's rail hooks remain intact.

A response updates only the project/template form from which the run started.
Switching projects or templates invalidates it, including switching away and
back. Landing copy and palette values remain local draft state. Tagline
candidates are local too; selecting one still saves nothing. The existing Save
handler remains the only way these fills write a landing record. The handlers
copy their existing allowed fields rather than merging arbitrary response keys;
legal identity, payment and other never-fill fields are not added to the form.

`draft:logo`, uploads and recordings are outside this part. Later placement
parts depend on the shared proposals store from #2105. This PR is Part of #2103,
not its closure. No migration is needed. No layout or style changes are made,
so there is no departure from the existing desktop or phone canvas.

### Verification

`cloudflare-worker/test/founder_brand_fills_d778.test.ts` exercises each mounted
route with real SQLite and stubbed, guarded model responses. It checks the
returned value, member usage/charge and canonical page/option, preserves the
business row, then turns off that exact page and checks no model is called and
no business row changes.

`frontend/test/founder_brand_fills_d778.test.mjs` mounts the actual page for each
option: mount runs nothing; the press carries its own headers; the response
fills local state only; candidate selection stays local; Save sends the chosen
value once. Separate cases switch project and template while a response is
pending. The existing API methods are exercised through a stubbed fetch too.

The regression cases failed on the previous code's old context and stale-form
application. All 25 source mutations were caught: wrong fallback context, wrong press option,
wrong actor, stale response allowed, automatic Save, dropped API headers, missing
project/template invalidation, mistaking a reopened form for the same one, and
business writes inside each generation route, and discarding the mounted page
that owns the Manual switch. Restoring the implementation
returns both focused suites to green. Root build and full drift must pass before
opening the draft PR. Providers stay stubbed; production data is never read.

### Part 2 — Pitch deck's positioning draft

One inventoried row: `Founder · Raise · Pitch deck` / `draft:positioning`
(`Generate positioning`, handler `draft`, kind `write`). The existing mounted
`POST /api/decks/positioning` now uses `run()` with `rail_write`, rather than
calling an external provider directly. The matrix selects the offered model;
the router holds, guards, meters and charges the pressing member. Manual,
budget and safety refusals keep their shared status and message. An unavailable
model returns an explicit error, never invented positioning.

The route keeps its existing paid-plan and project-ownership gates. The scoped
project supplies `record: project:<id>`; a browser record label cannot replace
it. Page headers retain the mounted rail's switch, with the inventoried page
and option as the fallback. The existing API method accepts explicit press
headers, so the first request names the option before its busy-state hook runs.

The generated lines stay in the page's local result state. This tool copies
text for the founder to use in the deck; generating or copying writes no project
or deck record. Changing projects invalidates a pending result or error, even
when switching back. Unmounting invalidates the request too. The current UI and
its desktop/phone layout are retained; no new canvas interpretation, API route,
proposal writer or migration is introduced.

Worker tests use real SQLite and stubbed guarded runs to check output, actor,
page/option, scoped record, usage/charge, Manual, budget, guard and provider
refusals, ownership and byte-identical business rows. Frontend tests mount the
real page, exercise both fallback and mounted-page headers, local-only output,
project-switch and switch-back races, stale errors, and the existing API's fetch
headers. Regressions fail before the change; source mutations check each
boundary and are restored before the full build and drift suite.

Other founder options remain for later bounded parts. In particular,
`form:deck-template` still needs explicit acceptance rather than treating a
model-populated template as a saved version; this part does not change it.
