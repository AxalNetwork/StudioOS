### The three decisions from #3724's thread

They were recorded on the thread and are not yet on main as files. They are kept here so the numbers stay with the work. Each becomes its own file when its builder lands it.

- **D1487: the recommendation read, prefs, feedback and topics (Parts A and B).** `GET /api/events/recommended?limit=8` (signed in, not charged per view; `enabled:false` runs nothing); `GET`/`PUT /api/events/recommendation-prefs`; `POST /api/events/:id/recommendation-feedback` (`saved`, `not_for_me` or `null`, never shown to the host); `topics` (at most 5 known slugs) on event create and edit and as `topic=` on the public list. The reasons quote only the caller's own rows. A missing signal is `not_recorded`, never zero. Migration 709.
- **D1488: the charged Explain (Part C).** `POST /api/events/:id/recommendation/explain/quote` returns `{ microusd }` and runs nothing. `POST …/explain` runs `rail_match` on the `/my/events` rail page and charges the caller. The prompt holds the event's public fields and the caller's reasons, and nothing about other members.
- **D1489: the page and the editor's topics (Part D).** The row, Why this?, Not for me, Tune, the phone and the editor's topics picker. This change is the frontend half of D1489. The topics picker waits for D1487's `topics` field (§gaps).

### §gaps

Every element that needs data no route serves yet. Each line names the route or field it waits for. S1 files the Codex tasks from this list.

1. **Recommended events read:** `GET /api/events/recommended?limit=8` (D1487, Part A; ranking by rules first, then embeddings in Part B). Adapter: `recommended`.
2. **Recommendation prefs:** `GET` and `PUT /api/events/recommendation-prefs`, with interests, goals (≤ 500), formats, event types, home city, travel range, saved and enabled (D1487). Adapter: `prefs`, `savePrefs`.
3. **Feedback (Save, Not for me, Undo):** `POST /api/events/:id/recommendation-feedback` (D1487). Adapter: `feedback`.
4. **Explain, quoted and charged:** `POST /api/events/:id/recommendation/explain/quote` and `…/explain` (D1488, Part C). Adapter: `explainQuote`, `explain`.
5. **Topics:** `topics` on `POST`/`PATCH /api/events` and `topic=` on `GET /api/public/events` (D1487). It unblocks the editor's topics picker (NE1) and Discover's topic chips (ME5).
6. **The signals' read state** (`signals: { name: read|not_recorded|unreadable }`) for Tune's "What the picks use now" (D1487). Until it lands, each signal reads "Not recorded".
7. **The Axal / external source** on each event (`source`), for ME5's badge and External events (D1487, question 1 pending owner).
8. **Cover upload:** an R2 upload route for the event cover with the three crops (card 16:9, social 1.91:1, square), focal point, alt text and the cover's source (uploaded or generated) recorded (Part E; decision and migration from S1). Adapter: `uploadCover`.
9. **Four cover variants per draw**, with Regenerate and "More like this one" (Part E, on the router's `event_cover` image task). Adapter: `drawVariants`. One image per draw works today (#3935).
10. **Brand colours from the brand kit** for the generate prompt (Part E). Not drawn until a read is named.
11. **Cover alt text stored on the event** (`cover_alt`): the upload sends it, and the event has no column for it (Part E).
12. **The editor's live preview** of the My events card and the 1.91:1 social card (NE1). It needs the social card renderer to be callable for an unsaved event (#3705).
13. **"Create the meeting for me"** (Google Meet; Zoom once its app is verified) from the editor (NE1). It needs a route on the calendar connection.
14. **Scheduled publish** ("Schedule", NE4). It needs a `publish_at` field and a job. The board marks it "Later".
15. **Recurrence** (NE1). The board marks it "Later".
16. **The phone row** (ME11): `PhoneUpcoming` draws the row once D1487 answers. This needs no route, only the read switched on.
