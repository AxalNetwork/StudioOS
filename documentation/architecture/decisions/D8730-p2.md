### Worker (◇ #8730)

- `GET /api/advisor/preview-examples?shell=founder|exploring&track=…` (`routes/advisor.ts`, `previewExamplesFor`), admins only. Founder: the founder bank as a new founder sees it (week 1, no tiers, no milestones), two examples and the next two as Next up with their `page_target`. Exploring with no track: the role question. Exploring with a track: the first two of that track's 12 discovery questions. The envelope holds id, section, prompt, options and page_target only. It has no conversation, no answer and no count. The admin bank is never an answer, and any other shell gets 400 `preview_role_unknown`.
- An admin's advisor write carrying `X-Axal-Preview-Shell: founder|exploring` is refused with 403 `role_preview_read_only` ("Answers are not saved in a preview. Back to HQ to keep working as yourself.") by a router middleware that runs before every handler (`util/investorPreview.ts` `rolePreviewRefusal`, as D5915 does for Investor). Reads pass. A member, a support session and the investor marker are not refused by it: the header can narrow access but never grants it.
- `/advisor/progress` returns `profiling.applicable:false` for a still-exploring visitor, with or without a track, because `workingBankFor` only ever asks them the discovery bank.
- The discovery bank's `page_target` (and `writeRouter`'s `saved_to.page_url`) is `/exploring`, which exists. `/explorer/profile` never did. The role option now reads "I advise founders". `mapRoleAnswer` matches `advis`, so an answer stored with the old wording still maps to advisor.
