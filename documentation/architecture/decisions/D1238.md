### 1. The store (migration 618)

| Table | Holds |
|---|---|
| `deal_flow_entries` | one row per flow and deal: stage, owner, how it entered, when it entered and last moved, the pass (reason, when, when it comes back) and a note of up to 2,000 characters |
| `deal_flow_events` | what happened to each row: entered, moved, owner, passed, note. No note's text is kept here. |
| `deal_flow_dismissals` | "Not for me" on New for you, with an optional reason of up to 500 characters |

**Whose flow a row is (`scope_key`):**
- `c:<company_id>`: a firm. Every investor seat linked to the company reads and moves the same rows.
- `u:<user_id>`: an investor with no firm selected.
- The firm is the one `investorActiveCompany` resolves from `X-Company-Id`, the same reading `deals.ts` uses.

**The stages:** `sourcing`, `screening`, `diligence`, `commit`, `closing`, `passed`.

**How a row entered (`entered_via`):** `invited`, `requested`, `committed`, `added`, `introduction`, `syndicate`, `watchlist`, and `thesis`. Nothing writes `thesis` yet (§4).

**The CHECKs:** a passed row has its reason and its time; a revisit by date has its date; one row per flow and deal.

### 2. The routes (`routes/deal_flow.ts`, mounted at `/api/deals/flow`)

The mount sits before `dealContext` and `deals` in `index.ts`, so `flow` is never read as a deal id. The Professional gate on `/api/deals/*` covers it unchanged.

| Route | Does |
|---|---|
| `GET /` | the flow, newest move first, with `by_stage` counts and `scope` (`firm` or `you`) |
| `POST /` | adds a deal `{ deal_id, stage?, owner_user_id?, via_key? }`; 201 |
| `PATCH /:dealId` | moves the stage, changes the owner, or writes the note |
| `POST /:dealId/pass` | `{ reason, revisit?, revisit_at?, note?, via_key? }` |
| `GET /:dealId/events` | the row's events, oldest first |
| `GET /inbox` | New for you |
| `POST /inbox/:key/dismiss` | Not for me `{ reason? }` |

**Who may call them:** an Investor only. A founder, an admin or a partner gets 403 `investor_required`; signed out is 401. Another firm's rows are never read.

**Each row** (`services/dealFlow.ts` `shape`):
- `deal_id`, `venture`, `sector`, `round_status` (the deal's own `deals.status`), `stage`, `owner`, `entered_via`, `entered_at`, `stage_changed_at`;
- `days_in_stage`: whole days since the last move, or `null` when the time is missing, never 0;
- `ask`: the round's target, else its amount, else `null`;
- `pass`: `{ reason, passed_at, revisit, revisit_at }` while passed, else `null`;
- `note`;
- `can_open`.

**`can_open` is DEAL's rule.** It is true only when the investor is invited to the deal or has committed to it: the same two EXISTS as `investorHasDealRelationship`. A flow row never opens a deal by itself. A deal whose venture is deleted is left out.

**Refusals** are `{ error, code }` with one sentence. A failure that is not a refusal answers 503 `deal_flow_unreadable`. The log holds the outcome only.

### 3. Closing, the owner and the pass

**Closing follows a commitment.**
- Adding or moving a deal to Closing needs a commitment that is not withdrawn, by this investor or by a seat of the same firm.
- Without one: 409 `closing_needs_commitment`.

**The owner** is the investor themself, or an active investor seat linked to the same firm. With no firm, only themself. Anyone else: 400 `invalid_owner`.

**A move** is guarded on the stage it read. If the row moved meanwhile: 409 `flow_changed`. Each move writes a `moved` event and resets days in stage.

**Passed is reached only by the pass.** `POST /` and `PATCH` refuse `stage: passed` with 400 `use_pass`.

**The pass:**
- The reason is required: one of the studio's five (`services/dealPassTaxonomy.ts`: early, valuation, thesis, team, competitive). Otherwise 400 `reason_required`.
- `revisit` is `next_round` (the default) or `date`. A date must be after today; otherwise 400 `invalid_revisit`.
- A deal not yet in the flow is added as passed, entered through its New for you item when `via_key` names one, else `added`.
- A row already passed is 409 `already_passed`.
- **It never touches `deals`.** The round stays open for every other investor, and `deals.pass_reason` is not written.
- Moving out of Passed clears the pass from the row and keeps it in the events.

### 4. New for you (`GET /inbox`)

Every way in that is not yet in this flow, newest first. Each item is `{ key, source, entered_via, deal_id, venture, sector, round_status, at, message, can_open }`.

| Source | Read | Key |
|---|---|---|
| Invitation | `deal_invitations` still `invited`, to this investor | `invitation:<id>` |
| Room request | `investor_dealroom_members`, joined without an invitation | `room:<deal_id>` |
| Commitment | `commitments` not withdrawn, by this investor | `commitment:<id>` |
| Introduction | an accepted `intro_propositions` this investor sent, to a founder whose venture has a deal | `introduction:<id>:<deal_id>` |
| Syndicate | `syndicates` that are open and carry a `deal_id` | `syndicate:<id>` |
| Watchlist | this investor's `watchlist_items` converted to a deal | `watchlist:<id>` |

- With a firm selected, the investor's own invitations, rooms and commitments narrow to that firm, plus rows with no firm (`deals.ts`' reading).
- A deal already in this flow, a dismissed item, and a deleted venture are left out.
- **One failed source never blanks the list.** Each source answers alone; one that cannot be read is `sources.<name> = { available: false, unreadable: true, reason }` and the rest still list.
- **Thesis matches are not recorded.** `sources.thesis` is `{ recorded: false, reason }`: they come with the thesis fit, which no store holds yet.
- **An open syndicate is listed for every investor.** Today a syndicate has no invitation list. Its `can_open` stays DEAL's rule.

**Adding through New for you:** `POST /` and the pass accept `via_key`. It must be a current item for that deal, else 404 `inbox_item_not_found`. Its source sets `entered_via`.

**Not for me** (`POST /inbox/:key/dismiss`):
- hides the item for the whole flow (every seat of the firm), not for another firm;
- a key that is not a current item, a malformed key or a closed syndicate is 404;
- a reason over 500 characters is 400.
