## D967 — My events: the ticket drawer reads the host's name (#3350)

- **Status:** built by S09 for S03's task, 2026-10-26 (#3350, part of #2387). It closes a gap left by D1035 (#2876).
- **Basis:** `origin/main` at `90f63e3ae1`.
- **Migration:** none. `events.host_user_id` and `users.name` are already on `main`.

### The gap

The ticket drawer (MEV3) always drew "The host's name is not read here yet." D1035 recorded that "the host's name is in no read". That was true of `GET /api/events/:id`, the read the drawer uses. Only `GET /api/events/invitations` and the admin reads returned `host_name`.

### Built

- **Worker:** `GET /api/events/:id` now returns `host_name`, from the same bound `LEFT JOIN users host ON host.id = e.host_user_id` that `/invitations` uses.
  - It returns the name only, nothing else from the host's account.
  - It is null with no host, or when the host's account was removed.
  - The read's gate (`canViewEvent`) is unchanged.
- **Frontend:** the drawer's host line reads `host_name` through `hostLine` (`eventDrawersModel.js`):
  - **A name:** "Hosted by Rhea Host".
  - **Null or blank:** "Not recorded: this event has no host on record, or the host's account was removed."
  - **A failed event read:** "The host's name could not be read." with Try again. It names no host.
  - **While reading:** "Reading…".
- `HOST_NOT_READ` is removed.
