## D8508 part 2 — The live, read-only AI gateway check in the release preflight (#8508)

**Date:** 2026-11-26. **Status:** Built. The owner answered both questions on #8508 with A (2026-11-26): the release token gets the read access, and a missing Advisor gateway warns. It follows part 1 (`D8508.md`, the static check).

### What it is

`scripts/lib/aiGatewaysLive.mjs` holds two pure functions:

- `livePlan(toml, table)` reads one variable table of `wrangler.toml` and lists what to look up on the account.
- `readLiveState(plan, { request, timeoutMs })` does the looking up through a `request(path)` function the caller passes in. It makes the reads one at a time, each bounded by `timeoutMs` (10 s by default), with at most `MAX_PAGES` (5) pages for a listing.

| Item | Read | Present when |
|---|---|---|
| each gateway the table names (Advisor, deck, providers, agents) | `GET ai-gateway/gateways/<id>` | 200 with that id |
| `AGENT_AI_GATEWAY_TOKEN` on the table's Worker | `GET workers/scripts/<worker>/secrets` | the name is in the list (names only; a secret's value is never returned by this endpoint) |
| each account alias (`AGENT_CLAUDE_ALIAS_1..3`, `AGENT_OPENAI_ALIAS`) | `GET ai-gateway/gateways/<agents>/provider_configs` | a row with that alias and the slot's provider |

**States.** Each item ends up in one of three states:

- `present`;
- `missing`: a 404, or a complete listing without the name;
- `could not be read`: 401, 403, 429, 5xx, a timeout, a network error, an answer that is not the expected JSON, a gateway answering with a different id, or a listing longer than five pages.

**What a result contains.** A kind, a name taken from the table, a state, the routes that use the item and whether each route is switched on. It never contains a token, an account id, a path or the text of an answer, even when the transport throws an error that contains them. A test plants those markers to check this.

**Verdict (`liveVerdict`).**

- `stops`: missing on a route that is switched on and has no fallback. These are the providers gateway when `AI_PROVIDER_GATEWAY_OPENAI` is `on`, and the agents gateway, its token binding and its aliases when `AGENT_ENGINE` is not `off` and the inference stub is off.
- `warnings`: missing on the Advisor's or the deck's gateway. Both routes fall back to calling without a gateway, and owner answer A makes that a warning. The deck has the same fallback, so it is treated the same way.
- `unread`: reported as a warning, and never a stop on its own.

**In the release.** `scripts/check-ai-gateways-live.mjs` runs as the preflight step "Check AI gateways and the agents token on the account" in the `deploy` job, right after layer 1.

- It reads `[env.production.vars]` and calls the API with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` (owner answer A: the release token).
- It writes a table of states to the job summary, an `::error` for each stop and a `::warning` for each warning or unread item.
- It exits 1 only on a stop.
- If the token or account id is missing or malformed, it calls nothing and reports every item as `could not be read`.
