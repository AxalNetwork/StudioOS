- **Status:** decided and built by S09, 2026-10-25 (#2997, part of #2370, from S1's build-coverage check of D923 on 2026-10-25).
- **Basis:** `origin/main` at `dcd1386be1`.
- **Migration:** none.
- **Not here:** "Adjust terms" waits for O-TERMS and is filed separately.

Each gap was re-read on `main` before it was built. All five were still open.

### 1. The invitation record uses the Worker's agreement-ready rule

- **Was:** the record (PI3) worked out from R8 in the browser whether the Partner Services agreement could be sent. R8 is `GET /api/legal/esign/templates/partner_services`, and the rule was D923 §2's. The Overview's banner had used the Worker's answer since D927, so the two could disagree.
- **Now:** the desk reads D928's `GET /api/admin/partners/agreement-ready`, in place of R8. `agreementReady` maps its answer:

| The Worker's answer | The record |
|---|---|
| `ready: true` | ready |
| `ready: false`, with its `reason` and unfilled `fields` | not ready ("The Partner Services agreement is not ready, so it cannot be sent yet. …") |
| `ready: null`, a 503 `unreadable`, a paused read, any other failure | nothing is said either way |

The browser's copy of the rule (`FINALIZE_FILLS`, `TEMPLATE_REFUSALS`) is gone.

### 2. PI10b

- **The locked card.** New invitation reads the studio's own deal types, `GET /api/licence/mine/partner-deal-types` (D986 §6). A type the licence does not allow is drawn as PI10b draws it:
  - a dashed, muted card with ⊘;
  - the type's name;
  - "HQ has not granted Capital partnership to this studio." (the type's own name);
  - no checkbox, so it cannot be picked.
- **When every type stays open,** as D986 §3 and §4 rule:
  - the account is HQ-held (404 `no_licence`);
  - HQ has not set the list (`recorded: false`).
- **When the read fails,** nothing is locked, and the dialog says "Which deal types this studio may offer could not be read. Sending still checks them."
- **The refusal sentence.** A write the Worker refuses with 422 `deal_type_not_allowed` is said in the Worker's own sentence, in place: "This studio's licence does not allow Capital partnership. HQ sets which partner deal types a studio may offer." It is no longer "Try again".
- **The branch door.** D923 left the desk with no door on a branch shell until #2376 decided deal types per licence. D986 has now decided them, and the invitation write checks the branch's licence copy. So:
  - the branch Community index (`pages/branch/BranchCommunity.jsx`) lists Partner invitations as its sixth console, linking `/admin/partner-invitations` (served by `admin_partners.ts`, which has no HQ-only gate);
  - the branch shell's Community row lights on the desk.
- **Unchanged:** PI10b's other two lines, "This deal is no longer active, so it cannot be terminated." and "This invitation is already signed or revoked.", were already the 409s' words (D923 §2).

### 3. A voided deal's reason

D924 stores `partner_deals.void_reason`. `GET /deals`, `GET /deals/:id` and the invitation read's chosen deal already return it. It is now drawn on the deal record and on the invitation record:

| `void_reason` | Says |
|---|---|
| `invitation_revoked` | "Voided: the invitation was revoked before the deal started." |
| `link_lapsed` | "Voided: the agreement was signed after the invitation's link lapsed." |
| `admin_revoked` | "Voided: an admin revoked the invitation." |
| none (voided before D924) | "Voided. The reason was not recorded." |

### 4. Lapsed, with C1 and T1 agreeing

- **Was:** C1's closed line read "Closed: Signed · Lapsed · Revoked", while tile T1 read "Lapsed, not closed". A lapsed invitation is not closed: Resend renews it.
- **Now:** C1 reads "Closed: Signed · Revoked · Lapsed, not closed". The Lapsed count is in amber and still opens Invitations at Lapsed. Both use one constant, `LAPSED_NOT_CLOSED`.

### 5. The Deals list's joins, on the Worker

- **Was:** the Due diligence column matched each row against R9 (`dd.listCases`, 200 cases), and the lapsed cross-check matched each row against R1 (the newest 200 invitations). A row past either cap read "Not in this read".
- **Now:** D926's `GET /api/admin/partners/deals` joins both, per row, with bound SQL.
  - **`due_diligence`** is one of:
    - `{ state: 'not_opened' }`: no member yet;
    - `{ state: 'none' }`: a member with no partner case;
    - `{ state: 'case', uid, status }`: the member's open or in-review case first, else the newest.
  - **`invitation_lapsed`** is the deal's own invitation, lapsed by D927's rule (`isLapsed`). It is null when the deal has no invitation row: not known, never false.
  - The join's helper columns are not in the answer.
- **The page** reads both from the row (`ddFromRow`, `lapsedFromRow`), with R9's words. The desk no longer reads R9.
