## D8345 part 1 — Hosted readers: direct checks, early refusal and executor reconciliation (#8345)

Part 1 of #8345. It finishes the source work that `D8345.md` left open after #8366
(S39's readers) and #8368 (S09's ports) merged on 2026-11-24: S21's review items H2
(five reader checks with no direct test) and H4 (a refusing hosted admission made four
outbound calls first), and the reconciliation of the three readers' output with S09's
executor ports in `scripts/ci/runners/executor-isolation.mjs`. The issue's slot is S39;
the work was handed back to this session on 2026-11-27 after the earlier S39 holder left.

Nothing here makes hosted execution possible. `hostedBoundaryJob()` is still `null`,
S09's `inspectBoundary`/`inspectReadiness` still report `deniesHostControl: false`, and
no authority producer emits `hostedEvidence.includedEligibility`. Each of the three
still refuses on its own.

### What changed

1. **H4, early refusal** (`scripts/ci/runners/hosted-readers.mjs`). Both native
   documents (readiness at admission, the live boundary at execution) need the trusted
   `JobContainer` that serves the receipt's profile. `readProvenance` now checks that
   before anything else, so a hosted admission with no boundary job refuses with
   `hosted_native_job_unconfigured` before the authority read, the OIDC token request,
   the JWKS fetch and the two Actions reads. Before this change it made those four
   outbound calls and then refused. The same check still runs at inspection time,
   so a job whose profile changes after provenance still refuses.
2. **H2, direct reader cases** (`frontend/test/hosted_readers_8345.test.mjs`). Each of
   the five checks S21 found covered only by a later check in the composed path now has
   a direct case:
   - an envelope whose `active` is not exactly `true` (`false`, `'true'`, `1`, missing);
   - a `self-hosted` label in any letter case on the target job;
   - a failed provenance refresh leaves no earlier provenance for readiness or the live
     boundary;
   - one readers object refuses a second receipt binding (generation, plan or request)
     even when authority agrees with the second one;
   - two distinct Actions job IDs naming one check run refuse in either order.
3. **Reconciliation with S09's ports** (tests only, plus one comment). New cases run the
   real readers through S09's actual ports:
   - **Through the bridge's execution port.** `capacity-executor.mjs` in `verify-plan`
     mode calls `hostedExecutorDependencies` and `verifyExecution` with the argument
     shape `runner-execution.mjs` uses. The check before install and the recheck before
     test both pass, with exactly one authenticated receipt refresh each and none per
     reader document. Each of these refuses: unverified egress (S09's real value), no
     live instance, a document naming another instance, and a `github-8` request
     without its authority lane. The execution port never reads readiness.
   - **Document identities.** Each document carries the receipt's exact
     `childWorkflowSha`, with `executorSha` kept as the separate control revision. The
     readiness, live and lane documents all name the provenance job. The live document
     carries the job's own `instanceId` and `policyDigest`, readiness has no instance
     and names the same policy, and the inspection time is preserved, not re-stamped.
   - **The whole chain.** An authenticated receipt drives the real readers and
     S09's `executionIsolation` inside `runInContainer` with a `hosted` `JobContainer`
     on a synthetic engine, through install, the pre-test recheck, test, export and
     verified removal. A passing test exits 0. A failing test keeps its raw exit 3 as
     `test_failure`. Host control not denied at the recheck stops before the test
     (`boundary_recheck_failed`), and the container is still removed.
   - **The comment.** The one change to `executor-isolation.mjs` is a comment. It said
     no reader exists on `main`; it now says `capacity-executor.mjs` supplies S39's
     factory and the readers refuse before any outbound call while the boundary job is
     `null`. No code there changed.
4. **S21's note on the snapshot guard.** In the bridge snapshot-age test the target
   token is now issued ten seconds earlier. The −1 ms case is then refused only by the
   bridge's own non-future term (`at<=time`). Before, the token's `iat` refused it as
   well, so removing that term went unnoticed.

H3 is unchanged: inside one composed check the readers hold the instance fixed, but
across rechecks the same-instance guarantee comes from S09's `JobContainer`, the
pinned `verifyExecution` and the supervisor's identity compare. This part adds no
retained readers object.

### Out of scope here, and what still blocks the first pilot

These need operator or production authority and are not touched: the hosted
boundary job and its trusted policy and digest-pinned image; a verified egress rule
that makes `deniesHostControl` true; a native hosted canary showing candidate code
cannot read the OIDC token, job token, runner-agent credentials or host metadata;
a real target-job token; the included-eligibility producer and provider facts; S34's
pre-exposure continuation/restart gate; and every activation switch. Admission, pilot
callers, `AGENT_ENGINE` and Mac execution stay off. Included capacity stays zero.
No timeout, cap, lease, workflow, permission, secret, required check or resource
changed.
