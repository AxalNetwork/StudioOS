### 1. One registry of Studio blocks

`services/studioModules.ts` names today's blocks once (`STUDIO_MODULES`). Each block has a key, a profile, a title, a group, its default size, and the `/api/*` paths it reads.

| Profile | Modules |
|---|---|
| founder | `company_progress`, `eadwyn_questions`, `module_map` (cohort only) |
| investor | `usage_quota`, `deal_lifecycle`, `scored_opportunities`, `quick_stats`, `portfolio_glance`, `upcoming_events` |
| advisor | `today`, `storefront`, `engagements`, `consented_proof`, `earnings` |
| partner (the Operating Partner) | `firm_standing`, `firm_feed` (the P2 tiles and feed) |

- **Fixed, never placed:** `chat`, `strip` (founder only), `profile_card`.
- **Removed by #3698, never offered:** `founder_actions` ("Do these next") and `founder_activity` ("Activity across the platform"), so a member cannot add them back.
- **Not offered yet:** "Holding progress" and "What this adds up to" have no store (D564 `NO_STORE`). Owner question B, S1's pick.
- **Defaults** (`STUDIO_DEFAULTS`, one table in code) are today's blocks in today's order, so nothing moves for a member. This is owner question A, S1's pick. The canvas changes this one table.

### 2. Plan locks are derived, never written

The registry holds no tier. `lockOf(user, module)` checks each path the module reads against two paywalls, and the first lock wins:

- **Raise + Grow:** a path under `STUDIO_PREFIXES` locks the module unless `userMeetsTier(user, 'studio')`. It names the founder Raise + Grow plan.
- **Professional:** a path under `INVESTOR_PRO_PREFIXES` locks the module unless an `INVESTOR_PRO_EXEMPT` GET matches it or `userMeetsInvestorTier(user, 'professional')`. It names the investor Professional plan.

The two prefix arrays moved out of `index.ts` into `middleware/paywallPrefixes.ts`, and `index.ts` imports them. The paywalls mount exactly as before. The investor `PLAN_KEY` is now exported.

No block on /studio is plan-locked on `main`, so every module answers `locked_by_plan: false` today. The first module that reads a paywalled prefix is locked with no change here, and a test holds that with synthetic rows.

### 3. Whose Studio

- **A member's role names it.** A Spin-Out Lab member with no other Studio role is a founder, as in `Dashboard.jsx`'s Lab branch.
- **An admin previews one profile at a time** and must name it with `?profile=` (400 `invalid_profile` otherwise). This is owner question C, S1's pick. An admin's own Admin Studio layout is a later issue.
- **A member naming another profile** is refused (403 `profile_not_allowed`).
- **Any other account** is refused (403 `no_studio_profile`).

### 4. The store and the routes

`studio_layouts` (migration 687) holds one row per member and profile: an ordered JSON array of `{ key, size }`.

- **No defaults are stored.** With no row, the read answers the default and writes nothing.
- **`[]` is a saved choice,** distinct from no row.
- **Retention:** a row is kept until it is reset, and it goes with the account.
- **No activity log.** It is a display preference, so no `activity_logs` row is written (as with 465).

`routes/studio_layout.ts` is mounted at `/api/studio`:

| Method, path | Answers |
|---|---|
| `GET /modules` | `{ profile, modules: [{ key, title, group, default_size, cohort_only, locked_by_plan, plan }] }` |
| `GET /layout` | `{ profile, source: 'saved' \| 'default', layout: [{ key, size, locked_by_plan }], updated_at, dropped }` |
| `PUT /layout` | Replaces the saved layout; answers like the read. |
| `POST /layout/reset` | Deletes the row; answers the default. Idempotent. |

- **What `PUT` refuses,** writing nothing:
  - `invalid_layout`: not a list, or an entry that is not exactly `{ key, size }`;
  - `invalid_size`;
  - `too_many_modules`: more than 12;
  - `duplicate_module`;
  - `unknown_module`: fixed, removed, other-profile and unknown keys alike;
  - 402 `module_locked`, naming the plan.
- **What the read does with a saved key:**
  - one this profile no longer offers is left out and named in `dropped`;
  - one that is now plan-locked stays, marked `locked_by_plan: true`.
- **A stored row that cannot be parsed** is 500 `layout_unreadable`, never a silent fall-back to the default.
- **Every refusal** goes through `refuse()`.
- **The member is always the session's.** No route takes a user id.

### 5. The client

`frontend/src/lib/api/studioLayout.js` exports `studioLayoutApi`: `modules`, `layout`, `saveLayout` and `resetLayout`. It sends `profile` only when given, and is re-exported from `api.js` in alphabetical order (D527).
