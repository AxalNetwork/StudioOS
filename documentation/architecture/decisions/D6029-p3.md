## D6029 part 3 — Build › Tools in the sidebar (#6029)

The last part of #6029. D6029.md built BD23's sidebar list without Tools because Build › Tools and Operating systems listed tools twice. D5078 (#5078, merged in #8208) settled that: tools are one section of Operating systems, `/build/operating-systems#tools`, beside Systems and Cadence. This part adds the sidebar entry that BD23 draws after Progress.

- **The entry:** `BUILD_SUBPAGES` in `frontend/src/sidebarConfig.js` gains `{ to: '/build/operating-systems', hash: '#tools', label: 'Tools', end: true, keepVenture: true }` after Progress and before the Modules heading. There is one Tools entry, it points at D5078's section, and nothing adds a second tools page or store.
- **The venture:** the link carries the page's `?project_id=` through `ventureQuery` from `pages/cycles/operatingSystemsModel.js`, D5078's own rule (a numeric `project_id` or `project`, else nothing). It reads `/build/operating-systems?project_id=7#tools`, as the phone and tablet picker already does. The other entries keep their plain addresses.
- **What lights:** a section entry lights on its own path and hash only (`subpageActive(child, pathname, hash)`). On `/build/operating-systems#tools` Tools is lit and Operating systems is not; on the page without `#tools`, or on `#cadence`, Operating systems is. `activeSubpage` picks the one lit entry, so exactly one link carries `aria-current="page"`.
- **The row's `match`:** unchanged. The hashed entry is left out of it, so `/build/operating-systems` is listed once.
- **Unchanged:** Plan and Progress, the desktop fallback tabs when the sidebar is closed or collapsed, the phone and tablet Tools entry (`CYCLES.build.history`), and the Operating systems page itself.

Pinned by `frontend/test/build_nav_bd23_6029.test.mjs`: the list order with Tools after Progress, one Tools entry at D5078's section, the venture carried and a non-numeric one dropped, which entry lights for each hash, one `aria-current`, and the sidebar passing `hash` and `search`.
