## D4829 — Practice operating cockpit (#4829)

Implements the owner-approved Practice v2 PX-00 and PX-10 boards (D4874) on `/practice`: Needs attention, Today, Practice health and Recent clients, in that order. The shell carries one heading, “Run my advisory business”, and the operating subtitle. New engagement opens the existing creation form; Share booking link opens the Sessions booking-links section. The existing first-use checklist (D4830) retains control while setup has a recorded missing step.

No new store or API is introduced. Requests and confirmed sessions read paginated bookings, engagements read their own store, delivered counts use sent version timestamps, and money uses the existing ledger and its canonical `earningsCards` definitions. Money is explicitly all time and recorded, not a bank balance. Calendar boundaries use the Practice timezone; an unset timezone explicitly falls back to UTC, while an unreadable or invalid timezone cannot produce a confident Today or delivered-month count. Partial lists name their bound; a failed source has its own retry and never becomes zero. A retry cannot overwrite a newer read.

Attention links carry an exact record kind and numeric id to its existing zone. A small read-only focus bridge waits for that zone’s matching record and focuses it without performing a write. It reports when the record cannot be located. This avoids editing Delivery or Sessions, whose redesigns remain separately owned. Recent clients join by linked account id and open D4831’s shared Client Sheet; same-name accounts are never combined. Unlinked clients remain accessible from their engagement records.

The old five-table board factory remains for its existing contract consumers; the mounted root uses the new cockpit. Long source explanations sit behind a disclosure. Existing zone order, shell, navigation and rail are retained. Intentional differences from the fixture artboard: real counts replace fixture numbers, “Ready to send” uses D5316’s explicit mark, deadlines appear on their actual recorded day, and money labels state the all-time ledger basis. No claim is made that a pending session is confirmed, a completed session is a delivery, or recorded collection is a payout.

Sent activity and historical client recency use each version’s immutable recipient (D4684), never the work product’s current client after relinking. An older version without a recorded recipient says so. A completed session or received delivery is a recorded client relationship, and partial engagement reads cannot classify a client as a prospect or former client.

Today also shows each client open and acceptance on its own recorded day. These receipts never increase the delivered-month count, which remains versions actually sent.
