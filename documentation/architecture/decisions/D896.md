## D896 — The deck's sources: DECK_SOURCES, the sources read, refresh, and the boards that draw them (#2675)

- **Status:** built by S15, 2026-10-24 (#2675, part 2 of #2434). Stacked on D894's integration (#2685).
- **Canvas:** PD4, PD10, PD10b and PD11 of the owner's "Pitch Deck Studio" (`design/incoming/`).
- **Migration:** none. Bindings live in the slide JSON.
- **Why:** #2434 asks that every figure a card shows be read from a store StudioOS already has, with its source, date and grade. This part builds the read, the stale check and the four boards. Later parts mount them: part 3 the Sources step, part 4 the panel and the chips on cards.

### 1. One slot per row

`cloudflare-worker/src/services/decks/sources.ts` holds `DECK_SOURCES`, seventeen read-only adapters, one for each row of #2434's "Sources a card binds to" table, covering Validate, Build, Raise, Grow, Team and Scoring. Each adapter owns a fixed list of slots: 32 slots in all, 2 of them optional (Scoring). So "31 of 40 slots" counts the same slots for every venture.

Each item is `{ source_key, area, module, label, value, unit, of?, as_of, grade, source, href, record_ref, snapshot_hash, state, optional? }`.

| `state` | Meaning | Counted |
|---|---|---|
| `recorded` | code read a value | filled, by its grade |
| `not_recorded` | the store holds nothing; `href` is the module that fills it | a slot, not filled |
| `unreadable` | the store failed to read; only its own adapter's slots | a slot, not filled |
| `withheld` | Mercury, for anyone but the venture's founder | not a slot for this reader |

A missing value is `not_recorded`, never 0. A recorded zero, such as no release in 90 days with GitHub connected, is a real 0. No model runs.

### 2. Grades in one function

`sourceAndGrade(origin)` turns a store's origin into a Source label and a default grade. Until SCORING (#2428) lands its "Source to default grade" mapping, the function follows #2434's table, and every part calls this one function.

| Origin | Source | Grade |
|---|---|---|
| a connected tool (Stripe, Mercury, GitHub, Carta) | Connector | Measured |
| counted from platform records | Recorded | Measured |
| a recorded interview session | Recorded | Measured |
| an interview logged by hand | Recorded | Sourced |
| typed, with a file behind it | Document | Sourced |
| counsel-approved round terms | Document | Reviewed |
| typed, no source | Typed | Stated |

- **A count is as strong as its weakest member.** One hand-logged interview makes the interview count Sourced. One must-have without a GitHub link makes the count Stated.
- **Round terms are Reviewed only while counsel's approval covers them.** The approved hash must equal the terms hash, as `roundCalls.ts` checks, and that approval grades the round's target and close too.
- **Stripe wins.** Its latest snapshot is read before the founder's typed one, and a typed one is used only when Stripe holds none.

### 3. The routes

`cloudflare-worker/src/routes/deck_sources.ts` is mounted in `index.ts` after `deck_share_actions` and **before `decks`**. Hono matches routes in registration order, so `decks`' `GET /:id` would otherwise answer `/sources`, as it answers `/methods` and `/brand` today (worker map §0.1).

- **`GET /api/decks/sources?project_id=[&include=scoring]`** returns `{ project_id, items, coverage }`. `coverage` is `{ slots, filled, by_grade, not_recorded, unreadable }`, and only `recorded` items count as filled.
- **`POST /api/decks/:id/refresh`** walks the version's bindings (on a slide, a field or a block) and compares each one's `snapshot_hash` with its store's item. Each binding comes back as:
  - `fresh`: the store holds the same value;
  - `stale`: the store holds a different value, or a newer snapshot of the same one;
  - `gone`: the store no longer holds a value;
  - `unknown`: the store could not be read, or is withheld from this reader.

  Refresh **writes nothing**. Re-reading a value into the deck is the editor's Save (`PUT /api/decks/:id`, a new version), and "Keep as of" is simply not saving. Neither route writes, so neither logs a `raise.pitch-deck` row.
- **`snapshot_hash`** is the first 12 bytes, as hex, of the SHA-256 of `[source_key, record_ref, [value, of], as_of]`.
- **Who:** `projectOwned` decides, as for every deck read. Mercury is read only for the venture's founder: from their own connection, in the startup's active company, and outside a support session, the same rule as `cycle_raise`'s `mercuryFounderOnly`. For anyone else, an admin included, those four slots are `withheld`.

### 4. Scoring

Owner question 4 was drawn A: Scoring is off by default and appears as a band, never a number. The two Scoring slots are left out unless `include=scoring` is passed. Neither band is defined yet: #2428 defines the scorecard band and #2433 the Product-market fit band. So both slots read `not_recorded` today, and `score_snapshots.total_score` is never read. The scorecard dialog says investors would see nothing, and its Include button is disabled until a band is recorded.

### 7. Departures from the canvas

- **Module names are the Worker's.** The canvas's "Validate › Interviews" is "Validate › Customer research", "Pain map" is "Problem discovery", and "Grow › Revenue" is "Grow › Revenue and traction", because those are the modules that exist.
- **Theme titles are not shown as labels.** The top pain theme's slot is "Top pain theme", with its interview count; the title is the founder's own words and stays in its module.
- **PD4 starts with every recorded row chosen.** A row with no value cannot be chosen.
