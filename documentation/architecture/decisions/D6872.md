## D6872 — Grow obligations: compliance and other are two stored event types (#6872)

Issue #6872, after #6122 part 1 (D6122). Grow › Company's obligation form offers six kinds. Before this, `growWriters.ts` stored both `compliance` and `other` under `compliance_events.event_type = 'other'`. The duplicate guard is `UNIQUE(project_id, event_type, due_date)`, so a compliance obligation and an other obligation could not fall on the same day: the second was refused as a clash of a kind it was not. The owner chose answer B: store them apart.

**The mapping.** `OBLIGATION_EVENTS.compliance` is now `'compliance'`; `other` stays `'other'`. The other four kinds are unchanged (`governance` → `board_meeting`, `risk`, `culture`, `tax` → `franchise_tax`). `event_type` is free text with no CHECK, so the new value needs no schema change. The duplicate guard now treats the two kinds apart: one of each can be due on the same day, and a second of the same kind is still refused with the same 409.

**Reading the kind back.** Grow's list, its record, the kind filter and the due strip all read `obligationKind`, which prefers the stored `kind` column. A row with no `kind` and `event_type` `compliance` or `other` reads as compliance, as every kind-less `other` row did before. Calendar → Compliance names the type from `TYPE_WORDS`, which gains `compliance: 'Compliance'`, so the deadline's pill says Compliance or Other, and New › Compliance deadline's Type list offers both.

**Calendar's own writes.** `POST /api/compliance/events` now stores `kind` when the type is `compliance` or `other`, so a deadline made in Calendar as Other reads in Grow as Other, not Compliance. Every other type keeps `kind` empty and reads as it did. Completing a repeating deadline at `PATCH /api/compliance/events/:id` copies `kind` to the next occurrence, which it did not before. Without that, a rolled-forward Grow obligation would lose its kind.

**Existing rows.** Migration `202611161117_6872_obligation_event_types.sql` moves the rows that can be told apart. Grow wrote every compliance obligation with `kind = 'compliance'` over `event_type = 'other'`, and nothing else writes that pair, so those rows move to `event_type = 'compliance'`. A row that would clash with a compliance row already due that day stays where it is. It still reads as compliance through its `kind`. A row with `event_type = 'other'` and no `kind` cannot be told apart, because Calendar and older writers stored it without one. It keeps its type and reads as compliance, as before. The migration only updates rows and can run twice.

**Not changed.** Company compliance tasks (`services/compliance/companyTasks.ts`) are company-scoped and never write either Grow kind, so their roll-forward and word list are left alone. `growCycle.ts` and `growDaily.ts` read obligations by title, date and state, not by kind, so they need no change.

Tests: `cloudflare-worker/test/obligation_event_types_6872.test.ts` and `frontend/test/obligation_event_types_6872.test.mjs`.
