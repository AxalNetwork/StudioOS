## D6131 part 3 — Draft, complete and prefill investor onboarding (#6131)

**Decision date:** 2026-11-27. D6128 and its owner answers govern the flow.

The Eadwyn draft endpoint reads only the signed-in member's investor
progress. It assembles a free proposal from the recorded check band,
stages, sectors, regions and exclusions. It uses a deterministic
formatter, so it needs neither model credits nor a provider request.
Account and entity details, accreditation, existing thesis text and fund
interest do not enter the draft. Accept or Edit puts the proposal in the
editable thesis field. Continue persists it. Discard leaves the field as it was.

Investor Finish sends the reviewed answers to the existing completion
route. A D1 transaction writes the canonical profile with the Settings
writer's normalization and omitted-field behavior, reads back the saved
profile via the completing statement, then marks onboarding complete.
The wizard uses the returned profile for the ending and the saved-answer
display. Any refused or unreadable finish leaves Review available for
retry. Old clients sending only a flow must reload with their saved
answers. Reopening a completed wizard reads the canonical profile. A
legacy completed record without a saved profile offers an explicit save.

The fund application offers prefill only after reading that the caller
has no existing application and has a saved ready-to-commit profile.
Angel, family office, institutional LP and fund GP map to individual,
family office, institution and other. A valid dollar target and note
are editable. A target outside $50,000–$2,000,000 is flagged and the
application target stays empty. The application requires fresh
accreditation confirmation. Existing applications keep their own data
and status.

No schema or provider configuration changes. Independent review and hosted
CI cover publication when the source lands.
