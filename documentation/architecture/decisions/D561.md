## D561 — Learning videos: a Super Admin upload to R2, and gated playback with Range

**A Learning video can now be uploaded to R2 rather than linked.** The Super
Admin uploads the file in parts into the private `FILES` bucket, under
`learning/videos/<item uid>/`, and the upload is attached to its item.
Members play it through `GET /api/learning/items/:uid/video`. That route asks
`canSeeLearning`, answers HTTP Range with 206 and sends
`Cache-Control: private`. Issue #1162, epic #1157. No migration: the
`video_source` and `r2_key` columns came with D557 (migration 388).

**The upload.** These routes live in the new `routes/learning_video.ts`, are
mounted at `/api/admin/learning` and are Super Admin only (the `gate` every
authoring route uses).

| Step | Route | Checks |
| --- | --- | --- |
| Start | `POST /items/:uid/video/uploads` `{content_type, size_bytes}` | the item exists and is a video; the type is `video/mp4` or `video/webm` (415); the size is at most 2 GB (413). Makes the key and returns `key`, `upload_id`, `part_size` and the part count. |
| Part | `PUT /items/:uid/video/uploads/part?key=&upload_id=&part_number=` (raw body) | the key belongs to this item; the part number is 1 to the maximum; there is a Content-Length, it is at most 95 MB, and the body matches it. |
| Complete | `POST /items/:uid/video/uploads/complete` `{key, upload_id, parts}` | the key belongs to this item. After R2 completes, the object's **real** size and type are checked. One over 2 GB, or of another type, is deleted and refused. Otherwise the item gets `video_source = 'r2'` and `r2_key`, any link is cleared, and `logAdminAction` records the actor, the key, the size and the key it replaced. |
| Abort | `POST /items/:uid/video/uploads/abort` `{key, upload_id}` | the key belongs to this item. |

- **Why the parts are 95 MB.** A Worker request body is capped at 100 MB, so
  a 2 GB file goes up as at most 22 parts.
- **Why no upload table.** Each step after the first is handed the key, and
  `keyBelongsTo` checks it sits under the item named in the path, as one
  32-hex-character file name with an allowed extension. So a step cannot
  complete, abort or attach another item's object.
- **Uploads that never finish.** R2 aborts them on its own after seven days.
- **No bucket binding.** A deployment without `FILES` answers
  `503 video_storage_unavailable` on every step.

**Playback.** `GET /api/learning/items/:uid/video` is mounted at
`/api/learning`.
- **Who may play it.** `canSeeLearning` decides, exactly as for the item: a
  draft, archived or `program` video plays only for the Super Admin.
- **Refusals look like absence.** A refused item, an item with no uploaded
  video, and a missing object are all `404 not_found`, so the route never
  confirms that a hidden item exists.
- **Range.** One range (`bytes=a-b`, `bytes=a-`, `bytes=-n`) is answered with
  206, `Content-Range: bytes a-b/size` and its Content-Length. A range past the
  end is 416 with `Content-Range: bytes */size`. No range, a malformed one, or
  several ranges get the whole object as 200. RFC 9110 allows that, and
  players never need multipart/byteranges.
- **Headers.** `Accept-Ranges: bytes`,
  `Cache-Control: private, max-age=3600` and `X-Content-Type-Options: nosniff`.
- **Cookie auth.** The session cookie authenticates the request, so a
  `<video src>` on the same origin plays it.
- **No bucket URL is ever sent.** The member item read adds
  `video_stream_url` (this route's path, or null) and still never selects
  `r2_key`.

**Linked and uploaded videos together.**
- **A link replaces an upload.** Setting `video_url` through `PATCH /items/:uid`
  sets `video_source = 'url'` and clears `r2_key`; the sweep then removes the
  object.
- **Clearing a link leaves an upload alone.** Setting `video_url` to null
  leaves an uploaded video where it is. Before, it cleared `video_source`
  whatever it was.
- **No claiming an upload by hand.** A field write that names
  `video_source: 'r2'` is refused (`video_source_by_upload`). The previous code
  was `video_upload_not_built`, and the D557 test that pinned it is re-aimed.
- **Publishing.** A video publishes with a link or an uploaded file.

**Cleanup: a later sweep, not a delete on archive.** An archived item can be
published again, so archiving keeps its video.
`sweepLearningVideos` runs from the per-minute cron at 03:40 UTC, on every
deployment, against that deployment's own rows. It deletes an object under
`learning/videos/` when:
- its item no longer exists;
- its item does not point at it (replaced by a newer upload or by a link), and
  it is over a day old, so an upload that has just completed is never swept;
- its item has been archived for over 30 days, judged by `updated_at`, which
  the status change sets. That item's `video_source` and `r2_key` are cleared,
  so publishing it again is refused until a new video is attached, rather than
  publishing a player with nothing behind it.

Items have no delete route, so a deleted item is covered by the first case.

**Clients.**
- `frontend/src/lib/api/adminLearning.js` gains `startVideoUpload`,
  `uploadVideoPart`, `completeVideoUpload` and `abortVideoUpload`.
  `uploadVideoPart` sends a Blob slice as `application/octet-stream`.
- The player and the studio's upload are Session 1's (#1163), built against
  these routes.

**Tests.** `cloudflare-worker/test/learning_video_d561.test.ts` (12 tests) runs
the routers on node:sqlite (baseline plus migrations to 388) with an in-memory
R2 that implements multipart uploads, ranged get, head, list and delete.
- **Gates.** Only the Super Admin uploads; a plain admin and a member get 403.
  A draft or `program` video is 404 for a member and plays for the Super Admin.
  A signed-out request is refused.
- **Uploads.** A wrong type is 415. Over 2 GB is 413, and exactly 2 GB is
  allowed. A reading item is 409. Another item's key is refused on part and
  complete. An oversized part is refused. A completed object over 2 GB is
  deleted. An aborted upload is closed.
- **Records.** Completing sets `video_source`, `r2_key` and a null
  `video_url`, joins the parts in order, records the actor, and lets the item
  publish.
- **Playback.** `bytes=2-5` answers 206 with `bytes 2-5/10`, length 4 and
  those bytes. Open-ended and suffix ranges work, a range past the end is 416
  with `bytes */10`, and no range is 200 with the whole object. The headers are
  `private`, the content type and `Accept-Ranges`. The item read gives the
  stream path and never the key.
- **Links.** A link replaces an upload; clearing a link keeps one.
- **`parseRange`.** Edge cases.
- **The sweep.** It keeps the live object, an object replaced a moment ago,
  and a recently archived video. It deletes an object replaced over a day
  ago, an object whose item is gone, and a 45-day-archived video, and clears
  that item.
