### 1. The editable PowerPoint

The PowerPoint download stays D901's one picture per card. The Google path uses its own writer, `pptxEditable.ts`, which places every D898 block where the print card draws it. D1112 fixes that card at 1920 × 1080, with 3% padding (CSS percentages are of the width, on every side), a 24 px gap, and 12 columns by 6 rows. One card pixel is 6350 EMU and half a point.

- **Text, metrics, video, audio, links and graphics** are text boxes. A metric with no figure reads "Not recorded", never 0. Video, audio and link blocks show their label and address as text.
- **An image** is a picture when its first bytes are PNG, JPEG or GIF, the formats both PowerPoint and Slides read. An image that could not be fetched, or is WebP, says "This image could not be included in the file." in its place.
- **A chart** is a picture of its own block on the print page: a Browser Rendering screenshot clipped to the block's rectangle, from a signed print link. When no browser is bound, the answer is not a PNG, or the deck has more than 30 charts, the chart is its type and series in words, as the HTML file writes it. Nothing redraws a chart, so the file can show no figure the deck does not hold. D1112 notes that the print page itself names a chart's series rather than plotting them; the picture shows exactly what the print page shows.
- **A card made of fields** (D897), and the Sources appendix, use the text writer's stacked frames (`buildSlideXml`).
- **Speaker notes** are each card's notes when asked for, "No notes on this card." for a card without any, and empty when not asked for.
- **The answer** counts the charts pictured and written as text, and the images placed and not placed. The dialog says when a chart went in as text.

### 2. The route

`POST /api/decks/:id/export/google-slides` takes `{notes, sources}`.

**Who.**
- A signed-in member, never a support session (D1091's `member`, answering 403 `support_session_refused`).
- The D895 deck check that PDF, PowerPoint and HTML use.
- D1091's Workspace scope for the deck's venture (`context`): the member's connection is active and its company is enabled. The member gets 409 `google_not_connected`, `workspace_not_allowed` or `company_not_enabled` otherwise.

All of these refusals come before any Google call. A file over 5 MB, Drive's multipart limit, is refused with 413 `presentation_too_large` before any call as well.

**Order.**
1. Build the file.
2. Create it in Drive. The id Drive returns is what the ledger keeps.
3. Record it in one batch: one `deck_exports` row (`google_slides`, the uploaded file's SHA-256, the Drive id in `external_ref`) and one `raise.pitch-deck` audit row ("Deck exported to Google Slides", naming no figure, title or file).

If that batch fails, the presentation already exists, so the route answers 503 `export_not_recorded_created` with its link rather than claiming nothing happened. A Google failure records nothing: 403/401 answer `workspace_not_allowed`, 429 `google_rate_limited`, anything else `google_not_created`. No provider body reaches an answer or a log.

**Answer:** `{created, file_id, url, converted, charts, images, content_hash}`.

### 3. The one write

`driveCreate.ts` holds `GOOGLE_WORKSPACE_WRITES`, a frozen map with one entry. The entry is `files.create`: a POST to `https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart`.

- **No file id in the path**, so the call can only create. There is no update, copy, delete, permission or sharing call.
- **No `parents`**, so the file lands in the member's My Drive.
- **The metadata** asks for `application/vnd.google-apps.presentation`, which tells Drive to convert the upload.
- **Under `drive.file`**, Google lets the app reach only the files it created or the member chose.
- **The transport** is a single call with no redirects, a ten-second limit and a 64 KB answer cap. A file id that fails D1091's `validFileId` is not a created file.

D1091's `workspace.ts` stays GET-only. Its guard test is unchanged and still passes, and D904's test scans the whole Worker: `driveCreate.ts` is the only file that uploads to Drive. The Super Admin Research Sheets writer (`fundSheets.ts`) is separate, with its own grant and store (D1091).

### 4. PD17's Google states

Google Slides is now offered. When it is chosen, the dialog reads D1091's connection (`googleWorkspace.mine()`) once, and shows one of three states:

- **Not connected, or files not allowed:** "Connect Google to create this presentation in your Drive. Axal VC creates only the file you export." with "Connect Google ›" to `/account/connectors/google_workspace` (D1091's GW1/GW2), and Export disabled. A refusal that means "connect first" (including `company_not_enabled`) brings the link back.
- **Connected:** before the write, "This creates a new presentation of vN in your Google Drive and records the export in this venture's history. Axal VC creates only this file and changes nothing else in your Drive. Nothing is shared." Afterwards, "Created in Google Slides · Open ›".
- **Unreadable:** said in words. Export stays possible, because the Worker answers if Google is not connected.

Three more rules:
- A file Google kept as PowerPoint says "Created in your Drive as a PowerPoint file: Google did not turn it into Slides.", and is never called a Slides deck.
- Open links only to `https://docs.google.com` or `https://drive.google.com`.
- Every refusal is a sentence (`exportFailure`). The Worker answers codes only.

The copy says "Axal VC", as D1091's Google screens do, where #2683's draft said "StudioOS".
