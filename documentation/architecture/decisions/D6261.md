### Why

An ask spent a paid slot and then nothing could happen to it. No route changed `investor_introductions.status`, the founder was never told, and the Asked view said "nothing moves it yet".

### What changed

**Statuses.** These are the only four, listed in `ASK_STATUSES`, and the page labels exactly these:

| Status | Written by | When |
|---|---|---|
| `pending` | `POST /api/introductions/request` | the investor clicks Send ask |
| `accepted` | `POST /api/introductions/asks/received/:uid/accept` | the recipient founder clicks Accept |
| `declined` | `POST /api/introductions/asks/received/:uid/decline` | the recipient founder clicks Decline |
| `withdrawn` | `POST /api/introductions/asks/:uid/withdraw` | the investor clicks Withdraw ask while it is pending |

Only `pending` moves. Each move is one conditional `UPDATE … WHERE status = 'pending'` that names the caller. A withdraw racing an answer therefore has one winner, and the loser gets 409 `ask_already_answered`. The move writes `decided_at` and `decided_by`, the user who clicked.

**Who answers.** `recipient_user_id` is resolved once, when the ask is made, before any slot is spent. It uses the Asked view's precedence: a founder account, else the venture's founder record, else the founder record. A record names its lowest user id, as D702 resolves it. If no founder account exists, the column is null, nobody can answer, the row says `answerable: false`, and the investor may withdraw it. An ask that would land on the investor's own account is refused with 400 `cannot_ask_self`, and nothing is spent.

**Another member's ask.** Every read and write names the caller: `investor_user_id` to withdraw, `recipient_user_id` to answer or list. Answering also needs the founder licence. Anyone else, including the investor trying to answer their own ask and the founder trying to withdraw it, gets 404 `ask_not_found`, the same answer as for an unknown uid. A support session (`impersonated_by`) gets 403 for withdraw and for an answer.

**Who is told, and only after a click.** In-app notices only (`channels: ['in_app']`). The investor's Send ask tells the founder (`intro_ask`). The founder's Accept or Decline tells the investor (`intro_ask_answered`). Both link to `/network/introductions?intro=<uid>&kind=ask`. A failed notice does not undo the write. Asks recorded before this change are not announced to anyone.

**`kind=ask` in the destination contract (D4609).** Both halves name the third kind, so a proposition or teammate-desk surface never claims an ask's uid. The investor workspace opens the Asked view only when the link names `kind=ask`. A legacy link with no kind stays where it was.

**The slot.** Withdrawing returns a slot only when the ask was spent in the current quarter (`quarter` matches the counter's quarter), and never below zero. An ask from an earlier quarter is withdrawn with `slot_returned: false`, because that quarter's allowance has ended. A declined or accepted ask keeps its slot spent. The legacy quarterly allowance (Free 3, Plus 10, Professional 25, Institutional 100) is unchanged.

**Accepted opens the NDA step, and is not the NDA.** `GET /api/introductions` returns `nda_founder_user_id` on an accepted row and on no other. The Asked view then offers "Start the mutual NDA", which calls the existing `POST /api/trust/intro/request` on the investor's click. That route mints the 3-way envelope and tells the founder, as before. Nothing is signed, and no introduction is recorded as made, by an acceptance. The route's old comment, which said the frontend called the trust route right after the ask, was not true of the code and has been corrected.

**Screens.** Asked view: each card shows its status label, a sentence on what it means, the decision date, Withdraw ask while pending, and the NDA button once accepted. Founder `/network/introductions`: a new "Investor asks" card lists the asks addressed to them, with investor name, message and state, and Accept and Decline on pending rows only. An unreadable list says "unavailable", never "No investor has asked". The page's rail no longer claims it accepts and declines nothing. No canvas covers these two parts yet. They reuse the existing card and table styles, and the Network v2 Investor canvas (D6256) can restyle them.

### Asks already recorded

They keep their status (`pending`), their quarter and their spent slot. The migration gives each one the founder who may now answer it, by the same precedence. The founder sees it in Investor asks and can accept or decline it. The investor can withdraw it. A slot comes back only if it was spent in the current quarter. No notice is sent for them, because nobody clicked anything.

### Not in this change

- #7673: the all-role intro service with external targets. This change does not alter that model or the allowance.
- Email or Slack notices. The ask stays in-app only.
