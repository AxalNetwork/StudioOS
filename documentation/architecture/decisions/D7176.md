### The Worker (each ◇ item of D7042)

- **`competitor_sources.origin`** — `'fetched'` or `'manual'` (migration `202611180053_7176_competitor_saved_versions.sql`). `POST /:id/candidates/:cid/sources` writes `'manual'`. Every row on record before the migration reads `'fetched'`: the store could not tell an attached source from a fetched one until now.
- **Refresh** (`POST /:id/refresh`) fetches every stored source again (`fetchPage`, `refresh: true`) and does nothing else: no discovery, no model, no write to `output_json`, the candidates, the notes, the conclusion or the edited flags. A page that answers moves its row's status and date (and, for a fetched row, its title); a page that does not keeps its row as it was and is listed in `refresh.results`. The writes go in one batch at the end; a failure answers 503 `refresh_failed` and changes nothing. A manual row is re-checked, never deleted. Owner answer A: refresh runs no model, so it logs no AI run (the D778 test now says so).
- **The analyst's work survives.** Notes and the new conclusion live in `output_json` (`notes`, `conclusion`); per-section edited dates live in `competitor_analysis_outputs.sections_edited_json`, which a save sets for each generated section (`market_summary`, `gaps`, `wedge`, `next_actions`) whose text it changes. `persistResult` keeps manual sources and lays the stored notes and conclusion over a run's output; since this change only a new analysis comes through it.
- **Versions.** `competitor_analysis_outputs.version` (default 1). A save of the title or the output (`PATCH /:id`) claims the next version; `If-Match` (or `base_version` in the body) naming an older one answers 409 `version_conflict` with `current_version`, and writes nothing. The superseded version's record is kept in `competitor_analysis_versions`. A save with no version named (an older client) still counts as one, unchecked. Candidate, source and category writes are not saves and do not move the version.
- **Rerun is a proposal.** `POST /:id/rerun` runs discovery and synthesis and answers `{ proposal_id, base_version, candidates: { add, remove }, output: { <field>: { now, proposed, changed, edited_at } }, kept }`. It writes only `competitor_rerun_proposals` (one pending proposal per analysis): never the status, the inputs or the body. A competitor added by hand, one carrying a source attached by hand, one the venture tracks and one a kept signal points at are never proposed for removal; notes and the conclusion are never in `output`. A failure answers 503 `rerun_failed` naming the version that is still on record.
- **Apply** (`POST /:id/rerun/apply`, new) takes `If-Match: <base_version>` (428 `if_match_required` without it) and `{ proposal_id, add, remove, output }`. A stale version or a later save answers 409 `version_conflict`; a superseded or applied proposal 409 `proposal_gone`. Only the ticked additions (with their sources and signals), removals and rewrites are written, as one new version; an accepted rewrite clears that section's edited date; the status becomes complete and the proposal's inputs are stored. The client method is `competitorReviewApi.apply` in `frontend/src/lib/api/competitorReview.js` (`api.js` is a frozen hub).
- **Export by version.** `GET /:id/export?format=md|json&version=N` answers the current record, or the kept copy of an older version (404 `version_not_found`, 400 `bad_version`), with `X-Analysis-Version`. The Markdown carries the conclusion.

### The page

- Every action's answer is MERGED into the draft (`frontend/src/pages/research/companyAnalysisDraft.js`): a field the person changed since the last record keeps their text; the rest take the server's. `take()` now runs only on a fresh read.
- Save states Saved (with version and time), Unsaved changes (naming the fields), Saving and Save failed (an alert). A failed save keeps the draft editable with Retry save and Copy my changes; a 409 offers "Load version N, keep my changes". Leaving the page with unsaved changes asks first (`beforeunload`).
- The content legend and kind tags: Generated by the run (with "Edited by you <date>" from `sections_edited`), Yours (title, conclusion, notes), Attached by you (`origin = 'manual'`), Fetched. The conclusion field is new. The evidence table lists every source with how it got here, its date and its state, and after a refresh what this refresh did; a source not fetched, and every source after a failed refresh, carries Stale with its age.
- Refresh and Rerun are explained side by side before either is pressed. Refresh keeps focus on its button and says what it checked; a failure keeps the draft, says nothing changed, and offers Retry refresh.
- Rerun opens "Review the rerun" against the saved version: additions ticked; removals and rewrites of edited text unticked (owner answer A); a sticky polite count; "Not part of this review" listing the person's own work; Cancel (and Escape) returns to the exact draft and focus to Rerun discovery; Accept sends the ticked ids with `If-Match` and says the new version. A failed rerun keeps the body and offers Retry rerun and Quick scan. The Companies workspace panel's Re-run opens this review on the analysis's page.
- Export ▾ is a menu naming the saved version; arrow keys move, Escape returns focus to Export. With unsaved changes the reader chooses: Save, then export (the default, owner answer A), Export saved version N, or Cancel. A download happens only on a 2xx with the format's content type; otherwise an alert says nothing was downloaded, with Retry export and Dismiss. `fetchMarkdown` in `CompetitorAnalysis.jsx` throws on the same two cases, so the panel's Markdown no longer saves a 503 page as a file.
- Phone (below 768px): a bottom bar with Save and Actions ⋯; the Actions sheet says what each action does and returns focus to Actions ⋯; the dirty-draft decision is a bottom sheet. Dark: every surface carries its `dark:` pair.
- The saved list (RS-14 A1) shows run state (Last run failed for an errored run), Edited since run, updated and created dates, and a loading state.
