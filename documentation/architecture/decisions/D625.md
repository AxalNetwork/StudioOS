## D625 — The partner-profile list is trimmed and logged, and the identity reads show in the security feed

**The admin list of partner profiles no longer carries identity, and opening it writes one audit row. The three reads from D612 show on HQ's security feed.** Issue #1346. No migration.

**The list.** `GET /api/profiling/admin/list` used to return every column of every profile, including the EIN, `chat_history` and `extracted_data`, on each admin page load. The table draws the name, email, persona, founder track, formation, partnership goal, legal entity, agreement and status. The list now returns those fields and nothing else. Review fetches `GET /api/profiling/admin/:email`, which D612 already logs, and the window draws that response. A failed read is said so, and the window stays shut.

**The list log.** One `partner_profile_list_access` row per read, including an empty list. `details` is the count. `actor` is `hashEmail` of the admin. `user_id` is the admin. The row holds no name, email, EIN, transcript or extracted data. This is the fourth identity read. D612 covers the other three only.

**Whose id a profile read names.** `partner_profile_access` uses the profile's own `user_id` when it has one, and the account found by email only when it does not. An address that has moved to a later account does not rename the audit row.

**The feed.** `kyc_record_access`, `kyc_queue_access` and `partner_profile_access` are on `ACTOR_SIDE_ACTIONS`, so the governance feed's activity arm can show them. The list action is not on that list.
