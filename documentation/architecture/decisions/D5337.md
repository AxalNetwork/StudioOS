## D5337 — The operator's restore runs the drill's code, from either copy (#5337)

Follow-up to #4558 (D4558, PRs #4756 and #4795). D4558 left
`scripts/restore-d1.sh` as it was: "moving it onto the splitter and the
manifest is its own task (D523)". This is that task.

### What the current state showed

Read from `main` on 2026-11-10.

- **The operator's script imported the whole export in one call.**
  `restore-d1.sh` ran one `wrangler d1 execute <db> --remote --file
  <backup.sql>`. One import of production's ~272 MB export fails on D1's side
  (#1007; the D523 run ended `{"D1_RESET_DO":true}`).
- **It checked nothing.** No manifest, no sha256, no size, no migration, and
  afterwards only three hard-coded counts, printed and never compared.
- **It could not read the independent copy.** Only `dr-drill.sh` knew how
  to fetch, check and decrypt one.
- **So a passing drill proved nothing about it.** The drill splits the
  export, breaks foreign-key cycles at a nullable back-edge (the 2026-11-08
  fix for chunk 275), checks the manifest first and compares every row count
  after. The script an operator runs in a real recovery did none of that.

### Decision

1. **One restore path, sourced by both scripts.** `scripts/dr-restore-lib.sh`
   holds what a restore does, moved out of `dr-drill.sh` unchanged:
   - `dr_fetch_primary`: the manifest, then the backup, from R2 with
     `--remote`;
   - `dr_fetch_independent`: the copy's manifest and ciphertext, the
     ciphertext's sha256, and `age` decryption with the owner's key file;
   - `dr_verify`: `d1-backup-manifest.mjs verify`;
   - `dr_import_chunks`: `dr-drill-split.mjs`, then one
     `wrangler d1 execute --remote --file` per chunk;
   - `dr_compare_counts`: every table's `COUNT(*)` against the manifest.

   A function that fails exits the script with a named `FAIL_REASON` and the
   drill's exit code for that step. Each caller's EXIT trap cleans up. It is
   in `scripts/`, not `scripts/lib/`: that folder holds side-effect-free
   modules, and this talks to Cloudflare.
2. **`dr-drill.sh` behaves as before.** Its own parts stay: the heartbeat,
   the throwaway database (still created with `--jurisdiction eu`), the smoke
   checks, the marker and the pager. Two small changes:
   - the `rpo_breach` page for a stale backup now comes from the EXIT trap;
   - a split failure and an incomplete import now name a reason in the
     marker (`split_failed`, `chunks_incomplete`).
3. **`restore-d1.sh` runs the same functions**, in this order:
   1. refuse the target by name;
   2. fetch;
   3. verify, before the target is read;
   4. check the target;
   5. confirm;
   6. import;
   7. compare.

   It takes three sources:
   - `r2://<bucket>/<key>`;
   - a local export with its manifest;
   - `DR_SOURCE=independent` with a recovery point.

   A backup of any age is accepted (`DR_MAX_BACKUP_AGE_HOURS`, default
   9600 h). An export older than Time Travel's 30 days is this path's use.
4. **The target safeguards, kept and enforced.** The target is named
   explicitly; there is no default. The script refuses it when:
   - it is production, by name (`studioos-db`) or by name or id from
     `wrangler.toml`'s production tables, checked again against the id
     `wrangler d1 info` reports;
   - it does not exist;
   - `wrangler d1 info --json` does not report `jurisdiction: eu` (D167);
   - it holds any table, view, index or trigger other than D1's own `_cf_`
     and `sqlite_` objects.

   The script never creates or truncates a database. The operator creates the
   target with `--jurisdiction eu`, as `D1_RECOVERY.md` §4 shows.
5. **Secrets and content.**
   - The backup, the decrypted plaintext and the chunks live only in the
     run's 0700 temp directory. It is removed on every exit, including
     SIGINT and SIGTERM.
   - The owner's key file is read in place by `age`, never copied or printed.
   - Logs hold names, counts, sizes, hashes and times. wrangler's output is
     never printed, because it can quote a statement.
6. **Every stop is named.** A non-zero exit prints one `reason=<code>` line.
   `D1_RECOVERY.md` §3 lists every reason, and a test holds that list to the
   code.

### What it does not do

- It runs nothing against any Cloudflare account. No restore, export or
  deploy was run for this change.
- It does not create the target. Whether it should is the open question
  below.
- The drill still does not exercise `restore-d1.sh`'s target checks. Those
  belong to a target the operator names, and the drill makes its own.

### Open question for the owner

Should `restore-d1.sh` create the target itself?

- **A. No (as built).** The operator creates it with `--jurisdiction eu`, and
  the script refuses anything not EU-resident, not empty or production. Every
  database creation stays a deliberate operator act.
- **B. Yes, when the named target does not exist.** The script runs
  `wrangler d1 create <target> --jurisdiction eu` itself. This saves one
  step against the 4 h RTO, but a typo in the name makes a new database
  instead of failing.

The pick is A.

### Tests

- `frontend/test/restore_d1_d5337.test.mjs` (13 tests) runs the script with
  a fake `wrangler` whose target is a real SQLite file. Each chunk executes
  with foreign keys on, one transaction per file, and the counts compared
  are read back from that file. It covers:
  - a clean restore of an export with a foreign-key cycle, a child exported
    before its parent and a self-reference;
  - a local export;
  - each target refusal: unnamed, production by name and by id, missing, not
    EU, not empty (left untouched; `_cf_KV` alone does not count),
    confirmation mismatch;
  - each backup refusal, with the target never read;
  - an old export accepted;
  - a failed chunk, named with its tables and quoting nothing;
  - differing and unreadable row counts;
  - the independent copy, uploaded by the real `dr-second-copy.sh` into the
    fake store and decrypted by the real `age`, with no key, a wrong key, a
    tampered ciphertext, a bad point and an unconfigured copy refused, and
    the temp directory empty afterwards;
  - that both scripts source the library and neither keeps its own split,
    manifest check or file import;
  - that `D1_RECOVERY.md` §3 names every reason the code can stop on, and
    that the RTO row describes the script.
- 25 mutations of the script and library, one per refusal or guarantee, each
  killed by these tests. The restored source passes.
- `_dr_fakes.mjs` holds the `age` key pair and fake `aws` store, moved out
  of `dr_second_copy_d4558.test.mjs` so both suites use the same store.
- `dr_drill_d263.test.mjs`'s defect scan now reads the library too.
