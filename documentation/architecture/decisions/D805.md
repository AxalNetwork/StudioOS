## D805 — The Usage console's two missing reads: cost by kind with "no output recorded", and today's token-pack orders

- **Status:** decided by the owner through S1 on #2243, 2026-10-20. Part of D785 (#2210). Built by S12.
- **Basis:** `origin/main` at `6b2aae744e`. Worker paths are relative to `cloudflare-worker/src/`.
- **Source:** the "Usage & Billing console" canvas (`design/incoming/Usage Page.dc.html`), boards B1, B2 and B4.
- **Read by:** #2214 (Usage and Cost) and #2246 (Limits), through `aiBudgetApi.cost` and `aiBudgetApi.spendLimit` (`frontend/src/lib/api/aiBudget.js`).

### 1. What the canvas draws that no read gave

- **B2's totals row:** "Total charged", "Token cost", "Audio and speech cost" and "Image cost". D787's `/api/ai-budget/cost` gave totals and a per-model split, but no split by kind.
- **B2's note:** "Not recorded: streamed replies recorded no output count." No read counted those runs.
- **B1's limits card and B4:** "Token-pack orders today: [1] of [5]." The count lived only inside the purchase check.

### 2. Cost by kind (`services/aiCost.ts`)

**`totals.by_kind`** gives `{ tokens, audio_speech, image, other }`, each with `{ cost_usd, charged_microusd }`, as D787 sums money. It is summed by the model's catalogue `kind` through one map, `KIND_GROUP`:

| Line | Catalogue kinds |
| --- | --- |
| `tokens` | Text Generation, Summarization, Translation, Text Embeddings |
| `audio_speech` | Automatic Speech Recognition, Text-to-Speech |
| `image` | Text-to-Image, Image-to-Text |
| `other` | Text Classification, Voice Activity Detection, Image Classification, Object Detection, and any model the catalogue does not know |

- **Every catalogue kind is placed.** The test fails on a kind `KIND_GROUP` lacks, so a new kind is placed on purpose.
- **Nothing is dropped.** A model in `other` is named in `totals.other_models`, so the four lines always add up to the total.
- **A guard row** (D763) counts under its own model's kind: Llama Guard is Text Generation, so `tokens`.
- **The CSV** gains a `kind` column after `name`.

### 3. "No output recorded"

**`totals.output_not_recorded`** counts the runs in range on a model priced per output token (`unitPrice(model, 'tokens_out')` above 0) that recorded no output count.

**One departure from the issue's wording.** The issue says to count runs "whose `completion_tokens` is null". Migration 040 declares `completion_tokens INTEGER NOT NULL DEFAULT 0`, so it is never null. A run that recorded no output count records 0: before D762's `meterStream`, a streamed reply settled on its input alone and wrote 0. So the read counts an output count of 0 (or null, should one appear).

**Not counted:**
- a cached answer;
- a refused run;
- a model priced by the minute, the character or the image, which has no output tokens to record;
- a model the catalogue does not price.

### 4. Today's pack orders (`services/aiCredits.ts`)

- **One count.** `recentPackOrders(env, userId, excludeOrderRef)` is the query the purchase check used: the member's `ai_topup_purchases` rows in the rolling `orderWindowHours` (24). It was moved out of `tokenPackQuote`, not copied. `tokenPackQuote` refuses with `token_pack_daily_limit` at `n >= ordersPerDay`, as before.
- **The read.** `packOrdersToday` reads the same function. `GET /api/ai-budget/limit` answers `pack_orders: { today, per_day, window_hours, resets_at }`. `resets_at` is when the oldest order in the window leaves it, or null with none. The window rolls, so "today" means the last 24 hours, as the check counts it.
- **Auto-reloads count.** D794 (#2219, on `main`) buys every reload through `tokenPackQuote`, which writes an `ai_topup_purchases` row. Each reload is therefore counted by the same function, with no extra code.
