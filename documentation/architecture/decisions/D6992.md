## D6992 — Resources and Events show the same open cohort, and a failed read no longer looks empty (#6992)

- **Status:** built 2026-11-22 for slot S15. Not deployed. Plan key X10 of the public website audit, tracker #6976. Register P1: `/events` and `/resources`.
- **Files:**
  - `frontend/src/components/site/LabProgramCard.jsx` (new)
  - `frontend/src/pages/events/PublicEventsPage.jsx`
  - `frontend/src/pages/site/ResourcesPage.jsx`, `frontend/src/pages/site/network.css`
  - `frontend/src/lib/siteResources.js`
  - `frontend/src/lib/spinoutLab.js`
  - `frontend/test/resources_events_cohort_6992.test.mjs`
- **Scope:** frontend only. No Worker route, migration or API module changed.

### Why

The Resources hub's "Programs & events" block read only the events list and
said "Nothing is scheduled right now." while `/events` drew a Spin-Out Lab
cohort card. The two pages disagreed about the same programme.

The hub's reads also hid failures. `useLiveList` caught a failed read into
`[]`, so a failed jobs read said "No open roles right now.", and
`useSiteStats` swallowed its error, so a failed stats read drew nothing.

### What changed

1. **One card.** `LabProgramCard` is one component, used by `/events` and by
   the hub. It is fed by the cohort record (`useCohortRecord`, the public
   `GET /spinout-lab/brief`). Its places come from `placesFromRecord`, the
   pure half of `useCohortPlaces`, so the page reads the brief once. The card
   names the cohort as the record does ("December 2026"). It no longer uses
   the client-side number from `openCohortCopy()` ("Cohort N"). A field the
   record leaves blank (start, application close, places) reads "Not
   recorded". It is never left out or drawn as 0. `LabProgramSlot` draws the
   card's slot in its read state: loading, the card, the programmes' own empty
   line ("No programme is open for applications right now."), or Unavailable
   with Try again.
2. **Separate empty lines.** The hub's events line is now "No events are
   scheduled right now.". On `/events` with no filter set, the line is "No
   upcoming events are scheduled right now." (or "No past events are
   listed."). The "match your filters" lines stay for when a filter is set.
3. **Read states.** `useLiveList` returns `{ state, items, retry }`. The
   state is `loading`, `loaded`, `empty` or `unavailable`. A failed or
   malformed read is reported (`reportError`) and is `unavailable`. The hub
   draws "Unavailable. We could not load this list." with Try again
   (`DataState` from `ui/Honesty.jsx`), never the empty sentence.
   `useSiteStatsRead` does the same for `/api/public/stats`. `useSiteStats`
   keeps its shape for `PublicDirectoryPage`: the counts, or null. Null draws
   no figure, so a failure never prints 0. The failure is reported now, not
   swallowed.
4. **Order.** The hub draws blocks with rows first, then blocks without. Each
   group keeps the canvas's order. The first two blocks fill the wide row. An
   open cohort counts as a row for "Programs & events".

### Behaviour on failure

This changes what a visitor sees when a read fails. Before, a failed hub list
showed that list's empty sentence, and a failed stats read showed nothing.
Now each failure says "Unavailable" with Try again. When the cohort read
fails, the programmes slot on both pages says "Unavailable. We could not load
the open cohort." with Try again. Before, `/events` drew a card from the
client-side cohort count even when nothing had been read.

### Not changed

The card's redesign (#6979, W3). The homepage's counts and its own
`useLiveList` and `useSiteStats` copies in `pages/LandingPage.jsx`. The
`/events` feed's own failure line ("Unable to load events…") was already an
alert and not an empty list.
