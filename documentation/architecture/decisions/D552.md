## D552 — Every AI run records its page, and a page can read its own spend

**Every call into the AI router now records the page it was asked from in
`ai_usage_logs.surface`, using one fixed name per page from
`cloudflare-worker/src/services/aiSurfaces.ts`. `GET /api/ai/me/spend` takes
`?surface=<name>` and returns that page's spend this month and its last run,
from the caller's own rows. It accepts the listed names and, since step 3, any
other page path in the exact form the router records. The rail reads it for
the page it sits on and shows that page's month, its last run, and the month
split by page.** Issue #1145: the Worker half (steps 1, 2 and 5) in #1149, the
rail (step 3) after it. No migration: the column is migration 319's (D404).

**The route.** `GET /api/ai/me/spend?surface=<name>`, behind `requireAuth`,
reads only the caller's own rows (`aiUsageSelfScope`, the same scope as the
account meter).
- **No `surface` parameter:** the account report, unchanged.
- **A listed name:**
  `{ ok, surface, recorded, reason, month: { key, spend_usd, calls },
  unattributed: { calls, spend_usd } | null, last_run, last_run_recorded,
  last_run_reason }`.
  - `month` is this calendar month (UTC) on that page.
  - `last_run` is the page's most recent run up to now. It has the same shape
    as the account receipt, with token counts nulled where they are not counts
    (D401).
  - `unattributed` is the caller's runs this month that carry no page. Runs
    made before this change carry none, so a reader can see how much of the
    month no page has claimed.
  - The response does not include the account's figures.
- **Any other value is refused**, including an empty value, a trailing slash,
  a different case or a path under a listed name:
  `refuse(c, 400, { code: 'unknown_surface', … })`, with the accepted names on
  `surfaces`. Nothing is read. (Step 3 widened this to any recorded page path;
  see below. The other refusals stand.)
- **Honesty.**
  - A page with no runs is `month.calls: 0, spend_usd: 0`. The read ran.
  - It is also `last_run: null, last_run_recorded: true`, with
    `last_run_reason` "No AI run has been recorded from this page."
  - An unreadable store (no table, or migration 319 not applied) is
    `recorded: false`, with `spend_usd`, `calls` and `unattributed` all null,
    and `reason` saying it could not be read. It is never a zero.
  - A last-run read that fails is `last_run_recorded: false` with its own
    reason.

## Step 3 — the rail reads its own page

**Superseded on the rail by D698 (2026-10-15):** this page's month and last run left the Eadwyn AI rail for `/account/usage`, and the rail no longer sends `?surface=`; the read and the hook's `page` option stay; see `D698.md`.

**Which paths the route accepts: B.** #1149 asked A, B or C:
- **A.** add the rail's pages to the fixed list;
- **B.** also accept any path in the exact form the router records;
- **C.** keep the nine names only.

S09 picked A then. Building step 3 changed the pick to B. The rail records
`location.pathname` (D404), and it sits on dozens of pages, many of them
parameterised (`/research/funds/catalog/:id` among them). A
fixed list would have to name a pattern for each, which is a second route
table that drifts from the first; C leaves almost every rail page with a 400.
B costs nothing in safety:
- the value is bound, never interpolated;
- it only ever filters the caller's own rows (`aiUsageSelfScope`);
- it must already be in stored form: `normaliseSurface(v) === v`, so a
  trailing slash, surrounding space, a query string or anything outside
  `SURFACE_RE` is still refused, and an empty value is still refused;
- every fixed name is such a path (pinned), so the nine names need no second
  check. `isSpendSurface` in `routes/ai.ts` is the whole rule.

The owner said to go ahead on #1145 without naming a letter. B is open to
reversal by S1 or the owner: going to A means turning `isSpendSurface` back
into an allow-list.

**The rail** (`ui/WorkerRail.jsx`, `hooks/useAiSpend.js`, `ui/assistCost.js`):
- `useAiSpend({ page })` makes a third read, `api.myAiSpend(page)` =
  `GET /api/ai/me/spend?surface=<page>`, only for a path that matches
  `RECORDABLE_PAGE_RE` (a copy of `SURFACE_RE`, held equal by a test). Its
  result and its error are `pageSpend` and `pageSpendError`, apart from the
  account read's. A new page re-reads.
- `RailPageUsage`, inside the Usage block, draws:
  - **this page this month** (`pageMonthLine`): its spend and runs; or "No
    run on this page yet." when the last-run read found none ever; or "No run
    on this page this month." when it ran before, or its last run could not
    be read, because "yet" would then be a claim. Beside a zero it names the
    month's runs with no page, for D404's reason;
  - **this page's last run**, labelled "Last run · this page", from the page
    read. With no run, nothing is drawn twice;
  - **the month split by page** (`splitByPage` over `by_surface`): the five
    costliest pages, this page among them wherever it ranks and marked
    `aria-current`, runs with no page as their own row, the rest folded into
    one "N more pages" row so the rows still add up to the month.
- A failed page read is Unreadable with a retry, and a figure left from an
  earlier read is not shown beside it. A failed `by_surface` is Unreadable
  too, never an empty list.
- A path the router does not record is not read. The line says its runs count
  among those with no page, and the receipt falls back to the account's,
  labelled "your account, any page".
- `pageSpendLine` (D404's sentence over `by_surface`) is removed. The page
  figure is now read directly.
