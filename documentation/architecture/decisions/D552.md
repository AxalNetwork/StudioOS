## D552 — Every AI run records its page, and a page can read its own spend

**Every call into the AI router now records the page it was asked from in
`ai_usage_logs.surface`, using one fixed name per page from
`cloudflare-worker/src/services/aiSurfaces.ts`. `GET /api/ai/me/spend` takes
`?surface=<name>` and returns that page's spend this month and its last run,
from the caller's own rows. It accepts only the listed names.** Issue #1145, Worker
half (steps 1, 2 and 5). The rail reading it (step 3) waits for the rail's
own PRs. No migration: the column is migration 319's (D404).

**What was true on main (`5201db161`).**
- `aiRouter.run` takes an optional `surface`, validates it against
  `SURFACE_RE` and writes it, or NULL, on every usage row (D404).
- Only two callers passed one, and both forwarded the app path the page sent:
  the rail's read-back (`routes/ai.ts`, `POST /ai/workspace/explain`) and the
  zone drafts (`routes/research.ts`, `POST /research/drafts`).
- The other nineteen router calls passed nothing. They were in
  `routes/founder_validate.ts`, `routes/research.ts` (Ask), `routes/brand.ts`,
  `routes/advisor.ts`, `routes/profiling.ts`,
  `services/competitorAnalysis.ts`, `services/deckExtract.ts`,
  `services/publications.ts`, `services/fills/citations.ts`,
  `services/advisor/rerank.ts`, `services/advisor/guardrails.ts` (the
  safety pass) and `services/market_intel/extractors/index.ts`. Every one of
  those runs landed in the month's unattributed group. A page's "this month" figure was therefore only the part of its
  cost that came from the rail.
- `GET /api/ai/me/spend` took no parameter. Its `last_run` was the account's
  most recent run, whichever page made it.

**The names.** Each name is the app path of the page that owns the feature.
That keeps the names in the same namespace as the paths the rail already
records, and each name passes `SURFACE_RE` unchanged. A feature reached from
more than one page records the page that owns it. The server cannot tell which
button was pressed without trusting the request, and the point of a fixed name
is not to.

Two callers still forward the page's own path rather than a fixed name:
- The rail's read-back (`routes/ai.ts`).
- The zone drafts (`routes/research.ts`).

The rail sits on more than seventy pages, many of them parameterised. Listing
those pages is step 3's question, not this one. Both values are re-checked by
the router's `normaliseSurface`. The safety pass
(`classifyInput`) now takes the page as a required fourth parameter. The rail
passes its forwarded path, and the advisor passes `/studio`.

One call records no page: `paraphraseForSnippet` in
`services/market_intel/extractors/index.ts`. Nothing in `src/` calls it, so no
page asks for it, and naming one would put a false row on that page. The guard
fails if it gains a caller.

**The route.** `GET /api/ai/me/spend?surface=<name>`, behind `requireAuth`,
reads only the caller's own rows (`aiUsageSelfScope`, the same scope as the
account meter).
- **No `surface` parameter:** the account report, unchanged.
- **A listed name:**
  `{ ok, surface, recorded, reason, month: { key, spend_usd, calls },
  unattributed: { calls, spend_usd } | null, last_run, last_run_recorded,
  last_run_reason }`.
  - `month` is this calendar month (UTC) on that page.
  - `last_run` is the page's most recent run up to now. It has the same shape
    as the account receipt, with token counts nulled where they are not counts
    (D401).
  - `unattributed` is the caller's runs this month that carry no page. Runs
    made before this change carry none, so a reader can see how much of the
    month no page has claimed.
  - The response does not include the account's figures.
- **Any other value is refused**, including an empty value, a trailing slash,
  a different case or a path under a listed name:
  `refuse(c, 400, { code: 'unknown_surface', … })`, with the accepted names on
  `surfaces`. Nothing is read.
- **Honesty.**
  - A page with no runs is `month.calls: 0, spend_usd: 0`. The read ran.
  - It is also `last_run: null, last_run_recorded: true`, with
    `last_run_reason` "No AI run has been recorded from this page."
  - An unreadable store (no table, or migration 319 not applied) is
    `recorded: false`, with `spend_usd`, `calls` and `unattributed` all null,
    and `reason` saying it could not be read. It is never a zero.
  - A last-run read that fails is `last_run_recorded: false` with its own
    reason.

**Guards.** `cloudflare-worker/test/ai_surface_d552.test.ts`, 18 tests.
- **The list.** Every name passes `SURFACE_RE` and `normaliseSurface`
  unchanged. No name repeats. The list is frozen. `isAiSurface` is an exact
  match.
- **The source scan.** It finds every call into `aiRouter.run`, under whatever
  name each file imports it as.
  - Every call must pass `surface`. The one exception, which has no caller,
    must still have none.
  - A fixed name must come from `AI_SURFACE`, never a quoted string.
  - A forwarded value must be one of the three known ones.
  - Each file's names must match the table above.
  - This file must list every name.
- **On real SQLite with a stub model.** The safety pass, the deck reviewer's
  two runs, a researched citation and a publication draft each leave a usage
  row with their page.
- **The route, on real SQLite behind a stubbed sign-in:**
  - a listed page returns its own month, last run and unattributed runs;
  - another account's newer and larger runs on the same page never appear;
  - a page only someone else used reads as empty, with the reason;
  - seven bad values are refused before the usage table is read;
  - no parameter still returns the account report;
  - a table without the column reads as unreadable, not zero;
  - the last run is bounded by `now`.

`ai_spend_self.test.ts` used to fail on any `req.query(` in `routes/ai.ts`.
It now requires that `surface` is the only query key the file reads.
`ai_workspace_explain.test.ts` now expects the rail's safety pass to carry
`page`.
