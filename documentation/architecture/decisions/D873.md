### 1. What was wrong in D858 for a call

An imported Zoom or Meet call is a session with `channel = 'video'`, `submitted_via` `zoom` or `google_meet`, and no `active_ms`. D858 read it as a recording, which caused two errors:

- **Minutes read 0.** Voice minutes came from `active_ms`, so a call of unknown length read **0**, an unknown shown as a count.
- **Sides were wrong for a multi-party call.** Every speaker but "Me" was the customer, so a colleague's words, or "Speaker ?", counted as the interviewee's.

### 2. What was decided

1. **A call is its own kind.** A session is a `call` when its `submitted_via` is:
   - `zoom` (channel `zoom`);
   - `google_meet` (channel `meet`);
   - `upload` (channel `upload`, #2519's value).

   The session read carries `session.channel`. A chat's channel is its provider; a recording or a typed paste has none.
2. **Sides.** A chat or a typed paste has two parties: "Me" is the founder, and anyone else is the customer, as D858 counted. A recording or a call can hold more, so a line's side is set by name:
   - **Founder:** "Me", or the founder's own `users.name`.
   - **Customer:** the interview's `interviewee_name`, or "Interviewee" (`speakerLabel`'s fallback).
   - **Unattributed:** anyone else ("Speaker ?", a colleague, a second customer). Never the interviewee.

   Names match case- and space-insensitively. `messages` gains an `unattributed` side next to `founder` and `customer`.
3. **Speakers.** The session read lists each speaker once, in the order they first speak, with their side and line count. The venture read does not: it stays aggregates only.
4. **Length.** A call's length is the recorder's `active_ms` when it kept one (an upload), else its last line's end. With neither, it reads null with `REASONS.callMinutes`. A venture's total is null when any call's length is unknown, never a partial sum.
5. **Language.** A call's language is its session's `language` when speech-to-text recorded one. A native transcript carries none, so it reads null with `REASONS.callLanguage`. If none of a venture's calls has a language, the figure is null, not an empty list.
6. **How the text was made.** The session read carries `transcript_source`, so the founder can tell how the draft summary's text came about:
   - `native`: the provider's own transcript, whose `final_model` is `<provider>_transcript`, as `meetings.ts` writes it;
   - `speech_to_text`: Workers AI, with its model, e.g. Whisper;
   - `chat`;
   - `typed`.

   A call or recording with no `final_model` reads null with `REASONS.transcriptModel`.
7. **The venture read takes `kind`.** `kind` is `chats` (D858's default, unchanged), `calls` or `all`; anything else is 400. `sessions_by_provider` counts calls by channel (`zoom`, `meet`, `upload`).

### 3. What stays as it is

- **The engine.** Imports still queue nothing (D765). The founder's Summarise and Structure run D757's engine on a call as on any session. Its suggestions are `validate_proposals` rows that write their module only on Accept (D777).
- **Unknown speakers are numbered where the transcript is parsed.** Several unnamed speakers all read "Speaker ?" today; numbering them happens in `zoom.ts` and `googleMeet.ts`, which #2517 (M1) and #2518 (M2) own. Whatever label they write, this read treats it as unattributed unless it is the founder's or the interviewee's name.
- **The summary's label stays in this read.** It is not added to `GET /sessions/:id`'s digest, which `founder_validate_sessions.ts` serves and this task does not own.

### 6. PR 2: a call's items, translated first

**A call is read for D859's items.** The engine ran the extraction (`extractConversationItems`) after a chat's structure stage only. It now runs it after a call's too: a Zoom, Meet or uploaded call, by `submitted_via` (`CALL_CHANNELS`, `conversationItems.ts`'s `CALL_SOURCES`). A call gets the chat's items and two of its own, in a prompt that says it is a call and that each line names its speaker:

| A call says | Item | Kind | Lands, on Accept |
| --- | --- | --- | --- |
| what was decided | `decision` {statement, owner_hint?} | `decision` (new finding kind) | the interview, Customer research |
| who will do what | `action_item` {statement, owner_hint?, due_hint?} | `follow_up` with `kind: 'action_item'` | the interview's follow-ups |

- **Proposals only.** Both are `validate_proposals` rows. The founder's Accept writes `interview_findings` through the module's own writer, and Discard is final, as for D859's items.
- **Calls only.** A chat's extraction drops a `decision` or an `action_item` (`placementFor`'s call check).
- **An owner or a date is kept only as the call said it.** `owner_hint` (at most 80 characters) is optional on a `decision` and on a `follow_up`. None is guessed.
- **Structuring may propose a decision too.** `decision` is in pass B, as D859's kinds are, and dedupe keeps one.

**Translated first (D857).** Structuring already read each segment's translation. The extraction read the stored words (`finalSegments`), so D859's note that "nothing here changes" did not hold. It now reads the session as structuring does (`readSessionSegments`), and an item cited from translated words keeps the customer's own words and their language beside its quote (`withOriginals`).

**"Recorded".** A call's suggestions, from structuring and from the extraction, carry `source_label: 'Recorded'` in their citation (`storePlacements`' `sourceLabel`), as D858's analytics name a call's words.

**The summary says how the call's text was made.** `summaryOf` adds `transcript: { source, model }` for a call: `native` for the provider's own transcript (`zoom_transcript`, `google_meet_transcript`), else `speech_to_text` with the model (Whisper). It is absent for a session that is not a call, or that names no model. One function decides it for the summary and the analytics (`callTranscriptSource`, `conversationAnalytics.ts`). The review's summary line shows it (`SessionSummary.jsx`, `transcriptLabel`): "From the call's own transcript", or "From speech-to-text (<model>)".

**Multi-party calls.** No change was needed. A suggestion's evidence already names the speaker of the line it quotes, and the interviewee separately (`moduleSuggestions`). A colleague's action item stays the colleague's.
