## D6064 — Pitch › Share & analytics: the founder reads viewer reactions and feedback (#6064)

- **Status:** built 2026-11-14. Answers D4839's "Backend required" line: viewers post through `POST /api/decks/share/:token/feedback` and nothing read it back.
- **Builds on:** D4839 (Pitch Studio v2), D4272 (Share & analytics daily read), D1500 (card uids, migration 714), D4598 (a reaction's place is the card the link sends), migration 071 (`deck_share_feedback`).

### What was decided

- **One read, its own router.** `GET /api/decks/:id/share-feedback?version=N` in `cloudflare-worker/src/routes/deck_share_feedback.ts`, which mounts itself (#4105) with no `before`. No new store and no migration: the table is migration 071's (with 714's `slide_reactions_by_uid`), and the read first calls `ensureDeckShareConversionSchema` from `deck_share_actions.ts`, the same runtime bootstrap the POST and `GET /:id/engagement` use. A table or the 714 column still missing after it is read as no feedback (the rows still read, by place, without the column); any other failure is `500 { state: 'unreadable' }` with our sentence, never SQLite text.
- **Who.** `deckFor(c, user, true)`, exactly the gate of `GET /:id/analytics/daily`: the venture's writers, which are its owner and its accepted co-founders. An advisor, another founder, an investor, a support session and an HQ admin who is not a Super Admin are refused 403 (a Super Admin passes, as on every deck write gate), an unknown deck 404, no session 401.
- **What.** The venture's feedback across its versions (or one, `version=N`; a bad value is 422 `bad_version`), newest first. Each item carries its version, the investor link it came through (the feedback's own view, or else the `feedback` conversion row that names its id; a link of another version names nothing), the per-card reactions (by card uid; a row written before 714 by its place on the cards that link sends, through `linkSentCards`), the written note and the two structured answers.
- **Anonymity.** `viewer` is `signed_in` or `anonymous` and nothing more. No user id, name or email is joined, and the free-form `contact` the POST accepts is never returned for any row: the viewer form does not ask for it, and the read is the same whether a viewer signed in or not. The investor shown is the founder's own label for the link.
- **Bounded.** At most 200 rows (`cap`), one more read to say `truncated: true` when there are more. The block says "Showing the newest 200".
- **Shown once, said twice.** The same POST copies the note into `discovery_interviews`, so it already appears on Validate's Customer Discovery panel. The response carries `discovery_mirror: true` and the block says so in its first line. Nothing is removed from the mirror; per-card reactions are only here.

### Frontend

`deckShareFeedbackApi.read` (`frontend/src/lib/api/deckShareFeedback.js`, D527's own module). `ShareFeedback.jsx` sits in `ShareBoard.jsx` under the board's version filter, with its own read and states: loading, Unreadable with Try again, refused (a 403 or 404), empty, and ready (reactions per card across links, then each link's feedback). `shareFeedbackModel.js` is pure.

### Not built

Marking feedback read, replying to a viewer, and an export. The contact field stays write-only.
