## D6248 — The Fund landing reads its performance figures (#6248)

`/funds` printed "RVPI · on NAV: Unavailable" and "NAV, RVPI, TVPI, IRR, and expense accruals are unavailable until the underlying records exist" as fixed text. Meanwhile `GET /api/fund-performance/:id` computes all four figures from recorded marks (D627). The owner's audience answer (C on #6245) and D6246 let the GP of record read that route. The landing now reads it, so the landing and `/funds/performance` tell the same truth.

### What the landing draws

The landing reads `fundPerformanceApi.read(fund.id)` for the selected fund only, alongside its three other reads. Each read is independent.

| Read result | NAV · investments only, RVPI, TVPI, IRR |
|---|---|
| A figure | The value: `fmtCents`, `fmtMultiple` (1.25x) or `fmtRate` (18.4%). A recorded 0 is a figure. |
| No figure | Not recorded, with the Worker's own `unavailable[<field>]` reason shown. If the Worker sends no reason, it says "The performance read gave no value and no reason." |
| The read failed | The shared Unavailable treatment: "Fund performance … This is not a claim that it is unrecorded." No figure claims Not recorded. |
| Reading | Reading… |

- **Under the figures:** the as-of date and the Worker's NAV basis ("Investments only; …"). The one **Open fund performance** link is #6245's, to `/funds/performance` (D6245); that page lists every fund, so the link carries none.
- **DPI** stays where it was, from the fund analytics read.

### What stays

- **Accrued expenses: Unavailable** stays on the Fund accounting card. The performance read does not supply accruals.
- **The summary sentence** now says only what is true: "Every recorded amount originates in this fund's operating record. Expense accruals are not recorded on Axal."
- **The rail's line** "Unavailable values stay unavailable" now reads "A figure that is not recorded says why."

### Departures

None. No route, Worker or permission change. The read and its gate are D627 and D6246.
