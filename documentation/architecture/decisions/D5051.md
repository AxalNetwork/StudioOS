### 1. Two reads, never merged into one guess

The page reads `GET /api/admin/licence-agreement-policies/licences/:uid` (D5052: each program's legal status,
the documents it needs, which are executed or in flight, what is missing, the frozen holdings and the executed
agreements that need replacing) and `GET /api/admin/licence-agreements/licences/:uid` (D5048: every version,
with its envelope, dates, slot and unresolved fields). Each is its own block. Every legal answer (in force,
missing, gating) is the D5052 read's; the D5048 read only adds versions, dates, fields and the envelope behind
a link. No read the UI needed was missing, so no Worker route was added.

### 2. The states

A required document reads one of: **Not prepared** (no version), **Prepared · not sent** (a draft or ready
version, no envelope), **Awaiting signature**, **Executed**, **Replacement required** (executed, but named by
D5052's `replacements_required`), **Not recorded** (no frozen policy for the program, so nothing is inferred,
D5052 §3) and **Unreadable** (the read failed, with Try again). A program's agreement is the worst of its gating
documents. A schedule the grant itself records as signed (a legacy schedule with no canonical row, which D5052
does not count as missing) reads Executed, "signed on the grant". None of these is drawn as 0 or as in force.

### 3. Grant is not in force

Program access gets its own card beside the commercial table: Program · Source · Commercial grant · Agreement ·
In force. "Granted" is the commercial word only; the In force column is D5052's status, and a granted program
that is not in force is highlighted with what it waits on ("Waiting on program licence signed") and is
countable under "Granted, not in force · N". A paused grant reads Paused; a failed read is Unreadable and never
"Not in force". The commercial table's Grant column keeps its words, and its "waiting on" now names
`agreement_executed` in words.

### 4. One canonical record

A version with an envelope IS that envelope's row in Contracts (D5050 §1), so it links to
`/admin/contracts/agreements/doc/<envelope>`. A version without one is a Contracts row that opens nothing, so
it links to the Agreements list filtered to the licence, the agreement type and the program or package. The
desk dropped those five filters (`agreement_type`, `agreement_status`, `licence`, `program`, `package`) when it
read its address, so choosing one in the list did nothing and no link could land on one; they are now in
`filterKeys`. The master territory licence agreement links the same way (`agreement_type=territory_licence`).
Nothing on these pages drafts, copies or sends a document: there is no create button, and the only writes the
clients offer are the Worker's own, which refuse a second version in flight (D5049).

### 5. Package readiness and Needs HQ

The package block reads the licence's current package holding: its name, frozen policy version (and "vN is the
latest" when behind, D5052 §2), strategy and gate. Per program: "No master agreement · per program"; package
master: the master's state and record; no holding: "No Axal VC package recorded", programs standalone. The
readiness card lists the offer, the package agreement and each included program, and ends "Legal readiness:
N of M programs in force", N counted only from D5052's `in_force`; programs granted outside the package are
named as standalone extras.

Needs HQ · legal lists, in L28's order: Agreement not prepared (a gating document with no version; a schedule
points at Program access, where it is sent), Missing fields (a draft with unresolved fields, named), Awaiting HQ
send (a ready or field-complete draft), Awaiting signature, and Stale after a term change (each
`replacements_required` entry, saying whether a replacement is being prepared). Each item links to where to act.

### Studio program agreements

The studio Contract tab reads `GET /api/licence/mine/program-agreements` independently of the territory
contract. The Worker resolves the licence from the caller's administrator membership and projects legal
readiness from the frozen holdings and commercial grant. It includes agreements sent to the studio and
their execution dates. Signed copies use the existing e-sign download route and scope. A branch without an HQ read receives the existing branch availability reason.

The HQ licence ledger adds five legal Needs HQ filters over its loaded rows. The Worker reads a page's
agreement versions, grants and frozen holdings in three queries and returns only the signal keys per licence.
An unavailable read leaves the rest of the ledger available and labels the legal chips Unavailable.

HQ prepares missing agreements from the template catalogue. Drafts open the stored preview, and a send uses
the reviewed revision and an HQ reason. Grant schedules continue to be sent from Program access.
