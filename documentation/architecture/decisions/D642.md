### Route and ownership

GET /api/usage/storage authenticates the caller and binds only their user ID.
Company, project and user query selectors are ignored: switching companies does
not change the result. Super Admins also receive only their own usage. Responses
are private/no-store and contain aggregates, without file names, keys or contents.

The five stable area keys and their recorded ownership are:

| Key | Store | Ownership |
| --- | --- | --- |
| data_room | data_room_files | uploaded_by_user_id |
| diligence_files | dd_attachments | uploaded_by_user_id |
| research_library | research_documents | owner_user_id |
| message_attachments | message_attachments (migration 323) | uploader_user_id |
| interview_recordings | discovery_interviews | project→founder profile→users.founder_id |

An interview counts as a file only with a nonblank recording_r2_key. A recorded
size without a key does not invent a recording. Founder-profile IDs are not user
IDs, and attribution follows the member's project ownership even if their active
account role changes. Uploads elsewhere are attributed to their recorded uploader,
not to the owner of the company the file happens to describe.

### Response contract

The response has total_bytes, files, unknown_size_files and areas. Each area has
key, files, bytes, unknown_size_files and recorded.

- Empty, successfully read stores return recorded:true with zero counts/bytes.
- NULL sizes remain files and increase unknown_size_files. An area's bytes is
  null if any size is unknown, including when every file has an unknown size.
  The route does not present a known subtotal as that area's exact total.
- A failed or malformed aggregate makes only that area recorded:false, with
  null metrics. Other areas still resolve. No SQL/provider exception is exposed.
- Top-level file and unknown-size counts are exact sums when every area is read;
  otherwise they are null. total_bytes is null if any area is unreadable or has
  unknown sizes. Safe-integer overflow also returns an unknown total rather than
  a rounded number. Invalid area values or SQLite SUM overflow mark that area
  unreadable.

This is an aggregate of stored metadata, not an R2 inventory, physical-storage
bill, quota enforcement or deduplicated object census. No bucket contents are
read. The five independent reads do not claim an atomic snapshot.

### The screens (S07, 2026-10-08)

The Usage canvas was committed by #1456. Both screens are built to it:

- `/account/usage`, U1 to U6: `frontend/src/pages/account/AccountUsage.jsx`, with its rules in `usageModel.js`.
  - It is the Account center section "Usage", after "Billing and orders", in the section list and the phone menu.

  - The rail's compact allowance card links to it ("See usage").
- `/admin/platform/allowances`, U7: `frontend/src/pages/hq/PlatformAllowancesPage.jsx`.
  - It is on the Platform strip after Topology, so it lights HQ's Platform row.
  - Platform links to it, beside Switches.

The figures come from D640, D641 and this decision's storage read, never from the canvas's placeholders. No read takes a company.

**Five reads, and each card fails on its own.** The five reads are:
- the allowance (`/ai-budget/me`);
- the top-up option (`/ai-budget/top-up`);
- the spend report (`/ai/me/spend`);
- the rate card (`/ai/rates`);
- storage (`/usage/storage`).

The spend report is one read behind four cards. Each of those cards also follows the report's own `*_recorded` flag for its figure, so a breakdown the Worker could not read is Unreadable on that card alone.

**Where the build departs from the canvas, and why.** Where the canvas and #1430's prompt differ, the prompt wins (S1, on #1435).
- **Where it went** is one card with two tabs, "By page" and "By task", as the prompt asks. "By page" has search and pages. The canvas drew a separate By task card and no search.
- **The page title stays "Account".** Every section of the Account center keeps that title (D568). The section draws "Usage" and its muted line as its own heading.
- **The days card draws no "Not recorded" day.** The canvas has a reason for a day whose run recorded no cost, but `days[]` has no per-day count of uncounted runs. A day with no runs is drawn as a real $0.00.
- **The receipt omits two lines the canvas draws:**
  - the page a run was on, because `last_run` carries no surface;
  - "answered after [model] failed", because the log records that a fallback answered, not which model failed first. The Fallback pill says that a fallback answered.
- **"Open Eadwyn" is not drawn on the AI empty states.** Eadwyn is the rail on each page, and has no single route to open.
- **"Open the data room" on the empty storage state is drawn for founders only.** `/raise/data-room` is a founder page.
- **A run's cost is shown in cents once it is at least one cent.** The prompt's rule gives four decimals only below one cent. The canvas's placeholder "$0.0731" is $0.07 here.
- **"Held" is the month's included holds plus the top-up holds.** That is what runs in progress have reserved and not yet spent.
- **On U7, "Set by" for a plan on the platform default is one footnote under the table,** not a tag on each of the nine rows. The pill already says "Platform default".

Tests: `frontend/test/usage_page_d642.test.mjs` covers each formatting rule and every state of every card. ### Validation

Canonical SQLite tables (baseline plus migration 323) back the real Hono route,
with actual JWT authentication. Tests cover all five areas, both callers,
multiple companies, deliberately unequal founder/user IDs, NULL and zero sizes,
empty stores, forged selectors, failed reads, numeric precision, and anonymous
or inactive refusals. New assertions are checked with deliberate mutations and
restored runs; the root build precedes the required full drift gate.

The U1 exhausted-allowance rendering test passes a fixed `now` through the card’s existing clock prop. Its hours-and-minutes assertion stays deterministic during the last UTC hour, when live product copy correctly shows minutes only. No product behavior changes.
