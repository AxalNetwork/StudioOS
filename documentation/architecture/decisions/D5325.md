- **Builds on:** D4956 (the Skill Library v2 canvas, boards SK-04, SK-08 and SK-13), D4160 and D4533 (the HQ lifecycle, the evidence hash and the publish gate), D4537 (the HQ list's slug, roles and tools), D4121 (the run-cost estimate).

### 1. Readiness is one server field

`GET /api/admin/ai-agents/skills` (each `skills[]` row) and `GET /api/teams/skills` (each card in `hq[]` and `company.skills[]`) carry **`readiness`**, one of:

| Value | Source |
|---|---|
| `retired` | `status = retired` |
| `in_review` | an open review on the current evidence (`lifecycleStatus` = `in_review`; a published skill too) |
| `published` | `status = published`, no open review on its current evidence |
| `changes_requested` | the latest review is on the current evidence and sent the draft back |
| `missing_cases` | an Axal draft with no live golden case |
| `needs_evaluation` | a required run (live case × required model) with no result on the current evidence; when none has one, only if no run exists on an older evidence either |
| `stale` | no result on the current evidence but results on an older one; or every run in and at the bar with the approval, or an open review, only on an older evidence |
| `failing` | every required run in, below 9 of every 10 |
| `ready_to_publish` | every run in, at the bar, and an unspent approval on exactly this evidence: what the publish gate lets through |
| `draft` | an Axal draft at the bar never sent for review (or sent back on an earlier draft); every company draft |
| `unknown` | a fact the state needs could not be read, a status outside the four, or no required model |

"Current evidence" is D4533's evidence hash (definition, live cases, evaluator, required models). The precedence is `readinessOf`'s: retired, in review, published, changes requested, missing cases, then the evaluation (no result: stale or needs evaluation; some missing: needs evaluation; below the bar: failing), then the approval (ready to publish, stale, or draft). `unknown` is never a passing state: a published skill whose reviews cannot be read is `unknown`, not `published`. A company skill has no golden cases or review, so it is `draft`, `published` or `retired` from its status alone. The same value goes to every caller who sees the skill; a reader only ever sees the published or retired word. The single-skill cards (`GET /teams/skills/:uid`, the create, PATCH and publish replies) carry the same field from the same function.

Both lists stay bounded: the readiness reads are two queries for the whole list (`currentResults`, which the HQ list already ran and now shares, and `reviewHistory`), whatever the number of skills. A failed `reviewHistory` read is `unknown`; in the Team list a failed results read is `unknown` too, while the HQ list keeps answering 500 for it, as it did before.

A published skill with a newer draft in progress reads `published` (or `in_review` once that draft is asked for review). The draft's own progress is the detail route's `freshness` (D4533), not the list's word.

### 3. The draft version check

The version is the draft's **definition hash** (`draftHash`), the same value the HQ detail already answers as `skill.draft_hash`. Every Team card now answers it as **`draft_hash`** for a writer (null for a reader). No column or migration: a hash changes whenever the content does, whichever path wrote it (an edit, a restore, a seed), which a counter would need every writer to bump; `updated_at` is to the second and two saves in one second would share it.

`PATCH /api/teams/skills/:uid` takes **`expected_draft_hash`**:

- equal to the current hash: the save goes through and the reply's card carries the new `draft_hash`;
- different: **409 `draft_conflict`**, with `draft_hash` (now), `draft` (the draft now, as a card's `draft`), `updated_at` and `updated_by` (`{ uid, name }`), for SK-04's conflict dialog ("This draft changed while you were editing"). Nothing is written and nothing is audited;
- not a 64-character lowercase hex string: 400 `draft_hash_invalid`;
- **absent: the save is unchecked, as before.** Two callers send none today (`frontend/src/pages/team/agentsAdapter.js` `updateSkill`, whose `toWorkerSkill` keeps only the draft fields, and `frontend/src/pages/hq/aiAgents/DefinitionEditor.jsx`). Refusing them with 428 would break both editors in a PR that may not touch the UI; #4537 and #4538 send the hash when they build the conflict state. A later decision can make it required once both do.

The check and the write agree on one snapshot: the PATCH reads the draft once (its columns, tags and roles in their order, as one SQL expression), checks the hash of that read, and puts a guard on the same expression as the first statement of its write batch. D1 runs a batch as one transaction; when the draft is no longer that snapshot the guard fails (`json()` of a non-JSON text raises), the batch rolls back, and the reply is the same 409. So a save landing between the check and the write is refused rather than overwritten, with or without `expected_draft_hash`. Retiring a company skill (`{ status: 'retired' }`) writes no draft content and is not checked.

### 4. Run cost

`services/agents/runCost.ts` answers an **estimate**: the tokens and dollars a run of an agent with given skills is expected to cost, from each version's `context_tokens` and the model's price (D4121; `tokens_per_run` in the HQ list, `context_tokens` on a Team card, `/agents/:uid/cost-estimate`). SK-08 asks for something else: "Quality and cost by executed version", counted from the version each run executed. An estimate is not a recorded cost and must not be shown as spend, so it does not meet SK-08. A recorded cost per run by executed version (from `ai_usage_logs.skill_id` and `skill_version`) is #4536's.

So this PR adds no cost route. Both lists carry **`run_cost: null`**, which the screen reads "Not recorded", never 0, and which #4536 fills. The estimate fields keep their names and meaning.

### Fields for #4537 and #4538

- HQ list row: `readiness`, `tools`, `run_cost` (null), and the existing `status`, `golden`, `tokens_per_run` (an estimate).
- Team card: `readiness`, `draft_hash` (writers; null otherwise), `run_cost` (null), `context_tokens` (an estimate).
- HQ detail: `skill.draft_hash` (unchanged), to send as `expected_draft_hash`.
- `PATCH /api/teams/skills/:uid` body: `expected_draft_hash`; 409 `draft_conflict` → `{ error, message, draft_hash, draft, updated_at, updated_by }`.
