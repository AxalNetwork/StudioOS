## D4667 part 2 — A first-ten skill without its evidence is refused before the model (#4667)

- **Status:** built by S35, 2026-11-18. Part of #4667 (part 1 is `D4667.md`). Worker only: no migration, no new route, no UI.
- **Code:** `services/agents/skillEvidence.ts` (`skillEvidenceForRun`, the one check), `services/agents/agentRun.ts` (the manual path), `agents/loop.ts` `runStep` (the scheduled path), `services/agents/skillInputs.ts` (`preflight`'s binding), `routes/team_agents.ts` (the readiness surface reads the same binding).
- **Hands over:** #4534's last criterion, as S1 recorded on #4667 on 2026-11-09: "Required reads are supplied through the approved binding from #4667; naming a skill does not count as loading its evidence."

### What was found, on main `b9a6b549d4`

`skillInputs.ts` was imported only by `reads.ts` and the readiness route. Neither `agentRun` nor the loop's `runStep` read readiness, so a run naming a first-ten skill whose required input was missing, withheld or unreadable still went to the model and was charged.

### What is decided

1. **One check, both paths.** `skillEvidenceForRun` runs the same `preflight` the readiness surface reports, read as the agent's sponsor through the real readers.
   - Manual: `agentRun` calls it right after `skillForRun` and before the skill text, the tool reads, the hold and the model.
   - Scheduled: `runStep` calls it after `sessionSkill` and before `agentRun`, over the context it just built, and hands its result to `agentRun` (`readiness`), which then does not check again.
   - `agentRun` accepts a handed-over check only on an engine run, and only for the same skill. A manual run that names one is checked all the same.
2. **`not_ready` is refused.** The answer is 422 `skill_not_ready`. Its message and `extra.inputs` name each required input that cannot be supplied, by field, read key and status. It carries no record's figures. Nothing is held, read through a tool, logged as usage or charged. The manual path writes a `refused` event. The scheduled path ends the run `refused` / `skill_not_ready`, pauses nothing, and opens the task again, like the other refusals of the run step.
3. **`conditional` runs, and says so.** Its system prompt ends with "The evidence for this skill is incomplete. Say so in your output, and state each limit:" and the preflight's limits.
4. **Evidence binds to the run.** Naming a skill does not load its evidence. The preflight now takes a binding (`Binding`):
   - `granted`: the read keys the agent's rule book names. Any other key is a new status, `not_granted`, and is not read. A required one makes the skill `not_ready`.
   - `bound` (scheduled path only): the keys whose blocks the task's context holds after what it left out for length. A granted key outside it is `missing` (`absent_optional`), reason `not_bound`.
   - `capture`: each read's answer, so the manual path puts the same snapshot it judged into the run's message, as `<agent_data source="read:<key>" trust="data">` blocks under an untrusted-data notice. Withheld, refused and unreadable inputs are not bound.
   - The scheduled path's context already carries its rule book's reads, so it binds nothing more.
   - The per-run ceiling is quoted again once the evidence is in the message, before any hold.
5. **A retried step answers first.** `agentRun` already answers a run key that proposed before any check. `runStep` checks only when no proposal exists for its run key, so a retry whose evidence has gone since still answers its first proposal: one hold, one charge, one proposal.
6. **The readiness surface reads the same binding.** `GET /api/teams/agents/:uid/skills/:slug/readiness` passes the agent's rule book as `granted`, so HQ (#4537) and discovery (#4538) see `not_granted` where a run would refuse.
7. **Scope of the check.** Only the ten slugs of `FIRST_TEN` have a matrix; any other skill passes unchanged. The check goes by slug, whatever the skill's scope, so a company copy of a first-ten skill is checked the same way. Native readers only: a member's approved MCP tool read does not stand in for a required input. The approved-MCP evidence shape is still open (below).

### Tests

`skill_run_evidence_4667.test.ts` covers both paths on the real migrated schema, through the real readers. The manual path runs the real `agentRun` with a stub model. The scheduled path drives `load`, `context` and `runStep` with the engine fixture's fake `agentRun`, which counts holds.
- Ready: the run goes ahead. The manual turn carries the balance the check read, and the usage rows carry `skill_id` and `skill_version`.
- Each of these is `skill_not_ready` on both paths, with no model call, no usage row and no proposal:
  - a required input withheld by its source's rule (an admin sponsor who is not on the venture's team);
  - a source never connected (nothing recorded);
  - a source that cannot be read.
- A key the rule book does not read is `not_granted`, refused on the manual path.
- Conditional (burn older than 45 days): the run goes ahead. The manual system prompt states the limit, and the scheduled path hands it to `agentRun`.
- A retried step that already proposed answers its proposal after its source is emptied, on both paths.
- A forged `readiness` on a manual run is ignored. A skill outside the first ten is not checked.
- A granted key the context left out for length is `not_bound`.
- `agent_skill_runs_d1612d`'s two pinning tests now run their skill under a slug outside the first ten. Their skill was `board-meeting-brief`, which a company agent with no venture now refuses `skill_not_ready`. The pinning they test is unchanged.
