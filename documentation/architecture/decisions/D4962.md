## D4962 — One contract for a company's General fields, and a dev backend that agrees with it (#4962)

#4962 (slot S30, taken at the owner's request, P1). A direct `PATCH /company/:uid` could persist an unsupported stage, a negative head count, an unbounded string, a `javascript:` website, and an arbitrary remote `logo_url` that skipped the hardened R2 upload route. The dev FastAPI disagreed with the Worker on who may read a company and who sees a member's email.

### The contract (`cloudflare-worker/src/services/companyProfileFields.ts`)

`validateCompanyFields(body)` runs before any write, on `PATCH /company/:uid` and on the General fields of `POST /company/create`:

| Field | Rule |
| --- | --- |
| `stage` | one of idea, pre_seed, seed, series_a, series_b, series_c_plus, growth, profitable, public; empty or null clears |
| `employee_count` | a whole number from 0 to 1,000,000 (a digits-only string is read as that number); null clears |
| `description` | at most 280 characters |
| `revenue_range` | at most 100 characters. It has no vocabulary anywhere in the app ("e.g. $1M–$5M ARR"), so it is bounded text, not an enum we invent |
| `current_products`, `expansion_goals` | at most 1,000 characters |
| `website` | http or https, a dotted host, no credentials, at most 500 characters. A bare host gets https; the stored form drops a bare host's trailing slash |
| `linkedin_url` | a LinkedIn company, school or showcase page on linkedin.com or one of its country hosts, stored as https (`linkedin.com` becomes `www.linkedin.com`), at most 300 characters |
| `international_presence` | a list of region names, each at most 80 characters with no comma, at most 30, de-duplicated case-blind, stored as the comma-separated column the app already reads |
| every text field | a string or null, trimmed, no control characters other than tab and newline; an empty string clears |
| any other key | refused (`unknown_field`), not ignored |
| `logo_url` | refused (`logo_url_not_writable`): a logo changes only through `POST` and `DELETE /company/:uid/logo` |
| a body that is not an object | refused (`body_invalid`); a JSON `null` used to be a 500 |

A refusal is `400 { code, field, detail }` and writes nothing. `company_name` and `default_currency` keep their older checks and codes.

### Database

Migration `202611072301_company_profiles_field_triggers.sql` adds triggers for the two stable invariants, `stage` (the nine values) and `employee_count` (an integer from 0 to 1,000,000), on INSERT and on UPDATE of the column. They are triggers and not CHECK constraints because SQLite adds a CHECK only by rebuilding the table, and a rebuild would fail the deploy on any legacy row that predates this validation. A trigger fires only on a NEW write: a legacy row that is never written, or is written for another column (a rename, an archive), keeps its value and stays editable. Description length and URL shapes stay the route's: a legacy row that exceeds them must stay readable.

### Existing outside logo URLs

Not migrated, and not copied: fetching a member's remote image into our storage is a production data change this issue does not authorise. They stay as they are and stay served (the logo `GET` already answers `404 no_stored_logo` for them and the client renders the URL itself). A PATCH or rename leaves them alone; the logo's `POST` replaces one and `DELETE` clears it (the `logo_change` event already records an outside logo as `outside`). The older settings page's "Logo URL" box is removed, since a link typed there is now refused.

### The dev backend (`backend/app/api/routes/company.py`)

The FastAPI router is Replit-dev-only (CLAUDE.md fact 3), but it had its own contract, so local behaviour could not prove production's. It is kept (retiring it is a separate decision) and brought in line:

- a non-member's `GET /company/{uid}` is 404, not a summary;
- a member's email is served to that member only (absent for the others, not masked);
- `logo_url` is gone from its schemas and refused;
- the General fields are validated by `backend/app/services/company_fields.py`, a pure-Python twin of the Worker module;
- writes need a seat (D4960's rule), and the company read carries `viewer`.

The golden cases in `cloudflare-worker/test/fixtures/company_field_cases.json` are run by the Worker validator, the frontend form model and the Python twin, so the three cannot differ without a case saying which.

### What this does not prove

The FastAPI route wiring is now exercised in CI with `TestClient` and a temporary SQLite database: member and non-member reads, a platform admin with and without a company seat, a company editor, non-object and malformed field bodies, unknown fields and a direct `logo_url` PATCH. This proves only the Replit-dev router's local request, authorization and persistence behavior. It does not prove production behavior, deployment or D1 compatibility; the Cloudflare Worker remains the production API and its route-level contract tests remain authoritative.
