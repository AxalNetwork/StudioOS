### What changed

`draftSummary` (`cloudflare-worker/src/services/publications.ts`), the caller D4556 §5 named:

1. **Switch off** (anything but exactly `'on'` in `AI_PROVIDER_GATEWAY_OPENAI`, which is every environment today): the summary runs on Workers AI through `aiRouter.run('publication', …)`, unchanged. `runGatewayTextModel` is never called.
2. **Switch on:** it calls `runGatewayTextModel` first with `openai/gpt-5-mini`, task `publication`, data class `public` (k≥5 aggregates written for publication), the press's rail page and option, a fresh execution id (`publication:draft:<uuid>`) and the same system prompt, user message and 600-token cap. An answer is the summary; the proposal names the gateway model and its usage row.
3. **After a gateway refusal**, it goes back to Workers AI only where the gateway refused before any provider ran and nothing was charged: `misconfigured`, `capacity_unavailable`, `model_not_offered`, or `all_models_failed` with `completion: 'none'` (rate limited, overloaded, billing, auth). That is the same run the switch-off path makes.
4. **Every other refusal stays a refusal** and the draft keeps the aggregate fallback text, as a Workers AI failure does today:
   - the member's own state (`assist_off`, a hold refusal such as `insufficient_tokens`) would refuse again;
   - a guard block would block again;
   - a timeout, a 5xx or an unreadable answer (`completion: 'unknown'`) may have done the work, so it is not run a second time;
   - `terms_mismatch` and `provider_refused` are not retried on another provider, because the data terms differ (D4556 §6, "Fallback").
5. **A throw** from the gateway path becomes `all_models_failed` with `completion: 'unknown'`. The thrown message is never returned.

`temperature` is not sent on the gateway path (D4556's adapter drops it); Workers AI keeps 0.3.
