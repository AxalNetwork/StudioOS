## D526 — One file per decision from D526 on, so PRs stop colliding in DECISIONS.md

**Each decision from D526 on is its own file, `decisions/D<n>.md`.
`DECISIONS.md` keeps D1 to D525 and takes no new entries. `check-decision-ids`
reads both places as one numbering.** GitHub issue 1054 (slot S02). No
migration.

**Why.** Measured on `main` from 2 August to 3 October 2026 (624 commits):
`DECISIONS.md` changed in 130 commits, `frontend/src/lib/api.js` in 113,
`frontend/src/App.jsx` in 109, and the built `docs/` in 92. Every PR inserted
its entry "in numeric position", so two open PRs almost always collided in
that one file, and each merge sent the others back to resolve it. That
happened to #1011, #1034 and #1035 on 3 October. A file per decision gives each
PR a file no other PR touches.

**The folder.** `documentation/architecture/decisions/`:
- `README.md` states the rule: the file is `D<n>.md` with the number the issue
  gives, its first line is `## D<n> — <title>`, and it holds one decision with
  what a `DECISIONS.md` entry holds.
- This file is the first one.

**The check.** `scripts/check-decision-ids.mjs` reads `DECISIONS.md` and every
`D*.md` in the folder. It keeps both of its earlier rules for `DECISIONS.md`
(unique, strictly increasing) and adds:
- **The three the issue named:**
  - the same number in both places, a refusal that names both;
  - a file whose name and heading differ (`D527.md` headed `## D528`);
  - a heading above D525 in `DECISIONS.md`, a refusal that names the file
    the entry belongs in.
- **The same boundary from the other side:**
  - a file numbered at or below D525, even at a gap in `DECISIONS.md`;
  - a file not named `D<n>.md` (`d526.md`, `D0526.md` and `D526-x.md` are
    refused);
  - a file with no heading;
  - a file holding more than one decision. A heading quoted inside a fence
    is not one, as in `DECISIONS.md`.
- `LAST_IN_DECISIONS_MD = 525` is exported, and the rules are exported as pure
  functions so a test can feed them wrong corpora.

**The helper.** `frontend/test/_decisions.mjs` exports `readDecision(id)`:
- it returns the entry, from its heading to the next decision heading,
  wherever it lives;
- it throws when a number is in neither place, or in both;
- fenced headings do not end an entry.

A test pinning what a decision says no longer has to know which side of D525
it is on.

**The rule, where it is written.**
- `AGENTS.md`'s house rule said "adds its D-entry to `DECISIONS.md` in
  numeric position". It now names the folder and the heading form, and keeps
  the `node scripts/check-decision-ids.mjs` anchor the D503 test pins.
- `CLAUDE.md` did not state the rule at all. It gains one bullet under "Rules
  for new work", and its index sentence names the folder.
- `CONTRIBUTING.md` and `.github/pull_request_template.md` never stated it and
  are unchanged.
- Two indexes name the folder:
  - `documentation/architecture/README.md` must name it, because
    `check-folder-docs` refuses a README that does not name its subfolders;
  - `documentation/README.md` points "why is it built this way" at both
    places.
- The D503 test's comment on that anchor is updated.

**Not changed.**
- No entry in `DECISIONS.md` was moved or rewritten, and citations by number
  keep working.
- Open PRs that added an entry at or below D525 keep it there; the old rules
  still accept it in numeric position.
- One open PR, #1061 (D527), adds `## D527` to `DECISIONS.md`. Once it takes
  this change from `main`, the check refuses that heading, and its entry
  belongs in `decisions/D527.md`. Raised on GitHub issue 1054 rather than
  decided here.

**Tests.** New `frontend/test/decision_files_d526.test.mjs` (9):
- each of the three named failures and each extra rule, checked with a wrong
  corpus and its right-shaped twin;
- the real corpus clean across both places;
- `readDecision`: it reads an old and a new entry, refuses a missing or
  malformed number, keeps a fenced heading inside its entry, and refuses a
  number found in both places in a throwaway repo root;
- the script run from two throwaway roots: it exits non-zero when a number
  is in both places and zero when the corpus is clean, so the wiring is
  tested and not only the exported rules;
- the rule files state the new rule, and none still says "in numeric
  position".

`decision_ids.test.mjs` passes unchanged.

**Mutations: 20 run, 20 caught**, each with a non-zero exit and a `not ok`
line, restored from a sha256-checked snapshot. Each rule was removed, and each
was turned the other way or moved by one so that it refuses the right shape:
- the cross-place duplicate, unchecked or inverted;
- the name and heading, unchecked or inverted;
- the D525 line, unchecked, refusing D525 itself, or moved to D526;
- the file range, unchecked or refusing D526;
- the name pattern loosened;
- a headingless file, or one holding two decisions, accepted;
- the folder not read, and the script checking `DECISIONS.md` alone;
- the helper running past the next heading, cut by a fenced heading,
  silently picking one place, or returning null for neither;
- `AGENTS.md` keeping the old rule, and `CLAUDE.md` dropping the new one.
