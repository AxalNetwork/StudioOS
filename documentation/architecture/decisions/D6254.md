## D6254 — The fund page for its GP and its LPs (#6254)

Build the fund-page slice of Investor Fund Detail Pages (D6244 and the owner
answers in D6244-p2): I9, I10, I11, the fund-page states in I18, phone I19A/B
and dark I21A. Reporting-period author/reader boards stay with #6250; the
cross-fund performance detail stays with #6253.

### Source and projection

| Value | Read | Recorded source |
| --- | --- | --- |
| Facts, live LP count, committed/invested totals, audience, periods | `/api/funds/:id/page` | Existing `readFundPage`; LPs receive issued periods only |
| Management fee and carry | Same page read | `vc_funds.management_fee`, `carried_interest`, fractional rates; zero is recorded |
| Document metadata | Same page read | The attached LPA's `legal_documents.status`, `version`, `updated_at` only |
| Today's performance | `/api/fund-performance/:id` | Existing scoped performance service, including GP-of-record access from D6246 |
| Position and unmarked counts, mark as-of | `/api/fund-performance/:id/positions` | Existing GP/admin-only position read |
| Your commitment, invested amount, signature date | `/api/funds/lp-portal` | Caller-owned `lp_holdings`, filtered to this fund |
| Your distributions and multiples | Same LP portal read | Existing per-LP performance, matched by both LP and fund id |

`readFundPage` adds a narrow terms object and a document descriptor list.
Neither adds private GP account/company identifiers, document bodies or
storage locations. LP and GP terms are the same recorded terms. Missing
rates stay null with reasons; malformed rates fail the read. There is no
other fund-document list in the schema, so other documents say Not recorded
with a reason. No store, route, sum, migration or write is introduced.

The browser validates the extension when present. Older page snapshots can
omit it; that absence displays a gap rather than a guessed fee. Present but
corrupt terms/documents fail validation.

### Page behavior

The GP view leads with the next recorded action: the first LP when none is
recorded, the newest draft returned by the period read, or a new reporting
period. The LP view links only to an issued report. GP zone navigation is hidden
for LPs and until the audience read resolves. Facts and totals lead
into today's performance, then the canvas's three-column GP layout or the
two-column LP reading layout. Both collapse to one column on phones.

Performance, GP positions and the LP portal load independently. The server's
`can_manage` decides which read exists at all: LPs never call GP positions;
GP-only views make no LP portal call. Changing fund/audience remounts those
reads; the existing company-scoped page hook discards old results. Missing
marks are not replaced by cost, and a failed read says Unavailable with
Retry. A zero distribution, fee or carry remains zero.

The LPA download distinguishes Refused, no stored body and Unavailable;
each leaves the rest of the page intact. Existing fact/terms editing and
brief preparation stay behind the existing management gate.

### Canvas departures

- I9's latest-quarter fallback is superseded by the merged D6246 GP read:
  both audiences can read today's scoped performance.
- The Uncalled figure has no field in that performance response. It is not
  computed by subtracting values from separately timed reads; the existing
  committed/called figures retain their separate basis.
- Other fund documents have no recorded list beyond the attached LPA.
  Their section states that gap rather than inventing documents or controls.
- LP history is approved but the mounted quarterly-history endpoint remains
  GP-only. This page explains the unavailable view and links issued reports;
  it makes no forbidden history or position request.
- Existing shared shell, Eadwyn rail and terms editor are retained. No
  unsupported Eadwyn report-summary or valuation action is added.

Regression coverage includes SQLite projection/privacy checks, zero/missing/
invalid rates, document metadata, LP draft exclusion, extended response
validation, per-fund/per-LP traceability, next actions, independent failures
and mounted assertions that forbidden reads never execute.
