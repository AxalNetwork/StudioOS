## D7705 — Market figure history for create and Eadwyn answers (#7705)

The two project-create paths append typed, no-source history for the TAM and
SAM actually stored, naming the authenticated actor. An explicit zero survives
ordinary creation; the prior blank/falsy handling is retained rather than
turning an absent input into a stored zero or empty string. History failure is best-effort, as in project PUT: the
created project remains and the response reports that provenance was not saved.
Client-supplied provenance does not relabel these create-time figures.

Eadwyn's existing SOM coercion is unchanged. A nonnumeric or negative result,
or one above a recorded SAM, follows the existing chat-note fallback without
changing the canonical figure or its history. An accepted answer batches the
project update with `marketFigureStatement`; a history error rolls both back
before the same fallback. This typed answer has no sizing version: the builder's
empty version-UID lookup resolves to NULL (version UIDs are server-generated
UUIDs). It has no named source and records the acting user. No sizing formula,
service, migration or production record changes here.

The source guard inventories project INSERT/UPDATE column lists and follows
local declaration/array-push dependencies, including PUT's `baseFields` and the
answer router's `colMap`. A market writer outside the three reviewed writer
files fails, as does a reviewed writer file with no history call. Planted
literal and dynamic writers exercise the guard. It is a syntax-level guard,
not a general proof over arbitrary program-generated SQL; a new construction
must extend the guard and receive review.

Validation is recorded in the PR and issue STATUS after the final tree is
checked. Fixtures use synthetic records over the complete migrated SQLite
schema; they are not deployment or production evidence.
