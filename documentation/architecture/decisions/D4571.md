## D4571 — Security S2: a control matrix read from the repository, guards that keep it true, and probe outcomes (#4571)

- **Status:** built 2026-11-06. Part of #4554.
- **Scope:** read-only inspection, plus tests and one script change (the probes' outcome line). No production IAM, secret, WAF, Access, D1, bucket, logging or deployment setting was read or changed.
- **Snapshot:** `documentation/audits/SECURITY_CONTROL_MATRIX_2026-11-06.md`, from `main` at `af28b98dbb`.

### What was decided

**Only what the repository shows is called verified.**
- Each control is VERIFIED (repo) when a test holds it, OBSERVED (repo) when the files show it but nothing tests it, and UNVERIFIED when it lives in a dashboard this session could not read.
- Account and zone IAM, WAF and bot rules, Access applications, rulesets, token scopes, bucket settings and scanner results are all UNVERIFIED. They are not "secure".
- A scanner being present is never reported as zero findings.

**Guards on every workflow, not one at a time** (`frontend/test/workflow_security_4571.test.mjs`):
- **WF-1:** every action is pinned to a full SHA.
- **WF-2:** every container image is pinned by digest.
- **WF-3:** every workflow declares its token's permissions, and none is `write-all`.
- **WF-4:** no `pull_request_target` or `workflow_run`.
- **WF-5:** no outsider-written event text inside `run:` or `script:`.
- **WF-6:** a comment-triggered workflow with a write token gates on `author_association`.

All six pass today, except where a finding is recorded. A recorded finding is a file named in the test together with its register id, and that id must be a row in the register. Removing the entry is the remediation, and the test fails if a fixed file is left listed.

**Access is described, not changed** (R2-02).
- Production has both Access settings unset (GOTCHAS (h)), so `requireCfAccess()` is a no-op there and `requireAdmin` is the whole gate on the document routes.
- The tests prove three things:
  - the application check stands on its own;
  - a configured middleware fails closed, including when the JWKS is unreachable;
  - every admin document route is either Access-mounted or on an explicit list waiting for the owner's matrix.
- The KYC per-document route is on that list (SC-01).
- Adding the mount is left to the owner, because a worker mount without the matching Access-app path returns 403 to every admin (the lesson GOTCHAS (h) records).

**Signed downloads have negative tests:** the TTL clamp, one object per token, tampering, expiry, replay, a KV failure refusing, and one generic 403.

**R2-09: every probe run names its outcome** (`scripts/lib/probeOutcome.mjs`).
- `EDGE_CHALLENGED` means the edge turned the probe away. It is a coverage gap, not a sign-in result.
- A skipped check is never a pass.
- Only the mailbox probe, which follows the link and asserts a session, can say `VERIFIED_END_TO_END`.
- The mailbox probe now also stops at a refusal and says who refused, as the insert probe already did.
- Exit codes are unchanged. No edge rule is relaxed and no CI range is allowed.
