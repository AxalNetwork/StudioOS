## D4674 — Expertise keeps prices, currencies and concurrent edits (#4674)

- **Status:** built by Claude Code for slot S26, 2026-11-07. Not deployed and not checked live.
- **Part of:** the Expertise audit (#4674, P1).
- **Migration:** none. The revision is the row's existing `updated_at`.
- **Code:** `services/advisorLimits.ts`, `routes/advisors.ts` (services and profile writes); `frontend/src/lib/moneyInput.js`, `advisorLimits.js`; `format.js` (`moneyCents`), `kit.jsx`, `ServicesZone.jsx`, `ProfileZone.jsx`, `expertiseModel.js`, `boards/advisorExpertise.js`.

### 1. What was wrong

- The price box stripped every comma: `12,50` was 1250 dollars and `1,5` was 15.
- The Expertise overview printed every price as whole US dollars: CHF 123.45 read `$123`.
- A service was created in USD when no currency was sent.
- `PATCH` read the row, merged in memory and wrote every column back, so two editors changing different fields lost one change, with two successes.
- Text over a limit was cut by `.slice` and reported as saved.

### 2. What changed

1. **Price input** (`amountToCents`, digit-string arithmetic, no float): a separator before one or two digits at the end is the decimal mark; before exactly three digits it is a group mark; with both, the last is the decimal. A lone dot before three digits (`1.500`) could be either and is refused with a sentence; so is anything malformed. Blank is "not recorded", `0` is a price.
2. **Currency is stated and supported.** The create form has a currency select; the Worker refuses a missing or unsupported code. The list holds only currencies with two decimals, because the price is stored in hundredths. Changing the currency of a priced service requires the price in the same edit.
3. **Money prints in its own currency, exactly** (`moneyCents`): whole amounts drop the cents, anything else keeps both. The overview and the detail row agree; `usdCents` is the same function fixed to USD. The CSV/export carries a Currency column beside the minor-unit amount.
4. **Concurrent edits.** The service and profile writes name only the fields in the body (a `CASE WHEN` per column in one fixed statement), so edits to different fields both persist. A `revision` makes an edit to the same record conditional; a stale one is a 409 with the current row, and the editors show it and keep nothing silently.
5. **Limits are refused, not cut** (`boundedText`, `boundedList`), shared with the inputs' `maxLength` through `advisorLimits.js`; a test holds the two files equal. After a save the editor resets from the row the server stored.

### 3. Left alone

- Two writes in the same millisecond share an `updated_at`. A stale revision could then pass; for different fields this does not matter (both persist), and for the same field the window is one millisecond.
- Existing rows keep whatever currency they hold; an unsupported stored code stays selectable in the edit form until it is changed.
- Retainers and other advisor price fields use the same stricter `price_cents` rule (a number or digit string) through `parsePriceCents`.

### 4. Tests

`advisor_stores.test.ts` (currency required and supported, magnitude-changing prices refused, currency change needs the price, limits, different-field edits both persist, stale revision 409 for services and the profile) and `frontend/test/advisor_expertise_d4674.test.mjs` (the parser table, round trip, CHF 123.45 on both surfaces, edit body, revision sent, limit parity). Each assertion was mutation-checked: ten mutations, each fails a test.
