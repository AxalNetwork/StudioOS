## D4811 part 24 — Closings on the agreement lifecycle: honest reads and audited transitions (#4811)

### Built (part 24) — 2026-11-13

D4811 (#4811) part 24 finishes the owner's answer of 2026-11-13 to S1's question B of 2026-11-09 (**A**: Closings takes the agreement lifecycle, Prepared, Ready for signature, Sent, Executed, Voided, instead of its own). Part 22 (#5752) built the read side: one pure rule, `closingPaperLifecycle` in `frontend/src/lib/contractLifecycle.js`, maps a closing line's staged paper (D1216, `services/stagedSigning.ts` `readStaged`) onto the agreement lifecycle and draws the agreement's own pills. This part closes the two gaps that were left: reads the rule could not honestly answer, and transitions that were not audited as an agreement's are. No migration, and no stored or API value changes.

**The mapping (unchanged from part 22, with this part's three rows added):**

| Closings paper, as `readStaged` returns it | Drawn as | Since |
|---|---|---|
| `complete` (every stage, Axal's included, signed) | ● Executed | part 22 |
| a stage `sent`, `signed` or `awaiting_release` | ➤ Sent · awaiting signature | part 22 |
| stages, all `waiting` | ◔ Ready for signature | part 22 |
| only voided papers | ⊘ Voided | part 22 |
| no paper (an empty list) | "No paper sent", no pill | part 22 |
| a stage `declined`; a stage `void` while the paper is not | "Declined"; "A signer's envelope was voided", no pill (question D, answered A) | part 22 |
| the list is not a list (a failed or malformed read) | "Unreadable", no pill | **part 24** |
| a stage state outside the six `StageView` writes, or a stage with none | "Unreadable", no pill | **part 24** |
| a live paper with no stage recorded | "Not recorded", no pill | **part 24** |

Prepared is still never drawn: a staged paper is generated (text and digest stored) and stage 1 is sent in the same request, so no closing store holds a paper before it is generated. The closing's own Open, Closed and Cancelled is the round's state, not a document's, and stays as part 22 left it.

1. **Honest reads.**
   - Before this part, `closingPaperLifecycle(null)` and a 200 answer with no `envelopes` list both read "No paper sent", and the admin desk's route dialog and third-party drawer read "No paper sent" while the line was still being read and after its read failed (they were handed the desk's `[]` placeholder). A stage state the Worker never writes counted as not moving and read "Ready for signature"; a live paper with no stage read "Ready for signature" too.
   - Now `closingPaperLifecycle` returns `unreadable` for a non-list and for an unknown stage state (`CLOSING_STAGE_STATES`, the six `StageView` states), and `unrecorded` ("Not recorded") for a live paper with no stage. The Worker's `complete` is still read first. The words are `CLOSING_PAPER_HONESTY`.
   - `deskModel.envelopesOf(answer)` returns the list or null. The desk (`AdminClosing.jsx`) turns a null into its failed-read state (Unreadable); the room (`RecordRoom.jsx`) into null ("Could not be read"). `deskModel.paperEnvelopes(entry)` hands the dialogs undefined while the read runs and null when it failed, and `paperWord(undefined)` reads "Reading…".
   - `PaperState` draws Unreadable in red with its dark pair, as the desk's failed read is; Not recorded is plain words.
2. **Audited transitions.** Each stage's envelope already wrote the e-sign trail (`esign_envelope_created`, the signature). Now, as agreements are:
   - an admin who starts the paper on a founder's closing writes `closing_paper_sent` through `logAdminAction` (both stores): `uid`, `deal_id`, `commitment_id`, `document_type`, `stages`, `countersign`, `position`, stage 1's `envelope_uuid`, `lifecycle: 'sent'`. The founder starting their own paper acts for no one else and writes only the e-sign trail. A start refused after the paper is recorded (the send failed) writes no row;
   - the Super Admin who releases Axal's countersign writes `closing_paper_countersign_released` under their own id, since the stage's e-sign trail names the paper's creator as sender. A release out of turn writes nothing;
   - an envelope voided because its text did not match the recorded digest writes `envelope_voided` (`by: 'system'`, `reason: 'text_changed'`, the staged uid and position) to its own trail, as the workflow void does. `appendAudit` and `AuditEntry` are now exported from `routes/esign.ts` for this.

   No row carries a token, a name, an email or the text. The guards are the ones D1216 already holds (the order, Super Admin with step-up for the countersign, the digest), and they are not changed.

**Where this departs:**
- **The mapping stays in the frontend, not in the Worker read.** The brief asked for the mapping in the Worker read if Closings mapped one to one. Part 22 already built it as one pure rule that every Closings view (desk, dialogs, room) draws, over facts the read already returns. A second copy in the Worker would be two rules that can drift, so this part does not add one.
- **Part 22's test now expects Unreadable for `closingPaperLifecycle(null)`**, not "No paper sent" (`contracts_executed_closings_4811`). An unread list was not given a state then either; it now also is not called no paper.
- **No new lifecycle words.** Every pill is `lifecycleBadge('agreement', …)` from `AGREEMENT_STATES`; Unreadable and Not recorded are the house's honesty words, drawn without a pill.
- **No owner question.** Every Closings state either maps to a lifecycle word or was settled by question D (answered A on 2026-11-13).
- **This is a part file** (`D4811-p24.md`, D5615), not a section appended to `D4811.md`.
