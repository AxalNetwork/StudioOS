## D1363 — Top up where a recording stops for tokens, and no AI limit for the Super Admin

- **Status:** decided by the owner on 2026-10-28; built by S21. The owner said:
  - "There should be a Top-up option here directly. But for the Super Admin, there should be a limit." They clarified it with "No limit for Super Admin (Recommended)".
  - "If users are blocked and have to go back, it's a hassle. They should be able to top up"
- **Migration:** none.
- **Builds on:**
  - D640: the AI budget and its holds;
  - D783: a plan includes 25% of its price, and the admin licence keeps typed caps;
  - D788: a member's own spend limit;
  - D791: the pause;
  - D1288: the Add tokens sheet opens over any page.

### 1. Top up where the member is, and the run continues by itself

A member refused for AI tokens is never sent to another page and never has to start again. They top up over the page they are on, and the refused step continues once the tokens are in their balance.

- **One signal.** The Add tokens sheet (`components/checkout/PackSheet.jsx`) calls `notifyTokensAdded()` once, when its landing reads the order as credited. It never fires while the payment is still being added. `onTokensAdded(fn)` (`lib/aiTokens.js`) calls `fn` once, and returns the unsubscribe.
- **Which refusals.** `tokenRefusal(error)` is true for `budget_user_day`, `budget_user_month` and `tokens`. These are refusals that buying tokens fixes. It is false for:
  - a pause (D791);
  - a run held for review;
  - the member's own spend limit (D788).

**The processing screen.** When the allowance and the balance cannot cover a recording's processing, the Worker stores `NOT_ENOUGH_TOKENS` as the session's error (`services/aiRouter.ts`). That is the same sentence `budgetRefusalMessage` gives every such refusal.

- `processingOf` (`services/interviewProcessing.ts`) adds `top_up`. It is true when the stage is `failed` and the error starts with that sentence. A placement refusal adds "The transcript is ready…" after it, and still counts.
- `ProcessingStages` (`pages/founder/RecordingView.jsx`) then shows **Top up and continue** beside Retry. It opens the Add tokens sheet over the page. `ResumeOnTokens` retries processing once the tokens land, with no second press.
- Any other failure shows Retry only.

**Record a Session.** A Start refused for tokens shows **Top up and continue** in the dialog (`RecordLightbox.jsx`; `startRefusal` adds `topUp`).

- **Eadwyn AI's send refused:** once the tokens land, the send is made again on the same session, and the dialog carries on as if the first press had worked.
- **Any other Start refused:** the refusal clears and the dialog says "Tokens added. Press Start to continue." Starting a recording or opening a meeting is never done without a press.

### 2. No limit for the Super Admin

`resolveAiCaps` (`services/aiBudget.ts`) gives an admin who is in `super_admins` (`hydrateSuperAdmin`) the caps `SUPER_ADMIN_AI_MICROUSD`. That is $1 billion a day and a month, a figure no run reaches. The read says `source: 'super_admin'` and `unlimited: true`.

- **Never refused for the allowance.** Every hold is taken from the included allowance, so the top-up balance is never drawn.
- **Still counted.** Each run is reserved, settled and logged as before. HQ › AI usage shows the Super Admin's spend like anyone's.
- **Still stoppable:**
  - a pause (D791) applies;
  - the member's own spend limit (D788) applies, because each is set on purpose.
- **Only the Super Admin.** A plain admin keeps the typed admin caps and its day. A row in `super_admins` for a user who is not an admin grants nothing here. The flag reads as not elevated when `super_admins` cannot be read (`loadSuperAdminFlag`), so an error never removes a limit.

**What the Super Admin sees.** No surface shows the billion-dollar figure. Each shows "No limit" and the month's spend:

- the usage card (`AiBudgetUsage`);
- the Worker rail;
- `/account/usage` (`allowanceView`);
- `/account/ai-tokens` (`availableView`, `limitRows`);
- the licence card (`allowanceCard`);
- the spend meter (`loadMyAiSpend` gives no cap).
