## D934 — Admin · Community's four lightboxes: Events, Job postings, Circles and Recent activity

- **Status:** built by S10 in slot S27 for #2718 (part 4 of #2367).
- **Basis:** `origin/main` at `638e4e661a`, which carries D918's Events reads (#2733). Paths are relative to `frontend/src/pages/admin/community/` unless they say otherwise.
- **Canvas:** "Community", boards CM3, CM4, CM5, CM6 and CM12 (`design/incoming/Community Page.dc.html`).
- **Migration:** none. No Worker change: every read exists on `main`.

### 1. The lightboxes

| Board | File | Opened from | Its read |
|---|---|---|---|
| CM3 Events | `EventsLightbox.jsx` | the Events card's "See all events" | `GET /api/admin/events`, D918's paged list (#2701): filtered, sorted and paged by the Worker, each row with its own counts |
| CM4 Job postings | `JobsLightbox.jsx` | the Jobs card's "See all postings" | `GET /api/admin/jobs`, every page |
| CM5 Circles | `CirclesLightbox.jsx` | the Circles and roster card's "See all circles" | `GET /api/admin/circles` |
| CM6 Recent activity | `ActivityLightbox.jsx` | "See all activity" on the Recent activity card | `GET /api/admin/community/activity` (D932), paged by the Worker |

- **The shell is `CommunityLightbox.jsx`.** It is a centred `Lightbox` from `frontend/src/ui/`, never a drawer. Below 1024px the lightbox becomes the page (`pageBelow="lg"`), with a back link "‹ Community" and a list in place of the table (CM12).
- **The pure parts are in `lightboxModel.js`:** search, filters, sorts, the 25-row page, "1–25 of [N]", and the Events and activity queries.
- **The address carries the lightbox.** `?open=events|jobs|circles|activity` opens it, so a link can.
  - Opening pushes, so Back closes the lightbox. Closing replaces the entry and keeps every other key.
  - Esc or Close closes the lightbox, and the `Lightbox` puts focus back on the opener.
- **Each lightbox makes its own reads when it opens.** A failed read costs only that lightbox. It says it is not the same as none, and Try again reads again.
- **Nothing is decided in a lightbox.** A row's title opens the item in its console:
  - an event opens its Events desk page, `/admin/events/:id`;
  - a posting opens the job board, `/admin/jobs`;
  - a circle opens circles, `/admin/circles`.

  Neither the job board nor circles has an address for one item, so a row opens the console's list.

### 2. What each lightbox draws

- **CM3 Events.**
  - D918 (#2701) merged before this PR, so as the issue asks, CM3 reads D918's paged list, and **D915's Guard G is retired here**: no analytics read is made.
    - The Worker searches (title, host or venture), filters, sorts and pages, 25 rows a page.
    - Each row carries its own `seats_taken`, `attended` and `waitlisted`.
    - A list with no `total` is drawn as could not be read, never as no events.
  - Columns: Title (with Featured), Type, Starts, Status, Capacity, Registered, Attended, Waitlisted, Fill and Show-up.
  - These are D915's words, through its own functions (`../events/eventsDeskModel.js`), fed D918's counts, so this lightbox and the Events desk cannot disagree:
    - Registered is seats taken;
    - Fill is "No cap" with no capacity;
    - Show-up is "Not held yet" before an event ends, and "Not held" for a cancelled one.
  - The host's name the list carries is never drawn.
  - Filters are D918's: status, when (upcoming, this week, next 30 days, ended), visibility, price and featured.
  - Sorts are D918's: start date (earliest first), newest, most registered, fill and show-up.
  - **The canvas's Type filter is not drawn**, because D918's list does not filter by type. Type is shown as a column.
- **CM4 Job postings.**
  - Columns: Role, Company, Status, Remote or on-site, Seniority, Created and Applications.
  - Filters: status, remote or on-site, seniority. Sorts: most applications, newest and role.
  - **The canvas's Posted and Days open are not drawn.** They need when a posting was published, which no read returns. Created stands in, and the foot says so.
- **CM5 Circles.**
  - Columns: Name, Type, Access, Published, Featured, Members and Activity. Members and Activity carry the "As entered" tag in the header, because an admin types them on each circle.
  - Filters: type, access, published, featured. Sorts: name, and members as entered.
- **CM6 Recent activity.**
  - It shows D932's rows, newest first, 25 a page.
  - Filters: kind, a from–to date range, and a title search. Each change is a new read of page 1.
  - A row dated by its item's last change carries a "Last change" tag.
  - A source that failed is named, and its rows are not counted, which is not a claim that nothing happened. The Worker's reason is not drawn.
  - The Worker pages to 1,000 rows, and a longer list says where paging stops.

### 3. Never a member's name

- None of the lightboxes reads the roster, a registrant list or the wellbeing aggregate.
- The activity read names no member: an admin's act is "An admin", and a member's act is the item or a count. The `actor` field is never drawn.
- Titles of events, postings and circles appear, as the consoles draw them.
