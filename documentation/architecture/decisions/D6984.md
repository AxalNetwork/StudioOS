## D6984 — The chosen role and plan travel from every public button into sign-up (#6984)

#6984 (X2, part of #6976; slot S05). Depends on #6983 (X1, PR #7027), which gave `/for-investors` its own investor lane.

### What was wrong, traced on main

| Where | What it did |
| --- | --- |
| `/for-founders`, `/for-investors` plan cards (`pages/site/DoorPage.jsx`) | every plan, free or paid, opened the door's lane link (`/register?lane=founder`); the plan and interval were lost |
| `/pricing` closing "Get started" (`pages/PricingPage.jsx`) | bare `/register`, whatever tab was open |
| `/pricing` Institutional card (`lib/pricingModel.js`) | bare `/contact` |
| `/register` (`pages/RegisterPage.jsx`) | a lane in `localStorage` `gvpn:intent` was reused with no expiry when the address named none, so an old investor click headed a later plain `/register` with the investor copy |

### What changed

- A door's paid plan opens `registerPathFor` (`lib/planIntent.js`, #4651), the same helper Pricing's cards use: `lane`, `plan=<catalogue key>`, `interval=monthly` (the door shows the monthly price), and the Pricing return as `next`, with `seen` when the plans read priced the tier (`planRegisterPath`). The plan key is the door's catalogue and tier id, and a link is only built when `specFor` finds a paid card for it; the free plan keeps the lane link.
- Pricing's closing button keeps the active tab's role: `closingRegisterPath(tab)` (`lib/pricingModel.js`) is `/register?lane=<the tab's family>`, so the investor tab opens `/register?lane=investor`; Models names no role. The Institutional card opens `/contact?topic=invest`, as the investor door's does (#6983).
- `laneForVisit` (`lib/registerCopy.js`): an address lane always wins and is stored as `{ lane, ts }`; a stored lane is used only when the address names none and it is under 24 hours old (`INTENT_TTL_MS`). An entry with no `ts`, a `ts` in the future or a value that is not a lane is treated as expired. The page already wrote `ts`; it was never read.
- `/register` shows one context line under the heading (`RegistrationContext`, `components/auth/RegistrationPlan.jsx`): "You are signing up as [role]." and, only when the catalogue read returned the plan (`selectionFor` state `ready`), "Plan: [plan name], [monthly|yearly]." The name is the catalogue card's; a plan not offered, without the asked interval, or unreadable is never named on that line. The layout, the membership steps line and the existing plan block are unchanged.

### Safety

No payment or membership is said to start: the membership steps line stays. `next` is built by `registerPathFor`, which drops a `next` that fails `sanitizeNextPath`. No price is typed: `seen` comes from the plans read.
