## D6420 — Prompt audit of 2026-11-14: what was applied (#6420)

**Context.** On 2026-11-14 every prompt the repository holds was read against
the code it describes: the instruction files (`CLAUDE.md`, `AGENTS.md`,
`replit.md`, `README.md`), the skills under `.claude/skills/`, the agent and
feature prompts in the Worker, and the Claude API calls. A second reader
checked each finding against the files. 51 findings were written; 47 stood.
The owner approved a PR for the high- and medium-confidence ones. They went
out as three PRs, all part of #6420.

**Decision.**

1. **Docs and skills corrected to match the repo.** Sentences in the
   instruction files and the skills that named a path, a command, a section
   or a rule the repository no longer has were rewritten to say what is there
   now. No rule changed; only its description.
2. **Untrusted text wrapped per D1506 at two more call sites** (this PR).
   - **An Eadwyn ask** (`routes/eadwyn.ts`, `askRunOptions`). What a connector
     returned and the file a member attached were joined into the system
     message with no delimiter. They now travel in the last user message,
     before the question: each connector's lines in a `connector_row` block,
     the file in a block of a new kind, `attached_file`. `ASK_PROMPT` carries
     `UNTRUSTED_RULE`. "Can propose" stays in the system message, because its
     words come from the catalogue. The file's name is caller-typed and is no
     longer sent to the model; the stored message still shows it. The limits
     (8,000 characters of file, twenty 300-character lines a connector), the
     guard's text, the quote and the reply shape are unchanged.
   - **A deck version's review** (`services/deckVersionReview.ts`). The cards'
     words went raw under "## Card N". `reviewMessage` now puts them in one
     `deck_import` block and `REVIEW_SYSTEM` carries the rule, as the uploaded
     deck's review (`deckExtract.ts`, `reviewPrompt`) already did.
   - D1506's table lists both, and its fixture test now holds 28 fixtures over
     eight kinds.
3. **The Claude API fossils and prompt contracts.** Settings and rates left
   over from retired models were removed or corrected, and prompts whose
   wording disagreed with the code that reads their answer were brought into
   line with it.

**Flagged, not applied.** Each needs the owner's choice or a measurement
first.

- `replit.md` asks for a `CHANGELOG.md` line on a user-facing change;
  `AGENTS.md` and the changelog gate forbid a task PR from touching it.
- `README.md` links a setup page that no tracked file builds.
- The Claude adapter sets no thinking or effort value, and the assistant's
  cached prefix is shorter than the least a cache takes. The review runner's
  fallback handling was flagged at low confidence.
- Agent skills: a skill's `roles:` and `tools:` against what each role's rule
  book reads; figures the records fully determine being written by the model;
  golden cases run on a prompt production does not send; seventy skills
  sharing six of eight steps; a persona's goal beside a role's mission.
- Feature prompts: a member's display name written into the advisor's system
  message; a deck theme's voice placed ahead of the fixed instructions, which
  costs cached input; about thirty prompts that ask for JSON in prose and
  slice it out of the reply.
- Low-confidence rewrites left alone: two skills that name a command a third
  says cannot finish in a session, and the list of tool names in the
  assistant's prompt.

Four findings did not stand on the second reading and were dropped; among
them the equity-split and syndicate prompts, which D766 lists as deliberate.

**Tests.** `cloudflare-worker/test/untrusted_ask_and_review_d6420.test.ts`: a
file, a connector line and a card that each say "ignore previous
instructions" appear only inside their block and never in the system message.
