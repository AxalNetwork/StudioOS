## D6697 — HQ formation case reads: the queue with saved views, one case, the filings board, ages and bands (#6697)

- **Status:** built 2026-11-23 for #6697 (H1 of #6680, Phase 3), on #6686's case store and eight recorded stages (D6686, D6686-p2), #6694's filings (D6694) and #6695's requests (D6695).
- **Files:** `routes/admin_formation_cases.ts`, `services/formationQueue.ts`, migration `202611231601_6697_formation_case_access_log.sql`, client `frontend/src/lib/api/adminFormationCases.js`, test `cloudflare-worker/test/admin_formation_cases_6697.test.ts`.
- **Out of scope:** writes (#6698), partner access, catalogue routes, screens. `GET /api/admin/incorporations` is unchanged.

### Who

- **Gate:** every route is `requireHqAdmin`. A non-admin is refused (403), and a branch gets the named `hq_only` refusal.
- **The queue and the filings board** carry no person's name, email or user id and no document, for any admin.
- **The case read:**
  - The founder's name and email, the HQ owner's name, each request's asker and asked-of user, a stage's owner and completer, note and event detail, the case's documents and its recorded answers go only to the case's assigned HQ owner (`hq_owner_user_id`) and Super Admins (`access: "full"`).
  - Any other admin gets counts (`access: "counts"`): `people: { count }` and `documents: { count }`, and the choice record without its answers.
  - Each full read writes one `formation_case_access_log` row per kind returned (`people` always, `documents` and `answers` when the case has any).

### The queue

- **Scope:** every case, legacy and v2 together, with legacy rows marked `legacy: true`.
- **Saved views (`view`):**

  | View | Rule (open cases) |
  |---|---|
  | `unassigned` | no HQ owner |
  | `waiting_on_hq` | waiting on HQ |
  | `screening_review` | stage `structure_review` |
  | `partner_late` | waiting on the partner, partner clock `late` |
  | `with_registry` | stage `submitted` |
  | `registry_question` | stage `registry_query` |
  | `waiting_on_founder` | waiting on the founder |
  | `closing` | registered, activating or handed off |
  | `all` | every case |

- **Filters:** `country` (from the case's catalogue form; a legacy case has none and never matches), `partner`, `route` (`simple` or `specialist`) and `track`.
- **Counts:** `views` holds the count of each view under the filters. An unreadable filter is a 400 with a code.
- **Read cap:** at most 2,000 cases are read for one answer; past that, `truncated` is true.

### Ages, clocks and bands (`services/formationQueue.ts`)

- **Ages:**
  - a case's age runs from `created_at`, and its stage age from `stage_entered_at`;
  - a party's clock sums the spans in which the case waited on that party, so a case waiting on the founder adds nothing to the partner's clock;
  - a closed case's clocks stop at `closed_at`.
- **Bands:** `new` up to 2 days, `aging` up to 7, `late` past 7, the same for every age. No per-partner target is applied, because none is agreed.

**Why a new log.** The issue asks for ages from event timestamps, but nothing recorded when `waiting_on` changed: `formation_cases.waiting_on` holds only the present party, and its writers record no waiting party in their events.
- Migration `202611231601_6697` adds `formation_case_waiting_log`, written by two triggers: one on a case's creation and one on every change of `waiting_on`. No writer is edited.
- Each existing case gets one row (`source: migration`) dated when the migration runs. Its clocks start there, `clocks_complete: false` says so, and the earlier history is never guessed.
- Both new tables are append-only (triggers refuse UPDATE and DELETE).

### The case read

- **Stages:** all fourteen stages in order, each with its recorded row where one exists. Per D6686-p2's owner answer, the eight stages from `paid` keep a record; `draft` to `quoted` read `record: null`.
- **Filings:** the case's filings, with days since submitted.
- **Requests:** the case's requests (title, kind, parties, due date, state).
- **Fee lines:** the catalogue's lines for the case's form and version, and the order's amount for a case with an order.
- **Timeline:** every event, with detail only for a full read.
- **Choice record:** the latest recorded answers' revision and date, with the answers only for a full read.

### Filings board

`GET /api/admin/formation/filings?state=` returns every filing grouped by state, with its case's uid and track, days since it was submitted and its band. It names no one.
