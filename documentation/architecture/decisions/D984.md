## D984 — Program grants part 3: the Administrator's read `GET /api/licence/mine/programs`, and HQ's dated copy of a licence's grants on its branch (#2775)

- **Status:** built by S14, 2026-10-25 (#2775, part 3 of #2376, under D981).
- **Migration:** 554 (`cloudflare-worker/sql/migrations/554_branch_program_grants.sql`).
- **Canvas:** "Program grants", GR7 (the studio's Programs tab), GR8 (a grant's terms) and GR13 C (`design/incoming/Program Grants Page.dc.html`).
- **Basis:** part 1 (D982, #2835): the store `program_grants`, the defaults and `presentGrant`.
- **Worker first.** The tab that reads this (`subsidiary/licence/ProgramsTab.jsx`) is part 7's. This part adds the read, the copy and the client, no screen.

### 1. The read

`GET /api/licence/mine/programs`, in `routes/licence_programs.ts`, mounted at `/api/licence` beside `licence_requests.ts`. It is read only: asking HQ for a program is a request (part 2, #2774).

| Field | What it holds |
|---|---|
| `linked` | `true` when a licence binds the caller; `false` for an account none binds (§3) |
| `source` | `hq` (read from the store) or `copy` (read from the branch's copy, §2) |
| `as_of`, `age_seconds` | On a branch, HQ's time for the copy and how old it is. Null on HQ, which reads its own store |
| `licence` | `uid`, `licence_ref`, `brand_name`, `kind`, `status` |
| `programs` | The nine programs in the canvas's order, each `{ program_key, name, group, standing, word, line, grant }`. Null with a `reason` when a branch has no copy yet, never `[]` |

- **On HQ, the licence is the one `licence_admins` binds the caller to,** joined the way `licence_requests.ts` joins it. A principal and a delegate read the same licence. One Administrator never reads another licence's grants.
- **Each program reads one standing:**

| Standing | Word | When |
|---|---|---|
| `in_force` | In force | Granted and in force by part 1's rule (D982 §4) |
| `granted` | Granted, not in force yet | Granted; `grant.waiting_on` says what it waits on |
| `paused` | Paused | HQ paused it |
| `ended` | Ended | HQ ended it |
| `not_recorded` | Not recorded | No row, and HQ grants this program. Never "Not granted" (D981 §3) |
| `switched_off` | Not offered | No row, and HQ has the program switched off in its defaults |
| `hq_only` | Runs at HQ | Product testing (D981 §3) |
| `not_offered` | Not offered yet | Investor cohort access and AI-native Venture |
| `hq_runs` | HQ runs it | Only in the unlinked answer (§3) |

- **"The defaults' word for a program with no row"** is that one flag: HQ grants it, or HQ has it switched off. The defaults' money and capacity are HQ's starting point for a grant not yet made, so they are not answered.
- **A grant carries part 1's presented shape** (`presentGrant`): its state, its terms (null where nobody set one, read "Not recorded"), `effective_end`, `in_force`, `waiting_on`, the schedule, HQ's note, `paused_at`, `ended_at` and `set_at`. Who at HQ set it (`set_by_user_id`) is HQ's record and is left out.
- **One in-force rule.** `presentGrant` decides it on HQ's grid, and the same function decides it here, from the store on HQ and from the copy on a branch.
- **A D1 error is a 503** `licence_programs_unreadable`, "Your programs could not be read. That is not the same as none.", never an empty list. The raw error is logged, not answered.

### 2. The branch's dated copy (migration 554)

- **It rides the licence copy,** as the terms schedule does (`branch_licence.terms_json`, migration 512, D797). Migration 554 adds `branch_licence.program_grants_json`. #2775 pointed at `branch_promo_ceiling` (256) as the model; the copy keeps 256's posture (HQ pushes, the branch reads local and shows the copy's age) but sits on `branch_licence` and not in a table of its own. **The reason:** that row already carries `pushed_at`, HQ's clock for when it asserted the content. And the licence push already exists:
  - every licence transition and terms save pushes;
  - a push that does not land is retried (D272);
  - a branch with no copy pulls one on its first read (D244), through the same assembler (D206).
  
  A table of its own would need its own push, retry and pull to match.
- **What HQ sends** (`programCopy` in `services/licencePrograms.ts`): `{ grants, offered }`.
  - `grants` holds the licence's grant rows, in the columns the studio reads (`COPY_COLUMNS`).
  - `offered` holds each program's "can be granted".
  - **The rows go raw, not as verdicts,** because in force turns on the day the page is read. The branch works it out from the row, its own clock, and the licence's status and renewal on the same copy.
- **`assembleLicenceRecord` adds it in its own try,** as it adds the terms. A store that cannot be read leaves the key out, so the branch keeps the programs it has rather than reading an empty set as "none granted". The rest of the copy still goes.
- **`applyLicenceCopy` writes it onto the copy this push wrote** (`WHERE pushed_at = ?`), so an older push arriving late never overwrites newer programs.
- **Three states, kept apart:**
  - SQL NULL: no push has carried programs yet. The read answers `programs: null` with "HQ has not sent this branch its programs yet."
  - `{"grants": []…}`: the licence holds no grant.
  - An unparseable copy: a 503.
  
  A branch with no `branch_licence` row at all reads "This branch holds no copy of its licence yet. Opening the licence page asks HQ for it."
- **On a branch only an admin reads it,** as `GET /mine` there. The copy is the whole deployment's and carries HQ's fees.
- **Each grant write now pushes.** Grant, change terms, pause, resume and end (`routes/admin_program_grants.ts`) call `pushLicenceToBranch` and answer `pushed`, as a terms save does. The write stands whether or not the push lands.
- **A defaults change pushes nothing.** It changes no licence's grants, only the word for a program a licence has no row for, and it reaches each branch with that licence's next push.

### 3. An account no licence binds (GR11 C)

It reads its own answer: `200`, `linked: false`, `reason` "Your account is not linked to a licence. On HQ-held accounts, HQ runs every program.", and the nine programs as `hq_runs`. It is never an empty list and never a 404. This is D981 §5's reading of decision 1, which part 4 rests on, and the owner may correct it.
