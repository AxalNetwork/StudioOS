## D7845 — Private, atomic fund shortlist saves (#7845)

Issue: #7845. Status: implemented; hosted verification pending. Owner: s39.

`POST /api/research/fund-shortlist` accepts `catalogue_ids` (1–50) and an owner-scoped `request_id` (8–64 letters, digits or hyphens). Its authentication gate matches single-fund save. `GET /api/research/fund-shortlist/requests/:requestId` reconciles the caller’s request; another owner’s request is indistinguishable from an absent one.

A sorted, distinct digest of the original ids binds the request to its selection. Retired ids resolve through the existing move ledger. Unknown ids refuse the entire selection. Runtime source withholding refuses with `source_withdrawn` (410), the original selected ids and a list citation; withheld row fields never appear. Every served kind is permitted under #7738 Q11 A; optional kinds are read from the served row, never request data.

One D1 batch inserts missing dossiers and the request record. Inserted names come from the served relation inside the batch. A final completeness constraint aborts every write if a selected record disappears or its source is withdrawn between validation and commit. The existing owner/catalogue unique index handles concurrent saves. No public facts enter private fields.

The request ledger contains only owner, request id, digest and created/already-held dossier ids. `research_funds.catalogue_uid` remains the sole saved catalogue reference. Replays read current owner-scoped dossiers, preserve initial classifications and report deleted dossiers as `no_longer_held`; they never recreate them. An unreadable outcome is explicitly unknown and never claims rollback. A response lost after commit can be reconciled with the same id.

The Worker and frontend API module ship together; #7856 owns the UI. There is no report/project permission expansion. No production data was read or changed. Rollback disables the new route; existing dossiers stay valid. The additive ledger migration must not be reverted after use.

Validation uses the fully migrated SQLite schema and mounted authenticated Hono routes, including 50-record bounds, mid-batch failure, runtime withdrawal, concurrent requests, lost responses and deletion/replay. See PR evidence for command exits and mutation results.

Mutation check: 18 mutations, 18 caught, 0 equivalent. Baseline and restored runs: 12/12 passing. Full local suite parts have not run; the PR remains a draft pending broad verification and independent review.

The new router mounts ahead of both client preparation and the main Research router. This preserves the client-preparation router’s immediate adjacency to Research and its existing route-order regression contract.
