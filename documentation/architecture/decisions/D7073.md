## D7073 — The agent gateway fails closed, and a busy model pauses nothing (#7073)

- **Status:** built 2026-11-17. Part of #7072. Closes the two model-routing blockers the agents audit of 16 November 2026 named before a paid canary (#3742).
- **Builds on:** D1528 (the `agents` AI Gateway and the platform circuit breaker), D4594 (the deterministic inference stub).

### What was wrong

1. **The gateway was optional by accident.** `agentGatewayId` answered `null` both when `AGENT_AI_GATEWAY` was unset and when it was set to something unusable. The run then reached the model on the ordinary route, outside the gateway and its spend limit.
2. **Every 429 was read as the gateway's limit.** A failed attempt with status 429 made the run `gateway_limit`, and the task loop wrote `agents:paused`. Workers AI answers 429 with code 3040 when a model is out of capacity. One busy model could pause every agent on the platform until a person cleared the key.

### The rule now

| `AGENT_AI_GATEWAY` | A sponsor's own run | A run the engine started |
|---|---|---|
| a usable id | through the gateway | through the gateway |
| unset or blank | as before, no gateway | refused 503 `gateway_required` |
| set, but not a gateway id | refused 503 `gateway_misconfigured` | refused 503 `gateway_misconfigured` |

- The check runs after the agent's own checks and before the policy quote, the tool reads and the hold. Nothing is priced, held or charged, and the run uid is still free.
- **An engine run** is one the task loop starts: `agents/loop.ts` passes `engine: true`. Nothing else sets it.
- **The inference stub needs no gateway.** Where `inferenceStubOn` is true (the preview Worker of #4594), no model is reached, so a missing gateway does not refuse. A malformed id is refused there too: a wrong setting is surfaced.
- **A sponsor's own run is unchanged while the var is unset.** It is a person's press, paid from their own tokens under a hold, and it is how agents work in production today. Making it need the gateway would switch that off until the owner creates one.

### Throttling and the breaker

- A failed attempt answered 429 **with Workers AI code 3040 or 3036** is the model's own capacity. When every 429 of a failed run is one of these, the run is 503 `model_throttled`.
- Any other failed 429 on a gatewayed run is still `gateway_limit`, and still sets the breaker.
- In the task loop, `model_throttled`, `gateway_required` and `gateway_misconfigured` end the run as `failed` with the task open again. No agent is paused and the breaker is not written.
- **They are not retried in the step.** A retried `run` step replays its hold and runs nothing (`step_lost`, D1528), so a retry could never succeed. The next run of the task is a new run with a new hold: a person's start, or the sweep within five minutes.

### What this does not do

- **It does not read the gateway's own error code.** The router records an attempt's status and a Workers AI code; it does not keep AI Gateway's 2xxx codes. So a 429 from a third-party provider behind the gateway is still read as the gateway's limit. Telling a spend-limit refusal from a rate limit needs the real response of a live gateway, which does not exist yet (0 gateways on 16 November). That is owner decision E on #7072.
- **It does not create the gateway or set the var.** The owner does both (`documentation/operations/AGENT_RUNTIME_SWITCH.md`).

### Tests

- `cloudflare-worker/test/agent_gateway_7073.test.ts`: the three gateway states, the refusal table above, the 429 classification, and the task loop (one attempt, no breaker, the agent active, the task open).
- `cloudflare-worker/test/team_agents_d1496.test.ts` (two cases at the end): the real `agentRun` refuses before any model call or hold, and a model that answers 3040 is `model_throttled` while `AiGatewayError: 2003` is `gateway_limit`.
- Ten mutations were run against these tests; each fails at least one.
