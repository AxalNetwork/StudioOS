## D7283 — Give Code Scanning sessions actionable private-evidence instructions (#7283)

Public Code Scanning trackers previously carried only an opaque alert link.
Sessions without Code Scanning read access could not identify the finding, and
one blocked report requested protected details in public issue comments. The
owner requested more useful issues while keeping findings and credentials out
of this public repository.

The tracker body now describes evidence retrieval, a private handoff contract,
the integration-specific read permission, ownership and grouped remediation,
regression checks, and scan-confirmed closure. Its read-only CLI example filters
the exact alert on the default branch into a permission-restricted temporary
file, with the scan commit when available and a distinct retrieval timestamp;
empty or failed exports do not establish a fix. An access blocker remains
until the assigned session confirms it can read the private evidence.

The pure body builder accepts only validated repository coordinates and the
alert number. It never incorporates scanner messages, rules, locations, or
other alert fields into the public body. Shell arguments are quoted literals.
New trackers receive the canonical S21 routing from D7251; actual claims and
human workflow states still stop automation. Existing issue bodies are not
silently rewritten by reconciliation.

The consolidated change includes the earlier D7251 routing implementation so
one PR covers routing and actionable context without competing tracker edits.
The focused suite covers the generated command without network access, private
file modes, failure and empty results, input rejection, payload non-disclosure,
and the existing tracker ownership and lifecycle. Mutations verify those guards
fail when broken. No alert is dismissed or closed merely by this change.
