## D1324 — Fill with Eadwyn part 1: the brand Save records provenance; a fill's hover names no model and no option key (#3485)

- **Migration:** none. **Canvas:** `Fill with Eadwyn Page.dc.html` and `Fill with Eadwyn · Boards.dc.html` (AF1–AF24, D1323). These two fixes do not wait for it.

### 1. The founder's brand Save records what Eadwyn wrote

`/build/brand` (`frontend/src/pages/BrandBuilderPage.jsx`) has "Auto-fill with AI" (`form:landing`). It drafted the page's copy into the form, and Save sent the form alone. So a headline Eadwyn wrote read, once saved, as one the founder typed. The Lab editor's Save (`PUT /landing/pages/:id`) has sent `ai_proposals` since task #199.

**The Worker half was already there.** `PUT /api/brand/landing/by-project/:pid` calls `recordCompositionFills` on `main`, with the row it wrote as the authority on which columns exist. The Save simply never sent anything for it to record.

**The page now keeps the autofill's proposal** (`frontend/src/lib/brand/proposals.js`):
- `proposalsFrom` takes the answer's `name`, `headline`, `subheadline`, `tagline` and `cta_text`. It takes nothing from a heuristic answer (`ai_generated` not true), which Eadwyn did not write.
- `keptProposals` keeps only the fields the draft still holds word for word, ignoring whitespace.
- Save sends those as `ai_proposals`, with the model that ran as `ai_model`. The model goes to the provenance row, never to the page.
- The proposals are cleared after a Save, so each is recorded once, and when the venture changes, so one venture's draft is never filed against another's page.

**A field the founder changed is theirs.** It is sent with no proposal, so the Save files no Eadwyn row for it. That is #3485's rule: "one `fill_provenance` row per kept field and none for a field the founder changed". The Lab editor keeps both values and marks the row `edited`; this page does not.

**The template's sections** (`content_json`) are one column that a per-field row cannot name, so they are not tracked here. The sheet's field registry (D1325, #3486) is where that is drawn.

### 2. A fill's hover names no model and no option key

- **"Model: …" was already gone.** `FilledMark` (`SpinoutLabMarketPage.jsx`) lost that line in D891 (`c96ed53bbf`), and the test now holds it to that: the hover names no model, with a model on the fill.
- **`fillRunLine`** (`frontend/src/lib/fillRun.js`) said `Run: fill:market · …`, the option key. It now says the control's label from the member inventories (`railOptions/founder.js`, `investor.js`, `advisor.js`, `partner.js`), via `optionLabel(page, key)`:
  - a key on more than one page is matched by its page (`explain:question` is "Explain" on Founder · Studio and "Explain this question" on the partner's Home);
  - a key no inventory lists, or a shared key on an unknown page, has no label, and the line names the run's page instead;
  - with neither, the line says "an Eadwyn run". It never says the key or a usage row's id.
