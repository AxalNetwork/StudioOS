## D5894 — Product testing runs in the generic program shell, and links out to its HQ page (#5894)

- **Status:** built 2026-11-27 (#5894). Frontend only: no migration, no new Worker route, no new client method.
- **Number:** D5894 is the issue's number (D4106).
- **Builds on:** D5313 (Perks in the shell, and the seven-step pattern), D5895 (AI-native Venture), D4873 part 4 (the generic shell, `MODULE_PATHS`), D1195 (Product testing's HQ page and its five tabs), D953 (the catalogue card's HQ-only foot).
- **Answers:** the owner's answer B on #5894 (2026-11-27). Product testing keeps `/admin/platform/product-testing` as its home, and the shell's Applications module links out to it. No redirects.
- **Canvas:** PG03a on the Programs v2 canvas (`design/incoming/Programs v2 · Boards.dc.html`). No canvas draws the HQ page itself (OF-06 draws the Partner side).

### What changed

`/admin/programs/product-testing` now opens Product testing's own `ProgramPage` in the shell. Until now it fell through to the registry-backed page.

| Tab | Address | What it draws |
| --- | --- | --- |
| Overview | `/admin/programs/product-testing` | Where it runs (the door to the HQ page, Super Admin only), then Capability modules |
| Playbook | `/how-it-runs` | the playbook editor |
| Availability & grants | `/availability` | the shell's section |
| Participation | `/participation` | for a Super Admin, R11's applications not withdrawn, and members "Not recorded" |
| Applications (module) | `/admin/platform/product-testing` | the HQ page, unchanged; a Super Admin's tab only |
| History | `/activity` | the activity read |
| Settings | `/settings` | the shell's member-access editor (Super Admin) or its value (Admin) |

- **The routes.** The six shell addresses are literal routes in `frontend/src/routes/adminProgramsProductTesting.jsx`, onto `ProgramPage` under `guard(['admin'])`. They are never `hqOnly`, because an Admin may read the registry row. The HQ page's three `App.jsx` lines (`/admin/platform/product-testing`, `/:tab`, `/programs/:uid`) are unchanged and still `hqOnly`. No route redirects.
- **The link-out.** `genericProgramModel.js` gains `MODULE_PAGES`, for a module whose screen lives outside `/admin/programs`. Its `applications` entry for `product-testing` is the HQ page's address, marked HQ-only. `moduleRows(key, program, { superAdmin })` gives a Super Admin that path. An Admin's row has no path and reads "Applications · HQ only". `PAGES['product-testing'].tabs` marks the tab `outside: true`, so `routeFor` never takes the HQ address for the shell's.
- **HQ-only stays HQ-only.** An Admin opens the shell and reads the registry's sections. An Admin does not see:
  - the Applications tab;
  - the header's "Open Product testing";
  - any link onto `/admin/platform/product-testing`;
  - any figure.

  An Admin's page makes no `/api/admin/testing` read, which the Worker answers to a Super Admin only.
- **Participation.** A Super Admin reads R11 (`GET /api/admin/testing/programmes`, through `adminTestingApi`). The page draws:
  - the applications not withdrawn, summed over every programme, with how many programmes are open or testing;
  - "Could not be read" when the read failed, or when a programme carries no count;
  - "Members taking part: Not recorded", with its reason. One member who applies to two programs is two applications, so this is never 0.

  An Admin reads "HQ only" with its reason, and no figure.
- **The catalogue card.** The card's Open now opens the shell, for an Admin too. Before, the Super Admin's Open went to `/admin/platform/product-testing/programs` and an Admin had no door. The figures stay the Super Admin's, and an Admin's foot now reads "Runs at HQ. Its campaigns and figures are for HQ only."
- **`PRODUCT_TESTING_PATH`** is the HQ page's home (`/admin/platform/product-testing`). It was its Programs tab.
- **The rail.** `railPages.js` gains `/admin/programs/product-testing` (key Programs), as its eight siblings have. The HQ page keeps its own key.

### Departures from PG03a

- **The module tab leaves the shell.** PG03a draws each module as a tab inside the shell. Under answer B, Product testing's Applications is the HQ page at its own address, so the tab opens that page and is never lit on a shell address.
- **Overview carries "Where it runs".** It names the HQ page's five tabs and links to it for a Super Admin. For an Admin it says why there is nothing to open. PG03a draws no such card.
- **Participation reads R11, not the tester pool.** The pool (D1042) counts members who joined as testers, but it is a different store from the programs' applications. Members taking part stays "Not recorded" until a read counts members across programs.
