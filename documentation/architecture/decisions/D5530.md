## D5530 — The @claude workflow authenticates by workload identity federation (#5530)

- **Status:** built; live proof waits on the owner's Console setup and one bounded run.
- **Why:** `claude-code.yml` stopped at its key check on October 24 and twice on
  October 28: the `ANTHROPIC_API_KEY` secret it required was unset, so the
  requested reviews on #2759 and #3553 never ran. The owner chose option B on
  #5530: keep the feature, and move it to workload identity federation like
  `claude-review.yml`, so no long-lived key is stored at all.
- **What changed:**
  - `claude-code.yml` passes `anthropic_federation_rule_id`,
    `anthropic_organization_id`, `anthropic_service_account_id` and
    `anthropic_workspace_id` to the pinned `claude-code-action` commit
    (`ec7c223f`, v1.0.276), which declares them and does the OIDC exchange
    itself. It reads no secret: `anthropic_api_key` is gone, because the action
    lets a static credential win over federation.
  - The values come from **its own** repository variables,
    `CLAUDE_CODE_FEDERATION_RULE_ID`, `CLAUDE_CODE_ORGANIZATION_ID`,
    `CLAUDE_CODE_SERVICE_ACCOUNT_ID` and `CLAUDE_CODE_WORKSPACE_ID`. The review's
    rule matches the `repo:…:pull_request` subject; a comment or issue run
    carries `repo:…:ref:refs/heads/main`, so that rule refuses it, and widening
    it would let every `main` workflow with `id-token: write` mint tokens. The
    new rule pins the subject to `main` and the `workflow_ref` claim to this
    file (`documentation/operations/CLAUDE_REVIEW.md` §4b).
  - The key check step is replaced by `scripts/check-claude-code-federation.mjs`,
    which validates the identifiers with the review's own `readFederation` and
    fails with a readable remediation, printing no identifier.
    `scripts/check-anthropic-key.sh` stays for Replit and local shells.
- **Guard:** `scripts/lib/claudeCodeFederation.test.mjs` fails if the workflow
  names any secret or an API-key or OAuth input, drops `id-token: write`, reads
  a federation input from another variable, or runs the action before the
  preflight. Mutation-checked against `main`'s workflow and against a
  workspace input pointed at the review's variable.
- **Unchanged:** the #4571 SC-02 caller gate (owner, member or collaborator)
  and `claude-review.yml`'s authentication.
- **Left for the owner (acceptance criteria 1 and 2 of #5530):** create the
  service account and rule of §4b, set the variables, then run one bounded,
  harmless invocation (a manual dispatch with a one-line prompt, or an
  `@claude` question on a scratch issue) and record the run on #5530. Then
  delete the unused `ANTHROPIC_API_KEY` secret if the review does not need it
  as its fallback, and revoke the key in the Console.
