## D9108 — Contracts › Closings: an Admin records and withdraws receipt evidence on a line, and adds a late line (#9108)

- **Status:** built 2026-11-27. Parent #4815 (gap g18). Canvas: `design/incoming/Closing room · Boards.dc.html` and `Closing Room Page.dc.html`, boards CP10 (receipt drawer, Admin), CP13, CP14, with the states CP16 to CP19 and dark CP21.
- **Route:** `/admin/contracts/closings/:dealId` (one closing, CP14). No new route.
- **Files:** `frontend/src/pages/closing/AdminClosing.jsx` (a Receipt control on each live line, Add a line while the closing is open, the lines as cards below the phone width), `RoomDialogs.jsx` `ReceiptDrawer` (an `admin` mode with the record actions and Withdraw), the new `EvidenceDialogs.jsx` (`RecordMercuryEvidenceDialog`, `RecordTransferDialog`, `WithdrawEvidenceDialog`, `AddLineDialog`), `roomModel.js` (the pure rules), `ClosingDialogs.jsx` (exports its `useAct` and `useLoad`).
- **Backend:** none. Every call is a mounted route: `POST /api/closings/:uid/lines`, `POST /api/closings/:uid/lines/:lineUid/evidence`, `POST /api/closings/:uid/evidence/:evidenceUid/withdraw`, `POST /api/deals/:id/transfers`, `GET /api/deals/:id/commitments`, `GET /api/admin/mercury/transactions?direction=credit`, and the closing read `GET /api/closings/:uid`.

### What is built

- **Receipt drawer, admin mode.** Each live line opens CP10 from its row. The drawer follows the line in the latest closing read, so its status and evidence change after each write with no reload; while the re-read is in flight it says "Reading the line again…". In the room (`RecordRoom.jsx`) the drawer keeps its link to Contracts › Closings, which now leads to a page that records evidence.
- **Record an Axal Mercury credit.** The credits on the four Axal entity connections, newest first. The body is always `{ kind: 'axal_mercury', source_ref: 'mercury:<uid>' }`; there is no kind picker.
- **Record a transfer.** Amount, reference and the phone box. First `POST /api/deals/:id/transfers` with `phone_verified: true` and `closing_line_uid`, then the evidence with `deal_transfer:<item.uid>`. If the second call fails, the dialog says the transfer was saved but not yet recorded on the line, and the retry repeats only the second call. Unticked, Record stays disabled and the dialog says why.
- **Withdraw.** A reason of 10 to 200 trimmed characters (the Worker's `WITHDRAW_REASON_MIN/MAX`), with a live count.
- **Add a line.** The deal's `pending` or `confirmed` commitments with no line on this closing (a withdrawn line included: the store keeps one line per commitment), or a Raise prospect by its id.
- **Refusals.** Every Worker refusal is shown as its own sentence, and the dialog stays open.
- **Not allowed.** An Admin the act table refuses `closing.evidence` sees the act's sentence in place of the controls.
