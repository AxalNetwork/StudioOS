## D6471 — A route-map canvas file writes its list cell one item per line, sorted (#6471)

- **Status:** built by S12 on #6471, 2026-11-18.
- **Keeps:** D4102 (one file per canvas row) and D4103 (the two projections are built by CI, not committed).

### The problem

A canvas file (D4102) is one table row on one line. Every branch that changes a canvas rewrites that line, so two branches that both add something to the same canvas always conflict, even when the right answer is to keep both additions.

### What was decided

**The "Backend it wires to" cell is a list, and a list is written one item per line.** When that cell is a pure list, the row keeps the slot `{backend}` in its place. The items follow the row after a blank line and a `backend:` line, one `- ` line each:

```
| Accounts | founder | `/accounts` | same | {backend} | CURRENT | Built in D1 (#1). |

backend:
- `accounts.ts` (the overview, one row per company)
- `billing.ts`
- `users.ts`
```

`scripts/lib/routeMap.mjs` joins the items back into the cell with `, `. Every reader still gets the map as one text through `readRouteMap()`.

A cell is a **pure list** when it is backticked names joined by `, `, each name followed by at most one parenthetical that ends the item. A `, ` inside backticks or parentheses does not split an item. Any other cell stays in the row exactly as written:
- prose;
- `;`-groups;
- "`a` and `b`";
- a file followed by its own routes (`` `ai.ts`: `GET /a`, `GET /b` ``);
- `—`.

**The list is sorted and has no duplicates.** Items are sorted by UTF-16 code unit, with no locale. `node scripts/build-route-map.mjs --check` fails, naming the file, the line and the item, on:
- an item that is in the list twice;
- an item out of order;
- an item not shaped `` - `name` `` with an optional `(note)`;
- a `{backend}` slot with no list;
- a conflict marker in a list;
- a pure-list backend cell still written in the row.

`scripts/convert-route-map-lists.mjs` converts a file. It is idempotent, and it converted the existing fragments: 115 of 228 canvas files. The other 113 have a backend cell that is not a pure list.

**Only the backend cell.** The issue named three kinds of list: routes, route files and source decisions.
- **Source decisions** have no cell. They sit inside the Notes prose, and the Notes cell stays as it is.
- **Route files** are the backend cell.
- **Routes** sit in "Proposed route" and "Live route today". Those cells are not lists in the sense used here. `PROFILE_ROUTING.md` prints their routes in the order written, and the first route that matches a sidebar row decides where the canvas is placed. Sorting them would change both projections and could move a canvas to a different nav section.

Nothing reads the backend cell's order. So moving and sorting that cell leaves both projections byte-identical.

### What the conversion changed, and what it did not

- **`PROFILE_ROUTING.md` and `PAGE_INVENTORY.md` are byte-identical** before and after the conversion. The sha256 values are in the PR. `route_map_lists_d6471` also builds both documents with every list reversed and gets the same bytes.
- **The combined map (`ROUTE_MAP.combined.md`, a reading copy) changed in 73 rows.** Their backend items are now in sorted order. Every row keeps the same set of items, and no other cell changed. The other 42 converted rows were already sorted.
- No route, file or row disappeared.

### The limit

- **Two branches adding an item between the same two neighbours still conflict.** Git cannot order two insertions into one gap. The fix is to keep both lines, sorted, and the check then confirms the order. Additions at different places in the list merge cleanly with git's default merge and no merge attributes (tested).
- **This does not stop most row conflicts.** Of the 112 canvas-row edits on main from 2026-11-04 to 2026-11-18, 111 changed the Notes cell. Only 6 changed the backend cell, and those 6 also changed Notes. Notes is prose and stays on the row's line (out of scope for #6471). So two branches that both write about the same canvas still meet on line 1. Moving Notes, for example to a sentence per line under the row, is the change that would remove those conflicts. It needs its own decision.

### Tests

`frontend/test/route_map_lists_d6471.test.mjs`:
- the converter sorts, drops duplicates and leaves non-list cells alone;
- the joiner restores the cell;
- a duplicate item, an out-of-order item, an inline list, an empty or malformed list and a conflict marker are refused;
- the projections do not read list order;
- two fixture branches that each add a different route file to the same canvas merge cleanly in a temp repo with no attributes, while the same two additions in the one-line form conflict;
- adjacent insertions still conflict.

Mutation-checked: dropping the duplicate check, the order check, the inline refusal, the sort or the de-duplication in the converter, or the `, ` join each fails a test. The D4102 fixtures now write `—` as the backend cell.
