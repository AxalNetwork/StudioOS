### 1. The catalogue read carries the checks, the keys' modes, "shows on" and each price's allowance

`GET /api/admin/catalog/products` keeps its gate (`requireAdmin`; part 1 decides the gate for the whole family) and its fields, and adds:

- **`keys`:** `{ account_mode, publishable_mode }`.
  - `account_mode` is the secret key's mode (`stripeMode`).
  - `publishable_mode` is the publishable key's (`publishableKeyMode`, read from KV, then the environment): `live`, `test`, `unknown` or null.
  - **No key is ever returned**, secret or publishable, only modes.
- **`checks`:** each check is `{ code, severity, product_id, price_id, message }`. The message is a sentence an admin can act on. Only active products and prices are judged, because an archived one reaches no member.

| Code | Severity | When |
|---|---|---|
| `plan_clash` | blocker | Two or more active products make the same plan (the same `planOf` licence key, e.g. `founder:growth`). Checkout (`priceForPlanMetadata`) and `/pricing` take whichever they read first. Two founder tiers are not a clash. |
| `plan_no_yearly` | warning | A plan with no active yearly price charged every one year: `/pricing` offers it monthly only, and its yearly checkout is refused. |
| `subscription_no_card` | warning | An active subscription whose metadata names no plan: no `/pricing` card and no plan checkout. |
| `price_interval_count` | blocker | An active plan price charged every N > 1 months or years. The checkout's price pick matches the interval only, so it could sell this one; `/pricing` ignores it. |
| `plan_price_short_interval` | blocker | A weekly or daily plan price. It gives no allowance and `/pricing` ignores it. |
| `plan_price_not_usd` | warning | A plan price in another currency. It gives no allowance and is never added to a USD figure. |
| `secret_key_missing` | blocker | No secret key is set. |
| `publishable_key_missing` | blocker | No publishable key is set. |
| `publishable_key_unknown` | blocker | The publishable key's prefix is neither `pk_live_` nor `pk_test_`. |
| `key_mode_mismatch` | blocker | The publishable key's mode differs from the account's. |

- **Per product:**
  - **`plan`:** `{ key, family, label, yearly_saving_percent }`, or null for a product that makes no plan. The saving is D816's `intervalPrices`, computed and never stored.
  - **`shows_on`:** the surfaces the product reaches, each `{ key, path, detail }`, read off the same rules the pages use (§2).
- **Per price:**
  - **`allowance_microusd`:** the monthly AI allowance the price gives (D783): 25% of a USD monthly price, a yearly price's ÷ 12, rounded down.
  - **`allowance_reason`:** null when counted, else `not_a_plan`, `archived`, `not_usd` or `not_monthly_or_yearly`.

A failed catalogue read, or a failed read of the token-pack store, is a 502 with a sentence. It is never an empty list, and without the pack store a pack would be called an add-on.

### 2. Shows on

| Product | Surfaces |
|---|---|
| A plan (`planOf` names one) | `pricing` (`/pricing`, its plan card), when it has an active monthly or yearly price charged every one interval; and `bundles` (`/pricing/products`, Profile bundles) |
| A token pack (its product is in `ai_token_packs`, or its kind is `token_pack`) | `packs` (`/pricing`, while the pack is on sale) only |
| Any other active product | `addons` (`/pricing/products`), with its audience categories, or "under All only" when it has none |
| An incorporation product with a `jurisdiction_id` | also `incorporate` (`/incorporate`) |
| An à la carte product | also `incorporate` (`/incorporate`) |
| An archived product | nothing |

### 3. Members per plan: `GET /api/admin/catalog/members` (Super Admin)

The read uses `member_subscription_amounts`, the charges the subscription webhook records. Canceled rows are not members.

- **`by_price`:** `{ price_id, product_id, active, other }`.
  - `active` is Stripe's paid status.
  - `other` counts the other live statuses: trialing, past_due, unpaid and incomplete.
- **`by_plan`:** `{ family, interval, interval_count, active, other, without_price }`, per family and interval.
- **`without_price_total`:** the rows with no price.

**Rows recorded before migration 572 carry no price.** They count under their family as `without_price`, and never as any one price. Two plans in one family, such as the two founder tiers, are told apart only by price.

A failed read is a 502 that says the failure is not a claim of none.

### 4. Migration 572 and the webhook

- **The migration:** migration 572 adds `member_subscription_amounts.price_id`, plus an index on `(price_id, status)`.
- **What is stored:** `chargeOf` now returns the first charged item's Stripe price id, or null. `recordSubscriptionAmount` stores it, on `customer.subscription.created` and `updated`.
- **Updates without a price id** keep the one recorded (`COALESCE`).
- **No backfill:** a row gains its price at Stripe's next update for it.

### 5. Change a price: `POST /api/admin/catalog/prices/:priceId/change`

**The body:** `{ unit_amount, reason, idempotency_key, nickname? }`.

**Why one route:** Stripe prices cannot be edited, so a change is a new price plus the old one archived. One route does both, so a half-done change is never left behind silently. The steps:
1. Create the new price on the same product, with the old one's currency, type, interval and count, and its nickname unless a new one is given.
2. The create carries `Idempotency-Key: price-change-<key>`, so a retried press makes one price.
3. Archive the old price.
4. If the archive fails, archive the new price again. The old price stays the only live one, and the route answers 502 with that sentence.
5. If that fails too, the 502 names both price ids and says both are live, and what to do.

Each outcome is audited in `admin_audit_log`, with the product, both price ids, the currency, the interval, both amounts and the reason:
- `catalog_price_change` (done);
- `catalog_price_change_rolled_back`;
- `catalog_price_change_incomplete`.

**Guards**, in order:

| Order | Guard | Refusal |
|---|---|---|
| 1 | `requireSuperAdminWriteBar`: TOTP, a recent step-up, Super Admin | it changes what members pay |
| 2 | Stripe configured | 503 |
| 3 | A Stripe price id | 400 |
| 4 | Not a token pack | 409, managed on HQ |
| 5 | `unit_amount` a whole number above zero | 400 |
| 6 | A reason of at least ten characters | 400 |
| 7 | A usable idempotency key | 400 |
| 8 | The price is in the catalogue | 404 |
| 9 | The price is live | 409 `price_archived` |
| 10 | Something changes | 409 `price_unchanged` |

Every refusal is a sentence (`refuse`), and no refused change reaches Stripe.
