## D5829 — Typeform answers require founder review before evidence (#5829)

The existing importer stores only selected, qualifying answers. This continuation
adds the private review API at `/api/typeform/validate` and extends the existing
Validate demand writer and hypothesis evidence reader. It does not add a screen.

An evidence mapping records the stable question identity and semantic rule,
version, venture, hypothesis, optional experiment, direction and optional
strength. The experiment must belong to that hypothesis in the same venture.
Changing a target appends a version. A pending review of an older version cannot
confirm against the replacement. The existing evidence contract links the signal
to the experiment's parent hypothesis; the review retains the experiment ID.

`POST /reviews/prepare` creates at most 100 private proposals per call. A proposal's
signal starts `to_confirm`. Its source key is generated internally from the form,
venture, response and question IDs. An interrupted preparation reuses that signal;
the unique source key prevents duplicate proposals and survives dismissal and
unlinking. `GET /reviews` never writes and reports completed responses, matching
answers and confirmed signals separately. Failed reads propagate an unavailable
response; they never fabricate a zero count.
`GET /form-counts` also breaks those figures down by form, so changing the bound
form cannot conflate its responses with a previous form's history. Review-list
totals explicitly cover the venture/connection scope.

`POST /reviews/:id/confirm` confirms the signal and writes the existing evidence
link and actor receipts in one D1 batch. A database guard rechecks the source,
venture, mapping version and pending decision inside that batch. A withdrawal
between preflight and commit aborts confirmation. Retrying a completed decision
does not create another signal or link. No hypothesis score, interview or
experiment result is inferred from a survey.

Dismiss and unlink remove derived links/signals while preserving a source
tombstone. Importer answer/response withdrawal, provider deletion and semantic
question-mapping replacement retract derived evidence in the source deletion's
batch. Future imports cannot recreate the material. Source signatures are written
when an answer is imported. Legacy unsigned answers are private source records,
never retrospectively attested as matching today's rule.

Question text is private source material, available only through the selected
connection owner's venture write access, with support sessions refused and the
connection's company enablement checked. Explicit `keep_text` is required for free
text retention. Review never copies text to a signal's note or identity, a claim,
activity receipt or public evidence label. Respondent publication permission is
`not_recorded`, and quote audience remains `private`: this API provides no
external quotation publication capability or implied respondent permission.

The schema change is additive. Worker code does not bootstrap tables at runtime.
The source-key column is used only by the Typeform writer path, preserving manual
and existing connector callers, including smaller migrated test fixtures. The
shared writer's segment functions are untouched under the owner's narrow handoff
alongside #7692. No unpublished S18 commit is claimed as recovered or verified.

Validation results will be recorded after current-tree tests, source mutations,
schema guards and the owner's full `test:drift` zero-exit publication gate.
