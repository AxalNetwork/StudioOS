## D612 — Audit logging for KYC record access, queue views, and partner profiles

**Issue:** #1312 · S16, found by #1165's audit (area 7, `kycAdminGet` and `adminGetProfile`). **No migration.**

### What was true on `main`

Opening an ID document file (`GET /api/kyc/admin/:userId/document`) wrote an audit row (`kyc_document_access`) to `activity_logs`. However:
- `GET /api/kyc/admin/:userId` returned the entire sensitive KYC record (legal names, date of birth, nationality, addresses, ID document numbers, and phone numbers) completely unlogged.
- The KYC admin queue (`GET /api/kyc/admin/queue`) returned full `kyc_data` blobs for every listed user solely so the review modal could read them, also unlogged.
- `GET /api/profiling/admin/:email` returned sensitive partner profiling data (EIN, onboarding transcripts) without any audit logging.

### What was decided

1. **Audit logging on read:**
   - `GET /api/kyc/admin/:userId` writes a `kyc_record_access` row to `activity_logs` with the actor hashed (`hashEmail(adminUser.email)`), `details: JSON.stringify({ member_id })`, and zero personal identity field values.
   - `GET /api/kyc/admin/queue` writes a single `kyc_queue_access` row to `activity_logs` per queue read with the actor hashed and `details: JSON.stringify({ count })`.
   - `GET /api/profiling/admin/:email` writes a `partner_profile_access` row to `activity_logs` with the actor hashed and `details: JSON.stringify({ member_id })`, omitting EIN and transcript contents.
   - 404 responses across all three endpoints write nothing to `activity_logs`.

2. **Trimming the KYC queue:**
   - The queue endpoint `GET /api/kyc/admin/queue` strips `kyc_data` from its JSON projection. Queue listing rows now contain only summary status, timestamps, and provider metadata needed to display table rows.
   - In `frontend/src/pages/AdminPage.jsx`, clicking "Review" on a submission row now calls `api.kycAdminGet(k.id)` to load the full KYC record and document metadata on demand. This ensures the review action is properly logged as `kyc_record_access` and activates the previously uncalled `kycAdminGet` client method identified in #1165.

### Verified

- `cloudflare-worker/test/identity_access_audit_d612.test.ts` asserts:
  - Queue access writes one `kyc_queue_access` log with `{ count }` and trims `kyc_data`.
  - Record access writes one `kyc_record_access` log with `{ member_id }` and omits personal values.
  - Record 404 writes no log.
  - Profile access writes one `partner_profile_access` log with `{ member_id }` and omits EIN and transcript text.
  - Profile 404 writes no log.
- `node scripts/check-decision-ids.mjs` passes.
