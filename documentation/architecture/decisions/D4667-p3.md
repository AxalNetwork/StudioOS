### What is decided

1. **One document, chosen by the run.** A run reads a document's text only when it selects one, as `data_room_file:<uid>`:
   - manual: the run's `record` (it is also the proposal's record);
   - scheduled: the session's target, kind `document` (now a checked target kind);
   - readiness: `GET /api/teams/agents/:uid/skills/:slug/readiness?document=data_room_file:<uid>`.

   With none selected, `data_room.index` answers the room's index: each live file's reference, name, current version and whether its current version's text is on record. It carries no text. A skill that needs the text is then `not_ready`, reason `not_selected`.
2. **The room's own rule.** The sponsor reads the room whole only as `roomProject` admits a person: its owner, through the tenancy scope, or an accepted co-founder. Anyone else is `withheld`, with none of the room. That includes an admin, who reads a room only through an audited support read, and an investor, who reads through a grant's tier, folder and NDA gates. Trash is never read. A session may target only a live file of a room in its scope that its sponsor reads by this rule.
3. **The shape.** A selected document answers:
   - `file_uid`, `version` (the current one: the kept versions are 1..n, so it is n + 1), `updated_at` and `text_indexed_at`;
   - `version_digest`, a SHA-256 over the file uid, the current object's key and the whole text on record;
   - its passages, in order, each `data_room_passage:<uid>:<seq>`.

   A read carries whole passages up to 4,800 characters. `coverage` counts every passage. `page.next` continues after the last one returned, through `page.after`. A continuation from another document, or one never given, is refused. A later page is never `complete`.
4. **Only the current version's text.** Text read before the file was last replaced is never supplied. Each state below gives the input that status:

   | State | Meaning | Input status |
   |---|---|---|
   | `not_current` | replaced after its text was read | `missing` |
   | `not_read` | its text was never read | `missing` |
   | `not_found` | not in this room, or in Trash | `missing` |
   | `no_text` | it holds no text the reader can read | `unreadable` |
   | `failed` | reading it to text failed | `unreadable` |

   Each carries its reason, and the 422 `skill_not_ready` message says it in words.
5. **Complete, bounded, unreadable.** Every passage in one read is `available`. Fewer is `partial`, and the skill is `conditional`. Its limit says how many passages were supplied and how many were left out, so the brief states it.
6. **Two fixed SQL fragments.** `data_room.index` puts two `${…}` in its query text, both recorded in `scripts/baselines/sql-prepare/services%2Fagents%2Freads.ts.json`. Every value is still bound.
   - `liveFiles`: one of five fixed strings, the Trash clause every room read carries.
   - `projectOwnerScope(...).sql`: the tenancy module's fixed owner clause, whose founder id is bound.
7. **Unchanged.** The gate (D4667-p2) is the same check on both paths. `granted` and `bound` bind this read as they bind any other. The manual run carries the passages it judged as data. Native readers only.
