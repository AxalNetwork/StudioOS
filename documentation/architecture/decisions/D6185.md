## D6185 — Search and page admitted investor room files (#6185)

The new SharedRoomFiles component reuses DataRoomSearch with shared search
and a whitelist of UIDs from the current listing. Hits are filtered before
rendering names/snippets or enabling Open. Only a listed file can reach the
existing download callback. No withheld name or raw-file metadata can add a
row; withheld files remain a count. Search-index unavailability and failed
searches remain distinct, and both leave the name filter working.

The listing query uses raw size/date solely to sort already-admitted files.
Added defaults to newest, Name to alphabetical and Size to largest, with
stable UID ties and unknown metadata last. Zero-byte files remain measured.
Pages hold 25 files and show the exact range. Folder changes retain sort and
requested page; small folders clamp the displayed page while returning to
the larger folder restores the requested page. Name filtering resets page.
Rows stack on phones, long names/snippets wrap, and controls are at least
44px high. No Type column is added: the checked issue assigns it to #5907.

Only optional props change the shared search component; existing founder
callers keep their behavior. The new component has no access-state or NDA
logic and uses the current admitted listing and logged download callback.
It performs no indexing and exposes no founder-only control.

The checked issue makes #5907 and #5903 prerequisites, both still open.
Open #6338 also owns DealWorkTabs.jsx/dealWorkModel.js. Those files remain
untouched: the new independent component/query and mounted regressions are
prepared, while a replacement of only the listing region awaits an explicit
handoff/reconciliation or landing. The current roomListing contract is reused
without editing its owned file. This PR is Part of #6185; no live Documents
entrypoint is claimed yet.

Tests cover sort/page/folder persistence, zero versus unknown metadata,
whitelist enforcement against extra search hits, exact shared-search calls,
index-off versus failure and working name filtering. No API, permission,
Worker, production data access, deployment or merge is introduced.
