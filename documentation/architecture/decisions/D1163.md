### 1. The departure from D714: drawn here, not linked

D714 opened `/funds/calls` and `/funds/ledger` for the chosen fund ("reuse, never fork"). The canvas draws the call ledger, its dialogs and the distribution notices inside the console, so this decision draws them here. It reuses the Worker's reads and acts, not the investor page's components: the same `GET /api/funds/:id/capital-calls`, `POST .../capital-calls/preview`, `POST .../capital-call`, `POST .../lines/:id/receipts`, and the D714 distribution routes. The console no longer links to `/funds/calls` or `/funds/ledger`. Those pages are unchanged.

`fund-admin-panel-calls`, `fund-admin-panel-distributions` and both tabs' addresses (`/admin/fund-admin/calls`, `/distributions`, with `?fund=`) are kept.

### 2. FND7: Capital calls

- **Six tiles:** Committed, Called, Received (receipts plus lines marked paid before receipts existed, which the note names), Outstanding, Overdue lines (with the oldest's days) and Next due. Without the ledger each figure is "Not recorded", never $0.00.
- **Outstanding by age:** the owing lines summed in cents into six bands: not yet due, no due date recorded, 1–30, 31–60, 61–90 and over 90 days overdue. A line with no due date is never "not yet due". The note names the band holding most of it. View as table draws the same figures.
- **The latest call,** whole: its amount, due date, purpose, the residual's line, who issued it, and each LP's line (owed, received, outstanding, state, age), with Record receipt (any Admin) and Open LP (`/admin/fund-admin/lps/:id?fund=`). Earlier calls are one line each, opened in place.
- **The proofs of funds** (D752) moved with the tab, still read only on Show.
- **People are named.** A line, a preview row and a distribution row show the LP's name; with none recorded they read "Name not recorded", never an email or a number.

### 3. FND8: New capital call, Record receipt, Call notices

Each is an in-page `Lightbox`.

- **New capital call.** An amount in dollars and a due date. **The due date starts empty and is never filled in:** without one the dialog says "Choose a due date. It is never filled in for you." and nothing is read. Preview draws each LP's share, its percentage of commitments, a flag for an LP with no approved identity check (flagged, not removed), the total, and the cents left over. Issue is the Super Admin's (`capital_call.issue` through `FundActControl`); an Admin reads "A Super Admin issues capital calls." in its place. Issue sends exactly the amount, note and due date on screen. The step-up is the request helper's: a 403 `step_up_required` opens `StepUpModal` and the call retries.
- **The issued call against its preview.** After Issue the ledger is read again, and `figuresMatch` checks the new call against what the preview showed: the same total, the same LPs, the same cents per LP. The console says "Call N is issued, with the figures its preview showed.", or names each LP whose line differs.
- **Record receipt.** The full outstanding or another amount, the date it arrived (not after today) and a reference. It records money already received; it moves no money.
- **Call notices.** Letter or A4. Preview reads every line's notice and one digest (`POST /api/fund-notices/calls/:callUid/preview`); Issue sends that digest and the page size (`.../issue`), all or none. Issue is the Super Admin's (`fund_notice.issue`); an Admin reads **"A Super Admin issues fund notices."**
- **L6.** A line whose notice cannot issue reads "This notice can't issue: …" with the Worker's reason, and Issue is replaced by "N notices can't issue, so none is issued until each can."

### 4. FND9: Distributions

- **The proceeds card** and **Where every cent goes**: proceeds, basis returned, profit, carry withheld (and whether the rate is the fund's or the job's 20% default; a missing rate says so), what goes to the LPs, and the cents no line received.
- **The per-LP preview, by name** (the preview route's `lp_name`): each LP's share and amount, and a total that is the sum of the lines. If the lines and the unallocated cents do not add up to what goes to the LPs, it says not to execute.
- **Execute** is the Super Admin's, with its foot ("Execute asks for your authenticator code…"); an Admin reads "A Super Admin executes distributions."
- **The distributions table:** Mark paid opens a dialog first ("This marks this payment as made. It records; it moves no money."). A paid line has Notice.
- **A distribution notice:** a tax character the admin chooses (never defaulted) and a page size. Preview draws the Worker's HTML in an `iframe` with `sandbox=""`, so it runs no script. Issue sends the previewed `figures_sha256`. Issue is the Super Admin's; an Admin reads "A Super Admin issues fund notices." A refusal is L6, and no Issue is drawn.
- **Cumulative distributions:** each month's paid lines added to the months before; pending lines are not counted, and the note says how many wait. View as table draws the same figures.

### 6. UNVERIFIED

- **Not looked at in a browser.** The tabs are built from `parts.jsx`, the theme tokens and the shared `Table` (which stacks below `sm`), with dark-mode classes beside every colour. No one has yet compared desktop, phone, light and dark against FND7–FND9.
- **The step-up was not run end to end.** Issue and Execute rely on the request helper's global `step_up_required` handling. The tests stub the APIs and do not exercise it.
- **A call notice is previewed as figures, not as the page.** The call preview route returns each line's figures and refusal, not its HTML, so the dialog lists each LP's notice amount. A distribution notice shows the rendered page.
