## D5035 — HQ Support reads recent decisions and their latest delivery outcomes from HQ (#5035)

A Super Admin returning to Queue or Delivery needs to see the decision that HQ recorded and whether the subsidiary acknowledged it. Both Support reads (`GET /api/admin/hq-support/local` and the full `GET /api/admin/hq-support`) now return `recent_decisions` from HQ’s D1 database. A slow or unavailable subsidiary cannot hold up the local read. A history read error has its own unavailable state. A successful empty read means no decisions were found.

### What the operator sees

HQ shows the latest 25 answered or declined escalations with a stored answer. Each escalation appears once. Its subject, branch, answer and decision time come from `hq_escalations` (migration 259). Migration 288 added the operator’s stored display name. The read orders decisions by `answered_at`, newest first, and uses `uid` to break ties. The query uses the partial index from `202611122048_5035_recent_escalation_decisions.sql` to stop after 25 matching rows. Until that migration is applied, the page reports Recent decisions as unreadable while the other Support reads remain available. A resend leaves the decision text, actor, time and place in this window intact.

Migration 288 (D243) added the last branch delivery result to the escalation. The page displays a stored `push_ok` of 1 as delivered and 0 as unsuccessful. New writes require an explicit positive acknowledgement to store 1. Older rows contain only the outcome the Worker wrote at the time. A NULL leaves receipt unknown, including for rows that predate delivery recording. `push_reason` and `push_at` describe the latest recorded attempt when present. HQ-tier requests use a local bell notice (D799). Their notification path provides no evidence of branch receipt.

**Send again** uses `POST /api/admin/escalations/:uid/resend` to send the answer already stored at HQ. The next recorded result replaces the previous result on that escalation. An ambiguous response preserves uncertainty. The database stores the current decision and its most recent delivery outcome. It has no ledger of every transmission or earlier versions of an answer.

### Ticket policy

Policy edits the P1/P2/P3 ticket hours through `PUT /api/admin/hq-support/sla-tiers`. A changed policy receives a version and queues distribution to deployed subsidiaries (D5032). The page reports coverage only for the version it is displaying. It can show a recorded HQ save while branch coverage is still unknown.
