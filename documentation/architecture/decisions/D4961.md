## D4961 — One Save for the logo and General, and a guard on leaving with unsaved changes (#4961)

#4961 (slot S29, taken at the owner's request, P1). Save used to upload the logo, then PATCH the fields. A failure between the two left the logo committed and the form saying "not saved", and a retry could repeat or contradict it. Moving to Team, Legal or Projects, any in-app link, and Back or Forward dropped unsaved edits without a word, because the app mounts a declarative `<BrowserRouter>` and `useBlocker` needs a data router.

### Decision

1. **One request, one commit.** `POST /company/:uid/settings` (multipart: `fields` JSON, `logo` file or `logo_action=remove`) validates everything first (the D4962 contract, the D4960 write gate, the logo's type and size), puts the new object in R2, then writes fields, `logo_url` and the events in ONE D1 batch. If the batch fails the new object is deleted; the previous object is dropped only after the commit. `PATCH /company/:uid` shares the same planner.
2. **A failed or unanswered save is reconciled, not guessed.** After any non-4xx failure the form re-reads the company and compares it to the intent (`reconcile`): all, none or some. The message says which. "Not saved" is said only when a 4xx or a re-read shows nothing committed. Try again checks first, then saves only what is missing. Discard re-reads the server state.
3. **Leaving asks first, by every door** (`frontend/src/lib/leaveGuard.js`): `beforeunload`; the router navigator's `push`, `replace` and `go`; and Back/Forward through a `popstate` gate. A real Chromium runs window listeners in the order they were added, so the gate is installed at boot in `main.jsx`, before the router mounts. A guard armed later cannot get ahead of the router (the first version passed every unit test and did not block Back in a browser). Declining walks the history back by the `idx` distance; accepting re-dispatches the event once.
4. The Logo URL box is gone from Settings: a logo changes only by upload or removal (D4962).

### Verified

Worker: `company_settings_save_4961.test.ts` (atomic commit, R2 cleanup on batch failure, previous object kept until commit, validation before any write). Frontend: `leave_guard_4961.test.mjs` (every branch on a fake window), `company_save_model_4961.test.mjs`, and the same controller driven through a real Chromium history.
