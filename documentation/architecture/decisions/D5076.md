## D5076 — Build modules draw by how much is recorded: one first action, then rows, then list controls (#5076)

- **Number:** D5076 is this issue's number (D4106). No migration, no Worker change.
- **Files:** `frontend/src/pages/cycles/progressiveList.js` (new), `frontend/src/pages/cycles/CycleModulePage.jsx`,
  `frontend/src/pages/cycles/PhoneModulePage.jsx`, `frontend/test/build_progressive_zero_states_d5076.test.mjs`.
- **Canvas:** Build V2 (M20261109 · Build V2, owner-approved 2026-11-10 on #4846), BD18 A/B/C and BD24 A.

### 1. The problem

The 8 November authenticated audit found every empty Build module drawing a mature page: Add twice (the
card's "Add feature ›" and the table's Add), search, filters, sort, an empty table header, "0 of 0", the
header's Connect a tool and every connector part, before a single record existed.

### 2. The rule

Three stages, from the module's records read (`listStage`):

| Stage | When | What draws |
|---|---|---|
| zero | the read's own `total` is 0 and no search or filter is in force | one guided first action: a heading, the founder outcome, one dominant button (the module's existing Add, relabelled "Add your first …"). No search, filters, sort, column header, count or pages. The card's `next` and the header's action give way; connector and Eadwyn parts move into a closed "Bring it in from your tools" region below. Another form's Add and Build in Lovable stay, as subordinate links. |
| few | 1 to 9 records | the rows, each form's Add once, a plain count ("3 features"). No search, filters or sort. The card's `next`, when it is the table's own Add, is not drawn a second time. |
| many | 10 records or more (BD18 C), or any search or filter in force | the full D661 table, unchanged. |

- **Honesty.** Zero is only a measured zero. A read with no `total` and no rows keeps the full table, which
  reads "Not recorded"; an unreadable read stays Unreadable with Retry. Neither is ever drawn as a first-run
  state.
- **A search never loses its box.** An empty search result is `many`, so it can be cleared.
- **Pages are never hidden.** Paging stays whenever the read has more than one page, at any stage.
- **Writes unchanged.** The dominant action is the module's existing Add (`FORMS.build`) with a new label;
  its href, state and dialog are the same. Operating systems' is "Connect your first system" (its form is
  Connect a system).
- **Scope.** Only the six Build modules are listed in `PROGRESSIVE`; the other 20 modules keep D661's table.
- **Phone.** The same stages: at zero, "One next thing" carries the heading, the outcome and the one CTA, with
  no controls and no empty list; at few, no controls.
