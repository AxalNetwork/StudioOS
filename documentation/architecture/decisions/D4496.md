## D4496 — Distribution cross-tab states and responsive layouts (#4496)

The DS series is primary and MK fills its gaps. Distribution uses the existing app navigation, Ask panel, venture permissions and campaign store. This change adds no provider actions, sending, API, billing policy or production-data operation.

The pure state model consumes verified writer permission and the existing AI budget response. AI switched off, paused, busy or out of tokens disables Ask independently from manual work. Unknown permission disables writes; unknown budget never implies zero tokens. A read-only Admin gets the founder-record explanation; other verified readers get the existing campaign reader sentence. An HQ reason and expiry are shown only when supplied by the actual access flow, through the existing AccessBanner. No reason or countdown is invented.

Provider failures use an allowlisted provider name and fixed copy, never an exception or upstream message. The ad-account suspension sample is absent because no live ad-account reader exists. Budget-reached requires a recorded paused campaign with at least 100% usage, and missing WhatsApp consent requires an explicit recorded `none` basis. A plan placeholder appears only for a caller-supplied real required Growth/Studio tier checked by sidebarConfig.hasTier; this task adds no tier restriction to an otherwise ungated route.

At 390px the Overview draws Leads, Replies, Cost per lead and Spend vs budget in two columns. At 768px it draws Leads, Cost per lead and Spend vs budget. Desktop retains its existing six readings. Null readings remain Not recorded and failed reads remain Unreadable. The existing usePhoneWidth hook supplies reactive breakpoints. Shared DS tokens carry the dark theme; phone and tablet controls have at least 44px targets, and the phone primary has 48px height.

The shell derives its venture from the existing project_id search and its caller from Auth, reads the existing form-options permission and AI budget, and supplies the same state to its Ask and manual actions. The shared Ask accepts an optional explicit accessible name for the paused explanation; other callers keep their existing names. Campaign list and Overview empty-state write actions follow the same recorded permission.

The shell, state components and Overview shipped first (#4521). Calendar, Inbox, Ads, Prospects and Channels already gate their own writes on the server's `can_write` and sit under the shell's notes, so they take the cross-tab states without further edits. Calendar opens in Week view at 1023px and below.

### The wizard (2026-11-06, after #4519 merged)

`NewCampaignPage` renders outside the shell, so it builds the same model itself: `distributionStates` from the AI budget read, the caller's role and a recorded `can_write`. The campaign selectors (`campaign=1`) are writer-only, and before this change a reader's 403 surfaced as "Unreadable: the campaign choices could not be read." When the selectors are refused, the page now reads the venture permission (`campaign=permission`, the read the shell uses):

- `can_write: false` → the reader page: the advisor note, or for an admin the founder-record reason and "Eadwyn is off while you read a founder's record". No form is drawn.
- That read fails as well → "Couldn't be read. This is not a claim that there are none." with Try again, which reads both again. No exception or server message is shown.
- Writable → the wizard, with the state notes under its header. AI paused, off or out of tokens turns off the field Ask and the assets Ask, never manual entry. A blocked state disables Save draft and Continue, with its reason beside Continue.

On a 390px phone the wizard fills the screen. It has a "‹ Campaigns" Back link, and the Back / Continue footer is sticky, 48px high, and keeps its disabled reason in view. Dark tokens cover the footer.

### Worker refusals

The writes behind these states are refused by the Worker as well:

- An advisor is refused on create, edit, delete, channel budgets, item links and creatives (`grow_campaigns_d4447`, `grow_campaigns_4483`) and on the campaign selectors.
- The advisor's permission read answers `can_write: false` (`campaign_options_4487`).

An admin is a writer on campaigns today (`projectOwned`), so "read-only admin" appears only when the permission read records `can_write: false`. The page adds no admin write policy.

The design's company switcher and fixed Founder nav are not built (#3704).
