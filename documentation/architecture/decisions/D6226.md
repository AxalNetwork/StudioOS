## D6226 — Positions reads return the Worker's own date, so mark age is never measured by the browser (#6226)

**Why.** `GET /api/positions/analytics` answers `as_of: null` when no `?as_of=` is asked, and neither `GET /api/positions` nor `GET /api/positions/:uid` carried a date. So the Portfolio v2 Positions board borrowed `kpi-compliance`'s `as_of` to age a mark (D4817 part 2), and its stale count read Unreadable whenever the reporting read failed. The company workspace reads no reporting-population read at all, so D4817 part 6 left the Stale chip off the company's latest FMV.

**What changed.**
- **Worker** (`cloudflare-worker/src/routes/positions.ts`, the three GET handlers only): the list read, the analytics read and the per-company read each add `today`, the Worker's UTC date (`YYYY-MM-DD`, from `todayIso()` in `_t13t14t15_helpers.ts`, the helper the route already imports from). `today` is the Worker's date whatever `?as_of=` was asked. `as_of` keeps its meaning: null when no date was asked, the asked date otherwise. No other field changes, so every existing consumer reads what it read before.
- **`markReference(asOf, compliance, positions)`** (`portfolioModel.js`) now prefers, in order: the chosen as-of date; the positions read's own `today` (`workerToday`); then `kpi-compliance`'s `as_of`, kept only for a positions read without `today` (an older Worker). It still never uses the browser clock. Positions passes its positions read.
- **The company header** (`keyFactsOf` in `companyModel.js`): the Latest FMV fact carries a `chip` ("Stale · 7 months old") when the mark is older than two quarters at the positions read's `today`. `FinancialMetric` draws an optional `metric.chip`; no other metric sets one. Without `today` no chip is drawn and the date alone is shown, as before.
- **Supersedes** D4817 part 6's departure "No Stale chip on the latest FMV", and in part D4817 part 2's rule that a failed reporting read leaves the stale count Unreadable. Each of those decisions carries a one-line note pointing here.

**Not changed.** `kpi-compliance` keeps its own `as_of`. The mark-history Sheet and the company's Financials tab are unchanged: the Sheet still measures at the Positions page's reference (now the positions read's `today`), and Financials draws no age.

**Verified.**
- `cloudflare-worker/test/positions_today_d6226.test.ts` mounts the router over the real schema with the clock fixed at 2026-11-14T23:59:30Z: each read carries `today: '2026-11-14'`; analytics keeps `as_of: null` without a date and the asked date with one, while `today` stays the Worker's.
- `frontend/test/portfolio_mark_today_d6226.test.mjs` mounts Positions with `kpi-compliance` answering 500: the stale count resolves to 1 (Northwind, 31 Mar 2026) from the positions read's `today`, not Unreadable. It also checks the company's FMV chip and its absence without `today`, and the reference order in the model.
- Eleven mutations, listed in the two test headers, each fail a test and pass again when reverted.
