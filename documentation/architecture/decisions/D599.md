## D599 — The Help Center, built to its canvas

**Issue #1280, slot S01, 2026-10-06.** No Worker change, no migration and no
new API route. This is step 1 of #1280, and the PR says `Part of #1280`.

The owner, 2026-10-06: "The current Help Center doesn't look at all like the
one that was supposed to be implemented, and where are the tickets users
submitted?" The same day the owner extended the canvas with the ticket screens,
from Session 1's prompt.

### What was true on main

- **`/help` was the old docs site with a front door.** Task #103 composed a
  hero and a category grid over it, but kept the rest:
  - a gray rail listing all 96 guides;
  - every guide rendered in one long scroll under the home;
  - the "Still stuck?" block at the very bottom of that scroll.
- **The canvas has none of that.** `design/canvases/integrated/Help Center.dc.html`
  draws:
  - H1, a home page: a lavender search band, the areas as cards, and "Still
    stuck?";
  - H2, one guide on its own page.
- **A member's tickets were a footer link away.** `/help/tickets` existed, but
  the only way to it from `/help` was "Open a ticket", below the whole corpus.

### The canvas, as it now stands

The owner's new export replaces the old one in place. Its route is live, as
`design/incoming/README.md` step 6 asks. It was decoded with
`scripts/read-canvas.mjs`.
- **H1** gains:
  - a "Your tickets" card;
  - a "Still stuck?" with four actions: Open a ticket, Message the team, Email
    support, and What we can see (the Trust Center).
- **H2** is unchanged.
- **H3 to H7** are the ticket screens: Your tickets, Open a ticket, the
  member's ticket (and H5b, not on the tracker yet), the admin's All tickets
  queue, and the admin's ticket. All five are drawn by an imported component,
  `Help Ticket Screen.dc.html`, now beside the canvas.

`integrated/` goes 76 to 77, and both design READMEs carry the new count.

### The change

- **`/help` is H1:**
  - **The hero band** has "How can we help?", a lede counted from the
    role-filtered manifest, the search with its `/` key, and three suggested
    searches. Each suggestion is still checked against the real index.
  - **The area cards** are two columns of tinted icon tiles. Each shows its
    guide count, four guides, and "All N →", which expands the card in place.
    The grid is built from the manifest, as before.
  - **"Your tickets"** shows the open tickets `GET /api/tickets` returns, at
    most three, latest activity first, each with its status and bounty state.
    - An admin's card reads "Open tickets across the platform", because the
      route answers an admin with every member's tickets.
    - A failed read says so and offers Try again. It never reads as none.
  - **"Still stuck?"** has four actions:
    - Open a ticket goes to `/help/tickets?new=1`, which now opens the form on
      arrival;
    - Message the team appears only on plans the Worker serves;
    - Email support;
    - What we can see, which goes to `/trust`.

    The status line keeps D332's rules.
- **`/help/<area>/<guide>` is H2.** It is one route, `/help/:area/:guide`, and
  the same `HelpCenterPage` reads which screen to draw from the path.
  - **The page** has a breadcrumb, the area tag, and a reading time from the
    guide's own words (200 a minute, never under one).
  - **The body** is the overview as the lede, the how-to steps, Tips in the
    lavender callout, Common pitfalls in the amber one, the screenshot, and
    Related.
  - **The rail** holds "On this page", then the guides in the same area. The
    canvas puts the licence line and the surface jumps there, which wait on
    #1280 step 3.
  - **A guide the viewer cannot read** answers "Guide not found". The page
    reads the same role-filtered manifest as the grid.
- **No old address breaks:**
  - **A hash on `/help`** (`#<area>/<guide>`) opens that guide's page. That
    hash was every guide's address, and it is in sent notifications, the
    advisor's tools and bookmarks.
    - A non-admin's admin anchor drops to `/help`, as before.
    - An anchor no guide carries leaves the home as it is.
  - **The admin path guard.** `AdminDocsPathGuard` now renders an admin guide
    at `/help/admin/<sub>` and sends `/docs/admin/<sub>` there. Redirecting to
    `/help#admin/<sub>`, as it did, would bounce straight back from the hash
    handler. Only an id-shaped segment is used; anything else opens the
    overview.
  - **A stale link is fixed.** StartupList's empty state linked
    `/help#core/projects`, and no `core` area has ever existed. It now opens
    `/help/build/projects`.
- **Helpers** live in `pages/docs/helpCenter.js`, as plain functions with no
  JSX, so the contract test runs them instead of reading them:
  - `parseGuidePath`, `guideHref` and `hashTarget`;
  - `readingMinutes`;
  - `openTicketsByActivity`.

### Where the build departs from the canvas, and why

- **No logo bar.** The app shell already carries the brand, and a second bar
  inside it would repeat it. The persona note it held reads per-guide licences,
  which no guide records.
- **"Popular this week" and "Did this answer it?" stay out.** Nothing counts
  views or stores answers yet. #1286 (S10, D603, migration 408) builds both
  stores, and Session 1 wires them here afterwards. Until then the contract
  test keeps them banned.
- **The per-guide surface tag, "Where this lives", "Open the surface" and
  "Applies to" stay out.** No guide records its surface or its licences. Adding
  them is #1280 step 3, content authoring.
- **The areas are the manifest's 14 sections, not the canvas's seven
  task-named ones.** Regrouping the corpus is also step 3.
- **The "Still stuck?" lede** does not promise "replies inside a working day".
  The SLA tiers run 24 to 96 hours by priority.
- **The "Your tickets" card has no review chip yet.** The ticket list does not
  return a feature request's review state. That comes with the ticket screens,
  #1280 step 4, Worker first.

### Verified

`frontend/test/help_center_contract.test.mjs` was changed where the behaviour
changed on purpose, and gained these tests:
- every guide has an address, and the page reads it;
- a `#<area>/<guide>` hash opens that guide, including the admin and unknown
  cases;
- every address the code builds for a guide names a real one. This sweeps
  `frontend/src` and the Worker for both shapes, plus every guide's Related
  links;
- the reading time;
- the "Your tickets" card, which reads the list and never shows a failed read
  as none;
- the canvas and its imported screens are in the repository.

The test that pinned the old single page ("the corpus stays mounted while a
search is open") is replaced by the guide-page tests, and the path guard's
test follows the guard.
