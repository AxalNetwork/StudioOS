### 2. The connection (part 1)

- **The record:** `MCP_PROVIDERS.beehiiv`.
  - Server `https://mcp.beehiiv.com/mcp`. Every endpoint must sit on `beehiiv.com`.
  - Four read tools: `list_publications`, `get_publication_stats`, `list_posts`, `get_post_stats`.
  - One write tool, `create_post_draft`, under `publish_issue: 2407`.
  - No scope is asked for or accepted, as Notion's record, so a grant that reports any scope is refused (`scope_refused`) and revoked.
- **`services/beehiiv/mcp.ts`:** `BEEHIIV_READ_TOOLS` and `BEEHIIV_DRAFT_TOOLS`, the record's frozen lists. Only `reads.ts` imports the file, and nothing imports the draft list. `beehiiv_connection_2407.test.ts` holds both, with the rule that no source file names the draft tool at a call site.
- **`services/beehiiv/reads.ts`:** the only file that opens a Beehiiv session.
  - A bad id is refused before any request.
  - A publication whose id is not Beehiiv's shape is dropped.
  - Every rate goes through `normaliseRate`.
  - Nothing but counts, rates, a title and a date is copied out of an answer.
- **`integrations/providers/beehiiv.ts`:** `connect` refuses a support session (403) and a paste (410). `disconnect` revokes at Beehiiv, best effort, then deletes the connection's `beehiiv_publication_links` rows. `revokeGranted` and `ready` follow PostHog.
- **Registry:** key `beehiiv`, `status: 'beta'`, `auth_type: 'oauth_mcp'`, `audience_rule: 'venture'`, category `Marketing` (new, appended to `CATEGORY_ORDER`).
  - `CONNECTOR_METADATA.beehiiv.pulls` and `feeds` are `BEEHIIV_FEEDS`'s built entries; `sends` is empty.
  - `writesProjectData` and `FED_LEDGER_PROVIDERS` gain `beehiiv`.
  - The brand icon is a monogram until a mark is recorded with its source.
- **The page (D753):**
  - It uses #2407's read sentences as written: "Reads your publication's subscriber counts, open and click rates, and each post's performance. Never reads your subscribers' addresses."
  - The draft sentences are prefaced "Drafts are not built yet". A page may not claim a write no code makes.
  - "Read works on every Beehiiv plan. Drafts need a paid plan." stays, naming capabilities, not plan names.
  - Every tool on the page is a read tool, named by its call site.
- **The picker,** in `routes/cycle_grow.ts` as #2407's Backend section places it:
  - `GET /beehiiv/publications?project=` returns the caller's own publications and the venture's link, or names the teammate whose Beehiiv serves it.
  - `PUT /beehiiv/publication` links, changes or unlinks the venture's publication. A link held by another member's connection is never replaced. Changing the publication starts its channel proposal afresh.

### 3. Grow in (part 2, the Worker only)

- **`POST /beehiiv/sync`:** one audience snapshot for the day and the last 20 sent posts.
  - At most 24 MCP POSTs (the record's budget). A post whose list answer has no figures is read with `get_post_stats` while the budget lasts. Past the budget, the sync says `partial`.
  - It raises the channel proposal once per link and returns counts only.
  - One failed read leaves the other's landing intact.
- **Where facts land:**
  - `subscribers_active` and `subscribers_premium` land in Revenue and traction.
  - `subscribers_free`, `open_rate_avg` and `click_rate_avg` land in Distribution, which draws all five.
  - Growth is computed from two snapshots when read.
- **The ledger:** every row lands through `connector_fed_items`, with external ids `beehiiv:fact:<venture>:<kind>:<day>` and `beehiiv:post:<venture>:<post>`.
  - The ledger is read by venture and external id under any Beehiiv connection. A figure the founder deleted therefore stays deleted through a disconnect and a new sign-in, not only through a re-sync.
  - Facts and posts keep `integration_id` without a foreign key, as `mercury_grow_facts` does, so a disconnect leaves them, dated, for the founder to delete.
- **The channel proposal:**
  - Accept links the named `growth_channels` row, or creates one through `addChannel` (kind `newsletter`, the founder's UTM source).
  - Dismiss stands for the life of the link.
  - Disconnecting removes the link and its decision, as #2407's schema puts the decision on the link. A new link may ask once more.
- **Deletes:** `DELETE /beehiiv/facts/:id` and `DELETE /beehiiv/posts/:id`. A writer deletes; the row stays deleted.
- **`beehiivPart`,** beside `mercuryPart`:
  - `not_linked`: the connect link.
  - `not_recorded`: not synced yet.
  - `ok`: every figure with "From Beehiiv, as of <date>", or `null` with its reason.
  - `unreadable`: the read failed. The rest of the module still loads.
  - A missing figure is never landed and never shown as 0.
- **`updatesHistory`:** each update gains `newsletter: null`, and the part gains `newsletter_reason`. Part 3 links a sent update's `publish_sends` row to the post its draft became (`beehiiv_post_stats.publish_send_id`).
- **`grow_updates`** was already in `moduleLabels.ts` ("Grow · Updates"). Its feed is listed in `BEEHIIV_FEEDS` as not built, so the registry does not claim it.
- **The SPA:** `frontend/src/lib/api/beehiiv.js`, one method per route above, listed in the generated api index.
- **The screens wait:** no screen is built. There is no Beehiiv canvas under `design/`, so `GrowFromBeehiiv.jsx` waits for BH1, BH2 and BH5. The Distribution Newsletter tab (D4495) keeps its disabled "Connect Beehiiv": connecting would change nothing the tab draws, because its connected state is part 3 and a canvas.
- **Who:** a support session is refused on every Beehiiv route but disconnect. The logs carry ids and counts, never a publication name, a post title or a figure.

### 7. Built (part 3), 2026-11-09: the PUBLISH adapter, draft only

Part of #2407, on the Worker only. No migration: `beehiiv_post_stats.publish_send_id` came with part 1's migration. It follows B1 (drafts only, each publication off by default) and the other answers in §1.

**A write lock that opens once (`integrations/mcpClient.ts`).** Before part 3 the shared client refused every write tool. Now:
- A session lists `write_offered`: the record's write tools, only on a record that names its `publish_issue`, only as the server lists them, never one it annotates destructive, and only with its pinned schema.
- `callTool` calls an offered write tool only with a live **publish ticket** (`mintMcpPublishTicket(provider, tool)`). The ticket is for one provider and one tool, buys one call, and is spent before the request. A copied or hand-built ticket, another provider's, a setup ticket or a spent one is refused before any request.
- A ticket can be minted only for a write tool of a record with a `publish_issue`. The only minter is `services/beehiiv/drafts.ts` (`mcp_client_d847.test.ts` and `beehiiv_connection_2407.test.ts` hold the tree to that).

**The draft (`services/beehiiv/drafts.ts`).**
- `renderDraft`: the first non-empty line is the title; every other line is one escaped `<p>`. Nothing else becomes HTML.
- `previewDraft` builds the preview with no request: title, body HTML, character counts against Axal VC's own ceilings (20,000 for the text, 250 for the title; Beehiiv documents none), media 0. Its problems keep Send off: nothing to send, a title with nothing under it, over a ceiling, an image (a draft from Axal VC is text only), a destination that is not a Beehiiv publication id.
- `createBeehiivDraft` sends the stored envelope's own title and HTML, after checking they are still what `renderDraft` makes of its text. It calls the draft tool once with `publication_id`, `title` and `body_content`, and **never a `status`**.
- Refused before the draft request, as `not_created`: `no_publication`, `content_changed`, `plan_required` (the server does not offer the draft tool: drafts need a paid Beehiiv plan), and a session that could not open, its stored tokens or their refresh included (`not_connected`, `unauthorized`, `rate_limited`, `unreachable`).
- After the request: a refusal Beehiiv answered (a tool error, a JSON-RPC error, a 4xx) is `not_created` `rejected`; a 429 is `rate_limited`. A timeout, a reset, a 5xx, an unreadable body or an answer with no post id is `unknown`: a draft may exist, so it is never sent again (D1319).

**The adapter (`integrations/providers/beehiiv.ts`).**
- `listDestinations`: the publications the sign-in sees, each "Draft only: not sent to subscribers". They arrive switched off for every company (PUBLISH's rule).
- `publishPreview` is `previewDraft`; `publish` is `createBeehiivDraft`.
- No `retract`: retract kind `none`. Axal VC never deletes or edits a founder's post; PUBLISH offers "Mark as removed".
- No `findPublished`: no read tool lists drafts (UNVERIFIED), so Check answers `check_not_supported` and an unknown outcome is looked for in Beehiiv.

**The rows.** `PUBLISH_TARGETS` gains Beehiiv's, the first provider row: all nine places, text limit 20,000 (Axal VC's), media 0, audience "Draft only: not sent to subscribers", retract `none`, `verified_on` null. `CONNECTOR_METADATA.beehiiv.publishes` is "A draft post in your publication"; `sends` stays empty, so no autopush or send mode reaches it. `PUBLISHERS` therefore holds `beehiiv`. The connector page names the draft tool by its one call site, and no longer says drafts are not built.

**Updates rows (part 2's `newsletter`).**
- A sync ties each landed post to the PUBLISH send whose `external_post_id` is that post's id, in the same venture, once (`publish_send_id`). Another venture's send is never tied. A failed tie leaves the post landed, and the next sync tries again.
- `updatesHistory` gives a sent update `newsletter: { recipients, open_rate, click_rate, as_of }` when an `updates` draft naming `portfolio_updates:<uid>` was sent to Beehiiv and its post has been synced. A figure Beehiiv did not give stays null. A deleted post's figures leave the row and stay gone.
- Otherwise `newsletter` is null, with `newsletter_reason` saying it was not drafted to Beehiiv or not synced since it was sent. A read that fails says "Unreadable", never "Not recorded".

**Where it departs from #2407's plan:**
- **No subtitle field.** PUBLISH's input is one text, so the draft has a title (the first line) and a body. A subtitle needs a field on the publish sheet (BH3).
- **No `findPublished`,** for the reason above.
- **The screens wait:** the Beehiiv preview tab (BH3) and the result line (BH4) are not drawn. PUBLISH's generic sheet shows the preview's title and HTML fields and the "Draft only" audience line. The publish sheet's code is unchanged.
