## D8827 — Eadwyn's version summary and per-conflict proposals on Compare with Axal (#8827)

Part of #4538. Builds the last piece D5963's canvas draws on Compare with Axal: SK-17's Eadwyn rail, with a summary of what Axal changed from the version an extension is based on to Axal's newest, and a way forward for each conflicting part. D4538 part 7 and part 9 left it as "not built".

### What this decides

1. **Accepting a proposal writes only through the rebase route.** A proposal is one of the rebase's own per-conflict choices: Keep mine (`mine`), Take Axal vN (`axal`), or a written value (`edit`). Accept puts that choice into the rebase sheet (SK-20) and opens it. The draft is written only when the editor presses Create draft there, through `POST /api/teams/skills/:uid/rebase` with `expected_draft_hash`.
   - **Why not `PATCH /skills/:uid`.** A PATCH edits the draft while it stays on its old Axal version. The draft's tools would still be checked against that old base, so a proposal that takes a tool new in vN could not land. The conflict would stay flagged, because the lineage still points at the old version. And the page has no editor to hold a PATCH's full set of parts (D4538 part 9). The rebase resolves the conflict, records the new base version, and already checks `expected_draft_hash`, the tool rule and every draft rule.
   - In the sheet, the accepted parts start chosen and every other conflict starts unchosen. This changes D4538 part 9's "nothing is pre-chosen" only for choices the editor has just accepted.
2. **The route.** `POST /api/teams/skills/:uid/proposals` is in its own file, `routes/team_skill_proposals.ts`, mounted at `/api/teams`.
   - Who may call it: the company's editors only (`mayWrite`). HQ admins and members get 403 `not_editor`. A caller who cannot read the skill gets 404.
   - It runs the same lineage checks as the rebase, so Eadwyn proposes only where a rebase could take the proposal.
   - It stores nothing.
   - `team_skills.ts` changes only by exporting its lineage helpers (`skillByUid`, `mayRead`, `mayWrite`, `baseOf`, `versionOf`, `versionParts`, `draftParts`, `threeWay`, `Parts`). The proposals therefore read the same comparison the page and the rebase read. The `/base` and `GET /skills/:uid` handlers are untouched.
3. **It is quoted and charged through the existing AI path.**
   - `{ estimate: true }` answers `quoteRun`'s hold and model, and runs nothing.
   - A run must bring that quote. If the hold or model has changed, the route answers 409 `quote_changed` with a fresh estimate.
   - The run is one `services/aiRouter.ts` `run`, pinned to the quoted hold (`pinMicrousd`). That gives it the router's budget hold, guard, metering and settlement (`aiBudget.ts`, `ai/pricing.ts`).
   - It reuses the `workspace_explain` task, as D6862's evidence read does: it reads back what one page shows. The usage logs tell its runs apart by the surface `AI_SURFACE.teamSkillCompare` and the rail page `Company · Team · Skills · Compare`.
   - No second router and no new task class are added.
4. **The tool rule (D5963).** "The base" of a proposal is the Axal version the accepted draft builds on: Axal's newest. `services/agents/skillCompareProposals.ts` withholds a proposal, with a reason the page shows, when:
   - the tools it would keep are not all Axal vN's (`tool_not_in_base`). Keep mine with a tool vN dropped is one case;
   - its words or value name a tool that is in neither Axal version (`tool_not_in_base`);
   - it is malformed (`proposal_invalid`). So is Edit on Output, Skill tags or Roles, which the rebase sheet does not write by hand.

   A summary line that names such a tool is dropped.
5. **Untrusted text.**
   - Each side's skill text reaches the model inside `untrustedBlock('record_text', …)`, and the system prompt carries `UNTRUSTED_RULE`.
   - Links in the answer that no skill text holds are cut (`withoutUnrecordedLinks`).
   - Only conflicting parts get proposals. The "unchanged" list comes from `threeWay()`, never from the model.
6. **When Eadwyn is unavailable.** If the model cannot be reached, the route answers 503 `proposals_unavailable` ("nothing was charged"). If the answer cannot be matched to the comparison, it answers 503 `proposals_unmatched`. Budget stops, the page switch and the guard keep their own codes (`refuseRun`). In each case the panel says what happened, adds that the comparison and Rebase still work, and draws nothing in place of an answer.

### Built to the canvas (SK-17, SK-25)
