## D6293 — Edit deal context and suggest recorded reviewers (#6293)

The approved DDL14 and DDL9b boards in `Due diligence · Boards.dc.html`
cover these existing case controls. No Worker route, permission or store
changes. The case dialog uses the existing lifecycle PATCH; Assign reads
the existing experts endpoint before its independent people search.

The context form records only changed round, cheque/currency and deal-link
fields. Shared `money.js` parses native minor units exactly, including zero,
JPY and KWD; it neither converts nor rounds. An unreadable stored currency
is retained unless deliberately changed or cleared. Deal choices come from
the caller-scoped subject search and must belong to this case's subject.
Untouched links remain untouched even when choices cannot be read.

The dialog requires `allowed.update`, excludes scoped reviewer reads,
preserves refused edits and refuses a stale observed case revision. This is
a UI freshness check, not a new server compare-and-swap guarantee. Existing
PATCH validation and authorization remain authoritative. The existing case
audit records actor and changed fields; these fields send no notification.

Reviewer suggestions use each section's `section_key` and the Worker's
recorded prior-review count. Missing counts say not recorded; recorded zero
stays zero. The UI retains only ID, name, role and count and never renders
email. Selection resets on section change and late responses cannot replace
the new section's suggestions. Empty, failed and unavailable suggestions
retain name search and assignment through the existing route. The experts
endpoint's narrower admin/partner gate is preserved: a permitted assigner
without access can still search by name. Existing invitation/Activity copy
says what is recorded and who is told.

The owner explicitly authorized s38's narrow DdCaseWork.jsx handoff
while #6356 (#6291) remains open. Overview's Deal context block now uses its
existing heading action to open the dialog, only for `allowed.update` and
inside its existing non-scoped gate. Other readers get the ownership sentence.
The phone action is at least 44px high. #6356's phone work is preserved; no
other part of that file changes. Both controls are complete, so the PR closes
#6293 once merged.

Verification covers exact amounts and changed-field payloads, unknown
currency, retained/refused/stale edits, scoped/read-only access, suggestion
counts/privacy, failure fallback, selected identity and late section reads.

widths. No production data is read or written and no deployment is made.
