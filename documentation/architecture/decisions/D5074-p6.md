## D5074 part 6 — the cap table scenarios' and Runway's controls from the Worker's capability maps (#5074)

Parts 1 and 2 are `D5074.md`; part 3 (`D5074-p3.md`) is the Investor narrative, part 4 (`D5074-p4.md`) Capital relationships and part 5 (`D5074-p5.md`) Use of funds' plan. This part moves the two scenario surfaces that part 2 and part 5 left: the cap table's Scenarios and Use of funds › Runway (Forecast, Scenarios, Compare).

### The cap table's scenarios

Scenarios are the venture's own saved models (D1018, D1023), not the record, so the record's map does not cover them. `cloudflare-worker/src/services/capTableScenarioCapabilities.ts` computes their map:

| Capability | Owner | Co-founder (write member) | Reader (advisor, read grant) | Admin, Super Admin, investor |
| --- | --- | --- | --- | --- |
| `edit` | yes | yes | no | the read is refused, so there is no map |
| `plan` | the caller's own plan (Raise + Grow, `studio`) | | | |

- **The read carries it.** `GET /api/captable/scenarios/by-project/:projectId/today` returns `capabilities` beside Today. The list, a scenario and Compare each read Today before they draw. `edit` is `canWriteProject(user, project)`, the gate every scenario write asks: a new variant through `ensureProjectWriteAccess`, a save, rename, attach or delete through `ensureScenarioWriteOr404` (`canWriteScenario`, the same gate for a venture's scenario). `plan` is `userMeetsTier(user, 'studio')`, the gate each write asks first (`ensureTier`, 402).
- **The page renders from it.** `scenarioStanding(capabilities)` (`scenariosModel.js`) gives `plan` and `writes` (`edit` and `plan`); only a `true` allows. `ScenariosPages.jsx` no longer reads the account's role, `hasTier` or the grants read.
- **What this fixes.** The page drew an admin's writes from the account's role: New scenario, Save, Rename, Delete and Attach. The Worker refused every one of them, because an admin never holds the venture's own gate (D1130). The admin's Today read is refused, so there is no map and nothing is drawn.

### Use of funds › Runway

- **Scenarios and Compare.** `GET /scenarios` and `GET /compare` return the same map as the plan read (`edit`, `mercury`, `admin_logged`), from the router's middleware. Scenarios draws New scenario, Edit, Make this the base and Delete only when `edit` is true. Before, a support session was shown all four, and the middleware refused each one `support_read_only`. Compare words Today's Mercury state from the map (an admin reads "Founder only"), as the plan's Runway does.
- **Forecast.** Forecast is its own store (`routes/financials.ts`, D1180). Its read returns `capabilities: { edit }`. `edit` is the save's own gate (`canEditFinancials`: an admin, or a founder on their own venture) and not a support session. The save and the recompute now refuse a support session `support_read_only`, as every other plan write does (part 5). Before, a support session could save the founder's forecast. Edit drivers and Save forecast are drawn only under `edit`. Without it, the page says "You can read the forecast. A support session does not change it."

### Not moved in this part

- The Raise overview's narrative card (`defs/raise.jsx`, `NarrativeHome`'s `admin`) and the cycle's New version dialog (`narrativeFormAccess`) still read the account. Neither has a narrative read with a map before it draws (part 3). They are the last item of #5074.
