## D7325 — Expand the worldwide fund directory from verified manager websites (#7325)

### Request and scope

The owner asked to add more funds worldwide to `/research/funds`, then to continue
the expansion. This adds reference-directory records through the existing Worker
read path. During implementation PR #7317 received a concurrent, independently
claimed verification update for #7326. Its branch and files are preserved; this
larger expansion uses its own branch from main. Apply-time identity checks allow
the two imports to coexist. Other Research UI and vehicle identity tasks retain
their existing owners.

The reviewed manifest contains 605 candidates and 641 evidence entries. Against
the pinned served catalogue, 49 identities are already represented and 556 are
new: Asia-Pacific 187, Americas 178, Africa and MENA 166, and Europe and Caucasus
25. Of those additions, 56 have a supported headquarters and 323 a supported
sector classification. Counts are derived from the manifest and import report,
never hardcoded as a production-row-count test.

### What a new record means

The source identifies a venture investment manager. Unless separately recorded,
its specific vehicle, fund number, fundraising date, fund size, LPs and LP backing
are unknown. A known manager is not evidence that a particular fund is open to
new investments. No availability, performance or return claim is made.

The original research manifest under `data/research-funds/` holds the official
website, retrieved evidence URLs, short factual paraphrases and verification date.
Historical names are aliases, so a renamed manager is not added again under its
old identity. Research regions describe collection coverage, not headquarters.
The headquarters country is recorded only where supported. A local office,
registered vehicle domicile or investment focus is not enough.

Sector labels come from retrieved manager statements. Semicolon separators and
spelling-equivalent labels (such as Artificial intelligence to AI) are formatted
for the existing comma-separated crosswalk, with the original classification
retained in the manifest. Broad Healthcare is never narrowed to Digital Health.
Stage and cheque-size
evidence is retained in the manifest for later product work; neither is loaded
into unrelated directory fields. The existing API has no public-directory stage
contract and fund sizes have source-specific currencies. This change leaves
unsupported financial fields NULL. EIF/EIFO continue to render as unknown when
no LP evidence is recorded.

### Reproducible loading and identity

`scripts/import-global-funds.py` is offline and uses only the Python standard
library. It validates every input and rebuilds the relevant existing catalogue
from five pinned committed migrations in an in-memory SQLite database. It rejects
invalid URLs, missing primary citations, duplicate manager names or hosts, invalid
dates and non-country headquarters labels. Names must yield an ASCII identifier
key; a name entirely outside that key space needs a sourced romanized form before
import. This prevents emitting the empty identifier `global-`; all reviewed
manifest names already satisfy the rule.

It compares manager names, historical aliases and normalized official website
hosts against served records. Vehicle suffixes and diacritics are normalized for
the comparison. Existing vehicles win and retain their richer data. The generated
migration also checks names/aliases and website hosts at apply time, protecting
against intervening catalogue additions. Host matching treats explicit ports
and a terminal DNS dot as the same host, removes only a leading `www.`, and
keeps other subdomains distinct. It uses prefixed manager IDs to avoid
colliding with historical records. Stable IDs make replay safe. The existing
`research_fund_directory_uid_moves` table also guards every insert: a later
vehicle migration may retire a manager UID, and replay must never revive it or
shadow its canonical redirect, even after a name and website change.

The concurrent #7326 migration was replayed with this import in both orders on
the prior catalogue. Applying #7326 first adds its 58 rows and this batch adds
511; applying this batch first adds 556 and #7326 adds 13. Both orders produce
569 combined additions with no cross-source normalized-name or official-host
collisions. This comparison is evidence for the reviewed #7326 head
`0cccf5eb2850723a0915a22cc10ae5e741ed7a4d`; later changes still need their own
review. The migrations do not depend on one another's files.

The CLI report names the five pinned baseline migrations and labels its
comparison scope. Later catalogue changes deliberately do not alter historical
reproduction; apply-time guards may reduce the number actually inserted.

This is a conservative identity match, not a fuzzy name merge: an ambiguous
identity is reviewed or omitted. A shared manager website can suppress several
candidate names; it never deletes existing vehicles. Later novel aliases still
require source review before another import.

### Source policy and country facets

The source record is `Axal VC — verified fund manager websites`, with `cite only`
and no claim of website republication permission. `published_url` is NULL so the
existing source presenter uses each row's official evidence URL. The compiled
manifest is linked as the evidence record, not substituted for the manager's page.

Source metadata is inserted with `INSERT OR IGNORE`. A later takedown verdict
therefore survives replay. Existing withheld third-party material stays withheld
and unchanged. Where independently retrieved manager evidence identifies the same
business, its new citation is separate from that withheld material; nothing is
copied from the blocked source into the new record.

Countries missing from the current catalogue receive ISO country rows and exact
raw-value `fund_hq` mappings in the existing override table. An existing manual
mapping, including one that pins a value as unmapped, wins. No shared taxonomy
module or frontend is changed.

### Verification and release

The focused test exercises the generated SQL on real SQLite, including the prior
vehicle migrations. It checks preserved rows, report histories and saved
references, duplicate suppression after generation, per-row source links, source
takedowns, unknown financial fields, country facets and idempotence. Invalid
manifests are rejected before any SQL is emitted. Fault-injection checks prove
that removing duplicate guards, inventing a zero fund size or replacing a source
verdict makes the relevant invariant fail.

The Node 22 root frontend build and all 13 focused tests pass. The PR records
the actual full-drift and hosted check outcomes after completion; they are not
inferred from a successful build. The focused migration replay also verifies
that the offline report and actual inserted manager identities agree.

The migration ships only through the repository's normal reviewed release
workflow. No production D1 data is read or written by this task. An independent
review from another vendor remains a landing requirement for this significant
data PR. If deploy logs are unavailable, a ready PR is not described as live.
