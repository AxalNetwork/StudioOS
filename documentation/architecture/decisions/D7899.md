## D7899 — Free deterministic repository security (#7899)

**Decision date:** 2026-11-20. **Scope:** repository settings and CI; no application,
database or production deployment change.

The owner requires free security controls without GitHub AI or generated fixes.
Keep advanced CodeQL, Semgrep OSS, Gitleaks, the dependency graph and Dependabot.
GitHub Copilot Autofix, AI-detected secrets, AI Scan and Copilot automations stay
off. Retire the Copilot preparation workflow and its feature-specific parity
test; retain the general workflow concurrency/draft guard with a live fixture.

### Alert handling

This supersedes D6935's Autofix generation/publication path. The reconciler
reads default-branch alerts and links existing same-repository pull requests,
including legacy remediation branches. It respects human assignees and atomic
claims and routes eligible work to S21. Resolution still requires the trusted
main scan to confirm that a finding is fixed. It can write issue trackers only:
contents, pull requests and security events are read-only for both workflow
and optional installation tokens. It never requests an AI fix or writes code,
branches or pull requests. Existing inert compatibility helpers are retained
where another active issue owns tracker refactoring.

### New dependency admission check

`dependency-review.yml` emits **Dependency Review** for every main-targeting
pull request, including drafts, and every requested merge group. The action
uses the immutable base/head SHAs from that event, so queue admission checks
the combined candidate. High/critical vulnerabilities fail in runtime,
development and unknown scopes. No new license policy is introduced. The job
has only contents-read permission, checks out no candidate, performs no install,
posts no comment and generates no fix. PR replacement runs can cancel; queue
runs cannot. Snapshot-warning retries and total runtime are bounded.

The action is pinned to v5.0.0, whose event resolver supports merge groups.
Do not add the required context before this workflow is deployed and verified
on a real PR and queue candidate. Keep the existing required-context maps and
live six-check merge queue until the rollout in
`documentation/operations/FREE_SECURITY_7899.md` completes.

### Advisory posture scan

`ossf-scorecard.yml` runs weekly and manually on this repository's explicitly
public main branch. It uses standard hosted Ubuntu, no extra credential,
no external result publication, no OIDC and no artifact upload. Only a successful
scan uploads SARIF to code scanning. Scorecard stays outside the merge path.

Pin Scorecard action v2.6.0 despite its recent release: its Scorecard 5.7.0
dependency fixes credential leakage through redirects, symlink reads outside
the checkout and missing failure exit codes. The latter is needed for reliable
success-only SARIF publication. The upstream release notes are linked in the
runbook. All new action references are full commit SHAs.

### Project secret detection

Add a dedicated Gitleaks rule for the complete member API bearer format already
defined by `cloudflare-worker/src/services/apiKeys.ts`. Public prefixes and the
documented placeholder do not match. Remove the blanket HS256 JWT-header
allowlist, which could not distinguish a fixture from a real token. No matching
literal fixture in the tracked tree required a replacement exemption. Existing
global path/regex exclusions otherwise remain; this is not a claim that all
historical allowlists have been audited.

Use Gitleaks for project-specific patterns without relying on a licensed
GitHub custom-pattern entitlement. No paid plan, trial, seat or AI-credit budget
is activated. Public-repository free eligibility must be reassessed before a
visibility change. See the runbook for the controls deliberately kept off.

### Verification

Behavioral regression suites exercise real mocked API sweeps, S21 handoff,
idempotence, existing PR linking, claims and main-confirmed closure. Workflow
tests evaluate PR/queue SHAs, cancellation, scopes, authority, public-main
admission and failed-scan upload refusal with mutation/restoration cases.
Synthetic Gitleaks CLI checks verify both Axal bearer and ordinary HS256 JWT
detection, and exclude public prefixes/placeholder/malformed values. Local and
hosted gate outcomes are recorded in the task and PR; configuration assertions
alone do not prove hosted execution or active branch enforcement.
