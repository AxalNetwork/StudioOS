### Renderer and contract boundary

RecordView takes the record, optional appended activity, cycleName,
moduleName and onLink/onForm/onWrite/onShowAll/onClient callbacks. It draws
only supplied sections, including their empty copy. It never reads, constructs
a dialog, confirms, mounts a form or invents activity. Its exported
RecordActions, RecordFacts, RecordSection and RecordActivity are available to
#1659 and #1665. Header, refusal/loading states and navigation belong to PR 2.

The fixture uses D689/D690's record contract: facts {label,value,reason},
main/side sections {key,title,action?,rows,empty?}, rows {a,b?,c?,tone?,href?,action?},
and activity rows {a,b} (text/date). The Worker types have not yet merged;
PR 2 must reconcile any naming changes in recordModel, in one place.
Pills accept the table's text/tone and the canvas's t/s spelling. Canvas
vio/amb map to v1/warn; unknown tones draw plain text.

The four facts and 1.5:1 body collapse to one column below 760px of the
named cycle size container, not the viewport. PR 1 uses Tailwind's named
container variants; #1655 supplies the container before mounting. Main rows
retain three cells, side rows two. The canvas's exact spacing, type sizes,
action tones, section ids and missing-fact reason are carried through with
light/dark pairs.

PR 1 copies CycleModulePage's NR class verbatim because that file is owned by
earlier tasks. PR 2 exports and imports NR as #1658 directs and removes the
temporary copy. PR 1 similarly owns a local RECORD_ID pattern; PR 2 replaces

### Actions and record links

A row links only with records.linkable === true, an actual Worker record id
and the lowercase allowed id pattern. An explicitly missing recordId never
falls back to an adapter's display id. The reserved new route is rejected.
Record URLs retain the supplied venture query. Route mounting, aliases and
adapter changes are PR 2.

Only declarations from record.actions and section.action authorize row
actions. A row may reference a key or {key,body}; it cannot override kind,
href, confirm or other declaration fields. In-app paths reject protocol
relative URLs, backslashes and controls. Link actions also allow mailto.
External HTTPS/javascript URLs and link actions without a destination or
registered client action are hidden.

The client registry contains export-persona. The parent onClient callback
invokes its handler with the already loaded record; D693 later adds
export-memo. Form/write callbacks preserve the declaration and confirm;
the route will provide saveability checks, confirmation outside the size
container, API writes and re-read behavior in PR 2.

finishRecordWrite is an injected-effect helper for that integration:
an open.url starts with /api/files/dl/ and is a safe in-app path before
opening in a new tab with noopener,noreferrer. Download writes never re-read.
Other URLs produce "That file could not be opened." and never open.
An open without url is reserved for #1659's parts view. Ordinary writes re-read.

### Persona export and privacy

personaModel explicitly copies only title, sub, at most four facts, the
Five steps main section and Pain themes side section. Stable section keys
or the canvas's exact case-insensitive titles select them. It never serializes
the whole record or any interview, contact, activity, arbitrary section or
action. The export is generated from the current read, without another API call.

The persona uses pdfBoard's 816×1056 design-pixel letter board (612×792 pt).
Its fixed budgets are five steps and eight themes; omitted row counts are
shown. Text is capped before layout, and the renderer measures every line,
ellipsizing the final allowed line including unbroken words. Title/sub,
facts and sections have fixed regions so long input cannot create a second
page or clip the footer. Filename: persona-<segment slug>-<UTC date>.pdf;
slug capped at 64 ASCII characters, fallback segment. PDF metadata is generic.

Canvas departures decided on the issue: PDF only (no PNG); real activity with
Show all instead of template rows; side section actions when supplied;
empty copy when no rows; no desktop next strip. Later integration also uses a
stretched first-cell link rather than a button nested in a row anchor, a
record-title phone select entry until #1665, and truthful data-room access copy.
