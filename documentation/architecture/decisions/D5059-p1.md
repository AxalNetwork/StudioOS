### HQ reconciliation sequence

Use a Super Admin session to read
`GET /api/admin/program-entitlements/reconciliation?program=<key>&limit=100`.
For each mapped program, follow `next_after` with the `after` parameter
until null, keeping each program's pages on the same UTC day. Restart that
program if the date changes. Retain the private report in an authorized
location. Public issue comments should contain aggregate outcomes only.

| Program key | Evidence for review |
| --- | --- |
| `spinout-lab` | Enrolment or cohort activation |
| `learning` | Active enrolment in a published learning program |
| `investor-cohorts` | Unended investor cohort grant with a current end date |
| `mentor-cohorts` | Active mentor assignment |
| `perks` | Previous perk claim |
| `refer-and-earn` | Previous referral submission beyond draft |
| `referral-partners` | Current active partner terms |
| `influencer` | Active influencer membership |
| `product-testing` | Active tester pool membership |

The AI-native Venture key returns `evidence_not_mapped`. Record it as an
unmapped source and review holders through Program access. An empty report
covers the selected evidence query, with the limitations in D5059 section 8.

For every program, record the report date, pages completed, evidence source,
counts by disposition, and unresolved exceptions in the private review.
For an approved grant change, record the current account/program, source
licences, agreement readiness, current grant revision, reviewer and reason.
Re-read that account immediately before submitting the HQ grant action.

Preserve paused and ended grant decisions. Review licence and agreement
blockers before granting. Historical activity needs a human decision about
participation. Re-run the report after approved changes and retain its
aggregate outcome.
