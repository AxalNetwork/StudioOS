## D1573 — Deck v2 D12: per-slide investor analytics, with a per-link "Time per slide" consent

- **Status:** built in slot S25, 2026-11-02 (#3820, deck builder v2 Phase D, under #3716). Not deployed or live verified.
- **Scope:** S1's final-canvas revision of #3820 (2026-11-01).
- **Boards:**
  - PD-8 · pd37, "Viewer analytics";
  - PD-8 · pd35, "Share, one link per investor": the Analytics column, the row's and the row editor's "Time per slide" switch, and "Analytics so far are kept" on Withdraw.
- **Builds on:**
  - D663's per-slide seconds (`deck_view_slides`, migration 442), written by the share reader's heartbeat;
  - D1500's card uids (A8, #3750, migration 714);
  - D1565's investor links (D4, #3812, migration 738) and D1111's Withdraw;
  - D1564's precedent of a link setting kept on the link's own `include_json`.
- **Migration:** none.

### The question

pd37 draws one investor's reading of a deck: seconds per card as bars over the thumbnails, the most-read card, and a visit timeline. pd35 adds an Analytics cell to each investor row and a "Time per slide" switch, with "Off keeps visit counts only".

Most of the data already existed:
- the share reader's heartbeat sends its running seconds per slide place;
- D663 stores them per view, and D1500 names each one's card by uid.

What was missing:
- a read of one link's seconds;
- the timeline;
- the consent, which had to stop the storing, not only the showing.

### What was decided

**No new store.** S1 gave "Migration: none". Per-card seconds did not need a table, because `deck_view_slides` already holds them by view and card uid. A link's analytics is that link's views joined to their rows.

**The consent is the link's own `include_json` key** (`time_per_slide`), beside what the link includes and D1564's `publish`:
- on unless the key says `false`. Every link made before this, and a new one by default, has it on, as pd35's row editor draws it. Links already stored per-slide seconds before this decision, so on is also what they did.
- `parseShareInclude` reads only its six keys and `publishOf` only `publish`, so neither changes.
- The one link writer (`createDeckLink`) takes `time_per_slide` (true or false, 400 otherwise) and writes the key only when it is off.
- `PUT /api/decks/:id/investor-links/:shareId/time-per-slide` `{ on }` sets it on a link.
- **Who owns the field.** #3812 (D1565) did not add one: its adapter row's description names consent, but no field, column or key was built. So the field is owned here, on the existing links, as S1's spec change 5 asked.

**With it off, only counts are stored.**
- The share read still writes the view row; that row is the visit count.
- The heartbeat (`decks.ts` `POST /share/:token/heartbeat`) then stores nothing more: no `read_seconds` and no `deck_view_slides` row. It answers `{ ok: true, counts_only: true }`.
- Turning the switch off on a live link stops what is stored from then on. What was counted before is kept, and is shown again if the switch is turned back on.

**Seconds per card, keyed by card uid, in the link's order.**
- The heartbeat now names each slide place's card against the cards as this link sends them (`linkSentCards`): the version's cards, in the link's variant order (D1565), less the cards the link leaves out.
- Before this, the place was read against the master's order, so a tailored link's seconds were put on the wrong cards.
- A row from before 714 (no uid) is read by place against the same list.

**The visit timeline** is one event per thing that happened, `{ kind, at, view_id }`, oldest first:

| Kind | From |
|---|---|
| `opened` | the link's first view |
| `nda_accepted` | the first NDA acceptance on the link (`deck_share_conversions`) |
| `reached_ask` | a view that counted seconds on the version's ask card (`askCardIndex`, D902) |
| `revisited` | every later view |

The kinds are #3815's three signals (first view, revisit, reached the ask). A "revisit after 48 h" is a `revisited` event 48 h after the one before, so #3815 can read this shape as it is.

**The read.** `GET /api/decks/:id/investor-links/:shareId/analytics` (`routes/deck_slide_analytics.ts`) answers:
- `deck_id`, `link_id`, `investor`, `nda`, `status`, `withdrawn_at`;
- `time_per_slide`, `views`, `last_viewed_at`, `read_seconds`;
- `cards` (each `{ card_uid, index, title, seconds }`), `most_read`, `ask_card_uid`;
- `timeline`.

Its gate is `projectOwned`, as `GET /:id/engagement`. The consent write needs `write: true`. A link that is not one of the deck's investor links is 404.

**Missing is null, never 0:**
- a card no heartbeat counted has `seconds: null`;
- with the consent off, `cards`, `most_read` and `read_seconds` are null;
- a link nobody has timed has `read_seconds: null` in its pd35 row as well (D1565 answered 0).

**Withdrawing keeps the analytics.** Withdraw (D1111) only closes the link. The read answers a withdrawn link in full, and its heartbeats are refused as before, so nothing more is stored.

**The engagement median.** `shareAnalytics`' per-viewer median leaves out views on a link with the consent off. Such a viewer still counts as a viewer, but its seconds are null, not 0.

### Departures

- **The thumbnails are title tiles**, as pd37's `THUMB` draws them, not rendered cards.
- **`reached_ask`'s time is the last heartbeat that counted the ask card in that view.** `deck_view_slides` keeps one `updated_at` per card and no first-reached time, so this is the latest the reader can have reached it. A first-reached time would need a column, and S1 gave no migration.
- **Times are shown as stored, in UTC** ("12 Oct · 09:14").
- **The switch writes when it is pressed**, as Withdraw does after its confirm. It is a setting on one link, not a draft.
- **The Walkthrough column** (#3837) and the "Revisited after 48 h" tag (#3815) are not drawn here.
- **`GET /:id/engagement`'s per-view list is unchanged.** It still lists a consent-off view's `read_seconds` as stored (0). Only the median was corrected.

### Verified

**`cloudflare-worker/test/deck_slide_analytics_d1573.test.ts`** (9 tests):
1. Per-card time per investor equals the heartbeat fixtures, by card uid. Running totals keep their last value per view and sum across views, and one investor's seconds never appear in another's.
2. A tailored link's slide places name the variant's cards.
3. With Time per slide off, only counts are stored. One view row is written, with no read seconds and no `deck_view_slides` row. The read answers `cards: null`. The key sits beside `include` and `publish` without changing either.
4. The switch on a live link stops what is stored from then on, and keeps what was counted.
5. The visit timeline: Opened, Accepted the NDA, Reached the ask, Revisited, with a tie in reading order.
6. A withdrawn link keeps its analytics and takes no more heartbeats.
7. Missing is null: no seconds, no most-read card and no timeline for a link nobody opened.
8. The engagement median leaves out a consent-off viewer.
9. The gate: the founder reads; another founder is refused (403); no sign-in is 401; an unknown link or deck is 404. An admin who is not a Super Admin reads but cannot write the consent. A plain studio link is not an investor link.

**`cloudflare-worker/test/deck_contracts_d1511.test.ts`** gains test 7: the real reply matches `deckSlideAnalytics` for a link nobody opened, a timed link and a consent-off link.
