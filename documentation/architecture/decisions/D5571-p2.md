## D5571 part 2 — Google Cloud Run Jobs as the second external executor, disabled and unmounted (#5571)

**Status:** part 2 of #5571, the Google Cloud Run Jobs adapter, prepared under the 2026-11-25 S1 reconciliation note. Disabled by default and unmounted; no Google Cloud project, Workload Identity pool, credential, binding, route, consumer or deployment exists or is changed, and no job is run. Azure (part 1, `D5571.md`) keeps first-live priority. AWS Fargate follows as its own bounded adapter. It builds on the merged D5565 `ExecutorAdapter` and mirrors part 1's structure: an injected privileged transport, an injected transactional start-reservation store, and operator config whose unset capabilities refuse.

### The adapter (`services/agents/cloudRunJobsExecutor.ts`)

`createCloudRunJobsExecutor({ config, transport, starts })` implements D5565's `ExecutorAdapter` for one pre-provisioned Cloud Run job. The request shapes come from the Cloud Run Admin API v2 reference (`run.googleapis.com/v2`):

| Contract call | Cloud Run call |
|---|---|
| `create` | `GET …/jobs/{job}`, then `POST …/jobs/{job}:run` with `{ etag, overrides: { containerOverrides: [{ name, env }], taskCount: 1, timeout: "<max_duration_s>s" } }`. The answer is a long-running `Operation` whose `metadata` is the `Execution` it created. |
| `get` | `GET …/jobs/{job}/executions/{id}` |
| `terminate` | `POST …/jobs/{job}/executions/{id}:cancel` with the execution's `etag` |
| `collect` | Read the execution. Cloud Run holds no artifacts; they reach the broker through D5565/D5567. |
| `cleanup` | `DELETE …/jobs/{job}/executions/{id}?etag=<etag>`, only for an ended execution this ref owns |

**The image is pinned by the job, not the execution.** `jobs.run` overrides cannot change the image, CPU or memory. So `create` reads the job first and refuses with `capability_denied` unless it has exactly one container whose image is `<registry repository>@<spec digest>` (`image_digest`), and declares `taskCount: 1` and `maxRetries: 0` (`job_shape`). An absent `maxRetries` is refused, because Cloud Run's default is 3 and a provider retry would run the same key twice; Axal retries only through a new fenced generation. The run carries the job's `etag`, so a job changed between the read and the run is refused by Cloud Run (409 `ABORTED` → `provider_conflict`), and the digest checked is the digest that runs. A refused job read sends no run and spends no key.

**Status mapping.** From the execution's `Completed` condition, keyed by `state` or `state/executionReason`: `CONDITION_PENDING` and `CONDITION_RECONCILING` → `provisioning`, or `running` once `runningCount > 0`; either with `CANCELLING` → `cancelling`; `CONDITION_SUCCEEDED` → `finished`; `CONDITION_FAILED` → `failed` (`NON_ZERO_EXIT_CODE` → `non_zero_exit`, `DELETED` → `deleted`, otherwise `failed`); `CONDITION_FAILED/CANCELLED` → `cancelled`. Any other pair, or no `Completed` condition, is `unknown`, never a guess.

**Ambiguous outcomes:**
- **Run is not idempotent.** `jobs.run` takes no request id. Every execution carries a plain env override, `AXAL_EXECUTION_KEY` = `tenant.run.attempt.generation`, and `create` lists the job's executions (following `nextPageToken`, at most 20 pages) for that key before it reserves and runs.
- **Unknown, then located.** A dropped connection, a 408, a 499, a 5xx (including 504 `DEADLINE_EXCEEDED`), a 409 `ALREADY_EXISTS`, or a 200 whose operation names no execution of this job returns `unknown` with `start_ambiguous`. `get` on the `pending:<key>` ref locates it by key; until then it stays `unknown`, because an empty list is not proof that a run never landed.
- **Reservations.** As in part 1: the injected `CloudRunStartReservations` store must be one durable transactional D1/DO store shared by every adapter for the job. A reservation never expires or releases. A failed reservation refuses before any run (`start_reservation_unavailable`). Definite 4xx refusals (excluding 408 and `ALREADY_EXISTS`) are recorded, and a retry returns `start_generation_refused`. Two executions with one key are `duplicate_execution`. No production store or binding is installed here.
- **Cancel.** Sent with the execution's `etag`. A dropped or 5xx cancel returns `unknown` with `stop_ambiguous`; an unlocated execution is not cancelled until it is visible. A `cancelling` or ended execution is never sent another cancel.
- **Ownership.** An execution is this ref's only when its full name is `projects/{p}/locations/{l}/jobs/{job}/executions/{id}` for this job, the id matches the ref, and its key matches the ref's tenant, run, attempt and generation. Anything else is `execution_not_authorized`, whatever name the ref gives.

**Exact owned cleanup.** `cleanup` deletes one execution: the one the ref owns, only once it has ended, conditional on the `etag` just read, so a version that changed in between is refused (`provider_conflict`) rather than deleted. It never deletes the job or another execution. A dropped or 5xx delete is `cleanup_ambiguous` (retry); an execution already gone (404) is `{ cleaned: true }`, so cleanup is idempotent.

**Fails closed.** Each capability comes from operator config, and an unset one refuses the spec with D5565's typed `capability_denied`: network mode (none unless declared enforced by Direct VPC egress and firewall), hostile-code isolation (operator attestation only), checkpoint restore (off), duration (`task_timeout_max_s`), regions, CPU, memory, disk and concurrency. Cloud Run's writable filesystem lives in task memory, so a spec whose `memory_mb + disk_mb` exceeds the job's memory limit is refused (`disk`).

**Credentials.** The adapter takes an injected Cloud Run transport. The broker exchanges the Worker's OIDC token through Workload Identity Federation (STS, then service-account impersonation) for a short-lived, `cloud-platform`-scoped token and attaches it. No key is in this module, the run request or the container; the overrides carry three references only.

**Errors.** 401 `UNAUTHENTICATED` and 403 `PERMISSION_DENIED` → `provider_auth_refused` (revoked identity). 429 `RESOURCE_EXHAUSTED` → `provider_quota`. 409 `ABORTED` → `provider_conflict`. Other 4xx → `provider_rejected` (a missing job on `run` included). 404 on a read → `execution_not_found`. Only the google.rpc `status` enum is read; provider text is never copied into a refusal.

**Cost.** As in part 1: without priced rates, `estimate` refuses with `estimate_unavailable`, never 0; with rates it bills vCPU-seconds and GiB-seconds over `max_duration_s` and marks the figure unmeasured.

### Not verified yet, and how it will be

These need an owner-authorized project and region:
- that an execution's `template.containers[].env` reflects the run's env overrides (ownership depends on it; if it does not, every lookup fails closed as `unknown` or `execution_not_authorized`, never misattributed);
- the `Completed` condition and `executionReason` a cancelled, timed-out and deleted execution actually report;
- that `maxRetries: 0` is serialized rather than omitted on a job read;
- whether `jobs.run` ever answers 409 `ALREADY_EXISTS`, and how etag mismatch is reported on `run`, `cancel` and `delete`;
- startup time, real billing figures, the maximum task timeout and the CPU/memory pairs the job accepts;
- native isolation of the chosen execution environment, for `untrusted_code`.

Until then, the configured job bounds every spec and estimates stay unavailable. No live-migration claim is made; `checkpoint_restore` stays off.

### Cloud Run runbook (staged; enabling is the owner's)

1. **Project.** A dedicated project for workspace runs, one Cloud Run job per Axal region in a matching location, with one container, `taskCount: 1`, `maxRetries: 0`, and a task timeout at least the longest permitted run.
2. **Least privilege.** A Workload Identity pool and provider trusting the Worker's OIDC issuer, allowed to impersonate one broker service account. Give that account a custom role on the one job only: `run.jobs.get`, `run.jobs.runWithOverrides`, `run.executions.get`, `run.executions.list`, `run.executions.cancel`, `run.executions.delete`. The job's own runtime service account gets Artifact Registry read on the one repository and nothing else.
3. **Image registry.** A private Artifact Registry repository. The job's image is set by digest; the adapter refuses a job whose image is a tag or another digest.
4. **Networking.** Direct VPC egress with all traffic routed to the VPC, and a firewall that denies egress or implements the allowlist. Set `enforced_network_modes` only after that is in place and tested.
5. **Metrics.** Execution create, start and completion times and the `Completed` condition, plus Cloud Run job metrics, feed D5570's queue-wait, start p50/p95, error and cost-per-success figures.
6. **Cost.** Set `rates` from the project's actual price sheet. Until then, D5570 reserves the spec ceiling.
7. **Teardown.** Cancel running executions, delete ended ones, then delete the job, the role binding and the Workload Identity provider.
8. **Emergency disable.** Set `enabled: false` (every call refuses before a request leaves), or remove the impersonation binding (every call returns `provider_auth_refused`).
9. **Rollback.** Delete the module and the test. Nothing imports them.

### Later gates (not in this part)

The actual project, region and authority, with native isolation and conformance; the transactional reservation-store integration and the provider-specific operating runbook as executed; a separate activation and cleanup proof. None is done or implied here.

### Tests

`cloudflare-worker/test/cloud_run_jobs_executor_5571.test.ts` has thirteen tests on a synthetic Cloud Run v2 endpoint serving recorded fixtures (Job, Execution, Operation, google.rpc errors). They cover: disabled refusals on all six calls and config validation; the etag-conditional, digest-pinned, one-task, secret-free run with the spec's timeout; a job not pinned to the digest, with more than one task or with retries refused before any run without spending the key, and a job changed between read and run refused; each fail-closed capability, including disk in memory; unknown starts (dropped before and after landing, 408, 504, 503, `ALREADY_EXISTS`, no execution named) located by key and never run twice; duplicate executions across list pages and twelve concurrent adapters sharing one reservation; a lost reservation reply; throttling and revoked permission on run, list, job read, get and cancel, with provider text never copied; every status mapping; cancel with the etag, ambiguous cancel and pending-cancel reconciliation; exact owned cleanup (wrong tenant, generation, region and path refused, ambiguous and refused deletes, idempotent re-clean, a changed version not deleted, the job never deleted); another job's execution refused; unpriced estimates refused.
