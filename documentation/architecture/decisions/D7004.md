## D7004 — Structured data for the firm, articles, events and breadcrumbs, from recorded facts only (#7004)

**Decision date:** 2026-11-23. **Scope:** a new plain module, one hook in the prerender, the Worker's record
card (D1439) and the help guide page. No title, description, canonical, route, `wrangler.toml` or `[assets]`
change. Part of #6976 (plan key X22). Builds on #6995 (X13), which writes each route's HTML.

### What changed

None of the 30 sitemap URLs carried JSON-LD. Now:

- **`frontend/src/lib/structuredData.js`** builds every block. It loads in plain Node (explicit `.js`
  specifiers), so the prerender and the Worker import it, as they import `ogRegistry.js`.
  - `Organization` on `/` and `/about`: the name "Axal VC", `https://axal.vc`, the site's mark
    (`/axal-mark.png`, the apple-touch-icon) and `sameAs` from `SOCIAL_LINKS` in `lib/siteLinks.js`, the
    accounts the live footer links.
  - `Article` from an article's record: headline, the author's name as a `Person`, `datePublished`,
    `dateModified` (only when the last edit is later than publication), the excerpt or subtitle, the cover,
    the URL, and the firm as publisher.
  - `Event` only when the record holds a start date and either a place (`in_person` or `hybrid` with
    `location_text`) or an online format (`virtual`, `online`, `hybrid`). An online event's location is a bare
    `VirtualLocation`: the only online address recorded is the join link, which a public page never carries.
  - `BreadcrumbList` on the trust center's five subsections (Trust center, then the tab, both from the
    registry's titles) and on each help guide (Help, the guide's area, the guide), the trail its page draws.
  - `compact()` drops every property with no recorded value, and an object left holding only its `@type`.
- **Never written:** a rating, a review, an offer or price, an employee count, a founding date, a founder, or
  testimonial markup. `FORBIDDEN_LD_KEYS` lists them and the tests check every block against it.
- **Escaping.** `jsonLdScript()` writes `<`, `>` and `&` as `\u003c`, `\u003e` and `\u0026` (the same JSON),
  and U+2028 and U+2029 likewise, so no value can close the `<script type="application/ld+json">` element or
  open a comment.
- **The prerender** (`scripts/prerender-og.mjs`) calls one hook, `withStructuredData(html,
  structuredDataFor(path))`, which writes an `<!-- BEGIN ld:managed -->` block straight after the
  `og:managed` block. The block is removed before it is written, so a re-run converges, and `--check` holds.
- **Articles and events** have no prerendered file: the Worker's record card (`services/socialCards.ts`)
  answers `/articles/<slug>` and `/events/<slug>` from the root shell. `rewriteShell` now removes the shell's
  own `ld:managed` block (the home's `Organization`) and writes the record's `Article` or `Event` in its place.
  The article read adds `published_at` and `updated_at`; the event read adds `ends_at` and `location_text`.
  Neither reads a price or the join link.
- **Help guides** are not prerendered (they are role-filtered React pages outside the sitemap). The guide page
  adds its `BreadcrumbList` with `injectJsonLd` (`lib/seo.js`) on render and removes it on leaving, which
  search engines that render JavaScript read. Prerendering the public guides would add pages with their own
  titles, which is #6996's ground, so it is left for a later issue.

### Consequences

- The root `docs/index.html` is also the single-page-application fallback, so a URL with no file of its own
  (a signed-in page, a help guide) is served the home's `Organization` block until the app boots. It states
  only facts about the firm, true on any page.
- Adding a fact (an address, a description) means recording it on the site first and reading it from there.
- The "open graph metadata" CI job builds `docs/` from source and needs no regenerated committed artifact: no
  card key or route was added, so `ogManifest.js` and the card images are unchanged.
- Tests: `frontend/test/structured_data_7004.test.mjs` (the real prerender, a help guide, escaping and gating)
  and `cloudflare-worker/test/structured_data_7004.test.ts` (the record cards over an in-memory D1).
