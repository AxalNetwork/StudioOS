### 1. Customer research: an interview only with consent

**What waits.** Each page under the picked "Interviews" source, or each row of a mapped database, waits as an `interview` proposal (D1086 §3). A sync stores no interview.

**Accept.** It takes `{ consent, interviewee, occurred_at, channel }` and checks them in this order. Each refusal writes nothing.

1. **Consent.** It must be `{ status: 'given', method, recorded_at }`, with a method from `CONSENT_METHODS` and a time not in the future (D667's `parseConsent`). Anything else is 409 `consent_not_given`. Notion is not even read.
2. **The channel.** It is one of `CHANNELS`, and `manual` by default. Anything else is 400 `invalid_channel`.
3. **The interviewee.** It is a label, and optionally a role and a company. Where the founder leaves it out, it comes from the row's mapped fields, else the page's title. An email address or a phone number anywhere, or any other field, is 400 `contact_not_accepted` (D667's `parseInterviewee`).
4. **When it took place.** The dialog's date, else the row's mapped date. It is never guessed: without one, 400 `invalid_occurred_at`.
5. **The notes.** The page is read whole, as of now, because the proposal keeps only a 2,000-character extract. A page proposal is held to what was proposed: if the page changed since, 409 `changed_in_notion` ("Sync from Notion, then import it"). An empty page is 400 `notes_empty`.

**Where it lands.** Through D667's storage step, now `storeInterview` and shared with `submitInterview`:
- the free tier's interview cap;
- the `discovery_interviews` row;
- the session, with consent `given`, its method and its time, and `submitted_via = 'notion'`;
- the notes, as the final transcript.

All of it is written, or nothing is.

**After Accept.** Structure and placements then run as for any session (D658). Nothing reaches another module until the founder accepts a placement there. The audit row holds ids and counts only.

### 2. The dialog: Import this interview

On Customer research, From Notion's Accept opens "Import this interview" (`FromNotion`'s new `acceptDialog`) instead of accepting at once.

- **The interviewee:** a label (the page's title to start from), a role and a company. The line under them reads "An email address or a phone number is not stored."
- **When:** the date it took place, and how (`manual` by default).
- **Consent:**
  - a tick: "The interviewee agreed to this interview being recorded and processed by StudioOS.";
  - then how they agreed, in the Interview Session page's four words, and when.
- **The button:** "Import interview" stays off until consent is ticked and answered, a label is given and the date is set. Beside it: "Without the interviewee’s consent, nothing from this page is stored."
- **A refusal** prints in the dialog as its own sentence, and the dialog stays open.

Every other module's Accept is unchanged: immediate, as D1086 built it.

### 3. Market intelligence: research pages as sources

**What lands.** Each page under the picked "Research" page lands as a fact through `addMarketSource`: its title, its Notion link and `kind = 'notion'`, with the founder as `added_by`.
- The text stays in Notion: no page is fetched.
- Notion's read of a tree's children carries no link, so the link is built from the page's checked id (`https://www.notion.so/<id>`).

**The ledger** (D1086) keeps one row per page:
- a re-sync updates the title, never adds a second row;
- a source the founder deletes stays deleted;
- a source typed by hand is never touched.

**From Notion** draws each source's title and link (`modules.ts` now names them for this module; a tree is still never mapped).

### 4. The engine, extended for every part

- **`Acceptor.accept` takes `deps`.** `deps.reads()` opens the founder's own Notion, but only when asked.
- **`AcceptRefused(status, code, detail)`** is an acceptor's refusal. The route answers it as `{ error, detail }` with that status, never with a page's text.
- **Parts 4–6** register their writers by importing their file in `routes/notion.ts`, as this part does.
