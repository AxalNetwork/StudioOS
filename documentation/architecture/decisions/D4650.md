## D4650 — The member's next learning action, by explainable rules (#4650, part 1)

- **Status:** built 2026-11-06 by S10 for #4650 (Learning audit 5/5). This is part 1 of the package: the next learning action. Parent #3726.
- **Migration:** none.
- **Builds on:**
  - D557 (progress and `canSeeLearning`);
  - D558 (programs and enrollment);
  - D3959 (the learning plan, `resolveSubject`, "Add to my plan");
  - D4643 (completion, by content type).

### What it replaces

- My learning used to show a "recommended" block whose copy named an internal issue dependency.
- It now shows **Next for you**: one next action with the reason it was chosen. When nothing is found, it shows an empty state that names what was checked.
- No internal issue number or dependency appears in product copy.

### The rules (`services/learningNext.ts`, `GET /api/learning/plan/next`)

The rules are tried in order, and the first one that finds something answers.

| Rule | Finds | Reason shown |
|---|---|---|
| `continue_course` | The course the member most recently worked on and has not completed, and its next required lesson that is not yet complete. | "*n* of *m* required lessons complete." |
| `program` | In the published programs the member is actively enrolled in, in program order: the first content not complete by D4643's definitions. A course or item counts as complete when completed, an exam when it has a passing attempt, an exercise when it has an accepted submission. A webinar is not offered here because it keeps its own time. | "Next in *program*." |
| `plan` | The member's next planned, upcoming item that is not done. | "In your plan for *date*." |

- **Eligibility comes first.** Every candidate is resolved through `resolveSubject`, the plan's own `canSeeLearning` check.
  - A candidate the member cannot see is skipped, never shown. This covers a draft course, or a program-only video without an enrollment.
  - So "Add to my plan" only ever offers something the plan would accept.
- **Nothing is invented.**
  - There is no model, no profile inference and no data about other members.
  - Rules on role, stage and goal wait for the signals #3724 settles.
  - Prerequisite order waits for the structured prerequisites field (part 2).
- **Read-only.** The route reads only the caller's own rows, and every statement is bound.

### Tests

`cloudflare-worker/test/learning_next_4650.test.ts` and `frontend/test/learning_stream_d3726.test.mjs`. They use synthetic members and content, and each new assertion is mutation-checked. They cover:

- the course rule, which counts required lessons only;
- the program rule, where a failed exam is still next;
- eligibility, where a draft course in progress and a program video the member may not see are skipped;
- the plan rule;
- the empty state;
- another member's rows never moving the answer;
- the card's states: ready, empty, unreadable, and loading.
