### 1. The reads

- **`GET /api/admin/approvals/decided`** (`requireAdmin`) returns every lane's decided rows, newest first, 25 a page.
  - **Filters:** `lane`, `outcome` (`approved`, `declined` or `other`), `decided_by` (an account id), `from` and `to` (days, `to` inclusive) and `page` (1 to 40).
  - **Each row** carries `lane`, `lane_label`, `item_id` and `who`. It has `outcome` with the store's own word in `outcome_word` (Approved, Declined, Sent back, Waitlisted, Paid and so on) and `decided_at`. Then come `decided_by` (`{ id, name }`, or null when the store does not record who), `wait_hours` (null when either end is not recorded), `note` and `note_shown` (true when the person the item is about is shown that note).
  - **`total`** is exact, the sum of every lane's count, or null with `total_reason` when a lane failed.
- **Each lane's line** in `lanes`:
  - a lane that records answers `{ key, label, recorded: true, since, count, caveat? }`;
  - a lane that does not answers `{ key, label, recorded: false, since: null, reason }`.

  A lane that does not record is never an empty list and never a zero. Asking for such a lane alone gives no items and `total: null`, with why.
- **`GET /api/admin/approvals/decided/weekly`** returns eight weeks, each starting Monday 00:00 UTC; the last one is marked `to_date`.
  - **Per lane:** `arrived` and `decided` counts, plus `available` and `reason`.
  - **`totals`** names the lanes each total leaves out.
  - **The tile** gives `decided_this_week` and `median_wait_hours`. It is null with a reason when a lane failed, and names the lanes that do not record in `leaves_out`.
- **Arrived** counts items, by the week they arrived, that are now waiting (read from the inbox's own board) or decided.
- **Decided** counts decisions by the week they were made. A lane that does not record has neither count: without its decided rows, its arrivals would only be the items still waiting.
- **HQ's eight lanes are a Super Admin's** (`decisionLanesFor`, D1040's `scope`). A plain Admin reads none of them, and naming one is `bad_lane`.

### 3. What a lane's own store cannot say

Each lane in the list below carries a `caveat` the page prints.
- **LP applications:** the time is the last review. A note saved after the decision moves it (D483).
- **Cohort applications:**
  - a decision made again replaces the earlier one;
  - an activated applicant keeps only its activation, so it is not listed.
- **Co-marketing pitches:** publishing replaces the approval time, so published pitches are not listed.
- **Events:** a sent-back event keeps no time, and no decider is recorded, so only approvals are listed.
- **Perk listings:** `updated_at` moves with the review, so the arrival is gone once a perk is decided. Its wait is null, and it adds no arrivals to the series.
- **Strategic access:** no decider is recorded.
- **Office-hours hosts:** a revocation replaces the approval.

Two other points:
- **Requests from studios** counts every kind, program-grant requests included, as the inbox's Support lane does. Program grants (`HQ_NOT_COUNTED_YET`) therefore have no separate decided lane: their answers are listed under Requests from studios.
- **A lane in the list that starts recording later** carries `since`. The page draws it as "decisions were not recorded before [date]".

### 4. The queries

- **Every lane's SELECT is one literal constant with the same ten columns.** It is wrapped in one literal filter, count and order (`listSql`, `countSql`) by concatenating constants, so nothing a caller sends reaches the query text.
- **Times pass through `datetime()`,** so ISO stamps and SQLite stamps compare and sort as one.
- **Paging:** page *p* reads each lane to *p* × 25 rows and merges them, so a page is exact. Pages stop at 40.
- **The series** reads each lane's decisions in the eight weeks, up to 5,000 per lane; past that the lane says so rather than undercount. Its waiting items come from the inbox's board, read once.
- **One failed lane** is its own `try`. It is named in `unreadable`; its count and the total are null, and every other lane answers.

### 5. For the owner

The six lanes that do not record would each need a decision time, and a decider, on their own store. Jobs, Wellbeing experts and Held AI runs already write one to the admin or activity log. Reading those logs would make one lane depend on another store's action names, so this part does not.

A follow-up could add the columns to each store, which needs a migration number from S21. Product testers' and program grants' "not counted yet" reasons in `approvalSources.ts` and `hqApprovalSources.ts` are now stale: migration 576 stores testers, and grant requests are stored in `hq_escalations`. Those reasons are part 3's and part 7's to change.
