### 1. What is built

All of it lives in `frontend/src/pages/testing/member/` (its README lists the files).

**PT-M1, the card** (`ProductTestingStudio.jsx`, `testerModel.js` `testerCard`), from `GET /api/testing/tester`:

| State | Pill | What it says | Its button |
|---|---|---|---|
| not applied | New | Become a Product tester. Try products before they launch… | See what testers do → Become sheet |
| applied | Waiting on Axal VC | You applied on <date>. An Axal VC admin decides, and you’re told in Inbox. | View my application → pool sheet |
| active | Active tester | You can apply to open programmes. You choose which ones. | See open programmes → focuses the list |
| paused | Paused | You won’t be picked for new programmes. Programmes you’re already in carry on. | View my place → pool sheet |
| declined | Not approved | Reason given: “<reason>” You can apply again from <date>. | none; from the date, "You can apply again now." and See what testers do |
| removed by HQ | Removed | You’re no longer in the tester pool. If you think this is wrong, open a ticket with Support. | Open a ticket → `/support` |

- A member who left the pool themselves reads "You left the tester pool. You can join again whenever you like." with See what testers do (D1336 lets them rejoin).
- **The Become sheet:** what testers do, who can apply, the consent text and its version from the read, the tick "I agree to consent version <v>.", Availability (optional), and Apply. Apply stays disabled until the tick. It sends the read's version (`joinPool`). A refusal is drawn with the Worker's sentence.
- **The pool sheet:** the status with its sentence, applied and decided dates, availability, the consent version (and that it changed, when `consent_current` is false). Leave the tester pool asks first, in place: "Leave the tester pool? You won’t be picked for new programmes. Programmes you’re already in carry on."
- **An Admin sees no card.** An Admin or Super Admin account is not read at all. An Admin viewing as a member gets 403 `admin_account` from the Worker, and the section draws nothing.

**PT-M2, Open programmes** (active testers only; nobody else is read): product, firm, what the test asks, testing dates, places left. A row opens the programme sheet:
- tiles for Run by, Testing and Places left;
- What the test asks;
- one field per question;
- D812's optional email consent with its version;
- the closing date;
- Apply, enabled once every question is answered.

A programme already applied to shows "You applied" and no Apply.

**PT-M3, My applications:** applied, picked, declined, withdrawn (by you, or "Withdrawn for you by HQ") and finished. Withdraw sits on an applied application, or a picked one whose programme has not closed, both in the row and in the sheet. It asks first with the confirm (§2), then shows "You withdrew from <programme>. <firm> has been told." The block draws for an active tester, and for anyone with an application to look back on.

**PT-M4, Inbox** (`InboxTesting.jsx`, mounted in `InboxPage.jsx`):
- a member's testing notice (applied, picked, not picked, withdrawn, programme closed; each links `/inbox` with `payload.programme_uid`) opens My application for that programme;
- HQ's tester-status notice (`product_tester_*`) opens the pool sheet;
- the firm's own notice of the same type links nothing and behaves as before;
- a notice whose application is still open carries Withdraw, which opens the sheet at its confirm.

`NotificationList` gains an optional `actionFor`, which the bell does not pass, so the row stays one rendering.

**PT-M5:**
- **States:** each read is its own block. "Reading…" with three bars while it reads. "Could not be read. That isn’t the same as having none." with Try again when it fails, which costs only that block. The empty sentences are the canvas's.
- **Phone, dark mode, consent:** below 640px each sheet is a full page (D1317), rows stack, and targets are 44px (`min-h-11`). Every class has its dark pair. No email and no other tester's name is drawn.

**Where it sits:** under each member's Studio home (founder, investor, advisor, partner, a Lab member) in `Dashboard.jsx`, and on `ExploringDashboard.jsx` (Explorers may join, D1335 §3). Admin Studio draws none.

**The Worker, one read widened:** each row of `GET /api/testing/applications/mine` (and HQ's withdraw reply) now carries `owner_name` ("Axal VC" for HQ's own programme) and `questions`, so the sheet names the firm and pairs each answer with its question. One test in `tester_pool_d1336.test.ts`.

### 2. Departures from the issue and the canvas

- **The withdraw confirm's second sentence.** The issue gives "Withdraw from <programme>? The firm is told; you can apply again while it is open." D1336 §5 records that a second application to the same programme is refused (`already_applied`, one row per member and programme, D812). So the confirm says "Withdraw from <programme>? The firm is told. You can’t apply to this programme again.", and the canvas's "Apply again" button is not drawn. **For the owner:** if a withdrawn member should be able to apply again, the Worker rule changes first, and then both the sentence and the button come back.
- **The section sits below the Studio home, not in its right column.** Each role's Studio home has its own layout. The section is a two-column grid of its own: the lists on the left, the card in a 380px column on the right, stacked on a phone.
- **Questions are free text.** A programme's questions are strings (D812). The canvas's select and chips have no schema behind them, so every question is a text field.
- **Availability** is a choice of four phrases, sent as the free text the Worker stores (at most 1,000 characters), or nothing.
- **Leave the tester pool** has no board of its own. D1335 §3 and the consent ("I can … leave the tester pool at any time") need a way to do it, so it sits in the pool sheet behind a confirm.
- **D812's email consent** is offered, unticked, on the programme sheet with its own version. The canvas does not draw it, but `apply` records it, and the firm's mail rule reads it.
