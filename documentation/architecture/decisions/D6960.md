## D6960 — Studio program requests and versioned HQ services (#6960)

A studio Administrator represents the licence linked to their account. Programs links to the existing studio program request, its history or the grant terms for that licence. HQ opens the program-filtered grants grid. An unlinked prospective operator can send a licence enquiry naming the program. Individual applications retain their own review and admission flows.

HQ approval of a studio request prepares a draft. The recorded grant, dates and applicable agreement determine operating access. When a branch uses a dated copy, the studio sees its copy date. Request history is filtered by the program before pagination and remains scoped to the requesting studio.

A package version records studio operating items and may explicitly describe a service delivered by HQ. For a new HQ service the package editor records the service description on a draft. Publishing freezes it. Older versions continue to represent their original operating items. Issuing an offer checks each local grant against the intended licence. An unavailable program blocks issuance until the commercial or operating terms are resolved. A compatible existing grant can be retained on its own recorded terms.

Offer, agreement and acceptance reads use the offered version's frozen composition. An accepted HQ service is listed with its package, description and term on the studio licence. Operating grants are written only for local items. Acceptance checks the scope of the operating policy and any required package master. Mixed bundles have no standalone-equivalent price comparison because the individual program prices do not price the HQ service. Roll out the additive package-item migration before serving the Worker changes.

### Catalogue editor integration

The delivery-term editor coexists with the D5897 catalogue draft, publish and retire actions. Catalogue writes refresh history details, so a just-published version no longer offers draft-only delivery editing. Whole-version clients that omit delivery retain stored terms through the existing service-aware readers and writes.
