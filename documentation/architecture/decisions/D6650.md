## D6650 — Classify R2 prefixes without reading or changing objects (#6650)

The inventory is source-only. The TypeScript 7 API already pinned by the root
package supplies typed AST/symbol/signature information for the main Worker
and tail consumer. Bucket names/environments come from Wrangler declarations.
The builder resolves aliases, computed/destructured methods, helper return
values and arguments, conditional keys and dominating assignments. It includes
multipart initiation, resume, parts, completion and abort as well as put/delete.
No Worker module is executed and no Cloudflare request is made.

`R2_INVENTORY.json` is the reviewed version-1 classification registry. Each
canonical bucket/prefix has record/replaceable/log class and explicit retention
and copy-approval fields. Preview aliases inherit classification only, with no
production retention promise. Original business evidence is conservatively a
record when no period is known; this is not a legal determination. Operational
periods are distinguished from legal retention bases. The runbook's seven-year
contracts/KYC requirement is recorded without endorsing its obsolete versioning
claim, which #6428 owns. Every live locked-copy approval remains `no`.

Stored keys read from D1, list results and other opaque expressions need reviewed
writer/prefix provenance. The guard fingerprints the source selector/handler;
changed provenance or an unmapped key fails closed. A reference cannot override
an independently resolved new literal prefix. Review hashes are not refreshed
automatically. This is conservative static analysis, not a live-object census;
unresolved/new flows require review rather than speculative prefix guesses.

The default command prints every current source call with binding, key expression,
file and line. `--write` regenerates the committed policy table from registry and
configuration; `--check` verifies source coverage, provenance and policy output.
Current call lines are deliberately printed on demand, so unrelated source line
shifts do not churn a shared generated document. TypeScript API upgrades may
require adapting the builder; parser/API failures are errors, never empty coverage.
The guard is part of `test:guards`.

The formation follow-up records filing packs, registry evidence, certificates and
structure memos as planned records. No physical prefix is invented before its
writer exists; new writers must classify their actual prefix. No identity-file
prefix is introduced, per #6680 decision 13 A. Existing formation/governance
proof stores are already records. Synthetic source fixtures prove that an
unclassified formation prefix fails, including when hidden behind a helper.

Only missing-bucket rows are added to INCIDENT_RESPONSE. The two contracts/KYC
rows and setup steps 4–5 remain owned by #6428. The registry matches #6665's
`classes` contract, but approves no live locking; periods/legal bases need counsel
confirmation and restores need #6654 suppression handling. Known external backup
prefixes are documented separately from the Worker mutation guard. Records in
`studioos-publications` must not be silently omitted by a files-only copier.

Validation uses synthetic source fixtures and local files only. No object key
from a real member, object contents, credentials, production write, preview
object, backup, drill, lock or lifecycle change is part of this task.
