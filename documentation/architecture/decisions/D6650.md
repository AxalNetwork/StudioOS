## D6650 — Classify R2 prefixes without reading or changing objects (#6650)

The inventory is source-only. The TypeScript 7 API already pinned by the root
package supplies typed AST/symbol/signature information for the main Worker
and tail consumer. Bucket names/environments come from Wrangler declarations.
The builder resolves aliases, computed/destructured methods, helper return
values and arguments, conditional keys and dominating assignments. It includes
multipart initiation, resume, parts, completion and abort as well as put/delete.
No Worker module is executed and no Cloudflare request is made.

`R2_INVENTORY.json` is the reviewed version-1 classification registry. Each
canonical bucket/prefix has record/replaceable/log class and explicit retention
and copy-approval fields. Preview aliases inherit classification only, with no
production retention promise. Original business evidence is conservatively a
record when no period is known; this is not a legal determination. Operational
periods are distinguished from legal retention bases. The runbook's seven-year
contracts/KYC requirement is recorded without endorsing its obsolete versioning
claim, which #6428 owns. Every live locked-copy approval remains `no`.

Stored keys read from D1, list results and other opaque expressions need reviewed
writer/prefix provenance. A reference is keyed by its site: file, enclosing
scope, operation and key expression. A site with no reference fails closed, so a
new stored-key delete, or a changed key expression, waits for a review. A
reference cannot override an independently resolved new literal prefix. A
reference whose site no longer exists is printed as a note to remove it, not a
failure: removing a site leaves no mutation unclassified. This is conservative
static analysis, not a live-object census; unresolved/new flows require review
rather than speculative prefix guesses.

The default command prints every current source call with binding, key expression,
file and line. `--write` writes the same document to
`documentation/operations/R2_INVENTORY.md`, which is generated and gitignored
(D5612); `--check` classifies every current call site against the committed
policy and fails if the document is tracked again. Nothing derived from the
Worker source is committed, so another change to an R2-touching file cannot make
the policy stale; only an unclassified prefix or an unreviewed stored-key site
fails. TypeScript API upgrades may require adapting the builder; parser/API
failures are errors, never empty coverage. The guard is part of `test:guards`.

The formation follow-up records filing packs, registry evidence, certificates and
structure memos as planned records. No physical prefix is invented before its
writer exists; new writers must classify their actual prefix. No identity-file
prefix is introduced, per #6680 decision 13 A. Existing formation/governance
proof stores are already records. Synthetic source fixtures prove that an
unclassified formation prefix fails, including when hidden behind a helper.

Only missing-bucket rows are added to INCIDENT_RESPONSE. The two contracts/KYC
rows and setup steps 4–5 remain owned by #6428. The registry matches #6665's
`classes` contract, but approves no live locking; periods/legal bases need counsel
confirmation and restores need #6654 suppression handling. Known external backup
prefixes are documented separately from the Worker mutation guard. Records in
`studioos-publications` must not be silently omitted by a files-only copier.

Validation uses synthetic source fixtures and local files only. No object key
from a real member, object contents, credentials, production write, preview
object, backup, drill, lock or lifecycle change is part of this task.

Integration with main `321c9d5eb5` preserves both the inventory guard and the
new deal-preparation reader check in `test:guards`. The new formation-step
delete uses the existing build-proof class; its owned-row selector and the
`uploadProof` writer were reviewed. Fourteen stored-key fingerprints were
re-reviewed against their unchanged selectors and named prefix writers; the
current compiler reference graph is stable across independent scans. The
inventory now covers 159 mutator sites, with 65 classes and no locked-copy
approval. No Worker call site or retention rule is changed by this integration.

The first version also committed a SHA-256 of each stored-key site's enclosing
handler and every function it called, and the rendered policy table. Both are
derived from source. In the merge queue on 2026-11-17 the hashes of 13 sites
changed after other changes edited those handlers (deck_reviewer.ts,
learning_video.ts, settings.ts and others) without changing any key, and the
candidate failed in 91 runs. The hashes and the committed table were removed;
the site key above is the review anchor. The same queue run found two real
gaps, which are now classified: `mark-request-evidence/` (D6909's investor
evidence on a mark request, a `record` with no recorded period or basis), and
the D6073 Trash purge in `dataRoomTrash.ts`, which deletes `data-room/` keys
read from `data_room_files` and `data_room_file_versions` and replaces the two
`removeDataRoomFile` deletes.
