### 1. Why

Countries must be data, not code. This change creates the empty store and the service that reads it. Nothing reads the store in production yet, and no fact is inserted here.

### 2. The tables

| Table | What it holds |
| --- | --- |
| `formation_catalogue_versions` | `version`, and `status` as one of `draft`, `in_review`, `published` or `retired`; `is_current`; who published it and when |
| `formation_sources` | a source (kind, title, `https` URL, publisher); not versioned |
| `formation_source_checks` | each check of a source: day, by whom, outcome; not versioned |
| `formation_jurisdictions` | ISO-2 `country` (upper case), optional `subdivision`, `registry_name`, `vocabulary_json`; one place per version |
| `formation_entity_forms` | `form_key` (unique per version), `label`, `offer_mode` (`orderable`, `guided`, `information_only` or `off`, default `off`), `legal_form_family`, `legacy_gate`, `legacy_display_json`, `allow_axal_collection` |
| `formation_form_facts` | `value`, `status` (`recorded`, `provisional`, `not_recorded` or `disputed`), `blocking`, `source_id`, `checked_on`, `checked_by` |
| `formation_fee_lines` | `payee`, `collected_by`, `currency`, nullable `amount_cents` (integer minor units), `timing`, source and day |
| `formation_pack_items` | `phase`, `kind`, `acting_party`, `title`, `template_key`, `counsel_required` (default 1), `position` |
| `formation_fact_schema` | the intake questions: key, label, answer kind, options, whether required |
| `formation_scenarios` | `route`, `waiver_allowed`, `conditions_json` |
| `formation_rules` | `rule_key`, `kind`, `rule_json` |
| `formation_restricted_jurisdictions` | `place`, `kind`, `source_id`, `checked_on`, `checked_by`; not versioned |

**Country codes:** `country` is plain ISO-2 text for now. A question is open on #5020 about reusing its country table.

### 3. The rules the store enforces

These are new tables, so plain CHECKs work. No existing table is rebuilt.

- **No figure without a source and a day (D4357):**
  - **Facts:** a fact is `recorded` only with a `source_id`, a `checked_on` day in `YYYY-MM-DD` form and a value.
  - **Fee lines:** a fee line with an amount carries a source and a day.
  - **No amount:** `amount_cents IS NULL` means "not recorded", never 0.
- **One current version:**
  - A partial unique index allows at most one row with `is_current = 1`.
  - A CHECK allows only a `published` version to be current.
  - A version that is published or retired names who published it and when.
- **A published version is immutable:**
  - **Its own row** may only:
    - move from `published` to `retired`;
    - gain or lose `is_current`, so the current flag can pass to a newer version;
    - record `retired_at`.
  - **What is refused:**
    - any other change to that row;
    - deleting it;
    - any `INSERT`, `UPDATE` or `DELETE` on the rows of the eight versioned tables that names a version which is not a draft or in review, or names no version at all.
- **A row belongs to its parent's version.** These must share the `version_id` of the row they hang from (a trigger refuses otherwise):
  - a form, and its jurisdiction;
  - a fact, fee line, pack item, scenario or question, and its form.
- **Restricted places** always carry a source, a day and who checked them.

### 4. The read service

`services/formationCatalogue.ts` is read only, and all of its SQL is bound.

- **`currentVersion(env)`** returns the current published version, or null.
- **`versionByNumber(env, n)`** returns a version of any status, for review and the editor.
- **`catalogueForm(env, formKey, { version? })`** returns one form of the current version (or of a version passed in). The result holds:
  - its jurisdiction;
  - its facts, each with its status and its source;
  - its fee lines, with `amount_cents` null when there is no amount;
  - its pack, in order.

  It returns null when there is no such version or form. A draft is never read as current.

### 5. Tests

**`cloudflare-worker/test/formation_catalogue_6689.test.ts` (7 cases),** on the full migrated schema (`_schema_once.mjs`):
- the tables, the index, the triggers and the defaults;
- a recorded fact without a source or a day is refused;
- a fee amount without a source or a day is refused, and an amount must be an integer;
- one current version, and only a published one; a published version refuses an edit and a delete, and its rows are frozen; retiring it and handing over "current" are allowed;
- a row must belong to its parent's version, and countries must be ISO-2 upper case;
- restricted places;
- the read service.

**Mutation checks:**
- removing the two source CHECKs turns the fact and fee cases red;
- removing the immutability triggers turns the version case red.
