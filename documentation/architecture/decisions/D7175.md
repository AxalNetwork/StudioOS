## D7175 — Research › Companies analysis: a fixed subject from setup to results, and no finding without a source, built (#7175)

The owner answered every question D7041 lists as drawn (option A; `D7041-p2.md`): a run on an unverified or missing website is allowed and labelled, and an unsupported gap or wedge line moves to Suggested research questions.
- **Parallel work:** #7176 (saved analyses: versions, manual-source origin, refresh and rerun that keep the researcher's work, export by version) changes the same files. This build adds helpers beside the existing code and leaves `persistResult`, re-run and refresh as they were; the subject rides in `inputs_json`, which both re-read.

### Worker (each ◇ item of D7041)

- **A durable subject uid on the run.** Migration `202611180051_7175_competitor_subject_and_verified_website.sql` adds `competitor_analyses.subject_uid` (nullable: a custom market has no subject; nothing is backfilled, because a market is not a company). `POST /api/competitors/analyze` takes `subject_uid`, checks it against `^[A-Za-z0-9_.:-]{1,64}$`, reads the directory row, and refuses `400 subject_uid_invalid`, `404 subject_not_found` or `503 subject_unavailable` before anything is stored. The subject's uid, name and host are also kept in `inputs_json.subject`, so a re-run and a refresh, which re-read the stored inputs, keep it out of the candidates without a change to either route. The runtime bootstrap (`competitorSchema.ts`) declares the column.
- **Self-match protection.** `isSubjectMatch` refuses a candidate whose name equals the subject's (case and spacing ignored), whose name is the subject's uid, or whose site's host equals the subject's (`www.` ignored). The run filters discovered and known candidates through it; the discovery prompt names the subject as never to be listed; `POST /:id/candidates` refuses the subject with `400 subject_not_candidate`. The run records the subject in `output_json.excluded`.
- **A verified website status on the directory record.** The same migration adds `research_company_directory.website_verified_at`. `GET /api/research/company-directory/:uid` returns it and `website_status` (`not_recorded`, `not_verified`, `verified`). Nothing writes it in this build, so every website reads Not verified (see the owner's question below).
- **Claim-to-source references in `output_json`.** The landscape prompt lists the fetched sources numbered from 1 (inside the untrusted block, D1506) and asks for `findings: [{ text, kind: fact | interpretation, sources: number[] }]`. `normalizeOutput` keeps only numbers that name a fetched source and stores their ids as `findings[].source_ids`; a finding left with none is stored with `[]`, which the page reads "No source in this run".
- **No fallback findings.** `normalizeOutput` no longer writes the three fixed gaps, the template wedge or the three fixed next actions. A gap or wedge the model gives with no fetched source moves to `next_actions` as "What source would confirm this: “…”?" (the owner's answer A). With 0 fetched sources the output states no summary, gaps, wedge, classifications, findings or signals, and every model statement is a question. With no candidates no competitor is named anywhere in the output.
- **Failed reads are recorded.** A crawl now records a failed read of a company's homepage, and of any page that timed out, was refused or rate-limited, or answered 5xx, in `competitor_sources` with its status (0 for no answer). A guessed path that 404s is not a failed read. This is what lets the page tell "No candidates" from "Sources unavailable".
- **An evidence status in the list payload and the export.** `evidenceOf` derives it on every read from the stored rows, so a source added by hand moves it: `insufficient` (0 fetched sources: 0 and 0 per D7041, or candidates with nothing read and nothing tried), `no_candidates` (sources read, no company listed), `unavailable` (candidates, and every read tried failed), `supported` (every finding cites a fetched source and no read failed), `partial` (anything else, including a run that stored no cited findings, as every run before this one did). `GET /:id`, `GET /` (with `subject_name`, read from the directory; a failed directory read leaves it null and says `subject_names: 'unreadable'`) and the JSON export carry it; it is null for a run that is not complete. The Markdown export adds the Subject and Evidence lines, Findings with `[n]` citations, Interpretation, the excluded subject, "Suggested research questions (not findings)" in place of "Recommended next actions", and the numbered Sources.

### Frontend (D7041 § Frontend only)

- **Profile entry (RS-13 A1).** `analysisHref` sends `?tab=analyses&company=<uid>&name=<name>`, never the website; `buildCompetitorsRedirect` keeps `company` and `name`.
- **Setup (A2–A5).** `CompetitorAnalysis` reads the subject's directory record (`AnalysisSubject.jsx`) and draws the subject card in its states: website with Not verified, no website Not recorded, Loading, Unavailable with Retry, and Not found. The market starts from the sector label (or the name) only into an empty field. The website is never written into Known competitors. Market question, the optional startup and Known competitors are separate groups; Problem and nudge sit under More context. The startup list arriving chooses nothing and switches no mode; a chosen startup offers Fill empty fields, which never overwrites a typed field. Known competitors refuses the subject's name, uid or site and holds Run until it is removed. A 403 reads Refused with Run without a startup; `market_required` sits under the field. While the run is pending the subject bar stays and the status is `role="status"`. A run from Saved analyses says Subject None · custom market. The Saved analyses list has Subject and Evidence columns. The run button reads "Run competitor analysis", and sticks to the bottom of a phone screen.
- **Results (B1–B5).** `CompanyAnalysis` draws the subject bar and the evidence chip under the title; the Partial bar with the failed URLs and "Retry the N reads" (Refresh sources); Findings with their source numbers, "Run statement · No source in this run" for one with none, and Interpretation kept apart; Suggested research questions in a dashed block (the run's `next_actions`, editable as before); the excluded subject; each competitor's source chips (numbered when read, Unavailable with the status when not), "unconfirmed" when none was read, and Not attempted · no website; Insufficient evidence with Add a source (focuses the add form) and Revise the search (setup with the subject and inputs kept), and no summary, gaps or wedge; No candidates; Sources unavailable with Retry; and a Markdown preview before the download. Below 1024px the competitor table is a list of cards with 44px controls.
