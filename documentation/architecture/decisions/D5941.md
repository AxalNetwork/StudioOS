## D5941 — Pipeline state coverage and refresh feedback (#5941)

The four editing zones use the same read/write loop. First reads show a
skeleton, failed reads show an unavailable state with Retry, and confirmed
empty reads show each zone's own empty message. A background refresh now says
Refreshing while keeping rows and editors mounted. A failed background refresh
says Unreadable refresh and identifies the displayed rows as the last successful
read. Retry continues to identify the previous read while requesting fresh data. Failed
writes retain the draft; an editor closes only after an accepted write.

The Lead setup notice uses the command centre's existing firm-coverage rules.
A colleague's empty catalogue cannot override lead-scoring evidence of firm
services. The catalogue read is keyed to the active company. Unknown firm
coverage is explicit. No leads and no active fit rules are separate states.

The zone readers provide no read-only capability flag today. A user without
a partner profile sees the existing profile notice, and Worker authorization
continues to refuse disallowed writes with the draft retained. A separately
entitled read-only collaborator state requires a server capability contract.
These zones have no realtime connection status to render; #4701 provides
list reconciliation rather than a socket status. Eadwyn and token refusals
belong to the shared rail and the lead-draft action's existing AI execution
feedback. No synthetic connection, capability or token state is introduced
by PP09.
