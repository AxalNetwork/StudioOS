## D1442 — The Ask panel's Worker part: the quote before Send, support and Explorer refusals, proposals by page and run

- **Status:** Built by the S14 session (#3991, part of #3706; 2026-11-01). Migration **694**, reserved by S1's spec on #3706.
- **Builds on:** D652 (`/api/eadwyn` conversations), D897 (`quoteRun`: the hold before a run), D780 (`ai_rail_proposals`), D765 (rail context on every run) and D1443 (the panel, S21's lane), whose `askPanelAdapter.js` turns `quote` and `waiting` on from these routes.

### Why

The Ask panel's screens go through `frontend/src/ui/askPanelAdapter.js`. Two of its methods are off because the Worker did not answer:
- `quote`: the cost line before Send ("Holds up to $X · you pay what it uses");
- `waiting`: the "N waiting" count on Ask.

Also, `POST /api/eadwyn/conversations/:uid/ask` ran without a support-session or Explorer refusal. The panel's rule AK13 needs those on the server too.

### What was decided

1. **`POST /api/eadwyn/conversations/:uid/quote`** (`routes/eadwyn.ts`).
   - **Gate:** `requireAuth` and the caller's own conversation; any other uid answers 404.
   - **Body:** `{ question ≤ 2000, page?, model?, file? }`.
   - **Answer:** `{ ai: true, hold_microusd, model, model_label }`. When the run itself would be refused (the page's switch, the budget, the model), it answers `{ ai: false, reason, message }` in `runRefusalView`'s words.
   - **Refusals:** 400 `question_required`; 403 `support_session_refused` or `no_profile`; 409 `company_changed`.
   - **It reads the switched-on connectors**, exactly as the run does, because their facts are part of what the run sends and so of what it holds. Each connector is capped at 20 facts of 300 characters.
   - **It runs, holds and writes nothing:** no `ai_usage_logs` row, no message, and no model or guard call.
2. **One builder.**
   - `askInputs` reads the question, model, page, file, connectors and earlier turns.
   - `askRunOptions` turns them into the `RunOptions`.
   - The quote passes them to `quoteRun`, and the ask passes them to `run()`. That makes the hold shown before Send the hold the run places.
   - The ask's call names `task` and `rail` from the built options, which keeps D765's static listing (`rail_run_path_d765`) reading them at the call.
3. **Refusals before anything runs** (`askRefusal`, on create, quote and ask, checked before the conversation or connectors are read):
   - an impersonated token (`impersonated_by`) gets 403 `support_session_refused`, as `rail_run.ts` refuses it;
   - an Explorer (`role = 'exploring'`) gets 403 `no_profile`, in `rail_run.ts`'s words ("Ask opens once you hold a venture or a profile.").
4. **`GET /api/ai/rail/proposals`** filters.
   - It takes `page=<rail page key>` as an alternative to `option`. At least one is required, otherwise 400 `option_or_page_required`, so the route never lists every row a member has.
   - An optional `run=<usage_log_id>` narrows to one run's rows; a value that is not a positive integer is 400 `invalid_run`.
   - In `listRail`, each filter is a bound `? IS NULL OR column = ?` pair. `user_id` is always bound, and the cap stays at 50.
   - Existing callers that pass `option` read what they read before.
5. **Migration 694** (`694_ai_rail_proposals_page_index.sql`) is additive and idempotent: `idx_ai_rail_proposals_user_page ON ai_rail_proposals (user_id, rail_page, status, id DESC)`.
   - It is numbered below main's newest migration because S1 reserved the number.
   - `scripts/migrate-d1.mjs` applies pending files by name from its ledger, so the order does not hold it back.
6. **Clients.**
   - `eadwynApi.quote(uid, { question, model, page, file })` in `frontend/src/lib/api/eadwyn.js`.
   - `railProposalsApi.list({ option, page, record, status, run })` in `railProposals.js`. A page alone sends no empty `option`.
7. **The seam is turned on (#3991 step 6).** D1443's first PR reached main while this was in review, so the swap rides this change.
   - In `frontend/src/ui/askPanelAdapter.js`, only `quote`'s and `waiting`'s bodies changed. `ASK_OFF_METHODS` is now empty.
   - `quote(uid, question, page)` sends nothing without a conversation and a question. An `{ ai: false }` answer, or a failed read, is off with its reason, never a hold.
   - `waiting(page)` counts the member's `proposed` rows on the rail's page. A failed read is off, never "0 waiting".
   - `PageAsk` (`ui/AskButton.jsx`) draws that count on Ask, and reads it again each time the panel closes. The server's 50-row cap bounds it.
   - `AskPanel.jsx` asks for the quote 400 ms after typing stops (`QUOTE_PAUSE_MS`), because a quote reads the switched-on connectors as the run will.

### Tests

`cloudflare-worker/test/ask_quote_d1442.test.ts` (7 tests) covers:
- the quote returns a hold, writes no usage row and stores no message, with no model or guard call;
- quote and ask share one builder: one `systemPrompt`, and an attached file raises the hold;
- an impersonated token gets 403 on create, quote and ask, before any hold or run;
- an Explorer gets 403 `no_profile`;
- another member's uid gets 404;
- `page=` lists only the caller's rows on that page, `run=` narrows to one run, neither filter gives 400, and the cap is 50;
- migration 694 applies twice and is an index only.

`frontend/test/ask_panel_d1443.test.mjs`'s seam test now pins the swap:
- no request is sent without a conversation and a question;
- a refused or failed quote is off;
- the count comes from `page=` with `status=proposed`, and a failed count is off;
- `PageAsk` passes the count, and the panel quotes after the pause.

Eleven mutations were each red when applied:
- the quote calling `run()`;
- the quote priced on the question alone;
- the impersonation check removed;
- the Explorer check removed;
- create left unrefused;
- the quote's conversation read without `user_id`;
- the page filter dropped;
- the run filter dropped;
- `user_id` unbound;
- the limit raised;
- the 400 removed.
