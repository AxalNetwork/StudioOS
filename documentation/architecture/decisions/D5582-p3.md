## D5582 part 3 — Preview drafting routes and counsel clause reservations (#5582)

The new router mounts at `/api/admin/workgraph/drafting`. It requires an HQ
preview deployment, `WORK_GRAPH_DRAFTING=preview`, and a Super Admin. Every
POST also requires a TOTP session with a recent step-up. No configuration
switch is enabled by this change.

The route accepts an existing WorkGraph asset with a head under
`human_publication`. Its company must be the caller’s verified selected company.
The tenant, project, kind, base digest and source are read from the asset and
head revision. The HTTP caller cannot override those values or impersonate an
agent. Creating and initially adopting an asset remains the internal registry’s
operation. This route exposes existing assets for preview evaluation.

- GET `/:assetUid` reads the current canonical domain row and its structured
  units. A newer domain save makes that WorkGraph head stale.
- POST `/:assetUid/candidates` takes two raw drafts, the expected head and
  bounded contributor references. The server derives units, sensitivity and
  merge permissions again, then calls the existing merge and draft writers.
  Conflicting units return the reviewable plan. Deck proposal insertion atomically
  checks that no proposal is waiting and that the expected head still holds, so
  concurrent callers cannot create two competing proposals. Decks write proposals, templates
  write research drafts, and offer plans return without writing a quote version.
- POST `/:assetUid/confirm-publication` reads a current saved version of the
  same deck, template or quote. It confirms only the digest the person supplies
  after review. For templates it also requires the matching stored publication.
  A stale digest cannot advance the WorkGraph head. Retries reuse the recorded
  revision’s approval timestamp, so a delayed retry has the same idempotency hash. Domain publication continues
  through Keep, template publication and partner quote saving.
- POST `/:assetUid/clauses/:clauseId/lease` acquires, renews or releases a counsel
  reservation through D5581’s existing lease service. With leases enabled,
  template candidate changes require a live fence for every affected clause,
  including removals. Publication confirmation requires fences for all included
  clauses. Counsel membership is read from `counsel_members`.

Canonical deck reads use the hydrated deck reader. Project ownership is checked
against the verified company. Quote versions must belong to the same quote and
company. Template versions come from the existing master library. Signed
agreements and envelopes have no drafting adapter here.

Revision and head events retain their actor, exact digest, contributor recipe
and D1 cost counters. Lease calls retain their audit and storage/DO counters.
No model or export job runs from these endpoints. Disabling the drafting flag
removes their entry point while preserving domain drafts, version history and
WorkGraph events.

The route tests cover default-off and production refusals, the Super Admin write
bar, an unverified company, foreign source records, separate slide changes,
conflicts, stale heads and approval digests, read-back publication, offer plans,
counsel membership and clause fences.

This PR is part of #5582. Automatic invocation of confirmation from each domain
screen, initial asset registration/adoption over HTTP and the frozen-export UI
remain separate work. There is no approved WorkGraph drafting screen in this
issue. Existing services and D5585’s frozen release manifests remain available
for that integration.
