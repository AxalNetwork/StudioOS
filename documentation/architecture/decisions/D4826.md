## D4826 — The Thinking shelf's states, mapped to the column and held there (#4826)

#4826 asks for canonical editorial states on Thinking instead of "Draft" for
everything unpublished, each with accurate audience copy and one clear next
action. **D4681 already built that**, and
`frontend/test/expertise_workflows_4681.test.mjs` pins it: eight states, each
with its label, who can read the piece, and a next step on a real route, plus
History from `article_revisions`. This decision records the mapping S1 asked
for first, holds it with a test, and fixes the three places where the stored
value still leaked past that work.

### The mapping: the canvas's eight states against what the Worker records

`articles.status` is written by two routers, and these are all of the values
they write:

| Canvas state | Stored as | Written by |
| --- | --- | --- |
| Draft | `draft` | `routes/articles.ts` — a new piece, and Withdraw |
| Submitted | `submitted` | `routes/articles.ts` — Submit for review |
| In review | `in_review` | `routes/admin_articles.ts` |
| Changes requested | `changes_requested` | `routes/admin_articles.ts` |
| Approved | `approved` | `routes/admin_articles.ts`, and what unfeaturing a published piece returns it to |
| **Scheduled** | **derived: `approved` with a `publish_at`** | the time is set by `routes/admin_articles.ts`; migration 346 (D484) holds the column |
| Published | `published` | both routers |
| Rejected | `rejected` | `routes/admin_articles.ts` |

**Seven of the eight are column values. Scheduled is the one departure**, and
it is a derivation from a store rather than an invention in the client:
`approved` with a `publish_at` that the per-minute cron publishes at (D484).
The Worker derives it the same way on the admin side — `articleQueue.ts` has
`CASE WHEN status = 'approved' AND publish_at IS NOT NULL THEN 'scheduled'` —
so the shelf and the editorial queue agree, and the advisor's own read
(`GET /api/advisors/me/thinking`) already selects `publish_at`, which is what
makes the state visible at all. **No canvas state is without a store**, so
nothing here is recorded as unbuilt.

One wording departure, which is D4681's and is kept: the canvas's **Rejected**
reads **"Not accepted"** on the shelf, because the shelf speaks to the writer
whose piece it is.

### What held the mapping open, and now does not

Nothing tied the states to the column. A status added to either router would
have fallen through `articleStage`'s `unknown` fallback — quietly, on a
founder's own shelf, and the fallback drew the raw column value as its label.
`expertise_states_4826.test.mjs` now reads both routers and asserts the
statuses they write are **exactly** `ARTICLE_STATUSES`, in both directions, so
a new status fails the build instead.

### Three places the stored value still leaked

- **The export.** The zone's Export carried `a.status`, so the one artefact a
  writer takes away named six states in the store's language
  (`changes_requested`, `in_review`). It carries `articleStateLabel(a)` now —
  the same words as the row's pill, Scheduled included.
- **The unknown fallback.** Its label was `String(a?.status)`, so an
  unrecognised status was shown to a founder as a column value. The state is
  **"Not recorded"**, and the stored value is named in the audience line
  (`Its state is recorded as “archived”, which this page has no words for
  yet.`), where it reads as the record it is. There is still one next step.
- **A false note.** `advisorZoneFilters.js` said "`articles.status` is draft or
  published". It is seven values, and has been since well before D4681 gave
  the shelf a pill per state.

### The two chips stay the canvas's

The filter chips are `All · Published · Drafts · Essays`, which is AX4's own
axis on `design/canvases/integrated/Pages · Advisor Expertise.dc.html`
(`filters: fil(['All','Published','Drafts','Essays'], 0)`), and the zone filter
table is held to the canvas verbatim by `profile_zone_filters.test.mjs`. So
**Drafts stays the coarse "not public yet" narrowing the canvas asks for** —
it is a filter bucket, not a state label, and inside it every row still names
its own state, the shelf's tile reads "Not public yet", and the export names
the state. Re-cutting the chips one-per-state is the Expertise V2 canvas's
call (EX-11, #4823), whose export is not on `main` yet; this decision does not
pre-empt it.

Accessibility is not by colour alone, and was not: `Pill` draws `stage.label`,
so every state is a word as well as a tone, and the row carries `data-stage`.

### The phone

The shelf row was one `flex … justify-between`, so a long title squeezed the
state pill and the figures. It stacks below `sm` and the figures read from the
start when it does; from `sm` up it is exactly as it was.

### Tests

`frontend/test/expertise_states_4826.test.mjs`, five tests: the router
equality above; the eight canvas states drawn, with Scheduled shown to be
derived from the column, the migration and the advisor read; the unknown
fallback; the export's words; and the phone row. Mutation-checked: 9 mutants
(a status dropped from the list, one added that no router writes, `scheduled`
added as a column value, the `scheduled` stage removed, `stageKey` ignoring
`publish_at`, the fallback label back to the column value, the export cell back
to `a.status`, the row layout back) — all 9 caught, 0 survived.

No Worker change, no store, no migration, no route: every state this draws was
already recorded.
