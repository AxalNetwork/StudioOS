### What is decided

- **One more block, same response.** `GET /api/admin/ai-agents/skills` returns `published_evaluation` next to `coverage`. It is computed from three reads: the published HQ skills at their current version with their live cases, the published history, and the latest campaign. The count stays fixed whatever the catalogue's size or the page. Like `coverage`, the block is the whole catalogue's on a `?page=` read.
- **The published history only.** Every figure reads `agent_skill_version_evals`. The draft history (`agent_skill_eval_results`, keyed by draft and evidence hash) is not read by these queries, so no number blends the two. Draft quality stays `skills[].golden`.
- **The current version of a published skill.** A retired or draft skill has no current version to measure and is not in the block. Its rows stay history, readable on `GET /:uid/evals/compare`.
- **One result per unit.** A unit is a version, a case key and a model. The latest row counts, by `run_at` and then `id`, which is the order `latestPerPair` uses. Running a case again replaces its result; it never adds a second one.
- **Expected units come from what a run takes.** The cases are `casesOf`'s: the starter case unless a live case carries its text, plus each live case. The models are the version's release manifest (`evidence_json.models.required`), else the skill's declared set, else the default set. A unit with no row is **missing**. A version with no row at all is **not evaluated**: it is counted under `versions.unevaluated`, and its results read `{ available: false }`, never 0 of 0. A zero over rows that exist is an observed 0.
- **Regressions use the compare rule.** `pairOutcome` and `compareResults` from `skillEvalCompare.ts` decide them. A pass that turned fail counts only on the same case text, model and evaluator; anything else is counted under its own not-comparable outcome. There are two baselines:
  - the newest earlier run on the same version that ran, which is the board's alert rule;
  - the previous published version's latest rows.

  Time to resolve a regression stays `{ available: false }`: no row links a regression to the version that fixed it.
- **Campaign coverage is #4668's progress.** It reads the latest campaign's manifest: done, skipped and pending, plus the published skills whose current version that campaign did not finish. `full_coverage` is true only when the campaign completed and finished every published skill's current version. A batch, a running campaign or a version published since the campaign started is never full coverage.
- **Unreadable is said.** If the history cannot be read, the block is `{ available: false, reason }`. If the campaign tables cannot be read, `campaign` is. Neither is served as zeros.
- **#3851 is not read.** No query names a proposal table. The test checks every SQL text the read prepares.
