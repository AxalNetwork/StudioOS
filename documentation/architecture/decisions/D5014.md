### What it is

Pricing is a **recommendation layer**. Nothing in this schema is a licence term. Four tables hold it:

| Table | Holds | Changes |
|---|---|---|
| `country_market_profiles` | One current profile per ISO 3166-1 alpha-2 country: population, PPP GDP per capita, startup-ecosystem score and rank. Each value has its own status, source, reference and as-of date. It also holds a regulatory class and notes. | Edited in place, with `revision` and `updated_by`. |
| `pricing_models` | Versioned model definitions: reference fees, royalty, minimum-royalty ratio, the three weights, the rounding increment, and JSON for normalization, regulatory surcharges and tiers. | A draft may be edited. An active or retired model is frozen. |
| `country_pricing_snapshots` | The inputs, factors, index, tier, recommended figures, trace and source digest that one recommendation used. | Append-only. |
| `licence_pricing_decisions` | What HQ accepted or overrode for a licence, against which snapshot. | Append-only. |

### The decisions

1. **Integers everywhere, enforced by the schema.** The issue sketched `NUMERIC` for PPP and the startup score.
   - Every figure is an integer instead:
     - PPP is whole international dollars.
     - The startup score is thousandths of a point.
     - Money is minor units.
     - Rates are basis points.
     - Factors and the index are millionths (1.0 = 1000000).
   - `CHECK (typeof(x) = 'integer')` means SQLite's loose typing cannot persist a float in any of these columns. A float is refused by the schema, not just avoided by code.
2. **Unknown is NULL with a status, never 0.**
   - Each external value has `*_status` (`recorded | provisional | not_recorded`), defaulting to `not_recorded`.
   - A status of `recorded` or `provisional` with a NULL value is refused, so an unknown cannot pass for a fact.
   - The issue named only `startup_score_status`. Population and PPP have one too, so every input says the same thing about itself.
3. **An active model is immutable, in the database.**
   - `trg_pricing_models_frozen` refuses any change to a non-draft model's calculation fields, any return from active to draft, and any move out of retired.
   - `trg_pricing_models_no_delete` keeps every non-draft model.
   - The routes refuse first with `409 pricing_model_immutable`, and a conditional `UPDATE … WHERE status = 'draft'` is a second layer. The trigger is the guarantee for any other writer.
4. **One active model, switched atomically.**
   - A partial unique index allows one `active` row.
   - Activation is one batch: retire the current active model, then activate the draft. The retire runs only if the draft is still a draft, so a lost race never leaves the platform with no active model.
5. **History never changes.**
   - Snapshots and decisions refuse `UPDATE` and `DELETE` by trigger.
   - A decision references its snapshot, and a snapshot references its model by uid and copies the version. A later country-data or model change makes new rows and leaves these alone.
   - An `overridden` decision must carry a non-blank reason (a `CHECK`).
6. **Snapshots hold the inputs that produced the recommendation.**
   - A snapshot copies the profile values, their statuses, sources and as-of dates, and `profile_revision`.
   - It does not reference the live profile. The live profile changes; the snapshot is evidence of what was used.

### API

All routes are Super Admin and HQ only. Writes use the existing write bar (a TOTP session with a recent step-up). Every write is audited through `logAdminAction` with its actor and, for lifecycle moves, its reason. `/api/admin/licence-pricing` joins `/api/admin/licences` in the recovery cool-off prefixes.

| Method and path | What it does |
|---|---|
| `GET /api/admin/licence-pricing/models` | Lists models: active first, then drafts, then retired. |
| `GET /api/admin/licence-pricing/models/:uid` | Reads one model. |
| `POST /api/admin/licence-pricing/models` | Creates a draft (write bar). |
| `PUT /api/admin/licence-pricing/models/:uid` | Edits a draft (write bar). |
| `POST /api/admin/licence-pricing/models/:uid/activate` | Activates a draft (write bar, reason). |
| `POST /api/admin/licence-pricing/models/:uid/retire` | Retires the active model (write bar, reason). |
| `DELETE /api/admin/licence-pricing/models/:uid` | Deletes a draft, only if no snapshot used it (write bar, reason). |
| `GET /api/admin/licence-pricing/countries` | Lists profiles; `?q=` matches code or name, and `?incomplete=1` keeps those with any input not recorded. |
| `GET /api/admin/licence-pricing/countries/:code` | Reads a profile and its latest snapshots. |
| `GET /api/admin/licences/:uid/pricing-decisions` | Lists a licence's decisions, each with its snapshot's model version, country and digest. It is mounted ahead of the licence ledger's `/:uid` catch-all. |

A model body is validated whole and the problems are returned per field:
- The weights must sum to exactly 10000 basis points; the database's `CHECK` enforces this too.
- Money must be non-negative integer minor units.
- `effective_from` must be a date.
- `fee_rounding_cents` defaults to 250000 (EUR 2,500).

### Not in this decision

- The pricing formula (#5015).
- The 49-market seed and the profile maintenance endpoints (#5016).
- Accepting or overriding a recommendation into licence terms (#5017). That will still go through the revision-safe licence terms write; `licence_pricing_decisions` only records it.

### Tests

`cloudflare-worker/test/licence_pricing_schema_5014.test.ts` runs the real router over every migration and checks that:
- applying the migration twice changes no licence, invoice or grant row, and outside its triggers it only creates;
- the route and the database both refuse edits to an active model, a return to draft and deletion;
- activating a second version retires the first;
- the database refuses a weight sum other than 10000, a second active model, and float money or a float index;
- snapshots and decisions are append-only, and an override without a reason is refused;
- not-recorded values read as `null`, and a status that claims a missing value is refused;
- decisions read together with their snapshot;
- a plain admin is refused, and a password session cannot write.

Mutation checks:
- Removing the frozen trigger fails the immutability test.
- Removing the integer check on fees fails the float test.
