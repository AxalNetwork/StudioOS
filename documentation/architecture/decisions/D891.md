## D891 — Raise figures cite stored evidence and actual room access

#2447 separates a stated figure from a measured one. Narrative checks respect
each version's stored Check against selection. A deck remains unexamined until
it binds a narrative version (#2434); project fields never stand in for it.
Stripe snapshots outrank typed snapshots. Verified revenue for the last complete
UTC month and Mercury revenue credits keep their own labels and are never presented as MRR.

Typed traction is `stated`. Only verified revenue ledger entries in the last
complete UTC month make its computed evidence `measured`. Migration 536 rebuilds `readiness_scores` with the
additional evidence value, preserves history and actors, and relabels historical
computed traction without claiming a later receipt verified an earlier score.
Other readiness scoring policy belongs to #2448/D890.

Room coverage and demo-day readiness require a file at least one active account
with an unexpired grant can download, using the same file tier, expiry,
commitment and project NDA rules as the download gate. Downloads alone feed
file activity counts; blocked attempts and room opens do not become downloads.
The founder matrix also applies file and grant expiry. Failed reads remain
Unreadable. A URL or milestone does not prove room readiness. An absent legacy deck payload
stays Pending; an explicit failed read is Unreadable.

Both the Raise overview figure and meter show signed or received money against
the target, with
soft, signed-awaiting-receipt and received amounts separately labelled. Legacy
amounts without a status remain explicit and unclassified, never inferred firm. Unrecorded amounts stay missing. Runway
prefers recorded Mercury cash and net burn from an active connection whose owner
still belongs to the venture, naming that source; typed snapshots remain stated.

An update save retains a source only when its key, unit, value, date and source
match the server's stored period facts. The server revalidates unchanged metrics
too; an unmatched numeric figure is typed. Landing-by-project saves record the
same accepted/edited composition fills as page saves. Fill details keep citation
and run cost without displaying the model name.

The deploy runs pending D1 migrations before shipping the Worker. Its ledger is
keyed by filename and checksum, so an unapplied 536 is applied even when 544 is
already recorded; the S1-assigned number is retained.
