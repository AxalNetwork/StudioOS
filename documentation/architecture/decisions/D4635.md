## D4635 — Deals: one accepted weighting, read states kept apart, Studio scorecards from the scoring read (#4635)

Package 5 of 5 of the Deals follow-up. Frontend only, using reads that already exist. No Worker change, no migration. Stacked on #4634 (package 4), which shares `DealFlow.jsx` and `flowModel.js`.

**What was wrong, checked against current `main`.**
- **Weighting.** The control saved the weighting and re-read it for itself, but the deal list sorted by a separate read the save never touched, so the order changed only on a refresh. A weighting read that failed sorted by equal weights without saying so.
- **Compare, deal flow.** A failed deal-flow read was replaced by an empty flow, so every venture read "Not on your deals".
- **Compare, fit and scores.** A fit failure was silent, and neither failure had a retry.
- **Compare, notes.** The saved-note read's `unreadable` count was dropped, so `{ items: [], unreadable: 1 }` looked like no notes.
- **Studio.** The Studio table showed a fixed "not yet" in every Scorecard cell.
- **Thesis.** A Fit cell with no thesis linked to `/account`, while the empty state's "Set your thesis" opened the My thesis card.

**What changed.**
- **One accepted weighting.** `WeightingControl` takes `onSaved`. Deal flow passes its own weights read's retry, so a successful save re-reads the weighting the sort uses and the order follows at once.
  - Closing the dialog, or a save that fails, changes nothing, so the prior order stands.
  - When the order is by weighting and the weighting cannot be read, the page says so, with Try again.
- **Read states kept apart in Compare.**
  - A failed flow read is named with its own retry. Stage reads "Stage unreadable" in the cards and "Unreadable" in the table, never "Not on your deals". The ventures, scores and fit that were read stay usable.
  - A failed fit read has its own line, and fit and scores share one retry that re-reads both.
- **Notes.** "One saved note could not be read" (or "n saved notes") appears with Try again, and the notes that were read stay listed. A save keeps the count.
- **Studio scorecards.** The lens reads the supported `POST /api/venture-scores/batch` for its rounds. The one shared `ScorecardCell` draws the strip, locked, Not shared, Unreadable or Reading…. Score reads keep the Worker's own sharing rules (D1256), which package 1 (#4631) does not change.
- **One thesis destination.** `THESIS_PATH` (`/account/security-privacy`, the My thesis card) is used by the Fit cell and by the empty state's primary.
