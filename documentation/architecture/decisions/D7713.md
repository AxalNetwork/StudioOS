## D7713 — Group Research company placements and page the member records (#7713)

Markets and Geographies list counts use the first crosswalk target. A market page includes every company with that market among its targets. A country page uses the first country target. A tracked sector includes a company once when any target market belongs to it. The sector's sub-market breakdown still counts each matching market individually. The fund, signal, evidence and period reads retain their existing rules.

D1 groups the raw sector and country columns using the new composite index. The Worker maps each distinct sector and country spelling once per request. NULL and the empty string share a crosswalk key while their raw values remain available for the existing displayed labels. Country detail also requests the newest directory date per group. Sum of the group counts and maximum group date give its directory-wide totals.

For detail pages, the Worker binds the matching raw pairs as one JSON array. SQLite probes both columns with NULL-safe equality. The member query returns the UID, the name, the group ordinal and, for country detail only, the headcount. The group ordinal preserves breakdown order when two labels have equal counts and compare equal under locale collation. Keys arrive in rowid order, preserving the old table scan's stable ordering of tied companies. Market/country names use English base sensitivity, while the sector page uses the default locale comparator. The Worker binds at most 50 sorted UIDs and receives the page in that order.

### Measured transfer

Local Node 22.23.3 SQLite, fixed clock, 5,040 synthetic companies, 63 distinct raw pairs, four markets, one fund and one signal with evidence. The same authenticated requests ran against the parent route source and the new handlers. Statement/row counts include all successful reads, including account lookups. The final column gives company-directory rows alone in execution order. A page's middle term counts narrow member keys.

| Route | All statements before → after | All rows returned before → after | Directory rows before → after |
| --- | ---: | ---: | --- |
| Markets list, including its separate `limit=1` request | 9 → 9 | 5,140 → 163 | 5,040 → 63 |
| Market `fintech` | 11 → 13 | 5,123 → 3,556 | 5,040 → 63 + 3,360 + 50 |
| Geographies list (`with_data=0&limit=100`) | 7 → 7 | 5,120 → 143 | 5,040 → 63 |
| Geography `GB` | 9 → 11 | 5,060 → 1,573 | 5,040 → 63 + 1,440 + 50 |
| Sectors list | 10 → 10 | 5,206 → 229 | 5,040 → 63 |
| Sector `fintech-defi` | 11 → 13 | 5,207 → 3,640 | 5,040 → 63 + 3,360 + 50 |

The lists issue one company-directory statement. Each nonempty detail issues three. An empty detail can return after the grouped read. EXPLAIN shows a covering composite-index scan for the undated counts, an index scan for counts with newest dates, composite-index searches for matching keys, and a unique UID index search for the page.

The grouped counts still scan the index entries for the whole directory. D1 rows read on list requests therefore stay near the directory size even when the Worker receives only 63 groups. These fixture measurements establish transfer sizes. Production distribution, latency and D1 billing were not measured. A detail still transfers a key per matching company, which can approach the directory size for a broad target. An aggregate maintained on writes is unnecessary for the transfer reduction demonstrated here. Revisit it if measured list traffic and D1 scan cost justify maintaining counts across directory edits and taxonomy changes.
