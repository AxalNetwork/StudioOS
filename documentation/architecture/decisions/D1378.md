## D1378 — Saving a call answers before Eadwyn AI's container starts

- **Status:** a fix, found live on 2026-10-29 by the owner. Built by S21.
- **Builds on:**
  - D1360: Eadwyn AI joins by default;
  - D1372: Start on a Meet link answers in seconds;
  - #3650: the bot's cold start may take up to 25 s.
- **Migration:** none.

### What happened

After D1372 the owner pressed Start Call on a Google Meet call. After 30 s the dialog again said "The server did not respond within 30s".

This time the Calendar lookup succeeded, and the Worker opened the call's session (session 36). D1360 then sends Eadwyn AI from inside the same request. `dispatchBot` waits for the run's `/init`, and `/init` starts the bot's container inline. Since #3650 that start may take up to 25 s on a cold start.

The Calendar reads and the container start together passed the dialog's 30 s. The dialog then deleted the interview it had made, and the session went with it.

### What changed

- **`dispatchBot` takes an optional `defer`** (`services/meetingBots.ts`). With it, the run is checked, charged against the budget and queued as before. Its start is handed to `defer` instead of being awaited, and the queued row is returned.
- **Saving a call for import passes `waitUntil`** (`sendBotByDefault` in `routes/founder_validate_meetings.ts`). This covers both the Calendar Meet attach and the Zoom save, so each answers once the bot is queued. The container starts after the reply.
- **A failure in the deferred start** is handled as it was inline. A failed start fails the run with `runtime_unavailable`. If the start never reaches a queued row, the next status read or dispatch starts it.
- **Without an execution context** (unit tests, scripts), the start still runs inline, as before.
- **Unchanged:** the bot-only send (`POST /sessions/:id/bot`) still awaits the start. It does nothing else in its request, so it stays within the 30 s.

### Verified

- **New test** (`meeting_capture_d1358`): the save answers while the run's `/init` is still pending. It returns 201 with the bot `queued`, and the start goes to `waitUntil`.
- **Mutation check:** without `defer` the new test fails.
- **Neighbouring tests:** 409 of 409 meeting-bot, meeting, Meet and Calendar tests pass. `tsc` reports no errors.
