### 1. Which renderer the reader uses

The public reader (`ArticleReaderPage.jsx`) draws `body_html`, the Worker's `renderMarkdown` output stored at publish. `react-markdown` draws only the editor's preview and the admin drawer. So the Worker is the source of the blocks, and the plugin makes both previews draw the same elements with the same classes. The shared cases are in both tests.

### 2. The blocks

| Block | Markdown | HTML |
| --- | --- | --- |
| Divider | a line holding only `---` | `<hr>` |
| Callout | a blockquote whose first line is `[!note]`, `[!tip]` or `[!warning]` (any case) | `<aside class="article-callout" data-kind="note\|tip\|warning"><p>…</p></aside>` |
| Link card | a paragraph holding only `[card](https://…)` or `[card: Title — description](https://…)` | `<a class="article-card" href rel="noopener noreferrer nofollow" target="_blank">` with `.article-card-title`, `.article-card-description` and `.article-card-domain` spans |

- **Divider.** `---` inside a code fence stays code: the fence is read first. A `---` line right under a paragraph is a divider too. In CommonMark it would make that paragraph a heading (a setext heading); the Worker never rendered setext headings, so the preview follows the Worker. Only `---` exactly: `----` stays text, as it does on the Worker.
- **Callout.** Any other blockquote is unchanged, an unknown `[!kind]` included. The body is escaped as every blockquote is.
- **Link card.** Never fetched, at render time or at insert. It shows the title and description stored in its Markdown, split on ` — `. Without them, it shows the link's domain (lower case, `www.` dropped) as its title and the URL as its description. Only `http://` and `https://` make a card. Anything else (`javascript:`, `data:`, root-relative, protocol-relative) stays an ordinary paragraph, whose link the inline rule already refuses. A card shares its paragraph with nothing.

Everything the renderer escaped before, it still escapes. No raw HTML passes.

### 3. Tests and mutations

- `cloudflare-worker/test/article_render_blocks_d1410.test.ts`: six tests.
- `frontend/test/article_render_blocks_d1410.test.mjs`: four tests. Each draws the preview, plus the Insert… list and its wiring.

Each mutation below fails at least one test:

1. **Worker:**
   - allow a non-http(s) card;
   - leave the callout body unescaped;
   - let `---` end a fence (read as a divider inside code);
   - make `----` a divider;
   - drop a callout kind;
   - make a card beside other lines.
2. **Client:**
   - allow a non-http(s) card;
   - leave the setext `---` a heading;
   - drop the cards;
   - drop a callout kind.
