## D6734 — Accept meeting-bot receipts on a separate receiver path (#6734)

**Parent:** D5674 and D5671.

`POST /webhooks/cloudflare/meeting-bot` accepts the bridge envelope using
the shared `parseCfReceipt` and `cfAudience` contract. The Worker authenticates
the bridge’s `cf-webhook-auth` header with distinct production and preview
credentials. An authenticated preview sender cannot submit a production
receipt. The native policy receiver continues to use `CF_WEBHOOK_SECRET`.

The receiver derives the destination data from the validated receipt and projects
the receipt into the existing D5671 recording family, retaining the closed
stage, outcome and provider fields. Production firing and recovery
use the health lane. The activity lane receives the production batch. Preview
uses the preview lane. The receipt ID is the durable event key. The outbox
acknowledges a replay without inserting another event or outbox item. A 202
acknowledges durable acceptance. Slack delivery has its own receipt.

The owner must configure the receiver’s `CF_BOT_DELIVERY_SECRET` for production
and `CF_BOT_PREVIEW_DELIVERY_SECRET` for preview, matching each sender’s
`CF_BOT_DELIVERY_SECRET`. Each sender’s `CF_BOT_DELIVERY_URL` must use the new
path. Unset credentials leave the bridge off and receipts pending. Rollback can
disconnect the bridge while preserving receipts and existing native routing.
