## D1130 — Cap-table access and exports use the issuance record; legacy admin gates and holder elections (#3010)

- **Task:** #3010, part of #2432; S22, s31. Draft implementation, not deployed or live-verified.
- **Migration:** none in this patch. A migration number for durable access requests was requested on #3010; no number is invented and no applied migration is edited.
- **Canvas:** D1015, CT2p, CT5, CT13–CT18 and CT22b, `design/incoming/Raise Cap Table Page.dc.html`.

### Access and security

Legacy `/api/captable` reads and saved-model/409A/Carta mutations no longer inherit an admin role. Admins use D1019's level read: group Summary normally, Full for support only with a 10–500 character reason logged before disclosure. HQ remains read only. The stateless simulator is available. D1017's plain-admin record corrections remain available with a 10–500 character reason and the existing atomic correction/audit write; document-reading runs are not corrections. This changes old URL behavior and requires S1's security review.

Venture grants and share links now copy their allowed fields from `cap_table_issuances`, never the saved scenario. Summary carries group percentages only. Investor names founder/investor positions and aggregates the option pool and other holders; employee/advisor names do not leave that projection. Full includes recorded positions, excluding proposals, private notes and audit internals. Own position resolves `holder:<id>`; an older name reference resolves only if exactly one recorded identity has that name. Ambiguous names show no private position, instrument or document. SAFE-only holders can still read their own recorded instruments. Investor-level instruments use the recorded holder kind, including SAFE-only investors; employee instruments and instruments with no recorded kind are excluded. The shared page draws those recorded instruments with their currency. New holder choices use recorded identities, including instrument-only holders. Unknown fully diluted totals yield unknown percentages, while known positions remain visible. Round count stays unknown; no class count or empty array becomes a financing-round count.

All successful opens still require the existing access-log write. Links retain their signed venture/level binding, revocation, expiry, view cap and attestation gates. Scenario capability links remain explicitly Modelled and are not converted to record links.

### Recorded exports and Carta

Venture `/live`, register CSV and PDF snapshots now project the same issuance balances and classes as Overview. Shares and options have separate columns; ownership uses the recorded fully diluted denominator, and stays unknown when that denominator is missing. A holder with options only is not described as owning 0%. Unassigned account-level connector rows retain their account view. A stale register count cannot alter the venture's recorded ownership; a failed record read cannot fall back to the register. A connected Carta integration alone is not proof of recorded Carta issuances. Export audit writes and the snapshot's NDA/nobody visibility remain in place.

Imports as proposals, the record-plus-complete-history CSV and the venture share page **already exist on the task's base main** (`a040f64850`, D1026). They are retained and exercised, not duplicated. The spreadsheet is CSV, as its existing client and route promise; this patch does not add an XLSX format.

### Holder-linked 83(b)

Migration 461 already gives `formation_steps` a holder reference, kind, state and due date; 441 stores proof and actor/timestamps. Existing Build writes record history and support proof upload. The filing validator incorrectly required a legacy founder marker. It now verifies the holder directly in the venture, allowing an employee's recorded identity and refusing foreign holders. No second election store is introduced.

The holder drawer retains its Build filing read. The Option pool grants block now reads the venture's equity plan and holder-linked filings, with proof presence only (no storage key). A failed election read marks that block Unreadable without removing known grants or the 409A. An actual filing date is not stored here, so the UI says it is not recorded; due/updated dates are never presented as filing dates. This remains a holder-level filing, not evidence that every later grant needs or has a separate election. Recording the filing and its proof uses Company creation's existing in-page dialogs.
