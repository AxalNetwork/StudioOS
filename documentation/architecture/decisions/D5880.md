## D5880 — The page's approval lanes held to the Worker's registry (#5880)

Part 6/8 (b) of #4716, the frontend half of D5879. The Worker writes every lane's facts once, in `cloudflare-worker/src/services/approvalLaneRegistry.ts` (D5879). The page kept its own lists: `LANES` and `HQ_LANES` in `frontend/src/pages/admin/approvals/approvalsModel.js`, and `inboxModel.js`'s `LANE_BY_KEY`, built from them, which names a lane and its group everywhere on /admin/approvals. Nothing held the two sides together, so a lane renamed, regrouped or moved to HQ on one side drifted silently.

### The decision: a test, not a generator

The page keeps its hand-written constants. `frontend/test/approval_lanes_registry_5880.test.mjs` imports both sides and fails on any difference in key, label, group or scope.

A generator was the larger change, for three reasons:
- **The page's lists carry more than the registry.** `glance`, `door`, `here`, `isNew` and `note` are the page's own. A generator would have to emit them too, or the page would merge two sources per lane.
- **Four labels differ on purpose** (below). A generator would need the same exceptions, written as code that changes output instead of as a test.
- **It is more machinery.** A new script under `scripts/`, an entry in `build-generated.mjs`, a gitignore line and a `--check` (D5612), for 29 rows that change rarely.

The test is one new file. The page's source changes in two small ways, and neither changes what is drawn:
- `inboxModel.js` exports `LANE_BY_KEY`, so the test reads the map the page itself uses.
- `approvalsModel.js` gains a comment pointing at the test.

### How the two sides are compared

| Fact | Page | Worker registry |
|---|---|---|
| key | `LANE_BY_KEY`'s keys (`LANES` and `HQ_LANES`) | `APPROVAL_LANES`'s keys |
| label | `laneLabelOf(key)`, which the page shows in place of the API's `lane_label` | `label` |
| group | `group` on `LANES`; `hq` for every `HQ_LANES` entry (as `LANE_BY_KEY` sets it) | `group` |
| scope | `studio` for `LANES`, `hq` for `HQ_LANES` (`isHqLane`) | `scope` |

The page's groups plus `HQ_GROUP` must also equal the registry's `INBOX_GROUPS`, in order.

### Known differences are pinned, not ignored

Four lanes carry the Approvals canvas's words on the page (D1038 §1) and the Worker's older board label in its inbox and decision-log responses. `laneLabelOf` shows the page's word wherever the page names the lane, so nothing on screen shows the Worker's. Changing the Worker's label would change its API output, which is not this task.

| Lane | Page | Worker |
|---|---|---|
| `exploring` | Explorers ready for a profile | Exploring |
| `cohort` | Spin-Out Lab applications | Cohort applications |
| `moderation` | Spin-Out moderation | Spinout moderation |
| `referrals` | Refer & Earn reviews | Referrals |

`LABEL_PAIRS` names both values for each lane. A change on either side still fails, and a pair whose labels agree again must be removed.

### Destinations

Every lane in the registry must have a case in `AdminApprovals.jsx`'s `LaneDoor` or `HqDoor`, the literal links that open the page that decides it. Each link must be a route that `App.jsx` or a module under `frontend/src/routes/` declares and that renders a page. The registry's own `decisionPath` values are held to the same rule.

What counts as a route is strict:
- **Exact paths.** The query and hash are stripped, and the destination must equal a declared path.
- **Listed params.** A `:param` route counts only for a destination listed in `PARAM_DESTINATIONS`, with the route it is meant to land on. Today that is KYB's `/admin/kyc/businesses` on `/admin/kyc/:tab`. Matching params loosely would let `/:at/:channel` (a handle's page) or `/admin/licences/:uid` answer a mistyped door.
- **Not catch-alls or redirects.** A splat route (`/admin/*`, `*`) and a `<Navigate>` redirect are not destinations, or every mistyped `/admin/…` door would land on Not found and pass.

Best-Fit has no review page yet, so `LaneDoor` draws it as words. `NO_DOOR` pins those words, and the test fails once Best-Fit links somewhere, so the entry must then be removed.

The door's words (the page's `door`, the registry's `decidedOn`) are not compared. They differ by design for KYB, Program-grant requests and the three lanes decided on this page's own boards, and the issue asks for key, label, group and scope.

### No visible change

No rendered value moves. /admin/approvals, /admin/approvals/lanes and /admin/approvals/decided draw what they drew before. The existing approvals suites pass unchanged.
