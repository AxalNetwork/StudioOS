### What the walkthrough found

- The phone editor promised "Only you see these." for speaker notes: `editorModel.js` `NOTES_PLACEHOLDER` says so on desktop and phone, while `ExportDialog.jsx` defaults notes and Sources on (`useState(true)`, L69–70) and the PDF prints notes pages.
- The file dialog and the investor link disagree: `shareModel.js` `DEFAULT_INCLUDE` keeps notes off and the appendix on for a link.
- PowerPoint is labelled "One picture per card" (`presentExportModel.js` L308), but `pptxEditable.ts` writes text boxes, native charts for 9 types, diagram shapes and pictures, can shrink long text to `FIT_FLOOR` 0.4 and always sets 13.33 × 7.5 in. It counts what it made; the route does not return the counts.
- The v4 export's file could not be fetched again: `routes/deck_exports.ts` records version, format, fingerprint (`X-Content-SHA256`), who and when, with no notes, appendix or stored file, and the browser gets the file once. The dialog has no preview, no preset and no retry.

### Built (#8771, S12, 2026-11-27)

Built to option A for Q1, Q2 and Q4, as the canvas draws them. Every sentence the dialog says about a file was checked against the writer that makes it on `main`.

- **Who it is for.** `ExportDialog.jsx` opens on the Investor copy every time: no speaker notes, the Sources appendix on (Q1 A, Q2 A). It also offers the Working copy (both on) and Custom (the two checkboxes, which stay where they were). The copy is not a third setting. It is the name of the two settings (`exportDisclosureModel.presetOf`). The Worker derives the same name (`deck_exports.copyOf`, `EXPORT_COPIES`), so the dialog and the ledger cannot disagree. A drift test reads both tables, and checks the investor copy against `shareModel.DEFAULT_INCLUDE`. The api methods are unchanged.
- **Preview and What leaves Axal VC** (`ExportDisclosure.jsx`, `exportDisclosureModel.js`). These are built from the picked version's own exportable cards:
  - **The page plan.** A PDF is cards, then `ceil(cards / 6)` notes pages, then Sources. It prints at the deck's aspect, or 1920 × 1080 for a template deck, as in `pdfExport.printPageOf`. PowerPoint and Google Slides are 13.33 × 7.5 in. The .odp is 28 × 15.75 cm. A 4:3 deck is told that its slides are 16:9 in those files.
  - **What leaves, row by row.** The rows are the cards, the speaker notes, the Sources appendix and the hidden cards. The appendix row counts its source lines. For PDF and HTML it also names the cards written with AI help: those two writers print that line, and the PowerPoint, .odp and Google Slides appendix does not.
  - **The editability table.** It counts text boxes and native charts (the client's copy of `NATIVE_CHART_TYPES`, checked against the Worker's). It lists the charts that become a picture or text, the diagrams written as shapes, the pictures (PNG, JPEG or GIF; anything else becomes a sentence), and the stacked text frames for field cards and Sources. It also states the `FIT_FLOOR` rule. The .odp is said to have no native charts, because `odp.ts` draws none.
- **Format lines** (`presentExportModel.FORMATS`).
  - PowerPoint: "Editable text, shapes and most charts · some charts as pictures". It no longer says "One picture per card".
  - PDF: "Every card as a page at the deck's size · text stays text".
  - Google Slides: "The same editable file, made in your Drive".
  - .odp: "… · charts as pictures or text".
- **The editor's promise.** `editorModel.NOTES_PLACEHOLDER` is now only "What you will say on this card." A new helper, `NOTES_HELPER`, is shown under the notes field on desktop (`BlockTools.jsx`) and on the phone (`PitchEditor.jsx`): "People who can open this deck in Axal VC can read these notes. They go into a file or an investor link only when you include them." It replaces "Only you see these."
- **The acknowledgment (Q4 A).** It is asked on every export whose notes setting is on and that has at least one card with notes. It quotes the first such note, and Export stays off until it is ticked. Any change to the format, version or settings asks again.
- **The completed export.** It shows:
  - the frozen version, the format, the copy and both settings;
  - the page or slide count;
  - the fingerprint, from `X-Content-SHA256`;
  - what the writer made: the new `X-Deck-Export-Report` header on PowerPoint and .odp, or `report` in Google Slides' JSON. `pptxEditable.writeEditableDeck` now also counts text boxes, boxes set smaller and the smallest share, diagrams, and slides from blocks versus text frames;
  - Download again (the same bytes, while the dialog is open);
  - a link to the same version in Present.

  A failure keeps its reference and offers Try again with the same settings.
- **Ledger.** Migration `202611270209_8771_deck_exports_disclosure.sql` adds `notes`, `sources` and `copy` to `deck_exports`. Every export route records them. `GET /api/decks/:id/exports` returns them, with null for older rows. The dialog shows null as "Notes and appendix Not recorded", never as "not included".

### Not built, and why

- **Q3 (Download again after the dialog closes).** Option A keeps the file for 30 days. That needs a stored copy (an R2 key, a retention sweep and a download route), and it is the owner's call because it keeps investor-bound content at rest. So Download again works only while the dialog is open. The completed panel says the file is not kept, and that exporting the same version again with the same settings is recorded as a new export.
- **The recipient preview link (PTX05, PTX08).** `main` has no route that previews an investor link's recipient view of a version. Only Present is linked. The check across Present and the link preview stays with S21's browser verification (#8795, #8777).
- **The real-file check (PTX09 ◇).** This means opening the fixture in PowerPoint, Keynote, Google Slides and a PDF reader, and inspecting editability, cropping, slide size, notes, source pages and projector legibility. A person must do it in those apps, and that was not possible here. The Worker test (`deck_export_disclosure_8771.test.ts`) checks the fixture's file structurally instead: the slide size in `presentation.xml`, one native chart part, notes slides empty or carrying the note, the report counts, the long title set smaller but never below FIT_FLOOR, and the fingerprint equal to the bytes. Until a person records the real-app results with a fingerprint, they are Not recorded.
- **Recording the report on the ledger row.** The canvas mentions this, but the acceptance does not need it. The counts are returned with the file, not stored.
- **The phone layout of the dialog.** The new parts stack in one column under 640 px (`sm:` breakpoint). No separate 390 px layout was drawn beyond that.
