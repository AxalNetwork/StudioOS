## D8080 — The agent registry: D1 synced from the manifests on deploy, and the HQ read (#8080)

- **Status:** part 1, built by S23 on 2026-11-22. #8079's manifests and validator are on main (#8090). The canvas
  (#8100) landed before the owner's answers, so `needs-design` stays.
- **This part:**
  - the schema;
  - the idempotent sync route and script;
  - drift against the live team agents;
  - the Super Admin read and its client method.
- **Waits:** "Deploy this agent" from the catalogue, and `frontend/src/pages/hq/aiAgents/Registry.jsx`. The screen
  waits on the owner's approval of the SA20 to SA24 boards (the D4137 addendum). The deploy-workflow line is #8069's.

**Schema** (`202611222134_8080_agent_registry.sql`):
- **`agent_registry`:** one row per manifest version, `UNIQUE (name, version)`.
  - **`version`:** the first 12 hex of `manifest_sha`, the SHA-256 of the file's bytes. The manifest schema
    (`agents/README.md`) has no version field, so a content change is a new version.
  - **Not in the schema yet:** `stage`, `cost_profile` and `security_profile` are columns, but they stay NULL
    because the manifest records none of them. As the issue asks, the registry reads the landed schema and
    invents nothing. A later manifest field fills them.
  - **`superseded_at`:** marks every version but the current one of each name, and every version of a name the
    folder no longer holds.
  - **Also stored:** `capabilities_json`, `models_json` and `manifest_commit` carry what the read shows.
- **`agent_registry_drift`:** (name, field, manifest value, runtime value, agent uid, seen at). Each sync replaces
  it whole, so it always says what the last sync saw.

**The sync.** `POST /api/internal/agent-registry/sync` takes `Authorization: Bearer <AGENT_REGISTRY_TOKEN>`,
compared in constant time. The token is a new Worker secret that only the production deploy environment holds.
- **Refusals:** an unset secret answers 503 `registry_sync_not_configured`. A wrong or missing token answers 401.
  A bad body answers 400 `registry_sync_invalid` naming the field. More than 256 KiB answers 413.
- **The write:** one D1 batch upserts each manifest by (name, version), supersedes the rest, and rewrites the drift
  table. A re-post of the same folder adds no row.
- **The script:** `scripts/deploy/sync-agent-registry.mjs` builds the body from `agents/*.agent.yml`. It refuses to
  post when the folder fails `check-agent-manifests`, and `--dry-run` prints the body. The line that runs it after
  the deploy is proposed on #8069. With the secret unset, nothing is synced and the read says "not recorded".

**Drift** is read only where D1 records the running agent:
- **Venture manifests:** compared with their live `team_agents` copies (not `removed`). Until part 2's deploy flow
  records the registry entry on each copy, a copy is bound by `role_key = name`.
- **`status`:** a live manifest expects `active` copies, and a paused one expects `paused`. A retired manifest
  expects no copy, so each live copy is drift.
- **`capabilities`:** a copy's live `agent_capabilities` grants (#8070) that the manifest does not name, by name or
  `<domain>.*`.
- **Budgets:** #8071's tables are not on main, so budgets are not compared, and the read says
  `budgets_compared: false`.
- **Platform manifests:** these have no D1 copy, so their copies and drift are `null` ("Not recorded"), never 0.

**The read.** `GET /api/admin/ai-agents/registry` is Super Admin only (`requireSuperAdmin`). It is a second mount
in `admin_ai_agents_roster.ts`, because `/roster/:key` would take `/roster/registry`. It answers:
- each name's current version, with capabilities, models, status, live copies and drift;
- the last sync's time and commit;
- `{ status: 'not_recorded' }` before any sync;
- `last_run: null`, because a run is recorded per team agent and part 2 joins it once a copy names its entry.

The client is `frontend/src/lib/api/aiAgentsRegistry.js`.

**Rollback.** Revert the Worker. The two tables are additive, and nothing else reads them. Deleting the secret
stops the sync.

**Tests.** `cloudflare-worker/test/agent_registry_8080.test.ts` runs on the migrated schema:
- the mounts;
- 503 and 401 store nothing; each 400 names its field; 413;
- upserts are idempotent: superseding, removal, and a revert reviving its own row;
- drift for a fixture mismatch (an extra grant, and a paused copy against a live manifest), replaced by the next
  sync; a revoked grant and a removed copy do not count; a platform manifest is never compared;
- the read: Super Admin only, "not recorded", current versions, null for platform agents, no email;
- the script's body from the real manifests, accepted by the route; a failing folder refused; no token, no post;
  the token is never printed.
