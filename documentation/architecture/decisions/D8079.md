## D8079 — The agent manifest: one reviewed file per agent, checked in CI (#8079)

- **Status:** built 2026-11-21. Part of #8059 (audit section 17). Feeds #8080 (the registry in D1) and #8082 (baseline as code).
- **Builds on:** #8070 (capability names), #8071 (budget fields), #8061 (App identities), #8067 (the privileged path list), #8072 (trusted and untrusted pools), #7073 (gateway model keys).

### The decision

Every agent the platform runs is declared in `agents/<name>.agent.yml`. The file
records its kind, owner, identity, capabilities, models, container size, limits,
network, write paths, runner pool, approval rule, escalation, status and the
files that run it. `agents/README.md` holds the schema and the rule for adding
one. `scripts/check-agent-manifests.mjs` validates every file, and
`frontend/test/agent_manifests_8079.test.mjs` runs it over `agents/` and over one
fixture per refusal.

The seed manifests describe what the repository already runs. Each value is
taken from the workflow, script or rule file listed in its `sources`:

| Manifest | What runs it | Identity | Status on 2026-11-21 |
| --- | --- | --- | --- |
| `landing-bot` | the feeder, ejection, refresh, main-repair and conflict workflows; `scripts/landing-bot/` | `studioos-landing-bot` | paused: `LANDING_BOT_ENABLED` unset, every run skipped |
| `keeper` | `landing-bot-keeper.yml`, `keeper*.mjs` | `studioos-landing-bot` | paused, same switch |
| `model-runner` | `landing-bot-model*.yml`, `scripts/landing-bot/model/` | `github-actions` (read, plus federation) | paused: only the paused bot calls it |
| `coordinator` | `scripts/coordinator.mjs`, the `coordinator-audit` skill | `session` (S01) | live |
| `scan-remediation` | `scan-remediation.yml`, `scripts/scan-remediation/` | `github-actions`, or its optional App | live |
| `sessions` | `AGENTS.md`, `scripts/claim.mjs` | `session` | live |

### Refusals

| Code | Rule |
| --- | --- |
| `prod_deploy` | `prod:deploy` (the audit's spelling), `deploy.production`, or a wildcard (`deploy.*`, `*`) covering it. Refused for every agent, platform or venture. |
| `capability_ungrantable` | `code.merge`, `cloud.write`, `finance.execute`, `email.send`, by name or wildcard (#8070: a person does them). |
| `capability_unknown` | A name outside the catalogue, or a wildcard that matches none, so a typo cannot pass and silently grant nothing. |
| `privileged_path` | A venture agent's `allowed_paths` glob that can match a path on #8067's list. |
| `approval_required` | An email, introduction or payment capability without `approval.external_actions: required`. |
| `schema` | Every other departure from the README's schema, including a `sources` path that does not exist. |

### Names

**#8070's twenty grantable names** are the catalogue, plus six repository actions
the seed agents already take and #8070's list does not name. Each one stands for
a workflow permission or call that exists today:

| Name | Stands for |
| --- | --- |
| `issue.read` | `issues: read`: issues and PR conversations |
| `issue.write` | `issues: write`: comments, labels, opening and closing issues |
| `ci.read` | `actions: read`, `checks: read` |
| `ci.dispatch` | `actions: write` for `gh workflow run` on main |
| `code.enqueue` | a merge-queue entry (the feeder; AGENTS.md step 5 for sessions) |
| `security.read` | `security-events: read` |

`code.enqueue` is not `code.merge`. The queue merges, under the rulesets and
required checks GitHub enforces. The agent only asks, and merge-policy keeps T2
for the owner. #8070 should seed its `capability_catalog` with these six. Until
then they are valid only here.

**`models.route`** (`gateway`, `direct`, `none`) is added beside `models.allowed`.
Without it, `allowed` would mean two things. None of the seed agents uses the
agent gateway. The model runner calls provider SDKs directly, and it lists the
provider accounts its `providers.mjs` names. The sessions and the coordinator are
models themselves, and the platform makes no model call for them.

**`sources`** is added so a manifest cannot outlive its code. A removed workflow
fails the check until its manifest is updated or retired.

**`limits` values** are a whole number or `none`. `none` means nothing in the
repository caps it today: no figure is invented. #8071 fills these in.

### The privileged list (#8067)

#8067 is open, and `scripts/lib/privilegedPaths.mjs` is not on main, so the
script carries the list as one exported constant, `PRIVILEGED_PATHS`, cited to
#8067. It is written as globs and taken from the two lists that decide a
privileged change on main today:

- the landing bot's `PROTECTED` (`scripts/landing-bot/rules.mjs`);
- merge-policy's T2 path rule `SENSITIVE` (`merge-control/src/lib/classify.mjs`).

The test runs forty-one probe paths through `PROTECTED` and `classify()`, and fails if
the constant disagrees on any of them. When #8067 lands, the constant imports its
module and the comparison test stays.

Two consequences follow from today's rules:

- **`SENSITIVE_NAME` is left out.** It is merge-policy's keyword rule (auth,
  billing, payment …). It tiers a PR by a word in a path and names no location,
  so a venture's own `auth/` folder stays T2 at merge time without being
  unlistable here.
- **Matching is strict, and it ignores case, as `SENSITIVE` does.** `SENSITIVE`
  matches `scripts/`, `.github/`, `merge-control/` and `attached_assets/` at any
  depth, and `AGENTS.md`, `CLAUDE.md`, `package*.json` and lockfiles anywhere. So
  a venture glob with `**`, or a bare `*.md`, can reach one and is refused. A
  venture agent names its folders and files narrowly. If that proves too tight
  once #8078 decides venture namespaces, the change belongs in #8067's list, not
  here.

A platform agent may name `**`. The landing bot's `pathGuard()` and merge-policy
still refuse a privileged write when it happens, and each such manifest says so
in a comment.

### YAML

The manifests are read with `yaml` 2.9.1, which is already a pinned dev
dependency (`check-production-credentials.mjs` reads every workflow with it).
Nothing new is installed. The issue allows any reader the tree already has. A
flat line reader like the one in `agents_protocol_d503.test.mjs` cannot read the
nested `models`, `limits`, `network` and `approval` mappings without a second
parser. Aliases are off (`maxAliasCount: 0`) and duplicate keys are refused, so
each file reads one way. Because of this, a glob that starts with `*` is quoted.

### CI

The test is in `frontend/test/`, so `npm run test:frontend` runs it on every PR
with no `package.json` edit. The line that adds the script to `test:guards`
edits `package.json`, which is T2. The owner lands it:

```text
&& node scripts/check-agent-manifests.mjs
```

It goes after `node scripts/check-production-credentials.mjs` in `test:guards`.

### What this does not do

- No registry row, no runtime check and no budget enforcement. Those are #8080,
  #8070 and #8071, which read these names.
- No live comparison. The `status` of a paused bot is what the repository and
  the run history showed on 2026-11-21. The switch itself
  (`LANDING_BOT_ENABLED`) is a repository variable, and #8082 compares the live
  values.
- No change to any workflow, permission or production resource.

### Rollback
