## D4480 — The member program page names the enrolment date (#4480)

Part of #3726, LR13/LR13b. The existing program detail read adds
`enrolled_at` only when the caller has an active member enrolment. It reads
the row bound to the session's user id, never another learner's row. A reader
who is not enrolled gets no key. Empty or unreadable stamps become null;
recorded SQLite UTC or ISO timestamps become an ISO instant. Existing program
visibility and staff-reader gates stay in place. Staff who are also actively
enrolled get their own member date; reader access alone never establishes
enrolment. No migration is needed.

The existing `learningApi.program` read carries the field to MemberProgram.
`enrolmentCopy` takes the enrolment state and date together, formats en-GB in
the viewer's local zone, and explicitly says when the date is not recorded.
The date alone uses the application's existing mono token in a semantic
`time` element; no custom font or canvas colour is introduced. An open program
the member has not joined retains “Anyone with a profile can join.”

The member page follows the owner's no-AI-panel rule. Existing layout and
responsive theme tokens remain; no sidebar or account-menu changes. Tests
cover own versus other/removed/reader enrolments, unknown timestamps, both
enrolment modes, local date boundaries and the read-to-view handoff. D3726 §2
records that this closes the date gap left by #4180.
