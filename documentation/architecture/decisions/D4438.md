## D4438 — Persona segments: HQ scope and waiting suggestions (SEG7, #4438)

Part of #2378. D1003 (#2818) merged suggestions but explicitly deferred its
cross-studio summary. This completes that read and D1004's disabled controls.
No migration, theme grouping or profiling-trends retirement.

- `admin_persona_segment_scopes.ts` self-mounts three Super Admin reads:
  registry scopes, overview by scope, and open suggestions by scope. A plain
  Admin is refused, as is an elevated caller on a subsidiary; unknown scope
  is 404, an unreadable registry 503 when it cannot decide that question.
- The default is HQ-held. Options reuse `insightsScopes` and its deployed
  `licence_deployments` rows. A stray binding cannot become a scope. `*` means
  All studios (HQ included); unlike `all`, it cannot collide with a legal
  subsidiary code. No subsidiary options are invented when none is deployed.
- A branch exposes `personaSegmentOverview` through the existing private-link
  RPC. It refuses on HQ, runs the same D999 `readPersonaSegments`, D1000
  profile/coverage queries, and projects only segment definitions and aggregate
  counts. No account identifier, email or individual answer travels. The HQ
  side projects the reply again; a wrong-tier/old/missing reply is unreadable.
- All studios calls each registered bound studio once, with a shared reference
  date and the branch service's deadline. Missing bindings are included as
  unanswered. A block is summed only when every studio answers that block.
  Null figures and undated weeks remain null. The reply carries a source
  denominator, never a silently smaller business-wide total.
- Needs and offers are per-studio definitions and stores, not additive figures.
  The All studios overview says **Not recorded** and asks for one studio,
  rather than inventing a unified needs-met denominator or double-counting
  shared offers. One studio reads its own coverage and profiles.
- Open suggestions reuse D1003's store/query. Its optional bound origin filter
  applies before the existing 200-row limit; old admin reads/decisions stay
  unchanged. The inset shows three of that scope's newest open suggestions
  and links the existing HQ decision page. It never decides on a read.
- The frontend client is its own generated API module. The scope select and
  suggestions remain available when overview blocks fail. A scope change
  rereads the three overview blocks in one call and reloads suggestions;
  late replies cannot overwrite a new scope. SEG11/SEG12 remain Reading and
  “Could not be read. This is not a claim that there are none.” A missing
  figure is Not recorded. Ordinary Admins keep their existing local reads.
- Scope applies to Overview's aggregates. Member lists and edits remain HQ's;
  a remote count has no misleading “Open Unclassified” link into HQ members.
  No remote personal-data fan-out is introduced. `themes_enabled` stays false.
