## D4691 — HQ Security: one identity shape, one session status rule, partial reads stated, evidence validated (#4691)

**HQ Security audit 4/6, slot S23 · 2026-11-07.** One additive migration
(`202611072219_security_events_support_actor.sql`). Scope: `/admin/security`
and the Trust workflows it links to. Related: #4571, #4616, #1021; siblings
#4669 (session containment) and #4675 (data-subject lifecycle).

### What was wrong

- **Identity.** Each reader built an actor name from whatever its join
  returned. An act with no account showed a blank actor. A support operator's
  own security events were recorded under the account holder. A refused
  attempt that named an account showed that account as the actor.
- **Network attribution.** HQ's cross-account session list carried each
  session's full client address. The repository's rule for security records is
  a network bucket (`ipPrefix`: /24 for IPv4, /48 for IPv6), and the bucket
  itself mis-handled compressed IPv6 forms.
- **Session status.** "Live support session" had three definitions on one page
  (any open record; open and inside the extension ceiling; open and inside the
  first token's thirty minutes). A branch support token was counted as active
  for a whole day instead of its thirty minutes.
- **Partial reads.** Several `/overview` reads had no failure state of their
  own: one failure took the whole page down, and an empty fallback would have
  read as zero. The AI-safety rule breakdown read as "no rule fired" when only
  the breakdown failed.
- **Evidence.** Any JSON object in the backup heartbeat read as a recorded
  backup. A passed restore drill read as passed however old it was. Neither
  marker carried a schema version.

### What changed

- **`services/sessionStatus.ts`** holds the definitions every count and list
  uses:
  - account sessions are `active`, `expired`, `revoked`, `signed_out` or
    `unknown`, with a per-factor token lifetime;
  - support sessions are `live`, `not_closed`, `ended` or `unknown`; "open" is
    every status but `ended`.

  The list and count SQL is written out beside its callers. A test runs it
  against the shared functions over a grid of rows. This module classifies
  rows for display only; enforcement is unchanged and belongs to #4669.
- **`services/securityIdentity.ts`** gives every actor one shape:
  - `kind` is `user`, `support`, `system` or `network`;
  - each identity also carries `label`, `on_behalf_of` and a network bucket.

  Feed rows carry `actor_identity`, with `actor` kept as its label. A refused
  sign-in or recovery is attributed to its network, and the account it named
  appears as the subject. Sessions rows carry `network` (the bucket) and
  `holder` instead of the address.
- **Security events record a support caller.** The migration adds a nullable
  `support_user_id` column. Gate refusals and step-ups made inside a support
  session store the operator (0 for a branch session). Their dedupe key is the
  operator's, so their events are never folded into the holder's.
- **`/overview` reads independently.** The audit count, admin MFA, the KYC
  queue and open erasure requests each have their own unreadable state. The
  AI-safety block is unreadable as a whole only when its rollup fails. The rule
  breakdown has `breakdown_available`, with null figures when it was not read.
- **Evidence is validated, versioned and dated** (`services/backup.ts`):
  - the heartbeat and drill markers are checked against schema 1;
  - a marker without a version is read as schema 1 and flagged `versioned:
    false`, and any other version is invalid;
  - states are `unreadable` (nothing read), `invalid` (read but not
    believable), and `fresh` or `stale`;
  - a heartbeat is stale after 26 hours from its recovery point (the 24-hour
    RPO plus the run window). A drill is stale after 32 days (the longest
    monthly gap plus a day);
  - missed RPO and RTO targets are carried;
  - the writers (backup workflow, drill script, worker cron heartbeat) stamp
    `schema_version: 1`.
- **The page** draws identity kinds and the network bucket, and marks a
  support-held session. Stale and invalid evidence are drawn in their own
  wording and tone, and each partial read is drawn as unreadable.

### Unverified

- Production: whether the deployed heartbeat and drill markers pass schema 1.
  A marker that fails reads as invalid on the page, which is the intended
  failure direction.
- Owner review of the evidence, the freshness windows and the decision to
  show HQ the network bucket rather than the address.
- The migration is applied by the deploy's migration step. It has not been
  run against production here.
