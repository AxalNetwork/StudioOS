### The rules every source follows

1. **One registry entry** in `services/calendar/registry.ts`: family, module, label, `page_only` and `pushable`. Then one reader in `READERS`, one family in `items.ts`'s `FAMILY_OF`, and one kind in the page's `KINDS` and `FAMILIES`.
2. **Confirm the store first.** Each source confirms its columns and its owner rule before its reader is written, and states both here.
3. **Owner only.** A personal source reads the member's own rows, `WHERE … = ?` bound. It is in `PERSONAL_ONLY_KINDS`, so no staff scope lists it.
4. **Page only** unless its section says otherwise: never in an `.ics` file, a feed or a provider copy.
5. **No titles, names or links in logs.** `gather` logs a source's outcome code alone.

### §a — Bot calls and recorded sessions (#3980, 2026-11-01)

Built by S17. The kind is `bot_call`: family Meetings, module "Validate › Record a session", label "Recorded call". It is page only and not pushable.

- **The store, confirmed:** `meeting_bots` (migration 531).
  - `scheduled_at`, `started_at` and `ended_at` are INTEGER epoch **milliseconds** (`dispatchBot` stores `Date.parse`; the run's Durable Object stores `Date.now()`).
  - `status` is one of queued, joining, waiting_room, recording, processing, done, failed or stopped.
  - The table has no integer id, so the item's `source_id` is the row's `rowid`, and `source_uid` is the run's `uid`.
- **Owner rule:** `b.user_id = ?`, bound. The venture must be live (`deleted_at IS NULL`) and the member active.
- **Times:** epoch milliseconds become ISO.
  - A run starts when the bot joined (`started_at`), else when it was scheduled.
  - It ends when the bot left (`ended_at`), else at its limit (30 or 120 minutes).
  - The window is half open on the start.
- **Words** (`BOT_STATE_WORDS`):
  - `done` alone reads **Recorded**; the other states read Scheduled, Joining, In the waiting room, Recording, Processing the recording, Did not record and Stopped.
  - **"Transcript ready" (join confirmed).** It is said only when the run is `done` and its interview session holds its final transcript. That means rows in `interview_transcript_segments` with `source = 'final'` for the run's `session_id`, which `meetingBotAssembly.ts` writes in the same batch that marks the session transcribed. A live passage alone is not a transcript, and a run not yet done never announces one.
  - The item carries `bot: { state, words, transcript_ready }`, and the agenda row prints `words`.
- **Privacy (D886):**
  - the reader never reads `meeting_url_enc`, `participants_enc` or the event payloads;
  - the item's `location_uri` is null;
  - the title names the interviewee, as the interview call does;
  - a failing read logs only `{ kind, outcome }`.
- **Where it goes:** `href` is the venture's Validate › Customer research. The page gives it a hue in both themes and its own dot shape.
- **Verified:** `cloudflare-worker/test/calendar_bot_calls_d1486.test.ts` (5 tests):
  - owner only, with a second user who sees none, and in no staff scope;
  - epoch to ISO, joined-else-scheduled to left-else-limit;
  - `done` gives "Recorded", and no transcript means no "Transcript ready";
  - not in `.ics` or a feed;
  - no link or participants read, and a failing read logs no title.
  - Mutations, each caught: the owner predicate dropped; the transcript EXISTS made always true; the `done` guard dropped.
