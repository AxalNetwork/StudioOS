## D611 — Colleague seats: the invite reaches the colleague, and accepting never turns an admin into an investor

**An Institutional investor's colleague invite is a link the inviter can pass on, emailed when mail is configured, and accepting it does not silently change someone's role.** Issue #1311. No migration.

**Delivery.** `POST /api/investor-seats/invite` still stores the single-use token. The reply is `invite_link` and `email_sent`, never the bare token. The link is `…/investor-seats/accept?token=…`. Mail uses the same Gmail path as a company invitation, and only when those credentials are set. Without them `email_sent` is false and the link is what the inviter copies.

**Who sees the link.** The inviter, and only on a seat that is still pending. `GET /api/investor-seats` adds `invite_link` for those rows and omits it once the seat is accepted or revoked. The token column stays on the row and is not a response field.

**The card.** It says "Invite emailed to …" only when `email_sent` is true. Otherwise it shows the link. It does not say "Invite sent." when nothing was sent.

**Accepting.** `POST /api/investor-seats/accept`:
- An admin is `409 admin_cannot_take_seat`. The role is not changed.
- A founder, a partner, or any other account that is not already an investor is `409 role_change_needs_confirmation`, and the body names the current role. The page asks, then sends `confirm_role_change: true`.
- An investor accepts as before, and the role stays investor.
- A revoked invite, one already accepted, the wrong email, and an inviter whose plan no longer covers seats stay the refusals they were. The accept page shows each of them.

**The page.** `/investor-seats/accept` is not role-gated. Signed out, it sends the person to sign in and back, with the token. Signed in, it follows the role rule above.
