## D5679 — Verify section notification destinations from the Worker (#5679)

An HQ Super Admin can test delivery using an authenticated, empty `POST /api/admin/slack/sections/{slug}/test`. Browser callers use the usual StudioOS CSRF header. The Worker writes a fixed, labeled synthetic message after checking the bot’s workspace and active private channel memberships. Requests can select only an approved slug. The test uses the existing Slack bot transport and reports the acknowledged channel and message timestamp.

Configure the target environment with one Slack bot (`SLACK_BOT_TOKEN` with `groups:read` and `chat:write`), invite it to each selected private channel, set `AXAL_SECTION_SLACK_TEAM_ID` to the expected workspace, and set `AXAL_SECTION_SLACK_CHANNELS` to an operator-maintained JSON object mapping full channel slugs without a leading hash to Slack channel IDs. Confirm the intended operator audience before adding an entry. Keep actual IDs and tokens in private configuration. Begin with one controlled test in the intended environment. The endpoint refuses archived, shared, pending-sharing, renamed or unverifiable channels. A provider rate limit may include a Retry-After interval. For an unconfirmed post inspect the private channel before retrying.

The existing audit feed receives the result. This first slice proves individual delivery. Durable event/recovery threads, automated producers, replay and incident-driven GitHub work remain in #5679 and its tracker #5678.
