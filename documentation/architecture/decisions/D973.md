## D973 — Admin network overview, people and drawer reads

2026-10-24 · #2759 · S27 / s30 · Part of #2369 · Depends on #2742 (D972).
No migration. No page changes: D975/D977 consume these reads later; the existing
D972 page retains its seven reads until its owning slots wire the new clients.

## Response states

The three GET routes live at `/api/admin/network`, require an admin account,
and never write network records. Every data block uses one of:

- `{ available: true, recorded: true, value }`: the store was read successfully;
  zero and empty arrays are legitimate only in this state.
- `{ available: true, recorded: false, reason }`: no applicable store or link.
- `{ available: false, reason }`: unreadable; offer Try again. There is no value.

`unreadable` lists failed source keys. Each source has its own explicit SQL
projection and catch, so a missing table does not blank unrelated blocks.
Database errors and SQL text stay off the wire. Authentication fails before the
network snapshot. Other admins' advisor profiles follow the existing advisor
privacy rule: only self or a super admin may see them.

## Overview — `GET /overview`

The envelope has `as_of` (UTC ISO), `timezone: America/New_York`, `scope` (hq or
branch code), the following blocks and `unreadable`:

- `counts.people` and `counts.by_kind`: identity count, and `{kind,count}[]` for
  advisor, operating_partner, deck_only. Inactive accounts and hidden roster
  entries remain identities; hiding a slide is not deleting a person.
  `counts.by_stage` is Not recorded until D976 (#2762) supplies its stage store.
  `counts.firms` has total/listed; `counts.lab_hosts` approved/pending;
  `counts.cohort_assignments` counts active, not-unassigned assignment rows.
- `sessions`: `{ timezone, as_of, weeks, this_month }`. Twelve ET Monday weeks,
  oldest first, each `{week,partial,booked,completed,no_show,cancelled}`. Only the
  current week is partial. Booked means pending/confirmed, separate from completed
  and no-show; cancelled is a separate count. Both office-hour booking stores
  contribute. Slot time is the basis, through as_of; future slots do not inflate
  historical weeks or the current-month figure. Zone-less D1 stamps are UTC;
  ET day/week assignment observes daylight saving. Current-month sessions exclude
  cancelled bookings. Missing/bad slot times make this block unreadable.
- `deals`: `{total,ending_soon,by_type:[{type,count,soonest_end}]}` from all active
  deal rows, without the old newest-200 cap. Ends are UTC instants; ending soon
  means now through 30 days. A missing end is null, never a guessed term.
- `settlements`: HQ only, issued rows with due_on from the current ET date through
  date +30 inclusive. `{currency:'usd',count,to_member_cents,from_member_cents,
  rows:[{id,deal_id,kind,direction,amount_cents,due_on}]}`. Directions stay separate,
  not netted. Branches return Not recorded / “Settlements are kept by HQ” and
  execute no settlement query. Draft/matched/void records are outside this due list.
- `skills`: `{supply:[{skill,count}],demand}` from advisor expertise and roster
  skills. Duplicates within one identity count once. No name-based deduplication
  across identities. `demand` is Not recorded: no matching founder demand store.
- `needs_you`: separately wrapped missing_advisor_profiles, unattached_partners,
  ending_deals, pending_hosts, missing_deck_photos, settlements. Queue items carry
  stored refs/IDs and existing admin hrefs; no fabricated rows. Missing photos
  covers the six actual profile cards, using D214's shared deckRosterReach rule.

## People — `GET /people`

Parameters: q (max 200), kind, skill, sector, lab_host (stored application status),
profile_check, kyc, on_deck, firm_attached, active_deal, sort, limit (1–100,
default25), offset (0–1,000,000, default0). Boolean filters accept true/false/1/0.
Profile check and KYC also accept `not_recorded`. Stage requests return 400 with
recorded:false and the D976 reason rather than pretending a filter exists.

Search runs on the server over name, headline, firm name/company and skills;
literal case-insensitive matching cannot become SQL. Sorts: name_asc (default),
name_desc, firm_asc, sessions_desc, rating_desc, last_active_desc. Missing values
sort last; ref is the stable tie breaker. Filtering and sorting happen before
paging. The backend projects metadata once, indexes relations by ID, then
filters/pages the complete identity set; there is no first-500 cutoff. This is
server pagination over the projected snapshot, not a SQL LIMIT before filtering.

Envelope: `{available,items,total,limit,offset,sort,filters,unreadable}`. A failed
identity source preserves known rows but makes available:false and total:null;
null never means zero. A requested search/filter source failure returns 503 with
`detail`/reason rather than a false empty match. Malformed skill JSON behaves
likewise. An unrelated enrichment failure leaves the list readable and that
column unavailable. `filters` supplies stored option values plus the sort list;
stage remains a Not recorded block.

Every item has ref, user_id/advisor_id (nullable), kind and name; wrapped columns
headline, firm, skills, sectors, stage, profile_check, kyc, lab_host, sessions_90d,
rating, deck, active_deals, hourly_rate, last_active, member_active.

- `user:<id>` joins accounts to advisor profiles only through advisors.user_id.
  Advisor profiles with no live account use `advisor:<id>`.
- `roster:<id>` remains a separate deck-only identity, even if its name matches a
  member. D974 (#2760) owns the future explicit roster link and archive semantics.
- Operating partners are partner-role accounts; a firm link comes only from
  users.partner_id. Roster company text is labelled source:roster_text and never
  becomes an account attachment. No email/name matching.
- Session totals are 90 days through as_of, with booked/completed/no_show/cancelled
  and total. Partner office hours belong to a firm; they never become a person's
  activity. Advisor ratings are count/average of founder reviews in the 1–5 range,
  not self reviews. Zero ratings means average:null.
- Deck has roster_id/shown/reach/position/has_photo. No R2 key is exposed. Member
  deck membership is Not recorded until D974. on_deck=true selects actual profile
  cards (first six), not merely hidden/named/counted roster rows.
- Hourly rate converts the existing whole-dollar advisor field to integer cents
  at this boundary; invalid values are unreadable. Last active uses the actual
  account activity stamp, never updated_at. Missing stages, links and KYC stay
  Not recorded, not inferred.

## Drawer — `GET /people/:ref`

Returns person (same public item), profile, work, terms, history, unreadable.
Malformed refs/healthy absent refs return 404; an unresolved ref during identity
source failure returns 503. Profile contains public advisor bio, wrapped stages,
languages, country, timezone, availability_note, weekly_hours, linkedin_url.

`work` has sessions_90d, explicitly labelled firm_sessions_90d for partners,
open_slots_14d (uncancelled slot count), cohort_assignments (cohort ID/assigned
stamp), engagements (counts only across drafting/proposed/signed/renewal_due/ended).
`terms` has hourly_rate, active_deals and Not recorded payout_readiness and
studio_agreement (D976). History is Not recorded until D974/D976 provides a read.
No engagement client names are selected, even temporarily; SQL aggregates lanes.
No reviewer identity, review text, booking topic/notes, member email, application
statement, proposal JSON, bank identifier or private photo key is selected.

`frontend/src/lib/api/adminNetwork.js` exports adminNetworkApi.overview(),
people(filters), person(ref), with one alphabetical api.js re-export. Query
whitelisting preserves false/zero and encodes opaque refs. API drift checks the
actual mount/client paths. No ROUTE_MAP row changes because no screen changes.

baseline/migrations. Gates cover auth, counts, time boundaries, privacy, money,

cents conversion, total-before-page, unreadable sources and branch settlements.

partial blocks and filter-source refusals. No tests are skipped.
