## D6285 — Research: drop the unmounted MarketZone body, list four pages in the README (#6285)

`frontend/src/pages/research/MarketZone.jsx`'s default export had been mounted
nowhere since D593 (`b9557713c`): `ResearchWorkspace` mounts
`MarketDirectoryZone` at `/research/markets`, and no module imported the
component, statically or lazily. Two mounted pages still imported four helpers
from it; four tests and one evidence entry read it by path (below).

**What moved.** `STALE_AT` (90), `AGE_AT` (30), `daysSince` and `ageBand` now
live in `pages/research/marketReadingRead.js`, unchanged, beside the other
readings of a market reading. `MarketReading.jsx` and `MarketDirectoryZone.jsx`
import them from there; the directory's change is that one import path.
`MarketZone.jsx` is deleted. No route, mount or Worker file changes.

**The README** loses its `MarketZone.jsx` row ("Markets.") and gains four at
the end of its table: `MarketDirectoryZone.jsx`, `GeographiesZone.jsx`,
`GeographyProfile.jsx` and `MarketReading.jsx`.

**Tests that read the dead file, and where their rules went.**

- `research_canvas_strips.test.mjs` read `MarketZone.jsx` for five rules. The
  windows, the never-run band and age-from-`ran_at` now run against the

  `daysSince(...)` call in the two mounted pages. The attachment gate is held
  on `attachState` and `ATTACH_COPY.blocked`, and on the reading page's own
  `stale` line. The tile-count rule is dropped: it guarded tiles only the dead

- `money_manual_conversion_5373.test.mjs` drops the deleted file's entry (its

- `siteIntelligence.js`'s `research-stale` claim cited `MarketZone.jsx`; its

Comments that named `MarketZone` as the live page are corrected; the ones that
