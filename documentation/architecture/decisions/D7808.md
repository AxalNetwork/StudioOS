## D7808 — The switcher's name and the rail's absent colour, checked in a browser (#7808)

- **Status:** built 2026-11-25. Follow-up to D7661 (#7661, PR #7695) and D7662 (#7662, PR #7696), filed on the owner's answer (A) of 2026-11-20.
- **Builds on:** D7517 (the fixture pattern and the axe tags), D7661 (the trigger's name), D7662 (`--fwr-absent`).
- **Test only.** No product code, no migration, no Worker route, no client method, no new dependency.

### The question

D7661 and D7662 were each proven in Chromium by a local scratch spec that was not committed, so only unit tests (`switcher_name_7661.test.mjs`, `rail_absent_contrast_7662.test.mjs`) kept them. A unit test reads the JSX or the stylesheet; it does not see the name Chromium computes, nor the colour the cascade ends on.

### The decision

One spec, `frontend/tests/e2e/switcher_rail_7808.spec.js`, with `expertise_axe_7517.spec.js`'s set-up: the built SPA (`docs/`) from its own local server with the Workers SPA fallback, a fixture advisor, invented `/api/*` answers in the Worker's shapes, every other origin aborted, the clock pinned. It opens `/expertise` at 1440 px, where the sidebar's switcher and the Worker rail both show.

- **Switcher (D7661).** `/api/company/memberships` answers `[]`, a 500, or one company. In light and dark, the `switcher-trigger` has no `aria-label` and its accessible name is exactly `switcherTriggerName()`'s sentence: "No company, switch company or project", "Unavailable, switch company or project", "Example Ventures, Company, switch company or project". The words drawn on the button open that name in order (Label in Name), and axe under the WCAG 2.0 to 2.2 A and AA tags finds nothing on the trigger. The expected names are literal strings, not imported, so a change to the function shows up here as a change to the name.
- **Rail (D7662).** The rail's model list is answered 404, which `railModels.js` turns into "Not recorded. The rail's model list has no row for this page yet." on `.fwr-absent`. In light and dark, axe under the same tags finds no violation anywhere in `aside.fwr`, and its `color-contrast` rule lists that line among its passes, not as incomplete, so the line was measured rather than skipped.

No axe rule is disabled. The rail scan covers the whole rail, so it also holds the rail's other text, which passed on main.

**CI.** The `visual` job of `.github/workflows/ci.yml` runs it after the Expertise step, on the `docs/` that job builds and its pinned Chromium, with `--retries=0 --trace off`. That step changes the `visual` job's digest in `frontend/test/ci_capacity_pilot_7909.test.mjs` (D7909), so the pin moves to the new digest, as #8537 did for its step. Locally: `npm run build` at the root, then `cd frontend && npx --no-install playwright test -c playwright.config.js tests/e2e/switcher_rail_7808.spec.js --trace off`.

### Tests

8 tests (6 switcher, 2 rail), passing on main. Mutation-checked against a rebuilt `docs/`:

- the switcher's sr-only sentence removed and the old `aria-label` put back: 6 of 6 switcher tests fail (the name reads "Switch company or project" and "Switch company or project. Current: Example Ventures, Company");
- light `--fwr-absent` set back to `var(--fwr-faint)`: the light rail test fails with `serious color-contrast: .fwr-absent`; the dark one passes, as it should, because the dark value was always `--fwr-faint`;
- dark `--fwr-absent` set to `#5f5a6b`: the dark rail test fails with the same violation.
