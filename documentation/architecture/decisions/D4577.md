## D4577 — Sign-in and registration labels name their inputs (#4577)

- **Status:** built 2026-11-07. No migration.
- **Builds on:** the Grow entry-flow audit of 2026-11-06, which found `/login`'s Email and `/register`'s Full Name and Email labels beside inputs with no id.

### What changed

`LoginPage.jsx` and `RegisterPage.jsx` give each visible label a matching `htmlFor` and its input an `id` (`login-email`, `login-totp`, `register-name`, `register-email`), so each input has its visible label as its accessible name and clicking the word focuses it. Input types, `autoComplete`, `inputMode` and styling are unchanged.

The page-level error is an `role="alert"` element with an id, and the inputs are `aria-describedby` it while it shows. The input a message is about (an empty or malformed email, a missing name, a short authenticator code) is also `aria-invalid`; the mark clears with the message, so a later error about something else (Google, a passkey) never marks a field invalid.

### Why a shared fix

#4646 (Learning) and the other Grow entry-flow items reuse these two pages, so they inherit the labels and add their own return-path coverage; no second edit to the same fields is needed.

### Verification

`auth_labels_4577.test.mjs` pairs every label with its input in the JSX. The visual check at desktop and phone widths could not be run in this sandbox (the frontend dev server needs a package that is not installed here), and the change adds attributes only, no class or style, so it is outstanding for the PR's reviewer to confirm on a preview.
