## D4713 — Practice financial history is not restated, "received" means collected, and period edits cannot cross periods (#4713)

- **Status:** built by slot S21 on 2026-11-07. Closes #4713 (Practice audit 4/6, P0/P1).
- **Migration:** `202611071525_advisor_booking_price_events.sql`: one table, the audit trail of a reprice. No existing column changes.
- **Builds on:** migration 241 (the stored take rate and cut), 205 (the advisor's own billing note), D4 (the Earnings canvas).

### What was wrong

1. A booking's billing PATCH re-read the **current** platform take rate on every write and rewrote the stored rate and cut, even when only `billing_state` changed. A $100 session priced at 15% / $15 became 12% / $12 when marked collected after the setting moved.
2. Earnings labelled priced work "You received", although most of it was never collected.
3. Earnings committed period-specific reads without checking the period was still selected, kept the old note on screen while a new period loaded, and saved or deleted against the **selected** period's key rather than the displayed note's.
4. Sessions started with empty availability defaults and allowed its editor while the first read was in flight; the PUT replaces the whole rule set, so an early save wrote the defaults over the stored timezone and blackouts.

### What was decided

**Financial terms are snapshotted when a line is priced, and only repricing changes them.**
- `PATCH /me/bookings/:id/billing` compares the requested amount with the stored one. Unchanged amount (a status-only change, or the same amount sent back with a state): the stored `take_rate_bps` and `platform_cut_cents` are kept, whatever the setting reads now.
- A changed amount is a **reprice**: it is stamped at the current rate, and a row goes to `advisor_booking_price_events` with the actor, the admin behind an impersonation if any, and the amount, rate and cut before and after. Pricing a line for the first time is not a reprice and writes no event.
- A line the advisor has recorded as **collected** or **written off** is settled history: a changed amount answers 409 `price_settled`. Clearing a billed line's price is a reprice and is audited.
- The settled rule is this PR's call, because the issue left it open. A collected or written-off amount cannot be edited in place, which is what keeps a reconciled period from moving; it can still be corrected in two explicit steps: the advisor moves the line back to billed (a status-only change, which keeps the stored rate), then reprices it (audited). The same holds for an admin acting under impersonation.

**Distinct figures, and "received" means collected.**
- `GET /me/ledger` adds `figures`, each `{ gross_cents, cut_cents, net_cents, sessions }` at every line's own stored rate:
  - `priced`: every priced line;
  - `billed`: ever billed (billed, then collected or written off);
  - `collected`: lines the advisor recorded as collected;
  - `written_off`;
  - `outstanding`: billed and neither collected nor written off.
- `billed = collected + written_off + outstanding` by construction.
- It also adds `recorded_payouts`: `{ available: true, paid_cents, payouts }` from `advisor_payouts` rows in state `paid` whose `paid_at` falls in the window, or `{ available: false }` when the ledger cannot be read. It is never a guessed zero.
- Earnings no longer says "You received" for priced work. The tile reads "Recorded as received" and shows the collected net; the first tile is "<period> priced"; the table's last column is "Net of cut"; the CSV and the AI narrative carry the same definitions. The canvas D4 drew "gross" and "You received"; this is a deliberate departure from that artboard, and `advisor_practice_pr5.test.mjs` pins the new labels beside the canvas's own.

**Earnings is bound to a period key.**
- `createPeriodGate()` issues a token per period request; the ledger and note reads commit only while their token is current, so reversed responses cannot paint one period's figures under another's label.
- On a period change the ledger, the note, the draft, the model text and the notices clear at once.
- Accept, Discard and the AI draft are tied to the period the displayed note was read for (`noteKey`). They do nothing before that note has been read, and a result that returns after a switch is dropped.
- Discard deletes only a note that exists for the period shown.
- A note edit that is not filed (`noteIsDirty`) is resolved first: switching asks to discard it, and declining keeps the period and the draft.

**Availability replacement is guarded.**
- Sessions reads its rules as `loading`, then `read` or `unreadable`. The editor exists only for `read`; the summary shows "Reading…" until then.
- `GET /me/availability` returns a `revision` (`''` when no rules exist yet). `PUT` accepts an optional `expected_revision`: the compare and the write are one statement, so a stale tab's save matches no row and answers 409 `rules_changed` with the current rules, overwriting nothing. Omitting it keeps the unconditional replace the route had.
- Editing one field sends the rest as read, so the timezone and blackouts survive.

### Not decided here

- A repricing UI. The Worker route accepts a new amount on an uncollected line today (that is the Sessions "What each session was worth" form); a separate explicit "Reprice" control with a reason field would be a design change.
- Truncation of the ledger at 2,000 rows (`LIMIT 2000`) is #4702's, which reworks the ledger, CSV and annual summary together.

### Tests

- `advisor_money_model.test.ts`: six new tests for the status-only snapshot, the audited reprice, the settled guard, the distinct figures, recorded payouts, and availability CAS (both the insert and update paths).
- `practice_financial_4713.test.mjs`: the gate, the received figure, dirty notes, and three mounted Earnings tests (reversed responses, switch-and-save, dirty switch) plus Sessions' guard.
- Each was checked by a mutation the test catches (reprice on every write, no audit, no settled guard, collected taken from every priced line, no CAS, gate always current, ledger not gated, accept keyed by the chip, dirty ignored, rules seeded as read).
