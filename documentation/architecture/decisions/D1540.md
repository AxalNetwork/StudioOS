### 1. A founder reports a bad result

`POST /api/decks/proposals/:uid/report` `{ reason, note? }` (`routes/deck_reports.ts`, mounted at `/api/decks` before `decks`).

- **What can be reported.** A deck rail proposal (`ai_rail_proposals`, page "Founder · Raise · Pitch deck") that is the caller's own, decided or not. Any other uid, another member's, or one from another page answers the same 404, so a uid is never confirmed to exist.
- **What it records.** `deck_proposal_reports`: a reason code (`wrong_figure`, `poor_writing`, `wrong_place`, `bad_image`, `unsafe`, `other`), an optional note of at most 280 characters, and the proposal's option, model and usage row, copied so HQ reads what ran even after the proposal is gone. One report per proposal and member: a second answers 409 `already_reported` with the first.
- **Who.** The member, never a support session (403 `support_session_refused`).
- **What it does not do.** It refunds nothing and changes no proposal. A run that failed was never charged (D844 releases a hold on throw, timeout or cancel). A refund for a result that ran is HQ's call through the token ledger's own adjustment, not this route.

**The control.** `AreaResults.jsx` (S1's proposal cards, D1604) gains a small "Report this result" link on each result that has a proposal uid. It opens a reason and an optional note in place, and Send records the report. A result already reported reads as reported; any other refusal shows the Worker's sentence. Nothing on the card changes. No new surface: no board draws a report control (the issue says so), so the control is the smallest addition to the existing cards.

### 2. HQ's queue

`GET /api/admin/deck-reports?status=open|resolved|all` and `POST /api/admin/deck-reports/:uid/resolve` `{ outcome: addressed|no_fault, note? }`, both `requireHqAdmin` (a branch is refused). The queue answers each report with the proposal's status and payload and the run's charge (null when not recorded, never 0). A resolution is written once (`WHERE status = 'open'`); a second is 409 `already_resolved`. Every read and every resolution is in the admin audit log, without the founder's note. The client methods are in `lib/api/deckReports.js`; the HQ page that draws the queue is B10's (#3786), out of scope here.

### 3. Pinned quotes

`POST /api/decks/new/quote` now stores what it showed for the outline and the whole-deck build (`deck_run_quotes`): the hold, the price list it was made under (`pricing_version`), and a hash of the run it priced. It answers `quote_uid` and `pricing_version` beside `hold_microusd`. A card's quote is shown, not pinned.

- **The price list.** `pricingVersion(env)` (`services/ai/pricing.ts`): the catalogue's Cloudflare pricing page date, the outside providers' price version, whether runs settle at cost or billed (`AI_BILLING`), and the markup.
- **The pin.** `/outline` and `/generate` take `quote_uid`. `takeQuote` takes it once, for this member, venture, step and exactly this run (one conditional write, so two presses cannot both use it), and the run gets `RunOptions.pinMicrousd`. In `run()` the hold is no larger than the pin and every settlement is capped at it; the run's own row records its share after the guard's. So a quote made before a price change settles at no more than the quoted price, whether the price changed before the run, during it or after it. A run that cost less pays what it used, as before.
- **A quote for another run is refused.** The hash covers the task, model, rail option and record, system prompt, messages and output allowance, so a six-card quote cannot cap a sixteen-card build. The per-message nonce on the untrusted-record fences (`ai/untrusted.ts`) is left out of the hash; the words inside the fences are kept. A quote that was used, lapsed (two hours), priced another run or is not the caller's answers 409 `quote_stale` and runs nothing. A run refused before it charged gives its quote back.
- **The one-click.** `OneClickBuild.jsx` sends the quote it showed with Build, asks for the price again after a build, and asks again on `quote_stale`.
- **A quote that could not be stored** is answered without `quote_uid` (the run is then unpinned, as before), with a warning that names no member.

### 4. The markup

AA's 1.25× is `AI_MARKUP` in `services/ai/pricing.ts`, which was already the one figure every quote, hold, settlement and price read uses (D760, D762). Nothing new was added; the test pins it at 1.25 and checks the `admin` licence still pays cost.

### 5. The owner's daily ceiling

#3761 (A17, D1510) owns the deck ceiling's alerts and its reach over area and autopilot runs, and it is not on main (state: blocked). So this issue adds the ceiling as owner-set configuration, once, for #3761 to build on rather than build again:

- `DECK_DAILY_CEILING_MICROUSD` (a Worker variable, not in `wrangler.toml`): what deck generation may charge across every member in one UTC day. Unset, empty, 0 or unreadable is **off**: nothing pauses until the owner sets it.
- `ceilingRefusal` (`services/decks/runQuotes.ts`) sums today's charged Pitch deck runs and refuses a run whose quote would pass the ceiling: 429 `deck_ceiling_reached`, "Generation is paused for today. Manual editing still works." (the sentence #3761's revision gives), before any hold. Once set, a spend that cannot be read pauses generation too.
- Applied on `/outline`, `/generate` and `/proposals/:id/regenerate-card`. `refusalOf` draws the message as-is; a 429 gets no "Add tokens" link.

### 6. The upgrade path returns to the AIRail

`refusalOf`'s plan link (`newDeckModel.js`) already goes to `/pricing` with no return address: the lightbox is page state, never in the URL, so coming back from the plans page lands on the pitch page and its AIRail, never the lightbox. ### 7. Departures

- The ceiling counts settled charges, so runs in flight at the same moment can each pass the check; the overshoot is at most those runs' holds.
- The ceiling is not applied to the card assist, image or area routes. #3761's revision makes it cover every generation route; `ceilingRefusal` is exported for that.
- `deck_run_quotes` is a new table: there was no stored quote on main to add `pricing_version` to.
- No `deckV2Adapter.js` method was swapped, so no contract was added (the issue names none for this task).

### 12. UPDATE (#4188, part of D4155): HQ's queue reads by name, and a resolution needs a note

D4155 (#4155, HQ › Decks) is not on main yet (it is in PR #4194), so K1's Worker part is recorded here. No migration: everything is read from what is already stored.

- **Each report row gains** `founder: { uid, name }` (the member who filed it: `users.uid` and `COALESCE(display_name, name)`, never an email; null when the account is gone), `deck: { uid, title, version }` (the version the result was made on, from `record_ref` `deck:<id>` or the payload's `deck_id`; `uid` is that `pitch_decks.id` as text, because versions have no uid column), `card: { index, label }` (`index` from 0 as every deck route counts, found by the payload's `card_uid` first and its place second; `label` "Card 4 · Traction" from that version's slide title, or the catalogue's title for the slide's kind, or "Card 4" alone), `asked` (the press in the editor's words: "Shorten", "Change tone · warm", "Translate · French", "Instruction · “…”", "Speaker notes", or "Outline" and "Build the deck" from a new-deck run's option) and `before` and `after` (the assist's words, or a one-card transform's notes or blocks). Each is null when not recorded, never "" or 0. A deck version that cannot be read leaves `deck` null on its rows; the queue still answers.
- **What was asked is now stored.** `deck_assist.ts` keeps a press's `tone`, `language` and `instruction` on its proposal's payload. Proposals made before this read the action's label alone ("Instruction" for an older Ask).
- **Filters.** `GET` takes `model` (an exact id, at most 200 characters, else 400 `invalid_model`) and `reason` (one of the six codes, else 400 `invalid_reason`); an empty value is no filter. Both are bound parameters.
- **Counts.** `counts: { open, resolved_this_week }` over the whole queue, whatever the filters; "this week" is since Monday 00:00 UTC. Each is its own read and is null when that read fails, never 0.
- **Resolve.** `note` is required: at least 10 characters trimmed, else 400 `note_required` (`invalid_note` for a note that is not text and `note_too_long` past 500 stay). The founder reads it as `resolution_note` on their report. The audit row (`deck_report_resolved`) keeps the note and names the admin (`admin: { uid, name }`, beside `admin_user_id`); the founder's own note is still never logged. The read's audit row records the filters.
- **Where the founder reads it.** There is no founder-side read of a report on main: the only reply that returns a founder their report after HQ resolved it is the 409 `already_reported` of a second report, which carries `resolution_note`. A founder-facing view of resolved reports is not built here.
- **The frontend.** The names and shapes are the ones `reportRow` in #4194's `hqDecksModel.js` reads (`founder.name`, `deck.title` and `deck.version`, `card.label`, `asked`, `before`, `after`), so wiring is `BUILD.K1.live = true`. `lib/api/deckReports.js` needed no change (its `resolve` already sends a note when given); its header comment now says the note is required.
- **Tests.** `cloudflare-worker/test/deck_reports_queue_d4155.test.ts` (10 tests); `deck_reports_pricing_d1540.test.ts`'s two resolve calls that expected 409 and 404 now send a note, since a note-less call now answers 400 first; `deck_assist_d899.test.ts` checks the Ask's instruction is on the payload. Nineteen mutations, each caught.
