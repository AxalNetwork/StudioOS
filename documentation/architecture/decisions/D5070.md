## D5070 — One safe error path for the Raise surfaces (#5070)

- **Status:** Built, 2026-11-08 (frontend only).
- **Builds on:** D258 (`request()` puts the Worker's sentence on `e.message` and its code on `e.code`), D5069 (the `changed_since_open` conflict and its recovery).

### What was wrong

About eighty places across Capital relationships, Investor narrative, Data room, Cap table, Use of Funds, Evidence and the Raise panels rendered `e.message` (or `e.detail`, `e.data.message`) straight into the page. `e.message` is whatever was thrown: a Worker sentence, but also `Failed to fetch`, a `TypeError`, a JSON parse error, or text a provider or the database put in a 5xx body.

### The rule

`frontend/src/lib/raiseErrors.js` — `userFacingRaiseError(error, { fallback, sentences, scope })` is the only way a Raise surface turns a failed call into text.

1. **A taxonomy code → its approved sentence**, whatever text came with it: `invalid_input`, `forbidden`, `changed` (`changed_since_open`, `scenario_changed`, …: D5069's conflict), `not_found`, `unavailable`, `rate_limited`, `pricing_unavailable`, `conflict`, `plan_required`, `signed_out`.
2. **A Worker refusal outside the table keeps its sentence** — the one allowlisted contract. It needs all of: an HTTP 4xx, a machine code, and text that reads as a sentence (3–300 characters, not a bare code, nothing that looks like SQL, a stack, a file path or a provider's text). Worker refusal bodies are authored sentences (`util/refusal.ts`, `PlanError`), which is why `invalid_plan` ("Use of Funds must total exactly 100%.") and `project_has_cap_table` are not in the table: a generic line would lose which field or what to do.
3. **A status with no code** (401, 402, 403, 404, 409, 410, 422, 429) → the taxonomy's sentence for it.
4. **Everything else** — a 5xx, no response, a thrown browser error, an unknown shape — is the caller's `fallback`, or the generic `unavailable` sentence. The raw error goes to `reportWarn`, never to the page.

A page that composes its own sentence and rethrows it uses `safeRaiseError(sentence)`; the mapper shows that as is. `raiseValidationErrors(error)` keeps a 400's `errors: [...]` list only where each entry is a sentence.

### Where

Every `catch` and read-state in `pages/raise/{caprel,narrative,dataroom,captable,useoffunds}`, `pages/cycles/evidence` and the Raise panels (Advisor access, Round closes). Pure models changed too: `runRefusal` (Story), `coachFailure`, `accessRefusal`, `variantSaveErrors`.

### Tests

- `raise_errors_5070.test.mjs`: injects internal codes and messages (D1 errors, `Failed to fetch`, a TypeError, a provider key, a stack, a constraint failure) and proves none is shown; the taxonomy; the Worker-refusal contract and its edges (no code, a 5xx); validation lists.
- `raise_no_raw_error_5070.test.mjs`: scans every file in those folders and fails on `e.message`, `e.detail` or `e.data.message` outside the one allowlisted line (`accessModel.js`, which reads the raw text only to test it with `isSentence`).
- Existing Raise tests that asserted a raw Worker message for a code-less 403/404 now assert the approved sentence.

### Not covered

- D5376 brings `pages/raise/pitch/` (the deck builder) into the same mapper and source scan. It is no longer excluded.
- A 4xx Worker refusal with a code outside the table is shown as the Worker wrote it. If a Worker route puts internal text in such a body, the Worker's refusal-body guard (`check-refusal-bodies`) is what catches it, not this mapper; the mapper's screen is a second net, not the first.
