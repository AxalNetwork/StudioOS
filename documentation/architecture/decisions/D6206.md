## D6206 — Positions read returns each company's distributed total; Performance cohorts show Distributed, DPI and TVPI (#6206)

Under #5311 (addendum PFA07). Builds on D6201 (#6201: an unreadable sub-read is Unavailable, never an empty set), D6207 (#6207: the dated basis) and D6887 (#6887: `GET /api/positions?as_of=` cuts the rows at the date). It replaces D4817 part 3's "Vintage cohorts show carrying value ÷ invested, not TVPI". That choice held only because the positions read carried no distributions per company. It now does.

**Where distributions are stored.** `portfolio_distributions` (migration 168): one dated row per realisation from a portfolio company back to the fund, with `project_id`, `fund_id`, `distribution_date` and `amount` in real dollars. It is the store `/api/positions/analytics` already sums. It is not `fund_distributions` (fund to LP, in cents). No schema change, and no new store.

**Worker.** `GET /api/positions` (`cloudflare-worker/src/routes/positions.ts`, `distributedByProject`):
- Each row carries `distributed`: Σ that company's recorded distributions. The scope predicate is the one `/analytics` uses (a held company, or a distribution attributed to a fund the caller runs as GP of record), and so is the rule: a positive amount with a `YYYY-MM-DD` date. A company with nothing distributed reads a measured `0`.
- `?as_of=` cuts the distributions on or before the date, the same cut as the cheques (D6887) and `/analytics`.
- The answer adds `distributions`: `{ available: true, total, unlisted }`. `total` equals `/analytics`' `distributed` for the same date. `unlisted` is the part recorded against a company with no listed position, so Σ rows + `unlisted` = `total`.
- When the distributions query fails (thrown, unsuccessful or malformed, D6201's `hasQueryResults`), the answer is `distributions: { available: false, reason: 'Portfolio distributions could not be read.' }` and each row's `distributed` is `null`. Only distributions are unavailable. The rows, invested, marks and the 200 status still answer, because the list is the page's spine and a missing realisations figure is not a missing book.

**Frontend.** In `frontend/src/pages/portfolio/portfolioModel.js`:
- `distributionsOf` reads that state: `ok`, `unavailable` (D5129's word for a read that did not answer), or `not_recorded` when the answer carries no `distributions` field at all (a Worker from before this change). It is never `$0`.
- `cohortsOf` gives each cohort `distributed`, `dpi` (distributed ÷ invested) and `tvpi` ((distributed + carrying value) ÷ invested), each a `{ value, state, reason }` cell. A cohort with nothing distributed shows `$0` and DPI `0.00×`. A cohort where one company has no figure while the read was ok shows Not recorded, not a partial sum. It adds `total`, the Book row: every listed position, undated ones included, plus `unlisted`. So the Book row's invested, distributed and TVPI are the book's own figures. `multiple` (carrying ÷ invested) stays because the statement still prints it.
- `registerRowsOf` gives each Positions register row `distributed`, `distributedRaw` and `distributedState`. The register draws no column yet (the issue made it optional).
- `cohortExportOf` writes `Vintage, Companies, Invested, Distributed, Carrying value, Carried at cost, DPI, TVPI, Basis, As of`.

In `InvestorPortfolioPerformance.jsx`, the Cohorts table has the columns Vintage, Companies, Invested, Distributed, Carrying value, DPI and TVPI, plus a Book row in its footer. When distributions fail, those three columns read Unavailable, with the reason in a tooltip, and a line under the table says so and offers Retry. Invested and carrying value stay drawn.

**Not built.**
- No Distributed column in the Positions register. The model carries the field, so adding the column later is a view change only.
- The quarterly statement PDF's cohort page (`lib/portfolioStatementPdf.js`) still prints carrying ÷ invested, with its old note that distributions are not recorded per company. That note is now out of date. Correcting it is a separate change to the statement.

**Verified.**
- `cloudflare-worker/test/positions_distributed_6206.test.ts`: per-company totals under the analytics rule, a measured 0, the `as_of` cut (inclusive), reconciliation with `/analytics`' `distributed`, and the four failure shapes answering 200 with only distributions unavailable.
- `frontend/test/portfolio_cohorts_6206.test.mjs`: the model's five figures, `$0`, Unavailable only in those columns, Not recorded for an older read, the reconciling Book row, the register field, and the mounted page in both states.
- Both files are mutation-checked both ways. Their headers list each mutation.
