## D6724 — Isolate AWS CodeBuild runner trials for the merge queue (#6724)

StudioOS will benchmark one candidate at a time before changing merge-group routing. The nine suite shards are the unit of comparison. An independent GitHub-hosted planner and gate allow the comparison to include time spent waiting for those jobs. Run three GitHub controls and three CodeBuild trials on the same reviewed commit under the conditions in D5611 and #6676.

Only the three reserved CodeBuild benchmark branches select the AWS project. The selector requires the expected repository, a push, both readiness flags and numeric run and attempt IDs. The report requires complete successful suite coverage and a matching per-attempt runner label plus an assigned runner on every AWS shard. Actual hardware and charges are joined from CodeBuild records.

The [project template](../../operations/CODEBUILD_RUNNER_6724.yml) describes a webhook-disabled Linux/Large project capped initially at nine builds. The [operator guide](../../operations/CODEBUILD_RUNNER_6724.md) covers independent authorization of public repository jobs, a dedicated CI account, region-specific quota, billing evidence and rollback. Live activation and the production selector are tracked under #6677.

Eighteen focused benchmark and scorecard tests passed. AWS CloudFormation validated the template in Frankfurt. Live authorization, speed and cost require an actual trial.
