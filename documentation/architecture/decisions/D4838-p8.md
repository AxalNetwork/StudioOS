## D4838 part 8 — PP08: the shared opportunity sheet (#4838)

Built 2026-11-15 by S22 for #5934. Part of D4838 (Pipeline v2); boards PP08 and PP08m.

- **`pages/partner/pipeline/OpportunitySheet.jsx`** is one sheet for a lead, a proposal, a negotiation and an engagement. It sits on the app's detail sheet (`ui/Sheet.jsx`, D1317). That sheet traps focus and returns it, closes on Escape and ×, and is full screen below 640px. The sheet passes `phone="full"`, so PP08m stays full screen even where a page asks for bottom sheets.
- **One identity, joined by id.** A caller passes whichever of `needId`, `quoteId` or `engagementId` it holds. A proposal is found by its quote or its need. A negotiation is found by its quote. An engagement is found by the `engagement_id` its proposal carries, because a retainer row does not carry its need. Nothing is joined by name.
- **The reads are the zones' own**, `/partner/pipeline/{leads,proposals,negotiations,retainers}`, each read to the end as the zones read it. Activity uses D5942's `/partner/pipeline/activity?need_id=`. No route was added.
- **The header** shows the client (else the opportunity's title), the stage with its state ("Negotiation · Terms", "Proposal · Lost") and a stage tracker. It also shows the value at the current stage: the monthly equivalent, the price or the lead's stated budget. With no value it reads Not recorded, never $0. The source is the Leads read's `source_label`, else "Marketplace need" for anything on a need.
- **Tabs appear only when their record exists.** Overview and Activity always appear. Fit appears for an open lead, Proposal for a quote, Terms for a tracked negotiation and Engagement for an engagement.
- **Activity lists recorded events only.** It shows a passed lead, a proposal version, a decision, the latest negotiation move, and a retainer created or ended. With none it reads Not recorded. It draws no event from a stage, and it leaves out a feed kind it does not know.
- **Failure.** If all four reads fail, the sheet shows Unreadable with Try again. If one read fails, the rest of the sheet still shows and names the read that could not answer. A failed activity read is Unreadable in its tab. A read that stopped before its end without finding the record counts as unreadable, not as absent.
- **#4685's rule.** The read loop is `usePipelineZone`. A background refresh (`refreshKey`, Try again) keeps the open tab and any editor a zone mounts in it (`editors`). A source that fails on refresh keeps its last good record, so its tab and editor stay. The hook's new optional `key` makes a different opportunity a first read again.

### Where PP08 departs from the canvas or the issue

- **Activity reads the feed.** The issue says Activity reads Not recorded "until a lifecycle feed exists". D5942 (#5942) merged that feed the day before, so the tab lists what it records and reads Not recorded only when nothing is recorded. The feed keeps only a negotiation's latest move, and the tab says so.
- **Overview is the first tab, not Activity.** The canvas opens on Activity. The issue lists Overview first, and the feed is often empty for a new lead.
- **The fourth stage reads "Retainer" only when a retainer is recorded,** else "Engagement". The canvas draws "Retainer" and the issue says "engagement".
- **Not yet opened from a zone.** The zones expand rows inline today and open no sheet. The zone issues wire `OpportunitySheet` in, and can pass a zone's editors through `editors`.
