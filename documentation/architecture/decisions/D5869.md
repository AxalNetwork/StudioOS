### 1. The source on every event (§gaps 7)

`shapeEvent` in `cloudflare-worker/src/services/eventsCommon.ts` returns `source`. Every event is
Axal's today, because the owner decided Axal events only (D1487, question 1), and no column records
anything else, so the value is the constant `EVENT_SOURCE_AXAL` (`'axal'`). Every read that shapes an
event carries it: the public list and detail (`events_public.ts`), the signed-in event reads
(`events.ts`, `admin_events.ts`) and the recommended read, which used to set `source: 'axal'` on its
own and now takes it from `shapeEvent`. The public calendar feed (`/api/public/events.ics`) is built
from the same shape and is unchanged: no ICS line reads the field.

### 2. The badge (ME5)

The frontend reads the field and does not assume it. `sourceLabel(event)` in `myEventsTabsModel.js`
answers `Axal` for `source: 'axal'` and `null` for an event with no `source` or one it does not know;
`SourceBadge` in `MyEventsTabs.jsx` draws it, ME5's small outlined badge, or nothing. It is on each
Discover row (beside the type), each Discover suggested card, and each recommended card, where it sits
after the type as ME5's card draws it. The recommended card used to draw the badge when `source` was
missing too; it no longer guesses.

Discover's filters end with ME5's dashed chip, "External events · Not enabled", which is a note and
not a control, and the line "Axal’s own events only." The canvas's "(pending owner)" is dropped: the
owner decided it (D1487).

### 3. The row on the phone (§gaps 16, ME11a)

`PhoneUpcoming` in `MyEventsPhone.jsx` draws "Recommended for you" between Needs you and the week
strip. It is `RecommendedRow` with `layout="swipe"`: the same cards, Save, Not for me (with Undo), Why
this? and Tune, in one row of 290px cards that scrolls sideways inside itself (`overflow-x-auto`,
snap), so the page never scrolls sideways. `MyEventsPage.jsx` passes it the page's own recommendation
read and `RECOMMEND_ACT`, the read and writes the desktop row uses (`recommendationsAdapter.js`).

The states are the desktop's (`rowState`), through `phoneRowState` in `myEventsPhoneModel.js`:
loading (a skeleton), Unreadable with Retry, too few signals, empty and ready, each under the row's
title. The phone has no Suggested card to fall back on, so two differ: recommendations turned off in
Tune draw no row at all, and "not available" in the desktop's words, which point at the Suggested card
below, becomes "Recommendations aren’t available right now." (the Worker's own sentence is kept when
it gives one). An Explorer's pick with no reason of their own reads "Popular with new members", as on
desktop.
