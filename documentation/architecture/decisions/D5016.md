### The catalogue

There are 49 sovereign markets: the 27 EU member states, plus every non-EU country in the StartupBlink top-40 that the issue lists. That is 40 listed countries plus the 9 EU members missing from that list:

- Romania
- Malta
- Cyprus
- Hungary
- Greece
- Slovenia
- Slovakia
- Croatia
- Latvia

Each seeded row holds only what is not an external measurement:
- the ISO 3166-1 alpha-2 code;
- the name;
- a planning region (`EU`, `EUROPE`, `NAM`, `APAC`, `MEA`, `LATAM`);
- the ISO 4217 currency.

Bulgaria and Croatia use the euro.

`strategic_note` tells the two groups apart:
- The 40 listed countries read *"Listed in the StartupBlink top-40 supplied with #5016; its score and rank are not recorded until imported with their source."*
- The 9 absent EU members read *"…no ecosystem score is recorded, and none may be until HQ approves a source or a provisional proxy."*

### The decisions

1. **No external figure is seeded.** Population, PPP and the startup score and rank are all NULL with status `not_recorded`, for all 49 markets.
   - The issue's source policy requires every recorded value to carry its source, reference and as-of date.
   - The StartupBlink scores and ranks, and the population and PPP figures, did not arrive with the issue as data. The issue text lists only country names. The image it mentions is not in the repository, and no dataset was attached.
   - A figure transcribed from memory would be exactly what the issue forbids: a value passed off as a sourced fact.
   - The engine refuses to price a market with a missing input, so nothing is mispriced in the meantime.
2. **Observations are history; the profile holds the current fact.**
   - `country_market_observations` is append-only by trigger. A row is either a sourced value or a status change.
   - The database refuses a value observation without a source and an as-of date, a `not_recorded` observation that carries a value, and any observation without a reason.
   - Each row records who made it, when, why, and the profile revision it produced.
3. **Every write names the revision it read.** The profile `UPDATE` matches on `revision`, and the observation is inserted in the same batch `WHERE changes() > 0`. A stale write changes nothing and answers `409 profile_conflict` with the current revision.
4. **One literal statement per kind of write.** A field's columns are updated by a single SQL text that uses bound `CASE ?1 = field` expressions. No SQL is built by interpolation.
5. **Provisional is an explicit act, and only on an existing value.**
   - A value can be recorded as `provisional`, or a recorded value marked `provisional` (`409 no_value` when there is none). This is how HQ approves a proxy for one of the 9 absent EU members.
   - `not_recorded` clears the value and its provenance.
   - A rank is recorded or cleared; it has no provisional state.
6. **The bulk import is all or none per country.**
   - Every row is validated before anything is written, and each country names the revision HQ read.
   - Each row after a country's first also requires the previous row's observation to exist. So if another write lands on exactly the revision a later row expects, that row still does not apply.
   - Countries that conflicted are reported (`207`); the others apply.
7. **A profile change affects only future recommendations.**
   - Snapshots are append-only (D5014), and a snapshot verifies from its own columns (D5015).
   - Recording a new value changes the next preview's digest and figures. It never changes an existing snapshot, the decision made from it, or any licence row.
8. **The v1 model is seeded as a draft.** It is exactly the engine's `V1_MODEL_DRAFT`, and a test holds the two together. HQ activates it, or edits it first. Nothing is priced on a model nobody chose.

### API (Super Admin, HQ only)

Writes require the write bar, a reason of 3–500 characters, and the expected revision, and are audited through `logAdminAction`.

| Route | What it does |
|---|---|
| `PATCH /api/admin/licence-pricing/countries/:code` | Updates the name, region, currency, regulatory class (`low`/`medium`/`high`/`very_high`, a planning input) and notes |
| `POST /api/admin/licence-pricing/countries/:code/observations` | Records `{ field, value, status, source, source_ref?, as_of }` as the field's current value |
| `PUT /api/admin/licence-pricing/countries/:code/fields/:field/status` | Sets a field to `{ status: provisional \| not_recorded }` |
| `POST /api/admin/licence-pricing/countries/import` | Imports `{ observations: [...], expected_revisions: { CODE: n }, reason }`, at most 500 rows |
| `GET /api/admin/licence-pricing/countries/:code/observations?field=` | Returns the history, newest first |
| `POST /api/admin/licence-pricing/countries/:code/preview` | Takes `{ model_uid?, allow_provisional? }`, calculates now and stores nothing. It uses the active model unless one is named, and needs Super Admin but not the write bar. |

D5014's list and search route covers "list/search profiles".

### What waits on HQ

The figures, each with its source. The import route takes them as they come from the source. Values are integers:
- population, as a count;
- PPP GDP per capita, in whole international dollars;
- the startup score, in thousandths of a point;
- the rank.

The datasets the issue names:
- **Population.** For example, World Bank WDI `SP.POP.TOTL`.
- **PPP.** For example, IMF WEO, or World Bank `NY.GDP.PCAP.PP.CD`.
- **StartupBlink.** The top-40 scores and ranks, taken from the supplied image or the published index.

### Tests

`cloudflare-worker/test/licence_pricing_catalogue_5016.test.ts` (9 tests):
- the exact 49 codes, 27 of them EU, with ISO2 codes and ISO 4217 currencies and no figure seeded;
- the 9 absent EU members told apart in their notes;
- the seed is re-runnable and never overwrites a profile HQ has edited;
- the seeded draft equals `V1_MODEL_DRAFT`;
- observations require their source, as-of date, reason and revision, and are kept as history;
- a stale write gets a `409` with the current revision;
- provisional and not-recorded behave as described above;
- profile details are revision-checked;
- the import is all or none per country, including the case where a revision is matched by coincidence, and a bad row stops everything;
- a new observation changes only future previews, while the old snapshot and its decision still reproduce and the licence is untouched;
- access control is enforced.

The D5014 and D5015 tests now start from an empty catalogue, because this migration seeds one.
