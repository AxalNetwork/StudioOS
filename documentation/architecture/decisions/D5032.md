## D5032 — HQ Support: one versioned ticket SLA policy, carried to every branch (#5032)

- **Status:** Built, 2026-11-08 (Worker, migration and frontend). HQ Support audit 3 of 6.
- **Migration:** `202611082049_support_sla_policy_version.sql` adds `support_sla_policy_state`, a single row: `version`, `source` (`hq` | `pushed`) and `applied_at`. Every database runs it, and there is no seed.
- **Builds on:** D482 (the tier store), D455/D459 (ticket bands), D137/D272/#4686 (the licence push, its revision and its retry), D4805 (the push is owed from the commit).

### What was wrong

HQ edited P1/P2/P3 at `PUT /sla-tiers`, but the branch copy was held. Each branch banded its own tickets (`slaForTicket`, from its own `hq_support_sla_tiers`) with the hours it shipped with, and nothing told HQ which hours those were.

### The policy has a version

- A save that changes a tier advances `support_sla_policy_state.version`. The tier rows, the version and one `licence_push_pending` row per deployed licence are one D1 batch, so a committed save always leaves its distribution owed.
- A save that changes nothing makes no version and sends nothing.
- A policy that was never saved is numbered 1 the first time it is distributed (`slaPolicyForCopy`). Until then, HQ shows "Policy not yet numbered".

### It travels in the licence copy

- `assembleLicenceRecordDetailed` adds `support_sla_json`, which holds `{ version, tiers: [P1, P2, P3] }`.
- A database without the store omits the section, and the branch keeps what it has. Any other read failure makes the push partial (#4686's rule).
- On the branch, `applyLicenceCopy` writes the section through `applySlaPolicyCopy`: the three tier rows and the state row in one batch. Each statement re-checks the version inside the batch, so an older copy never replaces newer hours, even when two copies race.
- A stale copy is not a failure.
- The escalation-kind hours (`SLA_HOURS`) are a separate promise and are not in the copy.

### Each branch says which version it applies

- `branchOpenTickets` now also answers `sla_policy`, the branch's own version read.
- HQ's full read reports each branch in one of these states:
  - `current`
  - `stale` (another version, or none)
  - `unreported` (a deploy older than the report)
  - `unreadable`
  - `not_deployed`
- It also gives `current` of `total`. `complete` is true only when HQ's version is known and every branch is current.
- The panel reads "Policy vN · applied on X of Y branches" and lists each branch that is behind, with its reason.

### The save reports the distribution

After the commit, each deployed licence's push runs inline with a 5-second deadline (`SLA_PUSH_DEADLINE_MS`). The answer lists each branch as `applied`, `failed` (it stays queued) or `unknown` (no answer in time; it stays queued). A save never says "applied" on less than every branch's acknowledgement.

### Verified

`hq_support_audit_d5030.test.ts`, with HQ's binding running the branch's real `applyLicenceCopy`:

- an HQ change to P1 reaches the branch's `hq_support_sla_tiers`, and a 30-hour urgent ticket on the branch moves from past to due soon;
- the version advances on each change, and the copy carries only the three tiers;
- the failed, hung, old-deploy and unbound branches;
- the stale and racing copies.

Every new assertion was mutation-checked.
