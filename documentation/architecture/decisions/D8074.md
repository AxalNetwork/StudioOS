## D8074 — Dependabot and secret-scanning alerts become slot tasks, with a seven-day SLA and a weekly digest (#8074)

**Decision date:** 2026-11-21. **Scope:** `scripts/scan-remediation`, its workflow and two labels. No
application, database or production change. Builds on D7283 (tracker bodies) and D7899 (S21 routing, no AI).

### What changes

- **Three sources, one tracker engine.** `scripts/scan-remediation/sources.mjs` defines Code Scanning (unchanged),
  Dependabot and Secret Scanning. Each names its tracker title (`[Dependabot] Remediate alert #N`,
  `[Secret Scanning] Remediate alert #N`), its dedup marker (`<!-- studioos-scan-remediation:<source>:N -->`),
  its protected alert URL and when GitHub has resolved it. `trackers.mjs` takes the source; with none it is
  the Code Scanning engine it was, so the existing tests pin the old behaviour.
- **What a tracker says.** The alert number, its protected URL and the rule: a GHSA id for Dependabot, the
  secret type for secret scanning. A rule that is not a published identifier is not written. No package,
  manifest, file, line or value is written anywhere. Secret-scanning alerts are read with `hide_secret=true`,
  so the reconciler never receives a secret.
- **Closure follows GitHub, not a merged PR.** A Dependabot task closes when GitHub marks the alert `fixed`
  from `main`'s dependency graph. A secret-scanning task closes only when the alert is resolved `revoked`. A
  dismissed alert, or any other resolution, leaves the task open for a person. A reopened alert reopens its task.
- **Routing.** Every new task is `bug`, `slot:S21` and `sla:7d`, the same handoff as Code Scanning. A claimed or
  assigned task is never relabelled.
- **SLA.** `sla.mjs` runs after each sweep. A task this workflow filed that is still open seven whole days
  after filing gains `sla:breached` and one comment. The comment is posted before the label, so a failed
  label write retries without a second comment. Trackers filed before D8074 carry no `sla:7d` and are not
  counted.
- **Weekly digest.** On Mondays at 08:41 UTC, or on a manual run with `digest`, the workflow sends one Slack
  message through the existing webhook sender (`scripts/health-alert-transport.mjs`,
  `SLACK_GITHUB_WEBHOOK_URL`). It carries counts per source and age band only. With no webhook configured, the
  run reports `not_configured` and passes.
- **Within an hour.** The sweep moves from every two hours to hourly.

### Credentials

The workflow token cannot read Dependabot or secret-scanning alerts. Only the scan-remediation App
credential can, with `vulnerability-alerts: read` and `secret-scanning-alerts: read`, both added to its token
request. A source the credential cannot read (HTTP 403 or 404) is skipped with one log line. The run does not
fail, and Code Scanning still reconciles. Granting the App those two permissions is the owner's step in the
App's settings. Nothing in this change writes an alert.

### Rollback

Revert the PR. The two labels stay on GitHub (labels-sync never deletes one). Filed trackers stay open and
can be closed by hand. No data or setting is changed.
