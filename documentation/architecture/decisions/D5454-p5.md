### What is decided

- **The investor projection no longer copies `evidence_refs`.** The raw key names every selected item's ref and version, including items the stores withhold from that investor. It left `PROJECTIONS.investor`'s allowlist.
- **Evidence comes only from the recipient's own view.** `project('investor', prep, released, view)` takes `investorManifestView(resolved, audience, recipientFacts)`, computed fresh at retrieval. It writes `content.evidence` with each delivered item as `kind`, `category` (the source word), `as_of` and `purpose`, copied key by key, so an extra key on an item is never carried. The view's `withheld` count is **not** copied: an investor learns nothing about what their access holds back. With no view, there is no evidence key at all, never an empty list that reads as "nothing selected".
- **The type asks for the view, not resolved items.** `InvestorEvidenceView` is `investorManifestView`'s return type, including `withheld`, so handing `project` the resolved items does not type-check.
- **Unchanged:** the `authoring` and `review` projections, which keep the raw `evidence_refs` for the admin and the reviewer and ignore a view; the `listed` rule (a withdrawn, archived, unreleased or unknown preparation projects nothing to an investor); the marketplace teaser.

### For ADP-04

The retrieval route builds the view per request:
1. `parseManifest` on the released revision; a refused manifest refuses retrieval;
2. `resolveManifestSources` on the issuer project;
3. `readRecipientFacts` for the caller;
4. `investorManifestView`, then `project('investor', …, view)`.

The NDA and audience rules stay `services/dealAccess.ts`'s and `retrievalDecision`'s.
