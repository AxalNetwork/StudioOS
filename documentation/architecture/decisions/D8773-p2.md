### What was built (2026-11-27)

Every sentence below was checked against the code it describes.

**Worker** (`services/lovable/prompt.ts`, `launch.ts`; no new route, mount or column):

- `privacyFindings()` returns each finding as `{ kind, words, lines }`: the 1-based lines it was found on (every occurrence for the regex shapes and interviewee names; the first for a recorded legal name, as `lintForSend` reports it), never the words. `checkLine()` says it: "This prompt contains an interviewee’s name, in line 13. Remove it to continue." Launch's `pii_found` refusal, its "Nothing was opened." and the support-session refusal are unchanged.
- `memberNameAdvisories()`: the account name (`users.name`) and display name of each member of this venture (accounts whose `founder_id` is the venture's, and `project_members` accepted and not removed), matched as whole words, 3+ characters, any case. It returns `{ kind: 'member_name', lines }` in the check's `advisories`, with `advisory_line`; `ok` reads findings only, so the launch never refuses for it.
- The draft takes `{ alias }` (2 to 60 letters, digits, spaces and `. , ' & -`, one line; otherwise `400 invalid_alias`), builds the template with it wherever the template names the venture, and returns `venture_name`, `venture_label`, `venture_lines` and `alias`. Nothing is written: the venture is not renamed and the alias is not saved (Q2, A). It also returns `support_session` from the token's `impersonated_by`, the same read the launch refuses on. Every check carries `checked_at`.

**Frontend** (`pages/cycles/lovable/*`, `pages/cycles/BuildPlanSend.jsx`, `buildProgressModel.js`):

- `PRIVACY_OK`, `PRIVACY_OK_SUB` and `PRIVACY_PASSED` are gone. The dialog says "No matches for the five checks below.", lists the five in the code's terms (email shapes; 8 to 15 digits; a US tax number shape, an IBAN or a 13 to 19 digit card shape; the full legal name on file for any Axal VC account, written in full; this venture's recorded interviewee names as whole words), the members' names advisory, and "Not covered: names of anyone else, part of a name or a nickname, and company details. Read the text yourself before it leaves." Send to… says "No matches for the four checks below." with the first four and a Not covered line that names interviewees (Q3, A).
- Two steps: Prepare (nothing leaves) and Review what will be sent (destination, how it travels, how the venture is named, exactly this text with its characters, lines and check time, nothing else goes, what Axal VC records, Copy instead), with Copy prompt beside Open in Lovable ↗. Copy calls nothing; Open is the launch as before.
- A member's name in the checked text sets the check to "Needs your choice": Review waits for Keep or a neutral alias (Q1, A). Apply alias asks the Worker for the aliased draft, which is checked again; it is offered only on the unedited draft. Restore the draft brings back the original text and checks it again. Edited · n lines and Compare with the draft diff the text against the draft by whole lines.
- One polite `role="status"` live region announces drafting, each settled check, the alias, a restore, Copy and Open; refusals and an unavailable check are `role="alert"`, and Unavailable has Check again. A support session sees the notice up front and no Review, Copy or Open. The entry reads "Prepare a Lovable prompt" (Q4, A).
