## D7905 part 3 — Supervisor-owned lifecycle and durable recovery evidence (#7905)

This part closes the four executor items from the #8010 compatibility review
and reconciles the #8009 deadline findings. It changes no timeout, cap or lease.

**Lifecycle.** The trusted supervisor owns the whole sequence: create, live
re-admission, install, test, capture, bounded export, then verified exact-ID
removal. `runCandidateInterruptible` returns an observation and never removes
the container, so an exporter can run while it still exists. Install and test
are separate execs, so an install failure is never reported as a test failure.

**Observations.** Each phase reports `success`, `failure` with its raw exit
code, `timed_out`, `cancelled`, `engine_failed` (docker exec's own 125–127) or
`unknown`. The exit is recorded on the process `exit` event, so an abort or
deadline that lands after exit cannot rewrite it. The supervisor's exit puts a
real nonzero test exit first, then cancelled 130 and timed out 124. Zero needs
an observed test success, verified removal and, when an exporter is
configured, a completed export. One JSON `container_outcome` line and the
step outputs carry the separate install, test, export and cleanup results.

**Recovery evidence.** The `{version, id, owner}` record is written before
start, exclusively and fsynced, to the listener's private state directory
(`~/.local/state/studioos-runner/containers`, mode 0700, no links). That is
outside `RUNNER_TEMP` and the workspace and never mounted into a candidate. A
record is deleted only after the engine reports that exact ID gone. A failed
or unverifiable removal keeps it, and the result is `cleanup_failure`. The
`cleanup` step acts only on its own run's records: it removes the run's files
either way, and fails visibly while a record remains. `prepare` retries exact
recovery of every retained record before new work, and keeps any it still
cannot remove.

**Deadlines (D8009).**
- The container sleeps to the receipt's absolute execution deadline,
  computed in the container at start. Staging and create time no longer move
  the stop later.
- Installs and tests stop `FINISH_RESERVE_MS` (90 s) before that deadline:
  60 s for exact inspect+rm, 30 s for capture and export.
- Export runs only while more than the 60 s removal reserve remains.
- Each ACL staging call is bounded to 20 s, so staging plus removal fits the
  coordinator's 120 s cancellation budget.
- The budget is checked again after staging: a run with no work time left
  refuses before any container exists.
