## D1179 — Use of funds: sourced Eadwyn readings and milestone wording

#3106, part of #2455. S18 · Codex s28. Builds on D1176; no migration.

### Built

The existing Use of funds router mounts `use_of_funds_eadwyn.ts` at
`/api/cycles/raise/use-of-funds/eadwyn`, with explicit `?project=` scope:

- GET reads this founder's kept readings; GET `/roadmap` reads the venture's
  recorded Build objectives for the name picker.
- POST previews `check`, `runway` or `wording`. It writes no reading, plan,
  milestone, hire, share, runway or forecast. It never initializes Base.
- POST `/keep` accepts a signed, short-lived check/runway receipt for the same
  founder and venture. Reading and `eadwyn_reading_kept` commit in one batch;
  retries create neither another reading nor another audit row. Audit copy
  contains an outcome only. A failed audit rolls back the reading.

The check's surface is `raise/use-of-funds-check`; the runway reading is
`raise/use-of-funds-runway`. Both meter on `/raise/use-of-funds`. The existing
client module exposes readings, roadmap, preview and Keep, with no new barrel
or Worker index mount. AI calls use the shared switch, guard and token-budget
path; provider errors, prompts, source passages and figures are never logged
or copied into an error response by these handlers.

### Sources and limits

`services/useOfFunds/eadwyn.ts` reads the existing plan projection with
`readOnly: true`. The check gathers Base, the newest saved deck's Ask slide,
the newest narrative version, round records and the existing cap-table
scenario. The runway reading gathers plan inputs, its modelled cash path,
measured runway today and the retained financial forecast. Each source keeps
its own label, provenance and date. Unknown legacy provenance is Recorded,
never an invented Typed/Connector origin. A forecast never supplies runway
today. The existing D1176 Mercury read remains founder-owned, cached and
provider-free; another member's connection is excluded.

Missing and failed blocks are listed separately; good blocks remain usable.
An absent Base or insufficient sources prevents a model call. Runway mode
also refuses before charging when the saved Base has no computed cash path;
its missing-input reason is returned as Not recorded. An oversized
source is explicitly Unreadable, never silently truncated. A check returning
no supported mismatch does not certify consistency or the missing sources.

The model returns prose and source-reference/quote pairs only. Every quote
must be an exact nonempty passage in that scoped source. A mismatch cites
both sides (at least two distinct sources). Runway explanations cite both
the inputs and the cash path. Invented references, duplicate citations,
extra write-shaped properties, numerical quantities in prose and prohibited AI wording
are refused. Actual figures appear in server-assembled citations, not newly
estimated prose. The neutral phrase "one record" is allowed; monetary or
runway quantities such as "one dollar" remain refused. A milestone name may
include numbers only when the entire name appears verbatim in its cited
roadmap passage; no invented or recombined numerical wording is accepted.
Unverifiable outputs and missing cost receipts disclose that the started
run may still be charged. A missing charge never becomes an invented zero. Source material is
delimited as untrusted data. A guard outage returns a static safe message
that a started run may still be charged, without exposing provider errors or
claiming that no charge occurred.

Kept readings are historical source snapshots. They are signed at preview,
expire for Keep after fifteen minutes, and remain readable afterward as
captured readings; their dated sources may have changed. Stored-body
tampering is Unreadable rather than treated as an empty list. Each saved row
is verified independently: corrupt rows or rows invalidated by a signing-key
change are counted as Unreadable while verified readings remain available. A
failed list query remains a whole-read failure. Keep accepts and persists only
the verified payload/signature pair, never extra receipt properties.

### UF14 and UF6

`workspaces/UseOfFundsEadwyn.jsx` draws the cited UF14 proposal in an in-page
lightbox, with Keep this reading and Dismiss. It mounts on the existing Home
and Runway module views for the founder. Visiting the page reads kept data
only and spends no AI tokens. Closing or changing venture drops late preview
results. Read/write failures retain explicit Unreadable and Try again states.

The two page options are Check this plan and Explain the runway. The split
form additionally names its contextual `form:uof-milestone-wording` option.
It offers recorded Build objectives, proposes only a milestone name and cites
the selected roadmap record. Accept places only a blank, allow-listed
`milestone_label.<section>` in the unsaved form. Typed wording cannot be
replaced; Dismiss writes nothing. The existing Save split remains the human
write. No amount, date, share or driver is placed by Accept. This assistant
uses a narrow optional FormLightbox slot; forms without an eligible name field
mount no helper, fetch no roadmap and offer no paid wording action; #3104's owned tool files are not
edited and its later milestone dialog may reuse the exported component.

The paired Worker/frontend never-fill registries gain `money_term` for the
explicit Use of funds financial columns, legacy plan fields, bare form
financial names, split percentage fields and financial-model inputs. Financial column tokens match qualified names in any table, including
future cents, burn, runway and forecast-driver columns. One exact exception,
`project_market_assumptions.runway`, retains that existing market-sizing
contract. A schema-driven regression checks every Use of funds money column
and paired registry behavior. Milestone labels remain eligible; placement
boundaries are regression-tested. The registered options regenerate the
D764 model matrix so all three actions have their own routing rows.
