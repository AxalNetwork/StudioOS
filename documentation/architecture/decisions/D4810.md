## D4810 — Programs: request volume stays flat as records grow, and the program detail is read once (#4810)

- **Status:** Built for #4810, 2026-11-07. Worker and frontend.
- **Builds on:** D962 (Learning's Completion by program, OD9), D4293 (influencer offers), and D963 and D1124 (the program frame and its grant badge).
- **No migration.**

### What was decided

1. **Learning overview: one completion read, not one per program.**
   - **Before.** Completion by program read each published program's whole learner roster, one request per program, and counted Finished in the browser.
   - **Now.** `GET /api/learning/programs/mine/completion` answers for every published program in the caller's `/programs/mine` scope:
     - `{ uid, learners, finished }` per program;
     - which programs it could not read (`unreadable`);
     - whether programs past the cap were left out (`capped`, `max`).
   - **OD9 runs in the Worker.** It moved there as `isDoneCell` and `hasFinishedCells`, kept beside the frontend's `isDone`.
   - **Cap.** The read counts the first `COMPLETION_MAX` (50) published programs by name, a fixed number of queries each.
   - **Nothing partial passes as complete.**
     - A program it could not read is said so, never counted as 0.
     - A program left out past the cap makes Finished undrawn, and the chart says the first 50 are counted.
2. **People: learners a page at a time.**
   - `GET /api/learning/programs/:uid/learners?limit=&offset=` reads a page of at most 200, and `total` says how many there are in all.
   - People reads 50 at a time, with Previous and Next, and says "1–50 of 120 enrolled now".
   - With no `limit` the route reads every learner as before. The learning studio's own program page reads the whole table, and changing it is not this issue's.
3. **Influencer offers: one paged read across influencers.**
   - **Before.** Offers were read influencer by influencer, each awaited before the next.
   - **Now.** `GET /api/admin/influencer-offers?limit=&offset=` (at most 100 a page, `total`) answers every influencer's offers, newest first, each with its influencer and in the same view as the influencer's own read. The tab makes two reads whatever the number of influencers: the influencers (for New offer) and one page, with Previous and Next.
   - **Gate.** The read keeps the per-influencer route's Super Admin gate: offers carry budgets and spend.
   - **What an admin sees.** Before, a plain admin got "Its offers could not be read" on every row. Now the tab says once that only the Super Admin reads them.
4. **Program detail: one read for the frame and the page.**
   - **Before.** `ProgramFrame` read `/api/admin/programs/:key` for its grant badge, and the page read it again for the playbook and the header's status. That was two requests, each with its own loading and error.
   - **Now.** Each page passes its `useProgramDetail` read to the frame (`detail`), and the frame reads only when no page passes one.
   - **Always on.** The page's read is now on for every tab, because the badge needs it on every tab. That also fixes the Influencer header's status, which was only read on How it runs.

### Page sizes and caps

| Read | Default | Cap | What says more exists |
|---|---|---|---|
| `GET /learning/programs/mine/completion` | — | 50 programs | `capped: true`, `max` |
| `GET /learning/programs/:uid/learners` | every learner (no `limit`) | 200 a page with `limit` | `total` |
| `GET /admin/influencer-offers` | 50 | 100 a page | `total` |

### Tests

Each test uses a large synthetic collection.

**Worker.**
- `learning_programs_d558`:
  - the completion read: scope, OD9, a draft left out, 60 extra programs capped at 50;
  - the learner pages, their total and the refusals.
- `influencer_offers_d4293`: 121 offers paged, newest first, with influencers; the bounds; the Super Admin gate.

**Frontend.**
- `admin_programs_d962`:
  - 120 programs make one completion read and no learners read;
  - the frame and page share one detail read;
  - People pages 50 at a time out of 120.
- `admin_influencers_d4298`: 200 influencers make two reads, never one per influencer, and Next pages on.

**Mutants.** Fourteen mutants of the cap, the OD9 rule, the published filter, the paging, the gate, the left-out state and the shared detail were each killed.
