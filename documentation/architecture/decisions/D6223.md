## D6223 — Company Terms: the investor opens the signed document behind each duty (#6223)

- **Status:** built by S04, 2026-11-16 (#6223, under #5311).
- **Builds on:** D1058 (reporting duties), D1061 (the company page's Terms), D6199 (the investor's signed copy in the closing room), D410 (the e-sign read's scope), D4817 part 9 / PR #5846 (Ownership & rights).
- **Migration:** none.
- **Worker:** `cloudflare-worker/src/routes/reporting.ts` (`signedCopies`, used by `GET /api/reporting/portfolio` and `GET /api/reporting/companies/:projectUid`).
- **Frontend:** `frontend/src/pages/investor/portfolioReportsModel.js` (`termsCopy`, `TERMS_COPY_WORDS`, `termsRows().copy`), `frontend/src/pages/investor/CompanyReports.jsx` (`TermsCard`, `DutyDocument`).

### 1. The read that already existed

A signer can already read their own envelope: `GET /api/legal/esign/:id/document` (`routes/esign.ts`), scoped by `esignEnvelopeScope`. That scope admits an envelope's creator, its subject (`esign_envelopes.user_id`) and any recipient whose `esign_recipients.user_id` is the caller. An investor who signed a closing line's envelope with their account is a recipient with their `user_id`, so the scope **already admits them**. No access rule changed. D6199's room downloads through the same read (`closingsApi.signedCopyBlob`); this page reuses that function. There is no second document read.

### 2. The reference is the envelope id

The read takes a numeric envelope id, not an opaque token. The reference handed over is that id, the same shape as D6199's `signed_copy.envelope_id`. The id is guessable, but guessing gains nothing: the read answers 404 for any envelope outside the caller's scope, the same as one that does not exist (D410). No new token or route was added.

### 3. Who gets it

Each duty in both investor reads carries `source.signed_copy = { state, envelope_id }`:

| state | envelope_id | When |
|---|---|---|
| `available` | the envelope's id | The duty is the caller's own (`holder_user_id`, as before), it is sourced from `signed_envelope`, the caller is a recipient of that envelope with `status = 'signed'`, the envelope is `completed` with a stored signed file (`esign/signed/…`), and `esignEnvelopeScope` admits the caller. |
| `not_signed` | null | A template-sourced duty: no signed copy is recorded. |
| `not_available` | null | A signed duty whose envelope the caller did not sign (another holder's paper, a declined or pending recipient), or whose signed file is not stored. The reason is never told apart, so the read says nothing about another person's paper. |
| `unreadable` | null | The lookup failed. The rest of the read still answers. |

The signer condition is narrower than the read's scope on purpose. The issue grants the copy to the person who signed it. The scope clause is kept in the query too, so the page can never offer an envelope that the read would refuse. The founder's desk is unchanged.

### 4. The page

On a duty row in "What [company] owes you":

- **`available`:** the document pill is a button, "[document] [clause] · Download signed copy". Pressing it fetches the copy through the scoped read and saves it. If the download fails, the row says "The signed copy could not be downloaded. Try again." Nothing is saved, the page does not navigate, and the button stays so the investor can try again.
- **Any other state:** the document stays a plain pill, with one line saying why:
  - a template duty: "No signed copy is recorded";
  - a copy the investor may not open: "not available to you here";
  - a failed lookup: Unavailable (the state stays `unreadable`, D5129);
  - a read that does not say: Not recorded.
