- **Builds on:** D321 (the honest states), D1419 (the Studio modules), D702 (what an investor may find), D1207 and D1484 (the calendar's sources and cancelled rows), D564 (Partner Studio's body).

### What was decided

1. **The eligible total and the preview are two fields (`routes/dashboard.ts`).**
   - `proprietary_deal_flow_summary = { total, total_is_lower_bound, preview_limit, previewed }`. `total` is the count of rows this viewer may see; the list `proprietary_deal_flow` is at most `preview_limit` (12) of them, newest first.
   - Eligibility comes first. The read takes up to `DEAL_CANDIDATE_CAP` (500) candidates, an investor's findable filter (D702) runs over them, and only then is the preview cut. Before, the list was cut to 12 and then filtered, so 14 eligible read as 12 or fewer, and an investor whose only eligible ventures were older got an empty preview.
   - Above the cap the total is a floor: `total_is_lower_bound` is true and the page draws `500+`.
   - A deal read that failed has `total: null`. It is not 0.
2. **Every dashboard read reports its own outcome.** `source_status` maps each read to `ready` or `unreadable`. A fallback (an empty list, the 0 of a `COUNT`) is still returned so the dashboard does not 500, but nothing may read it as a fact. A payload that carries a stand-in is not written to the L1 or KV cache, so the failure is not served for the next minute.
   - `deals`: proprietary-deal-flow candidates and total.
   - `scoresMine`: the caller's match-score rows and `ai_score_avg`.
   - `syndicatesAll`: open syndicates and `active_syndicates`.
   - `mySyndicateMemberships`: the caller's memberships and `my_syndicates`.
   - `marketplaceCount`: available marketplace profiles and `marketplace_available`.
   - `monthEarnings`, `lifetimeEarnings`, `compoundEarnings`, `pendingPayouts`: the four matching cent figures in `quick_stats`.
   - `chainCounts`: `chain_counts` and both copies of `network_reach`.
   - `topReferrers`, `recentCommissions`, `earningsSeries`: the matching performance-analytics lists/series.
   - `myTasks`: assigned operator-workspace tasks.
   - `notifications`: the dashboard notification feed.
   - `recommendedSyndicates`: personalised recommendations, only for a role that requests that read.
   #5351 makes every affected `quick_stats` figure `null` when its key is `unreadable`; a readable true zero remains 0. `routes/networkfx.ts`'s `/effects` copy follows the same rule and returns its own `source_status` for `compoundEarnings`, `directEarnings`, `chainCounts`, `activeSyndicates`, `mySyndicates` and `marketplaceCount`.
3. **The lifecycle says which counts it could not read (`/investor-lifecycle`).** A count whose read failed is `null`, not 0; `sources` carries each read's status and `partial` is true when any failed. A stage whose count is unreadable is not `reached` on that evidence. When no count could be read the route answers 503 `unreadable`, so the page draws Unreadable, not an empty funnel.
4. **Studio shows the failed figure, not a stand-in.**
   - Investor quick stats: "Deals in flow" is the worker's total. A figure whose read failed says "Could not be read" and the group offers one Retry; the others keep their numbers. The funnel names an unreadable stage and offers Retry.
   - Advisor Today (`advisorToday.js`) reads bookings, the calendar and the slots. It is **empty only when all three answered**; a failed input makes it Unreadable (when nothing else returned something) or names the gap above what did return; a loading input is Loading, not an empty day. Retry asks again for the failed input only.
   - Partner feed (`FirmFeed`): each line comes from one of three reads. With any read unanswered, the all-clear sentence is not drawn; the feed says which part it could not read, keeps the lines the others produced, and Retry asks again for the missing reads only (`usePartnerHome` keeps what answered and merges).
5. **A 200 calendar is not complete coverage (`studioAgenda.js`).** `calendarCoverage` reads `sources[].ok` for the kinds a widget depends on (`ADVISOR_AGENDA_KINDS`, `INVESTOR_AGENDA_KINDS`) and ignores the rest, so an unconfigured source for another module does not invalidate every widget. `ready`, `partial` (some relevant source failed) and `unreadable` (all did). A bare list (the dev backend) names no sources and claims nothing.
6. **One agenda identity.** `agendaKey` is the event kind plus the normalized source id: a booking `17` and its calendar copy `advisor_booking:17` (`source_id: 17`) are one entry, while an `ic_meeting` with the same number stays apart. An item with no source id has no key and is never merged. The booking row wins the duplicate.
7. **One active-upcoming policy.** `isActiveStatus` drops cancelled, no-show, declined, rejected and expired from Studio's lists on **both** branches of the Advisor merge and on the Investor's upcoming selector. The full Calendar still asks for cancelled rows (D1207) and strikes them through; this changes only what Studio shows.
