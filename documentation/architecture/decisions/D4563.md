## D4563 — HQ Contracts › Corporate Governance (#4563)

- **Status:** Built for #4563, 2026-11-06. It covers the Worker, the client module and the tab.
- **Builds on:**
  - D647 (the Contracts desk), D1219 (Closings, a desk tab at its own path);
  - D711 (`legal_document_files`, sealed append-only by two triggers);
  - D717 (`PdfPages`, the pinned pdf.js viewer);
  - `AXAL_ENTITIES` in `services/legalDocFormat.ts` (the entities' legal names).
- **Migration:** `202611062154_governance_documents.sql`. It is additive: three new tables, and no existing table changes.

### What was decided

1. **A tab at its own address.** Corporate Governance is `/admin/contracts/governance`, drawn by the Contracts desk (`ContractsDesk section="governance"`) and placed after Templates, beside the template library. Tabs are paths, so the tab is not a `?tab=`. It is HQ only: a branch gets no tab, the route is behind `hqOnly`, and every Worker route answers through `requireHqAuthoring`.
2. **One collection per entity.** There are three entities: Axal VC Holdings LLC, Axal VC Management LLC and Axal VC GP LLC. Each is one collection, grouped into five categories: operating agreements, formation certificates, member registers, resolutions and signing authority records. The fund is not a governance entity here.
3. **New tables, not `legal_document_files`.** That table's `kind` CHECK and its append-only triggers mean it could only take these files after a rebuild. So the governance documents get their own tables:
   - `governance_documents`: the record;
   - `governance_document_versions`: its files, numbered from 1 and append-only by two triggers, as D711 seals its files. A corrected file is a new version, and history is never rewritten;
   - `governance_entity_profiles`: the ownership metadata.

   No existing contract row is read for writing, copied or overwritten.
4. **Links are references.** A document may name a template of the library (`template_slug`, active templates only) or an envelope (`envelope_id`). Neither row is copied. The picker offers completed envelopes by title and date, never a signer's name or email.
5. **Statuses.**
   - The moves are draft → review → approved → executed. Review may return to draft, and approved may return to review.
   - Any status may move to archived. An archived document returns to draft only.
   - An executed or archived document takes no new version.
6. **Never executed unsigned.**
   - Executed needs evidence of signature: a version uploaded as the signed copy, or a linked envelope whose status is `completed`. Without either, the move is 409 `not_signed`.
   - The evidence is recorded in `executed_version` or `envelope_id`, and a table CHECK refuses an executed row with neither.
   - While a document stays executed, the envelope it was signed in cannot be unlinked or changed (409 `executed_link_locked`).
7. **Files.**
   - A file is a PDF or a Word `.docx`. The type is sniffed from the bytes; the declared type is not trusted. A file is at most 25 MB.
   - Files are kept in R2 under `governance/<entity>/<uid>/v<n>`. R2 is written first, then the row. When two uploads race for the same version number, the loser's object is deleted (409 `version_conflict`).
   - A PDF previews inline in the panel through `PdfPages`. A download is an attachment named `<entity>-<category>-v<n>`, never the uploaded name.
   - File responses carry `private, no-store` and `nosniff`.
8. **Confidential documents are the Super Admin's alone.**
   - A Super Admin's new document is confidential by default. Another admin cannot make or unmake one confidential (403).
   - To any other admin, a confidential document is 404 on every read, file and write, as if it did not exist. Their list counts it only, as "N confidential (Super Admin only)".
9. **Ownership is restricted, editable metadata.**
   - Each entity's ownership is kept as editable rows in `governance_entity_profiles.ownership_json`. A row is a holder, an interest, a percent and a note. There are at most 50 rows, and the percents total at most 100.
   - Only the Super Admin can read or write it (403 for anyone else). Nothing is hard-coded in the UI.
   - A percent that was not entered stays unknown and is never shown as 0.
10. **Audit.** Every write, every view of a confidential document, and every preview and download writes the admin audit (`logAdminAction`). The actions are:
    - `governance_document_created`, `_viewed`, `_updated` and `_status`;
    - `governance_version_uploaded`;
    - `governance_file_previewed` and `_downloaded`;
    - `governance_ownership_updated`.

    The details name the uid, entity, category, status and version. They never carry a title, file name, holder or file contents.

### Not in this decision

- Generating a governance document from a template (the link records which template it follows; drafting stays in the template editor).
- Sending a governance document for signature from this tab (send it as an envelope from the desk, then link the completed envelope).
