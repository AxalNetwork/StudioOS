## D694 — One cycle frame and a Customer research recording return

D689's Cycle Overview canvas gives each cycle one content gutter. Module and action routes had a second App shell inset because only the four roots were in the founder's full-bleed list. `isCyclePath` now derives those routes from `MODULES` and the four action paths, and App uses it for every licence. It admits the cycle roots, module pages, module `/new` and lower-case record IDs, the four actions, and `/validate/record/live`. It excludes the cap-table variants subtree, the legacy interview and session pages, inbox, and unrelated or malformed paths. No second slug list is maintained in the sidebar.

The phone body's top is 14px, not the canvas's 0 (CO:25), until D703 provides the first block's own top; its form page adds 4px, for CO:27's 18px. A chart (`CycleCharts.jsx`'s `Chart`) keeps a 480px inner box and scrolls sideways only below 760px in that column (CO:16), at every width: the canvas's `.co-chart` scrolls always (CO:83, CO:117), but the app's SVG draws `overflow-visible` labels that would give a wide column a scrollbar. The existing overview, figure and module card paddings already match the canvas and stay as they are. Fixed overlays sit outside the size container, because older supported Safari and Chrome versions (before Safari 18.4 and Chrome 129) treat container layout containment as their fixed-position containing block: the body and the container close after the in-flow `CreateStartupForm` card, and the form sheets and the action `Mount` follow as siblings inside `RailFrame`.
