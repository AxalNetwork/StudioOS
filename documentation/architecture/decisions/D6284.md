## D6284 — Markets RS-03: each market's countries, source count and newest source date (#6284)

- **Status:** built (Worker only). Part of #3701 (RS-03). The filters and the Table / Cards / Analysis views that read these fields are a follow-up frontend issue under #3701.
- **Builds on:** D533 (the sector and country crosswalk, `services/researchTaxonomy.ts`, migration 376), D538 (live market-intelligence rows only, `services/market_intel/liveRows.ts`), the signals ingest (migration 136; evidence rows are fetched, never seeded).
- **Migration:** none. Every field is derived at read time from stores that already exist.

### What was checked

- **The market store.** `research_market_directory` (migration 229) holds slug, name, `company_count` (Axal's supplied count), `source_name`, `source_boundary` and `as_of`. `source_name` and `source_boundary` are the same text on every row, so D3701's description (slug, name, count and date) is right in substance. Nothing in the store answers country, source or freshness.
- **What the crosswalk answers.** Through D533:
  - `mapCompanySector` and `mapCompanyCountry` place each directory company in one market and at most one country, which answers "countries with companies".
  - `research_market_sectors` names a market's tracked market-intelligence sector, or none.
  - `mapSignalTags` places an active signal in the markets its tags name.
- **What holds sources and dates.**
  - `market_intel_rows` holds `source_key` and `ts` per row, read through D538's live predicate.
  - `signal_evidence` holds `source_key` and `observed_at` per evidence row.
  - The index rows (`market_intel_indexes`) hold only a `source_count` per dimension and month. They name no source and carry no date finer than the month. The live rows they are computed from answer the question exactly, so those are what is read.

### What `GET /api/research/markets` adds, per market on the page

| Field | Value when recorded | Not recorded when |
|---|---|---|
| `countries` | `[{ code, count }]`: where the directory's companies in this market are based, most first | the market has no company (`NO_COMPANY_REASON`), or none of its companies records a country the crosswalk can place (`NO_COUNTRY_REASON`) |
| `source_count` | the number of distinct sources: the tracked sector's live market-intelligence `source_key`s, plus the `source_key`s of the evidence behind active signals whose tags name the market. Each is counted once per kind. | neither kind has a row (`NO_SOURCE_REASON`) |
| `newest_source_at` | the newest `ts` or `observed_at` among those sources, as the store wrote it | as above, or no source row records a date |
| `sources` | at most `SOURCES_CAP` (20) `{ kind, key, rows, newest }`, newest first. `source_count` counts them all. | always a list, empty when there is none |

- **The shape.** Each of the three fields is `{ status: 'recorded', value }` or `{ status: 'not_recorded', value: null, reason }`. That is the shape the index series and the overview already use. A market no source covers reads null with its reason, never 0.
- **Archived signals.** They are not counted, which matches the detail route.
- **Size and growth.** No market size or growth is derived, because no store records one.

### Bounded reads

The derived fields are read for the returned page only, after search, sort and paging. Search and sort are unchanged, and so are `limit` (at most 100) and `offset`. The number of statements is fixed whatever the page size:

- the companies, read once already for `company_count`;
- one grouped `market_intel_rows` query for the page's distinct tracked sectors, bound as one JSON array (`IN (SELECT value FROM json_each(?))`), so neither the page size nor D1's 100-parameter limit changes the statement;
- one grouped `signal_evidence ⋈ signals` query, mapped to markets by tags in the Worker.

There is no query per market. A test counts the statements prepared for a one-market page and for a hundred-market page, and they are equal.

### Departures

- **Index rows.** The issue says "from the tracked sector's index rows and signals". The index rows name no source and give no day, so the source count and the date come from the live rows behind them and from the signals' evidence rows. A signal row with no evidence is not counted as a source: its thesis is editorial (signals ingest), and only its evidence is fetched.
- **No contract file.** `cloudflare-worker/src/contracts/` covers deck v2 adapter methods only, so this route gets no schema there. The fields are checked by the route's tests.

### Tests

`cloudflare-worker/test/research_markets_d533.test.ts` adds five D6284 tests:

- countries, with both null reasons;
- every market null and never 0 when there is no source;
- market-intel and evidence sources joined, with stub, uncited and archived rows excluded;
- the source list capped while the count stays whole, and the statement count independent of the page size;
- paging unchanged.

The tests were mutation-checked: replacing the null with `0` fails them, and so does dropping the live-row or archived filter.
