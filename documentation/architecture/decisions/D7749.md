## D7749 — The fund directory filters and counts by investment stage, investment geography and cheque (#7749)

`GET /api/research/fund-directory?stage=seed` answered 400 because nothing recorded a stage. D7743 now keeps each source's statement about a fund, with stage and geography terms and money facts apart. This decision is the one mandate filter contract over that store. The Funds directory, the Capital relationships match read and the Companies plan's firm discovery all call it, and none of them adds a second parser.

### Where it lives

- `cloudflare-worker/src/services/researchFundMandate.ts` (new) holds the parsing (`parseMandateQuery`), the SQL clauses (`mandateConditions`, `managerNameCondition`), the facets (`termFacet`, `chequeFacet`), `coverage.mandate` (`mandateCoverage`) and the row summary (`readMandates`). It defines no vocabulary: stage and region terms are D7743's `STAGE_TERMS` and `REGION_TERMS`.
- `services/researchFundDirectory.ts` only wires these in. `routes/research.ts` is not edited, and no route is added. No column or migration is added: D7743's indexes on `(fact, fund_uid)` and `(vocabulary, term)` serve the filters.

### What a statement is here

The gate is the one `readFundStatements` uses, so the profile and the directory never disagree:

- A statement of a list whose verdict is `not allowed` never matches or counts.
- A statement with a period is history. It matches nothing and counts nowhere.
- A statement stored under a uid that moved is read under the new uid, one hop.
- The rows of `research_fund_vehicle_facts` (D7167) are read as statements too. That table records no currency basis, so its cheques are never comparable. It records no terms, so its stage and geography text is unmapped, as the issue asks for a free-text row of the old table.
- A statement matches only the row it is keyed to. Nothing is inherited between a manager's row and its vehicles' rows. Applying a firm's statement to its vehicles waits on the Companies plan's identity.

### Filters (every value bound)

- `stage`: a stage term or `none`. An unknown term is a 400 that names every allowed term. A multi-stage statement matches each of its terms.
- `invests_in`: a two-letter country code, a region term (any case, spaces, hyphens or underscores), `global`, or `none`. It is separate from `hq_country`. Literal: a statement that names a region matches that region only, never its countries, and the reverse. `mandate_basis` says so.
- `cheque` with `cheque_currency`: a whole amount, `worded` or `none`. An amount needs `cheque_currency`; there is no default. `cheque_currency` without an amount is a 400, and so is a code that is not three letters. An amount matches a row with a cheque statement that is a range, a lower bound or an upper bound, in that stated or reviewed currency, that contains it. Bounds are inclusive. An average, a typical or exact amount, a statement with no stated currency, or a bound in another currency never matches. `worded` lists rows whose cheque statements are all of that kind. `none` lists rows with no cheque statement. This is #7738 Q5's answer A.
- `none` means no served current statement of that fact. A row whose statements map to no term is in neither a term nor `none`. `facets_unmapped.stage` and `facets_unmapped.invests_in` count it, as HQ and focus already do.
- `q` also matches the vehicle label (`fund_number`), the name with its fund number, and a served current `manager_name` statement.

### Answer (all keys additive)

- `facets.stage` and `facets.invests_in`: one entry per term some matching row holds, plus `none`. Each leaves its own filter out and counts rows, not statements, so a row two sources call seed counts once. Each count is the total that picking it returns.
- `facets.cheque`: `{ currencies: [{ currency, count, min_cents, max_cents }], worded, none }`. `facets.cheque_not_comparable`: with an amount asked, the rows whose cheque statements hold none comparable in the asked currency; without one, the worded rows.
- Each row carries `mandate`: `stage`, `geography` and `cheque`, each with `status`, `terms`, the statements' wording and qualifier, `source_count` and each statement's provenance. Only these three facts are read, so a description or any other fact never reaches the answer.
- `coverage.mandate`: rows of the whole served directory with a current stage, geography, cheque and manager statement, and `cheque_comparable`. `coverage.fields` keeps its exact keys.
- The answer echoes `stage`, `invests_in`, `cheque` and `cheque_currency`, with `mandate_status` and `mandate_basis`.

### A store that cannot be read

A missing or unreadable statement store is not an empty one. The `coverage.mandate` read doubles as the probe:

- If it fails, the list, the total and the other facets still answer.
- `mandate_status`, `coverage.mandate` and every row's `mandate` read `unavailable`.
- `facets.stage` and `facets.invests_in` are empty. `facets.cheque`, `facets.cheque_not_comparable` and the two unmapped counts are null.
- A request that asks for `stage`, `invests_in` or `cheque` is refused. The directory route answers 503. The match route answers its existing unreadable 500. Neither returns an unfiltered list.

The test files that build their schema without D7743 keep passing unedited.
