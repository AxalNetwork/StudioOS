## D939 — Count historical admin tabs and send notices to the live Lab

Issue #2744, part of the shared admin page header #2375. Starts after #2742's
integration merged; no migration and no new page.

`redirectRoutes.ts` now holds sixteen explicit admin-tab counter keys: users,
profiles, kyc, lab-applications, legal, personas, directory, promos, payments,
bank-accounts, product-testing, billing, wellbeing, network-profiles,
integration-keys and github. The first fourteen are the historical console
sections; the last two already moved. They remain historical keys when their
sections move, rather than disappearing with the console's section list.

The beacon takes pathname and search separately. On `/admin`, it resolves the
first tab value (as the console does) to one of those fixed entries. It sends
only that canonical key; unknown tabs and other query/hash data never enter
it. Changing between tabs sends separate beacons. Unrelated query changes do
not resend the same tab, while opening another dynamic pathname still sends
its pattern as before. App passes the real address-bar pathname and search,
not the preview lens's location.

The public pageview endpoint must check the complete allowlisted key before
its usual query/hash stripping; otherwise each tab would be truncated to the
same `/admin` key and ignored. Only a complete known tab key is retained.
Existing public pages and path-only redirect beacons keep their behavior. No
IP, user agent, cookie, member ID or arbitrary query value is persisted. The
retirement runbook and parity tests distinguish path routes from historical
tab keys; the old path-only redirect inventory stays exact.

New cohort application notices link `/admin/programs/spinout-lab/applications`.
New week-outcome notices link `/admin/programs/spinout-lab/cohorts`; in-app and
email channels share the link. Existing sent notices still resolve through
`/admin/spinout-lab`, which retains its permanent keep entry. Ticket mirroring's
not-configured refusal names HQ › Integration keys › GitHub Sync, whose
current address is `/admin/integration-keys#github`.

Validation covers every fixed key through the Worker/SQLite pageview route,
unknown and augmented keys, separate totals, existing path-query stripping,
mounted hook tab changes and fetch failure, source wiring of both publishers,
and the real ticket refusal. Key assertions are mutation checked; full build
and drift outcomes are recorded in the draft PR. No redirect retirement,
notice send, GitHub Sync operation or production database change is performed
by this task.
