## D4601 — Build: a delayed answer stays with the request that asked, and Copy says Copied only after a write (#4601)

- **Status:** Built for #4601, 2026-11-07. Frontend only.
- **Builds on:** D1070 (Send to… and Progress), D656 (an overview card's own retry).
- **No migration. No Worker change.** The handoff's contract (Prepare, privacy check, recording) is unchanged.

### What was decided

1. **Send to…: the request and its answer are kept together (`BuildPlanSend.jsx`).**
   - The provider tabs, the item boxes and the repository selector are disabled while Prepare is pending.
   - Prepare keeps a snapshot of what it sent: provider, item ids and repository. The answer is stored with it.
   - The result is drawn from the snapshot, never from the controls as they are when the answer lands. So the result, the provider tab, the "Send · N accepted items" count, the text and the outbound link all describe the one request.
   - If a control is driven past `disabled` (assistive technology, a stale handler), the tab follows the snapshot when the answer arrives.
2. **A card retry belongs to the overview it started under (`CycleRoute.jsx`).**
   - The overview on screen has an identity: its cycle, its venture and a generation. Every re-read, venture switch or page change advances the generation.
   - `retryCard` captures the identity when it starts and applies its answer only if the identity is unchanged. A retry for venture A that answers after venture B is on screen, or after the overview was read again, changes nothing.
   - Each card also has a retry sequence, so of two retries of one card the older answer never replaces the newer.
   - The normal overview read keeps its own `alive` guard, unchanged.
3. **Copy says Copied only after the clipboard accepted the text.** The helper returns false when there is no clipboard API, no `writeText`, or the write is refused. The sheet then says the sentence it already had: "Could not copy. Select the text and copy it yourself." The form's Copy link and From Lovable's copy already report a missing API as a failure, through their `catch`.

### Not changed

Transport cancellation (`AbortController`) is not added. The identity check makes an obsolete answer inert whether or not the request is cancelled, as the issue allows.

### Tests

`frontend/test/build_async_context_4601.test.mjs` holds each answer and releases it in the order the test picks:
- Prepare pending: the controls are disabled; a tab, an item and the repository driven past `disabled` do not change the result's provider, count, repository or link; a refusal re-enables the controls;
- Copy: a working clipboard, none, one without `writeText`, one that refuses;
- the card retry: it applies when its venture is still shown; A's retry answering after B is shown; an older retry answering after a re-read; two retries of one card answering newest first.

Mutants of `BuildPlanSend.jsx` and `CycleRoute.jsx` are each killed. Two pairs of layers are each covered by the other (the tab follows the snapshot and the result draws from it; the identity key carries the venture and the generation), so they are killed together or by the generation alone.
