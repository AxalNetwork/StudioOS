# D5604 — Detect repeated merge-queue infrastructure failures

1. The [jobs response for run 43033531049](https://api.github.com/repos/AxalNetwork/StudioOS/actions/runs/43033531049/jobs) includes `steps[]` and their conclusions. Two matrix legs failed at Install age. The dependent summary also failed, so the fingerprint considers leaf failures.
2. The [rerun endpoint](https://docs.github.com/en/rest/actions/workflow-runs#re-run-failed-jobs-from-a-workflow-run) requires Actions write for installation tokens. No token or live rerun was exercised.
3. [GitHub removes queue entries after failed required checks](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue#failing-ci). A rerun would reuse the original SHA and ref. This ships without reruns and uses Actions read.

Poll the two latest completed CI runs for the main queue every 15 minutes. Two distinct heads with the same infrastructure fingerprint open one alert. A successful queue run closes it. Other results preserve the open alert until there is positive evidence of recovery. The queue ref is in the run's head branch, so the API query filters by event and the script then selects the main queue.
