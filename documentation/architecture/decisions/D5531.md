### Acquisition and trust

The cache holds compressed archives only. Every restored archive is hashed,
copied into a fresh private job directory and hashed again before use. A
corrupt or swapped cache copy cannot supply executable bytes. A failed host
with a verified version-matched copy needs no download. Without one, curl has
the existing five-attempt bound, 10-second connect and 120-second transfer
limits, with bounded backoff and HTTPS-only redirects. Exhaustion names the
scanner, exact version and acquisition stage and exits nonzero. A transferred
archive with incorrect integrity is refused immediately.

Gitleaks is extracted into a new job-private directory and its version checked
after archive verification. No sudo/global executable installation is needed.
CodeQL init receives the verified archive, retaining the pinned action's normal
initialization and analysis. The CLI accepts only the scanner name and optional
metadata mode: job payloads and environment variables cannot override pins.

The wiring must load the installer, acquisition module and pins using `git show`
from the trusted PR/merge-group base, or the current trusted main push. It must
never load them from the PR checkout or cache. Restore exact cache keys only;
save verified archives only on trusted main pushes. This prevents PR-written
cache contents from replacing a privileged run's scanner. Workflow changes still
require owner review under the existing landing policy.

offline verified-copy use, interrupted transfer then recovery, exhausted host,
valid executable archives with malicious bytes claiming the right version,
cache-copy replacement, unsupported platform and wrong executable version.
Their synthetic CodeQL executable proves acquisition flow only, not analysis.
Eight deliberate source mutations are caught, and all twelve tests pass after
restoring the source.

The actual pinned Gitleaks archive was fetched, checksum/version verified and
reused offline. With the unchanged project finding policy, it detected a fake
token in an intermediate commit even though the tip removed it; clean-base and
tip-only scans passed. No token was sent to a service, and no fixture was pushed.
