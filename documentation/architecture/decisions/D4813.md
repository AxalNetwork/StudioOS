- **Builds on:** `routes/advisors.ts` (`/me/cohort`, `/:cycleId/founders`, `/weeks`, `/guidance`, `/calendar`, `/me/cohort-access`), migration `212_cohort_guidance.sql`, `company_week_status`; route-map row `part-3/0140`.

### What the canvas decides

- **`/cohorts` is a command centre** with a persistent cohort selector (dates and the current week).
- **Task-oriented section names;** no WORK BOARD, FEED or COLLECTION labels. Provenance moves to secondary text.
- **Founders** with week status (status, deliverables, grace, decision reason); **guidance** post, answer and retire; **calendar** windows with booked sessions, the partial state when windows are not recorded, and overlaps; **outcomes** scoped to the cohort, with programme outcomes kept apart.
- **Eadwyn** leads with advisor prompts; AI drafts are marked; model and usage sit behind AI settings.
- Tablet 834 and a Super Admin preview with Impersonate advisor.

### Workflow fix

- The guidance route stores an out-of-range week as general guidance (NULL). The composer treats it as an error; the route should refuse it.

### Backend required

- Guidance titles, drafts, edit history, version conflict and acknowledgements.
- A cohort activity feed.
- Deadline snapshots kept apart from the live status.
- External calendar conflicts.
- Graduate and session counts for cohort outcomes.

### Built (2026-11-09) — package 1 of 4

Part of #4813: the global cohort selector, the Overview command centre and founder triage (boards CH01, CH02, CH03, the CH11 states they use, CH12 and CH13 at 390px, CH16 dark, CH18 preview).

- **One cohort for the whole workspace.** `?cohort=<cycleId>` is read, validated and written back by one provider (`pages/advisor/cohorts/CohortWorkspace.jsx`, model in `cohortModel.js`). A malformed value, or a cycle the advisor is not assigned to, falls back to one they hold and the header says so. Without a value the cohort this browser chose last is used (local storage, a convenience only), else the newest assignment, and the URL is rewritten so refresh and shared links keep it. All six section links carry it. Every read goes through `guardedRead`, so a response for the cohort just left is dropped, and a section clears its old content before the new cohort loads. Loading lines name the cohort.
- **Header:** "Cohorts", "Guide founders from milestones to outcomes.", the selector, the cycle's dates (New York time, the Lab's), "Week n of 4" from the week record, last updated and Refresh. **Tabs:** Overview, Founders, Guidance, This week, Calendar, Outcomes, links with `aria-current`. `WorkspaceShell` takes a `sectionNav` for this; with it the shell draws no archetype badge, so WORK BOARD, FEED and COLLECTION no longer appear on Cohorts. `/cohorts` is the Overview; the bucket's directory grid is gone from it.
- **Overview (C1):** four figures (founders visible, needing attention, guidance awaiting response, sessions in the next 7 days), each "Not recorded" when its read failed and "n+" when the read stopped at its cap. Needs your attention lists failed and grace founders, at-risk founders, unanswered founder questions, booked sessions in the next 48 hours and cohort deadlines in the next 72, each with who, the reason, a date, a state in words and a shape, and one action link that keeps the cohort. A failed read makes the list say it is partial. Cohort progress is a table (caption, row and column headers) with Passed, In progress, Grace, Failed, Not assessed, Not open and Missing data. Next 7 days comes from the calendar read.
- **Recent activity is guidance only:** what you posted, what you answered and who acted on it, which `cohort_guidance` and its acks record. Submissions, sessions held and Lab decisions are stated as not recorded.
- **Founders (C2, C3, C13):** explicit states (Failed, Grace, At risk, On track, Not assessed). Failed and grace are Needs attention whatever the percentage. Progress that cannot be read is Not assessed, never 0%. A board in state columns and a semantic table (Founder, Cohort, Week, Progress, Status, Next deadline, Last activity, Action) with search, a status filter, sort and a Board/Table radio group. At 390px the table is cards. An attention item opens Founders on that one founder (`&founder=`), with "Show all founders".
- **Worker (additive, tested in `cloudflare-worker/test/advisor_cohorts_v2_d4813.test.ts`):** `/weeks` returns each week's `grace_until`, `grace_reason`, `decided_at` and `decision_reason` (not `decided_by`). `/founders` and `/guidance` return `truncated` when the read hit 200 rows. `/calendar` reads bookings from now on in SQL; it used to take the first 200 bookings ever, oldest first, so an advisor with 200 past sessions saw none upcoming. It also returns `sessions_truncated`. Opt-out and assignment gating are unchanged.
- **Preview (C18):** the notice with Impersonate stays. The provider reads nothing, and the Overview draws its four sections with neutral states and no founder.

**Departures**

- **No Paused state or column.** Nothing the advisor can read records a pause. The Lab holds a founder at a failed week (`cohortTiming` freezes progress), so Failed reads "Week n · held" and sits in Needs attention.
- **The board's columns are states** (Needs attention, On track, Not assessed), as C2 draws them, not D393's four week lanes. The four-week view is the Overview's progress grid.
- **No venture.** The roster records no venture for a founder, so the column is Founder (name and email), not Founder / Venture.
- **Last activity** is the founder's latest recorded action on this advisor's guidance; otherwise it reads Not recorded.
- **The Action is Write guidance.** The founder detail (C4) is a later package, so Open founder is not drawn.
- **At risk** means work outstanding with under half done, or work outstanding within 48 hours of the week's deadline. The canvas names the state but does not define it.
- **"Session · no notes prepared" is not claimed.** Nothing stores a session brief, so a session in the next 48 hours is listed as booked.
- **Eadwyn prompts are not shown.** `WorkerRail` takes no `prompts` prop on main, so the rail keeps its stance and coverage.
- **Tabs on a phone navigate.** They are links rather than `ZoneNav`'s in-place lenses, because a lens would not carry the cohort query to the zone it opens.
