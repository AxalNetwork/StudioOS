## D4813 — Advisor › Cohorts v2: a cohort command centre, not a directory (#4813)

- **Status:** canvas landed 2026-11-09 (`design/incoming/Cohorts v2 Page.dc.html`, `design/incoming/Cohorts v2 · Boards.dc.html`, boards CH01 to CH19), drawn 2026-11-07 from the 14:05Z copy-paste prompt on #4813 and its browser audit. Package 1 of 4 built 2026-11-09, package 2 of 4 built 2026-11-09 (below); packages 3 and 4 not built.
- **Builds on:** `routes/advisors.ts` (`/me/cohort`, `/:cycleId/founders`, `/weeks`, `/guidance`, `/calendar`, `/me/cohort-access`), migration `212_cohort_guidance.sql`, `company_week_status`; route-map row `part-3/0140`.

### What the canvas decides

- **`/cohorts` is a command centre** with a persistent cohort selector (dates and the current week).
- **Task-oriented section names;** no WORK BOARD, FEED or COLLECTION labels. Provenance moves to secondary text.
- **Founders** with week status (status, deliverables, grace, decision reason); **guidance** post, answer and retire; **calendar** windows with booked sessions, the partial state when windows are not recorded, and overlaps; **outcomes** scoped to the cohort, with programme outcomes kept apart.
- **Eadwyn** leads with advisor prompts; AI drafts are marked; model and usage sit behind AI settings.
- Tablet 834 and a Super Admin preview with Impersonate advisor.

### Workflow fix

- The guidance route stores an out-of-range week as general guidance (NULL). The composer treats it as an error; the route should refuse it.

### Backend required

- Guidance titles, drafts, edit history, version conflict and acknowledgements.
- A cohort activity feed.
- Deadline snapshots kept apart from the live status.
- External calendar conflicts.
- Graduate and session counts for cohort outcomes.

### Built (2026-11-09) — package 1 of 4

Part of #4813: the global cohort selector, the Overview command centre and founder triage (boards CH01, CH02, CH03, the CH11 states they use, CH12 and CH13 at 390px, CH16 dark, CH18 preview).

- **One cohort for the whole workspace.** `?cohort=<cycleId>` is read, validated and written back by one provider (`pages/advisor/cohorts/CohortWorkspace.jsx`, model in `cohortModel.js`). A malformed value, or a cycle the advisor is not assigned to, falls back to one they hold and the header says so. Without a value the cohort this browser chose last is used (local storage, a convenience only), else the newest assignment, and the URL is rewritten so refresh and shared links keep it. All six section links carry it. Every read goes through `guardedRead`, so a response for the cohort just left is dropped, and a section clears its old content before the new cohort loads. Loading lines name the cohort.
- **Header:** "Cohorts", "Guide founders from milestones to outcomes.", the selector, the cycle's dates (New York time, the Lab's), "Week n of 4" from the week record, last updated and Refresh. **Tabs:** Overview, Founders, Guidance, This week, Calendar, Outcomes, links with `aria-current`. `WorkspaceShell` takes a `sectionNav` for this; with it the shell draws no archetype badge, so WORK BOARD, FEED and COLLECTION no longer appear on Cohorts. `/cohorts` is the Overview; the bucket's directory grid is gone from it.
- **Overview (C1):** four figures (founders visible, needing attention, guidance awaiting response, sessions in the next 7 days), each "Not recorded" when its read failed and "n+" when the read stopped at its cap. Needs your attention lists failed and grace founders, at-risk founders, unanswered founder questions, booked sessions in the next 48 hours and cohort deadlines in the next 72, each with who, the reason, a date, a state in words and a shape, and one action link that keeps the cohort. A failed read makes the list say it is partial. Cohort progress is a table (caption, row and column headers) with Passed, In progress, Grace, Failed, Not assessed, Not open and Missing data. Next 7 days comes from the calendar read.
- **Recent activity is guidance only:** what you posted, what you answered and who acted on it, which `cohort_guidance` and its acks record. Submissions, sessions held and Lab decisions are stated as not recorded.
- **Founders (C2, C3, C13):** explicit states (Failed, Grace, At risk, On track, Not assessed). Failed and grace are Needs attention whatever the percentage. Progress that cannot be read is Not assessed, never 0%. A board in state columns and a semantic table (Founder, Cohort, Week, Progress, Status, Next deadline, Last activity, Action) with search, a status filter, sort and a Board/Table radio group. At 390px the table is cards. An attention item opens Founders on that one founder (`&founder=`), with "Show all founders".
- **Worker (additive, tested in `cloudflare-worker/test/advisor_cohorts_v2_d4813.test.ts`):** `/weeks` returns each week's `grace_until`, `grace_reason`, `decided_at` and `decision_reason` (not `decided_by`). `/founders` and `/guidance` return `truncated` when the read hit 200 rows. `/calendar` reads bookings from now on in SQL; it used to take the first 200 bookings ever, oldest first, so an advisor with 200 past sessions saw none upcoming. It also returns `sessions_truncated`. Opt-out and assignment gating are unchanged.
- **Preview (C18):** the notice with Impersonate stays. The provider reads nothing, and the Overview draws its four sections with neutral states and no founder.

**Departures**

- **No Paused state or column.** Nothing the advisor can read records a pause. The Lab holds a founder at a failed week (`cohortTiming` freezes progress), so Failed reads "Week n · held" and sits in Needs attention.
- **The board's columns are states** (Needs attention, On track, Not assessed), as C2 draws them, not D393's four week lanes. The four-week view is the Overview's progress grid.
- **No venture.** The roster records no venture for a founder, so the column is Founder (name and email), not Founder / Venture.
- **Last activity** is the founder's latest recorded action on this advisor's guidance; otherwise it reads Not recorded.
- **The Action is Write guidance.** The founder detail (C4) is a later package, so Open founder is not drawn.
- **At risk** means work outstanding with under half done, or work outstanding within 48 hours of the week's deadline. The canvas names the state but does not define it.
- **"Session · no notes prepared" is not claimed.** Nothing stores a session brief, so a session in the next 48 hours is listed as booked.
- **Eadwyn prompts are not shown.** `WorkerRail` takes no `prompts` prop on main, so the rail keeps its stance and coverage.
- **Tabs on a phone navigate.** They are links rather than `ZoneNav`'s in-place lenses, because a lens would not carry the cohort query to the zone it opens.

### Built (2026-11-09) — package 2 of 4

Part of #4813: the guidance feed, the composer, drafts and responses (boards C5, C6, C14, and the C11 guidance states: guidance empty, draft saved, draft not saved, publish failed).

- **Workflow fix — a week is refused, never dropped.** `POST /me/cohort/:id/guidance` and `PATCH /me/guidance/:uid` answer 400 `guidance_week_invalid` (with `field: 'week_number'` and `max_week`) for a week that is not a whole number from 1 to the cohort's last recorded week window, or 1 to 52 for a cycle that predates week windows. Unstated (absent, null or empty) is still general guidance. Nothing is stored on a refusal. `parseGuidanceWeek` in `routes/_advisor_cohort_helpers.ts` is the rule; the composer's `validateWeek` mirrors it word for word so the error shows before a round trip, and the Worker stays the authority.
- **Store (migration `202611091920_cohort_guidance_v2.sql`, healed at runtime by `ensureCohortGuidanceSchema` through `runSchemaBootstrap`).** `cohort_guidance` gains `title` (nullable: older rows have none and the page names them by their first line), `is_draft` (default 0, so every existing row stays published) and `version` (default 1). `cohort_guidance_versions` is the append-only edit history, one row per version with what the note said and the action (`created`, `edited`, `published`, `retired`, `restored`, `answered`, `backfilled`), UNIQUE per (guidance, version); existing rows are backfilled at version 1. Status is still derived (retired, else draft, else published), as 212 decided.
- **Versions and conflicts.** Every change goes through one write (`writeGuidanceVersion`): an UPDATE that lands only while the row is still at the version the caller named, and the history row in the same batch. A stale version answers 409 `guidance_version_conflict` with the row as it stands (`current`). An edit of title, body or week must name its version (400 `guidance_version_required` otherwise); an answer or a retirement may omit it so a tab opened before this deploy keeps working, and is checked against the row as read.
- **Routes.** `POST /me/guidance/:uid/publish` publishes a draft (needs the version, the author, and the advisor's active assignment: an advisor whose access ended can still edit what they wrote but cannot send anything new); its published date is when it reached the cohort. `GET /me/guidance/:uid/history` lists the versions, author only. Both are ledgered as verified in `scripts/auth-inventory-ledger.json`. `GET /me/cohort/:id/guidance` adds `title`, `status`, `is_draft`, `version`, `updated_at`, `week_limit`, `acknowledgements_recorded: false` and `counts.drafts`; drafts are not counted as posted.
- **Drafts are private.** The list reads `advisor_user_id = caller` only, so another advisor on the same cohort never sees a draft, and a founder has no route to the list (403). No founder surface reads guidance yet, so nothing else had to change for founders; the opt-out rule on who acted is unchanged and tested.
- **Feed (C5).** "New guidance" sits in the header outside every state, so it is there for an empty cohort, while the feed loads or fails, and after the last note is retired; the empty state covers only the feed and offers the same action. Filters All, Published, Draft, Retired and Needs response are a radio group kept in `?filter=`. Each item shows its title (or its first line), a preview, the cohort, Week n or General, its status in words and a glyph, its published, saved, asked or retired date, who acted (or "Acknowledgements Not recorded"), an "Unsaved changes on this device" mark, and Edit, Publish, Retire, Restore, Answer and History, each against the version on screen. The Overview's Answer link opens Needs response.
- **Composer (C6).** Title, the selected cohort (stated, changed in the header), an optional week bounded by the cohort's weeks, a plain-text body, Preview, Save draft and Publish to the cohort (Save changes for a published note). States: unsaved, saving, saved, publishing, published, week error (on the field, `aria-invalid`, linked by `aria-describedby`, `role="alert"`), version conflict (Compare, Load their version, Keep mine; Keep mine only adopts the newer version number, so the next Save is a choice and the history keeps both), not saved and publish failed; the text is never cleared by a failure. The state line is `role="status"` (polite) or `role="alert"` (assertive).
- **Unsaved text per cohort.** Each keystroke is kept in local storage under `axal.cohorts.guidanceDraft:<cycleId>:<uid|new>` (try/catch around every access). The composer is keyed by cohort, so switching cohort shows that cohort's own text and coming back reopens the first one's. A kept edit is restored only when it was made on the version now on screen. Writes go through `guardedWrite` (`guidanceModel.js`), `guardedRead`'s twin: a save or publish that answers after the cohort changed is not painted into the new cohort, and its kept text is cleared on the cohort it was saved for.
- **Mobile (C14).** Below `md` the composer is full screen (`fixed inset-0`), every control is at least 44px, the filter row scrolls instead of widening the page, and leaving with unsaved text asks first (`beforeunload`, and Close confirms). Dark mode uses the existing token classes (`check-dark-mode` passes).

**Departures**

- **Acknowledgements are not recorded.** 212's `cohort_guidance_acks` exists, but nothing a founder uses writes it and no founder page reads guidance; building that founder surface is not this package. Items say "Acknowledgements Not recorded" rather than "0 of 6"; who acted is still listed by name when a row exists.
- **No question or reply counts on a published note.** A founder question is its own row with no link to the note it is about, so "Questions: 1" under a note cannot be computed. Questions appear as items (Needs response, Answered) instead.
- **"Publish to 6 founders" reads "Publish to <cohort>".** The count of founders who would see it depends on opt-outs and on a founder page that does not exist yet.
- **Plain-text body.** The repository has no rich-text editor and this package adds no dependency; the preview shows the text as founders would read it.
- **Retired notes stay in All.** They are listed with Restore so the last retired note never makes the feed look empty; Published, Draft and Retired narrow it.
- **The week bound for a cycle without week windows is 52**, the route's old range, because nothing else records how long such a cycle is.

**Left for packages 3 and 4:** This week (C7) and the Calendar agenda and partial states (C8, C9, C15); founder detail (C4); cohort-scoped Outcomes (C10); the tablet layout (C17); Eadwyn's advisor prompts and marked drafts. Of the backend-required list, titles, drafts, edit history and version conflict are now built; acknowledgements (a founder surface), the cohort activity feed, deadline snapshots, external calendar conflicts and graduate and session counts remain.
