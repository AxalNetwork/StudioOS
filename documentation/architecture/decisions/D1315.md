### 3. Addresses

- **The old addresses move.** `/account/developer` and every address under it move to
  the same address under `/account/builder`. The sub-path and the query are kept.
- **A page load gets a 308.**
  - The Worker runs first for `/account/developer` and `/account/developer/*` only
    (`run_worker_first`, both tables).
  - It answers each with a permanent 308 (`services/builderRedirect.ts`).
  - `/account/builder` itself stays with the assets binding.
- **A link followed inside the app** goes through `BuilderRedirect`, which replaces the
  address and keeps the hash too.
- **The redirects are counted** in `REDIRECT_ROUTES` until #2319.
- **No OAuth callback** sits under `/account/developer`, so no provider registration
  changes.

### 4. What did not change

- **Routes kept as they are:**
  - `https://axal.vc/mcp`, the OAuth flow and its scopes;
  - every other tool name;
  - the `/api/developer/*` routes. These are API addresses, not pages.
- **Stored values kept:**
  - analytics event ids and stored values;
  - the `developer_resync_indices` activity rows;
  - the `feature_flags` column.
- **Generic uses of "developer" are untouched**, such as provider portals and "Developer
  settings" in GitHub instructions.

### 5. The MCP tool

- **Renamed.** `structure_with_studioos` is listed as `structure_with_axalvc`, titled
  "Structure an interview with Axal VC".
- **The old name is an alias.** Calling it reaches the new tool through the tools/call
  gate (`toolAliases`), but it is never in tools/list.
- **The stored name is unchanged.** `storedAs` keeps `structure_with_studioos` in three
  places: the usage ledger's `operation`, the `mcp_tool_call` log and the metering price
  key.
- **An alias can never shadow a listed tool.**
