## D690 — Cycle record contract, owned activity, stable Validate IDs and consented exports

Status: Decided. Date: 2026-10-17. Slot: S18. Issue: #1690. This is part 1 of 3; #1691 and #1692 complete Validate's lists and records.

### Decisions built in this part

1. **One record contract serves the four cycles.** A `ModuleSpec` defines read and write gates, an owned store, one record read, gated sections, declared actions and optional form options. The shared Worker route reads a record and its activity, runs only actions declared for that record and viewer, and passes all query parameters except `project` to `formOptions`. Form actions carry T, CH and CK fields and an `input` hint where needed; file actions pass multipart form data to their writer. PATCH and DELETE use the same `edit` and `delete` action writers.
2. **Each store keeps its own gate.** A section requiring write access is omitted for a reader, not returned as an empty section. Partners may read the board's ordinary record facts, but not writer-only session details or actions. Advisor, investor and foreign-founder requests are refused. Actions and form options require write access.
3. **Ownership precedes record access.** A route checks the project and the row's actual store before a record read, activity read, action, PATCH or DELETE. Foreign and malformed IDs answer 404. Action body references declare their store for the same check. Validate's ten existing stores have fixed, bound ownership queries, including joins through a competitor analysis, hypothesis and interview.
4. **List IDs are stable path IDs.** A grouped pain theme uses its group ID; an ungrouped phrase has no record ID. Demand IDs use `signal-`, `revenue-` and `waitlist-` prefixes. A candidate ID that fails `^[a-z0-9][a-z0-9_-]*$` is not linkable. Validate's module read reports `records.linkable: false` until #1692 registers its record service. No person's name is an ID.
5. **One activity convention attributes writes.** New rows carry project, user, `cycle.module`, record ID, action, a one-line summary and actor `user:<id>`. A summary names records by code or title (a hypothesis by its code, a theme, feature or segment by its title, a roadmap item by its objective; an interview keeps its ID, because its title is the interviewee's name) and never contains an interviewee's name, quote or transcript. A link writes one row on each side, and only when the link was inserted. Module-level writes (the interviews and waitlist targets, the market readiness marks and the market sources) have no record in today's lists, so they log `entity_type` `<cycle>.<module>` with `entity_id` NULL, which no record read matches; `logCycleWrite` takes `entityId: null` as that explicit module-level form. A record's create row is one of a fixed set of actions shared by the activity count and the renderer: every name ending `_created`, `interview_logged`, `segment_written`, `demand_signal_written`, `waitlist_promoted`, and `competitor_mention_written` on the row whose write added the candidate. Rows #1736 logged under a record address for a module-level write, or under `validate.customer-segments`, between its deploy and this correction are re-filed once by migration 470. A batched create can read back its new ID within the activity statement from a fixed table and a bound UID or project ID. Record activity pages are 20 newest first. Existing free-text Validate activity stays untouched and is not guessed into a record's history; a spec must explicitly name any older row shapes it can safely read. Migration 459 adds nullable creator columns to pain groups, hypotheses, MVP features and roadmap OKRs, plus the scoped activity index. An older row with no creator says `Created <date>`.
17. **Exports carry writer access and quote consent.** The interviews and pain-map CSVs require the venture's own writer or an admin. Partners cannot export either. An interview's pains cell includes phrases only with recorded quote consent. With pains and missing or refused consent it says `Withheld (no consent to quote)`; with no pains it is empty. Interview notes remain in the writer's export, and pain-map content stays as it was.
19. **The work ships in three ordered PRs.** #1690 builds the contract, activity, IDs and export gates; #1691 builds lists and bottom-section reads; #1692 registers Validate's six records and their new writes. An Add or record link is shown only when its backing service exists. Other cycles register their own services later.

### Canvas departures and limits

The canvas shows every row as openable. Ungrouped pain phrases and malformed legacy candidate IDs have no safe record address, so their row ID is null. Validate's rows are not openable until #1692. An older activity row without a record key is not assigned to a person or record by parsing its sentence. These limits keep navigation and attribution truthful.

### Decisions built in part 2 (#1691)

9. **Each interview shows its state.** The module read sends `state` as a key, from the interview's latest session (by id) and its stage. The first rule that matches wins:

   | State | Key | Rule |
   |---|---|---|
   | Failed | `failed` | `processing_stage = 'failed'` |
   | Recording | `recording` | status `recording` or `paused` |
   | Waiting for messages | `waiting_messages` | status `draft`, `submitted_via` is `telegram` or `whatsapp` |
   | Waiting for the call transcript | `waiting_transcript` | status `draft`, `submitted_via` is `zoom` or `google_meet` |
   | Processing | `processing` | `processing_stage` is `uploading`, `transcribing`, `summarising` or `placing`, or status is `stopped` or `transcribing` |
   | Ready to review | `ready` | status `transcribed` or `structured` |
   | Reviewed | `reviewed` | status `reviewed` |
   | Lead, Invited, Booked | `lead`, `invited`, `booked` | no session past `draft`, and `stage` is `lead`, `invited` or `booked` |
   | Logged | `logged` | no session past `draft`, and the interview is held |

   The Waiting rules are the frontend's `openingStep(session) === 'channel'`. "No session past draft" reads the latest session: none, or one still `draft`. The adapter maps each key to the words above. The row also carries `role`, `pains` (how many recorded), `duration_min` (the latest session's active time, else the recording's own duration; null when neither) and `session_id`, which only a writer receives, since the session is a writer's detail (decision 2).
10. **Each list carries the canvas's title, columns, filters and sorts** (CO:611-616), sent as `records.filters` and `records.sorts`, default sort first. Customer research's columns are the canvas's five plus State; Channel stays a filter, and the adapter's `keys` line and `state` cell change in the same PR, so no channel is drawn under a State heading. Filters run before paging. Problem discovery adds ICP only (`icp:yes`), Need-to-have (`need:yes`) and Most recent (`sort=recent`). The profile's Fit filter is `fit:strong` (a strong-fit interview) or `fit:none` (none), and its one listed sort is Evidence. Experiments' Status lists Fit not recorded and Retired, Sprint lists the venture's open claims' sprints, and its History filter holds As of last week and Changed this month as two options of one key. The recruiting picker keeps `filter=stage:pipeline` and `sort=booked`, which still work but are not listed.
16. **The module reads carry what FVW's three pages computed,** so #1659 draws them and FVW can go (#1666). `parts` sits beside `records`, and each count covers the whole venture, never the page. Every module sends `parts.can_write`. Customer research's `stats` are FVW's strip. Problem discovery's `stats` are FVW's tiles, from `getPainGroupsView`, with `need_themes` and `icp_themes` null until a severity or fit is recorded. Its `themes` list is for writers only and absent for anyone else, and `unthemed` lists the 25 newest phrases that sit in no group, one per interview, beside `unthemed_total`. Experiments' `stats` count the open claims (`awaiting` is Testing plus Untested, `withheld` is Fit not recorded), and `fit_gap` gives each undecided claim's ICP support against the bar. A phrase said in an interview whose `quote_consent` is not 1 reaches a non-writer as "Quote withheld (no consent to quote)", in `unthemed` and in each theme's `wordings`. The views read the verdict history and never write it (#1666 adds that write):
    - Recently moved is a lane change within 14 days (`RECENTLY_MOVED_DAYS`). Every such row carries `moved: 'recent'`.
    - As of last week shows each claim's status from its observation in force seven days ago, with Inconclusive only if it was marked by then. A claim with no observation that old is left out.
    - Changed this month keeps claims whose verdict changed with the later observation on or after the first of the month (UTC), at today's status.
    - A change is two adjacent observations that disagree. The first observation is never one. `parts.stats.history_since` is the venture's first observation, or null, so the page can say where the record starts.
