## D8004 — Reuse locked installation inputs (#8004)

The build helper explicitly requires hashes for the Python runtime requirements.
Existing versions and platform markers are preserved, and the missing declared
runtime dependency is pinned alongside them so hash mode has a complete input.
Each pin records accepted release-artifact hashes. Existing pip consumers of this
file also enter hash-checking mode from those hashes.

The backup and recovery workflows install the Worker's lockfile with `npm ci`
and publish its absolute local CLI directory for subsequent steps. Their
preflight, credential scopes, operational commands and cleanup retain their
existing order and behavior.

Local verification covers requirements preservation and dependency closure,
installer success and failure with fake tools, later-step PATH selection, and
the existing backup and recovery checks. An isolated Python 3.12 pip dry run
resolved the active requirements with hash checking; it did not install the
runtime packages or test their imports. Source-only Python dependencies retain
their build behavior: application hashes do not freeze the separate isolated
build-tool environment, and metadata closure does not prove runtime compatibility
on every platform.
