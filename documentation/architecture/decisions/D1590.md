## D1590 — The recorded walkthrough: a take per card, captioned by the Listen job, kept until its maker deletes it (deck v2 F11)

- **Status:** part 1 (Worker and client) built by S17 on 2026-11-03 (#3837, deck v2 F11, part of #3716). The pd36 Record screen, the adapter swap and pd35's Walkthrough column follow in the same PR.
- **Number:** D1590, given at filing on #3837.
- **Migration:** `202611031710_deck_recordings.sql`. #3837 named 747, but D4106 now gives every new migration its UTC minute, so the file takes the stamp.
- **Owner decision W = A (2026-11-02):** a recorded walkthrough is kept until the founder deletes it, or until its deck or account is deleted, through the existing cascades. There is no automatic expiry. The delete must remove the stored file, not only the row, with a test.

### The stores

- **`deck_recordings`:** one row per take of one card of a deck version, by its maker. It holds the R2 key, MIME type and size of the take's file (camera and microphone), its length, and its captions as timed cues in milliseconds from the take's start. It also holds the caption model, its usage row and the charge.
- **`deck_recording_links`:** which share links play the walkthrough ("Attach to [Fund]'s link"). Attaching is per link; a link plays every card's newest take.
- **Cascades:** both go with their deck version and their maker's account; takes also go with their venture.

### The routes (`routes/deck_recordings.ts`, self-mounted before `decks`)

- `POST /api/decks/:id/recordings/quote { duration_ms }` returns `{ model, job, hold_microusd, minutes, balance }`. `job` names the Listen job that chose the model (DK11).
- `POST /api/decks/:id/recordings` takes a form: `card`, `duration_ms`, `media`, `audio?`, `model?`. It returns `{ take, walkthrough }`.
- `GET /api/decks/:id/recordings` returns `{ deck_id, cards: [take | null], recorded, links }`.
- `GET /api/decks/:id/recordings/:uid/media` returns the take's file (`private, no-store`).
- `DELETE /api/decks/:id/recordings/:uid` returns `{ deleted: true }`.
- `PUT /api/decks/:id/recordings/links/:shareId { attach }` returns `{ links }`.
- **Who:** the founder, on a deck version they may write. A walkthrough is its maker's, so a co-founder never reads another's takes. A support session may not record as the member.
- **The switch:** `deck:walkthrough` (HQ › Decks, #4189). Off answers 404 `not_switched_on`.

### Captions

- They run through `run()` with `speechJob: WALKTHROUGH_CAPTIONS` (`DK11C`, the DK11 Listen class: Whisper Large v3 Turbo, or Whisper), on the rail option `transcribe:walkthrough`, page "Founder · Raise · Pitch deck". No route calls `env.AI.run`, and no model id comes from outside `catalogue.ts`.
- The run is quoted and the balance checked before the file is stored. The cues are `captionsOf` the transcript's segments.
- **The sound captioned** is the take's own audio track when the browser sends one (`audio`, at most 5 MB), else the take itself when it is audio the model reads.
- **Refusals.** A refusal the member must hear about (assist off, a budget stop, the guard, a plan lock) stores nothing. A model that cannot be reached keeps the take, with its captions Not recorded (`null`, never an empty list). In practice every such refusal is caught at the quote, before the file is stored.

### Takes, retakes and deleting

- A take is at most three minutes and its file at most 40 MB (`webm`, `mp4`, `ogg` or `m4a`).
- **A retake** of a card adds the next take number ("Slide 1 · Take 2"). It then removes that card's earlier takes, row and file, and never reads another card's.
- **Delete** removes the R2 object first, then the row. A file that cannot be deleted keeps its row (503), so it is never lost track of.
- **After a cascade.** A row that leaves by a cascade (deck, venture or account) leaves its object behind. The daily cleanup (`models/jobs.ts` → `sweepOrphanRecordings`) deletes an object under `deck-recordings/` whose row is gone, once the object is a day old, so an upload whose row is still being written is never taken. It deletes at most 500 a run.

### Storage

A take is kept until its maker deletes it, so every stored take counts against the venture's storage plan.
- The upload asks `assertStorageRoom` before the write (413 `storage_full`) and `noteStorageLanded` after it.
- A new D1169 area, `deck_recordings` (kind `recordings`), counts each stored take at its `media_bytes`.
- `DATA_RETENTION.md` has both tables' rows.

### Tests

`cloudflare-worker/test/deck_recordings_d1590.test.ts` (8 cases):
- captions within 0.5 s of the audio's timing;
- a retake of one card leaving every other card's takes and files intact;
- delete removing the stored file;
- the captions as the Listen job's charged run on the rail option;
- a budget refusal storing nothing, and an unreachable model keeping the take;
- attach to a live link of this version only, another member refused, and a card outside the deck refused;
- the switch;
- the orphan sweep.

Mutations, each caught:
- the retake without its card filter;
- delete keeping the file;
- the sweep without its age check;
- attach to any version's link;
- the run without its speech job;
- storing seconds as milliseconds.

The run's own refusal after the upload (the file deleted again) cannot be reached from a route test: the guard does not refuse a transcript, and every other refusal is caught at the quote. It is not tested.

The suites that list the storage areas, the R2 writes and the deck keys were updated for the new area, the guarded upload and `deck:walkthrough`: `usage_storage_d1169`, `storage_room_d1170`, `feature_flags_deck_4189`, `usage_page_d642` and `usage_records_d642`.
