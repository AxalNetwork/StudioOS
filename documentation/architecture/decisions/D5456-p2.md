### 1. What is switched on

`PREPARATION_MUTATIONS_ENABLED` is now `create: true, edit: true`; `submit`, `review`, `publish` and `withdraw` stay `false` (submit waits for ADP-04's review and after-submit editing rule). Authority is unchanged: `preparationCapabilities` grants them only to a platform admin on the row's own deployment, outside a support session, whose writes are not frozen (D135). A partner, investor or founder, any licence and preview mode still hold nothing; a frozen admin keeps `read`.

`POST /api/admin/deals` and `PATCH /api/admin/deals/:uid` now create and save. When a caller holds `read` but not the write, the router answers `preparation_mutations_disabled` only if the flag itself is off, and otherwise `preparation_create_not_permitted` / `preparation_edit_not_permitted`, so the switched-on routes never claim to be switched off.

### 3. The Draft Deal dialog

The Studio lens's **Draft a deal** (admins only) opens the same dialog with one choice at the top:

- **Private draft** (the default) creates a preparation through `adminDealPreparationsApi.create` with the project's own company (`projects.company_id`; a project without one is refused in the dialog and by the server), then each **Save changes** sends only the fields that changed through `adminDealPreparationsApi.save` with `expectedRevision` set to the revision token the last save returned. The project is pinned once saved. An operation key is minted per payload and reused only when the same payload is retried after an "outcome unknown" answer or a lost connection, so a retry never creates or saves twice.
- **Live deal now** is the existing form and `api.draftDeal` call, unchanged (lead partner, stage and source included). The founder/investor test's draft-source assertions still read it.
- **The release gap, said plainly.** Beside the private choice the dialog says: "A private draft is for admins only. It cannot go live, reach investors or appear on the board yet: the reviewed release that publishes a draft is not built. If you need a live deal today, choose Live deal now." Closing after a private save confirms "Saved as a private draft. It is not live and is not on the board until the reviewed release ships."
- **Refusals are sentences.** Every private-save refusal is worded from its code in `draftPreparationModel.refusalSentence`, never `e.message`. A `revision_conflict` names the revision that won and the fields it changed (from the 409's `current` and `fields`), says nothing was saved, and offers **Load the latest version**, which reloads the authoring view and resets the revision the next save starts from. `open_preparation_exists` offers the same button for the existing draft.
- **Minimal, not a screen.** Private mode carries the ten fields the dialog already had that are D5456 content keys. No canvas exists for this dialog, and the full authoring screen (title, brief sections, #6196 terms, sources, readiness, revision list) is ADP-05's. The dialog is checked at 390 px and in dark mode.
