## D1237 — Deal-flow room requests record the firm and keep access explicit (#3250)

- **Task:** #3250, part 1 of #2423; S26, implemented by s30 (Codex).
- **Base:** main at `e1ede91398`. No migration, new client method or deployment.
- **Access:** Professional still gates the deal list. An investor reads a deal only when invited or committed; a room request does not widen that rule.

### Worker

A join records the verified active `company_id`, using the same resolver as the list and quota. An unverified header still resolves to NULL under the existing company-selection policy; its raw value is never stored. Existing NULL requests retain their legacy visibility.

The schema's unique key is investor/deal, not investor/firm/deal. An idempotent repeat in the same firm succeeds without a second audit. A request already held under another selected firm returns `room_requested_for_other_firm` (409), rather than claiming membership for the wrong firm. The UNIQUE-race handler re-reads that row and applies the same check. Leaving under another firm cannot delete its request; a matching firm, no selection, or a legacy NULL request follows the existing scope rules.

Free may GET its room quota, POST a numeric deal's join and DELETE its leave. Those precise middleware exemptions do not open `/api/deals`, child reads, diligence or other methods/paths. Free's cap is one even if a stale paid-plan column says five. Usage remains global across firms. The INSERT repeats the allowance check atomically, so two requests cannot consume the same final slot. Existing actor audit rows retain the verified firm, never a name or amount.

Investor list rows add `can_read` from the existing bulk invited-or-committed helper (`userReadableDealIds`), which uses the deal page's access predicate. No new per-row request is made. `is_member` remains firm-scoped; `scope=mine` remains the existing firm-scoped invitation/commitment filter. Read access itself remains the existing deal reader's rule.

### Frontend

`DealRoomsPanel` links only `can_read === true`. Other rows retain their names and request controls, with the invitation/commitment explanation. A missing or malformed access flag says access could not be confirmed and draws no link. An invitation request is labelled as such, rather than Member.

Join and Leave use the shared `Lightbox` confirmation. The explanation says what changes, that nobody is notified automatically, and that a request grants no access or withdraws no commitment. Back makes no write. Confirmation makes one request, then re-reads the panel; a refusal remains inside the dialog.

The `api.js` comment now defines Mine as invited or committed. The Deals rail says Eadwyn drafts on request and contains no advice or recommendation claim.

At this base, D1236's integration PR #3210 is still open; its listed DealFlow files and design exports are not in main. This task fixes the shared existing room panel/router and rail without copying that integration's files or inventing the future list. Integration with that new root remains a live/integration check.
