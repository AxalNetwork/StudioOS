## D5583 part 4 — Short-lived signed delivery of media revisions, streamed through the existing blob store (#5583)

Preview-only internal service, Part of #5583, following part 3 (D5583-p3). Like parts 2 and 3 it is unmounted: no
route calls it, no link is issued to anyone, and no new binding, secret, table or migration is added. Synthetic bytes
and the existing test stores only.

### What it adds

- `streamRevisionBytes` in `workGraphBlobs.ts`: a revision's bytes as a stream, never buffered whole. It shares
  `readRevisionBytes`' admission (now one private `admitRead`: shape, existence, the caller's scope, the `offline` and
  `bytes_deleted` flags, WorkGraph-held bytes, the row's own typed key), so the two reads cannot admit by different
  rules. `readRevisionBytes` keeps its buffered contract for its existing callers.
- `verifyingStream` in `sha256Incremental.ts`: passes a stream through while hashing it (the runtime's
  `crypto.DigestStream` in Workers, part 3's `Sha256` elsewhere). The last chunk seen is held back until the byte
  count and digest match; on a mismatch the stream errors instead of closing. More bytes than declared error at the
  chunk that crosses the size. Memory is one chunk.
- `signPurposeToken` / `verifyPurposeToken` in `signedDownload.ts`, the module every private download already signs
  with: the same secret (`KEK_R2`, else `JWT_SECRET`) and token shape (`b64url(payload).b64url(HMAC-SHA-256)`,
  compared in constant time), under a key derived for one purpose (`<purpose>:<secret>`, the derivation
  `learningStream.ts`'s source tokens use). The payload also names its purpose. A media token is therefore not a
  download token: `/api/files/dl` cannot redeem it, and a download token does not open media. Null without a secret
  of at least 16 characters, and for a token over 2,048 characters.
- `workGraphMediaDelivery.ts`: `mintMediaDelivery` and `openMediaDelivery`.

### The link

`mintMediaDelivery` mints only for a caller in scope, whose author is not revoked, for a revision that is a typed
media object (`master`, `snapshot`, `rendition`, `thumbnail`) at its own key, is its asset's current head, is not
tombstoned and carries no live flag (`offline`, `bytes_deleted`, `bytes_missing`, `residency_mismatch`, the same set
the head swap refuses). The token binds tenant, company and project, the asset and revision, the digest and size,
the object class, the asset's head sequence, issue time and expiry, a link id, and the minter (user, and agent run if
any). It carries ids, a digest and numbers only: no object key, no content. The lifetime is at most five minutes,
`signedDownload.ts`'s ceiling for private downloads (task #33); a claim set with a longer lifetime is refused on open
even when correctly signed.

`openMediaDelivery` takes the token and the reader (actor and `ValidationContext`). It refuses, in order: a missing
key (`no_signing_key`), a bad signature or another purpose (`bad_signature`), malformed claims, an expired link, a
reader whose scope does not cover the bound scope (`wrong_tenant`, before the revision is read), and a minter the
reader's context lists as revoked (`revoked`). It then hands the binding to `streamRevisionBytes`, which rechecks it
against the revision as it is now: the bound scope and asset are the row's (`wrong_tenant`), the digest and size are
the row's (`digest_mismatch`), the class is the key's (`not_media`), the revision is not tombstoned (`revoked`) and
carries no live flag, and it is still the head at the same head sequence (`superseded`; a head that moved away and
back also supersedes the link). R2's own answer is checked before the first byte (size, R2's SHA-256 checksum when it
has one, the digest in custom metadata), and the body is then verified as it streams.

A link may be opened more than once before it expires (a preview is requested again by the browser). It is not
single-use, so it needs no KV; everything it opens is rechecked on every open, which is what stops it.

### Audit and cost

Minting writes nothing (it reads one row). Every open is audited in `work_graph_integrity_events` with the existing
actions, so the table's action list is unchanged and no migration is needed: `bytes_read` when the stream is handed
out (detail: link id, minter, expiry, `delivery: signed`, `streamed`, `method`), `read_refused` with the code for every
refusal, and a second `read_refused` (`digest_mismatch`, phase `size` or `digest`) if the body turns out wrong while
streaming. Ids and digests only. Each result returns its cost: D1 statements and batches and R2 Class B reads; a
claims-level refusal costs one audit statement and no read.

### Tests and mutations

`cloudflare-worker/test/work_graph_media_delivery_5583.test.ts` (11 tests) refuses a wrong tenant (another tenant,
another project, claims rewritten to another tenant, claims widened to the company), an expired link and a lifetime
over the cap, a tampered signature or payload, another purpose, another key, no key and an oversized token, a stale
revision (superseded by a newer head, a forged head sequence, offline, tombstoned, a revoked minter, a live
`bytes_missing` or `residency_mismatch` flag), and a checksum mismatch (in the claims before any R2 read, in R2's
checksum or size before the first byte, in a row whose key names another digest, and in a rotted body, where the
stream errors and its last chunk is never released). The streaming test serves a 40 MiB synthetic master from a
pull-based body that refuses a whole-object read, checks bytes leave before 1 MiB has been pulled, hashes what
arrives, and shows a rotted last byte errors with one chunk withheld. 39 mutations of the gates were run; all were
caught.

### Left for later gates

Mounting any route, and with it how a reader's context is built for a link opened from a page, response headers and
range requests; activation; renditions and transforms (#5571); scheduling part 3's sweep; the migration/deploy order,
quota-cost benchmark and lifecycle rehearsal before activation; actual artwork rights and provider authorization.
Older (non-head) revisions are not deliverable by link; a caller in scope reads them through `readRevisionBytes` or
`streamRevisionBytes`.

### Coordination

`workGraphMedia.ts` is unchanged, and no media version identity changes: #5582's pinning of D5583 media versions in
deck exports reads the same revision rows and keys.

### Rollback

Leave the service unmounted. Nothing was stored; tokens expire within five minutes. The shared `admitRead` keeps
`readRevisionBytes`' behaviour, and the added refusal codes (`superseded`, `revoked`, `not_media`) are returned only
for a delivery binding.
