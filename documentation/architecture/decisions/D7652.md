## D7652 — Refresh sources leaves the rail inventory: it runs no model (#7652)

- **Status:** built 2026-11-19. Follows #7211 (D7176, owner answer A) and the owner's answer A on #7176 (2026-11-19).
- **Builds on:** D720 §11, D771 (founder inventory), D773 (advisor inventory), D778 part 9, D4313 (option jobs), D7176.

### Decision

Since D7176, `POST /api/competitors/:id/refresh` fetches the stored sources again and runs no model, so it logs no AI run. The rail inventory's own rule (`frontend/src/lib/railOptions/README.md`: "an option that runs no model is not a row") settles which of the issue's two fixes applies: the rows are **dropped**, not re-kinded. The inventory has no fetch kind (a row's `kind` is one of the canvas's fourteen task kinds, each of which picks models), and `noModel` is for Ask chips the rail offers, not for a button on the page. The page still offers Refresh sources (`CompanyAnalysis.jsx`, `CompetitorAnalysis.jsx`); it simply no longer names itself to the rail.

### What changed

- `founder.js` loses `analyse:sources` (Founder · Research · Companies); `advisor.js` loses `refresh:sources` (Companies).
- `CompetitorAnalysis.jsx` and `CompanyAnalysis.jsx` drop their `useRailOption` call for Refresh sources and press `api.competitors.refresh(id)` with no rail headers. The route never read them.
- The Worker: `COMPANIES_OPTIONS.sources` is gone from `services/competitorAnalysis.ts` (it was never passed to a run after D7176), and both keys leave `RAIL_OPTION_JOBS` in `services/ai/textJobs.ts`, whose test refuses a job for an option no inventory registers. `railMatrix.json` is regenerated (`node scripts/build-rail-matrix.mjs`) without the two option rows.
- Tests: the founder and advisor parity tests no longer count `api.competitors.refresh(` as a model call; `rail_options_run_d779_part2` pins 13 advisor rows and asserts both refresh presses send no option; `rail_options_wired_d773` asserts no profile lists the refresh control; `founder_competitors_d778` (frontend and Worker) asserts the refresh press sends no rail headers and still logs no run.

### Not changed

- `api.competitors.refresh(id, headers)` keeps its optional `headers` argument (`api.js` is a frozen hub); nothing passes it.
- `railOptionFor`'s `controlOf` still reads `api.competitors.refresh(` as the control `competitors.refresh`; with no row behind it, the lookup answers null.
- Earlier decisions (D773, D778, D779) that list the keys are records of their time and are not edited.
