## D998 — Persona segment profiles and reachable onboarding

2026-10-25 · #2813 · S20 / s30 · Part of #2378. No migration.

### The mapping

The taxonomy now describes each segment with `profile`, replacing the obsolete
`role_alignment` field in the Worker, frontend and dev FastAPI mirror. The five
values are the existing account profiles: founder, investor, advisor, partner,
exploring. This is descriptive metadata: choosing or retagging a segment does
not change users.role, permissions, subscriptions, primary/secondary rules,
question banks or stored answers. A segment may differ from the account profile;
that difference is what SEG1/SEG3i will report in the later reads.

- Investor: lp_individual, lp_institutional, gp_external, angel_scout,
  corporate_vc, sovereign_family_office.
- Founder: founder_new, founder_existing.
- Advisor: operator_advisor.
- Operating Partner: service_provider.
- Explorer: academic, press_analyst.

`persona_sources_agree.test.mjs` reads the three mirrors' new field and pins all
twelve assignments independently of their agreement, so three equally wrong
copies cannot pass. IDs, labels and follow-up question keys remain the existing
twelve. Future D999/D1000 can use this profile field for counts and seed data.

### Navigation and the checklist

App's actual sidebar grouping compares the segment's profile with the member's
current role. An Investor's Angel/Scout, institutional LP and GP links can now
pass that check. A mismatched or unknown segment adds no extra links. Existing
sidebar links are still deduplicated; a segment with an empty nav list invents
none. This rule does not grant access to a destination: its existing role and
tier guards still apply.

Operator / Advisor's old `/build` extra was a Founder-only destination. Both nav
mirrors now name the existing Advisor `/practice` workspace. Since Practice is
already in that sidebar, no duplicate group is drawn.

`/onboarding/persona` now admits Advisors alongside its four existing roles.
Their `mt.persona` checklist item points there instead of `/account/profile`:
the existing completion detector requires a primary user_personas row, so the
step must open the wizard that writes it. Other Advisor routes, Trust, Connectors
and auto-detection rules are unchanged. SQLite tests exercise an Advisor's actual
finalize request, then the real checklist's pending-to-completed transition,
and verify the account role stays advisor. Anonymous completion and an Advisor's
admin-list access remain refused.

### Guide and scope

The getting-started guide names the six Investor segments and Operator / Advisor,
and explains that a segment does not change the account profile. The old claim
that Investors and Advisors have one persona each is removed.

No new endpoint, schema, aggregate read, counts or admin segment write is added.
D997's Persona segments screen lives in the separate #2809 integration; this
branch starts from main as #2813 directs. No ROUTE_MAP row changes: this task
changes taxonomy metadata and existing access/navigation, not that page's reads.
The taxonomy endpoint now returns profile; the SPA consumes the same field from
its mirror. No runtime consumer of role_alignment remains in this repository.
