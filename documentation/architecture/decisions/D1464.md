## D1464 — Read with a reason, per open: the gate on the Data room and Capital relationships, and the founder's support-read logs (#4021)

- **Status:** built by S11, 2026-11-01. Part of #3713.
- **Builds on:** D1463 (#3713, #4023: `ReasonGate`, `AccessBanner`, `AccessPill`, `RecordSkeleton`, and the rail's `readOnlyFor="founder-record"`), D1102 (the Data room's admin summary and `POST /data-room/:p/support-read`), D1191 (Capital relationships' staff refusal, `POST …/support-read` and `GET …/support-reads`).
- **Boards:** RR09 (the founder's logs), RR11 (Data room), RR12 (Capital relationships), RR18 (an owner who cannot be resolved), on S1's spec (G3).
- **Supersedes:** D1101's and D1102's admin aggregate on the Data room's tabs. An admin no longer sees `AdminRoomSummary` there; the component stays in `DataRoomSummary.jsx` with its own test.
- **Migration:** none.

### 1. The Data room (RR11)

The Worker answers an admin's `GET /api/data-room/:p` with a summary (`mode: 'summary'`), never the room. `DataRoomTabPage` now draws `DataRoomSupport` for that answer, on every tab:
- `ReasonGate` in per-open mode: `record="Data room"`, `what="this data room"`, 1–500 characters (the Worker's own limit), with a `RecordSkeleton` behind it. Nothing of the room is drawn before the reason.
- Open sends the reason squashed to `dataRoomApi.supportRead` (`POST /data-room/:p/support-read`). The answer (`mode: 'support'`) is drawn read only under `AccessBanner` with no `endsAt` and no `onEnd`: a per-open read has no end to count to.
- The files list by folder, gate and tier (`fileRows`), each opening its detail in the right Sheet. No upload, share, NDA or download control is drawn: the support answer carries no signed link, and no write is offered.
- Nothing is kept: a reload, or leaving the module, asks again.

### 2. Capital relationships (RR12)

Staff get 403 `support_read_required` on every private read (D1191). `CapRelTabPage` takes `admin` from CycleRoute (`user.role === 'admin'`) and draws `CapRelSupport` on every tab:
- the same gate, `what="these capital relationships"`, 1–500 characters;
- one response from `capitalRelationshipsApi.supportRead(projectId, reason, { page })`, drawn read only under the banner: each investor's name, firm and stage. An email or a note in the answer is never drawn.
- Each further page is a further private response, so **Next 25** returns to the gate with an empty field; the next reason asks for page 2.

### 3. RR18 and a failed save

Both come from `ReasonGate`'s `refusalView` (D1463):
- 409 `support_owner_unresolved` draws the muted line, with no form and no Try again;
- 503 keeps the field, with "The reason could not be saved. Try again."

### 4. The founder's logs (RR09)

`SupportReadsCard` (`pages/raise/SupportReadsCard.jsx`, words in `pages/raise/supportReads.js`) is one card for both records, on each record's Activity tab:
- each row is "<name> · <Studio admin|HQ>", the reason, then "<when> · one open";
- a name, kind, reason or time the Worker did not record says Not recorded;
- empty: "No admin has read your data room." or "No admin has read your capital relationships.";
- a failed read, or an answer with no list, is "Unreadable" with Try again, never the empty line;
- 25 to a page, with Show more.

**Two Worker additions.** The issue named no Worker change, but its RR09 needs two facts the Worker did not send:
1. **The Data room had no founder-side read of its support reads.** The audit rows existed (`activity_logs`, `data_room_support_read`), but no route returned them. `GET /api/data-room/:p/support-reads` now does:
   - the owner and an accepted co-founder through `roomProject`; anyone else, an admin included, gets 404, as every room route answers;
   - bound SQL;
   - a failed read is 503 `support_history_unreadable`, never an empty list or the database's text;
   - no email and no account id.
2. **Neither history said whether the reader was a Studio admin or HQ.** `services/supportReads.ts` reads the reader's kind at read time: `super_admin` when the account holds a `super_admins` row, else `admin`, and null when the account is gone. `capitalSupportHistory` adds the same `reader.kind` to its existing rows; nothing else in its answer changes.

### 5. The rail and the pill

- CycleRoute keeps `supportOpen`, set by the pages' `onSupportRead`. While a per-open read shows, `WorkerRail` gets `readOnlyFor="founder-record"` (Eadwyn off, Q1 A), as the narrative already does.
- The pill and the banner say HQ for the Super Admin (`isSuperAdminUser`) and Studio admin for an Admin.
