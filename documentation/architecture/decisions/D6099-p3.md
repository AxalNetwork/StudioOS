### What the canvas decides
- Rename sits on the selected theme's heading, "[Exprot] · 6 feedback rows · 1 roadmap item", in the theme column on desktop (GR-43) and on the selected chip's heading at 390 (GR-48), not in a block of its own. A name that is already a theme is a merge, which asks in place of Save and names both themes and both counts (GR-44). When the list was stale, the question carries the Worker's 409 counts and "The counts changed since this page loaded". - Refusals keep the typed name (GR-45): empty, same name, not found with Reload themes, and read-only (403), in the Worker's words. A name that differs only in capitals is a note before Save, and Save still makes a separate theme.

- States (GR-47): no Rename until the counts arrive; unreadable counts replace Rename with "Rename is unavailable: theme counts could not be read." and Try again, while items, weight and Close the loop keep working and nothing reads 0; a reader or advisor sees nothing of the control, not a disabled button; Saving; Save failed with the name kept.

Eadwyn proposes nothing on this control: placements into a theme still named keep Accept, Edit and Discard, and a placement into the old name is held back and counted, never moved.
