## D7744 — A fund catalogue row carries its own size currency and record kind (#7744)

Before this, the Worker took a size's currency from its list's name (`LIST_CURRENCY`: EuroTech in euros, Shai Goldman in US dollars). A third list's size was nulled on read. Filters, bands, sort, facets and coverage each bound one list name per currency. Nothing said whether a row was a fund vehicle or a manager.

### Schema (migration `202611270508_7744_research_fund_size_currency_and_kind.sql`, additive)

- `research_fund_directory.fund_size_currency` and `research_fund_directory_reports.fund_size_currency`: three capital letters, or NULL.
- `research_fund_directory.record_kind`: `vehicle`, `manager`, `accelerator` or `resource`, or NULL. NULL reads "Kind not recorded".
- Triggers on insert and update check both, and a CHECK constraint does not. A later migration can widen either set by replacing a trigger, with no table rebuild. Allowing a kind puts no row in the catalogue. Which kinds are shown is #7740's decision.
- `research_fund_list_defaults` holds each list's kind and size currency. Its rows, as read from main `d26a93a25` on 2026-11-27:

| Source name | Kind | Size currency | Where the name comes from |
| --- | --- | --- | --- |
| `EuroTech VC Funds (public spreadsheet)` | vehicle | EUR | migrations 378 and 7166 |
| `Shai Goldman — new VC funds at/below $200M` | vehicle | USD | migration 429 |
| `Axal VC curated global fund directory` | manager | — | #7326, migration `202611181335_7326` |
| `Axal VC — verified fund manager websites` | manager | — | PR #7337 (merged as `6eb5d82f4`), migration `202611181350_7325` |
| `Axal VC verified global fund managers (2026-11-19)` | manager | — | PR #7586 (merged as `be00842fb`), migration `202611190015_7585` |

The Deep Tech mapping is not listed, so its rows keep NULL for both columns. The two names that were pending when the issue was filed are now merged. Both are read from the merged migrations, which sort before this one.

- Backfill: for every listed list, a row gets the list's kind, and the list's currency when the row has a size. A report row with a size gets its fund's list currency. On a fresh build of main's fund migrations plus this one, the rows with a size equal the rows given a currency. That is 1,327 EuroTech rows and 2,310 EuroTech report rows in EUR, and 886 Shai Goldman rows in USD. The test pins these counts.
- Insert triggers stamp a listed list's row that arrives with no kind, or with a size and no currency. They stamp a report row the same way. `scripts/import-research-funds.py` writes `INSERT OR REPLACE` without the new columns, so a re-import cannot blank a list's sizes or kinds. A row of an unlisted list is never stamped. A promoted row writes its own values or none.

### Reads

- `services/researchFundDirectory.ts`: `presentFund`, `getFund`'s report rows, the size filter, `size_band=none`, the bands, the size sort, the size facet, coverage and the per-source line all read the row's currency. No read compares `source_name` to decide a currency. Sizes are never converted. `DIRECTORY_COLUMNS` and `directoryColumns(alias)` export the row column list, now with `fund_size_currency` and `record_kind`.
- `size_currency` accepts any three-letter code, and EUR stays the default. Anything else is a 400. A code that no served row holds matches no size, and is not an error. The parser stays synchronous and shared with Capital relationships.
- New answer keys, all additive: `size_currencies` (the currencies served sized rows hold), `coverage.fields.size_by_currency`, `coverage.kinds`, `sources[].size_currencies` beside the kept `size_currency`, `record_kind` and `record_kind_reason` on list rows and the single read, and a `kind` parameter (one of the four, or `none`) with `facets.kind`. `size_eur`, `size_usd` and `size_unknown_currency` stay. `size_basis` and `facets_basis` are now derived from the asked currency and name no list. `SIZE_BASIS`, `SIZE_CURRENCIES`, `LIST_CURRENCY` and `currencySource` are removed.
- Other reads now select the column list: the profile's other vehicles and history (`researchFundProfile.ts`), where a report row shows its own currency; the comparison rows (`research_project_comparisons.ts`); and Sectors, whose euro filter already read `size_currency === 'EUR'` from `presentFund`.
- Markets and Overview stay euro-only. They choose euro rows by the row's currency through one exported helper: `euroSizeCents` in JavaScript and `EURO_SIZE_SQL` in SQL. Markets serves no non-euro size, and the Geography page prints every Markets size as euros. A row sized in another currency reads "Not shown: this page compares sizes in euros only". The Overview size note names no list. #7823 (stalled, with no PR) was handed these two files after this change by the owner on 2026-11-27, and rebases afterwards.

### Frontend

- `fundDirectoryRead.js` prints any currency the API marks and the money layer lists. EUR, USD and GBP use their marks. Another code prints as the code ("CHF 40M"). No sentence falls back to "euros". `sizeCurrencyOptions` returns the answer's `size_currencies`. `sizeCompareLine`, `unknownCurrencyLine` and `listSizeText` derive the three size sentences.
- `FundDirectory.jsx`: the size-currency control (the desktop select and the phone's radio group) offers the listed currencies. The sentence under the filters, the coverage sentence and the per-list text follow the answer. **Departure from the canvas:** RFD-02 and RFD-03B draw the control with two options. It now holds as many as the answer lists, three on a database with a GBP list.
- `fundProfileRead.js` `amount`: a code with no mark prints as the code. Its signature is unchanged. A row, its Sheet, its profile and a comparison cell agree.
- The kind label and kind filter are not drawn here (#7758).

### Not here

`services/raiseCycle.ts` reads `fund_size_cents` with no currency. `services/records/raise.ts` prints it with `usd(...)`, so a euro size reads as US dollars in a prospect's Fit section. Neither file is edited here. A STATUS on #7744 reports it so it can be filed.
