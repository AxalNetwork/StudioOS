## D5830 — Account and Validate Typeform pilot journey (#5830)

Issue #5830 builds over merged #6591, #7946 and #8293 / D5828-p2. Existing Account connector and Validate Customer research primitives are reused, with the shared Lightbox's focus, Escape, inert background and phone behavior. No new layout or provider policy is inferred.

## Selection and mapping

Account scopes the venture picker to the selected company's actual membership read. Switching user/company/venture destroys prior drafts and ignores late reads. Typeform US/EU is passed through the existing signed OAuth state; the provider-bound task allowlist returns only to Customer research and its positive venture ID. Other providers/Build return behavior is preserved. The owner authorized narrow hooks in integrations.ts (#8365) and defs/validate.jsx (#8209/#8158) in S38's session on 24 November 2026; those owners retain all other changes.

The binding is the only selected form store. Owner-only actions select/check/unbind a form, manually import, map a supported field and prepare the review queue; none happen on mount or OAuth completion. The new `/api/typeform/mappings` HTTP wrapper delegates to the existing importer. It checks the current encrypted grant's recorded region and exact provider form before replacement. The importer's all-or-nothing batch is wrapped with a same-transaction guard for the selected form, active grant/sync and current company membership/enablement, so revocation between reads and the batch cannot commit stale retractions or mappings. Reads expose stable field/type/rule metadata, not new question titles, choice labels, tokens or respondent identity.

Field-title policy is still unanswered. The UI therefore identifies questions by stable ID/ref/type, accepts explicit choice IDs/boolean/minimum/text retention and never broadens title exposure. Identity fields are unmappable. It preserves other rules when editing one question; the existing mapper validates all rules and retracts affected evidence. Linking the resulting mapping to a hypothesis/optional experiment is a separate existing call. If that call fails, the UI explicitly says the question rule was saved but its evidence target is still pending; it never claims an atomic two-endpoint success. The target chooser reads existing named hypotheses and experiments from the canonical Validate board/module; experiment choices are filtered to the selected hypothesis. Missing reads disable save. Target IDs are server scoped to the same venture.

## Review

Completed submissions, qualifying answers and confirmed evidence stay separate. Unavailable/busy/revoked/needs-remap states are not empty. Private text is shown only when deliberately opening its review. Accepting a proposal is separate and explicit; dismiss and unlink use existing backend transitions. Mapping versions, retraction and dedupe remain D5828/D5829. Disconnect removes the binding/connection and its connector-owned rows, but the current backend leaves accepted demand signals and hypothesis links in place. The UI explicitly tells the founder to unlink evidence before disconnecting if withdrawal is wanted; it does not falsely promise automatic withdrawal. This is preserved backend behavior, not a new retention policy. No quotation is treated as publication consent, and no investor sharing is added. Provider grants/approval flag (#5827) and actual founder pilot (#5831) remain external work; this is a fixture-backed integration, not live acceptance.

## Validation and Help

New real-schema HTTP tests cover dark/owner/support gates, exact EU region, repeated mapping without duplicate answers/signals, invalid/identity fields, post-read form changes and same-transaction revocation rollback. Mounted frontend tests cover private quotation, explicit confirmation, counts, repeated import and unavailability. Pure mapping/number/staleness assertions are mutation checked both ways. PR/STATUS records actual build/full-suite/browser exits.

Help impact: no shared guide is changed or claimed verified. New inline instructions explain ID-based rules, private review, explicit import and the separate target-save failure. Provider setup/title policy and live acceptance instructions belong to the existing connector/Help owners; no fabricated successful external check is recorded.
