### 1. `GET /api/events` grows (`routes/events.ts`)

Every field D1030's page reads stays as it was. The response keeps `hosting` and `attending` and adds `past`.

**Each place**, in `attending` and in `past`, now carries:
- `registration_id`;
- `payment_status` and `amount_cents`, the row's own (the query selected the status and dropped it);
- `comp`, with `comp_source` and `comp_source_recorded`;
- `checked_in_at`, from the place's check-in row;
- `decision_reason`, the host's reason for an approval or decline (migration 392);
- `is_speaker`, when an agenda item names the caller.

**Where a free seat came from.** Only an invitation records it (`event_invitations.source`), so `comp_source` comes from the invitation the place was made through, when that invitation was a comp:

| Invitation source | `comp_source` |
|---|---|
| `manual` | `invitation` |
| `auto_partner` | `official_partner` |
| `auto_lp` | `invested_lp` |
| `auto_investor` | `investor` |
| `auto_founder` | `startup_founder` |
| `auto_connection` | `host_contact` |

A seat an audience rule made free at registration stores no rule. Its `comp_source` is null with `comp_source_recorded: false`, never a guess. `comp_source_recorded` is null on a seat that is not free. Recording the rule would need a column on `event_registrations`, which this task did not add; S21 would number it.

**The check-in code and the join link are unchanged.** The code is sent only for a seated place whose payment is not pending, as before. The join link is sent only to seat holders and managers (#2623).

**Past** (`past: { places, total, limit, offset }`):
- **What it holds:** every place whose event has ended or been cancelled, or that was itself cancelled or declined. Newest event first; places at the same time, newest place first.
- **`outcome`** marks each place: `cancelled`, `declined`, `event_cancelled`, `attended` (checked in or marked attended), or `ended`.
- **Paging:** `past_limit` (default 20, at most 100) and `past_offset`, with an exact `total` from its own count. A page past the end still carries the total.
- **Upcoming is unchanged.** `attending` still holds the four active statuses whatever the date; cancelled and declined places are only in Past.

**Each hosted event** carries `counts`: `seats_taken` (registered, confirmed and attended), `waitlisted`, `pending_approvals` (`registered`, a seat waiting on the host), `checked_in` (a check-in row with a time), and `invitations_open` (pending invitations).
- They are counts only, from three grouped reads.
- An event with no row in a read has none of that thing. The read succeeded, so its 0 is a count.

**The review note** a host reads was already there: `hosting` is shaped with `includePrivate`, which sends `review_note`, the desk's last send-back reason (D917, migration 546). The test now holds it.

**A read that fails answers 5xx.** No read is caught to an empty list. The place columns are written out in each statement rather than shared through a template, because `check-sql-prepare` allows no new interpolation.

### 2. My invitations, signed in

**`GET /api/events/invitations`** lists the caller's pending invitations, by user id or email:
- only for events that are not cancelled and have not ended;
- with the invitation id, comp, the personal message, when it was sent, the host's name and the event;
- **the RSVP token is never sent:** a signed-in answer needs none.

**`POST /api/events/:id/invitation { action: 'accept' | 'decline' }`** answers the caller's own non-revoked invitation:
- **Decline** marks it declined.
- **Accept:**
  - The event must be published.
  - It registers through `registerPrincipal` with `source: 'invite'` and the invitation's id. The seat is free when the invitation is a comp, or when an audience rule makes it one, as `/register` decides.
  - The acceptance is written only once the seat is held. A full event leaves the invitation pending.
  - A paid ticket accepted here mints its PaymentIntent. `registerPrincipal` took a new flag, `selfPay`, for a caller who is the signed-in payer, which before only `source: 'self'` was. The public token route still never mints one.
- **Refusals,** through `refuse` with a code: `invalid_action`, `not_found`, `no_invitation`, `invite_revoked` and `not_open`.

### 3. The host's cancel

**`POST /api/events/:id/cancel { note? }`**, for whoever `canManage` (the host or an admin), with the desk's effects (`routes/admin_events.ts`):
1. **The paid tickets are read first,** so an unreadable payment ledger fails the cancel before anything changes.
2. **The event closes:** `status` becomes `cancelled` and `admin_published` 0, by a conditional update. A cancel that races another is refused, and no one is told twice.
3. **The change is audited** as `event_cancelled_by_host`, with the paid-ticket count.
4. **Every place holder is told,** with the note if there is one: registered, confirmed, attended and waitlisted, but not a place already cancelled.

**The reply** carries the event and `paid_tickets: { count, by_currency, refunds_by: 'events_desk' }`. A ticket is a platform charge, never paid to the host (`services/eventTickets.ts`), so its refund is the Events desk's (#2368), not this route's.

**Refusals,** through `refuse`: `not_found`, `forbidden` and `already_cancelled`.

### 4. Discover's filters (`routes/events_public.ts`)

`GET /api/public/events` takes:
- `format` (`virtual`, `in_person` or `hybrid`, the event's `location_kind`);
- `price` (`free` or `paid`).

A value outside the list is refused (`invalid_format`, `invalid_price`), never ignored. The reply adds `total`, the exact count of events the same filters match, with `limit` and `offset`.

**"Free for me" is not on the public feed.** It is a signed-in question, and the public feed takes no session. Its answer per event is the existing `GET /api/events/:id/eligibility` (`comp_eligible`, `comp_source`).
