## Built

The existing `AdminPageHeader`, routes, fund query and
`fund-admin-panel-<view>` hooks stay in place. The primary spans the phone
content width. Tables stack into labelled rows below `sm`, in light and dark.

`FeesReportsTabs.jsx` owns Fees and Reports; `FundTabs.jsx` re-exports their
existing names and keeps Calls and Distributions. Fees has the terms and
periods beside one another, then admission/net invested and period lines /
statements. Each recorded period opens its own lines; statements are read on
Open. Preview writes the existing draft, then Issue opens a confirmation;
the existing API request handles the Worker's step-up. Confirm terms also
asks in a dialog. The funding-call link asks what it changes before calling
the existing `fee.write` endpoint. Confirm terms, Issue and their final
confirmation controls remain `FundActControl` acts.

The fee read supplies LP ids, not names. These are labelled `LP #id`, never
invented names. Net invested is explicitly fund-level, with the recorded
as-of date; it is never presented as an inferred per-LP figure. Missing
windows, amounts and admission dates say what is missing.

Reports has three addressable parts, preserving `?fund=`:

- `/admin/fund-admin/reports`: Packs, the existing audited queue across funds and entities, search, period and
  status filters; an explicit header fund filter narrows the read; Open reads its figures before drawing the drawer. Prepare,
  Return and Issue keep their existing request bodies, digest and reasons.
  The Admin gets the Worker's issue sentence. Issuance is confirmed inside
  the drawer before the request and step-up.
- `/admin/fund-admin/reports/periods`: the existing report-period list. New
  and Open go to `FundReportPeriodPage`, reusing its letter/draft editor and
  reviewed-pack issue path rather than creating another period editor.
- `/admin/fund-admin/reports/notices`: existing issued notices, their frozen
  figures on Open, and their authenticated kept PDF on press. No notice is
  issued by browsing this list. The existing `fundNoticesApi` domain now
  exposes the mounted admin list, read and PDF routes as well as the LP reads.

Banking keeps the entity connection component and the existing act table.
Connections and payment instructions sit beside one another, followed by
Accounts and Transactions, which now includes the bank memo as plain text. Account,
direction and date filters use the mounted Worker parameters and reset paging;
text search explicitly searches the current page, since the API has no text query.
The Accounts block and transaction account selector share one audited read.
Reconciliation keeps independent reads for matches, unmatched credits and
Not ours. Confirm, Reject, Propose and Withdraw open dialogs explaining the
change; rejection and withdrawal keep the ten-character reason requirement.

Books replaces its wait card at `/admin/fund-admin/banking/books`. It mounts
its ledger read only there, reuses `FundLedgerView`, and renders the journal
with separate debit and credit columns, accounting periods and trial
balance. Its own fund selector uses ledger entitlement rather than the overview’s global filter.
Its side cards expose recorded periods and individual reconciliation
facts; no bank agreement or opening balance is inferred. A selected period
is checked against both the requested fund and period before drawing it.
Journal search and account filters operate on the recorded period’s lines.
Notice type/LP/reference and fee LP filters operate on the loaded records,
without turning a no-match state into a claim that the store is empty.
The original ledger screen retains its existing summary/journal/fees modes
and LP summary restriction; its tables now stack on a phone too.

Overview loading uses the eight labelled skeleton tiles and independent
skeleton cards. Its empty administered-funds block is centred. Failed blocks
say Unreadable and offer Try again without hiding working blocks or the
header. Failed access can be retried independently. `useRead` generations
prevent an older result from overwriting a newer retry or updating an
unmounted component, including Strict Mode's remount effects.

`LightboxPhoneProvider` makes the console's nested drawers bottom sheets,
including reused components; an explicit Lightbox phone form wins. Other
pages retain their default. The global authenticator modal opts into a
bottom sheet on `/admin/fund-admin` only. Its event, callback, retry and
verification path are unchanged.
