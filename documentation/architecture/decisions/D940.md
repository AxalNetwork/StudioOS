### 1. SHL7a: the HQ-only card

`frontend/src/pages/hq/SuperAdminOnlyNotice.jsx`, which `hqOnly(...)` in `App.jsx` draws for an admin without the Super Admin elevation, is redrawn to SHL7a:
- a dashed card, at most 600 px wide, centred below the shell's top;
- the eyebrow "HQ only";
- the title "This page belongs to the Super Admin", as the page's **one h1**, because `hqOnly` draws the card in place of the page and its header;
- the line "You are signed in as a studio admin, so this page stays closed rather than opening and refusing each action.";
- "Go to Studio" (to `/studio`) and "My licence" (to `/admin/my-licence`).

**There is no "Admin Console" link,** as the canvas draws it.

**The line drops the canvas's first sentence.** SHL7a's line opens "HQ manages bank accounts." because its example page is Bank accounts. `hqOnly` stands in for some 25 HQ-only pages, from licences to Telegram, so the card keeps the sentence that is true of all of them.

### 2. SHL7b: a member on an admin page

`frontend/src/pages/hq/AdminBoundary.jsx`, with its roles and words in `adminBoundaryModel.js`. It is drawn by `RoleGuard` through `ROUTE_BOUNDARIES` (D914's mechanism), in place of the redirect:
- a centred card, at most 520 px wide, with the ⊘ glyph;
- "This page is for studio admins", as the page's one h1;
- "If you run a studio, ask HQ for admin access.";
- the primary "Go to your home", to the member's own home (`ROLE_DEFAULT_PATH`; Explorers go to `/exploring`).

**Who sees it:**
- Founders, Operating Partners, Investors, Advisors and Explorers.
- Only on `/admin` and `/admin/...` addresses (`/^\/admin(\/|$)/`, so `/administrator` is not caught).
- In their own shell. Nothing admin is read behind it.

**Who does not:**
- `pending` keeps `RequireAuth`'s pin to onboarding.
- An admin is admitted by the guard and never reaches the card.
- Every other guarded route keeps today's redirect.

**A pending impersonation handoff still wins.** Task #102's comment in `RoleGuard`: when an admin starts impersonating from an admin page, the guard re-renders with the impersonated role before the caller's own navigation lands. The card is drawn only when no handoff target is pending, so the redirect to that target is never replaced by the card. The same rule now covers D914's narrative boundary, which had the same race.

**An `/admin` address no route names.** `/admin/kyc`, the issue's example, has no route. It fell through to `NotFoundPage` for everyone, so the guard never ran. One splat route, `<Route path="/admin/*" element={guard(['admin'], <NotFoundPage />)} />`, now catches unnamed admin addresses:
- an admin there still reads "Page not found";
- a member reads SHL7b.

React Router ranks every named `/admin/...` route above the splat, so no existing page changes.

### 3. Accessibility

- Each card is a `section` labelled by its h1, the only h1 on the page.
- Its links are ordinary links, reachable by Tab.
- No dialog and no focus trap.
- The glyph is `aria-hidden`.
