### What this part lands

PR #5694 merged on 2026-11-12 into `agent/codex-s39/5567-workspace-security`, a topic branch, so main never had the host. This part re-applies that merge commit (`bba52447e6`) onto main and fixes what main now needs:

1. **Patched Git.** The admission scan denied the Alpine candidate for twelve HIGH findings on Git 2.54.0, with 2.54.1-r0 listed as the fix. The Dockerfile now installs `git>=2.54.1-r0`. If the Alpine repository cannot satisfy the floor, `apk` stops the build, so an image with the vulnerable Git cannot be produced. The base stays `alpine:3.24` at the same digest; on 2026-11-27 Docker Hub still served that digest for the `3.24` tag. The scan threshold (HIGH, CRITICAL or UNKNOWN denies) is unchanged.
2. **A valid preview configuration.** `wrangler deploy --dry-run` with the repository's Wrangler 4.156.1 refused the topic branch's config: `max_instances` is not a supported field on Durable Object-managed containers. It is removed. Concurrency is capped by `concurrency_max` in the capabilities the broker supplies (null refuses admission) and by #5570's admission leases, not by the config. Both environments now set `workers_dev = false` and `preview_urls = false`, as `wrangler.agent-compute.toml` does, so no public URL exists. The workflow now runs that dry run.
3. **A workflow that runs on main.** The image workflow typechecks `cloudflare-worker/src`, which imports the generated route registry. It now runs `node scripts/build-generated.mjs` first (D5612), as the agent-compute and meeting-bot image workflows do.
4. **A testable entrypoint.** The gate of the private `WorkerEntrypoint` moved to `worker/entry.ts`, which does not import `cloudflare:workers`, so tests reach it. Behaviour is the same: only `WORKSPACE_PILOT = "preview"` admits new work; status, cancel, collect and cleanup stay reachable with the pilot off; a forged or foreign ref is refused before any Durable Object lookup; an unbound broker refuses everything with 503.
5. **README entries.** The union merge driver had mangled the four README edits from the topic branch. They are rewritten against main: a row in the root README and in `cloudflare-worker/test/README.md`, and the workflow inventory regenerated with `node scripts/workflow-inventory.mjs --write`.

### Contract tests added

Eight tests join the ten from part 1 in `workspace_cloudflare_5566.test.ts`:

- the entrypoint admits only on the exact flag value `preview`, and refuses before any lookup;
- status, cancel, collect and cleanup reach the host with the pilot off, while eight kinds of forged ref (other tenant, generation, run or provider, wrong id, bad region, tenant 0, null) are refused before lookup;
- an unbound broker refuses admission and acceptance with 503 and starts nothing;
- broker answers that do not match the request are refused before a VM starts: different spec or tenant, an empty or malformed budget ref, an image outside the Cloudflare registry or not pinned by digest, no materialization, ineligible capabilities;
- a second spec on the same execution conflicts, cleanup of a running execution is refused, and replayed create and collect accept the artifact once;
- control calls need the matching grant audience and the persisted spec;
- the adapter mints no ticket and looks up no host while disabled, over budget (above the cap, negative, fractional, NaN), ineligible or refused a ticket;
- the image contract: one digest-pinned base, the Git floor on the `apk add` line, no unversioned Git, user `node`, `setpriv --no-new-privs` entry, one `COPY`, no socket, privilege, `ARG`, `EXPOSE` or credential `ENV`; the config has no route, service binding or public URL; the workflow is read-only and deploys only with `--dry-run`.

Mutation check (`workspace_cloudflare_5566.test.ts`, run with `scripts/mutation-check.mjs`): 21 mutations, 21 caught, 0 equivalent. Each mutation breaks one guard in `entry.ts`, `controller.ts`, `executor.ts`, the Dockerfile, the config or the workflow.

**Commands** (from the repository root, at the commit whose scan passed; always `--env preview`, never the top-level environment):

1. `npm ci --prefix cloudflare-worker && node scripts/build-generated.mjs`
2. `cloudflare-worker/node_modules/.bin/wrangler deploy --config workspace-engine/wrangler.toml --env preview --dry-run --containers-rollout none --outdir /tmp/workspace-host` (must list `WORKSPACES`, `WORKSPACE_PILOT ("off")` and `CodingWorkspace (durable_object)`, and nothing else)

4. `wrangler containers list` and `wrangler containers images list`: record the application name and the image digest on #5566. The digest is what the broker's `image_ref` and the spec's `image_digest` must match.
5. `wrangler containers instances <application>`: must show zero instances.

With the pilot off and no broker bound, every create returns `workspace_preview_disabled`, and with the pilot on it returns `workspace_broker_unavailable`. Both are expected until the broker PR lands. Setting up the preview does not make the hosted acceptance runnable by itself.

**Teardown** (also the preview rollback)

1. Set `WORKSPACE_PILOT` to `off` and redeploy with `--env preview`. Status, cancel and cleanup keep working.
2. Cancel and clean up every execution the broker still holds, through the host.
3. `wrangler containers instances <application>` until it shows zero. An instance that will not stop stays recorded as `unknown`; do not count it as cleaned.
4. Only at zero: `wrangler containers delete <application>`, then `wrangler delete --config workspace-engine/wrangler.toml --env preview`, then `wrangler containers images delete` for the `coding` image.
5. Record on #5566 the before and after inventory. Keep manifests and audit rows under the existing retention policy.
