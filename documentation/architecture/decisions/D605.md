## D605 — Values compatibility across roles, on the archetype card's matches

**Each published-member match on the archetype card now carries one values
band: `aligned`, `mixed`, `far_apart`, or null for "not enough recorded".**
The band compares the caller's recorded values with the member's, on the
dimensions both sides' roles are asked (`PROFILING_V2.md` §6, Session 14).
Slot S10, issue #1296, 2026-10-06. This is the values half that #1006 left
out on the owner's pick 1A. Worker first, no migration.

### The four decisions (Session 1's, on #1296; the owner can overrule them)

1. **Who is compared:** the caller and a listed member, only when both have
   published their archetype. Publishing is the consent to be matched. The
   route lists only published members already (D602). A caller who has not
   published gets `values_fit: null` on every row, and `values_fit_reason`
   says why: "Publish your own archetype to see how your values compare."
2. **What the reply shows:** one band and how many dimensions were compared,
   `values_fit: { band, compared }`. It never shows a dimension, a score, a
   confidence or which side holds which, because §7.9 keeps a member's values
   from everyone else.
3. **A gap is never averaged away** (§6). If any one compared dimension is
   far apart, the band is `far_apart`, whatever the others say.
4. **Absent is absent** (§12). With fewer than three dimensions recorded on
   both sides, the band is `null`: never `aligned`, never 0. A value with
   confidence 0 is not recorded.

### The pairs (§6)

`services/valuesCompat.ts`, pure. The caller's side is their role and the
member's side is the row's persona; a coach is asked the advisor bank.

| Pair | Compared |
| --- | --- |
| every pair | the six Axal values (`axal_values`: integrity, stewardship, curiosity, resilience, collaboration, ambition) |
| founder · investor | also `founder_risk_appetite`, `founder_growth_vs_sustain`, and Schwartz achievement, benevolence and universalism |
| founder · partner | also `founder_autonomy_vs_structure`, and all four Schwartz dimensions |
| founder · advisor | also all four Schwartz dimensions |
| founder · founder | also all five founder spectrums, and all four Schwartz dimensions |
| no founder | the six Axal values only |

The paired dimensions already share a slug: an investor's `lean_risk` writes
`founder_risk_appetite`, and a partner's `collab_founder_led` writes
`founder_autonomy_vs_structure`. So both sides are on one scale. A dimension
counts only when both sides have it.

### The scales and thresholds

- `user_values` scores run −2 to +2 and are put on 0 to 1 as `(score + 2) / 4`.
  `axal_values` scores are already 0 to 1.
- The distance on each dimension is the absolute difference on 0 to 1.
- **`far_apart`**: any distance of **0.5** or more. That is two points on a
  −2 to +2 answer, which means opposite leanings.
- **`aligned`**: every distance is **0.25** or less, which is one point on a
  −2 to +2 answer.
- **`mixed`**: anything in between.
- **`null`**: fewer than **3** dimensions compared.

`MIN_COMPARED`, `ALIGNED` and `FAR_APART` are exported, and
`cloudflare-worker/test/values_compat_d605.test.ts` pins them.

### The route

`GET /api/profile/published-members` (D602) gains `values_fit` on each row and
`values_fit_reason` on the reply. The caller's values and every listed
member's are read in two queries for the whole list (`axal_values`, and
`user_values` joined to `value_dimensions`), never one query per row. A failed
values read is `503 published_members_unreadable`, like the route's other
reads, never a list in which every band is null.

### The client

`valuesFitLine` in `frontend/src/lib/archetypeCardV2.js` turns a band into
the card's line:
- "Values: aligned";
- "Values: some differences";
- "Values: far apart";
- "Values: not enough recorded" for a null band.

With no comparison (the caller has not published) it returns no line. The card
does not draw it yet; that waits on #1006's canvas.

### Guard

`cloudflare-worker/test/values_compat_d605.test.ts`:
- the thresholds and the §6 pairs;
- fewer than three shared dimensions is null, and so is a zero confidence;
- one far dimension makes the band `far_apart`, with both thresholds checked
  at their exact edges;
- a pair with no founder compares the Axal values only;
- an investor's `founder_risk_appetite` is compared with a founder's, on the
  normalised scale, and an advisor's is not;
- through the route:
  - aligned, far_apart and null bands;
  - an unpublished caller gets no comparison, with the reason;
  - no dimension, score or confidence appears in the reply;
  - a failed values read is a 503.

`frontend/test/archetype_card_v2_d602.test.mjs` pins the four lines.

Ten mutants were each caught:
- dropping the minimum;
- averaging the gaps;
- comparing spectrums with no founder;
- skipping the scale normalisation;
- dropping the confidence rule;
- dropping the investor's risk appetite;
- assuming the caller published;
- leaking a dimension name;
- turning a failed read into an empty list;
- a null band read as aligned.
