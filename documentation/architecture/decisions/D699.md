## D699 — Founder phone shell and company visits

Issue #1661, part of D689. Below 1024px the founder shell uses the Cycle Overview canvas's photo band and five tabs. Studio is a band link; Validate, Build, Raise and Grow are tabs; More is a page at `/more`. At desktop widths and for other roles the current shell remains. A width check chooses one header at a time, so one notification bell polls and connects.

The band uses the already committed `/site/lab-band.webp` illustration under the canvas gradient. It replaces the canvas upload with the same illustration's served WebP. There is no second top inset. The account sheet carries Founder Wellbeing, Refer & Earn and the branch badge; the impersonation, view-as and HQ strips remain above the band. The sidebar search is the sole drawer control without a phone home, because its rows are reachable directly.

| Existing founder phone door | New home |
| --- | --- |
| Studio | Band glyph |
| Validate, Build, Raise, Grow | Tabs |
| Spin-Out Lab, Network, Research, Messages, persona extras | More page |
| Trust, account popover rows, Wellbeing, Refer & Earn | Account sheet |
| Company switcher, create, Company Settings | Company sheet |
| Notifications | Band bell |

The canvas's `/switch/[id]`, `/companies/new`, and account label slugs are not routes. Company rows call the same `useCompanySwitch` switch/create path as the sidebar. Events opens `/my/events`, pricing `/plans-and-pricing`, and Log Out calls the shell callback. A created company becomes the selected company and gets a new company scoped sidebar. The shared-data notice remains beneath the company rows, where choosing a company happens.

| Company row | Description | Right |
| --- | --- | --- |
| Active with cycles | `Active · Validate, Build` (actual cycles) | Active |
| Active with none | Not started | Active |
| Other with visit | `Raise · last opened 12 Oct` (actual cycle/date) | › |
| Other with cycles, no visit | `Validate, Build` (actual cycles) | › |
| Other with none | Not started | › |
| Store read failed | No cycle description, or the visit line if present | As above |

The last form without a visit is a departure from the canvas, which shows only one other company's visit. The read keeps the switcher's `…`, `No company`, `Unavailable`, and duplicate-name creation date rules. A failed cycle read is `null`, never empty.

`CYCLE_STORES` checks the caller's own, non-deleted ventures whose `projects.company_id` is the selected company. An unscoped venture and a venture where the caller is only a co-member do not count. Validate checks discovery interviews, pain groups, hypotheses and demand signals. Build checks MVP features, venture risks, roadmap OKRs and formation steps. Raise checks readiness items, pitch decks, data-room files and raise prospects. Grow checks product feedback, growth channels, growth partners, markets and compliance events. Automatically seeded compliance obligations count because the Grow durable company-building module shows them. The owner question about changing that is tracked on #1008 with D692's first KPI.

Migration 466 stores one last visit for each `(user, company)` and accepts only four cycles. A visit is recorded on a cycle route at either width once per pair per hour, by the signed-in member only. An impersonation token is refused and an HQ support session or admin view-as does not send one. The client may drop a failed hint. The membership read adds `cycles_active` and `last_opened` without changing its order or older fields.

`PhoneBar` returns to history when there is an earlier tab entry. On the first entry, a founder goes to the page's cycle root, then the company's last opened cycle, then Validate. Other viewers admitted by Studio return there. An exploring viewer outside the Lab returns to Account, except from bare Account, which returns to Exploring. More has no Eadwyn button because it has no page work for Eadwyn; this departs from the canvas's generic pushed bar.
