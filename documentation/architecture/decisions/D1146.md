### 1. One Worker read: the model RD4 draws

`GET /api/cycles/raise/pmf/model?project=` (`routes/cycle_raise.ts`, `pmfModelRead` in `services/scoring/pmfStore.ts`).

- **Gate:** Raise's founder/admin venture gate, as the history read has.
- **Which version:** the one the venture's latest stored point was scored with. Before any point, the version the code scores with.
- **Where the model comes from:** the `scoring_model_versions` row for that version.
  - D1144 stores that row with the venture's first score. Before it exists, the read answers the code's definition with `stored: false`, and the dialog says the model is "Not stored on this database yet". The first score publishes it unchanged, because the writer refuses a different definition for the same version.
- **When the read refuses:** a stored point whose model row is missing, or a row RD4 cannot draw (`modelShape` checks every field the dialog names), is 503 Unreadable. It is never answered with the code's copy in its place.
- **Answer:** `{ version, stored, scored_with, published_at, model, grades }`. `grades` is SCORING's Source-to-grade table (D1143), which the model JSON does not carry.

The client is `cycleWrites.raise.pmfModel`.

### 2. RD4: How Product-market fit is scored

- **Where:** `PmfMethodDialog` in `pages/cycles/PmfMethod.jsx`, a centred Lightbox opened from the readiness part's "How Product-market fit is scored". It reads when it opens, not when the page mounts.
- **What it draws from the read (`methodOf` in `pmfModel.js`):**
  - the version, and when it was published (or that it is not stored yet);
  - each input with what it reads and its weight, plus the total; each Validate input links to its module;
  - the grades with their factors, and the freshness windows;
  - the confidence words and the floor;
  - the bands.
- **What is the page's own:** only the grades' words and the "Words" section. D1141's static copy of model v1 (`INPUTS`, `GRADES`, `BANDS`, `MODEL_VERSION`) is removed.
- **Failure:** a failed read is Unreadable with Try again, and nothing is drawn in its place.
- **Not drawn from the canvas:** "What is not in this score". It names other scorecard scopes (Market, Traction) that do not exist on `main` yet.
- **Shared later:** SCORING's method page (#2428) can draw the same dialog when it lands.

### 3. RD12: Validate's chip with the band

- **Where:** `PmfChip`, a chip in Validate's overview header beside the title. `CycleHeader` and `CycleOverview` take an optional `chip`; no other cycle passes one. It replaces D1141's line under the overview cards.
- **What it reads:** the venture's latest stored point, through the history read with `limit: 1`. It reads the store only, so opening Validate computes nothing.
- **What it shows:**

  | State | The chip reads |
  |---|---|
  | Scored | "Product-market fit · ◐ Fair · ●●○ Medium ›" |
  | No stored point | "Not scored yet" |
  | A point below the floor | "Not enough recorded" |
  | Failed read | "could not be read", with Try again |
  | Refused read (401, 403 or 404) | "Product-market fit ›" only: never "no score" |

- **Where it leads:** Fundraising readiness, keeping the venture.
- **Phone:** the phone root (`PhoneCycleRoot`) carries no header chip. D1141's door was not on the phone either.
