## D6170 — Deal "What's new" names every change type the Worker sends (#6170)

2026-11-14 · #6170 · No migration. No Worker change.

### The sentences

`GET /api/deals/:id/whats-new` (`cloudflare-worker/src/routes/deal_context.ts`)
sends thirteen change types and is gated to the investor licence on their own
deal (`context()`), so every sentence speaks to that investor.
`CHANGE_WORDS` in `frontend/src/pages/deal/dealFrameModel.js` had five; the
other eight were drawn as "Something changed". It now has one sentence each:

| Type | Sentence |
| --- | --- |
| `deal` | The deal’s status changed |
| `deck` | The founder shared a new deck version with you |
| `document` | A document was added |
| `firm_note` | A note was added at your firm |
| `investor_commitment` | An investor committed |
| `diligence_answer` | The founder answered a diligence request |
| `invitation` | Your invitation changed |
| `member` | You joined the deal room |
| `dd` | Your diligence case was updated |
| `ic` | The IC record on this deal changed |
| `commitment` | Your commitment changed |
| `envelope` | Your signing papers moved |
| `funded` | Your money was received |

The route sends types and times only, so no sentence carries a name or an
amount; `investor_commitment` stays anonymous. `ic` does not say "your
firm's": the route also reads an IC record a solo investor created with no
firm, so "the IC record on this deal" is true for both.

### The guard reads a Worker file from a frontend test

`frontend/test/deal_whats_new_words_6170.test.mjs` reads
`cloudflare-worker/src/routes/deal_context.ts` as text, takes the types from
the whats-new handler's `sources` list (each `type: '…'` and the quoted
per-fact list) and fails when that set and `CHANGE_WORDS` differ in either
direction. A type added to the Worker without a sentence fails it. If the
handler is reshaped so the list cannot be read, the test fails rather than
passing on an empty set.

### Not here

Detail per change (which document, which status) needs the Worker to send a
safe label; that is a follow-up.
