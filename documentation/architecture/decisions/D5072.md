## D5072 — Data Room Home: no placeholder, one room read by venture id, no duplicate module read (#5072)

- **Status:** Built, 2026-11-09 (Worker route and frontend; no migration).
- **Stacked on:** D5070 (the safe error contract `DataRoomSearch` already uses) and D5069 (merged).

### What was wrong

1. Home's "The last ninety days" block rendered `ACTIVITY_WAIT`: "The last ninety days need the activity read (part 4, D1105)…". Part 4 shipped; the text was implementation language in production.
2. Every Data Room tab read the room in two steps: `api.listProjects()` (the caller's whole project directory), then a scan for the venture's uid, then `GET /api/data-room/:projectUid`. `CycleRoute` already holds the venture's numeric id.
3. Measuring Home's cold open showed a second waste: `GET /api/cycles/raise/modules/data-room` was sent twice. `CycleRoute` reset the table's query on mount with a fresh `{}`, and the module read depends on `query`, so every module page read its module twice when it opened.

### What changed

- **Placeholder:** the block names what Activity holds and links to it (`ACTIVITY_NOTE`, a link to the Activity tab). A real 90-day figure on Home would be one more request on every open, against the point of this package; the daily figures, last fifty events and week counts are one click away on Activity.
- **Room by id:** `GET /api/data-room/by-project/:projectId` (Worker, `routes/data_room.ts`) finds the venture's uid from its id, then runs **the same handler** as `/:projectUid` (`serveRoom`): ownership and company scope for a founder, accepted co-founder membership, the admin summary for an admin. The id only finds the uid, so every gate is unchanged, and a venture the caller may not read answers the same 404 as one that does not exist (tested against another founder, a granted investor and a missing id). The answer carries `project_uid` for the room's later calls (files, shares, uploads). Ids that are not 1–10 digits are 404.
- **Frontend:** `api.dataRoomByProject(projectId)`; `useRoom` makes that one request and takes the uid from the answer. `projectUidOf` and its test are gone.
- **Duplicate read:** `CycleRoute` keeps the same query object when it already is the default, so the module read runs once.
- **Errors:** the search and indexing failures already go through D5070's `userFacingRaiseError` (that merge is part of this branch). Per-block unreadable states (`room`, requests, sources) are untouched.

### Measured (Home, cold open, the test's fetch log)

| | Requests | Repeats | Sequence before the room read |
| --- | --- | --- | --- |
| Before | 13 | the module read twice | `GET /projects`, then the room by uid |
| After | 11 | none | none: the room read starts at once |

The `GET /projects` response is the caller's whole project list, which grows with the number of ventures; it no longer travels at all. The regression test asserts the room is read once by id, `/projects` is never read, and no GET repeats.

### Considered, not built

- **Automatic search index after a file change.** The index step reads and embeds each file, so doing it inline in an upload or move would slow and risk the write; doing it right needs a queue job keyed on the file change. The manual Index control stays, and this is the follow-up if the founder workflow should stop needing it.
