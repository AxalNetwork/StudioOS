### 1. One project-wide read

**Before.**
- The objections were counted only inside a version record's side section (`services/records/raise.ts`, Investor feedback). So Home, which opens no version, could not draw them.
- `raise_prospect_feedback.answer` was written by Add feedback. D1189 shows it on the prospect's record only.

**Now.** `services/narrative/objections.ts` reads every feedback row on the venture's prospects (migration 463's table, joined to `raise_prospects` on the project), newest first:

- **One objection, many rows.** Rows whose words match once case and spacing are set aside are one objection.
  - Its **count** is how many rows said it.
  - **`prospects`** is how many investors did.
  - **`last_heard`** is the newest row's day.
  - The words shown are the newest row's.
- **Its key** is the first 16 hex of SHA-256 over those normalised words. So the key survives a deleted row, and needs no store.
- **`answer`** is the newest non-blank answer written on any of its rows in Capital relationships, else null.
- **Order:** most heard first, then by their words.
- **The cap.** At most 2,000 rows are read. Past that, `capped` is true and the panel says "Only the newest feedback is counted here", rather than undercount in silence.

**Two places read it:**
- `GET /api/cycles/raise/narrative/objections` (`routes/cycle_raise.ts`) answers `{ objections: [{ key, text, count, prospects, last_heard, answer }], capped }`. It is behind the narrative's own read gate: the venture's founder, or an admin after a reason (D914).
- The module read's `parts.narrative.objections` (`services/raiseCycle.ts`, `narrativeHome`) holds the same items, so Home reads nothing itself (D909).
  - It fails on its own: `{ state: 'unreadable' }`, with the versions still drawn.

`objections.ts` imports nothing of the narrative's store. The module read imports it, and the store imports the module read, so an import the other way would be a cycle (`services/raiseCycle.ts` ↔ `services/narrative/store.ts`).

### 2. "Answer it" and its route

`POST /api/cycles/raise/narrative/objections/:objection/draft` (`services/narrative/objectionDraft.ts`):

- **Body:** `{ version, section, words? }`.
  - The section is the one open in Story.
  - `words` are the unsaved words on the page; without them, the stored words, as D1114.
- **One `rail_write` run**, metered like every rail option, under page "Founder · Raise · Investor narrative" and option **`draft:narrative-objection`**. The issue named `draft:narrative/objection`. A slash in a founder draft key is a research ZoneDraft surface (`railOptions_founder_d771`), so it takes a hyphen, as D911 and D1114 did.
- **What the model reads:** the section's label, its words, the version's audience and positioning (D1114's `sectionMaterial`), the objection's words, and the founder's own answer from Capital relationships. Every figure in each is masked as `[figure]`, so no number the founder or an investor wrote reaches the model.
- **No figure leaves.** Each sentence of the answer that holds a digit is dropped and counted (`screenSection`). If all of them are dropped, the answer is 422 `nothing_kept`.
- **It writes nothing.** No section, binding, feedback or proposal row is written. It answers `{ version, section, objection, text, removed }`.
- **The same proposal as Ask Eadwyn.** Story shows the words in Ask Eadwyn's proposal box. Accept puts them in the words; Save version saves them with Eadwyn as the source, and the store refuses a digit again (D908).
- **Shared material.** `draftMaterial` in `routes/cycle_raise.ts` reads the version, the section and the positioning for both drafts. D1114's route uses it unchanged in behaviour (`narrative_section_draft_d1114` passes as before).

**Refusals:**

| Answer | When |
|---|---|
| 404 | a key that is not 16 hex, or no objection of this venture's with that key |
| 400 | no section chosen |
| 404 | an unknown section, or no version |
| 409 | version 0, the live deck |
| 403 `admin_read_only` | an admin, before any read or run (D914) |
| 403 `assist_off` | the page's switch is off |
| 402 | the allowance and the tokens cannot cover the run |
| 503 | the objections could not be read, or a model could not answer |

### 3. NAR10: the Objections panel on Story

`ObjectionsPanel.jsx`, beside the writing surface (a third column at `xl`, under it on a narrower screen):
- **"Objections heard · From Capital relationships · [n]"**, each objection with "Raised [n] times by [m] investors" ("Raised 1 time" for one row).
- **Its read.** The panel reads on its own. A failed read says "could not be read. This is not a claim that there are none" with Try again, never an empty list. None recorded says "No objection is recorded in Capital relationships yet."
- **Answer it** is on each row for the founder, labelled "Answer it in [section]". The foot says "Answer it opens Ask Eadwyn on this section. Eadwyn writes no numbers."
  - It is greyed with the page's AI-off line when assistance is off.
  - A refused run is shown as Ask Eadwyn's is (NAR17c's tokens, the Worker's sentence).
- **Not offered** to an admin, on the live deck's version 0, or on a phone. Ask Eadwyn is not offered on a phone either.
- **`?objection=<key>`**, from Home, marks that row (`aria-current`).

The canvas's panel has tabs (Claims, Objections, Notes). Claims waits for #2430, and the notes thread is D914's own card under Story. So the panel is Objections alone, with no tab bar.

### 4. NAR1: Home's "Objections heard" and the tile

- **The card** is `ObjectionsCard`, under Needs you. It lists each objection with its count.
  - "Answer it ›" opens Story on the newest version with `?objection=<key>`.
  - There is no Answer it for an admin (`isNarrativeAdmin`, passed from CycleRoute), or when no version is saved.

### 5. Open: which section answers an objection

The canvas shows "✓ Answered in [Market] ›" and "[2] of [3]". No store links an objection to a section, and the issue says "Migration: none". The question is with the owner on #2697:

- **A.** An additive migration, `narrative_objection_answers` (project, objection key, version, section, by, at). It is written when the founder accepts an "Answer it" draft into a section and saves, or picks the section by hand.
- **B.** No migration. "Answered" means a non-blank answer recorded in Capital relationships, shown with no section link.
- **C.** No migration. The link lives in `narrative_sections.source_ref`. It is lost the next time that section is typed in by hand.

S12 would pick A. Until the owner answers, every row offers Answer it, and the tile is a dash with its reason. The read already carries the key both A and C would store, and the answer B would count.
