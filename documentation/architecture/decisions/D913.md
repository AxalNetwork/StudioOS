### 1. One project-wide read

**Before.**
- The objections were counted only inside a version record's side section (`services/records/raise.ts`, Investor feedback). So Home, which opens no version, could not draw them.
- `raise_prospect_feedback.answer` was written by Add feedback. D1189 shows it on the prospect's record only.

**Now.** `services/narrative/objections.ts` reads every feedback row on the venture's prospects (migration 463's table, joined to `raise_prospects` on the project), newest first:

- **One objection, many rows.** Rows whose words match once case and spacing are set aside are one objection.
  - Its **count** is how many rows said it.
  - **`prospects`** is how many investors did.
  - **`last_heard`** is the newest row's day.
  - The words shown are the newest row's.
- **Its key** is the first 16 hex of SHA-256 over those normalised words. So the key survives a deleted row, and needs no store.
- **`answer`** is the newest non-blank answer written on any of its rows in Capital relationships, else null.
- **Order:** most heard first, then by their words.
- **The cap.** At most 2,000 rows are read. Past that, `capped` is true and the panel says "Only the newest feedback is counted here", rather than undercount in silence.

**Two places read it:**
- `GET /api/cycles/raise/narrative/objections` (`routes/cycle_raise.ts`) answers `{ objections: [{ key, text, count, prospects, last_heard, answer, answered }], capped, answers }`. `answered` and `answers` are §6's. It is behind the narrative's own read gate: the venture's founder, or an admin after a reason (D914).
- The module read's `parts.narrative.objections` (`services/raiseCycle.ts`, `narrativeHome`) holds the same items, so Home reads nothing itself (D909).
  - It fails on its own: `{ state: 'unreadable' }`, with the versions still drawn.

`objections.ts` imports nothing of the narrative's store. The module read imports it, and the store imports the module read, so an import the other way would be a cycle (`services/raiseCycle.ts` ↔ `services/narrative/store.ts`).

### 2. "Answer it" and its route

`POST /api/cycles/raise/narrative/objections/:objection/draft` (`services/narrative/objectionDraft.ts`):

- **Body:** `{ version, section, words? }`.
  - The section is the one open in Story.
  - `words` are the unsaved words on the page; without them, the stored words, as D1114.
- **One `rail_write` run**, metered like every rail option, under page "Founder · Raise · Investor narrative" and option **`draft:narrative-objection`**. The issue named `draft:narrative/objection`. A slash in a founder draft key is a research ZoneDraft surface (`railOptions_founder_d771`), so it takes a hyphen, as D911 and D1114 did.
- **What the model reads:** the section's label, its words, the version's audience and positioning (D1114's `sectionMaterial`), the objection's words, and the founder's own answer from Capital relationships. Every figure in each is masked as `[figure]`, so no number the founder or an investor wrote reaches the model.
- **No figure leaves.** Each sentence of the answer that holds a digit is dropped and counted (`screenSection`). If all of them are dropped, the answer is 422 `nothing_kept`.
- **It writes nothing.** No section, binding, feedback or proposal row is written. It answers `{ version, section, objection, text, removed }`.
- **The same proposal as Ask Eadwyn.** Story shows the words in Ask Eadwyn's proposal box. Accept puts them in the words; Save version saves them with Eadwyn as the source, and the store refuses a digit again (D908).
- **Shared material.** `draftMaterial` in `routes/cycle_raise.ts` reads the version, the section and the positioning for both drafts. D1114's route uses it unchanged in behaviour (`narrative_section_draft_d1114` passes as before).

**Refusals:**

| Answer | When |
|---|---|
| 404 | a key that is not 16 hex, or no objection of this venture's with that key |
| 400 | no section chosen |
| 404 | an unknown section, or no version |
| 409 | version 0, the live deck |
| 403 `admin_read_only` | an admin, before any read or run (D914) |
| 403 `assist_off` | the page's switch is off |
| 402 | the allowance and the tokens cannot cover the run |
| 503 | the objections could not be read, or a model could not answer |

### 3. NAR10: the Objections panel on Story

`ObjectionsPanel.jsx`, beside the writing surface (a third column at `xl`, under it on a narrower screen):
- **"Objections heard · From Capital relationships · [n]"**, each objection with "Raised [n] times by [m] investors" ("Raised 1 time" for one row).
- **Its read.** The panel reads on its own. A failed read says "could not be read. This is not a claim that there are none" with Try again, never an empty list. None recorded says "No objection is recorded in Capital relationships yet."
- **Answer it** is on each row for the founder, labelled "Answer it in [section]". The foot says "Answer it opens Ask Eadwyn on this section. Eadwyn writes no numbers."
  - It is greyed with the page's AI-off line when assistance is off.
  - A refused run is shown as Ask Eadwyn's is (NAR17c's tokens, the Worker's sentence).
- **Not offered** to an admin, on the live deck's version 0, or on a phone. Ask Eadwyn is not offered on a phone either.
- **`?objection=<key>`**, from Home, marks that row (`aria-current`).

The canvas's panel has tabs (Claims, Objections, Notes). Claims waits for #2430, and the notes thread is D914's own card under Story. So the panel is Objections alone, with no tab bar.

### 4. NAR1: Home's "Objections heard" and the tile

- **The card** is `ObjectionsCard`, under Needs you. It lists each objection with its count.
  - An objection a saved section answers shows "✓ Answered in [Section] ›" (§6). An admin sees it too: it is a read.
  - Any other objection has "Answer it ›", which opens Story on the newest version with `?objection=<key>`.
  - There is no Answer it for an admin (`isNarrativeAdmin`, passed from CycleRoute), or when no version is saved.
- **The tile "Objections answered"** is "[n] of [m]": how many of the objections heard a saved section answers (§6). Once both reads came back, "0 of 3" is a real zero.
  - Its sub: "Each one is answered in a saved section.", or "[k] not answered in a saved section yet."
  - When it cannot count, it is a dash, never a 0, with its reason:
    - "[m] heard. Which section answers each one could not be read.";
    - "No objection is recorded in Capital relationships yet.";
    - "The objections could not be read."
- **The founder's answer from Capital relationships is not shown here.** It is what they told an investor, not what the narrative says (§5).

### 6. Option A: the answer, its writes and its reads (migration 624)

**The store.** `narrative_objection_answers` holds one row per venture and objection key (`UNIQUE (project_id, objection_key)`):
- `version`: a saved version, never 0 (the live deck);
- `section_key`: one of the ten sections;
- `how`: `eadwyn` (an accepted "Answer it" draft, saved) or `picked` (chosen by hand);
- `answered_by` and `answered_at`.

The key is §1's: a hash of the objection's words. Nothing copies the words or names an investor.

**The read.** `readObjections` reads the answers apart from the feedback (`readAnswers`). Each objection gets `answered`: `{ version, section, how, by: { id, name }, at }`, or null.
- **A failed answers read never hides the objections.** The read answers `answers: 'unreadable'`, and every `answered` is null.
- The page then says "Which section answers each one could not be read.", offers no Mark or Clear, and the tile is a dash.
- With the answers read, `answers` is `'ok'`.
- The module read's `parts.narrative.objections` carries the same `answers`.

**The writes** (`routes/cycle_raise.ts`). Both are behind the narrative's write gate: only the venture's founder writes. An admin is refused with 403 `admin_read_only` (D914).

`PUT /api/cycles/raise/narrative/objections/:objection/answer`, body `{ version, section, how }`, answers `{ objection, answered }`.
- It inserts the row, or replaces the one already there: a later answer is the answer.
- It logs `narrative_objection_answered` under `raise.investor-narrative`, on the version. For example: "An objection marked answered in Market, version 7 (picked by hand)".

`DELETE` on the same path clears it, and answers `{ objection, answered: null }`.
- It logs `narrative_objection_unanswered`.

Neither log row holds the objection's words, an investor's name or a figure.

**Refusals:**

| Answer | When |
|---|---|
| 404 | a key that is not 16 hex, or no objection of this venture's with that key |
| 400 | `how` is not `eadwyn` or `picked` |
| 404 | an unknown section; a version that is missing or not this venture's |
| 409 `invalid_version` | version 0, the live deck |
| 404 (DELETE) | the objection is not marked answered |
| 403 | another venture's founder; an admin (`admin_read_only`) |
| 503 | the objections could not be read |

**Story: Eadwyn's draft becomes the answer only when it is saved** (`StoryTab.jsx`).
- "Answer it", then Accept, keeps the objection pending against that section. Nothing is written yet.
- Save version's dialog adds "Records that [Section] answers “[objection]”." for each pending objection whose section this save writes.
- Once every section is saved, Story records each one (`how: 'eadwyn'`) on the version.
- A section put back as it was saved is not written, so its answer is not recorded.
- If a section saves but its answer is refused, Story says so in the Worker's words and points to Mark answered. The words stay saved.

**Eadwyn's wording carries no number.** "Answer it" drops each sentence with a digit (§2), and the store refuses a digit in Eadwyn's words on save (D908).

**Story: marking and clearing by hand** (`ObjectionsPanel.jsx`). Each opens a dialog first.
- **"Mark answered in [Section]"** on a row records the open section of the open saved version (`picked`). Its dialog says:
  - "Records that [Section] in v[n] answers “[objection]”.";
  - "It replaces the earlier record: answered in [Section], v[n]." when there is one;
  - "[Section] has changes not saved yet. The record points to v[n] as saved; Save version keeps your changes." when the open section is unsaved;
  - "Your words and Capital relationships do not change."
- **"Clear answer"** opens "Clear this answer?":
  - "“[objection]” will no longer read as answered in [Section], v[n].";
  - "The section keeps its words. Capital relationships does not change."
- A refused write keeps its dialog open, with "Nothing was changed: [the Worker's sentence]."
- Neither is offered to an admin, on the live deck's version 0, or while the answers could not be read. Unlike Answer it, both are offered on a phone.

**"✓ Answered in [Section] ›"** sits under an answered objection.
- Beneath it: "v[n] · Eadwyn’s draft, saved" or "Picked by hand", then the name and the day.
- It opens Story on that version and section (`?version=&section=`).
- `?section=` opens that section, on arrival or when followed from Story itself.
