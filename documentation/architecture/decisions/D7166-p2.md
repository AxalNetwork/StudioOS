### What was decided

1. **Sort and Filters in thumb reach on a phone (RFD-03A).** Below 640px the Directory's sort select and filter row are not drawn. A bar holding "Sort · Size ↓" and "Filters · N" sticks to the bottom of the screen, above the phone tab bar (`--mobile-tabbar-h`, D425), while the list scrolls under it. Both targets are 48px. Sort opens a bottom sheet of the six orders; a choice applies at once.
2. **The full-height filter sheet (RFD-03B).** Filters opens the shared `Sheet` as a full-screen page (`phone="full"`), titled Filters, with Clear all in its head while a filter is in force. It holds every filter the desktop row holds: Manager HQ, Stated focus, the size in one currency at a time (EUR and USD as two radio buttons, From and To in millions), Vintage, EIF and EIFO. Filters apply as they change, exactly as on desktop, so the footer's "Show N fund vehicles" is the API's live `total`; while a read is out or after it failed the button reads "Show results", never a number it was not given. The count is also said in a polite region inside the sheet, because the page behind a modal sheet is inert. Escape, × or Show close it and focus returns to the Filters button (RFD-06 row 4).
3. **"Show them" (RFD-02).** The line "N funds have no size in euros, so the size filter leaves them out." ends in Show them. It shows exactly those funds: the size filter is replaced by its other side, `size_band=none` on `GET /api/research/fund-directory`, every match with no size in the asked `size_currency` (no amount, an amount in the other currency, or a list whose currency is not recorded). Every other filter stays. The rows answered are the ones `facets.size_not_comparable` counted, so the line's number and the list agree. The chip reads "Size: not recorded in EUR" and removes like any size filter; typing a From or To replaces it. Its accessible name starts with its visible text: "Show them: the 4 funds with no size in euros". Once the list answers, focus moves to the results heading.
4. **The Worker's `size_band=none`.** `services/researchFundDirectory.ts` accepts `none` beside the six bands and filters `(COALESCE(source_name, '') <> ? OR fund_size_cents IS NULL)`, bound to the asked currency's list, the same rows `sizeFacet` counts as not comparable. Like a band it cannot be combined with `size_min` or `size_max` (400). No new route, no new column, no migration.
5. **"Signed in. This is the search you opened." (RFD-04B, RFD-06).** When the route guard sends a signed-out visitor away from a Directory link (`/research/funds?view=directory…`), `loginRedirectFor` keeps the link as `next`, as part 1 built, and now also remembers it under `gvpn:funds-return` with the time, for a kept destination's 24 hours. The Directory reads that marker once as it mounts (`consumeFundsReturn`): when it names this same path and query, the marker is cleared and the page shows one polite `role="status"` line, "Signed in. This is the search you opened.", with "Directory · 3 filters · Size, largest first · page 1 of 1" built from the answer on screen, and focus lands on the results heading once the list answers. The region is in the tree, empty, from the first render, so the sentence is announced once when it arrives. A marker for another link is left alone; a stale or unsafe one is cleared and never announced. The too-long link keeps part 1's own line ("The link was too long to keep its filters…") instead. The redirect URL itself is unchanged, so every sign-in method (email link, Google, passkey, authenticator) still lands on the same `next`.
6. **Chips hand focus on (RFD-06 row 5).** Removing a chip moves focus to the chip that took its place, else Clear all, else the search.
7. **Investment geography stays Not recorded, and waits on a source.** No list the directory holds records where a fund invests: the EuroTech list and the Shai Goldman list record the manager's HQ, which is where the manager is based. D7167's `research_fund_vehicle_facts` can hold an `investment_geography` fact, but nothing writes one. So it reads Not recorded, with its reason, everywhere the boards draw it: the desktop Sheet and the phone's bottom sheet (`FundDetails`, from D7167's proposed field or `GEOGRAPHY_REASON`), and now the coverage disclosure (RFD-02D), "Investment geography · Not recorded · No list records it, so it is not offered as a filter." It is no filter, no sort and no query key. **It waits on a source:** a list, or a reviewed import into `research_fund_vehicle_facts`, that states where each vehicle invests, with its own provenance. Until one lands, nothing here is inferred from HQ.

### Departures from the canvas

- RFD-02C draws a count under each currency button ("EUR · 1,076 funds can match"). Neither the desktop row nor the phone sheet shows one: the API answers one currency's size facet at a time, so the other currency's count is not in the answer on screen. The live count is the sheet's Show button.
- RFD-03A draws the thumb bar at the screen's bottom edge; here it sits above the phone tab bar, which the canvas does not draw.
- The canvas draws "4 UK B2B funds have no size in euros"; the line names no filters ("4 funds have no size in euros"), since the chips beside it already do.
- The signed-in line carries the search text when there is one ("search “dawn”"), which the canvas's example has none of.
