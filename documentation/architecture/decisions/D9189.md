## D9189 — Project intake and Eadwyn's streams send no exception text (#9189)

- **Status:** built by S08 on #9189, 2026-11-27.
- **Follows:** D278 (refusal bodies: `error` is a code, `message` is our sentence, provider text only on `upstream` for an owner or admin) and D7256 (logs keep a bounded classification, never the text).

### The problem

Three routes passed the text of whatever was thrown straight to the browser or to the model:

- `POST /api/projects/submit` read its body with no catch and returned the `message` of any exception from the score checks as `reserved_field`. A body of `null` made the completeness check throw a `TypeError`, so the engine's own sentence came back as the error.
- `POST /api/assistant/message` sent the exception's `message` in the stream's `error` event, put a tool's exception text into the tool result Eadwyn read and the conversation stored, and sent up to 400 characters of the provider's error body as `detail`.
- `POST /api/advisor/explain` sent the exception's `message` in its stream's `error` event, and answered a failed model call with the provider's text as `error`. `/tool` and `/tool/auto` wrote a tool's exception text into the turn audit and returned the JSON parser's message on `llm_refusal`.

### What changed

- **Intake.** A body that is not a JSON object gets `400 invalid_body`, "Send the intake as a JSON object.", before any score check. Only `ReservedFieldError` keeps its own sentence (and now names its `field`, as `/api/scoring` does). Anything else is passed to `reportPrivateError` and gets `500 intake_check_failed`.
- **Stream `error` events** are built by `refusalBody`: a code on `error`, our sentence on `message` and `detail`, and the raw text only on `upstream`, clipped, for an admin. The codes are `assistant_failed`, `assistant_upstream_failed` (which also carries the provider's `status`) and `explain_failed`. The page already prints `message`, so no frontend change is needed.
- **Tool failures.** Eadwyn is given `{"error":"tool_failed"}`, and that is what the `tool` row stores. The advisor's audit row records `tool_execution_failed`, and `llm_refusal` reads `parse_failed`. The text goes to `reportPrivateError` in both routes.
- **`/explain` model failures.** When the refusal is `all_models_failed` or missing, so the text came from the provider, a member reads "Eadwyn could not reach its model just now. Try again in a moment." and an admin also gets `upstream`. Refusals whose sentences we wrote (budget, plan, guard, model choice) are unchanged.

### Tests

`cloudflare-worker/test/raw_exception_text_9189.test.ts` drives each route over the migrated schema with a stubbed `fetch` and Workers AI binding. Every awaited call inside `/explain`'s stream catches its own errors, so no route-level throw reaches that stream's `catch`. Its `error` event is held to `refusalBody` by a source check.
