### 2. The reads, and what each figure may say

| Desk | Read | Rule |
|---|---|---|
| Hosts | `GET /api/admin/lab-hosts?status=` | A chip reads its own status. The newest 500 rows come back with every status's count, uncapped.<br>The chips draw the Worker's counts, never the length of a list. At 500 rows the table says it shows the newest 500 and that search covers only those. |
| 83(b) review | `GET /api/admin/83b-review` | Every startup with a tracker, and the admins an operator is chosen from. |
| Formation orders | `GET /api/admin/incorporations` | The newest 200 paid orders, each with its project's newest 50 documents. A cap line is drawn at 200. |
| Graduation | `GET /api/spinout-lab/certificates` | The newest 500 certificates, the graduates with none (`awaiting`), and `eligible_total`.<br>When the graduate read fails (`awaiting: null`), Eligible says it could not be read, the table says only certificates are listed, and Issue all eligible is disabled. Nothing is drawn as 0.<br>Issued counts the issued rows and says "[n] revoked since". At 500 it reads "500+" with its cover line. |

**State rules on every desk:**
- Each desk reads alone, so one failing never blanks another.
- A failed read says "[what] could not be read", with a retry and a sentence saying no row is shown as waiting or unassigned. It never says "none yet".
- After a failed refresh the rows stay under a "Could not refresh" line.

**Emailed and Downloaded are "Not recorded",** in the tiles and in every row, each with the canvas's line:
- "No email is sent for a certificate yet."
- "The certificate is built in the graduate's browser."

**Words** are the canvas's:
- Hosts: Waiting, Approved, Declined, Withdrawn, Removed.
- Orders: Paid, Packet in progress, Packet ready, Filed.
- Graduation: Awaiting issue, Issued, Revoked.
- A decision or review reads "by an admin", as the canvas writes it.

**Gaps** never get a bare dash. A missing value has words: "Not reviewed yet", "Not set", "None yet", "Not filed", "Not generated", "No page yet", "No reissue".

**Days are the Lab's clock.** A stored stamp is UTC (`ui/parseStamp.js`) and is drawn as its day in ET. A calendar date (a follow-up, a filing date, a public issue date) is drawn as itself.

### 3. The writes

Every change opens an in-page `Lightbox` dialog that says what it changes. A Worker refusal is said inside the dialog in words, never as a code, and the dialog stays open. A result stays until Done, and closing after a write reads the desk again. There is no browser pop-up: the old certificate console's `window.prompt` for a revoke reason is gone with it.

| Dialog | Endpoint | What it holds |
|---|---|---|
| Approve, Decline, Remove a host | `POST /api/admin/lab-hosts/:uid/decision` | What the decision changes on Office Hours, and an optional note the host sees (1,000 characters). |
| Assign the 83(b) operator | `PUT /api/admin/83b-review/projects/:id/operator` | No admin preselected; Unassign when one is set. |
| Record a review (SL10d) | `POST …/projects/:id/reviews` | Complete or Incomplete with neither chosen, an optional note, and an optional follow-up date.<br>Record stays disabled until an outcome is chosen. A startup with no operator is told to assign one first, which is the Worker's rule. |
| Mark the packet ready (SL10d) | `POST /api/admin/incorporations/:id/packet-ready` | The project's documents as radios, none chosen. With no documents, it says so and offers no action. |
| Record the filing date (SL10d) | `POST …/:id/filed` | No date prefilled. A date after today (ET) or before the payment day is refused in place, with the Worker's own words. |
| Issue one certificate | `POST /api/spinout-lab/certificates` | — |
| Issue all eligible | `POST /api/spinout-lab/certificates/backfill` (limit 100) | The result reads "After Issue all eligible: [n] issued · [k] could not be issued: …", plus how many still wait. It stays on the page after the dialog closes. |
| Revoke (SL11r) | `POST /api/spinout-lab/certificates/:id/revoke` | A required reason. The canvas's line: the verification page will say it was revoked, and a same-date reissue is not possible. |

### 4. Search, filters and sort

These run in the browser over the rows read. They are exact below each cap, and the cap line says when they are not.

| Desk | Search | Filters | Sort |
|---|---|---|---|
| Hosts | name, company or email | Applied as | Waiting longest (the canvas's default), newest, name |
| 83(b) review | startup | Operator (any, unassigned, or one admin), Last review (complete, incomplete, none) | Next follow-up (soonest first, none last), name |
| Formation orders | company or project | Status, Jurisdiction | Paid (newest or oldest), company |
| Graduation | graduate or company | Status, Public page | Graduated (awaiting first, then newest), name |

### 5. Phone (SL20)

The canvas has no phone board for these tabs, so they follow the Lab's phone pattern. Below `lg` each table becomes a list of cards with the same values and actions, the tiles sit two up, and dialogs open as pages (`Lightbox` `pageBelow="lg"`). The page itself never scrolls sideways.
