### 1. CT-17: the filter row

The interim labelled selects from part 1 are gone. Under the existing search and status controls is one row of filter
buttons in the canvas's order: Agreement type, Legal state, Licence / territory, Program, Axal VC package, Template,
Signed date. A set button is drawn "on" and reads its value, or the count when several types are chosen
("Agreement type: 2"). One panel opens under the row: a disclosure like the Library, not an ARIA menu, and outside the
row's horizontal scroll so a phone never clips it. Escape and Done close it and return focus to its button.

- **Agreement type** is a multi-select of checkboxes. The Worker took one value, which could not "isolate package and
  program agreements" together, so `agreement_type` now takes a comma-separated list
  (`services/contractAgreementSources.ts`: each entry checked against `AGREEMENT_TYPES`, a repeat is one entry, an empty
  or unknown entry is the same 400 naming `agreement_type`). The route, its gate and every other filter are unchanged.
- **Legal state, Program, Axal VC package** are single choices (radio), as the Worker reads them.
- **Licence / territory** takes a licence reference or uid and an ISO-2 territory; **Template** a slug; **Signed date**
  a from and a to. Each is checked before it is sent, with the Worker's own patterns, and a value the Worker would
  refuse is named in place and not sent. Effective date is not offered (part 1 §4: no master licence contract records
  one), and the panel says so.
- **Active filters** are chips, one per value (each type its own chip), each removable on its own; **Clear all** clears
  these filters and keeps the search, status and sort; the count is the Worker's `total`.

The filters live in the address. `ContractsDesk.jsx`'s `filterKeys` had dropped the part-1 filters, so they never stuck.
This part carries the same three lines as PR #5740 (#5051), character for character, so whichever merges second merges
cleanly; the territory and signed-date keys are added on the separate `filters` line, away from that hunk.

Not drawn: the canvas's Licence family, Licence type and Holder buttons. The Worker reads them (D5060) but their
controls are #5060's (D5060 §7).

### 2. CT-18: the row

The agreement cell carries the object tag, then **territory · licence · package and version · program**, in the
canvas's order (a user licence agreement with no territory names its holder first); "From template slug vN" as a
source, never a state; and the links **Open licence ›**, **Open Program access ›** (program kinds), **Open package
context** and **View / download agreement ›** (the agreement workspace; "View agreement" when no signed PDF is on file).
The package link reads Not recorded with the Worker's reason: there is no package page yet (#5021). A licence the
Worker cannot name reads Not recorded with `licence_reason`, never a dead link.

The **legal-state word** sits under the lifecycle pill: "legal state · superseded · history". It is the document's
state (part 1 §3), so an executed schedule a terms change replaced shows the Executed pill and "superseded".

Departure: the table keeps the CT-02 columns S24 built (Agreement · store, Company · recipient, Where it stands,
Provider, Lifecycle · legal state) rather than the addendum's redraw (Agreement, Type, Lifecycle · legal state,
Counterparty, Effective). The columns are S24's desk layout; the addendum's content sits in them: the type under the
title, the counterparty in Company · recipient, the dates in Where it stands.

### 3. CT-19: the never-sent version

A version with no envelope and no send reads "○ Prepared · not sent · no envelope", dashed: never the executed seal and
never a template's outline. "No envelope" stands where the provider would be, its title opens nothing, there is no
document link, and the reason "Not sent: there is no envelope or signed document yet." is printed. A version with an
envelope stays one row (part 1 §1).

### 4. CT-20: phone and states

Below `md` the rows are cards (title, type, context and links, the pill with the legal-state word) and the filter
buttons scroll in one line with short names (Type, Legal state, Licence…). Departure: the canvas's phone shows only
the search and the chips; the desk's older controls (Document type, Party, Provider, Sort, Clear filters) still stack
above them, because they are the only way to reach those filters on a phone. The list reads:

- **None**, when a person narrowed it: "No agreements match these filters", the active filters, "Read succeeded.",
  Clear filters. With nothing narrowed: no agreements are recorded yet.
- **Unavailable**, on a failed read: "Agreements couldn't be read", the time, "The list is never shown as empty.",
  Retry.
- **Refused** on 401/403: "You can't view these agreements" with the Worker's reason. A 400 names the filter value
  Contracts does not know, with Clear filters.
