## D535 — research_fund_directory is rebuildable from the repo, size parser and future-dated reports fixed

**Research funds, step 1 of 4 — `research_fund_directory` is rebuildable
from the repo, with the size parser and the future-dated reports fixed.**
Issue #1081, slot S04, part of the Research rebuild epic (#1077). This PR
is the data step only: `scripts/import-research-funds.py` plus migration
378. The directory API, the fund-page API error handling, and the pages
themselves (gated on `needs-design`) are later steps on the same issue.

**What was wrong on main.** Migration 365 (`import-eurotech-funds.py`) was a
one-time snapshot: 1,076 `INSERT OR REPLACE` statements generated once and
committed, while production holds 2,032 rows — D1 has rows the repo cannot
reproduce. Two further bugs in that generator, both named in the issue:

1. **The size parser read the sheet's own thousands separator as a decimal
   point.** `"€ 1,375m"` became `1.375` (stripped `.`, then read `,` as the
   decimal point) instead of `1375` — every size using a thousands
   separator landed 1,000x too small. EQT Growth was stored as EUR 2.4m;
   the sheet's own exact-euro column for the same fund, `"€2,400,000,000.00"`,
   confirms the true figure is EUR 2,400m. The sheet's actual convention is
   the reverse of what the old parser assumed: `,` is the thousands
   separator (dropped), `.` is the decimal point (kept) — ordinary English
   notation, not the European convention the old code was written for.
2. **75 reports were dated after the day the migration was generated.**
   The old generator turned every non-blank annual column (2016..2026)
   into a report dated `{year}-12-31`, including the column for the
   still-open current year — a report for a fiscal year-end that hasn't
   happened yet. Fixed by never emitting a derived annual observation whose
   date is after the run date.

**The new importer, `scripts/import-research-funds.py`.** Reads both
public spreadsheets in `attached_assets/` directly (not the bundled
`frontend/src/data/fundDirectory.json`, which was a browser-side cache of
one old run) and regenerates migration 378 as `INSERT OR REPLACE`
statements keyed on `uid` (directory) and `(fund_uid, period)` (reports) —
rerunning the script, or applying the migration twice, leaves the same
rows, never duplicates. Verified: running it twice produces a
byte-identical migration file (sha256-matched), and re-applying the SQL to
an in-memory SQLite database twice leaves the same row count.

**The exact-euro column wins over the "€ Xm" shorthand when both exist.**
Column 67 of the EuroTech sheet (e.g. `"€1,375,000,000.00"`) is the sheet's
own precise figure; the importer prefers it over parsing the rounded `"€
Xm"` shorthand in column 5, falling back to the (now-fixed) shorthand
parser only when the exact column is blank.

**The Deep Tech Investors Mapping sheet is USD, with no per-period
history.** Rows from it that don't already match a EuroTech fund (by
normalized name) are added to the directory so the repo can at least name
them, but with `fund_size_cents` left `NULL` rather than writing a USD
figure into a column the schema, the route and every reader document and
consume as EUR cents. 1,540 of the rebuilt directory's 2,616 rows are
Deep-Tech-only in this PR for exactly that reason — a currency conversion
and a size/stage/ticket schema extension for that sheet's own fields
(ticket size, stage, region, sector flags) is left for a later step on this
issue rather than guessed here. The bundled `fundDirectory.json`'s richer
per-fund fields for Deep Tech rows (stage, region, min/max ticket) are not
yet in D1 either, for the same reason — recorded here rather than silently
dropped, so a later step on #1081 can decide the schema for them deliberately.

**Row counts (never content, per the issue's own instruction):**
EuroTech rows read: 1,413. Directory rows from EuroTech: 1,076. Directory
rows added from Deep Tech only: 1,540. Directory rows total: 2,616 (close
to the bundled file's 2,618 — the 2 missing are blank-name rows the

**A third production source has no file in the repo, so this migration

was in progress) says production's 2,032 funds come from three sources, not
the two named in the issue body: "EuroTech VC Funds" (1,045 rows — migration

or any importer, to read it from. This PR does not reproduce those 987

**Tests.** `scripts/test_import_research_funds.py` (17, `unittest` —
`pytest` isn't installed in this sandbox, but `unittest`-style tests are
also pytest-collectible, so this stays runnable either way): the size

## Steps 2 and 3 — the directory searched, filtered, sorted and paged on the server; the fund page's errors reported

Slot S09, taking #1081 over from S04 at the owner's request. No migration.

**What was true.** `GET /api/research/fund-directory` took `q` and `hq` and
returned up to 2,000 rows; the page never called it, and filtered the bundled
`fundDirectory.json` in the browser, 48 matches at a time. A failed read of
`/fund-directory/:uid`'s reports turned into a 500 for the whole fund.

**The directory API** (`services/researchFundDirectory.ts`, called by the two
handlers in `routes/research.ts`). Every value from the request is bound:
- `q` matches the name as a substring; `%`, `_` and `\` match themselves
  (`LIKE … ESCAPE '\'`).
- `hq_country` (ISO 3166-1 alpha-2) and `focus` (a market-directory slug) go
  through #1080's crosswalk: `mapFundHq` and `mapFundFocus` run over the
  distinct HQ and focus strings, and the strings that map to the target are
  bound as one JSON array (`json_each(?)`), since D1 allows at most 100 bound
  parameters. "Bay Area, Israel" therefore answers both `US` and `IL`.
- `size_min` and `size_max` are whole euros, compared only on the EuroTech list,
  the one list whose sizes are known to be euros. S1 (12:17Z on #1081): the
  lists are never banded, sorted or summed together unconverted. A size filter
  leaves out every row whose currency is not recorded.
- `vintage_from` and `vintage_to` (inclusive, on `fund_year`).
- `eif` and `eifo`: `1` is backed. `0` is not backed only where the row records
  its LPs: a 0 flag with no LP text means unknown (S1, 12:17Z).
- `stage` is refused with a 400 naming the field: the directory records no
  stage yet, and an unfiltered answer must never pass for a filtered one.
- `sort`: `name` (default), `size` or `vintage`, with `-` for descending, from an
  allow-list. Size puts the euro rows first, by size, and every row without a
  euro size after them.
- `limit` (25 by default, 100 at most) and `offset`. The answer carries `total`,
  `limit`, `offset`, `sort` and `size_basis`. A bad value is a 400 naming its
  field, never a silent default.

Each row now says its size's currency (`size_currency: 'EUR'`), or shows no
size and gives the reason. A number held for a list whose currency is not
recorded is not shown. `eif` and `eifo` read true, false, or null when unknown.

**The fund page API.** A fund that cannot be read is a 503 "Unreadable". A
fund whose reports cannot be read still answers, with `reports_status:
'unreadable'`: it is never passed off as a fund with no reports. `reports`
stays an array, so the page that reads it today keeps working.

**Client.** `frontend/src/lib/api/researchFunds.js` (`researchFundsApi.list`,
`.get`), re-exported by one line in `api.js` (D527). The pages that will call
it wait for the canvas approval (step 4), as do the page-side honesty fixes
(step 5). The existing `api.research.fundDirectory*` methods stay, because
`FundCatalogProfile.jsx` reads them until step 4 replaces it.

**Guards.** `cloudflare-worker/test/research_fund_directory_d535.test.ts`, 14
tests on real SQLite (365's CREATE statements, all of 376):
- the sign-in gate on both endpoints;
- paging, the total and the limit bounds;
- `q` with quotes, `%`, `_` and an injection attempt;
- `hq_country` and `focus` through the crosswalk;
- the size filters on euros only, and the sort;
- the vintage range;
- EIF and EIFO, including unknown;
- the currency rule on display;
- `stage` refused, and the bad field named;
- the directory's failure as a 503;
- the fund page's 404, its reports, and its unreadable reports.

`frontend/test/research_funds_api_d535.test.mjs` has 2 tests, for the module
and its re-export.

**Mutations: 18 run, 18 caught.** No sign-in on either endpoint; the old limit;

## Steps 4–5 — the Funds pages, to the canvas; coverage, sources and facets on the API

Slot S09, #1081. The owner approved `design/incoming/Research · Funds.dc.html`.
No migration.

**The API** (`GET /api/research/fund-directory`, backwards compatible — every
field of steps 2–3 stays):
- `coverage`: `{ total, as_of, fields: { size_eur, size_unknown_currency, hq,
  website, linkedin, sector_focus, fund_year, notable_lps, fund_number } }`, how
  many rows of the whole directory carry each field. Unfiltered, so the bars do
  not move with the filters.
- `sources`: `[{ name, url, rows, as_of, size_currency }]`, one per list the
  directory holds. `size_currency` is `EUR` for the EuroTech list and null for
  every other.
- `facets`: `hq_country`, `focus` and `vintage` as `[{ value, label, count }]`
  with a `none` entry last; `size_band` (six half-open euro bands) plus
  `size_not_comparable`; `eif` and `eifo` as `{ backed, not_backed, unknown }`.
  Each facet's counts apply every other active filter and not its own, so an
  option's count is what choosing it would return. A fund whose HQ names two
  countries counts under both; an HQ or focus the crosswalk places nowhere
  counts under neither, and `facets_unmapped` says how many. `facets_basis` says
  all of this in the answer. Labels come from `research_countries` (376) and
  `research_market_directory` (229).
- New filters: `none` for `hq_country`, `focus` and `vintage` (the field is NULL
  or blank — a recorded value the crosswalk cannot place is not `none`);
  `vintage=<year>`; `size_band`. `size_band` with `size_min`/`size_max`, or
  `vintage` with `vintage_from`/`vintage_to`, is a 400 naming the field.
- Size bands count euro rows only. A size from a list whose currency is not
  recorded is never banded, sorted or summed with them (S1, 12:17Z).
- `GET /fund-directory/:uid`: a report's size is shown only in a known
  currency, like the fund's own (`size_currency` per report).

Every value is bound. The facet queries reuse the step 2–3 condition builder
(`conditions`, with the filter to leave out), so `check-sql-prepare` sees no
new interpolation.

**The pages.**
- `/research/funds`: `FundDirectory.jsx` above the founder shortlist, inside

- Sizes: only a row with `size_currency: 'EUR'` shows one. Every other row reads
