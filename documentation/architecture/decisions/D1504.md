### What was decided

1. **Drift fails CI.** `services/ai/routedModels.ts` lists every routed id:
   - a router task's model, alternates and fallback chain (`ROUTE`, which includes the module routes);
   - every deck element's suggested models, the rest under All models, its chain and its pipeline steps (`ELEMENT_ROUTES`, `choicesFor`).

   `driftProblems()` names any id that fails a rule:
   - it is missing from `CATALOGUE`;
   - it is not `ga` or `partner`;
   - it is unpriced;
   - it does another kind of work than its element (write uses chat; draw and edit use draw; an upload's screen uses vision or chat; embedding routes use embed; audio routes use transcribe).

   `ai_model_terms_d1504.test.ts` requires `[]`, and shows a catalogue missing one routed id, retiring it or unpricing it each fails. Today 58 ids are routed and all pass. The weekly job (B9) reads the same list.
2. **An unavailable model is skipped for an hour** (`services/ai/availability.ts`).
   - **What marks a model:** a call answering 404, a 5xxx error code, or "no such model". Code 5035 ("your plan cannot run this") is a plan answer, not a missing model, so it does not mark one. Neither does 429 or 3040, which are capacity answers.
   - **Where the mark lives:** `RATE_LIMITS` KV under `ai_unavailable:<model>`, for 3,600 seconds. A KV that cannot be read or written skips and marks nothing.
   - **What the router does:** inside the hour it skips the model without a call (recorded as an attempt that was not called), and the run goes on down its own chain, in the same tier. The model that answered is the one `usage.model` and `fallback_used` record, so a proposal names it truly.
   - **Retired picks:** a stored pick of a retired model is already cleared when it is read. The rail clears it because the model is no longer offered (D764); a deck element clears it through D1503's `clearStale`.
3. **A terms register** (`services/ai/modelTerms.ts`, `documentation/architecture/MODEL_TERMS.md`).
   - **The record:** `termsOf(id)` answers `{ url, licence, commercial_output, attribution, flow_down, reviewed_on, reviewed_by, grandfathered }`.
   - **Grandfathered:** the frozen `GRANDFATHERED` list holds the 61 models main could run before the register existed (every priced `ga` or `partner` row, partner gate open, catalogue read 2026-10-31). It is written out, never generated, so a model the catalogue gains later is not grandfathered.
   - **The refusal:** `aiRouter.modelRefusal` refuses a model that is neither grandfathered nor reviewed (`reviewed_on` and `reviewed_by` in `REVIEWED`) with `model_terms_unreviewed`, "… is waiting on a review of its terms", as a 422 like the other model refusals.
   - **The record lives beside the catalogue,** not on each `CatalogueModel` row as the issue first said: `catalogue.ts` would otherwise import its own reader. `termsOf` is the field.
   - **Nothing is reviewed yet (X).** Every review field reads "Not recorded" and is never guessed.
4. **The deck's AI Gateway, inert** (`deckGatewayOptionFor`).
   - **Inert until the owner creates it:** `CF_AI_GATEWAY_SLUG_DECK` is `""` in all three `wrangler.toml` tables, so no run is gatewayed.
   - **Which runs it covers:** a deck run is `deck_image` or a run on a `deck:` rail option.
   - **What a deck run carries once the slug is set:**
     - `skipCache: true`, so a variant is never served from cache, and Regenerate and the 2–3 variants really differ;
     - `collectLog: false`, so the gateway keeps no prompt or answer;
     - at most five metadata entries: branch, account, task and rail option.
   - **No retry:** the advisor gateway's Task #50 bypass does not apply, because `isGatewayRouted` stays the advisor's.
   - **No router cache:** no deck task has `cacheTtlSec`.

### Verified

`cloudflare-worker/test/ai_model_terms_d1504.test.ts` (4 tests):
- drift, with a removed, a retired and an unpriced routed id each caught;
- terms: grandfathered models run, unreviewed ones are refused, and the register equals the grandfathered list;
- an end-to-end run where "No such model" marks the primary, the chain answers and is named, and the next run never calls the primary;
- the gateway: inert while empty, then no cache, no log and at most five metadata entries.

Mutations, each caught:
- `skipCache: false`;
- the router not reading the unavailability mark;
- `modelRefusal` ignoring the terms.
