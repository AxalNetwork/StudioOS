## D4117 — Team agents wear one of 16 fixed personas; no job title reaches the client (#4117)

- **Status:** built by Claude Code for slot S03, 2026-11-02. Not deployed and not checked live.
- **Part of:** #4116 (AI agent roster), task R1 (Worker). R2 uploads the avatars, R3 draws the cards and the Add flow, R5 adds skill cost.
- **Migration:** `202611021724_team_agents_persona.sql` (D4106's stamped name).

### 1. The catalogue

`cloudflare-worker/src/services/agents/personas.ts` holds the 16 personas as code, like the role catalogue: frozen, served by `GET /api/teams/personas`, and edited by no route. A change is a reviewed commit, and the names live in that one file, so a trademark-clearance swap is one line plus its image.

Each persona has `key`, `name` (a single word), `gender`, `tagline`, `goal`, `personality`, `story`, `risk` (1–5), `values`, `top_values`, `natural_fit` and `avatar` (`/agents/<key>.webp`).

Where the text comes from, by the owner's revisions of 2026-11-02:
- **Names:** the second sci-fi mapping on #4116 (Vesta, Orrin, Ilyse, Kade, Sylva, Solen, Tessaly, Corvane, Juno, Brann, Seren, Corin, Ryssa, Draxen, Elara, Aurel).
- **Tagline, goal, story:** the "Hall of the Trefoil" revision, copied exactly. `goal` is the plain business line.
- **Personality and gender:** the roster in #4116's body.
- **Values:** the 6 Axal behavioral values, the last revision on #4117. They are `FIT_V2_VALUES` from `services/axalFit.ts`, imported and never copied, so people and agents are described in one language. The legend the route returns is `FIT_V2_VALUE_SPECS`' labels and descriptions.
- **Risk:** the table's words: most cautious 1, cautious 2, balanced 3, bold 4, boldest 5.

**Not carried:** the outlooks (Guardian, Explorer, …), the five founder trade-offs and every Schwartz value. The owner removed them as reading like political camps, and no DTO has `philosophy` or `tradeoffs`.

### 2. Value scores

The owner gave each persona's top 3. The full scores follow one rule:
- the top three take 0.9, 0.8 and 0.7, in the table's order;
- the other three take 0.5, 0.4 and 0.3, in `FIT_V2_VALUES` order.

So the top three are always the highest, and because no two personas share a top-3 set, the 16 profiles are pairwise different. The test checks both.

### 3. Natural fit

Each area is served by a pair of values. These are the owner's example pairs from #4117, completed:

| Area | Values |
| --- | --- |
| Product, Marketing | Collaboration + Curiosity |
| Engineering | Resilience + Integrity |
| Design | Stewardship + Collaboration |
| GTM, Capital | Curiosity + Ambition |
| Finance, Legal | Stewardship + Integrity |

An area's score is its pair's sum. A persona's natural fit is its two highest areas, ties broken in the SkillRadar's order (Product, Engineering, Design, GTM, Marketing, Finance, Legal, Capital). It is advisory and blocks nothing.

Some fits differ from #4116's original body, which predates the values rewrite. For example, Juno comes out Engineering + GTM, not Design + Product. The rule decides, as #4117 asks. If the owner wants specific fits, they can change the pair table and the test spells out the effect.

### 4. Agents wear a persona

- **The column.** `team_agents.persona_key` names a persona. A partial unique index keeps one live agent per persona per Team, mirroring the role index; a removed agent frees its persona.
- **Existing agents.** The migration backfills each agent with its role's default persona (`ROLE_PERSONA`, and the same `CASE` in SQL):

| Role key | Persona |
| --- | --- |
| `ceo` | Solen |
| `cto` | Corvane |
| `cpo` | Juno |
| `cfo` | Orrin |
| `cmo` | Kade |
| `sales` | Seren |
| `coo` | Tessaly |
| `general_counsel` | Vesta |
| `people` | Elara |
| `research_analyst` | Ryssa |
| `investor_relations` | Aurel |

  The eleven are all different, and a Team already had at most one live agent per role, so the backfill never places a persona twice on a Team.
- **Adding an agent.** `POST /api/teams/:scope/:id/agents` takes `persona_key`; when it is omitted, the role's default persona is used, so today's screens keep working.
  - 400 `invalid_persona` for an unknown key.
  - 409 `persona_on_team` (with `persona_key`) when that persona is live on the Team. Both a pre-check and the index answer it, so two adds at once cannot both succeed.
  - `role_taken` answers first when the role is also taken.

### 5. The role, and the skills (#3951)

#4117 asks that `works_in` / `may_propose` become the union of the agent's skills' areas and outputs once #3951 lands. #3951 (D1612 A) is on main, but its skills carry **roles and taxonomy tags, not modules or rail options** (migration 759: `agent_skill_roles`, `agent_skill_tags`), so there is nothing yet to take a union of. Until a skill names the modules it works in, which the skill library (#3953) or a later D1612 part must add:
- the rule book stays keyed by `role_key`;
- `role_key` stays required on add;
- D1612's `role_mismatch` attach rule stands.

Both are back-compat only. The persona is the agent's identity, and the role is an internal key.

### 6. No job title reaches the client

Every agent DTO drops `role_name` and carries `persona`:
- `GET` / `POST` / `PATCH` agents;
- the profile;
- the approvals queue's `item.agent`;
- the skill pages' "used by" names (`team_skills.ts`'s `agentName`), which now use the persona's name and never fall back to a role.

The run's system prompt says "You are Vesta, an AI agent of …" with the persona's personality and goal, instead of "the CTO agent". The frontend's `agentName` reads `persona.name` first: one line, so today's Team pages show the agent's name until R3 redraws them.

**Still showing role names:** `GET /api/teams/roles` keeps them, for the rule-book editor and today's add sheet, until R3 replaces the role picker with the persona gallery. A test checks every agent DTO and `GET /personas` for any role title, outlook word, `philosophy`, `tradeoffs` or Schwartz key.
