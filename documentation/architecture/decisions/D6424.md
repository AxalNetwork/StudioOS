## D6424 — Recorded stale rules and visible diligence waits (#6424)

The owner chose a per-firm days-in-stage stale setting, with no default.
`deal_flow_attention_rules` stores the firm's optional threshold and its actor.
Only the verified active firm may be read or changed; support sessions cannot
write. Days must be whole numbers from 1 to 3650, or null to clear. A personal
flow cannot change a firm's rule. Unset is Not recorded, never zero stale.

The mounted `/api/deals/flow/attention` read returns each flow deal's stale
flag and visible open diligence request count, plus the aggregate stale and
waiting counts. Passed deals are excluded. Stale means recorded days in the
current stage at least the firm's threshold. Missing stage dates remain
unknown. Waiting means at least one unanswered requested item on an open or
in-review project diligence case the caller owns or reviews, for a deal the
caller can open. A Diligence stage alone is not a wait. The count is deals,
not requests; request text and other teams' case data never leave the read.

Each source has a recorded, not_recorded or unreadable state. Failed reads
retain null counts; the strip says Unreadable and offers retry instead of 0.
The existing new-deal inbox remains its own source. Stale/waiting are recorded
count badges; only New links to New for you. The strip's firm-rule control
saves the server setting explicitly. An empty input clears it. The existing
Standard SLA card treatment is separate from this firm attention setting.

Mounted full-schema SQLite tests cover firm isolation, shared seats, owner/
reviewer diligence access, source failures, threshold setting/clearing and
invalid/support writes. Rendered and mounted frontend tests keep all three
counts and the unknown/unreadable states truthful.
