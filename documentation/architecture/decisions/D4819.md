### What the canvas decides

- **L0 is the production state:** “No licences have been issued” and Issue first licence lead. Search, filters and sort are hidden at zero; territory coverage is one line (27 available · 0 held · 0 suspended); seat utilisation reads Not recorded in operator language (no `U1`).
- **Populated ledger:** counts plus a Needs HQ summary whose items are filters; nine columns with one primary state per cell; rows deep-link to `/admin/licences/:uid/:section`.
- **Licence detail:** identity header, attention strip, sections Overview · Terms · Agreement · Access · Operations · History. Overview keeps licence, agreement, commercial, access, branch, billing and requests as separate facts, plus a Sources card (HQ ledger vs branch freshness).
- **Terms** are a contractual schedule; Amend terms starts a session with before → after values, Review N changes, downstream effects and a required reason; a conflict state when another admin changed the record.
- **Agreement:** the executed agreement leads; ledger terms, draft, sent and executed are distinct; readiness preflight; the frozen document is shown before Send for signature.
- **Operations:** requests, compliance, billing, and branch sync as first-class state with Retry sync and Reconcile deployment.
- **One consequence sheet** (what happens, what else, reason, can it be undone) for activate, suspend, reinstate, terminate, admins, invoices, send, deploy and sync. Partial success is distinct from completion.
- **New licence** is a six-step issuance; rules (overlap, suspension, release) appear at the step where they apply.
- **“Program grants”** is renamed “Program access by licence”. Eadwyn is a compact launcher.

### Backend required

- Terms conflict: the terms write should state the revision it read (D4678 bumps `revision` on terms edits; the L7 conflict needs the write to refuse a stale revision).
- Branch sync: HQ revision vs branch acknowledged revision per licence. Deploy, retry and reconcile exist; acknowledgement does not. Partial success and History’s branch outcome depend on it.

### Build, part 1 (2026-11-07): the ledger and its zero state

Frontend only: no Worker change and no migration. It builds boards L00 to L02 and the data-state board L19.

**What was built.**

- **L00, the true zero state.** With no licence, `/admin/licences` leads with "No licences have been issued" and Issue first licence, which opens the existing draft form unchanged. "Why is this empty?" is a closed disclosure holding the canvas sentence. Search, the All / Axal / White-label filter, the status filter, the Needs HQ summary and the renewal pipeline are not drawn. Territory coverage is one line, built from the summary's real coverage (`27 available · 0 held · 0 suspended` today). View territory coverage opens the existing 27-cell grid. An empty ledger opens it without the renewal pipeline; a populated one opens it with the pipeline. If the summary cannot be read, the line says Unavailable with Retry. It never falls back to 27 free.
- **Operator copy.** Seat utilisation reads "Seat utilisation — Not recorded", followed by the canvas sentence. The page no longer prints the Worker's `seats_used_reason`, which names `U1`. The redundant "Territory licences" title is gone, and the page is titled Licences, with the canvas lede.
- **Policy prose moved to the actions.** The overlap sentence has left the ledger header. The territory step already states it ("this step refuses any country another licence already holds regardless of kind"), so the rule now appears only there. The suspension rule ("a suspended licence still holds its countries; releasing them is a termination") now appears in the Suspend dialog as a `consequence` line (`licenceReasonModel.js`, `LicenceReasonDialog.jsx`). The Terminate dialog already says that terminating releases every country. The coverage grid keeps its own legend sentence about suspended cells. That legend sits behind View territory coverage. No rule text was dropped.
- **L01 and L02, the populated ledger.**
  - **Counts line.** It reads `n licences · a active · s suspended · d draft`, from the summary's counts over the whole ledger. Pending activation and terminated are added when there are any. If the summary is unreadable, the line says Unavailable with Retry.
  - **Freshness.** "HQ ledger · read HH:MM UTC" and a Refresh button.
  - **Needs HQ.** It shows the two items the reads can compute: requests waiting (from each loaded licence's `/:uid/requests?limit=1` total) and renewals approaching (active or suspended licences renewing within 90 days, or overdue, from `renews_on`). Each item is a `role="checkbox"` that filters the table. The choice is kept in `?needs=`, and two chosen items narrow the table together. A requests item with any unreadable count reads "Requests waiting · Unavailable" and is not a filter. Until every count has answered, it reads "Reading…" instead of showing a partial count. With more pages unread, the summary says that it counts the loaded rows.
  - **Table.** It has nine columns, with one state per cell. Territory shows countries, or None. Renewal shows the date, or Not recorded, with "in Nd" or "Nd overdue" when the date is near. Requests shows None, "n waiting", or Unavailable with Retry. Attention counts the items above, and says Unavailable when the requests count is unknown. Agreement, Branch and Billing are Not instrumented (see below), and each of those cells links to its section of the licence. On a phone, the table becomes a stacked list showing the identity, the primary status and the attention count.
  - **Controls once licences exist.** Search, the kind filter and a status filter appear. The status filter runs on the server through the existing `?status=` and is kept in the URL.
- **Deep links.** A row links to `/admin/licences/:uid`, and the unread columns link to `/:uid/agreement`, `/:uid/operations` and `/:uid/fee-invoices`. `App.jsx` routes `/admin/licences/:uid` and `/admin/licences/:uid/:section` behind the same HQ guard to `licences/LicenceDeepLink.jsx`. That component opens the detail view that exists today (`?licence=&tab=`, D4707). The section defaults to overview. Each canvas section opens its nearest tab: overview → Entity, terms → Terms, agreement → Contract, access → Administrators, operations → Deploy, history → History. An existing tab key opens itself. A plain click opens the licence in place, and a modified click is left to the browser. The static `/admin/licences/programs` paths still outrank `:uid`.
- **The ledger and a licence are two views.** With no licence named, nothing opens. Before, the first row opened by default. An open licence shows a breadcrumb, "Licences / name", whose current page carries `aria-current`. A named licence that is not in the ledger once every page is read sends the page back to the ledger with a notice. Before, it opened a different licence, which only made sense while the list stood beside it.
- **Navigation.** "Program grants" is now "Program access by licence" on the HQ strip (`App.jsx`, `lib/hqStrips.js`), on that page's title and breadcrumb (`ProgramGrants.jsx`, `ProgramGrantsHistory.jsx`, `StudioView.jsx`) and on the links that name it: Approvals' door, the branch Programs tab, Lab settings and the proposals note. The address `/admin/licences/programs` is unchanged, so every old URL still works.
- **Eadwyn: left as it is.** `WorkerRail` takes no prompts and has no per-page compact or "model and usage behind a disclosure" mode. Building that would change the shared AIRail on every page, which is outside this slice. The rail keeps its trust note. The four licence prompts and the folded model and usage section need an AIRail change of their own.

**Not instrumented.** Three Needs HQ categories need reads the ledger does not make: agreements incomplete, branch out of sync and overdue invoices. The page names them as "Not instrumented on the ledger yet" and never counts them as 0. The issue also lists deployment failed, administrator missing, compliance action outstanding and terms that differ from the executed agreement. None of these can be computed from the ledger, summary and requests reads, so they are not shown. The Agreement, Branch and Billing columns are Not instrumented for the same reason. Filling them needs a ledger-level read of the contract state, the sync state (with the branch acknowledgement listed under Backend required) and invoice state, or per-row reads of the existing detail routes.

**Departures.**

- **Requests count.** The requests column and the requests item read each loaded licence's `/:uid/requests?limit=1`, four at a time. That is one call per row on the page, at most 50 per page. The canvas implies a ledger-level figure, which needs a Worker read.
- **Needs HQ scope.** Needs HQ counts and filters the loaded rows. Past the first 50 licences it says so, and Show more extends it. A whole-ledger count needs the summary to carry it.
- **Detail address.** The deep links land in today's detail through `?licence=&tab=`. The address bar then shows that form, not the path form. The detail slice moves the sections onto the paths.
- **Filters not built.** The canvas's Territory, Renewal window and Attention filter menus are not built. The Needs HQ items stand in for Attention.
- **Header action.** The header button reads Issue first licence at zero and New licence after that, matching the canvas.
