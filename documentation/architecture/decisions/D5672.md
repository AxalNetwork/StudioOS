## D5672 — Existing platform signals and conservative incident attribution (#5672)

The HQ Super Admin metadata reader reuses readPlatformCapacity,
readJobsSummary, readDlqSummary and readCapacityAlerts. It strips error and
mute text, applies reader deadlines, preserves unavailable values and returns
existing episode references. It creates no tables, episodes, probe schedule,
queue mutation or replacement store. A DLQ total is not a count of new arrivals;
new-arrival input requires a durable checkpoint from the existing ledger.

Pure observational policy separates handled HTTP 5xx from runtime outcomes,
requires a minimum denominator and sustained evidence, treats quiet traffic
as insufficient availability proof. HTTP/runtime input must separately carry
the verified raw sampleCount supporting the rate; an adaptive weighted total
cannot satisfy minimumSamples. Missing or inconsistent sample size is unknown.
The read-only Analytics SQL catalogue reports events.workersInvocations as
adaptive; a bounded query window does not establish a paging policy. Policy
also requires independently corroborated customer/dependency failures.
Queue idle, missing age, overdue completion,
Workflow demand-wait, stale telemetry and maintenance are distinct states.
Cron success must belong to the current scheduled slot: the trusted caller
supplies expectedRunAt separately from expectedCompletionAt. A previous slot's
success cannot borrow the current deadline's grace to appear healthy; absent
slot identity stays unknown.
Shared-dependency presentation counts firing sensors by kind and emits a single
logical firing/recovery; incomplete, unknown or old evidence cannot recover.
Caller persistence and group keys must reference existing platform episodes.

The planned production SQL monitor uses the issue's exact studioos response and 5xx
queries over the same window. No threshold is selected from a zero-backlog
snapshot. Policies are unapproved by default; baseline, sample floor, sustained
window, owner, fallback and cost require operator evidence. Native policy,
probe credentials/schedule, historical DLQ arrival adapter, Workflow source,
version/release correlation and live route receipts remain rollout gates.
