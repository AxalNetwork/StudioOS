## D4557 part 2 — Bounded general compute host and Worker bridge (#4557)

The owner accepted D4554 on main and reconciled the host grant on #4557:
Workspace Engine generation-bound tokens are canonical. The earlier D4557
mint/verify/claim helpers remain compatibility code. This implementation uses
`createWorkspaceSecurity` directly and creates no second grant authority.

The general host is a separate Worker with Python and document Container DO
classes. It is separate from the meeting bot and #5566's coding host. Both
host and broker admission remain off, with no production service binding.
The public authenticated staging API is Worker-first and uses existing scope,
actor, quota and proposal controls. No new UI is introduced.

A sponsor stages one immutable input manifest on an open manual agent task.
Admission snapshots its request UID alongside the existing run in a D1 batch;
changing task metadata or disabling compute cannot silently route that run to
a model. The AgentTaskWorkflow dispatches and waits for a small completion
event, then creates the existing human-review proposal referencing artifact
UIDs, sizes and digests. Lost events fall back to committed result metadata.
No result performs an automatic business action or model call.

The broker normalizes a WorkspaceSpec using server policy, resolves current
scope, checks image/provider evidence and an owner-reviewed per-job worst-case
cost ceiling. These bounds are policy, not measured invoices or financial
settlement. No model/provider billing is triggered. Missing policy refuses
admission. Live scope and generation are checked on canonical token issuance
and redemption. Input and completion audiences are separate and single use.
Artifact sink and idempotency identities are bound to the opaque job UID.

The host persists its one-job tombstone before allocating a VM. A DO alarm
owns bounded work; a reconstructed object never blindly restarts an attempted
VM. Canonical bootstrap permission is redeemed immediately before boot. The
VM receives only the approved operation, bounded bytes and redeemed bootstrap
context in a private header. Signing keys, D1, provider keys and R2 credentials
stay in Workers. Native startup uses `enableInternet: false`. Inputs cross the
port only after health and the actual running-image digest are verified.

The runtime supports sum/count over CSV/JSON, spreadsheet extraction/calculation
and text extraction from PDF/DOCX/XLSX/PPTX. No raw script or shell is accepted.
Aggregate inputs are 8 MiB. Office parsing checks actual expanded bytes,
entry count, compression ratio, traversal, duplicate/symlink entries and XML
entities. Workloads impose CPU, address-space, wall, output, descriptor,
process and file limits; the parser child also denies sockets, process
creation, exec and filesystem mutation with Linux x86-64 seccomp. Child logs
are discarded. Parent/child IPC is bounded JSON over a pipe with an absolute
deadline. Each VM accepts one job; each parser uses memory, no persistent job
filesystem. The image is a minimal pinned CPython runtime, with accurate OS
package metadata, three hashed Python dependencies and pinned zlib source.
It contains no shell, package manager, compiler or host socket.

Termination must be confirmed before completion publication. Broker cancellation
persists the generation fence before stop; teardown works after admission is
disabled and without broker/image eligibility. An unconfirmed stop remains
counted and retryable. SQL atomically limits live/unconfirmed jobs to two per
scope and four globally, in addition to default-policy application caps.
Late, tampered and duplicate callbacks cannot add artifacts. Every output uses
an immutable unique R2 key so a losing callback cannot delete winning bytes.
Unknown process metrics are NULL rather than fabricated zeros.

Private R2 holds input/output bytes, D1 holds bounded metadata and usage.
Expiry is collected by the existing sweep even when admission is halted.
Erasure confirms termination, clears host scoped metadata and grants, retains
an opaque replay tombstone and removes bytes before metadata cascades.
Telemetry uses only closed failure codes and audit identities; payloads,
bootstrap/completion tokens and raw output are not logged.

### Activation and acceptance still pending

D4554 §5 preserves the owner's original default scheduling choice. Upstream
has deprecated it and application scheduling is immutable. **Before application
creation**, the owner must reaffirm default with a migration plan or approve
the newer durable_object policy. The adapter supports an explicit newer
choice but the checked-in configuration does not make that decision.
Default scheduling must demonstrate a verifiable running-image digest;
empty/unknown image evidence refuses work. Do not weaken this check to obtain
a preview pass.

The local image workflow only builds/tests/scans and retains evidence. A separate
manual workflow requires an owner dispatch, exact main SHA, approved OCI
provenance, reaffirmed default policy and an independently protected environment
before deploying only the disabled preview host. Neither workflow publishes
images, provisions secrets or enables compute.
Registry signing/provenance and exact deployed OCI digest, current isolation
receipt, region/provider proof, cost envelope, account entitlements and the
end-to-end hosted preview require owner-approved configuration and review.
Local synthetic timings are not Cloudflare cold-start, throughput, availability,
residency or invoice evidence. The runbook defines the remaining preview and
rollback receipt. Part of #4557; the issue stays open until that proof exists.

This host currently accepts only an explicitly approved worldwide region policy
(`allowed_regions: ["global"]`). The native adapter has no verified regional
placement control; restricted-region requests fail closed even if a policy
claims them. Do not substitute a DO location hint or jurisdiction for Container
residency. A future regional mode requires a separate reviewed enforcement path.
