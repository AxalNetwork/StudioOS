## D9286 — Eadwyn's messages render escaped Markdown, and Explain is held to the question's own options (#9286)

- **Status:** built by S21 on #9286, 2026-11-28.
- **Chosen by:** the owner's supplemental Eadwyn audit (A7), as filed on the issue.

### The problem

- **Markdown printed raw.** `PersonalAdvisor.jsx` drew every message, and the Tutor panel's answer, as plain text, so the model's `**Daily**` and `- ` bullets reached the member as asterisks and dashes.
- **Explain guessed the choices.** `openTutor` sent `{ topic, conversation_id }` and nothing else. The model never saw the question's options, so it explained a question offering Daily, Weekly and Off with a **Custom** frequency the question does not have.

### What was decided

- Assistant messages (`role === 'assistant'`) and the Tutor's text render through `EadwynMarkdown` (`lib/eadwynMarkdown.jsx`), which calls `renderMarkdown` from `lib/articleMarkdown.js`. That renderer HTML-escapes the whole text before it adds any tag, and adds only its own tags; links and images keep its http(s) or root-relative rule. A `<script>` the model writes reaches the page as text. No raw HTML is passed through, and `PersonalAdvisor.jsx` itself holds no `dangerouslySetInnerHTML`. User messages and tool messages render as before.
- An Explain press on the active question (the topic is that question's prompt or id) sends `question_id`, `question_type` and `options` with the topic (`explainRequestBody`). A typed "explain X" about something else stays a free-form topic.
- The `/explain` handler takes the bank question the press named. `services/advisor/explainPrompt.ts` appends a section to the system prompt that lists that question's options, one per line, says to describe only those, and says to end with a Markdown link to the page that holds the field (`page_target`, root-relative only). A question with no fixed choices says so, so the model cannot invent some.
- **The bank is the authority, not the body.** The options the client sends can narrow the list to ones the bank lists, never add one. A client that sends Custom gets the bank's list.
- **Eligibility matches `/answer`.** The press now sends the id on every question, so `/explain` accepts the same ids `/answer` does: a visible one, a role detector, an answered one being re-asked, or a dynamic reflection. Any other id is still refused 409 `question_not_available`, and no model runs.
- Out of scope, as the issue says: a new model or prompt library.

### Tests

`frontend/test/eadwyn_markdown_9286.test.mjs` (bold and bullets render, `<script>` stays text, the Explain body, the wiring) and `cloudflare-worker/test/advisor_explain_options_9286.test.ts` (the real route on the full schema with the model stubbed: the prompt lists only the question's options and its page; a topic-only explain lists none; a hidden id is refused).
