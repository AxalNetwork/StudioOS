## D4592 — Fair eligible-work discovery for the agent sweep (#4592)

The five-minute agent sweep (`UTC minute % 5 === 1`) keeps the existing
`AgentRuntime.admit` path as the sole authority for admission. Discovery now
finds an agent's highest-priority task that is actually ready before applying
its bound: it excludes non-open/backlog tasks, unfinished dependencies and
agents with an admitted or running run. The runtime then repeats the engine,
halt, scope, financial, sponsor and single-flight checks immediately before a
run row is written. Discovery never grants authority.

The scan is a bounded keyset rotation over agent ids. Its cursor is a
best-effort persistent `RATE_LIMITS` KV value, scoped to this Worker
environment. A lost, malformed or unreadable cursor starts at zero; that is
safe because unready work is filtered in SQL rather than after the bound. Once
the cursor reaches the end it wraps. A scan examines at most 120 eligible
agent/task candidates, admits at most 60 new runs, and takes no more than four
candidates from one scope. Therefore a scope that is full, paused or otherwise
refused cannot consume an entire scan, and later eligible scopes make progress
within a complete rotation when capacity exists. Concurrent sweeps may inspect
the same candidate after a cursor race, but the existing scope writer and D1
single-flight index permit only one live run; a cursor write lost with a Worker
restart merely repeats safe discovery on the next rotation.

The previous task lookup stopped at the first 20 tasks before checking their
dependencies. The new query ranks only ready tasks, so a ready lower-priority
task is found even when more than 20 higher-priority tasks are blocked. It
uses the existing task-assignee/status index and dependency primary-key lookup;
the work remains bounded by the candidate and admission caps. The local
synthetic regression covers 61 agents, 21 blocked higher-priority tasks, a hot
scope plus a cold scope, cursor loss and duplicate sweeps. It is a source-level
contract, not a production throughput measurement.

Queue repair is a separate bounded lane: at most 20 stale admitted runs are
resent per sweep, while new-work admission retains all 60 opportunities. A
redelivery remains idempotent and an enqueue failure keeps the admitted row for
the resend path. No queue, scheduler, runtime, ledger or authorization system
is introduced.

The sweep records only low-cardinality aggregate counts in the existing
`system_metrics` telemetry store: candidates examined, eligible, admitted,
refused, resent, and oldest eligible-work age when known. Labels carry only
the cadence and whether a scan wrapped. They never include tenant, agent,
task, prompt, output or source content. #4559 owns the platform metric
dictionary and presentation; this change does not add a monitoring system.

No deployment, production D1 operation, provider enablement, autonomous-mode
switch or hosted capacity claim is part of this decision. Hosted validation
continues to depend on #4566's isolated preflight and owner approval.
