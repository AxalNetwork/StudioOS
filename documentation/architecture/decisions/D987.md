- **One failing never blanks another.** A failed block reads "… could not be read. That is not the same as none." with Try again; the rest of the page draws.
- **When the requests fail:**
  - the tab's count is a dash;
  - the grid says a requested program shows as not granted until they are read.
- **An unknown figure is never 0.**
  - Requests waiting is Unreadable when D982 could not read it.
  - Ending in 90 days, when null, reads "Not recorded".
  - A term nobody set reads "Not recorded".
  - A studio with no fee and currency recorded reads "Not recorded" for fees.
- **In use (GR3) reads "Not recorded · This studio has not reported program figures yet."** Nothing reports the studios' program figures until #3061.

### 3. The writes

Every write opens an in-page dialog, says what it changes, and needs a reason of 10 characters or more (D982's rule). The authenticator code is the app's step-up (`StepUpModal`): a write the Worker refuses with `step_up_required` asks for the code and is sent once more. Each dialog says "Saving asks for your authenticator code." A refusal is said in the Worker's own words, inside the dialog, and nothing is claimed done.

| Act | From | Route |
|---|---|---|
| Grant, Finish grant | Grid's + Grant, GR3's row, GR5's Finish grant (GR4 → GR10a review) | `POST …/licences/:uid/:program` `{terms, note, reason}` |
| Change terms | GR3's row (GR4 in change mode) | `PATCH …/licences/:uid/:program`, only the terms that changed |
| Pause, Resume, End | GR3's row (GR10b, GR10c) | `POST …/pause`, `/resume`, `/end` `{reason}` |
| Send schedule | GR3's row and Schedule column (D1120) | `POST …/schedule/send` `{reason}` |
| Approve, Decline | GR5's and GR3's Answer (GR5d) | D983's `approve`, `decline` `{reason}` |
| Can be granted | GR6's switch | `PUT …/defaults/:program` `{grantable, reason}` |
| Edit defaults | GR6's card | `PUT …/defaults/:program` `{terms, reason}`, only what changed |
| Partner deal types | GR3's switches | D986's `PUT` `{types, reason}` |

- **The lightbox (GR4) marks each term Default or Changed** against the program's defaults, with Reset to default. A term with no default (the dates) reads "Set for each grant".
- **The live sentence** is written from the form as it stands, for example: "Studio Lisbon may run Learning from 1 Nov 2026 to the end of its licence, paying HQ €2,000 a year. It starts when the program schedule is signed."
- **Review (GR10a) lists the terms that differ from the default** before anything is sent.
- **Units.** Money and shares are typed in units; the Worker stores cents and basis points.
- **A suspended licence freezes Grant, Change terms, Resume and Send schedule** (D982 refuses them as `licence_frozen`). The page says so and disables them; Pause and End stay open, as the Worker allows.
- **Finish grant** starts the lightbox from the draft's terms. It needs the grid's read for the licence and the defaults; without it, the row offers Open.
- **On a draft, Pause and End are not offered,** because the Worker refuses them there.

### 4. Where the page says less than the canvas, and why

- **"Ask for more" (GR5d) is not drawn.** No Worker route records it. Approve and Decline are D983's two answers. Approving a grant request records a draft; the program is granted when HQ finishes it.
- **GR5's "↳ From a proposal" is not drawn.** The requests read carries a lane (`hq` or `branch`), not a proposal. A branch's request shows "↳ From a branch · <code>".
- **Requests by month splits by outcome:** Approved, Declined, Withdrawn and Still waiting. The store has no split between default and changed terms, which the canvas draws.
- **The grid adds two states the canvas lacks.**
  - "✓ Granted · waiting on …" is a grant not in force yet (D982's `waiting_on`).
  - "✎ Draft · to finish" is an approved draft.
- **The grid's studio line shows its kind, status and reference.** The grid read carries no renewal date; one studio's page shows it.
- **The build-status pills (✓ Live, ◐ Partly built) are not drawn** on the defaults cards. No read carries a program's build status. A not-ready program's switch is off and locked, with D982's `locked_reason`. An HQ-only program's switch is off and locked, because D982 refuses `grantable: true` there.
- **The header's "Grant a program" and "⋯" (0.2) are not drawn.** A grant opens from its cell or row, where the studio and program are already known.
- **Signing is not a page act.** D1120 records it when the envelope is signed, and the Schedule column then reads Signed with its date.
