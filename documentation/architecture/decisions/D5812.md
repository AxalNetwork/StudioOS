### 1. Why

The packaged factory (`meeting-bot/src/runtimeAdapters.ts`) built `TeamsAdapter` on a raw Playwright page cast `as unknown as TeamsPage`. A Playwright `Page` has no `query(selector, attrs)` and no `onAudio`, so every Teams run threw at its first read and ended as `platform_blocked`. No Playwright-backed `TeamsPage` existed; only the test fake implemented it.

### 2. What was decided

1. **A real driver, `meeting-bot/src/adapters/teams/page.ts`** (`playwrightTeamsPage`). It implements the existing `TeamsPage` interface over the subset of Playwright's `Page` it calls (`TeamsBrowserPage`), so the core keeps no Playwright dependency and the factory passes the page without any cast.
   - `query` returns each **visible** match with only the named attributes (`getAttribute`, null when missing). The driver never reads an element's text; asked for `textContent` by name it returns null. A test greps the Teams driver, adapter and selectors for any text-reading call.
   - `click` / `fill` fail at once when the page shows no match (the adapter's next read decides what to do) and are otherwise bounded by `ACTION_TIMEOUT_MS` (5 s), so no step waits on Playwright's 30 s default.
2. **One capture routine for Meet and Teams.** `CAPTURE_SCRIPT`, `CAPTURE_BINDING` and `decodeBlock` moved from `adapters/meet/capture.ts` to `adapters/capture.ts`; the Meet file re-exports them, so Meet's imports and behaviour are unchanged.
3. **Audio is forwarded only after admission AND the notice.** The adapter calls the new optional `TeamsPage.startCapture()` when it first reads the in-call screen in `admitted()`. The driver turns the page's capture switch on, and forwards a block, only while it is admitted **and** has a subscribed listener; the core subscribes to audio only after the notice is posted (B2). So: nothing is captured in the lobby; a notice that fails leaves the switch off and nothing is uploaded or stored; the last listener leaving turns the switch off; a block that reaches Node early is dropped there.
4. **Allowlisted stages.** `TeamsAdapter.diagnostic()` returns the last join screen it read as `teams_<screen>`, only from the fixed `TEAMS_STAGES` list (the `TeamsScreen` names), so a refused run reports `platform_blocked@teams_captcha`, `…@teams_anonymous_blocked` or `…@teams_bot_blocked`, and an unanswered lobby `not_admitted@teams_lobby`. Each fits the Worker's `BOT_FAILURE_DETAIL` shape; no page text is ever in it. Part 3 derives the member-safe `blocked` reason from these.
5. **An orderly leave.** The factory's leave used to start the adapter's hang-up and `browser.close()` together, so the close could win and the bot vanished without hanging up. It now runs the adapter's leave first, bounded by `LEAVE_MS` (3 s), then closes the browser whatever happened. The lifecycle's own 5 s leave bound is unchanged. This applies to Meet's packaged leave too (it clicks Leave before the close as well).

### 3. Headless or headed: measured, and what is still open

Measured on 2026-11-27 with the fixture and the driver, Chromium 153.0.8010.12 (Chrome for Testing), the factory's launch arguments, two runs each:

| Mode | Launch | `HeadlessChrome` in the user agent | `navigator.webdriver` | Captured audio |
|---|---|---|---|---|
| headless (`headless: true`) | 192–376 ms | **yes** | true | 43,691–43,705 samples/s at 44.1 kHz, tone peak 1.0 |
| headed under Xvfb 1280×720 | 278–1005 ms | no | true | 43,691 samples/s at 44.1 kHz, tone peak 1.0 |

Both modes run the whole driver and capture audio identically. The difference that matters is detection: headless Chromium names itself `HeadlessChrome` in its user agent, which a tenant's `BlockDetectedBots` or Teams' "Suspected threats" check may key on. Whether Teams actually refuses it cannot be measured without a Teams tenant. **Decision: the factory keeps `headless: true`** (unchanged, the same launch as Meet). Part 5's live check (D1451 Q2 = B trial tenant) records whether headless is refused. If it is, the factory launches Teams headed, on the `DISPLAY=:99` Xvfb that `container-entry.sh` already starts for Zoom, which is a one-line change to the Teams launch. Not guessed ahead of that check.
