## D636 — Brand: the site address and saved templates; the watchlist item and journal entry pages

**Two screens of the Ops canvas's area 8 (#1165), built into the pages that
already serve their addresses.** M4 (`sp-brand`) adds the startup's address,
each page's own address and the saved templates to `/spinout-lab/brand`. M6
(`sp-watchlist`) adds `/watchlist/:uid`: one watchlist item and the journal
entries about it. Slot S10, issue #1394, 2026-10-07. Migration 426.

### What was on `main`

- **Brand.** `routes/brand.ts` already served the site address
  (`GET`/`PUT /site/by-project/:pid`), a page-address check
  (`GET …/page-slug-available`) and saved templates (`/custom-templates`, at
  most 50 a founder). `api.js` had a client method for each. **No screen
  called any of them.** The refusals were bare strings ("That slug is
  reserved.", "Template limit reached (50) — delete one first."), nothing
  recorded who changed an address or saved a template, and nothing recorded
  which project a template came from.
- **Watchlist.** `GET /watchlist/:uid` and the journal existed, but no page
  showed one item, and the journal could not be listed by item. The item did
  not return `passed_at`. No screen showed D618's edit mark.

### M4 — the address (Worker first)

- **The site address** (`PUT /site/by-project/:pid`) now refuses through
  `refuse()`, a code and a sentence each:
  - `address_invalid`: "An address is 1 to 48 lowercase letters, digits and
    hyphens, with no hyphen at either end.";
  - `address_reserved`: "That address is reserved. Choose another.";
  - `address_taken` (409): "That address is already taken."

  These are exported as `SITE_ADDRESS_REFUSALS`. A change writes
  `activity_logs` `brand_site_address_change` with the project and both
  addresses. Saving the same address again records nothing.
- **A page's own address** gets its own route,
  `PUT /landing/pages/:id/address`, because the page `PUT` rewrites every field
  it is sent. It changes `page_slug` and nothing else, with the same three
  verdicts as the availability check (`PAGE_ADDRESS_REFUSALS`), and records
  `brand_page_address_change`.
- **The screen** (`components/brand/BrandAddressPanel.jsx`):
  - `axal.vc/p/[slug]` with Edit;
  - the canvas's rule and the warning "Old links stop working after a change.";
  - a malformed or reserved address is refused before sending, with the
    Worker's own sentence, and a taken one shows the Worker's refusal;
  - under it, each page's address, checked against the Worker as you type,
    and savable only when it reads Available. A check that failed reads "Not
    checked", never Available.

### M4 — saved templates

- **Migration 426** adds `brand_custom_templates.source_project_id`, written
  from the page being saved. The list returns `project: { id, name }`, and
  `null` for a template saved before the migration, which the screen states as
  not recorded rather than guessing a project. Nothing is backfilled.
- **The 51st** is a 409 `template_limit_reached`: "You have 50 saved templates,
  the most allowed across all your projects. Delete one before saving
  another." The other refusals are sentences too (`template_name_required`,
  `page_required`, `page_not_found`, `forbidden`, `template_not_found`).
- **Save and delete record their actor** (`brand_template_save`,
  `brand_template_delete`) with the template's project.
- **The screen** (`components/brand/SavedTemplatesPanel.jsx`):
  - "[n] of 50 · across all your projects";
  - each template's name, project and date, with "Use for a new page" (the
    existing `from_custom_template_id` on page create) and Delete, which asks
    first;
  - "Save as template" on any page of this project. At 50 the form shows the
    Worker's sentence and does not send.

### M6 — the watchlist item and its journal entries

- **Worker.** The item returns `passed_at`. `GET /journal?watchlist_uid=`
  lists the entries about one item. The owner filter still applies, so an
  investor reads only their own.
- **The screen** (`pages/WatchlistItemPage.jsx`, `/watchlist/:uid`, the same
  guard as `/watchlist`; each Watchlist row's company name links to it):
  - the company, sector, stage and date added;
  - thesis, conviction (Low, Medium, High), source, tags, status, next check,
    and how it ended: "Converted to a deal" or "Passed · [reason]", with the
    date;
  - each journal entry: Invest, Pass or Defer, conviction out of 5, thesis,
    risks, "[outcome] · [3×] · [5 years]", then the outcome (Hit, Miss,
    Partial, Inconclusive) with notes and the actual multiple;
  - **"Edited after the outcome"** when D618's `edited_after_outcome_at` is
    set, and never otherwise.
- **Writes.** "Write an entry" and "Record outcome" use the journal's own
  routes, through the Journal tab's forms (now exported). Watchlist and journal
  rows are owner-only, and `owner_user_id` is the actor, so no further record
  is added.

### States

Every read has four states: loading, empty with its line, a field Not recorded
with its one-line reason, and Unreadable with Try again. A failed read never
draws an empty list or a blank address. No screen is drawn at phone width; the
board marks neither as phone.
