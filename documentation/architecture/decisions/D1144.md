## D1144 — Stored Product-market fit scorecards, history and Re-score (#3030)

S30 · 2026-10-25. Part 3 of #2433; D1143 is the one PMF engine. Migration 598.

### Store and shared contract

`scoring_model_versions` identifies an immutable definition by `(scope, version)`.
It stores the model JSON, publication day and optional publisher. Code seeds PMF
v1 as the system; it invents no publishing person. A conflicting definition for
the same version refuses computation.

`venture_scorecards` is SCORING's shared per-venture, per-scope history. It holds
an id/uid, value (nullable), band, confidence and coverage fractions, inputs JSON,
inputs hash, model version, trigger, computing user and timestamp. Its foreign
key names the scope and model version. PMF is the first scope; no investor read,
other scoring scope or platform-wide total is added.

The JSON preserves the collected facts, the exact engine result (including input
rows, confidence word, coverage counts and next steps), and the Pivot boundary.
It contains no interviewee name, quote, buyer, customer or email. The snapshot
is signed with `signHmac` and the existing domain-separated scoring key, over
its venture, scope, uid, inputs/result, scalar values and computation metadata.
Reads verify signatures and refuse tampering. No signing secret or signature is
returned to the browser. There is no new secret to provision.

### When a result is written

The hash canonicalises the code's model definition, collected inputs, Pivot day
and effective freshness flags. Request time, actor, trigger and the displayed
Verdict are not score inputs. A later day alone creates no row; crossing a
freshness boundary does. An input edit that leaves the number unchanged still
creates its own point. A → B → A creates three points, not two.

An atomic conditional insert compares with the latest hash inside the write,
not only before it. Two identical concurrent collectors create one snapshot.
The same batch seeds all eight checklist items, inserts the PMF checklist score
and records `pmf_recomputed`. Each dependent write names this request's unique
snapshot uid; a deduplicated request creates no extra checklist or audit row.
A failed batch leaves none of those writes behind.

The audit contains only model version, trigger and inputs hash. The actor and
venture use the normal cycle activity columns. Module and Re-score requests
read the real operator from the verified token during impersonation. It logs no score, input text or
figure. History never rewrites earlier points.

### Routes and client

- `GET /api/cycles/raise/modules/fundraising-readiness?project=` computes from
  the venture's stores and returns `parts.pmf`: the exact PMF result plus its
  snapshot id/hash, computed time/user, trigger, changed flag, Pivot and current
  Verdict. It runs before the card/records read, so they see the same checklist
  update. Failure gives an Unreadable PMF part and leaves the other module
  blocks available.
- `GET /api/cycles/raise/pmf/history?project=&limit=&before=` reads stored points
  only. Default 200, maximum 500; a page is oldest first, with `has_more` and
  `next_cursor` (the oldest id to pass as `before`). Each point has value/band,
  confidence/word, coverage counts, model, trigger and computation time.
- `POST /api/cycles/raise/readiness/rescore?project=` accepts `pmf: true`.
  `items: ['pmf']` runs only PMF, independently of the legacy checks. With no
  items, it also runs the six existing computed checks. Team stays manual.
  An unchanged PMF returns `changed: false` and adds zero to `scored`.
  A non-boolean flag, manual PMF score or PMF item without its flag is refused.
- PMF's existing record action sends the flag. The history client is
  `cycleWrites.raise.pmfHistory`; it whitelists `limit` and `before`, so the
  page options cannot replace its venture.

All routes use Raise's existing founder/admin `canWrite` project gate. No
partner, investor or different venture's founder gains access. History failures
are 503, not an empty successful series. Errors expose fixed sentences only.
All SQL is bound. No provider or AI call is introduced.

### Checklist item 8

`pmf`, Product-market fit, is eighth. Its score is value ÷ 10 (fractional values
are retained) only at Medium or High confidence; otherwise score and evidence
are null, the item says Not scored, and the existing mean leaves it out. A
recorded zero at Medium counts. Eligibility uses the engine's confidence word,
so a Low result rounded numerically to 0.45 does not qualify. This is a computed
check; the detailed input grades and confidence remain on the PMF result.
