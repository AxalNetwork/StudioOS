## D616 — Five dead client methods are removed

**Five methods in `frontend/src/lib/api.js` that nothing calls are gone.** Issue #1316. Frontend only. No migration. The dev FastAPI is untouched.

**What went, and why.**

- `emailSendDeal` called `POST /api/email/send-deal`, which has no Worker route, so production answered 404. The deal room's invite already sends that email. The line is also gone from `scripts/api-drift-baseline.json`.
- `adminVoidContract` posted a void with no reason, so the route always refused it with a 400. `adminVoidContractWithReason` is the method in use.
- `fundLPs` called the same route as `fundsLpsList`, which five screens use.
- `fundsListByStatus` was `fundsList` with a status filter, and nothing filtered.
- `trustSanctions` was the twin of `trustListSanctions`, which `/trust` uses.

**What stays.** `fundGet` on the research fund read, which is in use, and `fundsGet`, which the fund page in the area 6 design will read.

**#1165's count.** That audit counted 1,412 methods and **155 uncalled ones that have a mounted Worker route**. `emailSendDeal` was not in the 155, because it had no route. The other four were. Removing them leaves **151** uncalled methods that still have a route. No test pinned any of the five names, so none was rewritten for that reason. `frontend/test/dead_client_methods_d616.test.mjs` is the new pin.
