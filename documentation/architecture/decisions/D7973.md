## D7973 — Inactive authenticated CI capacity transport (#7973)

Part of #7909. This preparation adds an **unbound** `CapacityControl` Durable
Object, GitHub adapters, authenticated planner/receipt transport, and a durable
check outbox around the existing D7887 coordinator. It does not deploy an
object, bind a namespace, change the existing Merge Control ingress, grant App
permissions, set variables, enable an executor, or change a required check.
Neither `ci.yml` nor the legacy MacBook caller nor required-check consumers is
edited. The existing six hosted shards remain responsible for their checks.

### Authentication and receipt handoff

The new, uncalled reusable `capacity-planner.yml` defaults off under
`CI_CAPACITY_ENABLED`. It must be invoked by the original CI workflow at a
reviewed full SHA. It obtains its own reusable-workflow revision from the
reserved GitHub OIDC endpoint, checks out that revision as control code, and
reads candidate files only as data. No candidate dependency scripts run there.
It validates exact-once plan coverage and the original event payload; push
plans come from the exact parent's artifact, and queue plans use equal weights.
It submits once and exits; it never waits for external test execution.

The authority verifies RS256 against the fixed GitHub issuer's bounded JWKS,
audience, expiry/not-before/issued-at, repository ID, ref subject, original CI
workflow/run/attempt/source, and pinned `job_workflow_ref` plus
`job_workflow_sha`. The exact plan bytes bind their SHA256 digest. An ordinary
candidate job token cannot impersonate the pinned reusable planner. The ports
independently verify the parent attempt, plan artifact metadata, executor main
ancestry and complete queue constituent graph with same-repository PR heads.

`createReceiptReader({url,audience,oidcToken,fetcher})` returns the existing
`readReceipt({request,context,phase,signal})` port. Request lookup fields are
`requestId`, `generation`, `shard`, `profile`. Identity comes from a fresh signed
OIDC token, never the lookup body. Only an exact direct main executor run at the
configured revision can retrieve its currently owned, unexpired generation.
The existing admission code independently checks all receipt fields, GitHub
metadata, plan/runtime and isolation. The reader returns `{active:true,receipt}`
or throws; an inactive/unknown authority never approves execution.

The contract and single-editor handoff were posted on #7972. S09 keeps all
shared edits to `runner-admission.mjs`, `runner-execution.mjs`,
`runner-executor.yml` and isolation. This PR tests the reader through their
existing injection port and does not alter those files. Until that separate
reviewed injection lands, the production CLI's default denial stays intact.
Caller ownership was also recorded on #6677; #7882's legacy caller is untouched.

### Bounded durable effects

The object serializes ingress, switches, alarms and effects. It persists an
alarm **before** accepting a submission, and rearms before reconciliation.
The core persists dispatch/cancellation intents and generation fences before
network effects. A dispatch response may identify the new run; otherwise exact
workflow/title/revision discovery recovers it without repeating an ambiguous
POST. Observation checks the owning run, attempt, job, target labels and actual
test step. Infrastructure fallback requires verified termination with no test
failure; missing/unknown/cancellation uncertainty remains fenced. Old-generation
failures remain sticky. Inventory reads only approved group 5, selected repo and
direct main executor allowlist plus GitHub OS/label agreement; incomplete or unreadable inventory falls back
to standard hosted allocation before delegation. Group 6 remains a separate
capped included-compute profile in the existing core.

`CAPACITY_ENABLED` must equal `true` **and** the durable independent capacity
kill switch must be explicitly false. Both default off. Revocation denies all
receipts/new dispatches immediately; alarms continue observing/cancelling owned
children. This switch is independent of existing Merge Control cancellation and
claim behavior. Owner routes require a separate capacity owner token, which is
never passed to Actions jobs. No configured namespace or public route exists yet.

Reconciliation and publication use separate bounded App clients so retained
publication history cannot consume execution reconciliation’s budget. Outbox
passes handle at most four records, prioritize unfinished publications, persist
a fair cursor and prune intents after their requests leave retention.
GitHub operations have a 100-request/60-second client budget, 10-second request
and body-read limits, a 2 MiB API body cap, and at most three 100-row pages with
stable totals and duplicate rejection. JWT/key, request and response bodies have
separate bounds. Ingress limits authenticated attempts before key retrieval to
120 per minute per repository object. API errors and rate limits cannot grant
receipts or success. Publication intents are durable before check creation;
restart discovers an ambiguous create by exact App/check/external identity.
Only acknowledged check IDs receive idempotent updates. No ambiguous create is
repeated. Missing discovery can require operator diagnosis; it never becomes
success. The core retains its existing request/retention and identity fences.

### Publication authority

`ci-capacity/worker-pilot` means the six Worker shards plus configured
prerequisites only. It never substitutes for `ci-capacity/full-suite`.
Full-suite mode also requires the two frontend shards, rest and every configured
prerequisite, with exact parent attempt/source and unique complete job evidence.
Missing/unknown results remain pending, cancellations remain non-success, and
verified failures persist in the outbox across retries/restarts. Before success
publication the parent is independently rechecked. A superseded parent attempt
cannot create a newer check. Publication is not added to any required ruleset.

### Parent-owned deployment boundary

#7909 must supply reviewed configuration (repository/App IDs, pinned main
executor/planner SHA, prerequisite/full-suite job manifests, pool caps and
publication mode), a separate namespace/migration/ingress, App permission review,
owner secret/audience, executor OIDC injection and live recovery proof. The
adapter's token request declares the permissions it will need; this PR does not
install or grant them. Current main must still equal the pinned executor revision
at dispatch; drift refuses dispatch rather than silently executing another revision.
S09's actual-node isolation proof and #7888's bounded hosted-capacity evidence
remain separate acceptance. No live activation, fleet change or cutover is
implied by local fixture success.

### Validation and review

Local fixtures exercise signed OIDC through the object, SQLite restart, real
GitHub ports, existing executor admission and authoritative outbox publication.
They cover invalid provenance/signature/audience/expiry, duplicates, generation
and child mismatch, expiration/revocation, uncertain dispatch/publication,
cancellation uncertainty, complete/incomplete queue graphs, forks, infrastructure
fallback, old failures and full-suite prerequisites. Existing core recovery
fixtures remain part of `test:merge-control`.

Exact validation/mutation results and remaining independent review are recorded
on the PR. Local Node/SQLite platform shims prove policy/integration behavior;
they are not a Workers runtime deployment or live canary.

### Review repair: mixed inventory and Linux milestone

The focused review on #7981 reproduced a valid Linux runner being suppressed by
an ineligible Mac in the same approved group. Inventory now validates the whole
response's IDs, OS, status, busy flag and bounded label shapes, rejects malformed
or contradictory evidence, and ignores well-formed unsupported members. The
required `selfHostedProfiles: ['linux-x64']` configuration makes this milestone's
Mac exclusion explicit, even for a Mac with the shared capability label. A
broadened/missing profile policy is refused. Dispatch and receipt issuance also
refuse a disabled Mac profile. No labels or live group settings are changed.

S09 confirmed the reader/profile contract and composed the reader with
`resolveCatalogProfile` in its `executor-authority.mjs` at `48f3e090`. Its
configuration uses `CI_CAPACITY_URL` and `CI_CAPACITY_AUDIENCE` (repository variables);
S09 supplies phase-appropriate readiness and live isolation verifiers at
admission, verify-plan, run and live re-admission. No competing production
composition helper is introduced by this PR. Hosted receipts still refer only to coordinator-owned children; this
factory does not authorize or alter existing standard-hosted CI. No OIDC or
control-plane capability is passed through the candidate's environment.

The composed local fixture exercises actual admission, verify-plan and run
CLIs, catalog, `verifiedPlan`, `verifyRuntime` and `executeShard` with a mocked
trusted Linux boundary. An isolated two-PR overlay additionally loads S09's
actual authority/container entrypoints when that module is present. It tests successful publication, genuine test failure, incomplete
observations, revoked authority and denied isolation. Runtime facts and candidate
execution are explicit test doubles; this is not S09's actual-node proof, nor a
claim that its separate draft entrypoint injection has landed. S09 remains the
single editor for that injection and its receipt/profile acknowledgement has been received;
independent different-vendor review remains required.
