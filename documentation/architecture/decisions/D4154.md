- **Basis:** `origin/main` at the time of the branch. **Migration:** none.

### 1. What the Worker already does

`GET /api/calendar/events` takes `scope=studio|all` (D1206, `fetchCalendarScope`):
- Studio needs an admin on a studio deployment. HQ answers it as "not configured", because HQ has no member-to-licence association.
- `all` (Platform) needs the Super Admin on HQ.
- Every scoped item is `read_only` with `can` all false, and every email is nulled.
- The reply carries `coverage`: complete or not, and which studio did not answer.
- Each read is logged in the admin audit.

No screen sent `scope` until now.

### 2. What this build draws

| Board | Drawn from |
|---|---|
| **CA1 switcher** | `scopesFor(user)`, mirroring the route: a member has no switcher; an admin on a studio has Mine · Studio; the Super Admin on HQ has Mine · Platform. The scope is the address (`?scope=studio`, `?scope=platform`); a scope the viewer does not have falls back to Mine. The chip reads "Viewing: Studio · <studio name>" or "Viewing: Platform". |
| **CA2 Studio, CA3b Platform agenda** | The scoped read, grouped by day with each day's count. Each row has its time, type, title, owner (from the people the route sends), company and project. The filters are project, type (Meeting, Deadline, Compliance, Learning, Event) and a person by name. |
| **CA3 month** | Counts per day over the read. When the read was incomplete, an empty day reads "Not recorded", never "0 items". |
| **CA4 item detail** | Read only: what, when, who by name, and where it lives. "Changes are made in the company it belongs to." |
| **CA5 states** | Loading; "The calendar could not be read. That is not the same as nothing being booked. · Try again"; an empty scope that says whether every company answered; phone (agenda only). |

The personal calendar is unchanged and is never drawn in a staff scope. No New, RSVP, reschedule, cancel or push appears there.

`api.listCalendarEvents` gains an optional `scope`, for the route that is already mounted.
