## D5334 — One evaluation unit, regression scope and primary taxonomy rule (#5334)

Three audit findings distorted the Skill Library board: the twelve shipped starter cases also existed as seeded live cases and were paid twice; the alert compared a current failure with a pass from any version although the board used one version; and the library and HQ lists disagreed about which tag supplied area and level.

Published evaluation now runs once per distinct checked input-and-expectation content. A display name remains part of `caseSha` for immutable history and candidate/baseline attribution, while `caseContentSha` deliberately normalizes only that display name for execution deduplication. If a live row carries the shipped starter's content, the live identity wins and the `starter` unit is skipped; a changed input or expectation still runs. No historical row is edited or deleted. The board maps current case keys to the same content fingerprint before choosing the latest result per model, so historical starter/live rows count as one current content unit.

A pass-to-fail alert now reads its prior non-`not_run` result only within the same skill version, case key and model. A failure on a new version is a candidate-versus-baseline difference in the existing compare read, not a regression alert for a version that never passed. Same-version pass then fail and the existing alert-window dedupe are unchanged.

`areaOf` is the one exported primary-taxonomy rule used by the library source view and HQ store view: scan tags in order, choose the first whose category is a radar axis, and use that tag's own level. The seed's checked draft uses the same helper. No total catalogue size is pinned by this consistency rule.

Regression tests run an identical live/starter case once per model, retain a different-content case, count the board by content, distinguish v1→v2 comparison from v2 regression alerting, and compare source, seeded draft and HQ list area/level for every committed definition. Each of the three former behaviors was mutation-checked. No paid model, production record, result rewrite, publication or migration is involved.
