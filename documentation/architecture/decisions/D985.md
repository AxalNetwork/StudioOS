## D985 — Program grants part 4: a branch runs only the programs its licence holds (#2777)

- **Status:** built by S26, 2026-10-25 (#2777, part 4 of #2376, under D981).
- **Migration:** none. It reads the copy part 3 added (D984, migration 554).
- **Basis:** part 1's rule for a grant's dates (D982, `presentGrant`). Part 3's dated copy on the branch, `branch_licence.program_grants_json` (D984 §2). The freeze, `requireBranchNotSuspended` (D107).
- **Worker only.** No screen changes. A refusal's `detail` is the sentence the existing dialogs already show.

### 1. The helper

`programRefusal(env, key, today?)` in `cloudflare-worker/src/services/programEnforcement.ts`. It returns null when the write may run, or a refusal `{ status, body }` that the route sends with `c.json(body, status)`. It is a service, so it never builds a Response itself.

- **On HQ it returns null without reading anything.** A grant limits what a branch runs. It never limits an Administrator on HQ-held accounts (D981 §5, decision 1, read from GR11 C, which D984 §3 also rests on; the owner may correct it).
- **On a branch it reads one row:** the licence's uid, ref, brand, kind, status and renewal date, and the programs copy. Then it works out the program's standing on the branch's own day, by part 1's rule, the same rule D984's read uses.

| Standing | When | Answer |
|---|---|---|
| `held` | Granted, and inside its dates | null: the write runs |
| `not_held` | No row, a draft (D956), or a state this code does not know | 403 "This studio's licence does not hold [Program]. Ask HQ for it from the licence page." |
| `switched_off` | No row (or a draft), and HQ has the program switched off | 403 "HQ does not grant [Program] at the moment, so this studio cannot start anything in it." |
| `paused` | HQ paused the grant | 403 "HQ has paused [Program] for this studio. Nothing new starts until HQ resumes it." |
| `ended` | HQ ended the grant | 403 "HQ has ended this studio's grant of [Program]. Ask HQ from the licence page to run it again." |
| `not_started` | `starts_on` is after today | 403 "This studio's grant of [Program] has not started yet. It starts on the date HQ set." |
| `period_over` | `ends_on`, or the licence's renewal date when the grant ends with the licence, is before today | 403 "This studio's grant of [Program] has run past its end date. Ask HQ from the licence page to extend it." |

- **Each 403 body** is `{ detail, code: 'program_not_granted', program_key, standing }`. The program is named by its registry name (`programOf(key).name`), so a renamed program is renamed in the refusal too.
- **A copy the branch cannot parse is a 503** `program_grants_unreadable`: "Your programs could not be read, so [Program] cannot start anything new. That is not the same as not granted." HQ sent something, and the branch cannot say the program is held.
- **No copy refuses nothing.** That covers no `branch_licence` row, a row with `program_grants_json` still SQL NULL, and a table this deployment cannot read. This is the freeze's posture (D107): a grant is a claim HQ makes. Reading "not granted" from a copy HQ has not written would stop every branch's programs between this deploy and HQ's next push.

### 2. What it does not refuse, and why

- **A grant still waiting on its signed schedule, or on the licence becoming active.** The issue's rule is "does not hold the grant, or holds it paused". A granted program whose schedule is unsigned is held. The schedule is HQ's paperwork with the studio, and part 1 shows it as Granted, not in force yet. A licence that is not active is the freeze's job: suspended answers 423 before this gate runs. **This is a reading for the owner (§5, question 1).**
- **Anything that winds down or annotates.** Each one is a takedown or the end of something already running, and a paused grant means "nothing new starts", not "nothing may stop":
  - rejecting or waitlisting an applicant;
  - cancelling an interview;
  - a running cohort's grace and overrides, and cohort size settings;
  - rejecting or revoking a host;
  - revoking a certificate;
  - ending a mentor's access;
  - declining strategic access;
  - review notes, rejection, closing and paying a reward already earned on a referral;
  - rejecting or pausing a perk listing, or editing one that is already live.

### 3. Where it stands

Every call site comes after the route's own admin gate and after `requireBranchNotSuspended`. So an anonymous caller gets 401, a non-admin gets 401 or 403 without learning the grant, and a suspended branch gets 423.

| Spin-Out Lab | `admin_cohort.ts` | `/applications/:id/interview`, `/applications/cycles/:id/force-proceed` | always |

**Not gated, and why:**

- **Learning.** Its admin writes (`admin_learning_programs.ts`) are Super Admin only, and `requireSuperAdmin` refuses on a branch (`HQ_ONLY`). There is no branch write to gate.
- **Referral partners.** No branch admin write exists for it yet.
- **Product testing, AI-native Venture and Investor cohort access.** These are HQ's or not ready (D981 §3).
- **`ENFORCED_PROGRAMS`** lists the four a route may name.

### 5. For the owner

1. **Does "holds the grant" mean in force?** This part refuses only when the program is not held, paused, ended or outside its dates. A granted program whose schedule is unsigned still runs. To refuse it too, `standingOf` would return a refusal for `waiting_on` containing `schedule_signed`. That is one line, plus a sentence.
2. **A Lab host's approval, the certificate backfill and the cohort interview are treated as new starts.** Cohort size settings are not.
