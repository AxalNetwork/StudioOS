## D1015 — The Cap table tool: its tabs inside the Raise module page, the blocks four existing reads carry, and On record kept apart from Modelled (#2432)

- **Status:** decided and built by S21, 2026-10-24 (#2432, under #2711).
- **Canvas:** the owner's "Cap table", CT1–CT24 with lettered boards (artifacts `NtjTWkVfbEYkZ4xWk8n35Q`, the board grid, and `Lxsy595iChD3Cmwh8j4qGi`, the page). It is committed as `design/incoming/Cap Table · Boards.dc.html` and `Raise Cap Table Page.dc.html`.
- **Basis:** `origin/main` at `fd02f60e59`. The map is `documentation/audits/CAP_TABLE_MAP_2026-10-24.md`.
- **Migration:** none here. Parts 2, 4 and 5 take 573, 575 and 574.
- **Why:** the owner asked for a Cap table tool at `/raise/cap-table` and for the old Capital tab at `/raise/capital/cap-table` to go once it ships (#2432, #2459). Today the module page draws a model as if it were the cap table, the simulator sits on the old page, and nothing records what was issued. This decision is the integration: where the tool lives, its tab bar, the tabs whose reads exist, and the line that keeps a modelled figure from passing as a recorded one. The rest is fourteen slot tasks (§6).

### 1. Where the tool lives

The tool is the Cap table module, not a page beside it, as D906 made the Investor narrative.

| Address | What it is |
|---|---|
| `/raise/cap-table` | Overview: CycleRoute's module page as today (the Planned round card, the Holders records, From Mercury, Eadwyn's two bands), with the tool's tab bar and the Modelled line under its header |
| `/raise/cap-table/instruments` | Instruments (CT3) |
| `/raise/cap-table/option-pool` | Option pool (CT5) |
| `/raise/cap-table/scenarios` | Scenarios (CT6) |
| `/raise/cap-table/h-12`, `/e-3`, `/pool` | a row's own page (its record), unchanged; part 5 makes it the holder drawer |
| `/raise/cap-table/new` | Add holder, unchanged; part 8 makes it "Record an issuance" |

- **No route is added.** Every `/raise/cap-table/<word>` already reaches the module's record route (`/raise/:slug/:id`), and every one is a cycle path (`cyclePaths.js` RECORD_ID).
  - CycleRoute reads the three tab words as tabs (`isCapTableTab`, `frontend/src/pages/raise/captable/capTableModel.js`) and never as records. Row ids are `h-<n>`, `e-<n>` and `pool` (D691 decision 4), so none collides.
  - The record read is not made for a tab word.
- **The canvas's History, Access and Import and export tabs are not drawn.** None has a read (D953's rule). Their parts add them.
- **The guard is today's,** `labRoles(['admin', 'founder'])`, through the module routes. The Worker's gates are #2651's: investors refused, co-founders through accepted membership.
- **The Raise header is CycleRoute's own:** the eyebrow, the title, Call for Capital, the "Raise modules" rail and the phone Module select.
  - The canvas's in-page venture chooser is not drawn: an in-page project picker is refused (#181), and the venture comes from the address as on every founder tool.
  - The tool bar's chips (As of, Carta, 409A, proposals) and "Record an issuance" wait for parts 2 and 8.
- **The tab bar** is the canvas's second level: underlined text tabs, `nav aria-label="Cap table"`. Each tab keeps `?project_id=` and nothing else.
- **The old pages stay** until part 14. Scenarios opens the simulator (`/raise/capital/cap-table?project=`) for the model and the variant page for a variant. Option pool sends 409A writes there too. No redirect is added yet: the simulator still holds what no tab replaces.

### 2. What is read, and from where

| Tab | Read |
|---|---|
| Overview | `GET /api/cycles/raise/modules/cap-table`, as CycleRoute draws it today |
| Instruments | `GET /api/safe-issuances/project/:id` (D578) and `GET /api/captable/scenarios/by-project/:id/compare` |
| Option pool | `GET /api/captable/409a/:projectId` and the same compare read |
| Scenarios | the compare read |

- **Each read answers alone.** A failed one says "could not be read" where its block would be, with "This is not a claim that…" and Retry. A 403 or 404 says the venture's cap table is not open to you, never "none".
- **Not read:** `GET /api/captable/equity-plan`. Pools and vesting are stored per account, not per venture, so one venture's page would mix a founder's companies. Option pool says "Not read here yet." Part 5 moves them to the venture.
- **Money in its own unit.** The model is in whole dollars, and SAFE issuances in the currency's smallest unit with their own currency code. Discounts and rates are stored as fractions and drawn as percentages. A missing value is "Not recorded", never `$0` or `0%`.

### 3. On record and Modelled

The canvas never lets the two share a number without a tag. On `main` nothing records what was issued (map §3):
- **Overview** carries the Modelled tag and the line "Every figure on this page comes from your saved model, not from a record of what was issued. A record of issued shares is not kept yet." The Holders list and the Planned round card are the model.
- **Instruments** has two blocks:
  - "Sent through StudioOS": each SAFE from `safe_issuances` with its envelope's status. It is tagged On record only when countersigned. Its discount is "Not recorded" because the Worker stores none.
  - "In your model", tagged Modelled: each SAFE and note with amount, cap, discount, basis, interest and date signed.
    - A basis the model never states is drawn "Pre-money (not stated)", because the engine reads it as pre-money. It carries CT3's note, "Basis: pre-money, as entered. Axal's SAFE template is post-money."
    - An instrument with no cap and no discount says "Cannot convert".
    - The model's first round lists how each instrument converts, in the engine's own words.
- **Option pool:** the 409A status in the Worker's own sentence, with FMV, valuation date, valid until and provider; then the model's pool target, shares and fully diluted share, tagged Modelled.
- **Scenarios:** the model, named "Cap table · model" (CT19b's name), and each draft variant. Every card shows its round, pre-money, raise and pool target, founders after, and when it changed, tagged Modelled.

### 4. Who sees what

Today's gates, unchanged: the venture's founder, its accepted co-founders (`capRead`/`capWrite`), and admins (#2651, #2436). Investors are refused on every read. The canvas's levels, the investor's panel, the admin support read with a reason and the access log are parts 4, 9, 10 and 11.

### 5. Owner decisions, and what S21 read from the canvas

#2432 asked nine questions; the owner answered 7 (the address). The approved canvas answers five more:
1. **Record and model: read as answered, A.** Every board keeps On record and Modelled apart, and CT19b keeps today's model as a scenario.
2. **Co-founders: read as answered, A.** CT16 draws "Propose an issuance" and read-only access for a co-founder.
3. **Investors: read as answered, A.** CT13's levels start at None, and CT15 draws "The founder has not shared the cap table with you."
4. **Operating Partners and Admins: read as answered, A.** CT17 draws an OP's read as "Shared with you by…", and CT18 an Admin's reason the founder sees, with the Super Admin read only.
5. **SAFE basis: read as answered, A.** CT3 draws the post-money default and the pre-money "Check" note.

Still the owner's:

6. **Carta.** CT5c and CT14 draw Carta read-only while connected, which is the proposed A. Neither draws the alternative, so the canvas does not rule it out. Part 5 builds A unless the owner says otherwise.
8. **Currency.** The canvas's samples are in dollars and euros. Part 2 stores a currency per venture (A) unless the owner answers B.
9. **Money terms from a document.** Until the owner answers, B, as #2431's rule: CT11's Eadwyn variant leaves amount, cap, discount and shares empty (part 6).
