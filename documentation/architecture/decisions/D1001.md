## D1001 — Segment answers and displayed archetypes, as suppressed counts

Issue #2816, part of #2378. Builds on D999's account population and D1000's
segment profiles. No migration, AI call, themes or metering change.

`routes/persona_segment_aggregates.ts` prepares two Admin reads on the local
database, under `/api/personas/segments/:key`: `/answers` and `/archetypes`.
The companion `personaSegmentAggregatesApi` client is prepared locally.
Registration, its re-export and shared docs await S01’s file-ownership reply
on #2816; the partial draft does not mount these reads or add that client. No query
parameters are accepted, including cross-studio scope and member filters.
Unknown segment keys return 404. A thrown D1 read, failed result or absent
results array returns 503 `unreadable`, with no counts. Auth runs before reads.

Both populations use every active non-admin account whose newest primary
`user_personas.id` names the requested segment. Secondary and superseded
primaries contribute nothing; there is no newest-500 limit. This matches
D999, including its treatment of NULL active flags as active.

### Sign-up questions

The code taxonomy defines the question keys, prompts, types and choice labels.
SQL joins only each member's newest extra for that segment and question. It
returns grouped counts; member identifiers, numeric samples and open text
never leave the database query. Unknown keys are ignored. Invalid values are
counted as **Not recorded**, alongside absent answers.

Number bands are fixed, never derived from people's answers. USD amounts use
0/10k/25k/50k boundaries; AUM uses 0/1m/10m/100m. Deals per year use 0/3/6;
years of experience and hours per week use 0/5/10/20. Each interval includes
its lower boundary and excludes its upper boundary; the last has no upper
boundary. Only finite nonnegative JSON numbers count: malformed strings,
negative numbers, JSON strings/objects/null, NaN and infinity are missing.
Choice values must match a code option exactly. Open questions return an
`answered` cell and no buckets, themes, text or sample quotes. Blank spaces,
tabs and line breaks do not count as an answer. `themes_enabled` is false.

### Working style

One member contributes at most once. The newest snapshot by append-only `id`
across that member's personas supplies its `persona` and **displayed_slug**;
computed/secondary slugs never substitute for it. This is a member's latest
displayed snapshot, rather than a count of all historical or persona profiles.
A latest NULL display, absent snapshot or unrecognised persona/slug is **Not
recorded**; no fallback to an older display. Labels come only from
`ARCHETYPES_PROFILE_V2`. All known persona/slug cells are present, including
known zeros; the stored profile persona can differ from the segment's profile.

### Small cells and totals

Each question's mutually exclusive buckets **plus Not recorded**, or the full
archetype partition **plus Not recorded**, goes through the existing
`suppressGroup` and `SMALL_CELL_MIN = 5`. Counts 1–4 are null with
`suppressed: true`; when only one positive cell is hidden, the smallest other
positive cell is hidden too. If the whole segment has fewer than five members,
this read hides **every cell**, including zeros, because D999 already exposes
the member total. The hidden pattern is identical whichever bucket holds the
members; a companion selected by position could itself reveal the true cell.
Other known zeros remain zeros. Suppression is applied after
the full population is counted, never to individual records before grouping.

An answered/profiled subtotal is also hidden whenever any cell in its
partition is hidden. Otherwise that subtotal could undo suppression of the
missing complement or a constituent. No rates, ranges, largest-group claim
or extra total is returned. D999's public member totals cannot recover a
single hidden cell by subtraction from these partitions. No arbitrary cohorts
or adjustable suppression threshold are exposed.

### Verification

Real SQLite route tests cover population exclusions and primary tie-breaks,
fixed boundaries, invalid values, more than 500 members, exact-five and
complementary suppression, missing data, latest displayed snapshots, auth
refusals, query refusal and failed database reads. Client tests drive the real
request layer, check encoded paths and preserved nulls, and ensure failed reads
reject. Test and mutation results are recorded in the PR.
