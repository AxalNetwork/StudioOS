## D4476 — Learning exam review and per-question results (#4476)

LR11 now has a review sub-step within the timed attempt: one row per question,
Answered / Unanswered status, Edit, Back to questions, and Submit answers.
The server deadline continues through review and expiry submits the choices
once. Manual submits share the same in-flight guard. Phone navigation sticks
to the bottom, with 44px controls and a 16px gutter; tablet content stacks.

Right and wrong per question shows only under `reveal = score_and_answers`
and the route's explicit `answers_revealed: true`. Under `score` alone,
showing which questions were wrong would reveal part of the answer key.
Multiple-choice correctness requires the whole answer set. No Worker change,
new client method or migration is needed.

Results show Your attempts from the member's attempts read, including the
current attempt once that list refreshes. Missing scores say Score not
recorded; missing outcomes and dates remain unrecorded. Timeout results show
the LR11 status banner, and time_limit_passed refusals show the route's own
message. Transport failures use Unreadable without exposing the thrown text.
The exam page has no Ask control or Eadwyn rail.

The approved LR11/LR20d/LR21 canvas and the issue's copied spec are followed,
using the app's Card/Pill tokens and dark variants. The existing answer reveal
is retained. The canvas's six-row sample and contradictory Passed/Try again
sample are corrected with one row per actual question and a retry only when
the attempts read confirms availability. No explanations or certificate is
promised.

Verification covers the pure row/line helpers, partial multiple answers,
reveal guards, interactive review/edit/return/submit, expiry during review,
missing history scores and timeout refusal presentation. Removing the reveal
guard is mutation-checked. Existing frontend and Worker exam tests are retained.
