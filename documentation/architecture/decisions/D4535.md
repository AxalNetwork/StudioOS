### 2. The minimum additive schema (proposal; not a migration)

These are four tables, all additive. The execution slice lands them as its own numbered migration, checks the number is free, and may change them after review.

```sql
-- A workflow's identity. One row per workflow; its content lives only in its versions.
CREATE TABLE IF NOT EXISTS agent_skill_workflows (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  uid TEXT NOT NULL UNIQUE CHECK (length(uid) = 32),
  scope TEXT NOT NULL CHECK (scope IN ('hq', 'company')),
  company_id INTEGER REFERENCES company_profiles(id),
  slug TEXT NOT NULL CHECK (length(slug) BETWEEN 1 AND 64),
  status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'retired')),
  current_version INTEGER NOT NULL DEFAULT 0 CHECK (current_version >= 0),
  draft_json TEXT CHECK (draft_json IS NULL OR json_valid(draft_json)),   -- the editable draft, validated on save
  created_by INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CHECK ((scope = 'hq' AND company_id IS NULL) OR (scope = 'company' AND company_id IS NOT NULL))
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_agent_skill_workflows_slug ON agent_skill_workflows (scope, IFNULL(company_id, 0), slug);

-- A published version: the definition exactly as validated, and its hash. Never edited.
CREATE TABLE IF NOT EXISTS agent_skill_workflow_versions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  workflow_id INTEGER NOT NULL REFERENCES agent_skill_workflows(id),
  version INTEGER NOT NULL CHECK (version >= 1),
  definition_json TEXT NOT NULL CHECK (json_valid(definition_json)),
  definition_hash TEXT NOT NULL CHECK (length(definition_hash) = 64),
  policy_version TEXT NOT NULL,
  published_by INTEGER NOT NULL REFERENCES users(id),
  published_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (workflow_id, version)
);
CREATE TRIGGER IF NOT EXISTS trg_agent_skill_workflow_versions_immutable
BEFORE UPDATE ON agent_skill_workflow_versions BEGIN SELECT RAISE(ABORT, 'agent_skill_workflow_versions rows are immutable'); END;

-- A run: bound to one version through its frozen plan. Scoped like scope_tasks.
CREATE TABLE IF NOT EXISTS agent_skill_workflow_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  uid TEXT NOT NULL UNIQUE,
  run_key TEXT NOT NULL UNIQUE,                        -- planRun's run_key: one run per request
  version_id INTEGER NOT NULL REFERENCES agent_skill_workflow_versions(id),
  scope_kind TEXT NOT NULL CHECK (scope_kind IN ('company', 'project')),
  company_id INTEGER REFERENCES company_profiles(id),
  project_id INTEGER REFERENCES projects(id),
  plan_json TEXT NOT NULL CHECK (json_valid(plan_json)), -- the RunPlan, never rewritten
  status TEXT NOT NULL DEFAULT 'admitted'
    CHECK (status IN ('admitted', 'running', 'waiting_decision', 'finished', 'partial', 'stopped', 'cancelled', 'paused_incompatible')),
  cancel_requested_at TEXT,
  brief_proposal_uid TEXT,                             -- the assembled brief, a proposal
  brief_artifact_key TEXT,                             -- its R2 key in FILES
  started_by INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  ended_at TEXT,
  CHECK ((scope_kind = 'company' AND company_id IS NOT NULL AND project_id IS NULL)
      OR (scope_kind = 'project' AND project_id IS NOT NULL AND company_id IS NULL))
);
CREATE INDEX IF NOT EXISTS idx_agent_skill_workflow_runs_scope
  ON agent_skill_workflow_runs (scope_kind, IFNULL(company_id, 0), IFNULL(project_id, 0), status);

-- The one link the task store lacks: which task is which node of which run.
-- The node's attempts are that task's agent_task_runs rows; its output is their proposal.
CREATE TABLE IF NOT EXISTS agent_skill_workflow_run_nodes (
  run_id INTEGER NOT NULL REFERENCES agent_skill_workflow_runs(id),
  node_key TEXT NOT NULL CHECK (length(node_key) BETWEEN 1 AND 40),
  task_id INTEGER NOT NULL UNIQUE REFERENCES scope_tasks(id),
  state TEXT NOT NULL DEFAULT 'pending'
    CHECK (state IN ('pending', 'running', 'waiting_approval', 'succeeded', 'failed', 'skipped', 'cancelled')),
  reason TEXT CHECK (reason IS NULL OR length(reason) BETWEEN 1 AND 64),   -- a code, never a sentence
  output_artifact_key TEXT,                            -- R2 key when the output is over the inline budget
  evidence_refs_json TEXT NOT NULL DEFAULT '[]' CHECK (json_valid(evidence_refs_json) AND json_type(evidence_refs_json) = 'array'),
  PRIMARY KEY (run_id, node_key)
);
```

What this adds and what it does not:
- It adds no node table, attempt table, cost column, approval table or audit table.
- Attempts are `agent_task_runs` rows. Cost is `ai_usage_logs` and `ai_budget_reservations`. Decisions are `ai_rail_proposals`.
- Every read binds the scope columns, as `scope_tasks` reads do.

`scope_tasks.source_kind` gains no value. Widening its CHECK would rebuild a table that many others reference. A run's tasks are found through `agent_skill_workflow_run_nodes.task_id`, and they carry `source_kind = 'plan'` with `source_ref = 'workflow:<run uid>'`. The owner may prefer a dedicated `'workflow'` value at the cost of that rebuild.

### 3. The definition contract (`WorkflowDefinition`, schema 1)

The shape is closed. An unknown key is refused (`definition_invalid`), so nothing an author adds is silently followed.

- **Identity.**
  - `uid` (32 hex), `slug` (kebab, at most 64), `name` (at most 80) and `purpose` (at most 300), with the same limits as `agent_skills`.
  - `owner`: `{ scope: 'hq', company_id: null }` or `{ scope: 'company', company_id }`.
  - `provenance`: `origin` is `hq_reference`, `company_authored` or `copied`. A copy must name its `source_uid`, and only a copy may.
  - `version` (at least 1) and `lifecycle` (`draft`, `published`, `retired`).
- **Contracts.**
  - `input_schema` is a flat list of `{ name, type, required }`, where the type is one of `text`, `number`, `boolean`, `text_list`, `record_ref` and `record_ref_list`.
  - `output.sections` is the final output. Each section has a key, a title, `required`, and the `{ node, field }` sources it is built from. This is the provenance map.
  - `output.notice` is the proposal wording.
  - `output.approval` must be `required`.
  - Skill-level typed contracts do not exist yet: #4530's v1 contract constrains outputs only by `output_kind`. So each node declares its own `inputs` and `outputs`, and the workflow checks handoffs against those declarations. When #4530 adds per-skill schemas, the execution slice must check node declarations against them (§8).
- **Nodes.** A node has:
  - `key`, a stable logical id that appears in every attempt key;
  - `title`;
  - `skill_uid` and `version`;
  - `role_key`;
  - `tools`, which must be within the skill version's allow-list;
  - `depends_on`;
  - `inputs`, `mapping` and `outputs`;
  - `timeout_ms` and `max_retries`;
  - `failure`;
  - `approval` and `consequential`;
  - `budget`: `max_cost_cents` and `max_output_bytes`.
- **Version selection.**
  - `{ pin: 'exact', version }`.
  - `{ pin: 'policy', policy: 'agent_pin_at_plan' }`. This is the only policy: it takes the executing agent's `agent_skill_links` pin when the run is planned and freezes it into the plan. It is never "latest".
  - No pin, or any other policy, is refused `version_unpinned`.
- **Mappings.** A node input may come only from a declared workflow input or from a declared output of a node it depends on, directly or transitively. Types must match, and an optional output cannot feed a required input.
- **Failure.**
  - `stop` ends the run.
  - `continue_when_safe` skips the node's dependents and marks its sections missing. It is refused for a node that a `required` section reads.
  - `fallback` names a skill, with the same role and no wider tools, that runs under the same retry budget and is followed by `then: stop | continue_when_safe`.
- **Approval.** A node that is `consequential`, or whose skill version proposes a `record_change`, must be `approval: 'required'`. The final output is always `required`.
- **Budget.**
  - The run budget has `max_total_cost_cents`, `max_run_ms` (active execution; waiting for a person is not counted), `max_concurrency`, `max_fan_out`, `max_total_attempts`, `max_input_bytes`, `max_artifact_bytes` and `approval_expiry_hours`.
  - Every field must be stated. One that is not stated is refused `budget_missing`, never read as 0.
  - Ceilings are `WORKFLOW_CEILINGS`. A context may lower them, never raise them.
- **Conditions are deferred in v1.** `condition`, `when`, `if`, `conditions` and `branches` are refused `condition_unsupported`. A future condition engine gets its own schema version.

### 4. The validator's refusals (`validateWorkflow(def, context)`)

It returns every refusal it finds, each with `code`, `path`, the `node` where it applies, and `detail`. A shape failure stops before the semantic checks. Per skill reference, the checks run in `attachCheck`'s order.

| Code | When |
| --- | --- |
| `definition_invalid` | The shape is wrong, or a key is unknown. |
| `condition_unsupported` | A condition or branch key is used (deferred). |
| `grant_inheritance` | A node names `inherit_grants`, `grants`, `grants_from`, `run_as` or `tool_grants`: a branch cannot borrow authority. |
| `workflow_out_of_scope` | A company workflow is used outside its company. |
| `node_duplicate`, `node_missing` | A key is used twice, or a dependency, mapping or section names an unknown node. |
| `cycle` | Detected before activation. The detail lists every node on or behind the loop. |
| `skill_not_found` | The skill is missing, or the caller cannot read it, or it is another company's. All three answer the same, as in `attachCheck`. |
| `skill_unpublished`, `skill_retired`, `skill_suspended` | From the skill's status and the version's suspension (`skillRunRefusal`'s rule, in the context). |
| `version_unpinned`, `version_not_published` | There is no pin, the policy is unknown, the agent has no pin, or the version does not exist or was never published. |
| `role_mismatch` | The version does not list the node's role. |
| `agent_unavailable` | No active agent of that role exists in the caller's scope. |
| `tool_outside_skill` | The node names a tool the version does not list. |
| `tool_not_granted` | A tool the version uses is not in the agent's grants now (a revoked grant). |
| `mapping_target_unknown`, `input_unknown`, `mapping_not_upstream`, `output_undeclared`, `mapping_type_mismatch`, `input_unmapped` | A handoff is wrong. |
| `section_unmapped` | A final section has no source. |
| `continue_unsafe` | A required section reads from a node that may be skipped. |
| `fallback_widens_grants` | The fallback uses another role, names a tool the node lacks, or uses a skill whose tools exceed the primary's. |
| `approval_missing` | A consequential or record-change node, or the final output, has no checkpoint. |
| `budget_missing`, `budget_over_ceiling`, `budget_over_total`, `fan_out_exceeded` | A budget is unstated, a budget is over its ceiling, the worst case (every node at every attempt, a fallback doubling its node's attempts) is over the run's total cost, attempts or active time, or the definition fans out wider than its budget. |

**The context is facts, not reads.** `ValidationContext` supplies:
- the caller-authorized scope;
- per skill: `readable` (the caller's `mayRead`), scope, status, and per version `published`, `suspended`, roles, tools, `output_kind` and `content_hash`;
- per role: the agent that runs it, with its status, company, grants (`grantsOf(tool_grants_json)`), pins and configured model.

The caller builds these from D1 through the existing gates. The validator never reads D1.

### 5. What the execution slice must recheck at run time

Validation is admission, not authority. At each node attempt's start, the execution slice must go through `agentRun` (the only way an agent runs) with `skill = node.skill.uid` and `skillVersion = plan.skill.version`. That call:
- re-runs `skillForRun`: attached, the saved version still pinned (`skill_version_changed` otherwise), readable, not suspended, grants re-checked, reads within the allow-list;
- re-runs the sponsor, scope, pause, cap, allow-list (D4422) and halt gates.

Before any consequential effect, the execution slice must:
- reread the current grants (D4572 §R2-07.3);
- reread the run's `cancel_requested_at`;
- confirm the upstream proposal's decision is `accepted` or `edited`. An edited payload is what flows downstream.

If a recheck refuses, the node attempt fails with that code, and the plan is not re-resolved.

### 6. The run plan and idempotency (`planRun`)

`planRun(def, context, requestKey)`:
1. validates the definition;
2. requires `lifecycle = 'published'`;
3. returns a deep-frozen `RunPlan`, a copy that later edits to the definition cannot reach.

The plan holds:
- `policy_version`;
- the workflow's uid, slug, version and `definition_hash` (SHA-256 over the canonical JSON);
- the scope;
- the deterministic `order` and `levels`;
- per node: its exact skill revision (uid, version, `content_hash`, `output_kind`), the agent's uid, the requested model, the contract (inputs, mapping, outputs), timeout, retries, failure policy, approval and budget;
- the final sections and the budget.

The keys:
- `run_key = wfrun:` followed by a SHA-256 over the workflow uid, version, definition hash, scope, request key and policy version. The same request on the same version in the same scope gives the same key, so a duplicate start finds the run by `run_key` (unique).
- Per attempt: `key = <run_key>:<node>:a<n>:<skill uid>@<version>`, or `f<n>` for the fallback. `run_uid = wf-` followed by 40 hex characters of a SHA-256 over the key and the skill's content hash.
- The `run_uid` is meant to be the attempt's `agentRun` uid, so the existing `agent:<run uid>` proposal key and `:run` hold key deduplicate the proposal and the charge. The execution slice must let admission take this uid (admission mints its own with `crypto.randomUUID()` today, `agents/engine.ts`).
- A changed skill revision changes the attempt keys even under an unchanged definition (the `agent_pin_at_plan` case), so an old proposal is never answered for new instructions.

### 7. Replay, partial completion and cancellation (R2-10)

1. **Immutable run plan.** The plan is stored once (`plan_json`). Publishing a new version or editing the draft never touches it. The model is recorded as requested in the plan, and as actual on the usage row.
2. **Least privilege.**
   - A downstream node receives only the mapped fields of decided upstream proposals.
   - Grants are each agent's own, rechecked at run.
   - A fallback cannot widen grants, and a branch cannot inherit them.
   - Another company's skill or agent is invisible.
3. **Bounded execution.**
   - Validation enforces every ceiling against the worst case.
   - At run time, `readiness()` starts at most `max_concurrency` nodes.
   - The run loop's single-flight index (one live run per agent), `DAILY_LIMIT` and `OPEN_PROPOSALS_MAX` still apply.
   - Approval waits are bounded by the loop's 7-day `decision_expired`, which is the ceiling for `approval_expiry_hours`.
   - Unknown spend is not zero: an attempt with no settled usage leaves the run's cost unavailable (`provenance.ts` `reconcile`).
   - Admission against #4556's upstream quota is not built (§8).
4. **Replay compatibility.**
   - Logical identities are the node key and the attempt number.
   - Deduplication is the attempt's `run_uid`. Through `agentRun`, a replay answers the first proposal (`replayed: true`) and takes no second hold (`step_lost` when the hold replays with no proposal).
   - On resume after a code or definition upgrade, the stored plan is compared with a fresh plan (`resumeRefusal`). Any change to the policy, the definition, a node's skill revision or its agent returns `plan_incompatible`, and the run pauses (`paused_incompatible`) for a person to review or migrate it. Old effects are never replayed under new instructions.
5. **Evidence and partial completion.**
   - `assembleSections(plan, outcomes)` builds the section map.
   - A source is `included` only when its node `succeeded` on an attempt the plan made, with the exact pinned skill uid and version (or the fallback's). Otherwise it is named `failed`, `skipped`, `cancelled`, `not_run`, `output_missing` or `version_mismatch`.
   - A section is `complete`, `partial` or `missing`. `complete` is false while any node is missing.
   - The brief carries the notice and `proposal: true`. Large outputs are R2 references, never inline.
6. **Cancellation and late results.**
   - Cancelling sets `cancel_requested_at`. `readiness()` then makes every pending node `run_cancelled` and starts nothing.
   - A node already running ends at its next step (D4572 R2-07.2). An in-flight provider call is not cancelled: its usage settles through the hold and its output stays a proposal.
   - `lateResult()` refuses a result for a cancelled run, an attempt the plan did not make, a node not running, or a superseded attempt. So a late result can never restart a cancelled graph, and it is left to the existing reconciliation.
   - A failed node under `stop` makes every unstarted node `run_stopped`. Under `continue_when_safe`, it makes its transitive dependents `prerequisite_failed`.
   - Waiting for a person (`waiting_approval`) is a separate state from `running`. Only `running` counts against concurrency.

**Approval in v1 execution.** On the existing loop, every agent run ends `waiting_decision`, and `scope_task_deps` makes a dependent wait until its prerequisite task is `done`, which happens on Accept. So with today's primitives, every node is in effect `approval: 'required'`. The `approval` field still matters: the validator requires it on consequential nodes, and it keeps the definition honest if a later slice lets a dependent read an undecided proposal. Discard sends the task back (`needs_person`) and counts as a failed attempt.

### 8. The Startup Assessment reference workflow

`startupAssessment(uids, { uid })` is the definition as data. It is a **draft**, with HQ ownership and `hq_reference` provenance. Library skill uids are D1's, assigned when a skill is seeded, so they are bound in at authoring time.

- **Inputs:** a profile reference and the selected evidence references.
- **Nodes:**
  - market research: `market-entry-brief`, `research_analyst`, `research.read` and `validate.read`;
  - financial analysis: `unit-economics-summary`, `cfo`; consequential, with an approval checkpoint;
  - product assessment: `roadmap-review-brief`, `cpo`; it depends on market research and maps its `findings`;
  - legal/compliance review: `legal-due-diligence-coordination`, `general_counsel`; consequential, with an approval checkpoint.
- **Node settings:** each node is pinned to version 1, has one retry, continues when safe, and has a budget of 150 cents and 16 KB.
- **Run budget:** 1,200 cents, which is exactly the worst case. It also allows 8 attempts, a concurrency and fan-out of 3, and a 7-day approval expiry.
- **Final output:** sections for overall findings, market, financials, product, legal and compliance, evidence-backed strengths, risks, open questions and missing information. None of them is `required`, so a failed node is marked missing instead of blocking the brief.
- **Notice:** "A proposal for human review: not an investment decision, and not legal advice. Sections marked missing were not assessed."

**What activation still needs, by issue:**
- **#4531 / #4588:** supported, discriminating assertions and cases for the four skills used here. Only `legal-due-diligence-coordination` is among #4588's first ten. The other three either join a qualification set, or the reference picks qualified skills.
- **#4667:** readers that supply each node's inputs. On today's readers, D4667 found no skill `ready`. These four need `research.read`, `validate.read`, `stripe.read`, `grow.read`, `build.read`, `project.read`, `data_room.read` and `raise.read` shapes, plus a typed handoff for selected evidence references.
- **#4533:** release-evidence identity, so a node can be required to pin a *qualified* version, not merely a published one. `SkillVersionFact` would gain that flag, and the validator a refusal for it.
- **#4534:** merged. Execution parity is in place (`skillForRun` on both paths, `skill_version_changed`). §5 relies on it.
- **#4536:** measured execution, failure and cost signals, to set the budgets from evidence instead of these first ceilings.
- **#4530:** per-skill typed input and output schemas, so node declarations are checked against the skill's own contract.
- **#4556:** an upstream quota admission policy. D4556 records the seam and builds no quota system. Admission must use it once it exists, through the existing hold and settlement path.
- **#4572:** a grant-version fence (D4572's open proposal), if the owner wants resume to refuse on any grant change instead of rechecking.
- **#4594 (after #4566):** a hosted composite-workflow case.
- **Then the execution slice:** the migration in §2; admission accepting the plan's run uid; routes for validation, draft create and update, publish, run, run detail and cancel (each with a frontend method and a matching Hono route); and the run timeline.

### Departures

- **The final brief is assembled purely, with no fifth model node.** The issue asks for no monolithic prompt. A synthesis node can be added later as a declared node with its own skill and pin.
- **Nodes declare their own input and output fields.** Skills do not yet have typed contracts (#4530 v1). This is the "versioned handoff contract" the gate asks this work to own until #4530 extends the skill contract.
- **`fallback` must keep the node's role.** A different role means a different agent with a different sponsor and grants, which this slice treats as widening.
