### 1. The read

`GET /api/decks/:id/qa?stage=&investor_type=`, mounted in `routes/deck_qa.ts` before `decks`.

It answers `{ deck_id, version, stage, stage_label, investor_type, questions, more, reads }`. Each question carries:
- `key`: `objection-<16 hex>` (the objection's own key) or `finding-<16 hex>` (a hash of what the finding is about);
- `rank`, `kind` (`objection` or `finding`), `question`, and `cards`, the deck cards its answer draws on;
- for an objection: `heard` (count, investors, last heard), `answered_in` (D913's section and version) and `said`, the founder's own answer from Capital relationships;
- for a finding: `severity`, `code`, `card_uid`, `card_index`;
- `answer`: `{ state, text, bindings, fill }`;
- `kept`: the founder's kept answer, or null.

`reads` says which read could not be done (`objections`, `sources`, `claims`, `kept`), so a failed read is never shown as "none".

### 2. The ranking

1. **Real objections first.** Every objection the venture's investors raised, most heard first, as D913 orders them.
2. **Then the critic's rule findings** (D1557's `ruleFindings`, read through `deck_critic.ts`'s `readAll`): deal-breakers first, then by card. One question per card, worded per card (`CARD_QUESTION`); a Not backed figure asks where that figure comes from.

At most 20 questions; `more` counts the rest. No model runs, so the read is free and answers with AI off. The critic's own model findings are not used: they are a paid run, and a run is not a read.

### 3. Answers are bindings

An objection is matched to cards by its words (`TOPICS`, at most two cards); a finding is its card. The answer is those cards' deck sources (`CARD_CATALOGUE[].sources`). Each recorded slot is a binding with D896's keys, its label, its value and its unit.

| `answer.state` | When |
|---|---|
| `bound` | at least one slot holds a value; `text` is written from the bindings alone |
| `not_recorded` | every slot holds nothing; `fill` names each slot and the module that fills it |
| `unchecked` | no slot holds a value, and one is withheld or could not be read |
| `no_topic` | the question names no card the records answer |

**No answer contains an unbound figure.** A figure is a run of digits, read as the critic reads one, with separators and leading zeros set aside. A figure is bound when a binding's value, second value, date or slot label carries it. Formatting (`shown`) keeps every digit, so "$1,200.50" stays bound to 120050 cents. The rule covers every text the read returns:
- the answer's `text`;
- the founder's own words (`said`): shown only when every figure in them is bound; otherwise `said` is null and `said_held` is `unbound_figure`;
- a kept answer's note: refused on write, and not shown on read when its figure is no longer carried.

### 4. Kept answers (migration 736)

Written in `cycle_raise.ts`, beside the objections routes:
- `PUT /api/cycles/raise/narrative/questions/:question/answer?project=` with `{ deck_id, source_keys, note? }` → `{ question, kept }`;
- `DELETE` on the same path → `{ question, kept: null }`.

The rules:
- The question must be one of that deck's likely questions now (404 `question_not_found`), and the deck must be this venture's (404 `deck_not_found`).
- 1 to 6 `source_keys`, each a deck source that holds a value this founder can read now (422 `not_recorded`).
- The note is at most 600 characters and may state no figure that a kept binding does not carry (422 `unbound_figure`). Nothing is written on a refusal.

`deck_qa_answers` holds one row per question: the bindings with the value each held when kept, the note, the deck version, who kept it and when. A later answer replaces the earlier one. On read, each kept binding is `fresh`, `stale` (the record moved), `gone` or `unknown`, as D896 compares a binding.

Each write logs one `raise.pitch-deck` row naming the deck version and the count, never the question's words or a figure.

### 5. Who

The venture's founder alone, for both the read and the writes. The read uses D900's `reader` (`deck_check.ts`); the writes use the narrative's write gate plus D912's `narrativeFounder`. Answers state the records' figures, so:
- an admin, a support session and another member get 403 `founder_only` (or the deck's own 403/404);
- an admin's narrative write is refused first, by D914's `admin_read_only`.

### 6. Tests

Every new assertion that guards a rule was mutation-checked.
