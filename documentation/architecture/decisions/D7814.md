## D7814 — Bound analysis reads and atomic competitor saves (#7814)

Choose **option A**: the reusable editor may still send its candidate list, but
only name, category and summary update in place. IDs must already belong to the
analysis and appear once; omitted candidates stay. Relevance, scores, details
(including pricing), origin, domain, URL and position are ignored from the
request and remain stored. Sources and signals retain their candidate IDs.
Both list and single-candidate saves reject the subject as a competitor.

A list save must name its base version. Validation happens before writing.
Title, output, section-edit dates, historical snapshot, candidate edits and
version increment form one D1 batch. Every write checks the same version and
the increment is last; a concurrent text save causes 409 and no guarded write.
A batch failure rolls back all statements. A current-version snapshot left by an
older failed claim is refreshed from the actual pre-save record inside that
same batch, without rewriting older versions. Only title/output move the saved
version. Older text-only clients remain accepted against the version read at
the start of the save; their writes still use the same conditional batch.

The single-candidate route validates all allowed fields before its one candidate
UPDATE, and batches that UPDATE with the analysis edited marker. It never bumps
the saved version. No migration or change to _competitor_writes.ts is needed.

Cloudflare documents D1 batches as transactions that roll back on statement
failure: https://developers.cloudflare.com/d1/worker-api/d1-database/#batch .
Tests use the canonical migrated SQLite schema and the transactional D1 adapter,
including a real aborting trigger midway through a two-candidate save.

CompanyAnalysis shares the recordGate generation across the initial read and
answers from its actions, including the conflict re-read. Route identity is
checked before applying responses; writes carry the loaded analysis ID, version
and draft. Stale successes, failures and cleanup cannot replace another record.
The reusable editor sends only IDs and the three editable candidate fields,
and drops obsolete save responses.

useLeaveGuard replaces the page's private beforeunload effect. Its single hook
covers link/navigation, Back/Forward and reload only while the current draft is
dirty. Companies links use this tab's backToResults state. Existing RS-14/FND-S04
layout is retained; no new layout or Help flow is introduced.

Verification includes delayed successful/failed re-reads, delayed refresh,
loaded-record write payload, dirty and clean navigation, one reload listener,
mid-batch rollback, stale and racing versions, foreign IDs, protected candidate
fields, whole-field validation and subject refusals. Existing D7176 and D4607
suites run unchanged. Mutation results and exact test exits are recorded in the
PR/issue; no production overwrite or live verification is claimed.
