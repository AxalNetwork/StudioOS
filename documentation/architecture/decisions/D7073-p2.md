## D7073 part 2 — Engine runs use the model accounts on the `agents` gateway (#7073)

- **Status:** built 2026-11-17, engine off. Owner decision E on #7072, given in a Claude Code session on 2026-11-17.
- **Builds on:** D7073 (the gateway fails closed), D1528 (the `agents` gateway and the platform circuit breaker), D4594 (the inference stub), CLAUDE_REVIEW.md §6a (the review workflow's account order).

### The decision

`AGENT_AI_GATEWAY = "agents"` in the default, production and preview var tables: the owner created the gateway. `AGENT_ENGINE` stays `off`; nothing in this change starts an agent.

A run the engine starts no longer goes to the AI router. It tries the review workflow's accounts, in order, through the authenticated `agents` gateway:

| Slot | Account | Alias variable (default alias) | Model |
|---|---|---|---|
| 1 | Primary Claude | `AGENT_CLAUDE_ALIAS_1` (`claude-primary`) | `AGENT_CLAUDE_MODEL` |
| 2 | Claude account 2 | `AGENT_CLAUDE_ALIAS_2` (`claude-2`) | `AGENT_CLAUDE_MODEL` |
| 3 | Claude account 3 | `AGENT_CLAUDE_ALIAS_3` (`claude-3`) | `AGENT_CLAUDE_MODEL` |
| 4 | OpenAI / Codex | `AGENT_OPENAI_ALIAS` (`openai-codex`) | `OPENAI_MODEL` |

- Each run starts at slot 1, skips a slot with no alias, no priced model, or a model HQ locks or the scope does not allow, and stops at the first valid answer.
- Every attempt is a provider-native request (`/anthropic/v1/messages` or `/openai/chat/completions`) carrying `cf-aig-authorization` (the gateway's Run token, Worker secret `AGENT_AI_GATEWAY_TOKEN`) and `cf-aig-byok-alias`. The Worker never holds a provider key. Payload logging is off per request.
- An alias is never `default`. `env.AI.run()` reads only the `default` alias and falls through to Unified Billing when it is missing, so the account loop never uses it.

### What each failure does

| Answer | Loop | Billed |
|---|---|---|
| Gateway 2044 (no key stored under the alias) | next account | no |
| Gateway 2052 or 2021 (the call reached Unified Billing) | stop every account | no |
| 429 with a gateway code other than 2003/2018 (the spend limit) | stop every account, and the loop writes the platform breaker | no |
| 401, 403 | next account | no |
| Anthropic 402, a 400 "credit balance", a 429 `enforced_spend_limit_reached`; OpenAI 429 `insufficient_quota` | next account | no |
| any other 429 (source not certain) | stop this run | no |
| any other 4xx | stop this run | no |
| 5xx, timeout, no answer, an unreadable 2xx | stop this run | maybe: counted at the attempt's quote |

### Accounting

- One logical run: every attempt uses the run uid as its execution id, so a replayed step finds its own attempt's hold and returns `step_lost` rather than calling again. One proposal per run key, as before.
- Each attempt is one metered call with its own hold (`exec:<run uid>:agent.account.<slot>`), against the sponsor's budget. An attempt that billed nothing releases its hold; one that may have been billed settles at its quote; an answer settles at its reported usage. Each attempt writes a usage row naming the slot, the alias, `via: ai_gateway` and `billing: byok`, never a key or a prompt.
- The per-run ceiling is checked against the dearest configured account. The input guard runs once per run, the output guard on the answer.
- The one shared $100 gateway limit is the gateway's own, set in the dashboard; `AGENT_GATEWAY_MONTHLY_LIMIT_MICROUSD` stays the alert threshold.
- An OpenAI model the catalogue does not price (the review's `gpt-5.3-codex`) is used only with `AGENT_OPENAI_RATES`, USD per 1M tokens as `{"tokens_in","tokens_cached","tokens_out"}`. Without it slot 4 is skipped.

### The Advisor boundary

The account loop states the two wire formats itself and imports nothing from `services/ai/providers/`. The Personal Advisor's import graph reaches the agent run, and D5339 keeps the provider execution service and its adapters out of that graph (`scripts/ci/no-anthropic-in-prod.mjs`).

### Storing the keys: `agent-gateway-keys.yml`

The keys already live in this repository's Actions secrets (`ANTHROPIC_API_KEY`, `ANTHROPIC_API_KEY_2`, `ANTHROPIC_API_KEY_3`, `OPENAI_API_KEY`). A manual workflow, run from `main` only, stores them on the gateway (`scripts/agent-gateway-keys.mjs`):

1. Verify each key with a free models call. The primary key must answer with `anthropic-organization-id` equal to the review's `ANTHROPIC_ORGANIZATION_ID`; a key from another organization, or an unset variable, is not stored. A fallback key in the primary's organization is flagged: it shares the primary's credit.
2. Store the key in the account's Secrets Store as `agents_<provider>_<alias>`, scope `ai_gateway` — the name AI Gateway reads at run time. An existing secret has its value replaced, so **a rerun after a key rotation stores the new key**.
3. Create the gateway's provider config for that provider and alias when none exists (`default_config: false`).
4. List the provider configs again and confirm each alias.

`mode: plan` does steps 1 and the reads, and writes nothing. The summary names slots, aliases and outcomes only; no key, preview, token or organization id is printed.

**Primary on federation.** The review reaches the primary account through GitHub workload identity federation where it can. Federation gives the review a short-lived token, not a key the gateway can store. If `ANTHROPIC_API_KEY` is not set, the workflow reports exactly that gap for slot 1 and stores the other slots; the engine then starts at Claude account 2.

### Owner steps before the engine is switched on

- Worker secret `AGENT_AI_GATEWAY_TOKEN`: a Run token for the `agents` gateway (authenticated gateway on).
- Worker var or secret `CLOUDFLARE_ACCOUNT_ID` (32 hex) where the Worker reads it.
- The gateway setting that requires provider credentials, so a missing key answers 2044 rather than Unified Billing.
- `AGENT_OPENAI_RATES` for `gpt-5.3-codex`, or slot 4 stays skipped. The aliases (`claude-primary`, `claude-2`, `claude-3`, `openai-codex`), `AGENT_CLAUDE_MODEL` (`anthropic/claude-sonnet-5-5`) and `OPENAI_MODEL` are set in all three var tables; a different alias needs the same name in the Worker var and the workflow's repository variable.
- A Cloudflare token for the workflow (`AGENT_GATEWAY_ADMIN_TOKEN`, else `CLOUDFLARE_API_TOKEN`) with AI Gateway Edit and Secrets Store Write.
- One `apply` run of **Agent gateway keys** from `main`.

Stage A keeps its deterministic stub: with `AGENT_INFERENCE_STUB` on in the throwaway preview, an engine run never reaches the account loop and makes no network call.
