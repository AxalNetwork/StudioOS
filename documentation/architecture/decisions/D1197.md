### 1. What was built

Every read is `requireSuperAdmin` (a plain Admin is 403). Each answers its block with `available` and `reason`. A failed D1 read is 503 `testing_unreadable`, "… could not be read. That is not the same as none.", never an empty list. The log line names the read only, never the statement or a value. **No read carries an email address.**

| Route | What |
|---|---|
| `GET /api/admin/testing/programmes/:uid/events` | TST5's Activity: the programme's `testing_events`, newest first, paged (25, at most 100). Each event has its actor and the applicant it concerns by name; an actor whose account is gone is `null`, never an id. `detail` is the stored JSON. |
| `GET /api/admin/testing/programmes/:uid/applicants` | TST6: any programme's applicants, the same rows as the owner's read (the withdrawn left out). `can_decide` is true on HQ's own and **false on a partner's**. |
| `GET /api/admin/testing/applications` | TST8: every application across programmes, paged, with filters and two sorts (§3). |

### 2. HQ reads a partner's applicants, and decides nothing on them

- **#2382's owner question 2 is read as yes** until the owner answers: HQ reads a partner's applicants, read only, never an email.
- **The read changed, the writes did not.** Pick and decline still go through `ownProgramme`, so on a partner's application they answer 404, as before.
- **`can_decide` tells the page which applies.** The partner's own read (`/api/partner/testing/…/applicants`) now says `can_decide: true` as well, so both reads have the same shape.

### 3. The applications list

| Filter | Values |
|---|---|
| `programme` | a programme's uid |
| `owner` | `hq`, `partner` (every firm) or `partner:<firm id>` (one firm) |
| `status` | left out: everyone but the withdrawn; `all`: everyone; or one of applied, picked, declined, withdrawn |
| `role` | one of the five roles |
| `consented` | `yes` or `no` |
| `tester` | `yes` or `no`: an **active** tester in D1042's pool. Someone still applying to the pool is not one. |
| `q` | the name, at least two characters; `%` and `_` are searched as themselves (`likeNeedle`, D128) |
| `sort` | `applied` (newest first, the default) or `name` |

- **Fixed SQL, every value bound.** Each filter is `(? IS NULL OR …)`, so the statement text never changes with the query. `check-sql-prepare` counts no new interpolation.
- **A bad filter is 400** with a sentence naming the values it takes.
