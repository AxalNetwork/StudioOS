### What a founder chooses

Exactly one aggregate: the venture's **selected** property (`search_console_selections.site_url`, byte for byte), one
whole Monday–Sunday week of provider dates (Pacific Time, as D5840 stores them), search type `web`, and one metric:

| Metric | Value | Unit |
| --- | --- | --- |
| `clicks` | the week's clicks, summed over its reported days | `count` |
| `impressions` | the week's impressions, summed over its reported days | `count` |
| `ctr` | weighted: the week's clicks ÷ its impressions, with both given as numerator and denominator | `ratio` |

The sums are D5840's `weekTotals` over stored byProperty daily rows only. A top-page row is never read, so it can
never be summed in; no query is stored anywhere. A day Google returned no row for (`not_returned`) adds nothing, is
counted in the coverage and named in a note, and is never zero. A reported zero is a true zero.

A preview offers a candidate only when all seven days are stored as final (`complete`) and the metric is defined.
Otherwise it says why with no figure: `not_selected` (a property the venture did not select is never read),
`revoked` (the selection's access is `denied` or `revoked`, the binding member's connection is not active, or it is
switched off for the venture's company), `not_recorded`, `incomplete`, or `undefined` (no reported day, or no
impressions for CTR).

### The candidate

It has the `EvidenceCandidate` shape the shared paths take, plus a `search_console` block:

- `kind` `search-console-aggregate`, `source_table` `search_console_daily_totals`, `provider`
  `google_search_console`, `source_label` `connector`, `strength` `measured`, `area` "Investor narrative and Pitch
  deck", `observed_on` the week's Sunday, `stale` past 90 days, `private_reason` null and `visibility` `private`;
- `search_console`: exact `site_url`, `search_type`, `data_state` `final`, `aggregation_type` `byProperty`, time zone,
  window, metric, label, unit, numerator and denominator, coverage, `revision_key` and each day's revision;
- `summary` and `search_console.meaning` say the figure is organic Google web search activity and **not paying
  customers, revenue or attributed conversions**. `searchConsoleMayBack(metric, claimKey)` allows only the
  `organic_search*` and `distribution` keys and refuses `SEARCH_CONSOLE_NEVER_BACKS` (customers, revenue, MRR, ARR,
  conversions, traction proof and the like) whatever is asked.

### Identity, revision and hash

- `source_ref` = `search-console:web:<week_start>:<metric>:<property key>`, where the property key is 16 hex of a
  domain-separated SHA-256 of the site URL. It names no URL and fits the evidence source-ref pattern. Repeating the
  same choice gives the same `source_ref` and the same hash, and writes nothing.
- `revision_key` = the seven days' D5840 `source_revision`s, dot-joined (`1.1.2.1.1.1.1`).
- `snapshot_hash` = HMAC-SHA-256 under a key derived from `JWT_SECRET` with its own label
  (`studioos:raise-evidence:search-console:snapshot-key:v1`), over the venture, property, window, metric, value,
  numerator, denominator, revision key, coverage and the days' fingerprints. The venture is inside it, so a reference
  from another venture bound to the same property never verifies.

### Recheck

`recheck` takes the recorded `source_ref`, `snapshot_hash` and `revision_key`:

- `current`: the same revisions and the same hash. No review needed.
- `corrected`: one or more days have a newer revision. Each corrected day is rebuilt at its recorded revision from
  `search_console_revisions` (revision r+1's `previous_json` and `previous_fingerprint` hold r). The rebuilt
  original must hash to the recorded `snapshot_hash`. The answer gives `original` and `revised` (value, numerator,
  denominator, revision key), the `corrected_days` and `requires_review: true`. The revised preview is a new
  candidate with a new hash; nothing replaces the recorded one.
- `missing`: the week is no longer stored in full, or the reference does not match this venture's source. A forged
  hash, a revision newer than the source, a history row that is gone and another venture's reference all land here.
- `revoked`: the property is no longer the venture's selection, or its access was lost as above.

Every state but `current` has `requires_review: true`; `stale` is reported on each.

### Gates

Both routes go through the Evidence gate (`evidenceScope(c, true)`): the venture's founders, with the active
company; an admin, an investor, a non-founder member and a support session are refused. Both answer 503
`search_console_unavailable` until `GOOGLE_SEARCH_CONSOLE_APPROVED=1`, as D5840-p2's results read does. Malformed
input is 400 `invalid` before any read.
