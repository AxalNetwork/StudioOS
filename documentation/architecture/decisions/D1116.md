- **Basis:** `main` at `c29b9775`, after D1115 (#2995). Each gap was re-read against it before building, and none was done already.
- **Migration:** none. **Worker:** no change.
- **Canvas:** the owner's "Events Console", `design/incoming/Events Console Page.dc.html` (EV3, EV6, EV8, EV9a, EV17d, EV17f).

### 1. Type and Format (EV6, EV8)

**No new read.** The desk reads every page of D918's list and filters it in the browser (D919). Each row already carries the event's own `type` and `location_kind`, so the filters use those.

- **The words.**
  - Type is one of the twelve stored types (`lib/eventTypes.js`).
  - Format is Online (`virtual`), In person (`in_person`, and the legacy `physical`) or Hybrid.
  - Any other value reads "Not recorded" and matches no Type or Format filter.
- **The address.** `?type=` and `?format=online|in_person|hybrid`. An unknown value is ignored. Both count in the phone's "Filters · [n]".
- **All events.**
  - The table follows the canvas's columns: Event, Type, Starts, Status, Visibility, Format, the counts, Price and ⋯.
  - The filters follow the canvas's order: Status, Type, Visibility, Format, When, Price, Featured, Host.
  - The CSV gains Type and Format in the table's order.
- **Calendar.** It gets the same two filters. Its chip card names the type and the format ("Networking · Hybrid") under the time.

### 2. All events' per-row ⋯ menu (EV6, EV17d)

`RowActions.jsx`. Each table row has ⋯ in its last column, and each phone card has ⋯ beside it.

- **The items, in the canvas's order:** Open, Feature (or Stop featuring), Change capacity, Unpublish, Cancel event and Open as host (`/events/:id/manage`).
- **The rules are the event page's own:**
  - Unpublish appears only for a published event.
  - Cancel event appears only for one that isn't cancelled already.
  - Feature and Change capacity appear on every event, as they do there.
- **The dialogs and writes are the event page's own.** Each write item opens that event's dialog (`EventDialogs.jsx`), which says what it changes before anything is saved, then makes the same `adminEvents` write.
  - Change capacity counts from the row's own D918 counts.
  - Cancel event reads that one event's summary for its paid tickets. Until the summary answers, a paid event says its tickets are still being counted and waits for the refund box, as on the event page.
- **After a write**, the dialog closes, the page says what was done ("[Event] is featured."), and the desk reads its lists again. A refusal stays in the dialog, in its fixed sentence (D1115's `not_published` and `already_cancelled` included).
- **The menu is a disclosure**, as the event page's ⋯ is, not an ARIA menu. Escape closes it and returns focus to ⋯, and a click outside closes it. On a phone, ⋯ and each item are 44 px targets.

### 3. Review's Agenda fact (EV3)

- **The read.** `useReviewReads` reads the selected event's agenda (R5, `GET /api/events/:id/agenda`), as the event page reads it.
- **The fact** says "[n] items · [m] speakers".
  - Speakers are the distinct names the items record, matched regardless of case and spacing. An item with no speaker adds none.
  - "Show agenda ▾" lists each item with its time, title and speaker.
- **Other states:**
  - No item: "No agenda items".
  - Still reading: "Reading…".
  - A failed read, or an answer with no agenda: "Could not be read", with Try again. Never "none".

### 4. EV17f: dialogs as bottom sheets on a phone

Every dialog in `EventDialogs.jsx` passes `phone="sheet"` (D1014's `Lightbox` form): Approve, Send back, Change capacity, Cancel, Unpublish and Feature. On a phone each is pinned to the bottom with the page dimmed above it, as EV9a's capacity dialog is drawn there. Wider, it is the centred dialog it was.
