## D7739 — One protected browser route for private research imports (#7739)

The owner answered **Q1 A, Q2 A, Q3 B, Q4 A** on 20 November 2026:
[recorded answer](https://github.com/AxalNetwork/StudioOS/issues/7739#issuecomment-7049961403).
This is the supported design for Funds, Companies, Markets and the Network import;
it does not state that the routes, console or private store have deployed.

### Apply and read authority

A signed-in Super Admin chooses a file on their device. The browser sends bounded,
idempotent batches directly to Super Admin Worker routes. Writes require the existing
`requireSuperAdminWriteBar` (TOTP session and recent step-up); preview writes nothing.
A run becomes Complete only after stored rows are read back and match its permitted
projection. Record the acting user, deployed `WORKER_DEPLOY_VERSION` and payload digest.
No Actions payload, new production credential or direct production D1 session is the
supported apply route. Real payloads never go to staging, preview or branch databases.

Only Super Admins may read held full records in the import console. Log each full-record
read by record id. A browser-operating agent sees what the signed-in Super Admin sees;
the route choice does not promise protection from that access. #7760 places the owner
at the browser for the real apply.

### Exclude personal content before upload

Q3 B excludes contact columns, email addresses, phone numbers, personal profile links,
person-describing fields and **whole records whose subject is a named individual**.
The browser omits them before sending anything. The validated device file is unchanged.
Production and its backups never hold the excluded content; encrypted retention of it
is not the chosen alternative. Stored-equals-package is proved over the other columns
and eligible records, with withheld/excluded counts explicit. Do not confuse withheld
cells or excluded records with missing or altered stored values.

No private payload or record value may enter Git, an issue, PR, comment, workflow input,
step summary, workflow log, artifact, URL, Worker log/trace, client error report or model
prompt. Held content is never member-served, exported to a file or Sheet, or read by
Eadwyn. Processing is designed for catalogue-source records, not member-consent data.

The issue's backup basis is 30-day D1 Time Travel and 365-day object-locked nightly
exports. The current `backup-d1.yml` header repeats 365 days, while
`documentation/operations/D1_RECOVERY.md` describes a 35-day default and a 365-day
monthly prefix. These statements need reconciliation on #5510; live bucket retention
was not inspected, so this record does not certify a deployed 365-day nightly lock.
Live removal cannot erase earlier locked copies. Neither retention figure authorises
holding excluded personal content or supplies a lifetime for the permitted records.
