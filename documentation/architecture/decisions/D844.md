## D844 — MCP metering on the one AI token ledger: policy, idempotent holds, settle and release

- **Status:** filed by S1 for the owner on 2026-10-21 as #2466, part of #2463 (the MCP engine, member API keys and one AI token ledger). Built for slot S10.
- **Basis:** `origin/main` at `56c2498983`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D629 (the hold and its settle), D640 (a cost above the hold goes to review), D755 (the ledger rows written by triggers), D788 (the member's own monthly limit), D791 (pause) and D666 (`callTool`).
- **Migration:** 525.
- **The plan document** (`documentation/architecture/MCP_API_PLATFORM.md`) lands with #2464's PR and is not on `main` yet. This file is the contract until then. When the plan lands, §3 takes `meteredCall`'s input and output from §2 below, and §8 records this task.

### 1. The decision

Every billable MCP tool call, connector call and workflow step reserves and settles through the AI token ledger that already exists: `reserveAiBudget` and `settleAiReservation` (`services/aiBudget.ts`).
- There is never a second balance, ledger or conversion rate.
- A retry never charges twice.
- Every failure releases its hold.
- Prices are integer micro-USD, the ledger's own unit. Product copy says "AI tokens".

### 2. As built

**Migration 525** (`525_ai_reservation_idempotency.sql`):
- It adds `ai_budget_reservations.idempotency_key TEXT`.
- It adds a unique index on `(user_id, idempotency_key)` where the key is not NULL. One member's key never collides with another's, and NULL rows never collide.
- It is additive: every existing caller passes no key, and its rows stay NULL.
- The table is migration 419's and is not in `schema_baseline.sql`, so the baseline is not edited.

**`reserveAiBudget(env, userId, quote, now, { idempotencyKey })`:**
- With a key, a call first reads the hold that key already took.
  - If one exists, it returns that hold (`replayed: true`, with its `status`) and takes no other.
  - It does this before the pause and review checks, so a run already in flight keeps its hold.
- Otherwise the keyed insert is the existing atomic `INSERT … SELECT` plus the key, with `ON CONFLICT DO NOTHING`. If a concurrent call reached the key first, this insert is a no-op and the hold is read back. Two racing calls with one key hold once.
- Without a key, the statement is the one every caller used before, unchanged.
- The two forms are two literal statements, so neither splices SQL (`holdStatement`).

**`services/metering.ts`:**
- **`METERING_POLICY`** (version `d844-1`) lists every registered MCP tool as `mcp.tool.<name>` at `price_microusd: 0`.
  - `structure_with_studioos` pays for its model through its own `aiRouter` hold.
  - The test fails on a registered tool the policy does not list.
- **`quoteFor(operation, units, policy)`:** the price times the units. An operation the policy does not list, or units that are not a positive integer, are refused.
- **`meteredCall(env, { userId, executionId, operation, component?, quoteMicrousd, apiKeyUid?, pricingVersion?, timeoutMs?, signal? }, run)`** runs in this order:
  1. **Quote:** the server's, never the tool's input or the model's output.
  2. **Hold,** under the key `exec:<executionId>:<component>`. The component defaults to the operation.
  3. **Run.** The run may report the provider's cost (`meter.reportCost`, an integer).
  4. **Settle** at the reported cost, else the policy's quote. The unused part of the hold is released.
  5. **Release** (settle 0, `refunded`) when the run throws, passes `timeoutMs`, or its `signal` aborts.
- **What it returns:** `{ value, usage }`, where `usage` is `{ reservation_uid, reserved_microusd, charged_microusd, refunded_microusd, pricing_version, review }` for the usage row (#2465, D843). Until #2465 is on `main`, these are the typed return. A failed call carries the same object on the thrown error, as `meteringUsage`.
- **A quote of 0 holds nothing.** The run is the run, and `reservation_uid` is null.

**The composite rule:**
- A tool that runs AI through `aiRouter` is charged by that run's own hold, as every run is.
- A tool's fee is a second component under the same execution id, with its own key.
- Each is held and settled once, and nothing is counted twice. The test runs a real `aiRouter` run inside a priced tool and finds two holds: the fee, keyed `exec:<id>:fee`, and the run, unkeyed.

**The refusals** (`REFUSAL_WORDS`). Each is an MCP error result `{ error, code }`, in plain words, with no amounts:

| Ledger refusal | `code` | What the member reads |
| --- | --- | --- |
| `budget_user_month`, `budget_user_day` | `insufficient_tokens` | "Not enough AI tokens. Add AI tokens or wait for next month's allowance." |
| `spend_limit` (D788) | `monthly_limit` | "Your monthly limit is reached. Raise it in Usage, or wait for next month." |
| `ai_paused` (D791) | `ai_paused` | "AI is paused on this account. Contact support." |
| `budget_review` (D640) | `budget_review` | "An earlier AI charge on this account is being checked. Try again once it is settled." |
| a replay of a finished execution | `execution_closed` | "This call has already finished. Start a new one." |

The issue named three sentences for four refusals. `budget_review` gets its own sentence, because "Not enough AI tokens" would tell a member with tokens to buy more.

**`callTool`** (`mcp/server.ts`):
- After the grant, scope, rate-limit and company checks pass, a tool the policy prices above 0 runs inside `meteredCall`. Its execution id is a new UUID per call until #2470 (D842) gives each call its own.
- A refused check holds nothing.
- A metering refusal is logged `refused` and answered in its words.
- A tool the policy does not list runs unpriced, with a warning, so a tool registered before its price never charges anyone by accident.
- With v1's zero prices, no member's call changes. The priced path is tested with a test-only policy passed to `callTool`. The server always uses its own.

### 3. The failure table

| Case | What happens | Charged |
| --- | --- | --- |
| **Before execution** (a check refuses, or the hold is refused) | No hold, or the refusal in its words. The run does not start. | Nothing |
| **The hold cannot be taken or read** (the database fails) | The error propagates. The call answers "StudioOS could not complete that call." Fails closed: no hold, no run. | Nothing |
| **After the hold, the run throws** | The hold is released (`refunded`, actual 0). The error carries `meteringUsage` with `charged_microusd: 0`. | Nothing |
| **Timeout** (`timeoutMs`) | The same release. The run's late result is never used. | Nothing |
| **Cancel** (`signal` aborted) | The same release. | Nothing |
| **Partial execution** | The fee's hold is released. Any AI the run used was held and settled by its own `aiRouter` hold, at the provider's reported cost, as every AI run is. | Only the AI the provider ran |
| **The release itself fails** | The hold expires after five minutes, and the next read of the member's budget releases it (`releaseExpired`). The caller sees the run's own error. `meteringUsage.charged_microusd` is null (unknown). | Nothing, once it expires |
| **Missing usage** (the provider reports no cost) | It settles at the policy's quote. | The quote |
| **Duplicate callback** (settle replayed) | `settleAiReservation` changes only a `pending` hold, with a CAS on `settlement_uid`. A second settle does nothing. | Once |
| **Retry of the same execution** while its hold is pending | It returns the same hold. Both runs settle against it, and the second settle does nothing. | Once |
| **Retry of a finished execution** (settled or refunded) | Refused, `execution_closed`, without running. Running it would be free; charging it would be twice. A new call has a new execution id. | Nothing more |
| **Insufficient tokens, monthly limit, pause, review** | Refused at the hold, in words. | Nothing |
| **Provider reconciliation** (the reported cost is above the hold) | The hold goes to `review` with its recorded cost (D640) for a Super Admin to charge or refund. Never capped silently. The member's next hold waits until the review is decided. `usage.charged_microusd` is null and `review` is true. | Decided by HQ |

### 4. Concurrency

- **Many calls at once:** the hold is one atomic `INSERT … SELECT` that counts every pending hold, so concurrent calls cannot pass the balance. The member's own limit is the insert's last clause, so they cannot pass that either.
- **Two calls with one key:** they hold once, through the unique index and `ON CONFLICT DO NOTHING`.

### 5. Security

- **Price and units** come from the server-side policy and the provider's reported usage, never from tool input or model output. `callTool` takes no price from the call's arguments; the test passes `price_microusd` and `quoteMicrousd` as arguments and is charged the policy's price.
- **Errors carry no amounts.** No key, token or personal data is logged.
- **SQL:** bound statements only, and no raw-interpolated statement is added.

### 6. Not here

- The usage row itself (#2465, D843).
- Per-call execution ids from the client (#2470, D842).
- Prices above 0, which arrive with the providers and flows that charge (#2474, #2476).
