### Migration 728: the six tables

All new tables, so every statement is `IF NOT EXISTS` and the file re-runs cleanly. Nothing is altered, rebuilt or backfilled. Scope rows follow #3727's pattern (712, 727): `scope_kind`, with exactly one of `company_id` and `project_id`, both immutable ids.

| Table | For | What it holds |
|---|---|---|
| `agent_task_runs` | E3 | One row per run attempt: `uid` (also the Workflow instance id), `agent_id`, `task_id`, `attempt` (UNIQUE with the task), `status` (`admitted`, `running`, `waiting_decision`, `done`, `refused`, `failed`, `cancelled`, `halted`, `scope_moved`, `step_lost`), `step` (`load` … `after`), `steps_json` (the step timeline the page reads; summaries never hold a prompt), `workflow_instance_id`, `admitted_company_id`, `usage_log_id`, `proposal_uid`, `refusal` (a code), and timestamps. |
| `agent_duties` | E5 | An agent's recurring duty: `template_key`, `title`, `module`, `option`, `cadence` (`daily`, `weekly`, `monthly`), `weekday` (weekly only) or `day_of_month` (monthly only), `hour_utc`, `next_due_at`, `last_claimed_at`, `last_outcome` (a code), `status`. |
| `agent_handoffs` | E5 | One step of a chain: `chain_uid`, `depth` 1–3 (UNIQUE with the chain), from agent, to role and agent, the tasks it came from and created, `title`, `why` and `note` (≤ 1,000 characters each; the note is untrusted), `status` (`proposed`, `accepted`, `discarded`, `refused`), `refusal` (a code), who decided and when. |
| `agent_memory_notes` | E5 | A note an agent keeps in one scope: `kind` (`decision`, `fact`, `summary`), `body` (1–1,000 characters, never a raw prompt), the run that wrote it, `expires_at` (set when the agent is removed). |
| `agent_custom_roles` | E4 | A scope's own role, key `custom:<uid>`: `name` (≤ 60), `mission` (≤ 600), `works_in`, `reads`, `may_propose`, `hands_off_to` and `kpis` as JSON arrays, `tone`, `status` (`live`, `retired`). |
| `agent_scope_settings` | E3 | One row per scope: `engine_paused` (0 or 1), `max_parallel_runs` (1–5, default 2). A missing row means the defaults. |

**What the schema holds, and what it leaves to the services:**
- **The schema holds:**
  - one live run per agent: a partial unique index on `agent_task_runs (agent_id) WHERE status IN ('admitted', 'running')`;
  - one live duty per agent and template (`duty_exists`);
  - one settings row per scope;
  - every limit above.
- **The services hold:** five live custom roles per scope, the 20-runs-a-day limit, the 90-day note expiry, and handoff loops (`handoff_loop`). Each is a product rule with its own refusal, so it is not a schema CHECK.

**Erasure.** A deleted `team_agents` row takes its runs, duties, memory notes and its own handoffs with it (`ON DELETE CASCADE`). A handoff made to it keeps its row without the agent (`SET NULL`).

`team_agents.paused_reason` has no CHECK (712), so the runtime's added reasons (`spend_limit`, `ai_paused`, `daily_limit`, `scope_archived`) need no migration. The runtime part of this decision documents them.

### Checks

`cloudflare-worker/test/agent_engine_migration_728.test.ts` runs 5 tests on the real migrated schema, with foreign keys on:
- the six tables, additive and re-runnable;
- single flight, `(task, attempt)`, and the status and step vocabularies;
- a duty's cadence and day, and one live duty per template;
- handoff depth, note length, the scope's run limits and default, and one scope per row;
- an agent's deletion leaving none of its rows.

Mutation-checked: each change below fails the tests.
- Dropping the single-flight index, `UNIQUE (task_id, attempt)`, the weekly-day CHECK, the duty uniqueness or the run's cascade.
- Widening the depth to 4, the note to 2,000 characters, the run limit to 6, or the status vocabulary.
- Changing the default of 2.
