## D4834 — Practice Earnings as a recorded ledger, with per-source states, a phone section row and an unsaved-note dialog (#4834)

- **Status:** built 2026-11-10 (#4834, Practice UX 6/6). Part of #4834: the parts that need a backend field are listed under "Not built".
- **Canvas:** `design/incoming/Practice v2 Page.dc.html` and `design/incoming/Practice v2 · Boards.dc.html`: PX-07 A (ledger) and B (unsaved changes), PX-08 (states), PX-10 (phone), PX-13 (accessibility) (D4874).
- **Migration:** none. **Worker:** `GET /advisors/me/ledger` gains `lines` and `states.paid_out_count`; the period-note key accepts a calendar month (`2026-11`). Both routes stay `requireMyAdvisor`: an advisor reads only their own records, with every value bound.
- **Builds on:** D4679 (a status change never reprices; only the latest request writes), D4702 (a capped list sums the rest in one row), D4713 (unsaved note text is resolved before the period changes), D4714 (an unread source is never "none"), D4833 (the Practice v2 pattern inside the current shell).

### What the advisor sees

- **Period selector:** This month · Last month · Quarter · Year · Custom, with the period's own name beside it ("November 2026", "Q4 2026"). Quarter and Year are the current ones. Custom takes two days, both included; nothing is read until both are set.
- **Cards, each with its basis:** Recorded billed ("From 12 priced sessions · 1 session has no recorded price."), Recorded collected (sessions marked collected), Outstanding (billed, not marked collected), Platform fees (at each record's own rate). **Paid out** is a card only when at least one paid payout is recorded in the period; none recorded is no card, and an unreadable payout table is a card that says so. Nothing on the page is labelled "You received": the store records billing and collection as the advisor marked them, and money reaching them only as a paid payout.
- **Ledger:** one record per session in the period: Client, Session / engagement, Price, Billing state, Recorded collected, Platform rate, Platform fee, Net, Date. Rate and fee are the ones stored on the record when it was priced, read as frozen facts; a record priced before rates were stamped says "Not recorded · priced before rates were stamped" and is counted on the fees card. A billing-state change never reprices (D4679, unchanged). An unpriced record shows "Not recorded", never $0; a billed record's Recorded collected says "Not collected". The newest 200 records are listed and the rest are one summed row, on screen and in the CSV, so the records add to the totals.
- **Note for the period:** saved against a month, quarter or year key; a custom range carries no note and says so. Switching period with unsaved text opens "You have unsaved changes" (Stay · Discard · Save note): Save files the text against the period it was written for and then switches; Discard drops it; Stay, Escape or the backdrop keeps it. An older period's late answer, ledger or note, is dropped by ticket (`latestOnly`) and never drawn under the newer heading. Eadwyn's "Draft it" stays here as this page's task (D773's rail option); nothing is saved until the advisor saves.
- **Payouts:** setup (the account's own state and gate sentence, Connect / Continue setup / Check with the provider), recorded balance ("Not recorded · Axal holds no balance on your behalf") and history are separate. Unreadable payout data says "Payout information could not be read" with Try again, never "No payouts recorded".
- **Unavailable:** with no advisor profile on the account, the page is "Earnings unavailable" / "No advisor profile is attached to this account." with a "Learn why" disclosure, and no figure.
- **States:** `SourceState.jsx` draws loading, successful empty, unreadable, not recorded and withheld in PX-08's words. It is deliberately small and named as a stand-in, to be swapped for #5129's shared component. The ledger, the note, the payout setup and the payout history each have their own state, so one failing source never blanks the page.
- **Phone (below 1024px):** the Practice nav is one horizontally scrollable section row, Overview · Opportunities · Engagements · Sessions · Delivery · Earnings, with 44px targets (`ZoneNav`'s opt-in `row`, passed only for `/practice`). Below 768px the ledger is stacked record cards; the dialog is a bottom sheet (the shared `Lightbox`).
- **Accessibility:** visible focus rings on every control, a labelled note field, `th scope="col"` and a table caption, a billing state as a word and a shape (never colour alone), the dialog from `Lightbox` (role, `aria-modal`, focus moved in and contained, Escape, focus returned), saves and failures announced through `SaveNote`'s live region, and the period name in a polite live region.

### Departures from the canvas

- **No Practice v2 shell.** As for D4833, Earnings is a body inside the current advisor shell. The section row is the shell's existing zone row with an opt-in; this PR builds no separate Eadwyn panel (the rail is #5130's).
- **Sessions only in the ledger.** The canvas draws engagement milestones ("Pricing sprint · milestone 1") as ledger lines. Engagements store a contract amount per cycle and no billing state, so no milestone is a billed record; the page says retainers are not ledger lines.
- **Recorded collected is the record's whole price** when it is marked collected: the store has no separate collected amount.
- **Recorded balance** is drawn as Not recorded: nothing stores a balance.
- **Kept, though v2 does not draw them:** Export CSV (now the records on screen, with the summed row and the total) and Download 1099 summary in the ops row, the "No margin here, only revenue" limit, and the settlement sentence ("nothing has been charged under it"). D4's concentration tile, by-client table, retainer column and three-state payout set are gone with D4.
- **Section-row order:** the row is in the canvas's order (Sessions before Delivery) on `/practice` only; `shellConfig.js` keeps its order, which other guards pin.
- **Dark mode** uses the existing tokens.

### Not built (backend required)

- Included pricing (D4874): not stored, so no card or record shows it.
- A recorded collected amount separate from the price, and engagement milestones as billed records.
- A recorded payout balance.
- A note for a custom range.
