## D6131 — Investor onboarding v2 questions and review (#6131)

Build the frontend-only portion of the approved D6128 and D6128-p2 canvas:
seven questions plus Review; sectors and regions share the fourth question,
exclusions precede thesis, and the final three questions have explicit skips.
Review names every current answer and lets a member edit one question and
return directly. Skipped answers, empty selections and missing records remain
distinct. Internal progress metadata and retired slider values are not shown
or copied to the investor profile.

The opt-in review kind in OnboardingWizard preserves the founder/partner
flows. Investor progress carries a version marker, so old eight/nine-position
records map to their original question rather than the new numerical position.
Noninteger positions fall back to the first question; positions are bounded.
Failed reads have a retry state; failed intermediate saves stay on the question.
Start over confirms and saves the cleared progress before clearing the screen.
An immediate press lock covers progress writes and the optional entity save.

The NFX taxonomy remains canonical. Search retains picks; a thesis sector cannot
be added as an exclusion, while a legacy overlapping exclusion can be removed.
Entity details load the existing account record, retain only the six drawn
fields, and PUT only those fields after an edit, before progress advances.
Skipping the entity block neither writes nor erases the account's record.
The accreditation answer remains self-declared, never verification.

Ready-to-commit admitted investors get the fund workspace as their primary
ending; maybe retains its secondary fund door and Exploring keeps membership
status. No application is created or accreditation prefilled by a navigation.
The existing D6135 honest profile-copy failure/retry remains in force.

Remaining D6128 store work is not represented as delivered here: the NFX
server acceptance rule, an Eadwyn thesis-draft endpoint, profile-first atomic
completion/read-back, and fund-application prefill/target-range validation.
Those items belong to their store builds; this PR is Part of #6131. In
particular, Review here shows the member's saved-progress answers, not a
claim that the investor-profile row has been read back successfully.

Canvas departures: the optional entity block saves on Continue through the
existing corporate-profile endpoint; no draft action is drawn for an absent
thesis-draft endpoint. The existing final copy/retry boundary is retained until
the store build supplies the new completion contract. The phone uses the
shared wizard's wrapping controls rather than introducing a separate sheet
with a second answer state. Light/dark browser checks at 390 and 1440 cover
review/edit-return, search, retained answers and horizontal overflow.

This changes the frontend; there is no migration, binding, new endpoint or
production configuration. Roll back the application commit to restore the old
wizard. Hosted acceptance and independent vendor review remain separate gates.
