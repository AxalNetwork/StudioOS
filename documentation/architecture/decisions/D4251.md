## D4251 — AI model policy and the kill switch, without a deploy (#4251)

**Deck v2 B10a, slot S02 · 2026-11-03.** Split from #3786 (B10) by S1. Migration `202611030919_ai_model_policy.sql` (D4106 naming). It unblocks #3792's runbook step "switch off a model".

### The policy

`ai_model_policy(model_id PRIMARY KEY, enabled, plan_min, note, updated_by, updated_at)` holds one row per model HQ has a policy for, keyed on its `catalogue.ts` id. No row is no policy.

- **`enabled = 0`** switches the model off for everyone.
- **`plan_min`** (`free`, `growth` or `studio`; NULL is any plan) is the lowest plan that may run it, by `requireTier`'s own rule (`userMeetsTier`).
  - A floor that cannot be checked admits no one above free: an unknown floor value, or a run with no member.
- **`note`** is HQ's own words, shown on the HQ page.

`services/ai/modelPolicy.ts` reads and judges it.

### No deploy: where it bites

The policy joins the feature flags' switched-off set (`MODELS_OFF`, D1509). `catalogue.isOffered` and `catalogue.refusalFor` read that same set, so the policy reaches:

- **The run path:** `featureFlags.modelsOffFor`, which `aiRouter.chooseModels` asks on every run. A model switched off is refused `model_not_offered` on the next call.
- **Every reply that offers models:** `featureFlags.flagsFor`, behind the rail, the deck's element models, the lightbox chips and the generation side (`elementModelFor`). A member's pick of the model is kept and reads "<Model> is unavailable. Using <next>.", as a flag already does.

The table is read from D1 on each of those calls, with no cache, so nothing stands between HQ's write and the next refusal. A table that cannot be read (not migrated yet) is no policy, and a model switched off by a flag stays off either way.

### The routes (`routes/admin_ai_element_models.ts`)

The module mounts itself at `/api/admin/ai/element-models` (#4105).

- **`GET`** returns the grid:
  - `groups` and `elements`, from the one element catalogue (`elementModels`);
  - `models`: each catalogue model a grid element offers, plus any model with a policy row. Each carries `offered` (the catalogue's own answer, before any policy), `required`, the element ids it serves, and its `policy` with `updated_by: { uid, name }`. There is never an email.
- **`PUT { model_id, enabled, plan_min?, note?, reason }`** writes the row.
  - **Refusals:**
    - a model id the catalogue does not hold: 400 `unknown_model`;
    - a reason under 10 characters: 400 `reason_required`;
    - switching off or fencing the safety model (`@cf/meta/llama-guard-3-8b`, which runs on every call): 409 `model_required`.
  - **Audit:** each write is one admin audit row (`ai_model_policy_set`, through `logAdminAction`) with the reason, and the policy before and after.
- **Who:** HQ only, meaning a Super Admin on HQ's deployment (`requireSuperAdmin`). A plain admin, a member and a branch's Super Admin are refused 403.

### The HQ page

HQ › Decks gains a sixth tab, **AI models** (`/admin/platform/decks/models`, `AiModelsTab.jsx`), with its client in `frontend/src/lib/api/adminAiModels.js` (D527).

- **The grid:** one row per model. One column per element group, showing how many of that group's elements the model serves. Then the state (On, Off for everyone, a plan floor, or not offered by the catalogue), with HQ's note and who changed it last.
- **Change…** opens one dialog: on or off, who may run it, a note, and the reason.
  - Save stays disabled until the reason is long enough.
  - For the safety model, the switch is locked and the dialog says why.
- **Refused reads:** a refused read says only a Super Admin sees the tab. A failed read is never an empty grid.

### Not redone, and not here

- The per-deck element models (D1503, #3754), HQ's defaults and locks (D1549), the pd9o refusal and the org-lock adapter are unchanged. They still choose among the models this policy leaves offered.
- The agents' locks (`ai_model_locks`, D4162) are separate: they apply to agent runs only, and this policy applies to every run.
- #3786 keeps the pages that read A17's events (#3761).
