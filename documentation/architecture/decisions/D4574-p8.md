## D4574 part 8 — the Research router extraction: client prep out of `research.ts` (#4574)

This part continues `D4574.md` and `D4574-p7.md`. It is the "Research router
extraction" that #4613 hands to #4574. Cites #4573's baseline method: the
`wrangler deploy --dry-run` metafile read by
`scripts/perf/worker-bundle-baseline.mjs`, before and after on the same tree
(`origin/main` 6539655091).

**This is a maintainability change, not a performance one.** The routes still
ship in the same script, so the script does not shrink. The gain is a
5,359-line router that is 392 lines shorter, and one cohesive module that can
be read, reviewed and tested on its own.

### What moved

`routes/research_client_prep.ts` (new) holds the firm's proposal-prep records,
eleven routes on three tables:

| Routes | Table |
| --- | --- |
| `GET`, `POST /api/research/market-readings`; `GET`, `DELETE …/market-readings/:uid` | `research_market_readings` (migration 223) |
| `GET`, `POST /api/research/brief-notes`; `PATCH`, `DELETE …/brief-notes/:uid` | `research_brief_notes` (migration 222) |
| `GET`, `POST /api/research/attachments`; `DELETE …/attachments/:uid` | `research_attachments` (migration 222) |

The block is **byte for byte** what `research.ts` held (lines 1227–1618 on
6539655091), in the same order, with its row types, DTOs and its one helper.
The file's router keeps the name `research` so that `git diff --color-moved`
shows a pure move and the handlers' text is unchanged. The file adds only its
header, its imports, the same one-line `newUid` eleven route files already
define, and its `mount`. `research.ts` loses the block and its now-unused
`marketReadingRead` import, and keeps a two-line pointer. Nothing else in
`research.ts` changed.

**Where it mounts.** `mount = { path: '/api/research', router, before:
[research.ts's router] }`. The registry (#4105) mounts it immediately ahead of
`index.ts`'s `app.route('/api/research', research)`: after every middleware,
after `research_overview`, `research_markets` and `research_sectors`, as these
routes were. No route the Worker serves matches a request for one of them, so
mounting them ahead of the rest of `research.ts` changes no precedence. The
proof is below.

### The proof

**Route inventory.** A scratch script imported `index.ts`, took the composed
app and listed every non-middleware route under `/api/research`. For each
route it built a sample request (each `:param` becomes a literal) and asked the
app's own router which handlers run, in order (middleware by its index).

| Under `/api/research` | Before | After |
| --- | ---: | ---: |
| Routes (`METHOD path`) | 91 | 91 |
| The same set | — | yes |
| Handler chains that differ | — | 0 of 91 |
| Order of the 80 routes that did not move | — | unchanged |
| Order within the 11 that moved | — | unchanged |

The one request that matches two routes, `DELETE /funds/sheet` (the sheet
route, then `DELETE /funds/:uid`), is not in this block, and its chain is
unchanged.

`scripts/build-auth-inventory.mjs`, before and after: 4,104 routes on both
sides, and every route's method, path, family, gate, ownership evidence,
writes flag, review reason and ledger entry is identical. Only the `file` and
`line` of the eleven moved routes changed. `--check` passes, and no ledger
entry was added or changed.

**Tests.** Every existing Research suite passes. Two read this block's text by
file path, so their path now names the new file. Their assertions are
unchanged:

- `cloudflare-worker/test/research_market_reading.test.ts`
- `frontend/test/research_client_prep.test.mjs`

Pointed back at `research.ts`, they fail (2 and 3 assertions), so they still
check the code. `cloudflare-worker/test/research_client_prep_4574.test.ts`
(new, 3 tests) reads the real Worker:

1. The router mounts once at `/api/research`, immediately ahead of
   `research.ts`'s.
2. Each of the eleven routes is registered by the new router only.
3. A request for each one matches no other route, and its own route is last
   in its chain.

Mutation-checked: 6 mutants, all caught. They are: `before` dropped; `before`
emptied; a catch-all `GET /:any` in `research.ts`; a moved route left behind
in `research.ts`; a moved route's path changed; a trailing `use('*')` in the
new router.

### Why the rest of `research.ts` stays

Each other group is pinned by tests that would have to change, not just be
re-pointed:

- Library and Ask, the drafts band, the fund shortlist and its directories,
  benchmarks and diligence are each exercised by suites that mount
  `research.ts`'s router alone. Moving a group would make those suites mount
  a second router.
- Several source scans read `research.ts` as one corpus, and a moved group
  would silently drop out of them. Examples: `research_stores_scoping`'s
  owner filter over `research_funds` and `research_benchmarks`, and
  `research_fund_dossier`'s slice that ends at `GET /benchmarks`.

Extracting those means re-pointing behavioural and scanning tests in the same
PR. Each is its own reviewable step, so they are left for later.

**Still open on #4574:** a split of `services/` and `routes/`, which still
needs #4573's production CPU figures, and any further Research groups on the
terms above.

**Rollback:** revert the PR. The block goes back to its place in `research.ts`,
and the registry drops the row on its next build.
