## D688 — New venture boards for Build, Raise and Grow

Issue #1652, part of #1440. No migration or new API route.

Each module decides whether it is empty from its own store. There is no venture flag and no separate overview mode. An empty card carries the canvas line and one action from the Worker. A record outside a chart's range retains the established state, reason and action. A figure with no source record has a null value; a zero is a count only after a source record exists.

`?add=1` opens a module's first form on load or when the query changes. Solution design has Add feature first, then Add risk. Score readiness runs the existing rescore route, and New version sends the required investor type to the existing narrative route. Both carry the project in the query. Saving or closing removes `add` with a replace. Creating a venture selects its returned project id in the URL.

Since D695 (#1656), `?add=1` replaces the URL with the first Add's address, `/<cycle>/<slug>/new`, the rest of the query kept; the form opens there, and closing it leaves `/new`.

Build returns a phone focus only while its cards are empty, allowing Operating systems to be `not_recorded` when there is no company. The focus says “Add the first feature.” and links to Add feature. It has no meter, Then line or module index. Raise and Grow have no new phone focus.

D692 (#1701) moves this rule into `services/cycleFocus.ts` unchanged, and gives Build, Raise and Grow their established focus, meter and index; see D692.md.

### Canvas departures

- Fundraising readiness uses **Score readiness** because a planned round does not populate its score chart.
- Operating systems opens Connect a tool; its module page has no Add form.
- The Build phone focus omits the conditional Validate “Then” line and the redundant module index.
- Empty card captions remain hidden because their charts are absent. Actions are links, so they work.
- Without a company, Operating systems, Systems connected, Team expansion and Headcount remain `not_recorded`, with their existing reasons.
- Cards with records outside the visible range keep their existing reasons and actions; a deck with no views still offers Share.
- An enabled tool that is not mapped to a core system still keeps its existing reconnect action; it is recorded in the module's tool list.
