## D8522 — One contract every AI usage row satisfies, one writer, a guard (#8522)

**Decision date:** 2026-11-25. **Scope:** `ai_usage_logs` and `recordUsage` (`services/aiRouter.ts`), a new pure
module `services/aiUsageContract.ts`, one migration (expand only), one test file. Part of #8509 (row B6). Step 1 of
the issue, the production read, is not part of this decision (see "Open").

### What was found

Every call that records a model run reaches `recordUsage`: the router's run paths, `aiProviders.ts` (D851), the
image tools, live transcription, the rehearsal stream and the agent and deck runs that go through `run()`. Nothing
else inserts into the table; the only two `INSERT INTO ai_usage_logs` statements in `cloudflare-worker/src` are
inside `recordUsage` (with and without `agent_id`). So "every writer goes through one function" was already true
in the code; what was missing was the contract on what that function writes, and a guard that keeps it true.

What a row could lack:

- **Provider** and **request id**: no column. Only D851 provider rows named a provider, inside `units_json`.
- Whether the **token counts** were the provider's or zeros because the provider reported nothing: the columns are
  `NOT NULL DEFAULT 0`, so "not reported" and "zero" looked the same to `aiUsageAdmin` and `tokenAnomalies`.
- A call with **no `userId`** bound `undefined`, which D1 rejects; the row was lost with a warning.

### What changes

- **The contract** (`aiUsageContract.ts`): surface, provider, model, input and output tokens with a
  `tokens_reported` flag, the paying account (member, agent, or "not reported") and the request id. A field a writer
  cannot supply reads `not reported`, never absent. `contractProblems()` names every field a row lacks.
- **Three columns** (migration `202611250054_8522_usage_contract_columns.sql`): `provider`, `request_id`,
  `tokens_reported` (1, 0, or NULL for a row written before this). Nothing is backfilled. The runtime bootstrap in
  `aiRouter.ts` declares the same columns.
- **`recordUsage`** builds the contract from the caller's `who`, usage and charge, writes the three columns, and
  warns if the check ever finds a problem. `UsageWho` gains an optional `requestId`; `UsageMeta` gains optional
  `provider` and `tokens_reported`. Defaults:
  - provider: the caller's, else `units.provider` (D851), else the model's prefix (`@cf/` is Workers AI,
    `vendor/model` is that vendor), else `not reported`;
  - `tokens_reported`: the caller's, else D851's `units.usage_reported`, else true when tokens were counted, the
    run was refused or the answer was cached (a real zero), else false;
  - request id: the caller's, else `not reported`. No caller passes one yet, so every row reads `not reported`
    until the routes hand the request's id to `run()`; that is now visible instead of silent.
- **`surface` and the payer** keep their columns: a NULL `surface` or `user_id` is how those columns have always
  said "not reported", and readers filter on them, so they are not rewritten to the words.
- **A NULL `userId` binds NULL** instead of `undefined`, so a system run is recorded.
- **The guard** (`ai_usage_contract_d8522.test.ts`): reads every string literal in `cloudflare-worker/src` and
  fails on an `INSERT` or `REPLACE` into `ai_usage_logs` outside `services/aiRouter.ts`, and when `aiRouter.ts` does
  not hold exactly the two statements. An `UPDATE` (a stamp on an existing row) is not an insert.

### Tests

The file drives each writer with the arguments it passes today (router run, router refusal, deck run, agent run,
D851 provider run, image tools, the two minute-metered streams, a system run) and holds the stored row to the
contract, plus tests of the contract itself and of the guard. 16 mutations, 16 caught.

### Open

- **The production read (step 1)** needs production access this session does not have. The owner or slot S04 should
  post the latest row date and the row count per surface over 30 days, so a surface that stopped writing is found.
  No number is claimed here.
- **Request ids**: the routes do not carry one into `run()`. Passing the request's id (for example Cloudflare's
  `cf-ray`) is a follow-up per route; the contract and the column are ready for it.
- **Readers**: `aiUsageAdmin` and `tokenAnomalies` do not yet read `tokens_reported` or `provider`. They can now
  tell a not-reported zero from a real one; changing what they show is a separate issue.
