## D1320 — Account › Builder › API usage, and Activity's request history

S17, 2026-10-27, for #2481 (APIU1–APIU12, canvas `design/incoming/API Usage Page.dc.html`).
Built on #3477's branch (D1315), as S1's STATUS on #2481 says, with `main` merged. No migration.

### 1. What it draws

- **API usage** (`/account/builder/usage`, `ApiUsagePage.jsx`): APIU1, APIU2, APIU5, APIU7
  and APIU9–APIU11, plus APIU12's key notice.
  - **The toolbar:** range chips (7 days, 30 days, Month to date, Custom), the Key filter
    (with revoked keys under "Revoked"), Compare with previous period, and Download CSV.
  - **Four tiles:** Requests, OK, Failed (which opens Activity filtered to failures) and AI
    tokens charged, with what was returned.
  - **Chart 1, requests and AI tokens by day:** bars for OK and Failed, AI tokens as a line,
    the previous period as a dotted line, and a dashed hairline before usage was recorded.
  - **Chart 2, where the AI tokens went:** by key, provider, connector or tool. It shows the
    top five and "Other", with a table that includes the typical time (p50).
  - **Limits and alerts:**
    - each key's month against its own limit;
    - the account's limit (D788);
    - the rate limits (D849);
    - the alerts.
- **Activity** (`/account/builder/activity`, `ActivityPage.jsx`): APIU3 and APIU6.
  - **The log:** newest first, 100 a page, paged with Newer and Older. Each row has the time,
    the caller, the surface, the tool, the company, the outcome, the time taken and the AI
    tokens. A failed row carries its reason's line.
  - **Filters:** Caller (each key or each assistant connection), Surface, Outcome, Tool,
    Company and the range, all in the address.
  - **Search:** a request ID opens it, a key's name filters to it, and anything else is a
    tool. DEV5's "Calls by day" stays.
  - **Failures** (`?outcome=failed`, APIU6): a band of outcomes and the top three reasons.
- **The request drawer** (`/account/builder/activity/[uid]`, APIU4): Who, When, AI tokens
  (Held, Charged, Returned), Why it failed with what to do, and the execution ID with Copy.
  - Another member's request reads "This request is not on your account" (APIU12). Nothing
    says whether it exists.
  - It opens over the log, which stays mounted. On a phone it is a page.
- **The phone layout** (APIU8): two tiles a row, the log as cards, filters behind
  "Filters · N", and touch targets of at least 44px.
- **Dark mode** (APIU7): every surface carries its dark pair, and violet becomes `#a78bfa`.

### 2. Worker additions (on D845's routes, Worker first)

| Read | What it adds | Why |
|---|---|---|
| `GET /api/developer/usage/events?grant=` | one assistant connection's calls | contract gap 2: the Caller filter for an assistant |
| `GET /api/developer/usage/events?outcome=failed` | every call that did not succeed | APIU6, and the Failed tile's link |
| `GET /api/developer/usage?group=category` | calls grouped by D843's reason | APIU6's "Top reasons" (contract gap 5) |
| `GET /api/developer/usage/events/:execution_id` | one request, the history's columns | APIU4 on a reload or a shared link |

- **Tenancy.** Every statement keeps `WHERE e.user_id = ?` with the session's user. Another
  member's grant reads as none, and their execution id answers the same 404
  `unknown_request` as an id that does not exist.
- **Binding.** All four are bound statements with no interpolation.
- **Tests.** `cloudflare-worker/test/developer_usage_d1320.test.ts`.

### 3. Rules the page keeps

- **Never a zero for a missing value.** A charge that was never metered is "Not recorded",
  with its reason (the hold has not settled, the request was not metered, or "Not recorded
  before [date]"). A measured zero is "Free".
- **No sample data.** A day before `recorded_since` has no bar.
- **No model.** `group=model` is never requested (`reportParams` throws for it), and an
  event's `model` field is never drawn and never written to a CSV. Per-model cost stays on
  Usage › Cost, which the footer links to.
- **One failed read never blanks the page.** The summary, the breakdown, the key months, the
  limits, the account limit, the log and the day chart each read alone.
- **A key that is not the member's** (`?key=`) resets the filter to All keys, with APIU12's
  notice.
- **CSV.** It is built from the same reads, using `lib/csvExport.js`'s quoting, and saved to
  the member's device (#2419). The requests file pages through the filtered history, at most
  100 pages, and says when it stopped early.
- **Words.** AI tokens is never "credits". No AI model is named, and nothing says advice.

### 4. Alerts: what exists, said as it is

The key alerts are D849's and already send, in the app and by email:

- `api_key_limit`, at 80% and 100% of a key's own limit;
- `api_key_failures`, when more than 20% of at least 50 calls on a key fail within an hour.

They are always on, so APIU5 lists them without a switch and says that choosing them is not
offered yet. The account's 50%, 80% and 100% notices are D788's, set in Usage › Limits, and
linked from here. APIU5's checkboxes and its Save dialog need a store for key alert
preferences, which does not exist. Nothing on this page changes anything, so no dialog is
drawn.

### 5. Contract gaps still open (§3 of `MCP_API_PLATFORM.md`)

- **No HTTP status, request id, idempotency key, token counts or price list per request.**
  `api_usage_events` holds none of them, so the drawer shows the execution id only and says
  that token counts and the price list are not recorded per request yet.
- **No total count for a filtered log.** The footer says "Newest first · 100 a page" rather
  than "1–50 of N".
- **No connection events.** An assistant approved or revoked has no read yet. Activity says
  so and names #2479.
- **Chart 2's key breakdown cannot split assistants by connection.** The report has no
  `group=grant`, so calls with no key show as one "Assistants (no key)" row. Activity's
  Caller filter does split them.
- **Provider and connector rows do not filter the page.** The report filters by key only. A
  key row filters the page, and a tool row opens Activity filtered to that tool.
