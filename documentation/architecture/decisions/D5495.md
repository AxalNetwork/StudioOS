## D5495 — Deterministic concurrent Trust Publish replay coverage (#5495)

A repeated Publish by the same actor with the same key replays the successful
publication as HTTP 200 and the same publication UID. It records one act.
Different keys and stale reviews retain their refusal behavior.

PR #5559 already repaired the route. This follow-up covers the two interleavings
that the simultaneous-request test could only encounter by chance. Each request
uses the real authenticated router and SQLite adapter; a request-local wrapper
pauses reads while the other request commits. It neither fabricates database
results nor changes the shared environment binding. Existing concurrency and
stale-review cases remain enabled.

Validation removes each replay safeguard separately and inverts every new
assertion, then restores both code and assertions. The deterministic cases must
fail for each corresponding removed safeguard and pass with the merged repair.
The Trust suites also run together at normal test-runner concurrency. No live
publication, communication, schema change or production data is involved.
