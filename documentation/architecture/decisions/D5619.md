## D5619 — One CI failure digest for a PR session (#5619)

`ciDigest.mjs` preserves the verdict supplied by the existing `classify()`;
it does not infer inheritance or infrastructure failure. Available verdicts
come from `ciClassify.VERDICTS`, so infra_failure waits for #5604. A successful
job in another attempt on exactly the same head is marked flaky; the verdict
still belongs to the classifier. The fingerprint hashes verdict and sorted
failure IDs (job names until #5502 supplies IDs), excluding run IDs and time.

The comment carries a versioned hidden marker and fenced JSON containing verdict,
fingerprint, head SHA and digest count. Only a marker owned by github-actions[bot]
is updated. Identical comments do not write. Late results for an older PR head
and forks are ignored. Inherited/infra failures say not to merge main, port fixes
or re-run, with the classifier's safe incident URL when recorded. Job and first
failed step names use safeJobName; job URLs validate the run portion through
safeGithubUrl and allow only a numeric job suffix.

Failure detail is job-level until #5502. An optional CI_DIGEST_ARTIFACT JSON file
may supply headSha and failures [{id, job, testNames, excerpt, repro}]. No log is
parsed or unknown artifact automatically downloaded. Wrong-head detail is ignored.
Each detail is capped at 300 characters and fenced with a delimiter longer than
any contained backtick sequence. #5502's final artifact schema remains its owner.

The write token checks out scripts only at the PR base SHA, installs no PR
dependencies and executes no head code. The job is failure/pull_request-only;
each of its three steps also requires the same repository. Thus a fork runs no
steps. The existing queue guard parses a one-line event condition literally,
so the repository condition is repeated at all step boundaries rather than
weakening or editing #5601's owned queue test. The gate never needs this job.
First rollout skips if the base has no digest script yet. #5601/#5626 should land
first; when #5606 PR 2 lands, its owner updates the needs list to [fast, suite].

Verify-first:

- [GitHub fork policy](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions):
  fork PR tokens are read-only by default. Explicit same-repository guards and
  API-side head/repository checks remain even if repository policy changes.
- Comment edits produce `issue_comment` edited webhook events, but delivery to a
  subscribed Codex session is not observable in this executor. The safe default
  is one updating comment as requested. No claim is made that the notification
  reached a session. Deleting/recreating a comment without evidence of failed
  delivery would destroy history and contradict the requested single update.
- A failing PR cannot exercise this base-only publisher before merge. The live
  two-red-push acceptance therefore remains a post-merge verification, explicitly
  recorded in the PR rather than simulated as completed.

Nine digest tests plus nineteen existing workflow/security tests pass. Required
mutations fail: dont on pr_failure; hash run IDs; checkout head instead of base.
All CLI/API errors return zero. --report prints distinct observed pushes through
first green, or null when no green exists in bounded history.
