### Primary provider facts and limits (checked 2026-11-21)

- [GitHub-hosted runner overview](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners):
  hosted jobs normally receive a new VM (single-CPU runners differ). This establishes
  a between-job lifecycle, not a credential-denying boundary inside a job.
- [Hosted runner administrative privileges](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#administrative-privileges):
  Linux hosted VMs permit passwordless elevation. **Inference:** unmodified host
  process execution cannot be accepted as proof of denial of host control.
- [OIDC reference](https://docs.github.com/en/actions/reference/security/oidc):
  signed target-job claims include runner environment, repository ID, run/attempt,
  workflow SHA/ref and check-run identity. The trusted reader must validate signature,
  fixed issuer, configured audience, lifetime and subject before returning claims.
  `job_workflow_sha` applies to reusable workflows; this direct dispatch uses
  `workflow_sha`. A controller's OIDC token is not the target job's provider proof.
- [Workflow jobs API](https://docs.github.com/en/rest/actions/workflow-jobs):
  job/run IDs, check-run URL, steps, times and runner group metadata can corroborate
  the authenticated target job. Labels do not independently attest provider identity.
- [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)
  and [larger runners](https://docs.github.com/en/actions/concepts/runners/larger-runners):
  standard hosted jobs on public repositories remain free; larger runners are not
  made free by repository visibility. Eligible accounts can draw larger-runner usage
  from included compute. That does not prove a particular job still has allowance or
  a hard stop. Existing D7907 records that overage cannot be read with the job token.

The factory is trusted-code dependency injection, not an API for arbitrary JSON.
