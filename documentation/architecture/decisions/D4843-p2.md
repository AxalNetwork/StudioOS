### The lifecycle

The board draws five steps. The Worker has seven statuses (`PROGRAMME_STATUSES`, `services/testing.ts`). They fold as the canvas's backend-fit table (OF-10) says:

| Worker status | Step | Card says |
|---|---|---|
| `draft` | Draft | Waiting for you |
| `rejected` | Draft, named Sent back | Sent back by HQ, with HQ's note |
| `submitted` | HQ review | Waiting for HQ |
| `approved` | HQ review | Waiting for HQ (approved; HQ opens it) |
| `open` | Recruiting | the applicant line |
| `testing` | Testing | N testers testing |
| `closed` | Complete | N testers took part |

`testingLifecycle.js` holds the fold, the strip's cells, the next step and the list order, so a test runs them alone.

### One next action per state

| State | Action | Kind |
|---|---|---|
| Draft | Submit for approval (Edit beside it) | primary |
| Sent back | Edit and resubmit | primary |
| HQ review | none: Waiting for HQ | — |
| Recruiting | Review applicants | primary |
| Testing | Continue testing (opens the testers) | primary |
| Complete | View testers | secondary |

HQ's own draft is never submitted for approval; it offers no action here.

### The card

- the programme's logo (D1199), or its initial when it has none, through the HQ console's `ProgrammeLogo`, so both sides draw it the same way;
- its name, then places and dates on one line;
- the lifecycle strip on a desk, with done steps ticked and the current one marked (`aria-current="step"`);
- the next-step box: what the state means, and the action.

The page opens on "Product testing" with "Recruit Axal members to test your product before launch." and one header action, + New programme. Programmes list the owner's work first (sent back, then drafts), then recruiting, testing, waiting for HQ and complete, each by name. The status groups are gone: each card's lifecycle carries the state.
