### 1. One catalogue (`services/decks/elementModels.ts`, pure)

- **The elements.** `ELEMENTS` lists every element in the lightbox picker. Each has its group and the job `DECK_ELEMENT_JOBS` assigns it.
- **Which elements are routed.** An element gets an entry in `ELEMENT_ROUTES` only when its job is in the plan and the job is not a fixed check. That gives 33 elements.
  - **Free:** these run no model and read "No model · free": metric, team grid, the graphics library, upload, video, audio, link, button and embeds.
  - **Not routed:** `recorded_video` names DK14, which the plan does not have.
- **What a route holds.** Each entry is `{ task, option, kind, job, chain, plan_min, maxTokens, timeoutClass, pipeline, requirements }`.
  - `pipeline` is the draw's three DK6 checks.
  - `chain` is empty for an image, because an image never falls back to another model.
- **No model ids in the file.** Default, Alternative and Deeper, plus the `more` list, come from `selectorFor(job)`. The file contains no `@cf/` literal, and a test enforces this.

### 2. `resolveElementModel`

The levels are checked in this order:

1. HQ lock
2. Area override
3. Deck element pick
4. Deck group pick
5. Member element pick
6. Member group pick
7. HQ default
8. Row default (the job's first choice the caller can run)

Each candidate is checked against:
- `isOffered`;
- policy: `offerable`, which excludes hidden models and models on Legal's hold;
- the element's own choices;
- plan_min: the stricter of `MODEL_LOCKS` and the row's own `plan_min`.

How a failed check is handled:
- **Stale pick.** The pick reads as none and is returned in `stale`. The route clears deck, area and member rows. It keeps HQ rows, because only HQ changes them. The reply says "A model retired · Using [model]".
- **Plan.** A pick the plan does not include is skipped but kept.
- **Group pick.** A group pick that one element does not offer is skipped for that element. It is not stale.
- **Scopes.** A deck pick belongs to the venture (scope id: the project), so it holds across versions. HQ is scope id `hq`.

### 3. Rules, size, estimate and time

- **Where the rules live.** `OUTPUT_RULES`, `inputRefusal` and `outputProblems` are in `elementOutputRules.ts`, next to `elementModels.ts`. They read `newDeck.ts`, and `railMatrix.ts` imports `elementModels.ts`. Keeping `newDeck.ts` out of that chain avoids an import cycle, which had broken `deck_stage_norms_d1589` and the Mercury import guard in `fund_admin_overview_d714`.
- **`OUTPUT_RULES`.** Every element's figures are `records_only`, except an image's, which are `none`.
  - `inputRefusal` refuses a figure in the request. It uses `figureRefusal`.
  - `outputProblems` refuses a figure in words the model wrote, and any value not bound to a record.
- **`sizeFor`.** Text runs are sized in tokens in and out. An image is sized by its model's default tiles and steps.
- **`estimateDeck`.** Returns one quote line per element: `per × count` on its model, with the total equal to the sum of the lines. A line that cannot be priced is null, and so is the total.
- **`expected_ms`.** The timeout class's per-attempt limit, plus one chat limit for each pipeline step.

### 4. Routes

- **The routes.** `GET` and `PUT /api/decks/:id/element-models` (`routes/deck_element_models.ts`, mounted before `decks`). See ROUTE_MAP.
- **Shape.** The reply uses #3741's shape: `suggested` (at most 3), `more` and `pick`. It adds `resolved` and a `groups` list for the rail.
- **Locks.** A PUT on a key HQ locked gets 403 `role_locked`. A PUT on a model the caller's plan does not include gets 403 `plan_locked`.

### 5. Generation (dk-auto amendment 10)

- **The build.** `/generate`, the build and card quote, and regenerate-card resolve **Body** through `elementModelFor`. Each card's headline and sentence are written in one run, so that run uses Body's model, and the reply names it in `element_models`.
- **Images.** The deck's image quote and run resolve the photo element for a `scene` and the illustration element for any other style.
- **No pick.** If no pick sits above the row default, the run passes no model. It keeps its rail option's own resolution, so a deck without picks runs exactly as before.
- **Not on main yet.** #3768's whole-deck fan-out and #3764's area runs are not on main: their adapter rows (`narrativeOutline`, `areasQuote`, `areasGenerate`) are still off. Each must call `elementModelFor` when it lands.

### 6. The rail

- **Generated rows.** `railMatrix.ts` answers a generated `grid:<element>` row through `resolveRailOption`, on the Pitch deck page only. Each row has at most three models, and the rest go under `more`.
- **What stays the same.** `railOptionsOn` and `railMatrix.json` are unchanged, and `RAIL_KINDS` still has 21 kinds (the canvas's 14 and #3934's 7). No kind is added.
- **The client.** `lib/api/deckElementModels.js` is re-exported by one line (D527). `deckV2Adapter.elementModels` is now `through(() => deckElementModelsApi.read(id), 3754)` and is listed in `SWAPPED`.
- **The groups.** On a deck, each element group in `deckRailGroups.js` reads its block from the reply and saves a pick as the deck's group pick. `RailGroups.jsx` takes the group's `read` and `pick`. It shows a refused pick's message, and the Worker's "No model · free" for Graphics. No layout was added; #3797 owns the layout.

### 7. Departures

- **Pages with no deck keep the old option lists.** New deck and Templates have no deck id, so they have no reply to read. Their groups keep main's rail options, and a group with none says "Models are picked per deck". A no-deck read, by project, is a follow-up.
- **One model for a card's words.** The words build is one run for headline and body. If Title and Body picks differ, the build uses Body's.
- **No `uid` column on `deck_model_picks`.** The spec lists the columns, and nothing outside the Worker refers to a row.
- **Vision and Safety stay as they were.** Vision and checks keeps `review:deck-file`, and Safety stays the guard. Neither is a grid element.
