- **Status:** Built for #5580, 2026-11-15. Worker, migration and workflow; no screen yet.
- **Builds on:** D5580 part 1 (the advisory snapshot), part 2 (`workInFlight`, PR #5821, merged) and part 3 (the WorkGraph canvas, whose "Backend required" list this answers).
- **Migration:** `202611152335_5580_workgraph_snapshots.sql`.

### What was decided

1. **The hourly scan reaches the Worker.** `.github/workflows/pr-overlap.yml` still uploads the snapshot as an artifact. It now also posts it to `POST /api/admin/workgraph/snapshots` with a bearer token.
   - The post is advice only: a failed post is a warning and never fails the report.
   - With no `WORKGRAPH_INGEST_TOKEN` Actions secret, the job skips the post with a notice.
2. **The ingest has its own secret, not a member session.**
   - **Credential:** the Worker compares the bearer to `WORKGRAPH_INGEST_TOKEN` in constant time. With the secret unset it answers 503 `workgraph_ingest_not_configured`, so nothing is accepted until the owner sets it. A missing or wrong token answers 401. The secret, both places it is set and its rotation are in `PRODUCTION.md` § 4.
   - **Size and shape:** a body over 1,500,000 bytes answers 413, which keeps the row under D1's 2 MB limit. A body that is not a `studioos-pr-overlap-snapshot/v2` snapshot answers 400 with a code naming the missing part: an ISO UTC `generatedAt`, a boolean `partial`, the `prs` and `pairs` lists, and the `workInFlight` section.
3. **One row per scan, the latest week kept.** `workgraph_snapshots` stores:
   - the body as posted;
   - beside it, the columns the read needs without parsing: schema, `generated_at`, partial and size;
   - its sha256, unique, so a re-posted scan is stored once.

   Each ingest deletes all but the newest 168 rows (a week of hourly scans).
4. **The read says how fresh the scan is.**
   - **Who:** `GET /api/admin/workgraph/in-flight` is Super Admin only, because it shows every slot's work.
   - **What it returns:** the newest scan with `generated_at`, `received_at`, `partial`, `age_minutes` and `stale`. A scan is stale after 150 minutes: two missed hourly runs and a margin.
   - **Honest states:** with no scan stored it answers `status: 'none'` with the reason. A stored scan that cannot be parsed answers `status: 'unreadable'`. Neither is ever drawn as an empty board.
5. **Nothing here decides anything.** The routes store and return the scan. They do not block, label, merge, release a claim or override, as the canvas requires.

### Owner steps

Generate one value (`openssl rand -hex 32`) and set it as the Worker secret `WORKGRAPH_INGEST_TOKEN` and as the GitHub Actions secret of the same name. Until both are set, the read says no scan has been posted.

### Tests

`cloudflare-worker/test/workgraph_snapshots_5580.test.ts` covers:
- the ingest's refusals (unconfigured, missing, longer and same-length wrong tokens, an empty secret, oversized, and each malformed part), with nothing stored;
- storing a scan once, and keeping the newest 168;
- the read's gate (member, plain admin, Super Admin);
- the `none`, `read`, stale and `unreadable` answers.

12 mutations were run and all were caught. `frontend/test/pr_overlap_5616.test.mjs` still holds the workflow's permissions.
