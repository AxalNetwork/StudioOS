### 1. The states are D1264's

A version's figures are D1264's `narrative` surface: each figure a section states, read by fixed patterns, never by a model. They are written to `raise_claims` (`surface = 'narrative'`, `surface_version = 'v<n>'`) as Backed, Founder's figure, Mismatch or Not backed, from the founder's pinned evidence.

- **On the version asked about.** D1264 checks the newest version on the Evidence read. `checkNarrativeVersion` checks the version the tab names, with the same writer: other versions and other surfaces are untouched.
- **Read as the founder checks.** The founder's read of Claims checks the version as it reads, as the Evidence read does, writing only what changed. An admin with a reason (D914) reads the last states, with no figure.
- **Which sections.** D1264 reads the deck-row sections and Why now. Solution, Business model and Team keep their words in `narrative_sections`; a figure typed there is a claim too, under field key `section:<key>`, on the version asked about and on the newest version when Evidence refreshes.

### 2. Claims (NAR6) and the drawer (NAR7, NAR7b)

- **The table:** each claim with its section, its state and its best source. "Needs you first" orders Mismatch, then Not backed, then Founder's figure, then Backed. State, Source (Not backed included) and Section filter it.
- **The bar:** claims by best source, 100%, in whole percents that add to 100 (largest remainder). A claim with no record has no best source and is the dashed Not backed segment. It has a legend, and **Table** shows the same counts as rows.
- **Not backed:**
  - **Evidence candidates:** the pinned records of the figure's kind not linked to the claim (`couldBack`: a KPI snapshot or model assumption only for its own metric, so another metric of the same snapshot is not offered).
  - **Eadwyn's proposed links,** on lavender: open `raise:evidence-link` proposals for this claim, accepted through D1263's link route with the proposal's uid.
  - Each link opens a confirmation first. None of either is NAR15c: "No record in your Evidence pack could back this figure yet."
- **Mismatch:** both figures and both sources, "Neither figure is presumed right."
  - **"Use the record's figure"** (`POST /narrative/:version/claims/:uid/use-record { record_value }`) re-reads the record, refuses unless the claim is still a Mismatch and the record's figure is the one shown, moves only the number the check read (D900's `swapFigure`), and saves the section through `saveNarrativeSection`, with its own limits, log row and consistency check. The claims are checked again after.
  - **"Keep mine, with a note"** is D900's claim note (owner question 6, read as A): it stays a Mismatch, shown with the note.
  - **Departure, for review:** the issue says the swap "binds it through part 2". A claim's record is a pinned evidence item, not one of the PITCH registry's slots, and nothing maps one to the other, so the swap changes the words only. Binding the figure stays Story's Insert a figure, as D900 §9 says for the deck.
- **On a phone** the drawer is a full sheet (NAR19c, the Lightbox's `pageBelow`).
- **A failed read** says "The claims could not be read. This is not a claim that there are none." with Retry (NAR17a).

### 3. The check (NAR8) and Phrase the fix (NAR9)

- **NAR8** compares each figure the version states with:
  - the current deck's figure, read from its cards whether bound or typed (`Pitch deck v6 · card 1`);
  - the metric stores (`checkInputs`' metrics).
  - Each side is used only when "Check against" chooses it (#2447).
  - A side that agrees within `agrees` is OK; one that differs is a Mismatch naming its side. A figure stated in one place only is Not compared, and a check with nothing compared reads "Nothing compared yet.", never "no mismatch".
- **Run the check** (`POST`, the founder's):
  - runs D663's `runCheck` (`narrative_checks`, which the fix reads) and D1264's check on the version;
  - stamps every claim of the version with the run's time, so "Last checked" is the run even when no state changed;
  - logs one `narrative_checked` row with no figure.
- **Phrase the fix** is per mismatch row. The band's scope key names the version and the figure (`<project>:v<n>:<figure>`, `parseFixScope`), so the fix is for the row clicked, not the newest version's first (`narrativeFix.ts`).
- **The wording carries no number** (map E5):
  - the model reads which figure and where each side was read, with every digit taken out of the sources;
  - `finishNarrativeFix` refuses any draft with a digit, where `unfoundFigures` let an agreeing number through;
  - the figures come only from the check: the kept draft ends with the check's own sentence, which the dialog draws under the wording.
  - A refused draft says "Eadwyn's wording held a number, so none was kept."
- **"Accept into [section]"** places the wording in Story as a proposal (`?fix=<draft uid>&section=`): Story reads the founder's own fix drafts and draws it on lavender. Accept adds the wording after the section's words, leaving their provenance as it was, since they hold the founder's typed figures. Save version saves it. This answers bug 11.

### 4. The routes (`routes/cycle_raise.ts`, `narrativeScope`)

| Route | Who | What |
|---|---|---|
| `GET /narrative/:version/claims` | the founder; an admin with a reason reads states only | NAR6 and NAR7's data, with `can_check` |
| `GET /narrative/:version/check` | the same | NAR8's rows, `against`, the deck's version, `checked_at` |
| `POST /narrative/:version/check` | the venture's founder (`raiseEvidenceContext`), never a support session or an admin | runs both checks, stamps Last checked, answers the rows and the claims |
| `POST /narrative/:version/claims/:uid/use-record` | the venture's founder | §2 |

Version 0 is the live deck's wording and is refused (409). A version that is not the venture's is 404.
