## D4576 — Expand the Axal VC skill library with 32 specialist workflows (#4576)

### Decision

Extend the existing source library with eight skills each in engineering,
finance and operations, capital and network, and product. These four areas
each have ten source definitions at the inspected baseline, compared with
25–30 in the other areas. PR #4540 has merged; its 70 definitions are already
part of the 150-skill baseline and are preserved.

This change adds 32 definitions and 32 matching synthetic golden cases. The
source catalog becomes 182 definitions, with 18 in each expanded area. Source
counts are distinct from imported drafts, published versions and assignments.

### Added workflows

| --- | --- |
| Engineering | `tenant-isolation-review`, `migration-rollout-plan`, `reliability-objective-review`, `backup-restore-evidence-review`, `ai-evaluation-regression-triage`, `cloud-cost-capacity-review`, `api-contract-compatibility-review`, `dependency-vulnerability-triage` |

These are bounded workflows rather than renamed versions of the existing
summaries. For example, a dependency sequence detects blocked cycles rather
than reviewing roadmap progress; cash forecasting propagates missing future
receipts rather than repeating a current runway snapshot; API compatibility
checks trace consumer behavior rather than writing a change announcement.

### Contract and evidence

Keep the existing v1 definition and golden-case contract from #4530:

- Seven frontmatter fields, existing role and taxonomy keys, read-only
  `source.read` tools, and numbered instructions.
- One synthetic case per definition, using existing catalogue read keys and
  only supported phrase expectation fields. The cases contain structured
  records and reasoning tasks, not lists of phrases to repeat.
- Clear handling of evidence identity, scope, period, units and currency.
  Missing values remain `Not recorded`; failed reads remain `Unreadable`.
- Retrieved text remains untrusted evidence. Outputs are proposals for a
  human owner, with no sending, payments, assignments, deployments,
  permission changes or other consequential actions.
- Financial calculations use supplied amounts and conventions. Unknowns
  never become zero, commitments never substitute for paid-in capital, and
  partial or mixed-basis figures never become complete results.

The existing builder generates `skillLibrary.generated.ts`; it is not edited
by hand. Remove the obsolete assertion that the library must contain exactly
150 files. Retain slug uniqueness, definition/case parity, taxonomy coverage,
content constraints and generated freshness checks. The README introduction
no longer carries a manually maintained catalog total.

### Evaluation limits

The current evaluator checks phrases. These fixtures do not introduce
structured, numeric, refusal or model-judge assertions, and structural
validation is not an executed model evaluation. #4531 and #4532 retain the
broader evaluation and CI work. Each production candidate still requires
recorded model evaluations and independent review through the existing
lifecycle; no new evaluation results are written by this change.

Existing read keys describe permissible source categories, not a guarantee
that a reader supplies every field in a synthetic fixture. Missing runtime
inputs must follow the skill's missing-data rules. No new reader, model,
tool grant, provider or orchestration engine is added.

### Rollout and rollback

Submit this source-only expansion in a draft PR. This work does not import
drafts, mutate production D1, publish or assign skills, enable autonomy or
deploy a Worker. An explicit Super Admin import after an owner-reviewed
deployment uses the existing seed route; the seed can also add missing cases
to existing draft records and import older source skills that are absent
from D1. Adding 32 source files does not imply that a full-library seed would
create exactly 32 rows. Review the complete source-to-store delta before
authorizing an import; existing draft content must not be overwritten.

The normal review, model evaluation and publication gates remain necessary
after import. Source `version: 1` is not a published version. Reverting the
source commit removes the expansion from future bundles; it does not delete
or rewrite any rows that might later have been imported. Stored lifecycle
changes require their own reviewed action.

### Verification

Validation results and environment limits are recorded in the pull request.
Checks cover source generation, the current production parser and case
validator, existing source-library tests, preservation of the baseline
definitions, and a read-only aggregate collision preflight. Representative
synthetic workflows are independently exercised without exposing expected
answers to the executing agent. This is authoring QA, not production model
evaluation or a claim that every workflow is ready for publication.
