## D4450 — Retry-safe event Explain and an unreadable receipt (#4450)

Part of #3724, following S1's review of #4430 and the owner-account answer on
[#4450](https://github.com/AxalNetwork/StudioOS/issues/4450#issuecomment-6636263217).
A paid Explain must keep its successful prose when the subsequent receipt
read fails, and retrying one displayed quote must never charge twice.

The charge receipt's `first()` now catches a failed read and returns null.
Explain still answers 200 with its generated text and usage-log identity;
`charged_microusd: null` means Not recorded, never a zero charge.

Explain uses the existing deck-area `quoteUidOf`, `quoteHolds` and ten-minute
`QUOTE_TTL_MS`. Only the helpers' input type is narrowed to the fields their
existing signature actually reads (`QuotePlan`); the deck signature format
and validation algorithm are unchanged. One Explain plan binds the member,
event, model, current price and hash of the server-built prompt. The route
rechecks current visibility/eligibility/reasons and reprices before validating
the submitted quote. Missing, expired or mismatched `quote_uid` returns 409
`quote_stale`: “This price has expired. Get a new quote.” No run starts.
The quote response includes `quote_uid` and `expires_at`.

The client echoes the displayed quote UID in the paid request and its
Idempotency-Key header. The Worker builds its own run key from authenticated
member + event + quote UID; changing the client header cannot evade that key.
The router's existing unique reservation/settlement handles retry races. A
replay answers 409 `step_replayed` in words, takes no second hold, invokes no
second model and charges nothing again. A fresh quote identifies a new run.
Successful prose is not persisted or reconstructed on replay by this fix.

Tests inject a post-charge receipt read failure, exercise the real router and
token ledger for retries/new quotes, reject expiry and member/event/input/price
mismatches before any charge, check the client echo, and retain the related
deck and billing tests. New assertions are mutation-checked in both directions.
No store, migration, screen or production operation is added. Roll back the
route/client together if the quote contract must be withdrawn; no ledger rows
are removed.
