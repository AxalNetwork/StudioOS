## D5569 part 2 — The publisher broker contract: plan or refuse, off by default (#5569)

- **Status:** built on `agent/claude/5569-publisher-contract`, on top of part 1 (`D5569.md`, #5729). Disabled: nothing calls it, and with the flag off it refuses everything.
- **Code:** `cloudflare-worker/src/services/agents/agentPublisher.ts`, typed import of `scripts/lib/prOverlap.mjs` through `scripts/lib/prOverlap.d.mts`; `cloudflare-worker/test/agent_publisher_5569.test.ts`.
- **Migration, route, secret, binding:** none. No D1 write, no `fetch`, no clock read.

### What is decided

- **The workspace offers an intent; the broker decides.** A publish intent is content-addressed: tenant, company, project, the part 1 installation UID, repository, target ref, exact 40-hex base SHA, the patch digest and file list, the run provenance (stable agent id, task id, run UUID, attempt, workspace image and evidence digests), the agent's own test and scan results and an idempotency key. `intentDigest` hashes its canonical form. The broker supplies every observation, the clock included: the flag, the installation as GitHub last reported it, the base head, the repository's agent PRs, the last 403 or 429, the combined candidate's required checks and the human task approvals.
- **One decision, in a fixed order.** `planAgentPublish` returns a draft PR plan on `agent/<task>/<attempt>`, created only if that ref does not exist (`head_ref_condition: must_not_exist`) against the expected base SHA, or the first refusal that applies:

| Code | When | Retryable |
| --- | --- | --- |
| `publisher_disabled` | the flag is not exactly `on` (the default) | no |
| `invalid_intent`, `invalid_observation` | a malformed field, an unsafe path (`..`, absolute, `.git`, control characters), an invalid task id, attempt or approval | no / yes |
| `installation_not_found` | no installation, or one bound to another tenant, company or project | no |
| `installation_revoked`, `installation_approval_missing`, `installation_suspended` | the part 1 record or GitHub says so | no |
| `installation_stale` | GitHub's status is missing or unknown, or the read is older than five minutes | yes |
| `repository_mismatch`, `target_ref_mismatch` | the intent names another repository or a ref other than the protected base | no |
| `duplicate_publish` | the same key with the same digest, or an open PR for the same task (by task id or `agent/<task>/` branch); returns `reuse` | no |
| `idempotency_conflict` | the same key with different content | no |
| `task_already_merged`, `task_pr_declined` | the task's PR was merged, or closed by a person | no |
| `github_forbidden` | a 403 that is not a rate limit; waiting does not clear it | no |
| `github_rate_limited` | a 429, or a 403 with `retry-after`, `x-ratelimit-remaining: 0` or a secondary limit; `retry_at` is `retry-after`, else the reset, else one minute, doubled per consecutive limit, capped at an hour | yes |
| `protected_path` | CODEOWNERS or `.github/workflows/` or `.github/actions/`, whatever the installation allows | no |
| `scope_violation` | a path outside the installation's allowed paths (exact files, or folders ending in `/`; empty allows nothing) | no |
| `base_unknown`, `base_moved` | the base head was not read, or is not the intent's base SHA | yes / no |
| `agent_checks_failed`, `agent_checks_missing` | the run's tests or scan did not pass | no |
| `required_checks_missing` | the protected branch requires no checks (no), or the combined candidate has not reported a required one (yes) | no / yes |
| `required_checks_pending`, `required_checks_failed` | a required check on the combined candidate is still running, or failed | yes / no |
| `coordination_required` | another open agent PR shares a path or a new migration stamp (D5616's `pairs`); names it, its paths and a suggested order, with `textual_conflict: not checked` | yes |

- **Disjoint work proceeds.** A plan lists the open agent PRs it does not overlap in `parallel_with`. Path overlap alone is never called a textual conflict; a coordinator's clearance (`coordination_cleared`) lets an overlapping PR proceed.
- **Metadata is trusted fields only.** The title is built from the task id and attempt. The body maps agent and run to task, tenant, company, project, installation, base, digests and approvals, plus a machine marker with key and digest. The agent's summary and log excerpt are untrusted: one line each inside `<code>`, with newlines, control and bidi characters removed and every Markdown, HTML, mention, reference, link, slash and math character an entity. No line can start a slash command, open a comment, mention anyone or reference an issue.
- **No self-approval, bypass or auto-merge exists here.** The plan's fields are fixed and none approves, merges, enables auto-merge or bypasses protection. Merging remains a human review plus GitHub's protected merge queue (#5500) and exact-SHA release (#5501).

### What stays off

The flag has no binding in `wrangler.toml`, and nothing reads or mounts the module. A later part adds the broker that reads GitHub, mints installation tokens and executes a plan. That part also adds a bounded publish queue, the WorkGraph WorkIntent preflight (D5580) and the audit record of the commit SHA, PR URL, approval and deploy SHA. The part 1 table has no allowed-paths column, so the broker supplies allowed paths as an observation until the owner chooses where to store them. D5616's path classes are this repository's; in a venture repository most paths are plain `path` and only exact overlap applies.

### Owner activation

1. Create the separate write GitHub App, not the read-only connector or the Merge Control App. Grant only Contents and Pull requests read and write, plus Metadata and Checks read. Do not grant Administration, Workflows or bypass, and do not add the App to a ruleset bypass list.
2. Install it on each approved venture repository individually ("Only select repositories") and record the installation with an approver in `venture_git_installations`.
3. Protect each base branch: required reviews, required status checks and a merge queue, as #5500 does here. Release by exact SHA (#5501).
4. Only after the broker part lands and is reviewed, set the flag to `on` in preview, then in production. Rollback is the flag off. Removing this module and its test changes no data.
