## D6102 — Recorded KPI targets beside compatible actuals (#6102)

The helper reads metric_targets with a bound project ID and uses the existing
shared readTarget comparison. It preserves recorded zero. Missing actuals
leave comparison blank; a failed target read is Unreadable and keeps actuals
readable. No target write, permission or schema change is added.

MRR, paying accounts and burn have compatible Focus keys. Churn uses
monthly_churn_pct only when the KPI is a percentage; its ledger-money form
must never be compared with that percentage target. Computed/custom keys
not supported by the Focus writer say Not set · not supported in Focus.
No metric keys or target inputs are invented. All links retain project_id.

A favorable comparison (at/above an up target, at/below a down target) says
Target met; an unfavorable comparison says Above target or Below target.
The table adds no pacing or On track claim. Target formatting uses its known
metric even when an absent actual has no unit. The adapter appends two keys
so the old five-column response remains compatible until integration.

These columns extend GR-05, whose existing KPI table lacks them; #6102
explicitly requests the extension and its checked note requires recording
the departure. No separate screen or layout is invented.

Open #6349/#6342 own cycle_grow.ts and #6366 owns CycleModulePage.jsx.
The prepared route patch enriches only the revenue records and appends the
two columns. A prepared table patch allows an explicitly marked target link
above the existing row link overlay, preserving normal row behavior. Both

cycle adapter expectations will be updated with that integration. This PR

zero, missing actual/target, failed reads and incompatible churn/custom keys.
The types file describes the existing shared JS function rather than copying
its comparison. No production data access, deployment or merge is performed.
