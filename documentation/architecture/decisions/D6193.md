## D6193 — Deal activity: a kind on every row, documents and diligence in the feed, and DL14's five chips (#6193)

- **Status:** built 2026-11-14 by S12. Filed under #4815.
- **Board:** DL14 of `design/incoming/Investor Deal Page.dc.html`, which draws the chips All, Mine, Deal, Documents, Diligence.
- **No migration.** One Worker read changes (`GET /api/deals/:id/activity`), additively.

### 1. A kind on every row

Each row of `GET /api/deals/:id/activity` carries `kind`, one of `ACTIVITY_KINDS`: `deal`, `documents` or `diligence`.
- **`deal`:** deal created, stage moves, commitments and invitations, as before.
- **Unknown:** a row the page cannot class counts as `deal`, the issue's rule.

### 2. What the feed adds, and from where

Before this, the feed held no document or diligence events, so two chips would always have been empty. It now reads two more sources, each under the read rule it already has. Neither names anybody.

| Kind | Source | Who reads it | Row |
| --- | --- | --- | --- |
| documents | `documents` on the deal's venture (`project_id`), newest 50 | NDA-exempt readers, or an investor with the venture's active NDA. The `GET /:id/documents` rule (D4631) | "Document added: {title}" |
| diligence | `dd_cases` on the venture (`subject_type = 'project'`), not archived | the case owner, its reviewers, or a platform admin. The stage read's rule (D1150), plus the admin | "You opened a diligence case", or "Diligence case opened" |
| diligence | `dd_requests` answered on those cases, newest 50 | the same readers | "The founder answered a diligence request" (never the request's text) |

- **NDA-exempt readers:** the platform admin and the venture's own founder.
- **Other investors** are still never named (D1152, D4631). An investor never reads another investor's diligence case.
- **One source failing:** each new source is read on its own. A failed read adds one row ("Document activity could not be read", "Diligence activity could not be read"). The rest of the feed still answers. A failed source is never silent and never takes the feed down.

**Not in the feed:**
- data room files (`data_room_files`, behind their own grants);
- deck versions (`deck_grants`);
- NDA signatures.

The canvas's sample rows show them, but each has its own access rule, and that work is larger than this issue's size. "What's new" (D1587) counts the same document catalogue used here.

### 3. The chips

`DealActivity` (`pages/deal/DealNotes.jsx`) draws DL14's chips in canvas order.
- **Mine** is drawn on the Notes tab only, as before. The Activity tab used by founders and staff draws All, Deal, Documents and Diligence.
- **Filtering** happens in the page, on `kind` (`activityShown` in `dealFrameModel.js`).
- **An empty chip** says what this reader can see, never that nothing happened. For example: "No document activity you can read is recorded. Documents show once you hold the venture's NDA."
