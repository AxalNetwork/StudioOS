## D4710 — Mounted verification of Delivery stale writes (#4710)

### Reconcile the merged implementation first

PR #5562 (D5314 part 3, merged 2026-11-11) already wired the Delivery page's
`expected_revision` payloads and conflict actions. This package adds the
requested mounted regression coverage; it does not build another revision
check or edit the zone files owned by open PRs #5523/#5563.

### What is now exercised

`frontend/test/delivery_stale_writes_4710.test.mjs` mounts each real zone with
synthetic API answers: the page read revision 4, and the write is refused
because the current revision is 5.

| Zone/action | Asserted behavior |
| --- | --- |
| Deliverables title/version save | Read revision sent; editor and typed values remain; alert and explicit retry; same payload retried at returned revision |
| Capacity seat scope | Read revision sent; typed scope remains; conflict announced; same scope retried at returned revision |
| Health facts | Read revision sent; scope note, score and source remain; conflict announced; retry preserves the payload |
| Reports draft save | Read revision sent; both sections and client/period remain; explicit retry; next save adopts the successful save's returned revision |
| Reports Mark sent | Drawn revision sent once; refusal is announced; no success status; report remains a draft; Reload reads without retrying the send |

The tests reuse the existing zone harness and restore API methods and the
separate scoped-fill read after each case. The fixture names, account-related
ids and links are synthetic. No network/account credentials are used.

### Evidence boundary and remaining scope

These tests observe frontend behavior through stubbed API methods. The
Worker's stored-row immutability/409 behavior remains covered by the existing
`cloudflare-worker/test/delivery_write_conflicts_5314.test.ts`; a mocked refusal
does not prove production enforcement or actual client delivery. In this UI,
Mark sent records a manual act; it does not send an email.

The full 6/6 package still waits on #4709. Shared policy extraction, realistic
cross-firm route/actor fixtures, history/partial-read integration, grid and
phone semantics, and client acknowledgement of the immutable shared version
remain open. Reconcile the acknowledgement with #5314's client-open version
before building it. This partial PR must not close #4710.

### Regression checks

The new five mounted cases and the existing seven frontend revision-contract
checks pass together (12 tests). Nine temporary local mutations each fail the
new suite: drop each zone's revision or the send's revision, ignore conflicts,
retry at the wrong version, fail to adopt the saved revision, or clear the
failed report draft. All source was restored; this PR changes no production
file. Build and full-drift results are reported in the PR.
