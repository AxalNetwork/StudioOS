## D976 — The advisor and partner network: a stage per person, Pause and Resume with a reason, the advisor directory switch, and one person's standing

Issue #2762; part 4 of Advisors & Partners (#2369, D972 §6). Worker and its
client only; part 6 (#2764) draws them. Migration 552.

Code:

- `cloudflare-worker/src/routes/admin_network.ts`, mounted at `/api/admin/network`;
- `services/networkStanding.ts`;
- `services/networkStatesSchema.ts`;
- the gates in `routes/advisors.ts` and `routes/lab_hosts.ts`.

The client is `adminNetworkApi` in `frontend/src/lib/api/network.js`. The tests
are in `cloudflare-worker/test/network_standing_d976.test.ts`.

### 1. Why

No admin could pause anyone in the network or hide an advisor from the
directory. Only the advisor writes `advisors`, and `advisors.is_active` has no
admin writer (the map's §B.7). The canvas's person drawer (AP4) also needs
reads that do not exist:

- Standing;
- Work: sessions over 90 days, open slots, engagements per lane;
- Terms: payout account and studio agreement;
- Pause with a reason (AP9c).

### 2. Migration 552: `network_member_states`

The table has one row per member account (`users.id`), and only
`admin_network.ts` writes it. Its columns:

- `paused_at`, `paused_reason` and `paused_by`, set by Pause;
- `resumed_at`, `resume_reason` and `resumed_by`, set by the last Resume;
- `directory_hidden_at` and `directory_hidden_by`, set while an admin hides an advisor from the advisor directory.

No row means never paused and never hidden. Nothing is backfilled. Every write
is also a `logAdminAction` entry, recorded against the person as
`viewed_user_id`:

- `network.paused`, with its reason;
- `network.resumed`, with its reason;
- `network.directory_hidden`;
- `network.directory_shown`.

`ensureNetworkStatesSchema` mirrors the migration's DDL for dev databases. The
test checks that the mirror and the migration give the same columns.

### 3. The stage

- **Who is a person:** an account is an advisor if its role is `advisor` or it
  has an `advisors` row. It is an operating partner if its role is `partner`.
  Any other account is `not_in_network` (404).
- **The stage is derived, in this order:**
  1. `ended`: the account is inactive; or the advisor's own profile is
     inactive; or the partner's firm is `inactive`.
  2. `paused`: an admin paused the person. This is the only stored part.
  3. `onboarding`: an advisor with no advisor profile yet, or a partner account
     with no firm.
  4. `active`: everything else.
- **Invited is not returned.** It is a partner invitation with no account
  behind it yet, so it belongs to no person this read can name. Advisors have
  no invitation store, so for them Invited is not recorded. Part 1 (#2759)
  counts partner invitations.
- **Hidden from the directory is not a stage.** An active advisor can be
  hidden.
- `stageOf` and `kindOf` are exported, so part 1's people read uses the same
  rule.

### 4. Pause and Resume

```
POST /api/admin/network/people/:userId/pause   { reason }
POST /api/admin/network/people/:userId/resume  { reason }
```

- **Who may do it:** an admin only.
- **The reason** is required. It is trimmed and capped at 1000 characters; a
  blank reason or one that is not a string is 400 `reason_required`.
- **Pause is refused** for an ended person (409 `ended`), and a second time
  (409 `already_paused`). A conditional upsert makes the second Pause leave the
  first reason and time in place, even in a race.
- **Resume is refused** when the person is not paused (409 `not_paused`). It
  clears the pause and records its own reason.
- **What a pause does to an advisor (AP9c):**
  - `POST /api/advisors/slots/:id/book` refuses with 409
    `{ code: 'advisor_paused' }`. That covers the `/:uid/book` alias and booking
    links too.
  - The advisor leaves the advisor directory (`GET /api/advisors/` and
    `/match`).
  - The advisor leaves the Lab's office-hours directory
    (`GET /api/spinout-lab/hosts/directory`).
  - Bookings already made stay, and their slots stay readable.
- **The response says what the pause did** in `effects`:
  `advisor_bookings_stop`, `advisor_directory_hidden` and
  `lab_office_hours_hidden`. A dialog can then say only what is true.
- **A partner account's pause has no effects** (`effects: []`).
  - Partner office hours, the Lab's partner hosts and the partner directory all
    belong to the firm, not the account. Pausing one account of a firm does not
    stop the firm's bookings.
  - The pause records the stage and its reason. Switching off a firm is part 7
    (#2765).

### 5. The advisor directory switch

```
POST /api/admin/network/people/:userId/directory  { listed: boolean }
```

- It applies to an advisor with an advisor profile only; anyone else gets 409
  `not_an_advisor`.
- `listed` must be a boolean; otherwise the request is 400 `listed_required`.
- Hiding twice is 409 `already_hidden`. Showing when not hidden is 409
  `not_hidden`.
- **Hiding takes the advisor out of the advisor directory only.**
  - The advisor stays bookable and stays in the Lab's office hours. That is
    the difference from a pause.
  - The response's `listed` stays false while the advisor is paused: Show does
    not lift a pause.

### 6. `GET /api/admin/network/people/:userId` — one person's standing

The response is:

```
{ user_id, kind, stage, pause, directory, kyc_status,
  ratings, sessions, engagements, payout, agreement, lab_host }
```

- **`pause`** is `{ paused, paused_at, reason, last_resumed_at,
  last_resume_reason, effects }`.
- **`directory`**, for an advisor, is `{ listed, hidden_by_admin, hidden_at }`.
  For a partner it is not recorded: a firm is listed on Firms.
- **The last six fields are blocks in D893's shape.** A failed read is
  `{ available: false, unreadable: true, reason }`, a figure no store holds is
  `{ recorded: false, reason }`, and neither is ever a zero. An advisor with no
  profile yet gets not-recorded blocks.

| Block | Advisor | Operating partner |
|---|---|---|
| `ratings` | `advisor_reviews` by founders on the advisor's bookings: `count`, `average` (one decimal, `null` with none), `by_score` 1–5 | the firm's `partner_booking_ratings`, `scope: 'firm'` |
| `sessions` | the advisor's bookings by slot start: `completed`, `cancelled`, `no_show` and `not_marked` (held, never marked) in the last 90 days; `upcoming` (pending or confirmed, still ahead); `open_slots_14d` (slots with a free seat in the next 14 days) | the same over the firm's partner office hours, `scope: 'firm'`; not recorded with no firm |
| `engagements` | `advisor_engagements` counted per lane (drafting, proposed, signed, renewal due, ended), plus `other`. No client name. | not recorded: a partner's work is its firm's deals |
| `payout` | `advisor_payout_accounts`: `on_file`, `ready` (`derivePayoutState` is `verified`), `state`, `last_checked_at` | not recorded: a partner is paid through its firm's settlements |
| `agreement` | not recorded: no store records a studio agreement with an advisor | the signed partner invitation that made the account: `on_file`, `signed_at`, `source: 'partner_invitation'` |
| `lab_host` | the latest Lab host application for the advisor profile: `status`, `decided_at` | the same for the firm, `scope: 'firm'` |

No rating comment, client name or email is in the payload.

### 7. Open for the owner

- **An agreement store for advisors.** An advisor's studio agreement stays "Not
  recorded" until a store for it is decided.
- **Pausing a firm.** Whether pausing a partner account should also pause its
  firm's office hours is the owner's call. Today it does not (§4).
