## D4351 — A model the caller names meets its job's plan-lock and input-fit (AI model use cases 3c)

- **Status:** built 2026-11-03 (#4351, follow-up to #4313, the owner's decision of 2026-11-03).
- **Number:** D4351 is the issue's number (D4106).
- **Migration:** none.

### Why

Since #4347 (#4313 part 2), every rail text press runs a job through `textChoice`. A model the caller names (an "All models" choice, a persona module's connection) took another path: it was checked only against the page's or option's list, then ran. `textChoice` checks its own picks against two more rules, the plan lock (`MODEL_LOCKS` × the member's tier) and the input fit (the model's window holds the input and the output). A named model skipped both.

### What changed

- **One check.** `services/ai/textJobs.ts` `namedModelCheck(jobId, model, ctx)` applies `textBlock`'s plan-lock and input-fit rules, the same ones `textChoice` uses for its picks. It never chooses another model. It returns null when the model may run.
- **Where it runs.** `services/aiRouter.ts` `chooseModels` runs it for a text-shaped run that names a model on a rail page whose job writes text, before the page-list path, so before anything is held.
  - A run that names its own `textJob` already went through `textChoice` and is unchanged.
  - So is a run with no rail page: its caller is the platform, not a member's choice.
- **The refusals:**
  - **Plan-locked:** `plan_locked` with "This model is on [plan]. Pick another model, or change your plan." The run is recorded as refused, as `textChoice`'s is.
  - **Too long:** `invalid_input` with "This material is too long for [model]. [The longest model] reads the most; shorten it to fit. Nothing was run. Or pick another model." It is not recorded, as `textChoice`'s is not.
  - **Never a fallback:** a refused named model is never swapped for another.

### Which choices that run today will now be refused

These were read from the rail matrix on `origin/main` (975f6c3a8a): every page or option row whose job writes text, and the plan-locked models its list offers.

- **For every member: the four models locked to the top plan.** `lockAllows` has no tier that reaches `top_paid` today, so these are refused whoever names them, exactly as `textChoice` already refuses them as a pick:
  - `@cf/moonshotai/kimi-k2.6`, offered on 107 rows;
  - `@cf/deepseek-ai/deepseek-v4-pro-0813`, on 82;
  - `@cf/moonshotai/kimi-k2.7-code`, on 5;
  - `@cf/zai-org/glm-5.3`, on 5.

  Until now, naming any of them ran it. **This is the largest change here.** If the owner means these models to run for some plan, `lockAllows` needs a top tier; that is a separate decision.
- **For a member on no paid plan: the three models locked to the lowest paid plan.** They still run for a paying member:
  - `@cf/deepseek-ai/deepseek-v4-flash-0731`, on 117 rows;
  - `@cf/zai-org/glm-5.3-flash`, on 31;
  - `@cf/qwen/qwen3.8-27b`, on 5.
- **For any member: a named model whose window is smaller than the input plus the output allowance.** The smallest windows offered are:
  - `llama-3.3-70b-instruct-fp8-fast` and `qwq-32b`, at 24,000 tokens;
  - `qwen3-30b-a3b-fp8` and `llama-3.1-8b-instruct-fp8`, at 32,000;
  - `llama-3.2-1b-instruct`, at 60,000;
  - `llama-3.2-3b-instruct`, at 80,000.

  Until now such a run was sent and failed at the model, or was cut. It is now refused before any hold.
