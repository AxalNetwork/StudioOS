## D1367 — The Super Admin's AI cap is restored: the admin month, with no daily cap

- **Status:** decided by the owner on 2026-10-29; built by S21. The owner said: "restore cap even for the admin of 50$". Asked which cap, they chose "$50 a month, no daily cap".
- **Migration:** none.
- **Replaces:** D1363 §2 ("No limit for the Super Admin").

### The rule

`resolveAiCaps` (`services/aiBudget.ts`) gives a Super Admin the admin licence's **monthly** cap and no daily cap. That is the `ai_licence_caps` row for `admin` when HQ has typed one, else `WORKERS_AI_BUDGET_USD_MONTH`, whose default is $50.

- **No day.** `daily_capped` is false and the day equals the month, as for a member (D783). So one long transcription is not refused part-way through a day. This is the refusal that led to D1363.
- **The source** still reads `super_admin`.
- **No `unlimited` flag.** The $1 billion figure (`SUPER_ADMIN_AI_MICROUSD`) is gone, so no screen can print it again, such as the session meter's "Left this month $999,999,999.89".
- **Still applied:** a pause (D791) and the member's own spend limit (D788).
- **Only the Super Admin.** A plain admin keeps the typed day and month. A row in `super_admins` for someone who is not an admin still grants nothing.

**What is shown.** Every surface shows the real cap, because none of them is sent `unlimited`:
- the usage card;
- the Worker rail;
- `/account/usage`;
- `/account/ai-tokens`;
- the licence card;
- the session meter.

The spend meter (`loadMyAiSpend`) shows the month's cap and no daily cap. D1363's frontend "No limit" branches stay, but nothing triggers them now.

When the month is used up, the refusal is `budget_user_month`, which offers Top up and continue (D1363 §1).
