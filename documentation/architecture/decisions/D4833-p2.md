- **Status:** built for #4833 (Practice UX 5/6), 2026-11-15. Part 2 of #4833; part 1 is D4833.
- **Canvas:** `design/incoming/Practice v2 Page.dc.html`, PX-06 A (D4874): `chips([['Draft', 1], ['Ready'], ['Sent', 1], ['Opened', 1], ['Accepted', 1], ['All', 4]], 'All')`, and the Overview's "Memo v2 ready to send".
- **Builds on:** D5316 §2 (#5316, PR #5537): `ready_at`, `ready_by_user_id` and `ready_by_name` on each version, `ready_version` per work product, `totals.ready`, and `POST`/`DELETE /api/advisors/me/deliverables/:id/versions/:version/ready`.
- **Migration:** none. **Worker:** unchanged. The client methods `markMyAdvisorDeliverableVersionReady` and `clearMyAdvisorDeliverableVersionReady` were already in `api.js`.

### What the advisor sees

- **Filters:** Draft · Ready · Sent · Opened · Accepted · All, in the canvas's order. `?view=ready` opens on Ready.
- **The Ready chip narrows on the Worker's `ready_version`** (`isReadyItem`), which is the set `totals.ready` counts. So the chip's number is `totals.ready`, over every work product, and the cards under it are the same set. When a read does not carry `totals.ready`, the chip shows no number. It never shows 0 (D56/D68).
- **A card's status is still its latest version's.** An unsent latest version that carries `ready_at` is **Ready** (the `info` tone), not Draft, so Draft and Ready do not overlap. The card adds "Marked ready to send Nov 9 by Ada".
- **The detail sheet** shows the same line under the latest version and against that version in the history. A name that no longer reads back is shown as "Not recorded". The history stays free of controls.
- **Mark ready / Clear Ready** sits beside Send and Add version, on the latest unsent version only. Its consequence is shown before it is pressed:
  - Mark: "Marks v2 ready to send. Nothing is sent: the client sees nothing until you send it, and sending clears the mark."
  - Clear: "v2 goes back to Draft. Nothing is sent or deleted."
  - A version with no document cannot be marked. The control is disabled and says why, which is the Worker's own 422 `empty_version` rule.
  - There is no pop-up and no confirmation. The mark can be undone and sends nothing.
  - The answer, or the refusal, is shown in the sheet where it was asked, then the list is read again.
- **409 `already_sent`:** the version went out in the meantime, for example from another tab or from the by-client group. The sheet says "v2 has already been sent, so it can’t be marked ready or cleared", reads the list again, and the control goes away because the version is sent now.
- **Copy:** "There is no Ready filter" became "Ready is your own mark on a draft that is ready to send. It sends nothing; sending clears it." "There is no Ready state and no file upload" became "There is no file upload yet", which stays true until #5960 and #5961 land.

### Departures from the canvas

- **A mark on an older version.** The Worker's `ready_version` is the highest unsent version marked ready. That can be an older one, if the mark was set through the API before a newer draft was added. Such a card stays a Draft by its latest version, is still listed under Ready (so the count and the cards agree), and its line names the marked version ("v1 · Marked ready …"). This page only marks the latest version.
- **The by-client group** (D571) shows no Ready state. Its Send still goes through the confirmation, and sending clears the mark on the Worker.
- Version summary and document upload are not in this part (#5959, #5960, #5961). The Practice v2 shell is still #4829's.
