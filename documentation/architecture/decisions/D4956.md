### What the canvas decides

- The Team page keeps its areas, directories, SKILL.md format, version pins, read-only tools and no roles. The canvas adds an **HQ qualification workspace** and **search, filters and assign reasons** on the Team page.
- **HQ:** library (SK-01), skill overview (SK-02), a golden case × model evaluation matrix in a passing and a failing state with stale and not-run cells (SK-03), guided authoring with validation, unsaved-changes and conflict (SK-04), review with a diff and a named reviewer who is never the author (SK-05), a publish checklist over the server's real refusals (`needs_approval`, `golden_cases_failing`, SK-06), retire with a replacement (SK-07), and usage by version (SK-08).
- **Team:** library (SK-09), skill page (SK-10), and SKILL.md import refusing a write tool (SK-11).
- **A 10-state readiness model** (SK-13) and 12 page states (SK-12); phone, tablet 768 and dark boards.
- **`role_mismatch`:** v2 has no roles, but the Worker can still return it, so it is drawn as a reason with a remedy until the contract drops it.
- Re-checked against main on 2026-11-08: two P0s in the brief (the HQ lifecycle and the Team stubs) were already fixed, so those boards draw working flows.

### Backend required

- A server-computed readiness field, plus tools, in list responses (the HQ list omits tools today).
- A draft version check on `PATCH /api/teams/skills/:uid`, for the conflict state.
- Release history and rollback (#4533).
- Usage, quality and cost by executed skill version (#4536).
- Task-based discovery (#4538).
- A run-cost route; until it exists, cost reads Not recorded.

Readiness badges, the eval matrix layout, the publish checklist over existing refusals, editor guards and assign reasons. The design is code-informed, not screenshot-verified; no paid evaluation or publication was run. Skills, people, companies and outputs are sample data.
