## D4712 — A new advisor can complete the core Practice workflow from an empty account (#4712)

- **Status:** built by slot S21 on 2026-11-07. Closes #4712 (Practice audit 3/6, P1).
- **Migration:** none.
- **Builds on:** the Practice zone pages (PR2–PR5, D571), the legacy advisory tabs that are now redirects, and D4713 (which touches the same Sessions page for its availability guard).

### What was wrong

On the mounted Practice pages an advisor starting from nothing was trapped:

1. "Record an engagement" and "Record a work product" set `adding`, but their forms sat in the children `ZoneBody` does not draw for an empty collection, so nothing opened.
2. The post-session review section sat in the same children, so completed sessions could not be reviewed before the first work product existed.
3. Publishing a slot and completing / cancelling / no-showing a session existed only in the retired Opportunities and Engagements tabs. Sessions pointed users at them.
4. "Add a version" posted `{}` and recorded a version with no note and no link; the send path did not check content.

### What was decided

**One form, drawn wherever the page is.** `newEngagementForm` and `newProductForm` are built once and drawn under the empty state when nothing is on file, and in the Board / collection once there is something. Their buttons toggle (Close).

**The review section stands alone.** It sits outside `ZoneBody` and reads its own data (`loadHeld`: the completed bookings, then each session's reviews, all at once), so it has its own loading, error and empty state:
- loading: "Reading your held sessions…"
- sessions unreadable: "could not be read. That is not a claim that you have none", with Try again
- no held sessions: says to mark one held under Sessions
- a session whose reviews could not be read is `null`, shown as "Reviews not read" with no review form (filing over reviews that were not read could duplicate one). It is counted as "not read", never "No review" (`reviewCoverage`).

**A revision is never empty.**
- Worker: `POST /me/deliverables/:id/versions` requires a change note and an https link, else 422 `empty_version`. `POST …/versions/:version/send` refuses a version without an https link (422 `empty_version`), after the existing client-account check, so a legacy empty version or a title-only v1 cannot be sent.
- No route edits a recorded version: older versions are immutable by construction, and the form says so ("v1 stays exactly as recorded").
- Page: "Add a version" opens the revision form (the existing `AttachForm`, now requiring the note). Send says which version goes out ("Sends v2 — “Added the table” · opens docs.example") or why it cannot, and is disabled when there is nothing to send.
- `attachmentBody` now requires the change note as well as the link; the by-client Attach form shares it. The pinned test line that allowed an empty note is updated.
- Existing Worker fixtures that created empty versions and sent them were given content (`link_url`, `summary`), not exempted from the rule.

**Sessions runs the session.**
- `SlotPublisher`: the legacy form's four fields (starts, ends, seats 1 to 20, optional https meeting link) over the same `POST /me/slots`, checked first by `slotBody`. It is always on the page, and the empty-grid action opens it.
- `SessionLifecycle`: held / no-show / cancel on a confirmed session, over the same `/bookings/:id/complete | no-show | cancel` routes. A cancel needs a reason (the client is told); a no-show may carry one. A session already closed shows no form.
- No second booking or payment system is built: both reuse the existing routes. The legacy tabs stay as they are, and Clients and Contracts are untouched.

### Not decided here

- The review read still goes session by session. Reconciling its coverage with the overview, and the first-20 / 2,000-row limits, are #4702's.
- The legacy `advisory/OpportunitiesPage` and `EngagementsPage` files are not deleted: a redirect, not removal, was the decision that mounted the new pages.

### Tests

- `practice_first_use_4712.test.mjs`: the pure rules (`slotBody`, `outcomeBody`, `sendPreview`, `reviewCoverage`) and mounted zones: Engagements and Delivery in a true empty state, reviews with zero deliverables, an unreadable review and an unreadable session list, the revision form, Send's preview, Sessions publishing a slot and closing a session all three ways.
- `advisor_practice_d573.test.ts`: the whole core workflow from a synthetic advisor with no records, through to the client opening and accepting the second version, with a review filed while there are zero deliverables.
- Ten mutations were checked and caught: no note required, no link required, an empty version sendable, no form in either empty state, an unread review read as "No review", an optional note on a revision, no slot publisher, a cancel without a reason, and the lifecycle drawn for any status.
