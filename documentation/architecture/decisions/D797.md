## D797 — A licence's terms schedule: HQ records deal terms, renewal and notice, money and reporting per licence; the Administrator reads them, and the branch copy carries them

- **Status:** decided by S1 for the owner, 2026-10-20 (#2230; D-b of D795, #2228). The owner chose structured terms over the contract's text alone. The Licences canvas (`design/incoming/Licences Page.dc.html`, board L2) then added nine terms and the section numbers (S1 on #2230 and #2242), all in migration 512, so no second migration is needed.
- **Basis:** `origin/main` at `8902ea2c`. Worker paths are relative to `cloudflare-worker/src/`.
- **No UI here.** D800 and D801 draw the schedule, through `frontend/src/lib/api/licenceTerms.js`.

### 1. The store (migration 512)

- **`licence_terms`** has one row per `licence_uid`, and every term column is nullable. A null term is **not recorded**, never zero: a licence whose cure period HQ has not entered has no cure period on record.
- **The 31 terms:**

  | Group | Terms |
  | --- | --- |
  | Parties | `licensor_ip_entity` (platform IP: the payee for the licence fee and statements, D798 and D802) and `licensor_brand_entity` (trademark and brand), each one of `AxalEntityKey` (`management`, `holdings`, `gp`, `fund`); `governing_law` |
  | Territory | `exclusive` (0/1), `non_compete_months` (0–120), `referrals_note` |
  | Term and renewal | `renewal_mode` (`auto`, `on_request`), `non_renewal_notice_days`, `cure_days`, `termination_note` |
  | Money | `share_subscriptions_bps`, `share_licence_fees_bps`, `share_token_margin_bps` (a null stream falls back to `territory_licences.revenue_share_bps`), `royalty_platform_licence_bps`, `payment_terms_days`, `late_interest_bps` (per month), `minimum_guarantee_cents`, `fee_invoiced` (`annually`, `quarterly`) |
  | Deal terms | `first_look_business_days`, `co_invest_max_bps`, `carry_share_bps`, `referral_fee_bps`, `hq_approval_above_cents`, `conflicts_note` |
  | Seats | `seat_includes` |
  | Brand | `brand_kit` ("Axal VC brand kit", or the licensee's own for a white-label) |
  | Reporting | `usage_report_day` (1–28), `statement_period` (`quarter`, `month`), `data_role` (`licensee_controller`, `hq_controller`), `audit_right` (0/1), `audit_notice_days` |

  The canvas's single licensor became two, so the original `licensor_entity` is gone. Its replacement `licensor_ip_entity` is the payee every money read checks. The invoice date is the licence's anniversary (`starts_on`), so it has no column.

- **The ranges.** Basis points run 0–10000. Days run 0–3650, ten years, so a typo cannot store a century. Cents are 0 or more. The CHECKs hold every enum and range, so the store refuses what the route refuses.
- **Section numbers.** `DEFAULT_TERM_SECTIONS` gives each term the section the canvas cites (§1.1 to §8.5, §19.2, §19.5 and §22). `sections_json` stores only HQ's overrides for a licence (`{"carry_share_bps": "§7.3"}`). A read gives the defaults with the overrides on top, and a cleared override reads the default again.
- **The bookkeeping columns** are `updated_by_user_id` and `updated_at`.
- **`branch_licence.terms_json`** holds the terms as HQ pushed them. SQL `NULL` means a copy from before this column existed. The JSON `null` means HQ pushed and holds no terms for the licence.

### 2. One module for the field list (`services/licenceTerms.ts`)

- **`LICENCE_TERM_FIELDS`** gives each term its key, group, label, type and range. HQ's write, both reads, the branch copy and D800/D801 import it, so the list is written once.
- **`validateTermsBody`** refuses an unknown key, never ignoring it, so a typo cannot read as a save. It refuses a bad value naming the field. `null` clears.
- **Booleans** store as 0/1, and numbers must be whole: a float is refused, never rounded.
- **The other exports:** `termsFromRow`, `readLicenceTerms`, `termsDiff` and the three `TERMS_REASON` sentences.

### 3. HQ's write and read (`routes/admin_licences.ts`)

- **`PUT /api/admin/licences/:uid/terms`** takes the money-write bar, `requireSuperAdminWriteBar`: a TOTP-minted session, a step-up within 15 minutes, then the elevation.
  - The body is `{ terms?, sections?, reason }`. Only the keys named change.
  - A missing reason is 400 `reason_required`. A bad field is 400 `invalid_terms`, with the first field in `message` and all of them in `errors`.
  - Every save appends exactly one `licence_events` `terms_changed`. Its `detail_json` is `{ schedule: 'licence_terms', reason, changed }`, where `changed` holds each changed key's before and after (`sections.<key>` for a section). Its note is the reason.
  - It then pushes the branch copy, as Step 4's terms do (D272 retries a push that fails).
- **`GET /api/admin/licences/:uid/terms`** (Super Admin) reads the schedule back.
- **Step 4's `PATCH /:uid/terms`** (the fee, shares and term on `territory_licences`) is unchanged.

### 4. The Administrator's read (`GET /api/licence/mine`)

- **On HQ** it gains `terms`, `terms_reason` and `sections` for the caller's own licence. It is scoped through `licence_admins` as the rest of `/mine`, so a principal and a delegate read the same.
  - No row reads `terms: null` with "HQ has not recorded this licence's terms yet."
  - A failed read gives "…could not be read just now.", and costs the page its terms and nothing else.
- **On a branch** it reads `branch_licence.terms_json`, in its own query, so a branch that has not applied 512 still reads its licence.
  - A copy pushed before this change reads `terms: null` with "HQ has not pushed this licence's terms yet."

### 5. D798's statements read the schedule

- **`GET /api/licence/mine/statements`** reads `licensor_ip_entity` and `usage_report_day` from `licence_terms` and passes them to `licenseeStatements` (D798's seam; S1 moved this here from D808, #2250).
  - A licence whose IP licensor is not the fee's payee gets D798's `licensor_not_payee` refusal.
  - An unrecorded report day stays `null`, with no default (S1's ruling on #2250).
- **A schedule that cannot be read gives no payment instructions** (`terms_unreadable`). An account shown without the licensor checked could be the wrong entity's. The statements are still read.

### 6. The master agreement (D803) and HQ's editor (D801)

D803 (#2252) and D801 (#2274) were stacked on this branch and merged into it.
- **The template** names both licensors by merge field (`{{terms.licensor_ip_entity}}`, `{{terms.licensor_brand_entity}}`), with the Platform Licensor as the contracting entity for notices and invoices. It uses each new term at its section:
  - `referrals_note` at §2.5;
  - the three stream shares at §4.2, with the licence's single share for a stream left blank;
  - `royalty_platform_licence_bps` at §4.7;
  - `seat_includes` at §6.2;
  - `brand_kit` at §7.2;
  - `audit_notice_days` at §8.5.
  
  Migration 514's seed matches it. 514 is not on `main` yet, so it was changed rather than followed by a new migration.
- **The editor** takes the field list from this module, so the new terms appear in it on their own. `licenceTermsForm.js` gains the titles for the two new groups, "Seats" and "Brand and platform".

### 7. The branch copy

- **`assembleLicenceRecord`** is the one assembler behind the push and the pull (D206). It adds `terms_json`, a row-shaped JSON of the schedule, or the JSON `null`.
  - A ledger whose terms cannot be read leaves the key out, so the branch keeps the terms it has rather than losing the rest of the copy.
- **`applyLicenceCopy`** writes `terms_json` in its own update, after the copy's upsert.
  - It writes only when HQ sent the key, and only onto the copy that push wrote (`pushed_at`), so a late, older push never overwrites newer terms.
  - A branch without 512 logs the miss and keeps the rest of the copy.
