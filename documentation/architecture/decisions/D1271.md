## D1271 — Promo codes use HQ's Super Admin gates (#3297)

Part of #2381, following D1270's HQ-only screen. No migration or binding.

`cloudflare-worker/src/routes/admin_promos.ts` now uses `requireSuperAdmin`
for `GET /api/admin/promos`. Reads need the HQ elevation, without a TOTP
session or a recent step-up. `POST /api/admin/promos`, `PATCH` and `DELETE
/api/admin/promos/:id` use the shared `requireSuperAdminWriteBar`: a
TOTP-minted session, a recent step-up, then the HQ Super Admin elevation.
The shared gate order is retained.

A plain HQ Admin with a fresh TOTP session gets `403 Super admin required`
on each of the four routes. A branch with the same session gets `403 HQ
only`, even with a `super_admins` row present. Refusals precede promo reads,
Stripe calls and promo/audit writes. Existing authentication, stale-session,
strong-factor and recovery cool-off protections remain in place. The
`/api/admin/promos` cool-off prefix and its wildcard registration are unchanged.

The permitted holder's creation, activation and deletion logic is unchanged:
Stripe remains the source of truth, `promo_codes` is its mirror, and each
write retains the existing billing entry in `admin_audit_log`. D1271 changes
authorization only; the further scope, usage and history work belongs to the
other #2381 parts. The payments gates under #2386 remain separate.

`admin_promos_d1271.test.ts` mounts the real router and auth helpers over
canonical SQLite tables and migrations 264/277/282, with Stripe stubbed. It
checks all four plain-admin and branch refusals, unchanged rows and zero
provider/promo access after denial, holder reads without step-up, all three
successful audited writes, stale and non-TOTP write refusals, and the real
recovery middleware wired from the production cool-off prefix list.
New assertions and permission/cool-off regressions are mutation-checked.
