### 1. The pipeline (`services/decks/pipelines.ts`)

`PIPELINES.deck_image` lists six steps: expand, draw, check, style, alt and provenance. `runPipeline(input, deps)` runs them in that order. It takes its runs from `deps`, so a test can drive it with no Worker.

| Step | Run | A failure |
|---|---|---|
| expand | `rail_chat` rewrites the description as one picture | not used when it fails, or names a digit in any script (`\p{Nd}`); the description is drawn as written |
| draw | the picked model, at `sizeFor`'s size, with the request's seed | ends the image: "Eadwyn could not draw the image." Nothing is charged |
| check | moondream asks "a face?" then "written text?"; the `image_screen` run asks "NSFW?" | YES → refused (`real_person`, `text_in_image`, `image_blocked`) |
| style | `image_screen` asks whether the image is the deck's style and palette | NO → refused (`off_style`) |
| alt | `image_alt_text`, one sentence | never refuses; no text is `null` with its reason |
| provenance | the route's record, plus the XMP packet | — |

**Every check fails closed.** An errored check, or an answer that is neither YES nor NO, refuses the image as `check_unavailable`. No generated image is stored without passing all four checks.

### 2. Size and seed

- **`sizeFor(model, aspect, box)`** takes the area's box in slide pixels (`areasOf` and `boxOfAt`). Each side is the box's side divided by `UPSCALE_MAX` (1.25), rounded up to FLUX's 16-pixel grid, and at least 256. If that is more than the model's `maxSide`, both sides scale down together. A model that takes no size (Schnell) gets `null`. With no area, the size is the aspect's own size.
- **The seed** is `seedOf(seed_base, card_uid, area, variant)`, a 32-bit FNV-1a hash.
  - The seed base is D1544's: `seed:<theme.art_direction.seed_base>` when the version's theme keeps one, else `venture:<project id>`. The art direction is D1544's too (style and palette default to it, its note is in the prompt, its reference image rides in the draw's options). Nothing is stored a second time.
  - D1544 drew image n with `seed_base + n`. The pipeline's seed replaces that for a deck image, as #3756 asks; an edit (D1544's `deck_image_edits`) keeps its own.
  - A press starts at the card's next `variant_index`, so "draw one more" draws a new seed, not the same picture again.
  - Every row records its `seed` and `variant_index`, so its seed can be recomputed.

### 3. One hold, and a refusal settles at zero

- **A press holds once** (`reserveAiBudget`) for every image and step. Every run goes under that hold as `parentHold`, and the press settles once with the sum of its usage rows.
- **A refused image's usage rows are set to 0 before the settle** (`refundSettled`, bound to `reservation_uid = ? AND id IN json_each(?)`). The venture's cycle log gets one row, `deck_image_refused_zero`. The charge was never taken, so no money moves.
- **A passed image that R2 cannot store** stops the press with `image_unsaved`, as D1544's route did; it was charged for its runs.
- **The refused image is kept as a `discarded` row.** Its `r2_key` is `refused/<project>/<uid>`, and its bytes are never stored. The row keeps its steps at zero and `qa_json` with the code.
- **Every run of one image** carries `record_ref = deckimg:<pipeline_uid>`. An image's row keeps what its whole pipeline charged.

### 4. What the press answers

- **The quote** returns `steps`: every step and its hold (pd14's line). `per_image_microusd` is the hold for the whole pipeline.
- **A press** returns `{ images, refused, stopped? }`.
  - Each image carries `steps`, `seed`, `variant_index`, `pipeline_uid` and `provenance`.
  - Each refused line carries `code`, `message`, `steps` at zero, `charged_microusd: 0` and `redraw: true` (the one redraw offered).
- **When every image was refused**, the press answers 422 in the first one's words. The body carries `refused` and `charged_microusd: 0`.
  - `refusalOf` and `RefusalLine` (AreaLightbox, AreaResults) show it as pd15's sentence: "Not used: the image check found text in the picture. You were not charged for it."
  - No new UI and no new route.

### 5. The one-click run (`pipelineStep`, `stepExecutor`)

- **A generation run's `deck_image` step is the same pipeline**, under the run's parent hold, with no press (#3753, AUTO-6).
- **A refused image settles at zero and is redrawn once** at the next variant. A second refusal leaves the area out (`error_code` is the refusal code).
- **The step's variant** carries the image, alt, seed, variant, steps, qa and the refused lines.
- **No path draws a deck image without the checks.**

### 6. Provenance (V = A)

- **A passed image is marked before R2.** It is first stripped of metadata (D1506), then gets an XMP packet: `Iptc4xmpExt:DigitalSourceType = trainedAlgorithmicMedia` and `xmp:CreatorTool = <model id>`.
  - In a PNG the packet is an `iTXt` chunk ("XML:com.adobe.xmp") after IHDR. In a JPEG it is APP1 after SOI.
  - WebP is left unmarked. `provenance_json.xmp` is then `null`, saying so.
- **`provenance_json`** records the pipeline uid, model, seed, size, prompt hash, whether the prompt was expanded, the art direction and the XMP written.
- **`sha256`** stays the stripped image's hash, so duplicate detection (D1506) is not changed by the mark.

### 7. Columns

- **`deck_images` gains seven columns:** `seed`, `steps`, `prompt_sha256`, `pipeline_uid` (indexed), `variant_index`, `qa_json` and `provenance_json`.
- The migration only adds. No row is changed.

### 8. The first stamped migration

- **`202611021726_…` sorts before `543_…` as text.** Every guard and test fixture that sorted migrations with a plain `.sort()` would have applied it before `deck_images` existed.
- **They now sort with `compareMigrations`**, which is numeric and is what the runner uses. That covers `check-baseline-drift.mjs` and about seventy test fixtures.
- **Main's D4133 (`_schema_once.mjs`) now loads most fixtures** and already sorts with `compareMigrations`; the fixtures it did not take over sort the same way.
- **Three tests compared names as strings** (`f < '501'`). They now compare numbers.
- **`partner_delivery_stores`' name check** now accepts a three-digit prefix or a D4106 stamp.

### 9. Pages (D552)

The pipeline's runs record the page their caller names. `drawDeckImages` and `pipelineStep` forward `a.surface`, and the press passes `AI_SURFACE.raisePitch`. D552's table lists `services/decks/imageDraw.ts` as a forwarded page.

### 10. Tests

`cloudflare-worker/test/deck_image_pipeline_d1505.test.ts` covers:
- text, face and screen fixtures are refused and settle at zero, and the balance is unchanged;
- every check that cannot run, and an answer that is neither YES nor NO, refuses the image;
- every structure × area × aspect × sized model upscales by at most 1.25×;
- the seed reproduces, from the venture or from the theme's `seed_base`;
- XMP survives R2 (PNG and JPEG);
- the one-click step redraws once, then leaves the area out.

`_pipeline_ai.ts` is the shared stand-in.

- the upscale divisor raised to 1.6;
