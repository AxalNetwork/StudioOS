## D4677 — Pipeline: atomic, current and evidence-backed transitions (#4677)

- **Status:** built by Claude Code for slot S26, 2026-11-07. Not deployed and not checked live.
- **Part of:** the Pipeline audit, package 2 of 6 (#4677). Revalidated on `main` (93def47) before building: every problem below was still present.
- **Migration:** none.
- **Code:** `routes/needs.ts` (`quoteTransition`), `routes/pipeline.ts` (`openGateReview`, `decide`, the board), `routes/legalcap.ts` (the spin-out steps), `frontend/src/components/SpinoutWizard.jsx`.

### 1. What was wrong

- Accepting a quote was five unbatched writes with the winner decided from an earlier read. Two accepts could both win; an engagement insert that failed was swallowed (`catch {}`) after the quote was already accepted and the need filled, and the request still answered success.
- Deciding a gate wrote the gate, then the stage, then the project in separate statements, so a failure left a decided gate with the project in its old stage. An older pending gate could be decided over a newer review.
- A rejected or spun-out venture stayed on the active board. `go-independent` swallowed the project update's failure.
- The IP licence was written `signed` the moment it was generated; Stripe Atlas "incorporation" minted a random EIN and marked the company incorporated with no Atlas call, and its reservation guard could never match the `pending` status every subsidiary starts with. `force: true` skipped the passed gate and the incorporation.

### 2. What changed

1. **Quote acceptance is one batch** whose first statement claims the winner (still `submitted`, need open, no accepted quote on the need) and whose other three match only the quote that call accepted (`decided_at` is the token). The engagement is built by one `INSERT … SELECT` from the quote and its need with `NOT EXISTS`, so it cannot disagree with them, and its failure fails the batch. A retry returns the accepted quote and repairs a missing engagement.
2. **Gates.** A review supersedes older pending gates and opens the new one with the stage move in one batch. A decision matches only the deal's latest pending gate and moves the gate, stage and project together; an obsolete gate is `gate_superseded`.
3. **The board** drops rejected, archived and `spun_out` ventures; `?include_closed=1` keeps the history readable.
4. **Evidence.** The IP licence stays a draft until HQ records who signed and when. Incorporation is recorded only from the Atlas id, EIN and date a person enters, validated; nothing is minted. `go-independent` needs that recorded evidence and moves the subsidiary, project and stage history in one batch.
5. **The override is explicit.** `force` is gone. Starting a spin-out without a passed gate takes an admin's `override { kind, reason }`, recorded; nothing overrides incorporation.
6. **The wizard** has a signature form and an incorporation-evidence form, and sends no `force`.

### 3. Left alone, and why

- **No unique index on `quotes(need_id) WHERE status = 'accepted'`.** Production may already hold a need with two accepted quotes, and a migration cannot choose which to keep; the claim statement enforces the rule for every new accept. The index is the right next step once those rows are reviewed.
- `projects.status` has a CHECK without `spun_out`, so an independent venture is marked by `projects.stage = 'spun_out'` (already what `go-independent` wrote); `status` stays `spinout`.
- `POST /subsidiary/spinout` still creates the subsidiary, its three draft documents and its compliance rows as separate writes. It is idempotent per deal and the rows are drafts, so a partial run is repeated, not wrong.
- Subsidiaries the old mock marked `incorporated` carry a made-up EIN and Atlas id, and they still pass `go-independent`'s check, because the fields are filled. Nothing here can tell them from real ones; HQ should re-record any such company before it goes independent.
