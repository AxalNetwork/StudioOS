## D7660 — The workspace crumb in text-axal-muted, and the crumb row back in Expertise's axe scan (#7660)

- **Status:** built 2026-11-19. Filed from D7517's follow-ups (#7517, #7544) on the owner's answer of 2026-11-19.
- **Builds on:** D7517 (the Expertise axe spec, which left the crumb row out of its scan), D4803, D4814 and D7517 (the same `text-axal-faint` to `text-axal-muted` swap inside a scanned frame).
- **No migration, no Worker route, no client method, no new dependency.**

### The decision

`WorkspaceShell.jsx` draws the crumb row (`link-workspace-crumb`, `‹`, the zone link) above every workspace page's h1. The row's class set the colour for all of it, the zone link included, and it was `text-axal-faint`: `#a1a1aa` on the page ground `#f9fafb`, **2.45:1**, under WCAG 2.2 AA's 4.5:1. It is now `text-axal-muted`: `#6b6577` on `#f9fafb`, **5.35:1** (5.60:1 on white). The tokens are unchanged, and only this one class moves; the bold current-page segments stay `text-axal-ink`.

Dark mode takes no `dark:` class here: the shell maps both tokens in `index.css` (`.dark [data-app-main] .text-axal-muted` is `--app-text-muted`, `#9ca3af`, 7.37:1 on `#0b1220` and 6.99:1 on `#111827`), as it did for `text-axal-faint`, which already passed in dark.

### The scan

`frontend/tests/e2e/expertise_axe_7517.spec.js` no longer excludes the crumb row: its scope is Expertise's whole column (`div:has(> nav[aria-label="Expertise sections"])`), which holds the crumb row, and each scan first asserts the crumb link is inside that column. The sidebar and the Worker rail are still outside it.

Mutation-checked: with the crumb back on `text-axal-faint` the 18 light-mode page scans fail on `serious color-contrast: a[data-testid="link-workspace-crumb"]` (and the zone link on the zone pages); the 18 dark scans pass, as the analysis above predicts.
