### One classifier (item 1)

`scripts/merge-policy.mjs` (D5607) imported `node:child_process`, `node:path`
and `node:url` at module top, so a Worker could not bundle it. The pure
classifier moved, unchanged, to `merge-control/src/lib/classify.mjs`. The
script imports it and re-exports `classify`; it keeps only its Git diff
adapter and CLI. `merge-control/src/policy.ts` imports the same file, so
Wrangler bundles the same rules into the Worker. There is one copy.

- The file lives inside `merge-control/` because D5618's import-boundary test
  refuses relative imports that leave that folder. The script may import
  inward.
- It is plain JavaScript with a `classify.d.mts` type file. The landing-policy
  workflow runs `node scripts/merge-policy.mjs` on the runner's default Node
  with no type stripping.
- `merge-control/**` is a T2 path. A change to the rules needs the owner.
- `merge-control/test/policy_check_5620.test.ts` asserts that `policy.ts`
  exports the shared function, that the script imports and re-exports it, and
  that the script defines no rule of its own.
  `frontend/test/landing_policy_5607.test.mjs` asserts the script's export is
  the same function object. Either fails if a second copy appears.
- No model call. The classifier has no imports and no I/O.

### policy_version (item 1)

`policy_version` is the deployed build's commit. The deploy job checks that
`GITHUB_SHA` is a full SHA equal to the checked-out `HEAD`. It passes
`--define MERGE_CONTROL_POLICY_VERSION:"<sha>"` to the dry run and the deploy.
`wrangler.merge-control.toml` holds no value, so nothing can default it.
`policy.ts` reads the constant at module load and throws unless it is 40
lowercase hex characters. `index.ts` imports it and reports it on
`GET /status`, so every deployed bundle evaluates the check at startup. A
bundle built without the define throws at startup, and Cloudflare refuses an
upload whose startup throws.

- Verified locally with Wrangler 4.156.1: `deploy --dry-run --outdir` with the
  define inlines the SHA. Loading that bundle under Node with a
  `cloudflare:workers` stub succeeds. The bundle built without the define
  throws `policy_version is not injected: build refused`.
- The upload refusal itself was not exercised, because nothing was deployed.
- The test loader sets a fixed test value, standing in for the define. A test
  deletes it and confirms `policy.ts` refuses to load.

### evaluate({base, head}) (items 2 and 7)

`merge-control/src/policyCheck.ts` makes one `GET compare/<base>...<head>`
through the D5618 installation client. The client now allows `..` only in
that exact form, with two full SHAs. Each request has a 10-second abort
signal. The three-dot compare diffs against the merge base, as the script
does. Compare statuses map to `A`, `D`, `M`, `R` and `C`. Each file's patch
goes to the shared classifier. The result carries `conclusion`, `tier`,
`reasons`, `policy_version`, `base` and `head`.

`success` comes only from a finished classification of T0 or T1. Every other
path returns T2 with `action_required` and a named reason:

- a list of 300 files or more (the compare API cap; GitHub returns files on
  the first page only, per the 2026-11-11 21:48Z comment on #5620);
- any file without a patch: binary, oversized or a pure rename;
- a status other than the five above, such as `changed`, or a rename without a
  previous path;
- a response without a file list, an empty list, or a malformed entry;
- any API error, thrown exception or invalid input SHA;
- no result within 15 seconds; a late reply is ignored.

`evaluate` never throws, and its catch returns T2. It writes nothing.

### Known difference from the script

The compare API reports no file mode. The script reads link and submodule
modes from raw Git output; `evaluate` cannot. A submodule has no patch, so it
is T2. A symlink has a patch and is classified by its path alone. #5990 should
decide whether to read modes from the Git trees API, which has its own
truncation flag that must also mean T2, before the check is relied on.

### Mutations

Each mutation made the focused test file exit 1. Each was then restored.

| Mutation | Failing tests |
| --- | --- |
| The catch returns T0 `success` | cap/patch/malformed; errors/timeouts; client |
| Cap check `>=` becomes `>` | cap/patch/malformed |
| A missing patch is accepted | cap/patch/malformed |
| No timeout race | errors/timeouts |
| An API error yields a T0 file list | errors/timeouts; client |
| The client allows any `..` path | client |
| The script wraps a second `classify` | one-source (both test files) |
| A missing `policy_version` defaults to zeros | policy_version |
