## D1158 — Fund admin part 1: the LPs across funds read, the positions read per fund, and the quarterly performance history

- **Status:** filed by S21 for S1 as #3065, part 1 of Fund admin (#2388). Built by S22. Worker and clients only, no page. **No migration.**
- **Canvas:** FND5 (every LP of every administered fund in one table) and FND10 (positions with their latest mark, and two charts by quarter), in the D1157 export.

### 1. `GET /api/fund-admin/lps` (FND5)

**Route and service.** The route is `cloudflare-worker/src/routes/fund_admin.ts`; the service is `services/fundAdminLps.ts`.

**Gate.** `requireFundAdminReader`, the gate `/access` and `/overview` use:
- a support session is refused (`support_session_refused`);
- anyone but an admin gets 403;
- a branch Worker is refused (`HQ_ONLY`);
- a frozen admin gets D135's 423.

**Audited first.** The roster carries members' names, emails and identity states. So the fail-closed `auditRead` row (`fund_lps_read`, added to `READ_AUDIT_ACTIONS`) is written before any row is read. When that row cannot be written, the route answers 503 `audit_unavailable` with no rows.

**Rows.** There is one row per `limited_partners` row of each fund `administeredFunds` returns (GP of record absent or an admin). An outside GP's fund is never in it.

| Field | Where it comes from |
| --- | --- |
| `commitment_cents` | `limited_partners.commitment_amount` |
| `called_cents`, `received_cents`, `outstanding_cents`, `overdue_lines` | The fund's call ledger (`readFundCalls`): numbered and legacy unnumbered lines, the same lines the overview totals |
| `distributed_cents` | The sum of the LP's **paid** `fund_distributions` |
| `lp_type`, `lpa_signed`, `lpa_signed_at` | The LP row |
| `kyc_status` | The LP's account |
| `last_notice` | The newest D716 `legal_notices` row addressed to the LP |
| `booklet` | Joined through the application. See below. |

**The booklet join.** It runs `limited_partners.user_id` plus the fund's slug, then `lp_applications`, then `fund_subscription_booklets`:
- The live booklet comes before a withdrawn one.
- An application with no booklet yet reads `not_started`.

**Never a zero for a missing value.** Each figure no store holds is `null`, and the row's `unavailable` map gives the reason under the same key:

| Figure | Reason when null |
| --- | --- |
| Ledger figures, for an LP with no ledger line | "No capital call line has been issued to this LP." |
| Commitment of 0 | "No commitment is recorded" |
| Distributions | "No paid distribution is recorded" |
| Identity, for an LP with no account | It has no account |
| Identity, for an account with no check | No check is recorded |
| LP type | Not recorded |
| Last notice | No notice yet |
| Booklet | No account, the fund takes no applications, or no application |

**A failed store.** A store that cannot be read (the ledger, notices, booklets, distributions or LP type) makes only its own figures null, with "Unreadable … Try again". The rest of the row still reads. A fund whose ledger is truncated at `LINES_LIMIT` withholds its per-LP ledger figures with a reason, and does not show a partial sum.

**Filters, search, sort, pages.** These run on the Worker, after the bound read. Only the bound fund ids reach SQL, via `json_each(?)`.

| Parameter | Values |
| --- | --- |
| `fund` | An administered fund, or 404 `fund_not_administered` |
| `lpa` | `signed` / `unsigned` |
| `identity` | A KYC value, or `not_recorded` |
| `booklet` | `not_started` / `open` / `submitted` / `withdrawn` / `not_recorded` |
| `outstanding=1`, `overdue=1` | Flags |
| `q` | Name or email, case-insensitive, up to 100 characters |
| `sort` | `name` / `fund` / `commitment` / `called` / `received` / `outstanding` / `distributed` / `last_notice` |
| `dir` | `asc` / `desc` |
| `page` | Page number |
| `per_page` | Up to 200 |

- Sorting: a row with no value sorts last in either direction, and ties fall back to the LP id.
- A bad parameter answers 400 `invalid_lp_query`.

**Totals.** Totals are the sums over **every row the filters keep**, across all pages, not just the page returned. Each figure is summed over the rows that hold it. `totals.not_recorded` counts the rows that do not, and a figure no row holds totals `null`.

### 2. `GET /api/fund-performance/:id/positions` (FND10)

**Route and gate.** The route is `routes/fund_performance.ts`; the service is `readFundPositions` in `services/fundPositionsHistory.ts`. Only the fund's GP of record and admins may read it (`requireFundGp`). Anyone else gets the fund's 404 or the tier refusal.

**What each position carries.** Each position attributed to the fund returns:
- `round_name`, `invested_amount`, the company name and `position_date`;
- its latest valuation on or before today: `value_cents`, `valuation_date`, `source`, and `recorded_by` (`{ id, name }`).

**A position with no mark.** It reads `marked: false`, with `value_cents: null` and the reason "No valuation is recorded for this position; invested cost is not its value." `unmarked` counts these positions.

### 3. `GET /api/fund-performance/:id/history?step=quarter` (FND10)

**Gate and step.** The gate is the same as positions. `step` must be `quarter`; any other value answers 400 `invalid_history_step`.

**What it computes.** `readFundHistory` calls `readFundPerformance` as of each quarter end:
- from the quarter of the fund's first call (the earliest of `fund_capital_calls` and the legacy unnumbered lines, the same two stores `readFundPerformance` counts);
- through the last quarter end on or before today;
- at most 160 quarters, the latest kept, with `truncated` set when any are dropped.

Nothing is stored: the history is computed on every read.

**Point in time.** `readFundPerformance` gains `{ pointInTime: true }`. With it, the read counts only:
- positions held by the date (`position_date`, else `created_at`);
- calls issued by the date;
- distributions paid by the date.

Without it, today's reads are unchanged. Each statement takes the switch as a bound flag (`? = 0 OR …`), so there is no interpolation.

**A quarter it cannot compute.** It keeps D627's `unavailable` reasons and is never given a 0:
- A quarter holding a position not yet marked reads `nav_cents: null` with "Every attributed position needs a dated valuation".
- RVPI, TVPI and IRR are withheld with their reasons.

A fund with no call answers `items: []` and the reason "No capital call is recorded for this fund…".

### Tests

`cloudflare-worker/test/fund_admin_reads_d1158.test.ts` runs with `fetch` stubbed and counted, so Mercury is never reached. It covers:
- **Roles:** a founder, a partner, an investor, a support session and a branch admin are refused, and no refused read is audited. Admin and Super Admin read.
- **Audit:** a failing audit answers 503 with no rows.
- **No ledger line:** an LP with no ledger line reads null with its reason. Every other "not recorded" reason is covered too.
- **Totals:** totals equal the sum of the rows across every page, also when read one row per page.
- **Query handling:** every filter, the search, both sort directions with nulls last, pages, the bad-parameter refusals and the outside fund's 404.
- **A dropped store:** only its own figures are Unreadable.
- **Positions:** the latest mark, and an unmarked position with its reason.
- **Positions and history access:** the GP and admins read; another investor and a founder do not.
- **History:** quarters walk from the first call; positions, calls and distributions are counted point in time; a quarter with an unmarked position carries its reason; a fund with no call gives its reason; `step=month` is refused.

All 46 mutants of the new code were killed. The two that first survived (totals over the page instead of the filtered set, and the quarter label) now have assertions. The redundant account guard on KYC was removed.

`fund_performance_d627.test.ts`'s fixture table gains the `position_date` and `created_at` columns, which the real schema already has.
