## D7651 part 2 — Research › Markets: the Eadwyn summary of all of your readings, to the cent, from the stored rows (#7651)

- **Status:** built by Claude Code, 2026-11-19. Not deployed. Part of #3701. Part 1 is `D7651.md` (#7666, the summary of one reading); this part builds on it.
- **Owner's answer:** **A** (2026-11-19), to D7651's "Pending the owner": build the summary of all of a member's readings the same way as one reading's, from the stored readings only, with **no model call**. B (a model-written summary in a mounted draft band with rail options per licence) is not built.
- **Route:** `GET /api/research/market-readings/summary`, a new handler in `routes/research_client_prep.ts`. No migration.

### What was built

- **Worker.** `services/marketReadingRead.ts` `readingsSummary(rows, stored)` over the caller's readings joined to their own service lines, newest first (`ORDER BY r.ran_at DESC, r.id DESC LIMIT 500`). It returns `readings` (every reading the caller has stored, a `COUNT(*)`), `lines`, `age` (`current`, `ageing`, `stale`, `undated` over the lines), `newest_ran_at` (the lines' newest run date, or null) and `basis: 'stored_readings'`. Each line is part 1's `readingSummary(row)` plus `age_days` and `age`, so its range is the stored cents and `toMajorString` text ("99.50", "4500.00") and its `line` writes $4,500.00 – $6,000.00; nothing divides by 100 or rounds. The age bands are the page's own (`AGE_AT = 30`, `STALE_AT = 90`; `readingAgeBand`), and a test holds the Worker's constants equal to `marketReadingRead.js`'s.
- **Which readings are lines.** The card's own rows: the newest reading for each active service line, and every reading not for a service line — what `GET /market-readings` lists above the summary. An older run of a service line counts in `readings` but is not a line, because a newer run replaced it; a reading whose service line has left the catalog (inactive or gone) is not on the card, so it is not on the summary either. Two runs of one service line on the same day: the later save is the newest. The list read gained the same `id DESC` tie-break, so the card and its summary always name the same run.
- **Gate.** `requireAuth`, then an investor-only account (`holdsOnlyLicence(user, 'investor')`) is refused with 403 `readings_hidden_for_investors` through `refuse()` before anything is read (D6273 Q2). Both statements are `owner_user_id = ?`, so only the caller's rows are read. The route names no record, so `build-auth-inventory.mjs` flags nothing and it has no ledger entry (an entry for a route that is not flagged fails the check).
- **Precedence.** `GET /market-readings/:uid` also matches `/market-readings/summary`, and Hono runs matching handlers in registration order, so the summary is registered ahead of it and returns first. `research_client_prep_4574.test.ts` now lists it in its place and holds that the summary route answers first and that only `/:uid` is chained after it on that one path; reading uids are 32 hex characters, so no reading is called "summary".
- **Client.** `researchMarketReadingsApi.all()` in `frontend/src/lib/api/researchMarketReadings.js` (`api.js` is a frozen hub, D5615).
- **Page.** `ReadingsSummary.jsx`, drawn by `MarketDirectoryZone.jsx`'s `Readings` card between its header (Export CSV, Record a reading) and its rows, only when the zone passes it a read. The zone reads it with `useRead` beside the list, never for an investor (whose zone draws no readings card), and re-reads it after a save. It draws "Eadwyn summary of your readings", "From your stored readings only. No model is called and nothing is rounded.", the Worker's counts ("3 readings stored, 2 summarised below · 1 current, 1 ageing, 0 stale · newest run 2026-11-16"), and one line per row as RMP-12 draws it, the range in mono and unbroken at 390, then its age word. `marketReadingRead.js` `readingsSummaryView` reads each line through part 1's `summaryView`, so a line whose text disagrees with its cents reads Not recorded rather than a figure. States: loading (`aria-busy`, a reload keeps the last summary), Unavailable with Try again (`DataState`), "No readings recorded, so there is nothing to summarise.", and Not recorded for an answer that is not a summary.
- **Dark and phone.** The block sits on the violet band skin with its dark pair; muted lines carry `dark:text-gray-400`, the ageing and stale words their amber and red pairs; lines wrap with `break-words` and each range stays on one line.
