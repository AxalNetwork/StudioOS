### 1. What the canvas settles

The canvas follows the prompt in #4289. Where it is more specific, the canvas wins:

1. **The duration is counted in invoices, not months.** Every surface reads "12 invoices per member" and the ledger's invoice column reads "3 of 12". P3 counts a member's first 12 paid invoices on the attributed subscription. It does not count 12 calendar months from the first invoice, so a paused or annual plan doesn't lose or gain commission against the label.
2. **A moved handle redirects for 12 months** (in7s). After that, the old handle reads as unknown and can be taken again. P2 keeps `slug_history` rows for handles 12 months.
3. **Apply again after 90 days** (in9r). A declined application dates its retry. P1 refuses a new application before `decided_at + 90 days` and returns that date.
4. **The handle changes once every 30 days**, and Links says when ("Change in 18 days", in2). P2's read returns `next_change_at`.
5. **The Overview's Eadwyn line restates figures with their date** ("From your link records, as of …"). It is built from P6's read and never from a model call, so it cannot promise anything.
6. **A small group reads "Fewer than 5"** everywhere, in the cohort grid as `<5`. A value nothing stores reads "Not recorded", with the date the store starts when there is one ("EUR revenue is stored from …"). A failed read reads "could not be read. That is not the same as having none." with Try again.
7. **The rates on `/influencers` and in Settings are data, not copy.** The public tier table and Admin's tier defaults read the same settings P1 stores (D1050). The canvas's 20% · 25% · 30% are P1's seed, and the page never types them.
8. **Admin money columns** read "HQ reads" for an admin and the amounts for the Super Admin (in11b, in11d), each currency on its own line.
