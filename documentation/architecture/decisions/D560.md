## D560 — Learning webinars: registration within capacity, a time-gated join link, and recordings (migration 391)

**A webinar is a scheduled live session in the Learning center:**
- The Super Admin schedules it, publishes or cancels it, and attaches its
  recording afterwards.
- Members register within its capacity and get its calendar entry.
- The join link reaches only a registered member, and only from 15 minutes
  before the start until the end.

Slot S07, issue #1161, 2026-10-06, on #1158's tables (D557). The canvas is
`design/incoming/Learning.dc.html` (D566). Session 1's screen
(`WebinarPanel.jsx`, #1163, D562) reads this payload.

### Migration 391

| Table | What it holds |
| --- | --- |
| `learning_webinars` | `uid`, `title`, `abstract`, `host_name`, `starts_at` and `ends_at` (UTC ISO instants; the end must be after the start), `timezone` (IANA, for display), `join_url` (https), `capacity` (null is no limit, never 0), `recording_item_uid` (a D557 video item), `visibility`, `status` (`draft`, `published` or `cancelled`), `created_by` and timestamps. |
| `learning_webinar_registrations` | `webinar_id`, `user_id`, `registered_at`, `attended` (null until someone records it). Unique on the pair. |

Every closed set is a CHECK.

### The join link

It is gated in one function, `memberWebinar` in
`services/learningWebinars.ts`. `join_url` is in a payload only when all of
these hold:
- the caller is registered;
- the webinar is published (not a draft, not cancelled);
- the clock is between 15 minutes before `starts_at` and `ends_at`
  (`joinWindowOpen`).

Otherwise `join_url` is null, and `join` says why: `not_registered`, `not_yet`,
`ended`, `cancelled` or `draft` (addendum below). Two other places never carry the link:
- **A list never carries it**, whatever the window says.
- **The `.ics` file never carries it.** The file links to the webinar's page,
  which the member opens to join.

### Routes

**Super Admin** (`routes/admin_learning_webinars.ts`, at `/api/admin/learning`).
Every write is recorded as `learning.webinar.*`:
- `GET` and `POST /webinars`; `GET` and `PATCH /webinars/:uid`.
- `POST /webinars/:uid/publish`, `/unpublish` and `/cancel`. Publishing needs
  a start and an end, and only a published webinar is cancelled.
- `PUT /webinars/:uid/recording` with `{item_uid}`. It must be a video item;
  null detaches it.
- `PATCH /webinars/:uid/registrations/:userUid` with `{attended}`: true, false
  or null.
- A capacity below the current registrations is refused.
- The registrations list names people by name and uid, never by email.

**Members** (`routes/learning_webinars.ts`, at `/api/learning`):
- `GET /webinars?when=upcoming|past`, with `registered_count`, `seats_left`
  (null with no capacity), and whether the caller is registered. Upcoming
  includes a webinar that is running now.
- `GET /webinars/:uid`: the webinar, the caller's registration, the join link
  in its window, and the recording once it has ended.
- `POST /webinars/:uid/registration` and `DELETE …`:
  - **Register:** within capacity, and before the end. The capacity check and
    the insert are one statement, so two members cannot both take the last
    seat.
  - **Unregister:** before the end. After it, the registrations are the
    attendance record.
- `GET /webinars/:uid/calendar.ics`: built by the Calendar's helper
  (`buildEventIcs` in `services/eventsCommon.ts`). That helper now takes an
  optional `uid` and `url`, so the entry is the webinar's own; events'
  defaults are unchanged.

**Visibility** is `canSeeLearning`, as for every Learning subject. A cancelled
webinar is still shown, marked as cancelled, so its registered members learn
it is off.

### The recording

A past webinar returns
`recording: {available: true, item_uid, href: '/learning/videos/<uid>'}` once
a published video item is attached. Until then it returns
`{available: false, reason: 'Recording not available'}`. A draft video is not
linked, since the member could not open it.

### Not in this change

**Webinars as program content.** D558 (#1159, PR #1195) reserves the
`webinar` content kind and refuses it until this store exists. Once both
merge, a follow-up lets a program hold a webinar and opens `program`-visibility
webinars to its enrolled members.

### Tests

`cloudflare-worker/test/learning_webinars_d560.test.ts` (6 tests) runs on a
database built from the migrations through 391. Webinar times are set relative
to the real clock. It pins:
- the join link: never to an unregistered member, never before its window,
  gone at the end, never in a list, and never in the `.ics`;
- capacity, including a freed seat and no limit as null;
- the recording appearing once one is attached;
- the gates and the actor;
- 391 applying.

Each assertion was mutation-checked, and each mutation caught (21).

### Addendum (#1252, 2026-10-06): a draft is refused as a draft

**No route calls a draft "cancelled".** Only the Super Admin can open a draft,
and it was never cancelled.

| Webinar | `memberWebinar`'s `join` | `POST /webinars/:uid/registration` |
| --- | --- | --- |
| Draft | `draft` | 409 `{code: 'draft', message: 'This webinar is a draft. Publish it before members can register.'}` |
| Cancelled | `cancelled`, as before | 409 `{code: 'cancelled', message: 'This webinar was cancelled.'}`, as before |

**Tests:** one in `learning_webinars_d560.test.ts`, which fails on the code
before this change. It pins:
- the draft's and the cancelled webinar's `join`, both ways;
- each refusal's code and sentence;
- that a member still cannot open a draft;
- that a refused registration is not stored.

Eight mutations were made, and every one was caught.
