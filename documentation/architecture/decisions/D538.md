## D538 — No market-intelligence stub row reaches a read or a screen

**Every read of `market_intel_rows` and `market_intel_indexes` goes through
one shared predicate that leaves stub rows out; indexes are computed from live
rows only and marked so; every endpoint that served a stub-derived figure or a
figure written into the code says "not recorded" with the reason, and the
screens that read them say so too.** Issue #1078, slot S05, part of the
Research rebuild (#1077). This entry covers the first PR (step 1 of the
issue); storing no stub in production, turning on the keyless live sources and
the "live since" date follow on the same issue and are added here when they
land. Migration 379.

**What was true on main (`27af83d6d`).** Production, counted on 4 October 2026
(issue #1078): all 237,372 rows of `market_intel_rows` were synthetic stubs and
the 504 rows of `market_intel_indexes` were computed from them.
- `runOneSource` (`services/market_intel/aggregator.ts`) writes a source's
  `fetchStub` rows whenever its `MI_FLAG_<KEY>` is not `live`, and when a live
  source runs out of quota or fails. No flag is `live`.
- Every stub cites `https://axal.vc/market-intel/sources/<key>`; a live row
  cites the provider resource it counted.
- `composeSectorScores` gave a dimension with no rows a neutral 50, and the
  routes defaulted every missing index to 50 (`?? 50`), so a sector nothing
  recorded read as a middling one.
- `routes/market_intel.ts` carried five constants of figures nobody recorded:
  sector multiples, sentiment and hiring claims (`MARKET_PULSE`), sector P/E,
  growth and IPO windows with a 2026-03-27 stamp (`MACRO_DATA`), six named
  private rounds with amounts and valuations (`PRIVATE_ROUNDS`), six
  "high-conviction plays" (`HIGH_CONVICTION`) and fifteen studio benchmarks
  (`STUDIO_BENCHMARKS`). Seven endpoints served them, and
  `routes/private-data.ts` re-served two of them.

**What changed.**
- **The predicate** (`services/market_intel/liveRows.ts`). A row is live when
  it carries a citation and the citation is not the stub page; an uncited row
  is not live, since nothing could show where its number came from.
  `isLiveRow` in JS, `liveRowSql()` in SQL (`instr(...) <> 1`, not `NOT LIKE`,
  because `_` in a pattern is a wildcard). An index row has no citation, so
  migration 379 adds a nullable `basis` column with no backfill: the
  aggregator writes `'live'`, the rows written before it have none, and
  `liveIndexSql()` reads only `basis = 'live'`.
- **Indexes from live rows only.** `recomputeIndexes` reads with
  `liveRowSql()`. A dimension no live row feeds has no value (`null`), is not
  written, and for the current period its row is deleted, so a stale figure
  cannot linger; the headline averages only the dimensions that have a value,
  and is not written when none does.
- **Every read filtered.** The routes' index reads and both citations reads,
  the digest's composite and citation reads, and the X-draft chart probe
  (`services/xAggregator.ts`).
- **Caches versioned.** The warm KV snapshot moved from `compass:global` to
  `compass:global:live`, and the edge-cache key gained `__v=live`, so a
  response cached from stub-derived indexes before this change is never served
  again (the edge TTL is six hours, the KV one a day).
- **Endpoints**, each keeping its shape and its live parts:

  | Endpoint | Was | Now |
  | --- | --- | --- |
  | `/sector-compass` | composite and six dimensions per sector, 50 when missing | live values; `null` with `composite_reason` / `reason` "No live source yet for this sector"; `recorded_sectors`; `computed_at` null when nothing is computed |
  | `/founder-lens` | demand, supply and gap per sector from 50s, sorted by gap | `null` with `reason` where demand or supply is missing; recorded sectors first |
  | `/investor-lens` | capital, sentiment, score from 50s | `null` with `reason`; recorded first |
  | `/geography`, `/geography-lens` | composites of stub-derived indexes | live composites only; `not_recorded` when none |
  | `/citations` | the newest rows, stubs included | live rows only |
  | `/market-pulse` | `MARKET_PULSE`, `total_sectors: 9` | `signals: []`, `signals_not_recorded`, `total_sectors: null`; live headlines kept |
  | `/macro` | `MACRO_DATA` sector table and prose | `sectors: []`, `sectors_not_recorded`, the two prose fields `null`; live quotes kept |
  | `/private-rounds` | six named rounds | `rounds: []`, `total: null`, `not_recorded` |
  | `/studio-benchmarks` | fifteen figures | `{ not_recorded }` only |
  | `/competitive-intelligence` | the three constants | empty lists, `null`, a reason for each |
  | `/export` | a CSV of `MARKET_PULSE` | 409 `not_recorded` (the tier gate still runs first) |
  | `/api/private-data/market/private-signals` | `MARKET_PULSE`, `STUDIO_BENCHMARKS`, a "global conviction" read off them | empty, `null`, reasons (no screen calls it) |

- **Screens.**
  - `FounderResearchDesk.jsx`: "Market deep-dives" counted the pulse sectors
    and rounds as "stored market records"; it now counts only what is
    recorded and otherwise reads "Not recorded" with both reasons.
  - `InvestorResearchWorkspace.jsx`: the ledger's "Market compass" counted
    all twelve sectors and "Private rounds" the rows; they now count live
    sectors and say "Not recorded" with the reason, and the benchmark line
    no longer says a record is available when the answer is not recorded.
  - `MarketIntelPage.jsx`, which reads the same endpoints: the pulse, public
    markets, private rounds, high-conviction and studio-benchmark tabs draw
    a "Not recorded" panel with the reason instead of the invented rows; the
    compass, founder-lens, investor-lens and geography tabs render every
    score through `<Score>`, which prints "Not recorded" for `null`, and
    rank or pick only recorded sectors.
  - `SpinoutLabMarketPage.jsx`: no "current leader" is crowned from
    unrecorded sectors, segment picks are only those with a live gap, and an
    unrecorded composite or dimension reads "Not recorded" with the reason.
  The issue named the first two pages; the other two read the same endpoints
  and would have drawn "NaN" or a bare `null`, so they changed with them. No
  open issue or PR owns either. The founder desk's `?? 0` on fund research is
  #1082's, and stays for it.

**Not done here, and why.** The 237,372 stub rows and the 504 stub-derived
index rows stay where they are, hidden by the predicate; deleting them is the
owner's decision. If chosen, it is one migration: `DELETE FROM
market_intel_rows WHERE NOT <liveRowSql()>` in id-range chunks (D1 caps a
statement's run time, and 237,372 rows is too many for one), then `DELETE FROM
market_intel_indexes WHERE basis IS NULL`. Storing no new stub in production
and turning on the keyless sources are steps 2 and 3 of #1078, in the next PR.
