## D9190 — Uploaded file types are checked on every path (#9190)

**Date:** 2026-11-27. **Slot:** S10. **Source:** the coordinator audit of 2026-11-27 (SI-6, SI-7).

### Data room

A data room file's stored type is now decided in one place,
`storedFileType` in `cloudflare-worker/src/routes/data_room.ts`. The type is
lower-cased, its parameters are dropped, and it is kept only if
`DATA_ROOM_FILE_TYPES` lists it. That list covers documents, spreadsheets,
decks, plain text, CSV, Markdown, JSON, ZIP, raster images, audio and video.
Any other type is stored as `application/octet-stream`, in both the
`data_room_files` row and the object's `httpMetadata`. This includes markup,
script and SVG, which a browser could run.

- `storeDataRoomFile` applies the check, so the first upload and the Notion
  snapshot (`text/markdown`) both go through it.
- `replaceDataRoomFile` applies the same check. Its old pattern,
  `/^[\w.+-]+\/[\w.+-]+$/`, let any well-formed type through.
- The upload route reads the declared type up to the data URI's comma and
  takes the part before any `;`. Before this change, a URI with no `;` sliced
  at index -1 and stored a malformed type.

An unlisted type is stored, not refused. A founder can always add a file to
the room, and that file is downloaded rather than rendered.

### Article images

`POST /api/articles/:id/image` checks the base64 length before it decodes
anything. It answers 413 `too_large` when the length is above
`4 * ceil(MAX_IMAGE_BYTES / 3)`, the longest text that can decode to 5 MB.
The audit suggested `ceil(MAX_IMAGE_BYTES * 4 / 3)`, but that bound is one
character short and would refuse an image of exactly 5 MB.

After decoding, the bytes must open with the signature of the declared type:

- PNG, JPEG and WebP are read by `sniffMime`.
- GIF is `GIF87a` or `GIF89a`.

A mismatch answers 400 `mime_mismatch` with a sentence, and nothing is
stored. A payload that does not decode answers 400 `invalid_data_uri`
instead of throwing. The author page now shows a refusal's `message` before
its code.

The cover route is not changed. It already sniffs a cover copied from an
image, and it limits uploaded covers to their declared list.
