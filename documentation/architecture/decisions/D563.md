## D563 — The Workspaces launcher is retired; its 28 pages light the profile sidebar rows that own them

**Issue:** #1164. **Decided by:** S1, option A, at the owner's request
(2026-10-06).

### What was decided

The Workspaces launcher (D284, "S23 · H37"), a top-bar button that only
the HQ and Admin shells drew, is removed. It was the only way into most
of its 28 pages: 24 of them were in no profile's sidebar.

The profile sidebars keep the rows their approved canvases draw. No row
is added, and no row or zone count moves. Instead:

- **Each kept page joins the `match` of the row that owns it**, so it
  lights that row.
- **The row's overview links the page** in an "Also in <row>" list
  (`workspaces/AlsoIn.jsx`).
- **On an admin shell, the command palette still indexes all 28.**
  Admins reach the profile pages through View As and the palette; their
  own sidebar stays the admin consoles.
- **Every page keeps its route.**

The mapping is data: `PAGE_HOMES` in `lib/adminPlacement.js`, one line
per page. Each line names `[role, row, door]`:

- `row`: the page is the row's own destination (`/pipeline`, `/deals`,
  `/network`), or its overview alias (`/portfolio/health`).
- `also`: the row's `match` lists the page, and its overview draws the
  "Also in" link.
- `lab`: `/spinout-lab/83b`. The founder's Spin-Out Lab row matches it,
  and the Lab's own arsenal (`lib/spinoutLabArsenal.js`) links it.

The full table, with each route's guard, is in `ROUTE_MAP.md`, in the
section "The Workspaces launcher's 28 pages".

### Where the code disagreed with the starting table

- **`/scoring`** does not admit founders. Its guard is
  `labRoles(['admin', 'partner', 'investor'])`. It lives on investor
  Deals (diligence), not on founder Validate.
- **`/advisory` keeps its route.** It is an 800-line page (advisor
  directory, financial planner, diligence checker) that founder Validate
  already tabs and links, so redirecting it would have removed working
  features, which is outside this issue's navigation-only scope. The
  voice-rule problem was the launcher's label, "AI Advisory Suite". The
  palette now labels the page with its own heading, "Advisory".
- **`/spinout-lab/83b` is already in the Lab's tree.** The arsenal links
  it and `/incorporate/83b` redirects to it, so there is nothing to
  redirect it to. It now lights the founder's Spin-Out Lab row.
- **`/compliance` is not a second filings calendar.** It is the founder's
  company compliance calendar. D417 (#1002, PR #1127) stores fund-entity
  obligations, and the only UI it has is HQ · Funds' deadline flag. The
  page stays, under founder Raise ("stay legal").
- **`/network-effects` stays on founder Grow**, which already matched and
  tabbed it. Admin Insights (#1155) is S08's page.

### The one redirect

A founder on `/liquidity` is sent to `/raise/liquidity?mode=workspace`.
That address renders the same `LiquidityPage` inside the Raise shell,
and it is the Raise · Liquidity zone that `shellConfig.js` records as
`/liquidity`'s successor.

Partners and investors still land on `/liquidity`. For investors it
lights Portfolio.

To match, founder Raise drops `/liquidity` from its `match`, because no
founder renders that path any more (D505). The Raise tab bar lights
Liquidity on both addresses. `FounderWorkspaceTabs` now passes a tab's
`match` through to `WorkspaceTabs`; before this change it dropped it.

### Also changed

- **`adminPlacement.js`:**
  - the tier and form `launcher` are now `palette`;
  - `WORKSPACE_GROUPS`, which only the launcher read, is removed;
  - `WORKSPACES` stays for the palette.
- **The overviews that draw the list:**
  - `BucketBoard` and `BucketOverview`, for every bucket root;
  - `FounderValidatePage`, `FounderRaiseDesk` and `FounderGrowDesk`;
  - `InvestorPortfolioCanvas`.

### Not touched

- The rail frame on these pages belongs to #1156 (S09).
- The admin pages' content belongs to #1155 (S08).
- Pages that redirect a founder (`/my/jobs`, `/services`, `/needs`) keep
  their redirects.
- No migration.

### Verified

`frontend/test/workspaces_retired_d563.test.mjs` checks:

- the 28 pages, each with a home;
- each home is a role the route's guard admits;
- each kept page lights its row, by that row's `match`;
- no page lights two rows of one profile;
- each "also" page is linked from its row's overview;
- the Lab page is in the arsenal;
- the founder redirect;
- that no launcher remains.

Each of 24 mutations makes it fail. The D284 tests are updated to the
palette-only state.
