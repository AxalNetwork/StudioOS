## D6387 part 2 — A PR failure's repair issue goes to the slot of the task the PR links (#6387)

- **Status:** built. Part of #6387.
- **Counterexample:** PR #6954 closed #5867 (`slot:S23`). CI run 43913011831 failed on its head, and the reporter filed #7020 with `slot:S01`. At that point every new repair issue got S01, and the coordinator routed each one by hand.

**Rule.** The reporter first classifies the failure. Inherited main incidents, adopted incidents and recurrences of an open episode keep their issue and its routing. Only a new issue is routed:

1. The failure must be on a pull request's own run, and the PR must still be open with the failed commit as its current head. A run on main, a merge-queue candidate, another branch or a superseded head stays with S01.
2. The PR body only nominates task numbers, through `Closes`, `Fixes`, `Resolves` or `Part of` followed by `#N`. `Refs`, `Builds on`, cross-repository references and bare numbers are context, not owners. More than ten links count as shared.
3. Each linked number is read from the repository's own issues. It must be an issue, not a PR, and carry exactly one label matching `^slot:S\d{2,}$` (case-insensitive). The new issue takes that label as the repository spells it.
4. If every linked task names the same slot, that slot owns the repair. Otherwise it stays with S01: no linked task, a task without exactly one slot label, tasks on different slots, or an unreadable PR or task. Routing is advisory, so a read error never holds back the issue.

The issue body's **Owner** line records the rule that applied, from fixed text and verified numbers only. No PR text reaches labels or the body. The reporter does not read claim refs (`claim/<issue>`), because their slot field is free text written by the claiming session, while the issue's slot label is the coordinator's assignment. The `workflow-failures` job gains `pull-requests: read` to read the PR's current head and body.
