## D5040 — Super Admin transfer: the successor is active at the write, ids are strict, and the former holder leaves HQ at once (#5040)

- **Status:** Built for #5040, 2026-11-08. Package 1 of the HQ Team audit (P0).
- **Builds on:** D133 (one holder, enforced), D221 (a deactivated account cannot receive the elevation; the reason), D240 (the write enforces the ceiling), D241 (both parties are told), D940 (`hqOnly` and the closed-page notice).
- **No migration. No new route.** TOTP, the step-up and the Super Admin write bar are unchanged.

### What was decided

1. **The conditional successor INSERT re-asks `is_active = 1` (`routes/admin_super_admins.ts`).** The preflight refused a deactivated successor, but it is a read; an account deactivated between that read and the batch could still receive the sole elevation, leaving a holder who cannot sign in and no route back but SQL. The grant now conditions on `LOWER(role) = 'admin' AND is_active = 1 AND the caller still holds`. The caller's row goes only when the successor holds (D240), so the two writes move together or not at all.
2. **A lost write-time eligibility race answers `successor_changed`** (409, "stopped being an active administrator", "You still hold the elevation") with the caller confirmed still holding, writes no audit row and sends no notices. The role-changed case takes the same path.
3. **`parseUserId` is strict.** Only a decimal positive whole number with no leading zero, inside the safe-integer range, is an id: `123abc`, `1e2`, `1.5`, `-1`, `0`, `01`, `+5`, `0x10` and `2^53 + 1` answer 400 `Invalid user id` on both the grant/transfer and the revoke route. `parseInt` read the leading digits and ignored the rest, so a malformed path named a real account.
4. **A confirmed transfer takes HQ's screens away from the browser without a reload (`SuperAdminHolders.jsx`, `AccountsPage.jsx`, `handoverNote.js`).** The holder console tells the page (`onTransferred`); the page calls `leaveHq`, which clears `is_super_admin` on the signed-in user in context, re-reads /me to reconcile, and leaves one line. `hqOnly` reads that flag, so in the same render Team, the directory and the console unmount and `SuperAdminOnlyNotice` draws. The notice shows "You handed the Super Admin elevation to …" once, in a status region, then clears it (`sessionStorage`, wrapped; the page works without it). A failed /me re-read is reported and changes nothing, because the answer it would give is already known.
5. **A failed or refused transfer keeps the operator's reason and the chosen successor.** `run()` now resolves `true` only for a server-confirmed change; the form clears its fields only on `true`. Before, the `.then` ran after a failure too.

### Not done
- The holders' read of `is_active` for the picker is unchanged (the picker already omits deactivated admins).
- Other privileged pages (outside Team) that are mounted in another tab keep their state until that tab next reads /me; `useAuthSync` already syncs the user across tabs on the `storage` event.
