### Why the contract changed

A market's entry step needs three actions on its row: Mark done (or Reopen),
Edit and Remove. D690's `Row` carried one `action`, and a row form opened on
the values its declaration held for the whole record, so an Edit of the second
step would have opened blank. A record-level action cannot name the step, and
folding all three into one form would have put Remove behind no confirmation.

### What the contract now says

1. **`Row.actions`** — the row's further actions, drawn after `action`. Each is
   a reference like `action`: a declared key and the body sent back with it.
   The route strips `actions` from a non-writer's rows, as it strips `action`;
   the client draws only the ones that resolve to a declared action.
   - Desktop: further actions are buttons after the row's own action.
   - Phone: each one is a row beneath its row, with the row's text as the
     description; a danger action is red.
2. **`values` on a row reference** — a form action's starting values for that
   row only, overlaid on the declared fields' values for the keys the form
   declares. They are never sent back; `body` still is.
3. **`RecordAction.rowOnly`** — the action runs only from a row that names it,
   with that row's body. It is still declared (so the route can find and run
   it, and the client can resolve the row's key), but the record's header and
   the phone's Actions group do not draw it. Without it a market would show two
   "Edit" buttons, one of them for no step.
4. **`Next.action` keeps a row's body.** "Next for this record" picks the first
   Open row; its CTA now runs that row's action on that row, not the bare key.

### The entry plan

- The section reads each step's `uid`. An Open step's action is Mark done, a
  Done one's Reopen; Edit carries that step's text, owner and due day; Remove
  is `tone: 'danger'` behind a confirmation.
- **Every action proves the step twice.** `references` checks it in its own
  store within the venture (`ownedRow`'s `market_entry_steps`), then the writer
  loads it joined to this market's uid and venture, so a step of another
  venture's market, or of this venture's other market, is a 404 that writes and
  logs nothing.
- Mark done keeps the day a step was first done; Reopen clears it. Edit changes
  only the keys it sends (`text`, `owner_name`, `due_on`); a blank step is
  refused.
- Each change logs one `grow.market-expansion` row on the market:
  `grow_entry_step_done`, `_reopened`, `_updated` or `_removed`. The summary
  never holds the step's text.

### Not changed

Localisation checks and Open minutes still declare row-addressed actions
without `rowOnly`, so they still appear among their record's own actions. Marking
them `rowOnly` is a one-line follow-up each, left out of this issue's scope.
