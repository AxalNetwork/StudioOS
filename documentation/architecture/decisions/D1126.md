### 1. HQ's History tab

- **The page.** `/admin/licences/programs/history` (`pages/admin/grants/ProgramGrantsHistory.jsx`, guarded `guard(['admin'], hqOnly(…))` like the grid) lists every program decision HQ recorded, for every studio, newest first. Each row shows:
  - the day, who made the decision ("by HQ" when no name is recorded) and the studio;
  - what happened and to which program;
  - each changed term, before → after, with "Not recorded" for a value nobody set;
  - a partner deal types change, before → after;
  - HQ's reason.
- **Filters and paging.** A program filter narrows the list, and "Show older" reads the next page.
- **Failure and empty states.** A failed read says "The history could not be read. That is not the same as none." with Try again. "No program decision is recorded yet" is said only when the read answered with none.
- **The read.** `GET /api/admin/program-grants/history[?program=&licence=&before=&limit=]` (`requireSuperAdmin`, `services/programGrantsHistory.ts`).
  - It returns every `licence_events` row of event `program_changed`, the record that D982's grant writes, D983's answers and D986's deal types already append. It writes nothing and stores nothing new.
  - Pages are 100 rows (at most 200) by id, with `next_before`. An unknown program is a 400.
  - A row whose licence is no longer in the ledger keeps its record with `licence: null`, and the page says "A licence the ledger no longer holds". It is never given another studio's name.
- **The tabs.** HQ's tabs (Grid, History) are literal `HeaderTab`s in D936's header (`GrantsTabs`), so the reachability walk finds both doors. Requests and Default terms join `GrantsTabs` with part 6 (#2778). The route has a rail alias of HQ's Licences row (`railPages.js`).

### 2. Download CSV

- **`GET /api/admin/program-grants/export.csv`** returns one row per studio and program (`requireSuperAdmin`).
  - It covers every licence that is not a draft or terminated, in the grid's order, by the nine programs in catalogue order.
  - The columns are the licence reference, studio, licence status, program, grant, in force, waiting on, effective end, schedule signed, then **every term in its own column**, then the note and when it was set.
  - **A program with no grant row says "Not recorded", never "Not granted"** (D981 §3). HQ only and Not ready to grant say so.
  - A term nobody set, or one that does not apply, is a blank cell, which is how a CSV says "not recorded" (`services/csv.ts`).
- **`GET /api/admin/program-grants/licences/:uid/export.csv`** returns one studio's rows, named by its reference. An unknown licence is a 404.
- **Audit.** Both exports are in the admin audit log (`program_grants.exported`, a row count only) and carry `X-Export-Rows`.
- **The buttons.** Download CSV is in the More menu of HQ's header, on the grid and on History (`programGrantsApi.exportCsv`). A failed download says so on the page with the Worker's sentence; it is never silent. The one-studio button waits for GR3's page (§4). Its client, `exportLicenceCsv`, is ready.
