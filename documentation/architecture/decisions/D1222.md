### 1. Readiness while calls are off (CLS1)

**The route:** `GET /api/round-calls/readiness?project_id`.
- It is mounted before the flag's gate, so it answers whether calls are on or off. `/availability` is the only other route there.
- It reads the venture with `projectRecord` (the project's own facts, with no flag) and returns:
  - `{ project_id, enabled, items, ready, counted }`;
  - `items` are CLS1's seven, in the canvas's order, each `{ key, label, ready, reason }`.

**Where each item comes from (`roundCallPolicy.ts` `ventureReadiness`):**

| Item | Read | Ready when |
|---|---|---|
| Round target | the active `raise_rounds` row | `target_amount` is above 0 |
| Round terms | none | `null`, with "Round terms are written in the call itself." |
| Pitch deck version | `pitch_decks` | the venture has one |
| Data room | `data_room_files` and `data_room_folders` | at least one |
| Use of funds | `projects.use_of_funds` | not blank |
| Traction | `projects` | a summary, revenue, MRR or users recorded (the call's own rule) |
| Target close | the active round's `close_date` | a real date, today or later |

- With no active round, both the target and the close say "No active round is recorded in Raise."
- `ready` counts the items that are ready; `counted` counts the items a record can answer (six).
- **No investor data:** no prospect, recipient or investor is read.

**Who reads it:** the venture's owner and its accepted co-founders (§4). Anyone else is refused:
- another founder, or a project that is not theirs or does not exist: 404;
- an investor or an admin: 403;
- signed out: 401.

**Choice to check:** the issue says "owner-scoped". The read also admits co-founders, because they draft the call it prepares, and every item is already theirs to see in Raise's tools.

### 2. Prospects not on Axal (owner question 7)

**What a prospect counts as.** A pipeline prospect (`raise_prospects`) is on Axal when its email belongs to an active investor whose KYC is approved (`pipelineInvestors`). Any other prospect is "not on Axal".

**The audience preview** (`POST /:uid/audience-preview`) adds `not_on_axal`:
- every prospect of the venture that is not on Axal, as `{ prospect_id, name, chosen }`;
- `chosen` is true when it is among the ids sent;
- no email is returned.

**The save** (`PUT /:uid/audience`):
- A chosen prospect not on Axal is left out of the recipients, and the summary's `not_on_axal` counts those left out. Before this, one such prospect failed the whole save with `chosen_investor_unverified`.
- A prospect id that is not this venture's is still refused, now as 422 `prospect_not_found`.

### 3. Not delivered

`round_call_recipients.delivery_state` is written at send (`notified` or `not_delivered`). It is now read back in two places:
- **`parts.calls`** (`raiseCycle.ts` `callsHistory`): each item has `not_delivered`;
- **the founder's call** (`GET /:uid`): `progress.not_delivered`.

A draft has sent nothing, so both say `null`, never 0.

### 4. Co-founders draft and answer (owner question 4)

**Who is a member.** An active account with an accepted `project_members` row on the venture, with role `cofounder` or `owner` (`ventureMember`).
- An advisor's row admits nothing.
- A row that is pending or removed admits nothing.
- An investor or an admin is never a member, whatever a row says.
- A missing table means no membership, never an error.

**What a member may do:**
- read the context, the list and a call;
- create a draft and edit a draft;
- answer an investor's question.

**What stays the owner's:** the audience preview and save, the counsel request, send, extend and close.

**Checked twice.** The route's `owner()` admits members only where it says so. Each service's `founderActor` checks again, live, and admits members only for the draft, the context, the call's page and the answer. So a route that admitted a member by mistake still meets the owner check in `sendCall`, `manageCall` and `saveAudience`.

**The call page says what this viewer may do:**
- `relation` is `owner` or `member`;
- `can` is `{ draft, answer, audience, send, extend, close }`.

CLS14's "no permission" draws from `can`.

**Behaviour kept:** someone who is neither a founder nor a member is still refused with 403 `founder_required`; a founder of another venture with 404.
