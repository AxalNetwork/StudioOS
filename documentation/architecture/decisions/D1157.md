## D1157 — Admin › Fund admin: one place to run the Axal VC funds, each tab at its own address, today's reads where they exist, and "Not read here yet" where they do not (#2388)

- **Status:** decided and built by S21, 2026-10-25 (#2388, under #2711).
- **Canvas:** the owner's "Fund Administration · Admin", boards FND1–FND22. The two artifacts are `59ZPJbfN7dvmbpovwhZcWi` (the board grid) and `WUodW2gUkvzpRSZbmUv15V` (the page). Both were decoded with `scripts/read-canvas.mjs` and committed as `design/incoming/Fund admin · Boards.dc.html` and `Fund Admin Console Page.dc.html`. This is the canvas #1779 (D714) and #1008 item 36 waited for.
- **Basis:** `origin/main` at `a265fb2561`. The map is `documentation/audits/FUND_ADMIN_MAP_2026-10-25.md`.
- **Migration:** none here, and none in the parts: every new read is computed from tables on `main`.
- **Why:** the owner opened `/funds` ("Fund Ops") and could not manage the Axal VC funds there (#2388). This decision makes `/admin/fund-admin` the one place, with the canvas's tabs as addresses and the blocks today's reads carry. The rest is eight slot tasks (§6).

### 1. Where it lives

- `/admin/fund-admin` is Overview. Every other tab is a sub-path: `/funds`, `/lps`, `/calls`, `/distributions`, `/performance`, `/fees`, `/reports`, `/banking`. Banking has three parts: `/banking`, `/banking/reconciliation` and `/banking/books`. The two new routes `/admin/fund-admin/:tab` and `/admin/fund-admin/:tab/:sub` sit beside the old one in `App.jsx`, with the same `guard(['admin'])` (D714 decision 7: not `hqOnly`).
- The tabs come from `pages/admin/fundAdmin/fundAdminModel.js`:
  - `TABS` holds the canvas's nine, in its order: Overview, Funds, LPs, Capital calls, Distributions, NAV & performance, Fees, Reports, Banking;
  - `BANKING_PARTS` holds Banking's three;
  - `viewFrom(pathname)` names the view. A word under a tab (`/reports/notices`) is that tab, and an unknown word is Overview, never a blank page.
- **D714's `?tab=` links forward.** `legacyHref` maps each old value to its sub-path, and the console renders `<Navigate replace>` before any read. It keeps only a well-formed `?fund=` (digits). Reconciliation is no longer a tab: `?tab=reconciliation` opens `/banking/reconciliation`, and its count flag sits on the Banking tab.
- **"Management fees" is "Fees"**, as the canvas names it.
- **The links that pointed at `?tab=` now point at the sub-paths:**
  - Mercury's "Open Banking" (`mercuryEntityModel.js` `OPEN_BANKING`) opens `/admin/fund-admin/banking`;
  - Bank accounts' `RECONCILIATION_HREF` opens `/admin/fund-admin/banking/reconciliation`.
- **What is not moved here:**
  - `/funds` and `/funds/performance` still render Fund Ops for an admin. Forwarding them, retiring `FundOpsWorkspace` and `AdminFundsView`, and changing HQ › Funds' foot link are part 3, because the moved notice (FND16) and the redirect list (#2319) go with them;
  - an investor's `/funds` is unchanged (#2297 §5).

### 4. Who sees what

Unchanged by this decision. Every read keeps its Worker gate (`requireFundAdminReader`; `requireFundGp` for performance), and every act stays on the profile `FUND_ACTS` gives it. The console still draws each Super Admin act through `FundActControl`, so an Admin sees its sentence. The integration adds a read to a page an admin already opens (`/funds/performance` reads the same list), so it shows nobody anything new.
