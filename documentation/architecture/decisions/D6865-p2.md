## D6865 part 2 — Grow › Feedback v2: the Customers › Feedback tab, Save as feedback from the Inbox and an interview, and Eadwyn's placement review (#6865)

**Date:** 2026-11-22 · **Issue:** #6891 (split out of #6865; part 1 is `D6865.md`) · **Canvas:** `design/incoming/Grow v2 Feedback Page.dc.html` (#6099, D6099; boards GR-21 to GR-31) · **Route-map row:** `route-map/canvases/part-3/0160-pages-founder-grow.md`

### Built

**Worker**
- **Migration `202611220349_6891_feedback_reply_link.sql`.** It adds `product_feedback.reply_key`: the Inbox message key of the reply an item was saved from (`contact:<contact_replies.id>` or `mail:<sha-256>`), NULL otherwise. A partial unique index on (`project_id`, `contact_uid`, `reply_key`) holds one item per reply.
- **`POST /api/cycles/grow/feedback`** takes `reply_key` with origin `inbox_reply` and a `contact_uid`:
  - a `contact:` key must be an inbound reply of that contact in this venture, else 404 on `reply_key`;
  - a `mail:` key is a digest of mail Axal never stores, so only its shape is checked;
  - any other key is 400; a key with another origin, or with no contact, is 400;
  - a reply saved before is a 409 that names the item (`uid`), and nothing is written.
  - The activity row says "Feedback saved from an Inbox reply" or "Feedback saved from an interview".
- **`GET /api/grow/inbox/:contactUid`** marks each message with the feedback item it was saved as (`feedback: { uid, status }`, else `null`), read inside the thread's own contact and venture. A failed read of the links is `feedback_state: 'unreadable'`; the thread still draws.
- **Product improvement's form-options** (writers only) add `contacts`: the venture's own records, newest first, at most 200, for the sheets' Customer record chooser.
- **Client:** `cyclesWrite.grow.feedbackFromReply(projectId, replyKey, body)`, on the mounted `POST /feedback`.

**Frontend**
- **GR-21, the tab frame.** Customers' row under the Grow header is Pipeline · Accounts · Feedback (`growOverviewModel.js`, owner question 3 = A).
  - Pipeline is `/grow/customers`. Feedback is `/grow/product-improvement`, with its item count from the read; a failed count draws none.
  - Accounts has no page on main, so it is drawn and not linked, with its reason.
  - `/grow/product-improvement` owns its page (`defs/grow.jsx` `homes`, D6049; `FeedbackTab.jsx`). The tab shows:
    - the counts;
    - Source, Status and Sort, and Export where the Worker allows it;
    - themes ranked by item count, with their status split and No theme yet;
    - the selected theme's items, each with who gave it, the linked-customer chip or Not linked, the origin, status and roadmap item, opening the record view at its unchanged address;
    - then the theme's weight and Close the loop (D6865).
  - Add feedback is the header's one primary action (`?add=feedback`).
- **GR-21B, Add feedback** (`FeedbackSheet.jsx`) on the existing POST. It has the Customer record chooser (Not linked still saves with the typed name), Theme or a new theme, Roadmap item, Status, Tell them when it ships, and the origin Typed. Saving, a failed save with the fields kept and Try again, and the saved state are drawn.
- **GR-21C, Eadwyn's placements.** Writers only, and only while Eadwyn is on for the page. The pending `feedback_theme` proposals whose theme is already named are listed. Each opens the GR-11 review (Feedback, Placed in, Using it writes, Discard, Use this theme), through the existing proposal routes. A placement into a theme not named is held back and counted, never offered.
- **GR-24, GR-29C, Save as feedback from an Inbox reply** (`InboxTab.jsx`). Each inbound reply offers Save as feedback (writers only). The sheet is filled with:
  - the words selected in it, else the whole reply;
  - the person's name, email and company;
  - their record, linked;
  - origin Inbox reply.

  After saving, the reply carries "✓ Saved as feedback" and Open item. On a phone the sheet is a bottom sheet.
- **GR-25, Save as feedback from an interview** (`InterviewSaveFeedback.jsx`, in the interview's writer-only tools).
  - Quote consent is shown as recorded (Yes, No or Not recorded).
  - Save as feedback takes the passage selected in the interview; each session mark saves its label, and a mark with none saves an empty box.
  - The origin is Interview.
  - The interviewee is linked only when exactly one record matches; otherwise the sheet reads Not linked, offers Link, and still saves.
- **GR-27.** Nothing recorded draws one primary action, Add feedback, and two quieter ways in (the Inbox, interviews); the header has no action then. Items with no theme draw Themes as a measured 0 and "No themes yet", and the first save says "Added to Feedback · Open".
- **GR-28.** Loading is a skeleton in the tab's shape. A failed read is Unavailable with Try again, and "Pipeline and Accounts still work. Nothing is shown as 0." An advisor (no `parts.themes`) reads the counts, themes counted from the rows and the feedback with names hidden, and no chip, weight or Close the loop.
- **GR-29A, GR-30.** Below 768px the themes are a scrolling chip row and the items cards. Targets are 44px. Dark tokens are used throughout.

### Departures from the canvas
- The module's heading stays "Feedback" (D4862's navigation test), not "Customers"; the eyebrow reads Grow · Customers. The header has no Import.
- The tab row is links with `aria-current`, not a `tablist`. Accounts is not linked: main has no Accounts page. The Feedback count shows on `/grow/product-improvement` only; `/grow/customers` does not read it.
- The theme column draws no per-theme weight line. Only the selected theme's weight is read: one read per theme. All themes are listed; there is no "Show 7 more". The Theme filter is the theme column, and the items list shows all of a theme's items.
- Add feedback carries the Customer record chooser and the origin, which the issue asks for and GR-21B does not draw, plus "Or name a new theme".
- "Tell them when it ships" starts unticked in every sheet (the canvas draws it ticked). It records that the person asked to be told, which a reply or an interview does not say.
- Eadwyn's placements are a card in the tab, not the rail's Pending proposals. The existing inline proposal band (Propose themes, Use this theme, Discard) stays under the tab, so a placement can be decided in either.
- The Inbox keeps its D4494 frame. The selected words come from the reader's own text selection (no highlight drawn). The saved note does not count the theme's items.
- The interview's Save as feedback sits in "This interview", not under the Notes card. An interview records no email, so none is filled.
- GR-27's "From your tools" is the existing From Notion and PostHog parts below the tab, each with its own states. The rail's empty and first-save copy is unchanged.
- On a phone, Add feedback stays in the header (the canvas puts it at the foot).
- Dark uses the app's Tailwind dark tokens, not GR-30's exact hex.
