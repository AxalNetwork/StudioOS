## D631 — A fund’s recorded facts and immutable reporting periods

Issue #1389 implements Ops area 6 F1 (`fd-page`) at `/funds/:fundId`
and F2 (`fd-report`) at `/funds/:fundId/reporting/:periodId`. `new` starts a
draft; `new?corrects=<issued-id>` copies an issued report into a distinct
correcting period, preserving its original reference. The shared workspace
shell and Worker rail frame both pages; F1 works at 390px.
The two child-route patterns use the shell’s own inset, without an additional
App inset or width cap; other fund routes retain their existing layout rule.

### Access and records

The Worker mounts `GET /api/funds/:id/page` and
`GET /api/funds/:id/report-periods/:periodId`. Admins and the GP use the
existing institutional-tier and active-company fund gate. An investor who is
an LP can read only their fund and its issued periods. The canonical LP
membership predicate accepts unclaimed legacy-email membership but never a
row bound to another account. The page response is a whitelist, not the
internal fund row. Report summaries filter drafts out of LP reads.

Size is recorded integer cents (legacy default zero means not recorded),
LP counts are live, commitments sum the fund’s LP records, and invested totals
sum the original invested amounts on positions attributed to the fund.
Legacy monetary columns use the existing USD convention; no FX conversion or
canvas placeholder amounts are inferred. No attributed positions means
invested is Not recorded, not zero. Empty provider, GP and LPA fields give
visible one-line reasons. Missing schema, corrupt content or failed reads are
Unreadable with Try again; they never become an empty list or zero.

### Writes and immutability

The editor calls the existing `POST /api/funds/:id/report-periods` route.
Labels, valid calendar dates and bounded structured narrative are validated.
Persisted labels are immutable in the editor; a revision prevents stale saves.
Issued rows reject writes. A draft update also requires the previously read
notes and draft status at execution, so a concurrent issue cannot be rewritten.
Issuing records the server’s fund snapshot, timestamp and authenticated actor;
client snapshots and receipt fields are ignored.

Each write and its actor receipt use one transactional D1 batch. A fresh
server-owned receipt UUID conditions the audit insert on the actual winning
write. Audit failure rolls back the report write. Correction lineage can point
only to an issued period in the same fund and cannot be changed or erased on
an existing correction. The UI requires explicit confirmation that issuing
cannot be undone. Issued reports expose read-only controls; only a GP/admin
can start a correcting period.

The existing `fund_report_periods` table already stores narrative, snapshots,
status, issue metadata and timestamps. Its notes JSON carries the write receipt
and correction reference, so migration 421 is unnecessary and is not created.

### Canvas differences and boundaries

Recorded USD amounts replace the canvas’s example euro amounts. Issuer IDs
are displayed as recorded, rather than guessing a GP name. The added reporting
period links make the editor and issued LP reads reachable from the fund page.
Existing fund selectors and the investor landing link to the single-fund page.
The existing archive renders structured narrative as a recorded-content label,
so creating a period does not hand a React child an object. Unset report
dates stay Not recorded until a GP records valid dates. A scope-keyed hook
hides old data immediately on route/company changes and ignores late responses.
The rail reports coverage but does not promise the canvas’s optional AI draft
or note writes, because this task does not mount those operations. Issuing does
not claim delivery of a pack or send notifications. The owner merges and checks
deployment; this task performs no production D1 writes or deployment.
