### 1. The header (FND1)

The console draws `AdminPageHeader`, top to bottom:

- **The title,** "Fund administration".
- **The profile pill:** "Super Admin" (violet) or "Admin". It comes from the act table (`super_admin`), and none is drawn until the table reads.
- **One primary button,** named by the act table, never by the role. Each opens where the act is taken today:
  - **Overview and Capital calls:** "New capital call" when the table allows `capital_call.issue`, else "Preview a capital call". Either opens the fund's call ledger (`/funds/calls?fund=`); on Overview, with no fund chosen, it opens the Capital calls tab.
  - **Distributions:** "New distribution" when `distribution.execute` is allowed, else "Preview a distribution". It opens the tab's own form (`#distribution-form`).
  - **Fees:** "Preview period", which opens `#fee-prepare`.
  - **No button yet on Funds, LPs, NAV & performance, Reports and Banking.** Their acts (New fund, Add LP, Record a mark, Prepare a pack, Sync now) have no page of their own yet; parts 4, 5, 7 and 8 draw them. A button that went nowhere would be a claim. An unread act table names no Super Admin act, so its button reads "Preview a capital call".
- **More** (the shared ⋯ menu):
  - "All deployments' funds (HQ › Funds)", for the Super Admin only;
  - "LP applications (Approvals)";
  - "Export the funds (CSV)". The CSV is made in the browser from the overview read already on the page; nothing is sent. Money stays in whole cents as stored, a value no store holds is "Not recorded", and a funds block that did not read is written with its state, never as zeros.
- **The muted line:** "Run the Axal VC funds: LPs, capital calls, distributions, NAV, fees, reports and cash. Admins prepare; the Super Admin issues."
- **The as-of chip,** from the overview's `as_of`, with "Every figure on this page is as of this date." Before the overview reads, no date is drawn.
- **The moved notice** (§3).
- **The nine tabs as literal links,** each keeping `?fund=`, with their counts in mono:
  - Funds shows the administered funds' count when the overview read. When it failed it shows a dash with the reason, and while it reads, the loading bar;
  - LPs shows a dash, "Not read here yet: no read lists the LPs across funds";
  - Capital calls, Reports and Banking show the amber flag with how many wait (overdue lines, prepared drafts, matches to review). D1157 put Reconciliation's flag on Banking. With nothing waiting there is no flag, never a 0.

  `AdminPageHeader` gains the count kind `flag`: an amber dot with the number, and "waiting" for screen readers. The flags keep D714's testids (`fund-admin-flag-*`).

### 2. The fund filter (FND2)

- **The pill row** sits under the header: "All funds", then each administered fund. On a phone it is a select.
- **It is kept across tabs** as `?fund=`: every tab link carries it.
- **A tab that acts on one fund** (Capital calls, Distributions, Fees, Reports) offers no "All funds", and shows the fund the address names, else the first, as the tab reads it.
- **On a tab that shows every fund,** a chosen fund stays in the address for the next tab, and one line says: "This tab shows every fund. The filter is kept for Capital calls, Distributions, Fees and Reports."
- Each tab's own fund select (`fund-select`) is removed; the header carries the choice.

### 3. /funds forwards an admin (FND16)

- **An admin's `/funds` and `/funds/performance`** (not in investor view) forward to `/admin/fund-admin` and `/admin/fund-admin/performance`, keeping the query and hash. They add `?moved=fund-ops`, which shows "Fund Ops is now Fund administration, under Fund admin." Dismiss drops it from the address (#2375's `useMovedNotice`).
- **An investor's two addresses are unchanged** (#2297 §5). `/funds` is `InvestorFundLanding`. `/funds/performance` is `FundPerformancePage` in the fund shell, which is what Fund Ops' Performance tab drew; the locked "Funds admin" teaser tab is gone with Fund Ops.
- **They join #2319's count.** #2301's list holds only routes that forward everyone (the test reads App.jsx). These two forward an admin and stay an investor's pages, so they are in a new `ROLE_REDIRECTS` (`role: 'admin'`), spread into `REDIRECT_ROUTES` so the Worker counts their key. The address-bar beacon skips a `role` entry, so an investor's visit is never counted. `FundOpsRedirect` sends `redirect:/funds` or `redirect:/funds/performance` itself, once per forward.

### 5. Fund Ops retired; the refusals (FND20)

- **Retired:** `FundOpsWorkspace.jsx` is deleted. From `FundsPage.jsx`, `AdminFundsView` and its create, call and distribution dialogs are deleted. Every act they took is on the console (D714) or the call ledger. `FundsPage.jsx` keeps `LPADrawer`, which the LP workspace's My-commitment card opens (D372).
- **FND20a, a branch admin:** "Fund administration runs on HQ." and "Axal VC's funds and entity accounts are not administered from a branch.", with "Go to Studio". There is no header and no read.
- **FND20b, a support session:** "A support session cannot read fund administration." The canvas's "End support session" button is not drawn. The guard has no handle on the session, and the impersonation bar above already carries End session, so the line points there.
- **FND20c, anyone who is not an admin:** "This page is for studio admins." and "Fund administration is run by HQ's admins.", with "Go to your home".
- **Where FND20b and FND20c are drawn.** A non-admin never reaches the console: `RoleGuard` refuses them first. So both come from a route boundary for `/admin/fund-admin`, through D914's `ROUTE_BOUNDARIES`. The panel now receives `impersonating`.
- **An admin previewing another role** (View as) is still sent home, as before. The boundary carries `notPreview`, and RoleGuard skips it for a previewing admin.
