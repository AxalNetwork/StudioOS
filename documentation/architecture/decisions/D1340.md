### 1. Mail goes from the member's own mailbox

A send is always the member's own mailbox, through its own provider. Axal's house token (`GMAIL_CLIENT_*`, `services/email.ts`) stays for system mail and is never used here. A support session is refused on every route (403 `support_session_refused`): mail goes out in the member's own name.

### 2. Credentials: sealed, never shown, never logged

`mail_accounts.credentials` holds the provider's secrets. For OAuth that is the refresh token; for IMAP/SMTP it is the username, the app password, and the hosts, ports and TLS modes.

**The sealing** is `encryptColumn`, the helper EIN storage uses (`services/columnCipher.ts`, AES-256-GCM, keyed by `KEK_PII`):
- its AAD is `mail_accounts:credentials:<uid>`, so a blob copied to another row does not open;
- `openCreds` opens it only inside a use.

**What a client sees.** `accountView` is the only shape a client gets: uid, provider, address, display name, status, scopes, `can_read`, created, last used and last error. It has no credentials field.

**What a failure says.** An adapter fails with an `AdapterError`: a code and a sentence written in our code. The provider's text can echo a token or an address, so it is never passed on, stored or logged. The OAuth callback logs only the error's code.

### 3. Adapters

Every provider is one `MailAdapter` (`services/mail/adapters/`), with four calls:
- `send`;
- `verify`, which sends nothing;
- `revoke`;
- `listThread`, only where the account `can_read`.

**Outlook (Microsoft Graph).** Its own consent:
- **Scopes:** `Mail.Send offline_access User.Read`. `Mail.Read` is added only when the member asks to read replies (`{ read: true }` on start), and then `can_read` is set.
- **The app:** `MAIL_MICROSOFT_CLIENT_ID` and `_SECRET`, falling back to `MICROSOFT_CLIENT_*`.
- **The address:** Graph's `/me`.
- **Rotation:** every use refreshes the token, and the rotated refresh token is sealed in place of the old one.
- **The send** is a draft (`POST /me/messages`) and then its send, because `sendMail` alone returns no message id. The id kept is the `internetMessageId`.
- **`listThread`** reads a conversation's messages, for an account that `can_read`.
- **Revoke:** Microsoft has no call that revokes one app's refresh token, so a disconnect forgets it here. The member can remove the app's consent in their Microsoft account.

**Gmail, behind `MAIL_GMAIL_ENABLED` (#3547 Q1).** The adapter is built and tested, so Q1's answer only flips the switch. Until then, start answers 409 `gmail_not_offered` and the callback refuses a Gmail state.
- **The client** is separate: `MAIL_GMAIL_CLIENT_ID` and `_SECRET`. It is never the sign-in token and never the house token.
- **Scopes:** `gmail.send` with `openid email`. `gmail.send` alone cannot read the profile, so the address comes from the `id_token` that Google's token endpoint returned over TLS (OIDC code flow).
- **The send** is `users.messages.send` with the raw message (`mime.ts`).
- **Verify:** `gmail.send` reads nothing, so a refresh that succeeds is the proof.
- **Revoke:** revoked at Google.

**IMAP/SMTP, with an app password, over `cloudflare:sockets`.**
- **TLS always.** Each side is `tls` (implicit, 465 or 993) or `starttls` (587 or 143, upgraded before anything is said). There is no plaintext mode.
- **Port 25 is refused** before any socket opens: it is server-to-server relay. The sentence: "Port 25 is refused: it relays between servers. Use 465 or 587 for sending."
- **Hosts** must be host names. An IP literal, `localhost`, `.local` or `.internal` is refused.
- **Verify** sends nothing. SMTP runs EHLO and `AUTH PLAIN`, then QUIT; IMAP runs a `LOGIN`, then LOGOUT. A refused login is `mailbox_auth_failed`, and nothing is stored.
- **Send** is MAIL FROM, RCPT TO and DATA, then QUIT. The body is base64, so no line can be a lone "." and end DATA early.
- **Revoke:** there is none. An app password is revoked in the provider's own settings.
- **Server text** is never passed on or logged, because it can echo the username.

**The message (`mime.ts`)** is plain text in UTF-8:
- header values never carry a line break; the route refuses a subject, a recipient or a name with one, so no header can be injected;
- non-ASCII header text is an RFC 2047 encoded word;
- the body is base64.

### 4. Connecting, verifying, disconnecting

**`POST /api/mail/accounts/start/:provider`** (`outlook` or `gmail`) answers `{ authorize_url }`.
- Its `state` is a one-use nonce in `mail_nonces` (`kind = 'oauth'`, 10 minutes). Only its SHA-256 is stored.
- An unconfigured app is 503 `mailbox_unconfigured`.

**`GET /api/mail/accounts/oauth/callback`** is the provider's redirect, which carries no Authorization header. The spent state is the authority: it names the member and the provider, once.
- The code is exchanged and the address read.
- The refresh token is sealed.
- It redirects to `/connectors?mail=<connected|declined|expired|failed>`.
- A state used twice, forged or expired is `expired`.
- Connecting the same address and provider again replaces the credentials on the same row.

**`POST /api/mail/accounts/imap`** checks the settings, verifies, then stores. It answers 201 `{ account }`.

**`POST /api/mail/accounts/:uid/verify`** checks the mailbox again:
- a success clears `last_error`;
- `invalid_grant`, a 401 from the provider, or credentials that no longer open set `status = 'expired'` with the sentence the member reads, for example "Outlook asked for the mailbox to be connected again. Reconnect it to send.";
- any other failure keeps the status and records its sentence.

**`DELETE /api/mail/accounts/:uid`**:
- revokes at the provider where it can (Gmail);
- empties `credentials` and sets `status = 'revoked'`;
- keeps the row and its `mail_sent` rows, so a sent row still names its address;
- after it, the mailbox no longer lists, confirms or sends.

**Another member's uid** is 404 "Mailbox not found." on every route, the same as one that does not exist.

### 5. The send

**`POST /api/mail/send/confirm`** `{ account_uid }` is the composer's pressed Send. It answers a one-use nonce (`kind = 'send'`, 5 minutes; only its hash is stored). The cookie flow's CSRF token covers both POSTs as it covers every other.

**`POST /api/mail/send`** `{ account_uid, to, subject, body, draft_uid?, nonce }` runs its checks in order:
- **the member's own account,** else 404;
- **the input:** one recipient address, a one-line subject under 200 characters, a body under 20,000 characters;
- **an active mailbox,** else 409 in the mailbox's own sentence;
- **the draft:** with `draft_uid`, the member's own D1341 draft, else 404 "Draft not found.";
- **the hourly limit:** at most `SENDS_PER_HOUR` (20) rows in the last hour, else 429 `send_rate_limited`;
- **the nonce,** spent before anything goes out. A missing, wrong, expired or spent nonce is 403 `confirmation_required`: "Press Send in the composer to send this email."

**The log.** Each attempt writes one `mail_sent` row:
- the recipient, plain for the member, and `recipient_hash` (`indexHmac`, for counting without the address);
- the subject;
- the provider's message id;
- the draft uid and the refs the draft quoted;
- `sent_at`, or the error sentence.

**A failed send** is logged, and the mailbox is marked as §4 says.

### 6. Checks

**`cloudflare-worker/test/mail_accounts_d1340.test.ts`: 10 tests,** on the migrated schema. `cloudflare:sockets` is a scripted SMTP/IMAP server (`socketDeps.connect`), and `fetch` is a scripted Microsoft and Google. They cover:
- the settings rules: port 25, plaintext, a local host or IP, an empty password; header safety; the message's encoding;
- **port 25 is refused before any socket opens**;
- a mailbox verified by SMTP AUTH then IMAP LOGIN with nothing sent, sealed (`v1.`), opened only for its own row, and never in a reply;
- a wrong password, refused and not stored;
- **a send without the nonce is refused**, a nonce is spent once, a line break in a header is refused, and the recipient is hashed;
- **another member's uid is 404** on send, confirm, verify and disconnect;
- **an expired Outlook token turns the mailbox `expired` with a sentence**, logs the failed send, refuses further sends and shows the same on verify;
- the Graph send and the sealed rotated refresh token;
- Gmail held behind its switch; Outlook's three scopes, with `Mail.Read` only when asked; the state spent once, and a forged one refused;
- Gmail's scopes and client, its send, and its revoke at Google;
- **disconnect deletes the credentials and keeps the sent rows**;
- a draft's refs on the sent row, another member's draft as not found, the hourly limit, and the support session refused.

**Credentials are never in a reply or a log.** Every test that touches a secret checks every reply, and the captured console, for the password, both refresh tokens and the `AUTH PLAIN` string.

**Mutation checks, both ways.** They covered:
- the port 25 rule and the TLS rule;
- SMTP AUTH's reply, IMAP's login and IMAP's part in verify;
- the nonce check, and both nonces' spent-once rule;
- the owner filter on accounts and drafts;
- the credentials emptied on disconnect, the sealing, and the view without credentials;
- expiry on `invalid_grant`, the active-mailbox check and the rotation;
- the hourly limit and the support-session refusal;
- the Gmail switch and the header-safe subject;
- `Mail.Read` only when asked;
- Google's revoke and the provider revoke on disconnect.
