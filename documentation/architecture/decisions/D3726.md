### 1. What this build draws, and from what

| Board | Address | Drawn from |
|---|---|---|
| LR1 "Your progress" | `/learning` | The four figures (courses in progress, lessons completed this month, watch time this month, exams passed), each **Not recorded** with "arrives with #4180". Never a 0. |
| LR1 "New this week" | `/learning` | `GET /api/learning/catalog` (D557), the rows the All tab already reads: courses, videos and readings dated in the last seven days, newest first, at most four. A failed read is **Unreadable**, never an empty week. |
| LR1 "Recommended for you" | `/learning` | A dashed "Future" block with no rows, waiting on #3724. |
| LR4 resume | lessons, `/learning/videos/:uid`, `/learning/items/:uid` | The stored `position_seconds` on the caller's item progress (`GET /api/learning/items/:uid`). "Resume from 12:05" shows when the position is at least 5 s in and more than 5 s before the end; the player seeks there once. |
| LR4 position writes | the same | `POST /api/learning/progress` with `status: 'started'`, `position_seconds` and `percent` (the route keeps a completed subject completed and never lowers the percent). At most one write every 15 s while playing, and one on pause or end (`positionWriter`); a write in flight is never doubled. |
| LR4 chapters | the same | `item.chapters` when the item carries them; until L1 stores them, **No chapters** · "Chapters arrive with the Stream videos (#4176)." |
| LR4b plain transcript | the same | The stored transcript, with the line "No caption cues, so the plain transcript is shown." |
| LR13 / LR13b member program | `/learning/my-programs/:program` (new, every member role) | `GET /api/learning/programs/:uid` (D558), which already answers a member: the curriculum with their progress on each item, the overall count, **Continue** to the first item not done, and the enrolment card. A program open to join that they are not in draws "Join to start" on each row and **Join** (`POST /programs/:uid/enrol`). A program they may not see is the route's 404. My programs on the home links each program here. |

`learningModel.js` and `programModel.js` hold every word and rule, tested now (`frontend/test/learning_stream_d3726.test.mjs`):
- `LEARNING_STREAM_TASKS`, the issue behind each board this build cannot fill;
- `newThisWeek`, `PROGRESS_FIGURES`, `RECOMMENDED_FUTURE`;
- `clockLabel`, `resumeAt`, `positionWriter`, `NO_CHAPTERS`, `PLAIN_TRANSCRIPT_LINE`;
- `memberProgramHref`, `enrolmentCopy`, `continueTarget`.

The one new client call is `readMemberProgram` (`programReads.js`) over the existing `learningApi.program`, and `recordItemPosition` (`learningReads.js`) over the existing `learningApi.recordProgress`. No client method is added.

### 4. Rules carried from the brief

- "Not recorded" is never 0; a failed read is never an empty list.
- The member's progress is their own: every write is the caller's row (the route binds the session's user).
- No cohort dates, mentors or applications on a program: none is stored, and the page says so.
- The coming-soon gate (`learningComingSoon`) is unchanged: a held profile sees the card in place and reads nothing.
