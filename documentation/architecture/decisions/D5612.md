## D5612 — The route registry, the API index and the skill library are built before every build and test, not committed (#5612)

**Context.** #4105 made a new Worker router, a new API client module and
(D4225) a new library skill one new file each, but each also rewrote a
committed, sorted, generated list: `cloudflare-worker/src/routes/_registry.ts`,
`frontend/src/lib/apiModules.generated.js` and
`cloudflare-worker/src/services/agents/skillLibrary.generated.ts` (626 KB). In
the 7 days to 2026-11-11 (569 commits on `origin/main`) the API index was in
28 commits, the registry in 26 and the skill library in 3. Two PRs adding
neighbouring modules conflicted on the list, and the remedy was a rerun and
another push. CI never regenerated them; it only checked that the committed
copy was not stale. Part of #5600; it finishes #4101/#4105 the way D4103 did
for the routing projections and D529 for `docs/`.

**Decision.**

1. `.gitignore` lists the three files and they are removed from git.
2. `scripts/build-generated.mjs` runs the three generators
   (`build-route-registry.mjs`, `build-api-index.mjs`,
   `build-skill-library.mjs`). They use Node built-ins only, so it runs before
   `npm ci`. `--check` runs each generator's `--check`.
3. It runs before every build, typecheck and test:
   `scripts/build-frontend.mjs` (so `npm run build`, the deploy, the PR
   preview and branch provisioning); `frontend/` `predev` and `prebuild`;
   `cloudflare-worker/` `predev` and `prelint`; the root `pretest:frontend`,
   `pretest:worker`, `pretest:guards` and `pretest:types`; and the top of
   `scripts/test-drift-parts.mjs`, whose parts run `node --test` and `tsc`
   directly. `test:guards` itself is unchanged.
4. A CI job that runs `tsc`, `node --test`, a bundling `wrangler` command
   (`deploy`, `dev`, `versions`), `vite` or `playwright test` (whose `webServer`
   starts vite) without `npm run build` first has an
   explicit step, `node scripts/build-generated.mjs`: `ci.yml` `worker` (before
   `tsc`) and `drift` (before `check-api-drift.mjs`), every `*-contracts.yml`
   job, `deck-visual.yml` `visual` and `pr-preview.yml` `login-e2e` (both run
   `playwright test`), and the four other jobs that run `node --test` directly
   (`claude-review.yml` `selftest`, `meeting-bot-image.yml` `validate`,
   `release-alpha-rename.yml`, `release-draft.yml`).
   `frontend/test/generated_before_build_5612.test.mjs` reads every workflow
   and fails on a job that runs one of those commands with no earlier generate
   step or `npm run build`. `wrangler d1`, `r2`, `tail` and the like read no
   source and are not counted.
5. "Stale" checks became "deterministic and untracked"
   (`scripts/lib/generatedOutput.mjs`). Each generator's `--check` renders its
   output twice, once from the folder listing as read and once from it
   reversed (and, for the registry and the index, the list handed to the
   renderer reversed too), compares the bytes, and fails if `git ls-files`
   lists the output. `registryProblems` (`scripts/lib/routeRegistry.mjs`), the
   API index's checks (`apiIndexProblems` in `scripts/lib/apiModules.mjs`,
   read by `check-api-drift.mjs`), `route_registry_4105.test.ts`,
   `agent_skill_library_d1612.test.ts`, `skill_case_identity_5336.test.ts`
   and `scripts/check-skill-library.mjs` hold the same two rules. The skill
   library gate's `generated_stale` rule is now `generated_unsound`
   (`generatedSound`): tracked, not deterministic, or not the build of the
   files this run imports. The tests still assert that the module a run
   imports is the current build; that is now a property of the run, not of
   the commit.
6. `AGENTS.md`, `CLAUDE.md` and the READMEs that said to commit the files
   now say never to commit them.

`scripts/check-folder-docs.mjs` fails when a README cites a file that does not
exist (checked on #5612: with the three outputs deleted it names eight README
citations), so it runs after generation: in `test:guards` through
`pretest:guards`, and after the generate step in the two contracts workflows
that call it.

**What determinism catches, and what it does not.** Dropping the `.sort()` in
`build-skill-library.mjs`'s listing, in `renderRegistry`, or in
`renderApiIndex` makes `--check` fail. Dropping the `.sort()` in `routeFiles`
or `listModules` alone does not: the renderer sorts again, so the output is
still deterministic and still correct. The check guards the bytes, not each
line that produces them.

**Out of scope.** `frontend/src/decks/spinout/icons.generated.js` stays
committed (its generator needs ImageMagick); baselines and ledgers;
`check-skill-library.mjs --persisted` (#5335). No workflow gains a `paths:`
filter.
