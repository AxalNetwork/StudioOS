## D6414 — Require arrays when decoding stored event preferences (#6414)

Migration 709 checks JSON syntax for interests, formats and event types, but
historical or imported rows may contain a JSON object, scalar or null. Decode
all three through an explicit array-shape check in `readRecPrefs`. A malformed
row throws and the existing route boundary returns `503 unreadable`; it is
never treated as an empty preference list or a successful disabled result.

Preserve valid recorded arrays, absent-row defaults and the other fields.
This read does not rewrite stored values or impose today's write catalog on
historical array contents. Write validation remains in `prefsError`. No schema
change or migration is needed: the read boundary protects existing rows.

The real SQLite route regression covers each field with objects, null, string,
number, boolean and invalid syntax, checks both read endpoints fail closed,
and verifies the original row is unchanged and valid values still round-trip.
The test-only constraint bypass models rows that predate the syntax constraint.
