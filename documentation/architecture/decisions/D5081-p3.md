## D5081 part 3 — Raise tools own their pages: Cap table (#5081)

- **Status:** Part 3 built, 2026-11-16 (frontend only; no Worker change, no migration, no new route). Part 1 (Use of funds) is `D5081.md`, part 2 (Capital relationships) `D5081-p2.md`. Data room (RA-19) and the Raise navigation (RA-12) are later parts of #5081.
- **Canvas:** `design/incoming/Raise v2 · Boards.dc.html` RA-20 A (recorded against modelled) and B (refused), and RA-14's table ("Cap table · Yes · Removed · Set up cap table · Record issuance"); `design/incoming/Raise v2 Page.dc.html` (`captable()`, `capRefused()`).
- **Builds on:** D1015 (the tool), D1022 (Overview's record blocks), D1025 (Record an issuance at `/new`), D5074 (the record read's capability map), D5079 (a refusal is not a failed read), D5076 (the zero state's first action is the page's one primary), D5081 parts 1 and 2 (`owned`, a module's own primary, the Home read held by CycleRoute).

### What was wrong

`/raise/cap-table` drew the tool's Overview (the tool bar, Needs you, Who owns, the tiles, the bars, the instruments and the 409A line) and then CycleModulePage's generic layer under it: "Cap table · at a glance" (the Worker's Planned round card) and a Holders records table, both from the saved model, which Scenarios already shows as Cap table · model. The line under the tabs named those two blocks "below". The header's primary action was Raise's global Build your deck, while the tool bar carried the tool's own Record an issuance. On first use the empty card offered one button, Record founding shares.

### The decision

1. **The tool owns its page.** CycleRoute passes `owned` on Overview (`capTableOwnsHome`: the module page, no record, no tool tab, no lightbox), so the page draws its header, the tool's tab bar and Overview's blocks, and the module's own parts (Eadwyn's two bands, Evidence), and nothing generic, on a desktop or a phone. The URL is unchanged; an `e-<n>` or `pool` record keeps its own page. The Planned round card and the Holders list are the saved model, which Scenarios keeps as Cap table · model and Overview's third bar already draws (Modelled), so neither is kept. The line under the tabs (`OWNED_NOTE`) no longer promises them.
2. **One record read.** The record read (D1017) moved to `capTableHomeRead.js` (`useCapTableHome`), a small file so the tool's step stays lazy (D4574). CycleRoute holds it through `defs/raise.jsx` (HUBS.md: the frozen route gains no import specifier) on the module page and every tool tab, and hands it to `CapTableOverview` (`home`) on Overview and the drawers and dialogs over it, so the header's action and the blocks read once. An Explorer makes no read, as before.
3. **The primary action is the module's own** (`homeAction`, RA-20's Record issuance in the tool's own words, D1025). The owner gets **Record an issuance**, a co-founder **Propose an issuance**, each opening `/new` over Overview. None while the record is unread, failed or refused; for a viewer the capability map does not let write (a reader, an admin who corrects, anyone without the plan, D5074); and on first use. The tool's tabs carry the same action in place of Build your deck, except over Record an issuance and a proposal, which are already open. On a desktop the tool bar no longer draws Record an issuance a second time; the plan gate and the blocked save still say why nothing can be recorded. On a phone the header is the bar, with no action, so Record an issuance stays in the tool bar, full width (D1028).
4. **First use collapses to its set-up actions** (`isFirstUse`, `setupActions`, RA-14's Set up cap table). The record read answered with nothing recorded is first use: the empty card ("Nothing is recorded yet.") with **Set up cap table** (the founding shares, `/new`; a co-founder's Propose an issuance), **Import a spreadsheet** (Import and export, where the map allows an import) and **Model a round** (Scenarios). Without the plan, or for a reader, the card has no action. A read still loading, failed or refused is never first use. When the earlier model is kept as a scenario, its card keeps its one action, Record them from the model.
5. **No implementation-stage copy.** None was shipped on this page; the line that named blocks no longer drawn is the one sentence changed.

### What the boards draw that no read backs (reconciled against main)

Not built here, and nothing is made up in their place:

- **RA-20 A's Current ownership card** (Founders, Investors, Option pool, Fully diluted shares, Outstanding instruments, as of a date). Each figure is already on Overview from the record (the tool bar's As of, the tiles, the group bar, Who owns, the instruments). Restyling the blocks into one card is a follow-up of the Cap table redesign, not this part.
- **RA-20 A's Model the next round block** (three scenario cards with Founders after and New investors). Scenarios draws these cards from the compare read (D1024); copying them onto Overview would draw them twice. Overview keeps its third bar (the model's last round, Modelled).
- **The header's Import button beside Record issuance.** The module header carries one action; Import is the Import and export tab and, on first use, a set-up action.
- **Four tabs (Ownership, Instruments, Scenarios, History).** The tool keeps its seven (D1015): Option pool, Access and Import and export each have their own read. Folding them is RA-12's navigation, part 5.
- **RA-20 B (refused)** is already D5079's: "This cap table belongs to another company." with Switch company and Ask for access, and nothing after it. Unchanged.
