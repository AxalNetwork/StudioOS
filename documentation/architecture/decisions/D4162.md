### 1. The store

**`ai_agent_policy` is one row, id 1.**

| Column | Meaning |
|---|---|
| `platform_budget_microusd` | the platform budget (H5's) |
| `default_team_cap_microusd` | the cap a new team agent starts with |
| `max_team_cap_microusd` | the highest cap any team agent may have |
| `per_run_ceiling_microusd` | the most one run may cost |
| `area_models_json` | per radar area: up to 3 suggested models in order, and a default among them |
| `read_tools_json` | the read-only connector tools skills may request |
| `paused`, `paused_at`, `paused_by`, `paused_reason` | the kill switch |

- **NULL means not set:** no budget, no cap, no ceiling.
- **Every write upserts row 1 first.** A database that never had the row, or lost it, gets it back, and never gets a second one.
- **`ai_model_locks`** has one row per model locked off platform-wide, with its reason, date and admin.

### 2. Routes

`/api/admin/ai-agents/policy`, Super Admin only.

| Route | Does |
|---|---|
| `GET /` | reads the whole policy |
| `PUT /models` | sets the models per area |
| `POST /locks`, `DELETE /locks/:model` | locks or unlocks a model |
| `PUT /caps` | sets the budget, caps and ceiling |
| `PUT /tools` | sets the read tools |
| `POST /pause`, `POST /resume` | turns the kill switch on or off |

- **Every write needs a reason** of 1–500 characters.
- **Every write lands in one `DB.batch`:** the row-1 upsert, the change, and H5's `ai_admin_audit` row (action, `area: 'policy'`, subject, before, after, reason). The change and its audit land together or not at all.
- **Checks:**
  - A model must be in the catalogue.
  - An area must be one of the 8.
  - An area suggests 1–3 different models, and its default is one of them.
  - A cap is a whole number of micro-dollars above 0, or null.
  - The default team cap cannot be above the maximum.

### 3. The kill switch

- **Turning it on:** `POST /pause { reason, confirm: 'PAUSE' }`. `PAUSE` must be typed exactly; a lowercase `pause` is refused.
- **Turning it off:** `POST /resume { reason }`.
- **Refused paths while it is on** (403 `platform_paused`, "Axal has paused all AI agents on the platform. Open proposals can still be decided."):
  - **`engine.ts` `engineRefusal`**, the first check of `admitInScope`. Both runtimes reach it, because `do` and `sdk` share `DO_DEPS`. It covers every source: a person's start, the sweep, `after` and a duty. No run row is written.
  - **`agentRun`**, before any tool read, hold or charge.
- **Open proposals stay decidable.** Deciding one goes through `decideRail`, which admits nothing here.
- **A run already past admission** is refused at its model call by `agentRun`. For an immediate stop mid-step, #4157's `agents:halt` remains.
- **A policy that cannot be read counts as paused**, the same rule as `agents:halt`. A database before these migrations has no policy table and reads as no policy, so older schemas and tests run unchanged.
- **The team banner:** `GET /api/teams/platform-status` answers any signed-in member with `{ paused, since, by_name }`. The admin is named, never by email, and HQ's reason is not shown. `PlatformPausedBanner` draws one line at the top of the Team page (`TeamAgentsPage`) and draws nothing when agents are not paused.

### 4. Models, ceiling and caps at run time (`agentRun`)

- **A locked model** is swapped for the agent's area default when that is not locked. Otherwise the run is refused 403 `model_locked`.
  - The agent's area is the radar axis most of its linked skills tag (H5's `agentAreas`).
- **The per-run ceiling.** When one is set, the run is quoted first. A quote above it is refused 402 `run_ceiling`, and nothing is held or charged. A quote that cannot be read is 503 `run_quote_unreadable`; it is never passed as under the ceiling.
- **The maximum team cap.** `routes/team_agents.ts` refuses a cap above it, on both a new agent and a cap change (422 `cap_over_platform_max`). A policy that cannot be read sets no new cap (503).
  - H1's per-agent defaults read `default_team_cap_microusd` and are capped the same way.

### 5. Tools

- **Skills may request only read tools.** A tool is `<connector>.<tool>`, and the tool's name must start with a read verb: read, list, get, search, find, fetch, lookup, count, view, describe or query.
- **Anything else is a write and is refused** with 422 `write_tool`, naming each tool. There is no central read/write registry for connector tools, so the rule is the verb, strictly. A read tool with an unusual name has to be renamed, or added to the verb list by a later decision.

### 6. Guardrails

The three rules are:
- "Never advisor or advice on AI surfaces";
- "Legal and Capital explain or draft, never decide";
- "No invented figures".

Each is shown with the check that enforces it. None of those checks writes a row a count could be read from: they refuse in the moment, or fail the build. So each 30-day count is `null` ("Not recorded"), never 0. A check that starts recording adds its query to `guardrailCounts`.
