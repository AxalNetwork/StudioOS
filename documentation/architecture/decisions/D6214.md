## D6214 — Attributed, period-aware Portfolio reporting settings (#6214)

Implements the approved D6213/PF-13–19 settings sheet and owner answers in
D6213-p2. The existing Report toolbar action becomes Reporting settings; the
Rules view also offers access. The shared Sheet owns modal focus, dismissal,
phone layout and dark mode. No new route or visual-system token is introduced.

Each full rule revision records its fund, actor, timestamp, due-day default and
current effective month and quarter. The migration captures legacy per-fund
and HQ definitions as the initial history. A fund inherits HQ until it records
its own set. Empty sets are valid and remain distinct from unreadable sets.
Writes require the active-company fund GP gate and the existing fund-report
draft write bar, including support-session and frozen-admin restrictions.
A bound compare-and-insert rejects concurrent revisions. Activity attribution
commits only with a successful insert. The HQ default is read-only on this UI.

Compliance resolves rules for the requested period and each visible company's
funds and stage. Signed reporting duties retain their own due days; the fund
rule default applies otherwise, with HQ's 30-day default last. Previous periods
keep their recorded rules. Multiple funds' requirements are combined for a
company that reports to both. The founders' reporting desk and report builder
also consume stored required rule keys, while a document naming figures keeps
its explicit requirements. Neither frontend nor Worker maintains a parallel
hard-coded required KPI list.

Monthly and quarterly reads fail independently; saving requires both reads and
a matching revision. A stale save retains edits and compares current rules
before another save. Changes apply to the period in progress, as the owner
approved. Save and Close return to Reports with Rules selected; the reporting
period is preserved. The existing PDF/issued fund report work is separate.

The authoritative design remains design/incoming/Portfolio v2 Reporting
Settings Page.dc.html. Existing PortfolioFrame, Sheet and pf-* tokens supply
presentation and behavior; no repository-wide redesign is part of this task.

The books query interpolates only fundManageScope's fixed internal SQL fragments; user/company values remain in its bound parameters, as on the existing funds route. The SQL prepare ledger records this scoped use. Validation refusals carry authored sentences rather than exception text.

Review follow-ups: duty reads resolve keys independently at each period end; an unreadable duty stays explicitly unavailable without hiding other duties. Only the caller’s managed funds contribute rule history (admins retain their whole-book scope). Repeated keys across cadences are independent; a duplicate within one cadence is refused. The new migration validates legacy JSON and fails loudly before incompatible seeds can ship. Custom KPI keys remain tracked in company updates; the Grow report builder only requires its registered figures, as the sheet explicitly explains. Conflict refresh preserves the draft until the user chooses a comparison outcome. Reorder stays within the visible cadence, company changes reset the selected Rules book, and saving refreshes that book even when its id is unchanged. The approved PF-13–19 canvas has no remove control; no new undrawn control was added.

Final review verifies period lookup by immutable id (duplicate display labels cannot collide), request-local book/history caching so query count does not grow with periods, and an explicit firm-wide basis for non-manager company views. Legacy trigger validation and JavaScript use matching trimmed Unicode character limits, including missing nullable fields. The trigger uses SELECT RAISE ... WHERE so the normal migration transaction guard can classify it correctly.
