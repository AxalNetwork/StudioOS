## D7815 — Comparison save recovery and record-bound fund refreshes (#7815)

Project Compare keeps one request identity and frozen selection/title for an
attempt. The existing `saveOutcome` and `statusView` helpers supply the result
states. A lost response locks the selection and offers Check save status; an
unreadable status keeps the outcome unknown. A not-found status permits only a
retry of the same request. A found comparison refreshes the list. Both Companies
links use this tab's existing `backToResults` store. The established form and
outcome vocabulary are reused; no new screen or shared helper changes.

Adding a comparison member retains the early full/duplicate answers, but one
SQL INSERT now checks the live count, takes MAX(position)+1 and excludes a
present member in the same statement. A lost insertion race returns the existing
`added: false` shape for a duplicate or the existing `comparison_full` refusal.
No migration or index change is needed.

The public fund profile's main and pre-action reads use `recordGate` plus the
route identity. A late withdrawal, shortlist save or notice from another route
is dropped. The dossier's link, keep-own and accepted-brief refreshes use the
same gate as its initial read and preserve unsaved fields only for the dossier
that initiated the operation. Delayed focus callbacks obey that identity too.

Scope stays on the named #7815 handlers and reads. #7744, #7748, #7757 and #7759
remain blocked at intake and have no open implementation PR owning these parts.
The prerequisite #7653 is on the base; no broader #5157 ownership is
transferred. The canonical layout/behavior sources are the existing Research
canvases, D7177/D7167/D4607, comparisonSave and recordGate; no global design or
UX contract is introduced by this corrective task.
