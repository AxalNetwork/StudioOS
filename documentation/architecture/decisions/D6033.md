## D6033 — Solution design: a paged Risks list, including risks not tied to a feature (#6033)

- **Status:** built 2026-11-22. The owner answered option A on every D6026 question on 2026-11-16 (#6026), so Q1 A stands: the risks list returns, reversing the 7 November decision (#4603 part 2).
- **Builds on:** `routes/cycle_build.ts` (`POST /risks`, `PATCH /risks/:id`, the module read's severity counts), `services/records/owned.ts`, `services/buildPlanAccept.ts` (an accepted risk writes no feature), D6023 (a feature's risks edited on its record).

### What is built

- **A read of its own.** `GET /api/cycles/build/risks?project=…&state=…&feature=…&page=…` answers 25 risks a page, with the total, the page count, and the venture's unfiltered counts by state, by feature (tied, untied) and by severity. It has the module read's gate (`context`), and a writer (`canWrite`) also gets the company's members and the venture's features for Add. A reader is sent neither. A bad state, feature or page is a 400 with a code and a sentence. The module read is unchanged: it still reads the risks once, grouped by severity, and sends no list, so its statement budget (`build_read_amplification_4603.test.ts`) holds.
- **Every risk.** The list joins features with a LEFT JOIN, so a risk with no feature (an accepted Build Plan risk writes none) is listed, as "Not tied to a feature". "From the Build Plan" is drawn when a plan item landed in `venture_risks` at that id. High comes first, then Medium and Low, and closed risks follow open ones within a severity.
- **Ownership widened safely.** `ownedRow('venture_risks')` now accepts a risk of the venture with no feature. A risk that names a feature is the venture's only while that feature is the venture's too. Before, a feature-less risk was never the venture's own record.
- **The page.** Solution design draws the list above the features table, through Build's `aboveRecords` (no new hub entry). The list shows severity and state as a word and a glyph, owner as You, a name or No owner, mitigation or "No mitigation recorded", the feature linked or "Not tied to a feature", and "Addressed by test" as Not recorded yet. Filters for state and feature appear from ten risks (BD32). Add a risk sets title, severity, owner, feature and mitigation, and says owner and feature cannot change later. Edit risk changes title, severity, state (closing a risk) and mitigation, with owner and feature read only. Both go through the existing routes, and a refusal shows the Worker's sentence and keeps the dialog. A save re-reads the list and the module, so the counts card follows.
- **States.** Empty reads "No risks recorded" with Add a risk. A failed read is "Risks are unavailable" with Try again, and still offers Add, while the counts card and the features table stay drawn. A filter that matches nothing says so, never "No risks recorded".
- **Phone.** Below 768px the list is cards, and Add and Edit are bottom sheets. Build names Solution design in `aboveRecordsWhenEmpty`, so a phone shows the list before the venture's first feature. That is a one-condition change in `CycleRoute.jsx`, which adds no import.
