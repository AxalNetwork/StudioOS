## D4394 — Agent engine E8: the Worker fields TM10, TM13, TM18b and TM19c lacked (#4394)

- **Status:** built by slot S24 on 2026-11-04. Closes #4394.
- **Migration:** none. Every field reads columns that already exist (`team_agents.persona_key`, `ai_rail_proposals.task_id`, `ai_budget_reservations.execution_id`, `agent_task_runs.ended_at`, `agent_handoffs.created_at`).
- **Builds on:** D1531 (E8's screens), D1529 and D1530 (the read and manage gates, kept unchanged), D1614 W1 (the Work board), D4117 (personas, no job titles).

### What was decided

Six additions to existing routes in `routes/agent_engine.ts` and the services behind them. Each one draws something the E8 canvas already shows. The frontend picks a field up once it exists; this PR changes no frontend file.

**1. The planner names its agent (TM10c, TM10d).**
- `GET /api/teams/goals/:uid/plan/quote` and `POST …/plan` carry `agent: { uid, persona: { key, name } } | null`.
- `null` means Eadwyn plans: the scope has no active CEO / Chief of staff agent.
- The agent is named by its persona only (`plannerRef` in `services/agents/planner.ts`). It carries no `role_key`, no job title and no first or last name (D4117 §6). An agent whose persona key is unknown reads `persona: null`, never a guessed name.

**2. Discard a drafted plan (TM10d).**
- `POST /api/teams/goals/:uid/plan/discard { proposal }` answers `{ ok: true }`.
- It needs the same manage gate as accept (`managedGoal`). A goal the caller cannot read answers 404, and a member who cannot manage it gets 403.
- `discardPlan` claims the proposal exactly as accept does, with `UPDATE … WHERE uid = ? AND status = 'proposed'`. A plan already accepted or discarded therefore answers 409 `plan_decided`, two presses discard it once, and a discarded plan can no longer be accepted.
- A missing `proposal` answers 400 `invalid_plan`; a proposal that is not this goal's plan answers 404.

**3. The plan's cost (TM10d).**
- The draft answer carries `cost: { held: Spend, charged: Spend }`.
- `draftPlan` gives the run its own uid and passes it as the hold's `executionId`: to `agentRun` as `runUid`, and to Eadwyn's `run()` directly. `held` then reads back that hold (`runActivity.heldFor`).
- `charged` is the run's usage rows with their guard rows: `agentRun`'s own `charged`, or `chargedFor(usageLogId)` for Eadwyn.
- When either one is unrecorded or unreadable, it is `{ available: false }`, never 0.

**4. Why a Work board item is blocked (TM19c).**
- Items already carried `blocked_reason`.
- An item blocked `decision_expired` now also carries `proposal_uid`: the newest proposal still `proposed` for that task (`ai_rail_proposals.task_id`). "Decide now" opens that proposal.
- `proposal_uid` is `null` for any other block, and also when the task's proposals were all decided, so a decided proposal is never named.

**5. The runs a move stopped (TM18b).**
- On an `out` move, `GET /:scope/:id/moves` adds `stopped_runs: [{ agent: { uid, persona }, task: { uid, title } }]`. An `in` move carries no such field.
- A run counts when it ended `scope_moved` at or after this move and before the project's next move.
- **Each scope sees only its own agents' runs**, never the other side's:
  - A project that left every company sees its agents' runs.
  - The company it left sees its agents whose tasks the move blocked (`project_left`).
  - The issue does not say whose runs to show. Showing the other side's agents would let a company that lost a project keep reading that project's team, which the move just ended.
- A project moving between two companies reads `in` from its own side (#3850's direction rule), so only the company it left lists stopped runs for it.

**6. When a handoff chain started (TM13).**
- Each chain in `GET /:scope/:id/handoffs` carries `started_at`, the time of its earliest step.
- The list is still ordered newest first by its latest step. That ordering key stays internal.

### Rules kept

- D1529/D1530's read and manage gates hold on every route touched.
- A person is `{ uid, name }`, never an email. An agent is `{ uid, persona }`, never a job title.
- An unknown cost is `{ available: false }`, never 0.
