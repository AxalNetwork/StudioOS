## D6558 — Type a person into your own network book (#6558)

`POST /api/contacts/book` accepts a required name and optional company, title,
email and LinkedIn profile URL. The authenticated caller supplies the owner;
a body cannot select another member. Support sessions cannot write. The
mounted contacts client exposes `contactsBookApi.add(person)`.

A single D1 batch creates the book row and its `typed` provenance. An existing
own-book URL or email match creates a pending duplicate review (URL first),
never fills or merges the existing row. A foreign book is neither searched nor
changed. A failed provenance/review insert rolls the whole batch back. No
import job, invitation, notification or message is created. The form remains
with #5310.

Validation bounds text, normalizes email and LinkedIn profiles with the existing
CSV normalizers and refuses malformed fields. The API returns the new contact
id, optional review uid and `contacted: false`. Existing review decisions remain
the explicit way to merge or keep both. Multiple matching candidates are
resolved deterministically to one pending review; no automatic merge occurs.

Verification uses mounted routes over the complete migrated SQLite schema,
including support/anonymous refusals, another member's matches, an explicit
review decision, typed source filtering and rollback after a failing source
insert. Test fixtures contain synthetic people only.
