## D5317 — Restore drill history in Security Resilience (#5317)

The drill still writes the latest marker. The same EXIT trap writes one copy of the evidence per run under `drill-d1-history/` in the existing backups bucket. The key starts with the inverted UTC start time and includes a unique suffix, so overlapping runs cannot overwrite each other. No previous runs are backfilled.

Keep the latest 12 history objects. A successful history write prunes older matching objects in the dedicated prefix using the drill's existing credentials. A retention failure logs a warning and the next run can prune again. The reader always serves at most 12. Neither history writing nor pruning changes the drill outcome.

The Security overview reads history independently of the latest marker. An empty list is a successful read with no recorded runs. A missing binding, failed read or invalid record leaves history unavailable with no rows. Each historical pass ages against the same threshold as the latest marker, so a stale pass does not appear Verified.
