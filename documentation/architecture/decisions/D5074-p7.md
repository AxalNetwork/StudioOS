## D5074 part 7 — the Raise overview's narrative card and the New version dialog from the narrative map (#5074)

Part 3 (`D5074-p3.md`) moved the Investor narrative's pages onto the narrative map. It left two places reading the account, because neither had a narrative read with a map before it drew: the Raise overview's narrative card (`defs/raise.jsx`, `NarrativeHome`'s `admin`) and the cycle's Add/Edit dialogs (`narrativeFormAccess`). This part gives them that read, and it is the last item of #5074.

- **The read carries it.** The module read (`GET /api/cycles/raise/modules/investor-narrative`) returns `parts.narrative.capabilities`. That is `narrativeCapabilities(narrativeStanding(…))`, the same map the versions read returns and the narrative's writes refuse from (part 3). It is sent even when the part's own store fails (`state: 'unreadable'`), because who the caller is does not depend on that store. A refused module read (an admin without a reason, another founder, an investor) carries no part and no map.
- **The overview card renders from it.** `NarrativeHome`'s `admin` is `narrativeStanding(part.capabilities).readOnly`. A map without `edit` (an admin's) draws no Answer it and no reads list, and neither does no map. The account's role (`ctx.role`) no longer decides it.
- **The dialog renders from it.** `narrativeFormAccess(projectId, capabilities, user)` makes the New version and Edit dialogs read only when the module read's map has no `edit`. When the module read carried no map (it was refused, or has not answered), the account words the dialog as before: an admin's is read only and offers the reason form, the one way an admin's refused read recovers. This is part 3's rule for the pages: the account words only a read that carried no map.
- **Not moved.** `CycleRoute`'s page-level `narrativeAdmin` still reads the account. It draws the reason gate before any read has answered (D914), and it withholds the Add button, fills, drafts and asks around it. The Worker refuses those writes from the map either way.
