## D6001 — Customer research: add a lead, move its stage, and filter by stage (#6001)

- **Status:** built 2026-11-15. Follows the Validate v2 Discovery and ICP canvas (D5995, boards V26, VAP26B, VAP28 and VAP29G) where it does not wait on the owner. Part of #4837.
- **Builds on:** `services/cycleValidate.ts` (`LISTS['customer-research']`, `researchRecords`, `customerResearchCard`), `services/records/validate.ts` (the interview record), `services/validateWriters.ts` (`setInterviewStage`), `routes/progress.ts` (`POST /discovery/:projectId` and the waitlist `invite` and `follow-up` routes). No new route, no migration.

### What changed

1. **The Stage filter is listed.** `LISTS['customer-research']` lists Stage after Channel, with the options Lead, Invited, Invited · no slot yet, Booked, and Done · or no stage recorded. Each option filters on the stage a row has now. D697 decision 4 had removed Stage from the list and kept it only as the recruiting picker's `stage:pipeline`. The canvas brings it back next to State, so the frontend tests that pinned its absence now pin its presence.
2. **Stage is never guessed.** An interview with no stage is still a conversation logged after it was held. It counts as Done in the filter and the funnel, its State still reads Logged, and the Done option's label says so. Nothing in this change writes a stage the founder did not choose: Move stage preselects no option, and a request with no stage gets a 400. A row with no stage is labelled "Done · current · no stage recorded".
3. **The card's next link lands on the rows it names.** "Book the N invited leads with no slot yet" links to `?filter=stage:invited_no_slot`. That filter matches the same rows the card counts (`waitingForSlot`): rows at Invited with no `booked_at`. A lead that was booked and later moved back to Invited keeps its booking stamp, so it is not counted or listed. "Invite the N new waitlist leads" links to `#waitlist-leads`. `CycleRoute` now opens a module's table using the address's `?filter=` (`queryFromSearch`). The founder's filter controls take over from there.
4. **Move stage is a record action.** `set-stage` on the interview record calls the same writer as `PUT /interviews/:id/stage`, and that writer logs `interview_stage_set` on the record's activity. Each row in the list has a Move stage control, which posts the same action, so a move from the list and a move from the record are the same write. The form has the four stages, with the current one marked, and an optional "Date reached". A stage keeps the first date it was reached.
5. **Add a lead is a create at stage `lead`.** `POST /progress/discovery/:projectId` now accepts `stage: 'lead'` and refuses any other stage with a 400, because a later stage is a move with its own timestamp. It also accepts an optional `channel` (`in_person`, `video`, `phone`, `text`, `manual`). A lead gets no interview date unless one is typed, because it has not been held. Stage and channel are written in the same INSERT, so a lead is never stored without its stage. A create with neither field runs the statement it ran before. In the frontend, Add a lead is a dialog next to Record a session (`forms.js` `addLead`). It is not a `FORMS.validate` entry, because Customer research's `/new` and its zero-state action stay Record a session (D695, D6004). Only a writer sees it.
6. **Waitlist leads panel.** This panel appears under the list. It shows each customer sign-up with its CRM status. A New sign-up gets Invite, an Invited or Followed-up sign-up gets Follow up, and a Promoted sign-up gets its interview. These use the routes Spin-out Lab's page already calls. If the read fails, the panel says so and never shows itself as empty. A partner sees the panel without buttons.

### Pending the owner (D5995), not built

- **A promoted sign-up becoming an interview at stage Lead** (option A). `promote` still makes an interview with no stage, which reads as Done. This panel does not offer Promote. It stays on Spin-out Lab's page until the owner answers.

### Not drawn here

The cumulative funnel with its "reached … or later" labels, the stage chips with counts, the "Stage · date reached" column, and the phone's Move stage sheet from the list (VAP29G) are not built. On a phone, Move stage is on the interview record, where the record's actions are drawn. On the list, each phone row opens its record.
