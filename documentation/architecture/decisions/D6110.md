## D6110 — Team expansion: the role's host moves an applicant between stages (#6110)

- **Status:** built 2026-11-14 by S12. Filed under #4861.
- **No migration, no new route, no new client method.** The move is a record action that calls the existing writer, `setApplicationStage` (`services/growWriters.ts`), on `job_applications.stage`.

### 1. The record (`services/records/grow.ts`, `teamExpansion`)

- **Pipeline** counts every stage of `APPLICATION_STAGES`: Applied, Screen, Interview, Offer, Hired, Declined. It used to count four, so a move to Hired or Declined disappeared from the counts.
- **Shortlist.** Applicant names stay the host's (decision 9).
  - **The host** reads every applicant on the role, newest move first within each stage, to 50, then "N more applicants" linking to the jobs board's page. Each row has **Move to…**. It used to list only interview and offer, to 20.
  - **A hired applicant's row** reads "Add to the team roster" and links to `/build/team`. Nothing is written to the roster on its own.
  - **Anyone else** reads counts only: "1 at interview · 1 at offer · 2 hired". The interview and offer wording is unchanged.
- **The action `move-applicant`** ("Move to…", a form) is offered to the posting's host and an admin, the jobs board's `canManage`, on a role with applicants.
  - **Fields:** Applicant (this role's applicants, by name and current stage) and Move to (the six stages).
  - **Checks:** the writer checks the venture only, so the action checks that the applicant is on this role and refuses another role's applicant with 404 ("That applicant is not on this role."). An unknown stage is the writer's 400.
- **Activity:** the writer logs "Applicant moved to {stage}" on the role, never with the applicant's name, as before.

### 2. Opening the form from a row (`pages/cycles/recordModel.js`)

- **The row:** each applicant's row names the action with its own `{ application_id }`.
- **The pre-fill:** `recordFormFor` now starts a form field on the row's body value when the body names it, held as a string the way a choice holds it. So a row's Move to… opens on that applicant, and the record's own action row opens with none chosen.
- **The same fix elsewhere:** Validate's Update an experiment, whose rows send `{ experiment_id }`, now opens on its experiment too. `recordActionBody` still sends the body with the values.
