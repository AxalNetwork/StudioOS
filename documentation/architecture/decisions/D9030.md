## D9030 — A resumable driver for the D7821 company classification recompute (#9030)

**Decided.** The D7821 recompute (`POST /api/admin/research-company-mapping/recompute`) is run by one command, `scripts/research-company-recompute.mjs`, not by a hand POST loop. #7821 cites 52,896 company records; at the route's 100-row page limit that is more than 500 pages. The driver loops pages until `done:true`, carries `after` and `rules_version` from each answer into the next request, and prints one JSON object whose `counts` are the per-state, per-method and per-scheme counts summed over the pages it accepted. The route's counts describe the processed page only (D7821), so the sum is the driver's job; each accepted page is added once.

**Restart and stop.** A 409 `recompute_rules_changed` means an override landed during the run, so every page already summed was mapped under the old rules version. The driver discards those partial sums with the cursor and restarts once from an empty cursor without a `rules_version`. A second 409, any other non-200 answer (a 503 included), a network error or timeout, a malformed page or a page that does not advance stops the run: it prints `complete:false`, `stopped` (`status`, the refusal's `error` code, `at_after`), the `rules_version` and the sums of the pages accepted so far, and exits 1. Nothing is retried automatically except the one 409 restart. A stopped run is resumed with `--after <at_after> --rules-version <rules_version>`; that output carries `resumed_from`, and its `counts` cover only the rows after that cursor.

**Safety.** The admin session comes only from `RESEARCH_RECOMPUTE_COOKIE` (the Cookie header of a signed-in admin session); its `studioos_csrf*` value is mirrored into `X-CSRF-Token`, because the route is a cookie-authenticated POST behind the CSRF double submit. The cookie and the refusal's message are never printed; only the refusal's code is, after a `[a-z0-9_]` check. A base host of `axal.vc` or `app.axal.vc` is refused (exit 2, no request sent) unless `--confirm-production` is given. The base must be an https origin with no path or credentials; plain http is accepted for localhost only, for the tests' fake route. Redirects are refused so the cookie cannot follow one. `--dry-run` answers every page from an in-process stub of synthetic pages and needs no cookie.

**Operator steps.** These replace D7821's manual loop for the recompute; its override steps are unchanged.

1. Wait for the owner's written go on #9030. This decision does not authorise a production run.
2. Check the tooling with `node scripts/research-company-recompute.mjs --dry-run`.
3. Sign in to HQ as an admin, copy the session's Cookie header into `RESEARCH_RECOMPUTE_COOKIE` in the shell only, and run `node scripts/research-company-recompute.mjs --base https://axal.vc --confirm-production > recompute.json`.
4. If it exits 1, read `stopped`. A 409 means overrides are still being written: wait for them to finish and rerun from the start. Another stop is resumed with `--after` and `--rules-version` from the output, and the two outputs' `counts` are added by hand.
5. Post `counts`, `processed`, `pages`, `restarts` and `rules_version` on #7821 and #7830. Never post the cookie or any company row.
6. After any later override, recompute from the start (D7821).
