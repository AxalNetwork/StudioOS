## D4624 — Stop waits for every recorder slice, and a refused local write is recoverable (#4624)

- **Status:** Built for #4624, 2026-11-07. Frontend only.
- **Builds on:**
  - D685 §5.7.6 to §5.9.1 (the capture, its queue and Stop and process).
- **No migration, no Worker change.**

### What was decided

1. **Each slice has its own completion.**
   - `capture.stop()` waited one turn of the event loop for the last slice's `onstop`. A final event that fired later, or a local queue write that took longer, left `lastSeq` null, so a short recording read as "No audio was recorded".
   - Every slice now registers a promise that settles only when its final event has fired and its blob is written (or refused). `stop()` awaits all of them, including a prior slice that completes during Stop.
2. **`lastSeq` names what was persisted.** It moves only after `queue.put` resolves; `finish` is called with that sequence.
3. **A refused write is explicit and recoverable.**
   - The slice is kept in memory (`unsaved`), `stop()` reports `unsaved`, and the recorder does not call `finish`: it shows "Part of the recording could not be saved on this device. Free some space, then try again."
   - The capture is kept, so Retry stops it again, writes the slice again, and finishes with the persisted sequence.
4. **Unchanged:** offline queueing, pause and resume, the sign-out hold (`flush: false` sends nothing), and discard (which drops an unsaved slice).
