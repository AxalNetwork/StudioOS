### Why

`projects.tam/.sam/.som` are bare numbers. `loadMarket` returned `source: null` for every figure, so every band on the Market intelligence chart read "source not recorded", with no date and no record of what the figure was before.

### What changed

**The store.** `market_figures` holds one row per change: `project_id`, `figure` (`tam`, `sam` or `som`), `value` (NULL when cleared), `currency` (`USD`, as the project columns are), `method` (`typed`, `top_down`, `bottom_up` or `document`), `source_title`, `source_url`, `market_source_id`, `set_by` and `set_at`. The latest row per figure is the current one. A trigger refuses any rewrite of a row; only `market_source_id` and `set_by` may go NULL, which is what their `ON DELETE SET NULL` does. There is no delete trigger, so a project's hard delete still removes its rows.

**The source is copied, never typed by the client.** A save names one of the venture's own `market_sources` rows by id. The Worker checks that the row belongs to the venture and copies its title and link into the new row, so the history still names the source after the source row is removed. A source from another venture is refused with `400 invalid_market_source`, and a method not on the list with `400 invalid_market_method`. Nothing is written in either case.

**The write.** `PUT /api/projects/:id` is the one writer of the three columns that the sizing page, the project editor and admin edits all use. When the body carries `tam`, `sam` or `som`, the handler updates `projects` as before. It then appends one row for each figure whose value changed, or whose stated method or source changed. A page that echoes the whole project back with no `market_figure_source` writes no row for an unchanged figure, so the source already recorded stays. An admin's write on another person's venture is logged with `logAdminAction` (`market_figures_set`). If the rows fail to write, the figures are still saved, and the response says `market_figures: { recorded: null, reason }`. The sizing page then shows "Your sizing saved. Where it came from did not."

**The read.** `loadMarket` uses a figure's latest row only while that row's value equals the project's value. Otherwise, for example for a figure saved before this change, it falls back to `projects.*` with `reason: 'No source recorded for this figure'`. The same fallback applies when a writer that records no row changes the figure, so an old source is never shown against a new number. A row with a source gives `source`, `source_url`, `method` and `as_of` (the day of `set_at`). A row saved with no source named gives `source: null` with `reason: 'No source named when this figure was saved'`, and keeps its date.

**The page.** The band reads "<source> · as of <day>", "no source named · as of <day>", or, with no row, "source not recorded", as before. Market intelligence's parts end with History. It is the module read's `parts.market_history`, newest first, with each change's figure, value, method, source, who (a name, never an address) and day. It reads "Unreadable" when that part could not be read, and "No change recorded yet" when there is no row. The sizing drawer gains a Source picker over the venture's stored sources, seeded from the current TAM row. Its select is 44px tall.

### Writers of `projects.tam/.sam/.som`

| Writer | Writes a `market_figures` row |
|---|---|
| `PUT /api/projects/:id` (`routes/projects.ts`): the Lab sizing save, the project detail editor, admin edits of any venture | Yes |
| `POST /api/projects` (`routes/projects.ts`, project create: `tam`, `sam`) | Not yet. Reads "No source recorded" |
| `POST /api/projects/submit` (`routes/projects.ts`, the scored intake: `tam`, `sam`) | Not yet. Reads "No source recorded" |
| Eadwyn's founder answer `founder.project.som_usd` (`services/advisor/writeRouter.ts`, `som` only) | Not yet. Reads "No source recorded" |
| Scoring (`routes/scoring.ts`), fills (`services/fills/*`), imports (`routes/imports.ts`), Crunchbase, deck autofill | None of them writes the three columns. Scoring reads them as inputs, and the fills registry never proposes a TAM |
| `backend/` (FastAPI, dev only) | Not production. Unchanged |

Because of the three "Not yet" writers, `market_figures` is the source of truth for a figure only while its latest row agrees with `projects`, and the reader checks that on every read.

### Left as it is

- The three "Not yet" writers above. Each needs only a `recordMarketFigures` call after its own write.
- `method: 'document'` is in the store's list for a figure drawn from a document, but no writer sets it yet. The deck import does not write the three columns.
- The History part is not paged. It lists the latest 60 changes.
