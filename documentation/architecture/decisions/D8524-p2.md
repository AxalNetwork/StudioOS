### What running it found

On `main` at `d26a93a25`, the staged test failed: after the company signed, the investor's stage had no link. The spec was written before #8572 (merged earlier the same day as #8549) moved "send the next stage" into an owed effect, recorded in `esign_effects` in the same batch that completes the envelope. The test server builds its schema from the baseline plus a hand-picked list of migrations, and `202611250101_8516_esign_effects.sql` was not on the list. So the completion batch's effect insert failed inside the server, and the next stage was never sent. Production has the table, so this was the fixture, not the product. It went unnoticed because nothing ran the spec, which is the reason this part exists.

The server now applies that migration too. A test-server schema that misses a migration fails the spec, rather than passing silently.
