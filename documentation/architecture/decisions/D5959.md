## D5959 — A deliverable version's summary, stored apart from its change note (#5959)

Part of #4833 (Practice UX 5/6). D4833 lists this under "Not built (backend required)".

### The problem

The Practice v2 canvas's Add version dialog (`design/incoming/Practice v2 Page.dc.html`, PX-06) has three fields: "Change note · required", "Document or URL · required" and "Summary · optional". A version stores one text, `advisor_deliverable_versions.summary`. The Worker and the page have always used it as the change note: migration 239 calls it the trail's "what" line, and D4712 makes it required on a new version. There was nowhere to put a summary without changing what `summary` means.

### The decision

**The column is `version_summary`.** It is a new, nullable `TEXT` on `advisor_deliverable_versions` (migration `202611141017_5959_deliverable_version_summary.sql`). `summary` keeps its meaning as the change note, so no reader changes.

| Canvas field | Column | Rule |
|---|---|---|
| Change note · required | `summary` | required on a new version, 422 `empty_version` (D4712, unchanged) |
| Document or URL · required | `link_url` | required on a new version, an https link (unchanged) |
| Summary · optional | `version_summary` | optional, trimmed, capped at 2,000 characters like `summary`; `null` when not given or blank, never `''` |

**The routes** (`routes/advisors_deliverables.ts`):

- **Writes.** `POST /me/deliverables` (version 1) and `POST /me/deliverables/:id/versions` accept `version_summary`.
- **Reads.** `versionDto` returns it, so it appears in these lists:
  - the advisor's list (`GET /me/deliverables`, on `latest_version` and the version trail);
  - the client's received list (`GET /received/deliverables`).

**Written once.** No route changes a version that exists (D4712), and the database enforces this for the new column. The trigger `advisor_deliverable_versions_summary_immutable` refuses any UPDATE that changes `version_summary`, with `version_summary_immutable`. The INSERT is the only write. `PATCH /me/deliverables/:id` updates only the work product's own row, as before.

**Existing rows.** Nothing is backfilled. A version written before the migration reads `version_summary: null`, and its `summary` is untouched.

**A database that never ran the migration** is healed by `ensureAdvisorStoresSchema` (`services/advisorStoresSchema.ts`). This is the lazy bootstrap that baselined databases rely on (GOTCHAS: an ALTER is recorded without running under `--baseline`). It adds the same column and, once the column exists, the same trigger.

### Not in scope

- Any frontend change.
- An edit route for an existing version.
- The Ready wiring, which stays on #4833.

### Tests

`cloudflare-worker/test/advisor_deliverable_version_summary_5959.test.ts` has six tests:

- **Read back.** Given on create and on a new version, the summary comes back trimmed on the advisor's list and on the client's received list. Not given, or blank, it is `null`.
- **The cap.** It is capped at 2,000 characters.
- **The change-note rule is unchanged.** A version with a summary but no note, or with no link, is still refused 422 `empty_version`, and nothing is written.
- **A pre-migration row** reads `null`, with its note unchanged.
- **Written once.**
  - `PATCH`, ready and send do not change the summary, whatever body they are given.
  - A direct UPDATE is refused by the trigger.
- **Healing.** An unmigrated database is healed with the same column and trigger, and the migration file carries both.

The neighbouring suites pass unchanged: `advisor_deliverable_ready_5316`, `advisor_deliverables_scope`, `advisor_stores_bootstrap`, and every other Worker test file that reads the advisor stores.

**Mutation check.** Ten mutants were run, and all were killed:

- `versionDto` dropping the field;
- the INSERT binding the change note into it;
- `''` stored for an absent field;
- `''` returned for a null one;
- the note check reading the summary;
- the cap removed;
- the migration's trigger dropped;
- the bootstrap's trigger dropped;
- the bootstrap's column dropped.
