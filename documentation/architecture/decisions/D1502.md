### 1. The shape

A run is a **batch** (`deck_area_batches`) with its **steps** (`deck_area_batch_steps`), one step per line of the quote: an area's text, an image, a guard or vision check, a critique pass or a retry.

- **Class.** `areas` is the selected areas. `deck_build` is a whole deck from New deck. This is option (a) on #3753: one runtime and one table, with a class column. It has no second runtime.
- **One active run per deck.** The partial unique index `deck_area_batches_one_active` enforces it. A `deck_build` run counts as one. A second run on a busy deck is refused with `deck_busy`.
- **`idem_key` is unique.** The same Idempotency-Key is the same run, whether it is a retry while the run is going, two requests at once, or a request after the run has ended. The same key on another deck, or from another member, is refused with `idempotency_key_reused`.
- **A run and its plan land in one D1 batch** (one transaction). A replayed request never sees a run without its steps, so it can never settle a run at 0 before its plan exists.
- **A step keeps its request and what it wrote.** `input` is the step's request (JSON, at most 16 KB; more is refused `step_input_too_large`) and `result` is its variant (JSON, at most 64 KB). A member who closed the tab finds the run's proposals waiting. A step that `rebuild` marks `done` from its usage row charged, but its variant was never written, so its `result` is null.

### 2. Money: one quote, one parent hold

- `admit` takes ONE hold for the whole quote (`reserveBatch`). The hold is keyed `deck-batch:<Idempotency-Key>`, so a retried request replays the same hold and never takes a second one.
- When a request loses the race to another request with the same key, it does not release that hold: the hold belongs to the run that won. A hold that no run holds, because the deck was busy, is given back.
- Each step runs through `aiRouter.run` with `parentHold: {uid, userId}`:
  - The router takes no hold of its own.
  - It records the step's charge against the parent (`ai_usage_logs.reservation_uid`, with `record_ref = deckstep:<uid>:<seq>`).
  - It does not settle.
  - A parent hold of another member is refused as `misconfigured`.
- A step's charge is clamped to its line of the quote. **The quote is the most a run can cost.**
- The run settles the parent hold **once**, at the sum of what its steps charged, when it ends: done, cancelled or failed.
- Cancelling after 1 of 6 areas charges 1 and releases 5.

### 3. Finding: a long run outlives the five-minute hold

`HOLD_TTL_MS` is 300 000 ms. Every budget read releases expired holds at cost 0, so a whole-deck run longer than five minutes would lose its hold partway through. Its later steps would then charge against a released hold.

`extendAiReservation(env, reservation, now)` moves a pending hold's `expires_at` forward. The runtime calls it before every step. The hold therefore lives as long as the run keeps making progress, and a run whose driver has died still expires five minutes after its last step.

### 4. Steps never repeat

- A driver claims a step with a conditional `UPDATE … WHERE state = 'waiting'`. If two drivers run at once, the second claims nothing and stops, so each step runs once.
- A step that is `done` is never run again.
- `rebuild(uid)` restores a run whose driver died. For each step left `running`:
  - if a usage row with the run's hold and the step's `record_ref` exists, the step charged, so it becomes `done` with that charge;
  - otherwise it goes back to `waiting`.

  `rebuild` repeats nothing that charged.
- A failed step never sinks the others. It is `failed` with its `error_code`, and the run goes on.

### 5. The contract every implementation passes

`DeckGenRuntime` (`services/decks/genRuntime.ts`) has five methods: `admit`, `startBatch`, `cancel`, `status` and `rebuild`.

`cloudflare-worker/test/deck_gen_runtime_contract.test.ts` runs the same ten checks over every implementation in `IMPLEMENTATIONS`:
1. The quote is the parent hold and the settled maximum.
2. The same key twice, including two drivers at once, is one run with one hold and one charge.
3. A retry while the run is going is that run, and the key on another deck holds nothing.
4. A busy deck refuses a second run.
5. Cancelling after 1 of 6 charges 1.
6. A failed area does not sink the others.
7. A crash plus `rebuild` repeats nothing.
8. A run past five minutes keeps its hold.
9. The events carry what pd2b draws: card, element, model or "No model · free", state, seconds, cost, and the running charged-of-held.
10. Each step keeps its request and what it wrote.

An eleventh check covers the router's `parentHold`.

`IMPLEMENTATIONS` holds `D1GenRuntime` and, from part 2, `DeckGenRoom`; the Queue fallback (B9) joins it. Every check was mutation-checked against the code it guards.

### 6. `DeckGenRoom`: one Durable Object per deck

`durable-objects/deck-gen-room.ts`, bound as `DECK_GEN_ROOM` and named `deck:<id>`. It implements `DeckGenRuntime` over the same D1 tables as `D1GenRuntime`, and adds what only a long-lived object can.

- **It drives the run, not the request.** `/admit` admits and sets an alarm. `alarm()` drives each active run with six drivers at once, in slices of ten minutes, and re-arms until the run ends. Closing the tab stops nothing.
- **Drivers share the work safely.** A driver that loses a step's claim looks for the next one. Only the driver that closes the run settles it and emits `batch_done`.
- **It survives its own restart.** The first alarm in a fresh instance rebuilds each active run from D1 (§4). A step that charged is done; one that did not goes back to waiting; nothing repeats. Cloudflare retries an alarm that throws.
- **It streams.** `/events` is Server-Sent Events: a `snapshot` of the run, its recent events, then each event as it happens. Every event carries what pd2b draws per row, plus the running charged-of-held.
  - `area_busy` is pd9n's "Busy, retrying", with the retry and its wait.
- **Only the Worker reaches it** (`services/decks/genRooms.ts`), after the route's own access check. The member's id arrives in `x-deck-user`, and `/admit` refuses a plan in another member's name.
- **Nothing is admitted without the binding.** `admitDeckRun` answers 503 `runtime_unavailable`, because a run that nothing drives would hold the member's allowance and never finish.

### 7. `AiGovernor`: the caps are throttles

`durable-objects/ai-governor.ts`, bound as `AI_GOVERNOR`, one per account; the logic is `services/decks/aiGovernor.ts`. The caps are **per-step throttles, not a ceiling on a run's size** (spec change 3). A whole-deck run of 40 areas is admitted whole, and its steps queue for slots:

- at most 3 image, 6 text and 4 vision steps running at once per account (guard, critique and retry steps count as text);
- at most 2 of the account's runs drawing steps at once;
- a token bucket per model per account: 20 steps, refilled at 20 a minute, guard calls counted.

A lease expires after two minutes, so a driver that died holds nothing for long. The governor's state is in memory: an evicted governor starts empty, which costs a step at most a short wait.

### 8. Busy models back off, then fall back within the tier

`services/decks/stepExecutor.ts` is the default executor.

- It takes a governor slot, then runs the step through `aiRouter.run` under the parent hold, with `rail.record = deckstep:<uid>:<seq>`.
- A 429, or Workers AI's 3040, backs off exponentially with jitter (1 s, 2 s, … capped at 20 s, each between half and the whole step) and retries twice.
- Then the step falls back within the same tier, to the element's other suggestions (D1503's `chain`), and records `fallback_used`.
- A refusal that is not the model's (a guard block, an invalid input, a spent allowance) ends the step without retry or fallback.
- A step's charge is what its usage rows say, summed by its record ref under the parent, so a busy retry's cost counts. The run clamps it to the step's line of the quote.
- A step with no task is a check the Worker does itself: it runs no model and is free.

### 9. The routes, the bucket and the client

- **Routes:** `GET /api/decks/areas/batches/:uid` (resume), `GET …/events` (the room's stream) and `POST …/cancel` (Stop).
  - The deck's readers read and follow a run. Only the member who started it stops it (403 `not_your_run`). A run the member may not read is 404.
  - A step's request never leaves D1, and a step's seconds are null until it ends.
  - Stop without a room stops the run in D1 and settles what started.
- **`deck_generate`:** 6 runs a minute and 20 an hour per member, failing closed. It covers the run-starting paths that A3 (#3764) and the one-click build (#3768) mount: `POST /api/decks/[:id/]areas/(generate|batches)` and `POST /api/decks/:id/build`.
- **Bindings:** `DeckGenRoom` and `AiGovernor` are in all three `wrangler.toml` tables under the new migration tag `v4-deck-gen`.
- **Client:** `frontend/src/lib/api/deckBatches.js`.
  - `deckV2Adapter.batch` and `cancelBatch` now answer through it, with D1511 contracts (`deckBatch.schema.json`).
  - The stream is read with `fetch`, since EventSource cannot send the Authorization header.
