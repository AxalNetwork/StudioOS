### 1. The shape

A run is a **batch** (`deck_area_batches`) with its **steps** (`deck_area_batch_steps`), one step per line of the quote: an area's text, an image, a guard or vision check, a critique pass or a retry.

- **Class.** `areas` is the selected areas. `deck_build` is a whole deck from New deck. This is option (a) on #3753: one runtime and one table, with a class column. It has no second runtime.
- **One active run per deck.** The partial unique index `deck_area_batches_one_active` enforces it. A `deck_build` run counts as one. A second run on a busy deck is refused with `deck_busy`.
- **`idem_key` is unique.** The same Idempotency-Key is the same run, whether it is a retry while the run is going, two requests at once, or a request after the run has ended. The same key on another deck, or from another member, is refused with `idempotency_key_reused`.
- **A run and its plan land in one D1 batch** (one transaction). A replayed request never sees a run without its steps, so it can never settle a run at 0 before its plan exists.

### 2. Money: one quote, one parent hold

- `admit` takes ONE hold for the whole quote (`reserveBatch`). The hold is keyed `deck-batch:<Idempotency-Key>`, so a retried request replays the same hold and never takes a second one.
- When a request loses the race to another request with the same key, it does not release that hold: the hold belongs to the run that won. A hold that no run holds, because the deck was busy, is given back.
- Each step runs through `aiRouter.run` with `parentHold: {uid, userId}`:
  - The router takes no hold of its own.
  - It records the step's charge against the parent (`ai_usage_logs.reservation_uid`, with `record_ref = deckstep:<uid>:<seq>`).
  - It does not settle.
  - A parent hold of another member is refused as `misconfigured`.
- A step's charge is clamped to its line of the quote. **The quote is the most a run can cost.**
- The run settles the parent hold **once**, at the sum of what its steps charged, when it ends: done, cancelled or failed.
- Cancelling after 1 of 6 areas charges 1 and releases 5.

### 3. Finding: a long run outlives the five-minute hold

`HOLD_TTL_MS` is 300 000 ms. Every budget read releases expired holds at cost 0, so a whole-deck run longer than five minutes would lose its hold partway through. Its later steps would then charge against a released hold.

`extendAiReservation(env, reservation, now)` moves a pending hold's `expires_at` forward. The runtime calls it before every step. The hold therefore lives as long as the run keeps making progress, and a run whose driver has died still expires five minutes after its last step.

### 4. Steps never repeat

- A driver claims a step with a conditional `UPDATE … WHERE state = 'waiting'`. If two drivers run at once, the second claims nothing and stops, so each step runs once.
- A step that is `done` is never run again.
- `rebuild(uid)` restores a run whose driver died. For each step left `running`:
  - if a usage row with the run's hold and the step's `record_ref` exists, the step charged, so it becomes `done` with that charge;
  - otherwise it goes back to `waiting`.

  `rebuild` repeats nothing that charged.
- A failed step never sinks the others. It is `failed` with its `error_code`, and the run goes on.

### 5. The contract every implementation passes

`DeckGenRuntime` (`services/decks/genRuntime.ts`) has five methods: `admit`, `startBatch`, `cancel`, `status` and `rebuild`.

`cloudflare-worker/test/deck_gen_runtime_contract.test.ts` runs the same nine checks over every implementation in `IMPLEMENTATIONS`:
1. The quote is the parent hold and the settled maximum.
2. The same key twice, including two drivers at once, is one run with one hold and one charge.
3. A retry while the run is going is that run, and the key on another deck holds nothing.
4. A busy deck refuses a second run.
5. Cancelling after 1 of 6 charges 1.
6. A failed area does not sink the others.
7. A crash plus `rebuild` repeats nothing.
8. A run past five minutes keeps its hold.
9. The events carry what pd2b draws: card, element, model or "No model · free", state, seconds, cost, and the running charged-of-held.

A tenth check covers the router's `parentHold`.
