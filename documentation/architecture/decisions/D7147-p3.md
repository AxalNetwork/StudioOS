## D7147 part 3 — Staging ids are written all at once, by a tool; the staging token reaches one database (#7147)

- **Status:** built on `agent/claude/7147-staging-ids`, 2026-11-18. The token decision is the owner's, on #7147 (2026-11-18: "require single-database scope").
- **Code:** `scripts/lib/previewIsolation.mjs` (`provisioningState`, the `partial` and `malformed` problems in `preflight`), `scripts/lib/stagingIds.mjs` and `scripts/staging-write-ids.mjs` (the writer), `scripts/check-preview-isolation.mjs` (prints the state), `cloudflare-worker/test/preview_isolation_4566.test.mjs`, `scripts/lib/stagingIds.test.mjs`; the runbook, `documentation/operations/STAGING.md` steps 5 and 11 and open questions 3 and 4.
- **Migration:** none. `wrangler.toml` is unchanged: the real ids come in their own PR once runbook steps 1 to 4 have created the resources.

### What is decided

- **All four or none.** `[env.preview]`'s D1 `database_id` and three KV `id`s are either all placeholders (before provisioning, or after a tear-down) or all real. A mix is `partial` and fails `check-preview-isolation --static`, which runs in `test:guards` on every PR. This is how "`--static` stops accepting placeholders once the ids are real" (#7147) is enforced without changing what main accepts before the ids exist.
- **Format.** A written D1 id must be a UUID and a KV id 32 hex characters; anything else is `malformed` and fails the same check.
- **The ids go in through `scripts/staging-write-ids.mjs`,** which touches only the four placeholders inside `[env.preview]`, refuses an id production uses (the static preflight's `shared`), a repeated KV id, or a different id over one already written (that needs a tear-down), and writes nothing when it refuses. With `--workers-subdomain` it also corrects `APP_URL` and `EXTRA_DEV_ORIGINS`, which name `studioos-preview.workers.dev`, a host that does not exist.
- **The staging token's D1 grant is scoped to `studioos-db-preview`.** Product-wide D1 Edit would let it write to `studioos-db`, and the owner did not accept that. If Cloudflare offers only the product-wide grant, the runbook stops at step 11 and reports on #7147 rather than installing it.

### Not decided here

- Who runs steps 1 to 4 and 6 to 11: the owner, from a shell, with the one-run provisioning token, as the runbook says. No workflow holds that token.
