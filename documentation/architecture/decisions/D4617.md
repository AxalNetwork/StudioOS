## D4617 — Preserve unknown billing and connector state (#4617)

Account screens treat a partial read failure as unknown, not empty. A billing
overview whose `degraded` list contains `payment_methods` therefore cannot say
that no card is saved, and an auto-reload response whose `card_unreadable` flag
is set cannot do so either. Token-pack loading, read failure and a successful
empty result remain three separate states.

The Billing page owns one overview read per customer scope. Payment details and
the embedded dashboard consume that read, and every successful card mutation
invalidates it, so the two views cannot remain on different snapshots. The
dashboard keeps its local read only as a fallback for callers outside the
Billing page.

Connector catalogue data remains readable when the member's connection list
fails. Catalogue rows carry `connectionUnreadable` through the list and detail
models; descriptions remain available, while connect, disconnect and status
claims wait for a successful connection read.

Focused frontend regressions cover degraded payment methods, shared billing
invalidation, either auto-reload response order, unsaved pack selection, pack
retry, unreadable auto-reload cards, and a successful catalogue paired with a
failed connection read.
