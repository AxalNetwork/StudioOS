### Trust and receipt authority

The actual runner job is defined in runner-executor.yml, the file the organization runner group's selected-workflow restriction must name. A caller's workflow SHA is not the reused executor SHA. The initial hosted identity step verifies an RS256 GitHub OIDC JWT using the issuer's fixed HTTPS JWKS endpoint before loading any repository admission code. Repository, original dispatch context, child run/attempt, main ref, audience, expiry, caller workflow and pinned job_workflow_ref are checked. Only a direct main executor dispatch or a future main runner-dispatch.yml wrapper is recognized. Callee refs must be full SHAs; no branch-local reusable workflow is referenced. The admitted immutable executor revision is checked against main ancestry through GitHub metadata.

The receipt interface is aligned with S32's ExecutionReceipt in PR #7890 (e873f9c122ffb18c5d28503eef2c49f318670492). It binds requestId, repository, logicalShard, original event/run/attempt/workflow ID, source SHA, original queue base SHA, sha256-prefixed plan digest, authenticated parent artifact ID where relevant, executor SHA, validated profile, lease generation, exact child run and attempt 1, and start/execution deadlines. All IDs are safe positive integers; timestamps are UTC epoch milliseconds. Original sourceRef is derived independently from GitHub metadata. Pull requests remain on the existing hosted path; this executor initially accepts push/main and proven same-repository merge groups only.

S32 and s39 agreed on an authenticated OIDC POST /ci/receipt with requestId/logicalShard as lookup keys and an authoritative `{receipt, active:true}` response. A caller's JSON or request ID is never authority. Receipt lookup occurs during admission and again immediately before execution, with all identities/deadlines rechecked. A completed successful submitter is permitted; a hosted parent step need not stay occupied. Missing, revoked, expired, unknown or superseded authority denies execution. Every merge-group constituent is independently checked for same-repository provenance; a same-repository top entry cannot conceal a fork below it.

**The production receipt reader and profile adapter are deliberately unconfigured in this stage.** The CLI therefore denies candidate checkout/execution even if someone sets RUNNER_EXECUTOR_ENABLED. Dependency injection is an internal test/integration seam, not an input or environment-based trust bypass. Concrete OIDC/coordinator adapters require the agreed deployment/recovery and profile contracts. S32 reported no verified live Merge Control deployment in the connected account; no endpoint, signature key or readiness proof is guessed here.

### Profiles, source and plan

The fixed profile IDs agreed for coordination are hosted, linux-x64 and macos-arm64. #7885 owns the central catalog and its public schema; this PR defines only validation of its resolved values. No second machine inventory or hostname list is added. Hosted resolves only to ubuntu-latest. Self-hosted resolution requires an approved organization group plus the AND of GitHub's actual OS/architecture labels, self-hosted, and studioos-worker-v1. The Mac is restricted to worker-1-of-6. Node 22 and Python 3.11 patch pins come from reviewed resolved profile data. Unknown/unverified workloads and platform mismatches fail closed. Unit fixtures do not establish live Linux or Mac compatibility.

Main push work consumes the exact authenticated parent plan bytes and digest; missing plans do not regenerate. Merge groups use the trusted equal-weight planner, with no timing file. Exact-once coverage and existing two frontend/six Worker shard identities remain unchanged. Runtime execution uses the fixed candidate test-drift-parts.mjs from the admitted SHA, as the existing CI/Mac harness does; artifact-supplied command text is not executed. Candidate checkout uses no persisted Git credentials, and the SHA and clean tracked worktree are checked immediately before tests. Original event/source/run/attempt and queue base are preserved in the test environment and diagnostics. Node/Python architecture/version and SQLite support are checked before dependency scripts and tests.

### Result, time and cleanup

Only the real test step, its exact owning job and owned run all passing count as success. For a reused workflow, the result also needs the retained callee attestation and exact wrapper SHA; wrapper/run metadata alone cannot prove the pinned test definition. A genuine test failure is always red. Trace upload is advisory and cannot turn failure into success. The existing driver preserves failure annotations and dependency traces.

Execution is bounded to the receipt deadline and the profile cap: self-hosted tests have 25 minutes within a 35-minute job; standard hosted tests have 40 minutes within a 45-minute job. Start budgets match #7887 (90 seconds external, 10 minutes hosted). An early start is clamped to the actual profile execution cap rather than inheriting extra queue slack. Cancellation and timeout terminate only the spawned process group, escalate promptly, and remain cancellation/timeout even if the child exits zero. Job directories use reserved child run/attempt identifiers. Cleanup refuses altered parents or ownership markers, removes only the owned source/control/temp directories, and never follows a source symlink into another run.
