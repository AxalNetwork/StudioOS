## D4701 — Pipeline: every actionable record reachable, an unreadable source is not a zero, live state converges (#4701)

**Pipeline audit, package 5 of 6, slot S22 · 2026-11-07.** No migration. Packages 1 to 4 and 6 (#4685, #4693, #4705 and the access and transition packages) are other issues' work and are not touched here.

### What was wrong, checked against `main` before any change

Each item was reproduced from the code at the audit commit `d85951ca9095` and again on `origin/main` (`1ee5b2c`) before it was changed. The Worker and client facts were all still true; the PR lists them one by one.

- **Leads: exclusions after the cap.** `GET /partner/pipeline/leads` read the newest 200 open needs and the newest 200 passes independently, then dropped passed needs in JavaScript. A firm whose newest 200 needs were all passed saw an empty list, and a pass older than its newest 200 fell out of the exclusion set so its need came back as a lead. `open_count`, `passed_count` and the strip were counted from the capped arrays.
- **Proposals, Negotiations, Retainers: fixed `LIMIT 200`, totals from the page.** Win rate, live value, MRR, stalled count and at-risk MRR were computed over the 200 rows read. The version, term and usage reads were scoped to the partner, not to the 200 parents returned.
- **Quote analytics: `LIMIT 1000`, and a failed read became zero.** `GET /quotes/analytics` read the newest thousand quotes and engagements, and `.catch(() => ({ results: [] }))` turned an unreadable engagements table into "0 active, 0 delivered".
- **Build desk list: `LIMIT 100`, silent.** `GET /pipeline/active` stopped at 100 with no cursor and no total. The deal drawer's tab labels counted a 30-snapshot, 10-gate window as if it were the history.
- **Board states.** The first read had no `catch`, so a failure left an empty board with an unhandled rejection; the drawer's failed read left its spinner up for good. Opening deal B while A was answering could draw A's rows.
- **Period requests out of order.** The Analytics zone set state when its request settled; pressing two chips could leave the slower, earlier answer on screen.
- **Vote updates.** The board listens for `vote_updated` and the vote writer never sent one. Where it was applied, the pushed tally replaced the viewer's own `my_vote`.
- **Board events dropped during a local move.** An event that arrived while any card was moving was skipped, and nothing re-read afterwards. A socket that dropped and came back never re-read either.

### What changed

**Worker.**

- **`util/keyset.ts`.** Keyset cursors (the last row's sort keys, never an offset), `listLimit`, `trimPage` (the `limit + 1` read) and `scanAll`, which walks a whole population in chunks and says when it could not finish. A malformed cursor is a 400, never a restart from page one.
- **Leads.** Both exclusions (already bid, passed) are `NOT EXISTS` in the WHERE clause, so a page is `limit` actionable leads. `cursor` pages the leads and `passed_cursor` the passes, each with `next_cursor` / `has_more`. `open_count`, `strong_fit_count`, `excluded_count` and `passed_count` describe every record, counted by walking the population in chunks; `totals_complete` says whether the walk finished.
- **Proposals, Negotiations, Retainers.** Keyset pages (Retainers in its display order: recorded retainers by renewal date, then engagements with none, newest first; the tie-break is `-engagement id`), whole-book totals from the same chunked walk, and version, term and usage reads bound to the returned parents through one `json_each(?)` list, still joined back to the partner so ownership stays in the query.
- **Quote analytics.** Quotes and engagements are read to the end in id-ordered chunks (a walk that cannot finish throws). A failed engagements read is `delivery: null` with `delivery_unavailable: true`; the quote figures, which did read, stay. An unreadable quotes table is an error, not an empty body.
- **Build desk list and drawer.** `/pipeline/active` answers `{ items, next_cursor, has_more, total }` (the body was a bare array; its three client callers were moved). `/projects/:id/detail` adds `metrics_total`, `gates_total` and `*_truncated`.
- **Votes.** After the row is written and the public tally is built, the writer publishes `vote_updated` with `{ deal_id, tally }` to the deal room and the overview room. The tally is `buildPublicTally`'s output, which has no per-user field: no comment, no voter, no anonymity flag, no `my_vote`. A failed publish never fails a committed vote.

**Client.**

- **`lib/pagedRead.js`** follows cursors to the end and returns one envelope with `complete` / `remainder_error`. A later page that fails keeps the rows read and the zones say the rest could not be read (`PartialRead`); a first page that fails throws.
- **`hooks/useKeyedRead.js`**: a read keyed to what it was asked about (period, company, deal), with a generation. A reply for an earlier key or generation is dropped, a different key shows loading rather than the previous key's data, a first failure is `unreadable`, and a failed background refresh keeps the data and sets `refreshError`. The Analytics zone is keyed to `period|company`; the deal drawer to the deal.
- **`pages/pipeline/useBoardSync.js`** owns the board list: loading, ready, refreshing, empty (a ready board with no rows), partial and unreadable are different states. A re-read requested during a local move is queued and runs when the last move settles; a move settling drops any read that began before it and replaces it; a burst of events costs one extra read; a socket reconnect (`useWebSocket`'s new `onOpen({ reconnect })`) re-reads.
- **Votes on the board.** A pushed tally is merged over the viewer's own `my_vote`, an older tally never replaces a newer one, and a tally that cannot be read says "Votes unavailable" instead of drawing nothing.

### Decisions worth recording

- **Totals come from a walk, not from a second set of SQL aggregates.** The figures that matter (a stalled count, utilisation, a fit score) are derived in JavaScript from rules the SQL does not hold. A second implementation in SQL would be a second definition that could disagree with the row. The walk reads the same rows through the same reader, in chunks of 200 and at most 250 chunks per request, and reports `totals_complete: false` rather than present a partial total as whole.
- **`/pipeline/active` changed shape instead of staying an array with headers.** A bare array has nowhere to say there is more. The three callers (the board, the Build desk, the unused investor hook) were updated in the same PR; the FastAPI mirror is dev-only and keeps the array, which `readAllPages` treats as one complete page.
- **The vote event is published to the overview room as well as the deal room.** `GET /pipeline/votes/:deal_id` already answers any authenticated user with the same aggregate for any deal id, so the push exposes nothing the read does not. Viewer-specific state and comments stay on the writer's response and the `include_comments` read.
- **Retainers' tie-break is the engagement id, not `created_at`.** A keyset needs a unique last key; `created_at` is not unique.
