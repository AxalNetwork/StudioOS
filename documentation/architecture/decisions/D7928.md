### Why the table, not the API

The issue asks for the published uncertainty. The API serves only the LABSTAT means, so it cannot carry a standard
error, and it needs a registration key, which #7928 does not authorise. The standard-error table carries mean, SE and
CV together and needs no key. The importer reads one workbook per batch and only its **All consumer units** column, so
every row is national (`USA`). The area-type table is used because its first column is all consumer units; its other
columns (urban, rural) are never read.

### What a row says

| Field | Value |
| --- | --- |
| metrics | per category `ce_<item>_mean` (USD), `ce_<item>_se` (USD), `ce_<item>_cv` (percent) |
| items | `total` (Average annual expenditures), `food`, `housing`, `apparel` (Apparel and services), `transportation`, `healthcare`, `entertainment`, `education`, `personal_insurance` (Personal insurance and pensions) |
| `statistical_unit` | `consumer_unit` (BLS's definition is in every row's limitations): never a household or person count |
| `scale`, `currency`, `price_basis` | `units`; USD and `current_prices` for mean and SE; no currency and `not_applicable` for CV |
| `geography`, `period` | country `USA`; the calendar year |
| `observation_status` | `estimate` (survey estimates with sampling error) |
| `vintage`, `published_at` | the workbook's `Last-Modified`; without one, a content hash and no date |
| `limitations` | the consumer-unit definition and survey notes; the mean row adds "Published standard error: … USD; coefficient of variation: … percent", or "not published" for either |
| key, series | `ce:us:<year>:allcu:<item>:<stat>`, `CE.US.ALLCU.<ITEM>.<STAT>` |

So the uncertainty is kept twice: as its own rows (queryable) and in the mean's limitations (never separated from the
value it qualifies). A revised SE therefore adds a revision of both the SE and its mean.

A blank cell (BLS suppression) stores **no row**, never a zero; text in a value cell stores no row; a category the
table does not carry stores no row. The report counts them (`suppressed`, `unknown_cell`, `not_published`). A
published `0` is a value and is stored.

### Layout the reader expects, and fails closed on

The first sheet (`xl/worksheets/sheet1.xml`), shared or inline strings; exactly one row with `All consumer units` in
a column after A; below it, each category's label in column A, followed by sub-rows labelled `Mean`, `SE`, `CV(%)`
(and `Share`, ignored). Labels are compared after collapsing spaces and dropping leader dots and a trailing footnote
marker. A requested label found twice, a statistic row repeated under one item, an error or boolean cell, a
malformed number, a missing sheet or header fails the whole batch with `provider_payload`; earlier rows are kept.

**Before the owner enables `bls-ce`, someone must** open a real calendar-year table and confirm (1) the file name in
`ceTableUrl`, (2) the row labels and sub-row labels above, (3) whether bls.gov needs a particular `User-Agent` for
automated downloads (the shared `providerArchive` sends none), and (4) the terms on the copyright page. If any differs,
change the importer in a new PR; the fail-closed reader means a wrong guess imports nothing rather than wrong values.

### Bounds

One request per batch: one calendar year from 2023 (the first with the suppression rule) to 2025 (the latest
release), one to nine categories, three statistics each (at most 27 cells, inside the writer's 40). Workbook capped at
2 MB, sheet at 8 MB and shared strings at 4 MB inflated, through the D7927 ZIP reader.

### Rollback

Revert the PR. The source row stays disabled (its forward fix keeps it so); nothing is imported until the owner enables it.
