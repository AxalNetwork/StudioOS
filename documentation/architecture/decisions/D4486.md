## D4486 — Distribution Channels and read-only connections (#4486)

Distribution's Channels tab reads `GET /api/grow/channels?project=` behind
the existing project read gate. Existing Grow writers retain their write gate
and actor audit. Another venture's channels, owners, activity and campaign
links never enter the projection. No provider is called and no connection is
changed by this read.

### Channel details and compatibility

Migration `202611041912_growth_channel_details.sql` applies once through the
ledger. Migration 462 already supplied a `kind` column with an older CHECK:
the migration preserves it as `legacy_kind`, adds the requested nullable
`kind` (organic, ads, newsletter, outreach, signups, partner), and maps only
content→organic, paid_search/paid_social→ads, outbound→outreach and
partner→partner. Other legacy values stay preserved and the new kind is null.
Old open tabs may still submit the old vocabulary; the writer preserves and
maps those values. New forms offer the new vocabulary. Purpose is nullable,
at most 140 characters. Owner is the active founder or an accepted, active
venture member, validated on create and change; another user is a 400.

Channel state and connection state are independent. The table's Status is
active (lavender), testing (amber), or paused (muted). It never infers a
connected account from a typed channel name. Connection cards separately show
connected (green), expired/reconnect (amber), error/unreadable (red), or
not_connected/not_offered (muted). Each explanation is platform-authored.

The latest activity comes from content item updates, attributed customer
contact captures, manual spend rows and Mercury channel spend facts. Customer
UTM attribution is scanned once for the venture; no matching captured contact
means null and a Not recorded reason. A failed source means null and an
Unreadable reason. Reach and Clicks have no source and are absent. Campaign
links read D4447's store; there is no second campaign store.

### Connection privacy and availability

Mailboxes, Mercury and interview channel connections belong to the caller,
not to a venture owner whose private account a teammate can inherit. Only
the mailbox's owner sees its address. The connection query selects safe
columns and returns a fixed projection, never a credential, raw configuration
or provider error text. Support sessions receive no private connection data.
Venture owner names are never email addresses; avatars use the existing public
headshot route, never an R2 key.

WhatsApp and Telegram are interview capture only today. Mercury is a read of
spend and results. Lovable shows the recorded prototype link status, which
does not grant publishing access. Publish destinations count as connected only
when the registry actually supports their provider.

LinkedIn API is `not_offered`, with “Needs LinkedIn’s approval”. Meta, X,
Google Ads/YouTube, TikTok and Beehiiv are `not_offered`, with “Not offered yet”.
Mailchimp, Resend and SMS are not connectable. Designs' sample accounts,
scopes, metrics and errors are never runtime data.

Connect/Disconnect open the existing Email or Connectors flow after the
shared accessible confirmation dialog. This tab never sends, posts,
disconnects, starts ads or moves money. Existing Add/Edit forms keep the
channel name's Ask target; kind, purpose and owner add no Ask target.
The tab uses the existing Distribution shell (#4484); it adds no sidebar.

### Validation

SQLite: venture isolation, owner membership, preserved/cleared details,
attribution, safe connection projections and failed reads.

column order, empty readings and the three existing tool doors.
