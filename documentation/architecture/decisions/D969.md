## D969 — Grow forms load their chips from the Worker's form-options (#3352)

- **Status:** built by S12 for #3352, 2026-10-26.
- **Basis:** `main` at `1e83809`.
- **Migration:** none.
- **Worker:** two small changes:
  - the feedback row carries `roadmap_item_ref`;
  - a typed KPI refuses a connected source.
- **What it closes:** the Grow form-options have answered since #1698, but no Grow form read them. Every `optionsFrom` set offered only its "None yet" chip or its hard-coded default:
  - a KPI's Source was always Entered by hand;
  - Edit feedback's Theme and Roadmap item were free text.

### 1. The loaders

Each loader calls `w.formOptions('grow', projectId, <module>)`, which is `GET /api/cycles/grow/modules/<module>/form-options`. It fills its form's `optionsFrom` sets, as Raise's forms do.

| Form | Module | Sets it fills |
|---|---|---|
| Log feedback | `product-improvement` | `theme_choice`: the themes, then New theme. `roadmap_item_ref`: None yet, then the roadmap items. |
| Enter a KPI | `revenue-and-traction` | `kpi`: a derived KPI is disabled with the Worker's reason, then the venture's custom KPIs and Custom. `source`: see §2. |
| Open a role | `team-expansion` | `team` |
| Add market | `market-expansion` | `geography_ref`: Nothing yet, then the geographies. |
| Edit feedback | `product-improvement` | `theme` and `roadmap_item_ref`, as §3 describes. |

Add channel, Add partner and Add obligation have no loader. Their modules' form-options carry no set those forms name in `optionsFrom`, so a read would fill nothing.

`growChips(list)` turns a form-options list into chips. A `disabled` choice stays disabled, and its `reason` becomes its meta line.

**While the read is out:** the dialog reads "Reading the choices…".

**A failed read:**
- the dialog says why and shows **Try again**, which reads again;
- nothing can be saved until a read succeeds;
- an empty set is never offered.

Try again is new in `FormLightbox.jsx`. It works the same for every cycle's forms.

### 2. A KPI's source

Revenue and traction's form-options lists four sources:
- Entered by hand;
- Stripe, which is enabled when an active Stripe integration exists and disabled with "Stripe is not connected." otherwise;
- Accounting and Bank, each disabled with its reason.

A connected Stripe now shows as a chip.

**A typed figure is a hand entry.** The Worker's KPI writer stores every typed figure as `source = 'manual'`, and a connected source writes its own figures. So choosing Stripe for a typed figure saves nothing:
- **The form** shows "A connected source writes its own figures. Choose Entered by hand to type one." (`kpiCheck`).
- **The Worker:** `enterKpi` refuses any `source` other than `manual` with a 400 on `source`, before anything is written. A body with no `source` is still a hand entry.

`kpiBody` now sends `source`, which is `manual` unless another chip is chosen.

### 3. Edit feedback: the field is `roadmap_item_ref`

**What the Worker accepts:** the Worker's feedback PATCH accepts `roadmap_item_ref`, a roadmap item's id. It reads the item's label from that id. Edit feedback now posts `roadmap_item_ref`, not `roadmap_item_label`.

**The feedback row:** `GET /api/cycles/grow/modules/product-improvement` now carries `roadmap_item_ref`, so the chip opens on the row's item. The Grow adapter passes it to the Edit.

**Theme:** No theme, the venture's themes, then New theme, which reveals a "Theme name" box. The PATCH takes `theme` as text.

**A stored value the read does not list stays a chip.** A field's new `keep(current)` adds the chip the Edit opened with when the read does not list it. Without it, saving would be refused with "Pick one of the choices". This covers:
- a theme the read does not list;
- an item linked by id that is not among the 200 items read, shown under its stored label;
- an item that was only ever typed, shown under its typed label. Its value is `__typed`, so the Edit sends no `roadmap_item_ref` and the typed label stays until another chip is chosen.

`validate` in `forms.js` counts a field's `keep` chip as a choice too, so a row's own values pass its Edit form before any read. D661's Worker test checks that for every Grow Edit.

**What an untouched save sends:** `sentOnly` sends a field the row carried or the founder changed. A row with no item sends `roadmap_item_ref: null`, which the Worker stores as no link.

### 4. The comments

These comments now describe the code as it is:
- the Grow header in `forms.js`;
- the KPI source note;
- Edit feedback's fields.

"Stripe shows here once connected." is gone from the KPI form.

### 5. UNVERIFIED until the owner's live check

- A venture with more than 200 roadmap items, whose linked item is not in the read: that the kept chip shows the stored label.
