### Built (2026-11-27)

Option A is built for Q1, Q2 and Q3, as the canvas draws them; each stays open for the owner.

- **One rule for "feeds".** `cloudflare-worker/src/services/connectorBinding.ts` `projectBinding` resolves the three scopes the sync itself enforces (`projectEnabled`, `syncGithub`): the account connection; its enabled company, whose owner still belongs to it; and, for GitHub, `config.project_id` equal to this venture with repositories chosen. It returns `no_company`, `company_off`, `other_venture`, `no_repo`, `failing`, `not_read`, `stale`, `no_items` or `healthy`; `effective`, true only when all three hold; what would feed after a sync, with no counts; the last good read; and Stale (Q3 A: from the latest failed sync, else after 24 hours). The frontend mirror is `connectorsModel.js` `ventureFeed`, read from the same `config` the connections list returns.
- **Last successful read of the venture.** A GitHub sync now returns `project_id`, and its log row keeps it (`syncLogPayload`). `lastGoodReads` takes the newest ok sync naming the venture, or an older untagged one only while the connection is bound to the venture and the row is newer than its latest `repositories_chosen` (which records the venture). One statement, in the Tools part only; the overview read gains none.
- **Reasons.** "This project has no company scope for connectors." is now `NO_COMPANY_REASON` everywhere (the Overview card, Systems, Tools, Code, Hosting and the record). Operating systems' Code system carries `binding`. With no GitHub on for the company, or no company, `code.account` names the viewer's own GitHub at account scope only.
- **Owner route.** The Overview card offers the owner (or an admin, as the move route allows) "Link to a company" → `/build/connect?project_id=…&link=company`; anyone else is offered nothing there. Connect a tool shows the owner Link to a company… (`LinkCompanyDialog`, on `POST /projects/:id/move`) and re-reads the venture after, so the setup continues with Use for {company} and Choose repositories. Anyone else reads the owner's name and can copy a link to this setup (Q2 A). Operating systems' Company not linked yet adds Link to a company you have.
- **Rows.** A connected tool that does not feed the venture never says "Feeds …" and never offers Disconnect as its action: Account only (no company), Use for {company} (company off), or Choose repositories with what will feed after a sync (no repository, or another venture). Each connected row draws the three scopes (`scopeLadder`).
- **Stop or disconnect (Q1 A).** The confirm offers "Stop using for {company}" first (`PUT /:uid/companies` without it, naming the companies that stay), then Disconnect from your account, naming every company it serves. `PUT /:uid/companies` now lets go of GitHub's `project_id` and `repositories` in the same batch when the new set leaves out that venture's company (`releasedConfig`), so later syncs are not refused with `github_project_not_enabled`.

Not built: BLS07's Review → Result as separate steps (the confirm is one inline review), the 390 px frames beyond the existing responsive rows, the Super Admin preview state, and a per-venture last-read date on the Connect a tool row (the connections list carries none; Operating systems › Tools shows it).
