## D5571 part 3 — AWS ECS/Fargate RunTask as the third external executor, disabled and unmounted (#5571)

**Status:** part 3 of #5571, the AWS ECS/Fargate adapter, released by the 2026-11-27 coordinator audit. Disabled by default and unmounted. No AWS account, IAM role, identity provider, credential, binding, route, consumer or deployment exists or is changed, and no task is run. No AWS API that touches an account was called while writing it; the request shapes come from the Amazon ECS API reference only. Azure (part 1, `D5571.md`) keeps first-live priority. It builds on the merged D5565 `ExecutorAdapter` and follows part 2 (`D5571-p2.md`): operator config whose unset capabilities refuse, an injected transactional start-reservation store, and a privileged credential seam that this module never looks inside.

### The adapter (`services/agents/awsFargateExecutor.ts`)

`createAwsFargateExecutor({ config, signer, fetch, starts, now })` implements D5565's `ExecutorAdapter` for one pre-provisioned ECS cluster and one registered task definition revision. Calls go to `https://ecs.<region>.amazonaws.com/` as JSON 1.1 (`X-Amz-Target: AmazonEC2ContainerServiceV20141113.<Operation>`):

| Contract call | ECS call |
|---|---|
| `create` | `ListTasks` (by `startedBy`, `RUNNING` and `STOPPED`) and `DescribeTasks` to find an earlier start; `DescribeTaskDefinition` on the configured revision; then `RunTask` with `count: 1`, `launchType: FARGATE`, a pinned `platformVersion`, `clientToken`, `startedBy`, private `awsvpc` networking, env overrides and attribution tags. |
| `get` | `DescribeTasks` on the task ARN; past the run's deadline, `StopTask` with reason `axal: deadline`. |
| `terminate` | `StopTask` with reason `axal: cancelled`. |
| `collect` | Read the task. ECS holds no artifacts; they reach the broker through D5565/D5567. |
| `cleanup` | Read the task. ECS has no per-task delete, so nothing is deleted (see below). |

**The image is pinned by the revision.** RunTask cannot override a container's image. The config names a task definition ARN with an explicit revision (`family:N`, never the latest), and revisions are immutable. `create` reads it and refuses with `capability_denied` unless it is `ACTIVE`, has one essential container whose image is `<registry repository>@<spec digest>` (`image_digest`), uses `awsvpc` and is Fargate-compatible (`task_shape`), and is big enough for the spec: task CPU, memory, and ephemeral storage (20 GiB when the revision sets none) (`cpu`, `memory`, `disk`). A refused revision sends no start and spends no key. The adapter overrides neither CPU nor memory, so the revision's size is the size that runs and is billed.

**No credentials reach the task.** A revision with a `taskRoleArn` is refused (`credentials`): a task role puts AWS credentials in the container through the metadata endpoint. So is a container with `secrets` or `environmentFiles`. The execution role, which ECS uses outside the container to pull the image and ship logs, is allowed. `enableExecuteCommand` is always false. The overrides carry four references and nothing else: `AXAL_EXECUTION_KEY`, `AXAL_RUN_ID`, `AXAL_EXECUTION_GENERATION` and `AXAL_MAX_DURATION_S`.

**SigV4 through an injected signer.** The adapter builds each request and hands `{ method, url, region, service: 'ecs', headers, body }` to the injected `AwsRequestSigner`, which is the broker's federated-identity seam. The broker assumes one role by web identity (the Worker's OIDC token through `AssumeRoleWithWebIdentity`), keeps the short-lived session credentials and signs. The adapter sends a request only if the returned headers carry an `Authorization` header and the same `X-Amz-Target` and content type it asked to sign. A refused or malformed signature sends nothing (`provider_auth_unavailable`). `fetch` is injected too, so nothing can reach AWS unless the host wires both.

**Networking and attribution.** `networkConfiguration.awsvpcConfiguration` takes subnets (`subnet-…`, at most 16) and security groups (`sg-…`, at most 5) from config, with `assignPublicIp: DISABLED`. `enforced_network_modes` stays empty, so every spec is refused for `network_policy`, until an operator has verified the routes, security groups and egress firewall. Tags `axal:tenant`, `axal:run`, `axal:attempt` and `axal:generation` go on the task for cost attribution. ECS deletes a task's tags when it is stopped (StopTask reference), so ownership never reads tags.

**Status mapping.** From `lastStatus`, plus `stopCode` once stopped: `PROVISIONING`, `PENDING` and `ACTIVATING` → `provisioning`; `RUNNING` → `running`. `DEACTIVATING`, `STOPPING` and `DEPROVISIONING` → `cancelling` when `stopCode` is `UserInitiated`. Otherwise they stay `running` (or `provisioning` when the task never started), because a task that exits on its own passes through them too, and D5565 allows no `cancelling` → `finished`. `STOPPED` (and `DELETED`) with `UserInitiated` → `cancelled`, with `deadline_exceeded` when the stop came at or after the deadline. With `EssentialContainerExited` → `finished` only when the one container's `exitCode` is 0; non-zero → `failed`/`non_zero_exit`; no exit code → `failed`/`failed`. `TaskFailedToStart` → `failed`/`start_failed`. `SpotInterruption` and `TerminationNotice` → `failed`/`interrupted`. Anything else (`ServiceSchedulerInitiated`, no stop code, a new status) is `unknown`, never a guess.

**Timeout (TTL).** Fargate has no task timeout: a task runs until it exits or is stopped. The deadline is the task's `createdAt` plus the `AXAL_MAX_DURATION_S` it carries (bounded by `task_timeout_max_s`). The adapter enforces it on `get`: a task that has not ended past its deadline is sent `StopTask` and reported `cancelling` with `deadline_exceeded`. A task whose deadline cannot be read is `unknown` with `deadline_unverifiable`, never `running`. So enforcement is only as prompt as the reconciler's polling (D5570), plus Fargate's stop grace (SIGTERM, then SIGKILL after the container's stop timeout).

**Ambiguous outcomes:**
- **The client token covers an immediate retry only.** RunTask's `clientToken` returns the original result for a retry with identical parameters, and raises `ConflictException` for different ones. Its TTL is 24 hours or the task's lifetime plus one hour, whichever is shorter (Amazon ECS "Ensuring idempotency"). The token is the SHA-256 hex of the cluster ARN and the execution key (64 characters, within the 33–126 range). A lost answer (a dropped connection, a 408, `RequestTimeoutException`, a 5xx, an unreadable 200) is resent once, byte for byte, re-signed, seconds later, well inside the TTL. ECS then answers with the task the first send placed.
- **Late retries are never sent.** After that one resend, or on any later `create` for a key whose reservation is already held, nothing is sent again, because the token may have expired. The start is `unknown` with `start_ambiguous` on a `pending:<key>` ref. `get` locates it with `ListTasks` filtered by `startedBy` (`axal-<the same digest>`, `startedBy` being the only filter ListTasks then allows), for `RUNNING` and `STOPPED`, following `nextToken` for up to 20 pages each, then `DescribeTasks`. An empty list is not proof that nothing landed, and ECS forgets stopped tasks after at least an hour.
- **Ownership.** A task is this ref's only when its ARN is `arn:aws:ecs:<region>:<account>:task/<cluster>/<32-hex id>` in this cluster, the id matches the ref, and its `clusterArn`, `taskDefinitionArn`, `startedBy` and `AXAL_EXECUTION_KEY` env override all match. Anything else is `execution_not_authorized`. A 200 from RunTask describing a task that fails this check is `start_ambiguous`, not trusted.
- **Conflict.** `ConflictException` means the token is already bound to another request's tasks. That is `start_ambiguous`, located by key, never retried under a new token.
- **Reservations.** As in parts 1 and 2. The RunTask request is signed before the key is reserved, so a signer that refuses spends nothing. A failed reservation refuses before any start. Definite refusals (`ThrottlingException`, access and token errors, `InvalidParameterException`, `ClusterNotFoundException`, `Platform*`, `UnsupportedFeatureException`, other 4xx) and a 200 that placed nothing and listed `failures` (capacity, `provider_capacity`) are recorded, and a retry returns `start_generation_refused`. Two tasks with one key are `duplicate_execution`.
- **Cancel.** StopTask is safe to repeat. A dropped or 5xx stop is `unknown` with `stop_ambiguous`. A `cancelling` or ended task is never sent another stop, and an unlocated task is not stopped until it is visible.
- **Describe failures.** Only `MISSING` in `DescribeTasks.failures` counts as an absence. Any other failure reason is treated like a lost answer (`provider_unreachable`).

**Cleanup.** ECS has no per-task delete. A stopped Fargate task's ENI is released by ECS during `DEPROVISIONING`, and the task record expires on its own after at least an hour. `cleanup` therefore proves that the one task this ref owns has ended and deletes nothing: never the task definition, the cluster or another task. A task ECS no longer knows (`MISSING`) is `{ cleaned: true }`, so cleanup is idempotent. A read that fails, or a task that has not ended, is `cleanup_not_terminal`.

**Fails closed.** Each capability comes from operator config, and an unset one refuses with D5565's typed `capability_denied`. That covers network mode, hostile-code isolation (operator attestation only, even though Fargate runs each task in its own microVM), checkpoint restore (off), duration, regions, CPU, memory, disk and concurrency. GPU is false: Fargate has none. Config validation refuses a region outside the commercial `arn:aws` partition, an unrevisioned task definition, ARNs in different regions or accounts, the `LATEST` platform version, an image tag, and empty subnet or security-group lists.

**Errors.** The JSON 1.1 `__type` is read without its namespace, and provider text never is. `AccessDeniedException` (400 on ECS, 403 as a common error), `ExpiredTokenException`, `UnrecognizedClientException`, `IncompleteSignature`, `NotAuthorized`, `InvalidClientTokenId`, `OptInRequired`, 401 and 403 → `provider_auth_refused`. `ThrottlingException`, `LimitExceededException` and 429 → `provider_quota`. Other 4xx → `provider_rejected`. 5xx → `provider_unavailable` on reads, ambiguous on writes.

**Cost.** Without priced rates, `estimate` refuses with `estimate_unavailable`, never 0. With rates it bills the revision's vCPU and GiB (the configured `cpu_max` and `memory_mb_max`, which Fargate bills whatever the spec asks for) over `max(60, max_duration_s)` seconds, for Fargate's one-minute minimum, and marks the figure unmeasured. Ephemeral storage above 20 GiB is not priced here.

### Live-account facts only a real account can settle

These need an owner-authorized AWS account and region:
- that `DescribeTasks` returns `overrides.containerOverrides[].environment` as sent, for running and stopped tasks (ownership depends on it; if it does not, every lookup fails closed as `unknown` or `execution_not_authorized`, never misattributed);
- that a RunTask retry with the same `clientToken` seconds later returns the original task, and whether a 200 that placed nothing (`failures`) binds the token so that a later identical request repeats that failure;
- the exact `__type` and status ECS sends for throttling, a revoked role, an expired session and a token conflict, and whether `ConflictException` carries `resourceIds`;
- whether `ListTasks` with `startedBy` and `desiredStatus: STOPPED` lists a task stopped by `StopTask` and for how long, and how long `DescribeTasks` keeps a stopped task (documented as at least one hour);
- the `stopCode` and `exitCode` a deadline stop, a user stop, a non-zero exit, an image-pull failure and a capacity failure actually report, and whether `stoppingAt` is set on a user stop;
- whether StopTask on an already-stopped or `MISSING` task answers 200 or an error;
- whether attribution tags appear on Cost Explorer usage for tasks that were stopped (StopTask deletes tags), or whether cost allocation needs `enableECSManagedTags` or `propagateTags: TASK_DEFINITION` instead;
- task start latency (ENI provisioning plus image pull) and real per-second billing in the chosen region;
- the egress posture the subnets, route tables, security groups and Network Firewall actually enforce, for `enforced_network_modes`;
- Fargate's isolation for hostile code in the chosen platform version, for `untrusted_code`.

Until then, the configured revision bounds every spec, `enforced_network_modes` stays empty and estimates stay unavailable. No live-migration claim is made; `checkpoint_restore` stays off.

### AWS runbook (staged; enabling is the owner's)

1. **Account.** A dedicated account (or one under an organization's sandbox OU) for workspace runs. One ECS cluster per Axal region in a matching AWS region, Fargate capacity only, Container Insights on.
2. **Least privilege.** An IAM OIDC identity provider trusting the Worker's issuer, and one broker role assumable only by web identity with an audience and subject condition. Its policy allows, on the one cluster: `ecs:RunTask` (resource: the one task definition revision ARN, condition `ecs:cluster`), `ecs:DescribeTasks`, `ecs:ListTasks`, `ecs:StopTask`, `ecs:TagResource` (needed to tag on RunTask), `ecs:DescribeTaskDefinition`, and `iam:PassRole` for the execution role only. No task role exists. The execution role gets ECR pull on the one repository and CloudWatch Logs write on one log group.
3. **Image registry.** A private ECR repository with tag immutability and scan on push. The revision's image is set by digest; the adapter refuses a revision whose image is a tag or another digest. A new image is a new revision and a config change.
4. **Networking.** Private subnets with no internet gateway route. Egress through Network Firewall or VPC endpoints that deny or implement the allowlist, and a security group with no inbound rules. Set `enforced_network_modes` only after that is in place and tested.
5. **Metrics.** Task `createdAt`, `pullStartedAt`, `startedAt`, `stoppedAt`, `stopCode` and exit code, plus Container Insights, feed D5570's queue-wait, start p50/p95, error and cost-per-success figures.
6. **Cost.** Set `rates` from the region's Fargate price sheet, plus a budget alarm on the account. Until then, D5570 reserves the spec ceiling.
7. **Teardown.** Stop running tasks started by `axal-*`, wait for `STOPPED`, deregister and then delete the task definition revisions, delete the cluster, the broker role, the OIDC provider and the ECR repository.
8. **Emergency disable.** Set `enabled: false` (every call refuses before a request leaves). Or revoke the broker role's trust policy or attach a deny-all policy (every call returns `provider_auth_refused`), then stop running tasks with the console or CLI.
9. **Rollback.** Delete the module and the test. Nothing imports them.

### Later gates (not in this part)

The actual account, region and authority, with native isolation and conformance; the broker's web-identity signer as an implementation; the transactional reservation-store integration; the runbook as executed; a separate activation and cleanup proof. None is done or implied here.

### Tests

`cloudflare-worker/test/aws_fargate_executor_5571.test.ts` has fifteen tests. They run on a synthetic ECS endpoint that keeps tasks, honours `clientToken` (the same token and parameters return the original task; different parameters raise `ConflictException`), deletes tags on stop and answers `MISSING`, with a fake signer that records every request it signs. They use the same `specFixture` WorkspaceSpec as the Azure and Cloud Run tests. They cover:
- disabled refusals on all six calls, with nothing signed or sent, and config validation;
- the exact RunTask body: digest-pinned revision, private awsvpc, token, `startedBy`, tags, four references and no secrets;
- every request signed for `ecs` in the region and sent exactly as signed;
- a refusing, unsigned or retargeted signer sending nothing and spending no key;
- each refused revision shape before any start, without spending the key;
- each fail-closed capability;
- one identical resend after each lost answer, landing one task;
- doubly lost starts and `ConflictException` located by key and never resent;
- an untrusted 200;
- duplicate tasks across list pages, stopped tasks found, and twelve concurrent adapters sharing one reservation;
- a lost reservation reply;
- throttling, capacity, revoked or expired identity and rejection on RunTask, ListTasks, DescribeTaskDefinition, DescribeTasks and StopTask, with provider text never copied;
- every status mapping;
- the deadline stop: sent once, ambiguous then repeated, reported as `deadline_exceeded`, and unreadable deadlines;
- cancel, ambiguous cancel and pending-cancel reconciliation;
- cleanup that deletes nothing and refuses wrong tenant, generation, region and path, plus non-`MISSING` describe failures;
- foreign cluster, task definition, `startedBy`, ARN, key and a swapped describe answer refused;
- unpriced estimates refused, and the one-minute minimum.

A mutation run of 60 single-line changes to the adapter (dropped checks, flipped mappings, a resend loop, signing after reserving, a public IP, `LATEST`, execute-command on, among others) was caught by these tests, 60 of 60.
