## D6996 — Titles, descriptions and canonicals for help, trust, /pricing/products and the Lab brief (#6996)

**Decision date:** 2026-11-23. **Scope:** the Open Graph registry, the prerender and validator scripts, the Help
Center's guide index and page head, the trust center's frame, `/pricing/products`'s frame and the sitemap. No
Worker, route, `wrangler.toml`, card image or guide body change. Part of #6976 (plan key X14). Builds on #6995
(X13) and #6861 (Help Center v2).

### What was wrong

- `/help` and its public guides had no registry entry and no prerendered file, so the static-assets fallback
  served them the prerendered `/`: the homepage's title, description and canonical.
- `/pricing/products` had the same fallback before JavaScript, and its page then called itself "Plans and
  pricing", next to `/pricing`.
- The trust center's five tabs were prerendered with their own entries, but the page's frame passed one title
  ("Trust center") and one description to `usePageMeta` for every tab, over the registry's, so every tab's head
  read the same once the page loaded.
- `/spinout-lab/brief` had since been given its own page by #6966 (its program map entry's `og`, prerendered
  through `scripts/lib/programCatalog.mjs`). This change adds nothing for it; the new test holds it.

### What changed

- **Registry entries** (`frontend/src/lib/ogRegistry.js`), as their own blocks: `/pricing/products` ("Products
  and token packs") and `/help` ("Help Center", `prefix: true`, so a guide page takes the company section card).
  Neither needs a new card image.
- **Help guides come from the guide index.** `frontend/src/pages/docs/helpMeta.js` (plain, no imports) turns a
  guide into `{ path, title, description }`: the title is the guide's own plus " · Help Center"; the description
  is the opening whole sentences of the guide's overview, the first paragraph its page draws, as many as fit in
  200 characters (never less than the first). `publicHelpRoutes(sections, PUBLIC_HELP_ANCHORS)` lists each public
  guide in index order. `scripts/lib/helpGuides.mjs` hands it the real index for `scripts/prerender-og.mjs` and
  `scripts/validate-og-tags.mjs`, so a guide added to `PUBLIC_HELP_ANCHORS` gets its own page and preview with no
  other edit. The index's imports now name `.js`, so plain Node loads it.
- **The same head after JavaScript.** `DocsLayout.jsx` calls `usePageMeta` with the guide's `helpGuideMeta` when
  the viewer can read it; an address with no readable guide names none and is `noindex`; the home and the
  directory take the `/help` entry. No pageview beacon, as before.
- **Trust tabs.** `SitePage` takes an optional `path`. The trust center's frame passes its pathname and no title
  or description, so each tab's head is its registry entry, before and after JavaScript, and moving between tabs
  rewrites it.
- **`/pricing/products`** renders `SitePage` with no title, so the registry entry names it. The page's own h1
  ("Plans & Pricing") is body copy and is unchanged here.
- **Sitemap.** `/pricing/products`, `/help`, the six public guides, `/trust` and its five tabs are added. Each is
  prerendered, canonical to itself and indexable.

### Rules this holds

- Every prerendered route that is not `noindex` has a title no other one has, and a canonical that is its own
  URL; only `/` carries the homepage canonical.
- Every sitemap URL is prerendered, canonical to itself and not `noindex`; a `noindex` route is absent (D4582).
- Descriptions state only what the page shows: the help guides' are their own overview sentences, the help
  home's and `/pricing/products`' name the sections those pages draw.

`frontend/test/route_meta_6996.test.mjs` runs the real prerender and checks each rule.

### Generated artifacts

No committed generated file changes. `/help` and the guides use the company section card and `/pricing/products`
has no key, so `frontend/public/og/*.png` and `frontend/src/lib/ogManifest.js` stay as they are
(`generate-og-images.mjs --check` passes); `docs/` is built, not committed (D529).
