### 1. What one run does

1. **Config.** `renderProbeConfig` writes `wrangler.s4870.<run>.toml` (gitignored): flat (no `[env.*]`), workers.dev,
   the `AI` binding only, production's compatibility date and flags, `ENVIRONMENT = "preview"`, and the gateway id and
   `AI_GATEWAY_PROVIDERS_ZDR = "on"` as vars **on this Worker alone**. `checkProbeConfig` refuses a config with a route,
   a production host, an `[env.*]` table, any other binding, a cron, the production switch, or a name other than
   `studioos-s4870-<run>`.
2. **Deploy**, then a per-run `PROBE_TOKEN` secret. Until the secret is set, the probe answers 403 to everything.
3. **Check.** `POST /check` makes **one** call, as `aiProviders.ts` `callGateway` makes it:
   - `openai/gpt-5-mini`, D4556's adapter input, a synthetic prompt ("Reply with the single word: ready"), 256 output
     tokens at most;
   - the router's option (`providerGatewayOptionFor`): log collection off, cache skipped, the gateway's retries off,
     ids only in the metadata (execution `s4870:live:<run>`, no account);
   - the payload header off, the raw response, read by `chatCompletions.read`.
   It then reads **that call's** log entry (`env.AI.gateway(id).getLog(logId)`), up to six times, three seconds apart.
4. **Verdict** (`liveCheckVerdict`). It passes only if all three hold:
   - **answered:** the call answered, the served model starts with `gpt-5-mini` and `keySource` is `Unified` (the pin
     `runGatewayTextModel` applies; ZDR applies to Unified Billing only);
   - **log (item 1):** the entry carries no payload (`logCarriesNoPayload`), or no entry was ever stored, which carries
     none either. A payload, or no log id at all, fails;
   - **cost (item 2):** the log's `cost` against D851's settled provider charge for the same usage at multiplier 1
     (`usdRatesBilledMicro` on the catalogue row's rates), within 1 micro-dollar or 1%. No cost or no usage is
     `not_recorded`, a fail.
   It also reports `reconcile_marked`: 0 or 1, whether `runGatewayTextModel` would have written this call's row with
   `reconcile: 'gateway_log'` (no usage, a pin mismatch, or a failure with `completion: 'unknown'`). That count goes
   into the switch-on PR, as S1 asked; it is reported and never fails the run.
5. **Teardown:** `wrangler delete`, pass or fail. A failed delete fails the run and names the Worker to delete by hand.

### 2. What the answer holds, and what it never holds

States, counts and amounts: the call's status, error kind and completion, the answer's length, the finish reason, the
pin's two fields, the usage, the reasoning tokens, the settled charge and rates, the log's state, tokens and cost, how
many reads it took, and the marked count. **Never** the answer's text, a log head, the gateway's metadata or a secret.
The test asserts this with a payload-carrying log entry and an answer whose text it searches for.

### 3. What it does not cover

- **Production rows.** With the switch off, production writes no gateway rows, so there are none to count. The
  marked count is this call's.
- **Item 5**, settling marked rows from the gateway log, still needs its own design (S1's note on #4870).
- **The switch-on PR (item 4)** adds `CF_AI_GATEWAY_SLUG_PROVIDERS`, `AI_GATEWAY_PROVIDERS_ZDR = "on"` and
  `AI_PROVIDER_GATEWAY_OPENAI = "on"` to `[env.production.vars]` once this run passes and the owner has posted the
  slug. It is opened for the owner to approve and is not merged by S14. D4556 §9 step 6 (OpenAI's sub-processor
  notice, #1008) stays the owner's.
- **Cost of a run:** one call capped at 256 output tokens, on Unified Billing credits.
