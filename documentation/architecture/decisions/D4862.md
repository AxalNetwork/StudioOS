## D4862 — Preserve Grow overview navigation and GR-04 deep links (#4862)

The [approved Grow design](https://github.com/AxalNetwork/StudioOS/issues/4861) names eight operating areas and makes Reporting a utility. Use the existing paths for those destinations.

| Area | Existing entry point | Related existing destinations |
|---|---|---|
| Overview | `/grow` | `/grow/update` for sharing an update |
| Focus | `/grow/focus` | `/grow/revenue-and-traction` for the cycle metric records |
| Customers | `/grow/customers` | `/grow/product-improvement` for feedback |
| Distribution | `/grow/distribution` | The Distribution tabs and `/grow/launch` |
| Talent | `/grow/talent` | `/grow/team-expansion` |
| Partnerships | `/grow/partnerships` | `/grow/partner-network` |
| Markets | `/grow/market-expansion` | Existing module records |
| Company | `/grow/durable-company-building` | `/build/brand` for the brand editor |
| Reporting | `/grow/reporting` | Duties, report and edit routes |

The Grow breadcrumb in Focus, Customers, Talent, Partnerships and Launch now returns to Overview. Previously it led to Build Team from Focus and back to Focus from the other four tools. The link uses the existing project query normalizer and takes its context from the current location while the venture data is loading.

The regression tests render each tool and check the destination with a canonical, legacy, invalid and absent project query. They also check the registered routes for the table, module record and creation paths, and Distribution and Reporting deep links. The router, authorization rules, Distribution subpages and stores are unchanged.

The overview layout, attention ranking, state-driven primary action, revised section navigation and desktop/phone design validation remain with #4862. This part covers the route mapping and overview return links.
