### Built

- PAY7 has an explicit-submit “Search product or detail” field, up to 200 characters. The Worker applies it before count/pagination and CSV export. It matches product names, including a price-only audit row whose product is held in the mirror, and recorded detail. Matching is case-insensitive; punctuation is literal, using bound `instr` predicates rather than wildcard SQL.
- `/api/admin/payments/change-log/admins` lists every current admin, including one with no payment log row. It returns ids and names only behind `requireSuperAdmin`. Its read/retry is independent of the log. A failure leaves the log visible and says the admin list could not be read.
- A filter/search change returns to the newest page. Clear filters clears the search input too. CSV uses the same search, requires the existing reason and records the export before sending it. The audit records that search was applied, never the free-text query.
- The shared header has New product and More. More contains Sync from Stripe, Token packs, Promo codes and Revenue. New product and Sync reuse D1013's dialogs; opening the menu or dialog writes nothing. Only the elevated Super Admin is offered a write. New product waits for a readable catalogue instead of treating a failed read as empty.
- Below 768px the product address is PAY12b's full page, with Back to Catalogue, the existing product sections and separate readable price cards. The catalogue and Payments header are not drawn under it. Edit and Archive sit in the phone header’s More disclosure; a sticky footer offers Add a price and Change a price, clear of the existing Eadwyn launcher. Change asks which live price; nothing is preselected and choosing it opens the existing dialog without writing. Token packs stay read-only and archived products cannot be changed.
- New read failures and the touched log/export failure paths return a safe retry sentence without raw database details.
