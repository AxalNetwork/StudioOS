## D6470 — scripts/ and scripts/lib/ list their files from each file's header, not hand-written rows (#6470)

**Context.** `scripts/README.md` carried 151 table rows and
`scripts/lib/README.md` 76, one per script, and every pull request that added a
script appended one. Of the last 396 commits on `main`, 33 edited the first
and 19 the second. GitHub's merge ignores the `README.md merge=union` rule
(D6465), so two such pull requests conflicted on the PR page and in the merge
queue even though a local merge was clean. The rows had also drifted: most sat
in a section they did not belong to ("The two you will run" held 31 rows).

**Decision.**

1. Both READMEs carry `<!-- index: generated -->` (D6465) and an empty
   `<!-- files:begin -->` … `<!-- files:end -->` block under a new "The files"
   section. `scripts/check-folder-docs.mjs` generates the list from each file's
   header comment, as #4104 does for routes and services: `--write` fills it in
   the working tree, `--clean` empties it, and it is never committed (D5612).
   Rule 6 fails a hand-written row naming one of the folder's files.
2. `scripts/lib/folderFiles.mjs` now lists `.sh` and `.py` files too.
   `hashHeaderLine` reads a shell or Python file's leading `#` block after the
   shebang (rule lines, shellcheck and coding pragmas and a bare path skipped),
   else a Python module docstring. A listed file without a header fails the
   build by name, the same rule #4104 set for modules. `headerComment` returns a
   file's whole header as text, for tests that used to read a README row.
3. Each of the 207 rows that described a file moved into that file's header
   comment as its first paragraph, word for word, where the header did not
   already hold it; so the generated list shows the sentence the README showed.
   A Python header goes in `#` lines before the docstring, because three scripts
   pass `__doc__` to argparse and one prints its last line. Five rows that began
   "Not an importer:" or "Not a check:", which only made sense in the section
   they sat in, were reworded to keep every word ("#4105 (not an importer):
   writes …"). Only comment text changed; no code.
4. A data file (`.json`, `.txt`) cannot take a comment and is not listed. Its
   row moved into the header of the script that reads or writes it, prefixed
   with its name: `flaky-tests.json` into `flaky-tests.mjs`,
   `runtime-ddl-baseline.json` into `check-runtime-ddl.mjs`,
   `test-clock-allowlist.txt` into `check-test-clock.mjs`, `hub-freeze.json`
   into `lib/hubFreeze.mjs`, `lib/railMatrixOverrides.json` into
   `build-rail-matrix.mjs`. The READMEs say so.
5. What stays hand-written: the prose sections, the rows that name no file in
   the folder (`npm run build`, `npm run deploy`, `migrate-d1.mjs --branch
   <code>`, the `ci/` scripts, `perf/worker-bundle-baseline.mjs`) and every
   subfolder (the guard requires a parent README to name its subfolders;
   `scan-remediation/` moved into the Subfolders table). The small sections
   whose tables emptied (live probes, deck harness, preview, branch deploy,
   design artifact, importers) name their files in one sentence, so the
   grouping survives.
6. Fourteen files had no header and no row (`lib/claimWip.mjs`,
   ten `lib/*.test.mjs`, `build-meeting-bot-image.mjs`,
   `process-canvas-fonts.mjs`, `post-merge.sh`); each got one.
7. The eight tests that read a row of `scripts/README.md` (npm audit gate,
   docs-assets closure, client error beacon, decision appends, magic-link
   insert probe, branch provisioning, unused imports, schema pair drift) now
   assert the README is `index: generated` and read the same phrases from the
   script's header comment.

**Not built.** Other READMEs (#6472, #5976); the `ci/` and `perf/` subfolders
keep their rows in `scripts/README.md`. Rewriting the prose sections.

**Verified.** A one-off comparison (kept out of the repository, its output in
the pull request) read every row of the two READMEs on `origin/main` against
the new headers: 202 rows verbatim in a header, 5 with every word in a header,
20 kept as hand-written rows, 0 lost. `scripts/lib/scriptsReadmeIndex6470.test.mjs`
copies each real folder into a throwaway git repository and runs the real
guard: a fixture `.mjs`, `.sh` and `.py` with a header pass and appear in the
generated list with no README edit; without a header they fail by name; a row
added by hand fails. Two fixture branches that each add a script under
`scripts/` merge cleanly with `git merge-tree` and merge attributes off
(`GIT_ATTR_NOSYSTEM`, `core.attributesFile=/dev/null`, `* merge=text` in
`info/attributes`), while the same branches appending rows conflict.
