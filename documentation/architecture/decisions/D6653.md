## D6653 — Independent encrypted file copies, run heartbeats and outside-preview restore proof (#6653)

D6428 remains the approved-record-class and primary-prefix-retention gate.
The optional independent step consumes its completed private runner bundle;
it cannot choose additional live prefixes. That step receives only a separate
outside-store writer credential and the owner's age public recipient, never
production source/archive credentials or the offline private key. Objects and
the manifest are encrypted before upload. Conditional checksummed puts and
metadata HEAD verification precede the immutable completion descriptor.
An existing object is accepted on retry only for the same plaintext digest.
No delete, list or content GET is available to that writer role.

The outside-account endpoint/bucket use D1's DR_COPY variable style. A known
production-account R2 endpoint is refused. Non-R2 account ownership cannot be
proved from its URL, so the owner must explicitly confirm external ownership.
Outside retention and counsel approval remain owner prerequisites. Disabled
copying emits a notice without touching the outside store; explicitly enabled
but incomplete configuration fails instead of silently skipping protection.

Each snapshot attempt writes an immutable metadata heartbeat plus a latest
marker outside the primary locked record prefix. It records time, outcome,
counts, newest source-key modification time, run identity and copy status.
Missing source metadata is explicit; failed snapshots have null counts rather
than invented zeroes. Independent receipts must match the primary snapshot
identity and counts. Heartbeats and cleanup run after failures as well.
Private plaintext staging is never an Actions artifact.

The existing hourly GitHub alert path reads only heartbeat metadata using a
dedicated reader, plus the latest completed snapshot workflow. A failure,
missing/invalid marker, missing required outside copy, or freshness older than
two daily intervals raises one file-backup episode through the existing
durable delivery mechanism. Healthy evidence closes it; unreadable evidence
cannot infer recovery. A failed workflow still raises when it could not write
its marker. Alert facts contain bounded counts/reasons, never file keys,
bucket names, credentials or member content.

The monthly file drill and explicit synthetic-proof dispatch use a separately
configured outside-account preview bucket and preview credentials. They
generate an ephemeral age key and a fresh one-record fixture, store its
heartbeat outside the account, remove the local source, then decrypt and
verify the record using only the outside store. They cannot select a live
member record and never update the real backup heartbeat. D1's existing drill
and #6654's suppression-aware live-restore prerequisite are unchanged.

Fixture tests cover copy/restore integrity, partial failure, role isolation,
unconfigured skips, receipt matching, heartbeat freshness/failure, unavailable
evidence, workflow isolation and once-per-episode alert delivery. Mutation
checks run on disposable copies, not the shared checkout.

No bucket, credential, retention policy or enable flag is provisioned by this
PR. Configuration metadata cannot be read by this integration (HTTP 403), so
its presence is unknown. The owner-provisioned outside-preview configuration
and a verified hosted proof remain acceptance gates; a local fixture is not
a hosted/live recovery claim. Keep #6653 open until the run link, outside
heartbeat and restore evidence are recorded without sensitive values.
