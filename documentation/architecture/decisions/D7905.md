## D7905 — Real container evidence before runner enablement (#7905)

This part supplies an inactive Linux candidate boundary and stops the existing
bootstrap's register/start and direct service path. A private operator boolean
cannot authorize persistent-host execution. Stop/status/removal remain available.
No self-hosted lane may be re-enabled until the remaining proof is reviewed.

Choose a separate Linux container per run. The trusted host owns its engine
client and exact container ID; candidate code receives neither the engine socket
nor listener paths. A local root-owned, non-writable policy must pin an already
reviewed image by content digest and the existing native runtime versions.
There is no implicit pull, guessed image, new provider, or operator-controlled
workflow command. Mac verification returns false: an ephemeral Mac VM adapter
is still required, and a private HOME/different username is not a substitute.

The container is non-root with dropped capabilities, no-new-privileges, separate
PID/mount/IPC/cgroup namespaces, read-only root, bounded memory/CPU/processes,
private tmpfs and exactly two read-only inputs: candidate source and exact plan.
No published port, extra host mapping, device, linked container or ambient
credential environment is accepted. Candidate installs and the fixed Worker
shard driver run together inside that container. A bridge network permits
package acquisition; it does not receive job/OIDC/provider credentials.

`verifyIsolation` inspects the actual engine state and host namespace identities
for the exact owned ID, profile and receipt tuple. It rejects unreadable engine
state and cannot be replaced by a flag in the receipt. Candidate execution has
an execution deadline and exact-ID cleanup in finally; cleanup independently
checks identity and never kills arbitrary host processes or a pool by name.

Remaining before enablement: wire this boundary into the trusted executor and
receipt transport, review/publish a pinned native runtime image, implement the
Mac ephemeral VM lifecycle, and run a real self-hosted credential-denial canary
under a fresh bounded owner-approved pilot. Deterministic engine fixtures are
not that proof. This decision changes no group restrictions, machine services,
provider resources or production application data. The legacy Mac workflow was
separately paused while addressing #7902 and must stay paused.
