### 2. Code readiness

`cloudflare-worker/test/whatsapp_readiness_d861.test.ts` runs the same
behaviour checks with `ENVIRONMENT` set to development, preview and production,
on isolated SQLite databases and queues. Every provider request is forbidden.

| Gate | Evidence |
| --- | --- |
| Webhook signature | A correct HMAC over the raw bytes passes; changed bytes, a missing signature and an unset app secret do not. The existing D754 suite also checks the public webhook's authentication before its off acknowledgement. |
| Consent | Awaiting, declined and withdrawn WhatsApp chats are not admitted to an interview and queue no audio; a given consent admits and queues. D754's integration suite covers the notice, the contact's own reply, late jobs, withdrawal and the session gates. |
| Voice cap | 50 successful reservations per connection per UTC day; the next is refused, the next day opens, and a failed counter read throws before a model can run. |
| Connection limit | 120 events per connection per minute; the next is over the limit. Another connection and a new minute have independent windows. |
| Pending retention | Messages older than 30 days and their empty pending threads are removed; the exact boundary and a newer message survive that sweep. Imported sessions are not a 30-day pending copy. |
| Encrypted pending text | A real pending write uses the column cipher, decrypts under its own row's AAD, and cannot be decrypted under another row's AAD. |
| Rollout | Missing or unrecognised configuration is canary; canary admits only Super Admins, off admits nobody, and on admits members through the existing role/plan guards. |

The minute event counter deliberately **fails open** during a D1 fault
(`events.ts`), unlike the voice-spend counter. This is the existing D684
tradeoff to avoid dropping customer messages. It is not a hard outage quota;
S1 accepted that limitation for rollout on #2506 (22 October 2026): it
sheds load after signature verification, while money-related controls fail
closed. Preserve the `[channels] event counter unavailable` log. No quota
behaviour is changed by this task.

The daily purge is wired into the Worker's 03:50 UTC scheduled handler.
Pending text is encrypted in `channel_thread_messages.text_enc`; admitted,
consented text uses the recorder's existing transcript store. This decision
does not claim every transcript field is column-encrypted.

The test contains isolated, in-process mutations that remove and invert the
gates and corrupt the encrypted write, followed by the restored scenarios.
They never edit a tracked file or access a real provider.
