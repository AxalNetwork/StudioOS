## D5897 — The Axal VC package catalogue's actions: create draft version, edit draft, publish and retire (L29) (#5897)

- **Status:** built 2026-11-16 by S06. Part 1 (b) of #5026, after part 1 (a) (D5896).
- **Canvas:** board L29 of `design/incoming/Licences and Contracts v2 Addendum Page.dc.html` ("Axal VC packages"): the header's "Create draft version…", the row actions (a Draft row "Edit draft" and "Publish…", an Active row "Preview pricing" and "Retire…"), and the Rules card ("Published versions are immutable", "Retire stops new offers").
- **No migration, no Worker change.** The writes are D5022's (`routes/admin_licence_packages.ts`, Super Admin on HQ, behind the write bar).

### 1. The client

`lib/api/licencePackages.js` gains five writes, one per route:

| Method | Route |
|---|---|
| `create(body)` | `POST /api/admin/licence-packages` (a new key's draft v1) |
| `draftNext(key, body)` | `POST /:key/versions` |
| `editDraft(key, version, body)` | `PUT /:key/versions/:version` |
| `publish(key, version, reason)` | `POST /:key/versions/:version/publish` |
| `retire(key, version, reason)` | `POST /:key/versions/:version/retire` |

### 2. Which row offers what

`rowActions(status)` in `packageDraftModel.js`, on the store's own status:
- **Draft:** Edit draft and Publish….
- **Active:** Retire…. Preview pricing, also on that row in L29, is part 1 (c).
- **Retired:** nothing. An active or retired version has no edit door, matching the Worker, which refuses to edit them (`package_version_immutable`).

### 3. Create draft version and the editor

**The header button.**
- With packages listed, it opens a chooser: each key, labelled with its next version number ("Venture Building (next is v3)"), and "A new Axal VC package (v1)".
- With none, it opens the editor for a new key.
- A next version starts from the key's **newest** version: its fields and programs, read through `GET /:key/versions/:version`. If that read fails, the editor does not open and the page says so.

**The editor** (`PackageDraftEditor.jsx`, on `ui/Lightbox`) is one dialog with three modes: new key, next version, edit draft.
- **Money:** typed in major units of the version's currency and sent as integer minor units through `lib/money.js`'s `parseMinor`. More decimals than the currency has is refused there, never rounded.
- **Multipliers:** the floor and ceiling are typed as decimals (0.8) and sent as ppm.
- **Programs:** registry keys, one per line, in order. No client reads the program registry's names yet (D5896 §2). A program kept from the source version keeps its `included_by_default` and `metadata`; a new one takes the Worker's defaults.

**What the browser checks.** Only what a body cannot be built without: an amount or a multiplier that is not a number. Required fields, ranges, dates, keys and unknown programs are the Worker's (`validatePackageInput`, `unknownProgramKeys`), answered in its own words.

### 4. Delete a draft: not built

The router has `DELETE /:key/versions/:version` (a draft only, with a reason). L29 draws no door to it, and #5026 does not list it, so the client has no method and the page has no button. A draft that should not be published can be edited, or left unpublished.

### 5. Publish and Retire

Both go through `LicenceReasonDialog`, which gains an optional `max`. The reason is **3 to 500 characters**, the Worker's own rule (`reasonOf`). The dialog says what will happen before it asks:
- **Publish:** "<name> v<n> becomes the version in force, and its programs and prices are frozen from then on." Then, when another version is active, "v<m>, active now, is retired: it stops being offered, and licences on it keep it until their review." With none active, it says none is retired.
- **Retire:** "<name> v<n> stops being offered to licensees. Licences on it keep it until their review. No version of this package is active until another is published."

### 6. After a write

Every write re-reads, success or not: the catalogue, each listed version's programs and the history. The chosen package becomes the one written.

The page then says what happened:
- **Success:** "Saved. … is a draft", "Published. … is in force. v<m> was retired.", or "Retired. …".
- **A refusal** (a 4xx the Worker answered): "<action> refused." followed by the Worker's sentence and each field error it named, in the editor's words for the field ("Programs: items is a list of 1 to 50 programs"). The editor stays open with what was typed.
- **Anything else** (5xx, timeout, network): "<action> may or may not have been saved." with the error, and "The catalogue was read again: what it shows now is what is recorded." **No failure says nothing changed.** Only the Worker could say that, and an unanswered request has not.
