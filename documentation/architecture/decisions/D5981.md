## D5981 — Server failures of authenticated API operations feed the section incident outbox (#5981)

Part of D5679. The observability middleware is the first request-path
producer for the D5979 outbox. After the response exists, its background task
passes four values to `services/sectionIncidentRequestProducer.ts`: the method,
the matched route pattern, the status and whether a user was authenticated.
Nothing from the request body, query, headers, path, user, tenant or exception
is passed.

The producer is off unless `AXAL_SECTION_REQUEST_INCIDENT_START_UTC` holds an
ISO UTC time ending in Z and that time has passed. A malformed value, a future
value or a branch Worker leaves it off. The variable is not set in any
environment. Unauthenticated requests and responses below 400 are ignored.

A thrown error or a 5xx is a `confirmed_impact` for the D5980 rules, which
return an episode decision. A 4xx is `expected_4xx`, which the rules count. Both
go to platform triage until #5682 maps route families to sections. The
producer does not use the user's role to choose a section.

The outbox row holds only the following fields:

- `episode_id`: `request-<24 hex>-<UTC day>`
- `fingerprint`: `server_operation-<32 hex>`
- `section_slug`: the slug returned by the rules
- `impacted_sections`: `[]`

Both hex values come from a SHA-256 of the method and route pattern. Each
observation is a random UUID. An operation therefore opens at most one Slack
thread per UTC day, and recurrences go to that thread.

The write is registered with `waitUntil` through `enqueueSectionIncident`.
The response is not delayed, and its status and body do not change. A missing
table, a storage error, a throwing rule set or a throwing outbox ends with one
fixed warning.

Sampling applies per isolate. At most `SAMPLE_LIMIT` (5) observations per
operation per `SAMPLE_WINDOW_MS` (60 s) are enqueued. Later failures in that
window are counted as `sampled_out`. The count-only events, 4xx and sampled
out, stay in an isolate counter keyed by section and reason. #5982 replaces
that counter with the durable digest. The day bucket, the window and the limit
are proposals for owner review.

Running a live preview event needs the owner's Slack provisioning, which is
recorded on #5679.
