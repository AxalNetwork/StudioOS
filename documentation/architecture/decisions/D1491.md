### 5. Core wiring (S28, 2026-11-04)

This section supersedes the pre-core waiting states above. D1490 and D1493
are merged. The owner answered A(a), B(a), C(a), D(a), **drop Luma**, F(a),
and **no attendee import until counsel signs off** on #3725. The displayed
channels are Eventbrite, Google Business Profile, LinkedIn and Facebook;
LinkedIn/Facebook use link posts, accounts are HQ-only, and Axal is the only
ticket ledger. The old Luma enum remains readable for historical records;
no new Luma selection or connector is introduced.

- SY1 reads the channel registry and credential-free HQ accounts. The default
  switch writes its account. Connect uses the registry's authentication kind;
  Disconnect and Reconnect explain that posted listings stay up and require
  confirmation. A missing adapter stays unavailable. No fake adapter ships.
- SY2a is a separate **Save channels** section on a saved public event. Draft
  choices and copy remain local until that action. Preview sends nothing and
  uses unsaved copy. Limits come from the Worker, with the same UTF-16 bounds.
  Blank overrides use event copy. On an already approved event, **Save channels
  and post additions** explicitly explains the existing core's immediate queue
  behavior. This section saves separately from the event form's Save; a new
  public draft must be saved before choosing channels.
- SY2b reads choices before enabling Approve. Its count/button says what posts;
  choices save before approval, and a refused choice prevents approval. No
  unreadable response becomes a zero-channel approval.
- SY3/SY4 are shared on the editor, host manage tabs and admin event desk:
  status, posted time, safe external listing link, sync/skip/failure reason,
  Retry, confirmed Withdraw, and explicit Refresh on read-only status cards.
  Posted overrides cannot be edited with the choice writer. Registration
  counts remain **Not recorded**; import is excluded.
- SY5 reads activity with event ID, channel and outcome filters, cursor paging,
  responsive rows and the shared detail Sheet. No date-range filter is offered:
  the mounted API has no date filter. SY6 reads and saves stored hosts/type
  defaults, keeps host accounts off, and removes deprecated Luma defaults on
  save. The existing Super Admin route gates remain unchanged.
- SY7 reads distinguish loading, empty and **Unreadable** with Retry. Stale
  event responses cannot replace a new event. Refused writes show no success.
  SY8 keeps D1493's existing saved-listing eligibility and proposal flow.
