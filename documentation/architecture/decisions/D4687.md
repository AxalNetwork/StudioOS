## D4687 — Restore the complete Practice journey (#4687)

The audit that opened this was pinned to `d85951ca9`. Every item was re-run against `1ee5b2c41`.

| Scope item | Reproduced on current main | What changed |
| --- | --- | --- |
| `GET /api/advisors/me/slots` hits `/:uid/slots` | Yes. `advisors.get('/:uid/slots')` was registered before `advisors.get('/me/slots')` in the one router, and Hono matches in registration order, so the owner calendar was a 404 "Advisor not found" (uid `me`). `/practice/sessions` showed an error in the grid. `index.ts` mounts `advisorsRoutes` once at `/api/advisors` and no registry module mounts a second router there, so the router's own order was the whole cause. | `ownSlotDto` and `GET /me/slots` moved above `GET /:uid/slots`. No other `GET /:uid/...` precedes a two-segment `/me/...` read. |
| Engagements empty-state button shows nothing | Yes. `setAdding(true)` was set, but the create form lived only inside the non-empty `ZoneBody` children. | The form is one element, rendered under the empty state when `adding`, and in its old place otherwise. |
| Delivery empty-state button shows nothing | Yes, same cause. | Same fix. |
| Delivery review loop unreachable with no work products | Yes. "Sessions you have held" sat in the non-empty children, so an advisor with a completed session and no work product could not file a review. | The review loop is one element, rendered in the empty state too. |
| No mounted control to publish availability | Yes. `api.createAdvisorSlot` was called only from `pages/advisor/advisory/OpportunitiesPage.jsx`, which is not mounted. The Sessions empty state linked to Opportunities, which holds no slot form. | `SessionActions.jsx` `PublishAvailabilityCard` on `/practice/sessions`, with the empty-state button opening it. It writes through the existing `POST /api/advisors/me/slots`. |
| Confirm | Did not reproduce. `OpportunitiesZone.jsx` is mounted and its Accept calls `confirmAdvisorBooking`. | Nothing; the Sessions panel points to it when requests are waiting. |
| Complete, no-show, cancel | Yes. The only callers were in the unmounted `advisory/EngagementsPage.jsx`. | `SessionLifecyclePanel` on `/practice/sessions`: Session held, No-show and Cancel session, the last two asking for the reason in the page. Closed sessions are listed as history, with a "Review it" link to Delivery for a held one. Failures say "unchanged" and never show the Worker's message. |
| Links to pages without the capability | Yes: Sessions sent "Publish availability" to Opportunities and "Run the lifecycle" and the booking history to Engagements; the block note said to cancel booked slots from Engagements. | Each now points to the Sessions control that holds it. Opportunities' empty state gained a link to `/practice/sessions#publish-availability`. The `/advisor/advisory/clients` and `/contracts` links still resolve to mounted routes and were left. |

No new client method and no migration: every call already had a mounted Worker route.
