### What it is

`documentation/operations/DECK_GRID.md` holds the four procedures HQ runs on the deck builder's generation path:
1. switch off a model;
2. refund a batch;
3. unstick a batch;
4. purge an image, including a DMCA takedown.

Each procedure starts with an HQ screen, then a Worker route, and uses D1 SQL only where no route exists.

### The acceptance fixtures

`cloudflare-worker/test/deck_grid_runbook_d1547.test.ts` reads the runbook's SQL out of the file and runs it. An edit to the runbook is therefore an edit to what is tested.

- **Every SQL block** prepares on the real migrated schema, with its named placeholders bound. The first run found an audit query naming a column `admin_audit_log` does not have.
- **Unstick, step 2.** A run left `cancelling` by an orphaned `running` step stays stuck when the member presses Stop. After the runbook's two statements (the same rule `rebuild` applies after a crash), Stop closes the run `cancelled` at what its finished steps charged. It settles the hold once, and the deck admits a new run.
- **Unstick, step 3.** Closing a run by hand ends it `failed` and frees the deck. Once the hold expires, it is released at zero on the member's next budget read.
- **Purge.**
  - The reads find the deck that names the image, and the same bytes under another uid.
  - The write makes `GET /api/decks/images/:uid/file` answer 404.
  - The undo serves the image again.
- **Citations.** The routes, refusal codes and constants the runbook cites are pinned to the code.

Mutation checks: each of these edits to the runbook fails a test:
- dropping the charge cap;
- `stopped` in place of `waiting`;
- a purge that does not set the state;
- a wrong copy lookup;
- a close without its active-state guard;
- a wrong `MAX_SLICES`.

### Choices

- **Unstick by the code's own path first.** The SQL settles only the orphaned step, the way `rebuild` does. The member's Stop then runs `finish`, which settles the hold correctly.
  - The hand close (step 3) is for a starter who cannot press Stop.
  - It settles at zero, because SQL must not write a hold or `ai_credit_ledger` row. The ledger is append-only, and its triggers refuse edits.
- **Refunds go only through the existing routes:** the review refund, or a capped adjustment. There is no batch refund route, and none is added under a docs task.
- **A purge sets the row `discarded` first.** The file route answers 404 before it reads R2, so serving stops at once. The R2 delete follows, because the sweep keeps any file a deck still names.

### Known gaps (not built here)

- HQ has no route to stop another member's run.
- HQ has no purge route. A manual purge writes no `deck_r2_tombstones` row.
- `PUT /api/admin/feature-flags` accepts switching off `@cf/meta/llama-guard-3-8b`, which the model policy route refuses. The test pins the current state, so a fix must update the runbook.
- The DMCA policy is a draft, and its designated agent is not registered.
