### Tables

Each table is keyed as a project subject keys a record: `record_kind` (`company` or `fund`) and the directory uid.

| Table | Holds |
|---|---|
| `research_record_names` | Type from a closed set: `legal`, `alias`, `brand`, `former` or `match_key`. Then language, source name and link, and a date. A match key is for matching and is never returned as a name. |
| `research_record_identifiers` | Scheme from a closed list: `gb_companies_house`, `wikidata`, `no_brreg`, `fi_prh`, `ee_rik` or `lei`. Then a value and its source. The list holds no Network directory id and no source-list id; the only Research↔Network link is `network_directory_research_links` (#7672). |
| `research_record_domains` | Host; `not_reviewed`, `reviewed` or `rejected`; reviewed on; reviewer; proof link and note. A review or a rejection needs a reviewer, a date and https proof (a CHECK). |

- The same name, identifier or host on two records is allowed: uniqueness is per record only. A shared value is a matching clue and never links or merges records; a read of one record names no other.
- A name or identifier from a staged source record cites it as #7742 defines: `source_key`, `provider_record_id`, `stated_row_hash`.

### Backfill

The migration uses the uid forms main's importers write, and no other rule:

| uid form | Importer | Writes |
|---|---|---|
| `ch-<number>` | `import-companies-house.mjs` | the Companies House number (upper case), and the stored name as the legal name |
| `q<digits>` | `import-wikidata-*.mjs` | the Wikidata id `Q<digits>` and no legal name |
| `no-brreg:<id>`, `fi-prh:<id>`, `ee-rik:<id>` | `import-register-companies.mjs` (PR #7559, merged, so its rules are in this migration) | the register's id, and the stored name as the legal name |

Every other company record, and every fund, gets no row and reads "Not recorded". The register rules cover #7559's 25,500 uids. Count per form after apply (counts only):

```sql
SELECT CASE WHEN uid GLOB 'ch-?*' THEN 'companies_house' WHEN uid GLOB 'q[0-9]*' THEN 'wikidata'
            WHEN uid GLOB 'no-brreg:?*' THEN 'brreg' WHEN uid GLOB 'fi-prh:?*' THEN 'prh' WHEN uid GLOB 'ee-rik:?*' THEN 'rik'
            ELSE 'not_recorded' END AS form, COUNT(*) AS n FROM research_company_directory GROUP BY form;
```

**Hand-over to #7316:** from this migration on, the #7316 compilers write their identifiers themselves.

**Domains are not copied from the website column.** With no domain row, a read gives the recorded website's host as `not_reviewed` (`from: "recorded_website"`). A row is written only by a review or an import.

### Access

An identity read answers exactly as that record's own profile route answers the same account.
- **Company:** the Companies rule (`admitsCompanies`, imported from `researchCompaniesAccess.ts`, not edited) is decided before the record is read. An account outside it gets `refuseCompanies`'s one 403 for an existing and a missing record, with no identity field. After that, D7819's served rows (`readCompanyByUid`) apply: a held record is served with its identity, and an excluded or withdrawn one answers 410 `record_not_served` with its state and sentence only.
- **Fund:** the fund catalogue's rule (signed in), then `getFund` over `SERVED_FUNDS`. This follows a moved fund uid one hop (the answer carries `moved_from`), and a fund of a withdrawn list answers 410 `source_withdrawn`. A member's private fund dossier has no identity here.

**Member view.** A member sees names (never a match key), identifiers, and each domain's review state, date and proof link. A member never sees the reviewer or the note.

**#7824 is not on main.** This read calls the Companies rule as main holds it, and #7824 registers the read in its enumeration test and access matrix and edits its gate line.

### Admin writes

Admin only. Each goes through `logAdminAction` (`activity_logs`).
- **Names and identifiers:** add, correct and remove, each with its source. Refusals: a missing record is 404, a duplicate on the same record is 409 `already_recorded`, and a scheme outside the list is 400.
- **Domain review:** `reviewed` or `rejected` with https proof; `not_reviewed` withdraws a review.
- **The website verification date.** When the record is a company and the reviewed host is its recorded website's host (lower case, no `www.`, no trailing dot):
  - a review sets `research_company_directory.website_verified_at` to the review time, as the column's first writer;
  - a rejection or a withdrawal clears it;
  - a review of any other host never touches it;
  - a fetched page is not a review.

  That UPDATE is why `services/researchRecordIdentity.ts` is on the D7819 guard's maintenance-writer list. The profile, the analysis subject and the export already read the column, and none is edited.
- **Nothing from Network enters by a join.** A domain review changes no `network_directory_entries.website`, and a Network website review sets nothing here. A name, alias or host known only from a Network source enters only through these admin writes with its source, or through #7674 or #7681 calling this service.

### Reviewed matching

`identityForMatching(env, kind, uids)` is exported for #7674's reviewed candidate matching and is not a member route. It returns each record's match keys, identifiers and reviewed hosts.

### Records for later migrations

- A migration that moves fund uids also moves these rows (`record_kind = 'fund'`, `record_uid`).
- Once PR #7687 is on main, a migration that moves or removes a company or fund uid also handles the bridge rows of #7672, which hold a foreign key on both uids.
- The website verification date is the verification date the review ledger's freshness dates use (D7819 `dates.verified`).

### Operator steps

These are API calls with an admin session; no screen is filed.
1. **Review a domain:** `POST /api/research/record-identity/company/<uid>/domains` with `{ "host": "example.com", "state": "reviewed", "proof_url": "https://…", "note": "…" }`.
2. **Reject a domain:** the same call with `"state": "rejected"` and proof.
3. **Withdraw a review:** the same call with `{ "host", "state": "not_reviewed" }`.
4. **Names and identifiers:** `POST /api/research/record-identity/<kind>/<uid>/names` (or `/identifiers`) with the type or scheme, the value and `source_name`; `PATCH …/<id>` corrects and `DELETE …/<id>` removes.
