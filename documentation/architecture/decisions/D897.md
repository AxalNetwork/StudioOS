- **Status:** built by S22, 2026-10-24 (#2677, part 3 of #2434). Builds on D896's sources (#2675) and D898's slide model (#2676).
- **Canvas:** PD2 (the fast path), PD3, PD4 (mounted), PD5 and PD6 of the owner's "Pitch Deck Studio" (`design/incoming/`).
- **Migration:** 542 (`outline_json` and `kept_slides_json` on `pitch_deck_proposals`).
- **Why:** #2434 wants a deck built from the venture's records, where every figure is a binding, Eadwyn writes only the words, and the founder keeps what they want card by card. Before this part, `POST /api/decks/generate` wrote a version straight away (`decks.ts:551` at the time), with figures formatted from `projects` columns and an AI draft that could restate them.

### 1. Nothing is a version until it is kept

A New deck is one `pitch_deck_proposals` row from its outline to its last kept card. Like every fill (D767), it replaces the venture's earlier unkept proposal.

- `outline_json` holds what the deck is for: `audience` (one of migration 539's `AUDIENCES`), `round_ref`, `length`, `prompt`, `start`, `rows`, `exclude`, `proposed_by` and `rail_proposal_uid`.
- `kept_slides_json` holds the kept card indexes, ascending.

`POST /api/decks/proposals/:id/keep-slides` takes three forms:

- `{ indexes }` adds to what is kept;
- `{ all: true }` keeps every card;
- `{ save: true }` writes the kept cards, in the proposal's order, as the new current version through `insertVersion`, for the outline's audience and round, and then deletes the proposal.

The whole-deck `POST /proposals/:id/keep` and the discard are unchanged.

### 2. Code fills every figure

`services/decks/newDeck.ts` is pure.

**The card catalogue.** It holds sixteen cards. The canvas's twelve are the standard deck, Short is six of them, and Full is fifteen plus "Appendix · Every figure". Each card names the D896 slots it shows.

**How a card is built.** The build reads `readSources` and writes each slot into the card twice, both times with D896's binding:

- a `metric` block on the 12 × 6 grid;
- a read-only `auto` field, so present mode and export draw it today.

A slot the store holds is formatted by unit (`valueText`). A slot it does not hold is `value: null` with a `Not recorded` binding, which reads "Not recorded on StudioOS" with its module link. It is never 0. Every built deck passes `modelProblems` before it is stored.

**What Eadwyn writes.** The model writes words only: a headline and a sentence per card. It sees the figures as read-only facts. Any of its strings that names a number is dropped and counted (`numberIn`): digits, currency and percent signs, and number words from two upwards. "One" is left alone. `wording.dropped` says how many strings were dropped.

**The guarantee.** Together these mean a generated deck holds no number that is not a binding. The Worker test walks every string of a built deck to check it.

### 3. A prompt is not a source

`figureRefusal` refuses a prompt that states a figure, before any run, so the refusal costs nothing and writes nothing. The answer is 422 `figure_in_prompt`, naming the module that records what the prompt claims. For example, "Say we have 200 customers" gets "Record paying customers in Grow › Revenue and traction". A figure no slot names links to the sources step instead.

The founder's own outline rows are held to the same rule, because their titles become card headings. PD4's unticked records go in `exclude`; an excluded slot is on no card and in no prompt.

### 4. The routes (`routes/deck_new.ts`, mounted before `decks`)

| Route | What it does |
|---|---|
| `GET /new/context` | PD3's read: the seven audiences, three lengths, the card catalogue and standard outlines, the active round with its Reviewed chip (the same counsel test as D896's round adapter), the member's own average charge per option, and the fast path's defaults. |
| `POST /new/quote` | What the outline or build run would hold now. Runs nothing. |
| `POST /outline` | One run with option `deck:outline`, kept to the catalogue. Eadwyn's outline is also a D780 draft (`ai_rail_proposals`, kind `draft`). |
| `POST /generate` | The build: one run with option `deck:build`, from an outline proposal or, on PD2's fast path, straight from the records for a seed fund. |
| `POST /proposals/:id/keep-slides` | §1. |

**Cost before the run.** `quoteRun` in `aiRouter.ts` is the hold's own model choice and arithmetic (`chooseModels` and `holdQuoteMicro`, which `run()` now calls too). So the price Build deck and Regenerate show is exactly what the run reserves, and the receipt settles at what the run used. Each answer carries its run's `charged_microusd` from its usage row; null means unknown (a hold waiting for review), never 0.

**AI off and refusals.**

- AI off on the page is not a stop. The outline is StudioOS's standard one, and the cards are figures with their titles, at no cost.
- A budget stop, a pause or the guard refuses as everywhere (`refuseRun`); out of tokens is 402, and nothing is written.
- A model that could not answer leaves the figures-only path, and says so.

**Who.** Writes use the deck routes' `projectOwned`: the venture's founders write, an admin reads only (D895), and New deck keeps /generate's plan gate (`studio`). Every write logs one `raise.pitch-deck` cycle row, never a figure: `deck_outline_proposed`, `deck_built`, `deck_cards_kept` and `deck_kept`.

### 5. The page (`frontend/src/pages/raise/pitch/NewDeck.jsx`, `newDeckModel.js`)

`/raise/pitch/new` is a static route, so `/raise/:slug/new` cannot take it. The steps follow the canvas's Audience, Sources, Outline, Build:

- **PD3.** Audience, round, length and prompt. The prompt is flagged as it is typed, with the Worker's own word list, held equal by a test. Start from offers blank, a past version, or a template; a template is the editor's own `apply-method` proposal, kept here the same way.
- **PD4.** D896's `SourcesStep`.
- **PD5.** Rows can be edited, dragged or moved with the arrows, deleted, and added from the catalogue. The chips show each card's slots, and the estimate sits beside the member's own average.
- **PD6.** What each card was filled from, what the run cost, and the proposal with Keep, Discard, Keep all and Save as version.

Every write opens a dialog that says what it changes and what it costs. Each run names its rail option while it is in flight (`deck:outline`, `deck:build` and `form:deck-template`). `?proposal=<id>` reopens a proposal; PD2's fast path in `PitchStudio.jsx` builds one and lands there. The studio's New deck links now open `/raise/pitch/new`.
