### 1. Nothing is a version until it is kept

A New deck is one `pitch_deck_proposals` row from its outline to its last kept card. Like every fill (D767), it replaces the venture's earlier unkept proposal.

- `outline_json` holds what the deck is for: `audience` (one of migration 539's `AUDIENCES`), `round_ref`, `length`, `prompt`, `start`, `rows`, `exclude`, `proposed_by` and `rail_proposal_uid`.
- `kept_slides_json` holds the kept card indexes, ascending.

`POST /api/decks/proposals/:id/keep-slides` takes three forms:

- `{ indexes }` adds to what is kept;
- `{ all: true }` keeps every card;
- `{ save: true }` writes the kept cards, in the proposal's order, as the new current version through `insertVersion`, for the outline's audience and round, and then deletes the proposal.

The whole-deck `POST /proposals/:id/keep` and the discard are unchanged.

### 2. Code fills every figure

`services/decks/newDeck.ts` is pure.

**The card catalogue.** It holds sixteen cards. The canvas's twelve are the standard deck, Short is six of them, and Full is fifteen plus "Appendix · Every figure". Each card names the D896 slots it shows.

**How a card is built.** The build reads `readSources` and writes each slot into the card twice, both times with D896's binding:

- a `metric` block on the 12 × 6 grid;
- a read-only `auto` field, so present mode and export draw it today.

A slot the store holds is formatted by unit (`valueText`). A slot it does not hold is `value: null` with a `Not recorded` binding, which reads "Not recorded on StudioOS" with its module link. It is never 0. Every built deck passes `modelProblems` before it is stored.

**What Eadwyn writes.** The model writes words only: a headline and a sentence per card. It sees the figures as read-only facts. Any of its strings that names a number is dropped and counted (`numberIn`): digits, currency and percent signs, and number words from two upwards. "One" is left alone. `wording.dropped` says how many strings were dropped.

**The guarantee.** Together these mean a generated deck holds no number that is not a binding. The Worker test walks every string of a built deck to check it.

### 3. A prompt is not a source

`figureRefusal` refuses a prompt that states a figure, before any run, so the refusal costs nothing and writes nothing. The answer is 422 `figure_in_prompt`, naming the module that records what the prompt claims. For example, "Say we have 200 customers" gets "Record paying customers in Grow › Revenue and traction". A figure no slot names links to the sources step instead.

The founder's own outline rows are held to the same rule, because their titles become card headings. PD4's unticked records go in `exclude`; an excluded slot is on no card and in no prompt.

**Cost before the run.** `quoteRun` in `aiRouter.ts` is the hold's own model choice and arithmetic (`chooseModels` and `holdQuoteMicro`, which `run()` now calls too). So the price Build deck and Regenerate show is exactly what the run reserves, and the receipt settles at what the run used. **AI off and refusals.**

- AI off on the page is not a stop. The outline is StudioOS's standard one, and the cards are figures with their titles, at no cost.

- A model that could not answer leaves the figures-only path, and says so.

**Who.** Writes use the deck routes' `projectOwned`: the venture's founders write, an admin reads only (D895), and New deck keeps /generate's plan gate (`studio`). Every write logs one `raise.pitch-deck` cycle row, never a figure: `deck_outline_proposed`, `deck_built`, `deck_cards_kept` and `deck_kept`.

### 9. Amendment for #3659 (S22, 2026-10-29): plan the story, then compose each card from its evidence

S33's ruling on #3659 for the owner, 2026-10-29: extend D897 rather than take a new number. The work uses D898 §8's v1 contract (#3658) and does not touch `slideModel.ts`. No migration: everything below runs on the existing quote, run, proposal, keep and save path.

**9.1 The story before the cards** (`services/decks/newDeck.ts`):
- **A message per card.** An outline row may carry `message`, the one thing the card must say, in words.
  - The outline run asks for it.
  - A founder's row that names a number in it is refused as a title is (`figure_in_prompt`).
  - A model's numbered message is dropped.
  - The build run is given each card's message and asked for a headline that states it.
- **The audience's order.** `AUDIENCE_EMPHASIS` names what each audience reads first. Those cards move up to just after the title, and the rest keep the length's order. A short deck takes its six from the audience's own list.
  - A Series A fund reads traction, unit economics and market first.
  - An angel or a pre-seed fund reads problem and team first.
  - A grant reads problem, solution and validation.
  - The lengths keep their counts (6, 12, 16).
  - With no audience named, the canvas order stands (`standardOutline(length)`).
- **The plan.** `planOf(rows, items)` gives each card its message and the records it rests on, with each record's state. Code fills it, never a model. The outline and build replies carry it as `plan`.

**9.2 Composition** (`cardOf`, `buildCards`):
- **The layout.** A card's layout is the one its evidence earns (`chooseLayout`, D898 §8.3). The evidence is counted by code:
  - recorded figures;
  - a recorded chart series with two points or more (`CARD_SERIES`: a connector's before the founder's typed one);
  - and a typed diagram a record placed (`CardVisuals.diagrams`, which #3660 supplies).
- **How each kind of figure is placed:**
  - **Traction** with a series is `chart_text`: the series bound by its key (`grow.mrr.monthly`), never typed points, with two figure tiles beside it.
  - **Text figures:** one too long for a tile (`team.skills`) is a bound line of text.
  - **A card with nothing recorded** is a statement. One line names what is missing ("Not recorded on StudioOS yet: …"), instead of a row of empty tiles. A label that itself names a number is left off that line.
  - **The appendix** is one bound line per recorded figure, four across.
- **What does not fit moves, never cut.** After composing, `fitProblems` runs on the card. A headline too long for its heading gives way to the card's title, and a sentence too long for its space goes to the speaker notes. `buildCards` reports any remaining misfit as a problem, like the slide model's.
- **Two sources that disagree** stay apart. The connector's series is plotted and the founder's typed one stays in the library; they are never blended.

**9.3 Routes** (`routes/deck_new.ts`):
- **Every reply carries `proposal_hash`.** A request that sends `base_hash` is refused 409 `proposal_changed` when the proposal moved since that read, so another tab's build or keep is never overwritten unseen. A request without it behaves as before.
- **`POST /api/decks/generate` on an existing proposal keeps its kept cards.** A kept card whose row is still the same card stays as kept, edits and all. The rest are rebuilt.
- **`POST /api/decks/proposals/:id/regenerate-card { index, base_hash? }`** is one `deck:build` run for that card's row. Only that card changes.
  - Refused: a kept card (409 `card_kept`), a card the outline no longer matches (409 `outline_changed`), and a stale read.
  - AI off rebuilds the card from records at no charge. A budget refusal changes nothing.
  - The quote is `POST /api/decks/new/quote { step: 'card', index }`.
- **The chart series** are read once per build (`readAllSeries`). A failed read draws no chart, never a made-up line.
