## D9038 — The workspace frame and reload-loop checks run in CI, and may not skip there (#9038)

- **Status:** built 2026-11-27 (S33).
- **Supersedes:** D529's sentence "`check-reload-loop` and `check-workspace-frames` run by hand after a build". They run in `ci.yml` job `visual` now.
- **No migration, no Worker route, no client method, no new dependency.**

### The decision

`ci.yml` job `visual` already runs in the pinned Playwright image, sets `PW_CHROMIUM_PATH` and builds the SPA. After its browser specs it runs three steps on that build:

1. `node scripts/check-workspace-frames.mjs`: every workspace route of the four licences, `/api/*` stubbed.
2. `node scripts/check-workspace-frames.mjs --fail-reads`: the same routes with every read answered 500.
3. `node scripts/check-reload-loop.mjs`: a `controllerchange` storm reloads a bounded number of times.

The job's limit goes from 30 to 45 minutes. It ran about 18 minutes on main before these steps.

**A browser check may not skip in CI.** `scripts/lib/browserCheck.mjs` decides how both scripts launch:
- `PW_CHROMIUM_PATH` is used first, then the sandbox's pin.
- A `PW_CHROMIUM_PATH` that names no file fails. It never falls back to another browser.
- With `CI` set, a missing `@playwright/test` exits 1. Off CI it prints SKIPPED and exits 0, as before.
- A browser that does not launch exits 1 everywhere.
- In `check-reload-loop`, a service worker that never takes control exits 1 under `CI`.

`frames` loads the frontend's Oxc loader hook itself, because its boards import `.jsx`. On main, before this, the script stopped at `kit.jsx` before opening a browser.

### What the first run found, and what changed

The default run failed 25 routes and `--fail-reads` failed 25. None was hidden.

- **App fix: two h1s on `/research/markets`, `/research/geographies` and `/research/companies`, every licence.** `MarketDirectoryZone`, `GeographiesZone` and `CompanyDirectoryZone` each drew an `h1` under the shell's own. They now draw an `h2`.
- **Stale check: the crumb.** It read "the bold element" as the zone. Where a page passes its own title, `WorkspaceShell` draws `bucket ‹ zone link ‹ title` (D6160). That made five Expertise zones read "Practice profile" against "Profile". The check now reads the crumb's second item, link or bold.
- **Stale check: the padding.** It measured `.min-w-0.flex-1`, the column before RailFrame (D556). That selector has since matched page content, so it reported `/expertise`, `/pipeline/proposals` and others. The check now measures the shell's own body: the child of `.fwr-frame-main` that holds the crumb.
- **Stub shapes.** `/contacts/book`, `/research/funds` and `/research/fund-directory` were answered with a bare `[]`, which the Worker never sends. `/network/relationships` (investor, advisor, partner) and founder `/research/funds` threw into the error boundary. Each now gets its real empty envelope, copied from the Worker (`bookOf`, `GET /research/funds`, `listDirectory`).
- **Bucket roots that cannot link to their zones.**
  - Founder `/validate` declares `zones: []`, so the rule cannot apply there.
  - With no venture, founder `/build`, `/raise` and `/grow` draw "There is no venture to show yet." in place of the bucket. This is a stated boundary like the add-on lock that the check already exempts.
  - Under `--fail-reads`, a root whose own read was refused and that says so, with no skeleton left, has given that mode's answer.
  - The default run still holds every other root to its links.
