## D658 — Eadwyn turns an interview into proposals for every Validate module; compare and ask, with citations

**Issue:** #1471, part of #1469 (D656). **Built by:** S09. **Migrations:** 439
(`439_validate_proposals_structuring.sql`) and 446
(`446_interview_structure_receipts.sql`). **Canvas:**
`design/incoming/Interview Session.dc.html`, step `review`.

### What was true

- **`validate_proposals` (214, widened by 246) was already Validate's store.**
  It is the AI-proposes / founder-decides store, with kinds `pain_tag` and
  `hypothesis`. Accepting claims the row with `WHERE id = ? AND status =
  'pending'` and writes through the module's own writer.
- **Three writes lived inline in `founder_validate.ts`,** with no function
  another path could call:
  - a pain's severity in one interview;
  - an interview's ICP fit;
  - a hypothesis ↔ pain-group link, which is what Validate counts as evidence.
- **The router had no task for structuring a transcript.**

### What is true now

**Migration 439 extends `validate_proposals`; it adds no second table.** The
new columns:
- `session_id`, nullable, because proposals from the rail have none;
- `cite_from` and `cite_to`, the cited span in milliseconds from the start of
  the session, matching the transcript segments' offsets;
- `edited_payload_json`, which holds the founder's edit while `payload_json`
  keeps what the model said;
- `run_id`, which groups one structuring run.

The cited passage itself rides in `citation_json` as
`{ kind: 'transcript', session_id, from, to, quote }`.

**The kinds** (`services/interviewStructuring.ts`, `PLACEMENT_KINDS`):

| Kind | Payload | Module | Accept writes through |
| --- | --- | --- | --- |
| `pain_severity` | phrase; Severe, Real or Mild | Problem discovery | `upsertPainSeverity`, storing the level itself (D659 widened the values) |
| `icp_fit` | strong, partial or none; reason | Customer research | `setInterviewIcpFit` |
| `evidence` | hypothesis, pain group, supports or refutes, strength (Anecdote, Pattern or Measured) | Experiments | `insertHypothesisLink` (refutes is stored as `contradicts`), then D659's `setEvidenceStrength` |
| `segment` | name | Ideal customer profile | D659's `writeSegment` (source `interview`, ref `session:<id>`) and `assignInterviewSegment` on the interview |
| `demand_signal` | need-to-have, would pay, LOI or pre-sale | Demand | D659's `writeDemandSignal`, arriving `to_confirm`: not counted until the founder confirms it |
| `competitor_mention` | name, context | Market intelligence | D659's `writeCompetitorMention`, on the project's competitor list; with no list it refuses (409) and the placement stays proposed |
| `market_fact` | fact, source | Market intelligence | proposed only: no store |

**The three writers moved into `_founder_validate_writes.ts`.** The manual
routes call them too: `PUT /interviews/:id/pain-severity`,
`PATCH /interviews/:id/evidence` and `POST /hypotheses/:id/links`. So an
accepted placement and a hand-typed value are the same row, by construction.

**Severity.** Pain severity is the canvas's three words, Severe, Real and Mild,
from the proposal to the row: #1472 (D659) widened `interview_pain_severities`
to hold them, reading the old `need` and `nice` as Severe and Mild.

**Evidence strength.** The Lab has no Anecdote / Pattern / Measured scale, so
strength is the canvas's own. It sits beside the five-interview bar
(`VALIDATION_BAR`) and does not replace it, and D659's
`hypothesis_pain_links.strength` stores it.

**The rules,** as pure functions:
- **No citation, no placement.** A placement must cite a span inside the
  transcript it was given, ending after it starts and overlapping at least one
  segment. One that does not is dropped before anything is stored, and the run
  counts how many were dropped.
- **Never truncated silently.** `chunkSegments` splits a long transcript on
  segment boundaries, with every segment in exactly one part. Each part is run,
  the placements are merged (one finding once), and `parts` tells the founder
  how many parts were read.
- **Ask.** `checkAnswer` keeps only the citations inside the transcript. An
  answer left with none is refused (`no_citation`), not shown.
- **Compare.** `alignRuns` lays two runs side by side by module.
- **The receipt.** Each model call adds a line: the step (Structured,
  Re-structured or Asked), the model that actually answered, the model asked
  for, whether the fallback answered, the cost and the tokens. Every call goes
  through `aiRouter.run`, which reserves and settles the D640 budget itself; a
  refusal on any part stops the run and stores nothing.

**`structure_interview` in the router.**
- The default is `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, falling back to
  `@cf/meta/llama-3.1-8b-instruct-fp8`.
- The alternates are, in order, the 70B,
  `@cf/meta/llama-3.1-8b-instruct-fp8-fast` and **DeepSeek V4 Flash**
  (`@cf/deepseek-ai/deepseek-v4-flash-0731`). `InterviewReview.jsx` mirrors
  the list (`STRUCTURE_MODELS`), and Compare's "Structure again" takes the
  first that is not the last run's model, so it reaches for the 8B, which
  needs no paid plan, before DeepSeek.
  - The 8B fp8-fast is priced 0.045 / 0.384, from the same 2026-09-06 reading
    of Cloudflare's table that `aiRouter.ts` quotes.
  - DeepSeek is priced 0.44 / 1.32, from Cloudflare's model page and pricing
    table read 2026-10-09 (S1, #1471). Its cached-input rate ($0.014) has no
    column, so cached tokens bill at the full input rate: an over-count, the
    safe direction for the D640 budget.
  - Cloudflare marks DeepSeek "Paid access required". On a plan without it the
    call is refused, the fallback answers, and the receipt names the fallback.
- **`@cf/meta/llama-3.1-70b-instruct`** is retired: the rail shows it and
  cannot choose it. That is the page's job (#1473).

**The decisions** (`routes/founder_validate_structure.ts`, at
`/api/founder/validate`):
- `POST /placements/:id/accept`: accept, or edit then accept with
  `{ payload }`. The edit is validated as strictly as the model's own payload,
  against this project's rows.
- `POST /placements/:id/discard`: writes nothing to any module.
- Both use the store's optimistic-concurrency idiom, so two founders cannot
  both decide one placement.
- A placement of a kind with no writer is refused with
  `writer_not_available` and stays proposed.
- A placement naming an interview of another project is refused and stays
  pending.
- A Lab venture is an ordinary `projects` row, so its member (`ownsVenture`)
  accepts into the same `discovery_interviews` row the Lab's pages read.

### The session routes

#1470 (D657, migration 438) merged while this was in review, so the routes
that read a session are built here too, in the same file:

- **`POST /sessions/:id/structure`** (`{ model? }`) runs `structure_interview`
  over the session's `final` segments, never the live draft. It stores the
  cited placements under a new `run_id`, with `target_ref` set to the
  session's interview, and moves a `transcribed` session to `structured`.
  - The first run is "Structured"; a later one is "Re-structured", which is
    how Compare starts.
  - With no final transcript it answers 409 `no_final_transcript`.
  - **Consent.** A recorded session (audio or video) whose interviewee
    declined, or whose consent was never recorded, is refused with #1470's
    409 `consent_not_recorded` (`consentBlocks`), before any model runs: no
    receipt line, no placement. A typed transcript has no recording to
    consent to, so it is structured. `/ask` gets the same check.
  - **A model given but not recognised** (not a `@cf/` id: `"deepseek-v4-flash"`,
    a number, an object) is refused with 400 `model_not_offered` and nothing
    runs. It used to fall through as no model and silently run the default.
    A `@cf/` id the task does not offer is refused the same way by the router.
  - **A refused run** stores nothing and answers with #1470's codes: 402 for a
    spent budget (`budget_user_day`, `budget_user_month`, `budget_review`),
    with the budget's own message; 400 for `model_not_offered`; 503 only when
    no model could be reached. `/ask` uses the same codes. The page reads the
    `refusal` field, not the status (`refusalKind` in `InterviewReview.jsx`).
- **`GET /sessions/:id/placements`** returns every run's placements, each with:
  - its module;
  - its quoted passage;
  - `can_accept`: false for a proposed-only kind, so the page can say so.

  It also returns `compare`, the last two runs aligned by module.
- **`POST /sessions/:id/ask`** answers from the final transcript, part by
  part when it is long. An answer with no citation inside the transcript is
  refused with 422 `no_citation` and not shown.
- **Gates.** Every session route is gated on `canWrite` for the session's
  project, as #1470's routes are.

**The receipt.** #1470's `interview_session_receipts` admits only `live` and
`final` lines, and widening its CHECK means rebuilding a table that already
holds rows. So `interview_structure_receipts` sits beside it, with one row per
model call. Part 1 (#1489) merged migration 439 before the session routes, and
a merged migration is never edited, so this table has its own migration, 446,
numbered by S1. Each row holds:
- the step (`structured`, `re_structured` or `asked`) and the `run_id`;
- the model that answered, the model asked for, and whether the fallback
  answered;
- the tokens, the cost, and the outcome.

`GET /sessions/:id/receipt` now reads both tables as one list in time order.
#1470's own test fixture applies 439 and 446 too, as production does.

**Offsets for text sessions.** Text chat and manual entry store a start (the
message's time) or nothing, and no end. `toSegments` derives the spans the
same way every time:
- a missing end is the next segment's start;
- a missing start is the previous end, or the position × 1000 ms.

A recorded offset is never moved.

### What waits

- **A market fact has no store.** It stays proposed (`can_accept: false`,
  409 `writer_not_available`).

### Verified

`cloudflare-worker/test/interview_structuring_d658.test.ts` (33 tests) runs on
a real SQLite schema built from migrations 106, 211, 214, 246, 438, 439, 440
and 446 (with the baseline's competitor tables),
with the router's real budget path. It covers the five things the issue named:
- a placement without a citation is never stored;
- an accepted placement and a hand-typed row produce identical module rows;
- a discarded placement writes nothing;
- the receipt names the fallback model when the first choice fails;
- an answer with no citation is refused.

It also covers:
- segment, demand signal and competitor accepted through D659's writers, each
  compared against the same facts typed into D659's manual routes: the rows
  are identical but for the columns that say where a row came from (ids,
  times, source, session). A missing competitor list is refused with the
  placement left proposed, and a market fact is left proposed;
- the session routes: structure reads only the final transcript, Compare's
  second run and alignment, the session receipt naming the fallback beside the
  transcription line, a refused run storing nothing, and Ask;
- stable spans for text sessions;
- a long transcript split and merged;
- edit then accept;
- two racing accepts writing once;
- the proposed-only kinds;
- ownership;
- the Lab venture;
- consent: a declined or unrecorded recorded session is refused 409 by both
  routes, with no model call, receipt line or placement, and a typed
  transcript is structured;
- a model given but not recognised, and a `@cf/` model not offered, refused
  400 with nothing run; DeepSeek V4 Flash offered and named on the receipt;
- 402 for a spent budget and 503 for no model reached, on both routes.

`frontend/test/interview_review_d660.test.mjs` checks that every refusal, at
these codes, is classified by its `refusal` and not by its status.

Every new assertion was mutation-checked, and each mutant fails at least one
test.
