## D848 — One connector contract: capabilities, tools, execute, usage, health, errors, revoke

- **Status:** decided by S1 for the owner, 2026-10-21 (#2469). Part of #2463.
- **Basis:** `origin/main` at `56c2498983`. Worker paths are relative to `cloudflare-worker/src/`.
- **The plan doc.** #2463 names `documentation/architecture/MCP_API_PLATFORM.md` as the plan, landing with #2464's PR. Neither was on `main` or open when this was written. The contract below is what plan §3 should carry for connectors, and the plan's owner can lift it from here.

### 1. The contract

`integrations/contract.ts` defines `ConnectorAdapter`. Every provider adapter implements it, whether it reaches its provider through an MCP server (`pattern: 'mcp'`) or the provider's own API (`pattern: 'api'`).

| Member | What it is |
| --- | --- |
| `key`, `pattern` | The registry key, and `mcp` or `api`. |
| `capabilities()` | What the connection can do, as the registry's own chips. |
| `tools()` | Each tool's `name`, `input_schema` (a JSON Schema object with `additionalProperties: false`), `access` (`read` or `write`) and `unit`. |
| `connect`, `disconnect`, `revoke` | The provider's own route functions. `revoke` is `revokeGranted`: it ends a grant refused before any row was saved. |
| `execute(tool, input, ctx)` | Runs one listed tool for a connection the caller has already authorized. It answers `{ result, usage: { units, provider_cost_microusd } }`. |
| `health(ctx)` | `{ state, error_category }`. The state is `ok`, `degraded`, `expired`, `disconnected` or `error`. |
| `classifyError(e)` | `auth`, `rate_limited`, `not_found`, `invalid_input`, `provider_down` or `unknown`. |

**An adapter is not a second provider.** `registry.ts`'s `ProviderImpl` still drives the connect, sync, push and webhook routes. An adapter's `connect`, `disconnect` and `revoke` are those same functions, and the test holds them identical. GitHub's `disconnect` became a named function for this, unchanged.

### 2. Errors are fixed strings

- **From a status:** 401 and 403 are `auth`; 429 is `rate_limited`; 404 and 410 are `not_found`; 400, 409 and 422 are `invalid_input`; 5xx is `provider_down`; anything else is `unknown`.
- **Only our own error codes are read.** GitHub's status is read only from `github_api_failed: <status>`, and Stripe's only from `stripe_api_failed <path>: <status>`. The Stripe body that follows is never read. A number anywhere else in a message is not a status.
- **Our codes:** GitHub's `github_sign_in_expired`, `github_credentials_missing` and `github_refresh_failed` are `auth`; its renewal's busy and unavailable are `provider_down`.
- **A network failure or a timeout** is `provider_down`.
- **A `ConnectorError`** (an unknown tool, a bad input, missing credentials) carries its own category.
- **From a category to a state:** `auth` is `expired`; `rate_limited` and `provider_down` are `degraded`; the rest are `error`.
- **What the log keeps:** the raw error never leaves the adapter. A failed health check logs the provider key and the category, not the message.

### 3. Tools and usage

- **GitHub:** `read_account`, `read_installations` and `list_repositories`.
- **Stripe:** `read_account`. It returns the account's id and name, never its email.
- **Every tool is a read its connector's page already names,** and each is a request `connect` or the repository choice already makes, so D753's call-site test holds. Nothing the contract runs writes to a provider.
- **Inputs:** every tool takes an object with no fields. Any other input is refused as `invalid_input` before a request is made: an unknown field, an array or a string. A name the adapter does not list is `not_found`.
- **Usage:** one unit per call, with `provider_cost_microusd: null`. GitHub and Stripe bill nothing per call that Axal can see, so the cost is unknown, not zero, and #2466's metering prices the units.
- **No authorization or metering inside `execute`:** both run on the server around it.

### 4. `GET /api/connectors/health`

`routes/connectors_health.ts`, mounted before the connector router so that its `/:key` route never sees the path.

- **Whose connections.** The caller's own `integrations` rows. Each lists the companies it is granted: enabled `integration_companies` rows for companies the member still belongs to, the same join `companyScope.ts` uses. `companies` groups the connections by company.
- **The shape** (#2479). Each connection has `health { state, checked_at, error_category }` and `checks`, its last ten, newest first.
- **No guessing:**
  - a row that is not `active` or `error`, or holds no credentials, is `disconnected`, and nothing is called for it;
  - a connection whose provider has no adapter answers `contract: false` and a null state, because unknown is null.
- **Checks are kept, with no migration.** Each check is one `integration_logs` row: `event_type` `health`, `status` `ok` or `error`, and `response_summary` holding the state and category (`expired:auth`). The route reads back only rows whose words the contract knows, so a malformed row is dropped rather than answered.
- **Bounded:**
  - a check younger than 15 minutes is answered as kept;
  - an older one is run again, at most five per request, so one page load never fans out to every provider.
- **Never answered:** a token, the credentials column or a provider's message.

**Considered and not taken:** a `connector_health` table. The issue asks for no migration, and `integration_logs` already keeps a connection's events per row, with an index on `(integration_id, created_at)`.

### 5. What this does not do

- **Mercury** adopts the contract once #2468 moves it onto the shared MCP client. Until then it answers `contract: false`.
- **No UI.** #2479 builds the screen.
- **No new `/api/*` client method.** The SPA has no caller yet.

### 6. The guard

`cloudflare-worker/test/connector_contract_d848.test.ts`, 18 tests, with stubbed `fetch`:
- conformance of both adapters: the routes' own connect, disconnect and revoke, and read tools their pages name;
- the status, category and state tables;
- GitHub's and Stripe's error mapping, reading only our own codes;
- `execute`: results, usage, and refusals before any call;
- the input checker;
- health: a revoked token is `expired`, a Stripe 429 is `degraded`, and no provider text or token is answered;
- `disconnected` and the unguessed null;
- per member and per granted company;
- signed out is 401;
- a fresh check is reused and a stale one run again;
- the last ten, with a malformed row dropped.

Twenty-four mutations each fail it. They include a 429 not read as rate limited, the member scope dropped, the membership or enabled filter dropped, a stored check not validated, a fresh check not reused, an unknown field or a non-object accepted, an unknown tool run, Stripe's email returned, a cost claimed as zero, and a status read from anywhere in a message.

**Rollback:** revert the PR. The health rows already written stay in `integration_logs` as ordinary log rows.
