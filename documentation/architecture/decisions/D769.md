## D769 — The rail matches the "AIRail · every page" canvas: prices, the switch on every page, Add tokens, the guard sentence, then the page's and the open option's models from the Worker's matrix

- **Status:** decided by S1 for the owner, 2026-10-19 (#2088; task `F2` of D720's plan, #1874 §9). PR 1 (#2135, `Part of #2088`) built §1; PR 2 (`Closes #2088`) builds §2 and §3.
- **Basis:** `origin/main` at `def640f6`, which carries D764 PR 2 (#2143), D768 (#2133), D765 (#2132, #2145) and D770 (#2134, #2141, #2163). SPA paths are relative to `frontend/src/`, Worker paths to `cloudflare-worker/src/`.
- **Rules it applies:** D720 §1, §6 and §11.

### 1. Prices, the switch, Add tokens and the guard sentence (PR 1, #2135)

Every suggested card and All models row prints the Worker's price in the canvas's units (`ui/railPrices.js`), never × 1.25 in the client. "Turn off AI assistance on this page" is drawn on every page. Add tokens is always drawn. "Llama Guard 3 8B checks every run (…)" follows the Worker's `guard.every_run`. All models is the canvas's ten groups with its New badges.

### 2. The page's models come from the Worker's matrix (PR 2)

1. **"Suggested for this page"** is the page's row from `GET /api/ai/rail?page=<key>` (D764). The page key is the shell's (`useRailPage().page`, D768). The cards appear in the row's order, default first, each with the row's role word, line and price. The checked card is the member's pick, else the row's default. A row with more than one model is a radio group.
2. **The pick** is stored per page through `PUT /api/ai/rail/pick`. While an option is open, it is stored per option. The rail checks the card at once, then re-reads the Worker's answer. It no longer writes D698's per-section, per-task store (`ui/railModelChoice.js`), which stays for the fill bands.
3. **"On this page"** lists the page's options from `options[]`, each with the name of its pick or default. The open option is marked.
4. **An open option** (`useRailOption(key, label)`) moves the rail to that option's row (`GET /api/ai/rail?page=<key>&option=<key>`). Its label is the last crumb, as D768's provider already draws it. When it closes, the rail goes back to the page's row.
5. **No row, no models.** A rail with no page key (outside the shell, or a page D768 marks `offCanvas`) reads nothing and says "Not recorded. This page has no row in the rail's model list." A 404 says "Not recorded. The rail's model list has no row for this page yet." A failed read is Unreadable with a retry, never an empty list.
6. **A card's price** comes with its model in the same read: its `billed` units once the read's `billing` is `'billed'`, else its `cost` (`railModelPrice`). An All models row's price comes from the rate card (`GET /api/ai/rates`) by the same rule.
7. **All models** stays the canvas's ten groups, now one table, `ALL_MODELS`: each canvas name with its router id, or null. It folds in PR 1's `CATALOGUE_GROUPS`, `CATALOGUE_EXTRAS` and `ALL_MODEL_IDS`. A row is pickable where the page's row offers it. The guard is never pickable. `airail_d698.test.mjs` holds the table's ids equal to the ids `ROUTE` can send work to, less the retired 8B. That test filled in the twelve canvas models D764 added to the router: GLM-4.7 Flash, GPT-OSS 120B and 20B, Kimi K2.6 and K2.7 Code, DeepSeek V4 Pro, QwQ 32B, Gemma 4 26B, Llama 4 Scout, Mistral Small 3.1 24B, Granite 4.0 Micro and FLUX.1 Schnell.
8. **Retired from `ui/railModels.js`:** `TASK_KIND`, `SUGGESTED`, `CANVAS_LINE_HOLDS`, `CATALOGUE_GROUPS`, `CATALOGUE_EXTRAS`, `SECTION_JOBS`, `MODULE_JOBS`, `DEFAULT_JOBS` and `CANVAS_MODEL_IDS`, with `railSuggestions`, `jobsFor`, `kindFor` and `NOT_IN_CATALOGUE`. The file keeps the model names (`MODEL_COPY`), `ALL_MODELS`, `NEW_MODELS`, `GUARD_MODEL` and `railView`, which shapes the Worker's answer.

### 3. AI is on by default everywhere, and the canvas moves (PR 2)

1. **On by default** (D720 §6). `useAssistMode`'s default is on, on every page, a page with fills included. The rail passes no default of its own. `fills` joins `RETIRED_RAIL_PROPS`: hosts may still pass it, and the rail reads none of it. A stored choice, here or on the Worker, still wins. This depends on D765 (the Worker refuses `assist_off`) and D770 (a recording's Stop asks first), both merged.
2. **The canvas.** `design/incoming/AIRail · every page.dc.html` replaces `design/canvases/integrated/AIRail.dc.html` in place, under the name `Cycle Overview`'s two `dc-import`s load. `integrated/` stays at 98. Its data folder, `airail-every-page-data/`, follows once D771 PR 8 (#2160), which edits two of the folder's readers, has merged.

### What this does not change, and why

- **The switch stays stored under the rail's workspace.** D720 §6 stores it under the page key. D765's check (`assistOff`) reads the page the browser names in `X-Rail-Page`, which is still the rail's workspace (`lib/railPage.js`). A switch written under the page key would not be the switch the Worker enforces. The switch moves when `X-Rail-Page` carries the page key, and members' stored Manual rows must move with it.
- **A page pick reaches a run only where the run's page has a matrix row.** `aiRouter.run` resolves a rail run's models from the row and the member's page pick (D764 PR 3), keyed by the run's `rail.page`. While `X-Rail-Page` is the workspace, no member run resolves a row. Runs keep the route's model, or the fill bands' own pick (`readRailModel`), until that header moves.
- **Prices print at cost today.** The owner set `AI_BILLING = "charged"` (#2123), but `billingMode` (`services/ai/pricing.ts`) still answers `'cost'` until D762 reads the switch. The rail follows the Worker's `billing`, so it prints billed prices from that deploy with no client change, and never a price a run is not settled at.
