## D6562 — Record agreement inputs, replacement readiness and frozen preview (#6562)

An agreement records the core terms revision, schedule revision and versioned
contractual input snapshot used to render its body. Nullable migration columns
leave old agreements unknown; history is never backfilled from today's terms.
The renderer and snapshot share the same captured values. If a source cannot
be read the old placeholder behavior remains, but no comparable snapshot is
recorded and the new send readiness gate refuses that draft.

The contract read compares current values with the latest readable executed
agreement, including an executed row marked superseded while a replacement
is only a draft. A revision counter increase is not a changed-term count:
`terms_differ` counts changed contractual values, and exposes their keys.
Revision-only saves remain equal. Core terms, entity/signatory fields,
territory, licensed seats, schedule terms and rendered contractual exclusivity
are included. Section references and administrative metadata are excluded.
A missing legacy snapshot, no executed agreement or failed current input read
returns null and a reason, never same. Full frozen text/hash is returned only
through the existing Super Admin contract read; raw snapshots are not exposed.

The five readiness rows are Legal entity, Territory, Commercial terms,
Governing law and Signatory title. Commercial terms require the recorded
term, fee (zero is valid), currency, share/split and start/renewal dates. The
read provides current readiness and each draft's frozen readiness. Sending an
unready or unrecorded frozen draft is refused before signer lookup, envelope
creation or any mail. Existing hash and unresolved-placeholder refusals remain.
Legacy drafts must be prepared again; executed history is not changed.

`AgreementReplacement.jsx` implements the L09 readiness list and L10 scrollable
frozen text/full-hash preview, with text escaped by React. Missing fields link
to Terms. The send predicate requires both current and frozen readiness and a
recorded snapshot/text/hash. The comparison control only says differs when
the Worker explicitly answers true. The previous executed agreement remains
executed until the replacement is executed. No #5051 agreement block changes.

The parent integration is prepared against #5920/#6564 and awaits its narrow
file handoff; ContractStep is not edited while that ownership is outstanding.
Verification includes new mounted full-schema tests, existing instantiate/send
regressions with the additive migration, and rendered controls. No live
signature or mail provider is used.
