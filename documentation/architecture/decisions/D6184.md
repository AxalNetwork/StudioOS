### What a row shows

- **The signed count** is `signed_count` of `recipient_count` from `GET /api/legal/esign?deal_id=` ("2 of 3 signed"). A count the list does not return reads "Signatures not recorded", never 0.
- **A fully signed envelope (`completed`) offers Download.** It is the only status the Worker serves a signed copy for: `GET /api/legal/esign/:id/document` answers 409 for any other, and 404 for an envelope outside the viewer's scope.
- **An open envelope (`sent`, `partially_signed`)** says Download opens once it is fully signed, and how to sign.
- **A closed envelope** (`rejected`, `void`, and the older `declined`, `voided`, `expired`) says it can no longer be signed and has no signed copy. The Worker writes `rejected` and `void` (`esign.ts`); before this the row drew them as "Status not recorded" with the waiting tone.

### Download goes through `fetch`, not a link

A plain link to `api.esignDocumentUrl(id)` would leave the page and show a refusal as raw JSON. The row fetches the same URL with `rawRequestHeaders()` and the cookie, hands a PDF to the browser as a download, and on a refusal shows the Worker's own words in the row through `refusalError` (for example "Document not yet signed"). The existing client `esignDocumentUrl` gives the path; no client was added.

### How to sign: the link is the email's

`GET /api/legal/esign/:id` returns the envelope, its audit log (with any old `signing_url` redacted, D410) and each recipient's `recipient_email`, `status`, `signed_at` and `token_expires_at`. It never returns a signing token or link, to the recipient or anyone else. So the row reads that detail for open envelopes only, finds the viewer's recipient row by email (case-insensitive; the rows carry no user id), and says:

- pending: "Your signing link was sent by email to <address>. Open it from that email to review and sign."
- signed: "You signed on <day>. It is waiting on the others."
- rejected: "You declined this envelope."
- no row for the viewer: "You are not a signer on this envelope. It is waiting on the others."
- the read failed: Unreadable with Try again, never "not a signer".

No signing URL is built in the browser.

### Expected paper not yet sent: left out

No read says which set of paper (term sheet, subscription agreement, side letter) a deal uses. `GET /api/deals/:id/closing-checklist` records one closing template (`template_slug`: `safe`, `spa` or `subscription`), but nothing ties that slug to an envelope's `document_type`, so an "expected, not sent" row would be a guess. The card lists only envelopes that were sent. This is a gap for the design brief: a deal-level record of the expected paper, or a mapping from the checklist's template to envelope types.
