### 1. The reads (S1's step 1)

All are Super Admin and HQ only, the gate the licence pricing routes already use (`requireSuperAdmin`, which also
refuses on a branch). None needs the write bar, because none writes.

| Method and path | What it returns |
|---|---|
| `GET /api/admin/licence-pricing/catalogue` | Every market profile (the 49), each with its tier, index, data completeness (recorded, provisional and not recorded inputs), last source update, the recommended annual and initial fee, and the regulatory class. Accepts `?q=`, `?incomplete=1`, `?model=<uid>` (the version selector, a draft included) and `?allow_provisional=1`. |
| `GET /api/admin/licence-pricing/catalogue/:code` | One market: each input with its value, status, source, reference and as-of date; the observation history; the calculation now with its full trace and source digest; and the snapshots already frozen. |
| `GET /api/admin/licence-pricing/model-versions` | The current model, the drafts and the retired versions, each with how many country snapshots, licence snapshots and decisions it priced, plus a dated history (drafted, activated, retired, and by whom). |
| `GET /api/admin/licence-pricing/review-queue` | Every licence whose pricing review is due, whether or not a review row is open, oldest first, with `review_row: open \| none`, days overdue, the terms and the latest decision. Licences with no pricing decision are listed apart under `no_decision`. Accepts `?within_days=0..366`. |
| `GET /api/admin/licence-pricing/signals` | For each licence that is not terminated: the four Needs HQ signals, a sentence for each, and the pricing state behind them, with counts. Accepts `?needs=` (two signals narrow, as two chips do) and `?licence=<uid,…>`. |

A catalogue figure is calculated now with the D5015 engine and stored nowhere (`stored: false`), like the D5016
preview. Because the engine is pure, the country detail's `source_digest` equals the digest of a snapshot frozen from
the same inputs and model version; the tests check exactly that. Every recommendation names its model version.

### 2. The Needs HQ signals (S1's step 2)

They are API fields on `/signals`, not columns added to the ledger list. The ledger's Needs HQ filters already run
over the loaded rows (`licenceLedgerModel.js`), so the screen joins them by licence uid. The hot paged ledger read
(#4700) stays as it is.

| Signal | True when |
|---|---|
| `pricing_review_due` | The next review date is on or before today. |
| `pricing_data_incomplete` | Any country the basis prices from (or, with no usable basis, any country of the territory) has an input that is provisional, not recorded, or has no profile. Also true when there is no territory. |
| `pricing_overridden` | The latest pricing decision is `overridden`. |
| `exclusivity_at_risk` | The current exclusivity version is `at_risk`, or an exclusivity review is open. |

The next review date is D5017's `nextReviewOn`. A store that cannot be read makes its signal `null` with the sentence
"Unreadable…", never `false`, and the counts report it apart (`unreadable`). The reads are set-based: one query per
store, whatever the size of the ledger.

A licence with no pricing decision has `pricing_decision: 'not_recorded'` and the reason "No pricing decision recorded".
It is not "due", because it has no review date yet. The queue lists it under `no_decision`, so HQ records its first
recommendation at its next review, as the issue's rollout asks. No existing licence term is backfilled.

### 3. The queue is computed; no sweep (S1, 2026-11-09 23:51Z)

S1's pick, taken: the queue is computed from each licence's decisions and reviews on every read, so a due review is
listed whether or not anyone opened a review row for it, and a due review cannot be missed because nobody opened that
licence. Nothing opens review rows by itself. An automatic sweep would add a scheduled writer that snapshots every
due licence, and it would gain HQ nothing that the computed queue does not already show. The response says so
(`sweep`).

**One change to D5017.** A review closed with **keep** left the licence's review date where it was, so a licence HQ had
just reviewed stayed due for ever and would never leave the queue. `nextReviewOn` now takes the latest of:

- the decision's `pricing_review_on`;
- a postponement's date;
- **a year after the day HQ kept the terms.**

An open review's due date still wins. Apply and override already set a new date through their decision.

### 4. Audit and observability (S1's step 3)

The issue's audit events, against what `admin_audit_log` (`logAdminAction`) records:

| Event | Action | Here |
|---|---|---|
| Country profile change | `licence_pricing_profile_updated`, `…_observation_recorded`, `…_field_status_set`, `…_observations_imported` | existing (D5016) |
| Model activation | `licence_pricing_model_activated` (and `…_retired`) | existing (D5014) |
| Snapshot creation | `licence_pricing_snapshot_taken` | now also names every country snapshot it froze (`country_snapshots`) |
| Apply / override | `licence_pricing_applied` | now also names the model version and the review it closed (`review_uid`) |
| Annual review decision | `licence_pricing_review_resolved` (keep, postpone), or `licence_pricing_applied` with `review_uid` | apply/override part added |
| Exclusivity change | `licence_exclusivity_set`, `licence_exclusivity_review_resolved` | existing (D5019) |
| Program pricing decision | `program_pricing_decided` | **new**: before this, the decision reached only the licence history |

`program_pricing_decided` is written after the grant's batch commits, so a lost write records nothing.

The logs tell the four failure kinds apart with one `console.warn` JSON line,
`{"event":"country_pricing_incident","kind":…}`, carrying ids and codes only:

- `recommendation_calculation_failed`: the engine refused the model;
- `market_data_incomplete`: a licence snapshot came out unavailable;
- `stale_revision_conflict`: `terms_conflict`, `basis_conflict`, `review_conflict`, `snapshot_stale`;
- `branch_push_partial`: HQ committed and the branch push did not land.

They are emitted from the licence pricing routes. There is no metrics backend to count them; `wrangler tail` and the tail
consumer read the lines.

### 5. The end-to-end tests (S1's step 4)

`licence_pricing_hq_5020.test.ts` runs the real routers over every migration: the D5020 reads, the D5014/D5016 models
and catalogue, the D5017 licence pricing, the D5018 program grants and reference prices, and the D5019 exclusivity. It
covers the issue's sixteen scenarios: 1 (with a whole-store before/after comparison for "no side effects"), 2 to 8,
9 with 10, 11 with 12, and 13 to 16. It also tests access (Super Admin allowed; a plain admin, no session and a branch
refused), every audit event above, the Unreadable signal, and the pure rules.

The suite never reads the real clock. Due dates are in 2020 and dates that are not due are in 2999.
