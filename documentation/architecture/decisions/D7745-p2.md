## D7745 part 2 — The Research imports gate, exported for routers on its prefix (#7745)

**Date:** 2026-11-25. **Status:** Built. Follows part 1 (`D7745.md`, PR #8364).

### Why

#7746's mapping router mounts on `/api/research-source-imports` too and must answer exactly as the import routes do,
the support-session refusal included. Part 1 defined that gate as a private `gate(c, check)` in
`cloudflare-worker/src/routes/research_source_imports.ts`. A second copy could drift; one export cannot.

### The contract

```ts
import { requireSuperAdmin, requireSuperAdminWriteBar } from '../auth';
import { researchImportGate, type ResearchImportContext } from './research_source_imports';

const user = await researchImportGate(c, requireSuperAdmin);          // a read
const user = await researchImportGate(c, requireSuperAdminWriteBar);  // a write
if (user instanceof Response) return user;                            // the refusal, returned as is
```

- It signs the caller in, refuses a support session (a token with `impersonated_by`) with 403
  `support_session_refused` and the sentence `REFUSAL_SENTENCES.support_session_refused`, then runs the check handed in.
- It answers the `User` when every check passes. Otherwise it answers a `Response`: 401 for a caller who is signed out,
  and the check's own 403 for anyone who is not a Super Admin, for a branch deployment, and, for a write, for a session
  with no fresh TOTP step-up. Auth errors map through the same `mapError` as part 1.
- Authorization semantics are unchanged: part 1's eight routes call the same function, renamed, and their tests are
  untouched.
- **Auth inventory.** Call it inside the handler with the check named in the call. `scripts/lib/authInventory.mjs` reads
  `requireSuperAdmin` / `requireSuperAdminWriteBar` in the handler text, so the route reads `super_admin` and needs no
  ledger entry. A check stored in a variable or a wrapper defined elsewhere would hide it.

### Proof

`research_source_imports_7745.test.ts` test 1b builds a separate router from the import alone, on the same prefix. It
gets the same answers for signed out, a member, a plain admin, a branch, a support session, a write with no step-up,
and a Super Admin.
