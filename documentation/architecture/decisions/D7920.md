## D7920 — Refuse votes after an IC decision is recorded (#7920)

Status: implemented for review by s39, 2026-11-20. Service repair for the separate frontend containment in #6154 / #7922; no new route, migration or reopening store.

`POST /api/ic/:uid/vote` returns `409 voting_closed` for a recorded (`decided`) decision. Company scope and roster checks still run first, retaining 404 for an out-of-scope row and 403 for an off-roster viewer. The response explains that no later vote or recusal was recorded.

### The write, not just the request snapshot, decides

The existing vote upsert now inserts from a SELECT conditioned on the decision still being non-decided. The same predicate gates both a first insert and a conflict update; a recording that commits after the request's read but before this statement leaves no vote row changed. The existing `ic_votes.vote <> 'recused'` conflict-update guard remains, so a concurrent final recusal still wins too.

`RETURNING id` and D1's `first()` distinguish a successful write from no returned row without relying on optional change-count metadata. A refused write reads the decision's current status to distinguish `voting_closed` from `recusal_is_final`, then returns before journal drafting/regrading/cleanup. D1's documented first-row-or-null contract was checked against the official Cloudflare documentation source during implementation.

The first-vote draft promotion also requires the current stored status to remain `draft`. An accepted first vote must not overwrite a subsequent recording with a stale `voting` update.

There are two valid orderings:

- Recording wins the vote-write boundary: vote/refusal is 409; votes, declaration, journal, tally and recorded decision remain unchanged.
- Vote wins that boundary: it is accepted normally. A recording that follows stays decided even when the vote handler subsequently reaches draft promotion and private journal drafting.

Existing open-decision re-votes, rationale requirements, roster rules, final recusal and graded-journal history remain. This adds no Reopen action, reason/audit model or new lifecycle policy; the existing update endpoint is otherwise untouched.

### Verification

The dedicated tests execute the real IC router against SQLite with synthetic members/records. Hooks schedule a second real recording or recusal HTTP request immediately before/after the actual vote statement; they never fabricate query results. Cases cover invest/pass/defer, every vote kind, first votes and upserts, graded-journal preservation, both recording/voting orderings, open draft promotion, existing recusal races, company scope and roster refusal. Existing IC/company/roster/preview/graded-journal tests also run.

The PR reports local type, guard, mutation and build results separately from hosted CI/full-drift validation. No production data, live vote or deployed behavior is claimed. Roll back this route change to restore the previous behavior; no schema rollback is needed.
