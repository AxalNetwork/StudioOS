## D8354 — Worker tests load the cached schema instead of rebuilding it per database (#8354)

**Decision date:** 2026-11-23. **Scope:** worker tests only (`cloudflare-worker/test/`). No application, schema,
migration or workflow change. Builds on D4133 (`_schema_once.mjs`, the schema built once per run).

### Why

On 22–23 November four merge-queue entries (#8187, #8207, #8214, #8278) were dropped because a worker shard ran
past the 50-minute job limit. No test failed. In the slow shards about 110 tests took 30–330 s each instead of
milliseconds. A fifth entry (#8209) failed one date assertion while its run crossed midnight UTC.

Seventeen worker test files built their database with `buildFresh(BASELINE, LATER)` from
`scripts/check-baseline-drift.mjs`, or by executing the baseline and every migration by hand: once per test, or
several times. That build takes about 35 s locally by now; 12 s of it is one data migration,
`202611181350_7325_verified_global_fund_managers.sql` (1.2 MB of fund rows), and applied migrations cannot be
edited. D4133's cache already builds the same database once per run for 400 other test files; these predated it
or bypassed it.

### What changes

- **One helper.** `freshSchema({ dqs, below })` in `_schema_once.mjs` opens an in-memory handle, loads the cached
  schema and its rows (`loadSchema`), and then turns foreign keys on, as `buildFresh` does. `dqs` sets
  double-quoted string literals the way `buildFresh`'s flag did. `below` gives the build before a numbered
  migration.
- **Equivalence, checked against `buildFresh`.** The schema text is identical for the full build, with and
  without `dqs`, and for `below: 287` and `below: 288` (the prefixes `runtime_schema_declared_d235` compares).
  Row counts are identical. Row contents differ only where a migration seeds a build-time timestamp or a random
  uid, as any two fresh builds do.
- **Converted.** These files now call `freshSchema`:
  - `account_move_recovery_5043`
  - `admin_profile_onboarding_d1306`
  - `admin_profile_totp_d236`
  - `branch_emergency_sign_out_d4669`
  - `branch_freeze_admin_acts_d260`
  - `branch_support_session_d259`
  - `branch_unbind_admin_d262`
  - `hq_unbind_admin_d262`
  - `impersonation_d248`
  - `kyc_people_queue_d1229`
  - `pipeline_access_d4676`
  - `program_enforcement_d985`: its row-by-row template replay is gone too
  - `session_containment_d4669`
  - `runtime_schema_declared_d235`
  - `partner_profile_verdicts_d992`
  - `legal_template_research_schema_4591`: its current-schema case only
  - `grow_feedback_loop_6865`: it executed the migrations itself
- **Kept on `buildFresh`, on purpose:**
  - `baseline_drift_guard`, which tests the builder itself;
  - `research_directory_columns_d531` and the older-baseline case in `legal_template_research_schema_4591`,
    which build from a deliberately different migration list;
  - `scripts/check-baseline-drift.mjs`, the deploy's own comparison.

  `licence_termination_durable_4686` already used the cache; its local function is merely named `buildFresh`.
- **Midnight.** `grow_feedback_loop_6865`'s 60-day `since` is checked against the date 60 days before the request
  starts and before it ends. The route reads its own clock, so a run crossing 00:00 UTC matches the second date.
  Nothing else in the assertion is loosened.

### Rollback

Revert the PR. The tests return to building the schema themselves, which is slower but has the same coverage.
