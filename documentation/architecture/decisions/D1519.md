- **Status:** built by S09, 2026-11-02 (#3771, part of #3716; claimed from slot S25 at the owner's request). The issue gives the D number.

### 1. One file per element and family

Every deck prompt is a file `<element>.<family>.ts` in `services/decks/prompts/`, exporting `{ version, system, template }`:

| Element | Files | Who runs it |
| --- | --- | --- |
| `outline` | `outline.default.ts` | `POST /api/decks/outline` |
| `build` | `build.default.ts`, `build.llama.ts`, `build.mistral.ts`, `build.glm.ts` | `/generate`, `/proposals/:id/regenerate-card` (the one-click words) |
| `assist` | `assist.default.ts` | `POST /api/decks/:id/cards/:card/assist` (each action adds its own ask) |

A **family adapter** changes only the system prompt, for one family's habits: Llama's preface, Mistral's code fence and title case, GLM's visible reasoning. It keeps the element's template, so a family changes how a model is asked, never what. A test holds every family to the default's template.

A model's family is read from the vendor segment of its catalogue id (`familyOf`: `meta` → llama, `mistralai` → mistral, `zai-org` → glm, any other → default). No model id is listed here, so the catalogue (D760) stays the only model list.

### 2. One voice

`promptFor(element, model, voice)` opens every family's system prompt with `HOUSE_VOICE`: first person plural, present tense, short sentences, no hype, no exclamation marks, no emoji. It then adds the deck theme's `voice` (D1500's `theme.voice`), framed as data with `untrustedBlock` (D1506), since it is the founder's words. The text press reads `theme.voice` from the saved version. New deck has no theme yet, so it gets the house voice alone.

**The glossary** (`GLOSSARY`, `glossaryProblems`) is what keeps several models in one voice. `wordingFromModel` drops a string that breaks it, exactly as it drops one that names a number, and counts it in `wording.dropped`. The card then keeps its title rather than a second voice. The rules are:

- hype words;
- an exclamation mark;
- an emoji;
- the first person singular;
- the venture in the third person ("the company").

`deckGlossary(slides)` checks a whole deck.

### 3. `prompt_version` on every reply

`promptFor` names its result `<element>.<family>@v<version>`. The outline answers it in `outline.prompt_version`, the build and regenerate-card in `wording.prompt_version`, and a text press in `prompt_version`. That lets a weak batch be traced to the prompt that wrote it. The UI does not draw it.

### 4. A changed prompt brings its eval

`scripts/check-prompt-eval.mjs` hashes every file in `prompts/` (sha256 over name and bytes, in name order) and compares the result with `<!-- prompts-hash: … -->` in `ELEMENT_EVAL.md`.

`.github/workflows/prompt-eval-gate.yml` runs it on every PR, and again when a label is added or removed. A mismatch fails unless the PR carries the owner's `prompt-eval-waiver` label, which is added to `.github/labels.yml`. After re-running the element eval, `--write` records the new hash. A missing record is exit 2, never a pass.

The rule sits in its own workflow, not in `test:guards`, so that a waiver label added after the run re-runs it.

### 5. Tests

`cloudflare-worker/test/deck_prompts_d1519.test.ts` checks:

- the files' shape and that each family keeps its template;
- `promptFor`'s family choice, preamble, framed voice and `prompt_version`;
- that a deck written by three models (Llama, Mistral and GLM, read from the Write job's list) passes the glossary check, while a drifting string is dropped;
- what the glossary refuses and lets through;
- the CI rule: a changed prompt fails, and the waiver passes it.

`deck_fake_ai_d1511` now also asserts `wording.prompt_version` on the one-click run.
