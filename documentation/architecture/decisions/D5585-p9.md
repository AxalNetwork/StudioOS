### 1. The read

`GET /api/public/release-sites/:tenant/:company/:site`, no sign-in.

| Step | What it does |
|---|---|
| Flag | Unless `WORK_GRAPH_RELEASE_SITES` is `on`: 404 `release_sites_off`, before the path is parsed and before any D1 or R2 read |
| Path | Tenant and company positive integers, site a DNS label (part 6's `SITE_REF`); else 400 `malformed`, still with no read |
| Line | The line of the latest `release_website_cdn` outbox effect for that site **in that tenant and company**. The outbox row carries the line (`asset_uid`) and the site (`payload.ref`); no other table names a site. None: 404 `not_found` |
| Pointer | Part 2's `servedRelease` in the path's scope. A takedown or a tombstoned pin: 410 `withdrawn`, naming nothing and reading no R2. No head: 404 `not_found`. A non-public line: 404 `not_found` |
| Record | One R2 `get` of **the pointer's manifest's** key for this site. Absent: 404 `not_delivered` (published and not yet drained, or published without this site). Never the previous manifest's record |
| Check | The object's metadata names the same tenant, company, manifest and digest; its body the same manifest, digest, line, audience and pinned pieces (asset, revision, digest, role, in order) as D1. Anything else: 409 `record_mismatch` |
| Answer | `{ state, site, tenant_id, company_id, line, manifest_uid, digest, head_seq, record, cost }`. `record` is rebuilt from the checked ids, so nothing else in the object is ever echoed; no content, no source locator, no kind, no release key |

A thrown D1 or R2 call, or no `FILES` binding, is 503 `unavailable`; the thrown text is logged, never sent.

**Why the latest effect picks the line.** A site can move from one release line to another (a campaign's second line).
The latest publication that named the site is the one its owner meant. After that, the line's pointer decides, as
everywhere else: if that line's release is taken down the site is withdrawn, and it does not fall back to the earlier
line on its own.

### 2. Why this path

`/api/public/*` is where the Worker's unauthenticated reads live (`/api/public/trust`, `/plans-and-packs`,
`/version`, `/handle`), and the auth inventory files them together. The tenant and company are in the path because
part 6 keys the record by them and a site name is only unique inside a company; they are ids already in every
release record, and the read answers nothing for a pair that has not published to that site.

**Mount order.** `events_public`, `jobs_public` and `circles_public` each register `use('*')` on `/api/public` that
bootstraps their schema in D1. A router registered after them would touch D1 before its flag is read. So the router
mounts `before: [eventsPublic]`, the first legacy `/api/public` mount, and its handler answers without calling `next()`.
A test pins the `before`.

### 3. Caching and abuse

- **`Cache-Control: no-store`.** A takedown must stop the record on the very next request. The Worker holds no token
  that can purge a shared cache (D5585-p3 §2), and Cloudflare does not cache a Worker's own responses, so the only
  caches are a browser's and a proxy's. Any `max-age` would let one of them keep a withdrawn release for that long. The
  record is small; the cost is the reads, below.
- **Cost per request:** five D1 statements (the outbox row, then `servedRelease`'s line, manifest, takedowns and pins)
  and one R2 `get`, reported on every answer as `cost: { d1Statements, d1Batches, r2Requests }`.
- **Rate limit:** `release_site_read`, 60 a minute per IP, fail-open, like the other public reads (`public_trust`,
  `evidence_share_read`): a site must not go dark because KV is slow, and 60 a minute is far above a website's server
  reading it while keeping a sweep of tenant and site names slow.
- **CORS is unchanged.** The global policy admits only Axal's origins, so a browser on a customer's domain cannot read
  it cross-origin; the website's server or build reads it. Opening it to other origins is a separate decision.
- **Audit.** A public read writes no audit row, like every other `/api/public` read; the publication, takedown and
  delivery it reflects are each already audited (parts 1, 2 and 7).

### 4. Revoked people in the release admin context (D5585-p8 §6)

`releaseAdminContext` now resolves `revokedUserIds` beside `authorities`, from `revokedReleaseUsers(env, scope)`:

- **Revoked means `users.is_active = 0`.** It is the flag a session is refused on (`auth.ts`), and the platform's two
  revocations set it: an admin's deactivation (`PATCH /api/admin/users/:userId/toggle-active`) and an HQ licence
  termination (`admin_licences_lifecycle.ts`). No code deletes a `users` row (`dsrRequests.ts`), so there is no other
  account state to read; a missing row is not treated as revoked.
- **A removed company link is not a revocation.** Part 8 already handles it: both authority resolvers join
  `user_company_links`, so an unlinked person holds no authority and their approvals stop counting.
- **Who is checked:** the company's linked people, and everyone the scope's release records name as acting — decision
  reviewers, attesters (an agent's sponsor too), manifest authors and the approvers of component heads. One statement,
  not capped: a cap would drop a revocation, and the set is bounded by the company's people, not the platform's.
- **What it changes,** through the services' existing checks: a revoked reviewer's approval does not count at
  publication or in the evaluation (`missingApprovals`), a revoked person cannot decide or attest (`revoked_author`),
  and a revoked approver of a pinned component head refuses publication (`revoked_author`). Reactivating the account
  restores them on the next request. `revokedAgentRunIds` stays unresolved: agent runs are revoked through their
  sponsor, which this covers.
- **Not changed:** the public read serves what the pointer names; a revocation after publication does not withdraw a
  release. That is a takedown's job.

### 5. Tests

1. Flag off for eight values: 404 `release_sites_off`, `no-store`, with a D1 and an R2 that fail on any touch, even for
   a malformed path; the mount's `before`; the bucket's pattern covers the path and nothing beside it.
2. The pointer: `not_found` before any publication; `not_delivered` before the drain; the record after it (exact keys,
   ids only, no locator or kind, its cost); after the pointer moves, `not_delivered` (m1's record still in the bucket)
   until m2 is drained; a manifest published without the site gives `not_delivered`, not the older record; a second
   line publishing to the site takes it over, and the first line's other site keeps following the first line.
3. A tombstoned pin and a takedown: 410 `withdrawn` at once, before the retraction is drained, with no R2 read and no
   ids; still withdrawn after the record is retracted.
4. Tenants: four other (tenant, company) pairs read nothing; tenant 8's site of the same name shows its own release and
   neither answer names the other's manifest; later outbox rows naming the site in tenant 8, in company 71 or for the
   `stream` target never pick the line; sixteen tampered records (metadata tenant, company, manifest, digest; body
   JSON, v, manifest, digest, line, audience, each component field, length, null) are refused; extra fields in a
   matching record are not echoed; a non-public line with a planted outbox row and record is `not_found`.
5. Nine malformed paths read nothing; no bucket (no R2 request), a failing bucket and a failing D1 are 503 without the
   thrown text.
6. Revoked people: resolved per scope and only there (a person who approved a head in tenant 8 is not resolved in
   tenant 7); a linked person, a manifest author, a reviewer, an agent's
   sponsor and a head approver are each resolved from their own record; a revoked reviewer's approval stops counting
   in the evaluation and at publication, and they cannot decide; a revoked head approver refuses publication; after
   reactivation the release publishes.

### 8. Rollback

Leave `WORK_GRAPH_RELEASE_SITES` unset: the read refuses before any read. To remove the code, revert this part: the
route and service go, the bucket is unused, and `releaseAdminContext` returns to resolving no revocations. Nothing is
stored by this part.
