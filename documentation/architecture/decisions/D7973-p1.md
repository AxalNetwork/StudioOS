### Atomic admission and ordering

SqlCapacityBudgetStore persists one canonical bounded JSON window in the existing
authority's SQLite storage. A synchronous transaction reads, decides and writes
before resolving acceptance; storage exceptions roll back and refuse work. This
replaces the old shared 120/minute gate; no shared gate precedes protected lanes.
The new table is prepared code only, never applied to a live authority here.

Independent review by s34 also reproduced a fail-open reset from an existing
SQLite JSON-null or primitive cell. The adapter now rejects null, primitives
and arrays when a row exists, before calling the decision function. It retains
the malformed cell on rollback. Only an absent row supplies the initial null
sentinel. Explicit native-store shape checks remain the child helper's boundary.

Only method/path, the synchronous CAPACITY_ENABLED environment flag, bounded
bearer parsing and trusted settings run before budget.run. In response to s34's
review, the asynchronous durable kill-switch lookup is inside the bounded
verification callback, not ahead of admission. Work rechecks it before reading
the body and after reaching the ordered callback. Transport checks it again.
Independently authenticated owner controls and alarms remain separate from
ordinary authentication. Awaiting authentication does not extend the ordered
work queue. Admitted body work and queue occupancy retain the helper's slots.

### Trusted reader continuation

Each receipt-reader lifetime retains at most one exact bearer in trusted process
memory, for at most 30 seconds and ending one second before its claimed expiry.
The unverified client expiry can only shorten reuse; it grants no authority.
The entry is scoped to repository, child run/attempt and executor revision.
Concurrent acquisition shares one pending operation; another pending scope is
refused. Errors clear the entry. Submission does not use this cache. No bearer
is written to disk, durable budget state, a receipt or candidate environment.

Independent review by s34 found that HTTP 200 inactive receipts and field
mismatches initially threw outside cache invalidation. A three-read same-context
regression reproduced the single-acquisition defect. All trusted receipt
validation now runs inside that boundary, including malformed/empty responses,
so the next call obtains a fresh token. This corrects the conservative retry
contract; the original signature and current-receipt checks were never bypassed.

The authority promotes only a fingerprint of a freshly verified token after the
original transport returns an active owned receipt. Protected requests verify
the signature/claims again and perform the current owned-receipt lookup again.
A path, unowned result, new token, stale generation or wrong profile cannot
substitute for those checks. A restarted reader/authority, expired proof or new
token still bootstraps through ordinary admission. A continuing execution can
therefore be refused during sustained traffic at renewal; ingress, operational
deadlines and #8009 composition remain pre-activation gates. No universal
availability, fairness, hosted throughput or fleet-capacity claim is made.
