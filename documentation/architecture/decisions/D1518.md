## D1518 — Deck v2 A7: one harness for rubric, editing tasks, benchmark and element eval (#3770)

- **Status:** built by S09, 2026-11-01 (#3770, part of #3716; claimed from slot S15 at the owner's request). The issue gives the D number.
- **Spec:** the issue's "Final canvas revision (2026-11-01)": the original's harness, plus the zero-edit acceptance arm (dk-auto item 11) reported as the gate for #3768.
- **Scope:** scripts, docs and one test. No route, no migration, no screen.

### 1. One harness

`scripts/lib/deckEval.mjs` holds the data and decisions, pure and in plain JS. `scripts/eval-elements.mjs` runs them through the test loader, since it reads the Worker's TypeScript. The two documents, `documentation/product/ELEMENT_EVAL.md` and `documentation/product/DECK_BENCHMARK.md`, are what the harness writes and what a test reads back.

### 2. Briefs come from records, never a prompt

New deck has no prompt field (plan §0 row 3). Each of the twenty golden briefs is one element, a sample venture, the card it is for and that card's records: the input the one-click run reads. The three sample ventures are D1517's (`cloudflare-worker/test/fixtures/pitchStoryFixtures.ts`: full, sparse, conflicting), so the harness adds no fixture. A test refuses a brief with any key beyond `id, element, job, venture, card, records, expect`, and a record the venture does not hold. A sparse brief must keep its gaps honest.

### 3. Rubric v0, and the investor rubric

Rubric v0 *is* D1517's code rubric (`services/decks/rubric.ts`, gate `RUBRIC_GATE` = 70). It is named, not copied. The investor rubric v0 has six questions, 1 to 5 by a person. It is recorded and never gated, and never averaged into rubric v0.

### 4. The zero-edit acceptance arm: the gate for #3768

This arm takes the one-click output for the three sample ventures exactly as generated: `buildCards` on the venture's records, with every unrecorded record unticked as the one-click run does, and the recorded words the fake binding answers (D1511). It passes when rubric v0 ≥ the gate, with **0** "Not recorded" placeholders and **0** overflow.

The 2026-11-01 baseline in `DECK_BENCHMARK.md`:

| Venture | Rubric v0 | Placeholders | Overflow | Verdict |
| --- | --- | --- | --- | --- |
| full | 100 | 0 | 0 | pass |
| sparse | 86 | 7 | 0 | fail |
| conflicting | 100 | 0 | 0 | pass |

The sparse venture fails because unticking its unrecorded records still leaves "Not recorded" lines on cards whose every record is missing. That is what #3768 closes, and its acceptance is this row turning to pass.

`deck_eval_d1518.test.ts` holds the table to what the arm measures. A change to what one click builds must refresh it (`eval-elements.mjs --benchmark --write`), so the benchmark can never go stale silently.

### 5. What waits on the owner

- **F (benchmark access).** Each competitor arm (Gamma, Canva, Pitch, Genspark, Dokie) reads "not run" and carries no figure. The zero-edit arm's Gamma and Dokie columns read the same.
- **N (evaluation spend).** `--live` is refused until `EVAL_SPEND_CAP_USD` (the owner's cap) and a staging `EVAL_BASE_URL` are set. It never targets `axal.vc`. The live caller itself lands once N and F are made; until then the element eval runs dry (`--plan`).
- **Editing tasks v0** (§7.4, §7.4b; ten tasks with target steps) stay untimed (`measured: null`) until a person times them. No time is invented.

### 6. ELEMENT_EVAL.md is the proposal to #3721's plan

It lists every routed element with its job, its golden briefs, its eval state and the change a measurement proposes. There is no separate defaults file. The test holds the table equal to `ELEMENT_ROUTES` both ways. It names no model id: the catalogue (D760) is the only model list, and a measured change lands through #3721 in `modelUseCases.ts`.
