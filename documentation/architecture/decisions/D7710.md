- **Status:** built 2026-11-23 (#7710, under #3701), from the owner's Research › Markets audit of 2026-11-19 (2B, 2D).
- **Builds on:** D7171 (`sources_by_kind`, the filters and facets), D7707 (the period measured and the retrieval date), D7708 (the index window, each observation once), D7172 (the Markets CSV and "Not recorded").
- **Owner answers, built as A:**
  - **Q1:** the headline, the band, the filter and the sort use evidence that names the market, with the inherited count beside it. Most markets now read "None named".
  - **Q2:** the CSV appends columns, and its first four are unchanged.
- **Not here:**
  - The company profile's market index line (`companyDirectoryView.js` `indexRows`, `CompanyProfile.jsx`). Built in part 2, [D7710-p2](D7710-p2.md), once #7812 was on main (order #7812 → #7710 → #7813).
  - How the routes read the company directory (#7713), the sector page and overview (#7708), and new sources.
- No migration.

### What was wrong (checked on main)

- A market's `source_count`, `newest_source_at`, `fresh` band and `newest_source` sort mixed inherited sector sources with evidence that names the market.
- Sector sources were read over all time, a provider in both sets was counted twice, and the sector dates were fetch times.
- A World Bank year fetched again moved the market's newest date and its band.

### The Worker (`routes/research_markets.ts`)

| Field | Before | After |
|---|---|---|
| `source_count` | named + sector sources | evidence behind active signals that names the market; not recorded with "None named: …" when none does |
| `newest_source_at` | newest of both | newest named evidence (`signal_evidence.observed_at`) |
| `newest_source_basis` | — | `reported` (the date the source reports), or null |
| `distinct_source_count` | — | both sets, a source key in both counted once |
| `sources_by_kind.*` | `{ count, newest }` | `{ count, newest, basis }` |
| `sources[]` | `{ kind, key, rows, newest }` | `+ basis`; a sector source's `rows` are distinct observations |
| `fresh` filter, facet counts, `summary.fresh`, `sort=newest_source` | any kind | `newest_source_at` (named) |
| `summary.by_sector[]` | `newest_sector_source` | `+ newest_sector_basis` |
| answer | — | `sector_window`: `{ start, end, days }` |

- **The sector set** is read by D7708's rule: rows retrieved in the `WINDOW_DAYS` (30) days before the read (`retrievedAtSql() >= window start`), counted by `distinctObservationsSql()` (D7707's observation identity).
- **The sector date and its basis:** a source's newest date is the last day it measures (`observed_period_end`, basis `period_measured`), or its newest retrieval date (`retrieved`) when no row records a period. `kindSummary` takes the strongest basis any source in the kind has (period measured over retrieval), so an annual figure fetched again moves no date.
- **`GET /markets/:slug`:**
  - The all-time `index.source_mix` and its query are gone; no page read them.
  - Each index point carries `window_start`, `window_end` and `window_reason` from `storedWindow()` (D7708), and is never derived.
  - `period` and `month_to_date` stay.
