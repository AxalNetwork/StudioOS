## D8468 — The PR preview accepts PDF files (#8468)

`scripts/lib/previewArtifact.mjs` (D7146) unpacks a pull request's built `docs/` for the trusted preview
deploy and refuses the whole archive if any file has an extension outside `ALLOWED_EXTENSIONS`. Since #7801,
#7804 and #7969, `frontend/public/program-briefs/` holds eleven program-brief PDFs that every build copies into
`docs/`, so every preview artifact was refused and no pull request got a preview (#8468, the `PR preview deploy`
failures on 2026-11-24).

**Decision.** `pdf` joins the accepted types. A PDF is a static file a browser fetches, like the images and fonts
already on the list. The deploy only uploads it and never opens it, and production already serves the same files.
The preview's other protections (names, sizes, configuration files, symlinks) are unchanged.

**The guard.** `previewArtifact.test.mjs` now walks `frontend/public/` and requires every file the build copies to
pass `nameProblem`, so the next new file type fails in the pull request that adds it, not in every preview after.

Not in this change: #8470, where the `delete` job ran with an empty `PR_PREVIEW_CLOUDFLARE_API_TOKEN`. That is the
`preview` environment's secret, a settings matter.
