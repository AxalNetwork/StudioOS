## D1214 — Closing part 1: access, retired capital routes and identity (#3211)

Built for S13, 2026-10-26. Part of #2424. No migration, bank operation or deployment configuration change.

### What changed

- `networkfx.ts`: syndicate list and detail reads disclose names and pledged amounts only to the lead, a member or an admin. The list applies its scope before its limit. Roster queries never select email, including for admins. Both candidate-query paths already excluded email; executable tests now cover both with the model stubbed. Creation/join logs keep identifiers and outcomes, without names or amounts. The minimum refusal carries no figure.
- `captable.ts`: the legacy raw register read is for the venture's founder, its accepted cofounders and admins. A read-only advisor membership alone does not disclose the register. Anyone else needs a live person-bound founder grant naming a holder; that response contains only that venture's matching holder rows, without email or the venture's securities. The connection recorder's `user_id` and an email match never establish holder identity. Revoked grants and another venture's grants confer nothing. A holder may open that position across their own company selections without receiving access to the venture's full register. Migration 575 defines holder_ref as a name; zero or multiple matching rows refuse (409) rather than treating an ambiguous name as an identity. D1019's separate level-based cap-table views retain their policy. In that existing policy, a live holder_ref grants at least Own position even when level is None (captableAccess.ts grantLevel and migration 575); this legacy read follows the same rule and tests it explicitly.
- `legalcap.ts`: all legacy `/capital/*` routes return authenticated **410**, with **“Capital calls are managed in Fund admin.”** They perform no capital read or write, even if the ledger is unavailable. The conflicting capital-call bootstrap and its unused syndicate bootstrap are removed. The schema-collision/refused-index ledgers drop only those now-resolved entries; the column-union guard keeps testing the remaining metrics snapshot collision. `capital.ts`'s retired `POST /capitalCall` returns the same response. The existing `capitalCalls` client now reads `/capital/calls`; no screen calls a retired capital route. The supported fund-scoped calls, receipt recording and Fund admin acts remain the money workflow.
- `legal/generate`: absent template fields return null values in `terms`, a `missing_fields` list, **Not recorded** and a reason. Generation remains refused (400) until the member records the terms; it creates no incomplete paper and calls no AI for missing terms. Complete supplied terms retain the deterministic template and separate Eadwyn notes flow.
- `PATCH /legal/docs/:id/sign`: authenticated **410**, directing the member to the signing envelope. Even a matching completed envelope cannot make this legacy click update a document. The envelope flow owns signatures.
- `deals.ts`: creating or updating a pending commitment calls the same `requireApprovedKyc` guard as joining a syndicate. Unapproved investors receive the same **KYC required** sentence and 403, before any commitment write. Its audit entry links the saved commitment uid and no longer includes the amount. The commitment row holds the figure; the log holds only its reference, as #3211 requires. A new monetary history store is not added without a migration.

The list/detail privacy scope is intentional: #3211 permits names and amounts only for lead/member/admin, not an unrelated account or a project link alone. The earlier Network Effects creation/join screen was removed by #2324 (as #2424 records); this part adds no public discovery surface. Joining with terms supplied separately remains possible, and a test proves the caller gains the private reads only after joining. A minimum is not echoed in an error under #3211's no-figures-in-errors rule.

### Earlier fixes retained

The issue's starting inventory includes bugs already removed before this branch:

- #2441 removed `PUT /captable/:projectId/holders`. It stays absent, for every role, with no register writes. Reintroducing delete-and-replace would bypass the recorded cap-table workflow. The canonical record writers retain their batched, audited changes; this task adds no parallel register writer.
- #2443 removed invented legal terms, the automatic spin-out capital call and the pledge-to-funded transition. Tests retain those protections: reaching a syndicate target leaves it open, no receipt is invented, and a spin-out creates no capital call.
- The two syndicate candidate queries already omit email. New executable tests preserve this alongside the roster fix.

Money remains recorded and matched, never moved by the platform. This part adds no money arithmetic, currency conversion, bank or provider integration. The legacy commitment's recorded amount representation is unchanged; the closing store's cents and currency belong to part 2.
