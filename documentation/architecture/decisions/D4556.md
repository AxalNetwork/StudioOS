## D4556 — Third-party models through AI Gateway on the existing accounting path, before any second direct adapter (#4556)

- **Status:** built 2026-11-06 (#4556), off by default. No gateway was created, no credential changed, nothing enabled in production, nothing deployed.
- **Number:** D4556 is the issue's number (D4106).
- **Builds on:** D851 (direct provider adapters and their metering), D844 (one hold per execution), D763 (Llama Guard, failing closed), D1534 and D4316 (image tools already reach Bria and Pruna through AI Gateway on the binding), D261 and D1504 (gateway metadata, a gateway per workload).
- **Migration:** none. **Route:** none new. The Super Admin's existing Integration keys read (`GET /api/admin/integration-keys`) gains one read-only field, `gateway_providers`.

### Why

The issue asked for the next model provider beside D851's Anthropic adapter. Its first comment changed the question. Cloudflare now runs third-party models on the same `env.AI.run()` binding Axal already uses, through AI Gateway, billed on Cloudflare credits. So before a second direct adapter, this compares two paths with one working slice:

- **Path A**, AI Gateway on the binding;
- **Path B**, D851's direct adapter, with Axal holding the provider's key.

Its second comment (R2-08) asks for the line between tenant throttling, shared upstream capacity and spending authority to be written down. It does not ask for a quota system here.

### 1. What main does today (audited on `af28b98db`)

- **`ProviderId`** is `'anthropic'` only. **`ProviderUnit`** is `tokens_in` (uncached input), `tokens_cache_write`, `tokens_cached` and `tokens_out`, each priced per 1M.
- **`PROVIDER_MODELS`** has one row, with its printed rates, its page and the date read. **`PROVIDER_PRICING_VERSION`** is `p1-2026-10-21`.
- **The maps.** `PROVIDER_SWITCH` and `PROVIDER_SWITCH_VAR` name the switch, exactly `'on'`. `PROVIDER_KEY_SECRET` names the Worker secret.
- **The caller path.** `runProviderModel` (`services/aiProviders.ts`) checks the switch, the page's AI switch and the key. It holds one `meteredCall` under `exec:<executionId>:<component>`, calls with `fetch`, settles from the reported usage, and writes one `ai_usage_logs` row through `aiRouter.recordUsage`.
  - **Nothing calls it.** Its README says the guard comes first. It runs no Llama Guard, so a member's text would reach the provider unchecked.
  - A failure or a timeout releases the hold. A missing usage settles at the quote, and the row says `usage_reported: false`.
- **`run()`** (`services/aiRouter.ts`) does the same around Workers AI:
  - it takes the hold before the guard;
  - it checks the input guard before the model and the output guard before returning;
  - every guard call is charged under the run's hold, whatever the outcome;
  - the guard rows name the run's row in `guard_for`.
- **Already on Path A.** D1534 and D4316 send Bria and Pruna image tools through AI Gateway on the binding, on the deck's gateway, at a per-image price.

None of these replace Axal's AI token ledger. It stays canonical for member charges: one hold per execution, one row (D844). Cloudflare's spend limits and rate limits are platform fences beside it.

### 4. Logging

- **What is sent.** Every slice call sends `collectLog: false` in the binding's gateway options (documented, 2.1) and `cf-aig-collect-log-payload: false` in `extraHeaders`. The header is the issue's ask; whether the binding forwards it is typed (2.2), not documented.
- **What it gives.** Together these mean no prompt and no answer in the gateway's log. Unified Billing still logs the billing details (2.8), which is what reconciliation needs.
- **What it does not cover.** Logpush exports are not changed by the headers (2.8). No Logpush job may be pointed at this gateway.
- **The test.** `ai_gateway_slice_4556.test.ts` asserts both are on every call.
- **Not verified live.** Proving that the log really holds no payload needs a real gateway and a real call, which this issue does not authorise. `providers/gateway.ts` `logCarriesNoPayload(log)` is the check the owner runs on the slice's own entries (`env.AI.gateway(id).getLog(logId)`: no `request_head` or `response_head`) before the switch goes on. It is tested against fixture entries only.
- **ZDR is separate.** ZDR is a different control: it governs the provider's retention, not the gateway's logs.

### 5. The model and the workload

- **Model: `openai/gpt-5-mini`.** It is cheap ($0.25 / $2.00 per 1M) and a text chat model. Its catalogue page states **ZDR: Yes** (2.4), a published price, and an example answer that names the served model and the key source, which the slice pins. A model whose ZDR or price cannot be read from an official page is not eligible (`zdr_not_confirmed`).
- **Workload: `publication`, data class `public` only.** This is the admin publication summary: 3–5 bullets over k≥5 aggregate rows, written for publication (`services/publications.ts`). It is the least sensitive text task in the router.
  - The slice does **not** rewire `draftSummary`, which keeps running on Workers AI.
  - Pointing it here is an owner decision for after the hosted checks in §9.
  - Every other task is `task_not_eligible`. Every other data class, or none, is `data_class_not_approved`.
- **What it does.** Text only: no streaming, no tools, no structured output, no vision. The row's `capabilities` says so.
  - Streaming is refused by design: the output guard (D763) reads the whole answer first, as `advisor_explain` does.
  - Tools and structured output are left out because no eligible workload needs them.

### 6. What was built

- **`services/ai/catalogue.ts`** gains `GATEWAY_TEXT_MODELS`:
  - one row, with its printed rates, its 128k window, `zdr: 'yes'`, its workloads, and its page and date;
  - `gatewayTextEligibility`, checking ZDR first, then the task, then the data class;
  - the switch, `AI_PROVIDER_GATEWAY_OPENAI`, exactly `'on'`;
  - the config names, `CF_AI_GATEWAY_SLUG_PROVIDERS` and `AI_GATEWAY_PROVIDERS_ZDR`. No value is committed and `wrangler.toml` is unchanged.
- **`services/ai/providers/gateway.ts`** is a pure `GatewayAdapter` beside D851's `ProviderAdapter`:
  - it builds the chat input (`max_completion_tokens`, no `temperature`, never `stream`);
  - it reads the raw `Response` into the answer, the usage, the served model, the key source and the log id;
  - it reads the usage exactly: uncached input = `prompt_tokens − cached_tokens`, and reasoning stays inside the output. Unreadable usage is null, never 0;
  - it maps errors by status and AI Gateway code, and says whether the provider may have done work (`completion: none | unknown`).
- **`providers/types.ts`** adds three error kinds: `refused`, `timeout` and `unknown`.
- **`services/aiProviders.ts` `runGatewayTextModel`** is the shared execution service, extended and not duplicated. In order, each step refusing before the next costs anything:
  1. the switch;
  2. never the Advisor;
  3. the policy;
  4. the window;
  5. the config;
  6. the page's AI switch;
  7. the admission seam;
  8. one `meteredCall` hold (provider quote plus the guard's share);
  9. the input guard, then the call, then the pin (served model starts with `gpt-5-mini` and `keySource` is `Unified`), then the output guard;
  10. one row, with the guard rows naming it.
- **Retries.**
  - Only `rate_limited` and `overloaded`, and only where the gateway refused before the provider ran.
  - At most 3 attempts, waiting the `retry-after` the gateway sent (or a 500 ms doubling backoff), plus up to 250 ms of jitter, within an end-to-end budget of 4 s. A longer `retry-after` ends the run and returns it.
  - The gateway's own retries are off (`retries: { maxAttempts: 1 }`), so every attempt is counted here.
  - Timeouts, 5xx, unreadable answers and unexplained throws are never retried: the provider may have done the work.
- **Charges.**
  - An answer settles at the reported usage times the rates times the member's multiplier, plus the guard.
  - With no reported usage, the provider part settles at its quote (D851's policy): `usage_reported: false`, `reconcile: 'gateway_log'`, with the log id.
  - A failure, a refusal by the model or a pin mismatch charges the guard only, and its row keeps the reported usage and `reconcile: 'gateway_log'`. The platform bears any upstream cost there.
  - A timeout (`completion: 'unknown'`) is not "no work done". Nothing is charged to the member, and the row is marked for reconciliation against the gateway's log.
- **Fallback.** None. A failure never becomes a run on another provider, because the data terms differ. The caller decides, for example by running its Workers AI route through `run()` as it does today.
- **`gatewayProviderRows`** is the admin status. For each row it gives:
  - `off`, `missing_config` or `enabled`;
  - the switch's value, and the missing config **names** (never the gateway id or any value);
  - ZDR, the workloads, the capabilities, and the rates with their page.
- **`aiRouter.ts`.** All additive; `run()` is unchanged.
  - `providerGatewayOptionFor` builds the slice's gateway option, because only the router builds one (D261, held by `topology_d209.test.ts`). It sets `collectLog: false`, `skipCache: true` and the gateway's own retries off, with metadata of branch, account, task and execution: ids only.
  - `guardFinalText` takes an `'input'` side.
  - `GUARD_CHARS_PER_OUTPUT_TOKEN` is exported.

### 7. The choice

- **Route third-party catalogue models through AI Gateway (Path A).** Keep D851 direct (Path B) only for distinct cases:
  - a model the gateway's catalogue does not carry;
  - a feature the gateway's format drops;
  - a contractual or regional term that needs Axal's own provider agreement;
  - a workload that must not depend on Cloudflare's credit balance.
- **Why A first.**
  - No provider key exists at Axal to leak or rotate.
  - ZDR comes from Cloudflare's catalogue, per model.
  - The call is the binding every Workers AI run already uses.
  - The adapter is one per request format, not one per provider.
  - The cost is the 5% on credits (2.5), and one shared rate limit per gateway (2.12).
- **No second direct adapter is added.**
- **BYOK is not used.** It loses ZDR (2.5) and keeps key custody. It only makes sense for a provider absent from Unified Billing, or to escape the 200/min Unified Billing limit. If it is ever needed, the gateway must keep **Require provider credentials** on, so a missing key never falls back silently to Unified Billing (2.7), or the reverse.
- **Aliases, dynamic routes and `cloudflare/auto` are not used.** Axal's router decides the model. A gateway route could pick another model (2.9, 2.10), so the slice pins the answer's `model` and refuses any other (`terms_mismatch`).

### 8. Shared capacity (R2-08)

This issue builds no quota system. It records what shares what, and keeps the seam ready.

**Inference entry paths and the upstream capacity each shares** (as of `af28b98db`; RPM, TPM and concurrency are Cloudflare's or the provider's published figures, not measured, and no account-specific entitlement has been confirmed):

| Entry path | Upstream | Shared with |
|---|---|---|
| `aiRouter.run()` (most tasks, un-gatewayed), and the Llama Guard calls inside every run | Workers AI binding, per-model account limits | every tenant, every product, every branch Worker on the same Cloudflare account |
| Advisor tasks (`advisor_turn`, `advisor_explain`), through `CF_AI_GATEWAY_SLUG_ADVISOR`, bypassed un-gatewayed on failure | the same Workers AI limits, plus that gateway's own rules | every member using the Advisor |
| Deck runs (`CF_AI_GATEWAY_SLUG_DECK`, empty until the owner sets it) and the deck image tools (Bria, Pruna, Unified Billing) | Workers AI, plus Unified Billing's 200/min on the deck gateway | every account generating decks |
| Agent runs (`AGENT_AI_GATEWAY`) | Workers AI, plus that gateway's limit | every sponsor's agents |
| Live transcription (`liveTranscription.ts`, a WebSocket), document conversion (`toMarkdown`) | Workers AI | as above |
| D851 `runProviderModel` (no caller) | Anthropic's account limits on the one platform key (`AI_PROVIDER_ANTHROPIC_KEY`) | anything that ever uses that key |
| This slice | Unified Billing's 200/min on `CF_AI_GATEWAY_SLUG_PROVIDERS` | every tenant of the slice |

**What the existing governor covers, and what it does not.** `services/decks/aiGovernor.ts` and `durable-objects/ai-governor.ts` cap a deck run's steps per **application account**: 3 image, 6 text and 4 vision at once, 2 runs, and a 20-step token bucket per model per account. Leases expire after 120 s.

- Its state is in memory. A restarted or evicted object starts empty, and a deployment does too.
- A lease that expires while its call is still running upstream frees a slot for work that has not finished.
- A late `release` of an expired lease is harmless only because ids are never reused.
- Without the binding it falls back to an in-isolate governor (tests, local dev). In production that fallback would not be shared across isolates.
- It sees deck steps only. No other path above is counted, so it is a tenant-fairness throttle for decks, not an upstream quota across tenants and products.

**What stays separate.**

- **Tenant fairness:** the governor, and future admission.
- **Shared upstream capacity:** nothing enforces it today. Cloudflare's own 429s are the backstop.
- **Spending authority:** D844's hold and settlement in D1. It stays canonical, and no throttle or gateway spend limit replaces it.

**The seam.** `runGatewayTextModel` takes `deps.admit`:

- it runs before the hold;
- a refusal, or a check that throws, calls nothing (`capacity_unavailable`);
- an admitted lease is released once, in `finally`.

Absent, no capacity check runs, and it is never treated as a check that passed for anything but this slice. #4594 hosts the orchestration proof with stubs and the restart-safe lease strategy (eviction, deployment, a lease expiring during a stalled call, a duplicate or late release, a missing binding). #4573 and #4559 measure queue wait, throttling, retry amplification, useful completion and cost. #4575 consumes the restart and reconciliation evidence.

### 9. Not built, and why

- **No gateway, credit, switch, secret or `wrangler.toml` change.** The issue forbids them. Turning it on is the owner's, in this order:
  1. create an authenticated gateway of its own, with ZDR on, logs off by default, no Logpush, and **Require provider credentials** off;
  2. buy credits;
  3. set `CF_AI_GATEWAY_SLUG_PROVIDERS` and `AI_GATEWAY_PROVIDERS_ZDR = "on"`;
  4. run one synthetic call on a branch and read its log with `logCarriesNoPayload`;
  5. confirm the raw body carries `model` and `gatewayMetadata.keySource` (the pin refuses any answer without them, so a raw body that lacks them refuses everything rather than passing);
  6. send OpenAI's sub-processor notice (#1008);
  7. set `AI_PROVIDER_GATEWAY_OPENAI = "on"`.
- **No caller.** No route or job calls `runGatewayTextModel`. Wiring `publications.ts` to it is a separate, owner-approved change.
- **Not verified live:** that `returnRawResponse` and `extraHeaders` behave for third-party models as they are typed (2.2). That needs a hosted call.
- **BYOK cost in practice:** not compared. No BYOK key may be created.
- **Missing usage.** Settling it from the gateway log afterwards is not built: a settled hold cannot be adjusted without a ledger change. The row carries the log id, and the quote is the ceiling charged.
- **Replays.** A replay of a **pending** execution (two concurrent calls under one id) is D844's behaviour, unchanged here. A replay after it settles is refused (`execution_closed`), as tested.
- **The production Advisor stays Workers-AI-only.** This path refuses Advisor tasks, surfaces and pages. A test walks the import graph from every Advisor module and fails if `aiProviders.ts` or any provider adapter becomes reachable.
- **The CI guard.** `scripts/ci/no-anthropic-in-prod.mjs` already fails on main, before this change, on D851's files and two route comments (`routes/auth.ts`, `routes/dashboard.ts`). It is not wired into `test:drift` or any workflow. This change adds no file to that list: the test asserts it, and `gateway.ts` carries none of the guard's tokens. Fixing the five pre-existing hits is outside this issue.
