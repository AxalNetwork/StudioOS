## D5924 — Licences v2 Operations: deployment healthy and failed, with Retry sync and Reconcile (L14, L15) (#5924)

Built for #5924, part of #4819 (`D4819.md`, whose part 3 placed branch sync on Operations › Branch and domain). It redraws that tab's branch sync and deployment to boards L14 (synced) and L15 (update pending, last attempt failed) of `design/incoming/Licences v2 Page.dc.html`. It is frontend only: no Worker change and no migration. `admin_deployments.ts` is not touched, because #5925 (PR #6380) is changing it.

### Backend check

Each value was checked against the read it comes from, on main as it stands:

- **HQ revision, branch revision, when the branch accepted it:** `sync` on `GET /api/admin/licences/:uid` (`services/licenceSyncView.ts`, #4686), from `licence_sync_state` (`hq_revision`, `branch_revision`, `last_success_at`). An unreadable table arrives as `available: false`.
- **The copy that is owed:** the same `sync.pending`, from `licence_push_pending` (`revision`, `failure_code`, `attempts`, `last_attempt_at`). An unreadable table arrives as `pending_available: false`. A row queued with a change (D4805) has `attempts` 0 and is dated 1970, so the next retry picks it up.
- **When HQ tries again:** HQ's cron re-sends every row whose last attempt is older than `LICENCE_PUSH_RETRY_WINDOW_MINUTES` (60, `services/licencePush.ts`, D272), on a ten-minute tick.
- **Provisioning:** `GET /api/admin/licences/:uid/deployment` (D4706): the identity, `last_failure` with `settled_at`, `failure_code` and `failure_note`, `retryable` and `reconcilable`.
- **Reconcile:** `POST /api/admin/licences/:uid/deploy/reconcile`. It never dispatches. On an open attempt it reads GitHub's runs and settles the attempt. On a settled failure it answers `checked: 'settled'` with the record.
- **Retry (provisioning):** `POST /api/admin/licences/:uid/deploy/retry`, unchanged.

### What the record cannot give yet

- **Retry sync.** No Worker route re-sends a licence copy on demand. The copy is sent when the licence changes, and HQ's cron re-sends what has not landed at most once an hour. So Retry sync is drawn where L15 puts it, **disabled**, with its reason beside it: "HQ has no way yet to re-send a copy on demand. It re-sends a copy that has not landed by itself, at most once an hour." It also says when the next try can come ("not before <time>"). **Read again** re-reads the licence, to see whether HQ's own retry has landed. A Retry sync that pressed into nothing would be a claim. Wiring it needs a Worker route (a re-push through `pushLicenceToBranch` that records its outcome), which this issue's scope does not include. The test fails when such a route appears, so the button is wired then.
- **"France branch responded 6 min ago".** HQ never reads the branch, only its answer to HQ's last push. The line keeps part 3's wording, "Last accepted a copy <time> · revision N", with the sentence that this is the branch's answer to HQ's last push. The branch-side read is #5925 (PR #6380, `sync.branch_report`). Once it is on main, the Sources line can show it beside this one.
- **"Attempt 3 of 3" and "within 60 s".** The pending row counts attempts but records no maximum and no timeout. The card shows the failure code's sentence and "(attempt N)", then the code itself.
- **"France still runs the 30-day payment terms until it receives 143".** No store records what changed between two revisions. The Effect line says what is known: "The branch keeps the copy it last accepted (revision 142) until it accepts revision 143."

### What was built

- **`licenceDeploymentModel.js`.** It adds pure functions:
  - `syncBoard(sync, now)` gives one of six states: `synced`, `pending`, `out_of_sync`, `not_recorded`, `unconfirmed` (the revisions read, the queue did not) and `unreadable`. Only `synced` is drawn as synced. A branch with no accepted revision is out of sync, not synced.
  - `syncSources(sync, host)` gives the two Sources.
  - `agoText` and `whenText` give "4 min ago · 9 Nov 2026, 11:56 UTC".
  - `provisioningLine(view)` gives the failed attempt's time and code.
  - `canReconcile(view)` is true while an attempt is open and on every failed deployment.
  - `noticeForSettled(view)` is Reconcile's answer on a settled failure.
  - `SYNC_RETRY_WINDOW_MINUTES` and `RETRY_SYNC_REASON` support the disabled Retry sync.
- **`licences/LicenceSyncStrip.jsx`, the `strip` part.** It draws:
  - **Sources:** "HQ ledger · Current · revision N" and "Branch at <host> · Last accepted a copy <time> · revision N", kept apart.
  - **L14:** "Synced with HQ", then "Revision N · <ago> · <time>".
  - **L15:** "Update pending", then "HQ revision N · branch revision M · last attempt failed <ago>". Beside it sits Retry sync, disabled, with its reason. The rows are What failed (the code's sentence and the attempt count), Failed attempt (the time and `code <failure_code>`), Effect and Last accepted. Read again sits at the foot.
  - **Queued:** a row not yet tried reads "not attempted yet" and "Why it is waiting", never a failure dated 1970.
  - **Out of sync:** "no copy is queued". When the queue could not be read, it says so with Retry.
  - **Not recorded, Not confirmed, No branch deployed and Sync unreadable**, each a word and a shape (`data-state`). The unreadable states say what could not be read and offer Retry. The strip used to vanish when the sync record was unreadable; it now says so.
- **`LicenceDeploymentAttempts.jsx`.** It adds `ProvisioningLine` (L15's Provisioning row). A failed provisioning shows "Failed · <time> · code <failure_code>" with **Reconcile deployment**, beside Retry. Reconcile posts to `deploy/reconcile`, dispatches nothing, and says what the record holds: "Reconciled. Attempt N is recorded as failed (code), and nothing was sent. Retry starts attempt N+1." While an attempt is open, Check status is the same reconcile, so Reconcile is not drawn twice. An unreadable deployment read is now Unreadable with Try again, not a bare red line.
- **`licences/DeployStep.jsx`.** The deployment is its own card, headed Deployment, under the sync and domain strips. The chips and notes carry dark pairs. An unreadable registry is Unreadable with Try again, not a dead end.
- **`licences/LicenceDetail.jsx`.** One call changed: the strip is passed `deployment`, `deploymentAvailable` and `onReread={load}`. That file is also edited by #5927 (PR #6333), in other hunks.

### Departures from the canvas

- **Layout.** The canvas puts the Provisioning row inside L15's sync card and the deployment rows inside L14's. Here, provisioning is the Deployment card's first row, under the domain strip, because part 3 placed the domain strip between the two and `LicenceDetail.jsx` is shared with #5927.
- **Reconcile deployment is a button, not a "…" link.** It opens no sheet: it is a read and changes nothing. The consequence sheet is L17 (#5927).
- **No "Deploy branch…" on a deployed licence.** No route redeploys an existing deployment. The first Deploy form stays for a licence with none.
- **"Deployment: axal-fr · production · healthy" and "Last deploy … · succeeded".** These come from today's reads: the host, the status chip, the live chip, the last deployed version, and the attempts summary's last success.
- **States the canvas did not draw:** queued, out of sync, not recorded, not confirmed, no branch deployed, unreadable.
- **Phone and dark.** The canvas has no 390 or dark board for L14 or L15. Below 640px the card stacks, Retry sync, Read again and Reconcile become full-width 44px targets, and long hosts break. Dark uses Tailwind pairs (`check-dark-mode` passes).
