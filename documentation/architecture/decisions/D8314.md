## D8314 — GitHub alerts: sparse checkouts carry what their scripts import (#8314)

- **Status:** built 2026-11-23. Repairs #8314 and #8312 (`[Actions] .github/workflows/github-alerts.yml failure on main`).
- **Cause:** #8104 (e627d1495b) made `scripts/merge-policy.mjs` import `merge-control/src/lib/classify.mjs`. `scripts/github-alerts.mjs` reaches it through `scripts/lib`. The `queue-stalled`, `main-red`, `queue`, `future-clock` and `file-backup` jobs checked out `scripts` alone, so every scheduled run of them on main stopped with `ERR_MODULE_NOT_FOUND` before reading anything. Only `queue-deadline` (#8164) already listed `merge-control/src/lib`. Claude review's `alert` job (`review-blocked`) had the same gap; it runs only when a review is blocked, so it had not failed yet.

### What changes

- Those five jobs' sparse checkouts, and Claude review's `alert`, add `merge-control/src/lib`. No script, permission or schedule changes.
- `frontend/test/workflow_sparse_imports_8314.test.mjs` reads every workflow. For each job that checks this repository out sparsely at the workspace root, it walks the relative imports of each `node <script>` the job runs. It fails when an imported file falls outside the checkout (cone mode: everything under each listed directory, plus the files directly in each of its parent directories).
  - A checkout into another `path` or of another repository is out of scope: the planner's `control/` checkout is read at a pinned revision.
  - Package imports are out of scope: they come from `npm ci`, not the checkout.

### Rollback

Revert the PR. The five jobs fail again on their next scheduled run.
