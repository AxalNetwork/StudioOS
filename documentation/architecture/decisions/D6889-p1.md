## D6889 part 1 — The closing workspace shows actor names, the phone verifier and In Portfolio (#6889)

The Worker half of #6889 (D6889, PR #6910) added three records to the reads
the closing workspace (D6866, PR #6892, canvas D6158) already makes. This
part draws them where the canvas does. Frontend only: no route, Worker or
schema change.

**Files.**
- `frontend/src/pages/investor/deals/closingWorkspaceModel.js`: `auditRows`
  takes the closing event's `actor_name`; `transferRows` carries the
  verifier; new `phoneCell`, `transferBody`, `verifierOptions`,
  `portfolioRows` and `companyHref`.
- `ClosingWorkspace.jsx`: the verifier under Phone verified, and the Record
  in Portfolio table after close.
- `ClosingZone.jsx`: the verifier field in the Record transfer dialog.
- Test: `frontend/test/deals_closing_records_6889.test.mjs`. Three tests
  that read these files change with them: the 6866 Audit test (Not
  recorded), `investor_deals_id4` (the zone's call list gains `listUsers`)
  and `investor_deals_closing_money` (the body is built by `transferBody`).

### 1. The actor's name in the Audit tab (DX20)

A closing event's row names `actor_name`. When the read has none (the
account is gone or has no name) it reads "Not recorded", the shared
`NOT_RECORDED` from `lib/absence.js`. It never takes another name, and "Name
not shown yet" is gone from closing events. The tab is still not drawn for
an investor, whose read carries no events.

### 2. The phone verifier (DX19)

- **On the transfer.** The Phone verified cell reads Yes with "by <name>"
  below it, or Yes with "by Not recorded" when no verifier was named (every
  transfer recorded before D6889), or No. The recorder's name never stands
  in for the verifier.
- **In the Record transfer dialog.** An Admin gets a "Who confirmed them by
  phone" select of the Admins (`GET /api/users?role=admin`, an Admin's read,
  asked once when the dialog first opens). The caller is first, as "You ·
  <name>", because the verifier may be the recorder (owner answer 1 A). Only
  Admins are listed (2 A); an inactive account is not. The field is off until
  "Instructions verified by phone" is ticked, and unticking clears it.
  "Not recorded" is the default and sends nothing. A picked verifier is sent
  as an integer `phone_verified_by` only with `phone_verified: true`. The
  Worker checks it; its refusal (`phone_verifier_invalid`,
  `phone_verifier_without_verification`) shows in the dialog as given.
- **Anyone else** never sees the field. The Worker refuses a non-Admin's
  transfer anyway (D1215). If the Admins list cannot be read, the field stays
  off and says so, and the transfer still records.

### 3. In Portfolio after close (DX23 A)

Once the closing is closed, the close panel lists each received line
(withdrawn lines are not listed) with its amount, the day its receiving
evidence was accepted (or recorded), and In Portfolio or Not in Portfolio,
each as a word and a glyph.

- **An Admin** reads `portfolio_position_uid`. In Portfolio links to the
  venture's Portfolio page, `/portfolio/companies/<project uid>`. The project
  uid comes from `GET /api/positions` by the closing's `project_id`; that read
  is asked only by an Admin, only when some line is in Portfolio. The
  position's uid is printed under the label. If the positions read fails, or
  no row lists the venture, the label stays without a link and says why.
- **The founder** reads `in_portfolio` only (owner answer 3 A), so the label
  has no link and no uid. The founder does not reach `/deals/closing` today
  (the route admits Admin and investor); the model draws the founder's read
  correctly for when the route opens.
- **An investor's** read has neither field, so nothing is drawn.
- **No guessed link.** The label is the Worker's `closing_line_uid` link and
  nothing else. A stray uid on a line that is not in Portfolio links nothing.

### Where this departs from the canvas

- **Record position.** DX23 A draws a Record position button that opens
  Portfolio with the venture, amount and date filled in, naming the line.
  No Portfolio form takes a closing line today. The table instead says to
  record the position in Portfolio and name the line. That form is its own
  issue.
- **The link target.** No page opens one position by its uid. The link goes
  to the venture's Portfolio page, which lists the position among its rounds.
- **The after-close figures** (lines received, total received, executed
  paper, reporting duties) and the cap-table card on DX23 A are not part of
  #6889 and are not built here.
