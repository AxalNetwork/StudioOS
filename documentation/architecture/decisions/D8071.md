## D8071 — Agent execution budgets: tokens, minutes, PRs per day and retries, per agent, task and workspace (#8071)

**Decision date:** 2026-11-22. **Scope:** the agent engine's `run` step, the trusted publisher's broker, HQ's policy
routes and one sponsor read. One migration, expand only. No frontend: the budget panel waits for its canvas.

### What changes

- **Caps.** Each agent can have a monthly cap on tokens and on minutes, a cap on PRs per day and a cap on retries per
  task (`agent_budgets`). A task can narrow the tokens, minutes and retries caps for itself (`scope_tasks.budget_*`;
  NULL means the agent's cap). A workspace (a company or a project) has four ceilings on `agent_scope_settings`:
  agents in total, agents live at once, AI spend per month and compute spend per month. NULL means the platform's
  figure on `ai_agent_policy.workspace_*`, and a NULL platform figure means no ceiling. A NULL agent cap means no cap.
- **Period.** Tokens, minutes and spend count per calendar month, UTC (`YYYY-MM`). PRs count per UTC day. This is
  option A from the canvas brief (D4137-p3). A rolling 30-day period would only change `monthKey` and `monthStart`.
- **Reserve, then settle.** `services/agentBudgets.ts` holds both. `reserve` runs just before the `run` step's model
  call (`loop.ts`, one call). It takes an estimate: the prompt's length in characters divided by 4, plus
  `AGENT_MAX_TOKENS`. It refuses when that would pass any cap. `settle` runs after the call (one call) and adds what
  the usage ledger recorded for that call to the agent's month: `prompt_tokens + completion_tokens` and `latency_ms`
  from `ai_usage_logs`, guard rows included. Settlement is keyed `run:<run uid>:<step>` in
  `agent_budget_settlements`, so a retried step settles exactly once. A step that has already settled passes
  `reserve` on its replay, which charges nothing. `agent_budget_usage` is a per-period counter, not a second ledger
  of charges: every figure in it comes from `ai_usage_logs`.
- **Publish.** The broker calls `reservePublish` after the `code.pr` capability check and before anything is reserved
  or sent to GitHub. It calls `settlePublish` once the draft PR is open, keyed `publish:<idempotency key>`, so a
  publication counts once. A failure to count is logged and never fails a PR that is already open.
- **Halting.** On exhaustion the run ends `halted`, with refusal `budget_exhausted`, and the task is open again.
  The step's line in `steps_json` (D1528) names the cap, the amount used and the limit, for example
  `Halted: budget exhausted, the agent's tokens this month: 0 of 100.` Nothing is truncated. A cap whose usage cannot be
  read halts with `budget_unreadable`, because an unknown figure is never treated as zero.
- **No raise above the platform.** This is option A from the brief: a workspace's ceiling can never be above the
  platform's. The route refuses it with `409 above_platform_ceiling`. If the platform figure is later lowered,
  `reserve` takes the smaller of the two, so the platform figure always wins.
- **Routes**, all on `/api/admin/ai-agents/policy`. Each one is Super Admin only, and every write is audited (before,
  after, reason) in the same batch as the change: `GET /budgets`, `PUT /budgets/agents/:uid`, `PUT /budgets/tasks/:uid`,
  `PUT /budgets/workspace` and `PUT /budgets/platform`. The sponsor has one read-only route,
  `GET /api/teams/agents/:uid/budget`, which returns caps, usage this period and the runs halted for budget.

### Rate card (compute spend)

A compute job (`agent_compute_jobs`) is priced from its recorded resources:

| Resource | Price |
|---|---|
| vCPU time (`cpu_ms`) | 0.02 micro-USD per millisecond (USD 0.000020 per vCPU-second) |
| Wall-clock time (`wall_ms`, 1 GiB held) | 0.0025 micro-USD per millisecond (USD 0.0000025 per GiB-second) |

A job that is still running has no figures yet and costs nothing until it ends. The constants are `RATE_CARD` in
`agentBudgets.ts`. Changing a price is a change to that constant and to this table.

### Not in this change

- **The budget panel** (`frontend/src/pages/hq/aiAgents/BudgetPanel.jsx`, boards SA15 to SA19) is deferred. Its
  canvas (PR #8100) has not landed, and no layout is built without it. The routes above are what the panel will read.
- **Production deploys per day** for agents stay at 0, through the capability task (D8070's reserved
  `deploy.production`), not through a cap here.
- **Admission is unchanged.** A run past a cap is admitted and then halts at its `run` step before any model call.
  The sweep may admit the task again later. That run halts the same way and costs nothing.

### Rollback

Revert the PR. The Worker one version back reads none of the new tables or columns, and they stay in D1, empty or
unused. This follows the expand-then-contract rule: no data or setting needs to be undone.
