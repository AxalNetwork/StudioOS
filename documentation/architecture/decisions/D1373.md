## D1373 — An unread Meet pre-join page says what kind it was

- **Status:** a fix, from the first live run that carried D1368's diagnostic (2026-10-29, 11:07Z). Built by S21.
- **Builds on:**
  - D886: the meeting bot, and its privacy rule;
  - D1368: a failed run records where it stopped.
- **Migration:** none. The bot image ships through `meeting-bot-deploy.yml`.

### What the live run showed

With D1372's Start fix live, the owner's Meet call created a run. It failed with `platform_blocked@meet_prejoin_result:unknown`. The bot opened the link, and within 30 s it saw none of its pre-join hooks:

- no Ask to join;
- no Join now;
- no waiting room;
- no refusal.

Google showed it some other page. `unknown` does not say which one, so no fix could be checked against a cause.

### What changed

An `unknown` pre-join page is named by kind in one more code-only log line, `meet_page_<kind>`. That line becomes the run's `failure_detail` (`platform_blocked@meet_page_<kind>`). The kinds:

- `signin`: Google sent the bot to `accounts.google.com`, so the meeting wants a signed-in account;
- `other_host`: another host;
- `unsupported`: Google declined this browser (`unsupported_browser` hook);
- `name_only`: the guest name field with no join button, so the join button's hook is what is wrong;
- `unread`: a Meet page none of the hooks match.

### What was not done

The bot does not hide that it is an automated browser. It does not change its user agent and does not turn off Chromium's automation flags.

If Google declines it (`unsupported`, `signin`), these are the routes that remain:

- **A signed-in account:** the dedicated account in #3678, if Google's terms allow it for this use.
- **Google's own interfaces:** Meet's transcript import, which is already wired for Workspace calls (D871), or the Meet Media API.

That choice is the owner's.

### Privacy

The kind is read from the page's host and two hooks. The address, the page text and any name are never logged or stored, as D886 requires. The new hook is in `selectors.ts` with its own selector test, and it marks a fixture page, `unsupported`, that was CONSTRUCTED, not recorded.

### Verified

- **Bot suite:** passes on real Chromium. New tests cover:
  - each page kind on the fixture;
  - the pure classifier.
- **Mutation check:** without the page-kind line, two adapter tests fail.
