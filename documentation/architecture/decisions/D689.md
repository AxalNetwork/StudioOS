### The rulings

1. **D-a. The spacing mismatch was the shell's inset, not the cards.**
   - **The cause.** The overview path was full-bleed, so it drew only `CycleRoute`'s own `p-5`. Module, action, record and add paths were not in `FOUNDER_FULL_BLEED`, so the shell added `p-4 md:p-6` and `max-w-7xl` on top.
   - **The fix.** One predicate, `isCyclePath()`, derived from the module lists, makes every cycle path flush.
   - **The gutter is the canvas's:**
     - `22px 24px 30px` at 1024px and up;
     - `14px 14px 40px` in a cycle column under 760px;
     - `14px 22px 18px` below 1024px. The 14px top moves from each phone screen's first block onto the body, a recorded departure.
   - **Unchanged:** card paddings stay as drawn. (#1655, `D694.md`)
2. **D-b. The three pages went last, and nothing they did was lost.**
   - **Features moved first:** the bottom sections and the Customer research record (#1659), the record pages (#1658) and Verdict (#1704).
   - **Then #1666 redirected each old path, keeping the query:**
     - `/validate/interviews` → `/validate/customer-research`;
     - `/validate/pain-map` → `/validate/problem-discovery`;
     - `/validate/hypotheses` → `/validate/experiments`;
     - `?new=record` → `/validate/record`;
     - `?new=notes|upload` → `/validate/customer-research?log=notes|upload`.
   - **What this supersedes and builds:** it supersedes D685 §3.1 and §5.9.6, and it builds D661's planned redirects, which had never shipped.
3. **D-c. A record is a page at `/:cycle/:slug/:id`, inside the cycle chrome. Only Add is a lightbox.**
   - **Customer research.** Its record is the interview, at `/validate/customer-research/:id`. `/validate/interviews/:id` redirects there.
   - **Data room.** For founders, `/raise/data-room` became the Data room module. Its two tools are at `?mode=workspace` and the read-only `?mode=access`. A file's Manage access opens the workspace tool.
   - **Ids.** They match `^[a-z0-9][a-z0-9_-]*$`, stay the same across sort and page, and never carry a person's name. (#1658, #1659, #1699, #1657)
4. **D-d. Add is the canvas's centred 560px lightbox on every module, and a page below 1024px** (`/:cycle/:slug/new`).
   - **The component.** It is built on `ui/Lightbox.jsx`, which brings D686's Escape stack, focus trap, `inert` and scroll lock. It replaced `RecordFormSheet`'s side sheet for every Add and Edit.
   - **Copy and options.** Copy is the canvas's `A` table, byte for byte, unless D-s rewords a line. Chips come from the Worker's `form-options` read.
   - **Edit** is the same form, titled "Edit \<noun>", with "Save".
   - **The two exceptions.** Customer research's Add opens Record a session, and Verdict's opens Record a decision. (#1656, #1657, `D695.md`)
5. **D-e. The backend is built behind every field, Worker first.** All 27 modules got:
   - the one-record read and its paged activity;
   - one action route per record;
   - a `form-options` read;
   - a POST and a PATCH for every Add form;
   - stable row ids, and the canvas's lists.

   A module read sends `records.linkable: true` only once its cycle's record service is registered, so no row links to a 404. Fields with no store got migrations 459–464. `services/cycleActivity.ts` logs every cycle write. Old rows are read in their old shapes and never rewritten.
6. **D-f. Verdict is Validate's seventh module, and partners never see a decision.**
   - **The schema.** Migration 464 added the decision's hypothesis, its supersession, its state (given or withheld) and its pivot hypothesis, plus evidence and commitments tables.
   - **The evidence bar.** Below `DECISION_EVIDENCE_BAR = 5` checked evidence items, contradicting ones included, a decision is recorded as Withheld and never supersedes. `VALIDATION_BAR` keeps its own meaning.
   - **Partners.** Every Verdict surface checks `canReadDecision`, because the cycle read admits partners.
   - **The rest.** The memo is a client one-page PDF. Decision activity rows carry the decision and its scope, never the reasoning. (#1702–#1704, `D693.md`)

### Session 1's rulings on the reconcilers' points

Each was checked against `main` at `def640f651` when this file was written. All four stand as built.

1. **#1665's action page draws at the action `Mount`, with its own copy of the gutter (`PHONE_GUTTER`), not inside the body.**
   - **Why.** The `Mount` sits after #1655's size container. Share an update's page holds a `fixed inset-0` dialog, its nested Connect a tool, which must not sit inside a size container.
   - **The cost.** While a phone shows an action page, `CycleRoute` draws neither the container nor the body. `D703.md` records it.
2. **`PUT /api/company/visits` refuses an impersonation token in the Worker (403). An HQ support session or an admin's view-as is refused on the client only.**
   - **Why that is enough.** The route records the caller's own visit, keyed by the caller's user id and the caller's own `user_company_links` row. So a support session can at most record the admin's own visit to a company the admin is linked to, never a founder's.
   - **No Worker change.** `D699.md` records the client rule.
3. **`CYCLE_STORES` and `first_kpi` answer different questions, and stay separate.**
   - **`CYCLE_STORES`** (`services/companySheet.ts`) marks a cycle Active on the company sheet when one of its modules' own stores has a row.
   - **`first_kpi`** (`services/cycleFocus.ts`, `growNothingRecorded`) shows only when nothing at all is recorded in Grow. That covers recurring revenue, metric snapshots, open roles, custom KPIs, the company roster and the checklist.
   - **What they share.** Seeded obligations count in both. If the owner chooses to leave them out (#1008 item 25), both change together.
4. **No rail button on `/trust`, `/calendar`, `/my/events`, `/help` or `/plans-and-pricing`.** None of them mounts a `WorkerRail`, so none had Eadwyn. Adding a rail would change their desktop pages, which D689 did not ask for. `D700.md` records it.
