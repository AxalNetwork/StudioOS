### 1. What can be exported, and by whom

Two modules have an export: Product improvement (its Feedback table) and
Revenue and traction (its KPIs). Any other Grow module is a 404 naming the
module ("Distribution has no export"); a slug that is not a Grow module is the
read's own 404.

The gate is the one every Grow write uses: `project(…, write = true)`, that is
`canAccessProject` with `write: true` (the owner, a co-founder member, a
partner, an admin). An advisor member reads the table but cannot export it
(403, "You can read this venture but not change it"); another venture's founder
gets 403. A file is a copy that leaves the app, so it asks for the stronger of
the two gates the page already has rather than a new one.

The module read carries `records.can_export`: true for a writer on one of the
two modules, false otherwise. The page draws Export only then.

### 2. What a file holds (owner decision)

**No email, ever.** The export discloses nothing the page does not:
`product_feedback.from_email` is never a column, for anyone, writers
included. The customer's name (`from_name`) is a column only for a writer,
by the same rule the Feedback read applies (decision 9; the read builds the
rows through the same `recordsFor`). Because the export is writers-only, every
file today carries the From column; the builder keeps the rule so that a wider
gate could never widen the disclosure with it.

**The table's own search, filter and sort.** The route runs `shapeRecords` on
the rows `recordsFor` built, with the same `q`, `filter` and `sort` the module
read takes, so a file is the table on screen, every page of it.

**KPI history is monthly, because that is what is kept.** A KPI keeps one row
per day per source; its record's History (D691) reads the last value each
month held. The export writes exactly that: one line per KPI per month, newest
first, every stored month (the record shows the last twelve), with the note
"Last value held in this month" on each line. It is not every entry. A KPI with
no stored month is one line with empty cells and its reason ("Not recorded: needs
cash and burn"). A PostHog KPI has no stored months on this side, so its line is
its current reading, saying so.

**Money states its currency.** A money KPI's value is in `Amount (cents)` with
`Currency` = `USD` and `Unit` = `cents`; MRR and Burn, kept as whole dollars in
`project_metrics`, are converted to cents in the file. A count, a percentage or
months is in `Value` with its unit. A missing value is an empty cell, never 0;
a recorded 0 stays 0.

### 3. CSV hygiene

Every field goes through `services/csv.ts` `csvSafe`: quoted on `"`, `,`, CR or
LF, and a cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return
gets a leading apostrophe so a spreadsheet cannot run it; a plain number such
as `-42` is left as a number. This is the rule `capTableRegister.ts` and
`fundAdminLpsCsv.ts` already apply privately; it now lives in the shared module
so the next export does not write another copy (those two are left as they
are). The response is `csvResponse`: `text/csv; charset=utf-8`,
`Content-Disposition: attachment` with a sanitised filename
(`feedback-<project>-<date>.csv`, `kpis-<project>-<date>.csv`),
`Cache-Control: no-store` and `X-Export-Rows`.

### 4. The row cap

A file holds at most 5,000 data rows (`GROW_EXPORT_ROW_CAP`). Past it the
route refuses with 422 and a sentence that names the cap and the count ("This
export holds at most 5,000 rows and 5,001 feedback rows match. Narrow the
search or a filter, then export again."). It never returns a cut-short file that
looks complete. The page shows the sentence beside Export.

### 5. The activity log

Each export is logged through `logGrowWrite` (the Grow cycle's
`logCycleWrite`), as `grow.product-improvement` / `grow.revenue-and-traction`,
action `grow_feedback_exported` / `grow_kpis_exported`, `entity_id` NULL (a
module-level row, which no record's history returns), with the row count only:
never the search text or a name. The row is written before the file is
returned, so no log row means no file; a refused export logs nothing.

### 6. Opt-in on the shared page

`CycleModulePage` draws all four cycles' modules, so Export is not on by
default: it appears only when the caller passes `onExport`. `CycleRoute`
passes it only when `canExport(cycle, slug)` (the client's table of exports,
two Grow modules today) and the read's `records.can_export` are both true.
The phone module page does not draw Export yet.
