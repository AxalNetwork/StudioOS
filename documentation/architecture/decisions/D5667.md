## D5667 — Release evidence and operational routing (#5667)

The first slice provides a policy callback for the existing PublicationRelay.
An event with an authoritative release ID and deployment target uses a release
subject keyed by both. Distinct releases of one SHA retain distinct subjects.
Unassociated releases keep the caller's routine history policy.

The phase reader accepts only matching release ID, target and immutable SHA.
For each phase it selects the newest run, attempt and recorded timestamp.
Missing approvals, migrations, publication, smoke, parity, rollout and rollback
remain unknown. A migration command receipt does not assert a data mutation.
Contradictory receipts at the same source position are refused.

The phase reader and policy are tested through the existing relay/presentation
boundary with synthetic evidence. This is a partial implementation of #5667.
Live receipt acquisition and authorized association, scheduled-job inventory,
on-call policy, restricted-security routing, and destination-owner activation
remain outstanding. No live transport or runtime has been activated.
