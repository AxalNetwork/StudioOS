## D1493 — Event syndication, SY8: Ask proposes a channel's title and description (#3906)

- **Status:** the Worker part, built by the S33 session in slot S26, 2026-11-01. Part of #3906. The screens follow #3706 (the Ask panel).
- **Basis:** `origin/main` at `0b3f116d9c`; the issue's specification; D1490 (Part A, merged as #3911) for the per-event rows, the gate and the eligibility sentences; D1491 for the board.
- **Migration:** none. **`wrangler.toml`:** unchanged.

### What was decided

- **One rail option, `draft:syndication-copy`.** It runs once per press through `run()` on `rail_write`. Its page is `<Profile> · Events`, the key `frontend/src/lib/railPages.js` gives the events a member manages; its record is `events:<id>`; its page path (D552) is `/my/events` (`AI_SURFACE.eventSyndication`). It is charged to the member who pressed.
- **Quoted first.** `POST /api/events/:id/syndication/assist/quote` answers the hold and the model ("Holds up to $x · you pay what it uses"), or `ai: false` with the reason, and writes nothing: no hold, no run, no proposal.
- **Input:** `account_uid`, and `fields`, one or both of `title` and `description` (both by default). The model reads the event as it is stored (title, type, start, where, place, summary, description) and is asked for the channel's own limits.
- **Output:** one `ai_rail_proposals` row per field the answer filled, `kind: 'proposal'`, payload `{ account_uid, channel, field, value, source }`. Each value is cut to the channel's `title_limit` or `text_limit` from the registry (Part A's 200 and 5000 while the channel has no adapter), on a word where one is near. An answer that fills no field is 422 `nothing_proposed`.
- **Nothing in the run writes an override or posts.** Accept is the existing `POST /api/ai/rail/proposals/:uid/decide`; the page then saves the value with Part A's `PUT /api/events/:id/syndication`, and posting still waits for Approve and publish. A test holds `event_syndications` empty through a run and an Accept.
- **The gate, in order:**
  1. signed in;
  2. `canManage`, the host or an admin, else the same 404 as Part A (a missing event reads the same);
  3. not a support session (403);
  4. a public event, else 409 `not_public` in Part A's sentence ("Private event"), before any quote or hold; an unlisted event is refused the same way;
  5. an account the event may use (404 `account_not_found`).
- **A run's refusals** answer as every rail press does (`refuseRun`): 402 for out of tokens or a budget stop, 403 for AI off or a pause, 422 for the guard.
- **Logs** carry codes only, never the event's text or the model's answer.
- **No suggestion chips** on an admin console (#3706 AK19): this decision adds no client and no screen.
