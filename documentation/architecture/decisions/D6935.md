## D6935 — Automate Code Scanning trackers and draft fix PRs (#6935)

When CodeQL or Semgrep successfully uploads a scan on a push to `main`, a separate job dispatches `scan-remediation.yml` on `main`. The dispatch job has only `actions: write` and runs a fixed API request. Scanner and pull-request jobs retain their existing permissions. A two-hourly sweep picks up the existing backlog, pending fixes, and work missed when GitHub coalesces runs. A repository-wide concurrency group serializes reconciliation. Each automatic sweep rotates through up to five open alerts and verifies up to twenty tracked alerts absent from the open list. Manual runs with an alert number target just that alert.

### Tracker and fix lifecycle

The GitHub alert number identifies the work. Public trackers contain the number, restricted alert link, and work status. The reconciler checks for existing trackers and fix PRs before generating a classic GitHub Autofix suggestion. GitHub CodeQL fixes with a usable suggestion produce a draft PR with the `security-scan` label. Other scanners, including Semgrep, get a tracker for manual remediation. Pending suggestions can be picked up on a later sweep. Alerts without a usable suggestion stay available for manual remediation. The automation respects human assignments, slot claims, and commits on prepared branches. The PR references the tracker without a closing keyword so a subsequent default-branch scan can confirm the alert is fixed before the tracker closes.

The reconciliation job checks out the trusted workflow commit from `main` and never executes the proposed patch. Code Scanning, CI, reviewers, and the merge queue validate the generated change through the usual PR path. The existing combined scanner incident remains a summary of new findings on `main`.

### Run and credentials

Once this workflow is on `main`, use **Actions → Remediate code scanning alerts → Run workflow** on `main`. Leave the input empty to run a backlog sweep or enter one positive alert number. Equivalent commands:

```sh
gh workflow run scan-remediation.yml --repo AxalNetwork/StudioOS --ref main -f alert=''
gh workflow run scan-remediation.yml --repo AxalNetwork/StudioOS --ref main -f alert=ALERT_NUMBER
```

On 16 November 2026, the organization setting for Actions-created PRs was off, the repository checkbox was disabled, and the dedicated remediation secrets were absent. In this configuration a confirmed PR-creation policy refusal leaves a prepared branch, records its compare link on the tracker, and lets the sweep continue to other alerts. A later run can publish the draft when credentials permit it. Other permission and rate-limit errors surface as run failures.

The default credential is the job's `GITHUB_TOKEN`. For it to open PRs, **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests** must be enabled and permitted by organization policy. The workflow only creates drafts. GitHub requires a maintainer to approve workflow runs triggered when this token opens a PR. StudioOS recognizes its own generated remediation PRs at opening, so the scanner can select them before the label is added.

For automatic PR checks, install a dedicated GitHub App on StudioOS with repository **Contents**, **Issues**, **Pull requests**, and **Code scanning alerts** write permissions. Configure the `scan-remediation` GitHub Actions environment with `main` as its permitted branch and store both environment secrets `SCAN_REMEDIATION_APP_ID` and `SCAN_REMEDIATION_APP_PRIVATE_KEY`. Each run mints a short-lived token scoped to this repository. A partially configured pair fails explicitly. The `security-scan` label event from the App also requests the scanner run. Review and merge remain with the repository’s usual reviewers and merge queue.

If the scan API or PR creation returns a permission error, inspect the workflow run, check the credential and repository setting, then rerun. To pause remediation, disable **Remediate code scanning alerts** in Actions and remove the dispatch jobs in the scanner workflows if pausing beyond a short incident. To roll back the automation, revert this change. Existing issues, branches, and PRs remain available to maintainers.
