## D7745 part 3 — The store's writes returned as statements, and the Done-when audit (#7745)

**Date:** 2026-11-27. **Status:** Built. Follows part 1 (`D7745.md`, PR #8364) and part 2 (`D7745-p2.md`, PR #8696).

### Why

Part 1 put one `admin_audit_log` row in the same `DB.batch` as each run open, seal, reconcile and removal. The store's
own `openRun`, `sealRun` and removals (#7742, `researchSourceRecords.ts`) run their writes themselves, so part 1
rebuilt those three writes in `researchSourceImports.ts` from the store's exported SQL, and listed "store writes that
return their statements" as a hand-off to #7742. #7742 is closed and no open issue owns the store file, so the variants
are added here.

### What changed

In `cloudflare-worker/src/services/researchSourceRecords.ts`, three variants that return their writes instead of
running them:

| Variant | Returns | The function that now calls it |
|---|---|---|
| `openRunStatements(db, input, { exclusive? })` | `{ run_uid, replayed, manifest, statements }`: the run insert, then the rules insert. A replayed key returns no statements. | `openRun` (batches them) |
| `sealStatusStatement(db, runUid, status, now)` | The status update, with the verified time unless the run is uncertain. | `sealRun` (runs it) |
| `removalStatements(db, scope, input)` | `{ scope, counts, statements }`: the deletes, then the removal record last. | `removePrivateFields`, `removeRecord`, `removeSource` (batch them) |

- **The existing functions behave as before.** Same checks, same reads, same SQL, same batch. #7742's tests are
  unchanged and pass.
- **`exclusive`** swaps in two statements that moved from the import service into the store's `SQL`:
  `insertRunIfNoneOpen` (the run is written only while no run is `running`, `uncertain` or `partial`, the check and
  the insert in one statement) and `insertRulesForRun` (the rules only if that run was written). `openRun` never sets
  it.
- **The import service calls the variants** and adds only its audit row: right after the run insert at open
  (`onlyIfChanged`, so a run that lost the race leaves no row), after the status update at seal, and after the
  removal record at removal. Reconcile was already its own one statement plus the audit row; it is unchanged. The
  copies of the store's open checks and removal statements are gone from the import service.
- **One order of refusals moved at open.** The store's checks (idempotency key, removed source, column rules) now run
  before the import's open-run check. A request that fails two of them is refused by the earlier one. Either way it
  is refused and writes nothing.

### Signed-out callers get 401, not 403

Done when says every route answers 403 to a signed-out caller. The routes answer **401**, and this part keeps it.
`requireAuth` throws `Unauthorized`, and `AUTH_ERROR_STATUSES` (`cloudflare-worker/src/util/authErrors.ts`) maps it to
401 for every gate on the platform. The decision files say the same for their routes ("signed out is 401": D848,
D1082, D1222, D1238, D1591), and about two hundred Worker tests assert it. A 403 here would need a special case in the
shared gate (`researchImportGate`, part 2), and #7746 composes that gate. The issue's point is that a signed-out
caller reads and writes nothing, and test 1 proves that for all eight routes. A member, a plain admin and a branch
deployment get 403, and a support session gets 403 `support_session_refused`, as written.

### The recomputed hash

The body hash is recomputed for every record in a chunk, and a mismatch refuses the chunk by code and record id
(`body_hash_mismatch`, test 4). The stated whole-record row hash stays **declared, not checked**. No package hash
recipe exists: `HASH_RECIPES` is empty, and the recipe is the owner's open question D7742 Q1. None is invented here.
