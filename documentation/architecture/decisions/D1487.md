## D1487 — Private event recommendations, preferences and ranking (#3724)

The owner confirmed S1's defaults on 2026-11-04: Axal events only, free ranking, paid Explain, no attendee information or people-met feature, and recommendations enabled for Explorers. This PR is parts A/B of the tracker; the new ME/NE screens still need their approved canvas.

Migration 709 adds host-set topics, member-owned preferences and feedback, and D1-only event/member vectors. Nothing is added to the shared search index. All SQL binds values; identifiers used for vector caching are fixed statements. Preferences and feedback accept no target user, and support sessions cannot write them. The saved list checks current event visibility.

The recommendation read considers at most 200 upcoming public, published, admin-approved events. It excludes the member's own events, existing active registrations, hidden feedback and events whose registration gate refuses the member. A failed eligibility read fails the read rather than presenting eligibility as true. Each signal reads only the authenticated member's ventures, active rounds, nonarchived segments, published jobs, investor sectors/stages, active advisor services or partner engagements. A missing signal is `not_recorded`; a failed signal read is `unreadable`. Neither becomes zero. Reasons quote these records; they never quote thesis text or inspect attendees. Track affinity keeps today's Explorer words.

Rules score matching records, interests, formats, preferred event types and featured status. A cosine match adds a bounded five-point adjustment. Vectors use the existing fixed 768-dimensional system embedder, cached by model/version and current content hash. At most ten missing vectors are filled per request, including the member vector. Missing, corrupt or failed embeddings fall back to rules. Preferences disabled returns immediately without signals or embedding work. Support-session reads do not fill vector caches. No member is charged for a view.

The new client is ready for the future approved screens; this PR mounts no recommendation UI. Existing suggested-event reads and the paid explicit suggested/rank action remain intact. Topics are accepted on event create/edit and as a bound public-list filter. The dev schema mirrors only the topics column; production uses migration 709.

Validate with the real SQLite route tests, ownership and candidate exclusions, unreadable eligibility, disabled ranking, vector caching/invalidation and the public topic filter. Mutation checks cover each security predicate and honest signal state. Roll back the code; additive stores can remain. No production data or deployment is modified during development.
