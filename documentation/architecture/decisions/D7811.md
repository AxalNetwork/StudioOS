## D7811 — Opt-in formula-safe CSV parity and private-copy debt (#7811)

PR #7546 is merged. The frontend adds csvSafe and toSafeCsv with exactly the
Worker D6103 contract: leading =, +, -, @, tab or carriage-return text receives
one apostrophe before RFC quoting; plain numeric values/text matching
`^-?\d+(\.\d+)?$` stay unchanged. This deliberately prefixes signed percentages,
currency-formatted negatives, a lone hyphen and plus-prefixed phone numbers.
Already apostrophe-prefixed values stay unchanged. Null/undefined remain empty at
the serializer level; callers must supply their named missing-data state.

Both runtimes consume one literal case table. Frontend csvSafe uses String(value)
like the Worker, while the existing csvCell retains JSON serialization of objects.
This distinction is tested, not silently changed. Existing toCsv, downloadCsv and
exportView and all Worker callers are untouched. Adoption is opt-in only.

### Existing callers: possible changes under an explicit later opt-in

For every legacy caller below, formula-leading text (including human-entered
names, notes, titles and labels) would gain an apostrophe; plain negative numbers,
dates, CSV quotes/line breaks and empty cells would not change. Cell values that
are objects would change from JSON to `[object Object]` in the frontend safe API;
callers must construct explicit cell values first. No current caller is switched.

### Private-copy guard

The guard records 30 current quote-doubling file identities (the thirtieth,
hq/aiAgents/registryModel.js, arrived on main with #8485 while this PR was open) and reserves the two
named Markets owner files. It examines executable JS/JSX/TS/TSX (including .mjs/.cjs/.mts/.cts) AST calls to
replace a double quote with doubled quotes, including replaceAll; comments and
type declarations are not implementations. It rejects a new file containing a
copy. It deliberately allows owners to change or remove pending copies without
pinning bytes, helper counts or function names. No pending implementation changes.

### Convention for this plan's future exports

1. The header row is the first line.
2. Missing values say Not recorded or their named state, never blank.
3. A Worker export over its cap refuses with a code and sentence, never a short file.
4. Withheld rows are omitted and counted.
5. Scope, count and date appear in the control label and filename (D7172), and
   in response headers for a Worker export.

This convention does not bind the already filed #7716, #7710 or #7727 issues.
No migration, default output change or private-copy consolidation is included.
