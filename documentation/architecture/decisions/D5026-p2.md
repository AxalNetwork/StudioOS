### L35: the studio's package card

The Licences and Contracts v2 Addendum's L40 lists L35's read as "Studio-side read of package — pending read
#5026". There was none: `GET /api/licence/mine/programs` carries no package and `/mine/program-agreements`
only a `package_key` per agreement. So this part adds one read, `GET /api/licence/mine/package`
(`routes/licence_package_mine.ts`, self-mounted at `/api/licence`):

- The caller's licence is the one `licence_admins` binds them to, as every `/api/licence/mine/*` read does;
  no binding is a 404 `no_licence`, as `GET /mine` answers.
- `current` is D5025's `currentTerm` (the active accepted term, else the latest scheduled one), `next` a later
  accepted term that starts after it ends, and `standalone` D5025's `standaloneGranted` (programs granted that
  no accepted package item names). Each term carries the package name, version, dates, derived state, frozen
  programs and the accepted annual price with its currency.
- It never carries HQ's recommendation, override or its reason, the country snapshot or model, the acceptance
  receipt or who decided. The accepted price is read by the same accounts that already read the licence's own
  fee on `GET /mine` (D797: principal and delegates), so no role is refused.
- On a branch deployment HQ pushes no package copy: the answer is `source: 'copy'`, `recorded: false` with a
  reason, never "no package". A ledger without the offer tables is `recorded: false`. A failed read is 503
  `licence_package_unreadable`.

`subsidiary/licence/PackageCard.jsx` draws it on the Summary tab of `/admin/my-licence`, below the four term
cards: package and version, included programs, standalone extras, annual price, effective dates, status and the
next term. With no accepted term it says **No Axal VC package recorded** and names the standalone grants, or
says none is granted on its own and links to Programs: no package never reads as no programs. A failed read is
Unavailable with Retry; loading is a skeleton. Phone stacks the rows in one column; every light surface has its
dark pair.

Departures from L35: "Next review" is drawn as **Next term** (the accepted next term, or "None accepted yet ·
this term ends …"), because no review date is recorded for a package. The Commercial terms card and its
role-refused state (LX35B) are not drawn: the licence's fees, royalty and payment terms already sit on the
Summary and Terms tabs, and no role below the licence administrators reads this page. The program agreements
table stays on the Contract tab (D5051), not duplicated here.

### End-to-end regressions

`cloudflare-worker/test/package_regression_5026.test.ts` runs the issue's cases through the mounted routes on
SQLite, each read back through the studio's read with no HQ-only word in it: the catalogue seed (four
packages), the country-adjusted comparison, accepting Core Network at an override price, the Full Axal VC
refusal while it holds an HQ-only program (no partial grant), a standalone grant beside a package, no package
with standalone programs, renewal / upgrade / downgrade change reviews, a renewal to catalogue v3 scheduled and
accepted on its day, and the old v2 term reproducible from its frozen record. Branch push failure and the
grant-conflict matrix keep their own cases in `package_offers_5024.test.ts`.

A finding the renewal case records: an offer for the next term is refused (`grant_dates_conflict`) until HQ
extends each retained grant's end date in Program Grants. An offer never stretches a grant on its own; the test
does the extension through `PATCH /api/admin/program-grants/licences/:uid/:program` first.
