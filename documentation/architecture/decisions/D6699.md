## D6699 — Formation: editing the catalogue in a draft, the diff, source checks and restricted places (#6699)

- **Status:** built 2026-11-22.
- **Plan key:** H3 (Phase 4) of #6680.
- **Builds on:**
  - D6689 (C1): the catalogue tables, and the triggers that keep a published version immutable;
  - D6693 (C3): the admin router at `/api/admin/formation/catalogue`, and the allowed fact age (183 days unless `FORMATION_FACT_MAX_AGE_DAYS`);
  - D4357: no figure without a source and a day.
- **Feeds:** #6700 (H4), publishing and counsel's sign-off, which binds to the SHA-256s computed here.

### The problem

Countries are data (D6689), so HQ needs to change them without a deploy: in a draft, never in the published version, seeing exactly what changed, with a record of who checked each source and when. Two people editing the same draft must not overwrite each other.

### What is built

**`services/formationCatalogueEdit.ts`**
- **Rows by key, not id.** A country is `country` and `subdivision`; a form is `form_key`; a fact, fee line, pack item or scenario is its form's key and its own; a question is its form's key (or none) and `question_key`; a rule is `rule_key`. Ids differ between a published version and its draft copy; keys do not.
- **Canonical content.** Each row with its key and values, no ids; a JSON column read as its value (`vocabulary`, `legacy_display`, `options`, `conditions`, `rule`); object keys sorted; rows sorted by key.
- **`content_sha256`** of a version: the SHA-256 of its whole canonical content (no version metadata).
- **`rules_sha256`**: the SHA-256 of the rule set alone.
- **Each form's `templates_sha256`**: the SHA-256 of `{ form_key, templates }`, where `templates` lists each pack item that names a template with `counsel_required` and the SHA-256 of that template's active body (null when it has none, read as the D6693 order gate reads it). A change to a template body changes that form's hash and no other.
- **A row's revision**: the SHA-256 of its canonical row.
- **`diffContent`**: every row added, removed or changed between two versions, table by table, with each changed field `{ field, from, to }`.
- **`restrictedPlaces`**: the restricted places as stored, read on every call.

**Routes** (`routes/admin_formation_catalogue.ts`, the D6693 router, extended):

| Route | Gate | What it does |
| --- | --- | --- |
| `GET /versions` | HQ authoring | every version, newest first |
| `GET /versions/:version` | HQ authoring | its content with each row's revision, and the three hashes |
| `GET /versions/:version/diff` | HQ authoring | against the current published version, or `?against=N` |
| `GET /versions/:version/attention` | HQ authoring | stale facts (recorded or provisional, never checked or checked before the allowed age) and disputed facts |
| `POST /drafts` | HQ authoring | a new `draft`, numbered one above the highest, copied row for row from the current version in one batch |
| `PUT /drafts/:version/:entity` | HQ authoring | create a row (`revision: null`) or edit one |
| `DELETE /drafts/:version/:entity` | HQ authoring | remove a row; its revision is required |
| `GET /sources`, `POST /sources` | HQ authoring | sources with their latest check; record a source (https only) |
| `POST /sources/:id/checks` | HQ authoring | the day (not in the future), the result (`unchanged`, `changed`, `unreachable`) and a note; the checker is the caller |
| `GET /restricted` | HQ authoring | the restricted places |
| `POST`, `PATCH /:id`, `DELETE /:id` on `/restricted` | Super Admin, write bar | add, edit or remove one; kind, source and checked day required on add and edit |

`:entity` is `countries`, `forms`, `facts`, `fees`, `pack`, `questions`, `scenarios` or `rules`.

**Rules every edit follows**
- **Only a draft.** A `published`, `retired` or `in_review` version is refused `409 version_not_draft`. The D6689 triggers refuse a published one underneath as well.
- **A reason**, at most 500 characters, on every write. The change and its `admin_audit_log` row are one batch; the row is written only if the change wrote a row.
- **Revision-checked.** The route compares the revision sent with the row as stored (`409 revision_conflict`, with `current_revision`), then writes with a compare-and-set: the `UPDATE` or `DELETE` matches every stored column as it was compared. A write that loses a race after the check changes nothing and is refused the same way. Creating a row whose key exists is a conflict too.
- **Sourced figures.** A fact is saved as `recorded` only with a value, a source and a checked day (`400 fact_unsourced`); a fee line with an amount needs a source and a day (`400 fee_unsourced`). The source must exist. A checked day is a real day, not in the future. Whoever sets a fact's or fee's `checked_on` is its `checked_by`.
- **Fields are checked** against each table's types; an unknown field is refused, never dropped.
- **A country with forms, or a form with facts, fees, pack items, questions or scenarios,** is not removed (`409 row_in_use`).
- **One open draft.** A second `POST /drafts` while a draft or review is open is `409 draft_open`.
- **No model writes catalogue content.** Every route here is a person's request; nothing in the AI layer calls them.

**Restricted places** are not versioned. A change is read by the next request: nothing is cached, and no deploy is needed.

**Client:** `frontend/src/lib/api/adminFormationCatalogue.js` (`adminFormationCatalogueApi`).

### Choices made here

- **No migration; the revision is the content.** D6689 has no revision column. A content hash plus a compare-and-set gives the same guarantee for one row: a stale write is refused and saves nothing. It does not give a draft-wide revision (two people editing different rows both succeed), which is what a per-row editor needs. A draft-wide counter would need a column (a migration), left to the owner.
- **Edits are refused in review.** The store allows writes in `in_review`; the editor does not, so what counsel reviews (#6700) does not move.
- **The draft is copied from the current published version**, not from an older one. A draft numbered above the highest version; the notes say which version it came from and why.
- **The templates hash includes the bodies.** Counsel signs off what a template says, so a body change must show; the version's `content_sha256` covers the catalogue rows only.
- **Stale means past the allowed age of D6693**, the same age the order gate applies.
- **Restricted places use the D6693 Super Admin pattern** (`requireHqAdmin`, then `isSuperAdmin`, then `requireSuperAdminWriteBar`), as pausing a form does.

### Not built here

Publishing and counsel's sign-off (#6700), a rule test bench (#6718), the screens (#6702), and any reader that refuses an order in a restricted place.

### Tests

`cloudflare-worker/test/formation_catalogue_edit_6699.test.ts`, one test per Done-when case:
- a published version cannot be edited (nor one in review), and nothing is saved;
- a stale revision is refused with `revision_conflict` and nothing is saved; a write that loses a race after its check changes nothing;
- a fact cannot be saved as `recorded` without a source and a date (new or existing), and a fee amount likewise;
- the diff lists every changed, added and removed fact, fee line and rule (and every other table's row), with each field;
- a restricted-place change is read by the next request, and is the Super Admin's, past the write bar, with a reason, a source and a checked day.

Also: the draft copy has the same `content_sha256`, rows and revisions as its source; sources and their checks; stale and disputed facts; rows in use; and the SHA-256s, pinned to a literal canonical text and blind to ids, row order and JSON key order, with the rule set's and each form's templates' hashes changing only with their own content.

**Mutation check:** 14 mutations, 14 caught, 0 equivalent. Each broke one guard and turned its named test red: the draft-only check; the revision comparison; one column dropped from the compare-and-set `WHERE`; the changed-row check after the write; the checked day dropped from the recorded-fact rule; changed rules and removed rows dropped from the diff; the source and Super Admin checks on restricted places; key sorting and row sorting in the canonical content; the template body's hash; rules left out of the draft copy; the reason left out of the audit record.
