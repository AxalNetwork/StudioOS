## D5569 — Venture GitHub App installation record and disabled publisher (#5569)

The GitHub code adapter for WorkGraph starts with a credential-free
installation record in D1. Its opaque UID is the reference Team Landing
can store in #5624. The record carries the workspace tenant, company and
project, numeric App, installation and repository IDs, the repository name,
protected base ref and local owner approval and revocation fields. GitHub
IDs establish remote identity even if the repository name changes.

The internal inspector takes the scope resolved by the caller's authorization.
It binds the UID to that scope and to the project's current company, refusing
archived companies, deleted or moved projects, revoked registrations, and
missing approvers. A readable registration still yields a disabled response.
The migration allows one unrevoked registration per repository in a venture
scope and preserves the old UID when that registration is replaced.

The separate write App requires the owner's installation on explicitly
selected venture repositories. The future privileged broker must confirm the
configured App, the live installation and repository, and the protected
base ref before minting short-lived credentials restricted to that repository
and operation. The existing read-only connector and the internal Merge
Control App keep their current purposes.
[GitHub App installation authentication](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation).

This slice has no route, credential, activation flag or publication executor.
WorkGraph intent, scope and artifact verification, conditional Git updates,
retries, audit records and combined-candidate checks remain follow-ups.
GitHub protected-branch admission and exact-SHA release depend on #5500
and #5501. The publisher must have no bypass or self-approval.

Tests apply the additive migration twice to synthetic SQLite, verify the
disabled response and cross-scope refusals, and cover duplicate current
registration, revocation and ownership changes. Owner installation and
hosted verification remain pending. Rollback removes the unused reader and
leaves the additive table in place after it has been applied.
