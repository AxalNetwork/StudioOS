### 1. The reads

All four use `requireAdmin`, as every `/api/admin/partners` read does. Nothing here writes.

| Read | Answers |
|---|---|
| `GET /deals/:id` | The deal row with its proposal parsed, the partner's name, who terminated and the redemption count. Also its invitation, its envelope (sent, completed, the signing link's expiry and the recipient's state), its due-diligence case with the KYB section, the member's obligations per key, and the history. |
| `GET /deals/:id/terminate-preview` | Whether the deal can be terminated, whether the partner's own grants would revert, and which members would lose a plan, with a count. |
| `GET /redemptions` | Every redemption across deals, filtered, sorted and paged, with an exact total and each row's days left in its attribution window. |
| `GET /agreement-ready` | Whether the Partner Services agreement can be sent: `ready`, `reason` and the unfilled `fields`. |

The deal id matches digits only, so `GET /deals/top` still reaches its own route in `admin_partners.ts`. A test holds this.

### 2. Rules

- **Failures.** A missing deal is a 404. Any other failure, in any block, is a 5xx through `mapError`. It is never a 404, and never an empty block that reads as "none".
- **Obligations are read, never seeded.** The trust-score route `GET /api/trust/score/:userId` seeds obligations before it reads them, so it is not called. `legal_obligations` is read directly.
  - The four keys activation seeds (`partner_msa_v1`, `kyb_v1`, `kyc_v1`, `accreditation_v1`) are listed first, always.
  - A key with no row says `recorded: false` and `status: null`. A never-seeded obligation is not "satisfied".
  - A waived obligation is listed, not hidden. The member's other obligations follow.
- **The due-diligence case.** Activation opens a case with no deal id (`partnerDeals.ts`). The read matches cases on the member (`subject_type = 'partner'`) opened at or after the deal's activation.
  - One case is `match: 'one'`.
  - None is `'none'`.
  - More than one, from a second deal for the same member or a case opened by hand, is `'ambiguous'`: both are named and neither is picked.
  - A deal with no member or no activation is `'not_activated'`.
- **The proposal.** An unreadable `proposal_json` says `proposal_unreadable: true` with `proposal: null`. It is never passed off as an empty proposal.
- **History.** Built from the row's own dates (created, activation failed, activated, terminated, with who and why) and from the audit rows that name the deal: each activation retry, with who and its outcome.
- **The terminate preview** uses the same guards terminate writes with (`admin_partners.ts`). A member loses a plan only while their tier is still the one the deal gave and its status is still `partner_referral`. A member who has since paid for a plan would not lose it. The same holds for the partner's own `partner_grant`. A test checks the preview against terminate itself.
- **Redemptions across deals.** The filters are `attribution`, `partner`, `deal`, `window_within` (0 to 365 days), `from`, `to` and `q`. `q` matches the member's or partner's name or email, or the code, as a literal: `%` and `_` are escaped. The sorts are `newest`, `window` (open windows first, the soonest to close first) and `partner`. The total counts what the filters keep. A bad filter is a 400.
- **One attribution window.** `ATTRIBUTION_DAYS` is 365, the figure `GET /deals/:id/redemptions` counts with. The SQL writes 365 as a literal, so no value reaches its text, and a test holds the two equal.
- **Agreement ready** replaces D923 §2's browser rule. The agreement cannot be sent when:
  - the template has no body (`reason: 'no_body'`);
  - or the template names a field the send leaves empty (`reason: 'unfilled_fields'`). The send fills finalize's five merge fields (`FINALIZE_MERGE_KEYS`, now exported from `partner_onboarding.ts`) and the envelope's own (`AUTO_MERGE_KEYS`). Every `counterparty.*` field stays empty, because finalize sends with no recipient user.

  When the template cannot be read, nothing is said either way: a 503 with `ready: null`.
