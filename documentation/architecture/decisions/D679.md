## D679 — The public Network section

Issue: #1553. Part of #1546 (D673). Source: `design/canvases/integrated/Axal VC Website.dc.html`. This decision has two parts, built in parallel: Part 1 is Resources, Articles and the Directory; Part 2 is Programs & Events, Circles and Jobs.

### Part 1: Resources, Articles, Directory

Views: NETWORK SUB-NAV, NETWORK HUB, ARTICLES and DIRECTORY.

#### The decisions

- **Every row is read live.**
  - The hub's blocks read what their own section pages read. Nothing in the hub is typed.
  - The canvas's members, events, articles, circles and roles are examples. Its directory names real people, and none of them is in any file this part wrote.
- **The figures are D675's counts.**
  - The hub and the Directory draw `members_verified`, `countries`, `lps_and_funds` and `operators_and_advisors` from `GET /api/public/stats`, in the canvas's order and with its labels.
  - A count is drawn only when it comes back as a positive number, using the same rule as `LandingPage.figure`.
  - Until D675's change lands, the endpoint returns none of them. The hub draws no figure row and the Directory draws no figure cards, and that is correct.
- **The article pills are the live taxonomy.**
  - They are `GET /api/articles/sectors`, the field each article carries as `sector`.
  - A pill sets the `sector` the list read already takes.
  - The canvas's Underwriting, Formation, Cohort notes and Fund are examples, and none is drawn.
  - A card's chip is its sector's label in the same taxonomy. The hub names its articles' sectors with the same read.
- **The directory pills are the entity types the live rows carry.**
  - `GET /api/public/partners` lists admin-listed, active operating partners. It has no `type` field, so every row it returns is a partner, labelled "Operating partner" (the site's word, from the nav's door).
  - The pills are All plus each type present in the loaded rows. With today's read that means All and Operating partners.
  - A row that one day carries its own `type` is filed under it, and its pill appears.
  - The canvas's Partners, LPs and Founders filters have no live type, so they are not drawn. Operators is the operating partners.
- **The directory draws only what the public read exposes.**
  - Each row shows the name, the company, the headline and categories, the type, and the Verified and Featured marks.
  - The canvas's geography is not drawn, because the read does not carry one.
  - The CTA is "View profile" → `/partners/:slug`, the public profile the page already linked.
- **Existing behaviour is kept.**
  - Articles keeps its search, the author-role filter, the featured strip on an unfiltered first page, pagination, and its empty and loading lines. The author's name now links to `/authors/:id` when the row carries `author_user_id`.
  - The Directory keeps its search (on Enter or the Search button), the detailed filters panel (category, capacity, pricing tier, rate), the KYB-verified switch, Clear, the listed count, the Featured and Verified marks, and the profile links.
- **The Directory's three "Coming soon" tabs are gone, along with their field-shape cards** (Startups, Investors & LPs, Advisors).
  - They were the canvas's LPs and Founders filters in another form: types with nobody listed.
  - The page now offers only types that have rows, and an empty directory says "No one is listed in the directory yet."
  - `public_directory_no_invented_listings.test.mjs` pinned the old cards' layout. Its two layout tests now pin the stronger rule: the page draws no placeholder card at all, and the pills come from the live rows. Its data tests are unchanged.
- **The Directory's lede keeps only its second sentence.**
  - The canvas's first sentence ("Partners, LPs, founders, and operators across borders.") says what the directory holds. The public read holds operating partners only, so the sentence is not true of this page, and it is dropped rather than softened.
  - "Directory access is verified — members see full profiles and can request warm introductions" stays. Signed-in members request introductions through Network → Introductions (`/api/introductions/propositions`).
  - The hub's lede stays whole, for the same reason.
- **Event chips use the canvas's tints, keyed by the live event types.** `demo_day` is violet, `office_hours` is teal, and every other type is grey. The canvas's LP briefing has no live type.
- **Circles show their access.** The canvas's seat counts ("2 seats", "Full") have no field in `/api/public/circles`. Each circle row shows its type, region and member count, with a Public or Invite-only chip.

#### What was dropped and why

- **Geography on directory rows.** `GET /api/public/partners` does not return a location.
- **A "Request intro" CTA on directory rows.** The page had no request-introduction flow to keep. The partner profile's own "Engage this partner" goes to `/register`, and signed-in introductions live in the Network workspace.
- **The Directory's detailed filters do nothing on the server today.** The page sends category, capacity, pricing, verified-only and rate. The Worker accepts them and ignores them, because they have no backing columns (`routes/public.ts`). The panel is kept as existing behaviour. Every listed row has `kyb_verified: false` today, so no Verified mark shows until a source fills it.
- **Article cover images.** The canvas's card has none.
