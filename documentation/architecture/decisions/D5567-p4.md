## D5567 part 4 — fail-closed containment gate and job-environment credential scan (#5567)

**Status:** S14, 2026-11-18. A pure module and its tests. No route, no mount, no migration, no binding, no provider call; nothing is switched on.

### The gap it closes

The issue says providers that cannot enforce the selected policy are **ineligible**, and its acceptance asks that workloads fail closed on unsupported containment and that no cloud credential or provider token sits inside the coding container. Before this part:

- `workspaceSecurity.eligibility` checked a handful of provider booleans, but only inside the grant service (it needs the whole broker's dependencies), stopped at the first failure, and had no field for the guest's bindings, the detail of the egress fence, or where the evidence came from.
- #5570's placement filter has a "security capability" step and nothing pure to call for it.
- Nothing scanned what a job is started with for credentials.

### What it does

`cloudflare-worker/src/services/agents/workspaceContainment.ts`, pure and synchronous:

**Evidence.** `ContainmentEvidence` is a closed (`strict`) record of what one provider can enforce. It counts only when:

- `source` is `owner_registry` (a provider's or runner's own report never enables it);
- its `provider` is the candidate being judged;
- `verified_at` is not in the future and not older than 24 hours by the caller's clock (a caller may shorten that window, never widen it).

Missing evidence is `evidence_missing`; any extra, missing or wrongly typed field is `evidence_malformed`.

**Rules.** Each failing rule adds a reason; any reason makes the provider ineligible.

| Area | Required | Reason codes |
| --- | --- | --- |
| Egress, `deny` spec | outbound off | `egress_deny_unenforced` |
| Egress, `allowlist` spec | a connect-time fence that also blocks private ranges, DNS rebinding, redirect escape and raw sockets (a hostname check is a preflight, not enforcement) | `egress_allowlist_unenforced`, `egress_private_ranges_open`, `egress_dns_rebinding_open`, `egress_redirects_open`, `egress_raw_sockets_open` |
| Egress, unknown mode | refused | `egress_allowlist_unenforced` |
| Metadata, localhost | both blocked, for every mode | `metadata_reachable`, `localhost_reachable` |
| Guest | no D1, Durable Object, secret binding, cloud control-plane credential or other tenant's mount | `guest_d1_binding`, `guest_durable_object_binding`, `guest_secret_binding`, `guest_control_plane_credential`, `guest_other_tenant_mount` |
| Privilege | not privileged, no host socket, not root, no-new-privileges, immutable image | `privileged_mode`, `host_socket`, `root_user`, `new_privileges_allowed`, `mutable_image` |
| Sandbox | `coding_untrusted` needs gVisor or microVM; everything else at least a container; `unknown` never passes | `sandbox_too_weak`, `sandbox_unknown` |

**Interface for #5570.** `CONTAINMENT_STEP = 'security_capability'`.

- `containmentEligibility(spec, provider, evidence, { now })` returns every reason, in the stable order of `CONTAINMENT_REASONS`, so placement can explain a refusal.
- `isContainmentEligible` is the boolean form.
- `filterContainment(spec, candidates, { now })` splits candidates into eligible providers and ineligible ones with their reasons.
- `containmentRefusal` is the broker refusal: `containment_unsupported`, 422, `capability` = the first reason.

This part does not edit #5570's files; its filter imports these.

**Job environment.** `jobEnvironmentFindings(env)` checks what a job would be started with:

- each name against an allowlist (`GUEST_ENV_ALLOWED`: `PATH`, `HOME`, locale, Python runtime flags and a few more) and against cloud and provider credential name patterns (AWS, Azure, Google, Cloudflare, GitHub, registries, model-vendor keys, and any `*_TOKEN`, `*_SECRET`, `*_PASSWORD`, `*_API_KEY`, `*_CREDENTIALS`);
- each value against credential shapes (cloud access keys, GitHub and vendor tokens, private-key headers, JWTs, credentialled URLs).

It reports the variable name and a kind, never the value, so a finding can be logged. Anything that is not a string map is `malformed`. `jobEnvironmentClean` is the boolean.

### Tests

`cloudflare-worker/test/workspace_containment_5567.test.ts`, 12 tests, clock injected, no sleeps:

1. Full owner-registry evidence is eligible for both network modes.
2. Missing, malformed, self-reported, runner-reported, other-provider, stale and future-dated evidence; the age cap cannot be widened; a bad clock throws.
3. Egress per mode: an Internet-off-only provider is eligible for `deny` and not for `allowlist`; each fence gap alone; an unknown mode.
4. Metadata and localhost for both modes.
5. Each guest binding or credential alone.
6. Each privilege-escalation path alone.
7. Sandbox strength against the workload trust level.
8. All reasons in stable order, and the broker refusal's code, status and capability.
9. The placement filter's split.
10. The environment scan: allowed names clean; 18 credential names; 8 credential value shapes (synthetic, assembled at runtime) with the value never echoed; unlisted, malformed, array and string inputs.
11. The real compute VM (`agent-compute/vm.ts`) under both scheduling policies starts with Internet off and no `envVars` or `entrypoint`.
12. The compute image's runtime stage (`agent-compute/Dockerfile`) runs as a non-zero numeric user, its baked `ENV` is clean, and it mounts no build secret.

**Mutation check:** 37 mutations, 37 caught: each rule and reason removed in turn, the source, provider and freshness checks, the age cap, the clock guard, the strict schema, the stable order, the refusal status, the filter, each environment check, and the VM's Internet switch. The one survivor of the first run (the array check) was caught after adding the empty-array case.
