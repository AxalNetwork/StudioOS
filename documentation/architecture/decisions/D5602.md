## D5602 — Scope advisory PR scans and retain redacted main-scan incidents (#5602)

**Status:** implemented for review; no repository settings changed. Owner approval of the policy is recorded on #5602. CODEOWNER review of `.github/**` remains required.

### Coverage and trade-off

CodeQL and Semgrep keep every push to `main` and their existing weekly schedules. Pull requests scan on opened/synchronize/reopened/labeled when their current labels include `security-scan` or a sensitive path changed. Neither workflow runs on merge groups. This moves most findings for ordinary PRs to the main scan; it does not turn a skipped advisory scan into a claimed scan. Gitleaks and the full combined-code gate are untouched.

The pure `scanScope` gate includes root `wrangler*.toml`, `.github/**`, `cloudflare-worker/sql/**`, `cloudflare-worker/src/auth.ts`, `cloudflare-worker/src/middleware/**`, `.semgrepignore`, `scripts/sarif-summary.py`, `scripts/strip-suppressed-sarif.py`, and `package.json`/lockfiles anywhere. Old rename paths count too. A missing, inconsistent or capped 3,000-file PR inventory scans; an API failure fails admission rather than returning a docs-only result. Labels are read from the event payload, not substituted into shell code. Semgrep adopts CodeQL's event/ref concurrency with superseded PR cancellation; main/scheduled scans retain the existing coalescing policy.

The first short job runs on every admitted workflow event. It reads PR filenames with `pull-requests: read`; the actual scanning jobs depend on its explicit `scan` output and the unchanged visibility/upload decision. No workflow-level `paths:` filter can defeat the label override. Scanner acquisition, rule packs, findings exit policy, suppression handling and SARIF upload visibility remain unchanged.

### Main finding state

Semgrep keeps its pinned scanner container and existing Python runtime; its fingerprint CLI is parity-checked against the Node contract. A glibc Node setup step cannot run inside that Alpine image and is not required. After a successful main-push scan, an artifact contains SHA-256 fingerprints of `(rule ID, file URI)` for unsuppressed findings. It contains no paths, source excerpts or finding messages. Duplicate locations collapse to one rule/file identity. A malformed or absent SARIF fails snapshot generation and cannot publish a clean baseline.

Each scanner compares with the previous completed successful main scan's retained state artifact from the same workflow/repository. PR artifacts, another scanner/repository/run and failed or incomplete analyses cannot supply that baseline. CodeQL requires both language artifacts before reporting. Initial runs without an artifact establish a baseline without an alert. New fingerprints become outstanding; repeated runs retain them until they disappear, even when the original pre-existing baseline findings remain. State artifacts are retained for 90 days. If a baseline is lost while an incident is already open, history becomes explicitly unknown and cannot automatically close the incident; restore the retained baseline or review/rebaseline that incident deliberately.

The two scanners share one issue, `[alert] a scan found something new on main`. Its body contains only each scanner's run link and unresolved counts by rule; fingerprints stay in artifacts. The short main-only report jobs share a concurrency group, so creation/update/closure is serialized. GitHub may coalesce pending report jobs under heavy pressure; successful scans remain in code scanning/job summaries, and a later successful report uses the last completed state. Clearing one scanner retains the other's outstanding counts. No previous baseline means no issue transition. This mode sends no Slack message and publishes no public reproduction.

### CI and main-integration repair

The bounded JSON reader opens its input once, reads at most 8 MiB plus one
byte through that descriptor, and closes it on success and on errors. It does
not trust a path size check followed by a separate path read. Regression tests
replace the payload at the old read boundary, preserve valid JSON exactly at
the limit, reject oversize/malformed input, enforce the read budget and verify
cleanup. Deliberate reader, limit, parsing and cleanup mutations fail them.

The main health-reporter integration preserves its missing-token refusal,
retained incident episodes, delivery acknowledgements and trusted future-clock
evidence; scanner incidents retain their separate no-Slack path. The actual
scan CLI test also rejects missing authentication before any API call. Its
synthetic GitHub PATCH handler assigns only body/state/state_reason, rather
than merging an arbitrary request object. Scan admission, rules and thresholds
are unchanged by this repair.
