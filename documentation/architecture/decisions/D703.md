## D703 — On a phone, each cycle opens on its One Next Thing, and every module, record, add form and cycle action is its own page

Issue #1665, part of D689 (#1654). On 2026-10-14 the owner asked to "implement mobile versions, artifacts". The canvases are `design/canvases/integrated/Cycle Overviews · Mobile.dc.html` (COM; in `design/incoming/` until PR 2c moved it) and `Cycle Modules · Mobile.dc.html` (CMM), which import `design/canvases/integrated/Cycle Overview.dc.html` (CO) with `mobile`. This decision draws the four cycles on a phone, below 1024px:
- each cycle opens on a root, One Next Thing;
- each module, record, Add form and cycle action is a pushed page inside #1661's phone shell.

It reads only what #1701 (D692), #1658 (D696) and the record tasks return. It supersedes D685 §5.12's Validate-only focus, and D686's lightboxes for the four actions on a phone (D-h).

It shipped in parts, each `Part of #1665` but the last:
- **PR 1** drew the roots. PR 1a (steps 1-2, #1754) built the pieces, and PR 1b (steps 3-5, #1803) mounted them.
- **PR 2** drew the pushed pages. PR 2a (#1761) and PR 2b (#1765) built the pieces, unmounted. PR 2c (#1808) wired the module, Add and action pages, and PR 3a (#1827) the record page.
- **The closing PR** (`Closes #1665`) added `/validate/verdict`'s phone module page and the Verdict refusals, once #1704's closing PR (#1814) put the Verdict module on `main`.

The decisions, the layouts and the departures below are the whole of D703. The sections after them say what each PR shipped.

### Decisions

1. **One switch picks the phone page, in `CycleRoute`.**
   - `usePhoneWidth()` (#1661's hook on `PHONE_QUERY`) decides. Below 1024px the route renders the phone page in place of the desktop one, never both: no desktop tree is hidden with CSS, so each page has one search form, one focus trap and one Eadwyn button.
   - A server render, or a browser without `matchMedia`, gets the desktop page, and its `lg:` rules keep it usable at any width.
   - The switch reads the slug `CycleRoute` resolves (the route's, or #1658's `slug` prop), so `/validate/verdict` and `/raise/data-room` get the phone module page too.
2. **The roots draw the Worker's focus, meter and index as sent.** One component, `PhoneCycleRoot`, draws all four cycles from #1701's fields: `focus { rule, eyebrow, headline, why, cta: { label, href }, then }`, `meter { key, label, count, target, target_reason, display }` and `index [{ key, title, detail, value, href }]`.
   - **A null part falls back, and only then.**
     - The focus falls back to Validate's rule 1 (an empty Customer research card), else the first card's `next`, under "<Cycle> · Next".
     - The index falls back to one row per card in the same read, each linking its module page with the value "Unreadable". A module the Worker hides, such as Verdict for a partner, stays hidden.
   - **Validate's object index.** Until #1701's PR 1b, Validate's read sent `index` as `{ interviews_total, booked }`, and Validate kept its client-built rows (S1's ruling), so the live card did not change. #1701's PR 1b (#1784) sends rows, so this task's PR 1b deleted that branch with `ValidatePhoneFocus.jsx`. An `index` that is not an array now reads as none sent.
   - **The browser never adds a row.**
   - **One meter renderer.** It draws the Worker's `label` and `display` as sent ("14 of 20", "$900k of $1.5M"), then "· <target_reason>" when there is no target, and the 7px bar at `count / target` when both are numbers and the target is above zero. Inside `phone-meter-value` the text keeps D685's shape, `<display> <span>· <target_reason></span>`.
     - Only Validate falls back: with no Worker count it reads the `interviews_this_month` figure; with no `display` it writes "<count> of <target>" or "<count>"; with no target and no `target_reason` it writes "No target set".
     - Any other cycle with no `display` draws Not recorded. The browser never formats money.
     - Validate draws no meter under its first-conversation focus.
   - **A CTA that opens the cycle's own action route** (`/validate/record`, `/build/connect`, `/raise/call`) goes through `openAction` on a plain tap, as the desktop button does, so Back from the action page is one step. A modified tap is the browser's.
     - Every other CTA is a plain link.
     - Grow's root never opens Share an update (S1's ruling): its tell-customers CTA is "Open Product improvement" → `/grow/product-improvement`.
3. **"Then" appears once.** The row is the "Then" label and the text, with a leading "Then" (and an optional colon) stripped and the first letter upper-cased (CO:26, D-k). A word that only begins with "Then", such as "Thenceforth", is kept.
4. **Validate keeps "Set a target".** D685's form (#1609) moves into the root, under Validate's meter, with its test ids. It writes the same `PUT /cycles/validate/interviews-target` and re-reads the overview. No other cycle draws it.
5. **Every page's Eadwyn button is #1660's `EadwynButton`**, never one of this task's own, labelled as CO:229 does: "<Cycle> · Overview" on a root.
   - On a root it sits beside the eyebrow. With no focus, it sits beside the index label, a departure from the canvas, which always has a focus.
   - Who gets it is #1660's `available` (S1's ruling): a founder, and an admin who chose View as founder. An admin in an admin shell, or a Lab member with another licence, gets the same pages with no Eadwyn button, and `EadwynButton` draws nothing.
   - On a pushed page it is drawn through `PhoneBar`'s `eadwynLabel`, labelled "<Cycle> · <bar title>".
   - **Every pushed page has one bar, `CycleBar`, above the gutter.** It wraps #1661's `PhoneBar`, lifted out of the gutter (`-mx-[22px] -mt-[14px]`) with the body's 14px under it (`mb-[14px]`), and stays `sticky top-0` in the scroll area, as the canvas keeps its bar outside the scrolling body (CO:24-25).
   - **Back goes where the desktop close goes, and its label names that place.** A module page links to its cycle root, and a record to its module page, each with the venture. An Add page calls #1656's close and an action page `closeAction`, so Back never pushes a page the browser's Back would reopen. An action page's label is the module under it when there is one, else the cycle (CO:251). `PhoneBar`'s `back.onClick` carries this, so no Back reaches `PhoneBar`'s no-history fallback.
   - **A module's title comes from the cycle's own list when the read sends none.** A refused or unreadable module read has no card, so the bar, and the desktop header too, would otherwise title the page with its slug ("verdict"). `CycleRoute` hands both module pages `moduleName`.
6. **The phone module page shows its chart**, in #1655's wrapper, titled "<Module> · at a glance" (CO:641) with the card's range. It scrolls inside the gutter under the `cycle` container's 760px query, not out to the screen edge as CO:27 bleeds it.
7. **The module page's CTA is the desktop Add's target.** "One next thing" reads `card.next.text`, else the Add label (CO:260). The CTA is the module's own Add: the `/new` link #1656 gives a module with a form, with the same `state.under`, else the add link the module already has (Record a session's `onOpen`, the Raise read's `records.add`). A module with no Add draws the headline and no CTA.
8. **A row opens its record only when it can.** It links to `recordHref(…)` exactly when #1658's `rowLinks` says so, so the phone and the desktop link the same rows. Otherwise a row with the desktop's Edit opens it on a tap, and any other row is plain. A first cell with a tone keeps its pill, so the Decisions list keeps "Proceed".
9. **Nothing the desktop page does is lost on a phone.**
   - **On a module page:** search, filters and sort above the rows; paging, the tool links as handed (`moduleToolLinks`, so Data room's "Open the files tool" stays one tap away) and `children` below them. An unreadable read draws `Unreadable` with its retry, and a refused one (#1704: Verdict for a partner) the Worker's sentence in a neutral box, with no chart, no rows and no CTA.
   - **On a root:** `AlsoIn`'s pages (`alsoInFor('founder', <Cycle>)`) are a last `PhoneRows` group, "Also in <Cycle>", after the index, so D563's rule that every "also" page is linked from its row's overview holds on a phone. Build has none and draws no group.
   - **`/validate/verdict`** (App.jsx's static line, `slug="verdict"`, D693 decision 12) is a module page like the others below 1024px, through decision 1's switch: its chart, its "Record a decision" CTA and the Decisions rows. A partner's 403 is drawn as the refusal above.
10. **The record page is groups of rows** (CO:270-273), drawn by `RecordView.jsx`'s exported parts under `RecordPhoneProvider`, which `CycleRoute` sets below 1024px. #1659's `InterviewRecord`, built from those parts, gets them with no edit to its file.
    - "Next for this record", from the read's `next`. Its CTA is the declared action `next.action` names, with that action's label, run through #1658's handlers, not CO:269's link back. With no such action the headline stands alone.
    - The record's pills, as one chip row.
    - "At a glance": each fact, with "Not recorded" and its reason as the description.
    - Each main section, then each side section, with #1658's `sectionId` anchors, and the section's action as its group's last row.
    - "Activity", with "Show all".
    - "Actions", the record's actions as a last group, with a danger action in red.
    - Under the bar ("‹ <Module>", the record's title and sub, the Eadwyn label "<Cycle> · <record title>"), the loading, refused and unreadable states draw in place of the groups. A 404 reads "Record not found.", and a 403 the Worker's sentence ("Partners do not see decisions." on a Verdict record), each with no facts, no actions, no CTA and no Retry.
11. **The four actions are D686's sheets as pages.**
    - The prop is `asPage`, not `page`, because `RoundCallSheet` already holds a `page` state. Only `CycleRoute`'s one `<Mount …>` passes it; `RaiseCallPage`, `RoundCallPage` and the Connect a tool nested in Share an update stay dialogs.
    - **Why the page draws at the `Mount`, with its own copy of the gutter.** The action `Mount` follows the size container (#1655's decision 13), and Share an update's page holds a `fixed inset-0` dialog of its own, its nested Connect a tool, which must not sit inside a size container. So the action page stays at the `Mount` and is never moved into the body. While a phone shows it, `CycleRoute` draws neither the size container nor the body, and the page draws the body's gutter itself (`PHONE_GUTTER`, passed as `asPage.pageClass`). The page is then the route's only content, as #1656's Add page is the form alone.
    - The bar carries the sheet's own title. In page mode `ActionSheet` draws no header row and keeps its sub as its first line, so no page shows its title twice. A dialog opened inside a page keeps its own header.
    - Back is the `Lightbox`'s `onEscape` when set, else its `onClose`, so a Connect a tool panel goes back to the list and every other sheet closes.
12. **Frontend only.** No Worker change, no `/api/*` method and no migration.
