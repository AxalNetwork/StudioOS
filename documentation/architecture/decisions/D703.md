## D703 — On a phone, each cycle opens on its One Next Thing, and every module, record, add form and cycle action is its own page

Issue #1665, part of D689 (#1654). On 2026-10-14 the owner asked to "implement mobile versions, artifacts". The canvases are `design/incoming/Cycle Overviews · Mobile.dc.html` (COM) and `Cycle Modules · Mobile.dc.html` (CMM), which import `design/canvases/integrated/Cycle Overview.dc.html` (CO) with `mobile`. This decision draws the four cycles on a phone, below 1024px:
- each cycle opens on a root, One Next Thing;
- each module, record, Add form and cycle action is a pushed page inside #1661's phone shell.

It reads only what #1701 (D692), #1658 (D696) and the record tasks return. It supersedes D685 §5.12's Validate-only focus, and D686's lightboxes for the four actions on a phone (D-h).

It ships in parts:
- **PR 1** draws the roots. PR 1a (steps 1-2) builds the pieces, and PR 1b (steps 3-5) mounts them.
- **PR 2** draws the pushed pages: PR 2a and PR 2b build the pieces, unmounted, and the closing PR wires them.

This first version records decisions 1-5 and 12, the root's layout, and what PR 1a shipped. Later PRs amend it.

### Decisions

1. **One switch picks the phone page, in `CycleRoute`.**
   - `usePhoneWidth()` (#1661's hook on `PHONE_QUERY`) decides. Below 1024px the route renders the phone page in place of the desktop one, never both: no desktop tree is hidden with CSS, so each page has one search form, one focus trap and one Eadwyn button.
   - A server render, or a browser without `matchMedia`, gets the desktop page, and its `lg:` rules keep it usable at any width.
   - The switch reads the slug `CycleRoute` resolves (the route's, or #1658's `slug` prop), so `/validate/verdict` and `/raise/data-room` get the phone module page too.
2. **The roots draw the Worker's focus, meter and index as sent.** One component, `PhoneCycleRoot`, draws all four cycles from #1701's fields: `focus { rule, eyebrow, headline, why, cta: { label, href }, then }`, `meter { key, label, count, target, target_reason, display }` and `index [{ key, title, detail, value, href }]`.
   - **A null part falls back, and only then.**
     - The focus falls back to Validate's rule 1 (an empty Customer research card), else the first card's `next`, under "<Cycle> · Next".
     - The index falls back to one row per card in the same read, each linking its module page with the value "Unreadable". A module the Worker hides, such as Verdict for a partner, stays hidden.
   - **Validate's object index.** Until #1701's PR 1b, Validate's read sent `index` as `{ interviews_total, booked }`, and Validate kept its client-built rows (S1's ruling), so the live card did not change. #1701's PR 1b (#1784) sends rows, so this task's PR 1b deleted that branch with `ValidatePhoneFocus.jsx`. An `index` that is not an array now reads as none sent.
   - **The browser never adds a row.**
   - **One meter renderer.** It draws the Worker's `label` and `display` as sent ("14 of 20", "$900k of $1.5M"), then "· <target_reason>" when there is no target, and the 7px bar at `count / target` when both are numbers and the target is above zero. Inside `phone-meter-value` the text keeps D685's shape, `<display> <span>· <target_reason></span>`.
     - Only Validate falls back: with no Worker count it reads the `interviews_this_month` figure; with no `display` it writes "<count> of <target>" or "<count>"; with no target and no `target_reason` it writes "No target set".
     - Any other cycle with no `display` draws Not recorded. The browser never formats money.
     - Validate draws no meter under its first-conversation focus.
   - **A CTA that opens the cycle's own action route** (`/validate/record`, `/build/connect`, `/raise/call`) goes through `openAction` on a plain tap, as the desktop button does, so Back from the action page is one step. A modified tap is the browser's.
     - Every other CTA is a plain link.
     - Grow's root never opens Share an update (S1's ruling): its tell-customers CTA is "Open Product improvement" → `/grow/product-improvement`.
3. **"Then" appears once.** The row is the "Then" label and the text, with a leading "Then" (and an optional colon) stripped and the first letter upper-cased (CO:26, D-k). A word that only begins with "Then", such as "Thenceforth", is kept.
4. **Validate keeps "Set a target".** D685's form (#1609) moves into the root, under Validate's meter, with its test ids. It writes the same `PUT /cycles/validate/interviews-target` and re-reads the overview. No other cycle draws it.
5. **Every page's Eadwyn button is #1660's `EadwynButton`**, never one of this task's own, labelled as CO:229 does: "<Cycle> · Overview" on a root.
   - On a root it sits beside the eyebrow. With no focus, it sits beside the index label, a departure from the canvas, which always has a focus.
   - Who gets it is #1660's `available` (S1's ruling): a founder, and an admin who chose View as founder. An admin in an admin shell, or a Lab member with another licence, gets the same pages with no Eadwyn button, and `EadwynButton` draws nothing.
   - The pushed pages' bar (`CycleBar`, PR 2) is recorded with PR 2.
12. **Frontend only.** No Worker change, no `/api/*` method and no migration.

### Departures from the canvas so far

- "Then" is stripped of a leading "Then", so no page shows "Then Then" (CO:26, CO:203).
- "Set a target" is kept under Validate's meter.
- "Unreadable" index rows stand in for an index the Worker could not read.
- With no focus, the Eadwyn button sits beside the index label.
- An "Also in <Cycle>" group follows the index, so D563's rule that every "also" page is linked from its row's overview holds on a phone.

### PR 2a (step 8's `ui/` page mode, step 10's `asPage`)

This PR adds the pieces only. Nothing passes `asPage` yet; the closing PR mounts it from `CycleRoute`.

- **`frontend/src/ui/Lightbox.jsx`:**
  - `bar` may be a function, called in page mode with `{ title: title || label, sub, onBack }`. `onBack` is `onEscape` when set, else `onClose`, so a Connect a tool panel steps back to the list before the page closes (decision 11).
  - With no `bar`, a page takes its bar from `LightboxBarProvider`, and draws its own only when there is none. An element `bar` still wins, and #1656's `{bar || <header` fallback is kept.
  - `pageClass` classes the page's root, for the cycle gutter an action page draws itself.
  - `useLightboxPage()` is true inside a page and false inside a dialog, nested or not.
  - A `size="tall"` box has no fixed height in page mode, because a page draws no box.
  - `ui/index.js` exports `LightboxBarProvider` and `useLightboxPage`.
- **`frontend/src/ui/ActionSheet.jsx`:** inside a page it draws no header row, so the title and Back are the bar's alone. It keeps its sub as its first line at 12.5px, and its frame and body flow with the page. Steps, banner, body and footer are unchanged.
- **`asPage`** on the four action components, spread on their `Lightbox`:
  - `RecordLightbox`;
  - `ConnectToolSheet`, through `ConnectToolView`;
  - `RoundCallSheet`, through `CallLightbox`;
  - `ShareUpdateLightbox`.

  The prop is `asPage`, not `page`, because `RoundCallSheet` already holds a `page` state. `RaiseCallPage`, `RoundCallPage` and Share an update's nested Connect a tool pass none, so they stay dialogs.

### PR 2b (step 6's component, step 7's record layout, `PhoneBar`'s `back.onClick`)

This PR adds the pieces only, rendered nowhere yet. The closing PR switches `CycleRoute` to them below 1024px. It started from `main` once #1658's PR 2 (#1745) had merged, so it was not stacked.

- **`frontend/src/pages/cycles/PhoneModulePage.jsx`**, taking `CycleModulePage`'s props (decisions 6-9):
