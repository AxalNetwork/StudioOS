### 2. Model v1 as data (`model.ts`)

`VENTURE_MODEL_V1` holds the ten scopes this engine scores. They use D1253's keys and order, checked against `frontend/src/components/scoring/scorecard/scorecardModel.js`.

Each input has:
- a weight (a scope's weights sum to 100);
- a rule that turns its figure into 0–100 (`count`, `share`, `steps`, `scale` or `direct`);
- a freshness window: records 365 days, connector 90, quarter 120;
- the store it reads, and whether it is personal (part 3 shows a personal input to investors as a band).

The floor (0.25), the confidence cut-offs (High 0.70, Medium 0.45, Low 0.25) and the bands (Strong ≥ 70, Fair ≥ 40) are #2428's.

**One input, one scope.** #2428 names some stores under two scopes. Each feeds one here:
- **Commits** are Technical's build activity. Team's build evidence is platform actions.
- **Founder vesting** is Governance's. Team reads commitment.
- **Risks tied to a feature** are Technical's. The rest of the register is Risk's.
- **Each market's regulation score** is Political and regulatory's. Its demand, partners and cost scores are Geographic's.

**No input is invented.** Five inputs have no source on the platform yet:
- Production health: Vercel, #2408.
- The country index: owner question 4.
- The high-risk lists and the stability indicators: the same.
- Founder agreements: no store links a signed agreement to a venture.

They are in the model with `source: null`. Each applies, reads "Not recorded" with its reason, and lowers confidence until a later version reads it. Until an index is chosen, Geographic carries only its facts and market readiness (the issue's "Facts only").

**Not expected yet:**
- Traction and Financial before Build: `lifecycle_stage` is `idea` or `validate` (owner question 11).
- Values alignment for a solo founder.
- Spin-out IP terms for a venture that is not a spin-out.
- Production health before a non-prerelease release exists.

### 3. The engine (`engine.ts`)

`scoreScope` is pure and follows `pmf.ts`'s rules:
- **Missing is never a score.** Not recorded is out of the value: never 0 and never a neutral 50 (D538). A recorded 0 is a value.
- **Value** is the weighted mean of the inputs present, with the weights renormalised.
- **Coverage** is the inputs present out of the inputs that apply.
- **Confidence** is Σ weight × grade ÷ Σ weight over the inputs that apply. The grade sets confidence, never the value (bias guard 4). Past its window an input's grade halves, and it reads Stale.
- **Below 0.25** the scope reads "Not enough recorded", with no value and no band.
- **An input that does not apply** is out of every sum.
- **An unreadable input** makes the scope partial.

### 4. Migration 625

It adds one column, `venture_scorecards.state`: `scored`, `not_enough` or `not_expected`.
- **Why it is needed.** Both "Not enough recorded" and "Not expected yet" store a NULL value and band, so the word cannot be read back from them. Part 3's batch read for the strip needs it without parsing `inputs_json`.
- **PMF's existing rows** keep NULL.
- **An unreadable scope** is never stored.

Nothing else changes. Nothing is added to `users`.

### 5. The collectors (`collectors.ts`)

There is one collector per scope.
- **Every statement is static and bound.** They live in `STATEMENTS`, which the tests scan. A list of people is bound as one JSON array and read with `json_each`, so no SQL is built from values. No raw-interpolated SQL is added.

**Personal inputs are aggregated inside the collector.** The team is read as user ids only:
- the founder's users, plus accepted members;
- an advisor is flagged, and counts half on an axis only an advisor holds.

Skills, platform actions, commitment, experience, archetypes, runway and burn leave the collector as one count or figure per venture.

**The bias guards' never-inputs are unread.** No statement selects a name, email, photo, gender, age or date of birth, nationality, residence, ethnicity, religion, health, school or employer. `kyc_data` is never read.
- Experience is counted with `json_array_length`, so its text never leaves the database.
- Years are never scored.
- Archetypes count only as a mix of published ones.
- Values are not read: no store records a founder's consent to share them, so the input is "Not recorded" until part 3 adds one.

**Grades follow the Source-to-grade table:**
- **Measured:** a connector figure (Stripe, Mercury, GitHub), or a count of platform records.
- **Reviewed:** a DD case or an analyst score.
- **Sourced:** typed with a source (a market's sourced scores, a competitor with a source).
- **Stated:** typed alone.

### 6. Recompute on read, kept only on change (`store.ts`)

`scoreVenture(env, projectId, { actorId, trigger, today })`:
- **Collects and scores every scope.** It then hashes what each score rests on: the scope's model, its facts, its stale flags and its state.
- **Keeps a scope only on change.** It writes a signed row only when that hash differs from the scope's latest row, and the test sits inside the INSERT. An unchanged read writes nothing, and two identical reads write one row.
- **Treats a deleted input as a change.** It does not compare timestamps (`changedSinceScored`), so a deleted input is a change too. Crossing a freshness window is also a change.
- **Writes alongside each kept row:**
  - an `activity_logs` row carrying only the scope, model version, trigger and hash;
  - the scope's frozen model in `scoring_model_versions`. A stored model that differs from the code is refused.
- **Handles failed reads without storing them:**
  - a scope whose stores cannot be read is returned Unreadable;
  - a scope with an unreadable input (Mercury's read failing) is returned partial;
  - neither is stored, so the last complete row stays.
- **Delegates `pmf`** to `recomputePmf`.

`storedScorecard` reads each scope's latest row, verifying its signature, without recomputing; a tampered row is refused. Part 3 builds its reads on it.

Callers gate the venture first. The triggers are `read`, `rescore`, `sync` and `nightly`. No client sends a computed field, and no score sets a deal or venture status (bias guard 5).

### 7. Tests

`cloudflare-worker/test/venture_scoring_d1255.test.ts` has 20 tests. Collectors and the store run on the full schema: the baseline and every migration.
- **Model:** D1253's keys and order; weights sum to 100; each input feeds one scope.
- **Per scope (ten tests):**
  - the weights renormalise over the inputs present;
  - a missing input lowers confidence, not the value;
  - the grade moves confidence, not the value;
  - stale halves a grade;
  - below the floor there is no value and no band;
  - nothing recorded is never 0 or 50.
- **Engine:** a recorded 0 is a value; not-applicable inputs leave every sum; Traction and Financial before Build; an unreadable input makes a scope partial.
- **Bias guards:** every statement is scanned for the never-inputs, `kyc`, a name column and `SELECT *`. A venture seeded with a private name, email, employer, university, date of birth, nationality and GitHub login stores none of them.
- **Collectors:** every scope reads; an advisor-only axis counts half; commitment; build activity; three-month growth; spin-out terms; the country index's reason; Traction and Financial stored as `not_expected` before Build; a solo founder's values do not apply.
- **Idempotence:**
  - an unchanged read writes nothing;
  - a new competitor writes only Market;
  - a later day past the windows writes;
  - one model row per scope.
- **Signing:** rows verify, and a tampered row is refused. The audit carries only scope, model, trigger and hash.
- **Unreadable:** a dropped store makes its scope Unreadable and unstored; a failed Mercury read makes Financial partial and unstored.
- **Context:** a bad trigger, actor or venture is refused before anything is read.

**Mutation checks, each caught:**
- missing scored 0;
- no renormalisation;
- stale not halved;
- no floor;
- grade moving the value;
- stage ignored;
- an advisor at full weight;
- a solo founder's values applying;
- a statement reading an email;
- the hash ignoring facts;
- a write on every read;
- the signature not checked;
- a collector failure failing the card;
- a partial scope stored;
- Traction expected before Build.
