## D917 — Events review history and guarded writes

Issue #2700; part of #2368. Worker only, no frontend change.

Migration 546 adds nullable submitted_at, approved_at, review_note and
changed_after_approval_at. Public review submissions, including a self-published event switched to public,
record ISO submission time;
the Approvals lane waits from that time, with created_at as the legacy fallback.
Approval records its ISO time and clears a previous change flag. Material host
edits to title, times/timezone, location or price/currency set the change flag
without re-queuing an approved event. Change detection compares the normalized
values actually bound for accepted fields; invalid or normalized no-op inputs do
not raise a false history flag. Legacy admin-published events are covered.
Only draft or sent-back events can transition through submit-review, with the
state repeated in its UPDATE predicate. A repeated waiting submission is a no-op
and keeps its queue age. Cancelled and already admin-approved events are refused,
so submission cannot bypass the moderation guards and revive a cancellation.
Review fields are exposed only in the existing host/admin private projection.

Approve and send-back require pending_review (409 not_waiting otherwise).
Send-back requires a nonblank reason (400 reason_required), capped at 1000
characters, stored in review_note. "Sent back" is its own status, stored rejected,
not draft. State predicates are repeated in each atomic UPDATE so concurrent
moderators cannot both decide the same waiting submission.

Unpublish requires published, returns the event to draft and notifies its host
with an optional note. Cancel refuses an already-cancelled event, sends its
optional note to existing active registrants, and reports only paid registrations
with totals in recorded cents grouped by the event record's currency.
Registrations do not store a separate historical currency; this uses the existing
event-ticket schema and does not invent per-payment currency provenance. Notes are capped at 1000 characters.
The payment aggregate is read before cancellation; a failed read is not zero.
No refund or external payment operation is added (O-REF).

Featured ranks members' suggestions only. Studio-hosted events remain the owner's
O-STU decision. Existing route registration strings and suspension gates stay.
