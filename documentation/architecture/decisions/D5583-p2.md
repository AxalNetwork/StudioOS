## D5583 part 2 — Media classes in the existing blob store and member quota (#5583)

Preview-only internal service; Part of #5583, following merged part 1 and D5581 part 3.
No route, provider call, signed delivery link, rendition worker, production upload
or new binding. The initial ownership handoff question was withdrawn after
verifying #5581/#2449 closed and no newer open owner of these services.

### Storage and identity

Extend `workGraphBlobs.ts`, not a second blob service. Generic bytes keep the
legacy key and meaning. Creative media uses
`wg/v1/t<tenant>/c<company>/media/p<project-or-0>/<master|snapshot|rendition|thumbnail>/sha256/<digest>`.
Zero is the company-wide namespace, not a project. The same digest in another
class, project, company or tenant is a separate physical object. Repeated
bytes within the exact namespace reuse one object. Project isolation is a
narrower trust boundary within the tenant/company and keeps one project's
quota attribution separate from another's founder fallback. No cross-tenant
or cross-project dedup of private bytes.

Migration `202611220358_5583_media_blob_classes.sql` extends the existing
`work_graph_blobs` ledger's identity with project/class, preserving generic
rows without reclassification or invented attribution. The admitted owner is
a dated immutable audit snapshot; it does not freeze the company owner. Only
`deleted_at` changes, as before. Every physical copy is charged once, never
every revision that refers to it. The rebuild follows the existing migration runner; no production migration was executed here.

### Admission, quota and publication

`prepareMediaUpload` snapshots at most 8 MiB before its first await and uses
the landed format, MIME, structure, unsafe-metadata, rights and font rules. It
reads the registered asset and refuses wrong scope/kind, revoked authors, a
stale expected head, a derived version of a stale source, and stale dependency
pins. It returns a short-lived plan, not a reservation or release approval.

`storeMediaUpload` resolves the canonical company owner: the project's owner
through D1170, after verifying the project's company, or the first primary
admin for a company-wide asset. A missing owner stays unowned: D1170’s existing no-owner and unreadable-owner passes remain explicit, with no uploader substituted. It calls `assertStorageRoom` before putting bytes. Existing admin,
negotiated-plan and unreadable-meter behavior remains D1170's; this is not a
new concurrent quota reservation protocol. It rechecks admission after quota
reads and delegates the physical put/checksum/dedup to the existing blob
service. Threshold notices use `noteStorageLanded`, awaited, when bytes newly enter
the meter, including adoption of an intact orphan; an already charged retry adds nothing. Refusals and physical operations use the existing integrity log.
The receipt counts actual D1 prepares/batches and R2 operations, including
quota's article-list reads. No content/prompt enters an audit row.

`storageUsage.ts` counts live media objects under `work_graph_media` / Other,
shown as Creative media by both account readers. It derives the current
company owner/project-founder fallback exactly as the existing meter does;
ownership transfer moves the storage charge without rewriting a blob. The
shared area contract and route-map source describe it. No public Open route
is invented for an unmounted preview service.

The original D5583 class caps remain unchanged. This buffered path deliberately
refuses over 8 MiB; larger masters need the later checksummed multipart/resume
path. No unbounded request buffering or raised memory allowance is introduced.

### Readback, lifecycle, sources and rollback

Revision creation/head verification, byte reads and reconciliation understand
the typed key. Integrity is checked against the exact class/project source;
identical bytes in another class are not a substitute. Orphan/retention cleanup
marks only the matching project/class ledger row deleted, preserving a live
same-digest master. Existing offline flags, holds, residency and erasure rules
remain in the one blob service. Unsupported opaque formats remain immutable
variants. Master selection and head movement still use D5583 part 1's human
approval and the revision store's atomic CAS; an upload never moves a head.
A race after preflight can leave an orphan, collected through the existing
grace window rather than deleting another writer's object.

Third-party editor revisions remain canonical in their editor, under D5579;
this service accepts admitted local snapshots, not an editor URL masquerading
as uploaded bytes. No font binaries are copied. A stored rendition is uploaded
output, not proof that a renderer ran. Transforms/re-renders, provider workers,
throttled effects, multipart/resume and signed short-lived delivery remain
later parts, with #5571 and separate activation approval.

Rollback leaves the service unmounted and stops new typed uploads. Preserve
recorded objects and the forward-compatible reader/migration: do not drop or
backfill typed rows to roll back, and do not deploy an older generic writer
against the expanded conflict key. Any later activation must include its
migration/deploy order, quota-read cost benchmark and lifecycle rehearsal.

### Validation

Synthetic bytes, tenant/project scopes and SQLite/R2 test doubles only. Tests
cover all four classes, scoped dedup, a verified revision/head and readback,
corrupt bytes, stale/refused inputs, class-specific orphan cleanup, actual
migrated member quota, primary-owner transfer, and preserved generic rows, unowned files and orphan-adoption notices.
Existing media/variant/integrity/reconciliation, storage and account area
contract suites remain applicable. Worker type and SQL/folder/decision guards
are run locally. No production data, drill, upload or migration was used.

Local evidence: 64 scoped Worker tests and 52 account storage/frontend tests
pass. Nine targeted admission/namespace/cleanup mutations and five quota/
accounting mutations are caught. The real SQLite query plan uses two indexed
company/project/deletion lookups (MULTI-INDEX OR), without scanning the blob
ledger for member reads. Worker types, SQL columns, unused imports, folder
docs, decision IDs and diff checks pass. The batch's standard macOS SPA build
and full drift attempt hit existing case-insensitive import collisions
outside this slice; hosted CI must validate the normal case-sensitive build.
No test was skipped, disabled or quarantined to hide that limitation.
