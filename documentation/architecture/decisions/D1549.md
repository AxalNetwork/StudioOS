- **Status:** built in slot S25, 2026-11-01 (#3796, deck builder v2 Phase C, under #3716). Not deployed and not checked live.
- **Spec:** S1's final-canvas revision of #3796 (2026-11-01). Owner decision I = C (2026-11-01, on #3716): models are chosen per deck, plus an HQ default and lock.
- **Numbering:** #3796 gave D1549, and `check-decision-ids` found it free.
- **Migration:** none. Everything is stored in `deck_model_picks` (migration 717, D1503).
- **Builds on:** D1503's element routing (`services/decks/elementModels.ts`, `routes/deck_element_models.ts`), #3934's job table (`services/ai/modelUseCases.ts`, whose rows already carry `presets: { fast, balanced, best }`), D760's `catalogue.ts`, and D1604's AIRail groups and presets segment.

### 1. Presets per element group

- **What a preset is.** Fast, Balanced and Best. Custom is not stored: it is the deck's own group and element picks.
- **Where a preset's models come from.** `presetModelFor(element, preset)` returns the element's own job's `presets` row in #3721's plan, and only when that model is one of the element's choices. A group's preset is therefore its elements' rows: Images' Fast is the draw job's (DK4) Fast for a photo, and the edit job's (DK5) Fast for an edit. No model id is written in the new code, and a test fails on any `@cf/` literal in it.
- **How it is stored.** One `deck_model_picks` row: scope `deck`, scope id the project, key `preset`, and `model` holding the preset's name (`fast`, `balanced`, `best`). No run reads that column as a model id: the resolver maps it through `presetModelFor`.
- **Where it sits.** A new level, `deck_preset`, between the deck's group pick and the member's element pick. The order is now: HQ lock, area, deck element, deck group, deck preset, member element, member group, HQ default, row default (9 levels).
- **The preset in force.** `GET /api/decks/:id/model-presets` answers `preset`: the stored preset when the deck holds no pick of its own; `custom` when it does; `balanced` when it holds neither, since Balanced is each job's Default.
- **Pressing a preset.** Fast, Balanced or Best clears the deck's own element and group picks (its areas' overrides are kept) and stores the preset, in one batch, so the preset decides every group not locked. Custom clears the stored preset and keeps the picks. A group pick made after a preset makes the deck read Custom; the stored preset still holds every other group.
- **A preset model that cannot run.** A preset model the caller's plan does not include is skipped (the reply marks it `plan_locked`). One the catalogue does not offer now is skipped too, and the preset row is never cleared as a stale pick.

### 2. The org default and the org lock

- **Rows.** HQ's default for a group is the org row `group:<group>` with `locked = 0`; HQ's lock is the same row with `locked = 1`. D1503 already read both levels; C1 adds the way to write them.
- **The lock wins over every other level** (`resolveElementModel`). When HQ locked the element or its group, no level a member sets (area, deck element, deck group, deck preset, member element, member group) is read at all:
  - the lock's model runs;
  - if the caller's plan cannot run it, nothing runs: `model` is null, `locked` is true, and `lockedOut(r)` is true;
  - if the lock's model is retired or is not one the element offers (Images locked to a draw model, on an edit element), HQ's default and then the row default decide. Before C1 a member's pick could win in those last two cases.
- **The HQ table (aird6b).** `GET` and `PUT /api/admin/ai/deck-models`, a Super Admin's with a recent step-up (the gate of HQ › AI usage). One row per element group that runs a model: its label, its lead element's choices (the list the AIRail shows), the catalogue's Default, and HQ's row. A PUT `{ group, model | null, locked }` checks the model is offered now, allowed by policy and offered by the group (`keyOffers`); `null` clears the row; a lock needs a model. Each write is audited through `logAdminAction` (`deck_model_org_default`, `deck_model_org_locked`, `deck_model_org_cleared`) with the group, the model and the lock, never a name or an email.

### 3. The run and the quote

- **Every element through this.** `/generate`, `/new/quote` (build and card), regenerate-card and the deck's image quote and run already resolve their element through `elementModelFor` (D1503); they now see the preset and the lock.
- **A locked model runs pinned.** `runPickOf(r)` passes `pinned: true` with a locked model. `RunOptions.pinned` (new, in `aiRouter.ts`) makes `run()` and `quoteRun()` use that model and nothing else: the run is refused if the router would pick another primary, and a failure falls back to no sibling. Without it, a locked text model that failed fell back to the rail row's chain, so a model HQ locked out could answer.
- **Locked out.** When `lockedOut(r)`, the build and the image routes refuse with 403 `role_locked`: "Set by Axal VC HQ for this deck's Images. Its model is on Paid plans. Nothing was run." (pd9o's line, then why). Nothing is quoted, held or run.
- **The quote names the models.** The build quote now answers `element_models` (Body's model, its level, and `locked`), as the build already did; the image quote answers `element_models` for the photo or illustration element with the model the router chose.

### 5. The AIRail

- **Presets.** On a deck, `deckRailGroups.presetsFor(deckId)` reads the preset in force and `RailPresets` draws it pressed. A press stores it (`PUT`) and the group blocks and the locks read again. A refused press shows the Worker's message. With no deck (New deck, Templates) nothing is read and the segment stays greyed. When the rail is read only, the segment is not pressable.
- **The lock line.** `RailGroups` reads `groups.locks()` (the deck's `orgLocks`) once, and again after a preset press. A locked group says "🔒 Set by Axal VC HQ" under its name (aird5), before it is opened, and offers no pick. If `orgLocks` is off or unreadable, the line still appears when the group's own read says `locked`. The presets segment and the groups plumbing are D1604's; nothing was rebuilt.

### 6. Departures

- **Where the HQ table is.** The issue places it on B10's admin page. That page is not on main (B10 is blocked), so `DeckModelsCard.jsx` is drawn on HQ › AI usage (`/admin/platform/ai-usage`), the existing Super Admin AI page whose gate it shares.
- **Which rows the table has.** aird6b draws seven rows, including Graphics and Vision and checks. The table lists the groups the Worker answers: the element groups that run a model (Text, Images, Data, Diagrams, Venture records). Graphics runs none ("No model · free"), and Vision and checks is not a grid element group.
- **The lock as a switch.** aird6b draws a switch per row. It is a switch here, and each row has its own Save, because nothing may be written until the person saves.
- **One preset row per deck, not per group.** "Presets per element group" is read as: one preset choice on the deck, which maps to a model per group (and per element). A per-group preset is what Custom with group picks already is.
- **Pressing a preset clears the deck's own picks.** The issue does not say what happens to Custom picks. They are cleared so the preset decides, as the one-click bar asks; area overrides are kept.
- **aird6's "This area" model chip** is not built (S1: it contradicts the rule that models are picked in the AIRail only).
- **pd9g** (read-only HQ access: Models with no preset) is drawn only as far as the rail already knows it is read only: the segment is not pressable. The rail has no separate read-only support state to key it on.
