### What this part builds

- **The address.** `/hq/ai-agents/operations/policies/capabilities`, read by `viewFor` as `{ tab: 'operations', sub: 'capabilities' }`. The route is `frontend/src/routes/hqAiAgentsCapabilities.jsx` (collected by `App.jsx`'s glob; no `App.jsx` edit), on the same `hqOnly` HQ › AI agents page. Policies shows **Platform settings | Capabilities** above both views; Platform settings is SA6, unchanged.
- **`capabilityModel.js` (pure).** The five reserved names, locked whatever a read says (a row that claimed one grantable is still drawn locked); the canvas's column order; a cell as Granted, Not granted, Locked or Not offered; the ceiling row; the summary; the filters kept in the address (`?role=`, `?status=`, `?q=`); the reason rule; a refusal in the Worker's words; an agent's last refused run.
- **`CapabilityMatrix.jsx`.** The matrix (cells are named buttons, locked and not-offered marks are images, arrow keys move between buttons, a domain collapses to "granted of grantable" with `aria-expanded`), the panel (grant, revoke, locked, the header's picker, and on a phone an agent's list), the phone cards and the states. Writes go only through `aiAgentsPolicyApi.grantCapabilities` and `revokeCapability` (`POST …/capabilities/grant` and `/revoke`), each with the reason.
- **The last refusal.** No matrix field carries it, so each agent's newest refused run comes from the run log the panel already reads (`GET /api/admin/ai-agents/runs?agent=<uid>&status=refused`), and its code from that run's detail (`GET /runs/:uid`, `errors[].code`). No refused run reads "None", a failed read "Unavailable", a run with no code "code not recorded". The code links to Operations › Runs with `?run=<uid>`, which now opens that run's detail (`runFromSearch` in `Operations.jsx`).
- **Refusals in the Worker's words.** A refused grant or revoke shows the body's code and its own sentence (`{ error, message }`) inline, and keeps the reason. A request that got no answer says so and never shows the network error's text.
- **Missing data.** No grant ever recorded reads Not recorded on the summary and an empty mark ("nothing granted") on a collapsed domain, never "0" or "0/2". An unreadable policy reads Unavailable on the ceiling and on enforcement, never "nothing offered". A pair never held reads Not recorded under Last change. Last used is Not recorded.

No Worker route, schema, enforcement or data change. No capability is granted to any agent by this change.

### Option A, as built (owner questions)

1. **Per agent or per role (D4137-p2 Q1).** A) per agent, with "Apply to role" (built: a checkbox in the grant panel that grants the same name to every other live agent of that role, one grant each with the same reason, each done or refused on its own). B) per role only.
2. **When a revoke takes effect (Q2).** A) from the agent's next run; live runs finish (built: the line under every panel). B) halt live runs.
3. **Reason length.** A) 10 to 200 characters, as drawn (built; the Worker accepts 1 to 200 and stays the last word). B) 10 to 500, as the rest of HQ.
4. **Status words.** A) `team_agents`'s Active and Paused (built; Removed agents are not on the matrix route). B) the brief's live, paused, retired.
