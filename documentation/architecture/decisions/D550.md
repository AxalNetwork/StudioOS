## D550 — Recorded fund receipts and pending investor introduction requests

Issue #1140. Migration 312 already records append-only, dated capital-call
receipts. Fund analytics previously treated legacy LP invested capital as
called capital and the investor accounting page repeated it as collected.

The existing GP/admin analytics scope selects visible fund IDs before any LP
or receipt read. `readFundCapital` binds those IDs and independently sums call
lines (integer cents, with the existing legacy-dollar conversion) and receipts
for each LP. This avoids multiplying a call by its receipt count. Fund totals
sum the recorded rows, including partial payments. Collected and outstanding
are null with a reason when no receipts exist; a failed read returns Unreadable
and null cash amounts, never zero. A fully received call has a real zero
outstanding. An LP with no receipts stays Not recorded even if another LP paid.
Family cash totals stay unknown when a member's cash total is unknown.

Accounting consumes collected receipts and uses collected less deployed for
its existing dry-powder line. It shows called, collected and outstanding for
each recorded LP. These are recorded-ledger totals, not a bank reconciliation
or proof of complete historical contributions. Legacy DPI arithmetic is kept:
its paid-in denominator is now named separately so replacing called capital
cannot silently change performance. IRR's reason acknowledges dated receipts
and names the remaining missing complete cash-flow history and terminal
valuation. NAV, RVPI, TVPI, IRR calculation, fees, journal and close remain
outside this task pending #1138. No migration or new route is introduced.

Network adds only the requested action to person and organization rows. A
target comes from an attached founder user or project, never an inferred firm
or email domain. Multiple eligible organization targets require a choice.
The existing investor-only quota request route is unchanged. One shared lock
covers a target shown in both row types and rapid clicks before React renders.
Pending recorded asks disable repeats; unreadable ask history disables new
requests. Refusals show the route's own sentence. Success says Request pending,
never Introduced, and does not call consent, completion, outreach or Trust
Center routes. Existing proposition consent rules remain unchanged. S07 owns
the remainder of the Network page under #1023.

Canvas: `design/incoming/Investor LP Canvas.dc.html`, I6 and I7. The existing
accounting layout is retained with receipt-derived amounts and an LP capital
table using its existing collection table style. Intro actions are added to
I7's existing person and organization rows as explicitly requested by #1140;
the ask remains separate from the canvas's bilateral consent proposition.
The relationship row retains its two-column phone layout so action text cannot
be clipped by the later desktop grid override.
Desktop and phone verification uses local synthetic fixtures only.

Validation: regression tests execute ledger SQL against SQLite, prove partial
payments, legacy cents, no cross-fund sums, missing and failed reads, real zero
outstanding and unchanged DPI. Client tests exercise the shared request lock,
pending and refusal states, target selection and rendered action states. The
existing authorization and introduction consent suites also run unchanged.
Mutation checks break and restore the new assertions before the full build
and drift suite. Production deployment remains the owner's responsibility.
