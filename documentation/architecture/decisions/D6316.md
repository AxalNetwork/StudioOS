## D6316 — Read every prospects column with stable keysets (#6316)

The pipeline retains its existing per-status size (default 20, maximum 100),
source/campaign filters, seven counts and `updated_at DESC, id DESC` order.
Each column returns an opaque `next_cursor`; subsequent reads return that column
alone and the frontend appends it without replacing other columns. Failed page
reads preserve loaded cards and offer retry/reload. Refresh, source changes,
venture changes and edits from the sheet invalidate pending page requests.

A live mutable timestamp alone can skip an unseen row edited ahead of a cursor.
A 30-minute D1 membership captures contact ids, status and ordering timestamps
atomically. Subsequent pages keyset on those immutable timestamps and ids while
reading current card details. Counts and column membership describe that initial
view until reload; newly added or moved prospects appear in a refreshed view.
Deleted contacts disappear through cascading foreign keys. No contact content is
copied. Expired memberships are removed on the next first-page request. Cursors
are validated against stored membership, expiry, venture and selected filters;
the existing authenticated project reader gate still applies to every request.
An expired page refuses explicitly rather than silently skipping records.

The migration adds two short-lived tables and expiry/keyset indexes. Large
pipelines incur one membership row per matching contact per view. Roll back the
route/UI together; leave the additive tables until no old clients need them.
No production data or deployment was used for validation.
