### 1. One document, one row

The Contracts union already lists every e-sign envelope (source `esign`). A licence agreement version that has an
envelope **is** that envelope's document, so it is not a second row: its context is attached to the envelope's
row as `agreement`, and the row keeps `source: 'esign'`, so open, history, download, resend and void dispatch to
the envelope exactly as before. Only a version with **no envelope on file** — a draft, a version voided before it
was sent, a backfilled schedule whose envelope row is missing — becomes a row of its own, `licence_agreement` or
`licence_contract`, under a synthetic uid (`licence_agreement:<uid>`). Such a row has no envelope to open, so its
title is not a button and it says so; it opens on its licence. Both stores are read: the master territory licence
agreements (`licence_contracts`) and the package and program agreements (`licence_program_agreements`).

A database without either table (an older D1, or a test database built only from the tables it needs) reads it as
no rows; any other failure answers "Contracts are unreadable" as before.

### 2. The row's fields

`agreement` carries: the version's uid and store, kind and agreement type (Territory licence, Package agreement,
Program licence, Program schedule / addendum), licence uid and reference, territory (country codes), package key,
name and version, program key and name, counterparty (the licence's legal entity), template slug and version, the
legal state and its word, whether it is current, created/sent/signed/effective/superseded dates, envelope and
provider, whether a signed document is on file (and why not), and links: the licence, Program access (program
kinds), and the package (none yet: "There is no package page yet", #5021).

### 3. The legal state is the document's

`legal_status` is draft, awaiting_signature, executed, superseded or voided. A package or program version reads its
own status first (superseded, voided, executed, draft) and its envelope only while in flight (an envelope voided
or completed outside the flow). A master licence contract reads superseded from its row, then its envelope (D451).
Never the program grant's state: a paused grant leaves its executed schedule executed, and an executed schedule a
terms change replaced reads Superseded although its envelope reads signed (test 4). The union's own `status`
(draft/sent/signed/void) is unchanged for the existing filters and counters; an unsent version counts as a draft,
and a superseded unsent draft also counts under draft there (its `legal_status` says superseded).

### 4. Filters

`GET /api/admin/contracts` takes `agreement_type`, `agreement_status` (the legal state), `licence` (uid or
reference), `program`, `package`, `signed_from` and `signed_to` (YYYY-MM-DD, on the version's signature date, or
the row's for other rows), each validated against its allowed values (400 `invalid_contract_query` otherwise). The
existing `template` filter matches a version's template slug. Search reaches the licence reference, the holder, the
program and the package. The page offers the same choices (`lib/contractAgreements.js`, held to the Worker's lists
by the frontend test). Effective-date filtering is not offered: no master licence contract records an effective
date, so it would silently hide them.

### 5. The screen

`design/incoming/Contracts v2 Page.dc.html` (D4811) draws the agreements table but no licence, package or program
filters and no licence context on a row. So this PR keeps to the existing desk's patterns (labelled selects in the
filter bar; lines under the title) and the issue is marked `needs-design` for the canvas to place: the agreement
type, legal state, licence, program and package filters; the context line; the legal-state word beside the
lifecycle badge; and the three deep links.
