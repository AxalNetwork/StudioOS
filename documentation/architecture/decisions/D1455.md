### 1. One status (REC1, REC6)

`lifecycle({ bot, session, processing })` (`pages/founder/sessionLifecycle.js`, pure) merges the bot state and the processing state into one stepper:

Scheduled → Joining → Waiting to be admitted → Recording → Uploading → Transcribing → Summarising → Placing → Ready.

A session with no bot (this device, an import) starts at Recording.

Every step is read, never guessed:
- An unknown bot status or processing stage gives `current: null` and draws "Unreadable: this session's status could not be read. That does not mean it is ready." It is never drawn as Ready.
- A failed bot marks the step its failure code belongs to. `not_admitted` and `admission_refused` fail at Waiting, `schedule_missed` at Scheduled, `meeting_ended` and `no_audio` at Recording, and any other code at Joining.
- A failed processing run marks `processing.failed_stage` when the Worker sends it (D1456 W2). Without it, no step is marked, and the phone line reads "Failed at a step not recorded". The step is never guessed from the sentence.

`SessionStepper` (`pages/founder/SessionLifecycle.jsx`) draws the steps in a row from 1024px. Below 1024px it collapses to "4 of 9 · Recording" (`stepLine`), which expands. The current step carries `aria-current="step"`. The stepper shows on a bot session once its bot read has arrived, and on any session with a processing stage.

### 2. One failure panel (REC2)

`failureView` gives:
- **The title, in plain words:** D886's words for a bot failure (`botView(...).failure`), or the Worker's processing sentence, else "Processing stopped. Your audio is safe."
- **A short list of likely causes** for the failed step.
- **What Try again does:**
  - A processing failure: **Try again** posts `POST /sessions/:id/process` (`interviewSessions.process`, on main). "Import the recording or transcript instead" opens Record a session for the interview.
  - A bot failure: **Try again with a new session** opens Record a session for the same interview, a fresh session (Q3 A). The Worker refuses a second dispatch on one session (`session_in_use`).

"See details" holds the codes and times, for support: the bot's `failure_code`, the processing stage and failed stage, the bot's start and end, and the session id. No provider message, link or name is shown (D886's rule).

`MeetingBotPanel` takes `hideFailure` and `onRead`. The page reads the bot read the panel already holds, and the panel no longer repeats a failure in red. The separate "Processing stopped" card is not drawn when the panel is.

### 3. Transcript (REC4)

`TranscriptReview` takes `empty`, one line saying why there is no transcript ("No transcript: this session stopped before one was written. Try again above." on a failure). A bare "Not recorded" is drawn only where no reason is known.

### 4. Cost as money (REC5)

`money(micro)` gives two decimals, with the full value (four decimals) as the hover title.
- A value not read stays "Not recorded", never $0.00.
- A positive charge under half a cent reads "< $0.01", never "$0.00", which would say nothing was charged.
- A readable, empty receipt reads "Nothing was charged for this session.", the record read's own words (`validate.ts`). An unreadable one stays "Unreadable".
