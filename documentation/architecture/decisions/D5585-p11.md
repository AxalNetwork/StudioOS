### 2. Names

`releasePeople` answers `{ name }` for every user id a read returns, keyed by id; the name is `effectiveDisplayName`
(the profile's display name, else the account name: the one rule the public profile, bylines and Settings already use,
D4616). **Never an email, to anyone**: the Super Admin does not need one to read a release, and the reviewer must not
see another member's (#3841). One statement per read, none when the read names nobody; it is in the read's `cost`.

- **Super-Admin reads** name everyone they return: line creators, manifest authors (`authorUserId`, new on the
  evaluation), counted and not-counted reviewers (those asking for changes are among the not counted), grantees and
  the Super Admins who granted or revoked (holders and history).
- **The reviewer read** names only people linked to the reviewer's company, as the company page shows its members'
  names to its members; anyone else (an author who left, a Super Admin who cut a manifest without a link) is keyed
  with `name: null`. The pending items now carry `authorUserId` (WG-15 shows the author).
- **Attesters** are named by no read today: no release read returns an attester's id (the evaluation returns the
  requirements still missing, not who attested the rest). A later read that returns them adds them to `people`.

### 3. A line has no name

A release line is a `composite` asset (`work_graph_assets`) with a fixed row in `work_graph_release_lines`. Neither
table has a name or title column; a line is its uid, audience and project. Inventing one (a migration for a column
nothing writes) would leave every existing line nameless anyway and give the page a field no write fills. So the reads
say so: `lineName: null`, `lineNameReason: 'not_recorded'`. Beside it, `projectName` names the line's project when it
is one of the same company's projects and not deleted (`projects.company_id = line.company_id`, `deleted_at IS NULL`);
a project id of another company is never named. A line name, if the owner wants one, is a separate change: a column
set when the line is registered (the registering route does not exist yet either).

### 4. Why a decision does not count: one rule

`decisionNotCounted(ctx, manifest, lineAudience, decision)` is now **the** counting rule: `evaluate` calls it for every
live decision (each reviewer's latest row per profile) and counts exactly those it answers `null` for; every other one
goes to `notCounted` with the code it returned. There is no second copy of the rule. The codes, in the order the rule
checks them (the first that applies is the one given):

| Code | The decision… |
|---|---|
| `withdrawn` | is a withdrawal |
| `changes_requested` | is a reject or a request for changes (these reviewers are also `changesRequestedBy`) |
| `other_digest` | names another digest than the manifest's |
| `other_audience` | was given for another audience than the line's |
| `reviewer_revoked` | is by a person whose account is revoked (part 9) |
| `author_own` | is by the manifest's author |
| `authority_not_held` | is under an authority the reviewer does not hold now (part 8's store) |
| `authority_not_for_profile` | is under an authority that does not approve the profile |

Each `notCounted` item is `{ profile, reviewerUserId, authority, decision, decidedAt, reason }`. The test reads the
live decisions straight from the table and asserts that each is counted or not counted exactly once, that its reason is
the rule's answer for that row, and that every code is exercised (one row fails three rules and gets the first).

### 5. Scopes, status, candidates

All three are `requireSuperAdmin` (HQ only), behind the same switch.

- **`GET /scopes`**: every (tenant, company) with a release line, by tenant then company, each with
  `companyName` (`company_profiles.company_name`, null without a profile row), `companyArchived` and `lines`. At most
  200, with `truncated`. Tenants have no name on the platform; a tenant is its id. One statement.
- **`GET /status`**: `{ switches: { admin, delivery, sites } }`, booleans from the same predicates the routes use
  (`releaseAdminEnabled`, `releaseDeliveryEnabled` — `preview` — and `releaseSitesEnabled` — `on`). No other value of the
  environment is read or echoed. No D1 read past the gate. `admin` is always true when it answers (off, it is 404).
- **`GET /authorities/candidates?tenant_id&company_id`**: the people linked to the company (`user_company_links`, the
  only people a grant accepts), each `{ userId, name, active, held, seqs }`: what they hold now in exactly this tenant
  and company, and each authority key's current `seq` (what a grant or revocation sends as `expected_seq`; absent is
  0). Nobody unlinked is listed. `active: false` marks a revoked account (a grant would count for nothing). A company
  whose release records live under another tenant is refused `wrong_tenant` before anyone is listed, as a grant there
  would be. At most 200, with `truncated`. Two statements, plus the tenant check.
