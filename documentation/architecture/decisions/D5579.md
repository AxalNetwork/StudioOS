## D5579 — WorkGraph source of truth: the authority matrix and the versioned ChangeSet contracts (#5579)

- **Status:** Proposed for owner review, 2026-11-13. This is a planning record plus a pure contract module. It
  adds no table, no route, no binding and no data mutation. Part of the #5577 epic (P0, first on its critical
  path).
- **Number:** D5579 is this issue's number (D4106). No migration.
- **Builds on:** D4554 (one Worker/Hono control plane, D1 for records, R2 for bytes, DO and Queues for
  coordination); D5569 (the venture GitHub installation record, the first WorkGraph code adapter).
- **Code:** `cloudflare-worker/src/services/workGraphContracts.ts`.
- **Tests:** `cloudflare-worker/test/work_graph_contracts_d5579.test.ts`.
- **Evidence:** the D1 schema on `main` (`7ca13d975b`), read on 2026-11-13: `cloudflare-worker/sql/schema_baseline.sql`,
  `cloudflare-worker/sql/migrations/`, the Worker sources named below and `wrangler.toml`. No production row,
  bucket or account setting was read. "Exists in the schema" is not a claim that the store is populated.

### 1. Decision

WorkGraph is an **index and a policy layer over the stores StudioOS already has**, not a new content store.

- D1 holds WorkGraph's relational metadata and, later, the compare-and-swap revision head (#5581). It never holds
  large bytes.
- R2 holds immutable, content-addressed bytes, with their digest checked on read-back. It is never an editor.
- The content stays where it is canonical today: Git for code, the existing domain tables for legal templates,
  decks and offers, and the e-sign envelope for signed evidence.
- A WorkGraph record **points** at that content with a `SourceRef` (store, locator, id, revision). It never copies
  it into a second ledger.

Every record carries one scope: `tenantId`, `companyId`, and `projectId` (null for company-wide assets). This is
the shape D5569 adopted. Today `tenant_id` exists only in `venture_git_installations`. Existing tables scope by
`project_id` or `company_id`, through `services/tenancyScope.ts` and `services/projectAccess.ts`. An adapter
resolves the scope through those readers. It does not add a `tenant_id` column to a domain table.

WorkGraph's API (a later issue, not this one) sits behind the Worker's existing per-route auth: `requireAuth` and
`requireAdmin` in `src/auth.ts`, and `middleware/activeCompany.ts`. It reuses the following and adds no second
record of either:

- the approval inbox: `services/approvalSources.ts`, its lanes, and `approval_assignments`;
- AI run and charge identity: `agent_task_runs.uid`, `ai_usage_logs.id` and the reservation and charge columns.

**What this table does not license.**

- No content moves. An adapter (#5582 and #5583) reads the canonical table through its existing service.
- The duplicates above are listed so that WorkGraph never cites the derived copy. Retiring them is each owning
  domain's issue, not this one.
- A gap is never filled by inventing a store. There is no term-sheet record, no deal revision on `main`, no
  Figma connector, no 3D store and no design tokens. A WorkGraph asset of such a kind is refused until its
  domain issue lands.

### 3. Dataflow

```text
 agent run / person (existing auth; agent_task_runs.uid, ai_usage_logs.id)
        |
        v
 WorkItem (scope, deliverable, units it modifies, base version, deps, risk, idempotency key)
        |  admission: validateWorkGraph  -> refusal codes, nothing written
        v
 ChangeSet (base = asset head, proposed digest, components)
        |                                   +-------------------------------+
        |  bytes / structured JSON  ------> | R2: immutable, keyed by digest |  verifyVersionBytes
        |                                   +-------------------------------+  (read back, compare)
        v
 ReviewDecision (a person; exact content digest; approval inbox item)
        |
        v
 ArtifactVersion accepted --(#5581 CAS: expected head -> new head, in D1)--> Asset.headVersionId
        |
        v
 ReleaseManifest (pins asset + version + digest of every component; approvals; expected previous manifest)
        |
        +--> derived exports (PDF/DOCX/PPTX, renditions, Stream) in R2: never sources
        +--> signature: e-sign envelope becomes new, immutable evidence (legal_signed), never edited

 canonical content stays put:  Git | legal_templates | pitch_decks + pitch_card_blobs | quote_versions |
                               esign_envelopes + legal_document_files | R2 originals | remote editor @ revision
 WorkGraph holds only SourceRefs into them.
```

### 4. The contracts (`workGraphContracts.ts`, version 1)

The contracts are `WorkItem`, `Asset`, `SourceRef`, `ArtifactVersion`, `ChangeSet`, `ComponentRef`,
`ReviewDecision` and `ReleaseManifest`.

- **Fields.** They carry the fields the issue lists: scope, kind, actor (person, or agent with run, on-behalf
  user and charge), base version, parent ids, digest, byte length, media profile, recipe, access class,
  residency, licence, approval policy, expiry and the source revision.
- **Digests.** Every digest is lowercase hex SHA-256 of the exact bytes. A Git SHA is a source revision, not a
  digest.

`validateWorkGraph(graph, ctx)` is pure. It returns every violation with a fixed code and the ids involved:

| Code | Refuses |
|---|---|
| `wrong_tenant` | a record outside the caller's scope, or a version outside its asset's |
| `duplicate_id` | two records of one type with one id |
| `stale_revision` | a ChangeSet whose base is not the head |
| `cyclic_dependency` | WorkItems in a cycle, or a version that is its own ancestor |
| `revoked_author` | a revoked person, a revoked agent run, or an agent acting for a revoked person |
| `external_source_changed` | a version cut from a remote revision that is no longer current |
| `authority_violation` | a source that is not canonical for the kind |
| `immutable_record` | a ChangeSet on signed evidence or a released asset |
| `agent_review` | an agent approving |
| `stale_approval` | an approval of other bytes |
| `unpinned_component`, `unapproved_release` | a release whose bytes are not the version named, or were never approved by a person |
| `unknown_reference` | an id the graph does not hold |
| `malformed` | a missing id, an unknown kind, a non-hex digest, or a Git revision that is not a 40-hex SHA |

`verifyVersionBytes(version, bytes)` returns `digest_mismatch` when the digest or the length differs. This catches
a partial upload, a swapped object or a truncated read.

A revoked reviewer's approval does not count toward a release. A company-wide caller sees the company's projects;
a project caller sees only its own project.

### 5. Migration plan (proposed; nothing applied here)

Each step is a separate issue. Each is additive and reversible before anything is published.

1. **#5581** adds the WorkGraph tables: assets, versions, ChangeSets, reviews and manifests, with the CAS head. They
   are named by UTC minute (D4106) and carry scope columns, append-only triggers on versions, reviews and
   manifests, and a unique idempotency key per scope. It also adds the DO lease. It writes nothing into any
   domain table.
2. **Adapters (#5582, #5583, #5584)** map a domain row to a `SourceRef` through the domain's own service:
   - legal template: `legal_template_versions`;
   - deck: `pitch_decks` version plus `card_hashes`;
   - offer: `quote_versions` or `program_proposal_revisions`;
   - signed evidence: `esign_envelopes` with `legal_document_files`.

   Where the domain has no hash, the adapter computes the digest of the canonical bytes it reads and stores it
   only in WorkGraph's version row. It never alters the domain row.
3. **Preserved without change:**
   - `legal_templates` and all its version, publication and review rows;
   - every signed record (`esign_envelopes`, `legal_document_files`, `licence_program_agreements` once
     executed, `agreement_evidence`, `governance_document_versions`);
   - deal rows;
   - deck drafts (`pitch_deck_cards`, `pitch_deck_draft_doc`).

   No backfill rewrites them. A dual read happens only where an adapter must accept a pre-475 envelope's
   `signed_r2_key`.
4. **Rollback.** Dropping WorkGraph's own tables loses only WorkGraph's index. Every domain record is exactly as
   it was.
5. **Retention.** There is no document legal-hold record today: `services/dsrRequests.ts` states that no erasure
   policy exists. WorkGraph adds no deletion. Tombstones and expiry (`expiresAt`) follow the owning domain until
   the owner decides a retention policy.

### 6. Materialized index and dependency invalidation (design, for #5581)

- **Reverse dependency index.** A ReleaseManifest and every ChangeSet's `components` define edges from a component
  version to the outputs that include it. #5581 keeps that reverse index in D1, keyed by `(asset, version)`.
- **Invalidation on a new head.** When an asset's head advances, the index names every manifest and draft
  composite that pinned the old version. Their approvals become stale under the asset's approval policy, and
  only those outputs are re-rendered.
- **Admission check.** The same contract already refuses a release whose pinned digest differs from its version,
  or whose content no person approved. So a stale composite cannot be released, even if the index lags.
