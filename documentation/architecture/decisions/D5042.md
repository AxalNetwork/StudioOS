## D5042 — HQ Team: branch search is race-safe, and the browser and the Worker enforce one search contract (#5042)

- **Status:** Built for #5042, 2026-11-08. Package 3 of the HQ Team audit (P1). Built on #5041's branch (the same `/admins` route and the same table); its diff carries #5041's commit until that merges.
- **Builds on:** D128 (`likeNeedle`'s minimum), D138 (the Team read), D153 (view-as), D5041 (branch states).
- **No migration. No new route.** `GET /api/admin/hq/admins` gains `search`; `searched` now means "the branches were asked".

### What was decided

1. **One policy, in one place** (`cloudflare-worker/src/util/teamSearch.ts`). `normalizeTeamSearch` trims, collapses whitespace runs to one space and counts characters (code points). `none` (empty), `too_short` (< 2), `too_long` (> 64) ask nobody; `asked` (2 to 64) asks every branch the normalized string and only that. An over-long query is declined rather than truncated: a truncated query would search for something the operator did not type, and say nothing.
2. **The Worker enforces it** (`routes/admin_hq.ts`). A query outside the range makes no RPC, on the roster read and on the view-as (`?branch=`) read alike. The response says what it decided: `search = { state, query, min_length, max_length }`, and `searched` is true only when branches were asked. The branch RPC receives only `search.query`. Under view-as, a bound branch that was not asked is `not_asked` (an unbound code is still `not_deployed`, with no RPC), and the single-branch coverage no longer counts it as failed.
3. **The browser mirrors it** (`frontend/src/pages/hq/teamSearchPolicy.js`): the same two numbers and the same normalization, so the page does not send a request the Worker would decline. A test holds the numbers equal across the two files. The field carries `maxLength` and the hint "Type at least 2 characters to search the branches." appears for a one-character query.
4. **Reads are stale-safe** (`HqTeamTable.jsx`). Each read takes a generation number; only the newest may commit, success or failure. A slow answer for "gu" that lands after the answer for "gui" is dropped, and so is an older failure.
5. **Branch hits are shown as current only for the query asked now.** The table records which query its committed answer was read for (`answeredFor`). While a newer read is in flight the last answer stays on screen, dimmed, `aria-busy`, with "Showing the last answer (for “gu”) while the branches answer for “gui”." When the query is cleared the old hits are hidden at once ("Updating…"): they answer a question nobody is asking. "Nothing on this branch matched" is said only about the query it was read for.
6. **Local HQ filtering stays separate and immediate.** The roster is complete in the browser and narrows on each keystroke; only the branch request waits for the debounce.
7. **One polite live region** (`role="status"`, `aria-live="polite"`, tied to the field by `aria-describedby`) announces the hint, the search in flight, and what the branches answered ("2 matches on the branches for “gu”", "1 branch could not be read for “gu”").

### Not done
- No `AbortController`: `lib/api.js`'s `request` takes no signal today, so a superseded read still completes on the network and is ignored on arrival. Adding a signal there is an API-layer change this package does not need for correctness.
- Move actions on a dimmed (stale) hit are still enabled; the account they act on is the same account whichever query found it.
