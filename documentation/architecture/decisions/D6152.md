## D6152 — Deals: the dead fall-through to the old workspace is removed, and the text says what renders (#6152)

- **Status:** built 2026-11-14 by S12. Filed under #4815.
- **No Worker change, no migration.**

### What was dead

`InvestorDealsRoutes` drew `<InvestorDealsWorkspace embedded zone=…>` for a zone slug not in `ZONES`. The shell config lists three Deals zones (`screening`, `commit`, `closing`), and all three are in `ZONES`. ID1 Pipeline was retired by D1243, and the root renders Deal flow. So the branch could not render.

It is gone, with its lazy import. A zone route draws its own file. The root, and any path the shell config gives no zone, is Deal flow.

### Where `InvestorDealsWorkspace` still renders, and why the file stays

It renders from `InvestorWorkspacePage`'s deals branch, on `/pipeline`, for a session browsing **as** an investor that holds neither the Operating Partner nor the Investor licence. An Operating Partner holder goes to `PartnerBucketRoutes`, and an Investor holder is forwarded to Deal flow (`DealsPipelineRedirect`).

That page's other four paths (`/deals`, `/pipeline/screening`, `/pipeline/commit`, `/pipeline/transactions`) have no route that reaches it. The page is left unchanged.

The file stays because its Pass is the only control that answers an invitation `passed` (`POST /deals/:id/invitations/respond`).

### The invitation answers, as built

- **Accept:**
  - On the deal room, the stage track's "I'm interested" opens `RespondDialog`, and its confirm sends `interested`.
  - The old queue's Interested sends the same answer.
- **Decline:**
  - The old queue's Pass sends `passed`.
  - New for you's Pass on an invited deal (`PassDialog`) records a pass in Deal flow (`deal_flow_entries`). It does not answer the invitation, although its line says "The studio that invited you is told you passed."
  - That gap is reported on #6152, not changed here.
