- **Status:** Built, 2026-11-15 (Worker read, frontend). No migration.
- **Canvas:** `design/incoming/Raise Use Of Funds Page.dc.html`: UF1 (the Committed tile, `usedK`'s round row), UF10 (Committed so far in Compare). `design/incoming/Raise v2 Page.dc.html` RA21 and RA21b (the Remaining line, and Committed Unavailable).
- **Builds on:** D1176 (the plan read), D1177 (the tool), D1190 (the commitments read), D1191 (capital-relationships access).

### What was wrong

The Committed tile was a fixed "Commitments are not read here yet." and Compare's "Committed so far" row said the same. No Use of funds read carried the round's commitments.

### The read

`planRead` in `services/useOfFunds/read.ts` gains a `committed` block, and `GET /use-of-funds/compare` carries the same block. Both come from `committedRead`, which calls `commitmentsRead` in `services/capRelReads.ts`. Those are the figures `GET /cycles/raise/capital-relationships/commitments` serves: the same counted statuses, one line per investor, in the round's currency. The block is `{ state, source: 'Capital relationships', href, reason, value }`:

| state | when | value |
|---|---|---|
| `ok` | the read answered in full and an active round is recorded | `counted_cents`, `target_cents`, `remaining_cents`, `received_cents`, `amount_not_recorded`, the counted `statuses` with their words |
| `not_recorded` | no active round | null; `href` is Capital relationships › Commitments |
| `unavailable` | any source of the read did not answer, or access could not be checked | null |
| `refused` | the caller may not read commitments in Capital relationships | null |

**Access follows `capRelAccess.ts`, not the Use of funds gate.** The Use of funds route admits an admin. The commitments route refuses one (`support_read_required`) unless they make a reasoned support read. So an admin, a support session and anyone `capitalCanWork` refuses get `refused`, before any commitment SQL runs. Mercury's Received lines are read only for the founder, as `mercuryAllowed` already says for runway today.

**A partial read is Unavailable, not a smaller sum.** If any source is unreadable (`totals.partial`), the block gives no figure. A partial sum would show the round as less committed than it is.

**Remaining is target minus counted.** It is given only when the round records a target and every counted commitment has an amount. If one counted commitment has no amount, the sum is only a lower bound, so Remaining would be too high.

`commitmentsRead` used to read an active round that failed to load as "no round". It now records `sources.round` as unreadable, which sets `totals.partial`. So a round that cannot be read is Unavailable here, and Capital relationships lists it as a gap.

### The page

- **Committed tile (UF1):** "$X" over "of $Y · Signed, Wired · from the round", with the counted statuses that have investors. Unavailable and Refused say that word, muted. Not recorded links to Capital relationships › Commitments.
- **Remaining (RA21):** a line under the tiles, "Target $Y · committed $X · remaining $Z", shown only when Committed was read. When the read is Unavailable it is not shown, and an amber notice says so ("It is not $0") with Try again (RA21b).
- **Where this plan is used (`usedK`):** the round row reads "Committed $X · received $R · Signed" when Committed was read.
- **Compare (UF10):** Committed so far is the same figure in Today and in every scenario column, or the same state word with its reason.
