## D7748 — Research › Funds profile and comparison read: every sourced statement about a fund, with its wording, qualifier and source (#7748)

Part of #3701. Filed from the owner's Research › Funds audit of 2026-11-19. The layout-independent half of #7757 (profile) and #7759 (comparison rows): it changes what the Worker answers and draws nothing new on the pages on main.

### One read, the store's own rule

The single-fund read (`GET /api/research/fund-directory/:uid`, through `getFund`) and the project comparison read (`GET /api/research/projects/:uid/comparisons`) take their fields from `readFundStatements` (D7743) and nothing else: one call per request, for one fund or for every listed fund of a comparison, never one per fund. No SQL against the statement tables is written here, so the profile and the directory serve by one rule: a list whose verdict is 'not allowed' serves nothing, a description is served only under 'republish allowed', facts come from D7743's fixed list, a statement with a period is history, and a statement stored under a uid that moved is read under the new uid. The rows of `research_fund_vehicle_facts` come back from that read as statements, so `loadVehicleFacts` is no longer called by either route (it stays exported, unchanged).

If the statement read fails, every field answers `unavailable`, never `not_recorded`; the row's own facts, provenance and reports are still served, and the history's vehicle list is Unavailable as before. In the comparison, Manager, Stage, Geography and Cheque are left out of that fund's `values` (the page reads a missing cell as Unavailable), and the other cells stay.

### The answer (`services/researchFundProfile.ts`), additive

- **Main's four keys** (`manager_name`, `investment_stage`, `investment_geography`, `initial_cheque`) keep `status`, `value` and `provenance`. When a source states the field, the key gains `statements` (current), `past_statements` (those the store marks as history), `tied` and `old`. A field no source states answers main's object exactly, so a fund with no statements answers deep-equal to main on these keys. `observations` and `history` are not reused (`history.observations` is the size chart).
- **A statement** carries `wording`, `terms`, `old` and one `provenance` object (`provenanceOf`, the same as every chip); a money fact also carries `qualifier`, `currency`, `currency_basis`, `currency_verified` (a currency code is held) and `review_flags`, and `min_cents`, `max_cents` or `point_cents` only where the wording gave them; a past statement carries `period_start` and `period_end`. These names are the whole list. `source_record_ref`, the promoting user and the store's `origin` are not served. Order is `compareStatements`: latest reported first, undated last.
- **`tied`** is true when the first two current statements share a reported date (or neither has one) and differ (wording compared without case or outer spaces, then qualifier, amounts and currency). Then no statement leads and none is picked: `value` and `provenance` are null.
- **`value`** is filled only when exactly one statement leads and it has main's form: text; for the cheque a range, lower or upper bound in EUR, USD or GBP. Otherwise `value` is null with status `recorded`. Main's pages already read a recorded field with no printable value as "Not recorded: the value is held in a form this page cannot show" (`fundProfileRead.proposedRows`), and do so until #7757 lands. An average, a typical amount or an amount with no stated ISO currency (a bare symbol, `currency_basis: 'symbol_only'`) is served as worded, never as a range and never converted.
- **A past statement is never current.** A field with only past statements is `not_recorded` with `PAST_ONLY_REASON` and lists them under `past_statements`.
- **`manager_name`** keeps main's status, value and provenance from `research_fund_vehicle_facts`, so it is one string whenever recorded (the Sheet prints it on status alone); every statement, the new store's included, is listed beside it. A manager named only in the new store is still `not_recorded` here, with its statements listed. "Vehicles by this manager" keeps the text match until the Companies plan's identity replaces it.
- **Eight new keys under `proposed`** (`STATEMENT_FIELDS`): `stated_fund_capital`, `manager_aum`, `revenue_threshold`, `traction_requirement`, `lead_preference`, `interests`, `description`, `date_last_raised`. Each is `recorded` with its statements, `not_recorded` with its own reason (`STATEMENT_REASONS`), or `unavailable`, and always carries `statements`, `past_statements`, `tied` and `old`. They have no `value`. Stated fund capital never feeds `fund_size_cents`, the Reported size cell or the size chart. `sector_focus` is a D7743 fact but not one of these keys: the row's own Stated focus serves it, and it is in neither answer.
- **Old.** The landed canvas decision (D7032-p3, #7738 Q6, approved A) records the threshold: a statement is Old once its own reported date is older than 24 months (`OLD_AFTER_MONTHS`). The Worker measures it from its own date (`fundProfile(env, row, reviews, today = new Date())`), so no page reads the browser's clock: each statement's `old` is true, false, or null when undated, and each field's `old` (the Sheet's row) is its first current statement's. A date given only to the month or year counts from its last day. Q6 puts no flag on directory rows, so the directory list gains none.

`loadVehicleFacts`, `presentFact`, `fundCells` and `memberCells` keep accepting their present arguments; the 5157 and 7177 tests are not edited.

### The comparison (`routes/research_project_comparisons.ts`)

`fundCells` and `memberCells` take two optional arguments, the fund's statements and the date. Given them, the `stage` cell reads the statements and each fund member's `values` gains `geography` and `cheque` beside `manager` and `stage`: the leading wording as `value` (null when tied), the cheque's `qualifier`, `statements`, `past_statements`, `tied`, `old`, and `source`, `as_of` and `provenance` of the leading statement. No cell carries a rank, an order key or a converted amount. Without them the cells are main's. `ATTRIBUTES.fund` is unchanged, ten keys: the page draws one row per listed attribute and the canvas (FND-P06) draws ten, so the two rows appear with #7759. Only the fund portions of the file are touched (#7823 holds its company portions).

### Not here

`researchFundDirectory.ts` (`getFund` passes these objects through), any frontend file, any write. The read shows whatever the statement store holds: if the Companies plan populates statements for the existing lists, they appear with no change here. Firm against vehicle identity is that plan's; this read only labels what a source said.
