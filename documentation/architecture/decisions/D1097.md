### 2. Migration 590: `vercel_health_events`

**The columns:**
- `kind`, held by CHECK: `production_failed`, `rollback`, `domain_misconfigured`, `domain_unverified`, `certificate_failed`, `domain_expiring`;
- `subject`, a deployment id or a domain;
- `opened_at` and `closed_at`;
- `source`: `sync` or `webhook`;
- `vercel_project_id`;
- `dismissed_at` and `dismissed_by`, both set or neither.

**The keys:** `UNIQUE(integration_id, project_id, kind, subject, opened_at)`, as the issue gives it. A partial unique index allows **at most one open row per kind and subject**. `closed_at` is never before `opened_at`.

**Nothing personal:** no log, commit message, creator or person is stored. Nothing is backfilled.

### 3. Open and close on evidence (`health.ts`)

`healthFindings(evidence, now)` reads only what the API returned. It never reads a webhook body; part 1's webhook is a nudge that re-reads.

| Kind | Opens when |
|---|---|
| `production_failed` | the newest production deployment is `ERROR` |
| `rollback` | production points at a deployment older than the newest `READY` one |
| `domain_unverified` | a project domain reads `verified: false` |
| `domain_misconfigured` | a project domain's configuration reads `misconfigured: true` |
| `certificate_failed` | a read names a failed certificate. Part 1's client has no certificate read yet, so this opens only when one is passed. |
| `domain_expiring` | a Vercel-registered domain (Vercel knows its `expiresAt`) that one of this project's domains is, or sits under, expires within 30 days, or within 14 with auto-renew off (§6) |

- **What it returns:** each event, and **which kinds it could check**. A source that was not read checks nothing.
- **`applyHealth`:**
  - opens what is newly true, each with its `connector_fed_items` row `health:<kind>:<subject>:<opened_at>` (module `operating_systems`), in one batch;
  - keeps an event that still holds, and touches its ledger row;
  - closes an open event only among the kinds the evidence checked, so **a partial read never closes what it could not see**.
- **When trouble returns:** evidence that clears and later comes back is a new event, with its own `opened_at`.

### 4. Dismiss, and the Hosting read

**`DELETE /api/cycles/build/vercel/health-events/:id`** is `canWrite`, through `writeContext`, so an Operating Partner who reads the board cannot dismiss.
- It dismisses an open event of the venture, and writes one activity line in the same batch.
- **A dismissed event stays open until its evidence clears.** The next sync finds it open and opens nothing new, and the read leaves it out: it never comes back.
- **Refusals:**
  - 404 for another venture's event;
  - 409 for a closed event ("has closed") or one already dismissed.

**`parts.tools.hosting`** sits on Operating systems beside `code` and `syncs`. It is **its own read, Unreadable on its own**: "Unreadable: Vercel could not be read. The rest of this page is current." It holds each Vercel connection enabled for the company:
- Hosting, Vercel, "From the Vercel connection";
- its state and last sync, the owner by the Tools rule, and Open;
- its health: the open count, the count closed in the last 30 days, and the events, open ones first.

**The Tools rule:** the owner and the company's members read each event's domain or deployment. Anyone else reads the counts, with `items: null`.

**What it says while part 1 waits:**

### 6. Owner question: the expiry window

#2408 and #2962 both say "expiring within 30 days, or 14 with auto-renew off". Read literally:
- a domain that auto-renews is flagged 30 days out;
- one that does not is flagged 14 days out.

That warns later about the domain more likely to lapse. Both figures live only in `EXPIRY_WINDOW_DAYS`. The options are:
- **A.** As written: 30 days with auto-renew on, 14 with it off. **Built.**
- **B.** Reversed: 30 days with auto-renew off, 14 with it on. **Recommended.**
- **C.** One window, 30 days, whatever auto-renew says.
