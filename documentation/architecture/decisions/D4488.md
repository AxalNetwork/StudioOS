## D4488 — Distribution Ask proposals and safe acceptance (#4488)

Distribution drafts are `distribution_draft` runs. `POST /api/grow/distribution/ask/quote`
quotes without running or holding funds; `/run` recalculates that quote and refuses
with 409 when the displayed hold/model no longer matches. The server-derived hold
caps the run. Usage records the fixed Distribution page, option and venture record.
The receipt sums recorded member charges for the run and its guard checks; missing
charges remain Not recorded. A new quote never accepts a client-selected price cap.

Only the venture's own selected sources are read: unarchived Validate segments/ICP
and pain-group titles; discovery notes/pains with explicit quote consent, without
identity columns or raw transcripts; and Distribution channel names/state. No bank,
team-only financial store, customer contact or other venture is read. Source records
and reply context are untrusted data. Outputs must match the requested text kinds,
indices and strict field limits. No dates, money, rule or action fields are accepted.

Generated text is stored only as the member's D780 proposals under
`Founder · Grow · Distribution`, `draft:distribution`, `distribution:<project>`.
The list is member- and venture-scoped, open only, without agent-owned proposals.
Every operation checks venture write access; support sessions cannot act. AI-paused,
allowance and page-assistance refusals come from the shared router and fixed member
sentences, never provider exceptions or output.

`accept-safe` returns a result per UID. Only post copy, subject lines and newsletter
text qualify. Replies, outreach, ad creatives, sends, schedules, ad spend, budgets,
rules, unknown/extra keys and structured money never qualify. The individual route
validates the same ownership and payload before Accept/Edit/Discard. Generic D780
accept/edit cannot bypass this route. Every decision is once-only and audited.

Accept never sends, posts, schedules, activates, calls an ad provider or changes a
budget. An individual campaign-target ad proposal writes only its text to D4483's
existing `grow_campaign_creatives`, with campaign ownership, open-proposal and
not-ended predicates in one transaction. If the campaign ends before that transaction,
neither the creative nor the decision changes. Other text acceptance records a
proposal decision only. No second campaign store/router/client is introduced.

The wizard explicitly asks with `target:form`. Accept/Edit returns decided proposals
to its `onAccept` callback; the host places text/selected Name, Goal or Audience values
in local manual fields, marked Not saved until the existing Create/Save draft press.
Dates, budgets and UTM remain manual. Campaign fields are form-only and selected
field edits are validated without saving campaign fields. The public integration is
`DistributionAskIntent({projectId,campaignUid,kinds,now,onAccept,onClose,api})`;
`kinds` accepts strings or `{kind,channel_uid?,placement?,field?,context?}`. A reply
context is bounded text, never a recipient or send instruction. Safe text kinds are
`post`, `subject_line`, `newsletter`; individual kinds also include `outreach_email`,
`reply`, `ad_creative`, and form-only `campaign_fields`.

Waiting for you uses the shared Ask slot with an optional exclusive intent: no
conversation, suggested chips or composer while that intent is active; other intents
retain their existing behavior. Header and panel counts come from the same scoped
open-row projection. Unreadable counts have no chip. Loading, Nothing waits for you,
and remaining proposals during token exhaustion are explicit states. Models and
usage stay in AIRail, with no new actions there.

Dependencies: #4483 / #4503 supplies the creative store. #4484 / #4505 owns the shared
Distribution shell and Ask presentation; #4487 owns the wizard/manual field callback.
The draft PR records which integration is available at its current head.
