### Validation

The D666 guard, `checkMcpDeployment`, reads `wrangler.toml` through the installed wrangler's `unstable_readConfig`, the reader `wrangler deploy` uses, once for the top level and once for every environment the file's raw `env` table declares (`experimental_readRawConfig`); `production` and `preview` must be among them. It therefore checks the bindings wrangler would ship however the TOML spells them, and a config or an environment wrangler cannot read fails. It fails when any of those scopes declares an `unsafe` key, which `wrangler.toml` never has: `unsafe.bindings` and `unsafe.metadata.bindings` can name a D1 or KV id that the store comparison never reads. It pins exactly one OAuth binding in each of the top level, production and preview (the owner's id at the top level and in production; in preview, an id HQ does not bind) and the flags: `HQ_MCP_FLAG` at the top level and in production, `"false"` in preview and in any other environment. In every environment other than production, each D1 binding must name its own `database_id` and each KV binding its own `id`, and no D1 binding may use a `database_name` HQ's D1 uses: a D1 binding with no `database_id` is looked up by name at deploy. It also fails when any D1 or KV binding in an environment other than production names a store id (`id`, `preview_id`, `database_id` or `preview_database_id`) that a D1 or KV binding at the top level or in `[env.production]` names. The ids it compares have their quotes stripped and escapes decoded, as wrangler reads them, and are then lower-cased so a hex id matches in any case. Mutation/restoration probes flip each flag, comment/remove a binding, change its id and duplicate it. They put HQ's ids into preview's `OAUTH_KV`, `TOKENS` and D1 in each TOML string spelling, under a header with spaces or a quoted segment inside its brackets, under a quoted key, in a `preview_id` or `preview_database_id`, and in an extra preview table placed where a line-based parser would file it under `[env.preview.ai]`. They add `unsafe` metadata bindings naming HQ's D1 and OAuth ids inline in `[env.preview]`, and an `[env.preview.unsafe]` table; and an `[env.inspector]` on HQ's OAuth namespace, with MCP on or off, a D1 binding there named only by HQ's `database_name`, one with an empty `database_id`, one under HQ's `database_name` with its own id, and a KV binding with no `id`. A `CLOUDFLARE_ENV` set in the test's environment cannot make the top level read as another scope. Existing real OAuth/SQLite D666/D669 tests still exercise the handshake, context, interview submission, pending placements and refusals, using local fixture stores.

Branch renderer tests and mutation/restoration probes keep MCP off, omit HQ's OAuth binding, reject re-enablement and reject a copied namespace. The probes render from `wrangler.toml` with HQ's production flag forced to `"true"`, so removing the renderer's forced `"false"` fails whatever the live flag is. The topology binding catalog includes OAuth as HQ-only; the branch payload omits it rather than reporting an undeclared binding as missing. Its tests derive the sole exception from the generated branch config and mutation-check the row, scope and runtime presence. The generic binding-parity and branch-config guards remain required. Full validation builds the root SPA before `npm run test:drift`; no build output, new secret or D1 migration is committed.

Five reviews shaped this correction before it merged. The first was an adversarially verified S1 review of the merged change; each later one reviewed the correction before it. The list below describes the final state and names the review that found each problem.

1. **Preview shared HQ's OAuth store (major, latent; first review).** `[env.preview]` bound HQ's namespace id while running on its own D1 (`studioos-db-preview`). `revokeAllGrants` (`cloudflare-worker/src/mcp/grants.ts`) runs whenever `OAUTH_KV` is bound, flag on or off, and revokes `grant:<userId>:*` by numeric user id. So a preview Worker's sign-out-everywhere, TOTP re-pair or deletion request would revoke the grants of whichever HQ member holds the same id; a verifier reproduced this with fixture stores. No `studioos-preview` Worker exists and preview's other ids are placeholders, so nothing was exposed. The source was S1's own 2026-10-13 comment on #1555, which said to fill all three `OAUTH_KV-PENDING` blocks with the id; #1630 followed it, and its new guard required the shared id. Now preview binds `REPLACE_WITH_PREVIEW_KV_OAUTH_ID`, the provisioning list above `[env.preview]` includes `npx wrangler kv namespace create OAUTH_KV-PREVIEW`, and the guard requires HQ's id at the top level and in production and refuses any of HQ's D1 or KV ids in preview (item 4). Branch configs still omit `OAUTH_KV`, and `check-branch-config` still refuses HQ's ids.
2. **The switch-off steps could not hold (first review), and the first correction's could not revoke (second review).** Flipping the flag and running `npm run deploy` fails the pinned guard once committed, and a hand deploy is undone by the next CI deploy. The first correction made a `wrangler rollback` to `e3fb5042-82ca-4c4d-93b9-6f6ced4c8d8a`, the deploy of `7309b8a19`, the immediate step. That version's log lists the KV namespaces `TOKENS` and `RATE_LIMITS` only, and `revokeAllGrants` returns 0 when `OAUTH_KV` is unbound (`cloudflare-worker/src/mcp/grants.ts:105`), so every revocation path would have stopped while it was live, against this record's own "keep the binding". The immediate step is now a hand deploy of `main` with `--var MCP_SERVER_ENABLED:false`, which keeps the binding: wrangler 4.147.0 writes a `--var` over the `[vars]` value of the same name, as the deploy job's `--var WORKER_DEPLOY_VERSION` does on every deploy. The lasting step is a three-line PR to `main`, and `wrangler rollback` is a last resort. The `wrangler.toml` comments beside the two flags name the three lines.
3. **The lasting PR failed CI (second review).** The mutation test kept a second copy of the expected flags, and the branch renderer's mutation probe caught the removal of the forced `"false"` only while HQ's live flag was `"true"`. The expected HQ flag now lives in one constant, `HQ_MCP_FLAG` in the D666 test, and the renderer's probes run against a fixture with HQ's production flag forced on in `scripts/lib/branchConfig.test.mjs`. A scratch copy with exactly the three documented edits passed both tests, the D669 test, `check-wrangler-binding-parity`, `check-branch-config` and both topology tests.
4. **The guard did not read the TOML as wrangler does (second to fifth reviews).** The first correction checked only preview's `OAUTH_KV` and compared raw TOML text, so a preview id written as a literal string, `'a536…'`, passed although wrangler reads it as HQ's namespace. The second correction checked every preview D1 and KV store id and unquoted, unescaped and lower-cased ids before comparing them. It still read `wrangler.toml` through `parseSections` (`scripts/check-wrangler-binding-parity.mjs`), a line-based parser that skips a header with spaces or a quoted segment inside its brackets (`[[ env.preview.kv_namespaces ]]`, `[[env."preview".kv_namespaces]]`) and ignores a quoted key, filing what follows under the table above or nowhere. An HQ id spelled that way reached `[env.preview]` unseen: four such probes passed that guard. The guard now reads each scope through wrangler's own reader. The fourth review found that it still read only the top level, production and preview, and only their D1 and KV tables: an `unsafe` binding in `[env.preview]`, or a new `[env.inspector]` on HQ's OAuth namespace with MCP on, passed it. It now reads every environment the file declares and refuses any `unsafe` key. The fifth review found that a new environment could still bind HQ's D1 by `database_name` alone, with no `database_id`, which wrangler resolves at deploy; every environment but production must now name each D1 and KV store by its own id, and none may use HQ's `database_name`, as the Validation section above describes. It also found that the hand deploy needs both packages installed first.
