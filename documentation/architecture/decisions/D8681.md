## D8681 — Every workspace screen names itself in the browser tab, and each navigation resets the title (#8681)

- **Status:** built 2026-11-27 (S14).
- **Builds on:** D4815 (Deals names each route, "Deal flow · Axal VC"), D4582 (`usePageMeta` puts a public route's head back on a client-side move), the route registry in `frontend/src/lib/ogRegistry.js` and the prerender (`scripts/prerender-og.mjs`) that bakes each public route's `<title>` (Terms, Privacy, Help).
- **No migration, no Worker route, no client method, no new dependency, no new CI step.**

### What was wrong

A workspace screen had a tab title only if its own page set one. Deals, Portfolio, a deal room and a few account pages did; Approvals, Contracts, Security, Research, Help's tickets and HQ did not, so they kept the shell's "StudioOS, the founder workspace — Axal VC StudioOS". Deals set its title with no cleanup, so the next screen that set none (HQ) kept "Deal flow · Axal VC" after it had settled, not only at the handoff.

### The decision

1. **One table, one format.** `frontend/src/lib/pageTitles.js` decides the title from the address alone, in the form `<Screen> · Axal VC` that Deals already used. `routeTitleFor(pathname)` answers, in order: a screen named in `WORKSPACE_SCREENS` (each licence's landing page — every licence lands on Studio, a Super Admin on HQ, an exploring account on its Studio, a pending one on Onboarding — plus HQ's Team, Contracts, Security, Approvals, Help's tickets, Deals, Trust and Settings); a public route in the registry, with its own `ogTagsFor()` title, so a client-side visit says what the prerendered HTML says; a workspace bucket or zone from `workspaces/shellConfig.js` ("Companies · Research · Axal VC", "Funds · Research · Axal VC"); a sidebar row from `sidebarConfig.js`; otherwise **"Axal VC"**, the safe title. Matching is by whole path segment and the longest prefix wins, so a record's page takes its screen's title (`/admin/contracts/<id>` is "Contracts · Axal VC").
2. **No names in titles.** Every label comes from static configuration. No member name, company name or record title enters a title through this table. (Three pages already set narrower titles from records: `DealRoomPage` names the deal's project, Portfolio names the company, a connector names its provider. They run after the table and are unchanged here. Whether those should drop the record's name is a separate call.)
3. **Reset on every navigation.** `App.jsx` mounts `<RouteTitle />` beside `<Routes>`, *before* them. Its effect runs on every pathname change. React runs every unmount cleanup before any mount effect, and an earlier sibling's effects before a later one's. So a stale title (Deals' uncleaned one, or a page's cleanup putting back the title it found) is replaced, and a page that names itself more narrowly (a Deals tab, a Help guide, a programme page) still runs after the table and wins.
4. **Safe while unknown.** While a session with no cached user is loading, a workspace path shows only "Axal VC": the page, a refusal or a sign-in redirect has not been decided yet. The background re-sync of a cached user decides nothing, so it leaves the title alone (an early version flipped every settled title to "Axal VC" and back on each navigation, which the browser spec caught). A route that crashes into `RouteErrorBoundary` shows "Axal VC". An unknown address shows "Axal VC" over "Page not found".
5. **Prerendered titles are untouched.** On the first render of a public path the hook does nothing: the HTML already carries that route's own title, which may be narrower than the registry's (a Help guide's, a programme's). Later visits in the same tab set the registry title, and the page's own `usePageMeta` then applies its narrower one as before. `ogRegistry.js`, `seo.js` and the prerender are unchanged.
6. **One Deals format.** Three Deals pages still used "— axal": the Studio lens ("Deal flow — axal"), the investor deals workspace ("Deals — axal") and the embedded round calls ("Round calls · Deals — axal"). They now say "Deal flow · Axal VC" and "Round calls · Axal VC", as `DEALS_PAGE_TITLES` does.

### Verification

- `frontend/test/page_titles_8681.test.mjs` tests the table and the hook in a router. It covers a cold visit, Deals → HQ, Back and Forward, a narrower page winning, a cold public visit, loading, and the source order in `App.jsx`.
- `frontend/tests/e2e/page_titles_8681.spec.js` loads the built SPA in Chromium as an invented Super Admin, with fixtures. It checks a cold visit to nine screens; same-tab navigation through Contracts, Security, Deals, HQ, Research Companies and Funds; Back ×3 and Forward; Terms and back; the signed-in `/` redirecting to Studio; and an unknown address. Each title is checked again after the network is idle plus 400 ms, and must not have moved. Each change is logged with its time since the navigation began, together with the page's `h1`. In the run recorded on the PR, a same-tab change landed in 70–250 ms and a cold one in 170–1,060 ms. Every settled title matched its heading, except HQ: its `h1` is "Platform", under the crumb "HQ · Home". The spec is not in CI (see the PR's report). Run it with `npm run build` at the root, then `cd frontend && npx --no-install playwright test -c playwright.config.js tests/e2e/page_titles_8681.spec.js --trace off`.
- **Manual checks, not yet done.** The issue asks for two checks that need a person:
  1. **Two tabs.** Open Contracts in one tab and Security in another, then Research › Companies and Research › Funds. Switch between them with the tab strip and with Ctrl/Cmd+Tab. Each tab's label and hover tooltip should name its own screen. In a third tab, go Deals → HQ and confirm the label says "HQ · Axal VC" once HQ has drawn.
  2. **Screen reader.** With VoiceOver (VO+F2 reads the window title) and NVDA (Insert+T), read the title on each screen above after a cold load, after a sidebar link and after Back. Each should read "<Screen> · Axal VC", never the shell's marketing title, never a stale "Deal flow". Neither reader should announce a person's or a record's name.
