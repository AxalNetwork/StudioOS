## D539 — The EIF and EIFO flags say only what a fund's notable LPs say (migration 380)

**A fund is flagged as backed by the European Investment Fund (EIF), or by
Denmark's Export and Investment Fund (EIFO), only when its notable LPs name
that fund as a whole name.** Slot S07, issue #1084 (part of the Research
rebuild, #1077), 2026-10-06. Owner call **A** on #1084.

### The bug, and the call

- **Migration 365's importer** (`scripts/import-eurotech-funds.py:92-93`)
  tested a substring, `'EIF' in notable_lps`. "EIFO" contains "EIF", so every
  EIFO-backed fund was also flagged as EIF-backed.
- **Migration 378** (D535, `scripts/import-research-funds.py`) rebuilt the
  directory and took both flags from two unheaded spreadsheet columns, L and M.
  - Column L reads 1 on 268 of the 269 rows whose LPs name the EIF, but also
    on 307 rows that name none.
  - Column M is not EIFO: it reads 0 on all 12 rows that name EIFO.
- **The owner chose A:** recompute both flags from `notable_lps`, in a new
  migration and in both importers, so a flag claims nothing the LPs don't say.

### The rule

It lives in one Python function, `scripts/fund_lp_flags.py::lp_flags`, and in
migration 380's SQL. The two are checked against each other.

| Flag | Matches |
| --- | --- |
| EIF | "European Investment Fund" in any case, or `EIF` as a whole token: no ASCII letter directly before or after it. "EIFO", "EIFFEL" and "Seifert" do not match. |
| EIFO | `EIFO` as a whole token, or "Export and Investment Fund" in any case. |

**The EIFO spellings found in the spreadsheet**
(`attached_assets/EuroTechVCFunds(from1_2016)-Sheet1.csv`):
- `EIFO`
- `Export and Investment Fund of Denmark`
- `Export and Investment Fund (EIFO)`
- `Denmark’s Export and Investment Fund (EIFO)`

EIFO's predecessor (Vækstfonden, the Danish Growth Fund, merged into it in
2022) is not EIFO's name, so it is not matched.

**In SQL, with no REGEXP on D1**, the token test pads the text with a space at
each end and asks `GLOB`, which is case-sensitive, for
`*[^A-Za-z]EIF[^A-Za-z]*`. The names use `LIKE`, which is case-insensitive
for ASCII. The Python matcher uses the same character class and the same case
rules.

### Migration 380

- **What it changes:** `eif_flag` and `eifo_flag` on the EuroTech rows
  (`source_name = 'EuroTech VC Funds (public spreadsheet)'`), and only where
  the value changes. No other column and no other source.
- **It is idempotent:** a second run changes nothing.
- **Migrations 365 and 378 are not edited.**
- **Counts:**
  - On a database built from the migrations (378's rows), 380 changes 499
    EuroTech rows.
  - The 4 October breakdown of the same 499: EIF 1→0 on 248 and 0→1 on 1;
    EIFO 1→0 on 326 and 0→1 on 11.
  - The issue's "7 rows on production" was measured before 378. Production
    applies 378 and then 380 in order, so it ends on the same flags as the
    build.

### Importers

- `import-research-funds.py` (378's generator) now reads the flags from the
  LPs with `lp_flags` rather than columns L and M. Applying 380 to its fresh
  output changes 0 rows.
- `import-eurotech-funds.py:92-93` (365's generator) uses `lp_flags` too. The
  rest of that file is #1081's.
