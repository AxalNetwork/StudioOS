### The rule (Q1, Q3)

A Library row added from a room is a reference, not a copy. It stays tied to the grant it was added under.

The row is the investor's own `research_documents` row:
- read only, kind `diligence`;
- its `r2_key` is the room file's key;
- its `size_bytes` is NULL, so the room's bytes count against no one's storage (Q4: indexing is not charged);
- it is indexed in the investor's own namespace, like any upload.

`services/roomLibrary.ts` decides whether a reference still reaches its file. The first rule that fails names the reason the row then reads:

| Reason | When |
| --- | --- |
| `library_off` | the founder's per-room switch is off |
| `revoked` | the grant is no longer active, or is gone |
| `expired` | the grant's `expires_at` has passed |
| `removed` | the file is gone from the room |
| `moved` | `tierAdmits` no longer admits it to that grant (its tier, its expiry, or the grant's folders) |
| `nda_lapsed` | the file is behind the NDA and the NDA is no longer active |

A lapsed row stays, with `lost_at` and the reason. Its index entries are deleted at once, its index state reads `source_lost`, and it is never indexed again (`reindex` answers 409 `source_no_longer_available`). The indexer checks the reference before it reads the file and again after it writes, so a lapse during a run leaves nothing answerable.

**When the rule runs.** `reconcileRoomRefs(user)` runs before:
- the Library list (`GET /api/research/documents`);
- Ask (`POST /api/research/ask`);
- the Library citations a fill makes (`services/fills/citations.ts`);
- the room's own Library read.

So a reference never answers past the moment its grant stopped reaching the file. Turning the switch off lapses every reference to the room at once (`lapseRoom`).

**The file is followed.** When the founder replaces the file, a live reference takes the new key and is indexed again.

### Store

Migration `202611161204_6869_room_library.sql` adds two tables. No column is added to `research_documents`.
- `research_room_refs`:
  - the Library document, its owner, the room, the file and the grant;
  - when it was added;
  - `lost_at` and `lost_reason`, with a CHECK that the two are set together.
  - A partial unique index holds one live reference per investor and file.
- `data_room_library_settings`: the founder's per-room switch. A room with no row is off (Q2).

### Worker

`routes/room_library.ts`, mounted at `/api/room-library`.

| Method | Who | Rule |
| --- | --- | --- |
| `GET /rooms/:projectUid` | an investor with an active grant | Whether the room allows Library copies, and the caller's live references in it. No grant and no room answer alike (404 `room_not_found`). |
| `POST /items` | an investor, not an admin or a support session | The room's own gate, re-checked: the grant, `tierAdmits` (a hidden file is 404 `file_not_found`) and the NDA (403 `nda_required`, logged as `blocked`). The switch must be on (403 `library_off`). A second add is 409 `already_added`. Logged as `library_add`. |
| `DELETE /items/:documentUid` | the row's owner | Index entries first, then the reference and the row. The room's file is never touched. Logged as `library_remove`. |
| `GET /settings/:projectUid` | the room's owner or a cofounder | The switch, the live references, and `can_change`. |
| `PUT /settings/:projectUid` | the owner only | Turning the switch off lapses every live reference at once. |

### Changes to `research.ts`

- **List.** `GET /documents` gives each row its `room` (the room's name and uid, when it was added, and `lost_at` and `lost_reason`), `read_only: true` for a room row, and a `from_rooms` count.
- **Download.** A room row's download answers 409 `open_in_room` with the room's uid. The room's own download, with its log and NDA gate, stays the one path to the bytes.
- **Edit.** `PATCH` answers 409 `room_reference_read_only`.
- **Delete.** `DELETE` of a room row deletes the reference and the row, never the R2 object, and logs `library_remove`.

### Activity

`library_add` and `library_remove` join `ACTIVITY_ACTIONS`, worded "Added to their Library" and "Removed from their Library". The founder's Activity read, its filter and its CSV carry them (Q2). The week's figures stay opened, downloaded and blocked.
