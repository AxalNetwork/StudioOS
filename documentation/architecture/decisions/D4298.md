### 1. Where it lives

The registry key is `influencer` (P1), so the page is `/admin/programs/influencer` (D4289 §2), beside the other programs. It has seven static tabs:

- How it runs: part 1's playbook editor;
- Applications: where the bare address lands, because that is where work waits;
- Influencers;
- Offers;
- Payouts;
- Activity: part 1's activity read;
- Settings.

The catalogue card's door is the bare address. Every route takes `guard(['admin'], hqOnly(…))`, because the Worker's routes are HQ only (`requireHqAdmin`). The Applications tab carries the count of applications waiting on HQ (`counts.applied`), in amber when there is one.

### 2. The one new read: the Influencers table

P1 gave HQ applications, decisions, changes, flags and tier defaults, but no list of members. `GET /api/admin/influencers?status=active|paused|ended|all` (default `all`, `limit` up to 500, default 200) answers:

`{ influencers: [{ uid, user_uid, person: { name, role }, handle, tier, tier_label, status, signups, visits, paid_members, revenue, commission }], counts: { active, paused, ended } }`

- **Both uids.** `uid` is the membership's, which the change route takes. `user_uid` is the account's, which the offers, analytics and tax-form routes take.
- **Order.** Active first, then paused, then ended; within each, newest admitted first.
- **`signups`** counts `referrals` rows with this member as the referrer. It is a count, not money, so an admin reads it too.
- **`commission`** is the Super Admin's: one line per currency (`by_currency: [{ currency, earned_cents }]`), the sum of `amount_cents − reversed_amount_cents` over every commission row that is not `reversed`. It is never summed across currencies.
- **`visits`, `paid_members`, `revenue`** read `{ available: false, reason: 'not_recorded' }` until a store holds them per member. The Analytics read (P6) is per influencer, and calling it once per table row would be N reads.
- **No email**, for any viewer.
- Refusals: 400 `invalid_status`; anyone who is not HQ gets 403.

### 3. Money is the Super Admin's (O-MONEY A)

For anyone but the Super Admin, the Worker sends every money field as `{ available: false, reason: 'hq_reads' }`, and the page draws "HQ reads", never a zero. The Super Admin reads each currency on its own line. A recorded empty list reads "None yet". A figure nothing stores reads "Not recorded".

### 4. Every action asks for a reason

- **Row actions** (`PATCH /api/admin/influencers/:uid`): Change tier, Pause or Resume, End, and Take down handle (only while there is a handle). An ended member has no actions.
- **Flagged sign-ups** (`POST …/flags/:uid/decision`): Keep sends `clear`; Reverse sends `uphold`.
- **Offers** (`PATCH …/:userUid/offers/:offerUid`): Pause, Resume and End.
- **Linking an offer** (`POST …/:userUid/offers`).

Each of these needs a reason of at least 10 characters (`REASON_MIN`, the Worker's own floor) before anything is sent. The dialog says the member is told.

The application decisions follow P1's body. Admit names a tier from Affiliate Creator, Verified Influencer and Strategic Creator; Strategic Partner is agreed per contract. Decline and Ask for more carry the words the applicant reads, under the same 10-character floor.

### 5. Offers, Payouts and Settings

- **Offers.** The page lists every influencer's offers through P4's per-influencer read. A row whose read fails says so, and the other rows stay.
  - P4 links an existing Promos code (D-g), and Promos has no "owner preset" form. So "New offer" (Super Admin only) links a code by its `promo_…` id, with a budget, a currency and the featured flag, and points to Promo codes to make the code first.
  - An admin reads the offers but changes none, as P4's routes require.
- **Payouts.** Payouts are the existing Commissions queue (D-j); nothing is paid from this page. The tab opens Commissions on `?source=subscription_invoice` or `?source=influencer_bonus`. Commissions now reads `?source=`, accepting only `[a-z_]{1,64}` and otherwise falling back to All. No amount is typed on the tab.
- **Settings.** The tier defaults table shows rate, duration in paid invoices, and offer budget. A value the tier leaves to terms reads "Set per agreement"; an unset budget reads "Not set".
  - Only the Super Admin sees Edit, which sends P1's `PUT …/tier-defaults/:tier`. An empty field is `null`.
  - An admin reads the table, with "Only the Super Admin changes the tier defaults."
