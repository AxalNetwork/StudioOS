## D697 — Customer research, Problem discovery and Experiments and evidence carry everything the Interviews, Pain map and Hypotheses pages did, and an interview opens as Customer research's record

Issue #1659 (S12, moved from S02 on 2026-10-17). Part of #1654 (D689).

Validate's three bottom sections take over what `FounderValidateWorkspace` (FVW) drew on `/validate/interviews`, `/validate/pain-map` and `/validate/hypotheses`. An interview opens as Customer research's record at `/validate/customer-research/:id`. The issue holds S1's 21 decisions. This file records them as each part ships:

- **PR 1:** the sections, the parts mount and the census.
- **PR 2:** the record and the audio player.

Both wait on #1691 and #1692 (D690), the rest of #1658's PR 2 and #1703.

### The start-now part (`Part of #1659`)

S1 opened one part on 2026-10-17 that draws no read and needs none of those dependencies. It changes no page anyone sees today.

- **`PainSeverity` moved, not forked (decision 16).**
  - "How badly did they need it?" goes from `FounderValidateWorkspace.jsx` to `pages/founder/validatePieces.jsx`, with its docblock, byte for byte, now exported.
  - `validatePieces.jsx` imports `api` for it and names it in its own docblock. It is the one piece there that writes for itself (`api.setInterviewPainSeverity`).
  - FVW imports it from there and draws it where it did, until #1666 deletes FVW. The record's tools (step 8) will draw the same component.
- **`TranscriptReview`'s optional `time` prop (step 7).**
  - With `time`, each passage starts with its start as `[hh:mm:ss]`, from the `start_ms` the session transcript already carries.
  - A passage with no readable start draws no time, never `[00:00:00]`.
  - `/validate/session/:id` does not pass it, so that page is unchanged, and neither, until PR 2, is the review page.
- **Three pure rules in `interviewReviewModel.js` (step 10), for a Node test:**
  - `clock(ms)`: the `[hh:mm:ss]` above. Seconds are floored. Null for an absent, negative or unreadable start.
  - `findPassages(segments, text)`: the passages Search keeps. These are the passages `TranscriptReview` draws (the final segments when there are any), then those whose words hold the text, case aside. Blank text keeps them all, and it reads nothing.
  - `afterDelete(projectId)`: where the record lands after Delete, `/validate/customer-research?project_id=N`. An id that is not a positive whole number is left off the URL.
  - `recordParts(read)` is left out: it reads #1692's record, and comes with PR 2.

No client method, Worker route or migration. `CycleRoute.jsx`, `App.jsx`, `adapters/validate.js` and `InterviewReviewPage.jsx` are untouched, as S1's ruling sets.
