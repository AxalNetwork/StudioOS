## D7672 — Shared Network directory foundation and offline source import plan (#7672)

**Status:** implemented for review, 2026-11-19. Additive schema and offline planner only. No production migration, ingestion, API, UI, outreach or readiness gate has shipped through this change. #7673 owns requester readiness and the request lifecycle; #7674 owns authorized directory reads, private overlays and controlled publication. The later owner expansion to the complete NFX Signal library and Research mapping is #7681; this planner deliberately supports only the reviewed Airtable/Folk snapshot. The existing approved Network canvases remain the visual baseline.

### Why and existing records

The owner's November 19 direction requires external people, including people from the supplied Airtable and Folk directories, to be shared identities across Network Relationships, Introductions and Organizations. Directory presence does not prove that a member knows somebody, that they work at a company now, that they have joined Axal or that they consent to an introduction.

`network_connections`, founder/project `contacts`, and `partner_book_contacts` remain private or scoped books. `partner_relationships` remains the accepted account graph. `company_profiles` is the canonical company identity a directory organization may eventually link to; `user_company_links` grants workspace membership, `company_people` is the company's team/HR roster (migration 326), and `company_employment_history` records aggregate employee counts (migration 370). None is an external professional-affiliation import target. No existing table is backfilled here.

### Schema

Migration `202611191414_7672_network_directory.sql` adds:

| Table | Meaning |
| --- | --- |
| `network_directory_sources` | The two explicitly supplied source catalogs and their URLs. |
| `network_directory_import_runs` | Deterministic plan identity, version, input hash, reconciled disposition counts and completion after every planned record is recorded. |
| `network_directory_entries` | Stable source-backed person or organization identity, staged publication status, professional projection and nullable independently reviewed platform-user/company link. A checked kind prevents linking a person as a company. |
| `network_directory_source_records` | Immutable raw-content/decision hashes, source row identity, observation date, disposition and professional claims. The same source row may have several dated observations. |
| `network_directory_private_sources` | Original source fields and classification evidence, including emails. `operator_only` is the only allowed scope. There is no endpoint for this table in this change. |
| `network_directory_import_rows` | Run-to-record reconciliation, observation timestamp and replay checkpoints; repeated identical snapshots still retain each observation's date here. |
| `network_directory_affiliations` | Explicit source association of a person and organization, source observation, title when usable, unknown dates/currentness and unverified status. Composite foreign keys enforce the two entity kinds. |
| `network_directory_reviews` | Ambiguous source rows, source-channel duplicates and held affiliation decisions. No automatic resolution or merge. |
| `network_directory_book_links` | Empty, additive adapter for a later reviewed link from an owned book row to a directory person. The importer never writes it. |
| `network_directory_research_links` | Empty reviewed bridge from an organization/source snapshot to exactly one existing Research Company or Research Fund directory row, with unique target, reviewer, date and evidence. The importer never writes it. |

Professional projection fields are name, optional first/last name, validated profile/site URL, geography, source category labels, sector labels, stage labels, nullable currently-investing flag and previous-investment source text. `roles_json` remains empty until roles are explicitly established; Airtable Type belongs to `source_categories_json`. Unknown investing is NULL, distinct from a source's No. Free-form source labels are preserved, not reinterpreted as a controlled taxonomy. Raw emails, original URLs, rejected titles and other unclassified source cells stay in the operator table. No diligence files, private relationship notes or contact permissions are copied into the projection. Every entry starts `publication_status=staged`; verification and publication are separate. Check-size ranges, currency, mandate and geography taxonomies require later sourced fields under #7674, not fabricated defaults.

An entry is stable by source and source record ID, not by display name, email domain or name-derived platform lookup. Within Folk, a reviewed exact source organization key groups the source's people into that source's organization entry. This is not a global organization-name match. Two different source identities remain separate until explicit reconciliation. The optional verified user/company links are never supplied by this planner; a later linking service must verify identity and authorization. A link grants no workspace access.

Research uses `research_company_directory.uid` (migration 228) and `research_fund_directory.uid` (378 and later), not `company_profiles`. The empty bridge references those actual unique keys. `target_kind=company` is an organization profile, `fund_manager` is a manager record, and `managed_fund_vehicle` is an explicitly reviewed managed-vehicle association, not identity equivalence between firm and fund. The same Research row cannot belong to two directory organizations. Its source snapshot must identify the linked organization. This change adds no Research rows, updates no Research tables or APIs, and leaves the existing import owners #7316, #7325 and #7585 untouched.

### Source review and mapping

The planner requires a version 1 manifest with `rows` keyed by `{source, source_record_id}`, explicit entity kind and `accept|review|skip`; missing classifications are held. Source JSON cannot supply the reserved internal `derived_organization` or `decision` properties to bypass that manifest. Its optional `organizations` list has a reviewed exact source key, name, disposition and website. Only a person's `affiliation_disposition=accept_source_claim` and an accepted organization together create an association. `title_disposition=review` and an explicit reviewed `title:null` both mean NULL title, with no raw fallback. `linkedin_disposition=review|none` means NULL public identity URL. Source dates/current employment are never inferred.

| Source field | Mapping |
| --- | --- |
| Airtable Name, Type | Source-reviewed entity kind and display name; Type retained in source categories, separate from the person's roles. |
| Headquarters, Sector Focus | Geography and source sector labels. |
| Currently investing? | Exact Yes → 1, No → 0, everything else → NULL. |
| Previous Investments | Source text, not portfolio edges. |
| LinkedIn | Personal `/in/` URL only for a person; `/company/` only for an organization. An organization's founder URL does not identify that organization or create an affiliation. |
| Email, Twitter and other original cells | Original operator-only record; no invitation, email match or disclosure. |
| Folk Person, First name, Last name, Urls | Person and optional personal LinkedIn identity candidate. Urls is not assumed to be LinkedIn. |
| Folk Companies, Job title | Reviewed source association and optional usable title. Missing or ambiguous organizations/titles remain review items. |
| Folk Website | Only the reviewed organization candidate's valid site; a person's raw source website is not promoted automatically. |
| Folk Industry, Investment Stage | Source labels; no unstated investor role, employment claim or investment mandate is invented. |

Exact personal/profile identity collisions within an input set quarantine the conflicting records and create candidates. Reviewed email/LinkedIn channel collisions create additional review records without using the channel as a merge key. Malformed or mismatched channels stay in raw provenance. The planner does not search existing platform accounts or existing production directory rows; cross-run/global reconciliation remains a reviewed #7674 operation, with source-scoped IDs preventing silent cross-source merges.

### Planner and execution boundary

`scripts/lib/networkDirectoryPlan.mjs` is pure, deterministic planning. `scripts/plan-network-directory.mjs` reads local JSON and emits `{sql, params}` batches. It has no network, database credentials or apply option. Real records and generated plans must remain outside this public checkout; output is created exclusively with mode 0600 and no overwrite. Console output contains aggregate counts only. If the manifest contains file SHA-256 values, the CLI refuses input snapshots that differ from their review.

Example with paths supplied by the operator:

```sh
node scripts/plan-network-directory.mjs \
  --records /private-import/airtable_records.json \
  --records /private-import/folk_records.json \
  --manifest /private-import/reviewed_manifest.json \
  --out /private-import/directory-plan.json \
  --report /private-import/directory-summary.json
```

Every batch must execute atomically (D1 `batch()`), in order, stopping on any error. The preparing batch creates the run and source definitions; each source record's batch creates its entry, source snapshot, restricted raw record and checkpoint together; associations follow their organization entries. The final statement marks complete only when every planned source record checkpoint exists. A failed batch can be replayed safely. No generated batch is executed by this CLI.

UIDs and snapshot uniqueness make exact replay idempotent. A changed source snapshot is appended. A strictly newer unverified source observation can update that source's unlinked, staged professional projection; old replays cannot replace newer data (including within the same second), and reviewed, verified or withdrawn entries/affiliations are not overwritten or resurrected. Equal-time conflicting content or classification keeps the prior staged projection and adds a review record. Published/suppressed/archived or account/company-linked entry facts remain unchanged. Each run checkpoint preserves its source observation timestamp even when identical content reuses one immutable source snapshot. Duplicate inputs sort newest-first independently of file order. Derived organizations must be present in actual Companies cells; only their claimants determine their observation dates. An affiliation's composite provenance foreign key must name a source snapshot attached to that person.

Missing rows in a later input do not imply deletion or withdrawn employment. A changed kind conflicts at the composite foreign key rather than silently changing identity. A later held correction does not erase the older staged projection. #7674 publication must inspect the latest dispositions and open review evidence, and must never publish an older accepted projection merely because it still exists. This change exposes neither to members.

It created zero accounts, company profiles or book links and reported zero foreign-key violations. This is local replay evidence, not a production import or hosted D1 verification.

### Rollout, rollback and remaining work

The normal reviewed release workflow applies the additive migration before any ingestion. Do not execute schema SQL manually in production. After release, #7674 must provide the operator boundary, inspect the exact private plan/digest, perform approved controlled ingestion, reconcile counts and verify authorized directory visibility. This change has no published reader and therefore makes no member-facing data available by itself.

Rollback reverts application code; the additive tables can remain. Source withdrawal/suppression and reviewed merge/claim operations need future explicit services; deleting or relinking imported records is not an automatic rollback operation. A future reader must require `publication_status=published`, exclude withdrawn records, enforce member/operator field visibility and distinguish a source association from verified employment or a warm relationship.
