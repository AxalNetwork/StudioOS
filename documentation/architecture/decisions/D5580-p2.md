## D5580 part 2 — WorkIntent read from the claim, and soft proceed/coordinate/wait/serialize advice (#5580)

Part 2 of #5580. Part 1 is `D5580.md`. This part reads the claim that #5617 already
stores and does not add another one. It adds no issue tracker, no table and no
workflow permission, and it does not require a PR for every edit. Everything stays
**advisory**: nothing blocks, labels, reviews or merges. The pure rules are in
`scripts/lib/workIntent.mjs`. The reads are `readWork` in `scripts/pr-overlap.mjs`,
which run inside part 1's hourly job.

### What the claim stores, and where WorkIntent reads it

**#5617 claim ref (`refs/heads/claim/<issue>`, D5617).** The commit message is JSON:
`version`, `issue`, `slot`, `agent`, `session`, `at` and `ttlHours`. The first
claim's parent is `main` at claim time. Each renewal is a child of the claim it
renews. `walkClaim` follows these renewals back to the root claim and stops at the
first parent that is not a claim of the same issue. That parent is the intent's
**base SHA**, together with its commit date. The walk stops after seven renewals.

**The 403 fallback.** AGENTS.md lets a slot claim an issue with labels and a STATUS
comment instead. WorkIntent reads:

- STATUS blocks in comments by `OWNER`, `MEMBER` or `COLLABORATOR` authors;
- the slot labels of open issues labelled `state:in-progress`, `state:blocked` or
  `state:review`.

A holder whose latest STATUS says `DONE` holds nothing.

**#5618 lease.** The fenced lease is in Merge Control's Durable Object. It is
readable only with the owner token, and this job does not hold that token. Every
intent therefore carries `lease: { status: 'not read' }`. #5624's `path_owners` is
not on `main`, so it is not read either.

**Owner override.** No override store exists. Under D5617 the owner hands a claim
back by releasing the ref, so the claim simply disappears. D5618 has no override
field. `override` is always `null`. Recording an override with an audit trail is
left to a later part.

### Predicted paths: precedence

1. **The claim.** v1 records no paths, so this source is never used today.
2. **The linked open PRs' changed paths** (part 1's files read). These are measured,
   not predicted.
3. **The holder's latest STATUS `files:` line.** Only tokens that look like
   repository paths count. Globs, absolute paths and `..` are dropped.
4. **Not recorded.**

### Determinism

- **Duplicate registration.** Each issue yields one intent.
  - The claim ref is the authority. A STATUS block by its own holder (same slot and
    agent) only adds files and a PR.
  - A different holder's STATUS from before the ref is noted as history. One from
    after the ref is a duplicate and loses.
  - With no ref, the earliest registration wins. Ties break by source (ref, STATUS,
    label), then slot, then agent. Every losing registration is noted.
- **Stale SHA.** A base that is not an ancestor of `main`, or is more than 72 hours
  old, is `stale` and the reason is given. A base that cannot be checked is `null`,
  never fresh.
- **Disappeared PR.** If the STATUS names a PR that is no longer open, the link is
  dropped and noted. If the PR scan was partial, the note says the PR is not in the
  partial scan and does not claim it is gone. If an issue or claim commit returns
  404 or 410, it is noted and not read.
- **Invalid slot.** A slot that is not `SNN`, is `S00`, or is past S37 without a
  `slot:SNN` label in the repository is refused, and the note says why. Other valid
  registrations on the issue still compete. If the labels cannot be read, a later
  slot is accepted and noted as not verified. Invalid claim metadata is refused.
- **Concurrent lease expiry.** Intents are ordered by `expiresAt` first and then by
  issue number. An intent with no recorded expiry comes last. An expired claim is
  kept and noted as still held (D5617).

### Recommendation

`recommend()` compares each intent with every other intent and with every open PR
that no intent owns. The highest action wins, and each reason names the
counterparty, the rule and the path.

| Action | When |
|---|---|
| `serialize` | A critical path: part 1's `CRITICAL`, or an altering migration. Or an exclusive resource: a shared migration file or a shared new migration stamp, a schema path (`cloudflare-worker/sql/`), a contract path (`cloudflare-worker/src/contracts/`), or a release pointer (`CHANGELOG.md`, `frontend/src/lib/release.js`, `scripts/release-*.mjs`). |
| `wait` | Overlapping hunks, a shared dependency path (hub, manifest, API, baseline, generated), or an open dependency issue. |
| `coordinate` | The same path with disjoint or unknown hunks. A shared predicted path whose hunks are unknown. The same module (directory), except the folders where each file is its own module (`FLAT_FOLDERS`: `scripts/lib`, Worker routes and services, frontend routes and pages, workflows, and so on), Markdown, tests and SQL. A dependency whose state was not read. |
| `proceed` | None of the above. |

When both sides have fresh PRs, part 1's measured hunk class decides. When either
side is only a prediction, the path rules above decide.

### Wiring

- The #5600 summary gains a `### Work in flight` section: one line per intent, then
  `Refused:` and `Notes:`. Every claim, comment, label, agent and path string passes
  through D5616's `escape()`. If the claim refs cannot be read, the section says
  `Unreadable`, never "no work".
- The snapshot schema becomes `studioos-pr-overlap-snapshot/v2`. It is v1 plus
  `workInFlight` (`status`, `partial`, `intents`, `refused`, `notes`). Every v1
  field keeps its name and meaning.
- `readWork` has its own budget of 150 requests:
  - one claim-ref listing;
  - three label queries;
  - up to three label pages;
  - per issue: the claim chain, the issue, and up to three comment pages;
  - up to 20 dependency issues.

  The total request cap rises from 600 to 750, so the PR comments keep their share.
  At most 40 claimed issues are read, and reaching a cap marks the section partial.
- No workflow change. `contents: read` and `issues: write` already cover these reads.
