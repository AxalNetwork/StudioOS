The receipt source/parent/plan/control/child/shard/generation identity is compared
against a fresh authenticated canonical receipt, not echoed from caller JSON.
JWTs and job tokens stay in private acquisition closures and are neither persisted
nor returned. The Actions client permits only two fixed-origin GET resource forms,
up to three pages/300 jobs, at most 512 KiB per response, and no redirects.
Each reader observes caller cancellation, the receipt deadline and a ten-second
whole-reader bound even if a port ignores cancellation. The outer D8007 bound
remains ten seconds across verification. Timers do not prove native physical
completion; no timeout/resource limit is raised.

Boundary denial fields are emitted only after actual engine-state checks against
the trusted job's owned receipt/source/plan/image, isolated namespaces, fixed
mounts/environment and restrictive container configuration. No input denial flag
is accepted. The root-owned policy and actual node/image/engine security baseline
must be qualified separately; dependency injection and synthetic engine state do
not prove that baseline. No engine create/start/remove operation is added here.

The included response extension above is a **proposed consumer contract**, not a
claim that the server already emits verified provider facts. S39 retains its
producer/transport composition. No provider or billing credential enters a job.
The first pilot keeps included capacity zero and Macs excluded.
