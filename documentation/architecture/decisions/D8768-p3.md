## D8768 part 3 — The skill picker's keyboard, its failure states and the skill page's agents (#8768)

- **Status:** built by S09, 2026-11-27. Part 3 of #8768 (part 1 `D8768.md` is the canvas, part 2 `D8768-p2.md` the one eligibility rule). This part is frontend only and builds what part 2 left of the canvas's visual pass: TMS15's listbox keyboard model, TMS09's states in the pickers, the 390 px targets of TMS10–TMS14, and TMS02's per-agent states on the skill page. No Worker route, schema or contract changes. The owner accepted option A for every open question (comment of 27 Nov); Q1 stays as part 2 built it.
- **Keyboard (TMS15).** `SkillSheets.jsx`'s `SkillPicker` draws its rows as a multi-select `listbox` with one tab stop. `/` focuses search; ↓ from search enters the list; ↑ ↓ Home End move and stop at the ends (`listboxMove`); Space ticks an eligible row and, on any other row, leaves it unticked and says its state and reason (`spaceOnRow`); Enter opens details in place, and Esc there comes back to the same row with the picks kept; Esc in search clears the words first and only an empty search lets the Sheet close. A polite live line counts the rows shown after each search or area change (`pickerLiveLine`: "1 can attach, 1 blocked in Finance."). Each row's accessible name carries its state word and "natural fit".
- **States (TMS09).** Loading shows the counts line as "—", never 0 (`COUNTS_LOADING`). A read that fails says "… couldn't be read. Nothing below is a guess, and this isn't “No skills”", says the picks are kept and offers Try again (`PickerReadState`), in the Add skills drawer, the wizard's Skills step and Assign to agents. Offline (`useOnline`) says when the list was read and that the picks are kept, and turns Add off (`offlineWords`). A refusal at save after a race (`raceRefusal`: suspended, retired, a tool or capability gone, unpublished) names the skill, says nothing changed, unticks only that skill, keeps the other picks and reads the list again; the adapter now keeps the Worker's `skill_uid` on such a refusal. A pick that a re-read finds no longer eligible is not sent.
- **Phone (TMS10–TMS14).** Below 640 px the search field, area chips, rows, Back and the way-on button are 44 px targets; the Sheet already becomes a full-screen page with its footer as the bottom action bar.
- **Skill page (TMS02).** `SkillsTab.jsx`'s `YourAgents` lists, for someone who can assign a published skill, every agent they manage with the one rule's state (Attached, Can attach, Blocked by policy with its reason and recovery), natural fit first, under the line "Your 3 agents · 1 attached · 1 can attach · 1 blocked" (`yourAgentsLine`). It reads `GET /skills/:uid/assignable`, the read Assign to agents already uses. A failed read shows no agent as Can attach and offers Try again (TMS09 "eligibility unavailable").
- **Departures from the canvas.** TMS09's race board reads "Weekly KPI digest was added to Vesta": `PUT /agents/:uid/skills` saves the list as one write, so a refusal changes nothing, and the screen says that instead and leaves the rest ready for one more Add. The Read-only member board is unchanged from part 2 (no Add, no Assign; the existing read-only line).
- **Not built.** The "Your 3 agents" line on every directory card: it needs a gate check per skill per managed agent on each library read, which `attachCheck`'s per-call reads (version, suspension, capability) would multiply past a sane D1 budget; it waits on a batched eligibility read in the Worker. Run cost per skill stays #4536's ("Not recorded"). Discovery's and workflows' own role gate stay their owners' (part 2).
- **Tests.** `frontend/test/skill_picker_keyboard_8768.test.mjs`: the keyboard model, the live line, the TMS09 words, the adapter's `skill_uid`, the mounted listbox (one tab stop, arrows, Space on a blocked and an eligible row, Enter and Esc, search Esc, area), the 44 px classes, the Add skills drawer's failure, retry and race, offline, and the skill page's Your agents with a failed then a good read.
