## D7723 — Competitor prices are stored on stated terms, with capture date, source and history (#7723)

- **Status:** built 2026-11-19 from the owner's Research → Markets audit of the same date, under #3701. Owner question built as **A**.
- **Builds on:** `services/webFetch.ts` (`extractPricingHints`), `services/competitorDirectoryLink.ts`, `routes/_founder_validate_helpers.ts` (`canReadBoard`, `canWrite`) and the `market_figures` append-only trigger (D6011). The analysis engine (`services/competitorAnalysis.ts`, `routes/competitors.ts`, `routes/_competitor_writes.ts`, `services/competitorSchema.ts`, `services/webFetch.ts`) is read and imported only, never edited; this change fetches no page.

### The store

`competitor_price_observations` (migration `202611191832_7723_competitor_price_observations.sql`), **append-only**:

- The competitor's name and domain are copied as text, with the directory company uid when `competitorDirectoryLink` finds exactly one, and a grouping key (the site's host, else the name). `analysis_id` and `candidate_id` are plain values with **no foreign key**, so a rerun that drops the candidate, or deleting the analysis, leaves the row and the competitor's name.
- Stated terms, each a closed set checked by the table and the service: product; plan; charge type (`subscription`, `usage`, `implementation_fee`, `quote`); the amount as **decimal text, never a float** (a usage price can be below one minor unit: `'0.0004'` reads back as `'0.0004'`); `'0'` is a stated free price, and no amount is allowed only for a quote with no public figure; an ISO 4217 currency (`services/currencies.ts`); pricing unit (`per_seat`, `per_account`, `per_use`, `flat`) with a unit quantity and label required for usage and refused otherwise; billing period (`monthly`, `quarterly`, `annual`, `one_time`, `per_use`, and `not_stated` for a quote only); contract term (`no_commitment`, `monthly`, `annual`, `multi_year`, `not_stated`); region (`global`, `north_america`, `latin_america`, `europe`, `united_kingdom`, `middle_east_africa`, `asia_pacific`); captured on (a real date, not in the future); source kind (`official_page`, `filing`, `permitted_quotation`, `interview`) and an http or https source link, required for a page and a filing.
- The source-use confirmation (`source_use_confirmed`, always 1) and, for a quotation, leave to share it (`source_share_confirmed`), recorded with who (`entered_by`) and when (`entered_at`).
- `hint_text` is the hint verbatim when the row was confirmed from one. A hint is never a row.
- `corrects_uid` names the row a correction replaces; a unique index allows one correction per row.
- An interview-sourced row needs a venture and links that venture's `discovery_interviews` row by id. A row holds no person's name, contact detail or quoted speech; an interview source takes no link.

The trigger `competitor_price_observations_append_only` refuses any UPDATE that changes a recorded field. The references may go NULL when the user or interview they point at is deleted. The one other change is a **withdrawal**: `withdrawn_at`, `withdrawn_by` and `withdrawn_reason` set once, from nothing, in the same UPDATE that clears `amount` and `source_url`. There is no delete trigger, and no route deletes or edits a row.

**Deletes.** A venture's hard delete removes its rows (cascade on `project_id`, as `market_figures`). An account deletion (`DELETE FROM users`) sets `entered_by` and `withdrawn_by` to NULL and leaves every row: a venture's row is still read within the venture; an unattached row is read only by its author, so once the author is gone nobody reads it. A deleted interview sets `interview_id` to NULL.

### The routes (`routes/competitor_prices.ts`, `services/competitorPrices.ts`)

| Method and path | What it does |
| --- | --- |
| `GET /api/competitor-prices/proposals?analysis=<id>` | The hints the analysis's own candidates hold, per candidate, with the pages that answered for that candidate to choose a source from. Only the member who ran the analysis (404 `analysis_not_found` for anyone else). Read from `competitor_candidates` and `competitor_sources`, never from `competitor_cached_fetches`, which is shared across members. Each hint is `{ hint_text }`: nothing is parsed into an amount, unit or term, nothing is prefilled, nothing is written (`saved: false`). |
| `POST /api/competitor-prices` | Save one price, from a hint or by hand. Refused 400 `terms_missing` (with `missing`) unless every term above is stated, 400 `invalid_term` (with `field`) for a value outside its set, 400 `source_use_unconfirmed` without an explicit `source_use_confirmed: true`, 400 `quotation_share_unconfirmed` for a quotation without `source_share_confirmed: true`. From an analysis: the analysis must be the caller's, the candidate in it, a hint one it found (400 `hint_not_in_analysis`); the name and domain are the candidate's, and the venture is the analysis row's (400 `project_mismatch` if the body names another). A hand-added price may name a venture only when the caller passes `canWrite`. `corrects` names the row a correction replaces, in the same venture (or the caller's own unattached rows); a second correction of one row is 409 `already_corrected`. |
| `POST /api/competitor-prices/:uid/withdraw` | `{ reason }` required. `canWrite` on the venture, or the author of an unattached row; 409 `already_withdrawn` the second time. |
| `GET /api/competitor-prices?competitor=&project=` | The current prices for one competitor (matched by host or name). Current: for each product, plan, charge type and region, the latest capture that no correction replaced and that is not withdrawn. |
| `GET /api/competitor-prices/series?competitor=&product=&plan=&project=` | Every row of one plan, oldest capture first, with `current`, `replaced_by`, `corrects` and `withdrawn`. A withdrawn row reads `amount: null`, `source_url: null` and `withdrawn: { at, by, reason }`. |

Writes are refused in a support session (403 `support_session`). The client is `competitorPricesApi` in `frontend/src/lib/api/competitorPrices.js`.

### The owner question, as built

**Who reads a price observation attached to a venture?** Built as **A**: whoever passes `canReadBoard` for that venture (the gate that already shows its competitor names on the Validate card) reads it; writing and withdrawing need `canWrite`; an unattached price (no `project`) is read and withdrawn only by its author. A stranger and an investor are refused 403; another venture's prices for the same competitor are never returned because every read is scoped to one venture or to the caller's own unattached rows. Option B (only ever the member who entered it) was not built. Neither option changes who reads a competitor analysis: the hint list stays the analysis owner's alone.
