## D6430 — Deal activity respects each evidence source's read rule (#6430)

The mounted deal Activity read adds three independently bounded document
sources. Data-room files and version events use active, unexpired grants,
folder/subfolder scope, tier/commitment and NDA gates; owner/co-founder access
uses the room's existing tenancy rule. A plain admin read opens no file.
Deck-share events require the investor's exact active firm grant and current
deal relationship; the venture owner and admin may read the share history.
An invitation for one firm never makes another firm's deck grant readable.

NDA events use the canonical signed recipient timestamp linked through the
venture founder's pairwise NDA. A reader sees their own signature. The
venture owner/admin sees anonymous investor signature events, never another
investor's name, email or signature details. A pending NDA without a recorded
signature creates no event. Each source is newest-50 bounded after access
filtering, and a failed source contributes one Unreadable row while the feed
continues. Support sessions are refused. The document empty-chip copy names
the separate NDA/grant rules.

The existing room helpers retain their default fail-closed behavior. Activity
opts into throwing on a failed folder/commitment read so Unreadable cannot be
mistaken for no visible events. Tests mount the router on the complete
migrated SQLite schema, including the older D1152/D6193 regressions.
