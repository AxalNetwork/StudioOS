## D4835 — Offers catalogue pages and concurrency (#4835)

The service catalogue filters before pagination and sorts by creation date and ID. The response includes the matching total and marks request measures as page-only. The default page keeps the existing response size.

Perk performance is scoped to the selected listing. A different selection mounts fresh state, and only the latest read for that listing can update it.

A programme edit writes only submitted fields. Date edits also compare the date pair used for validation, so concurrent changes cannot create an invalid interval. The application insert checks programme status, time window, capacity, the validated programme configuration, and the active tester record in the same write as admission. A rejected insert adds no application event.

The catalogue, attribution, perk listings, claims, and credit history expose stable pages with a unique ID tie-breaker. Catalogue pages return a matching total. Other pages use a lookahead row to report whether another page exists. My Perks claim metrics and credit balance cover the full account, and older ledger pages start from the balance at their first row.

Surface and proof item deletes batch their dependent rows and the parent in one D1 transaction.

After D4672, the proof list pages by creation time and ID. Each page loads consent history only for its displayed items, including earlier revisions so their labels remain available. The published and self-stated totals cover the firm’s whole proof collection and count each item once using its current claim hash and unwithdrawn confirmations. The Proof page labels its other metrics and filters as page-only.
