### 3. The seam (`frontend/src/pages/raise/pitch/deckV2Adapter.js`)

Every v2 surface whose route is not on main reads this file and nowhere else. Each of its 46 methods answers `{ available: false, reason: "Not switched on yet.", issue }`, where `issue` is the GitHub issue whose route ends the wait (#3749 to #3882; the table is the plan's §6.2 and `SURFACES` in the file). The answers are frozen, the file has no network code, and `shown()` prints "Coming later" for an unavailable answer without ever calling the formatter, so no surface can draw a zero, "$0.00" or "none" in its place. When a route merges, its PR adds the client method under `frontend/src/lib/api/` and swaps one body for `through(() => …)`.

`deckV2Model.js` holds what every v2 surface shares: "Coming later", "(pending owner)", the hold line, the Grid's area labels ("c5–8 × r4–6"), the element picker's 8 groups with each item routed to a route on main, a free placement or an adapter method, the one set of proposal verbs, and Ask's names.

**One client method** is added by the whole integration, in its one-click step: `deckImagesApi.plan`, for `GET /api/decks/:id/images/plan`, which is on main (`deck_images.ts`). Batch 1 adds none.

### 4. Ask (`DeckAsk.jsx`, `frontend/src/ui/AskButton.jsx`)

- **The button** is Team's `AskButtonView`, lifted to `frontend/src/ui/AskButton.jsx`; `pages/team/AskButton.jsx` re-exports it. It draws "Ask" and is named "Ask Eadwyn", with ", N waiting" and an amber pill when a read counted N > 0. A read that failed draws no count, never "0 waiting", and the sub-line "Eadwyn could not be reached. Try again." Running, AI off and out of tokens have their own states (pd40), each with one text colour (never two stacked). The header's Ask never draws out of tokens: it runs no model, so nothing it does can be refused for tokens; the amber dot belongs to the selection's Ask, whose run's refusal says it (plan §4.3, a later step).
- **Where:** the header of the studio, New deck and the editor (`PitchPage.jsx`), on every width. It replaces D698's phone-only `EadwynButton` there; with that button gone the rail keeps its own floating button on a phone. A reader (read-only HQ) gets no Ask. The editor's typed field, until the instruction box replaces it, is named "Tell Eadwyn what to change in this block", so exactly one control is named "Ask Eadwyn".
- **"Waiting for you"** lists the whole-deck proposal (`GET /api/decks/by-project/:pid` → `proposal`) with Review (New deck's proposal review) and Discard (`DELETE /api/decks/proposals/:id`); and the card edits a card run left (`GET /api/ai/rail/proposals` for each deck option, `record=deck:<id>`), read again each time the sheet opens and after the editor's own bar runs or decides one. The sheet has no whole-deck Accept all: keeping every card (`keep-slides` with `all`) would save placeholder cards ("Not recorded on StudioOS yet: …") and skip the brand theme, which plan §3.4's cut decides in the review (`oneClickModel.js`, build step 13), so Review is the one way to accept a deck. In the editor, Accept checks that the edit still fits its card, places it at once, held until Save like every edit, then records the decision (`POST /api/ai/rail/proposals/:uid/decide`); a refused decision takes the placement back, and a placement that no longer fits records nothing and says why. A text edit lands only on the block whose text is still the proposal's "before". A decision in the sheet re-reads the editor's versions without blanking them, so the open editor keeps its unsaved changes. Elsewhere a card edit offers "Open in the editor ›". Ask runs no model, so it keeps working with AI paused.
- **Not listed:** generated images that were not kept. Main reads only kept images (`GET /api/decks/:id/images`).
- When #3706's platform Ask panel lands, this sheet becomes the deck's section in it (owner question F).
