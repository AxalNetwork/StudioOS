### 1. The new lanes

Each lane is a literal count query and a literal rows query on its own store, with its waiting state in that store's own words. Ages are `datetime()` and `julianday()`, so a stored ISO time and a SQLite time sort together.

| Lane | Store | Counts | Age from |
|---|---|---|---|
| `kyb` | `company_kyb_records` (220) | `status IN ('pending', 'in_review')` | `submitted_at`, else `created_at` |
| `comarketing` | `comarketing_pitches` | `status = 'proposed'` | `created_at` |
| `wellbeing_experts` | `experts` | active, unverified, not hidden, `profile_completion_pct >= 70`, `uid` not `seed_…` | `created_at` |
| `perk_listings` | `perks` (186) | `status = 'in_review'` only | `updated_at`, else `created_at` |
| `strategic_access` | `referral_strategic_access` (175) | `status = 'requested'` | `created_at` |
| `lab_hosts` | `lab_host_applications` (313) | `status = 'pending'` | `created_at` |
| `score_flags` | `score_snapshots` | `admin_review_status = 'flagged'`, not sandbox | `created_at` |
| `articles` | `articles` | `status IN ('submitted', 'in_review')` | `submitted_at`, else `created_at` |

- **The KYC split.** `kyc` stays people only (`users.kyc_status`); `kyb` is the businesses. `company_kyb_records` has no CHECK. Its comment gives `users.kyc_status`'s words, and its one writer stores `in_review`, so both waiting words are counted.
- **`product_testers` is not a lane.** No tester application is stored until part 4 (#2890, migration 576). A lane over a table that does not exist would read null on every studio, and so would every branch's backlog total. It is `NOT_COUNTED_YET`, with its reason, on HQ's approvals.
- **Wellbeing "not declined"** waits for part 5 (#2891, migration 577), which adds the `declined` state. Until then nothing can be declined, so the predicate has nothing to exclude.

### 2. Sub-counts

- **`comarketing`** carries `sub: { label: 'approved, not published yet', count }`, from `status = 'approved' AND published_at IS NULL`. The sub-count is read on its own: if it fails it reads `count: null` and its lane still answers.
- **`partner_profiles` already drops Drafts.** #2380's Worker change landed as D990 (`IS_WAITING_SQL`), so nothing changes here.
- **`due_diligence`'s "ready for sign-off"** is not invented. No case records being ready for sign-off yet, and #2385 defines it. It is `SUB_COUNTS_NOT_YET`, with its reason.

### 3. Notifies and Decided on

Every lane carries `notifies` and `decided_on` (APR2's two columns), and the glance and the branch digest pass them through:

- **`notifies`** says what the decision tells today: "The member", "The partner", "The host", "The author", "The studio" or "Nobody yet". It is read from what each decide route actually sends, not from what the canvas hopes. Co-marketing, wellbeing and strategic access say "Nobody yet" until part 5.
- **`decided_on`** names the page that decides. KYB's is `null`, with `undecided_reason`: no admin route decides a business verification yet.

### 4. HQ decides (APR9)

HQ's eight queues live in `services/hqApprovalSources.ts`, **not** in `APPROVAL_SOURCES`. A branch's board, its backlog total and its assignments read `APPROVAL_SOURCES`. These queues are decided only on HQ by `requireSuperAdmin` routes, so a branch has none to count and a plain Admin has none to decide.

| Lane | Store and open predicate | Notifies | Decided on |
|---|---|---|---|
| `testing_programs` | `testing_programmes`, `status = 'submitted' AND owner_kind = 'partner'` | The partner | Platform › Product testing |
| `learning` | `learning_exercise_submissions`, `status = 'submitted'` | Nobody yet | Learning studio |
| `tickets` | a feature ticket with no `feature_request_reviews` row, plus a `pending` community task whose ticket is still a task | The member | HQ review |
| `payouts` | `payouts`, `status IN ('requested', 'processing')` | Nobody yet | Commissions |
| `ai_runs` | `ai_budget_reservations`, `status = 'review'` | Nobody yet | Platform › AI allowances |
| `notices` | `admin_notices`, `status = 'responded'` | The studio | Licences |
| `support` | `hq_escalations`, `status = 'open'` | The studio | Support |
| `proposals` | `program_proposals`, `status = 'sent'` | Nobody yet | Programs › Proposals |

- **Program-grant requests** are `HQ_NOT_COUNTED_YET`. No request is stored until part 2 of Program grants (#2774).
- **The glance.** `GET /api/admin/studio-glance` on HQ adds `approvals.hq_decides` only when `isSuperAdmin` holds: `{ lanes, pending_total, unreadable, not_counted }`. A plain Admin's glance has no `hq_decides` key. The total is null when any HQ lane fails, and it is kept apart from `approvals.pending_total`, which stays the lanes every studio has.
- **Part 2's inbox read** (#2888, D1040) reads `HQ_APPROVAL_SOURCES` for a Super Admin when it lands. This part gives it the sources and does not add the route.

### 5. One failed lane

`countLanes` (generic over both lists) reads each lane in its own `try`. A failed lane is `count: null, oldest_at: null`, with its meta and, on HQ, `reason`. It never reads 0, and it never blanks the other lanes. A failed sub-count is that sub-count's `null` only.

### 6. The branch board

The eight new lanes reach every studio's board, digest and backlog total:

- **Consoles.** `LANE_CONSOLE` gives each lane its console. KYB's is `null`, so the row says "This lane has no registered console" rather than linking to KYC's.
- **Assignment.** The new lanes are assignable, because `isAssignmentLane` reads `APPROVAL_SOURCES` and migration 341 has no lane CHECK.
- **The freeze row (D260).** It now names the gated lanes: perk listings (`perks.ts`), Spin-Out Lab hosts (`lab_hosts.ts`), wellbeing experts (`wellbeing.ts`) and strategic access (`refer_earn.ts`). It also names the ungated ones: co-marketing pitches, articles and score flags. KYB has no decide route. Part 1 (#2887, D1039) moves co-marketing behind `requireAdmin` and changes that row when it lands.
