### The decision

1. **Home is the module's own page** (`NarrativeOwnedHome.jsx`), given to CycleRoute through D6049's `homes` as Fundraising readiness is: its body replaces the generic "at a glance" card and the Versions records table, its line is the header's (`LINE`), and it names the header's action. It draws, in order: RA-17's state line, D909's tiles, Needs you and Objections heard (`NarrativeHome`, unchanged), and RA-17's Versions table. The module's sources (From Mercury, PostHog, Evidence) follow as before.
2. **Every state is #5129's** (`narrativeHomeModel.js` `homeView`): Loading (the module read has not answered: a skeleton), Not recorded (the read carried no narrative part), Unavailable with Retry (the part is `unreadable`; never drawn as first use), None as first use, and the page. A refusal is the module page's own sentence, before Home.
3. **First use is one card** ("Start your investor narrative") with New version as the page's one primary and Write your positioning; the header has no action then (D5076). A reader reads "No narrative version is saved for this venture yet." and is given no action. The founder's "Who read this narrative" (D1463, RR07) stays on Home in every state.
4. **The header's action is Save version** (`saveVersionAction`), from the part's capability map only: none while loading, failed or on first use; for a writer (`edit`), a link to Home with `?save=version`, which opens the dialog; for anyone else, Save version drawn disabled, with "Save version is for the venture's writers. You can read this narrative, not change it." on the page. On a phone the bar carries no action, so Home draws it full width (D5081 part 1).
5. **Save version uses the store the narrative already has**: `POST /api/cycles/raise/narrative-versions` with `start_from: version`, the newest version and the audience chosen (`saveNarrativeVersion`). It creates the next version as a copy of the newest as it stands, with its sections, bound figures and positioning, and runs the check on it. The dialog says so: "Saves v5 for Seed fund, a copy of v4 as it stands now, and checks it against your records. Nothing in v4 changes." A version's name is its number and its audience, as the store names it; no free-text name is stored, so none is asked for.
6. **One save per press.** The dialog is a reducer (`saveReducer`): a press while saving is the same state, and the write goes through `singleFlight`, so two presses in one frame still make one request. A refusal (any 4xx) keeps the dialog open with the audience chosen and the Worker's sentence (`userFacingRaiseError`); a failed request keeps it with "The version was not saved. Your choices are kept; try again."; a save closes the dialog and re-reads Home once.
7. **Phone (390):** no table wider than the screen: Versions is one stacked row per version, set-up actions stack full width, every target is at least 44px. Raise v2 draws no narrative phone board (RA-26 has Evidence, Cap table, Use of funds and Pipeline), so this layout follows RA-26's.

### What the boards draw that no read backs (reconciled against main)

Not built, and nothing is made up in their place:

- **"v5 working" and "Working · unsaved since 14:10"** (RA-17's title and first chip). The store has saved versions and each version's revision (D5069); a working copy apart from a saved version, and when it was last left unsaved, are not recorded. Story keeps its unsaved words in the page only.
- **"Pitch v6 out of sync"**. Nothing records whether a deck's cards match a version's words. Home says which deck reads the narrative, from the part's `deck`.
- **"3 evidence issues"** is drawn as the sections with a Mismatch in the claim tally (`claims.mismatch_sections`, D6068), not a count of evidence issues, which no read carries.
- **Used by "Investor update · Data-room summary"**. Only a deck's cards are recorded as reading a version (`read_by`); other uses are not, so the column shows the deck or None.
- **Consistency for older versions**. The part carries the check for the newest version only, so older rows read Not recorded with that reason, never Ready or Superseded.
- **Check consistency and Open Pitch beside the action**. The `homes` entry names one action, and CycleHeader's other slot (`more`) is drawn by CycleRoute; the Check tab and the deck are one click away in the tool's tabs and Home's footer.
- **RA-17's two tabs (Story, Versions) and Story drawn on Home**. The tool keeps its six tabs (D906, D912), each with its own read; Story stays its own tab.
- **The disabled action's reason on the button.** CycleHeader draws `disabled` with no title or description slot (`CycleOverview.jsx`, edited by open PRs), so the reason is a line on Home under the header.
