## D8512 — A read-only reconciliation of the Stripe webhook (#8512)

Production's `stripe_webhook_events` holds no row. That fits "no event was
expected", but it also fits a wrong destination URL, a signing secret from
the other mode, or a disabled event list. Nothing in the repository could
tell them apart.

**Decision.** `services/stripeReconciliation.ts` compares Stripe's events of
the subscribed types over 72 hours with the receipts the webhook recorded. It
answers one of five states:

- `no_events_expected`;
- `reconciled`;
- `delivery_failed_or_absent`;
- `accepted_state_missing`;
- `unreadable`.

It is served to the Super Admin at `GET /api/admin/stripe/reconciliation`.

- **Read only, no new access.** One `GET /v1/events` through `stripeCall`
  with the key the Worker holds, and three D1 reads. Nothing is written,
  and no event is sent.
- **No identifiers out.** The answer is the state, the window and counts.
  Event ids stay inside the module.
- **"State missing" means the receipt never finished.** The webhook sets
  `handled_at` only after every handler and the ledger write succeeded
  (D1434, D5299). An unfinished receipt of the current mode, past a
  15-minute grace and not being worked on, is the sign. A receipt of the
  other mode is ignored by the webhook and is not counted.
- **Missing delivery outranks missing state.** An unreadable side is
  `unreadable`, never a clean state.
- **The smoke warns only.** `post-deploy-smoke.yml` gets a warning step,
  `scripts/check-stripe-reconciliation.mjs`, that always exits 0. The smoke
  holds no secret, so its line reads "not read" until the owner decides
  whether it gets a read credential. Failing a release on the state waits
  for the owner to call it known-good.

**Not decided here.** Steps 1 and 2 of #8512 (the Workbench read and the one
signed test delivery) remain the owner's.
