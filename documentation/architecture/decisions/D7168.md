## D7168 — Research › My funds and dossier: a shortlist past 500, identity by uid, and a dossier that keeps unsaved work (#7168)

- **Status:** built 2026-11-18 to the canvas D7033 records (`design/incoming/Research Funds My Funds and Dossier Page.dc.html`, boards FND-S00 to FND-S09). Part of #3701.
- **Builds on:** D7033 (the canvas and its ◇ items), D4613 (`catalogue_uid` and its unique index per owner), D312 and D593 (the dossier and its brief), D4607 (the record gate), D4961 (the leave guard), D597 (a withdrawn list answers 410).
- **Migration:** `202611180053_7168_research_fund_identity_allocation.sql` adds `research_funds.own_record_at` and `research_funds.intended_allocation_cents`, and an index on `(owner_user_id, updated_at DESC)`. Nothing is backfilled.

### What was decided

1. **`GET /api/research/funds` pages and searches on the Worker.** It takes `q`, `limit` (1 to 100, default 50), `offset`, `sort` (`updated`, the default, `saved` or `name`), `filter` (`right`, `warm`, `passed`), `identity` (`linked`, `own`, `legacy`) and `catalogue_uid`. A bad value is a 400 that names its field. It answers `total` for the search and filters, and every count (`saved_count`, `right_stage_count`, `warm_path_count`, `passed_count`, `passed_without_reason`, `linked_count`, `own_count`, `legacy_count`, `cheque_overlap_count`, `allocation_count`, `allocation_set_count`) over all saved rows, with `counts_scope: 'all_saved'`. Before, it read the newest 500 by `created_at` and counted only those. The query lives in `services/researchMyFunds.ts`: each statement is one literal, and a filter that is not set is switched off by a bound `''`. Search matches the saved name and the catalogue id. Matching the manager and the vehicle waits for the importer's columns (#7166).
2. **Identity is a column, never a name.** A row is `linked` (it has a `catalogue_uid`), `own` (it has `own_record_at`, set when the member typed it in by hand after this migration or chose "Keep as my own record"), or `legacy` (neither, so it was saved before catalogue links). The DTO carries `identity`. `PATCH` with `catalogue_uid` links a row that has none. It answers 409 `catalogue_uid_taken` with `holder` when another of the member's rows holds that vehicle, 409 `fund_already_linked` on a linked row, 404 `catalogue_vehicle_not_found`, 410 `catalogue_vehicle_withdrawn`, and 503 when the catalogue cannot be read. `PATCH { own_record: true }` keeps a row as the member's own, so it is not offered a match again (D7033 Q2, drawn as A). Nothing links automatically, even on one exact name match (Q1, drawn as A). `catalogue_links` on the list maps every linked row by catalogue uid, so the Directory's "Open your dossier" and "on My funds", and the catalogue page, open an entry by id. "Atlas A-I" and "Atlas AI" used to open the same dossier.
3. **Conflict detection.** `PATCH` takes `expected_updated_at`. A row stamped differently answers 409 `fund_changed` with the stored row on `item`. The write is `UPDATE … WHERE updated_at = ?`, so a write that lands between the read and the update is a conflict too, and every write moves the stamp by at least one millisecond. A `PATCH` with no stamp writes as before.
4. **The intended allocation.** `intended_allocation_cents` is USD cents, and blank stays blank (null, never 0). A negative or non-number value is 400 `allocation_invalid`. The list counts the funds whose cheque range includes the allocation (`allocation_count`), with a missing low end read as 0 and a missing high end left open, as the whole-round count always has. It also counts how many funds have an allocation set. Both sides are USD, so they compare, and the comparison never involves a figure in another currency. The dossier carries `allocation_test` (`services/researchFundRead.ts` `fundAllocationNote`): not set, nothing to compare, inside, below or above, with inclusive ends.
5. **The dossier's public record is separate.** `GET /api/research/funds/:uid` adds `public_record`. It is the linked catalogue row (`state: 'ok'`), `not_linked`, `not_found`, `withdrawn` (the directory's 410, with none of its fields), or `unavailable` when the catalogue read fails. In every one of these cases the private fields still load.
6. **The dossier keeps unsaved work** (frontend). Each field has its own buffer. A save sends only its field, with the `updated_at` the page holds. It then refreshes the fields it sent and the ones nobody is editing, so changing the stage keeps the note being typed. Saves on one fund run one after another. A failed save keeps the draft and says so. Offline is said. A 409 opens the conflict Sheet with both versions, offering Combine both (note), Keep mine and Keep the saved version, plus Copy my text. Leaving with unsaved text asks first, through D4961's guard. Write into the note is disabled while the note has unsaved text (ZoneDraft's new `acceptBlocked`). Once accepted, the page moves focus to the added text. Saves, links and accepts are announced in one polite live region.
7. **My funds** shows 50 rows a page, with a search box and Previous and Next. It uses the URL keys `mq` and `mpage`, because the Directory tab already owns `q` in the same URL. A "Needs a choice · N" toggle shows the legacy rows. The count strip states its scope. The tiles are Researched, Right stage, Whole-round test, Allocation test and Passed. The table has the canvas's seven columns, and stage fit, route in and status are three columns, each with its own editor.

### Where the build departs from the canvas

- Stage fit, route in and status stay three `<select>`s on the dossier rather than the drawn radiogroups. They are still three separate decisions, and each saves only its own field.
- The leave guard is the browser's confirm, which D4961's guard calls synchronously, not the drawn in-app dialog with "Stay and save" focused.
- The Directory's "Your [name] entry is not linked yet · Resolve it" hint is not drawn. The Directory list belongs to #7166.
- Export CSV in the page head is not built. No route exports My funds.
