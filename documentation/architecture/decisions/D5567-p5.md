## D5567 part 5 — Require owner containment evidence at the broker (#5567)

Owner option A requires ContainmentEvidence on provider policy, evaluated by workspaceSecurity eligibility before registration and each non-control grant issue/redemption. Provider reports cannot synthesize owner-registry authority. Image, legacy privilege and runtime checks remain mandatory; containment additionally checks freshness, provider identity, egress, bindings and sandbox strength using the security clock. Missing or expired evidence refuses.

The server compute policy rejects absent, malformed, self-reported or non-Cloudflare evidence. BYOC provider translation accepts a separate trusted-registry argument, default null; its runner manifest is never evidence authority. Cancel/status/cleanup grants retain the existing emergency-control exception so a denied/revoked provider can be torn down. No evidence registry, production provider or compute flag is activated.

Remaining acceptance: owner registry population/revocation lifecycle, hosted conformance/image-pipeline proof, scoped object transport and complete budget/approval/audit composition with the owning tasks. Revert this part to restore prior admission behavior; do not use rollback to enable unsupported workloads. No schema or resource changes.
