## D4711 — Expertise P3: announced saves, managed focus, writes that keep the page, copy that matches the forms (#4711)

- **Status:** Built for #4711 (Expertise P3), 2026-11-07. Frontend only.
- **Builds on:** D4681 (P2: services edited in place, deliberate proof deletion), D4689 (paged lists), D4670 (consent asks), D4697 (fixed failure sentences), D1329 (Ask on a new service).
- **No migration, no Worker change.**

### What was decided

1. **A save or a failure is announced.**
   - `SaveNote` is a live region (`role="status"`, `aria-atomic`) that is mounted empty and receives its sentence. A region mounted together with its text is read by some screen readers and skipped by others.
   - A failure is `aria-live="assertive"`, a save `polite`.
   - `ZoneBody`'s loading state is `role="status"` with "Loading…". Its unreadable card is `role="alert"`.
   - `StaleNote` (`role="alert"`) says a re-read failed.
   - These live in the shared kit, so the Research, Deals, Partner and Cohorts zones that draw it get them too.
2. **A field's hint describes its field.** `Field` gives the hint an id and points the control's `aria-describedby` at it. The hints carry rules ("blank reads as not recorded, not as free"), so a screen reader hears them on the field.
3. **The completeness meter is a progressbar:**
   - `role="progressbar"`, with its value as `aria-valuenow`;
   - `aria-valuetext` names the filled and missing fields (`completenessText`).
4. **Focus follows the workflow.**
   - **Opening:**
     - a service's edit form takes focus at Title;
     - Proof's consent ask takes it at its first field;
     - each delete or remove question takes it at "Keep it".
   - **Closing:** Escape closes each of these, and focus returns to the row button that opened it.
   - **State:** the toggles carry `aria-expanded`, and row buttons name their row.
5. **Removing a service asks first, once.**
   - **Asks first:** the trash button opens "Remove …?" in place, saying what goes with it (nothing else references `advisor_services`).
   - **Once:** a row has one write in flight, so a second press sends nothing.
   - **Outcome:** a 404 reads as "already removed". Every failure is a fixed sentence keyed on the refusal code (`refusalText`, `SERVICE_FAILED`), never the error's own text.
6. **A write re-reads in place (`usePagedList().refresh()`).**
   - **The defect:** writes called `load()`, which drew the loading state, unmounted every row and re-read only the first page. So:
     - a consent ask's "Request recorded" line vanished with its form;
     - focus was lost;
     - rows reached through "Show more" disappeared after an unrelated edit.
   - **Now:**
     - `refresh()` keeps the rows on screen;
     - it reads as many rows as were shown, page by page and bounded;
     - on failure it keeps the rows and sets `refreshError`.
   - **Newest wins:** every read carries a sequence number, so an older answer that lands last is dropped.
7. **The rail matches the forms.** The Expertise rail said no word on the bucket is drafted, beside a Services form that offers Ask on a new service's title and scope (D1329). It now says:
   - what Ask drafts there, and only when asked;
   - that nothing is saved until the service is added;
   - that no price, claim or attestation is drafted.
8. **Licence navigation is #4473's.** The Expertise routes stay `guard(['admin', 'advisor'])`. #4473 (S18) makes the guard admit a held licence, which reaches an additional Advisor licence. No switcher is added here, and a test pins both.

### Left for another issue

- **Worker access policy.** The Worker's `requireMyAdvisor` checks for an attached profile, not the Advisor licence. So the services, proof and thinking routes do not re-check a revoked licence. That is the access policy #4715 defines for the whole advisor domain, and it is fixed there rather than here.
