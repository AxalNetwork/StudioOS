## D4478 — Learning lesson footer, offline and phone bar (#4478)

Learning follows the supplied Learning Stream Page design's LR4, LR4b, LR8,
LR8b, LR19f, LR20b and LR21. The existing item/progress routes are sufficient;
this changes the frontend only, with no migration or new client method.

A known lesson order is derived from a zero-based index and a positive total.
Missing or invalid order draws no line. A module title is appended only when
recorded. The shared footer goes below a video and a course reading with text;
an empty reading has no footer. The completion control exposes Saving or
Nothing to complete yet in its title and linked accessible description.

The browser's online/offline events control the poster overlay. The native and
Stream players retain the existing positionWriter's 15-second online throttle,
pause flush and no-concurrent-write rule. Offline events overwrite one pending
position; reconnect flushes that latest position once. If an older write is
still in flight, the pending position is flushed after it settles. Changing
source or unmounting drops the old pending position, which must never be
written to the next video. Completion remains available offline; a failed save
shows the route's refusal payload, never an exception's message.

Below 640px the player bleeds through the 16px page gutter, only the chapter
chips scroll horizontally, and a persistent bottom bar offers 44px controls
with named previous/next icons. At 768px the player, footer and chapters stack.
Reading prose is at most 680px. Existing theme classes provide light/dark
surfaces and ink; no new hard-coded light colours are introduced. Learning
pages, including the dormant gate and studio pages, mount no assistant rail.
Learning remains in the Account menu; this adds no sidebar UI.

After #4499 and #4508 merged, LearningWired integrates the shared completion
control in the lesson and item headers. Empty readings omit the lede and keep
one disabled header action, even when an older progress row says completed.
Course lessons pass their recorded zero-based index and total to the footer.
learningModel re-exports the existing footer rules, keeping one implementation.
The validated URL time handoff and item remount key from #4477 are preserved.

LessonPlayer also accepts the legacy recorded `position` string and draws a
reading completion control for callers that do not supply a header. Standalone
videos have no invented previous/next controls. The uploaded-file fallback
identifies its actual source; real recorded chapters are retained.
