## D4536 part 3 — Flag possible overlap between published skills (#4536)

**Status.** Proposed for the HQ library read. The served overlap field remains
unavailable while #5970 owns the shared route and coverage module.

### Metric dictionary

| Metric | Source | Grouping | Window | Denominator | Availability | Scope |
|---|---|---|---|---|---|---|
| `coverage.overlap.suggestions` | `agent_skills` joined to `agent_skill_versions` on the current version | unordered pair of skill UID and immutable version | the current published catalogue at read time | eligible pairs compared | empty only after a successful scan; exceeding the catalogue cap or failing to read the source makes the measure unavailable | HQ, Super Admin |
| `score` | unique normalized purpose terms on both versions | pair | same snapshot | union of the two term sets | recorded only for a suggested pair | HQ, Super Admin |

### Method

1. Read only published HQ skills and their immutable current version. Select
   UID, version, purpose, output kind, ordered taxonomy tags and roles.
   Exclude company rows in SQL. Source-library, draft and retired rows have
   no place in the comparison. Report how many published rows could not be
   compared because version metadata is missing or invalid.
2. Compare different skills only when they share the recorded primary tag,
   output kind and at least one role. Take distinct purpose terms from
   `skillDiscovery.terms`. Require at least three shared terms and a Jaccard
   score of at least 0.30. The score is the number of shared terms divided
   by the number of distinct terms across both purposes. Taxonomy or role
   alone cannot qualify a pair.
3. Label each match **Possible overlap**. Return both UIDs and versions,
   shared role keys, the primary tag, output kind and score. Sort by
   descending unrounded score and then both UIDs in canonical pair order.
   Return up to 20 suggestions with the total before truncation, compared
   pair count, source row count and skipped metadata count. This is a
   review cue. It never changes a skill, affects discovery ranking or
   qualifies a version.

Use one bounded metadata read on the existing HQ route and apply #5970's
validated catalogue filters before grouping the candidates. Evaluation date
and model filters do not change overlap. Read at most 251 rows, in stable UID
order. If the 251st exists, return `{ available: false, reason }` rather than
presenting a subset as a scan. At 250 rows the worst case is 31,125 comparisons.
Do not add storage, a model call, a second route, or a dashboard to this slice.

### Calibration and integration checks

At main `4193d946`, an offline probe over 182 source-library definitions
found 104 pairs sharing a primary tag, output and role. The highest purpose
score was 5/18 for Pipeline health diagnostics and Pipeline review brief.
None crossed 0.30. The probe used source files as calibration inputs.
The served metric will use D1 snapshots, so the probe establishes neither
live catalogue coverage nor recall.

Before serving the block, test a synthetic near paraphrase and an exact
purpose copy as positives, and the source library's two Pipeline skills
as a negative. Cover half-complete metadata, a tenant row and a retired
row, reversed input order, an empty catalogue, the scan cap, and the
suggestions cap. A failed block should leave the other coverage and
published-evaluation measures readable.
