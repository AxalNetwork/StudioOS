## D9288 — Eadwyn's history says when it could not be read, and a tool receipt draws the same live, after reload and on the phone (#9288)

- **Status:** built by S21 on #9288, 2026-11-28.
- **Chosen by:** the owner's supplemental Eadwyn audit, §11.1 "History honesty", "Tool preview consistency" and "Phone history completeness", as filed on the issue.

### The problem

- **History.** `PersonalAdvisor.jsx`'s bootstrap caught a failed `GET /advisor/conversations/:id` and carried on with nothing hydrated, so the empty-transcript test fired and a reader with a long history was greeted with the newcomer orientation. A failed read looked like a new, empty conversation.
- **Question widget.** `AdvisorProgressWidget.jsx` read `/advisor/queue` and `/advisor/answered` with `allSettled` and kept whichever answered. Every bucket is computed from both (Proposed and Pending drop completed ids), so one failed read drew "You're all caught up!", empty buckets, or the previous read's buckets beside a fresh half.
- **Tool turns.** A live `/tool/auto` turn put the CTA on the message and the bubble skipped the result preview; after a reload the same row was re-parsed from the stored envelope and drew the preview too. The same action looked different before and after a reload.
- **Phone.** `StudioPhone.jsx`'s transcript sheet kept user and assistant rows only, so every saved action receipt disappeared from the phone's history.

### What was decided

- `frontend/src/lib/advisor/transcript.js` holds both rules, pure. `openingState({ historyReadable, hydrated })` decides what the chat opens on: `unreadable`, `orient` (read, and empty) or `history`. The bootstrap marks the history unreadable when the read throws or answers without a `messages` array, reports it, and opens on `historyUnreadableNotice`: "Couldn't load your earlier conversation." with Retry, which runs the load again. The orientation is shown only for a history that was read and is empty.
- `queueReadState(q, a)` is readable only when both reads answered their shape. When it is not, the widget draws "Couldn't load your questions." with Retry in place of all three buckets, desktop and phone, and keeps no half-read state on screen. The widget's sentence names questions, not a conversation, because that is what it failed to read.
- One tool-message model. A live turn's row is `{ role: 'tool', content: toolEnvelopeText(r) }`, the same string the Worker stores (`JSON.stringify({ result, cta })`). Every surface reads a row through `readToolMessage`, which also turns the Worker's `refused:<reason>` rows into "That action was not run." and an unparseable row into "This action's result could not be read." instead of raw JSON. The chat draws it with `ToolPreview` (`frontend/src/components/advisor/transcriptPieces.jsx`, beside `UnreadableNotice`), the phone sheet with `toolReceiptText`'s one line ("Found 4: …, and 1 more.").
- `components/advisor/` reached eight files, so it gets its README and a `check-folder-docs` entry.

### Left open

- The Worker caps the stored envelope at 4000 characters with `.slice`, so an oversized result is cut mid-JSON and its CTA is lost on reload; it now says the result could not be read. Storing the CTA first, or capping the result rather than the string, is a Worker change outside this issue.
