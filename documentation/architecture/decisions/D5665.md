## D5665 — Itemized Slack batches and durable delivery intent (#5665)

The sender accepts the metadata-only v1 source contract and trusted v1 routing
policy through an internal service binding. It revalidates and redacts before
SQL: no bodies, titles, logs, diffs, arbitrary links or finding contents.
Typed class/disposition/state/slot prefixes come from controlled fields;
GitHub labels are quoted data and cannot select severity, channel or mention.
Links are constructed only from validated GitHub repository/source IDs.
Security and restricted events require an approved private route, with no broad
activity fallback. Only an explicit owner identity mapping can render a mention.

Each nonempty hour has one activity root and five-minute thread batches with
an index, time range, item count, explicit missing-source count and bounded
searchable text pages. Every event keeps a page key/receipt, including 100 matrix
jobs across two attempts, skipped/cancelled outcomes and an incident recovered
before flush. Material actions share one PR/release/incident root, with retained
transition replies and latest root updates. Older updates are superseded so a
delayed retry cannot overwrite a newer root. Routine jobs never make action roots.

A workspace actor holds a durable per-destination outbox, unique logical keys,
parent receipts, attempt/timing/error state and per-channel pacing. Alarms use
the next eligible deadline; held/ambiguous parents do not spin. An independent
five-minute wake schedule recovers pending work after interrupted scheduling. It writes
intent and started-send state before external I/O. Roots precede thread replies;
a busy guard serializes sends within the actor. Sender priorities put human
actions ahead of routine pages. Rate limits honor Retry-After plus bounded
jitter; provider errors have exponential bounded retry and a durable dead state
after five attempts. An accepted timeout or lost acknowledgement write remains
ambiguous across restart and is not automatically resent. Client message UUIDs
help correlation, not an exactly-once claim. Registry changes cannot redirect an
old intent to another destination; per-route switches retain pending work.
Retention limits refuse stale ingestion/queued delivery; physical deletion waits
for the approved retention policy, not an invented default cleanup schedule.

Web API delivery verifies auth.test team ID, conversations.info channel ID,
private/public state, membership and archive state, then posts/updates with
unfurls/automatic mention parsing disabled. HTTP 200 with ok:false is a failure.
The deployment needs chat:write and the approved minimum channel-metadata read
scopes for this verification. File uploads are unnecessary and unimplemented.
No PR secret, CI runner per notification or GitHub write credential is involved.

D5663's bridge persists the original health logical key; only an actual matching
channel/timestamp receipt returns acknowledgement. Existing webhook receipts
have no timestamp and cannot be invented into thread roots. #5668 must inventory
and drain/reconcile those outstanding intents, disable the legacy publisher for
a route, then enable the internal publisher with its approved registry. One
publisher owns each route; no live cutover or old-message adoption is claimed.

Validation uses fixture tokens and a fake API, Node SQLite and a real Workers
SQLite/RPC restart. It covers busy batching, reverse transitions, duplicate
inputs, root updates, partial/retry/ambiguous states, access failures, kill
switches and intent-ack interruption. Local runtime supports November 8; the
November 12 configured target still needs upgraded-runtime validation. Full
build/drift, packaging and mutation results are recorded in STATUS. The approved
Slack-local count/edit/recovery/access canary and independent GitHub-visible
heartbeat observer remain blocked on #5668. The health endpoint and durable
summary are ready for that observer, but no deployed heartbeat is claimed.
#5657 prevents pushing this local preparation.

The read-only publication relay checkpoints only after durable enqueue and
replays the same logical keys after interruption. Source/service binding wiring
and the reviewed routing provider remain disabled rollout work under #5668.
