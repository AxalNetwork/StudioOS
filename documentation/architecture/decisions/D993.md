## D993 — Partner profiles part 4: agreement readiness from the library, the envelope state per profile, and Unbind

- **Status:** filed by S21 as #2804, part 4 of Partner profiles (#2380), from S21's integration in #2742 (D989). Built by S16. No migration.
- **Canvas:** `design/incoming/Partner Profiles Page.dc.html`, boards PRF3c (the agreement select), PRF5 A and F, and PRF6.
- **Worker only.** Part 6 (D995, #2806) draws these reads on PRF3–PRF6. This PR adds no screen.

### 1. The decision

Three additions to `routes/admin_partner_profiles.ts` (D990):
1. **The first-agreement options come from the Worker.** Each option is Ready only when the send would find text: it is read through the send's own resolver, so the page cannot offer a document the send would refuse.
2. **Each profile carries the state of the envelope its first agreement went out in.** The counts fill "envelopes out" from the same join.
3. **Unbind.** A Super Admin, with a recent step-up and a reason, frees a profile whose address now belongs to another account. It is the act `writeRouter.ts` already tells a member an admin can do.

### 2. As built

1. **`GET /api/admin/partner-profiles/agreements`** (`requireAdmin`; `services/partnerAgreements.ts`).
   - **The options:** the fifteen document types the review's select has always offered, in five groups:
     - Investors;
     - Founders · New venture;
     - Founders · Strategic scale;
     - Operators and service partners;
     - Liquidity.

     The labels are the console's. **The values are its exact spelling.** A value is the `document_type` the verify send passes to `createAndSendEnvelope` and stores on `partner_profiles.agreement_type`, so a respelling would orphan every profile that carries it. A test holds the two lists equal.
   - **Readiness:** each value goes through `templateBodyFor` (`routes/esign.ts`, D758), the resolver the send uses. That is the active, non-stub library row under the value's slug, else its bundled file.
     - **Ready** (`ready: true`) when there is text, with `source` (`store` or `template`).
     - Otherwise `readiness: "Not ready: no text in the library yet"`, the send's own refusal in the page's words.
   - **None of the fifteen has a bundled file** (`templateKeyForDocType` maps none of them), so each is Ready only once Contracts › Templates holds a row under its exact name.
   - **A library that cannot be read is a 503** (`agreements_unreadable`), never "Not ready".
2. **The envelope per profile** (`services/partnerProfiles.ts`).
   - **Which envelope:** the newest `esign_envelopes` row whose `document_type` is the profile's `agreement_type`, addressed to the profile's account (`user_id`) or to its email (`esign_recipients`, any case). This is the verify send's own idempotency match.
   - **The state:**
     - `out` (sent or partially signed);
     - `not_delivered` (out, but the latest mail event in `esign_audit_events` is `email_failed`);
     - `signed` (completed);
     - `declined` (rejected);
     - `void`.
   - **The words:** Out for signature, Not delivered, Signed, Declined, Voided.
   - **On the row:** `envelope: { state, label, document_type, sent_at, signed_at }`, on every list row and on a profile's `listed`. `sent_at` is the "since". `signed_at` is set only when it is signed.
   - **No agreement, or no envelope,** is `envelope: null`, which reads "Not sent".
3. **The counts:** `envelopes_out` is now `{ available, reason, count, not_delivered }`. `count` is the profiles whose envelope is out, the not-delivered ones included. An unreadable envelope store costs that block only, never reading as zero.
4. **`POST /api/admin/partner-profiles/:ref/unbind`.**
   - **Who:** `requireSuperAdminWriteBar`, meaning a Super Admin with a TOTP session and a step-up in the last 15 minutes. An Admin is refused.
   - **The reason** is 10 to 500 characters, as a void's (D802).
   - **What it does:** clears the profile's `user_id`, and only the binding it read. A write in between is refused (`binding_changed`), rather than unbinding someone else.
   - **Refusals:**
     - `not_bound` when the profile has no account;
     - `address_still_theirs` when the bound account still holds the address. Unbind frees a profile only when the address belongs to another account or to none.
   - **The log:** Governance gets `partner_profile_unbound` through `logAdminAction` (`admin_audit_log` and `activity_logs`). It records the reference, the previous account as its target, the account now holding the address, and the reason. No email is logged.
   - **Afterwards,** `ensurePartnerProfile` (`writeRouter.ts`) finds the row unclaimed and binds it to the account that now holds the address, on its next answer.
5. **The client:** `partnerProfilesApi.agreements()` and `.unbind(ref, reason)` in `frontend/src/lib/api/partnerProfiles.js`.

### 3. Departures, for review

- **The list lives in the Worker; the page still has its copy.** `PartnerProfilesConsole.jsx`'s `AGREEMENT_OPTIONS` stays until part 6 draws the select from this read. The test holds the two equal until then.
- **"Not delivered" is read from the mail audit only.** A DocuSign envelope writes no mail event here, so it reads "Out for signature" until signed or declined.
- **The envelope is the agreement's, not any envelope.** An envelope of another document addressed to the same person is not the profile's first agreement, and does not show.
- **Unbind refuses when the address is still the bound account's.** The issue's case is "an address that now belongs to another account". Freeing a profile from the account that still holds its address would let the next account to claim the address take the profile with it.
- **D990's counts test updated.** "Envelopes out" now reads from a working store (`count: 0` with no envelope sent) instead of "not available". D990's fixture carries the three signing tables.

### 4. Tests

`cloudflare-worker/test/partner_profiles_agreements_d993.test.ts` has 8 cases. It runs on `node:sqlite` with the baseline's tables and migrations 275 and 556, through the real router, and covers:
- the fifteen values against the console's, and the groups;
- readiness: a stored row, a stub, an inactive row, no row;
- each envelope state, the newest-wins rule, the document match and the address match;
- the record;
- the counts and an unreadable envelope store;
- Unbind and its Governance row;
- Unbind's refusals: no session, an Admin, a member, a password session, a stale step-up, the reason, not bound, still theirs, 404s, and a D1 failure with no log;
- the readiness read's 401, 403 and 503.

**20 of 20 mutations killed.** A 21st, the library store's own stub check, is the D758 store's logic and not this PR's. The stub row's "Not ready" assertion still pins it.
