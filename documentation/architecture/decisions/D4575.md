- **Scope:**

  - tests;
  - the go-live runbook's scorecard.

  There is:

  - no route;
  - no flag change.

### What was decided

**The audit.** A run's record already exists across six tables. The joins are:
- **the run** (`agent_task_runs`), to its task (`scope_tasks`) and its agent (`team_agents`);
- **its usage row** (`ai_usage_logs`), through `usage_log_id`;
- **its hold** (`ai_budget_reservations`), through the hold's idempotency key `agent:<run uid>:run`, set by `agentRun`. This finds a hold even when no usage row was written.
- **its proposal** (`ai_rail_proposals`), through `run_key` `agent:<run uid>`. The key is unique, so a retried step cannot write a second one.

So provenance is a read over these, `runProvenance(env, runUid)` in `services/agents/provenance.ts`. It returns:

| Group | Fields |
| --- | --- |
| Run | Status, step, failure, admitted and ended times |
| Task and agent | The task and its opaque scope (`project:7`); the agent's role, sponsor and configured model |
| Usage row | The model invoked, the skill and version |
| Keys | The run key and the hold key |
| Money | The hold's status, held and settled amounts, and whether it has expired; the charge |
| Decision | The proposal and its decision |
| Summary | One reconciliation word |

**Unavailable is not zero.** Each field that can be missing is `{ available: false, why }`:
- a charge the usage row does not hold, or no usage row at all;
- a model or skill no usage row names;
- a hold never written;
- a decision not yet taken.

Two fields are not recorded per run by any table. They always read unavailable, and the record does not invent them:
- **the tool grants as they were at admission.** Grants are read live at each call, which D4572 relies on.
- **the data class.**

Recording them would need a migration and an owner decision.

**The reconciliation words:**
- `nothing_charged`
- `settled_matches`
- `held_unsettled`
- `held_expired`: an orphan for the sweep.
- `released`
- `mismatch`: a settled amount differs from the charge, a refunded hold carries a charge, or a charge has no hold.
- `unrecorded`: a proposal or usage row whose money cannot be read.

Every word is reachable, and the test holds each one.

**Never in the record:**
- a prompt;
- a proposal's payload;
- a step's summary text;
- a task's title;
- an email or a name.

The test checks a synthetic title, payload, prompt, email and project name are absent.

**The scorecard** is a section of `documentation/operations/AGENT_ENGINE_GO_LIVE.md`. It covers:
- every metric with its existing source;
- the observed, estimated and unavailable labels;
- the owner-approved thresholds, which the owner still has to set;
- six gates;
- rollback.

It links the existing HQ evaluation board instead of adding one. The second-pass audit's gates (#4591, #4592, #4593, #4572, #4556, #4594, #4535, #4571, #4559, #4573) are rows that point to the issue that owns each. None of those gates is claimed met.
