## D5757 — Platform's scope switcher: HQ-wide by default, one subsidiary at `?scope=<code>` (#5757)

Finding 16 of #4860 ("Clarify scope"), split out at the owner's request on 2026-11-13. D4860 part 5 kept the switcher out until a reading was scoped per subsidiary (U1), because a switcher over HQ-wide reads would only relabel them. D5786 added that reading. This builds the switcher on it.

### What is built

- **The switcher** sits in the page header under Ask (`pages/hq/PlatformScope.jsx`, `ScopeSwitcher`). Its button says the scope in force, either "Scope: HQ-wide" or "Scope: Subsidiary `<code>`", and opens a list. The list has HQ-wide first, then each subsidiary from `GET /api/admin/platform/scopes`, with its registry status and "not bound" where it is not bound. The current scope is marked `aria-current`.
- **The scope is an address.** HQ-wide is `/admin/platform`, and a subsidiary is `/admin/platform?scope=<code>`. So a scope can be linked, reloaded and shared, and every option is a plain `<Link>`. Platform keeps its no-handler rule (D203, D4860): the switcher is a native `<details>`, with no onClick, select or form. The switcher is keyed on the scope, so it closes once a link moves the page. An absent or empty `scope`, or `scope=hq`, is HQ-wide.
- **HQ-wide is unchanged.** It reads `/summary`, `/admin/deployments` and `/monitoring/analytics/traffic-by-branch` as before, and draws the D4860 overview and the detail zones.
- **A subsidiary scope** is read from `GET /api/admin/platform/scopes/:code` alone (`ScopedOverview`). It draws:
  - **the state**: the Worker's (`healthStateOf`, D4854), with one sentence of confidence;
  - **three signal cards**: branch health, last stored check and traffic. Each card has its status as a symbol and words, its figures, when it was observed and where it came from;
  - **Needs attention**: the reading's detected incidents, drawn by the overview's own `NeedsAttention` through `detectedIncidents`;
  - **Not readable for a subsidiary**: scheduled jobs and dead letters, each Unreadable with the reason the read gives;
  - **HQ-only, not shown here**: the eleven HQ-only signals, named with their reasons behind a disclosure, and a link back to the HQ-wide view where they and their consoles are drawn.
- **Under a subsidiary scope**, the HQ-wide overview and the "System detail" zones are not drawn. Every one of those zones reads an HQ store: keys, the ticket mirror, the payments catalogue, promo codes, jobs, deployments, monitoring, broadcast and switches. So "narrowing the consoles" to a subsidiary means drawing none of HQ's in its place. They are named as HQ-only instead.
- **The rail** reads back the scope's own reading under a subsidiary scope (`scopeCoverage`), never the HQ-wide lines. `branch_rail_mount` pins `coverage={coverage}` and `const coverage = [...].filter(Boolean)`, so the HQ-wide list keeps its shape and is filtered out under a scope.
- **The client** is `lib/api/platformScopes.js` (`platformScopesApi.list` and `.read(code)`), its own module (D527). Nothing was added to `api.js`.

### Honesty rules, as built (`pages/hq/platformScopeModel.js`)

- **The state is the Worker's, with one guard.** A reading in which none of the three scoped signals answered is Unknown, whatever its state says. A state the page does not know is also Unknown. A read that failed or was refused is Unknown, with "Don't treat this as healthy".
- **A signal that did not answer** is Unknown with the read's own reason. Its figures are null, drawn as Not recorded and never as 0. A traffic count of 0 that Analytics Engine answered (D5786's "true zero") stays 0.
- **A stored check older than the window** is Stale, not Healthy. That check is the Worker's Low `branch_check:<code>` note, and like the note it does not lower the overall state.
- **A refusal is read from `err.code` (D258).** `invalid_scope` says the code is not a subsidiary code, and `unknown_scope` says no subsidiary is deployed or bound under it. A scope in the address that is not in the list is said to be so.
- **An unread list is not an empty one.** If the subsidiaries list fails, the switcher still offers HQ-wide and says the list could not be read: "This is not a claim that there are none". A registry that could not be read gives the Worker's partial-list reason.

### Deliberately left as it is

- **The HQ Platform strip stays HQ-wide** under every scope. The page still makes the three HQ-wide reads and publishes them to the strip (D4860 part 5), because the strip is shell chrome across every Platform console, and its Overview state is the platform's. Narrowing it would need a scoped reading on every console, which no route gives.
- **Scheduled jobs and dead letters per subsidiary** still need a branch RPC, as D5786 says ("Backend required for the remainder"). Until it exists, both read Unreadable.
- **The version context** keeps "Scope: HQ deployment", because the build route is HQ's own Worker.

### Tests

- `frontend/test/platform_scope_d5757.test.mjs` has 12 tests. The real `PlatformPage` is mounted with the Worker stubbed, at `/admin/platform` and `?scope=fr|de|es|zz`. It holds:
  - HQ-wide is the default: no scoped read is made, the overview and detail are drawn, and each subsidiary is a link to `?scope=<code>`;
  - under `fr`, only fr's own route is read. The HQ-wide overview and detail are not drawn, jobs and dead letters are Unreadable with reasons, and every HQ-only signal is named;
  - `de` (database failing) reads Degraded from its own route, with its incident in Needs attention and a true zero of traffic kept as 0;
  - `es` (provisioning, unbound, never checked, traffic unread) is Unknown, with traffic Not recorded and never 0, and the queue is not an all-clear;
  - a refused `zz` with the list failing is Unknown with the refusal, and HQ-wide is still offered;
  - the model's rules on their own;
  - a source guard: no handler, a dark variant for every hover background, no "advisor" or "advice" in user copy, and the client only in its own module.
- **Mutation-checked:** 15 mutants across the model, the component, the page and the client, all killed. Each test passes again on the restored source.
