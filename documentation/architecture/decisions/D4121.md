### 1. A skill version's context

Each skill version's SKILL.md is what a run includes for it. **`context_tokens`** is its size by the AI budget's own estimate (`estTokens`: one token per four characters, rounded up). The new table **`agent_skill_version_costs`** keeps it, keyed by skill and version:
- the migration back-fills every published version;
- `skillPublish.ts` writes a new version's row in the same batch as the version.

It is a sibling table because a published version is immutable: `trg_agent_skill_versions_immutable` refuses every UPDATE, so a new column could not be back-filled without dropping that guard. A version with no row is estimated from its SKILL.md when read.

### 2. The estimate

Per run, for the agent's own model:
- **Tokens in:** the run's own system prompt (`agentRun.ts`'s `systemPrompt`, now exported, for the agent's first module), plus a typical request (400 tokens), plus every pinned version's `context_tokens`.
- **Tokens out:** a typical proposal (800 tokens).
- **`tokens_per_run`:** in plus out.
- **`est_usd_per_run`:** the catalogue's price for those tokens, at what the sponsor pays (`memberChargeMultiplier`):
  - Workers AI models are priced by `billedMicro`;
  - provider models by `usdRatesBilledMicro`.
- **`monthly_at_cap`:** how many such runs the agent's monthly cap pays for (null for an agent not yet added, whose cap is set later).
- **`before`:** the agent's skills now.
- **`baseline`:** the same agent with no skills.
- **`delta`:** after minus before.

When the model's price cannot be read, or a pinned version cannot be read, the answer is **`{ available: false, reason }`**, never 0. The page reads "Not recorded" and never shows "$0.00" for a price nobody read; a real fraction of a cent reads "< $0.01".

The typical request and output sizes are estimates, not measurements. Runs do not yet read their skills' SKILL.md (#3954 wires that), so this is the cost a skill will add, which is what the owner's cost line promises. When runs record real token counts per skill, the typical sizes can be replaced with measured ones.

### 3. The thresholds and the hint

`RUN_COST_CONFIG` in `services/agents/runCost.ts` is the one place the figures live: `requestTokens` 400, `outputTokens` 800, `specialistMaxSkills` 6, `specialistCostRatio` 2.

The hint appears when:
- the agent would have more than 6 skills (`reason: 'skills'`), or
- a run would cost more than 2× its baseline (`reason: 'cost'`).

It names:
- the area most of its skills fall in (by their taxonomy tags, ties in the radar's order);
- an offered persona not already on the team whose natural fit includes that area, in catalogue order, or none.

Hidden and retired personas (D4158) are never suggested.
