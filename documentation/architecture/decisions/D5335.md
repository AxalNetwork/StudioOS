## D5335 — The skill library's read-only reconcile route (#5335)

- **Status:** built by Claude Code for slot S13, 2026-11-11. Not deployed. Follow-up to #4529 (PR #4971) and #4532 (PR #4989).
- **Number:** D5335 is this issue's number (D4106).
- **Migration:** none.
- **Code:**
  - `routes/admin_hq_skills.ts`: `GET /library/reconcile`.
  - `services/agents/skillCatalogue.ts`: `libraryManifest`, `reconcileReport`, `persistedFromJson` and `RECONCILE_CLASSES`.
  - `scripts/check-skill-library.mjs`: `--persisted` now accepts the route's JSON.
- **Test:** `cloudflare-worker/test/skill_library_reconcile_5335.test.ts`.

### 1. Why

D4532 §3 says that reconciliation with the store runs only "from a separately authorized read-only preflight". That preflight did not exist. `persistedManifest(env)` was called only by tests, and nothing produced a `--persisted` file from production. `SKILL_LIBRARY_AUDIT.md` therefore had to call the deployed catalogue unknown.

### 2. The route

`GET /api/admin/ai-agents/skills/library/reconcile` is gated on `requireSuperAdmin`, the narrowest role that reads Axal's drafts. A plain admin gets 403.

It runs D4532's own pieces and adds no rule of its own:
- `persistedManifest(env)` reads HQ-scope skills (`scope = 'hq' AND company_id IS NULL`) and their live cases.
- `libraryManifest(taxonomy, SKILL_LIBRARY)` builds the source side.
- `reconcile(source, persisted)` compares the two.

The Worker reads no file at run time, so the source side comes from the generated module. It goes through `checkLibrary`, against the store's live taxonomy (`taxonomyMaps`), which is the check the seed itself uses. On the committed library this manifest equals the CI gate's (`checkSourceCatalogue`), and a test pins the equality. An entry that `checkLibrary` refuses has no hash. `reconcile` calls it `invalid_reference`. In production, that happens when the store's taxonomy has lost a tag that the files use.

The answer has these parts:
- **`skills`:** one line per slug, with `class`, `disposition`, `source_hash` and `persisted_hash` (the two draft hashes), and `published_version`. `published_version` is the row's `current_version` when it is above 0; otherwise it is null.
- **`totals`:** every class, zeros included.
- **`manifest`:** the persisted side, as hashes and case identities (`case_id`, `revision`, `key`, `sha256`).

The answer never carries:
- draft text or case input;
- a company skill;
- a person or a user identifier. The skill `uid` is a skill's.

The route writes no store row. Its one write is `logAdminAction` (`agent_skill_library_reconciled`) with the scope, the number of lines and the totals. The audit records the read because the route reads every HQ draft and case to hash them.

It repairs nothing. Each class keeps D4532's disposition, and a person acts through the routes that already exist (`SKILL_LIBRARY_AUDIT.md` §10).

### 3. The command reads the route's JSON

`scripts/check-skill-library.mjs --persisted <file>` accepts either of two inputs through `persistedFromJson`:
- the bare array that `persistedManifest()` returns;
- the route's JSON, whose `manifest` array it uses.

Anything else exits 1 with a message. It is never read as an empty store, because an empty store would make every slug `source_only`. The command then reconciles its own source manifest, read from the files, against that manifest.

### 4. No client method

No screen uses the route yet. The UI belongs to #4956, so `frontend/src/lib/api/adminHqSkills.js` is unchanged.

### 5. The production result

This PR cannot produce the production result. After the deploy, a Super Admin opens the route once on production and pastes the class totals on #5335. Those totals and their date go into `SKILL_LIBRARY_AUDIT.md` §10, in the place marked for them, with no content.

### 6. Tests

`skill_library_reconcile_5335.test.ts` covers the following on a seeded local sqlite D1:
- every class through the route, with both hashes, the published version and the totals;
- a company skill with a library slug, or with a slug of its own, ignored;
- a plain admin refused with 403, and no audit row for the refusal;
- every store table's row count unchanged, plus exactly one audit row holding the totals;
- no draft step, case input, email, name or user uid in the answer, and the exact key set at each level;
- `libraryManifest` equal to the CI gate's manifest on the committed library;
- `check-skill-library --persisted` reaching the route's totals from the route's JSON, and refusing JSON with no `manifest`.

Each of the following mutations fails the suite:
- opening the gate to any admin;
- dropping the HQ-scope filter in `persistedManifest`;
- a write in the route;
- draft text added to the manifest;
- dropping the published version;
- dropping case ids from `libraryManifest`;
- the command ignoring the route's shape;
- removing the audit row;
- totals that omit zero classes.
