## D8260 — Company creation: export filings and proofs, and preselect stored papers for the Data room (#8260)

**Decision date:** 2026-11-22. **Scope:** Build › Company creation (BD25), Worker and frontend. No migration and
no new store. Follows D6038 (#6038, PR #8174), whose module page draws both hand-offs as "no endpoint".

### What changes

- **Routes.** `cloudflare-worker/src/routes/company_creation_handoffs.ts`, mounted at `/api/cycles/build`
  ahead of `cycle_build.ts`'s router:
  - `GET /company-creation/filings/export?project=<id>`: the filings table as CSV.
  - `GET /company-creation/data-room?project=<id>`: the four papers, with the stored ones not yet in the
    room preselected.
  - `POST /company-creation/data-room?project=<id>` with `{ kinds }`: copies those papers into the venture's
    data room.
- **Who.** The Build board gate first (`context`), then membership of the venture's company
  (`viewerIsMember`, which admits an admin), as the module's papers block already reads them (D6038).
  - A venture with no company is 409 `company_not_linked`.
  - A non-member is 403 `company_members_only` and is told nothing about the company.
  - Adding also needs the room's upload right (`roomProject` + `roomCan('upload')`, D1103), so only the owner
    or a co-founder adds. Anyone else, an admin included, gets 403 `room_upload_denied`.
- **The export.**
  - It writes the module page's own rows (`company()`), with the page's five columns and a sixth, "Proof link".
  - A stored proof on a Build filing or an obligation links to that filing in the app
    (`<APP_URL>/build/company-creation/<row>?project_id=<id>`), where Open proof mints its one-time download
    (D690). A download token is never written into a file, and neither is a stored key.
  - A filing with no stored proof reads Not recorded in that column, as every empty cell in a Build export
    does (D6043).
  - Every cell passes `csvCell`, so a value that starts like a formula is written as text.
- **The room copy.**
  - Each chosen paper's bytes are copied to a fresh `data-room/<venture uid>/<uid>` record (D6651). The room
    never shares the company document's object, so removing the paper from the room leaves the company's
    copy whole.
  - The row is filed as the cap-table and use-of-funds snapshots are: `visibility` nda, `access_tier` nobody,
    `source_kind` document.
  - `source_ref` is `company_document:<document uid>`. A paper already in the room is read as in the room,
    is not preselected, and is skipped if chosen. A copy in Trash (D6073) does not count: the paper is preselected
    again and a new copy is added.
  - A missing or unreadable paper is never preselected and is skipped with its reason.
  - Each row and its activity line (`build_paper_to_data_room`) are one batch. If the batch fails, the object
    just stored is erased as `unreferenced`. The upload counts against the venture owner's storage (D1170).
- **Frontend.** `CompanyCreationHandoffs.jsx` draws Export filings and proofs beside the filings table and Add
  to Data room under Documents. Both show only where the papers block read as a member's. The client is
  `frontend/src/lib/api/companyCreationHandoffs.js`.
- **Shared files.** Two shared functions become exports so the routes reuse them instead of copying them:
  `cycle_build.ts` `company` and `context`, and `company_documents.ts` `pointerOf`.

### Rollback

Revert the PR. No data changes shape. Papers already copied into a data room stay there as ordinary room
files, under NDA and shared with nobody, and the founder can remove them from the room as usual.
