## D7709 — Bounded, operator-run market observation imports (#7709)

The World Bank adapter now uses the shared writer in `services/marketObservations/`.
Dashboard quotes remain in `market-data.ts`; `researchMarketData.ts` prepares World Bank
observations, and the new folder owns all observation/run/source writes.

### Bounds and continuation

An operator names integer `from`/`to` years (1900–2100, at most ten years), and may
select at most ten distinct known indicators. One request fetches country metadata
(at most 400 rows) and at most two 20-row data pages. Each response is bounded to
250,000 bytes and 12 seconds. The cursor binds the range, indicators and current page;
it never supplies a URL. Requests exceeding the declared caps are refused before an
import run or provider call. A later-page failure retains admitted earlier pages,
records `partial`, and returns the failed page's continuation. These are batch receipts:
a succeeded batch with a continuation does not claim the whole source was refreshed.

### Rows and editions

`published_at` and `vintage` use the provider's `lastupdated` date. When it is absent,
publication stays null and the cell gets a deterministic content identity, never a
fetch-time publication date. Missing or nonnumeric values store nothing; measured
zero remains zero. World Bank's status remains `unspecified` (D7318).

One bounded prior query reads each cell's latest row and requested edition. Inserts
use `DB.batch` and bound values. Changed values or status in a new edition append a
row naming the latest stored predecessor. Existing editions and unchanged cells
append nothing. A contradictory value under an already-held immutable edition is a
classified `edition_conflict`, not an overwrite or fabricated edition. Concurrent
insert races are reconciled in one bounded postflight query, not one query per cell.
Buffered duplicate cells are counted unchanged only after their original is durable.

### Receipts and operator gate

Each enabled-source attempt records its start and terminal outcome (`succeeded`,
`partial` or `failed`), admitted-page rows seen, actual rows inserted and unchanged
cells. Failure retains existing observations. Source attempts, latest success and
latest-attempt error are recorded; an older finishing run cannot erase a newer
attempt's error. Errors contain a diagnostic class and optional HTTP status, never
a provider or database response body. Diagnostic logging uses D7256's bounded
classification helper. A disabled source is refused before provider work and checked
again before writes. No migration or new column is needed.

`POST /api/admin/market-observations/imports` accepts `{ importer: "world-bank",
params: { from, to, indicators? }, cursor?, reason }`, with a 3–500 character reason,
and requires the HQ Super Admin TOTP write bar. The actor, normalized parameters and
reason are audited before work; the outcome audit names the run and counters.
Success returns 202; incomplete attempts return a body-free 502 refusal with the
receipt and retry cursor. Validation and disabled-source refusals use `refuse()`.

`GET /api/admin/market-observations/runs` requires an HQ admin, defaults to World
Bank and 20 rows, and permits a source and limit up to 100. Running receipts older
than 15 minutes say `Not finished`; their unfinished counters are null. Historical
exception text is redacted on this new reader. Failed reads are unavailable, never
an empty successful result. Neither route names a member record, so no auth-inventory
entry is added. The member refresh handler and `refreshWorldBank` client method are
removed; the three existing Research reads remain.

### Verification and boundaries

Stored-row tests load the baseline and every migration and use synthetic, inline
World Bank response shapes. They cover edition replay, revisions and status changes,
missing values, measured zero, bounded pages/cursors, source disabling, partial and
failed runs, failed database writes, actor audits, HQ/factor/step-up gates and branch
refusals. Assertions and deliberately broken source variants are mutation-checked.
The decision-ID, auth inventory, folder documentation and drift checks are required.

General queries, the metric catalogue and CSV are #7716; additional sources and a
schedule are #7737; screens are #7718. No production data was read or written.
