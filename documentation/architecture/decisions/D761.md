## D761 — The AI router runs every kind of model the catalogue offers, each with its own request shape, timeout class and fallbacks, and every attempt reports the units the Worker measured

Status: Built (PR 4 of 4 closes it). Date: 2026-10-19. Slots: S22 (PR 1), S26 (PR 2 on). Issue: #2018. Part of D720 (#1874), task `A2` (the plan's D724). #1874's plan, §2 and §7 ("Timeouts"), is the decision; this file records it as built.

| PR | Holds |
| --- | --- |
| PR 1 (`Part of #2018`) | text and reasoning shapes, the per-class timeouts, the context-window skip, the paid-only fallbacks, `x-session-affinity`, and `units` on every attempt |
| PR 2 (`Part of #2018`) | vision, rerank, embeddings for rail runs, translation |
| PR 3 (`Part of #2018`) | speech (the websocket unit) and voice |

Worker only. Every test runs on a stubbed `env.AI`; nothing here calls Workers AI.

### Where things live

- **`cloudflare-worker/src/services/ai/shapes.ts`** holds the request and response shapes and the rules on each attempt. It is pure, with no `env`, binding or D1.
- **`services/aiRouter.ts`**:
  - `callWorkersAI` builds its requests and reads its answers through the shapes.
  - `run` applies the timeouts, the context-window skip and the attempt record.
  - D761 owns `callWorkersAI`'s shapes, `TaskClass`, `ROUTE` and the timeouts.
- **Owned elsewhere:**
  - D760 (A1): the prices and the catalogue;
  - D762 (A3): the quote, the hold and the settlement;
  - D763 (A4): the guard hooks.

### PR 1, as built

1. **The catalogue is read through one lookup.**
   - `shapes.factsFor(model)` answers a model's `kind`, `context_window` and `paid_only`.
   - D760 installs its catalogue with `setModelFactsSource`. Until then, the lookup knows only the reasoning controls in item 3. So no model is skipped for its context window, and none is treated as paid-only.
   - A model the source does not know is plain text, with nothing known about it.
2. **Timeouts per class** replace `PRIMARY_TIMEOUT_MS`:
   - chat: 8 seconds;
   - reasoning, and any input of at least `LONG_CONTEXT_TOKENS` (32,000): 30 seconds;
   - images: 60 seconds.

   A streamed run gets the same limit for its handshake and its first chunk (`firstChunkWithin`):
   - a stream that sends nothing in time is cancelled, and the router falls back;
   - a stream that opens after its limit has passed is cancelled rather than leaked;
   - the body after the first chunk is not timed.

   Each attempt records its `timeout_ms`.
3. **Reasoning models.** The control is the one each model page gives, taken from `@cloudflare/workers-types`, which Workers AI generates from its own metadata:
   - `reasoning_effort` for GPT-OSS 120B and 20B, DeepSeek V4 Flash and Pro, GLM 5.3 and 5.3 Flash, and Kimi K2.6;
   - `chat_template_kwargs` for Nemotron 3 120B;
   - no control for QwQ 32B and DeepSeek R1 Distill, which always reason.

   No effort is chosen in PR 1, so each model runs at its own default until a task names one.

   **Output budget.** A reasoning model gets `max(caller's max_tokens, the task's reasoningMaxTokens or 4,096)` instead of 512, because thinking spends tokens before the answer starts. The budget hold (`reserveAiBudget`) reserves the same figure.

   **The answer.** It is the message `content` (or `response`):
   - `reasoning_content` is never returned;
   - a reasoning model's inline `<think>…</think>` is stripped, including a closing tag with no opening one;
   - a text model's answer is left alone.
4. **Context windows.** When estimated input plus the attempt's `max_tokens` exceeds a model's known `context_window`, the router moves to the next model in the chain without calling the first. The skip is recorded as `called: false`, status 413. An unknown window always fits.
5. **Failures.**
   - Every failure moves down the chain, as before.
   - `failureOf` reads a thrown binding error's status and Workers AI's numeric code. A status on the error wins; otherwise it is read from the message.
   - The attempt records both.
   - A `paid_only` model's 429, or 403 with code 5035, is a failed attempt like any other (`isPaidOnlyRefusal` names it): the plan cannot run that model, and a sibling may well answer.
6. **Cache affinity.** `x-session-affinity` is `u<user id>:<page key>`, sent through the binding's `extraHeaders` beside any gateway option.
   - The page key is the run's normalised `surface`, else its task.
   - Anything outside `[A-Za-z0-9/_.-]` is refused, so an email or a name never becomes a key.
   - A call with no member behind it (user id 0) sends no header.
7. **Units.** Every attempt reports `units` in D760's names, measured by the Worker, never taken from a browser. It uses the provider's counts when given, else an estimate from the text the Worker holds. Each kind fills only its own units, and nothing is zero-filled.
   - **Text:** `tokens_in`, `tokens_out`, and `tokens_cached` when the provider reports `prompt_tokens_details.cached_tokens`.
   - **Embedding:** `tokens_in`.
   - **Transcription:** `audio_minutes`, from `audioMinutesFromBytes`.
   - **A stream at open:** `tokens_in`. Its output is counted where D762 settles it.

   `RunResult` carries the answering attempt's `units` and every attempt, in order, as `attempts`.
8. **Unchanged:**
   - **The system `embed` task** keeps BGE Base EN v1.5, because the `axal-search` index is 768 dimensions.
   - **The streamed `completion_tokens: 0`.** D762 owns it.
   - **`GET /api/public/ai-models`.** The fourteen `rail_<kind>` tasks come with D764's matrix, which supplies their models.

### PR 2, as built

Every shape is the model's own, read from `@cloudflare/workers-types` 5.20261012.1 (generated from Workers AI's metadata) and each model's page (`/workers-ai/models/<name>/`, through the Cloudflare docs connector, 2026-10-19). Where the two disagree, the page wins: the types leave `query` out of the reranker's input, and its page marks it required.

1. **What a run asks.** `RunOptions` gains three inputs, at most one per run:
   - `images`: base64 data URIs;
   - `rerank`: `{ query, contexts, topK? }`;
   - `translate`: `{ sourceLang?, targetLang }`, over `text`.

   A run's need is `chat`, `vision`, `rerank`, `embedding` (a route with `isEmbed`) or `translation`. `shapes.canServe(facts, need)` decides whether a model can take it.
2. **A model that cannot serve the run is skipped without a call.** This works like the context-window skip: the attempt is recorded `called: false` with status 422. A text-only model handed an image would otherwise answer as if there were none, and a fallback down the chain would hide that.
3. **Malformed input is refused before anything runs:** before the guard, the hold and every model. The refusal is `invalid_input`, and nothing is charged. It covers:
   - more than one of the three inputs;
   - more than 4 images, or an image over 4 MB;
   - an image that is not a PNG, JPEG, WebP or GIF data URI. The Worker never hands a model a URL to fetch, and measures what it sends;
   - a rerank with no query, an empty context, more than 100 contexts, or a `topK` below 1;
   - a translation without a language code. m2m100's page asks for codes (`en`, `pt-BR`), so names are refused.
4. **Vision.** The images ride on the last user message as content parts, text first, then `{ type: 'image_url', image_url: { url } }` per image. This is the shape all four of the catalogue's vision models take: Gemma 4 26B, Llama 4 Scout, Llama 3.2 11B Vision and Kimi K2.6. Vision is a capability of a text or reasoning model (`ModelFacts.vision`), not a kind, so Kimi K2.6 stays a reasoning model. The attempt reports `images_in` beside its tokens. Billing stays in tokens, which the provider's usage counts.
5. **Rerank** (`@cf/baai/bge-reranker-base`).
   - Request: `{ query, contexts: [{ text }], top_k? }`.
   - Result: `ranking`, best first, as `{ index, score }`, where `index` is the context's place in the request. An entry whose id is not a sent index is dropped.
   - Units: `tokens_in`, the query once per context plus that context, as the model reads each pair. A reranker writes nothing, so there is no `tokens_out`.
   - The query and every context go to the guard as the run's input.
6. **Embeddings for rail runs.** Every embedding model in the catalogue takes `{ text }` and answers `data[0]`, which is PR 1's shape: BGE Small, Base, Large and M3, Qwen3 Embedding 0.6B, EmbeddingGemma 300M and PLaMo Embedding 1B.
   - **`axal-search` takes only BGE Base EN v1.5's vectors.** `shapes.SEARCH_INDEX_MODEL` names that model, and `searchIndexAccepts(model, vector)` checks both the model and the 768 dimensions. EmbeddingGemma's 768 dimensions would fit the index and be silently wrong, so the dimension check alone is not enough.
   - `services/vectorize.ts`, the index's one writer, takes its model from that constant and checks every vector before `upsert`.
   - The system `embed` task keeps BGE Base.
7. **Translation** (`@cf/meta/m2m100-1.2b`).
   - Request: `{ text, target_lang, source_lang? }`. With no source language, nothing is sent, and the model uses its default, English.
   - Result: `translated_text`.
   - Units: `tokens_in` and `tokens_out`, priced alike on its page.
8. **The cache key** takes the images, the rerank and the translation as well as the words. Otherwise two runs with the same prompt and different images, or different target languages, would share one answer.
9. **The kinds, until D760.** PR 1's seam stays the only source: `factsFor` / `setModelFactsSource`. Until A1 installs its catalogue, two interim tables answer, as `REASONING_CONTROLS` does: `VISION_MODELS`, and `INTERIM_KINDS` (one reranker, seven embedding models and m2m100).

### PR 3, as built

Each shape is its model page's (`/workers-ai/models/<name>/`, through the Cloudflare docs connector, 2026-10-19).

1. **What a run asks.** `RunOptions.speak` (`{ voice?, lang? }`) asks for `text` to be spoken. It is a fourth input beside PR 2's three, still at most one per run, and the result carries `audio`: `{ bytes, mime }`. The need is `voice`. No task class is added: D765's run path picks the task, as it does for a rerank or a translation.
2. **Refused before anything runs** (`invalid_input`, nothing charged):
   - no text, or more than 2,000 characters (`MAX_SPEAK_CHARS`). Aura bills per character, so this bounds what one press can cost;
   - a voice that is not a lower-case name, or a language that is not a two-letter code;
   - a voice run that is also streamed, or asked of a transcription route.
3. **Aura** (`@cf/deepgram/aura-1`, `aura-2-en`, `aura-2-es`).
   - Request: `{ text, encoding: 'mp3', speaker? }`. The answer is a stream of audio.
   - A speaker the model's page does not list is refused for that model (status 400, not called), and the chain moves on. It never speaks in another voice than the one asked.
   - Units: `characters`, the text's length. Priced per 1,000 characters at the catalogue's rate (D760): $0.015 (Aura 1) and $0.030 (Aura 2 EN and ES). `PRICE_USD_PER_1K_CHARACTERS` is a view of the catalogue's `characters` price, as the minute tables are of theirs.
   - **Partner models.** The three Aura models are Workers AI partner models. D760's gate (`AI_PARTNER_MODELS`, `modelRefusal`) refuses a run that can reach one, before any call, until the owner turns the switch on. PR 3 adds no gate of its own.
4. **MeloTTS** (`@cf/myshell-ai/melotts`).
   - Request: `{ prompt, lang? }`. The answer is `{ audio: base64 }`.
   - It has one voice per language and lists no speaker, so a run naming one is refused for it.
   - Units: `audio_minutes`, from the bytes it returned (`audioMinutesFromBytes`, the transcription's measure). Priced at the catalogue's $0.0002 per minute of audio, in `PRICE_USD_PER_AUDIO_MINUTE`.
5. **The audio.** `readSpeech` takes a stream, bytes, a buffer, or base64 (flat or under `result`). It stops at 10 MB (`MAX_SPEECH_BYTES`) and cancels the stream there. The mime type is read from the first bytes: WAV, else MP3.
6. **The hold and the charge.**
   - A voice is held for its text's characters (Aura) and for the most audio `readSpeech` accepts, 44 minutes (MeloTTS). That bound is what MeloTTS can return, so the actual never exceeds it.
   - It settles on the answering attempt's characters or minutes.
   - The guard checks the text as the run's input. There is no text output to check.
7. **Never cached.** The KV entry holds text, so a voice run has no cache key.
8. **A live stream's units.** `liveTranscription.settleStream` returns `units`, as `audio_minutes_websocket`: the minutes streamed on the Worker's clock (`shapes.websocketUnits`). They are priced per WebSocket minute (`PRICE_USD_PER_AUDIO_MINUTE_WEBSOCKET`), apart from a file's `audio_minutes`. The stream still settles through its holds and its receipt; a usage row for it is D762's.
9. **Timeouts.** A voice gets the long class, 30 seconds. Speech is produced for the whole text before it returns.
10. **The kind.** `INTERIM_KINDS` gains the four voices as `voice`. D760's catalogue is on `main`, but it does not yet answer `factsFor` through `setModelFactsSource`, so the interim tables still do.

### PR 4, as built

Each request is its model page's, or for FLUX.2 its launch notes (through the Cloudflare docs connector, 2026-10-19).

1. **What a run asks.** `RunOptions.draw` (`{ width?, height?, steps?, seed?, negativePrompt? }`) asks for an image of `text`, the prompt. It is a fifth input beside the others, still at most one per run, and the result carries `image`: `{ bytes, mime, width, height }`. No task class is added; D765's run path picks the task.
2. **Refused before anything runs** (`invalid_input`):
   - no prompt, or more than 2,048 characters (FLUX.1 Schnell's limit, the tightest a page gives);
   - a width, height or step count that is not a whole number above 0, a seed that is not a whole number, or a negative prompt that is not text;
   - a streamed image run, or one on a transcription route.
3. **The size and steps are clamped**, not refused, to each model's range (`IMAGE_SPECS`). The smallest side the Worker asks for is 256.

   | Model | Sent as | Size | Steps | Billed in |
   | --- | --- | --- | --- | --- |
   | FLUX.1 Schnell | JSON `{ prompt, steps, seed? }` | none sent; the model decides | 1–8, default 4 | tiles and steps |
   | FLUX.2 [dev] | multipart form | 256–1920, default 1024 × 768 | 1–50, default 25 (the page gives no range; 50 is the Worker's own bound) | output tile-steps |
   | FLUX.2 Klein 4B | multipart form | 256–1920, default 1024 × 768 | fixed at 4, not sent | output tiles |
   | FLUX.2 Klein 9B | multipart form | 256–1920, default 1024 × 768 | fixed at 4, not sent | megapixels: the first, then each further one, rounded up |
   | Lucid Origin | JSON, `num_steps` | 256–2500, default 1120 × 1120 | 1–40; 25 is sent (no default is given) | tiles and steps |
   | Phoenix 1.0 | JSON, `num_steps`, `negative_prompt` | 256–2048, default 1024 × 1024 | 1–50, default 25 | tiles and steps |

   FLUX.2 takes a multipart form even for a prompt alone. The Worker builds a `FormData`, and passes its serialised body and content type as `{ multipart: { body, contentType } }`. A negative prompt is sent only to Phoenix, the one model whose page takes it.
4. **The image.** `readImage` takes `{ image: base64 }` (flat or under `result`) or a stream of bytes (Phoenix). It stops at 10 MB. Its type and size are read from its first bytes (PNG, JPEG, or WebP: VP8X, VP8 and VP8L). Where they cannot be read, the size is the one sent.
5. **Units.** A tile is 512 by 512 pixels, each side rounded up. The units are counted from the size the image came back at, in its model's billing unit (`shapes.imageUnits`): `tiles` and `steps`, `output_tile_steps`, `output_tiles`, or `first_megapixels` and `subsequent_megapixels`. No input image is sent, so there are no input units.
6. **Prices.** `IMAGE_PRICED_MODELS` names the six. An image run's cost is the catalogue's own (`costMicro` over its units), so there is no figure to keep in step with D760. The router fails at load if the catalogue cannot price one of them in its billing unit.
7. **The hold and the charge.** The hold covers the size and steps sent to each model on the chain; FLUX.1 Schnell is held at its default of 1,024 × 1,024. The run settles on the units of the image that came back. The guard checks the prompt as the run's input; it cannot read an image (D763).
8. **Never cached**, as a voice is not.
9. **Partner models.** FLUX.2 (all three), Lucid Origin and Phoenix are partner models: D760's gate refuses a run that can reach one until `AI_PARTNER_MODELS` is on. FLUX.1 Schnell is generally available.
10. **The kind.** `INTERIM_KINDS` gains the six as `image`, so each gets the 60-second image class.
