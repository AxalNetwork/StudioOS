### 1. The Calendar tab (EV8, EV8w, EV17e)

`/admin/events/calendar` is its own route in `App.jsx`, under `guard(['admin'])` and before `:id`. It has a literal tab door in `AdminEventsPage.jsx`, so the reachability walk finds it. It reads what All events reads: R1, every page, and R2's rows under Guard G for the chip card's seats.

- **Where an event sits.**
  - An event is placed on the day, and at the time, its `starts_at` falls in its own zone, as every other line on the desk prints it. "Today" is the viewer's own date.
  - An event with no start is on no day. The tab says how many there are, rather than drawing them somewhere.
  - The map's §5 caveat still holds: the editor stores a time in the host's browser zone.
- **Month.**
  - Monday to Sunday, from the Monday on or before the 1st to the Sunday on or after the last day.
  - Each day shows three chips in start order. "+n more" opens the day, listing every event on it.
- **Week.**
  - A time grid from 08:00 to 20:00 at least, widened to the week's earliest start and latest end.
  - Events that overlap on a day sit side by side: each takes the first free lane, and the group shares the width.
  - An event with no end is drawn one hour long.
- **List.** The month's events in start order, each a 44 px link to the event's page. The phone (`max-width: 639px`) opens on List.
- **The chips and their legend (EV8):**
  - Published is plain.
  - Waiting for review is dashed amber, with the word "Review".
  - Draft and Sent back are muted, with the word.
  - Cancelled is struck through, with the word.
- **Overlap.**
  - A day where events clash gets an amber dot and "[n] overlap", where n counts that day's events that clash with another.
  - The rule is D915 §2's, in one place (`calendarModel.clashMap`): two events clash when neither is cancelled and their times overlap. An event with no `ends_at` lasts one hour.
  - Times are compared as the stored instants, so two events in different zones clash only when they truly overlap.
- **The chip card.**
  - It shows the title, the time line (`whenLine`), the seats under Guard G, any overlap, the status and "Open event".
  - Seats read "Seats 12 / 20" or "9 taken · No cap". When a count cannot be trusted, the card says why, never 0.
  - Focus moves to the card's heading; Close or Escape dismisses it.
- **The address** keeps the view, the month and, in Week, that week's Monday: `?view=`, `?month=YYYY-MM` and `?week=YYYY-MM-DD`. It also keeps the filters.
- **Filters:** Status (any of several), Visibility and Price, the same controls and the same test (`matchesFilters`) as All events.
  - When is the calendar itself.
  - Featured is not on EV8.
  - Type and Format wait for part 1, and Host for part 3.

### 2. All events made complete (EV6, EV17d)

Everything is worked out in the browser from R1 and R2, as D915 reads them. No read is added.

- **Filters:**
  - Status, any of several.
  - Visibility.
  - When: Upcoming and Past compare the stored instant with now. This week (Monday to Sunday), This month and a date range compare the event's own day with the viewer's dates, as the Calendar places it.
  - Price: Free is a price stored as 0, and Paid one above 0. An event with no price stored is neither.
  - Featured.

  The Overview strip's `?status=published` door still reads, as a one-status filter.
- **Views:**
  - **This week.**
  - **Full:** a cap above 0 with every seat taken. When the seat counts cannot be read, no event is counted Full, and the view says so.
  - **Needs attention:** only the reasons the page can work out, for events that have not started.
    - Full applies to published events.
    - Clash uses D915 §2's rule.
    - Low sign-ups uses D915 §2's rule, for published events: a capped event starting within 7 days with fewer than a quarter of its seats taken.
    - Without seat counts, only clashes are listed, and the page says that.
    - Overdue waits for part 2's `submitted_at`, and "Cancelled with paid tickets" for part 3.
- **Sorts:**
  - Starts is the canvas's default order: upcoming soonest first, then past events latest first.
  - Created is newest first.
  - Seats taken, Fill and Show-up are highest first. An event whose figure is not known (not held yet, no cap, or not in R2's rows) goes last, never sorted as 0.
- **Rows per page:** 25, 50 or 100.
- **The address** holds every choice except the search (`allEventsModel.readQuery`/`writeQuery`), and leaves the defaults out.
- **"Download table (CSV)":**
  - It holds the rows on screen (this page), in the table's own words, so an unknown reads as it does on the page.
  - It carries counts only: no names and no emails.
  - It is made in the browser with a `Blob`, so nothing is uploaded and no Worker is asked.
  - A cell a spreadsheet would read as a formula (starting with `=`, `+`, `-`, `@` or a tab) is prefixed with an apostrophe, because hosts type event titles.
  - None of `type="file"`, `.draft(` or `dd.generateReport(` appears (`rail_options_admin_d774`).
- **Phone (EV17d):**
  - Below `sm` the table gives way to cards, each a 44 px link: title, start and zone, status, and "taken / cap".
  - The filters fold behind "Filters · [n]".
  - Every control is 44 px tall there.
