## D8316 — Two Worker tests that failed in the first minutes of a UTC day (#8316)

- **Status:** built 2026-11-23. Repairs #8316 and #8318 (`grow_feedback_loop_6865`) and #8315 (`meeting_bot_operations_integration_d886`). Each failed once, a few seconds after 00:00 UTC, and passes on main at any other time.
- **Scope:** tests only. No Worker code changes.

### Causes

| Test | Failed at | Why |
|---|---|---|
| `grow_feedback_loop_6865` › revenue is recurring … (#8316, merge queue for #8213; #8318, #8289) | 00:01 UTC, twice | The expected `since` came from `NOW`, read when the file loads. The Worker reads its own now during the call. The shard ran for minutes, and the call took 44 s, so the Worker's day was one later: `2026-09-24` against `2026-09-23`. |
| `meeting_bot_operations_integration_d886` › canonical audio … (#8315, merge queue for #8214) | 00:00:33 UTC | The test runs on the real clock, because the router writes its own times. Its bot run is created two minutes before now. The report's `today` holds runs created since 00:00 UTC, so in a day's first two minutes the run is yesterday's: `today` held no run and its audio charge was 0, not 13001. |

### What changes

- **Grow:** the test reads the clock just before and just after the call. It accepts the day 60 days before either reading, because the Worker read its now somewhere between them. Both reads carry `clock-ok: relative`, as the file's `NOW` does.
- **D886:** the audio test reads the 7-day window, which holds a run from two minutes ago at any hour. It also asserts that the window holds exactly that one run. The other D886 tests use a fixed noon and still read `today`.

### Rollback

Revert the PR. Both tests can fail again around midnight UTC.
