## D5960 — A deliverable version's document can be a stored file (#5960)

- **Status:** built 2026-11-14 by S12. Filed under #4833 (Practice UX 5/6).
- **Board:** PX-06 of `design/incoming/Practice v2 Page.dc.html` draws "Document or URL · required" with a file. D4833 recorded that versions held a web link only.
- **Migration:** `202611141100_5960_deliverable_version_files.sql`. It adds five nullable columns to `advisor_deliverable_versions`: `file_key`, `file_name`, `file_type`, `file_size`, `file_sha256`. `ensureAdvisorStoresSchema` heals the same five on a store adopted by baseline.
- **Not in scope:** the frontend, and replacing or deleting a stored file, because versions are immutable (D4712).

### 1. Creating a version

`POST /me/deliverables` (the first version) and `POST /me/deliverables/:id/versions` take JSON as before, or a multipart form whose `file` is the document.
- **A new version (D4712)** still needs a change note and a document. The document is an https link or a file:
  - neither: 422 `empty_version`;
  - both: 422 `two_documents`.
- **The first version** may still have no document, as before: a title-only work product is allowed, and it cannot be sent until a version with content exists.
- **The file follows `company_documents.ts`:**
  - at most 10 MB (`MAX_UPLOAD_BYTES`; over it, 413 `file_too_large`);
  - not empty;
  - a PDF, JPEG or PNG by its first bytes (`sniffType`). A declared type outside those three is refused too (400 `file_type_invalid`). No other type was added; widening is the owner's call on #4833.
- **Bytes first.** Every check runs before anything is stored. The bytes then go to R2 `FILES` under `advisor-deliverables/<advisor>/<uuid>`, and the row is written only after the put succeeds.
  - A failed put is 502 `storage_failed`, with no row written.
  - A failed row write removes the object again.
  - An unbound `FILES` is 503 `storage_unconfigured`.

### 2. Send and mark-ready

`POST …/versions/:version/send` and `…/ready` accept a version whose document is a link or a stored file (`hasDocument`). A version with neither is still refused, 422 `empty_version`.

### 3. Downloads

- **`GET /me/deliverables/:id/versions/:version/file`:** the owning advisor's own version. Another advisor's deliverable gets `requireOwnDeliverable`'s 404.
- **`GET /received/deliverables/:uid/file`** (the version's uid): the account the version was sent to, scoped exactly as `/open` and the list are (D4684). Anyone else, and an unsent version, get the same 404 ("Work product not found").
- **Response:** an attachment, with the sniffed type, `nosniff` and `no-store`.
- **A recorded key whose object cannot be read** (missing, or R2 failing) is 502 `file_unreadable`, never an empty file.

### 4. What a version says

`versionDto`:
- **`document`:** `file`, `link` or null.
- **`file`:** `{ name, type, size }` (`fileOf`), or null.
- The R2 key and the hash are never returned by any route.

### Tests

`cloudflare-worker/test/advisor_deliverable_files_5960.test.ts` (5) runs on the migrated schema with an in-memory R2:
- a file, a link, neither, both, a plain-http link, and a first version with a file;
- too large, wrong type by bytes, wrong declared type, and R2 down, each leaving nothing in R2 or D1;
- send and ready on a file-backed version, still refusing a version with no document;
- the advisor's download, another advisor's 404, the recipient's download before sending (404) and after, a stranger's 404, and a missing object or failed read giving 502;
- no response carrying the key or the hash.
