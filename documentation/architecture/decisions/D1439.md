## D1439 — Social cards, Part B: record links preview as themselves (the Worker card injector)

- **Status:** built by the S10 session (#3914, Part B of #3705, 2026-11-01). It reaches production with the next Worker deploy. Draft PR.
- **Spec:** S1's design on #3705 ([comment 6541346543](https://github.com/AxalNetwork/StudioOS/issues/3705#issuecomment-6541346543), "Part B: Worker card injector").
- **Builds on:**
  - `SOCIAL_PREVIEWS.md` (the registry, prerender and card generator);
  - D529 (`docs/` is built, not committed);
  - D702 (profile visibility);
  - #3913 (#3705, the family keys `event`, `authors` and `profile` in the registry);
  - D1440 (#3915, the page-to-card map).
- **Migration:** none. No new table; every card reads existing rows.
- **Owner answers it rests on:** C (a), by S1's default: an unlisted event gets its record card.

### Why

A shared link to a record page (an event, article, job, profile, startup, partner, author or public insight) previewed as the **home** card. Those paths had no HTML of their own: the assets binding answered them with the SPA shell, whose head is the home page's. `SOCIAL_PREVIEWS.md` §6 named the gap and the fix.

### What was decided

1. **The Worker answers eight prefixes before Hono.** These globs are in **both** `run_worker_first` lists, as `[assets]` globs, never a path-scoped apex route:
   - `/events/*`, `/articles/*`, `/jobs/*`, `/u/*`;
   - `/startups/*`, `/partners/*`, `/authors/*`, `/insights/public/*`.

   `index.ts` `fetch()` hands them to `serveSocialCard` right after the `/assets/*` block and before `app.fetch`. The Hono middleware would put the nonce CSP and `no-referrer` on the shell. `SOCIAL_CARD_GLOBS` is the one list; `apex_route_coverage` holds the toml to it.
2. **Exactly one segment is a record.**
   - The SPA's own literal routes under these prefixes are pages, not records: `/events/new`, `/jobs/new`, `/articles/draft|mine|edit`, `/partners/onboard|portal`.
   - So is any deeper path, such as `/events/:id/manage`.
   - All of these go out as the shell, untouched, with no D1 call. `/insights/public/` takes one segment after its two.
3. **One bound read per kind, behind the page's own public gate. Never the route handler.**

   | Kind | Gate |
   | --- | --- |
   | event | `status='published' AND ((visibility='public' AND admin_published=1) OR visibility='unlisted')` |
   | article | `status='published'`, read without the article route, which counts a view and the day's count |
   | insight | `admin_publications` `status='published'`, with the page's slug pattern |
   | job | `status='published' AND admin_published=1` |
   | person | `publicPersonCard(env, handle, null)`: anonymous, so Members-only and Hidden are not found |
   | startup | `publicStartupCard(env, handle, null)`: archived, rejected and intake are not found |
   | partner | `DIRECTORY_LISTED_WHERE`, stricter than the partner page's own `status='active'` |
   | author | an active user with a published article, by id or by `authorSlugs` slug, as `GET /api/public/authors/:id` |
4. **What a card carries, and never carries.**
   - **event:** title; start time in its timezone; Online, In person or Hybrid; the summary. Never the price, capacity, seats or join link.
   - **article:** title, excerpt (or subtitle), author and read time.
   - **job:** role, venture, location and Remote. Never the pay band, even when the page shows it.
   - **person:** name and headline only.
   - **startup:** name, stage and the description's first sentence. No traction, no amounts.
   - **partner:** name, company and specialisation.
   - **Sizes:** the title is `<record> — Axal VC StudioOS`, within 70 characters; the description is cut at 200.
   - **Escaping:** every value is escaped.
5. **Images.**
   - **The record's own https picture first:** an article's cover (`/api/articles/cover/<id>`) or an https event cover. A record image drops the `og:image:width`, `:height` and `:type` tags, since its size and type are unknown.
   - **Otherwise the family card:** `event`, `articles`, `jobs`, `authors` or `profile`. The first key the registry knows wins, so until #3913 merges the section's card stands in (`content`, or the Axal `default`), as S1's spec allows.
6. **A miss looks exactly like a private record.** Both get the section's card (`/events`, `/articles`, `/jobs`, `/authors`, or the Axal default for people, startups and partners), byte for byte, with `x-robots-tag: noindex`. A card never confirms that a record exists.
7. **Failure is the old behaviour.** On a D1 error, after 1.5 s, or when the assets answer is not `200 text/html`, the shell goes out untouched.
8. **The shell's headers come from one constant.** `_headers` is not applied to a Worker response, so `SHELL_HEADERS` sets the same five values:
   - HSTS;
   - nosniff;
   - `X-Frame-Options: DENY`;
   - `strict-origin-when-cross-origin`;
   - `Permissions-Policy`.

   A test holds the constant to the file. The Worker CSP is never set. The shell's `cache-control` is kept, and its `etag` and `content-length` are dropped, since they describe other bytes. HEAD answers the same headers with no body.
9. **The rewrite replaces the generated block, not tags one by one.** `prerender-og.mjs` writes the shell's tags between `<!-- BEGIN og:managed -->` and `<!-- END og:managed -->`. The injector replaces that block with the record's, in the same format, and leaves every other byte (every script and link tag) as it was. This is a deviation from the spec's `HTMLRewriter` handler. The block is generated and delimited, so a string replacement does the same job and runs in the Node test suite, where `HTMLRewriter` does not exist. A shell without the block goes out untouched.
10. **The registry is shared, not copied.** `socialCards.ts` imports `frontend/src/lib/ogRegistry.js` (typed by a new `ogRegistry.d.ts`) for the site name, the section cards and the cache-busted image URLs. There is no second registry.
11. **`PublicInsight.jsx` uses `usePageMeta`.** It replaces its inline tag code and its own brand strings ("Axal VC Venture Studio"), so the tab and a link preview agree. The hook is mounted once the publication has loaded, so its pageview beacon fires once.

### What it cost

- Every page load under the eight prefixes now runs the Worker: one assets fetch and at most one or two D1 reads for a record path, and none for a reserved one.
- The 1.5 s deadline bounds a slow read; the page itself never waits on more than that.

### Not done here

- **Part C:** the family art.
- **`/advisors/:uid`:** its anonymous gate is unconfirmed, so it keeps the home card.
- **`scripts/check-spa-live.mjs` with live records:** it now checks `/events/<slug>` and `/jobs/<slug>` (with `/articles/<slug>`) as card shells: the static headers, and an `og:title` that is not the home card's. The default slugs are no record, so a miss's section card is what is checked. `SMOKE_EVENT_SLUG` and `SMOKE_JOB_SLUG` point it at live records; this session cannot read production to pick them.

### Part D: token share links get the "Sign in to view" card (#3916, 2026-11-01)

Built by S26 for slot S10's issue, at the owner's request. The owner answered question B on #3705 with (a): token share links get the private card, and signed-in deep links keep the home card. No migration.

1. **Five more `run_worker_first` globs, in both lists:** `/esign/*`, `/deck/share/*`, `/share/*`, `/invite/*`, `/join/*`. They are `[assets]` globs, never a path-scoped apex route. `socialCards.ts` exports them as `PRIVATE_LINK_GLOBS`, and `frontend/test/apex_route_coverage.test.mjs` holds the toml to that list.
2. **One static card for every token link (SC8):**
   - title "Sign in to view";
   - description "This link opens a private page on Axal VC.";
   - image `/og/private.png?v=<hash>`, drawn in #3913, with its 1200×630 size tags;
   - `x-robots-tag: noindex`;
   - the shell's own headers, as for a record card.
3. **No record read and no D1 call.** The token is never looked up, so a preview never says whether a link is live, expired or revoked. The branch runs before the D1 check, so it is served even with no D1 binding.
4. **The token never appears in a tag.** `og:url` and `canonical` are `https://axal.vc`, not the request path, so every token link previews with the same bytes.
5. **A link is a prefix with something after it.** Any depth counts (`/share/captable/venture/<token>`). A bare prefix (`/share/`) reaches the Worker but is not a link: the shell goes out untouched. Only GET and HEAD are carded.
6. **`/verify/*` is not covered.** Certificate verification keeps the home card unless the owner makes it public.
7. **`/share/lab-report/:token`** is inside `/share/*`, so it gets the private card too. Its page also asks the reader to sign in.

**Cost.** Every page load under the five prefixes runs the Worker for one assets fetch, with no D1 call.

**Checks.** `cloudflare-worker/test/social_cards_d1439.test.ts` tests 14 to 16:
- every token prefix returns the private card, byte-identical across prefixes and tokens, and a spy on `env.DB` sees no access at all;
- every one sends `noindex` and the shell's headers;
- the token is nowhere in the page, even when repeated in the query;
- bare prefixes, `/verify/*` and lookalikes (`/joinx/`, `/shared/`, `/deck/<x>`) are not token links;
- a POST is not carded.

Each assertion was mutation-checked both ways.
