- **Status:** built by S09, 2026-10-26 (#3342, part of #2456).
- **Basis:** `origin/main` at `8c52a17f0c`.
- **Migration:** none. **Worker:** no change. The read is D1104's `GET /api/data-room/:projectUid/requests`, already on `main` and already used by the Requests tab: `{ requests, open, can_answer }`.

### The gap

Data room › Home's Needs you always said "Access requests are not read here yet: they have no single queue until part 3 (D1104)". D1104 had closed, and its queue was already read by the Requests tab.

### What Home draws now

Home reads the requests on their own read, so a failure there blanks only that line:
- **Open requests, for the venture's owner** (`can_answer`): "2 access requests wait for your answer", with "Share the room or decline, on Requests." and a link to Requests.
- **Open requests, for anyone else** (a co-founder): "3 access requests open", with "The venture's owner answers them. You can read them on Requests." It is information, not a task.
- **None open:** "No access request waits."
- **A failed read,** or a reply with no count: Unreadable with Try again, "This is not a claim that nobody asked." The rest of Home still draws.

The room's own items now say "Nothing in the room's files or access waits on you.", so they no longer contradict open requests.

`REQUESTS_WAIT` is removed from `filesModel.js`. Its rule is `requestsNeed`.
