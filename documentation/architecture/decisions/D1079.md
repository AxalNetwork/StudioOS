### 1. The page: HQ › Security › Trust center content

`/admin/security/trust-center`, `pages/hq/TrustContentPage.jsx` and its pure model `trustContentModel.js`.

- **Only a Super Admin reaches it:**
  - The route sits behind `hqOnly` (`App.jsx`), so an admin without the elevation sees `SuperAdminOnlyNotice` instead.
  - The Worker refuses its read to anyone else (`requireSuperAdmin`), and every write meets the write bar (`requireSuperAdminWriteBar`).
  - A lapsed step-up is `api.js`'s StepUp prompt. A cancelled one says nothing changed.
- **The door:** HQ Security's header, beside Trust obligations by role.
- **The header (TRU14):**
  - It shows "Security › Trust center content", "HQ only" and "What the public trust center shows. Visitors see a change only after you publish it."
  - **Publish changes** opens TRU14d. It is shut while nothing has a draft.
- **Blocks:** the seven, in the canvas's order.
  - Each shows "Last published [day]", or "Never published". Certifications reads "none held" when its published copy has no item.
  - A block with a draft carries a Draft pill.
  - Choosing one opens its editor on the draft, else the published copy, else an empty block.
- **A lines block** (six of the seven) has an introduction and groups of lines.
  - A line is a fact with the day it was checked, or "Not recorded" with the reason it is a gap.
  - **The Worker's refusals are said before a draft is sent,** in the Worker's own sentences: a line without its words, a line over 500 characters, a gap without its reason. A gap keeps no date and a fact keeps no reason, as `parseBody` stores them.
- **Certifications:** each item has its name, auditor, issue day and optional expiry.
  - Add opens only once the auditor's report is attached: a PDF, sent to `POST /reports`, which answers its uid.
  - The draft carries that uid. Visitors never see it (D1075 §2).
  - An empty list is "None held".
- **Saving:** **Save draft** writes the draft and says "Visitors see it after you publish". Discard draft asks first, and the published copy stays.
- **Subprocessors · editing:** the table has the canvas's columns: Company, What they do for us, Data they see, Where and Since.
  - **A draft** can be edited or deleted. Since reads "10 days after you publish", or its chosen day.
  - **A listed one** can be removed. It stays listed until Publish.
  - **One being removed** can be kept.
  - A removed one is history and leaves the table.
  - Add a subprocessor is a dialog, as is every remove, delete and keep. None uses a browser pop-up.
  - The line under the table says when subscribers are emailed: on Publish. The canvas's "emailed now" is not what the Worker does.
- **Changes to this page:** the latest 50 published changes, each with its day, its blocks and its note.
- **A failed read** is Unreadable with Try again, never an empty editor.

### 2. Publish (TRU14d)

- **"Publish?"** and its first line:
  - how many blocks change, with Subprocessors counted once when its list changes;
  - who is emailed, from the confirmed-subscriber count. When there are none, the line says no one is emailed.
- **The list:** each block whose draft goes live, each subprocessor added with the day it becomes active, and each one removed.
  - **The active day** is the later of its own start day and ten days after today (`activeFrom`), the rule `publish` applies (D1075 §3).
- **The change note** is required. Publish stays shut until it is 10 to 1000 characters, trimmed, and the field counts them.
  - **The Worker refuses a note outside those bounds too** (`parseNote`, 400 `note_required`). Its sentence is said in the dialog, which stays open, and nothing is claimed published.
- **When Publish answers,** the page reads again and says "Published.", with the note under Changes to this page.

### 3. SECURITY.md and security.txt

- **The Hall of Recognition** at `axal.vc/security/hall` is gone, because no such page exists. With the researcher's permission, credit is given in the advisory that announces the fix, as Coordinated disclosure already said.
- **The in-app report** said a footer link existed. Now it says what is true:
  - D1075 §6's store exists: Help's Security category, `POST /api/help/security-reports`. It is encrypted, read by HQ's Super Admins only, and never a ticket, a GitHub issue or a Slack post.

- **"Material changes will be announced via the GitHub repository and the in-app Trust Center"** became the truth:
  - every change to the file is in the repository's history;
  - each change HQ publishes to the public trust center is dated and kept with its note in the change log (`GET /api/public/trust/changes`).
- **The header** names `https://axal.vc/trust/disclosure` as the public policy page, and the date moved to 2026-10-25.
- **`frontend/public/.well-known/security.txt`** gains `Policy: https://axal.vc/trust/disclosure` (RFC 9116 §2.5.7).
- **The public Disclosure tab's PGP line** (`site/trustCenterModel.js`) said "Ask by email and we reply with one", the old promise. It now says none is published and to use the private advisory, so the page and the file say the same thing.
