## D7074 — Agent capacity from the task list and the budget: sub-agent lanes and elastic scopes (#7074)

- **Status:** built 2026-11-17, switched off until HQ sets a ceiling. The Worker, its migration and its tests are in this change. The screens are #7078. Part of #7072.
- **Builds on:** D1528 (admission in the scope's object, the single-flight index, the review backlog stop, the daily limit), D4162 (HQ's AI policy and its per-run ceiling), D4592 (the fair sweep).

### Why

The engine stopped at numbers that had nothing to do with how much work a team had or what it could pay for:

| Limit before | Where it lived | Now |
|---|---|---|
| 1 live run per agent | a unique index | 1 per agent **and lane**; a team sets `lanes_per_agent` |
| 1 to 5 live runs per team, 2 by default | a CHECK | the same in `fixed` mode; `elastic` mode goes to the team's `elastic_max_runs` |
| admission stops at 5 proposals awaiting a decision | a constant | `review_backlog_max`, 5 when unset |
| 20 runs per agent per UTC day | a constant | `daily_runs_per_agent`, 20 when unset |

A team that sets nothing has exactly the rules it had.

### Sub-agents are lanes

An agent may hold several live runs, one per lane. Lane 0 is the agent. Lanes 1 and up are its sub-agents.

- **A sub-agent is the same agent row.** It has the same role, rule book, sponsor, tools, model and monthly cap. Nothing new is created or granted, so no gate has a second place to be checked. This is owner decision A1 on #7072.
- **`agent_task_runs.lane`**, and the single-flight index is now on `(agent_id, lane)` for live runs. Admission takes the lowest free lane.
- **One task is still one run.** A task leaves `open` when it is admitted, so it cannot be admitted on a second lane.
- **A lane is free once its run awaits a decision**, as an agent was before: `waiting_decision` was never a live status.

### A sub-agent must fit under the cap

`agentRun` refuses a run once the month's spend reaches the agent's cap. That check reads settled charges, so several runs live at once could each pass it and together overshoot. Admission therefore checks a second lane before it starts:

```
cap − spend this month − (live runs × per-run ceiling) ≥ per-run ceiling
```

- The per-run ceiling is HQ's (D4162): the most one run may hold. It is the only bound on a live run's cost that exists before the run settles.
- **No per-run ceiling, no sub-agents.** Without it one run's cost has no bound, so HQ cannot offer sub-agents until it is set, and cannot clear it while they are offered (409 `lanes_need_run_ceiling`).
- An unreadable spend covers nothing. It is never read as zero.
- A lane that does not fit is refused 409 `lane_budget`. Nothing is paused; it starts when a run finishes or the cap is raised.
- The agent's own run (lane 0 with nothing else live) is admitted as before. `agentRun` still holds its cap, the sponsor's hold and the per-run ceiling on every run, sub-agent or not.

### Elastic scopes

`agent_scope_settings.capacity_mode` is `fixed` or `elastic`.

- `fixed` reads `max_parallel_runs`, 1 to 5, as before.
- `elastic` reads `elastic_max_runs`, or HQ's ceiling when that is unset.
- **The task list is the demand.** Only a ready task is ever offered for admission, so an elastic team with three ready tasks runs three, whatever its limit.
- **The budget is the limit that matters.** Every run takes its own hold on its sponsor's tokens, every agent has its cap, and every sub-agent lane must fit under that cap.

### HQ's ceilings

Two columns on `ai_agent_policy`: `elastic_runs_ceiling` and `lanes_ceiling`. `PUT /api/admin/ai-agents/policy/capacity` sets them, Super Admin only, with a reason and an audit row like every policy write.

- **Null means not offered**, and both are null on every database until HQ sets them. This is owner decision B1 on #7072: production does not change with this merge.
- **A ceiling is read at admission, not copied into the team's row.** A team whose row says elastic or four lanes reads as fixed with one lane while HQ offers neither. So withdrawing or lowering a ceiling takes effect at the next admission, with no rows to rewrite.
- A team's manager sets the team's own numbers on `PUT /:scope/:id/engine`, never above the ceiling: 403 `elastic_not_offered` or `lanes_not_offered` while nothing is offered, 400 `invalid_engine` above it.
- A scope on the defaults reads no ceiling at admission, so the common path makes the same queries it made before.

### Capacity follows the task list

- **`after`** (a decided run) offers the agent one ready task per lane, in priority order, until admission refuses one. With one lane that is one task, as before.
- **`propose`** now does the same for a scope whose capacity is elastic or has sub-agents: the lane is free, so it is refilled at once. A scope on the defaults waits for the decision or the sweep, as before. Owner decision C1 keeps the review backlog stop, so a team's reviewers still bound how far this runs ahead of them.
- **The sweep** offers an agent as many ready tasks as it has lanes free, where it offered one task to an agent with nothing live. Its other bounds (60 admissions, 120 candidates, 4 per scope) are unchanged; raising them is #7077.
- All of this needs `AGENT_AUTONOMY=self_start` and the engine `on`, as before. With `manual`, a person starts every run.

### What did not change

A person still decides every proposal. The kill switch, the platform halt, the scope pause, the canary and cohort modes, the per-run ceiling, the monthly cap, the sponsor's holds and plan, the rule book's modules and options, and the tool grants are all checked where they were.

### The migration

`202611170130_7074_agent_capacity.sql` adds `agent_task_runs.lane`, replaces `idx_agent_task_runs_live` with the per-lane index, and adds five columns to `agent_scope_settings` and two to `ai_agent_policy`.

- Deploy order does not matter. A Worker from before this change inserts runs with no lane, which is lane 0, and the new index then holds the old rule.
- The Worker reads settings with `SELECT *`, and writes the old statements when no capacity field is named and for lane 0. So it also runs against a database the migration has not reached.

### What this does not do

- **The screens.** `GET /:scope/:id/engine` returns `capacity` (what the team set, what HQ offers, what is in force). Drawing it is #7078 and needs a canvas.
- **Dispatch.** The queue's concurrency, the Workflow starts per batch and the sweep's bounds cap how fast admitted runs start. That is #7077.
- **A platform-wide model budget.** Workers AI's requests a minute are shared by every team. Fair sharing of it is #7077 and #5586.
- **Compute leases.** A run that needs a container or an outside executor also needs a lease (#5570, #5571). Their admission should pass through this one.
- **A sub-agent with its own cap** (decision A2), if the owner prefers it.

### Tests

`cloudflare-worker/test/agent_capacity_7074.test.ts`, 19 cases over the migrated schema with the real admission, task loop, sweep and routes:

- the rules as pure functions, and the schema's index and CHECKs;
- the defaults unchanged, with no read of HQ's ceilings;
- lanes: lowest free first, busy when all are held, a lane freed at `waiting_decision`;
- the lane budget: an exact fit, a miss, spend counted, an unreadable spend, the agent's own run unaffected;
- what HQ does not offer is not in force, and a withdrawn ceiling applies at the next admission;
- elastic past the fixed five and never past the ceiling;
- the review backlog and daily limit as settings;
- `after`, `propose` and the sweep filling free lanes, and none of it on the defaults;
- both routes, their refusals and the audit rows.

Twenty-two mutations were run against the file; each fails at least one case. One existing assertion changed: `agent_engine_d1528.test.ts` pins the engine response, which now carries `capacity`.
