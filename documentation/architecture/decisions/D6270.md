## D6270 — The investor's room and file pages, built to the Rooms canvas (#6270)

Builds boards IRV-03 and IRV-04 of the Investor Research v2 Rooms canvas (D6268, owner's answers in D6268-p2) on `/research/diligence/:grantUid` and its file page. Frontend only: the Worker already sends everything used here.

### One room component

The room's files are `frontend/src/pages/deal/SharedRoomFiles.jsx`, the component the deal's Data room tab already mounts (DE10, #5907/#6880, D6185). There is no second room component. It gains optional props, and the deal tab passes none of them, so its rows are unchanged:

- `grouped`: files run folder by folder in the read's folder order, each under its folder's heading. A file outside every listed folder is last, under "Not in a folder". `roomFilesQuery` does the ordering (`grouped`), after its own sort, so each group keeps the chosen sort.
- `fileLink`: a file's name links to its page, with the folder carried in router state. The row's Open (download) button is not drawn.
- `onOpen`: a search hit opens the file page.
- `addedLabel` and `rowExtra`: "Staged" before the date, and the room's New pill, NDA pill, last link issued and Library cell (D6913).

Both doors also gain a "Not in a folder · N" folder filter whenever the listing has such files (`LOOSE_FOLDER`). `roomListing` already counted them as `loose`; nothing drew them.

### Search

The shared `DataRoomSearch` in its `shared` mode (`POST /api/data-room/shared/:projectUid/search`) is mounted by the shared component, as it is on the deal tab. A hit is drawn only if its `file_uid` is in the listing (`allowedFileUids`), and it opens that file's page.

### What a withheld file never becomes

The worker never sends a withheld file's name, so names are already absent. The room also drops any folder that lists no file before drawing. A folder holding only withheld files therefore has no heading and no count to stand for them. The NDA count stays a count.

### New since your last visit

`stagedSinceLastVisit(created_at, last_opened_at)`. `last_opened_at` is read before this visit is logged, so it is the visit before this one. A file is New when it was staged strictly after that visit. A first visit, or a file with no staged date, is `null`: nothing is marked New, and the line says "This is your first visit, so no file is marked new."

### NDA

The room read's `nda` (D6267) is shown in the canvas's words: No NDA, NDA out for signature, or NDA signed (on file, with its end date or "no end date recorded"). A read without `nda` is Not recorded, never No NDA.

The room read carries no envelope, so "Review and sign" links to the deal's Data room tab (`tabHref(deal.id, 'documents')`), where Sign NDA and the envelope live (DE10). It is drawn only when a deal on the company is open to the reader (the room's `deals`, D6266) and the NDA is not on file. With no such deal, the page says where an NDA is signed instead of drawing a link to nowhere.

### Removed

- The in-page "Open the room →" anchor. The canvas draws none, and the page is the room.
- The one-row scope table. The canvas keeps the tiles and drops it.

### File page

About this file shows:
- **Staged on**: the file read's `created_at`.
- **Folder**: carried from the room, as the canvas draws it. The file read names no folder, so a direct link says "Shown when you arrive from the room".

Previous / next is not built.

### Memo

`ZoneDraft` gains `acceptedActions`, drawn only while the draft is accepted and not being edited. Every other mount passes nothing and is unchanged. The room passes Copy (clipboard) and Export, a `.txt` file named `room-memo-<company>-<day>.txt` built by `memoExport`. Export uses the accepted body under a one-line head that names the company and when it was accepted.

### Phone

At 390px nothing scrolls sideways:
- File rows stack below `md` (the shared component).
- Activity and download-history rows stack below `sm`.
- The room and file pages have no table and no fixed minimum width.
