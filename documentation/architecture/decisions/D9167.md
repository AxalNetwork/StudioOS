## D9167 — Every LIKE search is escaped and trimmed to D1's 50 bytes by one helper (#9167)

- **Status:** built by S08 on #9167, 2026-11-27.
- **Extends:** D128 (`cloudflare-worker/src/util/likeSearch.ts`, the one escaper).

### The problem

D1 refuses a `LIKE` pattern longer than 50 bytes with `LIKE or GLOB pattern too complex`. It does so only once a row is compared, so a search answered 500 on a live table and 200 on an empty one. With one published event, `GET /api/public/events?q=<49 × A>` (no login) returned 500. Multibyte text hit the limit at 16 CJK characters. The local D1 (Miniflare, workerd's SQLite) draws the same line: a 50-byte pattern answers, a 51-byte one fails.

Patterns were built in more than forty places. D128's `likeNeedle` escaped `%` and `_` but not `\` and did not cap the length. At least nine more local copies existed (`likePattern`, two `likeTerm`s, two `likeLiteral`s, several `likeOf`s, `likeContains`, `contractLike`). Eleven sites bound user input with no escaping at all (`%${q}%`, `'%' + email + '%'`), two stripped the wildcards instead of escaping them, and six built them in SQL (`LIKE '%' || ? || '%'`). The Security ledger used a second escape character (`!`).

### What was decided

**Trim, not refuse.** `util/likeSearch.ts` escapes `\`, `%` and `_` for `ESCAPE '\'`. It then cuts the term at a whole character so the whole pattern fits in `LIKE_PATTERN_MAX_BYTES` (50), wildcards and escape characters included. It cuts at a code point, never half a UTF-8 sequence or a surrogate pair, and never between an escape and the character it escapes. A trimmed search still answers: it matches every row the full term would, and possibly more. A 400 would have turned a long paste into an error for no gain.

- `likeNeedle` / `likeNeedleLower` give `%term%`; `likePrefix` / `likePrefixLower` give `term%`. The lower forms lower-case before measuring, because lower-casing can change the byte length (`İ`).
- `likeNeedleWhole` is for a value that identifies someone: the signed-by email on `/api/trust/agreements`. It returns `null` rather than trim, because a broader match there is another person's row. A blank email used to bind `%%`, which matched every signed document; that now reads nothing.
- Every search site under `routes/`, `services/` and `rpc/` binds the helper's output with `ESCAPE '\'`. The local copies are gone or call the helper. The Security ledger moved from `ESCAPE '!'` to `ESCAPE '\'`, so there is one escape character.
- Internal prefixes that can outgrow 50 bytes no longer use LIKE. They compare `substr(col, 1, length(?)) = ?`: the flow-cancel hold key, `ai_credit_ledger`'s `adj:deck-refund:<uuid>:` (54 bytes as a pattern, so the batch refund read failed once any adjustment row existed), and the two `interview_channel_refs` `external_ref:` prefixes. Short fixed prefixes (`raise:${id}:%`, `${projectId}/%`) stay as they are.

**The guard.** `scripts/check-like-patterns.mjs` (in `scripts/guard-commands.json`) reads `cloudflare-worker/src/**/*.ts`, except the helper. It fails on four shapes: a raw wildcard template (`%${…}%`, `%"${tag}"%`), a concatenated leading wildcard (`'%' + q`), wildcards built in SQL (`LIKE '%' ||`) and a local escaper (`.replace(/[\\%_]/g, …)` in any spelling). On `origin/main` it reports 67 findings in 49 files; on this branch, none.

### Verified

- `cloudflare-worker/test/like_pattern_cap_9167.test.ts` checks the byte math: ASCII, CJK, emoji, a term that would end mid-character, escaping, and the prefix, lower and whole forms. It then runs on Miniflare's local D1, after first proving that this engine refuses 51 bytes. With a seeded row, a 60-character ASCII term, a 30-character CJK term, emoji and a run of `%_\` on `/api/public/events` all answer 200, and the trimmed search still finds the row. A 60-character and a 30-character CJK search on `/api/admin/users` answer 200 and find the account. This is the local engine, not production D1.
- `frontend/test/like_pattern_guard_9167.test.mjs` checks each guard rule and the clean tree.
- Mutation check (both files): 13 mutations, 13 caught, 0 equivalent.

### Not built

- No search box changes. A trimmed term is not reported back to the caller.
