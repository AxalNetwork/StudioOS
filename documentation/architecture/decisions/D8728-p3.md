## D8728 part 3 — Admin Studio's way back from any control, a crumb that lasts the visit, the branch row lit, and the first browser pass (#8728)

Part 1 is `D8728.md` (the canvas and the owner questions); part 2 is `D8728-p2.md` (the build). This part closes what part 2 left between the canvas and the shipped page, frontend only, still on option A of each open question.

- **Status:** built. ⚑ Q1, Q2 and Q3 are still open with the owner; this part follows option A of each, as part 2 did. The territory scope of the count and of the filtered Inbox still cannot be checked on a real role until #8688 provides a restricted test territory and its Admin.

### What changed

- **Back returns to the control that left (SAD04, SAD20).** Part 2 noted the scroll and focus only for "Review overdue in Approvals". Every link the overdue card has into Approvals is now a `StudioLink` (`StudioOverdueCard.jsx`): each lane line ("Lane: {label} →", id `studio-overdue-lane-{key}`), the on-time line's Open Approvals, the unavailable card's Open Approvals →, the zero card's Open Approvals and the all-clear card's See what was decided. Each sends Studio's router state and notes its own id, so Back, the crumb or "‹ Studio" puts focus on that control. When it is gone because the queue changed meanwhile, focus still lands on the "Needs a decision" heading.
- **The crumb lasts the visit (SAD03, SAD13 L6).** Part 2 kept the router state when a chip changed, but opening an item dropped it, and so did closing the item or stepping to the next one, so "Studio › Approvals" disappeared. The item links (the row's name, Review, the phone card's name and Open, the drawer's ‹ and ›) and `closeItem` now pass `keepStudio(loc.state)`: Studio's marker only, never other router state. A direct visit still has no crumb.
- **The landing's count is a live status, and focus never falls to the page (SAD13 L1, L4, SAD20).** The count after the chips is `role="status"` (`resultCount` in `ApprovalsInbox.jsx`). It says "Reading…" while the read runs, "1 result", and "1 result · 19 of 20 lanes" when a lane did not answer. Removing the last chip, or Clear all, moves focus to Filters, which stays on the page.
- **⚑2 A, the branch sidebar row.** On a branch, the sidebar's Approvals row (`/branch/approvals`) now also lights on `/admin/approvals`, where Studio's count lands. `sidebarConfig.js` gives it `match: ['/branch/approvals', '/admin/approvals']`. HQ's row already pointed at `/admin/approvals`.
- **"Past the window" is retired on Studio (SAD21).** Part 2 dropped the band word but the Approvals tile's line under At a glance, and the Admin pages card, still read "… · oldest 4 days · past the window · 1 open". Part 2's test checked only the capitalised "Past the window". The first browser pass caught it. `approvalsGlance` now prints the total only (the lane's `sla` still rides along for the worst-first order), and the HQ Approvals card on Admin pages says "overdue", the Inbox's word, where it said "past the window".

### The browser pass

`frontend/tests/visual/admin_studio_8728.spec.mjs` runs the acceptance fixture in Chromium at 1440 × 900 and 390 × 844, against the built SPA, with every read answered in the spec. The fixture is a branch admin of a made-up territory, one overdue item and two on time, and 0 of 11 answers. The spec checks that "Needs a decision" and its action sit in the first screen ahead of Setup, at about 195 px on desktop and 187 px at 390 (the walkthrough measured 1,293 and 1,866). The action opens `?age=past` with the crumb ("‹ Studio" on a phone), the Age chip, "1 result", the territory chip and the lit branch row. Browser Back returns to Studio with focus on the action. An empty territory is all clear, an unreadable queue is never 0 or all clear, and no page is wider than the phone in light or dark. It draws no baseline.

### Departures from the canvas, still

Part 2's departures stand: no territory header with a read time, no per-lane ages on the on-time line, the "waiting" wording of the hidden line, the narrower all-clear card, "Retry" on the shared Unavailable, the computed At a glance order and no separate back link on the empty landing. This part adds none.
