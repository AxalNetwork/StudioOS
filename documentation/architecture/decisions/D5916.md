### What is built

- **The header** is the canvas's: Deal flow, "Every active round, who owns it, who is engaged and what needs attention.", and the Board and Table switch beside it. **The Table is the default** (`/deals`); the Board is `/deals?view=board`.
- **The stage strip:** In intake, Screened, Raising, Funded and Not raising, each the number of rounds the read returned in that status. Each tile is a link that filters the rows (`?round=<status>`, Not raising keeps `?round=not_raising`); the Not raising pill of D1242 is now the strip's last tile.
- **Needs attention**, counted over every round the read returned (never over a filtered view), each chip a link to `?attention=<key>`. Only an open round (In intake, Screened, Raising) carries one; a Funded or Not raising round needs no owner and is not stale.
  - **No owner:** no lead partner is recorded (`lead_partner_id`).
  - **Stale:** `days_in_stage` is in the red band of the viewer's Stage SLA (`lib/dealFlow.slaBand`), the same SLA the picker below sets. An unknown age is not stale.
  - **Terms missing:** a Screened or Raising round with no ask (`target_raise` or `amount`), no `instrument` or no `minimum_check`.
  - A zero is a count the read backs, so it shows, but it is not a link.
- **Left out, with no field behind them** (as #5916 asks):
  - **Investor waiting.** The read counts `interested` invitations, but an interested invitation's next step is the investor's (ask for the data room, then commit), and no field records an investor waiting on the studio.
  - **Closing blocked.** The read carries no closing checklist or blocker; the closing checklist is its own read (`deals.ts`), and counting it here would need a new read per round, which is a Worker change this slice does not make.
- **The table's columns** are the canvas's: Company, Round status, Scorecard, Lead, Investors, Ask, Committed, Source, Days, Attention, then the row's actions; Not raising adds Set by.
- **Row actions:** Advance is the row's own button; More (⋯) holds Pass…, Invite investors and Edit terms. An admin may move every round. An Operating Partner reads the same rows and counts, and sees Advance and More only on a round whose `can_move` is true (the rounds they lead); Invite investors stays an admin's. An admin's table carries the canvas's foot, "Operating Partners see the same table; actions appear only on rounds they lead."
- **States:** while the rounds are read, the strips and the rows are drawn as skeletons in their own shape; a failed read draws neither strip (never a zero) and says Unreadable with Try again, and the panels below still draw.
- **Phone:** below 1024px (`usePhoneWidth`) the table's rows are cards, so no table is wider than the screen; the strip is three tiles across, chips wrap, and every control is at least 44px below 768px.
