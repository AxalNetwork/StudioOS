### What it decides

- **People is the fifth Network link, after Overview, on every licence** (D7676 Q1, answer A). It is the first zone of `NETWORK_ZONES` in `frontend/src/workspaces/shellConfig.js`, and the founder's Network desk lists it first. Its routes are `/network/people` and `/network/people/:uid` in `frontend/src/routes/networkPeople.jsx`, both rendering the Network workspace on the People zone so the list stays mounted while a sheet opens and closes.
- **Counts are the server's.** The status line, the scope button and the pager all show `total` from `GET /entries`, which is counted under the same WHERE as the page. While it loads the line reads "Counting…", after a failed read "Unavailable", never 0.
- **The address holds the list.** `q` is the search and `c` the trail of cursors that reached the page on screen, so Previous, a reload and a copied link land on the same page. The sheet's address keeps the same query, and closing it returns to the list's address; the shared `Sheet` returns focus to the row link that opened it.
- **Four states stay apart** (`pages/network/directory/useDirectoryPage.js`): loading, ready, a failed first read (Unavailable with Try again, never an empty list) and a later page that failed (the last good page stays with its total, and "Try page n again").
- **The private area is the viewer's alone.** It reads and writes only `/entries/:uid/overlay`, which the Worker keys to the caller in every statement. Saved and the private note save through `PUT` and clear through `DELETE`; a support session's 403 `support_session_refused` is drawn as Refused with "A support session cannot read or change this member’s private relationship." and no control.
- **The shared pieces are reused by #9071** (Organizations, D7680): `useDirectoryPage`, `DirectorySearch.jsx` and `PersonSheet.jsx` take `kind`, a context bar and an organization link, so the organization directory reads the same route the same way.
