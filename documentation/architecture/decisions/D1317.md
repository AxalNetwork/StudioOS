### 2. The secret

- It exists only in the 201 body of create and rotate. The page holds it in one state slot (`reveal`)
  while the reveal dialog is open, and drops it on Done, on close, on any change of the drawer address
  and on unmount.
- `RevealDialog` is the only component that draws it: one read-only field, `autocomplete="off"`,
  `spellcheck="false"`, `data-private` and `ph-no-capture`, named "API key, shown once". It is never
  page text and never in an `aria-live` region.
- After Copy the field shows the prefix and four dots, Copy is disabled, and nothing brings the secret
  back. The clipboard is not cleared, since that could wipe something else the member copied.
- Done waits for "I have stored this key somewhere safe". Closing early asks first ("Go back" or
  "Close").
- A rotate opened from the drawer moves to the new key's drawer only after Done, so the secret is never
  on screen while the address changes.
- No file of the page writes storage, logs, reports an error or tracks an event. The tests hold that no
  console call, storage write or request carries a string of the secret's shape.

### 4. Owner questions, as built

1. **The name:** "API keys" (D1315 already named it).
2. **Default expiry:** 90 days, with 30 days, 1 year and Never; Never warns in amber. The Worker's
   ceiling is 365 days, so "Never" sends `null`.
3. **A second factor to create or rotate:** not built. D841 asks for a session only; a support session
   is refused. The canvas's authenticator crop waits for a Worker rule.
4. **Editing:** name and limit, as recommended.
5. **Keys per member:** the Worker holds 25 live keys (`MAX_LIVE_KEYS`), not 20. The refusal says so.
6. **Typed-name Revoke:** yes.
