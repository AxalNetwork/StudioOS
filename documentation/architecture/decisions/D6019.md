## D6019 — Validate exports the competitor list, the demand signals, and the evidence behind each claim with its experiments (#6019)

- **Status:** built 2026-11-14 for #6019.
- **Migration:** none.
- **Builds on:** D690 (the interview, pain map and summary CSVs, and the module lists), D693 (Export summary and `canReadDecision`), D4585 (a failed read is refused, never exported empty), D4586 § 4 (an experiment counts as observed only with a result), D527 (a new client domain is its own module).
- **Code:** `cloudflare-worker/src/routes/_founder_validate_exports.ts` (`serializeCompetitorsCsv`, `serializeSignalsCsv`, `serializeEvidenceCsv`), `cloudflare-worker/src/routes/founder_validate.ts` (three `GET …/export.csv` routes), `cloudflare-worker/src/services/cycleValidate.ts` (`loadDemand` exported; `loadCustomerWaitlist` and `demandRowsOf` split out of `demandRecords`), `cloudflare-worker/src/services/verdict.ts` (`decisionCitations`, since only that file may name the decision tables), `frontend/src/lib/api/founderValidateExports.js`, `frontend/src/pages/cycles/defs/validate.jsx` (`ExportCsv`, `MODULE_EXPORTS`).
- **Test:** `cloudflare-worker/test/validate_exports_6019.test.ts` (serializers, routes over real SQLite, one-source-at-a-time fault injection, gates), `frontend/test/validate_exports_6019.test.mjs` (the three buttons through `CycleRoute`).

### Why

Validate could export interviews, pain themes and the hypothesis summary. A founder could not take out the competitor list, the demand signals, or the evidence behind a claim with its experiments, though each is a page in Validate.

### What changed

**Three routes, each beside the three it joins.**

| Route | Gate | Reads (each required) | File |
|---|---|---|---|
| `GET /api/founder/validate/competitors/:projectId/export.csv` | `canReadBoard` | the tracked list (`loadTracked`: candidates and their signals) | `company, kind, latest_signal, latest_signal_date, source`, one row per tracked name; a stopped name is left out, as the list leaves it out |
| `GET /api/founder/validate/signals/:projectId/export.csv` | `canReadBoard` | `loadDemand` (demand signals and paid pre-sales), then `loadCustomerWaitlist` | `id, signal, who, amount, currency, period, date, counts`: the module list's one population (`demandRowsOf`), newest first |
| `GET /api/founder/validate/evidence/:projectId/export.csv` | `canReadDecision` | the claims, `evidenceFor` (`services/validateEvidence.ts`), `decisionCitations` (the decisions' evidence rows), the experiments | every claim's evidence (`code, claim, retired_at, evidence_id, kind, evidence, direction, strength, date, decisions`), then a blank line and the experiments (`code, experiment, method, target, status, result, observed`) |

**D4585's rule, for each source.** A read that fails throws `EvidenceUnreadable` with its source (`competitors`, `demand signals`, `waitlist`, `claims`, `evidence`, `decisions`, `experiments`). The route answers `503 { error: 'evidence_unreadable', source, detail }`, and the detail is the sentence the button shows: "The waitlist could not be read, so nothing was exported. Nothing was changed. Try again." No file is written from a partial read. A venture with nothing recorded exports headers and no rows, with status 200.

**Nothing unread is written as 0.** An amount is the exact decimal text from `toMajorString` (`frontend/src/lib/money.js`), in the currency's own decimals. A signal with no amount writes an empty amount and an empty currency. A competitor with no signal writes empty signal cells. A claim with nothing linked writes one row reading "No evidence linked", so the file never looks as if it lost the claim.

**No address, no quote.**
- The waitlist read selects `id, name, created_at` only. A sign-up who typed an email address into the name field is written with an empty name.
- A demand signal's `note` is not exported, because it can carry an interviewee's words.
- An interview in the evidence file is named by its theme and date (`Interview naming <theme>`), as `evidenceFor` already names it, never by its interviewee or their words. So no quote reaches any of the three files, with or without consent, and `QUOTE_WITHHELD` has nothing to replace here.

**Why the evidence file is gated as the summary.** Its `decisions` column names each Verdict decision that rested on the item (`proceed 2026-10-12`, with `(withheld)` and `(superseded)` when they apply), from `validation_decision_evidence.ref_id`, which holds the item's `id`. Partners may not read decisions (D693), so the route uses `canReadDecision`. The Experiments page shows the button only when the module read's `can_read_decisions` is not false.

**The buttons.** `ExportSummary`'s button became `ExportCsv`, and Export summary is now one use of it, with the same look, test id and failure sentence. Market intelligence (Export competitors), Demand and urgency signals (Export signals) and Experiments and evidence (Export evidence) each open their module's part with one. The client methods are `validateExportsApi.competitors`, `.signals` and `.evidence` in a new module, `frontend/src/lib/api/founderValidateExports.js`. The issue proposed adding them beside `exportValidateSummary` in `api.js`, but `api.js` is a frozen hub (D5615): `hub_freeze_5615.test.mjs` fails on a new key there, so the methods use the module route that `HUBS.md` names.

### Left as it is

- **`evidenceFor`'s pre-sale read.** It reads `revenue_entries` with `.catch(() => null)`, so a failed read drops that one linked pre-sale instead of refusing. That reader also serves the record page and the Verdict form. Making it strict is a change to those surfaces and belongs in its own issue. Every other read inside `evidenceFor` already throws, so the export refuses on a failure there.
- **Claim status in the evidence file.** The summary CSV already carries each claim's verdict, lane and counts. This file is about the items behind those numbers and does not repeat them.
- **Row caps.** Each file is capped at 5000 rows, the same as the interview export, with `X-Export-Rows` giving the count. The evidence file counts claims.
