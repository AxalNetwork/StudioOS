- **Migration:** none. **Worker:** D1001's reads mounted, and a `segment` filter on D1002's activity read.

### 1. The addresses

`/admin/persona-segments/:key` is Profile. `/members` and `/activity` are its other two tabs, as sub-paths. All three routes are in `App.jsx` after `/new` and `/unclassified`, and `segmentTabOf` never reads those words, `activity` or `suggestions` as a segment key.

- **Doors.** Each Overview card's name links to its segment. Each tab is a literal `HeaderTab` (`` to={`/admin/persona-segments/${segKey}/members`} ``).
- **The reachability walk.** It used to stop a template at its first `${`, so a tab after a value had no door. It now also reads a value between two literal parts as one segment, written `${}`. No literal segment equals `${}`, so only a `:param` in that place matches it (`admin_route_reachability.test.mjs`).
- **The frame.** The page sits in the same rail frames as Overview: HQ's H22 for a Super Admin, and D1004's own key for an Admin. A key with no segment, or a 404 from D1000, reads "No segment is recorded at this address." with the way back.

### 2. Profile (SEG2): counts only

Profile shows counts and HQ's own words, never a member's name. It never reads the members list.

- **The four tiles:**
  - Members, with its 30-day change (D999).
  - Sub-accounts: the segment's LP count from D999's `by_segment`, not added to the total. Product testers read "not recorded".
  - Still Explorers (D999's `still_explorers`).
  - Answered every question, as "[answered] of [members]" (D1128).
- **Who they are and the typical member:** D1000's `who` and `typical`.
- **How they work:** D1001's working styles, as bars. A style no one has is left out. A suppressed one reads "<5". The members with none recorded show as a hollow "Not recorded" bar.
- **What they told us at sign-up:** D1001's answers, one card per question.
  - A choice or number question shows its buckets as bars.
  - An open question shows "Answered" as a count, and says open answers are counted, not shown.
  - Each question ends with a hollow "Not answered" bar.
- **Needs and what answers them:** D1000's needs, each with what answers it, or "Nothing answers it yet."
- **Colours and counts.** The bars use the profile's fixed colour: Founders violet, Investors sky, Advisors amber, Operating Partners emerald, any other muted. The issue points at `pages/admin/insights/InsightsCharts.jsx`, which is not on `main`, so the bars use Overview's own fills and hollow form (`PersonaSegments.jsx`, D1004), class for class. A count from 1 to 4 comes back suppressed and reads "<5". A count the read does not hold reads "Not recorded", never 0.

### 3. Members (SEG3)

D1002's members read for this segment, 25 rows a page, with the read's own total ("1–25 of 27").

- **Columns:** Member (name and email), Profile ("Profile differs" when the segment is for another one), Sub-accounts, How set, Confidence, Tagged on and Last active. Confidence shows only for a suggestion at sign-up.
- **Filters:** search (two letters or more), Profile, How set, Confidence, Sub-account, Answered, Last active and Sort. Each one is sent to the server.
- **The move bar.** Each row has a checkbox. The move bar says "[n] selected", with "Move to another segment…" and Clear.
- **Each row's ⋯:** Move to another segment…, and Open account (`/admin/accounts/all?q=` with the member's email). Like the events desk's, the menu is a disclosure, not an ARIA menu.
- **After a move:** the dialog closes, the selection clears and the list is read again. The page says D1002's outcomes in words ("Moved to Angel / Scout.", "Moved 1 of 3 … 1 was already in it. 1 could not be moved. Try again."), with View activity.
- **A failed read** says "The members could not be read. That is not the same as none.", with Try again.

### 4. SEG4: the Move dialog, shared (`MoveDialog.jsx`)

The dialog is a `Lightbox` with `phone="sheet"`. It takes `members`, so the Members tab opens it for one member or for those selected. #2377's account drawer is to open it from "Retag…": that drawer is not on `main` yet, so nothing else opens it today.

- **Before anything is saved, it says:**
  - **Now:** the segment, how it was set and, for a suggestion at sign-up, how sure it was.
  - **New segment:** every segment from D1000, grouped by profile. A retired one is listed but disabled.
  - **The changes:** the new segment's sidebar links, its questions next time they open their profile, and that the move is logged under your name.
- **It refuses in words:**
  - The same segment: "Already in [it]. Nothing to change.", with no Move.
  - A retired segment: "[name] is retired, so it takes no new members."
  - An admin account, for an Admin: "Only a super admin can move an admin account.", with Close only. The Worker refuses it too (`super_admin_required`). D1002's members list leaves admins out, so the Members tab never offers one. The rule is there for the shared drawer.
- **A profile the segment is not for** is said before the move: "[Name] is a Founder. Angel / Scout is an Investor segment." For several members it is "[n] of them have a profile [segment] is not for."
- **Move** writes D1002's `POST /members/move` once. A refusal stays in the dialog with the choice kept, and the segment select is controlled. A failed segments read says nothing can be moved until it is read. It is never a browser pop-up.

### 5. Activity (SEG8, this segment's own)

D1002's activity read with `?segment=`, its kind filter and pages.

- **The Worker filter** keeps a row when the segment is where a member came from or went to (`seg_from` or `seg_to`). That covers moves in and out, sign-up choices and its own edits. An ask to finish names no segment, so it is not listed here.
- **Errors.** A key that isn't a segment key is a 400 `invalid_segment`. A failed read says so, and a source that could not be read is named.
