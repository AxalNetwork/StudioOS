## D8082 — The GitHub admin baseline as code, checked weekly by a read-only drift job (#8082)

- **Status:** built by S25 on 2026-11-21 for tracker #8059 (audit sections 1, 10 and 20).
- **Basis:** `origin/main` at `270cdf4a2`.

### What was decided

What `slot:chatgptpro` sets in the consoles is written down in
`documentation/operations/GITHUB_ADMIN_BASELINE.md`, one table row per setting
with a key the machine reads, and `.github/workflows/admin-drift.yml` compares
it with the live values every Monday. A drift becomes a task for the admin slot
instead of a surprise.

1. **One file, one key per row.** Sections: rulesets (#8060), repository
   settings (#8060, #8062), Actions (#8062), organisation (#8062), environments
   (#8063), GitHub Apps (#8061), runner groups (#8065) and Cloud (#8064,
   #8066). The Expected cell is compared; the Planned cell is the admin issue's
   intent and is not. Lists compare as sets.
2. **"To be recorded" is never drift.** No admin issue had posted a STATUS when
   this landed, so every row says "to be recorded". The check prints the live
   value beside each such row so the admin slot, or the coding slot mirroring
   its STATUS, can copy it in.
3. **Read-only, and fail closed.** `scripts/ops/check-github-admin.mjs` reads
   through a GET-only client (it has no other method). The `check` job holds
   the read token in `production-ops` (no deployment record) and only
   `contents: read`; the `file` job holds `issues: write` and no secret. A
   missing token, a 401, or a token that cannot read repository administration
   fails the run before anything is compared. A section the token cannot read
   (the organisation, Apps or runner groups with a repository-only token) is
   printed as unreadable and fails the run as soon as one of its rows has an
   expected value. The run never reports "no drift" for a value it could not
   read.
4. **The credential name.** #8063 has not reported one, so D8082 proposes
   `ADMIN_DRIFT_READ_TOKEN` in `production-ops`: a fine-grained token with
   repository Administration, Environments, Secrets and Variables read (names
   only), and organisation Administration and Self-hosted runners read. It has
   an inventory row in `production-credential-inventory.json` (D7145). If the
   admin slot records another name, the workflow, the inventory and the
   baseline's credential paragraph change together.
5. **One issue per drift key.** Labelled `slot:chatgptpro` and `state:ready`,
   titled `[admin drift] <key>`, found again by a marker in its body written
   by `github-actions[bot]` (an issue anyone else wrote is never adopted). A
   repeat updates the body; a comment is added only when the values change or
   the drift comes back (a closed issue is reopened, so there is still one per
   key). A resolved drift is noted once and left open: the admin slot confirms
   and closes, as D6387's repair issues are closed by people.
6. **Names and values only.** Every live value passes a filter before it
   reaches an issue or the report between jobs: token prefixes, long hex and
   base64, UUIDs, numbers of seven digits or more, URLs, IP addresses and
   internal host suffixes are replaced by "[withheld …]". Bypass actors are
   kept as `type:mode`, reviewers as a count and type. A pinned action SHA
   (after `@`) is kept.
7. **Cloud is "not checked".** No read-only cloud credential exists in
   `production-ops`, so the Cloud rows are listed (names and quotas only) and
   never compared.

### What stays not built

- A reader for Cloudflare, AWS or Azure, until a read-only credential is
  recorded for it.
- The baseline's values: they arrive with each STATUS on #8060 to #8066.
- Checking App installations by App identity (the organisation listing is used;
  a token that cannot list them reports the section unreadable).

### Verified

`node --test scripts/ops/check-github-admin.test.mjs` (run in CI through
`frontend/test/admin_drift_8082.test.mjs`): a fixture per section for match,
drift, to be recorded and a missing permission; the missing-token and
no-administration cases fail closed; one issue per drift, an update on repeat
with no duplicate, a resolved note, a reopened issue; no secret-shaped value in
a title, body or report. The workflow inventory, the credential guard, the
folder and decision guards pass.

### Rollback

Delete `admin-drift.yml` or disable it in the Actions tab; the issues it filed
stay. The check changes no setting, so nothing else needs undoing. Remove the
inventory row and the secret together with the workflow.
