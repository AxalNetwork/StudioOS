## D6047 — Raise Overview on a phone, board RA-11 (#6047)

- **Status:** built 2026-11-22 (#6047, Raise V2 build 3/5, under #4863). Frontend only.
- **Canvas:** `design/incoming/Raise v2 Page.dc.html` and `Raise v2 · Boards.dc.html` (D4863), board RA-11 (RA11a), with RA-03, RA-04, RA-06 and RA-08 for the states the phone shares with desktop.
- **Read:** `GET /api/cycles/raise/overview` as it stands on main (D663, D1610, D6045), the same read D6046 draws on desktop. No new route, no client method, no migration.

### The choice: a Raise branch in `PhoneCycleRoot.jsx`, not a change to `raisePhone`

The issue allowed either. The phone root now has a Raise branch, drawn by `pages/cycles/RaisePhoneRoot.jsx` over `raisePhoneModel.js`, and `raisePhone` in `cloudflare-worker/src/services/cycleFocus.ts` is unchanged. The reasons:

1. **Everything RA-11 draws is already in the read.** `primary_action`, `stage`, `next_steps`, `connectors` and the cards are spread beside `focus`, `meter` and `index`. Changing `raisePhone` would add nothing the phone could not read. It would also give the Worker a second copy of rules that `raiseOverviewModel.js` already holds for desktop.
2. **One set of rules for both widths.** The phone reuses D6046's builders (`journeyView`, `nextActionsView`, `readinessView`, `sourcesView`, `raisePrimaryAction`). So the primary action, the three next steps and the sources are the same on a phone and on desktop. This is the issue's objective: "the same priorities as desktop".
3. **Validate, Build and Grow are untouched.** The branch is taken only for `cycle === 'raise'`. The shared loading, refused and unreadable states are not changed.

### Rules

1. **The branch is drawn for a read that carries D6045's `stage` or `primary_action`.** Every Raise overview on main sends at least one of them, founder and staff alike. A read with neither predates D6045, and D703's focus root still draws it. This keeps D703's fixtures, and an older cached read, on the root they were written for.
2. **The primary action is the Worker's `primary_action` (RA-03), not D703's `focus`.** Drawing both would offer two different "next things" on one screen. The `focus` is still served, and Raise's phone root no longer draws it. An unreadable action is said ("No primary action is offered: …"). A staff read gets none.
3. **Order, for 390px:** the eyebrow with the page's Eadwyn button, the primary action (52px, full width, the first block, so it is on screen without scrolling), the journey, the next steps, the score, the connected-sources line and the module status list. **The next steps sit above the score**, as the acceptance criteria ask. RA11a draws readiness first; RA-04's own rule is "next actions before any score breakdown".
4. **The journey's phone form** is one row of four equal columns (`grid-cols-4`, each `min-w-0`, names wrap). The current stage is `aria-current="step"` and reads "You are here". The other stages' words (Earlier, Next, Later) go to screen readers, and the Worker's rule sits under the row. The per-tool marks stay on desktop; the module status list carries each tool's state.
5. **The score** is readiness coverage ("N of M areas assessed", the unassessed areas named, never a 0) and the round's meter (`phoneMeter`, the Worker's `display` as sent). A meter with no value reads Not recorded.
6. **The connected-sources line** has three forms. With nothing connected it is RA-06's one message and Connect sources. Otherwise it names each connected source with its last read (or "Last read · Not recorded"). A source that could not be read is Unavailable, with Try again. A list that could not be read is Unavailable, never "nothing connected".
7. **The module status list** is the Worker's `index` (`PhoneRows`). The Pitch row says the deck's state from `pitch_state` (No deck, Working draft only, Saved, Reviewed, Shared) in place of "Views this week". A staff read is sent no index, so it gets one row per card from that card's state: Has records, Started, Not recorded, or Unreadable. Before this, every row in a staff read was "Unreadable". The rows link to the module pages. The module phones (RA-26) for Data room, Cap table and Use of funds are #5075's.
8. **What the read does not serve is Not recorded, never invented:**
   - follow-ups due and investor objections (#8256);
   - which areas need attention (#8257);
   - whether a connected source is fresh or stale (#8258).

   Each is one labelled line with #5129's Not recorded chip. When those issues land, their values replace the chips.
9. **Staff read-only** (`read_only`, D1191): the amber Read only line, no primary action, no next-step actions and no Connect or Manage. "Read only. The founder takes these steps." is shown under the steps.
10. **390px:** every block is one column. No class in `RaisePhoneRoot.jsx` sets a fixed width over 99px, a nowrap or a sideways scroll, and every tap target is at least 44px. The test reads the source for this. It is a static guard, not a rendered measurement.
