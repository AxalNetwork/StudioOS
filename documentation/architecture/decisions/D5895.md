## D5895 — AI-native Venture runs in the generic program shell (#5895)

- **Status:** built 2026-11-15 (#5895). Frontend only: no migration, no new Worker route, no new client method.
- **Number:** D5895 is the issue's number (D4106).
- **Builds on:** D5313 (Perks in the shell, and the seven-step pattern for the others), D5891 (Mentor cohort access), D963 (AI-native Venture's tiles, playbook and foot line), D4873 part 4 (the generic shell).
- **Canvas:** PG03a on the Programs v2 canvas (`design/incoming/Programs v2 · Boards.dc.html`).
- **Scope note:** #4873's comment of 2026-11-09 lists nine pages without AI-native Venture. D5313 names it among "the other eight", and it is one of the built-in pages under `/admin/programs`. This moves it so that no built-in page is left outside the shell. Drop this if the owner meant otherwise.

### What changed

- **The strip.** `PAGES['ai-native-venture'].tabs` and `ProgramTabs.jsx`'s `AiNativeTabs` list the shell's six core sections in PG03's order and words. Each is a literal `<Tab to="…">`:

  | Tab | Address |
  | --- | --- |
  | Overview | `/admin/programs/ai-native-venture` |
  | Playbook | `/how-it-runs` |
  | Availability & grants | `/availability` |
  | Participation | `/participation` |
  | History | `/activity` |
  | Settings | `/settings` |

  There is **no module tab**: `MODULE_PATHS` has no entry for it, and the registry seeds no module. `AiNativeTabs` sits last in the file, in `PAGES` order, because D953's test holds the strips and `PAGES` to the same order.
- **The routes.** `/admin/programs/ai-native-venture` stays on its `App.jsx` line. The five new addresses are literal routes in `frontend/src/routes/adminProgramsAiNative.jsx`, onto the same `ProgramPage` under `guard(['admin'])`. Until now they fell through to `/admin/programs/:key/…` and drew the registry-backed page.
- **Overview keeps what the address showed:**
  - the four "Not running yet" tiles;
  - the playbook editor (`programs-ai-native-how`);
  - for an Admin, the foot line (`programs-ai-native-foot`).

  The test ids are the same. It adds Capability modules from `shellModules('ai-native-venture', detail.read)`: "None yet" on a good read, "Could not be read" on a failed one.
- **Playbook** is the same editor on its own.
- **Availability & grants** and **Settings** are the shell's sections, inside `OnRegistry`. A failed registry read marks only them; the tiles still draw.
- **Participation** is the shell's `Participation`: "Not recorded", with its reason. No store records who took part, so it is never 0.
- **History** is the program's activity read (`ActivityTab`).

### Departures from PG03a

- **Overview carries the playbook** as well as the Playbook tab, because the acceptance keeps the existing address showing the editor and the foot line with their ids.
- **No Offer to studios.** It still waits for #2376, as D963 said.

### Old tests that changed

Only the assertions that pinned the old one-page strip changed:

- `admin_programs_d953`: `routeFor` of the bare address is `overview`, not `page`; the tab labels are the six above; the mounted page now has `programs-tabs`.
- `admin_programs_d962`: AI-native Venture's `/activity` tab is History.

### Tests

`frontend/test/programs_ai_native_shell_5895.test.mjs` covers:

- **The strip:** it equals `PAGES` and has no module tab, and every tab's path routes to its own key, with and without a trailing slash.
- **The routes:** every new address is a literal route under the admin guard and is never HQ-only, and the old one stays in `App.jsx`.
- **Mounting:** on the route table of the `App.jsx` line, this module and `adminProgramsGeneric`, each of the six addresses and four deep links (a query, a hash, a trailing slash) opens AI-native Venture's own `ProgramPage`. Only its section shows and only its tab is lit, with no redirect.
- **Overview:** the tiles, editor and foot line for an Admin; no foot line for a Super Admin; modules "None yet", or "Could not be read".
- **Participation:** Not recorded.
- **Settings:** a PATCH of member access.
- **A failed registry read** marks only Availability and Settings.
- **History:** it reads the activity.

- a dropped route;
- a wrong strip word;
- the playbook on every tab;
- no foot line.
