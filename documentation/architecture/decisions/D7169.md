## D7169 — Research › Fund dossier quarterly reports, built: edit one metric and keep the rest (#7169)

- **Status:** built 2026-11-18 to the `Research Funds Quarterly Reports` canvas (boards FND-Q0 to FND-Q11, decided in D7034). Part of #3701.
- **Route:** no new page route. The section lives in the private dossier at `/research/funds/:uid` (`FundDossier`), where `FundReportsPanel` was already mounted.
- **Route-map row:** `part-5/0030-pages-fund-dossier`.
- **Migration:** none. Migration 230's columns carry everything the boards draw; the revision is the row's existing `updated_at`.

### What was built

**Worker** (`services/researchFundReports.ts`, handlers in `routes/research.ts`, all `requireAuth` and scoped to `owner_user_id`):

- `POST /research/funds/:uid/reports` is create-only. A period that already has a report answers 409 `period_exists` with `report_uid` and the saved `report`, and nothing is written. It used to upsert every column, so resubmitting a quarter cleared NAV, IRR, TVPI and the note.
- `PATCH /research/funds/:uid/reports/:reportUid` is a partial update: a field absent from the body keeps its value and `null` clears it. The answer is the full row plus `changed`.
- Revision check: PATCH takes the row's `updated_at` as If-Match (bare, quoted or weak). A different revision answers 409 `report_changed` with the current row; the UPDATE also names the revision in its WHERE, so a save landing between the read and the write is caught the same way. A PATCH with no If-Match answers 428 `revision_required`, so no client overwrites blind. Each write moves the revision at least one millisecond.
- Field errors: every field is checked and a refusal is 400 `invalid_report_field` with `field` (the first) and `errors: [{ field, detail }]`. A non-number, a fraction of a cent or basis point, a value out of range (a return below −100%, a negative NAV), a URL that is not http(s), a date that is not a calendar date, or a note over 2000 characters is refused, never stored as null. PATCH refuses a change of `period`.
- Currency stays USD only. A per-report currency is the proposed dependency D7034 names; it is not built and the sheet says the unit is fixed.

**Frontend** (`pages/research/FundReportsPanel.jsx`, `FundReportSheet.jsx`, `FundReportsChart.jsx`, `fundReportsModel.js`; client `lib/api/researchFundReports.js`):

- FND-Q1: the latest reported quarter with units, the chart with a metric switch (Quarterly return, NAV, Net IRR, TVPI), and the history with Edit and Delete. No reports yet, Loading and Failed to load (Unavailable with Retry, "This is not a claim that none exist") are separate; Add quarter is held while the list is loading or unknown.
- FND-Q2, FND-Q3, FND-Q4: Add quarter and Edit in the shared Sheet. A quarter that already has a report offers "Open … report", prefilled, and what was typed is offered back there (owner's option A). Each field is Kept, New value, Replaced, Will be cleared or Invalid entry, with "Was:"; emptying a saved field keeps it until Clear value is chosen (inline, and in the ⋯ menu); the change summary names each change and what is kept; the one primary action is "Save N changes". Only changed fields are sent, with the revision. `report_date` is sent.
- FND-Q5: one-decimal percents with a true minus, a measured 0.0% tagged "measured 0", TVPI as × from the stored hundredths (no longer "1.4%x"), money as US$, Not recorded, No report and Unavailable chips.
- FND-Q6: every quarter from the first reported to the latest at its own position (owner's option A). A quarter with no row is a dashed gap labelled No report in the chart and a "No report for this quarter" row with Add in the table; a recorded quarter missing the metric is a gap labelled Not recorded. Lines join only neighbouring quarters that both have a value.
- FND-Q7: an error summary that is focused and links to each field, the Worker's own field errors on their fields, the per-field conflict review (fields one side changed are merged; both-changed fields ask Mine or Theirs), save failed with Retry save, offline (save paused), session expired, and "Saved at … The list could not be re-read" with Unavailable and Retry.
- FND-Q8: Delete opens a review with the quarter's values and Keep report focused; Escape or Keep returns focus to the row's Delete. Closing an edit with unsaved changes asks Keep editing (focused) or Discard.
- FND-Q9: after a save, focus moves to the saved row (highlighted 4 s) and the change is announced ("Saved. 2026 Q2 updated: quarterly return 4.2%. Other values unchanged."); after a delete, to the next row or the heading. The chart is one tab stop: ← → Home End step through every quarter, gaps included, each announced; Enter opens it. Inputs name their unit ("NAV, US dollars").
- FND-Q10: below the phone width the history is cards (newest first) with 44px Edit and Delete, a Table toggle, the chart's last four quarters, and the edit orders changed fields before kept ones. Dark mode on every surface.

### Departures from the canvas

- The delete review is the shared Sheet (a `dialog`), not a separate `alertdialog`; the unsaved-changes question is an `alertdialog` region inside the edit sheet, and the conflict review replaces the edit sheet's body rather than opening a second sheet.
- At 390, Add quarter is a full-width 48px button at the head of the section, not a sticky bottom bar: the section sits inside the dossier with other sections. The edit sheet is the shared Sheet's full-screen page, its footer holding the count and the one Save; Cancel is the ×.
- The history table adds a Fund size column, so a fund size recorded per quarter has a history (the canvas shows it in the latest strip only).
- The source link reads the source's host name: the product stores a URL, not a label like the canvas's sample "GP letter · 2025 Q1".
- Report date uses the browser's date input rather than a "DD MMM YYYY" text box; the existing-period notice does not print when the saved report was last saved.
- Session expired: `request()` sends a protected page to sign-in on a 401. The edit is held in this tab only (`sessionStorage`, written before each save, removed on any answer but a 401) and offered back with Resume editing when the dossier opens again in the tab (owner's option A). Nothing else stores it.
- 428 `revision_required` is a refusal the canvas does not draw; the page always sends the revision.
- Migration 230 calls `tvpi_bps` basis points; it holds hundredths (1.4× is 140), as the form always stored. The column is not renamed.

### Not in this change

The dossier's section tabs and count (D7033), the per-report currency (proposed dependency), and anything the boards do not draw.
