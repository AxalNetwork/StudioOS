## D4489 — Distribution calendar plans (#4489)

The mounted `/api/grow/calendar` read uses inclusive calendar dates, project access and existing grow_campaign_items links. Optional HH:MM is a wall-clock plan, never an automatic send; time updates are audited and respect Notion ownership. Existing cycle_grow routes remain the content writers.

CalendarTab supplies six Monday-first weeks or seven week columns, filters, overflow expansion, honest empty/loading/unreadable states, and preserved create/edit/delete dialogs. Notion is Planned, never Sent. PieceSheet hands publishing to the existing PublishSheet and D1319's founder confirmation. Real-size preview frames overflow horizontally rather than being scaled.

Best-time hints have no evidence source. Approval has no store. Both remain hidden. Repurpose remains hidden pending #4488. Copy/image editing stays in the existing PublishSheet because calendar items have no copy or media store; preview missing content says Not recorded. No sample author, duration or metrics are invented.

The Calendar tab is wired through CycleRoute; Overview now uses CalendarWeek over the same scoped API and the old ContentCalendar list is retired there. Plan/edit/delete dialogs are preserved. Filter choices use existing Channels and campaign reads. The API exposes project write permission; read-only members cannot plan/edit/delete/change times. Compact screens start in Week view.

Copy is local until explicitly passed into PublishSheet, which retains its own checks and founder confirmation. Ask accepts a post proposal into the local textarea. Images are local previews, with validation and object-URL cleanup; Publish is disabled while an image is selected because Publish has no media-upload route. The missing upload capability is shown, never silently dropped. Repurpose remains hidden despite #4488 landing: its actual request validator does not support kind repurpose. These two upstream capability gaps remain explicit.

Preview image sources accept only browser-format same-origin blob URLs. The renderer reconstructs the source from the trusted origin and an encoded UUID; arbitrary DOM strings, network/data/javascript URLs, markup, and cross-origin blobs never become image sources. Regression checks exercise both the validator and rendered markup.
