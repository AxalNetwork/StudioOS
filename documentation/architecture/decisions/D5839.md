## D5839 — Search Console: its own read-only Google client and one verified property per venture (#5839)

**Decided.** Google Search Console is a connector of its own,
`google_search_console`, with its own Google OAuth client
(`GOOGLE_SEARCH_CONSOLE_CLIENT_ID` and `_SECRET`, or HQ › Integration keys).
It never reuses the Workspace or Calendar client. Each venture binds at most one
property, through one member's own connection.

**Why its own client.** Google revokes a grant per OAuth client: revoking a
Search Console token through the Workspace client would end Calendar, Drive and
Meet as well. That is what `revokeAndDisconnectGoogle` does today for Google
Workspace. With a separate client:

- a Search Console disconnect revokes only the Search Console grant;
- an existing Calendar, Drive or Meet grant cannot authorize a Search Console
  read, because it was issued to a different client;
- the consent omits `include_granted_scopes`, so Google returns nothing broader
  than `webmasters.readonly`.

**What it asks for.**

- The consent asks for `https://www.googleapis.com/auth/webmasters.readonly`
  alone, with `access_type=offline` and `prompt=consent`, so Google returns a
  refresh token.
- The signed state, its single use and the scope-overreach refusal are
  `routes/integrations.ts`'s, as for every OAuth connector.
- A grant that reports any extra scope is revoked and refused
  (`scope_overreach`).
- A grant without a refresh token is revoked and refused
  (`search_console_offline_refused`).
- A refresh that comes back with a different scope set is revoked and asks the
  member to sign in again.
- A refresh runs behind `refreshLease.ts`'s lease. Tokens live only in
  `integrations.credentials_enc`, encrypted.

**The property.**

- `GET /api/search-console/properties?project=` returns `sites.list` for a
  writer whose connection is switched on for the venture's company. Each
  property comes with Google's permission level, and `siteUnverifiedUser` is
  marked unusable.
- `PUT /api/search-console/property` with `{ project, site_url }` checks the
  identifier's shape first:
  - a domain property is `sc-domain:` plus a host;
  - a URL-prefix property is an `http(s)` URL ending in `/`, exactly as
    Google writes it.
- It then calls `sites.get` on that exact identifier and binds the property
  only for `siteOwner`, `siteFullUser` or `siteRestrictedUser`.
- If Google answers for a different identifier, nothing is bound
  (`property_mismatch`).
- `site_url: null` unbinds.
- A teammate's binding is never replaced (`venture_served`).
- `POST /api/search-console/property/check` repeats `sites.get` at sync time:
  - lost or unverified access marks the selection `access_state = 'denied'`
    (D5840's state, under which the sync lands nothing), and the selection
    stays for the founder to decide;
  - regained access clears the mark and records the current level.
- The browser receives the capability (`connected`, `company_enabled`,
  `can_bind`), the binding's identifier, kind, level, state and check time,
  and whose connection serves it. It never receives a token.
- The activity log records the bind, change, unbind and lost access with the
  property's kind, never its name.

**Disconnect.** It revokes the refresh token, which ends this client's whole
grant and nothing else at Google, then deletes the member's selections. A
reconnect starts with no selection, and the next bind is verified again.

**One selection, shared with the sync (D5840).** The bound property is written
to `search_console_selections`, the table D5840's sync
(`services/searchConsoleSync.ts`, #6588) reads: one row per venture, keyed to
the member who bound it (`user_id`), with the exact `site_url`, its kind, the
permission level and `access_state` (`ok`, `denied`, `revoked`). The sync's
`deps.accessToken(env, userId)` is `searchConsoleAccessTokenForUser`: that
member's own active connection, refreshed behind the lease; no connection reads
as a revoked grant. This PR adds no table of its own.

**Changed.**

- `integrations/searchConsoleOAuth.ts` and
  `integrations/providers/google_search_console.ts`.
- The registry row and metadata, the connector page, and the company scope.
- The managed key in `providerOauthKeys.ts`, its callback URL in
  `admin_integration_keys.ts`, and the key test's sentence.
- The disconnect refusal `search_console_revocation_failed`.
- `routes/search_console.ts`, which mounts itself at `/api/search-console`.
- No migration: the selection is D5840's `search_console_selections`
  (migration `202611150136_5840_search_console_sync.sql`).
- The HQ labels and the Google brand alias.

**Owner-only, not done here.** These are Google Cloud console steps that no
agent can take:

- enable the Search Console API in the approved project;
- configure the consent screen;
- register each environment's exact redirect URI,
  `<OAUTH_CALLBACK_BASE_URL>/api/integrations/oauth/google_search_console/callback`;
- add authorized test users while the app is in Testing;
- record what external-app verification `webmasters.readonly` needs for the
  planned audience.

Until the owner sets `GOOGLE_SEARCH_CONSOLE_APPROVED=1` and the client, `ready`
is false. The catalogue says the connector is not set up, and no state row is
written. Nothing here asserts production availability.

**Not built.** Search analytics reads and what lands from them; the Connectors
and Build picker UI over these routes.

**Verified.**

- `cloudflare-worker/test/search_console_5839.test.ts` (12 tests, against a
  fake Google) covers:
  - the consent shape;
  - readiness behind the flag;
  - sign-in end to end;
  - overreach and offline refusals;
  - identifier shapes;
  - owner, full and restricted bind, and unverified refused;
  - malformed, unlisted and mismatched selections;
  - two ventures and a teammate;
  - lost and regained access;
  - refresh and a revoked grant;
  - a support session, a non-member and an unswitched company;
  - disconnect and reconnect;
  - the selection D5840's sync reads, and the token for its member.
- Removing the usable-level check, or the refresh-token refusal, fails a test.
