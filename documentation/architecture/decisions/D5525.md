## D5525 — A company Member may still create a project in its company (#5525)

**Decision (2026-11-11, owner: A).** Creating a project inside a company needs a seat of any role in that company, as it did before D5366. Only the two refusals #5366 asked for apply to creation: a support session, and a platform admin using HQ access without a seat. `companyCreateDenial` (`services/companyAccess.ts`) is that rule, and both create paths use it: `POST /api/projects` and the scored intake submit.

**What stays as D5366 set it.** Every write to an existing company project still passes `companyWriteDenial`, which also refuses a seat that cannot edit. That covers a project's data, slug, roster, invitations, lifecycle (including moving it out of its company), and company-scoped agent-team management. Moving a standalone venture into a company checks only that its owner belongs there, as before.

**Verification.** `account_portfolio_d1415.test.ts` creates a project as a plain Member of the company again (201). `company_project_write_gate_5366.test.ts` keeps the support-session and HQ-without-seat refusals.
