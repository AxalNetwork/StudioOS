- **Migration:** none. Frontend only.
- **Builds on:** D879 (#2552, C1), the Worker's side. C1's PR was not open when this was built. This PR changes no Worker file and **should merge after C1** (see "Order" below).

### The owner's ruling (2026-10-22)

Axal VC's own Mercury accounts are HQ's only. `/api/admin/mercury` and HQ fund administration keep working unchanged. The member Mercury connector is the member's own, for Founders' Grow and Raise and Investors' Deals and Pipeline.

### 1. What moved under HQ

`pages/admin/fundAdmin/` now holds Axal VC's own Mercury:

- **`MercuryEntitySheet.jsx`.** `MercuryEntitySheet`, `MercuryEntityConnections` and their forms (connect, replace, disconnect, sync), unchanged in behaviour.
  - HQ's Bank accounts console (`admin/consoles/BankAccountsConsole.jsx`) opens the sheet.
  - The fund administration Banking tab (`BankingTabs.jsx`) draws the connections.
- **`mercuryEntityModel.js`.**
  - The rows and words: `ENTITY_KEYS`, `entityRow` and `entityRows`, `entityState`, `entityErrorWords`, `FUND_NOTE`, `orgNameDiffersSentence`.
  - The sheet's sentences, including `ENTITY_BRANCH_MANAGED` (a branch admin's sheet), plus `retryAfterSentence`.
  - The Overview tab reads its state and error words from here.

**Left in `pages/account/` because members use them:**

- `accountLine` (one account as "Checking ending NNNN"), which the investor's proof of funds also reads;
- every member string.

**Deleted, not moved:**

- `MercuryEntityPageBody` (the entity row's body on `/account/connectors/mercury`);
- `MercuryEntityPanel` (Build's lightbox);
- `FundAdminSection` and its "Entity connections" badge (`FUND_ADMIN_GROUP`);
- `ENTITY_AUDIT_FOOT` (the page's audit sentence).

Each was drawn only on a member surface, so after the move nothing calls them.

### 2. What the member pages lose

- **`connectorsModel.js`.** `ENTITY_SOURCE` and `isEntityRow` are gone. `isPersonalMercury` is now `key === 'mercury'`. `cardAction` no longer answers `entity`, and `keysHref`, `toolDeepLink` and `toolGroups` no longer filter the entity row.
- **`AccountConnectors.jsx`.**
  - The Fund administration group, the card's Open corner and badge, and the suggestion pill are gone.
  - Yours' search no longer counts the entity row.
- **`ConnectorPage.jsx`.**
  - The entity branch is gone: `MercuryEntityPageBody`, the ignored sign-in return, and the empty Manage.
  - An **admin on HQ** reads one line on Mercury's page: "Axal VC's own accounts are managed in HQ › Bank accounts." It is `HQ_ACCOUNTS`, with "Open Bank accounts" linking `/admin?tab=bank-accounts`.
    - The console sits under HQ's Platform strip; the issue's "Fund administration" names its other door.
    - A branch admin, a founder, a partner or an investor reads no such line.
- **`ConnectorSheet.jsx`** (`openingView`, the panel), **`connectorPageModel.js`** (`pageAction`, `manageItems`) and **`discoverModel.js`** (`signInKind`, the `entity` label) lose their entity branches.
- **`mercuryModel.js`.** The member sentences say "Axal VC's own accounts", never "an Axal entity":
  - the "never" rows;
  - the sign-in refusal;
  - the attention words;
  - `BRANCH_MANAGED`;
  - `NOT_OFFERED`, which no longer lists fund administration among Mercury's uses.

  The Worker's refusal code `mercury_entity_account` is still matched by name, because a member who tries one of Axal VC's own organizations meets it.

No file under `pages/account/` imports `adminMercuryApi` any more. Member bundles stop shipping the admin Mercury paths.

### 3. Order, and what C1 provides

- **What C1 (D879) serves.** An admin on HQ gets the founder page as a read-only preview (`has_implementation` false, so the band says "Not set up here"). The Worker serves no entity row, page or `/connect` branch. This PR draws exactly that, plus the HQ line from its own constant (`HQ_ACCOUNTS`). C1's descriptor need carry no text for it.
- **If this PR merges before C1,** an admin on HQ still gets the old entity row from the Worker. The page then draws it as a plain Mercury row with nothing to connect, plus the HQ line. It draws no entity UI and makes no `/api/admin/mercury` read; the tests mount both rows to prove it. Members see no change either way.
- **Grow and Raise on a founder's page.** They come from the row's `used_by` and `feeds`, which C1 declares. This page already draws them (`UsesGroups`, `FedGroup`), and this PR does not touch that.
