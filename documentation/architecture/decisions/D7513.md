### Step 3 of a call started from a closed one (RAC20C, RAC20D)

`GET /api/round-calls/:uid/source-audience`, on the follow-through router beside D6863's routes, behind the same gate (`requireCallMember`: calls on, signed in, the venture's owner or an accepted co-founder, in the active company). It answers only for a draft (`call_read_only`, 409) that records a source (`no_source_call`, 409) of the same venture (`source_not_found`, 404).

- **What it reads:** the closed call's **chosen** recipients only. A matching investor is re-matched when the audience is previewed, never copied (RAC20B's "Not carried" list). Each row is the investor's name (as the call page already shows it), how they answered the closed call (Responded, Did not respond, Not delivered) and where they stand today: `verified`, `not_verified` (KYC no longer approved), `not_active` (the account is paused or no longer an investor's) or `not_in_pipeline` (no prospect of this venture holds their address). No email, no user id.
- **What is ticked:** `ticked` is the Worker's: a row is ticked only when it is `verified`, which is exactly the set `PUT /api/round-calls/:uid/audience` can save (a verified investor's prospect in this pipeline). The sheet applies the ticks once, and only when the draft records no chosen audience of its own: a saved audience always wins. Ticks are an unsaved audience, so the owner's Next writes them through the existing audience route.
- **Who sets it:** the owner alone (D1222's `can.audience`, `saveAudience`'s check). A co-founder sees the ticks with every box disabled and the line "The audience is set by the venture's owner. You can see who is ticked. Only the owner can change it (D1222)." Their step writes nothing and does not ask for the owner's match preview; it says matches are re-matched when the owner previews the audience. Before this, a co-founder's step 3 failed the preview read and the audience write.
- **States:** loading draws the section's shape; a failed read is Unavailable with Retry, and nothing is ticked from it; a chip's missing count is Not recorded, never zero.
