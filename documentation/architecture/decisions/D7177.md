### Worker (each ◇ in D7043)

- **All-or-nothing save.** `POST /api/research/projects/:uid/comparisons` writes the new subjects, the comparison and its members (and the project's updated time) in one `env.DB.batch`, one transaction. Every statement names the project by uid and owner and only while it is not archived, and each member's keys are subqueries: a member whose subject or comparison is missing is a NULL key, so the batch fails instead of keeping a short comparison. A failed batch is answered `500 { detail: 'save_rolled_back', rolled_back: true }` only after a read finds no comparison under the uid the save minted; when that read fails too it is `503 { detail: 'save_outcome_unknown', rolled_back: null }`. A refusal made before any write keeps its own code (`400`, `404 not_in_directory`, `409 project_archived`, `503 directory_unreadable`), and a failed insert is no longer reported as `directory_unreadable`.
- **Request id.** Migration `202611180051_7177_research_comparison_request_id.sql` adds `research_project_comparisons.request_id` (8 to 64 characters, NULL for every earlier comparison) and a partial unique index on `(owner_user_id, request_id)`. A save that sends an id already used by the caller returns that comparison with `200 { repeat: true }` and writes nothing; one sent into another project is `409 request_id_reused`. A repeat that races the first attempt loses on the index inside its own batch and is answered with the first attempt's comparison.
- **Save status.** `GET /api/research/projects/comparison-saves/:requestId` reads the caller's comparison under that id: `{ state: 'saved', item, project }`, `{ state: 'not_found' }`, or `503 { state: 'unreadable', detail: 'save_status_unreadable' }`. Another member's id reads as not found. It never writes.
- **Generated title.** `defaultComparisonTitle` keeps whole names and drops the last ones until `" …"` fits inside 160 characters; it returned up to 162 before, and the CHECK then failed after the subjects were written.
- **Per-cell Unreadable.** A cell whose held value cannot be read (a figure that is not a number, a fund size that is not a number, a builder that throws) is `{ status: 'unreadable', reason }`; a row whose cells cannot be built at all is Unreadable in every row. Not recorded stays for a value the directory does not hold.
- **New project and comparison (the optional ◇).** `POST /api/research/projects/with-comparison` takes `{ project: { question, title? }, kind, uids, title?, request_id? }` and inserts the project in the same batch, so a refused or undone comparison leaves no empty project. Receipts: `research_project_created` and `research_project_comparison_created`.

### Departures from the canvas

- The new project inside the Compare sheet asks for a question as well as a title: a Research Project's question is required (`research_projects.question NOT NULL`), and the title defaults to it. The canvas draws only "New project title".
- The new project is made in the same request as the comparison (the optional ◇), so the canvas's RCC02B note "If the comparison is then refused, the new project stays, empty" no longer happens and is not shown.
- "Saved part-way" covers the two shapes the old save could leave (fewer than two columns, the same columns twice). The canvas's "2 of the 4 new companies were added; no comparison" card is not drawn: under the all-or-nothing save a status read cannot find a part-saved request, and the old saves carry no request id to look up.
- The Unreadable chip reads "Unreadable" (the house rule; Platform States' word is still the owner's open question in D5129).
- The canvas's sample companies, projects and figures are not copied: the page shows what the Worker returns.
