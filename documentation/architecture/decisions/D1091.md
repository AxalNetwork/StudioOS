## D1091 — Google Workspace connection and chosen files (#2956)

S30 · 2026-10-25. Part of #2402. Migration 588.

### Built

The Worker adds `drive.file` to the existing Google grant with a single-use
`gw_` consent nonce, refuses a callback without the scope or on a different
Google identity, preserves optional scopes on reconnect, and never returns a
stored token to the browser. Calendar and Workspace share one refresh-token
store. A credential-free `google_workspace` integrations row and explicit
company enablement scope the new files and future fed facts.

`POST /api/calendar/google/workspace-files/connect` takes `project` and, for
first enablement, `enable_company: true` (an explicit dialog choice). The member
must already hold the company link and write access to the venture. A missing
company permission refuses before provider reads. Support sessions cannot
connect or use any Workspace route. They may disconnect.

`/api/connectors/google-workspace` exposes venture-scoped picker configuration (`?project=`, public key,
project number, OAuth client id and scope; never a token), chosen files,
draft mapping, Stop using and a five-row preview. IDs and metadata are confirmed
with Google's own `files.get`; folders, shortcuts and the wrong kind are refused.
No partial registration is written if any chosen file fails. Preview stores
nothing; Form previews contain questions, not respondent identity.

The frozen allowlist names eight GET operations. Every provider read refuses
redirects, expires after ten seconds and caps its response at 2 MiB. Preview
Sheets use A1:Z5 and return at most five rows. Errors expose codes only.
Mappings are drafts: every future feed must validate its own allowed columns
before any write. File external IDs in the fed ledger use `<drive_file_id>` or
`<drive_file_id>:<item>` so Stop using unlinks only that file in that module.

Stop using keeps accepted facts. Disconnect revokes the combined Google grant,
then deletes chosen sources, proposals and company enablements and unlinks fed
facts without deleting them. A changed Google identity drops the old sources.
`fedOwnership.ts` provides the shared ledger-owner lookup and explicit-link
check for roadmap OKRs and MVP features. A hand-entered row has no owner;
permission to explicitly link it never authorizes automatic overwriting.
Conflicting historical owners fail closed.

The D753 directory entry and the browser Picker helper are present. The helper
requests its own `drive.file`-only GIS token with incremental scope inclusion
disabled, rejects a wider response and returns IDs only. No token is persisted
or posted to Axal. GOOGLE_WORKSPACE_FEEDS is empty: choosing a file claims no
module import exists.
