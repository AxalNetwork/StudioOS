## D1091 — Google Workspace connection and chosen files (#2956)

S30 · 2026-10-25. Part of #2402. Migration 588.

### Built

The Worker adds `drive.file` to the existing Google grant with a single-use
`gw_` consent nonce, refuses a callback without the scope or on a different
Google identity, preserves optional scopes on reconnect, and never returns a
stored token to the browser. Calendar and Workspace share one refresh-token
store. A credential-free `google_workspace` integrations row and explicit
company enablement scope the new files and future fed facts.

`POST /api/calendar/google/workspace-files/connect` takes `project` and, for
first enablement, `enable_company: true` (an explicit dialog choice). The member
must already hold the company link and write access to the venture. A missing
company permission refuses before provider reads. Support sessions cannot
connect or use any Workspace route. They may disconnect.

`/api/connectors/google-workspace` exposes venture-scoped picker configuration (`?project=`, public key,
project number, OAuth client id and scope; never a token), chosen files,
draft mapping, Stop using and a five-row preview. IDs and metadata are confirmed
with Google's own `files.get`; folders, shortcuts and the wrong kind are refused.
No partial registration is written if any chosen file fails. Preview stores
nothing; Form previews contain questions, not respondent identity.

The owner confirmed on 2026-10-25 that Workspace is read-only while the
pre-existing Super Admin Research Sheets writer remains intact. That feature
uses its own `google_sheets_oauth_tokens` grant/store in `fundSheets.ts`, not
Calendar/Workspace tokens. The whole-tree scan identified this existing
boundary; the new connector exposes no provider write.

The frozen allowlist names eight GET operations. Every provider read refuses
redirects, expires after ten seconds and caps its response at 2 MiB. Preview
Sheets use A1:Z5 and return at most five rows. Errors expose codes only.
Mappings are drafts: every future feed must validate its own allowed columns
before any write. File external IDs in the fed ledger use `<drive_file_id>` or
`<drive_file_id>:<item>` so Stop using unlinks only that file in that module.

Stop using keeps accepted facts. Disconnect revokes the combined Google grant,
then deletes chosen sources, proposals and company enablements and unlinks fed
facts without deleting them. A changed Google identity drops the old sources.
`fedOwnership.ts` provides the shared ledger-owner lookup and explicit-link
check for roadmap OKRs and MVP features. A hand-entered row has no owner;
permission to explicitly link it never authorizes automatic overwriting.
Conflicting historical owners fail closed.

The D753 directory entry and the browser Picker helper are present. The helper
requests its own `drive.file`-only GIS token with incremental scope inclusion
disabled, rejects a wider response and returns IDs only. No token is persisted
or posted to Axal. GOOGLE_WORKSPACE_FEEDS is empty: choosing a file claims no
module import exists.

### Design boundary — the screens (part 2)

The first PR stopped at the foundation because the canvas was not yet
approved. Part 2 builds the screens from S1's canvas on #2956 and D1314:

- **GW1, the connector page** (`pages/account/GoogleWorkspaceFiles.jsx`,
  mounted by `ConnectorPage.jsx` for `google_workspace`): the permission
  ("files you choose", read only), then "Files you chose · N files · N
  venture" with Venture, Module, Last read and Stop using. A file never read
  says "Not read yet" with its reason, never a blank. Stop using opens an
  in-page dialog that says what Axal VC keeps and that the file in Google is
  not changed. Choose files asks for the venture and the module, opens
  Google's own Picker (its own `drive.file` token, browser only), and the
  Worker confirms each id.
- **GW2:** "Allow Google files" asks for the venture and an explicit tick for
  its company (never inferred; Continue stays disabled until it is ticked),
  then goes to Google's consent page. The URL is refused unless it is
  `accounts.google.com`. With no Google sign-in, the page says "Google is not
  connected yet" with "Open the Google page ›" and offers no Allow.
- **GW8:** below `sm` the same files are a stacked list, and every target
  is at least 44 px.
- **GW3 and GW7** (`pages/cycles/FromGoogle.jsx`): one From Google section
  for every module feed (#2957–#2960) to mount with its own rows. It has four
  states: Loading "Reading…"; Empty, with Choose from Google Drive;
  Unreadable, which keeps the rows read before and offers Choose again; and
  Partly synced, with the count, the reason and Sync again. A failed read of
  the chosen file is Unreadable, never Empty. An empty cell is "—" with its
  reason, never 0. Delete opens an in-page dialog that says the row stays
  deleted when you sync again and that the file in Google is not changed.
- **GW4** (`pages/cycles/MapColumnsDialog.jsx`): the preview's first rows,
  with a field or "Don't use" for each column. A date or number field names
  the preview rows it cannot take and marks them Skipped, and says only the
  preview's rows are checked. Two columns cannot go to the same field. Saving
  stores the mapping as a draft.

GW1 lists files across ventures, so the Worker adds one read:
`GET /api/connectors/google-workspace/mine`. It returns the caller's
connection state, the Google account's email, and the caller's own chosen
files with each venture's name. Stopped files leave the list, and support
sessions are refused. It returns no token.

The D753 registry row stays Coming soon until the owner's Cloud project step
(#2402 decision 3). The section above owns the page's action; the generic
page's sign-in button is withheld for this connector. No module feed exists
yet: parts 3–6 mount `FromGoogle` and `MapColumnsDialog`.
