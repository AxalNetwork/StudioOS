### 1. `publish_at` on the author reads

`GET /api/articles/mine`, `GET /api/articles/draft/:id` and every write that answers with the article (create, `PUT`, submit) return:

- `publish_at` — the time an approved article goes out (D484), or null;
- `publish_at_set_by` — the display name of whoever set it, or null when none is set or that account is gone. It is never an email and never a user id.

Every one of those reads goes through `authorRow` (or `/mine`'s list, which joins the same way), so no caller of `authorArticleShape` can miss the name.

### 2. The author's revision reads

- `GET /api/articles/:id/revisions` → `{ revisions: [{ rev, title, status_at_save, reason, saved_by_name, created_at }] }`, newest first, at most 50 (`AUTHOR_REVISIONS_MAX`). The list carries no text.
- `GET /api/articles/:id/revisions/:rev` → `{ revision: { rev, title, subtitle, body_markdown, status_at_save, reason, saved_by_name, created_at } }`; 404 `revision_not_found` when the article has no such revision.

The gate, in order:

1. a support session (a token with `impersonated_by`) is refused 403 `support_session_refused` before anything is read, as Eadwyn on an article is (`article_assist.ts`);
2. `loadOwned`: the author, or an admin; anyone else, and an article that does not exist, gets 404 `not_found_or_forbidden`.

`saved_by_name` is the saver's display name, or null when that account is gone, as the admin drawer's read is (D1293). The admin's reads in `admin_articles.ts` are unchanged.

### 3. The autosave revision

`PUT /api/articles/:id` writes a revision with reason `autosave` when:

- the body changed (a `body_markdown` that differs from the stored one; a PUT of other fields, or of the same body, writes none); and
- no revision of the article was written in the last 15 minutes (`AUTOSAVE_REVISION_MINUTES`). The check is `created_at > datetime('now', '-15 minutes')` on `article_revisions`.

It is written after the edit lands, so it holds the text as saved. An approved text returned to Submitted (D1292) already writes its `manual` revision, so no autosave is written beside it. A submitted text's edit is autosaved like a draft's.

`articleMetrics.ts` counts only `request_changes` revisions, and the decisions read (`approvalDecisions.ts`) reads only `request_changes` too, so neither changes; a test pins the metrics read. The admin drawer's revisions tab shows the new rows with their reason, `autosave`.

### 4. Tests and mutations

`article_revisions_d1406.test.ts`, on migrations 068, 092, 093, 346, 635, 636 and 637, six tests. Each mutation below fails at least one:

1. drop `loadOwned` from the reads' gate;
2. write an autosave on an unchanged body;
3. write an autosave on every PUT (no 15-minute check);
4. leave `publish_at` out of the shape;
5. read an email into `saved_by_name`;
6. read an email into `publish_at_set_by`;
7. let a support session read;
8. list oldest first;
9. write an autosave beside the returned-to-Submitted revision.
