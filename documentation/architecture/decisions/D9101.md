## D9101 — Company creation copies IP details from the accepted Spin-Out application (#9101)

- **Status:** built for #9101 (slot S03), 2026-11-27. Builds BD25's IP assignment action in the After formation block of the Company Creation addendum (D6035), with its states (BD29), phone (BD30 C) and dark (BD31).
- **Builds on:** D6038 (Company creation's own page), D6040 (the module read's `facts.ip` and its "Copied spinout IP record" fact), D662 and D690 (the Worker's `POST /api/cycles/build/project/ip-copy`, its `writeContext` gate and its `build_ip_copied` log row), #8261 (`isFounderPreview`, founder preview).
- **Worker:** no change. **Migration:** none. **New client method:** `cyclesWrite.build.ipCopy(projectId, applicationId)` in `frontend/src/lib/api/cycleWrites.js`, for the route that was already mounted and tested.

### 1. When the step offers Record IP assignment

`companyCreationModel.js` `ipStep(facts, lab, mode)` stays pure: the page passes the viewer's Lab state and `useViewMode()`'s value. The step's `action` is `copy` only when all of these hold:

- the venture has no IP record (`facts.ip` reads empty through `buildFacts`, as before);
- the viewer is not a Super Admin in founder preview (`isFounderPreview(mode)` false);
- the viewer's latest Spin-Out application (`GET /api/spinout-lab/state`, `application`) has `status` `accepted` and a numeric id.

Otherwise there is no button. With no accepted application (none, pending, declined, withdrawn) the step keeps the reason it gave before. In founder preview it adds "Only the founder can copy their own Spin-Out application.": the route reads `spinout_applications` for the caller, so a Super Admin's press would answer 404 even though the write gate admits them.

### 2. The reads and the press

- The Lab state is read once, and only while the step is not recorded and the viewer is not in founder preview. While it loads the step keeps its shape with no button. If it fails, the step alone says "Could not check your Spin-Out application." with Could not be read and Try again; every other block is unaffected.
- Pressing the button calls `ipCopy` with the application's id. It shows Saving… and is disabled while the copy runs. Once it lands the page refetches the module (`reload`, else `onRetry`), so the step reads the copied record from `facts.ip`, joined as `buildFacts` joins it today, with the source "Copied spinout IP record". The copy's own `ip` answer is never drawn.
- A 404, 503, other refusal or a network error says what went wrong in words on the step, with a `!` glyph and `role="alert"`, and the button reads Try again (`ipCopyErrorWords`).

### 3. Departures from the canvas

- **No button for a venture outside the Lab.** BD25 draws Record IP assignment beside every Not recorded IP step. There is no route that records IP by hand, so the button appears only when an accepted Spin-Out application can be copied. A manual IP record is out of scope.
- **The copied words are the stored keys.** The step joins `origin`, `institution`, `research_group`, `tto_status` and `ip` as `BuildFacts.jsx` already does (underscores read as spaces). It does not map them to the application form's labels. That stays as D6040 drew it.
- **Founder preview** gets a line in place of the button. The canvas does not draw this state.
- **Button size.** The canvas's small button (`btn bsm`) is drawn with a 44px target on desktop and phone, as the issue requires.
