### 1. Stream sits beside the item

SQLite cannot widen `learning_items.video_source`'s CHECK without rebuilding the table. So:

- `learning_items.stream_uid` names the ready Stream video the item plays.
- `learning_stream_videos` holds every video made for the item, with its state: `awaiting_upload`, `processing`, `ready`, `error` or `superseded`.
- `learning_stream_captions` holds its captions.
- `chapters_json` holds the item's chapters.

**Precedence:** a ready Stream video plays first, then the R2 upload (D561), then the link. A `PATCH` that sets `video_url` clears `stream_uid`: a link replaces an upload, as D561 already says.

### 2. The binding, and shipping before it is on

- `[stream] binding = "STREAM"` is declared at the top level and again in `[env.production.stream]`. `check-wrangler-binding-parity` and the branch-config renderer both know the `stream` table.
- `STREAM?` is optional in `types.ts`. While it is absent, every Stream route answers 503 `stream_unavailable`.
- The member read then sends `video_stream: null`, and items play as before. So this merges before the owner turns Stream on (owner step A).

### 3. Uploads

- **Up to 200 MB:** `createDirectUpload`. The Worker always sets `requireSignedURLs: true`, the duration cap and the item in `meta`.
- **Over 200 MB:** the tus route calls Stream's REST API with `STREAM_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, because the binding offers only basic POST uploads. The client's `Upload-Metadata` keeps only its name; the Worker sets `requiresignedurls` and `maxdurationseconds` itself.
- **Refusals:** a non-video item, an unknown type and an over-size file are each refused before Stream is called.
- **Records:** each upload writes an `awaiting_upload` row with its expiry. No upload URL or token is logged.

### 4. The webhook

`POST /api/learning/stream/webhook` takes no session.

- **Signature:** `Webhook-Signature: time=…,sig1=…` must be the HMAC-SHA256 of `time + '.' + body` with `STREAM_WEBHOOK_SECRET`. It is compared in constant time and must be within five minutes of now. Without the secret the route answers 503. A bad or stale signature is 401 and changes nothing.
- **Effects (`applyStatus`)** are idempotent:
  - **ready:** sets the duration (rounded), size, dimensions, playback host and `ready_at`. The item's `stream_uid` and `duration_seconds` move to this video, and the item's previous ready video becomes `superseded`. An `r2_copy`, part 4, does so only once its duration is above 0.
  - **error:** stores the code and the message.
  - **A video this store never made** is ignored.
- **Missed webhook:** `GET …/stream` reads a `processing` or `awaiting_upload` row unchanged for two minutes again through `details()`, as a fallback.

### 5. Playback

The member's item read adds `video_stream`:

| Value | When |
| --- | --- |
| `null` | no Stream video, or no binding |
| `{ state: 'processing' }` | a newer video is still being processed |
| `{ state: 'error' }` | the newest video failed |
| `{ state: 'ready', iframe_url, hls_url, dash_url, poster_url, preview_url, captions, duration_seconds, expires_at }` | the item plays a ready video |

- **Every URL carries a token** from `generateToken()`. A token lasts one hour. It is minted only after `canSeeLearning`, and is never cached or logged; the Stream video id itself is never sent.
- **Isolation:** the Stream state is read in its own guarded query, so a store without the new columns reads as no Stream video.
- **The player** (`videoPlayback`) embeds a ready video's iframe only from Stream's own hosts. A processing video reads "This video is still processing." A failed one reads "This video could not be processed. Ask HQ to upload it again."

### 6. Captions, thumbnail, chapters

- **Generate:** `captions.generate(lang)` writes a `pending` row. When a generated caption is ready, `captionReady` writes its words, without timings, into the item's transcript, but only while there is none. The UPDATE's own `WHERE` enforces this: an author's transcript is never overwritten.
- **Upload:** a WebVTT file (it starts with `WEBVTT`, at most 1 MB) is stored as `uploaded`.
- **Thumbnail:** `thumbnailTimestampPct` from 0 to 1, for a ready video.
- **Chapters:** set on the item's `PATCH`. At most 100, start seconds strictly increasing, titles of 1–120 characters.
- **Abandon:** an upload that is not the current video can be abandoned. It is deleted at Stream and its row is superseded. The current one is 409 `stream_in_use`.
