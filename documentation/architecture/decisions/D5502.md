## D5502 — Exact-base CI failure evidence (#5502)

A failed run needs a test identity, not a shard name or the tail of a log.
The shard runner writes a second node:test reporter beside TAP on pull requests,
merge groups and main pushes. Its original exit status and D6464's single,
allowlisted merge-queue retry remain authoritative. Diagnostic write failures
cannot rescue a failed command.

### Evidence and attribution

Each artifact has schema version 1, run/attempt, tested SHA, recorded base SHA,
part, status, completion, repository-relative covered files and up to 200 test
failures. Each failure has a hash of kind/file/title, a bounded title, safe error
code, reproducible command and generic error excerpt. Identity excludes shard,
line number, timestamps and assertion values. Generated commands quote arguments
and escape the literal title as a regular expression. They include `npm run build`.

The collector binds artifacts to their Actions run, head SHA and attempt. It
looks up a completed **push to main at the recorded base SHA**, never the latest
main run. A matching stable identity is inherited; a covered file without that
failure is independent. Missing, expired, oversized, corrupt or incomplete
artifacts are unknown. Mixed failures retain their individual attribution;
independent failures take the overall `pr_failure` verdict. Cancelled legs are
unknown. The established setup fingerprint remains `infra_failure`.

The all-event diagnostic job is read-only and outside the required gate.
The existing PR digest still executes trusted base scripts; after this change
lands it reads the same exact-base evidence. It never falls back to job-name
inheritance. Legacy job-level library consumers remain unchanged and must not
be mistaken for exact test-level proof.

### Security and bounds

Do not upload raw log tails, assertion expected/actual values, stacks, request
payloads or environment variables. Recognized token patterns are redacted from
titles; modified/truncated titles make evidence incomplete. Error codes use an
allowlist. Markdown metacharacters in external display text are encoded.
Only validated GitHub job/run/incident URLs are rendered. Downloads are streamed
under 2 MiB, ZIPs admit one regular `failures.json` with size/CRC validation,
API pagination is capped, and evidence expires after three days. Re-run artifact
names include the attempt. No production service, D1 write or permission changes.

### Remaining dependency and compatibility limits

This is **Part of #5502**, pending #5505's guard producer and agreed schema.
No guard runner owned by S18 is changed. Setup/build/guard failures name the
failed Actions step and link its job, but guard identity and a safe detailed
excerpt are unknown until that producer lands. Delegated Mac shards without
these artifacts likewise stay unknown. Historical runs without evidence cannot
be reclassified from logs or job names.

On older Node reporter protocols, nested tests do not expose provable full
ancestry. Their titles are still shown, but the report stays incomplete to avoid
conflating equal leaf titles. Long titles, cancellation and truncated streams
also stay unknown. The summary bounds each attribution group to ten rows and
links the artifact for the remainder. The classified artifact's `failures`
contains only proven independent tests for #5610's selector; shared and unknown
records remain separate. All these limits preserve failure and uncertainty;
none turns a required check green.
