## D4102 — The route map is one file per section and one file per canvas row (#4102)

- **Status:** built by S21 on #4102 (Conflicts 1, part of #4101), 2026-11-02.
- **Replaces:** D1310's `merge=union` on ROUTE_MAP.md. D1310's union stays on the two projections, PROFILE_ROUTING.md and PAGE_INVENTORY.md.

### The problem

`documentation/architecture/ROUTE_MAP.md` was the most-edited file in the repository: 226 of 403 commits in the week to 2026-11-02, and 271 commits since 2026-10-26. Those edits were about 400 table rows added or changed, 260 prose lines and 32 new sections.

D1310 gave it `merge=union` so two branches appending rows would not conflict. But union also keeps both versions of a row two branches changed. Then `parseRouteMap` refuses the doubled canvas and `profile_routing_fresh` fails four tests on every branch. On 2026-11-02 that turned main and every open PR red twice:
- D1557 and D1560 both changed the "Pitch Deck Studio v2 Page" row;
- then #4044's one-row fix and #4098's one-row fix were union-merged into two rows again.

### What was decided

**The map is a folder of fragments** (`documentation/architecture/route-map/`, rules in its README):
- `sections/NNNN-<slug>.md`: one file per section of the old file (97), in file-name order.
- `canvases/part-N/NNNN-<slug>.md`: one file per canvas row (195), exactly one table line each. A section holding a canvas table keeps the header and separator, then the marker `<!-- route-map rows: canvases/part-N -->`, where the folder's rows are placed.

**Why one file per row and not one per domain.** Row edits are most of the churn. With one fragment per domain, two branches adding canvases to the same domain would still append to one file. With one file per row:
- adding a canvas adds a file and never meets another branch;
- changing a canvas edits its own file, so two branches changing the same canvas meet as an ordinary conflict on one line instead of a silent second row.

**One reader.** `scripts/lib/routeMap.mjs` `readRouteMap()` returns the whole map as one text. When it was split it reproduced the old file byte for byte, so every reader switched to it with no change in behaviour:
- `scripts/build-profile-routing.mjs`;
- the 22 frontend tests that read the file.

The same module refuses:
- a canvas with two rows, naming both files;
- a canvas file that is not exactly one row;
- canvas rows written inline in a section;
- a rows folder no section places, or a marker whose folder is missing;
- a fragment named outside `NNNN-<lowercase-slug>.md`;
- a conflict marker.

**The combined document is built, not committed (option (a) of #4102).** `node scripts/build-route-map.mjs` writes `route-map/ROUTE_MAP.combined.md` for people to read, and `.gitignore` keeps it out of git. Nothing reads it back. `node scripts/build-route-map.mjs --check` runs in `npm run test:guards`.

**ROUTE_MAP.md stays, as a pointer.** 81 documents link to it, so it is kept as a short page that says where the map is and how to add to it. No branch needs to edit it.

**No union for the map.** `.gitattributes` drops `ROUTE_MAP.md merge=union`. The fragments merge as ordinary files.

### What did not change

- `PROFILE_ROUTING.md` and `PAGE_INVENTORY.md` are still generated from the map, committed, and union-merged. `profile_routing_fresh` still fails a stale one. Splitting or no longer committing them is a sibling task under #4101; only their "Sources:" line changed here.
- The table columns, the canvas grades and every row's text are unchanged.

### Tests

- `frontend/test/route_map_fragments_d4102.test.mjs`, 9 tests:
  - the fragments join in order;
  - a canvas in two fragments fails and names both files, within one table and across tables;
  - one row per file;
  - inline rows are refused;
  - orphan and missing row folders are refused;
  - fragment names are checked;
  - conflict markers are refused;
  - the real map has one canvas per file.

  Mutation-checked: disabling the duplicate check fails 2 tests, and disabling the one-row rule fails 1.
- `profile_routing_fresh.test.mjs`: the D1310 union test now asserts that the map has no union and the projections keep theirs.
