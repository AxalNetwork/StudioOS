### 1. The contract

`POST /api/decks/:id/areas/instruct/quote` and `POST /api/decks/:id/areas/instruct` take the same body:

- `selection: [{ area_id, card_uid?, instruction? }]`, at most **6** areas, all on **one** card. `card` at the top level names the card for an entry without `card_uid`. It is the card's uid, or its position, which the Worker resolves to the uid. InstructionBox sends its position.
- Either a whole-selection `instruction` (at most 300 characters, like D899's) or one `action`: `shorten`, `expand`, `rewrite` or `more_visual`. Never both. An area may carry its own words. The top-level words fill in the areas that have none.
- `variants` 1 to 3, or `mode: 'compare'`.

The quote is #3764's areas quote (D1512 §1): per-area lines that sum to the area's hold, each area's gates and refusal, the total, `quote_uid` and a 10-minute `expires_at`.

The run is admitted through `admitDeckRun` as **one** batch of class `areas`, under one parent hold keyed by the `Idempotency-Key`. It inserts one `deck_area_proposals` row per selected area that can run, and answers `{ batch_uid, class, hold_microusd, replayed, selection, action, proposals, refused }`.

- **Same key, same run.** The same key twice answers the first run's proposals with `replayed: true`. There is no second hold and no second set of rows, so the founder is charged once.
- **The rest is #3764's.** The proposals settle from the run's steps (`settleProposals`, `variantsOf`). Accept is by the area (`/areas/:card_uid/:area_id/accept`), and Discard and the 14-day expiry are the same as for Generate into areas.

### 2. Only the selection

Every proposal, every run line and every quote line comes from one entry of `selection`. Nothing else on the card is planned or sent to a model, and nothing writes the deck row. The editor places an accepted variant, and Save writes the version.

An area resolves to the saved card's block with that id. One that is not words is refused on its own, with its sentence, and holds nothing:

| Code | When |
| --- | --- |
| `not_text` | a figure tile, a bound block, a chart or a picture. Those change from their own tools. |
| `no_text` | an empty block |
| `area_not_found` | an area that is not on the saved version |
| the model gates | as in D1512 |

The other areas still run. When none can, the run is 422 `nothing_to_run` and nothing is held.

The test instructs 2 of 4 text areas. It checks that the deck row is byte-identical afterwards, that proposals exist only for those 2, and that Accept on an area left out is 404. Planning every text block instead of the selection turns it red.

### 3. Figures are refused before any charge

An instruction, or an area's own words, that names a figure is refused at parse time with 422 `names_figure`, before any quote, hold or model call. Its message is InstructionBox's own sentence: "Figures come from your records. Pick a recorded figure instead. Nothing was charged." The test is `numberIn` (`newDeck.ts`), which also catches number words ("twelve customers"), so the browser's check and the Worker's cannot disagree on "$2.4M".

What comes back is words. A variant that names a number the area's text does not is refused when it settles (`wordingProblem`, D1512).

### 4. The words are data, and are stored once

The founder's words reach the model only inside `untrustedBlock('instruction', …)` (`textMessage('ask')`). Every text run passes the safety guard. An instruction is a rewrite on rail option `deck:rewrite`. Shorten, Expand and Rewrite run D899's own actions and rail options. More visual runs our fixed sentence (`MORE_VISUAL`), also as data, under `deck:rewrite`.

The proposal row never stores the words. It keeps three new columns:

| Column | What it holds |
| --- | --- |
| `selection_json` | the run's areas as resolved: `[{card_uid, area_id}]`, the same on every row of the run |
| `instruction_sha256` | the hash of the words, or of the action's name |
| `action` | `instruction`, or the action |

The words exist only in the run's step input (`deck_area_batch_steps`, cascaded with its run).

The hash is also part of the quote's signature (`planSignature`). So a quote for "warmer" is stale for "colder", even at the same price.

### 5. Compare is three seeds

The final canvas removed Compare models (pd16, D1512 §2). `mode: 'compare'` is read as `variants: 3` of the area's one resolved model: three seeds at three temperatures, each priced (O, pick (a)). The client never sends a model.

### 6. D899 and the adapter

D899's card tools (`deck_assist.ts`) are unchanged. InstructionBox runs one area through them, and their own tests still pass. S1 retired `CardAssistBar`, so no bar is left to replace.

`deckV2Adapter.instruct` is now `through(() => deckInstructApi.quote | run(…))`:

- `areas` (InstructionBox's area ids) become `selection: [{ area_id }]`, and `card` stays the card's position.
- `run: true` with `quoteUid` and `idempotencyKey` admits the run.
- The reply's contract is `contracts/deckInstruct.schema.json` (D1511).

InstructionBox itself is unchanged. Its several-areas path reaches the quote route, and still draws its "Coming later" line until B19 draws the quote, Run and the proposals. That is UI, out of scope here.
