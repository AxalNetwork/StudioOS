## D8768 part 2 — One eligibility rule at every skill picker, built (#8768)

- **Status:** built by S09, 2026-11-27. Part 2 of #8768 (part 1 is `D8768.md`, the canvas). The backend items marked ◇ #8768 there and the pickers' frontend are built; run cost per skill stays #4536's ("Not recorded"), and the canvas's visual pass (the phone 390 frames, the full listbox keyboard model, per-agent states on directory cards) is not. Q1 is built to option A (drafts counted, never named, for a reader), as the comment of 27 Nov asked. TMS08's "with no skills" Next is built to this canvas's drawing while D8769 ⚑ Q2 stays open.
- **One rule, one module.** `cloudflare-worker/src/services/agents/skillEligibility.ts` decides every state: `unreadable` (a published pointer with no version row, or a gate read that throws), `listed` (`version_not_published`), `published` (no agent), `attached`, `blocked` (`attachCheck`'s code, tool and capability) and `eligible`. `fitOf` is the role the version was written for or the persona's natural-fit areas; it sorts (`byEligibility`) and labels, never removes. `attachCheck` no longer refuses `role_mismatch` (D4116), so `PUT /agents/:uid/skills`, `POST /skills/:uid/assign`, the add-agent route and the run manifest (`skillRunManifest.ts`) all take a cross-area skill; a pinned cross-role skill now runs, which it must if it can be attached.
- **Reads.** `GET /agents/:uid/skills/available` lists every published, live skill the caller can read with `eligibility { state, code, tool, fit }`, natural fit first, plus `counts` and per-area `areas` (drafts, and skills the caller may not read, only counted). `GET /:scope/:id/skills/eligible?role=&persona=` is the same for an agent not yet added: its tools are judged against the read tools the sponsor could approve at step 3 (`sponsorToolPool`), each skill names its `tools_to_grant`, and a pool that cannot be read makes a tool-using skill `unreadable` (`tools_unreadable`), never eligible. `GET /skills/:uid/assignable` lists every agent the caller manages, any role, each with `eligibility`, and `counts`. `GET /skills` adds `areas` (listed, published, Axal's drafts, the company's drafts, unreadable). `GET /skills/:uid` adds `attach_refusal` and `alternative` (a published skill in the same area, the same output kind first). Every card adds `job` (`customerJob`: the stored description without a final "when …" routing clause or a planning or infrastructure sentence, applied on read because a published version is immutable) and `inputs` (D4667's, null when not recorded); `q` searches the job, inputs and output too.
- **Screens.** `SkillSheets.jsx`'s `SkillPicker` draws the drawer (TMS04–TMS06) and the wizard (TMS07, TMS08) from that answer: the state chip (word, glyph, border), the counts line, search (`/` focuses it) and an area filter that never drop a pick, details in place with Back that keeps the picks, and `emptyEligible`'s explicit empty state with the area that has something to attach. "No other skill of this role yet." is gone. The wizard picks up to three eligible natural-fit skills, names the tools step 3 will ask for, and its Next reads "Next: model and cap, with no skills" when none is picked. Assign to agents (TMS17) draws the same states and counts. The skill page and cards show Needs, You get and Run cost ("Not recorded"); a draft says why it cannot be attached and opens its published alternative (TMS03).
- **Left as they were.** `skillDiscovery.ts`'s `gateOf` (`POST /skills/discover`, SKILL_DISCOVERY_CONTRACT.md) and `skillWorkflow.ts` still gate a task recommendation on the role; `role_mismatch` is now their own code. Moving them is a contract change for their owners, not this picker's. The 26 Nov truncated roadmap text was not found on main, so `customerJob` drops any sentence with an issue or decision number, infrastructure words or catalogue-planning phrases, and a trailing unfinished sentence, whatever its source.
- **Tests.** `cloudflare-worker/test/skill_eligibility_8768.test.ts` (a draft-only Legal area, an eligible cross-area skill at the drawer, Assign and the wizard, an opted-out tool, an unreadable version and tool pool, the job line, inputs and the alternative) and `frontend/test/skill_eligibility_8768.test.mjs` (the six states, the words and counts, the empty state, and the mounted picker and wizard step). The D1612 suites now pin the cross-role attach instead of `role_mismatch`.
