## D7881 — One Worker shard uses the MacBook with bounded hosted fallback (#7881)

### Decision

The owner asked to share Worker CI between the existing M3 Pro MacBook and
standard GitHub-hosted runners, without adding a paid runner. Keep the existing
six Worker parts and their required checks. When repository variable
`MACBOOK_WORKER_ENABLED` is exactly `true`, the hosted `suite (worker-1-of-6)`
job may delegate its existing part to `.github/workflows/macbook-worker.yml`
on `main`. Other Worker parts and all pull-request runs stay hosted.

The Mac is `macbook-m3pro-01` in the `StudioOS MacBook` runner group (ID 4),
with labels `self-hosted`, `macOS`, `ARM64`, and `studioos-macbook`. The group
must allow only the selected StudioOS repository and this exact workflow at
`refs/heads/main`. Its existing branch-scoped benchmark may remain allowed
while rollout verification finishes. No larger GitHub-hosted runner is selected.

### Routing and failure semantics

GitHub does not provide an OR/fallback runner label. The existing hosted job
therefore dispatches a bounded child with its ordinary job token and observes
the actual assigned Mac job. A busy child workflow falls back immediately;
an unassigned Mac has 90 seconds to start, and an assigned Mac has 25 minutes
from job start to complete. The child has a 28-minute job timeout. The selected
parent has 75 minutes to accommodate delegation and the existing hosted test
path, within the current 90-minute merge-queue check timeout.

An unavailable API, offline Mac, refused admission or setup failure takes the
original hosted command. A completed, failed test step remains a failed shard;
it never becomes a hosted retry that can conceal the failure. A pass requires
the exact child's test step, job and run all to pass. Cancellation targets only
the parent's recorded child. The controller persists that ID before polling,
and the child rechecks that the parent is still actively waiting before tests.

This approach retains a hosted controller job while the Mac runs. It can
shorten this shard's execution time, but does not increase the organization's
hosted concurrency quota or allow one registered Mac runner to execute several
jobs at once. The Mac must be awake, connected and running its runner service.

### Source admission and evidence

The Mac workflow is loaded only from `main`. Before checking out the candidate,
it runs admission code from that trusted workflow commit. Admission verifies
the exact active CI run, attempt, source SHA and hosted delegation step twice.
Main-push jobs use the exact parent `suite-plan` artifact. Merge groups must
still have the live queue ref and complete same-repository PR provenance for
every synthetic queue entry; they regenerate the same deterministic equal-weight
plan as the hosted parent. Unverifiable or fork-containing queue groups stay
hosted. Ordinary pull-request workflows never use the Mac in this rollout.

The Mac receives only read permissions for contents, Actions and pull requests,
and no deployment or App credentials. Checkout credentials are not persisted.
Python, npm caches, source and test traces use this run's directories; cleanup
removes only those paths. Native ARM64 Node 22 and Python 3.11 are checked before
tests. Parent event context is restored for the existing driver's queue retry
policy and failure identities. Test traces return to the original parent shard
artifact; observed `ci-failure-id` annotations are mirrored on failures.

### Operation and rollback

After this workflow lands, allow
`AxalNetwork/StudioOS/.github/workflows/macbook-worker.yml@refs/heads/main`
in the selected runner group's workflow access and set the repository variable
`MACBOOK_WORKER_ENABLED=true`. Existing required check names and suite coverage
remain unchanged. Setting the variable to `false` (or removing it) makes future
jobs use the original hosted path. Let an already running shard finish, or
cancel its parent CI run to request cancellation of its owned child.

### Verification

Controller tests cover exact dispatch identity, assignment, bounded fallback,
busy/offline runners, unavailable APIs, cancellation, annotations and real
test failure propagation. Admission tests cover parent liveness, immutable
plans, exact source and complete queue provenance. Workflow tests exercise
source ordering, plan selection, gate behavior, trace transfer, cancellation,
run-scoped cleanup and timeout budgets, including mutation/restoration cases.
Existing suite-plan, merge-queue, runner-lane and workflow-security checks remain
in force.

The preceding native Mac benchmark used the same source commit
`c6d0d48a984847a2b14325c82e9616da4c3dfdcf` and the same 340 Worker test files as
the hosted baseline: 3,540 passed. Run 44729411217 took 13m11.58s in the test
driver and 17m24s for the job; hosted run 44720587048 took 23m29s and 24m07s.
That comparison is indicative: tracing was disabled on the first Mac run,
Node patch versions differed, and cache states differed. Rollout also checks
the real Mac with tracing enabled and the automatic parent/child path.
