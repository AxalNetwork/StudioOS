## D5065 — Operating Systems has one connection-state model (#5065)

Issue: [#5065](https://github.com/AxalNetwork/StudioOS/issues/5065). Parent: #4846.

### What was wrong

Operating Systems derived a connection's state three times — once for the
module rows, once for the tiles and once for the record — and each derivation
collapsed any status that was neither `active` nor `error` into
`not_connected`. The record's subtitle was derived from something else again:
the mere existence of a connection row. A revoked or disabled connection
therefore rendered the pill **Not connected** above the line
"Connected 9 Oct · last good sync 10 Oct". The same record said both at once.

Two further consequences of the same split:

- The record's primary action was always `Reconnect`, so a healthy system was
  told its main job was repair, and a kind that mapped no connection at all
  was told to reconnect a connection it had never had.
- The module card's next action only looked for `status = 'error'`, so a
  mapped-but-unusable system offered no recovery action anywhere. The card's
  Reconnect line also names a date — "failing since 9 Oct" — which is only
  true of a failing system; a revoked connection can still carry the
  `last_error_at` of an earlier failure, so the date is now named only for a
  system that is actually failing.
- Workspace's unavailable fields read "Workspace has no connection row.",
  which sounds like a fault rather than a capability that does not apply.

### The decision

`cloudflare-worker/src/services/systemsState.ts` is the one derivation.
Everything that names a system's state reads it from there: the module rows,
the tiles, the connected count, the list's filter and order, the card's next
action, the record's pill, its State fact, its subtitle, its primary action
and the connector rows.

Four states, replacing three:

| State | Meaning | Primary action |
|---|---|---|
| `connected` | mapped, and the connector reports it active | Manage connection |
| `failing` | mapped, `status = 'error'` | Reconnect |
| `disconnected` | mapped, any other status (revoked, disabled, expired, unknown) | Reconnect |
| `not_connected` | no connection mapped for the kind | Connect, or Choose connector when no connector is named |

`disconnected` is the state the old model had no room for. Its label is
**Reconnect required**, and it is never described as connected. A connection
that exists is never `not_connected`: there is a difference between nothing to
repair and something to repair, and the action a member is offered follows it.

An unrecognised status is reported in general terms — "the connector no longer
reports it as active" — rather than echoed, so a stored value never reaches
the page as copy.

Workspace stays a capability type of its own, and says so: its Last sync, Sync
and Sync log read "Not applicable: a workspace connection records no sync
time." and the like, because a workspace connection is a personal OAuth token
and not a synced connector. It no longer claims a missing row.

### What did not change

The privacy rule for another member's connector (Decision 11) is untouched:
the catalogue name is shown unless the viewer owns the connection, in every
state. The mapping writes, the `/systems/choices` read and the Disconnect
action are unchanged.

### Where it is held

`cloudflare-worker/test/build_systems_states_d5065.test.ts` covers active,
error, revoked, disabled, an unrecognised status, a missing mapping and
Workspace, over the real schema, with every assertion checked both ways.
