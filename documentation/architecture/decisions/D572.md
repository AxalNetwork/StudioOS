## D572 — Partner earnings: a failed payout reopens its commissions, and the fields the screens showed as "Not recorded"

**A failed payout now gives its commissions back.** Migration 393 records
which commissions each payout claimed (`payout_commissions`). Failing a
payout returns exactly those commissions to `accrued` in the same batch, and
records `failed_at`.

The same change adds the backend fields the partner earnings screens (D569,
#1174) read as "Not recorded":
- a currency per payout;
- the processor's name;
- when a payout was moved;
- the role of each sign-up;
- an interaction's outcome;
- an admin route that edits a commission rule.

Issue #1183, first PR (Part of). Migration 393.

**What was true on main (`58c80ef9`).**
- `PATCH /api/network/admin/payouts/:id/process` with `fail` set the payout to
  `failed` and nothing else. Its comment said the commissions were reset, but no
  code did it. Nothing recorded which commissions a payout had claimed, so
  nothing could.
- `POST /api/network/payout/request` ran a three-step race guard. The INSERT
  was conditional, but the UPDATE that marks commissions `paid` was not. When
  one chosen commission was taken between the read and the batch, the INSERT
  wrote nothing, yet the UPDATE still marked the rest `paid`, with no payout
  behind them.
- `payouts.currency` existed and the INSERT never set it, so every payout was
  USD. Balances summed `amount_cents` across currencies.
- The admin queue joined `users` for the requester only, so it had the
  processor's id and no name. No date was kept for processing or failing.
- `GET /referral/list` did not select `users.role`.
- `partner_interactions` had no outcome.
- `commission_rules` had no write route.
- Advisor Studio's Earnings module read `balance_cents` and `lifetime_cents`
  off `payoutsMe()`. On the Worker that is a bare list, so both always read
  "Not recorded". The shape it expected is the dev FastAPI shim's.

**Migration 393.**
- **`payout_commissions (payout_id, commission_id, created_at)`**, one row per
  commission a payout claimed. It is a history, not a pointer: a commission
  reopened by a failed payout and claimed by a later one has a row for each.
- **`payouts.uid`** (unique), so the request batch names the payout it just
  inserted without trusting `last_insert_rowid()` across statements.
- **`payouts.processed_at`** and **`payouts.failed_at`**.
- **`commission_rules.updated_at`** and **`commission_rules.updated_by`**.
- **`partner_interactions.outcome`**: text, at most 200 characters.

The runtime `ensureSchema` blocks in `network.ts` and `partnernet.ts` mirror
it for development databases (D235).

**The payout request** is one batch in which every step depends on the first.
1. The INSERT writes the payout, with its uid and currency, only if every chosen
   commission is still accrued, still this user's, and in that currency.
2. The link rows are written only if the payout with that uid exists.
3. The claim (`paid`) runs only if that payout exists.

So a request that loses a race writes nothing at all.

**Currency.** A payout takes the currency of the commissions it claims.
- **One currency held:** a request that names none takes it.
- **More than one held:** a request that names none is refused with
  `currency_required` and the list of currencies held.
- **A malformed code** is refused with `invalid_currency`.
- **`/commissions/me` totals.** It returns `by_currency` (balance, claimed,
  lifetime per currency). Its old `balance_cents` and `lifetime_cents` stay as
  they were while the account holds one currency. With more they are null and
  `mixed_currency` is true, because a sum across currencies is not a figure.

**Moving a payout** changes only a payout still open for that move.
- **Process:** `requested` → `processing`.
- **Complete:** `requested` or `processing` → `completed`.
- **Fail:** `requested` or `processing` → `failed`.
- **Refused:** anything else is refused with `payout_not_open`. Failing a
  completed payout would give back commissions that were paid. Completing a
  failed one would pay commissions that were given back.
- **What a fail reopens.** A commission is reopened only when it is still
  `paid`, this payout was the last to claim it, and this payout is now
  `failed`. A commission claimed again by a later payout belongs to that payout.
- **Payouts from before 393** have no uid and no link rows. Failing one
  reopens nothing, and the response and the activity log say so
  (`unlinked: true`) rather than guessing which commissions to reopen.
- **The fail response** carries `commissions_reopened`.

**Reads.**
- **`/payouts/me` and `/admin/payouts`** return each payout's `commission_ids`.
  It is null for a payout from before 393, meaning not recorded; an empty list
  would claim it took nothing.
- **`/admin/payouts`** also returns `processed_by_name`.
- **`/commissions/me` and `/admin/commissions`** return each commission's
  `payout_id`: the payout that last claimed it.
- **`/referral/list`** returns `referred_role`.
- **`/admin/commission-rules`** returns `updated_by_name`.

**Editing a commission rule.** `PATCH /api/network/admin/commission-rules/:key`
is admin only, like the read beside it.
- **Body.** It takes any of `amount_cents` (whole cents, 0 to 100,000,000, or
  null), `percentage_bps` (0 to 10,000, or null), `description` (at most 300
  characters) and `active` (true or false). A field left out keeps its value.
- **One way to pay.** After the edit, a rule must pay exactly one of a flat
  amount or a share (`rule_amount_ambiguous` otherwise). `fireCommissionEvent`
  reads the amount first and falls back to the share.
- **Audit.** Every edit is logged through `logAdminAction`, with the values
  before and after. The row records who changed it and when. The client method
  is `adminUpdateCommissionRule`.

**An interaction's outcome.** `POST /partnernet/relationships/:id/interactions`
takes an optional `outcome`.
- Text over 200 characters is refused (`outcome_too_long`), not clipped,
  because an outcome cut mid-sentence can say the opposite of what happened.
- A value that is not text is refused (`invalid_outcome`).
- No outcome is stored as null.

**Advisor Studio.** `pages/advisor/advisorEarnings.js` computes the two
figures.
- **Available balance** is `/commissions/me`'s balance. With more than one
  currency it is shown per currency.
- **Lifetime paid** is the sum of completed payouts from `payoutsMe()`, per
  currency. `/commissions/me`'s `lifetime_cents` counts every commission ever
  accrued, so it is not that.
- **A read in the wrong shape** is "Not recorded", never a zero.
