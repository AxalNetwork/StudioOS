## D4613 — Ask checks its references, shows cited sources apart from retrieved ones, announces itself, and one catalogue add is one shortlist row (#4613)

#4613 (Research audit 5/5, slot S12). This PR is the first part: reference
checking, accessible Ask controls and idempotent adds. The Evidence-scope
disclosure and the Research rail follow the approved #3701 design, and the
router extraction stays with #4574, so the issue stays open.

### References are checked, not verified

`services/researchCitations.ts` reads the bracketed numbers an answer cites
(`[1]`, `[1, 3]`, `[1][2]`, short ranges like `[2-4]`) and checks them
against the sources the model was given. The result travels with every answer,
on `POST /api/research/ask` and on every history read, as `reference_check`:

| `status` | Meaning |
|---|---|
| `resolved` | every reference names a supplied source |
| `invalid_refs` | at least one names a source that was never supplied (`invalid` lists them) |
| `none_cited` | the answer cites nothing by number |
| `no_answer` | nothing was written |

`claim_support` is always `not_verified`. A reference that resolves names the
passage the answer drew on; it is not a check that the passage supports the
sentence, and the page says exactly that under every answer. A claim-level
check needs its own contract and positive and negative fixtures, and is not
built here.

The check is derived on every read from the stored answer and its stored
citations, so answers recorded before this change get it too, and the stored
citations JSON (migration 221) keeps its shape.

### Cited and retrieved are told apart

Each citation now carries `cited: true | false`. Ask lists "Sources cited"
first and "Retrieved, not cited" after; an answer that did not run lists its
passages as "Passages retrieved". A citation with no mark (a payload from
before this change) counts as retrieved, never as cited. The session brief
carries only cited sources into its "Sources:" lines.

### Opening the passage

Each source has an "Open passage" control (the phone kept its buttons). The
sheet says whether the passage was cited or only retrieved, names the indexed
version the answer read (the citation's `revision`, from D4605), and the page,
the passage number and the passage as recorded. A source whose document is
still listed but was indexed again since the answer (its `indexed_at` is not
the citation's `revision`) reads "Re-indexed since this answer", and the sheet
says the document may now say something else. A removed document reads "No
longer available" and offers no link. Unknown on either side is not "changed".
The "Open in Library" link and its owner-only read are unchanged.

### Accessible Ask

The label stays on screen; the placeholder is only an example. The field is
described by a help line and, when a question fails, by the error, which is a
`role="alert"` and marks the field `aria-invalid`. A polite status region
says "Reading your library…" while a question runs and "Answer added to this
session." when it lands (or that it was recorded without an answer). The form
is `aria-busy` while it runs. Ctrl+Enter, or ⌘+Enter, sends from the field;
plain Enter still adds a line, and Tab still reaches the Ask button.

### One catalogue add, one row

Migration `202611092035_research_fund_catalogue_uid.sql` adds `research_funds.catalogue_uid` and a
partial unique index on `(owner_user_id, catalogue_uid) WHERE catalogue_uid IS
NOT NULL`. "Add to my funds" from the directory and from a fund's catalogue
page sends the directory uid; `POST /api/research/funds` writes with
`INSERT OR IGNORE` and answers a repeat with the row the first request wrote
(200, `existing: true`; the first is 201, `existing: false`). The uid is
checked against `[A-Za-z0-9_.:-]{1,80}` before it reaches SQL. A fund typed in
by hand has no catalogue uid, so any number of them stay possible, the same
name included. Existing rows keep NULL and nothing is backfilled, so the index
cannot collide with a row already in production. Both add buttons also hold a
ref latch, so two presses in one frame send one request, and the button reads
"Adding…" until the answer comes back.
