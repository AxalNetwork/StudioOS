## D643 — Sample wellbeing experts are never listed as real

**Issue:** #1438. **Built by:** S07. **Migration:** 433
(`433_wellbeing_sample_experts_inactive.sql`).

### What was true

- **The directory seeded itself on every read.** `ensureSeededExperts`
  (`services/wellbeing/seedExperts.ts`) ran on each `GET /api/wellbeing/experts`
  and `GET /api/wellbeing/experts/:uid`, in production too.
  - It inserted eight sample experts as `verified = 1, is_active = 1`, with
    made-up booking links.
- **They were the whole directory.** On 2026-10-07 production held eight
  experts, all of them samples, and members saw all eight as verified.
- **Nothing marked them.** Neither a member nor the admin roster could tell a
  sample from a real expert.

### What is true now

- **No seed in production.** `ensureSeededExperts` returns before writing when
  `isProductionEnv(env)` holds (`ENVIRONMENT` is `production` or `prod`, the
  rule `util/paymentMode.ts` already keeps). Production lists only experts who
  applied and were verified.
- **Migration 433 sets the eight inactive.**
  - It never deletes them, so an audit can still see they existed and what
    members were shown.
  - It touches only `is_active` and `updated_at`, only on sample rows still
    active, so a re-run changes nothing.
- **A sample is known by its uid.** Every seeded uid starts with `seed_`; an
  applied expert's uid is generated hex and cannot. `isSampleExpert` is the
  rule. The member list's SQL draws the same line with the prefix bound as a
  parameter, and a test holds the two to the same answer.
- **Members never meet one, in any environment.**
  - The member list excludes samples, so `matches`, `total_active` and
    `filtered_count` neither show nor count one.
  - Opening a sample is 404 for anyone but an admin, before a free-tier view
    is spent.
  - Booking one is 404.
- **The admin roster sees them, marked.** Each expert carries `is_sample`. The
  roster draws "Sample" beside the name and counts them in its header.
- **An empty directory says so.** When the Worker reports `total_active: 0`,
  the booking page reads "No wellbeing experts are listed yet." The filters
  line is kept for a directory that has experts and none matching.

### Verified

**`cloudflare-worker/test/wellbeing_samples_d643.test.ts`**, on the real router
and node:sqlite with the baseline's expert DDL:
- **Production** (both spellings): the list read, as a member and as an admin,
  inserts no sample and lists only the real expert. With no real expert the
  list is empty and `total_active` is 0.
- **Development:** the seed writes eight samples, once. A member's list shows
  and counts none. The admin's list marks each. A member cannot open or book
  one, and no view or booking is written. An admin opens one, marked.
- **The uid rule and the member list's SQL** agree on edge cases (`seed_`,
  `seedling`, `Seed_x`, `xseed_y`).
- **Migration 433:** samples go inactive and every other column is unchanged.
  A real row and a hidden sample keep their own values, and no row is deleted.
  A re-run touches nothing, and the seed run again does not revive them.

**`frontend/test/wellbeing_samples_d643.test.mjs`:** the empty-directory
sentence, the filters line kept for a filtered-out list, the page's wiring from
`total_active`, and the roster's "Sample" mark on a sample only.
