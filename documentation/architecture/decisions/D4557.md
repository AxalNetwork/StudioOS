## D4557 — Agent compute: the job, its run grant and its quotas, before the host (#4557)

Part of #4557. #4557 asks for a bounded, isolated container runner for agent
jobs: Python, PDF/Office conversion and spreadsheets. Its host waits on
#4554's compute-boundary decision (D4554), which is not yet written. The owner
answered (2026-11-07):

- **Q1 B:** build the parts that do not depend on the host now, off by
  default and unbound.
- **Q2 A:** the host is a separate Worker owning the container, as the meeting
  bot's is (D886), with its own wrangler file, a cross-script binding and an
  owner-gated deploy. The main `wrangler.toml` and the parity script stay
  untouched.
- **Q3 A:** the Durable Object Container API on the default scheduling policy,
  with `enableInternet: false`. `durable_object` waits for a measured reason.
- **Q4 A:** a job's output is still a proposal, whose payload references an R2
  artifact. A person decides.

### Decision

1. **`agent_compute_jobs`** (migration `202611070924_agent_compute_jobs.sql`)
   is one bounded job of a D1528 run.
   - It records the run, the agent, the scope, the workload, the declared
     inputs (names and sizes), the status, and the grant's `jti` and expiry
     (never the token).
   - It records a bounded outcome: output bytes, artifact keys, CPU and wall
     milliseconds, peak RSS, the exit code and a failure **code**.
   - No column holds a file, stdout, output text or a prompt. Content lives in
     R2 under `agent-compute/<scope_kind>/<scope_id>/<run_uid>/`.
   - The lifecycle stays the AgentTaskWorkflow's: this table is not a second
     scheduler.
2. **`services/agents/compute.ts`** holds the job's whole server-side
   contract.
   - **Off by default.** `computeEnabled` needs `AGENT_COMPUTE=on` **and** an
     `AGENT_COMPUTE_SECRET` of at least 32 characters. Neither is declared in
     any wrangler table, and no route or binding calls this file. Every entry
     point refuses `compute_off`.
   - **Creating a job** (`createJob`) needs a running step of the agent's own
     run. It is idempotent on the dispatch's key: a redelivery is the same job,
     with one charge. A key reused for another run is refused.
   - **Quotas are the server's** (`LIMITS`, per workload): the input count,
     size and file types; the output size and artifact count; and the CPU,
     memory, wall-clock, disk and process limits the host is to apply. A scope
     may have at most **2** live jobs.
     - Input names are one safe segment: no absolute path, `..`, slash,
       backslash, NUL or control character.
     - Archives are not inputs in v1. An Office file is a zip that the
       container opens under its own decompression limit.
   - **The run grant** (`mintGrant`) is short-lived (15 min) and signed with a
     key derived **per job** from the master, so a leaked grant opens one job.
     It names the job, the run, the scope, the workload and the idempotency
     key, and a job is granted once.
   - **A callback** (`verifyGrant`) is refused, before anything is written, if
     it is:
     - forged, or signed with another key;
     - for another job;
     - expired;
     - cross-tenant: its scope, run or key differs from the job's row;
     - for a job that has ended, which includes a late callback after a cancel.
   - **Single use** (`claimGrant`): a conditional UPDATE in D1 spends the grant
     once, so a replay is refused, even a concurrent one. KV's best-effort jti
     store was not enough here.
   - **The result** (`recordResult`) ends a running job once. Artifacts must
     sit under the job's own prefix and within its limits, and the failure is
     a code, never text. A second callback, or one after a cancel, changes
     nothing.

### What waits for D4554

- The host Worker with the Container-owning Durable Object, which applies the
  runtime limits and stops the process on cancel.
- The image, built minimal, non-root, pinned and scanned.
- The authenticated callback route that calls `verifyGrant`, `claimGrant` and
  `recordResult`.
- The loop step that dispatches a job and waits for its event.
- The proposal that references its artifact.
- The size benchmarks.
- The owner-run preview deploy.

### Tests

`cloudflare-worker/test/agent_compute_4557.test.ts` (8 tests) runs on the real
migrated schema. It covers:

- **Off by default:** every refusal, and that no wrangler table names
  `AGENT_COMPUTE`.
- **Input refusals:** traversal, odd names, archive and other types, count and
  size.
- **Job creation:** the run-and-agent scope, an idempotent redelivery, key
  reuse, and a run that is not running.
- **Per-scope concurrency.**
- **The grant:**
  - a forged body, a forged signature, garbage and another master key;
  - another job, an expiry, and a cross-tenant scope;
  - two concurrent claims, of which exactly one wins.
- **The result:**
  - another tenant's prefix, a traversal and another run's prefix of equal
    length;
  - the output cap, the artifact cap, and failure text in place of a code;
  - one record, a duplicate callback, and a late callback.
- **Cancel:** it refuses a later claim and result. A timeout is recorded as
  `timed_out`.
- **Nothing wired:** the index does not import the service, and the table has
  no content column.

Each assertion was mutation-checked both ways (15 mutations).
