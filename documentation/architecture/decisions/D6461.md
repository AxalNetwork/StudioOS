## D6461 — Pull-request workflows: cancel superseded runs, skip drafts where nothing requires them, no `pull_request_target` (#6461)

Part of #5600, plan key A2 ("stop wasting runners"). One push to a pull request started a median of 12 workflow runs, drafts included, and 88 of 112 open PRs were drafts. Runner wait, not test time, was the main delay. `ci.yml` is #6460's (PR #6486), and this change does not touch it.

### What changed

| Workflow | Change |
|---|---|
| `gitleaks.yml`, `landing-policy.yml` | A concurrency group per pull request with `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`. A push to `main` and a merge-queue entry each get their own group (`github.run_id`), so they are never cancelled. `scan` still reports on every PR push, queue entry and push to `main`. |
| `copilot-setup-steps.yml`, `meeting-bot-image.yml`, `release-rehearsal.yml` | The same per-PR group. They were the only pull-request workflows with none. |
| `prompt-eval-gate.yml`, `changelog-gate.yml`, `deck-visual.yml`, the seven `*-contracts.yml`, and `claude-review.yml`'s `selftest` | A draft skips the job (`if: ${{ !github.event.pull_request.draft }}`; `deck-visual` keeps `workflow_dispatch`), and `ready_for_review` is a trigger type, so marking the PR ready runs it. None of them is a required check. |
| `record-page-contracts.yml`, `form-lightbox-contracts.yml` | The folder, decision and dark-mode guard step and the root `npm run build` are gone. See below. |

### The two contract workflows' duplicate steps

The issue allowed dropping them only if `ci.yml`'s `suite (rest)` already runs the same ones. It does:

| Dropped step | Where `ci.yml` runs it on every pull request |
|---|---|
| `node scripts/check-folder-docs.mjs` | `suite (rest)`, through `npm run test:guards` (`package.json`) |
| `node scripts/check-decision-ids.mjs` | `suite (rest)`, through `npm run test:guards` |
| `node scripts/check-dark-mode.mjs` | `suite (rest)`, the last step of `test:drift` |
| `npm run build` | every `suite (…)` part, step "Build the SPA", before its tests |

`rest` is what `scripts/test-drift-parts.mjs` leaves unsharded from `test:drift`. `ci.yml` has no path filter, so it runs on every pull request. `frontend/test/generated_before_build_5612.test.mjs` now pins both halves:
- the contract jobs keep their own contract tests and no longer carry the guards or the build;
- `test:drift`'s `rest` part and the suite job still run them. It checks this by calling `partsOf` on `package.json` and reading `ci.yml`'s suite steps.

### `pull_request_target`

`claude-review.yml` already runs on `pull_request`, as its header says, with the reviewer checked out from the base commit and the PR head checked out as data only. No workflow is triggered by `pull_request_target`. So GitHub's 2026-12-02 default block on public repositories changes nothing here, and no owner policy is needed. The new test keeps it so.

### What runs on a draft, and why

`frontend/test/workflow_runners_6461.test.mjs` reads every workflow, and fails if:
- a workflow that a pull request starts has no cancel-in-progress group;
- a workflow that also runs on push, merge queue or schedule cancels anything but pull-request runs;
- a workflow not listed below runs a job on a draft, or does not run again on `ready_for_review`;
- the required `scan` or `applied migrations unchanged` skips drafts;
- any trigger is `pull_request_target`.

The list is exact, so an entry for a removed file fails.

| Runs on drafts | Why |
|---|---|
| `ci.yml` | #6460's (draft tiering) |
| `gitleaks.yml`, `migration-immutability.yml` | required checks |
| `codeql.yml`, `semgrep.yml` | D5602, out of scope |
| `landing-policy.yml` | reports the landing tier; concurrency only |
| `agent-compute-image.yml`, `meeting-bot-image.yml`, `release-rehearsal.yml`, `copilot-setup-steps.yml` | path-filtered to their own files |
| `claude-review.yml` job `review` | the reviewer applies `CLAUDE_REVIEW_DRAFTS` itself |
| `pr-preview.yml` job `delete` | runs only on close (its `deploy` already skips drafts) |

### What a skipped job saves

A job-level `if` still records a workflow run, so a draft head shows the same number of runs as before. Each skipped one is a completed run with no runner job. The saving is in runner jobs, which is where the wait was. The PR body gives the hosted count for a draft head and a ready head.

### Tests

- The new `workflow_runners_6461.test.mjs` (3 tests) applies ten in-test mutants, all refused. Six more mutants were run against the workflow files: five caught, and one equivalent, because a dispatch run of `meeting-bot-image` sits in its own `run_id` group, so `cancel-in-progress: true` cancels nothing.
- `generated_before_build_5612.test.mjs` now checks the comparison above, with its own refused mutants. Every other test that reads `.github/workflows` passes.
