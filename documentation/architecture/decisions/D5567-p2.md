## D5567 part 2 — the acceptance matrix, held against the real Worker bridge (#5567)

**Status:** S14, 2026-11-16. Tests and this record only: no runtime change, no migration, no binding, nothing switched on.

### What changed since part 1

Part 1 (#5693, carried to main by #5692) landed `workspaceSecurity.ts`. Its tests stub the service's dependencies. The second slice described in the 2026-11-13 STATUS was a SQLite grant/runner store and a D1 run/sponsor scope bridge. Its local commit never reached GitHub, and #5733 (D4557 part 2) has since landed the same seams on main by another route:

- **The atomic store.** The compute host's Durable Object backs `WorkspaceSecurityStore` with `ctx.storage.transaction`, and erasure tombstones it (`agent-compute/worker.ts`).
- **The D1 bridge.** `authorizeCompute` (`computeBridge.ts`) re-reads the following from D1 at every issue and redemption:
  - the user is active;
  - the agent's sponsor and status;
  - the run's status;
  - the task, the scope and the company;
  - read access;
  - the global halt and the engine mode;
  - the execution generation;
  - the exact spec and sponsor recorded at admission.
- **Audit.** `computeInternal('audit')` writes a durable `activity_logs` row.

So that slice is not rebuilt here. What the issue's first acceptance line still lacked was the matrix itself, run against this real wiring rather than stubs.

### The matrix

`cloudflare-worker/test/workspace_security_matrix_5567.test.ts` has one test per acceptance case. Each runs through `_compute_world_4557.ts`: the real `createWorkspaceSecurity`, the host's store, `authorizeCompute` and `computeInternal` over migrated SQLite.

| # | Case | What is held |
| --- | --- | --- |
| 1 | Cross-venture | Another company's sponsor is refused at registration and by the bridge. A run the host never registered gets no grant. |
| 2 | Revoked sponsor | A grant issued before the sponsor is disabled does not redeem, and no new grant is issued. |
| 3 | Forged callback | A changed signature, or a payload re-signed with another member, is refused. The untouched grant still redeems once. |
| 4 | Expired token | A grant at its expiry does not redeem (clock mocked, never slept). |
| 5 | Nonce replay | Two racing redemptions: exactly one succeeds. A third is a replay. |
| 6 | Late attempt | The host cannot advance a generation D1 has not recorded. Once D1's generation moves (as a cancel does), the old grant is dead under either generation. An advance cannot change the attempt. |
| 7 | Path traversal | No grant is issued for an object reference outside the opaque form (`../`, absolute, backslash, empty). |
| 8 | Metadata, localhost, egress | The compute spec admits no destination: metadata addresses, localhost, loopback, a credentialled URL, or an ordinary public host. |
| 9 | Leaked credentials | A grant's payload holds exactly the documented claims, and never the control secret. Another deployment's host, another audience and another object reference each refuse it. |
| 10 | Privilege escalation | An operator cannot take a runner or artifact audience. A stranger is not an operator. Publishing stays shut, because the bridge never reports an approval. |

**Mutation check:** 11 mutations across the service and the bridge, 11 caught. They removed:

- the expiry check;
- the replay check;
- the signature check;
- the operator-audience check;
- the sponsor-scope check;
- the object binding;
- the audience binding;
- the D1 generation fence;
- the active-user check;
- the recorded-sponsor check.

The eleventh reported publish approval.

### Still open, for the owner or a later part

1. **The permission revision was a constant.** `authorizeCompute` answered `revision: 1`, so a sponsor revoked and re-granted inside one grant's life kept it. The owner chose to close it; D5567 part 3 does, with per-member revision triggers.
2. **Refusals are not audited.** Only issued, redeemed, revoked and advanced grants write an audit row.
3. **Operator control grants fail closed in the real wiring.** The bridge requires the recorded sponsor, so a separately authorized operator's status, cancel or cleanup ticket is refused. That is safe, but the D5567 operator path does not work yet.
4. **No tenant-keyed encryption on this path.** The host never seals: `encryptionKey` answers null. Inputs are read by the Worker from R2 and handed over after redemption. #5568 owns the checkpoint and object lifecycle.
5. **Hosted proofs.** These still need #5566's coding sandbox:
   - containment (microVM or gVisor class);
   - the connect-time egress fence;
   - residency;
   - an SBOM and scan for a published coding image.

   Case 8 tests the broker's preflight, not a network.
