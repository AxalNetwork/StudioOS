## D577 — Coaches get their own Eadwyn profiling conversation

Issue #1190; owner chose B, relayed by S1 on 2026-10-06.

An advisor with an active paid listing (`advisors.is_active = 1 AND
hourly_rate_usd > 0`, linked by `user_id`) receives the coach conversation.
This matches Best-Fit. Free, unpriced, negative-rate or inactive advisor
listings receive the advisor conversation. Other account roles and pending
Explorer tracks retain their existing routing. A failed listing read fails the
request rather than silently selecting another conversation.

This is an Eadwyn conversation persona, not a new account role. The coach
conversation delivers the existing `fitCoach` bank only; the advisor
conversation retains advisor onboarding and delivers `fitAdvisor` only.
Completion and adaptive selection use each bank's unchanged module floors.
No question, permanent ID, scoring measure or bank is edited; no migration.
Coach reflection copy uses Eadwyn's voice and never calls Eadwyn an advisor.

Dropping a coach's hourly rate to 0 moves them to the advisor conversation;
raising an active advisor's rate above 0 moves them to the coach conversation.
The persistent chat can change persona in place, retaining its transcript.
Both sets of committed answers remain in the original ledger rows. For these
two personas, delivery, the Completed list and progress read the member's
latest captured answer or skip per ID across conversation restarts, scoped to
the delivered bank. Legacy coach answers collected in the pooled advisor
conversation therefore appear in the coach conversation and are not asked
again merely because routing changed. Other users' answers never carry over.
Failed writes do not replace a captured answer. Existing D358 dated re-asks
remain in place; this change does not reset answers or their dates.

The coach bank has no illustration question. Its existing account-wide
illustration choice is preserved; this routing change does not add a question.
The existing frontend renders the server persona and bank, so no new layout or
frontend API is needed. Production changes require owner review and deployment.
