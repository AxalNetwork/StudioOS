## D669 — MCP authorization, interview registration and bounded transcript processing

Issue: #1517. Extends D665–D668 and D658. Owner-directed implementation by S18 (the issue carries S19).

### Scope and ids

All six tools register on the stateless MCP server through callTool. Each requires its own token scope from the provider's ctx.auth.scope: validate:read for the three reads, validate:write for the three interview tools. A write scope does not silently imply read. No requested recognized scope means refusal, never a grant of both. Account activity, deletion and jwt_min_iat are re-read before every handler. The OAuth client id is persisted on grant props for attribution and quotas.

Every number in the consent companies list and grant is projects.id. submit_interview writes that exact project. A session must have session.project_id in the grant. No company_id crosswalk, user_company_links lookup or alternate project can redirect a write. The D667 fixture includes an unrelated company with the same numeric id as a granted project.

Grant choices are limited to ventures the person owns (`ownsVenture`); staff's broad board read cannot authorize a connection to an unowned venture. Co-founder membership alone does not establish ownership under that rule. Reads during each tool call still follow the app's `canReadBoard` rule, and writes keep `canWrite`. This decision does not widen Validate's access policy.

### Consent

The page shows the full redirect URI, the client's name as given, the scopes actually requested and a separate assistant identity label. Exact callback recognition is centralized; unknown callbacks remain connectable but say Unverified assistant. A support JWT carrying impersonated_by cannot approve or deny. Approving a second project keeps earlier grants via revokeExistingGrants: false.

ChatGPT's current stable callback and callback-id path come from [OpenAI's authentication documentation](https://developers.openai.com/plugins/build/auth). Claude's callback is documented in [Google Cloud's Claude MCP setup](https://docs.cloud.google.com/mcp/configure-mcp-ai-application). Google documents Gemini Enterprise's exact callback in its [custom MCP setup](https://docs.cloud.google.com/gemini/enterprise/docs/connectors/custom-mcp-server/set-up-custom-mcp-server). Grok's callback is supported by the integration's [registration instructions](https://uptimepage.dev/mcp-server/grok) and directly checked at [Grok's live sign-in completion endpoint](https://grok.com/connectors-oauth-exchange-code/), which canonicalizes the trailing slash; both exact paths are recognized. The consumer [Gemini setup](https://support.google.com/gemini/answer/17209137) still publishes no exact callback: unlisted consumer/desktop callbacks remain Unverified assistant. Callback recognition establishes the destination, not an endorsement of the self-declared client name.

Revoking a grant reaches other edges within about a minute, subject to Cloudflare KV propagation, rather than at once.

### Limits

- Dynamic registration: seven days, with the provider's renewal while in use.
- Before OAuth routes enter the provider: register 10/IP/minute, authorize 30/IP/minute; counter failure refuses. KV throttles are best effort across edges.
- Submit: 20/client/user in the last day. The count and session insert are one conditional SQLite statement. A quota refusal cleans up the temporary interview row.
- Assistant proposals: 100 pending run placements/session and 500/user in the last day, including decided rows. Each insert checks both counts atomically; dropped quota rows are reported. The daily proposal count follows the proposing user across all sessions and clients, so targeting another client's or an app-created session cannot escape it.
- Transcript: 100 KB total text/speaker bytes, at most 12 parts/model-router calls per structuring or ask run. The AI router's own bounded fallback may try an alternate per call. Refuse oversized runs before spending.
- Existing per-grant 60 calls/minute remains.

### Transcript and evidence

Speaker and text whitespace are flattened inside each segment. Each model message places the transcript between unique delimiters and the system prompt names it untrusted data, never instructions. A placement supplies a verbatim quote. quoteSpan finds its stored location, permits at most three segments, and requires the supplied cite to match; fabricated timestamps or paraphrases cannot become evidence. Both assistant and StudioOS paths share that locator.

The Validate fill band reads only pending rows with run_id IS NULL. Interview review evidence includes the hypothesis code/claim and pain-group title. Accept refuses an existing link whose strength would change, leaves its proposal pending, and points to Experiments; a fresh link's strength write uses compare-and-set.
