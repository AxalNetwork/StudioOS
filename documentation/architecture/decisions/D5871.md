## D5871 — "Create the meeting for me" in the event editor (#5871)

D3724 gap 13, board NE1. For an online or hybrid event, the host presses
"Create the meeting for me · Google Meet" beside the join link, and the event's
meeting link becomes a Google Meet link made on the host's own connected
Google account.

### The link is made inside the Save

There is no separate "create" route. The press asks the editor's next Save to
make the link: the Save sends `add_meet: true` on `POST /api/events` (a new
event) or `PATCH /api/events/:id` (a saved one). The client method is
`eventsApi.saveWithMeet(id, data)`. This is how New IC meeting and New check-in
already use `makeMeetLink` (D1211, `routes/calendar.ts`):

1. Every field of the save is checked first.
2. `makeMeetLink` makes the Meet event on the caller's Google account. It uses
   the event's title, start and length as they are being saved. The length runs
   from start to end, or is one hour when no end is set, and is clamped to 5
   minutes to 24 hours. If Google refuses, the save stops, nothing is written,
   and the editor shows the helper's own sentence (`MEETING_ERRORS`).
   `meet_not_connected` and `meet_reconnect` add a "Connect Google" link to
   `/account/connectors/google`.
3. The row is written with the Meet link as `location_url`, replacing any typed
   link. If that write throws, the helper's `undo` deletes the Meet event, and
   the error is passed on.
4. The Meet event is recorded as the host's Google copy of the event
   (`calendar_sync_records`, `event_hosted`). If the host already had a Google
   copy of this event, from an earlier sync or an earlier Meet, the new one
   replaces that record, and the old Google event is deleted on a best-effort
   basis. This keeps one copy, not two. Replacing the record also clears any
   failed-delete stamp, so the retry job does not delete the new Meet event.

A separate create-then-save route could leave a Meet event behind in a common
case: the host presses, then leaves without saving. Making the link inside the
Save means a link exists only for an event that was saved with it.

A new event that has not been saved yet can use the press too. The link is made
with the editor's title, start and end when the event is created, under the
same rule as creating any event: a signed-in member, who becomes its host.

### Who may ask

- Only the event's host (`host_user_id`). An admin can still edit the event
  under `canManage`, but cannot make a meeting on their own account for someone
  else's event: `403 meet_host_only`.
- A support session is refused (`403 support_session_refused`). This covers an
  impersonation token and a branch support token (`supportOperatorOf`).
- Not an in-person event (`400 meet_in_person`). The format being saved
  decides. Not a cancelled event (`409 meet_event_cancelled`).

The editor offers the press only when the format is Online or Hybrid. NE1 draws
Zoom greyed beside the press. The editor shows Zoom as words ("Zoom: not
available yet…") with no button, and does not show Teams at all.

### Time change and Cancel

This follows what the existing calendar code does for its own Meet links. The
Meet event is the host's Google copy of the event, so:

- **Cancel** (`POST /:id/cancel`, and the admin desk's cancel) removes it from
  the host's Google Calendar. The event's existing calendar cleanup
  (`cancelEventCalendarCopies`, D1131) deletes every `event_hosted` copy, with
  its retries. There is no event delete route, so Cancel is how an event is
  removed.
- **A time or title change** does not move the Meet event when the change is
  saved. The events PATCH has no copy hook today, unlike the IC reschedule's
  `onAxalSessionUpdated`. The copy hook would find nobody to copy to for an
  `event_hosted` item anyway. The link itself still works. The host's next
  "Sync to Google" (`syncUserToGoogle`) updates that same Google event to the
  event's time and does not add a second one, because it is the recorded copy.
  Moving it as soon as the change is saved is left for a later change to the
  events copy hook.

### What is not exposed

The join link stays where `location_url` already was. It goes to the host and
admin through `includePrivate`, and to holders of a confirmed seat. It never
goes to the social card, the editor's previews or the public reads. One related
change: an in-person event's `location_url` is public, and the editor hides the
field for that format. So the editor now saves an in-person event with no
`location_url`. A Meet link made while the event was online is not published if
the host later switches it to In person.
