## D8258 — Raise overview: source freshness and a disconnected state for connected tools (#8258)

- **Status:** built 2026-11-22. A follow-up of #6046 (D6046, "To file", third item).
- **Read:** `GET /api/cycles/raise/overview`'s `connectors` (D1610 W3), as `connectors()` in `cloudflare-worker/src/services/raiseCycle.ts` builds it. No new route, client method or migration.

### What changes

**Worker.** Each row keeps `key`, `label`, `fact`, `as_of` and `state`, and adds:
- `fresh_within_hours`: the source's freshness window (`FRESH_WITHIN_HOURS`);
- `freshness`: `fresh`, `stale` or `not_recorded` for a connected source, null for any other.

**The windows:**

| Source | Window | Why |
|---|---|---|
| Mercury | 48 hours | Balances sync daily, so a read older than two days missed a sync. |
| GitHub | 168 hours (a week) | Contributors change slowly and are synced on use. |
| Google Workspace | 168 hours (a week) | The chosen files change slowly and are synced on use. |

**`sourceFreshness`:**
- A stored timestamp with no zone is read as UTC, as D1 writes it. A bare day is read as its midnight.
- A read exactly at the window is still Fresh.
- No last read, or one that is not a time, is Not recorded, never Fresh.

**`state` gains `disconnected`.** The connection itself is lost: with no active connection serving the venture, one of its founder's or accepted members' connections to that provider is `error` (the provider refused its token, as Mercury's and the MCP clients' writers record it) or `disconnected`.
- A `paused` connection is the member's choice and stays Not connected.
- So does another founder's lost connection.
- An active connection serves the venture even when another member lost theirs.

**`unreadable` is unchanged:** a source that could not be read just now. Disconnected and Unavailable are two states, and the Worker never sends one for the other.

**Status page.** The Raise status page (`raiseStatusPage.ts`, D6897) gains the word "Disconnected" for that state, so a shared status never prints an undefined word.

**Frontend (`raiseOverviewModel.js` `sourcesView`, `windowWords`; `RaiseOverviewLead.jsx` `RaiseConnectedEvidence`):**

| Row | Drawn |
|---|---|
| Connected, Fresh | "Fresh" beside "Read <time>" |
| Connected, Stale | the shared Stale chip (`StateChip`, #5129), with the age from the last read, and the window said to a screen reader ("Older than 1 week.") |
| Connected, Not recorded | "Last read · Not recorded", never a date or 0 |
| Disconnected (RA-09 Source disconnected) | "<Source> was disconnected. Its figures are not read until it is reconnected.", Disconnected, and Reconnect to the connectors page for a viewer who may act. A read-only (staff) viewer sees the state, without Reconnect. |
| Could not be read (RA-06) | Unavailable with Try again, as before |

Two rules keep old or unknown values honest:
- An unknown state is Unavailable, never Connected.
- An unknown freshness is not drawn. An older read with a last read but no freshness shows the last read only.

A disconnected source counts as something to show: the "nothing connected" message is only for every source Not connected.

### Departures from the canvas

| Canvas | Here | Why |
|---|---|---|
| RA-09: "[Mercury] was disconnected. Runway is shown as of [2 Nov], not now." | "Mercury was disconnected. Its figures are not read until it is reconnected." | The read does not keep the lost connection's last fact. It reads only through an active connection, so it has no "as of" to give. |
| RA-06: "! Unavailable · Reconnect" on a source that could not be read | Unavailable with Try again; Reconnect only on a lost connection | The issue's rule: a failed read is not a lost connection. |
| "Fresh · Read 14:05" | "Fresh" and "Read <stored time>" | `lastRead` (D1466) shows the stored time as written; this changes no wording of it. |

### Rollback

Revert the PR. The rows lose the two fields, and a lost connection reads Not connected again. No stored data changes.
