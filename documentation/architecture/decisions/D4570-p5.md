## D4570 part 5 — Exports and downloads (#4570)

#4570 slice 5, after slices 1 to 4 in `D4570.md`. The ledger's next high-risk kind after writes is exports, downloads and signed links: the routes that hand a record out as a file, or serve the bytes behind a link that is its own credential. Ten entries move from `unreviewed` to `verified`, each covered by a negative tenant and role test in `cloudflare-worker/test/authz_exports_downloads_d4570.test.ts`. No product code changes.

### The family

Two groups. In the first, a session asks and the record says who may have it. In the second, there is no session: a token is the credential.

| Route | Who is let in | Who is refused, and how |
| --- | --- | --- |
| `GET /api/competitors/:id/export` | the analysis's owner | every other account, an admin and the Super Admin included: 404, the answer a missing id gets |
| `GET /api/deck-reviewer/:id/export` | the review's owner | the same |
| `GET /api/wellbeing/resources/:uid/file` | any member, for a published resource; an admin, for a draft | every non-admin, for a draft: 404, the answer a missing file gets, before any object is opened |
| `GET /api/learning/webinars/:uid/calendar.ics` | as `canSeeLearning`: an open published webinar, any member; a program webinar, a member actively enrolled in a published program holding it; a draft, the Super Admin | the unenrolled, a member whose enrolment was removed, an admin on a draft: 404, the answer a missing webinar gets |
| `GET /api/calendar/feed/my-events.ics` | the holder of the owner's current my-events address | a replaced or unknown address, the whole-calendar address, a disabled owner's address, an address made before "sign out everywhere", and any session without an address: 404, one answer |
| `GET /api/calendar/feed/calendar.ics` | the holder of the owner's whole-calendar address | the my-events address, an unknown address, any session without one: 404, one answer |
| `GET /api/decks/print-export/:token` | the holder of a print token | a forged, expired or tampered token, another route's token, any session with a bad token: 403, one answer |
| `GET /api/market-intel-public/publications/download/:token` | the holder of a publication token | the same, plus a token for a key outside `publications/`: 403, one answer |
| `GET /api/monitoring/analytics/download/:token` | the holder of an analytics token | a forged, expired or tampered token, the print and source tokens, any session with a bad token: 403, one answer; a publication token: see the hardening item |
| `GET /api/learning/stream/source/:token` | the holder of a source token, for the upload the item plays now | a forged, expired or tampered token, another route's token, a token for an upload the item no longer plays, a token for an item that plays a link: 404, one answer |

On the four signed-in routes, no credentials get 401, and so does a disabled owner asking for their own record. For the feeds and the four links, a session is no credential: every account's session with no token, or a bad one, gets the route's own refusal.

### The cases

The suite asks each route through `worker.fetch` on the migrated schema. Every person, record, key and byte is synthetic. The callers:

- **Non-parties.** Another venture's founder, another deal's investor, an unrelated Operating Partner, and an advisor whose grant on the venture was revoked and whose program enrolment was removed.
- **Admins.** An admin and the Super Admin, where the record is the owner's alone.
- **Owners who lost access.** A disabled owner, and an owner who pressed "sign out everywhere" after making a feed address.
- **No credentials.**

The tokens are the route's own valid one (rightful), and against it: forged (signed with another key), tampered (a payload field swapped under the original signature), expired, replaced, wrong scope, outside the key prefix, and each other route's valid token.

For every refusal:

- the status is the gate's, and each route gives one answer to everyone it refuses;
- where the route answers not-found, a non-party's answer for a real record equals its answer for an id that does not exist;
- the body and the `Content-Disposition` header name nothing: no title, no file name, no bytes;
- nothing changes. The suite compares before and after: the analyses, reviews, resources, webinars, registrations and enrolments, video items and decks, the feed tokens with their last-used stamps, the audit rows, the activity rows the route writes, and the notifications;
- no stored object is opened. The fake bucket records every `head` and `get`;
- no outbound call is made.

The last case runs the rightful party on every route: the owner's two exports, a published file to another member, a draft to an admin, each webinar to the member who may see it, each feed at its own address, and each link's own token. That proves each refusal is the gate and not a missing record, and that a rightful download does open its object, so the "nothing opened" checks above mean something.

**Mutation checks.** 22 of 22 were caught. Each was seen red, then restored:

- the competitor and deck-review loaders' `user_id = caller` binding removed, one at a time;
- the competitor export's `requireAuth` replaced by a fixed owner;
- `getCurrentUser`'s `is_active` refusal removed;
- the wellbeing draft rule removed;
- the webinar route's visibility test removed;
- `enrolledSql` reading a removed enrolment as active;
- `canSeeLearning`'s draft rule widened from the Super Admin to every admin;
- the feed reader's scope binding, its `is_active` test and its "sign out everywhere" test removed, one at a time;
- the print token's signature test and expiry test removed, one at a time;
- the publication token's signature test, expiry test and `publications/` prefix lock removed, one at a time;
- the analytics token's signature test and expiry test removed, one at a time;
- the source token's signature test and expiry test removed, one at a time;
- the source route's `r2_key` match and `video_source = 'r2'` test removed, one at a time.

One mutation was found equivalent and is not counted: removing the print token's `deck-print` tag test. Every other token the Worker signs with that key either fails its signature or names no deck id, so no case can tell the two apart.

### Hardening items, for the owner

Neither item is exploitable as the code stands. No product code is changed here.

1. **The analytics download token is not bound to its purpose.** Its payload carries no purpose tag. Its key is the Worker's shared signing key used as is, and the token has no storage-prefix lock. An expiry that does not parse as a number reads as never expired. So a token minted for another purpose under the same key can pass its signature test. The suite shows this with a publication token: it passes and names no stored object, so the route answers 404 where its own refusal is 403. Nothing is served. No signer in the Worker today writes a payload under that key that a caller could steer to a stored object.
   - Remediation class: a purpose-derived key and a purpose tag (as the video source token already has), a prefix lock, and an expiry that must parse.
   - The print and publication tokens check a tag, so they are not affected in the same way. Their expiry reads the same lenient way.
2. **Refusal status classes differ across the links.** The print, publication and analytics links refuse with 403. The video source link and the feeds refuse with 404, the answer an unknown path gets. Each route is uniform within itself, so nothing leaks. A shared rule would let one negative test cover them all.

### Coverage gaps

- **The exports' contents.** The suite asks each export in Markdown and checks that the owner's export carries the record. The JSON format, the feeds' event selection (D1033, D1209) and the print page's image copies and notes options (D1112) are covered by their own suites, not here.
- **Range requests.** The file and video routes answer a byte range. The range is read only after the gate, and the refusals here ask for whole files.
- **Admin reach is by design.** An admin reads a draft wellbeing file, and the Super Admin sees a draft or program webinar. The suite checks that they succeed, and does not question the rule.
- **Routes of this kind left out.** Some are held elsewhere:
  - the cap table CSV export stays with the item already with the owner privately (slice 3);
  - the data-room shared evidence read is a JSON projection, not a file. D1265's suite covers it;
  - the deck share NDA text, the public event and article images, the import templates and the e-signature links are not exports, or are a family of their own.

  One more download route was found during this slice. It is with the owner privately, and its ledger entry stays `unreviewed`. Remediation class: a revocation must take effect on every read path that the revoked access opened.
