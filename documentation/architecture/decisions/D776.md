## D776 — Each account's AI consumption, where it was spent: a member's Usage page by page and option, and HQ's AI allowances

- **Status:** filed by S1 for the owner (2026-10-19) as #2093, task H1 of D720 (#1874, §4 and §12). PR 1 is built; PR 2 waits on the "AI allowances" design (`needs-design`).
- **Basis:** `origin/main` at `48b77062e9`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D762 (`charged_microusd`, `reservation_uid` and the rail columns, migration 493), D763 (guard rows in the run's own hold, `guard_for`) and D629 / D755 (the hold's allowance and token amounts, migration 419).
- **Read by:** D769 (the rail's Usage box links its "This month" line here) and PR 2's HQ cards.

### 1. The decision

A member sees where their AI money went: this month, by the AI rail's page, then by option within a page, with how much came from the allowance and how much from tokens. HQ sees the same for one member (PR 2), from the same read scoped by `user_id`.

### 2. PR 1, as built

1. **`GET /api/ai-budget/runs?group=page|option|record&month=YYYY-MM`** (`routes/ai_budget.ts`, `services/aiConsumption.ts`). Signed in; the member's own rows only (`user_id = ?`, and the join to `ai_budget_reservations` also requires the hold's `user_id`). `group` defaults to `page`, `month` to the current UTC month; anything else is 400 `invalid_group` / `invalid_month`. A store that cannot be read is 503 `ai_runs_unreadable`, with no raw error.
2. **What each group sums.**
   - `runs`: the runs, not their guard checks (`guard_for IS NULL`).
   - `charged_microusd`: every row's own charge, guard rows included (D763 bills them in the run's hold, each recording its share). A NULL charge (a row before 493, a run held for a D640 review) is counted in `not_recorded`; a group whose every row is NULL reads `charged_microusd: null`, never 0.
   - `allowance_microusd` and `tokens_microusd`: the hold's `actual_included_microusd` and `actual_topup_microusd`, read once per hold through the run's own row. A guard row shares the hold and the page, so joining it too would count the hold twice. A hold not yet settled has NULL actual amounts (419's CHECK) and adds nothing.
   - `totals` over the whole month, and at most 200 groups, the largest charge first, with `truncated`.
3. **`/account/usage`.** The "Where it went this month" card gains a third view, **Charged**, beside By page (estimated cost by surface, D641) and By task. It reads `group=option` only when opened, folds options into their pages (`chargedPages`, `usageModel.js`), and shows each page's charge, its options, and "From your allowance $x · from tokens $y". "Not recorded" stands for a missing charge and for runs with no page; a real zero is shown as $0.00.
4. **Links.** A page links only when its key is an app path (`/build/roadmap`). D720's page keys (`Founder · Validate · …`) are shown as written until its page map (`railPages.js`, §8) lands; the same helper then turns them into links.
