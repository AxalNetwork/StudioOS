## D776 — Each account's AI consumption, where it was spent: a member's Usage page by page and option, and HQ's AI allowances

- **Status:** filed by S1 for the owner (2026-10-19) as #2093, task H1 of D720 (#1874, §4 and §12). PR 1 is built (#2129). PR 2 is built from the "AI allowances" design S1 released on 2026-10-19 (`design/canvases/integrated/Ops · Boards.dc.html`, `screens['hq-allowances']`).
- **Basis:** `origin/main` at `48b77062e9`. Worker paths are relative to `cloudflare-worker/src/`.
- **Stacks on:** D762 (`charged_microusd`, `reservation_uid` and the rail columns, migration 493), D763 (guard rows in the run's own hold, `guard_for`) and D629 / D755 (the hold's allowance and token amounts, migration 419).
- **Read by:** D769 (the rail's Usage box links its "This month" line here) and PR 2's HQ cards.

### 1. The decision

A member sees where their AI money went: this month, by the AI rail's page, then by option within a page, with how much came from the allowance and how much from tokens. HQ sees the same for one member (PR 2), from the same read scoped by `user_id`.

### 2. PR 1, as built

1. **`GET /api/ai-budget/runs?group=page|option|record&month=YYYY-MM`** (`routes/ai_budget.ts`, `services/aiConsumption.ts`). Signed in; the member's own rows only (`user_id = ?`, and the join to `ai_budget_reservations` also requires the hold's `user_id`). `group` defaults to `page`, `month` to the current UTC month; anything else is 400 `invalid_group` / `invalid_month`. A store that cannot be read is 503 `ai_runs_unreadable`, with no raw error.
2. **What each group sums.**
   - `runs`: the runs, not their guard checks (`guard_for IS NULL`).
   - `charged_microusd`: every row's own charge, guard rows included (D763 bills them in the run's hold, each recording its share). A NULL charge (a row before 493, a run held for a D640 review) is counted in `not_recorded`; a group whose every row is NULL reads `charged_microusd: null`, never 0.
   - `allowance_microusd` and `tokens_microusd`: the hold's `actual_included_microusd` and `actual_topup_microusd`, read once per hold through the run's own row. A guard row shares the hold and the page, so joining it too would count the hold twice. A hold not yet settled has NULL actual amounts (419's CHECK) and adds nothing.
   - `totals` over the whole month, and at most 200 groups, the largest charge first, with `truncated`.
3. **`/account/usage`.** The "Where it went this month" card gains a third view, **Charged**, beside By page (estimated cost by surface, D641) and By task. It reads `group=option` only when opened, folds options into their pages (`chargedPages`, `usageModel.js`), and shows each page's charge, its options, and "From your allowance $x · from tokens $y". "Not recorded" stands for a missing charge and for runs with no page; a real zero is shown as $0.00.
4. **Links.** A page links only when its key is an app path (`/build/roadmap`). D720's page keys (`Founder · Validate · …`) are shown as written until its page map (`railPages.js`, §8) lands; the same helper then turns them into links.

### 3. PR 2, as built

HQ › AI allowances (`/admin/platform/allowances`) keeps D642's plans and held runs and D755's packs, member account and reconcile cards. The canvas draws the plans and the held runs, which D642 already built to it. Its not-recorded line ("Set by: this plan uses the platform default…") stays in D642's plural wording, because the page draws it once under all ten plans. The canvas draws no card for the three below, so they follow the board's own card pattern (`pages/hq/HqAiCards.jsx`, words in `hqAiModel.js`). Nothing in them writes.

1. **`GET /api/ai/catalogue/hq`** (`routes/ai.ts`, beside D760's `/catalogue`; HQ's Admin or Super Admin, a branch's administrator 403). It lives there rather than in `ai_budget.ts`, whose D755 reads may never print a markup (`ai_credits_reads_d755`). It returns:
   - `billing`, from the Worker's own `billingMode`;
   - `markup` (`AI_MARKUP`);
   - `set_by: 'AI_BILLING'`;
   - each offered model (`catalogueFor`, D760), priced at cost and at what a member is billed (cost × `AI_MARKUP`), with `paid_only` and `pages`. `pages` lists every D764 matrix row, page or option, whose models name it.
2. **How members are charged.** "At Cloudflare's cost" or "Cloudflare's cost × 1.25". It says the owner sets it through `AI_BILLING`, never this page. It also says HQ's token margin counts token spend only, because the plan's price already pays for allowance draws (D762).
3. **Models offered.** Each model shows:
   - its kind;
   - cost and billed per unit;
   - "Paid billing only";
   - "New";
   - "Named on …" for the pages naming it, or "No page's row names it."
4. **`GET /api/ai-budget/members/:userId/runs?month=YYYY-MM`** (HQ's Admin or Super Admin). It returns one member's month (`services/aiConsumption.ts`, `memberMonth`):
   - `memberConsumption(…, 'option')`: the member's own grouped read, scoped by `user_id`, with its totals;
   - each run, newest first and at most 100 (`runs_truncated`), with its model, page, option, record, `guard_for`, cost (`est_cost_usd` in micro-USD) and charge (null, never 0, where not recorded).

   Each read writes the audit line `ai_member_runs_read`, with the member's id and the month and never a figure, as D755's `ai_member_account_read` does. A bad month is 400; an unknown member is 404; a store that cannot be read is 503, with no raw error.
5. **One member's AI account.** D755's card (allowance, balance and holds, ledger, purchases, Adjust) now also draws **This month**:
   - the pages with their options and charges (the member's own `chargedPages` fold);
   - each run, a guard check drawn under its run.
6. **Credit rules** already links here for AI tokens (`CreditRulesRegistryPage.jsx`, D755).
