## D5671 — Authenticated Cloudflare delivery and explicit route isolation (#5671)

Cloudflare generic webhooks authenticate the cf-webhook-auth secret before
bounded JSON parsing. Exact account/policy/type, reviewed operational summary
scope and a provider-verified phase map select a fixed script/component and
preview or production audience. Names, text, data, URLs and diagnostics never
enter the event. Unknown state or unregistered policy is refused. Generic
Save and Test lacks policy/episode identity and is intentionally not accepted
as a real alert; its direct channel-bound destination acknowledgement is a
separate operator step.

An independent disabled receiver actor reuses D5665's SlackOutbox and transport.
The CF-purpose registry maps internal health/activity/prs aliases only to
Cloudflare health/activity/preview roles. All must be private with verified
recipient access and Slack Connect disabled. Live conversations.info checks
sharing, team, privacy, membership and archive state before every message.
There is no fallback to a public or GitHub channel. No raw link or mention is
rendered; version/count/last-good are Not recorded until trusted producers
supply them. Release evidence stays with #5667; this does not duplicate it.

Durable acceptance precedes HTTP 202, which is not a Slack acknowledgement.
Unique event/episode keys, immutable activity, newest-state root edits and
paged five-minute batches survive retries and reversed firing/recovery.
Source and destination kill switch defaults to false. No production binding,
policy, webhook, Slack app, secret or Issues opt-in is changed.

Live delivery needs an approved bot/registry, provider registration and
provider-originated preview firing/recovery receipts. The Slack connector has
no channel-bound incoming-webhook creation method. SQL Monitors, Issues plan
eligibility/opt-in, retention, on-call ownership, independent missed-heartbeat
fallback and release bridge remain operator/integration gates. No live canary,
actual latency, audience access or target-date runtime result is claimed.

The private status endpoint uses a separate observer credential. A successful
status request does not advance its persisted scheduled heartbeat. The
disabled-by-default GitHub observer checks freshness and oldest undelivered
age outside the Cloudflare/Slack path; its fixed failure output is the
GitHub-visible fallback. Verify owner watch/response delivery before relying
on it. It has contents-read only, no PR trigger, no issue writer and no raw
status logging. Its fixed five-minute schedule is not a per-notification job.
The current approved URL shape is a Worker workers.dev /status endpoint;
there is no deployed route until the operator approves and configures one.
