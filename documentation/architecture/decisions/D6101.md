## D6101 — Remove a KPI typed with the wrong value (#6101)

- **Status:** built by S05, 2026-11-15. Under #4861 (Grow UX V2).
- **Files:** `cloudflare-worker/src/services/growKpis.ts` (`kpiEntries`, `removeKpiEntry`, a refusal `code` on `KpiRefused`),
  `cloudflare-worker/src/services/records/grow.ts` (History as entries, the `remove-entry` action),
  `cloudflare-worker/src/services/records/types.ts` (`RecordAction.row_only`), `frontend/src/pages/cycles/recordHeaderModel.js`
  and `frontend/src/pages/cycles/RecordView.jsx` (no header or Actions button for a `row_only` action).
  Tests: `cloudflare-worker/test/grow_kpi_entry_remove_6101.test.ts`, `frontend/test/kpi_entry_remove_6101.test.mjs`.

### What was decided

1. **What marks a hand entry.** The `source` column of the row: `custom_kpi_values.source = 'manual'` for a custom KPI,
   and for MRR, Customers, Churn and Burn a `project_metrics` row whose `source` is `'manual'` or empty. Migration 249
   keeps a NULL source for a founder's own entry, and `sourceOf` in `growKpis.ts` already reads it as manual, so the
   record that shows "manual" and the rule that removes agree. Every other source (Stripe, Mercury, Google Sheets, a
   CSV import, beehiiv) is a connected source's figure: refused with 409 `kpi_entry_connected` and a sentence saying to
   correct it where it came from. The manual test is inside the `UPDATE`/`DELETE` as well, so a row cannot be cleared
   after a connector takes it over.
2. **An entry is one stored row.** A `project_metrics` row id, or a `custom_kpi_values` uid. Removing a typed KPI's
   entry sets only that KPI's column to NULL, because one day's manual row can hold MRR and Customers together. A
   manual row then left holding no figure is deleted (every column but its bookkeeping is checked, and the four typed
   columns again inside the `DELETE`), so no reader counts an empty snapshot. A custom KPI's entry is deleted.
3. **History lists entries.** For a KPI a person can type (MRR, Customers, Churn as a rate, Burn, each custom KPI),
   History is now one row per hand entry with its day, value and a Remove, plus a connected source's last figure in
   each month (Stripe writes one a day). Newest first, 24 rows. New MRR, Expansion MRR, Runway, Churn read from the
   ledger and PostHog metrics keep their months: they have no entries.
4. **Remove runs from its row.** The action `remove-entry` is declared `row_only: true`; each manual History row names
   it with `{ entry }`. The header row and the Actions list draw no button for a `row_only` action, so Remove is never
   pressed without an entry (an empty one is refused, 400 `kpi_entry_required`). Other refusals:
   404 `kpi_entry_not_found` (another venture's row, an id holding no value of this KPI, a malformed id),
   400 `kpi_not_entered_by_hand` (a derived or PostHog KPI).
5. **Gate.** The record route's write gate, `canAccessProject(..., { write: true })`, unchanged: the owner, a
   co-founder, a partner and an admin. A reader (an advisor member) gets no row action and 403 on the action.
6. **Activity.** `grow_kpi_entry_removed` on the KPI's record (`grow.revenue-and-traction`, the KPI key), with the
   writer's user id and the time, summary "Hand entry removed: <value> for <day>", written by the record action as
   Enter by hand's is (`growKpis.ts` cannot import `growWriters.ts` or `cycleActivity.ts` without an import cycle).
7. **Re-read, not recompute.** The KPI table (`kpiRows`), the record, the Overview (`growFigures`) and a report draft
   (`assembleReport`) read the stores as they are now, so each shows the next latest value with no other change. A
   sent report's figures are frozen in `portfolio_updates.figures_json`, which the removal never touches.
8. **Alerts.** After a removal the KPI's alerts are checked at once, and removing a Burn entry checks Runway's too,
   as `enterKpi` does: a removal can cross an alert (notified once) or clear one (re-armed).

### Not built

- **Cash.** Runway reads `cash_balance`, but no KPI record or `enterKpi` path takes a typed cash balance, so there is
  no cash entry to remove here. A wrong typed cash balance is still corrected where it was entered.
- **Churn as a rate once the ledger has two billings.** History then shows the ledger's months, so a typed churn rate
  has no Remove; it does not change the figure shown.
- No `DELETE` route on `/api/cycles/grow`: the record action is the one path.
