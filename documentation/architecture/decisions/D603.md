## D603 — Help Center: weekly guide views and yes/no answers, Worker first

**The Help Center gets the two stores its canvas draws and the platform did not
have: guide views by day, for "Popular this week", and one yes/no answer per
member per guide, for "Did this answer it?".** Slot S10, issue #1286, step 2 of
#1280, 2026-10-06. Migration 408. This PR builds the stores, the routes and
the client. Session 1 wires the page under #1280; until then
`frontend/test/help_center_contract.test.mjs` keeps both off it.

### The anchor

A guide is addressed as `<area>/<guide>`, for example `capital/cap-table`. The
guides live in the frontend manifest (`pages/docs/sections/*.js`), which the
Worker does not have. So the Worker checks the anchor's shape: each part is
`[a-z0-9-]+`, and the whole is 3 to 120 characters. A bad shape is
`400 invalid_anchor` before any read or write. Migration 408's CHECKs hold the
same shape in the tables. The page drops anchors its viewer cannot read.

### The stores (migration 408, additive)

- **`help_guide_views (anchor, day, views)`**, primary key `(anchor, day)`,
  `views >= 0`, `day` a UTC `YYYY-MM-DD`. **No reader identity:** an
  anchor, a day and a count.
- **`help_guide_view_marks (user_id, anchor, day)`.** A view counts at most
  once per member per guide per day. This table holds a member id, so it is
  kept short: every view write deletes the marks older than two days (anything
  before yesterday, UTC), in the same batch.
- **`help_guide_feedback (id, anchor, user_id, answer, missing, created_at,
  updated_at)`**, `UNIQUE (anchor, user_id)`.
  - `answer` is `yes` or `no`.
  - `missing` is NULL, or 1 to 500 characters and only with `no`.
  - A member's later answer replaces the earlier one.

### The routes (`routes/help_center.ts`)

Mounted at `/api/help`. Signed in, for every role:

- **`POST /guides/:area/:guide/view`** runs one batch: drop old marks,
  `INSERT OR IGNORE` today's mark, then add one to today's count only if that
  mark was new (`WHERE changes() = 1`). It answers `{ anchor, day, counted }`.
  A second view the same day answers `counted: false` and changes nothing.
- **`GET /popular?days=7&limit=4`** sums the last N UTC days, today included
  (`days` 1–30). It orders by most views, then by anchor, drops guides with
  no views, and allows a limit of at most 10. It answers
  `{ window_days, guides: [{ anchor, views }] }`. A failed read is
  `503 popular_guides_unreadable`, never an empty list.
- **`GET /guides/:area/:guide/feedback`** returns the caller's own answer
  (`answer`, `missing`, `updated_at`), or null. No one reads another
  member's answer here.
- **`PUT /guides/:area/:guide/feedback`** takes `{ answer, missing? }`:
  - `missing` is trimmed, and blank becomes none;
  - with `yes` it is `400 missing_with_yes`;
  - over 500 characters it is `400 missing_too_long`.

  The answer is upserted on `(anchor, user_id)`, so the last one wins.

And `adminHelpCenter`, mounted at `/api/admin/help`:

- **`GET /feedback`** is `requireAdmin`, the narrowest role that reads every
  member's answers. It returns per-guide `yes` and `no` counts (most "no"
  first) and each "what was missing" text with its anchor and date, newest
  first, at most 500. **No member identity:** no user id, name or email.

The writes are the member's own, so no actor record beyond the row is needed.

### The client

`frontend/src/lib/api/helpCenter.js` (`helpCenterApi`), re-exported by one line
in `api.js`'s block (D527). It has `recordView`, `popular`, `myFeedback`,
`saveFeedback` and `adminFeedback`. Each path is a literal template that
`check-api-drift` matches against a mounted route.

### Guard

`cloudflare-worker/test/help_center_d603.test.ts`:
- a bad anchor is a 400 on all three guide routes, and the table refuses one
  too;
- a second view by the same member on the same day is not counted, while
  another member's is;
- old marks are deleted on a view;
- the popular window, its order, its limits and its default;
- a failed popular read is a 503;
- for feedback, the last answer wins, `missing` is trimmed, refused with yes
  and capped at 500, and another member cannot read it;
- the admin read is refused to a founder and an investor (403), and carries
  no identity;
- the counts table has exactly `anchor, day, views`.

Eleven mutants were each caught:
- the anchor check on a view, or the length bound;
- the once-a-day rule, or the mark purge;
- the order, or the window;
- `missing` with yes, or the trim;
- the admin gate;
- last-answer-wins;
- the failed read turned into an empty list.
