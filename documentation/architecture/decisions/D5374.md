## D5374 — HQ Home and HQ Funds draw an unreadable deployment registry as Unreadable, never as "no branch" or a complete coverage (#5374)

- **Status:** Built for #5374, 2026-11-10. Follow-up to D5041 (#5041), whose first "Not done" line this closes.
- **Builds on:** D5041 (`deployedBranches()` reports `{ available: false, reason }`; `/overview` and `/funds` carry `registry_available` and `registry_reason`), D150 (HQ Home reads the fan-out), D245 and D375 (the funds oversight page).
- **No migration. No new route. No Worker change.** `GET /api/admin/hq/overview` and `GET /api/admin/hq/funds` already spread `registryFlags(deployments)` into their payloads (`routes/admin_hq.ts`), and `branches_coverage` is built by `coverageOf`, which is never `complete` over an unreadable registry. Confirmed by reading both handlers; `hq_funds_registry_d245.test.ts` and `supervision_surface_d138.test.ts` already pin it on the Worker side.

### The defect

When HQ cannot read `licence_deployments`, `deployedBranches()` answers `available: false` and the fan-out has nothing to merge, so the payload carries `branches: []` and `branches_coverage: { total: 0, answered: 0, complete: false }`. Two pages read that as an empty fleet:

| Page | What it said | Why that was wrong |
| --- | --- | --- |
| HQ Home | "No branch is deployed yet, so seat utilisation cannot be summed from branch reads." (seat tile); "No branch is deployed for this licence" (each card); and, in the rail's coverage sentence, "No branch is deployed, so every figure above is HQ's own database." | Each needs a registry that was read and is empty. |
| HQ Funds | `complete: cov.answered === cov.total`, drawn as "of 0 branches, 0 answered" | 0 of 0 is vacuously complete. The set of branches was never established. |

### What was decided

1. **One shared test.** Both pages import `registryUnreadable` from `hqTeamBranchModel.js` (same folder, so it stayed where it was). `registry_available === false` is the only unreadable signal; a payload without the field makes no claim either way.
2. **HQ Home** (`HqHomePage.jsx`): an `Unreadable` block with the Worker's `registry_reason` and a Retry that re-reads the overview. With the registry unreadable, the seat-utilisation reason says the registry could not be read; a licence card with no branch read says that whether it has a branch is not established (`branchReason(b, what, registryDown)`); a seat sum over branches that did answer says other branches may exist, so it is a floor. The rail's coverage sentence leads with the unreadable registry. A readable, empty registry keeps all of today's wording.
3. **HQ Funds** (`HqFundsPage.jsx`): `oversightStats` takes `complete` from the payload's `branches_coverage.complete` (counting only for a payload from before that field existed) and is never complete when `registry_available === false`. The coverage text reads "the branch list could not be read" instead of "of 0 branches, 0 answered", in the band and the rail, and an `Unreadable` block with the reason and a Retry says the funds shown are only those of the sources that answered. A readable, empty registry still reads "of 0 branches, 0 answered".

### Tests

`frontend/test/hq_registry_unreadable_5374.test.mjs` mounts both pages over a stubbed `api` and reads what they draw: unreadable draws the block, the reason and a working Retry and none of the "no branch" sentences; readable-and-empty and an older payload keep today's wording; an unreadable registry with one answering branch is a floor, not a total. Every assertion is run against the page source with its guard removed (`mutationCheck`), in both directions: guards removed (the unreadable page falls back to "no branch") and guards forced on (the readable page draws Unreadable).

`WorkerRail` no longer renders its `coverage` prop (`RETIRED_RAIL_PROPS`), so the rail sentence is not visible on the page; it is checked from the source (leads with the registry, keeps the empty-registry sentence), and the visible effects of the same state are the tests above.

- `supportQueues.ts` has its own registry read (`readSupportDeployments`) that already keeps an unreadable registry as its own state.
