### 2. The cron

- **The trigger.** `"17 3 * * *"` is added to `[triggers]`, `[env.production.triggers]` and `[env.preview.triggers]`.
  `CRON_TRIGGERS` gains `{ name: 'swarm_retention', expr: '17 3 * * *' }`, and `cron_record_d201.test.ts` already fails
  when that list and the two deployed tables disagree. HQ grades the trigger like the other six, so it reads "never
  fired" until its first night.
- **The limit.** Cloudflare has had no per-Worker cron limit since 2023-10-18. The limit is per account: 5 on Workers
  Free and 1,000 on Workers Paid (developers.cloudflare.com/workers/platform/limits). The Worker now declares 7
  production triggers, 7 at the top level and 4 on preview. Branches keep their own two (`BRANCH_CRONS`). No guard
  forbids a new expression: `cron_record_d201` asks only that `CRON_TRIGGERS` and the tables agree, and that preview
  and branches fire nothing it does not know. So C1 is built as the owner gave it, not folded into an existing line.
- **Where it runs.** `scheduled()` gates every daily block on the event's own minute, not on which expression fired
  (D239). The every-minute ticker and the new trigger both fire at 03:17 and dedupe on one KV lease (D201), so the
  run happens once in that minute, whichever invocation takes the lease. The block is
  `if (now.getUTCHours() === 3 && now.getUTCMinutes() === 17)`, and it loads `swarmRetentionCron.ts` with
  `await import(…)`.
  - **The hub rule.** `HUBS.md` names a dynamic import inside `scheduled()` as the home of a cron job, and
    `hub_freeze_5615` does not freeze dynamic imports. `index.ts` gains no static import and no registration.
  - **Every tier.** The block is not gated on `hqCadences`. Each deployment's coordinator holds its own state.
  - **A branch.** A branch fires no `17 3` trigger. Its every-minute tick still reaches 03:17, and a branch without
    the binding records `skipped`.
- **One run.** `runSwarmRetentionTick` calls the coordinator's `/retire` (D5586-p4 §3). One call retires at most 2000
  tickets. A call that answers `more: true` is followed by another, at most `SWARM_RETENTION_CALLS` (3) in one run.
  Anything left over waits for the next night, oldest first. Each call is idempotent, so a repeated tick retires
  nothing twice.
- **What the cron row says (D8533).** The task is named `swarm retention`.

  | Outcome | When | Detail recorded |
  | --- | --- | --- |
  | `done` | Something was retired | the counts (`tickets=… slots=… audit=… evicted=… calls=…`, plus `more` when work is left) |
  | `skipped` | Nothing was due | `nothing due` |
  | `skipped` | The deployment has no `WORKSPACE_ADMISSION` binding | `coordinator not bound` |
  | `failed` | The coordinator refused (`clock_regressed`, `admission_unavailable`, …) | the refusal's code as the error class, which makes the row `partial` |

  A thrown stub counts as `admission_unavailable`. The task never throws into the tick.
- **Preview.** The owner asked for all three tables, so preview runs retention too. It touches only the preview
  coordinator's state and sends nothing outside. `STAGING.md` counts the extra 30 invocations a month.

### 3. The §5 engine pieces: not built, and why

D5586-p4 §5 lists three engine pieces: the caps from a broker record, the provider reader, and the scheduled
admit, reconcile and promote. None of them can be built without a new owner decision:

- **Caps.** The coordinator's caps (`per_provider_running`, `per_region_running`, per tenant) and each venture's
  policy (concurrency, render budget, storage quota) are values the owner approves. D5570-p2 ties them to "the
  owner-approved quota UI canvas" (the #8832 brief). No record holds them, and choosing where one lives is a schema
  decision.
- **The provider reader.** It reads a real provider's state for a reconciling lease. The issue says "no autonomous
  provider switch-on", and D5570-p2 enables no provider call. Which providers to read, and with which credentials, is
  the owner's call.
- **Scheduled admit, reconcile and promote.**
  - `promote` needs every waiting venture's policy and storage use, which come from the missing record.
  - With no caps, `admit` admits nothing. With no reader, `reconcile` keeps every slot. Run alone, they would change
    nothing.
  - A schedule for them would also be a new per-minute call into the object that serializes every admission. That is
    the cost the owner turned down for retention when choosing C1 over C2.

So this part builds only C1. Questions D to F (§4) are what the engine pieces wait on.

### 4. Open questions

**D. Where do the coordinator's caps and each venture's policy come from?** **D1 (my pick):** a broker-owned D1
record, written by the quota screen once its canvas lands (#8832). One row per provider and region holds the caps,
and one row per venture holds the policy. Both start empty, so an absent row still admits nothing. **D2:** Worker
vars in `wrangler.toml` for the caps, with no venture policy until the screen exists. **D3:** wait for #5570 to
define the record.

**E. Which provider does the reader read first?** **E1 (my pick):** Cloudflare alone (Containers / Workers), read
through bindings the Worker already has. Every other provider stays `unknown` and keeps its slot. **E2:** each
provider that #5570 places, behind a per-provider flag that is off by default.

**F. How are admit, reconcile and promote scheduled once D and E exist?** **F1 (my pick):** a Durable Object alarm
on the coordinator, set only while a lease is admitted or reconciling or a ticket is waiting, so an idle coordinator
costs nothing. **F2:** the every-minute ticker, with a `scheduled()` block like this part's.

### Rollback

Revert the commit. The next deploy then drops the trigger from each environment, because Wrangler replaces the whole
cron list. A retention run that already happened stays, and D5586-p4's rollback note applies to it: the carry and
the tombstones are optional fields. Wrangler can also drop the trigger alone, by removing the `"17 3 * * *"` string
from the three tables and the `CRON_TRIGGERS` entry. The block in `scheduled()` then still runs from the every-minute
tick, so remove it too, or the run continues.
