## D6476 part 2 — Re-queue only on trusted head evidence and positive class evidence (#6476)

- **Status:** built 2026-11-17, from the merge-queue audit of the same day (its two P0 findings on the ejection handler).
- **Builds on:** D6476, D6481 (first admission's evidence reader), D6467 (the shared rules).

### What changed

1. **Green on the current head means the trusted evidence first admission reads.** The handler used to accept any
   nonempty page of check runs that were all success, neutral or skipped. It now calls `readHeadEvidence` in
   `scripts/landing-bot/feeder-github.mjs`, which needs:
   - every context main's rules require, from the app each rule names;
   - `success` on this exact head (skipped and neutral are not green);
   - the full-suite job proven to be `ci.yml`'s pull_request run for this PR and head;
   - check runs read to the end of their pages.

   One unrelated success qualifies nothing. A moved head is no evidence. The decision's reason names what was
   missing.
2. **A flake needs positive evidence.** A failed merge group whose PR head and main each passed was called a flake.
   It is now the class `incompatible`: the signature of two changes that break each other. It is labelled
   `queue-ejected` with "compare it with the entry ahead" and is never re-queued. A flake is only every failing test
   named and on the flaky list, or the queue record's class.
3. **A cascade needs a failed job.** A failed group run with no failed job listed matched "failed only at the
   queue-ref check", because an empty list passes every test. It now needs at least one failed job, every one of
   them the queue-ref check.
4. **The group run is matched exactly.** `groupRunFor` parses the queue branch `gh-readonly-queue/main/pr-<n>-<sha>`
   and compares the number, so `pr-12` never matches `pr-123`. It takes the one run that started after this PR's
   last entry and before this removal. Two candidates or none is no evidence, and the class falls to `unknown`.

### Not changed

GitHub still enforces the required checks on every queue run; this is the bot's own gate before it asks.
