## D5949 — Revenue ledger 5/6: branches report promo issued and spend to HQ (#5949)

- **Status:** built. Slice 5 of 6 of #5038.
- **Builds on:** D266 (the 05:10 usage report), D4855 (the branch's promo ceiling ledger), D1156 (an authenticated branch report with its own time), D244 (`authenticateBranch`).
- **Migration:** `cloudflare-worker/sql/migrations/202611150136_5949_promo_issued_reports.sql`.
  - It adds `spent_cents` and `issued_currency` to `licence_promo_ceilings`. Both are NULL until the branch reports.
  - It creates `licence_promo_issued_reports`, which holds the latest report per licence and how HQ filed it.
  - It is additive, with no backfill.

### What was wrong

`licence_promo_ceilings.issued_cents` (migration 260) is HQ's copy of what a branch has issued
against its ceiling, and nothing wrote it. The only reference in the Worker was a read on HQ's
promo-ceilings route. Every ceiling therefore read "the branch has not told us", forever. The
branch kept the real figure in `branch_promo_ceiling.issued_cents` (`syncIssued` in
`promoRedemption.ts`).

### What changed

**The branch reports on the existing daily run.** Its own block at 05:10 UTC, beside the usage
report, calls `pushPromoIssuedReport` (`services/promoIssuedReport.ts`). It is gated on
`!hqCadences` like the usage report, and each block can fail alone. For the period and currency
of the ceiling copy the branch holds, it sends:

| Field | Meaning |
| --- | --- |
| `issued_cents` | committed plus live holds: the branch's own `issued_cents` rule, recomputed from `promo_ceiling_reservations` at send time |
| `spent_cents` | committed only |
| `reported_at` | the branch's own as-of time, not HQ's receipt |

A branch holding no ceiling copy sends nothing, since there is no period or currency to report
against. A failed push never throws (refusal, timeout, an answer that is not a receipt, no secret,
no binding, an unreadable ledger, even a malformed `BRANCH_CODE`). It returns `{ sent: false,
reason }`, as `pushUsageReport` does.

**HQ's method: `reportPromoIssued`** (`rpc/hqOps.ts`, on `BranchEntrypoint`, declared in
`RPC_SURFACE` as called and authenticated).

1. `authenticateBranch` runs first, so a caller without the branch's secret is refused before any
   read or write.
2. The report is then validated strictly:
   - exactly the five keys;
   - `YYYY-Qn`;
   - an upper-case currency code;
   - whole, non-negative minor units with spent ≤ issued;
   - an exact ISO time no more than five minutes ahead.
3. The report is always **recorded** in `licence_promo_issued_reports`. A report older than the
   one held, by the branch's time, changes nothing.
4. It is **written** into the ceiling row only when HQ has a ceiling for that licence and period
   in that currency. Otherwise it is filed as `no_ceiling` or `currency_mismatch` and never
   written into another period's or another currency's row.

**HQ's read** (`GET /api/admin/promo-ceilings`) gives each row an `issued_state` and an
`issued_state_reason`. The rule is `promoIssuedState`:

| State | When |
| --- | --- |
| `reported` | a figure in the ceiling's currency, and current (or for a closed period) |
| `stale` | the current period's figure is more than **48 hours** old, by the branch's `reported_at`. The run is daily, so that is two missed runs. A closed period's last report is its final figure and is never stale. An unparseable time is stale |
| `not_reported` | no figure (`issued_cents` NULL, never 0), and no report says why |
| `unreadable` | no figure, and the reports table could not be read to say why. A figure already held stays usable. The whole ceilings table failing keeps the route's existing `available: false` |
| `mismatch` | the figure, or the branch's latest report for this period, is in another currency (including HQ moving the ceiling's currency after a report); or the current period has no figure and the branch's latest report is for another period |

`remaining_cents` is computed only for `reported` and `stale`, and is null otherwise.
`issued_available` follows it, so a figure in another currency is never subtracted from a ceiling.
The page's existing check (`revenueModel.js`, `issued_available`) needs no change.

**The branch ledger stays the enforcement source.** Checkout decides on `canRedeemPromo` against
`branch_promo_ceiling` and the reservation ledger. Neither the redemption, renewal nor order
services read either HQ table, and a test holds them to that.

### Not in this change

Showing the new states on HQ's Revenue page: the API carries them, and the page keeps reading
`issued_available`. The live read-back of the enforced ceiling (`admin_promo_readback.ts`, #5039)
is unchanged.

### Tests

`cloudflare-worker/test/promo_issued_report_5949.test.ts` uses two full-schema SQLite databases,
branch and HQ, with the branch's binding calling HQ's real method. It covers:

- the branch's sums (released holds, expired holds and other currencies left out);
- the write and the HQ read after a run;
- `no_ceiling` recorded and not written;
- a currency mismatch, both reported and after HQ moved the ceiling;
- every state, including stale against a closed period, and unreadable versus not reported;
- refusals before any write: wrong, missing or unknown secret, and eight malformed reports;
- out-of-order reports;
- the push never throwing;
- the enforcement and cron gates.

Mutation-checked with 9 mutants, each failing a test:
- writing across currency;
- no ordering guard;
- an auth bypass;
- spent counting holds;
- unreadable collapsed into not reported;
- the stale threshold;
- remaining computed on a mismatch;
- a push that throws;
- no period mismatch.
