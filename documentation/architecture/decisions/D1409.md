### 1. Corrections to the issue

S1's specification records these; this build follows it.

- **The run path is `run()`, not `meteredCall`.** `meteredCall` (D844) meters MCP tools, flows and provider runs. A model run on the router holds and settles itself (D762), as the deck tools and the rail do.
- **The refusals keep the run path's codes:** 402 `budget_user_day`, `budget_user_month`, `budget_review` or `spend_limit`, and 403 `ai_paused` or `assist_off`, through `refuseRun`. `insufficient_tokens` is metering's wording and is not used, so the client's "Add tokens" mapping keeps working.
- **Options get record-scoped routes,** like deck assist. `POST /api/ai/rail/run` takes only `form:` options.

### 2. The options

Each option is one rail option, run with `task: 'rail_write'` and no router change:

| Option | Input | Proposal kind and payload |
|---|---|---|
| `draft:article-outline` | `brief` (required, at most 1,000) | `draft` `{ outline_markdown }` |
| `draft:article-section` | `heading` (required, at most 200), `brief` | `draft` `{ heading, markdown }` |
| `rewrite:article` | `selection` (required, at most 4,000), `tone`: `shorter`, `plainer` or `formal` | `proposal` `{ before, after, tone }` |
| `draft:article-continue` | `cursor_context` (required, at most 4,000) | `draft` `{ markdown }` |
| `draft:article-headlines` | none | `proposal` `{ headlines }`, at most 5, each at most 120 |
| `draft:article-seo` | none | `proposal` `{ seo_title ≤ 120, excerpt ≤ 200 }` |
| `draft:article-newsletter` | none | `draft` `{ summary_markdown ≤ 1,200 }` |
| `check:article-facts` | `selection` | `note` `{ claims: [{ quote, why, needs_source: true }] }`, at most 20 |

- **What the model reads:** the article as stored, `title + subtitle + body_markdown`, cut to 12,000 characters.
- **What the guard checks:** only what the member typed for the press (the brief, the heading, the selection, the text before the cursor). The article is the member's own text. The output is guarded as on every run.
- **Check facts lists claims that need a source.** It does not look anything up and does not judge truth (owner step B, pick a; a web lookup belongs to #3721's audit).
- **An answer that parses to nothing** proposes nothing: 422 `nothing_proposed`, with what the run charged.

### 3. The routes

- `POST /api/articles/:id/assist/quote` `{ option, input }` → `{ option, ai: true, hold_microusd, model }`, or `{ option, ai: false, reason, message }` when the run would be refused (AI off, a pause).
- `POST /api/articles/:id/assist` (the same body) → `{ proposal, option, cost: { charged_microusd, usage_log_id } }`.

**The gate, in order:**
1. signed in;
2. the article's author or an admin (`loadOwned`), else 404 `not_found_or_forbidden`;
3. not published, else 409 `already_published`;
4. not a support session, else 403 `support_session_refused`.

Then an unknown option is 400 `unknown_option`, and a bad input 400 `invalid_input` with its `field`.

**The run:**
- **The rail context:** page `<Profile> · Articles` from the member's role (`articlePage`; a valid `X-Rail-Page` header wins), the press's own option, record `articles:<id>`, surface `AI_SURFACE.articles`.
- **The charge** is to the member who pressed. An admin's run on another member's article is the admin's own proposal.
- **The cost** is read from `ai_usage_logs.charged_microusd`. A charge the row does not hold reads null, never 0.
- **Logs** carry codes only: never a brief, the article or a model's answer.

**Nothing writes the article.** Insert, Replace and Accept decide the proposal (`POST /api/ai/rail/proposals/:uid/decide`), and the editor's own `PUT /api/articles/:id` saves.
