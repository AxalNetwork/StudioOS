### 1. Corrections to the issue

S1's specification records these; this build follows it.

- **The run path is `run()`, not `meteredCall`.** `meteredCall` (D844) meters MCP tools, flows and provider runs. A model run on the router holds and settles itself (D762), as the deck tools and the rail do.
- **The refusals keep the run path's codes:** 402 `budget_user_day`, `budget_user_month`, `budget_review` or `spend_limit`, and 403 `ai_paused` or `assist_off`, through `refuseRun`. `insufficient_tokens` is metering's wording and is not used, so the client's "Add tokens" mapping keeps working.
- **Options get record-scoped routes,** like deck assist. `POST /api/ai/rail/run` takes only `form:` options.

### 2. The options

Each option is one rail option, run with `task: 'rail_write'` and no router change:

| Option | Input | Proposal kind and payload |
|---|---|---|
| `draft:article-outline` | `brief` (required, at most 1,000) | `draft` `{ outline_markdown }` |
| `draft:article-section` | `heading` (required, at most 200), `brief` | `draft` `{ heading, markdown }` |
| `rewrite:article` | `selection` (required, at most 4,000), `tone`: `shorter`, `plainer` or `formal` | `proposal` `{ before, after, tone }` |
| `draft:article-continue` | `cursor_context` (required, at most 4,000) | `draft` `{ markdown }` |
| `draft:article-headlines` | none | `proposal` `{ headlines }`, at most 5, each at most 120 |
| `draft:article-seo` | none | `proposal` `{ seo_title ≤ 120, excerpt ≤ 200 }` |
| `draft:article-newsletter` | none | `draft` `{ summary_markdown ≤ 1,200 }` |
| `check:article-facts` | `selection` | `note` `{ claims: [{ quote, why, needs_source: true }] }`, at most 20 |

- **What the model reads:** the article as stored, `title + subtitle + body_markdown`, cut to 12,000 characters.
- **What the guard checks:** only what the member typed for the press (the brief, the heading, the selection, the text before the cursor). The article is the member's own text. The output is guarded as on every run.
- **Check facts lists claims that need a source.** It does not look anything up and does not judge truth (owner step B, pick a; a web lookup belongs to #3721's audit).
- **An answer that parses to nothing** proposes nothing: 422 `nothing_proposed`, with what the run charged.

### 3. The routes

- `POST /api/articles/:id/assist/quote` `{ option, input }` → `{ option, ai: true, hold_microusd, model }`, or `{ option, ai: false, reason, message }` when the run would be refused (AI off, a pause).
- `POST /api/articles/:id/assist` (the same body) → `{ proposal, option, cost: { charged_microusd, usage_log_id } }`.

**The gate, in order:**
1. signed in;
2. the article's author or an admin (`loadOwned`), else 404 `not_found_or_forbidden`;
3. not published, else 409 `already_published`;
4. not a support session, else 403 `support_session_refused`.

Then an unknown option is 400 `unknown_option`, and a bad input 400 `invalid_input` with its `field`.

**The run:**
- **The rail context:** page `<Profile> · Articles` from the member's role (`articlePage`; a valid `X-Rail-Page` header wins), the press's own option, record `articles:<id>`, surface `AI_SURFACE.articles`.
- **The charge** is to the member who pressed. An admin's run on another member's article is the admin's own proposal.
- **The cost** is read from `ai_usage_logs.charged_microusd`. A charge the row does not hold reads null, never 0.
- **Logs** carry codes only: never a brief, the article or a model's answer.

**Nothing writes the article.** Insert, Replace and Accept decide the proposal (`POST /api/ai/rail/proposals/:uid/decide`), and the editor's own `PUT /api/articles/:id` saves.

### 4. Images (part 2)

**The routes**, behind the same gate as the text options (§3):
- `POST /api/articles/:id/images/quote` `{ prompt, style, aspect, count }` → `{ ai: true, model, model_label: 'FLUX.1 Schnell', per_image_microusd, count, total_microusd, balance: { ok, code?, message? } }`, or `{ ai: false, reason, message }` when the run path would refuse it.
- `POST /api/articles/:id/images/generate` (the same body) → `{ images: [{ uid, url, filename, width, height, style, aspect, alt, charged_microusd | null, usage_log_id }], stopped? }`.
- `POST /api/articles/:id/images/:uid/discard` → `{ ok: true, uid, deleted }`.
- `POST /api/articles/:id/cover` (`articles.ts`) also takes `{ image: 'img-….png' }` in place of `data_uri`.

**The ask:** a prompt of 3 to 400 characters; `style` one of `photo`, `illustration`, `diagram`, `abstract` (owner step A, pick a: `photo` is offered); `aspect` one of `16:9`, `4:3`, `1:1`, `3:4`; `count` 1 to 4. A bad field is 400 `invalid_input` with its `field`.

**Refused, in order, before anything costs:**
1. **A real person,** 422 `real_person` with the canvas's sentence, before any quote, run or hold. `personIn` reads the face words (a portrait, a headshot, "our CEO", "the founder") and the article author's display name: an article has no venture, so the author is the only person it names. An admin's press on another member's article checks that author's name. The prompt also says "No identifiable people, no faces, no text, no letters, no numbers".
2. **No storage binding,** 503 `storage_unavailable`.
3. **The run path's refusals** (AI off, a pause), through `refuseRun`; the quote answers them as `ai: false`.
4. **A balance that cannot cover every image asked for,** 402 with the router's code, before any hold. Four images on a balance that covers one is refused whole; one image then runs.
5. **No room on the author's storage plan,** 413 from `assertStorageRoom`. The owner is the article's author, whoever presses (D1411, #3894: the bytes live in the author's article); staff pressing pass, as every staff write does (D1170).

**Each image** is one `run()` of the `article_image` task on the rail option `draft:article-image`, record `articles:<id>`, surface `AI_SURFACE.articles`, charged to the presser. Its own task means usage logs and HQ name articles, not decks. Its bytes go to `articles/<id>/img-<uuid>.<ext>`, the shape the existing upload uses, and are read through `GET /:id/image/:filename` (the author or an admin while a draft, anyone once published). The URL is absolute (`new URL(path, c.req.url)`). Each image leaves one `ai_rail_proposals` row, `kind: 'proposal'`, payload `{ filename, url, width, height, style, aspect, alt: '' }`, holding that run's `usage_log_id`. A charge the usage row does not hold reads null.

**A failure part-way:** the first image failing is the run path's refusal, or 503 `model_unavailable`, with nothing stored. A later failure returns the images already drawn, each charged, with `stopped: { code, message }`. An image whose proposal cannot be written is deleted from R2, since nothing could place or discard it.

**Discard** takes only the presser's own `draft:article-image` proposal on this article (else 404) that is still open (else 409 `already_decided`). It decides the proposal, then deletes the bytes unless the article already shows them: the body names the file, or the cover key ends with it.

**The cover from an image** copies the bytes to `articles/<id>/cover-<uuid>.<ext>`. Setting another cover deletes the old cover copy, never a body image. The source must be a valid image name (400 `invalid_image`) that exists (400 `image_missing`) and is a PNG, JPEG or WebP read from its bytes (400 `unsupported_mime`).
