## D7743 — Research › Funds: every source's statement about a fund in its own words, with the money facts apart (#7743)

Part of #3701. Filed from the owner's Research › Funds audit of 2026-11-19.

### Why a new store

`research_fund_vehicle_facts` (migration `202611180053_7167`, D7167) keys one value per fund and field, has four fields, and stores a cheque only as a min or max in EUR, USD or GBP with no wording. It cannot hold two sources for one fact, the source's text, a qualifier on a cheque ("typically", "average first"), a currency the source never stated, or terms a filter can match. It stays as it is and gets no writer: an applied migration is never edited (D269), and changing its key needs a rebuild, which is the owner's call.

### The tables (migration `202611191932_7743_research_fund_observations.sql`)

- **`research_fund_observations`**: one row per fund, fact, list and source record (`UNIQUE (fund_uid, fact, source_name, source_record_ref)`), indexed on `(fact, fund_uid)`. `wording` is always the source's text, never blank, at most 4,000 characters. `source_name` references `research_fund_sources`, so every statement sits under a recorded terms review (D597). `source_record_ref` is opaque and never served. `period_start` and `period_end` are set only when the statement is history. `promoted_by_user_id` is NULL when a migration wrote the row and needs `promoted_at` when set. `method` is 'rule' or 'manual', as `researchTaxonomy.ts` uses it.
- **`fund_uid` has no foreign key.** A list's migration deletes and re-inserts its directory rows, and a cascade would delete other sources' statements. A statement whose uid moved (`research_fund_directory_uid_moves`) is read under the new uid, one hop.
- **Thirteen facts**: manager_name (a firm, never a person), investment_stage, investment_geography, initial_cheque, stated_fund_capital, manager_aum, revenue_threshold, traction_requirement, lead_preference, interests, sector_focus, description, date_last_raised. No contact fact and no contact column. A company's round size is not a fact here.
- **Money facts** (the cheque, fund capital, manager AUM and revenue threshold are four separate facts) carry `qualifier`, `min_cents`, `max_cents`, `point_cents`, `currency` (three capitals: a shape, not a closed list), `currency_basis` and `review_flags`. The CHECKs: a text fact has none of these; a money fact has a qualifier and a basis; `range` has both bounds and min ≤ max; `typical`, `average_first` and `exact` have the point only; `lower_bound` the min only; `upper_bound` the max only; `as_stated` no amounts. A currency code is present when, and only when, the basis is `stated` or `reviewed`. A flagged row is `as_stated`, and its flags are a non-empty JSON array of the four known flags (a CHECK strips each known flag and every comma and requires `[]` to remain, since a CHECK cannot read `json_each`).
- **`research_fund_observation_terms`** `(observation_id, vocabulary, term)`, primary key on all three, indexed on `(vocabulary, term)`, deleted with its statement. A country term is two capitals.
- **Triggers.** The issue asks for one trigger: a stage term only on an investment_stage statement, a country or region term only on an investment_geography statement. Two more close the ways round it: the same rule when a term row is updated, and a statement's `fact` never changes (a changed fact is a new statement). All three `RAISE(ABORT, …)` with the table and column named.

### The service (`cloudflare-worker/src/services/researchFundObservations.ts`)

- **Stage vocabulary, defined here only.** The rounds are `STAGES` from `companyProfileFields.ts` without idea, profitable and public, in its order and spelling (pre_seed, seed, series_a, series_b, series_c_plus, growth), plus three broad terms never expanded into rounds: early_stage, late_stage, multi_stage. `normaliseStage` matches exactly after `normalizeLabel`; a list gives one term per item; a range between two rounds gives every round between them; a range with an unknown end gives the known end and reports the other; an unmapped wording keeps its text, gets no term and is counted (`unmapped` on the writer's result).
- **Geography.** Countries by exact match through `COUNTRY_ALIASES` (imported, not edited). Regions are the seven `research_countries.region` allows (migration 376; the test reads that CHECK and compares) plus 'global', spelled as that table spells them so a filter can join on them. A region is never expanded into countries, and nothing is taken from the manager's headquarters.
- **`readAmount(fact, wording, heading?)`** returns the fact it was given. It reads a closed set of shapes (a range, "up to", a minimum, "typically", "average first", one exact amount; k, m, mm, million, bn, billion) and returns `as_stated` with no amounts for everything else. A typical or average value is a point, never bounds. A bare symbol gives currency NULL and basis `symbol_only`; a code beside an amount gives basis `stated`; a code only in the column heading gives `heading_only` and no currency. Two units in one value, a symbol that disagrees with its heading, a trailing question mark, or more than one amount give `as_stated` with the matching flag. It never returns `reviewed`; that is a person's.
- **The writer** (`observationStatements`) returns prepared statements for the caller's batch (#7751 writes one atomic batch): an upsert on the unique key, then the statement's terms replaced. A re-imported record replaces its row rather than adding one.
- **The served read** (`readFundStatements`), for #7748, #7749 and #7751: a statement is served only when its list's verdict is not 'not allowed'; a description only under 'republish allowed'; facts from a fixed allow-list (`SERVED_FACTS`); statements with a period come back apart as `past`; `source_record_ref` and the promoting user are never selected. The rows of `research_fund_vehicle_facts` come back as statements (`origin: 'vehicle_fact'`) under main's own gate, so the profile and the directory never disagree about what is recorded; such a cheque has no wording and no basis, and says so with NULL. `compareStatements` is the shared order: latest `reported_on` first, undated last, then latest `imported_on`, then list name.
- Nothing in the service logs wording.

### What other stores still mean

The directory row's `fund_size_cents` and `research_fund_directory_reports` stay what the directory filters, sorts and charts; a `stated_fund_capital` statement changes neither. `history.observations` on the fund read is the size chart and is not this table.
