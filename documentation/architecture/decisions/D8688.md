## D8688 — Role qualification on a local isolated Worker, with the restricted Admin as a branch principal (#8688)

**Context.** #8688 asks for an actual-role qualification of Admin, Founder, Investor, Advisor and Operating Partner.
Each needs a saved draft, a reload, the next action, a 390 px check and a second synthetic tenant. Admin also needs a
test-only territory and a supported way to provision a restricted Admin. The owner confirmed on 26 November that no
staging URL exists. The five production test identities are still Exploring, and their sign-in fails (#8680). The
role previews in #8689 hold Super Admin authority and cover navigation only.

**Decision.**

1. **The qualification runs the real Worker in process, on local data.** `cloudflare-worker/test/_role_qualification_8688.ts`
   builds three migrated SQLite databases: HQ and two branches. It seeds synthetic identities under the reserved
   `qualification.invalid` domain, then runs each scenario through `src/index.ts`, as the role itself, with a fixture
   session key. No D1, mail, chat or payment binding is configured. Every outside `fetch` is refused and counted, and
   the run requires the count to be zero. `role_qualification_8688.test.ts` runs it on every PR.
   `scripts/qualification/role-matrix.mjs` runs it with plain `node` and prints the matrix.
2. **Fail closed on the target.** `scripts/lib/roleQualification.mjs` `targetRefusals` reads the environment the same
   way `wrangler.toml` writes it. It refuses each of the following, by name:
   - an `ENVIRONMENT` that is `production`, unset or unknown (the file's top level and `[env.production]` both say
     `production`);
   - production's D1, by name or by the id the file binds;
   - a hosted or `preview` target without an `isolated` preflight under 24 hours old (D4566's
     `check-preview-isolation.mjs`, the rule `agent-validation-fixtures.mjs` applies);
   - any database that already holds an account outside the synthetic domain.

   The fixture checks each database before seeding it and again afterwards. The CLI refuses every target except
   `local`, because no isolated hosted environment exists yet.
3. **The test territory is a draft territory licence; the restricted Admin is that branch's principal.** The
   synthetic HQ Super Admin creates the licence through `POST /api/admin/licences` and sets its territory through
   `PUT /:uid/territories`, using the user-assigned ISO codes `XQ` and `XZ`, which no real country holds. HQ's push
   then runs in its two halves: `assembleLicenceRecord` on HQ and `applyLicenceCopy` on the branch. The branch's
   starting account is `seed-branch-principal.mjs`'s `principalSql` (D.3). The run creates no contract, no
   signature, no activation and no live licence.

   The restriction holds by construction:
   - the branch has its own database;
   - its own session key refuses the session on the other branch (401);
   - `HQ_ONLY` refuses HQ's licence routes (403);
   - the account does not exist on HQ.

   HQ's appointment route, `POST /api/admin/licences/:uid/admins`, is **not** used. It promotes the account to an HQ
   `admin`, and `requireAdmin` and `tenancyScope.ts` (`UNSCOPED_ROLES`) then leave its reads unscoped across HQ. Using
   it would give a demo identity the production-wide authority the issue forbids.
4. **The scenarios use the product's own routes, and the matrix records what is missing rather than faking it.** The
   per-role routes are listed in `scripts/qualification/README.md`. Two gaps are recorded as missing steps:
   - The Advisor has no dedicated session-preparation record. The run uses a draft of the cohort's guidance (D4813).
   - Activation needs a signed membership agreement, so the pending-review control does not activate.

   Next actions run only where they change local records and deliver nothing:
   - the LP lane, which notifies nobody;
   - in-app guidance;
   - a deal-flow stage;
   - a feature state;
   - a delivery milestone.
5. **The matrix records the build's app and Worker separately** (`HEAD:frontend/src`, `HEAD:cloudflare-worker/src`,
   with `+dirty` when the tree differs), and the authenticated role from the session's own `/api/auth/me`. It marks
   every result as actual-role, not preview-only. `isPublishable` refuses addresses, links, bearer values and
   token-like strings in any evidence.

**Result at this head.** Every API step passes for all five roles. The control passes its three applicable steps. No
outside request is made. The 390 px column reads "not run", because this mode has no browser. The CLI's `--phone`
merges a browser run's results into that column.

**Observation for the owner (not counted as a failure).** `canReadBoard` (D757) treats an Operating Partner as
studio-wide staff. A delivery firm with no engagement on a venture can therefore still read that venture's Build
overview (200). The matrix records this in its evidence. Whether outside delivery firms should keep that read is the
owner's call.

**Waiting on the owner or an environment.**
- An isolated hosted qualification environment (#7147, #7149) and a way for synthetic identities to sign in there
  without a production bypass. The local run stands in for both until they exist.
- The 390 px browser pass. It needs a Playwright Chromium, and this session could not download one. It also needs a
  spec under `frontend/tests/visual/`; Admin's row there would need a branch-mode server.
- Whether a territory Admin should ever be appointed on HQ. If so, HQ needs tenancy scoping for licence admins first.
- The production sign-in release (#8680), which is verified separately.

**Rollback.** Delete `scripts/qualification/`, `scripts/lib/roleQualification*.mjs`,
`cloudflare-worker/test/_role_qualification_8688.ts`, `role_qualification_8688.test.ts`, this file, and the README rows.
No product code, migration or configuration changes.

**Verified.** `role_qualification_8688.test.ts` passes (2 tests), and so does `roleQualification.test.mjs` (9 tests).
Each claimed mutation was seen to fail:
- the cohort assignment lookup dropped → Advisor scope fails;
- the pain-theme ownership check dropped → Founder scope fails;
- the fund list always `gp` → Investor reload fails;
- both branches on one session key → Admin scope fails;
- the guard's production branch removed → the guard test fails.
