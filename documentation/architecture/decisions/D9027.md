### 1. Where the slot comes from

- The collector already reads each PR's timeline (D5603, D6678). That
  timeline's `committed` events carry each commit's sha, parents, committer
  date and message. `prProvenance` maps them to commits and passes them to
  `classifyPr` in `scripts/ci/agent-provenance.mjs` (D8068, D8517). It keeps
  only the status and the slot that `classifyPr` returns. The message is not
  kept on the PR, and nothing new is fetched.
- The collector passes `classifyPr` in. `ciScorecard.mjs` does not import
  `scripts/ci/`: the landing bot workflows load it (through `queueDeadline.mjs`
  and `prRisk.mjs`) from a sparse checkout that has no `scripts/ci`, which
  `workflow_sparse_imports_8314` enforces. The library keeps its own copy of
  the slot shape and the legacy trailer name, and the test holds both to
  `agent-provenance.mjs`.
- The slot is never taken from the branch name. A PR whose commits name no
  single slot goes to the `untrailed` row, even on an `agent/**` branch.
- A PR none of whose commits names any identity trailer is `human`. It gets
  its own row.
- The legacy `Claude-Session` trailer stands in for `Agent-Session` before
  the 2026-12-01 cutover. It carries no slot, so a PR with only that trailer
  is `untrailed`. So is a PR whose commits name two slots, a malformed slot,
  or that has no commits on its timeline.
- A merge of main with no trailers does not lose the slot. `classifyPr` marks
  that chain as failed, but the one slot the other commits name still stands.

### 2. The table

`### Queue by agent slot` follows the scorecard's main table. It has one row
per slot, in order, then `human`, then `untrailed`, for the PRs merged in the
window:

| Column | What it counts |
| --- | --- |
| Merged PRs | PRs in the row merged in the window |
| Queue to merge, from the first entry, median (min) | p50 of D6678's first-entry clock over the row |
| Entries per merged PR (mean) | queue entries over the row's queued merged PRs |
| Removed entries | entries a `removed_from_merge_queue` ended |
| Failed-check candidates | the row's merge-group candidates (D5973) whose outcome is `failed-check` |

- A row of fewer than 3 merged PRs still shows its figures. It is marked
  `(small sample)`.
- A figure with nothing to measure reads `-`. A day with no merged PRs says
  so in one line.
