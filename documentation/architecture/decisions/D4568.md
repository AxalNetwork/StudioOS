## D4568 — D1 scale S2: measured index and query fixes on the usage tables; retention stays a decision (#4568)

- **Status:** built by S15 on `agent/claude-s15/4568-usage-indexes`, stacked on #4567's branch (D4567). Not merged.
- **Parent:** #4554. Depends on #4567's measurements; coordinates with #4559 and D851/#2474 (AI accounting).
- **Migration:** `202611070806_ai_usage_guard_reservation_indexes.sql` (additive: two partial indexes).

### Decision

1. **A change ships only with evidence from the code that runs.** `scripts/usage-tables-matrix.mjs` reads every statement on the five usage tables from `cloudflare-worker/src` and plans it on the migrated schema. Its `--candidates` diff, and the benchmark's `--index-control`, are the evidence for each change. The 2026-11-07 snapshot is `documentation/audits/USAGE_TABLES_2026-11-07.md` (with its `.json`).
2. **Two partial indexes on `ai_usage_logs`:**
   - **`(guard_for) WHERE guard_for IS NOT NULL`.** It serves `chargedFor`, `tagUsage`, sessions, work runs and deck usage.
   - **`(reservation_uid, record_ref) WHERE reservation_uid IS NOT NULL`.** It serves the deck step, batch and generation charge reads, image draw, and revenue.
   - **Effect.** Thirteen statements change plan, and eight scans become searches. Each read stays flat as the table grows (6.4 → 0.005 ms at 100k rows locally), for about 0.0007 ms of upkeep per inserted row. Being partial, a row without the column writes nothing to the index.
3. **The agent run reads one agent's area.** `agentArea(env, id)` has the same rule and tie-break as `agentAreas`, restricted to one agent through `UNIQUE (agent_id, skill_id)`. `agentRun`'s policy check and `runDetail` use it; the boards that need every agent keep `agentAreas`.
4. **No query's meaning changes.**
   - `chargedFor` matches a reference model exactly, with and without the indexes. An unrecorded row stays unknown.
   - A whole mix ends with identical charges, balances, ledger, holds, proposals and runs, and every #4567 invariant reads 0.
5. **Indexes no plan uses are reported, never dropped.** `idx_ai_usage_user_page_created` and `idx_ai_usage_logs_skill` wait for production's query insights.
6. **Retention is a decision document.** It is `documentation/operations/USAGE_RETENTION.md`: hot, financial-record, cold and metrics tiers, the foreign keys that bound a move, and the counsel, owner, recovery, export, erasure, immutability and rollback gates. No row is archived or deleted. Analytics Engine is never a ledger, and a derived summary never authorizes spend.

### Why

#4567 measured two run-path reads whose cost grows with the platform: the `guard_for` scan and `agentAreas`. The matrix found a third family with the same shape: deck steps summing by `reservation_uid`. All three are fixed by the cheapest additive change: indexes partial on their own column, and a WHERE clause. Everything that would move rows, drop an index or change a transaction boundary waits for production's evidence or the owner's decision.
