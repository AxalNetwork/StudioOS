## D6069 — New version starts from the pitch deck's words, for any venture with a saved deck version (#6069)

- **Status:** built by S10 for #6069, 2026-11-15. The owner said yes on #6069 on 2026-11-15, reversing D909 §3's Spin-Out-only reading for this option and dropping the #6067 dependency.
- **Canvas:** NAR11 (Investor narrative · Boards), "Start from: Pitch deck vN's words"; RA-17 (Raise v2 · Boards) sets the frame.
- **Migration:** `cloudflare-worker/sql/migrations/202611151230_6069_narrative_start_from_deck.sql`. It rebuilds `narrative_version_meta`, keeping every row and column.
- **Paths:** Worker paths are relative to `cloudflare-worker/src/`; frontend paths are relative to `frontend/src/`.

### 1. What the owner chose

New version's Start from offers "Pitch deck vN's words" to every venture that has a saved pitch deck version. This was D909 §5's owner question.

- **The Spin-Out option is unchanged.** "The Spin-Out deck wording" (`live`, `spinout_deck_overrides` version 0) is still offered to Spin-Out ventures only.
- **The new option sits beside it.** A Spin-Out venture with a deck sees both options.

### 2. The store

Migration 463's CHECK allowed `start_from` to be `live`, `version` or `blank`.

- **The new value.** The migration adds `deck`. SQLite cannot widen a CHECK, so the table is rebuilt, which is the first option D909 §5 named.
- **No new column.** A `deck` row keeps the deck version it read in `based_on_version`.
  - **Why.** Many test fixtures, and every read that names the table's columns (`loadVersions`, the version record, `store.ts`), keep working unchanged.
  - **The guarantee.** A new table CHECK requires a deck version of at least 1 on every `deck` row.
  - **What `based_on_version` means.** On a `version` row it is a narrative version. On a `deck` row it is a `pitch_decks.version` of the same venture. Every reader branches on `start_from` first (`basedOnLabel`).
- **The `pitch_decks` triggers.** The two triggers from 202611031522 refer to this table. The migration drops them and creates them again unchanged, because SQLite refuses to rename a table while a trigger names a missing one.

### 3. The writer: `saveNarrativeVersion` (`services/raiseWriters.ts`)

- **The request.** `start_from: 'deck'` comes with `deck_version: N`.
- **Refusals:**
  - **404:** the venture has no saved deck version N, or no `deck_version` was sent.
  - **400:** `deck_version` was sent without `start_from: 'deck'`.
  - Nothing is written before these checks.
- **What it copies.** The words come from `services/narrative/deckWords.ts` and go into the new version's own `spinout_deck_overrides` rows, under the deck keys D908 maps.
- **How cards match keys:**
  - **By card title.** Problem, Market, Traction, Competition, The ask and the closing card each fill their key.
  - **The one-liner.** The cover card's subtitle (else the first card's) fills `cover.thesis`.
  - **Which words.** A card's body, else its bullets, else its first paragraph or quote field.
  - **Clipping.** Words longer than the section's limit are cut to it.
  - **Skipped cards.** Appendix cards and cards whose title names no key give nothing, so their sections stay empty. No words are made up.
- **What it does not copy.** The live wording (version 0) is not copied, and the deck is never written.
- **Fields in the dialog:**
  - One-liner and The ask, when filled in, replace the deck's words.
  - When left empty, they keep the deck's words.
- **Editing later.** An Edit cannot change a deck start's `based_on_version`. It is refused with a 400.

### 4. The reads

- **Form-options** (`services/records/raise.ts`):
  - It lists `deck` only when the venture has a current deck.
  - It carries `deck: { version }`, or null without a deck.
- **Based on** (`basedOnLabel`): a deck start reads "Pitch deck vN". The label carries through to the versions table, Home and NAR12's "from Pitch deck v3 · saved … · by …" line.

### 5. The dialog (NAR11, `pages/cycles/forms.js`)

- **The chip.** `startFromChips(versions, spinout, deck)` draws "Pitch deck vN's words", with the line "Copies the words of pitch deck vN, card by card. The deck does not change."
- **Chip order.** Saved versions come first, then the Spin-Out wording, then the deck, then Blank.
  - With no saved version, a non-Spin-Out venture that has a deck gets the deck chosen by default.
  - Without a deck, Blank stays the default.
- **The note.** It reads "Creates v5 for seed funds. Pitch deck v3 does not change."
- **The body.** It sends `start_from: 'deck', deck_version: N`, and no `based_on_version`.
- **The address.** `?start_from=` still chooses only a saved narrative version.
