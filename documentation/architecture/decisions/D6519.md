## D6519 — Read matching claim refs once (#6519)

The expired-claim reaper paginated GitHub matching refs as if they were issue comments. The endpoint returns all matching refs and ignores page/per_page; with at least 100 claims the same response repeated until the safety cap failed the scheduled workflow.

Read matching refs once. Continue paginating issue comments so an expiry marker beyond the first 100 comments still prevents duplicate notices. The reaper remains comment-only: it never deletes a held ref, including an expired one.

The regression uses 101 matching refs, a single expired holder at the end, and a notice on comment page two. It fails before the repair and when comment pagination is removed. No scheduled job or live expiry notification was manually dispatched.
