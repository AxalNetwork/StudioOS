## D7147 part 2 — Staging has no meeting-bot binding while the bot is off (#7147)

- **Status:** owner decision on #7147, 2026-11-18, built on `agent/claude/7147-staging-estimate`. It amends D886 for staging (`[env.preview]`, the Worker `studioos-preview`) only. Production and the top level are unchanged.
- **Why here and not `D886-p2.md`:** a part file is only for decisions numbered by their issue, D4000 up (D5615, `check-decision-ids`), and appending to `D886.md` is refused by `check-decision-appends`. So the amendment is recorded as a part of this issue's decision.
- **Code:** `wrangler.toml` (`[env.preview]`), `scripts/lib/meetingBotBinding.mjs` (`botBindingProblem`, `withMeetingBotBinding`), `scripts/lib/meetingBotTeamsMatrix.mjs` (row `site_binds_its_own_bot_host`), and their tests.
- **Migration:** none.

### What is decided

- **Staging binds no bot host.** The `MEETING_BOT_CONTAINER` Durable Object binding to `studioos-meeting-bot-preview` leaves `[env.preview]`. That Worker is deployed only by `meeting-bot-deploy.yml`, whose recent runs failed, and it is not known to exist. `MEETING_BOT` is `"off"` in preview.
- **The rule the guards enforce:**
  - production, and the top level, must bind their own host, `studioos-meeting-bot`;
  - preview may bind nothing at all, but only while `[env.preview.vars]` has `MEETING_BOT = "off"`. A missing `MEETING_BOT` counts as on;
  - if preview binds a host, it binds only `studioos-meeting-bot-preview`. Production's host and a local class (no `script_name`) are refused.
- **Provisioning never adds the preview binding back.** `scripts/configure-meeting-bot-binding.mjs` still writes production's and the top level's binding when they are missing. It keeps a correct preview binding if one is present, and refuses a preview bot switched on without one.
- **The Worker already tolerates the absence.** Every path that starts or runs a bot checks `botConfigured`, which needs `MEETING_BOT` on and the binding present. The Super Admin diagnostic returns `binding_missing` before touching the namespace.

### Reversing it

To bring the bot to staging, deploy `studioos-meeting-bot-preview` first, add the binding back to `[env.preview]`, and only then switch `MEETING_BOT` on. The guards accept that shape.
