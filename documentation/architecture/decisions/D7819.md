## D7819 — Company review ledger and public reads (#7819)

The ledger starts empty. A missing review is **No review recorded**, never an admission. `REACHABLE_COMPANIES` hides excluded/withdrawn records; held records remain reachable with their reason. `COUNTED_COMPANIES` also excludes held records. Both are literal derived relations over an explicit public projection. An unreadable ledger throws; there is no unfiltered fallback. The SQL-prepare baseline permits exactly one interpolation of REACHABLE_COMPANIES: it is a module-owned literal relation, contains no request data, and requested UIDs remain bound JSON. Existing readers are deliberately unchanged pending migration by their owning issues.

The current review is keyed by directory UID, without a directory or ingestion-run foreign key. Directory removal cannot erase its hold. Current rows cannot be deleted; updates append snapshots automatically. History and checks reject update/delete. Optional run_reference is opaque text, with no dependency on ingestion tables. Reviewer and admin_note are private and never selected by the public relations or UID reads. Bulk lookup binds JSON; excluded, withdrawn and removed records return only UID, status, reason code and its sentence. Saved names remain the responsibility of the saved-work reader, which must not restore hidden fresh values.

Statuses: admitted, held, excluded, withdrawn. The fixed member sentences are:

| Reason code | Sentence |
|---|---|
| verified | The recorded evidence has been checked. |
| quality_hold | This record is held while its quality is checked. |
| identity_uncertain | This company’s identity needs confirmation. |
| source_unavailable | The source could not be checked. |
| out_of_scope | This record is outside the directory’s scope. |
| source_withdrawn | The source has been withdrawn. |

Freshness fields stay separate: source_effective is the directory snapshot as_of; retrieved is null because the directory has no record-level retrieval timestamp; verified is the recorded website_verified_at; last_failed_check is the latest failed check; next_review and withdrawn_on are ledger values. Review time is never used as verification time. Evidence entries retain their own publication/retrieved/verified dates, selected by the directory ID resolved from this UID only. Later failure does not erase earlier successful checks. Unknown dates are null.

The source guard accepts explicit pending readers and a separate, initially empty maintenance-writer list. It strips comments by parsing TypeScript with esbuild, retains executable SQL strings, rejects new physical-table references, and rejects stale/missing entries. Only the three issue-reserved readers can be absent. #7810's publisher service must join the pending list if it lands first; if this lands first, that service must use this module. #7821's classification writer needs an explicit reviewed maintenance entry when present; neither future file is preallowed.

Rollback: revert the Worker code; the additive empty tables/indexes are safe for the previous Worker. No production writes or record classifications are performed by this issue.

Mutation checks: tests reject deliberate changes counting held records and projecting private review fields. Each mutant was restored byte-for-byte; the clean tests are rerun before push. Full-suite readiness is deferred while #5719 remains open; the owner permits draft PRs only.
