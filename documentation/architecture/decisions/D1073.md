## D1073 — Member Trust Center: honest failures, evidence-led review and admin-tool links (#2965)

- **Slot:** S18 · Codex, claimed from S29 at the owner's request.
- **Scope:** part 1 of #2425. No migration, new API client or public Trust Center change.
- **Status:** built and tested locally; deployment and the owner's live check remain **UNVERIFIED**.

### Requirements reads

Both desktop and phone show **Unreadable — Your requirements could not be read.**
with **Try again** when `/api/trust/me` fails. Neither the score badge nor the
score panel nor an empty-obligations success message is rendered. Retrying
enters loading again and then shows the newly read requirements. Provider or
exception text is not used in this failure message.

Main already had an early desktop guard saying “Trust score unreadable.” This
task retains that protection, gives it the requested summary and retry behavior,
and shares the same failure content with the phone frame. The successful-read
score formula is unchanged.

### Starting is not submitting evidence

The generic **Start** button and its page handler are removed from every
obligation list. Real envelope **Open to sign** and a member's pairwise **Sign**
remain; the page cannot put a requirement under review merely by clicking Start.

`POST /api/trust/obligation/:key/start` stays mounted for stale clients. It
requires authentication, then returns HTTP **410** with
`error: obligation_start_retired` and a fixed message directing the caller to
the actual signing or verification flow. This applies to known and unknown
keys. It does not create trust tables, seed obligations or update their status,
evidence or timestamps. Existing evidence-submission and signing handlers are
unchanged. Historical `in_review` rows are not guessed at or migrated.

### Identity follows the Worker

The Identity tab is visible only for the authoritative `investor` role returned
by `/api/trust/me`. A legacy `kyc_v1` row does not override this gate for founders,
partners, admins, advisors or exploring members, matching `seedObligations`'s
non-investor waiver. Investors still have the tab when their row is absent.
The existing server authorization and KYC submission rules do not change.

### Platform administration leaves the member page

- The sanctions tab, screening form and recent-screening list are removed.
- Admins no longer fetch or render the platform-wide pairwise NDA list. Resend
  and Void controls and their browser prompt are removed from this page.
- Admin-only **Admin tools** links open **Contracts · Pairwise NDAs** at
  `/admin/contracts?tab=ndas` and identity/sanctions reviews at `/admin/kyc`.
- Non-admin members retain their own pairwise list, signing and envelope history.
  Role agreements and the caller's other contracts remain.

The admin APIs are not retired: their admin desks and other consumers still
use them. The links confer no authorization; those destinations keep their
existing Worker gates. No request is made to an admin tool merely to draw its
link, and no new write or audit path is introduced.

### Integration and canvas limits

task's starting main (`32cd64750d`), those files and D1072 were absent; the named
integration PR #2925 did not yet contain them. This task therefore preserves

existing Section for the two specified admin links. It does not invent a new
screen or public Trust Center. TRU10's exact visual match remains **UNVERIFIED**

The same member component currently serves `/trust`; D1072 owns moving it to
`/trust/me` and publishing `/trust`. Neither routing nor D1072's public files is
changed here. The component fixes apply when that integration moves it.
