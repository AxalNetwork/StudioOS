## D6557 — Read recorded network activity (#6557)

`GET /api/relationships/activity?limit=10` assembles recorded events from four
existing stores. Limits must be whole numbers from 1 to 50. Follow-up tasks
belong to the caller and join their own book. Introduction event rows name the
caller as requester or teammate. Completed LinkedIn import jobs and decided
duplicate reviews belong to the caller. Pending work is not an event.

The response is `{ events, sources, complete }`. Each event has `kind`, `at`
and `label_parts` containing a fixed action and, for imports, the recorded
created-contact count. No contact names, task titles, notes, emails, URLs or
other members' books are selected. Events are newest first and globally
limited after each source is bounded. The frontend client exposes `activity`;
the card itself remains with #5310.

A failed source is `unreadable` with a fixed safe reason and `complete: false`;
other readable events survive. Readable sources with no events stay readable.
The response remains HTTP 200 to preserve partial events through the existing
client; consumers must inspect `sources` and `complete`. Anonymous and support
sessions use the existing relationship refusal gates. The read writes nothing.

Mounted real-SQLite tests exercise participant and owner isolation, ordering,
limits, safe projections, a failed source alongside available events and a
readable empty source. Mutation probes invert ownership, unreadability,
ordering, bounding, counts and support gates.
