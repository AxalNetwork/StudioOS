### Shared Lightbox

pageBelow="lg" opts into a normal-flow page below 1024px. It reuses the
shared usePhoneWidth hook (PHONE_QUERY), reads the width on first render and
follows changes. With no opt-in the existing modal behavior is unchanged.
Page mode has no backdrop, dialog role, aria-modal, inert marking, scroll
lock, Tab trap or Escape listener. Its back row calls the same onClose as
the dialog's close button. The default back label comes from the module
part of the eyebrow. A supplied React bar node replaces that header.

Widening installs the existing dialog effects; narrowing releases them.
Other lightboxes remain modal on phones. Header padding is 18px 20px and
footer padding 14px 20px, as both the form and Record a session canvases draw.
The dialog still mounts in place, with z-80, focus return, counted locks and
the shared Escape stack. #1665 later adds its provider/function bar and other
page extensions; this PR does not preempt those parts.

### Field boundary and form behavior

FormLightbox draws a 560px Lightbox with the cycle and module name from the
registries, title, sub (legacy lead), foot and CTA (legacy button fallback).
It forwards bar and uses the existing cycle-form-* test identifiers. Inputs
have unique label/description ids even with nested forms/dialogs.

formFields is the one adapter for Worker/canvas and legacy definitions.
Legacy select becomes CH, textarea becomes T with a 56px minimum, other
legacy inputs keep their kinds and validation. Canonical fields use
kind T/CH/CK, name, k, input, opts/options, ph, h, def and note. Canvas
t/m/on option spellings and tuple checks are accepted alongside
value/label/meta/checked. Brackets are removed from display examples;
money-input euro placeholders use dollars. Other labels/notes keep their currency,
and stored field values are not rewritten. Native radio chips have an explicit
visible keyboard-focus outline on their labels.

CH is a native radio group styled as chips. CK uses native checkboxes and
the value is an array of declared option values. Empty groups draw their
explicit empty sentence, else a recorded-empty sentence, with no invented
options. Locked options stay disabled. Parts group two named fields under
one label; each still has its own input, value and validation.

when is a trusted form function or a declarative {name,value} condition;
array check values use membership. Invisible fields are neither validated
nor sent, preventing a stale hidden amount from entering another signal kind.
Current row values take precedence over fromQuery values, then field
value/initial/def, then checked options. A numeric CH default can name a
canvas option index when it is not already an option value.

loadOptions keeps fields hidden and saving disabled until it resolves.
Its {field:{options,note}} entries merge at the adapter boundary, supplying
defaults and truthful no-provider notes/links. Failure preserves the
Worker's sentence and disables saving. Late completion after close is ignored.
The parent keys each mounted form per row; a new callback does not re-read.

Notes may be strings, {text,href} or functions of current values. File inputs
pass the chosen File to onSubmit; the parent owns multipart construction.
Legacy validation still checks amounts, scores, dates, required/max/choice
rules and form.check. CK additionally rejects undeclared values. No required
marker is drawn. Refusals appear on the named visible field or above fields.
Values survive a refusal, including 402, without dispatching a paywall event.

The CTA is disabled with Saving… while a write runs; a ref prevents duplicate
submits. A normal success notifies onSaved and closes. done(result) can instead
keep the dialog/page open with returned text, a safe in-app Continue link,
optional one-time link text/copy and Close. Lightbox's existing focusKey moves
focus off the removed Save control after a done transition. No signature request is sent.
Phone controls use larger radii and row heights with a full-width 52px CTA.

### Addresses, keys and the registry (PR 1, second part, S11, 2026-10-17)

#1652's frontend PR (#1688) and #1669 are on main. This part is the start-now
half of PR 1 that S1 set on 2026-10-17. `CycleRoute.jsx` waits for #1655's PR 2,
and PR 1 merges only after that half lands.

- **Every form has a `key` and a `cta`** in `forms.js`. A key is unique in
  its module (`risk`, `feature`, `must-have`, `formation-step`, `readiness`,
  `narrative-version`, and each Grow form's noun), so `/new?form=<key>` can
  name a later Add. An Edit's key is `edit-<noun>`. Today's forms keep their
  copy: an Add's `cta` is its button, until #1657 (Raise, Grow) and PR 3
  (Build) bring the canvas's. Every Edit's `cta` is "Save" (decision 7), and
  its row button stays "Edit", Solution design's "Mark" and Operating
  systems' "Choose connector".
- **`initialValues` and `validate` take the canvas's kinds** (decision 2), so
  every caller, not only `FormLightbox`, reads the same field shape:
  - a CK value is an array of its checked options, and must name declared
    options;
  - a CH `def` may be its option's index;
  - a T box's `input` is today's `type`;
  - a `parts` field's own parts hold the values;
  - a `when` field is checked only while it counts.

  Today's `type` fields keep every rule, with the same sentences.
- **Every Add has an address** (decision 5).
  - `App.jsx` has `/<cycle>/:slug/new` beside each `/:slug` line, with the
    same guard, rendering `<CycleRoute cycle="…" adding />`.
  - `/validate/customer-research/new` is a `HistoryRedirect` to
    `/validate/record`, with the query kept.
  - A static segment outranks a parameter, so the redirect wins over
    `/validate/:slug/new`, and `/:slug/new` wins over #1658's `/:slug/:id`.
  - Until `CycleRoute`'s part lands, `/new` draws its module page, and the
    form opens from the module's Add as today.
- **`RecordsTable`'s Add link passes its entry's `state`,** so an Add pushed
  to its `/new` address carries `state.under`, and closing goes back
  (decision 5).

`CycleRoute`'s part followed #1655's PR 2 (below). `formOptions` follows
#1690, which declares its route, so it goes in PR 2.

### The routed forms (PR 1, last part, S11, 2026-10-17)

#1655's PR 2 (#1730) and this PR's first part (#1726) are on main. This part
is `CycleRoute.jsx`'s, and it deletes the side sheet.

- **The open Add is the address's** (decision 5).
  - On `/<cycle>/<slug>/new`, `CycleRoute`'s `adding` opens the form whose
    `key` is `?form=`, else the module's first.
  - A `?form=` the module has no form for opens the first, so a stale link
    (Add risk once it leaves Solution design) still lands on an Add.
  - Each Add on the records table is a link to its address, with
    `?project_id=` and, for a later form, `?form=<key>`, pushed with
    `state.under`.
  - Closing goes back when the page pushed it; a deep link replaces itself
    with the module page, the query kept without `form`.
  - A known module with no form replaces `/new` with its page; an unknown
    slug keeps the redirect to the cycle.
- **`?add=1` is an alias** (#1652's card hrefs). It replaces the URL with
  `/<cycle>/<slug>/new`, the rest of the query kept. A module with no form,
  and the overview, still ignore it.
- **The open Edit is the history entry's.** A row's Edit pushes the same
  URL with `state.editing`, the row's id. The row is looked up in the module
  read's rows, and the form starts from `valuesOf(row)`. Back, ×, Cancel and
  a save all go back. An entry opened with no history before it replaces
  itself instead, so closing never leaves the app.
- **One `openForm`, one place for it** (decision 6, and #1655's decision 13).
  - At 1024px and up it is the dialog, at the mount after the size
    container.
  - Below 1024px it is the page, drawn as the content of `cycle-route-body`,
    in the gutter, with nothing at the mount.
  - Crossing 1024px with a form open moves it between the two places, so it
    draws again from its first values.
- **A save re-reads.** `onSaved` marks the page dirty. A second effect,
  beside the lightbox's (whose line three tests pin), re-reads once `adding`
  and `state.editing` are both gone, so nothing reloads behind an open form.
- **`formOptions` ships on its own** (S1's ruling A, 2026-10-17), because
  #1736 (D690) merged 14 seconds after #1735. `cycleWrites.js` gains one
  `formOptions(cycle, projectId, slug, query?)` over D690's form-options route,
  with `query` after `?project=` and only a known cycle and a slug's charset
  in the path. No form calls it yet: PR 2 (Validate, after #1692), #1657 and
  #1704 do, and the route answers 404 for a cycle whose records task has not
  registered its specs. `check-api-drift.mjs` used to count only verbs on a
  mounted router's own name, so it could not see D690's routes, which a
  factory (`createCycleRecords()`) declares on a local `route`, and read this
  first call to one as drift. The guard now also reads a router a same-file
  factory builds, and `form_options_d695.test.mjs` runs it.
- **`RecordFormSheet.jsx` is deleted.** `FormLightbox` keeps its test ids
  (`cycle-form-<name>`, `-loading`, `-save`, `-note-<name>`, `-refusal`).
  Its CH fields are radio chips, not a `<select>`, so a value the read did
  not offer cannot be picked; `formErrors` still refuses one.
