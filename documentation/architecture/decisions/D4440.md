## D4440 — Correct event syndication settings, drafts and approval (#4440)

Follows S1's cross-vendor review of merged #4431, assigned in [#4440](https://github.com/AxalNetwork/StudioOS/issues/4440), Part of #3725. All eight confirmed findings are addressed before a real channel adapter is connected. No adapter, migration, secret, external send or attendee import is added.

1. **HQ settings:** the radio and read validator use the Worker's `admins` value, alongside `approved_events`. The mounted settings regression submits through `parseSettings`, and accepts an already stored `admins` setting.
2. **Deliberate choices:** the panel and approval dialog track edited account IDs. `choicesOf` sends only those IDs; posted, withdrawn, cancelled and skipped rows are excluded and their controls locked. A clean row is never echoed by an unrelated Save. Ask also excludes unavailable and terminal rows. Historical listing URLs and timestamps remain recorded.
3. **Account availability:** a historical listing remains readable after its account is disconnected or otherwise unavailable to the event. Its `adapter_ready` is false even if that channel has an adapter. Expired/error accounts are also unavailable for choices. Those rows are not sent by the client and cannot prevent an otherwise valid Save/Approve.
4. **Accepted copy:** Ask notifies the editor after a successful save, which rereads the channel panel. A toggle-only choice omits overrides; the Worker retains the current `overrides_json` on conflict in that case. Only a row whose copy was edited sends copy; an explicit empty object still clears overrides. An unrelated choice therefore cannot overwrite newly accepted Ask copy.
5. **Approval:** non-public events do not read or show posting choices, say "Private events are never posted to other channels", and approve with no channels even if the channel read would fail. The public-event count includes only available nonterminal saved selections/pending listings or deliberately selected new rows. An untouched suggested default or failed row is not advertised as a post; failed listings keep their explicit Retry action.
6. **Event Save:** the event record's Save no longer refreshes the channel panel. Its draft survives. Only accepting saved Ask copy changes the channel refresh revision.
7. **Reconnect:** after a successful disconnect, reload runs even if the new connect fails. The next attempt is a fresh Connect, not a second disconnect against a gone account.
8. **Ticket links:** normalize whitespace before serialization, then validate with the Worker's `^https://[^\s]+$` rule and length bound. Invalid input sets `aria-invalid`, shows a field-level error, and blocks Save/Preview. A blank override uses the event link.

The settings test uses the actual Worker parser. `syndication_review_4440.test.ts` combines the real client choice projection with real Worker reads/writes over baseline SQLite plus migration 710, preserving terminal history, omitting disconnected rows and retaining accepted copy on choice-only writes.

Existing D1490/D1491 and SY8 tests stay enabled. Older approval fixtures now identify their public visibility, refused-save tests first make an explicit edit, and the SY8 mount check follows its save notification. New/changed assertions are inverted and restored, and behavior mutants exercise the fixes. The root build precedes the required full drift run. Production D1 is not read or written; the owner verifies deployment after merge.
