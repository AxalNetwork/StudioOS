### What main did

The brief editor kept its text in its own state, so it lived only while the Brief tab was open. The project page read the brief once (keyed on the project and its reload counter), and a save did not touch that read. The mounted test, run against main, showed each of these:

- save, open another tab, come back: the editor showed the text and version from before the save, and the next save was refused (409 `brief_changed`);
- text typed and not saved was gone after a tab switch, without a word;
- leaving the project by link, Back or reload asked nothing;
- a refused save kept the text in the fields but offered no action that let the next save succeed; a save refused because the project was archived showed the Worker's sentence and did not say it was archived.

### What is built

- **The draft is held by the project page.** `useBriefDraft(uid, read)` in `ProjectBrief.jsx` is called from `ResearchProject.jsx`, which stays mounted while the member moves between the project's tabs. It holds the saved copy (sections and version) and the typed sections, in memory, for the open project only; a different project starts afresh. Nothing goes to browser storage.
- **A save refreshes the held copy in place.** The saved sections and version replace the held copy; the editor is not keyed on the version, so it is not remounted or reset. The next save names the version the last one wrote. A later page read (another action's reload) is taken only when nothing is typed and it is not older than the held copy.
- **Leaving asks; a tab switch does not.** While typed text is unsaved, `useLeaveGuard` is on with a destination test, `keepsProject(uid)`: `/research/projects/<uid>` and its one-segment tabs keep the draft and go through unasked; every other route, Back or Forward out of the project, a reload or a closed tab asks with the guard's own sentence. Once saved, nothing asks.
- **The leave guard's optional destination test.** `createLeaveGuard({ …, keeps })` and `useLeaveGuard(dirty, message, confirmLeave, keeps)`: `keeps({ pathname, search, hash })` answering exactly `true` lets a link, a path `navigate()` or a Back/Forward (read from `win.location`, which has already moved) through without asking; a kept Back/Forward also moves the guard's recorded history position, so a later declined Back walks back the right distance. A test that throws or answers anything else asks, as with none. With no `keeps`, every caller behaves as before; their tests are unchanged.
- **A refused save loses nothing.** On a 409 that is not `project_archived`, the page says "Not saved: this brief changed since you opened it. Your text is still here, exactly as typed." and offers one action, "Load version N, keep my changes" (N read from the brief on record; "Load the saved brief, keep my changes" if that read fails). It re-reads the brief: a section the member changed against the copy they started from keeps their text and tick, every other section takes the saved one, and the held copy takes the saved version, so the next save is accepted.
- **Archived meanwhile.** A 409 `project_archived` says the project was archived while the member was writing, keeps the text, and offers no load action.
- `ProjectBrief.jsx` still holds its eight headings as one list and the tick's label, "Reviewed by you".
