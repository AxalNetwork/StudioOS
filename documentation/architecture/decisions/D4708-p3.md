## D4708 part 3 — HQ Security: the page split into its folder, behaviour unchanged (#4708)

- **Status:** part 3 of #4708 (HQ Security audit 6/6), built by S26, 2026-11-16. Part 1 is `D4708.md`, part 2
  `D4708-p2.md`. A structural refactor of the frontend only; nothing is deployed by it.
- **Scope:** `frontend/src/pages/hq/SecurityPage.jsx` and `frontend/src/pages/hq/security/`. No Worker file, route,
  gate, request, copy or session-containment behaviour (#4669) changes.

### Decision

`SecurityPage.jsx` (1,226 lines) becomes the shell (263 lines). It keeps what belongs to the route: the three reads,
their ordering (D4699), the session acts (`actLeavesOperatorSignedIn`, `runSessionAct`, `SessionsPanel`) and the
default export. Everything it rendered moved, line for line, into eight files under `pages/hq/security/`:

| File | What moved |
| --- | --- |
| `SecurityConsole.jsx` | The view: rail, header, tabs, the page-level banner and the `workspaces` map; `securityEventsBar` |
| `securityShared.js` | The unreadable sentinel, the Events filter defaults, the formatters, the identity line |
| `SecurityParts.jsx` | `Zone`, `Stat`, `NotRecordedList` |
| `AccessZones.jsx` | The Access tiles and the data-access zone |
| `PrivacyZones.jsx` | The previous data-subject-request zone and its parts |
| `TrustZones.jsx` | The Sanctions card and the KYC zone |
| `AiSafetyZone.jsx` | The previous AI safety zone and the token-anomalies tile |
| `ResilienceZones.jsx` | The Backup / DR card and its two sentences |

Four inline blocks of the `workspaces` map became components with explicit props (`AccessSummaryZone`,
`DataAccessZone`, `DsrZone`, `KycZone`); they render the same markup in the same place.

- **Importers are unchanged.** `SecurityPage.jsx` re-exports every name it exported before, so nothing that imports
  that path changes. `security_page_split_4708.test.mjs` holds the export list.
- **The reads stay on the page.** The view and its zones make no request (the folder's existing rule); the same test
  checks every moved file.
- **Source-reading tests follow the code.** Tests that pinned a rule by reading `SecurityPage.jsx` read
  `frontend/test/_securitySource.mjs`'s `securityRaw()` instead: the shell and its parts in a fixed order, the pattern
  `_hqTeamSource.mjs` set for HQ Team (D5044). No assertion was changed or removed. Two path lists moved one entry to
  where its code now lives: `header_ask_d1443p5` (the header is in `SecurityConsole.jsx`) and
  `absence_helpers_single_definition` (the same hand-written title-caser, now in `securityShared.js`; converting it
  would change behaviour, so it stays deferred as before).
- **Two registries name the file that now draws the page.** `admin_route_reachability` credits the page's doors
  (Trust obligations by role, Trust center content) through its `COMPOSED` map, `SecurityPage.jsx` →
  `security/SecurityConsole.jsx`, as it does for every page drawn from the files beside it. The Super Admin rail
  registry (`lib/railOptions/superAdmin.js`, H36) names `SecurityConsole.jsx` as the file that mounts the rail; that
  entry is read by its parity test only.

### Not done

- The title-caser is not moved onto `lib/absence.js` (a behaviour change, outside a structural refactor).
- No zone's markup, wording or state was changed; anything a review finds there is its own change.
