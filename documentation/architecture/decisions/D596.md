## D596 — Research companies: UK companies from Companies House, with no personal data

**The company directory takes UK companies from Companies House's free bulk
company data, with each row citing the register and the Open Government
Licence, and with no personal data.** Slots S10 and S18, issue #1231, 2026-10-07. From
the owner's answer 1A on #1083, which D537 records. Migration 405.

### The importer

`scripts/import-companies-house.mjs` reads the unzipped
"BasicCompanyDataAsOneFile" CSV that Companies House publishes each month
(https://download.companieshouse.gov.uk/en_output.html) and writes migration
405. It never writes to a database.

**What it reads, and what it never reads.** It reads only these columns, each
by name: `CompanyName`, `CompanyNumber`, `CompanyCategory`, `CompanyStatus`,
`CountryOfOrigin`, `IncorporationDate`, `Accounts.AccountCategory`, and the
four `SICCode.SicText` columns. No `RegAddress.*` column is named, so no
address, postcode or care-of name can reach a row. The bulk file holds no
officers and no persons with significant control, and nothing here asks for
them. The country is the company's country of origin, not its address. If a
column the importer needs is missing from the header, it throws, so a format
change can never move a value into the wrong field.

**What it keeps.** A company that is:
- `Active`;
- a private or public limited company;
- of United Kingdom origin;
- not filing dormant accounts;
- in a SIC code that the reviewed table maps.

**The reviewed SIC table.** `SIC_SECTORS` in the importer lists 58 UK SIC
2007 codes. Each maps to a key of the crosswalk's `COMPANY_SECTOR_RULES`
(D533), which the importer imports rather than copies, so a mapped code always
reaches a taxonomy market. A code is listed only when its activity is the
label's own: "62012 Business and domestic software development" maps to
`software development`, "64191 Banks" to `bank`. Broader codes, such as IT
consultancy or "other business support", are left out rather than stretched.
A test holds every value to the crosswalk. A company's sector is the label of
its first mapped SIC code, and `sic_codes` keeps every code the register
lists, so a reviewer can check the mapping.

**The cap: 3,000 rows**, the same as D537's Wikidata file:
- within a sector label, the oldest incorporation date first, then by company
  number;
- across labels, round-robin in label order, so no sector (software, banks)
  takes the whole file.

The order is deterministic, so a re-run on the same month's file writes the
same migration. Oldest first favours companies with a trading history over
the month's new incorporations, and the dormant filter has already removed
companies that do not trade.

### Where the rows go: `research_company_directory`, not a sibling table

The register's rows fit the directory's columns. Migration 405 adds one
column, `sic_codes`, and does not create a sibling table. The directory's
search, filters, `coverage` and `facets` (D534) already read this table, so
the country filter and the facets count the new rows with no Worker change.
A sibling table would have meant a second query, and a second total, on every
directory read.

What a row carries:
- `uid` `ch-<company number>`, in lower case, the key `INSERT OR IGNORE` uses;
- the name as the register writes it;
- `website` empty. Companies House records no website, and the directory
  already counts an empty website as none (D534's `coverage`) and prints
  nothing for it, so none is invented;
- `country` `United Kingdom`, as migration 376 names GB, so the crosswalk maps
  it;
- `founded_year`, the year of the incorporation date, kept from 1800 to the
  year of the pull and otherwise NULL;
- `sector` and `sic_codes`, as above;
- `source_name` `Companies House`; `source_url` the company's public page
  (`find-and-update.company-information.service.gov.uk/company/<number>`);
  `source_license` the OGL line, "Contains public sector information licensed
  under the Open Government Licence v3.0."; and `as_of`, the date of the
  file.

Funding, revenue, headcount and valuation stay NULL, and the page prints
"Not recorded".

### One company, one row

#1231 asks for a company that both Wikidata and Companies House name to appear
once, matched on the website host where both have one. **The bulk file
records no website,** so a host match can never apply to a Companies House
row. What migration 405 does instead:
- Each row is inserted only if the directory holds no United Kingdom company
  whose lower-cased name is the register name's key: lower case, one space,
  and any trailing "plc", "public limited company", "limited", "ltd" or
  "ltd." taken off, with or without that suffix. "TESCO PLC" is skipped when
  the directory holds a UK company named "Tesco". The Wikidata row is kept,
  because it carries a website.
- The match is exact and limited to the country. A same-named company in
  another country is a different company and is added.
- It runs at apply time (`WHERE NOT EXISTS`), so it sees whatever Wikidata
  rows are applied before 405.

The owner chose this UK name-key match (option 1A on #1231), because the
Companies House bulk file has no website to match against Wikidata's website
host. A register number match would require #1229's Wikidata importer to read
P2622 into another column; that was not the chosen rule.

**Order.** Migration 403 (Wikidata) merged before 405. The migration runner
applies numbered files in order; 405's `WHERE NOT EXISTS` sees 403's rows.
Applying 405 first could leave a duplicate name when 403 later inserts its
Q-id without a name check, so this order is part of the decision.

### On the pages

The company profile no longer assumes every record is Wikidata's.
`recordSource` reads the row's `source_name`. A Companies House record says
"Companies House · OGL v3.0", shows the OGL line the licence requires, and
links "View the Companies House record". The sources table names the row's
own register. A directory row from Companies House says so under its name,
and the directory's source boundary names both sources and the OGL.

### Guard

`cloudflare-worker/test/research_companies_house_d596.test.mjs`, on fixtures
shaped like the bulk CSV, so it holds without the network:
- every SIC code maps to a crosswalk key, and so to a market;
- no address column is named, and a row from a record full of address data
  carries none of it;
- the CSV reader keeps quoted commas and doubled quotes, and trims the
  header;
- the filters keep only active, UK-origin, non-dormant limited companies in
  a mapped code, and the year comes from the incorporation date;
- selection is oldest first, round-robin, capped, and one row per number;
- the file applies; its rows apply twice to the same rows; each row cites
  Companies House, its page, the OGL and `as_of`; the number is unique; the
  website is empty; no figure is set; no column looks like an officer, an
  address or a person;
- a UK company the directory holds by name is not added again, while a
  same-named company abroad is;
- the directory's `coverage`, country facet, `country_code=GB` filter and
  sector facet count the new rows from the table.

`frontend/test/research_companies_house_d596.test.mjs` holds the profile card,
the sources table and the directory row to each row's own source.

Mutations: dropping the name check, reading a `RegAddress` column, the
dormant filter, the origin filter, the de-duplication by number, or the year
bound; changing the OGL line; reversing the age order; and a SIC value that
is not a crosswalk key are each caught. So are a profile that ignores the
source and a directory that drops the row's source.

### Applied source file

The GitHub research-import workflow ran the committed importer on the
2026-10-01 `BasicCompanyDataAsOneFile` export, without writing to production.
Its data branch `data/companies-house-37645259090` contains the unchanged
generated `405_research_company_directory_companies_house.sql`: 5,704,712
register records read, 694,468 passing the filters, then a 3,000-row cap.
On a fresh local schema with migration 403 applied first, 2,986 Companies
House rows are inserted; 14 of the 3,000 are already represented by a UK
directory name. The resulting directory has 6,286 rows, of which 3,165 are
labelled United Kingdom. Reapplying the insert statements adds no rows.

The applied rows have no officer, person-with-significant-control or address
columns; they carry country of origin only. All Companies House metrics without
a source record remain NULL. The actual-data guard checks every row's public
register URL, OGL line, SIC mapping, UK name-key uniqueness, missing metrics,
and the directory's country and sector facets after 403 and 405.

**The `ROUTE_MAP` row for `/research/companies`** belongs to #1229, so it is
not edited here.
