## D7259 — Preserve active remediation handoffs (#7259)

The owner selected Q2 C: reconciliation honours a fresh slot STATUS or a
review tracker paired with an open pull request. A session that cannot write
an atomic claim must not have its ongoing work returned to the ready queue
on every sweep. This implements that available portion of #7259.

### Recognition and ownership

The tracker engine reads the latest trusted, leading AGENTS-format STATUS for the
same issue and S21. `IN_PROGRESS`, `BLOCKED` and `READY_FOR_REVIEW` hold the
tracker for 24 hours from the comment's creation, matching the standard claim
TTL. A later `DONE` releases that STATUS hold. Invalid, future, stale,
untrusted and other-task reports do not acquire work. The issue's update
timestamp does not refresh a session's report. Existing atomic claims,
assignees, manual slots and workflow barriers retain their meaning.

A same-repository open PR targeting the default branch can name a tracker
through its exact issue URL, qualified repository reference or standalone
`#number`. Code examples, other repositories and explicit alert/finding
numbers do not count as issue references. Existing canonical protected alert
links continue to work. One PR may reference several trackers. Duplicate
references converge; several matching PRs are all linked and move the tracker
to review without selecting one arbitrarily or leaving it ready. No PR
content is changed.

Before changing an existing tracker, including between comment and label
writes, the engine re-reads the issue, atomic claim and handoff evidence. A linking
transition may complete its own PR review handoff, but cannot bypass another
session's STATUS or claim. One association check serves reconciliation,
ownership holds and the last PR read: the linked PR's identity, open state,
branch, repository and current issue/alert reference are checked again before
linking effects. Label transitions clear
the old queue state before adding the new state, so an interrupted review
handoff cannot leave both ready and review permanently set. A `state:review`
tracker with an open matching PR stays in
review. Once the PR is closed and no fresh STATUS or other ownership barrier
remains, an unresolved tracker returns to ready. An unreadable handoff does
not permit a ready write. Closing a PR alone never closes its tracker:
GitHub's resolved alert state and default-branch instance remain authoritative.

### Remaining scope

The owner's Q1 A opaque batch format remains approved but is not implemented
here. Batch creation, grouping, prioritisation and atomic member-claim
exclusion remain work for #7259. Shared claim-file changes require the scoped
handoff from #7566. This change does not dismiss alerts, create branches or
PRs, publish finding details, or alter workflow permissions.

### Verification

Focused tracker and reconciliation tests cover fresh and expired STATUS
holds, explicit release, wrong-author/task/slot reports, handoffs during API
reads and writes, unreadable history, PR scope and freshness, multi-tracker
PRs, multiple PRs, interrupted transitions, retry convergence and
scanner-confirmed closure. Source mutations check the new assertions in
both directions. Local build, drift and guard results are recorded in the PR
with any environment limitations; this decision does not assert their result.
