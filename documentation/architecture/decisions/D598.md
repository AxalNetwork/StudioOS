## D598 — Admin Studio (`/studio`) shows no Worker AI rail

**Issue #1273, slot S01, 2026-10-06.** The owner's words: "In Admin profile
/studio page should never contain WORKER AI · STUDIO sidebar, remove it". No
Worker change, no migration and no new route.

### What was true on main

- D556 (#1180) gave the admin's front door a Worker AI rail. `AdminStudioHome`
  wrapped the page in `RailFrame` around `StudioRail`, a rail on workspace
  "Studio" whose coverage was the studio glance.
- No other file mounted `StudioRail`.
- `admin_studio_overview.test.mjs` and `rail_frame_d556.test.mjs` required the
  rail.

### The change

- **The page has no rail.** `/studio` for an admin, the Super Admin included,
  renders no `RailFrame`, no `StudioRail` and no `WorkerRail`. The page is back
  in the plain `<div data-testid="admin-studio-home">` it had before D556. It
  keeps D246's order: Eadwyn (`StudioInterview`), the posture, what needs a
  decision, then one card per other Admin page.
- **`StudioRail.jsx` is deleted.** Nothing else mounted it.
- **Every other page keeps its rail.** That includes every other Admin page,
  and D556's shared frame is unchanged. D556 carries a note pointing here.

### Tests

- **`rail_frame_d556.test.mjs`.** Its Admin Studio tests are replaced by one
  that fails if the page mounts a frame, a rail or `StudioRail` again, or if
  `StudioRail.jsx` comes back. It also fails if any file mounts a Worker AI
  rail on the "Studio" workspace, and it checks that the Dashboard still
  mounts this page for an admin. The census no longer expects a
  component-framed rail.
- **`admin_studio_overview.test.mjs`.** It again forbids any rail on the page
  or in its cards, as it did before D556 re-aimed it.
