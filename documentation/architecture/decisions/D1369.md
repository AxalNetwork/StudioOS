## D1369 — Every offered model has a stated use and a connection to the modules that can run it

- **Status:** asked for by the owner in the s28 chat (#3626). Built by S20 in #3640, which the owner merged and which deployed on 2026-10-28 (deploy run 40781515007). Filed by S1, who chose a new number over extending D764 (option A on #3626).
- **Builds on:** D764 (the model matrix in the Worker) and D720's rail. D764 is unchanged: this decision adds to it and does not rewrite it.
- **Migration:** none.

### Why

Pricing's "Used for" column was built from page-level picks alone. It missed:
- models the backend uses on its own (the guard, images);
- several offered models that no page named.

Some models also cannot take a chat request at all. The Clef models answer typed questions, and an alternate embedding model cannot write into the search index, whose dimensions are fixed.

### What was decided

1. **One registry.** `cloudflare-worker/src/services/ai/moduleModels.ts` gives each of the 60 offered models:
   - an operation (for example `decision`, `chat`, `embedding` or `rerank`);
   - the rail kinds it fits;
   - a plain purpose line.

   The owner's availability switches stay authoritative over it.
2. **Pricing reads the registry.** "Used for" shows the purpose and the connected module names, on desktop and phone. The copy states application suitability, not benchmark rank. Provider and infrastructure names stay out of product copy.
3. **Conversation choices widen; fallbacks do not.**
   - Compatible models join a page's conversation choices, and the page's default is kept.
   - Extra choices never enter an automatic fallback chain.
   - Image queries, decisions, sentiment and classifiers never become chat picks.
4. **Module operations run over supplied material only.** `/api/ai/modules` is mounted by `routes/ai.ts`; its source is `routes/ai_modules.ts`. It has three routes:
   - `GET /?page=`: discovery;
   - `POST /quote` and `POST /run`.

   The route rules:
   - The authenticated member is the charged account; a body cannot name another member or a business record.
   - Persona scope follows `requireRole`. Admins may use View as. Super Admin rows need the admin role and the server-hydrated Super Admin flag.
   - The request body is capped at 7 MB.
5. **Each model gets the request shape it accepts** (`moduleShapes.ts`): typed decisions, image queries, labels, sentiment and turn detection. Translation, transcription, voice, image, embedding and ranking reuse their existing paths. An alternate embedding model never writes the search index.
6. **The common router stays the one gate.** It owns:
   - the guard and the assistance switches;
   - partner gates;
   - budget holds and settlement;
   - usage logs.

   A quote validates the same inputs as a run. A rerank hold counts each query and context pair. Spend records the page the request started from.

### Not built

- **No specialist screens.** The operations exist in the backend, but no new page offers them.
- **Not selectable:** streaming transcription and the automatic safety guard stay backend uses, not module operations a member picks.
- **No business-record writes:** no operation reads or writes a member's records automatically.

### Verified

From #3640:
- **Tests:** 83 backend and 18 frontend tests pass on merged main.
- **Inversion check:** all 57 changed assertions were inverted, and 36 deliberate faults were caught.
- **Live read-only checks after deploy:**
  - all 52 publicly offered models show a purpose and module names;
  - unsigned `/api/ai/modules` returns 401.
- **Not run:** no paid inference. The tests therefore do not show every account's live model availability.
