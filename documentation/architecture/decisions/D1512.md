### 1. One quote, one run, one hold

`POST /api/decks/:id/areas/quote` prices every selected area. `POST /api/decks/:id/areas` admits **one** run for all of them through `admitDeckRun` (D1502), under one parent hold keyed by the request's Idempotency-Key. The same key twice is the same run, with no second hold and no second set of proposals. Quote = hold = the sum of the lines ≥ what settles.

- **What the quote reply carries.** Per area: its lines, which sum to its hold (pd14: variants × price, the image pipeline's steps, "Safety check on every text run", "Values free · read from your records"). Then its gates (`image_check`, `plan`, `records`), its refusal if any, the total hold, and `expires_at` (10 minutes). The tests hold the sum.
- **The quote is stateless.** Its uid is the expiry plus a signature of what it priced: each area, its element, its model, its change, and each line's price. A Generate whose plan differs from that signature, or that comes after the expiry, is 409 `quote_stale`. A quote stores nothing, so it needs no row.
- **Areas.** At most 6, on one card. The whole-deck build (dk-auto AUTO-6, step 7) uses D1502's `deck_build` class, which takes up to 60 areas across cards under the same one hold. #3768 is the caller. #3753's caps (text 6, images 3) stay what they are: the `AiGovernor` paces the steps, and the caps are never a ceiling on the run.

### 2. Variants are seeds of one model; Compare is gone

The final canvas removed Compare models (pd16), so `mode: 'compare'` and a request-side `variants: [{ model }]` are not read. The client sends `variants: n` (1 to 3) and never a model.

- **The model** is the AIRail's pick for each element, resolved on the server (`elementModelFor`, D1503, with HQ's lock first, D1549).
- **A text variant** records its seed: a hash of the deck, the card's uid, the area and the variant, so the same area always gets the same seeds. It runs at its own temperature (0.4, 0.7, 0.9).
- **An image variant** k draws at its own seed pair, 2k and 2k+1 (the pair is the pipeline's one redraw). Variant 0 draws exactly as a press always has.
- **Who pays (decision O).** Each variant is charged.

### 3. What each area can be

| Kind | Elements | What runs |
| --- | --- | --- |
| text | title, kicker, body, bullets, callout, caption | An area with words takes the founder's change (Rewrite, Shorten, Expand). An empty area gets words written to its text capacity from the card's own words (the "empty text area" element). In both, words that name a number the card's text does not are refused (`wordingProblem`). |
| chart | chart, table, timeline | The model picks only which recorded series to show; code builds the block (`chartBlock`). With nothing recorded, the area is refused `not_recorded`. |
| image | photo, illustration | The image pipeline (D1505), every image checked. What it drew is stored as a `proposed` deck image. |
| records | team grid, team bios, use of funds, round terms, cap table, logo wall, interview quote | No model. `ventureElement` (D1543) with its gates. The one variant is free. |

Anything else (speaker notes, a figure, an upload, the dialogs) keeps its own route.

### 4. Gates are the server's

An area that cannot run is refused on its own, with its sentence, and the others still run. The refusals:
- the records gates (D1543: `pick_required`, `no_consent`, `no_permission`, `not_included`, `not_recorded` …);
- HQ's lock on a model the caller's plan cannot run (`role_locked`);
- an element switched off for the member (`not_switched_on`);
- picks that cannot be read (`picks_unreadable`), so nothing runs on a guess;
- a card with nothing to write or draw from.

When no area can run, the answer is 422 `nothing_to_run` and nothing is held.

### 5. Proposals, Accept and Discard

`deck_area_proposals` holds one row per area of a run, made when the run is admitted.

- **Settling.** `GET …/areas/proposals?batch=` settles each row once its steps have ended: `ready` when at least one variant can be placed, else `failed`.
- **What each variant carries.** Its model's name, seed, cost and seconds; its own error ("This variant failed. You were charged only for what ran."); and the free code critique, which costs nothing (`fits` from D1517's fit, `contrast_aa` from the deck theme's ink on its ground, `density_ok`). A check that was not run is null, never false.
- **A failed variant leaves the others acceptable.**
- **Accept** is by the area: `POST …/areas/:card_uid/:area_id/accept { proposal_uid, variant }`. It records the outcome (`accept`, or `accept_all` from Accept all) and supersedes the area's other open proposals. An image variant's deck image is kept, and the area's other variant images are discarded. #3761 reads the outcome as the accept rate.
- **Discard** records `discard`.
- **Expiry.** A proposal nobody decided expires after 14 days in A15's daily cleanup (`Jobs.cleanup`), with D1508's image proposals. The expiry lives in its own module (`areaExpiry.ts`, importing only types). `models/jobs.ts` is imported almost everywhere, and `areas.ts` reaches the readers of a venture's records, so this keeps member bank data out of every cron and admin path (`mercury_member_privacy_d752.test.mjs`).

### 6. A run's image is now a stored proposal

Until now, the run's image step (`pipelineStep`, #3753/#3756) returned the drawn bytes as its result. A run keeps a step's result as JSON of at most 64 KB, so no run image could ever be shown or kept. `storeDrawn` (`imageDraw.ts`) is now the one store path, for the press and the run alike: metadata stripped, the AI XMP packet added, the bytes in R2, and a `proposed` row with the seed, steps and provenance. The step's result names the stored image (uid, file URL, size, alt, model), never the bytes.

### 7. The screen

The lightbox (S1's, D1604) keeps its layout. Changes are only where the batch needed them:
- **Batch mode.** `batchMode()` now reads a swapped row as on. Before, it read `availability()`'s `null` as off.
- **What goes to the batch.** Only what only it can do: several areas under one hold, variants 2 and 3, and words for an empty area. A single area with one variant keeps its own route, as do a Title's headline, speaker notes, a figure and an upload.
- **One quote.** The batch's rows share one quote. Each row shows its own hold, and the footer adds "Valid for 10 min".
- **Results.** One result per variant, labelled "<model> · variant n · <seconds>", each deciding itself through the area routes. Accept all places one variant per area, the first still open. Accepting one variant marks the area's other variants "Another variant was placed in this area." Discarding the last open variant discards the proposal.
- **The one-click build** still starts no run, so its "Live progress per card" line stays Coming later, now titled with #3768.
