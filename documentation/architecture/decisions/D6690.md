## D6690 — Formation catalogue version 1, "legacy parity", generated from the code arrays (#6690)

- **Status:** built by S11 for #6690, 2026-11-16. Part of #6680 (plan key C2, Phase 2).
- **Depends on:** the tables (#6689, D6689) and the truth pass on the arrays (#6683, D6683), both merged.
- **Generator:** `scripts/build-formation-seed.mjs`. It writes `cloudflare-worker/sql/migrations/202611161600_6690_formation_catalogue_seed_v1.sql`; `--check` fails when the file is not what the arrays generate.
- **Test:** `cloudflare-worker/test/formation_seed_6690.test.ts`.

### 1. What version 1 is

Version 1 reproduces today's six products exactly, so that readers can move to the catalogue (#6691) with no change a founder can see. The migration writes version 1 as a draft, fills it, then publishes it and makes it current.

- **Published by:** `published_by = 0`, meaning the seed migration itself, not a person.
- **Published at:** fixed at `2026-11-16T00:00:00Z`.
- **Every database gets it** (D6689). After version 1, versions are written in HQ's database only (owner decision 8).

### 2. Where each row comes from

The generator reads the arrays from the Worker's own modules. Each is now exported, with its text unchanged. The handoff steps moved from an `if` chain in the incorporate route into `HANDOFF_NEXT_STEPS`, which the route reads.

| Array | Module | Becomes |
|---|---|---|
| `JURISDICTIONS` | `routes/legal.ts` | One form per entry, in order. `form_key` is the id; `label`; `offer_mode` `orderable`; `legacy_gate` `'1'`. Every other display field (country, entity type, summary, pros, cons, the null cost, time and tax fields, `atlas_supported`) goes to `legacy_display_json`. |
| `JURISDICTION_MAP` | `services/incorporationCompany.ts` | The jurisdiction (`US-DE` becomes country `US`, subdivision `DE`) and `legal_form_family`. No registry name: no array holds one. |
| `JURISDICTION_TEMPLATES` | `routes/legal.ts` | One pack item per template, in the entry's order: `before_filing`, a `document`, acted by Axal, titled as today. |
| `COUNSEL_REQUIRED_TEMPLATES` | `routes/legal.ts` | `counsel_required` on the US forms. Only the Wyoming charter, as today. |
| `HANDOFF_NEXT_STEPS` | `routes/legal.ts` | One pack item per step: `after_filing`, a `step`, acted by the founder, at position 100 and up. Delaware C-Corp has none. |
| `STATE_FILING_FEES` | `services/incorporationQuote.ts` | One fee line, `state_filing_fee`: payee is the source's authority, collected by the payee, at formation, amount null, `checked_on` null. Its source is a `formation_sources` row (`registry`). |
| `STANDARD_EVENTS` | `routes/compliance.ts` | One provisional fact per event, `compliance_event_<n>`, holding the event as JSON, in order. |
| `JURISDICTION_CERT_TITLES` | `services/incorporationPacket.ts` | A provisional fact, `certificate_title`. Wyoming has none, as today. |

Two rows go beyond the arrays, as #6690 asks:

- **Counsel on the non-US forms.** Every pack item of `uk_ltd`, `sg_pte` and `ee_oy` is `counsel_required = 1`.
- **Where the business operates.** `us_wy_ccorp` and `us_de_llc` carry a `not_recorded` fact, `registration_where_operates`, with no value.

### 3. What is never seeded

- **No `recorded` fact.** Every fact is `provisional` or `not_recorded`, because no source has been read for any of them.
- **No fee amount, and no `checked_on`** on any fee line (D4357).
- **No invented fact.** Every value is a string or field that the arrays already hold.

### 4. A finding for the owner

`STANDARD_EVENTS` still carries uncited figures in three descriptions:
- Delaware's "Min ~$450/yr" and "(~$100/yr)";
- the Delaware LLC's "Flat $300/yr";
- the UK's "(£34 online)".

#6683's truth pass covered `JURISDICTIONS` and the packet, not `compliance.ts`.

Parity means version 1 carries these strings as they are, as `provisional` facts, which is no claim that they are checked. A merged seed is never edited, so removing them is a code change plus a version 2. That question is asked on #6690.

### 5. Why `formation_catalogue_6689` loads an earlier schema

Its cases build their own version 1. With the seed applied, version 1 already exists, so those cases now load the schema from before the seed (`loadSchema(d, { below: 202611161600 })`). What they test is unchanged.

### 6. Tests

`formation_seed_6690.test.ts` runs on the full migrated schema, with the seed applied as every database applies it.

- **Each array is rebuilt from version 1's rows and compared with the array: equal.** This covers `JURISDICTIONS`, the templates, the counsel set (US forms), the fees, the map, the events, the certificate titles and the next steps.
- **Nothing is recorded:**
  - no fact is `recorded`;
  - no fee line has an amount or a day;
  - all six forms carry `legacy_gate '1'`;
  - every non-US item is counsel-required;
  - the "where it operates" fact is `not_recorded` with no value, on the two forms that need it.
- **Version 1 is published and current,** and `catalogueForm` serves it.
- **The generator gives the committed file byte for byte,** and gives it again on unchanged arrays.

**Mutation check:** each change to the generator is made, the file is regenerated with it, and the test is run. All mutants were caught. Among them:
- a template out of order or retitled;
- the wrong counsel flag;
- a wrong currency;
- an event, a certificate title or a next step dropped;
- the jurisdiction code split wrongly;
- a display field dropped;
- a fact seeded `recorded`;
- a fee amount seeded;
- the version left as a draft;
- `legacy_gate` not `'1'`.
