### What was built

- A third tile, "Advisory refunds due · As of now · N open · oldest YYYY-MM-DD". Zero reads 0 with the word Zero; a failed read reads Unavailable and "never 0 owed"; a read of 200 open rows (the route's cap) reads "200+", a floor.
- The block under the exceptions table: open rows (booking, why, Stripe payment, amount, recorded on, "Mark refunded…"), then a collapsed Resolved list with resolved on, resolved by and the reason (one line, in full on focus or hover). Empty, never any rows, loading and unreadable are each drawn. Below 1024px both lists are cards with a 44px full-width action.
- "Mark refunded…" runs Scope → Review → Step-up → Result. The reason is 12 to 500 characters (the D224 floor, `lib/refundReason.js`). 409 and 404 offer Refresh the list; 503 keeps the reason and offers Try again; a session without an authenticator is told to sign in again; a cancelled step-up keeps the reason; no answer at all says the row may or may not be marked and asks for a refresh, never "nothing changed". The Result names the signed-in operator and the server's `resolved_at`.
- Needs attention gains "N advisory refunds due, oldest recorded YYYY-MM-DD" when a row is open, after the critical items.
- A viewer who is not a Super Admin is never sent to the read and sees no block and no tile; a 403 on the read hides it too.

### The two points from the handoff

- **Resolved order.** The route now orders resolved rows by `resolved_at`, newest first (open rows still newest recorded first), so the 200-row read keeps the latest resolutions, and the list says "most recently resolved first". Tested in `cloudflare-worker/test/advisory_refunds_resolve_5305.test.ts`.
- **A row with no amount.** On this page each such row reads Not recorded, never 0, and nothing is summed: there is no total row, and currencies are never added together. `advisors_money.ts` is unchanged: its `refunds_owed.amount_cents` and `refunded.amount_cents` add only recorded amounts, and since #6393 each carries `unpriced_sessions` beside it, the count of rows the sum leaves out. A page that draws that sum must say it excludes those rows; none draws it today (`earningsLedger.js` carries `refunds_owed_cents` and shows it nowhere).

### Departures from the canvas

- **Step-up has no code field in the sheet.** The request helper's own authenticator prompt opens when the Worker asks for a step-up, as it does for RefundReviewFlow; the sheet's step 3 says so and holds "Verify and mark refunded" / "Marking…".
- **No Eadwyn draft in the rail.** No Eadwyn route drafts this reason. The Review step has "Start from this row's values", a local template from the row's own values with blanks (`____`) for the Stripe refund id and date; a reason still holding a blank is not sent. It is not labelled Eadwyn.
- **"Most recently resolved first"**, not "most recently recorded first", after the route change above.
- **Unreadable** keeps the house word and its "Retry" button (`ui/Honesty.jsx`) in the block; the tile reads Unavailable, as the canvas draws it.
- **"Sign in again"** is not a button: the sheet closes, and signing in again is the operator's own step.
- **Phone** follows RV20; the sheet is a bottom sheet below 640px and a 680px dialog above.
