### 1. No second ledger

The issue asks to extend the registries that exist. So:

- **Tickets live in #5570's admission state.** `swarmOf(state)` keeps the swarm's tickets under a `swarm` key of the
  same `AdmissionState` that `createAdmissionControl` keeps its slots in. One `AdmissionStore` transaction (one
  Durable Object storage transaction, through `DurableWorkspaceAdmissionStore`) covers both. Neither #5570 file
  changed.
- **Container work takes #5570's lease.** A `code` or `video_render` ticket that swarm admission admits calls
  `admission.enqueue` under the ticket's uid. The provider and region caps, fencing, expiry and reconcile of #5570
  then apply unchanged.
- **The bill is the lease's settlement.** A lease-lane ticket settles through `admission.release`. Its charge is that
  lease's one settlement, including the reserve charged when metrics are missing. The swarm ticket records it once.
- **Revisions and publication stay #5581's and #5585's.** The active-revision check at admission is advisory. The
  compare-and-swap head is the authority, so a ticket admitted on a head that then moves is refused at the swap and
  rebases.

### 2. Admission (`swarmAdmission.ts`)

**Modalities and work classes.** There are five modalities: `code`, `document`, `brand_image`, `video_render` and
`final_publication`. The issue's distinctions map to them like this:

| Distinction | What it is here |
| --- | --- |
| Registered agent | A record. It holds no capacity. `planning()` and the read model report it apart from executions |
| Queued task | A waiting ticket |
| Concurrent job | An admitted `code` ticket (lease lane) |
| Iterative generation | An admitted `document` or `brand_image` ticket (inline lane: a model call under the existing AI holds, no container) |
| Expensive render | An admitted `video_render` ticket (lease lane) |
| Final publication | An admitted `final_publication` ticket (serial lane: at most one live ticket per asset) |

A container exists only while a lease is held. A lease belongs to a ticket and never to an agent, so no container is
ever pinned to an idle agent.

**Checks, in order.** The first one that fails is the refusal:

1. The request's shape.
2. A replay. The same terms answer the current state and take the lease again. Changed terms are refused with
   `ticket_contract_changed`.
3. The kill switch (503 `swarm_halted`), platform-wide or per venture.
4. The venture's scope (403 `wrong_tenant`).
5. The agent: 403 `agent_revoked`, or 503 `agent_unverified` when its state was not read.
6. Modality, provider and model, each allow-listed per venture (422 `modality_not_allowed`, `provider_not_allowed`,
   `model_not_allowed`).
7. The active revision: 503 `revision_unverified` when it was not read, 409 `stale_revision` when it is not the base.
8. The render budget: 503 `budget_unverified` when it was not read, 409 `budget_exhausted` when it is spent.
9. The storage quota: 503 `storage_unverified` when it was not read, 409 `storage_quota_exhausted` when it is full.
10. Capacity: the venture's concurrency, the modality's concurrency, and one publication in flight per asset.

A ticket that fails only on capacity waits, with its reason. When the venture's queue is full, the refusal is 503
`no_capacity` and lists every reason, for example `["modality_capacity", "venture_queue_full"]`.

**Budget accounting.** A quote of `unavailable` reserves the ticket's ceiling, never 0. A venture's committed budget
is its live reserves plus its settled charges. Waiting tickets commit nothing.

**Promotion.** `promote` admits waiting tickets fairly. Each pick goes to the venture that holds the fewest live
tickets, then to the earliest-queued ticket. Budget and storage are checked again. A venture missing from the input
admits nothing.

**Ending a ticket.**
- `settle` bills a ticket once. A repeat returns the first bill with `first: false`.
- `withdraw` ends a ticket that never ran, with no bill: a waiting ticket, or a lease-lane ticket whose lease is
  still waiting. Anything that may have run must settle (`settle_required`).
- `revokeAgent` withdraws the revoked agent's waiting tickets. Its running tickets keep their capacity until they
  settle, because revoking does not stop work already running.

**Audit.** Every transition and every refusal after validation appends an entry in the same transaction, so it
commits or rolls back with the change. At most `SWARM_AUDIT_MAX` (2000) entries are kept, and `audit_dropped` counts
the ones dropped. Moving them to D1 is part 2 (question A below).

### 3. Capacity, cost and throughput (`swarmCapacity.ts`)

**Not zero.** A figure the platform does not record is `not_recorded`. A record that exists but could not be read or
priced is `unavailable`. Neither is ever shown as 0.

**The read model.** `capacityReadModel` reports by modality, venture (tenant), team, provider, budget, storage and
backlog (with the reason each ticket waits, the render backlog and the oldest wait), plus costs and bottlenecks. It
raises these alerts: `kill_switch_on`, `venture_halted`, `budget_low`, `budget_unverified`, `storage_low`,
`storage_unverified`, `queue_near_full` and `audit_dropped`. With a scope it shows one venture only, which is a
tenant's own view. Registered agents are counted apart from executions.

**Bottlenecks the platform records today.** `readBottlenecks` reads these. It refuses `wrong_tenant` before any
statement, and binds every statement to the scope's tenant and company:

| Signal | Source |
| --- | --- |
| D1 conflict rate | `work_graph_events`: `advance_refused` rows with `stale_revision` against all head-move attempts. These are the real CAS refusals |
| Agent planning overlap | `work_graph_lease_events`: `busy` against `acquire` |
| Outbox backlog | `work_graph_effects`: pending, claimed and dead rows, and the oldest pending one's age |
| R2 uploads | `work_graph_integrity_events`: `blob_put`, `blob_refused` and class-A operations. The cost is `unavailable`, because no price per operation is recorded |
| Human review queue | `work_graph_release_manifests` newer than their line's published head |
| Image-model capacity, GitHub PR/CI wait, preview transcoding, egress | `not_recorded`. Nothing records them yet |

A statement that fails makes only its own signal `unavailable`. With no attempts, the conflict rate is
`not_recorded`, not 0%.

**Cost attribution.** The categories are AI inference, compute, GPU, storage GB-month, requests, egress, Stream
output and CI minutes. A category with no entry is `not_recorded`. Any unpriced entry makes its category's total, and
the grand total, `unavailable`, while the known part is still shown. A reserve charged because metrics were missing
is counted as `estimated_microusd`, never as measured.

**Throughput.** `throughput` gives p50 and p95 (nearest rank) for queue wait, run time, time to an approved
deliverable and human approval delay, and approved deliverables per hour. It uses recorded timestamps only.
`readApprovals` takes each run's approval time from its first applied `advance_head` event that carries an approval.

### 4. The synthetic benchmark (`swarm_benchmark_5586.test.ts`)

**Scale.** It runs 10, 50 and 100 concurrent tasks across code, documents, brand images and video renders, in two
tenant-isolated ventures.

**What it runs.** The real stack:
- #5570's placement and leases.
- This swarm admission.
- #5581's revisions and CAS head, on a real SQLite database built from the migrations.
- #5581's verified blob put, over an in-memory R2 that checks SHA-256.
- #5585's publication.

**Determinism.** The clock is simulated: one tick is one second, and nothing else moves it. Costs and durations are
fixed per modality. This is the D1551 load-test pattern, so the same input gives the same figures on any host, and
the test checks this. The suite runs in about 2.5 seconds.

**Chaos cases.**

| Case | How the harness produces it |
| --- | --- |
| Simultaneous same-asset updates | Tasks share assets. The CAS refuses stale writers, which then rebase |
| Busy provider | 6 containers for up to 100 tasks |
| Provider brownout | A reader that throws |
| Missing callback | The lease expires, reconcile settles it, and the late callback takes the same bill |
| Partial upload | R2 refuses a torn body |
| Crash between revision and head move | The completion is redelivered with the same keys |
| Redelivered completion | Replayed, with no second head move and no second charge |
| Changed citation | The approved manifest becomes unpublishable |
| Revoked agent | Its waiting tickets end with no bill |
| Budget exhaustion | A small venture is refused, and is never overcommitted |
| Region unavailable | Placement queues. It never falls back to another region |

**Assertions.**
- Every task ends.
- Every acknowledged revision is its asset's head or an ancestor of the head, and `head_seq` equals the count of
  acknowledged moves.
- Every finished task is charged exactly its measured cost, once, and every lease settlement agrees.
- Nothing is charged to a refused or revoked task.
- No lease or ticket is left holding capacity.
- No venture's run writes into another venture's records, and a cross-tenant write is refused.
- Two concurrent publishes of the same manifest land once, with four effects. A replay returns the same effect ids.
- The measured D1 conflict count equals the stale rebases the harness saw.

Each run reports its figures through `t.diagnostic`. At 100 tasks the larger venture shows p50 16 s and p95 56 s to
an approved deliverable, with a CAS conflict rate of 0.375. Those are simulated seconds, not a production claim.

  transaction from the in-state entries, using their `seq` as the idempotency key. Then audit survives state
