## D5073 — Evidence and Capital Relationships: no stale venture, batch commands, reconciliation by stable id (#5073)

- **Status:** Built, 2026-11-09 (Worker routes and frontend; no migration).
- **Builds on:** D1263 (Evidence decisions), D1193 (Eadwyn's proposals), D5069/D5070.

### What was wrong

1. **Stale Evidence.** `useEvidence` started a project-scoped read with no sequence or venture check, so a slow answer for venture A that landed after the user switched to B replaced B's state, and A's read stayed drawn while B loaded.
2. **Sequential "bulk" writes.** Evidence Accept all, Dismiss and Share, and Capital Relationships' Accept all, sent one request per row in a loop: slow, and fragile to retry at volume.
3. **CRM state held as snapshots.** The pipeline kept the open investor as the object it was clicked as (and fell back to it when a re-read no longer had it), kept the previous venture's investors drawn while the next loaded, kept list picks whose investors had gone, and kept the view only in component state.

### Worker: batch commands

Both return one authoritative result per row, in the order sent. They are not all-or-nothing, and each row runs the same function a single press runs, so every existing check stays per row.

- `POST /api/cycles/raise/evidence/items/batch` `{ action: 'accept' | 'dismiss' | 'share', items }`, at most 50 (`EVIDENCE_BATCH_MAX`). `items` are `{ id, snapshot_hash }`, `{ id }` or `{ id, version, visibility }`. Each row calls `acceptItem`, `dismissItem` or `setSharing`: the founder gate, the snapshot hash an accept must still match, the version a share must still hold, and the source-changed refusal are all per row. A refusal is `{ id, ok: false, code, message }` (`changed`, `decided`, `invalid`, …) and writes nothing for that row. A row sent twice is refused the second time. A body with other keys, an unknown action, none or more than 50 rows is 400. Non-founders are refused as for a single press.
- `POST /api/cycles/raise/capital-relationships/proposals/accept-batch` `{ uids }`, at most 50. Each runs `acceptProposal`: still open, the venture's own investor, the one prospect writer's validation. A proposal that is no longer open or belongs to another venture is that proposal's refusal (`unknown_proposal`, `unknown_investor`).

### Frontend

- **Evidence reads.** Every read takes a sequence number; an answer is applied only if it is the newest and the page is still on the venture that asked. The state names its venture, and the page draws "loading" for any state that is not its own venture's, including the frame before the new read starts.
- **Bulk Evidence.** `decideMany` sends one request and maps the results back, one outcome per proposal. If the request fails as a whole every row says not saved; a row the server did not report is not called accepted. Share sends one request for the items that change and names the ones refused.
- **Bulk scope in words.** Accept all says it applies to the loaded page ("Applies to the 50 loaded proposals from this source, at most 50 per press. 10 more loaded ones wait for the next press. More are waiting on the server beyond this page; look again after this press to load them. Each outcome is listed after."). Capital Relationships' Accept all is the note's proposals, as it said, now in one request, with refused ones counted and listed.
- **Pipeline.** The open investor and the view (`?investor=<id>`, `?view=list`) are in the address; refresh, Back and Forward land on the same screen. The open investor is looked up by id in the LATEST read. If it is gone, an explicit "No longer in this view" sheet is drawn, not a stale one. Changing venture clears the open investor and dialogs and never draws the previous venture's investors; list picks that no longer exist are dropped.

### Tests

Worker: evidence batch (partial failure with a stale snapshot, a repeat finds the rows decided, the cap, shape, repeated ids, who may send, share with a moved version) and proposal batch (decided, accepted, another venture's, not a uid, a repeat; the cap). Frontend: A → B → B resolves → A resolves leaves B; a late failure for A does not blank B; one request per press with per-row outcomes; the scope text; the proposals' one request; the open investor from the address, "no longer in this view", the view in the address, and a venture switch. Five mutations (no sequence guard, no per-venture state in the prospects read, a stale open-investor fallback, among others) each fail a test.
