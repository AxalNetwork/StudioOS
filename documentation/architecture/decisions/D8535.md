- **Test:** `cloudflare-worker/test/data_room_live_revocation_d8535.test.ts`.

### What the investor holds while the room is open

The investor reads the room (`GET /api/data-room/shared/:projectUid`, and the document page `GET /api/research/diligence/:grantUid/files/:fileUid`). A preview is the room's one-time signed link: `POST /api/data-room/shared/:projectUid/files/:uid/download` mints `/api/files/dl/<token>`. The room has no preview apart from that link (the `data_room.ts` header says why). The room's one export is a Library copy (`POST /api/room-library/items`, D6869). That copy is a reference that follows the grant.

The owner can end the grant in two ways while the room is open:
- **revoke** it: `DELETE /api/data-room/:projectUid/grants/:uid`;
- **move** the venture to another of their companies: `POST /api/projects/:id/move`.

### The rule

The grant as it stands when a request arrives decides that request. A link, a page or a copy made under an earlier grant carries no access of its own.

- **The next read is refused.** The room and the document page answer 404, the same answer as a room that does not exist. The room drops out of `GET /shared`.
- **A signed link checks the room's gate again when it is opened.** `/api/files/dl/:token` takes a token with audience `data_room:<projectUid>` and asks `dataRoomLinkOpen` (`routes/data_room.ts`) before it opens the object. Every one of these must hold:
  - an active, unexpired grant for the token's user on that venture;
  - a live file in the venture holding the token's object;
  - the file's tier and expiry, and the grant's folders (`tierAdmits`);
  - for a file behind the NDA, an active NDA.

  If any fails, the link answers the route's one generic 403 and opens nothing. A gate that cannot be read also opens nothing. The founder's own links (audience `data_room_founder:`) are not an investor's and are not checked against a grant. The deck proof link (`routes/deck_proof.ts`) mints the same investor audience, so it gets the same check.
- **Lifetime of a cached preview URL:** 120 seconds from minting (`ttlSec: 120`; `signedDownload.ts` caps every link at 300 seconds). The link is single use. Once it has been opened, it is spent. Before it is opened, it is refused from the moment the grant ends, even within its 120 seconds.
- **A range request** for the file being previewed is refused in two cases:
  - on the opened link, because the link is spent;
  - on a link minted before the change, because of the gate check above.

  `/api/files/dl` serves whole files only and ignores `Range`. A range request therefore never returns bytes that a full request would refuse.
- **The export is cancelled, not refused at download.** The Library reference lapses with `lost_reason = 'revoked'` on the investor's next Library read or Ask (`reconcileRoomRefs`). Its index entries are deleted. Its download answers 409 `open_in_room` with no room named and no link minted. A new Library add is refused with 404.
- **Reopening from history is refused.** Repeating the same request (`POST …/download`, or the room URL) gets the 404 above. The opened link gets 403.
- **A response that began before the change completes.** The Worker checks the gate when the request arrives, then streams the object. It does not check again mid-stream. A response whose headers were sent before the revocation delivers the whole file. Nothing that starts after the change opens a stored object. The test checks both: the held response's body is read after the change and is whole, and the bucket records no read after the change.

### A move ends the room's grants

`projectMoveStatements` writes `projects.company_id` for the move route. Its batch now also sets every active `data_room_grants` row of the venture to `status = 'revoked'`, so the move and the end of the grants commit together. The grants were given under the company the venture leaves. This follows D5459's rule that an approval stops covering new actions once the project moves. The owner re-shares from the venture's new company with `POST /grants`, which reactivates the same row.

This applies only to the move route. A filing that places a venture in its newly created company (`toNewCompanyUid`, `incorporationCompany.ts`) does not end its grants.
