## D614 — Deal rooms and co-invest: join checks the deal, a Free investor can still leave, co-invest is Institutional, and create refuses an unknown status

**Issue:** #1307, found by #1165's audit (area 6). **No migration.**

### What was decided

Four gates. Each is on a route that let a request through that it should
have answered.

1. **Join checks the deal.** `POST /api/deals/:id/dealroom/join` answers
   404 `deal_not_found` when no deal has that id, and writes nothing.
   Until now a bad id inserted a membership row, and that row counted
   against the investor's room quota (`investor_dealroom_max`) like a real
   room.
2. **Leave is open on every plan.** Every `/api/deals/*` route sits behind
   the Professional gate (`INVESTOR_PRO_PREFIXES` in `index.ts`), so an
   investor who dropped to Free could no longer call
   `DELETE /api/deals/:id/dealroom/leave` for the rooms they had joined.
   The gate is now `requireInvestorTierExcept('professional')`, which skips
   the requests listed in `INVESTOR_PRO_EXEMPT`
   (`middleware/requireInvestorTier.ts`). That list has one entry: `DELETE`
   on the leave route. Listing deals, joining a room and every other method
   on these prefixes stay Professional.
3. **Co-invest is Institutional.** `GET /api/funds/syndication` checked the
   role and nothing else. The pricing page (`InvestorPricingPage.jsx`)
   sells "Co-invest discovery" on Institutional only, but any investor
   could read every listing. The route now runs the same check as
   `requireInvestorTier`, `userMeetsInvestorTier(user, 'institutional')`,
   and refuses with the same 402 body, `investorUpsell('institutional')`
   (`required: 'institutional'`), so the client's paywall opens. Admins and
   partners pass, as they pass every investor gate. A founder is still
   refused by role first (D370).
4. **Create refuses an unknown status.** `POST /api/deals` passed any
   `status` to D1, and a value the column's CHECK refuses came back as a
   500. It now answers 400 `unknown_status` with `allowed`, which is
   `DEAL_STATUSES`: the list `PUT /:id` already validates against, and the
   one the table's CHECK allows (`schema_baseline.sql`). No status, or an
   empty one, still defaults to `applied`.

### Not changed

- **`POST /api/deals` still accepts `rejected`.** The table allows it, and
  this issue asked only that unknown statuses be refused. `/draft` and
  `PUT /:id` both send a pass through `POST /:id/pass`, because that route
  requires a reason (task #127). Whether create should do the same is left
  open, and the PR says so.
- The room quotas, the tier prices and the paywall copy.

### Verified

`cloudflare-worker/test/dealroom_coinvest_gates_d614.test.ts` runs on a real
node:sqlite database and asserts each gate from both sides:

- **Join:** an unknown deal is refused and uses no quota slot, and a real
  join right after counts as the first.
- **Leave:** a Free investor can leave a room through the gate mounted as
  `index.ts` mounts it, and is still refused listing, joining, and a `POST`
  to the leave path.
- **Co-invest:** Free and Professional investors get the 402; Institutional
  investors, admins and partners get 200; a founder gets 403.
- **Create:** a bad status is a 400 that writes nothing, and its `allowed`
  list equals the baseline schema's CHECK. An allowed status, and no status
  at all, still create a deal.

D370's syndication test now expects the 402 for its free-tier LP.
