## D9169 — Preflights and requests with no credential skip the role-schema bootstrap; every /api response carries Server-Timing (#9169)

- **Status:** built by S26 on #9169, 2026-11-27.
- **Measures for:** #8755 (magic-link start over its 5 s budget). The `Server-Timing` phases here are the measurement #8755 asks for.

### The problem

Production answered unauthenticated 401s, 404s and CORS preflights in 4 to 6.5 s (`/api/account/invitations` 401 in 0.70, 3.94 and 5.03 s; `OPTIONS /api/auth/me` 204 in 4.57 s). The Worker entry (`src/index.ts`) ran the role-schema bootstrap (`ensureInvestorSchema`, `ensureAdvisorSchema`, `ensureExploringSchema`: `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE users`, the users-table role rebuild and `UPDATE users` promotions) before Hono for every `/api/*` request except a short list of anonymous GETs. That included every non-GET method (OPTIONS too) and every request with no credential. None of those requests can reach a role-dependent read. Nothing showed where the time went.

### What was decided

1. **Only a request that carries a credential pays the bootstrap.** `carriesCredential` in `src/index.ts` is checked after `requiresBlockingRoleSchemaBootstrap`. OPTIONS never carries one. Otherwise the test is wide on purpose, so every request that could be signed in bootstraps exactly as before:
   - any `Authorization` header, valid or not;
   - the session cookie under the name `getCurrentUser` reads (`authCookieName(env)`: `studioos_auth` on HQ, `studioos_auth_<code>` on a branch);
   - a `Sec-WebSocket-Protocol` header (`bearer.<jwt>`, `routes/realtime.ts`);
   - a `token` query parameter (the WebSocket and signed-link fallbacks).

   A malformed `BRANCH_CODE`, where the cookie name cannot be known, counts as credentialed. The 503 `investor_schema_not_ready` refusal and the per-binding readiness latches are unchanged. Sign-up paths that write the `exploring` role already run their own `ensureExploringSchema` (`routes/auth.ts`, `auth_google.ts`, `auth_apple.ts`).
2. **`Server-Timing` on every `/api/*` response that passes the entry's secret checks** (`src/util/serverTiming.ts`): `bootstrap;dur=…, ratelimit;dur=…, auth;dur=…` in ms, in that order. A phase that did not run reads `dur=0;desc="skipped"`. The three phases are:
   - `bootstrap`: the entry's role-schema bootstrap;
   - `ratelimit`: the KV buckets in `middleware/rateLimit.ts`, at each exit;
   - `auth`: each resolution of the caller in `getCurrentUser`, summed. A memoised wait is not counted again.

   The header holds phase names and numbers only: never a path, bucket, user id or token. The timings are kept in a WeakMap keyed by the request object, which is also Hono's `c.req.raw`. A WebSocket upgrade (101) is returned untouched.

Authorization is unchanged. No route gate, status or body changes, and the limiter's buckets and fail-open/fail-closed policy are as before. `unauth_fast_path_9169.test.ts` drives the real entry with a fresh D1 binding per request (a cold isolate) and checks:
- OPTIONS (204), an anonymous protected GET (401) and an anonymous unknown path (404) run no DDL and no `UPDATE users`;
- a Bearer or session-cookie request still runs the bootstrap.

### Not done here

The remaining request-time DDL (the three bootstraps themselves) should move into migrations under `cloudflare-worker/sql/migrations/` through the schema-change skill. That is a follow-up. Until then, the first credentialed request on a cold isolate still pays it, and `Server-Timing`'s `bootstrap` phase will show how much.
