- The draft put the venture's display name, here a person's name, in line 1, and the dialog said "Privacy check passed. No names, emails or interview quotes are in the prompt." That sentence is `PRIVACY_OK` and `PRIVACY_OK_SUB` in `lovableModel.js`; it certifies more than the check does.

A display name that is not a recorded legal name passes, so a founder-named venture gets through.

### What was built (2026-11-27)

Every sentence below was checked against the code it describes.

**Worker** (`services/lovable/prompt.ts`, `launch.ts`; no new route, mount or column):

- `privacyFindings()` returns each finding as `{ kind, words, lines }`: the 1-based lines it was found on (every occurrence for the regex shapes and interviewee names; the first for a recorded legal name, as `lintForSend` reports it), never the words. `checkLine()` says it: "This prompt contains an interviewee’s name, in line 13. Remove it to continue." Launch's `pii_found` refusal, its "Nothing was opened." and the support-session refusal are unchanged.
- `memberNameAdvisories()`: the account name (`users.name`) and display name of each member of this venture (accounts whose `founder_id` is the venture's, and `project_members` accepted and not removed), matched as whole words, 3+ characters, any case. It returns `{ kind: 'member_name', lines }` in the check's `advisories`, with `advisory_line`; `ok` reads findings only, so the launch never refuses for it.
- The draft takes `{ alias }` (2 to 60 letters, digits, spaces and `. , ' & -`, one line; otherwise `400 invalid_alias`), builds the template with it wherever the template names the venture, and returns `venture_name`, `venture_label`, `venture_lines` and `alias`. Nothing is written: the venture is not renamed and the alias is not saved (Q2, A). It also returns `support_session` from the token's `impersonated_by`, the same read the launch refuses on. Every check carries `checked_at`.
