## D8253 — Grow Markets: customers and sign-ups by country (#8253)

- **Status:** built 2026-11-22. Follows D6120, whose evidence line read "Customers and prospects carry no country yet".
- **Migration:** `202611222045_8253_contacts_country.sql` — a nullable `contacts.country` (ISO 3166-1 alpha-2) and an index on `(project_id, audience, country)`. Additive; the Worker one version back ignores the column.

### What this decides

1. **Where it is stored.** On the `contacts` row: the venture's prospects and customers are the `audience = 'customer'` rows (D4492). A row nobody tagged has `country` NULL and is in no country.
2. **Who sets it.** The Grow prospect form (`POST /api/grow/prospects`, field `country`) and `PATCH /api/grow/prospects/:uid/country` (an empty value clears it). Both need write access to the venture; a code Research › Geographies does not list is refused with 400. The generic contacts `PUT` and the CSV import do not take a country: neither form asks for one, and a country is never inferred from an address or an IP.
3. **What is counted.** `growMarketCustomers.ts` counts tagged `audience = 'customer'` rows of the venture, per country. A market's count is the rows tagged with its attached country. The Markets list rows and the record's `parts.market` carry `customers: { state, tagged, reason }`: `ok` with the count; `not_recorded` with `tagged: null` when no row is tagged or no country is attached; `unreadable` with `tagged: null` when the read failed. Never a 0.
4. **Where it shows.** The record's Demand evidence reads "Prospects and customers tagged Portugal: 12", Not recorded with its reason, or Unavailable.
5. **Sign-ups.** `waitlist_signups` carries no country and no form there asks for one, so it is not counted; a sign-up that becomes a contact is counted once tagged.

### Rollback

Revert the commit. The column and index stay (migrations are never undone); older code ignores them. Tags already set are kept.
