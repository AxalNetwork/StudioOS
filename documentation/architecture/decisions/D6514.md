## D6514 — Bound verbose SARIF separately from compact scan state (#6514)

The two reported JavaScript CodeQL analyses finish successfully, then fail
in `Save opaque finding fingerprints`. The scanner snapshot reads verbose
SARIF through the same 8 MiB reader used for compact event and state JSON.
A valid SARIF document one byte beyond that budget reproduces the failure.
The hosted SARIF itself is not retained after the failed snapshot, and the
code-scanning API refuses this environment's integration token, so its exact
size and the hosted failure's final resolution remain unverified.

Give only local SARIF snapshot inputs a 64 MiB ceiling. Event payloads,
previous-state artifacts and GitHub responses retain their existing 8 MiB
budgets. Read from one opened descriptor, stop at the ceiling plus one byte,
and close it on every outcome. A size failure has a fixed diagnostic; parser
messages, paths and excerpts never enter that diagnostic. Invalid JSON,
missing finding identities and oversized inputs still fail without writing
a partial snapshot. Finding identities, suppressions, scan admission and
incident/baseline policy are unchanged.

The regression exercises the actual CLI: a small and an over-8-MiB report
produce identical opaque findings, exactly 64 MiB is accepted, and one byte
more is refused. Existing event-bound and descriptor-race tests remain in
force. Deliberate mutations restore the old SARIF limit, widen the event
limit, remove the read ceiling and disclose parser messages; each must fail.

Keep #6514 open until a fresh hosted main scan verifies fingerprint saving
and the subsequent findings job. Do not rerun an unchanged failing head,
suppress findings, widen scanner scope exceptions or dispatch scan load.
