## D1602 — Opt-in data-room sources for pitch decks (#3881)

**S33 · 2026-11-01.** Migration 753. Builds on D896 sources, D1506 untrusted-input framing and the existing D1 job queue. No new infrastructure binding, external extraction provider or production data operation.

### Owner decision

The owner confirmed: **“Keep Sourced until a verified stamp exists.”** File names, source tags, uploaded signatures and model output never imply counsel approval. All three slots carry origin `file`, Source **Document**, grade **Sourced**. A separate verified-approval feature may upgrade them later; this task introduces no stamp.

### Write and extract

`PUT /api/data-room/:projectUid/files/:uid/deck-source` accepts `{enabled:boolean,confirm_quote?:string}`. The verified room owner alone writes; an accepted cofounder gets `403 owner_only`, an admin `403 support_read_required`, everyone else `404`. It uses the existing authenticated, frozen-account and active-company gates and writes a count-only cycle activity. The room read advertises `deck_sources_available` only after the migration is readable; the file sheet hides the control otherwise.

Enabling atomically tags, clears prior values and enqueues `dataroom_extract`. Repeated saves while queued/done/no_values are idempotent. Failed or abandoned attempts can be explicitly retried. PDF/DOCX first return `402 quote_required`; that read never opens the R2 object. The confirmation binds owner, current object key, content revision, model and maximum hold. Before each typed run, `quoteRun` rechecks the price against the approved ceiling. `run` owns the founder's reservation, safety check and receipt. The cost confirmation also authorizes replacement versions at that ceiling; a higher price fails without running and needs a fresh confirmation. CSV/XLSX use code only and cost no model run.

Only tagged, current, queued files are opened, under their own project's R2 prefix and after checking that the approving owner still owns the venture. One conditional claim prevents duplicate delivery from charging twice. Jobs contain only project ID, file UID and an opaque attempt token; no content, figures or names. Failed extraction records `unreadable` without logging document text, output or raw conversion errors. A started attempt older than five minutes, or a never-started queue entry older than thirty minutes, is displayed as unreadable, stopping the file sheet’s polling and allowing an explicit retry. A late delivery persists unreadable and refuses to buy a run after that deadline. Runtime failures persist unreadable; a killed worker is represented by this read-only timeout until retried or delivered again. No GET writes to the store.

### Reader limits and evidence

- At most 20 MiB per object. CSV is bounded RFC4180 text; XLSX reads bounded local ZIP/XML numeric cells and fixed English row labels, including numeric formula caches, without evaluating formulas, relationships or URLs. Competing values for the same slot are omitted. A fixed recognized year header chooses its latest column; dates in notes do not change that choice; several numeric columns without a year header are ambiguous and omitted.
- PDF: up to ten pages, split with the existing `pdf-lib` dependency and converted through Workers AI's binding per actual page. DOCX: recorded page breaks, or an explicit one-page document property, only. Unknown Word pagination produces no values. Office inflate and entry limits prevent unbounded expansion.
- Typed inputs have a combined 16,000-character ceiling, `untrustedBlock('data_room_document', ...)` and `withUntrustedRule`. Input cuts discard partial rows rather than turning a clipped number into a different value. Output must be a JSON array of exact `{slot,value,unit,page}` objects. Code accepts only finite nonnegative supported values, integral counts and an actual page containing the same labelled number. Uncited, ambiguous, wrong-unit, unexpected-field and unrecorded-link output is discarded. A page or value is never inferred.
- `as_of` is the current R2 object's actual upload day, including when an older version is restored. Renaming a file cannot change this date. Missing object/date or unsupported/corrupt content is unreadable; no supported extraction is `no_values`, with null / not-recorded source slots, never invented zero.

### Versioning, reads and retention

`deck_source_revision` is a monotonically increasing **content revision**, separate from the archive-slot numbering used by the existing make-current swap. Both replacement and make-current atomically increment it, clear derived rows, reset the attempt token and enqueue the new tagged revision. Disable and delete explicitly remove derived rows in the same batch, even with foreign keys disabled. Old in-flight jobs cannot repopulate a withdrawn or replaced source.

`dataroom_deck_values` holds only the three numeric slots, unit, page, upload day and provenance. It cascades on project/file deletion. No additional R2 object or document-text store is created. The retention-inventory owner was notified on #3759 to include this table in A15; that inventory does not exist on this base and is not invented here. Saved decks keep their recorded binding until refreshed, matching existing source behavior.

The `dataroom` adapter reads only current tagged `done` revisions, without opening files or running AI. Slots are `dataroom.revenue_plan` (USD), `dataroom.headcount_plan` (count), and `dataroom.contract_count` (count), under Raise › Data room. If multiple tagged files fill a slot, the newest upload day wins, then file UID for a deterministic tie. Citations are `dataroom:<uid>:v<content revision>:p<page>`; CSV uses `p0` to mean unpaged and stores a null page; XLSX uses its numeric sheet ordinal. Figures are bound by code. Generation prompts receive only “Recorded; placed by code” for these slots, including in the every-figure appendix.

`value REAL` in migration 753 follows the issue's source-metric schema: it is a forecast/document figure in USD, **not a financial ledger or settlement amount**. Counts remain integral by the extraction validator.
