## D4836 — Offers programme logos and safe failed-write recovery (#4836)

**Status:** independent implementation complete; the remaining Offers overlay/accessibility migration is blocked on #4844's shared pattern. This PR is part of #4836 and does not close that tracker.

### Programme persistence and logo retry

Offers Product testing enables the existing shared `ProgrammeForm` logo control and existing partner upload/remove endpoints. There is no new API, schema, permission or storage policy. Programme create/edit completes once before the separate logo operation. A failed logo write retains the original saved programme UID, title and selected File/removal intent in a named result outside the list-read boundary. Retry performs only that logo operation, even if refreshing the programme list failed. It cannot create/edit another programme or follow the currently open editor. A per-UID in-flight guard prevents overlapping retries. A late initial logo response cannot close another editor.

The shared logo field now has a real label, associated help and validation error, and `aria-invalid`. Partial success moves focus to the retained logo result; a successful logo retry moves focus to the saved programme after refresh, with a stable New programme/region fallback. This avoids losing focus when the list refresh replaces a Sheet's trigger. Existing Sheet/SlideOver focus containment, Escape and inert-background behaviour are reused.

The old “logo cannot be uploaded here” copy is removed. The zone still states that applicant emails are private and delivery/open figures are not recorded.

### Safe failed-write notes

`useGuardedWrite` maps validation, authentication, permission, conflict, rate, network and server failures to fixed user-facing copy. Only a bounded 400/422 response naming a valid field may supply its Worker validation sentence. An arbitrary exception/server body is never treated as a useful field error. Existing retry closures, retained form input and saved-but-refresh-failed handling remain in place.

### Verification

Mounted tests cover partial success plus list failure, original UID/File retry, removal-only retry, overlapping retry, another editor opening during retry, a late first upload, field associations and focus recovery. The first-use suite exercises seven validation/session/permission/conflict/network/server failure variants across Visibility, Proof and Audience fit, with retained input and retry. Its dynamic mutation checks include raw-error leakage and treating a server response as validation. Additional temporary mutations break logo enablement, operation/UID/File binding, the busy guard, focus recovery, late-close protection and error visibility; each must fail the real mounted journeys.

Synthetic local Chromium journeys pass at 1440, 1280, 834 and 390px, plus 390px dark, with reduced motion: keyboard opening/containment/Escape/return, inert background, label/help/error associations, partial-save focus, logo-only retry, saved-record focus and no page overflow. They use synthetic records and API stubs; no programme is created in production and no mail is sent. This scoped verification is not an accessibility compliance claim for the entire Offers family.
