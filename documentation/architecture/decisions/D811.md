## D811 — Signed Axal VC Mail link, consented audiences and atomic feedback

Issue #2257, part of D809. Stacked on D810 PR #2273 (migration 515,
newsletter consent/suppression stores and signed preferences tokens). D812's
programme store is already on main.

Mail authenticates independently of sessions and admin roles with a shared
Worker secret, `MAIL_LINK_SECRET`, set by the owner in both Workers. Nothing is
exposed until it is set: every route answers 404 first. HMAC-SHA256 signs the
method, exact path **including query**, Unix-second timestamp and hex SHA256 of
the UTF-8 body, separated by newlines. The timestamp has a five-minute window in
either direction. KV nonces expire in ten minutes; an atomic D1 unique claim
closes the race that KV's eventually consistent get/put alone cannot close.
Replay stores fail closed. The router mounts before browser CORS/session middleware and bypasses unrelated role-schema bootstrap,
with its own fail-closed 120/minute/IP rate bucket and a 256 KiB body bound.

Newsletter topics, members by role and Partner Letter use confirmed D810
subscribers with explicit consent and an enabled topic. Partner Letter also
checks current investor/LP role. Registration alone does not consent to event
marketing: event guests need the confirmed events topic. Suppressions, pending
subscriptions, disabled topics, inactive accounts and stale account-email links
are excluded both in counts and pages. Recipient pages contain at most 500 rows,
with an audience-bound subscriber-ID keyset cursor. Merge fields are recorded
member name and profile organization, or null. D810 signs preferences and
one-click topic-unsubscribe URLs. No address is stored in read or feedback logs.

Migration 517 is the next free after 516, allocated under #2257's explicit
permission. It adds required `mail_link_reads`, ten-minute nonce claims and
feedback receipts. Receipt IDs digest (type, normalized email, message ID);
missing message ID is an empty value. A batch inserts only unseen receipts,
then changes preferences/suppressions only for that batch's random claim marker.
Receipts, topic opt-outs, unsubscribe-all, legacy insights mirror, suppression
and address-free `service:axal-mail` activity rows commit together. Duplicate
reports cannot undo a later resubscription; within one batch the first tuple
wins even if later duplicates disagree about the audience. Validation precedes any batch write;
one failure rolls everything back. Up to 500 events require only six statements.

### Part waiting on the owner

Picked D812 testers can consent to one programme without owning a D810
newsletter subscriber record. Creating newsletter consent on an audience read
would invent consent; reusing a token without its record would produce broken
unsubscribe links. The issue asks S1 to choose A (recommended: programme-scoped
signed preferences/unsubscribe) or B (require a separate confirmed testing_calls
opt-in). No choice has been assumed. Testers are explicitly unavailable (503),
not silently zero or exported without working unsubscribe links. This PR is
**Part of #2257**, not its closure, until that contract is decided and built.

### Verification

Real signed Hono requests against canonical baseline tables plus migrations 515
and 517 test signature binding, replay including concurrent KV lag, unset-secret
404s, rate limiting, live suppression-aware counts, consent/role/event gates,
500-row cursor paging, working D810 URLs, topic/all opt-outs, idempotency across
resubscription and concurrent feedback, 500-event batches, rollback, privacy,
unreadable stores and body bounds. New assertions are mutation-checked with the
restored scenarios run before and after each mutation. Full drift/build results
are recorded in the PR.
