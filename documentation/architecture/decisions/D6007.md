## D6007 — Ideal customer profile V2: the primary ICP, firmographics and disqualifiers, and Compare segments (#6007)

**Decision date:** 2026-11-22. **Builds to:** `design/incoming/Validate v2 Discovery and ICP Page.dc.html`, boards V21 (ICP desktop), V23 (segment record) and V24 (Compare segments), as answered by the owner on D5995 part 2 (option A on every question). **Builds on:** D690 (the segment's five steps), D6003 (Archive and complete edits), D5129 (data states).

### What is built

- **Primary ICP.** `customer_segments.is_primary`, with a partial unique index on `(project_id) WHERE is_primary = 1`, so the store itself holds "exactly one per venture". `setPrimarySegment` clears the old primary and sets the new one in one batch and logs `segment_primary_set` (naming the segment it replaced) or `segment_primary_cleared` on the segment's activity. Setting the segment that already holds it writes and logs nothing. Archiving a segment clears it. Routes: `PUT /api/cycles/validate/segments/:id/primary` (`{ primary: true | false }`, writers), and on the segment record **Set as primary ICP** / **Clear primary ICP** with a confirm. The ICP list gains the **Primary ICP** column (★ Primary, otherwise a dash, never Not recorded) and the record a ★ Primary ICP pill.
- **Firmographics and disqualifiers.** `firmographics_json` (`[{ label, value }]`) and `disqualifiers_json` (`["…"]`) on the segment, NULL until written (migration `202611220319_6007_segment_primary_profile.sql`). Each holds at most 12 entries. They are stored on the segment and never derived from interviews; interview findings stay in "From interviews". The record's Edit form takes them one per line (`Label: value` for a firmographic), and an emptied box clears the list. The record draws them in a side section of their own, with the empty sentence "No firmographics or disqualifiers recorded on this segment."
- **Compare segments is a mode, not a route (option A).** `/validate/ideal-customer-profile?compare=1,2,3` owns the module page through `def.homes`, and the page's search params are now handed to a home. Without the parameter the page draws as before. It reads `GET /api/cycles/validate/segments/compare?ids=…` (readers of the module, `canReadBoard`): two to four active segments in the order asked. For each it returns the five steps, the value source, held interviews by fit, evidence (stopping at Pattern, as `segmentsOf` does), the top three pain themes, firmographics and disqualifiers. An unwritten value is `null`, drawn as Not recorded; Urgency reads Not set, and a value promised with no source reads Needs a source. Archived or foreign ids are returned as `missing`, and the page says one is not shown. Columns are removed down to two and added up to four from the venture's list. With fewer than two named, the page opens on three, the primary first. A writer sets the primary from a column header. **Compare segments** is a tool link on the module and an action on the segment record, which opens with that segment chosen.

### Not built here

- **A source on every step** (no issue yet, per D5995), segment **Archive** (D6003) and **the list of interviews in no segment** (D6002) belong to their own issues.
- **Readers elsewhere of the primary ICP.** Per the issue, they are a separate issue; nothing outside this module reads `is_primary` yet.

### Departures from the canvas

- V24 draws Compare with the app shell's crumb "Compare". The page keeps the module's own header and crumb, and the body's heading says Compare segments.
- On a phone, Compare is the same table, scrolling sideways with the row labels held. The canvas draws no phone board for V24.
- The canvas's Disqualifiers row sits last. The build also draws a Firmographics row above it, because the two are stored together and V23 draws them together.

### Rollback

Revert the PR. The migration only adds columns and an index, so the old code ignores them.
