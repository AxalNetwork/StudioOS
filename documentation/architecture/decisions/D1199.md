### 1. The routes

| Route | Who | What |
|---|---|---|
| `PUT /api/partner/testing/programmes/:uid/logo` | a partner, on their firm's programme | multipart `file`: a square PNG or SVG → `{ logo: { logo_key, content_type, size } }` |
| `DELETE /api/partner/testing/programmes/:uid/logo` | the same | `{ logo: { logo_key: null } }` |
| `PUT` and `DELETE /api/admin/testing/programmes/:uid/logo` | Super Admin, on HQ's own programmes | the same |
| `GET /api/testing/programmes/:uid/logo` | any signed-in reader who may see the programme | the image |

**Who may change a logo.** The owner only, through `ownProgramme`. Another firm's programme answers 404, as a missing one does, and HQ's route reaches only HQ's programmes.

**When.** A logo changes only while the programme can be edited (`draft`, or `rejected` and sent back), as every other field does. So an approved programme cannot change under HQ's review. Each change appends a `testing_events` row: `logo_set` or `logo_removed`.

### 2. What is accepted

**The bytes decide the type.** The type the browser declares is never read.
- **A PNG** is its eight-byte signature followed by an `IHDR` chunk.
- **An SVG** is UTF-8 text whose first element, after an optional BOM, XML declaration and comments, is `<svg`.

Anything else is 400 `not_an_image`: a GIF, a JPEG, HTML, or text that only claims to be an image.

**The other checks:**

| Check | Refusal |
|---|---|
| At most 256 KB (`LOGO_MAX_BYTES`) | 413 `file_too_large` |
| Not empty | 400 `empty_file` |
| Square: a PNG's IHDR width equals its height; an SVG's `viewBox`, else its `width` and `height`, is square. An SVG that gives neither is asked for a square viewBox. | 400 `not_square` |
| No script in an SVG (below) | 400 `unsafe_svg` |

**An unsafe SVG is refused, not cleaned.** These are refused wherever they sit in the file, even before the root element:
- `<script>`, `<foreignObject>`, `<iframe>`, `<embed>` or `<object>`;
- an event handler (`on…=`, after whitespace, a slash or a quote);
- a `javascript:` URL;
- an `href` or `xlink:href` that is not an in-document `#` reference (so no external image or `data:` document);
- a `<!DOCTYPE>` or `<!ENTITY>`.

**Any other SVG is stored as `routes/brand.ts`'s `sanitizeSvg` rebuilds it** (D198's allowlist), never as uploaded. An element off the allowlist, such as an editor's metadata, is not stored.

### 3. Storage and `logo_key`

- **The bucket** is the platform's private `FILES` bucket.
- **The key** is `testing-logos/<programme uid>/<uuid>.<png|svg>`, stored with its content type.
- **The Worker alone sets `logo_key`.** A create or edit body that carries one is refused (400). Before this change `programmeInput` accepted any string up to 500 characters.
- **Replacing** a logo deletes the old object, best effort. **Removing** one clears the key and deletes the object. A refused upload stores nothing.
- **Without `FILES`** (a dev environment), an upload or a read answers 503 `storage_unavailable`.

### 4. Serving

`GET /api/testing/programmes/:uid/logo`:

- **Who may read it:**
  - the programme's partner firm and Super Admin, in any status;
  - any other signed-in member once the programme is one members can see (`open`, `testing`, `closed`).
  - A draft's logo is 404 to a stranger.
- **Headers:**
  - `Content-Type`: `image/png` or `image/svg+xml`, from the stored object;
  - `X-Content-Type-Options: nosniff`;
  - `Cache-Control: private, max-age=300`;
  - for an SVG opened on its own, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`.
- **Never another file:** only the `testing-logos/` prefix is read, whatever a row holds.
- **No logo is a 404,** which the page draws as the initial letter.
- **Sign-in:** the session cookie works, so an `<img>` loads it.

**Logs** hold outcomes only, never a key, uid or file name.

### 5. The client (`frontend/src/lib/api/productTesting.js`)

No page draws these yet: TST7's field and the squares belong to the page parts.

### 7. Tests

**`cloudflare-worker/test/product_testing_logo_d1199.test.ts`** (10) runs on the SQLite D1 harness with migration 516 and an in-memory R2. It covers:
- a square PNG stored under the Worker's key and served with nosniff and a cache header;
- a declared image that is not one, a PNG header without its signature, a GIF, a JPEG and HTML refused;
- seven unsafe SVGs refused;
- a clean SVG stored as the sanitiser's rebuild, without its off-allowlist element;
- not square, too big, empty and an SVG with no size refused;
- another firm's programme, and HQ's from a partner's route and the reverse, as 404;
- `logo_key` in a create or an edit body refused;
- serving: a missing logo, a draft to a stranger, and a key outside the prefix as 404;
- replace deleting the old object, remove clearing the key, and a submitted programme refusing a change;
- the checks alone;
- the source: the prefix guard, and no value in a log line.
