## D899 — Eadwyn's card tools: words only, figures from records, every press priced first (#2678)

- **Status:** built by S25, 2026-10-25 (#2678, part 5 of #2434). Builds on D896's sources (#2675), D897's figure rules (#2677) and D898's editor and slide model (#2676).
- **Canvas:** PD7, PD9d and PD28 of the owner's "Pitch Deck Studio" (`design/incoming/`), with PD25's tokens dialog.
- **Migration:** none. Each press leaves one `ai_rail_proposals` row (D780).
- **Why:** #2434 wants Eadwyn to help with a card's words without ever writing a figure. Before this part, the editor had no AI on a card (`PitchEditor.jsx` said "the card AI bar (PD7) … waits for its own store").

### 1. One route, eight rail options

`routes/deck_assist.ts` is mounted after `deck_new.ts` and before `decks.ts`. It has two routes:

- `POST /api/decks/:id/cards/:card/assist/quote` returns `quoteRun`'s hold and runs nothing;
- `POST /api/decks/:id/cards/:card/assist` runs through `run()`.

`:id` is the version the editor opened, and `:card` is the card's place in it, from 0. The body carries `action`, then the `block` and `text` as the editor holds them (saved or not), and `tone`, `language`, `instruction`, `source_keys` or `heading` where the action takes them.

Each action is one founder option on "Founder · Raise · Pitch deck" (`ASSIST_OPTIONS`):

| Action | Option | Where it is pressed |
|---|---|---|
| rewrite, ask | `deck:rewrite` | PD7's bar (`CardAssistBar.jsx`); the connector headline (`ConnectorLightbox.jsx`) |
| headline | `deck:rewrite` | PD9d's lightbox |
| shorten, expand | `deck:shorten`, `deck:expand` | PD7's bar |
| tone, translate | `deck:tone`, `deck:translate` | PD7's bar, with a tone or a language from a fixed list |
| chart, table, timeline | `deck:chart`, `deck:table`, `deck:timeline` | the Add menu (`AddMenu.jsx`) |

Ask and the headline are rewrites with an instruction, so they share `deck:rewrite`.

The run's rail context is `railFor` with the option forced and the record `deck:<id>`. It is charged to the founder who pressed, and refused as every rail run is (`refuseRun`: 403 `assist_off`, 402 out of tokens, 422 guard). Gates use `projectOwned` with write access: another founder, an investor and an admin get 403.

### 2. No tool can write a number into a card

Each of these is a separate rule:

- **A bound figure is refused before anything runs.** This covers a metric tile, or any block with a binding, whether as the editor sends it or as the stored version holds it. It is refused as 422 `never_fill`, with "Figures come from your records. Update [module] to change this one.", and costs nothing.
- **An instruction that states a figure is refused.** This is D897's `figureRefusal`, giving 422 `figure_in_prompt` with the module that records the figure.
- **A wording may name only the figures the founder's text already had.** Every digit run and every currency or percent sign in the answer must already appear in the text (`wordingProblem`). A headline may name no number at all, not even a number word (D897's `numberIn`). If the answer fails, nothing is placed: 422 `figure_in_output` says the run was charged and returns the cost.
- **The chart, table and timeline tools choose sources, never values.** The model is sent keys and labels only (`chartMessage`). It answers with the keys to show. Code builds the block, keeping only the recorded keys it named, in its order, and makes each series a binding through `sanitizeBinding` (`chartBlock`). A title that names a number is dropped. If no key survives, the answer is 422 `no_figures_chosen` with the cost.
- **The connector card is code's.** PD9d makes metric tiles bound to the chosen sources, so it is free. A headline the founder types is refused on the page if it names a figure.

### 3. Every press shows its cost first

PD7's bar quotes each tool when a text block is selected, so each button carries "up to $…". The Add menu does the same for its three chart tools when they open.

A press opens a dialog with the quote, and only Run spends. The connector headline shows its cost next to its button, and the cost is read again as the chosen figures change.

A 402 opens PD25's tokens dialog: "Your records still fill every figure, at no cost". With AI assistance off on the page (`useAssistMode('raise')`, or a quote that answers `assist_off`), the bar and the chart tools are greyed under "AI assistance is off on this page. Your records still fill the figures."

### 4. A result is a proposal

Every run leaves one `ai_rail_proposals` row of kind `proposal`, with record `deck:<id>`. It writes no version, and an audit row `deck_card_assist_proposed` is logged against `raise.pitch-deck`.

The editor draws a text result as PD7 draws it: the before struck, the after on lavender. Accept decides the proposal (`railProposalsApi.decide`) and places the words on the block. A chart result is placed at the card's first free range of its size. Save writes the version as it writes every other change (D898). Discard places nothing.

### 5. PD28's rail row, and why FLUX.2 Klein 9B is not routed

The Add menu lists the page's four models: Llama 3.3 70B Fast, FLUX.2 Klein 9B, FLUX.1 Schnell and Gemma 4 26B. Their prices come from the member catalogue (`GET /api/public/ai/models`), never from the canvas.

**The page's rail matrix row stays `vision`.** Making it a `deck` kind would move D767's autofill off `rail_vision`, and `rail_matrix_d764` requires each `rail_<kind>` task to be a ROUTE key. The eight options are kind `write`, routed as `rail_write`.

**FLUX.2 Klein 9B is listed and not routed.** The router can send FLUX.2 (D761), but no card tool in this part makes an image. It is also a partner model, offered only behind `AI_PARTNER_MODELS`, so a member's catalogue may not carry it. The row says "Not routed on this page yet", and it reads "Not offered on your plan" when the catalogue leaves it out. Routing it belongs to images (#2682), when a card tool makes one.
