  `integrations` row like every other provider's.
- **Code:**

    authorize, token and revoke requests.
  - `cloudflare-worker/src/integrations/providers/quickbooks.ts`: the provider

  - `cloudflare-worker/src/routes/quickbooks.ts`: the founder's read and sync.
  - The registry, keys, scope, connector page and HQ label entries every

- **Client:** `frontend/src/lib/api/quickbooks.js`.
- **Tests:** `cloudflare-worker/test/quickbooks_connect_5834.test.ts`, over a

### 1. Off until the owner turns it on

The provider is ready only when `QUICKBOOKS_APP_APPROVED=1` and the Intuit
app's client id and secret are set (`QUICKBOOKS_CLIENT_ID` and
`QUICKBOOKS_CLIENT_SECRET`, or HQ › Integration keys). The callback checks the
flag again, so withdrawing approval mid-sign-in exchanges no code. The
console lists the exact callback,
`<OAUTH_CALLBACK_BASE_URL>/api/integrations/oauth/quickbooks/callback`, for
the owner to register with Intuit.

### 2. Sandbox and production are the deployment's, not the member's

Intuit's development and production keys belong to separate apps. The
deployment's `QUICKBOOKS_ENVIRONMENT` picks the API host: `production` reads
production, and any other value, unset included, reads the sandbox. The value
is stored on the connection (`config_json.environment`, D5834 §2), so a
connection keeps the host it was granted on. A request never names an
environment.

### 3. What a connection binds, and where each comes from

| Bound | Source | Never from |
|---|---|---|
| The realm (`external_account_id`) | Intuit's `realmId` on the callback, digits only | anything the member typed |
| The venture (`config_json.project_id`) | `project_id` at the start, carried in the signed state as `quickbooks_project_id` | the callback's query |
| The environment | the deployment (§2) | the request |

The member must be able to write to the venture (`canAccessProject` with
`write`). The callback is refused, with nothing exchanged and nothing saved,
in these cases:

| Case | Refusal |
|---|---|
| No venture was chosen | `quickbooks_venture_required` |
| The member cannot edit the venture | `quickbooks_venture_refused` |
| The realm is missing or not numeric | `quickbooks_realm_missing` |

The realm is trusted from the callback because Intuit's code is good for the
realm the member chose and no other. A realm id that does not match the grant
reads nothing: Intuit answers 403, which the sync reports as
`quickbooks_scope_denied`.

Intuit's token answer names no scope, so the connection records the one scope
it asked for, `com.intuit.quickbooks.accounting`. The client id and secret
travel only in an HTTP Basic header.

### 4. Rotation under the refresh lease

An access token lasts about an hour. Intuit rotates the refresh token, and the
spent one stops working. `quickbooksAccessToken` works like this:

- A token with more than a minute left is answered from the stored
  credentials, with no call and no lease.
- An expired token is refreshed behind `acquireRefreshLease` (#1903). Inside
  the lease, the credentials are read again first. A token another caller
  refreshed in the meantime is reused, and no second refresh is sent.
- A caller that cannot get the lease is answered `quickbooks_refresh_busy`
  and retries. It never refreshes with a token that may already be spent.
- The rotated refresh token, and its expiry
  (`x_refresh_token_expires_in`), replace the old ones.
- A refused refresh is `quickbooks_grant_revoked`. Its code alone goes to
  `last_error`, and the member is asked to connect again.

### 5. Revoke and disconnect

Disconnecting through `/api/integrations/:uid` (the existing machinery)
first revokes the refresh token at Intuit, which ends the whole grant.

- If Intuit answers 400, it no longer knows the token (already revoked or
  expired). That counts as revoked.
- Any other failure answers 503 `quickbooks_revocation_failed` and keeps the
  connection, so the member can try again rather than lose sight of a live
  grant.

Statement revisions and pins survive the disconnect (D5834 §3).

### 6. The founder's routes

Both routes require sign-in, and the connection must be the caller's own.

| Route | Answers |
|---|---|
| `GET /api/quickbooks/connection` | The caller's QuickBooks connection: status, whether a realm is bound, the venture, the environment, the last complete sync and the last error code. The realm id itself stays on the server. |
| `POST /api/quickbooks/connection/:id/sync` | Part 1's `syncQuickBooks` for `{ project_id, statements, basis }`. A token failure keeps its own code in the `incomplete` answer. |

Every code a member can meet has a sentence in `QUICKBOOKS_SENTENCES`.

### 7. What stays with the owner (D5832 §5)

- Register the Intuit app, with the callback in §1, in each environment.
- Set the keys, `QUICKBOOKS_ENVIRONMENT` and `QUICKBOOKS_APP_APPROVED=1`.
- Complete Intuit's app assessment before production.
- Name a consented sandbox or test realm, so the values can be checked
  against a live report. Until then, the tests run against a fake Intuit only.
