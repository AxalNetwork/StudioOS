## D7818 — Owner-only Research Project subject notes (#7818)

#5157 keeps the Research Project object. This adds one table beside its existing subjects table and a separate self-mounting router; none of #5157's files or study routes are changed. The handover is recorded on #5157.

A note belongs to the subject ID, for either company or fund, and cascades when that subject is removed. It never belongs to a study alternative, a fund dossier or a partnership prospect. There is no synchronization with those stores. The notes route reads no directory and is the only Worker reader of the note table. Every field is owner-only and absent from study/report/reviewer reads.

GET `/api/research/projects/:uid/subject-notes` returns notes keyed first by company/fund, then directory UID. PUT `/:uid/subject-notes/:kind/:directoryUid` saves one subject, with required expected_revision (0 for a new note). Omitted fields retain their saved value; null or blank clears optional text. Each successful save increments revision. The SQL tests revision and current project ownership/archive state again. A stale snapshot changes neither note nor receipt. D1 batch commits the note and its text-free activity receipt together. Receipt metadata contains only project UID, subject kind/UID and resulting revision; project_id on activity_logs is not used because it refers to a venture project.

Rationale: 4,000 Unicode code points; private_note: 10,000; next_action: 1,000. Status is route-validated as considering, shortlisted or set_aside. None uses “review”. The database checks only status length (1–40), allowing #7809 to rename route values without a schema change. due_day is a nullable strict YYYY-MM-DD calendar date, not a timestamp. Invalid and overflow dates are refused. Reads of another member's project are 404, archived writes 409, support-session writes 403. Missing authentication is 401 through the Worker's auth handler.

The router owns only `/:uid/subject-notes…`, registers no static first segment and declares no before ordering. No study router exists on the starting main revision; coexistence tests mount representative static `/with-study` and `/:uid/study` handlers after it. These are routing probes, not a claim to have implemented study endpoints. The cascade test uses a synthetic independent study-alternative reference because those study tables are not on that revision.

Rollback reverts code; the additive note table can remain. No live private text was read or written.

Mutation checks: tests reject deliberate changes accepting stale revisions and allowing support-session writes. Each mutant was restored byte-for-byte; the clean tests are rerun before push. Full-suite readiness is deferred while #5719 remains open; the owner permits draft PRs only.
