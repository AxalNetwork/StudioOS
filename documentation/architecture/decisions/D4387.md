## D4387 — An agent's sponsor can be changed, and a cap pause ends when the month turns (#4387)

- **Status:** #3742 E8, owner decided 2026-11-04. Closes #4387.
- **Migration:** `cloudflare-worker/sql/migrations/202611040924_team_agent_sponsor_changes.sql`.

### 1. Why

The Team canvas already drew TM9b's "Choose a new sponsor" and the cap pill's "Resumes [1 Nov]", but neither worked. No route changed a sponsor, so an agent paused `sponsor_left` could only be removed and added again. No pause ended by itself, so an agent paused at its monthly cap stayed paused after the month turned.

### 2. Changing the sponsor

The sponsor is the member whose AI tokens pay the agent's runs (owner Q2 A).

- **`PUT /api/teams/agents/:uid/sponsor`** takes `{ sponsor_uid, reason, drop_tools? }` and answers `{ agent }`. It sits beside `PATCH /agents/:uid` and uses PATCH's gate order: signed in, the agent exists, the caller can read its team, the caller manages it (`canManage`), the agent is not removed.
- **`GET /api/teams/agents/:uid/sponsors`** (same gates) lists the team's members (`teamMembers`, the seats `onTeam` counts, at most 100). Each member comes with `can_sponsor` and, when they cannot, the refusal's code and words. The dialog offers only members who can sponsor. The Team page's people read carries numeric user ids and no uids, so it could not name a sponsor. This read also lets the dialog say why a member cannot sponsor before anyone presses Save.
- **The reason** is trimmed and must be 10 to 500 characters (`reason_required`, as in `modelPolicy.ts`).
- **The new sponsor** must pass `sponsorRefusal` (`services/agents/sponsor.ts`). They must be on the team, be one of its editors, have a paid Founder plan (owner Q4 B, `planOk`) and have AI tokens left.
  - **Editors only.** A member who is not an editor is refused. Otherwise the next run would pause the agent `sponsor_left` at once (`agentRun.ts` checks the sponsor with `canManage`).
  - **"Has tokens"** is `defaultTokensLeft`, the read that agent duties already use to skip a sponsor with no tokens (`budgetAllows`). It counts the plan's allowance and the paid balance, since a run is paid from both. `ledgerBalance` would count only the purchased packs.
- **Tools.** An agent's read tools are grants on its sponsor's own connected MCP servers (`checkGrants` binds the server to its owner). No other member can read through them, so a new sponsor can never keep them. An agent with tools is refused `sponsor_tools` (with `tools`, the count) until the request sends `drop_tools: true`. The tools are then dropped (`tool_grants_json = '[]'`), and the event records how many. No route grants an existing agent new tools yet, so the new sponsor's own tools are not added here.
- **On success** `sponsor_user_id` is set. The UPDATE runs only while the sponsor is still the one the request read, so two concurrent changes cannot both succeed (409 `sponsor_changed_meanwhile`).
  - A `sponsor_changed` event is logged with the caller as its actor and `{ from: { uid, name }, to: { uid, name }, reason, tools_dropped? }`. No email and no numeric id.
  - An agent paused `sponsor_left` becomes active in the same UPDATE, and a `resumed` event `{ reason: 'sponsor_changed' }` is logged. Every other pause stays as it was.
  - The new sponsor gets an in-app notice that their tokens now pay the agent's runs. It is best effort: a failed notice does not undo the change.
- **`sponsor_lost_access`'s words** now end "An editor can choose a new sponsor." instead of "can add it again".

| Code | Status | Words |
|---|---|---|
| `reason_required` | 400 | Say why the sponsor changes, in 10 to 500 characters. It is kept in the agent's activity. |
| `sponsor_not_found` | 422 | There is no such member. |
| `same_sponsor` | 409 | That person already sponsors this agent. |
| `sponsor_not_member` | 422 | That person is not on this team. A sponsor must be a member of it. |
| `sponsor_cannot_manage` | 422 | That person cannot manage this team's agents. A sponsor must be one of its editors. |
| `sponsor_plan_required` | 422 | That person is not on a paid Founder plan. A sponsor pays for the agent's runs, so they need one. |
| `sponsor_no_tokens` | 422 | That person has no AI tokens left. A sponsor pays for the agent's runs from their tokens. |
| `sponsor_balance_unreadable` | 503 | That person's AI tokens could not be read, so the sponsor was not changed. Try again shortly. |
| `sponsor_tools` | 422 | This agent reads through N tools on its current sponsor's own connected servers, which a new sponsor cannot use. Choose to drop them to change the sponsor. |
| `sponsor_changed_meanwhile` | 409 | Someone changed this agent a moment ago. Reload it and try again. |

The caller's own gates are PATCH's: 404 `not_found`, 403 `not_member`, 403 `not_manager`, 409 `removed`, 400 `invalid_body`. A balance that cannot be read is always a refusal. It never counts as 0 or as enough.

### 3. The cap resume

- **What resumes.** An agent the run paused because it reached its monthly cap (`status = 'paused'`, `paused_reason = 'cap'`) resumes once the UTC month of its pause is over. The pause instant is its latest `paused` event, or its row's `updated_at` when there is no event. The agent becomes active, and a `resumed` event `{ reason: 'cap_reset' }` is logged with no actor.
- **Nothing else resumes.** The step never touches a pause made by hand (`manual`), by HQ (`persona_retired`), by the platform (`ai_paused`), or for any other reason (`spend_limit`, `daily_limit`, `sponsor_left`, `tool_disconnected`, `scope_archived`). Both the select and the UPDATE require `paused_reason = 'cap'`, so a pause a person makes between the two is not undone.
- **Where it runs.** No new timer: the step is `resumeCapPauses`, the first step of the existing agent sweep (`sweepAgents`, every 5 minutes on minute % 5 = 1), with `now` passed in. It handles at most 60 agents per sweep. The sweep's result gains `cap_resumed`.
- **Before the halt and engine checks.** A resume changes a status and admits no run, so it is safe while the engine is halted or off. If it waited for the engine, a cap-paused agent would stay paused for weeks after the engine returned. The sponsor's own run (`agentRun`) never needed the engine. `index.ts` therefore calls `sweepAgents` whenever `TEAM_AGENTS_ENABLED` is on. The sweep's resend and admit steps still return early while halted or off, and duties and alerts still run only with the engine on. A failed resume read is logged, and the rest of the sweep goes on.
- **`resumes_at`.** Every agent DTO (the list, the profile, the PATCH and PUT answers) carries `resumes_at`. For a cap-paused agent it is the first day of the month after its pause, as `YYYY-MM-DD` in UTC. For every other agent it is null. The sweep uses the same pause instant. The cap pill's "Resumes 1 Dec" reads this field and never computes a date in the browser. With null, the pill names no day.

### 4. The screens

- **TM9b.** A paused agent's fix link opens the profile on the dialog it names: "Choose a new sponsor" opens `SponsorSheet`, and "Raise the cap" opens Edit cap (`pauseWords(a).action`). A manager also gets "Change sponsor" in the profile's footer.
- **`SponsorSheet`** lists the candidates from §2 and marks the current sponsor. A member who cannot sponsor is shown with the Worker's reason, and their option is disabled.
  - It asks for a reason of at least 10 characters.
  - For an agent with tools, Save is enabled only after "Drop its N read tools" is ticked.
  - A refusal is drawn in the Worker's own words (`agentsAdapter.throughSponsor`), never as its code. It uses no `alert` or `confirm`.
  - No canvas draws this dialog. It reuses the Edit-cap dialog's frame.
- **Activity.** `sponsor_changed` reads "Sponsor changed to [name] by [actor]". `resumed` reads "Resumed at the start of the month" for `cap_reset` and "Resumed with its new sponsor" for `sponsor_changed`.

### 5. The migration

`team_agent_events.kind` was held to nine values by a CHECK in migration 712, and SQLite cannot widen a CHECK in place. Nothing references the table. The migration follows the house pattern (`202611031659_influencer_handles.sql`):

1. Copy the table aside.
2. Drop it and recreate it with the same columns, references and index, and with `sponsor_changed` added to the CHECK.
3. Copy the rows back with their ids, and keep the AUTOINCREMENT high-water mark.

It uses no transaction statements. `cap_reset` is a `resumed` detail, so it needed no new kind.

### 6. What it does not do

- It does not resume a cap pause when the cap is raised. Raising the cap leaves the agent paused until a manager resumes it, as before.
- It does not move a run already in flight. That run's hold stays with the sponsor it was admitted under, and only later runs are charged to the new sponsor.
- It does not move the agent's skills. A skill that needs a dropped tool cannot use it after the change.
- It does not let anyone sponsor an agent without a seat on its team, HQ's admins included.
- It does not resume an agent paused `tool_disconnected`, even when the sponsor change drops that tool. A manager resumes it.
