## D900 — Pitch deck studio part 6: the deck's review of a version, and its check against the records

- **Status:** the review is built by S26 for #2679 (part 6 of #2434), 2026-10-24, migration 541, merged in #2758. **The check** is built by S26 on 2026-10-27, after #2430's claim check (D1264, #3287) merged as #3467: migration 645, §7 to §11.
- **Basis:** `origin/main` at `5ed26088bf`, with part 1's fixes (D895, #2689) and D894's shell (#2685). Worker paths are relative to `cloudflare-worker/src/`; frontend paths to `frontend/src/`.
- **Canvas:** PD14, "Reviewer pass" (`design/incoming/Pitch Deck Studio · Boards.dc.html`; the page's `HOME · REVIEW` block): "a score only because the review returned one, strengths, weaknesses, red flags and fixes each pointing to a card, the cost of the run, and the history per version with Score not returned where none came back."

### 1. The store: `deck_reviews.deck_id` and `deck_version` (migration 541)

- **Two columns on the reviewer's own table.** A version review is a `deck_reviews` row with `source = 'deck'`, `deck_id` (the `pitch_decks` row, one version) and `deck_version`. Uploads and pasted text keep both NULL and stay as they were: per user, outside the deck's history.
- **Each run is a `deck_review_history` row**, as the reviewer already writes one. Nothing read that table before; `GET /:id/reviews` is its first reader.
- **No cost column.** A run's cost is its own `ai_usage_logs` rows, found by `record_ref = 'deck_review:<id>'`, guard rows included. The log already holds the charge (`charged_microusd`, D762), so a copy could only drift.

### 2. The routes: `routes/deck_review.ts`

Mounted at `/api/decks`, after `deck_notes` and before `decks`. Both paths are two segments, so neither shadows `GET /api/decks/:id`.

| Route | Who | What |
| --- | --- | --- |
| `POST /:id/review` | the venture's founders | Reviews this version's cards. 201 `{ review: { id, deck_id, deck_version, created_at, model, shape: 'cards', overall_score, summary, strengths[], weaknesses[], red_flags[], fixes[] }, cost }`; each point is `{ text, card }` |
| `GET /:id/reviews` | the founders; an Admin; the Super Admin on HQ | `{ reviews: [{ id, run_id, deck_id, deck_version, created_at, overall_score, cost, review }], viewer, capped }`: every version of the venture, newest first, at most 200 |

- **`cost`** is `{ charged_microusd, est_cost_usd, runs }`. `charged_microusd` is the sum over the run's rows, or **null** when any row has no recorded charge or there is no row. It is never a guessed 0.
- **Who.** A review is a charged run, so only the founders run one: the deck's write access (`projectOwned` with `write`), as a note's post is decided (D905). An Admin, or the Super Admin on HQ, reads the history and is answered 403 `read_only` on a run (PD21: an admin reads and changes nothing). An advisor member, another venture's founder and anyone else are not found.
- **Refusals.** A run the router refused (the page's switch, a budget stop, the guard) answers in that refusal's own words (`refuseRun`, D766). An empty version is 400 `deck_empty`, before any run.
- **The rail.** The run is logged under `Founder · Raise · Pitch deck` and a new option, `review:deck-version` ("Review this version"). It is inventoried in `lib/railOptions/founder.js`, and the matrix is rebuilt from it.
- **Audit.** Each review writes one `raise.pitch-deck` activity row in the same batch: `deck_reviewed`, "Review run on v4, 12 cards". It never carries a score or any figure from the deck (D691 decision 12).

### 3. The review itself: `services/deckVersionReview.ts`

- **It reads the version's cards, not an upload.** `cardText` gives each card's words in the order the card shows them: title, subtitle, the legacy body and bullets, then each field, with a metric grid as "label: value". An image is skipped, and each line is said once. `deckText` numbers the cards "## Card N", as the studio does, capped at 16,000 characters as the reviewer caps its text.
- **Every point names a card.** The prompt asks for `{ text, card }` in four columns (strengths, weaknesses, red flags, fixes). A card number this version does not have, or none at all, keeps the point's words and points nowhere (`card: null`, "No card named"), never at a guessed card.
- **The score is the review's own.** `returnedScore` keeps a number from 0 to 100. A missing, empty or non-numeric score is null ("Score not returned"); nothing here computes one. Part 1 (D895) made the same fix in the reviewer's normalizer; this file never had a heuristic.
- **Nothing is invented when the run fails.** A refusal, an unreadable answer, or an answer with no summary and no point stores nothing: no row, no history, no activity. The route answers 502 `review_not_returned` with what the run cost. The reviewer's deterministic fallback review (`deckExtract.ts`) is not used here.

### 4. The page: the Review tab (PD14)

`pages/raise/pitch/PitchReview.jsx`, with its words and derivations in `reviewModel.js`, replaces the embedded `DeckReviewerPage` in `PitchStudio.jsx`'s Review tab.

- **The current version's review:**
  - the header reads "Review v4 · <title>" and "Proposed by Eadwyn · ran <date · time> · cost $0.0180";
  - the score shows "of 100 · returned by the review" only when one came back, and "Score not returned" otherwise;
  - the summary is shown;
  - the four columns each show a "Card N" pill (or "No card named") on every point.
- **"Review this version · $0.0180"** opens a dialog that says what the run reads (the version's N cards), what it costs, and what it changes ("The review is added to this version's history. Nothing on the deck changes."). The figure on the button is the venture's last recorded charge. With none recorded, the button names no figure, and the dialog says the cost is shown when the run is done. The press sends `railPressHeaders('review:deck-version')`.
- **"Reviews per version"** lists every run, newest first: version, score or "Score not returned", when it ran, and its cost or "Not recorded".
- **An admin** reads the review and the history and is offered no run: "Only the venture's founders run a review. You can read the reviews." Who may run is the Worker's `viewer`, not a guess from the role.
- **A failed history read** says so and disables the run. A version never reviewed says so.
- **Uploads and pasted text stay available** below, as "Review an upload or pasted text": the embedded `DeckReviewerPage`, unchanged. It keeps its `AssistLayout surface="deck_review"` wrap, and `ui_assist_rail_and_sidebar.test.mjs` pins it there. It still works with no venture, as before D894.
- **The client:**
  - `api.deckReviewVersion(id, headers)` and `api.deckReviews(id)`;
  - `/decks/:id/review` joins `SLOW_PATHS`, so the run gets the long deadline the reviewer's regenerate has.

### 5. Departures, for review

- **The estimate is the last recorded charge, not a quote.** The router's hold is an upper bound over every fallback model and the guard (`aiRouter.ts`). Showing that ceiling as the review's price would overstate it. The canvas draws the same figure on the button and in the header, and the last charge is that figure.
- **A failed run stores nothing.** The reviewer stores its heuristic fallback review. Here, a review that came back empty is no review, so the history never shows a review nobody wrote.
- **The history is the venture's.** The reviewer's rows are per user. A version review belongs to the deck, so every founder of the venture, and its admins, read every version's reviews.

### 7. The check: D1264's claim check, on the version asked about

The deck's figures are D1264's `deck` surface: every string on a card, read by `parseStatedFigures`'s fixed patterns (never a model), each a claim keyed `slide:<n>#<figure>` with `surface = 'deck'` and `surface_version = 'v<n>'`. The states are D1264's, from the founder's pinned evidence, best source first: Backed, Founder's figure, Mismatch, Not backed.

- **`raiseClaims.ts`** gains `checkDeckVersion(env, projectId, row)`: the same compute and the same writer (`writeSurfaces`, split out of `checkClaims` unchanged), for the version passed rather than the current one. Other versions and other surfaces are not touched; older versions keep their last state, as D1264 says.
- **Stale** is a display state, never stored (D1263). A figure is Stale when a binding on its card (D896) is `stale` in the refresh comparison and the bound field states that figure (`deckCheck.ts` `staleClaims`). A sources read that fails marks nothing Stale rather than everything.
- **`deck_checks`** (migration 645) records that a version was checked, by whom and when, with its figure count, so a version with no figure reads "Checked · no figures" and one never checked reads "Not checked", never zeros.

### 8. The routes (`routes/deck_check.ts`, mounted before `decks`)

| Route | Who | What |
|---|---|---|
| `GET /api/decks/checks?project_id=` | any reader of the deck (`projectOwned`) | each version's `checked`, `checked_at` and counts by state, or `checked: false` and `counts: null` |
| `GET /api/decks/:id/check` | any reader | the version's last check. The founder reads the stated figure and the note; anyone else the states alone (D1264: `record` and `stated_value` are founder-only) |
| `POST /api/decks/:id/check` | the venture's founder (`raiseEvidenceContext`), never a support session | runs the check on that version and answers PD13's rows with both figures and both sources; 422 `deck_unreadable` when its slides cannot be read, and the last check stands |
| `POST /api/decks/:id/claims/:uid/use-record` `{ record_value }` | the venture's founder | "Use Stripe's figure" (§9) |
| `POST`/`DELETE /api/cycles/raise/evidence/claims/:id/note` `{ note }` | the venture's founder (`evidenceScope`) | "Keep mine, with a note" (§10), shared with the narrative's check (#2696) |

Each write logs one cycle row, never a figure or the note: `deck_checked` and `deck_figure_replaced` under `raise.pitch-deck`; `claim_kept_with_note` and `claim_note_cleared` under the claim's own module.

### 9. "Use Stripe's figure"

- **The record is read again,** never taken from the dialog: the claim must still be a Mismatch (409 `claim_not_mismatch`) and the record's figure must be the one the dialog showed (`record_value`, else 409 `record_changed`). Nothing is written on a refusal.
- **Only the number the check read moves.** `swapFigure` tries each number in the card's strings whose value is the stated one, and keeps a candidate only when the check's own patterns read the record's figure from the result. "Founded 42 months ago with 42 paying customers" changes the second 42. The figure is written the way the sentence wrote it (`$` and `%` kept, a scale like `$1.2m` written out).
- **It saves a new version** the way Restore does (`insertVersion` with the version's audience, round and theme), so the version it came from stays as it was. The editor then opens the new version, as it does after Save. With unsaved edits the dialog holds the button: "Save or discard your changes first".
- **Departure, for review.** The issue says the swap "binds" the figure. A claim's record is a pinned evidence item, not one of D896's `DECK_SOURCES` slots, and no mapping between the two exists yet. The swap changes the words only; binding the card is the editor's Sources panel, as before.

### 10. "Keep mine, with a note" (owner question 6, read as A)

- **On the claim's own row** (migration 645: `note`, `note_value`, `noted_at`, `noted_by`). D1264's upsert names only its own columns, so a check never clears a note.
- **Only a Mismatch takes a note** (409 `not_mismatch`); clearing is always allowed. The text is 1 to 500 characters.
- **The state stays Mismatch,** shown with the note: neither figure is presumed right.
- **A note applies to the figure it was written against** (`note_value`). Once the card states another figure, the read drops the note and says the earlier note no longer applies.
