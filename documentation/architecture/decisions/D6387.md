## D6387 — Open repair issues for actionable Actions failures (#6387)

A trusted reporter in `.github/workflows/github-alerts.yml` writes repair issues from GitHub's own Actions API. The reporter covers versioned, GitHub-managed and newly registered workflows. Each issue identifies a workflow and attempt, links its failed jobs and gives the repair owner a verification step. The existing Slack sender remains an independent consumer.

The reporter groups matching failures by workflow, affected context and failed job/step signature. An exact run/attempt can appear once in an episode. Existing human-owned repair issues stay authoritative when the reporter can verify both the cause and the open issue. A successful retry is evidence for the owner to assess. It does not automatically close the repair. Critical operational impact needs confirming evidence beyond the workflow's name.

A signed webhook can send a small batch of run/attempt IDs to the trusted workflow as soon as failures complete. A five-minute GitHub schedule reconciles missed completions and continues observing runs that were unfinished. Both use the same serialized issue writer. GitHub queue delays apply to both paths. The public issue body contains links and sanitized metadata. Full logs and restricted findings stay behind their original access controls.
