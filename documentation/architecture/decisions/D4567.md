## D4567 — D1 scale S1: measure the single database before changing it (#4567)

- **Status:** built by S15 on `agent/claude-s15/4567-d1-benchmark`, stacked on #4566's branch (D4566). Not merged. Nothing is deployed, and no schema or production setting changes.
- **Parent:** #4554. Coordinates with #4559 (telemetry), #4566 (preview isolation), #3847 (the agent runtime) and #2474 (provider accounting). It feeds #4568.
- **Migration:** none.

### Decision

1. **`studioos-db` stays one database.** Partitioning is studied only if the owner's production baseline shows the database is the bottleneck, *after* index, query, batching and retention fixes.
2. **The benchmark drives the real services.** `cloudflare-worker/test/_d1_bench.ts` runs `aiRouter.run`, `agentRun`, `admitInScope`, `markRun`, `moveTask`, `decideRail`, the loop's `after`, `loadAiBudget`, `memberHolds` and `listRail`, unmodified. They run over a throwaway node:sqlite file from every migration, with #4566's synthetic fixtures and stubbed inference. There is no second ledger and no replayed copy of the SQL.
3. **Every statement is metered by fingerprint.** For each: read or write, rows changed, time, batch, stage, query plan, and the index and trigger count of the table written. Fingerprints mask every literal. Reports hold aggregates only.
4. **Invariants are checked after every run, and fail the CLI.** They are:
   - double settlement, a missing charge, an orphaned hold;
   - a negative balance (the schema's CHECKs refuse one, and the meter counts the refusal);
   - a second live run, an orphaned run;
   - a duplicate proposal or hold;
   - a cross-tenant read, and unknown read as zero.
5. **Three classes of result, never conflated.**
   - **Simulated** (this work): statement counts and plans are exact, while latency and throughput are relative.
   - **Preview platform**: the owner's run, behind #4566's preflight. The driver inside the Worker is #4594's.
   - **Production observation**: the owner's read-only analytics, recorded as an audit.
6. **CI runs only the tiny deterministic test** (`d1_benchmark_4567.test.ts`). Load runs are manual: `npm run bench:d1` locally, and the owner's run on preview.
7. **What the findings start, and what they don't.** Every fix the findings point to belongs to #4568, with its own evidence; none is applied here:
   - an index for `chargedFor`'s `guard_for` scan;
   - `agentAreas` reading one agent's links rather than every agent's;
   - batching a run's usage and run/task writes;
   - reading the platform's switches once per request.

### Why

#4567 asks for limits measured, not assumed. Counting statements in the code that runs, on the real schema, replaces the trace's estimates:
- an agent run is 86 statements, of which 7 are batched;
- an AI call is 33.

It also found two reads whose cost grows with the platform rather than the request:
- the `guard_for` scan of `ai_usage_logs`;
- `agentAreas` over every registered agent's skill links.

Neither can be priced without production's row counts. That is the owner's baseline, which this session cannot read.
