## D1115 — Finish the Events desk reads, stored time zones and refusal words

#2995, part of #2368, completes the listed D915 gaps against current main.
D918's enriched paged list and counts-only summary were already mounted; its
waiting-hours field and server-side waiting sort were also already present.
Those working reads are retained. No migration or new API method is needed.

All events and Calendar now use counts from each D918 list row, across every
page. The event page's first row of tiles and capacity dialog use the independent
`registrations` summary block. The desk no longer fetches capped analytics and
Guard G is removed. Empty lists and recorded zero counts remain valid; missing
count fields are Not recorded and failed reads are Unreadable with retry. The
other summary blocks keep their independent failure states.

All events adds the canvas's Waiting time sort, longest first, using D918's
`waiting_hours`. Non-waiting events and unknown waits sort last, including when
a real waiting time is zero. Review adds the viewer's own date/time and zone
under Starts and ends while retaining the event-zone line. `not_published` and
`already_cancelled` now each have a fixed sentence inside the existing dialog.
No new layout is invented; Review uses EV3's existing secondary fact line.

The host editor used to convert its datetime-local inputs in the browser's zone
while storing the selected event zone as a separate label. The Worker now
converts new local clock values in that selected IANA zone and stores UTC
instants, on both create and edit. Explicit-offset instants retain their meaning;
a zone-only API edit retains existing instants. Invalid calendar dates, unknown
zones, skipped clock-change times and ambiguous repeated local times are refused
with fixed messages before any event write. An explicit offset resolves a repeated
time. SQL bindings, host/admin authorization and existing edit auditing remain.

The editor displays saved instants in the event's own zone and sends new wall
times to that mounted writer. Unchanged edits preserve seconds and the precise
DST occurrence; legacy offset-free stored timestamps are treated as UTC. The
saved header uses the Worker's returned event. Material-change detection compares
start/end instants so formatting-only normalization does not falsely flag an
approved event, while a real schedule change still does.

Tests cover more than 200 enriched rows through the mounted desk, Calendar's
expanded-day card, the summary's counts/failure, true zero versus missing counts,
the waiting order, Review's two zones, both refusal codes, editor read/save in
another browser zone and mounted Worker create/edit/authorization/DST cases.
New assertions are checked with deliberate source mutations and restoration.
Historical Guard G tests are retired; the remaining calendar, filters, CSV,
capacity, refusal, queue-refresh and access checks use the D918 contract.

The owner's post-merge live checks remain **UNVERIFIED**. No production data or
settings were accessed. Older events already stored at an incorrect instant
cannot be reconstructed from the timezone label alone: this change does not
shift historical rows in bulk. The owner/host must verify their intended times.
