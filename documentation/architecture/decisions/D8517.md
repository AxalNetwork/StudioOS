## D8517 — The release reports who made the code it ships, in shadow mode (#8517)

**Decision date:** 2026-11-25. **Scope:** one admission step in
`.github/workflows/cloudflare-worker-deploy.yml`, one exported report in
`scripts/ci/agent-provenance.mjs`, and the runbook. No production, database or permission change.

### Why

D8068 checks the identity chain on a pull request. The release admits an exact candidate SHA, but a
squash commit made by GitHub carries no trailers, so nothing at the gate said which slot and task
produced what was about to ship.

### What

For the candidate, the admission job lists the changes on its first-parent line since the last
successful run of the release workflow on `main`, reads each pull request's head from
`refs/pull/<n>/head`, runs the D8068 check on those commits and writes one row per pull request to
the job summary: slot, task, `pass` / `fail` / `human` / `unavailable`, and which session trailer
each commit used. A pull request none of whose commits names an identity trailer is `human`: the
check has nothing to judge there. The `Claude-Session` cutover (2026-12-01) is the same function's
rule, so the report says which form each commit used and flags a legacy form after the date.

### Shadow only

The step cannot fail the release: `continue-on-error: true`, `|| true` on every command, a closing
`exit 0`, and a script that returns 0 on any error. `scripts/lib/provenanceShadow8517.test.mjs`
asserts the text and runs the step's script with `gh`, `git` and `node` all broken. Making it a gate
is a later decision for the owner, after two weeks of reports.

### No new access

The admission job keeps `contents: read` and `actions: read`. The previous deploy comes from the
workflow-runs API (actions read); pull request heads are fetched with git using the job's own token
for that fetch only. The step reads no secret and names no environment. A private-repository
deployment where those reads are refused prints `unavailable` rows rather than widening anything.

### Protected path

`cloudflare-worker-deploy.yml` is a protected path: this change is made but landed by T2 and the owner.
No real release run has produced the summary yet; that is the last item of the issue's done-when and
needs the first release after the merge.
