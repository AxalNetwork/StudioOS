### 1A — free, open sources first

**The question.** The directory held 300 companies from Wikidata (CC0, migration
228), and funding was recorded for 16 of them (migration 375's columns). The
owner expects thousands. D9 and D12 withdrew third-party funding and investor
data until a licensed source of the PitchBook or Crunchbase class exists.

**The answer.** Grow the directory from free, open sources: more companies from
Wikidata by sector and country, US public companies from SEC EDGAR, and UK
companies from Companies House. Funding and investors stay "Not recorded"
unless a source records them. A licensed provider (B) and staying at 300 (C)
were not chosen.

**What that rules.**
- **An importer is a committed script that writes a migration.** It never
  writes to a database. Rows reach D1 through `migrate-d1` after review, like
  every other row.
- **Every row cites its source and licence:** the source's name, the record's
  own URL, the licence line, and the date of the pull (`as_of`).
- **Nothing invents a figure.** What no source records stays NULL, and the
  directory prints "Not recorded" for a null (D534). Taking a figure from an
  open source is a decision of its own, with that source's citation on the
  figure.

### The Wikidata part (#1229)

**The importer.** `scripts/import-wikidata-companies.mjs` queries Wikidata's
public SPARQL endpoint and writes
`cloudflare-worker/sql/migrations/403_research_company_directory_wikidata.sql`.
It selects an item with:
- an official website (P856);
- exactly one country (P17), named as migration 376's `research_countries`
  names it (matched on the country's ISO code, P297), so the crosswalk maps it;
  a country that list lacks keeps Wikidata's English label;
- an industry (P452) whose English label the crosswalk maps to a market. The
  importer imports `COMPANY_SECTOR_RULES` from `services/researchTaxonomy.ts`
  (D533), so the importer and the Worker read one dictionary;
- an English label, for the name;
- no dissolution date (P576).

It reads the inception year (P571) where Wikidata records one: the earliest
year, kept only from 1000 to the year of the pull. An item whose best-rank
countries are two different countries is skipped rather than guessed.

**How rows are chosen.** The order is deterministic, so a re-run against the
same Wikidata writes the same file:
- within an industry, most sitelinks first (how many Wikipedias describe the
  company), then by Q-id;
- across industries, round-robin in crosswalk-label order, so no industry
  (software, banks) takes the whole file;
- an item already in migration 228 is skipped, and an item two industries both
  offer is taken once;
- at most 400 candidates per industry, and a cap of **3,000 rows** for the
  file. That is ten times the directory as it stood, and the same order of size
  as migration 365's 3,440 fund rows, which a reviewer can still page through.

**What a row carries.** Migration 228's columns:
- `uid`: the Q-id in lower case, the key `INSERT OR IGNORE` uses, so applying
  the file twice adds nothing;
- name, website, country, founded year and `sector` (the industry's label as
  Wikidata spells it, the form 228 stores and the crosswalk reads);
- `source_name` `Wikidata`, `source_url` the entity's page, `source_license`
  228's CC0 line verbatim, and `as_of` the date of the pull.

Funding, revenue, headcount, valuation and every other figure are left NULL.
This pull reads identity fields only.

**What reads it.** Nothing changes in the Worker or the pages. `coverage` and
`facets` are computed from the table on every request (D534's
`directoryShape`), so `coverage.of` becomes the new total with no constant to
update. The directory's search, filters and pages already run on the server.

**Guard.** `cloudflare-worker/test/research_wikidata_companies_d537.test.mjs`,
on fixtures shaped like SPARQL results, so it holds without the network:
- the query selects on P856, P17 and P452, drops P576, and refuses an id that is
  not a Q-id;
- only industries whose label the crosswalk maps are kept;
- a row takes https first, the crosswalk's country name by ISO code and the
  earliest year, skips an item in two countries, and carries no figure;
- selection is round-robin, capped, and skips 228's 300 companies and
  duplicates;
- a written file parses, every row cites its entity under the CC0 line, a quote
  in a name survives, and applying it twice adds nothing;
- the list route's `total` and `coverage` are the table's own counts, before
  and after an import.

**Mutations: 22 run, 22 caught**, each with a non-zero exit and a `not ok`
line, sources restored from sha256-checked snapshots:
- the query drops P856 or the P576 filter, or the Q-id check loosens;
- the hyphenated label variant goes, or SPARQL quotes go unescaped;
- industries stop being filtered by the crosswalk;
- the website order ignores https, the country falls back to Wikidata's label,
  an item in two countries takes the first, the year takes the latest or has no
  upper bound, a non-http website is accepted, or control characters survive;
- 228's companies or cross-industry duplicates are kept, or the cap is
  ignored;
- a quote is not doubled, or the insert is plain `INSERT`;
- the licence line drifts from 228's, or the source URL is not the entity
  page;
- 228's uids are not read;
- `coverage.of` comes from a constant.

A twenty-third mutant, dropping a duplicate check in `parseIndustries`, changed
nothing: the Map it fills is keyed on the Q-id. So the check was removed.
