### 1. PD2: New in your data since vN, and the versions table

**"New in your data since vN"** (`PitchStudio.jsx` `NewInData`, `pitchStudioModel.js` `newInData`) is the first card beside the current deck.

- **The read.** It is D896's refresh read of the current version (`POST /api/decks/:id/refresh`), which writes nothing.
- **What it lists.** One row per figure the version holds whose store has moved on:
  - a **stale** figure reads "<figure> changed · <module>", with the day the store read it;
  - a **gone** figure reads "<figure> is no longer recorded", with the day the version had read it.
- **What it leaves out.**
  - A figure bound on two cards is listed once.
  - A fresh figure is not listed.
  - A figure that could not be read for this reader (Mercury's, for anyone but the founder) is never called new. It is counted apart, in a line of its own.
- **When there is nothing to list:**
  - a version that binds no figure says so;
  - one with nothing changed says "Nothing in your data has changed since v4.";
  - a failed read says "That is not the same as nothing", with Try again.
- **"Refresh the deck ›"** opens the editor (`/raise/pitch/edit`). D896 already marks the stale cards there, and the editor's Save is the write.

**The versions table** (`Versions`) gains three things:
- **Shared links.** Each version's links ever made, from `GET /api/decks/by-project/:pid`. Each version now carries `shared_links`, with a `shared_links_readable` flag beside them.
  - A version with no link is a counted 0.
  - A count that could not be read is `null` on the Worker and "Not read" on the page, never 0.
- **The Audience filter.** All, then each audience a version is written for, in the canvas's order, then "Not recorded" for a version from before D898.
- **The Sort control.** Newest (the canvas's default) or Oldest.

**Not drawn.** The canvas's Checks column is not in this issue's work, and is not drawn.

### 2. D898's blocks outside the editor

**One drawing, three places.** `BlockGrid.jsx` holds the editor's block view, moved out of `PitchEditor.jsx`, and the 12 × 6 grid. The editor, Present and the print page all draw from it.

**The rule is the editor's.** A card with blocks is drawn from its blocks, each at its range. A card without blocks is drawn from its fields, as before. A block without a whole range on the grid is not drawn (`presentExportModel.js` `gridBlocks`).

**In Present** (`PitchPresent.jsx`):
- Each block kind draws as the editor draws it: text, metric tiles, charts with their series (a typed series with its points), images, and graphics by name.
- Video, audio and link blocks are real links that open in a new tab.
- "Show sources" adds each metric tile's own source line through D1111's `sourceOf`. A tile with no figure reads "Not recorded", never 0.

**In the PDF and PowerPoint.** Both exports photograph the SPA print page (`/deck/print-export/:token`, `pages/PitchDeckPrintPage.jsx`) in Browser Rendering.
- Before this change, a studio deck (New deck's fields, the editor's blocks) fell to the legacy title-and-body card there.
- It is now drawn card by card (`PrintExtras.jsx` `StudioPrintCard`): the grid for a card of blocks, Present's fielded layout for the rest.
- A deck made from a template (a `method_id`) is still drawn by its template.

**In the HTML file** (`services/decks/offlineHtml.ts`):
- Each block is placed at its range on a 12 × 6 CSS grid.
- A block's image, and a video's poster, are fetched with the card images.
- **The file still asks for nothing (D901).** A video, audio or link block is its label plus its address as text, with no `href`.

**Not drawn yet.** A chart's bound series carry no values in the slide, only their binding. So every surface names them and their source, and plots nothing, as the editor does.

### 3. PD17: the two options for every format

"Include speaker notes" and "Include a Sources appendix" apply to every format the dialog offers. Google Slides is still part 10, drawn as unavailable. The dialog says where each option goes for the format chosen (`presentExportModel.js` `OPTIONS_WHERE`).

| Format | Speaker notes | Sources appendix |
|---|---|---|
| PDF | a page after the cards, six cards a page; a card with none says "No notes on this card." | the last page |
| PowerPoint | each card's speaker notes (the notes slide); without the option it keeps the card's text, as before | one more slide, photographed from the print page's appendix |
| HTML | under each card (D901) | the last card (D901, D1111) |

**How the options reach the print page.**
- `POST /api/decks/:id/export` takes `{ format, notes?, sources? }` (`routes/decks.ts`).
- The options ride inside the signed print token: `deck-print|<id>|<exp>|<flags>`. `verifyDeckPrintToken` returns them, and a token from before this change carries neither.
- **The print payload carries the notes and the appendix only when the token says so** (`printDeckOf`).
  - A share link's read and an unflagged print token still strip the notes, as D898 decided.
  - The appendix is the HTML file's own lines (`sourceLines`, and the new `aiCards`), so the three formats list the same figures.
- **A flag cannot be added by hand.** Editing the payload breaks the signature.

**The text-only PowerPoint fallback** is used only where Browser Rendering is missing, which is development. It gains the appendix slide and stays without speaker notes.
