### 1. Where the answers live

#4270 asked for a `deck_qa_answers` table. That table has held D1559's **kept** answers since migration 736: record bindings (at least one, by CHECK) and a short note. A written answer is the founder's own words with no binding, so it cannot live there. It lives in `deck_qa_written`, beside 736, keyed the same way (`objection-…`, `finding-…`) plus `typed-<16 hex>` for a question the founder adds. A question is **answered** when either store holds an answer.

The store is the founder's alone. Only `routes/deck_qa.ts` reads or writes it, and `deck_qa_written_4270` fails the build if any other Worker source names the table: no share, export or public read selects it.

### 2. The routes (`routes/deck_qa.ts`)

| Route | What |
|---|---|
| `GET /api/decks/:id/qa` | D1559's read, plus per question `written` (`{ text, source, by, at, deck_id, version }` or null) and `answered`; typed questions after the ranked ones (`kind: 'typed'`); `answered_count` of `total`; `reads.written`. `answer` stays D1559's bound draft. |
| `PUT /api/decks/:id/qa/answers/:key` | `{ answer, source }`. A ranked key must be one this deck asks now, and its words are copied. `source: 'ask'` is kept only when the answer is the bound draft word for word, else 422 `not_the_draft`. |
| `POST /api/decks/:id/qa/answers` | `{ question, card?, answer? }`: a typed question. At most 40 per venture (409 `too_many_questions`). |
| `DELETE /api/decks/:id/qa/answers/:key` | Clears a written answer; removes a typed question whole. |

**Who.** Writes are the venture's founder's, in their own session (403 `founder_only` otherwise). An HQ admin, in their own session, now reads `GET /qa` (#4270: "an HQ admin reads"); a support session is still refused. This widens D1559's founder-only read for HQ only; the prospect is still read with the venture's id, so another venture's prospect is still 404.

A count the read could not make is `answered_count: null` ("Not recorded"), never 0.

### 3. Ask

The canvas draws "Ask for questions" with a hold. #4270 limits Ask to "draft answers from the deck's bindings only", and D1559's read already writes that draft (`answer.text`) in code, with no figure a binding does not carry. So Ask here places those drafts into the unanswered questions, runs no model and charges nothing, and says so. A placed draft reads **Not saved** until Save; Discard drops it; an edit makes it the founder's (`source: 'typed'`). The questions themselves are D1559's ranking, so Ask does not propose new ones. A model-written Ask, with a quote and a hold, would need its own rail option and prompt registration; it is not built here.

### 4. The screens

`ScriptTile.jsx` gives Script & rehearsal its three views (`?view=questions`, `?view=rehearsals`; Script is the default and stays P1's block until P2a, #4268).

- **Likely questions** (`QuestionsTab.jsx`, ps4b): "Likely questions about <deck> v<n>", "Never shown to investors · n of m answered", each question with its card pill and Answered, Not answered yet or Not saved; Add a question; Ask for answers; Save, Edit, Discard, Clear answer, Remove question. A reader sees the answers and no control.
- **Rehearsals** (`RehearsalsTab.jsx`, ps4c): each run's date, duration of target (marked when over), words a minute, filler words, cards over budget and notes covered. `GET /rehearsals` now carries those from each report (null without one; the contract is updated). Open reads the run and draws per-card bars; "The black tick is the card's budget."
