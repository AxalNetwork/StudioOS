### 1. The store

- **`licence_partner_deal_types`:** one row per licence, holding `types_json` (a JSON array, which the CHECK requires), `updated_by_user_id` and `updated_at`.
- **Types** are a subset of `ALL_PARTNER_DEAL_TYPES`, stored in that list's order: equity partnership, services partnership, deal sourcing revenue share, capital partnership, custom deal.
- **An empty list is a decision:** the studio offers no partner deals.
- **No row reads "Not recorded",** never "every type" (D797's rule).

### 2. HQ's reads and write (`/api/admin/partner-deal-types`)

| Route | Guard | Returns or does |
|---|---|---|
| `GET /` | `requireSuperAdmin` | `catalogue` (each type and its label) and every licence with `recorded`, `types`, `updated_at`, or the Not recorded sentence |
| `GET /licences/:uid` | `requireSuperAdmin` | the licence, `recorded`, `types`, who set them and when, and the history (§5) |
| `PUT /licences/:uid` `{ types, reason }` | `requireSuperAdminWriteBar` | sets the list; `types: null` clears it back to Not recorded |

The PUT is refused, with a sentence and a code, for:

- a reason under 10 characters (`reason_required`);
- no `types` (`types_required`);
- a type that does not exist (`unknown_deal_type`, naming it);
- a terminated licence (409 `licence_terminated`);
- a list equal to what is stored (409 `unchanged`);
- an unknown licence (404).

A D1 error is a 5xx through `mapError`, never an empty list.

### 3. A licence HQ has not set

**Until HQ sets a licence's deal types, every type stays open,** as before this store existed. No studio loses a deal type because HQ has not got to it yet. Every read says that this is the rule, not HQ's choice: `recorded: false` with "Not recorded. HQ has not set which partner deal types this studio may offer, so every type stays open until it does." The owner may change this rule. Doing so changes one branch in the invitation write (§4), and no data.

### 4. Where the rule is applied

- **On a branch.** The partner invitation write (`POST /api/admin/partners/invitations`) reads the branch's copy, `branch_licence.partner_deal_types_json`:

  | Copy | Meaning | Invitation |
  |---|---|---|
  | a JSON array | HQ's set | a type outside it is refused: 422 `deal_type_not_allowed`, "This studio's licence does not allow Capital partnership. HQ sets which partner deal types a studio may offer.", with `not_allowed` and `allowed` |
  | JSON `null` | HQ has recorded none | every type (§3) |
  | SQL NULL | a copy pushed before 555 | every type (§3) |
  | anything else, or an unreadable copy | — | 503 `deal_types_unreadable`; nothing is written or sent |

- **On HQ's own deployment, nothing is limited.** HQ-held accounts run every program (D981's map, question 1), and HQ's own invitations are not a licence's. The refusal is checked only where `BRANCH_CODE` is set.
- **The partner's onboarding** picks among its invitation's types, so a refused type never reaches it.

### 5. The push, the copy and the history

- **The push.** `assembleLicenceRecord` adds `partner_deal_types_json`: the JSON array, or the JSON `null` when HQ has recorded none. A store that cannot be read leaves the key out, so the branch keeps the set it has.
- **The copy.** `applyLicenceCopy` writes the column only when the key is present, and only onto the copy that push wrote (its `pushed_at`), so an older push arriving late never overwrites a newer set. This is D797's rule for `terms_json`.
- **Each write pushes the licence** (`pushLicenceToBranch`). A push that does not land is retried (D272).
- **The history.** Each write appends, in the same batch, one `licence_events` row:
  - `event = 'program_changed'`: D982 §5's generic kind, which leaves later parts room to add actions without rebuilding the sealed table;
  - `note` = the reason;
  - `detail_json = { action: 'deal_types_changed', program_key: null, before, after, reason }`.

  `program_key` is null because deal types belong to the licence, not to one program. `GET /licences/:uid` returns the last 50 such rows, newest first.

### 6. The studio's read (`GET /api/licence/mine/partner-deal-types`)

- **On HQ:** the Administrator bound in `licence_admins` reads their own licence's row. Anyone else gets 404 `no_licence`, as `/api/licence/mine` answers.
- **On a branch:** an admin of the branch reads the copy, as `source: 'branch_copy'`, with its `state` (`not_pushed` or `not_recorded`) when it holds no set. A non-admin gets 403.
- **A store or copy that cannot be read** is a 503, never "Not recorded".
- **Mounting:** the router is mounted at `/api/licence` ahead of `routes/licence.ts`, as `licence_requests.ts` is.
