### 1. Attach a Meet call that was not scheduled from Axal

`POST /api/founder/validate/interviews/:id/meetings` with `{ attach: { event_id | meeting_code | join_url }, consent }` and **no** `session_id` (`routes/founder_validate_meetings.ts`, `attachCalendarMeet`).

- **The call is found in the member's own Calendar,** never taken from the link alone (`services/channels/googleMeet.ts`, `findCalendarMeet`). It reads the member's primary calendar with the `calendar.events` grant they already gave:
  - **By event id:** `events/{id}`. A recurring instance's id names one instance.
  - **By Meet code** (typed, or from a `meet.google.com` link): the events from 30 days ago to a year ahead. A recurring call carries its code on every instance, so the instance whose start is nearest now is taken.
- **Checks, in order. Each refusal stores nothing and opens no session:**

  | Check | Refusal |
  | --- | --- |
  | Consent recorded, as scheduling takes it | `400 consent_required`, before any Google request |
  | Meet usable on this deployment | `503 provider_unavailable` |
  | Google connected | `409 connect_first` |
  | The event exists, is not cancelled and has a Meet conference with that code | `404 meeting_not_in_calendar` |
  | The member's account organises it | `409 meeting_not_hosted` (D685's code and sentence) |
  | It has a start and an end (not all-day) | `409 meeting_no_time` |
  | It ended no more than 30 days ago (Meet keeps records 30 days) | `409 meeting_expired` |
  | No other call on an interview starts in its slot with that event or link | `409 meeting_link_reused` |

- **Organiser only.** Meet saves a call's transcript to the organiser's Drive, so a call another account organises would end at `no_transcript` every time. A founder invited to a customer's Meet can still record it in Axal or paste it. UNVERIFIED: whether Meet REST lists a non-organiser's artifacts at all. Allowing attendees later would be one check here, and an owner decision.
- **As scheduling does.** It opens a `video` session marked `google_meet`, with the consent given. It writes an `interview_channel_refs` row keyed by the event id, with the event's join link, start and end.
  - The status is `scheduled`, or `ended` when the call is already over.
  - The sweep imports the transcript after the call, exactly as for a scheduled call.
  - A grant without `meetings.space.readonly` still attaches, and says so (`meet_transcripts_unavailable`), as scheduling does.
- **Unchanged:**
  - **D685's attach with a `session_id`:** a link pasted for the recording in progress. It still has no end time until Stop sets it (`closeAttachedRefs`).
  - **Zoom's paste,** which still needs its recording session.
- **Client:** `channelsApi.attachCalendarMeet(interviewId, { event_id | meeting_code | join_url, consent })`.

### 2. Speakers

`participantLabel` labels each participant Meet lists (`conferenceRecords/{r}/participants`), and `SpeakerBook` numbers the rest per call. Numbers follow the order of first speech, across all the call's conference records.

| Participant | Speaker label |
| --- | --- |
| `signedinUser.user` is `users/<google_sub>` of the member's own Google connection | **Me** |
| a signed-in user with a `displayName` | that name |
| an anonymous user with a `displayName` (the name they typed) | that name |
| a dial-in (`phoneUser`) | **Phone participant N**. Meet's `displayName` here is a partly redacted phone number, and it is never stored. |
| no name (a signed-in user Meet does not name, an anonymous user with none, or an entry naming a participant Meet did not list) | **Speaker N**. The same signed-in user keeps their number across the call's conferences. |
| an entry with no participant at all | Speaker ? |

- **"Me" is matched by Google account id, never by name.** `google_oauth_tokens.google_sub` is read with the connection. Meet's `users/{id}` is documented as interoperable with the People API, whose id is the account's `sub`. UNVERIFIED in production. A row without `google_sub` (an older grant) yields no "Me": the founder keeps their display name.
- **What Meet returns for external participants:** still UNVERIFIED. Meet's docs give `signedinUser.displayName` for signed-in users and `anonymousUser.displayName` for guests. Whether an outside Google account's name is given to the organiser's grant can only be read on a live call; the owner's check in the runbook (§3) records it. Until then, an unnamed participant reads "Speaker N" instead of D684's "Speaker ?" for everyone, which keeps different people apart. D873 (#2520) treats any such label as unattributed.
- **One existing expectation changed:** `channels_meetings_d684` now reads "Speaker 1" for the entry from a participant Meet did not list.

### 3. A call without a transcript (option A)

When Meet has the call's conference records but no transcript (`meet_no_transcript`), the call's recordings are listed: `conferenceRecords/{r}/recordings`.
- Listing takes `meetings.space.readonly`, the scope Axal already asks for; Google's reference for `recordings.list` accepts it.
- Only a recording in state `FILE_GENERATED`, with an `https://drive.google.com` view link (`driveDestination.exportUri`), counts.

| What Meet has | What the call settles with |
| --- | --- |
| Records, no transcript, and a generated recording | `no_transcript` with the new code `meet_no_transcript_recording`: "Google Meet made no transcript of this call, but it was recorded to your Google Drive. Download the recording from Drive, then upload it here to transcribe it." |
| Records, no transcript, and no recording | `meet_no_transcript`, as before |
| The recording listing fails | `meet_no_transcript`, as before. The call is settled either way. |

- **The link is read live, never stored.** `GET /api/founder/validate/interviews/:id/meetings/:refUid/recording` returns `{ recordings: [{ url, started_at }] }`. It reads Meet with the member's grant (`meetRecordingLinks`), for the member's own Meet call only; any other call is `404 meeting_not_found`. Client: `channelsApi.meetingRecording`.
- **Axal never reads the file.** Fetching its bytes needs a Drive read scope (`drive.readonly`, a restricted scope with Google's security assessment). That is option B of question 1, for the owner. The upload it hands off to is D872 (#2519, on `main`): `frontend/src/lib/recordingUpload.js` takes a Meet recording downloaded from Drive, with the founder's attestation, into a `submitted_via 'upload'` session.

### 4. Push instead of the daily sweep: study only, nothing built

Read 2026-10-22 from Google's "Subscribe to Google Meet events" guide (Workspace Events API). What is not on that page is marked UNVERIFIED.

- **The events exist:**
  - `google.workspace.meet.conference.v2.ended` fires when a conference ends in a meeting space;
  - `google.workspace.meet.transcript.v2.fileGenerated` fires when a transcript file is generated;
  - transcript `started` and `ended` exist too.
  
  A payload carries only the resource name, so Axal would still read the transcript through Meet REST, as the sweep does today.
- **Subscriptions** target a meeting space or a user. Calendar invitees can receive only `conference.v2.started` and `transcript.v2.fileGenerated`, so a subscription for a call would be made with the organiser's own grant.
- **Delivery** is to a Google Cloud Pub/Sub topic (UNVERIFIED in detail). To reach the Worker, it would need:
  - a Pub/Sub topic in the owner's Cloud project;
  - a push subscription to a public Worker route;
  - the route verifying the Google-signed OIDC token on each push;
  - one Workspace Events subscription per call (or per member), created at schedule or attach time and renewed before it expires (UNVERIFIED: the TTL).

  A Worker can receive an HTTPS push. Verifying the token is the same JWKS check the Worker already does for Google sign-in (UNVERIFIED that the code can be shared as is).
- **What it would save:** the import would start minutes after the transcript is generated, not on the next sweep. The sweep would stay as the catch-up, which Google's guide itself recommends for missed events.
- **Recommendation:** keep the sweep (question 2, option A) until Meet transcripts are switched on and used. Pub/Sub adds a Cloud project resource, a public endpoint and subscription renewals, for an import that the sweep already makes within the hour.
