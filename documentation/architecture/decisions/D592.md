## D592 — Owner-controlled evidence blend, off by default

Task #1219, S18 · Codex, 2026-10-06. Implements the deferred proposal in D356/D358 and PROFILING_V2 §5.2; it does not activate it.

The proposed `evidence_level` is `min(5, 5 × evidence_weight / 3)`. Three is the existing corroboration weight: the index maps activity coverage into 0–5 and saturates there. It is not an independently assessed skill level. Choosing this calibration is a proposal for the owner to assess against the comparison, not evidence that completing three actions establishes expert proficiency. Evidence volume and ageing can move the proposed number down as well as up.

`PROFILE_EVIDENCE_BLEND_WEIGHT = 0.25` sits beside, outside, `PROFILE_V2_PARAMS`; existing parameter exports retain their bytes. This conservative weight matches the existing smallest material snapshot change. While on, a self-rated axis with positive finite evidence displays `clamp(self + clamp(evidence_level − self, −1, +1) × 0.25, 0, 5)`. It moves at most a quarter-level from self, without extra rounding. Absent, zero, faded or invalid evidence leaves self unchanged. Without self, the level stays null, even when evidence exists. The five states keep their existing thresholds and meanings. Snapshot weights retain their existing two-decimal normalization; the live evidence report uses its existing source-weighted reading.

The typed row `profile_evidence_blend_enabled` uses migration 241's existing `platform_settings`. Nothing seeds it: missing row is off; '0' is off and '1' is on. A malformed row or failed read is unreadable, aborting a profile read/recompute instead of stamping an incorrect off profile. A pre-241 database with no setting table cannot have been activated and remains off. There is no cached setting that could survive a flip.

`GET/PUT /api/profile/evidence-blend` is mounted below the existing profile router. Both require the actual elevated HQ Super Admin (an admin role/JWT alone is insufficient, and branches refuse). PUT accepts only a boolean, binds key/value/time/actor, persists `updated_by` as the authenticated user id, and calls `logAdminAction` with before/after and engine version. That shared helper's audit writes remain best-effort; the persistent setting always records its writer. This task introduces no operator panel or frontend API method. The owner alone activates the proposal on #1219 after reviewing the comparison.

Off returns the original levels, shapes, parameter object and snapshot version `profiling-v2.1`; the evidence report retains numeric version 2. On snapshots use `profiling-v2.1+evidence-blend-v1:w=0.25`, and the live report uses version 3. Turning off restores the original version, so either direction reaches the existing nightly `engine_bump` path. The bounded/resumable nightly pass reevaluates every person with saved fit answers; a flip during or after a pass reaches earlier users on the next pass. The evaluation stamp comes from the profile actually computed, rather than rereading the setting after persistence. A concurrent flip therefore leaves that person due. Material blended drift also appends a snapshot while on; off keeps the old materiality rule. No old snapshots are rewritten.

Archetypes classify trait answers, not skill levels. The blend leaves that classifier and its hysteresis intact.
