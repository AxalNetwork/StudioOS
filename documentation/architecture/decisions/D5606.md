## D5606 — Shadow the consolidated CI landing gate (#5606)

Part of #5600. PR 1 adds the shadow jobs on top of #5601. The six current required contexts and branch settings stay in effect during the shadow phase.

### Checks and outputs

The `ci / fast` job runs on every CI event. Its one full-history, blobless checkout supplies the scan range and migration comparison. The scan, migration guard, PR-only LFS guard and API drift checker run before dependency installation. Worker typecheck and frontend build follow. The two npm audits, the Python audit and routing docs remain outside merge groups. The independent steps use `!cancelled()` and keep their actual outcomes.

The verdict step reports `required=pass` only when checkout, setup and the required checks have succeeded. Advisory failures can make the fast job red and leave its required verdict at pass. `landing gate` always runs after `verified`, `fast` and `suite`. It fails when the required verdict is missing or unsuccessful. It accepts a successful suite, or a skipped suite on a push with the existing exact-SHA verified run. PR 1 keeps the current required jobs. PR 2 removes them only after the owner's check-name cutover.

### Preflight evidence

- Gitleaks v8.21.2 scanned a synthetic two-commit range in a full-history `blob:none` clone. It caught the marker in the intermediate commit even though the marker was removed by the tip. The clean base scan passed.
- The local shadow workflow tests retain the old gate and exercise the required and advisory verdicts. A failed migration or missing required output blocked the gate. A failed advisory audit left the required verdict at pass. Cancelled, failed and unverified skipped suites were refused.
- GitHub exposes dependency outputs through `needs`. Verify that a deliberately failed advisory step still delivers the explicit required output to `landing` in a hosted PR run before requesting any ruleset cutover.
