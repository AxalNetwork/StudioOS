## D4739 — HQ › AI agents: the From Axal lifecycle and the Policies controls are drawn, and the alerts open real pages (#4739)

- **Status:** built by S13 on #4739 (HQ admin UI audit of 2026-11-06).
- **Builds on:** D4137 (the panel), D4160 (the From Axal lifecycle, H2), D4162 (the platform policy, H4), D4523, D3851 (the engine halt) and D4157 (the agent alerts).
- **Migration:** none.

### The question

Three Worker features were merged without a screen. The lifecycle of From Axal skills (review, golden cases, evals, retire, bulk) was routed and had a client, but the library drew Publish…, Re-run evals and Retire… disabled behind "arrives with #4160", and the skill page said editing was "not connected on this page yet". The Policies tab showed the models, locks, caps and read tools as text and could only pause. And the bell's agent alerts sent HQ to `/admin/agents` and `/admin/operations`, which the SPA does not serve: `/admin/*` drew the not-found page. The engine halt had no screen at all.

### What was decided

**H2 is live, and every write takes a reason.**
- SA3: rows can be ticked. **Publish…**, **Re-run evals** and **Retire…** send the ticked skills to `POST /skills/bulk` with a reason of 10 to 500 characters (Retire also names a published replacement). Each skill is done or refused on its own, and the list says which.
- SA4 (`/hq/ai-agents/skills/:uid/edit`): ask a named Super Admin for a review, approve or ask for changes (the asked reviewer only), edit the golden cases (`PUT …/cases` with a reason; a case is never edited in place, so a changed case is a new one), re-run the evals, compare versions, and retire.
- The reviewer is chosen by name. `GET /skills/:uid` gains `reviewers: [{ uid, name }]`: the other active Super Admins, never the asker or the draft's last author, never an email. It is null when the read failed, never an empty list.

**Policies is a control panel.** Models by area (up to three suggestions and one default), lock and unlock a model, the four caps (dollars on screen, micro-dollars on the wire; blank clears a cap, it is not 0), and the read-tool list. Each write takes a reason and is audited by the Worker with it.

**The engine halt sits beside the pause** (`GET`/`POST /api/admin/agents/halt`), with a reason of 10 to 64 characters on both halt and clear. A halt that could not be read says so; it is never shown as "agents may run".

**A refusal shows its own sentence.** `refusals.js` keeps one sentence per code for skills, the policy and the halt. A code it does not know shows the Worker's own sentence, and failing that a plain one; the error's raw text is never shown. A test reads the Worker's sources and fails when a code has no sentence.

**The alerts open real pages.** The dead-letter and gateway alerts link to `/hq/ai-agents/operations`, the halt set and cleared alerts to `/hq/ai-agents/operations/policies`. A Worker test reads `App.jsx`'s routes and fails when any `link` in `alerts.ts` or `skillEval.ts` is not one. The skill-evaluation notice already linked to the skill's editor, which now has the actions.

**The docs say what main does.** The route-map section for the panel lists the Worker route behind each board, with the cohort card. The folder README describes the files and rules as they are. The Grid health tab's old `/admin/ai/deck-grid` address (retired in D2319) is gone from `hqDecks.jsx`, the decks README and the route-map section, and the README row now names the Beta cohort and AI models tabs.

### What was not done

- A reviewer is not picked from a search. The list is the Super Admins, who are few.
- The Company skills tab and the roster are unchanged; their writes already take reasons.
- `rosterRefusal` now follows the same rule (the Worker's sentence from `e.data`, never `e.message`).
