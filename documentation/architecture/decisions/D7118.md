### Why a new table

Since D574, `POST /daily` has been an alias of `/checkins`. It writes one row per UTC week into `wellbeing_daily_pulses`, and a later save replaces that row. The heart's "Today's check-in" therefore wrote the weekly record, and the table has no monthly period at all. Re-keying that table would change rows that members already saved.

`wellbeing_reflections` has one row per member, cadence (`day`, `week` or `month`) and period. A daily save never touches a weekly or monthly row, and none of them touch each other.

### Periods

Each period is a set of dates in the member's own calendar. The zone is the IANA zone the device sends with the request.
- **Day:** one calendar date.
- **Week:** Monday to Sunday, named by its Monday.
- **Month:** a calendar month, named by its first day.

A write must name the period by its first day. A period that has not started is refused, and so is anything before 2020-01-01.

The time zone rule:
- "Today" is always worked out in the zone the request carries.
- A saved row keeps its own dates and the zone it was first saved in, so moving zones never moves a past reflection.
- A save for a date that already has a reflection edits that reflection, whichever zone the edit comes from.

A week that crosses a month end is one weekly row. A month's summary lists it under weeks, and it is never counted as days.

### Protection

Scores, text and topics are stored as AES-GCM ciphertext (`cryptoBox`). This writer has no plaintext fallback columns.

If the cipher is unavailable, the write answers 503 `reflection_protection_unavailable` and stores nothing. Its message tells the member their words are kept on screen for a retry.

The route never logs a value. A refusal logs the error's own text, and only HQ's aggregate reads the scores. Text and topics are never read outside the author's own routes:
- not by HQ;
- not by an expert;
- not by a model;
- not by the expert directory's ranking, which still reads only the earlier check-ins' tags (that ranking is #7119's to put behind consent).

### Retries and concurrent edits

A write carries `base_revision`, which is 0 to create, and may carry a `request_id`.
- **Same `request_id` again:** returns the stored row (`replayed: true`) and does not write it twice.
- **Stale revision:** a write from an out-of-date copy, or a second create of the same period, answers 409 `reflection_changed` with `current_revision`. It is never applied over the newer edit.
- **Racing creates:** the insert is `ON CONFLICT DO NOTHING`, so the loser gets the same 409.
- **Racing edits:** the update is guarded by `WHERE revision = ?`, so the loser gets the same 409.

### Earlier check-ins

The record does not say whether a row in `wellbeing_daily_pulses` was daily (before D574) or weekly (after it). So `GET /earlier` reads those rows as "Earlier check-in". Each one keeps its own date, and the week it fell in is given.

They are never filed as a day or a week, so a past record is never counted twice. The daily, weekly and monthly histories do not include them, and neither does the month summary. The member can delete them one at a time, and they are included in the export.

The old routes `/checkins`, `/daily` and `/aggregate` keep working, and the existing page still uses them until the canvas build.

### History, the month summary, deletion, export and retention

- **History:** `GET /?cadence=` returns one cadence, newest first.
- **Month summary:** `GET /months/:month/summary` cites what was recorded:
  - the recorded days, the weeks that touch the month, and the month's own reflection, each as a period and its topics;
  - how many recorded days named each topic.

  A day with no entry is left out; it is never shown as a zero. No score is averaged and nothing is rated.
- **Deletion:** `DELETE /:uid` removes a reflection. Afterwards the period can be written again from revision 0.
- **Export:** `GET /export` downloads the member's own reflections and earlier check-ins as JSON, with `no-store`.
- **Retention:** a reflection is kept until the member deletes it. This is ⚑ Q3 on #7117 for the owner. Changing it means changing the `RETENTION` constant and adding a sweep.

### Access and isolation

The guard is the same as `/checkins`: any signed-in member except an investor-only account. The page's own route guard stays `admin` and `founder`.

Every query is scoped by the caller's user id. A uid that belongs to someone else answers 404, so the route never confirms that it exists. No route names another member.

### HQ aggregate

The HQ aggregate's scores now include reflections, behind the same floor of 7. The cohort is the number of distinct members across both stores, so a member who appears in both is counted once. A group of six stays suppressed whichever store it sits in. The aggregate never decrypts text or topics.
