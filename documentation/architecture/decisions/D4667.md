## D4667 — The first ten skills' inputs: evidence that says what it covers (#4667)

Part of #4667 (child of #4528; case content is #4588's, evaluator semantics #4531, CI #4532, runtime permissions #4534, release evidence #4533). No migration, no route.

**What was found, checked against current `main`.**
- The default task and scheduled context path (`services/agents/reads.ts`, `agents/loop.ts`) has readers for the project and company summaries, the team roster and the four cycles' records. Every other catalogue key (`mercury.balances`, `stripe.revenue`, `cap_table.read`, `data_room.index`, `compliance.calendar` and the rest) refuses `read_unavailable`.
- The cycle readers returned the latest 20 activity summaries, with no stable id, text clipped to 300 characters with no flag, and no count of what exists beyond the 20.
- An answer over `READ_MAX` was replaced by a substring of its JSON.
- Manual execution separately accepts approved tool reads (`agentRun.ts`). That path is not exercised here.

**What changed.**
- **Collections say what they cover.** Each cycle read answers `coverage { returned, total, omitted, complete }`. The total is its own `COUNT(*)`, never inferred from the page. A count that could not be made is `null`, and `omitted` is then `null` too: an unknown count is unavailable, not zero.
- **Rows are referable.** Each carries `ref: activity:<uid>` (the activity log's own uid, not a row number), and `clipped: true` when its text was cut at 300 characters.
- **An oversize answer keeps its shape.** Whole rows are dropped from the end of its longest list and counted in `omitted_for_size`, so `truncated` means "rows left out, here is how many". If no list can be shortened enough, the answer is `incomplete: true, reason: 'too_large', data: null`. A JSON substring is no longer ever produced.
- **The matrix and the preflight** (`services/agents/skillInputs.ts`).
  - `FIRST_TEN` names, for the ten skills of #4588 and in its order, each input: the field the skill needs, the read key it comes from, the KIND of evidence (`typed_record`, `document_text`, `activity_summaries`, a profile, or `manual_evidence`) and whether it is required.
  - `READER_PROVIDES` says what each built reader gives. A need is met only by that shape: activity summaries do not satisfy a request for a typed burn series or a transcript with consent.
  - `preflight` reads the actual readers for one scope and reports per input `available`, `empty`, `missing`, `absent_optional`, `partial` (more rows than supplied, an uncountable total, an over-limit answer, or the wrong shape), `stale` (newest record older than 45 days), `unavailable_reader` or `unreadable`.
  - A skill is `ready` only when every input is available. It is `conditional` when its required inputs are there in part or stale, or an optional one is not (the brief then states its `limits`), and `not_ready` when a required input is absent, empty, unreadable or the wrong shape.
  - `inputMatrix` and `pathsFor` give the static view for discovery (#4538) and the HQ flow (#4537): which paths could carry each skill.

**The finding that matters.** On the readers that exist today, none of the ten skills is `ready`, and none can run on the default or scheduled context path: each has a required input no built reader gives (typed balances, burn, revenue, document text, a cap table, workstreams, opportunities, or a transcript with consent). The preflight reports that, per input, instead of letting a run proceed on summaries. This is by design: building the missing readers or approved MCP adapters is the rest of #4667, and each lands as its own reader with its own declared shape.

**Tests** (`agent_reads_evidence_4667`, through the real readers on the migrated schema):
- A 21-record history supplies 20 and says 1 was left out; another project's records stay out.
- An overlong record is flagged; a short one is not.
- An oversize list keeps rows whole and counts what it dropped; a blob that cannot be shortened is `incomplete`.
- An unknown count stays null; a reader that throws, one that is not built, an empty complete collection, a missing record, a stale newest record and a partial page are six different statuses.
- All ten skills get a preflight with evidence and with no project; none is ready; a reader that does not declare the shape cannot make a skill ready by answering, and readers that do declare it can.
- Mutations caught: the total inferred from the page; an unknown count read as zero; oversize rows not shortened; a wrong-shape reader counted as supplying a required input.
- The existing agent suites that use the readers or the loop pass unchanged.

**Not done here; stays in #4667.**
- The missing readers and approved MCP adapters, each declared in `READER_PROVIDES`.
- Continuation (a cursor) for complete-period work beyond the latest 20 rows. The coverage and `omitted` now make the gap visible and refuse a complete-period claim; the cursor is a later step.
- Units, currency and period fields on typed evidence: they arrive with the typed readers.
- Native-reader versus approved-MCP tests apart, and a separate manual-evidence path test.
- Exposing the matrix and preflight through a route for HQ (#4537) and discovery (#4538): the functions are the contract; a route and its client method follow with those consumers.
- Shared context and runtime edits are #4534's, so `loop.ts` is untouched; the new fields ride inside each read's existing envelope, which `buildContext` already carries into the prompt.

### Second slice: typed readers, continuation, manual evidence and the readiness surface (#4667)

Still "Part of #4667". No migration. `loop.ts` is untouched (#4534); new answers ride the existing read envelope.

**Typed native readers** (`services/agents/reads.ts`, declared `typed_record` in `READER_PROVIDES`), on catalogue keys that already existed and refused `read_unavailable` until now. Each answer gives every record its own stable reference, the unit of each amount, its currency (or `null` where the source records none; never assumed), its date and its coverage. Each reader checks the source's own access rule as the agent's sponsor, with the sponsor's licences hydrated as auth does.
- `mercury.balances`: the venture's cash and treasury now, from `mercury_grow_facts` (Grow's Mercury sync), in cents, `currency: null` (the facts record none). Gate: `isTeamViewer`, the rule Grow uses. Per-account balances are not recorded for a venture: only these totals. (`mercury_accounts` and `mercury_balance_snapshots` are the studio's own entities, never a venture's.)
- `stripe.revenue`: `revenue_entries` in a period (default: the last twelve months), each with its currency, type, source and verification. Monthly totals (`by_month`) are given per currency, never added across currencies, and only when every entry of the period was read; otherwise `by_month` is null.
- `cap_table.read`: the cap table record (`readRecord`), with its currency, whether that currency was set, and its units (shares, cents, micros, bps). Gate: `resolveAccess` at Full: an agent never reads a holding its sponsor could not open in full.
- **Withheld.** Someone the rule refuses gets `{ withheld: true, reason }`, with none of the source's figures. A run's context carries that in place, with no throw in the loop, and the preflight reports a new status, `withheld`, distinct from missing, empty and unreadable. A required withheld input makes the skill `not_ready`.

**Continuation and periods.** `ReadContext.page` is `{ after, from, to }`. A cycle reader's page names `page.next`, the `activity:<uid>` its next page starts after. A period bounds both the rows and the count, so a period's total is the period's. A cursor from another project, cycle or period is refused (`unknown_cursor`), never widened. `readPages` follows the cursor up to a bound (10 pages by default, at most 50) and is `complete` only when it read every row of the period. All of it is fixed SQL with bound values. A run's default context passes no page and reads the latest page, as before.

**Manual evidence.** `preflight(..., supplied)` takes a person's record per input: `{ ref: 'manual:<slug>', recorded_at, text }`, checked before any model operation (`suppliedProblem`). A well-formed record meets a `manual:` input; one that is not well formed is refused with the reason. Standing in for a record the platform could have read, it is `partial`, so the skill is `conditional`, and its limit says the figure came from a person. Each input now says its `source` (`native` or `manual`) and, for a manual one, its `ref`.

**The surface for HQ (#4537) and discovery (#4538)**, on the existing `/api/teams` router: `GET /skills/inputs` (the matrix) and `GET /agents/:uid/skills/:slug/readiness?project=&from=&to=` (the preflight, read as the agent's sponsor, for whoever may read the team, with statuses and reasons and never a figure). A company agent reads a venture only when it is the company's. No client method yet: it follows with its consumer.

**What the matrix says now.** `monthly-investor-update` is the first skill whose required input a native reader carries on the default and scheduled paths. The other nine still lack a required reader.

**Tests.**

- `agent_reads_pages_4667` (4): the cursor over 45 rows, periods, refused cursors, manual evidence.
