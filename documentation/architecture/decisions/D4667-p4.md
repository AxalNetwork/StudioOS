### What was found, on #7658's head `745bb3869e`

`lp-quarterly-letter-draft` required "recorded fund performance with periods and valuation dates" from `raise.records`, which gives activity summaries. The input was `partial` (`wrong_shape`), so the skill was always `not_ready`. Fund performance is recorded on main: D627's `readFundPerformance` computes NAV, paid-in, distributed, RVPI, DPI, TVPI and IRR from `portfolio_positions`, `fund_position_valuations`, `fund_capital_calls` (with the legacy `capital_calls` lines) and paid `fund_distributions`; D1158 reads it point in time; D6278's benchmark "Ours" reads the same function. No agent read reached any of it, and a run had no way to name a fund.

The manual path already reads a sponsor's approved MCP tools (D1496 part 5: `tool_grants`, `cleanReads`, `readTools`, D852's approval and pin). A tool's answer is cut to an 8 KB JSON prefix (`capResult`). Nothing said what that answer is as evidence for a first-ten skill.

### What is decided

1. **A new read key, `fund.performance`.** A rule book grants it on purpose. No default rule book reads it, as with `grow.board_metrics`.
2. **One fund, chosen by the run.** A run reads a fund's figures only when it selects one, as `vc_fund:<id>`:
   - manual: the run's `record`;
   - readiness: `GET /api/teams/agents/:uid/skills/:slug/readiness?fund=vc_fund:<id>`; anything else is 400 `invalid_fund`.

   A scheduled session cannot select one: `agent_duties.target_kind` has no fund kind, and its CHECK constraint would need a table rebuild. `pathsFor` says so. For `lp-quarterly-letter-draft`, `default_context` and `scheduled` are `unsupported`, and `selected_record` is `supported` (`MANUAL_SELECTION_ONLY`).

   With none selected, `fund.performance` answers the funds the sponsor runs here, each with its reference, name, vintage and status, and no figures. A skill that needs the figures is then `not_ready`, reason `not_selected`.
3. **The GP of record only.** The sponsor reads a fund as `requireFundGp` admits a GP. `fundGpScope` has to match: the GP of record, under the agent's company (a company agent's own, a project agent's company), on the institutional investor tier. These answer `withheld`, with none of the fund:
   - an admin, who reads funds through audited admin acts;
   - a lower-tier investor;
   - an agent with no company.

   A fund the sponsor does not run under this company is `not_found`, the same answer as a fund that does not exist. An LP reads a fund through the LP portal, never as an agent's sponsor.
4. **One quarter, and its shape.** A read covers the last whole quarter that ends on or before `page.to`, or today when `page.to` is not given. It states that quarter as `period` (`2026-Q3`, `from`, `to`), and `from` is not used. It answers:
   - `performance`: `readFundPerformance` as of the quarter end, point in time. This is the same formula as fund performance and the benchmark offer, never a second one. A figure it cannot compute is null and keeps its reason (`unavailable`), never 0.
   - `marks`: each position the fund held by the quarter end (`portfolio_position:<uid>`), with its latest valuation on or before that date (`fund_position_valuation:<uid>`, value, `valuation_date`, source). A position with no valuation has `mark: null`, never its cost. A valuation dated before the quarter began is flagged `before_period`.
   - `capital_calls`: those issued in the quarter (`fund_capital_call:<uid>`, `capital_call:<uid>` for a legacy line).
   - `distributions`: those paid in the quarter (`fund_distribution:<id>`).

   Every amount is in integer cents. No currency is recorded on a fund, its calls or its marks, so `currency` is null and never assumed. Each list holds at most 200 rows and has its own coverage, counted separately from the rows returned. An answer over 8 KB drops whole rows and counts them (`omitted_for_size`), as every native read does.
5. **The input status:**

   | The read | Input status |
   |---|---|
   | read whole, every figure computed, every mark in the quarter | `available` |
   | a mark dated before the quarter | `stale` |
   | an unmarked position, an uncomputable figure, a list not read whole or not counted, or a cut record | `partial` |
   | no position, call or distribution by the quarter end | `empty` |
   | not selected, or not found | `missing` |

   `stale` and `partial` leave the skill `conditional`, and its limits name each gap (for example "1 position(s) have no mark on or before 2026-09-30: Tidepool Health"; "not recorded at the source: distributed_cents, dpi, tvpi, irr"). `empty` and `missing` make it `not_ready`. A 422 `skill_not_ready` says "no fund is selected for the run" or "the selected fund is not one the sponsor runs under this company".
6. **Approved-MCP evidence is its own kind.** `readTools` now returns `McpEvidence` for each read it makes:
   - `source: 'approved_mcp'`, `ref: mcp_tool:<integration_uid>:<tool>`, the server, the tool, the read's number and `fetched_at`;
   - `outcome` (`data` or `refused`), `complete`, `bytes` (the answer's whole length), and `typed: false`;
   - never its arguments or its words.

   It differs from a native read in three ways, and each is tested on its own:
   - **Readiness:** only native readers meet a first-ten input. The evidence check runs before any MCP call. A skill that is not ready is refused with nothing sent to the server, even when the sponsor names an approved tool that could answer the same question.
   - **Identity:** a native read cites a record's own reference. An MCP read cites the sponsor's connection, the approved tool, and when it was read.
   - **Size:** a native read over its limit keeps its typed shape and counts what it dropped. An MCP answer over 8 KB is cut to a JSON prefix, so its evidence is `complete: false`.

   A first-ten skill run that reads MCP tools has a system prompt (`mcpPrompt`) that says three things. The results come from the member's own approved tools, not from a record the platform read. They meet none of the skill's inputs. Each one is listed by its reference, and the prompt names each read that was cut ("say the result is incomplete") or refused ("supplies nothing"). A run with no MCP read adds no MCP text.
7. **Unapproved MCP evidence is refused before the model call,** through the checks main already has, now tested on a first-ten skill run whose native evidence is ready:
   - another member's or an ungranted tool is 403 `tool_not_granted`;
   - a granted tool the skill's version does not list is 422 `tool_not_in_skill`;
   - a tool whose schema changed since approval is 409 `tool_disconnected`, and the agent is paused.

   In each case nothing reaches the model and nothing is charged.
