## D9276 — Eadwyn commands: one registry for /section/module, aliases and shortcuts, generated from the modules' own forms (#9276)

- **Status:** built by S21 on #9276, 2026-11-28. No UI (#9278 draws the composer) and no Worker change.
- **Chosen by:** the owner, on #9276 and the #9271 audit, with the supplemental audit's reconciliation on the issue.

### The problem

Eadwyn's composer had no list of what a member may do from it. The modules and their Add forms already exist in code (`frontend/src/pages/cycles/modules.js`, the list each `frontend/src/pages/cycles/defs/*.jsx` draws, and `frontend/src/pages/cycles/forms.js`), but nothing turned them into commands, and a hand-typed catalogue would drift from them the day a form was added.

### What was decided

- **One registry, generated.** `frontend/src/lib/commands/registry.js` builds an entry for every cycle module (`/<section>/<module>`, handler `navigate`) and every Add form `formsFor` returns (`/<section>/<module><action>`, handler `form`), plus five shortcuts. Its only hand-written rows are `ACTIONS` (each form's stable action id, label and one short alias, keyed `<section>/<module>#<form key>`), `EXEMPT_FORMS` (a form with no command, with its reason) and `SHORTCUTS`. `buildRegistry` reports a form with no row (`missing`), a row with no form (`stale`) and a name used twice (`duplicates`), and the test fails on each.
- **The owner's example.** `/validate/ideal-customer-profile<create-segment>` resolves to `validate.ideal-customer-profile.create-segment`, labelled "Create customer segment · Validate › Ideal customer profile", whose handler opens the module's `segment` form at `/validate/ideal-customer-profile/new` (D695) with the open project's `project_id`. A form after a module's first adds `?form=<key>`. `/segment` names the same entry; a bare "segment" is a search whose first suggestion is it.
- **The grammar** (`frontend/src/lib/commands/grammar.js`) is a pure parser answering `{ entry }`, `{ suggestions }` or `{ unknown }`. Angle brackets are optional (`/validate/ideal-customer-profile create-segment`). Anything that is not an exact path or alias is a fuzzy search over labels, module titles, section titles, aliases and paths: per typed word, exact 3, prefix or one typo 2, two typos (words of six letters or more) 1. So a typo suggests rather than answering unknown.
- **A typed path resolves only to a listed entry.** The parser never builds an address from what was typed; `entry.href()` is built from the entry's own fields. `/api/...`, a path with `..`, or a query string answers suggestions or unknown.
- **Seeing an entry grants nothing.** Each entry carries the guard of its route in `frontend/src/App.jsx`: `roles` and whether the guard is `labRoles([...])` (Validate, Build and Raise are `labRoles(['admin', 'founder'])`, Grow a plain `['admin', 'founder']`). `visibleTo` admits the role, or an active Spin-Out Lab member under a `labRoles` guard; the test reads App.jsx and holds each section's `/:slug` and `/:slug/new` guards equal to `SECTION_GUARDS`. The module's Worker writer still decides every write. An investor sees none of Validate's actions, not even as a suggestion.
- **Each entry carries** its stable id, aliases, the allowed scope types (`project`, `company`, `none`), required inputs (the form's own `required` fields), its permission check (`roles`, `labRoles`) and availability (`coverage`, with `unavailable` saying why), preview behaviour, writer, result link and error/retry behaviour.
- **Shortcuts.** `/record` opens Record a session at `/validate/record` (#9280 extends it); `/task` and `/ticket` open Studio's ticket form (`/studio/tickets/new`, `?type=task` for a task, D701), founders only as that route is guarded; `/team` is listed as unavailable until #9282 builds it and sets its scope; `/explain` explains the page the member is on.
- **One handler more than the issue named.** The issue lists `form`, `navigate`, `record`, `team`, `ticket` and `task`; `/explain` fits none of them, so it has its own, `explain`.
- **Exempt.** Build › Company creation's `suggested` form (Add a suggested filing, D8259) opens only from a suggested filing's own link with that filing's values, so it has no command.
- **Related lists stay apart.** Global navigation, the rail's options (`frontend/src/lib/railOptions/`), advisor tools and agent skills have other purposes; the registry reads the forms and cycle defs and merges none of them.
- **Coverage.** Validate first, then every cycle the generator finds: all four cycles' modules and forms are listed today.
