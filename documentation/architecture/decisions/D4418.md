## D4418 — Work W7 client, deep links and existing actions (#4418)

Part of #3968; W7's detail screens are a separate follow-up task.

All eighteen routes in work_items.ts now have explicit, encoded workApi
methods. workAdapter delegates through the existing WORK_OFF boundary, so an
engine-off 404 remains an unavailable block and other failures propagate.

The item query opens the matching item after the current project's board
read succeeds. If filters hide it, the single-item read must confirm both its
uid and project before the sheet opens. An absent uid leaves the board visible with "That task wasn't
found." Closing the sheet removes only the item query parameter. The sheet is
keyed by item uid to prevent a previous item's local state being reused.

Move is shown only under canMove, opens the existing moveTargets, saves through
the adapter and refreshes the board. Schedule reuses Workload's existing UTC
ScheduleBox. Its save and refusal handling remain shared. The Needs-you strip
opens the latest dated failed run and narrows the board to In review, with a
way back to all items. No Worker behavior, schema or engine setting changes.

The focused tests exercise the real HTTP client, every route and body, every
off-block adapter, the mounted sheet actions, read-only Move visibility, run
selection, review filtering, item deep links and missing tasks.
