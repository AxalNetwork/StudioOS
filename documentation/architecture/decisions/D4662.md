## D4662 — Sent conversation history survives its draft and exposes every page (#4662)

A sent record owns its `person_ref` and quoted-ref snapshot. Both manual RecordCompose and AI ComposeSheet sends supply the person; the Worker resolves explicit refs through `personRecord`, the same module access gates as context reads, before provider I/O. A supplied person must agree with the caller-owned draft. Older callers with a draft inherit that established association; callers without context remain explicitly unassociated. The operation fingerprint includes explicit person context, so replay cannot silently move a message to another conversation. Existing no-context fingerprints remain compatible.

The timestamped migration adds the nullable association and conversation-order index. It backfills only an existing same-user draft relationship. It never guesses from a recipient address or changes quoted refs. Reads no longer join editable drafts: subsequent edits, revisions and deletion cannot alter sent history. The existing user predicate remains on both counts and rows, and `created_at DESC, id DESC` breaks timestamp ties. Pages retain the 20-row contract and no longer stop silently at page 500.

The selected thread refreshes sent rows and drafts after an accepted send or confirmed-arrived resolution, and drafts after closing the composer. Older pages append by uid, with a server total and a Load older emails control. Sequence fences discard responses superseded by refresh, person navigation, account changes or unmount. A failed read preserves previously read rows and offers an actionable retry for the same person; it never claims an empty or complete conversation. The account id keys the Email home so another account cannot inherit a conversation's state.

History reads also respect D4665 operation outcomes. Accepted operations read sent; pending and uncertain remain separate from definite refusal, including interrupted pending operations older than D4665's existing timeout. Both the thread and global settings log use the same outcome wording. No delivery adapter, reconciliation policy, read admission, schema binding or deployment configuration is widened.

Validation uses the migrated schema, synthetic people and a non-delivering adapter. Worker cases cover manual sends, AI draft edits/deletion, immutable quotes, invalid/private/mismatched refs, replay identity, same-user migration backfill, 45 tied-timestamp rows across three pages and uncertain delivery. Mounted frontend cases cover both composer payloads, same-person completion, stale page/account/person replies, duplicate uid reconciliation, page counts/end states and failed-read retries. No production content or real mail is used.

The migration is additive; reverting code leaves the association column available. Old unknown history stays unknown, and its global-log row says “Conversation: Not recorded”. Concurrent inserts can shift offset pages; uid reconciliation prevents duplicate display, and send completion restarts from page one. Cursor pagination and reconstructing already-deleted historical associations are outside this existing API contract.
