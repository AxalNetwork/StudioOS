## D6710 — Formation cases offered to partner firms, with a scoped access check (#6710)

Part of #6680 (plan key P2). Builds on the partner registry (D6692), the case
store (D6686), HQ's queue and actions (D6697, D6698) and the people, consent
and screening gates (D6705). Owner decision 4 was answered 4A on #6681.

### What is stored

Migration `202611270444_6710_formation_case_assignments.sql` adds two tables.

- `formation_case_assignments`: one offer of one service on a case to one firm
  (`formation_partner_id`, with the firm's `partners.id` copied beside it,
  which is the id that cases and consents carry). The states are `offered`,
  `accepted`, `declined`, `expired`, `withdrawn` and `completed`. Each row
  records `offered_by`, `expires_at`, `decided_by` and `decided_at` (the firm's
  answer, HQ's withdrawal of an unanswered offer, or NULL for an expiry), and
  `ended_by`, `ended_at` and `end_reason` for an accepted row that ended. A
  partial unique index allows one live (`offered` or `accepted`) row per case
  and service. The issue lists five states. `expired` is a sixth, so that an
  offer nobody answered does not read as one that HQ withdrew.
- `formation_partner_notices`: a deletion or return request recorded for a
  firm whose assignment ended, with `delivery`, `requested_by` and the firm's
  acknowledgement (`acknowledged_by`, `acknowledged_at`). Acknowledgement is
  written by the partner-facing routes in #6711.

### Who may be offered a case

`eligiblePartners` in `services/formationAssignments.ts` lists every firm with
a coverage row for the case's country, form and service. A firm is eligible
only if all of these hold:

- it is verified;
- that coverage row is switched on;
- it holds a licence for the country valid through today;
- it has a signed data agreement;
- none of its restricted places is one of the case's countries. The case's
  countries are the form's country and each current person's country of
  residence.

`restricted_places_json` is free text (D6692). A place that is not a
two-letter country code cannot be compared, so the firm is refused with
`restricted_places_unreadable` until HQ records the place as a code. The
check does not guess what a name means. Eligible firms are ranked by coverage
priority, then by open (offered or accepted) cases, then by measured
turnaround. Turnaround is the mean number of hours from acceptance to
completion over the firm's completed assignments. A firm with no completed
assignment has `null` turnaround ("not recorded"), never 0, and ranks last on
that key.

### HQ routes

The routes are in `routes/admin_formation_cases.ts`. Each one needs
`requireHqAdmin` and is limited to the case's HQ owner or a Super Admin. That
is the same ownership rule as D6698's case actions.

- `GET /:uid/eligible-partners` returns the ranking, with the reason each
  ineligible firm cannot be offered the case.
- `POST /:uid/offer` takes `formation_partner_uid`, an optional `service`
  (default `formation`), optional `expires_in_hours` (1 to 336, default 72)
  and optional `expected_revision`.
- `POST /:uid/reassign` takes the same fields plus a required `reason` and a
  `notice_kind` (`deletion_request` by default, or `return_request`). It also
  needs `requireStepUp`, because it moves a firm's access to personal data.

Both writes check eligibility, then re-screen the case's people with D6705's
`screenFormationCase(env, id, 'offer', actor, revision)`. A write is refused
when the case is held (`case_on_hold`), when the case has no people, or when
the lists cannot be read (`screening_unavailable`, 503). It is not refused
because a list is empty. The write itself is one batch. The batch is guarded
on the case revision that was read and on the firm still being eligible
today. It carries:

- a `formation_case_events` row;
- an `admin_audit_log` row that names the user and the firm;
- an `activity_logs` row through `logAdminAction`.

### Reassignment

A reassignment ends the old firm's access in the same batch:

- its assignment becomes `withdrawn`;
- the case's `partner_id` is cleared, so D6705's `sharingAllowed` fails for it
  at once;
- a deletion or return request is recorded for it.

The new firm receives an offer. Consents name a firm, so the new firm reads no
people or documents until the founder gives a consent naming it. A person's
notice also names a firm, so the new firm needs a new notice. The old firm's
consents are left as they are. They give the old firm nothing, because every
read binds the case's current firm.

### Access check

`canAccessFormationCase(env, user, caseId, now)` returns one of three values:

- `'full'` when the user is partner-licensed, holds a live
  `formation_partner_members` row for a verified firm, and that firm's
  assignment on the open case is accepted. For the formation service, the
  case must also name that firm.
- `'redacted'` when the same holds except that the offer is unanswered and
  unexpired.
- `null` in every other case: another firm's case, a revoked membership, a
  suspended firm, a declined, expired or ended assignment, or a closed case.

People and documents need a second check. `canReadFormationPeople` requires
full access through the formation assignment, then D6705's `sharingAllowed`
for the scope. That covers the firm's consent, the person's notice for this
firm, a clear screening and no hold. The token `canAccessFormationCase` is in
`EVIDENCE_TOKENS` in `scripts/lib/authInventory.mjs`. The partner-facing
routes that call these checks belong to #6711.

### Acceptance and track

`answerOffer` stores the firm's accept or decline. #6711 gives it a route, and
the rule is kept here beside the access check. When the formation service is
accepted, the case's `partner_id` is set to the firm, and a case that is not
yet paid moves to the `v2` track. An offer already needs a v2 case, because
`screenFormationCase` refuses a legacy case. The track statement therefore
changes nothing today. It holds the rule if offers are ever opened to legacy
cases.

### Expiry

The scheduled handler calls `expireOffers` every minute in a bounded batch.
An offer past `expires_at` becomes `expired` and gets a
`partner_offer_expired` event with party `system`. The access check treats an
offer as expired from `expires_at` onward, even before the sweep runs. HQ's
`unassigned` view (D6697) now also holds an open case when, for some service,
the latest offer came back expired or declined and nothing has been offered
since. The queue row carries `partner_offer_returned`.

### Notice wording is pending

Counsel has not approved wording for the request to the old firm. For that
reason `PARTNER_NOTICE_WORDING` is `null`, and each request is recorded with
`delivery = 'awaiting_counsel'`. Nothing is sent. A later change sends
requests only once counsel has approved wording. That change sets `delivery`
and `sent_at` and must not invent the text.

### Retention

Both tables hold firm and case references, user ids and HQ's free-text reason.
They hold no person's data. They follow the case's retention decision, which
is owner decision 14 on #6682 until counsel sets a period.
