## D7903 — Bounded coordinator recovery and executor contract (#7903)

The inactive capacity coordinator accepts only `worker-[1-6]-of-6` on `push`
or `merge_group`, matching the executor. Other CI jobs and PR work remain in
`ci.yml`. Provenance, exact plan, generation, parent and child fencing stay
mandatory; this change enables no routing or production adapter.

A verified terminal external failure with a test step that did not run permits
one hosted fallback. Unknown test truth stays fenced and a real test failure is
sticky. A failed hosted fallback ends in failure, with no further generation.
Reservations subtract only reserved, dispatching, dispatch_unknown and queued
attempts. Running attempts are already represented by busy inventory.

The SQL store refuses a new receipt before exceeding 1,000 retained requests,
both at submission and transactionally at save. Full history cannot stop active
reconciliation. Settled receipts remain for seven days, then submission prunes
them. A request with unresolved children cannot be pruned. Indexed pending rows
replace full-history scans during ticks. Indexed parent high-water marks and
unique child IDs replace repeated scans for supersession and duplicate ownership.
An existing database builds these indexes once, transactionally.

Compact request, parent and child identity tombstones survive full-receipt
retention. They prevent UUID reuse, old-parent revival and reassignment of an
old child. A pruned receipt is unavailable; it cannot manufacture a success.
These compact indexes still grow with historical identities: operational
archival of the fences requires a separately reviewed horizon that cannot
revive an old execution. No D1 migration or remote write is involved.

Validation uses real local SQLite, including a full 1,000-row store, transactional
rollback, restart, fallback, storage retention and preservation of fences.
Live coordinator activation and runner canaries are not claimed.
