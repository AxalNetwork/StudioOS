### 1. The copy

`POST /api/admin/learning/stream/migrations { item_uid }` takes one item per call; the studio loops over items. It is Super Admin only, through `admin_learning.gate`, and the write is recorded.

**Refusals:**
- 503 `stream_unavailable` without the binding;
- 404 for an unknown item;
- 409 `not_r2` when the item is not a video with an uploaded file;
- 409 `already_copied` while a copy of that same file is waiting, processing or ready. An errored copy does not block a retry.

**The call:**
- The Worker mints a source URL, `<origin>/api/learning/stream/source/<token>`.
- It calls `env.STREAM.upload(url, { requireSignedURLs: true, meta: { item_uid, origin: 'r2_copy' } })`.
- If Stream refuses, the answer is 502 `stream_copy_failed` and nothing is recorded.
- Otherwise it writes an `r2_copy` row in `processing` that names the copied file (`source_r2_key`). The item keeps playing its file, and the R2 object is kept.

### 2. The source token

`signSourceToken` / `verifySourceToken`:

- **Payload:** `learning-stream-source|<item uid>|<r2 key>|<exp>`. It is signed with HMAC-SHA256, using a key derived from the purpose and `JWT_SECRET` (`learning-stream-source:<secret>`), and lasts one hour.
- **Two layers of scope:**
  - The purpose is part of the key, so a token another route of this Worker signs with the same secret (`signDownloadToken`, for instance) never verifies.
  - The payload names its purpose, so a token signed with this key for anything else is refused too.

  Each layer is tested on its own.
- **The route** `GET /api/learning/stream/source/:token` takes no session; the token is its only credential.
  - It serves the named object, with Range and `private, no-store`, only while that object is still the item's current upload.
  - A changed upload, another item's object, a tampered or expired token, or any other value is 404, as an unknown path is.
  - The bucket key is never in a URL or a response.

### 3. Verification

D4176's webhook (`applyStatus`) already sets `verified_at` on an `r2_copy` that is ready with a duration above 0. Ready with no duration leaves it "copying".

**This change:** a verified copy moves the item (`stream_uid`, `duration_seconds`, and superseding the item's previous ready video) only while the item still plays the copied object. Without this guard, a copy of a file the item has since replaced would take over the item. Such a copy is verified but plays nothing.

### 4. The sweep

`sweepLearningVideos` runs daily at 03:40 UTC.

**R2 objects:**
- **An object with a copy that is not verified is never deleted,** whatever else is true. The copy may still be fetching it, or may be retried; an errored copy holds its object too.
- **The object an item plays** is deleted once its copy has been verified for `R2_KEPT_AFTER_COPY_DAYS` and the item plays that copy. The item then drops `video_source` and `r2_key` and plays Stream alone.
- **A verified copy the item does not play** leaves the original to D561's usual rules.

**Owner step F** (R2 after a verified copy) is not answered yet. The value is S1's pick (a), 30 days, and it is one constant.

**At Stream** (`sweepStreamVideos`, only when bound):
- it deletes a video superseded for more than `SUPERSEDED_KEPT_DAYS` (30), and an upload link unused past its expiry;
- each is deleted at Stream, then its row and its captions;
- the item's current video is never touched;
- a video Stream says is already gone still closes its row.

Dates are compared through `julianday()`, because the table holds both `datetime('now')` and ISO strings.

The cron line logs counts only.

### 5. The studio's read, and publishing

- **`GET /api/admin/learning/items`** adds `stream_copy` to each uploaded item: `{ state: 'none' | 'copying' | 'verified' | 'failed', stream_uid?, verified_at?, error_code?, error_message? }`.
  - It is read from the newest copy of the file the item plays now, in its own guarded query.
  - L2 (#4177) draws it as Copy to Stream, Copying…, Verified and Copy failed (with the route's words and Try again).
  - The bucket key is never sent.
- **Publishing** now accepts an item whose only video is on Stream. That is all an item has once its copied original has been swept.
