## D8248 — Commit zone: vote words Invest / Pass / Abstain on every IC screen (#8248)

Status: built 2026-11-22 by S04, on the owner's answer A on #6144 (recorded on #6144, 2026-11-22). It closes the "Vote words" departure D6144 lists.

### The decision

Every screen that prints an Investment Committee vote uses the words from the Commit canvas: **Invest / Pass / Abstain**. They replace Yes / No / Abstain everywhere at once, so no two screens disagree. Recused keeps its own word and its ⊘ glyph, and stays apart from Abstain.

Only the words change. The stored values `yes | no | abstain | recused` stay the same, and so does the Worker's contract (`POST /api/ic/:uid/vote`, `cloudflare-worker/src/routes/ic.ts`). `api.icVote` still sends `yes`, `no`, `abstain` or `recused`. The Worker is not changed and no migration is needed.

### One table

`VOTE_WORDS` in `frontend/src/pages/icDecisionModel.js` holds the words: `{ yes: 'Invest', no: 'Pass', abstain: 'Abstain', recused: 'Recused' }`. `voteWord(vote)` returns a stored value's word. A value the table does not know is shown as it is stored, never as a vote word. `tallyText` builds the tally from the same table, for example `Invest 2 · Pass 1 · Abstain 0 · Recused 1`. Every screen reads from this table:

- **Commit card** (`CommitZone.jsx`). The card's own `VOTE_WORDS` keeps its notes and takes its labels from the shared table. The vote marks, the vote table, the close-vote tally and the "How this works" text use the new words. The page's table export names its vote column `Votes (invest/pass/abstain)`.
- **Vote dialogs** (`commit/VoteDialogs.jsx`). The choices read ▲ Invest, ▼ Pass and ○ Abstain. "You voted …" and the Your vote panel use `voteWord`.
- **Decision record** (`ICDecisionPage.jsx`). The buttons read Vote invest, Vote pass and Vote abstain. They are worded apart from the author's invest / pass / defer outcome buttons. The vote list and the tally use the new words.
- **All decisions** (`ICDecisionsPage.jsx`). "My vote" used to print the raw stored value, for example `yes`. It now prints the word.

### Out of scope

The Pipeline board's deal-interest vote (`PipelinePage.jsx`, strong buy and similar) is a different vote with its own vocabulary, so it is not changed. Yes / No answers on other screens are not IC votes. Examples are licence terms, NDA choice and incorporation.

### Tests

`frontend/test/commit_vote_words_8248.test.mjs` covers:

- the three words on each screen (card, dialog, record, list);
- Recused's own word and glyph;
- the stored values sent to `api.icVote` for each choice and for a recusal;
- no screen printing Yes / No as a vote word.

It also pins the words in the sources. The existing tests that expected Yes / No (`ic_decision_pages_6155`, `commit_zone_actions_6144`) now expect the new words.

### Rollback

Revert the PR. The words go back to Yes / No / Abstain. No stored data or Worker behaviour changed.
