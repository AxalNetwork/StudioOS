## D4591 — The hosted schema rehearsal uses throwaway databases and the repository's own provisioning and restore paths (#4591)

- **Status:** built by S05 on `agent/claude-s05/4591-hosted-rehearsal`. The owner approved a hosted rehearsal on 2026-11-09 (option A), and chose a new dispatch-only workflow to run it.
- **Parent:** #4554, audit finding R2-03. Builds on #4852 (the legal-template declarations and clean-rebuild regression), #5133 (`SCHEMA_DRIFT.md`), D4566 (synthetic fixtures) and D4558 (the drill's import path).
- **Migration:** none.

### Context

Contract item 5 of #4591 asks for hosted preview provisioning and a restore rehearsal with synthetic fixtures. It was to use the #4566 preview isolation and the #4558 recovery path. When the owner approved it, three things stood in the way:

- The preview D1 and its KV namespaces were never created. That step is owner-only under #4566, and the config entries are still placeholders.
- The agent session has no Cloudflare credentials.
- None of the existing workflows can run it with synthetic data only:
  - `dr-drill.yml` restores production's backup;
  - `branch-provision.yml` creates a whole subsidiary;
  - `backup-d1.yml` writes into the production backups bucket, which the drill reads.

### Decision

1. **Two throwaway databases per run, never a standing preview database.** `.github/workflows/schema-rehearsal.yml` is dispatch-only. It uses the repository's existing `CLOUDFLARE_API_TOKEN`, scoped to one step. The run creates `studioos-rehearsal-<run>-src` and `-dst` in the EU jurisdiction and deletes both from the script's `finally`, pass or fail. Nothing is left to own, isolate or tear down afterwards.
2. **Provisioning goes through `migrate-d1.mjs` itself.** A new `--rehearsal <run>-(src|dst)` target resolves to `studioos-rehearsal-*` and to a generated `wrangler.rehearsal.<id>.toml` that declares that one database and nothing else. The ids are validated, and the target cannot be combined with `--remote`, `--preview` or `--branch`. The run is `--bootstrap`, then a plain apply, then a `--dry-run` that must report nothing pending. That is the sequence `branch-provision.yml` runs for a branch, so the rehearsal exercises the same code path.
3. **Parity uses the production check's own functions.** The hosted database is compared with a fresh local build of the same files through `check-baseline-drift.mjs`'s exported `buildFresh`, `compareObjects` and `compareColumns`. The comparison covers names and columns in both directions.
4. **Fixtures and restore are reused.**
   - **Fixtures:** #4566's `seedStatements` and `toSqlFile`. Every address is `@synthetic.invalid`.
   - **Restore:** the D4558 drill's `dr-drill-split.mjs`, importing one chunk per execute, as the drill does.
   - **Comparison after the restore:** every object's SQL, every table's row count (one row of scalar subqueries per 50 tables: D1 refuses even a six-term compound SELECT, and any row over 100 columns), and `PRAGMA foreign_key_check`.
5. **Evidence is counts and verdicts only.** The step summary and the artifact `schema-rehearsal-summary` hold names, counts, durations and the verdict. Wrangler output that could quote SQL is withheld, and only its error codes are printed.
6. **`--local` proves the script without the account.** It runs the same steps against wrangler's local D1 and labels the result `local`. It is never reported as a hosted run.

### What the first local runs found

Each finding below was fixed before the first hosted run.

- **D1 refuses compound SELECTs.** A count over the tables with `UNION ALL` fails on D1 at six terms ("too many terms in compound SELECT"), and a result row over 100 columns fails too. Counts are therefore one row of scalar subqueries per 50 tables.
- **The restore path drops SQL comments inside `CREATE TABLE` text.** SQLite stores that text as written, but the text that comes back after export, split and import has no comments. Columns, types, defaults, constraints and appended columns are the same. The comparison therefore strips comments outside quotes and compares the rest. A changed default, or a `--` inside a quoted value, is still a difference.
- **The full local run.** `node scripts/schema-rehearsal.mjs --local` got through:
  - provisioning: 2,739 objects, with no parity difference against the committed files;
  - seeding;
  - export: 1,059 tables and 21,409 rows;
  - restore: 15 chunks.

  The restored database matches the source on every object's SQL (comments aside), every table's row count, and foreign keys. Provisioning took about 35 minutes locally.

### What it does not prove

- It reads no production data, so it does not show that production's backup restores. That is the monthly `dr-drill.yml`.
- It is not a Time Travel restore.
