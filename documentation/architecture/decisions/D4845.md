## D4845 — Offers: responsive and accessibility QA across the six zones (#4845)

- **Status:** built (#4845, Offers UI/UX audit 5 of 5). Checks the Offers v2 canvas (`design/incoming/Offers v2 Page.dc.html`, D4872) boards OF-08 (states), OF-09 (phone) and OF-10 (accessibility rules) against Catalog, Perk deals, Proof, Visibility, Audience fit and Product testing, and the `/offers` overview (OF-01). Builds on D4841 to D4844 and #5129's state vocabulary (D5129). Mints no route, no API method and no store.
- **Ownership kept:** #4836 owns the Audience fit pass-reason overlay (`PassReasons`), the two Perks overlays (`ClaimModal`, `ExtendModal`) and their keyboard journeys. None of them is edited here; the contrast check in the test skips `PassReasons`.

### What changed

- **Zone navigation (OF-09a, OF-10).** Below 640px the grouped Offers row is one full-width 44px button that names the bucket and the current zone ("Offers · Proof ▾"). It opens, in the page's flow, Overview and each group under its visible label (`role="group"` named by that label), every entry a 44px link with `aria-current` on the current one. Escape closes it and puts focus back on the button; choosing a zone closes it. From 640px the grouped row is drawn as before, its pills and group labels at 12px (were 11px and 10px). Only a bucket that declares `groups` (Offers alone) draws this; every other row is unchanged.
- **Failed reads (OF-08; #4844's two follow-ups).** Visibility now passes `what` to `ZoneBody`, so its loading and failed states are #5129's `SectionState` (announced loading, Unavailable with Try again) instead of the older "This did not load" card. Proof, Audience fit, Visibility and Product testing keep `zoneReadError(e)` as the zone's error: the no-firm refusal stays as it came (so `NoPartnerProfile` still draws), and any other failure becomes `readFailureText`'s written sentence ("Nothing here is out of date; it just isn’t shown.", or a session, permission, rate or connection sentence). The response's own text, including Product testing's raw server message, no longer reaches the page.
- **Failed save.** Product testing's Submit for approval says "<name> was not sent to HQ." with `writeFailureText`'s fixed sentence, not the response's text. `WriteNote`'s Retry and Reload use the Offers ghost action (44px on a phone, focus ring).
- **Stacked records on a phone (OF-09, OF-10).** Visibility's attribution table is a table from 640px and a list of labelled records below it, each select full width and named "Where <engagement> came from" (the select had no name). Perk lifecycle passes a new opt-in `stack` to the shared `Instrument` (`workspaces/canvasKit.jsx`): below 640px each perk is a record with its cells under the column names, instead of a 640px grid scrolled sideways. Without `stack` nothing changes for the other callers. Header cells in Visibility's attribution table carry `scope="col"`.
- **Keyboard.** Catalog's row menu (⋯) is a menu button: `aria-haspopup="menu"`, focus moves to the first item on open, ArrowDown/ArrowUp (wrapping), Home and End move, Escape closes and returns focus to ⋯, Tab closes. Each item is 44px on a phone with the amber focus ring. Each row's Edit is named "Edit <service>".
- **Targets (OF-10).** `offerButtonClass`, the zone's one primary, is 48px below 640px (was 44px); every other Offers action and field stays 44px. The shared `Sheet`'s × is 44px below 640px and draws a focus ring (a class change only; the Sheet's behaviour is untouched). The overview's Try again links and zone preview links are 44px below 1024px.
- **Type and contrast (OF-10).** `text-axal-faint` (#a1a1aa, 2.6:1 on white) is gone from the Offers zone files and from the partner kit's `NotComputable` and `NoPartnerProfile`, replaced by gray-600 (7.6:1) with a gray-400 dark pair, and both are now 12px or more. Visibility's caption, table heads, meta and foot lines and the overview's group labels are 12px or more. Visibility's heading and empty state use the Offers `OfferHeading` and `OfferEmpty`, and its controls the Offers input and action classes.

### Departures from the canvas

- OF-09a draws the switcher as `aria-haspopup="listbox"`. It is built as a disclosure of links: every entry is a route, and a listbox would hide that from a screen reader and break middle-click and Copy link.
- OF-08's "Proof couldn’t be loaded." headline is #5129's Unavailable chip and sentence, as D4844 already drew Proof, Audience fit and Testing; Visibility now matches them.

### Verification

`frontend/test/offers_responsive_a11y_4845.test.mjs` (18 tests) pins the rendering as markup and classes, with no screenshot harness: the switcher's phone-only classes, 44px height, name and dark pair; the grouped row's 640px breakpoint and 12px type; the mounted switcher's links, one `aria-current`, labelled groups, Escape and focus return; the failed read of all four zones (Unavailable, announced, the written sentence, Try again, no response text, not the empty state, not the older card); the unlinked line; Visibility's announced loading; the refused Submit; Visibility's attribution records, named selects and `th scope`; Perk lifecycle's records and the opt-in; no sideways-scrolling table in the zone files; the Catalog menu's keyboard journey; the 48px and 44px targets and the Sheet's ×; no text under 12px or in `axal-faint` in the zone files, with the greys' contrast computed; heading order (h2 first, no skipped level) on populated Proof, Audience fit, Product testing and Visibility. Mutation check on that file: 39 mutations, 38 caught, 1 equivalent (`aria-current` on the switcher's links is written by react-router's NavLink only while its own route matches).

What was checked by reading the code rather than by a test: the Proof cards at one column below 768px, Audience fit's rules table becoming records below 768px, Catalog's table becoming cards below 640px, Product testing's lifecycle folding to a status chip with a full-width next action on a phone, the Sheet as a full-screen page below 640px (`sheet.css`), the overview's two-column figures and full-width first action on a phone, and Tab order following source order in every zone. No browser, screen reader or rendered contrast audit was run, so this is not a WCAG 2.2 AA conformance claim for the Offers family.
