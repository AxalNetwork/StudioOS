### 1. "Set up your practice" (PX-01)

`pages/advisor/practice/practiceSetup.js` and `PracticeSetup.jsx`. Each of the five steps is a recorded fact:

| Step | Done when | Read |
| --- | --- | --- |
| Practice profile | the advisor profile has a display name (a 404 is "not done") | `GET /advisors/me` |
| Create a service or session type | an active session type exists | `GET /advisors/me/session-types` |
| Set availability | an upcoming slot is unblocked with a seat left | `GET /advisors/me/slots?days=60` |
| Create a booking link | an active booking link exists | `GET /advisors/me/booking-links` |
| Set payout details | the payout account has payouts enabled | `GET /advisors/me/payout-account` |

- Payout is a step because the backend records it (`advisor_payout_accounts`, migration 241), as S1's plan requires.
- The card says "n of 5 complete". The **one** primary action is the next missing step, and it links to the editor for that step: `/expertise/profile`, `/practice/sessions#session-types`, `#publish-availability`, `#booking-links` or `/practice/earnings`. Below it, PX-01's five-line "What happens next".
- **A failed read** is "Could not be read · Try again": neither ticked nor counted.
- **It takes the board's place** while at least one step is known to be missing. This replaces the five separate empty cards the 2026-11-07 live audit found. Once every step is done, or none can be known because the reads failed, the board shows as before; its sections say what could not be read.
- **Mechanism:** `BucketBoard` gains an optional `board.lead` component, given the sections as `fallback`. The Practice board names `PracticeSetup`. No other board sets one.

### 2. Opportunities (PX-02, PX-02b)

- **Header (PX-02):** "Everything asking for your time, before it becomes committed work.", with **Share booking link** (`/practice/sessions#booking-links`) and **Set availability** (`#publish-availability`).
- **Request card:** adds the session length and, in words, "Awaiting you · waiting 2 days" (never colour alone). **Decline…** now carries `aria-expanded` for the reason form it opens.
- **Empty state (PX-02b):** "No requests yet". The line is "Publish a booking link or share your advisor profile to receive requests." The actions are Create booking link and, when the advisor's uid is known, **Preview profile**. Preview profile opens the public `/advisors/:uid`, never the editor (the confusion #4823 recorded). The zone reads `GET /advisors/me` for the uid, optionally: without it the link is left out.
- **Kept from D4702 / D4714:** the decision log keeps the advisor's answer separate from a later cancellation. An accepted request the client cancelled is still Accepted; a client withdrawal is never a Decline. That is the resolved history PX-02 asks for.

### Where this departs from the canvas

- **Filter chips.** PX-02 draws Awaiting decision · Accepted · Declined · Cancelled · All, with counts. The chips stay the registry's (Awaiting decision · Accepted · Declined · Expired · All time): `advisorZoneFilters.js` is pinned verbatim to the Advisor Detail canvas by its guard, and moving that guard to Practice v2 is the shell's (#4829). Expired is also a recorded, derived state that PX-02 does not draw.
- **Open client.** PX-02's card has Open client, which opens the shared Client Sheet built in #4831. It is not drawn here until that sheet exists.
