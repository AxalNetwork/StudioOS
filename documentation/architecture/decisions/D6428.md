## D6428 — File recovery uses approved append-only snapshots, not R2 versioning (#6428)

R2 has no versioning or dashboard restore of prior object versions. The two
file rows and setup steps in INCIDENT_RESPONSE.md now describe a real,
checksum-verified append-only copy into a private `files-recovery/` archive
prefix. This implementation changes no live bucket policy or production file.

The owner's direction (#6652 A) limits locked copies to record classes with
an approved legal retention basis. There are no default KYC or contract
prefixes: #6650 supplies the registry, #6651 supplies write-once record keys,
#6654 supplies live suppression-ledger integration and #6653 owns the later
independent copy/missed-run alert. Personal files without an approved basis
stay out. The daily workflow remains disabled until the operator enables its
repository variable after approval and configuration.

The standard-library Python copy tool accepts only `studioos-files` record
classes marked `locked_copy: yes` with a recorded `retention_basis` and the
approved duration; other classes stay out. It consumes the reviewed registry and
verifies the actual destination-prefix lock through the Cloudflare API. It
requires the approved 2557-day retention, refusing missing, shorter,
indefinite or longer overlapping locks. Existing D1/KV retention is not
changed. Private S3 credentials are step-scoped; no data, keys, manifests or
credentials are printed or published as artifacts.

Each run lists only approved prefixes, conditions reads on the listed ETag,
writes unique immutable archive keys with If-None-Match, reads each copy back
and checks SHA-256 before committing its manifest. A partial copy has no
completed manifest. This captures observed objects, not continuous version
history: writes overwritten or deleted before capture are not recoverable.
No live protection, successful live run or off-account copy is claimed.

Restore requires a suppression-check callback with an explicit restore or
suppress decision for each object. Missing/incomplete ledger access fails
closed, and suppressed objects are not fetched. Live restore has no CLI
entry point until #6654 supplies its current-ledger adapter. Restored files
use hashed filenames in a fresh private staging directory and are checksum
verified. The synthetic-only drill exercises source loss, verified restore
and suppression without any provider access or production content.
