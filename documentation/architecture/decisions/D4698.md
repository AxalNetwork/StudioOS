## D4698 — Delivery zones keep populated content mounted and close an editor only on a confirmed save (#4698)

- **Status:** Built for #4698, 2026-11-07. Frontend only.
- **Builds on:**
  - #4673 (a composed report belongs to its engagement and period);
  - D637 (the partner's delivery edits).
- **No migration, no Worker change.** The create routes for deliverables and seats never refused an empty store; the forms were simply not drawn there.

### What was decided

1. **The skeleton belongs to the first read.**
   - Every Delivery zone set `loading: true` on each reload, and `ZoneBody` answers `loading` with a skeleton in place of its children. Saving one record unmounted every open editor and discarded what was typed in it.
   - `useZoneRead` (`pages/partner/delivery/useZoneMutations.js`) shows the skeleton once. A later read marks the body `aria-busy`, keeps the rows, and if it fails keeps them too and announces that they may be out of date. A response that lands after a newer read began is dropped.
2. **A write is tracked by key, before its request starts.**
   - `useMutations().run(key, fn)` writes the key into a ref synchronously, so two clicks in one frame cannot both start. A second start on the same key is refused; different rows use different keys and are independent.
   - It resolves `{ ok }` and never throws. A form resets, and an editor closes, only on `ok`; a refusal leaves every value as typed and is announced with `role="alert"` (`role="status"` for a success, in `SaveNote`).
   - A pending button uses `aria-disabled`, not `disabled`, so keyboard focus stays where it was.
3. **First records are written from the empty state.** The empty Deliverables state holds the log form. The empty Capacity state holds the seat form and the cap, internal-hours and client-hours forms.
4. **A draft is re-seeded when its own record changes.** Drafts were reset on every refetch because they keyed on the row object; they now key on the record's saved values.
5. **The selected chip governs the cards.** Status reports and Health drew every record whatever chip was chosen, with Mark sent, Discard and Record on rows the chip had excluded. They draw the same set as the table and the export.
6. **Edit binds to the report pressed.** The card hands its own engagement and period to the composer, which sets both selectors and composes exactly that pair.

### Not changed

- "Not recorded" and "Unreadable" stay as they were. A store that could not be read still never offers a form and never reads as empty.
- The transitions, invoicing and operational-measurement work of the earlier packages (#4682, #4690) is untouched.
