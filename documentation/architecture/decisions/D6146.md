## D6146 — Recorded history in the deal-flow peek (#6146)

The DLS7 peek gains the issue's requested collapsed History section. It reads
`dealFlowApi.events` only when opened, and only for a row in the firm's flow.
Every returned event is shown newest first with its recorded actor/time;
missing fields say Not recorded. Entered, move, pass, owner and note changes
get plain words; unrecognized kinds remain visible rather than disappearing.

The current row's pass rule/date is labeled Current pass, separate from the
events: the events endpoint does not record historical return dates. The
caller passes that already-read row field directly, leaving `flowModel.js`
(which #6300 owns) unchanged. No extra flow read is needed. Loading, empty
and unreadable/retry states belong to History and preserve the rest of the
peek. Cleanup and a deal-specific key prevent stale responses crossing deals.

This small section extends DLS7 as explicitly requested by #6146; it adds no
new screen, route, Worker behavior, write, score inference or permission.
Tests cover event words, chronology, lazy reads, every state, outside-flow
visibility, stale responses and the existing mounted peek regressions.
