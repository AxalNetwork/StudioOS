## D5074 part 4 — Capital relationships' controls from the Worker's capability map (#5074)

Part 1 and 2 are `D5074.md`; part 3 (`D5074-p3.md`) is the Investor narrative. This part moves Capital relationships onto the same pattern.

`cloudflare-worker/src/services/capRelCapabilities.ts` computes Capital relationships' capabilities once, from who the caller is on the venture (`capRelStanding`: staff, and `capitalCanWork`, the owner or an accepted co-founder):

| Capability | Owner, co-founder | Staff (admin, the Super Admin on HQ) | Investor, advisor, anyone else | The request it governs |
| --- | --- | --- | --- | --- |
| `work` | yes | no | no | every capital request: the pipeline, Calls, Match and its rank, Outreach, Commitments, Activity, Closing and the prospects (403 `Forbidden` otherwise; staff get `support_read_required` or `admin_read_only`, as before) |
| `support_reads` | yes | no | no | `GET /capital-relationships/support-reads`, the founder's list of who read with a reason (D1464) |
| `support_read` | no | yes | no | `POST /capital-relationships/support-read`, the reasoned read-only view (403 `admin_required` otherwise) |
| `admin_reason_required` | no | yes | no | staff's view opens only with a reason the founder sees |

- **The read carries it.** The module read (`GET /api/cycles/raise/modules/capital-relationships`) returns `capabilities` in both its modes: the working read for the owner and co-founders, and the counts-only summary for staff. An investor, an advisor, a removed co-founder or another founder is refused as before, with no map. A support session is refused before any map (`support_session_refused`).
- **The requests ask the same function.** `scope` in `routes/cycle_raise.ts` builds the map once for every capital path. Staff's requests are still limited to the summary read and the support read (`capitalStaffRequestAllowed`), and everyone else's are refused outside `work`. The route no longer calls `capitalCanWork` itself. The support read refuses outside `support_read`, and the founder's reads list refuses outside `support_reads`.
- **The page renders from it.** `capRelStanding(capabilities)` (`capRelModel.js`) reads only the map. `CapRelTabPage` reads the module read once and draws staff's support gate exactly when the map says `support_read` and `admin_reason_required`, on every tab. Otherwise it draws the founder's tabs. Activity draws the reasoned-reads card exactly when the map says `support_reads`. The account's admin flag from `CycleRoute` opens only the support door, and only when the read was refused and so carries no map. That door grants nothing by itself, because the Worker gates the support read. When the map and the account disagree, the map wins. Staff's only read before a reason is the counts-only summary, which names no investor.
- **The venture comes from the route helpers.** `tabSearch` is `ventureSearch(ventureRef(search))`, so a link names its venture as `?project_id=` only. `CapRelMovedRedirect` stays the input-compatibility redirect for the old addresses.
- **Tests.** `cloudflare-worker/test/caprel_capabilities_5074.test.ts` checks the pure map, and pins it to the frontend mirror (`frontend/test/_caprel_capabilities.mjs`). Over HTTP, on the full schema:
  - The founder owner, a member owner and an accepted co-founder get the worker's map: a tab's read and the reads list answer, and the support read is refused `admin_required`.
  - An admin and the Super Admin get the summary with staff's map: the support read answers, a tab's read is refused `support_read_required`, and the reads list is refused.
  - An advisor, an investor-licence member, a removed co-founder and another founder read no map. A support session is refused before one.
  - A source scan pins `scope` and the two support routes to the map.

  `frontend/test/caprel_capabilities_5074.test.mjs` checks that staff's map draws the gate on every tab whatever the account says, with only the summary read before a reason, and that the worker's map never draws it. It also covers a refused read, Activity's card, the link form, and that no page decides the view from the account. `reason_gate_per_open_d1464` serves staff's map with the summary.
