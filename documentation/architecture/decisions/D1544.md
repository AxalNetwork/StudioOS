## D1544 — Deck v2 B8: image edits as child images, and the deck's art direction

Issue #3784 (deck builder v2, B8). Migration 735. Built in slot S13 on
2026-11-02, taken from `state:blocked` at the owner's request while owner
decisions P and X are still open.

### What was decided

**An edit of a deck image is a child image.** Four edits, each made from one
`deck_images` row (the parent) and stored as a new proposed row that names it
(`parent_uid`, `edit_op`, migration 735):

| Op | What the model is asked | References sent |
|---|---|---|
| `vary` | the same subject, style and palette in a new composition | the parent |
| `edit` | the founder's instruction (at most 400 characters), everything else kept | the parent |
| `erase` | remove what the mask marks in white and fill it to match | the parent, then the mask (a PNG at most 512 by 512) |
| `expand` | continue the scene outward to the chosen frame (`aspect`) | the parent |

- **The parent never changes.** Revert (`POST /api/decks/images/:uid/revert`)
  discards the child and answers the parent as it was. Nothing reaches a card
  until the founder keeps the child and saves the version, as for any image.
- **The model is D1478's DK5** ("Edit this image or restyle it to the brand"):
  FLUX.2 Klein 4B by default, the member's DK5 pick when DK5 lists it, no
  fallback. Klein 4B is a partner model on a paid plan, so with the partner
  switch off or a free plan the edit is not offered (`model_not_offered`).
  Legal's hold already clears Klein 4B (D1478, D (a)).
- **One exception:** a vary of a drawn image whose DK5 cannot run redraws the
  parent's own description on DK4 (the deck's image job, FLUX.1 Schnell) with a
  new seed. It needs no reference, and the reply says `redraw: true`.
- **The hold includes the input images.** FLUX.2 bills each reference image
  (D1478 #3935's `imageUnits`), so the quote is taken with the references the
  run will send, and one hold covers the edit and its three post-draw checks
  (`drawPressQuote`). An erase holds more than an edit of the same image: its
  mask is a second input.

**The parent is resized through Cloudflare Images (the owner's choice,
2026-11-02).** FLUX.2 takes reference images each at most 512 by 512; a deck
image is usually 1024 by 768. The Worker had no way to resize an image, so a
new `[images]` binding (`IMAGES`, both env blocks in `wrangler.toml`, and the
binding-parity guard knows the table) scales the parent down to fit 512 by 512
as JPEG before the quote. An image that already fits is sent as it is. Without
the binding an edit answers 503 `resize_unavailable` and runs nothing. Images
transformations are billed per unique transform beyond Cloudflare's free
monthly allowance, and the account must have Images enabled before deploy.

**Never a person.** Eadwyn never draws a real person (#2434 owner question 7,
A). A photo of a person is an upload with that person's agreement recorded, and
the agreement covers the photo, not a drawn change to it, so:
- an image that shows a person (`shows_person = 1`) is never edited:
  422 `person_edit_refused`, before any quote, hold or run;
- an instruction that asks for a person (a face word, or a founder's or the
  venture's name) is 422 `real_person`; a figure or a chart is refused as for a
  drawn image;
- the result is checked like every draw (`postDrawCheck`): a face is
  422 `real_person` and nothing is stored.

A consented edit of a person's photo would need its own owner decision and a
`deck_images` rebuild, because the table's checks forbid a generated row that
shows a person. It is not built.

**The deck's art direction.** `theme.art_direction` (kept on each version) is
either D1500's sentence or an object `{ style, palette, seed_base,
reference_uid, note }` (`services/decks/artDirection.ts`). Every image request
on the deck inherits it:
- a request's own style or palette wins; anything it leaves out comes from the
  direction;
- image n of a run draws with seed `seed_base + n`, so a deck's images share a
  seed family;
- the note goes into every prompt, and into every edit's prompt;
- the reference image (a kept image of the venture that shows no person) is
  sent to a model that takes references, resized like a parent and priced in
  the hold; a model that takes none draws without it.

**The studio.** The adapter's `imageVary` (#3784) prices an edit through
`deckImageEditsApi.quote` and is swapped, with its contract
(`deckImageVary.schema.json`) checked against the route's real replies. "Edit
or vary" in the element picker is re-keyed from #3778 to #3784; background
removal and upscale stay #3778's `imageEdit`, as do crop, focus and filters.
The image lightbox's references line follows the quoted model: a FLUX.2 model
reads "takes up to 4 reference images", FLUX.1 Schnell keeps "takes no
reference images".

### Not built

- **The one-click style-consistency check** before a run's images are shown
  (dk-auto gap d, with #3756 and #3799). The run inherits the art direction;
  the check that compares the images is the critique's to build.
- **Pickers for references in the lightbox and the pd7 Brand kit "Reference
  images ×3".** No board draws them as a working control and the spec builds
  no new UI; the art direction's `reference_uid` is set through the theme.
- **Partner models beyond Klein 4B** in the AIRail Images group: owner
  decisions P and X are still open, and Legal's hold stands.
- **A consented edit of a person's photo** (above).

### Coordination with #3778

#3778 owns crop, focus, filters, upscale and background removal on the same
pd27 panel. This decision moves only "Edit or vary" (erase, expand, vary and
edit) to #3784's key and leaves #3778's rows and its `imageEdit` adapter key
as they were, so the two PRs do not touch the same rows of `deckV2Model.js`.
