## D659 — The Validate stores and the shared cycle read, `/api/cycles/validate` (migration 440)

**The Validate cycle's overview and its six module pages read one Worker
route, `/api/cycles/validate`, in the shape #1469 (D656) fixed for all four
cycles. Migration 440 adds the records the six modules had no home for. Every
figure, card, status, share and `next` line is computed at read time from
records and stored nowhere. The Spin-Out Lab's discovery figures are computed
by the same read.** Issue #1472, part of #1469. Canvases:
`design/incoming/Cycle Overview.dc.html` (cycle Validate; boards O1, O1n, O5)
and `design/incoming/Cycle Modules · Boards.dc.html` (MV1–MV6).

### The read

```
GET /api/cycles/validate/overview?project=:pid
→ { cycle: 'validate', question, figures: [Figure ×4], cards: [Card ×6] }
GET /api/cycles/validate/modules/:slug?project=:pid&q=&filter=&sort=&page=
→ { module, card: Card, records: { cols, rows, total, page, page_size } }
```

`services/cycleCards.ts` holds `Figure`, `Card`, the five states and
`safeCard` / `safeFigure`. Validate is the first cycle task to merge, so it
created the file; Build, Raise and Grow (#1475–#1477) import it.

- **Each card fails on its own.** Every card loads its own rows with no
  `.catch` that turns a failure into an empty read. A throw reaches
  `safeCard`, which makes that one card `unreadable` and names its source.
  The older loaders swallow errors (`loadPainGroupModel`,
  `getPainGroupsView`). They now take `{ strict: true }`, which this read
  uses. Their other callers keep the default.
- **A missing value is `null` with a reason, never 0.** A figure with no
  records is `empty` with `value: null`. A TAM nobody entered is
  `{ value: null, reason: 'No figure entered' }`. A need-to-have share with no
  judged pain is `null` with its reason. The change in supported claims over
  30 days is `null` until the verdict history covers 30 days.
- **`too_little` is fewer than three points.** `seriesState` counts recorded
  points. `countState` counts records for cards drawn one bar per record
  (themes, segments, claims). A sparkline is `[]` under three points.
- **`next` is counted, not templated.** For example: "Book the 2 invited
  leads with no slot yet", "Interview 2 more people from Ops leads", "Confirm
  the 1 signal waiting". A new venture gets the canvas's one starting action
  on every card (O1n).
- **Weekly series are bucketed in SQL**: held interviews, customer-waitlist
  sign-ups and evidence links per week. The customer-research records page in
  SQL with every filter bound. The other module tables are a project's own
  themes, segments or claims. They are filtered and paged after the one read
  that computes them.
- **Who.** Reading is `canReadBoard`: the venture's own (an admitted Lab
  member on their own project included), admins and partners. It is the
  founder board's audience, because every card is derived from the interviews
  they may already read. Writing is `canWrite`. An investor reaches nothing.

Module slugs: `problem-discovery`, `customer-research`,
`ideal-customer-profile`, `market-intelligence`, `demand-signals`,
`experiments`. These follow #1474's own examples (`/validate/problem-discovery`,
`/validate/experiments`).

### Migration 440

| Gap in #1472 | Store |
| --- | --- |
| No segment on an interview | `customer_segments` (unique per project and normalised name), `discovery_interviews.segment_id` |
| No Booked / Done | `discovery_interviews.stage` (lead / invited / booked / done), `invited_at`, `booked_at`, `done_at`, `channel` |
| Severity has two values | No column: Severe / Real / Mild are new values of `interview_pain_severities.severity` |
| No LOI or pre-sale record | `demand_signals` (loi / pre_sale / waitlist / need_to_have / would_pay; who, amount in cents, currency, period, date; confirmed / counted / to_confirm; source manual / interview / session) |
| No waitlist target key | No column: the `waitlist_target` key of `metric_targets` |
| `competitor_signals` has no project and no source | `competitor_signals.project_id`, `source_url`, `source_kind`, `observed_on` (also in `competitorSchema.ts`'s runtime CREATE) |
| No Inconclusive, no sprint or owner | `hypotheses.sprint`, `owner_user_id`, `inconclusive_at` |
| No strength per evidence item | `hypothesis_pain_links.strength` (anecdote / pattern / measured) |
| Three Lab market checks in browser state | `market_readiness_marks` (positioning_map, assumptions_reviewed), `market_sources` |

Every new column is nullable, and NULL is "not recorded". Nothing is
backfilled.

### Decisions inside the issue's words

- **Old severities.** A `need` reads as Severe and a `nice` as Mild. The two
  old values were the ends of the scale, and Real is the level between them
  that the old form could not express. No row is rewritten. The old two-count
  view counts Severe and Real as a need and Mild as a nice-to-have, so a
  three-level judgement does not disappear from the pages that read
  `need_count`. The severity PUT accepts both vocabularies. The Lab page's
  modal still writes need / nice, so D351's "never a third stored band" still
  holds for that page. It no longer holds for the store.
- **A stage-less interview is done.** It was logged before stages existed,
  and the log form records a conversation that already happened. A lead, an
  invitation or a booking is not "held". Held interviews are the only ones in
  the weekly chart, the interviews figure and the segment counts.
- **Inconclusive sits under the computed verdict.** Supported and Refuted
  stay the founder board's computed verdict (`_founder_validate_helpers.ts`,
  bar of five). A founder's Inconclusive mark shows only while the evidence
  decides nothing. If the evidence later decides the claim, the claim leaves
  Inconclusive with no write.
- **Segment evidence stops at Pattern.** It is Anecdote under three held
  interviews and Pattern from three. Measured needs a measured signal tied to
  a segment, and no store links a signal or a payment to a segment yet.
- **The first segment** is copied once from the project's *confirmed* ICP
  definition (persona · industry) by the ICP card's read. A draft seeds
  nothing. This is the only write a read makes, and it copies only the
  founder's own words.
- **The waitlist bar** is written only by this route's writer. The Grow
  targets view (`GET /progress/metrics/:pid/targets`) leaves it out: it is
  read against sign-ups, not a snapshot.
- **`would_pay`** is a demand kind beside the canvas's four, because #1471's
  interview proposals name it.
- **TAM, SAM and SOM have no source store.** The sourced fill writes the
  sizing *inputs*, not the three figures. The market card says "No source
  recorded for this figure" rather than guessing one.
- **A paid deposit or pilot is a pre-sale.** It is read from
  `revenue_entries` and never copied into `demand_signals`.

### The writers (#1471)

`services/validateWriters.ts` has one function per record: `writeSegment`,
`assignInterviewSegment`, `setInterviewStage`, `writeDemandSignal`,
`setDemandSignalStatus`, `setWaitlistTarget`, `writeCompetitorMention`,
`setMarketMark`, `addMarketSource`, `removeMarketSource`,
`setHypothesisPlan` and `setEvidenceStrength`. The manual routes call them.
#1471's accept path calls `writeSegment`, `writeDemandSignal` and
`writeCompetitorMention`. Each writer validates its own values against a
fixed list, binds every one, and records its actor in `activity_logs`. A
signal typed into the form is `manual` and confirmed. A proposed one arrives
`to_confirm` and is not counted until the founder confirms it. The manual
route sets `source_kind` itself, so a client cannot claim an interview
source. A competitor mention lands on the project's own competitor list
through `insertManualCandidate`. With no list it refuses (409), as the
competitor fill does.

### The Spin-Out Lab

The Lab discovery page's funnel, four-item readiness and claim counts moved
into `frontend/src/lib/labDiscovery.js`, unchanged. `labDiscovery` in
`services/cycleValidate.ts` computes them for the cycle read. The test reads
`/api/cycles/validate` as an admitted Lab member and requires the same funnel,
readiness and counts that `labDiscoveryCounts` gives from the same rows.
The Lab market page reads and writes its three stored checks through
`GET /market-readiness`, `PUT /market-marks/:item` and `/market-sources`. It
no longer ticks a check it could not read. "Not saved yet" now marks only a
source whose save failed.
