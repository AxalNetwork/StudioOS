## D5532 part 2 — The production Worker uploads no source maps (#5532)

- **Status:** built 2026-11-15 by S25, the owner's option A.
- **Code:** `wrangler.toml`, a top-level `upload_source_maps = false`.
- **Test:** `cloudflare-worker/test/worker_source_maps_5532.test.mjs`.

### The rejection was source-map size, not startup CPU

From 2026-11-13 13:48 UTC on, no production publish succeeded. Every run of
`cloudflare-worker-deploy.yml` that reached "Deploy to Cloudflare Worker"
failed with this message:

```text
total sourcemap size is too large, must not exceed 15 MiB when gzipped (received 56290 KiB / 15447 KiB gzipped) [code: 10021]
```

Cloudflare uses code 10021 for this and for "Script startup exceeded CPU time
limit", so part 1 read these failures as the startup problem it profiles.
They were not. The script itself was 17.7 MB, 5.0 MB gzipped, and passed. Its
source map was 58.6 MB, about 15.1 MiB gzipped, just over the limit.

### Why the maps were uploaded

Neither `wrangler.toml` nor the deploy workflow asked for source maps.
Wrangler 4.156.1, the locked version, uploads them anyway when the key is
unset. Its deploy bundle step is
`uploadSourceMaps === false ? void 0 : loadSourceMaps(…)`: only an explicit
`false` skips them, and an unset key loads them in non-strict mode. A local
`wrangler deploy --dry-run --env production --outdir` on `main` `70b35afe84`
wrote `index.js.map` (58,575,661 bytes) without the key and no map with it.

### The rule

`upload_source_maps = false` sits at the top level, beside `minify`. It is an
inheritable key, so `--env production` gets it without a second copy. The
test fails if the key is missing or not at the top level, if any line sets it
to anything but `false`, or if the deploy workflow passes
`--upload-source-maps`. It also reads the installed Wrangler for the two lines
this behaviour depends on, so a Wrangler upgrade that changes the default
fails the test instead of the publish.

Stack traces in Workers logs now show minified positions. That is the cost.
Uploading maps again needs either a map under 15 MiB gzipped or a separate,
explicit decision.

### Not changed

Part 1's startup profiler, its admission contract and its open question are
unchanged. The 2026-11-13 rejection of `86a53d83` reported "Script startup
exceeded CPU time limit", which is a real startup rejection, and that is
still #5532's open question.
