## D623 — Only the author or a Super Admin edits a review comment's text

**Changing the text of an article review comment is the author's, or a Super Admin's. Resolving it stays any admin's.** Issue #1344. No migration. Follows D617, which says the same about deleting one.

**The text.** `PUT /api/admin/articles/comments/:cid` may set `body` only when the caller wrote the comment or is a Super Admin. Anyone else gets 403 `not_your_comment`, and the row does not change, including a resolve sent in the same request. An unknown id gets 404 `comment_not_found`. An empty or whitespace-only body gets 400 `empty`, the same refusal as creating a comment, and nothing is written. Sending the text it already has is not an edit.

**The audit.** A Super Admin who changes another admin's text is logged with `logAdminAction` as `article_comment_edited`, with `article_id` and `comment_id` only. The text is not in the row. The author editing their own comment, including a Super Admin editing their own, is not logged.

**Resolving.** `resolved: true` or `resolved: false` stays open to any admin. That is how review works. It is not an audit event.

Nothing here locks the comment. D617's delete rule is unchanged.
