## D4580 — Verify the Grow authentication return journey (#4580)

### Reproduced and fixed

At main `1fc4b8f17d`, clicking the sign-in email button with `bad-address`
called `/api/auth/magic/start` and left `aria-invalid` unset. Registration's
native email validation stopped the form before its associated error could
render. These were reproduced in Chromium against local Vite with synthetic
API responses and inspected at 1440px and 390px.

Sign-in now checks the same email shape as registration before either email
or authenticator submission. Registration lets its existing validation handle
the primary form, so malformed input gets the visible alert, `aria-invalid`
and `aria-describedby` together. The Worker still validates every request.
No layout, authentication policy, provider configuration or email template changes.
