### 1. Addresses

| Address | What it opens |
|---|---|
| `/admin/articles` | Pipeline: today's queue and review panel |
| `/admin/articles/:id` | Pipeline with that article's review open |
| `/admin/articles/calendar` | Calendar |
| `/admin/articles/authors` | Authors |
| `/admin/articles/performance` | Performance |

- **The model.** `pages/admin/contentQueueModel.js` holds the tabs, `viewOf(pathname)` and `articleHref(id)`.
  - An article id is a positive whole number.
  - Any other segment opens Pipeline with no article, never a guess.
- **The route.** `App.jsx` adds `/admin/articles/*` behind the same `guard(['admin'])` as the page. Who may open the page is unchanged (§4, question 1).
- **The strip** already owns the subtree since D936, so the HQ Content strip and row stay lit on every address.
- **The open article belongs to the address.** Choosing an article in the list goes to its address, and a shared link or a notice opens it.

### 2. The header

- The page sits under `AdminPageHeader` (D936):
  - the crumb "Content › Content queue", for a Super Admin only, since `/admin/content` is HQ only;
  - the title "Content queue";
  - the line "Articles members propose, from submission to publish. Each decision is an admin's, and the author is told.";
  - the four tabs.
- "Approve → Publish bursts the 60-day edge cache" is gone (#2383 item 14).

### 3. What each tab draws today

- **Pipeline:** today's queue, status tabs, review panel, comments, revisions and scheduling, unchanged.
- **Calendar, Authors and Performance:** each says what it will show, what it waits on, and where today's version of the block is.
  - Performance says "Views per week: Not recorded", because views are one all-time count today.
  - None draws an empty board or a zero.
- **Notices.** "New article awaiting review" (`articleNotify.ts`, `newsNotify.ts`) links `/admin/articles/<id>`, not the bare queue (#2383 item 11).

### 4. Owner questions

#2383's five questions have no answer on the issue. The canvas draws an answer to each, so the integration takes those answers. The owner can override any of them; the answer then replaces it.

1. **Who uses the page:** Admin and Super Admin both, as now. ART16 draws the Admin's view, and there is still no Admin shell row.
2. **Self-approval:** a second admin approves an admin's own article, and a Super Admin can override with a reason. This is ART6's dialog B; an Admin sees "Ask another admin" only.
3. **Edits after submission:** an author's edit to a submitted or approved article sends it back to Submitted and clears its time.
4. **Featured:** only a Super Admin features, at most three at a time ("Feature on Articles…", Super Admin only, ART3, ART16). Authors' own "featured" tags stop counting.
5. **Daily views:** yes, one row per article per day, with no personal data.
