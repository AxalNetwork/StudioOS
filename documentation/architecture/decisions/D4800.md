### 2. The state vocabulary

`frontend/src/pages/hq/security/securityStates.js` holds the thirteen states from SE02: Verified, Healthy, Action required, Failed, Pending, Stale, Unknown, Unavailable, Not instrumented, Unsupported, Not applicable, Measured zero and No data yet. Each has the canvas's word, shape and description.
- **`StatusBadge.jsx`** draws a state as shape plus word, with the description as visually hidden text and as `title`. Status is never colour alone. Twelve distinct shapes; Verified and Healthy share the check, as the canvas does.
- **`securityState(key)`** throws on an unknown key, so a typo cannot quietly read as a real state.
- **`readFigure(value, { readable })`** returns `unavailable` with no text for `null`, `undefined`, a non-number or a failed read, and `measured_zero` for a real 0.
- **`ReadValue`** draws a figure, or Unavailable with "… could not be read" and Retry. It never draws 0.

The folder README documents the API for #4801 and later slices.

### 3. Overview

`overviewModel.js` (`buildOverview`) derives everything from `/overview` and `/governance`. `OverviewWorkspace.jsx` draws it in the canvas's order.

1. **Action required**, most severe first. Each finding has its evidence (what, when, where) and one action:
   - **The restore drill.** A failed run is `Failed`. It shows its step, exit code, date and days since, and links to Resilience. A drill that has never run is `Action required`. An unreadable marker is a check that could not run, "This is not a pass."
   - **Admin MFA** as "x of n". For example: "0 of 2 HQ administrators have a second factor. 2 accounts can still sign in with a password alone." Review administrators links to the admins at HQ › Team (`/admin/hq-team`), as D4803 settled.
   - **Deletion requests** overdue, or due within 14 days of the 30-day clock.
   - **Unreviewed sanctions hits.**
   - **Each check that could not run** is a finding of its own (`Unavailable`), with Retry. This covers the overview, the ledger, any one ledger source, the drill marker, MFA figures, sanctions, support sessions, the session count, the ledger's counts, the AI counters and token anomalies. When any check could not run, the heading line says "A check could not run, so this list may be incomplete". "Nothing needs action" is drawn only when every read answered and nothing is open. While reading, it says "Still reading — nothing is claimed yet".
2. **Checked and clear.** Measured zeros for checks that ran, each with "Read HH:MM UTC" and what was read: deletion requests near deadline, unreviewed sanctions hits, live impersonations, refused sign-ins in 24 hours and token anomalies. It also lists "n of n admins with MFA" and "n of n sources read" when every source answered. A store that could not be read, or a count the payload did not carry, is never in this row.
3. **Status by area.** Eight cells: Authentication, Sessions & access, Privacy & DSR, Trust & sanctions, AI safety, Backup & recovery, Security events and Subprocessor notices. Each has a state, a one-line fact and its freshness, and each links to its workspace. There is no score. AI safety is "x of n evaluated outputs judged safe", with "small sample" under 20. An unsafe verdict makes the cell Unknown rather than Action required, because the page already says unsafe verdicts are historical checks, not open incidents. A passing drill is Verified only when the backup heartbeat was also read.
4. **Evidence sources.** "5 of 5 sources read", from the ledger's own `sources[]`. A failed source is named beside the count, with Retry. The store names, rows and reasons, and the implementation notes, sit behind Source details. With a filter on Events, the line says which filter it counted under.

### 4. Departures from the canvas

- **The workspace nav is links that the arrow keys also move.** SEC says these are routes and not ARIA tabs; the issue asks for arrow keys. Both hold: links with `aria-current`, plus arrow, Home and End movement.
- **The phone nav is one section select.** SE11a draws four links and "More ▾". The #4800 phone board (S4) draws a 44 px section selector, and seven workspaces do not fit at 390 px.
- **The Overview's right-hand column is not built.** SE01 draws "Recent security activity" and an Emergency card there. Recent activity needs the human event labels (`eventLabels.js`, the Events workspace, #4802). The Emergency card's wording ("every HQ-held account; branch databases are not touched; you will be signed out too") goes with the Scope → Review → Result dialog (#4801). Force re-auth stays in Access, unchanged.
- **Eadwyn is unchanged.** `WorkerRail` takes no prompt list: its `groups` prop is models and consumption only (`ui/RailGroups.jsx`). Opening Eadwyn on security prompts, with model and usage under one disclosure, means changing the shared rail, which is not a small change inside this page's props. It is left for a later slice.
- **Sub-lines per workspace** come from the registry. The canvas draws only Overview's and Events'; the other five are written to the same pattern.

### 5. What is Not instrumented, or Unavailable by construction

- **Per-store freshness.** No store records when it was last collected (#4800 question C). "Observed" and every "Read HH:MM UTC" are the time this browser received the read. Stale is defined in the vocabulary but nothing can be marked Stale yet.
- **Subprocessor notice delivery.** The cell reads Not instrumented: nothing records per-notice delivery (D4803, Backend required).
- **Which administrators lack MFA.** `/overview` returns the two counts only, and HQ › Team does not show a factor per admin. The finding links to the admins, but neither page can say which of them to chase.
- **Restore drill history.** The marker keeps the latest run only (D4803). Overview shows that run.

### 6. Tests

`frontend/test/hq_security_v2_d4800.test.mjs`, 15 tests:
- **The tab registry.** Order, every key, unknown values, the arrow keys, Home, End.
- **Deep links.** Every `?tab=` renders its own workspace, with exactly one `aria-current` link and the phone select on the same workspace. An unknown or empty tab renders Overview.
- **Every existing zone under its workspace, and only there.** The shell's bar, links and rail are on every workspace, and the six filters are still drawn.
- **The vocabulary.** Every state renders its word, its shape, a hidden shape and a spoken description. There are twelve distinct shapes, and an unknown key throws. An unreadable value is never 0 and offers Retry.
- **The Overview.** Action required above Checked and clear, above Status by area, above the sources, and the failed drill above MFA. The failed drill's step, exit code, date and link. Never run, passed, and passed without backup evidence. MFA "x of n" and its link to `/admin/hq-team`, for 0, 1 and all enrolled, no admins, and missing figures. Checked and clear lists only checks that ran: `null` counts and unreadable stores are kept out. The eight areas, with no score.
- **A partial source failure.** One source down, the whole overview down, the ledger down, or still loading: each one never renders as clear.
- **"Nothing needs action"** is drawn only when every check ran.
- **The tab marks.**
- **A mounted journey** in the repo's synthetic document. Arrow keys, End and the wraps move the URL and the focus. The phone select drives the same URL, and a workspace draws the read the page already had.

The existing Security page tests (`hq_security`, `hq_security_h23`, `hq_security_sessions_d481`, `hq_security_dsr_d168`, `hq_governance_h7`, and the five other suites that read `SecurityPage.jsx`) pass unchanged. Every line and helper they pin is still in the file.
