### The Worker (`routes/cycle_build.ts` `roadmap()`)

- **Late** is an item past its target date that is not Done: `date(target_date) < date('now')`, its column not `done`
  (any case). A date SQLite cannot read is no date, so never Late. **Unlinked** moves no feedback theme and no KPI, with
  a blank value counting as none. Each is one SQL expression (`lateSql`, `linkSql`). The facts' aggregate, both list
  paths (the SQL page and the in-memory one) and the Late and Links filters all read it, so the strip's figure is
  always the filtered list's total.
- **The facts** add `now`, `next`, `later`, `done`, `late` and `unlinked`, counted by the module's existing grouped
  scan over every item. They stay exact when the list pages, which D6034's backend list asked for.
- **Each row** adds a State column ("Blocked · waits on [item]", In flight, Provisional, Done, then "Blocks N" and
  "Late"), and the keys `state`, `late`, `link`, `blocks` and `waits_on`. The state is `okrGraph.ts`'s `statesFor`:
  Done first, then Blocked by an unresolved blocker, then the stored column. There is no At risk. A blocker off the
  listed page still blocks: one edge read per module page brings every edge whose two ends are this venture's items,
  with the blocker's title and column. A Done item blocks nothing.
- **Filters** Late (`late:yes`) and Links (`link:unlinked`, `link:linked`) page in SQL, with their counts over the
  whole list.
- **Add item** (`records/build.ts` `formOptions`) offers the venture's features as `feature_id`. Edit item's Feature
  gains the same choices. The write's existing ownership check refuses another venture's feature.

### The page (`RoadmapBoard.jsx`, `roadmapBoardModel.js`, mounted as `defs/build.jsx` `aboveRecords`)

- The figure strip: Now, Next, Later, Done, Shipped this month, Late and Unlinked. A figure the read does not carry
  reads Not recorded, never 0. Late and Unlinked are toggle buttons (`aria-pressed`) that set the list's own filter,
  so nothing is filtered in the browser.
- Board and Timeline are a native radio group. The board draws the listed page in four columns: each card shows its
  owner, its date or "Late · due …", what it moves or "Unlinked · no theme, no KPI", its state, and "Blocks N".
  On a phone, a segmented column control shows one column (BD30). A row in a column other than the four is said
  once under the board, never dropped.
- The timeline groups the listed items by target month, earliest first, then a No date recorded tray.
- The board links `/build/roadmap` as **Dependencies and Scenarios** (option A), so the module's old tool door
  ("Open the roadmap: Now, Next and Later") is removed.
- Before the first item, the board draws nothing; the progressive list's zero guide stands alone (BD28).

### Where this departs from the canvas

- **The list stays under the board.** The canvas draws no table. The list keeps search, the filters, paging, Add and
  Export, and the board draws the page the list holds, with a line naming the page when the list pages.
- **The timeline is grouped by month** on every width, which is BD30's phone shape. BD26's desktop drawing, with
  placement by day, a today line, blocker-to-blocked connectors and a hatched Late span, is not drawn. Late is said
  on each card instead.
