## D1366 — Top-up is on sale in production: the $10 pack

- **Status:** decided by the owner on 2026-10-28 ("We need to enable it"), after screenshots of Add tokens and Pricing › Models showing "Top-up isn't available yet." with Pay and Add tokens disabled. Built by S21.
- **Migration:** none.
- **Builds on:**
  - D629: the top-up price;
  - D750: its readiness;
  - D755: token packs and the `STRIPE_PRICE_AI_TOPUP` fallback.

### Why nothing was on sale

Production had no row in `ai_token_packs`, and `STRIPE_PRICE_AI_TOPUP` was unset. So `packsOnSale` listed nothing, and every Add tokens and Pay was off. The code was right: a member must never be offered a price that cannot be charged.

Stripe already held one suitable price. On the account production uses (the sandbox, the same mode as `STRIPE_SECRET_KEY`), the "AI top-up" product (`metadata.purpose = ai_topup`) has `price_1UNzpEF1hAXeCvFjjXynLkhe`: $10, one-time, USD, active.

### The change

`wrangler.toml` `[env.production.vars]` sets `STRIPE_PRICE_AI_TOPUP` to that price.

- **How it is sold:** it is offered as a pack with no bonus (D755 §3, origin `environment`).
- **The mirror:** `readAiTopupProduct` fetches it into the catalog mirror on the first read when Sync from Stripe has not mirrored it (D750 decision 2).
- **Not a secret:** it is a price ID, so it is a plain var.

### Afterwards, in HQ

- **Adopt it.** HQ › Platform › Allowances › Token packs shows the fallback's line with **Adopt**. Once it is adopted, delete the var, as `documentation/operations/AI_TOKEN_PACKS.md` says.
- **More amounts.** These are **New pack…** there; the var names one price only.
- **Card payments.** The account is the Stripe sandbox, so only Stripe test cards complete a payment until production moves to live keys and live prices.
