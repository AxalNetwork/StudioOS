### Venture-record elements and the logos store (D1543, #3781)

`routes/deck_venture_elements.ts`, mounted at `/api/decks` beside `deck_typed_values.ts`, before `decks`; the elements are `services/decks/ventureElements.ts`, and the logos store is `deck_logos` (migration 732). Client: `lib/api/deckVentureElements.js` (`deckVentureElementsApi`), read through `deckV2Adapter.ventureElements` (a `SWAPPED` row of the seam). Every value is a record with its Source and grade (`sources.ts`'s one mapping); no model runs, and every reply says `model: null`.

| Route | Who | What it answers |
| --- | --- | --- |
| `GET /api/decks/:id/venture-elements[?include=cap_table]` | whoever may read the deck (`projectOwned`) | `{ deck_id, elements: { team_grid, team_bios, use_of_funds, round_terms, cap_table, logo_wall, interview_quote } }`, each `{ available: true, blocks, bindings, model: null, label }` or `{ available: false, code, line }`, so the one-click run places what passes its gate and leaves the rest out. The cap table is `not_included` unless `include=cap_table`; the quote is never placed here (`pick_required`, or `quotes_not_switched_on`). 403 / 404. |
| `GET /api/decks/:id/venture-elements/:element` `[?include=cap_table] [?detail=holders] [?final=1] [?logos=k1,k2] [?segment=<id>]` | as above | One element: `{ deck_id, element, available: true, blocks, bindings, model: null, label, … }`. Round terms carry `label: 'Proposed, subject to counsel'` and `proposed: true` unless every term is Reviewed; the cap table is one header row and one Total row (`totals_only: true`); a logo wall is one image block per permitted logo with its `logo_key`; a quote is the picked line by role with its `session_uid`. Refusals (`error` is the code, `message` the canvas's line), 409: `no_consent`, `no_permission`, `totals_only` (`detail=holders`), `not_included`, `subject_to_counsel` (`final=1` on terms counsel has not approved), `quotes_not_switched_on`, `pick_required`, `not_recorded`; 503 `unreadable`; 400 `unknown_element`. |
| `GET /api/decks/:id/logos` | whoever may read the deck | `{ deck_id, logos: [{ logo_key, customer_name, image_uid, image_url, permitted, permission_reference, permitted_at }] }`, at most 48. No user id or email. |
| `POST /api/decks/:id/logos` `{ customer_name, image_uid, permitted?, permission_reference? }` | write access to the venture; never a support session (403 `support_session_refused`) | `{ logo }`. The picture is one of the venture's kept `deck_images`. 400 `customer_name_required`, `image_required`, `invalid_permission`, `permission_reference_required`; 404 `image_not_found`; 409 `logo_exists`, `too_many_logos`. |
| `PATCH /api/decks/:id/logos/:key` `{ permitted, permission_reference? }` | as `POST` | `{ logo }`: records the customer's permission (a reference is required) or withdraws it, which takes the logo off every link at once. 400 `invalid_logo_key`, `invalid_permission`, `permission_reference_required`; 404 `logo_not_found`. |
| `DELETE /api/decks/:id/logos/:key` | as `POST` | `{ deleted: true }`; 404 `logo_not_found`. |

Saves: `PUT /api/decks/:id` and `PATCH /api/decks/:id/cards/:uid` refuse a block with an unpermitted `logo_key` (409 `no_permission`) or an `interview_quote` whose session has no recorded consent (409 `no_consent`), writing nothing (`services/decks/saveGates.ts`).

Share links: `shareInclude.shareGatesFor` now reads `deck_logos`' permitted keys at share time, so a logo-wall block goes out only while its customer's permission stands; the cap table still needs the link's `include.cap_table` (off by default) and then sends totals only; a quote still needs a consented session.
