### WhatsApp interview channel Worker contract (D754, #1871)

`routes/channels.ts`, mounted on `/api/channels`. The runbook is `documentation/operations/WHATSAPP.md`. `WHATSAPP_CHANNEL` (`off` / `canary` / `on`, default `canary`, #1950) decides who may connect or link: in canary only Super Admins. Routes marked *venture* answer 404 `unknown_provider` to a member who cannot hold a venture (D757 §2.11); a closed route answers 503 `not_available`.
- `GET /` lists each provider's `available` (secrets set and the rollout open to this member), `missing` secret names for an admin, `rollout` for a Super Admin, and for WhatsApp the Embedded Signup ids; each connection with its status and, for WhatsApp, `calls` (why WhatsApp Calling is not offered, #1586).
- **Way A, the member's business number.** `POST /whatsapp/connect` *venture* `{ code, waba_id, phone_number_id? }` finishes Embedded Signup (400 `invalid_request` on malformed ids). `DELETE /whatsapp` and `POST /whatsapp/test` stay open to an existing connection.
- **Consent (#1954, D754 §4–§5).** `POST /threads/:uid/assign` takes `consent?: { ask: true } | { method }`: a WhatsApp chat links and waits. `POST /threads/:uid/consent-request` sends Axal's notice, only when the member presses it, inside the 24-hour window, at most twice, 24 h apart. `POST /threads/:uid/consent { method: verbal | written | pre_agreed }` takes the member's word once the notice was delivered (400 `consent_method_required`). Both refuse 409 `consent_not_offered`, `attestation_not_offered`, `thread_ignored`, `consent_needs_interview` or `already_given`. `GET /threads/:uid` carries `consent` and each voice note's `voice_fetch_by` (the media id's 7-day deadline).
- **Way B, Send to Axal (#1937–#1939).** Every route answers 503 `not_available` until all four `WHATSAPP_AXAL_*` settings are set; a Super Admin's 503 also carries `missing`, the unset names only (#2056). `POST /whatsapp/link` *venture* returns a one-time code and its `wa_link` (at most 10 codes an hour, 429 `rate_limited`); `GET /whatsapp/link` *venture* the newest claim, with Axal's `axal_number` and a plain `axal_link` (wa.me); `POST /whatsapp/link/:uid/confirm` *venture* is Axal's half; `DELETE /whatsapp/link` unlinks. `PUT /whatsapp/link/venture { project_id | null }` *venture* records where recordings go, in `whatsapp_link_settings` (migration 504, #1939 part 3): 409 `whatsapp_not_linked` without a link, 403 `venture_not_yours` for a venture the member's founder account does not own, whether missing or another's; `GET /whatsapp/link` returns it as `venture`, and every unlink clears it. `GET /whatsapp/captures` lists what the member forwarded, with no media id; `POST /whatsapp/captures/:uid/consent { method: pre_agreed | verbal | written }` answers a capture still waiting (404 `capture_not_waiting`).
- **The webhook.** `GET /whatsapp/webhook` answers Meta's `hub.verify_token` challenge (403 `forbidden`, 503 `not_configured`). `POST /whatsapp/webhook` checks `X-Hub-Signature-256` over the raw body before parsing: 401 `unauthorized` unsigned or wrongly signed, 503 `not_configured` with no secrets, 400 `malformed`, 500 `retry` when an event could not be stored. With `WHATSAPP_CHANNEL` `off` it still verifies, then answers 200 `ignored: rollout_off` and stores nothing. `scripts/check-spa-live.mjs` fails the smoke run if an unsigned POST is ever accepted.
