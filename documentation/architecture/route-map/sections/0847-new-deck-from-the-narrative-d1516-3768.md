### New deck from the narrative (D1516, #3768)

`routes/deck_narrative.ts`, mounted at `/api/decks` beside `deck_areas.ts`. The outline reads the venture's latest narrative version (`narrative_version_meta`), cuts the stage's arc to the cards with recorded proof, plans each card's grid (`grid_plan`: a structure, its areas and the element per area), and picks the theme and template. The build saves those cards as a new version that is **not** current, bound to the narrative version it read (`pitch_decks.narrative_version`, migration `202611031522_pitch_decks_narrative_version.sql`). It then admits one `deck_build` run over every area under one hold, as #3764's proposals. The build path is under the `deck_generate` rate bucket; the outline is not. Client: `lib/api/deckNarrative.js` (`deckNarrativeApi`), read through `deckV2Adapter.narrativeOutline`.

| Route | Who | What it answers |
| --- | --- | --- |
| `POST /api/decks/narrative/outline` | the venture's writers | `{ project_id, audience?, stage?, sector? }` → `{ project_id, narrative: { version, ref, reason, dropped }, stage, stage_label, stage_source, cards: [{ card, uid, title, why, proof, structure, areas: [{ id, element }] }], left_out: [{ card, title, line }], warnings, theme: { kind, reason }, template: { template_id, reason }, quote }`. A card with no recorded proof is left out with "<Title> not evidenced". The quote is the areas quote of every area, class `deck_build`. It runs and holds nothing. |
| `POST /api/decks/narrative/build` | the venture's writers, with an `Idempotency-Key` | The same body (+ `quote_uid`) → `{ deck_id, version, narrative_version, batch_uid, class, hold_microusd, replayed, theme, template, proposals, refused, left_out }`. 400 without a key; 409 `quote_stale`; 422 `nothing_to_run`; 409 `build_in_flight` for a second press racing the first. The same key twice is the same build: no second version and no second hold. |
