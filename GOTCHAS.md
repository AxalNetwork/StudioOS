lived inline in `replit.md`. They were split out so the README stays a
scannable overview of live invariants while the detailed gotchas remain easy to
find. Content below is preserved verbatim from the original `replit.md`
"Persistent gotchas" section.

### Telegram broadcaster (Task #3)
- **Bot token** in `TELEGRAM_BOT_TOKEN` (Worker secret only; never Replit Secrets, never `.replit`). When unset, all send paths return 503 `{code:'telegram_token_missing'}` and the breaker stays neutral — draft authoring + linter still work. Provision: `wrangler secret put TELEGRAM_BOT_TOKEN --env production`.
- **Migration 067 pending apply** in prod (additive, `IF NOT EXISTS`). Worker carries `ensureTelegramSchema()` lazy bootstrap (mirrors `ensureTeamMembersSchema`), so the four tables (`telegram_channels`, `telegram_posts`, `telegram_aggregations`, `user_promotion_consent`) auto-create + seed the six canonical channels with NULL chat_id on first hit. Apply via `wrangler d1 execute studioos-db --remote --env production --file=cloudflare-worker/sql/migrations/067_telegram.sql` to seed without a hot path.
- **Promotion consent** lives in side table `user_promotion_consent(user_id PK, consented, consented_at, source)` — `users` is at the D1 ALTER limit (same pattern as `user_google_links` from migration 065).
- **Send gate** runs `services/telegramRedactCheck.ts::lintForSend()` before every send. Findings: `email|phone|tax_id|bank_iban|card_like|consent_missing|private_in_public`. Public channel (`audience='public'`) treats ANY user-mention as blocking; private channels block only on missing `consent_for_promotion`. Admin override path requires `override_reason` ≥8 chars, persists `override_reason` + `override_findings` on the post AND writes `telegram_pii_override` to `admin_audit_log` BEFORE the actual send.
- **Route mount precedence**: `/api/admin/telegram` MUST be mounted BEFORE the catch-all `/api/admin` in `index.ts`. Sits inside the existing `app.use('/api/admin/*', requireCfAccess())` perimeter — no new middleware. Admin role enforced per-route via `requireAdmin`.
- **R2 media** at `telegram/{channel_id}/{post_id}/{uuid}.{ext}` (binding `FILES`); 8 MB cap, photo (jpg/png/webp) or document (pdf/csv/txt). DELETE-post clears the R2 key best-effort.
- **MarkdownV2** is the wire format. UI shows a hint that `_*[]()~\`>#+-=|{}.!` must be escaped with `\`. Aggregator drafts are pre-escaped by `services/telegramAggregator.ts`.
- **Reusable**: `telegramRedactCheck.ts` is the canonical PII linter — Task #4 LF (LinkedIn auto-poster) imports it directly. Do not duplicate.

### Auth blockers — magic-link / passkeys / step-up (Task #4 IB)
- **Schema** — migration `083_auth_blockers.sql` (additive, `IF NOT EXISTS`). Worker carries `services/authBlockersSchema.ts::ensureAuthBlockersSchema()` lazy bootstrap (mirrors `ensureTelegramSchema`) so `magic_link_tokens`/`passkeys`/`webauthn_challenges` + `user_sessions` cols (`last_step_up_at`, `step_up_due_at`, `assurance_level`) auto-create on first hit. - **Step-up is SESSION-scoped, not user-scoped** — magic-link sessions carry a 7-day `user_sessions.step_up_due_at`; `getCurrentUser` auto-relocks past it. Deliberately does NOT touch `users.recovery_step_up_due_at` (migration 060 partial/broken in prod). `requireStepUp(c, ttl=15)` passes when session `factor in (totp,passkey)` AND recent (`created_at`|`last_step_up_at`), else 403 `{code:'step_up_required', ttl}`. `POST /api/auth/step-up {totp_code}` stamps `last_step_up_at`. SPA retries via the `lib/api.js` 403 interceptor → `StepUpModal`.
- **Magic-link** — `POST /api/auth/magic/start` returns constant 202 (rate-limited, 15-min single-use SHA-256-hashed token); `GET /api/auth/magic/verify` find-or-creates the user and mints a `factor='magic'`/`assurance_level='email_only'` session. Lower-assurance — step-up still gates sensitive routes.
- **Passkeys** — `@simplewebauthn/server`+`browser` v13 (WebCrypto, Workers-OK). `util/webauthn.ts`: rpID=`axal.vc`, origins incl. `app.axal.vc`+localhost in non-prod. Routes under `/api/auth/passkey`; UI in LoginPage + Settings → Security PasskeyPanel. **Both `@simplewebauthn/*` packages resolve from ROOT `node_modules` for worker AND frontend** — they're in `frontend/package.json` deps but Vite walks up to root to resolve them; don't assume a separate `frontend/node_modules` copy.
- **NICE-AUTH-04** — `POST /api/auth/sign-out-everywhere` is an alias that bumps `users.jwt_min_iat` via `auth.ts::bumpJwtMinIat`; `/api/settings/sessions/revoke-all` retained.

### Backend / Worker
- **Admin role changes** — direct SQL only, no UI.
- **Referrer-Policy is two-tier (NICE-SEC-01)** — the authenticated app/API surface (`middleware/securityHeaders.ts` on the Worker + dev `backend/app/main.py`) emits `no-referrer` (canonical; never leak IDs/query-params); the public Jekyll marketing site (`github.toml`) + static/Pages header config (`cloudflare.toml`) keep `strict-origin-when-cross-origin` (no sensitive URLs, wants referral attribution). The split is deliberate — don't "unify" them.
- **`activity_logs.actor`** — 16-hex SHA-256-truncated `email_hash` for all writes (`util/hashEmail.ts`); never plaintext. Join on `user_id`. Legacy reads in `routes/activity.ts` keep `LOWER(actor)=LOWER(email)`.
- **`SCORING_HMAC_SECRET`** — ≥32 bytes hard-required in production; worker refuses to boot otherwise. Dev falls back to `JWT_SECRET` with a warning.
- **`AXAL_ENCRYPTION_SECRET || JWT_SECRET`** keys all `cryptoBox` AES-GCM at-rest encryption. PBKDF2 iterations are **100,000** (Workers runtime caps PBKDF2 at 100k — values above throw `NotSupportedError: PBKDF2 failed: iterations exceeds the maximum`). `decryptString`/`decryptBytes` retain a 200k LEGACY fallback via `decryptWithFallback()` so ciphertext written by older isolates (whose key was cached before the limit tightened) stays readable. Never change `ITERATIONS` without keeping the legacy in the fallback list.
- **Pagination clamps** — always use `util/pagination.ts` (`/api/activity` ≤200, `/api/admin/users` ≤50, `/api/dashboard?days` ≤365).
- **CI audit gates** — `npm audit --omit=dev --audit-level=high` (frontend + worker) + `pip-audit` (backend) block high/critical CVEs in prod deps.
- **OAuth keys (Slack/HubSpot/Salesforce/DocuSign)** — env-var first, then admin-managed `provider_oauth_keys` rows; 60s in-isolate cache. `ensureCreds()` is async — never call sync. Admin revoke cascades `integrations.status='disconnected'` for that provider.
- **Integration Keys CF-secret promotion (Task #7)** — admin Save / Rotate in `/admin?tab=integration-keys` no longer leaves a long-lived encrypted DB row. PUT pushes BOTH env-var names from `PROVIDER_ENV_VARS` (e.g. `SLACK_CLIENT_ID` + `SLACK_CLIENT_SECRET`) to the live Worker script via Cloudflare's `PUT /accounts/{id}/workers/scripts/{script}/secrets` API, then `deleteOauthCredsRowOnly()` drops any stale `provider_oauth_keys` row (no cascade-disconnect — existing user OAuth tokens stay valid). If the second push fails, the first one is rolled back via `deleteSecret()` so no half-set pair survives. Rotate pushes just the secret half. Remove deletes both via `DELETE …/secrets/{name}` then runs the existing `deleteOauthCredsAndDisconnect()` cascade. Required secrets: **`CLOUDFLARE_API_TOKEN`** (scoped to `Workers Scripts: Edit`) and reused **`CLOUDFLARE_ACCOUNT_ID`**; optional `CF_WORKER_SCRIPT_NAME` (defaults to `studioos`). When the token is unset, PUT/Rotate return 503 `{error:'cloudflare_api_token_missing'}` and Rotate falls back to the legacy DB path so admins aren't locked out. Every push/rotate/delete writes an `admin_audit_log` row with `report_type='integration_keys'` and action `integration_key_cf_secret_{push,rotate,delete}`. `client_id_preview` in the list response is masked as `first4••••last4` — never log or surface the full client_id.
- **MI Personas export** — chart fields are `Maybe<X> = X | GatedChart`. CSV/PDF exporters in `routes/market_intel.ts` MUST narrow via `isGated()` before reading `.buckets`/`.cells`/`.rows`; the 402-tier guard is the first line of defence, this narrowing is the second.
- **Anthropic is dev/eval-only** — production runs on Workers AI. Only `routes/assistant.ts` may call Anthropic, double-gated by `STAGE !== 'production' && ENABLE_ANTHROPIC_DEV === '1'`. CI guard `scripts/ci/no-anthropic-in-prod.mjs` blocks new prod callers. After deploy: `wrangler secret delete ANTHROPIC_API_KEY --env production`.
- **Personal Advisor `/explain`** (Task #16/#31) — Workers AI only via `aiRouter` task class `advisor_explain` (`MID_LLAMA` → `SMALL_LLAMA` fallback). Output buffered so `stripVerbatimLeak` runs on full text. SSE wire: `provider` → `delta…` → `done`.
- **Advisor question banks** (Task #5 CH) — single source of truth in `cloudflare-worker/src/services/advisor/banks/*.ts`. Frontend `router.js::predictTarget` consumes the auto-generated `banks.manifest.json` (manifest wins on conflict; legacy frontend banks must stay a strict subset). Size + write-router coverage enforced by `scripts/check-advisor-bank-drift.mjs` and `scripts/check-write-router-coverage.mjs` (both wired into `npm run test:drift`). Never rename or delete bank ids — `writeRouter.ts` holds a hard-coded id→column map keyed by Task #2 originals. New ids use `founder.lab.*` / `founder.dd.*` / `investor.<topic>.*` / `partner.{sp,ma,st,cv}.*` / `partner.rate.*` / `partner.comp.*` namespaces.

The `/explain` SSE wire is `provider`→`delta`→`done` with the full output buffered so `stripVerbatimLeak` runs before any token streams (leak → templated refusal + `done.leaked=true`).
