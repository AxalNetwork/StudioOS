# services/ai — the AI router's parts

What `../aiRouter.ts` uses to talk to Workers AI, kept pure so a test reaches
each rule without a binding. Read
[D761](../../../../documentation/architecture/decisions/D761.md) first.

| File | What it owns |
| --- | --- |
| `shapes.ts` | D761: the request and response shape for each kind of model: text and reasoning (PR 1); vision content parts, rerank, rail embeddings and translation (PR 2); voices, Aura and MeloTTS, and a live stream's WebSocket minutes (PR 3); image generation, FLUX, Lucid Origin and Phoenix, measured in each model's billing unit (PR 4). It also says which models may write `axal-search` (BGE Base EN v1.5 only, `searchIndexAccepts`). It also holds the rules on each attempt: the timeout class (chat 8 s, reasoning and long context 30 s, images 60 s; a stream's first chunk the same), the context-window check, failures read as a status and Workers AI's code, the paid-only refusals, `x-session-affinity`, and the `units` an attempt used, measured by the Worker. A model's kind, window and plan come from D760's catalogue through `factsFor` / `setModelFactsSource`. |
| `catalogue.ts` | D760 ([D760.md](../../../../documentation/architecture/decisions/D760.md)): every Workers AI model, one row each, with its kind, capabilities, context window, status, paid-only and partner flags, its prices as the decimal strings Cloudflare prints, and its neurons, the figure Cloudflare bills, per `UNIT_SCALE` units. Held equal to `test/fixtures/workers_ai_catalogue.json`, the read with its sources. `isOffered` (status `ga` or `partner`, priced, past the partner gate), `refusalFor` (`model_unpriced` or `model_not_offered`) and `defaultDemoted`. |
| `pricing.ts` | D760: `AI_MARKUP`, written here and nowhere else; `billingMode` ('cost' until D762); `multiplierFor` (the `admin` licence pays cost); `USD_PER_NEURON` ($0.011 per 1,000); `unitPrice`, a unit's neurons × that rate, the price every view and read serves; `costMicro` and `billedMicro`, exact decimal sums over the neuron prices, rounded up to a micro-USD once per run; `billedUnitPrice`, the unit price the Worker serves. |
| `railMatrix.json` | D764 (#2089): one row per canvas page, `{ pageKey, kind, routeTask, models: [{ id, role, line }] }`, generated by `scripts/build-rail-matrix.mjs` and never edited by hand. `models[0]` is the page's default. PR 2's `GET /api/ai/rail` reads it. PR 3 adds `options`, one row per option a profile registers (`frontend/src/lib/railOptions/`). |
| `railMatrix.ts` | D764 (#2089): the matrix read (`resolveRail`, `resolveRailOption`, `railOptionsOn`) and the run rule `resolveRailChain`, which `aiRouter.run` applies to a rail run's text and vision work. |
| `guard.ts` | D763 ([D763.md](../../../../documentation/architecture/decisions/D763.md)): Llama Guard 3 8B's rules. `sliceForGuard` cuts a text into slices of at most 2,000 characters (at a paragraph break, else a sentence end, else the limit) that join back exactly; `parseVerdict` reads `safe` or `unsafe` and its S-codes, and anything else is `unreadable`, never safe; the category table (S6 and S7 log, every other code blocks) with `decide` and `combine`; and the refusal copy in Eadwyn's voice, with the Wellbeing link on S11 for a founder or an admin; `GUARD_CATALOGUE` for the catalogue. Part 2 hooks it into `run()` (`../aiRouter.ts`: the input and output checks, `releaseChecked`, the one hold). |

**Adding here.** A file here takes plain values and returns plain values. No
`env`, no binding, no D1: `aiRouter.ts` does the calling, and these files say
how. The owner's switches `catalogue.ts` reads (`AI_PARTNER_MODELS`,
`AI_PAID_MODELS`) arrive as a plain object of strings. A new kind of model is
a new shape in `shapes.ts`, with its case in
`test/ai_router_shapes_d761.test.mjs`. The guard's cases are in
`test/ai_guard_d763.test.mjs`, and the catalogue's and the prices' in
`test/ai_catalogue_d760.test.mjs`.
