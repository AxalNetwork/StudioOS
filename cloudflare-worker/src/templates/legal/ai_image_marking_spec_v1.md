# AI-generated images: marking and attribution (specification for counsel)

This is a specification, not a counterparty document. It says how the
Service would mark the images its AI features generate, and where it
would say so on screen. Counsel is asked to confirm it meets the
obligations that apply (see "Questions for counsel" below). Nothing here
is switched on: plan task A12 (the deck image pipeline) builds the stamp
switched off, and owner decision V switches it on.

## 1. Which images are marked

Every image produced by one of the router's image tasks, whatever page
asked for it:

| Task | Where it is used | Stored at |
| --- | --- | --- |
| `deck_image` | Pitch deck cards and backgrounds (D903), and the Grid's image and illustration areas | `deck-images/<project>/<uid>.<ext>` (`deck_images` rows) |
| `brand_logo` | Build › Brand's logo (D766) | the brand kit's logo asset |
| `article_image` | Article images (D1409) | `articles/<id>/img-<uuid>.<ext>` |

An image a member **uploads** is never marked as generated. Its own
metadata is stripped on upload (A13, #3757), and nothing is added.

## 2. The marking (decision V)

**Option A, S1's pick.** Every generated image carries an XMP packet with:

- `Iptc4xmpExt:DigitalSourceType` =
  `http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia`;
- the model id that drew it, as the catalogue names it (for example
  `@cf/black-forest-labs/flux-1-schnell`);
- the date it was generated (UTC).

The packet holds no prompt, no member name, no venture name and no cost.

**Option B, if counsel requires it.** Option A plus a C2PA manifest
signed by the Service, asserting the same three facts.

**Option C.** No marking.

## 3. Where marking joins the pipeline

The deck's image pipeline is Expand · Draw · Image check · Alt text
(board pd15, "Results · proposed"). The stamp is written **after Image
check passes and before the bytes are stored**. So:

- an image refused by the check is never stored, and is never marked;
- the stored object in R2 is the marked file, so every later read
  (the editor, a shared link, an export) starts from marked bytes;
- the upload path's metadata stripping (A13) runs only on uploads, so it
  can never remove the stamp from a generated image.

## 4. Exports keep the marking (board pd8b)

| Format | How the marking survives |
| --- | --- |
| PDF | the image is embedded as the stored file, with its XMP packet |
| PPTX | the image part is the stored file, unchanged |
| HTML (offline) | the image is the stored file (as a data URL or a sibling file), unchanged |
| .odp | the image is the stored file, unchanged |

A test must show that `DigitalSourceType` is still readable in R2, in the
PDF and in the PPTX (plan §5.4, E5). An export that re-encodes an image
(resizing, format change) must write the stamp again.

## 5. Attribution on screen

**One line, not two.** The editor already shows one line for a placed
image: `placedLine` in `frontend/src/pages/raise/pitch/imageModel.js:76`,
drawn in `frontend/src/pages/raise/pitch/ImageToolbar.jsx:62`.

- For a generated image it reads "<model label> · generated <day> ·
  <cost>", for example "FLUX.1 Schnell · generated 1 Nov · <cost>".
- For an upload it reads "Uploaded <day>", plus "· the person's
  agreement recorded" when one was recorded.

This line **is** the in-editor attribution. No second attribution line
is added. When V is on, the generated form reads "AI image · <model
label> · generated <day> · <cost>", so the words "AI image" lead the
line the member already sees.

**On the slide itself** (Present, a shared link, an export) no visible
text is added by default; the machine-readable stamp carries the facts.
The member may add one line to the deck's sources appendix: "Images
marked AI image were generated by <model label>."

## 6. Questions for counsel

1. Does Option A meet EU AI Act Article 50(2) (machine-readable marking
   of synthetic images, applicable from 2 August 2026) for ventures and
   viewers in the EU, or is a C2PA manifest (Option B) required?
2. Is the in-editor line (§5) enough disclosure to the member, and is any
   visible label required on a slide shown to investors?
3. Do any model licences the Service routes require their own attribution
   (for example "Built with Llama"), and where must it appear? This is
   owner decision X's register (`MODEL_TERMS.md`).
4. Should the ToS clause forbidding removal of the marking (ToS v4
   §4C.6) be kept, softened, or dropped?
