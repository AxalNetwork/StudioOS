# frontend/src/lib/commands — Eadwyn's commands

<!-- index: none -->

D9276 (#9276): what a member may do from Eadwyn's composer, as one list
generated from the code, and the parser that reads what they typed against it.
Nothing here renders, fetches or writes; the composer (#9278) draws it.

- `registry.js` builds an entry for every cycle module (`/<section>/<module>`)
  and every Add form (`/<section>/<module><action>`, alias `/<alias>`) from
  `../../pages/cycles/modules.js` and `../../pages/cycles/forms.js`, plus the
  shortcuts `/record`, `/task`, `/ticket`, `/team` and `/explain`. Each entry
  carries its stable id, aliases, the route guard's roles, scope, handler,
  required inputs, coverage, preview, writer, result link and error behaviour.
- `grammar.js` parses typed text into `{ entry }`, `{ suggestions }` or
  `{ unknown }`, only ever among the entries the viewer may see.

## Rules

- **The list follows the code.** Modules and forms are read, never copied. A
  new Add form needs its row in `ACTIONS` (stable action id, label, one short
  alias) or in `EXEMPT_FORMS` with its reason, or
  `frontend/test/eadwyn_commands_9276.test.mjs` fails.
- **An action id is stable.** Change a label freely; never an `action`, which
  members may have learnt to type.
- **Seeing an entry grants nothing.** `SECTION_GUARDS` mirrors `App.jsx`'s
  route guards (the test holds them equal); the module's Worker writer still
  decides every write.
- **A typed path is never an address.** The parser only picks listed entries;
  an entry's `href()` is built from its own fields.
- **Related lists stay apart.** Navigation, `../railOptions/`, advisor tools
  and agent skills are not merged into the registry.
- The coverage map in `documentation/architecture/decisions/D9276.md` is
  generated by `coverageMarkdown()`, and the test fails when it is stale.
